# dataset.createExperiment()

**自以下版本加入：** `@mastra/core@1.61.0`

建立實驗，但不啟動執行。由自己的編排器（例如 Temporal 工作流程）以下列其中一種方式控制執行流程：

- **指定目標：**傳入 `targetType` 和 `targetId`，再對每個數據項目呼叫 [`runExperimentItem()`](/reference/datasets/runExperimentItem)。Mastra 會執行目標，並在伺服器端執行評分器。
- **不指定目標：**省略這兩個參數，在自己的基礎設施上完成所有執行，並透過 [`submitExperimentResult()`](/reference/datasets/submitExperimentResult) 逐項提交結果。

兩種方式最後都要呼叫 [`finalizeExperiment()`](/reference/datasets/finalizeExperiment)。

實驗在建立時固定數據集版本。因此，即使數據集之後有變，提交的結果仍會按固定的數據項目集合驗證。

## 使用範例 {/* #usage-example */}

```typescript
import { Mastra } from '@mastra/core'

const mastra = new Mastra({/* storage config */})

const dataset = await mastra.datasets.get({ id: 'dataset-id' })

const { experimentId, totalItems, datasetVersion } = await dataset.createExperiment({
  id: 'temporal-wf-run-42', // optional: idempotent create on retry
  targetType: 'agent',
  targetId: 'translation-agent',
  scorers: ['accuracy'],
})
```

傳入自訂 `id` 可令建立操作具備冪等性：再次使用相同 `id` 呼叫時會傳回現有實驗，工作流程活動重試亦不會重複建立。若呼叫拋出 `EXPERIMENT_ID_CONFLICT` 錯誤，表示該 `id` 已屬於另一數據集中的實驗，或對應實驗使用不同目標。

`targetType` 和 `targetId` 必須同時提供，而且建立實驗時，目標必須已在 Mastra 註冊。`scorers` 需要指定目標，因為 Mastra 不會為沒有目標的實驗評分；此時應透過 `submitExperimentResult` 提交扁平分數。
