# dataset.purgeItem()

**新增於：** `@mastra/core@1.65.0`

從每個歷史版本、刪除墓碑及相關實驗結果中永久清除數據項目內容。如只需從目前數據集版本移除數據項目，請改用 [`deleteItem()`](/reference/datasets/deleteItem)。

## 使用範例 {/* #usage-example */}

```typescript
import { Mastra } from '@mastra/core'

const mastra = new Mastra({/* storage config */})

const dataset = await mastra.datasets.get({ id: 'dataset-id' })

await dataset.purgeItem({ itemId: 'item-id' })
```

## 行為 {/* #behavior */}

永久清除會將現有歷史記錄及刪除墓碑中的數據項目內容欄位替換為遮蔽值，並在其元數據加入清除標記。與該數據項目相關的實驗結果中，相同欄位以及標籤和註解也會被清除。清除後提交的實驗結果寫入會以遮蔽內容儲存。

永久清除會與並行的數據項目寫入序列化執行或發生衝突，但不保證哪個操作先完成。如修改型 `updateItem()` 呼叫在競態中失敗，它會重新讀取清除標記，並以 `DATASET_ITEM_PURGED` 拒絕請求。`deleteItem()` 仍保持冪等，競態期間建立的任何刪除墓碑也會保持遮蔽狀態。

一般數據項目變更使用緩慢變動維度第 2 型（SCD-2）版本控制。永久清除會為滿足抹除要求而刻意覆寫歷史不可變性，同時保留數據項目身分及數據集版本時間軸。它不會建立新的數據集版本。鎖定版本的讀取仍可傳回數據項目的記錄骨架，但已清除的內容不再可用。實驗計數及檢視狀態亦會保留。

MongoDB 儲存需要支援交易的複本集或分片部署。如交易不可用，操作會在變更數據項目或其實驗結果前失敗。

`externalId` 保持不變，因為 Mastra 將它用作身分鍵。請勿在 `externalId` 中儲存敏感數據。

永久清除是冪等操作，而且無法還原。
