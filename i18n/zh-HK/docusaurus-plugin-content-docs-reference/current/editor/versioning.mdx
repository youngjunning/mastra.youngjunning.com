# 版本管理

Editor 為已儲存的 Agent 和提示區塊提供版本管理。資料庫資源透過草稿與發佈操作管理版本；程式碼定義的 Agent 覆寫則使用內容固定的檔案及 Git 歷史紀錄。

關於發佈與實驗方式，請參閱 [Editor 版本管理](/docs/studio/editor#versioning)。

## 資料庫生命週期 {/* #database-lifecycle */}

資源紀錄會儲存 `activeVersionId`，個別快照本身不儲存生命週期狀態。

| 術語 | 含義 |
| - | - |
| 最新版本 | 最近建立的設定快照 |
| 已發佈版本 | `activeVersionId` 指向的快照 |
| 草稿 | 與 `activeVersionId` 不同的最新快照，或沒有啟用版本時的最新快照 |
| 歷史版本 | 其他保留的快照 |

儲存已變更的快照欄位會建立新的最新版本。儲存相同的快照欄位，或只修改元資料，都不會建立新版本。

若已有啟用版本，建立草稿不會改變用來處理已發佈請求的版本。發佈時會更新 `activeVersionId`。還原歷史版本時，系統會複製其設定並建立新的未啟用草稿。

直接呼叫的命名空間方法與 REST API 遵循相同規則。`editor.prompt.update()` 和 `editor.agent.update()` 都會建立未啟用草稿，不會將新版本指定給 `activeVersionId`。若要透過 SDK 發佈版本，必須明確傳入：`editor.agent.update({ id, status: 'published', activeVersionId: version.id })`。已儲存 Agent 的 REST `PATCH` 路由也會建立未啟用草稿，除非啟用 `autoPublish`；`POST /stored/agents/:id/versions/:versionId/activate` 則會發佈該版本。

若一般已儲存資源沒有啟用版本，解析已發佈版本時可能回退到最新快照。對程式碼定義的 Agent 覆寫而言，若請求 `status: 'published'` 但沒有啟用中的覆寫版本，則會傳回原本的程式碼定義 Agent。

## 程式碼來源 {/* #code-source */}

當 `source: 'code'` 時，啟用中的 Agent 覆寫會以內容固定的 JSON 格式序列化至 `<codePath>/agents/<encodedAgentId>.json`。`codePath` 預設為 `./mastra/editor`。

首次發佈 Agent 時會建立此檔案。之後的伺服器更新預設會建立草稿，並在該版本啟用時寫入檔案。Studio 中的 Git 版本為唯讀，並以提交訊息作為變更說明。預設歷史掃描最多讀取最近 50 個提交，並略過解析後 JSON 快照與前一個相同的連續提交。

來源選項請參閱 [`MastraEditor`](/reference/editor/mastra-editor#source)。

## 選擇 Agent 版本 {/* #select-an-agent-version */}

未傳入選擇條件而呼叫 [`mastra.getAgentById()`](/reference/core/getAgentById) 時，會傳回已註冊的程式碼定義 Agent。傳入 `status` 或 `versionId` 可套用已儲存的覆寫版本。TypeScript 範例請參閱[選擇版本](/docs/studio/editor#select-a-version)。

使用預設伺服器前綴時，將選擇條件作為 `/api` 路徑的查詢參數傳入：

```bash title="Version selection through the API"
# Published version
curl http://localhost:4111/api/agents/support-agent

# Latest draft
curl http://localhost:4111/api/agents/support-agent?status=draft

# Exact version
curl http://localhost:4111/api/agents/support-agent?versionId=abc-123
```

Client SDK 和 React SDK 的選擇條件請參閱 [Client SDK Agent 參考文件](/reference/client-js/agents#version-management)。

## 子 Agent 版本管理 {/* #sub-agent-versioning */}

版本覆寫會透過請求內容沿[監督 Agent 委派](/docs/subagents)傳遞。可在三個層級指定選擇條件：

1. `Mastra` 執行個體的 `versions`：每次呼叫的預設值
2. 伺服器請求內容中的 `versions`：加入請求內容的單次請求設定
3. 直接呼叫 `generate()` 或 `stream()` 時的 `versions`：單次呼叫設定

項目依 Agent ID 合併。對同一個 ID，優先次序為：**直接呼叫 > 請求內容或現有請求內容 > Mastra 執行個體預設值**。

在 Mastra 執行個體上設定預設值：

```typescript title="src/mastra/index.ts"
import { Mastra } from '@mastra/core'
import { MastraEditor } from '@mastra/editor'

export const mastra = new Mastra({
  agents: { supervisor, researchAgent, writerAgent },
  editor: new MastraEditor(),
  versions: {
    agents: {
      'research-agent': { status: 'published' },
      'writer-agent': { versionId: 'abc-123' },
    },
  },
})
```

為單次直接呼叫覆寫某個子 Agent：

```typescript title="src/routes/experiment.ts"
const result = await supervisor.generate('Research and write about AI safety', {
  versions: {
    agents: {
      'research-agent': { status: 'draft' },
    },
  },
})
```

也可以在伺服器請求內容中傳入選擇條件：

```bash title="Per-request sub-agent versions"
curl -X POST http://localhost:4111/api/agents/supervisor/generate \
  -H "Content-Type: application/json" \
  -d '{
    "messages": [{ "role": "user", "content": "Research AI safety" }],
    "versions": {
      "agents": {
        "research-agent": { "status": "draft" }
      }
    }
  }'
```

若未設定 Editor 或無法解析指定版本，Mastra 會記錄警告並使用程式碼定義的子 Agent。

## 已儲存 Agent REST API {/* #stored-agent-rest-api */}

Mastra 伺服器的預設前綴為 `/api`。自訂伺服器前綴會改變下列路徑。

| 方法 | 路徑 | 說明 |
| - | - | - |
| `GET` | `/api/stored/agents` | 列出已儲存的 Agent |
| `POST` | `/api/stored/agents` | 建立已儲存的 Agent |
| `GET` | `/api/stored/agents/:storedAgentId` | 取得已儲存的 Agent |
| `PATCH` | `/api/stored/agents/:storedAgentId` | 更新已儲存的 Agent |
| `DELETE` | `/api/stored/agents/:storedAgentId` | 刪除已儲存的 Agent |
| `GET` | `/api/stored/agents/:storedAgentId/dependents` | 列出可讀取的依賴項目，並統計隱藏的跨 Workspace 引用 |
| `POST` | `/api/stored/agents/:storedAgentId/export` | 將允許覆寫的欄位匯出為內容固定的 JSON |

依賴項目回應會依 `id` 和 `name` 列出呼叫者可讀取的 Agent。只有目標 Agent 為公開時，`hiddenCount` 欄位才會統計呼叫者無法讀取的跨 Workspace 引用。

版本管理路由位於 `/api/stored/agents/:storedAgentId/versions` 之下。操作和 Client SDK 方法請參閱[版本管理](/reference/client-js/agents#version-management)。

Client SDK 提供 `listStoredAgents()`、`createStoredAgent()` 和 `getStoredAgent()`。`getStoredAgent(id)` 傳回的資源包含更新、刪除、查詢依賴項目、匯出及版本管理方法。
