# Tool配置

編輯器將Tool選擇儲存為Agent版本的一部分。儲存的配置可以新增已註冊的Tool和來自整合提供者的Tool，以及來自模型上下文協定 (MCP) 用戶端的Tool。

看[Editor tools](/docs/studio/editor#tools) for the Studio workflow and common uses.

## Tool來源 {/* #tool-sources */}

|來源 |描述 |
| - | - |
|登錄Tool |在 Mastra 運行時Tool註冊表中註冊的Tool |
| MCP 客戶 |儲存的本機或遠端 MCP 伺服器設定公開的Tool |
|整合Tool|由遺留整合提供者配置解決的Tool |
|[Tool providers](/reference/editor/tool-provider) | Tools resolved by providers registered on `MastraEditor`, such as Composio or Arcade |

程式碼定義的Agent保留其現有Tool。這[`editor` override setting](/reference/agents/agent#editor-overrides) controls whether Editor can add and remove tools or only change descriptions.

## 描述覆蓋 {/* #description-overrides */}

每個選定的Tool都可以儲存特定於Agent的描述。描述改變了模型所看到的內容，而不修改原始Tool定義。

在僅描述模式下，編輯器僅將覆寫套用至程式碼定義Agent程式上已存在的Tool。對於 MCP Tool，Agent程式級描述優先於 MCP 用戶端上儲存的描述。

如果兩個來源解析相同的Tool ID，則較晚的來源將取代完整的較早Tool，包括其描述。看[Resolution order](#resolution-order).

## 條件Tool集 {/* #conditional-tool-sets */}

編輯器可以儲存條件變體`tools`, `mcpClients`, `integrationTools`, and `toolProviders` fields. At runtime, matching variants are shallow-merged based on request-context values.

規則語言使用與以下相同的運算子和巢狀行為[prompt block display conditions](/reference/editor/prompt-blocks#display-conditions).

條件適用於Tool欄位變體或 MCP 用戶端參考。每個Tool`rules` values in stored tool entries aren't evaluated by the current Editor resolver.

## 儲存的 MCP 用戶端 {/* #stored-mcp-clients */}

這`editor.mcp` namespace manages reusable MCP client configurations. See the [`mcp` namespace](/reference/editor/mastra-editor#namespaces) for CRUD method signatures.

`@mastra/mcp`是可選的對等依賴項`@mastra/editor`. Install it before configuring stored MCP clients so Editor can load their tools at runtime:

```bash npm2yarn
npm install @mastra/mcp
```

### 交通 {/* #transports */}

|交通 |儲存的配置 |
| - | - |
|`stdio` | `command` with optional `args`, `env`, and `timeout` |
| HTTP | `url` with optional `timeout` |

儲存的 HTTP 定義不接受任意標頭。當保留`mastra__authToken` value is present in request context, Editor forwards it as an `Authorization: Bearer` header.

### 濾 {/* #filtering */}

MCP Tool可以在兩個層級列入許可名單：

1. **伺服器級別**: 儲存的伺服器的`tools` map limits tools for every agent that uses the client. Omitting `tools` at this level exposes all of the server's tools.
2. **Agent級別**：Agent的 MCP 用戶端引用限制該Agent的剩餘Tool。省略`tools` at this level selects no tools.

Agent級Tool名稱可以使用命名空間或裸名稱。若要選擇Agent程式層級的每個剩餘Tool，請傳遞明確的空`tools` map:

```typescript
const mcpClients = {
  'docs-client': { tools: {} }, // all tools
  'search-client': { tools: { docs_search: {} } }, // only docs_search
  'billing-client': {}, // no tools
}
```

### 命名空間 {/* #namespacing */}

MCPTool使用`serverName_toolName` IDs to avoid conflicts. A `search` tool from the `docs` server becomes `docs_search`.

## 決議順序 {/* #resolution-order */}

編輯器會依下列順序合併Tool記錄。後面的記錄用相同的 ID 取代前面的記錄。

1. 程式碼定義的Tool
2. 註冊儲存Tool
3. MCPTool
4. 遺留整合Tool
5. V1Tool-提供者Tool

獨立儲存Agent程式使用相同的順序，無需代碼定義的Tool。靜態程式碼Agent程式覆蓋在舊整合Tool之後停止。

盡可能使用跨來源的唯一Tool ID。碰撞取代了完整的早期Tool，而不是合併其欄位。
