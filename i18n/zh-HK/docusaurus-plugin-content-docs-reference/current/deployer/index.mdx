# Deployer

Deployer 透過封裝程式碼、管理環境檔案，並使用 Hono 框架提供應用程式服務，負責部署獨立運作的 Mastra 應用程式。具體實作必須為目標部署環境定義部署方法。

## 使用範例 {/* #usage-example */}

如要建立自訂 Deployer，可以繼承抽象類別 `Deployer`，並在 `deploy` 方法中實作目標環境所需的部署邏輯。例如：

```typescript
import { Deployer } from '@mastra/deployer'

class CustomDeployer extends Deployer {
  constructor() {
    super({ name: 'custom-deployer' })
  }

  async deploy(outputDirectory: string): Promise<void> {
    // Prepare the output directory
    await this.prepare(outputDirectory)

    // Bundle the application
    await this._bundle('server.ts', 'mastra.ts', {
      projectRoot: process.cwd(),
      outputDirectory,
    })

    // Custom deployment logic
  }
}
```

## 核心概念 {/* #core-concepts */}

### 部署生命週期 {/* #deployment-lifecycle */}

Deployer 抽象類別實作了結構化的部署生命週期：

1. **初始化**：使用名稱初始化 Deployer，並建立 Deps 實例來管理依賴項。
1. **環境設定**：`getEnvFiles` 方法找出部署時使用的環境檔案（`.env`、`.env.local`、`.env.production`）。
1. **準備**：繼承自 Bundler 的 `prepare` 方法清理輸出目錄並建立所需的子目錄。
1. **封裝**：繼承自 Bundler 的 `_bundle` 方法封裝應用程式程式碼及其依賴項。
1. **部署**：子類別實作抽象方法 `deploy`，執行實際部署。

### 環境檔案管理 {/* #environment-file-management */}

Deployer 類別透過 `getEnvFiles` 方法提供內置的環境檔案管理功能。此方法：

- 按優先次序由低至高的預定順序尋找環境檔案：`.env`、`.env.local`、`.env.production`
- 依此順序傳回所有現有檔案，因此後面檔案中的值會覆蓋前面檔案中的值
- 如找不到環境檔案，則傳回空陣列

```typescript oxfmt:false
getEnvFiles(): Promise<string[]> {
  const possibleFiles = ['.env', '.env.local', '.env.production'];
  const fileService = new FileService();

  return Promise.resolve(fileService.getExistingFiles(possibleFiles));
}
```

### 封裝與部署的關係 {/* #bundling-and-deployment-relationship */}

Deployer 類別繼承 Bundler 類別，明確連結封裝與部署：

1. **封裝是前提**：部署前必須先將應用程式程式碼封裝成可部署的形式。
1. **共用基礎功能**：封裝與部署共用依賴項管理和檔案系統操作等基礎功能。
1. **專屬部署邏輯**：封裝負責整理程式碼，部署則加入目標環境所需的邏輯，部署封裝後的程式碼。
1. **可擴充性**：透過實作抽象方法 `deploy`，可為不同目標環境建立專屬的 Deployer。
