# VercelDeployer

`VercelDeployer` 會打包 Mastra 伺服器，並產生符合 Vercel [Build Output API](https://vercel.com/docs/build-output-api/v3) 的建置輸出。Vercel 會直接將這些輸出部署為無伺服器函數。

## 安裝 {/* #installation */}

要使用 `VercelDeployer`，請安裝 `@mastra/deployer-vercel` 套件：

```bash npm2yarn
npm install @mastra/deployer-vercel@latest
```

## 使用範例 {/* #usage-example */}

匯入 `VercelDeployer`，並在 Mastra 配置中將其設為部署器：

```typescript title="src/mastra/index.ts"
import { Mastra } from '@mastra/core'
// highlight-next-line
import { VercelDeployer } from '@mastra/deployer-vercel'

export const mastra = new Mastra({
  // highlight-next-line
  deployer: new VercelDeployer(),
})
```

## 建構函數選項 {/* #constructor-options */}

部署器接受以下選項：

- `studio?: boolean`: 將 [Studio](/docs/studio/overview) 與 API 一同部署為由 Vercel Edge CDN 提供的靜態資源。預設為 `false`。
- `maxDuration?: number`: 函數執行逾時時間（秒）。此選項只設定 Vercel 的限制；Mastra 的請求逾時需另外配置，請參閱[請求逾時](#request-timeouts)。
- `memory?: number`: 函數記憶體（MB）
- `regions?: string[]`: 函數的部署區域（例如 `['sfo1','iad1']`）

`maxDuration`、`memory` 和 `regions` 選項會合併至 `.vercel/output/functions/index.func/.vc-config.json`，同時保留預設欄位（`handler`、`launcherType`、`runtime`、`shouldAddHelpers`）。

### 自訂選項範例 {/* #example-with-overrides */}

```typescript title="src/mastra/index.ts"
import { Mastra } from '@mastra/core'
import { VercelDeployer } from '@mastra/deployer-vercel'

export const mastra = new Mastra({
  deployer: new VercelDeployer({
    studio: true,
    maxDuration: 600,
    memory: 1536,
    regions: ['sfo1', 'iad1'],
  }),
})
```

## 請求逾時 {/* #request-timeouts */}

Vercel 的函數執行時限與 Mastra 的請求逾時會分別生效：

- **Vercel 函數執行時限**：由部署器的 `maxDuration` 選項設定，單位為秒。
- **Mastra 請求逾時**：透過 `server.timeout` 在 `Mastra` 配置中指定，單位為毫秒。未設定時預設為 `180000`（180 秒）；逾時請求會收到 `504 Gateway Timeout` 回應。

`maxDuration` 不會改變 `server.timeout`。即使 `maxDuration` 設得較高，請求超過 180 秒仍會失敗。因此，執行 Workflow 或串流 Agent 等耗時較長的請求時，須同時提高這兩個值：

```typescript title="src/mastra/index.ts"
import { Mastra } from '@mastra/core'
import { VercelDeployer } from '@mastra/deployer-vercel'

export const mastra = new Mastra({
  deployer: new VercelDeployer({
    maxDuration: 600, // seconds
  }),
  server: {
    timeout: 600_000, // milliseconds, keep at or below maxDuration
  },
})
```

## 建置輸出 {/* #build-output */}

執行 `mastra build` 後，部署器會產生符合 Vercel [Build Output API (v3)](https://vercel.com/docs/build-output-api/v3) 的 `.vercel/output` 目錄。其中包含路由配置和無伺服器函數套件，Vercel 可直接部署，無須偵測框架。

建置輸出包括：

- **config.json**：將請求導向相應處理程式的路由配置
- **functions/**：打包為無伺服器函數的 Mastra 伺服器
- **static/**：Studio 單頁應用程式的靜態資源（僅在 `studio: true` 時產生）

未啟用 Studio 時：

```bash
.vercel/
└── output/
    ├── config.json
    └── functions/
        └── index.func/
            ├── .vc-config.json
            ├── index.mjs
            └── node_modules/
```

啟用 `studio: true` 時：

```bash
.vercel/
└── output/
    ├── config.json
    ├── static/
    │   ├── index.html
    │   └── assets/
    │       ├── *.js
    │       └── *.css
    └── functions/
        └── index.func/
            ├── .vc-config.json
            ├── index.mjs
            └── node_modules/
```

啟用 Studio 後，路由會將 `/` 和 Studio 建置路由清單中列出的路徑交由 `index.html` 提供，讓用戶端處理路由；靜態資源（JS、CSS）則由 Vercel Edge CDN 提供，不會呼叫函數。其他所有路徑，包括 `/api/*` 和透過 `registerApiRoute()` 註冊的自訂路由，都由無伺服器函數處理。若自訂路由位於 Studio 路由之下（例如 `/agents/custom`），則會由 `index.html` 提供，因此應將自訂路由註冊在 Studio 路由根路徑之外。

此目錄在建置時產生，不應提交至版本控制系統。
