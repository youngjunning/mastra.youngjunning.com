# 通路提供者

`ChannelProvider`是平台整合實現的用於將Agent連接到訊息傳遞平台的介面。提供者擁有完整的整合生命週期。這包括使用 OAuth 進行應用程式配置、使用事件處理進行 Webhook 路由、適配器建立和Agent連接以及憑證管理。

在 上註冊提供者`Mastra` constructor under `channels`，由您選擇的 id 鍵入。每個提供者的路由都會自動合併到伺服器的 API 路由中，並且`initialize()`在 Mastra 啟動期間運行。

```typescript title="src/mastra/index.ts"
import { Mastra } from '@mastra/core/mastra'
import { SlackProvider } from '@mastra/slack'

export const mastra = new Mastra({
  channels: {
    slack: new SlackProvider({
      refreshToken: process.env.SLACK_REFRESH_TOKEN!,
      baseUrl: process.env.MASTRA_BASE_URL,
    }),
  },
})
```

提供者的`baseUrl` is the public URL the platform sends webhooks and events to. In production this is your deployed Mastra server URL. For local development, the platform can't reach `http://localhost:4111`, so run a tunnel (such as [cloudflared](https://developers.cloudflare.com/cloudflare-one/connections/connect-networks/) or [ngrok](https://ngrok.com/)）並點`baseUrl`在隧道 URL 處（例如`https://abc123.trycloudflare.com`）以便事件到達您的本機開發流程。

馬斯特拉包括[`SlackProvider`](/reference/channels/slack-provider) and [`TelegramProvider`](/reference/channels/telegram-provider) implementations. Build a custom provider by implementing this interface.

## 動態解析度 {/* #dynamic-resolution */}

而不是靜態記錄，`channels` also accepts a resolver: an async function returning the current provider map, with a synchronous `getRoutes()` method. Mastra mounts the resolver's routes at construction and resolves providers at runtime, so connections added after boot become usable without a redeploy. The `channels()` helper from `@mastra/connect` returns a resolver backed by the Mastra platform.

```typescript title="src/mastra/index.ts"
import { Mastra } from '@mastra/core/mastra'
import { channels } from '@mastra/connect'

export const mastra = new Mastra({
  channels: await channels({ projectId: process.env.MASTRA_PROJECT_ID! }),
})
```

配置解析器後，調用`resolveChannels()` to get the current provider map. It also works with a static record, where it returns the record directly.

```typescript
const providers = await mastra.resolveChannels()
```

## 訪問提供者 {/* #accessing-a-provider */}

透過以下方式存取註冊提供者`channels` getter, keyed by the id you registered it under. The getter is typed from the constructor config, so `mastra.channels.slack` is the concrete provider with its full method surface.

```typescript
await mastra.channels.slack.configure({ refreshToken })
```

當密鑰僅在運行時已知時，請改為透過字串 id 查找提供者。`getChannelProvider` takes the concrete type as a generic, and `getChannelProviders` returns every registered provider keyed by id. With a [resolver](#dynamic-resolution), both return the latest resolved snapshot. Use `resolveChannels()` when you need providers that reflect the current platform state.

```typescript
import type { SlackProvider } from '@mastra/slack'

const slack = mastra.getChannelProvider<SlackProvider>('slack')
const all = mastra.getChannelProviders()
```
