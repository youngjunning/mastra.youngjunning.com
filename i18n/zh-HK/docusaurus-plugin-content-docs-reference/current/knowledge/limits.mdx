# 限制

文字限制以 token 計算。數量屬估算值，因此下表數值均為約數。

：：：阿爾法

Knowledge 目前處於 alpha 階段，其 API 可能隨版本變更。

:::

| 項目 | 限制 |
| - | - |
| 筆記文字 | 250 tokens |
| 頁面描述 | 100 tokens |
| 頁面巢狀層級 | 10 層 |
| 單次移動的頁面數（包括被移動頁面之下的所有頁面） | 500 |
| `knowledge_search` 的結果數，以及每次 `knowledge_read` 傳回的筆記及子頁面數 | 預設 10，最多 50 |
| 頁面正文或 `match` 結果（每次 `knowledge_read`） | 預設 1,000 tokens，最少 100 |
| 完整 `knowledge_read` 中保留的筆記，以及提及該頁面的筆記 | 每份清單 1,000 tokens |
| `knowledge_list` 項目 | 預設 50，最多 100；預設約 1,000 tokens 以內 |
| `knowledge_list` 深度 | 預設 1 層，最多 3 層 |
| 每頁用於語義搜尋的 Embedding 分塊 | 100 個，每塊約 2,000 tokens |
| 每回合的釘選內容 | 預設 500 tokens，無上限 |
| 每回合釘選的頁面數 | 預設 20 |
| 釘選清單的深度 | 預設 1 層，最多 3 層 |
| 每份釘選清單中的頁面數 | 在分配到的 token 預算內盡可能多，最多 1,000 |

寫入內容超出限制時，操作會失敗，模型會從工具結果收到錯誤。工具 Schema 不會顯示 token 限制，因為 Schema 無法計算 token 數。

頁面正文沒有 token 上限。`knowledge_read` 會分段傳回較長的正文，Agent 可按行 `range` [逐段編輯](/reference/knowledge/knowledge-tools#knowledge_page)。釘選頁面的正文會截斷，以符合釘選內容的預算。請參閱[一次執行會收到的內容](/docs/knowledge/pinned-context#what-a-run-receives)。

如果頁面太長，無法放入單一 Embedding，系統會在段落之間及標題之前切成互相重疊的分塊。每個分塊都以頁面名稱和描述開頭。搜尋只會傳回該頁面一次，並按最相符的分塊排序。超過 100 個分塊後，正文其餘部分只能透過關鍵字搜尋找到。重寫頁面會取代其分塊，刪除頁面則會移除分塊。

無法放入預算的釘選頁面會按以下方式處理：

- 設定中釘選的頁面絕不會被捨棄。如果單是這些頁面就超出預算，每頁會獲得相同份額並被截斷。
- 被截斷的釘選頁面以 `[truncated — knowledge_read for the rest]` 結尾。
- 放不下的 Agent 釘選頁面會在同一行列出名稱，最多十個，其餘以數量表示，例如：`Also pinned (open with knowledge_read): Refund Policy, …and 3 more`。

釘選清單計作一個釘選項目，並共用 token 預算。放不下的清單會逐層填入，每個頁面仍列在其父頁面之下。若有頁面被省略，清單結尾會顯示 `…and 4 more; knowledge_list from: "site:mastra"`；如果取得的頁面不足以確定省略數量，則顯示 `…and more`。再次釘選清單會設定新的深度；如果已儲存的清單與設定中的清單重複，只會提供一次。

如果某個 scope 聲明的 `pinnedContext` 頁面數超過 `maxPins`，或頁面太多導致每頁分到的 token 少於 50，Knowledge 會在啟動時記錄警告。

透過 `tools: { read: { maxTokens } }` 調整讀取上限，請參閱 [`tools`](/reference/knowledge/knowledge-class#constructor-options)。透過 `pinnedContext: { maxPins, maxTokens }` 調整 `Knowledge` 的釘選限制。
