# Knowledge 類別

`Knowledge` 類別儲存頁面及筆記，宣告有哪些範圍、各主體在其中擁有甚麼角色，並為連接的 Agent 提供 Knowledge Tool。功能介紹及快速入門請參閱 [Knowledge](/docs/knowledge/overview)。

:::alpha

Knowledge 目前處於 alpha 階段，API 可能隨版本變更。

:::

## 使用範例 {/* #usage-example */}

```typescript title="src/mastra/knowledge.ts"
import { Knowledge, knowledgeMemoryScopes } from '@mastra/core/knowledge'
import { LibSQLStore } from '@mastra/libsql'

export const knowledge = new Knowledge({
  id: 'company',
  storage: new LibSQLStore({ id: 'knowledge', url: 'file:./knowledge.db' }),
  tools: true,
  scopes: {
    ...knowledgeMemoryScopes(),
    'team:$orgId:$teamId': {
      access: [
        { principal: 'self', role: 'editor' },
        { principal: 'org:$orgId', role: 'viewer' },
      ],
    },
  },
})
```

建構函式會擲出 `KnowledgeDeclarationError`：例如缺少 `scopes`，或宣告無效（同一類型的兩個模式重疊，或規則中的主體無法綁定）。缺少 `scopes` 時，錯誤訊息為：

```text
Knowledge needs `scopes`: declare the scopes its runs hold, e.g. `scopes: { ...knowledgeMemoryScopes() }`, or `{}` for none.
```

## 方法 {/* #methods */}

### 工具 {/* #tools */}

#### `createTools()` {/* #createtools */}

```typescript oxfmt:false
createTools(options?: { read?: boolean; write?: boolean; pinnedContext?: boolean }): Record<string, Tool>
```

傳回可明確連接的 Knowledge Tool，例如供未透過 `knowledge` 連接的 Agent 使用。每個選項都會覆寫實例上的對應 Tool 群組；省略的選項沿用實例設定。如實例啟用 `pinnedContext`，`createTools({ write: false })` 仍會傳回 `knowledge_pin`。請參閱 [Knowledge Tool](/reference/knowledge/knowledge-tools)。

```typescript
const tools = knowledge.createTools({ write: false })
// knowledge_list, knowledge_search, knowledge_read
```

#### `getInstructions()` {/* #getinstructions */}

```typescript oxfmt:false
getInstructions(options?: { read?: boolean; write?: boolean; pinnedContext?: boolean }): string
```

傳回與 `createTools(options)` 配套的使用說明。其建立方式與連接 Agent 時相同：可使用已啟用 Tool 群組的內建說明片段，亦可使用 `instructions` 選項產生的說明。

### 存取控制 {/* #access */}

#### `explainAccess()` {/* #explainaccess */}

```typescript oxfmt:false
explainAccess(
  runScopes: readonly string[],
  target: { scope: string } | { page: string },
): Promise<KnowledgeAccessExplanation>
```

說明持有 `runScopes` 的執行為何能或不能存取某個範圍或頁面。`runScopes` 是標準地址，包括 `resource:` 及 `thread:`（標準地址 `resource:slack%3AU123` 對應 Memory 資源 `slack:U123`）。`target.page` 接受頁面 ID 或 `org:acme#policies/refund` 這類頁面路徑。

```typescript
await knowledge.explainAccess(['org:acme'], { page: 'team:acme:support#refunds' })
// {
//   role: 'viewer',
//   reasons: [{ principal: 'org:acme', role: 'viewer', rule: 'team:$orgId:$teamId', via: 'rule' }],
//   page: { id: '…', scope: 'team:acme:support' },
// }

await knowledge.explainAccess(['org:globex'], { page: 'team:acme:support#refunds' })
// { role: null, reasons: [], page: { id: '…', scope: 'team:acme:support' }, reason: 'hidden' }
```

未宣告的執行範圍會擲出錯誤，與執行開始時的行為相同：

```text
Knowledge run scope "project:x" does not match a declared scope type. Declare it in Knowledge `scopes` (for Memory's resource:/thread: scopes, spread `...knowledgeMemoryScopes()`).
```

未宣告的 `target.scope` 會擲出 `Knowledge scope "project:x" does not match a declared scope type.`

:::warning

`explainAccess()` 只能由宿主呼叫。它能區分頁面不存在及頁面被隱藏，而執行絕不能得知這項差異。請勿透過 Agent Tool，或未實施管理員級身分驗證的伺服器路由，公開此方法。

:::

#### `readScopeFor()` {/* #readscopefor */}

```typescript oxfmt:false
readScopeFor(principals: readonly string[]): Promise<KnowledgeReadScope>
```

傳回 `principals` 持有者可讀取的內容：這些主體本身，以及其規則授予角色的所有範圍。角色不會再傳遞至其他範圍。宿主程式碼代表用戶讀取 Knowledge 時，請將結果作為 `read` 傳給儲存空間的讀取方法。未宣告的主體會擲出 `Knowledge run scope "project:x" does not match a declared scope type.`；空列表則無法讀取任何內容。

#### `scopeGrants()` {/* #scopegrants */}

```typescript oxfmt:false
scopeGrants(scope: { address: string; parentAddress?: string | null }): KnowledgeScopeGrant[]
```

傳回宣告授予其他範圍在目前範圍上的角色，形式為 `{ principal, role }`。每個主體只保留最高角色，且不包含 `self` 規則。此方法不讀取儲存空間。`parentAddress` 提供透過 `belongsTo` 綁定的規則所需的樹狀父層。它適用於顯示範圍間存取關係的瀏覽介面；如要查看某次執行的權限，請使用 `explainAccess()`。

#### `scopeDeclaration()` {/* #scopedeclaration */}

```typescript oxfmt:false
scopeDeclaration(key: string): KnowledgeScopeDeclarationInfo | undefined
```

按宣告鍵傳回建立範圍時使用的宣告，供介面顯示：`{ key, description?, displayLabel?, belongsTo?, children }`。亦支援 `org:$orgId/private` 這類子鍵。不包含存取規則；如要查看規則，請使用 `explainAccess()`。未知的鍵會傳回 `undefined`。

#### `scopeLabel()` {/* #scopelabel */}

```typescript oxfmt:false
scopeLabel(address: string): string | undefined
```

傳回範圍地址的 `displayLabel`，並填入其中的 `$params`：`'$orgId organization'` 用於 `org:$orgId` 時，會產生 `acme organization`，對應 `org:acme`。具體地址自身的 `displayLabel` 優先。如地址不符合任何宣告或沒有標籤，則傳回 `undefined`。

### 宿主寫入操作 {/* #host-writes */}

`upsertPage()`、`removePage()`、`addNote()`、`updateNote()` 及 `removeNote()` 只能由宿主呼叫：它們不會檢查執行範圍或存取規則。請勿透過 Agent Tool，或未實施管理員級身分驗證的伺服器路由，公開這些方法。

#### `upsertPage()` {/* #upsertpage */}

```typescript oxfmt:false
upsertPage(input: {
  scope: string
  path: string
  name: string
  description?: string
  body?: string
  author?: string
}): Promise<{ page: KnowledgePage; status: 'created' | 'updated' | 'unchanged' }>
```

建立或更新 `path` 對應的頁面（鍵以 `/` 連接，例如 `guides/install`），並將它放在 `scope` 中；缺少的範圍及路徑中的頁面亦會一併建立。再次寫入相同路徑會更新該頁面。省略 `description` 或 `body` 時，會保留已儲存的值。傳回 `unchanged` 表示沒有寫入：頁面版本不變，不觸發變更事件，亦不會重新產生嵌入。`author` 會記錄為寫入者，預設為 `host`。不含鍵的路徑會擲出 `Knowledge page path "<path>" needs at least one key.`。請參閱[載入內容](/docs/knowledge/load-your-content)。

#### `removePage()` {/* #removepage */}

```typescript oxfmt:false
removePage(input: { scope: string; path: string; author?: string }): Promise<KnowledgePage | null>
```

刪除 `path` 對應的頁面並傳回該頁面；如頁面不存在，則傳回 `null`。如頁面有子頁面，會擲出 `"<scope>#<path>" has child pages; remove them first.`；如它是範本頁面，會擲出 `"<scope>#<path>" is declared in config; change the scope's pages to remove it.`。如另一次寫入先修改頁面，則直接擲出錯誤，不會重試。

#### `addNote()` {/* #addnote */}

```typescript oxfmt:false
addNote(input: {
  scope: string
  path: string
  text: string
  when?: Date
  stamps?: string[]
  author?: string
}): Promise<KnowledgeNote>
```

向 `path` 對應的頁面新增筆記。`text` 最多 250 個 Token。對現有頁面的 `[[scope#path]]` 提及會將筆記連結到那些頁面；其他 `[[...]]` 文字保持純文字。`stamps` 是可看見該筆記的讀者所屬範圍地址，預設使用頁面範圍。頁面不存在時會擲出 `KnowledgeNotFoundError`。

#### `updateNote()` {/* #updatenote */}

```typescript oxfmt:false
updateNote(input: { id: string; text: string; when?: Date; stamps?: string[]; author?: string }): Promise<KnowledgeNote>
```

取代筆記時，會先新增新筆記，再刪除舊筆記，最後傳回具有新 ID 的筆記。省略 `when` 或 `stamps`，或傳入空值時，會保留其舊值。如新增後刪除舊筆記失敗，兩筆筆記都會留下，呼叫會擲出錯誤；請自行刪除不需要的那筆。如舊筆記已被其他操作刪除，新筆記亦會移除，不會留下任何筆記。

#### `removeNote()` {/* #removenote */}

```typescript oxfmt:false
removeNote(input: { id: string; author?: string }): Promise<KnowledgeNote | null>
```

刪除筆記並傳回該筆記；如已刪除，則傳回 `null`。

### 儲存及維護 {/* #storage-and-maintenance */}

#### `getStorage()` {/* #getstorage */}

```typescript oxfmt:false
getStorage(): Promise<KnowledgeStorage>
```

傳回 Knowledge 儲存空間，供管理頁面、刪除操作及自訂匯入腳本等宿主程式碼使用。其讀取方法接受 `read`：`'all'` 會略過角色檢查。如讀取應限於用戶可見內容，請傳入 `readScopeFor()` 的傳回值。

```typescript
const store = await knowledge.getStorage()
const read = await knowledge.readScopeFor(['org:acme'])
const [scope] = await store.getScopesByAddress(['team:acme:support'])
const page = await store.getPageByPath({ scopeId: scope.id, path: ['handbook', 'refunds'], read })
```

#### `reindexLinks()` {/* #reindexlinks */}

```typescript oxfmt:false
reindexLinks(): Promise<number>
```

從所有頁面正文重建頁面連結索引，並傳回已索引的頁面數量。正常寫入會保持索引更新，因此此方法適用於索引建立前的頁面，或直接寫入儲存空間的頁面。它不需要向量儲存空間。

#### `renameScopeDeclaration()` {/* #renamescopedeclaration */}

```typescript oxfmt:false
renameScopeDeclaration(from: string, to: string): Promise<number>
```

將從宣告鍵 `from` 建立的已儲存範圍及其子範圍（`from/<name>`），一次遷移至鍵 `to`，並傳回遷移的範圍數量。如 `from` 仍存在於 `scopes`、`to` 不存在，或某個已儲存地址不符合 `to` 的模式，此方法會拒絕執行，且不作任何修改。在儲存鍵與 `scopes` 一致之前，實例會拒絕運作。

在 MongoDB 上，重新命名僅在副本集上的交易中執行。在獨立伺服器上，它不是原子的，並且中途失敗可能會導致某些範圍被重新命名。

請參閱[重新命名或停用範圍類型](/reference/knowledge/scope-declarations#rename-or-retire-a-scope-type)。

### 事件 {/* #events */}

#### `onChange()` {/* #onchange */}

```typescript oxfmt:false
onChange(listener: (event: KnowledgeChangeEvent) => void): () => void
```

每次透過此實例的儲存空間完成寫入後，都會呼叫 `listener`：包括 Tool 寫入、透過 `getStorage()` 進行的宿主寫入，以及新增範圍。傳回值是取消監聽的函式。可用它更新即時介面。透過其他方式取得的儲存空間所發生的寫入，不會被此監聽器偵測到。

事件只帶有 ID，不包含內容或存取權限。因此，任何將事件轉送給用戶的服務，都必須透過 `readScopeFor()`，在該用戶可讀取的範圍內重新讀取各頁面：

| `kind` | `op` | Fields |
| - | - | - |
| `scope` | `create` | `pageId`、`scopeId`（新範圍頁面的 ID） |
| `page` | `create`、`update`、`move`、`merge`、`delete` | `pageId`、`scopeId`；`fromScopeId` 用於 `move` 及 `merge`；`sourceId` 用於 `merge`，表示被合併頁面的 ID |
| `note` | `add`、`restamp`、`remove`、`restore` | `pageId`、`noteId` |
| `pin` | `add`、`remove` | `pageId` |

每個事件還包含 `knowledgeId` 及 `at`。建立範圍時只會送出一個 `scope` 事件，不會為每個子範圍或範本頁面分別送出，因此收到事件時應重新列出該範圍。監聽器擲出的錯誤會被記錄，但不會令寫入失敗。

```typescript
const unsubscribe = knowledge.onChange(event => {
  if (event.kind === 'page') refreshPage(event.pageId)
})
```

### 屬性 {/* #properties */}

#### `pinnedContextEnabled` {/* #pinnedcontextenabled */}

`boolean`。表示 `pinnedContext` 是否啟用；啟用後，已連接 Agent 每回合都會收到釘選頁面。
