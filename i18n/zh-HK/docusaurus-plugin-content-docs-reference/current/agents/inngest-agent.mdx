# `createInngestAgent()`

:::測試版

在 API 穩定之前，可能會在沒有重大版本更新的情況下發生重大變更。

:::

`createInngestAgent()`包裝現有的[`Agent`](/reference/agents/agent) with [因格斯特](https://www.inngest.com/docs)- 動力持久的執行力。喜歡[`createDurableAgent()`](/reference/agents/durable-agent#createdurableagentoptions)，它串流事件[發布訂閱](/docs/server/pubsub)並支援可恢復流，但在 Inngest 的執行引擎上而不是在進程內運行Agent循環。當運行必須在進程重新啟動後繼續存在或在分散式環境中運行時使用它。

對於進程內持久執行，請使用[`createDurableAgent()`](/reference/agents/durable-agent#createdurableagentoptions). For fire-and-forget execution on the built-in workflow engine, use [`createEventedAgent()`](/reference/agents/durable-agent#createeventedagentoptions).

## 使用範例 {/* #usage-example */}

設定 Inngest 用戶端，包裝Agent，將其註冊到 Mastra，並公開 Inngest 服務端點：

```typescript title="src/mastra/index.ts"
import { Mastra } from '@mastra/core'
import { Agent } from '@mastra/core/agent'
import { createInngestAgent, serve as inngestServe } from '@mastra/inngest'
import { Inngest } from 'inngest'

const inngest = new Inngest({ id: 'my-app' })

const agent = new Agent({
  id: 'my-agent',
  name: 'My Agent',
  instructions: 'You are a helpful assistant',
  model: '__GATEWAY_OPENAI_MODEL__',
})

const durableAgent = createInngestAgent({ agent, inngest })

export const mastra = new Mastra({
  agents: { myAgent: durableAgent },
  server: {
    apiRoutes: [
      {
        path: '/inngest/api',
        method: 'ALL',
        createHandler: async ({ mastra }) => inngestServe({ mastra, inngest }),
      },
    ],
  },
})
```

串流回應並讀取結果：

```typescript
const { output, runId, cleanup } = await durableAgent.stream('Hello!')

const text = await output.text

cleanup()
```

## `InngestAgent`介面 {/* #inngestagent-interface */}

傳回的對象`createInngestAgent()`. It provides the durable execution methods below. Any property or method not explicitly defined (e.g., `listTools()` and `getMemory()`) is forwarded to the underlying agent via a Proxy. Thread APIs such as `sendSignal()`, `sendStateSignal()`, `sendNotificationSignal()`, and `subscribeToThread()` are forwarded too, but a signal that wakes an idle thread starts the run through the durable `stream()`.

## 方法 {/* #methods */}

### 執行 {/* #execution */}

#### `stream(messages, options?)` {/* #streammessages-options */}

使用 Inngest 的持久執行引擎串流回應。建立 PubSub 訂閱後，透過 Inngest 事件觸發Workflow。

```typescript
const { output, runId, cleanup } = await durableAgent.stream('Hello!', {
  onChunk: chunk => console.log(chunk),
  onFinish: result => console.log('done', result),
})

const text = await output.text
cleanup()
```

返回：[`Promise<InngestAgentStreamResult>`](#inngestagentstreamresult)

#### `resume(runId, resumeData, options?)` {/* #resumerunid-resumedata-options */}

恢復暫停的 Ingest 運行，例如在Tool批准後。從儲存載入Workflow快照並尋找掛起的步驟，然後將復原事件傳送到 Inngest。

恢復的輸出包括暫停先前的Tool呼叫和文字。為了恢復它們，`resume()` waits up to 10 seconds for the stored snapshot to include every suspended tool call. If the snapshot is still incomplete, `resume()` rejects with `Cannot resume run <runId>: ...` and doesn't send a resume event. The run stays suspended, so you can call `resume()` again.

```typescript
const { output, cleanup } = await durableAgent.resume(
  runId,
  {
    approved: true,
  },
  { threadId: 'thread-1', resourceId: 'user-1' },
)

await output.text
cleanup()
```

第三個參數接受`threadId` and `resourceId` in addition to the lifecycle callbacks:

#### `generate(messages, options?)` {/* #generatemessages-options */}

在 Inngest 的持久執行引擎上運行響應並使用單一`FullOutput`. If the run suspends, `generate()` resolves with `finishReason: 'suspended'`. The `runId` option is optional. If you omit it, `generate()` creates a run ID and returns it in `result.runId`. Continue the run with [`resumeGenerate()`](#resumegenerateresumedata-options). Use [`stream()`](#streammessages-options) with `onSuspended` when the caller needs a suspension callback.

```typescript
const result = await durableAgent.generate('Delete the old records', {
  requireToolApproval: true,
})

result.runId // Generated automatically
result.finishReason // 'suspended' when approval is required
```

返回：`Promise<FullOutput<TOutput>>`

#### `resumeGenerate(resumeData, options)` {/* #resumegenerateresumedata-options */}

恢復暫停狀態`generate()` run and resolves with a single `FullOutput`. Pass the run ID as `options.runId`, the same as `Agent.resumeGenerate()`. The older `resumeGenerate(runId, resumeData, options?)` order still works but is deprecated.

```typescript
if (!result.runId) {
  throw new Error('Run ID is missing')
}

const resumedResult = await durableAgent.resumeGenerate({ approved: true }, { runId: result.runId })
```

返回：`Promise<FullOutput<TOutput>>`

#### `observe(runId, options?)` {/* #observerunid-options */}

重新連接到現有運行，在交付即時事件之前重播快取的事件。網路斷開後使用此功能。經過`offset` to start replay from a known position.

```typescript
const { output, cleanup } = await durableAgent.observe(runId, {
  offset: 0,
  onChunk: chunk => console.log(chunk),
})

await output.text
```

結果來自`observe()` doesn't include `threadId` or `resourceId`.

返回：`Promise<Omit<InngestAgentStreamResult, 'threadId' | 'resourceId'>>`

：：：警告

這`cleanup()` returned by `observe()` destroys the run's registry entries and cached events. Only call it when you are done with the run. If the run is suspended and you intend to resume later, don't call `cleanup()`.

:::

#### `prepare(messages, options?)` {/* #preparemessages-options */}

為持久執行準備運行而不觸發它。傳回可用於手動觸發 Inngest Workflow事件的序列化Workflow輸入。

```typescript
const { runId, messageId, workflowInput, threadId, resourceId } = await durableAgent.prepare(
  'Summarize the document',
  {
    memory: { threadId: 'thread-1', resourceId: 'user-1' },
  },
)
```

返回：

```typescript
interface PrepareResult {
  runId: string
  messageId: string
  workflowInput: any
  threadId?: string
  resourceId?: string
}
```

## 活動規模限制 {/* #event-size-limit */}

Inngest Realtime 將每個訊息的大小限制為大約 512 KB。預設`InngestPubSub` keeps every stream event under 480 KB:

* 超大的`finish` event is sent without `output.steps`. The final text, usage, and finish reason still arrive, but `steps`, `toolCalls`, and `toolResults` on the stream result are empty for that run.
* 任何其他大型活動，例如`tool-result` chunk carrying a large tool result, is replaced with a `data-oversized-event` chunk. Its `data` holds the original `eventType`, `chunkType`, `bytes`, and `limit`. The chunk is transient, so it isn't saved to memory.

這兩種情況都會記錄警告。僅減少即時串流：儲存到記憶體的訊息和運行的Workflow快照保留完整資料。

為了避免限制：

* 傳回小型Tool結果，例如 ID 或摘要，並單獨取得大型資料。
* 從記憶體讀取完整結果或串流完成後執行的Workflow。
* 透過一個`pubsub` without the limit, such as [`RedisStreamsPubSub`](/reference/pubsub/redis-streams):

```typescript title="src/mastra/index.ts"
import { createInngestAgent } from '@mastra/inngest'
import { RedisStreamsPubSub } from '@mastra/redis-streams'

const durableAgent = createInngestAgent({
  agent,
  inngest,
  pubsub: new RedisStreamsPubSub({ url: 'redis://localhost:6379' }),
})
```

## 提供 Ingest 功能 {/* #serving-inngest-functions */}

這`@mastra/inngest` package provides `serve()` and `createServe()` to register Inngest workflow functions with your HTTP framework.

### `serve(options)` {/* #serveoptions */}

透過 Hono（預設框架）為 Mastra Workflow提供服務。從 Mastra 收集所有 Inngest 支援的Workflow並將它們註冊為 Inngest 函數。

```typescript
import { serve } from '@mastra/inngest'

app.use('/inngest/api', async c => {
  return serve({ mastra, inngest })(c)
})
```

### `createServe(adapter)` {/* #createserveadapter */}

接受任何 Ingest 服務適配器的工廠 (`inngest/express`, `inngest/fastify`, `inngest/next`, etc.) and returns a serve function for that framework.

```typescript title="Express"
import { createServe } from '@mastra/inngest'
import { serve } from 'inngest/express'

const serveExpress = createServe(serve)
app.use('/inngest/api', serveExpress({ mastra, inngest }))
```

```typescript title="Next.js"
import { createServe } from '@mastra/inngest'
import { serve } from 'inngest/next'

const serveNext = createServe(serve)
export const { GET, POST, PUT } = serveNext({ mastra, inngest })
```
