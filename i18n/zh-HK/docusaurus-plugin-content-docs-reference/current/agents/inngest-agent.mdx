# `createInngestAgent()`

:::beta

API 穩定前，即使沒有提升主要版本號，也可能出現破壞性變更。

:::

`createInngestAgent()` 為現有的 [`Agent`](/reference/agents/agent) 加入由 [Inngest](https://www.inngest.com/docs) 支援的持久執行能力。它與 [`createDurableAgent()`](/reference/agents/durable-agent#createdurableagentoptions) 一樣，透過 [PubSub](/docs/server/pubsub) 串流傳送事件，並支援可恢復的串流；但 Agent 迴圈是在 Inngest 的執行引擎上運行，而非在目前的進程內。如執行工作須在進程重新啟動後繼續，或須於分散式環境執行，請使用它。

如需在進程內持久執行，請使用 [`createDurableAgent()`](/reference/agents/durable-agent#createdurableagentoptions)。如需在內置 Workflow 引擎上啟動後無須等候結果的執行，請使用 [`createEventedAgent()`](/reference/agents/durable-agent#createeventedagentoptions)。

## 使用範例 {/* #usage-example */}

設定 Inngest 用戶端、包裝 Agent、將其註冊至 Mastra，並提供 Inngest 的 serve 端點：

```typescript title="src/mastra/index.ts"
import { Mastra } from '@mastra/core'
import { Agent } from '@mastra/core/agent'
import { createInngestAgent, serve as inngestServe } from '@mastra/inngest'
import { Inngest } from 'inngest'

const inngest = new Inngest({ id: 'my-app' })

const agent = new Agent({
  id: 'my-agent',
  name: 'My Agent',
  instructions: 'You are a helpful assistant',
  model: '__GATEWAY_OPENAI_MODEL__',
})

const durableAgent = createInngestAgent({ agent, inngest })

export const mastra = new Mastra({
  agents: { myAgent: durableAgent },
  server: {
    apiRoutes: [
      {
        path: '/inngest/api',
        method: 'ALL',
        createHandler: async ({ mastra }) => inngestServe({ mastra, inngest }),
      },
    ],
  },
})
```

以串流方式產生回應並讀取結果：

```typescript
const { output, runId, cleanup } = await durableAgent.stream('Hello!')

const text = await output.text

cleanup()
```

## 方法 {/* #methods */}

### 執行 {/* #execution */}

#### `stream(messages, options?)` {/* #streammessages-options */}

使用 Inngest 的持久執行引擎以串流方式產生回應。建立 PubSub 訂閱後，Workflow 會由 Inngest 事件觸發。

```typescript
const { output, runId, cleanup } = await durableAgent.stream('Hello!', {
  onChunk: chunk => console.log(chunk),
  onFinish: result => console.log('done', result),
})

const text = await output.text
cleanup()
```

返回：[`Promise<InngestAgentStreamResult>`](#inngestagentstreamresult)

#### `resume(runId, resumeData, options?)` {/* #resumerunid-resumedata-options */}

恢復暫停的 Inngest 執行工作，例如等待 Tool 批核後的工作。它會先從儲存空間載入 Workflow 快照並找出暫停的步驟，再向 Inngest 傳送恢復事件。

恢復後的輸出包含暫停前的 Tool 呼叫及文字。為還原這些內容，`resume()` 最多等候 10 秒，直至儲存的快照包含所有暫停的 Tool 呼叫。如快照仍未完整，`resume()` 會以 `Cannot resume run <runId>: ...` 拒絕，亦不會傳送恢復事件。執行工作仍然暫停，因此可以再次呼叫 `resume()`。

```typescript
const { output, cleanup } = await durableAgent.resume(
  runId,
  {
    approved: true,
  },
  { threadId: 'thread-1', resourceId: 'user-1' },
)

await output.text
cleanup()
```

第三個參數除了生命週期回調，亦接受 `threadId` 及 `resourceId`：

#### `generate(messages, options?)` {/* #generatemessages-options */}

在 Inngest 的持久執行引擎上產生回應，並解析為單一 `FullOutput`。如執行工作暫停，`generate()` 會回傳 `finishReason: 'suspended'`。`runId` 選項可以省略；省略時，`generate()` 會建立執行 ID，並透過 `result.runId` 回傳。可使用 [`resumeGenerate()`](#resumegenerateresumedata-options) 繼續執行。如呼叫方需要暫停回調，請使用設有 `onSuspended` 的 [`stream()`](#streammessages-options)。

```typescript
const result = await durableAgent.generate('Delete the old records', {
  requireToolApproval: true,
})

result.runId // Generated automatically
result.finishReason // 'suspended' when approval is required
```

返回：`Promise<FullOutput<TOutput>>`

#### `resumeGenerate(resumeData, options)` {/* #resumegenerateresumedata-options */}

恢復已暫停的 `generate()` 執行工作，並解析為單一 `FullOutput`。與 `Agent.resumeGenerate()` 一樣，請將執行 ID 傳入 `options.runId`。舊參數次序 `resumeGenerate(runId, resumeData, options?)` 仍可使用，但已棄用。

```typescript
if (!result.runId) {
  throw new Error('Run ID is missing')
}

const resumedResult = await durableAgent.resumeGenerate({ approved: true }, { runId: result.runId })
```

返回：`Promise<FullOutput<TOutput>>`

#### `observe(runId, options?)` {/* #observerunid-options */}

重新連接現有執行工作：先重播快取的事件，再接收即時事件。網絡中斷後可使用此方法。傳入 `offset` 可從指定位置開始重播。

```typescript
const { output, cleanup } = await durableAgent.observe(runId, {
  offset: 0,
  onChunk: chunk => console.log(chunk),
})

await output.text
```

`observe()` 的結果不包含 `threadId` 或 `resourceId`。

返回：`Promise<Omit<InngestAgentStreamResult, 'threadId' | 'resourceId'>>`

:::warning

`observe()` 回傳的 `cleanup()` 會刪除此執行工作的註冊表項目及快取事件。只應在不再需要此執行工作時呼叫它。如工作仍然暫停，而你打算稍後恢復，請勿呼叫 `cleanup()`。

:::

#### `prepare(messages, options?)` {/* #preparemessages-options */}

為持久執行準備工作，但不觸發執行。回傳可用於手動觸發 Inngest Workflow 事件的序列化 Workflow 輸入。

```typescript
const { runId, messageId, workflowInput, threadId, resourceId } = await durableAgent.prepare(
  'Summarize the document',
  {
    memory: { threadId: 'thread-1', resourceId: 'user-1' },
  },
)
```

返回：

```typescript
interface PrepareResult {
  runId: string
  messageId: string
  workflowInput: any
  threadId?: string
  resourceId?: string
}
```

## 事件大小限制 {/* #event-size-limit */}

Inngest Realtime 將單則訊息大小限制為約 512 KB。預設的 `InngestPubSub` 會讓每個串流事件保持在 480 KB 以下：

* 過大的 `finish` 事件會在不包含 `output.steps` 的情況下傳送。最終文字、用量及結束原因仍會送達，但這次執行的串流結果中，`steps`、`toolCalls` 及 `toolResults` 會是空的。
* 其他過大的事件，例如包含大型 Tool 結果的 `tool-result` 資料區塊，會替換為 `data-oversized-event` 資料區塊。其 `data` 包含原始的 `eventType`、`chunkType`、`bytes` 及 `limit`。這個資料區塊是暫時的，不會儲存至 memory。

兩種情況都會記錄警告。只有即時串流會縮減；儲存至 memory 的訊息及這次執行的 Workflow 快照仍保留完整資料。

為了避免限制：

* 回傳較小的 Tool 結果，例如 ID 或摘要，並另行擷取大型資料。
* 在串流結束後，從 memory 或該次 Workflow 執行工作讀取完整結果。
* 傳入不受此限制的 `pubsub`，例如 [`RedisStreamsPubSub`](/reference/pubsub/redis-streams)：

```typescript title="src/mastra/index.ts"
import { createInngestAgent } from '@mastra/inngest'
import { RedisStreamsPubSub } from '@mastra/redis-streams'

const durableAgent = createInngestAgent({
  agent,
  inngest,
  pubsub: new RedisStreamsPubSub({ url: 'redis://localhost:6379' }),
})
```

## 提供 Inngest 函數 {/* #serving-inngest-functions */}

`@mastra/inngest` 套件提供 `serve()` 及 `createServe()`，用於向 HTTP 框架註冊 Inngest Workflow 函數。

### `serve(options)` {/* #serveoptions */}

使用 Hono（預設框架）提供 Mastra Workflow 服務。它會從 Mastra 收集所有由 Inngest 支援的 Workflow，並註冊為 Inngest 函數。

```typescript
import { serve } from '@mastra/inngest'

app.use('/inngest/api', async c => {
  return serve({ mastra, inngest })(c)
})
```

### `createServe(adapter)` {/* #createserveadapter */}

接收任意 Inngest serve 轉接器（例如 `inngest/express`、`inngest/fastify`、`inngest/next`），並回傳適用於該框架的 serve 函數的工廠方法。

```typescript title="Express"
import { createServe } from '@mastra/inngest'
import { serve } from 'inngest/express'

const serveExpress = createServe(serve)
app.use('/inngest/api', serveExpress({ mastra, inngest }))
```

```typescript title="Next.js"
import { createServe } from '@mastra/inngest'
import { serve } from 'inngest/next'

const serveNext = createServe(serve)
export const { GET, POST, PUT } = serveNext({ mastra, inngest })
```
