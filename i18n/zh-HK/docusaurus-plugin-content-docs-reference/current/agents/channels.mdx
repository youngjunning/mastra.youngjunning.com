# 頻道

**添加於：** `@mastra/core@1.22.0`

頻道將Agent連接到訊息傳遞平台。透過以下方式配置它們`channels` property on the `Agent`構造函數。您傳遞的物件是`ChannelConfig`。請參閱[頻道概覽](/docs/channels)有關概念和平台設定說明。

## 使用範例 {/* #usage-example */}

```typescript title="src/mastra/agents/support-agent.ts"
import { Agent } from '@mastra/core/agent'
import { createSlackAdapter } from '@chat-adapter/slack'
import { createDiscordAdapter } from '@chat-adapter/discord'

export const supportAgent = new Agent({
  id: 'support-agent',
  name: 'Support Agent',
  instructions: 'You are a helpful support assistant.',
  model: '__GATEWAY_OPENAI_MODEL__',
  channels: {
    adapters: {
      slack: createSlackAdapter(),
      discord: createDiscordAdapter(),
    },
  },
})
```

## Tool顯示模式 {/* #tool-display-modes */}

`toolDisplay`控制Tool呼叫在聊天中的呈現方式。預設`'cards'`
posts a "Running…" card per tool and edits it with the result, matching the
behavior in earlier versions. This is the default on every adapter, including
Slack. To get grouped tool state on Slack, set `streaming: true` and
`toolDisplay: 'grouped'` explicitly. `'text'` is the same lifecycle but without rich
Block Kit, useful for platforms that don't render cards well.

`'timeline'`和`'grouped'` stream tool state as inline `task_update` chunks
alongside the agent's text. These modes require `streaming: true` and rely on
the chat adapter to render the chunks. Slack supports both natively; other
adapters may render a placeholder until they add support. If `streaming` is
disabled, the channel logs a one-time warning and falls back to `'cards'`.

`'hidden'`默默地執行Tool。僅打字狀態表示工作狀態
進步。

將函數傳遞給`toolDisplay` for fully custom rendering. The function
receives a `ToolDisplayEvent` (`running` / `result` / `error` / `approval` /
`approved` / `denied`) and a `ToolDisplayContext` (`{ mode, platform }`）；
返回`{ kind: 'post', message }``{ kind: 'stream',
chunk }`推入活動的串流小Tool，或者`undefined`跳過
渲染該事件。

用戶選擇批准或拒絕後，Mastra 會發送一個`approved` or `denied`
event. Both include `byUser`, the name of the user who responded, which is
undefined in DMs. A `post` result replaces the approval card in place. If the
function returns nothing, a blank message, or throws, Mastra shows the default
"Approved" or "Denied" card, which names the user outside DMs.

預設情況下，流程結果會在沒有活動狀態時開啟串流會話。放`openIfEmpty: false` when the chunk only applies to an existing session. Mastra
skips the chunk when no session is active. Static channels ignore this option
and keep their existing plain-text fallback behavior.

```typescript
toolDisplay: event => {
  if (event.kind !== 'running') return undefined

  return {
    kind: 'stream',
    chunk: {
      type: 'task_update',
      id: event.toolCallId,
      title: event.displayName,
      status: 'in_progress',
    },
    openIfEmpty: false,
  }
}
```

批准/拒絕提示（`requireApproval`) render as a separate built-in card in
every string mode, because inline task entries can't carry interactive buttons.
With a `toolDisplay` function, the `approval` event is passed to your function
in both streaming and static modes; return a non-blank `{ kind: 'post', message }`
to replace the built-in card with your own message (for example, a localized
one). Returning `undefined`, a blank message, or `{ kind: 'stream' }` falls back
to the built-in card so the user can still approve or deny the request. Keep the
button ids in the format the default action handler expects. See [Custom
approval cards](#custom-approval-cards).

```typescript title="src/mastra/agents/streaming.ts"
import { Agent } from '@mastra/core/agent'
import { createSlackAdapter } from '@chat-adapter/slack'

const agent = new Agent({
  id: 'streaming-agent',
  name: 'Streaming Agent',
  instructions: '...',
  model: '__GATEWAY_OPENAI_MODEL__',
  channels: {
    adapters: {
      slack: {
        adapter: createSlackAdapter(),
        streaming: true, // off by default on every adapter
        toolDisplay: 'timeline',
      },
    },
  },
})
```

### 客製化批准卡 {/* #custom-approval-cards */}

自訂批准訊息取代了內建卡，但 Mastra 的預設設置`onAction` handler still handles the button action. It only resumes the suspended run
when the button ids are exactly:

* 批准：`tool_approve:<toolCallId>`
* 否定：`tool_deny:<toolCallId>`

`<toolCallId>`是`event.toolCallId` from the `approval` event. Any other id,
including one with extra whitespace, doesn't match a pending approval. The run
stays suspended. The default handler must also stay enabled: don't set
`handlers.onAction: false`, and if you provide your own `onAction`, call
`defaultHandler()` so approval clicks are processed.

客製化`toolDisplay` function replaces the built-in renderer for every tool
event. The example below only renders approvals, so other tool calls post
nothing; return a message for `result` and `error` events as well if you want
those visible.

```typescript title="src/mastra/agents/localized-approval.ts"
import { Agent } from '@mastra/core/agent'
import { createSlackAdapter } from '@chat-adapter/slack'

const agent = new Agent({
  id: 'localized-approval-agent',
  name: 'Localized Approval Agent',
  instructions: '...',
  model: '__GATEWAY_OPENAI_MODEL__',
  channels: {
    adapters: {
      slack: {
        adapter: createSlackAdapter(),
        toolDisplay: event => {
          if (event.kind !== 'approval') return undefined

          return {
            kind: 'post',
            message: {
              type: 'card',
              title: `Approve ${event.displayName}?`,
              children: [
                {
                  type: 'actions',
                  children: [
                    {
                      type: 'button',
                      id: `tool_approve:${event.toolCallId}`,
                      label: 'Genehmigen',
                      style: 'primary',
                    },
                    {
                      type: 'button',
                      id: `tool_deny:${event.toolCallId}`,
                      label: 'Ablehnen',
                      style: 'danger',
                    },
                  ],
                },
              ],
            },
          }
        },
      },
    },
  },
})
```

## 產生 UI 卡 {/* #generative-ui-cards */}

:::警告\[實驗]`generativeUI` is experimental and may change in a minor release.
:::

放`generativeUI: true` on the Slack adapter to let the agent post structured cards (status summaries, key/value fields, tables, charts, images, and link buttons) instead of long markdown replies. Install the optional peer first:

```bash npm2yarn
npm install @json-render/chat
```

`@json-render/chat`需要 zod 4，因此仍在 zod 3 上的項目無法啟用`generativeUI` yet.

`@mastra/core`負載`@json-render/chat` at runtime, so `mastra build` and `mastra deploy` don't pick it up on their own. Add it to [`bundler.dynamicPackages`](/reference/core/mastra-class) so it's included in the build output:

```typescript title="src/mastra/index.ts"
import { Mastra } from '@mastra/core'
import { supportAgent } from './agents/support-agent'

export const mastra = new Mastra({
  agents: { supportAgent },
  bundler: { dynamicPackages: ['@json-render/chat'] },
})
```

```typescript title="src/mastra/agents/support-agent.ts"
import { Agent } from '@mastra/core/agent'
import { createSlackAdapter } from '@chat-adapter/slack'

export const supportAgent = new Agent({
  id: 'support-agent',
  name: 'Support Agent',
  instructions: 'You are a helpful support assistant.',
  model: '__GATEWAY_OPENAI_MODEL__',
  channels: {
    adapters: {
      slack: { adapter: createSlackAdapter(), generativeUI: true },
    },
  },
})
```

在該適配器上運作得到`render_card` tool whose description lists the available components. The agent passes a flat spec of `{ root, elements }`, where the root element is a `Card`:

```json
{
  "root": "card",
  "elements": {
    "card": { "type": "Card", "props": { "title": "Deploy status" }, "children": ["fields"] },
    "fields": { "type": "Fields", "children": ["env", "version"] },
    "env": { "type": "Field", "props": { "label": "Environment", "value": "beta" } },
    "version": { "type": "Field", "props": { "label": "Version", "value": "1.8.1" } }
  }
}
```

Tool返回`{ ok: true, messageId }` once the card is posted. When the spec is invalid or exceeds the platform's limits (on Slack, one table and 100 rows per card), it returns `{ ok: false, issues }` without posting, so the agent can fix the spec and call it again. The tool call itself isn't rendered as a tool card. Interactive buttons aren't available yet. Cards can link out with `LinkButton`.

## 自訂打字狀態 {/* #custom-typing-status */}

將函數傳遞給`typingStatus` to customize the status copy. The function is
called once per stream chunk; return a string to set the status, or `false` /
`null` / `undefined` to leave the current status unchanged. Return values are
de-duplicated so the platform only sees a call when the status changes. When
the run ends, any status it set is cleared automatically so runs that finish
without posting a message don't leave a stale status on the thread.

`defaultTypingStatus`導出自`@mastra/core/channels` so you can
fall back to the built-in defaults for chunks you don't handle.

```typescript title="src/mastra/agents/custom-typing.ts"
import { Agent } from '@mastra/core/agent'
import { defaultTypingStatus } from '@mastra/core/channels'
import { createDiscordAdapter } from '@chat-adapter/discord'

const agent = new Agent({
  id: 'custom-typing-agent',
  name: 'Custom Typing Agent',
  instructions: '...',
  model: '__GATEWAY_OPENAI_MODEL__',
  channels: {
    adapters: {
      discord: {
        adapter: createDiscordAdapter(),
        typingStatus: (chunk, ctx) => {
          if (chunk.type === 'tool-call' && chunk.payload.toolName === 'searchDocs') {
            return 'is searching docs…'
          }
          return defaultTypingStatus(chunk, ctx)
        },
      },
    },
  },
})
```

## 處理程式 {/* #handlers */}

覆蓋內建事件處理程序。每個處理程序可以是：

* **省略**：使用預設的 Mastra 處理程序（透過Agent路由訊息並發布回應），除了`onMessage`, which is disabled by default
* **`false`**：完全禁用處理程序
* **一個功能** `(thread, message, defaultHandler, ctx) => Promise<void>`: wraps or replaces the default
* 當一個`chatOptions.concurrency` strategy batches messages from several senders into one dispatch, the function is called once per sender's turn, each with its own `ctx`; `ctx.skipped` holds that turn's earlier batched messages

```typescript title="src/mastra/agents/custom-handlers.ts"
import { Agent } from '@mastra/core/agent'
import { createSlackAdapter } from '@chat-adapter/slack'

const agent = new Agent({
  id: 'custom-handler-agent',
  name: 'Custom Handler Agent',
  instructions: '...',
  model: '__GATEWAY_OPENAI_MODEL__',
  channels: {
    adapters: {
      slack: createSlackAdapter(),
    },
    handlers: {
      onMention: async (thread, message, defaultHandler) => {
        console.log('Received mention:', message.text)
        await defaultHandler(thread, message)
      },
      onDirectMessage: false,
    },
  },
})
```

```typescript
import type { ChannelHandlers } from '@mastra/core/channels'

const handlers: ChannelHandlers = {
  onMessage: async (thread, message, defaultHandler) => {
    if (thread.channelId !== 'slack:C_SUPPORT') return
    await defaultHandler(thread, message)
  },
}
```

`defaultHandler`運行Agent程式、發布回應並訂閱線程。該線程中的後續訊息將轉到`onSubscribedMessage`. Runs started through `onMessage` report `channel.eventType` as `message`. When a queued batch mixes mentioned and unmentioned senders, unmentioned senders go to `onMessage` when it's set. Otherwise they go to `onMention`, or are skipped if `onMention` is `false`.

這`ChannelHandler` function signature:

```typescript
type ChannelHandler = (
  thread: Thread,
  message: Message,
  defaultHandler: (thread: Thread, message: Message) => Promise<void>,
  ctx: ChannelHandlerContext,
) => Promise<void>

type ChannelHandlerContext = {
  mastra?: Mastra
  requestContext: RequestContext
  readonly signalMetadata: Record<string, unknown>
  readonly skipped: readonly Message[]
}
```

`ctx.mastra`已解決`mastra` instance, so a handler can reach storage or other registered primitives without being passed an external accessor:

```typescript
onDirectMessage: async (thread, message, defaultHandler, ctx) => {
  const store = await ctx.mastra?.getStorage()?.getStore('memory')
  await defaultHandler(thread, message)
}
```

`ctx.requestContext`是[`RequestContext`](/docs/server/request-context) for the run this message is about to start, built fresh for every message. Write to it before calling `defaultHandler` and the value reaches the run, alongside the channel entries Mastra adds afterward:

```typescript
onDirectMessage: async (thread, message, defaultHandler, ctx) => {
  ctx.requestContext.set('locale', 'en-GB')
  await defaultHandler(thread, message)
}
```

運行從其請求上下文中讀取的任何內容都可以透過這種方式決定每個訊息，例如平台發送者對應到哪個使用者。

`ctx.signalMetadata`是附加到該訊息的Agent訊號的元數據，為每個訊息新建。在呼叫之前加入 JSON 可序列化的非敏感值`defaultHandler`. Mastra may persist signal metadata and publish it through PubSub. Unlike `ctx.requestContext`, it follows the message whether it starts a new run or is delivered to one that's already active.

`ctx.skipped`列出來自同一寄件者的較早訊息，聊天 SDK 在本回合中批次處理`chatOptions.concurrency` strategy such as `burst`, `debounce`, or `queue` is set, oldest first. It's empty when nothing was batched.

## 資源ID解析 {/* #resource-id-resolution */}

預設情況下通道線程的內存`resourceId` is `${platform}:${message.author.userId}`. The sender owns the memory, scoped per platform. For apps with a shared identity, such as single sign-on (SSO), this splits memory: the same user gets `feishu:user_123` in a Feishu DM but `user_123` on the web.

經過`resolveResourceId` to decide memory ownership separately from the sender. It runs only when a new thread is created. Reused threads keep their stored `resourceId` and never call the hook, so existing conversations don't depend on the resolver being available. Return `ctx.defaultResourceId` to fall back to the built-in behavior.

```typescript title="src/mastra/agents/sso-agent.ts"
import { Agent } from '@mastra/core/agent'
import { createSlackAdapter } from '@chat-adapter/slack'

const agent = new Agent({
  id: 'sso-agent',
  name: 'SSO Agent',
  instructions: '...',
  model: '__GATEWAY_OPENAI_MODEL__',
  channels: {
    adapters: {
      slack: createSlackAdapter(),
    },
    resolveResourceId: async ({ thread, message }) => {
      // DM: share resource-level memory with the web app by using the bare SSO id
      if (thread.isDM) {
        return await resolveSsoUserId(message)
      }
      // Group chat: the conversation owns the memory; the sender stays the actor
      return thread.channelId
    },
  },
})
```

## 線程ID解析 {/* #thread-id-resolution */}

預設情況下，新通道線程會取得隨機 UUID 作為其內部 Mastra 線程 ID。經過`resolveThreadId` to pick the id yourself: for example, give the thread the same id as its session to match the names your app assigns to threads it creates.

鉤子在後面運行`resolveResourceId`, so the resolved owner is available on the context. Like `resolveResourceId` it runs only when a new thread is created: reused threads keep their stored id and never call the hook. The returned id must be unique across the memory store. If it already belongs to an existing thread, Mastra logs a warning and uses a generated id instead so the existing thread is never overwritten. Return `ctx.defaultThreadId` to keep the built-in behavior.

```typescript title="src/mastra/agents/session-agent.ts"
import { Agent } from '@mastra/core/agent'
import { createSlackAdapter } from '@chat-adapter/slack'

const agent = new Agent({
  id: 'session-agent',
  name: 'Session Agent',
  instructions: '...',
  model: '__GATEWAY_OPENAI_MODEL__',
  channels: {
    adapters: {
      slack: createSlackAdapter(),
    },
    // Owner: a session id resolved from the sender's linked account
    resolveResourceId: async ctx => resolveSessionId(ctx),
    // Thread id: align with the session id so app URLs that address
    // threads by session id resolve channel-created threads too
    resolveThreadId: ({ resourceId, defaultThreadId }) => {
      return isSessionId(resourceId) ? resourceId : defaultThreadId
    },
  },
})
```

## 內嵌媒體 {/* #inline-media */}

控制將哪些附件類型（影像、影片、PDF 等）作為文件部分傳送到模型。不匹配的類型被描述為文字摘要，以便Agent程式了解該文件，而不會導致拒絕不支援類型的模型崩潰。

不符的類似文字的附件（`text/*`, JSON, YAML, XML, and similar) are downloaded through the adapter's authenticated fetch when one is available (for example, Slack private files) and given to the agent as text. Contents over 128 KB are truncated. Files the adapter reports as larger than 10 MB aren't downloaded.

預設(`['image/png', 'image/jpeg', 'image/webp', 'application/pdf']`) matches the formats supported by major vision models. Override `inlineMedia` to expand the list (e.g. `['image/*', 'audio/*']`) or replace it entirely with a predicate function.

支援的全域模式：

|圖案|比賽|
| - | - |
|`image/*` | All image types (`image/png`, `image/jpeg`, etc.) |
| `video/*` | All video types |
| `*` or `*/*` | All types |
| `application/pdf` | Exact type match |

對於具有私有 CDN 的平台（例如 Slack），附件是透過聊天 SDK 中經過身份驗證的憑證取得的。對於具有公共 CDN 的平台（例如 Discord），URL 會直接傳遞給模型。

## 內聯連結 {/* #inline-links */}

將訊息文字中找到的 URL 提升為文件部分，以便模型可以處理連結的內容，而不是查看原始 URL 文字。每個條目可以是字串（域模式）或具有強制 mime 類型的物件。

**字串條目**匹配域並執行 HEAD 請求來偵測 Content-Type。檢查已解析的類型`inlineMedia` and only matching types become file parts.

**物件條目**`inlineMedia` check. This is useful for sites like YouTube where a HEAD request returns `text/html`, but the model treats the URL as video content.

```typescript
type InlineLinkEntry =
  | string // Domain pattern (HEAD determines mime type)
  | { match: string; mimeType: string } // Domain + forced mime type (skips HEAD)
```

import { toChatLogger } from '@mastra/core/channels'
import { createDiscordAdapter } from '@chat-adapter/discord'
import { PinoLogger } from '@mastra/loggers'

const logger = new PinoLogger({ name: 'app', level: 'info' })

const discord = createDiscordAdapter({
  logger: toChatLogger(logger, { component: 'discord', minLevel: 'warn' }),
})
