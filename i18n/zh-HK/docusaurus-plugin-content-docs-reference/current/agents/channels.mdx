# Channels

**新增於：** `@mastra/core@1.22.0`

Channels 將 Agent 連接至訊息平台。透過 `Agent` 建構函式的 `channels` 屬性設定。傳入的物件類別為 `ChannelConfig`。概念及平台設定方法請參閱 [Channels 概覽](/docs/channels)。

## 使用範例 {/* #usage-example */}

```typescript title="src/mastra/agents/support-agent.ts"
import { Agent } from '@mastra/core/agent'
import { createSlackAdapter } from '@chat-adapter/slack'
import { createDiscordAdapter } from '@chat-adapter/discord'

export const supportAgent = new Agent({
  id: 'support-agent',
  name: 'Support Agent',
  instructions: 'You are a helpful support assistant.',
  model: '__GATEWAY_OPENAI_MODEL__',
  channels: {
    adapters: {
      slack: createSlackAdapter(),
      discord: createDiscordAdapter(),
    },
  },
})
```

## 各適配器選項 {/* #per-adapter-options */}

將適配器包在 `ChannelAdapterConfig` 物件中，即可設定各適配器的選項：

```typescript title="src/mastra/agents/example.ts"
import { Agent } from '@mastra/core/agent'
import { createDiscordAdapter } from '@chat-adapter/discord'
import { createSlackAdapter } from '@chat-adapter/slack'

const agent = new Agent({
  id: 'example',
  name: 'Example',
  instructions: '...',
  model: '__GATEWAY_OPENAI_MODEL__',
  channels: {
    adapters: {
      discord: {
        adapter: createDiscordAdapter(),
        toolDisplay: 'text',
        cors: {
          origin: ['https://customer-saas.example'],
          credentials: true,
        },
        gateway: false,
      },
      slack: createSlackAdapter(), // Plain adapter uses defaults
    },
  },
})
```

## 工具顯示模式 {/* #tool-display-modes */}

`toolDisplay` 控制工具調用在聊天中的顯示方式。預設值 `'cards'` 會為每個工具發布一張「執行中…」卡片，並在得到結果後更新卡片，與舊版行為一致。所有適配器（包括 Slack）都以此為預設值。若要在 Slack 中分組顯示工具狀態，必須明確設定 `streaming: true` 和 `toolDisplay: 'grouped'`。`'text'` 的生命週期相同，但不使用豐富的 Block Kit 卡片，適合不擅長呈現卡片的平台。

`'timeline'` 和 `'grouped'` 會把工具狀態作為行內 `task_update` 片段，與 Agent 文字一起串流傳輸。這兩種模式需要 `streaming: true`，並依賴聊天適配器呈現片段。Slack 原生支援這兩種模式；其他適配器在提供支援前可能只顯示佔位符。若停用 `streaming`，Channel 會記錄一次警告並改用 `'cards'`。

`'hidden'` 會靜默執行工具，只有輸入狀態會提示工作正在進行。

向 `toolDisplay` 傳入函式可完全自訂呈現方式。函式接收 `ToolDisplayEvent`（`running` / `result` / `error` / `approval` / `approved` / `denied`）和 `ToolDisplayContext`（`{ mode, platform }`）。傳回 `{ kind: 'post', message }` 可發布或編輯獨立訊息，傳回 `{ kind: 'stream',
chunk }` 可推送到活動的串流元件，傳回 `undefined` 則跳過該事件。

用戶選擇 Approve 或 Deny 後，Mastra 會傳送 `approved` 或 `denied` 事件。兩種事件都包含 `byUser`，即回應者的姓名；在私訊中該值為 undefined。傳回 `post` 結果會原位替換審批卡片。若函式不傳回內容、傳回空訊息或拋出錯誤，Mastra 會顯示預設的「Approved」或「Denied」卡片；非私訊中卡片會顯示用戶姓名。

預設情況下，串流結果會在沒有活動工作階段時開啟新工作階段。若該片段只適用於現有工作階段，請設定 `openIfEmpty: false`。Mastra 在沒有活動工作階段時會跳過該片段。靜態 Channel 會忽略此選項，繼續使用現有的純文字後備行為。

```typescript
toolDisplay: event => {
  if (event.kind !== 'running') return undefined

  return {
    kind: 'stream',
    chunk: {
      type: 'task_update',
      id: event.toolCallId,
      title: event.displayName,
      status: 'in_progress',
    },
    openIfEmpty: false,
  }
}
```

批准/拒絕提示（`requireApproval`）在所有字串模式下都會顯示為單獨的內建卡片，因為行內任務項目無法承載互動按鈕。使用 `toolDisplay` 函式時，無論串流還是靜態模式，函式都會收到 `approval` 事件；傳回非空的 `{ kind: 'post', message }` 可用自訂訊息（例如本地化文案）替換內建卡片。傳回 `undefined`、空訊息或 `{ kind: 'stream' }` 則會改用內建卡片，以確保用戶仍能批准或拒絕請求。按鈕 ID 必須符合預設操作處理器預期的格式。參見[自訂審批卡片](#custom-approval-cards)。

```typescript title="src/mastra/agents/streaming.ts"
import { Agent } from '@mastra/core/agent'
import { createSlackAdapter } from '@chat-adapter/slack'

const agent = new Agent({
  id: 'streaming-agent',
  name: 'Streaming Agent',
  instructions: '...',
  model: '__GATEWAY_OPENAI_MODEL__',
  channels: {
    adapters: {
      slack: {
        adapter: createSlackAdapter(),
        streaming: true, // off by default on every adapter
        toolDisplay: 'timeline',
      },
    },
  },
})
```

### 自訂審批卡片 {/* #custom-approval-cards */}

自訂審批訊息會替換內建卡片，但 Mastra 的預設 `onAction` 處理器仍負責處理按鈕操作。只有按鈕 ID 與以下格式完全匹配時，才會恢復已暫停的執行：

- 批准：`tool_approve:<toolCallId>`
- 拒絕：`tool_deny:<toolCallId>`

`<toolCallId>` 是 `approval` 事件中的 `event.toolCallId`。其他 ID（包括含多餘空格的 ID）都無法匹配待審批項，執行會保持暫停。預設處理器也必須保持啟用：不要設定 `handlers.onAction: false`；如果提供自訂 `onAction`，請調用 `defaultHandler()`，讓審批點擊得到處理。

自訂 `toolDisplay` 函式會替換所有工具事件的內建呈現器。下例僅呈現審批事件，因此其他工具調用不會發布內容；若希望顯示這些調用，也須為 `result` 和 `error` 事件傳回訊息。

```typescript title="src/mastra/agents/localized-approval.ts"
import { Agent } from '@mastra/core/agent'
import { createSlackAdapter } from '@chat-adapter/slack'

const agent = new Agent({
  id: 'localized-approval-agent',
  name: 'Localized Approval Agent',
  instructions: '...',
  model: '__GATEWAY_OPENAI_MODEL__',
  channels: {
    adapters: {
      slack: {
        adapter: createSlackAdapter(),
        toolDisplay: event => {
          if (event.kind !== 'approval') return undefined

          return {
            kind: 'post',
            message: {
              type: 'card',
              title: `Approve ${event.displayName}?`,
              children: [
                {
                  type: 'actions',
                  children: [
                    {
                      type: 'button',
                      id: `tool_approve:${event.toolCallId}`,
                      label: 'Genehmigen',
                      style: 'primary',
                    },
                    {
                      type: 'button',
                      id: `tool_deny:${event.toolCallId}`,
                      label: 'Ablehnen',
                      style: 'danger',
                    },
                  ],
                },
              ],
            },
          }
        },
      },
    },
  },
})
```

## 生成式 UI 卡片 {/* #generative-ui-cards */}

:::warning[Experimental]
`generativeUI` 是實驗性功能，可能在次要版本中變更。
:::

在 Slack 適配器上設定 `generativeUI: true` 後，Agent 可發布結構化卡片（狀態摘要、鍵值欄位、表格、圖表、圖片及連結按鈕），代替冗長的 Markdown 回覆。請先安裝可選的 peer 依賴：

```bash npm2yarn
npm install @json-render/chat
```

`@json-render/chat` 需要 zod 4，因此仍使用 zod 3 的項目暫時無法啟用 `generativeUI`。

`@mastra/core` 會在執行時載入 `@json-render/chat`，而 `mastra build` 和 `mastra deploy` 不會自行將其打包。請將其加入 [`bundler.dynamicPackages`](/reference/core/mastra-class)，使其包含在構建產物中：

```typescript title="src/mastra/index.ts"
import { Mastra } from '@mastra/core'
import { supportAgent } from './agents/support-agent'

export const mastra = new Mastra({
  agents: { supportAgent },
  bundler: { dynamicPackages: ['@json-render/chat'] },
})
```

```typescript title="src/mastra/agents/support-agent.ts"
import { Agent } from '@mastra/core/agent'
import { createSlackAdapter } from '@chat-adapter/slack'

export const supportAgent = new Agent({
  id: 'support-agent',
  name: 'Support Agent',
  instructions: 'You are a helpful support assistant.',
  model: '__GATEWAY_OPENAI_MODEL__',
  channels: {
    adapters: {
      slack: { adapter: createSlackAdapter(), generativeUI: true },
    },
  },
})
```

在該適配器上執行時，Agent 會取得 `render_card` 工具，工具描述列出了可用元件。Agent 傳入扁平的 `{ root, elements }` 規範，其中根元素是 `Card`：

```json
{
  "root": "card",
  "elements": {
    "card": { "type": "Card", "props": { "title": "Deploy status" }, "children": ["fields"] },
    "fields": { "type": "Fields", "children": ["env", "version"] },
    "env": { "type": "Field", "props": { "label": "Environment", "value": "beta" } },
    "version": { "type": "Field", "props": { "label": "Version", "value": "1.8.1" } }
  }
}
```

卡片發布後，工具傳回 `{ ok: true, messageId }`。如果規範無效或超過平台限制（Slack 中每張卡片最多一張表格、100 行），工具不會發布卡片，而會傳回 `{ ok: false, issues }`，以便 Agent 修正規範後重試。工具調用本身不會顯示為工具卡片。目前不支援互動按鈕。卡片可通過 `LinkButton` 連結到外部頁面。

## 自訂輸入狀態 {/* #custom-typing-status */}

向 `typingStatus` 傳入函式可自訂狀態文案。每個串流片段都會調用該函式一次；傳回字串可設定狀態，傳回 `false` / `null` / `undefined` 則保持當前狀態不變。傳回值會去重，因此只有狀態變化時才會調用平台介面。執行結束時，已設定的狀態會自動清除，避免沒有發布訊息的執行在執行緒中留下過期狀態。

`defaultTypingStatus` 從 `@mastra/core/channels` 導出，可在未自行處理的片段上改用內建預設值。

```typescript title="src/mastra/agents/custom-typing.ts"
import { Agent } from '@mastra/core/agent'
import { defaultTypingStatus } from '@mastra/core/channels'
import { createDiscordAdapter } from '@chat-adapter/discord'

const agent = new Agent({
  id: 'custom-typing-agent',
  name: 'Custom Typing Agent',
  instructions: '...',
  model: '__GATEWAY_OPENAI_MODEL__',
  channels: {
    adapters: {
      discord: {
        adapter: createDiscordAdapter(),
        typingStatus: (chunk, ctx) => {
          if (chunk.type === 'tool-call' && chunk.payload.toolName === 'searchDocs') {
            return 'is searching docs…'
          }
          return defaultTypingStatus(chunk, ctx)
        },
      },
    },
  },
})
```

## 處理器 {/* #handlers */}

可以覆蓋內建事件處理器。每個處理器可採用以下形式：

- **省略**：使用預設 Mastra 處理器（由 Agent 處理訊息並發布回應），但 `onMessage` 預設停用。
- **`false`**：完全停用該處理器。
- **函式** `(thread, message, defaultHandler, ctx) => Promise<void>`：包裝或替換預設處理器。
- 當 `chatOptions.concurrency` 策略將多個傳送者的訊息合併為一次分發時，每名傳送者的輪次都會單獨調用此函式，並帶有各自的 `ctx`；`ctx.skipped` 儲存該輪次中更早的批次訊息。

```typescript title="src/mastra/agents/custom-handlers.ts"
import { Agent } from '@mastra/core/agent'
import { createSlackAdapter } from '@chat-adapter/slack'

const agent = new Agent({
  id: 'custom-handler-agent',
  name: 'Custom Handler Agent',
  instructions: '...',
  model: '__GATEWAY_OPENAI_MODEL__',
  channels: {
    adapters: {
      slack: createSlackAdapter(),
    },
    handlers: {
      onMention: async (thread, message, defaultHandler) => {
        console.log('Received mention:', message.text)
        await defaultHandler(thread, message)
      },
      onDirectMessage: false,
    },
  },
})
```

若要在沒有 @提及的情況下回覆，請提供 `onMessage`。它接收 Bot 可讀取、且尚未分派給私訊、提及或已訂閱執行緒處理器的所有訊息。如果只希望回覆某些 Channel，請在調用 `defaultHandler` 前按 Channel 篩選：

```typescript
import type { ChannelHandlers } from '@mastra/core/channels'

const handlers: ChannelHandlers = {
  onMessage: async (thread, message, defaultHandler) => {
    if (thread.channelId !== 'slack:C_SUPPORT') return
    await defaultHandler(thread, message)
  },
}
```

`defaultHandler` 會執行 Agent、發布回應並訂閱該執行緒。執行緒中後續訊息會交給 `onSubscribedMessage`。通過 `onMessage` 發起的執行，其 `channel.eventType` 為 `message`。當排隊批次同時包含提及和未提及 Bot 的傳送者時，若已啟用該處理程序，未提及者進入 `onMessage`；否則進入 `onMention`，若 `onMention` 為 `false` 則跳過。

`ChannelHandler` 函式簽名：

```typescript
type ChannelHandler = (
  thread: Thread,
  message: Message,
  defaultHandler: (thread: Thread, message: Message) => Promise<void>,
  ctx: ChannelHandlerContext,
) => Promise<void>

type ChannelHandlerContext = {
  mastra?: Mastra
  requestContext: RequestContext
  readonly signalMetadata: Record<string, unknown>
  readonly skipped: readonly Message[]
}
```

`ctx.mastra` 是解析後的 `mastra` 實例，因此處理器無須額外傳入存取器，就能存取存儲或其他已註冊的基礎元件：

```typescript
onDirectMessage: async (thread, message, defaultHandler, ctx) => {
  const store = await ctx.mastra?.getStorage()?.getStore('memory')
  await defaultHandler(thread, message)
}
```

`ctx.requestContext` 是此訊息即將啓動的執行所用的 [`RequestContext`](/docs/server/request-context)，每條訊息都會新建。在調用 `defaultHandler` 前寫入的值會進入執行，同時保留 Mastra 隨後添加的 Channel 項目：

```typescript
onDirectMessage: async (thread, message, defaultHandler, ctx) => {
  ctx.requestContext.set('locale', 'en-GB')
  await defaultHandler(thread, message)
}
```

執行從請求上下文讀取的任何值，都可以像這樣逐條訊息確定，例如平台傳送者對應哪個用戶。

`ctx.signalMetadata` 是附加到此訊息的 Agent Signal 上的元資料，每條訊息都會新建。在調用 `defaultHandler` 前添加可 JSON 序列化且不敏感的值。Mastra 可能持久化 Signal 元資料，並通過 PubSub 發布。與 `ctx.requestContext` 不同，無論訊息啓動新執行還是送入已有的活動執行，它都會隨訊息傳遞。

設定 `burst`、`debounce` 或 `queue` 等 `chatOptions.concurrency` 策略時，`ctx.skipped` 按從舊到新的順序列出 Chat SDK 在本輪次中合併的同一傳送者的較早訊息。沒有合併訊息時，該陣列為空。

## Resource ID 解析 {/* #resource-id-resolution */}

Channel 執行緒的 Memory `resourceId` 預設是 `${platform}:${message.author.userId}`。傳送者擁有按平台區分的 Memory。對於使用單一登入（SSO）等共享身分的應用，這會將同一用戶的 Memory 分開：其飛書私訊使用 `feishu:user_123`，Web 端則使用 `user_123`。

傳入 `resolveResourceId` 可將 Memory 所有權與傳送者身分分開確定。它只在創建新執行緒時執行。復用執行緒會保留已存儲的 `resourceId`，不會調用此hook，因此現有對話不依賴解析函式是否可用。傳回 `ctx.defaultResourceId` 可沿用內建行為。

```typescript title="src/mastra/agents/sso-agent.ts"
import { Agent } from '@mastra/core/agent'
import { createSlackAdapter } from '@chat-adapter/slack'

const agent = new Agent({
  id: 'sso-agent',
  name: 'SSO Agent',
  instructions: '...',
  model: '__GATEWAY_OPENAI_MODEL__',
  channels: {
    adapters: {
      slack: createSlackAdapter(),
    },
    resolveResourceId: async ({ thread, message }) => {
      // DM: share resource-level memory with the web app by using the bare SSO id
      if (thread.isDM) {
        return await resolveSsoUserId(message)
      }
      // Group chat: the conversation owns the memory; the sender stays the actor
      return thread.channelId
    },
  },
})
```

## Thread ID 解析 {/* #thread-id-resolution */}

新建 Channel 執行緒在 Mastra 內部預設使用隨機 UUID 作為執行緒 ID。傳入 `resolveThreadId` 可自行指定 ID；例如將執行緒 ID 設為其工作階段 ID，使其與應用創建的執行緒命名一致。

此hook在 `resolveResourceId` 之後執行，因此上下文中可以取得解析後的所有者。與 `resolveResourceId` 一樣，它只在創建新執行緒時執行：復用執行緒保留已存儲的 ID，不調用此hook。傳回的 ID 必須在整個 Memory 存儲中唯一。如果它已屬於現有執行緒，Mastra 會記錄警告並改用生成的 ID，避免覆蓋現有執行緒。傳回 `ctx.defaultThreadId` 可沿用內建行為。

```typescript title="src/mastra/agents/session-agent.ts"
import { Agent } from '@mastra/core/agent'
import { createSlackAdapter } from '@chat-adapter/slack'

const agent = new Agent({
  id: 'session-agent',
  name: 'Session Agent',
  instructions: '...',
  model: '__GATEWAY_OPENAI_MODEL__',
  channels: {
    adapters: {
      slack: createSlackAdapter(),
    },
    // Owner: a session id resolved from the sender's linked account
    resolveResourceId: async ctx => resolveSessionId(ctx),
    // Thread id: align with the session id so app URLs that address
    // threads by session id resolve channel-created threads too
    resolveThreadId: ({ resourceId, defaultThreadId }) => {
      return isSessionId(resourceId) ? resourceId : defaultThreadId
    },
  },
})
```

## 行內媒體 {/* #inline-media */}

控制哪些附件類別（圖片、影片、PDF 等）以檔案片段形式傳送給模型。不匹配的類別會以文字摘要描述，讓 Agent 瞭解檔案，同時避免不支援該類別的模型報錯。

對於不匹配的文字類附件（`text/*`、JSON、YAML、XML 等），若適配器可透過認證下載附件（如 Slack 私有檔案），就會下載附件並作為文字交給 Agent。超過 128 KB 的內容會截斷。適配器報告大小超過 10 MB 的檔案不會下載。

預設值（`['image/png', 'image/jpeg', 'image/webp', 'application/pdf']`）匹配主流視覺模型支援的格式。可覆蓋 `inlineMedia` 來擴充清單（例如 `['image/*', 'audio/*']`），也可完全改用判斷函式。

支援的萬用模式：

| 模式 | 匹配類別 |
| - | - |
| `image/*` | 所有圖片類別（`image/png`、`image/jpeg` 等） |
| `video/*` | 所有影片類別 |
| `*` 或 `*/*` | 所有類別 |
| `application/pdf` | 精確匹配該類別 |

對於使用私有 CDN 的平台（如 Slack），Chat SDK 會使用認證憑證下載附件。對於使用公共 CDN 的平台（如 Discord），附件 URL 會直接傳給模型。

## 行內連結 {/* #inline-links */}

將訊息文字中的 URL 轉為檔案片段，讓模型處理連結內容，而非只看到原始 URL 文字。每個項目可以是字串（網域模式），也可以是帶有強制 MIME 類別的物件。

**字串項目**匹配網域，並傳送 HEAD 請求偵測 Content-Type。解析出的類別會與 `inlineMedia` 對照，只有匹配的類別才會成為檔案片段。

**物件項目**匹配網域並強制指定 MIME 類別，跳過 HEAD 請求和 `inlineMedia` 檢查。適用於 YouTube 等網站：HEAD 請求傳回 `text/html`，但模型會將該 URL 視為影片內容。

```typescript
type InlineLinkEntry =
  | string // Domain pattern (HEAD determines mime type)
  | { match: string; mimeType: string } // Domain + forced mime type (skips HEAD)
```

const logger = new PinoLogger({ name: 'app', level: 'info' })
