# withSseHeartbeat()

包裝伺服器傳送事件（SSE）的 `Response`，在底層串流閒置時定期送出 `: heartbeat` 註解。代理伺服器及負載平衡器通常會關閉一段時間沒有位元組傳送的連線，導致長時間推理或較慢的 Tool 呼叫期間回應中斷。

使用 [`handleChatStream()`](/reference/ai-sdk/handle-chat-stream)、[`handleWorkflowStream()`](/reference/ai-sdk/handle-workflow-stream) 或 [`handleNetworkStream()`](/reference/ai-sdk/handle-network-stream) 自行建立回應時，可使用此函數。[`chatRoute()`](/reference/ai-sdk/chat-route) 會透過 `heartbeatMs` 選項在內部套用相同的包裝邏輯。

## 使用例子 {/* #usage-example */}

Next.js App Router 例子：

```typescript title="app/api/chat/route.ts"
import { handleChatStream, withSseHeartbeat } from '@mastra/ai-sdk'
import { createUIMessageStreamResponse } from 'ai'
import { mastra } from '@/src/mastra'

export async function POST(req: Request) {
  const params = await req.json()
  const stream = await handleChatStream({
    mastra,
    agentId: 'weatherAgent',
    version: 'v7',
    params,
  })
  return withSseHeartbeat(createUIMessageStreamResponse({ stream }), 15000)
}
```

請在回應編碼後才包裝。`handleChatStream()` 傳回 UI 訊息區塊串流；心跳是原始 SSE 註解，只有這些區塊序列化為傳輸格式後才可插入。

## 傳回值 {/* #returns */}

傳回一個 `Response`，以串流傳送原本的回應內容，並在閒置期間插入心跳註解。若省略 `heartbeatMs`、其值小於等於 `0`，或回應沒有內容，便會原樣傳回輸入的回應。

## 行為 {/* #behavior */}

- 心跳只會插入完整 SSE 訊框之間，不會拆開尚未傳送完的訊框。
- 來源資料、串流結束及串流錯誤，始終優先於到期的心跳。
- 取消包裝後的回應會同時取消來源串流，並清除尚待觸發的心跳計時器。
- 啟用心跳時，若傳入的值無法由計時器排程，便會拋出 `RangeError`（非有限數值或大於 `2147483647` 的值）。開始串流傳送前，可使用 `assertValidHeartbeatMs()` 對用戶提供的設定執行相同檢查。
