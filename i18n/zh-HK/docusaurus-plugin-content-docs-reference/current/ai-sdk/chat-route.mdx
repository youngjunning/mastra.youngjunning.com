# 聊天路由()

以 AI SDK 格式為串流Agent對話建立聊天路由處理程序。該函數註冊一個 HTTP`POST`在以 AI SDK 相容格式將回應串流傳輸到用戶端之前接受訊息並執行Agent的端點。在 a 內使用它[自訂API路由](/docs/server/custom-api-routes).

使用[`handleChatStream()`](/reference/ai-sdk/handle-chat-stream) if you need a framework-agnostic handler.

`chatRoute()`保留現有的 AI SDK v5/預設行為。如果您的應用程式是針對 AI SDK v6 輸入的，請傳遞`version: 'v6'`.

:::note 中斷連線行為

預設情況下，`chatRoute()` forwards the incoming request's `AbortSignal` to `agent.stream()`. If the client disconnects, Mastra aborts the in-flight generation.

放`resumable: true` to let the generation continue after a disconnect and allow AI SDK UI to reconnect to the active stream. Resumable chats don't support abort-based cancellation because `useChat().stop()` is indistinguishable from a refresh or network interruption at the server.

:::

## 使用範例 {/* #usage-example */}

此範例顯示如何在`/chat` endpoint that uses an agent with the ID `weatherAgent`.

```typescript title="src/mastra/index.ts"
import { Mastra } from '@mastra/core'
import { chatRoute } from '@mastra/ai-sdk'

export const mastra = new Mastra({
  server: {
    apiRoutes: [
      chatRoute({
        path: '/chat',
        agent: 'weatherAgent',
      }),
    ],
  },
})
```

您也可以使用基於運行時定義的Agent程式路由`agentId`. The URL `/chat/weatherAgent` will resolve to the agent with the ID `weatherAgent`.

```typescript title="src/mastra/index.ts"
import { Mastra } from '@mastra/core'
import { chatRoute } from '@mastra/ai-sdk'

export const mastra = new Mastra({
  server: {
    apiRoutes: [
      chatRoute({
        path: '/chat/:agentId',
      }),
    ],
  },
})
```

## 可恢復的串流 {/* #resumable-streams */}

放`resumable: true` on `chatRoute()` and `resume: true` on AI SDK UI's `useChat()` to reconnect after a refresh or network interruption. The route factory returns a two-item array containing:

* `POST <path>`：啟動Agent運行。請求的 AI SDK 聊天 ID 成為 Mastra 記憶體線程 ID。
* `GET <path>/:chatId/stream`：重播快取的事件並追蹤活動運行。路線返回`204` when the run is finished, unavailable, expired, or outside the caller's scope.

將傳回的數組作為一個條目傳遞給`server.apiRoutes`. Mastra flattens nested route arrays during server configuration.

```typescript title="src/mastra/index.ts"
import { Mastra } from '@mastra/core'
import { chatRoute } from '@mastra/ai-sdk'

export const mastra = new Mastra({
  server: {
    apiRoutes: [
      chatRoute({
        path: '/chat/:agentId',
        resumable: true,
      }),
    ],
  },
})
```

主動運行發現是進程本地的。重新連線請求必須到達啟動產生的相同正在執行的伺服器進程。可恢復模式不轉送請求`AbortSignal`, so `useChat().stop()` closes the client connection without cancelling the agent run.

如果聊天使用資源ID，則設定`MASTRA_RESOURCE_ID_KEY` in the request context through authentication middleware. Don't send the resource ID only as `memory.resource` in the POST body: the reconnecting GET request has no body, so `chatRoute()` rejects that configuration with `400`.

## 附加配置 {/* #additional-configuration */}

您可以使用[`prepareSendMessagesRequest`](https://ai-sdk.dev/docs/reference/ai-sdk-ui/use-chat#transport.default-chat-transport.prepare-send-messages-request) to customize the request sent to the chat route, for example to pass additional configuration to the agent:

```typescript
const { error, status, sendMessage, messages, stop } = useChat({
  transport: new DefaultChatTransport({
    api: 'http://localhost:4111/chat',
    prepareSendMessagesRequest({ messages }) {
      return {
        body: {
          // With memory configured, send only the new message. Mastra loads the
          // rest of the conversation from storage.
          messages: [messages[messages.length - 1]],
          // Pass memory config
          memory: {
            thread: 'user-1',
            resource: 'user-1',
          },
        },
      }
    },
  }),
})
```

沒有記憶，發送完整`messages` array as the chat route uses it as the request context.

有了內存，儲存的線程就是真相的來源，所以`regenerate` and editing an earlier message in `useChat` don't change it. To change stored history, use `memory.saveMessages` or the memory store's `updateMessages`, then send a new message.
