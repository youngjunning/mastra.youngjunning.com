# createCodingAgent()

**加入版本：** `@mastra/core@1.48.0`

`createCodingAgent()` 會以編程 Agent 所需的基本預設設定建立 [`Agent`](/reference/agents/agent)：本機 Workspace、設定 `memory` 時的任務清單訊號 Provider、網絡重試錯誤處理器，以及目標評估提示詞。只需提供 `model` 和 `instructions` 就能建立可用的 Agent，也可覆寫任何預設設定。

回傳值是標準的 `Agent`，可用於任何接受 `Agent` 的地方，包括傳入 [`AgentController`](/reference/agent-controller/agent-controller-class) 作為其 Agent。此函式位於 `@mastra/core`，背後沒有託管服務；它填入的每項預設設定，也可透過 [`new Agent()`](/reference/agents/agent) 自行設定。

這些預設設定與 [Mastra Code](https://code.mastra.ai) 使用的設定一致，但不包括該產品的提示詞、模式及工具。`createCodingAgent()` 只設定[預設設定](#defaults)所列的運行時元件。

## 使用範例 {/* #usage-example */}

傳入模型及指令即可。`createCodingAgent()` 會補上 Workspace 和錯誤處理器；設定 `memory` 時加入任務訊號 Provider，設定 `goal` 時加入目標提示詞：

```typescript title="src/mastra/coding-agent.ts"
import { createCodingAgent } from '@mastra/core/coding-agent'

const agent = createCodingAgent({
  id: 'my-coding-agent',
  name: 'My Coding Agent',
  model: '__GATEWAY_OPENAI_MODEL_BASE__',
  instructions: 'You are a helpful coding assistant.',
})

const result = await agent.generate('Which test files mention the /health endpoint?')
```

Agent 會取得其 Workspace 對應的 [Workspace 工具](/reference/workspace/workspace-class#filesystem-tools)。因此，只有建立 pull request 等超出 Workspace 能力的操作，才需要設定 `tools`。Mastra 亦會在系統提示詞中加入 Workspace 說明。

:::warning

預設 Workspace 會以應用程式程序的權限在主機執行命令。如何改用隔離的 Sandbox，請參閱 [Workspace](#workspace)。

:::

如需 Mastra Code 使用的行為提示詞，涵蓋儲存庫探索、編輯、命令及提交，可用 `instructions` 配合 [`buildBasePrompt()`](/reference/coding-agent/build-base-prompt) 建立。

## 預設值 {/* #defaults */}

只有未提供對應欄位時才會填入預設值。`signals` 是例外：任務訊號 Provider 會附加至傳入的 Provider。

| 欄位 | 省略時的預設值 |
| - | - |
|`workspace` | 以基礎路徑為根目錄的 [`Workspace`](/reference/workspace/workspace-class)，由 `LocalFilesystem` 及 `LocalSandbox` 支援。 |
| `signals` | [`TaskSignalProvider`](/reference/signals/task-signal-provider)，只有設定 `memory` 時才加入。 |
| `errorProcessors` | 未知串流錯誤重試及專門的 ECONNRESET 與錯誤請求策略，加上 `PrefillErrorHandler`、`ProviderHistoryCompat` 及 `CyberRefusalHandler`。 |
| `outputProcessors` | [`CyberRefusalHandler`](/reference/processors/cyber-refusal-handler). |
| `maxProcessorRetries` | `DEFAULT_MAX_PROCESSOR_RETRIES`（3），為輸出處理階段的網絡安全拒絕重試設定次數上限。 |
|`goal.prompt` | `DEFAULT_GOAL_JUDGE_PROMPT`（僅當`goal`已配置）。 |

除此之外不會填入其他設定；`model`、`instructions`、`tools`、`memory`、儲存空間及輸入處理器均沒有預設值。

每項預設設定都有明確的停用方法：

| 預設設定 | 如何停用 |
| - | - |
|工作空間 |`workspace: undefined` |
| 任務追蹤 | 不為 Agent 設定 `memory` |
| 錯誤處理器 | `errorProcessorDefaults: false` |
| 輸出處理器 | `outputProcessors: []` |
| 處理器重試次數 | `maxProcessorRetries: 0` |
| 目標評估提示詞 | 省略 `goal`，或傳入自訂的 `goal.prompt` |

### 工作空間 {/* #workspace */}

省略 `workspace` 欄位時，會建立以 `basePath`（預設為 `process.cwd()`）為根目錄的本機 Workspace：

```typescript
import { Workspace, LocalFilesystem, LocalSandbox } from '@mastra/core/workspace'

new Workspace({
  filesystem: new LocalFilesystem({ basePath }),
  sandbox: new LocalSandbox({ workingDirectory: basePath }),
})
```

若要保留相同的 Workspace 結構、改在其他目錄工作，請傳入 `basePath`：

```typescript
import { createCodingAgent } from '@mastra/core/coding-agent'

const agent = createCodingAgent({
  id: 'my-coding-agent',
  name: 'My Coding Agent',
  model: '__GATEWAY_OPENAI_MODEL_BASE__',
  instructions: 'You are a helpful coding assistant.',
  basePath: '/srv/checkouts/my-app',
})
```

也可傳入 `workspace`，自行設定後端。下例中，Agent 可讀取整個儲存庫，但命令只在其中一個套件內執行。若要使用遠端 Sandbox，可在相同位置取代 `LocalSandbox`；可用後端及隔離選項請參閱 [Sandbox](/docs/sandbox/overview)：

```typescript
import { createCodingAgent } from '@mastra/core/coding-agent'
import { LocalFilesystem, LocalSandbox, Workspace } from '@mastra/core/workspace'

const agent = createCodingAgent({
  id: 'my-coding-agent',
  name: 'My Coding Agent',
  model: '__GATEWAY_OPENAI_MODEL_BASE__',
  instructions: 'You are a helpful coding assistant.',
  workspace: new Workspace({
    filesystem: new LocalFilesystem({ basePath: '/srv/checkouts/my-app' }),
    sandbox: new LocalSandbox({ workingDirectory: '/srv/checkouts/my-app/packages/api' }),
  }),
})
```

若要停用預設 Workspace（例如已在 [`AgentController`](/reference/agent-controller/agent-controller-class) 層注入 Workspace），請明確傳入 `workspace: undefined`。省略欄位會建立預設 Workspace；明確設為 `undefined` 則不會建立：

```typescript
import { createCodingAgent } from '@mastra/core/coding-agent'

const agent = createCodingAgent({
  id: 'my-coding-agent',
  name: 'My Coding Agent',
  model: '__GATEWAY_OPENAI_MODEL_BASE__',
  instructions: 'You are a helpful coding assistant.',
  workspace: undefined, // opt out of the default workspace
})
```

### 訊號 {/* #signals */}

[`TaskSignalProvider`](/reference/signals/task-signal-provider) 會加入 `task_write`、`task_update`、`task_complete` 及 `task_check` [任務工具](/reference/tools/task-tools)，並將任務清單持久儲存於線程狀態，讓 Agent 在多步驟請求中保留計劃：

```typescript
import { createCodingAgent } from '@mastra/core/coding-agent'
import { Memory } from '@mastra/memory'

const agent = createCodingAgent({
  id: 'my-coding-agent',
  name: 'My Coding Agent',
  model: '__GATEWAY_OPENAI_MODEL_BASE__',
  instructions: 'Plan multi-step work with the task tools, then carry it out.',
  memory: new Memory(),
})
```

此 Provider 需要由 Memory 支援的線程，因此只有設定 `memory` 時才會加入。設定 Memory 後，它會與傳入的 `signals` 合併，避免自訂 Provider 意外停用任務追蹤。即使同時傳入 `signals: []` 及 `memory`，仍會加入任務 Provider。若要使用 Memory 而不啟用任務追蹤，請改用 [`new Agent()`](/reference/agents/agent)。在 `@mastra/core@1.49.0` 之前，此 Provider 一律會加入，因此在沒有 Memory 的情況下會失敗。

`TaskSignalProvider` 不接受建構函式參數；自訂這項預設設定，實際上是在選擇 Agent 還會取得哪些其他 Provider：

```typescript
import { createCodingAgent } from '@mastra/core/coding-agent'
import { WebhookSignalProvider } from '@mastra/core/signals'
import { Memory } from '@mastra/memory'

const agent = createCodingAgent({
  id: 'my-coding-agent',
  name: 'My Coding Agent',
  model: '__GATEWAY_OPENAI_MODEL_BASE__',
  instructions: 'You are a helpful coding assistant.',
  memory: new Memory(),
  signals: [
    new WebhookSignalProvider({
      extractResourceId: payload => (payload as { repository: string }).repository,
    }),
  ],
})
```

這個 Agent 會同時取得 webhook Provider 及任務 Provider。

### 錯誤處理器 {/* #error-processors */}

預設的 [`StreamErrorRetryProcessor`](/reference/processors/stream-error-retry-processor) 採用以下重試策略：

- 未被 Provider 元資料或特定比對條件識別的未知錯誤，最多重試兩次，每次等待 `3000ms`；已知的授權失敗會立即回報。
- 網絡連線重設（`ECONNRESET` / `socket hang up`）最多重試兩次，採用指數退避（`1000ms * 2^retryCount`，上限 `30000ms`）。
- 錯誤請求在等待 `2000ms` 後重試一次。

特定的網絡連線重設及錯誤請求策略優先於未知錯誤策略。傳入 `errorProcessors` 會設定基礎清單：四個共用預設處理器中，凡是清單未以相同 `id` 指定的，仍會依其 `id` 對應的位置加入。因此，傳入空陣列也會得到全部四個。設定 `errorProcessorDefaults: false` 後，則完全依傳入清單執行，不加入共用預設處理器；若也未傳入清單，Agent 就不會執行錯誤處理器。以這種方式加入的 `StreamErrorRetryProcessor` 使用共用預設設定，不會重試未知錯誤或錯誤請求（HTTP 400）。若需保留其中一種策略，請在清單中傳入自訂實例。`PrefillErrorHandler` 及 `ProviderHistoryCompat` 用於兼容 Provider：兩者都會修復訊息記錄結構造成的錯誤，例如 Provider 拒絕以 assistant 訊息結尾的對話。

當 OpenAI 或 Anthropic 的網絡安全防護拒絕某個步驟時，[`CyberRefusalHandler`](/reference/processors/cyber-refusal-handler) 會重試一次；一般編程工作也常遇到這種情況。它同時用於 `errorProcessors`（OpenAI 將拒絕作為 API 錯誤回傳）及 `outputProcessors`（Anthropic 將拒絕作為步驟結果回傳）。傳入其中一個清單，會取代該清單中的這個處理器。

重試發生在遇到錯誤的 `generate()` 或 `stream()` 呼叫內，因此程式碼不會察覺已恢復的失敗。重試次數用盡時，錯誤會如一般模型錯誤般回報：`generate()` 拒絕 Promise，`stream()` 發出 `error` chunk。`generate()` 和 `stream()` 亦支援每次呼叫傳入 `errorProcessors`，以取代 Agent 在該次請求使用的處理器清單。這些處理器共用的重試次數上限 `maxProcessorRetries`，請參閱[處理器](/docs/agents/processors#error-processor-retry-limits)。

### 目標 {/* #goal */}

預設不會設定目標。傳入 `goal` 但未提供 `prompt` 時，會使用 `DEFAULT_GOAL_JUDGE_PROMPT`。`goal` 設定包含評估模型及執行次數上限；目標內容則屬於各個線程，透過 [`setObjective()`](/docs/harness/goals#managing-the-objective) 設定：

```typescript
import { createCodingAgent } from '@mastra/core/coding-agent'
import { Memory } from '@mastra/memory'

const agent = createCodingAgent({
  id: 'my-coding-agent',
  name: 'My Coding Agent',
  model: '__GATEWAY_OPENAI_MODEL_BASE__',
  instructions: 'You are a helpful coding assistant.',
  memory: new Memory(),
  goal: {
    judge: '__GATEWAY_OPENAI_MODEL_LUNA__',
    maxRuns: 50,
  },
})

const threadId = 'thread-1'
const resourceId = 'user-1'

await agent.setObjective('Get the test suite passing', { threadId, resourceId })
```

[目標](/docs/harness/goals)需要[儲存空間](/docs/storage)後端及由 Memory 支援的線程。若最終未解析到 `judge`，目標評估步驟不會執行任何動作。
