# 設定

本參考文件列出 Mastra 支援的所有選項。透過建立 [`Mastra` 類別](/reference/core/mastra-class)的實例來初始化及設定 Mastra。

```ts title="src/mastra/index.ts"
import { Mastra } from '@mastra/core'

export const mastra = new Mastra({
  // Your options...
})
```

## 頂層選項 {/* #top-level-options */}

### agents {/* #agents */}

**類型：** `Record<string, Agent>`

以名稱為索引的 Agent 實例紀錄。Agent 是能利用 AI 模型、Tool 及 Memory 自主決策並採取行動的系統。

詳情請參閱 [Agent 文件](/docs/agents/overview)。

```typescript title="src/mastra/index.ts"
import { Mastra } from '@mastra/core'
import { Agent } from '@mastra/core/agent'

export const mastra = new Mastra({
  agents: {
    weatherAgent: new Agent({
      id: 'weather-agent',
      name: 'Weather Agent',
      instructions: 'You help with weather information',
      model: '__GATEWAY_OPENAI_MODEL__',
    }),
  },
})
```

### backgroundTasks {/* #backgroundtasks */}

**類型：** `BackgroundTaskManagerConfig`

啟用並設定背景工作管理器。啟用後，Agent 可非同步派發耗時的 Tool 呼叫（包括子 Agent 呼叫），同時繼續執行 Agent 迴圈。工作會持久儲存，因此必須設定 `storage` 後端。

詳情請參閱[背景工作文件](/docs/harness/background-tasks)。

```typescript title="src/mastra/index.ts"
import { Mastra } from '@mastra/core'
import { LibSQLStore } from '@mastra/libsql'

export const mastra = new Mastra({
  storage: new LibSQLStore({
    id: 'mastra-storage',
    url: 'file:./mastra.db',
  }),
  backgroundTasks: {
    enabled: true,
    globalConcurrency: 10,
    perAgentConcurrency: 5,
    backpressure: 'queue',
    defaultTimeoutMs: 300_000,
  },
})
```

### deployer {/* #deployer */}

**類型：** `IDeployer`

將應用程式發佈至雲端平台的部署 Provider。

詳情請參閱[部署文件](/docs/deployment/overview)。

```typescript title="src/mastra/index.ts"
import { Mastra } from '@mastra/core'
import { NetlifyDeployer } from '@mastra/deployer-netlify'

export const mastra = new Mastra({
  deployer: new NetlifyDeployer(),
})
```

### events {/* #events */}

**類型：** `Record<string, EventHandler | EventHandler[]>`

內部發佈／訂閱系統的事件處理函式。將事件主題對應至處理函式；事件發佈至主題時會呼叫這些函式。

:::warning
此選項供 Mastra 的 Workflow 引擎內部使用。大多數用戶毋須設定。
:::

```typescript title="src/mastra/index.ts"
import { Mastra } from '@mastra/core'

export const mastra = new Mastra({
  events: {
    'my-topic': async event => {
      console.log('Event received:', event)
    },
  },
})
```

### gateways {/* #gateways */}

**類型：** `Record<string, MastraModelGateway>`

用於存取 LLM Provider 的自訂模型路由閘道。閘道負責各 Provider 的身份驗證、URL 建構及模型解析。可用此選項支援自訂或自行託管的 LLM Provider。

詳情請參閱[自訂閘道文件](/models/gateways/custom-gateways)。

```typescript title="src/mastra/index.ts"
import { Mastra } from '@mastra/core'
import { MyPrivateGateway } from './gateways'

export const mastra = new Mastra({
  gateways: {
    private: new MyPrivateGateway(),
  },
})
```

### idGenerator {/* #idgenerator */}

**類型：** `(context?: IdGeneratorContext) => string`\
**Default:** `crypto.randomUUID()`

用於建立唯一識別碼的自訂 ID 產生函式。Mastra 會傳入可選的上下文，讓您能按要建立的實體產生 ID。

`IdGeneratorContext` 包含：

- `idType`: `'thread' | 'message' | 'run' | 'step' | 'generic'`
- `source?`: `'agent' | 'workflow' | 'memory'`
- `entityId?`：要求產生 ID 的 Agent、Workflow 或 Memory 實體 ID
- `threadId?`：適用時的執行緒 ID（例如建立訊息 ID 時）
- `resourceId?`：適用時的資源 ID（例如按用戶區分的執行緒）
- `role?`：建立訊息 ID 時的訊息角色
- `stepType?`：建立步驟 ID 時的 Workflow 步驟類型

:::warning

Mastra 內部使用此選項為 Workflow 執行、Agent 對話及其他資源建立 ID。大多數用戶毋須設定。

:::

```typescript title="src/mastra/index.ts"
import { v4 as uuid } from '@lukeed/uuid'
import { Mastra } from '@mastra/core'

export const mastra = new Mastra({
  idGenerator: context => {
    if (context?.idType === 'message' && context?.threadId) {
      return `msg-${context.threadId}-${uuid()}`
    }

    if (context?.idType === 'run' && context?.source && context?.entityId) {
      return `${context.source}-run-${context.entityId}-${uuid()}`
    }

    return uuid()
  },
})
```

### logger {/* #logger */}

**類型：** `IMastraLogger | false`\
**預設值：** `ConsoleLogger`，開發環境級別為 `INFO`，正式環境級別為 `WARN`

用於應用程式記錄日誌及偵錯的 Logger 實作。設為 `false` 可完全停用日誌。

詳情請參閱[日誌文件](/docs/observability/logging)。

```typescript title="src/mastra/index.ts"
import { Mastra } from '@mastra/core'
import { PinoLogger } from '@mastra/loggers'

export const mastra = new Mastra({
  logger: new PinoLogger({ name: 'MyApp', level: 'debug' }),
})
```

### mcpServers {/* #mcpservers */}

**類型：** `Record<string, MCPServerBase>`

向兼容 MCP（Model Context Protocol）的客戶端提供 Mastra Tool、Agent、Workflow 及資源的 MCP 伺服器。可用此選項編寫自己的 MCP 伺服器，供任何支援該協定的系統使用。

詳情請參閱 [MCP 概覽](/docs/connections/mcp)。

```typescript title="src/mastra/index.ts"
import { Mastra } from '@mastra/core'
import { MCPServer } from '@mastra/mcp'

const mcpServer = new MCPServer({
  id: 'my-mcp-server',
  name: 'My MCP Server',
  version: '1.0.0',
})

export const mastra = new Mastra({
  mcpServers: {
    myServer: mcpServer,
  },
})
```

### memory {/* #memory */}

**類型：** `Record<string, MastraMemory>`

可供 Agent 參照的 Memory 實例登錄表，包括使用 `{ type: 'id', memoryId: '<key>' }` 的已儲存 Agent。Memory 會保留過去對話中的相關資訊，讓 Agent 的多輪互動保持連貫。Mastra 支援儲存近期訊息的訊息紀錄、儲存用戶長期資訊的工作記憶，以及按相關性找回舊訊息的語義檢索。

詳情請參閱 [Memory 文件](/docs/memory/overview)。

:::note

大多數用戶直接在 Agent 上設定 Memory。此頂層選項用於定義可由多個 Agent 共用的可重用 Memory 實例。

:::

```typescript title="src/mastra/index.ts"
import { Mastra } from '@mastra/core'
import { Memory } from '@mastra/memory'
import { LibSQLStore } from '@mastra/libsql'

export const mastra = new Mastra({
  storage: new LibSQLStore({
    id: 'mastra-storage',
    url: ':memory:',
  }),
  memory: {
    chatMemory: new Memory({
      options: {
        lastMessages: 20,
      },
    }),
  },
})
```

### observability {/* #observability */}

**類型：** `ObservabilityEntrypoint`

Mastra 為 AI 應用程式提供可觀測性功能。可透過理解 AI 特有模式的 Tool 監控 LLM 操作、追蹤 Agent 決策及偵錯複雜的 Workflow。追蹤會記錄模型互動、Agent 執行路徑、Tool 呼叫及 Workflow 步驟。

詳情請參閱[可觀測性文件](/docs/observability/overview)。

```typescript title="src/mastra/index.ts"
import { Mastra } from '@mastra/core'
import { LibSQLStore } from '@mastra/libsql'
import { Observability, MastraStorageExporter } from '@mastra/observability'

export const mastra = new Mastra({
  storage: new LibSQLStore({
    id: 'mastra-storage',
    url: 'file:./mastra.db',
  }),
  observability: new Observability({
    configs: {
      default: {
        serviceName: 'my-app',
        exporters: [new MastraStorageExporter()],
      },
    },
  }),
})
```

### processors {/* #processors */}

**類型：** `Record<string, Processor>`

用於轉換 Agent 輸入及輸出的 Processor。Processor 在 Agent 執行流程的特定階段執行，可在輸入送達語言模型前修改輸入，也可在輸出傳回前修改輸出。可用它加入防護機制、偵測提示詞注入、審核內容或套用自訂業務邏輯。

詳情請參閱 [Processor 文件](/docs/agents/processors)。

:::note

大多數用戶直接在 Agent 上設定 Processor。此頂層選項用於定義可由多個 Agent 共用的可重用 Processor 實例。

:::

```typescript title="src/mastra/index.ts"
import { Mastra } from '@mastra/core'
import { ModerationProcessor } from '@mastra/core/processors'

export const mastra = new Mastra({
  processors: {
    moderation: new ModerationProcessor({
      model: '__GATEWAY_OPENAI_MODEL_LUNA__',
      categories: ['hate', 'harassment', 'violence'],
    }),
  },
})
```

### pubsub {/* #pubsub */}

**類型：** `PubSub`\
**Default:** `EventEmitterPubSub`

用於元件間事件驅動通訊的發佈／訂閱系統。Mastra 內部用它處理 Workflow 事件及元件通訊。

:::warning
此選項供 Mastra 內部使用。大多數用戶毋須設定。
:::

```typescript title="src/mastra/index.ts"
import { Mastra } from '@mastra/core'
import { CustomPubSub } from './pubsub'

export const mastra = new Mastra({
  pubsub: new CustomPubSub(),
})
```

### scorers {/* #scorers */}

**類型：** `Record<string, Scorer>`

Scorer 評估 Agent 回應及 Workflow 輸出的質素。它們以模型評分、規則及統計方法提供可量化指標，協助衡量 Agent 質素、追蹤表現、比較做法及找出改善空間。

詳情請參閱 [Scorer 文件](/docs/evals/overview)。

:::note

大多數用戶直接在 Agent 上設定 Scorer。此頂層選項用於定義可由多個 Agent 共用的可重用 Scorer 實例。

:::

```typescript title="src/mastra/index.ts"
import { Mastra } from '@mastra/core'
import { createToxicityScorer } from '@mastra/evals/scorers/prebuilt'

export const mastra = new Mastra({
  scorers: {
    toxicity: createToxicityScorer({ model: '__GATEWAY_OPENAI_MODEL_LUNA__' }),
  },
})
```

### classifiers {/* #classifiers */}

**類型：** `Record<string, Classifier>`

Classifier 向決策模型提出關於應用程式狀態的固定選項問題，並傳回具類型的答案。在此註冊可重用的 Classifier 後，可透過 `getClassifier()` 或 `getClassifierById()` 取得。若評估已註冊的 Classifier 時沒有運行中的 Trace，它會啟動根 `CLASSIFIER_EVALUATION` span，使用 `Mastra` 實例設定的可觀測性 Provider。

詳情請參閱 [Classifier 參考](/reference/classifier/classifier)。

```typescript title="src/mastra/index.ts"
import { Mastra } from '@mastra/core'
import { Classifier } from '@mastra/core/classifier'
import { typeSafeAi } from '@ai-sdk/typesafe-ai'

const safety = new Classifier({
  id: 'safety',
  model: typeSafeAi.decisionModel('__AI_SDK_TYPESAFE_DECISION_MODEL__'),
  questions: {
    unsafe: {
      type: 'boolean',
      criteria: { true: 'Unsafe', false: 'Safe' },
    },
  },
})

export const mastra = new Mastra({
  classifiers: { safety },
})
```

### storage {/* #storage */}

**類型：** `MastraCompositeStore`

用於持久儲存應用程式資料的儲存 Provider。Memory、Workflow、Trace 等需要持久儲存的元件會使用它。Mastra 支援 PostgreSQL、MongoDB、libSQL 等多種資料庫後端。

詳情請參閱[儲存文件](/docs/storage)。

```typescript title="src/mastra/index.ts"
import { Mastra } from '@mastra/core'
import { LibSQLStore } from '@mastra/libsql'

export const mastra = new Mastra({
  storage: new LibSQLStore({
    id: 'mastra-storage',
    url: 'file:./mastra.db',
  }),
})
```

### tools {/* #tools */}

**類型：** `Record<string, Tool>`

Tool 是 Agent 可重用的函式，用於與外部系統互動。每個 Tool 都定義輸入、輸出及執行邏輯。

詳情請參閱 [Tool 文件](/docs/agents/tools)。

:::note
大多數用戶直接在 Agent 上設定 Tool。此頂層選項用於定義可由多個 Agent 共用的 Tool。
:::

```typescript title="src/mastra/index.ts"
import { Mastra } from '@mastra/core'
import { createTool } from '@mastra/core/tools'
import { z } from 'zod'

const weatherTool = createTool({
  id: 'get-weather',
  description: 'Fetches weather for a city',
  inputSchema: z.object({
    city: z.string(),
  }),
  execute: async () => {
    return { temperature: 20, conditions: 'Sunny' }
  },
})

export const mastra = new Mastra({
  tools: {
    weather: weatherTool,
  },
})
```

### tts {/* #tts */}

**類型：** `Record<string, MastraVoice>`

提供語音合成功能的文字轉語音 Provider。註冊語音 Provider 後，Agent 可將文字回應轉成語音。

:::note

## 打包器選項 {/* #bundler-options */}

### bundler.externals {/* #bundlerexternals */}

**類型：** `boolean | string[]`\
**Default:** `true`

執行 `mastra build` 時，Mastra 會將專案打包至 `.mastra/output` 目錄。此選項控制哪些套件不納入 bundle（標記為「external」），改由套件管理工具另外安裝。當 Mastra 內置打包工具（[Rollup](https://rollupjs.org/configuration-options/#external)）無法順利打包某些套件時，這個選項很有用。

預設情況下，`mastra build` 會將此選項設為 `true`。

各值的意思如下：

- `true`：將專案 `package.json` 列出的所有依賴套件標記為 external
- `false`：不將任何依賴套件標記為 external；全部一起打包
- `string[]`：指定要標記為 external 的套件名稱陣列；其餘套件一起打包

```typescript title="src/mastra/index.ts"
import { Mastra } from '@mastra/core'

export const mastra = new Mastra({
  bundler: {
    externals: ['some-package', 'another-package'],
  },
})
```

### bundler.sourcemap {/* #bundlersourcemap */}

**類型：** `boolean`\
**Default:** `false`

為打包產物產生 source map。啟用後，`mastra dev` 及 `mastra start` 會使用 Node.js 的 `--enable-source-maps` 旗標啟動伺服器，令堆疊追蹤指向原始碼檔案。

```typescript title="src/mastra/index.ts"
import { Mastra } from '@mastra/core'

export const mastra = new Mastra({
  bundler: {
    sourcemap: true,
  },
})
```

### bundler.minify {/* #bundlerminify */}

**類型：** `boolean`\
**Default:** `false`

壓縮打包產物：移除註解及空白，並縮短局部識別碼；匯出的名稱會保留。

預設關閉，以維持構建產物可讀、堆疊追蹤可用。需要縮小 bundle 時才啟用，例如封裝供本地部署使用的容器映像。`mastra dev` 不會壓縮。

```typescript title="src/mastra/index.ts"
import { Mastra } from '@mastra/core'

export const mastra = new Mastra({
  bundler: {
    minify: true,
  },
})
```

### bundler.transpilePackages {/* #bundlertranspilepackages */}

**類型：** `string[]`\
**Default:** `[]`

列出構建時需透過 esbuild 轉譯原始碼的套件。若依賴套件包含 TypeScript 或其他打包前需編譯的程式碼，請使用此選項。

只有直接匯入尚未編譯的原始碼時才需要此選項。已編譯為 CommonJS 或 ESM 的套件毋須列在這裏。

Mastra 會自動偵測 monorepo 中的 Workspace 套件並加入此列表，因此通常只需指定要轉譯的外部套件。

構建時，Mastra 亦會解析 `tsconfig.json` 中的 `baseUrl` 及 `paths` 別名，包括指向 TypeScript 原始碼檔案的 ESM 風格匯入，例如 `~/utils/logger.js`。

```typescript title="src/mastra/index.ts"
import { Mastra } from '@mastra/core'

export const mastra = new Mastra({
  bundler: {
    transpilePackages: ['@my-org/shared-utils'],
  },
})
```

### bundler.pnpmWorkspaceSettings {/* #bundlerpnpmworkspacesettings */}

**類型：** `Record<string, JSONValue>`\
**Default:** `{}`

使用 pnpm 安裝部署依賴套件時，明確指定寫入產生的 `pnpm-workspace.yaml` 的設定。值可以是字串、數字、布林值、null、陣列或巢狀物件。其他套件管理工具會忽略此選項。

此選項用於指定部署安裝時應遵循的 pnpm 安裝政策：

```typescript title="src/mastra/index.ts"
import { Mastra } from '@mastra/core'

export const mastra = new Mastra({
  bundler: {
    pnpmWorkspaceSettings: {
      blockExoticSubdeps: false,
      minimumReleaseAge: 0,
    },
  },
})
```

明確指定的設定會覆寫從來源 Workspace 複製的設定。省略此選項時，仍按原有方式只複製來源 Workspace 設定的一部分。

只支援以下鍵：`allowBuilds`、`onlyBuiltDependencies`、`ignoredBuiltDependencies`、`minimumReleaseAge`、`minimumReleaseAgeExclude`、`trustPolicy`、`trustPolicyExclude`、`trustPolicyIgnoreAfter` 及 `blockExoticSubdeps`。其他鍵會在 pnpm 執行前報錯，包括 Mastra 為部署產物產生的鍵（`packages`、`overrides`、`patchedDependencies`、`allowUnusedPatches`、`supportedArchitectures`、`nodeLinker`），以及會更改 TLS 驗證、registry、網絡存取、store 完整性、依賴套件擴充、catalog 或構建腳本權限的設定。`neverBuiltDependencies` 不受支援，因為 pnpm 10 會執行所有未列在其中的構建腳本。此選項不接受命令列旗標，亦不適合存放密鑰。

明確設定的 `allowBuilds` 及 `onlyBuiltDependencies` 會採用與從來源複製的構建許可相同的驗證方式。

### server.auth {/* #serverauth */}

**類型：** `MastraAuthConfig | MastraAuthProvider`

伺服器的身份驗證設定。Mastra 支援 JWT、Clerk、Supabase、Firebase、WorkOS 及 Auth0 等多種身份驗證 Provider。

詳情請參閱[身份驗證文件](/docs/auth/overview)。

```typescript title="src/mastra/index.ts"
import { Mastra } from '@mastra/core'
import { MastraJwtAuth } from '@mastra/auth'

export const mastra = new Mastra({
  server: {
    auth: new MastraJwtAuth({
      secret: process.env.MASTRA_JWT_SECRET,
      mapUserToResourceId: user => user.id,
    }),
  },
})
```

`mapUserToResourceId` 回呼函式會將已驗證的用戶對應到 Memory／執行緒作用域所用的資源 ID。提供此回呼函式時，會在身份驗證成功後呼叫，並以 `MASTRA_RESOURCE_ID_KEY` 將傳回值寫入請求上下文。省略時，內置路由會改用客戶端提供的資源 ID（例如 `memory.resource`），因此擁有權檢查會信任呼叫方。Mastra 會在此情況下於啟動時發出警告。詳情請參閱[授權（用戶隔離）](/docs/server/middleware#authorization-user-isolation)。

### server.mcp {/* #servermcp */}

**類型：** `object`\
**Default:** `undefined`

設定[內置 MCP 伺服器](/docs/server/mcp)，透過 `/api/mcp` 向客戶端公開 Agent、Workflow 及 Tool。

| 屬性 | 類型 | 預設值 | 說明 |
| - | - | - | - |
| `enabled` | `boolean \| 'dev'` | `'dev'` | `'dev'` 只在 `mastra dev` 下提供端點；正式環境只有設定 `server.auth` 後才提供。`true` 一律提供端點，未設定驗證時會記錄警告。`false` 一律關閉。 |
| `path` | `string` | `'/mcp'` | 端點路徑，掛載在 API 前綴之下。每個路徑區段可使用字母、數字、`-`、`.`、`_` 及 `~`。路徑無效，或與 `MCPServer` 路由及其他伺服器路由衝突時，會改用 `/mcp` 並記錄錯誤。 |
| `toolsets` | `('agents' \| 'workflows' \| 'tools' \| 'memory' \| 'observability' \| 'observability_analytics' \| 'stored_agents')[]` | 所有工具集 | 要提供的工具集。客戶端可在每次請求中透過 `?toolsets=` 或 `X-MCP-Toolsets` 標頭縮小範圍。 |
| `enumLimit` | `number` | `25` | 可列為 id 參數列舉值的可見 Agent 或 Workflow 數量上限；可取得獨立 `tool_<id>` Tool 的數量亦受此上限限制。 |
| `featured` | `{ agents?: string[]; workflows?: string[] }` | `undefined` | 額外取得專屬 `agent_<id>` 或 `workflow_<id>` Tool 的 Agent 及 Workflow。 |
| `readOnly` | `boolean` | `false` | 只提供後端路由屬於讀取操作的 Tool。客戶端亦可透過 `?readonly=1` 或 `X-MCP-Readonly` 標頭指定。 |
| `include` | `{ agents?: string[]; workflows?: string[]; tools?: string[] }` | `undefined` | 對某類基本物件設定後，只提供列表中的物件。每個項目可比對物件的 `id` 或註冊 key。 |
| `exclude` | `{ agents?: string[]; workflows?: string[]; tools?: string[] }` | `undefined` | 一律不提供列表中的物件。每個項目可比對物件的 `id` 或註冊 key；優先於 `include`。 |
| `serverInfo` | `{ name?: string; version?: string; title?: string; instructions?: string }` | `undefined` | 提供給 MCP 客戶端的伺服器識別資訊。 |
| `oauth` | `{ resource?: string; requireAudience?: boolean; authorizationServers?: string[]; scopesSupported?: string[] }` | `undefined` | OAuth 探索及 token 受眾設定。請參閱 [`server.mcp.oauth`](#servermcpoauth)。 |

```typescript title="src/mastra/index.ts"
import { Mastra } from '@mastra/core'

export const mastra = new Mastra({
  server: {
    mcp: {
      featured: { agents: ['support-agent'] },
      exclude: { tools: ['delete-account'] },
    },
  },
})
```

### server.mcp.oauth {/* #servermcpoauth */}

{/* vale Vale.Terms = YES */}

**類型：** `object`\

### server.handleShutdownSignals {/* #serverhandleshutdownsignals */}

**類型：** `boolean`\
**Default:** `true`

由 `mastra dev` 及 `mastra build` 產生的伺服器是否自行安裝 `SIGINT`／`SIGTERM` 處理函式。預設收到訊號後會開始正常關閉：伺服器先停止接受新連線並等待進行中的請求完成，再呼叫 `mastra.shutdown()` 並結束程序（請參閱 [`server.drainTimeout`](#serverdraintimeout)）。

設為 `handleShutdownSignals: false` 可自行處理訊號，例如在 Mastra 設定模組註冊呼叫 `mastra.shutdown()` 的處理函式：

```typescript title="src/mastra/index.ts"
import { Mastra } from '@mastra/core'

export const mastra = new Mastra({
  server: {
    handleShutdownSignals: false,
  },
})

let shuttingDown = false
const shutdown = async () => {
  if (shuttingDown) return
  shuttingDown = true
  // custom shutdown coordination
  await mastra.shutdown()
  process.exit(0)
}

process.once('SIGINT', shutdown)
process.once('SIGTERM', shutdown)
```

請注意以下限制：

- 若沒有自行註冊處理函式，Node.js 會按預設訊號行為立即終止程序，不會等待請求完成。
- 自訂處理函式無法存取產生的入口檔案中的 HTTP 伺服器控制代碼，因此無法等待進行中的 HTTP 請求完成。若只需延長等待時間，請優先調整 [`server.drainTimeout`](#serverdraintimeout)。如需完全控制伺服器生命週期，請使用[伺服器適配器](/docs/server/server-adapters)。
- 執行 `mastra dev` 時，內置處理函式會在熱重新載入之間釋放儲存資源（例如 DuckDB 檔案鎖）。停用內置處理函式但沒有等效的自訂處理函式，重新載入後可能發生鎖定衝突。

### server.host {/* #serverhost */}

**類型：** `string`\
**預設值：** `localhost`（若已設定 `MASTRA_HOST` 環境變數，則使用其值）

Mastra 開發伺服器綁定的主機地址。若已設定 `MASTRA_HOST` 環境變數，它會覆寫預設值。

```typescript title="src/mastra/index.ts"
import { Mastra } from '@mastra/core'

export const mastra = new Mastra({
  server: {
    host: '0.0.0.0',
  },
})
```

### server.https {/* #serverhttps */}

**類型：** `{ key: Buffer; cert: Buffer }`

開發伺服器執行 TLS 時使用的 HTTPS 設定。Mastra 支援透過 `mastra dev --https` 在本地開發時使用 HTTPS，此旗標會自動建立及管理證書。若需自行管理證書，請提供密鑰及證書檔案：

```typescript title="src/mastra/index.ts"
import { Mastra } from '@mastra/core'
import fs from 'node:fs'

export const mastra = new Mastra({
  server: {
    https: {
      key: fs.readFileSync('path/to/key.pem'),
      cert: fs.readFileSync('path/to/cert.pem'),
    },
  },
})
```

### server.middleware {/* #servermiddleware */}

**類型：** `Middleware | Middleware[]`

自訂 Middleware 可在路由處理函式執行前後攔截請求，用於身份驗證、記錄日誌、注入請求上下文或加入標頭。每個 Middleware 都會收到 Hono `Context` 及 `next` 函式。傳回 `Response` 可提前結束請求；呼叫 `next()` 則繼續處理。

詳情請參閱 [Middleware 文件](/docs/server/middleware)。

```typescript title="src/mastra/index.ts"
import { Mastra } from '@mastra/core'

export const mastra = new Mastra({
  server: {
    middleware: [
      {
        handler: async (c, next) => {
          const authHeader = c.req.header('Authorization')
          if (!authHeader) {
            return new Response('Unauthorized', { status: 401 })
          }
          await next()
        },
        path: '/api/*',
      },
    ],
  },
})
```

### server.onError {/* #serveronerror */}

**類型：** `(err: Error, c: Context) => Response | Promise<Response>`

發生未處理錯誤時呼叫的自訂錯誤處理函式。可用它自訂錯誤回應、將錯誤記錄至 Sentry 等外部服務，或實作自己的錯誤格式。

所有伺服器適配器都支援此鈎子。`c` 參數提供與 Hono 兼容的上下文物件；非 Hono 適配器（Koa、Express、Fastify）會提供 shim，其中包含 `c.json()`、`c.req.path` 等常用方法。

```typescript title="src/mastra/index.ts"
import { Mastra } from '@mastra/core'
import * as Sentry from '@sentry/node'

export const mastra = new Mastra({
  server: {
    onError: (err, c) => {
      Sentry.captureException(err)

      return c.json(
        {
          error: err.message,
          timestamp: new Date().toISOString(),
        },
        500,
      )
    },
  },
})
```

### server.onValidationError {/* #serveronvalidationerror */}

**類型：** `(error: ZodError, context: 'query' | 'body' | 'path') => { status: number; body: unknown } | undefined`

請求未通過 Zod schema 驗證時呼叫的自訂處理函式。可用它自訂驗證錯誤回應、修改狀態碼，或按 API 規範設定錯誤格式。

傳回 `{ status, body }` 物件可覆寫預設的 `400` 回應；傳回 `undefined` 則沿用預設行為。所有伺服器適配器（Hono、Express、Fastify、Koa）都支援此鈎子。

`context` 參數表示請求的哪個部分未通過驗證：

- `'query'`：查詢參數
- `'body'`：請求主體
- `'path'`：路徑參數

```typescript title="src/mastra/index.ts"
import { Mastra } from '@mastra/core'

export const mastra = new Mastra({
  server: {
    onValidationError: (error, context) => ({
      status: 422,
      body: {
        ok: false,
        errors: error.issues.map(i => ({
          path: i.path.join('.'),
          message: i.message,
        })),
        source: context,
      },
    }),
  },
})
```

亦可對個別路由設定 `onValidationError`，該路由由 `createRoute()` 建立。路由級鈎子優先於伺服器級鈎子。

### server.port {/* #serverport */}

Mastra 開發伺服器綁定的連接埠。若已設定 `PORT` 環境變數，它會覆寫預設值。

```typescript title="src/mastra/index.ts"
import { Mastra } from '@mastra/core'

export const mastra = new Mastra({

    port: 8080,
  },

```

### server.drainTimeout {/* #serverdraintimeout */}

**類型：** `number`\
**Default:** `5000` (5 seconds)

伺服器收到 `SIGINT` 或 `SIGTERM` 後，等待進行中請求完成的最長時間，單位為毫秒。值必須是 `0` 到 `2147483647` 之間的有限數值。期間伺服器停止接受新連線，並等待進行中的請求（包括運行中的串流）完成；若先到期限，剩餘 HTTP 連線會關閉。WebSocket 等升級連線會在程序結束時終止。無論如何，程序結束前都會呼叫 `mastra.shutdown({ drainTimeout })`，讓進行中的 Workflow 執行（包括持久化 Agent 執行）在 Worker 及發佈／訂閱服務清理前，享有相同時間以完成或暫停。背景工作取消及 Worker 清理亦共用這段時間。之後，產生的伺服器還會最多等待 5 秒清理 Workspace 及 Storage。設為 `0` 會跳過兩次等待。

滾動部署時，若需等待耗時的 Agent 回合或 Workflow 步驟完成，可提高此值。HTTP 請求等待及 Workflow 等待會依次進行，因此最壞情況應以此值的兩倍再加 5 秒清理時間估算，並確保總和小於平台的寬限期（例如 Kubernetes 的 `terminationGracePeriodSeconds`）：

```typescript title="src/mastra/index.ts"
import { Mastra } from '@mastra/core'

export const mastra = new Mastra({
  server: {
    drainTimeout: 600000, // 10 minutes
  },
})
```

等待期間再次傳送任何一個關閉訊號，會跳過等待並立即終止程序。

### server.studioBase {/* #serverstudiobase */}

**類型：** `string`\
**Default:** `/`

託管 [Studio](/docs/studio/overview) 的基礎路徑。可用它將 Studio 放在現有應用程式的子路徑，而非根路徑。

與現有應用程式或 Cloudflare Zero Trust 等受惠於共用網域的驗證工具整合時，此選項很有用。它亦支援在同一網域下管理多個服務。

```typescript title="src/mastra/index.ts"
import { Mastra } from '@mastra/core'

export const mastra = new Mastra({
  server: {
    studioBase: '/my-mastra-studio',
  },
})
```

**URL 範例：**

- 預設：`http://localhost:4111/`（Studio 位於根路徑）
- 設定 `studioBase`：`http://localhost:4111/my-mastra-studio/`（Studio 位於子路徑）

### server.timeout {/* #servertimeout */}

**類型：** `number`\
**預設值：** `180000`（3 分鐘）

請求逾時時間，單位為毫秒。超過此時間的請求會被終止。

在無伺服器平台上，此限制獨立於平台本身的函式逾時。例如，[Vercel Deployer](/reference/deployer/vercel#request-timeouts) 透過 `maxDuration`（秒）設定 Vercel 的上限，而 `server.timeout` 仍然生效，因此耗時請求需要同時提高兩項上限。

```typescript title="src/mastra/index.ts"
import { Mastra } from '@mastra/core'

export const mastra = new Mastra({
  server: {
    timeout: 30000, // 30 seconds
  },
})
```
