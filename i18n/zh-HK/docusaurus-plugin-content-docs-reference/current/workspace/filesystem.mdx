# 工作空間檔案系統

**添加於：** `@mastra/core@1.1.0`

這`WorkspaceFilesystem` interface defines how workspaces interact with file storage.

### `stat(path)` {/* #statpath */}

取得檔案或目錄元資料。

```typescript
const stat = await filesystem.stat('docs/guide.md')
// { name: 'guide.md', path: 'docs/guide.md', type: 'file', size: 1234, createdAt: Date, modifiedAt: Date }
```

**返回：** `Promise<FileStat>`

```typescript
interface FileStat {
  name: string // File or directory name (basename only)
  path: string // Path within the filesystem namespace; relative to basePath for LocalFilesystem
  type: 'file' | 'directory'
  size: number
  createdAt: Date
  modifiedAt: Date
  mimeType?: string
}
```

內建的`read_file` tool uses `mimeType` to choose how to return a file. Files whose type matches the tool's `mediaTypes` option come back as native media parts, up to `maxMediaBytes`. Larger files return metadata only unless the caller passes an `encoding`. By default the media types are PNG, JPEG, WebP, and PDF. Files that `mediaTypes` doesn't match and that have no `mimeType`, a text-like type, or `application/octet-stream` come back as text. See [agent tools](/reference/workspace/workspace-class#filesystem-tools) for the `mediaTypes` and `maxMediaBytes` options. A custom filesystem that never sets `mimeType` returns images and PDFs as text.

放`mimeType` for files only, and leave it unset for directories. `getMimeType()` from `@mastra/core/workspace` is the extension lookup that `LocalFilesystem` uses. It returns `application/octet-stream` for unknown extensions.

```typescript
import { getMimeType } from '@mastra/core/workspace'

const mimeType = type === 'file' ? getMimeType(path) : undefined
```

  provider: string
  status?: string

  readOnly?: boolean
  icon?: string // Icon identifier for UI display
  metadata?: Record<string, unknown> // Provider-specific, e.g. LocalFilesystem includes basePath

### `walk(path, options?)` {/* #walkpath-options */}

提供者以盡可能少的呼叫執行本機遞歸樹遍歷。實施後，Workspace`list_files` tool uses it instead of issuing one `readdir` round trip per directory, which matters for remote providers (sandboxes, object stores). If `walk` throws, tools fall back to the `readdir`-based walk automatically and log a warning through the workspace logger, since the fallback issues one round trip per directory.

```typescript
const entries = await filesystem.walk?.('.', { maxDepth: 3 })
// [{ name: 'index.ts', type: 'file', path: 'src/index.ts' }, ...]
```

### `grep(options)` {/* #grepoptions */}

由提供者執行的本機內容搜尋（例如`rg` or `grep` inside a sandbox). When implemented, the workspace `grep` tool delegates to it instead of downloading every file to search host-side. Throw `UnsupportedGrepPatternError` when a pattern can't run natively so that callers catch it and fall back to the host-side implementation. That fallback is logged at `info` level; any other error from `grep` also triggers the fallback but is logged as a warning, since the host-side search reads every candidate file.

```typescript
const results = await filesystem.grep?.({
  pattern: 'TODO',
  path: '.',
  caseSensitive: true,
  includeHidden: false,
})
// [{ path: 'src/index.ts', matches: [{ line: 3, column: 6, text: '// TODO: fix' }] }]
```

}
