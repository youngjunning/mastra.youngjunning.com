# PlatformSandbox

這個客戶端用於在 Mastra Platform 環境中建立 Sandbox。每個 `PlatformSandbox` 實例管理一個遠端 Sandbox：`start()` 建立 Sandbox，`executeCommand()` 在其中執行命令，`destroy()` 則將其刪除。如需管理更多遠端 Sandbox，可建立更多實例；也可使用 `clone()`，從已設定的範本衍生實例（參閱[複製多個 Sandbox](#cloning-for-a-fleet-of-sandboxes)）。

Sandbox 從預先建置的 Provider 範本啟動，範本已安裝 Python 3、Node 22、TypeScript、tsx 及常用建置工具。你亦可使用可跨 Provider 使用的 `Template()` 建構器建立[可重用範本](#reusable-templates)。傳入固定的 `id` 可啟用[檢查點還原](#checkpoint-recovery)，讓新 Sandbox 從先前 Sandbox 的檔案系統啟動。

相關 Provider：用於自行託管 Railway Sandbox 的 [`RailwaySandbox`](/integrations/sandboxes/railway)，以及用於本機 Sandbox 的 [`LocalSandbox`](/reference/workspace/local-sandbox)。

:::note

介面詳情請參閱 [WorkspaceSandbox 介面](/reference/workspace/sandbox)。

:::

## 安裝 {/* #installation */}

```bash npm2yarn
npm install @mastra/platform-workspace
```

設定平台憑證。若未提供存取權杖、專案 ID 或環境 ID，系統會從環境變數讀取；因此，部署至 Mastra Platform 時毋須傳入任何建構函式選項。

<Tabs>
  <TabItem value="env-file" label=".env 檔案">
    ```bash
    MASTRA_PLATFORM_ACCESS_TOKEN=your-platform-access-token
    MASTRA_PROJECT_ID=your-project-id
    MASTRA_ENVIRONMENT_ID=your-environment-id
    ```
  </TabItem>

  <TabItem value="constructor" label="建構函式">
    ```typescript
    new PlatformSandbox({
      accessToken: 'your-platform-access-token',
      projectId: 'your-project-id',
      environmentId: 'your-environment-id',
    })
    ```
  </TabItem>
</Tabs>

部署至 Mastra Platform 時，系統會自動注入 `MASTRA_PLATFORM_ACCESS_TOKEN`、`MASTRA_PROJECT_ID` 及 `MASTRA_ENVIRONMENT_ID`，因此呼叫建構函式時毋須傳入選項。本機開發時，可將組織設定頁面 **API Tokens** 下以 `sk_` 開頭的 API 權杖設為 `MASTRA_PLATFORM_ACCESS_TOKEN`。

Sandbox Provider 會先從建構函式的 `sandboxProvider` 選項取得，其次讀取 `SANDBOX_PROVIDER` 環境變數；兩者皆未設定時，預設為 `e2b`。

## 用法 {/* #usage */}

將 `PlatformSandbox` 加入 Workspace，然後將 Workspace 指派給 Agent：

```typescript
import { Agent } from '@mastra/core/agent'
import { Workspace } from '@mastra/core/workspace'
import { PlatformSandbox } from '@mastra/platform-workspace'

const workspace = new Workspace({
  sandbox: new PlatformSandbox({
    // accessToken, projectId, environmentId all fall back to env vars
    idleTimeoutMinutes: 30,
  }),
})

const agent = new Agent({
  id: 'code-agent',
  name: 'Code Agent',
  instructions: 'You are a coding assistant working in this workspace.',
  model: '__GATEWAY_ANTHROPIC_MODEL_SONNET__',
  workspace,
})

const response = await agent.generate(
  'Print "Hello, world!" and show the current working directory.',
)

console.log(response.text)
```

### 私人網絡 {/* #private-networking */}

將 `networkIsolation` 設為 `PRIVATE`，即可加入環境的私人網絡，存取同一 Mastra Platform 環境中運行的其他服務：

```typescript
const workspace = new Workspace({
  sandbox: new PlatformSandbox({
    networkIsolation: 'PRIVATE',
  }),
})
```

預設的 `ISOLATED` 模式只允許對外連接互聯網，無法連接私人網絡。

### 公開連接埠 {/* #public-ports */}

連接埠預設不公開：存取時須使用已登入的預覽連結。設定 `publicPorts` 後，任何持有連接埠 URL 的人都可存取，例如 webhook 接收服務：

```typescript
const workspace = new Workspace({
  sandbox: new PlatformSandbox({
    publicPorts: true,
  }),
})
```

兩種情況下的連接埠 URL 相同，差別只在於是否需要登入。此設定在建立 Sandbox 時確定；重新連接時傳入新值，不會改變現有 Sandbox 的設定。複製的實例會使用你傳入的 `publicPorts` 選項，不會沿用重新連接的 Sandbox 設定。

### 重新連接至運行中的 Sandbox {/* #reattaching-to-a-running-sandbox */}

傳入現有的 `sandboxId`，即可重新連接至運行中的 Sandbox，而毋須建立新 Sandbox：

```typescript
const sandbox = new PlatformSandbox({
  sandboxId: 'sbx_abc123',
})
await sandbox.start()

const result = await sandbox.executeCommand('cat', ['/workspace/state.json'])
```

指定 `sandboxId` 時，Sandbox 已存在，因此毋須提供 `environmentId`。

呼叫 `start()` 後，從 `sandboxId` 屬性讀取運行中 Sandbox 的平台 ID，並儲存供下次重新連接使用。在目前程序啟動 Sandbox 之前，該屬性為 `undefined`。傳入建構函式的 `sandboxId` 只供 `start()` 作重新連接的提示；在 `start()` 執行前，`getInfo()` 只會回傳本機狀態，不會向平台查詢該 ID。預設使用 `reattach: 'best-effort'` 時，如果平台已找不到該 ID，`start()` 會改為根據 Sandbox 的邏輯 `id` 建立新 Sandbox。此回退操作需要 `environmentId`（或 `MASTRA_ENVIRONMENT_ID`）；若儲存的 ID 可能已失效，請同時提供環境 ID，否則 `start()` 會拋出 `environmentId is required`。

重新連接時，`start()` 回傳 `{ outcome: 'connected' }`；建立新 Sandbox 時回傳 `{ outcome: 'created' }`。從檢查點還原亦屬新建：即使檔案系統已還原，虛擬機仍是新建立的。共用介面約定請參閱 [`start()`](/reference/workspace/sandbox#start)。

如果建立新 Sandbox 會令應用程式依賴的狀態在不易察覺的情況下遺失，請設定 `reattach: 'required'`：

```typescript
const sandbox = new PlatformSandbox({
  sandboxId: 'sbx_abc123',
  reattach: 'required',
})
```

設定 `reattach: 'required'` 後，如果平台回報目標不存在（404）、已失效（410）或已銷毀，`start()` 會拋出 `code` 為 `SANDBOX_REATTACH_FAILED` 的 `SandboxError`，而不會建立 Sandbox。錯誤的 `details` 包含 `provider`、`sandboxId`、`logicalId`（Sandbox 的邏輯 `id`）及 `reason`。其他錯誤會原樣傳遞。如要建立新 Sandbox，請清除已儲存的 `sandboxId`，並在建構 Sandbox 時省略此選項。複製的實例會繼承 `reattach` 設定。

### 可重用範本 {/* #reusable-templates */}

將可重用的範本建構器傳入 `PlatformSandbox`。建立新 Sandbox 時，系統會將序列化後的範本定義傳送至 Platform；Platform 會按內容識別範本，並開始或重用 Provider 的建置。建立 Sandbox 不會等待建置完成。若所需的確切範本尚未建置完成，Platform 會先使用最合適的替代範本啟動 Sandbox，並在背景建置所需範本。若同一範本系列中有資源設定相符的舊範本，便會用作替代；否則使用 Provider 的基礎範本：

```typescript
import { PlatformSandbox, Template } from '@mastra/platform-workspace'

const commitSha = process.env.REPOSITORY_COMMIT_SHA!
const template = Template()
  .cpuCount(4)
  .memoryMB(8_192)
  .setWorkdir('/workspace/repo')
  .setEnvs({ BUILD_CONFIG_MARKER: 'template-v1' })
  .aptInstall(['git', 'jq'])
  .runCmd('git clone https://github.com/mastra-ai/mastra.git /workspace/repo')
  .runCmd(`git checkout ${commitSha}`)
  .runCmd('pnpm install --frozen-lockfile')

const sandbox = new PlatformSandbox({
  environmentId: 'env_abc',
  sandboxProvider: 'e2b',
  template,
})
await sandbox.start()
```

`Template()` 支援 `cpuCount`、`memoryMB`、`docker`、`runCmd`、`setWorkdir`、`setEnvs`、`aptInstall`、`pipInstall` 及 `npmInstall`。Platform 會在內部將建構器序列化，並計算內容雜湊值。呼叫 `await template.build(options)`，即可開始或重用 Provider 的建置，而毋須建立 Sandbox。此方法會回傳 `ready`、`pending` 或 `failed`，並附上範本 ID，以及視乎情況提供的重試提示或錯誤。

對 E2B 而言，`cpuCount()` 及 `memoryMB()` 設定範本的建置資源；從確切範本或資源設定相符的舊範本建立的 Sandbox，會沿用這些設定。兩個方法均接受正的安全整數，預設值分別為 2 個 CPU 和 1,024 MB。若重複設定資源，以最後一次設定為準；實際生效的值亦屬內容識別資料的一部分。省略兩項設定，等同明確指定預設值。若尚在建置的範本回退至 Provider 的基礎範本，Sandbox 可能會使用 Provider 的預設資源。可檢查 `templatePending`，判斷是否出現此情況。

`docker()` 會在 E2B 範本中安裝 Docker Engine 和 Compose。Docker 守護程序會在首次使用時才啟動，因此從未使用 Docker 的 Sandbox 不會產生相關費用。只有啟用 Docker 時，這項設定才會計入內容識別資料；未啟用 Docker 的範本會維持原有 ID。使用 Docker 時，記憶體至少應設為 2,048 MB。

Railway 會將命令、工作目錄、環境變數及套件操作轉換為 Railway 範本指令。Railway 目前會忽略 `cpuCount()` 及 `memoryMB()`，因為其 Sandbox 範本 API 沒有提供相應的資源設定。

對於公開的 GitHub 儲存庫，當 `start()` 需要建立新 Sandbox 時，`createRepoTemplate()` 可延遲解析並建置固定至特定 commit 的範本定義：

```typescript
import { createRepoTemplate, PlatformSandbox } from '@mastra/platform-workspace'

const sandbox = new PlatformSandbox({
  environmentId: 'env_abc',
  template: createRepoTemplate({
    getRepositoryAccess: async () => ({ cloneUrl: 'https://github.com/mastra-ai/mastra.git' }),
    setupCommand: 'pnpm install --frozen-lockfile',
    memoryMB: 2048,
  }),
})
await sandbox.start()
```

`createRepoTemplate()` 以一般選項形式接受 `cpuCount`、`memoryMB` 及 `docker` 設定，其作用與 `Template()` 建構器的同名方法相同，亦遵循上述內容識別及舊範本回退規則。省略這些選項便會使用 Provider 的預設值。

`setupCommand` 亦可接受陣列；每個項目會作為獨立、可快取的建置步驟執行。`workingDirectory` 設定建置程序及 Sandbox 的工作目錄，儲存庫則會複製至 `<workingDirectory>/<repo>`。`buildEnv` 只會將環境變數傳給建置步驟，不會將其加入序列化的範本定義。`buildEnvRevision` 是在複製儲存庫及執行設定步驟前寫入的不透明 ID；新的修訂值會令這些步驟重新建置。每次變更 `buildEnv` 時都應更新此值，但切勿從環境變數的值推算它。

`getRepositoryAccess` 與 Factory Sandbox 上下文中的解析器採用相同介面，因此主程式可直接傳入該上下文。若未提供解析器，`createRepoTemplate()` 會回傳 `undefined`，Sandbox 則會從 Provider 的預設範本啟動。重新連接至現有 `sandboxId` 時不會呼叫解析器；建立新 Sandbox 時，解析器會先取得儲存庫預設分支的最新 commit，Platform 才會開始或重用相應的範本建置。若無法解析該 commit，或 Provider 建置失敗，Sandbox 仍會從 Provider 的預設範本建立，讓執行階段的設定程序從頭檢出儲存庫。對於私人儲存庫，短期有效的授權權杖會作為臨時建置環境變數傳送，不會進入序列化的範本定義或持久儲存的範本記錄，也不影響內容識別。

#### 在同一範本中使用多個儲存庫 {/* #several-repositories-in-one-template */}

傳入 `repos` 而非 `getRepositoryAccess`，即可將多個儲存庫複製到同一 Sandbox。每個儲存庫各有自己的存取解析器及 `setupCommand`；後者可為字串或陣列，陣列中的每個項目都是獨立的建置步驟：

```typescript
const template = createRepoTemplate({
  repos: [
    {
      getRepositoryAccess: async () => ({ cloneUrl: 'https://github.com/mastra-ai/mastra' }),
      setupCommand: 'pnpm install --frozen-lockfile',
    },
    {
      getRepositoryAccess: async () => ({
        cloneUrl: 'https://github.com/mastra-ai/template-docs-expert',
      }),
      setupCommand: 'npm install',
    },
  ],
  workspaceSetupCommand: 'npm install --global @mastra/mcp-docs-server',
  continueOnSetupFailure: true,
  workingDirectory: '/home/user/repos',
})
```

每個儲存庫都會複製至 `<workingDirectory>/<repo>`。系統會先建置公開儲存庫，再建置私人儲存庫；各組內仍按呼叫方指定的順序處理。私人儲存庫的憑證是所有建置步驟均可讀取的臨時環境變數，因此任何儲存庫的設定命令都可讀取其他儲存庫的權杖。請只將設定命令可互相信任的儲存庫列在一起。

所有儲存庫設定完成後，`workspaceSetupCommand` 會在工作目錄中執行。`continueOnSetupFailure` 預設為 `false`；啟用後，即使某個設定命令失敗，系統也會將該儲存庫記錄於 `.mastra-sandbox/setup-failed` 並繼續，而不會令整個建置失敗。

標記檔案可讓工作階段知道映像檔已執行哪些步驟：每個儲存庫各有 `.mastra-sandbox/repos/<repo>`；Workspace 命令執行後則有 `.mastra-sandbox/workspace-setup`。這些檔案都位於工作目錄下。若啟用了 `continueOnSetupFailure`，請先檢查 `.mastra-sandbox/setup-failed`。

工作目錄及按指定順序排列的儲存庫清單會構成系列鍵。變更其中任何一項都會建立新系列；在首次建置完成前，該系列須從頭啟動。變更設定命令或憑證則會留在可重用既有建置的新舊範本系列中。若無法解析清單中任何儲存庫的存取資料，範本會暫時退化為只包含資源設定，直至下次解析成功。若無法解析某個儲存庫的分支最新 commit，該儲存庫會以未固定 commit 的方式複製；其他儲存庫仍維持固定至各自的 commit。

`createRepoTemplate()` 亦會在範本定義中加入不依賴 commit 的 `family` 鍵：單一儲存庫使用 `repo:<cloneUrl>:<workingDirectory>/<repo>`；儲存庫清單則使用根據工作目錄及按順序排列的複製 URL 計算出的 `repos:<hash>`。`family` 會將同一儲存庫不同 commit 的連續建置歸為同一系列。Platform 會藉此尋找同系列中先前已完成的建置，先以其檔案系統啟動新 commit 的 Sandbox，同時在背景建置與該 commit 完全相符的範本。對 E2B 而言，尋找舊範本時亦會按實際 CPU 及記憶體設定區分，避免回退時悄悄改變所要求的機器規格。直接使用 `Template()` 建構器時，可透過 `.withFamily(key)` 自行設定系列鍵；鍵值須為不超過 200 個字元的非空字串。省略此設定便不會使用同系列舊範本回退。系列鍵不影響按內容識別的範本身分：若兩個定義只有 `family` 不同，仍會共用同一快取位置。

Platform 會按伺服器根據範本定義計算出的內容雜湊值，在所選環境及 Provider 下儲存建置狀態。

#### 查看尚在建置的範本 {/* #observing-a-pending-template-build */}

當 Sandbox 從替代範本啟動時（即同系列中資源設定相符的舊範本，或 Provider 的基礎範本），Platform 的回應會包含 `templatePending` 欄位，並由 `PlatformSandbox` 提供以便查看建置狀態：

```typescript
await sandbox.start()
if (sandbox.templatePending) {
  // The sandbox is running on a fallback template.
  // A later start() of a sandbox with the same template definition
  // will pick up the exact template once the background build finishes.
  console.log('exact template still baking:', sandbox.templatePending.templateId)
}
```

若 Sandbox 從完全相符的範本啟動，`templatePending` 便是 `undefined`。`PlatformSandbox` 不會在運行中的 Sandbox 內重新執行範本操作。如有與特定 commit 相關的檔案系統狀態，請在自己的執行階段設定程序中處理（例如以 `onStart` hook 執行 `git fetch && git checkout <sha>`），做法與從新範本啟動時相同。待完全相符的範本建置完成後，可在之後的 `start()` 中重新建立 Sandbox，以使用該範本。

:::warning

預設情況下，每項範本操作都會序列化並傳送至 Platform，再由 Platform 按所選 Provider 的能力解讀。短期有效的建置憑證應使用 `setEnvs(values, { ephemeral: true })` 傳入：這些值會另外傳送，不會計入內容識別資料或持久儲存。它們在執行階段無法使用；若與序列化環境變數的鍵相同，則以臨時值為準。每次建置或可能觸發建置的新 Sandbox 建立操作，都須重新提供這些值。在 Railway，Provider 快取會包含臨時建置變數。因此，即使 Platform 範本 ID 保持不變，輪換變數值仍可能觸發 Provider 再次建置。

:::

### 檢查點還原 {/* #checkpoint-recovery */}

建構函式的 `id`（明確指定或自動產生）會在呼叫 `POST /sandbox` 時傳送至 Platform，作為建議使用的還原鍵：

* 若 Platform 識別出先前工作階段使用過的 `id`，新 Sandbox 會從該 Sandbox 檔案系統最近的檢查點啟動，而非使用基礎配置。
* 若 Platform 不識別該 `id`，便會按基礎配置建立新 Sandbox。自動產生的 ID 不會與先前的 ID 相符，因此省略 `id` 等同停用檢查點還原。

傳入固定的 `id`，即可在不同工作階段之間，或在一次 `destroy()`／`start()` 週期後，保留 Sandbox 的檔案系統：

```typescript
const sandbox = new PlatformSandbox({
  id: `project-${projectId}`,
})
await sandbox.start() // Boots from the most recent checkpoint for this id, or fresh if unknown
```

檢查點還原與透過 `sandboxId` 重新連接的還原範圍不同。重新連接會回到同一個運行中的 Sandbox，連同其中運行的程序一併接續。檢查點還原則會建立全新的 Sandbox，並從 Platform 為先前使用該 `id` 的 Sandbox 擷取的最新檢查點還原檔案系統。運行中的程序，以及上次擷取檢查點後寫入的檔案，都不會還原。

更新檔案系統後，可呼叫 `snapshot()`，立即擷取已設定的還原檢查點。若呼叫方未提供 `id`，或 Sandbox 未運行，此方法會完成呼叫，但不會擷取檢查點。

```typescript
await sandbox.snapshot()
```

每個 `id` 對應一個獨立的檔案系統。若不相關的 Sandbox 重用同一 `id`，Platform 可能會讓它們從彼此的檢查點啟動。

當 `id` 尚未有對應的檢查點時，可設定 `seedCheckpointName`，提供僅在啟動時使用的後備檢查點。若兩個檢查點都存在，Platform 會優先還原 `id` 對應的檢查點。之後擷取的快照仍會寫入 `id` 對應的檢查點；種子檢查點不會改變。

```typescript
const sandbox = new PlatformSandbox({
  id: `project-session-${sessionId}`,
  seedCheckpointName: 'project-base',
})
```

### 複製多個 Sandbox {/* #cloning-for-a-fleet-of-sandboxes */}

`clone()` 會回傳一個獨立的 `PlatformSandbox` 實例。它會繼承原實例的憑證及預設設定（存取權杖、專案、環境、Provider、範本、網絡隔離、逾時、指示、環境變數、閒置逾時及公開連接埠），亦可逐個實例覆寫。回傳的 Sandbox 尚未啟動，會在自行呼叫 `start()` 時才建立，因此 `clone()` 不會執行 I/O：

```typescript
const template = new PlatformSandbox({
  networkIsolation: 'PRIVATE',
  idleTimeoutMinutes: 30,
})

const perProject = template.clone({ id: `project-${projectId}` })
await perProject.start()
```

為每個複製實例設定固定的 `id`，即可讓它們各自透過 `clone()` 獨立啟用[檢查點還原](#checkpoint-recovery)。

### 執行命令 {/* #executing-commands */}

`executeCommand` 會在遠端 Sandbox 執行命令並回傳輸出。透過 `args` 傳入參數，系統便會安全地為參數加上 shell 引號：

```typescript
const result = await sandbox.executeCommand('python', ['analyze.py'], {
  timeout: 30_000,
  cwd: '/workspace',
  env: { INPUT: 'repo' },
})

console.log(result.stdout)
console.log(result.exitCode)
```

:::warning

`command` 參數是 shell 字串，會原樣拼接至遠端 shell 命令。因此可以使用管道、重新導向及串接命令（`ls -la | grep foo`）；但不可信的輸入必須透過 `args` 傳入，由系統安全地加上引號，或由呼叫方自行加上 shell 引號。若將不可信的值用作 `command`，便可能在 Sandbox 中執行任意 shell 命令。

:::

### 背景程序 {/* #background-processes */}

`sandbox.processes` 可在背景執行命令。程序運行期間會持續傳送輸出；你亦可列出程序、連接至程序或將其停止：

```typescript
const handle = await sandbox.processes.spawn('pnpm dev', {
  onStdout: data => console.log(data),
})

// Everything running in the sandbox, plus exited processes not read yet
const running = await sandbox.processes.list()

await handle.kill()
```

除非透過 `spawn()` 或建構函式傳入 `timeout`，否則程序沒有時間限制。若要連接至並非由此管理器啟動的程序（例如應用程式重新啟動後仍在運行的程序），可呼叫 `get(pid)`。連接前產生的輸出無法取得。

長時間運行的程序，其輸出串流會定期重新連接；程序在重新連接期間仍會繼續運行。重新連接期間產生的輸出會遺失。若程序恰好在輸出串流重新連接時結束，`wait()` 會回報結束代碼 `1`，而非實際的結束代碼。

### 連接埠 URL {/* #port-urls */}

`sandbox.networking.getPortUrl(port)` 會傳回應用程式在 Sandbox 中監聽的連接埠 URL，例如開發伺服器的 URL：

```typescript
await sandbox.processes.spawn('pnpm dev --host 0.0.0.0 --port 3000')

const url = await sandbox.networking?.getPortUrl(3000)
// https://3000-<sandbox id>.sandbox.us.mastra.cloud/
```

連接埠預設為私有：Sandbox 所屬組織的成員登入 Mastra 後，才能在瀏覽器開啟該 URL。設定 [`publicPorts: true`](#public-ports) 後，任何持有 URL 的人毋須登入即可開啟。URL 永不過期，可以分享；開啟 URL 亦會喚醒已暫停的 Sandbox。

若 Sandbox 的連接埠無法開放，`networking` 會是 `undefined`。Sandbox 未運行或已銷毀、連接埠編號不是 1 至 65535 的整數，或指定的是 Sandbox 保留的控制連接埠時，`getPortUrl()` 會傳回 `null`，而不會啟動 Sandbox。其他 Platform 錯誤（例如存取權杖無效）則會拋出。

您控制的瀏覽器（例如 Agent 使用的瀏覽器）無法自行登入。`getPortAuthCookie(port)` 會傳回 Cookie，讓該瀏覽器在一小時內毋須登入即可開啟連接埠 URL。請勿分享此 Cookie；任何持有它的人都能開啟該連接埠。

```typescript
const cookie = await sandbox.getPortAuthCookie(3000)
if (cookie) await browserContext.addCookies([cookie])
```

## 錯誤 {/* #errors */}

平台 API 請求失敗時會拋出 `PlatformApiError`。結構化的 `{ error: { message, type } }` 回應會解析為 `.code`（機器可讀的錯誤類型）及 `.proxyMessage`（供人閱讀的訊息）；原始回應內容仍可透過 `.body` 取得：

```typescript
import { PlatformApiError } from '@mastra/platform-workspace'

try {
  await sandbox.executeCommand('cat', ['/missing.txt'])
} catch (err) {
  if (err instanceof PlatformApiError) {
    if (err.code === 'not_found') {
      // handle missing resource
    } else if (err.code === 'authentication_error') {
      // refresh token
    }
    console.error(err.status, err.code, err.proxyMessage)
  }
}
```

如果回應內容不是 JSON，例如負載平衡器回傳 HTML 格式的 502 頁面，`code` 和 `proxyMessage` 均為 `undefined`。

`executeCommand` 透過 direct-exec 資料平面執行命令（使用 WebSocket 連接 Railway tcp-proxy）；若發生無法復原的故障，亦可能拋出以下兩種 Sandbox 錯誤：

```typescript
import { SandboxDestroyedError, SandboxExecTransportError } from '@mastra/platform-workspace'

try {
  await sandbox.executeCommand('pytest')
} catch (err) {
  if (err instanceof SandboxDestroyedError) {
    // /exec-lease returned 410; the sandbox has been destroyed.
    // The cached sandbox id and lease have already been cleared,
    // so reusing the instance will reprovision on the next call.
  } else if (err instanceof SandboxExecTransportError) {
    // Both the initial WebSocket attempt and the built-in retry
    // closed without an exit frame against a live sandbox.
    console.error(err.closeCode, err.closeReason, err.wsEndpoint)
  }
}
```

`SandboxExecTransportError` 包含診斷欄位 `opened`、`closeCode`、`closeReason`、`wsEndpoint`、`sandboxId`、`command` 及 `attempts`，方便維運人員區分 Railway 資料平面故障與命令執行失敗。
