# 本機檔案系統

**添加於：** `@mastra/core@1.1.0`

將檔案儲存在本機檔案系統上的目錄中。接口詳情請參見[WorkspaceFilesystem Interface](/reference/workspace/filesystem).

## 用法 {/* #usage */}

添加一個`LocalFilesystem` to a workspace and assign it to an agent. The agent can then read, write, and manage files as part of its tasks:

```typescript
import { Agent } from '@mastra/core/agent'
import { Workspace, LocalFilesystem } from '@mastra/core/workspace'

const workspace = new Workspace({
  filesystem: new LocalFilesystem({
    basePath: './workspace',
  }),
})

const agent = new Agent({
  id: 'file-agent',
  model: '__GATEWAY_OPENAI_MODEL__',
  workspace,
})

// The agent now has filesystem tools available
const response = await agent.generate('List all files in the workspace')
```

## 方法 {/* #methods */}

### `init()` {/* #init */}

初始化檔案系統。如果基本目錄不存在，則建立它。

```typescript
await filesystem.init()
```

呼叫者`workspace.init()`.

### 延遲初始化 {/* #lazy-initialization */}

如果尚未初始化，LocalFilesystem 將在第一次操作時初始化，並自動建立基底目錄。呼喚`init()` explicitly is optional but can be useful to pre-create directories before the first operation.

### `destroy()` {/* #destroy */}

清理檔案系統資源。

```typescript
await filesystem.destroy()
```

呼叫者`workspace.destroy()`.

### `setAllowedPaths(pathsOrUpdater)` {/* #setallowedpathspathsorupdater */}

在運行時更新允許的路徑。接受新的路徑數組（取代目前路徑）或接收目前路徑並傳回新路徑集的更新程式回呼。

```typescript
// Set directly
filesystem.setAllowedPaths(['/home/user/.config'])

// Update with callback
filesystem.setAllowedPaths(prev => [...prev, '/home/user/documents'])

// Clear all allowed paths
filesystem.setAllowedPaths([])
```

## 路徑分辨率 {/* #path-resolution */}

### 如何`basePath` works {/* #how-basepath-works */}

這`basePath` option sets the root directory for all file operations. Paths passed to methods like `readFile()` are resolved as follows:

* 解析相對路徑`basePath`: `docs/guide.md` → `<basePath>/docs/guide.md`
* 使用`.` to refer to the root of `basePath`, for example `readdir('.')`
* 絕對路徑被視為主機路徑，而不是內部路徑`basePath`. With the default `contained: true`, any absolute path that falls outside `basePath` and the configured `allowedPaths` is rejected with a `PermissionError`
* `~`擴展到使用者的主目錄，因此它也是主機路徑，並且受到相同的包含規則的約束

```typescript
const filesystem = new LocalFilesystem({
  basePath: './workspace',
})

// Resolves to ./workspace/docs/guide.md
await filesystem.readFile('docs/guide.md')
await filesystem.readFile('./docs/guide.md')

// Root of basePath
await filesystem.readdir('.')

// Throws a PermissionError with the default contained: true
await filesystem.readFile('/docs/guide.md')
```

讀取外部主機絕對路徑`basePath`, add them to `allowedPaths` or set `contained: false`. Prefer `allowedPaths` when only a few external directories are needed.

```typescript
const filesystem = new LocalFilesystem({
  basePath: './workspace',
  allowedPaths: ['/home/user/shared-docs'],
})

await filesystem.readFile('/home/user/shared-docs/guide.md')
```

### 掛載的檔案系統 {/* #mounted-filesystems */}

當一個`LocalFilesystem` is mounted in a workspace through `CompositeFilesystem`, workspace-facing paths include the mount prefix. For example, with a mount at `/workspace`, the workspace path `/workspace/report.md` is passed to the underlying filesystem as `report.md`, relative to its `basePath`. See [Filesystem mounts](/docs/sandbox/filesystem#mounts) for mount configuration.

### 相對路徑和執行上下文 {/* #relative-paths-and-execution-context */}

當您使用相對路徑時`basePath`, it resolves from `process.cwd()`. In Mastra projects, the cwd changes based on how you run your code:

|背景 |工作目錄|`./workspace` resolves to |
| - | - | - |
| `mastra dev` | `./src/mastra/public/` | `./src/mastra/public/workspace` |
| `mastra start` | `./.mastra/output/` | `./.mastra/output/workspace` |
| Direct script | Where you ran the command | Relative to that location |

當相同的相對路徑解析到不同的位置時，這可能會導致混亂。

### 推薦：使用絕對路徑 {/* #recommended-use-absolute-paths */}

為了使所有執行上下文的路徑保持一致，請使用具有絕對路徑的環境變數：

```typescript
import { LocalFilesystem } from '@mastra/core/workspace'

const filesystem = new LocalFilesystem({
  basePath: process.env.WORKSPACE_PATH!,
})
```

放`WORKSPACE_PATH` in your environment to an absolute path like `/home/user/my-project/workspace`. It ensures the workspace path is consistent regardless of how you run your code.
