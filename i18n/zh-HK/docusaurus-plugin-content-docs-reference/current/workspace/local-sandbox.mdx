# LocalSandbox

**新增於：** `@mastra/core@1.1.0`

在本機系統執行命令。介面詳情請參閱 [WorkspaceSandbox 介面](/reference/workspace/sandbox)。

## 用法 {/* #usage */}

將 `LocalSandbox` 加入 Workspace，再將該 Workspace 指派給 Agent。之後，Agent 就可以在處理任務時執行 shell 命令：

```typescript
import { Agent } from '@mastra/core/agent'
import { Workspace, LocalFilesystem, LocalSandbox } from '@mastra/core/workspace'

const workspace = new Workspace({
  filesystem: new LocalFilesystem({ basePath: './workspace' }),
  sandbox: new LocalSandbox({
    workingDirectory: './workspace',
    env: {
      NODE_ENV: 'development',
    },
  }),
})

const agent = new Agent({
  id: 'dev-agent',
  model: '__GATEWAY_OPENAI_MODEL__',
  workspace,
})

// The agent now has the execute_command tool available
const response = await agent.generate('Run npm install')
```

### 自動啟動行為 {/* #auto-start-behavior */}

如果 `LocalSandbox` 尚未運行，首次執行命令時便會自動啟動。你亦可以在應用程式啟動時呼叫 `workspace.init()`，預先啟動 Sandbox，避免首次執行命令時出現延遲。

## 路徑解析 {/* #path-resolution */}

### 相對路徑與執行環境 {/* #relative-paths-and-execution-context */}

如果為 `workingDirectory` 指定相對路徑，該路徑會以 `process.cwd()` 為基準解析。在 Mastra 專案中，目前工作目錄會隨程式碼的執行方式而改變：

| 執行方式 | 目前工作目錄 | `./workspace` 解析為 |
| - | - | - |
| `mastra dev` | `./src/mastra/public/` | `./src/mastra/public/workspace` |
| `mastra start` | `./.mastra/output/` | `./.mastra/output/workspace` |
| 直接執行指令碼 | 執行命令時所在的目錄 | 該目錄下的 `workspace` |

因此，同一個相對路徑可能解析到不同位置，容易令人混淆。

### 建議：使用絕對路徑 {/* #recommended-use-absolute-paths */}

為了使所有執行上下文的路徑保持一致，請使用具有絕對路徑的環境變數：

```typescript
import { LocalSandbox } from '@mastra/core/workspace'

const sandbox = new LocalSandbox({
  workingDirectory: process.env.WORKSPACE_PATH!,
})
```

將環境變數 `WORKSPACE_PATH` 設為絕對路徑，例如 `/home/user/my-project/workspace`。這樣無論以甚麼方式執行程式碼，命令都會在同一目錄執行。

## Windows shell {/* #windows-shell */}

`executeCommand(command, args)` 會依 POSIX shell 規則為 `args` 加上引號。在未啟用隔離的原生 Windows 環境中，`LocalSandbox` 會透過 Git Bash 而非 `cmd.exe` 執行這些命令。它會依序尋找 `MASTRA_WINDOWS_SHELL` 指定的 shell、命令的 `PATH` 中 `git.exe` 旁的 `bin\bash.exe`，以及 `%ProgramFiles%\Git\bin\bash.exe`。如果找不到 shell，命令會改由 `cmd.exe` 執行；但 `cmd.exe` 無法解析依 POSIX 規則加上引號的參數。不帶 `args`、以單一字串傳入的命令一律透過 `cmd.exe` 執行；以 argv 形式呼叫 `cmd`、`powershell` 或 `pwsh` 的命令亦一樣。在 Git Bash 下，`LocalSandbox` 會設定 `MSYS_NO_PATHCONV=1` 及 `MSYS2_ARG_CONV_EXCL=*`，讓 `/F` 等選項及 Windows 路徑原樣傳給原生 Tool。

安裝 [Git for Windows](https://git-scm.com/download/win) 即可取得 Git Bash。層級較深的儲存庫路徑可能超過 Windows 的路徑長度限制，因此亦請執行 `git config --global core.longpaths true`。如果想讓 argv 形式的命令繼續透過 `cmd.exe` 執行，例如呼叫 `dir` 等 `cmd.exe` 內置命令，請將 `MASTRA_WINDOWS_SHELL` 設為 `cmd.exe` 的完整路徑。

## 背景程序 {/* #background-processes */}

`LocalSandbox` 內置程序管理器，用於啟動及管理背景程序。這些程序透過 `child_process.spawn` 作為本機電腦上的子程序運行。

```typescript
const sandbox = new LocalSandbox({ workingDirectory: './workspace' })
await sandbox.start()

// Spawn a background process
const handle = await sandbox.processes.spawn('node server.js')

// Read output, send stdin, signal EOF, and wait for completion
console.log(handle.stdout)
await handle.sendStdin('input\n')
await handle.closeStdin()
await handle.wait()
```

啟用原生隔離（`seatbelt` 或 `bwrap`）後，啟動的程序亦會使用相同的隔離後端。

完整 API 請參閱 [SandboxProcessManager 參考文件](/reference/workspace/process-manager)。

## 靜態方法 {/* #static-methods */}

### `detectIsolation()` {/* #detectisolation */}

偵測目前平台上最適合且可用的隔離後端。

```typescript
const detection = LocalSandbox.detectIsolation()
// { backend: 'seatbelt', available: true, message: 'Seatbelt available on macOS' }
```

## 環境隔離 {/* #environment-isolation */}

預設情況下，`LocalSandbox` 的環境中只包含 `PATH`。這樣既能執行命令，亦能避免意外洩露 API 金鑰等機密資料。

```typescript
// Default: only PATH is available (commands work, secrets protected)
const secureSandbox = new LocalSandbox({
  workingDirectory: './workspace',
})

// Explicit: pass specific variables
const sandbox = new LocalSandbox({
  workingDirectory: './workspace',
  env: {
    NODE_ENV: 'development',
    API_URL: 'https://api.example.com',
  },
})

// Full access (use with caution)
const devSandbox = new LocalSandbox({
  workingDirectory: './workspace',
  env: process.env,
})
```

## 原生作業系統 Sandbox {/* #native-os-sandboxing */}

`LocalSandbox` 支援原生作業系統層級的 Sandbox，可提供額外安全保障：

* **macOS**：使用 Seatbelt（`sandbox-exec`）隔離檔案系統及網絡
* **Linux**：使用 Bubblewrap（`bwrap`）進行命名空間隔離

```typescript
// Detect the best available backend for this platform
const detection = LocalSandbox.detectIsolation()
console.log(detection)
// { backend: 'seatbelt', available: true, message: '...' }

// Enable native sandboxing
const sandbox = new LocalSandbox({
  workingDirectory: './workspace',
  isolation: 'seatbelt', // or 'bwrap' on Linux
  nativeSandbox: {
    allowNetwork: false, // Block network access (default)
    readWritePaths: ['/tmp/extra'], // Additional writable paths
  },
})
```

啟用隔離時：

* 檔案寫入僅限於 Workspace 目錄、`readWritePaths` 及暫存位置。在 macOS（seatbelt）上，還可寫入 `/private/tmp`、`/var/folders` 及 `/private/var/folders`。在 Linux（bubblewrap）上，`/tmp` 是 Sandbox 內的私有 tmpfs，不會寫入主機。
* 檔案讀取權限取決於隔離後端。在 macOS（seatbelt）上，可以讀取所有位置，以滿足系統執行檔的存取需求。在 Linux（bubblewrap）上，產生的政策只會開放選定的系統路徑（例如 `/usr`、`/lib`、`/bin` 及必要的 `/etc` 檔案）、`readOnlyPaths`、`readWritePaths` 和 Workspace。如果 `allowSystemBinaries` 不為 `false`，Node.js 所在目錄、`/opt` 及 `/snap` 亦可見。其他主機路徑無法存取。如果設定了 `bwrapArgs`，它會取代產生的政策，因此只有你提供的參數決定哪些路徑可見。
* 預設禁止存取網絡。
* 程序隔離可防止 Sandbox 內的程序影響主機系統。

### Sandbox 設定檔的位置 {/* #sandbox-profile-location */}

在 macOS 上使用 seatbelt 隔離時，`LocalSandbox` 會在 `process.cwd()` 下的 `.sandbox-profiles/` 目錄產生設定檔，與工作目錄分開：

```text
project/
├── .sandbox/                      # Default working directory (sandboxed)
│   └── ... files created by sandbox
├── .sandbox-profiles/             # Seatbelt profiles (outside sandbox)
│   └── seatbelt-a1b2c3d4.sb       # Hash based on workspace + config
└── ... your project files
```

設定檔名稱是 Workspace 路徑及設定的雜湊值。因此，設定相同的 Sandbox 會共用設定檔，設定不同的 Sandbox 則使用不同檔案，避免多個 Sandbox 同時運行時發生衝突。

將設定檔與工作目錄分開，可防止 Sandbox 內的程序讀取或修改自己的安全設定檔。設定檔在 Sandbox 啟動時建立，並在銷毀時清除。
