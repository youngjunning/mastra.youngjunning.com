# 本地Sandbox

**添加於：** `@mastra/core@1.1.0`

在本機系統上執行命令。接口詳情請參見[WorkspaceSandbox interface](/reference/workspace/sandbox).

## 用法 {/* #usage */}

添加一個`LocalSandbox` to a workspace and assign it to an agent. The agent can then execute shell commands as part of its tasks:

```typescript
import { Agent } from '@mastra/core/agent'
import { Workspace, LocalFilesystem, LocalSandbox } from '@mastra/core/workspace'

const workspace = new Workspace({
  filesystem: new LocalFilesystem({ basePath: './workspace' }),
  sandbox: new LocalSandbox({
    workingDirectory: './workspace',
    env: {
      NODE_ENV: 'development',
    },
  }),
})

const agent = new Agent({
  id: 'dev-agent',
  model: '__GATEWAY_OPENAI_MODEL__',
  workspace,
})

// The agent now has the execute_command tool available
const response = await agent.generate('Run npm install')
```

### 自動啟動行為 {/* #auto-start-behavior */}

`LocalSandbox`如果尚未運行，則在第一次執行命令時自動啟動。您也可以透過呼叫明確啟動沙箱`workspace.init()` at application startup to avoid first-command latency.

## 路徑分辨率 {/* #path-resolution */}

### 相對路徑和執行上下文 {/* #relative-paths-and-execution-context */}

當您使用相對路徑時`workingDirectory`, it resolves from `process.cwd()`. In Mastra projects, the cwd changes based on how you run your code:

|背景 |工作目錄|`./workspace` resolves to |
| - | - | - |
| `mastra dev` | `./src/mastra/public/` | `./src/mastra/public/workspace` |
| `mastra start` | `./.mastra/output/` | `./.mastra/output/workspace` |
| Direct script | Where you ran the command | Relative to that location |

當相同的相對路徑解析到不同的位置時，這可能會導致混亂。

### 推薦：使用絕對路徑 {/* #recommended-use-absolute-paths */}

為了使所有執行上下文的路徑保持一致，請使用具有絕對路徑的環境變數：

```typescript
import { LocalSandbox } from '@mastra/core/workspace'

const sandbox = new LocalSandbox({
  workingDirectory: process.env.WORKSPACE_PATH!,
})
```

放`WORKSPACE_PATH` in your environment to an absolute path like `/home/user/my-project/workspace`. It ensures commands run from a consistent directory regardless of how you run your code.

## Windows外殼 {/* #windows-shell */}

`executeCommand(command, args)`引號`args` for a POSIX shell. On native Windows without isolation, `LocalSandbox` runs these commands through Git Bash instead of `cmd.exe`. It uses the shell in `MASTRA_WINDOWS_SHELL` if set, then the `bin\bash.exe` next to `git.exe` on the command's `PATH`, then `%ProgramFiles%\Git\bin\bash.exe`. If no shell is found, commands fall back to `cmd.exe`, which can't parse POSIX-quoted arguments. Commands passed as a single string without `args` always run through `cmd.exe`，就像 argv 呼叫一樣`cmd`, `powershell`， 和`pwsh`。在 Git Bash 下，`LocalSandbox`套`MSYS_NO_PATHCONV=1`和`MSYS2_ARG_CONV_EXCL=*`所以切換就像`/F`Windows 路徑到達本機Tool時保持不變。

安裝[Git for Windows](https://git-scm.com/download/win) to get Git Bash. Deep repository paths can exceed the Windows path limit, so also run `git config --global core.longpaths true`. To keep running argv commands through `cmd.exe`, for example to call `cmd.exe` builtins like `dir`, set `MASTRA_WINDOWS_SHELL` to the full path of `cmd.exe`.

## 後台程式 {/* #background-processes */}

`LocalSandbox`包括一個內建的進程管理器，用於產生和管理後台進程。進程在本機電腦上作為子進程運行，使用`child_process.spawn`.

```typescript
const sandbox = new LocalSandbox({ workingDirectory: './workspace' })
await sandbox.start()

// Spawn a background process
const handle = await sandbox.processes.spawn('node server.js')

// Read output, send stdin, signal EOF, and wait for completion
console.log(handle.stdout)
await handle.sendStdin('input\n')
await handle.closeStdin()
await handle.wait()
```

啟用本機隔離時（`seatbelt` or `bwrap`), spawned processes are also wrapped with the same isolation backend.

看[`SandboxProcessManager` reference](/reference/workspace/process-manager) for the full API.

## 靜態方法 {/* #static-methods */}

### `detectIsolation()` {/* #detectisolation */}

檢測目前平台的最佳可用隔離後端。

```typescript
const detection = LocalSandbox.detectIsolation()
// { backend: 'seatbelt', available: true, message: 'Seatbelt available on macOS' }
```

## 環境隔離 {/* #environment-isolation */}

預設情況下，`LocalSandbox` only includes `PATH` in the environment. Commands can run without accidental exposure of API keys and secrets.

```typescript
// Default: only PATH is available (commands work, secrets protected)
const secureSandbox = new LocalSandbox({
  workingDirectory: './workspace',
})

// Explicit: pass specific variables
const sandbox = new LocalSandbox({
  workingDirectory: './workspace',
  env: {
    NODE_ENV: 'development',
    API_URL: 'https://api.example.com',
  },
})

// Full access (use with caution)
const devSandbox = new LocalSandbox({
  workingDirectory: './workspace',
  env: process.env,
})
```

## 本機作業系統沙箱 {/* #native-os-sandboxing */}

`LocalSandbox`支援本機作業系統級沙箱以提高安全性：

* **macOS**：使用安全帶（`sandbox-exec`) for filesystem and network isolation
* **Linux**：使用氣泡膜（`bwrap`) for namespace isolation

```typescript
// Detect the best available backend for this platform
const detection = LocalSandbox.detectIsolation()
console.log(detection)
// { backend: 'seatbelt', available: true, message: '...' }

// Enable native sandboxing
const sandbox = new LocalSandbox({
  workingDirectory: './workspace',
  isolation: 'seatbelt', // or 'bwrap' on Linux
  nativeSandbox: {
    allowNetwork: false, // Block network access (default)
    readWritePaths: ['/tmp/extra'], // Additional writable paths
  },
})
```

啟用隔離時：

* 檔案寫入僅限於Workspace目錄，`readWritePaths`, and temporary locations. On macOS (seatbelt), writes are also allowed under `/private/tmp`, `/var/folders`, and `/private/var/folders`. On Linux (bubblewrap), `/tmp` is a private in-sandbox tmpfs that isn't written to the host.
* 文件讀取取決於後端。在 macOS（安全帶）上，任何地方都允許讀取（系統二進位檔案需要）。在 Linux (bubbblewrap) 上，產生的策略僅公開選定的系統路徑（例如`/usr`, `/lib`, `/bin`, and essential `/etc` files), `readOnlyPaths`, `readWritePaths`, and the workspace. When `allowSystemBinaries` isn't `false`, the Node.js directory, `/opt`, and `/snap` are also visible. Other host paths aren't accessible. If you set `bwrapArgs`, it replaces the generated policy, so your arguments alone determine what's visible.
* 預設阻止網路訪問
* 進程隔離防止影響主機系統

### 沙箱設定檔位置 {/* #sandbox-profile-location */}

在 macOS 上使用安全帶隔離時，`LocalSandbox` generates a profile file in a `.sandbox-profiles/` folder in `process.cwd()`, separate from the working directory:

```text
project/
├── .sandbox/                      # Default working directory (sandboxed)
│   └── ... files created by sandbox
├── .sandbox-profiles/             # Seatbelt profiles (outside sandbox)
│   └── seatbelt-a1b2c3d4.sb       # Hash based on workspace + config
└── ... your project files
```

配置檔案名稱是工作空間路徑和配置的哈希值，因此具有相同設定的沙箱共享相同的配置文件，而不同的配置則獲得單獨的文件。這可以防止同時運行多個沙箱時發生衝突。

這種分離可以防止Sandbox進程讀取或修改自己的安全設定檔。設定檔在沙箱啟動時創建，並在銷毀時清除。
