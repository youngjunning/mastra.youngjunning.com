# PlatformFilesystem

將檔案儲存在 Mastra Platform 的 Workspace 儲存桶中。每個 Mastra Platform 環境可以有一個儲存桶；`PlatformFilesystem` 為 Agent 提供對該儲存桶的 `read`、`write`、`list`、`delete` 和 `move` 操作。

相關 Provider：[`S3Filesystem`](/integrations/file-storage/amazon-s3) 用於直接存取 S3，[`LocalFilesystem`](/reference/workspace/local-filesystem) 用於存取本機目錄。

:::note

介面詳情請參閱 [WorkspaceFilesystem 介面](/reference/workspace/filesystem)。

:::

## 安裝 {/* #installation */}

```bash npm2yarn
npm install @mastra/platform-workspace
```

設定平台憑證。存取令牌、項目 ID 和儲存桶名稱預設從環境變數讀取，因此在 Mastra Platform 部署中呼叫建構函式時可以不傳入任何選項。

<Tabs>
  <TabItem value="env-file" label=".env 檔案">
    ```bash

    MASTRA_PROJECT_ID=your-project-id
    MASTRA_PLATFORM_BUCKET_NAME=your-bucket-name
    ```
  </TabItem>

  <TabItem value="constructor" label="建構函式">
    ```typescript
    new PlatformFilesystem({
      accessToken: 'your-platform-access-token',
      projectId: 'your-project-id',
      bucketName: 'your-bucket-name',
    })
    ```
  </TabItem>
</Tabs>

在 Mastra Platform 部署中，系統會自動注入 `MASTRA_PLATFORM_ACCESS_TOKEN`、`MASTRA_PROJECT_ID` 和 `MASTRA_PLATFORM_BUCKET_NAME`，因此呼叫建構函式時毋須傳入選項。在本機開發時，`MASTRA_PLATFORM_ACCESS_TOKEN` 可以使用機構設定頁面 **API Tokens** 下以 `sk_` 開頭的 API 令牌。

## 用法 {/* #usage */}

將 `PlatformFilesystem` 加入 Workspace，並將該 Workspace 指派給 Agent：

```typescript
import { Agent } from '@mastra/core/agent'
import { Workspace } from '@mastra/core/workspace'
import { PlatformFilesystem } from '@mastra/platform-workspace'

const workspace = new Workspace({
  filesystem: new PlatformFilesystem({
    // accessToken, projectId, bucketName all fall back to env vars
  }),
})

const agent = new Agent({
  id: 'file-agent',
  name: 'File Agent',
  instructions: 'You are a research assistant that reads and writes reports.',
  model: '__GATEWAY_ANTHROPIC_MODEL_SONNET__',
  workspace,
})
```

### 讀取和寫入檔案 {/* #reading-and-writing-files */}

物件鍵的每個路徑部分都會進行百分比編碼，因此檔案名稱中的 `?`、`#`、`%`、`&`、`+` 和空格在整個讀寫過程中都能保留：

```typescript
const fs = new PlatformFilesystem()

await fs.writeFile('/analyses/repo.md', markdown)
const content = await fs.readFile('/analyses/repo.md')
const entries = await fs.readdir('/analyses')
await fs.moveFile('/analyses/repo.md', '/analyses/repo-final.md')
```

### 唯讀模式 {/* #read-only-mode */}

傳入 `readOnly: true` 可將儲存桶以唯讀方式掛載。任何修改操作都會拋出 `WorkspaceReadOnlyError`：

```typescript
const fs = new PlatformFilesystem({ readOnly: true })

await fs.readFile('/analyses/repo.md') // ok
await fs.writeFile('/analyses/repo.md', 'x') // throws WorkspaceReadOnlyError
```

### 覆蓋語義 {/* #overwrite-semantics */}

`writeFile` 支援 `overwrite: false`；如果目標已存在，就會拋出 `FileExistsError`。

`copyFile` 和 `moveFile` 一律會覆寫目標。向任何一個方法傳入 `overwrite: false` 會拋出錯誤，而不會直接覆寫。

### 追加文件 {/* #appending-files */}

`appendFile` 採用讀取、修改、寫入的過程，並非不可分割的操作。同時向同一路徑追加內容可能互相覆寫。需要同時寫入時，請使用 `writeFile` 寫入不同的鍵。

## 錯誤 {/* #errors */}

檔案系統專屬錯誤與標準 Workspace 錯誤類型一致：

* `FileNotFoundError`：路徑不存在。由 `readFile`、`stat` 和 `deleteFile` 拋出（設定 `force: true` 時除外）。
* `FileExistsError`：呼叫 `writeFile` 時傳入了 `overwrite: false`，而目標已存在。
* `WorkspaceReadOnlyError`：對唯讀檔案系統執行了修改操作。

其他 Platform API 錯誤會拋出 `PlatformApiError`。結構為 `{ error: { message, type } }` 的回應會解析為 `.code`（供程式讀取的錯誤類型）和 `.proxyMessage`（供人閱讀的錯誤訊息）：

```typescript
import { FileNotFoundError } from '@mastra/core/workspace'
import { PlatformApiError } from '@mastra/platform-workspace'

try {
  await fs.readFile('/missing.txt')
} catch (err) {
  if (err instanceof FileNotFoundError) {
    // handle missing file
  } else if (err instanceof PlatformApiError) {
    if (err.code === 'authentication_error') {
      // refresh token
    }
    console.error(err.status, err.code, err.proxyMessage)
  }
}
```

`FileNotFoundError`、`FileExistsError` 和 `WorkspaceReadOnlyError` 是從 `@mastra/core/workspace` 重新匯出的標準 Workspace 錯誤類型。`PlatformApiError` 則是 `@mastra/platform-workspace` 專屬的錯誤類型。

如果回應內容不是 JSON，例如負載平衡器傳回的 HTML 502 頁面，`code` 和 `proxyMessage` 都是 `undefined`。
