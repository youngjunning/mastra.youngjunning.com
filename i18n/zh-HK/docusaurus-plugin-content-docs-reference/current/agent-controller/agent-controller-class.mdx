# AgentController

`AgentController` 類為一個或多個 [`Session`](/reference/agent-controller/session) 實例提供共享宿主。先初始化 Controller 並建立 Session，再通過 `session.*` API 管理對話狀態和執行控制。

入門介紹請參閱 [AgentController 概覽](/docs/harness/agent-controller)。

## 使用範例 {/* #usage-example */}

以下範例初始化 Controller 並建立 Session，在傳送訊息前訂閱 Session 事件。

```typescript title="src/mastra/agent-controller.ts"
import { Agent } from '@mastra/core/agent'
import { AgentController } from '@mastra/core/agent-controller'
import { Workspace } from '@mastra/core/workspace'

const agent = new Agent({
  id: 'coding-agent',
  name: 'Coding agent',
  instructions: 'Help with software engineering tasks.',
  model: '__GATEWAY_ANTHROPIC_MODEL_SONNET__',
})

const controller = new AgentController({
  id: 'coding-controller',
  agent,
  workspace: new Workspace({ id: 'coding-workspace' }),
  modes: [{ id: 'build', name: 'Build', metadata: { default: true } }],
})

await controller.init()

const session = await controller.createSession({ resourceId: 'project-42' })
const unsubscribe = session.subscribe(event => {
  if (event.type === 'message_update' && event.event.type === 'text-delta') {
    process.stdout.write(event.event.delta)
  }
})

await session.sendMessage({ content: 'Review the project structure.' })
unsubscribe()
```

訊息生命週期始於 `message_start` 中的初始訊息。簡潔的 `message_update` 事件通過 ID 定位訊息，並攜帶文本、推理內容或訊息部分的變化。`message_end` 攜帶 ID，表示訊息結束。

## 方法 {/* #methods */}

### Session {/* #sessions */}

#### `createSession(options)` {/* #createsessionoptions */}

獲取或建立以 `id` 註冊的實時 Session。呼叫此方法前須先呼叫 `init()`。

```typescript
const session = await controller.createSession({
  id: 'run-a',
  resourceId: 'project-42',
  threadId: 'thread-7',
})
```

相同的 `id` 會返回同一個 `Session` 實例。即使共用 `resourceId`，不同 ID 的 Session 仍彼此獨立：各自擁有執行循環、對話串綁定、模式、模型和狀態，但其已儲存的對話串與資源級 Memory 屬於同一資源。省略 `id` 時預設使用 `resourceId`，因此每個資源只需一個 Session 時無需指定 ID。傳入 `threadId` 時，此方法會將已緩存的 Session 切換到該對話串；若對話串不存在則建立它。

#### `getSession(sessionId, requestContext?)` {/* #getsessionsessionid-requestcontext */}

返回以 `sessionId` 註冊的實時 Session；如果目前沒有對應的實時 Session，則返回 `undefined`。

```typescript
const session = await controller.getSession('run-a')
```

返回：`Promise<Session<TState> | undefined>`

#### `onSessionCreated(listener, options?)` {/* #onsessioncreatedlistener-options */}

在 `createSession()` 建立新的實時 Session 後訂閱目前進程內的通知。某個監聽器拋出的錯誤不會影響其他監聽器。呼叫返回的函數可取消訂閱。

預設情況下，監聽器採即發即忘方式執行。傳入 `{ blocking: true }` 後，`createSession()` 會等待監聽器完成才返回新 Session，讓宿主可在調用方啟動執行前準備 Session 狀態。阻塞式監聽器按註冊順序逐一執行，之後才通知非阻塞式監聽器。阻塞式監聽器不得調用 `createSession()` 來建立具有相同 `id` 的 Session，否則會等待自身初始化完成而導致死結。

```typescript
const unsubscribe = controller.onSessionCreated(
  async session => {
    const settings = await loadSettings(session.identity.getResourceId())
    if (settings) await session.state.set(settings)
  },
  { blocking: true },
)

// Default listeners stay fire-and-forget.
controller.onSessionCreated(session => {
  console.log(`Created ${session.identity.getResourceId()}`)
})
```

監聽器只在每個新建立的 Session 上執行一次；以後呼叫 `createSession()` 返回緩存 Session 時不會再次執行。通知僅發生在目前程序中，不會作為事件持久化。

返回：`() => void`

#### `onSessionDeleted(listener)` {/* #onsessiondeletedlistener */}

在 `deleteSession()` 拆除實時 Session 後訂閱目前進程內的通知。某個監聽器拋出的錯誤不會影響其他監聽器。呼叫返回的函數可取消訂閱。

```typescript
const unsubscribe = controller.onSessionDeleted(session => {
  console.log(`Closed ${session.identity.getResourceId()}`)
})

await controller.createSession({ resourceId: 'project-42' })
await controller.deleteSession({ sessionId: 'project-42' })
unsubscribe()
```

此監聽器只在目前程序中盡力執行，不屬於持久化的刪除事件。

返回：`() => void`

#### `deleteSession({ sessionId })` {/* #deletesession-sessionid- */}

拆除以 `sessionId` 註冊的實時 Session。此方法先中止活動任務，再移除對話串訂閱、活動對話串鎖及 Controller 註冊表中的實時 Session；不會刪除已持久化的對話串或訊息。

```typescript
const deleted = await controller.deleteSession({ sessionId: 'run-a' })
```

返回：`Promise<boolean>`。移除了實時 Session 時為 `true`；沒有匹配的實時 Session，或同一 Session 的另一次刪除正在進行時為 `false`。

#### `setResourceId(session, { resourceId })` {/* #setresourceidsession--resourceid- */}

將實時 Session 移至另一資源，並清除其活動對話串綁定。Session 仍以原 ID 註冊。

```typescript
await controller.setResourceId(session, { resourceId: 'project-43' })
```

#### `getKnownResourceIds(session)` {/* #getknownresourceidssession */}

列出已儲存對話串中出現過的資源識別碼。

```typescript
const resourceIds = await controller.getKnownResourceIds(session)
```

返回：`Promise<string[]>`

#### `listActiveThreadRuns()` {/* #listactivethreadruns */}

列出此 Controller 中跨所有資源和對話串正在執行的執行。列表來自進程內執行跟蹤，因此只涵蓋目前程序啟動的執行，不會建立或存取 Session。

```typescript
const runs = controller.listActiveThreadRuns()
```

返回：`ActiveThreadRun[]`

```typescript
interface ActiveThreadRun {
  runId: string
  resourceId?: string
  threadId: string
}
```

### 儲存查詢 {/* #storage-queries */}

這些方法無需建立 Session 或設定其 Workspace，即可讀取已儲存的對話串和訊息。

#### `queryThreadById({ threadId })` {/* #querythreadbyid-threadid- */}

返回一個已儲存對話串；對話串或儲存不存在時返回 `null`。

```typescript
const thread = await controller.queryThreadById({ threadId: 'thread-7' })
```

返回：`Promise<AgentControllerThread | null>`

#### `queryThreads(options)` {/* #querythreadsoptions */}

列出已儲存的對話串。`resourceId` 和 `metadata` 用於篩選結果。除非 `includeForkedSubagents` 為 `true`，否則不包含派生的子 Agent 對話串。

```typescript
const threads = await controller.queryThreads({
  resourceId: 'project-42',
  includeForkedSubagents: false,
  metadata: { repository: 'mastra' },
})
```

所有選項都是可選的。返回：`Promise<AgentControllerThread[]>`

#### `queryThreadMessages(options)` {/* #querythreadmessagesoptions */}

根據 `StorageListMessagesInput` 的分頁、排序、包含和篩選選項，列出某個對話串中已儲存的訊息。必須提供 `threadId`。預設按 `createdAt` 從新到舊排序；省略 `perPage` 時，每頁由儲存層返回 40 條訊息。

```typescript
const result = await controller.queryThreadMessages({
  threadId: 'thread-7',
  page: 0,
  perPage: 20,
  orderBy: { field: 'createdAt', direction: 'DESC' },
})
```

返回：`Promise<StorageListMessagesOutput>`，其中包含 Controller 格式的訊息。

#### `generateThreadTitle(options)` {/* #generatethreadtitleoptions */}

無需建立 Session，即可根據對話串對話生成並儲存標題。`threadId` 必填；可選欄位包括 `sessionId`、`model` 和 `requestContext`。傳入 `sessionId` 時會借用實時 Session 的 Agent 和請求脈絡。對話串不存在時會拋出錯誤；模型未生成標題時返回 `undefined`。

```typescript
const title = await controller.generateThreadTitle({
  threadId: 'thread-7',
  sessionId: 'run-a',
})
```

返回：`Promise<string | undefined>`

### 生命週期 {/* #lifecycle */}

#### `init()` {/* #init */}

初始化共享儲存，將執行時服務傳給 Agent，並啟動已設定的週期性處理器。設定的 Workspace 會在使用時按需初始化。重複呼叫會復用同一個初始化 Promise。

```typescript
await controller.init()
```

#### `initStorage()` {/* #initstorage */}

只初始化 Controller 的儲存層，不設定 Workspace，也不啟動完整的 Controller 執行時。此方法可重複呼叫，供直接查詢儲存時使用。

```typescript
await controller.initStorage()
```

返回：`Promise<void>`

#### `destroy()` {/* #destroy */}

停止由 Controller 管理的週期性處理器，但不會銷毀其建立的 Session。

```typescript
await controller.destroy()
```

### 模式及 Agent {/* #modes-and-agents */}

#### `listModes()` {/* #listmodes */}

傳回設定的模式定義。

```typescript
const modes = controller.listModes()
```

返回：`AgentControllerMode[]`

#### `getDefaultMode()` {/* #getdefaultmode */}

返回 Controller 啟動時使用的模式。構造函數依次選擇：與 `defaultModeId` 匹配的模式；首個標記為 `default: true` 或 `metadata.default: true` 的模式；首個已設定模式。如果 `defaultModeId` 沒有匹配項，構造函數會拋出錯誤。

```typescript
const mode = controller.getDefaultMode()
```

返回：`AgentControllerMode`

#### `getCurrentAgent(session)` {/* #getcurrentagentsession */}

返回 Session 目前活動模式對應的底層 Agent。

```typescript
const agent = controller.getCurrentAgent(session)
```

返回：`Agent`

### Workspace 及 Browser {/* #workspace-and-browser */}

#### `hasWorkspace()` {/* #hasworkspace */}

報告 Controller 是否設定了靜態、動態或對象形式的 Workspace。

```typescript
if (controller.hasWorkspace()) {
  console.log('Workspace configured')
}
```

返回：`boolean`

#### `isWorkspaceReady()` {/* #isworkspaceready */}

報告 Controller 級 Workspace 是否已就緒。

```typescript
const ready = controller.isWorkspaceReady()
```

返回：`boolean`

#### `getWorkspace()` {/* #getworkspace */}

返回 Controller 的靜態 Workspace。動態 Workspace 工廠按 Session 解析，因此此處返回 `undefined`；請改用 `resolveWorkspace`。

```typescript
const workspace = controller.getWorkspace()
```

返回：`Workspace | undefined`

#### `resolveWorkspace({ session, requestContext? })` {/* #resolveworkspace-session-requestcontext- */}

返回 Session 執行時使用的 Workspace。Session 建立時便會解析自己的 Workspace，包括動態工廠，因此通常返回該實例；僅在未建立 Session 時才回退到工廠。

```typescript
const workspace = await controller.resolveWorkspace({ session, requestContext })
```

返回：`Promise<Workspace | undefined>`

#### `setBrowser(browser)` {/* #setbrowserbrowser */}

替換 Controller 的 Browser，並將其傳給底層 Agent。

```typescript
controller.setBrowser(browser)
```

const mastra = controller.getMastra()

### 模型 {/* #models */}

#### `getCurrentModelAuthStatus(session)` {/* #getcurrentmodelauthstatussession */}

返回 Session 所選模型的身份驗證狀態。

```typescript
const status = await controller.getCurrentModelAuthStatus(session)
```

返回：`Promise<ModelAuthStatus>`

#### `listAvailableModels()` {/* #listavailablemodels */}

列出已設定網關及內建網關提供的模型。若設定了使用次數提供者，每個模型的 `useCount` 由 `modelUseCountProvider` 提供。

內置網關會下載公開模型目錄（models.dev 和 Netlify）。只有尚未下載任何目錄時，呼叫才會等待下載；之後會返回上次下載的目錄，即使新下載失敗也是如此。目錄超過 5 分鐘後，下次呼叫會在後台重新下載，不會等待。設定的網關和 API Key 可用性每 10 秒重新檢查。

```typescript
const models = await controller.listAvailableModels()
```

返回：`Promise<AvailableModel[]>`

#### `invalidateAvailableModelsCache()` {/* #invalidateavailablemodelscache */}

讓下一次 `listAvailableModels()` 呼叫重新檢查設定的網關和 API Key 可用性，並在後台重新下載 models.dev 與 Netlify 的目錄。應用保存或移除憑據、或更改自定義 Provider 後應呼叫此方法。

```typescript
controller.invalidateAvailableModelsCache()
```

### 定期處理器 {/* #intervals */}

#### `registerInterval(handler)` {/* #registerintervalhandler */}

啟動或替換一個週期性處理器。

```typescript
controller.registerInterval({
  id: 'refresh',
  intervalMs: 60_000,
  handler: async () => refreshData(),
})
```

#### `removeInterval({ id })` {/* #removeinterval-id- */}

停止指定的週期性處理器，並執行其可選的關閉回調。

```typescript
await controller.removeInterval({ id: 'refresh' })
```

#### `stopIntervals()` {/* #stopintervals */}

停止所有週期性處理器，並執行各自可選的關閉回調。

```typescript
await controller.stopIntervals()
```
