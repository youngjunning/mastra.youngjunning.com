# 會議

一個`Session`是在一個會話 ID 下註冊的隔離運行時。多個會話可以共享一個資源，該資源擁有其儲存的執行緒和資源範圍的記憶體。它擁有其事件總線、線程綁定、狀態、模式和模型選擇、運行控制、批准、暫停、後續和顯示狀態。這[`AgentController`](/reference/agent-controller/agent-controller-class)提供共用Agent、配置、儲存、Workspace和服務。

透過創建會話`controller.createSession()`. Direct construction and controller wiring methods aren't application APIs.

有關概念性介紹，請參閱[AgentController overview](/docs/harness/agent-controller).

## 使用範例 {/* #usage-example */}

以下範例使用受支援的控制器到會話流。

```typescript
await controller.init()

const session = await controller.createSession({ resourceId: 'project-42' })
const unsubscribe = session.subscribe(event => {
  if (event.type === 'display_state_changed') {
    render(event.displayState)
  }
})

await session.sendMessage({ content: 'Review the current project.' })
unsubscribe()
```

## 方法 {/* #methods */}

### 身份和事件 {/* #identity-and-events */}

#### `getTags()` {/* #gettags */}

傳回建立會話時提供的標籤的副本。

```typescript
const tags = session.getTags()
```

返回：`Record<string, string>`

#### `subscribe(listener)` {/* #subscribelistener */}

訂閱此會話的隔離事件總線。此方法傳回一個取消訂閱函數。

```typescript
const unsubscribe = session.subscribe(event => {
  console.log(event.type)
})

unsubscribe()
```

返回：`() => void`

### 訊息和運行控制 {/* #messages-and-run-control */}

#### `sendMessage({ content, files?, requestContext?, author? })` {/* #sendmessage-content-files-requestcontext-author- */}

發送用戶訊息。當沒有執行緒處於活動狀態時，會話首先建立一個執行緒。經過`author` when the host has authenticated the sender.

```typescript
await session.sendMessage({
  content: 'Summarize this file.',
  files: [{ data: fileContents, mediaType: 'text/plain', filename: 'notes.txt' }],
  author: { id: 'user-123' },
})
```

作者堅持下`content.metadata.signal.author`. Read it with `getMessageAuthor(message)` from `@mastra/core/agent`. When `requestContext` carries `MASTRA_MESSAGE_AUTHOR_KEY`, the session uses that value if `author` is omitted. See [Reserved keys](/docs/server/request-context#reserved-keys).

#### `queueMessage({ content, files?, requestContext?, author? })` {/* #queuemessage-content-files-requestcontext-author- */}

將訊息排隊以供下次運行，或在會話空閒時立即發送。作者元資料與排隊的訊息一起保留。

#### `queueSignal(signal, { requestContext?, tracingContext?, tracingOptions? }?)` {/* #queuesignalsignal--requestcontext-tracingcontext-tracingoptions- */}

將鍵入的訊號排隊以供下次運行，或在會話空閒時立即發送。訊號保持不變`type`, `tagName`, and `attributes`. Set `signal.author` to record an author, because the session doesn't stamp one from `requestContext` as it does for `queueMessage()`.

```typescript
await session.queueSignal({
  type: 'reactive',
  tagName: 'skill',
  attributes: { name: 'triage' },
  contents: 'Triage the new issue.',
})
```

#### `steer({ content, files?, requestContext?, author? })` {/* #steer-content-files-requestcontext-author- */}

`content` as a new message. Pass `files` to attach files in the same shape as `sendMessage()`: `{ data, mediaType, filename? }`, where `data` is raw text or a base64 data URL for text files, and base64 for binary files.

```typescript
await session.steer({ content: 'Focus on the failing tests.' })
```

#### `followUp({ content, files?, requestContext? })` {/* #followup-content-files-requestcontext- */}

在運行處於活動狀態時對後續操作進行排隊，或在空閒時立即發送它。經過`files` to attach files the same way as `steer()`.

```typescript
await session.followUp({
  content: 'Then compare against this screenshot.',
  files: [{ data: screenshotBase64, mediaType: 'image/png', filename: 'expected.png' }],
})
```

#### `getCurrentRunId()` {/* #getcurrentrunid */}

`null` while idle.

```typescript
const runId = session.getCurrentRunId()
```

返回：`string | null`

#### `abort()` {/* #abort */}

中止活動運作並清除掛起的暫停顯示狀態。

```typescript
session.abort()
```

### 工作空間 {/* #workspace */}

#### `getWorkspace()` {/* #getworkspace */}

傳回為此會話解析的Workspace。這保留了會話級覆蓋。

Workspace是可選的。當會話和`AgentController` configures one, the session still runs without filesystem or sandbox access, and this returns `undefined`. Check the result before using it.

```typescript
const workspace = session.getWorkspace()
const skill = await workspace?.skills?.get('code-review')
```

返回：`Workspace | undefined`

### 會議補助金 {/* #session-grants */}

會話範圍授予自動批准Tool而無需提示。授權是短暫的：它們會在會話重新啟動時重置並且永遠不會保留。

#### `grantCategory(category)` {/* #grantcategorycategory */}

為目前會話授予Tool類別。此類別中的Tool是自動批准的。

```typescript
session.grantCategory('edit')
```

#### `grantTool(toolName)` {/* #granttooltoolname */}

為目前會話授予特定Tool。

```typescript
session.grantTool('mastra_workspace_execute_command')
```

#### `getGrants()` {/* #getgrants */}

傳回目前授予的類別和Tool。

```typescript
const grants = session.getGrants()
// { categories: string[], tools: string[] }
```

#### `hasCategoryGrant(category)` {/* #hascategorygrantcategory */}

傳回類別是否具有記憶體中會話授權。

```typescript
const allowed = session.hasCategoryGrant('edit')
```

返回：`boolean`

#### `hasToolGrant(toolName)` {/* #hastoolgranttoolname */}

傳回Tool是否具有記憶體中會話授權。

```typescript
const allowed = session.hasToolGrant('write_file')
```

返回：`boolean`

### Tool批准 {/* #tool-approvals */}

#### `resolveToolApproval(toolName, scope?)` {/* #resolvetoolapprovaltoolname-scope */}

應用顯式Tool規則、會話授權和類別規則後傳回有效策略。

規則屬於每個線程。透過跑步`RequestContext` as `scope` to use the rules and grants of the thread that run belongs to. A thread ID as `scope` checks that thread's grants against the current thread's rules. Without `scope`, the current thread is used.

```typescript
const policy = session.resolveToolApproval('execute_command')
const policyForRun = session.resolveToolApproval('write_file', requestContext)
```

返回：`PermissionPolicy`

#### `respondToToolApproval({ decision, toolCallId, requestContext?, declineContext? })` {/* #respondtotoolapproval-decision-toolcallid-requestcontext-declinecontext- */}

回應由以下人員提出的待處理Tool批准請求`tool_approval_required` event. `toolCallId` is required and identifies the parked call, so pass the `toolCallId` from the event. Pass `always_allow_category` to also grant the tool's whole category for the gate's thread.

```typescript
session.respondToToolApproval({ decision: 'approve', toolCallId: event.toolCallId })
session.respondToToolApproval({ decision: 'decline', toolCallId: event.toolCallId })
session.respondToToolApproval({ decision: 'always_allow_category', toolCallId: event.toolCallId })
```

#### `respondToToolSuspension({ resumeData, address?, toolCallId?, requestContext? })` {/* #respondtotoolsuspension-resumedata-address-toolcallid-requestcontext- */}

使用應用程式提供的資料恢復暫停的Tool。供應`toolCallId` for a prompt on the active thread. To resume after switching threads, retain the full `address` returned by `session.claimToolSuspension(toolCallId, runId)` and pass it instead of `toolCallId`.

尋址恢復使用來源執行緒的模式、模型和執行緒擁有的首選項，而不選擇該執行緒或取代活動執行緒的訂閱。即使您在執行期間切換線程，Tool狀態回呼仍然綁定到來源。主機擁有的自訂狀態和權限規則保持共用。

進程重新啟動後，完整位址可以透過控制器配置的Agent程式恢復持久掛起。恢復需要唯一識別的始發Agent和現有的恢復授權檢查。設定失敗會使提示可以重試，而無需完成另一個執行緒的活動運行。

```typescript
await session.respondToToolSuspension({
  toolCallId: event.toolCallId,
  resumeData: ['src'],
})
```

為了`submit_plan`, pass `{ action: 'approved' }` or `{ action: 'rejected', feedback }`. Approval can switch to the mode configured by `transitionsTo` before the tool resumes.

### 代幣使用 {/* #token-usage */}

#### `getTokenUsage()` {/* #gettokenusage */}

傳回活動執行緒的運行令牌使用計數的副本。

每個步驟完成時，執行運行都會將令牌使用情況儲存到自己的執行緒中，包括在選擇另一個執行緒時復原的執行。如果儲存作業失敗，執行擁有者將保留測量的使用情況並重試下一步。僅訂閱執行緒的會話會顯示其儲存的總數，而不會再次計算重播的步驟或儲存使用情況。

```typescript
const usage = session.getTokenUsage()
// { promptTokens, completionTokens, totalTokens, ... }
```

## 身分 {/* #identity */}

`session.identity`識別進程本機會話主機：資源 ID 和會話`id`, plus an `ownerId`. The `id` and `ownerId` are stable for the life of the host and don't change when the resource ID is switched. AgentController doesn't persist the live session or mirror these values to a `SessionRecord`.

### `session.identity.getId()` {/* #sessionidentitygetid */}

傳回穩定的會話標識符。

```typescript
const sessionId = session.identity.getId()
```

### `session.identity.getOwnerId()` {/* #sessionidentitygetownerid */}

傳回進程本機會話主機的穩定擁有者識別碼。該值不是持久線程所有者。

```typescript
const ownerId = session.identity.getOwnerId()
```

### `session.identity.getResourceId()` {/* #sessionidentitygetresourceid */}

返回目前資源 ID。

```typescript
const resourceId = session.identity.getResourceId()
```

### `session.identity.getDefaultResourceId()` {/* #sessionidentitygetdefaultresourceid */}

傳回建立會話所使用的資源 ID。

```typescript
const defaultResourceId = session.identity.getDefaultResourceId()
```

若要變更資源 ID，請使用[`controller.setResourceId()`](/reference/agent-controller/agent-controller-class#setresourceidsession--resourceid-), which also clears the active thread. The session `id` and `ownerId` aren't affected by resource switches.

## 線 {/* #thread */}

`session.thread`擁有活動執行緒綁定和資源範圍的執行緒操作。配置儲存後，儲存的線程和訊息可以在控制器重新建立後繼續存在。當會話建立或切換執行緒時，會話設定（例如模式、模型、思維層級、令牌使用、掛起運行和所有權）將從活動執行緒中恢復。即時會話及其事件匯流排不會持續存在。

新線程存儲會話主機的`ownerId` in the reserved `metadata.ownerId` and `metadata.createdBy` fields. Clones use the cloning Session host for both fields. Existing threads without `metadata.ownerId` read as owned by the current Session host without writing a backfill.

### `session.thread.create({ title?, id?, requestContext? })` {/* #sessionthreadcreate-title-id-requestcontext- */}

创建一个线程，将会话绑定到它，然后打开其事件流。經過`requestContext` when memory is a function that reads the signed-in user.

對於使用以下命令建立的會話`createInitialThread: false`, explicit mode, model, and thread-preference selections made before its first binding seed the first new thread. This also applies to `ensureId()` and the first message. Failed creation leaves those selections available for retry.

會話綁定對話後，每個新執行緒都會使用控制器預設值而不是前一個對話的選擇，即使您清除或刪除綁定也是如此。開啟現有執行緒會恢復該執行緒的設置，而不是套用未綁定的啟動選擇。

```typescript
const thread = await session.thread.create({
  id: 'thread-7',
  title: 'Investigate login failure',
})
```

返回：`Promise<AgentControllerThread>`

### `session.thread.rename({ title })` {/* #sessionthreadrename-title- */}

重命名活動的儲存線程。

```typescript
await session.thread.rename({ title: 'Fix login failure' })
```

### `session.thread.clone({ sourceThreadId?, title?, resourceId?, requestContext? })` {/* #sessionthreadclone-sourcethreadid-title-resourceid-requestcontext- */}

克隆擁有的線程及其訊息，然後將會話綁定到克隆。經過`requestContext` when memory is a function that reads the signed-in user.

```typescript
const clone = await session.thread.clone({
  sourceThreadId: 'thread-7',
  title: 'Alternative approach',
})
```

返回：`Promise<AgentControllerThread>`

### `session.thread.switch({ threadId, emitEvent?, requestContext? })` {/* #sessionthreadswitch-threadid-emitevent-requestcontext- */}

切換到擁有的儲存線程並水合其模式、模型和觀察記憶體設定。經過`requestContext` when memory is a function that reads the signed-in user.

仅当此会话启动时，切换离开才会取消正在运行的本地执行。侦听另一个会话运行的会话会分离，但不会取消该运行。这遵循当前操作的发起者，而不是线程的所有权。停放的Tool提示仍可用於稍後恢復。

```typescript
await session.thread.switch({ threadId: 'thread-8' })
```

### `session.thread.delete({ threadId, requestContext? })` {/* #sessionthreaddelete-threadid-requestcontext- */}

刪除擁有的線程。刪除活動執行緒也會清除目前綁定。經過`requestContext` when memory is a function that reads the signed-in user.

```typescript
await session.thread.delete({ threadId: 'thread-8' })
```

### `session.thread.getId()` {/* #sessionthreadgetid */}

返回活動線程 ID，或者`null` when no thread is bound.

```typescript
const threadId = session.thread.getId()
```

### `session.thread.ensureId({ requestContext? })` {/* #sessionthreadensureid-requestcontext- */}

傳回活動線程 ID，當沒有綁定時建立並綁定一個新線程。並發呼叫共享一個執行緒。將其與使用以下命令建立的會話一起使用`createInitialThread: false`.

```typescript
const threadId = await session.thread.ensureId()
```

### `session.thread.getOwner({ threadId? })` {/* #sessionthreadgetowner-threadid- */}

返回線程的持久所有者。忽略`threadId` to read the active thread. The method returns `undefined` when no thread is selected. An owner-less legacy thread returns the Session host's `ownerId` without writing a backfill.

```typescript
const ownerId = await session.thread.getOwner()
```

返回：`Promise<string | undefined>`

### `session.thread.transferOwnership({ toOwnerId, threadId? })` {/* #sessionthreadtransferownership-toownerid-threadid- */}

店鋪`toOwnerId` in the thread's `metadata.ownerId` and emit `thread_owner_changed`. The original `metadata.createdBy` value doesn't change. Without `threadId`, this transfers the active thread. With `threadId`, it transfers that thread of the session's resource and the active thread stays the same.

```typescript
await session.thread.transferOwnership({
  toOwnerId: 'user-456',
  threadId: 'thread-123',
})
```

返回：`Promise<void>`

傳輸在一個進程內串行進行。需要持久的跨進程比較和設定的儲存支援的應用程式應首先在自己的儲存中執行它，然後呼叫此方法來鏡像結果。

成功的更改會發出：

```typescript
const event = {
  type: 'thread_owner_changed',
  threadId: 'thread-7',
  fromOwnerId: 'user-123',
  toOwnerId: 'user-456',
}
```

啟動時運行快照所有權。在AgentTool和動態運行時函數中，`AgentControllerRequestContext.threadOwnerId` remains unchanged for the run's lifetime. A transfer becomes visible on the next run. `AgentControllerRequestContext.session.ownerId` continues to identify the process-local Session host.

### `session.thread.list(options?)` {/* #sessionthreadlistoptions */}

列出儲存中的線程。預設情況下，僅傳回目前資源的線程，並且隱藏臨時分叉子Agent線程。

```typescript
const threads = await session.thread.list()
const allThreads = await session.thread.list({ allResources: true })
const everything = await session.thread.list({ includeForkedSubagents: true })
```

### `session.thread.getById({ threadId })` {/* #sessionthreadgetbyid-threadid- */}

按 ID 返回單一線程，或者`null` if it doesn't exist.

```typescript
const thread = await session.thread.getById({ threadId: 'thread-abc123' })
```

### `session.thread.listActiveMessages(options?)` {/* #sessionthreadlistactivemessagesoptions */}

檢索活動線程的訊息。當沒有綁定執行緒時傳回一個空數組。

```typescript
const messages = await session.thread.listActiveMessages({ limit: 50 })
```

### `session.thread.listMessages({ threadId, limit? })` {/* #sessionthreadlistmessages-threadid-limit- */}

檢索特定線程的訊息。

```typescript
const messages = await session.thread.listMessages({ threadId: 'thread-abc123' })
```

訊息讀取方法`listActiveMessages`, `listMessages`, and `firstUserMessage` return `MastraDBMessage` objects, while `firstUserMessages` returns a `Map<string, MastraDBMessage>` keyed by thread ID. Each message has a `role`, an `id`, a `createdAt`, and a `content` object with `content.format` and a `content.parts` array. Read text, reasoning, tool calls, and attachments from `content.parts`. Signals such as system reminders and notifications are returned as separate messages with `role: 'signal'`.

### `session.thread.firstUserMessage({ threadId })` {/* #sessionthreadfirstusermessage-threadid- */}

檢索線程的第一個用戶訊息，或者`null` if none.

```typescript
const firstMsg = await session.thread.firstUserMessage({
  threadId: 'thread-abc123',
})
```

### `session.thread.firstUserMessages({ threadIds })` {/* #sessionthreadfirstusermessages-threadids- */}

一次檢索多個執行緒的第一個使用者訊息，以映射形式傳回。

```typescript
const firstByThread = await session.thread.firstUserMessages({
  threadIds: ['thread-a', 'thread-b'],
})
```

### `session.thread.getSetting({ key })` {/* #sessionthreadgetsetting-key- */}

從活動線程元資料中讀取設定。

```typescript
const value = await session.thread.getSetting({ key: 'omThreshold' })
```

### `session.thread.setSetting({ key, value })` {/* #sessionthreadsetsetting-key-value- */}

將設定寫入活動線程元資料。

```typescript
await session.thread.setSetting({ key: 'omThreshold', value: 0.8 })
```

### `session.thread.deleteSetting({ key })` {/* #sessionthreaddeletesetting-key- */}

從活動線程元資料中刪除設定。

```typescript
await session.thread.deleteSetting({ key: 'omThreshold' })
```

## 模式 {/* #mode */}

`session.mode`擁有主動模式選擇。

### `session.mode.get()` {/* #sessionmodeget */}

返回活動模式 ID。

```typescript
const modeId = session.mode.get()
```

### `session.mode.resolve()` {/* #sessionmoderesolve */}

返回完整的`AgentControllerMode` object for the active mode, resolved against the controller's configured modes.

```typescript
const mode = session.mode.resolve()
```

### `session.mode.switch({ modeId })` {/* #sessionmodeswitch-modeid- */}

切換到另一種模式，在活動執行緒上保留該模式，然後發出`mode_changed`. The active model stays the same unless you switch it separately, which is necessary when your host assigns different models to different modes.

```typescript
await session.mode.switch({ modeId: 'build' })
```

## 模型 {/* #model */}

`session.model`擁有會話的單一活動模型選擇。

### `session.model.get()` {/* #sessionmodelget */}

返回活動模型 ID。

```typescript
const modelId = session.model.get()
```

### `session.model.displayName()` {/* #sessionmodeldisplayname */}

傳回活動模型 ID 的最後一段作為短顯示名稱。退貨`'unknown'` when no model is selected.

```typescript
const name = session.model.displayName()
```

### `session.model.hasSelection()` {/* #sessionmodelhasselection */}

檢查當前是否選擇了模型。

```typescript
if (session.model.hasSelection()) {
  // Ready to send messages
}
```

### `session.model.set({ modelId })` {/* #sessionmodelset-modelid- */}

在記憶體中設定活動模型，而不保留它、報告模型使用或發出`model_changed` event.

```typescript
session.model.set({ modelId: '__GATEWAY_ANTHROPIC_MODEL_SONNET__' })
```

### `session.model.switch(modelId, options?)` {/* #sessionmodelswitchmodelid-options */}

切換會話的活動模型。模型 ID 保留為線程的 ID`currentModelId` and restored with that thread. Reports the selection to the controller's `modelUseCountTracker` and emits a `model_changed` event.

經過`{ thinkingLevel }` as the second argument to switch and persist both values in one operation. The level must be `'off'`, `'low'`, `'medium'`, `'high'`, `'xhigh'`, or `'max'`, and the controller's state schema must accept it. Both live values are updated before events are emitted. Omitting the option preserves the existing thinking-level override. Every `model_changed` event includes the current `{ modelId, thinkingLevel }`, even when the thinking level is unchanged. The level is `undefined` when the session has no override.

```typescript
await session.model.switch('__GATEWAY_ANTHROPIC_MODEL_SONNET__', {
  thinkingLevel: 'high',
})
```

客戶端 SDK 公開了與以下相同的操作`session.switchModel(modelId, { thinkingLevel })`.

## 觀察記憶 {/* #observational-memory */}

觀察記憶模型選擇，依角色分組`session.om.observer` and `session.om.reflector`. Both roles expose the same methods. Selection intent and the effective concrete model ID are separate values.

### `session.om.observer.model()` / `session.om.reflector.model()` {/* #sessionomobservermodel--sessionomreflectormodel */}

傳回角色的配置模型。

```typescript
const observerModel = session.om.observer.model()
const reflectorModel = session.om.reflector.model()
```

返回：`'auto' | string | undefined`

`'auto'`遵循活動的主模型。任何其他字串都是顯式模型 ID。

### `session.om.observer.modelId()` / `session.om.reflector.modelId()` {/* #sessionomobservermodelid--sessionomreflectormodelid */}

傳回角色的有效具體模型 ID。對於自動選擇，控制器調用`omConfig.resolveAutoModelId` with the role, current main model ID, and read-only session state. If that resolver returns no model or throws, the role uses its concrete `omConfig` fallback.

```typescript
const observer = session.om.observer.modelId()
const reflector = session.om.reflector.modelId()
```

### `session.om.observer.threshold()` / `session.om.reflector.threshold()` {/* #sessionomobserverthreshold--sessionomreflectorthreshold */}

傳回角色的令牌閾值（觀察者的觀察閾值，反射器的反射閾值），或者`undefined` when unset.

```typescript
const observationThreshold = session.om.observer.threshold()
const reflectionThreshold = session.om.reflector.threshold()
```

### `session.om.observer.switchModel({ modelId })` / `session.om.reflector.switchModel({ modelId })` {/* #sessionomobserverswitchmodel-modelid---sessionomreflectorswitchmodel-modelid- */}

在自動選擇和顯式選擇之間切換一種角色。經過`'auto'` to follow the active main model, or pass a concrete model ID to pin the role. Automatic selection clears the role's stale concrete model ID. The other role is unchanged. The emitted `om_model_changed` event continues to contain the effective concrete `modelId`.

```typescript
await session.om.observer.switchModel({ modelId: 'auto' })
await session.om.reflector.switchModel({
  modelId: '__GATEWAY_ANTHROPIC_MODEL_HAIKU__',
})
```

### `session.om.observer.resolvedModel()` / `session.om.reflector.resolvedModel()` {/* #sessionomobserverresolvedmodel--sessionomreflectorresolvedmodel */}

透過配置的模型閘道將角色的模型 ID 解析為模型實例，或者`undefined` when no model ID is set or no resolver is configured.

```typescript
const observerModel = session.om.observer.resolvedModel()
const reflectorModel = session.om.reflector.resolvedModel()
```

## 權限 {/* #permissions */}

`session.permissions`擁有代表的Tool批准策略`session.state`: the per-category and per-tool rules consulted during approval resolution. These are distinct from the in-memory grants documented under [Session grants](#session-grants). Grants reset with the live session. Permission rules aren't durable unless the host restores the corresponding session state.

### `session.permissions.getRules()` {/* #sessionpermissionsgetrules */}

傳回目前的權限規則，或空規則(`{ categories: {}, tools: {} }`) when none are set.

```typescript
const rules = session.permissions.getRules()
// { categories: { execute: 'ask' }, tools: { dangerous_tool: 'deny' } }
```

### `session.permissions.setForCategory({ category, policy })` {/* #sessionpermissionssetforcategory-category-policy- */}

設定審批政策（`'allow' | 'ask' | 'deny'`) for a tool category. Resolves once the change is persisted to session state.

```typescript
await session.permissions.setForCategory({ category: 'execute', policy: 'ask' })
```

### `session.permissions.setForTool({ toolName, policy })` {/* #sessionpermissionssetfortool-toolname-policy- */}

設定特定Tool的核准策略。每個Tool的策略優先於類別策略。一旦堅持就解決了。

```typescript
await session.permissions.setForTool({ toolName: 'dangerous_tool', policy: 'deny' })
```

## 子Agent {/* #subagents */}

`session.subagents`擁有子Agent配置。目前它公開了子Agent模型選擇`session.subagents.model`.

### `session.subagents.model.get({ agentType? })` {/* #sessionsubagentsmodelget-agenttype- */}

返回子Agent模型 ID，首選 per-`agentType` value when one is given, then the global subagent model, or `null` when neither is set.

```typescript
const modelId = session.subagents.model.get({ agentType: 'explore' })
```

### `session.subagents.model.set({ modelId, agentType? })` {/* #sessionsubagentsmodelset-modelid-agenttype- */}

設定子Agent模型 ID。透過一個`agentType` to set a per-type override, or omit it to set the global default. Persists to thread settings and emits a `subagent_model_changed` event.

```typescript
// Set the global subagent model
await session.subagents.model.set({ modelId: '__GATEWAY_ANTHROPIC_MODEL_SONNET__' })

// Set a per-type override
await session.subagents.model.set({
  modelId: '__GATEWAY_ANTHROPIC_MODEL_HAIKU__',
  agentType: 'explore',
})
```

## 顯示狀態 {/* #display-state */}

`session.displayState`擁有規範的`AgentControllerDisplayState` snapshot a UI renders from, and the reducer that keeps it in sync with every session event.

### `session.displayState.get()` {/* #sessiondisplaystateget */}

傳回當前值`AgentControllerDisplayState` snapshot for UI rendering.

```typescript
const displayState = session.displayState.get()
```

### `session.displayState.restoreTasks(tasks)` {/* #sessiondisplaystaterestoretaskstasks */}

在 UI 重播持久任務Tool歷史記錄後恢復快照的任務部分。這是快照的純粹更新，不會發出事件，因此在調用它後明確重新渲染。


## 狀態 {/* #state */}

`session.state`公開活動對話的執行緒擁有的首選項以及主機擁有的狀態。更新被序列化並根據`stateSchema` passed to the AgentController. Visible state changes emit `state_changed`.

線程擁有的偏好包括思維層次、觀察記憶設定和子Agent模型選擇。切換執行緒會使主機擁有的自訂欄位和權限規則保持不變，並且不會保留它們。

排隊寫入透過非同步更新和驗證保持其來源執行緒。在寫入掛起時從 A 切換到 B 不會將 A 的首選項套用到 B。主機欄位更新仍然會影響主機。保留運行和活動視圖的相同執行緒共享更新排序。恢復運行後會看到在停止時所做的編輯。只有當該來源處於活動狀態時，才會發出沒有來源位址且影響對話顯示的事件。

在Tool的控制器請求上下文中，`sessionId`, `resourceId`, and `threadId` identify the session, its resource, and its active thread. `state` is a snapshot taken when the context was built. Use `getState()` or `session.state.get()` to read the latest source-thread state after a write.

### `session.state.get()` {/* #sessionstateget */}

傳回目前狀態快照的唯讀副本。

```typescript
const state = session.state.get()
```

### `session.state.set(updates)` {/* #sessionstatesetupdates */}

將部分更新合併到狀態中。隊列按順序應用並發調用，並在發出之前根據模式驗證它們`state_changed` with the changed keys.

```typescript
await session.state.set({ yolo: true })
```

### `session.state.update(updater)` {/* #sessionstateupdateupdater */}

針對目前快照執行更新程序，並在寫入佇列中自動套用其結果。將此用於必須查看最新狀態的讀取-修改-寫入變更。更新器傳回可合併的`updates` and optional `events`, plus the `result` value that `update()` resolves to.

```typescript
const added = await session.state.update(current => ({
  updates: { count: (current.count ?? 0) + 1 },
  result: (current.count ?? 0) + 1,
}))
```

## 持久性邊界 {/* #persistence-boundaries */}

一個`Session` is a live runtime object. Its event bus, arbitrary custom state, permission rules, permission grants, follow-ups, and active stream don't automatically survive controller or process recreation. The host must restore the host-owned state it needs.

配置的儲存會保留執行緒和訊息以及令牌使用情況，而執行緒設定會恢復模式、模型和支援的首選項。恢復的設定可以包括思維層次、觀察記憶和具有每個Agent類型覆蓋的子Agent模型選擇。持久掛起的運行可以使用其完整掛起位址和原始Agent程式來恢復，但任意自訂狀態仍然需要主機管理的持久性。

雖然運行保留了來源執行緒視圖，但即使盡力元資料持久性失敗，返回該執行緒時成功的記憶體中首選項寫入仍然可用。冷重啟只能恢復保留的設定和控制器預設值。

聊天頻道可以映射回儲存的執行緒。然而，`AgentControllerChannels` keeps channel-to-session and auto-approval state in memory.
