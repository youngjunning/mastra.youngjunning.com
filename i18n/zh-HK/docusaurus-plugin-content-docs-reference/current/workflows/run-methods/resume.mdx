# Run.resume()

`.resume()` 方法會以新資料恢復已暫停的 Workflow，從指定步驟繼續執行。

## 使用範例 {/* #usage-example */}

```typescript
const run = await workflow.createRun()

const result = await run.start({ inputData: { value: 'initial data' } })

if (result.status === 'suspended') {
  const resumedResults = await run.resume({
    resumeData: { value: 'resume data' },
  })
}
```

## 擴充使用範例 {/* #extended-usage-example */}

```typescript
if (result.status === 'suspended') {
  const resumedResults = await run.resume({
    step: result.suspended[0],
    resumeData: { value: 'resume data' },
  })
}
```

:::note

如果剛好只有一個步驟暫停，可以省略 `step` 參數，Workflow 會自動恢復該步驟。如果有多個步驟暫停，就必須明確指定要恢復的步驟。

:::

### 恢復 [`.foreach()`](../workflow-methods/foreach) 的單次迭代 {/* #resuming-a-single-foreach-iteration */}

如果 [`.foreach()`](../workflow-methods/foreach) 步驟的多次迭代都已暫停，可使用 `forEachIndex`（由零開始）逐次恢復，並為每次迭代提供不同的 `resumeData`。未被 `forEachIndex` 指定的迭代會維持暫停，直至恢復為止。

```typescript
// Resume only the second iteration (index 1) with its own data
await run.resume({
  step: 'approve',
  resumeData: { ok: true },
  forEachIndex: 1,
})

// Later, resume the first iteration with different data
await run.resume({
  step: 'approve',
  resumeData: { ok: false },
  forEachIndex: 0,
})
```

如果省略 `forEachIndex`，該步驟所有已暫停的迭代都會使用相同的 `resumeData` 恢復。

## 並行恢復呼叫 {/* #concurrent-resume-calls */}

每次暫停只能由一個 `resume()` 呼叫繼續執行。在執行任何步驟之前，`resume()` 會以原子操作將儲存的執行狀態由 `suspended` 改為 `running`，取得該次執行的處理權。如果另一個呼叫方已取得處理權，此呼叫會拋出 `WORKFLOW_RESUME_ALREADY_CLAIMED`，而且不會執行任何步驟。因此，每次暫停之後的步驟及其副作用只會執行一次。

恢復操作可能被觸發多次時，這一點尤其重要，例如審批按鈕被點擊兩次，或 webhook 重試。多個伺服器實例回應同一事件時也是如此。

```typescript
try {
  await run.resume({ step: 'approval', resumeData: { approved: true } })
} catch (error) {
  if (error.id === 'WORKFLOW_RESUME_ALREADY_CLAIMED') {
    // Another caller is already continuing this run. Re-read the run state
    // instead of resuming again.
  }
}
```

經 HTTP 呼叫時，未取得處理權的恢復請求會傳回 `409 Conflict`。

[`timeTravel()`](./timeTravel#concurrent-time-travel-calls) 也以相同方式取得執行的處理權；未取得處理權時會拋出 `WORKFLOW_TIME_TRAVEL_ALREADY_CLAIMED`。

:::note

回報支援 `supportsConcurrentUpdates()` 的儲存適配器會以原子方式保障處理權的取得。不支援原子讀取、修改及寫入的適配器（例如 ClickHouse、Cloudflare D1、Cloudflare KV、Cloudflare Durable Objects、LanceDB 和 Redis）無法提供此保障；當 `shouldPersistSnapshot` 排除 `running` 狀態時，也會略過取得處理權的步驟。

:::
