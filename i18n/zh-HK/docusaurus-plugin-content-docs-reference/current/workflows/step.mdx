# 階梯班

Step 類別定義Workflow中的各個工作單元，封裝執行邏輯、資料驗證和輸入/輸出處理。
它可以將Tool、Agent或配置的分類器作為參數來自動建立步驟。

## 使用範例 {/* #usage-example */}

```typescript title="src/mastra/workflows/test-workflow.ts"
import { createWorkflow, createStep } from '@mastra/core/workflows'
import { z } from 'zod'

const step1 = createStep({
  id: 'step-1',
  description: 'passes value from input to output',
  inputSchema: z.object({
    value: z.number(),
  }),
  outputSchema: z.object({
    value: z.number(),
  }),
  execute: async ({ inputData }) => {
    const { value } = inputData
    return {
      value,
    }
  },
})
```

## 從Agent程式建立步驟 {/* #creating-steps-from-agents */}

您可以直接從Agent程式建立步驟。此步驟將使用Agent的名稱作為其 ID。

### 基本Agent步驟 {/* #basic-agent-step */}

```typescript title="src/mastra/workflows/test-workflow.ts"
import { testAgent } from '../agents/test-agent'
import { createStep } from '@mastra/core/workflows'

const agentStep = createStep(testAgent)
// inputSchema: { prompt: string }
// outputSchema: { text: string }
```

### 具有結構化輸出的Agent步驟 {/* #agent-step-with-structured-output */}

經過`structuredOutput` to have the agent return typed structured data:

```typescript title="src/mastra/workflows/test-workflow.ts"
import { createStep } from '@mastra/core/workflows'
import { z } from 'zod'

const articleSchema = z.object({
  title: z.string(),
  summary: z.string(),
  tags: z.array(z.string()),
})

const agentStep = createStep(testAgent, {
  structuredOutput: { schema: articleSchema },
})
// inputSchema: { prompt: string }
// outputSchema: { title: string, summary: string, tags: string[] }
```

## 從分類器建立步驟 {/* #creating-steps-from-classifiers */}

透過一個[`Classifier`](/reference/classifier/classifier) with constructor-configured questions to `createStep()`. By default, the classifier evaluates the complete `inputData`. Use `state` to select a JSON value from the step context.

```typescript title="src/mastra/workflows/ticket-triage.ts"
import { Classifier } from '@mastra/core/classifier'
import { typeSafeAi } from '@ai-sdk/typesafe-ai'
import { createStep } from '@mastra/core/workflows'

const router = new Classifier({
  id: 'ticket-router',
  model: typeSafeAi.decisionModel('__AI_SDK_TYPESAFE_DECISION_MODEL__'),
  questions: {
    route: {
      type: 'choice',
      criteria: {
        billing: 'Billing, invoices, and payments',
        support: 'Account access and product help',
        other: 'Anything else',
      },
    },
    urgent: { type: 'boolean' },
  },
})

const classifyTicket = createStep(router, {
  maxRetries: 2,
  retries: 1,
})
```

輸入的步驟輸出是 JSON 安全的：

* `answers.route.choice`是選定的選擇文字。
* `answers.urgent.probability`是布爾答案的機率`true`, not a thresholded boolean.
* 選擇和評分答案可能包括分佈。
* 決策模型拒絕的一個問題是`{ type: 'refusal' }` and has no `choice`, `score`, or `probability`.
* `usage`包含規範化的令牌使用情況。

`maxRetries`控制分類器模型呼叫重試。`retries` controls workflow step retries. Classifier warnings, response metadata, and raw provider data aren't included in workflow output.

沒有建構函數配置的問題的分類器不能用作Workflow步驟。此步驟評估其完整輸入。添加前面的`.map()` call when the workflow needs to select or reshape that input.

## 評分步驟輸出 {/* #scoring-step-output */}

附`scorers` to a step to evaluate that step's output automatically, at the point it runs, instead of only scoring the workflow's final answer. This is useful for multi-step and RAG workflows, where you want to see which step degraded quality, for example whether a retrieval step returned relevant chunks before later steps reason over them.

每個得分者都會收到自己的步數`input` and `output`. Scoring runs asynchronously after the step succeeds, and the result is stored against the step's trace. Use `sampling` to control how often a scorer runs.

以下範例將評分器附加到檢索步驟，以便對每次執行進行評分：

```typescript title="src/mastra/workflows/rag-workflow.ts"
import { createStep } from '@mastra/core/workflows'
import { z } from 'zod'
import { retrievalRelevanceScorer } from '../scorers/retrieval-relevance'

const retrievalStep = createStep({
  id: 'retrieval',
  inputSchema: z.object({ query: z.string() }),
  outputSchema: z.object({ query: z.string(), chunks: z.array(z.string()) }),
  scorers: {
    retrievalRelevance: {
      scorer: retrievalRelevanceScorer(),
      sampling: { type: 'ratio', rate: 1 },
    },
  },
  execute: async ({ inputData }) => {
    const chunks = await retrieve(inputData.query)
    return { query: inputData.query, chunks }
  },
})
```

將記分器附加到要測量的每個步驟，以便在多步驟Workflow中建立每個步驟分數。由於評分僅限於單一步驟，因此您不需要專用的跨步驟指標來查看品質變化的位置。

新增了Agent和Tool步驟[`Workflow.agent()`](/reference/workflows/workflow-methods/agent) and [`Workflow.tool()`](/reference/workflows/workflow-methods/tool) accept the same `scorers` option in their step options.
