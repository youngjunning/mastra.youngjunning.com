# 可觀測性 API

可觀測性 API 提供擷取追蹤、監察應用程式效能、為追蹤評分以作評估，以及記錄與追蹤和跨度相關回饋的方法。

## 取得指定追蹤 {/* #getting-a-specific-trace */}

透過 ID 取得指定追蹤，包括其所有跨度和詳細資料：

```typescript
const trace = await mastraClient.getTrace('trace-id-123')
```

## 篩選並取得追蹤 {/* #getting-traces-with-filtering */}

取得追蹤根跨度的分頁清單，並可選擇套用篩選條件：

```typescript
const traces = await mastraClient.getTraces({
  pagination: {
    page: 1,
    perPage: 20,
    dateRange: {
      start: new Date('2024-01-01'),
      end: new Date('2024-01-31'),
    },
  },
  filters: {
    name: 'weather-agent', // Filter by trace name
    spanType: 'agent', // Filter by span type
    entityId: 'weather-agent-id', // Filter by entity ID
    entityType: 'agent', // Filter by entity type
  },
})

console.log(`Found ${traces.spans.length} root spans`)
console.log(`Total pages: ${traces.pagination.totalPages}`)

// To get the complete trace with all spans, use getTrace
const completeTrace = await mastraClient.getTrace(traces.spans[0].traceId)
```

## 列出供清單檢視使用的追蹤 {/* #listing-traces-for-a-list-view */}

`listTracesLight()` 傳回與追蹤清單相同的資料列，但不包含 `input`、`output` 和 `attributes` 的完整內容。每列改為提供簡短的 `inputPreview`、`outputPreview` 和 `errorPreview` 字串（最多 100 個字元，截斷時以 `…` 結尾），讓清單無須傳輸完整內容也能顯示預覽欄；另提供 `threadId` 和 `resourceId`，供記憶體上下文欄使用。

同時顯示大量追蹤時，建議使用此方法；只有在開啟某列時才擷取完整記錄：

```typescript
const list = await mastraClient.listTracesLight({
  pagination: { page: 0, perPage: 25 },
  filters: { entityType: 'agent' },
})

for (const span of list.spans) {
  console.log(span.name, span.inputPreview)
}

// Fetch the full payload only for the trace the user selects
const selected = await mastraClient.getTrace(list.spans[0].traceId)
```

此方法接受與 `listTraces()` 相同的篩選、排序和增量輪詢參數。只有需要完整跨度內容時，才使用 `listTraces()`。

## 查詢跨度 {/* #querying-spans */}

`querySpans()` 傳回跨追蹤的已完成跨度摘要。此方法要求以 ISO 時間戳指定跨度開始時間的有效範圍，並支援游標分頁：

```typescript
const result = await mastraClient.querySpans({
  timeRange: {
    from: '2026-10-01T00:00:00.000Z',
    to: '2026-10-02T00:00:00.000Z',
  },
  where: {
    op: 'and',
    args: [
      { op: 'eq', left: { path: 'threadId' }, right: { literal: 'thread-123' } },
      { op: 'gte', left: { path: 'durationMs' }, right: { literal: 1000 } },
    ],
  },
  orderBy: [{ field: 'startedAt', direction: 'desc' }],
  page: { limit: 100 },
})

// Pass result.page.next as page.after to continue with the same filters and ordering.
console.log(result.spans)
```

回應格式為 `{ spans, page: { next } }`。呼叫前請檢查 `capabilities.spanQuery`；使用可選篩選條件前，亦須檢查對應欄位的能力。欄位、運算子、預設值、能力、回應詳情及游標處理方式，請參閱[查詢跨度](/reference/observability/tracing/advanced-queries#query-spans)。

### 匯總跨度 {/* #aggregate-spans */}

`aggregateSpans()` 對符合直接跨度述詞的已完成跨度分組。每個分組傳回一列；設定 `interval` 後，每個分組的每個非空時間區間各傳回一列。此方法會計入任何深度的跨度，包括追蹤匯總未涵蓋的巢狀 Agent 執行：

```typescript
const { capabilities } = await mastraClient.getObservabilityCapabilities()

if (capabilities.spanAggregate) {
  const { rows, truncated } = await mastraClient.aggregateSpans({
    timeRange: {
      from: '2026-10-01T00:00:00.000Z',
      to: '2026-10-08T00:00:00.000Z',
    },
    where: { op: 'eq', left: { path: 'spanType' }, right: { literal: 'agent_run' } },
    groupBy: ['status'],
    interval: '1d',
    measures: ['count', 'errorRate'],
  })
}
```

請求和回應結構與 `aggregateTraces()` 相同，但使用直接跨度述詞，以及 `spanType`、`name` 和 `parentEntityName` 等跨度維度。Token 和成本指標歸屬於記錄用量的跨度，不會加到父跨度。呼叫前請檢查 `capabilities.spanAggregate`；按 `model` 或 `provider` 分組或計算相異值前，請檢查 `capabilities.spanAggregateModelDimensions`。使用較舊的 adapter 時，這類請求會傳回 `501`。

當 `capabilities.aggregateTimeToFirstMeasures` 為 `true` 時，`aggregateTraces()` 和 `aggregateSpans()` 均支援首個 Token 時間（TTFT）及首個資料區塊時間（TTFC）指標，即 `timeToFirstToken.*` 和 `timeToFirstChunk.*`。沒有記錄值的跨度和追蹤會被略過，不會當作 0 計算。請參閱[首個資料區塊時間（TTFC）](/reference/observability/tracing/advanced-queries#time-to-first-chunk-ttfc)及[首個 Token 時間（TTFT）](/reference/observability/tracing/advanced-queries#time-to-first-token-ttft)。

有關選取條件、維度、各跨度的用量，以及如何列出分組中的跨度，請參閱[匯總跨度](/reference/observability/tracing/advanced-queries#aggregate-spans)。

## 查詢執行緒 {/* #querying-threads */}

`queryTraceThreads()` 透過 `POST /observability/threads/query` 從已完成的追蹤取得執行緒摘要。每列包含活動時間戳、追蹤數量、上下文和預覽。沒有執行緒 ID 的追蹤不會包含在內。

```typescript
const result = await mastraClient.queryTraceThreads({
  timeRange: {
    traces: {
      from: '2026-10-01T00:00:00.000Z',
      to: '2026-10-02T00:00:00.000Z',
    },
  },
  where: { op: 'eq', left: { path: 'status' }, right: { literal: 'error' } },
  orderBy: [{ field: 'endedAt', direction: 'desc' }],
  page: { limit: 100 },
})

for (const thread of result.threads) {
  console.log(thread.firstTraceId, thread.lastTraceId, thread.traceCount, thread.outputPreview)
}
```

### 執行緒時間範圍 {/* #thread-time-ranges */}

只可選擇一種時間選取條件。每個範圍都須使用 ISO 時間戳，且 `from` 必須早於 `to`。範圍包含 `from`，但不包含 `to`。

| 選取條件 | 符合條件的執行緒 |
| - | - |
| `timeRange.traces: { from, to }` | 至少有一個追蹤在指定時間範圍內開始 |
| `timeRange.threads: { field: 'startedAt', from, to }` | 首次活動發生在指定時間範圍內 |
| `timeRange.threads: { field: 'endedAt', from, to }` | 最近一次活動發生在指定時間範圍內 |

例如，找出最近一次活動發生在 10 月 1 日的執行緒：

```typescript
const result = await mastraClient.queryTraceThreads({
  timeRange: {
    threads: {
      field: 'endedAt',
      from: '2026-10-01T00:00:00.000Z',
      to: '2026-10-02T00:00:00.000Z',
    },
  },
})
```

每列包含授權範圍內保留的完整歷史記錄，包括指定時間範圍之前和之後的追蹤。篩選條件會套用至這些完整資料列。`environment` 篩選條件檢查首個追蹤的環境。

### 執行緒篩選條件 {/* #thread-filters */}

使用 `where` 篩選執行緒資料列，並以 `and`、`or` 和 `not` 組合述詞。

| 欄位 | 運算子 |
| - | - |
|`threadId`, `organizationId`, `firstTraceId`, `lastTraceId` | `eq`, `ne`, `in`, `notIn`, `exists`, `notExists` |
| `resourceId`, `userId`, `runId`, `sessionId`, `requestId`, `serviceName`, `experimentId`, `environment`, `executionSource` | 與上一列相同的字串運算子 |
| `entityType`, `entityId`, `entityName`, `entityVersionId` | 與上一列相同的字串運算子 |
| `status` | `eq`、`ne`、`in`、`notIn`；值為 `success` 或 `error` |
| `startedAt`, `endedAt`, `timeToFirstChunkMs`, `timeToFirstTokenMs` | `eq`, `ne`, `lt`, `lte`, `gt`, `gte`, `in`, `notIn`, `exists`, `notExists` |
| `traceCount` | `eq`, `ne`, `lt`, `lte`, `gt`, `gte` |

例如，篩選來自指定 Agent、且至少包含三個追蹤的執行緒：

```typescript
const result = await mastraClient.queryTraceThreads({
  timeRange: {
    traces: {
      from: '2026-10-01T00:00:00.000Z',
      to: '2026-10-02T00:00:00.000Z',
    },
  },
  where: {
    op: 'and',
    args: [
      { op: 'in', value: { path: 'entityId' }, set: ['support-agent', 'sales-agent'] },
      { op: 'gte', left: { path: 'traceCount' }, right: { literal: 3 } },
    ],
  },
})
```

使用存在性篩選條件 `{ op: 'exists', path: 'userId' }` 檢查值是否非 `null`。傳回的資料列包含模型、Provider 和預覽資料，但不能按這些資料篩選。

### 執行緒回應 {/* #thread-response */}

回應格式為 `{ threads, page: { next } }`，不包含總數。`threads` 中的每個項目均包含以下欄位：

| 傳回欄位 | 含義 |
| - | - |
| `threadId`, `organizationId` | 執行緒識別資料。不同組織中相同的執行緒 ID 仍屬不同執行緒。 |
| `firstTraceId`, `lastTraceId` | 按開始時間排列的最早及最新追蹤。開始時間相同時，以追蹤 ID 作為確定性的排序依據。 |
| `resourceId`, `userId`, `runId`, `sessionId`, `requestId`, `serviceName`, `experimentId`, `environment`, `executionSource` | 首個追蹤的上下文；缺少時為 `null`。 |
| `entityType`, `entityId`, `entityName`, `entityVersionId` | 首個追蹤的實體。 |
| `startedAt`, `endedAt` | 執行緒中最早的開始時間及最晚的結束時間。 |
| `status` | 最後開始的追蹤之根跨度發生錯誤時為 `error`，否則為 `success`。 |
| `traceCount` | 執行緒中的邏輯追蹤數量。 |
| `inputPreview` | 首個追蹤的輸入預覽。 |
| `outputPreview`, `errorPreview` | 最後開始的追蹤之預覽。 |
| `timeToFirstChunkMs` | 首個追蹤的根 Agent 產生首個資料區塊所需時間，單位為毫秒。無法取得資料或根跨度並非 Agent 時為 `null`。 |
| `timeToFirstTokenMs` | 首個追蹤的根 Agent 產生首個 Token 所需時間，單位為毫秒；`null` 的規則相同。只有儲存系統支援時才會提供此欄位。 |

較早開始的追蹤可能最後才完成。此時，它會提供 `endedAt`；狀態及輸出／錯誤預覽仍由最後開始的追蹤提供。首個追蹤缺少的值，不會由較後的追蹤補上。

### 執行緒排序與分頁 {/* #thread-ordering-and-pagination */}

排序欄位只可選擇 `startedAt` 或 `endedAt`，方向為 `asc` 或 `desc`。預設按 `endedAt` 降序排列。每頁預設 25 列，最多 100 列。取得下一頁時，將 `result.page.next` 作為 `page.after` 傳入，並沿用相同的時間選取條件、篩選條件、範圍和排序方式。游標為 `null` 表示沒有更多頁面。分頁反映即時資料，因此新增追蹤可能令執行緒移至其他頁面。

如要載入執行緒中的追蹤，請使用 [`queryTraces()`](#querying-traces)，並指定 `threadId` 篩選條件及涵蓋該執行緒活動的時間範圍。

### 執行緒查詢支援 {/* #thread-query-support */}

使用此功能前，請透過 `getObservabilityCapabilities()` 檢查 `capabilities.threadQueryRows`。若此值缺失或為 `false`，即表示無法取得完整的執行緒資料列。較舊的 core 或 storage 套件會對這類請求傳回結構化的 `501` 回應。混用不同版本套件時，仍可使用舊版識別資料請求。

當授權範圍內的歷史記錄超過 250,000 列已儲存的追蹤根資料（包括重複副本）時，ClickHouse 會拒絕範圍過廣的執行緒查詢。縮窄時間範圍以減少候選執行緒後，查詢仍可能成功。被拒絕的查詢會傳回 `503 TRACE_QUERY_RESOURCE_LIMIT`，不會附帶部分結果。

## 查詢追蹤 {/* #querying-traces */}

`queryTraces()` 根據追蹤欄位及相關跨度的條件，找出已完成的邏輯追蹤。每個查詢都須指定 ISO 時間戳範圍。

```typescript
const result = await mastraClient.queryTraces({
  timeRange: {
    from: '2026-08-01T00:00:00.000Z',
    to: '2026-08-08T00:00:00.000Z',
  },
  where: {
    spans: {
      some: {
        op: 'and',
        args: [
          { op: 'eq', left: { path: 'spanType' }, right: { literal: 'tool_call' } },
          { op: 'exists', path: 'error' },
        ],
      },
    },
  },
})
```

請參閱[查詢追蹤](/reference/observability/tracing/advanced-queries#query-traces)，了解請求欄位、述詞、限制、回應格式和錯誤。

### 載入頁面並輪詢追蹤 {/* #load-a-page-and-poll-for-traces */}

`queryTraces()` 支援透過 `page` 進行鍵集分頁、透過 `pagination` 取得按頁碼編排的頁面，以及透過 `mode: 'delta'` 進行增量輪詢。每個請求只可使用一種模式。從 `listTracesLight()` 遷移時，請讀取 `traces` 而非 `spans`，並保留按頁碼編排的頁面所傳回的 `deltaCursor`：

```typescript
const timeRange = {
  from: '2026-08-01T00:00:00.000Z',
  to: '2026-08-08T00:00:00.000Z',
}
const initial = await mastraClient.queryTraces({
  timeRange,
  pagination: { page: 0, perPage: 100 },
})
if (!initial.deltaCursor) throw new Error('Delta polling is unavailable')

const changes = await mastraClient.queryTraces({
  timeRange,
  mode: 'delta',
  after: initial.deltaCursor,
  limit: 100,
})
```

按 `traceId` 合併 `changes.traces`，保留 `changes.deltaCursor`，並在 `changes.delta.hasMore` 為 `true` 時繼續輪詢。各次輪詢須沿用相同的時間範圍和述詞。只會傳回已完成的追蹤；輪詢不保證通知相關記錄的更新或刪除，亦不保證通知不再符合條件的追蹤。

初始載入行為、游標有效期、資料保留及完整輪詢流程，請參閱[增量輪詢](/reference/observability/tracing/advanced-queries#poll-after-loading-a-numbered-page)。

### 匯總追蹤 {/* #aggregate-traces */}

`aggregateTraces()` 對時間範圍及可選的 `where` 述詞所選出的追蹤分組。每個分組傳回一列；設定 `interval` 後，每個分組的每個非空時間區間各傳回一列。此方法接受與 `queryTraces()` 相同的述詞。

```typescript
const { capabilities } = await mastraClient.getObservabilityCapabilities()

if (capabilities.traceAggregate) {
  const { rows, truncated } = await mastraClient.aggregateTraces({
    timeRange: {
      from: '2026-08-01T00:00:00.000Z',
      to: '2026-08-08T00:00:00.000Z',
    },
    where: { op: 'eq', left: { path: 'environment' }, right: { literal: 'production' } },
    groupBy: ['entityName'],
    interval: '1d',
    measures: ['count', 'errorRate', 'duration.p95', 'cost.sum'],
    orderBy: { field: 'count', direction: 'desc' },
    limit: 10,
  })
}
```

每列的 `dimensions` 以 `groupBy` 欄位為鍵，`measures` 以指標名稱為鍵；設定 `interval` 時會包含 `bucket` 時間戳，要求成本指標時則會包含 `cost` 覆蓋資料。符合條件的分組數量超過 `limit` 時，`truncated` 為 `true`。呼叫前請檢查 `capabilities.traceAggregate`。用戶端會套用已設定的重試策略，但不會重試 `4xx`、`501`，以及錯誤代碼為 `TRACE_QUERY_EXECUTION_TIMEOUT` 的 `504` 回應；一般網關 `504` 回應仍可重試。

維度、指標、Token 與成本的計算方式、時間區間、限制及錯誤，請參閱[匯總追蹤](/reference/observability/tracing/advanced-queries#aggregate-traces)。

### 探索追蹤查詢欄位及其值 {/* #discover-trace-query-fields-and-values */}

`getTraceQueryFields()` 傳回指定述詞範圍內的標準查詢欄位，以及觀察到的頂層字串元資料欄位。回應包括各欄位的值類型、支援的運算子，以及能否提供值建議。

```typescript
const timeRange = {
  from: '2026-08-01T00:00:00.000Z',
  to: '2026-08-08T00:00:00.000Z',
}

const fields = await mastraClient.getTraceQueryFields({
  timeRange,
  predicateScope: 'spans',
  search: 'model',
  limit: 25,
})
```

對於支援匯總的伺服器，其 `trace` 範圍的回應亦包含 `aggregate`：其中列出可傳入 `groupBy` 的 `dimensions`，以及可要求的 `measures`。請參閱[探索欄位及其值](/reference/observability/tracing/advanced-queries#discover-fields-and-values)。

請使用相同範圍的回應所提供的確切本地路徑。例如，`model` 應放在 `spans.some` 或 `spans.none` 述詞內。欄位選擇器可以並行擷取 `trace` 和 `spans` 兩個範圍。

只有選定標示為 `valueSuggestions: true` 的欄位後，才呼叫 `getTraceQueryValues()`：

```typescript
const controller = new AbortController()

const values = await mastraClient.getTraceQueryValues(
  {
    timeRange,
    predicateScope: 'spans',
    path: 'model',
    search: 'claude',
    limit: 25,
  },
  { signal: controller.signal },
)

// Cancel this autocomplete request when the search text changes.
controller.abort()
```

兩種方法都使用不區分大小寫的字面子字串搜尋，亦接受空白搜尋字串。數量上限預設為 25，最多為 100。結果先按出現次數排序，再按路徑或值確定順序。`observedFieldsTruncated` 和 `valuesTruncated` 表示呼叫端應收窄 `search`。探索結果不提供游標。

建議值有數量限制，僅供參考。即使建議值不可用、為空或已截斷，手動輸入的值仍然有效。探索請求不接受草稿查詢述詞。用戶端不會重試這兩種請求；每次呼叫所提供的 `AbortSignal` 會優先於 `MastraClient` 上設定的訊號。

探索請求逾時時會傳回 `504 TRACE_QUERY_EXECUTION_TIMEOUT`；後端記憶體或資源耗盡時會傳回 `503 TRACE_QUERY_RESOURCE_LIMIT`。兩種錯誤都不包含部分建議值；截斷標記只會出現在成功且已完整排序的回應中。

## 刪除追蹤 {/* #deleting-traces */}

刪除追蹤及其相關的跨度、指標、日誌、分數和回饋：

```typescript
const result = await mastraClient.deleteTraces({
  traceIds: ['trace-1', 'trace-2'],
})

if ('accepted' in result) {
  console.log('Deletion requested')
} else {
  console.log(result.success)
}
```

每個請求最多接受 1,000 個追蹤 ID，不提供租戶範圍欄位。未連結至追蹤的訊號會予以保留。實驗建立的追蹤與其他追蹤一樣會被刪除。

用戶端支援兩種回應格式：OSS 完成刪除操作後會傳回 `{ success: true }`；支援佇列批量刪除的 Platform 後端接受清理請求後，則會傳回 `202 { accepted: true }`。接受請求不代表讀取時已看不到相關記錄，因此回報刪除完成前須檢查回應。若要在 Platform 使用這些用戶端方法，部署環境須支援批量刪除端點。

## 為追蹤評分 {/* #scoring-traces */}

使用已註冊的評分器為指定追蹤評分，以便進行評估：

```typescript
const result = await mastraClient.score({
  scorerName: 'answer-relevancy',
  targets: [
    { traceId: 'trace-1', spanId: 'span-1' }, // Score specific span
    { traceId: 'trace-2' }, // Score specific span which defaults to the parent span
  ],
})
```

## 按跨度取得分數 {/* #getting-scores-by-span */}

取得追蹤中指定跨度的分數：

```typescript
const scores = await mastraClient.listScoresBySpan({
  traceId: 'trace-123',
  spanId: 'span-456',
  page: 1,
  perPage: 20,
})
```

## 按 ID 取得分數 {/* #get-a-score-by-id */}

使用 `getScore()` 取得一筆可觀測性分數記錄：

```typescript
const { score } = await mastraClient.getScore('score-id-123')
```

回應格式為 `{ score: record | null }`。找不到分數時，會傳回 HTTP 200 及 `{ score: null }`。
傳回類型為由 `@mastra/client-js` 匯出的 `GetScoreResponse`。

## 建立分數 {/* #creating-scores */}

為追蹤建立分數，並可選擇指定其中一個跨度：

```typescript
const response = await mastraClient.createScore({
  score: {
    traceId: 'trace-123',
    spanId: 'span-456',
    scorerId: 'accuracy',
    score: 0.95,
  },
})
```

`createScore()` 要求 `score.traceId` 不得為空白，`spanId` 則為可選欄位。若未提供 `scoreId` 或 ISO `timestamp`，用戶端會在每次呼叫時各產生一次，並在重試期間沿用。提供這些欄位可重用現有識別資料。上下文解析及重試行為，請參閱[訊號寫入選項](#signal-write-options)。

## 回饋 {/* #feedback */}

回饋方法透過已設定的 API 伺服器，建立、列出和查詢評分、讚好、留言及更正等人工參與訊號。建立方法支援 OSS 和 Platform。Platform 及支援回饋替換的 OSS 伺服器均支援完整替換。範例請參閱[回饋指南](/docs/observability/feedback)；完整結構請參閱[回饋參考文件](/reference/observability/feedback)。

### 按 ID 取得回饋 {/* #get-feedback-by-id */}

使用 `getFeedback()` 取得一筆回饋記錄：

```typescript
const { feedback } = await mastraClient.getFeedback('feedback-id-123')
```

回應格式為 `{ feedback: record | null }`。找不到記錄時，會傳回 HTTP 200 及 `{ feedback: null }`。
傳回類型為由 `@mastra/client-js` 匯出的 `GetFeedbackResponse`。

兩個取得方法均接受未編碼的 ID，並將其編碼為 URL 路徑區段。它們使用用戶端已設定的 API 前綴、憑證和標頭。JSON 回應中的記錄時間戳為 ISO 字串。

### 建立回饋 {/* #creating-feedback */}

為追蹤建立回饋記錄，並可選擇指定其中一個跨度：

```typescript
const response = await mastraClient.createFeedback({
  feedback: {
    traceId: 'trace-123',
    spanId: 'span-456',
    feedbackSource: 'user',
    feedbackType: 'rating',
    value: 1,
    comment: 'Helpful answer.',
  },
})
```

`createFeedback()` 要求 `feedback.traceId` 不得為空白，`spanId` 則為可選欄位。若未提供 `feedbackId` 或 ISO `timestamp`，用戶端會在每次呼叫時各產生一次，並在重試期間沿用。使用 `feedbackUserId` 識別回饋作者；`userId` 則識別跨度的使用者。已驗證身分的 OSS 使用者優先於請求中提交的回饋作者。

### 訊號寫入選項 {/* #signal-write-options */}

兩種建立方法都接受可選的頂層 `contextMode`，與 `feedback` 或 `score` 包裝欄位並列：

* `"provided"` 使用記錄中已展平的上下文欄位，不會查找跨度；缺少的上下文欄位不會獲補充。
* `"resolve"` 從已儲存的根跨度及可選的目標跨度取得上下文。根跨度的標籤會被繼承，記錄元資料會覆蓋同名的已儲存元資料鍵。找不到根跨度時傳回 `TRACE_NOT_FOUND`；找不到目標跨度時傳回 `SPAN_NOT_FOUND`。

省略 `contextMode` 時會使用伺服器預設值：OSS 為 `"provided"`，Platform 為 `"resolve"`。用戶端會保留省略狀態。如需兩種伺服器採用相同行為，請明確指定模式。在 OSS 上，每個已設定的可信範圍欄位都會覆蓋呼叫端輸入。於 `"provided"` 模式下，其他上下文欄位仍使用呼叫端提供的值。例如，可信的組織 ID 會覆蓋 `organizationId`；若未設定可信的資源範圍，則不會清除 `resourceId`。

```typescript
const result = await mastraClient.createFeedback({
  contextMode: 'resolve',
  feedback: {
    traceId: 'trace-123',
    feedbackUserId: 'reviewer-1',
    feedbackType: 'thumbs',
    value: 1,
  },
})
```

在可選的第二個參數中使用 `retries` 和 `anchorRetryTimeoutMs` 控制重試。網絡及伺服器錯誤使用用戶端的傳輸重試設定。只有錯誤代碼為 `TRACE_NOT_FOUND` 或 `SPAN_NOT_FOUND` 的 404 回應會觸發錨點重試；從首次收到此類回應起，最多重試 30 秒。將 `anchorRetryTimeoutMs` 設為較短時限，或設為 `0` 以停用錨點重試。其他 404、身分驗證錯誤及驗證錯誤均不會重試。

建立操作的回應包含 `success`，並可包含 `data`；其中載有產生或提供的 `feedbackId`／`scoreId`、`traceId`、可為 `null` 的 `spanId`，以及標準化為 UTC 的 `timestamp`。用戶端亦接受只有成功狀態的回應。Platform 的成功回應確認記錄已發布，但記錄未必能立即透過讀取操作看到。直接呼叫 OSS HTTP API 時，可以省略 ID 和時間戳，交由伺服器產生。

明確指定模式需要伺服器支援。較舊的伺服器可能會忽略 `contextMode`。向 Platform 傳送 `"provided"` 前，須先部署其提供上下文模式的支援功能。

### 替換回饋 {/* #replacing-feedback */}

`replaceFeedback()` 向 `PUT /api/observability/feedback/:feedbackId` 傳送完整替換資料。請包含原有的 `feedbackId`、`traceId` 和標準化的 `timestamp`，以及所有需要保留的回饋欄位。Platform 及支援回饋替換的 OSS 伺服器接受此方法。若 OSS 的 storage adapter 不支援替換，便會傳回 `501`。在 OSS 上提供編輯功能前，請檢查 `capabilities.feedbackReplacement`；缺少此能力即表示功能不可用。

```typescript
await mastraClient.replaceFeedback({
  feedback: {
    feedbackId: 'feedback-1',
    traceId: 'trace-123',
    timestamp: '2026-01-01T00:00:00.123Z',
    feedbackType: 'thumbs',
    value: -1,
    feedbackUserId: 'reviewer-1',
  },
})
```

如建立操作的回應包含 `data`，請使用其中標準化的時間戳。OSS 會以 `409` 拒絕變更原有追蹤或時間戳；Platform 亦將時間戳用作記錄識別資料的一部分，因此同樣須予以保留。用戶端會在重試期間沿用替換內容，但每次獲接受的 PUT 重試都是一次新的替換，可能覆蓋其他編輯。將 `{ retries: 0, anchorRetryTimeoutMs: 0 }` 作為第二個參數傳入，可停用自動重試。

### 刪除回饋和分數 {/* #deleting-feedback-and-scores */}

按 ID 刪除回饋或分數記錄。刪除操作具冪等性，因此不存在的 ID 會被略過。每個請求最多接受 1,000 個 `feedbackIds` 或 1,000 個 `scoreIds`。可選的 `organizationId` 和 `resourceId` 欄位會將刪除範圍限制在範圍欄位相符的記錄：

```typescript
await mastraClient.deleteFeedback({
  feedbackIds: ['feedback-1', 'feedback-2'],
  organizationId: 'org-1',
  resourceId: 'resource-1',
})

await mastraClient.deleteScores({
  scoreIds: ['score-1', 'score-2'],
  organizationId: 'org-1',
  resourceId: 'resource-1',
})
```

兩種方法在 OSS 上均傳回 `{ success: boolean }`；支援佇列批量刪除的 Platform 後端則傳回 `{ accepted: true }`。回應處理方式請參閱[刪除追蹤](#deleting-traces)。獲接受的記錄在清理程序執行前仍可能可以讀取。Platform 使用已驗證身分的組織／項目範圍，請求內容中的範圍欄位不能覆蓋該範圍。

### 列出回饋 {/* #listing-feedback */}

取得回饋記錄的分頁清單，並可選擇套用篩選條件：

```typescript
const feedback = await mastraClient.listFeedback({
  filters: {
    feedbackType: 'rating',
    feedbackSource: 'studio',
  },
  pagination: { page: 0, perPage: 20 },
  orderBy: { field: 'timestamp', direction: 'DESC' },
})
```

`filters` 接受 [`FeedbackFilter`](/reference/observability/feedback#feedbackfilter) 的所有欄位。用戶端會將這些欄位作為 `GET /api/observability/feedback` 的查詢參數傳送。請參閱[清單查詢參數](/reference/observability/feedback#list-query-parameters)。

const averageRating = await mastraClient.getFeedbackAggregate({

const ratingsByAgent = await mastraClient.getFeedbackBreakdown({
