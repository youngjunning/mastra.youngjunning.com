# 資料集 API

資料集 API 透過 `MastraClient` 提供 Mastra 的資料集及實驗路由，包括由呼叫方驅動實驗及刪除實驗的方法。呼叫方可使用自己的編排器（例如 Temporal Workflow）控制實驗循環，由 Mastra 保存正式紀錄。建立實驗後，可透過 `runExperimentItem` 讓 Mastra 在伺服器端執行每個資料項目，或透過 `submitExperimentResult` 提交自行計算的結果。執行結束時，再呼叫最終確認方法。

執行資料項目、提交結果及最終確認都可安全重試。只有在請求中提供呼叫方指定的 `id` 時，建立實驗才能安全重試；否則每次重試都會建立新實驗。

* 提供呼叫方指定的 `id` 時，`createDatasetExperiment` 具備冪等性
* `runExperimentItem` 和 `submitExperimentResult` 依據 `(experimentId, itemId, attempt)` 更新或新增結果
* 如實驗已完成，`finalizeExperiment` 會傳回已儲存的紀錄

## 使用範例 {/* #usage-example */}

```typescript
import { MastraClient } from '@mastra/client-js'

const client = new MastraClient({
  baseUrl: 'http://localhost:4111',
})

// 1. Create the experiment. Pass your orchestrator's run ID so a
//    retried workflow converges on the same experiment.
const { experimentId, totalItems, datasetVersion } = await client.createDatasetExperiment({
  datasetId: 'clinical-triage-evals',
  id: 'temporal-wf-run-42',
  targetType: 'agent',
  targetId: 'triage-agent',
  scorerIds: ['clinical-judge'],
})

// 2. Run one item per activity. Mastra executes the agent, runs the
//    scorers, and upserts the result. Retried activities converge on
//    a single row per (experimentId, itemId, attempt).
const { result, scores } = await client.runExperimentItem({
  datasetId: 'clinical-triage-evals',
  experimentId,
  itemId: 'item-1',
})

// 3. Finalize. The server computes succeeded/failed/skipped counts
//    from the persisted rows.
const experiment = await client.finalizeExperiment({
  datasetId: 'clinical-triage-evals',
  experimentId,
})
```

如只需匯入結果，建立實驗時不要提供 `targetType` 和 `targetId`，並在第 2 步改用 `submitExperimentResult`。

## `runExperimentItem()` {/* #runexperimentitem */}

在伺服器端執行一個實驗資料項目：Mastra 使用實驗目標處理該項目、執行解析出的評分器，並依據 `(experimentId, itemId, attempt)` 更新或新增結果。實驗建立時必須指定目標。評分器的解析優先次序與原生執行相同：實驗的 `scorerIds` 優先於資料項目的 `scorerIds`，後者又優先於資料集的 `scorerIds`。

## `finalizeExperiment()` {/* #finalizeexperiment */}

將由呼叫方驅動的實驗標記為已完成。伺服器依據已儲存的結果紀錄計算各類資料項目數量：`succeededCount` 表示至少有一次嘗試未發生錯誤，`failedCount` 表示每次嘗試都發生錯誤，`skippedCount` 表示從未提交結果。此操作具備冪等性：對已完成的實驗再次呼叫，會傳回已儲存的紀錄。

## 刪除資料集實驗() {/* #deletedatasetexperiment */}

透過所屬資料集刪除實驗。伺服器會先刪除實驗的可觀測性 Trace，包括當中的 span 及關聯訊號，再刪除實驗及其結果紀錄。如儲存系統不支援刪除 Trace，Trace 會保留，伺服器會記錄警告。如因其他原因無法刪除 Trace，Promise 會遭拒絕，Mastra 會保留實驗及其結果紀錄，但部分 Trace 可能已被刪除。

```typescript
await client.deleteDatasetExperiment('dataset-id', 'experiment-id', {
  organizationId: 'organization-id',
  projectId: 'project-id',
})
```

## 清除資料集項目() {/* #purgedatasetitem */}

從現有資料集歷史及關聯的實驗結果中清除資料項目內容，包括結果標籤及留言，同時保留版本歷史、實驗計數及審核狀態。之後為該資料項目提交的結果會以內容已遮蔽的形式儲存；之後對該資料項目的更新會遭拒絕。

```typescript
await client.purgeDatasetItem('dataset-id', 'item-id', {
  organizationId: 'organization-id',
  projectId: 'project-id',
})
```

可選的第三個參數可將清除操作限定在指定租戶的組織及專案範圍內。如資料集不屬於該範圍，或資料項目在資料集中沒有歷史紀錄，伺服器會傳回 `404`。

傳回 `Promise<{ success: boolean }>`。此操作具備冪等性，且無法復原。清除操作會與同時進行的資料項目寫入依序執行或發生衝突，但不保證哪項操作先完成。如修改資料項目的操作在競爭中落後，儲存層會重新讀取清除標記，並以 `DATASET_ITEM_PURGED` 拒絕該操作。刪除操作仍具備冪等性；競爭期間建立的刪除墓碑紀錄亦會保持遮蔽。MongoDB 儲存系統需要支援交易的複本集或分片部署。完整行為請參閱 [`dataset.purgeItem()`](/reference/datasets/purgeItem)。
