# Agents API

Agents API 提供與 Mastra AI Agent 互動的方法，包括產生回應和串流互動，亦提供管理 Agent Tool 的方法。

## 取得所有 Agent {/* #getting-all-agents */}

取得所有可用 Agent 的清單：

```typescript
const agents = await mastraClient.listAgents()
```

傳回以 Agent ID 為鍵、序列化 Agent 設定為值的記錄。

## 使用特定 Agent {/* #working-with-a-specific-agent */}

透過 ID 取得特定 Agent 的實例：

```typescript title="src/mastra/agents/my-agent.ts"
import { Agent } from '@mastra/core/agent'

export const myAgent = new Agent({
  id: 'my-agent',
})
```

```typescript
const agent = mastraClient.getAgent('my-agent')
```

## Agent 方法 {/* #agent-methods */}

### `details()` {/* #details */}

取得 Agent 的詳細資訊：

```typescript
const details = await agent.details()
```

### `generate()` {/* #generate */}

讓 Agent 產生回應：

```typescript
const response = await agent.generate(
  [
    {
      role: 'user',
      content: 'Hello, how are you?',
    },
  ],
  {
    memory: {
      thread: 'thread-abc', // Optional: Thread ID for conversation context
      resource: 'user-123', // Optional: Resource ID
    },
    structuredOutput: {}, // Optional: Structured Output configuration
  },
)
```

您也可以使用帶有記憶體選項的簡化字串格式：

```typescript
const response = await agent.generate('Hello, how are you?', {
  memory: {
    thread: 'thread-1',
    resource: 'resource-1',
  },
})
```

### `stream()` {/* #stream */}

以串流方式接收 Agent 回應，進行即時互動：

```typescript
const response = await agent.stream('Tell me a story')

// Process data stream with the processDataStream util
response.processDataStream({
  onChunk: async chunk => {
    console.log(chunk)
  },
})
```

您也可以使用帶有記憶體選項的簡化字串格式：

```typescript
const response = await agent.stream('Tell me a story', {
  memory: {
    thread: 'thread-1',
    resource: 'resource-1',
  },
  clientTools: { colorChangeTool },
})

response.processDataStream({
  onChunk: async chunk => {
    if (chunk.type === 'text-delta') {
      console.log(chunk.payload.text)
    }
  },
})
```

您也可以直接從回應正文中讀取：

```typescript
const reader = response.body.getReader()
while (true) {
  const { done, value } = await reader.read()
  if (done) break
  console.log(new TextDecoder().decode(value))
}
```

#### 取消串流 {/* #cancelling-a-stream */}

取消回應內容會中止底層 HTTP 請求，並停止尚未執行的客戶端 Tool 及後續請求：

```typescript
const response = await agent.stream('Tell me a story')
const reader = response.body.getReader()

const { value } = await reader.read()
await reader.cancel('user navigated away')
```

亦可傳入 `abortSignal`，從串流外取消請求。`streamUntilIdle()`、`resumeStream()`、`resumeStreamUntilIdle()`、`approveToolCall()`、`declineToolCall()`、`generate()` 和 `generateLegacy()` 同樣支援此選項：

```typescript
const controller = new AbortController()

const response = await agent.stream('Tell me a story', {
  abortSignal: controller.signal,
})

// Later
controller.abort()
```

#### AI SDK 相容格式 {/* #ai-sdk-compatible-format */}

如要在客戶端從 `agent.stream(...)` 的回應串流輸出 AI SDK 格式的資料片段，請將 `response.processDataStream` 包裝成 `ReadableStream<ChunkType>`，再使用 `toAISdkStream`：

```typescript title="client-ai-sdk-transform.ts"
import { createUIMessageStream } from 'ai'
import { toAISdkStream } from '@mastra/ai-sdk'
import type { ChunkType, MastraModelOutput } from '@mastra/core/stream'

const response = await agent.stream('Tell me a story')

const chunkStream: ReadableStream<ChunkType> = new ReadableStream<ChunkType>({
  start(controller) {
    response
      .processDataStream({
        onChunk: async chunk => controller.enqueue(chunk as ChunkType),
      })
      .finally(() => controller.close())
  },
})

const uiMessageStream = createUIMessageStream({
  execute: async ({ writer }) => {
    for await (const part of toAISdkStream(chunkStream as unknown as MastraModelOutput, {
      from: 'agent',
    })) {
      writer.write(part)
    }
  },
})

for await (const part of uiMessageStream) {
  console.log(part)
}
```

### `sendMessage()` {/* #sendmessage */}

將用戶輸入傳送至執行中的 Agent 或閒置的記憶線程。配合 `subscribeToThread()` 使用，客戶端便可顯示訊息喚醒線程或由目前執行接收後產生的串流輸出。

```typescript
const agent = mastraClient.getAgent('support-agent')

const result = await agent.sendMessage({
  message: {
    contents: 'Also consider the customer note I just added.',
    attributes: { sentFrom: 'web' },
  },
  resourceId: 'user-123',
  threadId: 'thread-abc',
})

console.log(result.runId)
```

`message` 接受字串、文字或檔案片段陣列，或包含 `contents`、`attributes`、`metadata` 和 `providerOptions` 的物件。

### `queueMessage()` {/* #queuemessage */}

將用戶輸入加入佇列，供線程下一輪處理。如線程正在執行，Mastra 會在目前執行結束後啟動新的執行；如線程閒置，則會立即啟動。

```typescript
await agent.queueMessage({
  message: 'Also check whether the tests need updates.',
  resourceId: 'user-123',
  threadId: 'thread-abc',
})
```

### `queueSignal()` {/* #queuesignal */}

將帶有類型的訊號加入佇列，供線程下一輪處理。排序方式與 `queueMessage()` 相同，並保留訊號的 `type`、`tagName` 和 `attributes`。

```typescript
await agent.queueSignal({
  signal: {
    type: 'reactive',
    tagName: 'skill',
    attributes: { name: 'triage' },
    contents: 'Triage the new issue.',
  },
  resourceId: 'user-123',
  threadId: 'thread-abc',
})
```

### `sendSignal()` {/* #sendsignal */}

向執行中的 Agent 或記憶線程傳送底層訊號。適用於毋須存入收件匣的系統內容，例如即時提醒或通知類內容。如需長期保存通知紀錄，請使用伺服器端 [`Agent.sendNotificationSignal()`](/reference/agents/agent#sendnotificationsignalnotification-options) API。用戶輸入則優先使用 `sendMessage()` 或 `queueMessage()`。

```typescript
const agent = mastraClient.getAgent('support-agent')

const result = await agent.sendSignal({
  signal: {
    type: 'reactive',
    tagName: 'system-reminder',
    contents: 'Also consider the latest customer note.',
  },
  resourceId: 'user-123',
  threadId: 'thread-abc',
})

console.log(result.runId)
```

使用 `ifActive.behavior` 和 `ifIdle.behavior` 控制 Mastra 如何傳送、儲存或捨棄訊號，以及訊號會否喚醒線程：

```typescript
await agent.sendSignal({
  signal: { type: 'reactive', tagName: 'system-reminder', contents: 'Store this for later.' },
  resourceId: 'user-123',
  threadId: 'thread-abc',
  ifIdle: {
    behavior: 'persist',
  },
})
```

如喚醒閒置線程的串流需要模型設定、Tool 或執行階段上下文等選項，請傳入 `ifIdle.streamOptions`：

```typescript
await agent.sendSignal({
  signal: { type: 'reactive', tagName: 'system-reminder', contents: 'Start from this signal.' },
  resourceId: 'user-123',
  threadId: 'thread-abc',
  ifIdle: {
    behavior: 'wake',
    streamOptions: {
      maxSteps: 3,
    },
  },
})
```

傳回 `{ accepted: true, runId: string }`。

### `subscribeToThread()` {/* #subscribetothread */}

訂閱記憶線程的原始串流資料區塊，以呈現由 `sendMessage()`、`queueMessage()`、`sendSignal()` 或伺服器端通知派發啟動或延續的線程輸出。

```typescript
const agent = mastraClient.getAgent('support-agent')

const subscription = await agent.subscribeToThread({
  resourceId: 'user-123',
  threadId: 'thread-abc',
})

await subscription.processDataStream({
  onChunk: chunk => {
    console.log(chunk)
  },
  reconnect: true,
})
```

傳入 `withInitialHistory: true`（或 `{ perPage }`），即可在第一個 `thread-history` 資料區塊接收已儲存的訊息，毋須另外擷取歷史紀錄。其後不會重播已完成的執行，因此重新連線時不會再次串流輸出已完成的回應。

在 React SDK 中，`useChat()` 會透過 `initialHistoryPagination` 提供首頁的 `hasMore` 標記，讓您毋須再次請求歷史紀錄，便可決定是否提供載入較舊訊息的選項：

```typescript
import { useChat } from '@mastra/react'

const { messages, initialHistoryPagination } = useChat({
  agentId: 'support-agent',
  resourceId: 'user-123',
  threadId: 'thread-abc',
  enableThreadSignals: true,
  withInitialHistory: { perPage: 20 },
})

// { hasMore: true }: older messages exist
// { hasMore: false }: the page reaches the start of the thread
// undefined: history is disabled, still loading, or the subscription ended
```

`initialHistoryPagination` 只描述目前 Agent、資源、線程及 `withInitialHistory` 值所對應的初始訂閱頁面。即時輸出或 `setMessages()` 不會改變此值。自行載入較舊頁面後，請使用該等回應中的 `hasMore` 值。

`subscribeToThread()` 傳回底層 `Response` 及 `processDataStream()` 輔助方法。該方法會持續讀取訂閱串流，直至連線關閉或請求中止。傳入 `reconnect: true` 後，傳輸連線關閉或重新連線失敗時會再次訂閱，例如代理伺服器閒置逾時之後。如重新連線請求傳回 4xx 狀態碼（如 `401` 或 `403`）或 `501`，`processDataStream()` 會停止重試，並以原始 `MastraClientError` 拒絕；`408` 和 `429` 仍會重試。

訂閱亦提供 `abort(options?)` 和 `unsubscribe()`。`await subscription.abort({ clearPendingSignals: true })` 會請求中止執行並清除待處理訊號，但不會關閉訂閱。省略該選項則會保留待處理輸入。`unsubscribe()` 只會關閉訂閱，不會中止執行。

### `abortRun(runId)` {/* #abortrunrunid */}

透過 ID 請求取消持久化執行，包括沒有記憶線程的執行。取消回應內容或中止整個客戶端共用的 `abortSignal`，只會讓觀察端與持久化執行斷開連線。向串流方法傳入單次呼叫專用的 `abortSignal`，則會請求取消執行。如沒有該訊號，請使用 `abortRun()` 停止執行。

```typescript
const runId = crypto.randomUUID()
const response = await agent.stream('Research this topic', { runId })

// When the user chooses Stop:
const { aborted } = await agent.abortRun(runId)
```

<PropertiesTable content={[{ name: 'runId', type: 'string', description: '要取消的持久化執行 ID。' }]} />

傳回 `{ aborted: boolean }`。遠端中止請求以非同步方式處理，因此 `true` 不代表執行程序已停止。未知或已完成的執行會傳回 `false`。此方法要求使用具持久執行能力的 Agent，並具備 Agent 執行權限；執行歸屬檢查同樣適用。啟用細緻授權後，具有記憶線程的執行還需要 `memory:write` 權限。非持久執行 Agent 會傳回 HTTP 501。

### `abortThread()` {/* #abortthread */}

請求取消線程目前的執行。設定 `clearPendingSignals: true`，可在中止前清除待處理訊號。

```typescript
const { aborted } = await agent.abortThread({
  resourceId: 'user-123',
  threadId: 'thread-abc',
  clearPendingSignals: true,
})
```

### `cancelQueuedMessages()` {/* #cancelqueuedmessages */}

取消指定的待處理訊號，而不停止目前的執行。此操作涵蓋處理請求的伺服器程序中，共用同一記憶線程的 Agent 所有待處理輸入。與核心方法不同，SDK 只接受訊號 ID，不接受 `queueOwnerId`。

```typescript
const { cancelledSignalIds } = await agent.cancelQueuedMessages({
  resourceId: 'user-123',
  threadId: 'thread-abc',
  signalIds: ['signal-123', 'signal-456'],
})
```

傳回 `{ cancelledSignalIds: string[] }`，列出接收請求的伺服器程序已取消的各個 ID，每個 ID 只會出現一次。回應不包含遠端確認。已交由執行程序或其他實例處理的訊號不會列入。未提供 ID 清單、清單為空或超出數量上限時，會傳回 HTTP 400。兩個取消端點均受線程歸屬限制。

伺服器會透過共用的 PubSub 後端發佈所有請求取消的 ID，即使接收請求的程序中沒有對應的待處理訊號。其他已訂閱的實例可移除相符的待處理輸入，但這種盡力而為的非同步傳播不會確認遠端取消結果。取消操作不會撤銷已儲存的訊息、狀態更新、通知紀錄或接受確認，亦不會取消由 `continueWithMessages()` 產生的後續執行。

伺服器必須使用支援整個線程取消及中止時清除訊號的核心版本。請同時升級 `@mastra/core` 和 `@mastra/server`。不受支援的請求會傳回 HTTP 501，不會沿用舊版取消行為。啟用細緻授權後，兩個取消端點除了 Agent 執行權限，還需要該線程的 `memory:write` 權限。

### `streamUntilIdle()` {/* #streamuntilidle */}

以串流方式傳回回應，並保持連線，直至本次執行派發的所有[背景任務](/docs/harness/background-tasks)完成。每當一項任務完成，伺服器會重新進入 Agent 循環，讓 LLM 在同一次呼叫中處理結果。此方法要求在 [Mastra 執行個體啟用背景任務](/reference/configuration#backgroundtasks)，並提供記憶線程；否則會改用一般的 `stream()` 呼叫。

```typescript
const response = await agent.streamUntilIdle('Research solana for me', {
  memory: {
    thread: 'thread-1',
    resource: 'resource-1',
  },
  maxIdleMs: 5 * 60_000, //optional
})

response.processDataStream({
  onChunk: async chunk => {
    if (chunk.type === 'background-task-completed') {
      console.log('task complete:', chunk.payload.taskId)
    }
  },
})
```

### `resumeStreamUntilIdle()` {/* #resumestreamuntilidle */}

使用自訂資料恢復已暫停的 Agent 串流，並保持串流開啟，直至本次執行派發的所有[背景任務](/docs/harness/background-tasks)完成。此方法可在暫停點後繼續執行，例如 Agent 內的 Workflow 暫停。必須在 [Mastra 執行個體啟用背景任務](/reference/configuration#backgroundtasks)並提供記憶線程；否則會改用一般的 `resumeStream()` 呼叫：

```typescript
const response = await agent.resumeStreamUntilIdle(
  { approved: true, selectedOption: 'plan-b' },
  {
    memory: {
      thread: 'thread-1',
      resource: 'resource-1',
    },
    runId: 'run-123',
    toolCallId: 'tool-call-456', // optional
    maxIdleMs: 5 * 60_000, //optional
  },
)

await response.processDataStream({
  onChunk: chunk => {
    console.log(chunk)
  },
})
```

此串流會輸出與 `stream()` 相同的資料區塊類型，並額外輸出表示任務生命週期事件的 `background-task-*` 資料區塊。完整的伺服器端 API 請參閱 [`Agent.streamUntilIdle()`](/reference/streaming/agents/streamUntilIdle)；資料結構請參閱[背景任務資料區塊](/reference/streaming/ChunkType#background-task-chunks)。

### `network()` {/* #network */}

來自Agent網路的串流響應以進行多Agent互動：

```typescript
const response = await agent.network('Research this topic and write a summary')

response.processDataStream({
  onChunk: async chunk => {
    console.log(chunk)
  },
})
```

### `listSuspendedRuns()` {/* #listsuspendedruns */}

從儲存空間列出 Agent 已暫停的執行，包括等待核准 Tool 呼叫或因 Tool 暫停而等待的執行。由於查詢以儲存空間為基礎，伺服器重新啟動後及跨伺服器實例仍可取得結果。將傳回的 `runId` 傳給 `approveToolCall()`、`declineToolCall()` 或 `resumeStream()`。

```typescript
const { runs, total } = await agent.listSuspendedRuns({
  threadId: 'thread-456',
  resourceId: 'user-123',
})

if (runs[0]) {
  console.log(runs[0].toolCalls) // [{ toolCallId, toolName, args, requiresApproval }]
  await agent.approveToolCall({
    runId: runs[0].runId,
    toolCallId: runs[0].toolCalls[0].toolCallId,
  })
}
```

支援選用的篩選條件（`threadId`、`resourceId`、`fromDate`、`toDate`）及分頁參數（`perPage`、`page`）。傳回 `{ runs, total }`，其中 `total` 是分頁前符合條件的執行數目。傳回的執行資料結構詳見 [`Agent.listSuspendedRuns()`](/reference/agents/listSuspendedRuns)。

### `approveToolCall()` {/* #approvetoolcall */}

批准待處理的Tool呼叫並返回連續流。當您渲染批准回應中復原的區塊時，請使用此選項。

```typescript
const response = await agent.approveToolCall({
  runId: 'run-123',
  toolCallId: 'tool-call-456',
})

response.processDataStream({
  onChunk: async chunk => {
    console.log(chunk)
  },
})
```

### `sendToolApproval()` {/* #sendtoolapproval */}

核准或拒絕已訂閱線程中待處理的 Tool 呼叫。如希望恢復執行後的資料區塊透過現有線程訂閱傳送，而非另開後續串流，請與 `subscribeToThread()` 一起使用。

```typescript
const result = await agent.sendToolApproval({
  resourceId: 'user-123',
  threadId: 'thread-456',
  toolCallId: 'tool-call-456',
  approved: true,
})

console.log(result.accepted)
```

傳回 `{ accepted: true, runId: string, toolCallId?: string }`。

### `declineToolCall()` {/* #declinetoolcall */}

拒絕待處理的 Tool 呼叫並傳回後續串流。需要呈現拒絕回應中恢復執行後的資料區塊時，請使用此方法。可傳入選用的 `reason`，告知模型呼叫遭拒的原因。預設值為 `Tool call was not approved by the user`。

```typescript
const response = await agent.declineToolCall({
  runId: 'run-123',
  toolCallId: 'tool-call-456',
  reason: 'This file is outside the allowed directory', // optional
})

response.processDataStream({
  onChunk: async chunk => {
    console.log(chunk)
  },
})
```

### `resumeStream()` {/* #resumestream */}

使用自訂資料恢復暫停的Agent程式流。使用它可以在暫停點後繼續執行，例如Agent內的Workflow暫停：

```typescript
const response = await agent.resumeStream(
  { approved: true, selectedOption: 'plan-b' },
  {
    runId: 'run-123',
    toolCallId: 'tool-call-456', // optional
  },
)

await response.processDataStream({
  onChunk: chunk => {
    console.log(chunk)
  },
})
```

### `approveToolCallGenerate()` {/* #approvetoolcallgenerate */}

使用 `generate()`（非串流）時，核准待處理的 Tool 呼叫。傳回完整回應：

## 客戶端Tool {/* #client-tools */}

客戶端Tool可讓您在Agent請求時在客戶端執行自訂功能。

```typescript
import { createTool } from '@mastra/client-js'
import { z } from 'zod'

const colorChangeTool = createTool({
  id: 'changeColor',
  description: 'Changes the background color',
  inputSchema: z.object({
    color: z.string(),
  }),
  execute: async inputData => {
    document.body.style.backgroundColor = inputData.color
    return { success: true }
  },
})

// Use with generate
const response = await agent.generate('Change the background to blue', {
  clientTools: { colorChangeTool },
})

// Use with stream
const response = await agent.stream('Tell me a story', {
  memory: {
    thread: 'thread-1',
    resource: 'resource-1',
  },
  clientTools: { colorChangeTool },
})

response.processDataStream({
  onChunk: async chunk => {
    if (chunk.type === 'text-delta') {
      console.log(chunk.payload.text)
    } else if (chunk.type === 'tool-call') {
      console.log(
        `calling tool ${chunk.payload.toolName} with args ${JSON.stringify(
          chunk.payload.args,
          null,
          2,
        )}`,
      )
    }
  },
})
```

### 塑造模型的客戶端Tool輸出 {/* #shape-client-tool-output-for-the-model */}

客戶端 Tool 支援 `toModelOutput`，可控制模型收到的內容，包括圖片等多模態內容。由於客戶端 Tool 在本機執行，對應轉換亦會在 `execute` 完成後於客戶端進行。客戶端會將轉換後的輸出及原始結果一併傳回伺服器，讓原始結果仍可供儲存及應用程式邏輯使用。

```typescript
const screenshotTool = createTool({
  id: 'takeScreenshot',
  description: 'Takes a screenshot of the current page',
  inputSchema: z.object({}),
  execute: async () => {
    const base64 = await captureScreenshot()
    return { ok: true, data: base64 }
  },
  toModelOutput: output => ({
    type: 'content',
    value: [{ type: 'media', data: output.data, mediaType: 'image/jpeg' }],
  }),
})
```

### 追蹤客戶端Tool {/* #tracing-client-tools */}

伺服器端安裝並設定 `@mastra/observability` 後，客戶端 Tool 會記錄 `CLIENT_TOOL_CALL` span，作為目前 `AGENT_RUN` span 的子節點。模型發出客戶端 Tool 呼叫時，伺服器會建立該 span，並將 W3C Trace 上下文注入送出的 Tool 呼叫資料區塊；Tool 參數就緒後，該 span 隨即結束。如伺服器端未設定可觀測性，客戶端 Tool 追蹤不會產生任何效果。

客戶端 SDK 亦會量度每個客戶端 Tool 的 `execute` 函式實際耗時，並將數值傳回伺服器，以 `toolType: "client"` 的 `mastra_tool_duration_ms` 指標輸出。

如要從 Tool 的 `execute` 函式取得更詳細的遙測資料，可使用執行上下文中的 `observe` 輔助方法新增子 span 和結構化日誌：

```typescript
import { createTool } from '@mastra/client-js'
import { z } from 'zod'

const fetchUserTool = createTool({
  id: 'fetchUser',
  description: 'Fetches the current user profile',
  inputSchema: z.object({ userId: z.string() }),
  execute: async ({ userId }, { observe }) => {
    observe.log('info', 'fetching user', { userId })
    const user = await observe.span('http GET /users', async () => {
      const res = await fetch(`/api/users/${userId}`)
      return res.json()
    })
    return user
  },
})
```

`observe` 始終可用。沒有啟用追蹤上下文時（例如在受追蹤的 Agent 以外執行），`span` 會直接執行函式，而 `log` 不會執行任何操作；毋須檢查是否為 null。

SDK 會將收集器緩衝的所有內容序列化為 OTLP/JSON，並在下一個請求的內容中送回伺服器。伺服器端的 `@mastra/observability` 套件會驗證各個 span 屬於正確的追蹤（以防止跨追蹤注入），並將每個 span 和日誌轉送至伺服器端遙測共用的可觀測性匯流排。設定可觀測性後，現有匯出器便會自動接收這些資料。

## 儲存Agent {/* #stored-agents */}

儲存型 Agent 是保存在資料庫中的 Agent 設定，可在執行期間建立、更新及刪除。設定透過鍵參照 Tool、Workflow、其他 Agent 及評分器等元件；建立 Agent 執行個體時，Mastra 會從登錄表解析這些參照。記憶功能以內嵌的 `SerializedMemoryConfig` 物件設定，可指定 `lastMessages` 和 `semanticRecall` 等選項。

### `listStoredAgents()` {/* #liststoredagents */}

檢索所有儲存Agent程式的分頁清單：

```typescript
const result = await mastraClient.listStoredAgents()
console.log(result.agents) // Array of stored agents
console.log(result.total) // Total count
```

具有分頁和排序功能：

```typescript
const result = await mastraClient.listStoredAgents({
  page: 0,
  perPage: 20,
  orderBy: {
    field: 'createdAt',
    direction: 'DESC',
  },
})
```

### `createStoredAgent()` {/* #createstoredagent */}

建立一個新的儲存Agent：

```typescript
const agent = await mastraClient.createStoredAgent({
  id: 'my-agent',
  name: 'My Assistant',
  instructions: 'You are a helpful assistant.',
  model: {
    provider: 'openai',
    name: 'gpt-5.4',
  },
})
```

預設情況下，`createStoredAgent()` 會立即發佈初始版本。將 `autoPublish` 設為 `false`，即可建立尚未發佈的草稿，並在呼叫 [`activateVersion()`](#activateversion) 前先行檢視：

```typescript
const draft = await mastraClient.createStoredAgent({
  id: 'draft-agent',
  name: 'Draft Assistant',
  instructions: 'You are a helpful assistant.',
  model: {
    provider: 'openai',
    name: '__AI_SDK_OPENAI_MODEL_BASE__',
  },
  autoPublish: false,
})
```

設定為 `code` 來源的編輯器，一律會發佈初始版本，因為儲存時會將 Agent 設定寫入檔案系統。

具有所有選項：

```typescript
const agent = await mastraClient.createStoredAgent({
  id: 'full-agent',
  name: 'Full Agent',
  description: 'A fully configured agent',
  instructions: 'You are a helpful assistant.',
  model: {
    provider: 'openai',
    name: 'gpt-5.4',
  },
  tools: { calculator: {}, weather: {} },
  workflows: { 'data-processing': {} },
  agents: { 'subagent-1': {} },
  memory: {
    options: {
      lastMessages: 20,
      semanticRecall: false,
    },
  },
  scorers: {
    'quality-scorer': {
      sampling: { type: 'ratio', rate: 0.1 },
    },
  },
  defaultOptions: {
    maxSteps: 10,
  },
  metadata: {
    version: '1.0',
    team: 'engineering',
  },
  durable: true,
})
```

#### 儲存Agent程式的可恢復流 {/* #resumable-streams-for-stored-agents */}

設定 `durable`，即可為載入設定後的一般 Agent 配置[可恢復串流](/docs/agents/resumable-streams)。傳入 `true` 以啟用、`false` 以停用，或傳入物件以調整串流清理方式：

```typescript
const agent = await mastraClient.createStoredAgent({
  id: 'durable-agent',
  name: 'Durable Agent',
  instructions: 'You are a helpful assistant.',
  model: {
    provider: 'openai',
    name: 'gpt-5.4',
  },
  durable: { cleanupTimeoutMs: 0 },
})
```

只接受可序列化的選項；快取及 pubsub 設定繼承自伺服器的 `Mastra` 實例。現有儲存型 Agent 的 `durable: true` 欄位同樣只用於可恢復串流。如需保留持久化執行及檢查點恢復功能，請註冊以 `createDurableAgent({ agent })` 包裝的程式碼定義 Agent。
