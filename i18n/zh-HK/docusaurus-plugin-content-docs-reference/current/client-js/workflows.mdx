# Workflow API

Workflow API 提供與 Mastra 中的自動化 Workflow 互動及執行 Workflow 的方法。

## 取得所有 Workflow {/* #getting-all-workflows */}

取得所有可用 Workflow 的清單：

```typescript
const workflows = await mastraClient.listWorkflows()
```

## 取得 Workflow 執行次數 {/* #getting-workflow-run-counts */}

單次請求即可取得各 Workflow 處於 `running` 和 [`suspended`](/docs/workflows/suspend-and-resume) 狀態的執行次數。次數由伺服器計算，並以 Workflow 在 Mastra 設定中註冊時使用的登記鍵為索引；此鍵可能與 Workflow 本身的 `id` 不同：

```typescript
const runCounts = await mastraClient.listWorkflowRunCounts()
// { "cityWorkflow": { running: 2, suspended: 1 }, ... }
```

返回：`Record<string, { running: number; suspended: number }>`

伺服器可能會將次數快取數秒。尚未提供此端點的舊版伺服器會回傳 `404 Not Found`。如果客戶端可能連接舊版部署，請處理此錯誤。

## 使用特定 Workflow {/* #working-with-a-specific-workflow */}

透過 ID 取得特定 Workflow 的實例：

```typescript title="src/mastra/workflows/test-workflow.ts"
import { createWorkflow } from '@mastra/core/workflows'

export const testWorkflow = createWorkflow({
  id: 'city-workflow',
})
```

```typescript
const workflow = mastraClient.getWorkflow('city-workflow')
```

## Workflow 方法 {/* #workflow-methods */}

### `details()` {/* #details */}

取得 Workflow 的詳細資訊：

```typescript
const details = await workflow.details()
```

### `createRun()` {/* #createrun */}

建立新的 Workflow 執行實例：

```typescript
const run = await workflow.createRun()

// Or with an existing runId
const run = await workflow.createRun({ runId: 'existing-run-id' })

// Or with a resourceId to associate the run with a specific resource
const run = await workflow.createRun({
  runId: 'my-run-id',
  resourceId: 'user-123',
})
```

`resourceId` 參數會將 Workflow 執行與指定資源（例如用戶 ID 或租戶 ID）關聯。此值會連同執行紀錄儲存，供日後篩選及查詢。

### `startAsync()` {/* #startasync */}

啟動 Workflow 執行並等待完成，傳回完整的 Workflow 輸出。

```typescript
const run = await workflow.createRun()

const result = await run.startAsync({
  inputData: {
    city: 'New York',
  },
})
```

你亦可傳入 `initialState`，設定 Workflow 狀態的初始值：

```typescript
const result = await run.startAsync({
  inputData: {
    city: 'New York',
  },
  initialState: {
    count: 0,
    items: [],
  },
})
```

`initialState` 物件的結構應符合 Workflow 的 `stateSchema` 定義。詳見 [Workflow 狀態](/docs/workflows/workflow-state)。

若要將執行與指定資源關聯，請向 `createRun()` 傳入 `resourceId`：

```typescript
const run = await workflow.createRun({ resourceId: 'user-123' })

const result = await run.startAsync({
  inputData: {
    city: 'New York',
  },
})
```

### `start()` {/* #start */}

啟動 Workflow 執行而毋須等待完成。此方法會立即回傳成功訊息；之後可在 Workflow 實例上呼叫 `runById()` 查詢結果：

```typescript
const run = await workflow.createRun()

await run.start({
  inputData: {
    city: 'New York',
  },
})

// Poll for results later
const result = await workflow.runById(run.runId)
```

此方式適合需要先啟動、稍後再查詢結果的長時間執行 Workflow。

### `resumeAsync()` {/* #resumeasync */}

恢復已暫停的 Workflow 步驟並等待完整結果：

```typescript
const run = await workflow.createRun({ runId: prevRunId })

const result = await run.resumeAsync({
  step: 'step-id',
  resumeData: { key: 'value' },
})
```

### `resume()` {/* #resume */}

恢復已暫停的 Workflow 步驟，毋須等待完成：

```typescript
const run = await workflow.createRun({ runId: prevRunId })

await run.resume({
  step: 'step-id',
  resumeData: { key: 'value' },
})
```

如果 [`.foreach()`](/reference/workflows/workflow-methods/foreach) 步驟有多個迭代暫停，可傳入從零開始計算的 `forEachIndex`，逐一恢復迭代；`0` 指第一個迭代。未指定的迭代會維持暫停。

```typescript
await run.resume({
  step: 'approve',
  resumeData: { ok: true },
  forEachIndex: 1, // resumes the second iteration
})
```

`resumeAsync()` 和 `resumeStream()` 亦支援 `forEachIndex`。

### `cancel()` {/* #cancel */}

取消正在執行的 Workflow：

```typescript
const run = await workflow.createRun({ runId: existingRunId })

const result = await run.cancel()
// Returns: { message: 'Workflow run canceled' }
```

此方法會停止正在執行的步驟，並阻止後續步驟執行。檢查 `abortSignal` 參數的步驟可清理計時器、網絡請求等資源，以回應取消操作。

取消機制及如何編寫回應取消操作的步驟，詳見 [Run.cancel()](/reference/workflows/run-methods/cancel) 參考文件。

### `stream()` {/* #stream */}

以串流方式取得 Workflow 執行的即時更新：

```typescript
const run = await workflow.createRun()

const stream = await run.stream({
  inputData: {
    city: 'New York',
  },
})

for await (const chunk of stream) {
  console.log(JSON.stringify(chunk, null, 2))
}
```

### `runById()` {/* #runbyid */}

取得 Workflow 執行的結果：

```typescript
const result = await workflow.runById(runId)

// Or with options for performance optimization:
const result = await workflow.runById(runId, {
  fields: ['status', 'result'], // Only fetch specific fields
  withNestedWorkflows: false, // Skip expensive nested workflow data
  requestContext: { userId: 'user-123' }, // Optional request context
})
```

## 動態 Workflow {/* #dynamic-workflows */}

:::beta

在 API 穩定之前，即使未提升主要版本號，亦可能出現破壞性變更。

:::

動態 Workflow 是以 JSON 表示的 Workflow 定義。伺服器會儲存每個定義，並註冊為可執行的 Workflow。定義格式詳見[動態 Workflow](/docs/workflows/dynamic-workflows)。

### `listDynamicWorkflows()` {/* #listdynamicworkflows */}

列出動態 Workflow 定義，可按 `status`（`'active' | 'archived'`）及 `authorId` 篩選：

```typescript
const { definitions, total } = await mastraClient.listDynamicWorkflows({
  status: 'active',
})
```

### `upsertDynamicWorkflow()` {/* #upsertdynamicworkflow */}

建立或取代動態 Workflow 定義。伺服器會驗證並儲存定義，再即時註冊以供執行：

```typescript
const stored = await mastraClient.upsertDynamicWorkflow({
  id: 'greeting-workflow',
  description: 'Returns a greeting for the supplied name',
  inputSchema: {
    type: 'object',
    properties: { name: { type: 'string' } },
    required: ['name'],
  },
  outputSchema: {
    type: 'object',
    properties: { message: { type: 'string' } },
    required: ['message'],
  },
  graph: [
    {
      type: 'mapping',
      id: 'create-greeting',
      mapConfig: JSON.stringify({
        message: { template: 'Hello, ${initData.name}!' },
      }),
    },
  ],
})
```

如果根定義包含尚不存在的輔助 Workflow，請透過 `dependencies` 在同一請求中提交其定義。伺服器會將整組定義一併驗證和註冊，並透過 `dependencyIds` 回傳輔助 Workflow 的 ID：

```typescript
const stored = await mastraClient.upsertDynamicWorkflow({
  id: 'root-workflow',
  // ...schemas and graph referencing 'helper-workflow'...
  dependencies: [helperDefinition],
})

console.log(stored.dependencyIds) // ['helper-workflow']
```

### `getDynamicWorkflow()` {/* #getdynamicworkflow */}

取得用於管理定義的動態 Workflow 實例。若要執行動態 Workflow，請像其他 Workflow 一樣使用 `getWorkflow(id).createRun()`：

```typescript
const dynamicWorkflow = mastraClient.getDynamicWorkflow('greeting-workflow')
```

### `dynamicWorkflow.details()` {/* #dynamicworkflowdetails */}

取得已儲存的定義，包括 schema、graph、狀態和時間戳記：

```typescript
const definition = await dynamicWorkflow.details()
```

### `dynamicWorkflow.delete()` {/* #dynamicworkflowdelete */}

刪除已儲存的定義，並取消註冊執行中的 Workflow：

```typescript
await dynamicWorkflow.delete()
```

### 執行動態Workflow {/* #executing-a-dynamic-workflow */}

註冊後，動態 Workflow 即可透過一般 Workflow API 執行：

```typescript
const workflow = mastraClient.getWorkflow('greeting-workflow')
const run = await workflow.createRun()
const result = await run.startAsync({ inputData: { name: 'Ada' } })
```

## 時間表 {/* #schedules */}

排程透過 `createWorkflow` 的 `schedule` 欄位在程式碼中宣告。Client SDK 提供讀取及操作方法，可在執行期間管理 Workflow 排程。詳見[排程 Workflow](/docs/workflows/scheduled-workflows)。

### `createSchedule()` {/* #createschedule */}

傳入 `workflowId`，建立 Workflow 排程。

```typescript
const schedule = await mastraClient.createSchedule({
  workflowId: 'daily-report',
  cron: '0 9 * * *',
  inputData: { reportType: 'summary' },
})
```

### `listSchedules()` {/* #listschedules */}

列出 Workflow 排程，可按 Workflow ID 或狀態篩選。

```typescript
const schedules = await mastraClient.listSchedules({
  workflowId: 'daily-report',
  status: 'active',
})
```

### `getSchedule()` {/* #getschedule */}

按 ID 取得單一 Workflow 排程。

```typescript
const schedule = await mastraClient.getSchedule('daily-report')
```

### `updateSchedule()` {/* #updateschedule */}

更新 Workflow 排程。

```typescript
const updated = await mastraClient.updateSchedule('daily-report', {
  cron: '0 10 * * *',
  inputData: { reportType: 'summary' },
})
```

### `deleteSchedule()` {/* #deleteschedule */}

刪除 Workflow 排程。

```typescript
await mastraClient.deleteSchedule('daily-report')
```

### `runSchedule()` {/* #runschedule */}

立即觸發一次 Workflow 排程，而不更改其 cron 執行週期。

```typescript
const run = await mastraClient.runSchedule('daily-report')
```

### `pauseSchedule()` {/* #pauseschedule */}

暫停排程，讓排程器停止觸發。傳回更新後的排程。

```typescript
await mastraClient.pauseSchedule('daily-report')
```

### `resumeSchedule()` {/* #resumeschedule */}

恢復已暫停的排程。系統會從目前時間重新計算下次觸發時間，因此不會補觸發暫停期間錯過的執行。傳回更新後的排程。

```typescript
await mastraClient.resumeSchedule('daily-report')
```

### `listScheduleTriggers()` {/* #listscheduletriggers */}

列出 Workflow 排程的觸發紀錄，包括每次觸發所關聯的執行摘要。

```typescript
const { triggers } = await mastraClient.listScheduleTriggers('daily-report', {
  limit: 50,
})
```
