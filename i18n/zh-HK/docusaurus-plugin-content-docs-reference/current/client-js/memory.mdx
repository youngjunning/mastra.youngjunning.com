# 記憶體API

Memory API 提供了管理 Mastra 中的對話線程和訊息歷史記錄的方法。

## 獲取所有線程 {/* #get-all-threads */}

檢索特定資源的所有記憶體線程：

```typescript
const threads = await mastraClient.listMemoryThreads({
  resourceId: 'resource-1',
  agentId: 'agent-1', // Optional - can be omitted if storage is configured
})
```

什麼時候`agentId` is omitted and storage is configured on the server, threads will be retrieved using storage directly. This is useful when multiple agents share the same threads (e.g., in workflows with multiple agent steps).

## 建立一個新線程 {/* #create-a-new-thread */}

建立一個新的記憶體線程：

```typescript
const thread = await mastraClient.createMemoryThread({
  title: 'New Conversation',
  metadata: { category: 'support' },
  resourceId: 'resource-1',
  agentId: 'agent-1',
})
```

## 使用特定線程 {/* #working-with-a-specific-thread */}

取得特定記憶體線程的實例：

```typescript
const thread = mastraClient.getMemoryThread({ threadId: 'thread-id', agentId: 'agent-id' })
```

## 執行緒方法 {/* #thread-methods */}

### 獲取話題詳細信息 {/* #get-thread-details */}

檢索有關特定線程的詳細資訊：

```typescript
const details = await thread.get()
```

### 更新主題 {/* #update-thread */}

更新線程屬性：

```typescript
const updated = await thread.update({
  title: 'Updated Title',
  metadata: { status: 'resolved' },
  resourceId: 'resource-1',
})
```

### 刪除話題 {/* #delete-thread */}

刪除線程及其訊息：

```typescript
await thread.delete()
```

### 克隆執行緒 {/* #clone-thread */}

建立包含所有訊息的執行緒的副本：

```typescript
const { thread: clonedThread, clonedMessages } = await thread.clone()
```

使用選項克隆：

```typescript
const { thread: clonedThread, clonedMessages } = await thread.clone({
  newThreadId: 'custom-clone-id',
  title: 'Cloned Conversation',
  metadata: { branch: 'experiment-1' },
  options: {
    messageLimit: 10, // Only clone last 10 messages
  },
})
```

使用訊息過濾進行克隆：

```typescript
const { thread: clonedThread } = await thread.clone({
  options: {
    messageFilter: {
      startDate: new Date('2024-01-01'),
      endDate: new Date('2024-01-31'),
    },
  },
})
```

克隆響應包括：

* `thread`：新創建的克隆線程，帶有克隆元數據
* `clonedMessages`：具有新 ID 的複製訊息數組

## 訊息操作 {/* #message-operations */}

### 儲存訊息 {/* #save-messages */}

將訊息儲存到記憶體：

```typescript
const result = await mastraClient.saveMessageToMemory({
  messages: [
    {
      role: 'user',
      content: 'Hello!',
      id: '1',
      threadId: 'thread-1',
      resourceId: 'resource-1',
      createdAt: new Date(),
      format: 2,
    },
  ],
  agentId: 'agent-1',
})

// result.messages contains the saved messages
console.log(result.messages)
```

### 檢索主題訊息 {/* #retrieve-thread-messages */}

取得與記憶體線程關聯的訊息：

```typescript
// Get all messages in the thread (paginated)
const result = await thread.listMessages()
console.log(result.messages) // Array of messages
console.log(result.total) // Total count
console.log(result.hasMore) // Whether more pages exist

// Get messages with pagination
const result = await thread.listMessages({
  page: 0,
  perPage: 20,
})

// Get messages with ordering
const result = await thread.listMessages({
  orderBy: { field: 'createdAt', direction: 'ASC' },
})

// Get messages with shallow metadata filters
const result = await thread.listMessages({
  filter: {
    metadata: {
      category: 'billing',
      escalated: true,
      priority: 2,
      archivedAt: null,
    },
  },
})
```

元資料過濾器僅匹配淺標量值：`string`, finite `number`, `boolean`, and `null`. Every key-value pair must match with AND semantics. `null` matches only keys explicitly set to `null`. Metadata keys must start with a letter or underscore and contain only alphanumeric or underscore characters. The limit is 128 characters. Reserved prototype keys such as `__proto__`, `constructor`, and `prototype` aren't allowed. Performance depends on the server storage backend, and arbitrary metadata filters may scan candidate messages.

### 刪除訊息 {/* #delete-messages */}

從執行緒中刪除一條或多條訊息：

```typescript
// Delete a single message
const result = await thread.deleteMessages('message-id')

// Delete multiple messages
const result = await thread.deleteMessages(['message-1', 'message-2', 'message-3'])

// Returns: { success: true, message: "Message deleted successfully" }
```

## 工作記憶 {/* #working-memory */}

工作記憶允許Agent在互動過程中維護有關使用者的持久資訊。它的作用域可以是特定線程，也可以是資源（使用者）的所有線程。

### 獲得工作記憶 {/* #get-working-memory */}

檢索線程的當前工作記憶體：

```typescript
const workingMemory = await mastraClient.getWorkingMemory({
  agentId: 'agent-1',
  threadId: 'thread-1',
  resourceId: 'user-123', // Optional, required for resource-scoped memory
})
```

回應內容包括：

* `workingMemory`：目前工作記憶體內容（字串或`null`). When using a JSON or schema-based working memory template, the content is a JSON-encoded string
* `source`: 記憶是否來自`"thread"` or `"resource"` scope
* `workingMemoryTemplate`：用於工作記憶的範本（如果配置）
* `threadExists`: 線程是否存在

### 更新工作記憶 {/* #update-working-memory */}

更新線程的工作記憶體內容：

```typescript
await mastraClient.updateWorkingMemory({
  agentId: 'agent-1',
  threadId: 'thread-1',
  workingMemory: `# User Profile
- Name: John Doe
- Location: New York
- Preferences: Prefers formal communication
`,
  resourceId: 'user-123', // Optional, required for resource-scoped memory
})

// Returns: { success: true }
```

對於資源範圍的工作內存，您必須提供`resourceId` parameter. It allows the memory to persist across all conversation threads for that user.

預設情況下，呼叫會取代整個記錄。對於基於模式、資源範圍的工作內存，透過`mode: 'merge'` with a JSON object string to deep-merge only the provided fields atomically. The server returns `400` if the storage adapter doesn't support atomic merges (currently only `@mastra/pg` does).

```typescript
await mastraClient.updateWorkingMemory({
  agentId: 'agent-1',
  threadId: 'thread-1',
  resourceId: 'user-123',
  workingMemory: JSON.stringify({ city: 'Berlin' }),
  mode: 'merge',
})
```

### 取得記憶體狀態 {/* #get-memory-status */}

檢查記憶體系統的狀態：

```typescript
const status = await mastraClient.getMemoryStatus('agent-id')
```
