# Memory API

Memory API 提供管理 Mastra 對話執行緒及訊息記錄的方法。

## 取得所有執行緒 {/* #get-all-threads */}

取得指定資源的所有記憶執行緒：

```typescript
const threads = await mastraClient.listMemoryThreads({
  resourceId: 'resource-1',
  agentId: 'agent-1', // Optional - can be omitted if storage is configured
})
```

如果省略 `agentId`，而伺服器已設定儲存空間，系統會直接從儲存空間取得執行緒。這適用於多個 Agent 共用執行緒的情況，例如包含多個 Agent 步驟的 Workflow。

## 建立新執行緒 {/* #create-a-new-thread */}

建立記憶執行緒：

```typescript
const thread = await mastraClient.createMemoryThread({
  title: 'New Conversation',
  metadata: { category: 'support' },
  resourceId: 'resource-1',
  agentId: 'agent-1',
})
```

## 操作指定執行緒 {/* #working-with-a-specific-thread */}

取得指定記憶執行緒的實例：

```typescript
const thread = mastraClient.getMemoryThread({ threadId: 'thread-id', agentId: 'agent-id' })
```

## 執行緒方法 {/* #thread-methods */}

### 取得執行緒詳情 {/* #get-thread-details */}

取得指定執行緒的詳情：

```typescript
const details = await thread.get()
```

### 更新執行緒 {/* #update-thread */}

更新執行緒屬性：

```typescript
const updated = await thread.update({
  title: 'Updated Title',
  metadata: { status: 'resolved' },
  resourceId: 'resource-1',
})
```

### 刪除執行緒 {/* #delete-thread */}

刪除執行緒及其訊息：

```typescript
await thread.delete()
```

### 複製執行緒 {/* #clone-thread */}

建立包含所有訊息的執行緒副本：

```typescript
const { thread: clonedThread, clonedMessages } = await thread.clone()
```

指定選項複製：

```typescript
const { thread: clonedThread, clonedMessages } = await thread.clone({
  newThreadId: 'custom-clone-id',
  title: 'Cloned Conversation',
  metadata: { branch: 'experiment-1' },
  options: {
    messageLimit: 10, // Only clone last 10 messages
  },
})
```

篩選訊息後複製：

```typescript
const { thread: clonedThread } = await thread.clone({
  options: {
    messageFilter: {
      startDate: new Date('2024-01-01'),
      endDate: new Date('2024-01-31'),
    },
  },
})
```

複製結果包括：

* `thread`：新建立的執行緒副本，包含複製元資料
* `clonedMessages`：複製後的訊息陣列，每則訊息都有新的 ID

## 訊息操作 {/* #message-operations */}

### 儲存訊息 {/* #save-messages */}

將訊息儲存到記憶系統：

```typescript
const result = await mastraClient.saveMessageToMemory({
  messages: [
    {
      role: 'user',
      content: 'Hello!',
      id: '1',
      threadId: 'thread-1',
      resourceId: 'resource-1',
      createdAt: new Date(),
      format: 2,
    },
  ],
  agentId: 'agent-1',
})

// result.messages contains the saved messages
console.log(result.messages)
```

### 取得執行緒訊息 {/* #retrieve-thread-messages */}

取得記憶執行緒中的訊息：

```typescript
// Get all messages in the thread (paginated)
const result = await thread.listMessages()
console.log(result.messages) // Array of messages
console.log(result.total) // Total count
console.log(result.hasMore) // Whether more pages exist

// Get messages with pagination
const result = await thread.listMessages({
  page: 0,
  perPage: 20,
})

// Get messages with ordering
const result = await thread.listMessages({
  orderBy: { field: 'createdAt', direction: 'ASC' },
})

// Get messages with shallow metadata filters
const result = await thread.listMessages({
  filter: {
    metadata: {
      category: 'billing',
      escalated: true,
      priority: 2,
      archivedAt: null,
    },
  },
})
```

元資料篩選條件只比對淺層純量值：`string`、有限的 `number`、`boolean` 和 `null`。所有鍵值配對都必須符合（AND 邏輯）。`null` 只會比對明確設為 `null` 的鍵。元資料鍵必須以字母或底線開頭，而且只能包含英數字元或底線，長度上限為 128 個字元。不允許使用 `__proto__`、`constructor` 和 `prototype` 等保留的原型鍵。效能取決於伺服器的儲存後端；任意元資料篩選條件可能需要掃描候選訊息。

### 刪除訊息 {/* #delete-messages */}

從執行緒刪除一則或多則訊息：

```typescript
// Delete a single message
const result = await thread.deleteMessages('message-id')

// Delete multiple messages
const result = await thread.deleteMessages(['message-1', 'message-2', 'message-3'])

// Returns: { success: true, message: "Message deleted successfully" }
```

## 工作記憶 {/* #working-memory */}

工作記憶讓 Agent 在多次互動中保留使用者資訊。作用範圍可以是單一執行緒，也可以是某個資源（使用者）的所有執行緒。

### 取得工作記憶 {/* #get-working-memory */}

取得執行緒目前的工作記憶：

```typescript
const workingMemory = await mastraClient.getWorkingMemory({
  agentId: 'agent-1',
  threadId: 'thread-1',
  resourceId: 'user-123', // Optional, required for resource-scoped memory
})
```

回應包括：

* `workingMemory`：目前的工作記憶內容，為字串或 `null`；使用 JSON 或按 schema 定義的工作記憶範本時，內容是 JSON 編碼字串
* `source`：工作記憶來自 `"thread"` 或 `"resource"` 範圍
* `workingMemoryTemplate`：工作記憶使用的範本（如已設定）
* `threadExists`：執行緒是否存在

### 更新工作記憶 {/* #update-working-memory */}

更新執行緒的工作記憶內容：

```typescript
await mastraClient.updateWorkingMemory({
  agentId: 'agent-1',
  threadId: 'thread-1',
  workingMemory: `# User Profile
- Name: John Doe
- Location: New York
- Preferences: Prefers formal communication
`,
  resourceId: 'user-123', // Optional, required for resource-scoped memory
})

// Returns: { success: true }
```

使用資源層級的工作記憶時，必須提供 `resourceId` 參數，讓該使用者的工作記憶在所有對話執行緒之間保留。

預設情況下，呼叫會取代整筆記錄。對於按 schema 定義、作用於資源層級的工作記憶，可傳入 `mode: 'merge'` 和 JSON 物件字串，以原子方式深層合併指定欄位。如果儲存適配器不支援原子合併，伺服器會傳回 `400`；目前只有 `@mastra/pg` 支援。

```typescript
await mastraClient.updateWorkingMemory({
  agentId: 'agent-1',
  threadId: 'thread-1',
  resourceId: 'user-123',
  workingMemory: JSON.stringify({ city: 'Berlin' }),
  mode: 'merge',
})
```

### 取得記憶系統狀態 {/* #get-memory-status */}

檢查記憶系統的狀態：

```typescript
const status = await mastraClient.getMemoryStatus('agent-id')
```
