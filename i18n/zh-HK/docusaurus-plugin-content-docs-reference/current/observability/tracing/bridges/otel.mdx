# OtelBridge

:::warning

OpenTelemetry Bridge 目前仍處於**實驗階段**。API 及設定選項可能在後續版本中變更。

:::

將 Mastra 追蹤與 OpenTelemetry 基礎設施雙向整合：為 Mastra 操作建立原生 OTEL span，並繼承目前 OTEL span 的上下文。它亦會將 Mastra 日誌事件轉送至全域註冊的 OTEL `LoggerProvider`，在事件來源 Mastra span 的 OTEL 上下文中發出日誌，自動關聯追蹤與日誌。

### `onLogEvent` {/* #onlogevent */}

```typescript oxfmt:false
async onLogEvent(event: LogEvent): Promise<void>
```

將 Mastra 日誌事件轉送至全域註冊的 OTEL `LoggerProvider`。追蹤關聯按以下順序判定：

1. 如日誌中的 `spanId` 對應 bridge 持有的 OTEL span，則在該 span 儲存的 OTEL 上下文中發出日誌。
1. 否則，如日誌同時包含 `traceId` 及 `spanId`，則將這兩個 ID 附加至所發出日誌記錄的 `SpanContext`。
1. 否則，在目前生效的 OTEL 上下文中發出日誌。

如沒有全域註冊的 `LoggerProvider`，則不發出日誌，也不報錯。

### `flush` {/* #flush */}

```typescript oxfmt:false
async flush(): Promise<void>
```

如 tracer provider 及 logger provider 支援 `forceFlush`，就強制清空其緩衝資料。全域 provider 會在清空時取得，因此即使 `LoggerProvider` 在 bridge 建立後才註冊，也會一併處理。這適用於需要在執行環境終止前送出遙測資料的無伺服器環境。程序結束前亦應呼叫 `sdk.shutdown()`，等待 OTEL SDK 已開始匯出的批次；此方法及 provider 自身的 `forceFlush()` 都不會等待該批次。

### `shutdown` {/* #shutdown */}

```typescript oxfmt:false
async shutdown(): Promise<void>
```

關閉 bridge 並清理資源。先結束未正確關閉的 span，再清空 provider 的緩衝資料以匯出這些 span。

## 使用範例 {/* #usage-examples */}

### 基本用法 {/* #basic-usage */}

```typescript
import { Mastra } from '@mastra/core'
import { Observability } from '@mastra/observability'
import { OtelBridge } from '@mastra/otel-bridge'

const mastra = new Mastra({
  observability: new Observability({
    configs: {
      default: {
        serviceName: 'my-service',
        bridge: new OtelBridge(),
      },
    },
  }),
  agents: { myAgent },
})
```

### 與 Exporter 配合使用 {/* #combined-with-exporters */}

Bridge 可以與 Exporter 配合使用：Bridge 負責 OTEL 上下文，Exporter 則將資料傳送至其他目的地：

```typescript
import { Mastra } from '@mastra/core'
import { Observability, MastraStorageExporter } from '@mastra/observability'
import { OtelBridge } from '@mastra/otel-bridge'
import { LangfuseExporter } from '@mastra/langfuse'

const mastra = new Mastra({
  observability: new Observability({
    configs: {
      default: {
        serviceName: 'my-service',
        bridge: new OtelBridge(), // Handles OTEL context
        exporters: [
          new MastraStorageExporter(), // Studio access
          new LangfuseExporter({
            // Additional destination
            publicKey: process.env.LANGFUSE_PUBLIC_KEY,
            secretKey: process.env.LANGFUSE_SECRET_KEY,
          }),
        ],
      },
    },
  }),
})
```

## 設定要求 {/* #setup-requirements */}

Bridge 透過 OpenTelemetry tracer provider 建立 span。要匯出 Mastra span，須符合以下條件：

- **必須提供 tracer provider。** 在 Mastra 執行前全域註冊一個，例如呼叫 `@opentelemetry/sdk-node` 中 `NodeSDK` 的 `sdk.start()`，或呼叫 `trace.setGlobalTracerProvider(provider)`。如未全域註冊，請透過 `new OtelBridge({ tracerProvider })` 傳入。
- **要將 Mastra span 嵌套於外層 span 之下，必須安裝上下文管理器。** `NodeSDK` 會自動安裝。沒有上下文管理器時，span 仍可匯出，但 Mastra 根 span 無法讀取目前生效的 span，因此會開始新的 trace，而不會加入外層 trace。

如沒有可用的 tracer provider，Agent 及 Workflow 仍會執行，但不會透過 OpenTelemetry 匯出 Mastra span。Bridge 只會記錄一次以下警告：

```text
[OtelBridge] No OpenTelemetry tracer provider is registered globally, so Mastra spans will not be exported through OpenTelemetry. ...
```

完整設定步驟（包括設定 OTEL 插樁及執行應用程式）請參閱 [OtelBridge 指南](/integrations/observability/opentelemetry#bridge)。

## 標籤支援 {/* #tags-support */}

OtelBridge 支援為 trace 加上標籤，以便分類及篩選。標籤只套用至根 span，並儲存為原生 OTEL span 的 `mastra.tags` 屬性。

### 用法 {/* #usage */}

```typescript
const result = await agent.generate('Hello', {
  tracingOptions: {
    tags: ['production', 'experiment-v2', 'user-request'],
  },
})
```

### 標籤如何存儲 {/* #how-tags-are-stored */}

標籤以 JSON 字串形式的陣列儲存在 span 的 `mastra.tags` 屬性中：

```json
{
  "mastra.tags": "[\"production\",\"experiment-v2\",\"user-request\"]"
}
```

此格式與所有 OTEL 相容的後端和收集器相容。
