：：：警告

OpenTelemetry Bridge 目前正在**experimental**. APIs and configuration options may change in future releases.

:::

實現 Mastra 追蹤和 OpenTelemetry 基礎架構之間的雙向整合。為 Mastra 操作建立本機 OTEL 跨度並從活動 OTEL 跨度繼承上下文。也將 Mastra 日誌事件轉發到全球註冊的 OTEL`LoggerProvider`, emitting each log under the OTEL context of the originating Mastra span so trace-log correlation works automatically.

### `onLogEvent` {/* #onlogevent */}

```typescript oxfmt:false
async onLogEvent(event: LogEvent): Promise<void>
```

將 Mastra 日誌事件轉送至全域註冊的 OTEL`LoggerProvider`. Trace correlation is resolved in this order:

1. 如果日誌帶有`spanId` the bridge has an OTEL span for, the log is emitted under that span's stored OTEL context.
2. 否則，如果日誌攜帶`traceId` and `spanId`, those IDs are attached to the emitted log record's `SpanContext`.
3. 否則，日誌將在目前處於活動狀態的任何 OTEL 上下文下發出。

如果沒有`LoggerProvider` is registered globally, emission is a silent no-op.

### `flush` {/* #flush */}

```typescript oxfmt:false
async flush(): Promise<void>
```

強制刷新追蹤器提供者和記錄器提供者（如果它們支援）`forceFlush`. The global providers are resolved at flush time, so a `LoggerProvider` registered after the bridge was constructed is flushed too. Useful in serverless environments where you need to drain telemetry before the runtime terminates. Call `sdk.shutdown()` as well before the process exits to wait for any batch your OTEL SDK has already started exporting. Neither this method nor the provider's own `forceFlush()` waits for that batch.

### `shutdown` {/* #shutdown */}

```typescript oxfmt:false
async shutdown(): Promise<void>
```

關閉橋樑並清理資源。結束任何未正確關閉的跨度，然後重新整理提供者以便匯出這些跨度。

## 使用範例 {/* #usage-examples */}

### 基本用法 {/* #basic-usage */}

```typescript
import { Mastra } from '@mastra/core'
import { Observability } from '@mastra/observability'
import { OtelBridge } from '@mastra/otel-bridge'

const mastra = new Mastra({
  observability: new Observability({
    configs: {
      default: {
        serviceName: 'my-service',
        bridge: new OtelBridge(),
      },
    },
  }),
  agents: { myAgent },
})
```

### 與出口商聯合 {/* #combined-with-exporters */}

該橋可以與出口商一起使用。橋接器處理 OTEL 上下文，而導出器將資料傳送到其他目的地：

```typescript
import { Mastra } from '@mastra/core'
import { Observability, MastraStorageExporter } from '@mastra/observability'
import { OtelBridge } from '@mastra/otel-bridge'
import { LangfuseExporter } from '@mastra/langfuse'

const mastra = new Mastra({
  observability: new Observability({
    configs: {
      default: {
        serviceName: 'my-service',
        bridge: new OtelBridge(), // Handles OTEL context
        exporters: [
          new MastraStorageExporter(), // Studio access
          new LangfuseExporter({
            // Additional destination
            publicKey: process.env.LANGFUSE_PUBLIC_KEY,
            secretKey: process.env.LANGFUSE_SECRET_KEY,
          }),
        ],
      },
    },
  }),
})
```

## 設定要求 {/* #setup-requirements */}

該橋透過 OpenTelemetry 追蹤器提供者創建跨度。對於要匯出的 Mastra 跨距：

* **必須有可用的追蹤器提供者。**&#x5728; Mastra 運行之前全域註冊一個，例如透過調用`sdk.start()` on `NodeSDK` from `@opentelemetry/sdk-node`, or by calling `trace.setGlobalTracerProvider(provider)`. If the provider isn't registered globally, pass it with `new OtelBridge({ tracerProvider })`.
* **必須安裝上下文管理器，Mastra 跨度才能嵌套在外部跨度下。** `NodeSDK` installs one automatically. Without a context manager, spans are still exported, but Mastra root spans can't read the active span, so they start new traces instead of joining the outer trace.

當沒有可用的追蹤器提供者時，Agent程式和Workflow仍會運行，但不會透過 OpenTelemetry 匯出 Mastra 範圍。網橋記錄此警告一次：

```text
[OtelBridge] No OpenTelemetry tracer provider is registered globally, so Mastra spans will not be exported through OpenTelemetry. ...
```

請參閱[OtelBridge Guide](/integrations/observability/opentelemetry#bridge) for complete setup instructions, including how to configure OTEL instrumentation and run your application.

## 標籤支援 {/* #tags-support */}

OtelBridge 支援追蹤標記以進行分類和過濾。標籤僅應用於根跨度並作為`mastra.tags` attribute on native OTEL spans.

### 用法 {/* #usage */}

```typescript
const result = await agent.generate('Hello', {
  tracingOptions: {
    tags: ['production', 'experiment-v2', 'user-request'],
  },
})
```

### 標籤如何存儲 {/* #how-tags-are-stored */}

標籤作為 JSON 字串化數組儲存在`mastra.tags` span attribute:

```json
{
  "mastra.tags": "[\"production\",\"experiment-v2\",\"user-request\"]"
}
```

此格式與所有 OTEL 相容的後端和收集器相容。
