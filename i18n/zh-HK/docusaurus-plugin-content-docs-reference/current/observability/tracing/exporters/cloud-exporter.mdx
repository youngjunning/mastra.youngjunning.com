# 雲導出器

**添加於：** `@mastra/observability@1.8.0`. **已棄用於`1.12.0`**&#x8D0A;成[`MastraPlatformExporter`](/reference/observability/tracing/exporters/mastra-platform-exporter).

:::警告\[已棄用]

`CloudExporter`仍然可用於向後相容，但將在未來的主要版本中刪除，因此使用[`MastraPlatformExporter`](/reference/observability/tracing/exporters/mastra-platform-exporter) for new projects. The classes have identical constructors and share environment variables and runtime behavior. To preserve existing monitoring rules, `CloudExporter` retains its original `mastra-cloud-observability-exporter` exporter `name` and `CLOUD_EXPORTER_*`錯誤 ID。

:::

將追蹤範圍、日誌、指標、分數和回饋發送到 Mastra 平台以進行線上視覺化和監控。

## `CloudExporterConfig` {/* #cloudexporterconfig */}

```typescript
interface CloudExporterConfig extends BaseExporterConfig {
  /** Maximum number of spans per batch. Default: 1000 */
  maxBatchSize?: number

  /** Maximum wait time before flushing in milliseconds. Default: 5000 */
  maxBatchWaitMs?: number

  /** Maximum retry attempts. Default: 3 */
  maxRetries?: number

  /** Cloud access token (from env or config) */
  accessToken?: string

  /** Project ID for project-scoped collector routes (letters, numbers, hyphens, underscores) */
  projectId?: string

  /** Base cloud observability endpoint */
  endpoint?: string

  /** Explicit cloud traces endpoint override */
  tracesEndpoint?: string

  /** Explicit cloud logs endpoint override */
  logsEndpoint?: string

  /** Explicit cloud metrics endpoint override */
  metricsEndpoint?: string

  /** Explicit cloud scores endpoint override */
  scoresEndpoint?: string

  /** Explicit cloud feedback endpoint override */
  feedbackEndpoint?: string
}
```

延伸`BaseExporterConfig`, which includes:

* `logger?: IMastraLogger`- 記錄器實例
* `logLevel?: LogLevel | 'debug' | 'info' | 'warn' | 'error'`- 日誌等級（預設：INFO）

## 環境變數 {/* #environment-variables */}

如果配置中未提供，導出器將讀取這些環境變數：

* `MASTRA_CLOUD_ACCESS_TOKEN`- 身份驗證令牌`CloudExporter` requests
* `MASTRA_PROJECT_ID`- 派生項目範圍的收集器路由時所使用的項目 ID，例如`/projects/:projectId/ai/spans/publish`
* `MASTRA_CLOUD_TRACES_ENDPOINT`- 追蹤端點覆蓋。傳遞基本來源或以以下結尾的完整追蹤發布 URL`/spans/publish`. The other signal endpoints are derived from it. Defaults to `https://observability.mastra.ai`

`CloudExporter`不讀書`MASTRA_PLATFORM_OBSERVABILITY_ENDPOINT`. Use [`MastraPlatformExporter`](/reference/observability/tracing/exporters/mastra-platform-exporter) for that variable.

## 方法 {/* #methods */}

### `exportTracingEvent` {/* #exporttracingevent */}

```typescript oxfmt:false
async exportTracingEvent(event: TracingEvent): Promise<void>
```



僅有的`SPAN_ENDED` tracing events are exported. `SPAN_STARTED` and `SPAN_UPDATED` are ignored. Matching spans are buffered and uploaded to the Cloud traces endpoint on the next flush.

### `onLogEvent` {/* #onlogevent */}

```typescript oxfmt:false
async onLogEvent(event: LogEvent): Promise<void>
```

處理雲導出的日誌訊號。

每一個`LogEvent` passed to this handler is buffered and exported to the Cloud logs endpoint derived from the configured base endpoint. Unlike tracing, there is no additional event-status filtering at the `CloudExporter` level. If the exporter is disabled, this method becomes a no-op.

### 沖水 {/* #flush */}

```typescript oxfmt:false
async flush(): Promise<void>
```

強制將所有緩衝事件刷新到 Mastra 平台，而無需關閉導出器。在無伺服器環境中很有用，您需要確保在執行時間終止之前導出跨度。

### 關閉 {/* #shutdown */}

```typescript oxfmt:false
async shutdown(): Promise<void>
```

刷新剩餘事件並執行清理。

## 行為 {/* #behavior */}

### 驗證 {/* #authentication */}

如果沒有透過配置或環境變數提供存取令牌，則導出器：

* 記錄帶有註冊資訊的警告
*

### 食材 {/* #batching */}

導出器批量追蹤跨度、日誌、指標、分數和回饋，以實現高效的網路使用：

* 當緩衝事件總數達到時刷新`maxBatchSize`
* 沖洗時`maxBatchWaitMs` elapsed since the first buffered signal in the batch
* 沖水`shutdown()`

### 錯誤處理 {/* #error-handling */}

* 使用指數退避重試`maxRetries` attempts
* 所有重試失敗後刪除批次
* 記錄錯誤但繼續處理新事件

### 端點路由 {/* #endpoint-routing */}

* 基本起源自動導出訊號端點
* 沒有`projectId`, derived routes use `/ai/{signal}/publish`
* 和`projectId` or `MASTRA_PROJECT_ID`, derived routes use `/projects/:projectId/ai/{signal}/publish`
* 即使在以下情況下，也會按原樣使用明確完整發佈 URL：`projectId` is configured

### 訊號處理 {/* #signal-processing */}

* `exportTracingEvent()`只出口`SPAN_ENDED` tracing events
* `onLogEvent()`, `onMetricEvent()`, `onScoreEvent()`, and `onFeedbackEvent()` buffer every event they receive for that signal type
* 所有支援的訊號批次都會在期間上傳到其匹配的雲端發布端點`flush()` and `shutdown()`

const exporter = new CloudExporter()

  accessToken: 'your-token',
  projectId: 'project_123',
  maxBatchSize: 500,
  maxBatchWaitMs: 2000,
  logLevel: 'debug',
})
