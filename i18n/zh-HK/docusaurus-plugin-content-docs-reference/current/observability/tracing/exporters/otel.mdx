# 奧特爾出口商

將追蹤和日誌傳送到任何與 OpenTelemetry 相容的可觀測平台。追蹤使用標準化 GenAI 語意約定。日誌攜帶其原始嚴重性和訊息正文，並透過 OTEL 日誌記錄的本機追蹤上下文和追蹤與追蹤相關聯。`mastra.traceId` / `mastra.spanId`屬性。


## 元資料映射 {/* #metadata-mapping */}

使用`metadataMapping` when your backend expects metadata such as `userId` under a specific span attribute name:

```typescript
import { OtelExporter } from '@mastra/otel-exporter'

const exporter = new OtelExporter({
  provider: {
    custom: { endpoints: { traces: 'https://collector.example.com/v1/traces' } },
  },
  metadataMapping: { userId: 'user.id', tenantId: 'tenant.id' },
})
```

帶有元資料的跨度`{ userId: 'user-123', tenantId: 'acme' }` exports both `user.id` and `tenant.id`, alongside the existing `mastra.metadata.userId` and `mastra.metadata.tenantId`屬性。映射適用於包含所選元資料鍵的每個範圍，包括子範圍。

映射值是字串。物件和陣列是 JSON 編碼的。鑰匙遺失，`null`, `undefined`, and empty strings are omitted. `0` and `false` become `"0"` and `"false"`。鍵按字面匹配，因此包含點的鍵不會選擇嵌套屬性。空目標名稱將被忽略。

明確映射會覆寫具有相同目標名稱的現有屬性。如果多個元資料鍵對應到相同名稱，則最後一個具有非空值的對應獲勝。映射不會影響日誌記錄或資源屬性。

### 自訂訊號端點 {/* #custom-signal-endpoints */}

供應任一`endpoint` or `endpoints`, never both. TypeScript rejects configurations with both options. Runtime validation also rejects them and disables the exporter with an error message.

使用`endpoints` to supply the exact URL for each signal. URLs are passed to the selected exporter without adding, removing, or replacing path segments. Trace and log endpoints can use different hosts and unrelated paths:

```typescript
import { OtelExporter } from '@mastra/otel-exporter'

const exporter = new OtelExporter({
  provider: {
    custom: {
      protocol: 'http/protobuf',
      endpoints: {
        traces: 'https://traces.example.com/api/ingest/?tenant=acme',
        logs: 'https://logs.example.com/events',
      },
    },
  },
})
```

提供至少一個訊號端點。忽略`logs` for trace-only export or `traces` for log-only export. The `signals` toggles can still disable a configured signal. Protocol and headers apply to both endpoints. The selected protocol must support the signal. A custom `exporter` instance overrides trace transport as before.

您可以明確傳遞環境變數值：

```typescript
const exporter = new OtelExporter({
  provider: {
    custom: {
      endpoints: {
        traces: process.env.OTEL_EXPORTER_OTLP_TRACES_ENDPOINT,
        logs: process.env.OTEL_EXPORTER_OTLP_LOGS_ENDPOINT,
      },
    },
  },
})
```

該類型需要至少一個信號鍵並允許`undefined` values for environment-variable configuration. At runtime, at least one URL must be non-empty. A missing value disables that signal. Mastra doesn't load endpoint environment variables automatically.

奇異的`endpoint` option retains its existing behavior for compatibility: OTLP signal paths are derived from the collector URL, and Zipkin uses the configured URL directly. For custom paths, use `endpoints` instead.

## 協議要求 {/* #protocol-requirements */}

不同的提供者需要不同的 OTEL 匯出程式包。跟踪和日誌匯出是獨立的：如果您只需要跟踪，則僅安裝跟踪包；如果您還需要日誌匯出，則安裝所選協議的跟踪和日誌包。 Zipkin 不支援 OTLP 日誌。

|協定|追蹤包 |日誌包|
| - | - | - |
| gRPC |`@opentelemetry/exporter-trace-otlp-grpc` (+ `@grpc/grpc-js`) | `@opentelemetry/exporter-logs-otlp-grpc` (+ `@grpc/grpc-js`) |
| HTTP/Protobuf | `@opentelemetry/exporter-trace-otlp-proto` | `@opentelemetry/exporter-logs-otlp-proto` |
| HTTP/JSON | `@opentelemetry/exporter-trace-otlp-http` | `@opentelemetry/exporter-logs-otlp-http` |
| Zipkin | `@opentelemetry/exporter-zipkin` | not supported |

## 標籤支援 {/* #tags-support */}

OtelExporter 支援追蹤標記以進行分類和過濾。標籤僅應用於根跨度並儲存為`mastra.tags` attribute.

### 用法 {/* #usage */}

```typescript
const result = await agent.generate('Hello', {
  tracingOptions: {
    tags: ['production', 'experiment-v2', 'user-request'],
  },
})
```

### 標籤如何存儲 {/* #how-tags-are-stored */}

標籤作為 JSON 字串化數組儲存在`mastra.tags` span attribute for maximum backend compatibility:

```json
{
  "mastra.tags": "[\"production\",\"experiment-v2\",\"user-request\"]"
}
```

:::注意
雖然 OpenTelemetry 規格支援本機陣列屬性，但許多後端（Jaeger、Zipkin、Tempo）對陣列的支援有限。 JSON 字串確保所有可觀察平台的行為一致。
:::
