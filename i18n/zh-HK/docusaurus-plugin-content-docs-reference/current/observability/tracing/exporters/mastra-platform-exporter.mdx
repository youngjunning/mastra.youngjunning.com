# Mastra平台出口商

**添加於：** `@mastra/observability@1.12.0`。早期版本（`@mastra/observability@1.8.0`透過`1.11.x`) 匯出與已棄用的相同的匯出器`CloudExporter`.

將追蹤範圍、日誌、指標、分數和回饋發送到 Mastra 平台以進行線上視覺化和監控。

：：：筆記

`MastraPlatformExporter`以前被稱為`CloudExporter`. The original `CloudExporter` class is still exported from `@mastra/observability` so existing imports keep working, but it's deprecated and will be removed in a future major version. New code should use `MastraPlatformExporter`.

:::

## `MastraPlatformExporterConfig` {/* #mastraplatformexporterconfig */}

```typescript
interface MastraPlatformExporterConfig extends BaseExporterConfig {
  /** Maximum number of buffered events per batch (spans, logs, metrics, scores, feedback). Default: 1000 */
  maxBatchSize?: number

  /** Maximum wait time before flushing in milliseconds. Default: 5000 */
  maxBatchWaitMs?: number

  /** Opt into byte-triggered batches and upload concurrency control */
  byteBatching?: {
    maxBatchBytes?: number // Default: 8 MiB
    maxConcurrentUploads?: number // Default: 2
    uploadTimeoutMs?: number // Default: 30000
  }

  /** Maximum retry attempts for collector batches. Default: 3 */
  maxRetries?: number

  /** Mastra Observability access token (from env or config) */
  accessToken?: string

  /** Project ID for project-scoped collector routes (letters, numbers, hyphens, underscores) */
  projectId?: string

  /** Base observability endpoint */
  endpoint?: string

  /** Explicit traces endpoint override */
  tracesEndpoint?: string

  /** Explicit logs endpoint override */
  logsEndpoint?: string

  /** Explicit metrics endpoint override */
  metricsEndpoint?: string

  /** Explicit scores endpoint override */
  scoresEndpoint?: string

  /** Explicit feedback endpoint override */
  feedbackEndpoint?: string

  /**
   * When false, `accessToken`, `projectId` and the traces endpoint are taken
   * from config only and the environment variables below are ignored. Use this
   * when embedding Mastra in another tool so a user project's `.env` cannot
   * redirect the host's own telemetry. Default: true
   */
  resolveFromEnv?: boolean
}
```

延伸`BaseExporterConfig`, which includes:

* `logger?: IMastraLogger`- 記錄器實例
* `logLevel?: LogLevel | 'debug' | 'info' | 'warn' | 'error'`- 日誌等級（預設：INFO）

## 環境變數 {/* #environment-variables */}

如果配置中未提供，導出器將讀取這些環境變數：

* `MASTRA_PLATFORM_ACCESS_TOKEN`- 身份驗證令牌`MastraPlatformExporter` requests
* `MASTRA_PROJECT_ID`- 派生項目範圍的收集器路由時所使用的項目 ID，例如`/projects/:projectId/ai/spans/publish`
* `MASTRA_PLATFORM_OBSERVABILITY_ENDPOINT`- 可觀察性端點覆蓋，由導出器讀取`@mastra/observability@1.17.4` and later. Pass either a base origin such as `https://observability.eu.mastra.ai` or a full traces publish URL ending in `/spans/publish`. The other signal endpoints are derived from it. Defaults to `https://observability.mastra.ai`
* `MASTRA_CLOUD_TRACES_ENDPOINT`- 舊追蹤端點覆蓋。優先於`MASTRA_PLATFORM_OBSERVABILITY_ENDPOINT` when both are set

當`resolveFromEnv` is `false`.

### 食材 {/* #batching */}

導出器批量追蹤、日誌和指標，以及已包含其追蹤詳細資訊的回饋和分數：

* 當緩衝事件總數達到時刷新`maxBatchSize`
* 沖洗時`maxBatchWaitMs` elapsed since the first buffered signal in the batch
* 沖水`shutdown()`

### 回饋和分數交付 {/* #feedback-and-score-delivery */}

導出器收到的回饋和分數可以使用其追蹤 ID 和可選的跨度 ID 引用平台中儲存的追蹤。如果記錄需要來自該追蹤的詳細信息，匯出器會立即發送它，而不是等待批次。

稱呼`flush()` before ending a short-lived process, or `shutdown()` when stopping the exporter, to wait for pending deliveries and retries. These methods finish when records have been accepted or dropped after a failure. Accepted feedback and scores may take time to appear in Platform.

### 位元組批次 {/* #byte-batching */}

放`byteBatching` to flush by serialized byte size and control concurrent uploads:

```typescript
import { MastraPlatformExporter } from '@mastra/observability'

const exporter = new MastraPlatformExporter({
  byteBatching: {
    maxBatchBytes: 8 * 1024 * 1024,
    maxConcurrentUploads: 2,
    uploadTimeoutMs: 30_000,
  },
})
```

沒有`byteBatching`, the exporter keeps its existing count-based batching behavior.

* `maxBatchBytes` 預設情況下，當批次達到 8 MiB 時觸發上傳。較大的記錄會完整發送，不會被截斷或基於大小的丟棄。
* `maxConcurrentUploads`控制並發收集器批次上傳。預設為兩個。
* `uploadTimeoutMs`設定上傳截止日期，包括重試。預設值為 30 秒。

記錄計數和基於計時器的刷新觸發器仍然適用。當上傳落後時，排隊的記錄將被保留，因此佇列記憶體可能會成長。

檢查目前隊列`exporter.getByteBatchingStats()`.

### 錯誤處理 {/* #error-handling */}

* 對收集器批次使用指數退避重試`maxRetries` attempts
* 所有重試失敗後刪除批次
* 記錄錯誤但繼續處理新事件

引發的錯誤`MastraPlatformExporter` use the `MASTRA_PLATFORM_EXPORTER_*` `id` prefix. The deprecated `CloudExporter` continues to emit `CLOUD_EXPORTER_*` `id`s.

### 配額暫停 {/* #quota-pause */}

當組織用盡可觀察性配額時，Mastra 平台會拒絕發布請求`402 Payment Required` plus the `x-mastra-observability: disabled` header. When the exporter sees a `402` (or the header) on any publish route, it:

* 刪除被拒絕的批次而不重試
* 暫停收集器批次以取得追蹤、日誌、指標、分數和回饋，刪除緩衝的和傳入的批次記錄
* 記錄遙測已暫停的警告
* 使用空批次定期偵測平台，使用來自`x-mastra-observability-retry-after` header (seconds), or every 5 minutes if the header is absent
* 一旦平台停止拒絕，自動恢復匯出並記錄警告`402`

偵測計時器不會使 Node.js 進程保持活動狀態，因此短暫的無伺服器進程在暫停時會正常退出。

每個收集器請求（批量上傳和追蹤恢復探測）都包括`x-mastra-observability-capabilities: quota-pause-v1` header. This tells the platform that the client understands the quota-pause contract, so it can safely respond with `402` instead of silently dropping telemetry for older clients that would retry it.

### 端點路由 {/* #endpoint-routing */}

* 基本起源自動導出訊號端點
* 沒有`projectId`, derived routes use `/ai/{signal}/publish`
* 和`projectId` or `MASTRA_PROJECT_ID`, derived routes use `/projects/:projectId/ai/{signal}/publish`
* 即使在以下情況下，也會按原樣使用明確完整發佈 URL：`projectId` is configured

### 事件處理 {/* #event-processing */}

* `exportTracingEvent()`只出口`SPAN_ENDED` tracing events
* `onLogEvent()`和`onMetricEvent()` buffer events
* `onScoreEvent()`和`onFeedbackEvent()` deliver records as described in [Feedback and score delivery](#feedback-and-score-delivery)
* 所有支援的訊號批次都會在期間上傳到其匹配的發布端點`flush()` and `shutdown()`

## 跨線格式 {/* #span-wire-format */}

發送到 Mastra 平台的每個跨度的形狀記錄在此處僅供參考：它不是從`@mastra/observability` and shouldn't be imported. The exporter spreads the original `AnyExportedSpan` (so the source field names are preserved) and layers a small set of platform-friendly aliases on top:

```typescript
type MastraPlatformSpanRecord = AnyExportedSpan & {
  // Aliases derived from the source span
  spanId: string // alias for span.id
  spanType: string // alias for span.type
  startedAt: Date // alias for span.startTime
  endedAt: Date | null // alias for span.endTime ?? null
  error: AnyExportedSpan['errorInfo'] | null

  // Stamped at export time
  createdAt: Date
  updatedAt: Date | null
}
```

傳播`AnyExportedSpan` also carries the original `id`, `type`, `name`, `traceId`, `parentSpanId`, `isRootSpan`, `isEvent`, `startTime`, `endTime`, `entityType`, `entityId`, `entityName`, `tags`, `attributes`, `metadata`, `input`, `output`, and `errorInfo`. See [Interfaces](/reference/observability/tracing/interfaces) for `AnyExportedSpan`.

## 用法 {/* #usage */}

```typescript
import { MastraPlatformExporter } from '@mastra/observability'

// Uses environment variable for token

// Explicit configuration

  accessToken: 'your-token',

  maxBatchSize: 500,
  maxBatchWaitMs: 2000,
  logLevel: 'debug',

```

## 遷移自`CloudExporter` {/* #migrating-from-cloudexporter */}

這兩個類別共享相同的建構子簽章、環境變數和行為。若要遷移，請替換導入和建構函數：

```typescript
// Before
import { CloudExporter } from '@mastra/observability'
const exporter = new CloudExporter()

// After
import { MastraPlatformExporter } from '@mastra/observability'
const exporter = new MastraPlatformExporter()
```

原來的`CloudExporter` is preserved unchanged so dashboards or alert rules that match the previous `CLOUD_EXPORTER_*` error IDs or `mastra-cloud-observability-exporter` exporter name keep working until you migrate.
