# MastraPlatformExporter

**加入版本：** `@mastra/observability@1.12.0`。較早版本（`@mastra/observability@1.8.0` 至 `1.11.x`）將同一個 exporter 匯出為現已棄用的 `CloudExporter`。

將追蹤 Span、日誌、指標、評分和回饋傳送至 Mastra 平台，以便在線上檢視和監察。

:::note

`MastraPlatformExporter` 原名 `CloudExporter`。原有的 `CloudExporter` 類別仍由 `@mastra/observability` 匯出，因此現有匯入仍可使用；但該類別已棄用，將在未來的主要版本中移除。新程式碼應使用 `MastraPlatformExporter`。

:::

## Span 預覽 {/* #span-previews */}

`MastraPlatformExporter` 會按 Span 類型，自動產生簡短易讀的 `inputPreview`、`outputPreview` 和 `errorPreview` 摘要。每項預覽最多包含 100 個字元；截斷時會加上省略號。完整負載仍可另外取得。

## `MastraPlatformExporterConfig` {/* #mastraplatformexporterconfig */}

```typescript
interface MastraPlatformExporterConfig extends BaseExporterConfig {
  /** Maximum number of buffered events per batch (spans, logs, metrics, scores, feedback). Default: 1000 */
  maxBatchSize?: number

  /** Maximum wait time before flushing in milliseconds. Default: 5000 */
  maxBatchWaitMs?: number

  /** Opt into byte-triggered batches and upload concurrency control */
  byteBatching?: {
    maxBatchBytes?: number // Default: 8 MiB
    maxConcurrentUploads?: number // Default: 2
    uploadTimeoutMs?: number // Default: 30000
  }

  /** Maximum retry attempts for collector batches. Default: 3 */
  maxRetries?: number

  /** Mastra Observability access token (from env or config) */
  accessToken?: string

  /** Project ID for project-scoped collector routes (letters, numbers, hyphens, underscores) */
  projectId?: string

  /** Base observability endpoint */
  endpoint?: string

  /** Explicit traces endpoint override */
  tracesEndpoint?: string

  /** Explicit logs endpoint override */
  logsEndpoint?: string

  /** Explicit metrics endpoint override */
  metricsEndpoint?: string

  /** Explicit scores endpoint override */
  scoresEndpoint?: string

  /** Explicit feedback endpoint override */
  feedbackEndpoint?: string

  /**
   * When false, `accessToken`, `projectId` and the traces endpoint are taken
   * from config only and the environment variables below are ignored. Use this
   * when embedding Mastra in another tool so a user project's `.env` cannot
   * redirect the host's own telemetry. Default: true
   */
  resolveFromEnv?: boolean
}
```

繼承 `BaseExporterConfig`，其中包括：

- `logger?: IMastraLogger` - Logger 實例
- `logLevel?: LogLevel | 'debug' | 'info' | 'warn' | 'error'` - 日誌級別（預設：INFO）

## 環境變數 {/* #environment-variables */}

如設定中未提供相應值，exporter 會讀取以下環境變數：

- `MASTRA_PLATFORM_ACCESS_TOKEN` - `MastraPlatformExporter` 請求的驗證權杖
- `MASTRA_PROJECT_ID` - 推導 `/projects/:projectId/ai/spans/publish` 等項目專屬 collector 路由時使用的項目 ID
- `MASTRA_PLATFORM_OBSERVABILITY_ENDPOINT` - 覆寫可觀測性端點。`@mastra/observability@1.17.4` 及更新版本的 exporter 會讀取此變數。可提供 `https://observability.eu.mastra.ai` 這類基礎來源，或以 `/spans/publish` 結尾的完整追蹤發佈 URL。其他訊號端點會由此推導。預設為 `https://observability.mastra.ai`
- `MASTRA_CLOUD_TRACES_ENDPOINT` - 舊版追蹤端點覆寫設定。兩者均已設定時，優先於 `MASTRA_PLATFORM_OBSERVABILITY_ENDPOINT`

當 `resolveFromEnv` 為 `false` 時，上述環境變數均會被忽略。

## 方法 {/* #methods */}

### `exportTracingEvent` {/* #exporttracingevent */}

```typescript oxfmt:false

```

處理準備匯出至 Mastra 平台的追蹤事件。

只匯出 `SPAN_ENDED` 追蹤事件；`SPAN_STARTED` 和 `SPAN_UPDATED` 會被忽略。符合條件的 Span 會先進入緩衝區，於下次送出時上傳至追蹤端點。

### flush {/* #flush */}

```typescript oxfmt:false

```

強制將緩衝區中的事件傳送至 Mastra 平台，而不關閉 exporter。適用於無伺服器環境，可確保 Span 在執行時環境終止前完成匯出。


## 行為 {/* #behavior */}

### 身分驗證 {/* #authentication */}

如設定和環境變數均未提供存取權杖，exporter 將：

- 記錄包含註冊資訊的警告
- 不執行實際操作（丟棄所有事件）

### 批次處理 {/* #batching */}

exporter 會將追蹤、日誌、指標，以及已包含追蹤詳情的回饋和評分分批處理：

- 緩衝事件總數達到 `maxBatchSize` 時傳送批次
- 批次中第一筆訊號進入緩衝區後經過 `maxBatchWaitMs` 時傳送批次
- 呼叫 `shutdown()` 時傳送批次

### 回饋及評分傳送 {/* #feedback-and-score-delivery */}

exporter 收到的回饋和評分可透過 Trace ID 和可選的 Span ID，參照儲存在 Platform 中的追蹤。如果紀錄需要該追蹤的詳情，exporter 會立即傳送，不等待批次。

短生命週期程序結束前請呼叫 `flush()`，或在停止 exporter 時呼叫 `shutdown()`，以等待待處理的傳送和重試。紀錄獲接受或在失敗後被丟棄時，這些方法才會完成。已接受的回饋和評分可能需要一段時間才會顯示於 Platform。

### 按位元組分批 {/* #byte-batching */}

設定 `byteBatching`，即可按序列化後的位元組數傳送批次，並控制並行上傳數量：

```typescript
import { MastraPlatformExporter } from '@mastra/observability'

const exporter = new MastraPlatformExporter({
  byteBatching: {
    maxBatchBytes: 8 * 1024 * 1024,
    maxConcurrentUploads: 2,
    uploadTimeoutMs: 30_000,
  },
})
```

未設定 `byteBatching` 時，exporter 維持原有按紀錄數量分批處理的行為。

- 預設情況下，批次達到 8 MiB 時，`maxBatchBytes` 會觸發上傳。更大的單筆紀錄仍會完整傳送，不會被截斷或因大小而丟棄。
- `maxConcurrentUploads` 控制同時上傳至 collector 的批次數，預設為 2。
- `uploadTimeoutMs` 設定包括重試在內的上傳期限，預設為 30 秒。

按紀錄數量和計時器觸發傳送的規則仍然適用。如上傳速度跟不上，佇列中的紀錄會保留，因此佇列佔用的記憶體可能增加。

使用 `exporter.getByteBatchingStats()` 查看目前的佇列。

### 錯誤處理 {/* #error-handling */}

- 對 collector 批次採用指數退避重試，最多嘗試 `maxRetries` 次
- 所有重試均失敗後丟棄批次
- 記錄錯誤，但繼續處理新事件

`MastraPlatformExporter` 擲出的錯誤使用 `MASTRA_PLATFORM_EXPORTER_*` 作為 `id` 前綴。已棄用的 `CloudExporter` 仍會產生以 `CLOUD_EXPORTER_*` 為前綴的錯誤 `id`。

### 配額暫停 {/* #quota-pause */}

當機構的可觀測性配額用盡時，Mastra 平台會以 `402 Payment Required` 和 `x-mastra-observability: disabled` 回應標頭拒絕發佈請求。exporter 在任何發佈路由收到 `402`（或該標頭）時，會：

- 丟棄被拒絕的批次，不再重試
- 暫停追蹤、日誌、指標、評分和回饋的 collector 批次，並丟棄緩衝區中及新進入的批次紀錄
- 記錄遙測已暫停的警告
- 定期以空批次探測平台。間隔由 `x-mastra-observability-retry-after` 回應標頭指定（單位為秒）；如沒有該標頭，則每 5 分鐘探測一次
- 平台不再傳回 `402` 後，自動恢復匯出並記錄警告

探測計時器不會令 Node.js 程序持續運作，因此短生命週期和無伺服器程序在暫停期間仍可正常結束。

每個 collector 請求（包括批次上傳和追蹤復原探測）都包含 `x-mastra-observability-capabilities: quota-pause-v1` 標頭。這讓平台知道客戶端支援配額暫停協定，因此平台可以安全地傳回 `402`，而不用像處理會重試的舊版客戶端那樣，靜默丟棄遙測數據。

### 端點路由 {/* #endpoint-routing */}

- 基礎來源會自動推導訊號端點
- 未設定 `projectId` 時，推導出的路由使用 `/ai/{signal}/publish`
- 設定 `projectId` 或 `MASTRA_PROJECT_ID` 後，推導出的路由使用 `/projects/:projectId/ai/{signal}/publish`
- 即使已設定 `projectId`，明確指定的完整發佈 URL 仍會原樣使用

### 事件處理 {/* #event-processing */}

- `exportTracingEvent()` 只匯出 `SPAN_ENDED` 追蹤事件
- `onLogEvent()` 和 `onMetricEvent()` 會緩衝事件
- `onScoreEvent()` 和 `onFeedbackEvent()` 按[回饋及評分傳送](#feedback-and-score-delivery)所述方式傳送紀錄
- 在 `flush()` 和 `shutdown()` 期間，所有支援的訊號批次都會上傳至各自對應的發佈端點

## Span 傳輸格式 {/* #span-wire-format */}

此處記錄傳送至 Mastra 平台的 Span 結構，僅供參考：它並未從 `@mastra/observability` 匯出，不應匯入。exporter 會展開原始 `AnyExportedSpan`（保留來源欄位名稱），再加入少量方便平台使用的別名欄位：

```typescript
type MastraPlatformSpanRecord = AnyExportedSpan & {
  // Aliases derived from the source span
  spanId: string // alias for span.id
  spanType: string // alias for span.type
  startedAt: Date // alias for span.startTime
  endedAt: Date | null // alias for span.endTime ?? null
  error: AnyExportedSpan['errorInfo'] | null

  // Stamped at export time
  createdAt: Date
  updatedAt: Date | null
}
```

展開後的 `AnyExportedSpan` 亦包含原有的 `id`、`type`、`name`、`traceId`、`parentSpanId`、`isRootSpan`、`isEvent`、`startTime`、`endTime`、`entityType`、`entityId`、`entityName`、`tags`、`attributes`、`metadata`、`input`、`output` 和 `errorInfo`。關於 `AnyExportedSpan`，請參閱[介面](/reference/observability/tracing/interfaces)。

## 用法 {/* #usage */}

```typescript
import { MastraPlatformExporter } from '@mastra/observability'

// Uses environment variable for token
const exporter = new MastraPlatformExporter()

// Explicit configuration
const customExporter = new MastraPlatformExporter({
  accessToken: 'your-token',
  projectId: 'project_123',
  maxBatchSize: 500,
  maxBatchWaitMs: 2000,
  logLevel: 'debug',
})
```

## 從 `CloudExporter` 遷移 {/* #migrating-from-cloudexporter */}

兩個類別的建構函式簽名、環境變數和行為均相同。遷移時請替換匯入和建構函式：

```typescript
// Before
import { CloudExporter } from '@mastra/observability'
const exporter = new CloudExporter()

// After
import { MastraPlatformExporter } from '@mastra/observability'
const exporter = new MastraPlatformExporter()
```

原有的 `CloudExporter` 保持不變，因此比對舊版 `CLOUD_EXPORTER_*` 錯誤 ID，或 exporter 名稱 `mastra-cloud-observability-exporter` 的儀表板和警示規則，在遷移前仍可正常運作。
