# DefaultExporter

**自 `@mastra/observability@1.12.0` 起已棄用**，請改用 [`MastraStorageExporter`](/reference/observability/tracing/exporters/mastra-storage-exporter)。

:::warning[已棄用]

`DefaultExporter` 為向後兼容而保留，將於未來的主要版本移除。新項目請使用 [`MastraStorageExporter`](/reference/observability/tracing/exporters/mastra-storage-exporter)。兩個類別的建構函數、配置及執行時行為相同。`DefaultExporter` 保留原有 `mastra-default-observability-exporter` 匯出器 `name`，因此依賴此名稱的監控規則仍可正常運作。

:::

透過自動批次處理及重試機制，將可觀測性事件持久儲存至 Mastra Storage。

## `DefaultExporterConfig` {/* #defaultexporterconfig */}

```typescript
interface DefaultExporterConfig extends BaseExporterConfig {
  /** Maximum number of spans per batch. Default: 1000 */
  maxBatchSize?: number

  /** Maximum total buffer size before emergency flush. Default: 10000 */
  maxBufferSize?: number

  /** Maximum time to wait before flushing batch in milliseconds. Default: 5000 */
  maxBatchWaitMs?: number

  /** Maximum number of retry attempts. Default: 4 */
  maxRetries?: number

  /** Base retry delay in milliseconds (uses exponential backoff). Default: 500 */
  retryDelayMs?: number

  /** Tracing storage strategy or 'auto' for automatic selection. Default: 'auto' */
  strategy?: TracingStorageStrategy | 'auto'
}
```

繼承 `BaseExporterConfig`，其中包括：

- `logger?: IMastraLogger` - 日誌記錄器實例
- `logLevel?: LogLevel | 'debug' | 'info' | 'warn' | 'error'` - 日誌級別（預設值：INFO）

## `TracingStorageStrategy` {/* #tracingstoragestrategy */}

```typescript
type TracingStorageStrategy = 'realtime' | 'batch-with-updates' | 'insert-only'
```

### 策略行為 {/* #strategy-behaviors */}

- **realtime**：立即將每個事件持久儲存至儲存空間
- **batch-with-updates**：分別以批次處理建立及更新事件，並依序套用
- **insert-only**：只處理 SPAN_ENDED 事件，忽略更新

### flush {/* #flush */}

```typescript oxfmt:false
async flush(): Promise<void>
```

強制將所有緩衝事件寫入儲存空間，而不關閉匯出器。適用於需要在執行環境終止前確保 span 已匯出的無伺服器環境。

### 關閉 {/* #shutdown */}

```typescript oxfmt:false
async shutdown(): Promise<void>
```

將餘下緩衝事件寫出並執行清理。

## 自動策略選擇 {/* #automatic-strategy-selection */}

當 `strategy: 'auto'`（預設值）時，匯出器會查詢儲存適配器支援的能力：

```typescript
interface TracingStrategy {
  /** Strategies supported by this adapter */
  supported: TracingStorageStrategy[]

  /** Preferred strategy for optimal performance */
  preferred: TracingStorageStrategy
}
```

匯出器會：

1. 優先使用儲存適配器的首選策略（如可用）
2. 若首選策略不可用，則改用第一個受支援的策略
3. 若用戶指定的策略不受支援，則記錄警告

## 批次處理行為 {/* #batching-behavior */}

### 寫出觸發條件 {/* #flush-triggers */}

符合以下任一條件時，緩衝區會寫出：

- 緩衝區大小達到 `maxBatchSize`
- 自第一個緩衝事件起經過的時間超過 `maxBatchWaitMs`
- 緩衝區大小達到 `maxBufferSize`（緊急寫出）
- 呼叫 `shutdown()`

### 重試邏輯 {/* #retry-logic */}

寫出失敗後會按指數退避重試：

- 重試延遲：`retryDelayMs * 2^attempt`
- 最多嘗試次數：`maxRetries`
- 所有重試均失敗後捨棄該批次

當儲存空間不支援某種信號或重試次數耗盡時，`DefaultExporter` 會發出 `ObservabilityDropEvent`，並由註冊在匯出器及 bridge 上的 `onDroppedEvent` 處理程式接收。該事件包含信號、原因、數量、匯出器名稱、已知的儲存空間名稱，以及經過清理的錯誤詳情。

### 亂序處理 {/* #out-of-order-handling */}

對於 `batch-with-updates` 策略：

- 追蹤哪些 span 已建立
- 拒絕對尚未建立的 span 執行更新或結束操作
- 就亂序事件記錄警告
- 維護序號，確保更新按順序執行

## 使用方法 {/* #usage */}

```typescript
import { DefaultExporter } from '@mastra/observability'

// Default configuration
const exporter = new DefaultExporter()

// Custom batching configuration
const customExporter = new DefaultExporter({
  maxBatchSize: 500,
  maxBatchWaitMs: 2000,
  strategy: 'batch-with-updates',
  logLevel: 'debug',
})
```
