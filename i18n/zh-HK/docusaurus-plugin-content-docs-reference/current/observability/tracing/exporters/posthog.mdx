# PosthogExporter

將 Tracing 數據傳送至 PostHog，用於 AI 可觀測性及分析。

## 建構函數 {/* #constructor */}

```typescript oxfmt:false
new PosthogExporter(config: PosthogExporterConfig)
```

## `PosthogExporterConfig` {/* #posthogexporterconfig */}

```typescript
interface PosthogExporterConfig extends BaseExporterConfig {
  apiKey?: string
  host?: string
  flushAt?: number
  flushInterval?: number
  serverless?: boolean
  defaultDistinctId?: string
  enablePrivacyMode?: boolean
}
```

繼承 `BaseExporterConfig`，當中亦包括：

* `logger?: IMastraLogger` - 日誌記錄器實例
* `logLevel?: LogLevel | 'debug' | 'info' | 'warn' | 'error'` - 日誌級別（預設：INFO）

## 方法 {/* #methods */}

### `exportTracingEvent` {/* #exporttracingevent */}

```typescript oxfmt:false
async exportTracingEvent(event: TracingEvent): Promise<void>
```

將追蹤事件匯出至 PostHog。

### `onFeedbackEvent` {/* #onfeedbackevent */}

```typescript oxfmt:false
async onFeedbackEvent(event: FeedbackEvent): Promise<void>
```

將回饋事件匯出至 PostHog。請參閱[回饋匯出](#feedback-export)。

### flush {/* #flush */}

```typescript oxfmt:false
async flush(): Promise<void>
```

將緩衝中的事件強制送出至 PostHog，但不關閉匯出器。適用於需要在執行環境終止前確保 Span 已匯出的無伺服器環境。

### 關閉 {/* #shutdown */}

```typescript oxfmt:false
async shutdown(): Promise<void>
```

送出待處理的批次事件，並關閉 PostHog 客戶端。

## 用法 {/* #usage */}

### 零設定（使用環境變數） {/* #zero-config-using-environment-variables */}

```typescript
import { PosthogExporter } from '@mastra/posthog'

// Reads from POSTHOG_API_KEY, POSTHOG_HOST
const exporter = new PosthogExporter()
```

### 明確設定 {/* #explicit-configuration */}

```typescript
import { PosthogExporter } from '@mastra/posthog'

const exporter = new PosthogExporter({
  apiKey: process.env.POSTHOG_API_KEY!,
  host: 'https://us.i.posthog.com',
  serverless: true,
})
```

## Span 類型對應 {/* #span-type-mapping */}

| Mastra Span 類型 | PostHog 事件類型 |
| - | - |
|`MODEL_INFERENCE` | `$ai_generation` |
| `MODEL_GENERATION` | `$ai_span` |
| `MODEL_STEP` | `$ai_span` |
| `MODEL_CHUNK` | `$ai_span` |
| `TOOL_CALL` | `$ai_span` |
| `MCP_TOOL_CALL` | `$ai_span` |
| `PROVIDER_TOOL_CALL` | `$ai_span` |
| `PROCESSOR_RUN` | `$ai_span` |
| `AGENT_RUN` | `$ai_span` |
| `WORKFLOW_RUN` | `$ai_span`|
| 所有其他 Workflow | `$ai_span` |
| `GENERIC` | `$ai_span` |

每次呼叫模型 Provider 都會產生一個 `MODEL_INFERENCE` Span，並匯出為一項 `$ai_generation` 事件。事件包含模型、token 用量、輸出，以及該次呼叫傳入的工具定義（存於 `$ai_tools`）。其 `$ai_input` 是該次呼叫收到的對話：本次執行的輸入訊息，以及先前每次呼叫的輸出及工具結果。若一次執行呼叫模型三次，就會送出三項 `$ai_generation` 事件。

`MODEL_GENERATION` Span 包含這些呼叫，並匯出為 `$ai_span`。PostHog 只會彙總 `$ai_generation` 事件的 token 及費用，因此不會重複計算。若 `@mastra/core` 或 `@mastra/observability` 版本未記錄 `MODEL_INFERENCE` Span，則 `MODEL_GENERATION` 會匯出為 `$ai_generation`。

:::note

使用已棄用的 `generateLegacy()` 及 `streamLegacy()` 方法時，不會記錄 `MODEL_INFERENCE` Span；其 `MODEL_GENERATION` Span 會匯出為 `$ai_span`。這些執行不會向 PostHog 送出 `$ai_generation` 事件，亦不會送出 token 或費用數據。請使用 `generate()` 及 `stream()` 保留這些數據。

:::

## 回饋匯出 {/* #feedback-export */}

透過 [`addFeedback()`](/docs/observability/feedback) 記錄的回饋會以原生 `$ai_feedback` 事件匯出至 PostHog。PostHog 會在關聯的 Trace 上將其顯示為 **User feedback**，無須額外設定。

```typescript
const trace = await mastra.observability.getRecordedTrace({ traceId })
await trace.addFeedback({
  feedbackType: 'thumbs',
  value: 'down',
  comment: 'Wrong answer',
})
```

回饋事件會對應到這些 PostHog 屬性：

| Mastra 回饋欄位 | PostHog 屬性 |
| - | - |
|`traceId` | `$ai_trace_id` |
| `comment`（沒有 comment 時使用 `value`） | `$ai_feedback_text` |
| `feedbackId` | `feedback_id` |
| `feedbackType` | `feedback_type` |
| `value` | `feedback_value` |
| `feedbackSource` | `feedback_source` |
| `spanId` | `span_id` |
| `sourceId` | `source_id` |
| `metadata.sessionId` | `$ai_session_id` |
| `metadata`（其他鍵） | 自訂屬性 |

沒有 `traceId` 的回饋會被捨棄，因為 PostHog 透過 `$ai_trace_id` 將回饋連結至 Trace。事件的 distinct ID 依序取自 `feedbackUserId`、`metadata.userId`、`defaultDistinctId`，最後回退為 `anonymous`。
