# 軌跡精度記分器

Mastra 提供了兩個軌跡準確性評分器，用於評估Agent商或Workflow是否遵循預期的操作序列：

1. **基於代碼的記分器**- 使用精確的步驟匹配和排序進行確定性評估
2. **基於LLM的評分者**- 使用人工智慧進行語義評估來評估軌跡品質和適當性

兩名記分員都與Agent商和Workflow一起工作。這`runEvals` pipeline automatically extracts trajectories, so scorers receive a `Trajectory` object directly.

## 軌跡擷取 {/* #trajectory-extraction */}

這`runEvals` pipeline uses two extraction strategies, depending on whether observability storage is configured:

### 基於痕跡的擷取（首選） {/* #trace-based-extraction-preferred */}

當目標的`Mastra` instance has storage configured, the pipeline fetches the full execution trace from the observability store and calls `extractTrajectoryFromTrace()`. This produces a hierarchical trajectory with nested `children` that captures the complete execution tree. The tree includes nested agent runs and tool calls within workflow steps. It also includes model generations.

例如，呼叫Agent的Workflow，Agent又呼叫Tool，會產生：

```text
workflow_run
  └─ workflow_step (validate-input)
  └─ workflow_step (process-data)
       └─ agent_run (my-agent)
            └─ model_generation
            └─ tool_call (search)
            └─ model_generation
            └─ tool_call (summarize)
  └─ workflow_step (save-result)
```

### 回退提取 {/* #fallback-extraction */}

當儲存不可用時，管道會回退到：

* **Agent商：** `extractTrajectory()`, Extracts `ToolCallStep` entries from `toolInvocations` in the agent's message output. Produces a flat list of tool calls.
* **Workflow：** `extractWorkflowTrajectory()`, Extracts `WorkflowStepStep` entries from `stepResults`. Produces a flat list of workflow steps.

這些回退不會捕獲巢狀執行或非Tool呼叫範圍。

## 預期步驟 {/* #expected-steps */}

定義預期軌跡時，使用`ExpectedStep` instead of the full `TrajectoryStep` discriminated union. `ExpectedStep` is a discriminated union that mirrors `TrajectoryStep`: when you specify a `stepType`, you get autocomplete for that variant's fields (e.g., `toolArgs` for `tool_call`, `modelId` for `model_generation`). All variant-specific fields are optional, so you only assert against what you care about.

忽略`stepType` entirely to match any step by name only.

### 簡單的預期步驟 {/* #simple-expected-steps */}

```typescript
const steps: ExpectedStep[] = [
  // Match by name only (any step type)
  { name: 'search' },

  // Match by name and step type (autocomplete for tool_call fields)
  { name: 'search', stepType: 'tool_call' },

  // Match with specific toolArgs (auto-compared when present)
  { name: 'search', stepType: 'tool_call', toolArgs: { query: 'weather' } },

  // Match a model generation step by model ID
  { name: 'gpt-4o', stepType: 'model_generation', modelId: 'gpt-4o' },
]
```

### 嵌套期望 {/* #nested-expectations */}

每個預期步驟可以包括`children` config with its own evaluation rules. This lets you set different ordering or comparison rules at each level of the hierarchy.

```typescript
const scorer = createTrajectoryScorerCode({
  defaults: {
    ordering: 'strict',
    steps: [
      { name: 'validate-input', stepType: 'workflow_step' },
      {
        name: 'research-agent',
        stepType: 'agent_run',
        children: {
          // Sub-agent can call tools in any order
          ordering: 'unordered',
          steps: [
            { name: 'search', stepType: 'tool_call' },
            { name: 'summarize', stepType: 'tool_call' },
          ],
        },
      },
      { name: 'save-result', stepType: 'workflow_step' },
    ],
  },
})
```

在此範例中，父Workflow要求對其步驟進行嚴格排序，但巢狀Workflow`research-agent` allows its tool calls in any order.

## 在得分手之間進行選擇 {/* #choosing-between-scorers */}

### 在以下情況下使用基於代碼的評分器： {/* #use-the-code-based-scorer-when */}

* 你需要**deterministic, reproducible** results
* 你有一個**known expected trajectory** to compare against
* 您想要驗證**exact step sequences**
* 速度和成本是優先考慮的（沒有法學碩士呼叫）
* 您正在 CI/CD 中執行自動化測試

### 在以下情況下使用基於 LLM 的評分器： {/* #use-the-llm-based-scorer-when */}

* 你需要**semantic understanding** of whether steps were appropriate
* 最優軌跡**isn't predetermined** (evaluate based on task requirements)
* 你想要檢測**unnecessary, redundant, or missing** steps
* 你需要**explanations** for scoring decisions
* 您正在評估**production agent behavior**

### 預期軌跡來源 {/* #expected-trajectory-sources */}

基於代碼的記分器解決了`expectedTrajectory` from two sources, in order of priority:

1. **建構函數選項**：建立得分手時經過的靜態軌跡。用於所有資料集項目。
2. **資料集項**： 一個`expectedTrajectory` field on the dataset item, passed through the `runEvals` pipeline. Allows different expected trajectories per item.

```typescript title="src/static-expected.ts"
// Static: same expected trajectory for all items
const scorer = createTrajectoryAccuracyScorerCode({
  expectedTrajectory: {
    steps: [
      { stepType: 'tool_call', name: 'search' },
      { stepType: 'tool_call', name: 'summarize' },
    ],
  },
})
```

```typescript title="src/per-item-expected.ts"
// Per-item: each dataset item has its own expectedTrajectory
const scorer = createTrajectoryAccuracyScorerCode()

await runEvals({
  target: mastra.getAgent('myAgent'),
  scorers: { trajectory: [scorer] },
  data: [
    {
      input: 'Search and summarize weather',
      expectedTrajectory: {
        steps: [
          { stepType: 'tool_call', name: 'search' },
          { stepType: 'tool_call', name: 'summarize' },
        ],
      },
    },
    {
      input: 'Just search for weather',
      expectedTrajectory: {
        steps: [{ stepType: 'tool_call', name: 'search' }],
      },
    },
  ],
})
```

### 評價模式 {/* #evaluation-modes */}

基於程式碼的記分器以三種模式之一運行`ordering`:

#### 嚴格模式（`ordering: 'strict'`) {/* #strict-mode-ordering-strict */}

只有完全匹配（相同的步驟、相同的順序，沒有任何額外或缺失）得分`1.0`. Anything else gets partial credit for the expected steps that matched in position, with a penalty deducted for each extra step. For example, the two expected steps followed by one extra step scores `0.75`.

#### 放鬆模式（`ordering: 'relaxed'`, default) {/* #relaxed-mode-ordering-relaxed-default */}

允許額外的步驟。預期步驟必須以正確的相對順序出現。分數是根據匹配的預期步數計算的，並對額外或重複的步數可選擇懲罰。

#### 無序模式（`ordering: 'unordered'`) {/* #unordered-mode-ordering-unordered */}

僅檢查每個預期步驟是否存在。順序被忽略，額外的步驟會在結果中報告，但不會受到懲罰。

## 基於代碼的評分詳細信息 {/* #code-based-scoring-details */}

* **連續得分**：在每種排序模式下傳回 0.0 和 1.0 之間的值。在嚴格模式下，分數是按順序匹配的預期步數的份額，減去額外步數的懲罰，並且當`allowRepeatedSteps` is `false`, repeated steps
* **確定性**：相同的輸入總是產生相同的輸出
* **快速地**: 沒有外部API調用

## 基於程式碼的記分器範例 {/* #code-based-scorer-examples */}

### 嚴格排序的Agent軌跡 {/* #agent-trajectory-with-strict-ordering */}

驗證Agent是否遵循準確的Tool呼叫順序：

```typescript title="src/example-strict-trajectory.ts"
import { createTrajectoryAccuracyScorerCode } from '@mastra/evals/scorers/prebuilt'
import { runEvals } from '@mastra/core/evals'

const scorer = createTrajectoryAccuracyScorerCode({
  expectedTrajectory: {
    steps: [
      { stepType: 'tool_call', name: 'auth-tool' },
      { stepType: 'tool_call', name: 'fetch-tool' },
    ],
  },
  comparisonOptions: { ordering: 'strict' },
})

const result = await runEvals({
  target: mastra.getAgent('myAgent'),
  scorers: { trajectory: [scorer] },
  data: [{ input: 'Get my data' }],
})

console.log(result.scores.trajectory['code-trajectory-accuracy-scorer']) // 1.0
```

### 輕鬆排序的Agent軌跡 {/* #agent-trajectory-with-relaxed-ordering */}

只要預期步驟以正確的相對順序出現，就允許額外的步驟：

```typescript title="src/example-relaxed-trajectory.ts"
const scorer = createTrajectoryAccuracyScorerCode({
  expectedTrajectory: {
    steps: [
      { stepType: 'tool_call', name: 'search-tool' },
      { stepType: 'tool_call', name: 'summarize-tool' },
    ],
  },
  comparisonOptions: { ordering: 'relaxed' },
})

// Agent called search-tool → log-tool → summarize-tool
// The extra log-tool is allowed in relaxed mode
// score: 0.75 — all expected steps matched, small penalty for extra step
```

### 特徵 {/* #features */}

基於法學碩士的評分器提供：

* **任務知覺評估**：根據使用者的請求評估每個步驟是否必要
* **訂購評估**：評估步驟是否依邏輯順序執行
* **缺失步驟檢測**：標識應該採取的步驟
* **冗餘檢測**：標記不必要或重複的步驟
* **推理生成**：為評分決策提供人類可讀的解釋

### 評估流程 {/* #evaluation-process */}

1. **接收軌跡**：獲取預提取的`Trajectory` object from the pipeline
2. **分析步驟**：使用法學碩士評估每個步驟的必要性和順序
3. **產生分數**：計算分數，權重為 60% 必要性、30% 排序、減去 10% 缺失罰分
4. **產生推理**：提供人類可讀的解釋

## 基於LLM的評分細節 {/* #llm-based-scoring-details */}

* **分數分數**：傳回 0.0 到 1.0 之間的值
* **情境感知**
* **解釋性的**：提供分數的推理
* **靈活的**：有或沒有預期軌跡均可工作

### 評分行為 {/* #scoring-behavior */}

統一評分器評估四個維度：

1. **準確性**：將實際步驟與預期步驟進行配對（如果`steps` is configured). Uses the `ordering` mode.
2. **效率**：檢查步驟預算（`maxSteps`, `maxTotalTokens`, `maxTotalDurationMs`) and redundant calls (`noRedundantCalls`).
3. **黑名單**：檢查禁止的Tool或序列。任何違規行為都會立即導致分數**0.0** regardless of other dimensions.
4. **Tool故障**：檢測重試和回退模式。它還檢測參數修正模式。

最終得分是活動維度的加權組合，根據活動維度進行標準化。預設權重為準確度 0.4、效率 0.3、Tool故障 0.2、黑名單 0.1，但您可以透過以下方式自訂權重：`weights` option. Blacklist violations override everything to 0. When nested evaluations are present, the score is 70% top-level and 30% nested average.

### 每件商品的期望 {/* #per-item-expectations */}

每個資料集項都可以用自己的值覆蓋預設值`expectedTrajectory`. This lets you vary expectations per prompt:

```typescript title="src/unified-per-item.ts"
import { createTrajectoryScorerCode } from '@mastra/evals/scorers/prebuilt'
import { runEvals } from '@mastra/core/evals'

// Default blacklist applies to all items
const scorer = createTrajectoryScorerCode({
  defaults: {
    blacklistedTools: ['deleteAll'],
    maxSteps: 5,
  },
})

const result = await runEvals({
  target: mastra.getAgent('myAgent'),
  scorers: { trajectory: [scorer] },
  data: [
    {
      input: 'Search for weather',
      expectedTrajectory: {
        steps: [{ stepType: 'tool_call', name: 'search' }],
        maxSteps: 2,
      },
    },
    {
      input: 'Search and summarize',
      expectedTrajectory: {
        steps: [
          { stepType: 'tool_call', name: 'search' },
          { stepType: 'tool_call', name: 'summarize' },
        ],
      },
    },
  ],
})
```

## 使用軌跡記分器`runEvals` {/* #using-trajectory-scorers-with-runevals */}

軌跡記分器配置在`trajectory` key in the scorer config. The `runEvals` pipeline handles trajectory extraction automatically.

### 智能體軌跡評估 {/* #agent-trajectory-evaluation */}

```typescript title="src/agent-trajectory-eval.ts"
import { runEvals } from '@mastra/core/evals'
import { createTrajectoryAccuracyScorerCode } from '@mastra/evals/scorers/prebuilt'

const trajectoryScorer = createTrajectoryAccuracyScorerCode({
  expectedTrajectory: {
    steps: [
      { stepType: 'tool_call', name: 'search' },
      { stepType: 'tool_call', name: 'format' },
    ],
  },
})

const result = await runEvals({
  target: mastra.getAgent('myAgent'),
  scorers: {
    agent: [qualityScorer], // receives raw MastraDBMessage[] output
    trajectory: [trajectoryScorer], // receives pre-extracted Trajectory
  },
  data: [{ input: 'Find and format the data' }],
})

// result.scores.agent['quality'] — agent-level score
// result.scores.trajectory['code-trajectory-accuracy-scorer'] — trajectory score
```
