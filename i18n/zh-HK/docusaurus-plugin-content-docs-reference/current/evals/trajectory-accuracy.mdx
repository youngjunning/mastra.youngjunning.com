# 軌跡準確性評分器

Mastra 提供兩種軌跡準確性評分器，用於評估 Agent 或 Workflow 是否按照預期的動作順序執行：

1. **基於程式碼的評分器**——精確匹配步驟及其順序，給出確定性結果
1. **基於 LLM 的評分器**——由 AI 從語義上評估軌跡品質和適宜性

兩種評分器都適用於 Agent 和 Workflow。`runEvals` 流程會自動擷取軌跡，因此評分器直接接收 `Trajectory` 物件。

## 擷取軌跡 {/* #trajectory-extraction */}

`runEvals` 流程根據是否設定了可觀測性儲存，採用兩種擷取策略之一：

### 從 trace 擷取（建議） {/* #trace-based-extraction-preferred */}

如果目標的 `Mastra` 實例設定了儲存，流程會從可觀測性儲存中取得完整執行 trace，並呼叫 `extractTrajectoryFromTrace()`。得到的分層軌跡包含巢狀的 `children`，能夠反映完整執行樹，包括 Workflow 步驟中的巢狀 Agent 執行、工具呼叫和模型生成。

例如，一個 Workflow 呼叫 Agent，而 Agent 再呼叫工具時，生成的軌跡如下：

```text
workflow_run
  └─ workflow_step (validate-input)
  └─ workflow_step (process-data)
       └─ agent_run (my-agent)
            └─ model_generation
            └─ tool_call (search)
            └─ model_generation
            └─ tool_call (summarize)
  └─ workflow_step (save-result)
```

### 後備擷取方式 {/* #fallback-extraction */}

沒有可用儲存時，流程會改用後備到以下方式：

- **Agent：** `extractTrajectory()` 從 Agent 訊息輸出中的 `toolInvocations` 擷取 `ToolCallStep` 項目，生成扁平的工具呼叫列表。
- **Workflow：** `extractWorkflowTrajectory()` 從 `stepResults` 擷取 `WorkflowStepStep` 項目，生成扁平的 Workflow 步驟列表。

這些改用後備方式無法擷取巢狀執行，也無法擷取非工具呼叫的 span。

## 預期步驟 {/* #expected-steps */}

定義預期軌跡時，應使用 `ExpectedStep`，而非完整的 `TrajectoryStep` 判別聯合類型。`ExpectedStep` 是與 `TrajectoryStep` 對應的判別聯合類型：指定 `stepType` 後，即可獲得該類型欄位的自動補全，例如 `tool_call` 的 `toolArgs`、`model_generation` 的 `modelId`。各類型特有欄位均為可選，因此只需斷言關心的欄位。

```typescript
  // Match with specific toolArgs (auto-compared when present)
```

### 巢狀預期 {/* #nested-expectations */}

每個預期步驟都可以包含帶有獨立評估規則的 `children` 設定，以便在層級結構的不同層級設定不同的順序或比較規則。

```typescript
const scorer = createTrajectoryScorerCode({
  defaults: {
    ordering: 'strict',
    steps: [
      { name: 'validate-input', stepType: 'workflow_step' },
      {
        name: 'research-agent',
        stepType: 'agent_run',
        children: {
          // Sub-agent can call tools in any order
          ordering: 'unordered',
          steps: [
            { name: 'search', stepType: 'tool_call' },
            { name: 'summarize', stepType: 'tool_call' },
          ],
        },
      },
      { name: 'save-result', stepType: 'workflow_step' },
    ],
  },
})
```

在此例子中，父級 Workflow 要求其步驟嚴格按順序執行，但巢狀的 `research-agent` 可以按任意順序呼叫工具。

## 選擇評分器 {/* #choosing-between-scorers */}

### 適合使用基於程式碼的評分器的情況 {/* #use-the-code-based-scorer-when */}

- 需要**確定且可重現**的結果
- 有**已知的預期軌跡**可供比較
- 需要驗證**精確的步驟順序**
- 重視速度和成本（無需呼叫 LLM）
- 正在 CI/CD 中執行自動化測試

### 適合使用基於 LLM 的評分器的情況 {/* #use-the-llm-based-scorer-when */}

- 需要從**語義上判斷**步驟是否合適
- 最優軌跡**無法事先確定**，需要依據任務要求評估
- 需要檢測**不必要、重複或缺失**的步驟
- 需要獲得評分決策的**解釋**
- 正在評估**生產環境中 Agent 的行為**

### 預期軌跡的來源 {/* #expected-trajectory-sources */}

基於程式碼的評分器按以下優先級取得 `expectedTrajectory`：

1. **構造函數選項**：建立評分器時傳入的靜態軌跡，適用於所有數據集項目。
1. **數據集項目**：數據集項目中的 `expectedTrajectory` 欄位，由 `runEvals` 流程傳入；各項目可以使用不同的預期軌跡。

```typescript title="src/static-expected.ts"
// Static: same expected trajectory for all items
const scorer = createTrajectoryAccuracyScorerCode({
  expectedTrajectory: {
    steps: [
      { stepType: 'tool_call', name: 'search' },
      { stepType: 'tool_call', name: 'summarize' },
    ],
  },
})
```

```typescript title="src/per-item-expected.ts"
// Per-item: each dataset item has its own expectedTrajectory
const scorer = createTrajectoryAccuracyScorerCode()

await runEvals({
  target: mastra.getAgent('myAgent'),
  scorers: { trajectory: [scorer] },
  data: [
    {
      input: 'Search and summarize weather',
      expectedTrajectory: {
        steps: [
          { stepType: 'tool_call', name: 'search' },
          { stepType: 'tool_call', name: 'summarize' },
        ],
      },
    },
    {
      input: 'Just search for weather',
      expectedTrajectory: {
        steps: [{ stepType: 'tool_call', name: 'search' }],
      },
    },
  ],
})
```

### 評估模式 {/* #evaluation-modes */}

基於程式碼的評分器根據 `ordering` 選擇以下三種模式之一：

#### 嚴格模式（`ordering: 'strict'`） {/* #strict-mode-ordering-strict */}

只有完全匹配（步驟和順序均相同，且沒有額外或缺失的步驟）才得 `1.0`。其他情況會根據預期步驟在對應位置的匹配程度給部分分數，並對每個額外步驟扣分。例如，兩個預期步驟之後多出一個步驟，得分為 `0.75`。

#### 寬鬆模式（`ordering: 'relaxed'`，預設） {/* #relaxed-mode-ordering-relaxed-default */}

允許額外步驟。預期步驟必須按正確的相對順序出現。得分根據匹配的預期步驟數量計算，並可對額外或重複步驟扣分。

#### 無序模式（`ordering: 'unordered'`） {/* #unordered-mode-ordering-unordered */}

只檢查每個預期步驟是否出現。忽略順序；結果中會報告額外步驟，但不會因此扣分。

## 基於程式碼的評分細節 {/* #code-based-scoring-details */}

- **連續得分**：所有順序模式都傳回 0.0 到 1.0 之間的值。嚴格模式下，得分為按順序匹配的預期步驟佔比，再減去額外步驟的扣分；當 `allowRepeatedSteps` 為 `false` 時，還會扣除重複步驟的分數
- **確定性**：相同輸入始終產生相同輸出
- **快速**：無需呼叫外部 API

## 基於程式碼的評分器例子 {/* #code-based-scorer-examples */}

### 嚴格順序的 Agent 軌跡 {/* #agent-trajectory-with-strict-ordering */}

驗證 Agent 是否按精確的工具呼叫順序執行：

```typescript title="src/example-strict-trajectory.ts"
import { createTrajectoryAccuracyScorerCode } from '@mastra/evals/scorers/prebuilt'
import { runEvals } from '@mastra/core/evals'

const scorer = createTrajectoryAccuracyScorerCode({
  expectedTrajectory: {
    steps: [
      { stepType: 'tool_call', name: 'auth-tool' },
      { stepType: 'tool_call', name: 'fetch-tool' },
    ],
  },
  comparisonOptions: { ordering: 'strict' },
})

const result = await runEvals({
  target: mastra.getAgent('myAgent'),
  scorers: { trajectory: [scorer] },
  data: [{ input: 'Get my data' }],
})

console.log(result.scores.trajectory['code-trajectory-accuracy-scorer']) // 1.0
```

### 寬鬆順序的 Agent 軌跡 {/* #agent-trajectory-with-relaxed-ordering */}

只要預期步驟保持正確的相對順序，即允許額外步驟：

```typescript title="src/example-relaxed-trajectory.ts"
const scorer = createTrajectoryAccuracyScorerCode({
  expectedTrajectory: {
    steps: [
      { stepType: 'tool_call', name: 'search-tool' },
      { stepType: 'tool_call', name: 'summarize-tool' },
    ],
  },
  comparisonOptions: { ordering: 'relaxed' },
})

// Agent called search-tool → log-tool → summarize-tool
// The extra log-tool is allowed in relaxed mode
// score: 0.75 — all expected steps matched, small penalty for extra step
```

### 功能 {/* #features */}

基於 LLM 的評分器能夠：

- **感知任務的評估**：根據用戶請求判斷每個步驟是否必要
- **順序評估**：判斷步驟是否按合理順序執行
- **缺失步驟檢測**：識別本應執行的步驟
- **冗余檢測**：標出不必要或重複的步驟
- **生成理由**：提供人類可讀的評分解釋

### 評估流程 {/* #evaluation-process */}

1. **接收軌跡**：從流程取得已擷取的 `Trajectory` 物件
1. **分析步驟**：使用 LLM 判斷各步驟是否必要、順序是否合理
1. **計算得分**：必要性佔 60%，順序佔 30%，再減去10% 的缺失步驟扣分
1. **生成理由**：提供人類可讀的解釋

## 基於 LLM 的評分細節 {/* #llm-based-scoring-details */}

- **小數得分**：傳回 0.0 到 1.0 之間的值
- **感知上下文**：考慮用戶意圖和任務要求
- **解釋得分**：提供評分理由
- **靈活**：有無預期軌跡均可使用

### 基於 LLM 的評分器選項 {/* #llm-based-scorer-options */}

```typescript
// Evaluate based on task requirements (no expected trajectory)

      { stepType: 'tool_call', name: 'search-tool' },
      { stepType: 'tool_call', name: 'summarize-tool' },

  },
})
```

### 評分行為 {/* #scoring-behavior */}

綜合評分器評估四個維度：

1. **準確性**：將實際步驟與預期步驟匹配（如果設定了 `steps`），並採用指定的 `ordering` 模式。
1. **效率**：檢查步驟預算（`maxSteps`、`maxTotalTokens`、`maxTotalDurationMs`）和重複呼叫（`noRedundantCalls`）。
1. **禁用規則**：檢查禁止呼叫的工具或工具序列。無論其他維度得分如何，只要違反規則，得分立即變為 **0.0**。
1. **工具失敗**：檢測重試、改用後備和參數修正模式。

最終得分按啟用維度的權重合成，並根據實際啟用的維度歸一化。預設權重分別為：準確性 0.4、效率 0.3、工具失敗 0.2、禁用規則 0.1；可以透過 `weights` 自訂。違反禁用規則會使總分變為 0。存在巢狀評估時，頂層得分佔 70%，巢狀得分的平均值佔 30%。

### 按數據集項目設定預期 {/* #per-item-expectations */}

每個數據集項目都可以用自己的 `expectedTrajectory` 覆蓋預設值，因此可以針對不同提示詞設定不同預期：

```typescript title="src/unified-per-item.ts"
import { createTrajectoryScorerCode } from '@mastra/evals/scorers/prebuilt'
import { runEvals } from '@mastra/core/evals'

// Default blacklist applies to all items
const scorer = createTrajectoryScorerCode({
  defaults: {
    blacklistedTools: ['deleteAll'],
    maxSteps: 5,
  },
})

const result = await runEvals({
  target: mastra.getAgent('myAgent'),
  scorers: { trajectory: [scorer] },
  data: [
    {
      input: 'Search for weather',
      expectedTrajectory: {
        steps: [{ stepType: 'tool_call', name: 'search' }],
        maxSteps: 2,
      },
    },
    {
      input: 'Search and summarize',
      expectedTrajectory: {
        steps: [
          { stepType: 'tool_call', name: 'search' },
          { stepType: 'tool_call', name: 'summarize' },
        ],
      },
    },
  ],
})
```

### 例子：效率與禁用規則 {/* #example-efficiency-and-blacklist */}

```typescript title="src/unified-scorer.ts"
import { createTrajectoryScorerCode } from '@mastra/evals/scorers/prebuilt'

const scorer = createTrajectoryScorerCode({
  defaults: {
    blacklistedTools: ['escalate', 'admin-override'],

    noRedundantCalls: true,

    toolFailures: 0.1,

  },
})
```

## 在 `runEvals` 中使用軌跡評分器 {/* #using-trajectory-scorers-with-runevals */}

在評分器設定中，軌跡評分器位於 `trajectory` 鍵下。`runEvals` 流程會自動擷取軌跡。

### 評估 Agent 軌跡 {/* #agent-trajectory-evaluation */}

```typescript title="src/agent-trajectory-eval.ts"
import { runEvals } from '@mastra/core/evals'
import { createTrajectoryAccuracyScorerCode } from '@mastra/evals/scorers/prebuilt'

const trajectoryScorer = createTrajectoryAccuracyScorerCode({
  expectedTrajectory: {
    steps: [
      { stepType: 'tool_call', name: 'search' },
      { stepType: 'tool_call', name: 'format' },
    ],
  },
})

const result = await runEvals({
  target: mastra.getAgent('myAgent'),
  scorers: {
    agent: [qualityScorer], // receives raw MastraDBMessage[] output
    trajectory: [trajectoryScorer], // receives pre-extracted Trajectory
  },
  data: [{ input: 'Find and format the data' }],
})

// result.scores.agent['quality'] — agent-level score
// result.scores.trajectory['code-trajectory-accuracy-scorer'] — trajectory score
```
