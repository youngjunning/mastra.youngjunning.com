# Multi-turn Judge 評分器

**加入版本：** `@mastra/evals@1.9.0`

`createMultiTurnJudgeScorer()` 建立由 LLM 擔任評審的評分器，依據一項自然語言準則評估整段對話。它傳回**二元**分數：符合準則時為 `1`，否則為 `0`；`reason` 會列出準則及評審的說明。

其他預建的 LLM 評審只讀取一則助理訊息；此評分器會讀取 `run.output` 中累積的每輪助理回覆，因此適用於[多輪 `inputs`](/docs/evals/multi-turn)形式的 [`runEvals()`](/reference/evals/run-evals)。

## 在多輪評估中使用 {/* #usage-with-multi-turn-evals */}

將評分器傳給 `runEvals`，並提供 `inputs` 陣列。傳送給評審的提示詞包含每輪助理回覆：

```typescript title="src/evals/trip-planning-eval.ts"
import { runEvals } from '@mastra/core/evals'
// highlight-next-line
import { createMultiTurnJudgeScorer } from '@mastra/evals/scorers/prebuilt'
import { weatherAgent } from '../agents'

const result = await runEvals({
  data: [
    {
      inputs: [
        "I'm planning a trip to London, Paris, and Tokyo next week.",
        "How's the weather looking in London?",
        'And Paris?',
        'Tokyo too?',
        'Should I pack an umbrella for the London leg?',
      ],
    },
  ],
  target: weatherAgent,
  scorers: [
    {
      // highlight-start
      scorer: createMultiTurnJudgeScorer({
        model: '__GATEWAY_ANTHROPIC_MODEL_HAIKU__',
        criterion:
          'The agent provided weather forecasts for London, Paris, and Tokyo, and gave weather-appropriate packing or clothing advice.',
      }),
      // highlight-end
      threshold: 1,
    },
  ],
})
```

使用 `threshold: 1` 將結果轉為通過或失敗：分數只有兩個值，因此任何更低的門檻都會一律判為通過。

## 持久化分數 {/* #persisting-scores */}

只有在 Mastra 實例中註冊相同 ID 的評分器，分數才會寫入分數儲存庫。持久化程序透過 `Mastra.getScorerById()` 查詢評分器中繼資料；由於只查詢 ID，註冊實例的 `criterion` 可以使用佔位值：

```typescript title="src/mastra/index.ts"
import { Mastra } from '@mastra/core'
import { LibSQLStore } from '@mastra/libsql'
import { createMultiTurnJudgeScorer } from '@mastra/evals/scorers/prebuilt'

export const mastra = new Mastra({
  agents: { weatherAgent },
  storage: new LibSQLStore({ url: 'file:./mastra.db' }),
  scorers: {
    // highlight-start
    'multi-turn-judge-scorer': createMultiTurnJudgeScorer({
      model: '__GATEWAY_ANTHROPIC_MODEL_HAIKU__',
      criterion: 'placeholder',
    }),
    // highlight-end
  },
})
```

完整要求及未註冊評分器時的警告，請參閱[分數持久化](/docs/evals/overview#score-persistence)。

## 評分細節 {/* #scoring-details */}

評分器分兩個階段運作：

1. **評判**：將 `run.output` 中的助理訊息整理成編號對話紀錄，由評審依準則整體評估。只包含工具呼叫或沒有文字的輪次會略過。
2. **計分**：判定為 `satisfied` 時得 `1` 分，其他結果得 `0` 分，再乘以 `scale`。

評審只能看到助理回覆，看不到用戶的輪次或任何 Tool 結果。因此，應依據 Agent 的回覆撰寫準則。這將評分內容限於 Agent 自己的輸出，但對於脫離用戶問題便無法理解的回覆（例如「對，帶一把。」），評審也無法單獨判斷。如果準則依賴用戶輪次，請用 `turns[].scorers` 逐輪評分，或撰寫同時呈現雙方訊息的[自訂評分器](/docs/evals/multi-turn)。

對話紀錄以不可信資料的形式傳給評審，並以明確的分隔符號包住；提示詞也要求忽略其中看似指令的內容，避免 Agent 回覆藉提示注入取得通過判定。
