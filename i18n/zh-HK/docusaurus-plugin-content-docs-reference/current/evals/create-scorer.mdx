# createScorer

Mastra 提供統一的 `createScorer` 工廠函式，用來定義評估輸入及輸出的自訂評分器。每個評估步驟都可使用原生 JavaScript 函式，或以 LLM 為基礎的提示物件。自訂評分器可加入 Agent 及 Workflow 步驟。

## 如何建立自訂評分器 {/* #how-to-create-a-custom-scorer */}

使用 `createScorer` 工廠函式指定評分器名稱、說明及可選的 judge 設定，再串接步驟方法建立評估流程。至少必須提供一個 `generateScore` 步驟。

**提示物件步驟**使用包含 `description` 及 `createPrompt` 的物件設定；`preprocess` 及 `analyze` 還可使用 `outputSchema`，`generateScore` 則不可使用。這類步驟會呼叫 judge LLM。**函式步驟**是一般函式，絕不會呼叫 judge。

```typescript
import { createScorer } from '@mastra/core/evals'

const scorer = createScorer({
  id: 'my-custom-scorer',
  name: 'My Custom Scorer', // Optional, defaults to id
  description: 'Evaluates responses based on custom criteria',
  type: 'agent', // Optional: for agent evaluation with automatic typing
  judge: {
    model: myModel,
    instructions: 'You are an expert evaluator...',
  },
})
  .preprocess({/* step config */})
  .analyze({/* step config */})
  .generateScore(({ run, results }) => {
    // Return a number
  })
  .generateReason({/* step config */})
```

此函式會傳回評分器建構器，可繼續串接步驟方法。有關 `.run()` 方法及其輸入及輸出，請參閱 [MastraScorer 參考文件](./mastra-scorer)。

judge 只會在定義為**提示物件**的步驟中執行（提示模式下的 `preprocess`、`analyze`、`generateScore` 及 `generateReason`）。如只使用函式步驟，就不會呼叫 judge，亦沒有可檢查的 LLM 輸出；分數及原因必須由函式產生。

提示物件步驟執行時，LLM 的結構化輸出會存入對應的結果欄位（`preprocessStepResult` 或 `analyzeStepResult`）。對於 `generateScore`，judge 會傳回 `{ score: number }`，當中的 `score` 即為評分器分數。

## 重試 judge 請求 {/* #retry-judge-requests */}

使用現有的 judge `errorProcessors` 設定，可在 judge 請求失敗時重試暫時性故障。它不會重試評分器 Workflow、Trace 目標、批量項目、分數寫入或已完成的評分器步驟。

`@mastra/core` `1.49.0` 不包含評分器的錯誤處理器設定。使用此設定前，請升級至支援評分器處理器的版本，或移植對應的局部改動。

以下例子使用有上限的重試次數。請將處理器的 `maxRetries` 及 `judge.maxProcessorRetries` 設為相同值，並將內部 judge Agent 的模型重試次數保持為預設值 `0`，避免模型重試令處理器嘗試次數倍增。

```typescript title="src/mastra/scorers/response-quality.ts"
import { createScorer } from '@mastra/core/evals'
import { StreamErrorRetryProcessor } from '@mastra/core/processors'

const isTransientNetworkError = (error: unknown) =>
  error instanceof Error && /ECONNRESET|ETIMEDOUT|socket hang up/i.test(error.message)

const retryProcessor = new StreamErrorRetryProcessor({
  maxRetries: 2,
  maxRetryAfterMs: 30_000,
  delayMs: ({ retryCount }) => Math.min(1_000 * 2 ** retryCount, 30_000),
  matchers: [isTransientNetworkError],
  retryUnknownErrors: false,
})

export const responseQuality = createScorer({
  id: 'response-quality',
  description: 'Scores response quality',
  judge: {
    model: myModel,
    instructions: 'Return a score and concise reason.',
    errorProcessors: [retryProcessor],
    maxProcessorRetries: 2,
  },
})
  .generateScore({
    description: 'Score the response quality.',
    createPrompt: ({ run }) => `Score: ${run.output}`,
  })
  .generateReason({
    description: 'Explain the score.',
    createPrompt: () => 'Explain the score.',
  })
```

按此設定，失敗的請求最多會向 Provider 嘗試三次：首次請求加上兩次處理器重試。如 `generateScore` 已完成，而 `generateReason` 遇到可重試故障，則只重試 `generateReason`。

`StreamErrorRetryProcessor` 會按 Provider 傳回的可重試元數據及範圍明確的自訂比對條件決定是否重試。`retryUnknownErrors` 預設關閉，因此驗證、無效請求及上下文長度錯誤會立即失敗，除非明確比對這些錯誤。`Retry-After` 預設上限為 `30_000` 毫秒；可用 `maxRetryAfterMs` 修改。

避免加入外層評分器或 Workflow 重試。除非有意接受額外嘗試次數，否則不要同時使用非零的模型重試設定及此處理器。

### 覆寫單一步驟的重試設定 {/* #override-retries-for-one-step */}

步驟層級的 `judge` 設定會覆寫評分器層級的 judge 欄位。處理器陣列會取代評分器層級的陣列。如步驟設定省略 `maxProcessorRetries`，便會繼承評分器層級的數值上限。

協調處理器重試需要使用 Mastra 現時生成 API 的 judge 模型。舊版模型轉接器會呼叫 [`generateLegacy()`](/reference/agents/generateLegacy)，略過錯誤處理器，並使用該 API 獨立的 AI SDK `maxRetries` 預設值 `2`。

## 類型安全 {/* #type-safety */}

建立評分器時可指定輸入及輸出類型，以獲得更好的類型推斷及 IntelliSense 支援：

### Agent 類型捷徑 {/* #agent-type-shortcut */}

評估 Agent 時，使用 `type: 'agent'` 即可自動取得正確的 Agent 輸入及輸出類型：

```typescript
import { createScorer } from '@mastra/core/evals'

// Agent scorer with automatic typing
const agentScorer = createScorer({
  id: 'agent-response-quality',
  description: 'Evaluates agent responses',
  type: 'agent', // Automatically provides ScorerRunInputForAgent/ScorerRunOutputForAgent
})
  .preprocess(({ run }) => {
    // run.input is automatically typed as ScorerRunInputForAgent
    const userMessage = run.inputData.inputMessages[0]?.content
    return { userMessage }
  })
  .generateScore(({ run, results }) => {
    // run.output is automatically typed as ScorerRunOutputForAgent
    const response = run.output[0]?.content
    return response.length > 10 ? 1.0 : 0.5
  })
```

### 使用泛型定義自訂類型 {/* #custom-types-with-generics */}

如要自訂輸入及輸出類型，可使用泛型：

```typescript
import { createScorer } from '@mastra/core/evals'

type CustomInput = { query: string; context: string[] }
type CustomOutput = { answer: string; confidence: number }

const customScorer = createScorer<CustomInput, CustomOutput>({
  id: 'custom-scorer',
  description: 'Evaluates custom data',
}).generateScore(({ run }) => {
  // run.input is typed as CustomInput
  // run.output is typed as CustomOutput
  return run.output.confidence
})
```

### 內建 Agent 類型 {/* #built-in-agent-types */}

* **`ScorerRunInputForAgent`**：包含用於評估 Agent 的 `inputMessages`、`rememberedMessages`、`systemMessages` 及 `taggedSystemMessages`
* **`ScorerRunOutputForAgent`**：Agent 回應訊息陣列

使用這些類型可讓評分邏輯獲得自動完成、編譯時驗證及更清晰的文件。

## 使用 Agent 類型為 Trace 評分 {/* #trace-scoring-with-agent-types */}

使用 `type: 'agent'` 時，評分器既可直接加入 Agent，亦可為 Agent 互動產生的 Trace 評分。評分器會自動將 Trace 數據轉為相應的 Agent 輸入及輸出格式：

```typescript
const agentTraceScorer = createScorer({
  id: 'agent-trace-length',
  description: 'Evaluates agent response length',
  type: 'agent',
}).generateScore(({ run }) => {
  // Trace data is automatically transformed to agent format
  const userMessages = run.inputData.inputMessages
  const agentResponse = run.output[0]?.content

  // Score based on response length
  return agentResponse?.length > 50 ? 0 : 1
})

// Register with Mastra for trace scoring
const mastra = new Mastra({
  scorers: {
    agentTraceScorer,
  },
})
```
