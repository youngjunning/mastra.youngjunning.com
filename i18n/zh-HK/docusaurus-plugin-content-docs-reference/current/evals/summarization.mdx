# 摘要評分器

`createSummarizationScorer()` 建立的評分器從兩個方面評估摘要：每項陳述是否得到原文支持，以及摘要是否保留了原文資料。最終得分取兩項中較低的一項。因此，摘要僅僅準確卻空洞，或內容全面卻不準確，都無法獲得高分。

摘要取自 Agent 最後一則包含文字的訊息；原文預設取自該次執行輸入的第一則用戶訊息。若待摘要的內容來自其他位置，例如工具執行結果，請傳入 `source` 或 `sourceExtractor`。

## 使用例子 {/* #usage-example */}

根據摘要所概括的文件為摘要評分。

```typescript title="src/mastra/scorers/summarization.ts"
import { createSummarizationScorer } from '@mastra/evals/scorers/prebuilt'

const scorer = createSummarizationScorer({
  model: '__GATEWAY_OPENAI_MODEL__',
})

const result = await scorer.run({
  input: {
    inputMessages: [{ id: '1', role: 'user', content: sourceDocument }],
  },
  output: [{ id: '2', role: 'assistant', content: summary }],
})

console.log(result.score)
console.log(result.reason)
```

## 摘要評估 {/* #summarization-evaluation */}

當 Agent 將文字壓縮成摘要時，可使用此評分器：

- 文件與會議逐字稿摘要
- 客戶支援對話與電郵摘要
- 將長篇輸入壓縮為簡短輸出的任何步驟

兩個維度的分數由這些判斷結果計算，並非直接儲存：準確性分數是 `alignment` 中 `supported: true` 的比例；涵蓋度分數是 `questions` 中其對應 `coverage` 項目標記為 `answered: true` 的比例。

## 評分細節 {/* #scoring-details */}

### 雙維度評估 {/* #two-axis-evaluation */}

評分器分三步執行：

1. **原文判斷**：擷取摘要中的陳述並對照原文核對，同時從原文生成封閉式問題。每個問題都設定為可由原文回答“是”。
1. **涵蓋度判斷**：僅根據摘要回答每個問題。
1. **計算得分**：計算兩個比例，取較低者作為得分。

涵蓋度判斷由單獨一次模型呼叫完成，且這次呼叫不會收到原文。如果判斷模型能看到原文，就可能直接從原文回答問題，掩蓋摘要遺漏的資料。

### 評分公式 {/* #scoring-formula */}

```text
Alignment    = supported_claims / total_claims
Coverage     = answered_questions / total_questions
Summarization = min(Alignment, Coverage) × scale
```

如果摘要沒有提出任何陳述，或原文無法生成問題，得分為 0。

### 得分解讀 {/* #score-interpretation */}

以下區間以預設 `scale` 值 1 為前提；使用自訂值時，得分區間也要相應乘以該值。

- **0.9–1.0**：優秀；忠實於原文並覆蓋主要內容
- **0.7–0.8**：良好；有少量遺漏或一處缺乏依據的細節
- **0.4–0.6**：一般；遺漏重要資料或偏離原文
- **0.1–0.3**：較差；原文大部分資料丟失或被錯誤表述
- **0.0**：摘要沒有可供判斷的內容，或所有陳述都缺乏依據；一個問題也未回答時同樣得 0 分

### 如何查看兩個維度 {/* #reading-the-two-axes */}

兩個維度的判斷結果都保存在執行結果中：準確性判斷位於預處理步驟，涵蓋度判斷位於分析步驟。每條判斷結果都包含對應的陳述或問題及其理由。低準確性得分與低涵蓋度得分含義不同：

- 準確性低、涵蓋度高，表示摘要編造或歪曲了細節
- 涵蓋度低、準確性高，表示摘要雖然準確，卻遺漏了太多內容

reason 欄位會指出決定最終得分的維度。

### 得分未衡量的方面 {/* #what-the-score-leaves-out */}

摘要長度不計入得分。逐字復述原文的“摘要”能支持每項陳述並回答所有問題，因此可得 1 分。如果你還需要評估壓縮程度，應自行增加長度檢查。

### 成本 {/* #cost */}

每次評估會呼叫模型三次。`maxQuestions` 限制涵蓋度評估所用的問題數目，否則工作量會隨原文長度增加。對於無法用十個問題充分概括的長文件，可提高此上限。

## 評分器設定 {/* #scorer-configuration */}

### 為執行輸入生成摘要 {/* #summarizing-the-run-input */}

```typescript
const scorer = createSummarizationScorer({
  model: '__GATEWAY_OPENAI_MODEL__',
})
```

### 為其他來源的文件生成摘要 {/* #summarizing-a-document-from-elsewhere */}

```typescript
import { extractToolResults } from '@mastra/evals/scorers/utils'

const scorer = createSummarizationScorer({
  model: '__GATEWAY_OPENAI_MODEL__',
  options: {
    sourceExtractor: (input, output) => {
      return extractToolResults(output)
        .filter(({ toolName }) => toolName === 'fetchDocument')
        .map(({ result }) => String(result))
        .join('\n\n')
    },
    maxQuestions: 20,
  },
})
```

## 例子 {/* #example */}

對照一組文件評估摘要 Agent：

```typescript title="src/example-summarization.ts"
import { runEvals } from '@mastra/core/evals'
import { createSummarizationScorer } from '@mastra/evals/scorers/prebuilt'
import { summarizerAgent } from './agent'

const scorer = createSummarizationScorer({
  model: '__GATEWAY_OPENAI_MODEL__',
  options: { maxQuestions: 10 },
})

const result = await runEvals({
  target: summarizerAgent,
  scorers: [scorer],
  data: [
    {
      input:
        'The company was founded in 1995 by John Smith. It started with 10 employees and grew to 500 by 2020. The company is based in Seattle.',
    },
  ],
  onItemComplete: ({ scorerResults }) => {
    console.log({
      score: scorerResults[scorer.id].score,
      reason: scorerResults[scorer.id].reason,
    })
  },
})

console.log(result.scores)
```

關於 `runEvals` 的詳情，請參閱 [runEvals 參考文件](/reference/evals/run-evals)。

如要將此評分器加入 Agent，請參閱 [評分器概覽](/docs/evals/overview#adding-scorers-to-agents) 指南。

## 與 faithfulness 評分器比較 {/* #comparison-with-faithfulness */}

| 使用場景 | 摘要評分器 | Faithfulness 評分器 |
| - | - | - |
| **衡量內容** | 同時衡量依據和涵蓋度 | 僅衡量依據 |
| **對照材料** | 被概括的原文 | 檢索到的上下文或工具結果 |
| **檢測遺漏** | 是 | 否 |
| **需要完整原文** | 是 | 否，僅有上下文即可 |

如果要判斷回答是否有檢索上下文依據，請使用 `faithfulness`；如果輸出旨在代替較長的原文，請使用 `summarization`。
