# 總結記分員

這`createSummarizationScorer()`函數建立一個評分器，在兩個軸上評估摘要：每個聲明是否具有來源文字支援以及摘要是否保留來源資訊。最終得分取兩者中較低者。總結不能說是忠實而空洞，也不能說是徹底但錯誤。

摘要是Agent攜帶文字的最後一則訊息，來源文字預設為運行輸入的第一個使用者訊息。經過`source` or `sourceExtractor`當被總結的文本位於其他地方時，例如Tool結果。

## 使用範例 {/* #usage-example */}

根據其濃縮的文檔對摘要進行評分。

```typescript title="src/mastra/scorers/summarization.ts"
import { createSummarizationScorer } from '@mastra/evals/scorers/prebuilt'

const scorer = createSummarizationScorer({
  model: '__GATEWAY_OPENAI_MODEL__',
})

const result = await scorer.run({
  input: {
    inputMessages: [{ id: '1', role: 'user', content: sourceDocument }],
  },
  output: [{ id: '2', role: 'assistant', content: summary }],
})

console.log(result.score)
console.log(result.reason)
```

## 總結評價 {/* #summarization-evaluation */}

當Agent程式壓縮文字時使用此記分器：

* 文件和成績單摘要
* 支援主題和電子郵件摘要
* 將長輸入壓縮為短輸出的任何步驟

軸分數是從這些判決中得出的，而不是儲存的：對齊是`alignment` entries with `supported: true`, and coverage is the share of `questions` whose `coverage` entry has `answered: true`.

## 評分詳情 {/* #scoring-details */}

### 兩軸評估 {/* #two-axis-evaluation */}

記分器運行三步驟管道：

1. **來源判斷**：摘要中的主張是根據來源提取和檢查的，封閉式問題是從來源中提取的。每個問題都被寫下來，所以來源回答“是”。
2. **覆蓋範圍**：每個問題都僅使用摘要來回答。
3. **評分**：計算兩個比率，較低者為分數。

覆蓋步驟作為單獨的模型呼叫運行，從不接收來源文字。能夠看到消息來源的法官會從消息來源而不是摘要中回答問題，這將隱藏該軸存在的要衡量的遺漏。

### 評分公式 {/* #scoring-formula */}

```text
Alignment    = supported_claims / total_claims
Coverage     = answered_questions / total_questions
Summarization = min(Alignment, Coverage) × scale
```

當摘要沒有提出任何主張或來源沒有提出任何問題時，得分為 0。

### 分數解讀 {/* #score-interpretation */}

這些範圍採用預設值`scale` of 1. When using a custom scale, multiply accordingly.

* **0.9-1.0**：優秀的總結，忠實於來源並涵蓋了要點
* **0.7-0.8**：很好的總結，有一個小遺漏或不受支持的細節
* **0.4-0.6**：總結一般，要麼遺漏重要訊息，要麼偏離來源
* **0.1-0.3**：總結不佳，大部分來源已遺失或相互矛盾
* **0.0**：摘要沒有提供任何可供判斷的內容，或未能支持任何主張。不回答任何問題的摘要也會獲得此分數

### 讀取兩個軸 {/* #reading-the-two-axes */}

兩個軸都會對運行結果做出判斷：預處理步驟的對齊判斷和分析步驟的覆蓋判斷。每個判決都包含其所屬的主張或問題及其背後的原因。低對齊分數與低覆蓋分數有不同的意義：

* 低對齊分數和高覆蓋率意味著摘要發明或扭曲了細節
* 低覆蓋率分數和高對齊意味著摘要是準確的，但遺漏了太多內容

原因欄位以產生分數的軸命名。

### 分數遺漏了什麼 {/* #what-the-score-leaves-out */}

長度對樂譜沒有影響。逐字重複原始碼的摘要支持每個主張並回答每個問題，因此得分為 1。當壓縮是您測試的一部分時，請添加您自己的長度檢查。

### 成本 {/* #cost */}

每個評估都會呼叫三個模型。`maxQuestions` bounds the coverage half of the work, which otherwise grows with source length. Raise it for long documents where ten questions can't represent the content.

## 記分器配置 {/* #scorer-configuration */}

### 總結運行輸入 {/* #summarizing-the-run-input */}

```typescript
const scorer = createSummarizationScorer({
  model: '__GATEWAY_OPENAI_MODEL__',
})
```

### 總結其他地方的文檔 {/* #summarizing-a-document-from-elsewhere */}

```typescript
import { extractToolResults } from '@mastra/evals/scorers/utils'

const scorer = createSummarizationScorer({
  model: '__GATEWAY_OPENAI_MODEL__',
  options: {
    sourceExtractor: (input, output) => {
      return extractToolResults(output)
        .filter(({ toolName }) => toolName === 'fetchDocument')
        .map(({ result }) => String(result))
        .join('\n\n')
    },
    maxQuestions: 20,
  },
})
```

## 例子 {/* #example */}

根據一組文件評估摘要Agent：

```typescript title="src/example-summarization.ts"
import { runEvals } from '@mastra/core/evals'
import { createSummarizationScorer } from '@mastra/evals/scorers/prebuilt'
import { summarizerAgent } from './agent'

const scorer = createSummarizationScorer({
  model: '__GATEWAY_OPENAI_MODEL__',
  options: { maxQuestions: 10 },
})

const result = await runEvals({
  target: summarizerAgent,
  scorers: [scorer],
  data: [
    {
      input:
        'The company was founded in 1995 by John Smith. It started with 10 employees and grew to 500 by 2020. The company is based in Seattle.',
    },
  ],
  onItemComplete: ({ scorerResults }) => {
    console.log({
      score: scorerResults[scorer.id].score,
      reason: scorerResults[scorer.id].reason,
    })
  },
})

console.log(result.scores)
```

欲了解更多詳情`runEvals`, see the [runEvals reference](/reference/evals/run-evals).

若要將此記分員新增至Agent，請參閱[Scorers overview](/docs/evals/overview#adding-scorers-to-agents) guide.

## 與忠誠度的比較 {/* #comparison-with-faithfulness */}

|使用案例 |總結|誠信|
| - | - | - |
|**What it measures** | Support and coverage together | Support only |
| **Judged against** | The source text being condensed | Retrieved context or tool results |
| **Catches omission** | Yes | No |
| **Needs the full source** | Yes | No, context alone is enough |

使用`faithfulness` when the question is whether an answer stays grounded in retrieved context. Use `summarization` when the output is meant to stand in for a longer text.
