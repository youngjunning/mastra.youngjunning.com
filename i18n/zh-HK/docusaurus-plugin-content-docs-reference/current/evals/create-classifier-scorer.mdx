# createClassifierScorer

`createClassifierScorer()` 將建構時設定的一個 [`Classifier`](/reference/classifier/classifier) 問題接入 Mastra 評分器流程。它會傳回具數值 `score` 的標準 `MastraScorer`，並在 `analyzeStepResult` 中保留所選答案、機率、用量、警告及安全的回應元數據。

每次執行評分器都會呼叫 `Classifier.decide()`，評估分類器中設定的所有問題，但只將 `question` 指定問題的答案轉為 0 到 1 的分數。`question` 選項不會限制傳送給模型的問題。此轉接器不會合併多個問題、套用布林閾值、推斷選項順序，亦不會呼叫第二個評判模型。

如每次執行只想評估一個問題，請使用只設定該問題的獨立分類器。例如，五個 rubric 評分器共用一個包含五個問題的分類器時，每個評分器每次都會評估全部五個問題，而非只評估自己選取的問題。

Agent 評分器的執行數據包含訊息物件，`Classifier.decide()` 無法直接接收，因此必須提供 `state`。可用它擷取與 JSON 兼容的文字，例如使用 `@mastra/evals/scorers/utils` 中的輔助函式。

## 例子 {/* #example */}

```typescript title="src/mastra/scorers/response-quality.ts"
import { Classifier } from '@mastra/core/classifier'
import { typeSafeAi } from '@ai-sdk/typesafe-ai'
import { createClassifierScorer } from '@mastra/core/evals'
import {
  getAssistantMessageFromRunOutput,
  getUserMessageFromRunInput,
} from '@mastra/evals/scorers/utils'

const responseJudge = new Classifier({
  id: 'response-judge',
  model: typeSafeAi.decisionModel('__AI_SDK_TYPESAFE_DECISION_MODEL__'),
  questions: {
    quality: {
      type: 'score',
      instructions: 'How well does the response answer the request?',
      criteria: ['Incorrect or irrelevant', 'Partially correct', 'Correct and complete'],
    },
    route: {
      type: 'choice',
      criteria: {
        correct: 'The response took the correct route',
        partiallyCorrect: 'The response took a partly correct route',
        incorrect: 'The response took the wrong route',
      },
    },
    factual: {
      type: 'boolean',
      criteria: { true: 'The response is factual', false: 'The response contains factual errors' },
    },
  },
})

export const qualityScorer = createClassifierScorer({
  id: 'response-quality',
  description: 'Scores response quality with the configured classifier',
  classifier: responseJudge,
  question: 'quality',
  type: 'agent',
  state: ({ run }) => ({
    input: getUserMessageFromRunInput(run.input) ?? '',
    output: getAssistantMessageFromRunOutput(run.output) ?? '',
  }),
})
```

此分類器設定了三個問題，供下方例子共用。每次呼叫 `qualityScorer.run()` 都會評估 `quality`、`route` 和 `factual`，但只有 `quality` 的答案決定分數。如只想評估 `quality`，請從此分類器的 `questions` 移除 `route` 和 `factual`。

對於有 N 項準則的評分問題，分類器會傳回從 `0` 到 `N - 1` 的等級，`result.score` 則將該等級除以 `N - 1`。如有三項準則，`Partially correct` 的分數為 `0.5`。

## 選擇題 {/* #choice-questions */}

選擇題必須為每個已設定選項明確對應一個介乎 `0` 與 `1` 之間的分數；不預設選項順序，亦不使用後備值。

```typescript
const routeScorer = createClassifierScorer({
  id: 'route-score',
  classifier: responseJudge,
  question: 'route',
  type: 'agent',
  scores: {
    correct: 1,
    partiallyCorrect: 0.5,
    incorrect: 0,
  },
  state: ({ run }) => ({
    input: getUserMessageFromRunInput(run.input) ?? '',
    output: getAssistantMessageFromRunOutput(run.output) ?? '',
  }),
})
```

所選選項及其可選的機率分布仍可從 `result.analyzeStepResult.answer` 取得。

## 布爾問題 {/* #boolean-questions */}

對於布林問題，`result.score` 是分類器估計的 `P(true)`，不會套用閾值，亦不會將機率轉為 `0` 或 `1`。

```typescript
const factualityScorer = createClassifierScorer({
  id: 'factuality',
  classifier: responseJudge,
  question: 'factual',
  type: 'agent',
  state: ({ run }) => ({
    input: getUserMessageFromRunInput(run.input) ?? '',
    output: getAssistantMessageFromRunOutput(run.output) ?? '',
  }),
})
```

## 請求上下文 {/* #request-context */}

`state` 函式會接收評分器的執行數據，包括 `run.requestContext`，因此分類器輸入可以包含租戶政策等每次請求特有的資料。這樣，同一個分類器便可按請求者不同，對相同輸出作出不同判斷：

```typescript
import { RequestContext } from '@mastra/core/request-context'

export const policyScorer = createClassifierScorer({
  id: 'policy-factuality',
  classifier: responseJudge,
  question: 'factual',
  type: 'agent',
  state: ({ run }) => ({
    policy:
      (run.requestContext instanceof RequestContext
        ? run.requestContext.get('policy')
        : run.requestContext?.policy) ?? null,
    output: getAssistantMessageFromRunOutput(run.output) ?? '',
  }),
})
```

## 註冊分類器 {/* #registered-classifiers */}

傳入分類器 ID，評分器執行時便會從 Mastra 解析該分類器。亦須將已設定的分類器類型及所選問題作為泛型參數提供，因為 TypeScript 無法從字串 ID 推斷兩者。

```typescript
import { Mastra } from '@mastra/core/mastra'

const registeredScorer = createClassifierScorer<typeof responseJudge, 'quality'>({
  id: 'registered-response-quality',
  classifier: 'response-judge',
  question: 'quality',
  type: 'agent',
  state: ({ run }) => ({
    input: getUserMessageFromRunInput(run.input) ?? '',
    output: getAssistantMessageFromRunOutput(run.output) ?? '',
  }),
})

new Mastra({
  classifiers: { responseJudge },
  scorers: { registeredScorer },
})
```

如尚未向 Mastra 註冊分類器便執行引用其 ID 的評分器，呼叫會因錯誤而失敗；錯誤會指出分類器及評分器的 ID。直接傳入已設定的分類器實例，即可略過註冊表解析。

## 錯誤 {/* #errors */}

內嵌分類器設定無效時，`createClassifierScorer()` 會拋出 `TypeError`：

* 分類器沒有配置問題。
* 所選問題不存在。
* 選項對應遺漏了已設定選項、包含未知選項，或某個值不是介乎 `0` 與 `1` 之間的有限數字。
* 評分題或布林題收到 `scores` 對應。

評分器執行期間發生錯誤時，`scorer.run()` 會以 `ScorerRunError` 失敗，其 `failedStep` 為 `analyze`，原始錯誤可透過 `cause` 取得。包括以下情況：

* 分類器評估失敗或未傳回所選問題的答案。
* 決策模型拒絕回答所選問題。錯誤會指出分類器、問題及評分器。
* 在評分器註冊至 Mastra 前使用分類器 ID，或該 ID 不在 `classifiers` 中。
* 已註冊的分類器對此評分器的配置無效。

## 結果證據 {/* #result-evidence */}

`result.analyzeStepResult` 包括：

* `question`：所選的問題鍵。
* `answer`：保留確切類型的選項、分數或布林答案，包括可選的機率。
* `usage`：標準化後的分類器 token 用量。
* `warnings`、`rounding` 及 `providerMetadata`：決策模型傳回的評估依據。
* `response`：安全的回應識別資訊，包括 `id`、`timestamp` 及 `modelId`。

Provider 的原始回應內容及標頭不會複製到評分器結果中。如需完整的原始回應，請直接呼叫 `Classifier.decide()`。

分類器評估會在評分器目前的 Trace 上下文中執行。
