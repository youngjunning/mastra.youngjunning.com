# Tool呼叫準確度評分器

Mastra 提供了兩個Tool調用準確性評分器，用於評估法學碩士是否從可用選項中選擇了正確的Tool：

1. **基於代碼的記分器**- 使用精確的Tool配對進行確定性評估
2. **基於LLM的評分者**- 使用人工智慧進行語義評估以評估適當性

## 在得分手之間進行選擇 {/* #choosing-between-scorers */}

### 在以下情況下使用基於代碼的評分器： {/* #use-the-code-based-scorer-when */}

* 你需要**deterministic, reproducible** results
* 你想測試**exact tool matching**
* 您需要驗證**specific tool sequences**
* 速度和成本是優先考慮的（沒有法學碩士呼叫）
* 您正在執行自動化測試

### 在以下情況下使用基於 LLM 的評分器： {/* #use-the-llm-based-scorer-when */}

* 你需要**semantic understanding** of appropriateness
* Tool選擇取決於**context and intent**
* 你想要處理**edge cases** like clarification requests
* 你需要**explanations** for scoring decisions
* 你正在評估**production agent behavior**

## 基於程式碼的Tool呼叫準確性評分器 {/* #code-based-tool-call-accuracy-scorer */}

這`createToolCallAccuracyScorerCode()` function from `@mastra/evals/scorers/prebuilt` provides deterministic binary scoring based on exact tool matching and supports both strict and lenient evaluation modes, as well as tool calling order validation.

### 參數 {/* #parameters */}

<PropertiesTable
  content={[
{
  name: 'expectedTool',
  type: 'string',
  description:
    'The name of the tool that should be called for the given task. Determines the score when expectedToolOrder is omitted or empty. With a non-empty expectedToolOrder it does not affect the score, but still populates correctToolCalled.',
  required: false,
},
{
  name: 'strictMode',
  type: 'boolean',
  description:
    'Controls evaluation strictness. For single tool mode: only exact single tool calls accepted. For order checking mode: tools must match exactly with no extra tools allowed.',
  required: false,
  default: 'false',
},
{
  name: 'expectedToolOrder',
  type: 'string[]',
  description:
    'Array of tool names in the expected calling order. A non-empty array enables order checking mode, which determines the score. An empty array scores in single tool mode using expectedTool, but still populates correctOrderCalled.',
  required: false,
},
]}
/>

此函數傳回 MastraScorer 類別的實例。請參閱[MastraScorer reference](./mastra-scorer) for details on the `.run()` method and its input/output.

### 評估模式 {/* #evaluation-modes */}

基於程式碼的記分器以兩種不同的模式運作：

#### 單Tool模式 {/* #single-tool-mode */}

什麼時候`expectedToolOrder` isn't provided or is empty, the score reflects single tool selection:

* **標準模式（strictMode: false）**：退貨`1` if the expected tool is called, regardless of other tools
* **嚴格模式（strictMode: true）**：退貨`1` only if exactly one tool is called and it matches the expected tool

#### 訂單檢查模式 {/* #order-checking-mode */}

當非空時`expectedToolOrder` is provided, the score reflects the tool calling sequence:

* **嚴格順序（strictMode：true）**：Tool必須嚴格按照指定的順序調用，沒有額外的Tool
* **彈性訂單（strictMode: false）**：預期的Tool必須以正確的相對順序出現（允許使用額外的Tool）

## 基於代碼的評分詳細信息 {/* #code-based-scoring-details */}

* **二進制分數**：總是返回0或1
* **確定性**：相同的輸入總是產生相同的輸出
* **快速地**: 沒有外部API調用

### 基於代碼的評分器選項 {/* #code-based-scorer-options */}

```typescript
// Standard mode - passes if expected tool is called
const lenientScorer = createCodeScorer({
  expectedTool: 'search-tool',
  strictMode: false,
})

// Strict mode - only passes if exactly one tool is called
const strictScorer = createCodeScorer({
  expectedTool: 'search-tool',
  strictMode: true,
})

// Order checking with strict mode
const strictOrderScorer = createCodeScorer({
  expectedTool: 'step1-tool',
  expectedToolOrder: ['step1-tool', 'step2-tool', 'step3-tool'],
  strictMode: true, // no extra tools allowed
})
```

### 基於代碼的評分器結果 {/* #code-based-scorer-results */}

```typescript oxfmt:false
{
  runId: string,
  preprocessStepResult: {
    expectedTool?: string, // undefined when only expectedToolOrder is configured
    actualTools: string[],
    strictMode: boolean,
    expectedToolOrder?: string[],
    hasToolCalls: boolean,
    correctToolCalled: boolean,
    correctOrderCalled: boolean | null,
    toolCallInfos: ToolCallInfo[]
  },
  score: number // Always 0 or 1
}
```

## 基於程式碼的記分器範例 {/* #code-based-scorer-examples */}

基於代碼的評分器根據精確的Tool匹配提供確定性的二進位評分（0 或 1）。

### 正確選擇Tool {/* #correct-tool-selection */}

```typescript title="src/example-correct-tool.ts"
const scorer = createToolCallAccuracyScorerCode({
  expectedTool: 'weather-tool',
})

// Simulate LLM input and output with tool call
const inputMessages = [
  createTestMessage({
    content: 'What is the weather like in New York today?',
    role: 'user',
    id: 'input-1',
  }),
]

const output = [
  createTestMessage({
    content: 'Let me check the weather for you.',
    role: 'assistant',
    id: 'output-1',
    toolInvocations: [
      createToolInvocation({
        toolCallId: 'call-123',
        toolName: 'weather-tool',
        args: { location: 'New York' },
        result: { temperature: '72°F', condition: 'sunny' },
        state: 'result',
      }),
    ],
  }),
]

const run = createAgentTestRun({ inputMessages, output })
const result = await scorer.run(run)

console.log(result.score) // 1
console.log(result.preprocessStepResult?.correctToolCalled) // true
```

### 嚴格模式評估 {/* #strict-mode-evaluation */}

僅當調用了一個Tool時才通過：

```typescript title="src/example-strict-mode.ts"
const strictScorer = createToolCallAccuracyScorerCode({
  expectedTool: 'weather-tool',
  strictMode: true,
})

// Multiple tools called - fails in strict mode
const output = [
  createTestMessage({
    content: 'Let me help you with that.',
    role: 'assistant',
    id: 'output-1',
    toolInvocations: [
      createToolInvocation({
        toolCallId: 'call-1',
        toolName: 'search-tool',
        args: {},
        result: {},
        state: 'result',
      }),
      createToolInvocation({
        toolCallId: 'call-2',
        toolName: 'weather-tool',
        args: { location: 'New York' },
        result: { temperature: '20°C' },
        state: 'result',
      }),
    ],
  }),
]

const result = await strictScorer.run(run)
console.log(result.score) // 0 - fails because multiple tools were called
```

### Tool訂單驗證 {/* #tool-order-validation */}

驗證Tool是否以特定順序呼叫：

```typescript title="src/example-order-validation.ts"
const orderScorer = createToolCallAccuracyScorerCode({
  expectedTool: 'auth-tool', // ignored when order is specified
  expectedToolOrder: ['auth-tool', 'fetch-tool'],
  strictMode: true, // no extra tools allowed
})

const output = [
  createTestMessage({
    content: 'I will authenticate and fetch the data.',
    role: 'assistant',
    id: 'output-1',
    toolInvocations: [
      createToolInvocation({
        toolCallId: 'call-1',
        toolName: 'auth-tool',
        args: { token: 'abc123' },
        result: { authenticated: true },
        state: 'result',
      }),
      createToolInvocation({
        toolCallId: 'call-2',
        toolName: 'fetch-tool',
        args: { endpoint: '/data' },
        result: { data: ['item1'] },
        state: 'result',
      }),
    ],
  }),
]

const result = await orderScorer.run(run)
console.log(result.score) // 1 - correct order
```

### 靈活的訂購模式 {/* #flexible-order-mode */}

允許額外的Tool，只要預期的Tool保持相對順序：

```typescript title="src/example-flexible-order.ts"
const flexibleOrderScorer = createToolCallAccuracyScorerCode({
  expectedTool: 'auth-tool',
  expectedToolOrder: ['auth-tool', 'fetch-tool'],
  strictMode: false, // allows extra tools
})

const output = [
  createTestMessage({
    content: 'Performing comprehensive operation.',
    role: 'assistant',
    id: 'output-1',
    toolInvocations: [
      createToolInvocation({
        toolCallId: 'call-1',
        toolName: 'auth-tool',
        args: { token: 'abc123' },
        result: { authenticated: true },
        state: 'result',
      }),
      createToolInvocation({
        toolCallId: 'call-2',
        toolName: 'log-tool', // Extra tool - OK in flexible mode
        args: { message: 'Starting fetch' },
        result: { logged: true },
        state: 'result',
      }),
      createToolInvocation({
        toolCallId: 'call-3',
        toolName: 'fetch-tool',
        args: { endpoint: '/data' },
        result: { data: ['item1'] },
        state: 'result',
      }),
    ],
  }),
]

const result = await flexibleOrderScorer.run(run)
console.log(result.score) // 1 - auth-tool comes before fetch-tool
```

## 基於 LLM 的Tool呼叫準確性評分器 {/* #llm-based-tool-call-accuracy-scorer */}

這`createToolCallAccuracyScorerLLM()` function from `@mastra/evals/scorers/prebuilt` uses an LLM to evaluate whether the tools called by an agent are appropriate for the user request, providing semantic evaluation rather than exact matching.

### 參數 {/* #parameters-1 */}

<PropertiesTable
  content={[
{
  name: 'model',
  type: 'MastraModelConfig',
  description: 'The LLM model to use for evaluating tool appropriateness',
  required: true,
},
{
  name: 'availableTools',
  type: 'Tool[]',
  description:
    "Tools available to the agent, for example created with `createTool()`. Each tool's `id` and `description` are passed to the judge as context.",
  required: true,
},
]}
/>

傳遞可用於特定Agent程式運行的Tool`availableTools`. If tool availability changes between runs, create a scorer with each run's tool snapshot. A global superset can cause the judge to report unavailable tools as missing and lower the score.

### 特徵 {/* #features */}

基於法學碩士的評分器提供：

* **語意評估**：理解上下文和使用者意圖
* **適當性評估**：區分「有用」和「合適」的Tool
* **澄清處理**：識別Agent何時適當要求澄清
* **刀具缺失檢測**：標識應該被呼叫的Tool
* **推理生成**：提供評分決定的解釋

### 評估流程 {/* #evaluation-process */}

1. **提取Tool調用**：標識Agent輸出中提到的Tool
2. **分析適當性**：根據使用者請求評估每個Tool
3. **產生分數**：將適當的調用除以實際調用的數量加上法官報告的缺失Tool的數量
4. **生成推理**：提供人類可讀的解釋

## 基於LLM的評分細節 {/* #llm-based-scoring-details */}

* **分數分數**：傳回 0.0 到 1.0 之間的數值，四捨五入到小數點後兩位。只有當適當的評估與對該Tool的實際呼叫相符時，分數才會計算在內，因此額外的評估不會增加分數。分母計算所有實際召喚加上法官報告的缺失Tool。
* **無Tool調用**：如果裁判報告缺少Tool，則傳回 0；如果不需要Tool，則回傳 1。
* **情境感知**：考慮使用者意圖和適當性
* **解釋性的**：提供分數的推理

### 基於法學碩士的評分器選項 {/* #llm-based-scorer-options */}

```typescript oxfmt:false
// Basic configuration
const basicLLMScorer = createLLMScorer({
  model: '__GATEWAY_OPENAI_MODEL__',
  availableTools: [
    createTool({ id: 'tool1', description: 'Description 1' }),
    createTool({ id: 'tool2', description: 'Description 2' })
  ]
});

// With different model
const customModelScorer = createLLMScorer({
  model: '__GATEWAY_OPENAI_MODEL_BASE__', // More powerful model for complex evaluations
  availableTools: [...]
});
```

## 基於法學碩士的評分器範例 {/* #llm-based-scorer-examples */}

基於法學碩士的評分器使用人工智慧來評估Tool選擇是否適合使用者的要求。

### 基本法學碩士評估 {/* #basic-llm-evaluation */}

```typescript title="src/example-llm-basic.ts"
import { createTool } from '@mastra/core/tools'
import { createToolCallAccuracyScorerLLM } from '@mastra/evals/scorers/prebuilt'

const llmScorer = createToolCallAccuracyScorerLLM({
  model: '__GATEWAY_OPENAI_MODEL__',
  availableTools: [
    createTool({
      id: 'weather-tool',
      description: 'Get current weather information for any location',
    }),
    createTool({
      id: 'calendar-tool',
      description: 'Check calendar events and scheduling',
    }),
    createTool({
      id: 'search-tool',
      description: 'Search the web for general information',
    }),
  ],
})

const inputMessages = [
  createTestMessage({
    content: 'What is the weather like in San Francisco today?',
    role: 'user',
    id: 'input-1',
  }),
]

const output = [
  createTestMessage({
    content: 'Let me check the current weather for you.',
    role: 'assistant',
    id: 'output-1',
    toolInvocations: [
      createToolInvocation({
        toolCallId: 'call-123',
        toolName: 'weather-tool',
        args: { location: 'San Francisco', date: 'today' },
        result: { temperature: '68°F', condition: 'foggy' },
        state: 'result',
      }),
    ],
  }),
]

const run = createAgentTestRun({ inputMessages, output })
const result = await llmScorer.run(run)

console.log(result.score) // 1.0 - appropriate tool usage
console.log(result.reason) // "The agent correctly used the weather-tool to address the user's request for weather information."
```

### 處理不當的Tool使用 {/* #handling-inappropriate-tool-usage */}

```typescript title="src/example-llm-inappropriate.ts"
const inputMessages = [
  createTestMessage({
    content: 'What is the weather in Tokyo?',
    role: 'user',
    id: 'input-1',
  }),
]

const inappropriateOutput = [
  createTestMessage({
    content: 'Let me search for that information.',
    role: 'assistant',
    id: 'output-1',
    toolInvocations: [
      createToolInvocation({
        toolCallId: 'call-456',
        toolName: 'search-tool', // Less appropriate than weather-tool
        args: { query: 'Tokyo weather' },
        result: { results: ['Tokyo weather data...'] },
        state: 'result',
      }),
    ],
  }),
]

const run = createAgentTestRun({ inputMessages, output: inappropriateOutput })
const result = await llmScorer.run(run)

console.log(result.score) // 0 - if the judge marks search-tool inappropriate and reports weather-tool as missing
console.log(result.reason) // The judge explains why search-tool was inappropriate for this weather request.
```

### 評估澄清請求 {/* #evaluating-clarification-requests */}

LLM 評分員會辨識Agent何時適當要求澄清：

```typescript oxfmt:false title="src/example-llm-clarification.ts"
const vagueInput = [
  createTestMessage({
    content: 'I need help with something',
    role: 'user',
    id: 'input-1'
  })
];

const clarificationOutput = [
  createTestMessage({
    content: 'I'd be happy to help! Could you please provide more details about what you need assistance with?',
    role: 'assistant',
    id: 'output-1',
    // No tools called - asking for clarification instead
  })
];

const run = createAgentTestRun({
  inputMessages: vagueInput,
  output: clarificationOutput
});
const result = await llmScorer.run(run);

console.log(result.score); // 1.0 - appropriate to ask for clarification
console.log(result.reason); // "The agent appropriately asked for clarification rather than calling tools with insufficient information."
```

## 比較兩位得分手 {/* #comparing-both-scorers */}

以下是在相同資料上使用兩個記分器的範例：

```typescript title="src/example-comparison.ts"
import { createTool } from '@mastra/core/tools'
import {
  createToolCallAccuracyScorerCode as createCodeScorer,
  createToolCallAccuracyScorerLLM as createLLMScorer,
} from '@mastra/evals/scorers/prebuilt'

// Setup both scorers
const codeScorer = createCodeScorer({
  expectedTool: 'weather-tool',
  strictMode: false,
})

const llmScorer = createLLMScorer({
  model: '__GATEWAY_OPENAI_MODEL__',
  availableTools: [
    createTool({ id: 'weather-tool', description: 'Get weather information' }),
    createTool({ id: 'search-tool', description: 'Search the web' }),
  ],
})

// Test data
const run = createAgentTestRun({
  inputMessages: [
    createTestMessage({
      content: 'What is the weather?',
      role: 'user',
      id: 'input-1',
    }),
  ],
  output: [
    createTestMessage({
      content: 'Let me find that information.',
      role: 'assistant',
      id: 'output-1',
      toolInvocations: [
        createToolInvocation({
          toolCallId: 'call-1',
          toolName: 'search-tool',
          args: { query: 'weather' },
          result: { results: ['weather data'] },
          state: 'result',
        }),
      ],
    }),
  ],
})

// Run both scorers
const codeResult = await codeScorer.run(run)
const llmResult = await llmScorer.run(run)

console.log('Code Scorer:', codeResult.score) // 0 - wrong tool
console.log('LLM Scorer:', llmResult.score) // 0.3 - partially appropriate
console.log('LLM Reason:', llmResult.reason) // Explains why search-tool is less appropriate
```
