# 提示詞對齊評分器

`createPromptAlignmentScorerLLM()` 創建一個評分器，從意圖理解、要求滿足、回答完整性和格式適當性幾個方面，評估 Agent 的回答與用戶提示詞是否一致。

## 評分詳情 {/* #scoring-details */}

### 評分器配置 {/* #scorer-configuration */}

可以調整 scale 參數和評估模式，以符合所需的評分方式。

```typescript
const scorer = createPromptAlignmentScorerLLM({
  model: '__GATEWAY_OPENAI_MODEL__',
  options: {
    scale: 10, // Score from 0-10 instead of 0-1
    evaluationMode: 'both', // 'user', 'system', or 'both' (default)
  },
})
```

### 多輪對話 {/* #multi-turn-conversations */}

默認情況下，評分器只看到當前輪次。在對話中，`"A"` 這樣的簡短回答脫離上下文就沒有意義，評判模型無法知道用戶問了什麼，因此會將回答評為不一致。

設定 `includeConversationHistory`，將 Agent 記憶中的先前輪次提供給評判模型。它會利用歷史輪次理解當前提示詞，但仍只給當前回答評分。

```typescript
const scorer = createPromptAlignmentScorerLLM({
  model: '__GATEWAY_OPENAI_MODEL__',
  options: {
    evaluationMode: 'user',
    includeConversationHistory: { maxMessages: 6 }, // or `true` for the last 10 messages
  },
})
```

此選項只影響評分器能收到歷史訊息的 Agent 運行。根據普通提示詞字串進行評分的運行不受影響。

### 多維度分析 {/* #multi-dimensional-analysis */}

提示詞對齊評分器從四個關鍵維度評估回答，並根據評估模式調整加權方式：

#### 用戶模式（'user'） {/* #user-mode-user */}

僅評估回答與用戶提示詞的一致性：

1. **意圖一致性**（權重 40%）：回答是否回應用戶的核心請求
2. **要求滿足度**（權重 30%）：是否滿足用戶的所有要求
3. **完整性**（權重 20%）：回答的詳細程度是否滿足用戶需求
4. **回答適當性**（權重 10%）：格式和語氣是否符合用戶預期

#### 系統模式（'system'） {/* #system-mode-system */}

僅評估回答是否遵循系統指令：

1. **意圖一致性**（權重 35%）：回答是否遵循系統行為準則
2. **要求滿足度**（權重 35%）：是否遵守所有系統約束
3. **完整性**（權重 15%）：是否遵循所有系統規則
4. **回答適當性**（權重 15%）：格式和語氣是否符合系統要求

#### 綜合模式（'both'，默認） {/* #both-mode-both---default */}

在一次分析中同時評估用戶提示詞和系統指令：

* 評判模型同時對照用戶提示詞和系統指令評估每個維度
* 使用用戶模式的權重合併各維度分數
* 評分器不會單獨計算系統分數，因此結果並非用戶模式分數與系統模式分數的混合

### 評分公式 {/* #scoring-formula */}

**用戶模式：**

```text
Weighted Score = (intent_score × 0.4) + (requirements_score × 0.3) +
                 (completeness_score × 0.2) + (appropriateness_score × 0.1)
Final Score = Weighted Score × scale
```

**系統模式：**

```text
Weighted Score = (intent_score × 0.35) + (requirements_score × 0.35) +
                 (completeness_score × 0.15) + (appropriateness_score × 0.15)
Final Score = Weighted Score × scale
```

**綜合模式（默認）：**

```text
Weighted Score = (intent_score × 0.4) + (requirements_score × 0.3) +
                 (completeness_score × 0.2) + (appropriateness_score × 0.1)
Final Score = Weighted Score × scale
```

在綜合模式下，每個維度的分數均來自對用戶提示詞和系統指令的聯合分析。

**權重分配依據**：

* **用戶模式**：優先考慮意圖（40%）和要求（30%），以反映用戶滿意度
* **系統模式**：同等重視行為準則（35%）和約束條件（35%）
* **綜合模式**：聯合分析時採用用戶模式的權重，因此仍以用戶需求為主，同時評估系統指令

### 分數解讀 {/* #score-interpretation */}

* **0.9-1.0** = 所有維度都高度一致
* **0.8-0.9** = 一致性很好，只有少量不足
* **0.7-0.8** = 一致性良好，但遺漏部分要求或內容不夠完整
* **0.6-0.7** = 一致性一般，存在明顯不足
* **0.4-0.6** = 一致性較差，存在較多問題
* **0.0-0.4** = 一致性很差，回答未能有效回應提示詞

### 何時使用每種模式 {/* #when-to-use-each-mode */}

**用戶模式（`'user'`）**：適用於：

* 根據用戶滿意度評估客服回答
* 從用戶視角測試內容生成質量
* 衡量回答是否切中用戶問題
* 只關注請求是否得到滿足，不考慮系統約束

**系統模式（`'system'`）**：適用於：

* 審核 AI 安全性和行為準則遵循情況
* 確保 Agent 遵循品牌用語和語氣要求
* 驗證是否遵守內容政策和約束
* 測試系統層面的行為一致性

**綜合模式（`'both'`）**：適用於（默認、推薦）：

* 評估回答是否既滿足用戶請求又遵循系統指令
* 同時關注用戶要求和系統要求的生產監控

## 常見用例 {/* #common-use-cases */}

### 程式碼產生評估 {/* #code-generation-evaluation */}

非常適合評估：

* 編程任務是否完成
* 程式碼品質和完整性
* 是否遵循編碼要求
* 格式規格（函數、類別等）

```typescript
// Example: API endpoint creation
const codePrompt = 'Create a REST API endpoint with authentication and rate limiting'
// Scorer evaluates: intent (API creation), requirements (auth + rate limiting),
// completeness (full implementation), format (code structure)
```

### 指令遵循評估 {/* #instruction-following-assessment */}

非常適合：

*
* 是否遵循多步驟指令
* 是否符合具體要求
* 教育內容評估

```typescript
// Example: Multi-requirement task
const taskPrompt =
  'Write a Python class with initialization, validation, error handling, and documentation'
```

### 內容格式驗證 {/* #content-format-validation */}

適用於：

* 是否符合格式規範

```typescript

const formatPrompt =
```

### Agent 回答質量 {/* #agent-response-quality */}

```typescript
const agent = new Agent({
```

### 提示詞工程優化 {/* #prompt-engineering-optimization */}

測試不同的提示詞，以提高回答的一致性：

```typescript
const prompts = [
  'Write a function to calculate factorial',
  'Create a Python function that calculates factorial with error handling for negative inputs',
  'Implement a factorial calculator in Python with: input validation, error handling, and docstring',
]

// Compare alignment scores to find the best prompt
for (const prompt of prompts) {
  const result = await scorer.run(createTestRun(prompt, response))
  console.log(`Prompt alignment: ${result.score}`)
}
```

### 多智能體系統評估 {/* #multi-agent-system-evaluation */}

比較不同的 Agent 或模型：

```typescript oxfmt:false
const agents = [agent1, agent2, agent3];
const testPrompts = [...]; // Array of test prompts

for (const agent of agents) {
  let totalScore = 0;
  for (const prompt of testPrompts) {
    const response = await agent.run(prompt);
    const evaluation = await scorer.run({ input: prompt, output: response });
    totalScore += evaluation.score;
  }
  console.log(`${agent.name} average alignment: ${totalScore / testPrompts.length}`);
}
```

### 高度一致的示例 {/* #excellent-alignment-example */}

此示例中，回答充分回應用戶提示詞，並滿足所有要求。

```typescript title="src/example-excellent-prompt-alignment.ts"
import { createPromptAlignmentScorerLLM } from '@mastra/evals/scorers/prebuilt'

const scorer = createPromptAlignmentScorerLLM({
  model: '__GATEWAY_OPENAI_MODEL__',
})

const inputMessages = [
  {
    role: 'user',
    content:
      'Write a Python function to calculate factorial with error handling for negative numbers',
  },
]

const outputMessage = {
  text: `def factorial(n):
    """Calculate factorial of a number."""
    if n < 0:
        raise ValueError("Factorial not defined for negative numbers")
    if n == 0 or n == 1:
        return 1
    return n * factorial(n - 1)`,
}

const result = await scorer.run({
  input: inputMessages,
  output: outputMessage,
})

console.log(result)
```

### 高度一致的輸出 {/* #excellent-alignment-output */}

回答提供了所要求的 Python 階乘函數，並處理負數輸入，因此獲得高分。

```typescript oxfmt:false

  reason: 'The score is 0.95 because the response perfectly addresses the primary intent of creating a factorial function and fulfills all requirements including Python implementation, error handling for negative numbers, and proper documentation. The code format is appropriate and the implementation is complete.'
}
```

## 與其他評分器比較 {/* #comparison-with-other-scorers */}

| 方面 | 提示詞對齊 | 答案相關性 | 忠實性 |
| - | - | - | - |
| **關注點** | 多維度的提示詞遵循情況 | 問題與回答的相關性 | 是否有上下文依據 |
| **評估內容** | 意圖、要求、完整性、格式 | 與問題的語義相似度 | 與上下文的事實一致性 |
| **適用場景** | 一般提示詞遵循評估 | 信息檢索 | RAG／基於上下文的系統 |
| **維度** | 四個加權維度 | 單一相關性維度 | 單一忠實性維度 |
