# CLI 指令

您可以使用 Mastra 提供的命令列介面 (CLI) 來開發、建置和啟動您的 Mastra 專案。

## `mastra dev` {/* #mastra-dev */}

啟動一個暴露的伺服器[Studio](/docs/studio/overview) and REST endpoints for your agents, tools, and workflows. You can visit [http://localhost:4111/swagger-ui](http://localhost:4111/swagger-ui)一次了解所有可用端點的概覽`mastra dev`正在運行。

您還可以[configure the server](/reference/configuration#server-options).

### 旗幟 {/* #flags */}

該命令接受[common flags][common-flags] and the following additional flags:

#### `--https` {/* #--https */}

啟用本機 HTTPS 支援。[Learn more](/reference/configuration#serverhttps).

#### `--inspect` {/* #--inspect */}

以檢查模式啟動開發伺服器，有助於調試。 （可選）指定自訂主機和連接埠（例如，`--inspect=0.0.0.0:9229` for Docker). This can't be used together with `--inspect-brk`.

#### `--inspect-brk` {/* #--inspect-brk */}

以檢查模式啟動開發伺服器並在腳本開頭處中斷。 （可選）指定自訂主機和連接埠（例如，`--inspect-brk=0.0.0.0:9229`). This can't be used together with `--inspect`.

#### `--custom-args` {/* #--custom-args */}

要傳遞給 Node.js 進程的以逗號分隔的自訂參數列表，例如`--require=newrelic` or `--experimental-transform-types`.

#### `--request-context-presets` {/* #--request-context-presets */}

[request context](/docs/server/request-context) presets. When provided, a dropdown displays in Studio's request context editor, letting you quickly switch between preset configurations.

```bash
mastra dev --request-context-presets ./presets.json
```

該檔案必須是 JSON 對象，其中每個鍵都是預設名稱，每個值都是一個對象：

```json
{
  "development": { "userId": "dev-user", "env": "development" },
  "production": { "userId": "prod-user", "env": "production" }
}
```

### 配置 {/* #configs */}

您可以設定環境變數來修改`mastra dev`.

#### 跳過對等依賴性檢查 {/* #skip-peer-dependency-check */}

放`MASTRA_SKIP_PEERDEP_CHECK=1` to skip the peer dependency version mismatch check at startup:

```bash
MASTRA_SKIP_PEERDEP_CHECK=1 mastra dev
```

這在 monorepo 開發過程中非常有用，因為此時對等依賴關係可能會發生衝突，但套件尚未發布。

#### 禁用建置緩存 {/* #disable-build-caching */}

放`MASTRA_DEV_NO_CACHE=1` to force a full rebuild rather than using the cached assets under `.mastra/`:

```bash
MASTRA_DEV_NO_CACHE=1 mastra dev
```

當您調試捆綁器插件或懷疑過時的輸出時，這會有所幫助。

#### 限制並行度 {/* #limit-parallelism */}

`MASTRA_CONCURRENCY`限制並行運行的昂貴操作數量（主要是建置和評估步驟）。例如：

```bash
MASTRA_CONCURRENCY=4 mastra dev
```

將其保留為未設置，以便 CLI 為電腦選擇合理的預設值。

#### 自訂提供者端點 {/* #custom-provider-endpoints */}

使用 Vercel AI SDK 支援的提供者時，您可以透過設定基本 URL 透過Agent程式或內部網關重新導向請求。對於 OpenAI：

```bash
OPENAI_API_KEY=<your-api-key> \
OPENAI_BASE_URL=https://openrouter.example/v1 \
mastra dev
```

對於人擇：

```bash
ANTHROPIC_API_KEY=<your-api-key> \
ANTHROPIC_BASE_URL=https://anthropic.internal \
mastra dev
```

這些被轉發到 Mastra 型號路由器，並且可以與任何`"openai/..."`
or `"anthropic/..."` model selections.

## `mastra factory dev` {/* #mastra-factory-dev */}

啟動開發伺服器[Agent Builder](https://agent-builder.mastra.ai/) development. It uses the same dev runtime and flags as [`mastra dev`](#mastra-dev) and writes to the same `.mastra/output` directory.

```bash
npx mastra factory dev
```

兩個命令共享相同的開發鎖，因此`mastra dev` and `mastra factory dev` can't run simultaneously in the same project. If one is already running, the other exits with a duplicate development server error.

使用`mastra factory dev` when developing Agent Builder features. It accepts the same flags as [`mastra dev`](#mastra-dev), including `--https`, `--inspect`, `--inspect-brk`, `--custom-args`, and `--request-context-presets`.

## `mastra build` {/* #mastra-build */}

這`mastra build` command bundles your Mastra project into a production-ready Hono server. [Hono](https://hono.dev/) is a lightweight, type-safe web framework that makes it straightforward to deploy Mastra agents as HTTP endpoints with middleware support.

在幕後，Mastra 的 Rollup 伺服器會找到您的 Mastra 項目檔案並將其捆綁到生產就緒的 Hono 伺服器。在捆綁過程中，它會搖動您的程式碼並產生用於偵錯的來源映射。

輸出在`.mastra` can be deployed to any cloud server using [`mastra start`](#mastra-start).

如果您要部署到[serverless platform](/docs/deployment/cloud-providers) you need to install the correct deployer to receive the correct output in `.mastra`.

它接受[common flags][common-flags].

### 旗幟 {/* #flags-1 */}

#### `--studio` {/* #--studio */}

將 Studio UI 與建置捆綁在一起。

### 配置 {/* #configs-1 */}

您可以設定環境變數來修改`mastra build`.

#### 跳過對等依賴性檢查 {/* #skip-peer-dependency-check-1 */}

放`MASTRA_SKIP_PEERDEP_CHECK=1` to skip the peer dependency version mismatch check:

```bash
MASTRA_SKIP_PEERDEP_CHECK=1 mastra build
```

#### 限制並行度 {/* #limit-parallelism-1 */}

對於 CI 或在資源受限環境中執行時，您可以透過設定來限制一次執行的昂貴任務數量`MASTRA_CONCURRENCY`.

```bash
MASTRA_CONCURRENCY=2 mastra build
```

## `mastra start` {/* #mastra-start */}

：：：筆記

你需要跑`mastra build` before using `mastra start`.

:::

啟動本機伺服器以在生產模式下為您建立的 Mastra 應用程式提供服務。預設情況下，[OTEL Tracing](/docs/observability/tracing/overview) is enabled.

### 旗幟 {/* #flags-2 */}

該命令接受[common flags][common-flags] and the following additional flags:

#### `--dir` {/* #--dir */}

您建置的 Mastra 輸出目錄的路徑。預設為`.mastra/output`.

#### `--custom-args` {/* #--custom-args-1 */}

要傳遞給 Node.js 進程的以逗號分隔的自訂參數列表，例如`--require=newrelic` or `--experimental-transform-types`.

## `mastra worker build` {/* #mastra-worker-build */}

捆綁您的 Mastra 應用程式以進行工作人員部署。產生相同的輸出`mastra build`: a self-contained `.mastra/output/` directory.

```bash
mastra worker build [options]
```

### 旗幟 {/* #flags-3 */}

#### `--dir` {/* #--dir-1 */}

Mastra 來源目錄的路徑。預設為`src/mastra`.

#### `--root` {/* #--root */}

專案根目錄。預設為當前目錄。

#### `--tools` {/* #--tools */}

要包含在捆綁包中的以逗號分隔的Tool路徑。

#### `--output-dir` {/* #--output-dir */}

自訂輸出目錄。預設為`.mastra/output`.

#### `--debug` {/* #--debug */}

在建置期間啟用調試日誌記錄。

## `mastra experiment build` {/* #mastra-experiment-build */}

建立一個獨立的同伴工作線程，可以在不暴露 HTTP 伺服器的情況下運行實驗。工人裝載你的出口`Mastra` instance and accepts versioned newline-delimited JSON (NDJSON) protocol messages on standard input. It writes protocol events to standard output.

```bash
mastra experiment build [options]
```

該命令將工作人員寫入`.mastra/experiment-worker` by default. The directory contains the executable entry point, production dependencies, and `experiment-worker-manifest.json`. Treat standard output as protocol-only output. Worker diagnostics are written to standard error.

### 神器契約 {/* #artifact-contract */}

`experiment-worker-manifest.json`將工件標識為`mastra-experiment-worker` version `1` and provides:

* 可執行檔中嵌入的 CLI 版本、建立時間和唯一建置 ID。
* 支援的協定和資料集規範化版本。
* 啟動工作程序所需的可執行檔、參數和工作目錄。
* 依賴項清單和產生的鎖定檔案路徑。
* 每個工件檔案的排序 SHA-256 摘要。
* 從這些檔案路徑和摘要派生的 SHA-256 內容摘要。

內容摘要不包括`experiment-worker-manifest.json` to avoid a self-referential digest. Package the manifest with the rest of the directory. Use an outer package digest when the manifest itself must be attested.

### 協議合約 {/* #protocol-contract */}

工作人員實現固定實驗同儕工作人員協議版本`1`. It reads strict UTF-8 NDJSON frames from standard input and requires every frame, including the last one, to end with a newline. Frames larger than 1 MiB, malformed or truncated frames, unsupported protocol or canonicalization versions, and messages that don't match the active experiment correlation are rejected as protocol failures.

運行請求必須與工件的嵌入式建置 ID 匹配，並包含有序資料集項目計數和 SHA-256 證明。工作進程發出連續的序號，從`0`, timer-driven heartbeats, awaited experiment lifecycle events, and exactly one terminal event. Cancellation must match the active protocol version and experiment ID, plus the job ID, attempt, and idempotency key.

協議退出代碼為：

|程式碼|意義|
| - | - |
|`0` | Completed |
| `10` | Completed with item errors |
| `20` | Fatal failure |
| `21` | Retryable failure |
| `30` | Cancelled |
| `31` | Timed out |
| `70` | Protocol failure |

### 資料包欄位處理 {/* #packet-field-handling */}

工作人員將目標身分、有序內嵌資料集項目、記分器 ID、並發性、逾時、實驗元資料、請求上下文、Tool模擬和取消傳遞給`runExperiment`. Scorer versions and artifact provenance are retained as experiment metadata. Scorer code provenance is enforced by artifact admission rather than runtime scorer lookup.

版本`1` uses deterministic undeclared-tool denial. Non-empty network allowlists and secret references are rejected with a policy failure because network enforcement and secret materialization belong to the process sandbox. Dataset item source and expected-trajectory fields are preserved as item metadata when passed to `runExperiment`.

### 旗幟 {/* #flags-4 */}

#### `--dir` {/* #--dir-2 */}

Mastra 來源目錄的路徑。預設為`src/mastra`.

#### `--root` {/* #--root-1 */}

專案根目錄。預設為當前目錄。

#### `--output-dir` {/* #--output-dir-1 */}

自訂工件目錄。相對路徑是從專案根解析的。預設為`.mastra/experiment-worker`.

#### `--debug` {/* #--debug-1 */}

在建置期間啟用調試日誌記錄。

## `mastra worker start` {/* #mastra-worker-start */}

：：：筆記

你需要跑`mastra worker build` or `mastra build` before using `mastra worker start`.

:::

從先前建置的套件啟動工作進程。可選的`name` argument sets `MASTRA_WORKERS` in the spawned process, controlling which worker starts.

```bash
mastra worker start [name] [options]
```

### 旗幟 {/* #flags-5 */}

#### `--dir` {/* #--dir-3 */}

建置輸出目錄的路徑。預設為`.mastra/output`.

#### `--env` {/* #--env */}

環境文件的路徑。預設為`.env.production`, falling back to `.env`.

### 範例 {/* #examples */}

```bash
# Start only the orchestration worker
mastra worker start orchestration

# Start only the scheduler
mastra worker start scheduler

# Start from a custom build directory
mastra worker start orchestration --dir ./dist
```

看[Workers](/docs/deployment/workers) for deployment topologies and configuration.

## `mastra studio` {/* #mastra-studio */}

開始[Studio](/docs/studio/overview) as a static server. After starting, you can enter your Mastra instance URL (e.g. `http://localhost:4111`) to connect Studio to your Mastra backend. Looks for `.env` and `.env.production` files in the current working directory for configuration.

### 旗幟 {/* #flags-6 */}

該命令接受[common flags][common-flags] and the following additional flags:

#### `--port` {/* #--port */}

運行 Studio 的連接埠。預設為`3000`.

#### `--server-host` {/* #--server-host */}

要連接的 Mastra API 伺服器的主機。預設為`localhost`.

#### `--server-port` {/* #--server-port */}

要連接的 Mastra API 伺服器的連接埠。預設為`4111`.

#### `--server-protocol` {/* #--server-protocol */}

要連接的 Mastra API 伺服器的協定。預設為`http`.

#### `--server-api-prefix` {/* #--server-api-prefix */}

Mastra API 伺服器的 API 路由前綴。預設為`/api`.

#### `--request-context-presets` {/* #--request-context-presets-1 */}

[request context](/docs/server/request-context) presets. Works the same as the [`mastra dev` flag](#--request-context-presets).

```bash
mastra studio --request-context-presets ./presets.json
```

## `mastra deploy` {/* #mastra-deploy */}

建立您的專案並將其部署到由以下人員選擇的 Mastra 平台環境`--env`. This is the recommended command for all new deploys and replaces both [`mastra studio deploy`](#mastra-studio-deploy) and [`mastra server deploy`](#mastra-server-deploy), which continue to work but should no longer be used for new setups.

需要通過身份驗證[`mastra auth login`](#mastra-auth-login) or a `MASTRA_API_TOKEN` environment variable.

```bash
mastra deploy
mastra deploy --env staging
mastra deploy --env production --region eu
```

命令運行`mastra build` and zips the output before uploading it to the selected environment. It then polls the deploy status while streaming build logs until the deploy reaches a terminal state.

組織、專案和環境按以下順序解析：環境變數 (`MASTRA_ORG_ID`, `MASTRA_PROJECT_ID`), CLI flag (`--org`, `--project`, `--env`), `.mastra-project.json` config file, current org from credentials, and lastly interactive prompt. On first deploy, the CLI saves the resolved org and project IDs to `.mastra-project.json` so subsequent deploys skip the prompts.

確認後，CLI 將建立一個缺少的項目`package.json` `name` field and creates a missing target environment, defaulting to `type: staging` for anything other than `production`. Combined with `--yes`, this creates and deploys everything in one non-interactive command:

```bash
mastra deploy --env staging --yes
```

什麼時候`--env <name>` is set and `--env-file` isn't, the CLI auto-selects `.env.<name>` from the project directory if present (for example `.env.staging`). The `<name>` value is validated against a strict allowlist before being interpolated into a file path.

### 論點 {/* #arguments */}

#### `[dir]` {/* #dir */}

項目目錄。預設為當前目錄。

### 旗幟 {/* #flags-7 */}

#### `--env` {/* #--env-1 */}

目標環境名稱。預設為`production`. Auto-selects `.env.<name>` from the project directory when `--env-file` isn't set. If the environment doesn't exist, the CLI creates it after confirmation.

#### `--org` {/* #--org */}

組織 ID。也可以透過設定`MASTRA_ORG_ID` environment variable.

#### `--project` {/* #--project */}

项目 ID、slug 或名称。也可以透過設定`MASTRA_PROJECT_ID` environment variable. If no project matches, the value is used as the name of a new project to create on deploy.

#### `-y, --yes` {/* #-y---yes */}

自動接受預設設置，無需確認提示，包括建立專案和環境。

#### `-c, --config` {/* #-c---config */}

專案設定檔的路徑。預設為`.mastra-project.json`.

#### `--env-file` {/* #--env-file */}

與部署捆綁在一起的 env 檔案的路徑（相對於專案目錄）。設定後，停用`.env.<name>` auto-selection based on `--env`.

```bash
mastra deploy --env staging --env-file .env.staging.local
```

#### `--region` {/* #--region */}

新建環境的區域（例如`eu`). Applied only when the CLI creates the environment.

#### `--skip-build` {/* #--skip-build */}

跳過建置步驟並部署現有的`.mastra/output` directory. The CLI warns if the existing build is stale relative to the current source.

#### `--skip-preflight` {/* #--skip-preflight */}

跳過建置輸出的預上傳驗證。

#### `--debug` {/* #--debug-2 */}

在建置步驟期間啟用調試日誌。

### CI/CD 使用 {/* #cicd-usage */}

放`MASTRA_API_TOKEN`, `MASTRA_ORG_ID`, and `MASTRA_PROJECT_ID` as environment variables for headless deploys. Interactive prompts are skipped automatically when `MASTRA_API_TOKEN` is set. Combine with `--yes` to auto-accept environment creation.

```bash
export MASTRA_API_TOKEN="..."
export MASTRA_ORG_ID="..."
export MASTRA_PROJECT_ID="..."
mastra deploy --env staging --yes
```

## `mastra env` {/* #mastra-env */}

管理 Mastra 平台上的環境。環境是部署目標（例如`production`, `staging`, `preview-42`) that belong to a project. The current organization is resolved from stored credentials.

每個子命令都以固定順序解析其項目。它首先檢查`--project <name|slug|id>` flag, then the `MASTRA_PROJECT_ID` environment variable. It then reads the `.mastra-project.json` file written by [`mastra deploy`](#mastra-deploy) in the current directory. Run from your project directory and you never need to name the project.

### `mastra env list` {/* #mastra-env-list */}

列出項目的環境。每個環境都會顯示其最新部署（帶有`(active)` marker when it's serving traffic) and the env var names injected by managed resources such as attached databases.

```bash
mastra env list
```

#### `--json` {/* #--json */}

發出機器可讀的 JSON。僅包含非敏感元資料（id、名稱、slug、類型、區域、分支、URL、託管環境變數名稱和最新部署狀態），因此輸出可以安全地登入 CI。

### `mastra env create` {/* #mastra-env-create */}

為專案創建新環境。

```bash
mastra env create staging --type staging --region eu
```

#### `-t, --type` {/* #-t---type */}

環境類型。之一`production`, `staging`, or `preview`. Defaults to `staging`.

#### `-r, --region` {/* #-r---region */}

環境區域（例如`eu`).

#### `--json` {/* #--json-1 */}

發出機器可讀的 JSON。敏感字段被省略，如[`mastra env list`](#mastra-env-list).

### `mastra env delete` {/* #mastra-env-delete */}

刪除環境。

```bash
mastra env delete <env>
```

`<env>`可以是環境名稱、slug 或 ID。 CLI 會提示確認，除非`--yes` is passed.

#### `-y, --yes` {/* #-y---yes-1 */}

跳過確認提示。

### `mastra env restart` {/* #mastra-env-restart */}

重新啟動環境的正在執行的服務，以便儲存的環境變數（包括附加資料庫中的託管變數）立即生效，而無需進行新的部署。

```bash
mastra env restart <env>
```

`<env>`可以是環境名稱、slug 或 ID。如果環境從未部署過，則會失敗並出現衝突錯誤。

### `mastra env vars pull` {/* #mastra-env-vars-pull */}

將環境的環境變數拉入本機環境檔案（預設值：`.env`). The file contains the set a deploy of that environment runs with: the vars stored on the environment itself (for example, added in the dashboard's environment editor). Each environment is pulled on its own, and values stored on another environment are never merged in. Projects still on the [legacy pipeline](/docs/mastra-platform/deploy#migrating-from-server-and-studio-deploys) run from project-level vars instead, so pulling any of their environments returns those shared project-level values. Managed vars injected by attached databases are listed as comments (names only) since their values are platform-managed secrets.

```bash
mastra env vars pull
mastra env vars pull <env> --output .env.staging
```

`<env>`可以是環境名稱、slug 或 ID，且當項目只有一個環境時可以省略。該文件是用`0600` permissions. The command stops if the output file already exists. Pass `--force` to replace it.

#### `-o, --output` {/* #-o---output */}

要寫入的文件。預設為`.env`.

#### `-f, --force` {/* #-f---force */}

替換現有的輸出檔。

### `mastra env db` {/* #mastra-env-db */}

管理附加到 Mastra 平台上的項目的資料庫。資料庫由託管提供者（例如 Turso 或 Neon）進行配置，並將其連接環境變數自動注入部署。

資料庫是**environment-scoped** (its env vars only go to one environment) or **shared** (project-scoped: its env vars go to all environments). Environment-scoped is the default for `mastra env db create`: pass an environment argument, or let the CLI pick or prompt for one. Pass `--shared` on create to attach a shared database instead. For other subcommands (`list`, `delete`, `keys`), pass the environment argument to work with environment-scoped databases and omit it for shared databases.

建立和刪除資料庫需要`admin` role in the organization.

### `mastra env db list` {/* #mastra-env-db-list */}

列出附加到項目的資料庫，包括提供者、配置狀態、範圍（每個資料庫提供的環境）以及每個資料庫注入的環境變數名稱。傳遞環境以僅顯示提供該環境的資料庫（環境範圍內的加上共享的）。

```bash
mastra env db list
mastra env db list <env>
```

#### `--json` {/* #--json-2 */}

### `mastra env db create` {/* #mastra-env-db-create */}

## `mastra studio deploy` {/* #mastra-studio-deploy */}

：：：筆記

`mastra studio deploy`繼續工作但被取代[`mastra deploy`](#mastra-deploy), which supports environments (`--env staging`, `--env production`) on a single project. New setups should use `mastra deploy`.

:::

建立您的專案並將其部署到 Mastra 平台。需要通過身份驗證[`mastra auth login`](#mastra-auth-login) or a `MASTRA_API_TOKEN` environment variable.

```bash
mastra studio deploy
```

命令運行`mastra build` and zips the output. It reads an env file from the project directory before uploading everything to the platform. After uploading, it polls the deploy status and streams build logs until the deploy reaches a terminal state.

部署指令會自動載入專案的`.env` file. If `MASTRA_PROJECT_ID` points to a project that was provisioned for Observability, the deploy links to that project instead of creating a new one. Deploying Studio to an observability-only project converts it into a Studio project on the platform side.

CLI 至少需要一個`.env` or `.env.*` file (excluding `.env.example`) in the project directory and fails with `Error: No env file found for deploy.` if none exists. When multiple env files are present, the CLI prompts you to pick one (defaulting to `.env.production`). Pass `--env-file` to choose explicitly. With `--yes` and multiple env files, you must pass `--env-file` or the deploy errors.

組織和項目按以下順序解析：環境變數標誌，`.mastra-project.json` config file, current org from credentials, and lastly interactive prompt. On first deploy, the CLI saves the resolved IDs to `.mastra-project.json` so subsequent deploys skip the prompts.

如果`--project <value>` doesn't match an existing project (by ID or slug), the CLI treats `<value>` as a new project name and creates it after confirmation. Combined with `--yes`, this creates and deploys a new project in one non-interactive command:

```bash
mastra studio deploy --project "my-new-project" --yes
```

## `mastra auth` {/* #mastra-auth */}

管理 Mastra 平台的身份驗證。憑證儲存在`~/.mastra/credentials.json`. You can also set the `MASTRA_API_TOKEN` environment variable as an alternative to interactive login.

### `mastra auth login` {/* #mastra-auth-login */}

開啟瀏覽器進行登入並在本機儲存憑證。

當需要瀏覽器登入且沒有互動式終端機時（在 CI 中，當輸入或輸出透過管道傳輸時，或在Agent程式的 shell 中），該命令首先列印如何驗證無頭 shell，然後仍然等待瀏覽器登入。在同一台機器上，您可以運行`mastra auth login` once in your own terminal so later commands reuse the saved session. In CI or on another machine, set `MASTRA_API_TOKEN` and `MASTRA_ORG_ID` instead. Create the token from a signed-in terminal with [`mastra auth tokens create`](#mastra-auth-tokens-create) or in the dashboard. If the browser sign-in wait times out, the command exits with status 1. If `MASTRA_API_TOKEN` is already set in a non-interactive shell, the command skips browser sign-in: it verifies the token and checks that an organization is selected (from `MASTRA_ORG_ID` or saved credentials), then exits with status 0. If either check fails, it exits with status 1 and names what's missing.

### `mastra auth logout` {/* #mastra-auth-logout */}

刪除儲存的憑證。如果`MASTRA_API_TOKEN` is still set in the environment, the CLI warns that it will continue to be used.

### `mastra auth tokens` {/* #mastra-auth-tokens */}

列出所有 API 令牌及其上次使用日期。

#### `mastra auth tokens create` {/* #mastra-auth-tokens-create */}

```bash

```

使用`--permission` to grant the token extra access. The available permission is `databases:write`, which lets the token create and delete managed databases, for example from CI. Only organization admins can create tokens with permissions. Repeat the flag to grant more than one.

如果平台在沒有請求權限的情況下建立令牌，則該命令將撤銷該令牌並退出並出現錯誤。如果撤銷也失敗，則錯誤顯示`mastra auth tokens revoke` command to run.

## `mastra connect` {/* #mastra-connect */}

管理連結平台專案的提供者連接，以便Agent使用`@mastra/connect` pick up provider toolsets without leaving the terminal.

命令使用您登入的組織`mastra auth login`. Switch organizations with `mastra auth orgs switch`.

目標項目由`--project` flag, the `MASTRA_PROJECT_ID` environment variable, or the `.mastra-project.json` written by `mastra deploy`, in that order. All subcommands accept `--project <name|slug|id>`.

### `mastra connect list` {/* #mastra-connect-list */}

首先列出具有連接的提供者的提供者。活動連線顯示為綠色，需要重新授權的連線顯示為黃色，未連線的提供者顯示為灰色。尚不可用的提供者被標記為即將推出。

```bash
mastra connect list
```

### `mastra connect add` {/* #mastra-connect-add */}

將提供者連接到項目。當組織已擁有未附加到項目的提供者連線時，該命令會列出它們並允許您附加現有連線或建立新連線。由於沒有現有連接，它會直接進入提供者的身份驗證流程。

OAuth 提供者會在您的瀏覽器中開啟提供者的同意畫面，並列印其 URL（如果您需要手動開啟它）。 API 金鑰和基本驗證提供者會在終端機中提示輸入憑證，並在完成連線之前進行驗證。具有其他驗證類型的提供者會開啟託管連線頁面。該指令會等到連線變成活動狀態後再退出。

憑證提示需要互動式終端，即使使用`--yes`. Run the command outside CI or connect through the platform UI. Each provider's [integration page](/docs/mastra-platform/connect#providers) lists its API key and permission requirements.

一旦新連線處於活動狀態，該命令就會提供設定顯示名稱的功能，以便您可以區分與相同提供者的連線。它列出了提供者的現有連接，建議一個不與它們衝突的名稱，並要求確認所選名稱是否與另一個連接的名稱重複。將該欄位留空以跳過命名。設定顯示名稱需要組織管理員角色；如果命名失敗，連線仍保持活動狀態。

```bash
mastra connect add <provider>
```

經過`--yes` to skip all prompts. This always creates a new connection without a display name, even when existing connections could be reused.

### `mastra connect remove` {/* #mastra-connect-remove */}

取消提供者與項目的連線。組織層級的連接將被保留，並可以在以後重新連接。

```bash
mastra connect remove <provider>
```

當提供者有多個連線時，指令會提示刪除哪一個連線。經過`--yes` to skip confirmation. Without a terminal, or with `--yes`, removing several connections at once requires `--all`, and `--connection <id>` removes a single one.

### 替換需要重新授權的連接 {/* #replace-a-connection-that-needs-reauthorization */}

`mastra connect list`標記需要重新授權的連接，例如在撤銷提供者 API 金鑰後。連接Tool解析會跳過這些連接並發出警告。

取消受影響連接的鏈接，然後添加一個新連接：

```bash
mastra connect remove posthog
mastra connect add posthog
```

如果項目有多個連接，請在刪除時選擇受影響的連接。什麼時候`add` offers to reuse an organization connection, choose **Create a new connection** and authorize it with valid credentials.

## `mastra traces import` {/* #mastra-traces-import */}

將歷史追蹤從受支援的Observability提供者匯入到現有的 Mastra 平台專案中。該命令在本地準備完整的跟踪，批量上傳整個跟踪，支持恢復，並通過 Mastra 平台驗證樣本。

```bash
mastra traces import <provider> [options]
```

目前支援以下提供者：

|供应商|论证|要求|
| - | - | - |
|朗福斯|`langfuse` | Langfuse Cloud or self-hosted Langfuse v4 or later |

看[Import existing traces](/docs/mastra-platform/observability#import-existing-traces) for the complete workflow, data mapping, local-file lifecycle, and limits.

### 選項 {/* #options */}

#### `--target-project <name|slug|id>` {/* #--target-project-nameslugid */}

選擇接收追蹤的目標 Mastra 平台專案。優先於`MASTRA_PROJECT_ID`. Without either value, the command uses the project linked in `.mastra-project.json`. The source project comes from the provider credentials, such as `LANGFUSE_PUBLIC_KEY` and `LANGFUSE_SECRET_KEY`.

#### `--since <date>` {/* #--since-date */}

將導入視窗的起始時間設定為 ISO 8601 日期或時間戳記。預設為30天前`--until`, clamped to the current 30-day Platform retention boundary. `--from` is accepted as an alias.

#### `--until <date>` {/* #--until-date */}

將匯入視窗的獨佔結束設定為 ISO 8601 日期或時間戳記。預設為導入開始的時間，不能是將來的時間。`--to` is accepted as an alias.

完整的窗口必須在當前 30 天的平台保留期內，`--since` must be earlier than `--until`, and the window can't exceed 30 days.

#### `--dry-run` {/* #--dry-run */}

讀取原始程式碼並在本地準備有效的跟踪，而無需上傳它們。該命令寫入報告並列印恢復準備導入的命令。

#### `--resume <import-id>` {/* #--resume-import-id */}

使用已儲存的提供程序、目標專案、日期視窗和確認的進度恢復準備好的匯入。使用產生的恢復命令中顯示的相同目標項目。該選項不能與`--since`, `--until`, or `--dry-run`.

#### `-y, --yes` {/* #-y---yes-4 */}

無需確認即可上傳。

### 環境變數 {/* #environment-variables */}

該命令加載`.env` and `.env.local` from the current directory.

|變數|必填|描述 |
| - | - | - |
|`LANGFUSE_PUBLIC_KEY` | For new Langfuse imports | Public project API key. Together with the secret key, it selects the source Langfuse project. |
| `LANGFUSE_SECRET_KEY` | For new Langfuse imports | Secret project API key. |
| `LANGFUSE_BASE_URL` | No | Langfuse host. Defaults to `https://cloud.langfuse.com`. |
| `MASTRA_API_TOKEN` | For headless authentication | Mastra Platform API token. Without it, the command uses credentials from `mastra auth login`. |
| `MASTRA_ORG_ID` | With `MASTRA_API_TOKEN` | Organization that owns the destination project. |
| `MASTRA_PLATFORM_ACCESS_TOKEN` | For upload and read-back with interactive login | Mastra Platform access token for the destination. Not required for `--dry-run` or when `MASTRA_API_TOKEN` is set. |
| `MASTRA_PROJECT_ID` | When no project is otherwise linked | Destination project ID. The `--target-project` flag takes precedence over it. |

### 範例 {/* #examples-1 */}

預覽預設的 30 天視窗而不上傳：

```bash
mastra traces import langfuse --target-project my-mastra-project --dry-run
```

匯入較小的日期視窗而不顯示確認提示：

```bash
mastra traces import langfuse \
  --target-project my-mastra-project \
  --since "$SINCE" \
  --until "$UNTIL" \
  --yes
```

恢復現有導入：

```bash
mastra traces import langfuse \
  --resume 00000000-0000-0000-0000-000000000000 \
  --target-project my-mastra-project
```

## `mastra api` {/* #mastra-api */}

使用 JSON 輸入和 JSON 輸出呼叫 Mastra 運行時伺服器。將其用於本機開發伺服器、部署的 Mastra 平台專案、自架 Mastra 伺服器或託管的 Mastra 平台Observability API。

```bash
mastra api agent list
mastra api agent run weather-agent '{"messages":"What is the weather in London?"}'
mastra api tool execute get-weather '{"location":"San Francisco"}'
mastra api trace list '{"page":0,"perPage":20}'
```

使用`mastra api <resource> <action> --help` to see examples for a command.

### 輸出 {/* #output */}

成功響應將寫入`stdout` as JSON. Single-resource commands return:

```json
{ "data": {} }
```

列表命令回傳一個`data` array and pagination metadata:

```json
{ "data": [], "page": { "total": 0, "page": 0, "perPage": 0, "hasMore": false } }
```

錯誤被寫入`stderr` as JSON and return a non-zero exit code:

```json
{
  "error": {
    "code": "SERVER_UNREACHABLE",
    "message": "Could not connect to target server",
    "details": {}
  }
}
```

退出代碼反映請求是否成功，而不是回應的內容：

* `0`：伺服器傳回成功的回應。這包括空結果和報告現有狀態的有效負載，例如表明記錄已存在的Tool結果。傳回帶有以下內容的物件的Tool`error` field still exits `0`, so check the `data` payload when the tool reports its own failures.
* `1`: 請求失敗。這包括無法存取的伺服器、無效的 JSON 輸入、遺失的資源或引發錯誤的Tool。

如果讀取輸出的命令提前退出，如`| head`, the exit code still reflects whether the request succeeded.

### 目標解析度 {/* #target-resolution */}

對於運行時命令，該命令會按以下順序解析目標伺服器：

1. `--url <url>`對於顯式遠端或自託管伺服器。
2. `http://localhost:4111`對當地人來說`mastra dev` server.
3. `.mastra-project.json`對於 Mastra 平台專案。

當 CLI 解析專案時，將使用自動平台身份驗證`.mastra-project.json` or recognizes an explicit Mastra-hosted Studio, Factory, or observability URL. Localhost and arbitrary explicit `--url` targets don't receive automatic credentials. Headers passed with `--header` are sent to any target, including localhost.

對於Observability命令（`trace`, `log`, `score`, and `metric`), the CLI targets the United States endpoint at `https://observability.mastra.ai` by default instead of a project deployment URL. Trace Intelligence commands (`learning`) work the same way but target `https://output.signals.mastra.ai`. When the CLI selects either hosted target automatically, it resolves credentials in this order:

1. 顯式的`Authorization` and `X-Mastra-Project-Id` headers passed with `--header`.
2. `MASTRA_PLATFORM_ACCESS_TOKEN`和`MASTRA_PROJECT_ID` from your environment.
3. 項目元數據來自`.mastra-project.json` for the project ID.
4. 您的 Mastra CLI 登入令牌作為身份驗證後備。

學習命令也發送`X-Mastra-Organization-Id`, resolved from an explicit `--header`, `MASTRA_ORGANIZATION_ID` in your environment, or `.mastra-project.json`, in that order.

歐盟Observability資料儲存在`https://observability.eu.mastra.ai`. Pass that trusted host with `--url`; it uses the same Platform credential resolution as the default United States endpoint:

```bash
mastra api --url https://observability.eu.mastra.ai trace list
```

使用`--url` and `--header` when you need to override another target or its credentials.

### 工廠命令 {/* #factory-commands */}

使用`mastra api factory` to manage Factory projects, work items, decisions, attention items, and queue health. These commands use the same JSON input, output, authentication, headers, timeout, and target resolution as other `mastra api` commands.

列出目前組織可用的 Factory 專案：

```bash
mastra api factory project list
```

在傳送受控工作項轉換之前檢查產生的請求架構：

```bash
mastra api factory work-item transition --schema
```

使用其目前版本移動工作項目：

```bash
mastra api factory work-item transition <project-id> <work-item-id> '{"board":"work","stage":"planning","requestId":"00000000-0000-4000-8000-000000000000","cause":"manual","expectedRevision":1}'
```

使用以下命令部署專案後`mastra deploy`, the resulting non-secret `.mastra-project.json` lets the CLI find the hosted Factory instance, apply your Mastra CLI credentials, and select the deployed project's organization automatically. For an explicit hosted Factory `--url`, the CLI uses `MASTRA_ORG_ID` when set, then the organization selected by `mastra auth orgs switch`. An explicit `X-Mastra-Organization-Id` header takes precedence over both. Before deployment, or to target a specific local, remote, or self-hosted Factory server, pass `--url` instead:

```bash
mastra api --url http://localhost:4111 factory project list
```

工廠端點使用其根級`/web/factory/...` paths. `--server-api-prefix` still controls local target probing, but it isn't prepended to Factory requests.

### 旗幟 {/* #flags-13 */}

#### `--url <url>` {/* #--url-url */}

定位特定的 Mastra 伺服器 URL。

```bash

```

#### `--server-api-prefix <prefix>` {/* #--server-api-prefix-prefix */}

設定目標伺服器的API路由前綴。預設為`/api`. Use this when the server is mounted under a custom prefix (for example a `@mastra/fastify` `MastraServer` with `prefix: "/api/mastra-studio"`), the same way `mastra studio` accepts `--server-api-prefix`. You can also set the `MASTRA_API_PREFIX` environment variable instead of passing the flag.

```bash

```

#### `--header <"Key: Value">` {/* #--header-key-value */}

傳送自訂 HTTP 標頭。重複該標誌以發送多個標頭。


#### `--pretty` {/* #--pretty */}

漂亮列印的 JSON 輸出。預設為`false`.

#### `--schema` {/* #--schema */}

列印接受 JSON 輸入的命令的面向 CLI 的請求架構。此模式來自目標伺服器的路由契約，包括命令形狀、位置、範例、請求模式和回應形狀。

`--schema`在接受 JSON 輸入的葉子命令上可用。它不能作為頂級使用`mastra api` flag.

```bash

```

### 輸入模型 {/* #input-model */}

接受輸入的指令採用一個內嵌 JSON 參數。不要傳遞檔案路徑或標準輸入。

```bash
mastra api workflow run start data-pipeline '{"inputData":{"source":"s3://bucket/data.csv"}}'
```

使用位置參數作為穩定 ID，使用 JSON 作為濾波器或負載。對於同時需要查詢參數和請求正文的路由，請傳遞一個 JSON 物件。 CLI 根據伺服器路由架構分割輸入。

```bash
mastra api thread create '{"agentId":"weather-agent","resourceId":"user_123","threadId":"thread_abc123","title":"Support conversation"}'
```

列表命令接受`page` and `perPage` in the JSON input when the target route supports pagination:

```bash
mastra api score list '{"page":0,"perPage":50}'
mastra api trace list '{"page":0,"perPage":20}'
```

支援過濾器的路由在同一 JSON 輸入中接受它們。例如，可觀察性追蹤清單支援分頁和路由支援的篩選器：

```bash

```

`https://observability.mastra.ai` by default. Pass `--url http://localhost:4111` to query a local server.

```bash

```

Mastra 平台目前不公開所使用的架構端點`--schema`. To find fields and values recorded in your project, use [field and value discovery](/reference/observability/tracing/advanced-queries#discover-fields-and-values).

回應仍然嵌套在`data` to preserve cursor pagination:

```json
{
  "data": {
    "traces": [],
    "page": { "next": "opaque-cursor" }
  }
}
```

每次呼叫都會進行一次查詢。傳遞一個非空值`data.page.next` value back as `page.after` in the next query. See [Pagination and errors](/reference/observability/tracing/advanced-queries#pagination-and-errors) for pagination modes, cursor handling, and errors.

若要載入編號頁面然後輪詢，請在兩個請求中保持相同的時間範圍和謂詞：

```bash
mastra api trace query '{"timeRange":{"from":"2026-08-01T00:00:00.000Z","to":"2026-08-08T00:00:00.000Z"},"pagination":{"page":0,"perPage":100}}'
mastra api trace query '{"timeRange":{"from":"2026-08-01T00:00:00.000Z","to":"2026-08-08T00:00:00.000Z"},"mode":"delta","after":"CURSOR_FROM_NUMBERED_RESPONSE","limit":100}'
```

代替`CURSOR_FROM_NUMBERED_RESPONSE` with `data.deltaCursor` from the first response. Delta results remain under `data`, with `traces`, `delta: { limit, hasMore }`, and `deltaCursor`. Merge traces by `traceId`, retain each returned cursor, and continue immediately while `data.delta.hasMore` is `true`. Don't combine delta mode with `page`, `pagination`, or `orderBy`.

省略`after` establishes a cursor and returns no historical traces. Changing the time range or predicate requires a fresh numbered request. See [Delta polling limitations](/reference/observability/tracing/advanced-queries#poll-after-loading-a-numbered-page) before using this workflow to maintain a local trace list.

#### `mastra api trace aggregate` {/* #mastra-api-trace-aggregate */}

將按時間範圍和可選選項選擇的軌跡進行分組`where` predicate, and returns one row of measures per group, or per group and non-empty time bucket when `interval` is set. The inline JSON input is required and accepts the same predicates as `trace query`. Like other observability commands, it targets `https://observability.mastra.ai` by default.

```bash
mastra api trace aggregate <input>
mastra api trace aggregate '{"timeRange":{"from":"2026-08-01T00:00:00.000Z","to":"2026-08-08T00:00:00.000Z"},"groupBy":["entityName"],"measures":["count","errorRate"]}'
```

放`interval` to `1m`, `5m`, `15m`, `1h`, or `1d` to split each group into time buckets:

```bash
mastra api trace aggregate '{"timeRange":{"from":"2026-08-01T00:00:00.000Z","to":"2026-08-08T00:00:00.000Z"},"where":{"op":"eq","left":{"path":"entityName"},"right":{"literal":"weather-agent"}},"interval":"1d","measures":["count","duration.p95"]}'
```

有關維度、度量和請求選項，請參閱[Aggregate traces](/reference/client-js/observability#aggregate-traces). Run `mastra api trace aggregate --help` for more examples.

回應仍然嵌套在下面`data` so `truncated` is preserved. `truncated` is `true` when more groups matched than `limit`:

```json
{
  "data": {
    "rows": [
      {
        "dimensions": { "entityName": "weather-agent" },
        "measures": { "count": 42, "errorRate": 0.05 }
      }
    ],
    "truncated": false
  }
}
```

可觀察性儲存不支援追蹤聚合返回的伺服器`501`. The CLI prints it like other request failures, as an `HTTP_ERROR` with the server response in `error.details.body`.

#### `mastra api span query` {/* #mastra-api-span-query */}

查詢完成的可觀察性跨越跟踪，包括嵌套在其他跟踪內的Agent運行和Tool調用。內嵌 JSON 輸入是必需的，並且使用與以下相同的請求[`querySpans()`](/reference/observability/tracing/advanced-queries#query-spans). Its `where` predicate filters span fields directly. Like other observability commands, it targets `https://observability.mastra.ai` by default.

```bash
mastra api span query <input>
mastra api span query '{"timeRange":{"from":"2026-08-07T00:00:00.000Z","to":"2026-08-08T00:00:00.000Z"},"where":{"op":"and","args":[{"op":"eq","left":{"path":"spanType"},"right":{"literal":"tool_call"}},{"op":"eq","left":{"path":"status"},"right":{"literal":"error"}}]}}'
```

回應仍然嵌套在下面`data` as `{ "spans": [], "page": { "next": "opaque-cursor" } }`. Pass a non-null `data.page.next` value back as `page.after` in the next query, keeping the same time range, predicate, and ordering. Run `mastra api span query --help` for more examples.

Observability儲存不支援跨度查詢的伺服器返回`501`. Filters on identity, context, and parent or root entity fields return `422` when the store doesn't support them. Check `spanQueryContextFields` in the server's observability capabilities before using them. The CLI prints both as an `HTTP_ERROR` with the server response in `error.details.body`.

#### `mastra api span aggregate` {/* #mastra-api-span-aggregate */}

將按時間範圍和可選選項選擇的跨度進行分組`where` predicate, and returns one row of measures per group, or per group and non-empty time bucket when `interval` is set. It accepts the same fixed measures, `interval`, `having`, `orderBy`, and `limit` as `trace aggregate`. Its `where` filters spans directly, and its dimensions and `countDistinct` fields follow the span contract. It groups by span fields such as `spanType`, `entityName`, `status`, and `rootEntityName`.

```bash
mastra api span aggregate <input>
mastra api span aggregate '{"timeRange":{"from":"2026-08-01T00:00:00.000Z","to":"2026-08-08T00:00:00.000Z"},"where":{"op":"eq","left":{"path":"spanType"},"right":{"literal":"tool_call"}},"groupBy":["entityName"],"measures":["count","errorRate","duration.p95"],"orderBy":{"field":"errorRate","direction":"desc"},"limit":10}'
```

令牌和成本度量計算記錄它的跨度的使用情況，通常是`model_generation` span. They aren't added to parent spans such as `agent_run`. For span dimensions, measures, and limits, see [Aggregate spans](/reference/observability/tracing/advanced-queries#aggregate-spans). Run `mastra api span aggregate --help` for more examples.

喜歡`trace aggregate`, the command prints `rows` and `truncated` under `data`, and if the observability store can't aggregate spans, the CLI prints the server's `501` response as an `HTTP_ERROR`.

## 遙測 {/* #telemetry */}

預設情況下，Mastra 會收集有關您的專案的遙測數據，包括您的作業系統、Mastra 版本和 Node.js 版本。伺服器事件還包括下述項目標識符。您可以閱讀[CLI telemetry source code](https://github.com/mastra-ai/mastra/blob/main/packages/cli/src/analytics/index.ts) to check what's collected by the CLI.

當伺服器啟動時`mastra dev`, `mastra start`, or a `mastra build` output has observability configured, Mastra counts the input and output tokens each model call uses in that server process. Every 15 minutes, and once more when the server shuts down, it sends a `mastra_model_token_usage_v2` event per provider and model used since the previous report. If no model calls finished since then, nothing is sent. Each event contains the tokens used since the previous report, the report window's start and end times, the reason for the report (`interval` or `shutdown`), the command (`dev`, `start`, or `server` when the build output runs directly), and `NODE_ENV`. No prompts, responses, or other message content is sent. You can read the [model usage telemetry source code](https://github.com/mastra-ai/mastra/blob/main/packages/core/src/telemetry/model-usage-telemetry.ts) to check what's collected.

為了與較早的分析相容，伺服器還發送較早的分析`mastra_model_token_usage` event at startup. It reads token totals from observability storage and sends the usage added since a cursor saved in `~/.mastra/usage-telemetry.json`. You can read the [startup usage telemetry source code](https://github.com/mastra-ai/mastra/blob/main/packages/core/src/telemetry/usage-telemetry.ts) to check what's collected.

伺服器啟動時，Mastra 發送項目表面快照，其中包含元件計數、功能標誌和粗略儲存後端類別，但沒有元件名稱或元件識別碼。您可以閱讀[feature telemetry source code](https://github.com/mastra-ai/mastra/blob/main/packages/core/src/telemetry/feature-telemetry.ts) to check what's collected.

伺服器事件`mastra_feature_usage`, `mastra_model_token_usage`, and `mastra_model_token_usage_v2` include:

* `project_id`： SHA-256 雜湊值的前 16 個十六進位字符`MASTRA_PROJECT_ROOT`, or the current working directory when unset. This identifier also keys the local model-usage cursor.
* `project_id2`：用於跨機器和部署關聯的可選標識符。如果修剪過`MASTRA_PROJECT_ID` value has UUID format, the value is sent **unhashed**, prefixed with `mp_`. Search for `mp_<platform-project-id>` to find that project's telemetry. Names, slugs, and other non-UUID values aren't sent as Platform identifiers.

當沒有UUID形狀的平台ID可用時，`project_id2` uses the first 16 hexadecimal characters of the SHA-256 hash of the normalized Git `origin` remote. Normalization keeps the lowercase host and repository path, excluding the scheme, credentials, port, query, fragment, trailing slashes, and `.git` suffix. Equivalent SSH and HTTPS remotes produce the same identifier. Remotes with the same host and path share an identifier even if different ports or SSH users refer to different repositories. Local filesystem remotes aren't used. Git discovery runs asynchronously and is cached for the process, including when unavailable. If neither source is available, `project_id2` is omitted.

這些伺服器事件不是匿名的：平台 ID 將它們連結到該項目，並且可以對已知儲存庫 URL 進行規範化和雜湊處理以匹配 Git 派生的事件。對 Git 身分進行雜湊處理可以避免傳送原始儲存庫 URL 或憑證，但不會封鎖與公用或其他已知儲存庫的關聯。

Studio UI 也會收集匿名瀏覽器端使用情況分析，例如頁面視圖和 UI 互動。您可以閱讀[source code](https://github.com/mastra-ai/mastra/blob/main/packages/playground/src/lib/analytics.tsx) to check what's collected. Setting `MASTRA_TELEMETRY_DISABLED` disables this too: the value is injected into the served page, so it applies to `mastra dev` and self-hosted builds alike.

您可以透過在啟動 Mastra 之前設定此環境變數來選擇退出 CLI、伺服器和 Studio 使用情況分析。停用後，伺服器遙測不會尋找 Git 遠端或傳送項目識別碼：

```bash
MASTRA_TELEMETRY_DISABLED=1
```

您也可以在使用其他設備時進行設置`mastra` commands:

```bash
MASTRA_TELEMETRY_DISABLED=1 mastra dev
```
