# 信號提供者

**添加於：** `@mastra/core@1.42.0`

用於建構訊號提供者的抽象基底類別。訊號提供者監視外部來源（API、Webhooks、事件流）並透過內建訂閱註冊表將通知訊號推送到Agent執行緒。

預設情況下，訊號提供者不是處理器。需要拦截Agent执行的提供者从返回处理器`getInputProcessors()` or `getOutputProcessors()`. Providers that expose agent-callable tools return them from `getTools()`.

對於即用型基於 Webhook 的提供程序，請參閱[`WebhookSignalProvider`](/reference/signals/webhook-signal-provider).

## 使用範例 {/* #usage-example */}

每 30 秒檢查一次 API 的輪詢提供者：

```typescript title="src/signals/slack-signals.ts"
import { SignalProvider } from '@mastra/core/signals'
import type { SignalSubscription } from '@mastra/core/signals'

class SlackSignals extends SignalProvider<'slack-signals'> {
  readonly id = 'slack-signals'
  readonly pollInterval = 30_000

  async poll(subscriptions: SignalSubscription[]) {
    for (const sub of subscriptions) {
      const messages = await fetchSlackMessages(sub.externalResourceId)
      if (messages.length > 0) {
        await this.notify(
          {
            source: 'slack',
            kind: 'new-messages',
            summary: `${messages.length} new messages in ${sub.externalResourceId}`,
          },
          { threadId: sub.threadId, resourceId: sub.resourceId },
        )
      }
    }
  }
}
```

向Agent商註冊：

```typescript title="src/mastra/index.ts"
import { Agent } from '@mastra/core/agent'

const agent = new Agent({
  id: 'agent',
  signals: [new SlackSignals()],
})
```

Agent打電話`connect(this)` and registers any processors or tools the provider returns. It then starts polling.

## 方法 {/* #methods */}

### 聯繫 {/* #connection */}

#### `connect(agent)` {/* #connectagent */}

由Agent構造函數呼叫。建立雙向鏈接，以便提供者可以將訊號發送回Agent。建立連結後覆蓋以運行其他設定。總是打電話`super.connect(agent)`.

```typescript
class MySignals extends SignalProvider<'my-signals'> {
  readonly id = 'my-signals'

  override connect(agent) {
    super.connect(agent)
    // additional setup after agent link is established
  }
}
```

#### `__registerMastra(mastra)` {/* #__registermastramastra */}

當提供者的Agent向 Mastra 實例註冊時呼叫。覆蓋以存取儲存或其他 Mastra 服務。總是打電話`super.__registerMastra(mastra)`.

```typescript oxfmt:false
override __registerMastra(mastra) {
  super.__registerMastra(mastra)
  // this.mastra is now available
}
```

### 處理器和Tool集成 {/* #processor-and-tool-integration */}

#### `getInputProcessors()` {/* #getinputprocessors */}

返回輸入處理器該提供者需要向Agent註冊。當您的提供者攔截Agent輸入步驟（例如，注入上下文提示或偵測Tool呼叫）時進行覆寫。

```typescript oxfmt:false
getInputProcessors() {
  return [this]
}
```

返回：`InputProcessorOrWorkflow[]`

#### `getOutputProcessors()` {/* #getoutputprocessors */}

返回輸出處理器該提供者需要向Agent註冊。當您的提供者攔截Agent輸出步驟時覆蓋。

```typescript oxfmt:false
getOutputProcessors() {
  return [this]
}
```

返回：`OutputProcessorOrWorkflow[]`

#### `getTools()` {/* #gettools */}

傳回該提供者向Agent商公開的Tool。當您的提供者新增Agent可呼叫Tool（例如訂閱或取消訂閱命令）時進行覆寫。

```typescript oxfmt:false
getTools() {
  return {
    subscribe_pr: createTool({ /* ... */ }),
    unsubscribe_pr: createTool({ /* ... */ }),
  }
}
```

返回：`Record<string, unknown>`

### 訂閱追蹤 {/* #subscription-tracking */}

#### `subscribe(target, externalResourceId, metadata?)` {/* #subscribetarget-externalresourceid-metadata */}


### 輪詢 {/* #polling */}

#### `poll(subscriptions)` {/* #pollsubscriptions */}

在每個輪詢週期中對所有活動訂閱進行呼叫。覆蓋以檢查外部來源並發出通知。此框架可防止輪詢週期重疊：如果`poll()` call takes longer than `pollInterval`, the next cycle is skipped.

```typescript oxfmt:false
async poll(subscriptions: SignalSubscription[]) {
  for (const sub of subscriptions) {
    const events = await checkExternalSource(sub.externalResourceId)
    for (const event of events) {
      await this.notify(
        { source: 'my-provider', kind: event.type, summary: event.message },
        { threadId: sub.threadId, resourceId: sub.resourceId },
      )
    }
  }
}
```

#### `startPolling()` {/* #startpolling */}

啟動輪詢計時器。之後由Agent致電`connect()`. Idempotent: calling multiple times has no effect.

```typescript
provider.startPolling()
```

#### `stopPolling()` {/* #stoppolling */}

停止輪詢計時器。

```typescript
provider.stopPolling()
```

### 網路鉤子 {/* #webhooks */}

#### `handleWebhook(request)` {/* #handlewebhookrequest */}

處理傳入的 Webhook 請求。重寫以解析有效負載並將其與訂閱匹配。然後發出通知信號。看[`WebhookSignalProvider`](/reference/signals/webhook-signal-provider) for a ready-to-use implementation.

從返回的路由呼叫此方法[`getRoutes()`](#getroutes) or from your own HTTP endpoint, after verifying the webhook request.

```typescript oxfmt:false
async handleWebhook(request) {
  const payload = request.body as { repo: string, event: string }
  const subs = this.getSubscriptionsForResource(payload.repo)

  for (const sub of subs) {
    await this.notify(
      { source: 'github', kind: payload.event, summary: `Event on ${payload.repo}` },
      { threadId: sub.threadId, resourceId: sub.resourceId },
    )
  }

  return { status: 200, body: { matched: subs.length } }
}
```

返回：`Promise<{ status?: number; body?: unknown }>`

#### `getRoutes()` {/* #getroutes */}

傳回該提供者在 Mastra 伺服器上所需的 API 路由，例如 Webhook 接收器或 OAuth 回呼。選修的。當提供者的Agent註冊後，Mastra 將這些路由新增至`server.apiRoutes`, so you don't add them by hand.

Agent註冊時會收集路由。如果您新增Agent`addAgent()` after the server has started, its provider routes aren't served until the server restarts. `removeAgent()` removes the agent's provider routes, unless another registered agent uses the same provider instance.

如果已註冊具有相同方法和路徑的路由，則現有路由獲勝：

*
* 一條路線在`server.apiRoutes` or a file-system route replaces the provider route, and Mastra logs a warning.
* 如果兩個不同的提供者聲明相同的路線，則安裝第一個註冊的提供者，並且 Mastra 會記錄警告。

```typescript oxfmt:false
getRoutes() {
  return [
    registerApiRoute('/acme/webhook', {
      method: 'POST',
      requiresAuth: false,
      handler: async c => {
        // Public route: verify the sender before handling the payload
        const rawBody = await c.req.text()
        if (!verifyAcmeSignature(rawBody, c.req.header('x-acme-signature'))) {
          return c.json({ error: 'invalid signature' }, 401)
        }
        const result = await this.handleWebhook({ body: JSON.parse(rawBody), headers: c.req.header() })
        return c.json(result.body ?? {}, result.status ?? 200)
      },
    }),
  ]
}
```

返回：`ApiRoute[]`

提供者路線遵循與其他路線相同的規則[custom API routes](/docs/server/custom-api-routes#authentication). Adding a provider to an agent mounts its routes with no extra step from the user, so set access on each route deliberately:

* 當伺服器配置了身份驗證時，路由預設需要身份驗證。
* 一條路線與`requiresAuth: false` is public. Verify the sender, for example with a webhook signature, before calling `handleWebhook()`.
* 應設定經過身份驗證的路由`requiresPermission` or `fga`. When an FGA provider audits protected routes, routes with neither are reported at startup.
* 路徑不能以伺服器的開頭`apiPrefix` (`/api` by default). The server throws at startup. Use a provider-specific prefix such as `/acme/...`.

### 生命週期 {/* #lifecycle */}

#### `start()` {/* #start */}

之後調用`connect()` to run async initialization. Override when setup requires the agent or Mastra instance to be available.

```typescript oxfmt:false
async start() {
  await this.loadInitialState()
}
```

打電話叫關機。預設實現停止輪詢並清除所有訂閱。

```typescript
provider.stop()
```
