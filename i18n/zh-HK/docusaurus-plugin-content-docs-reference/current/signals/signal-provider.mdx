# SignalProvider

**新增於：** `@mastra/core@1.42.0`

這是建立訊號 Provider 的抽象基底類別。訊號 Provider 監察外部來源（API、Webhook、事件串流），並透過內建訂閱登記機制向 Agent 線程推送通知訊號。

訊號 Provider 預設不是處理器。需要攔截 Agent 執行過程的 Provider，可透過 `getInputProcessors()` 或 `getOutputProcessors()` 傳回處理器；需要提供 Agent 可呼叫的 Tool，則可透過 `getTools()` 傳回。

如需可直接使用的 Webhook Provider，請參閱 [`WebhookSignalProvider`](/reference/signals/webhook-signal-provider)。

## 使用示例 {/* #usage-example */}

以下輪詢 Provider 每 30 秒檢查一次 API：

```typescript title="src/signals/slack-signals.ts"
import { SignalProvider } from '@mastra/core/signals'
import type { SignalSubscription } from '@mastra/core/signals'

class SlackSignals extends SignalProvider<'slack-signals'> {
  readonly id = 'slack-signals'
  readonly pollInterval = 30_000

  async poll(subscriptions: SignalSubscription[]) {
    for (const sub of subscriptions) {
      const messages = await fetchSlackMessages(sub.externalResourceId)
      if (messages.length > 0) {
        await this.notify(
          {
            source: 'slack',
            kind: 'new-messages',
            summary: `${messages.length} new messages in ${sub.externalResourceId}`,
          },
          { threadId: sub.threadId, resourceId: sub.resourceId },
        )
      }
    }
  }
}
```

將其註冊至 Agent：

```typescript title="src/mastra/index.ts"
import { Agent } from '@mastra/core/agent'

const agent = new Agent({
  id: 'agent',
  signals: [new SlackSignals()],
})
```

Agent 會呼叫 `connect(this)`、註冊 Provider 傳回的處理器或 Tool，然後開始輪詢。

## 方法 {/* #methods */}

### 連接 {/* #connection */}

#### `connect(agent)` {/* #connectagent */}

由 Agent 建構函數呼叫，建立雙向連接，讓 Provider 能向 Agent 發送訊號。可覆寫此方法，在連接建立後執行額外設定；必須呼叫 `super.connect(agent)`。

```typescript
class MySignals extends SignalProvider<'my-signals'> {
  readonly id = 'my-signals'

  override connect(agent) {
    super.connect(agent)
    // additional setup after agent link is established
  }
}
```

#### `__registerMastra(mastra)` {/* #__registermastramastra */}

當 Provider 所屬的 Agent 註冊至 Mastra 實例時呼叫。可覆寫此方法以存取儲存或其他 Mastra 服務；必須呼叫 `super.__registerMastra(mastra)`。

```typescript oxfmt:false
override __registerMastra(mastra) {
  super.__registerMastra(mastra)
  // this.mastra is now available
}
```

### 處理器與 Tool 整合 {/* #processor-and-tool-integration */}

#### `getInputProcessors()` {/* #getinputprocessors */}

傳回此 Provider 需要註冊至 Agent 的輸入處理器。若 Provider 要攔截 Agent 輸入步驟（例如加入上下文提示或偵測 Tool 呼叫），請覆寫此方法。

```typescript oxfmt:false
getInputProcessors() {
  return [this]
}
```

返回：`InputProcessorOrWorkflow[]`

#### `getOutputProcessors()` {/* #getoutputprocessors */}

傳回此 Provider 需要註冊至 Agent 的輸出處理器。若 Provider 要攔截 Agent 輸出步驟，請覆寫此方法。

```typescript oxfmt:false
getOutputProcessors() {
  return [this]
}
```

返回：`OutputProcessorOrWorkflow[]`

#### `getTools()` {/* #gettools */}

傳回此 Provider 向 Agent 提供的 Tool。若 Provider 加入訂閱、取消訂閱等 Agent 可呼叫的 Tool，請覆寫此方法。

```typescript oxfmt:false
getTools() {
  return {
    subscribe_pr: createTool({ /* ... */ }),
    unsubscribe_pr: createTool({ /* ... */ }),
  }
}
```

返回：`Record<string, unknown>`

### 訂閱追蹤 {/* #subscription-tracking */}

#### `subscribe(target, externalResourceId, metadata?)` {/* #subscribetarget-externalresourceid-metadata */}

讓線程訂閱外部資源。此方法受保護，請在 Provider 實作內呼叫。

```typescript
const sub = this.subscribe(
  { threadId: 'thread-1', resourceId: 'user-1' },
  'github:mastra-ai/mastra#123',
  { pr: 123 },
)
```

傳回：`SignalSubscription`，即新建立的訂閱，或合併元數據後的現有訂閱。

### 輪詢 {/* #polling */}

#### `poll(subscriptions)` {/* #pollsubscriptions */}

每個輪詢週期都會呼叫此方法，並傳入所有有效訂閱。可覆寫此方法檢查外部來源並發送通知。框架會避免輪詢週期重疊：若一次 `poll()` 執行超過 `pollInterval`，便會跳過下一個週期。

```typescript oxfmt:false
async poll(subscriptions: SignalSubscription[]) {
  for (const sub of subscriptions) {
    const events = await checkExternalSource(sub.externalResourceId)
    for (const event of events) {
      await this.notify(
        { source: 'my-provider', kind: event.type, summary: event.message },
        { threadId: sub.threadId, resourceId: sub.resourceId },
      )
    }
  }
}
```

#### `startPolling()` {/* #startpolling */}

啟動輪詢計時器。Agent 會在 `connect()` 後呼叫此方法；重複呼叫不會有額外效果。

```typescript
provider.startPolling()
```

#### `stopPolling()` {/* #stoppolling */}

停止輪詢計時器。

```typescript
provider.stopPolling()
```

### Webhook {/* #webhooks */}

#### `handleWebhook(request)` {/* #handlewebhookrequest */}

處理傳入的 Webhook 請求。可覆寫此方法來解析載荷、比對訂閱並發出通知訊號。現成實作請參閱 [`WebhookSignalProvider`](/reference/signals/webhook-signal-provider)。

驗證 Webhook 請求後，從 [`getRoutes()`](#getroutes) 傳回的路由或自訂 HTTP 端點呼叫此方法。

```typescript oxfmt:false
async handleWebhook(request) {
  const payload = request.body as { repo: string, event: string }
  const subs = this.getSubscriptionsForResource(payload.repo)

  for (const sub of subs) {
    await this.notify(
      { source: 'github', kind: payload.event, summary: `Event on ${payload.repo}` },
      { threadId: sub.threadId, resourceId: sub.resourceId },
    )
  }

  return { status: 200, body: { matched: subs.length } }
}
```

返回：`Promise<{ status?: number; body?: unknown }>`

#### `getRoutes()` {/* #getroutes */}

傳回此 Provider 在 Mastra 伺服器上需要的 API 路由，例如 Webhook 接收端點或 OAuth 回調。此方法屬可選。註冊 Provider 所屬的 Agent 時，Mastra 會將路由加入 `server.apiRoutes`，毋須手動加入。

註冊 Agent 時會收集其路由。若伺服器啟動後才透過 `addAgent()` 加入 Agent，其 Provider 路由要待伺服器重啟才會生效。呼叫 `removeAgent()` 會移除該 Agent 的 Provider 路由，除非另一個已註冊 Agent 使用同一個 Provider 實例。

若相同方法和路徑的路由已註冊，現有路由優先：

- 多個 Agent 共用一個 Provider 時，其路由只會掛載一次。
- `server.apiRoutes` 中的路由或檔案系統路由會取代 Provider 路由，Mastra 同時會記錄警告。
- 如果兩個不同的 Provider 宣告相同路由，會掛載先註冊的路由，Mastra 同時會記錄警告。

```typescript oxfmt:false
getRoutes() {
  return [
    registerApiRoute('/acme/webhook', {
      method: 'POST',
      requiresAuth: false,
      handler: async c => {
        // Public route: verify the sender before handling the payload
        const rawBody = await c.req.text()
        if (!verifyAcmeSignature(rawBody, c.req.header('x-acme-signature'))) {
          return c.json({ error: 'invalid signature' }, 401)
        }
        const result = await this.handleWebhook({ body: JSON.parse(rawBody), headers: c.req.header() })
        return c.json(result.body ?? {}, result.status ?? 200)
      },
    }),
  ]
}
```

返回：`ApiRoute[]`

Provider 路由遵循其他[自訂 API 路由](/docs/server/custom-api-routes#authentication)的相同規則。將 Provider 加入 Agent 後，路由會自動掛載，因此應明確設定每條路由的存取權限：

- 伺服器設有身分驗證時，路由預設需要驗證身分。
- 設為 `requiresAuth: false` 的路由是公開路由。呼叫 `handleWebhook()` 前，應透過 Webhook 簽名等方式驗證發送方。
- 需要驗證身分的路由應設定 `requiresPermission` 或 `fga`。FGA Provider 審核受保護路由時，如兩者均未設定，啟動時會作出報告。
- 路徑不可由伺服器的 `apiPrefix`（預設為 `/api`）開頭，否則伺服器啟動時會拋出錯誤。可使用 `/acme/...` 等 Provider 專屬前綴。

### 生命週期 {/* #lifecycle */}

#### `start()` {/* #start */}

在 `connect()` 後呼叫，用於非同步初始化。若初始化需要存取 Agent 或 Mastra 實例，請覆寫此方法。

```typescript oxfmt:false
async start() {
  await this.loadInitialState()
}
```

#### `stop()` {/* #stop */}

關閉時呼叫。預設實作會停止輪詢並清除所有訂閱。

```typescript
provider.stop()
```

    summary: 'PR #123 was updated',
    priority: 'high',
    payload: { prNumber: 123 },

)

## 類型守衛 {/* #type-guard */}

```typescript
import { isSignalProvider } from '@mastra/core/signals'

if (isSignalProvider(obj)) {
  obj.connect(agent)
}
```
