# 線程事件

`subscribeThreadEvents()` 用於觀察線程中本機待處理的輸入。它只提供佇列計數事件；負責串流輸出 Agent 結果的 [`subscribeToThread()`](/reference/agents/agent#subscribetothreadoptions) 則是另一個訂閱介面。

## `subscribeThreadEvents(scope, listener)` {/* #subscribethreadeventsscope-listener */}

訂閱指定資源及線程的事件。

```typescript
const scope = {
  resourceId: 'user-123',
  threadId: 'thread-abc',
}

const unsubscribe = agent.subscribeThreadEvents(scope, event => {
  if (event.type === 'queue-count-changed') {
    console.log(`${event.count} messages are pending`)
  }
})

// Later, when you no longer need updates:
unsubscribe()
```

當線程上有正在執行的工作，並呼叫 [`queueMessage()`](/reference/agents/agent#queuemessagemessage-options) 或 [`queueSignal()`](/reference/agents/agent#queuesignalsignal-options) 時，計數會變更。

訂閱時，監聽器會同步收到一次包含目前本機計數的初始事件；之後只會在計數變更時收到更新。傳回的取消訂閱函式可重複呼叫，亦不會取消已排隊的訊息。

計數只反映目前執行環境的狀態。使用同一執行環境及 PubSub 實例的其他 Session 或 Agent 提交的訊息亦會計入其中。

計數包括在本機 FIFO 佇列中等候的訊息，以及在取得或轉移租約期間尚未取消的訊息。取消、移交執行、轉送予其他擁有人或執行失敗時，計數會下降；模型完成生成並不會令計數下降。閒置時呼叫 `queueMessage()` 會立即移交訊息，不會形成可取消的待處理佇列項目。

計數只涵蓋 [`queueMessage()`](/reference/agents/agent#queuemessagemessage-options) 及 [`queueSignal()`](/reference/agents/agent#queuesignalsignal-options) 共用佇列中的項目，不包括等候送入正在執行工作的 Signal。

按擁有人限定觀察範圍時，會同時比對呼叫端 Agent、其本機執行環境、資源、線程及擁有人 ID。可使用 [`cancelQueuedMessages()`](/reference/agents/agent#cancelqueuedmessagesoptions) 取消指定的待處理輸入，或某個擁有人群組的輸入。

AgentController Session 訂閱後，即使尚未提交後續輸入，也會觀察共用線程的計數。`session.steer()` 會在傳送新輸入前中止目前的執行，但不會清除已排隊的後續輸入。清理 Session 時會停止觀察並取消尚未完成的本機準備工作，但已提交的訊息仍會留在 Agent 佇列中。

## `AgentThreadEvent` {/* #agentthreadevent */}

目前唯一會發出的事件類型是 `queue-count-changed`。

```typescript
type AgentThreadEvent = {
  type: 'queue-count-changed'
  count: number
}
```

`count` 是所觀察佇列中本機待處理訊息的數量。綜合線程狀態、個別訊息生命週期、執行及審批事件均不會作為公開線程事件發出。Mastra 日後可能將它們加入為獨立事件類型。
