# 觀察記憶

**引入版本：** `@mastra/memory@1.1.0`

觀察記憶（OM）是 Mastra 面向長上下文代理的記憶系統。**Observer** 追蹤對話並生成觀察紀錄；**Reflector** 將相關紀錄合併，並提煉貫穿對話的規律，對這些紀錄進行重組。兩者共同維護觀察紀錄。隨著對話增長，這份紀錄會取代原始訊息歷史。

## 用法 {/* #usage */}

```typescript title="src/mastra/agents/agent.ts"
import { Memory } from '@mastra/memory'
import { Agent } from '@mastra/core/agent'

export const agent = new Agent({
  id: 'my-agent',
  name: 'my-agent',
  instructions: 'You are a helpful assistant.',
  model: '__GATEWAY_OPENAI_MODEL_LUNA__',
  memory: new Memory({
    options: {
      observationalMemory: true,
    },
  }),
})
```

## 設定 {/* #configuration */}

`observationalMemory` 選項接受 `true`、設定物件或 `false`。設為 `true` 時，OM 會啟用自動模型選擇。傳入設定物件時，可以在頂層設定 `model`，也可以設定 `observation.model` 和／或 `reflection.model`。如果省略所有模型欄位，每個角色預設使用 `'auto'`。

Observer 的輸入支援多模態。OM 為 Observer 構建對話紀錄時，會保留 `[Image #1: screenshot.png]` 這樣的文字佔位符，並在可行時一併傳送底層圖像內容。單對話串觀察和多對話串批次觀察均如此。非圖像檔案只以佔位符呈現。

OM 使用快速的本地 token 估算來判斷是否達到閾值。文字由 `tokenx` 估算；對於圖像類輸入，則採用按供應商調整的啟發式規則，並在元資料不完整時使用確定性的備用規則。

      },

### 提取行為 {/* #extraction-behavior */}

- 提取的值儲存在該對話串 OM 元資料的 `om.extracted` 下。
- 內置提取器的值也會鏡像到兼容性元資料欄位 `currentTask`、`suggestedResponse` 和 `threadTitle`。
- `thread-title` 只有在啟用 `observation.threadTitle` 後才會更新對話串標題。
- `observation.extract` 在觀察期間運行；`reflection.extract` 在反思期間運行。
- 帶 schema 的提取器會追加一次結構化輸出請求。
- 無 schema 的提取器是直接在 Observer 或 Reflector 輸出中產生的內聯字串提取器。
- 動態提取器函式會在可用時收到運行時上下文，包括 `source`、`threadId`、`resourceId`、`mainAgent`、`memory` 和 `requestContext`。
- `WorkingMemoryExtractor` 使用常規提取器流程，通過現時 `Memory` 實例更新工作記憶。工作記憶帶有 JSON schema 時，它會執行結構化提取，並跳過 OM 元資料持久化，避免工作記憶內容在 OM 提取元資料中重複儲存。
- 設定 `workingMemory.schema` 後，`WorkingMemoryExtractor` 會在儲存每次更新前按該 schema 驗證。不匹配的更新會被跳過並報告為提取失敗，原有工作記憶保持不變。schema 不會作為結構化輸出約束傳送給模型，因此一次無效的工作記憶更新不會使其他提取器失敗。可選欄位中的 `null` 會被視為未提供。
- `observationalMemory.observation.manageWorkingMemory` 會添加 `WorkingMemoryExtractor`，並將 `workingMemory.agentManaged` 預設設為 `false`。啟用工作記憶時，還會將 `workingMemory.useStateSignals` 預設設為 `true`。
- 提取失敗會在 OM 標記資料中報告，不會捨棄其他成功提取的值。

### 共享 token 預算 {/* #shared-token-budget */}

啟用 `shareTokenBudget` 後，總預算為 `observation.messageTokens + reflection.observationTokens`，本例中即 100k。若觀察紀錄只使用 30k token，訊息最多可使用 70k；訊息較短時，觀察紀錄也有更多空間，直到觸發反思。使用共享預算時，必須關閉非同步緩衝。

```typescript title="src/mastra/agents/agent.ts"
import { Memory } from '@mastra/memory'
import { Agent } from '@mastra/core/agent'

export const agent = new Agent({
  id: 'my-agent',
  name: 'my-agent',
  instructions: 'You are a helpful assistant.',
  model: '__GATEWAY_OPENAI_MODEL_LUNA__',
  memory: new Memory({
    options: {
      observationalMemory: {
        shareTokenBudget: true,
        observation: {
          messageTokens: 20_000,
          bufferTokens: false,
        },
        reflection: {
          observationTokens: 80_000,
        },
      },
    },
  }),
})
```

### 非同步緩衝 {/* #async-buffering */}

預設情況下，非同步緩衝處於啟用狀態，設定如下：

- `observation.bufferTokens: 0.2`：每達到 `messageTokens` 的 20% 就緩衝一次。
- `observation.bufferActivation: 0.8`：啟用後保留閾值對應內容的 20%。
- `reflection.bufferActivation: 0.5`：觀察紀錄達到反思閾值的一半時，開始後台反思。

緩衝的 Observer 呼叫不會產生後續提示，啟用時也會清除已儲存的提示。關於閾值與 `blockAfter` 之間的行為，參見[後台緩衝跟不上時](#when-buffering-falls-behind)。

設定 `observation.bufferTokens: false` 可同時關閉觀察與反思的緩衝。兩者隨後都會在達到各自閾值時同步運行。

```typescript oxfmt:false
observationalMemory: {
  observation: {
    bufferTokens: false,
  },
}
```

已棄用的 `scope: 'resource'` 不支援非同步緩衝。

## 早期啟用 {/* #early-activation */}

預設情況下，訊息歷史達到 `observation.messageTokens` 時，緩衝的觀察紀錄會啟用。OM 也可以提前啟用它們，這對提示詞快取即將過期或代理切換模型供應商的情況有幫助。兩種情況下，下次請求都無法復用快取的提示詞，因此傳送經過壓縮的較短上下文不會增加額外成本。

- `activateAfterIdle`：對話串空閒達到指定時長後啟用。接受毫秒數（`300_000`）、時長字串（`'5m'`、`'1hr'`）、按供應商確定提示詞快取 TTL 的 `'auto'`，或按供應商指定 TTL 的物件（參見[按供應商設定空閒 TTL](#per-provider-idle-ttls)）。
- `activateOnProviderChange`：若下一步驟使用的 `provider/model` 與上一個代理步驟所用的不同，則啟用。預設為 `false`。

```typescript title="src/mastra/memory.ts"
import { Memory } from '@mastra/memory'

const memory = new Memory({
  options: {
    observationalMemory: {
      activateAfterIdle: 'auto',
      activateOnProviderChange: true,
    },
  },
})
```

頂層設定只適用於觀察。反思須通過嵌套的 `reflection` 設定單獨啟用：

```typescript title="src/mastra/memory.ts"
import { Memory } from '@mastra/memory'

const memory = new Memory({
  options: {
    observationalMemory: {
      activateAfterIdle: '5m',
      observation: {
        activateAfterIdle: false,
      },
      reflection: {
        activateAfterIdle: '10m',
        activateOnProviderChange: true,
      },
    },
  },
})
```

在此示例中，觀察忽略頂層空閒設定，而反思啟用空閒啟用和供應商變化時啟用。

### 自動空閒 TTL {/* #automatic-idle-ttls */}

設定 `activateAfterIdle: 'auto'` 後，Mastra 會根據現時模型供應商選擇空閒 TTL：

| 供應商 | 自動 TTL |
| - | - |
| Anthropic、OpenRouter、未知供應商、xAI | 5 分鐘 |
| DeepSeek | 1 小時 |
| Google Gemini | 24 小時 |
| Groq | 2 小時 |
| OpenAI，且 `providerOptions.openai.promptCacheRetention: "24h"` | 1 小時 |
| OpenAI，且 `providerOptions.openai.promptCacheRetention: "in_memory"` | 5 分鐘 |
| OpenAI `gpt-4*`、`gpt-5`、`gpt-5-*`，以及 `gpt-5.1` 至 `gpt-5.4`（含帶 `-` 後綴的變體） | 5 分鐘 |
| 其他 OpenAI 模型 | 1 小時 |

如需固定 TTL，請使用 `'5m'` 或 `300_000`。

### 按供應商設定空閒 TTL {/* #per-provider-idle-ttls */}

`'auto'` 無法識別為單條訊息設定的快取 TTL，例如 Anthropic 的 `cacheControl: { type: 'ephemeral', ttl: '1h' }`。它仍會使用該供應商預設的 5 分鐘 TTL，因此緩衝的觀察紀錄可能在 1 小時快取尚未失效時就啟用。若需按供應商指定 TTL，請傳入物件：

```typescript title="src/mastra/memory.ts"
import { Memory } from '@mastra/memory'

const memory = new Memory({
  options: {
    observationalMemory: {
      activateAfterIdle: { default: 'auto', anthropic: '1h' },
    },
  },
})
```

將 `anthropic` 條目設為與 `cacheControl.ttl` 相同的 TTL。Mastra 不會讀取單條訊息的快取設定，因此這兩個值需要手動保持一致。

物件按以下規則解析：

- 鍵為供應商名稱。Mastra 會取模型供應商 ID 中第一個 `.` 之前的部分，不區分大小寫地進行比較。因此 `anthropic` 同時匹配 `anthropic` 和 `anthropic.messages`。如果 Claude 由其他供應商提供，則使用該供應商的鍵，例如 `amazon-bedrock`。鍵不能包含 `.` 或 `/`。
- 每個值接受與單個 TTL 相同的形式：毫秒數、時長字串、`'auto'`，或用於關閉該供應商空閒啟用的 `false`。
- `default` 適用於未單獨指定鍵的所有供應商。如果沒有 `default`，這些供應商不會在空閒時啟用。
- `observation.activateAfterIdle` 和 `reflection.activateAfterIdle` 也接受相同的物件。`observation.activateAfterIdle` 物件會替換頂層值，不與其合併。

## 空閒時緩衝 {/* #buffer-on-idle */}

設定 `observation.bufferOnIdle: true` 後，代理輪次結束並進入空閒狀態時，系統會在後台緩衝觀察紀錄。這樣，短輪次無需等待下一輪或達到 `messageTokens` 閾值即可被觀察。

```typescript title="src/mastra/memory.ts"
import { Memory } from '@mastra/memory'

const memory = new Memory({
  options: {
    observationalMemory: {
      observation: {
        bufferOnIdle: true,
      },
    },
  },
})
```

`bufferOnIdle` 預設關閉，且獨立於 `bufferTokens`：`bufferTokens` 控制步驟執行期間的緩衝，`bufferOnIdle` 控制空閒輪次結束時的緩衝。

## 後台緩衝跟不上時 {/* #when-buffering-falls-behind */}

如果訊息到達速度超過 Observer 的緩衝速度，訊息歷史可能在緩衝片段準備好之前越過 `messageTokens`。在 `messageTokens` 與 `observation.blockAfter` 之間（後者預設值為 `1.2`，按預設閾值計算為 36,000 token），Mastra 會繼續在後台緩衝，並在後續步驟啟用片段，代理無需等待。

如果緩衝片段啟用後，待處理 token 數仍達到 `blockAfter`，例如較大的工具結果留下尚未覆蓋的尾部訊息，就會執行同步觀察。達到 `blockAfter` 時，啟用流程會先限時等待仍在生成的緩衝觀察紀錄；若等待超時，Mastra 會同步觀察剩餘訊息。遲到的觀察結果若對應訊息已被觀察，則會被捨棄。由空閒 TTL 或供應商變化觸發的啟用不會等待。

超過 `blockAfter` 後，啟用流程可能選擇更多片段，從而越過保留目標。緩衝啟用通常會至少保留一部分上下文（約 1,000 token 與設定的保留下限中的較小值）；但若單個片段覆蓋整個待處理窗口，它仍會啟用，並可能留下更少內容。

非同步緩衝的 Observer 呼叫不會生成後續提示，因為延遲生成的提示在啟用時可能已經過時。緩衝片段啟用後，已儲存的建議回復和現時任務都會被清除。

反思也以相同方式緩衝。觀察紀錄達到 `reflection.bufferActivation`（預設 `0.5`）所指定的 `reflection.observationTokens` 比例時，後台反思開始運行；若超過 `reflection.blockAfter`（預設 `1.2`）仍沒有可用的緩衝反思，則同步運行。

## 重試和失敗策略 {/* #retries-and-failure-policy */}

Observer 和 Reflector 的模型呼叫遇到暫時性供應商錯誤時會重試。每個階段都有兩項設定：

- `maxRetries`：首次模型呼叫後的重試次數，預設為 `8`。這是該階段唯一的重試設定；底層模型呼叫不會執行供應商級重試。
- `failurePolicy`：重試耗盡後的處理方式。`'abort'`（預設）使現時輪次失敗；`'continue'` 允許現時輪次繼續。

```typescript title="src/mastra/memory.ts"
import { Memory } from '@mastra/memory'

const memory = new Memory({
  options: {
    observationalMemory: {
      observation: {
        maxRetries: 8,
        failurePolicy: 'continue',
      },
      reflection: {
        maxRetries: 8,
        failurePolicy: 'continue',
      },
    },
  },
})
```

供應商故障通常會同時影響兩個階段。如果希望現時輪次在故障時繼續，應為兩個階段都設定此策略。

使用 `'continue'` 時，Mastra 通過 OM 診斷報告失敗，將失敗輸入保留到後續週期，並允許現時輪次繼續。系統不會推進觀察邊界或捨棄未觀察的訊息。Reflector 失敗時，已持久化的觀察紀錄仍會保留，並在下次達到閾值時重試反思。

該策略只處理同步運行期間 Observer 和 Reflector 的模型或供應商故障，包括達到 `blockAfter`、關閉非同步緩衝，以及資源作用域中的觀察。持久化、索引、轉換、鎖定、不變量和明確中止相關的失敗仍屬致命錯誤。

無論策略如何，後台緩衝失敗都不會中斷現時輪次。失敗會以 `om_buffering_failed` 報告，相關輸入仍待處理。如果待處理內容持續增長並達到 `blockAfter`，同步觀察就會應用 `failurePolicy`。

:::warning

`'continue'` 無法為長時間故障兜底。未觀察的訊息會一直待處理，並不斷累積在主代理的上下文中，直到達到模型的上下文上限。

:::

## 時間間隔標記 {/* #temporal-gap-markers */}

如果對話串中上一條訊息距新用戶訊息至少已過 10 分鐘，時間間隔標記會在新訊息前插入簡短提醒。預設關閉。

```typescript title="src/mastra/memory.ts"
import { Memory } from '@mastra/memory'

const memory = new Memory({
  options: {
    observationalMemory: {
      temporalMarkers: true,
    },
  },
})
```

標記會存入記憶，同時以臨時提醒事件形式發出，方便客戶端將其顯示為時間線提示。Observer 也能看到這些標記，因此觀察紀錄可以注明事件發生的時間，例如“用戶在間隔 2 天後詢問部署問題”。

## token 估算 {/* #token-estimates */}

OM 根據本地 token 估算決定何時進行觀察，而不是依據供應商的用量報告。文字使用 `tokenx` 估算；圖像採用按供應商調整的啟發式規則，圖像類 `file` 內容也遵循該規則。供應商實際計算的 token 數可能高於估算值，因此需要[上下文溢出恢復](/docs/memory/observational-memory#context-overflow-recovery)。

### token 數快取 {/* #token-count-cache */}

OM 會把估算值快取在訊息元資料中，避免每次檢查閾值時都重新計算相同內容：

- 每個內容部分的估算值儲存在 `part.providerMetadata.mastra` 中；只要快取版本和分詞器來源一致，就會復用。
- 只有字串內容、沒有分段內容的訊息使用訊息級快取。
- 每輪都會重新計算訊息和對話的額外開銷；只快取內容本身的估算值。
- `data-*` 和 `reasoning` 內容部分會被跳過，也不會快取。

### 為檔案提供自訂估算值 {/* #supplying-your-own-estimate-for-a-file */}

可以為 `image` 或 `file` 內容部分通過 `providerMetadata.mastra.tokenEstimate` 附加 token 估算值。計數器會直接使用該值：

```typescript
const filePart = {
  type: 'file',
  data: 'storage://bucket/large-report.pdf',
  mimeType: 'application/pdf',
  filename: 'large-report.pdf',
  providerMetadata: {
    mastra: {
      tokenEstimate: {
        v: 0,
        source: 'client',
        key: 'client',
        tokens: 100_000,
      },
    },
  },
}
```

- `v`：快取 schema 版本。設為 `0`。OM 不會讀取呼叫方提供的此欄位。
- `source`：必須是 `'client'`。這表示該條目具有權威性，不會被重新計算或覆蓋。
- `key`：設為 `'client'`。框架生成的條目會在此放置內容哈希；使用 `'client'` 可使估算值在多次寫入後保持穩定。
- `tokens`：要使用的 token 數，必須是有限的非負數。

只有 `image` 和 `file` 內容部分會採用自訂估算值。`text` 和 `tool-invocation` 內容部分始終會計數。

## 限制 Observer 重讀的內容 {/* #limiting-what-the-observer-re-reads */}

預設情況下，每批新訊息都會連同完整的觀察紀錄，以及先前的 `current-task` 和 `suggested-response` 值，一起作為上下文傳送給 Observer。紀錄變大時，可設定 `observation.previousObserverTokens` 限制其大小：

```typescript title="src/mastra/memory.ts"
import { Memory } from '@mastra/memory'

const memory = new Memory({
  options: {
    observationalMemory: {
      observation: {
        previousObserverTokens: 10_000,
      },
    },
  },
})
```

- `false`（預設）：傳送完整紀錄。
- 數字，例如 `2000`：保留最近約相應 token 數的觀察紀錄。
- `0`：不傳送先前的觀察紀錄。

如果有緩衝的反思尚待處理，其已覆蓋的觀察紀錄行會在截斷前由反思結果替換。

## 讓 Observer 管理工作記憶 {/* #let-the-observer-manage-working-memory */}

設定 `observation.manageWorkingMemory: true` 後，由 Observer 持續更新[工作記憶](/docs/memory/working-memory)，無需依賴主代理呼叫工作記憶工具。

```typescript title="src/mastra/memory.ts"
import { Memory } from '@mastra/memory'

const memory = new Memory({
  options: {
    workingMemory: {
      enabled: true,
    },
    observationalMemory: {
      observation: {
        manageWorkingMemory: true,
      },
    },
  },
})
```

這會添加 `WorkingMemoryExtractor`，並改變兩項工作記憶的預設值：

- `workingMemory.agentManaged` 預設為 `false`，因此主代理不再收到工作記憶工具和指令。如需保留，請設為 `true`。
- `workingMemory.useStateSignals` 預設為 `true`，將工作記憶從系統提示詞移至狀態信號中，使更新不致使提示詞快取失效。

## 掛鈎 {/* #hooks */}

`observationalMemory.hooks` 接受兩類掛鈎：

- **生命週期掛鈎**（`onObservationStart`、`onObservationEnd`、`onReflectionStart`、`onReflectionEnd`）用於遙測。它們會收到 `threadId`、`resourceId` 和 `trigger`；結束掛鈎還會收到模型呼叫的 `usage`、`providerMetadata` 和可能發生的 `error`。它們不會改變 OM 儲存的內容。
- **轉換掛鈎**（`beforeObservation`、`afterObservation`、`beforeReflection`、`afterReflection`）用於改變週期中流轉的資料。不傳回內容則原樣傳遞輸入，也可傳回替換值。

```typescript
const memory = new Memory({
  options: {
    observationalMemory: {
      hooks: {
        // Drop or redact messages before the Observer sees them.
        beforeObservation: ({ messages }) => ({
          messages: messages.filter(m => !isSensitive(m)),
        }),
        // Rewrite observations before they are persisted.
        afterObservation: ({ observations }) => ({
          observations: redact(observations),
        }),
        // Rewrite the text the Reflector condenses.
        beforeReflection: ({ observations }) => ({
          observations: stripInternalNotes(observations),
        }),
        afterReflection: async ({ observations, resourceId }) => {
          await syncToExternalStore(resourceId, observations)
        },
      },
    },
  },
})
```

所有路徑都會等待轉換掛鈎完成，包括手動 `observe()` 和 `reflect()`、輪次中的同步觀察，以及非同步緩衝。如果 `beforeObservation` 傳回空的 `messages` 陣列，就會跳過 Observer 呼叫，但這些訊息仍標記為已觀察。若轉換掛鈎拋出錯誤，週期會在提交轉換後的文字前失敗；已運行的提取器回調和其他副作用不會回滾。

`afterObservation` 和 `afterReflection` 只替換觀察或反思文字，不會修改對話串元資料中的結構化提取值；反思提取也在 `afterReflection` 之前運行。不要把後置掛鈎當作整個週期的資料脫敏邊界。

掛鈎會收到 `threadId` 和 `resourceId`，因此也可通過 `memory.updateWorkingMemory()` 更新工作記憶。這些更新與 OM 提交不是原子操作。

若不希望 Observer 讀取技能指令，請使用 [`skillResultRedactor`](#skillresultredactor)。

## 遷移現有對話串 {/* #migrating-existing-threads */}

無需遷移。對話串首次超過 `observation.messageTokens` 時，OM 會讀取並觀察現有訊息，一並處理積壓內容。在已棄用的資源作用域下，同一資源各對話串中所有未觀察的訊息會一起處理；對話串較多的用戶可能需要等待較長時間。

## 流式資料部分 {/* #streaming-data-parts */}

觀察記憶會在代理執行期間發出帶類型的資料部分，客戶端可據此實時展示 UI 反饋。這些資料與代理響應一起流式傳輸。

### 讀取提取器結果 {/* #read-extractor-results */}

兩個完成事件的 `data` 負載都包含提取器輸出。提取器欄位如下：

```typescript
interface DataOmObservationEndPart {
  type: 'data-om-observation-end'
  data: {
    /** Whether the completed work was an observation or reflection */
    operationType: 'observation' | 'reflection'
    /** Values extracted during this OM operation, keyed by extractor slug */
    extractedValues?: Record<string, unknown>
    /** Extractor failures from this OM operation. Successful extractor values are still included */
    extractionFailures?: Array<{ slug: string; error: string }>
    // ...other fields documented in the tables below
  }
}
```

兩個提取器欄位均可選。完成事件可能包含提取值、失敗資訊、兩者都有，或兩者都沒有。`data-om-observation-end` 報告同步完成；`data-om-buffering-end` 報告已完成但尚待啟用的後台緩衝工作，此時提取器元資料已經持久化。`DataOmBufferingEndPart` 帶有相同的提取器欄位，這兩種類型都從 `@mastra/memory/processors` 導出。客戶端示例參見[從流中讀取提取值](/docs/memory/observational-memory#read-extracted-values-from-a-stream)。

### `data-om-status` {/* #data-om-status */}

每個代理循環步驟在模型生成前發出一次。它提供現時記憶狀態的快照，包括兩個上下文窗口的 token 用量，以及非同步緩衝內容的狀態。

```typescript
interface DataOmStatusPart {
  type: 'data-om-status'
  data: {
    windows: {
      active: {
        /** Unobserved message tokens and the threshold that triggers observation */
        messages: { tokens: number; threshold: number }
        /** Observation tokens and the threshold that triggers reflection */
        observations: { tokens: number; threshold: number }
      }
      buffered: {
        observations: {
          /** Number of buffered chunks staged for activation */
          chunks: number
          /** Total message tokens across all buffered chunks */
          messageTokens: number
          /** Projected message tokens that would be removed if activation happened now (based on bufferActivation ratio and chunk boundaries) */
          projectedMessageRemoval: number
          /** Observation tokens that will be added on activation */
          observationTokens: number
          /** idle: no buffering in progress. running: background observer is working. complete: chunks are ready for activation. */
          status: 'idle' | 'running' | 'complete'
        }
        reflection: {
          /** Observation tokens that were fed into the reflector (pre-compression size) */
          inputObservationTokens: number
          /** Observation tokens the reflection will produce on activation (post-compression size) */
          observationTokens: number
          /** idle: no reflection buffered. running: background reflector is working. complete: reflection is ready for activation. */
          status: 'idle' | 'running' | 'complete'
        }
      }
    }
    recordId: string
    threadId: string
    stepNumber: number
    /** Increments each time the Reflector creates a new generation */
    generationCount: number
  }
}
```

`buffered.reflection.inputObservationTokens` 表示傳送給 Reflector 的觀察紀錄大小。`buffered.reflection.observationTokens` 表示壓縮結果的大小，即反思啟用後將取代這些觀察紀錄的內容大小。客戶端可以用這兩個值展示壓縮率。

客戶端可以根據原始值計算百分比和啟用後的估算值：

```typescript
// Message window usage %
const msgPercent = status.windows.active.messages.tokens / status.windows.active.messages.threshold

// Observation window usage %
const obsPercent =
  status.windows.active.observations.tokens / status.windows.active.observations.threshold

// Projected message tokens after buffered observations activate
// Uses projectedMessageRemoval which accounts for bufferActivation ratio and chunk boundaries
const postActivation =
  status.windows.active.messages.tokens -
  status.windows.buffered.observations.projectedMessageRemoval

// Reflection compression ratio (when buffered reflection exists)
const { inputObservationTokens, observationTokens } = status.windows.buffered.reflection
if (inputObservationTokens > 0) {
  const compressionRatio = observationTokens / inputObservationTokens
}
```

## 獨立使用 {/* #standalone-usage */}

大多數應用應使用 `Memory` 類。若要進行基準測試、實驗，或必須讓 OM 按特定順序與[護欄](/docs/agents/guardrails)等處理器一起運行，則可直接使用 `ObservationalMemory` 引擎。

將引擎包裝在 `ObservationalMemoryProcessor` 中。它需要 `Memory` 實例來加載和持久化訊息。儲存適配器上的 `stores.memory` 類型是可選的，因此需要斷言或檢查它：

```typescript title="src/mastra/agents/agent.ts"
import { Agent } from '@mastra/core/agent'
import { LibSQLStore } from '@mastra/libsql'
import { Memory } from '@mastra/memory'
import { ObservationalMemory, ObservationalMemoryProcessor } from '@mastra/memory/processors'

const storage = new LibSQLStore({
  id: 'my-storage',
  url: 'file:./memory.db',
})

const memory = new Memory({ storage })

const om = new ObservationalMemory({
  storage: storage.stores.memory!,
  memory,
  model: '__GATEWAY_GOOGLE_MODEL_FLASH__',
  observation: {
    messageTokens: 20_000,
  },
  reflection: {
    observationTokens: 60_000,
  },
})

const omProcessor = new ObservationalMemoryProcessor(om, memory)

export const agent = new Agent({
  id: 'my-agent',
  name: 'My Agent',
  instructions: 'You are a helpful assistant.',
  model: '__GATEWAY_OPENAI_MODEL_LUNA__',
  inputProcessors: [omProcessor],
  outputProcessors: [omProcessor],
})
```

引擎接受與 `observationalMemory` 設定相同的選項，另加 `storage`、`onDebugEvent` 和 `obscureThreadIds`。參見[獨立設定](#standalone-config)。

`om.observe()` 只在待處理 token 達到閾值時執行觀察。傳入 `force: true` 可立即觀察待處理訊息；跳過閾值只對本次呼叫有效。

```typescript
const result = await om.observe({ threadId, resourceId, force: true })
// result.observed is true when pending messages were observed
```

代理無需通過此方式從上下文窗口錯誤中恢復；[上下文溢出恢復](/docs/memory/observational-memory#context-overflow-recovery)會處理這種情況。

## 回憶工具 {/* #recall-tool */}

`retrieval` 為真值時，Mastra 會註冊 `recall` 工具，用於分頁瀏覽觀察紀錄組所對應的原始訊息。在預設資源作用域下，該工具可列出對話串（`mode: "threads"`），並通過 `threadId` 瀏覽其他對話串；它也支援跨對話串搜尋。設定 `retrieval: { vector: true }` 可啟用語義搜尋（`mode: "search"`）；設定 `scope: 'thread'` 則將工具限制在現時對話串。該工具會自動添加到代理。

啟用檢索後，OM 還會注入說明，指導代理何時核對細節、如何搜尋和翻頁，以及何時讀取原始訊息。這些說明從首輪開始就會提供，包括只讀運行，並且只描述已設定的模式。反思後的紀錄組會標為 `_kind: reflection_`，提醒代理將其視為有資訊損失的摘要。可通過 `retrieval: { instructions: '...' }` 在內置說明後追加自訂指引。

### 觀察紀錄分頁 {/* #observation-pages */}

設定向量搜尋後，`mode: "observations"` 可讀取搜尋命中附近的原始觀察紀錄組，包括已被反思壓縮掉的組和尚未啟用的緩衝組。請原樣複製命中結果中的 `groupId`；在資源作用域下還需複製其 `threadId`：

```json
{
  "mode": "observations",
  "threadId": "source-thread-id",
  "groupId": "group-id-from-search",
  "direction": "after",
  "limit": 5
}
```

設定 `direction: "before"` 可向前翻頁；省略 `direction` 則會包含錨定組本身。分頁結果和後續呼叫會傳回 `{ results, count, hasMore }`，並提示是否存在尚未觀察的較新訊息。

### 搜尋結果 {/* #search-results */}

搜尋結果按日期列出，共用 2,000 token 的文字限額。因此，較長的紀錄組會從最符合查詢的行開始縮短。已在代理上下文中的結果會傳回簡短引用，排名較低的命中則可利用騰出的空間。`limit` 統計的是摘錄而非引用，因此 `count` 可能大於 `limit`。

### 儲存要求 {/* #storage-requirements */}

搜尋結果中的組 ID 包含承載它的紀錄（`groupId@recordId`），因此翻頁時只需讀取單條紀錄。變更之前已建立索引的組仍可使用，但翻頁時需要掃描對話串的觀察歷史。翻頁要求儲存適配器支援觀察歷史篩選，因此應與 `@mastra/memory` 一同升級。Convex 用戶還需重新部署 Mastra 服務端函式。

### ModelByInputTokens {/* #modelbyinputtokens */}

`ModelByInputTokens` 根據輸入 token 數選擇模型。它會選擇能覆蓋實際輸入大小的最小閾值對應的模型。

#### 構造函式 {/* #constructor */}

```typescript
new ModelByInputTokens(config)
```

`config` 是一個物件，其 `upTo` 鍵將 token 閾值（數字）映射到目標模型。每個層級都必須指定具體模型 ID，不能使用 `"auto"`。

#### 例子 {/* #example */}

```typescript
import { ModelByInputTokens } from '@mastra/memory'

const selector = new ModelByInputTokens({
  upTo: {
    10_000: 'google/gemini-2.5-flash', // Fast for small inputs
    40_000: '__GATEWAY_OPENAI_MODEL_LUNA__', // Stronger for medium inputs
    1_000_000: '__GATEWAY_OPENAI_MODEL__', // Most capable for large inputs
  },
})
```

#### 行為 {/* #behavior */}

- 系統會在內部排序閾值，因此設定物件中的順序無關緊要。
- `inputTokens ≤ smallest threshold` → 使用該閾值對應的模型。
- `inputTokens > largest threshold` → `resolve()` 拋出錯誤。如果發生在 OM 的 Observer 或 Reflector 運行期間，OM 會通過 TripWire 中止，因此呼叫方收到的是空的 `text` 結果或流式 `tripwire`，而不是正常的代理回復。
- OM 計算 Observer 或 Reflector 呼叫的輸入 token 數，並直接確定匹配的模型層級。

### skillResultRedactor {/* #skillresultredactor */}

`skillResultRedactor` 會創建一個 `beforeObservation` 轉換掛鈎，在 Observer 模型讀取內置 Agent Skills 工具（`skill`、`skill_search` 和 `skill_read`）的結果前將其遮蓋。每個結果會替換成佔位符，但工具呼叫仍會保留。因此 Observer 仍能紀錄使用了哪個技能、傳入了哪些參數，而不會接觸技能正文。

```typescript
import { Memory } from '@mastra/memory'
import { skillResultRedactor } from '@mastra/memory/hooks'

const memory = new Memory({
  options: {
    observationalMemory: {
      model: '__GATEWAY_GOOGLE_MODEL_FLASH__',
      hooks: {
        beforeObservation: skillResultRedactor(),
      },
    },
  },
})
```

傳入 `toolNames` 可遮蓋另一組工具的結果。若要與自訂轉換組合，請串聯兩個掛鈎的輸出，並等待每個掛鈎完成：

```typescript oxfmt:false
const dropSkillResults = skillResultRedactor()

hooks: {
  beforeObservation: async input => {
    const messages = (await dropSkillResults(input))?.messages ?? input.messages
    return { messages: messages.filter(m => m.role !== 'signal') }
  },
}
```

`(input: { messages: MastraDBMessage[] } & ObserveHookContext) => { messages: MastraDBMessage[] } | undefined`

掛鈎傳回的訊息中，匹配的工具結果會被佔位符替換。如果沒有訊息匹配，則傳回 `undefined`，負載會原樣傳遞。工具呼叫、參數及其他所有訊息保持不變。
