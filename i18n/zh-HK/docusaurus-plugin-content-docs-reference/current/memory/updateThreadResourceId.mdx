# Memory.updateThreadResourceId()

`.updateThreadResourceId()` 透過重新指定現有對話串的 `resourceId`，將其擁有權轉移至另一資源。它會更新對話串及其所有相關訊息，使它們歸屬新資源，同時保留對話串原有的 `createdAt` 時間戳。此方法適用於將私人對話串移入共用 Workspace 等情況。

## 使用例子 {/* #usage-example */}

```typescript
import { Memory } from '@mastra/memory'
import { LibSQLStore } from '@mastra/libsql'

const memory = new Memory({
  storage: new LibSQLStore({ id: 'memory-store', url: 'file:./memory.db' }),
})

const thread = await memory.updateThreadResourceId({
  threadId: 'thread-123',
  resourceId: 'new-resource-456',
})
```

## 行為 {/* #behavior */}

- 對話串的 `resourceId` 會重新指定給新資源，其所有訊息亦會更新為參照新資源。
- 保留對話串原有的 `createdAt` 時間戳，並更新 `updatedAt` 時間戳。
- 如對話串已屬於目標資源，此方法不會更新資料，而會傳回現有對話串。
- 如對話串不存在，此方法會拋出錯誤。

## 安全性 {/* #security */}

轉移對話串擁有權會改變其所屬資源，並繞過一般的逐資源擁有權檢查。HTTP 端點（`POST /memory/threads/:threadId/transfer`）只供不受資源範圍限制的特權呼叫者使用。已解析出資源範圍的請求會被拒絕；若已設定 `server.auth` 但沒有 FGA Provider，此端點亦會拒絕沒有資源範圍的請求，不會預設其具有特權。請在可信任的服務環境執行轉移，避免直接向終端用戶開放。

與所有 Memory 操作（例如刪除對話串、列出訊息、寫入工作記憶）一樣，若伺服器完全沒有設定驗證，此端點亦不會驗證身分。向不可信任的呼叫者開放 Memory API 前，請設定 `server.auth`；如需按資源實施存取控制，亦須設定 FGA Provider。
