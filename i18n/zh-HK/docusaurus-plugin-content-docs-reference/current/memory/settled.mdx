# 內存.settled()

這`.settled()`方法解決一旦後台工作`Memory`實例啟動已完成。Agent運行返回後，一些記憶體工作仍在繼續：

* 觀察記憶體週期（緩衝觀察和反射，包括它們產生的嵌套Agent運行）
* 向量清理開始於`deleteThread()` and `deleteMessages()`

在關閉您擁有的儲存連線之前等待此方法。如果沒有它，後台語句可以針對關閉的連線運行。當其他執行緒仍在使用儲存時，作用域呼叫可以返回，因此調用`settled()` without a scope before closing shared storage.

該方法是在內存基類上聲明的，因此它也可以在`MastraMemory` instance returned by `agent.getMemory()`. The `scope` parameter is only on `Memory` from `@mastra/memory`.

## 使用範例 {/* #usage-example */}

```typescript
await agent.generate('Hello', {
  memory: { thread: 'thread-123', resource: 'user-456' },
})

await memory.settled()
await store.close()
```

## 等待一場對話 {/* #wait-for-one-conversation */}

在繁忙的伺服器上，等待所有工作可能需要很長時間，因為其他執行緒不斷開始新工作。傳遞一個範圍來等待更少。當觀察記憶體使用線程作用域時，下面的呼叫等待`thread-123` only. When it uses resource scope, it waits for every thread under `user-456`:

```typescript
await memory.settled({ threadId: 'thread-123', resourceId: 'user-456' })
```

## 擴充使用範例 {/* #extended-usage-example */}

測試套件和短期進程是最常見需要此功能的地方，因為它們在運行完成後立即關閉儲存。

```typescript title="src/test-memory.ts"
import { Memory } from '@mastra/memory'
import { PostgresStore } from '@mastra/pg'

const store = new PostgresStore({ connectionString })
const memory = new Memory({ storage: store })

// ... run your agent ...

// Wait for observational memory and vector cleanup to finish before closing.
await memory.settled()
await store.close()
```

<Callout type="note">
  `settled()`加入您呼叫時已開始的工作，以及任何
  工作排隊的工作。這並不妨礙之後新工作的開始，
  因此，一旦您關心的Agent商運行返回，請致電它。
</Callout>
