# Mastra.addDynamicWorkflows()

:::測試版

在 API 穩定之前，可能會在沒有重大版本更新的情況下發生重大變更。

:::

這`.addDynamicWorkflows()` method adds a bundle of dynamic workflow definitions that may reference each other. The typical case is a root workflow plus helper workflows it nests, where none of the definitions exist yet.

整個捆綁包都經過預先驗證。然後，成員按依賴順序註冊，因此助手始終位於嵌套它的Workflow之前。

[`addDynamicWorkflow()`](/reference/core/addDynamicWorkflow)是單一成員的情況。

## 使用範例 {/* #usage-example */}

```typescript
await mastra.addDynamicWorkflows([
  helperDefinition, // nested by the root — order in the array doesn't matter
  rootDefinition, // graph contains { type: 'workflow', workflowId: helperDefinition.id }
])
```

## 退貨 {/* #returns */}

一旦每個成員都經過驗證、註冊和持久化，承諾就會解決。

## 行為 {/* #behavior */}

* 引用根據實例的註冊表並結合捆綁包自己的 ID 進行解析，因此根可以嵌套在同一呼叫中引入的幫助程式。註冊順序是從依賴圖匯出的，而不是陣列順序。
* 被拒絕的捆綁包不會註冊任何內容。在任何內容發生變異之前，都會偵測到重複的 ID、無效成員和依賴循環，如果註冊或持久性中途失敗，記憶體中的註冊表將恢復到其先前的狀態。
* 儲存寫入最後發生。中間捆綁包中的儲存級故障可能會留下一些寫入的行，但註冊表仍會回滾，並且孤立的行在下次啟動之前處於惰性狀態。
