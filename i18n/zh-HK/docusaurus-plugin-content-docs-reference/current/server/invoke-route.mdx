# invokeRoute()

`invokeRoute()` 函式在同一程序內以呼叫方的用戶身份執行伺服器路由，並傳回經 HTTP 呼叫該路由時會收到的結果。請求上下文須已通過 Mastra 伺服器的身份驗證。函式會執行與該路由在各適配器上的 HTTP 端點相同的檢查，包括身份驗證 Provider 的 `authorize`、`authorizeUser` 和 `rules`、結構驗證、RBAC 權限檢查，以及細粒度授權（FGA）。

使用它可透過其他渠道（例如 MCP Tool）提供路由功能，無須經由 HTTP 伺服器代理呼叫，同時避免兩條呼叫路徑的行為逐漸出現偏差。

## 使用範例 {/* #usage-example */}

```typescript title="src/mastra/tools/metric-aggregate.ts"
import { Mastra } from '@mastra/core/mastra'
import { RequestContext } from '@mastra/core/request-context'
import { createTool } from '@mastra/core/tools'
import { GET_METRIC_AGGREGATE } from '@mastra/server/handlers/observability'
import { invokeRoute } from '@mastra/server/server-adapter'
import { z } from 'zod'

export const agentRunCount = createTool({
  id: 'agentRunCount',
  description: 'Counts agent runs',
  inputSchema: z.object({}),
  execute: async (_input, { mastra, requestContext = new RequestContext() }) => {
    if (!(mastra instanceof Mastra)) throw new Error('agentRunCount must run inside Mastra')

    const { status, body } = await invokeRoute(GET_METRIC_AGGREGATE, {
      mastra,
      requestContext,
      body: { name: ['mastra_agent_duration_ms'], aggregation: 'count' },
    })
    if (status !== 200) throw new Error(`Metric aggregate failed with status ${status}`)
    return body
  },
})
```

## 行為 {/* #behavior */}

* **不會再次執行身份驗證。** 如已設定伺服器或 Studio 的身份驗證，請求上下文必須已包含 Mastra 伺服器驗證機制識別出的用戶。否則，`invokeRoute()` 會直接傳回 `401`，不會執行處理程式。經 Mastra 伺服器適配器送到 MCP Tool 的請求會附帶這個上下文。
* **授權掛鉤會收到 HTTP 路徑。** `authorize()` 和 `rules` 會收到路由的 HTTP 方法及路徑。該路徑帶有伺服器的 `apiPrefix`（預設為 `/api`），並已填入路徑參數。`authorize()` 不會收到個別適配器專用的請求上下文。
* **只支援 JSON 路由。** 如路由使用其他 `responseType`，例如串流路由或 MCP 傳輸路由，`invokeRoute()` 便會拋出錯誤。
* **處理程式不會收到 HTTP 專用參數。** 處理程式會收到經解析的參數，以及 `mastra`、`requestContext` 和 `abortSignal`。如路由需要讀取 `request`、`registeredTools`、`taskStore` 或 `routePrefix`，便不適合用這個函式呼叫。

## 與 `dispatchRoute()` 的分別 {/* #differences-from-dispatchroute */}

[`dispatchRoute()`](/reference/server/dispatch-route) 對所有路由（包括串流路由）都會執行相同的檢查，兩者有以下分別：

* 如已設定身份驗證，`invokeRoute()` 必須有經驗證的用戶身份才可執行路由。`dispatchRoute()` 容許沒有用戶身份的呼叫方存取在驗證設定中列為公開的路徑。
* `invokeRoute()` 用伺服器的 `apiPrefix` 組成傳入 `authorize()` 和 `rules` 的路徑。`dispatchRoute()` 則使用提供該路由的伺服器適配器的前綴。
* `invokeRoute()` 與 HTTP 適配器一樣，容許請求內容中的欄位覆蓋同名路徑參數。`dispatchRoute()` 則優先使用路徑參數。
* `invokeRoute()` 傳回 `{ status, body }`。`dispatchRoute()` 傳回處理程式的原始結果，如檢查失敗則傳回狀態碼和錯誤回應內容。
