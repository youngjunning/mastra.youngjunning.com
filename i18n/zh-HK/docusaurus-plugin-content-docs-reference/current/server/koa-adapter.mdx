# Koa 轉接器

這`@mastra/koa`軟體包提供了一個伺服器適配器，用於運行 Mastra[相思木](https://koajs.com)。有關一般適配器概念（建構函數選項、初始化流程等），請參閱[伺服器適配器](/docs/server/server-adapters).

## 安裝 {/* #installation */}

安裝 Koa 轉接器和 Koa 框架：

```bash npm2yarn
npm install @mastra/koa@latest koa koa-bodyparser
```

## 使用範例 {/* #usage-example */}

```typescript title="server.ts"
import Koa from 'koa'
import bodyParser from 'koa-bodyparser'
import { MastraServer } from '@mastra/koa'
import { mastra } from './mastra'

const app = new Koa()
app.use(bodyParser())

const server = new MastraServer({ app, mastra })

await server.init()

app.listen(3000, () => {
  console.log('Server running on http://localhost:3000')
})
```

`init()`不會啟動 Mastra 的後台工作人員。運行[scheduled workflows](/docs/workflows/scheduled-workflows), agent schedules, or event listeners, call `await mastra.startWorkers()` after the server starts listening. See [Start background workers](/docs/server/server-adapters#start-background-workers).

## 錯誤處理 {/* #error-handling */}

Koa 適配器遵循 Koa 的標準錯誤處理模式，透過 Koa 的中間件鏈從路由處理程序向上傳播錯誤。您可以使用常規的 Koa 錯誤處理中間件：

```typescript title="server.ts"
const app = new Koa()
app.use(bodyParser())

// Your error middleware catches errors from Mastra route handlers
app.use(async (ctx, next) => {
  try {
    await next()
  } catch (err) {
    ctx.status = err.status || 500
    ctx.body = { error: err.message }
    // Log, report to Sentry, etc.
  }
})

const server = new MastraServer({ app, mastra })
await server.init()
```

這[`server.onError`](/reference/configuration#serveronerror) hook is also supported. When configured, it's called before the error propagates to middleware, and its response is used directly:

```typescript title="src/mastra/index.ts"
import { Mastra } from '@mastra/core'

const mastra = new Mastra({
  server: {
    onError: (err, c) => {
      console.error('Unhandled error:', err)
      return c.json({ error: err.message }, 500)
    },
  },
})
```

什麼時候`init()` is used, a global error-handling middleware is also registered as a safety net. Errors that reach this middleware are emitted via `ctx.app.emit('error', err, ctx)` following the standard Koa convention. Client errors (4xx) and `501` errors already logged by the route handler are only emitted as `error` events when you register your own `error` listener; otherwise they go to `errorMonitor` listeners only.

## 保護原始路由 {/* #protecting-raw-routes */}

當您需要 Mastra 管理的身份驗證和路由元資料時，例如`requiresAuth`, prefer [`registerApiRoute()`](/reference/server/register-api-route). For raw Koa routes mounted directly on the app, use `createAuthMiddleware()`:

```typescript title="server.ts"
import Koa from 'koa'
import { createAuthMiddleware, MastraServer } from '@mastra/koa'
import { mastra } from './mastra'

const app = new Koa()
const server = new MastraServer({ app, mastra })

await server.init()

app.use(createAuthMiddleware({ mastra }))
app.use(async ctx => {
  if (ctx.path !== '/custom/protected') return

  const user = ctx.state.requestContext.get('user')
  ctx.body = { user }
})
```

## 手動初始化 {/* #manual-initialization */}

對於自訂中間件排序，請單獨呼叫每個方法，而不是`init()`. See [manual initialization](/docs/server/server-adapters#manual-initialization) for details.
