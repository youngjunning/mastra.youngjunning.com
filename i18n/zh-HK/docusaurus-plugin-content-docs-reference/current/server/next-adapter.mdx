# Next.js 適配器

`@mastra/next` 套件把 Mastra 掛載至 Next.js App Router 應用程式。一般概念請參閱[伺服器適配器](/docs/server/server-adapters)。

## 安裝 {/* #installation */}

安裝 Next.js 適配器及其 Hono 對等相依性：

```bash npm2yarn
npm install @mastra/next@latest hono
```

## 使用範例 {/* #usage-example */}

在涵蓋所有子路徑的 App Router 路由中掛載適配器：

```typescript title="app/api/[...mastra]/route.ts"
import { createNextRouteHandler } from '@mastra/next'
import { mastra } from '@/mastra'

export const { GET, POST, PUT, DELETE, PATCH, OPTIONS, HEAD } = createNextRouteHandler({
  mastra,
})
```

`prefix` 預設為 `/api`，必須與 catch-all 路由的掛載路徑相符。例如，掛載於 `app/api/mastra/[...mastra]/route.ts` 時，應使用 `createNextRouteHandler({ mastra, prefix: '/api/mastra' })`。

## 簽名 {/* #signature */}

```typescript
function createNextRouteHandler(options: NextRouteHandlerOptions): NextRouteHandlers
```

## 傳回值 {/* #return-value */}

返回一個`NextRouteHandlers` object with `GET`, `POST`, `PUT`, `DELETE`, `PATCH`, `OPTIONS`， 和`HEAD`特性。每個屬性都是具有以下簽名的處理程序：

```typescript
(request: Request) => Response | Promise<Response>
```

## Serverless 部署與延遲初始化 {/* #serverless-deployments--lazy-initialization */}

適配器先同步匯出路由處理函式，在首個請求到達時才建立底層 Hono 應用程式及 `MastraServer`。初始化後的應用程式會供同一程序的後續請求重用，因此 serverless 執行環境毋須在頂層進行非同步初始化。

A2A 端點使用記憶體任務儲存。任務狀態只在程序存活期間保留，不會在不同的 serverless 實例之間共用。

## 請求主體大小限制 {/* #body-size-limit */}

請求主體大小預設上限為 4.5 MB。超出上限的請求會收到 `{ error: 'Request body too large' }`。

設定 `server.bodySizeLimit` 即可調整 `Mastra` 實例的請求主體大小上限。

## 中介軟體 {/* #middleware */}

透過 `server.middleware` 或 `setServerMiddleware()` 設定的中介軟件會經過適配器中以 Hono 為基礎的伺服器，但標記為 `requiresAuth: false` 等框架公開路由除外。詳見[伺服器中介軟件](/docs/server/middleware)。
