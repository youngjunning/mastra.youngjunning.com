# 快速適配器

這`@mastra/express`軟體包提供了一個伺服器適配器，用於運行 Mastra[表達](https://expressjs.com)。有關一般適配器概念（建構函數選項、初始化流程等），請參閱[伺服器適配器](/docs/server/server-adapters).

## 安裝 {/* #installation */}

安裝 Express 轉接器和 Express 框架：

```bash npm2yarn
npm install @mastra/express@latest express
```

## 使用範例 {/* #usage-example */}

```typescript title="server.ts"
import express from 'express'
import { MastraServer } from '@mastra/express'
import { mastra } from './mastra'

const app = express()
app.use(express.json()) // Required for body parsing

const server = new MastraServer({ app, mastra })
await server.init()

app.listen(4111, () => {
  console.log('Server running on port 4111')
})
```

快遞要求`express.json()` middleware for JSON body parsing. Add it before creating the `MastraServer`. `init()` doesn't start Mastra's background workers. To run [scheduled workflows](/docs/workflows/scheduled-workflows), agent schedules, or event listeners, call `await mastra.startWorkers()` after the server starts listening. See [啟動後台工作者](/docs/server/server-adapters#start-background-workers).

## 與霍諾的區別 {/* #differences-from-hono */}

|方面|快遞|霍諾 |
| - | - | - |
|正文解析|需要`express.json()` | Handled by framework |
| Context storage | `res.locals` | `c.get()` / `c.set()` |
| Middleware signature | `(req, res, next)` | `(c, next)` |
| Streaming | `res.write()` / `res.end()` | `stream()`幫手|
|中止訊號|建立自`res.on('close')`，僅當回應未完成時才中止 |`c.req.raw.signal` |

## 新增自訂路線 {/* #adding-custom-routes */}

直接將路線新增至 Express 應用程式：

```typescript title="server.ts"
const app = express()
app.use(express.json())

const server = new MastraServer({ app, mastra })

// Before init - runs before Mastra middleware
app.get('/early-health', (req, res) => res.json({ status: 'ok' }))

await server.init()

// After init - has access to Mastra context
app.get('/custom', (req, res) => {
  const mastraInstance = res.locals.mastra
  res.json({ agents: Object.keys(mastraInstance.listAgents()) })
})

app.listen(4111)
```

：：：提示

之前新增的路線`init()` run without Mastra context. Add routes after `init()` to access the Mastra instance and request context.

:::

當您需要 Mastra 管理的身份驗證和路由元資料時，例如`requiresAuth`, prefer [`registerApiRoute()`](/reference/server/register-api-route). For raw Express routes mounted directly on `app`, use `createAuthMiddleware()`:

```typescript title="server.ts"
import express from 'express'
import { createAuthMiddleware, MastraServer } from '@mastra/express'
import { mastra } from './mastra'

const app = express()
app.use(express.json())

const server = new MastraServer({ app, mastra })
await server.init()

app.get('/custom/protected', createAuthMiddleware({ mastra }), (req, res) => {
  const user = res.locals.requestContext?.get('mastra__user')
  if (!user) {
    return res.status(401).json({ error: 'Unauthorized' })
  }
  res.json({ user })
})

app.get('/custom/public', createAuthMiddleware({ mastra, requiresAuth: false }), (req, res) => {
  res.json({ ok: true })
})
```

`createAuthMiddleware()`當 Mastra 伺服器沒有身份驗證時，請呼叫下一個處理程序而不進行身份驗證`auth` config, or when the route matches a public pattern. Public patterns include the built-in defaults (`/api` and `/api/auth/*`) and any `auth.public` patterns you configure. In those cases `mastra__user` isn't set, so protected handlers should reject requests without it, as the example above does.

## 存取上下文 {/* #accessing-context */}

在 Express 中介軟體和路由中，透過以下方式存取 Mastra 上下文`res.locals`:

```typescript
app.get('/custom', (req, res) => {
  const mastra = res.locals.mastra
  const requestContext = res.locals.requestContext
  const abortSignal = res.locals.abortSignal

  const agent = mastra.getAgent('myAgent')
  res.json({ agent: agent.name })
})
```

可用屬性`res.locals`:

|關鍵|描述 |
| - | - |
|`mastra` | Mastra instance |
| `requestContext` | Request context map |
| `abortSignal` | Request cancellation signal |
| `registeredTools` | Tools registered with the adapter |
| `taskStore` | Task store for A2A operations |
| `customRouteAuthConfig` | Per-route auth overrides |

配置身份驗證後，使用以下命令讀取經過身份驗證的用戶`res.locals.requestContext.get('mastra__user')`. Clients can't set the reserved `mastra__user` key through the `requestContext` query parameter or body. On raw Express routes, the value is only populated after [`createAuthMiddleware()`](#adding-custom-routes) runs, so apply it before trusting the user. Don't rely on the legacy `user` key for authorization. A client can supply it on routes without auth middleware.

## 新增中介軟體 {/* #adding-middleware */}

之前添加 Express 中介軟體`init()` to run it on every request. Mastra context isn't available at that point:

```typescript title="server.ts"
const app = express()
app.use(express.json())

// Runs on every request, before Mastra context exists
app.use((req, res, next) => {
  console.log(`${req.method} ${req.url}`)
  next()
})

const server = new MastraServer({ app, mastra })
await server.init()
```

之後加入中間件`init()` never runs for Mastra's routes. Express dispatches handlers in registration order, so middleware registered after the routes only applies to routes added later.

該適配器無法運作[`server.middleware`](/docs/server/middleware) handlers because they use Hono's signature, and it logs a warning when that option is set. If you need Express middleware between Mastra's context step and its routes, use the manual initialization flow below.

## 手動初始化 {/* #manual-initialization */}
