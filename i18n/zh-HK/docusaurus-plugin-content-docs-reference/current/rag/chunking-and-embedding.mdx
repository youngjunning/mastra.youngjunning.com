# 文件分塊與嵌入

處理文件前，先根據內容建立 MDocument 實例。可以使用不同格式的內容初始化：

```ts
import { MDocument } from '@mastra/rag'

const doc = MDocument.fromText('Your plain text content...')
const docFromHTML = MDocument.fromHTML('<html>Your HTML content...</html>')
const docFromMarkdown = MDocument.fromMarkdown('# Your Markdown content...')
const docFromJSON = MDocument.fromJSON(`{ "key": "value" }`)
```

## 處理文件 {/* #document-processing */}

使用 `chunk` 將文件拆成便於處理的區塊。Mastra 提供多種針對不同文件類型優化的分塊策略：

* `recursive`：按內容結構智能分割
* `character`：按字元分割
* `token`：按 token 分割
* `markdown`：按 Markdown 結構分割
* `semantic-markdown`：按相關標題群組分割 Markdown
* `html`：按 HTML 結構分割
* `json`：按 JSON 結構分割
* `latex`：按 LaTeX 結構分割
* `sentence`：按句子分割

:::note
各策略接受的參數不同，分別針對相應的分塊方式優化。
:::

以下例子使用 `recursive` 策略：

```ts
const chunks = await doc.chunk({
  strategy: 'recursive',
  maxSize: 512,
  overlap: 50,
  separators: ['\n'],
  extract: {
    title: true, // Optionally extract a title for each chunk
  },
})
```

如果文字需要保留句子結構，可以使用 `sentence` 策略：

```ts
const chunks = await doc.chunk({
  strategy: 'sentence',
  maxSize: 450,
  minSize: 50,
  overlap: 0,
  sentenceEnders: ['.'],
})
```

如果 Markdown 文件需要保留各章節之間的語義關係，可以使用 `semantic-markdown` 策略：

```ts
const chunks = await doc.chunk({
  strategy: 'semantic-markdown',
  joinThreshold: 500,
  modelName: '__AI_SDK_OPENAI_MODEL_BASE__',
})
```

:::note
擷取元數據時可能會呼叫 LLM，因此請確保已設定 API 金鑰。
:::

如需進一步了解分塊策略，請參閱 [`chunk()` 參考文件](/reference/rag/chunk)。

## 產生嵌入 {/* #embedding-generation */}

使用所選的 Provider 將區塊轉換為嵌入。Mastra 透過模型路由器支援嵌入模型。

### 使用模型路由器 {/* #using-the-model-router */}

最簡單的方法是將 `provider/model` 格式的字串傳入 Mastra 的模型路由器：

```ts
import { ModelRouterEmbeddingModel } from '@mastra/core/llm'
import { embedMany } from 'ai'

const { embeddings } = await embedMany({
  model: new ModelRouterEmbeddingModel('__GATEWAY_OPENAI_EMBEDDING_MODEL__'),
  values: chunks.map(chunk => chunk.text),
})
```

Mastra 支援 OpenAI 和 Google 的嵌入模型。完整的支援列表請參閱[嵌入參考文件](/reference/rag/embeddings)。

模型路由器會自動從環境變數中尋找 API 金鑰。

嵌入函數會傳回向量，即表示文字語義的數字陣列，可用於向量資料庫中的相似度搜尋。

### 設定嵌入維度 {/* #configuring-embedding-dimensions */}

嵌入模型通常會輸出固定維度的向量（例如，OpenAI 的 `__AI_SDK_OPENAI_EMBEDDING_MODEL__` 會輸出 1536 維向量）。
部分模型支援降低輸出維度，有助於：

* 降低向量資料庫的儲存需求
* 降低相似度搜尋的運算成本

以下是一些支援調整維度的模型：

OpenAI（text-embedding-3 系列模型）：

```ts
import { ModelRouterEmbeddingModel } from '@mastra/core/llm'

const { embeddings } = await embedMany({
  model: new ModelRouterEmbeddingModel('__GATEWAY_OPENAI_EMBEDDING_MODEL__'),
  options: {
    dimensions: 256, // Only supported in text-embedding-3 and later
  },
  values: chunks.map(chunk => chunk.text),
})
```

Google（gemini-embedding-001）：

```ts
const { embeddings } = await embedMany({
  model: google('gemini-embedding-001', {
    outputDimensionality: 256, // Truncates excessive values from the end
  }),
  values: chunks.map(chunk => chunk.text),
})
```

:::important[向量資料庫兼容性]
儲存嵌入時，應將向量資料庫索引的維度設為與嵌入模型的輸出維度一致，避免維度不符造成錯誤或數據損壞。
:::

## 例子：完整流程 {/* #example-complete-pipeline */}

以下例子展示文件處理、嵌入產生及向量儲存的完整流程：

```ts
import { ModelRouterEmbeddingModel } from '@mastra/core/llm'
import { PgVector } from '@mastra/pg'
import { MDocument } from '@mastra/rag'
import { embedMany } from 'ai'

const doc = MDocument.fromText(`
  Climate change poses significant challenges to global agriculture.
  Rising temperatures and changing precipitation patterns affect crop yields.
`)

const chunks = await doc.chunk({
  strategy: 'recursive',
  maxSize: 256,
  overlap: 50,
})

const { embeddings } = await embedMany({
  model: new ModelRouterEmbeddingModel('__GATEWAY_OPENAI_EMBEDDING_MODEL__'),
  values: chunks.map(chunk => chunk.text),
})

const vectorStore = new PgVector({
  id: 'pg-vector',
  connectionString: process.env.POSTGRES_CONNECTION_STRING,
})

await vectorStore.createIndex({
  indexName: 'embeddings',
  dimension: 1536,
})

await vectorStore.upsert({
  indexName: 'embeddings',
  vectors: embeddings,
})
```
