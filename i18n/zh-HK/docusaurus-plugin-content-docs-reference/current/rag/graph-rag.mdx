# GraphRAG

`GraphRAG` 類別以圖式方法實現檢索增強生成。它根據文件片段建立知識圖譜：節點代表文件，邊代表語義關係。這樣既可直接比對相似內容，亦可遍歷圖譜找出相關內容。

## 基本用法 {/* #basic-usage */}

```typescript
import { GraphRAG } from '@mastra/rag'

const graphRag = new GraphRAG(1536, 0.7)

// Create the graph from chunks and embeddings
graphRag.createGraph(documentChunks, embeddings)

// Query the graph with embedding
const results = await graphRag.query({
  query: queryEmbedding,
  topK: 10,
  randomWalkSteps: 100,
  restartProb: 0.15,
})
```

快照是深層複本，修改快照不會影響原本的圖譜。由於每個節點都包含完整的嵌入向量，快照可能很大：使用 1536 維嵌入向量建立的 1,000 節點圖譜，序列化後約有 20 MB 的 JSON。儲存欄位須預留足夠容量。

如果快照版本不受支援、節點的嵌入向量維度與快照記錄的維度不符、嵌入向量包含非有限數值，或某條邊引用了快照中不存在的節點，就會擲出錯誤。因此，無效快照會在載入時被發現，不會等到之後查詢才失敗。

## 持久儲存圖譜 {/* #persisting-a-graph */}

建立圖譜的時間複雜度隨片段數量呈 O(n²) 增長，因此每次啟動程序都重新建立會浪費資源。建立後可將圖譜序列化，並把快照存放在現有的狀態儲存空間。快照是一般 JSON，可存入檔案、blob 欄位或鍵值快取；`GraphRAG` 不依賴特定儲存後端。

```typescript
import { readFile, writeFile } from 'node:fs/promises'
import { GraphRAG } from '@mastra/rag'
import type { GraphRAGSnapshot } from '@mastra/rag'

const SNAPSHOT_PATH = './docs-graph.json'

async function loadOrBuildGraph() {
  try {
    const snapshot = JSON.parse(await readFile(SNAPSHOT_PATH, 'utf8')) as GraphRAGSnapshot
    return GraphRAG.deserialize(snapshot)
  } catch {
    // No usable snapshot yet, so build the graph from scratch
  }

  const graphRag = new GraphRAG(1536, 0.7)
  graphRag.createGraph(documentChunks, embeddings)

  await writeFile(SNAPSHOT_PATH, JSON.stringify(graphRag.serialize()))

  return graphRag
}
```

快照只反映建立時使用的片段，不會增量更新。底層文件有變更時，須重新建立圖譜並儲存新快照。
