# 將嵌入儲存在向量資料庫中

產生嵌入後，須將其儲存在支援向量相似度搜尋的資料庫。Mastra 提供統一介面，讓你在不同向量資料庫儲存和查詢嵌入。

    <h3>使用 MongoDB Vector Search</h3>

    若團隊希望把向量搜尋、全文搜尋及營運數據集中於單一資料庫，減少基礎設施複雜程度，同時維持正式環境所需效能，可以使用 MongoDB Vector Search。
    詳細設定步驟和最佳做法請參閱 [MongoDB Vector Search 官方文件](https://www.mongodb.com/docs/atlas/atlas-vector-search/vector-search-overview/?utm_campaign=devrel\&utm_source=third-party-content\&utm_medium=cta\&utm_content=mastra-docs)。

    <h3>將 VoyageAI 與 MongoDB 結合使用</h3>

    MongoDB 可直接配合針對檢索任務優化的 VoyageAI 嵌入模型。完整例子及專用模型請參閱 [VoyageAI 嵌入文件](/models/embeddings#voyageai)和 [MongoDB 向量資料庫參考文件](/integrations/vectors/mongodb)。

    <h3>混合搜尋（向量與全文）</h3>

    MongoDB 透過伺服器端的 `$rankFusion`，結合向量相似度搜尋及 BM25 全文搜尋。此功能要求 MongoDB 8.0 或以上版本，由 8.1 起正式提供，並已在 MongoDB Atlas 8.0.x 啟用。可用於合併語意檢索和關鍵字搜尋結果：

    ```ts
    await store.createSearchIndex({ indexName: 'myCollection', fields: ['text'] })
    const results = await store.hybridQuery({
      indexName: 'myCollection',
      queryVector: embedding,
      query: 'search terms',
      paths: ['text'],
      topK: 10,
    })
    ```

    如需了解 `createSearchIndex()`、`textQuery()` 和 `hybridQuery()`，請參閱 [MongoDB 向量資料庫參考文件](/integrations/vectors/mongodb)。

    <h3>自動嵌入</h3>

    MongoDB 可以自行產生嵌入，因此應用程式毋須設定嵌入 Provider。建立索引時指定 `autoEmbed` 和 Voyage AI 模型，然後寫入純文字，並以查詢字串搜尋：

    ```ts
    await store.createIndex({
      indexName: 'myCollection',
      autoEmbed: { model: 'voyage-4' },
    })
    await store.upsert({
      indexName: 'myCollection',
      documents: chunks.map(chunk => chunk.text),
      metadata: chunks.map(chunk => ({ text: chunk.text })),
    })
    const results = await store.query({
      indexName: 'myCollection',
      queryText: 'search terms',
      topK: 10,
    })
    ```

    自動嵌入是 MongoDB 的預覽功能，須使用支援此功能的部署環境。支援的選項及要求請參閱 [MongoDB 向量資料庫參考文件](/integrations/vectors/mongodb#automated-embedding)。

## 使用向量存儲 {/* #using-vector-storage */}

初始化後，所有向量儲存共用相同的介面來建立索引、更新插入嵌入和查詢。

### 建立索引 {/* #creating-indexes */}

在儲存嵌入之前，您需要為嵌入模型建立一個具有適當維度大小的索引：

```ts title="store-embeddings.ts"
// Create an index with dimension 1536 (for __AI_SDK_OPENAI_EMBEDDING_MODEL__)
await store.createIndex({
  indexName: 'myCollection',
  dimension: 1536,
})
```

尺寸大小必須與您選擇的嵌入模型的輸出尺寸相符。常見的尺寸有：

* OpenAI `__AI_SDK_OPENAI_EMBEDDING_MODEL__`：1536 維（亦可自訂，例如 256 維）
* `Cohere embed-multilingual-v3`： 1024 維
* `VoyageAI voyage-3.5`：1024 個尺寸（或自訂：256、512、1024、2048）
* `Google gemini-embedding-001`：768 尺寸（或自訂）

:::警告
索引維度建立後無法變更。若要使用不同的模型，請刪除索引並使用新的維度大小重新建立索引。
:::

### 資料庫命名規則 {/* #naming-rules-for-databases */}

每個向量資料庫都會對索引和集合強制執行特定的命名約定，以確保相容性並防止衝突。

<Tabs>
  <TabItem value="mongodb" label="MongoDB">
    集合和索引名稱必須：

    * 以字母或底線開頭
    * 長度最多 120 位元組
    * 僅包含字母、數字、底線字元或點
    * 不可包含 `$` 或空字元
    * 例子：`my_collection.123` 是有效名稱
    * 例子：`my-index` 是無效名稱（包含連字符）
    * 例子：`My$Collection` 是無效名稱（包含 `$`）
  </TabItem>

  <TabItem value="pgVector" label="PgVector">
    索引名稱必須：

    * 以字母或底線開頭
    * 僅包含字母、數字和底線字符
    * 例子：`my_index_123` 是有效名稱
    * 例子：`my-index` 是無效名稱（包含連字符）
  </TabItem>

  <TabItem value="oracledb" label="OracleDB">
    索引名稱是邏輯 Mastra 名稱。 OracleDB 在內部將每個邏輯索引對應到物理 Oracle 表。

    邏輯索引名稱必須：

    * 非空
    * 不超過 512 個字符
    * 在向量索引的生命週期內保持穩定
    * 例子：`my_collection_123` 是有效名稱
    * 例子：`customer-support/docs:v1` 是有效名稱，並會對應至安全的 Oracle 資料表名稱
  </TabItem>

  <TabItem value="pinecone" label="Pinecone">
    索引名稱必須：

    * 僅使用小寫字母、數字和破折號
    * 不包含點（用於 DNS 路由）
    * 不使用非拉丁字元或表情符號
    * 總長度（含項目 ID）少於 52 個字符
      * 例子：`my-index-123` 是有效名稱
      * 例子：`my.index` 是無效名稱（包含點）
  </TabItem>

  <TabItem value="qdrant" label="Qdrant">
    集合名稱必須：

    * 長度為 1-255 個字符
    * 不包含任何以下特殊字元：
      * `< > : " / \ | ? *`
      * 空字元 (`\0`)
      * 單位分隔符號 (`\u{1F}`)
    * 例子：`my_collection_123` 是有效名稱
    * 例子：`my/collection` 是無效名稱（包含斜線）
  </TabItem>

  <TabItem value="chroma" label="Chroma">
    集合名稱必須：

    * 長度為 3-63 個字符
    * 以字母或數字開頭和結尾
    * 僅包含字母、數字、底線字符或連字符
    * 不包含連續句點 (..)
    * 不是有效的 IPv4 位址
    * 例子：`my-collection-123` 是有效名稱
    * 例子：`my..collection` 是無效名稱（包含連續的點）
  </TabItem>

  <TabItem value="astra" label="Astra">
    集合名稱必須：

    * 不能為空
    * 不超過 48 個字符
    * 只可包含字母、數字和 `_`
    * 例子：`my_collection_123` 是有效名稱
    * 例子：`my-collection` 是無效名稱（包含連字符）
  </TabItem>

  <TabItem value="libsql" label="libSQL">
    索引名稱必須：

    * 以字母或底線開頭
    * 只可包含字母、數字和 `_`
    * 例子：`my_index_123` 是有效名稱
    * 例子：`my-index` 是無效名稱（包含連字符）
  </TabItem>

  <TabItem value="upstash" label="Upstash">
    命名空間名稱必須：

    * 長度為 2-100 個字符
    * 僅包含：
      * 字母數字字元（a-z、A-Z、0-9）
      * 底線、連字符、點
    * 不以特殊字元（\_、-、.）開頭或結尾
    * 可以區分大小寫
    * 例子：`MyNamespace123` 是有效名稱
    * 例子：`_namespace` 是無效名稱（以底線開頭）
  </TabItem>

  <TabItem value="weaviate" label="Weaviate">
    索引名稱對應到 Weaviate 集合，其中：

    * Weaviate 大寫（第一個字母大寫）
    * 應只包含字母、數字和 `_`
    * 必須以字母開頭，因為只有第一個字元是大寫的（前導數字或符號仍然無效）
    * 在集合描述中保留原始 Mastra 索引名稱，因此 `listIndexes()` 和 `describeIndex()` 會傳回你提供的名稱
    * 例子：`my_collection` 儲存為 `My_collection`，傳回時仍為 `my_collection`
    * 例子：`123_collection` 是無效名稱（以數字開頭）
  </TabItem>

  <TabItem value="cloudflare" label="Cloudflare">
    索引名稱必須：

    * 以字母開頭
    * 少於 32 個字符
    * 僅包含小寫 ASCII 字母、數字和破折號
    * 使用破折號代替空格
    * 例子：`my-index-123` 是有效名稱
    * 例子：`My_Index` 是無效名稱（包含大寫字母和底線）
  </TabItem>

  <TabItem value="opensearch" label="OpenSearch">
    索引名稱必須：

    * 僅使用小寫字母
    * 不以下劃線字元或連字符開頭
    * 不包含空格、逗號
    * 不包含特殊字元（例如`:`, `"`, `*`, `+`, `/`, `\`, `|`, `?`, `#`, `>`, `<`)
    * 例子：`my-index-123` 是有效名稱
    * 例子：`My_Index` 是無效名稱（包含大寫字母）

### 插入或更新嵌入 {/* #upserting-embeddings */}

建立索引後，即可儲存嵌入及其基本中繼資料：

```ts title="store-embeddings.ts"
// Store embeddings with their corresponding metadata
await store.upsert({
  indexName: 'myCollection', // index name
  vectors: embeddings, // array of embedding vectors
  metadata: chunks.map(chunk => ({
    text: chunk.text, // The original text content
    id: chunk.id, // Optional unique identifier
  })),
})
```

插入或更新操作會：

* 接收嵌入向量陣列及對應的中繼資料
* 更新 ID 相同的現有向量
* 為尚不存在的 ID 建立新向量
* 自動分批處理大型資料集

## 加入中繼資料 {/* #adding-metadata */}

向量儲存支援以任何可序列化為 JSON 的欄位作為中繼資料，方便篩選及整理。中繼資料沒有固定結構，應統一欄位名稱，避免查詢結果不如預期。

:::warning
中繼資料對向量儲存很重要。若沒有中繼資料，就只有數值形式的嵌入，無法傳回原始文字或篩選結果。至少應把來源文字存為中繼資料。
:::

```ts
// Store embeddings with rich metadata for better organization and filtering
await store.upsert({
  indexName: 'myCollection',
  vectors: embeddings,
  metadata: chunks.map(chunk => ({
    // Basic content
    text: chunk.text,
    id: chunk.id,

    // Document organization
    source: chunk.source,
    category: chunk.category,

    // Temporal metadata
    createdAt: new Date().toISOString(),
    version: '1.0',

    // Custom fields
    language: chunk.language,
    author: chunk.author,
    confidenceScore: chunk.score,
  })),
})
```

使用中繼資料時請注意：

* 統一欄位名稱，例如 `category` 與 `Category` 不一致會影響查詢
* 只加入篩選或排序需要的欄位；額外欄位會增加負擔
* 加入時間戳記（例如 `createdAt`、`lastUpdated`），以追蹤內容是否仍然新近

## 刪除向量 {/* #deleting-vectors */}

使用 `deleteVectors` 配合中繼資料篩選條件，移除與文件相關的嵌入。文件刪除或更新後，可用此方式清理過時的向量。

### 透過元資料過濾器刪除 {/* #delete-by-metadata-filter */}

最常見的用例是當使用者刪除特定文件時刪除該文件的所有向量：

```ts title="delete-vectors.ts"
// Delete all vectors for a specific document
await store.deleteVectors({
  indexName: 'myCollection',
  filter: { docId: 'document-123' },
})
```

這在以下情況下特別有用：

* 使用者刪除文檔，您需要刪除其所有區塊
* 您正在重新索引文件並希望首先刪除舊向量
* 您需要清理特定使用者或租戶的向量

### 刪除多個文檔 {/* #delete-multiple-documents */}

您也可以使用複雜的篩選器來刪除符合多個條件的向量：

```ts title="delete-vectors-advanced.ts"
// Delete all vectors for multiple documents
await store.deleteVectors({
  indexName: 'myCollection',
  filter: {
    docId: { $in: ['doc-1', 'doc-2', 'doc-3'] },
  },
})

// Delete vectors for a specific user's documents
await store.deleteVectors({
  indexName: 'myCollection',
  filter: {
    $and: [{ userId: 'user-123' }, { status: 'archived' }],
  },
})
```

### 按向量 ID 刪除 {/* #delete-by-vector-ids */}

如果您有特定的向量ID要刪除，您可以直接傳遞它們：

```ts title="delete-by-ids.ts"
// Delete specific vectors by their IDs
await store.deleteVectors({
  indexName: 'myCollection',
  ids: ['vec-1', 'vec-2', 'vec-3'],
})
```

## 最佳實踐 {/* #best-practices */}

* 大量插入前先建立索引
* 大量插入時使用批次操作（upsert 方法會自動分批）
* 只儲存查詢時需要的中繼資料
* 讓嵌入維度與模型輸出一致（例如，`__AI_SDK_OPENAI_EMBEDDING_MODEL__` 對應 1536 維）
