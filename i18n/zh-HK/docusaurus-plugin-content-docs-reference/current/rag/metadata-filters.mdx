# 元資料篩選條件

Mastra 根據 MongoDB/Sift 查詢語法，為所有向量儲存提供一致的元資料篩選語法。每種向量儲存都會將篩選條件轉換成自身的查詢格式。例如，PgVector 使用 PostgreSQL JSONB 謂詞；OracleDB 將元資料儲存為 Oracle JSON，並將篩選條件編譯成使用參數綁定的 `JSON_VALUE`、`JSON_EXISTS`、`REGEXP_LIKE` 和 `LIKE` 謂詞。

## 基本範例 {/* #basic-example */}

```typescript
import { PgVector } from '@mastra/pg'

const store = new PgVector({
  id: 'pg-vector',
  connectionString,
})

const results = await store.query({
  indexName: 'my_index',
  queryVector: queryVector,
  topK: 10,
  filter: {
    category: 'electronics', // Simple equality
    price: { $gt: 100 }, // Numeric comparison
    tags: { $in: ['sale', 'new'] }, // Array membership
  },
})
```

## 通用規則及限制 {/* #common-rules-and-restrictions */}

1. 欄位名稱不能：
   * 包含點 (.)，除非引用嵌套字段
   * 以 $ 開頭或包含空字符
   * 為空字串

2. 值必須：
   * 屬於有效的 JSON 類型（字串、數字、布林值、物件或陣列）
   * 不能是 `undefined`
   * 符合運算子要求的類型（例如，數值比較需要數字）

3. 邏輯運算符：
   * 必須包含有效條件
   * 不能為空
   * 必須正確嵌套
   * 只能在頂層使用或嵌套在其他邏輯運算符中
   * 不能在字段層級使用或嵌套在字段內
   * 不能在運算子內部使用
   * 有效的：`{ "$and": [{ "field": { "$gt": 100 } }] }`
   * 有效的：`{ "$or": [{ "$and": [{ "field": { "$gt": 100 } }] }] }`
   * 無效的：`{ "field": { "$and": [{ "$gt": 100 }] } }`
   * 無效的：`{ "field": { "$gt": { "$and": [{...}] } } }`

4. `$not` 運算子：
   * 必須是物件
   * 不能為空
   * 可用於欄位層級或最上層
   * 有效的：`{ "$not": { "field": "value" } }`
   * 有效的：`{ "field": { "$not": { "$eq": "value" } } }`

5. 運算符嵌套：
   * 邏輯運算子必須包含欄位條件，而不是直接運算符
   * 有效的：`{ "$and": [{ "field": { "$gt": 100 } }] }`
   * 無效的：`{ "$and": [{ "$gt": 100 }] }`

## 各向量儲存的注意事項 {/* #store-specific-notes */}

### Astra {/* #astra */}

* 使用點表示法支援嵌套字段查詢
* 數組字段必須在元資料中明確定義為數組
* 元資料值區分大小寫

### ChromaDB {/* #chromadb */}

* `where` 篩選條件只會傳回元資料中存在指定欄位的結果
* 空元資料欄位不包含在篩選結果中
* 否定匹配必須存在元資料欄位（例如，$ne 不會匹配缺少該欄位的文件）

### Cloudflare Vectorize {/* #cloudflare-vectorize */}

* 在使用過濾之前需要明確元資料索引
* 使用 `createMetadataIndex()` 為要篩選的欄位建立索引
* 每個 Vectorize 索引最多 10 個元資料索引
* 字串值的索引最多為前 64 個位元組（在 UTF-8 邊界上截斷）
* 數值使用 float64 精度
* 過濾器 JSON 必須小於 2048 位元組
* 欄位名稱不能包含點 (.) 或以 $ 開頭
* 字段名稱限制為 512 個字符
* 建立新的元資料索引以包含在過濾結果中後，必須重新插入向量
* 對於非常大的資料集（約 10M+ 向量），範圍查詢的準確性可能會降低

### libSQL {/* #libsql */}

* 支援使用點表示法的巢狀物件查詢
* 驗證數組欄位以確保它們包含有效的 JSON 數組
* 數字比較保持正確的類型處理
* 條件中的空數組得到妥善處理
* 元資料儲存在 JSONB 列中，以便有效率地查詢

### OracleDB {/* #oracledb */}

* 元資料以 Oracle JSON 格式與每筆 `VECTOR` 資料一同儲存
* 純量比較使用 `JSON_VALUE`；陣列、欄位存在與陣列元素匹配檢查使用 `JSON_EXISTS`
* `$regex` 使用 Oracle 的 `REGEXP_LIKE`；字串 `$contains` 使用不區分大小寫的 `LIKE`
* 巢狀欄位支援點表示法，並轉換為引號的 Oracle JSON 路徑
* 使用者提供的元資料值作為參數綁定，而不是插入到 SQL 中

### PgVector {/* #pgvector */}

* 完全支援 PostgreSQL 原生 JSON 查詢功能
* 使用本機數組函數有效處理數組操作
* 對數字、字串和布林值進行正確的類型處理
* 巢狀欄位查詢在內部使用 PostgreSQL 的 JSON 路徑語法
* 元資料儲存在 JSONB 列中以實現高效索引

### Pinecone {/* #pinecone */}

* 元資料欄位名稱限制為 512 個字符
* 數值必須在 ±1e38 範圍內
* 元資料中的陣列總大小限制為 64KB
* 嵌套物件用點表示法展平
* 元資料更新取代整個元資料對象

### Qdrant {/* #qdrant */}

* 支援使用嵌套條件的進階過濾
* 有效負載（元資料）欄位必須明確索引以進行過濾
* 使用 `createPayloadIndex()` 為要篩選的欄位建立索引：

```typescript
// Index a field before filtering on it
await store.createPayloadIndex({
  indexName: 'my_index',
  fieldName: 'source',
  fieldSchema: 'keyword', // 'keyword' | 'integer' | 'float' | 'geo' | 'text' | 'bool' | 'datetime' | 'uuid'
})

// Now filtering works
const results = await store.query({
  indexName: 'my_index',
  queryVector: queryVector,
  filter: { source: 'document-a' },
})
```

* 有效率地處理地理空間查詢
* 對 null 值和空值的特殊處理
* 特定於向量的過濾功能
* 日期時間值必須採用 RFC 3339 格式
* `$regex` 會轉換成 Qdrant 的全文匹配，匹配完整詞元，而非任意正則表達式或子字串（例如，`{ name: { $regex: "item" } }` 不會匹配 `"item1"`）。對於未建立索引的 payload 欄位，v1.19.1 之前的 Qdrant 版本會改用子字串匹配

### Upstash {/* #upstash */}

* 元資料欄位鍵的 512 個字元限制
* 查詢大小有限（避免使用大型 IN 子句）
* 過濾器中不支援 null/未定義值
* 在內部轉換為類似 SQL 的語法
* 區分大小寫的字串比較
* 元資料更新是原子的

### MongoDB {/* #mongodb */}

* 需要 MongoDB Atlas，或已啟用 MongoDB Vector Search 的部署。此向量儲存透過 `$vectorSearch` 聚合階段查詢。
* 直接使用 MongoDB 查詢語法進行元資料過濾器，包括元資料中的巢狀欄位和陣列。
* 支援上表所列的比較、陣列、邏輯及元素運算子，以及 `$regex` 和 `$size`。`$size` 接受整數，例如 `{ tags: { $size: 3 } }`。
* 使用 `filter` 匹配元資料物件中的欄位，使用 `documentFilter` 匹配原始文件文字。兩者可用於同一次查詢。
* 建立索引時，在 `filterFields` 宣告要篩選的元資料欄位。若篩選條件只使用已宣告的欄位，以及 MongoDB Vector Search 接受的運算子（`$and`、`$or`、`$eq`、`$ne`、`$gt`、`$gte`、`$lt`、`$lte`、`$in`、`$nin`），Mastra 會直接將條件傳給 `$vectorSearch`：

```typescript
await store.createIndex({
  indexName: 'my_index',
  dimension: 1536,
  filterFields: ['category', 'price'],
})
```

* 若篩選條件引用未宣告的欄位或使用其他運算子，Mastra 會先篩選集合，再將符合條件的文件 ID 傳給 `$vectorSearch`。只有 ID 集合未超過 MongoDB 的 16 MB BSON 文件限制時，這條後備路徑才可運作。大型集合一旦超過限制，查詢就會失敗；因此，對大型數據集進行選擇性篩選時，應宣告篩選欄位。

### Couchbase {/* #couchbase */}

* 目前不支援元數據過濾器。檢索結果後必須在客戶端進行過濾，或直接使用 Couchbase SDK 的搜尋功能進行更複雜的查詢。

### Amazon S3 Vectors {/* #amazon-s3-vectors */}

* 相等比較的值必須是基本類型（字串、數字或布林值），不能是 `null`、`undefined`、陣列、物件或 Date。範圍運算子接受數字或 Date；Date 會轉換成以毫秒計的 Unix 時間戳。
* `$in` 和 `$nin` 要求使用**非空的基本類型陣列**。陣列元素可以是 Date，並會轉換成以毫秒計的 Unix 時間戳。**不支援陣列相等比較**。
* 隱含的 AND 會規範成明確形式（`{a:1,b:2}` → `{$and:[{a:1},{b:2}]`）。邏輯運算子必須包含欄位條件，並使用非空陣列；只能出現在最上層或其他邏輯運算子內，不能出現在欄位值中。
* 建立索引時列於 `nonFilterableMetadataKeys` 的鍵會被儲存，但無法用於篩選。此設定不可更改。
* `$exists` 要求布林值。
* `undefined`、`null` 或空的篩選條件均視為未設定篩選條件。
* 每個元資料鍵名稱不得超過 63 個字元。
* 每個向量的總元資料：最多 40 KB（可過濾 + 不可過濾）
* 每個向量的元資料金鑰總數：最多 10 個
* 每個向量的可過濾元資料：最多 2 KB
* 每個向量索引的不可過濾元資料鍵：最多 10 個
