# UnsupportedFileHandler

`UnsupportedFileHandler` 是一個**錯誤處理器**。當模型拒絕用戶傳送的檔案時，它會從提示中移除該檔案，再次呼叫模型，讓 Agent 能夠繼續工作。若 Agent 的 Workspace 有 Sandbox，檔案會上傳到其中，並將路徑提供給模型；否則，模型會收到替代檔案的佔位文字。

Mastra 預設將此處理器加入每個 Agent 的 `errorProcessors`，順序位於 `PrefillErrorHandler` 之後、`StreamErrorRetryProcessor` 之前，無需額外配置。設置 `errorProcessorDefaults: false` 會將它與其他預設處理器一起停用。

## 運作方式 {/* #how-it-works */}

1. 所有檔案最初都會原樣傳送給模型。模型支援的檔案類型因 Provider 而異，也會隨時間變化，因此處理器不會預先判斷。
1. 檔案導致模型呼叫失敗，可能有兩種情況：
   - Provider SDK 在送出請求前拒絕該檔案類型，並拋出包含媒體類型的 `UnsupportedFunctionalityError`。OpenAI 和 Anthropic 的 SDK 就會這樣處理。
   - Provider 在 HTTP 回應中拒絕請求。錯誤訊息通常不會提到檔案：例如，Gemini 對某些檔案類型會回傳 `502`。只要請求包含非圖像、非 PDF、非文字的檔案，任何 API 錯誤都符合此條件，但表示稍後重試的狀態碼 `408`、`409`、`429`、`503` 或 `504` 除外：這些情況由 [`StreamErrorRetryProcessor`](/reference/processors/stream-error-retry-processor) 原樣重發請求，檔案也會一同傳送。
1. 首次拒絕呼叫時，處理器會從提示中移除被拒絕的檔案，以及其他所有非圖像、非 PDF、非文字的檔案。呼叫只會重試一次，這樣便能在同一次重試中處理模型可能無法讀取的所有檔案。
1. 處理器回傳 `{ retry: true }`，再次呼叫模型。若仍然失敗，錯誤會向外拋出。

若 Agent 的 Workspace 有 Sandbox，每個檔案都會按 [`FileUploadProcessor`](/reference/processors/file-upload-processor#upload-location) 的方式上傳。模型會收到包含 Sandbox 路徑的說明，Agent 因而可以用自身的 Tool 處理該檔案：

```text
[File uploaded to the sandbox]
path: /home/user/uploads/thread-1/0b2f4c6e8a1d3f5b7c9e2a4d6f8b1c3e5a7d9f2b4c6e8a1d3f5b7c9e2a4d6f8b.xlsx
name: leads.xlsx
type: application/vnd.openxmlformats-officedocument.spreadsheetml.sheet
size: 48213 bytes
```

若沒有 Sandbox，或上傳失敗，模型會收到 Mastra 用於不可用附件的佔位文字，本輪對話仍會繼續。沒有檔案名時，佔位文字會顯示檔案類型：

```text
[Attachment unavailable: leads.xlsx]
```

這裏的 Sandbox 是目前步驟所用的 Workspace，也就是 Agent 的 Tool 使用的 Workspace。超過 10 MB 的檔案不會上傳，模型會收到說明原因的提示。

只有傳送給模型的提示會改變。已儲存的訊息仍保留檔案，因此執行緒、Studio 等客戶端以及支援該類型的模型仍可存取它。即使執行緒已存有被拒絕的檔案，下一輪仍可正常進行，因為每輪都會按相同方式處理該檔案。

如要自行決定哪些檔案進入 Sandbox，並在模型看到檔案前完成上傳，可將 `FileUploadProcessor` 加入 `inputProcessors`。

## 限制 {/* #limitations */}

- **跨執行緒共用的 Sandbox。** 檔案預設寫入 Agent 的 Sandbox，按執行緒分目錄存放；目錄只能分隔檔案，不能保護檔案。若其他執行緒或用戶共用該 Sandbox，任一執行緒的命令 Tool 都可以讀取這些檔案。處理私人檔案時，請使用[每位用戶或每個執行緒獨立的 Sandbox](/docs/sandbox/overview#sandboxes-per-user-or-thread)。
- **僅再嘗試一次。** 移除檔案後若呼叫仍失敗，錯誤會向外拋出。只要請求中包含此類檔案，發生 API 錯誤時就會移除檔案並重試一次，即使錯誤並非由檔案引起；表示稍後重試的狀態碼除外。不含此類檔案的請求若因其他原因被拒絕，處理器不會介入。
