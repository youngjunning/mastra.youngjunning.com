# 令牌限制器處理器

這`TokenLimiterProcessor`限制訊息中的令牌數量。根據`trimMode`，它充當提示處理器、輸入處理器和輸出處理器：

* **提示處理器** (`processLLMRequest`): In the default `best-fit` and `contiguous`修剪模式，在每次模型呼叫之前、Agent循環的每個步驟中強制執行提供者提示上的輸入預算。提示是在較早的提示處理器（例如`ToolCallFilter`）對其進行了轉換，因此僅計算實際到達模型的令牌。Tool呼叫和Tool結果訊息被分組，以便它們一起保留或刪除，並且修剪是暫時的：儲存的訊息永遠不會被修改。
* **輸入處理器** (`processInput`): In `memory-only` trim mode, filters historical messages to fit within the context window before the agentic loop starts, prioritizing recent messages
* **輸出處理器**：透過串流或非串流限制產生的回應令牌，並使用可設定的策略來處理超出的限制

## 使用範例 {/* #usage-example */}

```typescript
import { TokenLimiterProcessor } from '@mastra/core/processors'

const processor = new TokenLimiterProcessor({
  limit: 1000,
  strategy: 'truncate',
  countMode: 'cumulative',
})
```

## 輸出流行為 {/* #output-stream-behavior */}

作為輸出處理器，只有攜帶產生輸出的部分才算是限制：`text-delta` and `object`. Lifecycle parts (such as `step-start`), reasoning deltas, response metadata, and tool parts (`tool-call`, `tool-result`) are neither counted nor withheld, so tool calls always reach the agentic loop and get executed.

使用預設的`truncate` strategy, the first time output is withheld the processor emits a transient `data-token-limit-reached` part on the stream:

```typescript oxfmt:false
for await (const part of stream.fullStream) {
  if (part.type === 'data-token-limit-reached') {
    console.log('output truncated at', part.data.limit, 'tokens')
  }
}
```

## 媒體令牌計數 {/* #media-token-counting */}

圖像和文件附件是估計的而不是標記化的，包括`file` message parts and tool results shaped like `{ data, mediaType }`. Images use a flat per-image estimate; other media uses decoded byte size, while remote URLs and provider file ids use a flat fallback because their size isn't known locally. Encoded payloads such as base64 data are never counted as text, avoiding an inflated count that could truncate history unnecessarily.

## 錯誤行為 {/* #error-behavior */}

當修剪輸入時，`TokenLimiterProcessor` throws a `TripWire` error in the following cases:

* **空消息**：如果沒有要處理的非系統訊息，則會拋出 TripWire，因為您無法傳送沒有訊息的 LLM 要求。
* **系統訊息超出限制**：如果單獨的系統訊息超出了令牌限制，則會引發 TripWire，因為您無法傳送僅包含系統訊息而沒有使用者/助理訊息的 LLM 要求。
* **沒有適合的消息**：如果沒有訊息符合剩餘令牌預算，則會拋出 TripWire，因為您無法發送沒有訊息的 LLM 請求。

```typescript
import { TripWire } from '@mastra/core/agent'

try {
  await agent.generate('Hello')
} catch (error) {
  if (error instanceof TripWire) {
    console.log('Token limit error:', error.message)
  }
}
```

## 擴充使用範例 {/* #extended-usage-example */}

### 作為輸入處理器（限制上下文視窗） {/* #as-an-input-processor-limit-context-window */}

使用`inputProcessors` to limit historical messages sent to the model, which helps stay within context window limits:

```typescript title="src/mastra/agents/context-limited-agent.ts"
import { Agent } from '@mastra/core/agent'
import { Memory } from '@mastra/memory'
import { TokenLimiterProcessor } from '@mastra/core/processors'

export const agent = new Agent({
  id: 'context-limited-agent',
  name: 'context-limited-agent',
  instructions: 'You are a helpful assistant',
  model: '__GATEWAY_OPENAI_MODEL__',
  memory: new Memory({/* ... */}),
  inputProcessors: [
    new TokenLimiterProcessor({ limit: 4000 }), // Limits historical messages to ~4000 tokens
  ],
})
```

### {/* #as-a-per-step-processor-limit-multi-step-token-growth */}

當Agent程式跨多個步驟使用Tool時（例如`maxSteps > 1`), each step accumulates conversation history from all previous steps. `TokenLimiterProcessor` applies its limit at every step, measuring the prompt that's about to be sent after any earlier prompt processors have run. To count the prompt the model actually receives, register the limiter after prompt-shrinking processors such as `ToolCallFilter`:

```typescript title="src/mastra/agents/multi-step-agent.ts"
import { Agent } from '@mastra/core/agent'
import { TokenLimiterProcessor } from '@mastra/core/processors'

export const agent = new Agent({
  id: 'multi-step-agent',
  name: 'multi-step-agent',
  instructions: 'You are a helpful research assistant with access to tools',
  model: '__GATEWAY_OPENAI_MODEL__',
  inputProcessors: [
    new TokenLimiterProcessor({ limit: 8000 }), // Applied at every step
  ],
})

// Each tool call step will be limited to ~8000 input tokens
const result = await agent.generate('Research this topic using your tools', {
  maxSteps: 10,
})
```

處理器Workflow不運作`processLLMRequest`, so a `TokenLimiterProcessor` inside a processor workflow trims stored messages in `processInputStep`, before prompt processors such as `ToolCallFilter` remove anything from the request. To count the prompt the model receives, add the limiter directly to `inputProcessors`.

### 作為輸出處理器（限制響應長度） {/* #as-an-output-processor-limit-response-length */}

使用`outputProcessors` to limit the length of generated responses:

```typescript title="src/mastra/agents/response-limited-agent.ts"
import { Agent } from '@mastra/core/agent'
import { TokenLimiterProcessor } from '@mastra/core/processors'

export const agent = new Agent({
  id: 'response-limited-agent',
  name: 'response-limited-agent',
  instructions: 'You are a helpful assistant',
  model: '__GATEWAY_OPENAI_MODEL__',
  outputProcessors: [
    new TokenLimiterProcessor({
      limit: 1000,
      strategy: 'truncate',
      countMode: 'cumulative',
    }),
  ],
})
```
