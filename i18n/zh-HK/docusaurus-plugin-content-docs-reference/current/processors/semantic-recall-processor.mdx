# 語意回憶

這`SemanticRecall`是一個**混合處理器**可以使用向量嵌入對對話歷史進行語義搜尋。輸入時，它執行語義搜尋以查找相關的歷史訊息。在輸出時，它為新訊息創建嵌入，以實現未來的語義檢索。具有自嵌入向量存儲並且沒有`embedder`，它將訊息文字發送到存儲，存儲創建嵌入。

## 使用範例 {/* #usage-example */}

```typescript
import { SemanticRecall } from '@mastra/core/processors'
import { openai } from '@ai-sdk/openai'

const processor = new SemanticRecall({
  storage: memoryStorage,
  vector: vectorStore,
  embedder: openai.embedding('text-embedding-3-small'),
  topK: 5,
  messageRange: 2,
  scope: 'resource',
})
```

## 擴充使用範例 {/* #extended-usage-example */}

```typescript title="src/mastra/agents/semantic-memory-agent.ts"
import { Agent } from '@mastra/core/agent'
import { SemanticRecall, MessageHistory } from '@mastra/core/processors'
import { PostgresStore, PgVector } from '@mastra/pg'
import { openai } from '@ai-sdk/openai'

const storage = new PostgresStore({
  id: 'pg-storage',
  connectionString: process.env.DATABASE_URL,
})

const vector = new PgVector({
  id: 'pg-vector',
  connectionString: process.env.DATABASE_URL,
})

const semanticRecall = new SemanticRecall({
  storage,
  vector,
  embedder: openai.embedding('text-embedding-3-small'),
  topK: 5,
  messageRange: { before: 2, after: 1 },
  scope: 'resource',
  threshold: 0.7,
})

export const agent = new Agent({
  id: 'semantic-memory-agent',
  name: 'semantic-memory-agent',
  instructions: 'You are a helpful assistant with semantic memory recall',
  model: '__GATEWAY_OPENAI_MODEL__',
  inputProcessors: [semanticRecall, new MessageHistory({ storage, lastMessages: 50 })],
  outputProcessors: [semanticRecall, new MessageHistory({ storage })],
})
```

## 行為 {/* #behavior */}

### 輸入處理 {/* #input-processing */}

1. 從最後一條用戶訊息中提取用戶查詢
2. 為查詢產生嵌入
3. 執行向量搜尋以查找語義相似的訊息
4. 檢索匹配的訊息以及周圍的上下文（基於`messageRange`)
5. 為了`scope: 'resource'`, formats cross-thread messages as a system message with timestamps
6. 新增召回訊息`source: 'memory'` tag

### 輸出處理 {/* #output-processing */}

1. 從新用戶和助理訊息中提取文字內容，跳過同一運行中先前已嵌入的訊息
2. 將長訊息分割成最多`maxChunkChars` characters and generates an embedding for each chunk
3. 每個區塊儲存一個向量行以及元資料（線程元資料、訊息 ID、線程 ID、資源 ID、角色、內容、時間戳記）。行 ID 源自訊息 ID（第一個區塊按原樣使用 UUID 訊息 ID），因此再次儲存相同的訊息會取代其行，而不是新增行
4. 使用 LRU 快取進行嵌入以避免冗餘 API 呼叫

### 跨線程召回 {/* #cross-thread-recall */}

什麼時候`scope` is set to `'resource'`, the processor can recall messages from other threads. These cross-thread messages are formatted as a system message with timestamps and conversation labels to provide context about when and where the conversation occurred.
