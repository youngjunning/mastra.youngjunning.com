# StreamErrorRetryProcessor

`StreamErrorRetryProcessor` 是一種**錯誤處理器**，用於重試暫時性的 LLM API 和串流故障。它內置了對 OpenAI Responses 流錯誤的匹配規則，也支援添加匹配器來識別其他 Provider 特有的錯誤格式。

Mastra 預設會將此處理器加入每個 Agent 的 `errorProcessors`，排在 `ProviderHistoryCompat`、`PrefillErrorHandler` 和 `UnsupportedFileHandler` 之後，位於最後。這樣，負責修復請求的處理器可以先嘗試修復，再由此處理器原樣重試。預設實例設定 `maxRetries: 2`，除內置匹配規則外還包含連線重置匹配器；它不會重試未知錯誤，也不會再次傳送修復處理器未能解決的錯誤請求（HTTP 400）。如需調整策略，可在 `errorProcessors` 中提供自己的實例。只有列表中缺少相同 `id` 時，Mastra 才會加入預設實例，因此你提供的實例會替代預設實例。

## 使用例子 {/* #usage-example */}

設定 `StreamErrorRetryProcessor`。使用相同的 `id` 時，不會再加入預設實例：

```typescript title="src/mastra/agents/openai-agent.ts"
import { Agent } from '@mastra/core/agent'
import { StreamErrorRetryProcessor } from '@mastra/core/processors'

export const agent = new Agent({
  id: 'openai-agent',
  name: 'openai-agent',
  instructions: 'You are a helpful assistant.',
  model: '__GATEWAY_OPENAI_MODEL_BASE__',
  errorProcessors: [new StreamErrorRetryProcessor({ maxRetries: 5 })],
  maxProcessorRetries: 5,
})
```

如果將 `maxRetries` 設為大於 `3`，還需同時設定 `maxProcessorRetries`；否則 Agent 會在錯誤處理器重試達到 `3` 次時停止。參見[重試次數限制](#retry-limits)。

如需僅運行自行設定的處理器、不合併任何預設處理器，請設定 `errorProcessorDefaults: false`。如果沒有提供 `errorProcessors` 列表，Agent 此時只會運行 Memory 提供的錯誤處理器（如果有）；Memory 提供處理器時，重試上限為 `3`。參見[預設啟用錯誤處理器](/docs/agents/processors#error-processors-are-enabled-by-default)。Agent 級別的空 `errorProcessors` 列表仍會使用預設處理器；呼叫時傳入 `errorProcessors: []` 則會替換已解析的列表，但 Agent 仍會運行 Memory 提供的錯誤處理器。若為全部三個預設 id 提供自己的處理器，就會用這些實現替代所有預設處理器。

## 工作原理 {/* #how-it-works */}

處理器按以下順序檢查錯誤及其原因鏈：

- 匹配器結果：任一已設定的匹配器傳回 `true`
- 內置的 OpenAI Responses 流錯誤匹配規則
- Provider 重試元數據：`isRetryable === true`

首個匹配結果決定重試策略。因此，即使內置匹配器也能匹配，同樣會採用先匹配的自訂匹配器的 `maxRetries`、`delayMs` 和 `onRetry`。

錯誤可重試時，處理器傳回 `{ retry: true }`，不會修改訊息。

除非你自己的匹配器匹配到該錯誤，否則即使 Provider 元數據將其標記為可重試，處理器也絕不會重試憑證或配額被拒絕的錯誤。AI SDK 會將所有 `429` 錯誤標記為可重試，包括配額耗盡的情況。

設定 `delayMs` 後，處理器會先等待，再發出重試信號。對於 `ECONNRESET` 這類暫時性網絡錯誤，這很有用，因為立即重試很可能再次失敗。延遲時間可以是固定毫秒數，也可以是使用錯誤參數計算的函數，例如用於實現指數退避。

### 重試次數限制 {/* #retry-limits */}

`maxRetries` 預設為 `1`，限制此處理器請求重試的次數。Agent 還透過 `maxProcessorRetries` 限制處理器重試次數。設定了錯誤處理器但未設定 Agent 上限時，運行時上限為 `3`。

如果需要統一的重試預算，請將兩個值明確設為相同的有限值。同時將該次呼叫的模型 `maxRetries` 設為 `0`，避免 Provider 嘗試次數疊加。

### `Retry-After` 處理 {/* #retry-after-handling */}

對於帶有 `Retry-After` 回應標頭的可重試錯誤，處理器會沿錯誤原因鏈讀取不區分大小寫的相對秒數或 HTTP 日期，並在 `delayMs` 與設定上限後的伺服器端延遲中取較長時間等待。

`maxRetryAfterMs` 預設為 `30_000`，只限制 Provider 給出的等待時間；明確設定的較長 `delayMs` 不受影響。無效或已過期的回應標頭會被忽略。

## 重試未知錯誤 {/* #retry-unknown-errors */}

設定 `retryUnknownErrors` 後，對於自訂匹配器、Provider 元數據和內置 OpenAI 匹配器均未確定策略的錯誤，也會進行重試。無論是否啟用 `retryUnknownErrors`，自訂匹配器都會重試它所匹配的錯誤。未知錯誤重試使用處理器級別的 `maxRetries` 和 `delayMs`。已知的憑證及配額拒絕錯誤（包括 HTTP `401` 和 `403` 回應）不會被當作未知錯誤重試；但匹配到它們的自訂匹配器仍會重試：

```typescript title="src/mastra/agents/resilient-agent.ts"
import { Agent } from '@mastra/core/agent'
import { StreamErrorRetryProcessor } from '@mastra/core/processors'

export const agent = new Agent({
  id: 'resilient-agent',
  name: 'Resilient agent',
  instructions: 'You are a helpful assistant.',
  model: '__GATEWAY_OPENAI_MODEL_BASE__',
  errorProcessors: [
    new StreamErrorRetryProcessor({
      retryUnknownErrors: true,
      maxRetries: 2,
      delayMs: 3000,
    }),
  ],
})
```

具體的匹配器策略仍優先於未知錯誤的設定。此選項預設為 `false`，因此只有明確啟用後才會重試未知錯誤。

## 延遲重試 {/* #delaying-retries */}

透過自訂匹配器配合 `delayMs`，可在等待一段時間後重試暫時性的網絡連線重置：

```typescript title="src/mastra/agents/resilient-agent.ts"
import { Agent } from '@mastra/core/agent'
import { StreamErrorRetryProcessor } from '@mastra/core/processors'

const isECONNRESET = (error: unknown) => {
  if (!error || typeof error !== 'object') return false
  const code = (error as { code?: unknown }).code
  if (typeof code === 'string' && code.toUpperCase() === 'ECONNRESET') return true
  const message = error instanceof Error ? error.message : undefined
  return typeof message === 'string' && /econnreset|socket hang up/i.test(message)
}

export const agent = new Agent({
  id: 'resilient-agent',
  name: 'resilient-agent',
  instructions: 'You are a helpful assistant.',
  model: '__GATEWAY_OPENAI_MODEL_BASE__',
  errorProcessors: [
    new StreamErrorRetryProcessor({
      maxRetries: 2,
      delayMs: ({ retryCount }) => Math.min(1000 * 2 ** retryCount, 30000),
      matchers: [isECONNRESET],
    }),
  ],
})
```

## 預設的 OpenAI Responses 匹配器 {/* #default-openai-responses-matcher */}

`isRetryableOpenAIResponsesStreamError` 會匹配 `type: 'error'` 或 `type: 'response.failed'` 的 OpenAI Responses 流錯誤資料區塊。它使用 `@mastra/core/error` 中共用的 Provider 失敗資訊讀取器解析每個資料區塊，並重試報告了速率限制、Provider 服務中斷或超時的錯誤。作為後備規則，它也會重試明確提示可以重試的錯誤，例如 `You can retry your request`。憑證或配額拒絕錯誤絕不會重試。

`StreamErrorRetryProcessor` 預設包含此匹配器。你也可以將其導入，在自訂重試邏輯中復用。
