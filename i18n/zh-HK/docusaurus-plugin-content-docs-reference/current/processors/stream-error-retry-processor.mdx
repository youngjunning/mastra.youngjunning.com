# 流錯誤重試處理器

`StreamErrorRetryProcessor`是一個**錯誤處理器**重試暫時的 LLM API 和流失敗。它包括針對 OpenAI 回應流錯誤的內建匹配，並支援針對其他特定於提供者的錯誤形狀的附加匹配器。

Mastra 將此處理器添加到每個Agent的`errorProcessors` by default, last, after the `ProviderHistoryCompat`, `PrefillErrorHandler`， 和`UnsupportedFileHandler`預設情況下，因此修復請求的處理器在該請求保持不變重試之前就有機會。預設實例使用`maxRetries: 2`與內建匹配一起使用連接重置匹配器，並且它不會重試未知錯誤或重播修復處理器無法修復的錯誤請求（HTTP 400）回應。提供您自己的實例`errorProcessors`改變其政策。因為只有在預設情況下才會加入預設值`id`您的清單中缺少該實例，您的實例已被使用，並且預設實例未新增到它旁邊。

## 使用範例 {/* #usage-example */}

配置`StreamErrorRetryProcessor`. Supplying the same `id` means the default isn't added:

```typescript title="src/mastra/agents/openai-agent.ts"
import { Agent } from '@mastra/core/agent'
import { StreamErrorRetryProcessor } from '@mastra/core/processors'

export const agent = new Agent({
  id: 'openai-agent',
  name: 'openai-agent',
  instructions: 'You are a helpful assistant.',
  model: '__GATEWAY_OPENAI_MODEL_BASE__',
  errorProcessors: [new StreamErrorRetryProcessor({ maxRetries: 5 })],
  maxProcessorRetries: 5,
})
```

放`maxProcessorRetries` alongside a `maxRetries` above `3`, because the agent stops error-processor retries at `3` when it's unset. See [Retry limits](#retry-limits).

若要僅執行您配置的處理器，而不合併任何預設值，請設定`errorProcessorDefaults: false`. Without an `errorProcessors` list, the agent then runs only the error processors its memory contributes, if any. When memory contributes one, the retry cap of `3` applies. See [Error processors are enabled by default](/docs/agents/processors#error-processors-are-enabled-by-default). An empty agent-level `errorProcessors` list still gets the defaults. A call-time `errorProcessors: []` replaces the resolved list instead, though the agent still runs the error processors its memory contributes. Supplying your own processor for all three default ids replaces every default with your own implementation.

## 它是如何運作的 {/* #how-it-works */}

處理器會依以下順序檢查錯誤及其原因鏈：

* 匹配器結果：任何傳回的配置匹配器`true`
* 內建 OpenAI Responses 流錯誤匹配
* 提供者重試元數據：`isRetryable === true`

第一個匹配決定重試策略，因此配置的匹配器的`maxRetries`, `delayMs` and `onRetry` apply even when the built-in matcher would also match.

當錯誤可重試時，處理器返回`{ retry: true }`. It doesn't mutate messages.

除非您自己的匹配器之一與之匹配，否則處理器永遠不會重試憑證或配額拒絕，即使提供程式元資料將其標記為可重試也是如此。 AI SDK標記了每一個`429` retryable, including an exhausted quota.

什麼時候`delayMs` is set, the processor waits before signaling a retry. This is useful for transient network errors like `ECONNRESET` where immediately retrying is likely to fail again. The delay can be a fixed number of milliseconds or a function evaluated with the error args (for example, to implement exponential backoff).

### 重試限制 {/* #retry-limits */}

`maxRetries`預設為`1` and limits this processor's retry requests. The agent also limits processor retries with `maxProcessorRetries`. When error processors are configured without an agent limit, the runtime cap is `3`.

當您需要單一重試預算時，將這兩個值明確設定為相同的界限值。保留模型`maxRetries` at `0` for that call to avoid multiplying provider attempts.

### `Retry-After`處理 {/* #retry-after-handling */}

對於可重試的錯誤`Retry-After` response header, the processor reads case-insensitive delta-seconds and HTTP-date values through the error cause chain. It waits for the longer of `delayMs` and the bounded server delay.

`maxRetryAfterMs`預設為`30_000`. It caps only provider-provided wait time. A longer explicit `delayMs` remains unchanged. Invalid or expired headers are ignored.

## 重試未知錯誤 {/* #retry-unknown-errors */}

放`retryUnknownErrors` to retry errors that no custom matcher, provider metadata, or built-in OpenAI matcher selects a policy for. Custom matchers retry the errors they match whether or not `retryUnknownErrors` is enabled. Unknown-error retries use the processor-level `maxRetries` and `delayMs` values. Known credential and quota refusals, including HTTP `401` and `403` responses, aren't retried as unknown errors. A custom matcher that matches them still retries them:

```typescript title="src/mastra/agents/resilient-agent.ts"
import { Agent } from '@mastra/core/agent'
import { StreamErrorRetryProcessor } from '@mastra/core/processors'

export const agent = new Agent({
  id: 'resilient-agent',
  name: 'Resilient agent',
  instructions: 'You are a helpful assistant.',
  model: '__GATEWAY_OPENAI_MODEL_BASE__',
  errorProcessors: [
    new StreamErrorRetryProcessor({
      retryUnknownErrors: true,
      maxRetries: 2,
      delayMs: 3000,
    }),
  ],
})
```

特定的匹配器策略仍然優先於未知錯誤值。該選項預設為`false`, so unknown errors aren't retried unless you enable it.

## 延遲重試 {/* #delaying-retries */}

使用`delayMs` with a custom matcher to retry transient network resets with a wait:

```typescript title="src/mastra/agents/resilient-agent.ts"
import { Agent } from '@mastra/core/agent'
import { StreamErrorRetryProcessor } from '@mastra/core/processors'

const isECONNRESET = (error: unknown) => {
  if (!error || typeof error !== 'object') return false
  const code = (error as { code?: unknown }).code
  if (typeof code === 'string' && code.toUpperCase() === 'ECONNRESET') return true
  const message = error instanceof Error ? error.message : undefined
  return typeof message === 'string' && /econnreset|socket hang up/i.test(message)
}

export const agent = new Agent({
  id: 'resilient-agent',
  name: 'resilient-agent',
  instructions: 'You are a helpful assistant.',
  model: '__GATEWAY_OPENAI_MODEL_BASE__',
  errorProcessors: [
    new StreamErrorRetryProcessor({
      maxRetries: 2,
      delayMs: ({ retryCount }) => Math.min(1000 * 2 ** retryCount, 30000),
      matchers: [isECONNRESET],
    }),
  ],
})
```

## 預設 OpenAI 響應匹配器 {/* #default-openai-responses-matcher */}

`isRetryableOpenAIResponsesStreamError`將 OpenAI 響應流錯誤塊與`type: 'error'` or `type: 'response.failed'`. It reads each chunk with the shared provider-failure reader from `@mastra/core/error` and retries chunks that report a rate limit, a provider outage, or a timeout. As a fallback, it retries errors with explicit retry guidance such as `You can retry your request`. It never retries a credential or quota refusal.

`StreamErrorRetryProcessor`預設情況下包含此匹配器。您也可以匯入它並在自訂重試邏輯中重複使用它。
