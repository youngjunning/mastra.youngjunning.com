# MastraAuthAuth0 類

`MastraAuthAuth0` 類通過 Auth0 為 Mastra 提供身份驗證。它使用 Auth0 簽發的 JWT 驗證傳入請求，並通過 `auth` 選項接入 Mastra 伺服器。

## 使用例子 {/* #usage-example */}

```typescript title="src/mastra/index.ts"
import { Mastra } from '@mastra/core'
import { MastraAuthAuth0 } from '@mastra/auth-auth0'

export const mastra = new Mastra({
  server: {
    auth: new MastraAuthAuth0({
      domain: process.env.AUTH0_DOMAIN,
      audience: process.env.AUTH0_AUDIENCE,
    }),
  },
})
```

:::note

如果已設置必需的環境變量 `AUTH0_DOMAIN` 和 `AUTH0_AUDIENCE`，可以省略構造函數參數，直接使用 `new MastraAuthAuth0()`。

:::

## 預設授權行為 {/* #default-authorization-behavior */}

預設情況下，`MastraAuthAuth0` 驗證 Auth0 JWT，並允許所有已認證用戶訪問：

1. **憑證驗證**：使用 Auth0 的公钥 (JWKS) 驗證 JWT 憑證
2. **簽名驗證**：確保憑證由您的 Auth0 租戶簽名
3. **過期檢查**：驗證憑證尚未過期
4. **受眾驗證**：確認憑證是针對您的 API（audience）簽發的
5. **簽發者驗證**：確保憑證由您的 Auth0 網域簽發

所有驗證通過後，用戶即獲得授權。如需實現基於角色的訪問控制等自訂邏輯，請提供 `authorizeUser` 函數。

## Auth0 用戶類型 {/* #auth0-user-type */}

`Auth0User` 類型在 `authorizeUser` 函數中對應解碼後的 JWT 載荷，通常包含：

* `sub`：用戶的唯一標識符（subject）
* `email`：用戶的電子郵件地址（如果包含在憑證中）
* `email_verified`: 郵箱是否驗證
* `name`：用戶的顯示名稱（如果有）
* `picture`：用戶個人資料圖片的 URL（如果有）
* `iss`：憑證頒發者（您的 Auth0 域）
* `aud`：憑證受眾（您的 API 標識符）
* `iat`：憑證簽發時間戳
* `exp`: 憑證過期時間戳
* `scope`：憑證獲授的 scope
* 在 Auth0 租戶中設定的自訂 claim和應用程序元數據

可用的確切屬性取決於您的 Auth0 設定、請求的 scope，以及您設定的任何自訂 claim。

已驗證用戶的 `id` 取自憑證的 `id` claim；若憑證沒有該 claim，則取自 `sub` claim。沒有 `id` 時，同樣適用這項回退規則。RBAC 按 `id` 查找角色；除非設定了 `mapUserToResourceId`，用戶建立的記錄也歸屬於此識別碼。參閱 [JWT Provider 的用戶 ID](/docs/guides/authentication-identity#user-ids-from-jwt-providers)。
