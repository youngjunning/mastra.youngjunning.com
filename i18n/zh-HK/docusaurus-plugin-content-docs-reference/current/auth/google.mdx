# MastraAuthGoogle 與 MastraRBACGoogle 類別

## MastraAuthGoogle 類別 {/* #mastraauthgoogle-class */}

`MastraAuthGoogle` 類別使用 Google Workspace 為 Mastra 提供身分驗證。它透過加密的工作階段 cookie 實現 OAuth 2.0 / OIDC 登入流程，並驗證 Google ID 權杖；透過 `auth` 選項與 Mastra 伺服器整合。

### 使用範例 {/* #usage-example */}

```typescript title="src/mastra/index.ts"
import { Mastra } from '@mastra/core'
import { MastraAuthGoogle } from '@mastra/auth-google'

export const mastra = new Mastra({
  server: {
    auth: new MastraAuthGoogle({
      clientId: process.env.GOOGLE_CLIENT_ID,
      clientSecret: process.env.GOOGLE_CLIENT_SECRET,
      redirectUri: process.env.GOOGLE_REDIRECT_URI,
      allowedDomains: ['example.com'],
    }),
  },
})
```

:::note

如果已設定所需的環境變數，可以省略建構函式參數，直接使用 `new MastraAuthGoogle()`。

:::

### 認證流程 {/* #authentication-flow */}

`MastraAuthGoogle` 按以下順序驗證請求：

1. **工作階段 cookie**：啟用 SSO 後，提供者會讀取並解密加密的工作階段 cookie。工作階段有效且尚未過期時，用戶即通過身分驗證。
2. **Google ID 權杖後備驗證**：如沒有有效的工作階段 cookie，則透過 Google 的 JWKS 端點驗證 `Authorization` 標頭中的權杖。

完成身分驗證後，`authorizeUser` 會檢查用戶是否具有有效的 Google 用戶 ID，以及權杖的到期時間是否尚未屆滿；如設定了網域限制，還會檢查已驗證的 `hd` 聲明是否與 `allowedDomains` 相符。

### 認證方式 {/* #authentication-methods */}

#### `authenticateToken(token, request?)` {/* #authenticatetokentoken-request */}

驗證 Google ID 權杖。啟用 SSO 後，此方法會先檢查加密的工作階段 cookie，再驗證 Bearer 權杖。

```typescript
const user = await auth.authenticateToken(idToken, request)
```

傳回：`Promise<GoogleUser | null>`

#### `getCurrentUser(request)` {/* #getcurrentuserrequest */}

從工作階段 cookie 或 Bearer Google ID 權杖取得已通過身分驗證的用戶。

```typescript
const user = await auth.getCurrentUser(request)
```

傳回：`Promise<GoogleUser | null>`

#### `authorizeUser(user)` {/* #authorizeuseruser */}

傳回 `true` 的條件是：用戶具有 ID、權杖尚未過期，且在設定了網域限制時符合 `allowedDomains`。

```typescript
const allowed = auth.authorizeUser(user)
```

傳回：`boolean`

#### `getUser(userId)` {/* #getuseruserid */}

傳回 `null`。Google ID 權杖會直接驗證，因此此提供者不會按 ID 查詢用戶。

```typescript
const user = await auth.getUser(userId)
```

傳回：`Promise<GoogleUser | null>`

## MastraRBACGoogle 類別 {/* #mastrarbacgoogle-class */}

`MastraRBACGoogle` 類別將 Google Workspace 群組對應至 Mastra 權限。它透過 Google Admin SDK Directory API 取得用戶群組，並根據可設定的角色對應解析權限。它可配合 `MastraAuthGoogle` 或其他身分驗證提供者使用。

:::note

RBAC 在正式環境中需要 Mastra Enterprise Edition (EE) 授權；開發環境毋須授權。詳見[需要 EE 授權的功能](/docs/license#what-requires-an-ee-license)。如需更多資訊，請[聯絡銷售團隊](https://mastra.ai/contact)。

:::

### 使用範例 {/* #usage-example-1 */}

將 `MastraRBACGoogle` 傳入 `rbac` 選項，即可配合身分驗證提供者使用：

```typescript title="src/mastra/index.ts"
import { Mastra } from '@mastra/core'
import { MastraAuthGoogle, MastraRBACGoogle } from '@mastra/auth-google'

export const mastra = new Mastra({
  server: {
    auth: new MastraAuthGoogle(),
    rbac: new MastraRBACGoogle({
      serviceAccount: {
        clientEmail: process.env.GOOGLE_SERVICE_ACCOUNT_EMAIL!,
        privateKey: process.env.GOOGLE_SERVICE_ACCOUNT_PRIVATE_KEY!,
        subject: process.env.GOOGLE_WORKSPACE_ADMIN_EMAIL!,
      },
      roleMapping: {
        'admins@example.com': ['*'],
        'engineering@example.com': ['agents:*', 'workflows:*', 'tools:*'],
        'viewers@example.com': ['agents:read', 'workflows:read'],
        _default: [],
      },
    }),
  },
})
```

如要將 Google Workspace RBAC 與其他身分驗證提供者配合使用，請傳入 `getUserKey` 函式，從該提供者的用戶物件取得 Google Directory API 用戶鍵值：

```typescript title="src/mastra/index.ts"
import { Mastra } from '@mastra/core'
import { MastraAuthAuth0 } from '@mastra/auth-auth0'
import { MastraRBACGoogle } from '@mastra/auth-google'

export const mastra = new Mastra({
  server: {
    auth: new MastraAuthAuth0(),
    rbac: new MastraRBACGoogle({
      getUserKey: user => user.email,
      serviceAccount: {
        clientEmail: process.env.GOOGLE_SERVICE_ACCOUNT_EMAIL!,
        privateKey: process.env.GOOGLE_SERVICE_ACCOUNT_PRIVATE_KEY!,
        subject: process.env.GOOGLE_WORKSPACE_ADMIN_EMAIL!,
      },
      roleMapping: {
        'engineering@example.com': ['agents:*', 'workflows:*'],
        'admins@example.com': ['*'],
        _default: [],
      },
    }),
  },
})
```

### RBAC 方法 {/* #rbac-methods */}

#### `getRoles(user)` {/* #getrolesuser */}

傳回用戶的 Google Workspace 群組角色 ID。

```typescript
const roles = await rbac.getRoles(user)
```

傳回：`Promise<string[]>`

#### `getPermissions(user)` {/* #getpermissionsuser */}

傳回根據 Google Workspace 群組和 `roleMapping` 解析出的 Mastra 權限。

```typescript
const permissions = await rbac.getPermissions(user)
```

傳回：`Promise<string[]>`

#### `hasPermission(user, permission)` {/* #haspermissionuser-permission */}

檢查用戶是否具有指定權限。

```typescript
const canReadAgents = await rbac.hasPermission(user, 'agents:read')
```

傳回：`Promise<boolean>`

#### `hasRole(user, role)` {/* #hasroleuser-role */}

檢查用戶是否具有指定的 Google Workspace 群組角色。

```typescript
const isAdmin = await rbac.hasRole(user, 'admins@example.com')
```

傳回：`Promise<boolean>`

#### `hasAllPermissions(user, permissions)` {/* #hasallpermissionsuser-permissions */}

檢查用戶是否具有所有指定權限。

```typescript
const canManageAgents = await rbac.hasAllPermissions(user, ['agents:read', 'agents:update'])
```

傳回：`Promise<boolean>`

#### `hasAnyPermission(user, permissions)` {/* #hasanypermissionuser-permissions */}

檢查用戶是否至少具有一項指定權限。

```typescript
const canReadSomething = await rbac.hasAnyPermission(user, ['agents:read', 'workflows:read'])
```

傳回：`Promise<boolean>`

#### `getAvailableRoles()` {/* #getavailableroles */}

傳回 `roleMapping` 中設定的角色 ID，不包括 `_default`。

```typescript
const roles = await rbac.getAvailableRoles()
```

傳回：`Promise<{ id: string; name: string }[]>`

#### `getPermissionsForRole(roleId)` {/* #getpermissionsforroleroleid */}

傳回為指定角色 ID 設定的權限。

```typescript
const permissions = await rbac.getPermissionsForRole('engineering@example.com')
```

傳回：`Promise<string[]>`

#### `clearCache()` {/* #clearcache */}

清除所有已快取的 Google Workspace 群組查詢結果。

```typescript
rbac.clearCache()
```

傳回：`void`

#### `clearUserCache(userKey)` {/* #clearusercacheuserkey */}

清除指定 Directory API 用戶鍵值（例如電郵地址）的群組查詢快取。

```typescript
rbac.clearUserCache('user@example.com')
```

傳回：`void`

#### `getCacheStats()` {/* #getcachestats */}

傳回目前群組查詢快取的項目數及最大容量。

```typescript
const stats = rbac.getCacheStats()
```

傳回：`{ size: number; maxSize: number }`

### 附加配置 {/* #additional-configuration */}

`MastraRBACGoogle` 使用 `GET https://admin.googleapis.com/admin/directory/v1/groups?userKey=...` 並處理分頁。在正式環境部署 Google Workspace 時，請提供具備全網域委派權限的服務帳戶；如應用程式已管理 Google API 權杖，亦可傳入 `accessToken` 或 `getAccessToken`。

如 `user.groups` 已是陣列，`MastraRBACGoogle` 會直接使用該值，不會呼叫 Directory API。空的 `groups` 陣列表示用戶沒有 Google 群組角色；如設定了 `_default`，則使用 `_default` 權限。

`MastraRBACGoogle` 不會自動讀取服務帳戶環境變數。請透過 `serviceAccount` 選項傳入服務帳戶憑證，或傳入 `accessToken` / `getAccessToken`。
