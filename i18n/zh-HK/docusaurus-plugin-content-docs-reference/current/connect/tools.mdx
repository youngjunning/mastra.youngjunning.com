# tools()

返回解析器，供你取得已連線至 Mastra 平台項目的各 Provider 工具。將其傳給 Agent 的 `tools` 選項後，Mastra 每次執行 `generate()` 或 `stream()` 都會呼叫它。解析器依 `ttlMs` 緩存工具；緩存過期後的下一次呼叫會在後台刷新。

```typescript title="src/mastra/agents/ops.ts"
import { Agent } from '@mastra/core/agent'
import { tools } from '@mastra/connect'

export const opsAgent = new Agent({
  id: 'ops',
  name: 'ops',
  instructions: 'You help the team track work in Linear and GitHub.',
  model: '__GATEWAY_OPENAI_MODEL_LUNA__',
  tools: tools(),
})
```

返回：`ToolsResolver`，一個生成扁平工具記錄的解析器，記錄以工具鍵（例如 `linear_create_issue`）為索引。參見[解析器](#the-resolver)。

如需開始使用，參見 [Connect](/docs/mastra-platform/connect#add-tools-to-an-agent)。

### 按請求設定 {/* #per-request-options */}

傳入回調函式而非選項物件，即可按請求調整選項，例如按角色篩選工具或設定核准政策。每次解析都會執行回調函式（可為同步或非同步），並傳入 Mastra 提供給解析器的相同上下文；其中的 `requestContext` 會在解析器用作 Agent 的 `tools` 選項時填入：

```typescript
const connected = tools(ctx => ({
  providers: {
    linear:
      ctx?.requestContext?.get('role') === 'viewer'
        ? { allowTools: ['linear_list_*'] }
        : { requireApproval: ['linear_delete_*'] },
  },
}))
```

解析器會按不同的選項值分別緩存快照，因此選項相同的請求會共用緩存，並遵循 `ttlMs` 及過期時先返回舊值、在後台重新驗證的行為。不同呼叫返回的選項只要結構相同，即視為同一值；但自訂的 `client.fetch` 等無法序列化的值會按身分比對。解析器最多保留 32 種選項值的緩存，超出時淘汰最近最少使用的一種。因此應以角色等有限輸入推導選項，避免使用無上限的請求數據。

使用回調函式時，選項驗證會在首次解析出該選項值時進行，而非呼叫 `tools()` 時；驗證失敗會使該次解析失敗。`refresh()` 會取得回調函式在沒有傳入上下文時所返回的選項資料（與直接呼叫 `await connected()` 使用的變體相同）；`disconnect()` 則會關閉所有已緩存的變體。

## 解析器 {/* #the-resolver */}

返回的 `ToolsResolver` 會緩存工具。距上次獲取未超過 `ttlMs` 時，直接返回緩存。過期後的首次呼叫仍會立即返回緩存，同時啓動從平台後台獲取數據的任務（過期時返回舊值並重新驗證）。刷新成功後，後續呼叫使用新快照；刷新失敗則繼續使用緩存。只有呼叫解析器才會觸發刷新，不會空閒輪詢。可呼叫 `await connected.refresh()` 等待獲取新工具記錄。

如果需要普通的工具記錄，例如在生成時傳給 `toolsets` 選項，可直接呼叫解析器：

```typescript
import { tools } from '@mastra/connect'

const connected = tools()

const response = await agent.generate('Summarize my open issues.', {
  toolsets: { connect: await connected() },
})
```

解析器還提供以下手動控制方法：

- `refresh()` 立即從平台擷取資料，然後更新緩存並返回工具記錄。若平台擷取失敗，Promise 會被拒絕。
- `disconnect()` 清除緩存快照，並關閉此解析器底層狀態的 MCP 傳輸。選項相同的解析器共用該狀態，因此也會一併斷線。之後解析時會重建狀態；先前返回的 MCP 工具會在下次呼叫時重新連線。
- `with(extra)` 返回新解析器，將額外工具併入每次解析結果；工具鍵衝突時以額外工具為準。它接受靜態工具記錄或同步／非同步函式，也支援鏈式呼叫。若要在 `tools` 回調函式中展開解析結果來完成同樣的合併，請參見[將工具加入 Agent](/docs/mastra-platform/connect#add-tools-to-an-agent)。
- `codeMode(options)` 透過 [Code Mode](#code-mode) 提供這些工具。

如果需要按工具鍵之外的條件篩選，或依據選項無法表達的數據篩選，可在 Agent 的 `tools` 函式中對解析結果做後處理。請在函式外創建一次解析器，以便共享緩存：

```typescript title="src/mastra/agents/ops.ts"
import { Agent } from '@mastra/core/agent'
import { tools } from '@mastra/connect'

const connectTools = tools({ providers: ['linear'] })
const viewerTools = new Set(['linear_list_issues'])

export const opsAgent = new Agent({
  id: 'ops',
  name: 'ops',
  instructions: 'You help the team track work in Linear.',
  model: '__GATEWAY_OPENAI_MODEL_LUNA__',
  tools: async ctx => {
    const all = await connectTools(ctx)

    if (ctx.requestContext?.get('role') === 'admin') {
      return all
    }
    return Object.fromEntries(Object.entries(all).filter(([key]) => viewerTools.has(key)))
  },
})
```

只有 `admin` 角色可使用所有工具。其他角色或未設定角色時，只能使用 viewer 子集。請在受信任的伺服器端程式碼中根據已認證用戶設定 `role`。[按渠道調整工具](/reference/connect/channels#vary-tools-by-channel)對渠道消息採用相同模式。

錯誤處理取決於原因：

- 設定錯誤（缺少項目 ID 或令牌、Provider ID 格式有誤、同一層級同時設定 `allowTools` 與 `disallowTools`、`ttlMs` 無效）會在呼叫 `tools()` 時拋出。使用[回調函式形式](#per-request-options)時，則會在首次解析出無效選項時失敗。
- 若平台目錄確認某個已啟用的 Provider ID 不存在，解析會以 `invalid_options` 失敗。個別 Provider 的篩選條件中有未知工具鍵或零相符項目的萬用字元時也一樣。若無法連線至目錄，未知 ID 只會記錄警告並略過。
- 若緩存中已有快照，後台更新失敗時解析器會繼續提供緩存中的工具集並發出警告；只有從未緩存過資料時才會拒絕請求。
- 單一 Provider 有問題（例如連線需要重新授權）時，會記錄警告並略過該 Provider；其他 Provider 的工具仍會載入。

## Code Mode {/* #code-mode */}

`codeMode()` 透過 [Code Mode](/docs/agents/code-mode) 向 Agent 提供已連線的工具：Agent 編寫一個 TypeScript 程式，以 `external_*` 函式呼叫工具，而非每個工具呼叫都佔用獨立步驟。當任務需要跨多個呼叫或 Provider 執行操作時可使用它，例如先列出一個 Provider 的條目，再到另一個 Provider 中逐一查詢。

```typescript title="src/mastra/agents/ops.ts"
import { Agent } from '@mastra/core/agent'
import { LocalSandbox } from '@mastra/core/workspace'
import { tools } from '@mastra/connect'

const code = tools({ providers: ['linear', 'slack'] }).codeMode({ sandbox: new LocalSandbox() })

export const opsAgent = new Agent({
  id: 'ops',
  name: 'ops',
  instructions: async ctx => ['You help the team track work.', await code.instructions(ctx)],
  model: '__GATEWAY_OPENAI_MODEL_LUNA__',
  tools: code.tools,
})
```

:::warning

`LocalSandbox` 會以具有宿主機權限的 `node` 行程執行模型編寫的程式。已連線工具返回的第三方數據（例如 Issue 文本）可能影響模型生成的程式碼。僅在受信任或本地開發場景使用 `LocalSandbox`。有關隔離方案，請參見 [Code Mode 工作原理](/docs/agents/code-mode#how-it-works)。

:::

`codeMode()` 返回 `tools` 和 `instructions` 兩個函式，都需要傳給 Agent。與解析器一樣，它們會在每次請求時解析當前連線。隨著 Provider 連線或斷開，程式可呼叫的函式也會變化。同一請求中，兩者使用同一次解析結果，指令不會宣告程式無法呼叫的函式。

此方法接受所有 [`createCodeMode()` 選項](/reference/tools/create-code-mode)，但不包括 `tools`；可用選項為 `sandbox`、`timeout`、`id`。此外，還接受 `transport` 以使用[遠端沙箱](/docs/agents/code-mode#remote-sandboxes)或[行程內隔離](/docs/agents/code-mode#in-process-isolation)，以及 `toolSearch` 以啟用[工具搜尋](#tool-search)。所有解析器都支持此方法，包括回調形式及 `with()` 返回的解析器。透過 `with()` 添加的額外工具也會成為程式可呼叫的函式。

有些工具會保留為 Agent 直接呼叫的工具，而不成為程式函式，因為它們會暫停 Agent 執行，程式內部無法執行這類呼叫：

- 透過 `requireApproval` 要求核准的工具。Agent 仍會等待用戶核准每次呼叫。
- `request_connection` 工具，讓連線提示能暫停執行，直到用戶完成連線。

對於 [MCP Provider](#mcp-providers)，`requireApproval` 列表會使該 Provider 的**所有**工具保留為直接工具，包括列表中未列出的工具。Mastra 在請求時發現 MCP 工具，並在每次呼叫時核對列表，因此 Code Mode 無法提前判斷哪些呼叫需要核准，於是將該 Provider 的所有工具排除在程式之外。生成的 HTTP 工具則不同，只有匹配列表的工具保留為直接工具。

```typescript
// Every neon-mcp tool stays direct, not just neon-mcp_run_sql
const ops = tools({
  providers: { 'neon-mcp': { requireApproval: ['neon-mcp_run_sql'] } },
}).codeMode({ sandbox })
```

若要讓程式呼叫該 Provider 的其他工具，可用 `disallowTools` 移除受核准限制的工具，而非對其設定核准。若仍需核准，Agent 就必須逐一呼叫該 Provider 的工具。

當沒有可編排的工具（例如項目尚無連線）時，`tools` 只返回直接工具，`instructions` 返回空字串。

### 工具搜尋 {/* #tool-search */}

每次請求都在指令中宣告全部函式會消耗上下文：僅 Linear 約需 4,000 個 Token，Linear、GitHub 和 Stripe 合計超過 20,000 個。啟用工具搜尋後，指令只列出函式名；Agent 會得到 `search_functions` 工具，用於檢索所需函式的 TypeScript 宣告。Agent 可按預期操作或列表中的準確名稱搜尋，再編寫程式。程式仍能呼叫所有函式，只是宣告改為按需檢索。

如果宣告所有函式需要超過約 10,000 個 Token，工具搜尋會自動啟用。也可設定 `toolSearch` 進行選擇：

```typescript title="src/mastra/agents/ops.ts"
// Always list names only and search for declarations
const searching = tools().codeMode({ sandbox: new LocalSandbox(), toolSearch: true })

// Always declare every function up front
const declared = tools().codeMode({ sandbox: new LocalSandbox(), toolSearch: false })
```

## 選擇 Provider {/* #choosing-providers */}

`providers` 的陣列形式是允許列表，只返回列出的 Provider。若不設定此項，則包含所有已連線且具有受支持工具集的 Provider。列出的 Provider 若尚未在項目中建立連線，會先被跳過；連線建立後會自動納入。記錄形式中，`false` 可排除一個 Provider，即使 ID 不匹配任何 Provider 也不會報錯。

使用陣列可將發現範圍限制為指定 Provider；使用記錄則可設定指定 Provider，同時保留其他 Provider：

```typescript
const onlyLinear = tools({ providers: ['linear'] })
const allWithLinearApproval = tools({
  providers: { linear: { requireApproval: true } },
})
```

各 Provider 的 `allowTools` 和 `disallowTools` 工具鍵列於 [Provider 工具集參考](/reference/connect/providers)。

## 連線解析 {/* #connection-resolution */}

對於項目中已有連線的每個 Provider：

1. 顯式設定的 `connectionId` 優先。
1. 否則，若只有一個活動連線，就自動使用它。
1. 否則，不固定連線，並在每次呼叫時選擇：工具集會增加 `<provider>__list_connections` 工具；其他工具都必須提供 `connection_name`；Agent 按 `list_connections` 返回的顯示名稱為每次呼叫選擇連線。若 `connection_name` 不符合任何活躍連線，該次呼叫會以 `unknown_connection` 失敗。

合成的 `list_connections` 輔助工具無需核准；即使頂層 `allowTools` 或 `disallowTools` 篩選條件本會排除它，它仍可使用。

處於 `needs_reauth` 狀態的連線會被跳過並記錄警告，直至有人[重新授權](/reference/cli/mastra#replace-a-connection-that-needs-reauthorization)。

## MCP Provider {/* #mcp-providers */}

除了生成的工具集，解析器還會發現平台目錄中宣告支持 MCP 的已連線 Provider。發現的工具遵循同一扁平契約，以 `<provider-id>_<tool-name>` 作為命名空間。若一個 Provider 同時有生成的工具集和 MCP 能力，優先使用 MCP 目錄。

應用僅傳送自身的平台令牌。在向 Provider 的 MCP 伺服器代理每個協議請求之前，平台會移除呼叫方身份認證，並注入 Provider 憑據。MCP 會話在刷新間復用；連線發生變化、Provider 斷開或呼叫 `disconnect()` 時關閉。

發現的 MCP 工具與生成的工具遵循相同核准策略：預設無需核准，除非設定 `requireApproval`，例如 `'neon-mcp': { requireApproval: ['neon-mcp_run_sql'] }`。傳入已移除的 `autoApproveTools` 鍵會在呼叫時拋出 `invalid_options` 錯誤。

## 環境變數 {/* #environment-variables */}

`tools()`、`channels()` 和 `credential()` 會讀取以下環境變數。程式碼中傳入的選項優先。

| 變數 | 用途 |
| - | - |
| `MASTRA_PLATFORM_ACCESS_TOKEN` | 用於認證每個請求的平台存取令牌 |
| `MASTRA_PLATFORM_SECRET_KEY` | 未設定 `MASTRA_PLATFORM_ACCESS_TOKEN` 時使用的後備令牌 |
| `MASTRA_PROJECT_ID` | 用於獲取連線的項目 ID |
| `MASTRA_ORG_ID` | 組織 ID；設定後透過 `x-organization-id` 請求標頭傳送 |
| `MASTRA_PLATFORM_REGION` | `us` 或 `eu`；選擇 `https://integrations.us.mastra.ai` 或 `https://integrations.eu.mastra.ai`，而非預設的 `https://integrations.mastra.ai` |
| `MASTRA_INTEGRATIONS_API_URL` | Connect API 基礎 URL；覆蓋區域設定 |

## 錯誤 {/* #errors */}

拋出 `MastraConnectError`，其中包含 `code` 屬性：

| 錯誤碼 | 觸發條件 |
| - | - |
| `missing_project_id` | 未設定項目 ID |
| `missing_access_token` | 未設定平台令牌 |
| `invalid_options` | Provider ID 未知或格式錯誤、篩選條件衝突、工具鍵或通配符重復或無匹配項，或 `ttlMs` 無效 |
| `unauthorized` | 平台拒絕令牌（401/403） |
| `proxy_error` | 代理到 Provider 的請求失敗；`status` 和 `detail` 包含 Provider 回應 |
| `unknown_connection` | 工具呼叫傳入的 `connection_name` 不匹配任何活動連線 |
| `platform_error` | 其他平台請求失敗 |
