# 排程

檔案式 Agent 會從自己的 `schedules/` 目錄找出**排程**。每個檔案宣告一項週期性工作：cron 表達式，以及觸發時 Agent 要執行的動作。Mastra 啟動時會將排程註冊到排程儲存空間，無須編寫執行階段註冊程式碼。

本頁介紹檔案式約定。如要在執行階段建立排程，請參閱[排程](/reference/schedules/overview)。

`defineSchedule` 由 `@mastra/core/agent` 重新匯出，因此檔案式 Agent 只需使用一個匯入路徑。`@mastra/core/schedules` 亦會匯出它。

## 快速入門 {/* #quickstart */}

在 Agent 的 `schedules/` 目錄下新增檔案：

```typescript title="src/mastra/agents/support/schedules/heartbeat.ts"
import { defineSchedule } from '@mastra/core/agent'

export default defineSchedule({
  cron: '*/5 * * * *',
  prompt: 'Check system health and report any failures.',
})
```

Mastra 每五分鐘會使用該提示詞執行一次 `support` Agent。

## 排程 ID {/* #schedule-identity */}

排程 ID 是移除副檔名後、相對於 `schedules/` 的路徑。因此，可用巢狀目錄將相關排程分組：

```text title="Schedule layout"
src/mastra/agents/
└── support/
    ├── config.ts
    ├── instructions.md
    └── schedules/
        ├── heartbeat.ts      # id: heartbeat
        ├── cleanup.md        # id: cleanup
        └── billing/
            └── sweep.ts      # id: billing/sweep
```

此 ID 在多次建置之間保持穩定，Mastra 因而能區分修改過的排程及新排程。重新命名或移動檔案，等同刪除舊排程並建立新排程。

`heartbeat.ts` 及 `heartbeat.md` 會得到相同的 ID，因此同時宣告兩個檔案會令建置失敗。

## 執行模式 {/* #execution-modes */}

一項排程必須且只能設定一種執行模式；兩種都設定或都不設定，建置都會失敗。

### Prompt 模式 {/* #prompt-mode */}

`prompt` 會用固定訊息執行所屬 Agent。如排程以執行緒為目標，觸發時會送出喚醒訊號並立即傳回，不等待執行結束，因為執行緒串流的執行階段會繼續執行直至完成。沒有執行緒的排程則會等待 `agent.generate`，直至執行完成才結束。

```typescript title="src/mastra/agents/support/schedules/digest.ts"
import { defineSchedule } from '@mastra/core/agent'

export default defineSchedule({
  cron: '0 9 * * 1',
  timezone: 'America/New_York',
  prompt: 'Summarize last week and post the digest.',
})
```

### Handler 模式 {/* #handler-mode */}

`handler` 會在排程觸發時計算本次觸發的參數。如提示詞取決於目前狀態、某些觸發應略過，或執行需要頻道傳送上下文，請使用它。

```typescript title="src/mastra/agents/support/schedules/billing/sweep.ts"
import { defineSchedule } from '@mastra/core/agent'

export default defineSchedule({
  cron: '0 3 * * *',
  handler: async ({ mastra, agentId }) => {
    const overdue = await findOverdueInvoices()

    // Returning null skips this fire; nothing runs and the trigger is
    // recorded with outcome 'skipped'.
    if (overdue.length === 0) return null

    return {
      prompt: `Chase these overdue invoices: ${overdue.join(', ')}`,
      threadId: 'billing-ops',
      resourceId: agentId,
    }
  },
})
```

Handler 的傳回值會覆寫排程中對應的已儲存欄位。傳回 `undefined` 表示不覆寫，本次觸發會繼續使用已儲存欄位。由於 Handler 模式不能宣告 `prompt`，這會因缺少提示詞而令本次觸發失敗。要執行便傳回 `prompt`；要略過則傳回 `null`。

Handler 是函式，無法持久儲存在排程紀錄中。Mastra 會在排程觸發時，於目前進程中查找對應函式。Handler 模式既未提供亦不能宣告提示詞時，本次觸發會附上原因並失敗，而不會向 Agent 發送空訊息。

在進程內查找，表示執行排程器的進程必須註冊所屬 Agent。一般部署使用單一入口啟動，自然符合此條件。獨立 Worker 則需要與伺服器使用相同入口；如從精簡入口啟動而找不到對應 Handler，觸發會失敗，工作不會執行。

### Markdown 排程 {/* #markdown-schedules */}

`.md` 排程會在 frontmatter 設定 cron，並以文件正文作為提示詞。這屬於 Prompt 模式，適合編寫較長的提示詞：

```markdown title="src/mastra/agents/support/schedules/cleanup.md"
---
cron: '0 3 * * *'
timezone: 'UTC'
name: 'nightly cleanup'
---

Review tickets untouched for 30 days.

Close the ones that are clearly resolved and summarize the rest.
```

cron 表達式一律要加引號。開頭的 `*` 會被 YAML 視為別名，因此 `cron: */5 * * * *` 會解析失敗，而 `cron: "*/5 * * * *"` 可以正常解析。

Frontmatter 接受以下所有選項，但不接受 `handler`：它需要函式，只能寫在 `.ts` 或 `.js` 排程模組中。`prompt` 亦不能設定，因為文件正文就是提示詞。未知的 frontmatter 欄位會令建置失敗，而非被悄悄忽略，因此 `ifIdel` 這類拼寫錯誤會在建置時被發現。

## 在開發環境測試排程 {/* #testing-a-schedule-in-development */}

排程會按 cron 週期觸發，在反覆開發時等待週期並不方便。可改為按 ID 手動觸發：

```bash
# List schedules to find the id
curl http://localhost:4111/api/schedules

# Fire one now, out-of-band from its cron
curl -X POST http://localhost:4111/api/schedules/<scheduleId>/run
```

這會記錄一次 `triggerKind: "manual"` 的觸發，但不會推進 `nextFireAt`，因此不影響正常週期。Studio 亦會列出這些排程及其觸發紀錄。

儲存的 ID 具有命名空間，並經過 URL 編碼。`billing/sweep` 在 `support` Agent 上會變成 `fsa_support__billing%2Fsweep`；請從清單回應複製 ID，不要自行組合。

## 註冊和生命週期 {/* #registration-and-lifecycle */}

Mastra 啟動時會將宣告的排程同步至儲存空間；之後每註冊一個 Agent，亦會再次同步。宣告排程便可啟動排程器，無須設定 `scheduler: { enabled: true }`。

同步會比較每項已宣告排程及其儲存紀錄，只寫入有變更的欄位：

- 新增排程檔案會建立一筆紀錄。
- 修改 `cron` 或 `timezone` 會更新紀錄並重新計算下次觸發時間，因此修改後的排程不會再按舊週期觸發。
- 刪除或重新命名排程檔案會刪除對應紀錄。
- 透過 API 暫停的排程在重新部署後仍保持暫停。同步會刻意保留 `status`。

同步只會刪除目前進程中已註冊 Agent 所屬的紀錄，因此只載入部分 Agent 的進程不會刪除其他 Agent 的排程。如從項目徹底移除某個 Agent，其殘留紀錄會在下次觸發時清理，因為排程器屆時找不到可執行的 Agent。

透過 `mastra.schedules.create(...)` 在執行階段建立的排程位於獨立的命名空間，不受這項同步影響。

## 限制 {/* #limits */}

**只限根 Agent。** 請在最上層 Agent 宣告排程。如將 `schedules/` 目錄放在 `subagents/` 下，建置會失敗：Subagent 連接至父 Agent，不會註冊到 Mastra 實例，排程器因此無法將其識別為目標。請將排程交給父 Agent，再由它委派。

**需要儲存空間。** 排程會以紀錄形式持久儲存，而記憶體儲存中的紀錄無法在重新啟動後保留，因此必須為實例設定[儲存空間](/reference/file-based-agents/storage)。

**託管環境。** 排程器是 Mastra 進程中的背景 Worker，因此主機必須讓該進程持續運作。長時間運作的 Node 伺服器及容器都適用。如環境在請求之間凍結或回收進程（大多數 Serverless 函式平台都是如此），便會錯過排程觸發。此時應改用平台自身的 cron 呼叫執行端點。

**以程式碼定義的 Agent。** 如 Agent 目錄中的 `config.ts` 直接匯出 `new Agent({...})`，Mastra 會原樣使用該 Agent，並在警告後略過其 `schedules/` 目錄。此類 Agent 請使用 `mastra.schedules.create(...)` 建立排程。

## 範例 {/* #example */}

以下 Support Agent 有兩項排程：固定的每週摘要，以及只在有待處理事項時執行的夜間清理。

```text title="Scheduled support agent"
src/mastra/agents/
└── support/
    ├── config.ts
    ├── instructions.md
    └── schedules/
        ├── weekly-digest.md
        └── billing/
            └── sweep.ts
```

```typescript title="src/mastra/agents/support/config.ts"
import { agentConfig } from '@mastra/core/agent'

export default agentConfig({
  model: '__GATEWAY_OPENAI_MODEL__',
})
```

```markdown title="src/mastra/agents/support/schedules/weekly-digest.md"
---
cron: '0 9 * * 1'
timezone: 'America/New_York'
---

Summarize the past week's tickets and post the digest to the team channel.
```

```typescript title="src/mastra/agents/support/schedules/billing/sweep.ts"
import { defineSchedule } from '@mastra/core/agent'

export default defineSchedule({
  cron: '0 3 * * *',
  timezone: 'America/New_York',
  handler: async () => {
    const overdue = await findOverdueInvoices()
    if (overdue.length === 0) return null
    return { prompt: `Draft reminders for ${overdue.length} overdue invoices.` }
  },
})
```
