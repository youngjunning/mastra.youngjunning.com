# 工作室

馬斯特拉配置[Studio](/docs/studio/overview)從一個`studio.ts`直接在下面的文件`src/mastra/`。該文件預設導出一個`StudioConfig`Studio 驗證和授權的物件：誰可以存取 Studio，以及經過驗證的使用者可以執行哪些操作。

使用此页面进行基于文件的约定。有關身分驗證提供者、基於角色的存取控制 (RBAC) 和細粒度授權 (FGA)，請參閱[Studio auth](/docs/studio/auth).

## 快速入門 {/* #quickstart */}

對於本地開發，您不需要`studio.ts`. Start the dev server and open Studio:

```bash npm2yarn
npm run dev
```

Studio 在本機開發中無需身份驗證即可開啟。添加`studio.ts` when you're ready to secure a shared or production deployment.

## 新增身份驗證 {/* #add-authentication */}

使用身份驗證提供者要求使用者先登錄，然後才能存取 Studio。本範例使用[WorkOS](/integrations/auth/workos):

```typescript title="src/mastra/studio.ts"
import { MastraAuthWorkos } from '@mastra/auth-workos'
import type { StudioConfig } from '@mastra/core/server'

export default {
  auth: new MastraAuthWorkos(),
} satisfies StudioConfig
```

身份驗證提供者處理使用者是誰。對於使用者登入後可以執行的操作，請在相同配置中新增 RBAC 或 FGA。看[Studio auth](/docs/studio/auth) for full examples.

## 程式碼優先權 {/* #precedence-with-code */}

程式碼註冊的 Studio 配置獲勝`studio.ts`. Use `studio.ts` when one project-wide Studio config is enough. Use code registration when auth depends on runtime wiring in `src/mastra/index.ts`.
