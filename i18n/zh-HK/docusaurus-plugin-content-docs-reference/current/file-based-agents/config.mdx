# 配置.ts

一個Agent的`config.ts`設定其模型和運行時選項。將其用於屬於[`Agent`](/reference/agents/agent)其本身，而兄弟文件則提供說明、Tool、技能等。

## 屬於什麼`config.ts` {/* #what-belongs-in-configts */}

`config.ts`是基於文件的Agent模型和運行時選項所需的入口點。當Agent不需要自己的文件時，將Agent級設定放在此處，例如模型、描述、預設執行選項、重試行為、記分器和顯示身分。

當您希望基於檔案的路由將相鄰關注點合併到Agent程式中時，請將它們保留在同級檔案中。例如，使用`instructions.md` for the always-on prompt and `tools/` for model-callable actions.

## 快速入門 {/* #quickstart */}

下列`config.ts` plus an `instructions.md` file creates a working file-based agent:

```typescript title="src/mastra/agents/weather/config.ts"
import { agentConfig } from '@mastra/core/agent'

export default agentConfig({
  model: '__GATEWAY_OPENAI_MODEL__',
})
```

```markdown title="src/mastra/agents/weather/instructions.md"
You are a helpful weather assistant. Answer questions about current conditions and forecasts.
```

馬斯特拉使用`weather` directory name as the default agent `id` and `name`. The sibling `instructions.md` supplies the required instructions.

## 設定模型 {/* #set-the-model */}

這`model` field is the only required field in `agentConfig()`. The build fails when an agent directory doesn't provide a model. Other capabilities either come from sibling files or have defaults.

```typescript title="src/mastra/agents/weather/config.ts"
import { agentConfig } from '@mastra/core/agent'

export default agentConfig({
  model: '__GATEWAY_OPENAI_MODEL__',
})
```

## 來自目錄的身份 {/* #identity-from-the-directory */}

基於文件的Agent`id` and `name` default to the directory name. For `src/mastra/agents/weather/`, Mastra registers the agent as `weather` unless you override those fields.

覆蓋`id` or `name` when the stable routing key and the display name should differ.

```typescript title="src/mastra/agents/weather/config.ts"
import { agentConfig } from '@mastra/core/agent'

export default agentConfig({
  id: 'weather-assistant',
  name: 'Weather Assistant',
  model: '__GATEWAY_OPENAI_MODEL__',
})
```

## 設定運行時選項 {/* #set-runtime-options */}

`agentConfig()`接受[`Agent` constructor options](/reference/agents/agent#constructor-parameters), except that `id`, `name`, and sibling-file fields can be supplied by the file-based convention. Use the Agent reference for the full option list.

請注意：

* 基於文件的子Agent需要非空`description` because the parent model uses it for delegation routing.
* `defaultOptions`, `maxRetries`, `scorers`, and other Agent options can live in `config.ts` when they don't need their own file.

## 相鄰設定所在的位置 {/* #where-adjacent-settings-live */}

保持`config.ts` focused on runtime options. Use sibling files for concerns that benefit from their own location.

|設定|檔案或資料夾|為什麼它住在那裡|
| - | - | - |
|說明 |[`instructions.md` or `instructions.ts`](/reference/file-based-agents/instructions) | Keeps the always-on prompt readable as markdown, or computed in TypeScript |
| Tools | [`tools/`](/reference/file-based-agents/tools) | Gives each callable action its own typed module |
| Skills | [`skills/`](/reference/file-based-agents/skills) | Keeps load-on-demand procedures separate from always-on instructions |
| Memory | [`memory.ts`](/reference/file-based-agents/memory) | Configures persistent memory without crowding runtime options |
| Workspace | [`workspace.ts`](/reference/file-based-agents/workspace) | Configures files and sandbox behavior separately from model settings |
| Processors | [`processors/`](/reference/file-based-agents/processors) | Separates input and output processing pipelines |
| Subagents | [`subagents/`](/reference/file-based-agents/subagents) | Gives each specialist child agent its own directory |

## 優先權 {/* #precedence */}

`config.ts`根據以下規則與Agent的其他文件合併：

|網域 |來源A |來源 B |得獎者 |
| - | - | - | - |
|說明 |動態的`config.instructions` | [`instructions.ts` or `instructions.md`](/reference/file-based-agents/instructions) | Dynamic `config.instructions` |
| Instructions | Static `config.instructions` | [`instructions.ts` or `instructions.md`](/reference/file-based-agents/instructions) | The instructions file |
| Instructions | [`instructions.ts`](/reference/file-based-agents/instructions) | [`instructions.md`](/reference/file-based-agents/instructions) | `instructions.ts` |
| Tools | `config.tools` | [`tools/`](/reference/file-based-agents/tools) | Both merge; `config.tools` wins on key collisions |
| Tools | Function `config.tools` | [`tools/`](/reference/file-based-agents/tools) | Function `config.tools`;發現的Tool被忽略|
|技能 |`config.skills` | [`skills/`](/reference/file-based-agents/skills)|兩者合併；`config.skills`名稱衝突獲勝 |
|技能 |功能`config.skills` | [`skills/`](/reference/file-based-agents/skills)|功能`config.skills`;發現技能被忽略|
|內存|`config.memory` | [`memory.ts`](/reference/file-based-agents/memory) | `config.memory`|
|工作空間 |`config.workspace` | [`workspace.ts`](/reference/file-based-agents/workspace) | `config.workspace` |

遺失的`instructions.md`, `instructions.ts`, and `config.instructions` fails the build. Missing both `config.memory` and `memory.ts` leaves the agent without memory.

## 發現生命週期 {/* #discovery-lifecycle */}

基於檔案的原語由 Mastra 捆綁器在下面發現`mastra dev` and `mastra build`. During discovery, Mastra reads supported files under `src/mastra/` and imports TypeScript and JavaScript modules. It also reads markdown instructions and skills. The bundler then copies workspace seed files and registers the assembled primitives with your Mastra app.

發現後，基於文件的Agent正常運行[`Agent`](/reference/agents/agent). Calling it from the Agent API, Studio, workflows, or your application code uses the same runtime as a code-defined agent.

發現是基於來源的且保守的。

它會跳過符號連結、測試檔案和非Agent目錄的目錄。Workflow和單例專案文件僅在具有預設匯出時才進行文件路由。

透過 Mastra CLI 啟動您的應用程序，以便運行發現：

```bash npm2yarn
npx mastra dev
```

如果您匯入您的`mastra` instance directly, `agents/<name>/` directories and the other conventions aren't discovered. When you consume Mastra as a library, register those primitives in code instead.
