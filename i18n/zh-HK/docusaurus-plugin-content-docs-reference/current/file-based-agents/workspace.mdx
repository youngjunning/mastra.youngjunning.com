# Workspace

[Workspace](/docs/sandbox/overview) 整合檔案系統存取及指令執行等功能；已設定的後端決定可用的 Tool。透過 `mastra dev` 或 `mastra build` 找到以檔案設定的 Agent 時，Mastra 會自動提供預設 Workspace。預設 Workspace 包含檔案系統存取及指令執行功能，因此 Agent 毋須額外設定即可讀寫檔案及執行 shell 指令。

本頁介紹以檔案設定 Agent 的慣例。如需了解 Workspace Provider、Tool、搜尋、生命週期及 Sandbox 的詳情，請參閱 [Sandbox](/docs/sandbox/overview)。

## 預設 Workspace {/* #default-workspace */}

若沒有 `workspace.ts`，而建置程序為每個 Agent 提供 Workspace 路徑，以檔案定義的 Agent 就會取得預設 [`Workspace`](/reference/workspace/workspace-class)。預設 Workspace 使用：

- [`LocalFilesystem`](/reference/workspace/local-filesystem)：以 Agent 封裝後的 Workspace 目錄為根目錄。
- [`LocalSandbox`](/reference/workspace/local-sandbox)：使用相同的工作目錄。

這會自動為 Agent 提供檔案 Tool 及 shell Tool。每個 Agent 均有獨立的預設 Workspace；子 Agent 的 Workspace 目錄位於父 Agent 的 Workspace 路徑之下。

## 停用預設 Workspace {/* #disable-the-default-workspace */}

將 `workspace` 設為 `undefined`（在 `config.ts` 中），即可建立沒有 Workspace 的 Agent：

```typescript title="src/mastra/agents/weather/config.ts"
import { agentConfig } from '@mastra/core/agent'

export default agentConfig({
  model: '__GATEWAY_OPENAI_MODEL__',
  workspace: undefined,
})
```

停用 Workspace 後，Agent 不會自動取得檔案 Tool 及 shell Tool。

## 快速開始 {/* #quickstart */}

使用預設 Workspace 時，無須新增檔案。Agent 目錄可以從以下結構開始：

```text title="Default workspace"
src/mastra/agents/weather/
├── config.ts
└── instructions.md
```

只有需要自訂 Workspace 時才新增 `workspace.ts`：

```typescript title="src/mastra/agents/weather/workspace.ts"
import { Workspace, LocalFilesystem, LocalSandbox } from '@mastra/core/workspace'

export default new Workspace({
  name: 'weather-workspace',
  filesystem: new LocalFilesystem({ basePath: './data/weather' }),
  sandbox: new LocalSandbox({ workingDirectory: './data/weather' }),
})
```

完整設定請參閱 [`Workspace` 參考文件](/reference/workspace/workspace-class)。

## 何時自訂 Workspace {/* #when-to-customize-the-workspace */}

預設本機目錄不足以應付需求時，可自訂 Workspace。常見原因包括：

- 讓檔案 Tool 使用其他檔案系統根目錄。
- 在其他 Sandbox Provider 中執行 shell 指令。
- 為 Workspace 加入 BM25 或向量搜尋。
- 讓多個 Agent 共用同一個 Workspace。

有關 Provider 設定方式及執行階段行為，請參閱 [Sandbox 指南](/docs/sandbox/overview)及 [Workspace 搜尋](/docs/sandbox/search)。

## 執行階段界線 {/* #runtime-boundary */}

Workspace 的檔案系統控制檔案 Tool 的存取範圍，Sandbox 則決定 shell 指令在哪裏執行。應用程式的執行階段程式碼（包括 [`tools/`](/reference/file-based-agents/tools) 內的程式碼）仍在應用程式或伺服器程序中執行，除非程式碼明確呼叫 Workspace 或 Sandbox API。

## 初始檔案 {/* #seed-files */}

新增 `workspace/` 目錄即可為 Agent 提供初始檔案。建置時，Mastra 會將 `workspace/` 下的檔案複製到 Agent 預設的執行階段 Workspace；Agent 啟動時，這些檔案已在磁碟上。

```text title="Seed files"
src/mastra/agents/weather/
├── config.ts
└── workspace/
    ├── README.md
    └── data/
        └── cities.json
```

檔案會複製到封裝後的 Workspace 路徑，供 Workspace 檔案 Tool 及 Sandbox 指令讀取。複製時會略過符號連結形式的初始檔案。

## 與 config 的優先順序 {/* #precedence-with-config */}

`config.workspace` 的優先順序高於 `workspace.ts`，即使設為 `undefined` 亦然。否則，Mastra 使用預設的檔案式 Workspace。完整合併規則請參閱 [`config.ts` 優先順序](/reference/file-based-agents/config#precedence)。
