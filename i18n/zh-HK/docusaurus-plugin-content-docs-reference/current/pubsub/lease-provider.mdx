# LeaseProvider

`LeaseProvider` 定義分散式租約契約，與事件傳遞（[`PubSub`](/reference/pubsub/base)）分開。Mastra 的 [signals 層](/docs/signals/overview) 會用它在多個程序（例如Serverless呼叫）之間，為資源（通常是執行緒鍵）選出唯一擁有者。擁有者程序負責喚醒並執行 Agent 串流；其他程序會將後續工作路由給它，而不會啟動相互競爭的執行。

當 Workflow 儲存不支援執行隔離時，[持久化 Agent](/docs/harness/durable-agents#run-ownership) 也會透過租約認領每次執行，讓當機復原時能判斷是否仍有其他程序在執行。

租約與發布／訂閱分開。`LeaseProvider` 實作必須真正協調鎖定，例如使用 Redis 的原子 `SET` 操作或 Lua；單一程序也可以使用記憶體對應表。對於未提供租約能力的後端，signals 執行期間會使用不執行實際操作的 Provider，維持單一程序的行為。

內置的 [`RedisStreamsPubSub`](/reference/pubsub/redis-streams) 實作了 `LeaseProvider`，讓 signals 能在分散式與Serverless部署中跨實例協調。

## 使用範例 {/* #usage-example */}

不需要直接建立 `LeaseProvider`。設定實作此介面的發布／訂閱後端（例如 `RedisStreamsPubSub`）時，請將其傳入 `Mastra` 建構函式，signals 執行期間便會自動用它協調跨程序工作。

```typescript title="src/mastra/index.ts"
import { Mastra } from '@mastra/core'
import { RedisStreamsPubSub } from '@mastra/redis-streams'

export const mastra = new Mastra({
  // RedisStreamsPubSub implements both PubSub and LeaseProvider
  pubsub: new RedisStreamsPubSub({
    url: process.env.REDIS_URL,
  }),
})
```

若要在自訂後端實作租約，請實作下列方法。signals 執行期間會以結構方式偵測此能力（因此可跨 package 邊界運作），且僅在所有方法都存在時使用。

```typescript title="src/mastra/pubsub.ts"
import { PubSub } from '@mastra/core/events'
import type { LeaseProvider } from '@mastra/core/events'

export class CustomPubSub extends PubSub implements LeaseProvider {
  async acquireLease(key: string, owner: string, ttlMs: number) {
    // Atomically claim the lease, or report the current holder.
    return { acquired: true, owner }
  }

  // ...getLeaseOwner, releaseLease, renewLease, transferLease
}
```

## 方法 {/* #methods */}

### 租約操作 {/* #leasing */}

#### `acquireLease(key, owner, ttlMs)` {/* #acquireleasekey-owner-ttlms */}

以原子操作嘗試取得指定鍵的租約。呼叫者取得租約時傳回 `{ acquired: true, owner }`；否則傳回 `{ acquired: false, owner }`，其中 `owner` 是目前持有者，呼叫者可將後續工作路由給它。若持有者不明，例如後端已關閉，或競爭中的租約在讀取前過期，失敗結果可能沒有 `owner`。路由前請先檢查 `owner`。同一擁有者可冪等呼叫 `acquireLease` 來續約或重新認領。

```typescript
const result = await pubsub.acquireLease('thread:abc', runId, 15000)

if (result.acquired) {
  // This process owns the thread, so wake and run the agent.
} else if (result.owner) {
  // result.owner holds the lease, so route the signal to them.
} else {
  // The holder is unknown, so retry acquisition or report the failure instead of dropping the work.
}
```

傳回值：`Promise<{ acquired: boolean; owner?: string }>`

#### `getLeaseOwner(key)` {/* #getleaseownerkey */}

讀取租約目前的擁有者；若租約無人持有，則傳回 `undefined`。

```typescript
const owner = await pubsub.getLeaseOwner('thread:abc')
```

傳回值：`Promise<string | undefined>`

#### `releaseLease(key, owner)` {/* #releaseleasekey-owner */}

釋放租約。如果呼叫者不是目前擁有者，則不執行任何操作：實作會在釋放前以原子方式檢查擁有權，因此不會覆蓋其他擁有者的並行續約。

```typescript
await pubsub.releaseLease('thread:abc', runId)
```

傳回值：`Promise<void>`

#### `renewLease(key, owner, ttlMs)` {/* #renewleasekey-owner-ttlms */}

延長由 `owner` 持有的現有租約的 TTL。續約成功且呼叫者仍持有租約時傳回 `true`；若租約已失效（TTL 到期或由其他擁有者取得），則傳回 `false`。

```typescript
const stillOwned = await pubsub.renewLease('thread:abc', runId, 15000)

if (!stillOwned) {
  // Lost the lease, so stop renewing and let the new owner take over.
}
```

傳回值：`Promise<boolean>`

#### `transferLease(key, fromOwner, toOwner, ttlMs)` {/* #transferleasekey-fromowner-toowner-ttlms */}

以原子方式將現有租約從 `fromOwner` 轉給 `toOwner` 並更新 TTL，過程中不會釋放鍵。這種無間隙操作讓後續擁有者能在目前擁有者完成後立即接管同一鍵。例如，隊列中的後續執行可在執行緒執行結束時接管。若先釋放再取得，鍵會短暫處於無主狀態，競爭程序可能搶先取得租約並啟動衝突的執行。

傳回 `true` 表示 `fromOwner` 仍持有租約，且擁有權已轉給 `toOwner`；若租約已失效，則傳回 `false`，呼叫者此時應重新呼叫 `acquireLease`。

```typescript
const transferred = await pubsub.transferLease('thread:abc', currentRunId, nextRunId, 15000)

if (!transferred) {
  // Lease was lost, so acquire fresh instead.
  await pubsub.acquireLease('thread:abc', nextRunId, 15000)
}
```

傳回值：`Promise<boolean>`

:::警告
無法以原子方式轉移租約的後端，必須盡力先呼叫 `releaseLease(fromOwner)`，再呼叫 `acquireLease(toOwner)`。它們必須註明這次交接不是原子的，因為其他程序可能在兩次呼叫之間認領該鍵。將此方法設為必要項，可讓呼叫者使用同一條程式路徑，同時明確標示各後端對原子性的選擇。
:::

## 能力偵測 {/* #capability-detection */}

signals 執行期間偵測 `LeaseProvider` 時依據結構，而非使用 `instanceof`，因此獨立發布的後端即使解析到另一份 `@mastra/core` 也能被識別。一個值只有作為 `LeaseProvider` 提供全部五個方法（`acquireLease`、`getLeaseOwner`、`releaseLease`、`renewLease`、`transferLease`）時，才會被識別。

當設定的發布／訂閱後端未實作 `LeaseProvider` 時，執行期間會改用永遠判定取得成功、但不執行實際操作的 Provider。每個呼叫者都會贏得自己的租約競爭，而釋放、續約與轉移都不起作用，以維持預期的單一程序行為。
