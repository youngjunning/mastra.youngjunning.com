# UnixSocketPubSub

`UnixSocketPubSub` 是一種 [`PubSub`](/reference/pubsub/base) 實作，透過 Unix 網域 socket 在同一主機的多個進程之間傳送事件。它會選出一個進程擔任代理，其他進程則以客戶端身分連線。代理退出後，其餘客戶端會自動選出新代理。

多個本機進程需要共用串流時可使用它，例如在 Mastra Code 終端介面中協調跨進程的 線程串流。單一進程內傳送事件可使用 [`EventEmitterPubSub`](/reference/pubsub/event-emitter)；跨主機的分佈式事件傳送可使用 [`RedisStreamsPubSub`](/reference/pubsub/redis-streams) 或 [`GoogleCloudPubSub`](/reference/pubsub/google-cloud-pubsub)。

`UnixSocketPubSub` 採用推送式傳輸：事件毋須透過讀取循環便會送達，因此 Mastra 不會為它啟動拉取工作進程。

## 使用範例 {/* #usage-example */}

傳入所有參與進程共用的 socket 路徑。

```typescript title="src/mastra/index.ts"
import { Mastra } from '@mastra/core'
import { UnixSocketPubSub } from '@mastra/core/events'

export const mastra = new Mastra({
  pubsub: new UnixSocketPubSub('/tmp/mastra/events.sock'),
})
```

## 方法 {/* #methods */}

`UnixSocketPubSub` 實作了 [`PubSub`](/reference/pubsub/base) 介面。以下方法是此實作特有的。

### `close()` {/* #close */}

關閉 socket 連線；若此實例是代理，亦會釋放代理角色。應在正常關閉時呼叫。`close()` 最多等待一秒，讓之前已開始的租約釋放操作完成。若操作在此之後仍因另一進程持有鎖而受阻，就會以 `UnixSocketPubSub is closed` 錯誤遭拒；在 `close()` 之後啟動的租約操作則會拋出錯誤。

```typescript
await pubsub.close()
```

## 代理選舉 {/* #broker-election */}

第一個將自身 socket 連結至共用路徑的進程會成為代理。它會在所有已連線客戶端之間轉送事件，其他進程則以客戶端身分連線。每個候選進程先以專用名稱綁定 socket，再將它硬連結至共用路徑。如果該路徑已有 socket，硬連結就會失敗，避免候選進程意外取代仍在運作的代理。

代理正常退出時會移除共用路徑。之後客戶端會重新連線，第一個成功將自身 socket 連結至該路徑的客戶端會成為新代理，其餘客戶端則會重新向它訂閱。

連線遭拒不會立即觸發接管。客戶端會先按退避策略重試；只有 socket 持續拒絕連線時，客戶端才會取得獨佔檔案鎖並取代該 socket。代理只會在共用路徑仍指向自身 socket 時移除它。如果代理發現該路徑已被刪除或取代，就會卸任並以客戶端身分重新加入。因此，即使進程一度連到不同 socket，最終仍會收斂至同一個代理，而不會一直處於分裂狀態。
