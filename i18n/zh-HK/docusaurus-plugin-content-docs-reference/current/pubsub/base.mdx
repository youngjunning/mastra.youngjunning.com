# 發布訂閱

`PubSub`是 Mastra 事件系統的抽象基底類別。它定義了每個 pub/sub 後端實現的合約，因此 Mastra 的其餘部分可以發布和訂閱事件，而無需知道正在使用哪種傳輸。

Mastra 在內部使用發布/訂閱來進行Workflow事件處理、串流和跨元件通訊。大多數應用程式都使用預設值[`EventEmitterPubSub`](/reference/pubsub/event-emitter) and never construct a `PubSub`直接地。僅當您需要自訂傳輸時才實現此類。

對於內建實現，請參閱[`EventEmitterPubSub`](/reference/pubsub/event-emitter), [`UnixSocketPubSub`](/reference/pubsub/unix-socket-pubsub), [`CachingPubSub`](/reference/pubsub/caching-pubsub), [`RedisStreamsPubSub`](/reference/pubsub/redis-streams)， 和[`GoogleCloudPubSub`](/reference/pubsub/google-cloud-pubsub).

## 使用範例 {/* #usage-example */}

延長`PubSub` and implement the four abstract methods to add a custom backend.

```typescript title="src/mastra/pubsub.ts"
import { PubSub } from '@mastra/core/events'
import type { Event, EventCallback, SubscribeOptions } from '@mastra/core/events'

export class CustomPubSub extends PubSub {
  async publish(topic: string, event: Omit<Event, 'id' | 'createdAt'>): Promise<void> {
    // Deliver the event to subscribers of `topic`.
  }

  async subscribe(topic: string, cb: EventCallback, options?: SubscribeOptions): Promise<void> {
    // Register `cb` to receive events published to `topic`.
  }

  async unsubscribe(topic: string, cb: EventCallback): Promise<void> {
    // Remove a previously registered callback.
  }

  async flush(): Promise<void> {
    // Wait for any in-flight deliveries to settle.
  }
}
```

將實例傳遞給[Mastra](/reference/core/mastra-class) constructor:

```typescript title="src/mastra/index.ts"
import { Mastra } from '@mastra/core'
import { CustomPubSub } from './pubsub'

export const mastra = new Mastra({
  pubsub: new CustomPubSub(),
})
```

## 交付方式 {/* #delivery-modes */}

一個`PubSub` declares which delivery modes it supports through the `supportedModes` property. Mastra reads this to decide whether to run a long-lived worker that pulls events.

|模式|描述 |
| - | - |
|`pull` | Consumers actively read from the broker, for example Redis Streams `XREADGROUP`. Mastra runs an orchestration worker to read. |
| `push` | Events arrive without the consumer asking, either in-process or through an HTTP endpoint. No read loop is required. |

預設為`['pull']` so that custom implementations keep today's behavior unless they opt in to push delivery.

## 方法 {/* #methods */}

### 核心方法 {/* #core-methods */}

#### `publish(topic, event)` {/* #publishtopic-event */}

將事件發佈到主題。這`id` and `createdAt` fields are assigned by the implementation.

```typescript
await pubsub.publish('my-topic', {
  type: 'example',
  data: { value: 1 },
  runId: 'run-123',
})
```

#### `subscribe(topic, cb, options?)` {/* #subscribetopic-cb-options */}

註冊回調以接收發佈到主題的事件。什麼時候`options.group` is set, subscribers in the same group compete for messages and each event is delivered to one member. Without a group, every subscriber receives every event.

經過`options.batch` to opt in to batched delivery. The unchanged callback signature delivers a batch of N events as N consecutive `cb(event, ack, nack)` calls in publish order. Batching is honored only when the backend's [`supportsNativeBatching`](#properties) is `true`. Other backends ignore the option and deliver events one at a time.

放`options.startFrom` to `"latest"` to receive only events published after a new consumer group is created. The default, `"earliest"`, includes retained events. Existing consumer groups keep their current checkpoint.

```typescript
await pubsub.subscribe(
  'my-topic',
  (event, ack, nack) => {
    console.log(event)
  },
  { startFrom: 'latest' },
)
```

#### `unsubscribe(topic, cb)` {/* #unsubscribetopic-cb */}



```typescript
await pubsub.unsubscribe('my-topic', callback)
```

#### `flush()` {/* #flush */}

等待任何飛行中的交付結算。在關閉之前呼叫此函數以避免丟失事件。

```typescript
await pubsub.flush()
```

#### `clearTopic(topic)` {/* #cleartopictopic */}

一旦不再向某個主題發布任何事件，就刪除該主題的所有保留狀態（快取的歷史記錄、持久性流條目和使用者群組）。當運行達到最終狀態時，Mastra 的運行生命週期（持久Agent和事件工作流引擎）會自動呼叫此函數，因此每次運行的主題不會在保留訊息的傳輸上累積。

`EventEmitterPubSub`, have nothing to clear. Backends that persist messages, like [`RedisStreamsPubSub`](/reference/pubsub/redis-streams), override it. Implementations follow a best-effort contract and log failures instead of throwing because callers invoke cleanup without awaiting it.

```typescript
await pubsub.clearTopic('workflow.events.v2.run-123')
```

#### `trimTopic(topic, { runId, producedBefore? })` {/* #trimtopictopic--runid-producedbefore- */}

刪除發布主題的所有保留條目`runId`. Other entries are untouched. Mastra calls this once a run completes successfully and its messages are saved to storage, so finished runs leave the topic while runs still in progress or waiting for approval stay. The default implementation is a no-op. [`RedisStreamsPubSub`](/reference/pubsub/redis-streams) overrides it. Same best-effort contract as `clearTopic`.

和`producedBefore` (epoch ms), only entries whose `data.producedAt` is at or before it are deleted, and entries marked `data.pinned` (approval and suspension prompts) are kept. Mastra uses this while a run continues: each time the run's messages are saved mid-run, the parts up to the last finished step leave the topic.

```typescript
await pubsub.trimTopic('agent.thread.thread-abc', { runId: 'run-123' })
await pubsub.trimTopic('agent.thread.thread-abc', { runId: 'run-123', producedBefore: Date.now() })
```

### 重播方法 {/* #replay-methods */}

`subscribe`, so backends without history support behave as live-only. [`CachingPubSub`](/reference/pubsub/caching-pubsub) overrides them to replay cached events.

#### `getHistory(topic, offset?)` {/* #gethistorytopic-offset */}

返回主題的快取事件，從`offset`. Returns an empty array when the backend has no history.

```typescript
const events = await pubsub.getHistory('my-topic', 0)
```

返回：`Promise<Event[]>`

#### `subscribeWithReplay(topic, cb)` {/* #subscribewithreplaytopic-cb */}

重播快取的事件，然後訂閱即時事件。

```typescript
await pubsub.subscribeWithReplay('my-topic', event => {
  console.log(event)
})
```

#### `subscribeFromOffset(topic, offset, cb)` {/* #subscribefromoffsettopic-offset-cb */}

從已知位置開始重播快取的事件，然後訂閱即時事件。當客戶端知道其最後位置時，這比完整重播更有效。

```typescript
await pubsub.subscribeFromOffset('my-topic', 42, event => {
  console.log(event)
})
```
