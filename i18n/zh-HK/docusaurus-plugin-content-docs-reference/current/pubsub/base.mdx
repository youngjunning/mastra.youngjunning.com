# PubSub

`PubSub` 是 Mastra 事件系統的抽象基底類別。它定義所有發佈訂閱後端都須實作的契約，讓 Mastra 其他部分毋須知道底層傳輸方式，就能發佈及訂閱事件。

Mastra 內部使用發佈訂閱處理 Workflow 事件、串流輸出及元件間通訊。多數應用程式使用預設的 [`EventEmitterPubSub`](/reference/pubsub/event-emitter)，毋須直接建立 `PubSub`。只有需要自訂傳輸方式時才實作此類別。

內建實作包括 [`EventEmitterPubSub`](/reference/pubsub/event-emitter)、[`UnixSocketPubSub`](/reference/pubsub/unix-socket-pubsub)、[`CachingPubSub`](/reference/pubsub/caching-pubsub)、[`RedisStreamsPubSub`](/reference/pubsub/redis-streams) 及 [`GoogleCloudPubSub`](/reference/pubsub/google-cloud-pubsub)。

## 使用範例 {/* #usage-example */}

如需新增自訂後端，請擴充 `PubSub` 並實作四個抽象方法。

```typescript title="src/mastra/pubsub.ts"
import { PubSub } from '@mastra/core/events'
import type { Event, EventCallback, SubscribeOptions } from '@mastra/core/events'

export class CustomPubSub extends PubSub {
  async publish(topic: string, event: Omit<Event, 'id' | 'createdAt'>): Promise<void> {
    // Deliver the event to subscribers of `topic`.
  }

  async subscribe(topic: string, cb: EventCallback, options?: SubscribeOptions): Promise<void> {
    // Register `cb` to receive events published to `topic`.
  }

  async unsubscribe(topic: string, cb: EventCallback): Promise<void> {
    // Remove a previously registered callback.
  }

  async flush(): Promise<void> {
    // Wait for any in-flight deliveries to settle.
  }
}
```

將實例傳入 [Mastra](/reference/core/mastra-class) 建構函式：

```typescript title="src/mastra/index.ts"
import { Mastra } from '@mastra/core'
import { CustomPubSub } from './pubsub'

export const mastra = new Mastra({
  pubsub: new CustomPubSub(),
})
```

## 傳送模式 {/* #delivery-modes */}

`PubSub` 透過 `supportedModes` 屬性宣告支援的傳送模式。Mastra 根據此屬性決定是否啟動長時間運作的 Worker 來拉取事件。

| 模式 | 說明 |
| - | - |
|`pull` | 消費者主動從 Broker 讀取，例如使用 Redis Streams 的 `XREADGROUP`。Mastra 會執行編排 Worker 來讀取。 |
| `push` | 事件在程序內或透過 HTTP 端點主動送達，消費者毋須請求，亦不需要讀取循環。 |

預設為 `['pull']`，因此自訂實作只有明確啟用 push 傳送，才會改變現有行為。

## 方法 {/* #methods */}

### 核心方法 {/* #core-methods */}

#### `publish(topic, event)` {/* #publishtopic-event */}

將事件發佈至主題。`id` 及 `createdAt` 欄位由實作指定。

```typescript
await pubsub.publish('my-topic', {
  type: 'example',
  data: { value: 1 },
  runId: 'run-123',
})
```

#### `subscribe(topic, cb, options?)` {/* #subscribetopic-cb-options */}

註冊回呼以接收發佈至主題的事件。設定 `options.group` 後，同組訂閱者競爭訊息，每個事件只傳送給一名成員；未設定組時，每名訂閱者都會收到每個事件。

傳入 `options.batch` 可啟用批次傳送。回呼簽章不變：一批 N 個事件會按發佈順序觸發 N 次連續的 `cb(event, ack, nack)` 呼叫。只有後端的 [`supportsNativeBatching`](#properties) 為 `true` 時才會批次傳送；其他後端會忽略此選項，逐一傳送事件。

將 `options.startFrom` 設為 `"latest"`，新的消費者組就只接收建立後發佈的事件。預設值 `"earliest"` 會包括保留的事件。現有消費者組繼續使用目前的檢查點。

```typescript
await pubsub.subscribe(
  'my-topic',
  (event, ack, nack) => {
    console.log(event)
  },
  { startFrom: 'latest' },
)
```

#### `unsubscribe(topic, cb)` {/* #unsubscribetopic-cb */}

從主題移除先前註冊的回呼。

```typescript
await pubsub.unsubscribe('my-topic', callback)
```

#### `flush()` {/* #flush */}

等待正在進行的傳送結束。關閉前呼叫此方法，避免遺失事件。

```typescript
await pubsub.flush()
```

#### `clearTopic(topic)` {/* #cleartopictopic */}

當某個主題不再接收新事件時，刪除其所有保留狀態，包括快取記錄、持久化串流項目及消費者組。Mastra 的執行生命週期（持久型 Agent 及事件驅動的 Workflow 引擎）會在執行進入終止狀態時自動呼叫此方法，避免按執行建立的主題在保留訊息的傳輸後端持續累積。

預設實作不執行任何動作，因為 `EventEmitterPubSub` 等不按主題保留狀態的傳輸後端毋須清理。持久化訊息的後端，例如 [`RedisStreamsPubSub`](/reference/pubsub/redis-streams)，會覆寫此方法。清理採盡力而為的契約：失敗時記錄日誌而不拋出錯誤，因為呼叫端不會等待清理完成。

```typescript
await pubsub.clearTopic('workflow.events.v2.run-123')
```

#### `trimTopic(topic, { runId, producedBefore? })` {/* #trimtopictopic--runid-producedbefore- */}

刪除該主題上所有以 `runId` 發佈的保留項目，其他項目不受影響。執行成功完成且訊息已儲存後，Mastra 會呼叫此方法，因此已完成執行的訊息會從主題移除，仍在執行或等待批准的執行則會保留。預設實作不執行任何動作；[`RedisStreamsPubSub`](/reference/pubsub/redis-streams) 會覆寫它。此方法與 `clearTopic` 一樣採盡力而為的契約。

傳入 `producedBefore`（Unix 紀元毫秒）時，只會刪除 `data.producedAt` 不晚於該時間的項目；標記為 `data.pinned` 的批准及暫停提示會保留。Mastra 在執行尚未結束時使用此功能：每次於執行途中儲存訊息後，都會從主題移除截至最後一個已完成步驟的內容。

```typescript
await pubsub.trimTopic('agent.thread.thread-abc', { runId: 'run-123' })
await pubsub.trimTopic('agent.thread.thread-abc', { runId: 'run-123', producedBefore: Date.now() })
```

### 重播方法 {/* #replay-methods */}

這些方法用於連線中斷後恢復串流。預設實作會退回一般的 `subscribe`，因此不支援歷史記錄的後端只能接收即時事件。[`CachingPubSub`](/reference/pubsub/caching-pubsub) 會覆寫這些方法，以重播快取事件。

#### `getHistory(topic, offset?)` {/* #gethistorytopic-offset */}

回傳主題從 `offset` 開始的快取事件。後端沒有歷史記錄時回傳空陣列。

```typescript
const events = await pubsub.getHistory('my-topic', 0)
```

返回：`Promise<Event[]>`

#### `subscribeWithReplay(topic, cb)` {/* #subscribewithreplaytopic-cb */}

重播快取的事件，然後訂閱即時事件。

```typescript
await pubsub.subscribeWithReplay('my-topic', event => {
  console.log(event)
})
```

#### `subscribeFromOffset(topic, offset, cb)` {/* #subscribefromoffsettopic-offset-cb */}

從已知位置開始重播快取的事件，然後訂閱即時事件。當客戶端知道其最後位置時，這比完整重播更有效。

```typescript
await pubsub.subscribeFromOffset('my-topic', 42, event => {
  console.log(event)
})
```
