# EventEmitterPubSub

`EventEmitterPubSub` 是預設的 [`PubSub`](/reference/pubsub/base) 實作。它使用 Node.js [`EventEmitter`](https://nodejs.org/api/events.html#class-eventemitter) 在處理程序內傳送事件，因此無需外部服務。

適用於單一處理程序的應用程式。若要在同一主機的多個處理程序之間傳送事件，請參閱 [`UnixSocketPubSub`](/reference/pubsub/unix-socket-pubsub)；若要在分散式環境傳送事件，請參閱 [`RedisStreamsPubSub`](/reference/pubsub/redis-streams) 或 [`GoogleCloudPubSub`](/reference/pubsub/google-cloud-pubsub)。

事件只在處理程序內傳送，因此不會持久儲存，也不會與其他處理程序共享。若可恢復的串流需要重播事件，請使用 [`CachingPubSub`](/reference/pubsub/caching-pubsub) 包裝它。

## 使用範例 {/* #usage-example */}

`EventEmitterPubSub` 會在未設定 `pubsub` 選項時自動使用，因此大部分應用程式無需自行建立。只有需要設定或共用實例時才明確建立。

```typescript title="src/mastra/index.ts"
import { Mastra } from '@mastra/core'
import { EventEmitterPubSub } from '@mastra/core/events'

export const mastra = new Mastra({
  pubsub: new EventEmitterPubSub(),
})
```

若要與應用程式的其他部分共用事件發射器，請傳入現有的 `EventEmitter`：

```typescript
import EventEmitter from 'node:events'
import { EventEmitterPubSub } from '@mastra/core/events'

const emitter = new EventEmitter()
const pubsub = new EventEmitterPubSub(emitter)
```

若要顯示批次傳送錯誤，請傳入記錄器：

```typescript
import { EventEmitterPubSub } from '@mastra/core/events'

const pubsub = new EventEmitterPubSub(undefined, { logger })
```

## 方法 {/* #methods */}

`EventEmitterPubSub` 實作了 [`PubSub`](/reference/pubsub/base) 契約。以下方法具有此實作特有的行為。

### `subscribe(topic, cb, options?)` {/* #subscribetopic-cb-options */}

為主題登記回呼。未設定 `options.group` 時，每位訂閱者都會收到每個事件；設定後，事件會在群組成員之間輪流分配。

傳入 `options.batch` 即可啟用批次傳送。詳情請參閱下文的[批次處理](#batching)。

```typescript
await pubsub.subscribe('workflow.events', (event, ack, nack) => {
  console.log(event)
})
```

### `flush()` {/* #flush */}

等待由 `nack` 觸發、尚未完成的重新傳送執行後才傳回。

```typescript
await pubsub.flush()
```

### `close()` {/* #close */}

移除所有監聽器並取消尚未完成的重新傳送。請在正常關閉時呼叫。

```typescript
await pubsub.close()
```

## 重新傳送 {/* #redelivery */}

群組內的訂閱者呼叫 `nack` 後，事件會稍作延遲再傳送至該群組，`deliveryAttempt` 計數亦會增加。呼叫 `ack` 會清除該事件的追蹤紀錄。廣播式訂閱者收到的 `ack` 和 `nack` 函數不會執行任何操作，因為每個事件都只會傳送給每位訂閱者一次。

## 批次處理 {/* #batching */}

`EventEmitterPubSub` 原生支援 `options.batch`。訂閱者啟用後，事件會暫存在各訂閱者專屬的記憶體緩衝區；符合清空條件時，回呼會連續執行以傳送這些事件。廣播式和群組訂閱者都可使用批次處理。完整策略請參閱 [`SubscribeBatchOptions`](/reference/pubsub/base#subscribebatchoptions)。

```typescript
await pubsub.subscribe(
  'workflow.events',
  event => {
    console.log(event)
  },
  {
    batch: {
      maxSize: 10, // flush once 10 events have queued
      maxWaitMs: 500, // ...or after 500ms, whichever comes first
    },
  },
)
```

緩衝區位於各處理程序的記憶體中，因此批次狀態不會持久儲存，重新啟動後亦不會保留。由 `maxWaitMs` 觸發的清空操作會盡力完成：若 `coalesce` 等步驟擲出錯誤，錯誤會透過設定的 `logger` 顯示，而不會向外擲出。`flush()` 會清空所有批次訂閱者的緩衝區，然後傳回。
