# 由 Mastra Cloud 遷移至 Mastra 平台

Mastra 平台以獨立的 Studio 和 Server 產品、透過 CLI 進行的部署，以及全新的可觀測性系統取代 Mastra Cloud。本指南會逐步說明遷移流程。

## 主要變動 {/* #what-changed */}

| 項目 | Mastra Cloud | Mastra 平台 |
| - | - | - |
| **產品** | 單一項目 | 獨立的 Studio 和 Server |
| **部署** | 推送後自動部署 | 透過 CLI 部署（`mastra studio deploy`、`mastra server deploy`） |
| **項目建立** | 從 GitHub 匯入 | 首次部署時由 CLI 建立項目 |
| **儲存** | 託管的 libSQL 資料庫（Cloud Store）或自備資料庫 | 自備託管資料庫 |
| **可觀測性** | 以日誌記錄器為基礎 | 使用配備匯出器的 `Observability` 類別 |
| **環境變數** | 建立項目時設定 | 首次部署時從 `.env` 初始化，其後於控制台管理 |
| **URL** | 單一 URL | Studio 和 Server 各有獨立 URL |

## 開始遷移前 {/* #before-you-start */}

<Steps>
  <StepItem>
    安裝或更新 CLI：

    ```bash npm2yarn
    npm install -g mastra@latest
    ```
  </StepItem>

  <StepItem>
    登入：

    ```bash
    mastra auth login
    ```
  </StepItem>

  <StepItem>
    確認項目可在本機建置：

    ```bash
    mastra build
    ```
  </StepItem>
</Steps>

## 以託管資料庫取代 Mastra Cloud Store {/* #replace-mastra-cloud-store-with-a-hosted-database */}

Mastra Cloud 曾提供由 [Turso](https://turso.tech) 支援的託管 libSQL 資料庫；Mastra 平台則不會代為託管資料庫。請將儲存設定指向外部託管的資料庫實例。

如果您原本已使用自備的託管資料庫，請保留現有設定，並確保連線字串透過控制台中的環境變數提供，而非寫死在程式碼中。

如果您使用 Cloud Store，請按照以下步驟匯出資料，並匯入您自行管理的新 libSQL 資料庫。

### 匯出 Cloud Store 資料 {/* #export-your-cloud-store-data */}

匯出 Cloud Store 資料有兩種方法：從控制台下載，或使用 Turso CLI 手動產生資料庫傾印檔。

#### 方法 A：從控制台匯出（建議） {/* #option-a-export-from-the-dashboard-recommended */}

在 [Mastra 控制台](https://projects.mastra.ai)開啟項目，前往 **Runtime → Settings → Storage**，然後按 **Export Database**。控制台會產生包含 Cloud Store 全部內容的 `.sql` 傾印檔，並直接下載至「下載項目」資料夾。

下載完成後，將傾印檔轉為 SQLite 資料庫檔案：

```bash
sqlite3 mydb.db < ~/Downloads/mastra-cloud-dump.sql
```

現在您已有可攜式的 `mydb.db` 檔案。在後續步驟將其用作新資料庫的資料來源前，可以先在本機檢查或備份。

#### 方法 B：使用 Turso CLI 匯出 {/* #option-b-export-via-the-turso-cli */}

如果您習慣使用指令列，或需要編寫匯出腳本，可以透過 [Turso CLI](https://docs.turso.tech/cli) 直接產生資料庫傾印檔。此方法需要資料庫 URL 和驗證權杖，兩者都可在控制台找到。

<Steps>
  <StepItem>
    從控制台取得 Cloud Store 憑證。

    在 [Mastra 控制台](https://projects.mastra.ai)開啟項目，前往 **Runtime → Settings → Env Variables**。使用 Cloud Store 的項目除了您自行設定的變數外，系統還會注入以下兩個變數：

    * `MASTRA_STORAGE_URL`：libSQL 連線字串（例如 `libsql://<db-name>-<org>.turso.io`）。
    * `MASTRA_STORAGE_AUTH_TOKEN`：僅限該資料庫使用、具有讀取權限的驗證權杖。

    每個變數都提供一般環境變數操作：透過眼睛圖示顯示或隱藏數值，以及編輯、刪除和複製數值。使用 **Copy Value** 分別複製兩個值，供下方的傾印指令使用。

    :::note
    只有啟用 Cloud Store 的項目才會顯示這兩個變數。如果您在 Mastra Cloud 使用自備資料庫，您已持有相關憑證，可以直接跳至[將 Mastra 應用程式連接至新資料庫](#point-your-mastra-app-at-the-new-database)。
    :::

    :::note
    如果變數不存在、數值無法解密，或 Turso CLI 拒絕權杖，請使用與 Mastra Cloud 帳戶關聯的電郵地址寄信至 [support@mastra.ai](mailto:support@mastra.ai)，索取待匯出項目的 libSQL URL 和驗證權杖，並附上項目名稱或 ID。如果您的網絡無法存取 CLI，支援團隊也可以代為產生傾印檔。
    :::
  </StepItem>

  <StepItem>
    安裝 Turso CLI。

    ```bash title="macOS"
    brew install tursodatabase/tap/turso
    ```

    ```bash title="Linux / WSL"
    curl -sSfL https://get.tur.so/install.sh | bash
    ```

    Windows 安裝及無介面安裝方法請參閱 [Turso CLI 入門指南](https://docs.turso.tech/cli/introduction)。
  </StepItem>

  <StepItem>
    將資料庫匯出為 SQL 傾印檔。

    將支援團隊提供的憑證（或先前從控制台複製的值）設為環境變數，再將資料庫傾印至本機檔案。如果 URL 來自控制台，請將通訊協定由 `libsql://` 改為 `https://`，因為同時傳入 URL 和驗證權杖時，Turso CLI 要求使用 HTTPS 格式。

    ```bash
    export MASTRA_STORAGE_URL="https://<db-name>-<org>.turso.io"
    export MASTRA_STORAGE_AUTH_TOKEN="<token-from-dashboard-or-support>"

    turso db shell "$MASTRA_STORAGE_URL?authToken=$MASTRA_STORAGE_AUTH_TOKEN" ".dump" > mastra-cloud-dump.sql
    ```

    :::warning
    將驗證權杖嵌入連線字串不及 Turso 建議的方法安全：包含權杖的完整 URL 可能出現在指令歷史紀錄、程序資訊或終端機輸出中。Turso 建議先執行 `turso auth login`，再只以資料庫名稱產生傾印檔：`turso db shell <database-name> ".dump" > mastra-cloud-dump.sql`。但此流程要求資料庫屬於您自己的 Turso 帳戶，Cloud Store 並不符合此條件，因此上方的環境變數範例可用於這次性的匯出。如需完全避免將權杖插入指令，請支援團隊代為產生傾印檔並將 SQL 檔案寄給您。
    :::

    產生的 `mastra-cloud-dump.sql` 包含完整的資料庫結構和資料，包括 thread 和訊息歷史紀錄、Workflow 快照、trace 及評估分數。繼續操作前，請妥善保存此檔案。
  </StepItem>
</Steps>

### 將傾印檔匯入新的 libSQL 資料庫 {/* #load-the-dump-into-a-new-libsql-database */}

傾印檔採用標準 SQL 格式，可匯入任何與 libSQL 相容的資料庫。以下範例使用新建的 Turso 託管資料庫，以沿用原有資料庫類型並避免轉換資料庫結構。

<Steps>
  <StepItem>
    使用您自己的 Turso 帳戶登入 Turso CLI。

    ```bash
    turso auth login
    ```

    如果您沒有 Turso 帳戶，CLI 會提示您建立。計劃詳情請參閱 [Turso 定價](https://turso.tech/pricing)。
  </StepItem>

  <StepItem>
    建立新資料庫並同時匯入傾印檔。

    ```bash
    turso db create mastra-migrated --from-dump ./mastra-cloud-dump.sql
    ```

    `--from-dump` 會在建立資料庫時還原本機 SQLite/libSQL 傾印檔，比事後透過管道將 SQL 陳述式傳入 `turso db shell` 更快、更安全。請選擇靠近 Mastra Server 執行位置的區域，以降低延遲。可執行 `turso db locations` 查看可用區域；如管理多個群組，可傳入 `--group <group-name>`。

    對於數 GB 大小的傾印檔，請加上 `--wait`，讓 CLI 等待資料庫完全可用後再結束。
  </StepItem>

  <StepItem>
    產生新資料庫的連線憑證。

    ```bash
    turso db show mastra-migrated --url
    turso db tokens create mastra-migrated
    ```

    第一個指令會輸出 libSQL URL，第二個指令會輸出驗證權杖。`LibSQLStore` 需要這兩個值。
  </StepItem>
</Steps>

### 將 Mastra 應用程式連接至新資料庫 {/* #point-your-mastra-app-at-the-new-database */}

將新憑證設為環境變數，可寫入本機 `.env` 檔案，也可在 Mastra 平台控制台設定：

```bash title=".env"
TURSO_DATABASE_URL="libsql://mastra-migrated-<org>.turso.io"
TURSO_AUTH_TOKEN="<token-from-turso-db-tokens-create>"
```

設定 `LibSQLStore`，使其讀取這些環境變數：

```ts title="src/mastra/index.ts"
import { Mastra } from '@mastra/core/mastra'
import { LibSQLStore } from '@mastra/libsql'

export const mastra = new Mastra({
  storage: new LibSQLStore({
    id: 'libsql-storage',
    url: process.env.TURSO_DATABASE_URL!,
    authToken: process.env.TURSO_AUTH_TOKEN,
  }),
})
```

完整設定選項請參閱 [libSQL 儲存參考文件](/integrations/databases/libsql)。

### 驗證遷移結果 {/* #verify-the-migration */}

停用舊 Cloud 項目前，請確認新資料庫能提供應用程式所需的資料。

- 執行 `turso db shell mastra-migrated "SELECT name FROM sqlite_master WHERE type='table';"` 列出資料表。結果應包含 Mastra 管理的資料表，例如 `mastra_threads`、`mastra_messages`、`mastra_workflow_snapshot` 和 `mastra_traces`。
- 對確定已有資料的資料表統計資料列數，例如執行 `turso db shell mastra-migrated "SELECT COUNT(*) FROM mastra_messages;"`，並與針對 Cloud Store URL 執行相同查詢的結果比較。
- 使用新憑證啟動 Mastra 應用程式，並確認現有 thread 或 Workflow 執行紀錄可在 [Studio](/docs/studio/observability) 中正常載入。

## 更新可觀測性設定 {/* #update-observability-configuration */}

Mastra Cloud 使用以日誌記錄器為基礎的追蹤。Mastra 平台則使用 `Observability` 類別，並明確設定匯出器。

安裝可觀測性套件：

```bash npm2yarn
npm install @mastra/observability
```

**遷移前（Mastra Cloud）：**

```ts title="src/mastra/index.ts"
import { Mastra } from '@mastra/core/mastra'
import { PinoLogger } from '@mastra/loggers'

export const mastra = new Mastra({
  logger: new PinoLogger({ name: 'my-app', level: 'info' }),
  // traces appear in Cloud dashboard automatically
})
```

**遷移後（Mastra 平台）：**

```ts title="src/mastra/index.ts"
import { Mastra } from '@mastra/core/mastra'
import {
  Observability,
  MastraStorageExporter,
  MastraPlatformExporter,
  SensitiveDataFilter,
} from '@mastra/observability'

export const mastra = new Mastra({
  observability: new Observability({
    configs: {
      default: {
        serviceName: 'my-app',
        exporters: [new MastraStorageExporter(), new MastraPlatformExporter()],
        spanOutputProcessors: [new SensitiveDataFilter()],
      },
    },
  }),
})
```

- `MastraStorageExporter` 將可觀測性事件持久儲存至 Mastra Storage，供 [Studio](/docs/studio/observability) 使用。
- 設定 `MASTRA_PLATFORM_ACCESS_TOKEN` 後，`MastraPlatformExporter` 會將可觀測性事件傳送至 Mastra 平台。
- `SensitiveDataFilter` 會在匯出前遮蔽 span 資料中的密碼、權杖和金鑰。

完整設定方式（包括使用 DuckDB 儲存指標的複合儲存方案）請參閱[可觀測性概覽](/docs/observability/overview)。

## 部署 Studio {/* #deploy-studio */}

部署託管的 Studio 實例：

```bash
mastra studio deploy
```

CLI 會建置項目、上傳建置產物，再進行部署。首次部署時會建立 `.mastra-project.json`，將本機項目與平台項目連結。請將此檔案提交至程式碼儲存庫。

本機環境設定檔為選用項目。如項目目錄中有 `.env` 或 `.env.*` 檔案，部署時會包含其中的環境變數。

如要透過單一步驟以非互動方式建立新的平台項目，無須另外執行 `mastra studio projects create`：以 `--project` 指定名稱，並以 `--yes` 接受預設選項：

```bash
mastra studio deploy --project "my-new-project" --yes
```

詳情請參閱 [Studio 部署文件](/docs/studio/deployment#mastra-platform)。

### 多個環境 {/* #multiple-environments */}

一個 Mastra 平台項目可在多個[環境](/docs/mastra-platform/environments)執行同一套程式碼，例如 `production` 和 `staging`。使用統一的 [`mastra deploy`](/docs/mastra-platform/deploy) 指令分別部署至各環境：

```bash
mastra deploy --env production --yes
mastra deploy --env staging --env-file .env.staging --yes
```

每個環境都有專屬 URL、環境變數及部署歷史紀錄。

## 部署 Server（選用） {/* #deploy-server-optional */}

如果需要正式環境的 API 端點，請部署 Server：

```bash
mastra server deploy
```

這會建立獨立的部署，提供穩定的 API URL、環境變數管理及自訂網域支援。完整步驟請參閱 [Server 部署指南](/docs/mastra-platform/server)。

:::note
首次部署時會自動包含 `.env`、`.env.local` 和 `.env.production` 中的環境變數。其後請透過[網頁控制台](https://projects.mastra.ai)管理環境變數。
首次部署前，請檢查並清理這些檔案，以免上傳只供開發使用或包含個人資訊的密鑰。
:::

## 設定 CI（選用） {/* #set-up-ci-optional */}

Mastra Cloud 會在程式碼推送後自動部署。Mastra 平台透過 CLI 部署，因此您可以在任何 CI Provider 中執行部署指令。

### 先決條件 {/* #prerequisites */}

1. 建立 API 令牌：

   ```bash
   mastra auth tokens create ci-deploy
   ```

1. 將權杖儲存為 GitHub Actions Secret（例如 `MASTRA_API_TOKEN`）。

1. 將首次手動部署產生的 `.mastra-project.json` 提交至程式碼儲存庫。

設定 `MASTRA_API_TOKEN` 後，CLI 會以無介面模式執行，並略過所有互動式提示。

### 推送至 main 分支時部署 Server {/* #deploy-server-on-push-to-main */}

部署 Server 時，CLI 會從 `.mastra-project.json` 讀取組織和項目，因此除了權杖，無須設定其他環境變數：

```yaml title=".github/workflows/deploy-server.yml"
name: Deploy to Mastra Server

on:
  push:
    branches: [main]

jobs:
  deploy:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: pnpm/action-setup@v4
      - uses: actions/setup-node@v4
        with:
          node-version: '22'
      - run: pnpm install
      - run: pnpm mastra server deploy --yes --config .mastra-project.json
        env:
          MASTRA_API_TOKEN: ${{ secrets.MASTRA_API_TOKEN }}
```

### 推送至 main 分支時部署 Studio {/* #deploy-studio-on-push-to-main */}

在無介面模式部署 Studio 時，即使提供 `--config`，仍須將 `MASTRA_ORG_ID` 和 `MASTRA_PROJECT_ID` 設為環境變數：

```yaml title=".github/workflows/deploy-studio.yml"
name: Deploy to Mastra Studio

on:
  push:
    branches: [main]

jobs:
  deploy:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: pnpm/action-setup@v4
      - uses: actions/setup-node@v4
        with:
          node-version: '22'
      - run: pnpm install
      - run: pnpm mastra studio deploy --yes --config .mastra-project.json
        env:
          MASTRA_API_TOKEN: ${{ secrets.MASTRA_API_TOKEN }}
          MASTRA_ORG_ID: ${{ secrets.MASTRA_ORG_ID }}
          MASTRA_PROJECT_ID: ${{ secrets.MASTRA_PROJECT_ID }}
```

## 停用舊 Cloud 項目 {/* #decommission-old-cloud-project */}

將所有指向舊 Mastra Cloud URL 的用戶端改為使用新的 Server 或 Studio URL。在 [Studio 可觀測性控制台](/docs/studio/observability)確認新平台可顯示 trace。確認所有功能正常後，再刪除舊 Mastra Cloud 項目。
