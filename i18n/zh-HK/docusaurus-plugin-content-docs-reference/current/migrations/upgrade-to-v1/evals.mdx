# 評估和記分員

評估 API 已整合到新的評分系統上，並更新了命名約定和配置要求。

## 改變了 {/* #changed */}

### `getScorers`到`listScorers` {/* #getscorers-to-listscorers */}

這`getScorers()` method has been renamed to `listScorers()`. This change aligns with the naming convention used across the API where plural getter methods use the `list`前綴。

若要遷移，請將所有呼叫替換為`getScorers()` with `listScorers()`.

```diff
- const scorers = mastra.getScorers();
+ const scorers = mastra.listScorers();
```

:::提示\[程式碼修改]

您可以使用 Mastra 的 codemod CLI 自動更新您的程式碼：

```bash
npx @mastra/codemod@latest v1/mastra-plural-apis .
```

:::

### `runExperiment`到`runEvals` {/* #runexperiment-to-runevals */}

這`runExperiment()` function has been renamed to `runEvals()` to identify that it runs evaluations.

若要遷移，請更新函數調用`runExperiment` to `runEvals`.

```diff
- import { createScorer, runExperiment } from '@mastra/core/evals';
+ import { createScorer, runEvals } from '@mastra/core/evals';
  import { myAgent } from './agents/my-agent';

  const scorer = createScorer({
    id: 'helpfulness-scorer',
    // ...
  });

- const result = await runExperiment({ target: myAgent, scorers: [scorer], data: inputs });
+ const result = await runEvals({ target: myAgent, scorers: [scorer], data: inputs });
```

:::提示\[程式碼修改]

您可以使用 Mastra 的 codemod CLI 自動更新您的程式碼：

```bash
npx @mastra/codemod@latest v1/evals-run-experiment .
```

:::

### `getScorerByName`到`getScorerById` {/* #getscorerbyname-to-getscorerbyid */}

這`getScorerByName()` method has been renamed to `getScorerById()`. Scorers now require an `id` field instead of `name`. This change aligns with the broader API pattern of using `id` for entity identification.

若要遷移，請更新要使用的方法呼叫和記分器配置`id` instead of `name`.

```diff
  const scorer = createScorer({
-   name: 'helpfulness-scorer',
+   id: 'helpfulness-scorer',
    // ...
  });

- const scorer = mastra.getScorerByName('helpfulness-scorer');
+ const scorer = mastra.getScorerById('helpfulness-scorer');
```

:::提示\[程式碼修改]

您可以使用 Mastra 的 codemod CLI 自動更新您的程式碼：

```bash
npx @mastra/codemod@latest v1/evals-scorer-by-name .
```

### 記分員配置來自`name` to `id` {/* #scorer-configuration-from-name-to-id */}

得分手現在需要`id` field instead of `name`. The `name` field is now optional. The new field aligns scorers with other Mastra entities.

若要遷移，請更新要使用的記分器定義`id` as the required field.

```diff
  const scorer = createScorer({
-   name: 'helpfulness-scorer',
+   id: 'helpfulness-scorer',
+   name: 'Helpfulness Scorer', // optional
    // ...
  });
```

### 儲存分數 API`listScoresBy*` pattern {/* #storage-score-apis-to-listscoresby-pattern */}

分數儲存 API 已重新命名以遵循`listScoresBy*` pattern. This change aligns with the broader storage API naming conventions.

若要遷移，請更新分數查詢方法以使用新的命名模式。

```diff
- const scores = await storage.getScores({ scorerName: 'helpfulness-scorer' });
+ const scores = await storage.listScoresByScorerId({
+   scorerId: 'helpfulness-scorer',
+ });

// Also available:
// - listScoresByRunId
// - listScoresByEntityId
// - listScoresBySpan
```

### 預建記分器導入到`scorers/prebuilt` path {/* #prebuilt-scorer-imports-to-scorersprebuilt-path */}

預建得分手進口已合併為單一的`@mastra/evals/scorers/prebuilt` path instead of separate `scorers/llm` and `scorers/code` paths. This change simplifies imports and provides a clearer organization of prebuilt scorers.

若要遷移，請更新導入語句以使用新的`scorers/prebuilt` path.

```diff
  // LLM-based scorers
- import { createHallucinationScorer } from '@mastra/evals/scorers/llm';
- import { createFaithfulnessScorer } from '@mastra/evals/scorers/llm';
+ import { createHallucinationScorer } from '@mastra/evals/scorers/prebuilt';
+ import { createFaithfulnessScorer } from '@mastra/evals/scorers/prebuilt';

  // Code-based scorers
- import { createContentSimilarityScorer } from '@mastra/evals/scorers/code';
- import { createCompletenessScorer } from '@mastra/evals/scorers/code';
+ import { createContentSimilarityScorer } from '@mastra/evals/scorers/prebuilt';
+ import { createCompletenessScorer } from '@mastra/evals/scorers/prebuilt';
```

### 記分器訊息​​類型來自`UIMessage` to `MastraDBMessage` {/* #scorer-message-types-from-uimessage-to-mastradbmessage */}

記分器輸入和輸出類型現在使用`MastraDBMessage[]` instead of `UIMessage`. This change aligns scorers with the database-persisted message format for consistency across the framework.

要遷移，請更新記分器實作以使用`MastraDBMessage` types and access message content through the nested `content` structure.

```diff
  import type {
    ScorerRunInputForAgent,
    ScorerRunOutputForAgent
  } from '@mastra/core/evals';

- // ScorerRunInputForAgent uses UIMessage[]
- const inputMessages: UIMessage[] = run.input.inputMessages;
+ // ScorerRunInputForAgent now uses MastraDBMessage[]
+ import type { MastraDBMessage } from '@mastra/core/agent';
+ const inputMessages: MastraDBMessage[] = run.input.inputMessages;
```

### 訊息內容結構為嵌套格式 {/* #message-content-structure-to-nested-format */}

現在可以透過巢狀存取Tool呼叫和文字內容`content` object instead of flat message properties. The nested structure matches the database message format and its types.

要遷移，請透過以下方式存取Tool調用`message.content.toolInvocations` and text via `message.content.content` or use the `getTextContentFromMastraDBMessage()` helper.

```diff
+ import { getTextContentFromMastraDBMessage } from '@mastra/evals';
+
  const run = await scorer.run(testRun);

  // Accessing text content
- const text = message.content;
+ const text = getTextContentFromMastraDBMessage(message);
+ // or directly: message.content.content

  // Accessing tool invocations
- const toolCalls = message.toolInvocations;
+ const toolCalls = message.content.toolInvocations;
```

## 已刪除 {/* #removed */}

### 舊版評估代碼 {/* #legacy-evals-code */}

舊版評估代碼已從`@mastra/core`. This includes legacy evaluation metrics, scorer/judge modules, and hook-based automatic evaluation code. This change simplifies the codebase by removing outdated evaluation approaches.

要遷移，請使用新的 evals/scorers API`@mastra/core/evals` or `@mastra/evals`.

```diff
- // Legacy evals APIs
+ import { createScorer, runEvals } from '@mastra/core/evals';
+
+ const scorer = createScorer({
+   id: 'my-scorer',
+   // Use new scorer API
+ });
```

### Agent`TMetrics` generic parameter {/* #agent-tmetrics-generic-parameter */}

這`TMetrics` generic parameter has been removed from `AgentConfig` and the `Agent` constructor. Metrics/scorers are now configured using the scorers API instead of being part of the Agent type system. This change simplifies the Agent type signature.

若要遷移，請刪除`TMetrics` generic parameter and configure scorers using the scorers API.

```diff
- const agent = new Agent<AgentId, Tools, Metrics>({
+ const agent = new Agent<AgentId, Tools>({
    // ...
  });
```

### 與 Evals 相關的類型匯出 {/* #evals-related-type-exports */}

幾個與 evals 相關的類型匯出已被刪除，包括`DeprecatedOutputOptions`, `Metric`, and processor option types. These types are now internal or have been replaced by the new scorers API. This change reduces API surface area.

若要遷移，請刪除這些已刪除類型的參考並使用新的記分器 API。

```diff
- import type {
-   DeprecatedOutputOptions,
-   Metric,
-   LanguageDetectorOptions,
-   ModerationOptions,
- } from '@mastra/core';
+ // Use new scorers API types
+ import type { Scorer } from '@mastra/core/evals';
```

### `createUIMessage`測試助手 {/* #createuimessage-test-helper */}

這`createUIMessage()` test helper has been removed and replaced with `createTestMessage()`. The new helper creates `MastraDBMessage` objects with the nested content structure and supports optional tool invocations. This change aligns test utilities with the new message format.

若要遷移，請替換`createUIMessage()` calls with `createTestMessage()` and update to use `MastraDBMessage` types.

```diff
- import { createUIMessage } from '@mastra/evals';
+ import { createTestMessage } from '@mastra/evals';

  // Creating test messages
- const message = createUIMessage({
-   id: 'test-1',
+ const message = createTestMessage({
+   id: 'test-1', // optional, defaults to 'test-message'
    role: 'user',
    content: 'Hello',
    toolInvocations: [], // optional
  });
```
