title: "遷移指南模板"
description: "使用此遷移頁面模板記錄 v1 破壞性變更，包括套件版本、變更前後示例、遷移步驟和驗證指引。"
---

此範本是有關如何填入各個遷移指南的樣式指南。使用此指南作為如何建立此目錄中的文件的指南。你不能偏離這個結構。

遵循`.cursor/rules/writing-documentation.mdc`有關如何撰寫散文內容的說明。

找到需要記錄的所有變更後，您應該將它們分為兩大組：「已更改」和「已刪除」。

例子：

```md
## Changed

## Removed
```

所有更改都必須在這兩個部分下進行。

每個更改（無論是“更改”還是“刪除”）都應該是​​ h3 標題。您必須嚴格遵循該格式。

例子：

```md
## Changed

### `oldFunction` to `newFunction`
```

現在標題已經就位，您需要為每個變更遵循精確的結構。你不能偏離這個結構。

用一兩句話簡單描述變化。接下來用一句話解釋為什麼要改變。

每個更改的第三個元素必須是解釋如何將現有程式碼遷移到新版本。保持簡潔但清晰，盡量不要刪減太多資訊。之後必須使用“diff”語法提供程式碼區塊。在程式碼區塊內，您需要顯示需要使用該 diff 語法進行變更的程式碼的「之前」和「之後」範例。

例子：

````md
## Changed

### `oldFunction` to `newFunction`

The `oldFunction` has been renamed to `newFunction`. This change improves clarity and consistency across the API.

To migrate, replace all instances of `oldFunction` with `newFunction` in your codebase.

```diff
- const result = oldFunction(args);
+ const result = newFunction(args);
```
````

如果遷移需要的步驟比尋找和替換更多，您可以在程式碼區塊之前新增其他說明。如果需要多個步驟，請使用編號清單清楚地解釋每個步驟。
