# Agent 類別

Agent 類別調整了語音方法及屬性存取方式，並簡化了串流 API。

## 變更 {/* #changed */}

### `getAgents` 改為 `listAgents` {/* #getagents-to-listagents */}

`mastra.getAgents()` 方法已更名為 `mastra.listAgents()`。這項變更符合整個 API 的命名慣例：傳回集合的方法使用 `list` 前綴。

遷移時，請將所有 `mastra.getAgents()` 呼叫改為 `mastra.listAgents()`。

```diff
- const agents = mastra.getAgents();
+ const agents = mastra.listAgents();
```

:::tip[Codemod]

您可以使用 Mastra 的 codemod CLI 自動更新您的程式碼：

```bash npm2yarn
npx @mastra/codemod@latest v1/mastra-plural-apis .
```

:::

### `RuntimeContext` 改為 `RequestContext` {/* #runtimecontext-to-requestcontext */}

程式碼庫中的 `RuntimeContext` 類別已更名為 `RequestContext`。新名稱表明此類別儲存個別請求的資料，亦符合 Web 框架的命名慣例。

遷移時，請將所有匯入及參數名稱中的 `RuntimeContext`/`runtimeContext` 分別改為 `RequestContext`/`requestContext`。

```diff
- import { RuntimeContext } from '@mastra/core/runtime-context';
+ import { RequestContext } from '@mastra/core/request-context';

- const runtimeContext = new RuntimeContext();
- runtimeContext.set('userTier', 'enterprise');
+ const requestContext = new RequestContext();
+ requestContext.set('userTier', 'enterprise');

- await agent.generate(messages, { runtimeContext });
+ await agent.generate(messages, { requestContext });
```


### 以 getter 方法取代直接存取屬性 {/* #direct-property-access-to-getter-methods */}

直接存取 `agent.llm`、`agent.tools` 及 `agent.instructions` 屬性的方式已棄用。存取方法改善了封裝，亦與整體 API 設計一致。

遷移時，請以對應的 getter 方法取代屬性存取。

```diff
- const llm = agent.llm;
- const tools = agent.tools;
- const instructions = agent.instructions;
+ const llm = agent.getLLM();
+ const tools = await agent.listTools();
+ const instructions = agent.getInstructions();
```

### 語音方法移至 `agent.voice` 命名空間 {/* #voice-methods-moved-to-agentvoice-namespace */}

語音相關方法已從 Agent 類別移至 `agent.voice` 命名空間，令語音 API 集中在同一處。

遷移時，請改由 `agent.voice` 命名空間呼叫語音方法。

```diff
- await agent.speak('Hello');
- await agent.listen();
- const speakers = agent.getSpeakers();
+ await agent.voice.speak('Hello');
+ await agent.voice.listen();
+ const speakers = agent.voice.getSpeakers();
```

### `agent.fetchMemory()` 改為 `(await agent.getMemory()).recall()` {/* #agentfetchmemory-to-await-agentgetmemoryrecall */}

`fetchMemory()` 方法已由新 API 取代；新 API 明確呈現非同步存取記憶的過程。

遷移時，請以新 API 取代 `fetchMemory()` 呼叫。

```diff
- const messages = await agent.fetchMemory({ threadId: 'thread-123' });
+ const memory = await agent.getMemory();
+ const result = await memory.recall({ threadId: 'thread-123' });
+ const messages = result.messages;
```

### 處理器方法由 `get*` 更名為 `list*` {/* #processor-method-names-from-get-to-list */}

Agent 的處理器方法已由 `get*` 更名為 `list*`，以與整體 API 保持一致。按此慣例，`list*` 方法會傳回集合。

若要遷移，請更新處理器方法名稱。

```diff
- const inputProcessors = await agent.getInputProcessors(runtimeContext);
- const outputProcessors = await agent.getOutputProcessors(runtimeContext);
+ const inputProcessors = await agent.listInputProcessors(requestContext);
+ const outputProcessors = await agent.listOutputProcessors(requestContext);
```

### 仍支援 Zod v3 及 v4 結構化輸出 schema {/* #zod-v3-and-v4-structured-output-schemas-remain-supported */}

Mastra v1 的公開 Agent API 在接收結構化輸出 schema 時，仍同時支援 Zod v3 及 Zod v4。這包括 `agent.generateLegacy()`、`agent.streamLegacy()` 等方法，以及相關選項類型。

就 Zod 版本相容性而言，傳入 Agent API 的現有 Zod schema 無須遷移。保留現有匯入即可：

```ts
import { z as z3 } from 'zod/v3'
import { z as z4 } from 'zod/v4'

await agent.generateLegacy({
  prompt: 'Summarize this ticket',
  output: z3.object({ summary: z3.string() }),
})

await agent.streamLegacy({
  prompt: 'Extract contact info',
  output: z4.object({ email: z4.string().email() }),
})
```

只有在想讓整個應用程式統一使用某個 Zod 版本時，才需要更新匯入。

### 按 AI SDK 版本更名預設選項方法 {/* #default-options-method-renames-for-ai-sdk-versions */}

預設選項方法已更名，以區分舊版 AI SDK v4 API 與 AI SDK v5+ API。現在可從方法名稱辨識適用的 AI SDK 版本。

若要遷移，請根據您使用的 AI SDK 版本更新方法名稱。

```diff
  // For legacy AI SDK v4
- const options = await agent.getDefaultGenerateOptions();
- const streamOptions = await agent.getDefaultStreamOptions();
+ const options = await agent.getDefaultGenerateOptionsLegacy();
+ const streamOptions = await agent.getDefaultStreamOptionsLegacy();

  // For new AI SDK v5+ (default)
  const streamOptions = await agent.getDefaultStreamOptions();
```

### 將 `modelSettings.abortSignal` 移至頂層 `abortSignal` {/* #modelsettingsabortsignal-to-top-level-abortsignal */}

`abortSignal` 選項已從 `modelSettings` 移至串流及生成選項的頂層。執行控制現在與模型專屬設定分開。

遷移時，請將 `abortSignal` 從 `modelSettings` 移至選項頂層。

```diff
  agent.stream('Hello', {
-   modelSettings: {
-     abortSignal: abortController.signal,
-   },
+   abortSignal: abortController.signal,
  });
```

### `output` 改為 `structuredOutput.schema` {/* #output-to-structuredoutputschema */}

已棄用的 `output` 及 `experimental_output` 選項已移除。結構化輸出現在統一使用單一、穩定的 API。

遷移時，請將 `output` 或 `experimental_output` 改為 `structuredOutput.schema`。

```diff
  agent.stream('Hello', {
-   output: z.object({ result: z.string() }),
+   structuredOutput: {
+     schema: z.object({ result: z.string() }),
+   },
  });
```

### 建立 Agent 時必須提供 `id` 欄位 {/* #agent-id-field-is-now-required */}

建立 Agent 時現在必須提供 `id` 欄位。以往可以不明確指定 ID；現在已不再支援。

遷移時，請為所有 Agent 設定新增 `id` 欄位。

```diff
  const agent = new Agent({
+   id: 'my-agent',
    name: 'My Agent',
    instructions: 'You are a helpful assistant',
    model: '__GATEWAY_OPENAI_MODEL__',
  });
```

`id` 可以與 `name` 相同，也可以使用其他識別值。呼叫 `mastra.getAgentById()` 時會用到此 ID；它在 Mastra 實例中必須是唯一的。

```typescript
// Register agent with Mastra
const mastra = new Mastra({
  agents: {
    myAgent: agent, // key can differ from id
  },
})

// Retrieve by ID
const agent = mastra.getAgentById('my-agent')
```

### 串流 API 回應現在會遮蔽敏感資料 {/* #stream-api-responses-now-redact-sensitive-data */}

Mastra 伺服器現在會自動遮蔽 Agent 串流回應中的敏感資訊，避免系統提示詞、Tool 定義及 API 金鑰意外出現在 `step-start`、`step-finish` 和 `finish` 串流區塊中。

**遮蔽的內容：**

- `request.body` 中的 LLM 請求內容（系統提示詞、Tool schema）
- 步驟結果中的 `metadata.request`
- 巢狀步驟資料中的 `output.steps[].request`

此行為預設啟用。如需存取完整請求資料，例如用於除錯或內部服務，可在直接使用伺服器轉接器（如 `@mastra/hono` 或 `@mastra/express`）時停用遮蔽功能。

## 移除的功能 {/* #removed */}

### `generateVNext` 和 `streamVNext` 方法 {/* #generatevnext-and-streamvnext-methods */}

已棄用的 `generateVNext()` 和 `streamVNext()` 方法已移除。這些方法以往用於相容 AI SDK v5+；其實作現在已成為標準實作。

遷移時，請改用標準的 `generate()` 和 `stream()` 方法。

```diff
- const result = await agent.generateVNext('Hello');
- const stream = await agent.streamVNext('Hello');
+ const result = await agent.generate('Hello');
+ const stream = await agent.stream('Hello');
```

```bash
npx @mastra/codemod@latest v1/agent-generate-stream-v-next .
```

### 從 `stream()` 和 `generate()` 移除 `format` 參數 {/* #format-parameter-from-stream-and-generate */}

`agent.stream()` 和 `agent.generate()` 方法不再接受 `format` 參數。AI SDK 串流格式轉換現在由 `@mastra/ai-sdk` 套件處理。將 AI SDK 專屬程式碼移至獨立套件，亦改善了 tree-shaking 效果。

遷移時，請使用 `@mastra/ai-sdk` 的 `toAISdkStream()` 函式轉換為 AI SDK 格式。

```diff
- const stream = await agent.stream(messages, {
-   format: 'aisdk',
- });

+ import { toAISdkStream } from '@mastra/ai-sdk';
+
+ const stream = await agent.stream(messages);
+ const aiSdkStream = toAISdkStream(stream, { from: 'agent' });
```

### `agent.toStep()` 方法 {/* #agenttostep-method */}

Agent 類別中的 `toStep()` 方法已移除。現在可以直接將 Agent 加入 Workflow 步驟，無須明確轉換。

遷移時，請直接將 Agent 加入 Workflow 步驟；Workflow 會自動完成轉換。

```diff
- const step = agent.toStep();
- const workflow = new Workflow({
-   steps: [step],
- });

+ const workflow = new Workflow({
+   steps: [agent],
+ });
```

### 移除 Agent 的 `TMetrics` 泛型參數 {/* #tmetrics-generic-parameter-from-agent */}

`AgentConfig` 及 `Agent` 建構函式不再使用 `TMetrics` 泛型參數。指標與評分器現在透過 scorers API 設定，不再屬於 Agent 的類型系統。

遷移時，請移除 `TMetrics` 泛型參數，並使用新 API 設定評分器。

```diff
- const agent = new Agent<AgentId, Tools, Metrics>({
+ const agent = new Agent<AgentId, Tools>({
    // ...
  });
```

### Tripwire 回應格式變更 {/* #tripwire-response-format-changed */}

Tripwire 回應不再使用獨立的 `tripwire` 及 `tripwireReason` 欄位，而是由單一 `tripwire` 物件包含所有相關資料。

遷移時，請更新程式碼，從新的物件結構讀取 Tripwire 資料。

```diff
  const result = await agent.generate('Hello');

- if (result.tripwire) {
-   console.log(result.tripwireReason);
- }
+ if (result.tripwire) {
+   console.log(result.tripwire.reason);
+   // New fields available:
+   // result.tripwire.retry - whether this step should be retried
+   // result.tripwire.metadata - additional metadata from the processor
+   // result.tripwire.processorId - which processor triggered the tripwire
+ }
```

對於串流回應：

```diff
  for await (const chunk of stream.fullStream) {
    if (chunk.type === 'tripwire') {
-     console.log(chunk.payload.tripwireReason);
+     console.log(chunk.payload.reason);
+     // New fields available:
+     // chunk.payload.retry
+     // chunk.payload.metadata
+     // chunk.payload.processorId
    }
  }
```

步驟結果現在亦包含 Tripwire 資訊：

```diff
  const result = await agent.generate('Hello');

  for (const step of result.steps) {
-   // No tripwire info on steps
+   if (step.tripwire) {
+     console.log('Step was blocked:', step.tripwire.reason);
+   }
  }
```

### `prepareStep` 訊息格式 {/* #preparestep-messages-format */}

`prepareStep` 回呼現在接收 `MastraDBMessage` 格式的訊息，而非 AI SDK v5+ 的模型訊息格式。這令它與新的 `processInputStep` 處理器方法保持一致；該方法會在 Agent 迴圈的每一步執行。

如需舊版 AI SDK v5+ 格式，請使用 `messageList.get.all.aiV5.model()`：

```diff
  agent.generate('Hello', {
    prepareStep: async ({ messages, messageList }) => {
-     // messages was AI SDK v5+ ModelMessage format
-     console.log(messages[0].content);
+     // messages is now MastraDBMessage format
+     // Use messageList to get AI SDK v5+ format if needed:
+     const aiSdkMessages = messageList.get.all.aiV5.model();

      return { toolChoice: 'auto' };
    },
  });
```

### 將 `threadId` 和 `resourceId` 移至 `memory` 選項 {/* #threadid-and-resourceid-to-memory-option */}

`agent.stream()` 和 `agent.generate()` 不再接受 `threadId` 及 `resourceId` 選項。請改用 `memory` 選項，以更清晰的方式設定記憶。

遷移時，請將 `threadId` 及 `resourceId` 移入 `memory` 選項：

```diff
  await agent.stream('Hello', {
-   threadId: 'thread-123',
-   resourceId: 'user-456',
+   memory: {
+     thread: 'thread-123',
+     resource: 'user-456',
+   },
  });
```

建立新對話執行緒時，`memory` 選項亦支援傳入執行緒中繼資料：

```typescript
await agent.stream('Hello', {
  memory: {
    thread: {
      id: 'thread-123',
      title: 'Support conversation',
      metadata: { category: 'billing' },
    },
    resource: 'user-456',
  },
})
```
