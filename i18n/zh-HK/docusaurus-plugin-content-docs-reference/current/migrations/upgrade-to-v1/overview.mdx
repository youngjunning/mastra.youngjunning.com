# 升級到 Mastra v1

:::注意\[更新至最新0.x版本]
在升級到 v1 之前，請確保您已更新至 Mastra 的最新 0.x 版本。遵循[upgrade to latest 0.x guide](https://mastra.ai/guides/v0/migrations/upgrade-to-latest-0x)首先，然後返回此處完成 v1 遷移。
:::

Mastra v1 於 2026 年 1 月發布。我們建議使用 Mastra v1 啟動任何新項目，或升級現有項目以繼續接收更新和支援。

本指南涵蓋從 Mastra 0.x 升級到 v1.0 時的重大變更。遷移按套件和功能區域組織，以協助您系統地更新程式碼庫。

:::提示\[需要幫助嗎？ ]
需要遷移方面的協助嗎？加入我們的[Discord community](https://discord.gg/mastra-ai) to ask questions.
:::

:::警告\[來自 Mastra Cloud？ ]
舊版 Mastra Cloud 產品已被替換為[Mastra platform](/docs/mastra-platform/overview), which splits hosting into two separate products: **Studio** (visual environment, observability) and **Server** (production API). Because old Mastra Cloud access tokens don't work with Mastra platform, create new ones with `mastra auth tokens create`.

如果您升級到 v1 軟體包而不遷移您的`telemetry:` config to `observability:` and creating a Studio project, observability data will stop flowing. Follow the [Mastra Cloud migration guide](/reference/migrations/mastra-cloud) end to end.
:::

## 遷移策略 {/* #migration-strategy */}

### 將所有 Mastra 軟體包更新為`latest` tag {/* #update-all-mastra-packages-to-latest-tag */}

使用套件管理器更新專案的版本。更新**all** Mastra packages together to ensure compatibility (all `@mastra/*` packages and `mastra`).

以下是更新最常用軟體包的方法：

```bash npm2yarn
npm install @mastra/core@latest @mastra/loggers@latest @mastra/memory@latest mastra@latest
```

安裝任何其他 Mastra 軟體包`@latest` tag and you'll get the latest v1 version available. Be sure to update all Mastra packages (especially if you're in a monorepo) to avoid version mismatches.

### 更新 Node.js 版本 {/* #update-nodejs-version */}

Mastra v1 需要 Node.js**22.13.0** or higher. Update your development and production environments accordingly.

### 完成遷移清單 {/* #go-through-migration-checklist */}

工作通過[migration checklist](#migration-checklist) below to update your codebase. Each item links to a detailed guide for that specific change.

:::注意\[程式碼模組]

我們準備了自動化[codemods](https://github.com/mastra-ai/mastra/tree/main/packages/codemod) for you. If you want, you can run all v1 codemods at once:

```bash
npx @mastra/codemod@latest v1
```

:::

:::注意\[需要遷移資料庫]

如果您使用 PostgreSQL 或 LibSQL 存儲，則需要執行資料庫遷移。請參閱[Storage migration guide](/reference/migrations/upgrade-to-v1/storage#database-migration) for details.

:::

## 按地區劃分的重大變化 {/* #breaking-changes-by-area */}

* **[馬斯特拉級](/reference/migrations/upgrade-to-v1/mastra)**- 進口重組和財產准入變更。
* **[Agent類](/reference/migrations/upgrade-to-v1/agent)**- 語音方法移至命名空間和串流 API 更新。
* **[Tool](/reference/migrations/upgrade-to-v1/tools)**- CreateTool 執行簽名會變更為單獨的輸入和上下文。
* **[Workflow](/reference/migrations/upgrade-to-v1/workflows)**- 函數名稱更改並刪除了舊功能。
* **[記憶](/reference/migrations/upgrade-to-v1/memory)**- 配置現在需要明確參數並更改預設值。
* **[貯存](/reference/migrations/upgrade-to-v1/storage)**- 分頁標準化，方法重新命名為清單模式。
* **[向量](/reference/migrations/upgrade-to-v1/vectors)**- 向量儲存方法重新命名為清單模式。
* **[抹布](/reference/migrations/upgrade-to-v1/rag)**- 為了清晰起見，更新了參數命名。
* **[MCP](/reference/migrations/upgrade-to-v1/mcp)**- 重新組織了Tool上下文並刪除了已棄用的客戶端類別。
* **[追蹤](/reference/migrations/upgrade-to-v1/tracing)**- OTEL 遙測技術被專用觀測套件和導出器取代。
* **[評估和記分員](/reference/migrations/upgrade-to-v1/evals)**- Scorers API 與新的命名約定相結合。
* **[命令列介面](/reference/migrations/upgrade-to-v1/cli)**- 刪除命令和標誌以簡化介面。
* **[部署](/reference/migrations/upgrade-to-v1/deployment)**- CloudflareDeployer 配置更新為使用標準 wrangler.json 屬性名稱。
* **[客戶端 SDK](/reference/migrations/upgrade-to-v1/client)**- 為保持一致性而重新命名的類型和實用程式。
* **[語音套餐](/reference/migrations/upgrade-to-v1/voice)**- 套件從語音重新命名為語音。

## 遷移清單 {/* #migration-checklist */}

按順序完成此清單，從影響大多數應用程式的高影響力變更開始。

:::注意\[程式碼模組]

我們準備了自動化[codemods](https://github.com/mastra-ai/mastra/tree/main/packages/codemod) for you. Throughout the migration guide you'll find instructions on how to use them for specific changes.

如果需要，您可以一次運行所有 v1 codemod：

```bash
npx @mastra/codemod@latest v1
```

:::

### 高影響力的變化 {/* #high-impact-changes */}

* 更新`createTool` tool signatures to `(inputData, context)` format - [Tools](/reference/migrations/upgrade-to-v1/tools)
* 重組`@mastra/core` imports to use subpath imports - [Mastra Class](/reference/migrations/upgrade-to-v1/mastra)
* 更新分頁自`offset/limit` to `page/perPage` - [Storage](/reference/migrations/upgrade-to-v1/storage)
* 安裝`@mastra/observability` and wrap configuration with `new Observability()` - [Tracing](/reference/migrations/upgrade-to-v1/tracing)
* 遷移自`telemetry:` to `observability:` configuration (if upgrading from 0.x OTEL) - [Tracing](/reference/migrations/upgrade-to-v1/tracing)

### 中等影響的變化 {/* #medium-impact-changes */}

* 重新命名`RuntimeContext` to `RequestContext` throughout codebase - [Agent Class](/reference/migrations/upgrade-to-v1/agent), [Tools](/reference/migrations/upgrade-to-v1/tools), [Workflows](/reference/migrations/upgrade-to-v1/workflows)
* 更新儲存方法`get*` to `list*` pattern - [Storage](/reference/migrations/upgrade-to-v1/storage)
* 用 getter 方法替換直接屬性存取 -[Mastra Class](/reference/migrations/upgrade-to-v1/mastra), [Agent Class](/reference/migrations/upgrade-to-v1/agent)
* 如果依賴預設值則更新記憶體範圍`thread` scope - [Memory](/reference/migrations/upgrade-to-v1/memory)
* 更新向量存儲調用以按名稱使用參數 -[Storage](/reference/migrations/upgrade-to-v1/storage)
* 消除`format` parameter from agent methods - [Agent Class](/reference/migrations/upgrade-to-v1/agent)
* 更新要使用的語音方法`agent.voice` namespace - [Agent Class](/reference/migrations/upgrade-to-v1/agent)
* 重命名配置屬性`processors` to `spanOutputProcessors` (if using custom processors) - [Tracing](/reference/migrations/upgrade-to-v1/tracing)

### 影響較小的變更 {/* #low-impact-changes */}

* 重新命名`keepSeparator` to `separatorPosition` in chunk options - [RAG](/reference/migrations/upgrade-to-v1/rag)
* 重新命名`createRunAsync` to `createRun` - [Workflows](/reference/migrations/upgrade-to-v1/workflows)
* 更新語音包名稱`@mastra/speech-*` to `@mastra/voice-*` - [Voice Packages](/reference/migrations/upgrade-to-v1/voice)
* 更新記分器方法：`runExperiment` → `runEvals`, `getScorerByName` → `getScorerById` - [Evals & Scorers](/reference/migrations/upgrade-to-v1/evals)
* [CLI](/reference/migrations/upgrade-to-v1/cli)
* 更新客戶端 SDK 類型`Get*` to `List*` - [Client SDKs](/reference/migrations/upgrade-to-v1/client)
* 代替`runCount` with `retryCount` - [Workflows](/reference/migrations/upgrade-to-v1/workflows)
* 更新自訂匯出器方法`exportEvent` to `exportTracingEvent` (if using custom exporters) - [Tracing](/reference/migrations/upgrade-to-v1/tracing)
