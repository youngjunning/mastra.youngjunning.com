# 追蹤

v1 重新架構了可觀測性系統，並將其移至獨立的 `@mastra/observability` 套件。本指南介紹兩種遷移方式，具體取決於您從哪個版本升級。

:::warning[升級後可觀測性數據將停止傳送]
如果您將 Mastra 套件升級至 v1，卻未將 `telemetry:` 設定遷移為 `observability:`，舊設定會在執行時被忽略。服務仍會正常啟動而不會報錯，但**追蹤、日誌和指標都不會傳送到任何目的地**。如果您之前將數據傳送至 Mastra Cloud，其儀表板將不再顯示數據。

請在升級 Mastra 套件的同一次變更中完成遷移，並確認追蹤已出現在 [Mastra Studio](/docs/studio/observability)，然後才將升級視為完成。如果您之前使用 Mastra Cloud 託管服務，亦須依照 [Mastra Cloud 遷移指南](/reference/migrations/mastra-cloud) 操作。新平台需要新的存取權杖和 Studio 專案，`MastraPlatformExporter` 才能將數據傳送至該平台。
:::

:::note[匯出器重新命名]

`MastraPlatformExporter`（將數據傳送至 Mastra 平台）取代原本的 `CloudExporter`；`MastraStorageExporter`（將數據持久儲存至 Mastra Storage）取代原本的 `DefaultExporter`。舊類別仍可從 `@mastra/observability` 匯入，行為亦維持不變，但已被棄用。新程式碼應使用 `MastraPlatformExporter` 和 `MastraStorageExporter`。現有的 `CloudExporter` 或 `DefaultExporter` 匯入在未來的主要版本移除這些類別之前仍可使用。

:::

## 遷移路徑 {/* #migration-paths */}

### 從以 OTEL 為基礎的遙測遷移（0.x） {/* #from-otel-based-telemetry-0x */}

如果您在 Mastra 中使用舊版 `telemetry:` 設定，需要遷移至經過全面重新設計的新系統。

**之前（0.x，帶有 OTEL 遙測）：**

```typescript
import { Mastra } from '@mastra/core'

export const mastra = new Mastra({
  telemetry: {
    serviceName: 'my-app',
    enabled: true,
    sampling: {
      type: 'always_on',
    },
    export: {
      type: 'otlp',
      endpoint: 'http://localhost:4318',
    },
  },
})
```

**遷移後（v1 可觀測性）：**

```typescript
import { Mastra } from '@mastra/core'
import {
  Observability,
  MastraStorageExporter,
  MastraPlatformExporter,
  SensitiveDataFilter,
} from '@mastra/observability'

export const mastra = new Mastra({
  observability: new Observability({
    configs: {
      default: {
        serviceName: 'mastra',
        exporters: [
          new MastraStorageExporter(), // Persists observability events to Mastra Storage
          new MastraPlatformExporter(), // Sends observability events to Mastra platform (if MASTRA_PLATFORM_ACCESS_TOKEN is set)
        ],
        spanOutputProcessors: [
          new SensitiveDataFilter(), // Redacts sensitive data like passwords, tokens, keys
        ],
      },
    },
  }),
})
```

此設定包含 `MastraStorageExporter`、`MastraPlatformExporter` 和 `SensitiveDataFilter` 處理器。完整設定選項請參閱[可觀測性追蹤文件](/docs/observability/tracing/overview)。

#### 遷移後（v1 自訂設定） {/* #after-v1-with-custom-configuration */}

如果需要使用特定的匯出器（例如 OTLP），請安裝對應的匯出器套件並進行設定：

```bash npm2yarn
npm install @mastra/otel-exporter@latest @opentelemetry/exporter-trace-otlp-proto
```

```typescript
import { Mastra } from '@mastra/core'
import { Observability } from '@mastra/observability'
import { OtelExporter } from '@mastra/otel-exporter'

export const mastra = new Mastra({
  observability: new Observability({
    configs: {
      production: {
        serviceName: 'my-app',
        sampling: { type: 'always' },
        exporters: [
          new OtelExporter({
            provider: {
              custom: {
                endpoint: 'http://localhost:4318/v1/traces',
                protocol: 'http/protobuf',
              },
            },
          }),
        ],
      },
    },
  }),
})
```

主要變化：

1. 安裝 `@mastra/observability` 套件
2. 將 `telemetry:` 替換為 `observability: new Observability()`
3. 在 `configs:` 中明確設定 `MastraStorageExporter`、`MastraPlatformExporter` 和 `SensitiveDataFilter`
4. 將字串形式的匯出類型（`'otlp'`）改為匯出器類別實例（`new OtelExporter()`）

### 從 AI 追蹤遷移 {/* #from-ai-tracing */}

如果您已升級至作為過渡方案的 AI 追蹤系統，需要安裝新套件並明確設定。

**遷移前（AI 追蹤）：**

```typescript
import { Mastra } from '@mastra/core'

export const mastra = new Mastra({
  observability: {
    default: { enabled: true },
  },
})
```

**遷移後（v1 可觀測性）：**

```typescript
import { Mastra } from '@mastra/core'
import {
  Observability,
  MastraStorageExporter,
  MastraPlatformExporter,
  SensitiveDataFilter,
} from '@mastra/observability'

export const mastra = new Mastra({
  observability: new Observability({
    configs: {
      default: {
        serviceName: 'mastra',
        exporters: [new MastraStorageExporter(), new MastraPlatformExporter()],
        spanOutputProcessors: [new SensitiveDataFilter()],
      },
    },
  }),
})
```

主要變化：

1. 安裝 `@mastra/observability` 套件
2. 從 `@mastra/observability` 匯入 `Observability`、匯出器和處理器
3. 在 `configs` 中明確設定 `MastraStorageExporter`、`MastraPlatformExporter` 和 `SensitiveDataFilter`

## 變更內容 {/* #changed */}

### 套件匯入路徑 {/* #package-import-path */}

可觀測性功能已移至獨立的 `@mastra/observability` 套件。

遷移時，請安裝套件並更新匯入敘述：

```bash npm2yarn
npm install @mastra/observability@latest
```

```diff
- import { Tracing } from '@mastra/core/observability';
+ import { Observability } from '@mastra/observability';
```

### 登錄區設定 {/* #registry-configuration */}

可觀測性登錄區現在透過含有明確設定的 `Observability` 類別實例進行設定，不再使用一般物件。

遷移時，請使用 `new Observability()` 明確設定匯出器和處理器。

```diff
+ import {
+   Observability,
+   MastraStorageExporter,
+   MastraPlatformExporter,
+   SensitiveDataFilter,
+ } from '@mastra/observability';

  export const mastra = new Mastra({
-   observability: {
-     default: { enabled: true },
-   },
+   observability: new Observability({
+     configs: {
+       default: {
+         serviceName: 'mastra',
+         exporters: [new MastraStorageExporter(), new MastraPlatformExporter()],
+         spanOutputProcessors: [new SensitiveDataFilter()],
+       },
+     },
+   }),
  });
```

### 設定屬性從 `processors` 改為 `spanOutputProcessors` {/* #configuration-property-processors-to-spanoutputprocessors */}

span 處理器的設定屬性已從 `processors` 重新命名為 `spanOutputProcessors`。

遷移時，請在設定物件中重新命名此屬性。

```diff
+ import { SensitiveDataFilter } from '@mastra/observability';

  export const mastra = new Mastra({
    observability: new Observability({
      configs: {
        production: {
          serviceName: 'my-app',
-         processors: [new SensitiveDataFilter()],
+         spanOutputProcessors: [new SensitiveDataFilter()],
          exporters: [...],
        },
      },
    }),
  });
```

### 匯出器方法從 `exportEvent` 改為 `exportTracingEvent` {/* #exporter-method-exportevent-to-exporttracingevent */}

如果您實作了自訂匯出器，其匯出方法已從 `exportEvent` 重新命名為 `exportTracingEvent`。

遷移時，請更新自訂匯出器中的方法實作。

```diff
  export class MyExporter implements ObservabilityExporter {
-   exportEvent(event: TracingEvent): void {
+   exportTracingEvent(event: TracingEvent): void {
      // export logic
    }
  }
```

## 已刪除 {/* #removed */}

### 以 OTEL 為基礎的 `telemetry` 設定 {/* #otel-based-telemetry-configuration */}

0.x 中以 OTEL 為基礎的 `telemetry` 設定已移除。舊系統中的 `serviceName`、`sampling.type` 和 `export.type` 屬性不再受支援。

遷移時，請依照上文「從以 OTEL 為基礎的遙測遷移」一節操作。詳細設定選項請參閱[可觀測性追蹤文件](/docs/observability/tracing/overview)。

### 自訂檢測檔案 {/* #custom-instrumentation-files */}

系統不再自動偵測 `/mastra` 中副檔名為 `.ts`、`.js` 或 `.mjs` 的檢測檔案，也不再支援透過獨立檔案加入自訂檢測邏輯。

遷移時，請使用內建匯出器系統，或透過 `ObservabilityExporter` 介面實作自訂匯出器。

### `instrumentation.mjs` 檔案 {/* #instrumentationmjs-files */}

如果您之前使用 `instrumentation.mjs` 檔案初始化 OpenTelemetry 檢測邏輯（在 AWS Lambda 等部署環境中很常見），現在不再需要這些檔案。新的可觀測性系統直接在 Mastra 實例中設定。

#### 遷移前（0.x） {/* #before-0x */}

之前需要一個檢測檔案：

```javascript
// instrumentation.mjs
import { NodeSDK } from '@opentelemetry/sdk-node'
// ... OTEL setup
```

啟動程序時還必須匯入該檔案：

```bash
node --import=./.mastra/output/instrumentation.mjs --env-file=".env" .mastra/output/index.mjs
```

#### 遷移後（v1） {/* #after-v1 */}

只需刪除 `instrumentation.mjs` 檔案，並在 Mastra 實例中設定可觀測性：

```typescript
// src/mastra/index.ts
import {
  Observability,
  MastraStorageExporter,
  MastraPlatformExporter,
  SensitiveDataFilter,
} from '@mastra/observability'

export const mastra = new Mastra({
  observability: new Observability({
    configs: {
      default: {
        serviceName: 'mastra',
        exporters: [new MastraStorageExporter(), new MastraPlatformExporter()],
        spanOutputProcessors: [new SensitiveDataFilter()],
      },
    },
  }),
})
```

正常啟動程序即可，無須使用 `--import` 旗標：

```bash
node --env-file=".env" .mastra/output/index.mjs
```

不再需要獨立的檢測檔案或特殊的啟動旗標。

### 安裝 {/* #installation */}

**專用匯出器**（Arize、Braintrust、Langfuse、LangSmith）：

```bash npm2yarn
npm install @mastra/[exporter-name]-exporter
```

**OpenTelemetry 匯出器**（Dash0、Laminar、New Relic、SigNoz、Traceloop）：

```bash npm2yarn
npm install @mastra/otel-exporter@latest
```

還需安裝該 Provider 所需的通訊協定套件（請參閱 [OTEL 指南](/integrations/observability/opentelemetry#exporter)）。
