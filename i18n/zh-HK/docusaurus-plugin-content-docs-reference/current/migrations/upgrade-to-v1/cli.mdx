# CLI

CLI 已移除部署指令、設定標記及初始檔案，令操作更精簡；同時新增遷移指令，協助升級資料庫 schema。

## 新增 {/* #added */}

### `mastra migrate` 指令 {/* #mastra-migrate-command */}

新增的 `mastra migrate` 指令可在升級 Mastra 版本時執行資料庫遷移。由可能存在資料不相容問題的舊版本升級時，這項功能尤其實用。

```bash
npx mastra migrate
```

此指令會先打包專案並連接至已設定的儲存空間，再執行所有必要的遷移。目前支援遷移重複的 span 項目；這些重複項目可能會阻止建立唯一約束。

如要了解何時需要此遷移，請參閱[儲存空間遷移指南](/reference/migrations/upgrade-to-v1/storage#duplicate-spans-migration)。

## 已刪除 {/* #removed */}

### `mastra deploy` 指令 {/* #mastra-deploy-command */}

CLI 已移除 `mastra deploy` 指令。這項變更移除了特定供應商的部署邏輯，令 CLI 更精簡。

遷移時，請選擇適合你的[部署平台](/docs/deployment/overview)。

### 移除 `--env` 標記（`mastra build`） {/* #--env-flag-from-mastra-build */}

`--env` 標記已從 `mastra build` 指令中移除，令建置指令更精簡。

遷移時，請使用 `mastra start --env <env>`，以自訂環境啟動建置輸出。

```diff
- mastra build --env production
+ mastra build
+ mastra start --env production
```

### 移除 `--port` 標記（`mastra dev`） {/* #--port-flag-from-mastra-dev */}

`--port` 標記已從 `mastra dev` 指令中移除。連接埠現時透過 Mastra 實例設定集中管理。

遷移時，請在 Mastra 實例中設定 `server.port`，不要再使用 CLI 標記。

```ts
const mastra = new Mastra({
  server: {
    port: 3001,
  },
})
```

### CLI 中的遙測選項 {/* #telemetry-options-from-cli */}

CLI 指令已移除 `telemetry` 選項，包括 `--no-telemetry` / `-nt` 標記。遙測功能現已移至 observability 套件，因此 CLI 不再提供遙測設定。

遷移時，請從 CLI 指令中移除遙測標記，並使用 `@mastra/observability` 提供的 tracing 功能。
