# createTool()

使用 `createTool()` 函式可定義自訂 Tool，讓 Mastra Agent 能與外部系統互動、執行運算或存取指定資料。

## 使用範例 {/* #usage-example */}

```typescript title="src/mastra/tools/weather-tool.ts"
import { createTool } from '@mastra/core/tools'
import { z } from 'zod'

export const weatherTool = createTool({
  id: 'weather-tool',
  description: 'Get the current weather for a location',
  inputSchema: z.object({
    location: z.string(),
  }),
  outputSchema: z.object({
    location: z.string(),
    temperatureCelsius: z.number(),
    conditions: z.string(),
  }),
  execute: async ({ location }) => {
    return {
      location,
      temperatureCelsius: 21,
      conditions: 'sunny',
    }
  },
})
```

`execute` 的第一個參數是經 `inputSchema` 驗證的值。你可以直接在函式簽署中解構結構定義內的欄位，例如 `{ location }`。第二個參數可選，包含執行上下文。

### 僅供顯示的 Tool {/* #display-only-tools */}

如果 Tool 只需讓客戶端顯示內容，請設定 `renderOnly: true`，毋須定義 `execute`：

```typescript
const showCard = createTool({
  id: 'show-card',
  description: 'Display a product card',
  inputSchema: z.object({ productId: z.string() }),
  renderOnly: true,
})
```

Mastra 會透過串流發出 Tool 呼叫，並傳回 `{ acknowledged: true }` 作為結果，讓 Agent 毋須等候客戶端回覆便可繼續產生文字。這個做法亦適用於子 Agent 的 Tool，其呼叫會以嵌套的 `tool-output` 串流事件出現。請勿為僅供顯示的 Tool 設定與確認結果不相容的 `outputSchema`。確認結果只表示呼叫已發出，**不**表示瀏覽器已呈現內容。如果 Agent 需要根據客戶端操作的結果繼續處理，請省略 `execute`，由客戶端傳回結果。如果子 Agent 需要用戶輸入，亦可使用可暫停的伺服器端 Tool。

## 為 Tool 輸入啟用嚴格模式的例子 {/* #example-with-strict-tool-inputs */}

設定 `strict: true` 後，Mastra 會要求支援嚴格模式的模型 Provider 產生完全符合 Tool 結構描述的參數。

```typescript title="src/mastra/tools/weather-tool.ts"
import { createTool } from '@mastra/core/tools'
import { z } from 'zod'

export const weatherTool = createTool({
  id: 'weather-tool',
  description: 'Get the current weather for a location',
  strict: true,
  inputSchema: z.object({
    location: z.string(),
  }),
  outputSchema: z.object({
    location: z.string(),
    temperatureCelsius: z.number(),
    conditions: z.string(),
  }),
  execute: async ({ location }) => {
    return {
      location,
      temperatureCelsius: 21,
      conditions: 'sunny',
    }
  },
})
```

Mastra 只會將 `strict: true` 傳給支援嚴格模式 Tool 呼叫的模型配接器，對其他配接器則會忽略這項設定。

## `toModelOutput` 例子 {/* #example-with-tomodeloutput */}

如果應用程式需要取得 Tool 傳回的詳細內部資料，而模型只需接收簡化後的值或多模態內容，請使用 `toModelOutput`。

```typescript title="src/mastra/tools/weather-tool.ts"
import { createTool } from '@mastra/core/tools'
import { z } from 'zod'

export const weatherTool = createTool({
  id: 'weather-tool',
  description: 'Get the current weather for a location',
  inputSchema: z.object({
    location: z.string(),
  }),
  outputSchema: z.object({
    location: z.string(),
    temperatureCelsius: z.number(),
    conditions: z.string(),
    radarImageUrl: z.string().url(),
  }),
  execute: async ({ location }) => ({
    location,
    temperatureCelsius: 21,
    conditions: 'sunny',
    radarImageUrl: 'https://example.com/radar/seattle.png',
  }),
  toModelOutput: output => {
    return {
      type: 'content',
      value: [
        {
          type: 'text',
          text: `${output.location}: ${output.temperatureCelsius}°C and ${output.conditions}`,
        },
        { type: 'image-url', url: output.radarImageUrl },
      ],
    }
  },
})
```

Tool 仍會向應用程式傳回完整的 `execute` 結果，而模型收到的是經 `toModelOutput` 轉換後的值。

`toModelOutput` 可以傳回：

* `type: 'text'`
* `type: 'json'`
* `type: 'content'`，其中包含 `text`、`image-url`、`image-data`、`file-url`、`file-data`、`file-id`、`image-file-id` 或 `custom` 等內容部分

`toModelOutput` 亦適用於由客戶端執行而未定義 `execute` 函式的 Tool。客戶端在下一次請求中交回 Tool 結果後，伺服器會先以 Tool 定義中的 `toModelOutput` 轉換結果，再交給模型。

## `transform` 例子 {/* #example-with-transform */}

如果 Tool 在執行時需要保留原始輸入或輸出，但用於介面顯示的串流資料或對話記錄中的訊息只需包含更精簡或更安全的資料，請使用 `transform`。

```typescript title="src/mastra/tools/customer-tool.ts"
import { createTool } from '@mastra/core/tools'
import { z } from 'zod'

export const customerTool = createTool({
  id: 'lookup-customer',
  description: 'Looks up a customer',
  inputSchema: z.object({
    customerId: z.string(),
    internalPath: z.string(),
  }),
  outputSchema: z.object({
    displayName: z.string(),
    apiKey: z.string(),
    debugScore: z.number(),
  }),
  execute: async () => {
    return {
      displayName: 'Acme',
      apiKey: 'secret-value',
      debugScore: 0.97,
    }
  },
  transform: {
    display: {
      input: ({ input }) => ({ customerId: input?.customerId }),
      output: ({ output }) => ({ displayName: output?.displayName }),
      error: () => ({ message: 'Customer lookup failed' }),
    },
    transcript: {
      input: ({ input }) => ({ customerId: input?.customerId }),
      output: ({ output }) => ({ displayName: output?.displayName }),
      error: () => ({ message: 'Customer lookup failed' }),
    },
  },
})
```

Tool 仍會接收 `inputSchema` 所定義的原始輸入值，並傳回 `execute` 的原始結果。Mastra 會對串流傳送至介面的資料套用 `display` 轉換，並對用戶可見的對話記錄訊息套用 `transcript` 轉換。

## MCP 註記例子 {/* #example-with-mcp-annotations */}

透過 MCP（Model Context Protocol）公開 Tool 時，可以加入註記來描述 Tool 的行為，並自訂 Tool 在客戶端的顯示方式。這些 MCP 專用屬性集中在 `mcp` 屬性內：

```typescript title="src/mastra/tools/weather-tool.ts"
import { createTool } from '@mastra/core/tools'
import { z } from 'zod'

export const weatherTool = createTool({
  id: 'weather-tool',
  description: 'Get the current weather for a location',
  inputSchema: z.object({
    location: z.string().describe('City name or coordinates'),
  }),
  outputSchema: z.object({
    location: z.string(),
    temperatureCelsius: z.number(),
    conditions: z.string(),
  }),
  // MCP-specific properties
  mcp: {
    // Annotations for client behavior hints
    annotations: {
      title: 'Weather Lookup', // Human-readable display name
      readOnlyHint: true, // Tool doesn't modify environment
      destructiveHint: false, // Tool doesn't perform destructive updates
      idempotentHint: true, // Same args = same result
      openWorldHint: true, // Interacts with external API
    },
    // Custom metadata for client-specific functionality
    _meta: {
      version: '1.0.0',
      category: 'weather',
    },
  },
  execute: async ({ location }) => {
    return {
      location,
      temperatureCelsius: 21,
      conditions: 'sunny',
    }
  },
})
```

## Tool 生命週期鉤子 {/* #tool-lifecycle-hooks */}

Tool 支援生命週期鉤子，用於監察 Tool 執行的各個階段並作出回應。這些鉤子特別適合在串流期間記錄日誌、分析資料、執行驗證及即時更新。

以下例子為 Tool 設定了所有生命週期鉤子：

```typescript title="src/mastra/tools/weather-tool.ts"
import { createTool } from '@mastra/core/tools'
import { z } from 'zod'

export const weatherTool = createTool({
  id: 'weather-tool',
  description: 'Get the current weather for a location',
  inputSchema: z.object({
    location: z.string(),
  }),
  outputSchema: z.object({
    location: z.string(),
    temperatureCelsius: z.number(),
    conditions: z.string(),
  }),
  execute: async ({ location }) => {
    return {
      location,
      temperatureCelsius: 21,
      conditions: 'sunny',
    }
  },
  onInputStart: ({ toolCallId }) => {
    console.log(`Tool call ${toolCallId} input started`)
  },
  onInputDelta: ({ inputTextDelta, toolCallId }) => {
    console.log(`Tool call ${toolCallId} received input chunk: ${inputTextDelta}`)
  },
  onInputAvailable: ({ input, toolCallId }) => {
    console.log(`Tool call ${toolCallId} received location: ${input.location}`)
  },
  onOutput: ({ output, toolCallId, toolName }) => {
    console.log(`Tool ${toolName} call ${toolCallId} returned conditions: ${output.conditions}`)
  },
})
```

### 可用鉤子 {/* #available-hooks */}

#### `onInputStart` {/* #oninputstart */}

Tool 呼叫的輸入開始串流傳輸時觸發，此時尚未收到任何輸入資料。

```typescript
export const tool = createTool({
  id: 'example-tool',
  description: 'Example tool with hooks',
  onInputStart: ({ toolCallId, messages, abortSignal }) => {
    console.log(`Tool ${toolCallId} input streaming started`)
  },
})
```

#### `onInputDelta` {/* #oninputdelta */}

每收到一段串流傳入的文字便會觸發一次。可用於顯示即時進度或解析尚未接收完整的 JSON。

```typescript
export const tool = createTool({
  id: 'example-tool',
  description: 'Example tool with hooks',
  onInputDelta: ({ inputTextDelta, toolCallId, messages, abortSignal }) => {
    console.log(`Received input chunk: ${inputTextDelta}`)
  },
})
```

#### `onInputAvailable` {/* #oninputavailable */}

收到完整的 Tool 輸入並按 `inputSchema` 完成解析和驗證後觸發。

```typescript
export const tool = createTool({
  id: 'example-tool',
  description: 'Example tool with hooks',
  inputSchema: z.object({
    location: z.string(),
  }),
  onInputAvailable: ({ input, toolCallId, messages, abortSignal }) => {
    console.log(`Tool received complete input:`, input)
    // input is fully typed based on inputSchema
  },
})
```

#### `onOutput` {/* #onoutput */}

伺服器端執行的 Tool 傳回輸出後，或伺服器透過後續請求收到客戶端執行 Tool 的成功結果後觸發。可用來記錄結果或觸發後續操作。

```typescript
export const tool = createTool({
  id: 'example-tool',
  description: 'Example tool with hooks',
  outputSchema: z.object({
    result: z.string(),
  }),
  execute: async input => {
    return { result: 'Success' }
  },
  onOutput: ({ output, toolCallId, toolName, abortSignal }) => {
    console.log(`${toolName} execution completed:`, output)
    // output is fully typed based on outputSchema
  },
})
```

由客戶端執行的 Tool 無需定義 `execute` 函式。瀏覽器執行 Tool 並在後續請求中交回結果，之後由伺服器執行 `onOutput`。成功結果必須能對應至原本的 Tool 呼叫，才會觸發此鉤子。AI SDK 中 `error-text`、`error-json` 等類型的錯誤結果不會觸發 `onOutput`。

客戶端交回執行結果時，後續請求必須同時包含助理發出的 Tool 呼叫及對應的 Tool 結果。`@mastra/client-js` 會自動傳送兩者。只包含 Tool 結果的請求不會觸發此鉤子。對於客戶端執行的結果，回呼只會收到 `{ toolCallId, toolName, output, abortSignal }`。

請求採用至少一次傳遞方式，重試時會再次執行鉤子。請確保鉤子具備冪等性，並將客戶端輸出視為不可信的資料。伺服器不會按 `outputSchema` 驗證結果，因此 `output` 只受靜態型別約束。

### 鉤子執行順序 {/* #hook-execution-order */}

由伺服器端執行 Tool 時，一般串流呼叫會按以下次序觸發鉤子：

1. **onInputStart**：輸入開始串流傳輸
2. **onInputDelta**：每收到一段輸入便觸發一次
3. **onInputAvailable**：完整輸入已解析並驗證
4. Tool 的 **execute** 函式執行
5. **onOutput**：Tool 成功執行完畢

由客戶端執行 Tool 時，步驟 1–3 會在模型串流傳送 Tool 呼叫期間完成，之後由客戶端執行 Tool，伺服器端不會執行 `execute`。伺服器收到包含成功結果的後續請求時，便會執行 `onOutput`。

### 鉤子參數 {/* #hook-parameters */}

源碼中定義的鉤子回呼參數如下：

* `onInputStart`：接收 `ToolCallOptions`，其中包括 `toolCallId`、`messages` 及 `abortSignal` 等欄位。
* `onInputDelta`：接收 `{ inputTextDelta: string } & ToolCallOptions`。
* `onInputAvailable`：接收 `{ input: TSchemaIn } & ToolCallOptions`，其中 `input` 的型別由 `inputSchema` 推導。
* `onOutput`：接收 `{ output: TSchemaOut; toolName: string } & Omit<ToolCallOptions, 'messages'>`，其中 `output` 的型別由 `outputSchema` 推導。此鉤子不會收到 `messages`。

### 錯誤處理 {/* #error-handling */}

系統會自動捕捉鉤子拋出的錯誤，並將錯誤記錄到控制台。Tool 會繼續執行，呼叫亦不會因此失敗。

## MCP Tool 註記 {/* #mcp-tool-annotations */}

透過模型上下文協定（MCP）公開 Tool 時，可以提供註記來描述 Tool 的行為，讓 OpenAI Apps SDK 等 MCP 客戶端判斷如何顯示及處理 Tool。

MCP 專用屬性集中在 `mcp` 屬性內，包括 `annotations` 及 `_meta`：

```typescript oxfmt:false
mcp: {
  annotations: { /* behavior hints */ },
  _meta: { /* custom metadata */ },
}
```
