# 創建Tool()

這`createTool()`函數用於定義您的 Mastra Agent可以執行的自訂Tool。Tool透過允許Agent與外部系統互動或執行計算來擴展Agent的功能。他們還可以存取特定數據。

## 使用範例 {/* #usage-example */}

```typescript title="src/mastra/tools/weather-tool.ts"
import { createTool } from '@mastra/core/tools'
import { z } from 'zod'

export const weatherTool = createTool({
  id: 'weather-tool',
  description: 'Get the current weather for a location',
  inputSchema: z.object({
    location: z.string(),
  }),
  outputSchema: z.object({
    location: z.string(),
    temperatureCelsius: z.number(),
    conditions: z.string(),
  }),
  execute: async ({ location }) => {
    return {
      location,
      temperatureCelsius: 21,
      conditions: 'sunny',
    }
  },
})
```

第一個`execute` parameter is the validated value from `inputSchema`. Destructure schema fields directly in the function signature, as shown with `{ location }`。可選的第二個參數包含執行上下文。

### 僅顯示Tool {/* #display-only-tools */}

對於只要求客戶端顯示某些內容的Tool，請設定`renderOnly: true` instead of defining `execute`:

```typescript
const showCard = createTool({
  id: 'show-card',
  description: 'Display a product card',
  inputSchema: z.object({ productId: z.string() }),
  renderOnly: true,
})
```

Mastra 串流Tool呼叫並返回`{ acknowledged: true }` as its result, allowing the agent to continue generating text without a client round trip. This also works for tools owned by sub-agents. Their calls appear as nested `tool-output` stream events. Don't set an incompatible `outputSchema` on a render-only tool. The acknowledgement means the call was emitted, **not** that the browser rendered it. Don't use this for client actions whose outcome matters to the agent. For those, omit `execute`並從客戶端傳回結果，或當子Agent需要使用者輸入時使用掛起伺服器Tool。

## 具有嚴格Tool輸入的範例 {/* #example-with-strict-tool-inputs */}

放`strict: true` when you want Mastra to ask supported model providers to generate tool arguments that exactly match the tool schema.

```typescript title="src/mastra/tools/weather-tool.ts"
import { createTool } from '@mastra/core/tools'
import { z } from 'zod'

export const weatherTool = createTool({
  id: 'weather-tool',
  description: 'Get the current weather for a location',
  strict: true,
  inputSchema: z.object({
    location: z.string(),
  }),
  outputSchema: z.object({
    location: z.string(),
    temperatureCelsius: z.number(),
    conditions: z.string(),
  }),
  execute: async ({ location }) => {
    return {
      location,
      temperatureCelsius: 21,
      conditions: 'sunny',
    }
  },
})
```

馬斯特拉前鋒`strict: true` to model adapters that support strict tool calling and ignores the option for other adapters.

## 範例為`toModelOutput` {/* #example-with-tomodeloutput */}

使用`toModelOutput` when your tool should return rich internal data to your app, but the model should receive either a simplified value or multimodal content.

```typescript title="src/mastra/tools/weather-tool.ts"
import { createTool } from '@mastra/core/tools'
import { z } from 'zod'

export const weatherTool = createTool({
  id: 'weather-tool',
  description: 'Get the current weather for a location',
  inputSchema: z.object({
    location: z.string(),
  }),
  outputSchema: z.object({
    location: z.string(),
    temperatureCelsius: z.number(),
    conditions: z.string(),
    radarImageUrl: z.string().url(),
  }),
  execute: async ({ location }) => ({
    location,
    temperatureCelsius: 21,
    conditions: 'sunny',
    radarImageUrl: 'https://example.com/radar/seattle.png',
  }),
  toModelOutput: output => {
    return {
      type: 'content',
      value: [
        {
          type: 'text',
          text: `${output.location}: ${output.temperatureCelsius}°C and ${output.conditions}`,
        },
        { type: 'image-url', url: output.radarImageUrl },
      ],
    }
  },
})
```

該Tool仍然返回完整的`execute` result to your application, while the model receives the transformed `toModelOutput` value.

`toModelOutput`可以返回：

* `type: 'text'`
* `type: 'json'`
* `type: 'content'`與像這樣的零件`text`, `image-url`, `image-data`, `file-url`, `file-data`, `file-id`, `image-file-id`, or `custom`

`toModelOutput`也適用於沒有`execute` function that run on the client. When the client sends the tool result back on the next request, the server applies the tool definition's `toModelOutput` to it before the model sees it.

## 範例為`transform` {/* #example-with-transform */}

使用`transform` when the tool should keep raw inputs or outputs for runtime behavior, but display streams or transcript messages should receive a smaller or safer shape.

```typescript title="src/mastra/tools/customer-tool.ts"
import { createTool } from '@mastra/core/tools'
import { z } from 'zod'

export const customerTool = createTool({
  id: 'lookup-customer',
  description: 'Looks up a customer',
  inputSchema: z.object({
    customerId: z.string(),
    internalPath: z.string(),
  }),
  outputSchema: z.object({
    displayName: z.string(),
    apiKey: z.string(),
    debugScore: z.number(),
  }),
  execute: async () => {
    return {
      displayName: 'Acme',
      apiKey: 'secret-value',
      debugScore: 0.97,
    }
  },
  transform: {
    display: {
      input: ({ input }) => ({ customerId: input?.customerId }),
      output: ({ output }) => ({ displayName: output?.displayName }),
      error: () => ({ message: 'Customer lookup failed' }),
    },
    transcript: {
      input: ({ input }) => ({ customerId: input?.customerId }),
      output: ({ output }) => ({ displayName: output?.displayName }),
      error: () => ({ message: 'Customer lookup failed' }),
    },
  },
})
```

該Tool仍然接收原始數據`inputSchema` value and returns the raw `execute` result. Mastra applies `display` transforms to streamed UI payloads and `transcript` transforms to user-visible transcript messages.

## 帶有 MCP 註釋的範例 {/* #example-with-mcp-annotations */}

透過 MCP（模型上下文協定）公開Tool時，您可以新增註解來描述Tool行為並自訂客戶端顯示Tool的方式。這些 MCP 特定屬性分組在`mcp` property:

```typescript title="src/mastra/tools/weather-tool.ts"
import { createTool } from '@mastra/core/tools'
import { z } from 'zod'

export const weatherTool = createTool({
  id: 'weather-tool',
  description: 'Get the current weather for a location',
  inputSchema: z.object({
    location: z.string().describe('City name or coordinates'),
  }),
  outputSchema: z.object({
    location: z.string(),
    temperatureCelsius: z.number(),
    conditions: z.string(),
  }),
  // MCP-specific properties
  mcp: {
    // Annotations for client behavior hints
    annotations: {
      title: 'Weather Lookup', // Human-readable display name
      readOnlyHint: true, // Tool doesn't modify environment
      destructiveHint: false, // Tool doesn't perform destructive updates
      idempotentHint: true, // Same args = same result
      openWorldHint: true, // Interacts with external API
    },
    // Custom metadata for client-specific functionality
    _meta: {
      version: '1.0.0',
      category: 'weather',
    },
  },
  execute: async ({ location }) => {
    return {
      location,
      temperatureCelsius: 21,
      conditions: 'sunny',
    }
  },
})
```

## 工俱生命週期掛鉤 {/* #tool-lifecycle-hooks */}

Tool支援生命週期掛鉤，使您可以監控Tool執行的不同階段並做出反應。這些掛鉤對於串流過程中的日誌記錄、分析、驗證和即時更新特別有用。

以下範例示範了配置了所有生命週期掛鉤的Tool：

```typescript title="src/mastra/tools/weather-tool.ts"
import { createTool } from '@mastra/core/tools'
import { z } from 'zod'

export const weatherTool = createTool({
  id: 'weather-tool',
  description: 'Get the current weather for a location',
  inputSchema: z.object({
    location: z.string(),
  }),
  outputSchema: z.object({
    location: z.string(),
    temperatureCelsius: z.number(),
    conditions: z.string(),
  }),
  execute: async ({ location }) => {
    return {
      location,
      temperatureCelsius: 21,
      conditions: 'sunny',
    }
  },
  onInputStart: ({ toolCallId }) => {
    console.log(`Tool call ${toolCallId} input started`)
  },
  onInputDelta: ({ inputTextDelta, toolCallId }) => {
    console.log(`Tool call ${toolCallId} received input chunk: ${inputTextDelta}`)
  },
  onInputAvailable: ({ input, toolCallId }) => {
    console.log(`Tool call ${toolCallId} received location: ${input.location}`)
  },
  onOutput: ({ output, toolCallId, toolName }) => {
    console.log(`Tool ${toolName} call ${toolCallId} returned conditions: ${output.conditions}`)
  },
})
```

### 可用掛鉤 {/* #available-hooks */}

#### `onInputStart` {/* #oninputstart */}

在接收任何輸入資料之前，Tool會呼叫輸入流開始時呼叫。

```typescript
export const tool = createTool({
  id: 'example-tool',
  description: 'Example tool with hooks',
  onInputStart: ({ toolCallId, messages, abortSignal }) => {
    console.log(`Tool ${toolCallId} input streaming started`)
  },
})
```

#### `onInputDelta` {/* #oninputdelta */}

在輸入文字流入時呼叫每個增量區塊。對於顯示即時進度或解析部分 JSON 很有用。

```typescript
export const tool = createTool({
  id: 'example-tool',
  description: 'Example tool with hooks',
  onInputDelta: ({ inputTextDelta, toolCallId, messages, abortSignal }) => {
    console.log(`Received input chunk: ${inputTextDelta}`)
  },
})
```

#### `onInputAvailable` {/* #oninputavailable */}

當完整的Tool輸入可用並且已根據Tool進行解析和驗證時調用`inputSchema`.

```typescript
export const tool = createTool({
  id: 'example-tool',
  description: 'Example tool with hooks',
  inputSchema: z.object({
    location: z.string(),
  }),
  onInputAvailable: ({ input, toolCallId, messages, abortSignal }) => {
    console.log(`Tool received complete input:`, input)
    // input is fully typed based on inputSchema
  },
})
```

#### `onOutput` {/* #onoutput */}

在伺服器執行的Tool傳回輸出後或在後續請求中用戶端執行的Tool結果成功到達後呼叫。用它來記錄結果或觸發後續操作。

```typescript
export const tool = createTool({
  id: 'example-tool',
  description: 'Example tool with hooks',
  outputSchema: z.object({
    result: z.string(),
  }),
  execute: async input => {
    return { result: 'Success' }
  },
  onOutput: ({ output, toolCallId, toolName, abortSignal }) => {
    console.log(`${toolName} execution completed:`, output)
    // output is fully typed based on outputSchema
  },
})
```

客戶端執行的Tool沒有定義`execute` function. The browser runs the tool and sends the result on a follow-up request. `onOutput` then runs on the server. Only a correlated successful result invokes the hook: error results, such as the AI SDK `error-text` and `error-json` output types, don't invoke `onOutput`.

對於客戶端執行的結果，後續請求必須包含輔助Tool呼叫和Tool結果，其中`@mastra/client-js` sends automatically. A request that carries only the tool result doesn't fire the hook. In this case the callback receives `{ toolCallId, toolName, output, abortSignal }` only.

至少一次傳遞意味著重試請求再次運行掛鉤。保持鉤子冪等並將客戶端輸出視為不可信資料：伺服器不會驗證結果`outputSchema`, so the `output` type is a static type only.

### 鉤子執行順序 {/* #hook-execution-order */}

對於伺服器執行Tool上的典型流Tool調用，掛鉤會按以下順序調用：

1. **輸入開始時**：輸入流開始
2. **onInputDelta**：當塊到達時多次調用
3. **輸入可用時**：完整的輸入被解析和驗證
4. Tool**execute** function runs
5. **輸出**：Tool已成功完成

對於客戶端執行的Tool，步驟 1-3 在模型串流Tool呼叫時運行，客戶端運行該Tool而不是伺服器端`execute`, and `onOutput` runs on the follow-up request that carries a successful result.

### 掛鉤參數 {/* #hook-parameters */}

鉤子回調接收這些來源支援的參數形狀：

* `onInputStart`: 收到`ToolCallOptions`, including fields such as `toolCallId`, `messages`, and `abortSignal`.
* `onInputDelta`: 收到`{ inputTextDelta: string } & ToolCallOptions`.
* `onInputAvailable`: 收到`{ input: TSchemaIn } & ToolCallOptions`, where `input` is typed from `inputSchema`.
* `onOutput`: 收到`{ output: TSchemaOut; toolName: string } & Omit<ToolCallOptions, 'messages'>`, where `output` is typed from `outputSchema`. This hook doesn't receive `messages`.

### 錯誤處理 {/* #error-handling */}

掛鉤錯誤會自動擷取並記錄，但不會阻止Tool繼續執行。如果鉤子拋出錯誤，它將被記錄到控制台，但不會使Tool呼叫失敗。

## MCPTool註釋 {/* #mcp-tool-annotations */}

透過模型上下文協定 (MCP) 公開Tool時，您可以提供描述Tool行為的註解。這些註解可協助 OpenAI Apps SDK 等 MCP 用戶端了解如何呈現和處理您的Tool。

MCP 特定屬性分組在`mcp` property, which includes `annotations` and `_meta`:

```typescript oxfmt:false
mcp: {
  annotations: { /* behavior hints */ },
  _meta: { /* custom metadata */ },
}
```
