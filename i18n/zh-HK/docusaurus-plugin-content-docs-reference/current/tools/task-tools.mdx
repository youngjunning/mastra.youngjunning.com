# 任務 Tool

四個內置 Tool 不依賴特定 Agent，用來管理 Agent 執行期間的結構化任務清單。任務清單會持久儲存在對話線程層級的 `threadState` 儲存區，並映射至 Agent 的[狀態訊號](/docs/signals/state-signals)通道，因此不會因[觀察式記憶](/docs/memory/observational-memory)截斷而遺失。

任務追蹤需要具備記憶功能的對話線程（`threadId` + `resourceId`）。如果沒有記憶功能，這些 Tool 會傳回錯誤，說明任務追蹤需要 Agent 的記憶功能。

建議使用 [`TaskSignalProvider`](/reference/signals/task-signal-provider)：註冊一次即可設定全部四個 Tool 和 `TaskStateProcessor`。概念說明請參閱[內置 Tool](/docs/agents/tools#task-tracking)。

## 使用範例 {/* #usage-example */}

```typescript title="src/mastra/agents/index.ts"
import { Agent } from '@mastra/core/agent'
import { Memory } from '@mastra/memory'
import { TaskSignalProvider } from '@mastra/core/signals'

const agent = new Agent({
  id: 'coder',
  name: 'Coder',
  instructions: 'Track your progress with the task tools.',
  model,
  memory: new Memory(),
  signals: [new TaskSignalProvider()],
})
```

亦可直接匯入這些 Tool。`taskWriteTool`、`taskUpdateTool`、`taskCompleteTool` 和 `taskCheckTool` 是匯出名稱；`task_write`、`task_update`、`task_complete` 和 `task_check` 則是模型在 Tool 呼叫及追蹤紀錄中看到的 Tool ID：

```typescript title="src/mastra/agents/index.ts"
import { taskWriteTool, taskUpdateTool, taskCompleteTool, taskCheckTool } from '@mastra/core/tools'
import { Agent } from '@mastra/core/agent'
import { Memory } from '@mastra/memory'

const agent = new Agent({
  id: 'coder',
  name: 'Coder',
  instructions: 'Track your progress with the task tools.',
  model,
  memory: new Memory(),
  tools: { taskWriteTool, taskUpdateTool, taskCompleteTool, taskCheckTool },
})
```

## `task_write` {/* #task_write */}

建立或取代整份任務清單。每次呼叫都會取代上一份清單。

### 輸入結構 {/* #input-schema */}

<PropertiesTable
  content={[
{
  name: 'tasks',
  type: 'TaskItemInput[]',
  description: '更新後的完整任務清單。',
  isOptional: false,
  properties: [
    {
      type: 'TaskItemInput',
      parameters: [
        {
          name: 'id',
          type: 'string',
          description:
            "穩定的任務識別碼（例如 'task_investigate_tests'）。更新任務時請保持不變；省略時會自動產生。",
          isOptional: true,
        },
        {
          name: 'content',
          type: 'string',
          description: "以祈使句撰寫的任務描述（例如 '修正身份驗證錯誤'）。",
        },
        {
          name: 'status',
          type: "'pending' | 'in_progress' | 'completed'",
          description: '任務目前的狀態。',
        },
        {
          name: 'activeForm',
          type: 'string',
          description: "執行期間顯示的進行式描述（例如 '正在修正身份驗證錯誤'）。",
        },
      ],
    },
  ],
},
]}
/>

### 輸出 {/* #output */}

傳回 `TaskToolResult`，當中包括易於閱讀的 `content` 摘要、附有已分配 ID 的完整 `tasks` 陣列，以及 `isError` 標記。

### 行為 {/* #behavior */}

* 同一次呼叫中的 ID 必須唯一。如果明確指定重複的 ID，系統會產生替代 ID。
* 重寫現有清單時，如果省略 ID，而只有一項任務明確吻合，系統會沿用該任務原有的 ID，以保持識別碼穩定。
* 同一時間只能有一項任務處於 `in_progress` 狀態。提交多項處於 `in_progress` 狀態的任務會傳回錯誤。

## `task_update` {/* #task_update */}

透過穩定 ID 更新單一任務。只需提供有變更的欄位。

### 輸入結構 {/* #input-schema-1 */}

<PropertiesTable
  content={[
{
  name: 'id',
  type: 'string',
  description: '要更新的任務的穩定識別碼。',
  isOptional: false,
},
{
  name: 'content',
  type: 'string',
  description: '新的祈使句形式任務描述。',
  isOptional: true,
},
{
  name: 'status',
  type: "'pending' | 'in_progress' | 'completed'",
  description: '任務的新狀態。',
  isOptional: true,
},
{
  name: 'activeForm',
  type: 'string',
  description: '新的進行式描述。',
  isOptional: true,
},
]}
/>

`content`、`status` 和 `activeForm` 至少須提供其中一項。

### 行為 {/* #behavior-1 */}

* 如果更新將某項任務設為 `in_progress`，其他處於 `in_progress` 狀態的任務會自動改為 `pending`。
* 如果找不到指定 ID，會傳回錯誤並列出可用的任務 ID。

## `task_complete` {/* #task_complete */}

透過穩定 ID 將單一任務標記為已完成。

### 輸入結構 {/* #input-schema-2 */}

<PropertiesTable
  content={[
{
  name: 'id',
  type: 'string',
  description: '要標記為已完成的任務的穩定識別碼。',
  isOptional: false,
},
]}
/>

### 行為 {/* #behavior-2 */}

如果找不到指定 ID，會傳回錯誤並列出可用的任務 ID。

## `task_check` {/* #task_check */}
