# 隔離Vm程式碼模式傳輸

`IsolatedVmCodeModeTransport` 類別在程序內的 V8 isolate 執行 [Code mode](/docs/agents/code-mode) 程式，底層使用 [isolated-vm](https://github.com/laverdet/isolated-vm)。isolate 本身就是執行邊界，因此毋須工作空間 Sandbox：程式無法存取檔案系統、網絡、程序或模組。它唯一可用的能力是 `external_*` 函數，這些函數會回調宿主端的實際工具。

相比預設的 `StdioCodeModeTransport`，此傳輸方式不會啟動程序或寫入暫存檔，適合無法使用作業系統層級隔離的 Serverless 及多租戶主機。

## 安裝 {/* #installation */}

```bash npm2yarn
npm install @mastra/isolated-vm
```

`isolated-vm` 是原生擴充套件。常見平台有預先編譯的二進位檔，通常毋須額外設定。只有在平台沒有相應的預先編譯版本、需要從原始碼編譯時，才需要 C++ 工具鏈。

在 Node.js 20 或更新版本，若宿主程序啟動時沒有 `--no-node-snapshot`，建立 isolate 會令程序崩潰。建構函數會將缺少此旗標回報為錯誤。請在啟動伺服器時傳入，或透過 `NODE_OPTIONS` 設定：

```bash
NODE_OPTIONS=--no-node-snapshot npm run dev
```

## 用法 {/* #usage */}

將此傳輸方式作為第二個參數傳給 `createCodeMode()`。毋須 `sandbox`：

```typescript
import { createCodeMode } from '@mastra/core/tools'
import { IsolatedVmCodeModeTransport } from '@mastra/isolated-vm'

const { tool, instructions } = createCodeMode(
  { tools: { getTopProducts, getProductRatings } },
  new IsolatedVmCodeModeTransport({ memoryLimitMb: 128 }),
)
```

## 運作原理 {/* #how-it-works */}

每次執行都會建立擁有獨立堆記憶體的新 isolate。宿主先用 esbuild 移除 TypeScript 型別，再於 isolate 內執行程式。每次 `external_*` 呼叫都會以 JSON 字串雙向跨越隔離邊界，因此宿主物件的引用不會洩漏至模型編寫的程式碼。允許清單、工具驗證、請求內容及 Trace 都在宿主端執行，與其他傳輸方式相同。

設定項目 `timeout`（由 `createCodeMode()` 設定）同時適用於非同步停滯及同步無限循環；每次執行後都會釋放 isolate。
