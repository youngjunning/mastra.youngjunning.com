# MCPClient

`MCPClient` 類別可在 Mastra 應用程式中管理多個 MCP 伺服器連線及其 Tool。它負責連線的生命週期與 Tool 命名空間，並讓應用程式存取所有已設定伺服器的 Tool。

:::note
正從 `@mastra/mcp` 1.x 升級？請參閱[遷移指南](/reference/migrations/mcp-v2)。
:::

## 建構函數 {/* #constructor */}

建立 MCPClient 類別的新實例。

```typescript oxfmt:false
constructor({
  id?: string;
  servers: Record<string, MastraMCPServerDefinition>;
  timeout?: number;
  typegen?: { outFile: string };
  clientInfo?: { name?: string; version?: string };
  registerProcessHooks?: boolean;
}: MCPClientOptions)
```

### 具類型的客戶端契約 {/* #typed-client-contracts */}

將明確的伺服器對照表類型傳入 `MCPClient<TServers>`，即可檢查已設定的伺服器名稱、探索到的 Tool 名稱及直接呼叫的參數。`MCPClientOptions<TServers>` 接受相同的對照表類型。宣告的伺服器全部必須提供；如只需設定其中一部分，可使用 `Pick<TServers, 'weather'>`。未傳入類型參數時，探索結果仍使用原有的寬泛類型。

此對照表透過 `tools` 描述各伺服器的 Tool，並為每個 Tool 指定 `input` 和 `output` 類型。以下例子假設 `WEATHER_MCP_URL` 指向一台正在運作的天氣伺服器：

```typescript
import { MCPClient } from '@mastra/mcp'

interface MCPServers {
  weather: {
    tools: {
      get_weather: {
        input: { location: string }
        output: { temperature: number; conditions: string }
      }
    }
  }
}

const mcp = new MCPClient<MCPServers>({
  servers: { weather: { url: new URL(process.env.WEATHER_MCP_URL!) } },
})

try {
  const tools = await mcp.listTools()
  const weather = tools.weather_get_weather
  if (weather?.execute) {
    const result = await weather.execute({ location: 'Paris' })
    if (result && 'temperature' in result && typeof result.temperature === 'number') {
      console.log(result.temperature)
    }
  }
} finally {
  await mcp.disconnect()
}
```

`listTools()` 和 `listToolsWithErrors().tools` 提供精確的 `server_tool` 鍵。`listToolsets()` 和 `listToolsetsWithErrors().toolsets` 則以伺服器鍵組織未加前綴的 Tool 名稱。兩種結果都可能不完整：伺服器或 Tool 可能不存在。呼叫 Tool 前請確認其可用。錯誤對照表、錯誤詳情及可選的探索耗時仍維持原有類型。

執行結果可能是結構化輸出、協定結果封裝物件、驗證錯誤或 `undefined`。讀取成功結果的欄位前，請檢查結果結構和屬性類型。協定封裝物件可能包含其他屬性。對於沒有輸出 schema 的 Tool，請設定 `output: unknown`。

這些契約描述的是 schema 快照，實際運作的伺服器可能與快照不同。伺服器的 schema 有變動時，請使用具備同等權限的憑證更新契約。伺服器新增的 Tool 在執行期間仍可使用，但不會出現在快照的已知鍵中。執行期間的探索、驗證與執行行為不變。

### 產生客戶端類型 {/* #generate-client-types */}

使用 `@mastra/mcp` 提供的指令，根據線上 Tool 的輸入與輸出 schema 產生具體的 TypeScript 介面。匯出現有客戶端，並設定 `typegen.outFile`：

```typescript title="src/mcp/client.ts"
import { MCPClient } from '@mastra/mcp'
import type { MCPServers } from './mcp-types.generated'

export const mcp = new MCPClient<MCPServers>({
  id: 'weather-client',
  servers: { weather: { url: new URL(process.env.WEATHER_MCP_URL!) } },
  typegen: { outFile: 'src/mcp/mcp-types.generated.ts' },
})
```

設定模組所需的環境變數和驗證憑證，然後從專案根目錄執行以下命令：

```bash npm2yarn
npx @mastra/mcp generate ./src/mcp/client.ts
```

首次執行時，純類型匯入所需的生成檔案可能尚未存在。載入器會處理 TypeScript 及間接匯入的模組，不會執行類型檢查。生成後請執行類型檢查。

請使用生成的名稱，並在執行時確認 Tool 是否可用及結果的結構。以下例子假設伺服器提供 `get_weather`，接受必填的字串參數 `location`，並輸出數值 `temperature`：

```typescript title="src/mcp/call-weather.ts"
import { mcp } from './client'

try {
  const tools = await mcp.listTools()
  const weather = tools.weather_get_weather
  if (weather?.execute) {
    const result = await weather.execute({ location: 'Paris' })
    if (result && 'temperature' in result && typeof result.temperature === 'number') {
      console.log(result.temperature)
    }
  }
} finally {
  await mcp.disconnect()
}
```

這個指令接受一個或多個檔案路徑。輸入檔案和 `outFile` 的路徑均以指令的工作目錄為準。指令只會選取已啟用類型生成功能，並透過具名或預設匯出直接匯出的客戶端。指令不會掃描原始碼目錄樹、呼叫工廠函數，亦不會檢查匯出物件內的巢狀成員。重複指定同一檔案、透過符號連結指向同一檔案，或多次匯出同一客戶端時，只會處理一次。如有檔案沒有符合條件的客戶端，指令便會報錯。

如果多個獨立客戶端採用相同的伺服器設定，請各自使用不同的 ID 和輸出路徑：

```typescript title="src/mcp/clients.ts"
import { MCPClient } from '@mastra/mcp'

const servers = { weather: { url: new URL(process.env.WEATHER_MCP_URL!) } }
export const first = new MCPClient({
  id: 'first',
  servers,
  typegen: { outFile: 'first.generated.ts' },
})
export const second = new MCPClient({
  id: 'second',
  servers,
  typegen: { outFile: 'second.generated.ts' },
})
```

```bash npm2yarn
npx @mastra/mcp generate ./src/mcp/clients.ts
```

現有的實例快取仍然適用。建立客戶端時，如明確指定的 ID、伺服器設定和 `typegen.outFile` 都相同，便會傳回現有物件。如伺服器設定或 `outFile` 不同，便會取代快取中的實例，避免其後建立客戶端時沿用當次並未指定的輸出檔案。

生成過程只會列出 Tool 定義，並不呼叫 Tool。如探索出錯、欠缺身份驗證、逾時、輸出路徑衝突、輸出將覆蓋指定的輸入檔案，或結構描述完全無法表示（例如有循環參照、巢狀層級過深或無法解析本機參照），生成便會失敗。每項錯誤都會指出涉及的客戶端檔案、伺服器或 Tool。指令會先準備好所有要生成的原始碼，再替換檔案。不論成功或失敗，指令都會中斷所選客戶端的連線。探索或預先檢查失敗時，現有輸出會保留。每個檔案的替換都是原子操作，但多個檔案並非在同一交易中替換。替換期間如遇上檔案系統故障，較早替換的檔案可能已經更新。

沒有輸出結構描述的 Tool 會使用 `unknown`。字串格式、長度限制及數值範圍等限制會保留對應的基本 TypeScript 類型，並繼續在執行時驗證。不受支援的部分，包括條件式結構描述和 `prefixItems` 元組，會放寬為 `unknown` 並發出警告。如果關鍵字的值不符合容許的結構，相關結構描述亦會放寬為 `unknown` 並發出警告，其他伺服器仍可繼續生成類型。警告會列明涉及的伺服器、Tool 和結構描述內的位置。生成器不會擷取外部結構描述參照。遇到無法解析的本機參照或循環參照時，生成便會失敗。協定的巢狀深度上限為 128 層，超出時亦會失敗。結構描述如超出協定的 10,000 個節點上限，會放寬為 `unknown` 並發出警告。生成器對原始 JSON 值採用較寬鬆的上限，超出該上限的結構描述或目錄亦會按同樣方式處理。生成器會在複製或轉換結構描述之前檢查這些上限，避免伺服器公布的大型結構描述令指令停滯。

:::note 模組執行與憑證

此指令會執行指定的模組及這些模組匯入的模組。請使用可信而且不會在匯入時觸發應用程式啟動副作用的模組，並在執行指令前提供憑證。指令不會載入 dotenv 檔案或啟動互動式身份驗證。客戶端現有的逾時和探索設定仍然適用。

生成器的診斷訊息不會包含原始結構描述、傳輸錯誤或憑證。匯入的應用程式、自訂日誌處理函數或伺服器子進程輸出的日誌不在此保證範圍內。

:::

### `MastraMCPServerDefinition` {/* #mastramcpserverdefinition */}

`servers` 對照表中的每部伺服器均以 `MastraMCPServerDefinition` 類型設定。客戶端會根據所提供的參數選擇傳輸方式：

* 如有提供 `command`，會使用 Stdio 傳輸。
* 如有提供 `url`，會使用 Streamable HTTP 傳輸。

客戶端支援 MCP `2026-07-28` 版。建立連線時，客戶端會查詢伺服器支援的版本（`server/discover`）。如伺服器尚未升級，客戶端會改用 2026 年之前的 `initialize` 握手程序，讓 Tool、資源和提示詞在新舊版本均可使用。使用舊版欠缺的功能（`resources.subscribe()`、`inputRequests`）會引發錯誤，並列明協商採用的版本。`onListChanged()` 處理函數在新舊版本均可使用，因為舊版伺服器即使沒有 `subscriptions/listen` 串流，亦會發送清單變更通知。設定 `protocolVersion` 可略過版本探測。

## Tool 審批 {/* #tool-approval */}

在伺服器定義中設定 `requireToolApproval`，即可要求該伺服器的 Tool 在執行前先獲人工批准。這項設定沿用現有的[人工參與審批](/docs/workflows/human-in-the-loop)流程。

### 要求審批所有 Tool {/* #require-approval-for-all-tools */}

將 `requireToolApproval` 設為 `true`，該伺服器上的所有 Tool 均須獲批才可執行：

```typescript
const mcp = new MCPClient({
  servers: {
    github: {
      url: new URL('http://localhost:3000/mcp'),
      requireToolApproval: true,
    },
  },
})
```

### 以函數動態判斷是否需要審批 {/* #dynamic-approval-with-a-function */}

傳入函數，逐次判斷調用是否需要批准。函數會收到 Tool 名稱、模型傳入的參數、傳入請求所附的上下文，以及伺服器所公布的 MCP Tool `annotations`（如有）：

```typescript
const mcp = new MCPClient({
  servers: {
    github: {
      url: new URL('http://localhost:3000/mcp'),
      requireToolApproval: ({ toolName, args, requestContext }) => {
        // Read-only tools don't need approval
        if (toolName === 'list_repos') return false
        // Destructive tools with force flag always need approval
        if (toolName === 'delete_repo') return args.force === true
        // Non-admin users need approval for everything else
        return requestContext?.userRole !== 'admin'
      },
    },
  },
})
```

亦可傳入異步函數。函數會收到傳入請求的 `requestContext`，可用於驗證、權限檢查或其他按請求執行的邏輯。

### 使用可信伺服器的 Tool 註解 {/* #use-tool-annotations-from-a-trusted-server */}

如果信任該 MCP 伺服器，可根據它提供的 [Tool 註解](https://modelcontextprotocol.io/specification/2025-11-25/server/tools#tool-annotations)（`readOnlyHint`、`destructiveHint`、`idempotentHint`、`openWorldHint`、`title`）決定是否需要審批：

```typescript
const mcp = new MCPClient({
  servers: {
    github: {
      url: new URL('http://localhost:3000/mcp'),
      requireToolApproval: ({ annotations }) => {
        // Skip approval for tools the server has marked read-only
        if (annotations?.readOnlyHint) return false
        // Always require approval for destructive tools
        if (annotations?.destructiveHint) return true
        return true
      },
    },
  },
})
```

根據 MCP 規格，**客戶端必須將 Tool 註解視為不可信，除非它們來自可信伺服器**。註解只供參考，並無安全隔離作用。惡意或有缺陷的伺服器可能將可寫入資料的 Tool 標示為唯讀。只可對可信伺服器按註解放寬審批要求。

`listTools()` 和 `listToolsets()` 回傳的 Tool 亦會在 `tool.mcp.annotations` 提供這些註解，供你為 Agent 設定 Tool 時查閱。

每個 Tool 亦有 `tool.title`，優先採用伺服器提供的 Tool `title`，其次採用 `annotations.title`。如果兩者均未提供，`tool.title` 為 `undefined`，顯示時便會使用 Tool 名稱，符合 MCP 的顯示名稱優先次序。

## 伺服器指令 {/* #server-instructions */}

如果 MCP 伺服器在初始化時公布指令，`MCPClient` 會為該伺服器儲存指令。轉送指令至 Agent 的系統提示須**明確啟用**。為伺服器設定 `forwardInstructions: true` 後，透過 `listTools()` 或 `listToolsets()` 使用該伺服器 Tool 的 Agent 會自動收到指令。

指令按伺服器名稱分組，每部伺服器最多保留 `instructionsMaxLength` 個字元。

```typescript
const mcp = new MCPClient({
  servers: {
    db: {
      url: new URL('http://localhost:3000/mcp'),
      forwardInstructions: true,
      instructionsMaxLength: 512,
    },
  },
})

const agent = new Agent({
  id: 'db-agent',
  name: 'DB Agent',
  instructions: 'Help with database changes.',
  model,
  tools: await mcp.listTools(),
})
```

按預設省略 `forwardInstructions` 時，指令仍會保存在快取中，可用 [`getServerInstructions()`](#getserverinstructions) 查閱，但不會加入任何 Agent 的系統提示。

> **安全說明：** 伺服器指令會原樣轉送至 Agent 的系統提示，只會按長度限制截斷。惡意或遭入侵的 MCP 伺服器可藉此注入指令，而 Agent 會視之為可信的系統指令。只應為可信伺服器啟用 `forwardInstructions`。建議先用 `getServerInstructions()` 檢查第三方伺服器的指令，再將它們轉送。

## 安全 {/* #security */}

### Stdio 伺服器的子進程環境 {/* #subprocess-environment-for-stdio-servers */}

Stdio 子進程不會繼承父進程的全部環境變數。預設只會繼承 MCP SDK 許可清單上的變數（POSIX：`HOME`、`LOGNAME`、`PATH`、`SHELL`、`TERM`、`USER`；Windows：`APPDATA`、`HOMEDRIVE`、`HOMEPATH`、`LOCALAPPDATA`、`PATH`、`PROCESSOR_ARCHITECTURE`、`SYSTEMDRIVE`、`SYSTEMROOT`、`TEMP`、`USERNAME`、`USERPROFILE`），並與 `env` 內設定的變數合併。API 密鑰等敏感變數只有明確傳入，才會出現在子進程的環境中。

如需更嚴格的隔離，可設定 `inheritDefaultEnv: false`，讓子進程只收到 `env` 中設定的項目：

```typescript
const mcp = new MCPClient({
  servers: {
    myTool: {
      command: '/usr/local/bin/my-mcp-server',
      inheritDefaultEnv: false,
      env: { MY_TOOL_API_KEY: process.env.MY_TOOL_API_KEY! },
    },
  },
})
```

`env` 內的變數會原樣傳給子進程，所以來自不可信來源的伺服器設定（例如用戶提供的設定檔）應視為不可信輸入。

### 使用 `allowedHosts` 限制對外請求的目標主機 {/* #restricting-outbound-hosts-with-allowedhosts */}

如果 HTTP 伺服器的 URL 來自不可信設定，攻擊者便可能透過控制 URL 誘使客戶端存取內部服務，造成伺服器端請求偽造。為這類伺服器設定 `allowedHosts`，可限制客戶端連線的目標主機：

```typescript
const mcp = new MCPClient({
  servers: {
    remote: {
      url: new URL(untrustedConfig.serverUrl),
      allowedHosts: ['api.example.com'],
    },
  },
})
```

主機驗證規則如下：

* 使用預設的請求方式時，客戶端會在請求**送出前**截停任何發往未獲許可主機的請求，包括每次重新導向的請求。客戶端會自行處理最多 5 次重新導向，逐次驗證目標。跨來源重新導向不會轉送 `Authorization` 標頭。只要協定、主機或連接埠有變，便會移除該標頭，與標準 fetch 的行為一致。
* 如果提供自訂 `fetch`，客戶端仍會在請求送出前檢查初始 URL，但會在收到回應後才使用 `response.url` **事後驗證**重新導向。對外請求可能已經送出。如果最終 URL 指向未獲許可的主機，便會捨棄回應。自行建立的 `Response` 若沒有填寫 `response.url`，便會略過這項事後檢查。
* 透過 `authProvider` 發出的 OAuth 請求亦須驗證，包括查找授權伺服器的元資料、交換權杖和更新權杖。如果授權伺服器與 MCP 伺服器不在同一主機，也要將授權伺服器的主機加入 `allowedHosts`。
* 目標主機未獲許可時，連線會失敗並回傳明確的錯誤，重新連線機制不會重試。

`allowedHosts` 只會比對完整的主機名稱，不支援萬用字元或 URL 協定檢查。如需設定檢查協定或 IP 範圍等規則，可提供自訂的 `fetch` 實作。客戶端每次發出請求都會調用該實作。

### 將 Tool 回應視為不可信輸入 {/* #treat-tool-responses-as-untrusted-input */}

MCP 伺服器回傳的 Tool 結果會作為模型輸入加入 Agent 的上下文。惡意或遭入侵的伺服器可利用 Tool 輸出進行提示注入。傳輸客戶端不會清理 Tool 回應。可在 Agent 層使用 Mastra 的[輸入和輸出處理器](/docs/agents/processors)，在內容送入模型前和模型輸出後檢查、轉換或攔截內容。使用第三方伺服器時，請配合 `requireToolApproval`，並遵循上文關於 `forwardInstructions` 的安全說明。

## 方法 {/* #methods */}

### `listTools()` {/* #listtools */}

擷取所有已設定伺服器的 Tool，並在各 Tool 名稱加上伺服器前綴（格式為 `serverName_toolName`），以免名稱衝突。
可將回傳值傳入 Agent 定義。

結果不包含只供應用程式使用的 Tool，即 `_meta.ui.visibility` 不含 `"model"` 的 Tool。`listToolsets()` 和 `listToolDefinitions()` 亦會排除這些 Tool。

伺服器名稱和 Tool 名稱均可包含 `_`，所以兩組不同的名稱可能產生相同的鍵。例如，伺服器 `local` 的 Tool `x_status` 和伺服器 `local_x` 的 Tool `status` 均會產生 `local_x_status`。該鍵會對應 `servers` 中較後列出的伺服器所提供的 Tool，客戶端會記錄警告並列出兩組名稱。重新命名其中一部伺服器即可保留兩個 Tool。

```ts
new Agent({ id: 'agent', tools: await mcp.listTools() })
```

### `listToolsWithErrors(options?)` {/* #listtoolswitherrorsoptions */}

擷取所有已設定伺服器的 Tool，並為 Tool 名稱加上相應的伺服器前綴。如果伺服器無法連線或列出 Tool，亦會逐一回傳相關錯誤。

設定 `perServerTimeoutMs` 可限制探索程序等待每部伺服器的時間。限時內完成探索的伺服器所提供的 Tool 會保留在 `tools` 內，逾時的伺服器則會列在 `errors` 內。`durations` 會以毫秒記錄每部伺服器的探索耗時。

```typescript
const { tools, errors, errorDetails, durations } = await mcp.listToolsWithErrors({
  perServerTimeoutMs: 3_000,
})

new Agent({ id: 'agent', tools })
console.log(errors, errorDetails, durations)
```

為了向後兼容，`errors` 繼續使用字串映射。`errorDetails` 會提供相同的錯誤訊息。如果底層錯誤有提供相關資料，也會附上可供程式讀取的 `httpStatus` 和傳輸錯誤 `code` 欄位。如果有 HTTP 狀態碼，舊格式的訊息亦會附上 `(HTTP nnn)` 後綴。

調用時如不傳入選項，只會省略 `durations`。`tools`、`errors` 和 `errorDetails` 一律會回傳。

### `listToolsets()` {/* #listtoolsets */}

回傳以伺服器名稱為鍵的物件，每個值包含對應伺服器的 Tool。Tool 保留原有名稱，不加伺服器前綴。
可在程式執行時將回傳值傳入生成或串流方法。

```typescript
const res = await agent.stream(prompt, {
  toolsets: await mcp.listToolsets(),
})
```

Agent 按 Tool 名稱合併各組 Tool。如果兩部伺服器提供同名 Tool，例如 `search`，模型只會收到 `servers` 中較後列出的伺服器所提供的 Tool，Agent 亦會記錄警告。如要保留兩個 Tool，可將 `listTools()` 回傳的帶前綴 Tool 作為一組傳入：

```typescript
const res = await agent.stream(prompt, {
  toolsets: { mcp: await mcp.listTools() }, // docs_search, tickets_search
})
```

### `listToolsetsWithErrors(options?)` {/* #listtoolsetswitherrorsoptions */}

回傳按伺服器名稱分組的 Tool 集合，以及各伺服器的探索錯誤。可設定 `perServerTimeoutMs`，分別限制每部伺服器的探索時間，並在 `durations` 內以毫秒記錄各部伺服器的探索耗時。

```typescript
const { toolsets, errors, errorDetails, durations } = await mcp.listToolsetsWithErrors({
  perServerTimeoutMs: 3_000,
})

const res = await agent.stream(prompt, { toolsets })
console.log(errors, errorDetails, durations)
```

調用時如不傳入選項，只會省略 `durations`。`toolsets`、`errors` 和 `errorDetails` 一律會回傳。

#### 逐部回報伺服器的探索結果 {/* #report-each-server-as-it-settles */}

回傳的 Promise 要待所有伺服器的探索結束後才會兌現，因此一部回應較慢的伺服器便可延遲整體結果。傳入 `onServerSettled`，可在任何伺服器的探索成功、失敗或逾時後立即處理。回調函數會收到伺服器名稱、`value`（以該伺服器原有 Tool 名稱為鍵的 Tool 集合）或 `error`，以及以毫秒計的 `duration`。`listToolsWithErrors()` 和 `listToolDefinitionsWithErrors()` 亦支援此選項。

```typescript
await mcp.listToolsetsWithErrors({
  perServerTimeoutMs: 60_000,
  onServerSettled: (serverName, { value, error, duration }) => {
    if (error) {
      console.error(`${serverName} failed after ${duration}ms: ${error.message}`)
    } else {
      console.log(`${serverName} ready with ${Object.keys(value).length} tools`)
    }
  },
})
```

回調函數拋出的錯誤會記入日誌，探索程序會繼續。如果 `async` 回調函數回傳的 Promise 被拒絕，拒絕亦會記入日誌並獲處理，不會造成未處理的拒絕。

#### 只探索指定伺服器 {/* #discover-only-some-servers */}

傳入 `serverNames` 可只探索指定的伺服器，例如只重試逾時的伺服器，毋須重新啟動其他伺服器。未有設定的名稱會被略過。`listToolsWithErrors()` 和 `listToolDefinitionsWithErrors()` 亦支援此選項。

```typescript
const { errorDetails } = await mcp.listToolsetsWithErrors({ perServerTimeoutMs: 3_000 })

// Only servers that timed out are worth retrying. A server that failed for
// another reason (bad config, auth refused) will just fail again.
const timedOut = Object.entries(errorDetails)
  .filter(([, details]) => details.code === MCP_DISCOVERY_TIMEOUT_CODE)
  .map(([serverName]) => serverName)

const retry = await mcp.listToolsetsWithErrors({ serverNames: timedOut })
```

`MCP_DISCOVERY_TIMEOUT_CODE` 由 `@mastra/mcp` 匯出，用來標記 `perServerTimeoutMs` 所觸發的錯誤，讓你區分伺服器回應逾時和其他故障。

### `listToolDefinitions()` {/* #listtooldefinitions */}

以普通、可序列化的定義回傳各伺服器的 Tool，按伺服器名稱分組，並以伺服器提供的原有 Tool 名稱為鍵，不使用 `listTools()` 所採用的 `serverName_toolName` 格式。

與 `listTools()` 一樣，此方法會排除只供應用程式使用的 Tool，即 `_meta.ui.visibility` 不含 `"model"` 的 Tool。MCP 應用程式會透過宿主調用這些 Tool，因此不會將它們交給 Agent。

此方法與 `listTools()` 的分別在於，結果不含函數或對正在運作的客戶端的參照，因此可用 `JSON.stringify` 序列化，然後快取至 Redis 或數據庫，亦可儲存為建置產物。每項定義均包含 MCP `tools/list` 回應的資料，包括名稱、標題、描述、輸入結構、輸出結構、註解和 `_meta`，以及探索時記錄的伺服器名稱、版本及指令。

```typescript
const definitions = await mcp.listToolDefinitions()

await cache.set('mcp-tools', JSON.stringify(definitions))
```

### `listToolDefinitionsWithErrors(options?)` {/* #listtooldefinitionswitherrorsoptions */}

除了 `listToolDefinitions()` 所提供的結果，此方法還會分別回傳各部連線失敗的伺服器所對應的錯誤。快取目錄時可使用此方法，以免儲存的清單漏掉探索時未能連線的伺服器。

設定 `perServerTimeoutMs`，可分別限制各部伺服器的探索時間。傳入選項時，`durations` 會以毫秒記錄各部伺服器的探索耗時。

```typescript
const { definitions, errors, errorDetails, durations } = await mcp.listToolDefinitionsWithErrors({
  perServerTimeoutMs: 3_000,
})

if (Object.keys(errors).length === 0) {
  await cache.set('mcp-tools', JSON.stringify(definitions))
}

console.log(errorDetails, durations)
```

調用時如不傳入選項，只會省略 `durations`。`definitions`、`errors` 和 `errorDetails` 一律會回傳。

### `toolFromDefinition()` {/* #toolfromdefinition */}

根據快取的定義重建一個可執行的 Tool。客戶端會待該 Tool 首次執行時才建立連線。

回傳的 Tool 與 `listTools()` 回傳的 Tool 行為一致，包括嚴格模式的元資料、審批規則、結構化內容處理、Tool 錯誤處理及重新連線行為。兩種方式均會根據伺服器所公布的 `outputSchema` 驗證成功調用所回傳的結構化結果。結果無效時，Tool 調用會被拒絕。MCP 錯誤結果會略過輸出驗證。

沒有宣告 `$schema` 的 MCP 結構定義會使用 JSON Schema 2020-12，支援本地 `$ref` 和 `$defs` 參照、組合關鍵字和布林子結構。為限制驗證不可信 Tool 目錄所需的資源，輸入及輸出結構定義的子結構最多可巢狀 128 層，子結構節點上限為 10,000 個。

`structuredContent` 可以是任何 JSON 值，包括字串、數字、布林值和 `null`。物件或陣列結果亦會透過不可列舉的 Mastra 元資料屬性提供 MCP 內容和 `_meta` 封裝。純量或 `null` 結果無法附加這些屬性，因此會原樣回傳。

```typescript
const definitions = JSON.parse(await cache.get('mcp-tools'))

const tool = await mcp.toolFromDefinition({
  serverName: 'weather',
  definition: definitions.weather.getForecast,
})
```

### `authenticate()` {/* #authenticate */}

如果伺服器的 `MCPOAuthClientProvider` 使用回送重新導向 URL，此方法會執行互動式 OAuth 授權碼流程。本地回調伺服器會將授權 URL 傳給 Provider 的 `onRedirectToAuthorization` 回調函數，並等待瀏覽器回傳授權碼。取得授權碼後，會以此交換權杖並重新連線。參閱[互動式瀏覽器驗證](#interactive-browser-authentication)。

選用參數 `timeoutMs` 設定等待瀏覽器回傳授權碼的最長時間，預設為 5 分鐘。逾時後調用會被拒絕。

```typescript oxfmt:false
async authenticate(serverName: string, options?: { timeoutMs?: number }): Promise<void>
```

### `getServerAuthState()` {/* #getserverauthstate */}

回傳已設定伺服器的 OAuth 授權狀態。連線嘗試因授權錯誤被拒絕後為 `'needs-auth'`，伺服器接受 Provider 的憑證後為 `'authorized'`。未有設定 `authProvider` 或尚未嘗試連線時為 `undefined`。

```typescript oxfmt:false
getServerAuthState(serverName: string): 'needs-auth' | 'authorized' | undefined
```

### `cancelAuthentication()` {/* #cancelauthentication */}

取消指定伺服器正在進行的 `authenticate()` 流程，以免放棄瀏覽器授權後客戶端仍無限期等待。此操作會中止流程，包括回調伺服器綁定連接埠之前的準備階段。如果本地回調伺服器正在監聽，也會將其關閉。仍在等待的 `authenticate()` 調用會被拒絕。成功取消流程則回傳 `true`，未有流程在執行則回傳 `false`。

取消後 `getServerAuthState()` 的回傳值視乎流程進度。如果在收到 `401` 拒絕後取消，狀態仍為 `'needs-auth'`，可以立即重試。如果在準備階段取消，且尚未嘗試連線，狀態會維持原值，通常為 `undefined`。

```typescript oxfmt:false
async cancelAuthentication(serverName: string): Promise<boolean>
```

### `events` 屬性（實驗性） {/* #events-property-experimental */}

使用 `events` 屬性可列出並訂閱支援 [MCP 事件擴充功能（SEP-3415）](https://github.com/modelcontextprotocol/modelcontextprotocol/pull/3415)的伺服器事件。你可以在伺服器發生事件時作出回應，例如有新內容推送到程式碼庫，毋須輪詢 Tool。每次事件至少會投遞一次。重新連接或恢復訂閱後，伺服器可能重發同一次事件。客戶端會將 `eventId` 與 `dedupWindow` 保留的近期 ID 比對，略過重複的事件。

完整操作示例見 [MCP 事件](/docs/connections/mcp#mcp-events)。

:::warning
SEP-3415 仍屬草案。這個 API 可能在任何版本中改動。
:::

```typescript
const events = await mcpClient.events.list('github')

const subscription = await mcpClient.events.subscribe(
  'github',
  'repo.push',
  { repo: 'mastra-ai/mastra' },
  { cursor: await loadCursor() },
)

for await (const event of subscription) {
  await handlePush(event.data)
  // Safe to persist after each handled occurrence
  await saveCursor(subscription.cursor)
}
```

客戶端不會向未聲明支援 `io.modelcontextprotocol/events` 擴充功能的伺服器發送 `events/*` 請求。`list()` 回傳的 Promise 會以 ID 為 `MCP_CLIENT_LIST_EVENTS_FAILED` 的 `MastraError` 拒絕，`subscribe()` 則會以 `MCP_CLIENT_SUBSCRIBE_EVENT_FAILED` 拒絕。在這兩種情況下，`error.cause.id` 都是 `MCP_EVENTS_NOT_SUPPORTED`。`list()` 和 `subscribe()` 因其他原因失敗時，仍分別使用這兩個錯誤 ID，詳細原因可在 `error.cause` 查看。

#### `events.list(serverName: string)` {/* #eventslistservername-string */}

逐頁取得並回傳伺服器提供的所有事件類型。每項事件描述均包含 `name`、可選的 `description`、伺服器支援的 `delivery` 模式，以及可選的 `inputSchema` 和 `payloadSchema`。

```typescript oxfmt:false
async list(serverName: string): Promise<MCPEventDescriptor[]>
```

現時伺服器的事件清單有變動時，客戶端不會收到通知。再次呼叫 `list()` 即可取得新增的事件類型。

#### `events.subscribe(serverName, eventName, args?, options?)` {/* #eventssubscribeservername-eventname-args-options */}

提出訂閱，回傳的 Promise 會在伺服器確認後完成。遇到未知事件、參數無效或沒有訂閱權限等錯誤時，Promise 會被拒絕。新訂閱由伺服器接受訂閱的一刻開始。要接收之前發生的事件，須用 `options.cursor` 從較早的位置恢復訂閱。使用 webhook 投遞時，Promise 可能在伺服器接受訂閱之後才完成。若客戶端暫時未能將收到的事件轉交到相應的訂閱，便會回應 `503`，伺服器其後會重試。

```typescript oxfmt:false
async subscribe(
  serverName: string,
  eventName: string,
  args?: Record<string, unknown>,
  options?: MCPEventSubscribeOptions,
): Promise<MCPEventSubscription>
```

客戶端按以下優先次序，選用事件支援的第一種投遞模式：`webhook`（只適用於客戶端已有 [`webhook` 設定](#webhook-delivery)時）、`push`（維持開啟的 `events/stream` 請求），然後是 `poll`（重複發送 `events/poll` 請求）。傳入 `options.delivery` 即可指定必須使用的模式。

傳回的 `MCPEventSubscription` 可作非同步迭代，逐一提供事件（`eventId`、`name`、`timestamp`、`data`），並包含以下成員：

* `cursor`：可安全儲存的最新位置，不會越過迴圈尚未收到的事件。如事件類型不支援重播，值便是 `null`。
* `truncated`：如伺服器回報迴圈剛收到的事件之前有缺漏，例如已儲存的游標早於伺服器保留事件的時段，值便是 `true`。請在迴圈內讀取。缺漏後的首宗事件對應 `true`，其後的事件對應 `false`。
* `mode`：目前的傳送模式，值為 `'webhook'`、`'push'` 或 `'poll'`。
* `deliveryStatus`：只適用於 Webhook 模式。包含伺服器就 Webhook URL 傳送情況作出的最新回報（`active`、`lastDeliveryAt`、`lastError`、`failedSince`），每次續訂時更新。
* `onError(handler)`：接收可復原的錯誤，例如串流中斷而客戶端正重新開啟串流。傳回一個可移除該處理函數的函數。
* `cancel()`：停止訂閱並結束迭代。提早退出 `for await` 迴圈亦會取消訂閱。

訂閱無法繼續時，迭代器會直接拋出 `MastraError`，不加包裝。伺服器出現不可重試的錯誤時，錯誤代碼為 `MCP_EVENTS_SUBSCRIPTION_FAILED`。伺服器終止推送或 Webhook 訂閱時，錯誤代碼為 `MCP_EVENTS_SUBSCRIPTION_TERMINATED`。連續失敗 `retry.maxAttempts` 次時，錯誤代碼為 `MCP_EVENTS_RETRIES_EXHAUSTED`。重新連線後，客戶端會重新開啟中斷的串流，並從上一個游標繼續輪詢。經 `reconnectServer()` 重新連線亦然。`disconnect()` 會結束所有訂閱。

#### `events.handleWebhook(request: Request)` {/* #eventshandlewebhookrequest-request */}

處理一次 Webhook 傳送，並傳回要送交伺服器的回應。請將此處理函數掛載至 `webhook.url` 指向的路由。

```typescript oxfmt:false
async handleWebhook(request: Request): Promise<Response>
```

此方法會在解析請求主體之前，以原始請求主體驗證 Standard Webhooks 簽署。它會回應伺服器的驗證握手，並按 `X-MCP-Subscription-Id` 請求標頭將事件分派至相應訂閱。回應狀態碼如下：

* `200`：事件已交予相應訂閱。如屬驗證請求，回應會原樣傳回驗證挑戰值。
* `401`：簽署無效，或時間戳記距今超過 5 分鐘。
* `503`：客戶端尚未識別訂閱 ID。伺服器會重試，以處理早於訂閱回應抵達的事件。
* `400`：請求已簽署，但主體格式有誤。請求方法並非 `POST` 時，會傳回 `405`。
* `413`：請求主體超過 1 MiB。在進行任何其他檢查前，最多只讀取此上限容許的資料量。
* `404`：客戶端未設定 `webhook`。

#### 透過 Webhook 傳送事件 {/* #webhook-delivery */}

設定 `webhook` 後，客戶端會用 `events/subscribe` 登記每項訂閱，伺服器則以 POST 請求將事件傳送至指定網址。伺服器必須驗證客戶端的身分，而該網址必須可經 `https` 公開存取。

```typescript title="src/mastra/index.ts"
import { Mastra } from '@mastra/core'
import { registerApiRoute } from '@mastra/core/server'
import { MCPClient } from '@mastra/mcp'

export const mcpClient = new MCPClient({
  servers: {
    github: {
      url: new URL('https://mcp.example.com/mcp'),
      requestInit: { headers: { Authorization: `Bearer ${process.env.GITHUB_MCP_TOKEN}` } },
    },
  },
  webhook: { url: 'https://agent.example.com/mcp/webhook' },
})

export const mastra = new Mastra({
  server: {
    apiRoutes: [
      registerApiRoute('/mcp/webhook', {
        method: 'POST',
        // Deliveries are authenticated by their signature, not by Mastra auth
        requiresAuth: false,
        handler: c => mcpClient.events.handleWebhook(c.req.raw),
      }),
    ],
  },
})
```

每項訂閱到期前，客戶端會以最新的游標再次呼叫 `events/subscribe` 以續訂。如伺服器在 `deliveryStatus` 回報傳送失敗，例如接收端點逾時，`onError` 會收到 `MCP_EVENTS_WEBHOOK_DELIVERY_FAILING`，錯誤詳情包含 `lastError`。每次 Webhook 傳送中的 `cursor` 只涵蓋端點已確認的事件。因此，從儲存的游標恢復訂閱時，最後處理的事件可能會再次送達。下一次續訂會恢復暫停的訂閱。`cancel()` 會送出 `events/unsubscribe`。

Webhook 狀態儲存在本進程。接收路由必須與發起訂閱的 `MCPClient` 在同一進程運行。

透過 Webhook 傳送事件，需要與伺服器建立已通過身分驗證的 HTTP 連線，因為伺服器會將每項 Webhook 訂閱綁定至呼叫方。經 stdio 或未經驗證的 HTTP 連線提出的 `events/subscribe` 會被伺服器拒絕。達到 Webhook 訂閱數目上限後，伺服器亦會拒絕新訂閱（`-32025`）。如沒有強制指定傳送模式，訂閱會改用 `push` 或 `poll`，首個 `onError` 處理函數會收到 `MCP_EVENTS_WEBHOOK_UNAVAILABLE`，錯誤詳情包含拒絕代碼 `code` 及改用的模式 `fallback`。強制指定 `delivery: 'webhook'` 時，訂閱請求會失敗。

在同一部伺服器上，事件名稱和參數相同的訂閱共用一項伺服器端 Webhook 訂閱。每項訂閱經各自的迭代器接收每宗事件。客戶端要到最後一項訂閱取消時才會送出 `events/unsubscribe`。

### Agent 及 Workflow 中的事件（實驗功能） {/* #events-in-agents-and-workflows-experimental */}

`MCPEventsSignalProvider` 會以通知形式將 MCP 伺服器事件傳送至 Agent 的執行緒。將它加入 Agent 的 `signals` 後，便可為執行緒訂閱事件。Agent 需要用於通知的儲存網域，`InMemoryStore` 及標準儲存配接器均有提供。

:::警告
SEP-3415 是草案。此 API 可能會在任何版本中發生變更。
:::

```typescript title="src/mastra/agents/repo-agent.ts"
import { Agent } from '@mastra/core/agent'

const mcp = new MCPClient({
  servers: { github: { url: new URL('https://example.com/mcp') } },
})

export const repoEvents = new MCPEventsSignalProvider({
  client: mcp,
  subscribeOptions: { maxAgeMs: 60 * 60 * 1000 },

export const repoAgent = new Agent({
  id: 'repo-agent',
  name: 'Repo Agent',
  instructions: 'Triage repository activity.',
  model: '__GATEWAY_OPENAI_MODEL__',
  signals: [repoEvents],
})

await repoEvents.subscribeThread(
  { resourceId: 'user-1', threadId: 'thread-1' },
  { server: 'github', event: 'repo.push', args: { repo: 'mastra-ai/mastra' } },
)
```

訂閱結束時，例如由伺服器終止，每個已訂閱的執行緒都會收到一則優先級為 `high` 的通知，類型為 `kind: 'mcp-event-subscription-ended'`。這些執行緒其後會取消訂閱。

Provider 提供以下方法：

* `subscribeThread(thread, { server, event, args? })`：為執行緒訂閱事件，從已儲存的游標繼續接收，並在 MCP 訂閱獲確認後完成。如伺服器拒絕訂閱，執行緒便不會訂閱，Promise 亦會被拒絕。執行緒的訂閱關係只保留在記憶體。重新啟動後，請為每個仍需接收事件的執行緒再次呼叫 `subscribeThread()`。
* `unsubscribeThread(thread, { server, event, args? })`：如執行緒原先已有訂閱，傳回的 Promise 會以 `true` 完成。最後一個執行緒取消訂閱時，會取消 MCP 訂閱並刪除已儲存的游標。
* `stop()`：取消所有 MCP 訂閱並保留已儲存的游標。使用相同 `cursorStore` 的新 Provider 可從停止的位置繼續。
* `MCPEventsSignalProvider.key({ server, event, args? })`：傳回游標儲存機制採用的訂閱鍵。

事件至少會傳送一次。Provider 先通知執行緒，然後才儲存游標，因此系統故障前剛發出通知的事件，可能會在重新啟動後重播。通知的 `dedupeKey` 包含事件 ID。如首則通知仍未送達，重播產生的通知會與它合併。如首則通知已送達，執行緒便會再次收到通知。

### `tasks` 屬性（實驗功能） {/* #tasks-property-experimental */}

部分 Tool 的執行時間超過單一 HTTP 請求可保持開啟的時間。實作 [MCP Tasks 擴充功能（SEP-2663）](https://modelcontextprotocol.github.io/ext-tasks/specification/2026-07-28/tasks.html) 的伺服器可用任務回應這類呼叫，讓客戶端稍後取得結果。如要接收任務，請在伺服器設定中指定 `tasks`：

```typescript
const mcpClient = new MCPClient({
  servers: {
    reports: {
      url: new URL('https://reports.example.com/mcp'),
      tasks: { maxWaitMs: 30 * 60_000 },
      inputRequests: async ({ params }) => askUser(params),
    },
  },
})
```

:::警告
此 API 可能會在任何版本中發生變更。
:::

設定 `tasks` 後，客戶端會通知伺服器可接收任務。伺服器會逐次決定直接回應呼叫，還是傳回任務。如未設定 `tasks`，客戶端便不會收到任務，Tool 呼叫的行為維持不變。

Tool 呼叫傳回任務時，Tool 的呼叫介面維持不變，客戶端會按以下方式處理：

* 客戶端會按伺服器建議的間隔輪詢任務，直至任務完成，再傳回 Tool 的結果。
* 如任務需要輸入，客戶端會透過 `inputRequests` 為每個請求鍵取得一次答覆，以 `tasks/update` 送出答覆，然後繼續輪詢同一任務，不會再次送出 `tools/call`。如未設定處理函數，Agent 或 Workflow 中的 Tool 呼叫會暫停，等候用戶答覆（見[在 Agent 聊天中回覆任務的輸入請求](#answering-task-input-from-the-agent-chat)）。直接呼叫 `tool.execute()` 會以 `MCP_CLIENT_TOOL_TASK_INPUT_UNHANDLED` 失敗。任務會在伺服器上保持開啟，直至 TTL 屆滿。
* 中止 Tool 呼叫時會送出 `tasks/cancel`。達到 `maxWaitMs` 時亦會送出該請求，並以 `MCP_CLIENT_TOOL_TASK_TIMEOUT` 結束呼叫。即使輪詢或輸入處理函數仍在運行，兩種情況均會即時結束呼叫，其後才收到的回應或答覆會被捨棄。
* 客戶端輪詢期間若執行中斷連線操作，呼叫會以 `MCP_CLIENT_TOOL_TASK_POLL_FAILED` 失敗，客戶端不會重新連線。
* 如輪詢期間未能連接伺服器，例如伺服器正在重新啟動或部署，客戶端會重新連線並繼續輪詢，等候間隔逐步增加至最多 30 秒。連線被拒，或代理伺服器傳回 HTTP 502、503 或 504，均視為無法連接。如 5 分鐘後仍未收到回應，或先達到 `maxWaitMs` 或任務的 TTL，呼叫會以 `MCP_CLIENT_TOOL_TASK_POLL_FAILED` 失敗。任務仍可能在伺服器上完成。TTL 由任務的 `createdAt` 起計。如客戶端無法讀取該時間戳記，則由開始等候時起計。
* Tool 呼叫的 span 包含 `mcpTaskKey` 元資料，值為任務 ID 的 SHA-256 雜湊。Mastra 伺服器會用相同的鍵標記該任務的 span，方便配對兩端的紀錄，並避免任務 ID 出現在任何一端的 Trace。
* 已完成任務內的 Tool 錯誤與 Tool 直接傳回的錯誤一樣，按 `onToolError` 處理。如伺服器取消任務，呼叫會以 `MCP_CLIENT_TOOL_TASK_CANCELLED` 失敗。如伺服器將任務標示為 `failed`，呼叫會以 `MCP_CLIENT_TOOL_TASK_FAILED` 失敗。
* 已傳回任務的呼叫不會重試，因為重試會啟動另一項任務。
* 呼叫轉為任務時，以及任務狀態每次變更時，Tool 都會在輸出串流寫入一項 `MCPTaskProgress` 紀錄（`{ type: 'mcp-task', taskId, status, createdAt, serverName }`）。Studio 的 Tool 呼叫卡片會據此顯示運行中任務的狀態、已用時間及 MCP 任務 ID。Tool 輸出不會隨執行緒儲存，重新載入後卡片只會顯示結果。

Agent 啟用[背景任務](/docs/harness/background-tasks)後，來自已設定 `tasks` 的伺服器的 Tool 會以延後執行的背景任務運行，並且不會重試。遠端任務運行期間，Agent 可繼續工作。取消背景任務亦會取消遠端任務。可透過 Agent 的 `backgroundTasks.tools` 逐一覆寫各 Tool 的行為。

#### 在 Agent 聊天中回覆任務的輸入請求 {/* #answering-task-input-from-the-agent-chat */}

如任務需要輸入、未設定 `inputRequests` 處理函數，且 Tool 在 Agent 或 Workflow 中運行，Tool 呼叫便會如同呼叫 `suspend()` 一樣暫停。遠端任務會在伺服器上保持開啟。暫停時附帶的資料（`MCPInputRequestSuspendPayload`）包含仍待答覆的請求：

```typescript
const payload: MCPInputRequestSuspendPayload = {
  type: 'mcp-input-request',
  serverName: 'reports',
  toolName: 'approve_and_send',
  taskId: 'Zx81…', // the MCP task the answers go to
  createdAt: '2026-10-30T10:00:00.000Z', // when the task was created
  requestedAt: '2026-10-30T10:00:04.000Z', // when the call suspended; new each time the task asks again
  requests: {
    approve: {
      method: 'elicitation/create',
      params: {
        mode: 'form',
        message: 'Send it?',
        requestedSchema: {
          type: 'object',
          properties: { ok: { type: 'boolean' } },
          required: ['ok'],
        },
      },
    },
  },
}
```

為每個請求鍵提供一項答覆（`MCPInputRequestResumeData`），即可恢復 Tool 呼叫。例如，前台呼叫可透過 `agent.resumeStream()` 恢復，延後執行的背景任務則可透過 `backgroundTaskManager.resume()` 恢復：

```typescript
await agent.resumeStream(
  { inputResponses: { approve: { action: 'accept', content: { ok: true } } } },
  { runId, toolCallId },
)
```

恢復時，客戶端會透過 `tasks/update` 將答覆送交同一任務並繼續輪詢，不會再次送出 `tools/call`。如伺服器再次要求輸入，呼叫便會再次暫停，並附上新的請求。如任務在這段時間內已結束，呼叫會傳回相應的任務錯誤，例如 `MCP_CLIENT_TOOL_TASK_CANCELLED`。如伺服器已找不到該任務，則會傳回 `MCP_CLIENT_TOOL_TASK_POLL_FAILED`。如恢復資料不符合 `{ inputResponses: { [key]: { action: 'accept' | 'decline' | 'cancel', content? } } }` 的格式，或有請求仍未答覆，呼叫便會直接以 `MCP_CLIENT_TOOL_TASK_RESUME_INVALID` 失敗，不會聯絡伺服器。

如已設定 `inputRequests` 處理函數，該函數會優先執行，呼叫便不會暫停。

暫停時附帶的資料包含可用於存取任務的 MCP 任務 ID。該 ID 會隨暫停的 Tool 呼叫一同儲存，請按處理其他執行緒資料的方式處理。

#### `tasks.get(serverName: string, taskId: string)` {/* #tasksgetservername-string-taskid-string */}

傳回任務的目前狀態（`MCPDetailedTask`）。狀態為 `completed` 時包含 `result`，狀態為 `input_required` 時包含 `inputRequests`。呼叫失敗時會傳回 `MCP_CLIENT_GET_TASK_FAILED`。如任務不明或由其他呼叫方建立，`error.cause.code` 為 `-32602`。

#### `tasks.update(serverName: string, taskId: string, inputResponses: MCPTaskInputResponses)` {/* #tasksupdateservername-string-taskid-string-inputresponses-mcptaskinputresponses */}

回覆處於 `input_required` 狀態的任務的 `inputRequests`，答覆採用與請求相同的鍵。伺服器會略過未要求或已答覆的鍵。呼叫失敗時會傳回 `MCP_CLIENT_UPDATE_TASK_FAILED`。

#### `tasks.cancel(serverName: string, taskId: string)` {/* #taskscancelservername-string-taskid-string */}

要求伺服器停止任務。伺服器仍可能完成該任務。呼叫失敗時會傳回 `MCP_CLIENT_CANCEL_TASK_FAILED`。

## 回答輸入請求 {/* #answering-input-requests */}

當伺服器上的 Tool、資源或提示需要用戶提供資料時，呼叫會以 `input_required` 結果結束。結果包含一項或多項內嵌請求。每項請求均有伺服器指定的 `key`，並帶有表格（`requestedSchema`）或用戶必須瀏覽的網址。如要回覆這些請求，請在伺服器定義中設定 `inputRequests`。客戶端會為每項內嵌請求呼叫一次處理函數，帶同答覆重試原有呼叫，再以最終結果完成 Tool 呼叫。如沒有設定處理函數，`input_required` 結果會以錯誤形式傳回。

```typescript
import { MCPClient } from '@mastra/mcp'

const mcpClient = new MCPClient({
  servers: {
    interactiveServer: {
      url: new URL('http://localhost:3000/mcp'),
      inputRequests: async ({ key, params, signal }) => {
        if (params.mode === 'url') {
          return { action: 'decline' }
        }
        const content = await collectUserInput(params.message, params.requestedSchema, { signal })
        return { action: 'accept', content }
      },
    },
  },
})
```

### `MCPInputRequest` {/* #mcpinputrequest */}

處理函數會收到以下欄位：

* `key`：伺服器指定的鍵，用來識別對應的回覆。如果同一輪收到多個請求，請將這個鍵傳給用戶介面。
* `params`：請求參數。表格模式包含 `message` 和 `requestedSchema`，其中 `requestedSchema` 是一個扁平的 JSON Schema 物件，欄位均為基本類型。URL 模式則包含 `message` 和 `url`。
* `signal`：發出請求的呼叫取消或逾時時，此訊號會觸發中止。

設定處理函數後，客戶端會向伺服器表明支援表格模式。如要同時接受 URL 模式的請求，請擴充同一個伺服器定義中的 `capabilities.elicitation` 設定。

### 回應類型 {/* #response-types */}

傳回一個 `ElicitResult`：

* **接受**：用戶提供資料並確認提交。`content` 必須符合 `requestedSchema`。

  ```typescript
  return {
    action: 'accept',
    content: { name: 'John Doe', email: 'john@example.com' },
  }
  ```

* **拒絕**：用戶明確拒絕提供所要求的資料。

  ```typescript
  return { action: 'decline' }
  ```

* **取消**：用戶關閉了請求。
  ```typescript
  return { action: 'cancel' }
  ```

如用戶拒絕或取消請求，Tool 呼叫會以錯誤結束。伺服器收到用戶確認提交的回覆後，仍可再次要求輸入，因此同一次 Tool 呼叫可執行處理函數多次。

### 按 Schema 收集輸入 {/* #schema-based-input-collection */}

逐一讀取 `requestedSchema` 的欄位，提示用戶填寫：

```typescript
inputRequests: async ({ params }) => {
  if (params.mode === 'url') return { action: 'decline' }

  const { properties, required = [] } = params.requestedSchema
  const content: Record<string, string | number | boolean> = {}

  for (const [fieldName, fieldSchema] of Object.entries(properties)) {
    const value = await promptUser({
      name: fieldName,
      title: fieldSchema.title,
      description: fieldSchema.description,
      required: required.includes(fieldName),
    })

    if (value !== null) {
      content[fieldName] = value
    }
  }

  return { action: 'accept', content }
}
```

### 建議做法 {/* #best-practices */}

* **預先設定處理函數**：在伺服器定義中設定處理函數，確保要求用戶輸入的 Tool 每次都有處理函數可用。
* **驗證輸入**：檢查是否提供了必填欄位。
* **尊重用戶選擇**：妥善處理用戶拒絕或取消的情況。
* **清晰的用戶介面**：說明要提供哪些資料，以及索取資料的原因。
* **安全**：切勿自動接受索取敏感資料的請求。把 URL 模式請求中的連結當作指向不受信任的網站。

## OAuth 認證 {/* #oauth-authentication */}

要連接按照 [MCP 2026-07-28 授權規範](https://modelcontextprotocol.io/specification/2026-07-28/basic/authorization)要求 OAuth 認證的 MCP 伺服器，請使用 `MCPOAuthClientProvider`。Provider 不會在執行時註冊客戶端。你可以透過 `clientInformation` 提供已在授權伺服器預先註冊的客戶端資料，或將[客戶端 ID 元數據文件](https://modelcontextprotocol.io/specification/2026-07-28/basic/authorization/client-registration#client-id-metadata-documents)的網址設為 `clientMetadataUrl`：

```typescript
import { MCPClient, MCPOAuthClientProvider } from '@mastra/mcp'

// Create an OAuth provider
const clientMetadataUrl = 'https://app.example.com/oauth/client-metadata.json'

const oauthProvider = new MCPOAuthClientProvider({
  redirectUrl: 'http://localhost:3000/oauth/callback',
  clientMetadataUrl,
  clientMetadata: {
    client_id: clientMetadataUrl,
    redirect_uris: ['http://localhost:3000/oauth/callback'],
    client_name: 'My MCP Client',
    grant_types: ['authorization_code', 'refresh_token'],
    response_types: ['code'],
  },
  onRedirectToAuthorization: url => {
    // Handle authorization redirect (open browser, redirect response, etc.)
    console.log(`Please visit: ${url}`)
  },
})

// Use the provider with MCPClient
const client = new MCPClient({
  servers: {
    protectedServer: {
      url: new URL('https://mcp.example.com/mcp'),
      authProvider: oauthProvider,
    },
  },
})
```

在 `clientMetadataUrl` 提供的文件必須包含相同的 `client_id`、`client_name` 和 `redirect_uris`。如使用回環回調，請在託管的文件中包含 `getCallbackUrlCandidates()` 傳回的所有後備網址。Provider 會把文件網址當作 `client_id` 傳送，而且不會呼叫註冊端點。如果授權伺服器既不接受元數據文件，也不接受預先註冊的 `clientInformation`，授權流程會明確報錯。只可設定一種客戶端身份，同時設定 `clientInformation` 和 `clientMetadataUrl` 時，建構函數會拋出錯誤。

`MCPOAuthClientProvider` 儲存的權杖會與授權伺服器已驗證的 `issuer` 綁定。Provider 會持久儲存探索狀態，確保授權碼交換請求只發往發出重新導向的伺服器。回環回調亦會把 RFC 9207 的 `iss` 參數轉發給 SDK。如果參數與預期值不符，SDK 會在交換授權碼前拒絕請求。

每部伺服器應有獨立的 `MCPOAuthClientProvider` 實例。授權期間，Provider 會保留所屬伺服器的會話和憑證狀態。多部伺服器共用一個實例時，各自的授權流程可能覆蓋彼此的狀態。設定多部受保護的伺服器時，請分別建立 Provider。如果這些 Provider 共用同一個持久儲存後端，請為每個 Provider 分配獨立的 `OAuthStorage` 命名空間，因為儲存變更的先後次序只會在同一個 Provider 實例內協調。

### 透過瀏覽器進行互動式認證 {/* #interactive-browser-authentication */}

當伺服器因需要授權而拒絕連線，客戶端會記錄 `'needs-auth'` 狀態，等待進一步處理。呼叫 `authenticate()` 即可完成授權流程。這個方法會在 Provider 的回環重新導向網址啟動一次性回調伺服器。如該連接埠已被佔用，便會順序嘗試之後的連接埠。SDK 隨後會執行探索，並使用已設定的客戶端身份。`onRedirectToAuthorization` 會收到授權網址，讓應用程式在用戶的瀏覽器開啟。瀏覽器傳回授權碼後，流程便會完成權杖交換：

```typescript
import { MCPClient, MCPOAuthClientProvider } from '@mastra/mcp'

const clientMetadataUrl = 'https://app.example.com/oauth/client-metadata.json'

const oauthProvider = new MCPOAuthClientProvider({
  redirectUrl: 'http://127.0.0.1:5533/oauth/callback',
  clientMetadataUrl,
  clientMetadata: {
    client_id: clientMetadataUrl,
    redirect_uris: ['http://127.0.0.1:5533/oauth/callback'],
    client_name: 'My MCP Client',
    grant_types: ['authorization_code', 'refresh_token'],
    response_types: ['code'],
  },
  onRedirectToAuthorization: url => {
    // Open the user's browser at the consent page
    console.log(`Please visit: ${url}`)
  },
})

const mcp = new MCPClient({
  servers: {
    protectedServer: {
      url: new URL('https://mcp.example.com/mcp'),
      authProvider: oauthProvider,
    },
  },
})

try {
  await mcp.listTools()
} catch {
  if (mcp.getServerAuthState('protectedServer') === 'needs-auth') {
    await mcp.authenticate('protectedServer')
  }
}
```

同時向同一部伺服器呼叫 `authenticate()` 時，各呼叫會加入正在進行的授權流程。不同伺服器會各自進行認證。如果已儲存有效權杖，呼叫會直接重新連線，毋須開啟瀏覽器。

自行控制授權流程的應用程式可透過匯出的輔助函數 `createOAuthCallbackServer` 取得授權碼。這個函數會建立一次性回環伺服器，驗證 OAuth 的 `state` 參數後，才以授權碼履行 Promise。伺服器使用未加密的 HTTP，因此只適用於本機回環重新導向。使用 HTTPS 重新導向網址的網頁應用程式必須自行託管回調端點，並直接操作 Provider：

```typescript
import { createOAuthCallbackServer, getCallbackUrlCandidates } from '@mastra/mcp'

// getCallbackUrlCandidates() lists every URL the helper may bind, so list all
// of them as redirect_uris in your pre-registration or metadata document.
const redirectUris = getCallbackUrlCandidates('http://127.0.0.1:5533/oauth/callback').map(url =>
  url.toString(),
)

const server = await createOAuthCallbackServer({
  redirectUrl: 'http://127.0.0.1:5533/oauth/callback',
  state: expectedState,
})

// server.url reflects the port actually bound — use it as the redirect_uri.
try {
  const { code, iss } = await server.waitForCode()
  // Exchange the code here, passing `iss` so the SDK validates the issuer.
} finally {
  await server.close()
}
```

### 自訂權杖儲存 {/* #custom-token-storage */}

如需跨會話持久儲存權杖，請實作 `OAuthStorage` 介面。Provider 以字串作為鍵，儲存權杖（最新一組，以及每個授權伺服器簽發者各一項記錄）、探索狀態和 PKCE 驗證器。後端只需提供鍵值儲存介面：

```typescript
import { MCPOAuthClientProvider, OAuthStorage } from '@mastra/mcp'

class DatabaseOAuthStorage implements OAuthStorage {
  constructor(
    private db: Database,
    private userId: string,
  ) {}

  async set(key: string, value: string): Promise<void> {
    await this.db.query(
      'INSERT INTO oauth_tokens (user_id, key, value) VALUES (?, ?, ?) ON CONFLICT DO UPDATE SET value = ?',
      [this.userId, key, value, value],
    )
  }

  async get(key: string): Promise<string | undefined> {
    const result = await this.db.query(
      'SELECT value FROM oauth_tokens WHERE user_id = ? AND key = ?',
      [this.userId, key],
    )
    return result?.[0]?.value
  }

  async delete(key: string): Promise<void> {
    await this.db.query('DELETE FROM oauth_tokens WHERE user_id = ? AND key = ?', [
      this.userId,
      key,
    ])
  }
}

const provider = new MCPOAuthClientProvider({
  redirectUrl: 'http://localhost:3000/callback',
  clientMetadata: {/* ... */},
  clientInformation: { client_id: 'my-registered-client' },
  storage: new DatabaseOAuthStorage(db, 'user-123'),
})
```

### 靜態 Tool 設定 {/* #static-tool-configuration */}

如果整個應用程式共用同一條 MCP 伺服器連線，請用 `listTools()` 取得 Tool，並傳給 Agent：

```typescript
import { MCPClient } from '@mastra/mcp'
import { Agent } from '@mastra/core/agent'

const mcp = new MCPClient({
  servers: {
    stockPrice: {
      command: 'npx',
      args: ['tsx', 'stock-price.ts'],
      env: {
        API_KEY: 'your-api-key',
      },
      logger: logMessage => {
        console.log(`[${logMessage.level}] ${logMessage.message}`)
      },
    },
    weather: {
      url: new URL('http://localhost:8080/mcp'),
    },
  },
  timeout: 30000, // Global 30s timeout
})

// Create an agent with access to all tools
const agent = new Agent({
  id: 'multi-tool-agent',
  name: 'Multi-tool Agent',
  instructions: 'You have access to multiple tool servers.',
  model: '__GATEWAY_OPENAI_MODEL__',
  tools: await mcp.listTools(),
})

// Example of using resource methods
async function checkWeatherResource() {
  try {
    const weatherResources = await mcp.resources.list()
    if (weatherResources.weather && weatherResources.weather.length > 0) {
      const currentWeatherURI = weatherResources.weather[0].uri
      const weatherData = await mcp.resources.read('weather', currentWeatherURI)
      console.log('Weather data:', weatherData.contents[0].text)
    }
  } catch (error) {
    console.error('Error fetching weather resource:', error)
  }
}
checkWeatherResource()

// Example of using prompt methods
async function checkWeatherPrompt() {
  try {
    const weatherPrompts = await mcp.prompts.list()
    if (weatherPrompts.weather && weatherPrompts.weather.length > 0) {
      const currentWeatherPrompt = weatherPrompts.weather.find(p => p.name === 'current')
      if (currentWeatherPrompt) {
        console.log('Weather prompt:', currentWeatherPrompt)
      } else {
        console.log('Current weather prompt not found')
      }
    }
  } catch (error) {
    console.error('Error fetching weather prompt:', error)
  }
}
checkWeatherPrompt()
```

## 實例管理 {/* #instance-management */}

`MCPClient` 類別內置機制，防止管理多個實例時出現記憶體洩漏：

1. 如以相同設定建立多個實例而沒有指定 `id`，系統會拋出錯誤，以防止記憶體洩漏。
2. 如需以相同設定建立多個實例，請為每個實例指定獨有的 `id`。
3. 以相同設定重新建立實例前，請先執行 `await configuration.disconnect()`。
4. 如只需一個實例，可將設定移到外層作用域，避免重複建立。

例如，以下程式碼嘗試以相同設定建立多個實例，但沒有指定 `id`：

```typescript
// First instance - OK
const mcp1 = new MCPClient({
  servers: {/* ... */},
})

// Second instance with same config - Will throw an error
const mcp2 = new MCPClient({
  servers: {/* ... */},
})

// To fix, either:
// 1. Add unique IDs
const mcp3 = new MCPClient({
  id: 'instance-1',
  servers: {/* ... */},
})

// 2. Or disconnect before recreating
await mcp1.disconnect()
const mcp4 = new MCPClient({
  servers: {/* ... */},
})
```

## 伺服器生命週期 {/* #server-lifecycle */}

MCPClient 會這樣管理伺服器連線：

1. 自動管理與多部伺服器的連線
2. 有序關閉伺服器，避免開發期間出現錯誤訊息
3. 連線中斷時清理資源

### 由應用程式控制結束程序的時機 {/* #handle-shutdown-yourself */}

預設情況下，客戶端連線後會註冊 `SIGINT`、`SIGTERM`、`SIGHUP` 和 `beforeExit` 掛鈎，以中斷與伺服器的連線並結束程序。這些掛鈎可能會打斷應用程式正在等候完成的清理工作，例如等候尚在處理的 HTTP 請求完成。

設定 `registerProcessHooks: false`，由應用程式接手關閉流程。待使用該客戶端的請求全部完成後，再呼叫 `disconnect()`：

```typescript
import { MCPClient } from '@mastra/mcp'

const mcp = new MCPClient({
  servers: { weather: { url: new URL('https://example.com/mcp') } },
  registerProcessHooks: false,
})

process.once('SIGTERM', async () => {
  // Finish your application's cleanup before disconnecting the client.
  await mcp.disconnect()
  process.exit(0)
})
```

同一程序內的每個 `MCPClient` 都須在連線前設定此選項。只要任何一個客戶端註冊了預設掛鈎，即使呼叫了 `disconnect()`，全域的 `SIGINT` 和 `SIGTERM` 監聽器仍會保留至程序結束。

停用掛鈎後，應用程式須自行關閉 MCP 連線。如果使用 Mastra 伺服器，請配合伺服器的關閉流程，在適當時機呼叫 `disconnect()`，讓尚在處理的請求可繼續使用客戶端直至完成。

## 使用自訂 `fetch` 在執行時處理身份驗證 {/* #using-custom-fetch-for-runtime-defined-authentication */}

連接 HTTP 伺服器時，可以提供自訂的 `fetch` 函數，在執行時處理身份驗證、攔截請求或執行其他自訂操作。例如，可在每次請求時更新權杖，或將傳入請求內的用戶憑證轉發至 MCP 伺服器。

自訂的 `fetch` 函數可接收第三個選用參數 `requestContext`，用來讀取當前請求的資料，例如中介軟件設定的驗證 Cookie，或執行 Agent 或 Tool 時傳入的持有者權杖。如果請求並非由 Tool 呼叫發出，例如 `listTools()` 的請求及其觸發的連線握手，`requestContext` 的值就是 `null`。如果 Tool 呼叫建立了連線，握手會收到該次呼叫的 `requestContext`，包括透過 `toolsFromDefinitions()` 或 `toolFromDefinition()` 重建的 Tool 在首次執行時建立連線，以及呼叫時重新連線的情況。握手後仍保持開啟的串流，例如由伺服器向客戶端傳送事件的串流，會沿用同一個 `requestContext`。客戶端透過這些串流回覆伺服器請求時也會沿用該參數，例如回覆要求輸入的請求。如果你的程式收到這些串流上的伺服器日誌或通知後自行發出請求，該請求的 `requestContext` 會是 `null`。

因此，如果伺服器會驗證每個請求，查找 Tool 和呼叫 Tool 時都須提供憑證。下例在 Tool 呼叫提供 `requestContext` 時轉發用戶的 Cookie，缺少此參數時（例如 `listTools()` 的請求）則傳送應用程式本身的權杖。所有沒有 `requestContext` 的請求都會附上這個權杖，因此伺服器應限制它只可用於查找 Tool，例如只允許列出 Tool。

提供 `fetch` 後，可以直接在自訂函數內處理請求設定和身份驗證，因此 `requestInit` 和 `authProvider` 均可省略。

```typescript
const mcpClient = new MCPClient({
  servers: {
    apiServer: {
      url: new URL('https://api.example.com/mcp'),
      fetch: async (url, init, requestContext) => {
        const headers = new Headers(init?.headers)
        if (requestContext) {
          // A tool call: forward the auth cookie from the incoming request
          const cookie = requestContext.get('cookie')
          if (cookie) {
            headers.set('cookie', cookie)
          }
        } else {
          // No requestContext, as in listTools(): a token the server only accepts for discovery
          headers.set('authorization', `Bearer ${process.env.MCP_DISCOVERY_TOKEN}`)
        }
        return fetch(url, { ...init, headers })
      },
    },
  },
})

// Use with an agent — requestContext is automatically forwarded
const agent = new Agent({
  id: 'my-agent',
  name: 'My Agent',
  instructions: 'You are a helpful assistant.',
  model: openai('gpt-5.4'),
  tools: await mcpClient.listTools(),
})

await agent.generate('Hello!', {
  requestContext: myRequestContext, // forwarded to the custom fetch
})
```

如果伺服器只接受個別用戶的憑證，啟動時請略過 `listTools()`。由持有獨立憑證的客戶端呼叫 [`listToolDefinitions()`](#listtooldefinitions)，建立並儲存 Tool 目錄。例如，可在建構步驟中透過 `requestInit` 設定靜態標頭。執行時再以 [`toolsFromDefinitions()`](#toolsfromdefinitions) 重建 Tool。每個重建後的 Tool 都會在首次呼叫時開啟連線，因此握手會帶上該次呼叫的 `requestContext`。

## 在自訂 `fetch` 內處理身份驗證失敗 {/* #handling-auth-failures-inside-custom-fetch */}

無法進行身份驗證時，自訂 `fetch` 不應以 `throw` 拋出例外。`tools/call` 等 JSON-RPC 請求使用 `POST`，SDK 會將非 2xx 回應當作錯誤回報給 `listTools()`、`tools/call` 等操作的呼叫方。如果 `fetch` 拋出例外，SDK 同樣會回報錯誤，但伺服器的狀態碼和回應內容會遺失。連接使用 2025-11-25 版協議的伺服器時，客戶端還會在握手後傳送不帶請求內容的 `GET`，開啟由伺服器向客戶端傳送事件的串流。因此，請檢查 `init.method`，不要假定請求一定帶有 `POST` 內容。長時間開啟的串流發生故障後會重新開啟，包括客戶端為 `resources.subscribe()` 開啟的 `subscriptions/listen` `POST` 串流，以及中斷的 `GET` 事件串流。未經身份驗證的 `subscriptions/listen` 串流可能反覆重連。請等候取得權杖，再轉發請求：

```typescript
async function waitForToken(timeoutMs = 5000): Promise<string | null> {
  // Replace with your token lookup. Return null if no token is available.
  return getAuthToken({ timeoutMs })
}

const mcpClient = new MCPClient({
  servers: {
    apiServer: {
      url: new URL('https://api.example.com/mcp'),
      fetch: async (url, init) => {
        const token = await waitForToken()
        if (!token) {
          // Forward the request without a token and let the server reject it.
          return fetch(url, init)
        }

        const headers = new Headers(init?.headers)
        headers.set('authorization', `Bearer ${token}`)
        return fetch(url, { ...init, headers })
      },
    },
  },
})
```

## 發送請求標頭 {/* #sending-request-headers */}

在 `requestInit` 設定靜態標頭。每個請求都會附上這些標頭，包括開啟 `subscriptions/listen` 串流的請求：

```ts
const client = new MCPClient({
  servers: {
    exampleServer: {
      url: new URL('https://your-mcp-server.com/mcp'),
      requestInit: {
        headers: {
          Authorization: 'Bearer your-token',
        },
      },
    },
  },
})
```

若標頭值會隨請求而變，請使用自訂 `fetch`。
