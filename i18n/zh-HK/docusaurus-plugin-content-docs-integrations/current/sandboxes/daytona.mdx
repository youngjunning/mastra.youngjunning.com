# Daytona

在隔離的 [Daytona](https://www.daytona.io) 雲端 Sandbox 執行指令。支援多種執行環境、資源設定、儲存卷、快照、串流輸出、Sandbox 重新連線、檔案系統掛載（S3、GCS）及網絡隔離。介面詳情請參閱 [WorkspaceSandbox 介面](/reference/workspace/sandbox)。

## 安裝 {/* #installation */}

```bash npm2yarn
npm install @mastra/daytona @daytona/sdk
```

可用以下三種方式之一設定 Daytona API 金鑰。

<Tabs>
  <TabItem value="shell-export" label="從 Shell 匯出">
    ```bash
    export DAYTONA_API_KEY=your-api-key
    ```
  </TabItem>

  <TabItem value="env-file" label=".env 檔案">
    ```bash
    DAYTONA_API_KEY=your-api-key
    ```
  </TabItem>

  <TabItem value="constructor" label="建構函式">
    ```typescript
    new DaytonaSandbox({ apiKey: 'your-api-key' })
    ```
  </TabItem>
</Tabs>

## 使用方法 {/* #usage */}

將 `DaytonaSandbox` 加入 Workspace，並指派給 Agent：

```typescript
import { Agent } from '@mastra/core/agent'
import { Workspace } from '@mastra/core/workspace'
import { DaytonaSandbox } from '@mastra/daytona'

const workspace = new Workspace({
  sandbox: new DaytonaSandbox({
    language: 'typescript',
    timeout: 120_000,
  }),
})

const agent = new Agent({
  id: 'code-agent',
  name: 'Code Agent',
  instructions: 'You are a coding assistant working in this workspace.',
  model: '__GATEWAY_ANTHROPIC_MODEL_SONNET__',
  workspace,
})

const response = await agent.generate(
  'Print "Hello, world!" and show the current working directory.',
)

console.log(response.text)
// I'll run both commands simultaneously!
//
// Here are the results:
//
// 1. **Hello, world!** — Successfully printed the message.
// 2. **Current Working Directory** — `/home/daytona`
//
// Both commands ran in parallel and completed successfully!
```

### 使用快照 {/* #with-a-snapshot */}

使用預先建立的快照，可省卻環境設定時間：

```typescript
const workspace = new Workspace({
  sandbox: new DaytonaSandbox({
    snapshot: 'my-snapshot-id',
    timeout: 60_000,
  }),
})
```

### 使用自訂映像及資源 {/* #custom-image-with-resources */}

使用自訂 Docker 映像，並指定資源配置：

```typescript
const workspace = new Workspace({
  sandbox: new DaytonaSandbox({
    image: 'node:20-slim',
    resources: { cpu: 2, memory: 4, disk: 6 },
    language: 'typescript',
  }),
})
```

### 臨時 Sandbox {/* #ephemeral-sandbox */}

執行一次性工作時，可在 Sandbox 停止後立即將其刪除：

```typescript
const workspace = new Workspace({
  sandbox: new DaytonaSandbox({
    ephemeral: true,
    language: 'python',
  }),
})
```

### 串流輸出 {/* #streaming-output */}

透過 `onStdout` 及 `onStderr` 回調即時接收指令輸出：

```typescript
await sandbox.executeCommand('bash', ['-c', 'for i in 1 2 3; do echo "line $i"; sleep 1; done'], {
  onStdout: chunk => process.stdout.write(chunk),
  onStderr: chunk => process.stderr.write(chunk),
})
```

兩個回調均可省略，亦可分別使用。

### 重連 {/* #reconnection */}

提供相同的 `id`，即可重新連接現有 Sandbox。重新連接後，檔案及狀態會保持不變：

```typescript
const sandbox = new DaytonaSandbox({ id: 'my-persistent-sandbox' })

// First session
await sandbox._start()
await sandbox.executeCommand('sh', ['-c', 'echo "session 1" > /tmp/state.txt'])
await sandbox._stop()

// Later — reconnects to the same sandbox
const sandbox2 = new DaytonaSandbox({ id: 'my-persistent-sandbox' })
await sandbox2._start()
const result = await sandbox2.executeCommand('cat', ['/tmp/state.txt'])
console.log(result.stdout) // "session 1"
```

如 Sandbox 已停止或已封存，系統會自動將其重新啟動。如 Sandbox 已失效（已銷毀或發生錯誤），則會建立新的 Sandbox。

### 檔案系統掛載 {/* #filesystem-mounting */}

將 S3 或 GCS 儲存貯體掛載為 Sandbox 內的本機目錄。

#### 透過 Workspace 掛載設定 {/* #via-workspace-mounts-config */}

最簡單的方法是在 Sandbox 啟動時自動掛載檔案系統：

```typescript
import { Workspace } from '@mastra/core/workspace'
import { DaytonaSandbox } from '@mastra/daytona'
import { GCSFilesystem } from '@mastra/gcs'
import { S3Filesystem } from '@mastra/s3'

const workspace = new Workspace({
  mounts: {
    '/s3-data': new S3Filesystem({
      bucket: process.env.S3_BUCKET!,
      region: 'auto',
      accessKeyId: process.env.S3_ACCESS_KEY_ID,
      secretAccessKey: process.env.S3_SECRET_ACCESS_KEY,
      endpoint: process.env.S3_ENDPOINT, // e.g. https://<account-id>.r2.cloudflarestorage.com
    }),
    '/gcs-data': new GCSFilesystem({
      bucket: process.env.GCS_BUCKET!,
      projectId: 'my-project-id',
      credentials: JSON.parse(process.env.GCS_SERVICE_ACCOUNT_KEY!),
    }),
  },
  sandbox: new DaytonaSandbox({ language: 'python' }),
})
```

Workspace 啟動時，檔案系統會自動掛載至指定路徑。之後，Sandbox 內執行的程式碼可像存取本機目錄一樣，存取 `/s3-data` 及 `/gcs-data` 內的檔案。

#### 臨時 S3 憑證 {/* #temporary-s3-credentials */}

使用臨時憑證時，必須將三個憑證值全部傳給 `S3Filesystem`。Daytona 會將工作階段權杖轉交 s3fs：

```typescript
import { Workspace } from '@mastra/core/workspace'
import { DaytonaSandbox } from '@mastra/daytona'
import { S3Filesystem } from '@mastra/s3'

const workspace = new Workspace({
  mounts: {
    '/s3-data': new S3Filesystem({
      bucket: process.env.S3_BUCKET!,
      region: process.env.S3_REGION ?? 'us-east-1',
      endpoint: process.env.S3_ENDPOINT,
      prefix: 'resource-123/thread-456/',
      accessKeyId: process.env.SCOPED_S3_ACCESS_KEY_ID!,
      secretAccessKey: process.env.SCOPED_S3_SECRET_ACCESS_KEY!,
      sessionToken: process.env.SCOPED_S3_SESSION_TOKEN!,
    }),
  },
  sandbox: new DaytonaSandbox({ language: 'python', ephemeral: true }),
})
```

啟動 Workspace 前，請向儲存服務 Provider 取得僅容許存取目標前綴的憑證。憑證的簽發方式視乎 Provider；Mastra 不會簽發憑證，亦不會限制憑證權限。`prefix` 只會選取目錄，不會強制執行授權。請驗證每個請求的身分及其資源與執行緒的存取權限，並為不同的安全範圍使用不同的 Sandbox。

臨時憑證會在開始掛載時載入，之後不會自動更新。主機端的憑證 Provider 函式亦不會更新現有掛載。請確保工作在憑證有效期內完成；日後執行工作時，應以新憑證建立新的 Sandbox。重新連接 Sandbox 不會更新其憑證。

憑證會上傳至私人目錄中只有擁有者可存取的檔案。啟動 s3fs 後，Daytona 會刪除用作暫存臨時憑證的檔案及目錄。常駐程式仍會在其環境中保留憑證，因此以同一使用者或 root 身分執行的 Sandbox 程式碼仍可能讀取憑證。切勿提供權限超出 Sandbox 所需範圍的憑證。使用長期憑證的掛載，會在 s3fs 需要密碼檔案期間保留該檔案。卸載及重新連接時的清理程序會先確認常駐程式已結束，才刪除檔案。如常駐程式仍在執行（包括掛載已移往一旁後），或無法確認其狀態，系統會保留檔案並記錄警告。日後卸載同一路徑時會再次嘗試刪除；刪除 Sandbox 則會移除所有剩餘檔案。

有前綴的檔案系統在初始化時，必須有權限列出該前綴。對 s3fs 而言，這類掛載可能還需要在準確的 `<prefix>/` 鍵下建立一個零位元組物件。請在掛載前建立這個目錄標記。啟動 s3fs 後，Daytona 會檢查已掛載目錄的中繼資料，但不會列出目錄內容；檢查逾時時間為 15 秒，再過 5 秒會強制終止。檢查失敗會回報掛載失敗。清理程序會嘗試卸載失敗的掛載；如有需要，會把卡住的掛載移往一旁，騰出原路徑以供重試。移走的舊掛載可能一直保留至 Sandbox 刪除。這項啟動檢查不能保證個別檔案可讀寫，亦不能保證常駐程式持續正常運作；請透過掛載路徑實際測試讀取及寫入。

### 網路隔離 {/* #network-isolation */}

限制出站網路存取：

```typescript
const workspace = new Workspace({
  sandbox: new DaytonaSandbox({
    networkBlockAll: true,
    networkAllowList: '10.0.0.0/8,192.168.0.0/16',
  }),
})
```

對套件登錄服務及託管 API 等 IP 位址可能改變的服務，請使用 `domainAllowList`：

```typescript
const workspace = new Workspace({
  sandbox: new DaytonaSandbox({
    networkBlockAll: true,
    domainAllowList: 'registry.npmjs.org,*.githubusercontent.com',
  }),
})
```

兩份允許清單都會在建立 Sandbox 時套用，並由 `clone()` 保留。如需在 Sandbox 啟動後更改政策，請使用底層 Daytona Sandbox：

```typescript
await sandbox.instance.updateNetworkSettings({
  domainAllowList: 'api.example.com',
})
```

### Secrets {/* #secrets */}

可注入憑證，而毋須向 Sandbox 內執行的程式碼披露原始值。先透過 Daytona 控制台或 SDK 為組織建立一次 [Daytona Secret](https://www.daytona.io/docs/en/secrets/)，再將環境變數名稱對應至 Secret 名稱：

```typescript
const workspace = new Workspace({
  sandbox: new DaytonaSandbox({
    secrets: {
      GITHUB_TOKEN: 'github-token',
    },
  }),
})
```

在 Sandbox 內，環境變數存放的是不透明佔位符。向該 Secret 容許的主機發送 HTTPS 請求時，Daytona 的出口代理會在請求標頭中以實際值取代佔位符，因此原始憑證不會進入 Sandbox。Secrets 在建立 Sandbox 時套用，並由 `clone()` 保留。

### 電腦操作（桌面） {/* #computer-use-desktop */}

透過 `computerUse` 啟用[電腦操作功能](/docs/sandbox/computer)，讓 Sandbox 支援截圖、滑鼠及鍵盤控制。Sandbox 用於 Workspace 時，Agent 會自動取得 `mastra_workspace_computer_*` Tool。

電腦操作預設停用。設定 `computerUse: true` 後，桌面程序（Xvfb、xfce4、x11vnc、noVNC）會在首次執行電腦操作時才啟動：

```typescript
const sandbox = new DaytonaSandbox({ computerUse: true })
await sandbox.start()

await sandbox.computer.leftClick(100, 200)
await sandbox.computer.type('hello')
const { data } = await sandbox.computer.screenshot() // PNG bytes

// Live desktop view via the noVNC preview link
const url = await sandbox.computer.streamUrl()
```

亦可傳入選項物件設定此功能。例如，直接管理 Daytona 程序時，可停用桌面自動啟動：

```typescript
const sandbox = new DaytonaSandbox({
  computerUse: { autoStart: false },
})

await sandbox.start()
await sandbox.daytona.computerUse.start()
```

如需使用 Daytona 專有的桌面 API（區域、壓縮截圖、螢幕錄影、無障礙樹），可[直接存取 SDK](#direct-sdk-access) 中的 `sandbox.daytona.computerUse`。

## 背景程序 {/* #background-processes */}

`DaytonaSandbox` 內置程序管理器，可啟動及管理背景程序。這些程序透過以工作階段為基礎的指令執行機制，在 Daytona 雲端 Sandbox 中運作。

```typescript
const sandbox = new DaytonaSandbox({ language: 'typescript' })
await sandbox.start()

// Spawn a background process
const handle = await sandbox.processes.spawn('node server.js', {
  env: { PORT: '3000' },
  onStdout: data => console.log(data),
})

// Interact with the process
console.log(handle.stdout)
await handle.sendStdin('input\n')
await handle.kill()
```

完整 API 請參閱 [`SandboxProcessManager` 參考文件](/reference/workspace/process-manager)。

## 掛載雲端儲存空間 {/* #mounting-cloud-storage */}

Daytona Sandbox 可掛載 S3 或 GCS 儲存貯體，讓 Sandbox 內的程式碼透過本機目錄存取雲端儲存空間。適用情況包括：

- 處理儲存在雲端儲存貯體的大型數據集
- 將輸出檔案直接寫入雲端儲存空間
- 在 Sandbox 工作階段之間共用數據

使用範例請參閱[檔案系統掛載](#filesystem-mounting)。

Daytona Sandbox 使用 FUSE（用戶空間檔案系統）掛載雲端儲存空間：

- **S3/R2**：透過 [s3fs-fuse](https://github.com/s3fs-fuse/s3fs-fuse) 掛載
- **GCS**：透過 [gcsfuse](https://github.com/GoogleCloudPlatform/gcsfuse) 掛載

如 Sandbox 映像尚未安裝所需的 FUSE 工具，系統會在掛載時自動安裝。

### S3 環境變數 {/* #s3-environment-variables */}

| 變數 | 說明 |
| - | - |
| `S3_BUCKET` | 儲存貯體名稱 |
| `S3_REGION` | AWS 地區；R2/MinIO 可使用 `auto` |
| `S3_ACCESS_KEY_ID` | 存取金鑰 ID |
| `S3_SECRET_ACCESS_KEY` | 私密存取金鑰 |
| `S3_ENDPOINT` | 端點 URL（僅適用於 S3 相容服務） |

### GCS 環境變數 {/* #gcs-environment-variables */}

| 變數 | 說明 |
| - | - |
| `GCS_BUCKET` | 儲存貯體名稱 |
| `GCS_SERVICE_ACCOUNT_KEY` | 服務帳戶金鑰 JSON（完整 JSON 字串，而非檔案路徑） |

### 透過快照減少冷啟動延遲 {/* #reducing-cold-start-latency-with-a-snapshot */}

預設會在首次掛載時透過 `apt` 安裝 `s3fs` 及 `gcsfuse`，因此增加啟動時間。若要省卻這段時間，可預先把它們建入 Daytona 快照，再透過 snapshot 選項傳入快照名稱。

**選項 1：宣告式映像建置**

```typescript
import { Daytona, Image } from '@daytona/sdk'

const template = Image.base('daytonaio/sandbox')
  .runCommands('sudo apt-get update -qq')
  .runCommands('sudo apt-get install -y s3fs')
  // gcsfuse requires the Google Cloud apt repository
  .runCommands(
    'sudo mkdir -p /etc/apt/keyrings && ' +
      'curl -fsSL https://packages.cloud.google.com/apt/doc/apt-key.gpg -o /tmp/gcsfuse-key.gpg && ' +
      'sudo gpg --batch --yes --dearmor -o /etc/apt/keyrings/gcsfuse.gpg /tmp/gcsfuse-key.gpg && ' +
      // Use gcsfuse-jammy for Ubuntu, gcsfuse-bookworm for Debian
      'echo "deb [signed-by=/etc/apt/keyrings/gcsfuse.gpg] https://packages.cloud.google.com/apt gcsfuse-jammy main" | sudo tee /etc/apt/sources.list.d/gcsfuse.list',
  )
  .runCommands('sudo apt-get update -qq && sudo apt-get install -y gcsfuse')

const daytona = new Daytona()

await daytona.snapshot.create(
  {
    name: 'cloud-fs-mounting',
    image: template,
  },
  { onLogs: console.log },
)
```

**選項 2：Dockerfile：**使用 [`Image.fromDockerfile()`](https://www.daytona.io/docs/typescript-sdk/image#fromdockerfile)

```dockerfile
FROM daytonaio/sandbox
RUN sudo apt-get update -qq
RUN sudo apt-get install -y s3fs
# Use gcsfuse-jammy for Ubuntu, gcsfuse-bookworm for Debian
RUN sudo mkdir -p /etc/apt/keyrings && curl -fsSL https://packages.cloud.google.com/apt/doc/apt-key.gpg -o /tmp/gcsfuse-key.gpg && sudo gpg --batch --yes --dearmor -o /etc/apt/keyrings/gcsfuse.gpg /tmp/gcsfuse-key.gpg && echo "deb [signed-by=/etc/apt/keyrings/gcsfuse.gpg] https://packages.cloud.google.com/apt gcsfuse-jammy main" | sudo tee /etc/apt/sources.list.d/gcsfuse.list
RUN sudo apt-get update -qq && sudo apt-get install -y gcsfuse
```

```typescript
import { Daytona, Image } from '@daytona/sdk'

const daytona = new Daytona()

await daytona.snapshot.create(
  {
    name: 'cloud-fs-mounting',
    image: Image.fromDockerfile('./Dockerfile'),
  },
  { onLogs: console.log },
)
```

然後在 Sandbox 設定中使用快照名稱：

```typescript
const workspace = new Workspace({
  mounts: {
    '/s3-data': new S3Filesystem({/* ... */}),
    '/gcs-data': new GCSFilesystem({/* ... */}),
  },
  sandbox: new DaytonaSandbox({ snapshot: 'cloud-fs-mounting' }),
})
```

## 直接存取 SDK {/* #direct-sdk-access */}

透過底層 Daytona `Sandbox` 實例，執行檔案系統、git 等 `WorkspaceSandbox` 介面未提供的操作：

```typescript
const daytonaSandbox = sandbox.instance

// Upload a file
await daytonaSandbox.fs.uploadFile(Buffer.from('hello'), '/tmp/hello.txt')

// Run git operations
await daytonaSandbox.git.clone('https://github.com/org/repo', '/workspace/repo')
```

如 Sandbox 尚未啟動，`instance` getter 會擲出 `SandboxNotReadyError`。

## Sandbox 建立模式 {/* #sandbox-creation-modes */}

`DaytonaSandbox` 會按提供的選項選擇建立模式：

| 選項 | 建立模式 |
| - | - |
| 已設定 snapshot | 以快照建立（`snapshot` 優先於 image） |
| 已設定 `image`，未設定 `snapshot` | 以映像建立（可配合 `resources`） |
| 兩者均未設定 | 預設以快照建立 |

只有設定 `image` 時才會套用資源配置。只傳入 `resources` 而未設定 `image` 不會產生效果。
