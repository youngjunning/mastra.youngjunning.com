# Fly.io Sprites

使用官方 `@fly/sprites` SDK，在可持久保存狀態的 [Fly.io Sprites](https://sprites.dev) 上執行指令。Sprite 是 Linux 虛擬機，檔案系統會在不同次執行之間保留，閒置時則會自動休眠。`SpritesSandbox` 按名稱取得或建立 Sprite，讓新進程重新連接後仍可存取原有檔案。執行指令時支援串流輸出、逾時和取消，亦可向背景進程傳送標準輸入及建立檢查點。介面詳情見 [WorkspaceSandbox 介面](/reference/workspace/sandbox)。

## 安裝 {/* #installation */}

```bash npm2yarn
npm install @mastra/sprites
```

:::note
由於 `@fly/sprites` SDK 要求使用 Node.js 24 或以上版本，`@mastra/sprites` 亦有同樣要求。
:::

你可用以下任何一種方法設定 Sprites API 憑證。

## 使用方法 {/* #usage */}

把 `SpritesSandbox` 加入 Workspace，再把該 Workspace 指派給 Agent。

```typescript
import { Agent } from '@mastra/core/agent'
import { Workspace } from '@mastra/core/workspace'
import { SpritesSandbox } from '@mastra/sprites'

const workspace = new Workspace({
  sandbox: new SpritesSandbox({
    id: 'mastra-project',
    // token read from SPRITES_TOKEN
  }),
})

const agent = new Agent({
  id: 'code-agent',
  name: 'Code Agent',
  instructions: 'You are a coding assistant working in this workspace.',
  model: '__GATEWAY_ANTHROPIC_MODEL_SONNET__',
  workspace,
})

const response = await agent.generate(
  'Print "Hello, world!" and show the current working directory.',
)

console.log(response.text)
```

### 重用 Sprite {/* #reusing-a-sprite */}

`id` 就是 Sprite 的名稱。呼叫 `start()` 時，`SpritesSandbox` 會查找同名的 Sprite，找到便重新連接，否則會建立一個。先前連線階段寫入的檔案仍會保留。

```typescript
const first = new SpritesSandbox({ id: 'mastra-project' })
await first.executeCommand('sh', ['-c', 'echo hello > notes.txt'])
await first.stop()

// Later, possibly in another process
const second = new SpritesSandbox({ id: 'mastra-project' })
const result = await second.executeCommand('cat', ['notes.txt'])
console.log(result.stdout) // hello
```

如果你的帳戶已有同名的 Sprite，系統便會重用它，因此請為項目選用獨有的名稱。若省略 `id`，系統會隨機產生名稱。

`spriteConfig`（記憶體、CPU、區域和儲存空間）只在建立 Sprite 時生效。

### 停止與銷毀 {/* #stopping-and-destroying */}

`stop()` 和 `destroy()` 各有以下作用。

* `stop()` 會終止這個實例啟動的背景進程並關閉 SDK 連接，Sprite 及其檔案系統則會保留。Sprite 閒置時會自行休眠，毋須手動暫停。
* `destroy()` 會永久刪除 Sprite 及其檔案系統，毋須先呼叫 `start()`。已不存在的 Sprite 會視為已刪除。

```typescript
const sandbox = new SpritesSandbox({ id: 'mastra-project' })

// Remove the Sprite when the project is finished
await sandbox.destroy()
```

### 檢查點 {/* #checkpoints */}

`snapshot()` 會把 Sprite 的當前狀態記錄為檢查點，並等待記錄完成。

```typescript
await sandbox.snapshot()
```

檢查點儲存在 Sprite 內，不能用來啟動另一個 Sandbox，亦不能用作另一個 Sandbox 的初始狀態。因此，`supportsCheckpoints` 的值是 `false`，而 `SpritesSandbox` 沒有實作 `clone()`。如要列出或還原檢查點，可透過 `sandbox.sprite` 使用 `@fly/sprites` SDK。

### 串流輸出 {/* #streaming-output */}

傳入 `onStdout` 和 `onStderr`，便可在有輸出時即時接收。

```typescript
await sandbox.executeCommand('npm', ['install'], {
  onStdout: data => process.stdout.write(data),
  onStderr: data => process.stderr.write(data),
  timeout: 120_000,
})
```

指令逾時或其 `abortSignal` 觸發時，指令會被終止，結果會顯示 `killed: true`。

## 背景進程 {/* #background-processes */}

`SpritesSandbox` 提供進程管理器，用來啟動和管理背景進程。每個進程都在獨立的 Sprites exec 連線階段執行，並支援從 stdin 接收輸入。

```typescript
const sandbox = new SpritesSandbox({ id: 'mastra-project' })
await sandbox.start()

const handle = await sandbox.processes.spawn('node server.js', {
  env: { PORT: '3000' },
  onStdout: data => console.log(data),
})

await handle.sendStdin('reload\n')
await handle.kill()
```

其他實例看不到某個 `SpritesSandbox` 實例啟動的進程。呼叫啟動這些進程的實例的 `stop()`，便會終止這些進程。

完整 API 見 [`SandboxProcessManager` 參考文件](/reference/workspace/process-manager)。

## 編輯器的 Provider {/* #editor-provider */}

在 `MastraEditor` 註冊 Provider，便可在執行時按已儲存的 Sandbox 配置建立實例。

```typescript
import { MastraEditor } from '@mastra/editor'
import { spritesSandboxProvider } from '@mastra/sprites'

const editor = new MastraEditor({
  sandboxes: { [spritesSandboxProvider.id]: spritesSandboxProvider },
})
```

如要了解如何註冊自訂 Sandbox Provider，請參閱 [Sandbox Provider 參考文件](/reference/editor/sandbox-provider)。
