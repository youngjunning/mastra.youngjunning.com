# Apple Container

透過 Apple 的 [`container`](https://github.com/apple/container) CLI，在本機 OCI Linux 容器中執行指令。Provider 會啟動一個長時間運行的容器，並用 `container exec` 執行 Workspace 指令。介面詳情請參閱 [WorkspaceSandbox 介面](/reference/workspace/sandbox)。

## 安裝 {/* #installation */}

```bash npm2yarn
npm install @mastra/apple-container
```

需要一部運行 macOS 26 或以上版本、已安裝 Apple `container` CLI 的 Apple 晶片 Mac。使用此 Provider 前，先啟動容器系統：

```bash
container system start
```

## 用法 {/* #usage */}

將 `AppleContainerSandbox` 加入 Workspace，再將該 Workspace 指派給 Agent：

```typescript
import { Agent } from '@mastra/core/agent'
import { Workspace } from '@mastra/core/workspace'
import { AppleContainerSandbox } from '@mastra/apple-container'

const workspace = new Workspace({
  sandbox: new AppleContainerSandbox({
    image: 'node:22-slim',
    volumes: {
      '/Users/me/project': '/workspace',
    },
    workingDirectory: '/workspace',
  }),
})

const agent = new Agent({
  id: 'dev-agent',
  name: 'Dev Agent',
  instructions: 'You are a coding assistant working in this workspace.',
  model: '__GATEWAY_ANTHROPIC_MODEL_SONNET__',
  workspace,
})

const response = await agent.generate('Run `node --version`.')
console.log(response.text)
```

## 環境變數 {/* #environment-variables */}

使用 `env` 設定容器層級的環境變數。也可以透過 `executeCommand` 選項，為個別指令傳入環境變數：

```typescript
const sandbox = new AppleContainerSandbox({
  image: 'node:22-slim',
  env: {
    NODE_ENV: 'development',
  },
})

await sandbox.executeCommand('node', ['-e', 'console.log(process.env.TASK_ID)'], {
  env: { TASK_ID: '42' },
})
```

## 綁定掛載 {/* #bind-mounts */}

使用 `volumes` 選項將主機目錄掛載到容器中：

```typescript
const sandbox = new AppleContainerSandbox({
  image: 'node:22-slim',
  volumes: {
    '/Users/me/project': '/workspace/project',
    '/Users/me/.npm': '/root/.npm',
  },
})
```

綁定掛載會在建立容器時生效。主機路徑必須在 Sandbox 啟動前已存在。

## 資源和平台選項 {/* #resource-and-platform-options */}

可以透過建構函式傳入 Apple container CLI 選項：

```typescript
const sandbox = new AppleContainerSandbox({
  image: 'node:22-slim',
  volumes: {
    '/Users/me/project': '/workspace',
  },
  cpus: 2,
  memory: '2G',
  platform: 'linux/arm64',
  readonlyRootfs: true,
  tmpfs: ['/tmp'],
})
```

這些選項只會在建立新容器時生效。如果 Sandbox 重新連接到同名的現有容器，須銷毀並重新建立 Sandbox，才能套用已更改的運行時選項。
Apple 的 `--tmpfs` 只接受 `/tmp` 這類容器路徑，不接受 `/tmp:rw,size=256m` 這類 Docker 格式的設定。
啟用 `readonlyRootfs` 時，請確保 `workingDirectory` 指向映像檔提供的路徑或綁定掛載路徑。亦支援可寫入的 tmpfs。

## 安全模型 {/* #security-model */}

`AppleContainerSandbox` 透過主機上的 Apple `container` 服務運行本機容器。建構函式選項應視為可信任的伺服器端設定：

* `volumes`、`mounts` 和 `publishedSockets` 可能讓容器內的程式碼存取主機路徑。
* `publishedPorts` 可能向主機或網絡開放容器內的服務。如只需本機存取，請綁定至 `127.0.0.1`。
* `ssh` 會轉發主機的 SSH Agent socket。
* `capAdd` 和 `virtualization` 會擴大容器內程式碼可執行的操作。
* `containerBinary` 是供可信任程式碼使用、只能在建構函式中設定的特殊選項，不屬於可序列化的編輯器 Provider 設定結構。

只授予工作負載所需的掛載和功能。只有現有容器帶有與 Sandbox ID 相符的 Mastra 所有權標籤，才會重新連接。此 Provider 建立的容器亦帶有設定雜湊標籤；如該標籤存在，而映像檔、指令、掛載、連接埠、功能或工作目錄等不可變的運行時選項已改變，重新連接便會失敗。

## 限制 {/* #limitations */}

`AppleContainerSandbox` 透過 `executeCommand()` 支援在 Workspace 執行前台指令。目前尚未提供用於背景程序或 LSP 工作階段的 `SandboxProcessManager`。



## 重連 {/* #reconnection */}

`AppleContainerSandbox` 會檢查指定名稱的容器，以決定如何重新連接。呼叫 `start()` 時：

* 如容器正在運行，便會重用。
* 如容器已停止，便會重新啟動。
* 如容器不存在，便會用已設定的映像檔建立。
* 如同名容器沒有相符的 Mastra 所有權標籤，操作會失敗，不會接管該容器。
* 如 Mastra 擁有的容器帶有設定雜湊標籤，但標籤與不可變的運行時選項不符，操作會失敗，不會重用該容器。

```typescript
const sandbox = new AppleContainerSandbox({ id: 'persistent-sandbox' })
await sandbox.start()

const sandbox2 = new AppleContainerSandbox({ id: 'persistent-sandbox' })
await sandbox2.start()
```

## 編輯器 Provider {/* #editor-provider */}

在 `MastraEditor` 中註冊此 Provider，以還原已儲存的 Sandbox 設定：

```typescript
import { MastraEditor } from '@mastra/editor'
import { appleContainerSandboxProvider } from '@mastra/apple-container'

const editor = new MastraEditor({
  sandboxes: {
    [appleContainerSandboxProvider.id]: appleContainerSandboxProvider,
  },
})
```
