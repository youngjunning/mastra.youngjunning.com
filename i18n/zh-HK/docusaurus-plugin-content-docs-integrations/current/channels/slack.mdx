# Slack

Mastra 可以透過兩種方式整合 Slack。

* **Agent 的 Tool** 讓 Agent 在 Slack 執行操作，例如讀取對話或發送訊息。
* **與 Agent 對話**讓用戶在 Slack 頻道的訊息串內或以私人訊息聯絡 Agent。每收到一則訊息，Mastra 都會執行 Agent，並將回覆以串流方式傳回 Slack。Slack 轉接器會處理 Slack AI 狀態提示和互動卡片。

[Mastra Connect](/docs/mastra-platform/connect) 可以設定這兩種整合，並將 Slack 憑證保存在 Mastra 平台。若要提供 Agent 對話功能，你亦可自行建立和管理 Slack 應用程式。

## 使用 Connect {/* #connect */}

開始前，請按 [Connect 設定指引](/docs/mastra-platform/connect#get-started)安裝 `@mastra/connect`，並完成平台項目的設定。

Slack Tool 和 Slack 對話功能各自使用獨立的連線和憑證。

* `slack` 授權 Agent 的 Tool 存取 Slack Workspace。
* `slack-channels` 保存 Agent 對話功能所需的應用程式設定權杖。

如需同時使用兩項功能，請加入兩個連線。

### 與 Agent 對話 {/* #agent-chat */}

Slack 對話功能使用應用程式設定權杖，讓 Mastra 為每個 Agent 建立及管理一個 Slack 應用程式。這個流程不會使用你自行建立的應用程式，包括按[自行設定](#self-managed-setup)指引建立的 Slack 應用程式。

伺服器需要一個 Slack 可連線的公開網址，以接收 webhook 請求和 OAuth 回調。Mastra 平台會提供此網址。如在其他環境託管，請將 `MASTRA_SERVER_URL` 設為伺服器的公開網址。在本機開發時，請使用可從公網連線的 HTTPS 隧道。

1. 開啟 [Slack 應用程式管理頁面](https://api.slack.com/apps)，然後前往 **Your App Configuration Tokens**。

2. 為準備運行 Agent 的 Slack Workspace 產生應用程式設定權杖。

3. 執行 `mastra connect add slack-channels` 並完成授權程序。平台會保存並輪換設定憑證。

4. 將 [`channels()`](/reference/connect/channels) 的回傳值傳入 `Mastra` 建構函式，註冊 Slack 頻道 Provider 和相關路由。

   ```typescript title="src/mastra/index.ts"
   import { Mastra } from '@mastra/core'
   import { channels } from '@mastra/connect'
   import { assistant } from './agents/assistant'

   export const mastra = new Mastra({
     agents: { assistant },
     channels: await channels({ providers: ['slack'] }),
   })
   ```

   `channels()` 內的 `slack` 鍵對應 `slack-channels` 連線。

5. 啟動 Mastra 應用程式。

6. 在 Studio 將 Slack 頻道連接至 Agent。Mastra 會建立 Slack 應用程式並回傳授權網址。開啟該網址，選擇 Slack Workspace，再批准機械人所要求的權限。

[預設 Slack 應用程式清單](/reference/channels/slack-provider#default-manifest)列出所需的權限範圍及事件訂閱。

## 自行設定 Slack 應用程式 {/* #self-managed-setup */}

如需直接管理用於 Agent 對話的 Slack 應用程式，可以自行建立應用程式，並將憑證存放在 Mastra 環境。

### 安裝 {/* #installation */}

安裝 Chat SDK 提供的 Slack 轉接器。

```bash npm2yarn
npm install @chat-adapter/slack
```

在 Agent 的 `channels.adapters` 物件加入 `createSlackAdapter()`。

```typescript title="src/mastra/agents/your-agent.ts"
import { Agent } from '@mastra/core/agent'
import { createSlackAdapter } from '@chat-adapter/slack'

export const yourAgent = new Agent({
  id: 'your-agent',
  name: 'Your Agent',
  instructions: 'Help people plan tasks, answer questions, and coordinate work in Slack.',
  model: '__GATEWAY_ANTHROPIC_MODEL_OPUS__',
  channels: {
    adapters: {
      slack: createSlackAdapter(),
    },
  },
})
```

### 建立 Slack 應用程式 {/* #create-a-slack-app */}

要連接 Agent，請在準備運行 Agent 的 Slack Workspace 建立 Slack 應用程式。應用程式會決定 Agent 在 Slack 的顯示方式、可用功能和接收的事件。

本指引使用[應用程式清單](https://docs.slack.dev/app-manifests/configuring-apps-with-app-manifests/#creating_manifests)自動產生 Slack 應用程式的設定。要將 Agent 加到自己的 Slack Workspace，這是最快的方法。本指引不涵蓋其他 Slack Workspace 安裝 Agent 時使用的平台 OAuth 流程。

按以下步驟從清單建立 Slack 應用程式。

1. 開啟 [api.slack.com/apps](https://api.slack.com/apps)。
2. 選擇 **Create an app**。
3. 選擇 **From a manifest**。
4. 選擇 Agent 要運行所在的 Slack Workspace。
5. 貼上下方的清單，然後選擇 **Create**。Slack 支援 JSON 和 YAML，請按建立應用程式視窗所顯示的格式選擇相應分頁。

清單會套用以下設定。

* `display_information.name` 和 `features.bot_user.display_name` 設定 Agent 在 Slack 顯示的名稱。名稱可隨時修改，更改名稱或權限後記得重新安裝應用程式。
* `app_home.messages_tab_enabled` 和 `app_home.messages_tab_read_only_enabled` 讓用戶可在 Slack 應用程式的 **Messages** 分頁發送私人訊息。
* `always_online` 讓 Slack 機械人帳戶一直顯示為在線。
* `oauth_config.scopes.bot` 讓機械人在已加入的頻道發佈和讀取訊息，亦涵蓋提及、私人訊息和查詢用戶所需的權限。
* `event_subscriptions` 指定 Slack 要向 webhook 發送的訊息事件。
* `interactivity` 啟用互動卡片，並指定 Slack 將卡片操作發送到哪個網址。

建立應用程式後，開啟 **Install App**，選擇 **Install to Workspace**，再批准應用程式要求的權限。

### 設定 Slack 憑證 {/* #set-slack-credentials */}

在 Mastra 設定 Slack 憑證，讓 Mastra 可以驗證 Slack 的請求，並將訊息傳回 Slack。

從 Slack 應用程式設定的以下位置複製憑證。

* **Basic Information** > **App Credentials** > **Signing Secret**
* **OAuth & Permissions** > **Bot User OAuth Token**

將複製的值設為 Mastra 環境的變數。

```bash title=".env"
SLACK_SIGNING_SECRET=your-signing-secret
SLACK_BOT_TOKEN=xoxb-your-bot-token
```

Mastra 會自動讀取這些環境變數。

### 設定 webhook 路由 {/* #configure-the-webhook-route */}

Slack 透過 webhook 將頻道活動通知 Mastra。當有新訊息、提及或用戶選取互動卡片等事件時，Slack 會呼叫 webhook 的 HTTP 端點。

Mastra 會自動為 Agent 註冊以下 Slack webhook 路由。

```text
/api/agents/<YOUR-AGENT-ID>/channels/slack/webhook
```

將 Mastra 伺服器的公開網址接上已產生的路由，便可組成 webhook 網址。

```text
https://<YOUR-PUBLIC-URL>/api/agents/<YOUR-AGENT-ID>/channels/slack/webhook
```

Slack 無法向 `localhost` 發送事件。在本機開發時，請讓 Mastra 開發伺服器保持運行，透過隧道將 `http://localhost:4111` 開放予外部連線，再到 Slack 儲存請求網址。

本機開發可用 `cloudflared` 或 `ngrok` 建立隧道。

```bash npm2yarn
npx cloudflared tunnel --url http://localhost:4111
```

將 `<YOUR-PUBLIC-URL>` 換成隧道產生的主機名稱。以下是一個例子。

```text
https://abc123.trycloudflare.com/api/agents/your-agent/channels/slack/webhook
```

按以下步驟更新 Slack 的請求網址。

1. 在 Slack 應用程式設定開啟 **Event Subscriptions**。
2. 將 **Request URL** 改為完整的 webhook 網址。
3. 選擇 **Save Changes**。
4. 開啟 **Interactivity & Shortcuts**。
5. 將 **Request URL** 改為同一個 webhook 網址。
6. 選擇 **Save Changes**。
7. 如 Slack 要求重新安裝應用程式，請開啟 **OAuth & Permissions**，再選擇 **Reinstall to Workspace**。

### 在 Slack 測試對話 {/* #try-it-in-slack */}

在 Slack 開啟與機械人的私人對話，發送一則訊息。清單已包含 `message.im` 事件訂閱和 `im:*` 權限範圍，因此可使用私人訊息。

要在頻道使用 Agent，請先邀請 Slack 機械人加入該頻道。

```text
/invite @your-bot-name
```

然後在頻道提及機械人。

```text
@your-bot-name What can you help me with?
```

Agent 會在同一個訊息串回覆。回覆內容視乎 Agent 所用的模型、指令、記憶和 Tool 設定。

## 認證及存取控制 {/* #authentication */}

Slack 轉接器沒有內置的獲准用戶名單。安裝應用程式後，Slack Workspace 內任何人都可向 Agent 發送私人訊息，或在機械人已加入的頻道提及它。每個 Slack 請求均會以簽署密鑰驗證。webhook 每收到一則有效訊息，Mastra 都會執行 Agent。

存取權主要透過頻道的成員資格控制。機械人只會收到私人訊息和獲邀加入的頻道所發出的事件，因此機械人加入的頻道決定了哪些用戶可透過頻道聯絡它。只邀請機械人加入容許它回覆的頻道。如要撤銷某個頻道的存取權，請將機械人移出該頻道。

如要更仔細地控制存取權，可按發送者的身分判斷。每個請求的頻道[請求上下文](#request-context)均包含發送者的 Slack 用戶 ID。你可以在輸入處理器或 Tool 讀取該 ID，在 Agent 執行操作前決定是否批准個別用戶存取。

### 伺服器認證 {/* #server-authentication */}

Slack webhook 路由豁免 Mastra 的[伺服器認證](/docs/auth/overview)。由於 Slack 無法發送 Bearer 權杖，Mastra 會將頻道 webhook 註冊為公開路由，並以 Slack 簽署密鑰驗證每個請求。即使啟用 [`MastraAuthSimple`](/docs/auth/simple-auth) 等認證 Provider，其餘 API 仍受伺服器認證保護，webhook 路由則繼續使用簽署密鑰。如自行管理 Slack 應用程式，請保持 `SLACK_SIGNING_SECRET` 已設定，讓轉接器拒絕未經 Slack 簽署的請求。

### 外部頻道 {/* #external-channels */}

[Slack Connect](https://slack.com/connect) 共享頻道可讓其他 Slack Workspace 的成員加入對話。如有 Slack Workspace 成員將機械人加入共享頻道，該頻道內所有人都可與 Agent 對話，包括機構以外的成員。凡可聯絡 Agent 的人，亦可接觸 Agent 能存取的 Tool 和資料。

將機械人加入共享或外部頻道，等同向該頻道的參與者授予 Agent 的存取權。加入之前，請確認 Agent 能存取的 Tool 和資料可安全地向外部成員開放。如需限制 Agent 回覆的對象，請按發送者的用戶 ID 控制存取。

## 請求上下文 {/* #request-context */}

每收到一則訊息，Mastra 都會將頻道上下文物件放入[請求上下文](/docs/server/request-context)的 `channel` 鍵。物件記錄發送者在 Slack 的顯示名稱及用戶 ID、機械人本身的身分，還有訊息來源詳情。你可在輸入處理器或 Tool 讀取它，以辨識用戶或按對話類型採用不同的處理方式。

```typescript title="src/mastra/tools/whoami.ts"
import { createTool } from '@mastra/core/tools'
import type { ChannelContext } from '@mastra/core/channels'
import { z } from 'zod'

export const whoami = createTool({
  id: 'whoami',
  description: 'Return the Slack identity of the current user',
  inputSchema: z.object({}),
  execute: async (_input, context) => {
    const channel = context?.requestContext?.get('channel') as ChannelContext | undefined

    return {
      platform: channel?.platform,
      userId: channel?.userId,
      userName: channel?.userName,
      isDM: channel?.isDM,
    }
  },
})
```

頻道上下文包含以下欄位。

* `botMention`、`botUserId` 和 `botUserName` 標示機械人在 Slack 的身分。
* `channelId` 和 `threadId` 標示收到訊息的 Slack 頻道和訊息串。
* `isDM` 表示訊息是否屬於私人訊息。
* `platform` 是平台識別碼。這個轉接器的值為 `slack`。
* `userId` 和 `userName` 分別是發送者的 Slack 用戶 ID 和顯示名稱。

Mastra 亦會將這些資料轉成一則簡短的系統訊息，讓 Agent 知道所在的平台和自身身分，以及對話是在私人訊息還是公開頻道進行。如要更改這個行為，請參閱頻道概覽內的[訊息串上下文](/docs/channels#thread-context)。

## 正式環境部署 {/* #production-deployment */}

如自行管理 Slack 應用程式，部署 Mastra 伺服器時，請將 Slack 應用程式設定內的兩個請求網址都更新為正式環境的 webhook 網址。本機開發所用的隧道網址是臨時的，隧道重新啟動後便會變更。

在無伺服器平台使用頻道整合時，可能需要設定 `waitUntil` 和共享的發佈／訂閱機制，讓背景回覆和訊息串租約可跨短暫運行的實例正常運作。詳情見頻道概覽的[無伺服器部署](/docs/channels#serverless-deployment)。

### 閒置伺服器 {/* #idle-servers */}

沒有流量時，平台伺服器會縮減至閒置狀態，Slack 整合仍可運作。下一次有提及或私人訊息等事件時，Slack 發送的 webhook 請求會喚醒伺服器，讓它恢復處理請求。閒置後的首次回覆可能因啟動而稍慢。Slack 預期在 3 秒內收到 `200` 確認回應，投遞失敗或逾時時最多會重試三次。冷啟動若耗時過長，Agent 可能要等 Slack 重試才會回覆。伺服器保持運行期間，後續訊息會以正常速度獲得回覆。
