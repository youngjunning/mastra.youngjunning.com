# GitHub

你可以用兩種方式將 GitHub 整合到 Mastra：

- **Agent Tool** 讓 Agent 經由 [Mastra Connect](/docs/mastra-platform/connect) 處理程式碼倉庫、議題、Pull Request、發佈版本及工作流程執行紀錄。
- **[Pull Request 訊號](#pull-request-signals)**讓 Agent 追蹤 Pull Request（PR），並在 PR 有變動時作出回應。

## 連接設定 {/* #connect */}

開始前，請按照 [Connect 設定步驟](/docs/mastra-platform/connect#get-started) 安裝 `@mastra/connect`，並設定你在 Mastra 平台上的專案。Connect 將 GitHub 憑證保留在 Mastra 平台，你的應用程式本身不會儲存這些憑證。

## Pull Request 訊號 {/* #pull-request-signals */}

`@mastra/github-signals` Provider 會輪詢已訂閱的 PR。如有相關活動，就會向 Agent 的對話串發送[通知訊號](/docs/signals/notifications)。Provider 在你自己的基礎設施上運行，經 GitHub CLI 存取 GitHub，毋須建立 Connect 連線。

### 安裝 {/* #installation */}

安裝 GitHub Signals 及此示例所用的記憶功能套件：

```bash npm2yarn
npm install @mastra/github-signals @mastra/libsql @mastra/memory
```

### 使用條件 {/* #prerequisites */}

使用 GitHub Signals 前，請確認已符合以下條件：

- 使用支援記憶和通知功能的 Mastra 儲存適配器。Provider 會將每項訂閱記錄在對話串的元資料中，因此必須先建立對話串。
- 可透過 `PATH` 執行 `gitcrawl`，並已設定好對目標倉庫的存取權限。Provider 會執行 `gitcrawl sync` 並讀取其 SQLite 資料庫。
- 可透過 `PATH` 執行 `sqlite3`。
- 已安裝 [GitHub CLI](https://cli.github.com/) 並完成身份驗證。Provider 在通知 Agent 前，會按 `gh api` 的實際回應核對倉庫權限及 GitHub App 的擁有人。

預設情況下，擁有 `admin`、`maintain` 或 `write` 權限的用戶發表留言時，可以觸發通知。CodeRabbit 及 Devin 機械人的留言亦明確獲准觸發通知。

核對機械人的授權時，Provider 會先檢查登入名稱是否與 `ignoredBots` 的項目完全相符，並忽略英文字母的大小寫。未列入忽略名單的機械人符合以下任何一項條件即可觸發通知：機械人列於 `authorizedBots`；GitHub App 由用戶擁有，而該用戶的倉庫權限列於 `authorizedPermissions`；或 GitHub App 與倉庫同屬一個組織。預設獲授權的權限為 `admin`、`maintain` 和 `write`。

如查詢 GitHub App 擁有人失敗、所需資料無法存取、回應格式有誤，或系統不支援該查詢，Provider 便會拒絕該機械人的留言。成功的查詢結果會快取 24 小時，失敗的結果不會快取。

### Agent 及訂閱設定 {/* #agent-and-subscription */}

建立一個 `GithubSignals` 實例，並在 Agent 上註冊。然後在 Mastra 實例上註冊該 Agent 及一個儲存適配器：

```typescript title="src/mastra/index.ts"
import { Agent } from '@mastra/core/agent'
import { Mastra } from '@mastra/core/mastra'
import { Memory } from '@mastra/memory'
import { GithubSignals } from '@mastra/github-signals'
import { LibSQLStore } from '@mastra/libsql'

export const githubSignals = new GithubSignals()

export const devAgent = new Agent({
  id: 'dev-agent',
  name: 'Development Agent',
  instructions: 'Triage pull request activity and help resolve issues.',
  model: '__GATEWAY_OPENAI_MODEL__',
  memory: new Memory(),
  signals: [githubSignals],
})

export const mastra = new Mastra({
  agents: { devAgent },
  storage: new LibSQLStore({
    id: 'mastra-storage',
    url: 'file:./mastra.db',
  }),
})
```

Agent 在記憶功能中建立對話串後，你便可以為該對話串訂閱 PR。如果只需留意程式碼修訂、由獲授權作者發表的最新 PR 留言，以及可偵測的審查討論狀態變動，請選用 `review` 模式：

```typescript
await githubSignals.subscribeThreadToPR({
  threadId: 'thread-123',
  resourceId: 'user-123',
  pr: {
    owner: 'acme',
    repo: 'web-app',
    number: 42,
  },
  mode: 'review',
})
```

Provider 會立即同步 PR、儲存訂閱，並開始每五分鐘輪詢一次。如需更改輪詢間隔，可在 `GithubSignals` 的建構函數中設定 `pollIntervalMs`。程序重新啟動後，為每項已持久儲存的對話串訂閱呼叫 `startPollingForThread()`，便可恢復輪詢。

每個對話串同一時間只能有一項 GitHub Signals 訂閱。如為同一對話串訂閱另一個 PR，新訂閱會取代原有訂閱。

### 訂閱模式 {/* #subscription-modes */}

GitHub Signals 提供兩種訂閱模式：

- `review`：追蹤 PR 來源分支最新提交的變動、由獲授權作者發表的最新 PR 留言，以及可偵測的審查討論狀態變動，包括所有審查討論均已解決的情況。
- `working`：追蹤 Provider 能偵測到且可觸發通知的所有 PR 活動。包含留言內容的通知仍須通過現有的授權檢查。省略 `mode`，或已儲存的訂閱沒有有效模式時，便會預設採用此模式。

下表顯示各模式遇到不同 PR 活動時的處理方式：

| PR 活動 | `working` | `review` |
| - | - | - |
| 首次取得 PR 狀態 | 發送初始狀態通知 | 儲存所有游標，毋須發送通知。如 PR 已關閉或合併，則發送通知並移除訂閱 |
| 有新提交或強制推送 | 最新留言的作者獲授權時發送通知 | 即使沒有留言作者，亦會發送通知 |
| 最新 PR 留言有更新，而作者已獲授權 | 發送通知 | 發送通知 |
| 偵測到審查討論狀態有變 | 仍有未解決的討論時發送通知 | 發送通知，包括所有審查討論均已解決時 |
| 持續整合檢查開始、失敗或恢復 | 發送通知 | 記錄新狀態，毋須發送通知 |
| 出現或解決合併衝突 | 發送通知 | 記錄新狀態，毋須發送通知 |
| 其他可觸發通知的 PR 整體狀態變動 | 通過相關授權檢查後發送通知 | 記錄新狀態，毋須發送通知 |
| PR 在未合併的情況下關閉 | 發送通知並保留訂閱 | 發送通知並移除訂閱 |
| PR 重開 | 發送通知 | 不會發送通知，因為 PR 關閉時已移除訂閱 |
| PR 合併 | 發送通知並移除訂閱 | 發送通知並移除訂閱 |

審查模式採用 `gitcrawl` 提供的最新 PR 留言，而快照不會區分 PR 的一般討論和針對個別程式碼行的審查留言。留言通知會載有留言內容，因此作者必須獲授權。審查狀態通知只會載有 Provider 產生的狀態摘要，毋須核對作者的權限。

審查狀態游標會記錄尚未解決的審查討論串數目，以及當中最新一個討論串的時間戳。當數目減至零時會報告這項變動，但無法報告已解決討論串中的新回覆。

如訂閱時已知 PR 已關閉或合併，Provider 不會記錄訂閱，亦不會發送活動通知。其餘情況下，審查模式會儲存首份可用而且顯示 PR 仍然開啟的快照，不會發送通知。即使訂閱時未能取得快照，要到稍後輪詢才首次取得快照，亦按此方式處理。如輪詢取得的首份可用快照或之後的快照顯示 PR 已關閉或合併，Provider 會發送結束通知並移除訂閱。PR 日後重開時，須再次訂閱才能繼續追蹤。

### 訂閱 Tool {/* #subscription-tools */}

Provider 會在 Agent 加入 `github_subscribe_pr` 及 `github_unsubscribe_pr` 兩個 Tool。訂閱時可傳入 `mode`：

```json
{
  "owner": "acme",
  "repo": "web-app",
  "number": 42,
  "mode": "review"
}
```

省略 `mode` 便會採用 `working` 模式。如只需查看一次 PR，毋須訂閱。

### MastraCode 命令 {/* #mastracode-commands */}

在 MastraCode 中，可用 PR 編號、`owner/repo#number` 或完整 GitHub PR 網址指定 PR。`--mode` 選項與模式值之間要留一個空格：

```text
/github subscribe 42 --mode review
/github acme/web-app#42 --mode working
/github unsubscribe 42
/github debug
```

MastraCode 不接受 `--mode=review` 的寫法，也不接受缺少模式值、重複指定模式值或無法識別的模式。取消訂閱時不可使用模式選項。`/github debug` 會顯示已儲存的模式。如舊有訂閱欠缺模式值，或模式值無效，則會顯示為 `working`。
