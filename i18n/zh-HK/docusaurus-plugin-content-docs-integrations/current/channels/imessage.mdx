# iMessage

iMessage 頻道讓 Mastra Agent 接收 iMessage 的私人訊息和群組訊息。[Photon](https://app.photon.codes) 和 [Linq](https://linqapp.com) 各自維護連接 Mastra 與 iMessage 的適配器。Mastra 負責連接 Agent 和適配器，並提供 Webhook 路由。開通電話號碼、設定憑證及登記 Webhook 的步驟載於各適配器的文件。

## 選擇適配器 {/* #choose-an-adapter */}

兩款適配器接駁 Mastra 的方法相同，先選擇你要使用的 Provider。

* **Photon** 提供託管及自行託管的 iMessage 服務，支援 Webhook，亦可透過[網關監聽器](#gateway-listener)保持連線並串流傳送訊息。
* **Linq** 提供託管的 iMessage、RCS 和 SMS API，以 Webhook 接收事件，並支援 Tapback 回應和媒體內容的雙向對應。

## 安裝適配器 {/* #install-the-adapter */}

<Tabs groupId="imessage-provider">
  <TabItem value="photon" label="Photon">
    安裝 Photon iMessage 適配器。

    ```bash npm2yarn
    npm install @photon-ai/chat-adapter-imessage
    ```
  </TabItem>

  <TabItem value="linq" label="Linq">
    安裝 Linq Chat SDK 適配器。

    ```bash npm2yarn
    npm install @linqapp/chat-sdk-adapter
    ```
  </TabItem>

## 設定 Agent {/* #agent-configuration */}

在 Agent 的 `channels.adapters` 物件內呼叫適配器的工廠函數。

<Tabs groupId="imessage-provider">
  <TabItem value="photon" label="Photon">
    ```typescript title="src/mastra/agents/imessage-agent.ts"
    import { Agent } from '@mastra/core/agent'
    import { createiMessageAdapter } from '@photon-ai/chat-adapter-imessage'

    export const imessageAgent = new Agent({
      id: 'imessage-agent',
      name: 'iMessage Agent',
      instructions: 'Answer questions and help with tasks over iMessage.',
      model: '__GATEWAY_OPENAI_MODEL__',
      channels: {
        adapters: {
          imessage: {
            adapter: createiMessageAdapter(),
            toolDisplay: 'text',
          },
        },
        threadContext: { maxMessages: 0 },
      },
    })
    ```

    Mastra 通常會在群組對話首次提及 Agent 時查詢平台的對話記錄。Photon 適配器無法執行此查詢，因此請設為 `threadContext: { maxMessages: 0 }`，略過這個步驟。
  </TabItem>

  <TabItem value="linq" label="Linq">
    ```typescript title="src/mastra/agents/imessage-agent.ts"
    import { Agent } from '@mastra/core/agent'
    import { createLinqAdapter } from '@linqapp/chat-sdk-adapter'

    export const imessageAgent = new Agent({
      id: 'imessage-agent',
      name: 'iMessage Agent',
      instructions: 'Answer questions and help with tasks over iMessage.',
      model: '__GATEWAY_OPENAI_MODEL__',
      channels: {
        adapters: {
          imessage: {
            adapter: createLinqAdapter({
              apiKey: process.env.LINQ_API_KEY!,
              signingSecret: process.env.LINQ_WEBHOOK_SECRET!,
            }),
            toolDisplay: 'text',
          },
        },
      },
    })
    ```

    `createLinqAdapter()` 直接接收憑證。`apiKey` 是你的 Linq API 密鑰，`signingSecret` 則由 [Webhook 訂閱](#webhook-url)提供。Linq 適配器能夠擷取對話記錄，因此可沿用 `threadContext` 的預設行為。
  </TabItem>
</Tabs>

在 Mastra 實例中登記 Agent。

```typescript title="src/mastra/index.ts"
import { Mastra } from '@mastra/core'
import { imessageAgent } from './agents/imessage-agent'

export const mastra = new Mastra({
  agents: { imessageAgent },
})
```

使用 `imessage` 作為適配器的鍵名。Mastra 會按這個鍵名設定 Webhook 路徑和 `requestContext` 中的 `platform` 值。

iMessage 沒有可用來批准或拒絕 Tool 呼叫的互動卡片，因此兩款適配器都需要設定 `toolDisplay: 'text'`，在訊息中以文字說明 Tool 呼叫。Photon 不支援顯示卡片。Linq 會將卡片轉為純文字，只保留按鈕標籤，無法觸發相應操作。

:::warning

純文字訊息無法提交審批決定。設有 `requireApproval: true` 的 Tool 會暫停執行，直至有人透過介面或 API 明確提交批准或拒絕，例如在 Studio 內操作。只有在其他途徑可以處理審批時，才應在 iMessage Agent 使用需要審批的 Tool。詳見 [Tool 審批](/docs/channels#tool-approval)。

:::

## 設定適配器 {/* #adapter-setup */}

<Tabs groupId="imessage-provider">
  <TabItem value="photon" label="Photon">
    請按 [Photon iMessage 適配器文件](https://github.com/photon-hq/vercel-chat-adapter-imessage)完成 iMessage 專用設定，包括開通號碼、設定託管或自行託管模式，以及登記 Webhook。適配器會按你設定的環境變數選擇模式。

    如使用託管服務，請在 [app.photon.codes](https://app.photon.codes) 建立項目，並以項目憑證設定以下環境變數。

    ```bash title=".env"
    IMESSAGE_PROJECT_ID=your-project-id
    IMESSAGE_PROJECT_SECRET=your-project-secret
    IMESSAGE_WEBHOOK_SECRET=your-webhook-signing-secret
    ```

    如自行託管伺服器，請將適配器指向伺服器的 gRPC 地址，格式為 `host:port`。適配器會移除 URL 的協定部分。如果只填寫主機名稱，適配器會加上 `:443`。

    ```bash title=".env"
    IMESSAGE_SERVER_URL=imessage.example.com:443
    IMESSAGE_API_KEY=your-server-token
    IMESSAGE_PHONE=+15551234567
    ```

    `IMESSAGE_PHONE` 是選填設定，在自行託管的伺服器有多個號碼時用於安排訊息路由。你亦可以直接將這些值傳入 `createiMessageAdapter()`，並可傳入 `credentials` 函數，在首次使用時從密鑰儲存庫取得項目 ID 和密鑰。
  </TabItem>

  <TabItem value="linq" label="Linq">
    請按 [Linq API 文件](https://docs.linqapp.com/)完成 Linq 專用設定，包括開通電話號碼和取得 API 密鑰。建立 Linq 帳戶後，複製 API 密鑰，並設定 Agent 會讀取的憑證。

    ```bash title=".env"
    LINQ_API_KEY=your-linq-api-key
    LINQ_WEBHOOK_SECRET=your-webhook-signing-secret
    ```

    `LINQ_WEBHOOK_SECRET` 是下一節建立 Webhook 訂閱時傳回的簽署密鑰。適配器亦接受 `baseURL` 選項，用於指定另一個 Linq API 基礎網址，例如 Sandbox 環境的網址。
  </TabItem>
</Tabs>

## Webhook URL {/* #webhook-url */}

Mastra 會按 Agent ID 和適配器的鍵名產生 iMessage Webhook 路由。

```text
/api/agents/imessage-agent/channels/imessage/webhook
```

以 Mastra 伺服器的公開網址為基礎，加上上述路徑。

```text
https://your-app.example.com/api/agents/imessage-agent/channels/imessage/webhook
```

<Tabs groupId="imessage-provider">
  <TabItem value="photon" label="Photon">
    在 [Photon 管理介面](https://app.photon.codes)登記此 URL，並將傳回的簽署密鑰設為 `IMESSAGE_WEBHOOK_SECRET`。密鑰只在登記時顯示一次。適配器會驗證每次投遞的簽署，並拒絕簽署不符的請求。只有託管模式提供 Webhook。
  </TabItem>

  <TabItem value="linq" label="Linq">
    建立 [Webhook 訂閱](https://docs.linqapp.com/guides/webhooks/subscriptions/)，將此 URL 設為目標地址，並至少訂閱以下事件。

    * `message.received`
    * `reaction.added`
    * `reaction.removed`

    將訂閱傳回的 `signing_secret` 設為 `LINQ_WEBHOOK_SECRET`。密鑰只在建立訂閱時顯示一次，其後無法取回。適配器會驗證每次投遞的 HMAC 簽署，檢查請求是否遭重放，並拒絕簽署不符的請求。
  </TabItem>
</Tabs>

:::note

兩個 Provider 都只會向公開的 HTTPS 端點投遞訊息，不支援 `http://` 或 `localhost` 等私人地址。在本機開發時，可按[頻道概覽](/docs/channels#webhook-routes)的說明使用隧道。

:::

## 重複投遞 {/* #duplicate-deliveries */}

Photon 和 Linq 採用至少投遞一次的機制，投遞失敗時會按退避策略重試，因此同一個訊息有可能送達多次。Chat SDK 透過頻道狀態適配器過濾重複訊息，而 Mastra 預設將用於識別重複訊息的鍵值保留在記憶體中。這個做法適用於單一持續運行的伺服器。

伺服器重新啟動後，Agent 仍可能收到重複訊息。無伺服器環境亦可能將重試請求轉送至另一個實例。透過 `channels.state` 傳入共用狀態適配器，讓各個實例都可讀取用於識別重複訊息的鍵值。除了 iMessage 適配器，請一併安裝狀態適配器。

```bash npm2yarn
npm install @chat-adapter/state-redis
```

`createRedisState()` 會讀取 `REDIS_URL` 環境變數。

```typescript title="src/mastra/agents/imessage-agent.ts" oxfmt:false
import { createRedisState } from '@chat-adapter/state-redis'

channels: {
  adapters: {
    imessage: {
      adapter: createiMessageAdapter(),
      toolDisplay: 'text',
    },
  },
  state: createRedisState(),
},
```

使用會產生副作用的 Tool 時，過濾重複訊息尤其重要，因為用戶會看見同一個訊息被處理兩次所產生的結果。

## 已讀回條 {/* #read-receipts */}

iPhone 的「訊息」App 會就 Agent 發出的每個訊息傳送已讀回條。Photon 適配器會將回條作為傳入訊息交給 Mastra，當中沒有文字或附件。Mastra 會略過這些訊息，避免 Agent 不斷回覆自己。這些訊息的 ID 帶有 `:read:` 後綴，並會在 `debug` 級別的日誌中顯示為已略過。

所有適配器均適用同一規則。傳入訊息如沒有文字，也沒有附件，就不會觸發 Agent 執行。自訂的 `onDirectMessage`、`onMention` 或 `onSubscribedMessage` 處理函數仍會收到這類訊息，並可在呼叫 `defaultHandler` 前處理。

## 網關監聽器 {/* #gateway-listener */}

Photon 適配器可在託管或自行託管模式下保持連線，以串流方式即時接收訊息，毋須透過 Webhook。Linq 適配器透過 Webhook 接收事件，並無網關模式。

Mastra 會在初始化時啟動網關監聽器，並在連線中斷時重新連線。因此，持續運行的伺服器毋須安排 cron 工作或新增路由。使用 Webhook 時，可在適配器設定中加入 `gateway: false`，關閉監聽器。

```typescript title="src/mastra/agents/imessage-agent.ts" oxfmt:false
imessage: {
  adapter: createiMessageAdapter(),
  toolDisplay: 'text',
  gateway: false,
},
```

在無伺服器平台上，建議優先使用 Webhook。網關監聽器需要一個持續運行的程序。詳見[無伺服器部署](/docs/channels#serverless-deployment)。
