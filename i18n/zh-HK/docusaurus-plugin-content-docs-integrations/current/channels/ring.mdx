# Ring

Mastra Agent 可透過 Ring 訊號接收 Ring 門鐘和攝錄機的事件，包括有人按門鐘或裝置偵測到移動。每宗事件都會化為一個[通知訊號](/docs/signals/notifications)，送到 Agent 的對話串。Agent 可擷取快照或影片片段，查看門外是誰。

事件和媒體都由 [Ring Partner API](https://developer.amazon.com/docs/ring/api-documentation.html) 提供。這個 API 不提供燈光、警報器、門鎖或雙向通話功能。

## 安裝 {/* #installation */}

安裝所需的套件：

```bash npm2yarn
npm install @mastra/ring-signals @mastra/libsql @mastra/memory
```

## 使用前準備 {/* #prerequisites */}

使用 Ring 訊號需要以下各項：

* 一部使用 Ring 收費計劃的 Ring 裝置。計劃須包括 **Person, Package & Vehicle Alerts**，移動偵測事件才會指出偵測到甚麼。
* 在 [Ring Developer Console](https://developer.amazon.com/ring/console/apps) 建立的開發者應用程式，類型須為 **Private App**，並選用 **Cameras and Doorbells** 權限範圍。請記下 **Client ID**、**Client Secret** 和 **HMAC Signature Key**。
* 支援頻道與通知的 Mastra 儲存適配器。已連結的 Ring 帳戶會保存在頻道儲存區，通知訊號則使用通知儲存區。
* 可從互聯網存取的 Mastra 伺服器 HTTPS 網址。Ring 會向伺服器發出請求，以連結帳戶和傳送事件。本機開發可使用隧道，例如 `npx cloudflared tunnel --url http://localhost:4111`。

把開發者應用程式的憑證加入環境變數：

```bash title=".env"
RING_CLIENT_ID=your-client-id
RING_CLIENT_SECRET=your-client-secret
RING_HMAC_KEY=your-hmac-signature-key
MASTRA_ENCRYPTION_KEY=a-long-random-string
RING_BASE_URL=http://localhost:4111
```

`MASTRA_ENCRYPTION_KEY` 用來加密已儲存的 Ring 權杖。如果沒有設定，系統會在未加密的情況下儲存權杖，並記錄一項警告。`RING_BASE_URL` 可按需要設定，指定快照和影片片段連結所指向的 Mastra 伺服器網址。詳見[媒體連結](#media-links)。

## 設定 Agent {/* #agent-configuration */}

將 `new RingSignals()` 加入 Agent 的 `signals` 陣列：

```typescript title="src/mastra/agents/home-agent.ts"
import { Agent } from '@mastra/core/agent'
import { Memory } from '@mastra/memory'
import { RingSignals } from '@mastra/ring-signals'

export const homeAgent = new Agent({
  id: 'home-agent',
  name: 'Home Agent',
  instructions: 'Watch the front door and say briefly whether each event needs attention.',
  model: '__GATEWAY_OPENAI_MODEL__',
  memory: new Memory(),
  signals: [new RingSignals()],
})
```

系統預設從環境變數讀取 `RING_CLIENT_ID`、`RING_CLIENT_SECRET`、`RING_HMAC_KEY` 和 `RING_BASE_URL`。如要覆寫這些值，可在設定中傳入 `clientId`、`clientSecret`、`hmacKey` 和 `baseUrl`。各選項及其預設值載於 [RingSignals 參考文件](/reference/signals/ring-signals)。

在 Mastra 實例註冊 Agent 和儲存適配器：

```typescript title="src/mastra/index.ts"
import { Mastra } from '@mastra/core'
import { LibSQLStore } from '@mastra/libsql'
import { homeAgent } from './agents/home-agent'

export const mastra = new Mastra({
  agents: { homeAgent },
  storage: new LibSQLStore({
    id: 'mastra-storage',
    url: 'file:./mastra.db',
  }),
})
```

## 連結帳戶 {/* #account-linking */}

連結 Ring 帳戶後，Agent 就可接收該帳戶的裝置事件。請依照以下次序完成兩邊的設定：

1. 在 Amazon 開發者網站的 [Ring Developer Console](https://developer.amazon.com/ring/console/apps) 設定開發者應用程式。
2. 到 [ring.com](https://ring.com) 把開發者應用程式與擁有裝置的 Ring 帳戶連結。

### Ring 開發者控制台 {/* #ring-developer-console */}

Mastra 伺服器會在 `/ring` 路徑下自動加入 Ring 所需的路由：

| Ring 設定項目 | 路由 | Ring 的用途 |
| - | - | - |
| Account Link URL | `GET <server URL>/ring/link` | 完成連結並顯示結果 |
| Token Exchange URL | `POST <server URL>/ring/token` | 以授權碼換取權杖 |
| Webhook URL | `POST <server URL>/ring/webhook` | 傳送按門鐘、移動偵測等事件 |
| App Homepage URL | `GET <server URL>/ring/home` | 從 Ring Appstore 的應用程式頁面連往應用程式主頁 |

Ring 向這些路由發出請求時毋須經過 Mastra 身份驗證。伺服器以 Ring 的簽署驗證 Webhook 請求，並以 Ring 提供的連結隨機值驗證帳戶連結請求。

交換權杖的路由本身不驗證授權碼，而是把每個授權碼交給 Ring。任何並非由 Ring 發出的授權碼都會被拒絕。為免大量請求湧入，請在伺服器的中介軟件為 `/ring/token` 設定請求速率限制。

每個 `RingSignals` 實例都會加入各自的路由。如有多個 Agent 使用 `RingSignals`，請讓每個實例使用獨立的 `routePrefix` 和 Ring 開發者應用程式。若兩個實例共用同一前綴，Mastra 只會註冊第一個實例的路由，第二個 Agent 便收不到 Ring 事件。

1. 開啟開發者應用程式的 **Account linking** 設定，輸入表內的四個網址。
2. 在 **Connect** 下選取 **Connect Ring account**，再登入擁有該裝置的 Ring 帳戶。私人開發者應用程式只供在此連接的帳戶使用。

### ring.com {/* #ringcom */}

1. 在瀏覽器登入 Ring 帳戶。
2. 前往 Ring Appstore 上的開發者應用程式頁面 `https://ring.com/appstore/<your-app>`。
3. 完成應用程式連結後，頁面會顯示 `Ring account linked`。

Ring 帳戶的 [Integrations](https://account.ring.com/account/integrations) 頁面會列出已連結的應用程式，可在該處暫停或移除。

### 連結後 {/* #after-linking */}

帳戶權杖會保存在頻道儲存區，並在到期前更新。如果在 Ring 帳戶的 **Integrations** 移除開發者應用程式，Ring 會發出 `app_integration_removed` 事件，觸發刪除該帳戶的權杖。

一個 Agent 可以連結多個 Ring 帳戶。Ring 容許每個私人開發者應用程式最多連結 10 個帳戶。每部裝置都會配對至擁有它的帳戶。

### 測試整合 {/* #test-the-integration */}

按一下門鐘。裝置的對話串會收到 `button_press` 通知，Agent 會作出回應。在 Studio 開啟該 Agent 便可查看對話串。對話串 ID 就是裝置 ID。

## 事件與優先級 {/* #events-and-priorities */}

Ring 事件會以通知訊號送達。系統預設啟用 `button_press`（`high` 優先級）和 `motion_detected`（`medium` 優先級）。完整的事件類型和預設設定載於 [RingSignals 參考文件](/reference/signals/ring-signals#events)。

可利用 `events` 選項更改預設設定或啟用指定事件。將某類事件設為 `false` 即可停用：

```typescript
new RingSignals({
  events: {
    motion_detected: {
      priority: 'medium',
      summary: 'Motion was detected at the front door.',
      attributes: event => ({ ...event.data.attributes, location: 'front door' }),
    },
    device_offline: { priority: 'low', summary: 'Device went offline.', coalesce: true },
  },
})
```

Agent 可看到每個通知的 `deviceId`、`timestamp` 和 `motionType` 屬性。可用 `attributes` 加入自訂屬性，例如裝置所在位置。

`coalesce` 會把重複出現的事件合併為一則待發出的通知，讓[傳送策略](/docs/signals/notifications)按收到的事件數目採取相應操作。預設會將低優先級通知合併成一份摘要。

## 對話串路由 {/* #thread-routing */}

每部 Ring 裝置預設各有一個對話串。`threadId` 使用裝置 ID，`resourceId` 使用 Agent ID。

如要自訂這兩個值，可手動設定 `target.resourceId` 和 `target.threadId`：

```typescript
new RingSignals({
  target: { resourceId: 'home', threadId: 'ring-alerts' },
})
```

如要為每宗事件選擇對話串，可把 `target` 設為函數。函數會接收 Ring 為該事件發出的 Webhook 內容，並傳回該事件的傳送目標。Webhook 內容包括以下欄位：

* `event.data.type`：事件類型，見[事件與優先級](#events-and-priorities)。
* `event.data.attributes.source`：裝置事件使用發出事件的裝置 ID，應用程式整合事件使用帳戶 ID，訂閱事件則使用 `subscriptions`。
* `event.data.attributes.timestamp`：裝置事件發生的時間，以 Unix 紀元起計的毫秒數表示。訂閱事件沒有這個欄位。
* `event.data.attributes.sub_type`：移動偵測事件的觸發原因，可為 `human`、`vehicle`、`package_delivery` 或 `other_motion`。如果已關閉 Smart Alerts，值為 `motion`。訂閱事件的值為 `paid` 或 `trial`。
* `event.meta.account_id`：裝置所屬的 Ring 帳戶 ID。

此例把不同類型的活動分送到不同對話串。由人觸發的移動偵測事件會送往 `ring-human`，由車輛觸發的則送往 `ring-vehicle`，其餘類推。按門鐘事件沒有 `sub_type`，所以會送往 `ring-doorbell`：

```typescript
new RingSignals({
  target: event => {
    const activity = event.data.attributes.sub_type ?? 'doorbell'
    return { resourceId: 'home', threadId: `ring-${activity}` }
  },
})
```

傳回 `undefined` 即可略過事件。函數可以宣告為 `async`。完整的 Webhook 內容類型 `RingWebhookEvent` 載於 [RingSignals 參考文件](/reference/signals/ring-signals#ringwebhookevent)。

## 擷取快照和影片片段的 Tool {/* #snapshot-and-clip-tools */}

Agent 可使用以下兩個 Tool：

* `ring_snapshot`：擷取事件的靜態影像並傳給模型，讓 Agent 可描述畫面。如果事件剛發生時 Ring 未有影像，就會使用事件發生前最近的一張影像。
* `ring_clip`：擷取由事件發生一刻開始的影片片段。Ring 需時處理錄影，Tool 會重試直至片段可供擷取。預設不會將影片傳給模型。詳見[讓模型讀取媒體](#let-the-model-see-media)。

### 讓模型讀取媒體 {/* #let-the-model-see-media */}

`visibleToModel` 決定 Tool 會否把媒體本身傳給模型。大部分模型都接受圖片，但只有少數接受影片，因此 `ring_snapshot` 預設為 `true`，而 `ring_clip` 預設為 `false`。如果 Agent 使用支援影片輸入的模型，例如 `__GATEWAY_GOOGLE_MODEL_FLASH__`，可為影片片段啟用這項設定：

```typescript
new RingSignals({
  tools: {
    clip: { visibleToModel: true },
  },
})
```

`visibleToModel` 設為 `false` 時，模型只會收到 Tool 的文字結果和連結，無法描述媒體畫面。

:::note

為影片片段啟用 `visibleToModel` 前，請先確認所用模型支援影片輸入。Gemini 模型支援影片輸入，Anthropic 和 OpenAI 的模型則不支援。Anthropic 會略過影片並發出警告，其他模型 API 亦可能拒絕請求。

影片的每一秒都會佔用模型的上下文視窗。預設長度 15 秒的片段會用上數千個 token。若將 `durationMs` 設為上限 15 分鐘，則可能用上數十萬個 token，因此讓模型觀看片段時，宜縮短 `durationMs`。影片不會儲存在 Agent 的記憶中，所以只會在擷取影片的步驟佔用上下文。

:::

### 媒體連結 {/* #media-links */}

Ring 不提供可分享的媒體連結。下載快照或影片片段需要 Ring 帳戶的權杖，因此瀏覽器或聊天應用程式不能直接從 Ring 下載。設定 `baseUrl` 後，Tool 會傳回指向你自己伺服器的已簽署連結，路徑位於 `<baseUrl>/ring/media/` 下。開啟連結時，伺服器會向 Ring 擷取媒體並轉送。媒體不會持久儲存，近期擷取的內容只會在記憶體內暫存數分鐘。

將 `RING_BASE_URL` 設為 Mastra 伺服器的網址。開發時可用 `http://localhost:4111` 或隧道網址，正式環境則使用部署後的網址。

如未設定 `RING_BASE_URL` 或 `baseUrl` 其中任何一項，Tool 就不會傳回連結。Agent 仍可看到每張快照，聊天頻道亦會收到附件，但應用程式沒有連結可供顯示。

### 在聊天頻道以附件傳送媒體 {/* #attach-media-in-chat-channels */}

當 Agent 同時使用 iMessage 或 Slack 等[頻道](/docs/channels)時，用戶無法在聊天中直接看到 Tool 的結果。Tool 會把快照和影片片段當作檔案附件送到頻道對話串，用戶便可在對話中收到。Studio、網頁及 API 的對話串會直接從 Tool 的結果讀取媒體，因此不會收到附件。

所有頻道預設都可接收附件，毋須額外設定。如要更改，可在個別 Tool 設定以下選項：

* `attachment`：設為 `false` 可停止傳送附件。如指定平台名稱清單，例如 `['imessage', 'slack']`，附件只會送往清單上的平台。
* `maxAttachmentBytes`：附件的大小上限，以位元組計。超過上限的檔案不會以附件傳送。

此例只會在 iMessage 和 Slack 以附件傳送快照，並將 Discord 的影片片段附件上限設為 10 MB：

```typescript
new RingSignals({
  tools: {
    snapshot: { attachment: ['imessage', 'slack'] },
    clip: { maxAttachmentBytes: { discord: 10_000_000 } },
  },
})
```

平台名稱是 Agent 的 `channels.adapters` 設定中對應適配器的鍵。以下 Agent 使用的平台名稱是 `imessage` 和 `slack`：

```typescript oxfmt:false
channels: {
  adapters: {
    imessage: { adapter: createiMessageAdapter() },
    slack: { adapter: createSlackAdapter() },
  },
},
```

如果頻道的平台不在清單上，或者檔案太大，Tool 會要求 Agent 改在回覆中分享連結。要產生連結，必須設定 `baseUrl`。以附件傳送的檔案不會儲存在 Agent 的記憶中。

### 在聊天中接收 Ring 提示 {/* #send-ring-alerts-to-a-chat */}

如要在聊天中收到 Ring 提示，頻道必須與 Ring 共用對話串。用 `resolveResourceId` 和 `resolveThreadId` 為頻道對話串指定固定的資源 ID 和對話串 ID，再把 `target` 設成相同的值。發出首個訊息前，請將 `.env` 內的 `HOME_OWNER_USER_ID` 設為你在頻道平台上的用戶 ID（`message.author.userId`）。只有你發出的私人訊息會進入 Ring 對話串。群組對話及其他發訊人會繼續使用各自的對話串，亦不會收到 Ring 提示。不過，他們仍可要求 Agent 擷取 Ring 媒體，詳見下方警告：

```typescript title="src/mastra/agents/home-agent.ts"
import { Agent } from '@mastra/core/agent'
import { Memory } from '@mastra/memory'
import { RingSignals } from '@mastra/ring-signals'
import { createiMessageAdapter } from '@photon-ai/chat-adapter-imessage'

const resourceId = 'home'
const threadId = 'ring-alerts'
// Your user ID on the channel platform
const ownerUserId = process.env.HOME_OWNER_USER_ID
if (!ownerUserId) {
  throw new Error('Set HOME_OWNER_USER_ID to your user ID on the channel platform')
}

export const homeAgent = new Agent({
  id: 'home-agent',
  name: 'Home Agent',
  instructions: 'Watch the front door and say briefly whether each event needs attention.',
  model: '__GATEWAY_OPENAI_MODEL__',
  memory: new Memory(),
  channels: {
    resolveResourceId: ({ thread, message, defaultResourceId }) =>
      thread.isDM && message.author.userId === ownerUserId ? resourceId : defaultResourceId,
    resolveThreadId: ctx => (ctx.resourceId === resourceId ? threadId : ctx.defaultThreadId),
    adapters: {
      imessage: { adapter: createiMessageAdapter() },
    },
  },
  signals: [
    new RingSignals({
      target: { resourceId, threadId },
    }),
  ],
})
```

頻道收到首個訊息時會建立 `ring-alerts` 對話串，之後 Ring 事件也會送到同一個對話串。如果 Ring 事件先到，對話串便會先由 Ring 建立。頻道無法接管已有的對話串，因此會另開一個。

:::warning

在首宗 Ring 事件送達前，請先從頻道向 Agent 發出訊息。請使用新對話，因為這兩個解析函數只會在建立對話串時執行。加入函數前已開始的對話會繼續使用原有的對話串。

任何能透過頻道向 Agent 發訊息的人，都可要求 Agent 使用 Ring Tool。請限制該平台上可聯絡 Agent 的用戶。

:::

## 限制 {/* #limitations */}

* Ring 預期於五秒內收到 Webhook 回應。如果平台會讓閒置的伺服器休眠，休眠後的首宗事件可能延遲送達。
* Ring Partner API 無法存取已啟用端對端加密的裝置。
* Ring 會為每張快照及每段影片加上水印。
* 只有在帳戶連結後發生的事件，才有快照和影片片段可供擷取。
* Studio 會顯示 Tool 結果中的快照，但不能播放影片片段。要觀看影片，請開啟 Tool 結果內的影片網址。
