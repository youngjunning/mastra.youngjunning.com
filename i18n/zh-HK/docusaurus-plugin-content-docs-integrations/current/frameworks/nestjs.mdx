# NestJS

在本指南中，您將使用 Mastra 和 NestJS 建立一個Tool來呼叫 AI Agent。這[NestJS server adapter](/reference/server/nestjs-adapter)將 Mastra 的Agent和Workflow路由註冊為 NestJS 模組，以便它們在現有的 NestJS 應用程式中運作。

## 開始之前 {/* #before-you-begin */}

* 您需要來自受支援的 API 金鑰[model provider](/models). If you don't have a preference, use [OpenAI](/models/providers/openai).
* 安裝 Node.js`v22.13.0` or later
* 使用 NestJS Express 平台（`@nestjs/platform-express`)

## 建立一個新的 NestJS 應用程式（可選） {/* #create-a-new-nestjs-app-optional */}

如果您已經有 NestJS 應用程序，請跳到下一步。

執行以下命令以建立一個新的 NestJS 應用程式：

```bash npm2yarn
npx @nestjs/cli new mastra-nest
```

這將建立一個名為`mastra-nest`, but you can replace it with any name you want.

## 初始化瑪斯特拉 {/* #initialize-mastra */}

導航到您的 NestJS 專案目錄：

```bash
cd mastra-nest
```

跑步[`mastra init`](/reference/cli/mastra#mastra-init). When prompted, choose a provider (e.g. OpenAI) and enter your key:

```bash npm2yarn
npx mastra@latest init
```

這創建了一個`src/mastra` folder with an example weather agent and the following files:

* `index.ts`：Mastra 配置，包括內存
* `tools/weather-tool.ts`：取得給定位置天氣的Tool
* `agents/weather-agent.ts`

你將透過`src/mastra/index.ts` file to the NestJS adapter in the next step.

## 更新為您的模組系統產生的文件 {/* #update-the-generated-files-for-your-module-system */}

這些文件`mastra init` generates need one change to compile in a NestJS project. Check the `type` field in your `package.json`. NestJS CLI v12 creates ECMAScript module (ESM) projects with `"type": "module"`. Earlier versions of the CLI create CommonJS projects.

<Tabs>
  <TabItem value="esm" label="ESM">
    ESM 專案使用`"moduleResolution": "nodenext"`, which requires file extensions on relative imports. Add `.js` to every relative import in the generated files, for example:

    ```typescript title="src/mastra/index.ts"
    import { weatherWorkflow } from './workflows/weather-workflow.js'
    import { weatherAgent } from './agents/weather-agent.js'
    ```

    ```typescript title="src/mastra/agents/weather-agent.ts"
    import { weatherTool } from '../tools/weather-tool.js'
    ```
  </TabItem>

  <TabItem value="commonjs" label="CommonJS">
    CommonJS 不支援頂級`await`. Open `src/mastra/index.ts` and remove the `DuckDBStore` import and the `domains` option of `MastraCompositeStore`:

    ```typescript title="src/mastra/index.ts" oxfmt:false
    import { DuckDBStore } from '@mastra/duckdb'

    // ...

    domains: {
      observability: await new DuckDBStore().getStore('observability'),
    },
    ```

    然後Observability資料儲存在預設的 LibSQL 儲存中。
  </TabItem>
</Tabs>

## 新增伺服器適配器 {/* #add-server-adapter */}

安裝 NestJS 伺服器適配器套件：

```bash npm2yarn
npm install @mastra/nestjs@latest
```

打開`src/app.module.ts` and register `MastraModule`:

```typescript title="src/app.module.ts"
import { Module } from '@nestjs/common'
import { MastraModule } from '@mastra/nestjs'
import { mastra } from './mastra/index.js'

@Module({
  imports: [
    MastraModule.register({
      mastra,
    }),
  ],
})
export class AppModule {}
```

：：：筆記

`MastraModule`註冊一個包羅萬象的控制器（`@All('*')`). If it's imported before your app modules, it can intercept unrelated routes and return 404s. To avoid conflicts, import `MastraModule` last or mount it under a dedicated prefix (e.g., `/api/v1/mastra`).

:::

## 測試你的Agent {/* #test-your-agent */}

預設情況下，Mastra 的端點會新增在`/api` subpath and use your agent/workflow IDs. The default `weather-agent` created by `mastra init` is available at `/api/agents/weather-agent`.

啟動你的 NestJS 伺服器：

```bash npm2yarn
npm run start
```

在單獨的終端機視窗中，使用`curl` to ask the weather agent:

```bash
curl -X POST http://localhost:3000/api/agents/weather-agent/generate -H "Content-Type: application/json" -d "{\"messages\":[{\"role\":\"user\",\"content\":\"What is the weather like in Seoul?\"}]}"
```

## 在您自己的服務中使用 Mastra {/* #use-mastra-in-your-own-services */}

此模組導出兩種從 NestJS 服務存取 Mastra 的方法：`MastraService` wrapper and the `MASTRA` injection token.

### 瑪斯特拉服務 {/* #mastraservice */}

`MastraService`是一個可注入的包裝器，具有用於常見操作的便捷方法：

```typescript title="src/agent.service.ts"
import { Injectable } from '@nestjs/common'
import { MastraService } from '@mastra/nestjs'

@Injectable()
export class AgentService {
  constructor(private readonly mastraService: MastraService) {}

  async chat(agentId: string, message: string) {
    const agent = this.mastraService.getAgent(agentId)
    return agent.generate({
      messages: [{ role: 'user', content: message }],
    })
  }

  async runWorkflow(workflowId: string, input: Record<string, unknown>) {
    const workflow = this.mastraService.getWorkflow(workflowId)
    return workflow.start({ inputData: input })
  }
}
```

`MastraService`暴露：

* `getMastra()`：返回底層`Mastra` instance
* `getAgent(id)`: 的簡寫`mastra.getAgent(id)`
* `getWorkflow(id)`: 的簡寫`mastra.getWorkflow(id)`
* `getOptions()`：返回模組配置
* `isShuttingDown`: `true` after graceful shutdown begins

### MASTRA 代幣 {/* #mastra-token */}

如果您需要`Mastra` instance directly (e.g., to access storage, memory, or other core APIs), inject it with the `MASTRA` token:

```typescript title="src/memory.service.ts"
import { Injectable, Inject } from '@nestjs/common'
import { MASTRA } from '@mastra/nestjs'
import type { Mastra } from '@mastra/core/mastra'

@Injectable()
export class MemoryService {
  constructor(@Inject(MASTRA) private readonly mastra: Mastra) {}

  async getThreadMessages(threadId: string) {
    const memory = this.mastra.getMemory()
    return memory?.getMessages({ threadId })
  }
}
```

兩種方法都使用相同的單例`Mastra` instance registered by `MastraModule`.
