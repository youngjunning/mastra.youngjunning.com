# Neon Object Storage

[Neon Object Storage](https://neon.com/docs/storage/overview)是 Neon 項目內置的 S3 兼容儲存服務。儲存桶隸屬於個別分支。建立子分支時，父分支的檔案會以寫入時複製的方式成為子分支的初始檔案。Mastra 透過 [`S3Filesystem`](/integrations/file-storage/amazon-s3) 連接此服務，讓 Agent 使用的 Workspace 檔案隨 [Neon Postgres](/integrations/databases/neon) 資料庫內的資料列一併建立分支。介面詳情請參閱 [Workspace 檔案系統介面](/reference/workspace/filesystem)。

## 開始之前 {/* #before-you-begin */}

你需要：

- 一個 [Neon](https://neon.com) 項目，所在區域須支援物件儲存：`aws-us-east-1`、`aws-us-east-2`、`aws-eu-central-1` 或 `aws-ap-southeast-1`
- [Neon CLI](https://neon.com/docs/cli/install)

## 安裝 {/* #installation */}

```bash npm2yarn
npm install @mastra/s3 @neon/config
```

## 建立儲存桶 {/* #create-a-bucket */}

在項目根目錄的 `neon.ts` 內宣告儲存桶：

```typescript title="neon.ts"
import { defineConfig } from '@neon/config/v1'

export default defineConfig({
  buckets: {
    'agent-files': {},
  },
})
```

儲存桶預設為私人。如要容許匿名讀取，請設定 `access: 'public_read'`。

將目錄連結至你的 Neon 項目，再在已連結的分支建立儲存桶：

```bash
neon link
neon deploy
```

`neon deploy` 會建立儲存桶，並將分支的儲存憑證寫入 `.env`。如沒有 `.env`，便會寫入 `.env.local`。`mastra dev` 可載入兩種檔案。

如要跳過 `neon.ts` 直接建立儲存桶，可先執行 `neon bucket create agent-files`，再執行以下指令自行擷取憑證：

```bash
neon env pull --service object-storage
```

## 環境變數 {/* #environment-variables */}

Neon 會設定以下四個物件儲存環境變數：

| 變數 | 值 |
| - | - |
| `AWS_ACCESS_KEY_ID` | 分支憑證的存取金鑰 ID |
| `AWS_SECRET_ACCESS_KEY` | 該分支憑證的秘密存取金鑰 |
| `AWS_ENDPOINT_URL_S3` | 分支的 S3 端點 |
| `AWS_REGION` | 項目所在區域，例如 `us-east-2` |

分支憑證可在獲發憑證的分支及其子分支使用。在 [Neon Function](/integrations/deploy/neon) 內，Neon 會注入這些環境變數，因此毋須提供 `.env` 檔案。

## 用法 {/* #usage */}

把這些環境變數傳入 `S3Filesystem`，再將 Workspace 分配給 Agent：

```typescript title="src/mastra/agents/file-agent.ts"
import { Agent } from '@mastra/core/agent'
import { Workspace } from '@mastra/core/workspace'
import { S3Filesystem } from '@mastra/s3'

const workspace = new Workspace({
  filesystem: new S3Filesystem({
    bucket: 'agent-files',
    region: process.env.AWS_REGION!,
    endpoint: process.env.AWS_ENDPOINT_URL_S3,
    accessKeyId: process.env.AWS_ACCESS_KEY_ID,
    secretAccessKey: process.env.AWS_SECRET_ACCESS_KEY,
  }),
})

export const fileAgent = new Agent({
  id: 'file-agent',
  name: 'file-agent',
  instructions: 'You manage files in the workspace.',
  model: '__GATEWAY_ANTHROPIC_MODEL_OPUS__',
  workspace,
})
```

務必設定 `endpoint`。Neon 只接受路徑式請求，`S3Filesystem` 亦只會在設定 `endpoint` 後採用這種格式。若省略此設定，AWS SDK 仍會讀取 `AWS_ENDPOINT_URL_S3`，但會以虛擬主機格式發出請求（`agent-files.<endpoint-host>`），令 TLS 驗證失敗。

`S3Filesystem` 識別到 Neon 端點後，會把 `icon` 設為 `'neon'`，並把 `displayName` 設為 `Neon Object Storage`。Studio 因此會在檔案樹顯示 Neon 掛載項目。

你可用 `prefix` 在同一個儲存桶內，為每個 Agent、用戶或對話串各自指定一個資料夾：

```typescript
const filesystem = new S3Filesystem({
  bucket: 'agent-files',
  prefix: `users/${userId}`,
  region: process.env.AWS_REGION,
  endpoint: process.env.AWS_ENDPOINT_URL_S3,
  accessKeyId: process.env.AWS_ACCESS_KEY_ID,
  secretAccessKey: process.env.AWS_SECRET_ACCESS_KEY,
})
```

前綴只限制檔案系統可尋址的物件鍵，並無權限隔離作用。

## 分支 {/* #branches */}

每個分支都有獨立的儲存端點。建立分支時，新分支會繼承父分支當時的所有儲存桶和檔案。在子分支寫入或刪除內容不會改動父分支，父分支其後寫入的內容亦不會出現在子分支。

你可透過分支，為預覽部署、測試執行或實驗用的 Agent 提供正式環境檔案的完整副本，毋須實際複製資料：

```bash
neon checkout preview/new-tools --create
```

`neon checkout --create` 會建立分支並在 `.neon` 內固定該分支，再將子分支的環境變數連同其儲存端點擷取至 `.env`。連接子分支時，可沿用父分支的憑證，但須使用子分支的端點。如要移除該分支的檔案，刪除分支即可。

## Skill Blob 儲存 {/* #skill-blob-storage */}

`S3BlobStore` 儲存由 [`MastraEditor`](/reference/editor/mastra-editor) 產生的 Skill Blob，這些 Blob 按內容尋址。它接受同一組連線選項：

```typescript
import { S3BlobStore } from '@mastra/s3'

const blobStore = new S3BlobStore({
  bucket: 'agent-files',
  region: process.env.AWS_REGION!,
  endpoint: process.env.AWS_ENDPOINT_URL_S3,
  accessKeyId: process.env.AWS_ACCESS_KEY_ID,
  secretAccessKey: process.env.AWS_SECRET_ACCESS_KEY,
})
```

## FilesSDK 適配器 {/* #filessdk-adapter */}

如使用 [`FilesSDKFilesystem`](/integrations/file-storage/vercel-files)，`neon` 適配器會讀取相同的 `AWS_*` 環境變數。請同時安裝適配器會載入的 AWS SDK 套件：

```bash npm2yarn
npm install @mastra/files-sdk files-sdk @aws-sdk/client-s3 @aws-sdk/s3-presigned-post @aws-sdk/s3-request-presigner
```

```typescript
import { Workspace } from '@mastra/core/workspace'
import { FilesSDKFilesystem } from '@mastra/files-sdk'
import { Files } from 'files-sdk'
import { neon } from 'files-sdk/neon'

const workspace = new Workspace({
  filesystem: new FilesSDKFilesystem({
    files: new Files({ adapter: neon({ bucket: 'agent-files' }) }),
    icon: 'neon',
    displayName: 'Neon Object Storage',
  }),
})
```
