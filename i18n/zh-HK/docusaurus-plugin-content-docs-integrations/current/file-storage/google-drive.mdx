# Google Drive

Mastra 支援兩種 Google Drive 整合方式：

* **Agent 的 Tool**：透過 [Mastra Connect](/docs/mastra-platform/connect)，Agent 可以在整個 Google Drive 帳戶內搜尋、上載和整理檔案。
* **[Workspace 檔案系統](#workspace-filesystem)**：透過 `@mastra/google-drive` 套件，把 Agent 的 Workspace 檔案存放在同一個 Google Drive 資料夾內。

## Connect {/* #connect */}

請先完成 [Connect 設定](/docs/mastra-platform/connect#get-started)，安裝 `@mastra/connect` 並設定平台項目。

## Workspace 檔案系統 {/* #workspace-filesystem */}

`GoogleDriveFilesystem` 把檔案存放在同一個 Google Drive 資料夾內。每個目錄都對應到指定根目錄下的一個 Drive 資料夾。路徑按 POSIX 語義處理，例如 `/notes/todo.txt`。介面詳情請參閱 [WorkspaceFilesystem 介面](/reference/workspace/filesystem)。

### 安裝 {/* #installation */}

```bash npm2yarn
npm install @mastra/google-drive
```

### 使用方法 {/* #usage */}

在 Workspace 加入 `GoogleDriveFilesystem`，再把該 Workspace 指派給 Agent：

```typescript
import { Agent } from '@mastra/core/agent'
import { Workspace } from '@mastra/core/workspace'
import { GoogleDriveFilesystem } from '@mastra/google-drive'

const workspace = new Workspace({
  filesystem: new GoogleDriveFilesystem({
    folderId: process.env.GOOGLE_DRIVE_FOLDER_ID!,
    accessToken: process.env.GOOGLE_DRIVE_ACCESS_TOKEN!,
  }),
})

const agent = new Agent({
  id: 'drive-agent',
  name: 'Drive Agent',
  model: '__GATEWAY_OPENAI_MODEL_LUNA__',
  workspace,
})
```

#### 身份驗證 {/* #authentication */}

請選用以下其中一種身份驗證方式：

* **`accessToken`**：預先取得的 OAuth 存取權杖。請使用 `https://www.googleapis.com/auth/drive` 授權範圍，以便存取與該驗證身份分享的資料夾。
* **`getAccessToken`**：傳回權杖的回調函數，適用於由外部機制更新權杖的情況。
* **`serviceAccount`**：Google 服務帳戶。請把目標資料夾分享給服務帳戶的電郵地址。

##### 服務帳戶 {/* #service-account */}

建議後端 Agent 採用服務帳戶驗證，毋須經過用戶同意程序，也毋須自行處理權杖更新。你只需從服務帳戶的 JSON 密鑰檔案取得**兩個值**：`client_email` 和 `private_key`。

###### 設定服務帳戶 {/* #set-up-the-service-account */}

1. 開啟 [Google Cloud 控制台](https://console.cloud.google.com/)，選擇或建立一個項目。
2. 前往 **API 和服務 > 程式庫**，搜尋 **Google Drive API**，然後選擇**啟用**。
3. 前往 **API 和服務 > 憑證**，選擇**建立憑證 > 服務帳戶**，並填妥表格。角色一欄可以留空：Drive 權限由資料夾的分享設定授予，與 IAM 角色無關。
4. 開啟剛建立的服務帳戶，在**密鑰**分頁選擇**新增密鑰 > 建立新密鑰 > JSON**。瀏覽器會下載 JSON 密鑰檔案。
5. 從 JSON 檔案複製 `client_email` 的值。分享 Drive 資料夾時，請填寫這個電郵地址。

###### 把 Drive 資料夾分享給服務帳戶 {/* #share-the-drive-folder-with-the-service-account */}

服務帳戶有獨立的 Google 身份。只有明確分享給該帳戶的 Drive 內容，它才可以存取。

1. 在 [Google Drive](https://drive.google.com/) 開啟目標資料夾。
2. 選擇**共用**。
3. 貼上服務帳戶的 `client_email` 電郵地址。
4. 選擇**編輯者**（可讀寫）或**檢視者**（唯讀）角色，然後選擇**傳送**。
5. 從網址複製資料夾 ID，即 `https://drive.google.com/drive/folders/<folderId>` 內 `/folders/` 後面的部分。

:::warning

服務帳戶不能在一般的「我的雲端硬碟」資料夾內建立檔案。服務帳戶沒有個人 Drive 儲存配額，因此它建立的檔案必須歸有配額的實體所有。如果只分享個人 Drive 資料夾，可以正常讀取，但寫入會因配額問題而失敗。

如需寫入，請把資料夾放到**共用雲端硬碟**（前稱團隊雲端硬碟）內，並把服務帳戶加入該共用雲端硬碟成為成員。服務帳戶建立檔案時，所需的儲存配額由共用雲端硬碟提供。

如只需讀取個人 Drive 資料夾的內容，則不受這項限制。

:::

###### 設定檔案系統 {/* #configure-the-filesystem */}

把 JSON 檔案內的 `client_email` 和 `private_key` 複製到環境變數：

```bash filename=".env"
GOOGLE_DRIVE_FOLDER_ID=1AbCdEfGhIjKlMnOpQrStUvWxYz
GOOGLE_DRIVE_CLIENT_EMAIL=my-bot@my-project.iam.gserviceaccount.com
# Wrap the value in quotes — the key contains newlines that must be preserved.
GOOGLE_DRIVE_PRIVATE_KEY="-----BEGIN PRIVATE KEY-----\nMIIEvQIBADANBgkq...\n-----END PRIVATE KEY-----\n"
```

```typescript
import { GoogleDriveFilesystem } from '@mastra/google-drive'

const filesystem = new GoogleDriveFilesystem({
  folderId: process.env.GOOGLE_DRIVE_FOLDER_ID!,
  serviceAccount: {
    clientEmail: process.env.GOOGLE_DRIVE_CLIENT_EMAIL!,
    privateKey: process.env.GOOGLE_DRIVE_PRIVATE_KEY!,
  },
})
```

**毋須**複製整份 JSON 檔案，也毋須傳入 `project_id`、`client_id`、`private_key_id` 或 `token_uri` 等不會用到的欄位。只須提供 `clientEmail` 和 `privateKey`；`privateKeyId`、`scopes` 和 `subject` 均為選填。`scopes` 的預設值是 `['https://www.googleapis.com/auth/drive']`。服務帳戶需要此授權範圍，才可存取分享給它的資料夾。較窄的 `drive.file` 範圍只允許存取應用程式自行建立的檔案，所以嘗試存取分享給服務帳戶的資料夾時，會收到 `404 Not Found`。

`GoogleDriveFilesystem` 會在簽署前自動統一 `privateKey` 字串的格式。它會移除兩端的引號，包括以 JSON 包裝的值內經過跳脫的引號，再把字面上的 `\n` 轉成實際的換行符。它亦會統一 `\r\n` 換行格式，並移除末尾的逗號。不論 `.env` 載入程式如何處理該值，密鑰均可正常使用。

###### 疑難排解 {/* #troubleshoot */}

* **`404 File not found: <folderId>`**：服務帳戶沒有權限存取該資料夾。請確認分享對象的電郵地址與 `client_email` 完全相同，並核對資料夾 ID 是否與網址相符。
* **寫入時出現 `storageQuotaExceeded`**：資料夾位於個人的「我的雲端硬碟」內。請把資料夾移至共用雲端硬碟，再把服務帳戶加入為成員。
* **`error:1E08010C:DECODER routines::unsupported`**：`privateKey` 的格式不正確。請確認值內包含完整的 PEM 區塊，並保留換行（可使用字面上的 `\n`）。

#### 唯讀模式 {/* #read-only-mode */}

傳入 `readOnly: true` 即可禁止寫入操作（`writeFile`、`appendFile`、`deleteFile`、`copyFile`、`moveFile`、`mkdir`、`rmdir`）。

```typescript
const filesystem = new GoogleDriveFilesystem({
  folderId,
  accessToken,
  readOnly: true,
})
```

### 方法 {/* #methods */}

GoogleDriveFilesystem 實作 [WorkspaceFilesystem 介面](/reference/workspace/filesystem)，提供所有標準檔案系統方法：

* `readFile(path, options?)`：下載檔案內容
* `writeFile(path, content, options?)`：上載或覆寫檔案
* `appendFile(path, content)`：讀取檔案，在檔案末尾加上內容，再重新上載
* `deleteFile(path, options?)`：刪除檔案
* `copyFile(src, dest, options?)`：使用 Drive 的 `files.copy` API 複製檔案
* `moveFile(src, dest, options?)`：更改檔案的上層資料夾，把檔案移到另一個資料夾
* `mkdir(path, options?)`：建立資料夾
* `rmdir(path, options?)`：移除資料夾
* `readdir(path, options?)`：列出資料夾內容（支援 `recursive` 遞迴列出及 `extension` 副檔名篩選）
* `stat(path)`：傳回檔案或資料夾在 Drive 內的元數據
* `exists(path)`：檢查檔案或資料夾是否存在

### 注意事項 {/* #notes */}

* Google Drive 容許同一個資料夾內有多個同名檔案。`GoogleDriveFilesystem` 解析路徑時只取第一個相符項目，因此如要按路徑查找，請確保個別資料夾內沒有重複名稱。
* 未設定 `recursive`（預設情況）或將它設為 `true` 時，`writeFile` 會自動建立上層資料夾。設為 `recursive: false` 時，上層資料夾必須已經存在。
* 寫入時會核對 `WriteOptions` 的 `expectedMtime`。如已儲存的 `modifiedTime` 跟預期值不符，系統會拒絕寫入並拋出 `StaleFileError`，以支援樂觀並發控制。
* 此 Provider 只透過內置的 `fetch` 調用 Drive REST 端點（`https://www.googleapis.com/drive/v3` 和 `https://www.googleapis.com/upload/drive/v3`），毋須額外的依賴套件。
