# Google雲端硬碟

透過兩種方式將 Google Drive 與 Mastra 結合使用：

* **AgentTool**讓Agent商透過 Google Drive 帳戶尋找、上傳和組織文件[Mastra Connect](/docs/mastra-platform/connect).
* **[Workspace檔案系統](#workspace-filesystem)**&#x5C07;Agent程式的Workspace文件儲存在 Google Drive 資料夾中，使用`@mastra/google-drive` package.

## 連接 {/* #connect */}

在開始之前，請完成[Connect setup](/docs/mastra-platform/connect#get-started) to install `@mastra/connect` and configure your platform project.

## Workspace檔案系統 {/* #workspace-filesystem */}

`GoogleDriveFilesystem`將檔案儲存在單一 Google Drive 資料夾中。每個目錄映射到配置的根目錄下的 Drive 資料夾，路徑使用 POSIX 語義（例如`/notes/todo.txt`). For interface details, see [WorkspaceFilesystem Interface](/reference/workspace/filesystem).

### 安裝 {/* #installation */}

```bash npm2yarn
npm install @mastra/google-drive
```

### 用法 {/* #usage */}

添加一個`GoogleDriveFilesystem` to a workspace and assign it to an agent:

```typescript
import { Agent } from '@mastra/core/agent'
import { Workspace } from '@mastra/core/workspace'
import { GoogleDriveFilesystem } from '@mastra/google-drive'

const workspace = new Workspace({
  filesystem: new GoogleDriveFilesystem({
    folderId: process.env.GOOGLE_DRIVE_FOLDER_ID!,
    accessToken: process.env.GOOGLE_DRIVE_ACCESS_TOKEN!,
  }),
})

const agent = new Agent({
  id: 'drive-agent',
  name: 'Drive Agent',
  model: '__GATEWAY_OPENAI_MODEL_LUNA__',
  workspace,
})
```

#### 驗證 {/* #authentication */}

提供以下身份驗證選項之一：

* **`accessToken`**：預先獲得的 OAuth 訪問令牌。使用`https://www.googleapis.com/auth/drive` scope so the token can see folders shared with the authenticated identity.
* **`getAccessToken`**：返回令牌的回呼。當令牌從外部刷新時很有用。
* **`serviceAccount`**：Google 服務帳戶。與服務帳戶電子郵件共用目標資料夾。

##### 服務帳號 {/* #service-account */}

服務帳戶身份驗證是後端Agent的建議選項。不需要使用者同意流程，也不需要令牌刷新處理。你只需要**two values** from the service account JSON key file: `client_email` and `private_key`.

###### 設定服務帳戶 {/* #set-up-the-service-account */}

1. 打開[Google Cloud Console](https://console.cloud.google.com/) and select or create a project.
2. 前往**APIs & Services > Library**, search for **Google Drive API**, and select **Enable**.
3. 前往**APIs & Services > Credentials**, select **Create credentials > Service account**, and complete the form. The role can be left blank: Drive permissions are granted by sharing folders, not by IAM roles.
4. 開啟新的服務帳戶，前往**Keys** tab, and select **Add key > Create new key > JSON**. The browser downloads a JSON key file.
5. 複製`client_email` value from the JSON file. This is the address you share Drive folders with.

###### 與服務帳戶共用雲端硬碟資料夾 {/* #share-the-drive-folder-with-the-service-account */}

服務帳戶是其自己的 Google 身分。在您明確與其共享之前，它無法看到雲端硬碟中的任何內容。

1. 打開目標資料夾[Google Drive](https://drive.google.com/).
2. 選擇**Share**.
3. 貼上服務帳戶的`client_email` address.
4. 將角色設定為**Editor** (for read and write) or **Viewer** (for read-only access). Select **Send**.
5. 從 URL 複製資料夾 ID。這是之後的片段`/folders/` in `https://drive.google.com/drive/folders/<folderId>`.

：：：警告

服務帳戶無法在標準「我的雲端硬碟」資料夾中建立檔案。服務帳戶沒有個人雲端硬碟儲存配額。它創建的任何文件都必須由擁有配額的實體擁有。如果您僅共用個人雲端硬碟資料夾，則讀取操作可以工作，但寫入操作會失敗並出現配額錯誤。

對於寫入訪問，請將資料夾放入**shared drive** (formerly Team Drive) and add the service account as a member of that shared drive. Shared drives provide the storage quota that service-account-created files need.

針對個人雲端硬碟資料夾的唯讀工作負載沒有此限制。

###### 設定檔系統 {/* #configure-the-filesystem */}

複製`client_email` and `private_key` from the JSON file into your environment:

```bash filename=".env"
GOOGLE_DRIVE_FOLDER_ID=1AbCdEfGhIjKlMnOpQrStUvWxYz
GOOGLE_DRIVE_CLIENT_EMAIL=my-bot@my-project.iam.gserviceaccount.com
# Wrap the value in quotes — the key contains newlines that must be preserved.
GOOGLE_DRIVE_PRIVATE_KEY="-----BEGIN PRIVATE KEY-----\nMIIEvQIBADANBgkq...\n-----END PRIVATE KEY-----\n"
```

```typescript
import { GoogleDriveFilesystem } from '@mastra/google-drive'

const filesystem = new GoogleDriveFilesystem({
  folderId: process.env.GOOGLE_DRIVE_FOLDER_ID!,
  serviceAccount: {
    clientEmail: process.env.GOOGLE_DRIVE_CLIENT_EMAIL!,
    privateKey: process.env.GOOGLE_DRIVE_PRIVATE_KEY!,
  },
})
```

你**don't** need to copy the entire JSON file or pass other fields like `project_id`, `client_id`, `private_key_id`, or `token_uri`. They're not used. Only `clientEmail` and `privateKey` are required. `privateKeyId`, `scopes`, and `subject` are optional. `scopes` defaults to `['https://www.googleapis.com/auth/drive']`, which is the scope required for the service account to see folders shared with it. The narrower `drive.file` scope only grants access to files the application created itself, so a folder shared with the service account would return `404 Not Found`.

`GoogleDriveFilesystem`自動標準化`privateKey` string before signing. It strips surrounding quotes, including escaped quotes from JSON-wrapped values, and converts literal `\n` sequences to real newlines. It also normalizes `\r\n` line endings, and removes a trailing comma. The key works regardless of how your `.env` loader handles the value.

###### 故障排除 {/* #troubleshoot */}

* **`404 File not found: <folderId>`**：服務帳戶無權存取該資料夾。確認該資料夾已與確切的人共用`client_email` address and that the folder ID matches the URL.
* **`storageQuotaExceeded`寫時**：該資料夾位於個人「我的雲端硬碟」中。將資料夾移至共用雲端硬碟並將服務帳戶新增為成員。
* **`error:1E08010C:DECODER routines::unsupported`**： 這`privateKey` value is malformed. Confirm the value contains the full PEM block and that newlines are preserved (literal `\n` is fine).

#### 唯讀模式 {/* #read-only-mode */}

經過`readOnly: true` to block write operations (`writeFile`, `appendFile`, `deleteFile`, `copyFile`, `moveFile`, `mkdir`, `rmdir`).

```typescript
const filesystem = new GoogleDriveFilesystem({
  folderId,
  accessToken,
  readOnly: true,
})
```

### 方法 {/* #methods */}

GoogleDriveFilesystem 實作了[WorkspaceFilesystem interface](/reference/workspace/filesystem), providing all standard filesystem methods:

* `readFile(path, options?)`- 下載檔案內容
* `writeFile(path, content, options?)`- 上傳或覆蓋文件
* `appendFile(path, content)`- 透過讀取並重新上傳檔案來追加內容
* `deleteFile(path, options?)`- 刪除文件
* `copyFile(src, dest, options?)`- 使用磁碟機複製文件`files.copy` API
* `moveFile(src, dest, options?)`- 透過交換父資料夾在資料夾之間移動文件
* `mkdir(path, options?)`- 建立一個資料夾
* `rmdir(path, options?)`- 刪除資料夾
* `readdir(path, options?)`- 列出資料夾內容（支持`recursive` and `extension` filtering)
* `stat(path)`- 傳回檔案或資料夾的雲端硬碟元數據
* `exists(path)`- 檢查檔案或資料夾是否存在

### 筆記 {/* #notes */}

* Google 雲端硬碟允許資料夾中存在多個同名檔案。`GoogleDriveFilesystem` resolves paths by picking the first match, so keep names unique within each folder when you rely on path-based lookup.
* `writeFile`時自動建立父資料夾`recursive` is unset (the default) or `true`. Set `recursive: false` to require the parent folder to already exist.
* `expectedMtime`在`WriteOptions` is honored. When the stored `modifiedTime` differs, the write is rejected with `StaleFileError` to support optimistic concurrency.
* 提供者僅使用 Drive REST 端點（`https://www.googleapis.com/drive/v3` and `https://www.googleapis.com/upload/drive/v3`) through the built-in `fetch`. No additional dependencies are required.
