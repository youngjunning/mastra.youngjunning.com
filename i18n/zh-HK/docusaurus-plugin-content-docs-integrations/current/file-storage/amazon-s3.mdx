# Amazon S3

Amazon S3 及兼容 S3 的服務均可用於儲存檔案，包括 Cloudflare R2、Neon Object Storage、MinIO、DigitalOcean Spaces 及 Tigris。介面詳情請參閱 [WorkspaceFilesystem 介面](/reference/workspace/filesystem)。

## 安裝 {/* #installation */}

```bash npm2yarn
npm install @mastra/s3
```

## 使用方法 {/* #usage */}

把 `S3Filesystem` 加入 Workspace，再將該 Workspace 指派給 Agent。

```typescript
import { Agent } from '@mastra/core/agent'
import { Workspace } from '@mastra/core/workspace'
import { S3Filesystem } from '@mastra/s3'

const workspace = new Workspace({
  filesystem: new S3Filesystem({
    bucket: 'my-bucket',
    region: 'us-east-1',
    accessKeyId: process.env.AWS_ACCESS_KEY_ID,
    secretAccessKey: process.env.AWS_SECRET_ACCESS_KEY,
  }),
})

const agent = new Agent({
  id: 'file-agent',
  name: 'file-agent',
  model: '__GATEWAY_ANTHROPIC_MODEL_OPUS__',
  workspace,
})
```

### AWS 憑證 Provider 鏈 {/* #aws-credential-provider-chain */}

沒有指定憑證時，`S3Filesystem` 會使用 AWS SDK 的預設憑證 Provider 鏈，從環境變數、`~/.aws` 配置檔案、ECS 容器憑證、EC2 執行個體設定檔等標準來源自動尋找憑證。

```typescript
import { S3Filesystem } from '@mastra/s3'

// SDK discovers credentials from the environment automatically
const filesystem = new S3Filesystem({
  bucket: 'my-bucket',
  region: 'us-east-1',
})
```

傳入憑證 Provider 函數，便可自動更新憑證。這適用於部署在 ECS 或 Lambda 的情況，也適用於透過 SSO 或 AssumeRole 取得臨時憑證、需要在憑證到期時更新的情況。

如需直接調用 `fromNodeProviderChain()`，請安裝 AWS SDK 的憑證 Provider 套件。

```bash npm2yarn
npm install @aws-sdk/credential-providers
```

```typescript
import { S3Filesystem } from '@mastra/s3'
import { fromNodeProviderChain } from '@aws-sdk/credential-providers'

const filesystem = new S3Filesystem({
  bucket: 'my-bucket',
  region: 'us-east-1',
  credentials: fromNodeProviderChain(),
})
```

憑證 Provider 函數只適用於 `S3Filesystem` 的 API 調用。把檔案系統掛載到 E2B 或 Daytona Sandbox 時，掛載配置只接受靜態的 `accessKeyId`、`secretAccessKey` 及 `sessionToken` 值，所以必須在掛載機制以外處理憑證更新。掛載可維持多久以及隔離要求，請參閱 [Daytona 的臨時憑證](/integrations/sandboxes/daytona#temporary-s3-credentials)。

### 按前綴限制權限 {/* #prefix-scoped-permissions */}

如有設定 `prefix`，初始化時會以標準化後帶有結尾 `/` 的前綴及 `MaxKeys: 1` 調用 `ListObjectsV2`。憑證須允許列出指定前綴下的物件。如沒有設定前綴，初始化時會使用 `HeadBucket`。這兩項檢查只驗證存取權限，不會檢查目錄是否存在。

前綴只限定檔案系統尋址時使用的物件鍵範圍。要隔離存取，請使用權限由儲存 Provider 的政策限制在指定前綴下的憑證，並把權限較廣的上層憑證留在後端。初始化設有前綴的檔案系統時，單有讀寫權限並不足夠，還須具備列出物件的權限。

### Cloudflare R2 {/* #cloudflare-r2 */}

```typescript
import { S3Filesystem } from '@mastra/s3'

const filesystem = new S3Filesystem({
  bucket: 'my-r2-bucket',
  region: 'auto',
  endpoint: `https://${process.env.R2_ACCOUNT_ID}.r2.cloudflarestorage.com`,
  accessKeyId: process.env.R2_ACCESS_KEY_ID,
  secretAccessKey: process.env.R2_SECRET_ACCESS_KEY,
})
```

### Neon Object Storage {/* #neon-object-storage */}

```typescript
import { S3Filesystem } from '@mastra/s3'

const filesystem = new S3Filesystem({
  bucket: 'agent-files',
  region: process.env.AWS_REGION!,
  endpoint: process.env.AWS_ENDPOINT_URL_S3,
  accessKeyId: process.env.AWS_ACCESS_KEY_ID,
  secretAccessKey: process.env.AWS_SECRET_ACCESS_KEY,
})
```

`neon deploy` 和 `neon env pull` 會寫入當前 Neon 分支所用的這些變數。請沿用預設的路徑式定址。各分支都有各自的端點及檔案副本。有關儲存桶設定及分支的詳情，請參閱 [Neon Object Storage](/integrations/file-storage/neon)。

### MinIO {/* #minio */}

```typescript
import { S3Filesystem } from '@mastra/s3'

const filesystem = new S3Filesystem({
  bucket: 'my-bucket',
  region: 'us-east-1',
  endpoint: 'http://localhost:9000',
  accessKeyId: 'minioadmin',
  secretAccessKey: 'minioadmin',
})
```

### Tigris {/* #tigris */}

```typescript
import { S3Filesystem } from '@mastra/s3'

const filesystem = new S3Filesystem({
  bucket: 'my-bucket',
  region: 'auto',
  endpoint: 'https://t3.storage.dev',
  accessKeyId: process.env.TIGRIS_ACCESS_KEY_ID,
  secretAccessKey: process.env.TIGRIS_SECRET_ACCESS_KEY,
  forcePathStyle: false,
})
```

Tigris 使用虛擬主機式定址，須將 `forcePathStyle` 設為 `false`。指定自訂端點時，此參數預設為 `true`。你可在 [Tigris 控制台](https://console.tigris.dev/)建立憑證。存取密鑰的前綴為 `tid_`，秘密存取密鑰的前綴為 `tsec_`。

## 方法 {/* #methods */}

S3Filesystem 實現了 [WorkspaceFilesystem 介面](/reference/workspace/filesystem)，提供以下全部標準檔案系統方法。

* `readFile(path, options?)` - 讀取檔案內容
* `writeFile(path, content, options?)` - 把內容寫入檔案
* `appendFile(path, content)` - 把內容附加到檔案末尾
* `deleteFile(path, options?)` - 刪除檔案
* `copyFile(src, dest, options?)` - 複製檔案
* `moveFile(src, dest, options?)` - 移動檔案或更改檔名
* `mkdir(path, options?)` - 建立目錄
* `rmdir(path, options?)` - 刪除目錄
* `readdir(path, options?)` - 列出目錄的內容
* `exists(path)` - 檢查路徑是否存在
* `stat(path)` - 取得檔案或目錄的元數據

### `init()` {/* #init */}

初始化檔案系統，同時驗證憑證及儲存桶的存取權限。

```typescript
await filesystem.init()
```

### `getInfo()` {/* #getinfo */}

返回這個檔案系統實例的元數據。

```typescript
const info = filesystem.getInfo()
// { id: '...', name: 'S3Filesystem', provider: 's3', status: 'ready' }
```

### `getMountConfig()` {/* #getmountconfig */}

為支援此類檔案系統掛載的 Sandbox 返回掛載配置。

```typescript
const config = filesystem.getMountConfig()
// { type: 's3', bucket: 'my-bucket', region: 'us-east-1', ... }
```

## 掛載到 E2B Sandbox {/* #mounting-in-e2b-sandboxes */}

在 E2B Sandbox 內掛載 S3Filesystem 後，便可把儲存桶當作本機目錄存取。

```typescript
import { Workspace } from '@mastra/core/workspace'
import { S3Filesystem } from '@mastra/s3'
import { E2BSandbox } from '@mastra/e2b'

const workspace = new Workspace({
  mounts: {
    '/data': new S3Filesystem({
      bucket: 'my-bucket',
      region: 'us-east-1',
      accessKeyId: process.env.AWS_ACCESS_KEY_ID,
      secretAccessKey: process.env.AWS_SECRET_ACCESS_KEY,
    }),
  },
  sandbox: new E2BSandbox({ id: 'dev-sandbox' }),
})
```

有關掛載的詳情，請參閱 [E2BSandbox 參考文檔](/integrations/sandboxes/e2b)。
