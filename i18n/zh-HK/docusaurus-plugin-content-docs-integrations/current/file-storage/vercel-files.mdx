# Vercel Files

[FilesSDK](https://files-sdk.dev) 為 S3、Cloudflare R2、Google Cloud Storage、Azure Blob、Vercel Blob、MinIO、本機檔案系統等提供統一的抽象層。你可以將檔案儲存到任何受支援的後端。有關介面的詳情，請參閱 [WorkspaceFilesystem 介面](/reference/workspace/filesystem)。

如要透過同一個適配器，以相同程式碼連接不同的儲存後端，可使用 `FilesSDKFilesystem`。更換底層驅動程式即可沿用現有的 Workspace 設定。如只連接一個後端，並希望直接使用該後端的專用選項，建議選用相應的 Provider，例如 [`S3Filesystem`](/integrations/file-storage/amazon-s3) 或 [`GCSFilesystem`](/integrations/file-storage/google-cloud-storage)。

## 安裝 {/* #installation */}

```bash npm2yarn
npm install @mastra/files-sdk files-sdk
```

`files-sdk` 是對等依賴套件，須配合所選的適配器設定。

## 用法 {/* #usage */}

以所選的適配器建立 FilesSDK 的 `Files` 實例，再把實例傳入 `FilesSDKFilesystem`。

```typescript
import { Agent } from '@mastra/core/agent'
import { Workspace } from '@mastra/core/workspace'
import { FilesSDKFilesystem } from '@mastra/files-sdk'
import { Files } from 'files-sdk'
import { s3 } from 'files-sdk/s3'

const files = new Files({
  adapter: s3({
    bucket: 'my-bucket',
    region: 'us-east-1',
  }),
})

const workspace = new Workspace({
  filesystem: new FilesSDKFilesystem({ files }),
})

const agent = new Agent({
  id: 'file-agent',
  name: 'file-agent',
  model: '__GATEWAY_ANTHROPIC_MODEL_OPUS__',
  workspace,
})
```

### 更換適配器 {/* #swapping-adapters */}

`FilesSDKFilesystem` 支援所有 FilesSDK 適配器。要切換後端，只須更換建立驅動程式的工廠函數。

```typescript
import { Files } from 'files-sdk'
import { r2 } from 'files-sdk/r2'
import { gcs } from 'files-sdk/gcs'
import { azure } from 'files-sdk/azure'
import { neon } from 'files-sdk/neon'
import { fs } from 'files-sdk/fs'

// Cloudflare R2
const r2Files = new Files({ adapter: r2({ accountId, bucket, accessKeyId, secretAccessKey }) })

// Google Cloud Storage
const gcsFiles = new Files({ adapter: gcs({ bucket, projectId }) })

// Azure Blob
const azureFiles = new Files({ adapter: azure({ container, connectionString }) })

// Neon Object Storage (reads AWS_* variables from `neon env pull`)
const neonFiles = new Files({ adapter: neon({ bucket }) })

// Local filesystem (useful for tests and development)
const localFiles = new Files({ adapter: fs({ root: './workspace' }) })
```

有關完整的適配器清單及設定選項，請參閱 [FilesSDK 文件](https://files-sdk.dev)。

### 只讀掛載 {/* #read-only-mounts */}

```typescript
const filesystem = new FilesSDKFilesystem({
  files,
  readOnly: true,
})
```

所有寫入操作（`writeFile`、`appendFile`、`deleteFile`、`copyFile`、`moveFile`、`mkdir`、`rmdir`）均會拋出 `WorkspaceReadOnlyError`，讀取操作則可如常執行。

## 方法 {/* #methods */}

`FilesSDKFilesystem` 實現 [WorkspaceFilesystem 介面](/reference/workspace/filesystem)，並提供所有標準檔案系統方法。

* `readFile(path, options?)` - 讀取檔案內容
* `writeFile(path, content, options?)` - 把內容寫入檔案
* `appendFile(path, content)` - 把內容加到檔案末尾
* `deleteFile(path, options?)` - 刪除檔案
* `copyFile(src, dest, options?)` - 複製檔案
* `moveFile(src, dest, options?)` - 移動或重新命名檔案
* `mkdir(path, options?)` - 建立目錄（在物件儲存中不會執行任何操作）
* `rmdir(path, options?)` - 刪除目錄
* `readdir(path, options?)` - 列出目錄內容
* `exists(path)` - 檢查路徑是否存在
* `stat(path)` - 取得檔案或目錄的元數據

### `init()` {/* #init */}

初始化檔案系統，並驗證目前設定的適配器能否憑所提供的憑證列出物件鍵。

```typescript
await filesystem.init()
```

### `getInfo()` {/* #getinfo */}

傳回此檔案系統實例的元數據。

```typescript
const info = filesystem.getInfo()
// { id: '...', name: 'FilesSDKFilesystem', provider: 'files-sdk', status: 'ready' }
```

### `files` {/* #files */}

底層的 FilesSDK `Files` 實例以公開屬性提供，可用來直接呼叫適配器專用的 API。

```typescript
const url = await filesystem.files.url('reports/q3.pdf')
```

## 物件儲存的行為 {/* #object-store-semantics */}

`FilesSDKFilesystem` 一律把所設定的後端當作物件儲存處理，即使底層適配器採用分層結構（例如 `fs`）。因此，各適配器的行為一致。

* **`mkdir`** 不會執行任何操作。有物件鍵以該目錄路徑作為前綴時，系統便會視該目錄為存在。
* **`exists`** 只會在路徑完全符合某個檔案的鍵，或該路徑是至少一個下層物件鍵的前綴時傳回 `true`。分層適配器中留下的空目錄不算在內。
* **`deleteFile`** 如找不到物件鍵，便會拋出 `FileNotFoundError`，傳入 `{ force: true }` 則例外。
* **`deleteFile`** 若目標是目錄，會交由 `rmdir({ recursive: true })` 處理，與 [`S3Filesystem`](/integrations/file-storage/amazon-s3) 及 [`GCSFilesystem`](/integrations/file-storage/google-cloud-storage) 的行為一致。
* **`moveFile`** 會先執行 `copyFile`，然後執行 `deleteFile`。整個過程並非 **原子操作**。複製成功後若未能刪除來源檔案，目的地檔案及來源檔案均會保留。
* **`appendFile`** 會先讀取內容，再修改及寫回。若同時向同一個物件鍵附加內容，各次寫入可能互相覆蓋。這是物件儲存的固有特性，同樣適用於 FilesSDK 以外的物件儲存工具。
* **`readdir({ recursive: true })`** 會列出中間各層的目錄項目，例如列出 `a/b` 時，也會列出 `a/b/c.txt`。
