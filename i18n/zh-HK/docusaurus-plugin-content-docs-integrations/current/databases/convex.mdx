# Convex

Mastra 使用 [Convex](https://convex.dev) 提供無伺服器儲存。Convex 是一個支援即時同步和自動快取的全端 TypeScript 開發平台。

:::warning[不支援可觀測性]

Convex 儲存**不支援可觀測性範疇的資料**，因此無法持久儲存 `MastraStorageExporter` 匯出的追蹤記錄。如果 Convex 是唯一的儲存 Provider，[Studio](/docs/studio/overview) 的可觀測性功能亦無法運作。要啟用可觀測性，請使用[複合儲存](/reference/storage/composite#specialized-storage-for-observability)，將相關資料傳送至支援這項功能的 Provider，例如 ClickHouse。

:::

:::warning[記錄大小限制]
Convex 規定**每筆記錄不得超過 1 MiB**。如訊息包含以 Base64 編碼的附件，例如圖片，儲存時可能會超出上限。可參閱[處理大型附件](/docs/memory/memory-processors#handling-large-attachments)了解替代做法，例如將附件上載至 S3、Cloudflare R2 或 [Convex 檔案儲存](https://docs.convex.dev/file-storage)等外部儲存服務。
:::

## 安裝 {/* #installation */}

```bash npm2yarn
npm install @mastra/convex@latest
```

## 配置 Convex {/* #convex-setup */}

使用 `ConvexStore` 之前，請先在 Convex 專案內定義資料庫結構和建立儲存處理程式。
以下範例列出 `ConvexStore` 和 `ConvexServerCache` 所需的完整資料庫結構。如只使用 `ConvexStore`，可省略 `mastraCacheTable` 和 `mastraCacheListItemsTable`；如使用 `ConvexServerCache`，則須加入這兩個資料表並建立快取處理程式。

### 1. 定義 Convex 資料庫結構 {/* #1-set-up-convex-schema */}

在 `convex/schema.ts` 內加入以下程式碼：

```typescript
import { defineSchema } from 'convex/server'
import {
  mastraThreadsTable,
  mastraMessagesTable,
  mastraResourcesTable,
  mastraWorkflowSnapshotsTable,
  mastraScoresTable,
  mastraObservationalMemoryTable,
  mastraVectorIndexesTable,
  mastraVectorsTable,
  mastraCacheTable,
  mastraCacheListItemsTable,
  mastraDocumentsTable,
} from '@mastra/convex/schema'

export default defineSchema({
  mastra_threads: mastraThreadsTable,
  mastra_messages: mastraMessagesTable,
  mastra_resources: mastraResourcesTable,
  mastra_workflow_snapshots: mastraWorkflowSnapshotsTable,
  mastra_scorers: mastraScoresTable,
  mastra_observational_memory: mastraObservationalMemoryTable,
  mastra_vector_indexes: mastraVectorIndexesTable,
  mastra_vectors: mastraVectorsTable,
  mastra_cache: mastraCacheTable,
  mastra_cache_list_items: mastraCacheListItemsTable,
  mastra_documents: mastraDocumentsTable,
})
```

### 2. 建立儲存處理程式 {/* #2-create-the-storage-handler */}

在 `convex/mastra/storage.ts` 內加入以下程式碼：

```typescript
import { mastraStorage } from '@mastra/convex/server'

export const handle = mastraStorage
```

如使用 `ConvexServerCache`，請建立 `convex/mastra/cache.ts` 並加入以下程式碼：

```typescript
import { mastraCache } from '@mastra/convex/server'

export const handle = mastraCache
```

### 3. 部署到 Convex {/* #3-deploy-to-convex */}

```bash
npx convex dev
# or for production
npx convex deploy
```

## 用法 {/* #usage */}

```typescript
import { ConvexServerCache, ConvexStore } from '@mastra/convex'

const storage = new ConvexStore({
  id: 'convex-storage',
  deploymentUrl: process.env.CONVEX_URL!,
  adminAuthToken: process.env.CONVEX_ADMIN_KEY!,
})

const cache = new ConvexServerCache({
  deploymentUrl: process.env.CONVEX_URL!,
  adminAuthToken: process.env.CONVEX_ADMIN_KEY!,
})
```

## 建構函數示例 {/* #constructor-examples */}

```ts
import { ConvexServerCache, ConvexStore } from '@mastra/convex'

// Basic configuration
const store = new ConvexStore({
  id: 'convex-storage',
  deploymentUrl: 'https://your-project.convex.cloud',
  adminAuthToken: 'your-admin-token',
})

// With custom storage function path
const storeCustom = new ConvexStore({
  id: 'convex-storage',
  deploymentUrl: 'https://your-project.convex.cloud',
  adminAuthToken: 'your-admin-token',
  storageFunction: 'custom/path:handler',
})

// Server cache for durable stream replay and response caching
const cache = new ConvexServerCache({
  deploymentUrl: 'https://your-project.convex.cloud',
  adminAuthToken: 'your-admin-token',
  cacheFunction: 'mastra/cache:handle',
})
```

## 伺服器快取 {/* #server-cache */}

`ConvexServerCache` 使用 Convex 實現 Mastra 的伺服器快取介面約定。如需持久儲存快取狀態，可用它支援持久化 Agent 的串流恢復、Workflow 串流重播或回應快取等功能。

`ConvexServerCache` 將每個列表項目各自儲存為一份 Convex 文件。這樣可避免用於重播串流的列表在同一份文件內不斷增長，有助於避免超出 Convex 的單筆記錄大小上限。

每個純量快取值及每個列表項目各佔一筆 Convex 記錄，大小均不得超出 Convex 的單筆記錄上限。從非常大的列表重播指定範圍時，仍須遵守 Convex 的查詢限制。

快取清理和 `clear()` 會分批執行，每批設有處理上限。客戶端每次呼叫最多可循環執行 1,000 次 Convex 寫入操作，而每次寫入操作最多可處理 25 個列表項目。`clear()` 清理某個鍵期間，讀取該鍵可能會收到空結果，直至清理完成。

如快取命名空間很大，請逐步清除，或用涵蓋範圍較小的前綴，以免清理操作需時太久。

分批清理期間，快取元資料可能暫時標為內部 `deleted` 狀態。下一輪清理會移除這些記錄。請等 `clear()` 完成後，才寫入使用相同前綴的新值。

`clear()` 只會移除已儲存的 `keyPrefix` 與配置的 `keyPrefix` 完全相同的記錄，不會按字串的共同前綴清除巢狀前綴下的記錄。每次呼叫 `listPush()`，都會按快取所配置的 `ttlMs` 重設列表的有效期。

請使用非空的 `keyPrefix`，除非你有意讓 `clear()` 移除該部署內的所有快取鍵。讀寫期間會逐步回收已到期的列表記錄。`clear()` 會移除屬於該前綴的所有記錄。

`ConvexServerCache` 最適合持久儲存頻率適中的事件，以便日後重播。對於高頻 token 串流，建議將事件分批處理，或採用延遲較低的快取後端。

`ConvexServerCache` 無法取代分散式發佈／訂閱傳輸機制。如應用程式需要跨進程即時傳遞事件，請另行配置適合正式環境使用的發佈／訂閱後端。

## 附加說明 {/* #additional-notes */}

### 資料庫結構管理 {/* #schema-management */}

儲存實現會按 Mastra 的不同範疇使用有類型定義的 Convex 資料表：

| 範疇 | Convex 資料表 | 用途 |
| - | - | - |
| 對話串 | `mastra_threads` | 對話串記錄 |
| 訊息 | `mastra_messages` | 聊天訊息 |
| 資源 | `mastra_resources` | 用戶的工作記憶 |
| 觀察記憶 | `mastra_observational_memory` | 觀察記憶的生成結果 |
| Workflow | `mastra_workflow_snapshots` | Workflow 狀態 |
| 評分器 | `mastra_scorers` | 評估資料 |
| 快取 | `mastra_cache` | 快取值、計數器及列表元資料 |
| 快取項目 | `mastra_cache_list_items` | 快取列表內的項目 |
| 後備儲存 | `mastra_documents` | 未知資料表的資料 |

### 觀察記憶 {/* #observational-memory */}

`ConvexStore` 支援[觀察記憶](/docs/memory/observational-memory)。要啟用這項功能，請在 Convex 資料庫結構加入 `mastraObservationalMemoryTable`，再用 `npx convex deploy` 重新部署。在引入這個資料表前建立的部署，也要同樣更新資料庫結構。

### 架構 {/* #architecture */}

所有設有類型定義的資料表均包含：

* `id` 欄位，儲存 Mastra 的記錄 ID（有別於 Convex 自動產生的 `_id`）
* `by_record_id` 索引，用於按 Mastra ID 快速查找記錄

這個設計符合 Mastra 的儲存約定，同時可用到 Convex 的自動索引和即時功能。

### 環境變數 {/* #environment-variables */}

請為部署設定以下環境變數：

* `CONVEX_URL`：Convex 部署網址
* `CONVEX_ADMIN_KEY`：管理員驗證憑證（可在 Convex 管理介面取得）
