# Cloudflare

Mastra 提供兩種 Cloudflare 儲存實現：

* **Cloudflare KV**（`CloudflareKVStorage`）：全球分佈式鍵值儲存，提供最終一致性
* **Cloudflare Durable Objects**（`CloudflareDOStorage`）：透過 Durable Objects 提供的 SQLite 儲存，具備強一致性

:::warning[不支援可觀測性]

Cloudflare 儲存**不支援儲存可觀測性資料**。如果只使用 Cloudflare 作為儲存服務，便無法持久保存 `MastraStorageExporter` 匯出的追蹤資料，[Studio](/docs/studio/overview) 的可觀測性功能亦無法運作。要啟用可觀測性，請使用[組合儲存](/reference/storage/composite#specialized-storage-for-observability)，將可觀測性資料轉送至 ClickHouse 等支援此功能的儲存服務。

:::

## 安裝 {/* #installation */}

```bash npm2yarn
npm install @mastra/cloudflare@latest
```

## Cloudflare KV 儲存 {/* #cloudflare-kv-storage */}

此儲存實現透過 Cloudflare Workers KV 提供全球分佈式的無伺服器鍵值儲存。

### 用法 {/* #usage */}

```typescript
import { CloudflareKVStorage } from '@mastra/cloudflare/kv'

// --- Example 1: Using Workers Binding ---
const storageWorkers = new CloudflareKVStorage({
  id: 'cloudflare-workers-storage',
  bindings: {
    threads: THREADS_KV, // KVNamespace binding for threads table
    messages: MESSAGES_KV, // KVNamespace binding for messages table
    // Add other tables as needed
  },
  keyPrefix: 'dev_', // Optional: isolate keys per environment
})

// --- Example 2: Using REST API ---
const storageRest = new CloudflareKVStorage({
  id: 'cloudflare-rest-storage',
  accountId: process.env.CLOUDFLARE_ACCOUNT_ID!, // Cloudflare Account ID
  apiToken: process.env.CLOUDFLARE_API_TOKEN!, // Cloudflare API Token
  namespacePrefix: 'dev_', // Optional: isolate namespaces per environment
})
```

### 附加說明 {/* #additional-notes */}

### 資料結構管理 {/* #schema-management */}

此儲存實現會自動建立和更新資料結構，並建立以下資料表：

* `threads`：儲存對話串
* `messages`：儲存每則訊息
* `metadata`：儲存對話串及訊息的額外元資料

### 一致性與資料傳播 {/* #consistency--propagation */}

Cloudflare KV 提供最終一致性。寫入資料後，部分地區可能無法即時讀取該筆資料。

:::warning[在不同 Worker 之間恢復執行]

寫入 KV 的資料可能需時約 60 秒才會傳到其他位置。如果一個 Worker 暫停了某次 Workflow 或[持久化 Agent](/docs/harness/durable-agents) 的執行，而另一個 Worker 隨即恢復執行，例如用戶很快批准了 Tool 呼叫，恢復時可能讀取到較舊的快照。這可能會令恢復失敗並出現 `AGENT_RESUME_NO_SNAPSHOT_FOUND` 或 `WORKFLOW_RUN_NOT_SUSPENDED` 錯誤，亦可能令執行從較早的步驟繼續。

如果暫停和恢復同一次執行的可能是不同的 Worker 或程序，請改用 [Cloudflare Durable Objects 儲存](#cloudflare-durable-objects-storage)。

:::

### 鍵結構與命名空間 {/* #key-structure--namespacing */}

Cloudflare KV 的鍵由可配置的前綴及各資料表專用的格式組成，例如 `threads:threadId`。
部署至 Workers 時，使用 `keyPrefix` 在同一命名空間內隔離資料。透過 REST API 存取時，使用 `namespacePrefix` 為不同環境或應用程式劃分獨立的命名空間。

## Cloudflare Durable Objects 儲存 {/* #cloudflare-durable-objects-storage */}

此實現透過 Cloudflare Durable Objects 提供基於 SQLite 的強一致性儲存，適合需要交易一致性和 SQL 查詢的應用程式。

### 用法 {/* #usage-1 */}

```typescript
import { DurableObject } from 'cloudflare:workers'
import { CloudflareDOStorage } from '@mastra/cloudflare/do'

class AgentDurableObject extends DurableObject<Env> {
  private storage: CloudflareDOStorage

  constructor(ctx: DurableObjectState, env: Env) {
    super(ctx, env)
    this.storage = new CloudflareDOStorage({
      sql: ctx.storage.sql,
      tablePrefix: 'mastra_', // Optional: prefix for table names
    })
  }

  async run() {
    const memory = await this.storage.getStore('memory')
    await memory?.saveThread({
      thread: { id: 'thread-1', resourceId: 'user-1', title: 'Chat', metadata: {} },
    })
  }
}
```

### 強一致性 {/* #strong-consistency */}

Durable Objects 保證強一致性。同一個 Durable Object 內的所有讀寫操作均按順序執行，適合需要快速回應及長時間運作的 Agent。

### SQL 功能 {/* #sql-capabilities */}

Durable Objects 儲存使用 SQLite，可高效執行查詢、篩選和分頁。這些功能是鍵值儲存無法提供的。

## 資料結構管理 {/* #schema-management-1 */}

兩種儲存實現均會自動建立和更新資料結構，並建立以下資料表：

* `threads`：儲存對話串
* `messages`：儲存每則訊息
* `workflow_snapshot`：儲存 Workflow 的執行狀態

## 已棄用的別名 {/* #deprecated-aliases */}

為維持向後兼容，仍可使用以下別名：

```typescript
// These are deprecated - use CloudflareKVStorage and CloudflareDOStorage instead
import { CloudflareStore } from '@mastra/cloudflare/kv' // alias for CloudflareKVStorage
import { DOStore } from '@mastra/cloudflare/do' // alias for CloudflareDOStorage
```
