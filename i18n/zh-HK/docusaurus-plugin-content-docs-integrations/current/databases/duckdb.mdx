# DuckDB

[DuckDB](https://duckdb.org/) 是在應用程式進程內運行的嵌入式分析資料庫。`@mastra/duckdb` 套件為本地開發提供由 OLAP 支援的可觀測性儲存，毋須運行外部服務，便可儲存追蹤數據、日誌、指標、評分及反饋。

如需向量搜尋，請參閱 [DuckDB 向量儲存參考文件](/integrations/vectors/duckdb)。向量儲存使用同一套件內的獨立 API。

## 何時使用 DuckDB {/* #when-to-use-duckdb */}

DuckDB 適合在本地開發可觀測性功能。它內嵌於應用程式，並以檔案儲存數據，毋須另設資料庫伺服器即可啟動。它支援與 ClickHouse 相同的可觀測性訊號，方便在部署至生產環境的後端之前測試儀表板及探索追蹤數據。

DuckDB 目前只實作 `observability` 儲存領域。設定[複合儲存](/reference/storage/composite)時，可配合 [LibSQL](/integrations/databases/libsql) 等儲存適配器，支援 `memory` 和 `workflows`。

:::warning
DuckDB 適合用於開發，不建議用於生產環境。它在應用程式進程內運行，將數據持久儲存在單一本機檔案，無法在使用臨時檔案系統的平台上運作，例如 Railway、Fly.io、Render、Heroku 或無伺服器容器。生產環境的可觀測性儲存請使用 [ClickHouse](/integrations/databases/clickhouse)。
:::

## 安裝 {/* #installation */}

```bash npm2yarn
npm install @mastra/duckdb@latest
```

## 用法 {/* #usage */}

### 在複合儲存中負責可觀測性儲存 {/* #as-the-observability-domain-in-a-composite-store */}

這是本地開發的標準設定。DuckDB 負責可觀測性儲存，LibSQL 負責其餘儲存領域。

```typescript title="src/mastra/index.ts"
import { Mastra } from '@mastra/core'
import { MastraCompositeStore } from '@mastra/core/storage'
import { LibSQLStore } from '@mastra/libsql'
import { DuckDBStore } from '@mastra/duckdb'
import { Observability, MastraStorageExporter } from '@mastra/observability'

export const mastra = new Mastra({
  storage: new MastraCompositeStore({
    id: 'composite-storage',
    default: new LibSQLStore({
      id: 'mastra-storage',
      url: 'file:./mastra.db',
    }),
    domains: {
      observability: new DuckDBStore().observability,
    },
  }),
  observability: new Observability({
    configs: {
      default: {
        serviceName: 'mastra',
        exporters: [new MastraStorageExporter()],
      },
    },
  }),
})
```

透過 `.observability` 屬性可以直接取得可觀測性儲存。亦可呼叫 `getStore()` 取得同一個儲存實例。這個通用方法適用於所有支援複合儲存的適配器：

```typescript
const observability = await new DuckDBStore().getStore('observability')
```

### 獨立使用 {/* #standalone */}

如果只需在 `Mastra` 的複合儲存之外使用可觀測性儲存，可直接建立 `DuckDBStore` 實例，再存取其可觀測性儲存領域：

```typescript
import { DuckDBStore } from '@mastra/duckdb'

const duckdb = new DuckDBStore({ path: './traces.duckdb' })
const observability = duckdb.observability

await observability.init()
```

### 記憶體資料庫 {/* #in-memory-database */}

將路徑設為 `:memory:`，即可使用臨時的 DuckDB 記憶體實例。進程結束後，數據便會消失，適合單元測試及短時間運行的指令碼。

```typescript
const duckdb = new DuckDBStore({ path: ':memory:' })
```

### 底層類型 {/* #lower-level-types */}

`@mastra/duckdb` 亦會匯出 `DuckDBConnection` 和相應的 `DuckDBStorageConfig` 類型。多個 Mastra 儲存實例可透過 `DuckDBConnection` 共用同一個底層資料庫。大部分應用程式毋須直接使用這兩者。

## 支援的儲存領域 {/* #supported-domains */}

DuckDB 目前只實作一個儲存領域：

| 儲存領域 | 是否支援 |
| - | - |
| `observability` | 是 |
| `memory` | 否 |
| `workflows` | 否 |
| `scores` | 否 |
| `agents` | 否 |

如需涵蓋所有儲存領域，請將 `DuckDBStore` 與支援其餘領域的適配器一併使用。本地開發一般會配合 [LibSQL](/integrations/databases/libsql)。

## 初始化 {/* #initialization */}

透過 `MastraCompositeStore` 將可觀測性儲存傳入 `Mastra` 後，該儲存領域會在首次使用時自動初始化。如需在 `Mastra` 之外自行初始化，請呼叫可觀測性儲存的 `init()` 方法：

```typescript
import { DuckDBStore } from '@mastra/duckdb'

const duckdb = new DuckDBStore({ path: './traces.duckdb' })
await duckdb.observability.init()
```

## 可觀測性策略 {/* #observability-strategy */}

DuckDB 支援 `MastraStorageExporter` 採用的 `event-sourced` 策略。這個策略會將 span 暫存於記憶體，再分批寫入已完成的事件，適合開發環境的流量。如需處理生產環境的大量流量，請參閱 [`MastraStorageExporter` 支援的儲存供應商](/docs/observability/integrations/exporters/mastra-storage#storage-provider-support)。
