# 動態資料庫

DynamoDB 儲存實作為 Mastra 提供了高容量、高效能的 NoSQL 資料庫解決方案，使用單表設計模式[ElectroDB](https://electrodb.dev/).

:::警告\[不支援可觀察性]

DynamoDB 存儲**doesn't support the observability domain**. Traces from the `MastraStorageExporter` can't be persisted to DynamoDB, and [工作室的](/docs/studio/overview)可觀察性功能不適用於 DynamoDB 作為您唯一的儲存提供者。若要啟用可觀察性，請使用[複合儲存](/reference/storage/composite#specialized-storage-for-observability)將Observability資料路由到受支援的提供者（例如 ClickHouse）。

:::

:::警告\[物品尺寸限制]
DynamoDB 強制執行**400 KB maximum item size**. This limit can be exceeded when storing messages with base64-encoded attachments such as images. See [Handling large attachments](/docs/memory/memory-processors#handling-large-attachments) for workarounds including uploading attachments to external storage.
:::

## 特徵 {/* #features */}

* 高效的單表設計可滿足所有 Mastra 儲存需求
* 基於 ElectroDB，用於類型安全的 DynamoDB 訪問
* 支援 AWS 憑證、區域和終端節點
* 與 AWS DynamoDB Local 相容進行開發
* 儲存線程、訊息、評估和Workflow數據
* 針對無伺服器環境進行了最佳化
* 可設定 TTL（生存時間），用於每個實體類型的自動資料過期

## 安裝 {/* #installation */}

```bash npm2yarn
npm install @mastra/dynamodb@latest
```

## 先決條件 {/* #prerequisites */}

在使用該軟體包之前，您**must** create a DynamoDB table with a specific structure, including primary keys and Global Secondary Indexes (GSIs). This adapter expects the DynamoDB table and its GSIs to be provisioned externally.

有關使用 AWS CloudFormation 或 AWS CDK 設定表的詳細說明，請參閱[TABLE\_SETUP.md](https://github.com/mastra-ai/mastra/blob/main/stores/dynamodb/TABLE_SETUP.md). Please ensure your table is configured according to those instructions before proceeding.

## 用法 {/* #usage */}

### 基本用法 {/* #basic-usage */}

```typescript
import { Memory } from '@mastra/memory'
import { DynamoDBStore } from '@mastra/dynamodb'

// Initialize the DynamoDB storage
const storage = new DynamoDBStore({
  id: 'dynamodb', // Unique identifier for this storage instance
  config: {
    tableName: 'mastra-single-table', // Name of your DynamoDB table
    region: 'us-east-1', // Optional: AWS region, defaults to 'us-east-1'
    // endpoint: "http://localhost:8000", // Optional: For local DynamoDB
    // credentials: { accessKeyId: "YOUR_ACCESS_KEY", secretAccessKey: "YOUR_SECRET_KEY" } // Optional
  },
})

// Example: Initialize Memory with DynamoDB storage
const memory = new Memory({
  storage,
  options: {
    lastMessages: 10,
  },
})
```

### 使用 DynamoDB Local 進行本機開發 {/* #local-development-with-dynamodb-local */}

對於本機開發，您可以使用[DynamoDB Local](https://docs.aws.amazon.com/amazondynamodb/latest/developerguide/DynamoDBLocal.html).

1. **運行 DynamoDB Local（例如，使用 Docker）：**

   ```bash
   docker run -p 8000:8000 amazon/dynamodb-local
   ```

2. **配置`DynamoDBStore` to use the local endpoint:**

   ```typescript
   import { DynamoDBStore } from '@mastra/dynamodb'

   const storage = new DynamoDBStore({
     id: 'dynamodb-local',
     config: {
       tableName: 'mastra-single-table', // Ensure this table is created in your local DynamoDB
       region: 'localhost', // Can be any string for local, 'localhost' is common
       endpoint: 'http://localhost:8000',
       // For DynamoDB Local, credentials are not typically required unless configured.
       // If you've configured local credentials:
       // credentials: { accessKeyId: "fakeMyKeyId", secretAccessKey: "fakeSecretAccessKey" }
     },
   })
   ```

   您仍需要在本機 DynamoDB 實例中建立表格和 GSI，例如，使用指向本機終端節點的 AWS CLI。

## TTL（生存時間）配置 {/* #ttl-time-to-live-configuration */}

DynamoDB TTL 可讓您在以下用例的指定持續時間後自動刪除項目：

* **成本最佳化**：自動刪除舊資料以降低儲存成本
* **資料生命週期管理**：實施保留政策以確保合規性
* **表現**：防止表無限增長
* **隱私合規性**：指定時間後自動清除個人數據

### 啟用TTL {/* #enabling-ttl */}

要使用 TTL，您必須：

1. **在 DynamoDBStore 中設定 TTL**（如下圖）
2. **在 DynamoDB 表上啟用 TTL**透過 AWS 控制台或 CLI，指定屬性名稱（預設值：`ttl`)

```typescript
import { DynamoDBStore } from '@mastra/dynamodb'

const storage = new DynamoDBStore({
  name: 'dynamodb',
  config: {
    tableName: 'mastra-single-table',
    region: 'us-east-1',
    ttl: {
      // Messages expire after 30 days
      message: {
        enabled: true,
        defaultTtlSeconds: 30 * 24 * 60 * 60, // 30 days
      },
      // Threads expire after 90 days
      thread: {
        enabled: true,
        defaultTtlSeconds: 90 * 24 * 60 * 60, // 90 days
      },
      // Traces expire after 7 days with custom attribute name
      trace: {
        enabled: true,
        attributeName: 'expiresAt', // Custom TTL attribute
        defaultTtlSeconds: 7 * 24 * 60 * 60, // 7 days
      },
      // Workflow snapshots don't expire
      workflow_snapshot: {
        enabled: false,
      },
    },
  },
})
```

### 支援的實體類型 {/* #supported-entity-types */}

可以為以下實體類型配置 TTL：

|實體|說明 |
| - | - |
|`thread` | Conversation threads |
| `message` | Messages within threads |
| `trace` | Observability traces |
| `eval` | Evaluation results |
| `workflow_snapshot` | Workflow state snapshots |
| `resource` | User/resource data |
| `score` | Scoring results |

### 在 DynamoDB 表上啟用 TTL {/* #enabling-ttl-on-your-dynamodb-table */}

在程式碼中設定 TTL 後，您必須在 DynamoDB 表本身上啟用 TTL：

**使用 AWS CLI：**

```bash
aws dynamodb update-time-to-live \
  --table-name mastra-single-table \
  --time-to-live-specification "Enabled=true, AttributeName=ttl"
```

**使用AWS控制台：**

1. 前往 DynamoDB 控制台
2. 選擇您的餐桌
3. 轉到“其他設定”選項卡
4. 在“生存時間 (TTL)”下，選擇“管理 TTL”
5. 啟用 TTL 並指定屬性名稱（預設：`ttl`)

：：：筆記

DynamoDB 會在過期後 48 小時內刪除過期項目。項目在實際刪除之前保持可查詢狀態。

## AWS IAM 權限 {/* #aws-iam-permissions */}

執行程式碼的 IAM 角色或使用者需要適當的權限才能與指定的 DynamoDB 表及其索引互動。以下是政策範例。代替`${YOUR_TABLE_NAME}` with your actual table name and `${YOUR_AWS_REGION}` and `${YOUR_AWS_ACCOUNT_ID}` with appropriate values.

```json
{
  "Version": "2012-10-17",
  "Statement": [
    {
      "Effect": "Allow",
      "Action": [
        "dynamodb:DescribeTable",
        "dynamodb:GetItem",
        "dynamodb:PutItem",
        "dynamodb:UpdateItem",
        "dynamodb:DeleteItem",
        "dynamodb:Query",
        "dynamodb:Scan",
        "dynamodb:BatchGetItem",
        "dynamodb:BatchWriteItem"
      ],
      "Resource": [
        "arn:aws:dynamodb:${YOUR_AWS_REGION}:${YOUR_AWS_ACCOUNT_ID}:table/${YOUR_TABLE_NAME}",
        "arn:aws:dynamodb:${YOUR_AWS_REGION}:${YOUR_AWS_ACCOUNT_ID}:table/${YOUR_TABLE_NAME}/index/*"
      ]
    }
  ]
}
```

## 關鍵考慮因素 {/* #key-considerations */}

在深入了解架構細節之前，在使用 DynamoDB 儲存適配器時請記住以下要點：

* **外部表配置：**&#x9019;個適配器*requires* you to create and configure the DynamoDB table and its Global Secondary Indexes (GSIs) yourself, prior to using the adapter. Follow the guide in [TABLE\_SETUP.md](https://github.com/mastra-ai/mastra/blob/main/stores/dynamodb/TABLE_SETUP.md).
* **單桌設計：**&#x6240;有 Mastra 資料（執行緒、訊息等）都儲存在一張 DynamoDB 表中。這是針對 DynamoDB 進行最佳化的精心設計選擇，與關聯式資料庫方法不同。
* **了解 GSI：**&#x719F;悉 GSI 的結構（根據`TABLE_SETUP.md`) is important for understanding data retrieval and potential query patterns.
* **電子資料庫：**&#x6B64;適配器使用 ElectroDB 管理與 DynamoDB 的交互，為原始 DynamoDB 作業提供抽象層和類型安全性。

## 架構方法 {/* #architectural-approach */}

此儲存適配器利用**single-table design pattern** with [ElectroDB](https://electrodb.dev/), a common and recommended approach for DynamoDB. This differs architecturally from relational database adapters (like `@mastra/pg` or `@mastra/libsql`) that typically use multiple tables, each dedicated to a specific entity (threads, messages, etc.).

這種方法的關鍵面向：

* **DynamoDB 本機：**&#x55AE;表設計針對 DynamoDB 的鍵值和查詢功能進行了最佳化，與模仿關係模型相比，通常會帶來更好的效能和容量。
* **外部表管理：**&#x8207;某些可能提供幫助程式函數以透過程式碼建立表格的適配器不同，此適配器**expects the DynamoDB table and its associated Global Secondary Indexes (GSIs) to be provisioned externally** before use. Please refer to [TABLE\_SETUP.md](https://github.com/mastra-ai/mastra/blob/main/stores/dynamodb/TABLE_SETUP.md) for detailed instructions using tools like AWS CloudFormation or CDK. The adapter focuses solely on interacting with the pre-existing table structure.
* **透過介面保持一致性：**&#x96D6;然底層儲存模型不同，但此適配器遵循相同的標準`MastraStorage` interface as other adapters, ensuring it can be used interchangeably within the Mastra `Memory` component.

### 單一表中的 Mastra 數據 {/* #mastra-data-in-the-single-table */}

在單一 DynamoDB 表中，使用 ElectroDB 管理和區分不同的 Mastra 資料實體（例如執行緒、訊息、追蹤、評估和Workflow）。 ElectroDB 為每種實體類型定義了特定的模型，其中包括獨特的關鍵結構和屬性。它允許適配器在同一個表中有效地儲存和檢索不同的資料類型。

例如，一個`Thread` item might have a primary key like `THREAD#<threadId>`, while a `Message` item belonging to that thread might use `THREAD#<threadId>` as a partition key and `MESSAGE#<messageId>` as a sort key. The Global Secondary Indexes (GSIs), detailed in `TABLE_SETUP.md`, are strategically designed to support common access patterns across these different entities, such as fetching all messages for a thread or querying traces associated with a workflow.

### 單表設計的優點 {/* #advantages-of-single-table-design */}

此實作使用 ElectroDB 的單表設計模式，它在 DynamoDB 環境中提供了多個優勢：

1. **更低的成本（可能）：**&#x66F4;少的表格可以簡化讀取/寫入容量單元 (RCU/WCU) 的配置和管理，尤其是按需容量。
2. **更好的性能：**&#x76F8;關數據可以透過 GSI 共置或高效訪問，從而實現常見訪問模式的快速查找。
3. **簡化管理：**&#x9700;要監控和備份的不同表更少，需要管理的資料也更少。
4. **降低存取模式的複雜性：**&#x45;lectroDB 有助於管理單一表上項目類型和存取模式的複雜性。
5. **交易支援：**&#x5982;果需要，DynamoDB 交易可以跨儲存在相同表格中的不同「實體」類型使用。
