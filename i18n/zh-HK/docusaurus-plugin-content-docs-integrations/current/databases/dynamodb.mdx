# DynamoDB

DynamoDB 儲存介接器以 [ElectroDB](https://electrodb.dev/) 實現單表設計，為 Mastra 提供高容量、高效能的 NoSQL 資料庫儲存。

:::warning[不支援可觀測性]

DynamoDB 儲存**不支援可觀測性資料**。`MastraStorageExporter` 匯出的 Trace 無法持久儲存在 DynamoDB。若 DynamoDB 是唯一的儲存 Provider，[Studio](/docs/studio/overview) 的可觀測性功能便無法使用。要啟用這些功能，可用[複合儲存](/reference/storage/composite#specialized-storage-for-observability)，將可觀測性資料分流至支援此功能的 Provider，例如 ClickHouse。

:::

:::warning[資料項目的大小限制]
DynamoDB 規定**每個資料項目最多 400 KB**。儲存附有 Base64 編碼圖像等附件的訊息時，大小可能超出上限。可參閱[處理大型附件](/docs/memory/memory-processors#handling-large-attachments)，了解將附件上載至外部儲存空間等處理方法。
:::

## 主要功能 {/* #features */}

* 採用高效的單表設計，應付 Mastra 的各類儲存需要
* 以 ElectroDB 提供類型安全的 DynamoDB 存取
* 支援配置 AWS 憑證、區域及端點
* 兼容 AWS DynamoDB Local，方便本機開發
* 儲存對話、訊息、評估及 Workflow 資料
* 為無伺服器環境作出優化
* 可按實體類型配置 TTL（存留時間），讓資料自動到期

## 安裝 {/* #installation */}

```bash npm2yarn
npm install @mastra/dynamodb@latest
```

## 使用前的準備 {/* #prerequisites */}

使用此套件前，**必須**建立符合指定結構的 DynamoDB 資料表，包括主鍵及全域次要索引（GSI）。資料表和索引須在介接器外預先建立。

請先按 [TABLE\_SETUP.md](https://github.com/mastra-ai/mastra/blob/main/stores/dynamodb/TABLE_SETUP.md) 所述，使用 AWS CloudFormation 或 AWS CDK 配置資料表，然後繼續。

## 用法 {/* #usage */}

### 基本用法 {/* #basic-usage */}

```typescript
import { Memory } from '@mastra/memory'
import { DynamoDBStore } from '@mastra/dynamodb'

// Initialize the DynamoDB storage
const storage = new DynamoDBStore({
  id: 'dynamodb', // Unique identifier for this storage instance
  config: {
    tableName: 'mastra-single-table', // Name of your DynamoDB table
    region: 'us-east-1', // Optional: AWS region, defaults to 'us-east-1'
    // endpoint: "http://localhost:8000", // Optional: For local DynamoDB
    // credentials: { accessKeyId: "YOUR_ACCESS_KEY", secretAccessKey: "YOUR_SECRET_KEY" } // Optional
  },
})

// Example: Initialize Memory with DynamoDB storage
const memory = new Memory({
  storage,
  options: {
    lastMessages: 10,
  },
})
```

### 以 DynamoDB Local 進行本機開發 {/* #local-development-with-dynamodb-local */}

開發時可在本機使用 [DynamoDB Local](https://docs.aws.amazon.com/amazondynamodb/latest/developerguide/DynamoDBLocal.html)。

1. **啟動 DynamoDB Local，可使用 Docker。**

   ```bash
   docker run -p 8000:8000 amazon/dynamodb-local
   ```

2. **配置 `DynamoDBStore`，使其使用本機端點。**

   ```typescript
   import { DynamoDBStore } from '@mastra/dynamodb'

   const storage = new DynamoDBStore({
     id: 'dynamodb-local',
     config: {
       tableName: 'mastra-single-table', // Ensure this table is created in your local DynamoDB
       region: 'localhost', // Can be any string for local, 'localhost' is common
       endpoint: 'http://localhost:8000',
       // For DynamoDB Local, credentials are not typically required unless configured.
       // If you've configured local credentials:
       // credentials: { accessKeyId: "fakeMyKeyId", secretAccessKey: "fakeSecretAccessKey" }
     },
   })
   ```

   仍須在本機 DynamoDB 實例內建立資料表及 GSI，例如透過 AWS CLI 指定本機端點來建立。

## 配置 TTL（存留時間） {/* #ttl-time-to-live-configuration */}

DynamoDB 可透過 TTL 在指定時限屆滿後自動刪除資料項目，適用於以下情況。

* **控制成本**：自動刪除舊資料，減省儲存開支
* **管理資料生命週期**：執行資料保留政策，以符合合規要求
* **維持效能**：避免資料表無限增長
* **符合私隱規定**：在指定期限過後自動清除個人資料

### 啟用 TTL {/* #enabling-ttl */}

要使用 TTL，必須完成以下兩項設定。

1. **在 DynamoDBStore 配置 TTL**，做法見下方範例。
2. **以 AWS 管理控制台或 CLI 為 DynamoDB 資料表啟用 TTL**，並指定屬性名稱（預設為 `ttl`）。

```typescript
import { DynamoDBStore } from '@mastra/dynamodb'

const storage = new DynamoDBStore({
  name: 'dynamodb',
  config: {
    tableName: 'mastra-single-table',
    region: 'us-east-1',
    ttl: {
      // Messages expire after 30 days
      message: {
        enabled: true,
        defaultTtlSeconds: 30 * 24 * 60 * 60, // 30 days
      },
      // Threads expire after 90 days
      thread: {
        enabled: true,
        defaultTtlSeconds: 90 * 24 * 60 * 60, // 90 days
      },
      // Traces expire after 7 days with custom attribute name
      trace: {
        enabled: true,
        attributeName: 'expiresAt', // Custom TTL attribute
        defaultTtlSeconds: 7 * 24 * 60 * 60, // 7 days
      },
      // Workflow snapshots don't expire
      workflow_snapshot: {
        enabled: false,
      },
    },
  },
})
```

### 支援的實體類型 {/* #supported-entity-types */}

TTL 可按以下實體類型配置。

| 實體 | 說明 |
| - | - |
| `thread` | 對話 |
| `message` | 對話內的訊息 |
| `trace` | 可觀測性 Trace |
| `eval` | 評估結果 |
| `workflow_snapshot` | Workflow 狀態快照 |
| `resource` | 用戶或資源資料 |
| `score` | 評分結果 |

### 在 DynamoDB 資料表啟用 TTL {/* #enabling-ttl-on-your-dynamodb-table */}

在程式碼配置 TTL 後，仍須在 DynamoDB 資料表上啟用 TTL。

**透過 AWS CLI**

```bash
aws dynamodb update-time-to-live \
  --table-name mastra-single-table \
  --time-to-live-specification "Enabled=true, AttributeName=ttl"
```

**透過 AWS 管理控制台**

1. 前往 DynamoDB 管理控制台。
2. 選擇要配置的資料表。
3. 開啟「其他設定」（Additional settings）分頁。
4. 在「存留時間 (TTL)」（Time to Live (TTL)）一欄，選擇「管理 TTL」（Manage TTL）。
5. 啟用 TTL，並指定屬性名稱（預設為 `ttl`）。

:::note

DynamoDB 會在資料項目到期後 48 小時內刪除項目。在實際刪除前，仍然可以查詢。

:::

## AWS IAM 權限 {/* #aws-iam-permissions */}

用於執行程式碼的 IAM 角色或用戶，須有權操作指定的 DynamoDB 資料表及其索引。以下是政策範例。請將 `${YOUR_TABLE_NAME}` 換成實際資料表名稱，再將 `${YOUR_AWS_REGION}` 和 `${YOUR_AWS_ACCOUNT_ID}` 換成相應的 AWS 區域及帳戶 ID。

```json
{
  "Version": "2012-10-17",
  "Statement": [
    {
      "Effect": "Allow",
      "Action": [
        "dynamodb:DescribeTable",
        "dynamodb:GetItem",
        "dynamodb:PutItem",
        "dynamodb:UpdateItem",
        "dynamodb:DeleteItem",
        "dynamodb:Query",
        "dynamodb:Scan",
        "dynamodb:BatchGetItem",
        "dynamodb:BatchWriteItem"
      ],
      "Resource": [
        "arn:aws:dynamodb:${YOUR_AWS_REGION}:${YOUR_AWS_ACCOUNT_ID}:table/${YOUR_TABLE_NAME}",
        "arn:aws:dynamodb:${YOUR_AWS_REGION}:${YOUR_AWS_ACCOUNT_ID}:table/${YOUR_TABLE_NAME}/index/*"
      ]
    }
  ]
}
```

## 使用時要留意的事項 {/* #key-considerations */}

使用 DynamoDB 儲存介接器時，請留意以下幾點。

* **在外部建立資料表**：使用介接器前，須依照 [TABLE\_SETUP.md](https://github.com/mastra-ai/mastra/blob/main/stores/dynamodb/TABLE_SETUP.md) 自行建立及配置 DynamoDB 資料表和全域次要索引（GSI）。
* **單表設計**：對話、訊息等 Mastra 資料均儲存在同一張 DynamoDB 資料表。這個設計配合 DynamoDB 的特性，有別於關聯式資料庫的做法。
* **了解 GSI**：掌握 `TABLE_SETUP.md` 所述的 GSI 結構，便較容易了解資料的擷取方式及可用的查詢模式。
* **ElectroDB**：介接器利用 ElectroDB 處理與 DynamoDB 的互動，為底層操作提供抽象層和類型安全。

## 架構設計 {/* #architectural-approach */}

儲存介接器透過 [ElectroDB](https://electrodb.dev/) 採用 **單表設計**，是 DynamoDB 常見且建議採用的方式。關聯式資料庫的介接器，例如 `@mastra/pg` 或 `@mastra/libsql`，一般會用多張資料表，分別儲存對話、訊息等實體。

這種架構主要有以下特點。

* **配合 DynamoDB 原生功能**：單表設計針對 DynamoDB 的鍵值存取和查詢能力作出優化，一般比沿用關聯式模型有更好的效能和容量表現。
* **由外部管理資料表**：部分介接器可能提供輔助函數，讓程式碼建立資料表。此介接器只與現有的資料表結構互動，因此 **須在使用前於外部建立 DynamoDB 資料表及相應的全域次要索引（GSI）**。使用 AWS CloudFormation 或 CDK 等工具的詳情，請參閱 [TABLE\_SETUP.md](https://github.com/mastra-ai/mastra/blob/main/stores/dynamodb/TABLE_SETUP.md)。
* **共用介面**：雖然底層儲存模型有別，此介接器與其他介接器同樣遵循 `MastraStorage` 介面，因此可在 Mastra 的 `Memory` 元件中互換使用。

### 如何在單一資料表組織 Mastra 資料 {/* #mastra-data-in-the-single-table */}

在同一張 DynamoDB 資料表內，ElectroDB 負責區分和管理對話、訊息、Trace、評估及 Workflow 等 Mastra 實體。ElectroDB 為各類實體定義各自的模型，指定不同的鍵結構和屬性，令介接器能在同一張表內高效儲存和擷取不同類型的資料。

例如，`Thread` 項目可用 `THREAD#<threadId>` 作為主鍵，而屬於同一對話的 `Message` 項目可用 `THREAD#<threadId>` 作為分區鍵、`MESSAGE#<messageId>` 作為排序鍵。`TABLE_SETUP.md` 詳列的全域次要索引（GSI）是為不同實體的常見存取模式而設，例如擷取某段對話的所有訊息，或查詢與某個 Workflow 有關的 Trace。

### 單表設計的優點 {/* #advantages-of-single-table-design */}

在 DynamoDB 透過 ElectroDB 採用單表設計，可帶來以下好處。

1. **有機會減省成本**：資料表較少，較容易配置及管理讀取和寫入容量單位（RCU/WCU），尤其是在使用按需容量時。
2. **改善效能**：將相關資料集中存放，或透過 GSI 高效存取，可加快常用查詢。
3. **減輕管理負擔**：需要監察及備份的資料表較少，日常管理也更簡單。
4. **簡化存取模式**：ElectroDB 協助管理單一資料表內不同的資料項目類型及存取模式。
5. **支援交易**：有需要時，可使用 DynamoDB 交易處理同一張資料表內不同類型的實體。
