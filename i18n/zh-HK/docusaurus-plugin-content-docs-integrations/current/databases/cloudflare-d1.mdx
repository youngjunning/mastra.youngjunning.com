# Cloudflare D1

透過 Mastra 的 Cloudflare D1 儲存實作，你可以用 D1 作為無伺服器 SQL 資料庫，進行關聯式資料操作並維持交易一致性。

:::warning[不支援可觀測性]

Cloudflare D1 儲存**不支援可觀測性範疇**。`MastraStorageExporter` 匯出的追蹤資料無法持久儲存在 D1。如果只用 D1 作為儲存 Provider，[Studio](/docs/studio/overview) 的可觀測性功能便無法運作。如要啟用可觀測性，請用[複合儲存](/reference/storage/composite#specialized-storage-for-observability)將可觀測性資料轉送至支援此功能的 Provider，例如 ClickHouse。

:::

:::warning[單行資料大小上限]
Cloudflare D1 的**每行資料大小上限為 1 MiB**。如果訊息含有經 Base64 編碼的附件（例如圖片），儲存時便可能超出上限。請參閱[處理大型附件](/docs/memory/memory-processors#handling-large-attachments)，了解上載附件至外部儲存空間等處理方法。
:::

## 安裝 {/* #installation */}

```bash npm2yarn
npm install @mastra/cloudflare-d1@latest
```

## 使用方法 {/* #usage */}

### 配合 Mastra 的 CloudflareDeployer 使用 {/* #using-with-mastra-cloudflaredeployer */}

在 Cloudflare 上使用 Mastra 和 D1Store 時，一般做法是使用 `CloudflareDeployer`。從 `cloudflare:workers` 匯入 `env`，再直接在 `new Mastra({...})` 內初始化 `D1Store`。

```typescript title="src/mastra/index.ts"
import { env } from 'cloudflare:workers'
import { D1Store } from '@mastra/cloudflare-d1'
import { Mastra } from '@mastra/core'
import { CloudflareDeployer } from '@mastra/deployer-cloudflare'

export const mastra = new Mastra({
  storage: new D1Store({ binding: env.DB }),
  deployer: new CloudflareDeployer({
    name: 'my-worker',
    d1_databases: [
      {
        binding: 'DB',
        database_name: 'your-database-name',
        database_id: 'your-database-id',
      },
    ],
  }),
})
```

:::note
使用 `import { env } from 'cloudflare:workers'` 時，必須直接在 `new Mastra({...})` 內初始化 `D1Store`，不可將它另設為模組層級的變數。另一個做法是在 `fetch` 處理函數內，待 `env` 可用後才初始化 `D1Store`。詳情請參閱 [CloudflareDeployer 參考文件](/reference/deployer/cloudflare#cloudflare-bindings)。
:::

### 在不提供 HTTP 路由的 Cloudflare Worker 內使用 {/* #using-in-a-cloudflare-worker-without-http-routes */}

如要直接在 Worker 內呼叫 Mastra，例如執行 Agent 或觸發 Workflow，而毋須提供 HTTP 路由，就不用 `CloudflareDeployer`。從 Worker 的 `env` 參數取得 D1 綁定，再透過程式碼呼叫 Mastra。

```typescript
import { D1Store } from '@mastra/cloudflare-d1'
import { Mastra } from '@mastra/core'

type Env = {
  DB: D1Database
}

export default {
  async fetch(request: Request, env: Env, ctx: ExecutionContext) {
    const mastra = new Mastra({
      storage: new D1Store({ binding: env.DB }),
    })

    const agent = mastra.getAgent('my-agent')
    const result = await agent.generate('Hello')

    return Response.json({ text: result.text })
  },
}
```

### 透過 REST API 存取 {/* #using-with-rest-api */}

在 Node.js、無伺服器函數等 Workers 以外的環境，請透過 REST API 存取 D1：

```typescript
import { D1Store } from '@mastra/cloudflare-d1'

const storage = new D1Store({
  accountId: process.env.CLOUDFLARE_ACCOUNT_ID!, // Cloudflare Account ID
  databaseId: process.env.CLOUDFLARE_D1_DATABASE_ID!, // D1 Database ID
  apiToken: process.env.CLOUDFLARE_API_TOKEN!, // Cloudflare API Token
  tablePrefix: 'dev_', // Optional: isolate tables per environment
})
```

### Wrangler 設定 {/* #wrangler-configuration */}

將 D1 資料庫綁定加入 `wrangler.toml`：

```toml
[[d1_databases]]
binding = "DB"
database_name = "your-database-name"
database_id = "your-database-id"
```

亦可加入 `wrangler.jsonc`：

```jsonc
{
  "d1_databases": [
    {
      "binding": "DB",
      "database_name": "your-database-name",
      "database_id": "your-database-id",
    },
  ],
}
```

## 補充說明 {/* #additional-notes */}

### 資料庫結構管理 {/* #schema-management */}

儲存實作會自動建立和更新資料庫結構，並建立以下資料表：

* `threads`：儲存對話串
* `messages`：儲存每則訊息
* `metadata`：儲存對話串和訊息的額外元數據

### 初始化 {/* #initialization */}

將儲存實例傳入 Mastra 類別後，Mastra 會在執行任何儲存操作前自動呼叫 `init()`：

```typescript
import { Mastra } from '@mastra/core'
import { D1Store } from '@mastra/cloudflare-d1'

type Env = {
  DB: D1Database
}

// In a Cloudflare Worker
export default {
  async fetch(request: Request, env: Env, ctx: ExecutionContext) {
    const storage = new D1Store({
      binding: env.DB,
    })

    const mastra = new Mastra({
      storage, // init() is called automatically
    })

    // Your handler logic here
    return new Response('Success')
  },
}
```

如果直接使用儲存實例而不經 Mastra，就必須自行呼叫 `init()` 來建立資料表：

```typescript
import { D1Store } from '@mastra/cloudflare-d1'

type Env = {
  DB: D1Database
}

// In a Cloudflare Worker
export default {
  async fetch(request: Request, env: Env, ctx: ExecutionContext) {
    const storage = new D1Store({
      id: 'd1-storage',
      binding: env.DB,
    })

    // Required when using storage directly
    await storage.init()

    // Access domain-specific stores via getStore()
    const memoryStore = await storage.getStore('memory')
    const thread = await memoryStore?.getThreadById({ threadId: '...' })

    return new Response('Success')
  },
}
```

:::warning
如未呼叫 `init()`，資料表便不會建立，儲存操作會在沒有提示的情況下失敗，或拋出錯誤。
:::

### 交易與一致性 {/* #transactions--consistency */}

Cloudflare D1 為單行資料操作提供交易保證。你亦可以將多項操作合併為一個工作單元執行：要麼全部成功，要麼全部不生效。

### 建立及遷移資料表 {/* #table-creation--migrations */}

初始化儲存時會自動建立資料表。你可以用 `tablePrefix` 選項分隔不同環境的資料表。如果要新增欄位、更改資料類型或調整索引，這類較複雜的結構變更須手動遷移，並應事先詳細規劃，以免遺失資料。
