# Google Cloud Spanner

Google Cloud Spanner 儲存配接器為 Mastra 提供具強一致性的儲存後端，可透過橫向擴展增加容量。配接器採用 Cloud Spanner 的 GoogleSQL 方言。

## 安裝 {/* #installation */}

```bash npm2yarn
npm install @mastra/spanner@latest
```

## 使用方法 {/* #usage */}

```typescript
import { SpannerStore } from '@mastra/spanner'

const storage = new SpannerStore({
  id: 'spanner-storage',
  projectId: process.env.SPANNER_PROJECT_ID!,
  instanceId: process.env.SPANNER_INSTANCE_ID!,
  databaseId: process.env.SPANNER_DATABASE_ID!,
})
```

使用前必須先建立實例和資料庫。配接器會在首次使用時建立所需的資料表，因此 Spanner 客戶端所用的憑證須具備修改資料庫結構的權限。你亦可在部署期間以權限較高的憑證呼叫一次 `storage.init()`。

## 建構函數示例 {/* #constructor-examples */}

以下是建立 `SpannerStore` 實例的幾種方法：

```typescript
import { Spanner } from '@google-cloud/spanner'
import { SpannerStore } from '@mastra/spanner'

// Using projectId / instanceId / databaseId
const store1 = new SpannerStore({
  id: 'spanner-storage-1',
  projectId: 'my-gcp-project',
  instanceId: 'my-instance',
  databaseId: 'mastra',
})

// Reusing an existing Spanner Database handle
const spanner = new Spanner({ projectId: 'my-gcp-project' })
const database = spanner.instance('my-instance').database('mastra')

const store2 = new SpannerStore({
  id: 'spanner-storage-2',
  database,
})

// Using the local Spanner emulator (set the SPANNER_EMULATOR_HOST env var)
process.env.SPANNER_EMULATOR_HOST = 'localhost:9010'
const store3 = new SpannerStore({
  id: 'spanner-storage-emulator',
  projectId: 'test-project',
  instanceId: 'test-instance',
  databaseId: 'test-db',
  spannerOptions: { servicePath: 'localhost', port: 9010, sslCreds: undefined },
})
```

## 附加說明 {/* #additional-notes */}

### 管理資料庫結構 {/* #schema-management */}

儲存配接器以 GoogleSQL 方言建立以下資料表：

* `mastra_workflow_snapshot`：Workflow 狀態及執行資料
* `mastra_threads`：對話串
* `mastra_messages`：個別訊息
* `mastra_resources`：資源工作記憶
* `mastra_scorers`：評估分數
* `mastra_background_tasks`：Tool 在背景執行的狀態
* `mastra_agents`：Agent 的精簡記錄（ID、狀態及現行版本）
* `mastra_agent_versions`：按版本保存的 Agent 設定快照
* `mastra_mcp_clients` / `mastra_mcp_client_versions`：MCP 客戶端設定及版本紀錄
* `mastra_mcp_servers` / `mastra_mcp_server_versions`：MCP 伺服器設定及版本紀錄
* `mastra_skills` / `mastra_skill_versions`：Skill 記錄及各版本快照（指令、參考資料、指令碼、資源及內容樹）
* `mastra_skill_blobs`：以 SHA-256 雜湊值作為鍵的內容尋址 Blob 儲存，用於保存各版本的 Skill 內容
* `mastra_prompt_blocks` / `mastra_prompt_block_versions`：提示區塊記錄及各版本的內容快照（範本內容、規則及請求上下文結構）
* `mastra_scorer_definitions` / `mastra_scorer_definition_versions`：評分器定義記錄及各版本的設定快照（評審指令、模型、分數範圍、預先配置的設定及預設抽樣）
* `mastra_schedules` / `mastra_schedule_triggers`：由 cron 驅動的 Workflow 排程及觸發紀錄，供 Mastra 內置的 `WorkflowScheduler` 使用
* `mastra_workspaces` / `mastra_workspace_versions`：Workspace 記錄及各版本的設定快照（檔案系統、Sandbox、掛載、搜尋、Skill 及 Tool）
* `mastra_datasets` / `mastra_dataset_items` / `mastra_dataset_versions`：評估資料集、按 SCD-2 保留版本的項目，以及版本快照
* `mastra_experiments` / `mastra_experiment_results`：實驗執行紀錄及各項結果
* `mastra_favorites`：每位用戶收藏的 Agent 和 Skill，反正規化的 `favoriteCount` 由上層記錄保存及維護
* `mastra_channel_installations` / `mastra_channel_config`：多個平台的頻道安裝紀錄及各平台的設定
* `mastra_ai_spans`：用於可觀測性的 AI 追蹤 Span，按每個 Trace 和 Span 分別記錄，為 Studio 的追蹤介面提供資料

資料表以 `STRING(MAX)` 儲存文字及 JSON 資料，亦使用 `INT64`、`FLOAT64`、`BOOL` 和 `TIMESTAMP` 類型。

以下資料表設有 Spanner 特有的 `STORED` 生成欄位。配接器從 JSON 資料取得欄位值，讓常用篩選可利用一般次級索引，免用 `JSON_VALUE` 掃描：

* `mastra_workflow_snapshot.snapshotStatus`：從 `snapshot` 取出 `$.status`，供 `listWorkflowRuns({ status })` 使用。
* `mastra_schedules.target_workflow_id`：從 `target` 取出 `$.workflowId`，供 `listSchedules({ workflowId })` 使用。

配接器在 `init()` 期間以 `ALTER TABLE ... ADD COLUMN IF NOT EXISTS` 加入這兩個欄位。若採用 `initMode: 'validate'`，由外部流程管理資料庫結構，配接器會略過這一步。如相應欄位不存在，配接器會在執行時改以 `JSON_VALUE` 篩選。

配接器不會建立或使用獨立的 schema 命名空間。如需隔離資料，請使用專用資料庫。

### 初始化 {/* #initialization */}

將儲存實例傳入 `Mastra` 類別後，Mastra 會在進行任何儲存操作之前自動呼叫 `init()`：

```typescript
import { Mastra } from '@mastra/core'
import { SpannerStore } from '@mastra/spanner'

const storage = new SpannerStore({
  id: 'spanner-storage',
  projectId: process.env.SPANNER_PROJECT_ID!,
  instanceId: process.env.SPANNER_INSTANCE_ID!,
  databaseId: process.env.SPANNER_DATABASE_ID!,
})

const mastra = new Mastra({
  storage, // init() is called automatically
})
```

若直接使用儲存實例，請在首次操作之前呼叫一次 `init()`。Spanner 不允許同時執行多項資料庫結構變更，所以 `SpannerStore.init()` 會逐一初始化各個儲存範疇。

```typescript
const storage = new SpannerStore({
  id: 'spanner-storage',
  projectId: process.env.SPANNER_PROJECT_ID!,
  instanceId: process.env.SPANNER_INSTANCE_ID!,
  databaseId: process.env.SPANNER_DATABASE_ID!,
})

await storage.init()
const memory = await storage.getStore('memory')
const thread = await memory?.getThreadById({ threadId: '...' })
```

:::warning
若 `disableInit` 為 true，而你沒有呼叫 `init()`，所需的資料表將不存在，儲存操作會失敗。
:::

### GoogleSQL 的特有行為 {/* #googlesql-specifics */}

這個配接器在以下幾方面有別於其他關聯式資料庫配接器：

* 插入或更新使用 `INSERT OR UPDATE`。Spanner 不支援在這類操作中使用 `RETURNING` 子句，因此呼叫端如需寫入後的狀態，須另行讀取。
* Spanner 不支援 `TRUNCATE`。`dangerouslyClearAll()` 會執行 `DELETE WHERE TRUE`。
* 識別字以反引號括起。
* DDL 經由 `database.updateSchema(...)` 套用。這是需時較長的非同步操作。
* Spanner 不支援 `NULLS FIRST/LAST`。配接器會以 `IS NULL` 作為排序鍵，模擬 NULL 值的排序方式。
* Spanner 沒有原生的 JSON 包含比對功能。配接器會將 `listTraces` 的 `metadata` 和 `scope` 篩選條件轉換為逐鍵比較的 `JSON_VALUE(...) = @v`，並將 `tags` 篩選條件轉換為對 `JSON_QUERY_ARRAY(...)` 的結果進行 `EXISTS` 檢查。Postgres 的 `@>` 包含運算子可在一次索引掃描中比對巢狀結構。Spanner 的做法仍適用於大部分單次查詢，但無法表達深層巢狀結構的比對條件。

### 直接存取資料庫 {/* #direct-database-access */}

`SpannerStore` 讓你直接使用底層的 Spanner 客戶端物件：

```typescript
store.database // @google-cloud/spanner Database
store.instance // @google-cloud/spanner Instance (when created internally)
store.spanner // @google-cloud/spanner Spanner client (when created internally)
```

這些物件可用於自訂交易或檢查資料庫結構等進階操作。直接使用資料庫物件會繞過配接器的驗證及 JSON 轉換邏輯。

### 以模擬器進行本機開發 {/* #local-development-with-the-emulator */}

用 Docker 在本機運行 Cloud Spanner 模擬器：

```bash
docker run -p 9010:9010 -p 9020:9020 gcr.io/cloud-spanner-emulator/emulator
```

設定 `SPANNER_EMULATOR_HOST=localhost:9010`，並在啟動應用程式之前建立實例和資料庫：

```bash
gcloud spanner instances create test-instance --config=emulator-config --nodes=1
gcloud spanner databases create test-db --instance=test-instance
```

連接時，在 Node.js 程序中設定同一個環境變數。`@google-cloud/spanner` 客戶端會自動偵測模擬器。
