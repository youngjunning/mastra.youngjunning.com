# CopilotKit

[CopilotKit](https://www.copilotkit.ai/) 提供 React 元件，讓你快速將可自訂的 AI 助手整合到應用程式。配合 Mastra，你可以建立支援雙向狀態同步及互動式 UI 的 AI 應用程式。

CopilotKit 透過 [AG-UI 協定](https://docs.ag-ui.com/)與 Mastra 通訊。`@ag-ui/mastra` 套件將 Mastra Agent 公開為 AG-UI 端點，供 CopilotKit 的 React hook 及元件使用。除了普通聊天，你還可以實現[生成式 UI、人手參與及前端 Tool](#generative-ui)，並將同一個 Agent 部署到 [Slack 等訊息渠道](#channels)。

想進一步了解 CopilotKit 的概念、元件及進階用法，請參閱 [CopilotKit 文件](https://docs.copilotkit.ai/)。

:::info

如果想讓 Mastra 直接在 Next.js API 路由中運行，請參閱 [CopilotKit 快速入門](https://docs.copilotkit.ai/mastra/quickstart)，了解這種全端整合方式。

:::

瀏覽 Mastra 的 [「UI Dojo」](https://ui-dojo.mastra.ai/)，查看 CopilotKit 與 Mastra 整合的實際例子。

## 整合指南 {/* #integration-guide */}

將 Mastra 作為獨立伺服器運行，再將使用 CopilotKit 的 Next.js 前端連接到其 API 端點。

<Steps>
  <StepItem>
    設定目錄結構，例如：

    ```bash
    project-root
    ├── mastra-server
    │   ├── src
    │   │   └── mastra
    │   └── package.json
    └── my-copilot-app
        └── package.json
    ```

    初始化 Mastra 伺服器：

    ```bash npm2yarn
    npx create-mastra@latest
    ```

    此指令會開啟互動式精靈，建立新的 Mastra 專案。按提示建立伺服器專案。

    進入剛建立的 Mastra 伺服器目錄：

    ```bash
    cd mastra-server # Replace with the actual directory name you provided
    ```

    基本的 Mastra 伺服器專案現已準備就緒。

    :::note

    請確保已在 `.env` 檔案中，為所用的 LLM Provider 設定合適的環境變數。

    :::
  </StepItem>

  <StepItem>
    使用 `@ag-ui/mastra` 提供的 `registerCopilotKit()` 輔助函式，為 CopilotKit 前端建立聊天路由。在 Mastra 專案安裝該套件及其對等依賴：

    ```bash npm2yarn
    npm install @ag-ui/mastra @mastra/client-js @mastra/core @ag-ui/core @ag-ui/client @copilotkit/runtime
    ```

    在 `src/mastra/index.ts` 註冊聊天路由：

    ```typescript title="src/mastra/index.ts" {2,7-19}
    import { Mastra } from '@mastra/core/mastra'
    import { registerCopilotKit } from '@ag-ui/mastra/copilotkit'
    // Rest of the imports...

    export const mastra = new Mastra({
      // Rest of the configuration...
      server: {
        cors: {
          origin: '*',
          allowMethods: ['*'],
          allowHeaders: ['*'],
        },
        apiRoutes: [
          registerCopilotKit({
            path: '/copilotkit',
            resourceId: 'weatherAgent',
          }),
        ],
      },
    })
    ```

    這會在 `/copilotkit` 路徑，以 CopilotKit 相容格式公開 Mastra 執行個體中的 Agent。前端使用下文的 `agent` prop 選擇對話的 Agent。請加入 CORS 設定，讓 CopilotKit 前端可以存取 Mastra 伺服器。部署到正式環境時，應將允許的 CORS 來源限制為前端網域。
  </StepItem>

  <StepItem>
    使用以下命令運行 Mastra 伺服器：

    ```bash npm2yarn
    npm run dev
    ```

Mastra 伺服器預設在 `http://localhost:4111` 運行。設定 CopilotKit 前端期間，請保持伺服器運行。
  </StepItem>

  <StepItem>
    返回上一層的專案根目錄。

    ```bash
    cd ..
    ```

    建立名為 `my-copilot-app` 的 Next.js 專案：

    ```bash npm2yarn
    npx create-next-app@latest my-copilot-app
    ```

    進入剛建立的 Next.js 專案目錄：

    ```bash
    cd my-copilot-app
    ```
  </StepItem>

  <StepItem>
    安裝用於顯示聊天介面的 CopilotKit UI 套件：

    ```bash npm2yarn
    npm install @copilotkit/react-ui @copilotkit/react-core
    ```

    開啟 Next.js 應用程式的首頁路由檔案（通常是 `app/page.tsx` 或 `src/app/page.tsx`），用以下程式碼取代原有內容，建立基本的 CopilotKit 聊天介面：

    ```typescript title="app/page.tsx" oxfmt:false
    import { CopilotChat } from '@copilotkit/react-ui'
    import { CopilotKit } from '@copilotkit/react-core'
    import '@copilotkit/react-ui/styles.css'

    export default function Home() {
      return (
        <CopilotKit runtimeUrl="http://localhost:4111/copilotkit" agent="weatherAgent">
          <CopilotChat
            labels={{
              title: 'Weather Agent',
              initial: 'Hi! 👋 Ask me about the weather, forecasts, and climate.',
            }}
          />
        </CopilotKit>
      )
    }
    ```

    `agent` prop 指定路由到哪個 Mastra Agent，其值必須與 Mastra 執行個體 `agents` 對應表中的某個鍵相同。
  </StepItem>

  <StepItem>
    確保 Mastra 伺服器和 CopilotKit 前端都在運作。啟動 Next.js 開發伺服器：

    ```bash npm2yarn
    npm run dev
    ```

    在瀏覽器開啟應用程式，與 Agent 對話。
  </StepItem>
</Steps>

現在，CopilotKit 前端已可與獨立運行的 Mastra Agent 伺服器通訊。

## 聊天介面選項 {/* #chat-ui-options */}

`CopilotChat` 會顯示嵌入頁面、填滿容器高度的聊天介面。CopilotKit 另提供兩種可直接替換的介面，使用相同的 props：

- `CopilotSidebar`：停靠在應用程式側邊的可摺疊面板。
- `CopilotPopup`：按下後開啟聊天視窗的浮動按鈕。

更換元件即可切換介面形式。三者都透過同一個 `CopilotKit` Provider 連接：

```typescript title="app/page.tsx" oxfmt:false
import { CopilotSidebar } from '@copilotkit/react-ui'
import { CopilotKit } from '@copilotkit/react-core'
import '@copilotkit/react-ui/styles.css'

export default function Home() {
  return (
    <CopilotKit runtimeUrl="http://localhost:4111/copilotkit" agent="weatherAgent">
      <CopilotSidebar
        labels={{
          title: 'Weather Agent',
          initial: 'Hi! 👋 Ask me about the weather.',
        }}
      />
      {/* your app */}
    </CopilotKit>
  )
}
```

如要用自己的元件建立完全自訂的聊天 UI，請參閱 [CopilotKit 無介面 UI 指南](https://docs.copilotkit.ai/)。

## 生成式使用者介面 {/* #generative-ui */}

生成式 UI 指由 Agent 協助建立、用戶可以與之互動的介面。CopilotKit 以一條軸線整理這類介面，稱為**生成式 UI 光譜**：一端由開發者控制（每個像素都由你決定），另一端由 Agent 創造（Agent 掌控整個顯示介面）。選擇光譜上的位置，就是在可預測性和涵蓋範圍之間取捨。

這條光譜分為三個層級：

| 層級 | 誰控制介面 | 基本方式 |
| - | - | - |
| **受控** | 元件由你編寫，Agent 選擇使用哪個元件及傳入甚麼資料。 | Tool 呼叫顯示、狀態顯示、推理、將元件作為 Tool |
| **聲明式** | Agent 輸出結構化規格，前端使用你註冊的元件目錄組合介面。 | A2UI（固定 schema 及靈活變體） |
| **開放式** | 介面由其他地方（MCP 伺服器）產生，並在應用程式中隔離運行。 | MCP Apps |

每個層級都使用透過 `registerCopilotKit()` 公開的 Mastra Agent，並在前端配合相應的 CopilotKit hook。完整概念請參閱 CopilotKit 的[生成式 UI 光譜](https://www.copilotkit.ai/generative-ui-spectrum)及[生成式 UI 概覽](https://docs.copilotkit.ai/concepts/generative-ui-overview)。

:::tip

Mastra 的 [UI Dojo](https://ui-dojo.mastra.ai/) 提供可運行的 CopilotKit 例子。原始碼位於 `src/pages/copilot-kit`。

:::

### 受控 {/* #controlled */}

你提供一組固定元件，由 Agent 選擇顯示哪個元件及提供資料。這種可預測、符合品牌規範的方式適合流量大的介面。受控層級的基本方式使用 CopilotKit v2 API，從 `@copilotkit/react-core/v2` 匯入。

#### Tool 呼叫顯示 {/* #tool-call-rendering */}

將 Agent 的 Tool 呼叫顯示為 React 元件。先如常在 Mastra 伺服器定義 Agent 及 Tool：

```typescript title="src/mastra/agents/weather-agent.ts"
import { Agent } from '@mastra/core/agent'
import { weatherTool } from '../tools/weather-tool'

export const weatherAgent = new Agent({
  id: 'weather-agent',
  name: 'Weather Agent',
  instructions: 'Use the weatherTool to fetch current weather data.',
  model: '__GATEWAY_OPENAI_MODEL__',
  tools: { weatherTool },
})
```

在前端使用 `useRenderTool`，按名稱為 Tool 註冊顯示元件。它只負責顯示，不會執行 Tool；`render` 函式會收到 Tool 呼叫的 `status`，並在 Agent 回傳後收到 `result`：

```tsx title="app/page.tsx"
import { z } from 'zod'
import { CopilotChat } from '@copilotkit/react-ui'
import { CopilotKit, useRenderTool } from '@copilotkit/react-core/v2'
import { Weather } from '@/components/weather'

function Chat() {
  useRenderTool(
    {
      name: 'weatherTool',
      parameters: z.object({ location: z.string() }),
      render: ({ status, result }) => {
        if (status !== 'complete') {
          return <div>Retrieving weather...</div>
        }
        return <Weather {...result} />
      },
    },
    [],
  )

  return <CopilotChat labels={{ title: 'Weather Assistant' }} />
}

export default function Page() {
  return (
    <CopilotKit runtimeUrl="http://localhost:4111/copilotkit" agent="weatherAgent">
      <Chat />
    </CopilotKit>
  )
}
```

Mastra 會逐步串流傳送 Tool 呼叫參數，因此參數送達時，`render` 函式會反覆執行，介面亦可在 Agent 運行期間逐步顯示。

#### 將元件作為 Tool {/* #components-as-tools */}

註冊 React 元件，讓 Agent 像呼叫 Tool 一樣呼叫它。CopilotKit 會在聊天內容中顯示元件，並傳入由 Zod schema 定義的具型別 props：

```tsx title="app/page.tsx"
import { z } from 'zod'
import { useComponent } from '@copilotkit/react-core/v2'

const schema = z.object({ text: z.string() })

function Callout({ text }: z.infer<typeof schema>) {
  return <div className="callout">{text}</div>
}

function Chat() {
  useComponent({ name: 'callout', render: Callout, parameters: schema }, [])
  return <CopilotChat labels={{ title: 'Assistant' }} />
}
```

Agent 像呼叫其他 Tool 一樣呼叫 `callout`，CopilotKit 則使用 Agent 傳入的 props 顯示 `Callout`。

#### 狀態渲染 {/* #state-rendering */}

根據 Agent 狀態顯示 UI，並在狀態串流更新時重新顯示。在 Mastra 中，Agent 狀態是它的工作記憶；狀態改變時會串流傳送至用戶端。使用 `useAgent` 讀取狀態；`agent.state` 具響應性，因此元件會自動更新：

```tsx title="app/page.tsx"
import { useAgent } from '@copilotkit/react-core/v2'

function TaskBoard() {
  const { agent } = useAgent()
  const tasks = (agent.state.tasks as any[]) ?? []

  return (
    <ul>
      {tasks.map((task, i) => (
        <li key={i}>
          {task.title}: {task.status}
        </li>
      ))}
    </ul>
  )
}
```

#### 推理 {/* #reasoning */}

推理功能毋須額外設定：Mastra Agent 使用具備推理能力的模型時，`CopilotChat` 會將模型的思考過程作為獨立訊息類型直接顯示在聊天中。如要調整樣式，可將自己的元件傳入 `CopilotChat` 的 `reasoningMessage` 插槽。詳情請參閱 CopilotKit 的[生成式 UI 指南](https://docs.copilotkit.ai/)。

### 聲明式 {/* #declarative */}

你毋須為每個 Tool 註冊固定元件，而是註冊一個具型別基礎元件的目錄，讓 Agent 按每次請求將它們組合成 UI 樹。CopilotKit 稱之為 **A2UI**（Agent-to-UI），包括固定 schema 及靈活變體。它適合那些重視涵蓋範圍、較少要求像素級精確度的長尾輔助互動。

最簡單的方法是將元件目錄傳給 `<CopilotKit>` Provider。只需這個 prop，就能啟用 A2UI 顯示，並將 A2UI Tool 注入 Agent，毋須修改後端：

```tsx title="app/page.tsx"
import { CopilotKit } from '@copilotkit/react-core/v2'
import { myCatalog } from './a2ui-catalog'

export default function Page() {
  return (
    <CopilotKit
      runtimeUrl="http://localhost:4111/copilotkit"
      agent="weatherAgent"
      a2ui={{ catalog: myCatalog }}
    >
      {/* your app */}
    </CopilotKit>
  )
}
```

目錄定義基礎元件及其 schema，也定義各元件的顯示方式。在固定 schema 變體中，元件預先編寫，Agent 的 Tool 只提供資料；靈活變體則讓 Agent 更自由地組合 UI 樹。請參閱 CopilotKit 的 [A2UI 文件](https://docs.copilotkit.ai/a2a/generative-ui/a2ui)。

### 開放式 {/* #open-ended */}

在光譜的另一端，Agent 掌控整個介面：UI 在其他地方產生，再透過 Sandbox 在應用程式中隔離運行。CopilotKit 以 **MCP Apps** 支援這種方式，由 MCP 伺服器提供在應用程式內顯示的 UI。這個層級以確定性換取新穎性，也是光譜中實驗性最強的一端。

最簡單的接入方式毋須改動前端：現有的 `<CopilotKit>` Provider 已足夠。在後端透過 `mcpApps` 選項，為 `registerCopilotKit()` 指定一個或多個 MCP 伺服器；此選項會傳遞至 CopilotKit runtime：

```typescript title="src/mastra/index.ts"
registerCopilotKit({
  path: '/copilotkit',
  resourceId: 'weatherAgent',
  mcpApps: {
    servers: [{ type: 'http', url: 'http://localhost:3108/mcp', serverId: 'my-server' }],
  },
})
```

當 Agent 呼叫 MCP App Tool 時，CopilotKit 會取得該 Tool 的 UI，並在聊天中顯示，毋須額外的前端程式碼。請參閱 CopilotKit 的 [MCP Apps 文件](https://docs.copilotkit.ai/agno/generative-ui/mcp-apps)。

## 應用程式控制與互動 {/* #app-control-and-interactivity */}

有些功能與[生成式 UI](#generative-ui) 光譜相關，卻不屬於其中的顯示層級：它們用來控制應用程式，或在運行途中設置人手確認環節，而非顯示 Agent 輸出。CopilotKit 可以讓 Agent 操作應用程式，亦可以暫停等待用戶。兩種模式都沿用相同的 Mastra 設定。

### 前端 Tool {/* #frontend-tools */}

讓 Agent 可以操作應用程式。透過 `useFrontendTool` 在前端註冊 Tool；Agent 呼叫時，`handler` 會在瀏覽器中執行：

```tsx title="app/page.tsx"
import { CopilotChat } from '@copilotkit/react-ui'
import { CopilotKit, useFrontendTool } from '@copilotkit/react-core'

function Chat() {
  useFrontendTool({
    name: 'colorChangeTool',
    description: 'Changes the background color',
    parameters: [
      { name: 'color', type: 'string', description: 'The color to change to', required: true },
    ],
    handler: ({ color }) => {
      document.body.style.setProperty('--background', color)
    },
  })

  return <CopilotChat labels={{ title: 'Background Color Changer' }} />
}

export default function Page() {
  return (
    <CopilotKit runtimeUrl="http://localhost:4111/copilotkit" agent="bgColorAgent">
      <Chat />
    </CopilotKit>
  )
}
```

對應的 Mastra Agent 是一般 Agent，其指令要求它使用指定顏色呼叫 `colorChangeTool`。

CopilotKit 將前端 Tool 與共享狀態、Agent 上下文一同歸入獨立的[應用程式控制](https://docs.copilotkit.ai/)概念。

### 人手參與 {/* #human-in-the-loop */}

在 Agent 運行途中暫停，待用戶審批、編輯或拒絕後再繼續。使用 `useHumanInTheLoop`：其 `render` 函式會收到 `respond` 回呼；在呼叫它之前，Agent 會一直暫停。

```tsx title="app/page.tsx"
import { CopilotChat } from '@copilotkit/react-ui'
import { CopilotKit, useHumanInTheLoop } from '@copilotkit/react-core'
import { StepsFeedback } from '@/components/steps-feedback'

function Chat() {
  useHumanInTheLoop({
    name: 'generate_task_steps',
    description: 'Generates a list of steps for the user to perform',
    parameters: [
      {
        name: 'steps',
        type: 'object[]',
        attributes: [
          { name: 'description', type: 'string' },
          { name: 'status', type: 'string', enum: ['enabled', 'disabled', 'executing'] },
        ],
      },
    ],
    available: 'enabled',
    // `respond` resumes the agent with the user's edited selection.
    render: ({ args, respond, status }) => (
      <StepsFeedback args={args} respond={respond} status={status} />
    ),
  })

  return <CopilotChat labels={{ title: 'Planning Agent' }} />
}

export default function Page() {
  return (
    <CopilotKit runtimeUrl="http://localhost:4111/copilotkit" agent="planningAgent">
      <Chat />
    </CopilotKit>
  )
}
```

在 `StepsFeedback` 中，讓用戶切換步驟，再呼叫 `respond({ accepted: true, steps })` 恢復 Agent 運行，或呼叫 `respond({ accepted: false })` 拒絕。Agent 會讀取回傳值並據此繼續運行。完整元件請見 [UI Dojo](https://ui-dojo.mastra.ai/)。

上述例子使用客戶端 Tool：Agent 呼叫 `generate_task_steps`，前端透過 `respond` 完成呼叫。Mastra 亦可以在伺服器端暫停，在 Tool 執行前掛起呼叫，等待人手審批或提供輸入。如採用這種方式，後端請參閱 Mastra 的 [Agent 審批](/docs/agents/human-in-the-loop)指南，前端請參閱 CopilotKit 的 [`useHumanInTheLoop`](https://docs.copilotkit.ai/reference/hooks/useHumanInTheLoop) 參考文件。

## 訊息渠道 {/* #channels */}

支援應用程式內 AI 助手的同一個 Mastra Agent，亦可在訊息平台上以機械人身份運行。CopilotKit 的 Channels SDK 可將 Agent 連接到 Slack 等平台，並在渠道內以原生方式處理對話串、Tool 呼叫、豐富的互動訊息及人手審批。

:::info

完整的平台設定請參閱 [CopilotKit Channels 文件](https://docs.copilotkit.ai/slack/mastra)。本節說明 Channels 如何配合 Mastra Agent。

:::

### 運作方式 {/* #how-it-fits-together */}

Mastra Agent 保持在原本的部署位置，透過 `registerCopilotKit()` 以 AG-UI 對外提供服務。渠道是以 `@copilotkit/channels` 建立的獨立常駐程序：接上一個或多個平台轉接器，再將渠道指向 Agent。`createChannel` 接收轉接器陣列，因此單一程序可同時服務多個平台。

安裝 SDK；其中已包含各轉接器所需的功能：

```bash npm2yarn
npm install @copilotkit/channels
```

```typescript title="channel.ts"
import { createChannel, Message, Section } from '@copilotkit/channels'
import { slack } from '@copilotkit/channels/slack'
import { mastraAgent } from './agent' // your AG-UI Mastra agent

const channel = createChannel({
  // Point the channel at your Mastra agent (an AbstractAgent, or a per-thread factory).
  agent: mastraAgent,
  adapters: [
    slack({
      botToken: process.env.SLACK_BOT_TOKEN!,
      appToken: process.env.SLACK_APP_TOKEN!,
    }),
  ],
})

channel.onMention(async ({ thread }) => {
  await thread.runAgent()
})

await channel.start()
```

Agent 接收標準 AG-UI 輸入並發出標準 AG-UI 事件；平台相關機制由轉接器處理，因此同一個 Mastra Agent 毋須改動即可用於各渠道。豐富的訊息以 JSX 編寫，再轉換為各平台的原生格式（例如 Slack 的 Block Kit）；如果平台沒有對應功能，互動卡片亦會適當降級。

### Slack {/* #slack */}

[Slack 快速入門](https://docs.copilotkit.ai/slack/mastra)會帶你從零建立可在頻道中以 `@` 提及的機械人，並加入帶互動按鈕的卡片。Slack 使用 Socket Mode，主動向 Slack 建立對外 WebSocket 連線，因此開發時毋須公開 URL 或通道服務。

在環境中設定 Slack 憑證：

- `SLACK_BOT_TOKEN`：機械人用戶 OAuth 權杖（`xoxb-...`）
- `SLACK_APP_TOKEN`：具有 `connections:write` 權限範圍的應用程式級權杖（`xapp-...`）

### 其他平台 {/* #other-platforms */}

Channels SDK 不只支援 Slack。Microsoft Teams 等平台亦使用同一套 `@copilotkit/channels` API：將對應轉接器加入 `adapters` 陣列，Agent 的其他程式碼便毋須修改。目前支援的平台及各平台的設定方式，請參閱 [CopilotKit Channels 文件](https://docs.copilotkit.ai/slack/mastra)。

### 訊息流程與架構 {/* #message-pipeline-and-architecture */}

託管渠道刻意分開管理憑證。如果 Mastra Agent 使用獨立的模型金鑰及 Tool，這點尤其重要：

- **由你保管** Agent 邏輯、模型憑證及 Tool，並運行渠道程序。
- **由 CopilotKit Intelligence 管理**平台憑證、訊息傳送、註冊、健康狀態及重新連線。

用戶向應用程式發送訊息後，一輪互動便開始。Intelligence 接收平台事件，閘道將這一輪互動交給你正在運行的渠道程序。Mastra Agent 運行並產生回覆，Intelligence 再以平台原生內容送回回覆。平台憑證不會進入 Agent 程序；企業版 Intelligence 亦可自行託管，以符合數據駐留要求。

:::note

預設情況下，互動操作保存在記憶體中，重新啟動後會重設。為渠道配置持久化的操作及狀態儲存（Redis 或 Postgres），才能讓按鈕及各對話串的狀態在重新啟動後保留，並跨多個執行個體共用。

:::

## 配置選項 {/* #configuration-options */}

以下 `registerCopilotKit()` 選項適用於常見的整合情境：

| 選項 | 用途 |
| - | - |
| `path` | 設定路由路徑，例如 `/copilotkit`。 |
| `resourceId` | 限定對話使用的 Mastra memory 範圍。 |
| `cors` | 在 `server.cors` 以外設定個別路由的 CORS。 |
| `setContext` | 在 Agent 運行前填入請求上下文，例如認證資料或各用戶的資源 ID。 |
| `agents` | 提供預先建立的 AG-UI Agent，而非使用已註冊於 Mastra 執行個體的 Agent。 |
| `tracingOptions` | 將 Mastra tracing 選項傳入每次 Agent 運行。 |

預設情況下，端點會公開 Mastra 執行個體中註冊的所有 Agent，前端使用 `agent` prop 選擇其中一個。其他 CopilotKit runtime 選項會傳遞到底層 runtime。例如，`mcpApps` 的用法請參閱[開放式生成式 UI](#open-ended)。

## 部署 {/* #deployment */}

部署整合 CopilotKit 的 Mastra 伺服器時，必須將 `@copilotkit/runtime` 排除在打包結果以外。該套件包含不兼容打包的依賴；如果一併打包，會導致 500 錯誤。

:::note

使用 `mastra dev` 開發時毋須打包，因此不會遇到此問題；但執行 `mastra build` 準備部署時，就會遇到這個問題。

:::

將 `@copilotkit/runtime` 加入打包工具的 externals 設定：

```typescript title="src/mastra/index.ts"
import { Mastra } from '@mastra/core/mastra'

export const mastra = new Mastra({
  bundler: {
    externals: ['@copilotkit/runtime'],
  },
})
```
