# 副駕駛套件

[副駕駛套件](https://www.copilotkit.ai/)提供 React 元件，可將可自訂的 AI 副駕駛快速整合到您的應用程式中。與 Mastra 結合，您可以建立具有雙向狀態同步和互動式 UI 的 AI 應用程式。

CopilotKit 透過[AG-UI protocol](https://docs.ag-ui.com/). The `@ag-ui/mastra`套件將您的 Mastra Agent程式公開為 AG-UI 端點，並且 CopilotKit 的 React 掛鉤和元件使用它。這解鎖了普通聊天之外的一系列體驗：[生成式 UI、人機互動與前端Tool](#generative-ui)，再加上部署相同的Agent[Slack 等訊息傳遞管道](#channels).

參觀[CopilotKit documentation](https://docs.copilotkit.ai/) to learn more about CopilotKit concepts, components, and advanced usage patterns.

:::資訊

對於 Mastra 直接在 Next.js API 路由中運行的全端整合方法，請參閱[CopilotKit Quickstart](https://docs.copilotkit.ai/mastra/quickstart) guide.

:::

參觀馬斯特拉["UI Dojo"](https://ui-dojo.mastra.ai/) to see real-world examples of CopilotKit integrated with Mastra.

## 整合指南 {/* #integration-guide */}

將 Mastra 作為獨立伺服器運行，並將 Next.js 前端（使用 CopilotKit）連接到其 API 端點。

    import { Mastra } from '@mastra/core/mastra'
    import { registerCopilotKit } from '@ag-ui/mastra/copilotkit'
    // Rest of the imports...

    export const mastra = new Mastra({

          allowMethods: ['*'],
          allowHeaders: ['*'],

## 聊天介面選項 {/* #chat-ui-options */}

`CopilotChat`呈現內聯全高聊天。 CopilotKit 提供了另外兩個共享相同 props 的嵌入式表面：

* `CopilotSidebar`：停靠在應用程式側面的可折疊面板。
* `CopilotPopup`：開啟聊天視窗的浮動按鈕。

交換組件以更改表面。所有三個都通過相同的連接`CopilotKit` provider:

```typescript title="app/page.tsx" oxfmt:false
import { CopilotSidebar } from '@copilotkit/react-ui'
import { CopilotKit } from '@copilotkit/react-core'
import '@copilotkit/react-ui/styles.css'

export default function Home() {
  return (
    <CopilotKit runtimeUrl="http://localhost:4111/copilotkit" agent="weatherAgent">
      <CopilotSidebar
        labels={{
          title: 'Weather Agent',
          initial: 'Hi! 👋 Ask me about the weather.',
        }}
      />
      {/* your app */}
    </CopilotKit>
  )
}
```

對於完全自訂的聊天 UI（自帶元件），請參閱[CopilotKit's headless UI guide](https://docs.copilotkit.ai/).

## 生成式使用者介面 {/* #generative-ui */}

生成式 UI 描述了Agent程式幫助創建並且使用者可以與之互動的介面。 CopilotKit 沿著單一軸組織這些介面，即**generative UI spectrum**, which runs from author-controlled (you decide every pixel) to agent-invented (the agent owns the rendered surface). Your position on the axis is a trade-off between predictability and breadth.

此頻譜分為三層：

|等級 |誰控制地表|基元 |
| - | - | - |
|**Controlled** | You wrote the component. The agent picks which one to use and what data to pass. | Tool call rendering, state rendering, reasoning, components as tools |
| **Declarative** | The agent emits a structured spec. The frontend composes it from a catalog you registered. | A2UI (fixed-schema and flexible variants) |
| **Open-ended** | The UI is invented elsewhere (an MCP server) and you sandbox it. | MCP Apps |

每一層都是一個透過揭露的 Mastra 特工`registerCopilotKit()` plus the matching CopilotKit hook on the frontend. For the full concept, see CopilotKit's [generative UI spectrum](https://www.copilotkit.ai/generative-ui-spectrum) and [generative UI overview](https://docs.copilotkit.ai/concepts/generative-ui-overview).

馬斯特拉的[UI Dojo](https://ui-dojo.mastra.ai/) has working CopilotKit examples. Browse the source under `src/pages/copilot-kit`.

:::

### 受控 {/* #controlled */}

您提供一組固定的組件。Agent程式選擇要渲染的元件並提供其資料。這種可預測的、品牌安全的方法非常適合人流量大的表面。受控原語使用 CopilotKit 的 v2 API，從`@copilotkit/react-core/v2`.

#### Tool調用渲染 {/* #tool-call-rendering */}

將Agent程式的Tool呼叫呈現為 React 元件。像平常一樣在 Mastra 伺服器上定義Agent程式和Tool：

```typescript title="src/mastra/agents/weather-agent.ts"
import { Agent } from '@mastra/core/agent'
import { weatherTool } from '../tools/weather-tool'

export const weatherAgent = new Agent({
  id: 'weather-agent',
  name: 'Weather Agent',
  instructions: 'Use the weatherTool to fetch current weather data.',
  model: '__GATEWAY_OPENAI_MODEL__',
  tools: { weatherTool },
})
```

在前端，透過名稱為該Tool註冊一個渲染器`useRenderTool`. It's render-only (it doesn't execute the tool); the `render` function receives the tool call's `status` and, once the agent returns, its `result`:

```tsx title="app/page.tsx"
import { z } from 'zod'
import { CopilotChat } from '@copilotkit/react-ui'
import { CopilotKit, useRenderTool } from '@copilotkit/react-core/v2'
import { Weather } from '@/components/weather'

function Chat() {
  useRenderTool(
    {
      name: 'weatherTool',
      parameters: z.object({ location: z.string() }),
      render: ({ status, result }) => {
        if (status !== 'complete') {
          return <div>Retrieving weather...</div>
        }
        return <Weather {...result} />
      },
    },
    [],
  )

  return <CopilotChat labels={{ title: 'Weather Assistant' }} />
}

export default function Page() {
  return (
    <CopilotKit runtimeUrl="http://localhost:4111/copilotkit" agent="weatherAgent">
      <Chat />
    </CopilotKit>
  )
}
```

由於 Mastra 增量地傳輸Tool呼叫參數，`render` function is called repeatedly as the arguments arrive, so the UI can paint progressively while the agent works.

#### 組件作為Tool {/* #components-as-tools */}

註冊一個React元件並讓Agent將其作為Tool來呼叫。 CopilotKit 將其與類型化 props 內聯渲染（使用 Zod 模式定義）：

```tsx title="app/page.tsx"
import { z } from 'zod'
import { useComponent } from '@copilotkit/react-core/v2'

const schema = z.object({ text: z.string() })

function Callout({ text }: z.infer<typeof schema>) {
  return <div className="callout">{text}</div>
}

function Chat() {
  useComponent({ name: 'callout', render: Callout, parameters: schema }, [])
  return <CopilotChat labels={{ title: 'Assistant' }} />
}
```

Agent調用`callout` like any other tool, and CopilotKit renders `Callout` with the props it passed.

#### 狀態渲染 {/* #state-rendering */}

根據Agent的狀態渲染 UI，並在串流時重新渲染。在 Mastra 上，Agent狀態是Agent的工作內存，在發生變化時串流傳輸到客戶端。閱讀它與`useAgent`; `agent.state` is reactive, so the component updates automatically:

```tsx title="app/page.tsx"
import { useAgent } from '@copilotkit/react-core/v2'

function TaskBoard() {
  const { agent } = useAgent()
  const tasks = (agent.state.tasks as any[]) ?? []

  return (
    <ul>
      {tasks.map((task, i) => (
        <li key={i}>
          {task.title}: {task.status}
        </li>
      ))}
    </ul>
  )
}
```

#### 推理 {/* #reasoning */}

推理是零配置的：當您的 Mastra Agent程式運行具有推理功能的模型時，`CopilotChat` renders the model's thinking inline as a dedicated message type, with no extra code. To restyle it, pass your own component to the `reasoningMessage` slot on `CopilotChat`. See CopilotKit's [generative UI guides](https://docs.copilotkit.ai/) for details.

### 聲明式 {/* #declarative */}

您無需註冊每個Tool的固定組件，而是註冊類型化構建塊的目錄，然後Agent根據請求將它們組裝成 UI 樹。 CopilotKit 稱之為**A2UI** (Agent-to-UI), which has fixed-schema and flexible variants. It suits the long tail of secondary interactions where breadth matters more than pixel-perfection.

阻力最小的方法是將您的目錄傳遞給`<CopilotKit>` provider. That single prop enables A2UI rendering and injects the A2UI tool into your agent, so no backend change is needed:

```tsx title="app/page.tsx"
import { CopilotKit } from '@copilotkit/react-core/v2'
import { myCatalog } from './a2ui-catalog'

export default function Page() {
  return (
    <CopilotKit
      runtimeUrl="http://localhost:4111/copilotkit"
      agent="weatherAgent"
      a2ui={{ catalog: myCatalog }}
    >
      {/* your app */}
    </CopilotKit>
  )
}
```

此目錄定義了圖元（它們的模式）和渲染器（每個圖元的顯示方式）。在固定模式變體中，元件是預先編寫的，Agent的Tool僅提供資料。靈活的變體讓Agent可以更自由地建立樹。請參閱 CopilotKit 的[A2UI documentation](https://docs.copilotkit.ai/a2a/generative-ui/a2ui).

### 開放式 {/* #open-ended */}

在光譜的遠端，Agent擁有整個表面：UI 是在其他地方發明的，並在您的應用程式中沙箱化。 CopilotKit 透過以下方式支援此功能**MCP Apps**, where an MCP server provides UI that renders inside your application. This tier trades determinism for novelty and is the most experimental point on the spectrum.

阻力最小的路徑使前端保持不變：您現有的`<CopilotKit>` provider is enough. On the backend, point `registerCopilotKit()` at one or more MCP servers with the `mcpApps` option (it's forwarded to the CopilotKit runtime):

```typescript title="src/mastra/index.ts"
registerCopilotKit({
  path: '/copilotkit',
  resourceId: 'weatherAgent',
  mcpApps: {
    servers: [{ type: 'http', url: 'http://localhost:3108/mcp', serverId: 'my-server' }],
  },
})
```

當Agent程式呼叫 MCP 應用程式Tool時，CopilotKit 會在聊天中取得並呈現該Tool的 UI，無需額外的前端程式碼。請參閱 CopilotKit 的[MCP Apps documentation](https://docs.copilotkit.ai/agno/generative-ui/mcp-apps).

## 應用程式控制和交互 {/* #app-control-and-interactivity */}

有些功能位於[generative UI](#generative-ui) spectrum rather than on it: they control your app or gate a run instead of rendering agent output. CopilotKit lets the agent act on your application and pause for the user. Both patterns run against the same Mastra setup.

### 前端Tool {/* #frontend-tools */}

讓Agent程式能夠對您的應用程式執行操作。在前端註冊該Tool`useFrontendTool`; the `handler` runs in the browser when the agent calls it:

```tsx title="app/page.tsx"
import { CopilotChat } from '@copilotkit/react-ui'
import { CopilotKit, useFrontendTool } from '@copilotkit/react-core'

function Chat() {
  useFrontendTool({
    name: 'colorChangeTool',
    description: 'Changes the background color',
    parameters: [
      { name: 'color', type: 'string', description: 'The color to change to', required: true },
    ],
    handler: ({ color }) => {
      document.body.style.setProperty('--background', color)
    },
  })

  return <CopilotChat labels={{ title: 'Background Color Changer' }} />
}

export default function Page() {
  return (
    <CopilotKit runtimeUrl="http://localhost:4111/copilotkit" agent="bgColorAgent">
      <Chat />
    </CopilotKit>
  )
}
```

匹配的 Mastra Agent是指示呼叫的普通Agent`colorChangeTool` with the requested color.

CopilotKit 將前端Tool視為其獨立Tool的一部分[App Control](https://docs.copilotkit.ai/) concept, alongside shared state and agent context.

### 人在迴路 {/* #human-in-the-loop */}

在運行中暫停Agent並等待用戶批准、編輯或拒絕，然後再繼續。使用`useHumanInTheLoop`: its `render` function receives a `respond` callback, and the agent's run stays suspended until you call it.

```tsx title="app/page.tsx"
import { CopilotChat } from '@copilotkit/react-ui'
import { CopilotKit, useHumanInTheLoop } from '@copilotkit/react-core'
import { StepsFeedback } from '@/components/steps-feedback'

function Chat() {
  useHumanInTheLoop({
    name: 'generate_task_steps',
    description: 'Generates a list of steps for the user to perform',
    parameters: [
      {
        name: 'steps',
        type: 'object[]',
        attributes: [
          { name: 'description', type: 'string' },
          { name: 'status', type: 'string', enum: ['enabled', 'disabled', 'executing'] },
        ],
      },
    ],
    available: 'enabled',
    // `respond` resumes the agent with the user's edited selection.
    render: ({ args, respond, status }) => (
      <StepsFeedback args={args} respond={respond} status={status} />
    ),
  })

  return <CopilotChat labels={{ title: 'Planning Agent' }} />
}

export default function Page() {
  return (
    <CopilotKit runtimeUrl="http://localhost:4111/copilotkit" agent="planningAgent">
      <Chat />
    </CopilotKit>
  )
}
```

裡面`StepsFeedback`, let the user toggle steps and then call `respond({ accepted: true, steps })` to resume the agent, or `respond({ accepted: false })` to reject. The agent reads the returned value and continues accordingly. See the full component in the [UI Dojo](https://ui-dojo.mastra.ai/).

上面的範例使用了客戶端Tool：Agent呼叫`generate_task_steps` and the frontend fulfills it through `respond`. Mastra can also pause on the server, suspending a tool call before it executes so a human approves or supplies input. For that path, see Mastra's [Agent approval](/docs/agents/human-in-the-loop) guide for the backend side and CopilotKit's [`useHumanInTheLoop`](https://docs.copilotkit.ai/reference/hooks/useHumanInTheLoop) reference for the frontend.

## 頻道 {/* #channels */}

為您的應用程式內副駕駛提供支援的同一個 Mastra Agent程式也可以在訊息傳遞平台中作為機器人運行。 CopilotKit 的 Channels SDK 將您的Agent連接到 Slack 和其他訊息傳遞平台，並在通道中本地處理線程、Tool呼叫、豐富的互動式訊息和人機互動批准。

:::資訊

完整的平台設置位於[CopilotKit Channels documentation](https://docs.copilotkit.ai/slack/mastra). This section shows how Channels fit together with a Mastra agent.

:::

### 它如何組合在一起 {/* #how-it-fits-together */}

您的 Mastra Agent保留在部署的位置，透過 AG-UI 公開`registerCopilotKit()`. A channel is a separate long-running process built with `@copilotkit/channels`: you attach one or more platform adapters and point the channel at your agent. `createChannel` takes an array of adapters, so a single process can serve several platforms at once.

安裝 SDK（每個轉接器均包含電池）：

```bash npm2yarn
npm install @copilotkit/channels
```

```typescript title="channel.ts"
import { createChannel, Message, Section } from '@copilotkit/channels'
import { slack } from '@copilotkit/channels/slack'
import { mastraAgent } from './agent' // your AG-UI Mastra agent

const channel = createChannel({
  // Point the channel at your Mastra agent (an AbstractAgent, or a per-thread factory).
  agent: mastraAgent,
  adapters: [
    slack({
      botToken: process.env.SLACK_BOT_TOKEN!,
      appToken: process.env.SLACK_APP_TOKEN!,
    }),
  ],
})

channel.onMention(async ({ thread }) => {
  await thread.runAgent()
})

await channel.start()
```

Agent接收普通 AG-UI 輸入並發出普通 AG-UI 事件；平台機制位於適配器後面，因此同一個 Mastra Agent在每個通道上運作不變。豐富的訊息被編寫為 JSX 並呈現為每個平台的本機格式（例如 Slack 上的 Block Kit），因此互動卡在沒有同等平台的情況下可以優雅地降級。

### 鬆弛 {/* #slack */}

這[Slack quickstart](https://docs.copilotkit.ai/slack/mastra) takes you from zero to a bot you can `@`-mention in a channel, then adds an interactive button card. Slack runs over Socket Mode, which opens an outbound WebSocket to Slack, so no public URL or tunnel is required during development.

在您的環境中設定 Slack 憑證：

* `SLACK_BOT_TOKEN`：機器人用戶 OAuth 令牌（`xoxb-...`)
* `SLACK_APP_TOKEN`：應用程式級令牌`connections:write` scope (`xapp-...`)

### 其他平台 {/* #other-platforms */}

Channels SDK 不僅限於 Slack。 Microsoft Teams 等其他平台也透過相同的方式運行`@copilotkit/channels` API: add the matching adapter to the `adapters` array and the rest of your agent code stays the same. See the [CopilotKit Channels documentation](https://docs.copilotkit.ai/slack/mastra) for the current platform list and per-platform setup.

### 訊息管道和架構 {/* #message-pipeline-and-architecture */}

託管通道會故意進行憑證分割，當您的 Mastra Agent程式使用單獨的模型金鑰和Tool時，這一點很重要：

* **你保留**Agent邏輯、模型憑證、Tool和通路流程。
* **CopilotKit 情報持有**平台憑證、訊息傳遞、註冊、運作狀況和重新連線。

當用戶向應用程式發送訊息時，回合就開始了。智慧接收平台事件，網關將輪流交給您正在運行的通道進程。您的 Mastra Agent運行並給出答案。然後，智慧將回復作為本機平台內容返回。平台憑證永遠不會進入Agent程式，企業智慧可以自行託管資料駐留。

：：：筆記

預設情況下，交互操作存在於記憶體中並在重新啟動時重置。使用持久操作和狀態儲存（Redis 或 Postgres）支援通道，以便按鈕和每個執行緒狀態在重新啟動後仍然存在並跨越多個實例。

:::

## 配置選項 {/* #configuration-options */}

使用這些`registerCopilotKit()` options for the common integration points:

|選項 |用它來 |
| - | - |
|`path` | Set the route path, such as `/copilotkit`. |
| `resourceId` | Scope Mastra memory for conversations. |
| `cors` | Configure per-route CORS in addition to `server.cors`. |
| `setContext` | Populate request context before agents run, such as auth or per-user resource IDs. |
| `agents` | Provide pre-constructed AG-UI agents instead of the agents registered on the Mastra instance. |
| `tracingOptions` | Forward Mastra tracing options to each agent run. |

預設情況下，端點公開在 Mastra 實例上註冊的每個Agent，前端選擇一個具有`agent` prop. Other CopilotKit runtime options are forwarded to the underlying runtime. For example, see [Open-ended generative UI](#open-ended) for `mcpApps`.

## 部署 {/* #deployment */}

使用 CopilotKit 部署 Mastra 伺服器時，必須排除`@copilotkit/runtime` from the bundle. This package contains dependencies that aren't compatible with bundling and will cause 500 errors if included.

：：：筆記

開發過程中不會出現此問題`mastra dev` since it doesn't require bundling. However, anyone running `mastra build` for deployment will encounter this issue.

:::

添加`@copilotkit/runtime` package to your bundler externals configuration:

```typescript title="src/mastra/index.ts"
import { Mastra } from '@mastra/core/mastra'

export const mastra = new Mastra({
  bundler: {
    externals: ['@copilotkit/runtime'],
  },
})
```
