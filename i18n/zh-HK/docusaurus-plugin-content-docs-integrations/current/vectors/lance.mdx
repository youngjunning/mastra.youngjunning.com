# Lance 向量儲存

LanceVectorStore 類別透過 [LanceDB](https://lancedb.github.io/lancedb/) 提供向量搜尋。LanceDB 是建基於 Lance 欄式格式的嵌入式向量資料庫，為本機開發及正式環境部署提供高效儲存和快速的相似度搜尋。

## 工廠方法 {/* #factory-method */}

LanceVectorStore 以工廠模式建立實例。應使用靜態 create() 方法，而非直接呼叫建構函數。

## 建立實例範例 {/* #constructor-examples */}

可使用靜態 `create()` 方法建立 `LanceVectorStore` 實例：

```ts
import { LanceVectorStore } from '@mastra/lance'

// Connect to a local database
const vectorStore = await LanceVectorStore.create('/path/to/db')

// Connect to a LanceDB cloud database
const cloudStore = await LanceVectorStore.create('db://host:port')

// Connect to a cloud database with options
const s3Store = await LanceVectorStore.create('s3://bucket/db', {
  storageOptions: { timeout: '60s' },
})
```

#### 何時優化 {/* #when-to-optimize */}

`upsert()` 寫入的資料列暫時不在現有向量索引內。`query()` 仍會掃描這些未建立索引的資料列並傳回結果，因此結果保持完整；但未索引資料列越多，查詢便越慢。LanceDB 的 `fastSearch()` 則會完全略過未索引資料列。

`optimize()` 會把新資料列加入現有索引，而不重新訓練索引。如果資料分布有大幅變化，應改用 `deleteIndex()` 及 `createIndex()` 重建索引。

LanceDB 建議在約 100,000 個資料列經修改，或執行 20 次寫入操作後進行優化。可使用 `getIndexCoverage()` 制定自己的優化策略：

```typescript
const [coverage] = await store.getIndexCoverage({ indexName: 'docs' })
const total = coverage.numIndexedRows + coverage.numUnindexedRows

if (coverage.numUnindexedRows >= 1_000 && coverage.numUnindexedRows / total >= 0.1) {
  await store.optimize({ indexName: 'docs' })
}
```

託管版 LanceDB Cloud 及 Enterprise 會自動維護資料表，因此毋須在這些環境呼叫 `optimize()`。

## 最佳實踐 {/* #best-practices */}

* 按使用情境選擇合適的索引類型：
  * 記憶體不受限制時，HNSW 可提供較高召回率及較佳效能
  * 對大型資料集，IVF 可更有效運用記憶體
* 對大型資料集，可考慮調整 `numPartitions` 及 `numSubVectors` 以取得最佳效能
* 使用完資料庫後，呼叫 `close()` 妥善關閉連線
* 以一致的結構儲存元資料，簡化篩選操作
