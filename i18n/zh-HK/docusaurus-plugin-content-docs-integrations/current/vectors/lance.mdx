# 蘭斯矢量店

LanceVectorStore 類別提供向量搜索，使用[LanceDB](https://lancedb.github.io/lancedb/)，一個基於 Lance 柱狀格式建構的嵌入式向量資料庫。它為本地開發和生產部署提供高效的儲存和快速的相似性搜尋。

## 工廠方法 {/* #factory-method */}

LanceVectorStore 使用工廠模式進行建立。你應該使用靜態`create()` method rather than the constructor directly.

## 構造函數範例 {/* #constructor-examples */}

您可以建立一個`LanceVectorStore` instance using the static create method:

```ts
import { LanceVectorStore } from '@mastra/lance'

// Connect to a local database
const vectorStore = await LanceVectorStore.create('/path/to/db')

// Connect to a LanceDB cloud database
const cloudStore = await LanceVectorStore.create('db://host:port')

// Connect to a cloud database with options
const s3Store = await LanceVectorStore.create('s3://bucket/db', {
  storageOptions: { timeout: '60s' },
})
```

#### 何時優化 {/* #when-to-optimize */}

`upsert()`將行寫入現有向量索引之外。`query()` still returns those rows by scanning them without the index, so results stay complete, but queries get slower as unindexed rows grow. LanceDB's `fastSearch()` skips unindexed rows entirely.

`optimize()`將新行新增至現有索引而不重新訓練它。如果您的資料分佈發生了很大變化，請使用以下命令重建索引`deleteIndex()` and `createIndex()` instead.

LanceDB 建議在大約 100,000 個修改行或 20 次寫入操作後進行最佳化。使用`getIndexCoverage()` to build your own policy:

```typescript
const [coverage] = await store.getIndexCoverage({ indexName: 'docs' })
const total = coverage.numIndexedRows + coverage.numUnindexedRows

if (coverage.numUnindexedRows >= 1_000 && coverage.numUnindexedRows / total >= 0.1) {
  await store.optimize({ indexName: 'docs' })
}
```

託管LanceDB Cloud和Enterprise自動維護表，因此您無需調用`optimize()` there.

## 最佳實踐 {/* #best-practices */}

* 使用適合您的用例的索引類型：
  * HNSW 在內存不受限制時提供更好的回憶和性能
  * IVF 可提高大型資料集的記憶體效率
* 為了獲得大型資料集的最佳效能，請考慮調整`numPartitions` and `numSubVectors` values
* 使用`close()` method to properly close connections when done with the database
* 使用一致的模式儲存元資料以簡化過濾操作
