# MongoDB向量存儲

這`MongoDBVector`類別提供向量搜尋使用[MongoDB 向量搜尋](https://www.mongodb.com/docs/atlas/atlas-vector-search/)。它可以在 MongoDB 集合中實現高效的相似性搜尋和元資料過濾。

## 安裝 {/* #installation */}

```bash npm2yarn
npm install @mastra/mongodb@latest
```

## 使用範例 {/* #usage-example */}

```typescript
import { MongoDBVector } from '@mastra/mongodb'

const store = new MongoDBVector({
  id: 'mongodb-vector',
  uri: process.env.MONGODB_URI,
  dbName: process.env.MONGODB_DB_NAME,
})
```

### 自訂嵌入欄位路徑 {/* #custom-embedding-field-path */}

如果您需要將嵌入儲存在嵌套欄位結構中（例如，與現有的 MongoDB 集合整合），請使用`embeddingFieldPath` option:

```typescript
import { MongoDBVector } from '@mastra/mongodb'

const store = new MongoDBVector({
  id: 'mongodb-vector',
  uri: process.env.MONGODB_URI,
  dbName: process.env.MONGODB_DB_NAME,
  embeddingFieldPath: 'text.contentEmbedding', // Store embeddings at text.contentEmbedding
})
```

### `createSearchIndex()` {/* #createsearchindex */}

在支援索引的集合上配置 MongoDB 搜尋（BM25/全文）索引，並將其記錄為文字搜尋索引`textQuery()` and `hybridQuery()` will target.

**託管館藏與自帶館藏：**

* 對於一個**managed** index (created without `collectionName`), `createIndex()` already provisions a *dynamic* full-text index named `${collectionName}_search_index` (covering all string fields). `createSearchIndex()` is therefore only needed when you want a **field-restricted** mapping or a **custom index name**.
* 對於一個**bring-your-own** index (created with `collectionName`), `createIndex()` doesn't auto-create any full-text index. Enabling `textQuery()`/`hybridQuery()` on a caller-owned operational collection is opt-in. Call `createSearchIndex()` explicitly to provision the (billable) text index. Until you do, `textQuery()`/`hybridQuery()` throw a clear error rather than querying a non-existent index.

命名：

* 什麼時候`fields` is provided **without** an explicit `searchIndexName`, the field-mapped index is created under a **distinct** default name (`${collectionName}_${indexName}_search_fields_index`, unique per logical index) so it doesn't collide with a managed collection's auto-created dynamic index and get silently ignored. This distinct index is persisted as the text-search index, so `textQuery()`/`hybridQuery()` use the restricted mapping automatically.
* 什麼時候`searchIndexName` is provided, that exact name is used and persisted. `textQuery()`/`hybridQuery()` resolve the persisted name automatically. You can also override the name per call via their `searchIndexName` / `textSearchIndexName` parameters.

### `deleteIndex()` {/* #deleteindex */}

刪除向量索引。行為取決於索引的創建方式：

* **管理索引**（創建時沒有`collectionName`): drops the entire collection and all its data.
* **自帶索引**（創建於`collectionName`): drops the MongoDB vectorSearch index. If `createSearchIndex()` provisioned a companion full-text search index, it drops that index too. A vectorSearch or full-text index that another logical index on the same collection still references is kept for that index. The caller's operational collection and its documents are preserved. This store never drops a collection it didn't create.

BYO 分類在建立索引時會持久記錄，因此即使透過不同的程序也能正確應用它（例如，由安裝作業建立的索引，後來由長期服務刪除）。始終透過**logical index name** (the `indexName` used at `createIndex`), not the physical collection name.

### `listIndexes()` {/* #listindexes */}

## 自動嵌入 {/* #automated-embedding */}

MongoDB 可以為您產生嵌入。建立索引`autoEmbed` and a Voyage AI model, write plain text through `documents`, and search with `queryText`. No embedding provider runs in your application, and no vectors travel through it.

```typescript
import { MongoDBVector } from '@mastra/mongodb'

const store = new MongoDBVector({
  id: 'mongodb-vector',
  uri: process.env.MONGODB_URI,
  dbName: process.env.MONGODB_DB_NAME,
})

// No `dimension`: the embedding model determines it.
await store.createIndex({
  indexName: 'movies',
  autoEmbed: { model: 'voyage-4' },
  filterFields: ['year'],
})

// Automated Embedding indexes build slower than client-embedded ones.
await store.waitForIndexReady({ indexName: 'movies', timeoutMs: 300000 })

// No `vectors`: MongoDB embeds the text as documents are written.
await store.upsert({
  indexName: 'movies',
  documents: [
    'A lonely astronaut adrift near a strange ocean planet.',
    'A heist crew robs a bank vault in Paris.',
  ],
  metadata: [{ year: 1972 }, { year: 2001 }],
})

// No `queryVector`: MongoDB embeds the query string with the same model.
const results = await store.query({
  indexName: 'movies',
  queryText: 'space opera about isolation',
  topK: 5,
  filter: { year: { $gt: 1970 } },
})
```

任何其他字段`autoEmbed` index definition accepts is forwarded to MongoDB as given, so options added after this release work without a package update. Anything omitted keeps MongoDB's default.

**重要提示：**

* 自動嵌入是**MongoDB Preview feature**. It requires an Atlas cluster with Automated Embedding available, or the `mongodb/mongodb-atlas-local:preview` image for local development. Self-managed deployments need `mongot` configured with a Voyage AI API key.
* Voyage AI API 金鑰必須透過 Atlas UI 進行設定。由 Voyage AI 直接頒發的密鑰會被預設嵌入端點拒絕。
* **MongoDB 將產生的向量儲存在集合之外**，因此文件僅包含文字。`includeVector: true` isn't supported on an `autoEmbed` index and throws.
* 嵌入是異步生成的。即使索引報告就緒，查詢也可以在寫入後短時間內合法地不傳回結果。
* 索引聲明向量場或`autoEmbed` field, never both. Omit `autoEmbed` to keep supplying your own vectors. The client-side path is unchanged.
* 透過`vectors` to an `autoEmbed` index is an error, since they would be written to a field no index reads.
* 什麼時候`document` is the embedded field it's no longer a declared filter field, so `documentFilter` uses the `$match` pre-filter automatically. Metadata filters declared through `filterFields` still push into `$vectorSearch`.
* `updateVector()`拒絕向量更新`autoEmbed` index. Upsert the document with new text instead, and MongoDB re-embeds it.
* `queryVector`仍然適用於`autoEmbed` index, but the vector must come from a compatible model and match the index `quantization`. MongoDB rejects a mismatch.
* 對於文件和查詢，嵌入產生按令牌計費。

## 為現有集合建立索引 {/* #indexing-an-existing-collection */}

您可以在現有操作集合上建立向量索引，而不是使用託管集合。當您想要在 MongoDB 資料庫中已存在的文件中新增向量搜尋功能時，這非常有用。

```typescript
import { MongoDBVector } from '@mastra/mongodb'

const store = new MongoDBVector({
  id: 'mongodb-vector',
  uri: process.env.MONGODB_URI,
  dbName: process.env.MONGODB_DB_NAME,
})

// Create a vector index on an existing 'transactions' collection
await store.createIndex({
  indexName: 'precedents',
  dimension: 1024,
  collectionName: 'transactions', // Use existing collection
  searchIndexName: 'txn_vec_idx', // Custom search index name
})

// Wait for the index to be ready
await store.waitForIndexReady({ indexName: 'precedents' })

// Query using document mode to get full source documents
const hits = await store.query({
  indexName: 'precedents',
  queryVector: embeddings,
  topK: 5,
  metadataMode: 'document', // Returns full document as metadata
})

// hits[0].metadata now contains all fields from the source document
console.log(hits[0].metadata.amount, hits[0].metadata.customField)

// Full-text / hybrid search on a BYO collection is opt-in: provision the text index first.
await store.createSearchIndex({ indexName: 'precedents', fields: ['note'] })
```

**重要提示：**

* 該集合必須已經存在並且包含帶有`embedding` field (or the custom `embeddingFieldPath` you configured)
* 使用時永遠不會建立或刪除集合`collectionName`
* **BYO 索引預設是唯讀的。** `upsert()`, `updateVector()`, `deleteVector()`, and `deleteVectors()` throw a clear error rather than mutating caller-owned operational documents. To let the store write embeddings into (or delete documents from) your collection, opt in explicitly with `createIndex({ ..., allowWrites: true })`. The policy is persisted and survives restarts. Entries written by older versions without the flag are treated as read-only (fail closed).
* 使用`metadataMode: 'document'` when querying to retrieve the full source document as `metadata`
* 在`'document'` mode the embedding is omitted from `metadata` by default; pass `includeVector: true` to retain it (and also expose it as a top-level `vector`)
* **濾`'document'` mode operates on root document fields**，不是嵌套的`metadata.` subdocument. `filter: { lane: 'fraud' }` matches the top-level `lane` field of your operational documents (in the default `'field'` mode, bare fields are rewritten to `metadata.<field>` for managed collections). Both the pushdown and `$match` fallback paths honor this.
* **本國的`ObjectId` `_id`s are supported.**&#x64CD;作性集合通常關鍵在於`ObjectId`; query results coerce `_id` to a string (the `QueryResult.id` contract), and `deleteVector()`/`updateVector()`/`deleteVectors()` accept that string and match the underlying `ObjectId` document. Managed collections (string `_id`s) are unaffected.
* BYO 集合上的全文搜尋和混合搜尋**opt-in**: no full-text index is auto-created, so call `createSearchIndex()` before `textQuery()`/`hybridQuery()`. The full-text index builds asynchronously. Call `waitForSearchIndexReady()` (or pass `waitUntilReady: true`) before an immediate text/hybrid query.
* `deleteIndex()`在 BYO 索引上會刪除向量索引（如果建立了文字索引，則刪除文字索引），但是**preserves** the collection and its documents

## 最佳實踐 {/* #best-practices */}

* 索引過濾器中使用的元資料欄位以獲得最佳查詢效能。
* 在元資料中使用一致的欄位命名以避免意外的查詢結果。
* 定期監控索引和集合統計資料以確保高效搜尋。
* 對現有集合建立索引時，請確保所有文件都具有所需的`embedding` field.

### 向量嵌入`MongoDB` {/* #vector-embeddings-with-mongodb */}

嵌入是記憶體使用的數字向量`semanticRecall` to retrieve related messages by meaning (not keywords).

：：：筆記

建議將 MongoDB 向量搜尋用於生產用途。對於自託管部署，向量搜尋可用於[local Atlas deployments via the Atlas CLI](https://www.mongodb.com/docs/atlas/cli/current/atlas-cli-deploy-local/).

:::

此設定使用 FastEmbed（一種本地嵌入模型）來產生向量嵌入。
要使用它，請安裝`@mastra/fastembed`:

```bash npm2yarn
npm install @mastra/fastembed@latest
```

將以下內容新增至您的Agent程式：

```typescript title="src/mastra/agents/example-mongodb-agent.ts"
import { Memory } from '@mastra/memory'
import { Agent } from '@mastra/core/agent'
import { MongoDBStore, MongoDBVector } from '@mastra/mongodb'
import { fastembed } from '@mastra/fastembed'

export const mongodbAgent = new Agent({
  id: 'mongodb-agent',
  name: 'mongodb-agent',
  instructions:
    'You are an AI agent with the ability to automatically recall memories from previous interactions.',
  model: '__GATEWAY_OPENAI_MODEL__',
  memory: new Memory({
    storage: new MongoDBStore({
      id: 'mongodb-storage',
      uri: process.env.MONGODB_URI!,
      dbName: process.env.MONGODB_DB_NAME!,
    }),
    vector: new MongoDBVector({
      id: 'mongodb-vector',
      uri: process.env.MONGODB_URI!,
      dbName: process.env.MONGODB_DB_NAME!,
    }),
    embedder: fastembed,
    options: {
      lastMessages: 10,
      semanticRecall: {
        topK: 3,
        messageRange: 2,
      },
      generateTitle: true, // generates descriptive thread titles automatically
    },
  }),
})
```
