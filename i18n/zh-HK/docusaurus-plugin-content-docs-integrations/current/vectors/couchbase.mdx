# Couchbase 向量儲存

`CouchbaseVector` 類別透過 [Couchbase Vector Search](https://docs.couchbase.com/server/current/vector-search/vector-search.html) 提供向量搜尋，讓你在現有 Couchbase 集合中有效率地搜尋相似向量。

## 使用要求 {/* #requirements */}

* **Couchbase Server 7.6.4 或更新版本**，或相容的 Capella 叢集
* Couchbase 部署已**啟用 Search Service**

## 安裝 {/* #installation */}

```bash npm2yarn
npm install @mastra/couchbase@latest
```

## 使用範例 {/* #usage-example */}

```typescript
import { CouchbaseVector } from '@mastra/couchbase'

const store = new CouchbaseVector({
  id: 'couchbase-vector',
  connectionString: process.env.COUCHBASE_CONNECTION_STRING,
  username: process.env.COUCHBASE_USERNAME,
  password: process.env.COUCHBASE_PASSWORD,
  bucketName: process.env.COUCHBASE_BUCKET,
  scopeName: process.env.COUCHBASE_SCOPE,
  collectionName: process.env.COUCHBASE_COLLECTION,
})
```

## 方法 {/* #methods */}

### `createIndex()` {/* #createindex */}

在 Couchbase 中建立新的向量索引。

:::note

索引建立是非同步的。呼叫 `createIndex` 後，應等索引就緒才查詢：小型數據集通常需時 1 至 5 秒，大型數據集可能更久。正式環境應輪詢索引狀態，不要只等待固定時間。

:::

### `deleteVectors()` {/* #deletevectors */}

從已設定的 Couchbase 集合中按 ID 刪除向量。傳入非空的 `ids` 陣列可刪除多份文件；不存在的 ID 會被忽略。不支援按篩選條件刪除，傳入 `filter` 會拋出 `MastraError`。`ids` 為空、同時傳入 `ids` 和 `filter`，或兩者都未傳入，也會拋出錯誤。

```typescript
await store.deleteVectors({ indexName: 'my_index', ids: ['vec_1', 'vec_2'] })
```

## 錯誤處理 {/* #error-handling */}

向量儲存會拋出可捕捉的型別化錯誤：

```typescript
try {
  await store.query({
    indexName: 'my_index',
    queryVector: queryVector,
  })
} catch (error) {
  // Handle specific error cases
  if (error.message.includes('Invalid index name')) {
    console.error(
      'Index name must start with a letter or underscore and contain only valid characters.',
    )
  } else if (error.message.includes('Index not found')) {
    console.error('The specified index does not exist')
  } else {
    console.error('Vector store error:', error.message)
  }
}
```

## 注意事項 {/* #notes */}

* **刪除索引：**刪除 Search 索引不會刪除相關 Couchbase 集合中的向量或文件。除非明確刪除，數據仍會保留。
* **所需權限：**Couchbase 用戶須具備連線權限、目標集合的文件讀寫權限（`kv` 角色），以及相關 bucket/scope 的 Search 索引管理權限（`search_admin` 角色）。
* **索引定義與文件結構：**`createIndex` 為 `scopeName.collectionName` 中的文件建立 Search 索引定義，將 `embedding` 欄位建立為向量索引，將 `content` 欄位建立為文字索引。每份文件的向量儲存在 `embedding`，元數據儲存在 `metadata`。若 `metadata` 含有 `text` 屬性，該屬性亦會複製到頂層 `content` 欄位，供文字搜尋使用。
* **複製與持久性：**可考慮使用 Couchbase 內置的複製和持久化功能保障數據持久性，並定期監察索引統計數據，維持搜尋效率。

## 限制 {/* #limitations */}

* 建立索引需要時間，建立後立即查詢可能受到影響。
* 只有在同一個 `CouchbaseVector` 實例上呼叫 `createIndex()` 建立新索引後，寫入時才會檢查向量維度。對現有索引呼叫 `createIndex()` 不會啟用寫入檢查。啟用後，`upsert()` 和 `updateVector()` 遇到維度不符會拋出錯誤。`query()` 一律會按索引維度檢查查詢向量。
* `deleteVectors()` 只支援按 ID 刪除，不支援按元數據篩選條件刪除。
* 向量寫入與索引更新採最終一致性，寫入後無法立即保證強一致性。
