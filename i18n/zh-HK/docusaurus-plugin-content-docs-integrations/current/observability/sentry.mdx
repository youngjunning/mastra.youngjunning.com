# Sentry

[Sentry](https://sentry.io/) 是一個提供 AI 專用追蹤功能的應用程式監察平台。Sentry 匯出器按 OpenTelemetry 語義慣例將 Trace 傳送至 Sentry，方便你查看模型效能、token 用量及 Tool 的執行情況。

## 安裝 {/* #installation */}

```bash npm2yarn
npm install @mastra/sentry@latest
```

## 設定 {/* #configuration */}

### 先決條件 {/* #prerequisites */}

1. 在 [sentry.io](https://sentry.io/) 登記 **Sentry 帳戶**。
2. 在 Project Settings → Client Keys 取得項目的 **DSN**（[數據來源名稱](https://docs.sentry.io/concepts/key-terms/dsn-explainer/)）。
3. 參照以下範例設定**環境變數**。

```bash title=".env"
SENTRY_DSN=https://...@...sentry.io/...

# Optional
SENTRY_ENVIRONMENT=production
SENTRY_RELEASE=1.0.0
```

### 從環境變數讀取設定 {/* #zero-config-setup */}

設好環境變數後，建立匯出器時毋須再傳入設定。

```typescript title="src/mastra/index.ts"
import { Mastra } from '@mastra/core'
import { Observability } from '@mastra/observability'
import { SentryExporter } from '@mastra/sentry'

export const mastra = new Mastra({
  observability: new Observability({
    configs: {
      sentry: {
        serviceName: 'my-service',
        exporters: [new SentryExporter()],
      },
    },
  }),
})
```

### 直接傳入設定 {/* #explicit-configuration */}

你亦可直接向匯出器傳入憑證，這些憑證會優先於環境變數的值。

```typescript title="src/mastra/index.ts"
import { Mastra } from '@mastra/core'
import { Observability } from '@mastra/observability'
import { SentryExporter } from '@mastra/sentry'

export const mastra = new Mastra({
  observability: new Observability({
    configs: {
      sentry: {
        serviceName: 'my-service',
        exporters: [
          new SentryExporter({
            dsn: process.env.SENTRY_DSN!,
            environment: 'production',
            tracesSampleRate: 1.0, // Send 100% of transactions to Sentry
          }),
        ],
      },
    },
  }),
})
```

## 設定選項 {/* #configuration-options */}

### 完整設定 {/* #complete-configuration */}

```typescript
new SentryExporter({
  // Required settings
  dsn: process.env.SENTRY_DSN!, // Data Source Name - tells the SDK where to send events

  // Optional settings
  environment: 'production', // Deployment environment (enables filtering issues and alerts by environment)
  tracesSampleRate: 1.0, // Percentage of transactions sent to Sentry (0.0 = 0%, 1.0 = 100%)
  release: '1.0.0', // Version of your code deployed (helps identify regressions and track deployments)

  // Advanced Sentry options
  options: {
    // Any additional Sentry.NodeOptions
    integrations: [],
    beforeSend: event => event,
    // ... other Sentry SDK options
  },

  // Diagnostic logging
  logLevel: 'info', // debug | info | warn | error
})
```

### 抽樣設定 {/* #sampling-configuration */}

抽樣比率控制傳送至 Sentry 的交易比例。應用程式處理大量交易時，可以調低這個比率。

```typescript
new SentryExporter({
  dsn: process.env.SENTRY_DSN!,
  tracesSampleRate: 0.1, // Send 10% of transactions to Sentry (recommended for high-load backends)
})
```

:::tip
開發期間建議設為 `1.0`（100%）。在生產環境運行的高負載應用程式，建議設為 `0.1` 至 `0.2`（10% 至 20%）。如要完全停用追蹤，請省略 `tracesSampleRate`。設為 `0` 無法完全停用追蹤。
:::

## Span 類型對應關係 {/* #span-type-mapping */}

Mastra 的 Span 類型會自動對應至以下 Sentry 操作。

| Mastra SpanType | Sentry 操作 | 備註 |
| - | - | - |
| `AGENT_RUN` | `gen_ai.invoke_agent` | 包含下層 MODEL\_GENERATION Span 的 token 用量 |
| `MODEL_GENERATION` | `gen_ai.chat` | 包含用量統計及串流數據 |
| `MODEL_STEP` | *（略過）* | 略過此類型以簡化 Trace 層級 |
| `MODEL_CHUNK` | *（略過）* | 數據集中記錄於 MODEL\_GENERATION |
| `TOOL_CALL` | `gen_ai.execute_tool` | 記錄 Tool 的執行情況，包括輸入及輸出 |
| `MCP_TOOL_CALL` | `gen_ai.execute_tool` | 記錄 MCP Tool 的執行情況 |
| `WORKFLOW_RUN` | `workflow.run` | |
| `WORKFLOW_STEP` | `workflow.step` | |
| `WORKFLOW_CONDITIONAL` | `workflow.conditional` | |
| `WORKFLOW_CONDITIONAL_EVAL` | `workflow.conditional` | |
| `WORKFLOW_PARALLEL` | `workflow.parallel` | |
| `WORKFLOW_LOOP` | `workflow.loop` | |
| `WORKFLOW_SLEEP` | `workflow.sleep` | |
| `WORKFLOW_WAIT_EVENT` | `workflow.wait` | |
| `PROCESSOR_RUN` | `ai.processor` | |
| `GENERIC` | `ai.span` | |

## OpenTelemetry 語義慣例 {/* #opentelemetry-semantic-conventions */}

匯出器遵循標準 GenAI 語義慣例，並採用 Sentry 專用屬性。

**MODEL\_GENERATION Span**

- `gen_ai.system`：模型供應商，例如 `openai` 或 `anthropic`
- `gen_ai.request.model`：請求指定的模型識別碼，例如 `gpt-5.4`
- `gen_ai.response.model`：生成回應所用的模型
- `gen_ai.response.text`：回應的文字內容
- `gen_ai.response.tool_calls`：生成回應期間發出的 Tool 調用（JSON 陣列）
- `gen_ai.usage.input_tokens`：輸入 token 數量
- `gen_ai.usage.output_tokens`：輸出 token 數量
- `gen_ai.request.temperature`：溫度參數
- `gen_ai.request.stream`：請求有否要求以串流方式傳送回應
- `gen_ai.request.messages`：輸入訊息或提示（JSON）
- `gen_ai.completion_start_time`：收到首個 token 的時間

**TOOL\_CALL Span**

- `gen_ai.tool.name`：Tool 識別碼
- `gen_ai.tool.type`：`function`
- `gen_ai.tool.call.id`：Tool 調用 ID
- `gen_ai.tool.input`：Tool 輸入（JSON）
- `gen_ai.tool.output`：Tool 輸出（JSON）
- `tool.success`：Tool 調用是否成功

**AGENT\_RUN Span**

- `gen_ai.agent.name`：Agent 識別碼
- `gen_ai.pipeline.name`：在 Sentry AI 介面顯示的 Agent 名稱
- `gen_ai.agent.instructions`：Agent 指令
- `gen_ai.response.model`：下層模型生成 Span 記錄的模型
- `gen_ai.response.text`：下層模型生成 Span 記錄的輸出文字
- `gen_ai.usage.*`：下層模型生成 Span 記錄的 token 用量

## 功能 {/* #features */}

- **分層追蹤**。保留 Span 之間的父子關係。
- **Token 用量追蹤**。自動追蹤每次模型生成所用的 token 數量。
- **Tool 調用追蹤**。記錄 Tool 的執行情況，連同輸入及輸出。
- **串流支援**。匯總串流回應。
- **錯誤追蹤**。自動記錄錯誤狀態並捕捉例外。
- **Workflow 支援**。追蹤 Workflow 的各個執行步驟。
- **簡化層級**。略過 MODEL\_STEP 和 MODEL\_CHUNK Span，減少 Trace 內的冗餘記錄。
