# Langfuse

[Langfuse](https://langfuse.com/) 是為 LLM 應用而設的開源可觀測性平台。Langfuse 匯出器會把 Trace 傳送至 Langfuse，讓你詳細查看模型效能、token 用量和對話流程。

## 安裝 {/* #installation */}

```bash npm2yarn
npm install @mastra/langfuse@latest
```

## 設定 {/* #configuration */}

### 先決條件 {/* #prerequisites */}

1. **Langfuse 帳戶**：到 [cloud.langfuse.com](https://cloud.langfuse.com) 登記帳戶，或自行託管 Langfuse。
2. **API 密鑰**：在 Langfuse 的 Settings → API Keys 建立一對公開密鑰和秘密密鑰。
3. **環境變數**：以環境變數設定憑證。

```bash title=".env"
LANGFUSE_PUBLIC_KEY=pk-lf-xxxxxxxxxxxx
LANGFUSE_SECRET_KEY=sk-lf-xxxxxxxxxxxx
LANGFUSE_BASE_URL=https://cloud.langfuse.com  # Or your self-hosted URL
```

### 毋須額外設定的用法 {/* #zero-config-setup */}

設好環境變數後，毋須傳入任何設定便可使用匯出器：

```typescript title="src/mastra/index.ts"
import { Mastra } from '@mastra/core'
import { Observability } from '@mastra/observability'
import { LangfuseExporter } from '@mastra/langfuse'

export const mastra = new Mastra({
  observability: new Observability({
    configs: {
      langfuse: {
        serviceName: 'my-service',
        exporters: [new LangfuseExporter()],
      },
    },
  }),
})
```

### 明確指定設定 {/* #explicit-configuration */}

你亦可直接傳入憑證，其值會優先於環境變數：

```typescript title="src/mastra/index.ts"
import { Mastra } from '@mastra/core'
import { Observability } from '@mastra/observability'
import { LangfuseExporter } from '@mastra/langfuse'

export const mastra = new Mastra({
  observability: new Observability({
    configs: {
      langfuse: {
        serviceName: 'my-service',
        exporters: [
          new LangfuseExporter({
            publicKey: process.env.LANGFUSE_PUBLIC_KEY!,
            secretKey: process.env.LANGFUSE_SECRET_KEY!,
            baseUrl: process.env.LANGFUSE_BASE_URL,
            environment: process.env.NODE_ENV,
            release: process.env.GIT_COMMIT,
          }),
        ],
      },
    },
  }),
})
```

## 設定選項 {/* #configuration-options */}

### 即時模式和批次模式 {/* #realtime-vs-batch-mode */}

Langfuse 匯出器支援兩種模式傳送 Trace：

#### 即時模式（開發） {/* #realtime-mode-development */}

Trace 會即時顯示在 Langfuse 儀表板，適合用於偵錯：

```typescript
new LangfuseExporter({
  publicKey: process.env.LANGFUSE_PUBLIC_KEY!,
  secretKey: process.env.LANGFUSE_SECRET_KEY!,
  realtime: true, // Flush after each event
})
```

#### 批次模式（正式環境） {/* #batch-mode-production */}

匯出器會自動分批傳送 Trace，以改善效能：

```typescript
new LangfuseExporter({
  publicKey: process.env.LANGFUSE_PUBLIC_KEY!,
  secretKey: process.env.LANGFUSE_SECRET_KEY!,
  realtime: false, // Default - batch traces
})
```

#### 按 Trace 流量調整批次設定 {/* #batch-tuning-for-high-volume-traces */}

自行託管 Langfuse，或串流執行每秒產生大量 span 時，可調整 OTEL 的批次大小和送出間隔，減輕 Langfuse 資料接收端點的請求負荷：

```typescript
new LangfuseExporter({
  publicKey: process.env.LANGFUSE_PUBLIC_KEY!,
  secretKey: process.env.LANGFUSE_SECRET_KEY!,
  flushAt: 500, // Maximum spans per OTEL export batch
  flushInterval: 20, // Maximum seconds between flushes
})
```

如要完全排除產生量大的 span 類型，例如串流回應中的 `MODEL_CHUNK` span，請在可觀測性設定內使用 [`excludeSpanTypes` 選項](/reference/observability/tracing/span-filtering)：

```typescript
import { SpanType } from '@mastra/core/observability'

new Observability({
  configs: {
    langfuse: {
      serviceName: 'my-service',
      exporters: [new LangfuseExporter()],
      excludeSpanTypes: [SpanType.MODEL_CHUNK],
    },
  },
})
```

### 完整設定 {/* #complete-configuration */}

```typescript
new LangfuseExporter({
  // Required credentials
  publicKey: process.env.LANGFUSE_PUBLIC_KEY!,
  secretKey: process.env.LANGFUSE_SECRET_KEY!,

  // Optional settings
  baseUrl: process.env.LANGFUSE_BASE_URL, // Default: https://cloud.langfuse.com
  realtime: process.env.NODE_ENV === 'development', // Dynamic mode selection
  flushAt: 500, // Maximum spans per OTEL export batch
  flushInterval: 20, // Maximum seconds between flushes
  logLevel: 'info', // Diagnostic logging: debug | info | warn | error

  // Langfuse-specific settings
  environment: process.env.NODE_ENV, // Shows in Langfuse UI for filtering
  release: process.env.GIT_COMMIT, // Git commit hash for version tracking
})
```

## 按 Agent 設定評估範圍 {/* #scoping-evaluators-per-agent */}

Langfuse 評估器（例如 LLM-as-a-Judge）可透過篩選條件，只評估指定的 Trace。Mastra 的 Langfuse 匯出器會自動為每個 Trace 標示發起執行的 Agent 或 Workflow，讓 Trace 層級的篩選條件配對至相應的執行紀錄。

如 Trace 的根 span 是 `AGENT_RUN`，匯出器會設定以下欄位：

* `langfuse.trace.name`：Agent 名稱。如無設定名稱，則使用 Agent ID。
* `langfuse.trace.metadata.agentId`：Agent ID。
* `langfuse.trace.metadata.agentName`：Agent 名稱。

`WORKFLOW_RUN` 根 span 亦按相同方式處理，匯出器會設定 `langfuse.trace.metadata.workflowId` 和 `langfuse.trace.metadata.workflowName`。

如要把評估範圍限於指定 Agent，可在 Langfuse 設定以下其中一項篩選條件：

* **Trace name（Trace 名稱）**：等於 Agent 名稱，例如 `weather-agent`。
* **Metadata（元資料）**：`agentId` 等於 Agent ID。

Langfuse 評估器的 Trace 名稱下拉選單會列出所有已出現的不同值。Agent 產生至少一個 Trace 後，便會在選單內有對應的選項。

如透過 `mastra.metadata.traceName` 自訂 `traceName`，自訂值會優先於預設的 Agent 名稱。

用 `tracingOptions.nestUnderParent` 啟動的執行隸屬於原有 Trace。匯出器不會從該次執行寫入 Trace 的名稱、輸入、輸出、元資料、用戶或會話。詳見[將執行納入較早啟動的 Mastra 執行](/docs/observability/tracing/overview#nesting-a-run-under-an-earlier-mastra-run)。

## 按 span 屬性篩選觀測紀錄 {/* #filtering-observations-by-span-attributes */}

Langfuse 的觀測層級評估器按觀測紀錄的最外層元資料篩選。OpenTelemetry 匯出器以 `mastra.<span_type>.<key>` 寫入的每項純量 span 屬性（字串、數字或布林值），都會由 Langfuse 匯出器提升到 `langfuse.observation.metadata.<key>`，鍵名會轉成 camelCase。匯出器亦會為每項觀測紀錄設定 `agentId`、`agentName`、`spanType` 和 `operationName`。

在 `MODEL_STEP` span 上，這項對應會產生 `stepIndex` 和 `isContinued`。如要讓每次 Agent 執行只評估一次，並以產生最終答案的步驟為準，請在觀測層級評估器同時設定 `spanType` 等於 `model_step` 和 `isContinued` 等於 `"false"`。

這些值以字串形式傳送，因此比較時應用 `"false"` 或 `"1"` 等字串值。span 的輸入和輸出沿用各自的對應規則，值為物件或陣列的屬性只會保留在巢狀的 `attributes` 元資料內。

## 自訂 Trace 元資料 {/* #custom-trace-metadata */}

Langfuse 只可按最外層元資料篩選 Trace 或將其分組。巢狀元資料的鍵不能用於篩選或分組。

如要加入自訂的最外層元資料，請在 span 元資料內的 `langfuse` 下設定鍵。匯出器會把各個鍵轉送到 `langfuse.trace.metadata.<key>`，這些鍵便可在 Langfuse 用於篩選：

```typescript
const tracingOptions = {
  metadata: {
    langfuse: {
      customerId: 'cust_123',
      tier: 'enterprise',
    },
  },
}
```

這個例子會產生 `langfuse.trace.metadata.customerId` 和 `langfuse.trace.metadata.tier`。

匯出器亦會轉送根 span 的元資料。Mastra 會為每個 Agent 和 Workflow 的根 span 設定 `runId` 和 `resourceId`，你可用 `tracingOptions.metadata` 加入自訂鍵。匯出器會把這些根 span 的鍵逐一轉送至 `langfuse.trace.metadata.<key>`。對應至 Langfuse 專用欄位的鍵（`userId`、`sessionId`、`threadId`、`traceName` 和 `version`）不會重複寫入 Trace 元資料。子 span 的其他元資料會留在相應的觀測紀錄。會話 ID 等專用欄位按各自的規則對應。

注意事項：

* 保留鍵 `prompt` 用來[連結提示詞](#prompt-linking)，不會當作 Trace 元資料轉送。
* 保留的識別鍵 `agentId`、`agentName`、`workflowId` 和 `workflowName` 取自根 span，優先於同名的自訂值。
* `langfuse` 內的鍵優先於根 span 元資料內的同名鍵。
* Langfuse 把 Trace 元資料屬性對應為字串，因此匯出器亦以字串傳送其值。數字、布林值和物件會以 JSON 序列化。Langfuse Cloud 在接收資料時會還原原有類型。

## 對話會話 {/* #conversation-sessions */}

匯出器以 span 元資料中的 `sessionId` 對應 Langfuse 會話。若沒有 `sessionId`，或其值為 `null`，便改用 `threadId`。如明確將 `sessionId` 設為空字串，匯出器便不會改用 `threadId`，亦不會傳送會話 ID。

使用 [Observational Memory](/docs/memory/observational-memory) 時，即使子 span 比父 span 先到達，Langfuse 匯出器仍會將 observer 和 reflector 的 span 歸入呼叫方的會話。明確指定的 `sessionId` 會優先採用，即使是空字串也一樣。未有明確指定時，匯出器會先用 Observational Memory 帶來的原始呼叫方執行緒 ID，再改用 span 自身的 `threadId`。Observational Memory 以呼叫方 span 的非空 `threadId` 識別呼叫方，若無則用原始請求的執行緒 ID。巢狀觀測會保留外層呼叫方的識別資料。

用執行緒 ID 作為會話對應的後備值，是 Langfuse 特有的行為。Observational Memory 不會從執行緒 ID 產生通用的 `sessionId` 元資料供其他匯出器使用。

observer 和 reflector 各用獨立的內部執行緒。多執行緒觀測以發起呼叫的一方的會話為準，批次內的首個執行緒不會決定會話。這項會話處理規則適用於任何 `bufferOnIdle` 設定，亦不影響緩衝或 span 的父子關係。

## 成本追蹤 {/* #cost-tracking */}

只有在模型生成的成本元資料符合以下所有條件時，匯出器才會把 Provider 回報的成本轉送至 Langfuse 的 `cost_details` 欄位：

* 該 span 是模型生成 span。
* `costContext.costMetadata.source` 是 `'provider_reported'`。
* `costContext.costUnit` 是 `'USD'`。
* `costContext.estimatedCost` 是有限的非負數。

匯出器會略過估算成本，讓 Langfuse 可按自身的定價模型計算。如 Langfuse 的模型生成紀錄未顯示成本，請查看 Provider 有否回報成本。若沒有，請在 Langfuse 設定模型價格。

詳細規則見 [`LangfuseExporter` 參考文件](/reference/observability/tracing/exporters/langfuse#cost-tracking)。

## 連結提示詞 {/* #prompt-linking */}

你可將 LLM 生成紀錄連結至儲存在 [Langfuse Prompt Management](https://langfuse.com/docs/prompt-management) 的提示詞，以追蹤提示詞的版本及查看相關指標。

### 使用輔助函數（建議） {/* #using-the-helper-recommended */}

將 `withLangfusePrompt` 配合 `buildTracingOptions` 使用，可簡化設定：

```typescript title="src/agents/support-agent.ts"
import { Agent } from '@mastra/core/agent'
import { buildTracingOptions } from '@mastra/observability'
import { LangfuseExporter, withLangfusePrompt } from '@mastra/langfuse'

const exporter = new LangfuseExporter()

// Fetch the prompt from Langfuse Prompt Management via the client
const prompt = await exporter.client.prompt.get('customer-support', { type: 'text' })

export const supportAgent = new Agent({
  id: 'support-agent',
  name: 'support-agent',
  instructions: prompt.compile(), // Use the prompt text from Langfuse
  model: '__GATEWAY_OPENAI_MODEL__',
  defaultGenerateOptions: {
    tracingOptions: buildTracingOptions(
      withLangfusePrompt({ name: prompt.name, version: prompt.version }),
    ),
  },
})
```

`withLangfusePrompt` 輔助函數接受 `name` 和 `version` 欄位來連結提示詞。Langfuse v5 規定兩個欄位都要提供。

### 手動傳入欄位 {/* #manual-fields */}

如未有使用 Langfuse SDK，亦可手動傳入欄位：

```typescript
const tracingOptions = buildTracingOptions(withLangfusePrompt({ name: 'my-prompt', version: 1 }))
```

### 提示詞物件的欄位 {/* #prompt-object-fields */}

提示詞物件須同時包含 `name` 和 `version`：

| 欄位 | 類型 | 說明 |
| - | - | - |
| `name` | string | 提示詞在 Langfuse 內的名稱 |
| `version` | number | 提示詞的版本編號 |

在 `MODEL_GENERATION` span 設定這些欄位後，Langfuse 匯出器便會自動將生成紀錄連結至相應的提示詞。

## 將現有 Trace 匯入 Mastra Platform {/* #import-existing-traces-into-mastra-platform */}

Mastra CLI 可從 Langfuse Cloud 或自行託管的 Langfuse v4 或更新版本實例匯入過往的 Trace 觀測紀錄。匯入操作獨立於本頁的匯出器設定。有關憑證、試行、繼續匯入、驗證和現行限制，請參閱[匯入現有 Trace](/docs/mastra-platform/observability#import-existing-traces)。
