# Google

這`@mastra/auth-google`軟體包使用 Google Workspace 為 Mastra 提供身份驗證和基於角色的存取控制。它支援帶有加密會話 Cookie 的 OAuth 2.0/OIDC 登入流程、驗證 Google ID 令牌，並將 Google Workspace 群組對應到 Mastra 權限。

當您的 Studio 使用者透過 Google 登入時使用它，且存取權限應僅限於一個或多個 Google Workspace 網域。

## 先決條件 {/* #prerequisites */}

本指南使用 Google Workspace 驗證。確保：

1. 建立或選擇 Google Cloud 項目
2. 為 Web 應用程式設定 OAuth 用戶端
3. 將您的 Mastra SSO 回呼 URL 新增至授權的重新導向 URI
4. 如果您打算使用 RBAC，請設定 Google Workspace 群組

對於 Google 線上論壇 RBAC，也需設定具有全域委派的 Google Workspace 服務帳號，並授予其 Directory API 只讀群組範圍：

```text
https://www.googleapis.com/auth/admin.directory.group.readonly
```

確保您的環境變數已設定。

```env title=".env"
GOOGLE_CLIENT_ID=your-client-id.apps.googleusercontent.com
GOOGLE_CLIENT_SECRET=your-client-secret
GOOGLE_REDIRECT_URI=http://localhost:4111/api/auth/sso/callback
GOOGLE_COOKIE_PASSWORD=a-random-string-at-least-32-characters-long
GOOGLE_ALLOWED_DOMAINS=example.com

GOOGLE_SERVICE_ACCOUNT_EMAIL=service-account@project.iam.gserviceaccount.com
GOOGLE_SERVICE_ACCOUNT_PRIVATE_KEY="-----BEGIN PRIVATE KEY-----\n...\n-----END PRIVATE KEY-----\n"
GOOGLE_WORKSPACE_ADMIN_EMAIL=admin@example.com
```

：：：筆記

`GOOGLE_COOKIE_PASSWORD`加密會話cookie。如果省略，則使用自動產生的值，該值在伺服器重新啟動後不會保留。為生產明確設定它。

`MastraAuthGoogle`讀到`GOOGLE_*` auth variables automatically. The service-account variables shown above are read by the configuration code you pass to `MastraRBACGoogle`.

:::

## 安裝 {/* #installation */}

在您可以使用之前`MastraAuthGoogle` class, install the `@mastra/auth-google` package.

```bash npm2yarn
npm install @mastra/auth-google
```

## 使用範例 {/* #usage-examples */}

### 環境變數的基本用法 {/* #basic-usage-with-environment-variables */}

設定上面的環境變數後，所有建構函數參數都是可選的：

```typescript title="src/mastra/index.ts"
import { Mastra } from '@mastra/core'
import { MastraAuthGoogle } from '@mastra/auth-google'

export const mastra = new Mastra({
  server: {
    auth: new MastraAuthGoogle(),
  },
})
```

：：：警告

使用`allowedDomains` or `GOOGLE_ALLOWED_DOMAINS` to enforce Workspace access. Mastra checks Google's verified `hd` claim, not the email address suffix.

:::

### 自訂配置 {/* #custom-configuration */}

如果您不想依賴環境變量，請直接傳遞建構函數選項：

```typescript title="src/mastra/index.ts"
import { Mastra } from '@mastra/core'
import { MastraAuthGoogle } from '@mastra/auth-google'

export const mastra = new Mastra({
  server: {
    auth: new MastraAuthGoogle({
      clientId: process.env.GOOGLE_CLIENT_ID,
      clientSecret: process.env.GOOGLE_CLIENT_SECRET,
      redirectUri: process.env.GOOGLE_REDIRECT_URI,
      allowedDomains: ['example.com'],
    }),
  },
})
```

### 使用 Google 網上論壇 RBAC 進行身份驗證 {/* #auth-with-google-groups-rbac */}

：：：筆記

RBAC 在生產中需要 Mastra Enterprise Edition (EE) 授權。它在開發過程中無需許可證即可運行。看[what requires an EE license](/docs/license#what-requires-an-ee-license). [Contact sales](https://mastra.ai/contact) for more information.

:::

添加`MastraRBACGoogle` to map Google Workspace groups to Mastra permissions:

```typescript title="src/mastra/index.ts"
import { Mastra } from '@mastra/core'
import { MastraAuthGoogle, MastraRBACGoogle } from '@mastra/auth-google'

export const mastra = new Mastra({
  server: {
    auth: new MastraAuthGoogle(),
    rbac: new MastraRBACGoogle({
      serviceAccount: {
        clientEmail: process.env.GOOGLE_SERVICE_ACCOUNT_EMAIL!,
        privateKey: process.env.GOOGLE_SERVICE_ACCOUNT_PRIVATE_KEY!,
        subject: process.env.GOOGLE_WORKSPACE_ADMIN_EMAIL!,
      },
      roleMapping: {
        'admins@example.com': ['*'],
        'engineering@example.com': ['agents:*', 'workflows:*', 'tools:*'],
        'viewers@example.com': ['agents:read', 'workflows:read'],
        _default: [], // users with unmapped groups get no permissions
      },
    }),
  },
})
```

### 跨提供者使用 {/* #cross-provider-usage */}

使用不同的驗證提供者（Auth0、Clerk 等）進行登錄，使用 Google Workspace 群組進行 RBAC。透過一個`getUserKey` function to resolve the Google Directory API user key from the other provider's user object:

```typescript title="src/mastra/index.ts"
import { Mastra } from '@mastra/core'
import { MastraAuthAuth0 } from '@mastra/auth-auth0'
import { MastraRBACGoogle } from '@mastra/auth-google'

export const mastra = new Mastra({
  server: {
    auth: new MastraAuthAuth0(),
    rbac: new MastraRBACGoogle({
      getUserKey: user => {
        if (!user || typeof user !== 'object') return undefined

        const { email } = user as { email?: unknown }
        return typeof email === 'string' ? email : undefined
      },
      serviceAccount: {
        clientEmail: process.env.GOOGLE_SERVICE_ACCOUNT_EMAIL!,
        privateKey: process.env.GOOGLE_SERVICE_ACCOUNT_PRIVATE_KEY!,
        subject: process.env.GOOGLE_WORKSPACE_ADMIN_EMAIL!,
      },
      roleMapping: {
        'engineering@example.com': ['agents:*', 'workflows:*'],
        'admins@example.com': ['*'],
        _default: [],
      },
    }),
  },
})
```

訪問[MastraAuthGoogle](/reference/auth/google) for all available configuration options.

## 角色映射 {/* #role-mapping */}

這`roleMapping` option maps Google Workspace group email addresses to arrays of Mastra permission strings. Permissions follow a `resource:action` pattern and support wildcards:

```typescript
const rbac = new MastraRBACGoogle({
  roleMapping: {
    // full access to everything
    'admins@example.com': ['*'],

    // full access to agents and workflows
    'engineering@example.com': ['agents:*', 'workflows:*'],

    // read-only access
    'viewers@example.com': ['agents:read', 'workflows:read'],

    // users whose groups don't match any key above
    _default: [],
  },
})
```

預設情況下，群組電子郵件地址用作角色 ID。使用`mapGroupToRoles` if you want to map by group name or another property. The `_default` key assigns permissions to users whose Google Workspace groups don't match any other key.

## 客戶端設定 {/* #client-side-setup */}

啟用身份驗證後，對 Mastra 路由的請求需要身份驗證。啟用 SSO 時`GOOGLE_CLIENT_SECRET`, `MastraAuthGoogle` uses Google sign-in and sets an encrypted session cookie after login.

### Cookie 會話（建議） {/* #cookie-session-recommended */}

對於跨來源請求（例如，前端`:3000` calling Mastra on `:4111`), enable CORS credentials on the Mastra server:

```typescript title="src/mastra/index.ts"
import { Mastra } from '@mastra/core'

export const mastra = new Mastra({
  server: {
    auth: new MastraAuthGoogle(),
    cors: {
      origin: 'http://localhost:3000',
      credentials: true,
    },
  },
})
```

配置客戶端以包含憑證：

```typescript title="lib/mastra-client.ts"
import { MastraClient } from '@mastra/client-js'

export const mastraClient = new MastraClient({
  baseUrl: 'http://localhost:4111',
  credentials: 'include',
})
```

### 不記名令牌 {/* #bearer-token */}

您也可以將 Google ID 令牌作為 Bearer 令牌傳遞。 Mastra 根據 Google 的 JSON Web 金鑰集 (JWKS) 端點驗證令牌：

```typescript title="lib/mastra-client.ts"
import { MastraClient } from '@mastra/client-js'

export const createMastraClient = (idToken: string) => {
  return new MastraClient({
    baseUrl: 'http://localhost:4111',
    headers: {
      Authorization: `Bearer ${idToken}`,
    },
  })
}
```

訪問[Mastra Client SDK](/docs/server/mastra-client) for more configuration options.

## 故障排除 {/* #troubleshooting */}

* **登入後401**：檢查一下`GOOGLE_CLIENT_ID`, `GOOGLE_CLIENT_SECRET`, and `GOOGLE_REDIRECT_URI` match the Google Cloud OAuth client.
* **Workspace使用者被拒絕**： 核實`GOOGLE_ALLOWED_DOMAINS` matches the Google ID token `hd` claim.
* **消費者 Gmail 帳號被拒絕**：這是預期的情況`allowedDomains` is configured because Gmail accounts don't have a Workspace `hd` claim.
* **RBAC 回傳預設權限**：沒有為使用者解析角色。驗證使用者電子郵件或自訂`getUserKey`, Google group membership, and `roleMapping`. If the Directory API lookup fails, the provider throws an error instead of returning `_default`.
* **Cookie 不會跨來源傳送**： 放`credentials: "include"` in `MastraClient` and configure `server.cors` with your frontend origin and `credentials: true`.
* **重新啟動時會話遺失**： 放`GOOGLE_COOKIE_PASSWORD` to a stable value of at least 32 characters. Without it, an auto-generated key is used in development and changes on each restart.
