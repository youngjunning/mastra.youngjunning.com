# Google

`@mastra/auth-google` 套件利用 Google Workspace 為 Mastra 提供身份驗證和按角色劃分的存取控制（RBAC）。套件支援 OAuth 2.0 / OIDC 登入流程，使用加密的會話 Cookie，驗證 Google ID 權杖，並將 Google Workspace 群組配對至 Mastra 權限。

如果 Studio 用戶透過 Google 登入，而你只想讓一個或多個 Google Workspace 網域的用戶存取 Studio，便可使用這個套件。

## 先決條件 {/* #prerequisites */}

本指南採用 Google Workspace 進行身份驗證。開始前，請完成以下步驟：

1. 建立或選擇 Google Cloud 項目
2. 為網頁應用程式設定 OAuth 客戶端
3. 將 Mastra SSO 回調 URL 加入已獲授權的重新導向 URI 清單
4. 如要使用 RBAC，請設定 Google Workspace 群組

如要透過 Google Groups 實施 RBAC，還須為 Google Workspace 服務帳戶設定全網域委派，並授予該帳戶以下 Directory API 授權範圍，以唯讀方式存取群組：

```text
https://www.googleapis.com/auth/admin.directory.group.readonly
```

請設定以下環境變數。

```env title=".env"
GOOGLE_CLIENT_ID=your-client-id.apps.googleusercontent.com
GOOGLE_CLIENT_SECRET=your-client-secret
GOOGLE_REDIRECT_URI=http://localhost:4111/api/auth/sso/callback
GOOGLE_COOKIE_PASSWORD=a-random-string-at-least-32-characters-long
GOOGLE_ALLOWED_DOMAINS=example.com

GOOGLE_SERVICE_ACCOUNT_EMAIL=service-account@project.iam.gserviceaccount.com
GOOGLE_SERVICE_ACCOUNT_PRIVATE_KEY="-----BEGIN PRIVATE KEY-----\n...\n-----END PRIVATE KEY-----\n"
GOOGLE_WORKSPACE_ADMIN_EMAIL=admin@example.com
```

:::note[備註]

`GOOGLE_COOKIE_PASSWORD` 用來加密會話 Cookie。如沒有設定，系統會自動產生一個值，伺服器重啟後便不會保留該值。請在生產環境明確設定這個變數。

`MastraAuthGoogle` 會自動讀取 `GOOGLE_*` 身份驗證變數。上面列出的服務帳戶變數，則由傳給 `MastraRBACGoogle` 的設定程式碼讀取。

:::

## 安裝 {/* #installation */}

使用 `MastraAuthGoogle` 類別之前，請先安裝 `@mastra/auth-google` 套件。

```bash npm2yarn
npm install @mastra/auth-google
```

## 使用範例 {/* #usage-examples */}

### 使用環境變數的基本設定 {/* #basic-usage-with-environment-variables */}

設定好上述環境變數後，便可省略建構函數的所有參數：

```typescript title="src/mastra/index.ts"
import { Mastra } from '@mastra/core'
import { MastraAuthGoogle } from '@mastra/auth-google'

export const mastra = new Mastra({
  server: {
    auth: new MastraAuthGoogle(),
  },
})
```

:::warning[警告]

用 `allowedDomains` 或 `GOOGLE_ALLOWED_DOMAINS`，只容許指定的 Workspace 網域存取。Mastra 檢查的是 Google 提供並已驗證的 `hd` 聲明，而非電郵地址的後綴。

:::

### 自訂設定 {/* #custom-configuration */}

如不想依賴環境變數，可直接把設定選項傳入建構函數：

```typescript title="src/mastra/index.ts"
import { Mastra } from '@mastra/core'
import { MastraAuthGoogle } from '@mastra/auth-google'

export const mastra = new Mastra({
  server: {
    auth: new MastraAuthGoogle({
      clientId: process.env.GOOGLE_CLIENT_ID,
      clientSecret: process.env.GOOGLE_CLIENT_SECRET,
      redirectUri: process.env.GOOGLE_REDIRECT_URI,
      allowedDomains: ['example.com'],
    }),
  },
})
```

### 身份驗證與按 Google Groups 群組實施 RBAC {/* #auth-with-google-groups-rbac */}

:::note[備註]

在生產環境使用 RBAC 須有 Mastra 企業版（EE）授權，開發環境則毋須授權。詳情請參閱[哪些功能須有 EE 授權](/docs/license#what-requires-an-ee-license)，或[聯絡銷售團隊](https://mastra.ai/contact)。

:::

加入 `MastraRBACGoogle`，將 Google Workspace 群組配對至 Mastra 權限：

```typescript title="src/mastra/index.ts"
import { Mastra } from '@mastra/core'
import { MastraAuthGoogle, MastraRBACGoogle } from '@mastra/auth-google'

export const mastra = new Mastra({
  server: {
    auth: new MastraAuthGoogle(),
    rbac: new MastraRBACGoogle({
      serviceAccount: {
        clientEmail: process.env.GOOGLE_SERVICE_ACCOUNT_EMAIL!,
        privateKey: process.env.GOOGLE_SERVICE_ACCOUNT_PRIVATE_KEY!,
        subject: process.env.GOOGLE_WORKSPACE_ADMIN_EMAIL!,
      },
      roleMapping: {
        'admins@example.com': ['*'],
        'engineering@example.com': ['agents:*', 'workflows:*', 'tools:*'],
        'viewers@example.com': ['agents:read', 'workflows:read'],
        _default: [], // users with unmapped groups get no permissions
      },
    }),
  },
})
```

### 配合其他身份驗證 Provider 使用 {/* #cross-provider-usage */}

你可以用 Auth0、Clerk 等其他身份驗證 Provider 處理登入，再按 Google Workspace 群組實施 RBAC。傳入 `getUserKey` 函數，從該 Provider 的用戶物件取得 Google Directory API 所需的用戶鍵值：

```typescript title="src/mastra/index.ts"
import { Mastra } from '@mastra/core'
import { MastraAuthAuth0 } from '@mastra/auth-auth0'
import { MastraRBACGoogle } from '@mastra/auth-google'

export const mastra = new Mastra({
  server: {
    auth: new MastraAuthAuth0(),
    rbac: new MastraRBACGoogle({
      getUserKey: user => {
        if (!user || typeof user !== 'object') return undefined

        const { email } = user as { email?: unknown }
        return typeof email === 'string' ? email : undefined
      },
      serviceAccount: {
        clientEmail: process.env.GOOGLE_SERVICE_ACCOUNT_EMAIL!,
        privateKey: process.env.GOOGLE_SERVICE_ACCOUNT_PRIVATE_KEY!,
        subject: process.env.GOOGLE_WORKSPACE_ADMIN_EMAIL!,
      },
      roleMapping: {
        'engineering@example.com': ['agents:*', 'workflows:*'],
        'admins@example.com': ['*'],
        _default: [],
      },
    }),
  },
})
```

所有設定選項均可在 [MastraAuthGoogle](/reference/auth/google) 查閱。

## 角色配對 {/* #role-mapping */}

`roleMapping` 選項將 Google Workspace 群組的電郵地址配對至由 Mastra 權限字串組成的陣列。權限採用 `resource:action` 格式，並支援萬用字元：

```typescript
const rbac = new MastraRBACGoogle({
  roleMapping: {
    // full access to everything
    'admins@example.com': ['*'],

    // full access to agents and workflows
    'engineering@example.com': ['agents:*', 'workflows:*'],

    // read-only access
    'viewers@example.com': ['agents:read', 'workflows:read'],

    // users whose groups don't match any key above
    _default: [],
  },
})
```

預設以群組的電郵地址作為角色 ID。如要按群組名稱或其他屬性配對，請用 `mapGroupToRoles`。如果用戶所屬的 Google Workspace 群組全部都配對不到其他鍵，便會按 `_default` 鍵分配權限。

## 客戶端設定 {/* #client-side-setup */}

啟用身份驗證後，送往 Mastra 路由的請求都須通過身份驗證。用 `GOOGLE_CLIENT_SECRET` 啟用 SSO 後，`MastraAuthGoogle` 會採用 Google 登入，並在登入後設定加密的會話 Cookie。

### 用 Cookie 維持會話（建議） {/* #cookie-session-recommended */}

如需發出跨來源請求，例如在 `:3000` 運行的前端呼叫在 `:4111` 運行的 Mastra，請在 Mastra 伺服器上容許 CORS 請求附帶憑證：

```typescript title="src/mastra/index.ts"
import { Mastra } from '@mastra/core'

export const mastra = new Mastra({
  server: {
    auth: new MastraAuthGoogle(),
    cors: {
      origin: 'http://localhost:3000',
      credentials: true,
    },
  },
})
```

設定客戶端，讓請求附帶憑證：

```typescript title="lib/mastra-client.ts"
import { MastraClient } from '@mastra/client-js'

export const mastraClient = new MastraClient({
  baseUrl: 'http://localhost:4111',
  credentials: 'include',
})
```

### Bearer 權杖 {/* #bearer-token */}

你亦可把 Google ID 權杖當作 Bearer 權杖傳送。Mastra 會用從 Google 的 JSON Web 金鑰集（JWKS）端點取得的金鑰來驗證權杖：

```typescript title="lib/mastra-client.ts"
import { MastraClient } from '@mastra/client-js'

export const createMastraClient = (idToken: string) => {
  return new MastraClient({
    baseUrl: 'http://localhost:4111',
    headers: {
      Authorization: `Bearer ${idToken}`,
    },
  })
}
```

更多設定選項可參閱 [Mastra Client SDK](/docs/server/mastra-client)。

## 故障排除 {/* #troubleshooting */}

* **登入後收到 401**：檢查 `GOOGLE_CLIENT_ID`、`GOOGLE_CLIENT_SECRET` 和 `GOOGLE_REDIRECT_URI` 是否與 Google Cloud 的 OAuth 客戶端設定相符。
* **Workspace 用戶無法存取**：核對 Google ID 權杖的 `hd` 聲明，確認它符合 `GOOGLE_ALLOWED_DOMAINS` 所列的其中一個網域。
* **個人 Gmail 帳戶無法存取**：設定 `allowedDomains` 後，這是正常情況，因為個人 Gmail 帳戶沒有 Workspace 的 `hd` 聲明。
* **RBAC 回傳預設權限**：系統找不到適用於該用戶的角色。請檢查用戶的電郵地址或自訂的 `getUserKey`，以及用戶所屬的 Google 群組和 `roleMapping`。如 Directory API 查詢失敗，Provider 會拋出錯誤，而不會回傳 `_default`。
* **跨來源請求沒有附帶 Cookie**：在 `MastraClient` 設定 `credentials: "include"`，並在 `server.cors` 指定前端的來源及設定 `credentials: true`。
* **伺服器重啟後會話遺失**：把 `GOOGLE_COOKIE_PASSWORD` 設為至少 32 個字元的固定值。如沒有設定，開發環境每次重啟都會自動產生新的金鑰。
