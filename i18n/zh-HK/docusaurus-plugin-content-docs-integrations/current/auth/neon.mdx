# Neon

`@mastra/auth-neon` 套件讓 Mastra 接駁 [Neon Auth](https://neon.com/docs/auth/overview)。Neon Auth 是以 Better Auth 為基礎的託管身份驗證服務，會將用戶和會話儲存在你的 Neon 資料庫。這個套件會驗證以 Bearer 令牌傳送的 Neon Auth JWT 和 Neon Auth 會話 Cookie，並讓 Studio 用戶以電郵地址和密碼登入或註冊。

## 先決條件 {/* #prerequisites */}

在 [Neon 控制台](https://console.neon.tech)為 Neon 項目的一個分支啟用 Neon Auth。**Auth** 頁面會顯示該分支的 Neon Auth 網址。將這個網址加入 `.env` 檔案：

```env title=".env"
NEON_AUTH_BASE_URL=https://ep-example-123456.neonauth.us-east-2.aws.neon.tech/neondb/auth
```

請使用 Neon 顯示的完整網址，包括 `/neondb/auth` 路徑。Mastra 會根據這個網址確定 JWKS 端點（`<NEON_AUTH_BASE_URL>/.well-known/jwks.json`）及預期的 JWT 簽發者。

Neon Auth 只接受來自受信任來源的登入請求。啟用 **Allow localhost** 後，Neon Auth 便會接受來自 `localhost` 的請求。部署前，請在 Neon Auth 設定內把 Mastra 伺服器和 Studio 使用的網域加入受信任網域清單。否則，Neon Auth 會拒絕 Studio 的登入請求，並回傳 `Invalid origin` 錯誤。

## 安裝 {/* #installation */}

安裝 `@mastra/auth-neon` 套件：

```bash npm2yarn
npm install @mastra/auth-neon@latest
```

## 使用示例 {/* #usage-example */}

將 `MastraAuthNeon` 註冊為伺服器的身份驗證 Provider：

```typescript {2,6} title="src/mastra/index.ts"
import { Mastra } from '@mastra/core'
import { MastraAuthNeon } from '@mastra/auth-neon'

export const mastra = new Mastra({
  server: {
    auth: new MastraAuthNeon(),
  },
})
```

`MastraAuthNeon` 預設會讀取 `NEON_AUTH_BASE_URL`。你亦可直接傳入 `baseUrl`。

設定完成後，存取 `/api` 下任何一條路由都需要 Neon Auth 憑證。這個 Provider 接受以下任一種憑證：

* **Neon Auth JWT**，透過 `Authorization: Bearer <token>` 請求標頭傳送。Mastra 會用 Neon Auth 的 JWKS 驗證簽署，並檢查簽發者、接收對象和到期時間。
* **Neon Auth 會話 Cookie**（`__Secure-neon-auth.session_token`）。Mastra 每次收到請求時都會透過 Neon Auth 驗證該 Cookie。

所有可用的設定選項，請參閱 [MastraAuthNeon](/reference/auth/neon)。

## 登入 Studio {/* #studio-sign-in */}

設定 `MastraAuthNeon` 後，Studio 會顯示供用戶輸入電郵地址和密碼的表單。Mastra 會把登入憑證轉交 Neon Auth，並將 Neon Auth 會話 Cookie 儲存在瀏覽器。在 Studio 建立的帳戶會列在 Neon Auth 的用戶清單，在應用程式其他部分建立的帳戶亦可登入 Studio。

會話 Cookie 設有 `Secure` 屬性，因此瀏覽器只會在透過 HTTPS 或從 `localhost` 存取 Studio 時儲存該 Cookie。如果透過其他主機上的普通 HTTP 存取 Studio，就無法維持登入狀態。

如只想讓現有用戶登入，可停用註冊功能。這會隱藏註冊表單，並拒絕傳送至 Mastra API 的註冊請求：

```typescript title="src/mastra/index.ts"
new MastraAuthNeon({
  signUpEnabled: false,
})
```

登出 Studio 時，Mastra 會清除 Studio 的會話 Cookie，並嘗試撤銷 Neon Auth 內的會話。如果向 Neon Auth 發出的請求失敗，該會話可能仍然有效。

## 客戶端設定 {/* #client-side-setup */}

使用 Neon Auth SDK 的前端可為已登入的用戶取得短期有效的 JWT，再傳送給 Mastra。

### 取得 JWT {/* #retrieving-a-jwt */}

如果前端使用 Vite，請在前端的 `.env` 檔案內將 `VITE_NEON_AUTH_URL` 設為與 Mastra 伺服器上的 `NEON_AUTH_BASE_URL` 相同的 Neon Auth 網址。

用戶登入後，呼叫 [Neon Auth SDK](https://neon.com/docs/reference/javascript-sdk) 的 `authClient.getSession()`。回傳的會話包含要傳送給 Mastra 的 JWT：

```typescript title="lib/auth.ts"
import { createAuthClient } from '@neon/neon-js/auth'

export const authClient = createAuthClient(import.meta.env.VITE_NEON_AUTH_URL)

export async function getMastraToken() {
  const { data, error } = await authClient.getSession()
  if (error) throw error
  if (!data?.session) throw new Error('Not signed in to Neon Auth')
  return data.session.token
}
```

Neon Auth JWT 會在 15 分鐘後到期。每批呼叫 Mastra 前，請重新取得令牌，無須儲存令牌供之後的批次重用。

:::note

有關跨來源 Cookie 的要求和取得令牌的其他方法，請參閱 [Neon Auth JWT 指南](https://neon.com/docs/auth/guides/plugins/jwt)。

:::

### 設定 `MastraClient` {/* #configuring-mastraclient */}

在 `Authorization` 請求標頭內傳送 JWT：

```typescript {6} title="lib/mastra/mastra-client.ts"
import { MastraClient } from '@mastra/client-js'

export const createMastraClient = (token: string) =>
  new MastraClient({
    baseUrl: 'https://<mastra-api-url>',
    headers: { Authorization: `Bearer ${token}` },
  })
```

更多設定選項請參閱 [Mastra Client SDK](/docs/server/mastra-client)。

## 基於角色的存取控制 {/* #role-based-access-control */}

`MastraRBACNeon` 將 Neon Auth [組織插件](https://neon.com/docs/auth/guides/plugins/organization)的角色（`owner`、`admin` 和 `member`）對應至 Mastra 權限。未列於 `roleMapping` 的角色會獲得 `_default` 權限：

```typescript {2,7-14} title="src/mastra/index.ts"
import { Mastra } from '@mastra/core'
import { MastraAuthNeon, MastraRBACNeon } from '@mastra/auth-neon'

export const mastra = new Mastra({
  server: {
    auth: new MastraAuthNeon(),
    rbac: new MastraRBACNeon({
      roleMapping: {
        owner: ['*'],
        admin: ['*'],
        member: ['agents:read', 'agents:execute', 'workflows:read'],
        _default: [],
      },
    }),
  },
})
```

如果請求附有會話 Cookie，Mastra 會從 Neon Auth 讀取用戶在該會話目前所選組織中的角色。設定 `organizationId` 後，Mastra 會固定使用同一個組織。用戶如果並非該組織的成員，就沒有角色，亦不會獲得權限。如果用戶沒有選定目前使用的組織，Mastra 會採用其 Neon Auth 用戶角色，例如 `user` 或 `admin`。

Neon Auth JWT 不包含組織角色。當中的 `role` 聲明固定為 `authenticated`，即 Neon Data API 使用的 Postgres 角色，Mastra 會忽略這項聲明。因此，附上 Bearer JWT 的請求預設沒有角色，亦不會獲得權限。要讓這類請求獲得權限，可透過 `getUserRoles` 自行查找用戶的角色：

```typescript title="src/mastra/index.ts"
new MastraRBACNeon({
  roleMapping: { admin: ['*'], member: ['agents:read'], _default: [] },
  getUserRoles: async user => lookUpRolesInYourDatabase(user.id),
})
```

:::note

在生產環境使用 RBAC 需要 Mastra Enterprise Edition (EE) 授權，在開發環境則可直接使用。請參閱[哪些功能需要 EE 授權](/docs/license#what-requires-an-ee-license)。

:::

## 驗證設定 {/* #verify-the-setup */}

啟動 Mastra 伺服器，向受保護的路由發出不附憑證的請求：

```bash
curl -i http://localhost:4111/api/agents
```

伺服器會回傳 `401 Unauthorized`。在 `Authorization: Bearer <token>` 請求標頭加入 Neon Auth JWT，再發出同一個請求，便會收到 `200 OK` 和你的 Agent 清單。開啟 `http://localhost:4111` 的 Studio 後，可在登入表單使用任何 Neon Auth 用戶的電郵地址和密碼登入。
