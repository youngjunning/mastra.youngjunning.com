# Okta

`@mastra/auth-okta` 套件透過 Okta 為 Mastra 提供身份驗證及基於角色的存取控制（RBAC）。套件支援使用加密會話 Cookie 的 OAuth 2.0 / OIDC 登入流程，並可將 Okta 群組對應至 Mastra 權限。

## 先決條件 {/* #prerequisites */}

本指南以 Okta 進行身份驗證。開始前請完成以下設定。

1. 到 [okta.com](https://www.okta.com/) 開立 Okta 帳戶。
2. 在 Okta 管理控制台設定 OAuth 應用程式，選擇網頁應用程式及授權碼授權類型（Authorization Code）。
3. 將重新導向 URI 加入應用程式的登入重新導向 URI 清單。
4. 建立 RBAC 所需的 API 權杖。

確認已設定以下環境變數。

```env title=".env"
OKTA_DOMAIN=dev-123456.okta.com
OKTA_CLIENT_ID=your-client-id
OKTA_CLIENT_SECRET=your-client-secret
OKTA_REDIRECT_URI=http://localhost:4111/api/auth/callback
OKTA_COOKIE_PASSWORD=a-random-string-at-least-32-characters-long
OKTA_API_TOKEN=your-api-token
```

:::note

`OKTA_COOKIE_PASSWORD` 用於加密會話 Cookie。如未設定，伺服器會採用自動產生的值，重啟後該值便會失效。請在正式環境中明確設定此變數。

只有在使用 `MastraRBACOkta` 將 Okta 群組對應至權限時，才需要設定 `OKTA_API_TOKEN`。

:::

## 安裝 {/* #installation */}

```bash npm2yarn
npm install @mastra/auth-okta
```

## 使用示例 {/* #usage-examples */}

### 使用環境變數的基本設定 {/* #basic-usage-with-environment-variables */}

完成上述環境變數設定後，建構函數的參數全部可以省略。

```typescript title="src/mastra/index.ts"
import { Mastra } from '@mastra/core'
import { MastraAuthOkta } from '@mastra/auth-okta'

export const mastra = new Mastra({
  server: {
    auth: new MastraAuthOkta(),
  },
})
```

### 為身份驗證加入 RBAC {/* #auth-with-rbac */}

:::note

在正式環境使用 RBAC 須持有 Mastra Enterprise Edition（EE）授權。開發環境毋須授權即可使用。請參閱[哪些功能需要 EE 授權](/docs/license#what-requires-an-ee-license)。如需更多資料，請[聯絡銷售團隊](https://mastra.ai/contact)。

:::

加入 `MastraRBACOkta`，便可將 Okta 群組對應至 Mastra 權限。

```typescript title="src/mastra/index.ts"
import { Mastra } from '@mastra/core'
import { MastraAuthOkta, MastraRBACOkta } from '@mastra/auth-okta'

export const mastra = new Mastra({
  server: {
    auth: new MastraAuthOkta(),
    rbac: new MastraRBACOkta({
      roleMapping: {
        Admin: ['*'],
        Engineering: ['agents:*', 'workflows:*', 'tools:*'],
        Viewer: ['agents:read', 'workflows:read'],
        _default: [], // users with unmapped groups get no permissions
      },
    }),
  },
})
```

### 配合其他身份驗證 Provider 使用 {/* #cross-provider-usage */}

登入可交由 Auth0、Clerk 等其他身份驗證 Provider 處理，RBAC 則由 Okta 提供。傳入 `getUserId` 函數，從處理登入的 Provider 的用戶物件判定相應的 Okta 用戶 ID。

```typescript title="src/mastra/index.ts"
import { Mastra } from '@mastra/core'
import { MastraAuthAuth0 } from '@mastra/auth-auth0'
import { MastraRBACOkta } from '@mastra/auth-okta'

export const mastra = new Mastra({
  server: {
    auth: new MastraAuthAuth0(),
    rbac: new MastraRBACOkta({
      getUserId: user => user.metadata?.oktaUserId || user.email,
      roleMapping: {
        Engineering: ['agents:*', 'workflows:*'],
        Admin: ['*'],
        _default: [],
      },
    }),
  },
})
```

:::note

如要連結同一用戶在不同 Provider 的身份，請將 Okta 用戶 ID 存入處理登入的 Provider 的用戶中繼資料。Mastra 會用這個 ID 向 Okta 查詢該用戶所屬的群組。

:::

完整的設定選項載於 [MastraAuthOkta](/reference/auth/okta) 參考文件。

## 角色對應 {/* #role-mapping */}

`roleMapping` 選項會將 Okta 群組名稱對應至 Mastra 權限字串的陣列。權限字串的格式為 `resource:action`，並支援萬用字元。

```typescript
const rbac = new MastraRBACOkta({
  roleMapping: {
    // full access to everything
    Admin: ['*'],

    // full access to agents and workflows
    Engineering: ['agents:*', 'workflows:*'],

    // read-only access
    Viewer: ['agents:read', 'workflows:read'],

    // users whose groups don't match any key above
    _default: [],
  },
})
```

如用戶所屬的 Okta 群組均未配對到其他鍵，Mastra 就會按 `_default` 鍵分配權限。

## 客戶端設定 {/* #client-side-setup */}

啟用身份驗證後，向 Mastra 路由發出的請求均須通過身份驗證。`MastraAuthOkta` 使用單一登入（SSO），用戶會在 Okta 託管的登入頁面驗證身份。完成登入後，系統會自動設定加密的會話 Cookie。

### 用 Cookie 維持會話（建議） {/* #cookie-session-recommended */}

如需發出跨來源請求，例如由 `:3000` 的前端呼叫 `:4111` 的 Mastra，請在 Mastra 伺服器的 CORS 設定中允許請求附帶憑證。

```typescript title="src/mastra/index.ts"
import { Mastra } from '@mastra/core'

export const mastra = new Mastra({
  server: {
    auth: new MastraAuthOkta(),
    cors: {
      origin: 'http://localhost:3000',
      credentials: true,
    },
  },
})
```

設定客戶端，讓請求附帶憑證。

```typescript title="lib/mastra-client.ts"
import { MastraClient } from '@mastra/client-js'

export const mastraClient = new MastraClient({
  baseUrl: 'http://localhost:4111',
  credentials: 'include',
})
```

### Bearer 權杖 {/* #bearer-token */}

你亦可將 Okta 權杖作為 Bearer 權杖傳送。Mastra 會以 Okta 的 JWKS 端點驗證權杖，當中的 `aud` 聲明必須與已設定的受眾（audience）相符。受眾預設為客戶端 ID，可用 `audience` 選項或 `OKTA_AUDIENCE` 更改。

Okta 將客戶端 ID 寫入 **ID 權杖**的 `aud` 聲明，因此 ID 權杖可使用預設值。**存取權杖**則載有簽發該權杖的授權伺服器所指定的受眾，請按伺服器類型設定相符的值。

* **組織授權伺服器**（預設，簽發者為 `https://{domain}`）。將受眾設為 `https://{domain}`。
* **自訂授權伺服器**（簽發者為 `https://{domain}/oauth2/{name}`）。將受眾設為 Okta 管理控制台中該伺服器的受眾值，例如 `api://default`。

```env title=".env"
OKTA_AUDIENCE=https://dev-123456.okta.com
```

傳入陣列便可接受多個受眾值。例如，可以接受瀏覽器傳送的 ID 權杖及服務呼叫方傳送的存取權杖，兩者均由同一個 Provider 簽發。

```typescript title="src/mastra/index.ts"
new MastraAuthOkta({
  audience: ['your-client-id', 'https://dev-123456.okta.com'],
})
```

:::note

`audience` 只適用於 Bearer 權杖。驗證 SSO 登入流程中交換的 ID 權杖時，一律以客戶端 ID 為準。

:::

```typescript title="lib/mastra-client.ts"
import { MastraClient } from '@mastra/client-js'

export const createMastraClient = (token: string) => {
  return new MastraClient({
    baseUrl: 'http://localhost:4111',
    headers: {
      Authorization: `Bearer ${token}`,
    },
  })
}
```

更多設定選項載於 [Mastra Client SDK](/docs/server/mastra-client) 文件。

## 故障排除 {/* #troubleshooting */}

* **所有請求均回傳 401**。核對 Okta 網域、客戶端 ID 和客戶端密鑰，並確認 Okta 應用程式的重新導向 URI 與 `OKTA_REDIRECT_URI` 相符。
* **請求回傳 401，伺服器日誌顯示 `unexpected "aud" claim value`**。Bearer 權杖的受眾與設定不符，通常是因為傳送了存取權杖，而受眾仍設為預設的客戶端 ID。將 `OKTA_AUDIENCE` 設為簽發該權杖的授權伺服器所指定的受眾值。詳見 [Bearer 權杖](#bearer-token)。
* **跨來源請求沒有附帶 Cookie**。在 `MastraClient` 設定 `credentials: "include"`，並在 `server.cors` 指定前端來源及 `credentials: true`。
* **伺服器重啟後會話遺失**。將 `OKTA_COOKIE_PASSWORD` 設為至少 32 個字元的固定值。如未設定，伺服器每次重啟都會使用新產生的密鑰。
* **RBAC 回傳空白權限清單**。確認已設定 `OKTA_API_TOKEN`，而且該權杖有權列出用戶所屬的群組。核對 `roleMapping` 內的群組名稱是否與 Okta 的群組名稱完全一致。
