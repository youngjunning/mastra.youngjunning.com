# Amazon Bedrock AgentCore

你可以用 [AgentCore CLI](https://github.com/aws/agentcore-cli) 將 Mastra 應用程式部署到 [Amazon Bedrock AgentCore Runtime](https://docs.aws.amazon.com/bedrock-agentcore/)。CLI 會為自備程式碼（BYO）的 TypeScript 項目建立基本結構，交由 AWS CodeBuild 構建容器，再配置執行環境。部署時毋須在本機啟動 Docker 背景程序。

本指南參考 [AgentCore 官方 TypeScript 入門指南](https://docs.aws.amazon.com/bedrock-agentcore/latest/devguide/runtime-get-started-cli-typescript.html)，並修改當中的範例，由呼叫處理函式呼叫 Mastra Agent。

:::note

如要用 Lambda 部署完整的 Mastra 伺服器，可參閱 [AWS Lambda 指南](/integrations/deploy/aws-lambda)。如要部署到長期運行的虛擬機，請參閱 [Amazon EC2 指南](/integrations/deploy/amazon-ec2)。

:::

## 開始之前 {/* #before-you-begin */}

開始前請準備以下項目：

* 一個具備 Amazon Bedrock AgentCore、AWS CodeBuild、Amazon ECR 及 AWS IAM 所需權限的 [AWS 帳戶](https://aws.amazon.com/)
* 已安裝並完成身份驗證的 [AWS CLI](https://aws.amazon.com/cli/)（使用 `aws configure` 或 `aws sso login`）
* 已安裝 Node.js `v22.13.0` 或以上版本
* [Docker](https://www.docker.com/)、[Podman](https://podman.io/) 或 [Finch](https://runfinch.com/)，供 `agentcore dev` 在本機測試時使用（執行 `agentcore deploy` 毋須安裝）

Amazon Bedrock AgentCore Runtime 只在[部分 AWS 區域](https://docs.aws.amazon.com/bedrock-agentcore/latest/devguide/agentcore-regions.html)提供。請選用支援 AgentCore 的區域，並確保該區域已啟用你打算呼叫的基礎模型。

## 建立 AgentCore 項目 {/* #create-a-new-agentcore-project */}

執行以下指令，建立新的 AgentCore 項目：

```bash npm2yarn
npx @aws/agentcore create --name MastraOnAgentCore --no-agent
```

進入新建的 `MastraOnAgentCore` 目錄：

```bash
cd MastraOnAgentCore
```

初始化自備程式碼（BYO）的 TypeScript Agent，並將它建立在 `app/MastraAgent`：

```bash npm2yarn
npx @aws/agentcore add agent --name MastraAgent --type byo --build Container --language TypeScript --framework Strands --model-provider Bedrock --code-location app/MastraAgent
```

CLI 會修改 `agentcore/agentcore.json`，並新增一個空的 `app/MastraAgent` 目錄。

## 設定 Agent 項目 {/* #set-up-the-agent-project */}

前往 `app/MastraAgent` 目錄，初始化新的 Node.js 項目：

```bash
cd app/MastraAgent
npm init --init-type=module -y
```

安裝所需的依賴套件。`bedrock-agentcore` 提供 `BedrockAgentCoreApp` HTTP 伺服器，用以實作 [AgentCore Runtime 服務合約](https://docs.aws.amazon.com/bedrock-agentcore/latest/devguide/runtime-service-contract.html)。Mastra Agent 可透過 `@ai-sdk/amazon-bedrock` 和 `@aws-sdk/credential-providers`，以 AgentCore Runtime 的執行角色呼叫 Bedrock。

```bash npm2yarn
npm install bedrock-agentcore @opentelemetry/auto-instrumentations-node @ai-sdk/amazon-bedrock @aws-sdk/credential-providers --legacy-peer-deps
```

同時安裝 TypeScript 及開發所需的依賴套件：

```bash npm2yarn
npm install --save-dev typescript @types/node tsx
```

執行 [`mastra init`](/reference/cli/mastra#mastra-init) 建立 Mastra 項目。提示你選擇 Provider 時，選哪一個都可以，因為下一步會覆寫這項設定。

```bash npm2yarn
npx mastra@latest init
```

將生成的 `src/mastra/agents/weather-agent.ts` 換成以下內容，讓 Agent 使用 Amazon Bedrock。由於下一步會移除儲存層，這裏也要刪除原有的 `memory: new Memory()`。

```ts title="app/MastraAgent/src/mastra/agents/weather-agent.ts"
import { Agent } from '@mastra/core/agent'
import { createAmazonBedrock } from '@ai-sdk/amazon-bedrock'
import { fromNodeProviderChain } from '@aws-sdk/credential-providers'
import { weatherTool } from '../tools/weather-tool.js'

const bedrock = createAmazonBedrock({
  credentialProvider: fromNodeProviderChain(),
})

export const weatherAgent = new Agent({
  id: 'weather-agent',
  name: 'Weather Agent',
  instructions:
    'You are a helpful weather assistant. Use the weatherTool to fetch current weather data.',
  model: bedrock('us.anthropic.claude-sonnet-4-6'),
  tools: { weatherTool },
})
```

:::note

`fromNodeProviderChain()` 讓 Agent 按 SDK 的標準查找順序取得 AWS 憑證，來源包括環境變數、共用配置檔案、SSO，以及容器或 EC2 角色。

:::

替換生成的 `src/mastra/index.ts`，移除預設的檔案儲存和可觀測性配置。AgentCore Runtime 容器以非 root 用戶身份運行，應用程式目錄亦為唯讀。預設的 `LibSQLStore` 因此無法開啟 `./mastra.db`，令執行環境無法啟動。

```ts title="app/MastraAgent/src/mastra/index.ts"
import { Mastra } from '@mastra/core/mastra'
import { PinoLogger } from '@mastra/loggers'
import { weatherWorkflow } from './workflows/weather-workflow.js'
import { weatherAgent } from './agents/weather-agent.js'

export const mastra = new Mastra({
  workflows: { weatherWorkflow },
  agents: { weatherAgent },
  logger: new PinoLogger({
    name: 'Mastra',
    level: 'info',
  }),
})
```

建立 `tsconfig.json`，加入以下內容：

```json title="app/MastraAgent/tsconfig.json"
{
  "compilerOptions": {
    "outDir": "./dist",
    "rootDir": ".",
    "strict": true,
    "esModuleInterop": true,
    "skipLibCheck": true,
    "types": ["node"],
    "declaration": true,
    "target": "ES2022",
    "module": "NodeNext",
    "moduleResolution": "NodeNext",
    "forceConsistentCasingInFileNames": true
  },
  "include": ["*.ts", "src/**/*"],
  "exclude": ["node_modules", "dist"]
}
```

:::note

加入 `tsconfig.json` 後，編輯器會在生成的 `src/mastra` 項目內顯示錯誤。這是因為新配置要求匯入路徑包含副檔名。可參照下例，在相關路徑加上 `.js`：

```ts title="app/MastraAgent/src/mastra/index.ts"
// Before
import { weatherWorkflow } from './workflows/weather-workflow'
// After
import { weatherWorkflow } from './workflows/weather-workflow.js'
```

:::

更新 `package.json`，指定入口和構建指令碼。使用 `npm pkg set` 可保留 `mastra init` 已加入的依賴套件。

```bash
npm pkg set main=dist/agent.js scripts.build=tsc scripts.start="node dist/agent.js" scripts.dev="npx tsx --watch agent.ts"
```

## 初始化 Agent {/* #initialize-the-agent */}

建立 `agent.ts`。每次收到 `POST /invocations` 請求，都會執行這個處理函式。在函式內取得 Mastra Agent，再呼叫它：

```ts title="app/MastraAgent/agent.ts"
import { BedrockAgentCoreApp } from 'bedrock-agentcore/runtime'
import { mastra } from './src/mastra/index.js'

const app = new BedrockAgentCoreApp({
  invocationHandler: {
    process: async (payload, context) => {
      const { prompt } = payload as { prompt: string }

      const agent = mastra.getAgentById('weather-agent')
      const response = await agent.generate(prompt, {
        runId: context.sessionId,
      })

      return response.text
    },
  },
})

app.run()
```

執行 `npm run build`，確認項目能成功編譯。

## 編寫 Dockerfile {/* #create-a-dockerfile */}

在 `app/MastraAgent` 目錄內建立 `Dockerfile`。容器部署使用 Docker 多階段構建，先將 TypeScript 編譯成 JavaScript，正式環境階段則只執行編譯結果。為加強保安，映像會以非 root 用戶身份運行，並開放 8080（HTTP）、8000（MCP）和 9000（A2A）連接埠。啟動時會自動載入 OpenTelemetry 遙測功能。

```dockerfile title="app/MastraAgent/Dockerfile"
FROM node:22-slim AS builder

WORKDIR /app
COPY package*.json ./
RUN npm ci
COPY . .
RUN npm run build

FROM node:22-slim
WORKDIR /app
ENV AWS_REGION=us-east-1
COPY --from=builder /app/dist ./dist
COPY --from=builder /app/node_modules ./node_modules
COPY --from=builder /app/package*.json ./

RUN useradd -m bedrock_agentcore
USER bedrock_agentcore

EXPOSE 8080 8000 9000
CMD ["node", "--require", "@opentelemetry/auto-instrumentations-node/register", "dist/agent.js"]
```

:::note

請選擇與 Bedrock 模型 ID 前綴相配的 `AWS_REGION`（前綴為 `us.`、`jp.`、`eu.` 或 `global.`）。

:::

另建 `.dockerignore`，從 Docker 構建上下文中排除毋須使用的檔案：

```bash
node_modules
dist
.git
*.log
```

## 在本機測試 Agent {/* #test-your-agent */}

返回項目根目錄：

```bash
cd ../..
```

在本機啟動 Agent：

```bash npm2yarn
npx @aws/agentcore dev --runtime MastraAgent
```

開啟另一個終端機視窗，發送測試請求：

```bash npm2yarn
npx @aws/agentcore dev "What is the weather in Tokyo?"
```

## 部署 Agent {/* #deploy-your-agent */}

在 `agentcore/aws-targets.json` 內設定要部署到的 AWS 帳戶和區域：

```json title="agentcore/aws-targets.json"
[
  {
    "name": "default",
    "account": "123456789012",
    "region": "us-east-1"
  }
]
```

部署到 AgentCore Runtime。CLI 會透過 AWS CodeBuild 構建映像，推送到 Amazon ECR，然後建立執行環境和 `DEFAULT` 端點。

```bash npm2yarn
npx @aws/agentcore deploy
```

:::note

部署之前，請在 `agentcore/agentcore.json` 內該 Agent 的 `environmentVariables` 欄位下，設定 Provider API 密鑰及其他機密資料。

:::

## 驗證部署 {/* #verify-your-deployment */}

執行 `agentcore status`，查看執行環境的 ARN、端點和最近的呼叫紀錄，然後用 CLI 呼叫已部署的 Agent：

```bash
npx @aws/agentcore invoke "What is the weather in Tokyo?"
```

如要在生成 token 的同時接收串流輸出，可加上 `--stream`：

```bash
npx @aws/agentcore invoke --stream "Plan a 3-day trip to Tokyo"
```
