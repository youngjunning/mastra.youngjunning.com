# AWS Lambda

使用 Docker 容器配合 [AWS Lambda Web Adapter](https://github.com/awslabs/aws-lambda-web-adapter)，即可將 Mastra 應用程式部署至 AWS Lambda。Mastra 伺服器會以容器化 Lambda 函數的形式運行，並自動調整容量。

:::注意
本指南介紹如何部署 [Mastra 伺服器](/docs/server/overview)。如果你採用[伺服器適配器](/docs/server/server-adapters)或 [Web 框架](/docs/deployment/web-framework)，請沿用該框架的部署方式。
:::

## 開始之前 {/* #before-you-begin */}

開始前請準備以下各項：

* 一個 [Mastra 應用程式](/docs)
* 一個具備 Lambda、ECR 和 IAM 操作權限的 [AWS 帳戶](https://aws.amazon.com/)
* 安裝 **[AWS CLI](https://aws.amazon.com/cli/)**，然後執行 `aws configure` 設定身分驗證
* 安裝並啟動 **[Docker](https://www.docker.com/)**

:::警告
AWS Lambda 的檔案系統只供暫時使用，本機資料庫檔案會在兩次調用之間遺失。如果 [LibSQLStore](/integrations/databases/libsql) 使用本機檔案，請將它設定為連接兼容 LibSQL 的遠端資料庫，例如 [Turso](https://turso.tech/)。
:::

## 建立 Dockerfile {/* #create-a-dockerfile */}

在項目的根目錄建立 `Dockerfile`：

```dockerfile title="Dockerfile"
FROM node:22-alpine

WORKDIR /app

# Install dependencies
COPY package*.json ./
RUN npm ci

# Copy source and build Mastra
COPY src ./src
RUN npx mastra build

# Alpine compatibility for some native deps
RUN apk add --no-cache gcompat

# Add the Lambda Web Adapter
COPY --from=public.ecr.aws/awsguru/aws-lambda-adapter:0.9.1 /lambda-adapter /opt/extensions/lambda-adapter

# Run as non-root
RUN addgroup -g 1001 -S nodejs && \
  adduser -S mastra -u 1001 && \
  chown -R mastra:nodejs /app

USER mastra

# Adapter / app configuration
ENV PORT=8080
ENV NODE_ENV=production
ENV AWS_LWA_READINESS_CHECK_PATH="/api"

# Start the Mastra server
CMD ["node", ".mastra/output/index.mjs"]
```

:::注意
這個 Dockerfile 使用 npm。如使用 pnpm、yarn 或其他套件管理工具，請調整相應的指令。例如，`npm ci` 無法使用 pnpm 的鎖定檔。
:::

## 構建及推送 Docker 映像 {/* #build-and-push-the-docker-image */}

<Steps>
  <StepItem>
    設定部署所需的環境變數。ECR 和 Lambda 等 AWS 服務應採用同一區域，以免在其他區域找不到所需資源：

    ```bash
    export PROJECT_NAME="your-mastra-app"
    export AWS_REGION="us-east-1"
    export AWS_ACCOUNT_ID=$(aws sts get-caller-identity --query Account --output text)
    ```
  </StepItem>

  <StepItem>
    構建 Docker 映像時，請停用 BuildKit，確保映像與 Lambda 的容器執行環境兼容：

    ```bash
    export DOCKER_BUILDKIT=0
    docker build --platform linux/arm64 -t "$PROJECT_NAME" .
    ```

    :::注意
    BuildKit 預設使用的映像格式可能與 Lambda 不兼容。設定 `DOCKER_BUILDKIT=0` 後，Docker 會改用傳統構建工具，產生 Lambda 能穩定接受的映像格式。
    :::
  </StepItem>

  <StepItem>
    建立 Amazon ECR 儲存庫，存放 Docker 映像：

    ```bash
    aws ecr create-repository --repository-name "$PROJECT_NAME" --region "$AWS_REGION"
    ```
  </StepItem>

  <StepItem>
    登入 Amazon ECR：

    ```bash
    aws ecr get-login-password --region "$AWS_REGION" | \
      docker login --username AWS --password-stdin \
      "$AWS_ACCOUNT_ID.dkr.ecr.$AWS_REGION.amazonaws.com"
    ```
  </StepItem>

  <StepItem>
    為映像加上標籤，再推送至 ECR：

    ```bash
    docker tag "$PROJECT_NAME":latest \
      "$AWS_ACCOUNT_ID.dkr.ecr.$AWS_REGION.amazonaws.com/$PROJECT_NAME":latest

    docker push \
      "$AWS_ACCOUNT_ID.dkr.ecr.$AWS_REGION.amazonaws.com/$PROJECT_NAME":latest
    ```
  </StepItem>
</Steps>

## 建立 Lambda 函數 {/* #create-the-lambda-function */}

<Steps>
  <StepItem>
    開啟 [AWS Lambda 控制台](https://console.aws.amazon.com/lambda/)，按 **Create function**。確認控制台所選的區域與建立 ECR 儲存庫時使用的區域相同。
  </StepItem>

  <StepItem>
    選擇 **Container image**，然後配置函數：

    * **函數名稱**：輸入名稱，例如 `mastra-app`。
    * **容器映像 URI**：按 **Browse images**，選擇你的 ECR 儲存庫，再選擇 `latest` 標籤。
    * **架構**：選擇 **arm64**。

    按 **Create function** 建立 Lambda 函數。
  </StepItem>

  <StepItem>
    設定記憶體及逾時上限。前往 **Configuration** > **General configuration**，按 **Edit**：

    * **記憶體**：512 MB，可按應用程式的需要調整。
    * **逾時上限**：至少 1 分鐘。預設的 3 秒對大部分 Mastra 應用程式來說太短。

    按 **Save**。
  </StepItem>

  <StepItem>
    前往 **Configuration** > **Environment variables**，按 **Edit**，加入 Mastra 應用程式所需的環境變數：

    * `OPENAI_API_KEY`：如使用 OpenAI，請填入 OpenAI API 密鑰。
    * `ANTHROPIC_API_KEY`：如使用 Anthropic，請填入 Anthropic API 密鑰。
    * 按需要加入其他 Provider 所需的 API 密鑰等設定。例如，LibSQL 配合 Turso 使用時，請加入 `TURSO_DATABASE_URL` 和 `TURSO_AUTH_TOKEN`。

    按 **Save**。
  </StepItem>

  <StepItem>
    啟用函數 URL，以供外部存取。前往 **Configuration** > **Function URL**，按 **Create function URL**：

    * **身分驗證類型**：選擇 **NONE**，允許公開存取。
    * 在 **Additional settings** 勾選 **Configure cross-origin resource sharing (CORS)**，然後設定以下各項：
      * **允許的來源**：`*`
      * **允許的請求標頭**：`content-type`。如配合 CloudFront 或 API Gateway 等服務使用，亦須允許 `x-amzn-request-context`。
      * **允許的請求方法**：`*`

    按 **Save**。
  </StepItem>
</Steps>

## 驗證部署 {/* #verify-your-deployment */}

<Steps>
  <StepItem>
    從 Lambda 控制台複製 **Function URL**，在瀏覽器開啟 `<your-function-url>/api/agents`。你應會看到一份 JSON 格式的 Agent 清單。
  </StepItem>

  <StepItem>
    現在可以經 HTTP 調用 Mastra 端點。

    :::警告
    在生產環境部署時，請先設定[身分驗證](/docs/auth/overview)，再將端點公開。CORS 只應允許受信任的網域，並應透過 AWS IAM 角色安全地存取其他 AWS 服務。敏感的環境變數應存放在 AWS Secrets Manager 或 Parameter Store。
    :::
  </StepItem>
</Steps>

## 後續步驟 {/* #next-steps */}

按本指南的步驟，即可快速將 Mastra 部署至 AWS Lambda。處理生產工作負載時，可考慮為 Lambda 函數啟用 [CloudWatch 監察](https://docs.aws.amazon.com/lambda/latest/dg/monitoring-cloudwatchlogs.html)，設定 [AWS X-Ray](https://docs.aws.amazon.com/lambda/latest/dg/services-xray.html) 作分散式追蹤，並配置[預置並行](https://docs.aws.amazon.com/lambda/latest/dg/provisioned-concurrency.html)以維持穩定效能。
