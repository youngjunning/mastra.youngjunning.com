# AWS Lambda

使用 Docker 容器將 Mastra 應用程式部署到 AWS Lambda[AWS Lambda Web Adapter](https://github.com/awslabs/aws-lambda-web-adapter)。此方法將您的 Mastra 伺服器作為具有自動擴展功能的容器化 Lambda 函數運行。

:::注意
本指南涵蓋了部署[Mastra server](/docs/server/overview). If you're using a [server adapter](/docs/server/server-adapters)或者[網路框架](/docs/deployment/web-framework)，按照您通常為該框架部署的方式進行部署。
:::

## 開始之前 {/* #before-you-begin */}

你需要：

* 一個[Mastra application](/docs)
* 一個[AWS account](https://aws.amazon.com/) with permissions for Lambda, ECR, and IAM
* **[AWS CLI](https://aws.amazon.com/cli/)**&#x5B89;裝：運行`aws configure` to authenticate
* **[碼頭工人](https://www.docker.com/)**&#x5B89;裝並運行

:::警告
在 AWS Lambda 上，檔案系統是短暫的，因此任何本機資料庫檔案都會在呼叫之間遺失。如果您正在使用[LibSQLStore](/integrations/databases/libsql) with a local file, configure it to use a remote LibSQL-compatible database (for example, [Turso](https://turso.tech/)) instead.
:::

## 建立 Dockerfile {/* #create-a-dockerfile */}

創建一個`Dockerfile` in your project root:

```dockerfile title="Dockerfile"
FROM node:22-alpine

WORKDIR /app

# Install dependencies
COPY package*.json ./
RUN npm ci

# Copy source and build Mastra
COPY src ./src
RUN npx mastra build

# Alpine compatibility for some native deps
RUN apk add --no-cache gcompat

# Add the Lambda Web Adapter
COPY --from=public.ecr.aws/awsguru/aws-lambda-adapter:0.9.1 /lambda-adapter /opt/extensions/lambda-adapter

# Run as non-root
RUN addgroup -g 1001 -S nodejs && \
  adduser -S mastra -u 1001 && \
  chown -R mastra:nodejs /app

USER mastra

# Adapter / app configuration
ENV PORT=8080
ENV NODE_ENV=production
ENV AWS_LWA_READINESS_CHECK_PATH="/api"

# Start the Mastra server
CMD ["node", ".mastra/output/index.mjs"]
```

:::注意
這個 Dockerfile 使用 npm。如果您使用 pnpm、yarn 或其他套件管理器，請相應地調整命令（例如`npm ci` won't work with pnpm lockfiles).
:::

## 建置並推送 Docker 映像 {/* #build-and-push-the-docker-image */}

<Steps>
  <StepItem>
    設定部署的環境變數。對所有 AWS 服務（ECR、Lambda）使用相同區域，以避免資源未跨區域出現的問題：

    ```bash
    export PROJECT_NAME="your-mastra-app"
    export AWS_REGION="us-east-1"
    export AWS_ACCOUNT_ID=$(aws sts get-caller-identity --query Account --output text)
    ```
  </StepItem>

  <StepItem>
    建置您的 Docker 映像。停用 BuildKit 以確保映像與 Lambda 的容器執行時間相容：

    ```bash
    export DOCKER_BUILDKIT=0
    docker build --platform linux/arm64 -t "$PROJECT_NAME" .
    ```

    :::注意
    BuildKit 的預設影像格式可能會導致與 Lambda 的相容性問題。環境`DOCKER_BUILDKIT=0` uses the classic builder, which produces images in a format Lambda reliably accepts.
    :::
  </StepItem>

  <StepItem>
    建立 Amazon ECR 儲存庫來儲存您的 Docker 映像：

    ```bash
    aws ecr create-repository --repository-name "$PROJECT_NAME" --region "$AWS_REGION"
    ```
  </StepItem>

  <StepItem>
    登入 Amazon ECR：

    ```bash
    aws ecr get-login-password --region "$AWS_REGION" | \
      docker login --username AWS --password-stdin \
      "$AWS_ACCOUNT_ID.dkr.ecr.$AWS_REGION.amazonaws.com"
    ```
  </StepItem>

  <StepItem>
    標記您的映像並將其推送到 ECR：

    ```bash
    docker tag "$PROJECT_NAME":latest \
      "$AWS_ACCOUNT_ID.dkr.ecr.$AWS_REGION.amazonaws.com/$PROJECT_NAME":latest

    docker push \
      "$AWS_ACCOUNT_ID.dkr.ecr.$AWS_REGION.amazonaws.com/$PROJECT_NAME":latest
    ```
  </StepItem>
</Steps>

## 建立 Lambda 函數 {/* #create-the-lambda-function */}

<Steps>
  <StepItem>
    導航至[AWS Lambda Console](https://console.aws.amazon.com/lambda/) and click **Create function**. Make sure you have the same region selected as where you created your ECR repository.
  </StepItem>

  <StepItem>
    選擇**Container image** and configure the function:

    * **函數名稱**：輸入名稱（例如`mastra-app`)
    * **容器鏡像URI**： 點選**Browse images**, select your ECR repository, and choose the `latest` tag
    * **建築學**： 選擇**arm64**

    點選**Create function** to create the Lambda function.
  </StepItem>

  <StepItem>
    配置記憶體和超時。前往**Configuration** > **General configuration** and click **Edit**:

    * **記憶**：512 MB（根據您的應用程式需求進行調整）
    * **暫停**：1 分鐘或更長（預設 3 秒對於大多數 Mastra 應用程式來說太低）

    點選**Save**.
  </StepItem>

  <StepItem>
    新增環境變數。前往**Configuration** > **Environment variables** and click **Edit**. Add the variables your Mastra application needs:

    * `OPENAI_API_KEY`：您的 OpenAI API 金鑰（如果使用 OpenAI）
    * `ANTHROPIC_API_KEY`：您的 Anthropic API 金鑰（如果使用 Anthropic）
    * 根據需要提供其他特定於提供者的 API 金鑰（例如`TURSO_DATABASE_URL` and `TURSO_AUTH_TOKEN` if using LibSQL with Turso)

    點選**Save**.
  </StepItem>

  <StepItem>
    啟用函數 URL 以進行外部存取。前往**Configuration** > **Function URL** and click **Create function URL**:

    * **認證類型**： 選擇**NONE** for public access
    * 在下面**Additional settings**, check **Configure cross-origin resource sharing (CORS)**, then configure:
      * **允許來源**: `*`
      * **允許標頭**: `content-type` (`x-amzn-request-context` is also required when used with services like CloudFront/API Gateway)
      * **允許方法**: `*`

    點選**Save**.
  </StepItem>
</Steps>

## 驗證您的部署 {/* #verify-your-deployment */}

<Steps>
  <StepItem>
    複製**Function URL** from the Lambda console and visit `<your-function-url>/api/agents` in your browser. You should see a JSON list of your agents.
  </StepItem>

  <StepItem>
    現在您可以透過 HTTP 呼叫 Mastra 端點。

    :::警告
    對於生產部署，設置[authentication](/docs/auth/overview) before exposing your endpoints publicly, restrict CORS origins to your trusted domains, use AWS IAM roles for secure access to other AWS services, and store sensitive environment variables in AWS Secrets Manager or Parameter Store.
    :::
  </StepItem>
</Steps>

## 後續步驟 {/* #next-steps */}

本指南提供了將 Mastra 部署到 AWS Lambda 的快速入門。對於生產工作負載，請考慮啟用[CloudWatch monitoring](https://docs.aws.amazon.com/lambda/latest/dg/monitoring-cloudwatchlogs.html) for your Lambda function, setting up [AWS X-Ray](https://docs.aws.amazon.com/lambda/latest/dg/services-xray.html) for distributed tracing, and configuring [provisioned concurrency](https://docs.aws.amazon.com/lambda/latest/dg/provisioned-concurrency.html) for consistent performance.
