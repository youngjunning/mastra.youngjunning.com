# Kubernetes

在 [Kubernetes](https://kubernetes.io/) 上透過負載平衡器將流量分配到多個 Pod，讓 Mastra 應用程式可以水平擴展。每個 Pod 各有獨立進程，因此各 Pod 必須共用發佈與訂閱後端及資料庫，才可看見其他 Pod 啟動的工作。

:::note
本指南示範如何用自行編寫的資源清單部署 [Mastra 伺服器](/docs/server/overview)。如要用受管理的 Chart 一併部署 Mastra Server 和 Studio，請參閱 [Kubernetes (Helm)](/integrations/deploy/kubernetes-helm)。如使用[伺服器適配器](/docs/server/server-adapters)或 [Web 框架](/docs/deployment/web-framework)，可沿用該框架的部署方式。
:::

:::beta
多 Pod 支援以[持久化 Agent](/docs/harness/durable-agents) 為基礎。API 尚未穩定，主版本號維持不變時亦可能有不相容的改動。在正式環境採用前，請先查閱[已知限制](#known-limitations)。
:::

## 開始之前 {/* #before-you-begin */}

開始前請準備：

* 一個 [Mastra 應用程式](/docs)
* 一個 [Kubernetes](https://kubernetes.io/docs/setup/) 叢集及 [`kubectl`](https://kubernetes.io/docs/tasks/tools/)
* 一個可供叢集拉取映像的容器映像庫
* 一個共用的 [Redis](https://redis.io/) 實例，所有 Pod 均可連接
* 一個共用的 [PostgreSQL](https://www.postgresql.org/) 資料庫，所有 Pod 均可連接

## 多個 Pod 為何需要共用基礎設施 {/* #why-multiple-pods-need-shared-infrastructure */}

只用一個 Pod 時，所有請求均由同一個進程處理，執行狀態留在該 Pod 的記憶體便足夠。用上多個 Pod 後，瀏覽器可能正在接收 Pod A 的串流，但用戶的下一個請求卻送到 Pod B，而 Pod B 並沒有該次執行的紀錄。

Redis 和 Postgres 讓各 Pod 分別共用事件和執行狀態：

* **發佈與訂閱**負責將事件從發佈的 Pod 傳到其他 Pod。Mastra 採用 [`RedisStreamsPubSub`](/reference/pubsub/redis-streams)，由它為每條對話線程提供租約，確保同一時間僅由一個 Pod 持有該對話。詳見[發佈與訂閱](/docs/server/pubsub)。
* **儲存**負責保留執行狀態。[持久化 Agent](/docs/harness/durable-agents) 會把每次執行保存為 Workflow 快照。即使 Pod 重新啟動，或請求改送到另一個 Pod，任何 Pod 仍可從資料庫恢復該次執行。

## 設定共用基礎設施 {/* #configure-shared-infrastructure */}

設定 `Mastra` 實例以連接 Redis 和 Postgres。由環境變數提供連線資料，所有 Pod 便可使用同一個映像。

安裝後端套件：

```bash npm2yarn
npm install @mastra/redis-streams @mastra/pg @mastra/redis ioredis
```

為 `Mastra` 實例設定發佈與訂閱、儲存及共用快取：

```typescript title="src/mastra/index.ts"
import { Mastra } from '@mastra/core'
import { RedisStreamsPubSub } from '@mastra/redis-streams'
import { RedisServerCache } from '@mastra/redis'
import { PostgresStore } from '@mastra/pg'
import Redis from 'ioredis'

export const mastra = new Mastra({
  // Carries events between pods, and provides
  // per-thread leases so one pod owns a conversation at a time.
  pubsub: new RedisStreamsPubSub({
    url: process.env.REDIS_URL!,
  }),
  // Persists run state so any pod can resume a run.
  storage: new PostgresStore({
    id: 'mastra-storage',
    connectionString: process.env.DATABASE_URL!,
  }),
  // Shared event cache so a reconnecting client can replay missed chunks
  // from any pod, not only the one that started the run.
  cache: new RedisServerCache({ client: new Redis(process.env.REDIS_URL!) }),
})
```

跨 Pod 恢復串流要靠 `cache`。客戶端重新連線後，會從這個快取重播錯過的事件，因此各 Pod 必須共用快取。預設的記憶體快取只可在同一進程內重播事件。

## 使用持久化 Agent {/* #use-durable-agents */}

一般 [`Agent`](/docs/agents/overview) 的串流及審批狀態只存在於一個 Pod 的記憶體。若請求送到另一個 Pod，該 Pod 便無法取得這些資料。[持久化 Agent](/docs/harness/durable-agents) 在 Workflow 內運行 Agent 迴圈並保存其狀態，讓任何 Pod 都可以觀察或恢復同一次執行。

用 `createDurableAgent()` 封裝 Agent：

```typescript title="src/mastra/agents/assistant.ts"
import { Agent } from '@mastra/core/agent'
import { createDurableAgent } from '@mastra/core/agent/durable'

const agent = new Agent({
  id: 'assistant',
  name: 'Assistant',
  instructions: 'You are a helpful assistant.',
  model: '__GATEWAY_OPENAI_MODEL__',
})

export const durableAssistant = createDurableAgent({ agent })
```

將持久化 Agent 註冊到上述 `Mastra` 實例。執行狀態存於 Postgres，事件經 Redis 傳遞，讓每個 Pod 都可存取該次執行。

## 部署 {/* #deploy */}

<Steps>
  <StepItem>
    按照 [Mastra 伺服器](/docs/server/overview)指南建構伺服器並封裝成容器映像，再推送到映像庫。確保伺服器會讀取 `process.env.PORT`，並在 `0.0.0.0` 監聽。
  </StepItem>

  <StepItem>
    將各 Pod 共用的連線字串存入 Secret：

    ```bash
    kubectl create secret generic mastra-secrets \
      --from-literal=REDIS_URL='redis://redis:6379' \
      --from-literal=DATABASE_URL='postgresql://user:pass@postgres:5432/mastra'
    ```
  </StepItem>

  <StepItem>
    套用 Deployment，讓容器使用該映像並讀取共用 Secret。先開一個副本，由第一個 Pod 單獨建立資料庫結構，下一步才增加副本：

    ```yaml title="deployment.yaml"
    apiVersion: apps/v1
    kind: Deployment
    metadata:
      name: mastra
    spec:
      replicas: 1
      selector:
        matchLabels:
          app: mastra
      template:
        metadata:
          labels:
            app: mastra
        spec:
          containers:
            - name: mastra
              image: your-registry/mastra:latest
              ports:
                - containerPort: 8080
              env:
                - name: PORT
                  value: '8080'
              envFrom:
                - secretRef:
                    name: mastra-secrets
              readinessProbe:
                tcpSocket:
                  port: 8080
              livenessProbe:
                tcpSocket:
                  port: 8080
              resources:
                requests:
                  cpu: 500m
                  memory: 512Mi
    ```

    下文的 HorizontalPodAutoscaler 需要 `resources.requests.cpu` 這項設定。Kubernetes 以實際 CPU 用量除以要求的 CPU 資源量，得出使用率。如果沒有設定 CPU 資源要求，控制器就無法計算目標副本數，亦不會調整規模。

    ```bash
    kubectl apply -f deployment.yaml
    ```

    待首個 Pod 就緒，再增加副本數目：

    ```bash
    kubectl wait --for=condition=available deployment/mastra
    kubectl scale deployment/mastra --replicas=3
    ```

    :::note
    各副本都使用同一映像，並連接到同一套 Redis 和 Postgres。單靠增加 Pod 無法跨 Pod 接續執行，還須共用這些基礎設施。
    :::
  </StepItem>

  <StepItem>
    透過 Service 提供存取 Deployment 的入口：

    ```yaml title="service.yaml"
    apiVersion: v1
    kind: Service
    metadata:
      name: mastra
    spec:
      selector:
        app: mastra
      ports:
        - port: 80
          targetPort: 8080
    ```

    ```bash
    kubectl apply -f service.yaml
    ```
  </StepItem>

  <StepItem>
    以 HorizontalPodAutoscaler 自動調整副本數目：

    ```yaml title="hpa.yaml"
    apiVersion: autoscaling/v2
    kind: HorizontalPodAutoscaler
    metadata:
      name: mastra
    spec:
      scaleTargetRef:
        apiVersion: apps/v1
        kind: Deployment
        name: mastra
      minReplicas: 3
      maxReplicas: 10
      metrics:
        - type: Resource
          resource:
            name: cpu
            target:
              type: Utilization
              averageUtilization: 70
    ```

    ```bash
    kubectl apply -f hpa.yaml
    ```

    :::note
    按 CPU 使用率自動調整規模時，叢集內須運行 [metrics-server](https://github.com/kubernetes-sigs/metrics-server)。GKE、EKS 和 AKS 等託管叢集已包含此元件。kind 和 minikube 等本機叢集要先啟用此元件，例如執行 `minikube addons enable metrics-server`。
    :::
  </StepItem>

  <StepItem>
    檢查 Pod 是否正在運行：

    ```bash
    kubectl get pods -l app=mastra
    ```

    在一個終端視窗將 Service 的連接埠轉發到本機。這個指令會留在前景運行：

    ```bash
    kubectl port-forward service/mastra 8080:80
    ```

    另開一個終端視窗，呼叫 API：

    ```bash
    curl http://localhost:8080/api/agents
    ```

    若回應是列出 Agent 的 JSON 清單，即表示部署已開始提供服務。

    :::warning
    公開端點前，請先設定[身份驗證](/docs/auth/overview)。
    :::
  </StepItem>
</Steps>

## 串流和重新連線 {/* #streaming-and-reconnection */}

持久化 Agent 透過共用的發佈與訂閱後端，把串流資料片段發佈到該次執行專用的主題。客戶端斷線後，可傳入執行 ID 呼叫 `observe()` 重新連線，再從共用快取重播漏收的片段：

```typescript title="src/server/reconnect.ts"
const { output, detach } = await durableAssistant.observe(runId)

request.signal.addEventListener('abort', detach, { once: true })

if (request.signal.aborted) detach()

for await (const chunk of output.fullStream) {
  // Chunks from the run, including any missed while disconnected
}
```

Postgres 保存執行狀態，Redis 保存事件，所以重新連線的請求可由任何 Pod 處理，即使執行是由另一個 Pod 啟動。詳見[可恢復的串流](/docs/harness/durable-agents#resumable-streams)。

多個客戶端可同時跟進同一次執行。每次呼叫 `observe()` 都會接收完整串流，所以一名用戶用兩部裝置查看，或兩名用戶各自查看時，內容都會保持同步。某個客戶端退出迴圈或呼叫 `detach()` 時，只有該客戶端會停止接收。請勿在觀察端呼叫 `cleanup()`，因為這會清除其他客戶端重新連線所需的快取事件。

## 跨 Pod 審批 Tool 呼叫 {/* #tool-approval-across-pods */}

持久化 Agent 會在呼叫 Tool 前暫停，等候人工批准。暫停的執行會存入 Postgres，任何 Pod 都可接收批准請求。

啟動一次需要審批的執行：

```typescript title="src/server/approval.ts"
const { runId } = await durableAssistant.stream('Delete the archived records', {
  requireToolApproval: true,
  memory: { thread: 'thread-1', resource: 'user-1' },
})
```

執行會在 Tool 開始運作前暫停。稍後可經任何 Pod 批准這次呼叫：

```typescript
await durableAssistant.resume(runId, { approved: true })
```

負責審批的 Pod 會從 Postgres 載入暫停的執行，執行已獲批准的 Tool 呼叫，再經共用的發佈與訂閱後端送出結果，讓正在跟進該次執行的客戶端收到後續輸出。詳見 [Tool 審批](/docs/harness/durable-agents#tool-approval)。

## 已知限制 {/* #known-limitations */}

* 預設設定只把執行狀態保留在一個 Pod 的進程記憶體內，各 Pod 無法共用。使用[持久化 Agent](/docs/harness/durable-agents) 並共用 Redis 和 Postgres，才可跨 Pod 串流、審批和重新連線。
* 跨 Pod 串流、審批和重新連線均須使用持久化 Agent。一般 Agent 將執行狀態留在記憶體內，無法在另一個 Pod 恢復執行。
* 多個 Pod 如同時啟動並連接到尚未初始化的資料庫，可能會爭相建立資料庫結構，令個別 Pod 無法啟動。先開一個副本，待資料庫結構建立完成後才增加副本。
* 如需更嚴格控制初始化，可在應用程式以外先建立資料庫結構，例如運行一次性的 Kubernetes Job，並在每個 Pod 的 `PostgresStore` 設定 `disableInit: true`。
