# Vercel 部署器

使用 `@mastra/deployer-vercel` 將 Mastra 伺服器部署為 Vercel 上的無伺服器函數。部署器會打包程式碼，並產生符合 Vercel [Build Output API](https://vercel.com/docs/build-output-api/v3) 規格的 `.vercel/output` 目錄，無需額外設定即可部署。

:::note
本指南說明如何部署 [Mastra 伺服器](/docs/server/overview)。如果使用[伺服器配接器](/docs/server/server-adapters)或 [Web 框架](/docs/deployment/web-framework)，請按照該框架的一般方式部署。
:::

## 開始之前 {/* #before-you-begin */}

你需要一個 [Mastra 應用程式](/docs)和一個 [Vercel](https://vercel.com/) 帳戶。

:::warning
Vercel Functions 使用臨時檔案系統，因此你設定的所有儲存服務（包括 Observability 的儲存服務）都必須託管在外部。如果你正以檔案 URL 使用 [LibSQLStore](/integrations/databases/libsql)，請改用遠端託管的資料庫。
:::

## 安裝 {/* #installation */}

將 `@mastra/deployer-vercel` 套件加入項目：

```bash npm2yarn
npm install @mastra/deployer-vercel@latest
```

匯入 [`VercelDeployer`](/reference/deployer/vercel)，並在 Mastra 設定中將它指定為部署器：

```typescript title="src/mastra/index.ts"
import { Mastra } from '@mastra/core'
// highlight-next-line
import { VercelDeployer } from '@mastra/deployer-vercel'

export const mastra = new Mastra({
  // highlight-next-line
  deployer: new VercelDeployer(),
})
```

## 部署 {/* #deploy */}

<Steps>
  <StepItem>
    將項目推送至遠端 Git Provider（例如 GitHub），然後將程式碼庫連接至 Vercel。

    Vercel 預設會執行 `npm run build`，從而觸發 `mastra build`。若尚未設定建置指令碼，請在 `package.json` 中加入 `"build": "mastra build"`。

    :::note

    記得設定執行應用程式所需的環境變數，例如 [Model Provider](/models/providers) 的 API 密鑰。

    :::
  </StepItem>

  <StepItem>
    準備就緒後，點擊 **Deploy**，然後等待首次部署完成。
  </StepItem>

  <StepItem>
    前往 `https://<your-project>.vercel.app/api/agents` 驗證部署；該網址應傳回 Agent 的 JSON 清單。

    Mastra 伺服器的每個端點都以 `/api` 為前綴，因此發出請求時，必須在 URL 中加上這個前綴。
  </StepItem>

  <StepItem>
    現在可以透過 HTTP 呼叫 Mastra 端點。

    :::warning
    對外公開端點前，請先設定[身分驗證](/docs/auth/overview)。
    :::
  </StepItem>
</Steps>

## Studio {/* #studio */}

啟用 `studio` 選項，即可同時部署 [Studio](/docs/studio/overview) 和 API。Studio 以靜態資源形式部署，由 Vercel 的 Edge CDN 提供，因此不會產生函數呼叫。

```typescript title="src/mastra/index.ts"
import { Mastra } from '@mastra/core'
import { VercelDeployer } from '@mastra/deployer-vercel'

export const mastra = new Mastra({
  deployer: new VercelDeployer({
    // highlight-next-line
    studio: true,
  }),
})
```

部署後，可透過根 URL（`https://<your-project>.vercel.app/`）使用 Studio，API 仍位於 `/api/*`。Studio 會自動連線至同源 API，因此不需要額外的環境變數。

Studio 的頁面由 CDN 提供，其他所有路徑的請求都會送往伺服器，因此透過 [`registerApiRoute()`](/docs/server/custom-api-routes) 加入的路由仍可透過各自的路徑存取。請避免為自訂路由選用 Studio 已使用的路徑，例如 `/agents` 或 `/workflows`，因為這些路徑會優先由 Studio 處理。

:::warning
Studio 連接至 Mastra 伺服器後，便可完整存取其中的 Agent、Workflow 和 Tool。請務必在正式環境中採取適當的保護措施，例如要求身分驗證或限制只能透過 VPN 存取，以防止未經授權的存取。
:::

## 選用的覆寫設定 {/* #optional-overrides */}

Vercel 部署器支援將選項寫入 Vercel Output API 的函數設定。可用選項包括 `maxDuration`、`memory` 和 `regions`，詳見 [`VercelDeployer` 參考文件](/reference/deployer/vercel#constructor-options)。

請求逾時受兩項獨立限制約束。`maxDuration`（以秒計）限制 Vercel 允許函數執行的時間；Mastra 的 `server.timeout`（以毫秒計，預設為 `180000`）則限制 Mastra 傳回 `504 Gateway Timeout` 前的等待時間。單獨調高 `maxDuration` 不會延長 Mastra 的 180 秒上限，因此執行 Workflow 等需時較長的請求必須同時調整兩項設定：

```typescript title="src/mastra/index.ts"
export const mastra = new Mastra({
  deployer: new VercelDeployer({ maxDuration: 600 }),
  server: { timeout: 600_000 },
})
```

詳情請參閱[請求逾時](/reference/deployer/vercel#request-timeouts)。

## Observability {/* #observability */}

無伺服器函數可能在傳回回應後立即終止。尚未完成的非同步工作（例如傳送遙測資料）可能因此中斷。等待 `flush()` 完成，可確保所有 Trace 都在函數結束前送出。

```typescript title="api/chat.ts"
import type { VercelRequest, VercelResponse } from '@vercel/node'
import { mastra } from '../src/mastra'

export default async function handler(req: VercelRequest, res: VercelResponse) {
  const { message } = req.body
  const agent = mastra.getAgent('myAgent')
  const result = await agent.generate([{ role: 'user', content: message }])

  await mastra.observability.flush()

  return res.json(result)
}
```

:::warning
Vercel 部署器不會呼叫 `flush`。若需要這項功能，須自行封裝處理函數，加入在傳回回應前執行的邏輯。也可以部署到持續運行的伺服器，例如[虛擬機器](/integrations/deploy/digital-ocean)，這類環境沒有上述問題。
:::
