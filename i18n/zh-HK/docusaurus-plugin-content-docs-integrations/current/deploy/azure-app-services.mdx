# Azure App Services

將您的 Mastra 應用程式部署至 Azure App Services。

:::note
本指南說明如何部署 [Mastra 伺服器](/docs/server/overview)。如果您使用 [伺服器轉接器](/docs/server/server-adapters) 或 [網頁框架](/docs/deployment/web-framework)，請按照該框架的常規方式部署。
:::

## 開始前 {/* #before-you-begin */}

您需要準備以下項目：

- 一個 [Mastra 應用程式](/docs)
- 一個有有效訂閱的 [Azure 帳戶](https://azure.microsoft.com/)
- 一個存放您的 Mastra 應用程式的 [GitHub 儲存庫](https://github.com/)

:::warning
Azure App Services 的部分定價層級使用暫存檔案系統，因此重新部署時會遺失所有本機資料庫檔案。如果您使用 [LibSQLStore](/integrations/databases/libsql) 搭配本機檔案，請將它改為使用與 LibSQL 相容的遠端資料庫（例如 [Turso](https://turso.tech/)）。
:::

## 建立新的 App Service {/* #create-a-new-app-service */}

以下步驟說明如何建立新的 Azure App Service，以託管您的 Mastra 應用程式。這會設定應用程式運行所需的基礎架構和環境。

<Steps>
  <StepItem>
    登入 [Azure Portal](https://portal.azure.com)，前往 **[App Services](https://docs.microsoft.com/en-us/azure/app-service/)**，或在頂部的搜尋欄搜尋該項目。選擇 **Create** 以建立新的 App Service，然後在下拉式選單中選擇 **Web App**。
  </StepItem>

  <StepItem>
    設定 App Service 的各個選項：

    - **Subscription**：選擇您的 Azure 訂閱
    - **Resource Group**：建立新的資源群組，或選擇現有群組
    - **Instance name**：為應用程式輸入一個獨有的名稱（此名稱將成為 URL 的一部分）
    - **Publish**：選擇 **Code**
    - **Runtime stack**：選擇 **Node 22 LTS**
    - **Operating System**：選擇 **Linux**
    - **Region**：選擇較接近用戶的區域
    - **Linux Plan**：視乎所選區域，您可能可以選擇方案。如有此選項，請選擇符合您需要的方案。
    - 選擇 **Review + Create**，等待驗證完成後，再選擇 **Create**。
  </StepItem>

  <StepItem>
    新部署已觸發。等待部署完成後，在後續步驟區段選擇 **Go to resource**。
  </StepItem>

  <StepItem>
    設定 GitHub 部署前，請先設定環境變數。在左側欄前往 **Settings** > **Environment variables**，然後加入所需的環境變數，例如：

    - Model Provider 的 API 金鑰（例如 `OPENAI_API_KEY`）
    - 資料庫連線字串
    - Mastra 應用程式所需的任何其他設定值

    選擇 **Apply** 儲存變更。
  </StepItem>
</Steps>

## GitHub 部署 {/* #github-deployment */}

按照以下步驟，將 Azure App Service 連接至 GitHub 儲存庫，以啟用持續部署。每次將變更推送至儲存庫時，Azure 都會自動建構及部署應用程式。

<Steps>
  <StepItem>
    在左側欄前往 **Deployment Center**，並選擇 **GitHub** 作為部署來源。如果尚未在 Azure 完成 GitHub 驗證，請登入 GitHub。

    在此範例中，繼續使用 [GitHub Actions](https://docs.github.com/en/actions) 作為 Provider。選擇你的組織、儲存庫和分支。

    Azure 會產生 GitHub Workflow 檔案，你可以先預覽再繼續。選擇 **Save**（儲存按鈕位於頁面頂部）。
  </StepItem>

  <StepItem>
    Azure 建立 Workflow 後，會觸發一次 GitHub Actions 執行，並將 Workflow 檔案合併至你的分支。**取消這次首次執行**，因為未作必要修改前，執行會失敗。

    :::warning
    Azure 產生的預設 Workflow 用於 Mastra 應用程式時會執行失敗，因此需要修改。
    :::

    將最新變更拉取至本機儲存庫，然後修改產生的 Workflow 檔案（`.github/workflows/main_<your-app-name>.yml`）：
  </StepItem>

  <StepItem>
    找到名為「npm install, build, and test」的步驟，然後進行以下修改：

    - 將步驟名稱改為「npm install and build」
    - 如果 Mastra 應用程式尚未妥善設定測試，請從 run 區段移除 `npm test` 指令，因為預設的測試指令碼會執行失敗，導致部署中斷。如果測試可以正常執行，則可保留測試指令。
  </StepItem>

  <StepItem>
    找到「Zip artifact for deployment」步驟，將 zip 指令替換為以下指令：

    ```yaml
    run: (cd .mastra/output && zip ../../release.zip -r .)
    ```

    修改後，部署套件只會包含 `.mastra/output` 中的建構產物。
  </StepItem>

  <StepItem>
    提交並推送 Workflow 的修改。Azure 控制台的 **Deployment Center** 會自動觸發建構。查看部署進度，直至部署成功完成。
  </StepItem>
</Steps>

## 驗證部署 {/* #verify-your-deployment */}

建置成功後，請稍候片刻，讓應用程式啟動。您可以使用 Azure Portal **Overview** 分頁中提供的預設 URL，存取已部署的應用程式。應用程式網址為 `https://<your-app-name>.azurewebsites.net`。

從 Azure Portal 複製 URL，然後在瀏覽器中前往 `https://<your-app-name>.azurewebsites.net/api/agents`。頁面應顯示 Agent 的 JSON 清單。

你現在可以透過 HTTP 呼叫 Mastra 端點。

:::warning
公開端點前，請先設定[身分驗證](/docs/auth/overview)。
:::
