# Render

可以透過兩種方式配合使用 [Render](https://render.com/?utm_source=partner\&utm_medium=partnerships\&utm_campaign=2026_partnership_mastra) 與 Mastra：

* **Agent Tool**：讓 Agent 透過 [Mastra Connect](/docs/mastra-platform/connect) 管理 Render 服務、環境變數、日誌及指標。
* **[部署](#deploy-on-render)**：在 Render 上執行 Mastra 應用程式。

## 連接 {/* #connect */}

開始前，請按照 [Connect 設定指南](/docs/mastra-platform/connect#get-started)安裝 `@mastra/connect`，並設定平台專案。

## 在 Render 上部署 {/* #deploy-on-render */}

你可以將 Mastra API 以 [Web Service](https://render.com/docs/web-services?utm_source=partner\&utm_medium=partnerships\&utm_campaign=2026_partnership_mastra) 形式部署在 Render 上，或使用 [Render Workflows](https://render.com/docs/workflows?utm_source=partner\&utm_medium=partnerships\&utm_campaign=2026_partnership_mastra) 執行各自有獨立重試策略的長時間任務。

選擇適合您的應用程式的部署路徑：

* **Mastra API**：將 Mastra [伺服器](/docs/server/overview)部署為設有公開端點的 Web Service。[Web Services 指南](https://render.com/docs/web-services?utm_source=partner\&utm_medium=partnerships\&utm_campaign=2026_partnership_mastra)說明如何部署自訂程式碼或支援的[伺服器適配器](/docs/server/server-adapters)。
* **Mastra Workflow**：在單一任務中執行整個 Mastra Workflow。Render 控制外層執行，Mastra 管理當中的步驟及狀態。設定詳情請參閱[定義 Workflow 任務](https://render.com/docs/workflows-defining?utm_source=partner\&utm_medium=partnerships\&utm_campaign=2026_partnership_mastra)。
* **分散式 Agent 操作**：為每項操作分別設定運算方案、逾時及重試策略。Render Workflows 管理執行佇列，並提供執行狀態的可觀測性。

本節會建立編輯流程，從三個角度平行審閱草稿，再將意見交給編輯 Agent。如要部署 Mastra API，或將整個 Mastra Workflow 作為單一任務執行，請參閱上方連結。

### Render Workflows 如何與 Mastra 整合 {/* #how-render-workflows-integrate-with-mastra */}

Mastra 提供 Agent 及應用程式邏輯，Render Workflows 則定義任務的執行邊界。典型流程分為三層：

1. 父 Render 任務協調執行。
2. 子 Render 任務呼叫 Mastra Agent，分別處理明確的工作。
3. 最後的 Render 任務整合結果。

從一個 Render 任務呼叫另一個任務，會建立串接的任務執行。每次串接執行都在獨立實例中進行；你可以單獨設定該任務的運算資源、逾時及重試策略。

本節的編輯流程會從三個角度平行審閱草稿，再由 Mastra 編輯 Agent 產生修訂稿。你可以透過[線上示範](https://render-workflows-mastra.onrender.com)試用運作中的版本。

### 設定 {/* #setup */}

你需要 Render 帳戶及 Render CLI。開發期間，CLI 會執行本機任務伺服器；你亦可用它在 Render 上建立 Workflow 服務。

安裝 CLI 並登入：

```bash
brew install render
render login
```

:::note
需要 Render CLI `v2.12.0` 或更新版本。其他安裝方法請參閱 [Render CLI 文件](https://render.com/docs/cli?utm_source=partner\&utm_medium=partnerships\&utm_campaign=2026_partnership_mastra)。
:::

建立名為 `render-workflows` 的空白 Mastra 專案：

```bash npm2yarn
npm create mastra@latest render-workflows -- --empty
```

```bash
cd render-workflows
```

安裝 Render SDK：

```bash npm2yarn
npm install @renderinc/sdk tsx
```

設定模型 Provider 的 API 金鑰。以下例子使用 OpenAI：

```text title=".env"
OPENAI_API_KEY=your_openai_api_key
```

任何支援的 [Mastra 模型 Provider](/models)均可使用。

### 建立分散式 Agent 流程 {/* #build-a-distributed-agent-pipeline */}

#### 建立 Agent {/* #create-the-agents */}

在 `src/mastra` 下建立 `agents` 目錄，並在當中建立 `reviewer-agent.ts` 及 `editor-agent.ts`。接着定義這兩個 Agent：

```ts title="src/mastra/agents/reviewer-agent.ts"
import { Agent } from '@mastra/core/agent'

export const reviewerAgent = new Agent({
  id: 'reviewer-agent',
  name: 'Reviewer Agent',
  model: '__GATEWAY_OPENAI_MODEL__',
  instructions: `
    Review the supplied draft only from the requested perspective.
    Identify concrete problems and recommend specific changes.
    Do not rewrite the full draft.
  `,
})
```

```ts title="src/mastra/agents/editor-agent.ts"
import { Agent } from '@mastra/core/agent'

export const editorAgent = new Agent({
  id: 'editor-agent',
  name: 'Editor Agent',
  model: '__GATEWAY_OPENAI_MODEL__',
  instructions: `
    Revise the supplied draft using the reviewers' feedback.
    Return the complete revised draft and nothing else.
    Preserve accurate details and do not introduce unsupported claims.
  `,
})
```

#### 配置 Mastra 實例 {/* #configure-the-mastra-instance */}

在 `src/mastra/index.ts` 中將兩個 Agent 加入 Mastra 實例：

```ts title="src/mastra/index.ts"
import { Mastra } from '@mastra/core/mastra'
import { editorAgent } from './agents/editor-agent.js'
import { reviewerAgent } from './agents/reviewer-agent.js'

export const mastra = new Mastra({
  agents: {
    editorAgent,
    reviewerAgent,
  },
})
```

透過 Mastra 實例取得 Agent，可讓它們存取日誌、儲存及可觀測性等共用應用程式服務。

#### 建立審核任務 {/* #create-the-review-task */}

在 `src` 下建立 `tasks` 目錄。審閱 Agent 每次只處理一個審閱角度；其運算方案、五分鐘逾時及重試策略只適用於該次分析。如模型 Provider 暫時故障，可以重試目前的分析，無須重新執行其他審閱任務。

```ts title="src/tasks/review-task.ts"
import { task } from '@renderinc/sdk/workflows'
import { mastra } from '../mastra/index.js'

type Review = {
  focus: string
  feedback: string
}

export const reviewDraft = task(
  {
    name: 'review_draft',
    plan: 'starter',
    timeoutSeconds: 300,
    retry: {
      maxRetries: 2,
      waitDurationMs: 1_000,
      backoffScaling: 2,
    },
  },
  async function reviewDraft(draft: string, focus: string): Promise<Review> {
    const reviewer = mastra.getAgentById('reviewer-agent')
    const response = await reviewer.generate(`
      Review this draft for ${focus}.
      Draft: ${draft}
    `)
    if (!response.text) {
      throw new Error(`The ${focus} review returned no text`)
    }
    return {
      focus,
      feedback: response.text,
    }
  },
)
```

#### 建立修訂任務 {/* #create-the-revision-task */}

此任務整合意見並產生修訂稿，所用運算方案比各審閱任務更大，逾時時間亦更長。

```ts title="src/tasks/revision-task.ts"
import { task } from '@renderinc/sdk/workflows'
import { mastra } from '../mastra/index.js'

type Review = {
  focus: string
  feedback: string
}

export const reviseDraft = task(
  {
    name: 'revise_draft',
    plan: 'standard',
    timeoutSeconds: 600,
    retry: {
      maxRetries: 2,
      waitDurationMs: 1_000,
      backoffScaling: 2,
    },
  },
  async function reviseDraft(draft: string, reviews: Review[]): Promise<{ draft: string }> {
    const editor = mastra.getAgentById('editor-agent')
    const response = await editor.generate(`
      Revise the draft using the review feedback.
      Draft: ${draft}
      Reviews: ${JSON.stringify(reviews, null, 2)}
    `)
    if (!response.text) {
      throw new Error('The editor returned no text')
    }
    return {
      draft: response.text,
    }
  },
)
```

#### 建立編排任務 {/* #create-the-orchestration-task */}

父任務透過 `Promise.all()` 平行發起三項審閱，再將整合後的意見交給修訂任務。這一層停用重試，因為每個子任務都有自己的重試策略。如啟用編排任務的重試，請確保再次執行不會重複觸發外部副作用或其他非冪等操作。

```ts title="src/tasks/editorial-task.ts"
import { task } from '@renderinc/sdk/workflows'
import { reviewDraft } from './review-task.js'
import { reviseDraft } from './revision-task.js'

export const editorialPipeline = task(
  {
    name: 'editorial_pipeline',
    plan: 'starter',
    timeoutSeconds: 1_200,
    retry: {
      maxRetries: 0,
      waitDurationMs: 1_000,
      backoffScaling: 2,
    },
  },
  async function editorialPipeline(draft: string): Promise<{ draft: string }> {
    const focuses = ['technical clarity', 'structure and flow', 'reader usefulness']
    const reviews = await Promise.all(focuses.map(focus => reviewDraft(draft, focus)))
    return reviseDraft(draft, reviews)
  },
)
```

#### 註冊任務 {/* #register-the-tasks */}

建立 `src/index.ts` 並匯入編輯任務：

```ts title="src/index.ts"
import './tasks/editorial-task.js'
```

執行入口檔案時，模組會載入，並註冊當中透過 `task()` 定義的每項任務。

修改 `tsconfig.json`：

```json title="tsconfig.json"
{
  "compilerOptions": {
    "module": "NodeNext",
    "moduleResolution": "NodeNext",
    "rootDir": "src",
    "outDir": "dist",
    "noEmit": false
  }
}
```

將以下程式加入 `package.json`：

```json title="package.json"
{
  "scripts": {
    "build": "tsc",
    "dev:workflows": "tsx src/index.ts",
    "start:workflows": "node dist/index.js"
  }
}
```

以上檔案構成完整流程。[render-examples/render-workflows-mastra](https://github.com/render-examples/render-workflows-mastra) 採用相同的 `src/` 目錄結構，並加入可啟動父任務的網頁介面。

### 執行流程 {/* #run-the-pipeline */}

#### 本機執行 {/* #local */}

啟動本機 Render Workflows 開發伺服器：

```bash
render workflows dev -- "npm run dev:workflows"
```

在另一個終端機中，列出已註冊的任務：

```bash
render workflows tasks list --local
```

啟動編輯管道：

```bash
render workflows tasks start editorial_pipeline \
  --local \
  --input='["Render Workflows runs long-running tasks outside the request lifecycle."]'
```

本機伺服器會將任務執行紀錄及日誌保存在記憶體中。執行結束後，可透過 `render workflows runs list <task-name> --local` 查看。

#### 正式環境 {/* #production */}

要在 Render 上執行流程，必須建立 *Workflow 服務*。這項 Render 服務保存任務定義：它建置程式碼儲存庫、註冊找到的每項任務，並為每次執行預備一個實例。

<Steps>
  <StepItem>
    #### 將專案推送到 Git 儲存庫 {/* #push-the-project-to-a-git-repository */}

    Render 從 GitHub、GitLab 或 Bitbucket 上的程式碼儲存庫建置 Workflow 服務，因此請將專案推送到其中一個平台。首次使用該平台時，Render 會要求存取儲存庫的權限。
  </StepItem>

  <StepItem>
    #### 建立 Workflow 服務 {/* #create-the-workflow-service */}

    在 [Render Dashboard](https://dashboard.render.com?utm_source=partner\&utm_medium=partnerships\&utm_campaign=2026_partnership_mastra) 選擇 **New > Workflow**，連結上一步的程式碼儲存庫，再填寫建立表格：

    | 欄位 | 值 |
    | - | - |
    |**Language** | Node |
    | **Region** | 任務所連接的其他 Render 服務所在區域 |
    | **Build Command** | `npm install && npm run build` |
    | **Start Command** | `npm run start:workflows` |

    點選 **Deploy Workflow**。Render 會建置專案並註冊 `review_draft`、`revise_draft` 及 `editorial_pipeline`；之後即可在該 Workflow 的 **Tasks** 頁面看到這些任務。

    亦可透過 Render CLI 在終端機建立相同的服務：

    ```bash
    render workflows create \
      --name mastra-workflows \
      --repo . \
      --runtime node \
      --build-command "npm install && npm run build" \
      --run-command "npm run start:workflows"
    ```

    `--repo .` 會讀取本機程式碼儲存庫的 `origin` 遠端，因此必須先推送專案。
  </StepItem>

  <StepItem>
    #### 設定 Workflow 環境變數 {/* #set-the-workflows-environment-variables */}

    首次執行前，請在 Dashboard 中為 Workflow 服務加入 `OPENAI_API_KEY`，或所選模型 Provider 的金鑰。
  </StepItem>

  <StepItem>
    #### 開始執行 {/* #start-a-run */}

    ```bash
    render workflows tasks start mastra-workflows/editorial_pipeline \
      --input='["Render Workflows runs long-running tasks outside the request lifecycle."]'
    ```

    這個識別碼的第一部分是 Workflow 的 slug，第二部分是任務名稱。兩者都顯示在 Render Dashboard 的任務頁面上。如你的 Workflow 名稱不同，請使用該頁面顯示的 slug。

    在 Render Dashboard 中開啟該 Workflow，即可查看每項任務的執行紀錄、嘗試次數、結果及日誌串流。
  </StepItem>
</Steps>

### 從您的應用程式觸發 {/* #trigger-from-your-application */}

你可以使用 Render SDK，從 Mastra 應用程式、Web Service 或程式非同步觸發流程。

透過程式碼觸發執行需要 Render API 金鑰，可在 [Render 帳戶設定](https://render.com/docs/api?utm_source=partner\&utm_medium=partnerships\&utm_campaign=2026_partnership_mastra#1-create-an-api-key)中建立。請在呼叫端服務設定：

```text title=".env"
RENDER_API_KEY=rnd_your_api_key
```

SDK 會自動從環境變數讀取 `RENDER_API_KEY`。

啟動任務並立即傳回執行 ID：

```ts title="src/start-editorial-pipeline.ts"
import { Render } from '@renderinc/sdk'

const render = new Render()

export async function startEditorialPipeline(draft: string) {
  const run = await render.workflows.startTask('mastra-workflows/editorial_pipeline', [draft])

  return {
    taskRunId: run.taskRunId,
  }
}
```

`startTask()` 傳回後，任務仍會繼續執行。如呼叫端需要等待完成結果，請改為呼叫 `await run.get()`。

請求處理程式傳回任務執行 ID 後，應用程式即可回應，無須在整個流程執行期間保持請求連線。
