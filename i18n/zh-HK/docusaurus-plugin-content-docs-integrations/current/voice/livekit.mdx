# LiveKit

## 快速入門 {/* #quickstart */}

即時語音讓用戶可以透過瀏覽器或電話，與 Mastra Agent 即時通話。Mastra 使用開源 WebRTC 平台 [LiveKit](https://livekit.io) 處理即時音訊和影片。

[`@mastra/livekit`](#api-reference) 套件將 Mastra Agent 連接至 [LiveKit Agents 框架](https://docs.livekit.io/agents/)：LiveKit 負責語音活動偵測、串流語音轉文字、語義回合偵測、中途打斷及文字轉語音等音訊處理。Mastra Agent 則使用自己的模型、Tool 和記憶產生每個回應。

如需低延遲、可中途打斷的語音對話，請使用即時語音。如需不依賴 LiveKit、由 Provider 提供的語音轉語音功能，請參閱[語音轉語音](/reference/voice/speech-to-speech)。

以下步驟會從空白專案開始，建立可與你對話的語音 Agent。語音工作階段需要兩個部分：Mastra 伺服器上發出存取權杖的 API 路由，以及獨立執行音訊處理流程、在每個回合呼叫 Agent 的 worker 程序。

<Steps>
  <StepItem>
    安裝整合套件，以及用於語音活動偵測和回合偵測的 LiveKit 插件：

    ```bash npm2yarn
    npm install @mastra/livekit @livekit/agents @livekit/agents-plugin-silero @livekit/agents-plugin-livekit
    ```
  </StepItem>

  <StepItem>
    在 `.env` 檔案設定 LiveKit 憑證。你可以在 [LiveKit Cloud](https://cloud.livekit.io) 建立免費專案，或使用 [`livekit-server --dev`](https://docs.livekit.io/home/self-hosting/local/) 在本機執行伺服器：

    ```bash title=".env"
    LIVEKIT_URL=wss://your-project.livekit.cloud
    LIVEKIT_API_KEY=your-api-key
    LIVEKIT_API_SECRET=your-api-secret
    ```
  </StepItem>

  <StepItem>
    將語音 Agent 加入 Mastra 實例，並公開連線路由。`liveKitConnectionRoute()` 輔助函式會加入 `POST /voice/livekit/connection-details` 端點，用來簽發 LiveKit 權杖，並將 Agent 派遣至房間：

    ```typescript title="src/mastra/index.ts"
    import { Mastra } from '@mastra/core/mastra'
    import { Agent } from '@mastra/core/agent'
    import { liveKitConnectionRoute } from '@mastra/livekit'

    const supportAgent = new Agent({
      id: 'support',
      name: 'Support',
      instructions: 'You are a friendly phone support agent. Keep replies short and conversational.',
      model: '__GATEWAY_OPENAI_MODEL_LUNA__',
    })

    export const mastra = new Mastra({
      agents: { support: supportAgent },
      server: {
        apiRoutes: [liveKitConnectionRoute({ agentName: 'mastra-voice' })],
      },
    })
    ```
  </StepItem>

  <StepItem>
    建立 worker。它以獨立程序執行，接聽 LiveKit 工作階段，並在每個回合呼叫 Agent。worker API 位於 `@mastra/livekit/worker` 入口，因此 Mastra 伺服器不會載入 LiveKit Agents 執行環境。此範例使用 LiveKit Inference 模型字串處理語音轉文字和文字轉語音，無需安裝 Provider 插件：

    ```typescript title="src/mastra/voice-worker.ts"
    import { fileURLToPath } from 'node:url'
    import { createLiveKitWorker, runLiveKitWorker } from '@mastra/livekit/worker'
    import { mastra } from './index'

    export default createLiveKitWorker({
      mastra,
      agent: 'support',
      stt: 'deepgram/nova-3',
      tts: 'cartesia/sonic-3',
      turnDetection: 'multilingual',
      greeting: 'Hi! How can I help you today?',
    })

    if (process.argv[1] === fileURLToPath(import.meta.url)) {
      runLiveKitWorker({ entry: import.meta.url, agentName: 'mastra-voice' })
    }
    ```

    `agent` 選項指定由哪個 Mastra Agent 回應每個工作階段。你可以如範例所示傳入固定的 key；若省略此選項，worker 便會使用派遣中繼資料中的 `agentId`，讓同一個 worker 服務 Mastra 實例中的所有 Agent。
  </StepItem>

  <StepItem>
    先下載回合偵測及語音活動偵測模型，這個步驟只需執行一次。然後在一個終端機執行 worker，並在另一個終端機執行 Mastra 伺服器：

    ```bash
    npx livekit-agents download-files
    npx tsx src/mastra/voice-worker.ts dev
    ```

    ```bash npm2yarn
    npm run dev
    ```

    worker 會向 LiveKit 伺服器註冊並等待工作階段；`mastra dev` 則提供連線路由。
  </StepItem>

  <StepItem>
    與 Agent 對話。開啟託管的 [LiveKit Agents Playground](https://agents-playground.livekit.io) 並連接你的專案，即可開始通話，無需自行建立前端。

    如要連接自己的應用程式，請呼叫連線路由取得權杖。`POST /voice/livekit/connection-details` 的請求內文可包含選填欄位 `agentId`、`threadId` 和 `resourceId`，並會傳回：

    ```json
    {
      "serverUrl": "wss://your-project.livekit.cloud",
      "roomName": "mastra-voice-a1b2c3d4",
      "participantName": "user-1",
      "participantToken": "eyJhbGci..."
    }
    ```

    此回應符合 LiveKit 前端範本使用的資料格式，因此以 [agent-starter-react](https://github.com/livekit-examples/agent-starter-react) 或 [LiveKit React 元件](https://docs.livekit.io/reference/components/react/) 建立的應用程式無需修改即可使用。
  </StepItem>
</Steps>

### 回合偵測與中途打斷 {/* #turn-detection-and-interruptions */}

LiveKit 會判斷用戶何時說完話，以及 Agent 何時被打斷。預設設定適用於多數情況；你也可以透過 `turnHandling` 調整：

```typescript title="src/mastra/voice-worker.ts"
export default createLiveKitWorker({
  mastra,
  agent: 'support',
  stt: 'deepgram/nova-3',
  tts: 'cartesia/sonic-3',
  turnDetection: 'multilingual',
  turnHandling: {
    endpointing: { mode: 'dynamic', minDelay: 300, maxDelay: 3000 },
    interruption: { minDuration: 500, resumeFalseInterruption: true },
  },
})
```

* `turnDetection: 'multilingual'`：在本機 CPU 執行 LiveKit 的語義回合結束模型。模型會讀取即時逐字稿，避免在用戶話未說完時打斷對方。如要根據靜音判斷回合結束，請改用 `'vad'` 或 `'stt'`。
* `endpointing`：限制用戶停止說話後，Agent 等待的時間。
* `interruption`：控制用戶中途打斷 Agent 的行為。當用戶在 Agent 說話時插話，LiveKit 會停止播放並取消進行中的 Mastra 串流，令模型停止產生 token。
* `preemptiveGeneration`：在用戶即將說完話時，提前讓 Mastra Agent 產生回應，以縮短首個 token 的等待時間。worker 預設停用此功能：每次提前產生回應時，Mastra Agent 都會根據暫時的逐字稿執行；即使 LiveKit 之後捨棄該次執行，部分用戶訊息及未曾說出的部分回應仍已儲存至 thread。如果延遲比 thread 記錄準確性更重要，可以使用 `preemptiveGeneration: { enabled: true }` 重新啟用；也可以透過唯讀方式執行回合，同時保留兩者。詳情請參閱[預先產生回應與記憶](#preemptive-generation-with-memory)。

所有選項請參閱 [LiveKit 回合偵測文件](https://docs.livekit.io/agents/logic/turns/)。

如要停用語音活動偵測，請在 `createLiveKitWorker()` 設定 `vad: false`。worker 會向 LiveKit 傳入 `null`；若省略 `vad`，LiveKit 則會啟用內建偵測器。停用時，請選用不依賴 VAD 的回合偵測模式，例如 `'manual'`。`sessionOptions` 中的值會覆蓋 worker 產生的選項，包括 `vad`。

### 為每通電話設定語音和轉錄 {/* #per-call-voices-and-transcription */}

頂層的 `stt` 和 `tts` 選項適用於每通電話。如要按電話選用不同設定，例如為每個租戶指定語音或語言，請改為設定 `configuration.stt` 和 `configuration.tts` 解析函式。每個解析函式會在每通電話執行一次，接收派遣中繼資料、請求上下文、房間名稱及工作上下文，並傳回對應頂層選項可接受的值：插件實例或 Inference 模型字串。傳回 `undefined` 則會使用頂層選項。

以下範例根據派遣中繼資料中的 `tenant` 欄位，為每個租戶指定不同的文字轉語音聲線：

```typescript title="src/mastra/voice-worker.ts"
import * as cartesia from '@livekit/agents-plugin-cartesia'

// One voice id per tenant, resolved from the dispatch metadata on each call.
const tenantVoices: Record<string, string> = {
  meridian: 'your-cartesia-voice-id-1',
  coastal: 'your-cartesia-voice-id-2',
}
// The resolver runs during call setup, so cache plugin instances across calls.
const ttsByVoice = new Map<string, cartesia.TTS>()

export default createLiveKitWorker({
  mastra,
  agent: 'support',
  stt: 'deepgram/nova-3',
  tts: 'cartesia/sonic-3',
  configuration: {
    tts: ({ requestContext }) => {
      const voice = tenantVoices[requestContext?.tenant as string]
      if (!voice) return undefined // fall back to the top-level `tts`
      let tts = ttsByVoice.get(voice)
      if (!tts) {
        tts = new cartesia.TTS({ voice })
        ttsByVoice.set(voice, tts)
      }
      return tts
    },
  },
})
```

`configuration.stt` 以相同方式設定每通電話的轉錄，例如為不同租戶選用不同的轉錄模型或語言。問候語亦可按電話設定：`configuration.greeting.text` 接受使用相同通話上下文的解析函式，讓同一個 worker 以各租戶自己的措辭開始對話。

### 為每通電話設定回合偵測 {/* #per-call-turn-detection */}

LiveKit 的 `TurnDetector` 類別在建立時會讀取工作的 Inference 執行器，因此只能在 LiveKit 工作內建立，不能在定義 worker 選項的模組層級建立。如要使用這類偵測器，請設定 `configuration.turnDetection` 解析函式。它會在每通電話執行一次，使用與 `configuration.stt` 相同的通話上下文，並可傳回頂層 `turnDetection` 選項接受的任何值。傳回 `undefined` 則會使用頂層選項。

```typescript title="src/mastra/voice-worker.ts"
import { turnDetector } from '@livekit/agents-plugin-livekit'

export default createLiveKitWorker({
  mastra,
  agent: 'support',
  stt: 'deepgram/nova-3',
  tts: 'cartesia/sonic-3',
  turnDetection: 'multilingual',
  configuration: {
    // Constructed inside the job, where the inference executor is available.
    turnDetection: () => new turnDetector.MultilingualModel(0.2),
  },
})
```

語義模型的 Inference 執行器必須在 Agent 伺服器啟動前註冊，因此設定此解析函式後，worker 會預先匯入 `@livekit/agents-plugin-livekit`。將頂層 `turnDetection` 設為 `'multilingual'` 或 `'english'`，便只會預先註冊該模型；否則兩個模型都會保持可用。

### 記憶與 thread {/* #memory-and-threads */}

如果選定的 Mastra Agent 已設定記憶功能，每通電話都會對應一個記憶 thread：

* `thread` 預設使用派遣中繼資料中的 `threadId`；若沒有，則使用房間名稱。
* `resource` 預設使用派遣中繼資料中的 `resourceId`；若沒有，則使用 thread。請在此傳入最終用戶的 ID，讓通話歸入正確用戶。Mastra Studio 會傳入 Agent ID，與側邊欄列出 thread 的方式一致。
* 如果 thread 尚未存在，worker 會建立標題為「語音通話」、中繼資料為 `{ source: 'livekit' }` 的 thread，並將口述問候語儲存為第一則助理訊息，讓 thread 呈現完整通話逐字稿。如要停用問候語儲存，請設定 `persistGreeting: false`。

每個回合只會傳送新的用戶輸入；Mastra Memory 會提供對話歷史、語義檢索結果和工作記憶。如要透過語音延續現有文字對話，可在連線請求內文傳入 `threadId`，將工作階段綁定至該 thread。在 Studio 中，從已開啟的聊天開始通話亦會綁定該 thread，逐字稿會在每次對話後加入聊天。

當用戶打斷 Agent，進行中的內容產生會中止，該回合的內容當下不會儲存。LiveKit 會在逐字稿保留用戶實際聽到的部分；到下一個回合，worker 會重新傳送這段內容，補寫至 thread，令記錄與通話一致。如果用戶打斷後立即掛斷，最後這段內容便不會記錄。詳情及對帳方法請參閱[被打斷的回合](#interrupted-turns)。

#### 預先產生回應與記憶 {/* #preemptive-generation-with-memory */}

LiveKit 預先產生回應時，會根據暫時的逐字稿呼叫 Mastra Agent；若逐字稿其後有變，便會捨棄該次執行。插件無法分辨預先嘗試與正式回合，因此設定了 `memory` 時，每次執行都會儲存，包括被捨棄的執行。如要啟用預先產生回應，同時避免寫入不準確的 thread 記錄，請在記憶對應設定中傳入 `options: { readOnly: true }`。Agent 仍可讀取 thread 的歷史、語義檢索結果和工作記憶，但不會寫入，預先嘗試便不會留下記錄。你須自行儲存已確認的回合：從 LiveKit 的 `ConversationItemAdded` 事件取得內容，該事件只會針對工作階段已確認的項目觸發。訊息沿用 LiveKit ID，因此重試儲存也不會產生重複記錄。

```typescript title="src/mastra/voice-worker.ts"
import { voice } from '@livekit/agents'
import { createLiveKitWorker } from '@mastra/livekit/worker'
import { mastra } from './index'

export default createLiveKitWorker({
  mastra,
  agent: 'support',
  memory: ({ metadata, roomName }) => ({
    thread: metadata.threadId ?? roomName,
    resource: metadata.resourceId ?? roomName,
    options: { readOnly: true },
  }),
  turnHandling: { preemptiveGeneration: { enabled: true } },
  onSessionStart: async ({ session, ctx, agent }) => {
    const mapping = agent.memory
    const memory = await mastra.getAgent('support').getMemory()
    if (!mapping || !memory) return

    let shuttingDown = false
    const maxRetries = 5
    const retryTimers = new Set<ReturnType<typeof setTimeout>>()
    ctx.addShutdownCallback(async () => {
      shuttingDown = true
      for (const timer of retryTimers) clearTimeout(timer)
      retryTimers.clear()
    })

    session.on(voice.AgentSessionEventTypes.ConversationItemAdded, ({ item }) => {
      if (item.type !== 'message' || (item.role !== 'user' && item.role !== 'assistant')) return

      const persist = async (attempt = 0): Promise<void> => {
        try {
          await memory.saveMessages({
            messages: [
              {
                id: item.id,
                threadId: mapping.thread,
                resourceId: mapping.resource ?? mapping.thread,
                role: item.role,
                content: {
                  format: 2,
                  parts: [{ type: 'text', text: item.textContent ?? '' }],
                },
                type: 'text',
                createdAt: new Date(),
              },
            ],
          })
        } catch (error) {
          if (shuttingDown) return
          if (attempt >= maxRetries) {
            console.error(`Failed to persist committed voice item ${item.id}; giving up`, error)
            return
          }
          console.error(`Failed to persist committed voice item ${item.id}; retrying`, error)
          const delay = Math.min(1_000 * 2 ** attempt, 30_000)
          const timer = setTimeout(() => {
            retryTimers.delete(timer)
            void persist(attempt + 1)
          }, delay)
          retryTimers.add(timer)
        }
      }

      void persist()
    })
  },
})
```

相同的 `options` 欄位亦適用於 `MastraVoiceAgent` 和 `MastraLLM`；使用遠端傳輸時，欄位會以 `memory.options` 放入請求內文傳送。

### 執行 Tool 時提供語音回應 {/* #speak-while-tools-run */}

如果 Tool 執行需時，語音對話不宜一直沒有聲音。使用 `toolFeedback`，在 Mastra Agent 開始呼叫 Tool 時說一句簡短的話：

```typescript title="src/mastra/voice-worker.ts"
export default createLiveKitWorker({
  mastra,
  agent: 'support',
  stt: 'deepgram/nova-3',
  tts: 'cartesia/sonic-3',
  toolFeedback: ({ toolName }) =>
    toolName === 'searchOrders' ? 'Let me look that up.' : undefined,
})
```

這句話會作為回應的一部分說出，並記錄在逐字稿中。

### 使用 Workflow 產生回應 {/* #generate-replies-with-a-workflow */}

worker 預設使用 Mastra Agent 產生每個回應。如需在每個回合執行多步驟邏輯，例如分類意圖、選擇處理路徑、依序呼叫 Tool，再組織回應，請改用 Mastra [Workflow](/docs/workflows/overview) 產生回應。設定 `workflow`，取代 `agent`。

LiveKit 仍負責音訊處理，並在每個回合呼叫 Mastra 一次，因此 Workflow 每個回合都會執行至完成。Workflow 不能暫停或恢復，回合之間亦不會保留對話狀態。請透過 `workflowInput` 傳入逐字稿，讓 Workflow 保持無狀態：

```typescript title="src/mastra/voice-worker.ts"
import { createLiveKitWorker, chatContextToMessages } from '@mastra/livekit/worker'
import { mastra } from './index'

export default createLiveKitWorker({
  mastra,
  workflow: 'phoneConversation',
  workflowInput: ({ chatCtx }) => ({ history: chatContextToMessages(chatCtx) }),
  replyStep: 'generateResponse',
  stt: 'deepgram/nova-3',
  tts: 'cartesia/sonic-3',
  turnDetection: 'multilingual',
})
```

Workflow 串流輸出的是結構化步驟事件，而非文字。如要在產生 token 時同步朗讀，回應步驟須將 Agent 的文字串流傳入該步驟的 `writer`：

```typescript title="src/mastra/workflows/phone-conversation.ts"
import { createStep } from '@mastra/core/workflows'

const generateResponse = createStep({
  id: 'generateResponse',
  // input and output schemas omitted
  execute: async ({ inputData, mastra, writer, abortSignal }) => {
    const stream = await mastra.getAgent('voice').stream(inputData.history, { abortSignal })
    await stream.textStream.pipeTo(writer)
    return { assistantMessage: await stream.text }
  },
})
```

* `replyStep`：只朗讀指定步驟的輸出。若省略，便會朗讀所有向各自 `writer` 寫入內容的步驟。
* `resultText`：當沒有步驟串流輸出文字時，從最終執行結果取得回應的後備方式。透過 `writer` 串流輸出可縮短首個 token 的等待時間，因此建議優先使用。
* `abortSignal`：將步驟的 `abortSignal` 傳入 `agent.stream()`，讓用戶中途打斷時能迅速停止產生內容。用戶打斷時，worker 會取消該次執行。
* `generate`：如需完全控制產生回應的方式，可以改為傳入 `generate` 函式。它可以是任何將一個對話回合轉為文字串流的回應產生函式。

使用 Workflow 時，worker 不會像 Agent 的 `stream()` 一樣自動儲存回合。你可以在 Workflow 中儲存對話歷史，或以 LiveKit 逐字稿為準，並在每個回合傳入。

### 將 Mastra 用作 LLM 元件 {/* #use-mastra-as-the-llm-component */}

`createLiveKitWorker()` 會替你管理 LiveKit 工作階段。如要自行管理工作階段，請使用 [`MastraLLM`](#mastrallm)：這是標準的 LiveKit LLM 插件，可將 Mastra Agent 放進你建立的 `voice.AgentSession` 的 `llm` 欄位。Mastra 應用程式、Agent 執行流程、Tool、記憶及可觀測功能都在 Mastra 伺服器執行，worker 則透過 HTTP 連接。worker 程序無需載入 Mastra 應用程式、資料庫或模型 Provider 的金鑰。

```typescript title="src/mastra/voice-worker-plugin.ts"
import { fileURLToPath } from 'node:url'
import { defineAgent, voice } from '@livekit/agents'
import * as silero from '@livekit/agents-plugin-silero'
import { MastraLLM } from '@mastra/livekit/plugin'
import { runLiveKitWorker } from '@mastra/livekit/worker'

export default defineAgent({
  entry: async ctx => {
    await ctx.connect()

    const session = new voice.AgentSession({
      llm: new MastraLLM({
        remote: { baseUrl: process.env.MASTRA_URL!, agentId: 'support' },
        memory: { thread: ctx.room.name!, resource: 'user-7' },
      }),
      stt: 'deepgram/nova-3',
      tts: 'cartesia/sonic-3',
      vad: await silero.VAD.load(),
      // Required with `memory` unless memory.options.readOnly is set: LiveKit enables
      // preemptive generation by default.
      turnHandling: { preemptiveGeneration: { enabled: false } },
    })

    await session.start({
      // These instructions never reach the Mastra agent; its own instructions apply.
      agent: new voice.Agent({ instructions: 'Replies come from the Mastra agent.' }),
      room: ctx.room,
    })

    session.say('Hi! How can I help you today?')
  },
})

if (process.argv[1] === fileURLToPath(import.meta.url)) {
  runLiveKitWorker({ entry: import.meta.url, agentName: 'mastra-voice' })
}
```

兩種方式使用同一套回覆流程；按由誰管理會話來選擇：

| | `createLiveKitWorker()` | `MastraLLM` |
| - | - | - |
| 會話管理 | Worker 輔助函式建立並管理 `AgentSession` | 由你的程式碼建立會話，可控制所有 LiveKit 選項及 hook |
| Mastra 應用程式的運行位置 | Worker 進程內 | Mastra 伺服器上，透過 HTTP 連接（或透過 `agent` 在同一進程內運行） |
| Worker 進程需要 | Mastra 應用程式、儲存空間及模型 Provider 金鑰 | LiveKit SDK，以及連接伺服器的網絡存取權 |
| 內置功能 | 問候語、同意機制、由 Agent 主動掛線、對話串初始化、可觀測性資料彙總 | 按需要使用[會話輔助函式](#runendcall)實作 |
| 適用情況 | 快速建立可用的語音 Agent；Studio 語音模式 | 現有 LiveKit 應用程式，以及需要全面控制會話的情況 |

Tool 保留在 Mastra Agent 上，並於伺服器執行。傳入會話的 LiveKit 端 Tool 會被忽略。Worker 可透過 `toolFeedback`（朗讀等待提示）、`onToolCall`（每次 Tool 呼叫開始時觸發）及 `onTurnComplete`（每次回覆完成後，連同文字、Tool 呼叫及 token 用量觸發）取得 Tool 活動資料。如需由 Agent 主動掛線，可在 `onToolCall` 中呼叫 [`runEndCall()`](#runendcall)。

:::warning
不要同時使用 `memory` 選項及 LiveKit 的 `preemptiveGeneration`；自行建立會話時，LiveKit 預設會啟用後者。LiveKit 捨棄預先生成的回合之前，部分用戶訊息和從未朗讀的部分回覆可能已寫入對話串。請設定 `turnHandling: { preemptiveGeneration: { enabled: false } }`；或不使用 `memory`，改為每回合傳入完整逐字稿；或設定 `memory.options.readOnly`，自行儲存已確認的回合。詳見[預先生成與記憶](#preemptive-generation-with-memory)。
:::

`MastraLLM` 亦接受同一進程內的 Mastra `agent` 實例，讓你自行管理會話而毋須另行部署；也可傳入自訂的 `generate` 函式。遠端傳輸功能亦可獨立透過 [`createRemoteAgentReplyGenerator()`](#createremoteagentreplygenerator) 使用，並可接入 `createLiveKitWorker` 的 `generate` 選項，讓內置完整功能的 Worker 連接遠端伺服器。

```typescript
import { dispatchVoiceSession } from '@mastra/livekit'

await dispatchVoiceSession({
  roomName: 'support-call-42',
  agentName: 'mastra-voice',
  metadata: { agentId: 'support', threadId: 'thread-42', resourceId: 'user-7' },

```

### 通話錄音 {/* #record-calls */}

向 `dispatchVoiceSession()` 或 `liveKitConnectionRoute()` 傳入 `recording`，即可建立已設定 [LiveKit 自動 egress](https://docs.livekit.io/transport/media/ingress-egress/egress/autoegress/)的房間。Mastra 會先建立並設定錄音房間，再派遣語音 Agent。不傳入 `recording` 時，現有行為及回傳值維持不變。

錄音需要 LiveKit Cloud 或自行託管的 [egress 服務](https://docs.livekit.io/transport/self-hosting/egress/)，以及輸出位置。以下範例會將來電者及 Agent 的聲音混合，錄製成 S3 bucket 中的一個 OGG 音訊檔案。除 LiveKit 憑證外，亦須在伺服器設定 `RECORDINGS_S3_BUCKET`、`RECORDINGS_S3_REGION`、`RECORDINGS_S3_ACCESS_KEY` 及 `RECORDINGS_S3_SECRET`。

安裝伺服器 SDK，以使用其輸出格式列舉值：

```bash npm2yarn
npm install livekit-server-sdk
```

在只於伺服器使用的模組中定義錄音設定：

```typescript title="src/mastra/recording.ts"
import type { LiveKitRecordingOptions } from '@mastra/livekit'
import { EncodedFileType } from 'livekit-server-sdk'

export const recording: LiveKitRecordingOptions = {
  room: {
    audioOnly: true,
    fileOutputs: [
      {
        fileType: EncodedFileType.OGG,
        filepath: 'calls/{room_name}.ogg',
        output: {
          case: 's3',
          value: {
            bucket: process.env.RECORDINGS_S3_BUCKET!,
            region: process.env.RECORDINGS_S3_REGION!,
            accessKey: process.env.RECORDINGS_S3_ACCESS_KEY!,
            secret: process.env.RECORDINGS_S3_SECRET!,
          },
        },
      },
    ],
  },
}
```

`LiveKitRecordingOptions` 接受用於建立 LiveKit `RoomEgress` 的設定，可以是一般物件或 SDK 實例。設定 `room.audioOnly: true` 可錄製混合音訊；如需分開錄製，則使用 `tracks` 或 `participant`。Mastra 會將設定傳給 LiveKit，不會代你選擇格式或儲存 Provider。其他輸出位置請參閱 [LiveKit 輸出選項](https://docs.livekit.io/transport/media/ingress-egress/egress/outputs/)。

外撥電話時，請先設定錄音，再加入電話參與者：

```typescript title="src/start-call.ts"
import { randomUUID } from 'node:crypto'
import { dispatchVoiceSession } from '@mastra/livekit'
import { recording } from './mastra/recording'

const roomName = `support-call-${randomUUID()}`

await dispatchVoiceSession({
  roomName,
  metadata: { agentId: 'support', resourceId: 'caller-7' },
  recording,
})

// Add the phone participant to roomName through your existing LiveKit SIP code.
```

每次錄音都要使用新的房間名稱，並等待派遣完成後才撥號。如果房間已存在，`dispatchVoiceSession()` 會擲出 `LiveKitRecordingRoomConflictError`；可從 `@mastra/livekit` 匯入此錯誤以處理衝突。檢查房間是否存在與建立房間是兩個獨立請求，因此應用程式須防止其他進程同時建立同名房間。此選項不會在現有房間開始錄音，也不會補錄先前的音訊。

瀏覽器會話則可將相同設定傳入連線路由：

```typescript title="src/mastra/index.ts"
import { Mastra } from '@mastra/core/mastra'
import { liveKitConnectionRoute } from '@mastra/livekit'
import { recording } from './recording'

export const mastra = new Mastra({
  server: {
    apiRoutes: [liveKitConnectionRoute({ recording })],
  },
})
```

啟用錄音後，收到連線資料請求時，路由會在瀏覽器加入前建立房間並派遣 Agent。回應仍為 `{ serverUrl, roomName, participantName, participantToken }`。錄音設定及儲存憑證只保留在伺服器，不會加入連線 token 或 Agent metadata。

路由亦接受同步或非同步的 `recording` 回呼。回呼接收 `{ body, context, roomName }`，其中包括已確定的房間名稱，讓伺服器可逐個會話選擇設定。如要略過該次請求的錄音，回傳 `undefined`。錄音設定不會直接從請求內容讀取。

如果錄音房間已存在，路由會在派遣 Agent 或發出 token 前回傳 HTTP 409。其他建立房間或派遣錯誤亦會令操作失敗；失敗時路由不會發出 token。如果房間建立後派遣失敗，房間仍會留在 LiveKit。設定成功不保證錄音完成或上傳成功。向用戶提供錄音前，請透過 LiveKit 的 [egress 事件](https://docs.livekit.io/intro/basics/rooms-participants-tracks/webhooks-events/#webhook-events)確認完成狀態並取得檔案資料。要驗證設定，可進行測試通話、結束房間，再播放 bucket 中 `calls/` 目錄下的完整檔案，確認包含雙方聲音。

#### 錄音生命週期與同意機制 {/* #recording-lifecycle-and-consent */}

啟用 `recording` 後，錄音會在建立房間時開始，早於瀏覽器連線或電話參與者加入。即使連線請求之後被放棄，Agent 仍可能啟動並耗用錄音及儲存資源。向用戶開放連線路由前，請先設定身份驗證及應用程式限額。

`createConsentTool()` 及 `configuration.consentPolicy` 不控制 LiveKit egress，亦不會延遲、暫停或停止自動錄音。如果應用程式需要在通話中取得同意後才錄音，請先取得同意，再使用 LiveKit 的顯式 egress API，在現有房間開始錄音。單靠語音問候不會限制此功能。

錄音依照 LiveKit 房間的生命週期運作。只中斷 Agent 連線，未必會結束房間或完成檔案。將錄音標記為可用前，請等待 egress 成功完成，並取得檔案結果。應用程式須自行清理設定失敗或遭放棄的房間。

音訊檔案儲存在指定的輸出位置，與 Mastra 記憶、逐字稿及 trace 分開。刪除 Mastra 對話串不會刪除錄音。應用程式須管理終端用戶的儲存空間存取權、保留期限及下載連結。即使逐個會話選擇錄音設定，儲存憑證亦應留在伺服器設定中。
### 在 Studio 中查看錄音 {/* #review-recordings-in-studio */}

註冊 `liveKitRecordingRoute()`，即可在 Studio 的語音通話 trace 面板加入 **Review Audio** 按鈕，開啟該通話的音訊播放器。錄音及 trace 儲存空間均須已設定：路由會讀取已儲存的 `voice call` span，並將其 `roomName` 傳給伺服器端的解析函式。瀏覽器只會提供 trace ID。

解析函式回傳 `{ url, expiresAt? }`；如沒有可用檔案，則回傳 `undefined`。私人儲存空間應使用短期有效的簽署 URL。路由不會在 trace 中儲存播放 URL；每次開啟檢視時，Studio 都會請求新的 URL。檔案不存在或播放出錯時，可按 **Refresh recording**，待上傳完成或連結過期後重試。

使用上述 S3 設定時，錄音及播放應使用相同的 `calls/{room_name}.ogg` 物件 key。即使房間已結束，不同通話仍須使用獨一無二的房間名稱。請在應用程式安裝 AWS SDK：

```bash npm2yarn
npm install @aws-sdk/client-s3 @aws-sdk/s3-request-presigner
```

```typescript title="src/mastra/recording-playback.ts"
import {
  GetObjectCommand,
  HeadObjectCommand,
  S3Client,
  S3ServiceException,
} from '@aws-sdk/client-s3'
import { getSignedUrl } from '@aws-sdk/s3-request-presigner'
import { liveKitRecordingRoute } from '@mastra/livekit'
import { authorizeRecording } from './recording-access'

const s3 = new S3Client({
  region: process.env.RECORDINGS_S3_REGION!,
  credentials: {
    accessKeyId: process.env.RECORDINGS_S3_ACCESS_KEY!,
    secretAccessKey: process.env.RECORDINGS_S3_SECRET!,
  },
})

export const recordingReviewRoute = liveKitRecordingRoute({
  authorize: authorizeRecording,
  resolveRecording: async ({ roomName }) => {
    const object = {
      Bucket: process.env.RECORDINGS_S3_BUCKET!,
      Key: `calls/${roomName}.ogg`,
    }
    try {
      await s3.send(new HeadObjectCommand(object))
    } catch (error) {
      if (error instanceof S3ServiceException && error.$metadata.httpStatusCode === 404)
        return undefined
      throw error
    }
    const expiresIn = 15 * 60
    return {
      url: await getSignedUrl(
        s3,
        new GetObjectCommand({ ...object, ResponseContentType: 'audio/ogg' }),
        { expiresIn },
      ),
      expiresAt: new Date(Date.now() + expiresIn * 1000).toISOString(),
    }
  },
})
```

將 `recordingReviewRoute` 與 `liveKitConnectionRoute({ recording })` 一起加入 `server.apiRoutes`。保留預設路徑 `GET /voice/livekit/recordings/:traceId`，供 Studio 探索。只要 Worker 已儲存通話 trace，而解析函式能找到檔案，便可檢視透過連線路由或伺服器主動派遣所建立的錄音。

檢視路由預設要求身份驗證，並須明確提供 `authorize({ traceId, context })` 回呼。請在應用程式實作 `authorizeRecording` 輔助函式，根據可信的擁有權或租戶紀錄，檢查已登入用戶是否有權存取所請求的 trace。只在允許存取時回傳 `true`。通過身份驗證本身不代表用戶擁有該錄音。

註冊路由時若缺少授權回呼，便會失敗；即使 `requiresAuth` 為 `false` 亦然。拒絕存取的請求會在讀取 trace 儲存空間或產生播放 URL 前回傳 `403`。授權規則出錯亦會停止解析。只有授權成功後，解析函式才會收到已儲存的 `span` 及請求 `context`。

:::warning

只在本機示範中使用 `requiresAuth: false`。這不會略過必需的錄音授權回呼。如果示範用的授權規則允許存取所有錄音，請明確限制它只用於本機開發，並在部署前換掉。

:::

只有錄音上傳權限，並不代表有播放權限。簽署 URL 所用的憑證須對錄音物件具有 `s3:GetObject` 權限，`HEAD` 檢查亦需要此權限。若要讓 S3 對不存在的物件回傳 `404` 而非 `403`，還須具備 `s3:ListBucket` 權限。應用程式可使用獨立的讀取憑證供播放之用。瀏覽器收到的臨時 URL 可授權存取該檔案，應視為敏感資料。詳見 [S3 物件權限](https://docs.aws.amazon.com/AmazonS3/latest/API/API_HeadObject.html)及[預先簽署的 URL](https://docs.aws.amazon.com/AmazonS3/latest/userguide/using-presigned-url.html)。

`liveKitRecordingRoute()` 不依賴特定儲存方式。你可以從其他 Provider，或由 LiveKit 完成事件建立的錄音索引，解析出 URL；毋須依賴 LiveKit 保留過往的 egress 工作。如果使用帶時間戳記的檔案名稱或更換 bucket，請在應用程式保留房間與物件的對應關係，並據此解析，而非直接組成物件 key。

### 可觀測性 {/* #observability */}

Mastra 實例設定了[可觀測性](/docs/observability/overview)後，Worker 會追蹤每次通話。每個會話都會建立一個 `voice call` span，並將以下資料記錄在其下：

* 每個回合的 Mastra Agent 運行紀錄，包括模型生成、Tool 呼叫及記憶操作，與文字聊天的記錄方式相同。
* 每項 LiveKit 音訊流程指標各有一個子 span：語音轉文字、文字轉語音、發話結束（回合偵測）、語音活動偵測，以及模型產生首個 token 所需的時間。這些 span 包含文字 trace 無法顯示的延遲及音訊數據。
* 會話結束時寫入 span 的各模型用量彙總，包括整通電話的 token、字元及音訊總量。

Worker 是獨立進程，因此儲存後端須支援伺服器及 Worker 同時寫入。以 SQLite 為基礎的 [LibSQL](/integrations/databases/libsql) 可以使用；只容許單一寫入者的儲存方式則不適用。Trace、記憶及對話串可以共用同一個儲存空間：

```typescript title="src/mastra/index.ts"
import { Mastra } from '@mastra/core/mastra'
import { LibSQLStore } from '@mastra/libsql'
import { Observability, MastraStorageExporter } from '@mastra/observability'

export const mastra = new Mastra({
  storage: new LibSQLStore({ id: 'voice-agent-storage', url: 'file:./voice-agent.db' }),
  observability: new Observability({
    configs: {
      default: {
        serviceName: 'voice-agent',
        exporters: [new MastraStorageExporter()],
      },
    },
  }),
})
```

預設會啟用追蹤。如要停用，向 `createLiveKitWorker` 傳入 `observability: false`。

### 從應用程式請求播放錄音 {/* #request-recording-playback-from-your-application */}

從 `@mastra/livekit/client` 匯入瀏覽器用戶端輔助函式。要使用此入口點，請安裝 1.x 系列中 1.51.2 或以上版本的 `@mastra/client-js`：

```bash npm2yarn
npm install @mastra/livekit @mastra/client-js
```

```typescript
import { MastraClient } from '@mastra/client-js'
import { getLiveKitRecording } from '@mastra/livekit/client'
import type { LiveKitRecordingResponse } from '@mastra/livekit/client'

const client = new MastraClient({
  baseUrl: 'https://mastra.example.com',
  credentials: 'include',
})

const recording: LiveKitRecordingResponse = await getLiveKitRecording(client, traceId)
if (recording.status === 'ready') {
  audioElement.src = recording.url
}
```

請先在伺服器註冊 [`liveKitRecordingRoute()`](#review-recordings-in-studio)。輔助函式會請求其預設路徑 `/voice/livekit/recordings/:traceId`，不受用戶端 API 前綴影響。它會保留用戶端的身份驗證標頭、Cookie、自訂 fetch 函式及中止訊號。可將 `{ signal }` 作為第三個參數傳入，以取消個別請求。失敗的請求會回傳 `MastraClientError`，且不會自動重試。

`@mastra/client-js@1.51.2` 聲明支援 Zod 3 及 4，但其依賴項 `@ai-sdk/ui-utils@1.2.11` 將 Zod 3 聲明為 peer dependency。版本要求不一致，可能令使用 Zod 4 的嚴格 npm 安裝失敗。配合此 SDK 使用 Zod `^3.25.76`，即可同時滿足兩者的版本要求。沒有安裝可選用戶端 SDK 的伺服器及 Worker 亦支援 Zod 4。

`/client` 入口點不會匯入 LiveKit 伺服器及 Worker 程式碼。此整合的其他入口點不需要 `@mastra/client-js`。安裝 `@mastra/livekit` 時，仍會安裝套件層級的依賴項；瀏覽器入口點只控制哪些程式碼進入瀏覽器 bundle。儲存憑證及錄音授權仍由伺服器處理。

### 回合指標與播放完成狀態 {/* #turn-metrics-and-playback-completion */}

`createLiveKitWorker()` 接受兩個 observer，用於評估語音通話：

```typescript title="src/mastra/voice-worker.ts"
import { createLiveKitWorker } from '@mastra/livekit/worker'

export default createLiveKitWorker({
  mastra,
  agent: 'support',
  onTurnMetrics: metrics => {
    console.info('voice metric', metrics)
  },
  onSpeechComplete: speech => {
    console.info('speech outcome', speech.speechId, speech.outcome)
  },
})
```

Observer 會以非同步方式運行，音訊流程不會等待它們完成。錯誤會寫入日誌。請讓回呼保持簡短。兩個 observer 都不會寫入或協調記憶。

`onTurnMetrics` 會收到帶版本資訊的紀錄，其 `phase: 'generation'` 或 `phase: 'speech'`。生成紀錄包含 `turnId`、獨一無二的 `attemptId`、最終 `outcome`、`durationMs`、可選的 `firstTextMs`，以及 Tool 耗時。同一則用戶訊息的多次嘗試共用同一個回合 ID。Tool 耗時由橋接層收到 Tool 呼叫起，計至收到結果為止；遠端耗時包含傳輸時間，並非純粹的伺服器執行時間。沒有結果的 Tool 呼叫不會有耗時數值。

語音紀錄亦包含 LiveKit 的 `speechId`。橋接層會在助理訊息的 metadata 中記錄回合及嘗試 ID，方便播放後關聯資料。若語音沒有對應的助理訊息，例如取消後沒有產生輸出的語音，則會以語音 ID 作為回合 ID，並省略嘗試 ID。不要按事件抵達次序推斷關聯。

| 指標 | 意義 |
| - | - |
| 生成 `firstTextMs` | 從開始生成，到首段文字送往語音合成的時間。可能包含等待提示語。 |
| 語音 `firstAudioMs` | LiveKit 回報的、從來電者說話結束到首段輸出音訊的時間。可能包含等待提示語。 |
| 語音 `completionMs` | 從來電者說話結束到輸出音訊播放完畢的時間。若語音被打斷、取消或失敗，則不提供此值。 |
| `speechStartedAt` / `speechEndedAt` | 如有提供，表示以 Unix epoch 毫秒計算的播放時間戳記。 |

缺少的指標值為 `undefined`，並非零。本機生成耗時使用單調時鐘計算。LiveKit 的語音時間數值會轉換為毫秒。設定可觀測性後，這些紀錄會以事件形式出現在現有的 `voice call` trace 中。若 LiveKit 有提供語音 ID，音訊流程指標事件會保留該 ID。

`onSpeechComplete` 會在語音 handle 完成時執行一次；若會話關閉時該語音仍在處理中，亦會執行一次。它提供語音指標，以及可選的 `playedText` 和 `transcriptSource`。結果可能是 `completed`、`interrupted`、`cancelled` 或 `failed`。語音生命週期完成，不代表一定產生了音訊；請檢查有否相關音訊指標。

指標來源是 `server-playout`。視乎輸出的同步支援程度，LiveKit 已確認的逐字稿可能只涵蓋部分內容，或屬估算結果；它不能證明遠端瀏覽器或電話聽眾聽到了每個字。`transcriptSource: 'unavailable'` 表示沒有可用的已確認助理逐字稿。

請繼續按原有生成契約使用 `onTurnComplete`。它可能在語音播放完畢前觸發，並顯示 `interrupted: false`，即使來電者稍後打斷音訊亦然。播放結果請使用 `onSpeechComplete`。現有 Agent 記憶可能已儲存生成的文字；加入此 hook 不會改變該儲存行為。

如果由你管理會話，請在 `session.start()` 前，從 `@mastra/livekit/worker` 或 `@mastra/livekit/plugin` 呼叫 `observeVoiceSession(session, { onTurnMetrics, onSpeechComplete })`。呼叫結果可用於移除 observer，並將仍在處理的語音標記為已取消。Worker 會自動附加其 observer。

### 語音片段邊界 {/* #speech-segment-boundaries */}

內置的 Agent、遠端及 Workflow 回覆生成器會保留文字片段與 Tool 步驟的邊界。等待提示語的文字排入佇列後便會送出 flush，因此 Tool 仍在運行時，確認訊息已可送往文字轉語音。Flush 只要求建立片段邊界，不保證每個語音 Provider 都會立即輸出音訊。

自訂生成器仍可回傳字串串流。如要明確標示邊界，請回傳 `ReadableStream<VoiceReplyChunk>`，並將 `VOICE_TEXT_FLUSH` 加入佇列；兩者均由 `@mastra/livekit/worker` 及 `@mastra/livekit/plugin` 匯出。直接讀取回覆生成器的程式碼，須區分字串與邊界物件。切勿將邊界物件串接至逐字稿。

Worker 會將邊界轉換為 LiveKit 的 `FlushSentinel`。使用 `MastraLLM` plugin 時，請為自行管理的 LiveKit Agent 加入 node adapter：

```typescript
import { voice } from '@livekit/agents'
import { MastraLLM, mastraLLMNode } from '@mastra/livekit/plugin'

class SupportAgent extends voice.Agent {
  override llmNode(...args: Parameters<voice.Agent['llmNode']>) {
    return mastraLLMNode(this, ...args)
  }
}

const session = new voice.AgentSession({
  llm: new MastraLLM({ agent: supportAgent }),
  // Configure STT and TTS for your application.
})
await session.start({ agent: new SupportAgent({ instructions: 'Support assistant' }), room })
```

沒有 adapter 時，plugin 仍會輸出文字，但 LiveKit 的預設 node 不會將 plugin 的邊界 metadata 轉換為 flush 標記。在 Workflow 回覆步驟使用 `pipeAgentReplyToWriter()`，可保留計算時間所需的邊界及 Tool 結果。

### 部署 {/* #deployment */}

Worker 與 Mastra 伺服器分屬不同進程。請使用正式環境指令，將其部署為長期運行的 Node 服務：

```bash
node dist/voice-worker.js start
```

LiveKit 關於容量規劃、妥善關閉及託管的指引仍然適用。詳見[部署 Agent](https://docs.livekit.io/agents/ops/deployment/)。Worker 會主動向 LiveKit 建立連線，因此毋須開放入站連接埠。

### 運作方式 {/* #how-it-works */}

LiveKit 語音會話涉及三個環節：

1. Mastra 伺服器簽發 LiveKit 存取 token，並將 Agent 派遣至房間。派遣資料包含 Mastra Agent ID、記憶對話串及資源等 metadata。
1. LiveKit Agent Worker（獨立且長期運行的進程）接收工作並執行音訊流程。音訊透過 WebRTC 在瀏覽器與 Worker 之間傳送，不會經過 Mastra HTTP 伺服器。
1. 每當用戶完成一個回合，Worker 便以新輸入呼叫 Mastra Agent 的 `stream()`，並朗讀串流輸出的文字。用戶打斷時，LiveKit 會取消串流，Mastra 亦會停止生成。

對話歷史儲存在 Mastra Memory，因此語音會話及文字聊天可共用同一個對話串。

## 升級至 0.5.0 {/* #upgrade-to-050 */}

0.5.0 預覽版需要 LiveKit Agents 1.7.1 或更新的 1.x 版本。語音輔助函式會使用 `FlushSentinel` 和 `SpeechHandle.exception()`，但 Agents 1.4.0 並無這些功能。部署前，請測試提供的預覽版本或套件封存檔。更新依賴項的版本範圍不會更新現有的鎖定檔；安裝後請檢查實際安裝的版本。

如果你在較早的快照中使用 `client.getLiveKitRecording(traceId)`，請改用從 `@mastra/livekit/client` 匯入的 `getLiveKitRecording(client, traceId)`。亦請從同一入口匯入 `LiveKitRecordingResponse`，取代從 client-js 匯入的 `GetLiveKitRecordingResponse`。

### 授權存取錄音 {/* #authorize-recording-access */}

升級註冊了 `liveKitRecordingRoute()` 的應用程式前，請加入 `authorize({ traceId, context })` 回呼，檢查已驗證身份的使用者是否有權存取所請求的 trace。即使設定了 `requiresAuth: false`，仍須提供此回呼；否則註冊路由時會擲出錯誤。只有允許存取時才傳回 `true`，而且授權檢查須在查找 trace 或解析播放 URL 之前完成。設定範例請參閱[在 Studio 中檢視錄音](#review-recordings-in-studio)。

### 安裝相容的套件 {/* #install-compatible-packages */}

Agents 及其插件須使用完全相同的發行版本。經測試的基準版本如下：

| 套件 | 版本 |
| - | - |
| `@livekit/agents` | `1.7.1` |
| `@livekit/agents-plugin-livekit` | `1.7.1` |
| `@livekit/agents-plugin-silero` | `1.7.1` |
| `@livekit/rtc-node` | `0.13.34` |
| `livekit-server-sdk` | `2.16.0` |

安裝本機預覽版封存檔時，請一併安裝版本相符的 LiveKit 套件：

```bash npm2yarn
npm install ./mastra-livekit-0.5.0-next.0.tgz @livekit/agents@1.7.1 @livekit/agents-plugin-livekit@1.7.1 @livekit/agents-plugin-silero@1.7.1 @livekit/rtc-node@0.13.34 livekit-server-sdk@2.16.0
```

請將封存檔路徑換成獲提供的預覽版本。其他 `@livekit/agents-plugin-*` 套件也須安裝相同的發行版本。Agents 1.7.1 和 Silero 1.7.1 需要 RTC `^0.13.34`；RTC 1.x 不符合此要求。請勿略過 peer dependency 錯誤強行安裝。

請使用 Node.js 22.13 或更新版本。`@mastra/livekit` 和 Agents 均需要 Zod `^3.25.76 || ^4.1.8`。安裝 0.5.0 前，請先升級較舊的 Zod 版本。然後檢查已安裝的依賴項樹，並初始化 worker 使用的模型：

```bash npm2yarn
npm ls @mastra/livekit @livekit/agents @livekit/agents-plugin-livekit @livekit/agents-plugin-silero @livekit/rtc-node
npx tsx src/mastra/voice-worker.ts download-files
```

整合套件和自訂的 `voice.AgentSession` 須共用同一份已安裝的 Agents。若安裝了多份，LiveKit 的執行階段類別檢查可能會失敗。

### 檢查 VAD 和語句結束偵測 {/* #check-vad-and-turn-detection */}

現在，`vad: false` 會在建立 session 時停用 VAD。過往 worker 雖然略過插件預熱，卻會向 LiveKit 傳入 `undefined`，因此可能啟用 LiveKit 隨附的 VAD。如果應用程式依賴這種行為，請明確設定偵測器。

```typescript title="src/mastra/voice-worker.ts"
import { createLiveKitWorker } from '@mastra/livekit/worker'
import { mastra } from './index'

export default createLiveKitWorker({
  mastra,
  agent: 'support',
  vad: false,
  turnDetection: 'manual',
})
```

預設設定仍會在預熱期間載入 Silero 插件。語句結束偵測選項 `'english'` 和 `'multilingual'` 仍會選用原有的文字模型。你亦可透過現有的實例和 resolver 選項使用 LiveKit 較新的 `inference.VAD` 和 `inference.TurnDetector` API；是否改用這些 API 須另行決定，因為這可能改變語句切分、模型下載和雲端資源用量。

### 檢查自訂 LiveKit Tool {/* #review-custom-livekit-tools */}

Mastra Tool 仍透過 Mastra Agent 執行。如果你亦有實作 LiveKit Tool 或自訂 LiveKit 插件，請留意 Agents 1.4 以來的變更：

* `ToolContext` 是類別。請使用其存取器和 `flatten()`，不要當作一般物件列舉或修改。
* 現在支援具名 Tool 清單及重複名稱檢查。匿名 Tool 的物件簡寫方式仍可使用，毋須轉換所有 Tool 對應表。
* Provider Tool 現在使用 `ProviderTool` 的子類別，而非舊版 `ProviderDefinedTool` API。

自訂插件的遷移詳情請參閱 [LiveKit Tool API](https://github.com/livekit/agents-js/blob/main/agents/src/llm/tool_context.ts)。

### 檢查關閉程序 {/* #review-shutdown */}

`onCallEnd` hook 仍使用 LiveKit 的工作關閉回呼。請確保清理工作在設定的關閉時限內完成，並驗證來電者中斷連線或 worker 收到關閉訊號時，清理工作都能完成。

### 驗證錄音與通話 {/* #verify-recordings-and-calls */}

整合套件的 room 級別 `recording` 設定和 S3 權限維持不變。LiveKit Agents 的 `AgentSession.start({ record })` 控制另一套 session 錄音和遙測功能；停用其中一套錄音不會停用另一套。

正式採用預覽版前，請同時測試瀏覽器通話，以及透過已設定的 SIP trunk 進行的電話通話。檢查雙方語音、中斷、Tool、問候語與同意流程、掛斷、完成的 trace，以及 `onCallEnd`。啟用錄音時，請等待 S3 物件產生，並使用 **Review Audio** 播放。亦須測試停用錄音，以及使用已存在的 room 名稱時能否正確拒絕。這些檢查須在已安裝模型檔案和原生程式庫的部署映像上執行。

## API 參考 {/* #api-reference */}

`@mastra/livekit` 套件將 Mastra Agent 連接至 LiveKit Agents 框架。LiveKit 負責音訊處理流程，包括語音活動偵測、語音轉文字、語句結束偵測、文字轉語音和插話處理；此套件則將回覆產生功能接入 Mastra Agent 的 `stream()` 呼叫。

設定步驟和相關概念請參閱[即時語音](#quickstart)。

此套件有三個入口：

* `@mastra/livekit`：伺服器端 API，包括 [`liveKitConnectionRoute()`](#livekitconnectionroute)、[`dispatchVoiceSession()`](#dispatchvoicesession)、[`pipeAgentReplyToWriter()`](#pipeagentreplytowriter)、[`serializeSessionMetadata()`](#livekitsessionmetadata) 和 [`createEndCallTool()`](#createendcalltool)。請在 Mastra 伺服器程式碼中匯入。此入口不會載入 LiveKit Agents 執行階段。
* `@mastra/livekit/worker`：worker 執行階段，包括 [`createLiveKitWorker()`](#createlivekitworker)、[`runLiveKitWorker()`](#runlivekitworker)、[`chatContextToMessages()`](#chatcontexttomessages)、每個 session 各自使用的 Agent 類別 [`MastraVoiceAgent`](#mastravoiceagent)，以及 session 輔助函式 [`speakGreeting()`](#speakgreeting)、[`waitForAgentDoneSpeaking()`](#waitforagentdonespeaking) 和 [`runEndCall()`](#runendcall)。只應在 worker 入口檔案中匯入。
* `@mastra/livekit/plugin`：LLM 元件插件，包括 [`MastraLLM`](#mastrallm) 和 [`createRemoteAgentReplyGenerator()`](#createremoteagentreplygenerator)。自行建立 `voice.AgentSession` 的 worker 須從此入口匯入。`createRemoteAgentReplyGenerator()` 亦由 `@mastra/livekit/worker` 匯出，因為它可用於 `createLiveKitWorker()` 的 `generate` 選項。`MastraLLM` 只供插件使用。

### `createLiveKitWorker()` {/* #createlivekitworker */}

建立使用 Mastra Agent 回應語音 session 的 LiveKit Agent 定義。請將它設為 worker 入口檔案的預設匯出。

```typescript title="src/mastra/voice-worker.ts"
import { fileURLToPath } from 'node:url'
import { createLiveKitWorker, runLiveKitWorker } from '@mastra/livekit/worker'
import { mastra } from './index'

export default createLiveKitWorker({
  mastra,
  agent: 'support',
  stt: 'deepgram/nova-3',
  tts: 'cartesia/sonic-3',
  turnDetection: 'multilingual',
})

if (process.argv[1] === fileURLToPath(import.meta.url)) {
  runLiveKitWorker({ entry: import.meta.url, agentName: 'mastra-voice' })
}
```

### `pipeAgentReplyToWriter()` {/* #pipeagentreplytowriter */}

在 Workflow 的回覆路徑中，將 Mastra Agent 的回覆串流傳至 Workflow 步驟的 `writer`。它會轉送 Agent 的文字增量，讓文字轉語音在完整回覆準備好之前開始；亦會轉送 Tool 呼叫區塊，讓 `toolFeedback` 觸發，並讓 `onTurnComplete` 取得 Tool 清單。若只傳送 `stream.textStream`，Tool 呼叫會在沒有提示的情況下遺失。請將步驟的 `abortSignal` 傳給 `agent.stream()`，讓使用者插話時能迅速停止產生回覆。

```typescript title="src/mastra/workflows/phone-conversation.ts"
import { pipeAgentReplyToWriter } from '@mastra/livekit'
import { createStep } from '@mastra/core/workflows'

const generateResponse = createStep({
  id: 'generateResponse',
  // input and output schemas omitted
  execute: async ({ inputData, mastra, writer, abortSignal }) => {
    const stream = await mastra.getAgent('support').stream(inputData.turn, { abortSignal })
    const reply = await pipeAgentReplyToWriter(stream, writer)
    return { reply }
  },
})
```

返回：`Promise<string>`，即累積的回覆文字。

### `MastraVoiceAgent` {/* #mastravoiceagent */}

這是 [`createLiveKitWorker()`](#createlivekitworker) 為每個會話建立的 LiveKit `voice.Agent` 子類別。回覆由 Mastra Agent（或自訂 `generate` 來源）經 Agent 的 `llmNode` 產生；LiveKit 繼續處理音訊循環、發話輪次偵測和插話。若你自行管理 `voice.AgentSession`，也可以自行建立此物件。例如，無需語音轉文字、文字轉語音或運作中的 worker，便可使用 `@livekit/agents` 的 `voice.testing` 測試由 Mastra 支援的 Agent。`createMastraVoiceAgent(options)` 是等效的工廠函式。

```typescript title="src/mastra/voice-agent.test.ts"
import { initializeLogger, voice } from '@livekit/agents'

import { supportAgent } from './agents/support'

// Required outside a LiveKit worker: AgentSession needs the LiveKit logger initialized.
initializeLogger({ level: 'silent', pretty: false })

const session = new voice.AgentSession()
await session.start({ agent: new MastraVoiceAgent({ agent: supportAgent, memory: false }) })
```

### `MastraLLM` {/* #mastrallm */}

這是由 Mastra Agent 支援的標準 LiveKit LLM 插件（`llm.LLM`）。若你自行建立 `voice.AgentSession`，並希望在 `llm` 欄位使用 Mastra，便可使用此插件。由 [`createLiveKitWorker()`](#createlivekitworker) 管理則是另一種方式。選擇方法請參閱[使用 Mastra 作為 LLM 元件](#use-mastra-as-the-llm-component)。

使用 `remote` 時，插件透過 HTTP 的 Server-Sent Events (SSE)，從你的 Mastra 伺服器串流傳送每輪回覆。Agent 循環、Tool 和記憶功能都在伺服器端執行；中斷 Agent 亦會中止伺服器端的生成。

```typescript title="src/mastra/voice-worker-plugin.ts"
import { voice } from '@livekit/agents'
import { MastraLLM } from '@mastra/livekit/plugin'

const session = new voice.AgentSession({
  llm: new MastraLLM({
    remote: { baseUrl: process.env.MASTRA_URL!, agentId: 'support' },
    memory: { thread: callId, resource: userId },
  }),
  stt: 'deepgram/nova-3',
  tts: 'cartesia/sonic-3',
  // Required with `memory` unless memory.options.readOnly is set: LiveKit enables
  // preemptive generation by default.
  turnHandling: { preemptiveGeneration: { enabled: false } },
})
```

插件會將 `provider` 回報為 `mastra`，並將 `model` 回報為 Agent id，讓 LiveKit 指標和備援轉接器像處理其他 LLM 一樣識別它。

#### 在 Mastra Agent 中執行的 Tool {/* #tools-run-on-the-mastra-agent */}

Tool 在伺服器端的 Mastra Agent 中定義和執行。插件不會轉送 LiveKit 的 Tool 定義：若會話傳入非空的 `toolCtx`，插件會記錄一次警告，列出被忽略的 Tool。每個 Tool 都必須在伺服器端完成；若 Tool 需要審批或在客戶端執行，該輪會以說明原因的錯誤結束，不會令通話一直停滯。

worker 可透過 `toolFeedback`、`onToolCall` 和 `onTurnComplete` 接收 Tool 活動資訊。

#### 指示 {/* #instructions */}

LiveKit 會把你的 `voice.Agent` 的 `instructions` 加入每個請求的聊天上下文。插件會略過這些指示，因為應以伺服器端 Mastra Agent 自身的指示為準。若要修改提示詞，請修改 Mastra Agent。

#### 中斷的發話輪次 {/* #interrupted-turns */}

當使用者打斷回覆時：

1. 插件取消串流。伺服器中止生成，且不會保存該輪的任何內容。
2. LiveKit 在聊天上下文記錄使用者實際聽到的部分，並標記為已中斷。
3. 下一輪中，插件會在新的使用者訊息之前，重新傳送使用者實際聽到的片段，讓記憶 thread 補回資料，與通話內容一致。訊息帶有 LiveKit 的訊息 id，伺服器會按 id 去重，因此重試和重新傳送都具冪等性。

如果使用者在打斷後立即掛斷，最後那段回覆便不會被記錄。若對話記錄必須包含該片段，請立即根據會話事件補存；由於使用相同的訊息 id，下一輪重新傳送時只會更新或插入，不會產生重複訊息：

```typescript title="src/mastra/voice-worker-plugin.ts"
import { voice } from '@livekit/agents'
import { MastraClient } from '@mastra/client-js'

const client = new MastraClient({ baseUrl: process.env.MASTRA_URL! })

session.on(voice.AgentSessionEventTypes.ConversationItemAdded, ({ item }) => {
  if (item.type !== 'message' || item.role !== 'assistant' || !item.interrupted) return
  void client.saveMessageToMemory({
    agentId: 'support',
    messages: [
      {
        id: item.id,
        threadId: callId,
        resourceId: userId,
        role: 'assistant',
        content: item.textContent ?? '',
        type: 'text',
        createdAt: new Date(),
      },
    ],
  })
})
```

#### 用量指標 {/* #usage-metrics */}

當伺服器回報某輪的 token 用量時，插件會將資料傳給 LiveKit。因此，與其他 LLM 插件一樣，會話的 `metrics_collected` 事件會包含首個 token 的等候時間、持續時間和 token 數量。同一份用量資料（`promptTokens`、`completionTokens`、`promptCachedTokens`、`totalTokens`）亦會以 `result.usage` 傳入 `onTurnComplete`。

#### 錯誤與逾時 {/* #errors-and-timeouts */}

傳輸層會拋出 LiveKit 的 `APIError` 類型（`APIStatusError`、`APIConnectionError`、`APITimeoutError`），因此會話的重試策略（`connOptions.maxRetry`）和 `FallbackAdapter` 故障轉移機制均可照常運作。某輪產生首個 token 後便不會重試：語音回覆應及早失敗，避免重播使用者已聽到一部分的內容。

連線和首個 token 的逾時監察會使用會話的 `connOptions.timeoutMs`（預設 10 秒），因此即使伺服器接受連線後一直沒有傳送串流，通話也不會無限期靜音。

如果 Mastra 伺服器在通話期間停止運作，每次回覆嘗試都會在重試後以特定類型的錯誤失敗。連續多次回覆失敗後，LiveKit 會關閉會話。若能在重試次數耗盡前恢復伺服器，通話便可在下一輪繼續。

#### 訊息內容 {/* #message-content */}

只會提取訊息中的文字：圖片內容會略過，音訊內容則只會以轉錄文字形式納入。語音處理流程不受影響，但你自行加入聊天上下文的項目必須包含文字。

### `createRemoteAgentReplyGenerator()` {/* #createremoteagentreplygenerator */}

建立回覆生成器，透過 HTTP/SSE 在**遠端** Mastra 伺服器執行 Agent 循環。`MastraLLM` 的 `remote` 模式會在內部使用此函式。你亦可將它直接傳入 `createLiveKitWorker` 的 `generate` 選項，讓功能齊備的 worker 連接遠端伺服器：

```typescript title="src/mastra/voice-worker.ts"
import { createLiveKitWorker, createRemoteAgentReplyGenerator } from '@mastra/livekit/worker'
import { mastra } from './index'

export default createLiveKitWorker({
  mastra, // local instance for logger and worker config; replies come from the remote server
  generate: createRemoteAgentReplyGenerator({
    baseUrl: process.env.MASTRA_URL!,
    agentId: 'support',
  }),
  memory: ({ metadata, roomName }) => ({ thread: metadata.threadId ?? roomName }),
  stt: 'deepgram/nova-3',
  tts: 'cartesia/sonic-3',
})
```

使用 `generate` 路徑時，worker 層級的 `toolFeedback` 和 `onTurnComplete` 選項不會生效，worker 的掛斷偵測亦不會觸發；請改為將這些 hooks 傳給生成器。

取消某輪回覆（插話）會終止 HTTP 請求，從而中止伺服器端的生成。錯誤會以 LiveKit 的 `APIError` 類型拋出。`retries` 選項只適用於初始連線嘗試。某輪傳出第一個資料區塊後便不會重試。

### `waitForAgentDoneSpeaking()` {/* #waitforagentdonespeaking */}

當 Agent 不再產生或播放回覆，即其狀態已離開 `thinking` 和 `speaking`，此函式便會完成。如果 Agent 已閒置，則會立即完成；為免無限等待，最遲會在 `maxWaitMs` 內完成，預設為 30 秒。關閉工作階段前使用此函式，讓結束語播完，避免被截斷。

```typescript
import { waitForAgentDoneSpeaking } from '@mastra/livekit/worker'

await waitForAgentDoneSpeaking(session)
```

### `runEndCall()` {/* #runendcall */}

在 Agent 要求掛線後結束通話。此函式會等待 Agent 說完結束語，再不受中斷地播報可選的最後訊息 `message`。之後會刪除房間，並中斷來電者的連線，包括 SIP 來電者。任務會透過已註冊的回呼關閉。

在自行管理的工作階段中，將此函式配合 [`MastraLLM`](#mastrallm) 的 `onToolCall` 及伺服器端 Agent 的[結束通話 Tool](#createendcalltool) 使用，即可讓 Agent 主動掛線：

```typescript title="src/mastra/voice-worker-plugin.ts"
import { MastraLLM } from '@mastra/livekit/plugin'
import { DEFAULT_END_CALL_TOOL, runEndCall } from '@mastra/livekit/worker'

let ending = false

const llm = new MastraLLM({
  remote: { baseUrl: process.env.MASTRA_URL!, agentId: 'support' },
  onToolCall: ({ toolName }) => {
    if (toolName !== DEFAULT_END_CALL_TOOL || ending) return
    ending = true
    void runEndCall(session, ctx, {}, console)
  },
})
```

匯出的常數 `DEFAULT_END_CALL_TOOL`（`'endCall'`）、`DEFAULT_END_CALL_REASON` 和 `DEFAULT_END_CALL_MAX_WAIT_MS`（30000）保存預設值。

### `createEndCallTool()` {/* #createendcalltool */}

建立供 Agent 在想結束通話時呼叫的 Mastra Tool。此 Tool 會發出結束通話的訊號，亦可執行可選的記錄工作；實際掛線由 worker 處理。此 Tool 由可在伺服器安全使用的根入口匯出。請將其加入在伺服器程式碼中定義的 Agent。

```typescript title="src/mastra/agents/support-agent.ts"
import { Agent } from '@mastra/core/agent'
import { createEndCallTool } from '@mastra/livekit'

const supportAgent = new Agent({
  id: 'support',
  name: 'Support',
  instructions:
    'Help the caller. When everything is wrapped up, say goodbye and call endCall as your final action.',
  model: '__GATEWAY_OPENAI_MODEL_LUNA__',
  tools: { endCall: createEndCallTool() },
})
```

使用 `createLiveKitWorker()` 時，設定 `configuration: { endCall: {} }`，worker 便會監聽此 Tool 並掛線。如工作階段由你自行管理，請使用 [`runEndCall()`](#runendcall) 實作掛線。
