# Inworld

## 語音 {/* #voice */}

Mastra 的 Inworld 語音實作透過 Inworld AI API 提供串流文字轉語音（TTS）及批次語音轉文字（STT）。它支援多種 TTS 和 STT 模型、可設定的音訊編碼，以及逐步輸出的音訊串流。

如需即時、全雙工的語音對話，同一套件亦匯出 [`InworldRealtimeVoice`](#realtime)。

### 使用範例 {/* #usage-example */}

```typescript
import { InworldVoice } from '@mastra/voice-inworld'

// Initialize with default configuration (uses INWORLD_API_KEY environment variable)
const voice = new InworldVoice()

// Initialize with custom configuration
const voice = new InworldVoice({
  speechModel: {
    name: 'inworld-tts-2',
    apiKey: 'your-api-key',
  },
  listeningModel: {
    name: 'groq/whisper-large-v3',
    apiKey: 'your-api-key',
  },
  speaker: 'Dennis',
})

// Text-to-Speech (streaming)
const audioStream = await voice.speak('Hello, world!')

// Speech-to-Text
const transcript = await voice.listen(audioStream)
```

### 注意事項 {/* #notes */}

* TTS 端點使用漸進式 NDJSON 串流，因此未收到完整回應前，音訊已可開始播放。
* API 金鑰可透過 `speechModel` 或 `listeningModel` 設定提供，亦可使用 `INWORLD_API_KEY` 環境變數。TTS 和 STT 的金鑰會分別解析：為 `speechModel.apiKey` 和 `listeningModel.apiKey` 指定不同的值，兩項服務即可使用各自的憑證。如只提供其中一個金鑰，另一項服務會先沿用該金鑰，再回退至環境變數。
* `inworld-tts-2` 是預設的旗艦模型。可用 `deliveryMode`（`STABLE`、`BALANCED` 或 `CREATIVE`）調整表達風格。`inworld-tts-2` 會忽略 `temperature` 選項。
* 相比 `inworld-tts-1.5-max`，`inworld-tts-1.5-mini` 的延遲較低，但音質亦較低。

## 即時語音 {/* #realtime */}

`InworldRealtimeVoice` 類別透過 WebSocket 使用 [Inworld AI 的 Realtime API](https://docs.inworld.ai/realtime/quickstart-websocket)，提供即時、全雙工語音互動。它支援語音對話、Tool 呼叫，以及語意語音活動偵測、MCP Tool 路由和播放速度等 Inworld 專用工作階段選項。

Inworld 的傳輸協定遵循 OpenAI Realtime GA 規範，因此客戶端和伺服器的事件名稱與 `@mastra/voice-openai-realtime` 相同。Provider 層面的分別包括：端點在 URL 中使用客戶端產生的工作階段金鑰；使用 `Authorization: Basic <key>` 標頭；透過具型別的建構函數 `session` 欄位設定 Inworld 專用選項；以及透過 `session.providerData` 傳送具型別的 `providerData` 物件，設定 STT、TTS、記憶、回應短語及回應速度等 Inworld 擴充功能。

批次文字轉語音及語音轉文字的用法，請參閱 [`@mastra/voice-inworld`](#voice)。

### 使用範例 {/* #usage-example-1 */}

```typescript title="src/mastra/index.ts"
import { InworldRealtimeVoice } from '@mastra/voice-inworld'
import { playAudio, getMicrophoneStream } from '@mastra/node-audio'

// Initialize with INWORLD_API_KEY from the environment
const voice = new InworldRealtimeVoice()

// Or initialize with explicit configuration
const voiceWithConfig = new InworldRealtimeVoice({
  apiKey: 'your-inworld-api-key',
  model: 'inworld/models/gemma-4-26b-a4b-it',
  speaker: 'Sarah',
  instructions: 'You are a helpful voice assistant.',
  session: {
    audio: {
      output: { speed: 1.1 },
      input: { turn_detection: { type: 'semantic_vad', eagerness: 'high' } },
    },
  },
})

// Establish connection
await voice.connect()

// Listen for audio output (PCM16 @ 24 kHz by default)
voice.on('speaker', stream => {
  playAudio(stream)
})

voice.on('writing', ({ text, role }) => {
  console.log(`${role}: ${text}`)
})

// Convert text to speech
await voice.speak('Hello, how can I help you today?', {
  speaker: 'Hades',
})

// Stream microphone audio to the model
const microphoneStream = getMicrophoneStream()
await voice.send(microphoneStream)

// Clean up
voice.close()
```

> Inworld API 金鑰已完成 Basic 編碼。請原樣填入 `INWORLD_API_KEY`；套件不會重新編碼。

#### `providerData`（Inworld 擴充功能） {/* #providerdata-inworld-extensions */}

`providerData` 是設定 Inworld 專用即時擴充功能的具型別物件。每次傳送 `session.update` 時，它都會置於 `session.providerData` 下，並與透過 `session` 欄位設定的 `session.providerData` 合併；鍵值衝突時以建構函數中的 `providerData` 為準。

它包含五組擴充選項及兩個工作階段層級欄位：

* `stt`：調整 STT，例如 `prompt`、`voice_profile`、`language_hints`，以及 VAD 或話輪結束閾值。
* `tts`：設定 TTS 分段及表達，例如 `segmenter_strategy`、`steering_handling`、`delivery_mode`、`conversational` 和 `user_turn_mode`。
* `memory`：設定自動滾動記憶，例如 `enabled`、`turn_interval` 和 `max_facts`。Inworld 會透過 `memory` 事件回傳狀態。
* `backchannel`：用戶說話時的簡短應答，例如「嗯嗯」。音訊透過 `backchannel` 事件送達。
* `responsiveness`：主要回應產生期間提前播放的填充音訊。填充音訊沿用一般的 `speaker` 和 `speaking` 事件，沒有獨立事件。
* `user_id` 和 `metadata`：傳遞給 Inworld 的工作階段層級識別資料。

```typescript
const voice = new InworldRealtimeVoice({
  providerData: {
    stt: { voice_profile: true, language_hints: ['en-US'] },
    tts: { delivery_mode: 'CREATIVE', segmenter_strategy: 'balanced' },
    memory: { enabled: true, turn_interval: 4 },
    backchannel: { enabled: true, max_per_turn: 1 },
    user_id: 'user-123',
  },
})
```

### 方法 {/* #methods-1 */}

#### `connect()` {/* #connect */}

開啟 WebSocket 連線並傳送初始 `session.update`；伺服器以 `session.updated` 確認後，Promise 才會完成。呼叫 speak()、listen() 或 `send()` 前必須先呼叫此方法。

如 WebSocket 在開啟前觸發 `error` 或 `close`，或握手超過 `connectTimeoutMs`（預設 15 秒），Promise 會被拒絕，而不會產生未捕捉的 socket 錯誤。發生拒絕時，尚未完全建立的連線會關閉。

```typescript
await voice.connect()
```

返回：`Promise<void>`

#### `speak()` {/* #speak */}

向模型傳送文字訊息並觸發音訊回應。傳回的 Promise 只有在今次呼叫觸發的回應完成整個生命週期（收到對應的 `response.done`）後才會完成；如用戶語音打斷回應，或發生傳輸錯誤，Promise 會被拒絕。

應依序呼叫 `speak()`。同時呼叫會共用同一組監聽器，回應與呼叫的對應順序沒有定義。

#### 話輪控制 {/* #turn-taking */}

##### `commitInput()` {/* #commitinput */}

手動將緩衝的輸入音訊提交為一個用戶話輪。將 `turn_detection` 設為 `null` 時，可用此方法實作按掣發話或手動話輪控制。

```typescript
voice.commitInput()
```

返回：`void`

##### `clearInput()` {/* #clearinput */}

捨棄緩衝的輸入音訊，不將其提交為用戶話輪。

```typescript
voice.clearInput()
```

返回：`void`

##### `clearOutput()` {/* #clearoutput */}

清空伺服器的整個輸出音訊緩衝區並停止播放。這亦會停止正在播放的回應短語。預設的插話處理方式（在 `interrupted` 時傳送 `response.cancel`）不會影響回應短語，應優先使用。只有需要清空全部輸出時才使用 `clearOutput()`。

```typescript
voice.clearOutput()
```

返回：`void`

#### `close()` 和 `disconnect()` {/* #close-and-disconnect */}

這兩個方法都會關閉 WebSocket，並將實例標記為已中斷連線。

返回：`void`

#### `getSpeakers()` {/* #getspeakers-1 */}

傳回套件附帶的精選聲線清單。Inworld 的聲線目錄比這份清單更完整；執行時可將任何聲線 ID 傳給 `speaker`。

返回：`Promise<Array<{ voiceId: string }>>`

### 注意事項 {/* #notes-1 */}

* API 金鑰可透過建構函數選項或 `INWORLD_API_KEY` 環境變數提供。金鑰已完成 Basic 編碼，請勿再次編碼。
* WebSocket URL 會附加 `?key=<sessionId>&protocol=realtime`。模型透過初始 `session.update` 設定，不放在 URL。
* 每次呼叫 `speak(input, { speaker })` 時，聲線覆蓋只對該回應有效（透過扁平的 `response.voice` 欄位），不會更改工作階段。
* 音訊輸出預設為 24 kHz PCM16。亦可透過 `session.audio.output.format` 使用 8 kHz 電話音訊格式 `audio/pcmu` 和 `audio/pcma`，或使用 `audio/float32`。
* 傳送音訊、呼叫 `speak()` 或 `listen()` 前，先呼叫 `connect()`。WebSocket 開啟前送出的事件會進入佇列，並在伺服器以 `session.updated` 確認後送出。
* 必須呼叫 `close()` 或 `disconnect()` 關閉語音實例，以釋放 WebSocket。
* 如 `session` 未提供 `audio.input.turn_detection`，預設使用語意 VAD。可傳入自訂物件覆蓋預設值，或傳入 `null` 完全停用話輪偵測。
* `audio.input.transcription` 預設為 `{ model: 'inworld/inworld-stt-1' }`，因此用戶音訊的 `writing` 事件預設可用。可傳入自訂物件覆蓋預設值，或傳入 `null` 停用用戶音訊轉錄。
* `on()` 和 `off()` 按 `InworldVoiceEventMap` 提供型別。已知事件名稱對應具型別的回調負載；未知名稱的負載型別為 `unknown`。
