# 儲存

儲存是 Mastra 執行環境的持久儲存層。即使程序重啟，記憶、Workflow 狀態、可觀測性資料、評估結果、排程和長時間執行的 Agent 狀態仍然可用。

以下功能由儲存層提供資料：

- [Memory](/docs/memory/overview)：訊息紀錄、執行緒、資源和工作記憶。
- [Workflow](/docs/workflows/overview)：暫停及恢復執行所用的持久快照。
- [可觀測性](/docs/observability/overview)：Trace、Span、指標、日誌和回饋。
- [Evals](/docs/evals/overview)：分數、資料集、實驗和評估結果。
- [長時間執行的 Agent](/docs/harness/durable-agents)：背景任務、排程、目標和執行緒狀態。

## 何時設定儲存 {/* #when-to-configure-storage */}

如果狀態需要在重啟後保留，或需要跨程序共用，請設定持久儲存適配器。這樣也可在不同的 Studio 工作階段查看狀態。預設的記憶體儲存適合測試和短時間的本機實驗，但程序結束後便會遺失資料。

如果應用程式需要以下任何功能，便應使用儲存：

- Agent 記住以往的訊息或有關用戶的資料。
- Workflow 可暫停，並在重啟後恢復執行。
- 保留 Trace、指標、日誌、分數或回饋，供日後分析。
- 排程和背景任務可在不同部署之間繼續執行。
- 多個執行環境程序讀寫同一份狀態。

## 儲存的運作方式 {/* #how-storage-works */}

Mastra 的儲存按**領域**劃分。每個領域管理一類執行階段資料，而儲存適配器可實作一個或多個領域。

| 領域 | 儲存內容 |
| - | - |
| `memory` | 執行緒、訊息、資源、工作記憶和其他 Agent 記憶狀態。 |
| `workflows` | 暫停及恢復執行所用的 Workflow 快照。 |
| `observability` | Trace、Span、指標、日誌和回饋。 |
| `scores` | 評估分數紀錄。 |
| `datasets` | 評估和實驗所用的資料集紀錄及項目。 |
| `experiments` | 實驗執行紀錄和個別項目的實驗結果。 |
| `backgroundTasks` | 背景任務紀錄及執行狀態。 |
| `schedules` | 排程定義和觸發紀錄。 |
| `threadState` | 持久儲存的任務、目標和執行緒狀態。 |

各適配器支援的領域有所不同。完整領域清單和內置結構描述詳見[儲存參考概覽](/reference/storage/overview)。

## 按資料存取模式選擇後端 {/* #choose-a-backend-by-data-shape */}

不同領域寫入和查詢的資料種類各異。應按領域的存取模式選擇後端：

- `memory`：每次呼叫使用記憶的 Agent 都會讀寫資料列。請選用支援交易的資料庫，例如 libSQL、PostgreSQL 或 MongoDB。
- `observability`：寫入大量遙測資料，並經常進行彙總查詢。請使用專用的可觀測性儲存，或 ClickHouse、DuckDB 等聯機分析處理（OLAP）後端。
- `workflows`：儲存持久快照，以確保在恢復執行時可以讀取。請使用可靠的持久儲存資料庫。
- `scores`、`datasets` 和 `experiments`：儲存寫入頻率較低的評估資料，這些資料通常在分析時才讀取。
- `schedules`：儲存排程定義和觸發紀錄。請選用已實作排程領域的適配器。

如果不同領域有不同的運作要求，可透過[組合儲存](#composite-storage)將各領域導向合適的後端。

## 在本機開始使用 {/* #get-started-locally */}

本機開發可使用以檔案儲存資料的 libSQL 資料庫。這樣毋須另行運行資料庫伺服器，重啟後亦可保留狀態。

```typescript title="src/mastra/index.ts"
import { Mastra } from '@mastra/core'
import { LibSQLStore } from '@mastra/libsql'

export const mastra = new Mastra({
  storage: new LibSQLStore({
    id: 'mastra-storage',
    url: 'file:./mastra.db',
  }),
})
```

:::tip[與 Studio 共用資料庫]

如同時執行 `mastra dev` 和應用程式，請使用絕對路徑，使兩個程序存取同一個資料庫：

```typescript
url: 'file:/absolute/path/to/your/project/mastra.db'
```

`file:./mastra.db` 等相對路徑是以各程序的工作目錄為基準，而這些目錄未必相同。

:::

Mastra 會在首次使用時初始化所需的儲存結構。

## 正式環境設定 {/* #configure-for-production */}

正式環境應使用持久儲存的託管資料庫。PostgreSQL 適合作為大多數團隊的預設選擇，因為它適合處理需要交易的執行階段狀態，亦有多種託管服務可供選擇。

正式環境的建議設定：

- 使用具備備份、監察和連線池的託管資料庫。
- 多程序的正式部署不應使用 `file:./mastra.db` 等本機檔案資料庫。
- 使用[組合儲存](#composite-storage)，將資料量大的領域，尤其是 `observability`，導向專用後端。
- 在儲存適配器或組合儲存設定[保留](/reference/storage/retention)政策，再由排程器或維護任務呼叫 `storage.prune()`。
- 按應用程式使用的領域選擇 Provider。例如，排程需要已實作 `schedules` 領域的適配器。

## 設定範圍 {/* #configuration-scope */}

你可在 Mastra 實例或 Agent 層級設定儲存。

### 實例層級儲存 {/* #instance-level-storage */}

在同一 Mastra 實例註冊的 Agent、Workflow、可觀測性、Evals、排程及其他執行階段功能，均共用實例層級的儲存。

<Tabs>
  <TabItem value="postgresql" label="PostgreSQL">
    ```typescript title="src/mastra/index.ts"
    import { Mastra } from '@mastra/core'
    import { PostgresStore } from '@mastra/pg'

    export const mastra = new Mastra({
      storage: new PostgresStore({
        id: 'mastra-storage',
        connectionString: process.env.DATABASE_URL,
      }),
    })
    ```
  </TabItem>

  <TabItem value="mongodb" label="MongoDB">
    ```typescript title="src/mastra/index.ts"
    import { Mastra } from '@mastra/core'
    import { MongoDBStore } from '@mastra/mongodb'

    export const mastra = new Mastra({
      storage: new MongoDBStore({
        id: 'mastra-storage',
        uri: process.env.MONGODB_URI,
        dbName: process.env.MONGODB_DB_NAME,
      }),
    })
    ```
  </TabItem>
</Tabs>

如果大部分執行階段資料領域可共用同一資料庫，便可使用實例層級儲存。

### Agent 層級儲存 {/* #agent-level-storage */}

Agent 層級儲存是在 `Memory` 實例上設定，只會為該 Agent 的記憶資料覆蓋實例層級的儲存設定。

```typescript title="src/mastra/agents/support-agent.ts"
import { Agent } from '@mastra/core/agent'
import { Memory } from '@mastra/memory'
import { PostgresStore } from '@mastra/pg'

export const supportAgent = new Agent({
  id: 'support-agent',
  name: 'Support agent',
  instructions: 'Answer customer support questions.',
  model: '__GATEWAY_OPENAI_MODEL__',
  memory: new Memory({
    storage: new PostgresStore({
      id: 'support-agent-storage',
      connectionString: process.env.SUPPORT_AGENT_DATABASE_URL,
    }),
  }),
})
```

如果 Agent 的記憶需要獨立隔離，或需要使用另一個記憶後端，便應使用 Agent 層級儲存。

## 組合儲存 {/* #composite-storage */}

[`MastraCompositeStore`](/reference/storage/composite) 可將不同領域導向不同的後端。如果單一資料庫並不適用於所有領域，可使用組合儲存。

以下範例使用 libSQL 作為預設儲存後端，並將 Workflow 狀態交由 PostgreSQL 儲存：

```typescript title="src/mastra/index.ts"
import { Mastra } from '@mastra/core'
import { MastraCompositeStore } from '@mastra/core/storage'
import { LibSQLStore } from '@mastra/libsql'
import { WorkflowsPG } from '@mastra/pg'

export const mastra = new Mastra({
  storage: new MastraCompositeStore({
    id: 'composite-storage',
    default: new LibSQLStore({
      id: 'default-storage',
      url: 'file:./mastra.db',
    }),
    domains: {
      workflows: new WorkflowsPG({
        connectionString: process.env.DATABASE_URL,
      }),
    },
  }),
})
```

你亦可將 `observability` 導向專用分析後端。有關範例請參閱[可觀測性快速入門](/docs/observability/overview#quickstart)。
