# 子Agent

**添加於：** `@mastra/core@1.8.0`

子Agent是專門的Agent，另一個Agent可以將任務委派給它。將它們新增至父Agent程式中`agents` property, then call [`Agent.stream()`](/reference/streaming/agents/stream)或者[`Agent.generate()`](/reference/agents/generate)。父Agent使用其指令和每個子Agent的指令`description`決定何時以及如何委派任務。

## 何時使用子Agent {/* #when-to-use-subagents */}

當任務需要不同專業的Agent一起工作時，請使用子Agent程式。父Agent決定何時委託並將上下文傳遞給每個子Agent程式。然後它綜合他們的結果。

常見用例：

* 研究和編寫Workflow，其中一個Agent收集數據，另一個Agent程式產生內容
* 每個階段需要不同專業知識的多步驟任務
* 需要對委派行為進行細粒度控制的任務

：：：筆記

協調子Agent的父Agent通常稱為主管。主管模式是在 Mastra 中建構多Agent系統的一種方法。其他模式，請閱讀[conceptual overview](/docs/guides/multi-agent-systems).

:::

## 快速入門 {/* #quickstart */}

定義具有清晰描述的子Agent，然後將它們新增至父Agent：

```typescript title="src/mastra/agents/parent-agent.ts"
import { Agent } from '@mastra/core/agent'
import { Memory } from '@mastra/memory'
import { LibSQLStore } from '@mastra/libsql'

const researchAgent = new Agent({
  id: 'research-agent',
  // highlight-next-line
  description: 'Gathers factual information and returns bullet-point summaries.',
  model: '__GATEWAY_OPENAI_MODEL_LUNA__',
})

const writingAgent = new Agent({
  id: 'writing-agent',
  // highlight-next-line
  description: 'Transforms research into well-structured articles.',
  model: '__GATEWAY_OPENAI_MODEL_LUNA__',
})

// highlight-start
const parentAgent = new Agent({
  id: 'parent-agent',
  instructions: `You coordinate research and writing using specialized agents.
    Delegate to research-agent for facts, then writing-agent for content.`,
  model: '__GATEWAY_OPENAI_MODEL__',
  agents: { researchAgent, writingAgent },
  memory: new Memory({
    storage: new LibSQLStore({ id: 'storage', url: 'file:mastra.db' }),
  }),
})
// highlight-end

const stream = await parentAgent.stream('Research AI in education and write an article', {
  maxSteps: 10,
})

for await (const chunk of stream.textStream) {
  process.stdout.write(chunk)
}
```

## 委託掛鉤 {/* #delegation-hooks */}

委託掛鉤允許您在委託發生時攔截、修改或拒絕委託。在下面配置它們`delegation` option, either in the agent's `defaultOptions` or per-call.

### `onDelegationStart` {/* #ondelegationstart */}

在父Agent委託給子Agent之前呼叫。回傳一個物件來控制委託：

* `proceed: true`：允許委派（預設行為）
* `proceed: false`：拒絕委託`rejectionReason`
* `modifiedPrompt`：重寫發送給子Agent的提示
* `modifiedMaxSteps`：設定子Agent的迭代預算。這會覆蓋模型提供的上限`maxSteps`, so it can raise the budget as well as lower it
* `threadMetadata`：附加元資料（例如`tenantId`) to the subagent's thread when it's created, so you can filter threads with `memory.listThreads({ filter: { metadata } })`

:::注意
當主管模型通過時`maxSteps` to a delegation, Mastra caps it at the subagent's `defaultOptions.maxSteps`. The model can lower the subagent's budget that way, but not raise it. `modifiedMaxSteps` is applied after that cap and replaces the capped value, so it can raise the budget above the subagent's default. Use it to stop a supervisor model from cutting a subagent short.
:::

```typescript title="src/mastra/agents/parent-agent.ts"
const stream = await parentAgent.stream('Research AI trends', {
  maxSteps: 10,
  delegation: {
    onDelegationStart: async context => {
      console.log(`Delegating to: ${context.primitiveId}`)

      // Modify the prompt for a specific agent
      if (context.primitiveId === 'research-agent') {
        return {
          proceed: true,
          modifiedPrompt: `${context.prompt}\n\nFocus on 2024-2025 data.`,
          modifiedMaxSteps: 5,
        }
      }

      // Reject delegation after too many iterations
      if (context.iteration > 8) {
        return {
          proceed: false,
          rejectionReason: 'Max iterations reached. Synthesize current findings.',
        }
      }

      return { proceed: true }
    },
  },
})
```

這`context` object includes:

|物業 |描述 |
| - | - |
|`primitiveId` | The ID of the subagent being delegated to |
| `prompt` | The prompt the parent agent is sending |
| `iteration` | Current iteration number |
| `requestContext` | The request context the subagent run will receive |

### 委託邊界處的請求上下文 {/* #request-context-at-the-delegation-boundary */}

每個委託都會收到一個請求上下文，其條目是從父運行淺層複製的，不包括運行範圍的身份密鑰。在子Agent程式運行期間設定或刪除條目不會影響父Agent程式的上下文。將條目設定為`context.requestContext` in `onDelegationStart` to pass values to the delegated run:

```typescript title="src/mastra/agents/parent-agent.ts"
const stream = await parentAgent.stream('Research AI trends', {
  maxSteps: 10,
  delegation: {
    onDelegationStart: async context => {
      context.requestContext.set('audience', 'technical')
    },
  },
})
```

子Agent程式在其Tool和動態配置中讀取這些條目，例如`instructions: ({ requestContext }) => ...`. See [Request Context](/docs/server/request-context) for details. Values must be JSON-serializable to work with durable agents.

### `onDelegationComplete` {/* #ondelegationcomplete */}

代表團結束後調用。用它來檢查結果或提供回饋，或停止執行：

* `context.bail()`：立即停止父Agent的循環
* 返回`{ feedback: '...' }`: Add feedback that gets saved to the parent agent's memory and is available on the next turn
* 返回`{ resultText: '...' }`: Replace the tool result text the parent model sees for this delegation, within the current run

放`resultText` when the subagent's own result would give the parent a misleading signal. For example, empty text from a subagent stopped on a tool-calls step looks like a successful but empty delegation to the parent model. You can also replace the error text from a failed delegation with a more useful message. This doesn't recover the delegation. The parent still receives a failed tool result. Unlike `feedback` on the next turn, `resultText` affects the parent's reasoning immediately.

若要在失敗時停止父Agent並保存回饋以供稍後使用，請調用`bail()` and return `feedback`:

```typescript title="src/mastra/agents/parent-agent.ts"
const stream = await parentAgent.stream('Research AI trends', {
  maxSteps: 10,
  delegation: {
    onDelegationComplete: async context => {
      console.log(`Completed: ${context.primitiveId}`)

      // Bail on errors
      if (context.error) {
        context.bail()
        return {
          feedback: `Delegation to ${context.primitiveId} failed: ${context.error}. Try a different approach.`,
        }
      }
    },
  },
})
```

這`context` object includes:

|物業 |描述 |
| - | - |
|`primitiveId` | The ID of the subagent that ran |
| `result` | The subagent's response, including `text`, `usage`, `finishReason`, `subAgentToolResults`, `subAgentPendingToolCalls`, `subAgentThreadId`, and `subAgentResourceId` when available |
| `success` | Whether the delegation succeeded |
| `error` | The original error if the delegation failed |
| `messages` | The collected subagent transcript, including partial messages when available |
| `bail()` | Function to stop the parent agent's loop |

#### 失敗的代表團 {/* #failed-delegations */}

當子Agent程式運行失敗時，父模型會收到失敗的Tool結果以及一般錯誤訊息。這不會自動停止父Agent，這可以解釋失敗或選擇其他方法。稱呼`context.bail()` to stop its loop instead.

鉤子接收`success: false`, the original `error`, and any collected partial results and messages. Returning `resultText` replaces the error text the parent model sees without changing the delegation's failed status or discarding its original cause. An empty string is also a valid replacement.

要讓父級繼續顯示策劃的失敗訊息而不是停止其循環，請返回`resultText` without calling `bail()`:

```typescript title="src/mastra/agents/parent-agent.ts"
const stream = await parentAgent.stream('Research AI trends', {
  maxSteps: 10,
  delegation: {
    onDelegationComplete: ({ success }) => {
      if (!success) {
        return {
          resultText: 'The delegated task failed. Try another approach.',
        }
      }
    },
  },
})
```

喜歡精心策劃的消息，如本例所示。返回`{ resultText: error.message }` explicitly forwards the underlying message to the parent model's provider, and the model may repeat it to the end user. Provider errors can contain sensitive information. A generic `resultText` isn't a redaction policy for logs, traces, or streamed error payloads.

對於代表運行的[background tasks](/docs/harness/background-tasks), configured retries can invoke `onDelegationComplete` once per attempt. Account for repeated calls if your hook has side effects.

### 掛鉤錯誤 {/* #hook-errors */}

如果委託鉤子拋出，則預設委託將繼續：`onDelegationStart` proceeds with the original prompt, `messageFilter` falls back to the unfiltered context, and `onDelegationComplete` keeps the subagent's original result. Set `hookErrorStrategy: 'throw'` to fail the delegation instead.

```typescript title="src/mastra/agents/parent-agent.ts"
const stream = await parentAgent.stream('Research AI trends', {
  maxSteps: 10,
  delegation: {
    hookErrorStrategy: 'throw',
    onDelegationComplete: async ({ result }) => {
      // If this throws, the parent sees a failed delegation instead of a
      // successful one whose result was silently dropped.
      await reportToAnalytics(result)
    },
  },
})
```

無論哪種方式，每個鉤子失敗都會記錄在運行的請求上下文中`__mastra_delegationHookErrors` as a list of `{ hook, primitiveId, toolCallId, runId, name, message }` entries, so you can detect a hook failure programmatically:

```typescript title="src/mastra/agents/parent-agent.ts"
import { RequestContext } from '@mastra/core/request-context'

const requestContext = new RequestContext()

await parentAgent.generate('Research AI trends', { maxSteps: 10, requestContext })

const hookErrors = requestContext.get('__mastra_delegationHookErrors') ?? []
```

什麼時候`hookErrorStrategy` is `'throw'`, a throwing `onDelegationStart` blocks the subagent from running at all, and a throwing `messageFilter` or `onDelegationComplete` surfaces to the parent as a failed tool call. If `onDelegationComplete` throws while handling a failed delegation, the original delegation error remains the surfaced error. The hook isn't invoked again for its own failure.

## 訊息過濾 {/* #message-filtering */}

預設情況下，子Agent會從父Agent接收完整的對話上下文。使用`messageFilter` to control what messages are shared, for example, to remove sensitive data or limit context size.

```typescript title="src/mastra/agents/parent-agent.ts"
const stream = await parentAgent.stream('Research AI trends', {
  maxSteps: 10,
  delegation: {
    messageFilter: ({ messages, primitiveId, prompt }) => {
      // Remove messages containing sensitive data
      return messages
        .filter(msg => {
          const content =
            typeof msg.content === 'string' ? msg.content : JSON.stringify(msg.content)
          return !content.includes('confidential')
        })
        .slice(-10) // Only pass the last 10 messages
    },
  },
})
```

回呼收到`messages` (the full conversation history), `primitiveId` (the subagent ID), and `prompt` (the delegation prompt). Return the filtered array of messages.

## 子Agent結果上下文 {/* #subagent-result-context */}

當子Agent完成時，父Agent的模型會在以後的迭代中接收子Agent的文字回應。嵌套Tool呼叫和子Agent元資料（例如執行緒和資源 ID）不會加入到父Agent的模型上下文中。

應用程式程式碼和 UI 整合仍然可以檢查`subAgentToolResults` and the rest of the raw delegation result in the tool result payload.

這樣可以保持偵錯和顯示資料可用，而無需將巢狀Tool參數或輸出傳回父Agent的下一個模型呼叫。

子Agent無法運行客戶端Tool（沒有`execute` function). If a subagent calls one, its run stops at that step with `finishReason: 'tool-calls'`. The delegation result lists the unresolved calls in `subAgentPendingToolCalls`, the parent agent's model is told which tools were never run, and Mastra logs a warning. Give client tools to the parent agent, or use [`suspend()`](/docs/agents/human-in-the-loop#use-suspend-in-supervisor-agents) in the subagent's tool when it needs input from the user.

放`includeSubAgentToolResultsInModelContext` to include the full subagent result, including nested tool results and subagent metadata, in the parent agent's model context.

```typescript title="src/mastra/agents/parent-agent.ts"
await parentAgent.generate('Research AI trends', {
  delegation: {
    includeSubAgentToolResultsInModelContext: true,
  },
})
```

### 重用早期的子Agent結果 {/* #reusing-an-earlier-subagent-result */}

預設情況下，子Agent結果會作為Tool結果到達父Agent，這些結果從轉送到後續子Agent的上下文中刪除。父Agent必須在下一個委託提示中重申先前的結果，這會消耗令牌並丟失詳細資訊。

放`enableResultReferences` to let a later delegation reuse an earlier result verbatim:

```typescript title="src/mastra/agents/parent-agent.ts"
await parentAgent.generate('Find and fix the token refresh bug', {
  delegation: {
    enableResultReferences: true,
  },
})
```

啟用後：

* 每個成功的非空子Agent結果都會獲得一個參考 ID，例如`explorer-1`. The parent agent's model sees it as a `[ref: explorer-1]` line after the subagent's text.
* 委派Tool獲得了`contextFromRefs` input. The parent agent can pass earlier IDs, either as strings (`["explorer-1"]`) or as objects with an optional label and note (`[{ ref: "explorer-1", as: "investigation", note: "bug location" }]`).
* 引用的文字插入委託提示之前，每個結果都在自己的標記區塊中，與先前的子Agent程式產生的結果完全相同。`onDelegationStart` and `messageFilter` receive the expanded prompt.
* 如果`onDelegationComplete` returns `resultText`, the replaced text is what later delegations receive.

對於單一父Agent運行，引用保存在記憶體中，並且不會持久保存。被拒絕、失敗、空和後台任務委託不會收到參考 ID。未知 ID 將被跳過並出現警告，並且委派將繼續。

引用的文本是從另一個Agent輸出的。每個區塊都使用一個新的、不可預測的標籤，並告訴接收子Agent將內容視為數據，但如果子Agent處理不受信任的輸入，請添加您自己的檢查`onDelegationStart` or through processors.

## 迭代監控 {/* #iteration-monitoring */}

`onIterationComplete`在父Agent循環的每次迭代之後調用。用它來監視執行或指導下一個迭代。您也可以提前停止執行。

```typescript title="src/mastra/agents/parent-agent.ts"
const stream = await parentAgent.stream('Research AI trends', {
  maxSteps: 10,
  onIterationComplete: async context => {
    console.log(`Iteration ${context.iteration}/${context.maxIterations}`)
    console.log(`Finish reason: ${context.finishReason}`)

    // Inject feedback to guide the agent
    if (!context.text.includes('recommendations')) {
      return {
        continue: true,
        feedback: 'Please include specific recommendations in your analysis.',
      }
    }

    // Stop early when the response is sufficient
    if (context.text.length > 1000 && context.finishReason === 'stop') {
      return { continue: false }
    }

    return { continue: true }
  },
})
```

返回`{ continue: true }` to keep iterating, or `{ continue: false }` to stop. Include optional `feedback` to inject guidance into the conversation. When `feedback` is combined with `continue: false`, the model may get one final turn for a text response that incorporates the feedback. The extra turn is granted only while the current iteration is active (e.g., after tool calls).

## 記憶體隔離 {/* #memory-isolation */}

Mastra 在委派期間隔離子Agent記憶體。子Agent程式會收到完整的對話上下文，以便做出更好的決策，但只有其特定的授權提示和回應才會儲存到記憶體中。

工作原理：

1. **完整上下文轉發**：當父Agent委託時，子Agent接收父Agent對話中的所有訊息
2. **作用域記憶體保存**：僅將委託提示和子Agent程式的回應儲存到子Agent程式的記憶體中
3. **每次呼叫都有新線程**：每個委託使用唯一的執行緒ID，確保乾淨分離

因此，子Agent可以獲得所需的上下文，而不會因父Agent的整個對話而使自己的記憶混亂。訪問[memory in multi-agent systems](/docs/memory/overview#memory-in-multi-agent-systems) for more details.

## Tool批准傳播 {/* #tool-approval-propagation */}

Tool批准透過授權鏈傳播。當子Agent程式使用Tool時`requireApproval: true` or calls `suspend()`, the approval request surfaces in the parent agent's stream.

```typescript
const sensitiveDataTool = createTool({
  id: 'get-user-data',
  requireApproval: true,
  execute: async input => {
    return await database.getUserData(input.userId)
  },
})

const dataAgent = new Agent({
  id: 'data-agent',
  tools: { sensitiveDataTool },
})

const parentAgent = new Agent({
  id: 'parent-agent',
  agents: { dataAgent },
  memory: new Memory(),
})

const stream = await parentAgent.stream('Get data for user 123')

for await (const chunk of stream.fullStream) {
  if (chunk.type === 'tool-call-approval') {
    console.log('Tool requires approval:', chunk.payload.toolName)
  }
}
```

## 消除 {/* #cancellation */}

當你通過一個`abortSignal` to the parent agent's [`stream()`](/reference/streaming/agents/stream) or [`generate()`](/reference/agents/generate) call, Mastra forwards that same signal to delegated subagents. Calling `AbortController.abort()` cancels in-flight subagent runs at their next step instead of letting them run to completion.

```typescript
const controller = new AbortController()

const stream = await parentAgent.stream('Research AI trends', {
  abortSignal: controller.signal,
})

// Cancel the parent agent and any in-flight subagents
controller.abort()
```

## 任務完成評分 {/* #task-completion-scoring */}

Agent並不總是在第一次嘗試時產生完整、正確的輸出。任務完成評分器可以透過在每次迭代後驗證任務是否完成來提供協助。如果驗證失敗，父Agent將繼續迭代。失敗的記分員的回饋包含在對話上下文中，以便子Agent可以看到缺少的內容。

```typescript
import { createScorer } from '@mastra/core/evals'

const taskCompleteScorer = createScorer({
  id: 'task-complete',
  name: 'Task Completeness',
}).generateScore(async context => {
  const text = (context.run.output || '').toString()
  const hasAnalysis = text.includes('analysis')
  const hasRecommendations = text.includes('recommendation')
  return hasAnalysis && hasRecommendations ? 1 : 0
})

const stream = await parentAgent.stream('Research AI in education', {
  maxSteps: 10,
  isTaskComplete: {
    scorers: [taskCompleteScorer],
    strategy: 'all',
    onComplete: async result => {
      console.log('Task complete:', result.complete)
    },
  },
})
```

### 評分錶 {/* #rubric-scorer */}

內建的評分錶可讓您將「正確」定義為清單，並讓Agent進行自我評估和迭代，直到滿足每個標準或`maxSteps` is reached.

它的工作原理是**LLM-as-judge** scorer. After each iteration, a separate grader model reviews the agent's output against the rubric. The loop ends when every required criterion passes. A failed criterion adds its feedback to the conversation so the agent can try again.

這對於具有明確、可驗證的成功標準的任務最有效。你可以像這樣使用它：

```typescript title="src/mastra/agents/rubric-scorer.ts"
import { Agent } from '@mastra/core/agent'
import { createRubricScorer } from '@mastra/evals/scorers/prebuilt'

const parentAgent = new Agent({
  id: 'parent-agent',
  instructions: 'You coordinate research and writing using specialized agents.',
  model: '__GATEWAY_OPENAI_MODEL__',
  agents: { researchAgent, writingAgent },
})

const rubricScorer = createRubricScorer({
  model: '__GATEWAY_OPENAI_MODEL_LUNA__',
  criteria: [
    { description: 'The response includes an analysis section' },
    { description: 'The response includes concrete recommendations' },
  ],
})

const stream = await parentAgent.stream('Research AI in education', {
  maxSteps: 10,
  isTaskComplete: {
    scorers: [rubricScorer],
    strategy: 'all',
  },
})
```

有關完整 API 詳細信息，請參閱[rubric scorer reference](/reference/evals/rubric).

## 編寫有效的指令 {/* #writing-effective-instructions */}

明確的指示對於有效授權至關重要。

父Agent的`instructions` should specify the available resources and when to use each one. They should also define coordination behavior and success criteria.

每個子Agent都應該有一個明確的`description` that explains its purpose and return format, including when the parent agent should use it.

父Agent使用這些描述來做出委託決策。

```typescript
const parentAgent = new Agent({
  id: 'parent-agent',
  instructions: `You coordinate research and writing tasks.

Available resources:
- researchAgent: Gathers factual data and sources (returns bullet points)
- writingAgent: Transforms research into narrative content (returns full paragraphs)

Delegation strategy:
1. For research requests: Delegate to researchAgent first
2. For writing requests: Delegate to writingAgent
3. For complex requests: Delegate to researchAgent first, then writingAgent

Success criteria:
- All user questions are fully answered
- Response is well-formatted and complete`,
  agents: { researchAgent, writingAgent },
})
```

## 在背景運行子Agent {/* #running-subagents-in-the-background */}

子Agent呼叫作為Tool呼叫進行分派，因此它們可以作為[background tasks](/docs/harness/background-tasks). This is useful when one or more delegations are long-running and you don't want them to block the parent agent's response.

啟用[backgroundTasks manager](/reference/configuration#backgroundtasks) on the Mastra instance, then opt subagents in on the parent agent:

```typescript title="src/mastra/agents/parent-agent.ts"
import { Agent } from '@mastra/core/agent'

const parentAgent = new Agent({
  id: 'parent-agent',
  instructions: 'Coordinate research and writing using the available agents.',
  model: '__GATEWAY_OPENAI_MODEL__',
  agents: { researchAgent, writingAgent },
  // highlight-start
  backgroundTasks: {
    tools: {
      researchAgent: { enabled: true, timeoutMs: 900_000 },
      writingAgent: { enabled: true, timeoutMs: 900_000 },
    },
  },
  // highlight-end
})

const stream = await parentAgent.streamUntilIdle('Research AI in education and write an article', {
  memory: { thread: 't1', resource: 'u1' },
})
```

使用[`streamUntilIdle()`](/reference/streaming/agents/streamUntilIdle) instead of `stream()` so the stream stays open until the subagents complete and the parent agent has had a chance to respond to their results.

如果子Agent未在父Agent下列出`backgroundTasks.tools` but has its own background-eligible tools, the parent agent still dispatches the subagent as a background task and inherits its config. See [Inheriting from the subagent](/docs/harness/background-tasks#inheriting-from-the-subagent) for details.

## 子Agent程式版本控制 {/* #subagent-versioning */}

當使用[editor](/docs/studio/editor), you can control which stored version of each subagent the parent agent uses at runtime. Set version overrides on the Mastra instance or per invocation:

```typescript
const result = await parentAgent.generate('Research and write about AI safety', {
  versions: {
    agents: {
      'research-agent': { status: 'published' },
      'writing-agent': { versionId: 'draft-456' },
    },
  },
})
```

版本覆蓋透過委託自動傳播。看[Subagent versioning](/reference/editor/versioning#sub-agent-versioning) for details on resolution order and server API usage.
