# 子 Agent

**加入版本：** `@mastra/core@1.8.0`

子 Agent 是專門處理某類工作的 Agent，其他 Agent 可以把任務委派給它們。先將子 Agent 加入父 Agent 的 `agents` 屬性，再呼叫 [`Agent.stream()`](/reference/streaming/agents/stream) 或 [`Agent.generate()`](/reference/agents/generate)。父 Agent 會根據自己的指示及各子 Agent 的 `description`，決定何時及如何委派任務。

## 何時使用子 Agent {/* #when-to-use-subagents */}

當一項任務需要不同專長的 Agent 合作，就可以使用子 Agent。父 Agent 會決定何時委派、將相關內容傳給每個子 Agent，然後整合結果。

常見情況：

- 研究與寫作流程中，由一個 Agent 搜集資料，另一個 Agent 撰寫內容
- 每個階段需要不同專長的多步驟任務
- 需要仔細控制委派行為的任務

:::note

負責協調子 Agent 的父 Agent 一般稱為監督 Agent。在 Mastra 中，監督模式是建立多 Agent 系統的其中一種方法。其他方法可參閱[概念概覽](/docs/guides/multi-agent-systems)。

:::

## 快速開始 {/* #quickstart */}

先為子 Agent 寫出清晰的描述，再把它們加入父 Agent：

```typescript title="src/mastra/agents/parent-agent.ts"
import { Agent } from '@mastra/core/agent'
import { Memory } from '@mastra/memory'
import { LibSQLStore } from '@mastra/libsql'

const researchAgent = new Agent({
  id: 'research-agent',
  // highlight-next-line
  description: 'Gathers factual information and returns bullet-point summaries.',
  model: '__GATEWAY_OPENAI_MODEL_LUNA__',
})

const writingAgent = new Agent({
  id: 'writing-agent',
  // highlight-next-line
  description: 'Transforms research into well-structured articles.',
  model: '__GATEWAY_OPENAI_MODEL_LUNA__',
})

// highlight-start
const parentAgent = new Agent({
  id: 'parent-agent',
  instructions: `You coordinate research and writing using specialized agents.
    Delegate to research-agent for facts, then writing-agent for content.`,
  model: '__GATEWAY_OPENAI_MODEL__',
  agents: { researchAgent, writingAgent },
  memory: new Memory({
    storage: new LibSQLStore({ id: 'storage', url: 'file:mastra.db' }),
  }),
})
// highlight-end

const stream = await parentAgent.stream('Research AI in education and write an article', {
  maxSteps: 10,
})

for await (const chunk of stream.textStream) {
  process.stdout.write(chunk)
}
```

## 委派掛鈎 {/* #delegation-hooks */}

委派掛鈎讓你在委派發生時攔截、修改或拒絕委派。可以在 Agent 的 `delegation` 設定在 `defaultOptions`，亦可以在每次呼叫時個別設定。

### `onDelegationStart` {/* #ondelegationstart */}

父 Agent 向子 Agent 委派任務前，系統會呼叫此掛鈎。傳回物件即可控制該次委派：

- `proceed: true`：允許委派（預設行為）
- `proceed: false`：拒絕委派，並提供 `rejectionReason`
- `modifiedPrompt`：改寫傳給子 Agent 的提示
- `modifiedMaxSteps`：設定子 Agent 的迭代額度。此值會覆蓋模型提供的 `maxSteps` 上限，所以可以增加或減少額度
- `threadMetadata`：建立子 Agent 的執行緒時加入中繼資料（例如 `tenantId`），方便用 `memory.listThreads({ filter: { metadata } })` 篩選執行緒

:::note
監督模型委派任務時若傳入 `maxSteps`，Mastra 會將此值限制在子 Agent 的 `defaultOptions.maxSteps` 之內。模型可以藉此降低子 Agent 的額度，卻不能提高。`modifiedMaxSteps` 會在套用上限後取代受限的值，因此可以將額度提高至子 Agent 的預設值以上。這有助避免監督模型令子 Agent 過早停止。
:::

```typescript title="src/mastra/agents/parent-agent.ts"
const stream = await parentAgent.stream('Research AI trends', {
  maxSteps: 10,
  delegation: {
    onDelegationStart: async context => {
      console.log(`Delegating to: ${context.primitiveId}`)

      // Modify the prompt for a specific agent
      if (context.primitiveId === 'research-agent') {
        return {
          proceed: true,
          modifiedPrompt: `${context.prompt}\n\nFocus on 2024-2025 data.`,
          modifiedMaxSteps: 5,
        }
      }

      // Reject delegation after too many iterations
      if (context.iteration > 8) {
        return {
          proceed: false,
          rejectionReason: 'Max iterations reached. Synthesize current findings.',
        }
      }

      return { proceed: true }
    },
  },
})
```

`context` 物件包括：

| 屬性 | 說明 |
| - | - |
| `primitiveId` | 接受委派的子 Agent ID |
| `prompt` | 父 Agent 傳送的提示 |
| `iteration` | 目前迭代次數 |
| `requestContext` | 子 Agent 執行時會收到的請求上下文 |

### 委派邊界的請求上下文 {/* #request-context-at-the-delegation-boundary */}

每次委派都會收到一份請求上下文，其中的項目從父 Agent 執行時的內容淺層複製，但不包括只屬於該次執行的身份識別鍵。子 Agent 執行期間新增或刪除項目，不會影響父 Agent 的內容。在 `context.requestContext` 設定項目（透過 `onDelegationStart` 掛鈎），就可以將值傳給接受委派的執行：

```typescript title="src/mastra/agents/parent-agent.ts"
const stream = await parentAgent.stream('Research AI trends', {
  maxSteps: 10,
  delegation: {
    onDelegationStart: async context => {
      context.requestContext.set('audience', 'technical')
    },
  },
})
```

子 Agent 可在 Tool 和動態設定中讀取這些項目，例如 `instructions: ({ requestContext }) => ...`。詳情請參閱[請求上下文](/docs/server/request-context)。如要配合可持久化的 Agent 使用，值必須能夠序列化為 JSON。

### `onDelegationComplete` {/* #ondelegationcomplete */}

委派完成後會呼叫此掛鈎。可用它檢查結果、提供回饋，或停止執行：

- `context.bail()`：立即停止父 Agent 的循環
- 傳回 `{ feedback: '...' }`：將回饋存入父 Agent 的記憶，供下一輪使用
- 傳回 `{ resultText: '...' }`：在目前執行中，取代父模型看到的該次委派 Tool 結果文字

當子 Agent 的原始結果可能誤導父 Agent，就應設定 `resultText`。例如，子 Agent 在 Tool 呼叫步驟停止並傳回空白文字時，父模型可能以為委派成功，只是沒有內容。你亦可以將失敗委派的錯誤文字改為更有用的訊息，但這不會令委派恢復；父 Agent 仍會收到失敗的 Tool 結果。`feedback` 在下一輪才生效，而 `resultText` 會即時影響父 Agent 的推理。

如要在失敗時停止父 Agent，並保留回饋供日後使用，請呼叫 `bail()` 並傳回 `feedback`：

```typescript title="src/mastra/agents/parent-agent.ts"
const stream = await parentAgent.stream('Research AI trends', {
  maxSteps: 10,
  delegation: {
    onDelegationComplete: async context => {
      console.log(`Completed: ${context.primitiveId}`)

      // Bail on errors
      if (context.error) {
        context.bail()
        return {
          feedback: `Delegation to ${context.primitiveId} failed: ${context.error}. Try a different approach.`,
        }
      }
    },
  },
})
```

`context` 物件包括：

| 屬性 | 說明 |
| - | - |
| `primitiveId` | 已執行的子 Agent ID |
| `result` | 子 Agent 的回應；如有提供，會包括 `text`、`usage`、`finishReason`、`subAgentToolResults`、`subAgentPendingToolCalls`、`subAgentThreadId` 和 `subAgentResourceId` |
| `success` | 委派是否成功 |
| `error` | 委派失敗時的原始錯誤 |
| `messages` | 收集到的子 Agent 對話紀錄，包括可用的部分訊息 |
| `bail()` | 停止父 Agent 循環的函式 |

#### 委派失敗 {/* #failed-delegations */}

子 Agent 執行失敗時，父模型會收到附有一般錯誤訊息的失敗 Tool 結果。這不會自動停止父 Agent；它可以解釋失敗原因，或改用其他方法。如要停止循環，請呼叫 `context.bail()`。

掛鈎會收到 `success: false`、原始 `error`，以及收集到的部分結果和訊息。傳回 `resultText` 可取代父模型看到的錯誤文字，但不會改變委派失敗的狀態，亦不會捨棄原始原因。空字串同樣是有效的替代值。

如要父 Agent 根據整理過的失敗訊息繼續執行，而不停止循環，請傳回 `resultText`，不要呼叫 `bail()`：

```typescript title="src/mastra/agents/parent-agent.ts"
const stream = await parentAgent.stream('Research AI trends', {
  maxSteps: 10,
  delegation: {
    onDelegationComplete: ({ success }) => {
      if (!success) {
        return {
          resultText: 'The delegated task failed. Try another approach.',
        }
      }
    },
  },
})
```

建議如範例般提供整理過的訊息。傳回 `{ resultText: error.message }` 會把底層錯誤直接傳給父模型的 Provider，而模型可能再轉述給終端用戶。Provider 錯誤可能包含敏感資料。一般性的 `resultText` 亦不能取代日誌、Trace 或串流錯誤資料的遮蓋政策。

如果委派以[背景任務](/docs/harness/background-tasks)執行，已設定的重試可能令每次嘗試都觸發一次 `onDelegationComplete`。掛鈎如有副作用，請留意重複呼叫。

### 掛鈎錯誤 {/* #hook-errors */}

委派掛鈎拋出錯誤時，預設仍會繼續委派：`onDelegationStart` 沿用原始提示，`messageFilter` 改用未篩選的內容，`onDelegationComplete` 保留子 Agent 的原始結果。如要委派因此失敗，請設定 `hookErrorStrategy: 'throw'`。

```typescript title="src/mastra/agents/parent-agent.ts"
const stream = await parentAgent.stream('Research AI trends', {
  maxSteps: 10,
  delegation: {
    hookErrorStrategy: 'throw',
    onDelegationComplete: async ({ result }) => {
      // If this throws, the parent sees a failed delegation instead of a
      // successful one whose result was silently dropped.
      await reportToAnalytics(result)
    },
  },
})
```

不論採用哪種方式，每次掛鈎失敗都會記錄在該次執行的請求上下文中，鍵為 `__mastra_delegationHookErrors`，值是由 `{ hook, primitiveId, toolCallId, runId, name, message }` 項目組成的清單，方便程式偵測：

```typescript title="src/mastra/agents/parent-agent.ts"
import { RequestContext } from '@mastra/core/request-context'

const requestContext = new RequestContext()

await parentAgent.generate('Research AI trends', { maxSteps: 10, requestContext })

const hookErrors = requestContext.get('__mastra_delegationHookErrors') ?? []
```

當 `hookErrorStrategy` 為 `'throw'`，`onDelegationStart` 拋出錯誤會完全阻止子 Agent 執行；`messageFilter` 或 `onDelegationComplete` 拋出錯誤，則會以失敗的 Tool 呼叫呈現給父 Agent。若 `onDelegationComplete` 處理失敗委派時拋出錯誤，對外呈現的仍是原本的委派錯誤。掛鈎不會因自身失敗再次被呼叫。

## 訊息篩選 {/* #message-filtering */}

子 Agent 預設會收到父 Agent 的完整對話內容。使用 `messageFilter` 控制共享哪些訊息，例如移除敏感資料或限制內容長度。

```typescript title="src/mastra/agents/parent-agent.ts"
const stream = await parentAgent.stream('Research AI trends', {
  maxSteps: 10,
  delegation: {
    messageFilter: ({ messages, primitiveId, prompt }) => {
      // Remove messages containing sensitive data
      return messages
        .filter(msg => {
          const content =
            typeof msg.content === 'string' ? msg.content : JSON.stringify(msg.content)
          return !content.includes('confidential')
        })
        .slice(-10) // Only pass the last 10 messages
    },
  },
})
```

回呼函式會收到 `messages`（完整對話紀錄）、`primitiveId`（子 Agent ID）和 `prompt`（委派提示）。請傳回篩選後的訊息陣列。

## 子 Agent 的結果內容 {/* #subagent-result-context */}

子 Agent 完成後，父 Agent 的模型會在往後的迭代收到子 Agent 的文字回應。巢狀 Tool 呼叫和子 Agent 中繼資料（例如執行緒 ID、資源 ID）不會加入父 Agent 的模型內容。

應用程式程式碼和 UI 整合仍可從 Tool 結果的資料中檢視 `subAgentToolResults` 及其他原始委派結果。

這樣既保留除錯和顯示所需的資料，亦毋須在父 Agent 下一次模型呼叫時傳入巢狀 Tool 的參數或輸出。

子 Agent 不能執行客戶端 Tool（即沒有 `execute` 函式的 Tool）。如果子 Agent 呼叫了這類 Tool，該次執行會停在這個步驟，`finishReason: 'tool-calls'`。委派結果會在 `subAgentPendingToolCalls` 列出未執行的呼叫，父 Agent 的模型會得知哪些 Tool 從未執行，Mastra 亦會記錄警告。請將客戶端 Tool 交給父 Agent；如果子 Agent 需要用戶輸入，可在其 Tool 中使用 [`suspend()`](/docs/agents/human-in-the-loop#use-suspend-in-supervisor-agents)。

設定 `includeSubAgentToolResultsInModelContext`，即可將完整子 Agent 結果（包括巢狀 Tool 結果和子 Agent 中繼資料）加入父 Agent 的模型內容。

```typescript title="src/mastra/agents/parent-agent.ts"
await parentAgent.generate('Research AI trends', {
  delegation: {
    includeSubAgentToolResultsInModelContext: true,
  },
})
```

### 重用較早前的子 Agent 結果 {/* #reusing-an-earlier-subagent-result */}

子 Agent 的結果預設以 Tool 結果形式傳給父 Agent，但這些結果會從轉交給後續子 Agent 的內容中移除。父 Agent 需要在下一次委派提示中重述較早前的結果，既消耗 token，亦可能遺漏細節。

設定 `enableResultReferences`，後續委派便可原文重用較早前的結果：

```typescript title="src/mastra/agents/parent-agent.ts"
await parentAgent.generate('Find and fix the token refresh bug', {
  delegation: {
    enableResultReferences: true,
  },
})
```

啟用後：

- 每個成功且非空的子 Agent 結果都會得到引用 ID，例如 `explorer-1`。父 Agent 的模型會在子 Agent 文字之後看到 `[ref: explorer-1]` 這一行。
- 委派 Tool 會增加 `contextFromRefs` 輸入。父 Agent 可以傳入較早前的 ID，既可以用字串（`["explorer-1"]`），亦可以用附有可選標籤及備註的物件（`[{ ref: "explorer-1", as: "investigation", note: "bug location" }]`）。
- 引用文字會放在委派提示之前，每個結果各佔一個附標籤的區塊，內容與先前子 Agent 產生的文字完全一致。`onDelegationStart` 和 `messageFilter` 會收到展開後的提示。
- 如果 `onDelegationComplete` 傳回 `resultText`，後續委派收到的就是替換後的文字。

引用只保留在單次父 Agent 執行的記憶體中，不會長期儲存。被拒絕、失敗、結果為空和背景任務形式的委派，都不會取得引用 ID。未知 ID 會被略過並記錄警告，委派則繼續。

引用文字是另一個 Agent 的輸出。每個區塊都會使用新產生、難以預測的標籤，並提醒接收的子 Agent 將內容當成資料。若子 Agent 會處理不可信的輸入，仍需在 `onDelegationStart` 或透過 Processor 自行檢查。

## 迭代監控 {/* #iteration-monitoring */}

父 Agent 的循環每完成一次迭代，就會呼叫 `onIterationComplete`。你可以用它監察執行情況、指引下一次迭代，或提早停止。

```typescript title="src/mastra/agents/parent-agent.ts"
const stream = await parentAgent.stream('Research AI trends', {
  maxSteps: 10,
  onIterationComplete: async context => {
    console.log(`Iteration ${context.iteration}/${context.maxIterations}`)
    console.log(`Finish reason: ${context.finishReason}`)

    // Inject feedback to guide the agent
    if (!context.text.includes('recommendations')) {
      return {
        continue: true,
        feedback: 'Please include specific recommendations in your analysis.',
      }
    }

    // Stop early when the response is sufficient
    if (context.text.length > 1000 && context.finishReason === 'stop') {
      return { continue: false }
    }

    return { continue: true }
  },
})
```

傳回 `{ continue: true }` 會繼續迭代，傳回 `{ continue: false }` 則會停止。亦可加入可選的 `feedback`，在對話中提供指引。如果同時設定 `feedback` 和 `continue: false`，模型可能再得到最後一輪機會，產生包含回饋的文字回應。只有目前迭代仍在進行中（例如 Tool 呼叫後），才會額外提供這一輪。

## 記憶隔離 {/* #memory-isolation */}

Mastra 在委派期間隔離子 Agent 的記憶。子 Agent 會收到完整對話內容，方便作出判斷，但只有該次委派的提示和回應會存入自己的記憶。

運作方式：

1. **轉交完整內容**：父 Agent 委派任務時，子 Agent 會收到父 Agent 對話中的所有訊息
1. **限定記憶寫入範圍**：只有委派提示和子 Agent 的回應會存入子 Agent 的記憶
1. **每次呼叫都使用新執行緒**：每次委派都有獨立的執行緒 ID，確保互不混雜

因此，子 Agent 能取得所需的內容，同時不會將父 Agent 的整段對話存進自己的記憶。詳情請參閱[多 Agent 系統中的記憶](/docs/memory/overview#memory-in-multi-agent-systems)。

## Tool 審批請求的傳遞 {/* #tool-approval-propagation */}

Tool 的審批請求會沿委派鏈傳遞。子 Agent 使用設有 `requireApproval: true` 的 Tool 或呼叫 `suspend()` 時，審批請求會出現在父 Agent 的串流中。

```typescript
const sensitiveDataTool = createTool({
  id: 'get-user-data',
  requireApproval: true,
  execute: async input => {
    return await database.getUserData(input.userId)
  },
})

const dataAgent = new Agent({
  id: 'data-agent',
  tools: { sensitiveDataTool },
})

const parentAgent = new Agent({
  id: 'parent-agent',
  agents: { dataAgent },
  memory: new Memory(),
})

const stream = await parentAgent.stream('Get data for user 123')

for await (const chunk of stream.fullStream) {
  if (chunk.type === 'tool-call-approval') {
    console.log('Tool requires approval:', chunk.payload.toolName)
  }
}
```

## 取消執行 {/* #cancellation */}

將 `abortSignal` 傳給父 Agent 的 [`stream()`](/reference/streaming/agents/stream) 或 [`generate()`](/reference/agents/generate) 呼叫時，Mastra 會把同一訊號傳給接受委派的子 Agent。呼叫 `AbortController.abort()` 後，執行中的子 Agent 會在下一個步驟取消，不會一直運行至完成。

```typescript
const controller = new AbortController()

const stream = await parentAgent.stream('Research AI trends', {
  abortSignal: controller.signal,
})

// Cancel the parent agent and any in-flight subagents
controller.abort()
```

## 任務完成評分 {/* #task-completion-scoring */}

Agent 未必第一次就能產生完整而正確的結果。任務完成評分器會在每次迭代後核實任務是否完成；若未通過，父 Agent 便會繼續迭代。未通過的評分回饋會加入對話內容，讓子 Agent 看見仍欠缺甚麼。

```typescript
import { createScorer } from '@mastra/core/evals'

const taskCompleteScorer = createScorer({
  id: 'task-complete',
  name: 'Task Completeness',
}).generateScore(async context => {
  const text = (context.run.output || '').toString()
  const hasAnalysis = text.includes('analysis')
  const hasRecommendations = text.includes('recommendation')
  return hasAnalysis && hasRecommendations ? 1 : 0
})

const stream = await parentAgent.stream('Research AI in education', {
  maxSteps: 10,
  isTaskComplete: {
    scorers: [taskCompleteScorer],
    strategy: 'all',
    onComplete: async result => {
      console.log('Task complete:', result.complete)
    },
  },
})
```

### 評分準則評分器 {/* #rubric-scorer */}

內置的評分準則評分器讓你以檢查清單定義「正確」，再讓 Agent 自行評估並反覆嘗試，直到符合所有準則或達到 `maxSteps`。

它採用 **LLM-as-judge** 方式評分。每次迭代後，另一個評分模型會根據準則審視 Agent 的輸出。所有必要準則均通過時，循環便會結束；未通過的準則會把回饋加入對話，讓 Agent 再試。

這種方式最適合成功條件清晰、可以驗證的任務。用法如下：

```typescript title="src/mastra/agents/rubric-scorer.ts"
import { Agent } from '@mastra/core/agent'
import { createRubricScorer } from '@mastra/evals/scorers/prebuilt'

const parentAgent = new Agent({
  id: 'parent-agent',
  instructions: 'You coordinate research and writing using specialized agents.',
  model: '__GATEWAY_OPENAI_MODEL__',
  agents: { researchAgent, writingAgent },
})

const rubricScorer = createRubricScorer({
  model: '__GATEWAY_OPENAI_MODEL_LUNA__',
  criteria: [
    { description: 'The response includes an analysis section' },
    { description: 'The response includes concrete recommendations' },
  ],
})

const stream = await parentAgent.stream('Research AI in education', {
  maxSteps: 10,
  isTaskComplete: {
    scorers: [rubricScorer],
    strategy: 'all',
  },
})
```

完整 API 資料請參閱[評分準則評分器參考文件](/reference/evals/rubric)。

## 撰寫有效指示 {/* #writing-effective-instructions */}

清晰的指示是有效委派的關鍵。

父 Agent 的 `instructions` 應列明可用資源及使用時機，並定義協作方式和成功條件。

每個子 Agent 都應有清晰的 `description`，交代用途、傳回格式，以及父 Agent 何時應使用它。

父 Agent 會根據這些描述決定如何委派。

```typescript
const parentAgent = new Agent({
  id: 'parent-agent',
  instructions: `You coordinate research and writing tasks.

Available resources:
- researchAgent: Gathers factual data and sources (returns bullet points)
- writingAgent: Transforms research into narrative content (returns full paragraphs)

Delegation strategy:
1. For research requests: Delegate to researchAgent first
2. For writing requests: Delegate to writingAgent
3. For complex requests: Delegate to researchAgent first, then writingAgent

Success criteria:
- All user questions are fully answered
- Response is well-formatted and complete`,
  agents: { researchAgent, writingAgent },
})
```

## 在背景執行子 Agent {/* #running-subagents-in-the-background */}

子 Agent 的呼叫以 Tool 呼叫形式派送，因此可以作為[背景任務](/docs/harness/background-tasks)執行。如果一個或多個委派需時較長，而你不想阻塞父 Agent 的回應，就適合這樣做。

在 Mastra 實例啟用 [backgroundTasks 管理器](/reference/configuration#backgroundtasks)，然後為父 Agent 的子 Agent 開啟背景執行：

```typescript title="src/mastra/agents/parent-agent.ts"
import { Agent } from '@mastra/core/agent'

const parentAgent = new Agent({
  id: 'parent-agent',
  instructions: 'Coordinate research and writing using the available agents.',
  model: '__GATEWAY_OPENAI_MODEL__',
  agents: { researchAgent, writingAgent },
  // highlight-start
  backgroundTasks: {
    tools: {
      researchAgent: { enabled: true, timeoutMs: 900_000 },
      writingAgent: { enabled: true, timeoutMs: 900_000 },
    },
  },
  // highlight-end
})

const stream = await parentAgent.streamUntilIdle('Research AI in education and write an article', {
  memory: { thread: 't1', resource: 'u1' },
})
```

請使用 [`streamUntilIdle()`](/reference/streaming/agents/streamUntilIdle)，而非 `stream()`，讓串流維持開啟，直至子 Agent 完成，且父 Agent 有機會回應結果。

即使子 Agent 沒有列在父 Agent 的 `backgroundTasks.tools` 下，只要它本身有合資格在背景執行的 Tool，父 Agent 仍會將它派送為背景任務，並沿用其設定。詳情請參閱[繼承子 Agent 的設定](/docs/harness/background-tasks#inheriting-from-the-subagent)。

## 子 Agent 版本管理 {/* #subagent-versioning */}

使用 [Editor](/docs/studio/editor) 時，你可以控制父 Agent 執行期間採用各子 Agent 的哪個已儲存版本。版本覆寫可設於 Mastra 實例，亦可針對個別呼叫設定：

```typescript
const result = await parentAgent.generate('Research and write about AI safety', {
  versions: {
    agents: {
      'research-agent': { status: 'published' },
      'writing-agent': { versionId: 'draft-456' },
    },
  },
})
```

版本覆寫會沿委派鏈自動傳遞。解析順序及伺服器 API 的詳情請參閱[子 Agent 版本管理](/reference/editor/versioning#sub-agent-versioning)。
