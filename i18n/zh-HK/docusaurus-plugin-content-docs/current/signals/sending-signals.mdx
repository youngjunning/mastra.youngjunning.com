# 發送訊號

當用戶有話要說時發送訊息，噹噹前答案應該首先完成時排隊跟進，或者當應用程式需要添加上下文時發送鍵入的信號。這三個目標都針對一個線程。您透過其接收Agent的輸出[thread stream](/docs/signals/thread-streams).

這些範例使用`Agent` and thread from the [overview quickstart](/docs/signals/overview#quickstart)。若要呼叫正在運行的伺服器上的Agent，請使用[客戶端SDK](/reference/client-js/agents)或者[伺服器路由](/reference/server/routes#agent-message-routes)。這[Agent參考](/reference/agents/agent#thread-signals)列出方法參數和傳回值。

## 發送訊息 {/* #send-a-message */}

將執行緒標識符傳遞給[`sendMessage()`](/reference/agents/agent#sendmessagemessage-options) for user input:

```typescript title="src/mastra/signals.ts"
const result = agent.sendMessage('Compare that with the previous option.', {
  resourceId: 'user_123',
  threadId: 'thread_456',
})

await result.accepted
```

`sendMessage()`立即返回。等待`result.accepted` to wait for Mastra's routing decision and catch routing failures. [Control when input arrives](#control-when-input-arrives) lists the possible actions.

Mastra 先檢查線程。空閒線程開始運行。活動運行會取得該訊息，並且模型會在下一個請求時看到該訊息。透過內存，可以儲存它以供以後運行和用戶界面使用。[When the agent sees your input](#when-the-agent-sees-your-input) covers interruption.

添加`attributes` when several people share a thread:

```typescript
const result = agent.sendMessage(
  {
    contents: 'Use the latest customer note too.',
    attributes: { name: 'Jane', sentFrom: 'slack' },
  },
  { resourceId: 'user_123', threadId: 'thread_456' },
)

await result.accepted
```

此模型接收`<user name="Jane" sentFrom="slack">Use the latest customer note too.</user>`.

## 排隊跟進 {/* #queue-a-follow-up */}

使用[`queueMessage()`](/reference/agents/agent#queuemessagemessage-options) when the current answer should finish before the agent sees the next message:

```typescript title="src/mastra/signals.ts"
const result = agent.queueMessage('Also check whether the tests need updates.', {
  resourceId: 'user_123',
  threadId: 'thread_456',
})

await result.accepted
```

排隊輸入等待活動運行完成，然後開始新的運行。在空閒線程上，它立即啟動。[`cancelQueuedMessages()`](/reference/agents/agent#cancelqueuedmessagesoptions) removes queued input without stopping the active run. Cancellation is best-effort across processes and doesn't revoke accepted input.

[`queueSignal()`](/reference/agents/agent#queuesignalsignal-options)具有相同行為的佇列類型上下文，但保留訊號的`type`, `tagName`, and attributes.

## 從系統發送上下文 {/* #send-context-from-a-system */}

使用[`sendSignal()`](/reference/agents/agent#sendsignalsignal-options) to add context from your application, such as a background job result. The signal's type and XML tag identify the context:

```typescript title="src/mastra/signals.ts"
const result = agent.sendSignal(
  {
    type: 'reactive',
    tagName: 'ci-result',
    contents: 'CI failed on main: 3 tests failed.',
  },
  { resourceId: 'user_123', threadId: 'thread_456' },
)

await result.accepted
```

`type`描述來源：`reactive` for context from your system or a processor, `notification` for an external event. `tagName` sets the XML tag; without it Mastra uses the type name, except `reactive` defaults to `system-reminder`.

馬斯特拉山口`contents` as written and XML-escapes attribute values. A closing tag matching the signal's own tag is escaped so content can't end it early; this isn't a prompt-injection defense, so treat forwarded third-party text as untrusted. Use XML-safe `tagName` and attribute names with letters, numbers, periods, hyphens, or the underscore character, starting with a letter or underscore.

喜歡`sendMessage()`, `sendSignal()` delivers by default. Set `transient: true` to apply context only to the current request; Mastra doesn't store it, and transient signals can't be state signals. The [Agent reference](/reference/agents/agent#sendsignalsignal-options) covers `attributes`, `metadata`, and `providerOptions`.

## 比對話更持久的輸入 {/* #input-that-outlives-the-conversation */}

使用[`sendNotificationSignal()`](/reference/agents/agent#sendnotificationsignalnotification-options) when an event needs a durable inbox record, delivery policy, and later reading. It can also merge related pending events. Sending [`sendSignal({ type: 'notification' })`](/reference/agents/agent#sendsignalsignal-options) adds context without creating an inbox record. See [Notifications](/docs/signals/notifications) for the setup and delivery rules.

使用[`sendStateSignal()`](/reference/agents/agent#sendstatesignalstate-options) for named context that changes over time, such as the current browser page. Instead of adding a chat message, you send a full snapshot or a description of what changed. [State signals](/docs/signals/state-signals) explains how to keep that context current.

## 控制輸入何時到達 {/* #control-when-input-arrives */}

應用程式通常保留預設值：活動執行緒接收輸入並喚醒空閒執行緒。覆蓋它們只會得到不同的結果。

|線程狀態|預設 |其他選項 |
| - | - | - |
|活躍|交付到活動運作 |堅持不交付，或丟棄 |
|閒置|喚醒新的奔跑 |堅持不跑，或放棄 |

設定行為`ifActive.behavior` or `ifIdle.behavior`. For example, an event that should be available next time but shouldn't start a run on its own can be persisted:

```typescript title="src/mastra/signals.ts"
const result = agent.sendSignal(
  {
    type: 'notification',
    contents: 'A new pull request is ready for review.',
  },
  {
    ...thread,
    ifIdle: { behavior: 'persist' },
  },
)

const { action } = await result.accepted

if (action === 'persist') {
  await result.persisted
}
```

只有空閒線程才會保留在這裡。活動線程仍然會傳遞給正在運行的運行，因此`persisted` is set only when the action is `persist`.

訊息和信號發送返回一個`accepted` promise. It resolves when Mastra decides what to do, not when a run finishes. `sendNotificationSignal()` includes `accepted` only when its delivery policy emits a signal, so check `decision` first. `sendStateSignal()` omits it when it skips an unchanged snapshot.

這`accepted` promise resolves with one of these actions:

* `wake`：此過程開始運行輸入。
* `deliver`：輸入已傳送到運行，或另一個進程接受了啟動運行的責任。
* `persist`：輸入將被存儲，無需交付或重新運行。等待`persisted` to confirm the write.
* `discard`: 輸入已刪除。
* `blocked`：暫停的運行阻止 Mastra 在執行緒上啟動新的運行。

當動作是`wake`, the result carries the run's `output` stream. A run that fails after starting reports the error there. A routing failure rejects `accepted`. Use [`persisted`](/reference/agents/agent#sendsignalsignal-options) to wait for a storage write.

## 當Agent商看到您的輸入時 {/* #when-the-agent-sees-your-input */}

當模型請求期間輸入到達時，Mastra 可以取消該請求並使用新輸入重試。當模型僅產生推理或元資料或等待其第一個標記時，中斷視窗保持開啟狀態。當模型產生文字、Tool呼叫或其他內容時，它會關閉。替換在同一運行和步驟中使用新輸入重試，並將丟棄的回應保留在歷史記錄之外。它沒有添加任何內容`maxSteps` and leaves `stepNumber` unchanged. There's no separate interruption limit, so repeated input can restart reasoning until the request completes, the run is cancelled, or its timeout expires.

一旦請求產生文字、Tool呼叫或其他內容，該視窗就會關閉。然後輸入等待下一個循環邊界。正在運行的Tool不會被取消或重複，排隊的輸入也不會向前跳轉。如果`maxSteps` is reached first, Mastra may save queued input without a response.

已經串流的推理可能會保持可見，直到客戶端重新載入歷史記錄。輸入處理器在請求被取消之前完成；輸出處理器在下一個請求之前穩定下來，並且它們的副作用仍然存在。使用總量不包括中斷的請求，但提供者可能仍會計費。

訊號以 XML 元素的形式到達模型：`<user>`, `<system-reminder>` for reactive context, and `<notification>` for external events. With Memory configured, accepted non-transient signals are written into thread history. [State signals](/docs/signals/state-signals) and [Notifications](/docs/signals/notifications) have their own shapes.

## 停止運行或清除排隊的輸入 {/* #stop-a-run-or-clear-queued-input */}

預設情況下，中止運轉會保留排隊的輸入。經過`clearPendingSignals: true` to drop the queue too:

```typescript
subscription.abort({ clearPendingSignals: true })
```

沒有訂閱，請致電[`agent.abortThreadStream()`](/reference/agents/agent#abortthreadstreamoptions) with the same option. Listeners stay subscribed and a later message can start a run. With shared PubSub, the clear request reaches the owning process but clears only its local queue. Neither abort nor cancellation revokes an acceptance that already resolved. Continuations are separate, so aborting the original doesn't cancel them.

## AgentController 和會話 {/* #agentcontroller-and-session */}

`Agent` methods directly. AgentController's `Session` wraps them and manages the subscription:

|任務|`Agent` | AgentController `Session` |
| - | - | - |
| Send a user message | `agent.sendMessage()` | `session.sendMessage()` |
| Queue a user follow-up | `agent.queueMessage()` | `session.queueMessage()` |
| Send a typed signal | `agent.sendSignal()` | `session.sendSignal()` |
| Queue a typed signal | `agent.queueSignal()` | `session.queueSignal()` |
| Send a notification | `agent.sendNotificationSignal()` | `session.sendNotificationSignal()` |
| Write a state signal | `agent.sendStateSignal()` | Not exposed on `Session` |
| Subscribe to a thread | `agent.subscribeToThread()` | Managed by `Session` |

看[Agent Controller](/docs/harness/agent-controller) for how `Session` manages threads and subscriptions.
