# 發送訊號

用戶需要發言時，可發送訊息；如要先完成目前的回覆，可將後續訊息加入佇列；應用程式要補充上下文時，則可發送指定類型的訊號。三者均以執行緒為目標，Agent 的輸出可透過[執行緒串流](/docs/signals/thread-streams)接收。

以下例子沿用[概覽的快速入門](/docs/signals/overview#quickstart)中的 `Agent` 和執行緒。如要調用正在運作的伺服器上的 Agent，請使用[用戶端 SDK](/reference/client-js/agents) 或[伺服器路由](/reference/server/routes#agent-message-routes)。方法參數及傳回值見 [Agent 參考](/reference/agents/agent#thread-signals)。

## 發送訊息 {/* #send-a-message */}

發送用戶輸入時，將執行緒識別碼交給 [`sendMessage()`](/reference/agents/agent#sendmessagemessage-options)：

```typescript title="src/mastra/signals.ts"
const result = agent.sendMessage('Compare that with the previous option.', {
  resourceId: 'user_123',
  threadId: 'thread_456',
})

await result.accepted
```

`sendMessage()` 會即時傳回。等待 `result.accepted` 可取得 Mastra 的路由決定，並捕捉路由失敗。各項操作見[控制輸入的交付時間](#control-when-input-arrives)。

Mastra 會先查看執行緒的狀態。閒置的執行緒會啟動一次執行；如已有執行在進行中，便會由該次執行接收訊息，而模型會在下次請求時看到訊息。如有使用 Memory，訊息會保留供日後的執行和介面使用。中斷的詳情見 [Agent 何時看到輸入](#when-the-agent-sees-your-input)。

如有多人共用一個執行緒，可加入 `attributes`：

```typescript
const result = agent.sendMessage(
  {
    contents: 'Use the latest customer note too.',
    attributes: { name: 'Jane', sentFrom: 'slack' },
  },
  { resourceId: 'user_123', threadId: 'thread_456' },
)

await result.accepted
```

模型收到的內容為 `<user name="Jane" sentFrom="slack">Use the latest customer note too.</user>`。

## 將後續訊息加入佇列 {/* #queue-a-follow-up */}

如要在目前的回覆完成後才讓 Agent 看到下一則訊息，請用 [`queueMessage()`](/reference/agents/agent#queuemessagemessage-options)：

```typescript title="src/mastra/signals.ts"
const result = agent.queueMessage('Also check whether the tests need updates.', {
  resourceId: 'user_123',
  threadId: 'thread_456',
})

await result.accepted
```

佇列內的輸入會等候目前的執行完成，再啟動新一次執行。如執行緒閒置，便會立即啟動。[`cancelQueuedMessages()`](/reference/agents/agent#cancelqueuedmessagesoptions) 會移除佇列內的輸入，正在進行的執行則會繼續。跨進程的取消操作會盡力執行，已接納的輸入不會撤回。

[`queueSignal()`](/reference/agents/agent#queuesignalsignal-options) 同樣可將指定類型的上下文加入佇列，並保留訊號的 `type`、`tagName` 及屬性。

## 由系統發送上下文 {/* #send-context-from-a-system */}

使用 [`sendSignal()`](/reference/agents/agent#sendsignalsignal-options) 加入來自應用程式的上下文，例如背景工作的結果。訊號的類型和 XML 標籤會識別這些上下文：

```typescript title="src/mastra/signals.ts"
const result = agent.sendSignal(
  {
    type: 'reactive',
    tagName: 'ci-result',
    contents: 'CI failed on main: 3 tests failed.',
  },
  { resourceId: 'user_123', threadId: 'thread_456' },
)

await result.accepted
```

`type` 標示來源：系統或處理器提供的上下文用 `reactive`，外部事件則用 `notification`。`tagName` 設定 XML 標籤；如省略，Mastra 會採用類型名稱，但 `reactive` 預設為 `system-reminder`。

Mastra 會原樣傳送 `contents`，並對屬性值作 XML 跳脫處理。與訊號標籤配對的結束標籤也會作跳脫處理，避免內容提早結束元素。這無法防禦提示注入，因此應將轉發的第三方文字視為不可信。為符合 XML 規則，`tagName` 和屬性名稱只可使用字母、數字、句點、連字號或底線，並須以字母或底線開頭。

與 `sendMessage()` 一樣，`sendSignal()` 預設會交付輸入。設定 `transient: true` 可將上下文限制於目前的請求；Mastra 不會儲存它，而暫時訊號也不可用作狀態訊號。`attributes`、`metadata` 及 `providerOptions` 的詳情見 [Agent 參考](/reference/agents/agent#sendsignalsignal-options)。

## 在對話結束後仍可使用的輸入 {/* #input-that-outlives-the-conversation */}

如事件需要在收件箱長期保留、按政策交付並供稍後讀取，請使用 [`sendNotificationSignal()`](/reference/agents/agent#sendnotificationsignalnotification-options)。這亦可合併相關的待處理事件。調用 [`sendSignal({ type: 'notification' })`](/reference/agents/agent#sendsignalsignal-options) 會加入上下文，但不會建立收件箱記錄。交付規則及設定方法見[通知](/docs/signals/notifications)。

如需傳送會隨時間改變的具名上下文，例如瀏覽器目前的頁面，可使用 [`sendStateSignal()`](/reference/agents/agent#sendstatesignalstate-options)。這時可傳送完整快照或描述變更內容，無須新增聊天訊息。更新上下文的方法見[狀態訊號](/docs/signals/state-signals)。

## 控制輸入的交付時間 {/* #control-when-input-arrives */}

應用程式一般可沿用預設設定：執行中的執行緒會接收輸入，而閒置的執行緒會被喚醒。如需其他結果才更改設定。

| 執行緒狀態 | 預設做法 | 其他選項 |
| - | - | - |
| 執行中 | 交付給正在進行的執行 | 只儲存而不交付，或捨棄 |
| 閒置 | 喚醒並啟動新一次執行 | 只儲存而不啟動，或捨棄 |

透過 `ifActive.behavior` 或 `ifIdle.behavior` 設定行為。例如，如果事件只需留待下次使用，毋須自行啟動執行，便可將它儲存：

```typescript title="src/mastra/signals.ts"
const result = agent.sendSignal(
  {
    type: 'notification',
    contents: 'A new pull request is ready for review.',
  },
  {
    ...thread,
    ifIdle: { behavior: 'persist' },
  },
)

const { action } = await result.accepted

if (action === 'persist') {
  await result.persisted
}
```

在這個例子中，只有閒置的執行緒會儲存輸入。執行緒如在運作，仍會把輸入交給正在進行的執行，因此只有操作為 `persist` 時才會設定 `persisted`。

發送訊息或訊號會傳回 `accepted` Promise。Mastra 一決定如何處理輸入，Promise 便會完成，無須等候執行結束。`sendNotificationSignal()` 只有在交付政策發出訊號時才包含 `accepted`，所以應先檢查 `decision`。`sendStateSignal()` 略過沒有變更的快照時，亦會省略它。

`accepted` Promise 完成後會傳回以下其中一項操作：

- `wake`：目前的進程已為這項輸入啟動一次執行。
- `deliver`：輸入已交付給一次執行，或已有另一個進程接手啟動執行。
- `persist`：輸入將會儲存，既不交付，也不啟動新執行。等候 `persisted` 可確認寫入。
- `discard`：輸入已被捨棄。
- `blocked`：執行緒內有一次執行已暫停，令 Mastra 無法啟動新執行。

操作為 `wake` 時，結果會包含該次執行的 `output` 串流。執行啟動後如告失敗，錯誤會在這個串流回報。如路由失敗，`accepted` 會被拒絕。使用 [`persisted`](/reference/agents/agent#sendsignalsignal-options) 等候寫入儲存區。

## Agent 何時看到輸入 {/* #when-the-agent-sees-your-input */}

如模型請求期間收到輸入，Mastra 可取消該請求，並帶同新輸入重試。模型等候第一個 token，或只產生推理內容或元數據時，仍可中斷；當模型產生文字、工具調用或其他內容後，便不可中斷。重試會在同一次執行的同一步驟使用新輸入，捨棄的回應不會寫入歷史記錄。重試不佔用 `maxSteps` 的額度，`stepNumber` 也不變。中斷並無獨立的次數限制，因此持續收到輸入可反覆重啟推理，直至請求完成、執行取消或逾時。

請求一旦產生文字、工具調用或其他內容，便不可再中斷。其後收到的輸入須等到下一輪迴圈開始；正在運作的工具不會取消或重複執行，而佇列內的輸入也不會提前處理。如先達到 `maxSteps`，Mastra 或會儲存佇列內的輸入，但不作回應。

已透過串流送出的推理內容或會繼續顯示，直至用戶端重新載入歷史記錄。輸入處理器會在取消請求前完成；輸出處理器會在下一次請求前結束，而已產生的副作用會保留。中斷的請求不計入總用量，但 Provider 仍可能收費。

訊號會以 XML 元素傳送給模型：`<user>`、代表反應式上下文的 `<system-reminder>`，以及代表外部事件的 `<notification>`。如已設定 Memory，獲接納且並非暫時的訊號會寫入執行緒的歷史記錄。[狀態訊號](/docs/signals/state-signals)及[通知](/docs/signals/notifications)各自有不同的格式。

## 停止執行或清除佇列內的輸入 {/* #stop-a-run-or-clear-queued-input */}

中止執行時，預設會保留佇列內的輸入。如要同時清除佇列，請傳入 `clearPendingSignals: true`：

```typescript
subscription.abort({ clearPendingSignals: true })
```

如沒有訂閱，可用相同選項調用 [`agent.abortThreadStream()`](/reference/agents/agent#abortthreadstreamoptions)。監聽器會繼續訂閱，而其後的訊息仍可啟動執行。使用共用 PubSub 時，清除請求會送到所屬進程，但只會清除該進程的本機佇列。中止或取消均不會撤回已完成的接納結果。延續執行各自獨立，中止原本的執行不會取消它們。

## AgentController 和 Session {/* #agentcontroller-and-session */}

大部分應用程式會直接使用 `Agent` 的方法。AgentController 的 `Session` 會封裝這些方法，並管理訂閱：

| 操作 | `Agent` | AgentController `Session` |
| - | - | - |
| 發送用戶訊息 | `agent.sendMessage()` | `session.sendMessage()` |
| 將用戶的後續訊息加入佇列 | `agent.queueMessage()` | `session.queueMessage()` |
| 發送指定類型的訊號 | `agent.sendSignal()` | `session.sendSignal()` |
| 將指定類型的訊號加入佇列 | `agent.queueSignal()` | `session.queueSignal()` |
| 發送通知 | `agent.sendNotificationSignal()` | `session.sendNotificationSignal()` |
| 寫入狀態訊號 | `agent.sendStateSignal()` | `Session` 不提供此方法 |
| 訂閱執行緒 | `agent.subscribeToThread()` | 由 `Session` 管理 |

`Session` 如何管理執行緒及訂閱，請參閱 [Agent Controller](/docs/harness/agent-controller)。
