# 訊號

**添加於：** `@mastra/core@1.39.0`

你可隨時透過訊號將輸入送往 Agent 的[對話串](/docs/memory/message-history#threads-and-resources)，即使 Agent 正在處理工作。輸入可以是使用者訊息、背景工作的更新或外部事件。Mastra 會根據訊號類型識別當中的輸入。

如要持續對話，請以訊號傳送輸入，再經[對話串串流](/docs/signals/thread-streams)接收輸出。先訂閱串流，有輸入時便可送出。Mastra 預設會將輸入交給目前的執行；對話串閒置時則開始一次執行。傳送前毋須查核 Agent 的運作狀態。

如只需提出一次請求，可用 [`agent.stream()`](/reference/streaming/agents/stream) 開始執行並直接讀取答覆。這個方法亦可使用 Memory，但不會訂閱同一對話串後續的執行。

觀看 [Mastra 訊號簡介](https://www.youtube.com/watch?v=7It2y89TVP4)，了解訊號如何喚醒長時間運作的 Agent，以及如何引導它繼續執行。

## 快速入門 {/* #quickstart */}

建立一個Agent，訂閱一個線程，然後將輸入傳送到該線程。首先訂閱意味著當輸入開始運行時訂閱已經開啟。

### 使用Agent {/* #use-an-agent */}

範例用 [Memory](/docs/memory/overview) 將對話串記錄儲存在本機 libSQL 資料庫，因此即使再次執行或重啟進程，仍可繼續原有對話。Memory 可使用任何受支援的儲存配接器；對話串於首次執行時建立。

```typescript title="src/mastra/signals.ts"
import { Agent } from '@mastra/core/agent'
import { Memory } from '@mastra/memory'
import { LibSQLStore } from '@mastra/libsql'

const agent = new Agent({
  id: 'support-agent',
  name: 'Support Agent',
  instructions: 'Help the user compare options.',
  model: '__GATEWAY_OPENAI_MODEL__',
  memory: new Memory({
    storage: new LibSQLStore({
      id: 'signals-storage',
      url: 'file:./signals.db',
    }),
  }),
})

const thread = {
  resourceId: 'user_123',
  threadId: 'thread_456',
}

const subscription = await agent.subscribeToThread(thread)

const result = agent.sendMessage('Compare that with the previous option.', thread)
await result.accepted

for await (const chunk of subscription.stream) {
  console.log(chunk)
}
```

Agent 回覆時，迴圈會逐段顯示輸出。執行結束後，訂閱仍會保留，以接收同一對話串之後收到訊息時的輸出。不再需要這些輸出時，可調用 `subscription.unsubscribe()`。如要傳送更多訊息或其他輸入，可參閱[傳送訊號](/docs/signals/sending-signals)。

### 使用客戶端SDK {/* #use-the-client-sdk */}

經 [`client.getAgent()`](/reference/client-js/mastra-client#methods) 操作時，亦是先調用 `subscribeToThread()`，再向同一對話串傳送訊息。客戶端會回傳訂閱串流，執行則仍由伺服器管理。完整範例見[對話串串流](/docs/signals/thread-streams)。

## 訊號如何到達線程 {/* #how-signals-reach-a-thread */}

將輸入傳送到活動運行並不總是立即中斷模型。 Mastra 會等待，直到運行可以接受它。如果目前的答案需要先完成，請改為排隊後續答案。您還可以儲存輸入以供以後使用，而無需開始運行，或根據線程的狀態丟棄它。

[傳送訊號](/docs/signals/sending-signals#when-the-agent-sees-your-input)列出這些傳送方式，並說明如何查核輸入是否已獲接收。若應用程式在多個進程運作，請[設定共用後端](/docs/signals/running-across-processes)，讓訊號送達執行該對話串的進程。

## 選擇 API 介面 {/* #choose-an-api-surface */}

|表面|用它來 |規範參考 |
| - | - | - |
| 直接調用 `Agent` 方法 | 持有 Agent 實例的伺服器端程式碼 | [Agent 參考](/reference/agents/agent#thread-signals) |
| HTTP or the JavaScript client SDK | Applications that call a running Mastra server | [Server agent routes](/reference/server/routes#agent-message-routes), [`client.getAgent()`](/reference/client-js/agents) |
| AgentController `Session` | Long-running assistants and coding agents built on AgentController | [Agent Controller](/docs/harness/agent-controller) |

若程式碼與 Agent 一同運作，可先用 `Agent` 方法；若要向伺服器發出請求，則使用客戶端 SDK。如果已使用 [Agent Controller](/docs/harness/agent-controller)，其 `Session` 會管理對話串和訂閱。
