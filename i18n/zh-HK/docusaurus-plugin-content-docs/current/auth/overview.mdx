# 身份驗證

Mastra 提供多種身份驗證方式。你可以選擇配合現有技術架構的身份系統，保護 API 和 [Studio](/docs/studio/overview)。

你可先透過共享密鑰進行基本的 JWT 身份驗證，待需要更進階的身份功能時再轉用現有的身份提供者。

## 身份驗證的保護範圍 {/* #what-auth-secures */}

設定身份驗證後，以下兩處會限制存取：

- **Studio 介面**：Studio 會顯示登入畫面，提供單一登入（SSO）、電郵及密碼登入，或同時提供兩種方式。如有設定 RBAC 提供者，Studio 亦會按角色控制存取權限，決定各團隊成員可查看的內容和可執行的操作。
- **API 路由**：不論請求來自 Studio 還是直接呼叫 API，內置路由（如 `/api/agents/*`、`/api/workflows/*`）和自訂路由均須驗證身份。少數內置路由仍然公開，例如 Studio 用來檢查登入狀態的 `GET /api/auth/capabilities`。

預設由 `server.auth` 指定的提供者保護兩者。如要為 Studio 使用獨立的提供者，請同時設定 `studio.auth`。Studio 發出的請求（包括呼叫 API 路由）其後只會使用 `studio.auth`，其餘請求繼續使用 `server.auth`。

身份驗證屬選用設定。如未設定，所有路由和 Studio 均可公開存取。你亦可在個別自訂路由設定 `requiresAuth: false`，開放公開存取。

如要控制自訂端點的身份驗證，請參閱[自訂 API 路由](/docs/server/custom-api-routes#authentication)。有關如何保護已部署的 Studio，請參閱 [Studio 身份驗證文件](/docs/studio/auth)。

:::warning
預設的身份驗證設定會保護 `/api/*`，並公開 `/api` 和 `/api/auth/*`。自訂 `server.apiPrefix` 後，預設規則將無法配對新前綴，內置路由便會落在保護範圍以外。請在 `server.auth.protected` 和 `server.auth.public` 中使用新的前綴。
:::

:::note

Studio 目前支援 Simple Auth、JWT、WorkOS、Better Auth 和 Google 進行身份驗證。

:::
