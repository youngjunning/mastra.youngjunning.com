# 快照

在 Mastra，快照以可序列化的形式記錄 Workflow 在某個時間點的完整執行狀態。快照包含從暫停位置繼續執行所需的所有資料，包括：

- 每個步驟目前的狀態
- 已完成步驟的輸出
- Workflow 已經過的執行路徑
- 所有暫停的步驟及其中繼資料
- 各步驟剩餘的重試次數
- 恢復執行所需的其他上下文資料

每次 Workflow 暫停時，Mastra 都會自動建立和管理快照，並將快照持久儲存至已設定的儲存系統。

## 快照在暫停和恢復執行時的作用 {/* #the-role-of-snapshots-in-suspend-and-resume */}

快照是 Mastra 暫停和恢復執行的關鍵。當 Workflow 步驟呼叫 `await suspend()` 時：

1. Workflow 在呼叫位置暫停。
1. 系統將 Workflow 當前狀態記錄成快照。
1. 系統將快照持久儲存。
1. 步驟被標記為已暫停，狀態為 `'suspended'`。
1. 稍後對暫停的步驟呼叫 `resume()` 時，系統會讀取快照。
1. Workflow 從原先暫停的位置繼續執行。

這項機制可用於建立需要人員參與的 Workflow、處理速率限制、等待外部資源，以及實作可能需要長時間暫停的複雜分支 Workflow。

## 快照的組成 {/* #snapshot-anatomy */}

每份快照包含 `runId`、輸入、步驟狀態（例如 `success`、`suspended`）、暫停和恢復執行時傳入的資料（如有），以及最終輸出，以便恢復執行時取得完整上下文。

## 如何儲存和讀取快照 {/* #how-snapshots-are-saved-and-retrieved */}

快照會儲存在已設定的儲存系統內。預設使用 libSQL，你也可改用 Upstash、PostgreSQL 或 OracleDB。每份快照均儲存在 `workflow_snapshots` 資料表，以 Workflow 的 `runId` 識別。

### 儲存快照 {/* #saving-snapshots */}

Workflow 暫停時，Mastra 會按以下步驟自動持久儲存快照：

1. 步驟執行期間呼叫 `suspend()` 函數，觸發快照流程。
1. `WorkflowInstance.suspend()` 方法記錄已暫停的狀態機。
1. 系統呼叫 `persistWorkflowSnapshot()` 儲存當前狀態。
1. 系統將快照序列化，再存入已設定資料庫的 `workflow_snapshots` 資料表。
1. 儲存紀錄包含 Workflow 名稱、執行 ID 和已序列化的快照。

### 讀取快照 {/* #retrieving-snapshots */}

Workflow 恢復執行時，Mastra 會按以下步驟讀取已儲存的快照：

1. 呼叫 `resume()` 方法並指定步驟 ID。
1. 透過 `loadWorkflowSnapshot()` 從儲存系統載入快照。
1. 剖析快照，準備恢復執行。
1. 按快照內的狀態重建 Workflow 執行。
1. 恢復暫停的步驟，然後繼續執行。

```typescript
const storage = mastra.getStorage()
const workflowStore = await storage?.getStore('workflows')

const snapshot = await workflowStore?.loadWorkflowSnapshot({
  runId: '<run-id>',
  workflowName: '<workflow-id>',
})

console.log(snapshot)
```

## 快照儲存選項 {/* #storage-options-for-snapshots */}

快照透過在 `Mastra` 類別設定的 `storage` 實例持久儲存。所有註冊到同一 Mastra 實例的 Workflow 都共用此儲存層。Mastra 支援多種儲存選項，以配合不同環境。

```typescript title="src/mastra/index.ts"
import { Mastra } from '@mastra/core'
import { LibSQLStore } from '@mastra/libsql'
import { approvalWorkflow } from './workflows'

export const mastra = new Mastra({
  storage: new LibSQLStore({
    id: 'mastra-storage',
    url: ':memory:',
  }),
  workflows: { approvalWorkflow },
})
```

## 最佳做法 {/* #best-practices */}

1. **確保資料可序列化**：所有需要放入快照的資料都必須可序列化，即可轉換為 JSON。
1. **縮減快照大小**：避免將大型資料物件直接儲存在 Workflow 上下文。可只儲存對這些物件的參照（例如 ID），有需要時再讀取資料。
1. **慎選恢復執行時的上下文**：恢復 Workflow 時，應仔細選擇要提供的上下文，因為它會與現有快照資料合併。
1. **設定監察**：監察已暫停的 Workflow，尤其是長時間執行的 Workflow，並確保它們可正常恢復執行。
1. **考慮儲存擴展需求**：若應用程式有大量暫停的 Workflow，請確保儲存方案的規模足以應付。

## 自訂快照中繼資料 {/* #custom-snapshot-metadata */}

你可以定義 `suspendSchema`，在暫停 Workflow 時附加自訂中繼資料。資料會儲存在快照內，以便恢復執行時使用。

```typescript {30-34} title="src/mastra/workflows/test-workflow.ts"
import { createWorkflow, createStep } from '@mastra/core/workflows'
import { z } from 'zod'

const approvalStep = createStep({
  id: 'approval-step',
  description: 'Accepts a value, waits for confirmation',
  inputSchema: z.object({
    value: z.number(),
    user: z.string(),
    requiredApprovers: z.array(z.string()),
  }),
  suspendSchema: z.object({
    message: z.string(),
    requestedBy: z.string(),
    approvers: z.array(z.string()),
  }),
  resumeSchema: z.object({
    confirm: z.boolean(),
    approver: z.string(),
  }),
  outputSchema: z.object({
    value: z.number(),
    approved: z.boolean(),
  }),
  execute: async ({ inputData, resumeData, suspend }) => {
    const { value, user, requiredApprovers } = inputData
    const { confirm } = resumeData ?? {}

    if (!confirm) {
      return await suspend({
        message: 'Workflow suspended',
        requestedBy: user,
        approvers: [...requiredApprovers],
      })
    }

    return {
      value,
      approved: confirm,
    }
  },
})
```

### 提供恢復執行的資料 {/* #providing-resume-data */}

恢復已暫停的步驟時，可藉 `resumeData` 傳入結構化輸入。資料必須符合該步驟的 `resumeSchema`。

```typescript {14-20}
const workflow = mastra.getWorkflow('approvalWorkflow')

const run = await workflow.createRun()

const result = await run.start({
  inputData: {
    value: 100,
    user: 'Michael',
    requiredApprovers: ['manager', 'finance'],
  },
})

if (result.status === 'suspended') {
  const resumedResult = await run.resume({
    step: 'approval-step',
    resumeData: {
      confirm: true,
      approver: 'manager',
    },
  })
}
```
