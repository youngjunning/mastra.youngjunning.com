# 快照

在 Mastra 中，快照是Workflow在特定時間點的完整執行狀態的可序列化表示。快照捕獲從中斷位置恢復Workflow所需的所有信息，包括：

* Workflow中每個步驟的當前狀態
* 已完成步驟的輸出
* Workflow的執行路徑
* 任何暫停的步驟及其元數據
* 每個步驟的剩餘重試次數
* 恢復執行所需的附加上下文數據

每當Workflow暫停時，Mastra 都會自動建立和管理快照，並將其保留到配置的儲存系統中。

## 快照在掛起和恢復中的作用 {/* #the-role-of-snapshots-in-suspend-and-resume */}

快照是實現 Mastra 暫停和恢復功能的關鍵機制。當Workflow步驟呼叫時`await suspend()`:

1. Workflow執行在該確切點暫停
2. Workflow的當前狀態被捕獲為快照
3. 快照持久化到存儲
4. Workflow步驟被標記為“已暫停”，狀態為`'suspended'`
5. 後來，當`resume()` is called on the suspended step, the snapshot is retrieved
6. Workflow執行從停止的地方繼續執行

該機制提供了一種強大的方法來實現人機互動Workflow、處理速率限制、等待外部資源以及實現可能需要長時間暫停的複雜分支Workflow。

## 快照解剖 {/* #snapshot-anatomy */}

## 如何儲存和檢索快照 {/* #how-snapshots-are-saved-and-retrieved */}

快照儲存到配置的儲存系統。預設情況下，它們使用 libSQL，但您可以設定 Upstash、PostgreSQL 或 OracleDB。每個快照都保存在`workflow_snapshots` table and identified by the workflow's `runId`.

### 儲存快照 {/* #saving-snapshots */}

當Workflow暫停時，Mastra 透過以下步驟自動保留Workflow快照：

1. 這`suspend()` function in a step execution triggers the snapshot process
2. 這`WorkflowInstance.suspend()` method records the suspended machine
3. `persistWorkflowSnapshot()`被呼叫來保存當前狀態
4. 快照被序列化並儲存在配置的資料庫中`workflow_snapshots` table
5. 儲存記錄包括Workflow名稱、運行 ID 和序列化快照

### 檢索快照 {/* #retrieving-snapshots */}

當Workflow復原時，Mastra 透過以下步驟檢索持久快照：

1. 這`resume()` method is called with a specific step ID
2. 快照是使用以下方式從儲存裝置載入的`loadWorkflowSnapshot()`
3. 快照已解析並準備恢復
4. 使用快照狀態重新建立Workflow執行
5. 暫停的步驟恢復，繼續執行

```typescript
const storage = mastra.getStorage()
const workflowStore = await storage?.getStore('workflows')

const snapshot = await workflowStore?.loadWorkflowSnapshot({
  runId: '<run-id>',
  workflowName: '<workflow-id>',
})

console.log(snapshot)
```

## 快照的儲存選項 {/* #storage-options-for-snapshots */}

快照是使用`storage` instance configured on the `Mastra` class. This storage layer is shared across all workflows registered to that instance. Mastra supports multiple storage options for flexibility in different environments.

```typescript title="src/mastra/index.ts"
import { Mastra } from '@mastra/core'
import { LibSQLStore } from '@mastra/libsql'
import { approvalWorkflow } from './workflows'

export const mastra = new Mastra({
  storage: new LibSQLStore({
    id: 'mastra-storage',
    url: ':memory:',
  }),
  workflows: { approvalWorkflow },
})
```

## 最佳實踐 {/* #best-practices */}

1. **確保可串行性**：任何需要包含在快照中的資料都必須是可序列化的（可轉換為 JSON）。
2. **最小化快照大小**：避免將大型資料物件直接儲存在Workflow上下文中。相反，儲存對它們的引用（如 ID）並在需要時檢索資料。
3. **小心處理履歷上下文**：恢復Workflow時，請仔細考慮要提供的上下文。這將與現有快照資料合併。
4. **設定適當的監控**：對暫停的Workflow（尤其是長時間運行的Workflow）實施監控，並確保它們正確恢復。
5. **考慮儲存擴充**

## 自訂快照元數據 {/* #custom-snapshot-metadata */}

您可以在暫停Workflow時附加自訂元數據，方法是定義`suspendSchema`. This metadata is stored in the snapshot and made available when the workflow is resumed.

```typescript {30-34} title="src/mastra/workflows/test-workflow.ts"
import { createWorkflow, createStep } from '@mastra/core/workflows'
import { z } from 'zod'

const approvalStep = createStep({
  id: 'approval-step',
  description: 'Accepts a value, waits for confirmation',
  inputSchema: z.object({
    value: z.number(),
    user: z.string(),
    requiredApprovers: z.array(z.string()),
  }),
  suspendSchema: z.object({
    message: z.string(),
    requestedBy: z.string(),
    approvers: z.array(z.string()),
  }),
  resumeSchema: z.object({
    confirm: z.boolean(),
    approver: z.string(),
  }),
  outputSchema: z.object({
    value: z.number(),
    approved: z.boolean(),
  }),
  execute: async ({ inputData, resumeData, suspend }) => {
    const { value, user, requiredApprovers } = inputData
    const { confirm } = resumeData ?? {}

    if (!confirm) {
      return await suspend({
        message: 'Workflow suspended',
        requestedBy: user,
        approvers: [...requiredApprovers],
      })
    }

    return {
      value,
      approved: confirm,
    }
  },
})
```

### {/* #providing-resume-data */}

使用`resumeData` to pass structured input when resuming a suspended step. It must match the step’s `resumeSchema`.

```typescript {14-20}
const workflow = mastra.getWorkflow('approvalWorkflow')

const run = await workflow.createRun()

const result = await run.start({
  inputData: {
    value: 100,
    user: 'Michael',
    requiredApprovers: ['manager', 'finance'],
  },
})

if (result.status === 'suspended') {
  const resumedResult = await run.resume({
    step: 'approval-step',
    resumeData: {
      confirm: true,
      approver: 'manager',
    },
  })
}
```
