# Workflows

Workflow 讓你用清晰而有結構的步驟安排複雜任務，毋須交由單一 Agent 推理整個過程。你可以控制任務如何拆分，以及資料流轉的順序和時間。Workflow 預設由內置執行引擎運行；如需託管基礎設施，也可使用 Inngest 等 [Workflow runner](/docs/deployment/workflow-runners)。

<Inject>
  **供 AI Agent 使用：**執行 `npx mastra api workflow run start test-workflow '{"inputData":{"message":"Hello, world!"}}'`，即可直接啟動此 Workflow，毋須編寫臨時腳本。指令需要有正在運行的 Mastra 伺服器；可用 `npx mastra dev` 啟動本機伺服器，或透過 `--url` 指定可連線伺服器的基本 URL。構造其他輸入之前，先執行 `npx mastra api workflow run start --schema`。安裝 Mastra Skill：`npx skills add mastra-ai/skills --skill mastra`，可取得完整的 API CLI 探索、目標指定、Schema、身分驗證和錯誤處理指引。
</Inject>

## 何時使用 Workflow {/* #when-to-use-workflows */}

如果任務可預先明確界定，而且有多個步驟須按特定次序執行，就適合使用 Workflow。它讓你細緻控制資料在步驟之間如何流轉和轉換，以及每個階段會調用哪些元件。

## 核心原則 {/* #core-principles */}

Mastra Workflow 按以下原則運作：

- 以 [`createStep`](/reference/workflows/step) 定義**步驟**，指定輸入與輸出 Schema 和業務邏輯。
- 以 [`createWorkflow`](/reference/workflows/workflow) 組合**步驟**，訂明執行流程。
- 運行 **Workflow** 完成整個序列；內置支援暫停、恢復及串流結果。

## 建立 Workflow 步驟 {/* #creating-a-workflow-step */}

步驟是 Workflow 的基本組件。使用 `createStep()` 建立步驟，並透過 `inputSchema` 和 `outputSchema` 定義接收及傳回的資料。兩種 Schema 均可使用 [Standard JSON Schema](https://standardschema.dev/json-schema) 定義，例如透過 [Zod](https://zod.dev/)、[Valibot](https://valibot.dev/) 或 [ArkType](https://arktype.io/)。

`execute` 函式定義步驟的工作內容。你可用它調用程式碼中的函式、外部 API、Agent 或 Tool。

    import { z } from 'zod'

    const step1 = createStep({
      id: 'step-1',
      inputSchema: z.object({
        message: z.string(),
      }),
      outputSchema: z.object({
        formatted: z.string(),
      }),
      execute: async ({ inputData }) => {
        const { message } = inputData

        return {
          formatted: message.toUpperCase(),
        }
      },
    })

## 建立 Workflow {/* #creating-a-workflow */}

使用 `createWorkflow()` 建立 Workflow，並透過 `inputSchema` 和 `outputSchema` 定義接收及傳回的資料。兩種 Schema 均可使用 [Standard JSON Schema](https://standardschema.dev/json-schema) 定義，例如透過 [Zod](https://zod.dev/)、[Valibot](https://valibot.dev/) 或 [ArkType](https://arktype.io/)。以 `.then()` 加入步驟，最後調用 `.commit()` 完成 Workflow。

### 了解控制流程 {/* #understanding-control-flow */}

Workflow 可用多種方法組合；所選方法決定每個步驟的 Schema 應如何設計。詳情請參閱[控制流程](/docs/workflows/control-flow)。

## Studio {/* #studio */}

開啟 [Studio](/docs/studio/overview)，然後在 **Workflows** 分頁選擇一個 Workflow。

- **圖形檢視**：中央面板呈現 Workflow 的步驟和執行流程。
- **輸入表格**：右側欄按 Workflow 的 `inputSchema` 產生表格。填妥後即可開始運行。
- **即時狀態**：運行期間，圖形會即時更新各步驟狀態；側欄會顯示 Workflow 的輸入、輸出、狀態及日誌。
- [**時間回溯**](/docs/workflows/time-travel)：運行完成後，可重播個別步驟以檢查或重試。

## Workflow 狀態 {/* #workflow-state */}
Workflow 狀態可讓步驟共用數值，毋須在每一步的 inputSchema 和 outputSchema 之間傳遞。可用狀態追蹤進度、累積結果，或在整個 Workflow 內共用設定。


```typescript title="src/mastra/workflows/test-workflow.ts"
import { createStep } from '@mastra/core/workflows'
import { z } from 'zod'

const step1 = createStep({
  id: 'step-1',
  inputSchema: z.object({ message: z.string() }),
  outputSchema: z.object({ formatted: z.string() }),
  stateSchema: z.object({ counter: z.number() }),
  execute: async ({ inputData, state, setState }) => {
    // Read from state
    console.log(state.counter)

    // Update state for subsequent steps
    setState({ ...state, counter: state.counter + 1 })

    return { formatted: inputData.message.toUpperCase() }
  },
})
```

有關狀態 Schema、初始狀態、暫停與恢復之間的持久化，以及巢狀 Workflow 的完整說明，請參閱 [Workflow 狀態](/docs/workflows/workflow-state)。

## 把 Workflow 當作步驟 {/* #workflows-as-steps */}

把 Workflow 當作步驟，便可在更大型流程中重用其邏輯。輸入及輸出遵循[核心原則](/docs/workflows/control-flow)所述的相同 Schema 規則。

```typescript {29} title="src/mastra/workflows/test-workflow.ts" oxfmt:false
import { createWorkflow, createStep } from '@mastra/core/workflows';
import { z } from 'zod';

const step1 = createStep({...});
const step2 = createStep({...});

const childWorkflow = createWorkflow({
  id: "child-workflow",
  inputSchema: z.object({
    message: z.string()
  }),
  outputSchema: z.object({
    emphasized: z.string()
  })
})
  .then(step1)
  .then(step2)
  .commit();

export const testWorkflow = createWorkflow({
  id: "test-workflow",
  inputSchema: z.object({
    message: z.string()
  }),
  outputSchema: z.object({
    emphasized: z.string()
  })
})
  .then(childWorkflow)
  .commit();
```

### 複製 Workflow {/* #cloning-a-workflow */}

需要重用 Workflow 邏輯，但希望以新 ID 分開追蹤時，可使用 `cloneWorkflow()`。每個複本獨立運行，並會在日誌及可觀測性工具中顯示為不同的 Workflow。

```typescript oxfmt:false {6} title="src/mastra/workflows/test-workflow.ts"
import { cloneWorkflow, createWorkflow, createStep } from "@mastra/core/workflows";

const step1 = createStep({...});

const parentWorkflow = createWorkflow({...})
const clonedWorkflow = cloneWorkflow(parentWorkflow, { id: "cloned-workflow" });

export const testWorkflow = createWorkflow({...})
  .then(step1)
  .then(clonedWorkflow)
  .commit();
```

## 註冊 Workflow {/* #registering-a-workflow */}

在 Mastra 實例中註冊 Workflow，即可供整個應用程式使用。註冊後，Agent 或 Tool 可以調用它，它亦可存取日誌及可觀測性等共用資源：

```typescript {5} title="src/mastra/index.ts"
import { Mastra } from '@mastra/core/mastra'
import { testWorkflow } from './workflows/test-workflow'

export const mastra = new Mastra({
  workflows: { testWorkflow },
})
```

## 取得 Workflow 參照 {/* #referencing-a-workflow */}

你可從 Agent、Tool、Mastra Client 或命令列運行 Workflow。視乎設定，在 `mastra` 或 `mastraClient` 實例上調用 `.getWorkflow()` 取得參照：

```typescript
const testWorkflow = mastra.getWorkflow('testWorkflow')
```

:::note

相較直接匯入，建議使用 `mastra.getWorkflow()`，原因有兩個：

1. 可存取 Mastra 實例的設定，包括日誌記錄器、遙測、儲存空間、已註冊的 Agent 及向量儲存空間。
1. 可完整推斷 Workflow 輸入及輸出 Schema 的 TypeScript 型別。

調用 `getWorkflow()` 時，請使用 Workflow 的**註冊鍵**（加入 Mastra 時所用的鍵）。`getWorkflowById()` 可按 Workflow 的 `id` 屬性檢索，但無法提供相同程度的型別推斷。
:::

## 運行 Workflow {/* #running-workflows */}

Workflow 有兩種運行模式：start 會等所有步驟完成後才傳回結果；stream 則在執行期間發出事件。只需要最終結果時選擇 start；要監察進度或在步驟完成時觸發動作，則選擇 stream。

<Tabs>
  <TabItem value="start" label=".start()">
    先以 `createRun()` 建立 Workflow 運行實例，再調用 `.start()`，傳入符合 Workflow `inputSchema` 的 `inputData`。Workflow 會執行所有步驟，然後傳回最終結果。

    ```typescript
    const run = await testWorkflow.createRun()

    const result = await run.start({
      inputData: {
        message: 'Hello world',
      },
    })

    if (result.status === 'success') {
      console.log(result.result)
    }
    ```
  </TabItem>

  <TabItem value="stream" label=".stream()">
    先以 `.createRun()` 建立 Workflow 運行實例，再調用 `.stream()`，傳入符合 Workflow `inputSchema` 的 `inputData`。逐一讀取 `fullStream` 以追蹤進度，最後等待 `result` 取得最終結果。

    ```typescript
    const run = await testWorkflow.createRun()

    const stream = run.stream({
      inputData: {
        message: 'Hello world',
      },
    })

    for await (const chunk of stream.fullStream) {
      console.log(chunk)
    }

    // Get the final result (same type as run.start())
    const result = await stream.result

    if (result.status === 'success') {
      console.log(result.result)
    }
    ```
  </TabItem>
</Tabs>

### Workflow 結果型別 {/* #workflow-result-type */}

`run.start()` 及 `stream.result` 均會按 `status` 傳回可辨識聯集型別；狀態可能為 `success`、`failed`、`suspended`、`tripwire` 或 `paused`。無論狀態如何，都可安全存取 `result.status`、`result.input`、`result.steps`，以及可選的 `result.state`。

此外，不同狀態會提供不同屬性：

| 狀態 | 專屬屬性 | 說明 |
| - | - | - |
| `success` | `result` | Workflow 的輸出資料 |
| `failed` | `error` | 導致失敗的錯誤 |
| `tripwire` | `tripwire` | 包含 `reason`、`retry?`、`metadata?`、`processorId?` |
| `suspended` | `suspendPayload`、`suspended` | 暫停資料及已暫停步驟路徑的陣列 |
| `paused` | _（無）_ | 只有共通屬性 |

要讀取特定狀態的屬性，請先檢查 `status`：

```typescript
const result = await run.start({ inputData: { message: 'Hello world' } })

if (result.status === 'success') {
  console.log(result.result) // Only available when status is "success"
} else if (result.status === 'failed') {
  console.log(result.error.message)
} else if (result.status === 'suspended') {
  console.log(result.suspendPayload)
}
```

## 串流 {/* #streaming */}

通用 `writer` API 的用法請參閱[串流](/docs/guides/streaming#writer-api)。

### 檢查 Workflow 串流負載 {/* #inspecting-workflow-stream-payloads */}

寫入串流的事件會包含在發出的資料區塊中。檢查區塊即可讀取事件類型、中途產生的值，或步驟專屬資料等自訂欄位。

```typescript
const testWorkflow = mastra.getWorkflow('testWorkflow')

const run = await testWorkflow.createRun()

const stream = await run.stream({
  inputData: {
    value: 'initial data',
  },
})

for await (const chunk of stream) {
  console.log(chunk)
}

if (result!.status === 'suspended') {
  // if the workflow is suspended, we can resume it with the resumeStream method
  const resumedStream = await run.resumeStream({
    resumeData: { value: 'resume data' },
  })

  for await (const chunk of resumedStream) {
    console.log(chunk)
  }
}
```

### 恢復中斷的 Workflow 串流 {/* #resuming-an-interrupted-workflow-stream */}

若 Workflow 串流因任何原因關閉或中斷，可用 `resumeStream` 方法恢復。它會傳回新的 `ReadableStream`，讓你繼續觀察 Workflow 事件。

```typescript
const newStream = await run.resumeStream()

for await (const chunk of newStream) {
  console.log(chunk)
}
```

### 在 Workflow 中使用 Agent {/* #workflow-using-an-agent */}

把 Agent 的 `textStream` 傳入 Workflow 步驟的 `writer`，便可串流輸出部分內容；Mastra 亦會自動把 Agent 用量計入該次 Workflow 運行。

```typescript
import { createStep } from '@mastra/core/workflows'
import { z } from 'zod'

export const testStep = createStep({
  execute: async ({ inputData, mastra, writer }) => {
    const { city } = inputData

    const testAgent = mastra?.getAgent('testAgent')
    const stream = await testAgent?.stream(`What is the weather in ${city}?`)

    await stream!.textStream.pipeTo(writer!)

    return {
      value: await stream!.text,
    }
  },
})
```

## 重新啟動運行中的 Workflow {/* #restarting-active-workflow-runs */}

若 Workflow 運行與伺服器失去連線，可從最後一個正在執行的步驟重新啟動。這適合在伺服器斷線時可能仍在進行的長時間任務。重新啟動後，Workflow 會由該步驟恢復並繼續。

### 使用 `restartAllActiveWorkflowRuns()` 重新啟動 Workflow 的所有活躍運行 {/* #restarting-all-active-workflow-runs-of-a-workflow-with-restartallactiveworkflowruns */}

`restartAllActiveWorkflowRuns()` 可重新啟動某個 Workflow 的所有活躍運行，毋須逐一巡覽並手動重啟。

```typescript
workflow.restartAllActiveWorkflowRuns()
```

多個運行會並行重新啟動，並行上限由 `recovery.workflowConcurrency` 控制（預設 `5`）。若運行共用不能並行執行的副作用，請在 Mastra 設定中將它設為 `1`。

如要排除由 `Mastra.restartAllActiveWorkflowRuns()` 在啟動時觸發的自動重啟，請在 Workflow 的 `options` 中設定 `autoRestartActiveRuns: false`。這適用於不宜全面重新執行的有副作用 Workflow。持久化 Agent Workflow 會自動設定此選項，因為它們由選擇啟用的 `recovery.durableAgents: 'auto'` 路徑負責恢復。

運行期間，Mastra 會持有該運行的儲存租約，並在背景續期。租約尚未到期時，`restart()` 會拒絕接手、擲出 `WORKFLOW_RESTART_RUN_OWNED` 錯誤，掃描亦會略過該運行。租約只用於協調，無法阻止寫入。若程序停止續租但仍在執行步驟，例如事件循環阻塞超過租約 TTL，恢復機制可能再次執行該步驟。`workflow.restartAllActiveWorkflowRuns()` 會略過這類運行而不重新檢查；如需恢復，請等租約到期後再調用。不支援運行所有權的儲存配接器維持原有行為，會重新啟動所有活躍運行。

伺服器啟動時調用的 `mastra.restartAllActiveWorkflowRuns()`，只會在預設引擎運行已停止時重啟：沒有實例持有其租約，而且運行與租約在 `recovery.workflowGraceMs`（預設 2 秒）期間都沒有變動。仍在執行或剛停止的運行會交由[恢復循環](#recovery-loop)處理。

對於使用會重新投遞未確認事件的訊息代理（Redis Streams、Valkey Streams、Google Cloud Pub/Sub）的 pubsub，事件驅動運行由代理恢復：Worker 若在步驟中途停止，代理會把步驟事件重新投遞給另一個 Worker，啟動中的實例不會重啟該運行。排程運行是例外，因為事件仍留在觸發它的程序內，所以會由恢復機制重啟。其他 pubsub（包括預設的程序內 pubsub）會在恢復時立即重啟所有活躍的事件驅動運行。程序內 pubsub 只在單一程序內傳遞事件，因此事件驅動 Workflow 不支援多個實例共用同一儲存空間並使用它。

重啟後會再次執行中斷的步驟；即使步驟在程序停止前已完成，只要結果未儲存，仍會重跑。在事件驅動引擎中，若結果已儲存，即使步驟事件延遲到達（例如代理重新投遞，或儲存結果期間調用了 `restart()`），也不會再執行，而會從已儲存結果繼續。這需要支援運行所有權的儲存配接器。設定了 `autoRestartActiveRuns: false` 的 Workflow（包括持久化 Agent Workflow）仍會再次執行步驟。因此，有副作用的步驟應具備冪等性，避免重複執行造成額外影響。

步驟的 `execute` 函式會收到 `runId` 及 `workflowId`。把兩者與傳給 `createStep()` 的步驟 `id` 結合；若步驟有多個副作用，再加入各副作用名稱，就可建立冪等鍵。

部分步驟還需要從輸入取得冪等鍵的一部分：

- 巢狀 Workflow 在恢復或重新投遞時可能取得新的 `runId`。請把父 Workflow 的 `runId` 傳入巢狀 Workflow，並用它取代巢狀運行的 `runId`。
- `foreach` 會為每個項目各執行同一步驟一次。請把可識別該項目的 ID 加入冪等鍵。
- 循環每次迭代都會執行同一步驟。請由步驟傳回迭代編號，並在下一次迭代從輸入讀取。重複或恢復同一次迭代時，輸入相同，編號亦不變。

有關 Agent 調用的 Tool，請參閱[讓 Tool 可安全重複執行](/docs/harness/durable-agents#make-tools-safe-to-repeat)。

### 恢復循環 {/* #recovery-loop */}

`mastra.startWorkers()` 亦會在執行編排 Worker 的實例上啟動恢復循環。每隔 `recovery.workflowScanIntervalMs`（預設 60 秒，可能上下浮動五分之一），循環會按 `restartAllActiveWorkflowRuns()` 的相同規則重啟已停止的預設引擎運行。實例崩潰後，首次掃描須等租約到期（`MASTRA_AGENT_THREAD_LEASE_TTL_MS`，預設 15 秒）及經過 `recovery.workflowGraceMs`。若掃描時運行仍在寬限期內，下次掃描會在寬限期結束後執行，但不早於 1 秒後。

共用儲存配接器的實例，會透過儲存空間中的租約資料列選出一個循環領導者。只有領導者的循環會列出運行；其他循環只嘗試接任。領導者會一直留任，直到透過 `stopWorkers()` 或 `shutdown()` 交還，或在崩潰後租約到期。無論由誰領導，每個實例啟動時仍會透過 `restartAllActiveWorkflowRuns()` 重啟自己已停止的預設引擎運行。兩次啟動之間，循環只恢復領導者註冊的 Workflow；若各實例在同一儲存空間註冊不同 Workflow，其他運行須等到下次啟動。循環重啟的運行會在領導者上執行。

```typescript title="src/mastra/index.ts"
export const mastra = new Mastra({
  recovery: { workflowScanIntervalMs: 30_000 },
})
```

恢復循環不會重啟事件驅動運行。會重新投遞未確認事件的代理負責恢復這些運行；對其他 pubsub，`restartAllActiveWorkflowRuns()` 會在啟動時重啟。循環亦會略過設定 `autoRestartActiveRuns: false` 的 Workflow；未註冊其他預設引擎 Workflow 的實例不會爭取領導者租約資料列。如 `recovery.workflows` 設為 `'off'`、實例以 `workers: false` 啟動、`MASTRA_WORKERS` 過濾器不含 `orchestration`，或儲存配接器不支援運行所有權，循環都不會運作。只調用 `restartAllActiveWorkflowRuns()` 而從未調用 `startWorkers()` 的程序，亦不會運行此循環。

### 使用 `restart()` 重新啟動活躍運行 {/* #restarting-an-active-workflow-run-with-restart */}

使用 `restart()` 從最後一個進行中的步驟重新啟動活躍運行，並由該處繼續。

```typescript
const run = await workflow.createRun()

const result = await run.start({ inputData: { value: 'initial data' } })

const restartedResult = await run.restart()
```

### 識別活躍運行 {/* #identifying-active-workflow-runs */}

活躍運行的 `status` 為 `running` 或 `waiting`。可檢查 Workflow 的 `status` 確認是否活躍，再以 `active` 識別這類運行。

```typescript
const activeRuns = await workflow.listActiveWorkflowRuns()
if (activeRuns.runs.length > 0) {
  console.log(activeRuns.runs)
}
```

:::note

Mastra 伺服器啟動時，會重啟不再由任何實例執行的活躍運行；其恢復循環會持續處理預設引擎運行。

:::

## 使用 `RequestContext` {/* #using-requestcontext */}

使用 [RequestContext](/docs/server/request-context) 取得與請求相關的值，以按請求情況調整行為。

```typescript title="src/mastra/workflows/test-workflow.ts"
import { createStep } from '@mastra/core/workflows'

export type UserTier = {
  'user-tier': 'enterprise' | 'pro'
}

const step1 = createStep({
  execute: async ({ requestContext }) => {
    const userTier = requestContext.get('user-tier') as UserTier['user-tier']

    const maxResults = userTier === 'enterprise' ? 1000 : 50

    return { maxResults }
  },
})
```

詳情請參閱[請求上下文](/docs/server/request-context)。

有關具型別安全的請求上下文 Schema 驗證，請參閱 [Schema 驗證](/docs/server/request-context#schema-validation)。
