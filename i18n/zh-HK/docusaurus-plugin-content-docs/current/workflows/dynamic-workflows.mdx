# 動態 Workflow

:::beta

API 穩定前，即使主要版本號不變，亦可能有不兼容的變更。

:::

動態 Workflow 以資料描述 Workflow。定義是一份載有結構描述和步驟圖的 JSON 文件。Mastra 驗證後會將它註冊為可執行的 Workflow，並儲存定義，讓程序重啟後仍可使用。

定義不含 JavaScript 閉包，所以只要能產生 JSON，就可建立 Workflow，例如 HTTP 客戶端、LLM、視覺化編輯器或自訂工具。註冊後，動態 Workflow 與以程式碼定義的 Workflow 使用相同的執行 API。

## 何時使用動態 Workflow {/* #when-to-use-dynamic-workflows */}

如果用戶、Agent、視覺化編輯器或外部系統需要在不改動程式碼、毋須重新部署的情況下建立 Workflow，可使用動態 Workflow。

如果 Workflow 應放在應用程式原始碼內，或需要自訂步驟函數，請繼續使用 [`createWorkflow()`](/docs/workflows/overview) 定義。動態 Workflow 可呼叫已在 `Mastra` 實例註冊的 Agent、Tool 和 Workflow。

## 快速入門 {/* #quickstart */}

以下例子註冊一個 Tool，再執行會呼叫這個 Tool 的動態 Workflow。`LibSQLStore` 把定義儲存在 `mastra.db`，讓 Mastra 重新啟動後可恢復定義。

```typescript title="src/dynamic-workflow.ts"
import { Mastra } from '@mastra/core/mastra'
import { createTool } from '@mastra/core/tools'
import { LibSQLStore } from '@mastra/libsql'
import { z } from 'zod'

const greetingTool = createTool({
  id: 'create-greeting',
  description: 'Create a greeting for a name',
  inputSchema: z.object({
    name: z.string(),
  }),
  outputSchema: z.object({
    message: z.string(),
  }),
  execute: async ({ name }) => ({
    message: `Hello, ${name}!`,
  }),
})

const mastra = new Mastra({
  storage: new LibSQLStore({
    id: 'mastra-storage',
    url: 'file:./mastra.db',
  }),
  tools: { 'create-greeting': greetingTool },
})

await mastra.addDynamicWorkflow({
  id: 'greeting-workflow',
  description: 'Create a greeting for the supplied name',
  inputSchema: {
    type: 'object',
    properties: {
      name: { type: 'string' },
    },
    required: ['name'],
  },
  outputSchema: {
    type: 'object',
    properties: {
      message: { type: 'string' },
    },
    required: ['message'],
  },
  graph: [
    {
      type: 'tool',
      id: 'greet',
      toolId: 'create-greeting',
    },
  ],
})

const workflow = mastra.getWorkflow('greeting-workflow')
const run = await workflow.createRun()
const result = await run.start({
  inputData: { name: 'Ada' },
})

if (result.status === 'success') {
  console.log(result.result.message)
}
```

Workflow 會輸出 `Hello, Ada!`。[`addDynamicWorkflow()`](/reference/core/addDynamicWorkflow) 會在更改儲存內容或現行 Workflow 登記資料前驗證定義。

定義必須可轉成 JSON 再讀取，因此採用 JSON Schema。`graph` 描述會呼叫哪些已註冊的元件，以及資料如何在元件之間流動。各欄位和圖項目詳見[動態 Workflow 定義參考](/reference/workflows/dynamic-workflow-definition)。

## 建置和更新定義 {/* #build-and-update-definitions */}

可從任何能產生 JSON 的來源取得定義。例如，API 路由可接收視覺化編輯器產生的定義，再直接註冊：

```typescript
const definition = await request.json()
await mastra.addDynamicWorkflow(definition)
```

### 先註冊依賴 {/* #register-dependencies-first */}

加入動態 Workflow 前，先在同一個 `Mastra` 實例註冊所引用的元件。Agent 和巢狀 Workflow 使用本身的 ID；Tool 則使用它在 `Mastra` 的 `tools` 物件內的鍵。快速入門例子先以 `create-greeting` 註冊 Tool，再透過 `toolId` 引用該鍵。

如果某一步的輸出不符合下一步的輸入，可使用 `mapping` 項目。映射可讀取 Workflow 的輸入、先前步驟的結果、Workflow 狀態及請求上下文。支援的映射描述項見[定義參考](/reference/workflows/dynamic-workflow-definition#mapping-steps)。

### 取代 Workflow {/* #replace-a-workflow */}

加入 `id` 相同的新定義，即可取代已儲存的定義及現行的 Workflow 登記：

```typescript
await mastra.addDynamicWorkflow(updatedDefinition)
```

新執行會用更新後的步驟圖，已開始的執行則沿用原有步驟圖。

### 一併加入巢狀 Workflow {/* #add-nested-workflows-together */}

如根 Workflow 引用未註冊的輔助 Workflow，可用 [`addDynamicWorkflows()`](/reference/core/addDynamicWorkflows) 一次加入所有定義：

```typescript
await mastra.addDynamicWorkflows([rootDefinition, helperDefinition])
```

Mastra 會驗證整組定義，再按依賴關係決定註冊次序。只要驗證失敗，便不會註冊任何定義。

### 透過 HTTP 管理定義 {/* #manage-definitions-over-http */}

應用程式毋須直接存取 `Mastra` 實例，即可透過以下其中一個介面管理動態 Workflow：

- [Client SDK 的 Workflow API](/reference/client-js/workflows)：從 JavaScript 或 TypeScript 客戶端呼叫 `upsertDynamicWorkflow()`。
- [伺服器路由](/reference/server/routes)：把定義傳送至 `POST /api/stored/workflows`。

如伺服器要求身份驗證，管理動態 Workflow 需要 `stored-workflows:read` 及 `stored-workflows:write` 權限，執行已註冊的 Workflow 則需要 `workflows:execute` 權限。

### 持久儲存定義 {/* #persist-definitions */}

定義儲存在 `workflowDefinitions` 儲存域。Mastra 啟動時會載入啟用中的定義，並按依賴次序註冊。

即使沒有支援此儲存域的配接器，`addDynamicWorkflow()` 仍會在記憶體註冊 Workflow，但程序重新啟動後會失去定義。配接器的支援情況見[儲存參考](/reference/storage/overview)。
