# MCP

馬斯特拉支持[Model Context Protocol (MCP)](https://modelcontextprotocol.io/introduction)，一種用於將人工智慧Agent連接到外部Tool和資源的開放標準。

使用 [`MCPClient`](/reference/tools/mcp-client) 連接 MCP 伺服器。使用 [`MCPServer`](/reference/tools/mcp-server) 向其他兼容 MCP 的系統提供 Mastra Agent、Tool、Workflow、prompt 及 resource。兩者均透過 stdio 及 Streamable HTTP 支援 MCP `2026-07-28` 版本。

對於 [Neon](/integrations/databases/neon#connect) 及 [Canva](/integrations/other/canva) 等託管 MCP 伺服器，Mastra 平台的 [Connect](/docs/mastra-platform/connect) 可代為管理 OAuth 流程及憑證，讓 Agent 透過 [`tools()`](/reference/connect/tools#mcp-providers) 使用伺服器的 Tool，毋須手動設定 `MCPClient`。

:::note
要從 `@mastra/mcp` 1.x 升級？請參閱[遷移指南](/reference/migrations/mcp-v2)。
:::

有關憑證選擇和權限邊界，請參閱[Authentication and authorization with MCP](/docs/guides/mcp-authentication-authorization).

## 連接到 MCP 伺服器 {/* #connect-to-mcp-servers */}

安裝MCP包：

```bash npm2yarn
npm install @mastra/mcp@latest
```

使用本機命令或遠端 URL 設定每個伺服器：

```typescript title="src/mastra/mcp/client.ts"
import { MCPClient } from '@mastra/mcp'

export const mcpClient = new MCPClient({
  id: 'my-mcp-client',
  servers: {
    wikipedia: {
      command: 'npx',
      args: ['-y', 'wikipedia-mcp'],
    },
    weather: {
      url: new URL('https://weather.example.com/mcp'),
      requestInit: {
        headers: {
          Authorization: `Bearer ${process.env.WEATHER_API_KEY}`,
        },
      },
    },
  },
})
```

:::tip Authentication

對受 OAuth 保護的伺服器，使用 `authenticate()` 完成瀏覽器授權流程。設定詳情請參閱 [OAuth authentication](/reference/tools/mcp-client#oauth-authentication)。

:::

將Tool從已配置的伺服器傳遞到Agent：

```typescript {2,13} title="src/mastra/agents/assistant.ts"
import { Agent } from '@mastra/core/agent'
import { mcpClient } from '../mcp/client'

export const assistant = new Agent({
  id: 'assistant',
  name: 'Assistant',
  instructions: `
    Use the available MCP tools to answer questions.
    Include the source of any information you retrieve.
  `,
  model: '__GATEWAY_OPENAI_MODEL__',
  tools: await mcpClient.listTools(),
})
```

### 產生直接Tool呼叫的類型 {/* #generate-types-for-direct-tool-calls */}

對於設定穩定的伺服器，可從已發佈的 Tool schema 產生類型，毋須重新宣告 Tool 參數及結果。這個可選流程不影響動態發現。

指定輸出路徑匯出客戶端，並將產生的 `MCPServers` 介面傳給建構函式：

```typescript title="src/mcp/client.ts"
import { MCPClient } from '@mastra/mcp'
import type { MCPServers } from './mcp-types.generated'

export const mcp = new MCPClient<MCPServers>({
  id: 'weather-client',
  servers: { weather: { url: new URL(process.env.WEATHER_MCP_URL!) } },
  typegen: { outFile: 'src/mcp/mcp-types.generated.ts' },
})
```

在項目根目錄執行指令前，請先設定 `WEATHER_MCP_URL` 並完成所需的身份驗證設定：

```bash npm2yarn
npx @mastra/mcp generate ./src/mcp/client.ts
```

產生的檔案在第一次執行時可能不存在，因為它的匯入是僅類型的。 Generation 無需進行類型檢查即可載入 TypeScript 模組，且無需執行Tool即可列出架構。之後運行項目的類型檢查。

使用產生的參數呼叫已發現的 Tool。以下假設伺服器發佈的 `get_weather` 接受字串 `location` 及數值 `temperature`：

```typescript title="src/mcp/call-weather.ts"
import { mcp } from './client'

try {
  const tools = await mcp.listTools()
  const weather = tools.weather_get_weather
  if (weather?.execute) {
    const result = await weather.execute({ location: 'Paris' })
    if (result && 'temperature' in result && typeof result.temperature === 'number') {
      console.log(result.temperature)
    }
  }
} finally {
  await mcp.disconnect()
}
```

Tool 可能不存在；執行結果除了結構化輸出，亦可能是協定封裝、驗證錯誤或 `undefined`。使用前應先收窄結果類型。缺少輸出 schema 時，結果類型為 `unknown`。

傳遞多個顯式客戶端檔案以產生多個輸出。直接將客戶端匯出為命名或預設匯出，使用不同的輸出路徑，並在伺服器配置匹配時為獨立客戶端提供不同的 ID。輸入和輸出路徑從命令的工作目錄解析。同一客戶端的重複匯出均處理一次。

發現失敗會使現有文件保持不變，模式問題產生也無法解決，例如引用循環、深度過大或未解析的本地引用。文件替換是每個文件的原子操作，而不是整個集合的操作。當伺服器架構變更時，使用等效權限重新產生。在生成之前，請自行提供憑證並載入任何環境檔案。導入客戶端會執行其模組和傳遞導入，因此選擇沒有應用程式啟動副作用的檔案。互動式身分驗證不是命令的一部分。

匯出選擇、實例快取、schema 限制及失敗處理請參閱[類型產生參考](/reference/tools/mcp-client#generate-client-types)。

### 靜態和運行時Tool {/* #static-and-runtime-tools */}

根據伺服器配置是否在請求之間發生變化來選擇如何載入Tool：

| |靜態Tool|執行時間Tool集 |
| :- | :- | :- |
|方法|`await mcpClient.listTools()` | `await mcpClient.listToolsets()` |
| Use case | Shared, fixed configuration | Per-user or per-request configuration |
| 憑證 | 所有請求共用 | 可按請求變更 |
| Agent API | 在 `Agent` 建構函式使用 `tools` | 在 `generate()` 或 `stream()` 使用 `toolsets` |
| Tool 名稱 | 加上伺服器名稱前綴，例如 `weather_get_weather` | 原始 Tool 名稱。不同伺服器的同名 Tool 會衝突。請參閱 [`listToolsets()`](/reference/tools/mcp-client#listtoolsets)。 |

前面的Agent範例使用靜態Tool。對於運行時憑證，為請求建立客戶端並在呼叫Agent時傳遞其Tool集：

```typescript {5-16,21} title="src/handle-request.ts"
import { MCPClient } from '@mastra/mcp'
import { mastra } from './mastra'

export async function handleRequest(prompt: string, apiKey: string) {
  const userMcpClient = new MCPClient({
    servers: {
      weather: {
        url: new URL('https://weather.example.com/mcp'),
        requestInit: {
          headers: { Authorization: `Bearer ${apiKey}` },
        },
      },
    },
  })

  const agent = mastra.getAgent('assistant')
  const response = await agent.generate(prompt, {
    toolsets: await userMcpClient.listToolsets(),
  })

  await userMcpClient.disconnect()
  return response.text
}
```

完整 API 請參閱 [`listTools()`](/reference/tools/mcp-client#listtools) 及 [`listToolsets()`](/reference/tools/mcp-client#listtoolsets)。

此例會在單次請求內完成。如 Agent 工作須在請求結束後繼續，或在程序重啟後恢復，應使用[持久化 Agent](/docs/harness/durable-agents) 或[背景工作](/docs/harness/background-tasks)，毋須自行實作工作追蹤。呼叫時傳入的 `toolsets` 無法移至其他程序。因此對持久化 Agent，應在 Agent 的 `tools` 函式中按[請求上下文](/docs/server/request-context)載入每次請求的 MCP Tool。

### Tool審批 {/* #tool-approval */}

在伺服器設定 `requireToolApproval`，要求其所有 Tool 都經過審批：

```typescript
const mcpClient = new MCPClient({
  servers: {
    github: {
      url: new URL('https://github.example.com/mcp'),
      requireToolApproval: true,
    },
  },
})
```

您也可以提供一個根據Tool名稱、參數或註解進行決定的函數：

```typescript
requireToolApproval: ({ toolName }) => toolName.startsWith('delete_')
```

對於不受你控制的伺服器，其 Tool annotation 只能視為不可信的提示。回呼上下文及安全指引請參閱 [Tool approval](/reference/tools/mcp-client#tool-approval)。

### 安全 {/* #security */}

MCP 伺服器代表您的Agent運行程式碼並傳回內容，因此請像任何其他外部相依性一樣謹慎地配置它們：

- **Stdio 子程序環境**：子程序只會繼承 MCP SDK 篩選後的環境變數允許清單（例如 POSIX 的 `PATH` 及 `HOME`），不會繼承父程序的完整環境。在伺服器設定 `inheritDefaultEnv: false`，便只會傳遞 `env` 列出的變數。
- **對外連線主機限制**：如 HTTP 伺服器 URL 來自不可信設定，請設定 `allowedHosts`，限制客戶端可連線的主機。預設 fetch 路徑會在發送前攔截重新導向；自訂 `fetch` 僅在請求發出後按最終回應 URL 驗證，因此如須阻止對外連線，必須自行執行重新導向政策。
- **Tool 回應的可信度**：Tool 結果是傳給模型的不可信輸入。使用[輸入及輸出處理器](/docs/agents/processors)在內容送達模型前進行清理，並對敏感 Tool 設定 `requireToolApproval`。

各選項的執行詳情請參閱 [MCPClient 安全參考](/reference/tools/mcp-client#security)。

|登記處 |連線|筆記|

## 公開 Mastra MCP 伺服器 {/* #expose-a-mastra-mcp-server */}

建立 `MCPServer`，向外部 MCP 客戶端提供 Mastra 元件：

```typescript title="src/mastra/mcp/server.ts"
import { MCPServer } from '@mastra/mcp'
import { assistant } from '../agents/assistant'
import { weatherTool } from '../tools/weather'
import { weatherWorkflow } from '../workflows/weather'

export const mcpServer = new MCPServer({
  id: 'my-mcp-server',
  name: 'My MCP Server',
  version: '1.0.0',
  agents: { assistant },
  tools: { weatherTool },
  workflows: { weatherWorkflow },
})
```

在主要的 `Mastra` 實例上註冊伺服器：

```typescript title="src/mastra/index.ts"
import { Mastra } from '@mastra/core/mastra'
import { mcpServer } from './mcp/server'

export const mastra = new Mastra({
  mcpServers: { mcpServer },
})
```

:::tip Authentication

以 OAuth 中介軟件保護 HTTP MCP 伺服器。設定方法請參閱 [OAuth protection](/reference/tools/mcp-server#oauth-protection)。

:::

已註冊的伺服器會透過 Streamable HTTP 在 `/api/mcp/:serverId/mcp` 提供服務。每項請求均獨立完整，因此同一伺服器可原樣運行於常駐主機及 serverless 平台。

如 Tool 完成前需要用戶輸入，可帶著 payload 呼叫 `context.suspend()` 並宣告 `resumeSchema`。伺服器會將其轉成一次 `input_required` 往返，收到答案後以 `context.resumeData` 再次運行 Tool。客戶端透過伺服器定義中的 `inputRequests` 處理程式回應。請參閱[向呼叫者要求輸入](/reference/tools/mcp-server#asking-the-caller-for-input)及[回應輸入請求](/reference/tools/mcp-client#answering-input-requests)。

prompt、resource、transport 及其他伺服器選項請參閱 [`MCPServer` 參考](/reference/tools/mcp-server)。

如要在不定義伺服器的情況下提供 Mastra 應用程式的所有 Agent、Workflow 及 Tool，可使用 `/api/mcp` 的[內置 MCP 伺服器](/docs/server/mcp)。

### 發布stdio伺服器包 {/* #publish-a-stdio-server-package */}

如希望客戶端透過 `npx` 等指令在本機運行伺服器，請將使用標準輸入／輸出（stdio）傳輸的伺服器打包。建立獨立的可執行入口來啟動伺服器：

```typescript title="src/mastra/mcp/stdio.ts"
#!/usr/bin/env node
import { mcpServer } from './server'

mcpServer.startStdio().catch(error => {
  console.error('Failed to start MCP server:', error)
  process.exit(1)
})
```

將入口構建為可執行的 Node.js 檔案，再讓套件的 `bin` 欄位指向該輸出。發佈套件時須包含該檔案，並保留 shebang 作為首行：

```json title="package.json"
{
  "bin": {
    "my-mcp-server": "dist/stdio.js"
  },
  "files": ["dist"]
}
```

發布包後，配置客戶端以按包名稱運行它：

```typescript title="src/mastra/mcp/client.ts"
import { MCPClient } from '@mastra/mcp'

const mcpClient = new MCPClient({
  servers: {
    myServer: {
      command: 'npx',
      args: ['-y', '@your-org/my-mcp-server@1.0.0'],
    },
  },
})
```

套件命名、身份驗證及發佈指令請參閱 [npm 套件發佈文件](https://docs.npmjs.com/creating-and-publishing-scoped-public-packages)。

## 建立 MCP 應用程式 {/* #build-mcp-apps */}

[MCP Apps 擴充功能](https://github.com/modelcontextprotocol/ext-apps)讓 MCP Tool 透過 `ui://` resource 提供互動式 HTML 介面。Mastra Studio 會在 Tool 頁面及 Agent 聊天中，以沙盒 iframe 顯示這些應用程式。

當Tool結果受益於互動（例如表單、計算器、顏色選擇器或資料視覺化）時，請使用 MCP 應用程式。

### 定義應用程式資源 {/* #define-an-app-resource */}

在 `content` 傳回供模型閱讀的簡短摘要，並將 UI 數據放入 `structuredContent`。將 `mcp._meta.ui.resourceUri` 設為 `appResources` 中相同的 `ui://` URI，讓 Tool 連結至應用程式：

```typescript title="src/mastra/mcp/calculator.ts"
import { MCPServer } from '@mastra/mcp'
import { createTool } from '@mastra/core/tools'
import { z } from 'zod'

const calculatorTool = createTool({
  id: 'calculatorWithUI',
  description: 'Calculate the sum of two numbers',
  inputSchema: z.object({ num1: z.number(), num2: z.number() }),
  mcp: { _meta: { ui: { resourceUri: 'ui://calculator/main' } } },
  execute: async ({ num1, num2 }) => ({
    content: [{ type: 'text', text: 'The result is displayed in the calculator app.' }],
    structuredContent: { result: num1 + num2 },
  }),
})

const calculatorMcpServer = new MCPServer({
  id: 'calculator-app-server',
  name: 'Calculator App Server',
  version: '1.0.0',
  tools: { calculatorTool },
  appResources: {
    'ui://calculator/main': { name: 'Calculator', htmlPath: './src/mastra/mcp/calculator.html' },
  },
})
```

模型讀取 `content`，應用程式接收 `structuredContent`。內嵌 HTML、檔案路徑、元數據及內容安全政策選項請參閱 [`appResources`](/reference/tools/mcp-server#mcp-apps-appresources)。

### 將應用程式連接到 Studio {/* #connect-the-app-to-studio */}

在 HTML resource 中使用 `@modelcontextprotocol/ext-apps` 的 `App` 類別。呼叫 `connect()` 前先註冊事件處理程式：

```html title="src/mastra/mcp/calculator.html"
<!doctype html>
<html>
  <body>
    <p id="result">Waiting for input</p>
    <button id="recalculate">Recalculate</button>

    <script type="module">
      import { App } from 'https://cdn.jsdelivr.net/npm/@modelcontextprotocol/ext-apps/+esm'

      const app = new App({ name: 'Calculator', version: '1.0.0' })
      let toolInput

      app.ontoolinput = params => {
        toolInput = params.arguments
      }

      document.querySelector('#recalculate').addEventListener('click', async () => {
        const result = await app.callServerTool({
          name: 'calculatorWithUI',
          arguments: toolInput,
        })
        document.querySelector('#result').textContent = JSON.stringify(result)
      })

      await app.connect()
    </script>
  </body>
</html>
```

訪客端 API 服務於互動的不同部分：

|應用程式介面 |目的|
| :- | :- |
| `app.ontoolinput` | 接收主機 Tool 呼叫的參數 |
| `app.callServerTool()` | 從 iframe 內呼叫 MCP Tool |
| `app.sendMessage()` | 在聊天中加入用戶訊息，並開始新一輪模型運行 |
| `app.connect()` | 註冊事件處理程式後連接主機 |

所有應用程式端方法及生命週期鉤子請參閱外部 [`App` API 參考](https://apps.extensions.modelcontextprotocol.io/api/classes/app.App.html)。

### 註冊 MCP 應用程式 {/* #register-mcp-apps */}

按照[提供 Mastra MCP 伺服器](#expose-a-mastra-mcp-server)的方式將伺服器註冊到 `Mastra`，並將 Tool 提供予需要顯示應用程式的 Agent。

對於實現 MCP Apps 的外部 MCP 伺服器，使用 `MCPClient.listTools()` 載入其 Tool 並註冊代理，讓 Studio 可解析遠端應用程式 resource：

```typescript title="src/mastra/remote-apps.ts"
import { Agent } from '@mastra/core/agent'
import { Mastra } from '@mastra/core/mastra'
import { mcpClient } from './mcp/client'

const tools = await mcpClient.listTools()
const mcpServers = mcpClient.toMCPServerProxies()

const agent = new Agent({
  id: 'remote-app-agent',
  name: 'Remote App Agent',
  instructions: 'Use the available remote tools.',
  model: '__GATEWAY_OPENAI_MODEL_LUNA__',
  tools,
})

export const mastra = new Mastra({
  agents: { agent },
  mcpServers,
})
```

透過 `listTools()` 載入的 Tool 會在 `_meta.ui` 包含 `serverId`，讓 Studio 毋須掃描所有伺服器就可解析各應用程式 resource。代理設定詳情請參閱 [`toMCPServerProxies()`](/reference/tools/mcp-client#tomcpserverproxies)。

### 沙箱安全 {/* #sandbox-security */}

Mastra Studio 使用 [`@mcp-ui/client`](https://www.npmjs.com/package/@mcp-ui/client)，透過沙盒代理載入應用程式 HTML，並以 `postMessage` 進行 JSON-RPC 通訊。

應用程式 iframe 允許腳本、表單和彈出視窗。他們無法存取父頁面的 DOM、cookie 或儲存。主機控制與訪客應用程式的所有通訊。

## MCP 活動 {/* #mcp-events */}

MCP 事件讓用戶端在伺服器上發生某些情況（例如開啟票證或建置完成）時做出反應，而不是按計畫呼叫Tool進行檢查。伺服器聲明事件類型，客戶端使用參數訂閱，伺服器透過與其Tool相同的 stdio 或 Streamable HTTP 傳輸傳遞每個符合的事件。

:::warning
MCP 事件實現了 MCP 擴充功能草案 [SEP-3415](https://github.com/modelcontextprotocol/modelcontextprotocol/pull/3415)。傳輸格式及 Mastra API 仍屬實驗性功能，任何版本都可能改動。
:::

- **訂閱：** 客戶端針對一種事件類型提出一次請求，可帶 `{ project: 'web' }` 等參數。伺服器只傳送符合條件的事件。
- **事件實例：** 一次傳送的事件，包含 `eventId`、`name`、`timestamp` 及 `data`。傳送保證至少一次；客戶端會在近期 ID 的 `dedupWindow` 範圍內按 `eventId` 去重。處理程式仍須容忍重複事件。
- **游標：** 事件序列中的不透明位置。儲存後可在下次訂閱時從該處接續。重播只涵蓋來源保留的歷史。`emit()` 來源只在單一程序緩衝，因此重啟或由另一實例處理訂閱都可能漏掉事件；持久重播須使用共用儲存支援的 `poll` 來源。

### 發布活動 {/* #publish-events */}

在 `MCPServer` 的 `events` 選項中以 `defineEvent()` 宣告各類型，再以 `server.events.emit()` 發佈事件實例：

```typescript title="src/mastra/mcp/tickets.ts"
import { createTool } from '@mastra/core/tools'
import { MCPServer, defineEvent } from '@mastra/mcp'
import { z } from 'zod'

const ticket = z.object({ id: z.string(), project: z.string(), title: z.string() })

const server: MCPServer = new MCPServer({
  id: 'tickets',
  name: 'Tickets',
  version: '1.0.0',
  tools: {
    openTicket: createTool({
      id: 'openTicket',
      description: 'Opens a support ticket',
      inputSchema: ticket,
      execute: async input => server.events.emit('ticket.created', input),
    }),
  },
  events: {
    'ticket.created': defineEvent({
      description: 'A support ticket was opened',
      inputSchema: z.object({ project: z.string() }),
      payloadSchema: ticket,
      match: (args, data) => data.project === args.project,
    }),
  },
})
```

例子使用 [`startHTTP()`](/reference/tools/mcp-server#starthttp)，透過 HTTP 在 `http://localhost:4111/mcp` 提供此伺服器。

`match` 決定哪些訂閱會收到事件實例。它按客戶端自行選擇的參數篩選，無法控制誰有權訂閱；應加入 `authorize` 限制呼叫者。此授權函式 會在每次輪詢及開啟訂閱時執行，傳回 `false` 就拒絕請求。事件類型可從 `server.events.emit()` 取得事件實例，由單一程序的緩衝區同時提供 push 及 poll；亦可使用讀取外部系統的 `poll` 函式，但後者只支援 poll。

### 訂閱活動 {/* #subscribe-to-events */}

先以 `mcp.events.list()` 列出伺服器提供的事件類型，再以 `mcp.events.subscribe()` 訂閱。傳回的訂閱是事件實例的非同步可迭代物件：

```typescript title="src/mastra/mcp/client.ts"
import { MCPClient } from '@mastra/mcp'

const mcp = new MCPClient({ servers: { tickets: { url: new URL('http://localhost:4111/mcp') } } })

const eventTypes = await mcp.events.list('tickets')
const subscription = await mcp.events.subscribe('tickets', 'ticket.created', { project: 'web' })

for await (const event of subscription) {
  console.log(event.eventId, event.data)
  if (subscription.cursor) await saveCursor('tickets:web', subscription.cursor)
}
```

伺服器接受訂閱後，`subscribe()` 即完成。新訂閱由目前時間開始；傳入 `options.cursor` 可從已儲存的位置接續。客戶端會按以下次序選擇事件提供的首個可用模式：客戶端設定了 `webhook` 時先選 `webhook`，然後是 `push`，最後是 `poll`。連線中斷後，客戶端會自行重新開啟串流。

### 從事件開始運行 {/* #start-runs-from-events */}

在循環中訂閱事件，每收到一個事件實例就啟動一次 Agent run 或 Workflow run。事件來自伺服器，因此應將 `event.data` 當作數據而非指令傳入，並在處理每個事件後儲存 `subscription.cursor`。循環一次只處理一個事件，運行緩慢的 run 會延遲下一個事件。如順序不重要，可不等待就啟動多個 run，但須等所有較早啟動的 run 完成後再儲存游標，否則程序當機時仍在運行的事件會遺失。

使用 push 或 webhook 傳送時，客戶端會緩衝循環尚未讀取的事件實例。如循環落後超過 `maxBufferedEvents`，最舊的事件會遺失，並回報 `MCP_EVENTS_BUFFER_OVERFLOW`。如想將事件作為通知送到 Agent thread，而非自行編寫循環，可使用 [`MCPEventsSignalProvider`](/reference/tools/mcp-client#events-in-agents-and-workflows-experimental)。

如伺服器位於遠端，而應用程式已提供 HTTP 服務，可改用 webhook 傳送：分別在伺服器的 `eventsOptions` 啟用 `webhook`，客戶端亦啟用 `webhook`，每個事件實例都會以 POST 請求送達端點。傳送模式、錯誤碼、緩衝、重試及 `poll` 來源例子請參閱 [`MCPServer` 事件參考](/reference/tools/mcp-server#events-experimental)及 [`MCPClient` 事件參考](/reference/tools/mcp-client#events-property-experimental)。[MCP 事件例子](https://github.com/mastra-ai/mastra/tree/main/examples/mcp-events)示範 Agent 流程如何與本機 stdio 伺服器端對端運行。
