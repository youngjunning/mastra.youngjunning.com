# A2A (Agent-to-Agent)

Mastra 支援 [Agent-to-Agent (A2A) 協定](https://a2a-protocol.org/latest/) 0.3.0 版，供跨平台多 Agent 系統使用。透過 A2A，可以把 Mastra Agent 開放為遠端 Agent，或將遠端 A2A Agent 用作 Mastra 子 Agent；亦可使用 JavaScript 客戶端 SDK 調用 A2A 端點。

A2A 是開放協定，讓系統跨網絡、框架、供應商和程式語言邊界，把工作委託給 Agent。遠端 Agent 可保留自己的工具、提示詞、記憶、Workflow 及基礎設施，不對外公開，只提供其他系統可以探索和調用的協定端點。

## 何時使用 A2A {/* #when-to-use-a2a */}

- 上層 Agent 需要把工作委託給專門的遠端 Agent。
- 遠端 Agent 由其他服務、團隊、供應商或執行環境管理。
- 後端、瀏覽器應用程式或其他兼容 A2A 的系統，需要以程式方式存取 Mastra Agent。
- 長時間運行的遠端工作需要任務 ID、狀態更新、產出物、取消操作、重新訂閱或推送通知。

## A2A 的運作方式 {/* #how-a2a-works */}

A2A 透過 Agent 卡片進行探索。卡片是一份由約定的公開 URL 提供的 JSON 文件，描述遠端 Agent，並載有接收 A2A JSON-RPC 請求的執行 URL。

Mastra Server 的 `apiPrefix` 採用預設值 `/api` 時，註冊為 `weather-agent` 的 Agent 會開放：

- Agent 卡片：`/api/.well-known/weather-agent/agent-card.json`
- 執行端點：`/api/a2a/weather-agent`

Agent 卡片包含名稱、描述、端點 URL、提供者、功能、保安中繼資料和技能等欄位：

```json title="agent-card.json"
{
  "protocolVersion": "0.3.0",
  "name": "Weather Agent",
  "description": "Provides weather information.",
  "url": "https://agent.example.com/api/a2a/weather-agent",
  "version": "1.0",
  "provider": {
    "organization": "Acme",
    "url": "https://acme.example.com"
  },
  "capabilities": {
    "streaming": true,
    "pushNotifications": true,
    "stateTransitionHistory": false
  },
  "defaultInputModes": ["text/plain"],
  "defaultOutputModes": ["text/plain"],
  "skills": [
    {
      "id": "weather",
      "name": "weather",
      "description": "Gets weather conditions for a location.",
      "tags": ["tool"]
    }
  ]
}
```

A2A 以訊息和任務表示工作。訊息可以包含文字、檔案或結構化資料片段。

任務是具有 ID 及生命週期狀態的有狀態工作單位。客戶端可以追蹤長時間運行的工作，並傳送後續對話，也可以取消工作或在斷線後重新訂閱。

## 協議版本 {/* #protocol-versions */}

Mastra 在同一張 Agent 卡片及執行 URL 上支援 A2A 協定 v0.3 和 v1.0。`A2A-Version` 請求標頭決定採用哪個傳輸協定版本：

- 缺少、留空或為 `0.3`：使用原有的 v0.3 API。
* `1.0`：使用 v1.0 API。
- 其他值：返回 `VersionNotSupported` 協定錯誤。

`A2AAgent` 和 `MastraClient.getA2A()` 預設使用 v0.3。要以 v1.0 委託子 Agent，請為 `A2AAgent` 設定 `protocolVersion: '1.0'`；要直接發出 v1.0 請求，則使用 `MastraClient.getA2AV1()`。兩種 v1.0 客戶端均會自動傳送 `A2A-Version: 1.0`。直接調用的 v1.0 客戶端亦新增 `tasks/list` 操作。

v1.0 協定類型和編解碼器可從 `@mastra/core/a2a/v1` 匯入。現有的 `@mastra/core/a2a/client` 匯出仍採用 v0.3。

## 開始使用 {/* #get-started */}

A2A 在 Mastra 中有兩條常見路徑：

- 使用 `A2AAgent`，把遠端 A2A Agent 用作 Mastra 子 Agent。
- 使用 `MastraClient.getA2A()`，向 Mastra A2A 端點發出請求。

當另一個 Mastra Agent 需要把工作委託給遠端 Agent，使用 `A2AAgent`。當應用程式程式碼需要直接調用已啟用 A2A 的 Mastra 端點，使用客戶端 SDK。

## 把 A2A Agent 用作子 Agent {/* #consume-a2a-agents-as-subagents */}

使用 `A2AAgent` 包裝遠端 A2A Agent，再按照[監督型 Agent](/docs/subagents) 模式，把它加入上層 Agent。若遠端伺服器託管多個 Agent，或使用自訂的公開探索路徑，須明確傳入 Agent 卡片 URL。遠端 Agent 要求 A2A v1.0 時，設定 `protocolVersion: '1.0'`；省略則使用 v0.3。

```typescript title="src/mastra/agents/support-agent.ts"
import { Agent } from '@mastra/core/agent'
import { A2AAgent } from '@mastra/core/a2a'

const remoteWeatherAgent = new A2AAgent({
  url: 'https://weather.example.com/api/.well-known/weather-agent/agent-card.json',
  protocolVersion: '1.0',
  headers: {
    Authorization: `Bearer ${process.env.WEATHER_AGENT_TOKEN}`,
  },
})

export const supportAgent = new Agent({
  id: 'support-agent',
  name: 'Support Agent',
  instructions: 'Answer user questions and delegate weather questions when needed.',
  model: '__GATEWAY_OPENAI_MODEL__',
  agents: {
    remoteWeatherAgent,
  },
})
```

如果 `url` 指向網域，`A2AAgent` 會從 `/.well-known/agent-card.json` 取得 Agent 卡片。採用這條探索路徑的單 Agent 伺服器可使用網域 URL；多 Agent 伺服器則須提供完整卡片 URL，例如 `https://agent.example.com/api/.well-known/weather-agent/agent-card.json`。

執行期間，`A2AAgent` 會：

- 取得並快取遠端 Agent 卡片。
- 從卡片讀取執行 URL 和功能。
- 在 v0.3 調用 `message/send` 或 `message/stream`；在 v1.0 調用 `SendMessage` 或 `SendStreamingMessage`。
- 把遠端訊息、任務、產出物和狀態更新轉成 Mastra 子 Agent 的結果。
- 遠端任務需要後續輸入或重新訂閱時，支援 `resumeGenerate()` 及 `resumeStream()`。

若遠端卡片沒有聲明支援串流，`A2AAgent.stream()` 會改用非串流的 generate 路徑，並返回已緩衝的串流結果。

## 使用客戶端 SDK 發送請求 {/* #send-requests-with-the-client-sdk */}

應用程式程式碼需要調用已啟用 A2A 的 Mastra Agent 時，使用 `MastraClient.getA2A()`。把 `baseUrl` 設為伺服器來源；若伺服器不使用預設的 `/api` 前綴，亦須設定 `apiPrefix`。

```typescript title="src/a2a-client.ts"
import { MastraClient } from '@mastra/client-js'

const client = new MastraClient({
  baseUrl: 'https://agent.example.com',
  headers: {
    Authorization: `Bearer ${process.env.AGENT_API_TOKEN}`,
  },
})

const a2a = client.getA2A('weather-agent')
const card = await a2a.getAgentCard()

console.log(card.name, card.capabilities)
```

使用 `sendMessageStream()` 傳送訊息，並透過伺服器傳送事件 (SSE) 接收任務狀態及產出物更新：

```typescript title="src/a2a-client.ts" oxfmt:false
const stream = a2a.sendMessageStream({
  message: {
    kind: 'message',
    role: 'user',
    messageId: crypto.randomUUID(),
    parts: [{ kind: 'text', text: "What's the weather in Prague?" }],
  },
})

for await (const event of stream) {
  if (event.kind === 'artifact-update') {
    console.log(event.artifact.parts)
  }
}
```

若任務仍在執行而串流連線中斷，可用 `resubscribeTask()` 繼續接收即時更新：

```typescript title="src/a2a-client.ts" oxfmt:false
const updates = a2a.resubscribeTask({
  id: 'task-123',
})

for await (const event of updates) {
  console.log(event)
}
```

### 使用 v1.0 客戶端 {/* #use-the-v10-client */}

使用 `getA2AV1()` 選用 A2A v1.0 傳輸協定。協定套件提供編解碼器，可由 JSON 格式輸入建立 v1 請求值：

```typescript title="src/a2a-v1-client.ts"
import { ListTasksRequest } from '@mastra/core/a2a/v1'
import { MastraClient } from '@mastra/client-js'

const client = new MastraClient({
  baseUrl: 'https://agent.example.com',
})

const a2a = client.getA2AV1('weather-agent')
const response = await a2a.listTasks(
  ListTasksRequest.fromJSON({
    contextId: 'customer-support',
    pageSize: 20,
  }),
)

for (const task of response.tasks) {
  console.log(task.id, task.status)
}
```

v1.0 客戶端支援 `getAgentCard()`、`sendMessage()`、`sendMessageStream()`、`getTask()`、`listTasks()`、`cancelTask()` 及 `resubscribeTask()`。

## 配置子 Agent 調用 {/* #configure-subagent-calls */}

`A2AAgent` 接受供需身分驗證或受限環境使用的請求選項：

```typescript title="src/mastra/agents/support-agent.ts"
import { A2AAgent } from '@mastra/core/a2a'

const remoteWeatherAgent = new A2AAgent({
  url: 'https://weather.example.com/api/.well-known/weather-agent/agent-card.json',
  headers: {
    Authorization: `Bearer ${process.env.WEATHER_AGENT_TOKEN}`,
  },
  retries: 2,
  backoffMs: 250,
  maxBackoffMs: 1000,
  timeoutMs: 30_000,
})
```

執行環境需要自訂 fetch 行為或取消請求時，亦可傳入 `credentials`、`fetch` 及 `abortSignal`。

## 人工參與流程 {/* #human-in-the-loop */}

A2A 以 `input-required` 任務狀態表示人工參與 (HITL) 的工作。任務暫停等待輸入時，客戶端以相同 `taskId` 傳送後續訊息，補上所需輸入，伺服器便會繼續執行。

Mastra 在伺服器端及客戶端，均把 Agent 的暫停機制對應至此狀態：

- **作為伺服器**：開放的 Agent 暫停時，任務會轉為 `input-required`。這包括因[工具審批](/docs/agents/human-in-the-loop)或工具調用 `suspend()` 而暫停。任務狀態訊息包含文字提示，以及帶有結構化 `suspendPayload` 和 `resumeSchema` 的資料片段。以相同 `taskId` 發出後續 `message/send` 或 `message/stream` 請求，即可用提供的輸入恢復執行。
- **作為客戶端**：遠端任務進入 `input-required` 或 `auth-required` 時，`A2AAgent` 會返回暫停結果，內含 `finishReason: 'suspended'` 和 `suspendPayload`。調用 `resumeGenerate()` 或 `resumeStream()`，即可用原本的 `taskId` 把輸入或憑證傳回遠端任務。

```typescript title="src/a2a-hitl.ts"
import { A2AAgent } from '@mastra/core/a2a'

const agent = new A2AAgent({
  url: 'https://agent.example.com/api/.well-known/booking-agent/agent-card.json',
})

const result = await agent.generate('Book a flight to Paris', { runId: 'run-1' })

if (result.finishReason === 'suspended') {
  // Inspect result.suspendPayload, collect input from a human,
  // then resume the remote task.
  const resumed = await agent.resumeGenerate({ approved: true }, { runId: 'run-1' })
  console.log(resumed.text)
}
```

對 `input-required` 任務，後續訊息可以用結構化資料片段攜帶恢復資料，亦可在文字片段中使用 JSON 或純文字。

若恢復執行後仍需要額外輸入，任務會再次進入 `input-required`，重複上述流程。要跨請求恢復暫停的執行，Mastra 伺服器須配置儲存空間，才能還原暫停狀態。

:::note
A2A 任務紀錄存於記憶體，因此只有暫停該任務的同一個伺服器進程可以恢復。伺服器重新啟動，或水平擴展部署未配置固定路由，都會令任務紀錄遺失；後續訊息將因找不到任務而失敗。
:::

## 推播通知 {/* #push-notifications */}

對聲明 `capabilities.pushNotifications` 的遠端 Agent，Mastra 支援 A2A 推送通知。客戶端無法維持串流連線，或長時間運行的任務需要在原有請求結束後更新回調 URL 時，可以使用推送通知。

用戶端取得任務 ID 後，可以為該任務註冊回呼 URL：

```typescript title="src/a2a-client.ts"
await a2a.setTaskPushNotificationConfig({
  taskId: 'task-123',
  pushNotificationConfig: {
    url: 'https://app.example.com/a2a/tasks',
    token: process.env.A2A_WEBHOOK_TOKEN,
  },
})
```

任務進入 `completed`、`failed`、`canceled`、`rejected`、`input-required` 或 `auth-required` 狀態時，Mastra Server 會把當前任務快照發送到已註冊的回調。推送通知只作盡力傳送。應保護回調 URL、驗證通知權杖，並避免將內部網絡位址設為推送目的地。

推播通知配置儲存在記憶體中，伺服器重新啟動後必須重新註冊。

## 簽署及驗證 Agent 卡片 {/* #sign-and-verify-agent-cards */}

Mastra 支援為 A2A Agent 卡片簽署，讓客戶端核實找到的卡片來自可信發布者，並且在傳送途中未被修改。應在開放遠端 Agent 的 Mastra 伺服器上配置簽署：

```typescript title="src/mastra/index.ts"
import { Mastra } from '@mastra/core/mastra'

export const mastra = new Mastra({
  server: {
    a2a: {
      agentCardSigning: {
        privateKey: process.env.A2A_AGENT_CARD_PRIVATE_KEY!,
        protectedHeader: {
          alg: 'ES256',
          kid: 'agent-card-key',
        },
      },
    },
  },
})
```

配置簽署後，Mastra 會在 Agent 卡片中加入 `signatures` 陣列。客戶端驗證須自行啟用；未簽署的卡片仍會原樣返回。

使用 `MastraClient.getA2A()` 驗證已簽署的卡片：

```typescript title="src/a2a-client.ts"
const card = await a2a.getAgentCard({
  verifySignature: {
    algorithms: ['ES256'],
    keyProvider: async ({ kid, jku }) => {
      return fetchTrustedPublicJwk({ kid, jku })
    },
  },
})

if (!card.signatures?.length) {
  throw new Error('Expected a signed A2A agent card.')
}
```

若客戶端須在調用遠端 Agent 前核實可信密鑰，應在客戶端驗證簽名。

## 驗證子 Agent 卡片 {/* #verify-subagent-cards */}

當上層 Agent 須在委託工作前驗證遠端 Agent，使用 `verifyAgentCard`。驗證掛鈎會收到已取得的 Agent 卡片，以及取得位置和時間的相關資料。

```typescript title="src/mastra/agents/support-agent.ts"
import { A2AAgent } from '@mastra/core/a2a'

const remoteWeatherAgent = new A2AAgent({
  url: 'https://weather.example.com/api/.well-known/weather-agent/agent-card.json',
  verifyAgentCard: {
    verify: async (card, context) => {
      if (card.provider?.organization !== 'Weather Inc') {
        throw new Error(`Unexpected provider for ${context.cardUrl}`)
      }
    },
  },
})
```

上層 Agent 委託工作前，可透過此掛鈎檢查預期的提供者、端點、綁定證書的身分、已簽署卡片或其他信任要求。
