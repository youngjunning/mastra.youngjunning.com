# 知識

Studio 的知識頁面顯示您的Agent商所了解的內容：每個範圍和頁面、它們如何連結以及誰寫了什麼。使用它來檢查您載入的內容並觀察Agent程式的編輯情況。它是唯讀的。

：：：阿爾法

知識處於阿爾法階段。其 API 可能會在不同版本之間變更。

:::

## 啟用路由 {/* #enable-the-routes */}

知識路線是**off by default**. Until you enable them, Studio's Knowledge page says browsing isn't enabled. Register the Knowledge instance on `Mastra` and add the routes:

```typescript title="src/mastra/index.ts"
import { Mastra } from '@mastra/core/mastra'
import { KNOWLEDGE_ROUTES } from '@mastra/server/server-adapter'
import { knowledge } from './knowledge'
import { supportAgent } from './agents/support-agent'

export const mastra = new Mastra({
  agents: { supportAgent },
  knowledge: { company: knowledge },
  server: { apiRoutes: [...KNOWLEDGE_ROUTES] },
})
```

路由掛載在伺服器的 API 前綴下，`/api/knowledge` by default, and need `@mastra/core` 1.81.0 or later. With 1.81.0, Studio counts links only among the pages it has loaded. [Server routes](/reference/server/routes#knowledge) lists each route, its parameters and its errors.

## 你所看到的 {/* #what-you-see */}

* **樹**：每個範圍及其內部的頁面，都按照您的Agent商組織它們的方式嵌套。
* **圖形**：相同的頁面以及它們的連接方式。行顯示每個頁面的父頁面、其註釋提到的頁面、其正文中寫入的連結以及哪些範圍授予對哪些頁面的存取權限。每種線都有一個圖例命名。在任一視圖中選擇一個頁面將其開啟。
* **頁**：正文、版本和最後更新者、其作者註釋、其子頁面、其他頁面上提及它的註釋以及它的固定物件。
* **活動**：每個頁面的創建、編輯、移動、合併、註釋和固定的歷史記錄，以及每個頁面的作者和時間。
* **搜尋**：頁面名稱、描述、正文和註釋文字。

在窄螢幕上，樹和圖表共享一個面板，並在它們之間切換以保留所選頁面。

當Agent寫入時，樹、圖和開啟的頁面會立即更新，而無需重新載入。 Studio 追蹤透過向 Mastra 註冊的 Knowledge 實例進行的寫入。來自同一儲存體上的另一個進程或另一個實例的寫入會在重新載入後顯示。

## 控制誰看到什麼 {/* #control-who-sees-what */}

路由傳回的內容取決於您的應用程式是否配置了身份驗證（`server.auth` or `studio.auth`):

* **無授權：**&#x8DEF;由以實例所有者的身份讀取，並將每個範圍、頁面和註釋傳回給可以存取伺服器的任何人。僅將其用於本機或測試項目，並在部署之前新增身份驗證。
* **授權：**&#x8DEF;由僅傳回登入使用者可以讀取的內容。在`authorize`, set the request context key `MASTRA_KNOWLEDGE_PRINCIPALS_KEY` to the user's Knowledge scopes. Knowledge applies the same access rules agents use. In the alpha, these rules aren't an [isolation boundary](/docs/knowledge/scopes-and-access), so don't store content that must never reach another user.

```typescript title="src/mastra/index.ts"
import { Mastra } from '@mastra/core/mastra'
import { KNOWLEDGE_ROUTES, MASTRA_KNOWLEDGE_PRINCIPALS_KEY } from '@mastra/server/server-adapter'
import { appAuthorize } from './auth' // your existing authorization

export const mastra = new Mastra({
  server: {
    apiRoutes: [...KNOWLEDGE_ROUTES],
    auth: {
      // authenticateToken, ...
      authorize: async (path, method, user, context) => {
        if (path.startsWith('/api/knowledge')) {
          context
            .get('requestContext')
            .set(
              MASTRA_KNOWLEDGE_PRINCIPALS_KEY,
              user.isAdmin ? 'all' : [`org:${user.orgId}`, `team:${user.orgId}:${user.teamId}`],
            )
          return true
        }
        return appAuthorize(path, method, user, context)
      },
    },
  },
})
```

如果您設定了不同的前綴，請更改`/api/knowledge` check in `authorize` to match. Otherwise the key isn't set and the routes return `403`.

一個`authorize` function replaces the server's rules and role checks for every route, so keep your app's existing decision for the other paths, as above. Returning `true` for everything would let any signed-in user call any route.

將值設為範圍數組，或者`'all'` for someone who should see the whole instance. An empty array reads nothing. See [Knowledge access and errors](/reference/server/routes#knowledge-access-and-errors) for what other values return. If you configure `studio.auth`, Studio requests use it instead of `server.auth`, so set the key in that `authorize`.

### 提供者`authorizeUser` {/* #providers-with-authorizeuser */}

伺服器從不調用`authorize` when the auth provider defines `authorizeUser`. This includes any `MastraAuthProvider` subclass that implements it, and every `CompositeAuth`. For these providers, set the key in a [server middleware](/docs/server/middleware) instead:

```typescript title="src/mastra/index.ts"
import { Mastra } from '@mastra/core/mastra'
import { KNOWLEDGE_ROUTES, MASTRA_KNOWLEDGE_PRINCIPALS_KEY } from '@mastra/server/server-adapter'
import { auth, getSessionUser } from './auth' // your provider and session lookup

export const mastra = new Mastra({
  server: {
    apiRoutes: [...KNOWLEDGE_ROUTES],
    auth,
    middleware: [
      {
        path: '/api/knowledge/*',
        handler: async (c, next) => {
          const user = await getSessionUser(c.req.raw)
          if (user) {
            c.get('requestContext').set(
              MASTRA_KNOWLEDGE_PRINCIPALS_KEY,
              user.isAdmin ? 'all' : [`org:${user.orgId}`, `team:${user.orgId}:${user.teamId}`],
            )
          }
          await next()
        },
      },
    ],
  },
})
```

伺服器中間件在路由的身份驗證檢查之前運行，因此登入使用者尚未位於請求上下文中。使用應用程式自己的會話檢查從請求中尋找用戶，如上所述。此後，路由的身份驗證仍會運行，並拒絕您的提供者不接受的呼叫者。更改中介軟體`path` if you set a different prefix.

### 部署說明 {/* #deployment-notes */}

* **無 RBAC 提供者：**&#x9019;`knowledge:read` check is skipped, so any authenticated user with a principal mapping can read the pages those principals cover, in every instance.
* **透過 FGA 提供者：**&#x6BCF;個知識實例都單獨檢查`knowledge:read`. A user sees only the instances you grant. See [Knowledge access and errors](/reference/server/routes#knowledge-access-and-errors).
* **巢JS：**&#x4E;estJS 適配器尚不支援知識路由。

## 建立自己的觀點 {/* #build-your-own-view */}

若要在您自己的應用程式中顯示知識更改，請訂閱[`knowledge.onChange()`](/reference/knowledge/knowledge-class#onchange). Events carry IDs, not content. Read the page again under the user's scopes before you show it to them. A `page` `delete` event can't be read again, so remove the page from your view. A `page` `merge` event's `pageId` is the target, so also remove the merged-away page in `sourceId`. A `scope` event is sent for a new scope only, not for its child scopes or template pages, so list the scope again to find them.
