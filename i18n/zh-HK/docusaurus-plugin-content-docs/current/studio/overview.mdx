# Studio

Studio 提供互動介面，用來建立、測試及管理 Agent、Workflow 和工具。開發時可在本機執行，也可加入[身份驗證](/docs/studio/auth)或[部署至生產環境](/docs/studio/deployment)，讓團隊管理 Agent、監察效能，並透過內置的可觀測性功能了解運行情況。

:::tip[📹 觀看短片]

觀看 [Mastra Studio 簡介](https://youtu.be/ojGu6Bi4wYk)，了解如何在 Studio 建立、測試和管理 Agent。

:::

## 启动 Studio {/* #start-studio */}

如以 `create mastra` 建立應用程式，請用 `dev` 指令碼啟動開發伺服器，也可直接執行 `mastra dev`。

```bash npm2yarn
npm run dev
```

服务器启动后，您可以：

- 在 [`localhost:4111`](http://localhost:4111/) 開啟 Studio 介面，操作 Agent、Workflow 及工具。
- 瀏覽 [`localhost:4111/swagger-ui`](http://localhost:4111/swagger-ui)，查看及試用底層 REST API。

你可在 Studio 即時編輯 [Agent](/docs/agents/overview)、[Workflow](/docs/workflows/overview) 及 Mastra 應用程式的其他部分。

## 部署 Studio {/* #deploy-studio */}

準備與團隊共享 Studio 時，可使用 [Mastra 平台上的 Studio](/docs/mastra-platform/studio) 或自己的基礎設施部署至生產環境。做法請參閱[部署文件](/docs/studio/deployment)。

## 基本組件 {/* #primitives */}

### Agent {/* #agents */}

你可以直接與 Agent 對話、切換[模型](/models)，並調整 temperature、top-p 等設定，查看它們對輸出的影響。

如果模型目錄載有推出日期，模型選擇器會在各 Provider 下先列出較新的模型。同日推出的模型按字母排序。沒有日期的模型亦按字母排序，並列在有日期的模型之後。

若要將模型選擇器限於自己[自訂閘道](/models/gateways/custom-gateways)的模型，請設定 `AUTO_BLOCK_EXTERNAL_PROVIDERS=true`。詳見[在 Studio 只顯示自訂閘道](/models/gateways/custom-gateways#showing-only-custom-gateways-in-studio)。

與 Agent 互動時，可查看推理過程及工具呼叫輸出，也可[查看追蹤記錄及日誌](#observability)，了解回覆如何產生。

回覆如有 Markdown 表格，可在表格上方選擇 **Copy table as markdown**，只複製表格。複製的內容會保留 Markdown 格式，並包含表格所用的連結及註腳定義。如要下載 CSV，請展開複製按鈕旁的箭嘴，再選擇 **Download CSV**。包含表格的文字段落完成串流並完整顯示後，兩項操作便可使用。Agent 此時可能仍在執行工具或撰寫後續內容。

CSV 匯出的是儲存格純文字。連結保留顯示文字，註腳保留標記，網址及註腳定義則不會匯出。試算表軟件可能當作公式的值會加上前置單引號，讓軟件視為文字。一般帶正負號的數字會原樣保留。

亦可加入[評分器](#scorers)，持續量度及比較回覆質素。

如要就回覆中的某段文字提問，請選取該段並選擇 **Add to chat**，也可按 Tab 鍵將焦點移至該選項。每段加入的文字都會在對話中顯示編號註解氣泡，訊息輸入欄會顯示數量，例如 **2 annotations**。選擇氣泡可為該段撰寫註解或移除該段，也可開啟計數清單，在對話中找回原文。傳送時，Agent 會先收到逐段編號的引文及各自的註解，再收到你輸入的文字。亦可只傳送註解。如果選取範圍橫跨兩則訊息，就不會顯示 **Add to chat**。

Agent 串流輸出回覆時，你可以在同一對話串傳送後續訊息。Studio 會將訊息標示為待確認，待串流確認後，再於該訊息下方繼續顯示回覆。其他已開啟同一對話串的 Studio 分頁也可看到正在進行的串流。

透過 [Editor](/docs/studio/editor)，非技術團隊成員也可逐步改進 Agent、為每項變更保留版本，並在毋須重新部署的情況下運行實驗。

使用 [Agent Builder](https://agent-builder.mastra.ai) 的獨立瀏覽器介面，建立及管理完整儲存在儲存層的 Agent。

#### 模型面板 {/* #models-panel */}

開啟 Agent 的 **Models** 面板，可按優先次序查看主要和後備模型。對於靜態模型清單，可調整排序、啟用或停用後備模型，以及更改 Provider 或模型。Studio 重新擷取 Agent 時會同步更新面板。

Agent 設定 `editor: { model: true }` 後，修改會經 [Editor](/docs/studio/editor#decide-what-collaborators-can-edit) 儲存。這需要同時設定 `MastraEditor` 和 Agent 儲存空間，缺少任何一項都會令儲存失敗並傳回 HTTP 500。若未設定該選項，修改只會套用至運行中伺服器記憶體內的 Agent，伺服器重新啟動後便會遺失。其他 Agent 的持久化編輯進度見 [GitHub issue #27089](https://github.com/mastra-ai/mastra/issues/27089)。

由函數提供的模型清單可能隨請求上下文改變，因此 Studio 會將其顯示為唯讀。要更改動態模型清單，請修改程式碼。

### Workflow {/* #workflows */}

以流程圖檢視 Workflow，並用自訂輸入逐步執行。執行期間，介面會即時顯示目前步驟及經過的路徑。

Workflow 追蹤記錄會顯示工具呼叫、原始 JSON 輸出及執行錯誤。

在執行按鈕旁選擇 **Run options**，即可為即將啟動的執行設定 **Resource ID**。Studio 會按 Workflow 記住此值，並可用 `GET /api/workflows/:workflowId/runs?resourceId=...` 列出 Studio 建立的執行。留空會建立不連結任何資源的執行。如伺服器從已驗證身份的用戶取得資源 ID，則以伺服器取得的值為準。

### 处理器 {/* #processors */}

可查看每個 Agent 所用的輸入及輸出處理器。Agent 詳情面板會列出所有處理器的名稱和類型，方便在測試前確認防護機制、Token 限制器及自訂處理器已正確接駁。

設定詳情請參閱[處理器](/docs/agents/processors)及[防護機制](/docs/agents/guardrails)。

### MCP 服务器 {/* #mcp-servers */}

可列出已連接 Mastra 實例的 MCP 伺服器，並查看可用工具。首項是 **Mastra (built-in)**，即位於 `/api/mcp` 的[內置 MCP 伺服器](/docs/server/mcp#in-studio)。條目會顯示端點 URL、是否需要權杖，以及 Claude Code、Cursor、VS Code 和 MCP Inspector 的設定方法。

### 工具 {/* #tools */}

將工具交給 Agent 前，可先獨立執行工具，觀察及測試其行為。遇到問題時，可獨立重新執行該工具以找出原因。

### Workspace {/* #workspaces */}

使用內置檔案瀏覽器查看 Agent 的 Workspace 檔案系統。你可切換掛載點、建立目錄及查看有語法高亮的檔案內容。可寫入的 Workspace 容許建立目錄及刪除檔案，唯讀的 Workspace 則會加上標記。檔案樹會顯示 Skill。可從 [skills.sh](https://skills.sh) 安裝社群 Skill、更新已安裝的 Skill，或刪除 Skill 資料夾以移除該 Skill。

配置详情见 [Workspace](/docs/sandbox/overview)。

### 請求上下文 {/* #request-context */}

透過依賴注入將執行時變數傳入 Agent 的指令及工具。可用 JSON 編輯請求上下文，如果 Agent 已定義 `requestContextSchema`，也可使用按結構產生的表單。設定值會在測試對話及實驗之間保留，毋須重啟即可觸發條件流程。

設定詳情請參閱[請求上下文](/docs/server/request-context)。

## 评估 {/* #evaluation */}

### 评分器 {/* #scorers */}

Scorers 分頁會在 Agent 的評分器執行時顯示結果。訊息經過 Agent 時，已定義的評分器會非同步評估每項輸出，並在此顯示結果。你可查看評分器在不同互動中的表現，比較各測試個案，找出可改善之處。

### 數據集 {/* #datasets */}

建立及管理用來評估 Agent 和 Workflow 的測試個案集合。可從 CSV 或 JSON 匯入項目、定義輸入和標準答案的結構，並鎖定指定版本，以精確重現實驗。使用[評分器](/docs/evals/overview)運行實驗，可比較提示詞、模型或程式碼變更對質素的影響。

完整 API 及版本管理詳情請參閱[數據集概覽](/docs/evals/datasets)。

### 实验 {/* #experiments */}

透過指定的 Agent、Workflow 或評分器處理數據集內所有項目，並集中收集結果。選擇目標後，可按需要加入評分器，再啟動實驗。結果介面會顯示各項目的輸入、輸出、狀態及評分明細。可並排查看兩至十個實驗並與基準比較，衡量提示詞、模型或程式碼變更的影響。

設定詳情請參閱[數據集概覽](/docs/evals/datasets)。

## 设置 {/* #settings */}

在設定頁面可設定 Studio 與 Mastra 伺服器的連線，選項包括：

- **Mastra instance URL**：Mastra 伺服器的基礎 URL，例如 `http://localhost:4111`。
- **API prefix**：適用於所有 API 請求的選用路徑前綴，預設為 `/api`。
- **Custom headers**：為每個請求加入鍵值對，可用於傳送身份驗證權杖或路由標頭。
- **Theme**：選擇深色、淺色或跟隨系統的主題。

## 在代码中配置 {/* #code-configuration */}

除了使用[設定](#settings)介面，也可透過 `src/mastra/index.ts` 的 [`server`](/reference/configuration#server-options) 選項設定本機開發伺服器及 Studio。

Studio 預設在 [http://localhost:4111](http://localhost:4111) 運行。可更改 [`host`](/reference/configuration#serverhost) 及 [`port`](/reference/configuration#serverport)。

Mastra 亦支援以 [`--https`](/reference/cli/mastra#--https) 參數進行 HTTPS 開發，自動為項目建立及管理憑證。執行 `mastra dev --https` 時，會為 localhost 或已設定的主機產生私鑰和憑證。詳情請參閱 [HTTPS 參考](/reference/configuration#serverhttps)。
