# 工作室授權

當您配置時[authentication](/docs/auth/overview)在您的 Mastra 伺服器上，Studio 會自動顯示登入畫面並強制執行存取控制。一種配置可以保護 Studio UI 和 API 路由的安全性。

無需身份驗證，Studio 和所有 API 路由均可公開存取。

：：：筆記

在生產中，具有第三方提供者的 Studio 登入畫面、基於角色的存取控制 (RBAC) 和細粒度授權 (FGA) 需要 Mastra 企業版 (EE) 授權。簡單身份驗證、JWT 和 API 路由上的身份驗證則不然。每個功能都無需開發許可即可使用。看[what requires an EE license](/docs/license#what-requires-an-ee-license). [Contact sales](https://mastra.ai/contact) for more information.

:::

:::注意
部署在 Mastra 平台上的 Studio 的工作方式有所不同。預設情況下，平台會注入自己的身份驗證，因此只有您的組織成員可以登錄，並且您的`server.auth` applies to API routes only. Set `MASTRA_PLATFORM_STUDIO_AUTH=disabled` to opt out. See [Authentication on Mastra platform](/docs/mastra-platform/studio#authentication).
:::

## 何時使用 Studio Auth {/* #when-to-use-studio-auth */}

* 多個團隊成員需要透過共享 Studio 部署與Agent程式、Workflow和Tool進行互動。
* 權限必須限制誰可以執行Agent或編輯Workflow，或刪除資料集。
* 登入畫面（SSO、電子郵件/密碼或兩者）應控制對 Studio 部署的存取。

## 快速入門 {/* #quickstart */}

将身份验证提供程序添加到您的 Mastra 服务器配置中。本範例使用[Simple Auth](/docs/auth/simple-auth) for a minimal setup:

```typescript title="src/mastra/index.ts"
import { Mastra } from '@mastra/core'
import { SimpleAuth } from '@mastra/core/server'

export const mastra = new Mastra({
  server: {
    auth: new SimpleAuth({
      tokens: {
        'my-api-key': {
          id: 'user-1',
          name: 'Alice',
          role: 'admin',
        },
      },
    }),
  },
})
```

配置完成後，Studio 將顯示登入畫面並要求對所有 API 請求進行身份驗證。參觀[Auth docs](/docs/auth/overview) for a full list of supported providers.

## 它是如何運作的 {/* #how-it-works */}

環境[`server.auth`](/reference/configuration#serverauth) does two things at once:

* **工作室使用者介面**：顯示登入畫面。使用者透過 SSO、電子郵件/密碼或兩者登錄，具體取決於提供者。
* **API路線**：需要對所有內建路由進行身份驗證（`/api/agents/*`, `/api/workflows/*`, etc.) and custom routes. This applies whether requests come from Studio or direct API calls.

Studio 透過呼叫來偵測可用功能`GET /api/auth/capabilities` endpoint. The response tells Studio which login methods to render and, if the user is already authenticated, includes their user info and permissions.

## 透過 URL 傳遞令牌 {/* #pass-a-token-through-the-url */}

`auth_header` URL parameter. This is useful when an external host already holds a token and wants to open an authenticated Studio session without showing the login screen.

這`auth_header` value always populates the `Authorization` request header. The parameter sets that one header only, so include any scheme prefix the server expects in the value, such as `Bearer`.

使用查詢字串中的令牌開啟 Studio：

```text
https://your-studio-host/?auth_header=Bearer%20your-token
```

Studio 依下列方式處理代幣：

* 上面寫著`auth_header` once on load and sends the value as the `Authorization` header on every API request in that session.
* 它刪除了`auth_header` from the address bar while preserving other query parameters and the hash.
* 它將令牌僅保留在記憶體中，並且從不將其寫入本地存儲，因此它不會在頁面重新載入時持續存在。

令牌包含在 URL 參數中，因此主機應用程式負責如何產生和傳輸該 URL。 URL 參數可以透過瀏覽器歷史記錄和引用標頭以及伺服器存取日誌公開。

## 基於角色的存取控制 {/* #role-based-access-control */}

RBAC 可讓您控制每位使用者在 Studio 中可以看到的內容和可執行的操作。它與身份驗證分開：`server.auth` handles who the user is, while `server.rbac` handles what they can do.

### 預設角色 {/* #default-roles */}

Mastra 包括四個預設角色。從以下位置匯入它們`@mastra/core/auth/ee`:

|角色 |權限 |
| - | - |
|`owner` | Full access (`*`) |
| `admin` | Read, write, execute, publish, and share (no delete) |
| `member` | Read and execute |
| `viewer` | Read-only |

### 啟用角色控制 {/* #enable-rbac */}

使用`StaticRBACProvider` with the default roles or define your own:

```typescript title="src/mastra/index.ts"
import { Mastra } from '@mastra/core'
import { SimpleAuth } from '@mastra/core/server'
import { StaticRBACProvider, DEFAULT_ROLES } from '@mastra/core/auth/ee'

export const mastra = new Mastra({
  server: {
    auth: new SimpleAuth({
      tokens: {
        'admin-key': { id: 'user-1', name: 'Alice', role: 'admin' },
        'viewer-key': { id: 'user-2', name: 'Bob', role: 'viewer' },
      },
    }),
    rbac: new StaticRBACProvider({
      roles: DEFAULT_ROLES,
      getUserRoles: user => [user.role],
    }),
  },
})
```

當 RBAC 處於活動狀態時，Studio 會隱藏使用者無權執行的操作。查看者看不到刪除按鈕。成員無法修改Agent配置。

### 權限格式 {/* #permission-format */}

權限遵循模式`{resource}:{action}`, with optional resource-level scoping:

|圖案|意義|
| - | - |
|`*` | Full access to everything |
| `*:read` | Read all resources |
| `agents:*` | All actions on agents |
| `agents:execute` | Execute agents only |
| `agents:read:my-id` | Read a specific agent by ID |

`agents`, `workflows`, `tools`, `datasets`, `memory`, `scores`, `observability`, `stored-agents`, `mcp`, and others. Actions are `read`, `write`, `create`, `delete`, `execute`, `publish`, and `share`.

`mcp:read`和`mcp:execute` gate the [built-in MCP server](/docs/server/mcp#authentication-and-permissions) and the routes of `MCPServer` instances you register. The default `viewer` role has `mcp:read` only, so a viewer can connect but gets an empty tool list. Each MCP tool call also needs the permission of the route it runs, such as `agents:execute`.

預設情況下，儲存的Agent程式對其所有者是私有的。`stored-agents:*` lets a user see and edit every stored agent. `stored-agents:admin` lifts the owner check, but the user still needs each route's own permission, such as `stored-agents:read` or `stored-agents:write`. The default `admin` role doesn't include either. See [stored agent visibility](/docs/studio/editor#visibility).

### 映射外部提供者角色 {/* #map-external-provider-roles */}

如果您的身分提供者已定義角色（例如，文員組織或 WorkOS 群組），請將它們對應到 Mastra 權限`roleMapping`:

```typescript title="src/mastra/index.ts"
import { StaticRBACProvider } from '@mastra/core/auth/ee'

const rbac = new StaticRBACProvider({
  roleMapping: {
    'org:admin': ['*'],
    'org:member': ['*:read', '*:execute'],
    'org:viewer': ['*:read'],
  },
  getUserRoles: user => user.providerRoles,
})
```

## 登入方式 {/* #login-methods */}

Studio 根據認證提供者調整其登入畫面：

|提供者類型 |登入介面 |
| - | - |
|仅限单点登录 | SSO 按钮（例如“使用 WorkOS 登录”）|
|僅限憑證 |電子郵件和密碼表格 |
|两者 | SSO 按钮和电子邮件/密码表单 |

每個提供者都可以啟用或停用註冊。停用後，Studio 會隱藏註冊連結並強制使用登入表單。
