# Studio 身份驗證

在 Mastra 伺服器配置 [身份驗證](/docs/auth/overview) 後，Studio 會自動顯示登入畫面及實施存取控制。同一份配置會保護 Studio 介面及 API 路由。

如未設定身份驗證，Studio 及所有 API 路由均可公開存取。

:::note

在正式環境中，使用第三方 Provider 的 Studio 登入畫面、角色存取控制（RBAC）及細粒度授權（FGA）需要 Mastra 企業版（EE）授權。Simple Auth、JWT 及 API 路由的身份驗證毋須這項授權。開發環境中所有功能均可免授權使用。參閱 [需要 EE 授權的功能](/docs/license#what-requires-an-ee-license)。如需更多資料，請 [聯絡銷售團隊](https://mastra.ai/contact)。

:::

:::note
部署至 Mastra 平台的 Studio 預設會使用平台注入的身份驗證，只有你所屬組織的成員可以登入。`server.auth` 只適用於 API 路由。可設定 `MASTRA_PLATFORM_STUDIO_AUTH=disabled` 停用平台身份驗證。參閱 [Mastra 平台的身份驗證](/docs/mastra-platform/studio#authentication)。
:::

## 適合使用 Studio 身份驗證的情況 {/* #when-to-use-studio-auth */}

* 多位團隊成員需要在同一個 Studio 部署環境使用 Agent、Workflow 及工具。
* 需要限制哪些人可執行 Agent、編輯 Workflow 或刪除資料集。
* 需要先經登入畫面驗證身份，才可存取 Studio。可採用 SSO、電郵和密碼，或同時提供兩種方式。

## 快速入門 {/* #quickstart */}

在 Mastra 伺服器的配置中加入身份驗證 Provider。以下示例使用 [Simple Auth](/docs/auth/simple-auth) 作基本設定。

```typescript title="src/mastra/index.ts"
import { Mastra } from '@mastra/core'
import { SimpleAuth } from '@mastra/core/server'

export const mastra = new Mastra({
  server: {
    auth: new SimpleAuth({
      tokens: {
        'my-api-key': {
          id: 'user-1',
          name: 'Alice',
          role: 'admin',
        },
      },
    }),
  },
})
```

完成配置後，Studio 會顯示登入畫面，所有 API 請求都須通過身份驗證。支援的 Provider 完整列表見 [身份驗證文件](/docs/auth/overview)。

## 運作方式 {/* #how-it-works */}

設定 [`server.auth`](/reference/configuration#serverauth) 後，身份驗證會同時套用於以下兩處。

* **Studio 介面**會顯示登入畫面。視乎 Provider，用戶可用 SSO 或電郵和密碼登入，也可能同時提供兩種選擇。
* **API 路由**要求所有內置路由（例如 `/api/agents/*` 及 `/api/workflows/*`）和自訂路由通過身份驗證。無論請求來自 Studio，還是直接呼叫 API，都適用。

Studio 會呼叫 `GET /api/auth/capabilities` 端點查詢可用功能。回應會告知 Studio 應顯示哪些登入方式。如用戶已通過身份驗證，回應亦會包含用戶資料和權限。

## 透過 URL 傳送權杖 {/* #pass-a-token-through-the-url */}

其他應用程式嵌入 Studio 或提供 Studio 連結時，可經 URL 參數 `auth_header` 傳送授權權杖。若外部應用程式已有權杖，就可跳過登入畫面，直接開啟已通過身份驗證的 Studio 工作階段。

`auth_header` 的值一律填入 `Authorization` 請求標頭。此參數只設定這個標頭，請在參數值中加入伺服器要求的驗證方式前綴，例如 `Bearer`。

開啟 Studio 時，把權杖放入 URL 的查詢字串。

```text
https://your-studio-host/?auth_header=Bearer%20your-token
```

Studio 會按以下方式處理權杖。

* 載入頁面時讀取一次 `auth_header`，並在該工作階段的每個 API 請求以 `Authorization` 標頭傳送該值。
* 從網址列移除 `auth_header`，保留其他查詢參數及 URL 片段。
* 只將權杖保存在記憶體內，不寫入瀏覽器本機儲存空間。重新載入頁面後，權杖便不會保留。

權杖經 URL 參數傳送，由宿主應用程式負責產生及傳送 URL。瀏覽器記錄、來源標頭及伺服器存取日誌均可能暴露 URL 參數。

## 角色存取控制 {/* #role-based-access-control */}

RBAC 控制每名用戶在 Studio 可查看的內容和可執行的操作。`server.auth` 負責驗證用戶身份，`server.rbac` 負責控制用戶權限。

### 預設角色 {/* #default-roles */}

Mastra 提供四個預設角色，可從 `@mastra/core/auth/ee` 匯入。

| 角色 | 權限 |
| - | - |
| `owner` | 完整存取權限（`*`） |
| `admin` | 可讀取、寫入、執行、發佈及分享，沒有刪除權限 |
| `member` | 可讀取及執行 |
| `viewer` | 唯讀 |

### 啟用 RBAC {/* #enable-rbac */}

使用 `StaticRBACProvider` 時，可採用預設角色，或自行定義角色。

```typescript title="src/mastra/index.ts"
import { Mastra } from '@mastra/core'
import { SimpleAuth } from '@mastra/core/server'
import { StaticRBACProvider, DEFAULT_ROLES } from '@mastra/core/auth/ee'

export const mastra = new Mastra({
  server: {
    auth: new SimpleAuth({
      tokens: {
        'admin-key': { id: 'user-1', name: 'Alice', role: 'admin' },
        'viewer-key': { id: 'user-2', name: 'Bob', role: 'viewer' },
      },
    }),
    rbac: new StaticRBACProvider({
      roles: DEFAULT_ROLES,
      getUserRoles: user => [user.role],
    }),
  },
})
```

啟用 RBAC 後，Studio 會隱藏用戶無權執行的操作。唯讀用戶看不到刪除按鈕，成員亦不能修改 Agent 配置。

### 權限格式 {/* #permission-format */}

權限採用 `{resource}:{action}` 格式，可進一步限定至個別資源。

| 格式 | 涵義 |
| - | - |
| `*` | 可完整存取所有資源 |
| `*:read` | 可讀取所有資源 |
| `agents:*` | 可對 Agent 執行所有操作 |
| `agents:execute` | 只可執行 Agent |
| `agents:read:my-id` | 可按 ID 讀取指定的 Agent |

資源包括 `agents`、`workflows`、`tools`、`datasets`、`memory`、`scores`、`observability`、`stored-agents`、`mcp` 等。操作包括 `read`、`write`、`create`、`delete`、`execute`、`publish` 及 `share`。

`mcp:read` 及 `mcp:execute` 控制 [內置 MCP 伺服器](/docs/server/mcp#authentication-and-permissions) 和已註冊 `MCPServer` 實例路由的存取權限。預設的 `viewer` 角色只有 `mcp:read`，因此可連接，但只會收到空白工具列表。每次呼叫 MCP 工具亦須具備相關路由的權限，例如 `agents:execute`。

已儲存的 Agent 預設只供擁有者存取。`stored-agents:*` 允許用戶檢視及編輯所有已儲存的 Agent。`stored-agents:admin` 可略過擁有者檢查，但用戶仍須具備個別路由要求的權限，例如 `stored-agents:read` 或 `stored-agents:write`。預設的 `admin` 角色沒有這兩項權限。參閱 [已儲存 Agent 的可見範圍](/docs/studio/editor#visibility)。

### 對應外部 Provider 的角色 {/* #map-external-provider-roles */}

如果身份 Provider 已定義角色，例如 Clerk 組織或 WorkOS 群組，可用 `roleMapping` 將這些角色對應至 Mastra 權限。

```typescript title="src/mastra/index.ts"
import { StaticRBACProvider } from '@mastra/core/auth/ee'

const rbac = new StaticRBACProvider({
  roleMapping: {
    'org:admin': ['*'],
    'org:member': ['*:read', '*:execute'],
    'org:viewer': ['*:read'],
  },
  getUserRoles: user => user.providerRoles,
})
```

## 登入方式 {/* #login-methods */}

Studio 會按身份驗證 Provider 顯示相應的登入畫面。

| Provider 類型 | 登入介面 |
| - | - |
| 只提供 SSO | SSO 按鈕（例如「使用 WorkOS 登入」） |
| 只提供電郵及密碼 | 電郵及密碼表格 |
| 同時提供兩種方式 | SSO 按鈕及電郵密碼表格 |

可按 Provider 啟用或停用註冊。停用後，Studio 會隱藏註冊連結，只可使用登入表格。
