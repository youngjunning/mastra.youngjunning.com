# Studio 可觀測性

Studio 包含以下可觀察性視圖：

- **Metrics**：查看整體效能資料
- **Traces**：檢查個別請求
- **Logs**：瀏覽內部及應用程式日誌

所有這些都需要配置可觀察性儲存後端。

## 快速入門 {/* #quickstart */}

詳細設定見[可觀測性指南](/docs/observability/overview)。如要快速建立本機開發環境，可在項目加入 `@mastra/observability`，再配合 [LibSQL](/integrations/databases/libsql) 和 [DuckDB](/integrations/vectors/duckdb)，同時支援 Trace 和指標。

```bash npm2yarn
npm install @mastra/observability @mastra/libsql @mastra/duckdb
```

然後將以下內容添加到您的`src/mastra/index.ts`:

```ts title="src/mastra/index.ts"
import { Mastra } from '@mastra/core/mastra'
import { LibSQLStore } from '@mastra/libsql'
import { DuckDBStore } from '@mastra/duckdb'
import { MastraCompositeStore } from '@mastra/core/storage'
import {
  Observability,
  MastraStorageExporter,
  MastraPlatformExporter,
  SensitiveDataFilter,
} from '@mastra/observability'

export const mastra = new Mastra({
  // highlight-start
  storage: new MastraCompositeStore({
    id: 'composite-storage',
    default: new LibSQLStore({
      id: 'mastra-storage',
      url: 'file:./mastra.db',
    }),
    domains: {
      observability: await new DuckDBStore().getStore('observability'),
    },
  }),
  // highlight-end
  observability: new Observability({
    configs: {
      default: {
        serviceName: 'mastra',
        exporters: [
          new MastraStorageExporter(), // Persists observability events to Mastra Storage
          new MastraPlatformExporter(), // Sends observability events to Mastra platform (if MASTRA_PLATFORM_ACCESS_TOKEN is set)
        ],
        spanOutputProcessors: [
          new SensitiveDataFilter(), // Redacts sensitive data like passwords, tokens, keys
        ],
      },
    },
  }),
})
```

## 指標 {/* #metrics */}

指標儀表板匯總 Agent、Workflow 和 Tool 在所選時段內的效能，範圍可由過去 24 小時至 30 天。首列顯示 Agent 執行總次數、模型成本、Token 用量及評分器的平均表現。下方卡片細列各模型的用量和成本、各 Agent 的 Token 用量、不同時段的 Token 用量及估算成本、Trace 的數量及當中完成和出錯的次數、延遲百分位數（p50 和 p95），以及評分走勢。

詳見[指標概覽](/docs/observability/metrics/overview)。

:::note

指標須使用支援此功能的可觀測性儲存，例如 DuckDB、ClickHouse，或已啟用可觀測性領域的 `PostgresStoreVNext`。LibSQL、MSSQL 和 MongoDB 均不支援指標。記憶體儲存會在重啟時重設。完整清單見[儲存支援](/docs/observability/metrics/overview#storage-support)。

:::

## Trace {/* #traces */}

執行 Agent 或 Workflow 時，**Observability** 分頁會顯示 Trace，列出模型調用、Tool 執行和 Workflow 步驟等主要操作。沿 Trace 可查看資料流向、各部分所需時間和實際執行過程。

開啟 Trace 清單上方的 **Columns**，可顯示或隱藏輸入、實體、所需時間、輸入 Token、輸出 Token、估算成本及自訂中繼資料欄。Studio 會在瀏覽器儲存選項，供目前的 Mastra 伺服器和 API 前綴使用。

自訂中繼資料欄須使用支援 Trace 查詢（`queryTraces`）的可觀測性儲存，例如[快速入門](#quickstart)所用的 DuckDB。在 **Columns** 選擇 **Add metadata column**，然後輸入 `tracingOptions.metadata` 所用的頂層鍵。

如果儲存不支援 Trace 查詢，例如只使用 LibSQL，Studio 會隱藏 **Add metadata column**，亦不會提供中繼資料、標籤等進階篩選。即使在 span 儲存中繼資料，這些清單功能也不會啟用。

Token 和估算成本欄須使用支援指標的可觀測性儲存。數列分支可能屬於同一個 Trace，因此 **Branches** 檢視會隱藏這些欄。

追蹤會略去框架底層細節，讓 Trace 更清晰易讀。詳見 [Trace 使用指南](/docs/observability/tracing/overview)。

如要匯出 Trace，可在面板頂部選擇 **Download trace JSON**。整個 Trace 會儲存為 `trace-<id>.json`，包括每個 span 的完整輸入、輸出、中繼資料及屬性。你可以分享這個檔案、把它附在錯誤報告內，或用來離線建立評估資料集。

## 紀錄 {/* #logs */}

你可瀏覽轉送到可觀測性儲存的 Mastra 內部日誌，並對訊息內容、實體名稱以及 Trace ID 作全文搜尋。預設時間範圍由過去 24 小時至 30 天，可按級別、實體類型和實體名稱作多選篩選。選取日誌後，詳細資料面板會顯示完整訊息、結構化資料及中繼資料。如有相關的 Trace，可直接前往該 Trace 及其 span 時間軸。

設定可觀測性後，系統預設會轉送日誌。級別設定、查詢範例和自訂方法見[日誌指南](/docs/observability/logging)。
