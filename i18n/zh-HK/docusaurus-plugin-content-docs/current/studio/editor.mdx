# 編輯

Editor 類似 Mastra Agent 的 CMS。協作者毋須存取程式碼庫或編寫程式碼，就能在 Studio 調整 Agent 的指令和 Tool，並在上線前測試改動。

預設由 TypeScript 提供協作者可覆寫的初始值。若將某個欄位交給 Editor 管理，Studio 便會獨佔該欄位：請在 Studio 定義它，並從 Agent 設定中省略。

[已部署的 Studio](/docs/studio/deployment) 讓本機開發環境以外的協作者亦可使用 Editor。

:::tip[📹 觀看]

觀看 [Mastra Editor 工作坊](https://www.youtube.com/watch?v=XTjuRoI7t_k\&pp=ygUWbWFzdHJhIGVkaXRvciB3b3Jrc2hvcA%3D%3D)，跟隨示範了解操作流程。

:::

## 何時使用編輯器 {/* #when-to-use-editor */}

當 Agent 由程式碼定義，但負責其行為的協作者不應修改程式碼庫時，請使用 Editor。若指令或 Tool 經常變動，而且需要在提供給用戶前測試，便特別適合。若所有改動都由開發者負責，Agent 設定亦隨應用程式發布，則請繼續[在程式碼中設定 Agent](/docs/agents/overview)。

若協作者需要直接在瀏覽器建立及管理完全儲存的 Agent，而非從程式碼定義的 Agent 開始，請使用 [Agent Builder](https://agent-builder.mastra.ai)。

## 快速入門 {/* #quickstart */}

安裝 `@mastra/editor`。本快速入門使用 LibSQL 儲存 Editor 的改動：

```bash npm2yarn
npm install @mastra/editor @mastra/libsql
```

在 `Mastra` 實例加入 `MastraEditor` 和儲存。若已有儲存，可直接沿用，毋須加入範例中的 LibSQL 儲存。

```typescript title="src/mastra/index.ts"
import { Mastra } from '@mastra/core'
import { MastraEditor } from '@mastra/editor'
import { LibSQLStore } from '@mastra/libsql'

export const mastra = new Mastra({
  agents: {/* existing agents */},
  storage: new LibSQLStore({
    id: 'mastra-storage',
    url: 'file:./mastra.db',
  }),
  editor: new MastraEditor(),
})
```

## 在 Studio 中使用編輯器 {/* #use-editor-in-studio */}

在 [Studio](/docs/studio/overview) 開啟 **Agents**，選取 Agent，再選取 **Editor**。協作者可按該 Agent 的 Editor 權限更新指令和 Tool。

使用資料庫儲存時，可將改動存為草稿進行測試，而不影響線上 Agent。準備好後再發布草稿。

## 指示 {/* #instructions */}

**Instructions** 區塊顯示 Agent 的指令。指令留在程式碼中時（預設），會以程式碼中的提示詞為起點，讓協作者覆寫或加入指令區塊。若 `editor.instructions` 為 `true`，提示詞改由 Studio 管理：請從程式碼省略 `instructions`，並在 Agent 執行前於 Studio 發布一個版本。

指令區塊可包含目前請求的值。例如，<code>{'{{userName}}'}</code> 可插入透過[請求脈絡](/docs/server/request-context)提供的姓名。[顯示條件](/reference/editor/prompt-blocks#display-conditions)可令區塊只對指定客戶、角色或功能旗標顯示。

### 提示區塊 {/* #prompt-blocks */}

提示區塊是儲存後可供多個 Agent 使用的指令文字。在 **Prompts** 建立並發布區塊，再開啟 Agent 的 **Instructions** 區塊，選取 **Add block**。

例如，客服、退貨及訂單狀態 Agent 都可能需要相同的退款政策。將政策儲存為提示區塊並加入各 Agent。政策有變時，只需更新並發布該區塊，毋須逐一編輯三個 Agent。

提示區塊更新後，所有參照其已發布版本的 Agent 都會收到改動。草稿只在預覽時使用；發布區塊前，不會影響線上 Agent。

範本語法、條件、版本及 API 詳見[提示區塊參考文件](/reference/editor/prompt-blocks)。

## Tool {/* #tools */}

Tool 讓 Agent 能執行操作。協作者可從 Editor 提供的 Tool 中選取，但不能在 Studio 實作新 Tool。Tool 的來源決定它如何提供使用：

* **專案 Tool** 必須由開發者在 Mastra 專案中實作並註冊。
* **整合 Tool** 在開發者註冊 Composio 或 Arcade 等 Provider 後可用。協作者其後可瀏覽 Provider 目錄並加入 Tool，毋須先在程式碼逐一加入。
* **MCP Tool** 在設定 MCP 用戶端後可用。有權限的協作者可在 Studio 建立用戶端，再從其伺服器公開的 Tool 中選取。

在 Agent 的 **Tools** 區塊，協作者可加入所需 Tool，亦可為該 Agent 改寫某個 Tool 的描述。更具體的描述有助 Agent 判斷何時使用 Tool，而毋須修改 Tool 本身。

### 專案Tool {/* #project-tools */}

開發者可在 `Mastra` 實例註冊專案 Tool，使其出現在 Editor 中：

```typescript title="src/mastra/index.ts"
import { Mastra } from '@mastra/core'
import { MastraEditor } from '@mastra/editor'
import { searchOrders } from './tools/search-orders'

export const mastra = new Mastra({
  tools: {
    searchOrders,
  },
  agents: {/* agents */},
  editor: new MastraEditor(),
})
```

Studio 的 Tool 選擇器會列出該 Tool。若 Agent 允許編輯 Tool，協作者便可將它加入 Agent。若 Tool 成員關係仍由程式碼管理，Agent 的 Editor 檢視亦會列出程式碼中已附加的 Tool。

### 作曲 {/* #composio */}

[Composio](https://composio.dev) 提供 GitHub、Slack、Gmail 等服務的 Tool。使用 Composio API key 註冊 Provider，即可在 Editor 使用其 Tool 目錄：

```typescript title="src/mastra/index.ts"
import { Mastra } from '@mastra/core'
import { MastraEditor } from '@mastra/editor'
import { ComposioToolProvider } from '@mastra/editor/composio'

export const mastra = new Mastra({
  agents: {/* agents */},
  editor: new MastraEditor({
    toolProviders: {
      composio: new ComposioToolProvider({
        apiKey: process.env.COMPOSIO_API_KEY!,
      }),
    },
  }),
})
```

Composio Tool ID 的格式如 `GITHUB_CREATE_ISSUE`。預設選取的 Tool 會使用與 Agent 作者關聯的連線。如要改用每位呼叫者的連線，請參閱[連線範圍](https://agent-builder.mastra.ai/tool-providers#connection-scope)。

### 拱廊 {/* #arcade */}

[Arcade](https://arcade.dev) 提供另一套內置身分驗證的 Tool 目錄。使用 Arcade API key 註冊：

```typescript title="src/mastra/index.ts"
import { Mastra } from '@mastra/core'
import { MastraEditor } from '@mastra/editor'
import { ArcadeToolProvider } from '@mastra/editor/arcade'

export const mastra = new Mastra({
  agents: {/* agents */},
  editor: new MastraEditor({
    toolProviders: {
      arcade: new ArcadeToolProvider({
        apiKey: process.env.ARCADE_API_KEY!,
      }),
    },
  }),
})
```

Arcade Tool ID 使用 `Toolkit.ToolName` 格式，例如 `Github.GetRepository`。

### MCP 客戶 {/* #mcp-clients */}

協作者亦可在 Studio 建立可重用的 MCP 用戶端，並將其 Tool 加入 Agent。已儲存的用戶端可啟動本機 `stdio` 伺服器，或連接遠端 HTTP 伺服器。Tool 篩選器讓各 Agent 只使用所需的 Tool。

MCP 設定、條件、篩選及解析順序詳見 [Editor Tool 參考文件](/reference/editor/tools)；Provider 選項詳見 [`ToolProvider`](/reference/editor/tool-provider)。

## 確定協作者可以編輯的內容 {/* #decide-what-collaborators-can-edit */}

`editor` 欄位決定哪些欄位由 Studio 管理。省略時，協作者可從程式碼中的值開始修改 Agent 指令、管理 Tool 及其描述。Agent 的 `id`、`name` 和模型設定仍由程式碼決定，除非明確啟用模型編輯。

```typescript title="src/mastra/agents/support-agent.ts"
import { Agent } from '@mastra/core/agent'
import { searchOrders } from './tools/search-orders'

export const supportAgent = new Agent({
  id: 'support-agent',
  name: 'Support agent',
  instructions: 'Help customers with Acme products.',
  model: '__GATEWAY_OPENAI_MODEL__',
  tools: { searchOrders },
})
```

將欄位設為 `true`，即交由 Studio 獨佔管理；此時須從程式碼省略該欄位：`editor.instructions` 為 `true` 時，TypeScript 會拒絕 `instructions`；`editor.tools` 為 `true` 時，會拒絕 `tools`。指令由 Studio 管理的 Agent，在包含指令的版本發布前會維持無法執行。

```typescript title="src/mastra/agents/support-agent.ts"
import { Agent } from '@mastra/core/agent'
import { searchOrders } from './tools/search-orders'

export const supportAgent = new Agent({
  id: 'support-agent',
  name: 'Support agent',
  model: '__GATEWAY_OPENAI_MODEL__',
  tools: { searchOrders },
  editor: {
    instructions: true,
    tools: {
      description: true,
    },
  },
})
```

此處由 Studio 管理指令，Tool 成員關係仍由程式碼管理；協作者只能改進 `searchOrders` 的描述。

| `editor` 值 | 協作者可更改 | 程式碼必須提供 |
| - | - | - |
| 省略 | 指令、Tool 及 Tool 描述 | `instructions`；Tool 為可選 |
| `false` | 無 | `instructions` |
| `{ instructions: true }` | 指令 | 毋須 `instructions`；Tool 為可選 |
| `{ tools: true }` | Tool 及其描述 | `instructions`；毋須 `tools` |
| `{ tools: { description: true } }` | 程式碼中已有 Tool 的描述 | `instructions`；要描述的 Tool |
| `{ model: true }` | 靜態模型後備清單 | 含有不可變項目 ID 的靜態後備陣列 |

如要在 Studio 編輯模型，請設定 `editor: { model: true }`，並在程式碼將 `model` 定義為靜態陣列。為每個項目指定穩定的 `id`，讓 Editor 能將已儲存的值對應到程式碼中的模型設定。Studio 可重新排序項目、更改 Provider 和模型，以及啟用或停用項目。

函式形式的模型設定仍由程式碼管理，不能在 Studio 編輯。完整設定請參閱[Editor 覆寫設定](/reference/agents/agent#editor-overrides)。

## 選擇更改的儲存位置 {/* #choose-where-changes-are-stored */}

Editor 可將改動儲存至已設定的資料庫，或存成儲存庫中的檔案。

### 資料庫儲存 {/* #database-storage */}

預設使用資料庫儲存。Editor 使用 `Mastra` 實例上設定的儲存，因此應用程式和 Editor 可共用同一後端。

如要讓 Editor 資料使用獨立後端，請設定 [`MastraCompositeStore`](/reference/storage/composite#options) 的 `editor` 選項。未明確指定路由的儲存網域仍使用其 `default` 儲存。

以下範例將應用程式資料和 Editor 資料存入不同的 LibSQL 檔案：

```typescript title="src/mastra/index.ts"
import { Mastra } from '@mastra/core'
import { MastraCompositeStore } from '@mastra/core/storage'
import { MastraEditor } from '@mastra/editor'
import { LibSQLStore } from '@mastra/libsql'

export const mastra = new Mastra({
  agents: {/* existing agents */},
  storage: new MastraCompositeStore({
    id: 'mastra-storage',
    default: new LibSQLStore({
      id: 'app-storage',
      url: 'file:./mastra.db',
    }),
    editor: new LibSQLStore({
      id: 'editor-storage',
      url: 'file:./editor.db',
    }),
  }),
  editor: new MastraEditor(),
})
```

### 儲存庫文件 {/* #repository-files */}

使用程式碼來源時，覆寫檔案會與應用程式程式碼一起保存。開發者可在拉取請求中審查檔案，並隨應用程式部署：

```typescript title="src/mastra/index.ts"
import { Mastra } from '@mastra/core'
import { MastraEditor } from '@mastra/editor'

export const mastra = new Mastra({
  agents: {/* existing agents */},
  editor: new MastraEditor({
    source: 'code',
    codePath: './mastra/editor',
  }),
})
```

此模式下，每個編輯過的 Agent 都有一個 JSON 覆寫檔案。Editor 不會產生 TypeScript，亦不會更改建立 Agent 的原始檔。預設 ID 為 `support-agent` 的 Agent 對應以下檔案：

```text
mastra/editor/agents/support-agent.json
```

檔案只包含由 Editor 管理的部分。例如：

```json title="mastra/editor/agents/support-agent.json"
{
  "instructions": "Help customers with Acme products and answer in their language.",
  "tools": {
    "searchOrders": {
      "description": "Look up an order by its number"
    }
  }
}
```

Agent 的模型、名稱及其他由程式碼管理的欄位仍留在 TypeScript 檔案中。Mastra 會讀取 JSON，並在 Agent 執行時套用這些值。

協作者在 Studio 儲存時，可以將檔案寫入本機檔案系統或下載。整合版本控制後，Studio 亦可改為建立拉取請求，再由 Git 提供審查及版本記錄。

檔案位置及來源選項詳見 [`MastraEditor`](/reference/editor/mastra-editor#source)。

## 版本控制 {/* #versioning */}

資料庫支援的 Agent 和提示區塊分為草稿版及已發布版。儲存會建立草稿，線上 Agent 繼續使用已發布版；發布後草稿才會生效。還原舊版本亦會建立草稿，供協作者測試後再發布。

以程式碼為基礎的 Agent 覆寫設定使用 JSON 檔案及 Git 版本記錄。

### 選擇版本 {/* #select-a-version */}

應用程式可按每個請求，透過傳入狀態（`published` 或 `draft`）或指定版本 ID 選用已儲存的版本：

```typescript title="Version selection"
const publishedAgent = await mastra.getAgentById('support-agent', {
  status: 'published',
})

const draftAgent = await mastra.getAgentById('support-agent', {
  status: 'draft',
})

const versionedAgent = await mastra.getAgentById('support-agent', {
  versionId: 'abc-123',
})
```

版本選擇支援：

* 在 A/B 測試中比較兩個版本。
* 在向所有人發布之前，先將草稿分發給一個小組。
* 保持發布版本的生產，同時使用最新的草稿。
* 將客戶固定到特定版本。

主管 Agent 呼叫子 Agent 時，亦可使用相同的版本控制。開發者可測試子 Agent 草稿，而不影響系統其他部分。

版本選擇、子 Agent 行為、REST 端點及 SDK 方法詳見 [Editor 版本參考文件](/reference/editor/versioning)。

## 可見性 {/* #visibility */}

設定 [`server.auth`](/docs/auth/overview) 後，每個已儲存的 Agent 都有擁有者及 `visibility`。在 Studio、透過 `POST /api/stored/agents` 或[內置 MCP 伺服器](/docs/server/mcp)建立的 Agent 歸建立者所有；除非設定 `visibility: 'public'`，否則預設為 `private`。擁有者是呼叫者透過 `mapUserToResourceId` 取得的資源 ID；未使用此映射時則取用戶的 `id`。未設定 `server.auth`，或呼叫者兩者皆無時，已儲存的 Agent 沒有擁有者，為 `public`，所有呼叫者都能使用。

| 身分 | 可查看及呼叫私人 Agent | 可編輯或刪除 |
| - | - | - |
| 擁有者 | 是 | 是 |
| 擁有 `*`、`stored-agents:*` 或 `stored-agents:admin` 的用戶 | 是 | 是 |
| 按 Agent ID 獲授權的用戶，例如 `stored-agents:read:support-agent` 或 `stored-agents:edit:support-agent` | 有 `read` 權限時可查看；`execute` 權限只允許呼叫 | 有 `edit` 或 `delete` 權限時可以 |
| 其他人 | 否 | 否 |

此表只說明擁有權規則。每條路由仍會檢查自身權限，例如編輯需要 `stored-agents:write`、呼叫需要 `agents:execute`；因此管理員權限或按 ID 授權還須配合路由權限。按 ID 授權只在用該 ID 請求 Agent 時生效，Agent 仍不會出現在這些用戶的 `GET /api/agents` 或 `GET /api/stored/agents` 清單中。

`public` Agent 可供所有用戶查看及呼叫，但只有表中的用戶能編輯或刪除。加入擁有者機制前儲存的 Agent 仍對所有人可見，任何具備路由權限的用戶都能編輯或刪除。程式碼定義的 Agent 不受影響，包括使用 Editor 覆寫值的 Agent。

這些規則適用於所有查詢 Agent 的路由，不限於 `/api/stored/agents`。對其他用戶而言，私人 Agent 就像不存在：`GET /api/agents` 不會列出它；該 Agent 的詳情、版本、Workspace 和排程路由傳回 `404`；記憶路由則按 Agent 不存在的情況回應。執行時透過 `POST /api/agents/:agentId/model` 更改模型需要編輯權限。`POST /api/agents/:agentId/clone` 會讓呼叫者成為私人副本的擁有者，並忽略請求主體中的 `authorId`。

## 程式化訪問 {/* #programmatic-access */}

Studio 提供的所有功能，亦可透過 [`mastra.getEditor()`](/reference/core/getEditor)、REST API 或 Client SDK 以程式方式使用。可用來編寫批量更新腳本，或從程式碼初始化已儲存的設定，亦可支援按[評估結果](/docs/evals/experiments)自動調整 Agent。

應用程式程式碼可存取 Mastra 實例時，呼叫 `mastra.getEditor()`：

```typescript title="src/scripts/update-agent.ts"
import { mastra } from '../mastra'

const editor = mastra.getEditor()!

await editor.agent.update({
  id: 'support-agent',
  instructions: 'Help customers with Acme products. Reply in their language.',
})
```

直接呼叫 `editor.agent.update()` 會將改動後的快照欄位儲存為新版本，但新版本起初是不啟用的草稿。只有明確傳入 `status` 或 `activeVersionId` 等紀錄欄位時，此方法才會更改它們。發布前，線上 Agent 仍使用先前版本。如要發布，請先取得草稿的版本 ID（例如透過 Client SDK 的 `listVersions()`），再明確指定：

```typescript title="src/scripts/publish-agent.ts"
await editor.agent.update({
  id: 'support-agent',
  status: 'published',
  activeVersionId: versionId,
})
```

已儲存 Agent 的 REST API 遵循相同規則。`PATCH /api/stored/agents/support-agent` 預設建立未啟用的草稿，除非設定 `autoPublish: true`；`POST /api/stored/agents/support-agent/versions/:versionId/activate` 則發布現有版本。

預設伺服器路徑前綴為 `/api`。開發者可在伺服器設定中自訂前綴。

草稿、發布及還原的生命週期詳見 [Editor 版本參考文件](/reference/editor/versioning)；可用操作詳見 [`MastraEditor` 命名空間](/reference/editor/mastra-editor#namespaces)及 [Client SDK Agent API](/reference/client-js/agents#stored-agents)。
