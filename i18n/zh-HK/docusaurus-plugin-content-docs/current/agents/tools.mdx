# 工具

Agent 使用工具呼叫 API、查詢數據庫，也可以執行程式碼庫中的自訂函式。工具讓 Agent 能以結構化方式存取數據並執行明確的操作，從而具備文字生成之外的能力。你還可以從遠端 [MCP Server](/docs/connections/mcp) 載入工具，擴展 Agent 的能力。對於 Linear、Slack 和 GitHub 等服務，Mastra 平台上的 [Connect](/docs/mastra-platform/connect#add-tools-to-an-agent) 提供帶有託管憑證的現成工具，也可以與自訂工具搭配使用。

<Inject>
  **供 AI Agent 參考：** `execute` 只有一種簽名：`execute(inputData, context)`。第一個參數按 `inputSchema` 驗證。執行時始終提供第二個參數，其中包含 `requestContext`、`tracingContext`、`abortSignal` 等執行元數據；不使用時可在函式簽名中省略。其他簽名形式已過時。直接執行 `npx mastra api tool execute weather-tool '{"location":"San Francisco"}'` 測試該工具，無需編寫臨時腳本。此命令需要執行中的 Mastra Server：可用 `npx mastra dev` 啟動本地服務，或透過 `--url` 指定可存取服務的基本網址。構造其他輸入前，先執行 `npx mastra api tool execute --schema`。執行 `npx skills add mastra-ai/skills --skill mastra` 安裝 Mastra Skill，取得完整的 API CLI 發現、目標定位、Schema、身份驗證及錯誤處理指南。
</Inject>

## 何時使用工具 {/* #when-to-use-tools */}

當 Agent 需要從遠端資源取得更多上下文或資訊，或者需要執行程式碼以完成特定操作時，可以使用工具。例如取得即時數據、傳回格式一致且定義明確的結果，這些任務僅靠模型無法可靠完成。

## 快速開始 {/* #quickstart */}

從 `@mastra/core/tools` 匯入 [`createTool`](/reference/tools/create-tool)，然後定義包含 `id`、`description`、`inputSchema`、`outputSchema` 和 `execute` 的工具。

以下例子建立一個從 API 取得天氣數據的工具。`execute` 只有一種簽名：`execute(inputData, context)`。第一個參數是經過 `inputSchema` 驗證的輸入；執行時始終將執行上下文作為第二個參數傳入，不使用時可在函式簽名中省略。也可以直接在函式簽名中解構輸入欄位。

```typescript title="src/mastra/tools/weather-tool.ts"
import { createTool } from '@mastra/core/tools'
import { z } from 'zod'

export const weatherTool = createTool({
  id: 'weather-tool',
  description: 'Fetches weather for a location',
  inputSchema: z.object({
    location: z.string(),
  }),
  outputSchema: z.object({
    location: z.string(),
    temperatureCelsius: z.number(),
    conditions: z.string(),
  }),
  execute: async ({ location }, { abortSignal }) => {
    const response = await fetch(`https://wttr.in/${location}?format=j1`, {
      signal: abortSignal,
    })
    const data = await response.json()

    return {
      location,
      temperatureCelsius: Number(data.current_condition[0].temp_C),
      conditions: data.current_condition[0].weatherDesc[0].value,
    }
  },
})
```

建立工具時，描述應簡潔，聚焦工具的主要用途。描述清楚的 Schema 名稱也有助於 Agent 判斷如何使用工具。有關屬性、設定和例子，請參閱 [`createTool` 參考文檔](/reference/tools/create-tool)。

要讓 Agent 使用工具，請將其加入到 `Agent` 類的 `tools` 屬性。在 Agent 的系統提示詞中說明可用工具及其大致用途，有助於它判斷何時呼叫工具。

```typescript {11} title="src/mastra/agents/weather-agent.ts"
import { Agent } from '@mastra/core/agent'
import { weatherTool } from '../tools/weather-tool'

export const weatherAgent = new Agent({
  id: 'weather-agent',
  name: 'Weather Agent',
  instructions: `
    You are a helpful weather assistant.
    Use the weatherTool to fetch current weather data.`,
  model: '__GATEWAY_OPENAI_MODEL__',
  tools: { weatherTool },
})
```

### 處理輸出驗證失敗 {/* #handle-output-validation-failures */}

如果結果不符合 `outputSchema`，Mastra 會記錄警告，並傳回驗證錯誤對象而非實際結果。模型會將此次呼叫視為失敗，可能再次呼叫。對於結果產生時已完成副作用的工具，應設定 `outputValidation: 'warn'`：Mastra 仍會記錄不匹配，但會原樣傳回實際結果，避免模型重複下單等操作。

```typescript title="src/mastra/tools/place-order-tool.ts"
import { createTool } from '@mastra/core/tools'
import { z } from 'zod'

export const placeOrderTool = createTool({
  id: 'place-order',
  description: 'Places an order and returns its id and total',
  inputSchema: z.object({ sku: z.string(), quantity: z.number().int().positive() }),
  outputSchema: z.object({ orderId: z.string(), total: z.number() }),
  outputValidation: 'warn',
  execute: async ({ sku, quantity }) => {
    return await orders.create({ sku, quantity })
  },
})
```

## 使用多個工具 {/* #multiple-tools */}

Agent 可以將複雜任務的不同部分交給多個工具處理。它會依據用戶訊息、自身指令，以及工具描述和 Schema 決定使用哪些工具。

```typescript {13} title="src/mastra/agents/weather-agent.ts"
import { Agent } from '@mastra/core/agent'
import { weatherTool } from '../tools/weather-tool'
import { hazardsTool } from '../tools/hazards-tool'

export const weatherAgent = new Agent({
  id: 'weather-agent',
  name: 'Weather Agent',
  instructions: `
    You are a helpful weather assistant.
    Use the weatherTool to fetch current weather data.
    Use the hazardsTool to provide information about potential weather hazards.`,
  model: '__GATEWAY_OPENAI_MODEL__',
  tools: { weatherTool, hazardsTool },
})
```

## 將 Agent 用作工具 {/* #agents-as-tools */}

透過 `agents` 設定加入子 Agent，即可建立 [Supervisor](/docs/subagents)。Mastra 會把每個子 Agent 轉換為 `agent-<key>` 工具。為每個子 Agent 提供 `description`，幫助 Supervisor 判斷何時委派任務。

```typescript title="src/mastra/agents/supervisor.ts"
import { Agent } from '@mastra/core/agent'

const writer = new Agent({
  id: 'writer',
  name: 'Writer',
  description: 'Drafts and edits written content',
  instructions: 'You are a skilled writer.',
  model: '__GATEWAY_OPENAI_MODEL__',
})

export const supervisor = new Agent({
  id: 'supervisor',
  name: 'Supervisor',
  instructions: 'Coordinate the writer to produce content.',
  model: '__GATEWAY_OPENAI_MODEL__',
  // highlight-next-line
  agents: { writer },
})
```

## 將 Workflow 用作工具 {/* #workflows-as-tools */}

透過 `workflows` 設定加入 Workflow。Mastra 會將每個 Workflow 轉換為 `workflow-<key>` 工具，並使用其 `inputSchema` 和 `outputSchema`。為 Workflow 提供 `description`，幫助 Agent 判斷何時觸發它。

```typescript title="src/mastra/agents/research-agent.ts"

})
```

## 調整模型接收的輸出 {/* #shape-output-for-the-model */}

如果工具傳回了應用所需的豐富結構化數據，但只需給模型較簡短或多模態的內容，可以使用 `toModelOutput`。這樣既能讓模型上下文保持精簡，又能在應用中保留完整的工具結果。

```typescript title="src/mastra/tools/weather-tool.ts"
import { createTool } from '@mastra/core/tools'

export const weatherTool = createTool({
  execute: async ({ location }) => {
    const response = await fetch(`https://wttr.in/${location}?format=j1`)
    const data = await response.json()

    return {
      location,
      temperatureCelsius: Number(data.current_condition[0].temp_C),
      conditions: data.current_condition[0].weatherDesc[0].value,
      weatherIconUrl: data.current_condition[0].weatherIconUrl[0].value,
      source: data,
    }
  },
  toModelOutput: output => {
    return {
      type: 'content',
      value: [
        {
          type: 'text',
          text: `${output.location}: ${output.temperatureCelsius}°C and ${output.conditions}`,
        },
        { type: 'image-url', url: output.weatherIconUrl },
      ],
    }
  },
})
```

`toModelOutput` 也適用於客戶端工具。透過 `clientTools` 傳入的工具在客戶端執行後，由客戶端完成映射，並將轉換後的輸出與原始結果一同傳送給伺服器。對於定義在伺服器上但沒有 `execute` 函式的工具（由瀏覽器執行，並在下一次請求中傳送結果），伺服器端定義中的 `toModelOutput` 會處理傳入的結果。模型接收轉換後的內容，而不是原始工具結果。

## 在客戶端執行的工具 {/* #tools-that-run-on-the-client */}

沒有 `execute` 函式的工具是客戶端工具，伺服器無法執行它。模型呼叫該工具時，Agent 會在當前步驟停止；本次執行以 `finishReason: 'tool-calls'` 結束，直到工具傳回結果，模型才會繼續生成文字。依據模型是否需要結果選擇相應模式：

- **客戶端執行工具，模型需要結果**：省略 `execute`。客戶端執行工具，將結果加入對話，再發起新請求，讓 Agent 繼續執行。使用 AI SDK 的 `useChat()` 時，請參閱[配合 `useChat()` 使用客戶端工具](/integrations/agentic-ui/ai-sdk-ui#client-tools-with-usechat)。
- **客戶端只需渲染工具呼叫**（例如商品卡片）：提供傳回簡短確認資訊的 `execute`。Agent 會在同一次執行中繼續執行，客戶端依據工具輸入渲染相應內容。傳回簡短值即可，不要重複傳回輸入，以免擴大模型上下文和已儲存的訊息。
- **工具需要用戶提供結構化回答**（例如確認寫入購物車）：在 `execute` 中呼叫 `suspend()`，收到用戶回答後恢復執行。參閱[使用 `suspend()` 在執行時暫停](/docs/agents/human-in-the-loop#runtime-suspension-with-suspend)。

```typescript title="src/mastra/tools/show-product-tool.ts"
import { createTool } from '@mastra/core/tools'
import { z } from 'zod'

export const showProductTool = createTool({
  id: 'show-product',
  description: 'Shows a product card to the user',
  inputSchema: z.object({
    productId: z.string(),
  }),
  // highlight-next-line
  execute: async () => ({ rendered: true }),
})
```

子 Agent 無法執行客戶端工具。如果子 Agent 呼叫沒有 `execute` 的工具，它的執行會停止，Supervisor 會在委派結果的 `subAgentPendingToolCalls` 中收到未完成的工具呼叫。可以把客戶端工具交給 Supervisor，或在子 Agent 的工具中使用 `suspend()`。暫停會傳遞到 Supervisor，參閱[在 Supervisor Agent 中使用 `suspend()`](/docs/agents/human-in-the-loop#use-suspend-in-supervisor-agents)。

## 轉換供 UI 和對話記錄使用的工具數據 {/* #transform-tool-payloads-for-ui-and-transcripts */}

如果工具傳回應用所需的原始數據，但瀏覽器端的流或用戶可見的對話記錄只應接收更精簡、更安全的數據格式，可以使用 `transform`。`transform` 與 `toModelOutput` 分工不同：`toModelOutput` 調整傳回模型的數據；`transform` 則針對 `display` 和 `transcript` 目標，調整工具輸入、輸出、錯誤、審批數據和暫停數據。

工具級 `transform` 只處理明確定義的階段。以下例子僅轉換 `output`，因此儲存的工具輸入保持不變。如果已設定的轉換失敗，Mastra 不會為 `display` 或 `transcript` 目標回退到原始數據。沒有可用的安全 `inputDelta` 轉換時，輸入增量會被抑制。

以下例子會從兩個目標的數據中移除機密資訊：

```typescript title="src/mastra/tools/customer-tool.ts"
import { createTool } from '@mastra/core/tools'
import { z } from 'zod'

export const customerTool = createTool({
  id: 'lookup-customer',
  description: 'Looks up a customer by id',
  inputSchema: z.object({
    customerId: z.string(),
  }),
  outputSchema: z.object({
    ssn: z.string(),
  }),
  execute: async ({ customerId }) => {
    // const response = await fetch(`https://your-crm.example.com/customers/${customerId}`)
    // const { ssn } = await response.json()
    return {
      ssn: '123-45-6789',
    }
  },
  // highlight-start
  transform: {
    display: {
      output: () => ({ ssn: '***-**-****' }),
    },
    transcript: {
      output: () => ({ ssn: '***-**-****' }),
    },
  },
  // highlight-end
})
```

應用程式的程式碼仍會收到工具傳回的原始 `ssn`。瀏覽器端的流接收 `display` 輸出，用戶可見的對話記錄接收 `transcript` 輸出。

如果 DurableAgent 可以在進程重啟後完成工具呼叫，應在工具的 `transform.transcript` 設定中聲明必要的對話記錄脫敏規則。傳給 DurableAgent 單次呼叫的轉換只保存在進程內的執行註冊表中，新進程無法恢復。持久化 Worker 會重新從已註冊的工具讀取工具級轉換設定。

其他階段包括 `input`、`inputDelta`、`error`、`approval`、`suspend` 和 `resume`，參閱 [`createTool()` 參考文檔](/reference/tools/create-tool#example-with-transform)。如需對多個工具使用同一規則，可在 [`Agent` 構造函式](/reference/agents/agent#constructor-parameters)中設定 Agent 級 `transform` 策略。

## 在工具呼叫前後執行邏輯 {/* #run-logic-around-tool-calls */}

使用 `hooks` 可以在 Agent 每次呼叫工具之前和之後執行自訂邏輯。Hook 適用於所有工具來源：直接分配的工具、Memory 工具、Toolset、客戶端工具、Agent 和 Workflow 工具，以及[工作區工具](/reference/workspace/workspace-class#tool-hooks)。常見用途包括日誌、審計、輸入驗證和攔截特定呼叫。

```typescript title="src/mastra/agents/support-agent.ts"
import { Agent } from '@mastra/core/agent'
import { db } from '../db' // your application database client

export const supportAgent = new Agent({
  id: 'support-agent',
  name: 'support-agent',
  instructions: 'Help users with their questions.',
  model: '__GATEWAY_OPENAI_MODEL__',
  // highlight-start
  hooks: {
    beforeToolCall: ({ toolName, input }) => {
      console.log(`Running ${toolName}`, input)
    },
    afterToolCall: async ({ toolName, input, output, error }) => {
      await db.auditLog.insert({
        toolName,
        input,
        output,
        error: error ? String(error) : undefined,
      })
    },
  },
  // highlight-end
})
```

`afterToolCall` 必須傳回 `void`（或 `Promise<void>`）。等待儲存操作完成，但不要傳回其結果。如果儲存操作拋錯，工具呼叫也會因此失敗；若審計日誌只需盡力寫入，應在 Hook 內捕獲錯誤。對於被 `beforeToolCall` 跳過或被拒絕的[執行前審批](/docs/agents/human-in-the-loop#pre-execution-approval)，`afterToolCall` 不會執行，應在處理這些決定的位置記錄。

`beforeToolCall` 在工具執行前執行，會收到工具名稱、輸入和執行上下文。傳回 `{ proceed: false, output }` 可完全跳過此次呼叫，Agent 會將 `output` 作為工具結果：

```typescript
const guardedAgent = new Agent({
  id: 'guarded-agent',
  name: 'guarded-agent',
  instructions: 'Run shell commands for the user.',
  model: '__GATEWAY_OPENAI_MODEL__',
  hooks: {
    beforeToolCall: ({ toolName, input }) => {
      const command = (input as { command?: string }).command ?? ''
      if (toolName === 'execute_command' && command.includes('rm -rf')) {
        return { proceed: false, output: 'Command blocked by policy.' }
      }
    },
  },
})
```

`afterToolCall` 在工具執行結束後執行，無論成功還是失敗。成功時收到 `output`；如果工具拋錯，則收到 `error`，Hook 執行後該錯誤會重新拋出。

### 為單次執行設定 Hook {/* #per-execution-hooks */}

向 `.generate()` 或 `.stream()` 傳入 `hooks`，即可只為該次執行設定 Hook。單次執行的 Hook 會覆蓋同名的 Agent 級 Hook：

```typescript
await supportAgent.generate('Look up the order status', {
  hooks: {
    beforeToolCall: ({ toolName }) => {
      console.log(`This run only: ${toolName}`)
    },
  },
})
```

Agent 級和單次執行的 Hook 按鍵合併：單次執行只提供 `beforeToolCall` 時，Agent 層級的 `afterToolCall` 仍會保留。

## 串流處理 {/* #streaming */}

工具支援生命週期 Hook，用於監測串流執行的不同階段，尤其適合日誌和分析。

有關 `writer` API 的一般用法，請參閱[串流處理](/docs/guides/streaming#writer-api)。

### 可用的 Hook {/* #available-hooks */}

- **onInputStart**：工具呼叫的輸入開始以串流方式傳入時觸發
- **onInputDelta**：每收到一段輸入時觸發
- **onInputAvailable**：完整輸入解析並驗證後觸發
- **onOutput**：工具成功執行並產生輸出後觸發

有關所有生命週期 Hook 的詳細說明，請參閱 [`createTool()` 參考文檔](/reference/tools/create-tool#tool-lifecycle-hooks)。

### 例子：使用 `onInputAvailable` 和 `onOutput` {/* #example-using-oninputavailable-and-onoutput */}

```typescript
import { createTool } from '@mastra/core/tools'
import { z } from 'zod'

export const weatherTool = createTool({
  id: 'weather-tool',
  description: 'Get weather information',
  inputSchema: z.object({
    location: z.string(),
  }),
  outputSchema: z.object({
    location: z.string(),
    temperatureCelsius: z.number(),
    conditions: z.string(),
  }),
  // Called when the complete input is available
  onInputAvailable: ({ input, toolCallId }) => {
    console.log(`Weather requested for: ${input.location}`)
  },
  execute: async ({ location }) => {
    const weather = await fetchWeather(location)
    return weather
  },
  // Called after successful execution
  onOutput: ({ output, toolName }) => {
    console.log(`${toolName} result: ${output.temperatureCelsius}°C, ${output.conditions}`)
  },
})
```

### 在 UI 中顯示串流工具輸入 {/* #streaming-tool-input-in-uis */}

模型生成工具呼叫時，參數先透過 `tool-call-delta` 串流區塊逐步到達，之後才會產生最終的 `tool-call` 串流區塊。UI 可以監聽相應的 `tool_input_start`、`tool_input_delta` 和 `tool_input_end` 事件，邊接收邊渲染參數，例如無需等待完整呼叫就顯示檔案路徑或命令。

對累計的 `argsTextDelta` 片段使用部分 JSON 解析器，可在 JSON 尚未完整時提取可用的參數值。這支援即時差異預覽（編輯工具）、串流檔案內容（寫入工具），以及即時顯示搜索模式或檔案路徑。

## 控制工具選擇 {/* #control-tool-selection */}

在執行時向 `.generate()` 或 `.stream()` 傳入 `toolChoice` 或 `activeTools`，可控制 Agent 使用哪些工具。

```typescript
await agent.generate('Check the forecast', {
  toolChoice: 'required',
  activeTools: ['weatherTool'],
})
```

所有執行時選項（包括 `toolsets`、`clientTools` 和 `prepareStep`）請參閱 [`Agent.generate()` 參考文檔](/reference/agents/generate)。

## 控制流回應中的 `toolName` {/* #control-toolname-in-stream-responses */}

流回應中的 `toolName` 由你使用的**對象鍵名**決定，而不是工具、Agent 或 Workflow 的 `id` 屬性。

```typescript oxfmt:false
export const weatherTool = createTool({
  id: 'weather-tool',
})

// Using the variable name as the key
tools: { weatherTool }
// Stream returns: toolName: "weatherTool"

// Using the tool's id as the key
tools: { [weatherTool.id]: weatherTool }
// Stream returns: toolName: "weather-tool"

// Using a custom key
tools: { "my-custom-name": weatherTool }
// Stream returns: toolName: "my-custom-name"
```

這樣可以指定工具在流中的名稱。如果希望 `toolName` 與工具的 `id` 一致，請將工具的 `id` 用作對象鍵名。

### 將子 Agent 和 Workflow 用作工具 {/* #subagents-and-workflows-as-tools */}

子 Agent 和 Workflow 遵循同一規則：Mastra 會將對象鍵名前加上相應前綴，作為工具名稱：

| 屬性 | 前綴 | 例子鍵名 | `toolName` |
| - | - | - | - |
| `agents` | `agent-` | `weather` | `agent-weather` |
| `workflows` | `workflow-` | `research` | `workflow-research` |

```typescript
const orchestrator = new Agent({
  id: 'orchestrator',
  agents: {
    weather: weatherAgent, // toolName: "agent-weather"
  },
  workflows: {
    research: researchWorkflow, // toolName: "workflow-research"
  },
})
```

因此，對於子 Agent，你會在流回應中看到兩個不同的標識符：

- 工具呼叫事件中的 `toolName: "agent-weather"`：生成的工具包裝器名稱
- `data-tool-agent` 串流區塊中的 `id: "weather-agent"`：子 Agent 實際的 `id` 屬性

## 內建工具 {/* #built-in-tools */}

Mastra 在 `@mastra/core/tools` 中提供與 Agent 無關的內建工具，為 Agent 加入交互和組織能力。

每個工具都有兩個名稱：程式碼中匯入的導出名，以及模型在工具呼叫、Trace 和 `toolName` 欄位中看到的工具 ID。

| 導出名 | 工具 ID | 用途 |
| - | - | - |
| `askUserTool` | `ask_user` | 向用戶提問並等待回答 |
| `submitPlanTool` | `submit_plan` | 提交計劃檔案供用戶審批 |
| `taskWriteTool` | `task_write` | 建立或替換結構化任務列表 |
| `taskUpdateTool` | `task_update` | 按 ID 更新一項已跟蹤任務 |
| `taskCompleteTool` | `task_complete` | 將一項已跟蹤任務標記為完成 |
| `taskCheckTool` | `task_check` | 檢查任務列表的完成狀態 |
| `webSearchTool` | `<provider.defined>` | 執行當前 Provider 的原生網頁搜索 |
| `webFetchTool` | `web_fetch` | 按 URL 取得網頁並傳回其文字內容 |

### 使用 Provider 的網頁搜索 {/* #use-provider-web-search */}

需要模型 Provider 執行其原生網頁搜索工具時，從 `@mastra/core/tools` 匯入 `webSearchTool`。Mastra 會在執行時依據當前模型解析該工具，再將由 Provider 管理的工具傳給模型。

```typescript {2,10} title="src/mastra/agents/research-agent.ts"
import { Agent } from '@mastra/core/agent'
import { webSearchTool } from '@mastra/core/tools'

export const researchAgent = new Agent({
  id: 'research-agent',
  name: 'Research Agent',
  instructions: 'Use web search when you need current information.',
  model: 'openai/gpt-5.6-sol',
  tools: {
    search: webSearchTool,
  },
})
```

`webSearchTool` 支援 OpenAI、Anthropic、Google Gemini 和 xAI 模型。如果 Mastra 無法從當前模型識別這幾種 Provider，Agent 執行會因 `MastraError` 失敗。

解析後的工具 ID 由 Provider 決定：`openai.web_search`、`anthropic.web_search_20250305`、`google.google_search` 或 `xai.web_search`。

透過 Mastra Gateway 提供的模型（例如 `mastra/openai/gpt-5.6-sol`）會改用 Gateway 自帶的網頁搜索（`openrouter.web_search`）。Gateway 網頁搜索的結果會直接出現在模型的文字回應中，不會產生單獨的工具呼叫塊或來源塊。Gateway 不支援其他 Provider 原生工具，傳入這類工具會使 Agent 執行因 `MastraError` 失敗。

`search` 鍵只是 Agent 內部的工具名稱；可以使用任意鍵名。`webSearchTool` 的值告訴 Mastra 使用 Provider 的網頁搜索。

### 取得網頁 {/* #fetch-a-web-page */}

需要 Agent 讀取指定 URL 時，從 `@mastra/core/tools` 匯入 `webFetchTool`。該工具透過 HTTP 或 HTTPS 請求頁面，並傳回文字內容及回應元數據。

```typescript {2,10} title="src/mastra/agents/reader-agent.ts"
import { Agent } from '@mastra/core/agent'
import { webFetchTool } from '@mastra/core/tools'

export const readerAgent = new Agent({
  id: 'reader-agent',
  name: 'Reader Agent',
  instructions: 'Fetch the page the user links to before answering.',
  model: 'openai/gpt-5.6-sol',
  tools: {
    fetch: webFetchTool,
  },
})
```

工具接受一個 `url` 輸入，並傳回 `content`、`truncated`、`status`、`statusText`、`contentType`、`url` 和 `ok`。它有以下限制：

- 只允許 `http:` 和 `https:` URL。
- 禁止請求 `localhost` 和私有或保留 IP 地址，包括 DNS 解析後指向這些地址的域名。
- 回應最多保留 100,000 個字符；截斷時結果中的 `truncated: true`。
- 請求最多跟隨 5 次重定向，超時時間為 15 秒。

失敗時不會拋錯。工具會傳回 `isError: true`，並在 `content` 中說明原因，以便 Agent 重試或解釋問題。

### 向用戶提問 {/* #ask-the-user-a-question */}

匯入 [`askUserTool`](/reference/tools/ask-user-tool) 並將其加入到 Agent 的工具集中。

該工具會暫停執行，並傳送帶有問題的 `tool-call-suspended` 事件。使用用戶回答呼叫 `resumeStream()` 後，執行會繼續。

```typescript title="src/mastra/agents/index.ts"
import { Agent } from '@mastra/core/agent'
import { askUserTool } from '@mastra/core/tools'

const agent = new Agent({
  id: 'assistant',
  name: 'Assistant',
  instructions: 'Ask the user for clarification when the request is ambiguous.',
  model,
  tools: { askUserTool },
})
```

以串流方式執行 Agent 並監聽 `tool-call-suspended` 串流區塊。`suspendPayload` 中包含問題和可選的結構化選項：

```typescript title="src/run.ts"
const stream = await agent.stream('Summarize my project')

for await (const chunk of stream.fullStream) {
  if (chunk.type === 'tool-call-suspended') {
    const { question, options } = chunk.payload.suspendPayload
    console.log(question)
    const answer = await getUserAnswer() // your UI logic
    const resumed = await agent.resumeStream(answer, { runId: stream.runId })
    for await (const c of resumed.textStream) process.stdout.write(c)
  }
}
```

`askUserTool` 支援自由文字、單選（`options` 陣列）和多選（`selectionMode: 'multi_select'`）問題。將它與 `autoResumeSuspendedTools` 配合使用，Agent 即可在用戶傳送下一條聊天訊息後自動恢復。詳見[工具自動恢復](/docs/agents/human-in-the-loop#automatic-tool-resumption)。

### 提交計劃供審核 {/* #submit-a-plan-for-review */}

匯入 [`submitPlanTool`](/reference/tools/submit-plan-tool)，即可讓 Agent 將計劃寫入檔案並提交給用戶審核。該工具會暫停執行，直到用戶批准或拒絕：

```typescript title="src/run.ts"
for await (const chunk of stream.fullStream) {
  if (chunk.type === 'tool-call-suspended' && chunk.payload.toolName === 'submit_plan') {
    const { path } = chunk.payload.suspendPayload
    // Read and display the plan file, then resume:
    const resumed = await agent.resumeStream({ action: 'approved' }, { runId: stream.runId })
    for await (const c of resumed.textStream) process.stdout.write(c)
  }
}
```

### 任務跟蹤 {/* #task-tracking */}

任務工具用於管理 Agent 執行期間的結構化持久任務列表。它們需要 [Memory](/docs/memory/overview)，才能將任務列表保存在某個 Thread 的儲存空間內。

透過 [`TaskSignalProvider`](/reference/signals/task-signal-provider) 一次註冊四個工具和 `TaskStateProcessor`，即可啟用任務跟蹤：

```typescript title="src/mastra/agents/index.ts"
import { Agent } from '@mastra/core/agent'
import { Memory } from '@mastra/memory'
import { TaskSignalProvider } from '@mastra/core/signals'

const agent = new Agent({
  id: 'coder',
  name: 'Coder',
  instructions: 'Track your progress with the task tools.',
  model,
  memory: new Memory(),
  signals: [new TaskSignalProvider()],
})
```

同一時間只能有一個任務處於 `in_progress` 狀態。任務列表保存在 Thread 範圍內的 `threadState` 儲存域，並投射到 Agent 的[狀態訊號](/docs/signals/state-signals)通道，因此即使 Observational Memory 截斷上下文，任務仍會保留。完整 Schema 參閱[任務工具參考文檔](/reference/tools/task-tools)。

[AgentController](/docs/harness/agent-controller) 會在每種模式下自動加入所有內建工具，無需手動加入。關於 AgentController 的特定行為，請參閱[工具審批](/docs/harness/agent-controller#approve-tools-and-resume-suspensions)。
