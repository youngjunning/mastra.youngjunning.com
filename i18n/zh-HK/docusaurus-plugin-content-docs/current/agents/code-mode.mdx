# 程式碼模式

**新增於：** `@mastra/core@1.38.0`

程式碼模式容許 Agent 在隔離的 Sandbox 中運用多個 Tool 進行運算，並將結果整合成一份更準確的回應。

模型會將逐輪呼叫 Tool 的工作交由函式處理，並按用戶的問題編寫函式，透過 `external_*` 函式協調現有 Tool，並將結果精簡或匯總為一份結構化答案。

[`createCodeMode()`](/reference/tools/create-code-mode) 回傳此 Tool，預設 `id` 為 `execute_typescript`。設定不同的 `id`，便可讓同一 Agent 同時使用多個程式碼模式 Tool，並個別限定可呼叫的 Tool（見[設定多個程式碼 Tool 的權限範圍](#scoping-tools-across-multiple-code-tools)）。

## 何時適合使用程式碼模式 {/* #when-to-use-code-mode */}

當 Agent 要透過多個 Tool 回答用戶問題或完成複雜運算，可使用程式碼模式：

- 減少來回呼叫：涉及多個 Tool 的查詢可在一次 Tool 呼叫內完成，毋須每次選擇 Tool 都重跑 Agent 迴圈。
- 縮減上下文：函式可先精簡或匯總內容較多的 Tool 回應，再交回 Agent。
- 準確計算：加總、求平均值等算術交由 JavaScript 處理，毋須依賴 token 預測。
- 預先規劃：篩選、匯總及分支處理集中在函式內，毋須分開多輪執行。

## 運作方式 {/* #how-it-works */}

未使用程式碼模式時，涉及多個 Tool 的查詢可能要經過數輪 Agent 迴圈。模型會選擇一個 Tool 並讀取結果，然後按需要重複。

每一輪都會將完整的 Tool 回應加入 Agent 的上下文視窗，可能影響推理表現，並增加 token 用量。

使用程式碼模式時，Tool 繼續在主機上運行，完整保留驗證、請求上下文及追蹤功能。只有模型編寫的協調程式碼在 Sandbox 內運行。每次 `external_*` 呼叫均會轉交主機上的實際 Tool，函式可先精簡或匯總結果，再一併回傳給 Agent。

函式會在 [Workspace 的 Sandbox](/docs/sandbox/overview) 內運行。程式碼由模型編寫，因此必須明確選定執行邊界：傳入 `sandbox`，或使用附有 Sandbox 的 Workspace。如需在主機上執行，須明確傳入 `new LocalSandbox()`。函式會以具備主機權限的 `node` 程序運行，因此只應用於可信或本機開發環境。

傳輸機制若自備執行邊界，則屬例外。[`IsolatedVmCodeModeTransport`](/reference/tools/isolated-vm-transport) 會在程序內的 V8 隔離環境運行程式，毋須 Sandbox（見[程序內隔離](#in-process-isolation)）。

## 快速入門 {/* #quickstart */}

`createCodeMode()` 回傳 Tool 及產生的指令。如未指定 `id`，Tool 便會以 `execute_typescript` 為名稱。將兩者一併加入 Agent：

```typescript
import { Agent } from '@mastra/core/agent'
import { createCodeMode, createTool } from '@mastra/core/tools'
import { LocalSandbox } from '@mastra/core/workspace'
import { z } from 'zod'

const getTopProducts = createTool({
  id: 'getTopProducts',
  description: 'Get top selling products',
  inputSchema: z.object({ limit: z.number() }),
  outputSchema: z.object({
    products: z.array(z.object({ id: z.string(), name: z.string(), totalSales: z.number() })),
  }),
  execute: async ({ limit }) => fetchTopProducts(limit),
})

const getProductRatings = createTool({
  id: 'getProductRatings',
  description: 'Get ratings for a product',
  inputSchema: z.object({ productId: z.string() }),
  outputSchema: z.object({ ratings: z.array(z.object({ score: z.number() })) }),
  execute: async ({ productId }) => fetchRatings(productId),
})

const { tool, instructions } = createCodeMode({
  tools: { getTopProducts, getProductRatings },
  sandbox: new LocalSandbox(), // required; runs on the host — see "How it works"
})

const agent = new Agent({
  id: 'shop-assistant',
  name: 'shop-assistant',
  instructions: ['You are a helpful shopping assistant.', instructions],
  model: '__GATEWAY_OPENAI_MODEL__',
  tools: { execute_typescript: tool },
})
```

例如用戶問「頭 5 位的產品有哪些？各自的平均評分是多少？」時，模型只會發出一次 `execute_typescript` 呼叫，集中處理多個 Tool 呼叫：

```typescript
const top = await external_getTopProducts({ limit: 5 })
const ratings = await Promise.all(
  top.products.map(p => external_getProductRatings({ productId: p.id })),
)
return top.products.map((product, i) => {
  const scores = ratings[i].ratings.map(r => r.score)
  const avg = scores.reduce((sum, s) => sum + s, 0) / scores.length
  return {
    name: product.name,
    sales: product.totalSales,
    averageRating: Math.round(avg * 100) / 100,
  }
})
```

五項評分查詢會並行執行，再由 JavaScript 計算平均值，最後將一份結構化結果交回 Agent。

要讓 `createCodeMode()` 有效運作，可留意以下做法：

- 讓各個 Tool 專責一項工作，由模型編寫程式碼將它們組合起來。
- 若多次呼叫可透過 `Promise.all` 並行執行，程式碼模式便最有幫助。

有關設定選項、回傳值、結果格式及查閱指令的方法，請見 [`createCodeMode()` 參考文件](/reference/tools/create-code-mode)。

## 設定多個程式碼 Tool 的權限範圍 {/* #scoping-tools-across-multiple-code-tools */}

`createCodeMode()` 每次呼叫都會保留獨立的許可清單。重複呼叫可為 Agent 建立多個程式碼 Tool，每個只可使用其中一組 Tool。各個實例只可呼叫該次 `createCodeMode()` 所接收的 Tool 對應的 `external_*` 函式，各組互相隔離。

為各個 Tool 指定不同的 `id`，避免識別碼衝突，並將各 Tool 的指令加入 Agent：

```typescript
const sales = createCodeMode({
  id: 'sales_code',
  tools: { listRecentOrders, getCustomer },
  sandbox,
})

const inventory = createCodeMode({
  id: 'inventory_code',
  tools: { listProducts, getSupplier },
  sandbox,
})

const agent = new Agent({
  id: 'ops-assistant',
  name: 'ops-assistant',
  instructions: ['You are an ops assistant.', sales.instructions, inventory.instructions],
  model: '__GATEWAY_OPENAI_MODEL__',
  tools: { sales_code: sales.tool, inventory_code: inventory.tool },
})
```

為 `sales_code` 產生的程式碼無法呼叫庫存 Tool，反過來亦然。這樣可按最小權限設定範圍，並減少每個 Tool 所需的提示內容。

## 已連接的 Tool {/* #connected-tools */}

如需協調已連接至 Mastra Platform 的 Provider 所提供的 Tool，可使用 [`tools().codeMode()`](/reference/connect/tools#code-mode)（來自 `@mastra/connect`）。每次收到請求時，它會根據目前的連接建立程式碼 Tool 和指令，並保留須經審批的 Tool，讓 Agent 直接呼叫。

## 遠端 Sandbox {/* #remote-sandboxes */}

預設傳輸方式會先將程式寫入主機的檔案系統，再用 `node` 執行。`LocalSandbox` 與主機共用檔案系統，因此適用。遠端 Sandbox（例如 [E2B](/integrations/sandboxes/e2b)）則在獨立的微型虛擬機內運行，主機上的路徑在其中並不存在。

遠端 Sandbox 須使用能將程式寫入其檔案系統的傳輸機制。如使用 E2B，請將隨附的 `E2BCodeModeTransport` 作為第二個參數傳給 `createCodeMode`：

```typescript
import { createCodeMode } from '@mastra/core/tools'
import { E2BSandbox, E2BCodeModeTransport } from '@mastra/e2b'

const { tool, instructions } = createCodeMode(
  { tools, sandbox: new E2BSandbox() },
  new E2BCodeModeTransport(),
)
```

## 程序內隔離 {/* #in-process-isolation */}

如要建立安全邊界，同時避免啟動新程序或使用遠端 Sandbox，可用 [`IsolatedVmCodeModeTransport`](/reference/tools/isolated-vm-transport)（來自 `@mastra/isolated-vm`）。它在程序內的 V8 隔離環境運行程式，毋須 Sandbox。該環境無法存取檔案系統、網絡或程序，只能透過 `external_*` 函式呼叫主機上的 Tool。

```typescript
import { createCodeMode } from '@mastra/core/tools'
import { IsolatedVmCodeModeTransport } from '@mastra/isolated-vm'

const { tool, instructions } = createCodeMode(
  { tools }, // no sandbox needed
  new IsolatedVmCodeModeTransport({ memoryLimitMb: 128 }),
)
```

`isolated-vm` 是原生擴充模組。在 Node.js 20 或以上版本，必須以 `--no-node-snapshot` 選項啟動主機程序。設定詳情見 [IsolatedVmCodeModeTransport 參考文件](/reference/tools/isolated-vm-transport)。

如主機無法安裝原生擴充模組或設定 Node.js 啟動選項（無伺服器平台常有此限制），可改用 [`QuickJsCodeModeTransport`](/reference/tools/quickjs-transport)（來自 `@mastra/quickjs`）。它使用編譯成 WebAssembly 的 QuickJS 執行環境，提供相同的程序內隔離，但執行速度較慢：

```typescript
import { createCodeMode } from '@mastra/core/tools'
import { QuickJsCodeModeTransport } from '@mastra/quickjs'

const { tool, instructions } = createCodeMode(
  { tools }, // no sandbox needed
  new QuickJsCodeModeTransport({ memoryLimitMb: 128 }),
)
```

如需比較各種傳輸方式，請見[選擇傳輸方式](/reference/tools/quickjs-transport#choosing-a-transport)。
