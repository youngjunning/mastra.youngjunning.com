# 人工介入

Agent 調用刪除資源或執行耗時任務等涉及敏感操作的 Tool 時，有時也需要與 Workflow 相同的[人工介入（HITL）](/docs/workflows/human-in-the-loop)機制。你可以在 Tool 執行前掛起調用，等待人工批准或拒絕；Tool 也可以自行掛起，向用戶請求更多信息。

## 何時使用人工介入 {/* #when-to-use-human-in-the-loop */}

- **破壞性或不可逆操作**：例如刪除記錄、發送郵件或處理付款。
- **高成本操作**：例如調用昂貴的第三方 API，需要先核對參數。
- **有條件的確認**：Tool 已開始執行，卻發現完成前還需要用戶確認或補充數據。

## 快速開始 {/* #quickstart */}

為 Tool 設定 `requireApproval: true`，再從流中檢查 `tool-call-approval` 資料區塊，以批准或拒絕操作：

```typescript title="src/mastra/agents/index.ts"
import { Agent } from '@mastra/core/agent'
import { createTool } from '@mastra/core/tools'
import { z } from 'zod'

const deleteTool = createTool({
  id: 'delete-record',
  description: 'Delete a record by ID',
  inputSchema: z.object({ id: z.string() }),
  outputSchema: z.object({ deleted: z.boolean() }),
  requireApproval: true,
  execute: async ({ id }) => {
    await db.delete(id)
    return { deleted: true }
  },
})

const agent = new Agent({
  id: 'my-agent',
  name: 'My Agent',
  model: '__GATEWAY_OPENAI_MODEL_LUNA__',
  tools: { deleteTool },
})

const stream = await agent.stream('Delete record abc-123')

for await (const chunk of stream.fullStream) {
  if (chunk.type === 'tool-call-approval') {
    const approved = await agent.approveToolCall({ runId: stream.runId })
    for await (const c of approved.textStream) process.stdout.write(c)
  }
}
```

:::note

人工介入使用快照保存請求狀態。請為 Mastra 實例配置[儲存提供方](/docs/storage)，否則會出現「snapshot not found」錯誤。

Agent 運行的快照是最小化的恢復數據：僅保存恢復掛起運行所需的信息，並在運行結束後刪除。執行記錄請使用[追蹤](/docs/observability/overview)，對話歷史請使用[記憶](/docs/memory/overview)。

:::

## 審批機制 {/* #how-approval-works */}

Mastra 提供兩種不同的 Tool 調用暫停機制：**執行前審批**和**運行時掛起**。

### 執行前審批 {/* #pre-execution-approval */}

執行前審批會在 Tool 的 `execute` 函數運行*之前*暫停調用。LLM 仍會選擇 Tool 並提供參數，但只有你明確批准後才會執行 `execute`。

這些選項採用 OR 邏輯：只要*任意一項*為 `true`，調用就會暫停：

| 選項 | 設定位置 | 作用範圍 |
| - | - | - |
| `requireToolApproval: true` | `stream()` / `generate()` 選項 | 暫停該請求中的**每一次** Tool 調用 |
| `requireApproval: true` | `createTool()` 定義 | 只暫停**該 Tool** 的調用 |

流會發出包含 `toolCallId`、`toolName` 和 `args` 的 `tool-call-approval` 資料區塊。使用流的 `runId` 調用 `approveToolCall()` 或 `declineToolCall()`，即可繼續：

```typescript
const stream = await agent.stream("What's the weather in London?", {
  requireToolApproval: true,
})

for await (const chunk of stream.fullStream) {
  if (chunk.type === 'tool-call-approval') {
    console.log('Tool:', chunk.payload.toolName)
    console.log('Args:', chunk.payload.args)

    // Approve
    const approved = await agent.approveToolCall({ runId: stream.runId })
    for await (const c of approved.textStream) process.stdout.write(c)

    // Or decline
    const declined = await agent.declineToolCall({ runId: stream.runId })
    for await (const c of declined.textStream) process.stdout.write(c)
  }
}
```

#### 說明拒絕原因 {/* #explaining-a-decline */}

`declineToolCall()`、`declineToolCallGenerate()` 和 `declineNetworkToolCall()` 可接收可選的 `reason`。該原因會代替 Tool 結果返回給模型，使模型能夠調整行為，而不是盲目重試。它也會寫入 Tool 調用的 `approval` 元數據，供後續回看對話時使用。

```typescript
const declined = await agent.declineToolCall({
  runId: stream.runId,
  toolCallId,
  reason: 'Reading other users PII is not allowed, ask the user for their own email instead',
})
```

不提供 `reason` 時，模型會收到預設消息 `Tool call was not approved by the user`。

#### 使用函數進行條件審批 {/* #conditional-approval-with-a-function */}

除了布爾值，`requireToolApproval` 還可以接收一個函數，逐次決定是否審批。函數接收 `toolName`、模型傳入的 `args`、`requestContext` 和 `workspace`。返回 `true` 表示需要審批，返回 `false` 表示允許執行。這樣就能在運行時設定審批條件，例如只審批名稱符合特定模式的 Tool：

```typescript
const stream = await agent.stream('Clean up old records', {
  requireToolApproval: ({ toolName }) => /^delete_/.test(toolName),
})
```

該函數可以是異步的。如果判斷取決於 Tool 名稱和參數，可以使用 [classifier](/docs/classifier) 估計調用是否需要人工審核：

```typescript title="src/mastra/agents/run-with-approval.ts"
import { Classifier } from '@mastra/core/classifier'
import { typeSafeAi } from '@ai-sdk/typesafe-ai'
import { agent } from './agent'

const approvalClassifier = new Classifier({
  id: 'tool-approval-classifier',
  model: typeSafeAi.decisionModel('__AI_SDK_TYPESAFE_DECISION_MODEL__'),
  questions: {
    requiresApproval: {
      type: 'boolean',
      instructions:
        'Does this tool call need human approval because it is destructive, irreversible, expensive, or handles sensitive data?',
    },
  },
})

const stream = await agent.stream('Clean up old records', {
  requireToolApproval: async ({ toolName, args }) => {
    const result = await approvalClassifier.decide({
      state: {
        toolName,
        argumentNames: Object.keys(args),
      },
    })

    // A refused question has no probability, so it falls back to requiring approval.
    return (result.answers.requiresApproval.probability ?? 1) >= 0.7
  },
})
```

例子只發送參數名，不發送參數值，因為 classifier 會把自身狀態轉發給配置的決策模型。如果決策必須使用參數值，請先遮蔽敏感數據，或選擇符合受保護 Tool 數據處理要求的決策模型和提供方。

返回 `true` 會將 Tool 調用掛起，等待人工審批，並不會自動批准或拒絕。閾值應與 Agent 可用 Tool 的風險相匹配。如果 `requireToolApproval` 函數拋出異常，預設會要求審批。

運行時會將這一結果與 Tool 的 `requireApproval` 設定合併。布爾值 `true` 表示需要審批；`false` 不會取消 `requireToolApproval` 要求的審批。Tool 級別的 `requireApproval` 函數具有最終決定權，會覆蓋該 Tool 的合併結果。

:::note

函數形式的 `requireToolApproval` 僅適用於普通的 `stream()` / `generate()` 調用。持久化 Agent 和已儲存的 Agent 會保存選項，而函數無法序列化，因此只接受布爾值。在這些場景傳入函數時，會回退為每次 Tool 調用都要求審批。

:::

#### 將審批綁定到確切的 Tool 參數 {/* #bind-approval-to-the-exact-tool-arguments */}

對於敏感 Tool，應將審批綁定到審核者看到的確切 Tool 名稱和參數。如果執行前參數發生變化，就不應沿用原審批執行。

`tool-call-approval` 資料區塊已包含 `toolName`、`toolCallId` 和 `args`。可以在展示審批請求時為這些字段生成指紋。下例用 JSON 字符串作指紋；生產環境應改用 Tool 名稱和參數的穩定哈希。

```typescript title="src/mastra/agents/approval-bound-agent.ts"
import { Agent } from '@mastra/core/agent'

// For your production usecase, build a stable hash of the tool name and args
function actionFingerprint(toolName: string, args: unknown) {
  const payload = JSON.stringify({ toolName, args })
  return `fingerprint-${payload}`
}

const sensitiveTools = new Set(['issue_refund', 'delete_record'])
const approvedFingerprints = new Set<string>()

export const approvalBoundAgent = new Agent({
  id: 'approval-bound-agent',
  name: 'Approval Bound Agent',
  model: '__GATEWAY_OPENAI_MODEL__',
  tools: { issueRefundTool, deleteRecordTool },
  hooks: {
    beforeToolCall: ({ toolName, input }) => {
      if (!sensitiveTools.has(toolName)) return

      const fingerprint = actionFingerprint(toolName, input)
      if (!approvedFingerprints.delete(fingerprint)) {
        return {
          proceed: false,
          output: `Tool call blocked: approval did not match ${toolName} arguments.`,
        }
      }
    },
  },
})
```

```typescript
const stream = await approvalBoundAgent.stream('Refund order ord-1042', {
  requireToolApproval: ({ toolName }) => sensitiveTools.has(toolName),
})

async function consumeApprovalStream(currentStream: typeof stream) {
  for await (const chunk of currentStream.fullStream) {
    if (chunk.type === 'tool-call-approval') {
      const { toolName, toolCallId, args } = chunk.payload
      const fingerprint = actionFingerprint(toolName, args)

      // Present toolName, args, and fingerprint to your approval UI.
      const approved = await showApprovalDialog({ toolName, args, fingerprint })

      const nextStream = approved
        ? await approveReviewedToolCall(currentStream.runId, toolCallId, fingerprint)
        : await approvalBoundAgent.declineToolCall({ runId: currentStream.runId, toolCallId })

      await consumeApprovalStream(nextStream)
    }
  }
}

async function approveReviewedToolCall(runId: string, toolCallId: string, fingerprint: string) {
  approvedFingerprints.add(fingerprint)
  return approvalBoundAgent.approveToolCall({ runId, toolCallId })
}

await consumeApprovalStream(stream)
```

在生產環境中，應將獲批指紋存入持久儲存，並按用戶、運行、Tool 調用和策略版本限定範圍。上面的 `Set` 刻意保持簡化，以說明關鍵邊界：審批只能消費一次，且只適用於審核時的同一組規範化 Tool 參數。

### 使用 `suspend()` 在運行時掛起 {/* #runtime-suspension-with-suspend */}

Tool 也可以在 `execute` 函數執行*過程中*調用 `suspend()` 暫停。當 Tool 開始運行後才發現需要用戶補充信息或確認才能完成時，這種方式很有用。

流會發出 `tool-call-suspended` 資料區塊，其中包含由 Tool 的 `suspendSchema` 定義的自定義載荷。調用 `resumeStream()` 並傳入符合 `resumeSchema` 的數據即可恢復運行。

```typescript
const weatherTool = createTool({
  id: 'get-weather',
  inputSchema: z.object({
    location: z.string().optional(),
  }),
  suspendSchema: z.object({
    question: z.string(),
  }),
  resumeSchema: z.object({
    location: z.string(),
  }),
  execute: async ({ location }, context) => {
    if (!location) {
      return await context?.agent?.suspend({
        question: 'Which city would you like the weather for?',
      })
    }
    return await fetchWeather(location)
  },
})
```

:::note

`suspend()` 不會拋出異常。調用後請立即返回，例如 `return await suspend({ ... })`；`await suspend(...)` 後面的代碼仍會在 Tool 真正暫停前執行。

:::

如果 Tool 既需要用戶提供結構化答案，又在子 Agent 中運行，請使用 `suspend()`，而不是不帶 `execute` 的 Tool：子 Agent 無法運行客戶端 Tool，但掛起請求可以通過 supervisor 向上傳遞。要通過 AI SDK 的 `useChat()` 恢復，請參閱[從 `useChat()` 恢復掛起的 Tool](/integrations/agentic-ui/ai-sdk-ui#resuming-a-suspended-tool-from-usechat)。

## 配合 `generate()` 審批 Tool {/* #tool-approval-with-generate */}

非流式場景也可在 `generate()` 中審批 Tool。需要審批時，`generate()` 會立即返回 `finishReason: 'suspended'`、包含 Tool 調用詳情（`toolCallId`、`toolName`、`args`）的 `suspendPayload`，以及 `runId`。

```typescript
const output = await agent.generate('Find user John', {
  requireToolApproval: true,
})

if (output.finishReason === 'suspended') {
  console.log('Tool requires approval:', output.suspendPayload.toolName)

  // Approve
  const result = await agent.approveToolCallGenerate({
    runId: output.runId,
    toolCallId: output.suspendPayload.toolCallId,
  })
  console.log('Final result:', result.text)

  // Or decline
  const result = await agent.declineToolCallGenerate({
    runId: output.runId,
    toolCallId: output.suspendPayload.toolCallId,
  })
}
```

### stream() 與 generate() 對比 {/* #stream-vs-generate-comparison */}

| 方面 | `stream()` | `generate()` |
| - | - | - |
| 響應類型 | 流式資料區塊 | 完整響應 |
| 審批檢測 | `tool-call-approval` 資料區塊 | `finishReason: 'suspended'` |
| 批准方法 | `approveToolCall({ runId })` | `approveToolCallGenerate({ runId, toolCallId })` |
| 拒絕方法 | `declineToolCall({ runId })` | `declineToolCallGenerate({ runId, toolCallId })` |
| 結果 | 可迭代的流 | 完整輸出對象 |

:::note

`toolCallId` 對這四個方法均為可選參數。當可能同時存在多個待處理的 Tool 調用時（supervisor Agent 中很常見），請傳入該參數。省略時，Agent 會恢復最近掛起的 Tool 調用。
:::

## Tool 級審批 {/* #tool-level-approval */}

除了在 Agent 級別暫停所有 Tool 調用，也可以只將特定 Tool 標記為需要審批。這樣只有指定 Tool 會暫停，其他 Tool 可立即執行。

### 使用 `requireApproval` 審批 {/* #approval-using-requireapproval */}

在 Tool 定義中設定 `requireApproval: true`。無論 Agent 是否設定 `requireToolApproval`，該 Tool 都會在執行前暫停：

```typescript title="src/mastra/tools/test-tool.ts"
import { createTool } from '@mastra/core/tools'
import { z } from 'zod'

export const testTool = createTool({
  id: 'test-tool',
  description: 'Fetches weather for a location',
  inputSchema: z.object({
    location: z.string(),
  }),
  outputSchema: z.object({
    weather: z.string(),
  }),
  resumeSchema: z.object({
    approved: z.boolean(),
  }),
  execute: async inputData => {
    const response = await fetch(`https://wttr.in/${inputData.location}?format=3`)
    const weather = await response.text()

    return { weather }
  },
  requireApproval: true,
})
```

`requireApproval` 為 `true` 時，流會像 Agent 級審批一樣發出 `tool-call-approval` 資料區塊。調用 `approveToolCall()` 或 `declineToolCall()` 即可繼續：

```typescript
const stream = await agent.stream("What's the weather in London?")

for await (const chunk of stream.fullStream) {
  if (chunk.type === 'tool-call-approval') {
    console.log('Approval required for:', chunk.payload.toolName)
  }
}

const handleApproval = async () => {
  const approvedStream = await agent.approveToolCall({ runId: stream.runId })

  for await (const chunk of approvedStream.textStream) {
    process.stdout.write(chunk)
  }
  process.stdout.write('\n')
}
```

### 使用 `suspend()` 審批 {/* #approval-using-suspend */}

這種方式下，Agent 和 Tool 都不設定 `requireApproval`。Tool 的 `execute` 函數會在指定位置調用 `suspend()` 暫停，並向用戶返回上下文或確認提示。適用於是否需要審批取決於運行時條件的場景。

```typescript title="src/mastra/tools/test-tool-b.ts"
import { createTool } from '@mastra/core/tools'
import { z } from 'zod'

export const testToolB = createTool({
  id: 'test-tool-b',
  description: 'Fetches weather for a location',
  inputSchema: z.object({
    location: z.string(),
  }),
  outputSchema: z.object({
    weather: z.string(),
  }),
  resumeSchema: z.object({
    approved: z.boolean(),
  }),
  suspendSchema: z.object({
    reason: z.string(),
  }),
  execute: async (inputData, context) => {
    const { resumeData: { approved } = {}, suspend } = context?.agent ?? {}

    if (!approved) {
      return suspend?.({ reason: 'Approval required.' })
    }

    const response = await fetch(`https://wttr.in/${inputData.location}?format=3`)
    const weather = await response.text()

    return { weather }
  },
})
```

此時流中會出現 `tool-call-suspended` 資料區塊，`suspendPayload` 包含 Tool 的 `suspendSchema` 定義的 `reason`。調用 `resumeStream`，傳入符合 `resumeSchema` 的數據和 `runId`，即可繼續：

```typescript
const stream = await agent.stream("What's the weather in London?")

for await (const chunk of stream.fullStream) {
  if (chunk.type === 'tool-call-suspended') {
    console.log(chunk.payload.suspendPayload)
  }
}

const handleResume = async () => {
  const resumedStream = await agent.resumeStream({ approved: true }, { runId: stream.runId })

  for await (const chunk of resumedStream.textStream) {
    process.stdout.write(chunk)
  }
  process.stdout.write('\n')
}
```

使用 `generate()` 時，結果的 `finishReason: 'suspended'`。來自 `suspend()` 的 Tool 數據位於 `suspendPayload.suspendPayload`。調用 `resumeGenerate()`，傳入 `resumeSchema` 數據和 `runId`，即可繼續：

```typescript
const output = await agent.generate("What's the weather in London?")

if (output.finishReason === 'suspended') {
  console.log(output.suspendPayload.suspendPayload) // { reason: 'Approval required.' }

  const resumed = await agent.resumeGenerate({ approved: true }, { runId: output.runId! })
  console.log(resumed.text)
}
```

掛起或待審批的 Tool 調用恢復後，流會先發出 `tool-call-resumed` 資料區塊，再發出相同 `toolCallId` 的 `tool-result`。其 `payload.kind` 為 `'suspension'` 或 `'approval'`，載荷還會重復原始 `args`、`suspendPayload` 和 `resumeSchema`。只有真正解除掛起或審批請求時，才會發出該資料區塊。

在 `@mastra/ai-sdk` 中，它會以 `data-tool-call-suspended` 部分（審批則為 `data-tool-call-approval`）到達，並帶有 `resumed: true`，替換原部分且保留其載荷。可以據此標記問題已得到回答。不要根據 Tool 輸出的形狀推斷：如果掛起來自子 Agent，委派調用的輸出是子 Agent 的結果，而非用戶的回答。

## 自動恢復 Tool {/* #automatic-tool-resumption */}

對於調用 `suspend()` 的 Tool，可以啓用自動恢復，讓 Agent 根據用戶的下一條消息恢復掛起的 Tool。在 Agent 預設選項或單次請求中將 `autoResumeSuspendedTools` 設為 `true`：

```typescript title="src/mastra/agents/my-agent.ts"
import { Agent } from '@mastra/core/agent'
import { Memory } from '@mastra/memory'

const agent = new Agent({
  id: 'my-agent',
  name: 'My Agent',
  instructions: 'You are a helpful assistant',
  model: '__GATEWAY_OPENAI_MODEL_LUNA__',
  tools: { weatherTool },
  memory: new Memory(),
  defaultOptions: {
    autoResumeSuspendedTools: true,
  },
})
```

啓用後，Agent 會在下一條用戶消息到來時，從消息歷史中檢測掛起的 Tool，根據 Tool 的 `resumeSchema` 提取 `resumeData`，並自動恢復該 Tool。

自動恢復只適用於攜帶數據的 `suspend()` 流程，不會批准使用 `requireApproval` 的 Tool。後者仍會保持掛起，直到通過 `approveToolCall()`、`declineToolCall()`、`resumeStream({ approved: boolean })` 或等效 UI/API 操作明確批准或拒絕。

下面的例子展示完整的對話流程：

```typescript title="src/mastra/tools/weather-tool.ts"
import { createTool } from '@mastra/core/tools'
import { z } from 'zod'

const weatherTool = createTool({
  id: 'weather-tool',
  description: 'Fetches weather for a city',
  inputSchema: z.object({
    city: z.string(),
  }),
  outputSchema: z.object({
    weather: z.string(),
  }),
  suspendSchema: z.object({
    message: z.string(),
  }),
  resumeSchema: z.object({
    city: z.string(),
  }),
  execute: async (inputData, context) => {
    const { resumeData, suspend } = context?.agent ?? {}

    // If no city provided, ask the user
    if (!inputData.city && !resumeData?.city) {
      return suspend?.({ message: 'What city do you want to know the weather for?' })
    }

    const city = resumeData?.city ?? inputData.city
    const response = await fetch(`https://wttr.in/${city}?format=3`)
    const weather = await response.text()

    return { weather: `${city}: ${weather}` }
  },
})
```

```typescript
const stream = await agent.stream("What's the weather like?")

for await (const chunk of stream.fullStream) {
  if (chunk.type === 'tool-call-suspended') {
    console.log(chunk.payload.suspendPayload)
  }
}

// User sends follow-up on the same thread
const resumedStream = await agent.stream('San Francisco')
for await (const chunk of resumedStream.textStream) {
  process.stdout.write(chunk)
}
```

```text title="Console output"
User: "What's the weather like?"
Agent: "What city do you want to know the weather for?"

User: "San Francisco"
Agent: "The weather in San Francisco is: San Francisco: ☀️ +72°F"
```

第二條消息會自動恢復掛起的 Tool。Agent 從用戶消息中提取 `{ city: "San Francisco" }`，作為 `resumeData` 傳入。

### 使用條件 {/* #requirements */}

要讓自動恢復生效，需要滿足以下條件：

- **已配置 Memory**：Agent 需要借助 Memory 跨消息追蹤掛起的 Tool。
- **同一線程**：後續消息必須使用相同的 Memory 線程和資源標識符。
- **已定義 `resumeSchema`**：Tool 必須定義 `resumeSchema`，Agent 才能知道要從用戶訊息中提取甚麼資料結構。

### 手動與自動恢復 {/* #manual-vs-automatic-resumption */}

| 方式 | 適用場景 |
| - | - |
| 手動（`resumeStream()`） | 程序控制、Webhook、按鈕點擊、外部觸發器 |
| 自動（`autoResumeSuspendedTools`） | 用戶通過自然語言提供恢復數據的對話流程 |

兩種方式使用相同的 Tool 定義。只有消息歷史中存在掛起的 Tool，且用戶在同一線程發送新消息時，才會觸發自動恢復。

## 重啓後恢復 {/* #resuming-after-a-restart */}

前面的例子會在掛起與審批期間保存 `stream.runId`。只要進程仍在運行，這樣做就可行；但在生產環境中，審批可能在頁面刷新、伺服器重啓後，或通過負載均衡器轉發到另一台伺服器後才到達。

使用 [`listSuspendedRuns()`](/reference/agents/listSuspendedRuns) 從儲存中重新查找某次對話的待處理運行：

```typescript
// In the request handler that receives the user's decision
const { runs } = await agent.listSuspendedRuns({
  threadId: 'thread-123',
  resourceId: 'user-456',
})

const run = runs[0]
const toolCall = run?.toolCalls[0]

if (run && toolCall) {
  let stream
  if (toolCall.requiresApproval) {
    // Suspended by requireApproval — approve or decline the tool call
    stream = await agent.approveToolCall({ runId: run.runId, toolCallId: toolCall.toolCallId })
  } else {
    // Suspended by suspend() — resume with the data the tool asked for
    console.log('Tool asked:', toolCall.suspendPayload)
    stream = await agent.resumeStream({ name: 'San Francisco' }, { runId: run.runId })
  }
  for await (const chunk of stream.textStream) process.stdout.write(chunk)
}
```

每條返回的運行都包含掛起的 Tool 調用（`toolCallId`、`toolName`、`args` 和 `requiresApproval`）。審批型掛起（`requiresApproval: true`）通過 `approveToolCall()` / `declineToolCall()` 處理；基於 `suspend()` 的掛起則帶有 `suspendPayload`，並等待帶恢復數據的 `resumeStream()`。因此，即使不在內存中保留狀態，也能為兩種流程重新構建正確的 UI。

`sendToolApproval()` 也會自動通過儲存查找運行。如果 Memory 中沒有該線程的活動運行，它會先在儲存中搜索掛起的運行。若多個掛起運行匹配同一線程，請傳入 `toolCallId`。

HTTP 接口 `GET /agents/:agentId/suspended-runs` 和客戶端 SDK 的 [`agent.listSuspendedRuns()`](/reference/client-js/agents#listsuspendedruns) 也提供相同的查找能力，供瀏覽器中的審批 UI 直接重新發現待處理運行。

:::note

只有為 Mastra 實例配置持久化[儲存提供方](/docs/storage)，掛起運行才能在重啓後保留。預設的內存儲存會在進程退出時丟失快照。

:::

### 崩潰後恢復決策 {/* #recovering-a-decision-after-a-crash */}

調用 `approveToolCall()`、`declineToolCall()` 或 `resumeStream()` 時，運行及其決策或恢復數據、目標 `toolCallId` 會一並在儲存中被認領。如果負責恢復的進程在運行結束前停止，可從任意進程調用 `recoverResume()`，用已儲存的決策完成該運行：

```typescript
const stream = await agent.recoverResume({ runId })

for await (const chunk of stream.textStream) process.stdout.write(chunk)
```

`recoverResume()` 只會接管已放棄的認領：尚未開始且認領已滿 60 秒；或者在支持運行隔離柵欄的儲存中，雖已開始但租約超過 60 秒未續期。此前調用會被 `AGENT_RESUME_ALREADY_CLAIMED` 拒絕。若運行尚未被任何恢復操作認領，則會被 `AGENT_RESUME_NOTHING_TO_RECOVER` 拒絕。

:::warning

恢復後的 Tool 調用會再次執行。認領是否放棄按時間判斷，因此某個進程停滯 60 秒後可能仍在執行 Tool，而恢復操作也會執行它。請讓有副作用的 Tool 能安全地重復執行，例如使用冪等鍵。

:::

## Tool 審批：supervisor Agent {/* #tool-approval-supervisor-agents */}

[supervisor Agent](/docs/subagents) 通過 `.stream()` 或 `.generate()` 協調多個子 Agent。當子 Agent 調用需要審批的 Tool 時，請求會沿委派鏈向上傳遞，並顯示在 supervisor 層：

1. supervisor 將任務委派給子 Agent。
1. 子 Agent 調用設定了 `requireApproval: true` 或使用 `suspend()` 的 Tool。
1. 審批請求向上傳遞給 supervisor。
1. 你在 supervisor 層批准或拒絕。
1. 決策再向下傳遞給子 Agent。

Tool 審批也會跨多級委派傳遞。如果 supervisor 委派給子 Agent A，而 A 又委派給子 Agent B，B 調用設定了 `requireApproval: true` 的 Tool，審批請求仍會顯示在最頂層 supervisor。

### 識別哪個子 Agent 的 Tool 暫停 {/* #identify-which-subagent-tool-paused */}

supervisor 會在自己的委派調用上報告子 Agent 的暫停，因此 `tool-call-approval` 或 `tool-call-suspended` 資料區塊中的 `toolCallId` 指向 supervisor 對子 Agent 的調用。批准、拒絕或恢復時，務必傳入該 `toolCallId`。

要展示子 Agent 中究竟哪個 Tool 調用暫停，請讀取同一載荷中的以下字段：

- `delegatedToolCallId`：子 Agent 中暫停的 Tool 調用 ID，可區分同一委派中的兩次暫停，例如先提問再審批。
- `delegatedToolName`：子 Agent 中暫停的 Tool 名稱。

即使經過多級委派，這兩個字段也始終指向最深層、真正暫停的 Tool 調用。Memory 會隨暫停一起保存它們，因此重新加載對話後仍可讀取；`generate()` 也會在 `suspendPayload` 中返回它們。

```typescript
const stream = await supervisorAgent.stream('Draft and publish the report')

for await (const chunk of stream.fullStream) {
  if (chunk.type === 'tool-call-approval' || chunk.type === 'tool-call-suspended') {
    // Label the pause with the subagent tool call that caused it
    console.log('Paused:', chunk.payload.delegatedToolName, chunk.payload.delegatedToolCallId)

    // Pass the supervisor's delegation call when you approve, decline, or resume
    console.log('Resume with:', chunk.payload.toolCallId)
  }
}
```

### 在 supervisor Agent 中批准和拒絕 {/* #approve-and-decline-in-supervisor-agents */}

下例創建一個包含待審批 Tool 的子 Agent。Tool 觸發審批請求時，該請求會以 `tool-call-approval` 資料區塊出現在 supervisor 的流中：

```typescript
import { Agent } from '@mastra/core/agent'
import { createTool } from '@mastra/core/tools'
import { Memory } from '@mastra/memory'
import { z } from 'zod'

const findUserTool = createTool({
  id: 'find-user',
  description: 'Finds user by ID in the database',
  inputSchema: z.object({
    userId: z.string(),
  }),
  outputSchema: z.object({
    user: z.object({
      id: z.string(),
      name: z.string(),
      email: z.string(),
    }),
  }),
  // highlight-next-line
  requireApproval: true,
  execute: async input => {
    const user = await database.findUser(input.userId)
    return { user }
  },
})

const dataAgent = new Agent({
  id: 'data-agent',
  name: 'Data Agent',
  description: 'Handles database queries and user data retrieval',
  model: '__GATEWAY_OPENAI_MODEL_LUNA__',
  tools: { findUserTool },
})

const supervisorAgent = new Agent({
  id: 'supervisor',
  name: 'Supervisor Agent',
  instructions: `You coordinate data retrieval tasks.
    Delegate to data-agent for user lookups.`,
  model: '__GATEWAY_OPENAI_MODEL__',
  agents: { dataAgent },
  memory: new Memory(),
})

const stream = await supervisorAgent.stream('Find user with ID 12345')

for await (const chunk of stream.fullStream) {
  // highlight-next-line
  if (chunk.type === 'tool-call-approval') {
    console.log('Tool requires approval:', chunk.payload.toolName)
    console.log('Arguments:', chunk.payload.args)

    // Approve the tool call
    // highlight-start
    const resumeStream = await supervisorAgent.approveToolCall({
      runId: stream.runId,
      toolCallId: chunk.payload.toolCallId,
    })
    //highlight-end

    for await (const resumeChunk of resumeStream.textStream) {
      process.stdout.write(resumeChunk)
    }

    // To decline instead, use:
    const declineStream = await supervisorAgent.declineToolCall({
      runId: stream.runId,
      toolCallId: chunk.payload.toolCallId,
    })
  }
}
```

### 在 supervisor Agent 中使用 `suspend()` {/* #use-suspend-in-supervisor-agents */}

Tool 也可以調用 [`suspend()`](#approval-using-suspend) 暫停執行並向用戶返回上下文。與 `requireApproval` 一樣，這種掛起也能沿 supervisor 的委派鏈傳遞，並顯示在 supervisor 層：

```typescript title="src/mastra/tools/conditional-tool.ts"
import { createTool } from '@mastra/core/tools'
import { z } from 'zod'

const conditionalTool = createTool({
  id: 'conditional-operation',
  description: 'Performs an operation that may require confirmation',
  inputSchema: z.object({
    operation: z.string(),
  }),
  suspendSchema: z.object({
    message: z.string(),
  }),
  resumeSchema: z.object({
    confirmed: z.boolean(),
  }),
  execute: async (input, context) => {
    const { resumeData } = context?.agent ?? {}

    if (!resumeData?.confirmed) {
      return context?.agent?.suspend({
        message: `Confirm: ${input.operation}?`,
      })
    }

    // Proceed with operation
    return await performOperation(input.operation)
  },
})
```

```typescript
// When using this tool through a subagent in supervisor agents
for await (const chunk of stream.fullStream) {
  if (chunk.type === 'tool-call-suspended') {
    console.log('Tool suspended:', chunk.payload.suspendPayload.message)

    // Resume with confirmation
    const resumeStream = await supervisorAgent.resumeStream(
      { confirmed: true },
      { runId: stream.runId },
    )

    for await (const resumeChunk of resumeStream.textStream) {
      process.stdout.write(resumeChunk)
    }
  }
}
```

### supervisor Agent 配合 `generate()` 審批 {/* #supervisor-approval-with-generate */}

supervisor Agent 中的 Tool 審批請求也可以通過 `generate()` 傳播：

```typescript
const output = await supervisorAgent.generate('Find user with ID 12345', {
  maxSteps: 10,
})

if (output.finishReason === 'suspended') {
  console.log('Tool requires approval:', output.suspendPayload.toolName)

  // Approve
  const result = await supervisorAgent.approveToolCallGenerate({
    runId: output.runId,
    toolCallId: output.suspendPayload.toolCallId,
  })

  console.log('Final result:', result.text)
}
```
