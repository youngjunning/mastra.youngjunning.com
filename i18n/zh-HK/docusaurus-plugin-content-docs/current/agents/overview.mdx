# Agent

Agent 使用 LLM 和 Tool 解決開放式任務。它們會根據目標進行推理，並決定使用哪些 Tool。設定 [Memory](/docs/memory/overview) 後，Agent 可以保留對話記錄。Agent 會持續反覆執行，直至模型產生最終答案或符合選用的停止條件。

Agent 可以產生結構化回應，供 UI 顯示或程式處理。你可以直接使用 Agent，也可以將多個 Agent 組合成 Workflow 或多 Agent 系統。

## 何時使用 Agent {/* #when-to-use-agents */}

當任務屬於開放式問題，無法預先確定執行步驟時，適合使用 Agent。Agent 會自行決定呼叫哪些 Tool、要循環多少次，以及何時停止；你只需提供目標和限制，不必逐步定義執行流程。若是控制流程明確、步驟預先確定的多階段程序，請改用 [Workflow](/docs/workflows/overview)。

觀看 [Mastra Agent 快速入門](https://www.youtube.com/watch?v=G8tXjcseNjg)，快速了解如何建立及測試 Mastra Agent。

## 快速入門 {/* #quickstart */}

從 `@mastra/core` 匯入並建立 `Agent` 類別的實例，同時提供必要屬性：

```typescript title="src/mastra/agents/test-agent.ts"
import { Agent } from '@mastra/core/agent'

export const testAgent = new Agent({
  id: 'test-agent',
  name: 'Test Agent',
  instructions: 'You are a helpful assistant.',
  model: '__GATEWAY_OPENAI_MODEL__',
})
```

`instructions` 用來定義 Agent 的行為、角色和能力。它屬於系統層級的提示詞，用以建立 Agent 的核心身分和專業範圍。`model` 則透過 Mastra 的[模型路由器](/models)，以 `'provider/model-name'` 格式指定。

要讓整個應用程式都能使用此 Agent，請將它註冊到 Mastra 實例中。該實例通常位於 `src/mastra/index.ts`：

```typescript {5} title="src/mastra/index.ts"
import { Mastra } from '@mastra/core'
import { testAgent } from './agents/test-agent'

export const mastra = new Mastra({
  agents: { testAgent },
})
```

註冊後，Workflow、Tool 或其他 Agent 都能呼叫它；它也能存取 Memory、記錄和可觀測性等共用資源。

如需了解可用屬性和設定，請參閱 [Agent API 參考](/reference/agents/agent)。

:::tip

使用 [Studio](/docs/studio/overview) 可以透過不同訊息測試 Agent、檢查 Tool 呼叫和回應，並除錯 Agent 行為。

使用 [Agent Builder](https://agent-builder.mastra.ai) 可以直接在瀏覽器中建立和管理完整持久化的 Agent，無須在 TypeScript 中定義。

:::

## 使用 Agent {/* #use-your-agent */}

註冊後，透過 [`mastra.getAgentById()`](/reference/core/getAgentById) 取得 Agent。呼叫 `.generate()` 可在處理完成後取得完整回應；呼叫 `.stream()` 可即時傳送產生的 token。Agent 可以從 [Workflow 步驟](/docs/workflows/agents-and-tools)、[Tool](/docs/agents/tools)、[Mastra Client](/reference/client-js/mastra-client)、路由處理程式、[Server Adapter](/docs/server/server-adapters)或命令列呼叫。若要在應用程式框架中使用 Agent，請參閱[整合](/integrations)。

從 Mastra 實例引用 Agent 時，應使用 `mastra.getAgentById()`，確保它能存取實例層級的儲存空間、記錄和 Agent 登錄等共用服務。直接匯入的 Agent 仍可使用本身的本機設定運作，但無法存取這些共用服務。

<Tabs>
  <TabItem value="generate" label=".generate()">
    在所有 Tool 呼叫和步驟完成後傳回完整回應。結果包含 `text`、`toolCalls`、`toolResults`、`steps` 和 token `usage` 統計資料。

    如需了解回應結構，包括 Tool 呼叫和 Tool 結果的內容，請參閱 [`Agent.generate()` API 參考](/reference/agents/generate)。

    ```ts
    const agent = mastra.getAgentById('test-agent')
    const response = await agent.generate('Help me organize my day')
    console.log(response.text)
    ```
  </TabItem>

  <TabItem value="stream" label=".stream()">
    傳回一個可在 token 到達時逐步處理的串流。結果透過 `textStream` 提供增量輸出，並以 Promise 提供 `toolCalls`、`toolResults`、`steps` 和 token `usage`；這些 Promise 會在串流結束時完成。

    如需了解串流回應結構，包括 Tool 呼叫和 Tool 結果的內容，請參閱 [`MastraModelOutput` API 參考](/reference/streaming/agents/MastraModelOutput)。

    ```ts
    const agent = mastra.getAgentById('test-agent')
    const stream = await agent.stream('Help me organize my day')

    for await (const chunk of stream.textStream) {
      process.stdout.write(chunk)
    }
    ```
  </TabItem>
</Tabs>

## 擴充 Agent {/* #expand-your-agent */}

Agent 開始運作後，可以按照下一步目標選擇相應文件：

| 目標 | 從這裏開始 |
| - | - |
| 讓 Agent 呼叫外部 API 或服務 | [Tool](/docs/agents/tools) |
| 跨對話保留上下文和偏好 | [Memory](/docs/memory/overview) |
| 傳回具型別的物件，而非純文字 | [結構化輸出](/docs/agents/structured-output) |
| 加入人工審批：暫停執行並等待人工確認 | [Human-in-the-loop](/docs/agents/human-in-the-loop) |
| 建立多 Agent 網絡 | [Supervisor Agent](/docs/subagents) |
| 註冊 Subagent | [將 Agent 當作 Tool](/docs/agents/tools#agents-as-tools) |
| 在產生前後攔截或轉換訊息 | [Processor](/docs/agents/processors) |
| 提升 Agent 安全性 | [Guardrail](/docs/agents/guardrails) |
| 建立能夠自行修正工作的 Agent | [Rubric Scorer](/docs/subagents#rubric-scorer) |
| 按照要求上下文切換 instructions 或模型 | [動態設定](/docs/server/request-context) |
| 加入語音轉文字或文字轉語音 | [Voice](/reference/voice/overview) |
| 連接 Slack、Discord 或 Telegram | [Channel](/docs/channels) |

## 多 Agent 系統 {/* #multi-agent-systems */}

多 Agent 系統會使用多個 Agent，共同處理單一 Agent 難以涵蓋的廣泛或高度專業任務。與其為一個 Agent 設定數十個 Tool 和冗長的 instructions，不如將職責拆分給多個專注的 Agent，再由協調 Agent 彙整結果。

閱讀[多 Agent 系統概念指南](/docs/guides/multi-agent-systems)，了解如何在 Mastra 中運用不同的協作模式。
