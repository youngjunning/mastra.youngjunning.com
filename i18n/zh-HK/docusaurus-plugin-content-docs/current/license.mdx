# 授權條款

Mastra 採用雙重授權模式，大部分程式碼受 Apache License 2.0 授權，企業專用功能則受 Mastra Enterprise License 授權。

- Mastra 程式碼庫內，凡名稱為 `ee/` 的目錄下的所有內容，包括但不限於：

  - `@mastra/core/auth/ee`
  - `@mastra/core/agent-builder/ee`
  - `@mastra/editor/ee`

  均按 [`ee/LICENSE`](https://github.com/mastra-ai/mastra/blob/main/ee/LICENSE) 訂明的條款授權。

- Mastra 軟件納入的所有第三方組件，均按各組件擁有人提供的原有條款授權。

- 上述目錄和限制以外的內容，可按 Apache License 2.0 使用。

## 哪些功能須取得企業版授權 {/* #what-requires-an-ee-license */}

是否須取得 Mastra 企業版（EE）授權，視乎所設定的功能，與安裝了哪些套件無關。下表列出各功能在正式環境的授權要求。開發和測試時，所有功能均可在沒有授權的情況下使用。

| 功能 | 正式環境是否須取得 EE 授權 |
| - | - |
| API 路由的身份驗證（`server.auth`），可用任何提供者，包括 Simple Auth、JWT、Auth0、Better Auth、Clerk、Firebase、Google、Neon、Okta、Supabase 和 WorkOS | 否 |
| Studio 使用 Simple Auth、JWT 或 Mastra 平台的身份驗證 | 否 |
| 使用第三方提供者的 Studio 登入畫面（SSO 按鈕或電郵及密碼表格） | 是 |
| 透過 `server.rbac` 或 `studio.rbac` 設定按角色存取控制（RBAC），適用於任何提供者 | 是 |
| 採用 `server.fga` 或 `studio.fga` 的細粒度授權（FGA） | 是 |
| Agent Builder | 是 |

### 正式環境沒有有效授權時 {/* #without-a-license-in-production */}

請在環境變數 `MASTRA_LICENSE_KEY` 設定授權密鑰。Mastra 亦會讀取舊有的 `MASTRA_EE_LICENSE`。如正式環境沒有有效密鑰：

- **RBAC、FGA 或 Agent Builder**：伺服器不會啟動，錯誤訊息會列明哪項功能須取得授權。
- **使用第三方提供者的 Studio 登入畫面**：Studio 會隱藏登入畫面，API 路由的身份驗證會繼續運作。

## Mastra Enterprise License {/* #mastra-enterprise-license */}

任何名為 `ee/` 的目錄（例如 `@mastra/core/auth/ee`）內的程式碼均按 Mastra Enterprise License 提供原始碼。這些功能可自由用於開發和測試，正式環境則須取得有效的企業版授權。詳情請[聯絡銷售團隊](https://mastra.ai/contact)。
