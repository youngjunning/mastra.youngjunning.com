# 由檔案系統提供的 Skill

每個由檔案系統提供的 Skill 都是一個目錄，包含可重用的指令及輔助檔案。Mastra 會按 `skills` 選項中的路徑尋找 Skill，供採用該設定的所有 Agent 使用。Skill 符合 [Agent Skills 規格](https://agentskills.io)。

如要直接在個別 Agent 的程式碼內定義 Skill，請使用 [Agent Skill](/docs/skills)。一個 Agent 可同時使用兩種 Skill；如兩者同名，會優先使用直接定義的 Agent Skill。

## 快速入門 {/* #quickstart */}

建立一個目錄，並在目錄內加入 `SKILL.md` 檔案：

```markdown title="workspace/skills/code-review/SKILL.md"
---
name: code-review
description: Reviews code for bugs and readability issues
---

# Code review

Check the code for bugs, missing error handling, and unclear naming.
```

加入目錄設定：

```typescript title="src/mastra/workspaces.ts"
import { LocalFilesystem, Workspace } from '@mastra/core/workspace'

export const workspace = new Workspace({
  filesystem: new LocalFilesystem({
    basePath: './workspace',
  }),
  skills: ['skills'],
})
```

`skills` 內的路徑以檔案系統的根目錄為起點，所以 Mastra 會找到 `./workspace/skills/code-review/SKILL.md`。使用此設定的 Agent 可按請求需要查找及載入 `code-review`。

## Skill 目錄結構 {/* #skill-structure */}

每個 Skill 佔用一個目錄，必須包含 `SKILL.md` 檔案，亦可放置輔助檔案：

```plaintext title="workspace/skills/code-review"
code-review/
  SKILL.md
  references/
    style-guide.md
  scripts/
    lint.ts
  assets/
    review-template.md
```

- `SKILL.md`：元數據及指令，Mastra 會在 Agent 選用 Skill 時載入
- `references/`：供 Agent 按需要閱讀或搜尋的文件
- `scripts/`：供 Skill 使用的指令碼
- `assets/`：範本、圖像及其他輔助檔案

把主要流程保留在 `SKILL.md`，並將詳細資料放到 `references/`，讓 Agent 按需要讀取。

## `SKILL.md` 格式 {/* #skillmd-format */}

YAML frontmatter 須提供 `name` 及 `description`。`name` 須與 Skill 目錄名稱一致，不得超過 64 個字元，只可包含小寫字母、數字或連字號，且不可用連字號開頭或結尾，也不可連續使用連字號。Markdown 正文載有 Agent 載入 Skill 時收到的指令。

Mastra 亦會讀取選填欄位 `license`、`compatibility`、`user-invocable` 及 `metadata`。完整的套件格式及欄位指引載於 [Agent Skills 規格](https://agentskills.io/specification)。

## Agent 使用 Skill 的方式 {/* #how-agents-use-skills */}

設定 Skill 後，Mastra 會在系統訊息加入各個 Skill 的名稱、描述、路徑及來源類型。Agent 無須把所有指令檔案載入上下文，也能查看可用的 Skill。

Mastra 亦會向 Agent 提供三項工具：

| 工具 | 用途 |
| - | - |
| `skill` | 載入 Skill 的 `SKILL.md` 指令，並列出參考文件、指令碼和資源檔案。 |
| `skill_read` | 讀取選定 Skill 目錄內任何檔案的全部或部分內容。 |
| `skill_search` | 搜尋 Skill 的名稱、描述、指令及參考檔案。 |

載入過程不保留狀態。指令會以工具結果留在對話中；如壓縮上下文後失去這些指令，Agent 可再次調用 `skill`。

### 關閉 Skill 清單 {/* #turn-off-the-skills-list */}

Skill 數目較多時，每次請求都在系統訊息列出全部 Skill 會消耗 token。加入 `SkillsProcessor` 並設為 `injectCatalog: false`，即可用簡短指令取代清單，提示 Agent 先用 `skill_search` 查找，再用 `skill` 載入：

```typescript title="src/mastra/agents/support-agent.ts"
import { Agent } from '@mastra/core/agent'
import { SkillsProcessor } from '@mastra/core/processors'
import { workspace } from '../workspaces'

export const supportAgent = new Agent({
  id: 'support-agent',
  name: 'Support Agent',
  instructions: 'You help customers with support requests.',
  model: '__GATEWAY_OPENAI_MODEL__',
  workspace,
  inputProcessors: [new SkillsProcessor({ injectCatalog: false })],
})
```

無論是檔案系統 Skill 還是 [Agent Skill](/docs/skills)，Agent 都可繼續使用 `skill`、`skill_read` 及 `skill_search`。毋須設定搜尋功能，`skill_search` 也會以查詢字詞配對 Skill 的名稱、描述和內容。Skill 數目較多時，可在 Workspace 設定 [BM25 或向量搜尋](#search-skill-content)，改善結果排序。系統一律會為 Agent Skill 建立索引。

只有數十個 Skill 時，可保留預設清單，讓 Agent 一次過看到所有選項；Provider 亦可快取這段固定的前綴。若 Skill 數目達到約一百個，或需要控制系統訊息長度，便可關閉清單。搜尋指令的長度不會隨 Skill 的數目改變。

[`SkillSearchProcessor`](/reference/processors/skill-search-processor) 同樣會隱藏清單，但會以本身的 `search_skills` 及 `load_skill` 取代標準工具，而且只支援 Workspace Skill。請選用其中一種處理器；若同時設定，Agent 便會取得兩套工具。完整選項見 [`SkillsProcessor`](/reference/processors/skills-processor) 參考文件。

## 設定 Skill 的路徑 {/* #configure-skill-paths */}

`skills` 陣列支援多種路徑格式：

| 路徑 | 搜尋方式 |
| - | - |
| `skills` | 在每個直屬子目錄內尋找 `SKILL.md` 檔案。 |
| `skills/code-review` | 直接載入指定的 Skill 目錄。 |
| `skills/code-review/SKILL.md` | 直接載入指定的 Skill 檔案。 |
| `./**/skills` | 找出相符的目錄，再從各目錄搜尋 Skill。 |
| `./**/SKILL.md` | 搜尋並載入相符的 Skill 檔案。 |

加入更多路徑，便可由專案、團隊或套件等不同的根目錄搜尋 Skill。

glob 最多會搜尋基準目錄以下四層。

如已設定檔案系統，Mastra 會在該檔案系統解析路徑；否則會以應用程式進程的目前工作目錄為基準，從本機磁碟讀取。明確指定 [`skillSource`](#custom-skill-sources) 後，兩種預設方式均會被取代。

## 同名 Skill {/* #same-named-skills */}

Mastra 會在系統訊息逐一列出由檔案系統提供的 Skill，連同各自的路徑及來源類型。如有多個 Skill 同名，按名稱查找時會依照以下優先次序：

1. 本機專案的路徑
1. `.mastra/skills` 下的受管理路徑
1. `node_modules` 下的外部路徑

若優先次序最高的候選項目中，有多個 Skill 屬於相同的來源類型，Mastra 無法作出選擇，並會拋出錯誤。請為其中一個 Skill 改名，或將它移至其他類型的來源。

Agent 可把系統訊息列出的確切路徑傳給 `skill` 或 `skill_read`，毋須按名稱查找。路徑末端可加上或省略 `/SKILL.md`。如果設定中的多條路徑解析後都指向同一個標準目錄，Mastra 會把它們視作別名，只列出該 Skill 一次。

Mastra 會先解析直接定義的 [Agent Skill](/docs/skills)，然後才處理檔案系統 Skill。兩者如有同名項目，會優先使用直接定義的 Skill。

## 搜尋 Skill 的內容 {/* #search-skill-content */}

如果設定 Skill 時同時啟用 [BM25 或向量搜尋](/docs/sandbox/search)，Mastra 會自動將各 Skill 的名稱、描述、`SKILL.md` 指令及參考檔案編入索引。指令碼和資源檔案不在索引範圍內。

未有設定 BM25 或向量搜尋時，`skill_search` 會對名稱、描述、指令及參考資料進行不分大小寫的文字配對。結果按配對到的查詢字詞數目排序，名稱或描述中的相符字詞權重較高。這樣無須另作設定也可搜尋 Skill；如有較多 Skill，索引搜尋可提供排序及語義檢索。

如結果來自參考檔案，便會附上檔案路徑，例如 `references/style-guide.md`，供 Agent 傳給 `skill_read`。

Agent 查找不存在的 Skill 名稱時，如可用的 Skill 不多於 20 個，`skill` 及 `skill_read` 會列出所有項目。如超過 20 個，則最多建議五個相近選項，並提示 Agent 使用 `skill_search`，以免輸入錯誤的名稱時把整份清單加入對話。

## 動態指定 Skill 路徑 {/* #dynamic-skill-paths */}

如可用路徑取決於請求的上下文，可傳入同步或非同步函數。以下例子會為具有 `developer` 角色的用戶加入開發用的 Skill：

```typescript title="src/mastra/workspaces.ts"
import { LocalFilesystem, Workspace } from '@mastra/core/workspace'

const workspace = new Workspace({
  filesystem: new LocalFilesystem({ basePath: './workspace' }),
  skills: ({ requestContext }) => {
    const paths = ['skills']

    if (requestContext?.get('user-role') === 'developer') {
      paths.push('developer-skills')
    }

    return paths
  },
})
```

Mastra 每次執行時都會解析函數的結果，向 Agent 提供該次請求所用的 Skill。傳回的路徑與靜態陣列一樣，支援目錄、檔案和 glob 格式。

## 自訂 Skill 的來源 {/* #custom-skill-sources */}

如要透過目前設定的檔案系統或本機磁碟以外的後端取得 Skill，請設定 `skillSource`。自訂來源會按每條設定路徑查找 Skill 及讀取檔案。

例如，`CompositeVersionedSkillSource` 會從按內容定址的 Blob 儲存區掛載已發佈的 Skill 版本，放在 Mastra 能找到的目錄內：

```typescript title="src/mastra/workspaces.ts"
import { CompositeVersionedSkillSource, Workspace } from '@mastra/core/workspace'

const skillSource = new CompositeVersionedSkillSource(
  [
    {
      dirName: 'code-review',
      tree: versionTree,
      versionCreatedAt,
    },
  ],
  blobStore,
)

const workspace = new Workspace({
  skills: ['.'],
  skillSource,
})
```

明確指定 `skillSource` 後，如路徑不存在，Mastra 不會轉用已設定的檔案系統或本機磁碟。來源介面及相關選項載於[設定參考](/reference/workspace/workspace-class#constructor-parameters)。
