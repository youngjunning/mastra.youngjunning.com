# 檔案系統

檔案系統讓 Agent 可讀取、寫入、列出及[搜尋](/docs/sandbox/search)檔案。它可用作知識庫，亦可在不同次的臨時 Sandbox 執行之間保存檔案。

可用以下兩種方式配置檔案存取：

- [直接存取檔案系統](#direct-filesystem-access)：使用 `filesystem` 接入一個檔案系統供應者，或自行建立的 [`CompositeFilesystem`](#manual-composition)。
- [掛載](#mounts)：使用 `mounts`，以帶有路徑前綴的供應者建立 `CompositeFilesystem`。如靜態 Sandbox 和檔案系統供應者同時支援掛載，Mastra 會自動將供應者掛載到配置的路徑。遠端 Sandbox 一般以用戶空間檔案系統（FUSE）掛載。

`filesystem` 和 `mounts` 只可配置其中一項。同時配置兩項會拋出 `WorkspaceError`，錯誤代碼為 `INVALID_CONFIG`。

兩種配置都會為 Agent 提供檔案工具。Sandbox 成功掛載供應者後，指令才可存取其檔案。

配置檔案系統後，Agent 可使用下列工具：

| 工具 | 用途 |
| - | - |
| `mastra_workspace_read_file` | 讀取整個檔案或部分內容。 |
| `mastra_workspace_write_file` | 建立檔案或覆寫現有檔案。 |
| `mastra_workspace_edit_file` | 替換現有檔案中相符的文本。 |
| `mastra_workspace_list_files` | 列出檔案及目錄。 |
| `mastra_workspace_delete` | 刪除檔案或目錄。 |
| `mastra_workspace_file_stat` | 回傳檔案或目錄的元數據。 |
| `mastra_workspace_mkdir` | 建立目錄和任何尚未存在的上層目錄。 |
| `mastra_workspace_grep` | 以正則表達式搜尋檔案內容。 |
| `mastra_workspace_ast_edit` | 按程式碼結構套用修改。須安裝 `@ast-grep/napi` 才可使用。 |
| `mastra_workspace_apply_patch` | 一次呼叫即可建立、更新、移動及刪除多個檔案。預設停用。 |

`apply_patch` 工具須在 `tools` 中透過專屬項目啟用。設定頂層 `tools.enabled` 不會啟用它。工具會先檢查修補中的每項改動，才寫入檔案：

```typescript title="src/mastra/workspaces/index.ts"
import { Workspace, LocalFilesystem, WORKSPACE_TOOLS } from '@mastra/core/workspace'

export const workspace = new Workspace({
  filesystem: new LocalFilesystem({ basePath: './workspace' }),
  tools: {
    [WORKSPACE_TOOLS.FILESYSTEM.APPLY_PATCH]: { enabled: true },
  },
})
```

## 支援的檔案系統 {/* #supported-filesystems */}

### `LocalFilesystem` {/* #localfilesystem */}

[`LocalFilesystem`](/reference/workspace/local-filesystem) 連接至 Mastra 應用程式所在機器的目錄，適用於本機開發或檔案已存於應用程式主機的情況。

### 其他檔案系統 {/* #other-filesystems */}

如檔案存於應用程式主機以外，或已放在外部服務，請選用其他供應者：

## 直接存取檔案系統 {/* #direct-filesystem-access */}

若要讓 Agent 透過檔案工具存取供應者，請使用 `filesystem`，它亦可接受解析函數或自行建立的 `CompositeFilesystem`。

以下範例為 Agent 提供檔案工具，用於存取本機知識庫：

```typescript
import { LocalFilesystem, Workspace } from '@mastra/core/workspace'

const workspace = new Workspace({
  filesystem: new LocalFilesystem({
    basePath: './knowledge-base',
  }),
})
```

Agent 會取得 `mastra_workspace_read_file`、`mastra_workspace_write_file`、`mastra_workspace_list_files` 及 `mastra_workspace_grep` 等工具。路徑以 `./knowledge-base` 為基礎解析，毋須 Sandbox 或指令工具。

參閱[搜尋](/docs/sandbox/search)，了解如何為檔案建立索引，以便按關鍵字或語義檢索。生成的工具及各項政策載於[檔案系統工具參考](/reference/workspace/workspace-class#filesystem-tools)。

## 掛載 {/* #mounts */}

如 Sandbox 內的程式需要按路徑存取持久儲存的檔案，請用 `mounts`。如果 Sandbox 和檔案系統供應者均支援掛載，Mastra 會自動掛載。Agent 仍可使用檔案工具，指令工具則可透過 `ls`、`cat` 或 `python` 等指令處理同一批檔案。

例如，將 S3 儲存桶掛載至 Daytona Sandbox 內的 `/workspace`：

```typescript
import { Mastra } from '@mastra/core'
import { Workspace } from '@mastra/core/workspace'
import { DaytonaSandbox } from '@mastra/daytona'
import { S3Filesystem } from '@mastra/s3'

const workspace = new Workspace({
  mounts: {
    '/workspace': new S3Filesystem({
      bucket: process.env.S3_BUCKET!,
      region: 'us-east-1',
    }),
  },
  sandbox: new DaytonaSandbox(),
})

export const mastra = new Mastra({ workspace })
```

### 使用掛載 {/* #using-mounts */}

供應者上已有的檔案會出現在 `/workspace`。Agent 可呼叫 `read_file('/workspace/report.md')`，亦可執行 `cat /workspace/report.md`。經任何一個介面寫入的檔案均由供應者保存，即使 Sandbox 停止後仍可存取。

沒有掛載也可以配合使用檔案工具及 Sandbox 指令，做法是由 Agent 在工具呼叫之間傳遞檔案內容。這適用於部分文字檔案。如程式需要目錄樹，或須處理大型檔案或二進制檔案，使用掛載較合適。

:::warning

檔案工具和指令工具的政策各自獨立。例如，要求核准 `write_file` 不會阻止 Agent 以 `execute_command` 寫入同一掛載路徑。如只准以檔案工具存取檔案，請停用 Sandbox 指令工具。

:::

### 路徑 {/* #paths */}

掛載路徑會開放給檔案工具使用，Sandbox 掛載成功後，指令亦可使用該路徑。底層供應者可將檔案存於其他位置。

假設遠端供應者掛載至 `/workspace`：

- 檔案工具使用例如 `/workspace/report.md` 的路徑。
- 遠端 Sandbox 的指令一般使用同一路徑。
- 供應者會將路徑對應至其配置的儲存桶、前綴或遠端目錄。

`LocalSandbox` 會改在 `workingDirectory` 內建立符號連結。`/workspace` 掛載在主機上對應 `<workingDirectory>/workspace`，指令一般以 `workspace` 存取。

## 組合檔案系統 {/* #composite-filesystem */}

`mounts` 選項會建立 `CompositeFilesystem`。這個 TypeScript 路徑路由器將多個供應者呈現為一棵虛擬目錄樹。

### 多個檔案系統 {/* #multiple-filesystems */}

在相應的掛載路徑下配置各個供應者：

```typescript
import { Workspace } from '@mastra/core/workspace'
import { E2BSandbox } from '@mastra/e2b'
import { GCSFilesystem } from '@mastra/gcs'
import { S3Filesystem } from '@mastra/s3'

const workspace = new Workspace({
  mounts: {
    '/data': new S3Filesystem({
      bucket: 'agent-data',
      region: 'us-east-1',
    }),
    '/reports': new GCSFilesystem({
      bucket: 'agent-reports',
    }),
  },
  sandbox: new E2BSandbox({ id: 'analysis-sandbox' }),
})
```

使用這項配置時：

- `list_files('/')` 會回傳虛擬目錄 `data` 和 `reports`。
- `read_file('/data/input.csv')` 會路由至 S3 供應者。
- `write_file('/reports/summary.md')` 會路由至 Google Cloud Storage 供應者。
- 各項 Sandbox 掛載成功後，Sandbox 指令也可使用同一路徑。

組合檔案系統會去掉掛載前綴，然後將餘下路徑交給相應的供應者。掛載路徑不可互相嵌套，因此同一組合檔案系統不可同時包含 `/data` 和 `/data/archive`。

### 未配置 Sandbox {/* #without-a-sandbox */}

即使沒有配置 Sandbox，也可以使用 `mounts`。Mastra 仍會建立 `CompositeFilesystem`，所有檔案工具均可使用帶掛載前綴的路徑。由於沒有 Sandbox，Agent 不會取得指令或程序工具。

### 手動組合 {/* #manual-composition */}

你亦可自行建立 `CompositeFilesystem` 並經 `filesystem` 傳入，以便路由路徑，而毋須自動設定 Sandbox 掛載：

```typescript
import { CompositeFilesystem, LocalFilesystem, Workspace } from '@mastra/core/workspace'
import { S3Filesystem } from '@mastra/s3'

const filesystem = new CompositeFilesystem({
  mounts: {
    '/local': new LocalFilesystem({ basePath: './data' }),
    '/archive': new S3Filesystem({
      bucket: 'agent-archive',
      region: 'us-east-1',
    }),
  },
})

const workspace = new Workspace({ filesystem })
```

如應用程式的其他部分需要將組合檔案系統用作供應者，可採用手動組合。一般 Sandbox 掛載可用 `mounts` 選項，以較少配置達到同樣的路由效果。

## 掛載支援 {/* #mount-availability */}

即使沒有 Sandbox 掛載，檔案工具和組合路由仍可運作。如遠端 Sandbox 和檔案系統供應者均支援掛載，`mounts` 會自動以 FUSE 讓指令存取檔案。`LocalSandbox` 則會使用符號連結。

內置 Sandbox 掛載目前支援以下組合：

| Sandbox 後端 | 檔案系統供應者 |
| - | - |
| `LocalSandbox` | `LocalFilesystem` |
| E2B | Amazon S3, Google Cloud Storage, Azure Blob Storage |
| Daytona | Amazon S3, Google Cloud Storage, Azure Blob Storage |
| Blaxel | Amazon S3, Google Cloud Storage |

遠端掛載可能需要在 Sandbox 內使用 `s3fs`、`gcsfuse` 或 `blobfuse2`。部分後端會在啟動時安裝尚未安裝的軟件，可能需要網絡連線和額外啟動時間。其他組合需要 [`onMount`](/reference/workspace/workspace-class#constructor-parameters) 鉤子或供應者專用設定。

Sandbox 無法掛載或掛載失敗時，Workspace 仍可使用。檔案工具可繼續透過供應者的 SDK 存取檔案，但指令無法存取該路徑。Mastra 會向 Agent 說明這些供應者只可經檔案工具存取。

## 按用戶或對話串劃分檔案系統 {/* #filesystems-per-user-or-thread */}

如要按請求、用戶、角色或租戶選用不同儲存空間，可向 `filesystem` 選項傳入解析函數：

```typescript
const workspace = new Workspace({
  filesystem: ({ requestContext }) => {
    const userId = requestContext.get('user-id') as string

    return new S3Filesystem({
      bucket: process.env.S3_BUCKET!,
      region: process.env.S3_REGION!,
      prefix: `users/${userId}`,
    })
  },
})
```

每個用戶各有獨立的檔案系統視圖，檔案工具會按請求上下文自動找出相應的供應者。

`mounts` 不接受解析函數，也不可與 Sandbox 解析函數一起使用。如每個用戶或對話串都需要獨立的 Sandbox 和儲存空間，請在 Sandbox 解析函數內建立並掛載供應者。請參閱[按用戶或對話串劃分 Sandbox](/docs/sandbox/overview#sandboxes-per-user-or-thread)。

## 政策及存取範圍 {/* #policies-and-containment */}

以 `WORKSPACE_TOOLS.FILESYSTEM` 下的個別常數（例如 `WORKSPACE_TOOLS.FILESYSTEM.WRITE_FILE`）配置各檔案工具。可全域設定核准要求，也可按工具設定。先讀後寫和輸出限制須在各檔案系統工具的項目內設定。請參閱[檔案系統工具配置參考](/reference/workspace/workspace-class#filesystem-tools)。

`LocalFilesystem` 預設只准存取 `basePath` 內的檔案。如 Agent 須存取該根目錄外的指定目錄，請使用 `allowedPaths`：

```typescript
const workspace = new Workspace({
  filesystem: new LocalFilesystem({
    basePath: './knowledge-base',
    allowedPaths: ['../shared-policies'],
  }),
})
```

存取範圍限制適用於檔案系統操作，包括檔案工具和建立搜尋索引。Shell 指令不受此限制。

如 Agent 可使用檔案但不得更改檔案，請設定 `readOnly: true`。如屬靜態供應者，Mastra 會移除與寫入有關的檔案工具。

使用檔案系統解析函數時，須到執行請求時才知道使用哪個供應者，所以寫入工具仍會註冊。供應者會在執行時拒絕寫入操作。

在組合檔案系統中，請讓 `LocalFilesystem` 項目沿用預設的 `contained: true`。只有確定要讓 Agent 不受限制地存取主機檔案系統時，才設定 `contained: false`。
