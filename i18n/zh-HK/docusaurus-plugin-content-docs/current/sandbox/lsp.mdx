# LSP 代码检查

語言伺服器協定（LSP）讓 Agent 取得項目程式碼的語義資料。語言伺服器理解程式語言及項目結構，因此可識別符號的類型、宣告、實作和診斷資料。

## LSP 有甚麼用途 {/* #what-lsp-adds */}

檔案及搜尋工具各自適合解答不同的程式碼庫問題：

| 工具 | 適合用途 |
| - | - |
| `read_file` | 讀取已知檔案的實際內容及前後文 |
| `grep` | 在多個檔案中找出與文字或正規表達式相符的內容 |
| [搜尋](/docs/sandbox/search) | 按關鍵字或語義相似度檢索已建立索引的檔案 |
| LSP 檢查 | 取得類型資料，並在項目內追蹤符號 |

LSP 檢查可補足這些工具的功能。Agent 可先用 `grep` 找到符號，再用 LSP 找出宣告位置，然後用 `read_file` 閱讀完整實作，才進行修改。

## 配置 LSP {/* #set-up-lsp */}

LSP 會啟動持續運行的語言伺服器程序，並與它交換 JSON-RPC 訊息。啟用前請確認以下設定：

- 使用靜態 [Sandbox](/docs/sandbox/overview)，其程序管理器提供的程序控制代碼須有可讀取的輸出串流及可寫入的輸入串流。這裏不支援 Sandbox 解析器。
- Mastra 應用程式已安裝 `vscode-jsonrpc` 和 `vscode-languageserver-protocol` 套件。
- 在 Sandbox 程序運行的環境安裝語言伺服器的二進制檔案及其執行環境。
- 以絕對路徑指定項目根目錄，並讓 Mastra 應用程式及 Sandbox 程序透過相同路徑存取根目錄和項目檔案。

Mastra 內置 TypeScript 和 JavaScript、Python、Go 及 Rust 的伺服器定義，但仍要安裝相應的語言伺服器二進制檔案。其他檔案類型可[註冊另一個伺服器](#custom-language-servers)。

安裝共用的協定套件：

```bash npm2yarn
npm install vscode-jsonrpc vscode-languageserver-protocol
```

接着為項目安裝語言伺服器，例如安裝 TypeScript 及其語言伺服器：

```bash npm2yarn
npm install typescript typescript-language-server
```

建立靜態 `LocalSandbox`，將檔案系統、Sandbox 及 LSP 根目錄指向同一目錄：

```typescript title="src/mastra/workspaces.ts"
import { resolve } from 'node:path'
import { LocalFilesystem, LocalSandbox, Workspace } from '@mastra/core/workspace'

const projectPath = resolve('./workspace')

export const workspace = new Workspace({
  filesystem: new LocalFilesystem({
    basePath: projectPath,
  }),
  sandbox: new LocalSandbox({
    workingDirectory: projectPath,
  }),
  lsp: {
    root: projectPath,
  },
})
```

檔案系統為 Agent 提供操作項目檔案的工具。首次有 LSP 查詢需要語言伺服器時，Sandbox 會在同一目錄啟動它。若欠缺所需的協定套件、程序管理器或伺服器二進制檔案，Mastra 會停用 LSP，或回報沒有可用的語言伺服器。

## 使用 Agent 工具檢查程式碼 {/* #inspect-code-with-the-agent-tool */}

啟用 LSP 後，Agent 會取得 `mastra_workspace_lsp_inspect` 工具。輸入用來指定檔案，並將游標定位到一個符號：

```json
{
  "path": "/absolute/path/to/workspace/src/orders.ts",
  "line": 10,
  "match": "const order = await <<<findOrder(orderId)"
}
```

`line` 由 1 開始計算。把該行內容複製到 `match`，在要檢查的符號前緊接插入一個 `<<<` 標記，只可插入一次。這個標記不屬於原始檔案。

工具會傳回語言伺服器可提供的欄位：

| 字段 | 输出 |
| - | - |
| `hover` | 類型資料或文件，連同其標記格式 |
| `diagnostics` | 被检查行的诊断严重程度、消息和来源 |
| `definition` | 宣告位置，若檔案可讀取則附有一行預覽 |
| `implementation` | 实现位置 |
| `error` | 无法检查时返回配置、服务器或查询错误 |

工具會略去無法取得的結果欄位。可按定義及實作的位置繼續用 `read_file` 查看完整上下文。

## 调整 LSP 配置 {/* #configure-lsp */}

設定 `lsp: true` 可使用預設值。若要控制根目錄、伺服器搜尋方式、逾時或保留的客戶端，請改用物件：

```typescript oxfmt:false
lsp: {
  root: projectPath,
  diagnosticTimeout: 4_000,
  initTimeout: 8_000,
  maxOpenClients: 4,
  disableServers: ['eslint'],
  binaryOverrides: {
    typescript: '/opt/mastra-tools/typescript-language-server --stdio',
  },
  searchPaths: ['/opt/mastra-tools'],
},
```

`binaryOverrides` 將內置伺服器 ID 映射至完整啟動指令。`searchPaths` 加入套件根目錄，當中的 `node_modules` 可能包含所需模組或二進制檔案。最後可設定 `packageRunner`，例如 `pnpm dlx`。這個後備做法預設停用，因為它可能安裝軟件，或在某些項目結構下停止回應。

`diagnosticTimeout` 控制直接呼叫 `getDiagnostics()` 和 `getDiagnosticsMulti()` API 時等候診斷的時間。Agent 檢查工具目前最多等候五秒。

Mastra 通常從每個檔案的位置向上尋找相應伺服器的項目標記，以找出項目根目錄。找不到標記時會改用 `lsp.root`。所有選項及預設值請參閱 [LSP 設定參考](/reference/workspace/workspace-class)。

### 限制保留的客戶端數量 {/* #limit-retained-clients */}

`maxOpenClients` 限制單一設定保留的語言伺服器客戶端數量，必須是正整數。達到上限時，Mastra 會從沒有生效中查詢租約的客戶端中，關閉最久未使用的一個。

如果所有保留的客戶端都有生效中的租約，下次取得租約時最多等候五秒。若仍沒有可用租約，`prepareQuery()` 和 `getDiagnostics()` 會傳回 `null`，而 `getDiagnosticsMulti()` 會略過未能取得客戶端的伺服器。省略 `maxOpenClients` 即不設上限。Mastra Code 的預設上限是 `4`。

### 更改工具名稱 {/* #tool-name-remapping */}

透過 `tools` 設定 Agent 檢查工具。例如，加入以下項目，即可以較短的名稱提供工具：

```typescript
import { WORKSPACE_TOOLS } from '@mastra/core/workspace'

const tools = {
  [WORKSPACE_TOOLS.LSP.LSP_INSPECT]: {
    name: 'lsp_inspect',
  },
}
```

在設定中將 `tools` 與 `lsp` 放在同一層。`name` 更改對外提供的工具名稱，設定鍵仍是 `WORKSPACE_TOOLS.LSP.LSP_INSPECT`。如要移除工具，請在同一項目設定 `enabled: false`。

自動產生的 Agent 工具共用的審批設定、動態策略、輸出限制及掛鈎，請參閱[工具設定參考](/reference/workspace/workspace-class#tool-configuration)。

## 自定义语言服务器 {/* #custom-language-servers */}

如某種語言沒有內置支援，或需要取代內置定義，請在 `lsp.servers` 下加入伺服器：

```typescript oxfmt:false
lsp: {
  root: projectPath,
  servers: {
    phpactor: {
      id: 'phpactor',
      name: 'Phpactor Language Server',
      languageIds: ['php'],
      extensions: ['.php'],
      markers: ['composer.json'],
      command: 'phpactor language-server',
      initializationOptions: {
        indexer: { enabled: true },
      },
    },
  },
},
```

每項定義支援以下欄位：

| 字段 | 必填 | 说明 |
| - | - | - |
| `id` | 是 | 唯一的伺服器 ID。使用內置 ID 可取代相應定義。 |
| `name` | 是 | 在日誌和錯誤訊息顯示的易讀名稱。 |
| `languageIds` | 是 | 伺服器處理的 LSP 語言識別碼。 |
| `extensions` | 是 | 伺服器處理的副檔名，包括開首的點。 |
| `markers` | 是 | 用來尋找項目根目錄的檔案或目錄。 |
| `command` | 是 | 启动服务器的完整命令。 |
| `initializationOptions` | 否 | LSP 初始化握手時傳送的設定。 |

自訂定義會與內置定義合併。如果 `id` 相同，自訂定義會取代內置定義。若伺服器列出多個語言 ID，Mastra 會將每個已設定的副檔名映射至第一個語言 ID。

## 直接查询 LSP {/* #query-lsp-directly */}

應用程式碼可直接查詢已設定的 LSP 管理器。`getDiagnostics()` 和 `getDiagnosticsMulti()` 會在內部管理客戶端租約，以及文件開啟和關閉的通知。

`prepareQuery()` 提供客戶端，可直接查詢游標停留資料、定義、實作等。請傳入絕對檔案路徑，它會開啟檔案並傳回租約。請先關閉檔案再釋放租約，並將兩次呼叫放入 `finally` 區塊：

```typescript
async function inspectHover(filePath: string, line: number, character: number) {
  const query = await workspace.lsp?.prepareQuery(filePath)
  if (!query) return null

  try {
    return await query.client.queryHover(query.uri, {
      line,
      character,
    })
  } finally {
    query.client.notifyClose(filePath)
    query.release()
  }
}
```

直接使用客戶端時，位置索引從 0 開始。若已設定 `maxOpenClients`，未釋放的租約可能令閒置客戶端無法被清除。清理時，Mastra 最多等候五秒讓生效中的租約釋放，然後強制關閉語言伺服器。受管理的 LSP 客戶端會在 Sandbox 銷毀前關閉。

## 限制 {/* #limitations */}

- LSP 只適用於有相應內置或自訂伺服器的檔案類型。
- 單靠檔案系統無法執行語言伺服器。LSP 需要配備雙向程序管理器的靜態 Sandbox。
- `LocalFilesystem` 的目錄隔離及 `allowedPaths` 不會限制 LSP 檢查。請將 `lsp.root` 限於可信的項目。如用戶可提交不受信任的主機路徑，請勿開放 LSP 工具。
- 檢查外部套件時，可能找到 `.d.ts` 等宣告檔案，而非執行時用的原始碼。
- 語言伺服器可能略去不支援的游標停留資料、診斷、定義或實作結果。

### 遙距 Sandbox {/* #remote-sandboxes */}

遙距 LSP 仍依賴主機。語言伺服器指令透過遙距 Sandbox 的程序管理器執行，但搜尋二進制檔案、讀取檔案及部分原始碼預覽仍由 Mastra 主機處理。

只有符合以下所有條件，才可使用遙距 LSP：

- 遙距程序管理器提供可讀取的輸出串流及可寫入的輸入串流。
- 項目在 Mastra 主機及遙距 Sandbox 使用相同的絕對路徑。
- 解析所得的伺服器指令已安裝於遙距映像。內置伺服器使用 `binaryOverrides` 設定，自訂伺服器則使用 `lsp.servers.command`。
- 主機能讀取檢查及預覽定義所需的檔案。

本機檔案系統與遙距 Sandbox 不會自動同步。只安裝在主機的二進制檔案無法在遙距 Sandbox 執行，只存在遙距環境的檔案亦無法提供主機端的所有結果。如果項目只在遙距環境，在 LSP 可跨後端一致存取檔案之前，請使用 `grep`、索引[搜尋](/docs/sandbox/search)及 Sandbox 指令。
