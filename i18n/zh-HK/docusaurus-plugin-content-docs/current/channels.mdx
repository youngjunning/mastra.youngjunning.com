# 頻道

**新增於：** `@mastra/core@1.22.0`

頻道讓 Agent 接通 Slack、Microsoft Teams、Discord、Telegram、WhatsApp、GitHub 及 Linear 等訊息及協作平台。用戶在平台傳送訊息或留言時，Agent 會按一般流程接收及處理，然後以串流方式將回覆送回原本的對話。Mastra 使用 [Chat SDK](https://chat-sdk.dev/) 實現頻道層。

先查看你所用平台的頁面：

<IntegrationGrid section="Channels" />

[其他適配器](#other-adapters)列出更多平台。除了此處列出的平台，Mastra 頻道也可使用相容的 [Chat SDK 適配器](https://chat-sdk.dev/adapters)；各適配器在 Mastra 中的設定方式相同。

## 何時使用頻道 {/* #when-to-use-channels */}

當 Agent 需要處理以下情況時，可使用頻道：

- 在用戶平日溝通或工作的平台與他們互動。
- 在 Slack、Microsoft Teams、Discord、Telegram 及 WhatsApp 等聊天平台回覆訊息。
- 讓多人在共用頻道或對話串與同一個 Agent 互動。
- 接入 GitHub issue、拉取請求討論及 Linear 留言等協作流程。

## 透過 Mastra Connect 加快頻道設定 {/* #configure-channels-faster-with-mastra-connect */}

如果不想逐一為每個頻道設定機械人或應用程式，也不想自行保管憑證，可以使用 [Mastra Connect](/docs/mastra-platform/connect#add-channels)。它會代為管理憑證，簡化頻道設定及維護。

## 設定 Agent {/* #configure-an-agent */}

頻道採用 Chat SDK 適配器，Mastra 端的設定方式一致：建立頻道適配器，再加入 Agent。

```typescript title="src/mastra/agents/your-agent.ts"
import { Agent } from '@mastra/core/agent'
import { createSlackAdapter } from '@chat-adapter/slack'

export const yourAgent = new Agent({
  id: 'your-agent',
  name: 'Your Agent',
  instructions: 'You are a helpful assistant.',
  model: '__GATEWAY_OPENAI_MODEL__',
  channels: {
    adapters: {
      slack: createSlackAdapter(),
    },
  },
})
```

:::note

頻道適配器需要平台專用環境變數，以提供憑證及驗證請求，例如機械人 token、簽署密鑰、應用程式 ID 及 webhook 驗證 token。具體變數名稱請參閱平台指南或 [Chat SDK 適配器目錄](https://chat-sdk.dev/adapters)。

:::

建議為頻道設定[儲存空間](/docs/storage)。儲存空間可在重新啟動後保留頻道及記憶狀態，包括對話串訂閱及工具審批：

```typescript title="src/mastra/index.ts"
import { Mastra } from '@mastra/core'
import { LibSQLStore } from '@mastra/libsql'
import { yourAgent } from './agents/your-agent'

export const mastra = new Mastra({
  agents: { yourAgent },
  storage: new LibSQLStore({
    id: 'mastra-storage',
    url: process.env.DATABASE_URL,
  }),
})
```

## Webhook 路由 {/* #webhook-routes */}

平台透過 webhook 向 Mastra 傳送頻道事件。Webhook 是一個 HTTP 端點；出現新訊息、有人提及 Agent，或用戶在互動式工具審批卡片上選擇「Approve」時，平台便會呼叫它。Webhook 將訊息交予 Agent 處理，Agent 之後在同一頻道回覆。

Mastra 會為每個已設定的適配器註冊 webhook 路由，並處理請求：

```text
/api/agents/<AGENT_ID>/channels/<PLATFORM>/webhook
```

例如，ID 為 `your-agent` 的 Agent 使用 Slack 適配器時，路由如下：

```text
/api/agents/your-agent/channels/slack/webhook
```

將平台的 webhook、事件或互動 URL 指向此路徑。詳情請參閱平台指南或 [Chat SDK 文件](https://chat-sdk.dev/adapters)。Webhook 會在 Agent 完成回覆前確認請求；驗證或處理函式失敗時會怎樣，請參閱[錯誤處理與傳遞](#error-handling-and-delivery)。

本機開發時，平台 webhook 需要公開 URL 才能連接本機伺服器。可使用 [cloudflared](https://github.com/cloudflare/cloudflared) 或 [ngrok](https://ngrok.com/) 建立通道，對外提供預設位於 `localhost:4111` 的伺服器：

```bash npm2yarn
npx cloudflared tunnel --url http://localhost:4111
```

以產生的公開 URL 作為 webhook 路徑的基底 URL，例如 `https://abc123.trycloudflare.com/api/agents/your-agent/channels/slack/webhook`。

:::note

通道 URL 只供本機開發使用。部署 Mastra 伺服器後，請將平台的 webhook、事件或互動 URL 更新為正式環境的 URL。

:::

## 對話串上下文 {/* #thread-context */}

用戶在頻道對話串中途提及 Agent 時，Agent 可能沒有之前的對話上下文。首次被提及時，Mastra 會從平台擷取較早的訊息，並在處理該次提及前存入 Agent 的記憶對話串。

1. 首次在對話串被提及時，Agent 會擷取首則訊息，以及提及之前最新的訊息。`maxMessages`（預設 `10`）設定範圍：首則訊息加上最多 `maxMessages - 1` 則近期訊息。若兩者之間另有訊息，會以 `[… N earlier Slack messages omitted]` 標記取代並儲存；平台名稱會與頻道相符。
1. 每則擷取的訊息會連同作者、平台訊息 ID 及附件，分別作為用戶訊息存入記憶，並帶有 `source: 'thread-history'` 屬性。該次提及隨後會作為一般訊息處理。
1. Agent 回覆後會訂閱該對話串，並透過 Mastra 記憶取得完整歷史。
1. 同一對話串之後的訊息不會再從平台擷取歷史。

設定 `threadContext: { maxMessages: 0 }` 可停用此行為。這只適用於非私訊對話串。

沒有記憶功能的 Agent 無法儲存這些訊息，因此會改為在提及訊息中，以上下文文字接收相同的歷史。寫入記憶失敗時亦會使用此後備方式。

記憶的 `lastMessages` 選項限制送入提示詞的訊息數量。預設值 `10` 在 `maxMessages` 為 `10` 時，會略去首則訊息及省略標記，因此應將 `lastMessages` 設為至少 `maxMessages + 1`。

Mastra 亦會加入一則簡短系統訊息，告知 Agent 請求來自哪個頻道及平台，以及是私訊還是公開頻道訊息。設定 `threadContext: { addSystemMessage: false }` 可略過。

## 工具審批 {/* #tool-approval */}

設定 `requireApproval: true` 的 Tool 會顯示附有 Approve 及 Deny 按鈕的互動卡片：

```typescript title="src/mastra/tools/delete-file.ts"
import { promises as fs } from 'node:fs'
import { createTool } from '@mastra/core/tools'
import { z } from 'zod'

export const deleteFile = createTool({
  id: 'delete-file',
  description: 'Delete a file from the system',
  inputSchema: z.object({
    path: z.string().describe('Path to the file to delete'),
  }),
  requireApproval: true,
  execute: async ({ path }) => {
    await fs.unlink(path)
    return { deleted: path }
  },
})
```

Agent 呼叫此 Tool 時，用戶會看到列有工具名稱、參數及 Approve、Deny 操作的卡片。工具須經審批才會執行。

如要以自訂訊息取代卡片，例如為按鈕提供本地化文字，可從 `toolDisplay` 函式回傳 `{ kind: 'post', message: card }`。自訂函式會取代所有工具事件的顯示方式，並不限於審批事件。只有按鈕保留 Mastra 預期的 ID，預設操作處理函式才會恢復執行。請參閱[自訂審批卡片](/reference/agents/channels#custom-approval-cards)。

預設只有要求呼叫工具的用戶可批准或拒絕。若共用頻道的其他成員也應能操作，請在該適配器設定 `toolApprovers: 'anyone'`：

```typescript title="src/mastra/agents/your-agent.ts" oxfmt:false
channels: {
  adapters: {
    slack: {
      adapter: createSlackAdapter(),
      toolApprovers: 'anyone',
    },
  },
},
```

這只會略過請求者檢查：操作仍須對應待處理的工具審批及已映射的對話串。若執行沒有記錄請求者（例如排程執行），預設模式無法嚴格保證只有請求者可操作；其他頻道成員此時也可能回應。若重新啟動後，已儲存訊息顯示多個可能的請求者，僅限請求者模式則會拒絕他們的點擊。

在適配器設定 `toolDisplay: 'text'`，可將工具呼叫顯示為純文字，而非互動卡片。在 `'hidden'` 模式下，同一對話串稍後收到用戶訊息時，`autoResumeSuspendedTools` 可恢復帶有資料的 `suspend()` 流程；這需要記憶功能。隱藏模式只會隱藏審批按鈕，不會將訊息視作同意。需要審批的 Tool 仍會暫停，直至透過 UI 或 API 操作明確批准或拒絕。

### 自訂操作處理 {/* #custom-action-handling */}

使用 `handlers.onAction` 處理自行發佈的卡片上的按鈕點擊及選項變更。處理函式會收到 Chat SDK 操作事件、預設處理函式，以及其他頻道處理函式收到的同一個 `ctx`。委派前寫入 `ctx.requestContext` 的值會傳至恢復後的工具呼叫。預設處理函式只處理內建 Approve 及 Deny 按鈕，忽略其他操作 ID；因此，未自行處理的事件應交由它處理，以維持工具審批功能：

```typescript title="src/mastra/agents/your-agent.ts" oxfmt:false
channels: {
  adapters: {
    slack: createSlackAdapter(),
  },
  handlers: {
    onAction: async (event, defaultHandler, ctx) => {
      if (event.actionId === 'retry') {
        await event.thread?.post('Retrying...')
        return
      }
      await defaultHandler()
    },
  },
},
```

設定 `onAction: false` 會完全停用操作處理，包括內建工具審批按鈕。要在頻道啟動後註冊更多 Chat SDK 處理函式，請使用 `agent.getChannels()?.sdk`。

## 回覆格式 {/* #reply-formatting */}

Agent 預設以 Markdown 發佈回覆。Slack 等原生支援 Markdown 的平台會直接顯示粗體、連結及表格；其他平台則轉為自身格式。Agent 使用標準 Markdown，即可在各平台正確顯示，與 Studio 中的顯示效果一致。

在適配器設定 `textFormat: 'plain'`，可將回覆原樣以純文字發佈：

```typescript title="src/mastra/agents/your-agent.ts" oxfmt:false
channels: {
  adapters: {
    slack: {
      adapter: createSlackAdapter(),
      textFormat: 'plain',
    },
  },
},
```

若已指示 Agent 輸出 Slack mrkdwn 等平台專用格式，而非標準 Markdown，可使用此選項。若之前為避免 Markdown 原樣顯示而加入這類提示詞指示，應將其移除。預設行為現在會原生顯示標準 Markdown。`textFormat` 只影響最終回覆文字，不影響工具卡片、錯誤訊息及原生串流文字。

### 只透過 Tool 回覆 {/* #reply-only-through-a-tool */}

設定 `textDisplay: 'hidden'` 可停止發佈 Agent 的回覆文字。之後，Agent 自己的訊息只能透過提供給它的 Tool（例如向對話串發文的工具）送達對話串。這可避免「Running the tests now」等過程說明出現在對話中，同時讓 Agent 自行決定何時發文：

```typescript title="src/mastra/agents/your-agent.ts" oxfmt:false
channels: {
  adapters: {
    slack: {
      adapter: createSlackAdapter(),
      textDisplay: 'hidden',
    },
  },
},
```

工具顯示、審批提示、錯誤訊息及輸入狀態不受影響。回覆文字仍會進入 Agent 的串流及記憶。

Mastra 加入 Agent 提示詞的頻道指示也會跟隨此設定：隱藏文字時，Agent 會知道只有透過 Tool 發佈的內容才能送達對話，亦可選擇不發佈訊息。

## 非訊息觸發的執行 {/* #runs-that-dont-start-from-a-message */}

從頻道開始的對話串也可能由其他來源啟動執行，例如排程、Studio 提示詞或喚醒 Agent 的 Signal。這類執行會收到與訊息觸發的執行相同的頻道指示。Agent 知道自己在頻道的身分，亦知道文字回覆是否會發佈到頻道。兩種執行使用相同的系統提示詞，因此可沿用快取。

經頻道傳入的訊息帶有 `platform` 屬性（例如 `platform="slack"`），讓 Agent 能將它與其他來源的提示詞區分。

這些執行的回覆與訊息觸發的回覆使用同一適配器路徑。Mastra 會記住對話串最後一位發言者，因此需要指定收件者的適配器（例如 Slack 的原生串流功能）亦能以相同方式運作。

## 辨識多位用戶 {/* #multi-user-awareness */}

在群組對話中，Mastra 會在每則訊息前加入發送者姓名及平台 ID，協助 Agent 分辨發言者：

```text
[Alice (@U123ABC)]: Can you help me with this?
[Bob (@U456DEF)]: I have a question too.
```

## 每則訊息的 Signal 元數據 {/* #per-message-signal-metadata */}

在自訂 Channel 處理函式使用 `signalMetadata`，可為單則傳入訊息附加結構化上下文。無論它啟動閒置執行，還是加入進行中的執行，元數據都會隨訊息傳遞。

以下例子會在呼叫預設處理函式前附加已註冊的檔案 ID：

```typescript title="src/mastra/agents/your-agent.ts"
import { Agent } from '@mastra/core/agent'
import { createSlackAdapter } from '@chat-adapter/slack'

export const yourAgent = new Agent({
  id: 'your-agent',
  name: 'Your Agent',
  instructions: 'You are a helpful assistant.',
  model: '__GATEWAY_OPENAI_MODEL__',
  channels: {
    adapters: {
      slack: createSlackAdapter(),
    },
    handlers: {
      onDirectMessage: async (thread, message, defaultHandler, ctx) => {
        ctx.signalMetadata.attachmentIds = ['file-1']
        await defaultHandler(thread, message)
      },
    },
  },
})
```

只加入可序列化為 JSON 的非敏感值。Signal 元數據可能存入記憶，或透過共用的發布訂閱傳輸送出；不會加入模型提示詞。

單次執行範圍內的設定（例如啟動執行的訊息所需的憑證）應使用 `requestContext`。必須附在單則訊息上的上下文，包括送達進行中執行的訊息，則使用 `signalMetadata`。

## 錯誤處理與傳遞 {/* #error-handling-and-delivery */}

頻道 webhook 會在 Agent 完成前向平台確認請求，所以 `200` 表示「已收到」，並非「已回覆」。確認前，適配器會同步拒絕無效請求：驗證失敗回傳 `401`、無法解析的請求內容回傳 `400`、暫時性狀態故障回傳 `503`；平台會按自身政策重試非 `2xx` 回應。回傳 `200` 後，平台不會再重試，錯誤由 Mastra 處理。預設處理函式會捕捉 Agent 執行失敗，並在對話串發送錯誤訊息（可透過 `formatError` 自訂，預設為 `❌ Error: {message}`）。自訂處理函式處理單則訊息時若擲出錯誤，Chat SDK 只會記錄日誌，不會發文或重試（多位發送者的批次見[批次訊息](#batched-messages)）。請在自訂處理函式自行捕捉錯誤：

```typescript title="src/mastra/agents/your-agent.ts" oxfmt:false
channels: {
  adapters: {
    slack: createSlackAdapter(),
  },
  handlers: {
    onDirectMessage: async (thread, message, defaultHandler, ctx) => {
      try {
        ctx.signalMetadata.ticketId = await lookupTicket(message)
      } catch (error) {
        ctx.mastra?.getLogger().error('Ticket lookup failed', { error })
        await thread.post('Something went wrong looking up your ticket. Try again in a moment.')
        return
      }
      await defaultHandler(thread, message)
    },
  },
},
```

平台重試有時會重複傳遞同一事件。適配器利用頻道狀態去除重複事件；[儲存空間](/docs/storage)可在重新啟動後保留該狀態。由於這種保護只能盡力而為，自訂處理函式的副作用應具備冪等性，避免重複傳遞再次建立工單等。

### 批次訊息 {/* #batched-messages */}

當 `chatOptions.concurrency` 策略（`burst`、`debounce` 或 `queue`）把多則訊息合併為一次派送時，Mastra 會按發送者拆成多個回合：同一發送者連續的訊息組成一個回合，按時間由舊到新處理。處理函式每回合執行一次，各自有 `ctx.requestContext`、`ctx.signalMetadata` 及 `ctx.skipped`（該回合較早的訊息），讓授權及上下文分別適用於每位發送者。請在處理函式等待 `defaultHandler` 完成，否則不同發送者的回合可能重疊。某回合擲出錯誤時會記錄日誌，其餘回合繼續執行，最後再擲出第一個錯誤。若批次因某則訊息提及機械人而送至 `onMention`，其他發送者未提及機械人的訊息亦會進入 `onMention`，其 `message.isMention` 為 `false`。

## 日誌 {/* #logging */}

Chat SDK 日誌預設使用 Mastra 實例上的[日誌記錄器](/docs/observability/logging)，因此遵循其格式、級別及 `redact` 設定。每筆記錄的 `component` 欄位為 `chat-sdk`。使用 `PinoLogger` 時，Mastra 自己的頻道日誌將 `component` 設為 `CHANNEL`，可據此分辨。設定 `chatOptions.logger` 可覆蓋預設值，將日誌送到其他位置。

適配器有獨立的日誌記錄器，預設輸出至主控台。應用程式在 Mastra 實例建立前便建立各個適配器，因此 Mastra 不能代為設定該記錄器。建立適配器時請傳入 [`toChatLogger()`](/reference/agents/channels#tochatlogger)：

```typescript title="src/mastra/agents/support-agent.ts"
import { Agent } from '@mastra/core/agent'
import { toChatLogger } from '@mastra/core/channels'
import { createDiscordAdapter } from '@chat-adapter/discord'
import { logger } from '../logger'

export const supportAgent = new Agent({
  id: 'support-agent',
  name: 'Support Agent',
  instructions: 'You are a helpful support assistant.',
  model: '__GATEWAY_OPENAI_MODEL__',
  channels: {
    adapters: {
      discord: createDiscordAdapter({
        logger: toChatLogger(logger, { component: 'discord', minLevel: 'warn' }),
      }),
    },
  },
})
```

這裏的 `logger` 與傳入 `new Mastra({ logger })` 的記錄器相同。請從獨立檔案（例如 `src/mastra/logger.ts`）匯出，供 Agent 檔案及 `src/mastra/index.ts` 一同匯入。`createRedisState()` 等狀態適配器也預設輸出至主控台，並接受相同的 `logger` 選項。

Discord 適配器的 Gateway 路徑會以 `info` 級別記錄每則訊息的首 100 個字元；`minLevel: 'warn'` 可避免這些內容進入日誌。Chat SDK 本身以 `debug` 級別記錄訊息文字。若 Mastra 的日誌記錄器使用 `debug`，請為 `chatOptions.logger` 設定更高的 `minLevel`，避免記錄訊息文字。

:::warning

日誌記錄器的 `redact` 設定不適用於匯出至[可觀測性](/docs/observability/logging)的日誌，而 `warn` 及 `error` 級別的記錄預設會匯出。`onSlashCommand` 處理函式擲出錯誤時，Chat SDK 的 `error` 記錄會包含指令文字；請在該處理函式捕捉錯誤，避免文字進入日誌及匯出資料。若將可觀測性的 `logging.level` 設為 `info` 或更低，請使用 `minLevel`，防止其他訊息文字被匯出。

:::

## 多模態內容 {/* #multimodal-content */}

Gemini 等模型可直接處理圖片、影片及音訊。配合 `inlineMedia` 及 `inlineLinks`，用戶便可跨平台向 Agent 分享多媒體內容：

```typescript title="src/mastra/agents/vision-agent.ts"
import { Agent } from '@mastra/core/agent'
import { createDiscordAdapter } from '@chat-adapter/discord'

export const visionAgent = new Agent({
  id: 'vision-agent',
  name: 'Vision Agent',
  instructions: 'You can see images, watch videos, and listen to audio.',
  model: '__GATEWAY_GOOGLE_MODEL_FLASH__',
  channels: {
    adapters: {
      discord: createDiscordAdapter(),
    },
    inlineMedia: ['image/*', 'video/*', 'audio/*'],
    inlineLinks: [
      { match: 'youtube.com', mimeType: 'video/*' },
      { match: 'youtu.be', mimeType: 'video/*' },
      'imgur.com',
    ],
  },
})
```

使用這項設定後：

- 用戶上載螢幕截圖，Agent 描述畫面內容。
- 用戶上載 `.mp4` 片段，Agent 概述影片。
- 用戶貼上 YouTube 連結，Agent 觀看及討論影片。
- 用戶貼上 imgur 連結，Agent 直接查看圖片。

預設只有圖片會以行內媒體形式傳送（`inlineMedia: ['image/*']`）。不支援的類型會以文字摘要描述，讓 Agent 知道檔案存在，同時避免不接受該類型的模型出錯。所有 `inlineMedia` 模式見[頻道參考文件](/reference/agents/channels#inline-media)；網域配對、HEAD 偵測及指定 MIME 類型見 [inlineLinks 參考文件](/reference/agents/channels#inline-links)。

## 無伺服器部署 {/* #serverless-deployment */}

在 Vercel 等無伺服器平台，每個請求都由獨立而短暫存在的實例處理。要讓頻道可靠運作，須在 Agent 回覆期間保持函式運行，並透過共用發布訂閱機制協調各個實例。

### 使用 `waitUntil` 保持函式運行 {/* #keep-the-function-alive-with-waituntil */}

頻道 webhook 會立即回傳 `200`，Agent 隨後在背景運行並發佈回覆。大多數無伺服器平台在回應送出後會立即凍結函式，令 Agent 尚未回覆便停止運行。傳入 `waitUntil` 函式，讓平台維持實例運作，直至該次運行完成。

在 Vercel 上，請將 `@vercel/functions` 提供的 `waitUntil` 傳入設定：

```typescript title="src/mastra/agents/your-agent.ts"
import { Agent } from '@mastra/core/agent'
import { createSlackAdapter } from '@chat-adapter/slack'
import { waitUntil } from '@vercel/functions'

export const yourAgent = new Agent({
  id: 'your-agent',
  name: 'Your Agent',
  instructions: 'You are a helpful assistant.',
  model: '__GATEWAY_OPENAI_MODEL__',
  channels: {
    adapters: {
      slack: createSlackAdapter(),
    },
    waitUntil,
  },
})
```

Vercel 及 AWS Lambda 會在回應送出後凍結函式，因此需要 `waitUntil`。Cloudflare Workers 及 Netlify Functions 可從請求上下文自動偵測，毋須手動提供。若執行環境的請求上下文有 `waitUntil`，但無法自動偵測，請使用 `resolveWaitUntil`。詳情見[頻道參考文件](/reference/agents/channels#parameters)。

### 以共用發布訂閱機制協調實例 {/* #coordinate-instances-with-a-shared-pubsub */}

頻道透過 Agent 的 [Signal 處理流程](/docs/signals/overview)路由訊息。每次運行都會取得所屬對話串的租約，確保同一時間只有一次運行負責該對話。

預設的記憶體內發布訂閱機制不能跨實例通訊，因此在無伺服器環境，後續訊息可能被送到與目前運行 Agent 不同的實例。

若沒有共用發布訂閱機制，另一個實例無法聯絡進行中的運行，便會自行啟動新運行；原有運行不受影響，但同一對話串會被處理兩次。

請在 `Mastra` 實例設定以 Redis Streams 為後端的共用發布訂閱機制，讓租約及 Signal 可跨實例協調：

```typescript title="src/mastra/index.ts"
import { Mastra } from '@mastra/core'
import { RedisStreamsPubSub } from '@mastra/redis-streams'
import { yourAgent } from './agents/your-agent'

export const mastra = new Mastra({
  agents: { yourAgent },
  pubsub: new RedisStreamsPubSub({
    url: process.env.REDIS_URL,
    keyPrefix: 'mastra:my-app',
  }),
})
```

Vercel 的託管 Redis 整合及 Upstash Redis 均可使用。何時需要分散式發布訂閱機制，請參閱 [PubSub 指南](/docs/server/pubsub)及 [`RedisStreamsPubSub` 參考文件](/reference/pubsub/redis-streams)。

### 查閱適配器文件 {/* #check-the-adapter-docs */}

在將新適配器接入 Mastra 前，請查閱其文件並確認：

- 是否支援附件、卡片及豐富訊息。
- 所需的憑證環境變數。
- 必要的平台權限或 scope。
- 一般訊息是否需要長時間運行的監聽程式或輪詢。
- 平台是否需要分別為設定、事件或互動提供路由。
- webhook 的驗證方式。
