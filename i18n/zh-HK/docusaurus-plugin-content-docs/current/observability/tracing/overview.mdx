# 用法

追蹤是一種可觀測性訊號，記錄請求經過 Agent、Workflow、Tool 及模型呼叫的過程。Mastra 將每項操作表示為一個 span，並把相關 span 歸入同一條 Trace，方便查看完整執行路徑。

本頁集中說明 Trace 的執行結果、span 階層、抽樣、中繼資料、篩選、Trace ID 及第三方追蹤脈絡。

<Inject>
  **供 AI Agent 使用：**執行 `npx mastra api trace list '{"page":0,"perPage":20}'`，即可直接查看近期的 Trace，毋須開啟 Studio 或編寫臨時腳本。此指令需要已設定可觀測性並正在運行的 Mastra 伺服器；可用 `npx mastra dev` 啟動本機伺服器，或以 `--url` 指定可連線伺服器的基礎 URL。設定其他篩選條件前，先執行 `npx mastra api trace list --schema`。安裝 Mastra Skill：`npx skills add mastra-ai/skills --skill mastra`，即可取得完整的 API CLI 指令探索、目標指定、schema、身份驗證及錯誤處理指引。
</Inject>

## 何時使用追蹤 {/* #when-to-use-tracing */}

* 查看完整執行路徑，排查 Agent 或 Workflow 的非預期行為。
* 追蹤單一請求中的模型呼叫、Tool 呼叫及 Workflow 步驟。
* 加入 Trace 專屬的中繼資料及標籤，方便篩選和調查。
* 將 Mastra Trace 接駁至第三方追蹤系統。

## 開始使用 {/* #get-started */}

要開始追蹤，請先在 Mastra 實例中設定可觀測性，再運行 Agent 或 Workflow。可透過以下功能調整其行為：

* [設定](/docs/observability/overview#configuration)：可觀測性的基本設定、多組設定，以及無伺服器環境下緩衝數據的送出
* [儲存](/docs/observability/overview#storage)：Trace、日誌及指標的儲存路由

## 執行結果 {/* #execution-outcomes */}

span 透過三個原生欄位描述單次執行的結果：

* `outcome`：執行結果，例如 `success`、`error`、`abort`、`interrupted`、`suspend`、`limit`、`blocked` 或 `unknown`。
* `stopReason`：可選的機器可讀原因，例如 `max_steps`、`guardrail` 或 `observer_failed`。
* `stopReasonContext`：關於該原因的簡要可選資訊，例如供應商錯誤碼、處理器 ID、訊號 ID 或相關 span ID。

若 outcome 為 `null` 或不存在，表示尚未記錄結果。可用 `endTime` 判斷 span 是否結束。舊版可觀測性實作可能令已結束的 span 仍保留 `null`。若剛好在容許的最後一步完成，結果為 `success`；用盡步數後仍需再執行一步，則為 `limit / max_steps`。

透過 `stopWhen` 或迭代 hook 按設定條件完成時，結果為 `success`，停止原因為 `stop_condition` 或 `iteration_hook`。委派成功後，若 supervisor 呼叫 `bail()`，則記錄 `success / delegation_bail`。若獲委派的 worker 失敗，hook 隨後退出，worker 會保留其失敗結果，supervisor 則記錄 `interrupted / delegation_bail`；`stopReasonContext` 會包含 `causeOutcome`，並在已知時包含 `causeStopReason`。

呼叫方取消時，目標執行記錄 `abort / caller_cancelled`；因此而停止的未完成子 span 記錄 `interrupted / caller_cancelled`。執行超時則在該執行上記錄 `limit / timeout`，被超時中斷的工作記錄 `interrupted / timeout`。已完成的 span 保留原有結果。通用清理流程會將其餘無法分類的 span 結束為 `unknown`。

若[護欄](/docs/agents/guardrails)觸發 tripwire 並停止執行，結果為 `blocked / guardrail`。其脈絡會標明處理器：

```json
{
  "outcome": "blocked",
  "stopReason": "guardrail",
  "stopReasonContext": { "processorId": "moderation" }
}
```

對於 Mastra 產生的結果，`stopReasonContext` 是提示訊息中的扁平摘要，最多包含三個純量欄位。它不包含原始錯誤訊息、訊號內容、tripwire 中繼資料或巢狀原因。字串最多 128 個字元；過長的值會被省略。缺少的資訊不會補上空欄位，若沒有可用資訊，脈絡為 `null`。

自訂生產者可以提供自己的結果字串、停止原因和脈絡物件。這些值會在 span 更新、匯出和重建過程中保留，並遵循與 span 中繼資料相同的序列化限制。框架的允許清單僅適用於 Mastra 生成的脈絡。

模型 chunk span 只在輸出處理器接受或脫敏內容後才記錄該內容。供應商的耗時和完成狀態另行記錄，不擷取原始 chunk 內容。Workflow 主動等待時記錄 `suspend`；執行器停止並移交未完成工作時記錄 `interrupted`，即使持久化的 Workflow 狀態為 `waiting` 也是如此。

當 observer 失敗並使主執行停止時，observer span 記錄自身結果，主 span 報告 `interrupted / observer_failed`。脈絡透過 `observerSpanId` 指向 observer 的 memory 操作，並用 `causeOutcome` 和 `causeStopReason` 概括其結果。例如，observer 因脈絡窗口耗盡而停止時，其結果仍是 `limit / context_window_exceeded`；請查看該 span 取得診斷資訊。訊號中斷只保留 `signalId` 和 `signalType`。

如果設定的失敗策略允許主執行繼續，主執行仍可能成功。護欄重試後若恢復，最終成功結果以及此前被拒絕嘗試的獨立結果都會保留。

`MastraStorageExporter` 和 `MastraPlatformExporter` 會在匯出的 span 記錄中攜帶這些欄位。要持久化這些欄位，儲存實作也必須支援它們。

模型推論 span（`MODEL_INFERENCE`）衡量供應商的執行過程並記錄用量。模型 chunk span（`MODEL_CHUNK`）記錄輸出處理器接受或轉換後的內容。chunk 屬於邏輯步驟（`MODEL_STEP`），因此即使緩衝中的輸出在供應商執行結束後才抵達，也不會超出父 span 的生命週期。在 Agent 串流路徑中，推論 span 不再擷取回應輸出；請改用處理後的 chunk span 或生成結果中的輸出。

## 抽樣策略 {/* #sampling-strategies */}

抽樣用於控制收集哪些 Trace，以平衡可觀測性需求與資源成本。

在高流量正式環境中，收集每條 Trace 可能既昂貴又沒有必要。

抽樣策略可擷取具代表性的 Trace 子集，同時確保不會遺漏錯誤和重要操作的關鍵資訊。

可在可觀測性設定層設定抽樣：

```ts title="src/mastra/index.ts"
import { Mastra } from '@mastra/core'
import { Observability } from '@mastra/observability'

export const mastra = new Mastra({
  observability: new Observability({
    configs: {
      '10_percent': {
        serviceName: 'my-service',
        // Sample 10% of traces
        sampling: {
          type: 'ratio',
          probability: 0.1,
        },
        exporters: [new MastraStorageExporter()],
      },
    },
  }),
})
```

`sampling` 選項控制收集哪些 Trace，幫助平衡可觀測性需求與資源成本。Mastra 支援四種抽樣策略：

1. **全量抽樣**：收集所有 Trace。適合需要完整可見性的開發、除錯或低流量情況。

   ```ts
   sampling: {
     type: 'always'
   }
   ```

2. **不抽樣**：完全停用追蹤。適合追蹤沒有價值的特定環境，或需要暫時停用追蹤但保留設定的情況。

   ```ts
   sampling: {
     type: 'never'
   }
   ```

3. **按比例抽樣**：隨機收集一定比例的 Trace。適合希望取得統計資料、又不想承擔全量追蹤成本的正式環境。機率介乎 0（不收集）與 1（全部收集）之間。

   ```ts oxfmt:false
   sampling: {
     type: 'ratio',
     probability: 0.1  // Sample 10% of traces
   }
   ```

4. **自訂抽樣**：按請求脈絡、中繼資料或業務規則實作抽樣邏輯。適合按使用者級別、請求類型或錯誤條件抽樣等複雜情況。

   ```ts oxfmt:false
   sampling: {
     type: 'custom',
     sampler: (options) => {
       // Sample premium users at higher rate
       if (options?.metadata?.userTier === 'premium') {
         return Math.random() < 0.5; // 50% sampling
       }

       // Default 1% sampling for others
       return Math.random() < 0.01;
     }
   }
   ```

## 加入自訂中繼資料 {/* #adding-custom-metadata */}

加入自訂中繼資料，在 Trace 中記錄應用特有的脈絡，以便排查生產問題。

中繼資料可以包含業務邏輯資訊和性能指標，也可以攜帶使用者脈絡或其他有助於解釋執行過程的資訊。

可透過追蹤脈絡向任意 span 加入中繼資料：

```ts
execute: async (inputData, context) => {
  const startTime = Date.now()
  const response = await fetch(inputData.endpoint)

  // Add custom metadata to the current span
  context?.tracingContext.currentSpan?.update({
    metadata: {
      apiStatusCode: response.status,
      endpoint: inputData.endpoint,
      responseTimeMs: Date.now() - startTime,
      userTier: inputData.userTier,
      region: process.env.AWS_REGION,
    },
  })

  return await response.json()
}
```

此處設定的中繼資料會顯示在所有已設定的 exporter 中。

### 用部署環境標記 Trace {/* #tagging-traces-with-the-deployment-environment */}

在 Mastra 頂層設定 `environment`，即可自動為所有可觀測性訊號附上部署環境，而不必每次呼叫都傳入 `tracingOptions.metadata.environment`。

```ts title="src/mastra/index.ts"
import { Mastra } from '@mastra/core'
import { Observability } from '@mastra/observability'

export const mastra = new Mastra({
  environment: 'production',
  observability: new Observability({
    configs: {
      default: {
        serviceName: 'my-service',
        exporters: [new MastraStorageExporter()],
      },
    },
  }),
})
```

如果未設定 `environment`，透過 `mastra dev` 啟動的執行會使用 `development`（儘管開發伺服器自身的 `NODE_ENV=production`）；其他情況下，Mastra 會回退到 `process.env.NODE_ENV`。若都未設定，該欄位保持未定義，不會猜測其值。

每次呼叫傳入的 `tracingOptions.metadata.environment` 始終優先，因此可以按需覆蓋單次呼叫的環境值。

### 自動從 `RequestContext` 提取中繼資料 {/* #automatic-metadata-from-requestcontext */}

毋須手動為每個 span 加入中繼資料。您可以讓 Mastra 自動從 RequestContext 提取值，並附加到同一條 Trace 的所有 span。這有助於在整條 Trace 中一致地記錄使用者 ID、環境資訊、功能開關及其他請求級數據。

#### 設定層提取 {/* #configuration-level-extraction */}

在追蹤設定中指定要提取的 RequestContext 鍵。使用該設定建立的所有 span 都會自動將這些鍵對應的值加入中繼資料：

```ts title="src/mastra/index.ts"
import { Mastra } from '@mastra/core'
import { Observability } from '@mastra/observability'

export const mastra = new Mastra({
  observability: new Observability({
    configs: {
      default: {
        serviceName: 'my-service',
        requestContextKeys: ['userId', 'environment', 'tenantId'],
        exporters: [new MastraStorageExporter()],
      },
    },
  }),
})
```

現在，使用 RequestContext 執行 Agent 或 Workflow 時，這些值會被自動提取：

```ts
const requestContext = new RequestContext()
requestContext.set('userId', 'user-123')
requestContext.set('environment', 'production')
requestContext.set('tenantId', 'tenant-456')

// All spans in this trace automatically get userId, environment, and tenantId metadata
const result = await agent.generate('Hello', {
  requestContext,
})
```

#### 按請求加入 {/* #per-request-additions */}

可透過 `tracingOptions.requestContextKeys` 加入本次 Trace 專用的鍵；它們會與設定層的鍵合併：

```ts
const requestContext = new RequestContext()
requestContext.set('userId', 'user-123')
requestContext.set('environment', 'production')
requestContext.set('experimentId', 'exp-789')

const result = await agent.generate('Hello', {
  requestContext,
  tracingOptions: {
    requestContextKeys: ['experimentId'], // Adds to configured keys
  },
})

// All spans now have: userId, environment, AND experimentId
```

#### 提取巢狀值 {/* #nested-value-extraction */}

使用點號路徑從 RequestContext 提取巢狀值：

```ts
export const mastra = new Mastra({
  observability: new Observability({
    configs: {
      default: {
        requestContextKeys: ['user.id', 'session.data.experimentId'],
        exporters: [new MastraStorageExporter()],
      },
    },
  }),
})

const requestContext = new RequestContext()
requestContext.set('user', { id: 'user-456', name: 'John Doe' })
requestContext.set('session', { data: { experimentId: 'exp-999' } })

// Metadata will include: { user: { id: 'user-456' }, session: { data: { experimentId: 'exp-999' } } }
```

#### 工作原理 {/* #how-it-works */}

1. **計算 TraceState**：建立根 span、啟動 Trace 時，Mastra 合併設定層和請求層的鍵，確定要提取的內容。
2. **自動提取**：根 span（Agent 執行、Workflow 執行）自動從 RequestContext 提取中繼資料。
3. **子 span 提取**：建立子 span 時，若傳入 `requestContext`，子 span 也可以提取中繼資料。
4. **中繼資料優先級**：span 選項中明確傳入的中繼資料始終優先於提取的中繼資料。

### 為 Trace 加入標籤 {/* #adding-tags-to-traces */}

標籤是用於分類和過濾 Trace 的字串標記。中繼資料包含結構化鍵值數據，標籤則是便於快速過濾和組織的普通字串。

執行 Agent 或 Workflow 時，透過 `tracingOptions.tags` 加入標籤：

```ts
// With agents
const result = await agent.generate('Hello', {
  tracingOptions: {
    tags: ['production', 'experiment-v2', 'user-request'],
  },
})

// With workflows
const run = await mastra.getWorkflow('myWorkflow').createRun()
const result = await run.start({
  inputData: { data: 'process this' },
  tracingOptions: {
    tags: ['batch-processing', 'priority-high'],
  },
})
```

#### 標籤的工作方式 {/* #how-tags-work */}

* **僅根 span**：標籤只應用於 Trace 的根 span（Agent 執行或 Workflow 執行的 span）。
* **廣泛支援**：大多數 exporter 都支援用標籤過濾和搜尋 Trace：
  * **Braintrust**：原生 `tags` 欄位
  * **Langfuse**：Trace 上的原生 `tags` 欄位
  * **ArizeExporter**：`tag.tags` OpenInference 屬性
  * **OtelExporter**：`mastra.tags` span 屬性
  * **OtelBridge**：`mastra.tags` span 屬性
* **可與中繼資料組合**：同一次 `tracingOptions` 中可以同時使用 `tags` 和 `metadata`。

```ts
const result = await agent.generate([{ role: 'user', content: 'Analyze this' }], {
  tracingOptions: {
    tags: ['production', 'analytics'],
    metadata: { userId: 'user-123', experimentId: 'exp-456' },
  },
})
```

#### 常見標籤用法 {/* #common-tag-patterns */}

* **環境**：`"production"`、`"staging"`、`"development"`
* **功能開關**：`"feature-x-enabled"`、`"beta-user"`
* **請求類型**：`"user-request"`、`"batch-job"`、`"scheduled-task"`
* **優先級**：`"priority-high"`、`"priority-low"`
* **實驗**：`"experiment-v1"`、`"control-group"`、`"treatment-a"`

### 為 Trace 命名 {/* #naming-a-trace */}

同一個 Agent 或 Workflow 的每次執行預設使用相同的根 span 名稱，例如 `workflow run: 'skill-analyze'`。如果一個 Workflow 會處理多種物件，可在 `tracingOptions` 中設定 `rootSpanName`，為每次執行命名。該名稱會替換 Studio Trace 清單及支援顯示 span 名稱的 exporter 中的根 span 名稱。

```ts
const run = await mastra.getWorkflow('skillAnalyze').createRun()

await run.start({
  inputData: { skillId: 'typescript' },
  tracingOptions: {
    rootSpanName: 'skill-analyze: typescript',
  },
})
```

該名稱僅用於根 span，子 span 保留預設名稱。Workflow 或 Agent ID 會單獨存為 `entityId` 和 `entityName`，因此實體過濾仍然有效。

基於 OpenTelemetry 的 exporter 和 Langfuse exporter 會根據實體 ID 構造 span 和 Trace 名稱，因此不受影響。若要命名 Langfuse Trace，請按 [Langfuse 集成文件](/integrations/observability/langfuse)設定 `metadata.traceName`。

### 隱藏敏感輸入/輸出 {/* #hiding-sensitive-inputoutput */}

處理敏感數據時，您可能希望避免在可觀測性平台中記錄輸入和輸出值。可在 `tracingOptions` 中使用 `hideInput` 和 `hideOutput`，從整條 Trace 的所有 span 中排除這些數據：

```ts
// Hide input data (e.g., user credentials, PII)
const result = await agent.generate([{ role: 'user', content: 'Process this sensitive data' }], {
  tracingOptions: {
    hideInput: true, // Input will be hidden from all spans
  },
})

// Hide output data (e.g., generated secrets, confidential results)
const result = await agent.generate([{ role: 'user', content: 'Generate API keys' }], {
  tracingOptions: {
    hideOutput: true, // Output will be hidden from all spans
  },
})

// Hide both input and output
const result = await agent.generate([{ role: 'user', content: 'Handle confidential request' }], {
  tracingOptions: {
    hideInput: true,
    hideOutput: true,
  },
})
```

#### 工作原理 {/* #how-it-works-1 */}

* **整條 Trace 生效**：在根 span 上設定後，這些選項會應用於 Trace 中的所有子 span，包括 Tool 呼叫和模型生成等。
* **匯出時過濾**：執行期間數據仍可在內部使用，但匯出 span 到可觀測性平台時會排除這些數據。
* **可與其他選項組合**：`hideInput`/`hideOutput` 可以與 `tags`、`metadata` 及其他 `tracingOptions` 一同使用。

```ts
const result = await agent.generate([{ role: 'user', content: 'Sensitive operation' }], {
  tracingOptions: {
    hideInput: true,
    hideOutput: true,
    tags: ['sensitive-operation', 'pii-handling'],
    metadata: { operationType: 'credential-processing' },
  },
})
```

如需更精細地控制敏感數據，可使用 [Sensitive Data Filter](/reference/observability/tracing/processors/sensitive-data-filter) 處理器。它能遮蔽密碼、令牌、密鑰等指定欄位，同時保留其餘輸入和輸出。

#### 子 span 與中繼資料提取 {/* #child-spans-and-metadata-extraction */}

在 Tool 或 Workflow 步驟內建立子 span 時，可傳入 `requestContext` 參數，以啟用中繼資料提取：

```ts
execute: async (inputData, context) => {
  // Create child span WITH requestContext - gets metadata extraction
  const dbSpan = context?.tracingContext.currentSpan?.createChildSpan({
    type: 'generic',
    name: 'database-query',
    requestContext: context?.requestContext, // Pass to enable metadata extraction
  })

  const results = await db.query('SELECT * FROM users')
  dbSpan?.end({ output: results })

  // Or create child span WITHOUT requestContext - no metadata extraction
  const cacheSpan = context?.tracingContext.currentSpan?.createChildSpan({
    type: 'generic',
    name: 'cache-check',
    // No requestContext - won't extract metadata
  })

  return results
}
```

您可以精確控制哪些子 span 包含 RequestContext 中繼資料。根 span（Agent 或 Workflow 執行）始終自動提取；子 span 只有在明確傳入 `requestContext` 時才會提取。

## 建立子 span {/* #creating-child-spans */}

子 span 可追蹤 Workflow 步驟或 Tool 內部的細緻操作，例如數據庫查詢、API 呼叫、文件操作或複雜計算。這種層級結構有助於定位性能瓶頸，並瞭解操作的確切執行順序。

在 Tool 呼叫或 Workflow 步驟中建立子 span，以追蹤具體操作：

```ts
execute: async (inputData, context) => {
  // Create another child span for the main database operation
  const querySpan = context?.tracingContext.currentSpan?.createChildSpan({
    type: 'generic',
    name: 'database-query',
    input: { query: inputData.query },
    metadata: { database: 'production' },
  })

  try {
    const results = await db.query(inputData.query)
    querySpan?.end({
      output: results.data,
      metadata: {
        rowsReturned: results.length,
        queryTimeMs: results.executionTime,
        cacheHit: results.fromCache,
      },
    })
    return results
  } catch (error) {
    querySpan?.error({
      error,
      metadata: { retryable: isRetryableError(error) },
    })
    throw error
  }
}
```

子 span 會自動繼承父 span 的 Trace 脈絡，在可觀測性平台中保持層級關係。

## span 格式化 {/* #span-formatting */}

Mastra 提供兩種在 span 數據送達可觀測性平台前進行轉換的方式：**span 處理器**和**自訂 span 格式化器**。兩者都能修改、過濾或豐富 Trace 數據，但作用層級和用途不同。

| 功能 | Span 處理器 | 自訂 span 格式化器 |
| - | - | - |
| 設定層級 | 可觀測性設定 | 單一 exporter |
| 處理物件 | 內部 `Span` 物件 | 匯出的 `ExportedSpan` 數據 |
| 適用範圍 | 所有 exporter | 單一 exporter |
| 非同步支援 | 否 | 是 |
| 用途 | 安全、過濾、資訊補充 | 平台專屬格式化、非同步補充資訊 |

需要對所有 exporter 應用同步轉換（例如遮蔽敏感數據）時，使用 **span 處理器**。如果不同 exporter 需要同一數據的不同表示形式（例如一個平台使用純文字，另一個使用結構化數據），或需要從外部 API 取得數據等非同步操作，則使用**自訂 span 格式化器**。

### span 處理器 {/* #span-processors */}

span 處理器會在匯出前轉換、過濾或豐富 Trace 數據。它們構成從建立 span 到匯出的處理流水線，可用於安全、合規或除錯。每個處理器執行一次，其結果影響所有 exporter。

#### 內建處理器 {/* #built-in-processors */}

* [Sensitive Data Filter](/reference/observability/tracing/processors/sensitive-data-filter) 會遮蔽敏感資訊，並在預設可觀測性設定中啟用。

#### 建立自訂處理器 {/* #creating-custom-processors */}

實作 `SpanOutputProcessor` 介面即可建立自訂 span 處理器。以下基礎範例將 span 中的所有輸入文字轉為小寫：

```ts title="src/processors/lowercase-input-processor.ts"
import type { SpanOutputProcessor, AnySpan } from '@mastra/core/observability'
import { Mastra } from '@mastra/core'
import { Observability } from '@mastra/observability'

export class LowercaseInputProcessor implements SpanOutputProcessor {
  name = 'lowercase-processor'

  process(span: AnySpan): AnySpan {
    span.input = `${span.input}`.toLowerCase()
    return span
  }

  async shutdown(): Promise<void> {
    // Cleanup if needed
  }
}

// Use the custom processor
export const mastra = new Mastra({
  observability: new Observability({
    configs: {
      development: {
        spanOutputProcessors: [new LowercaseInputProcessor(), new SensitiveDataFilter()],
        exporters: [new MastraStorageExporter()],
      },
    },
  }),
})
```

`process()` 必須修改收到的 span 並傳回同一個實例，或傳回 `undefined` 以捨棄該 span。不要傳回副本（例如 `{ ...span, input: '...' }`）：`exportSpan()` 和 `isValid` 是實際 span 實例的成員，副本無法匯出。此時 Mastra 會記錄處理器錯誤並捨棄該 span。

處理器按定義順序執行，因此可以串聯多個轉換。常見用途包括：

* 遮蔽密碼、令牌和 API 密鑰等敏感數據
* 加入環境專屬中繼資料
* 按條件過濾 span
* 統一數據格式
* 補充業務脈絡

## span 過濾 {/* #span-filtering */}

span 過濾可在數據抵達可觀測性平台前減少噪聲和按 span 計費的成本。可針對每個可觀測性實例單獨設定，讓不同 exporter 或環境保留不同詳細程度的數據。

* 使用 `excludeSpanTypes`，以少量設定排除整類 span。
* 需要根據匯出的 span 數據執行自訂邏輯時，使用 `spanFilter`。

以下範例展示如何在同一設定中組合這兩個選項：

```ts title="src/mastra/index.ts"
import { Mastra } from '@mastra/core'
import { SpanType } from '@mastra/core/observability'
import { Observability, MastraStorageExporter } from '@mastra/observability'
import { LangfuseExporter } from '@mastra/langfuse'

export const mastra = new Mastra({
  observability: new Observability({
    configs: {
      default: {
        serviceName: 'my-app',
        exporters: [new MastraStorageExporter(), new LangfuseExporter()],
        excludeSpanTypes: [SpanType.MODEL_CHUNK, SpanType.MODEL_STEP],
        spanFilter: span => {
          if (span.type === SpanType.TOOL_CALL && span.attributes?.success) {
            return false
          }

          return true
        },
      },
    },
  }),
})
```

過濾在匯出時按以下順序進行：

1. 除非 `includeInternalSpans` 為 `true`，否則先丟棄內部 span。
1. `excludeSpanTypes` 移除匹配的 span 類型。
1. `spanOutputProcessors` 轉換剩餘的 span。
1. `spanFilter` 決定是否保留最終匯出的 span。

如果 `spanFilter` 拋出異常，Mastra 會保留 span 並記錄錯誤，避免數據悄然遺失。完整 span 類型清單和更多範例見 [span 過濾參考文件](/reference/observability/tracing/span-filtering)。

### 自訂 span 格式化器 {/* #custom-span-formatters */}

自訂 span 格式化器可調整 span 在特定可觀測性平台中的呈現方式。與 span 處理器不同，它按 exporter 設定，因此各目標平台可以使用不同格式，並且支援同步和非同步操作。

#### 用途 {/* #use-cases */}

* **從 AI SDK 消息提取純文字**：將結構化消息陣列轉換為可讀文字。
* **轉換輸入/輸出格式**：自訂特定平台的數據呈現方式。
* **平台專屬欄位映射**：按平台要求增減欄位。
* **非同步補充數據**：從外部 API 或數據庫取得更多脈絡。

#### 設定 {/* #configuration */}

在任意 exporter 設定中加入 `customSpanFormatter`：

```ts title="src/mastra/index.ts"
import { BraintrustExporter } from '@mastra/braintrust'
import { LangfuseExporter } from '@mastra/langfuse'
import { SpanType } from '@mastra/core/observability'
import type { CustomSpanFormatter } from '@mastra/core/observability'
import { Mastra } from '@mastra/core'
import { Observability } from '@mastra/observability'

// Formatter that extracts plain text from AI messages
const plainTextFormatter: CustomSpanFormatter = span => {
  if (span.type === SpanType.AGENT_RUN && Array.isArray(span.input)) {
    const userMessage = span.input.find(m => m.role === 'user')
    return {
      ...span,
      input: userMessage?.content ?? span.input,
    }
  }
  return span
}

export const mastra = new Mastra({
  observability: new Observability({
    configs: {
      default: {
        serviceName: 'my-service',
        exporters: [
          // Braintrust gets plain text formatting
          new BraintrustExporter({
            customSpanFormatter: plainTextFormatter,
          }),
          // Langfuse keeps the original structured format
          new LangfuseExporter(),
        ],
      },
    },
  }),
})
```

#### 串聯多個格式化器 {/* #chaining-multiple-formatters */}

使用 `chainFormatters` 組合多個格式化器。鏈中可以同時包含同步和非同步格式化器：

```ts
import { chainFormatters } from '@mastra/observability'

const inputFormatter: CustomSpanFormatter = span => ({
  ...span,
  input: extractPlainText(span.input),
})

const outputFormatter: CustomSpanFormatter = span => ({
  ...span,
  output: extractPlainText(span.output),
})

const exporter = new BraintrustExporter({
  customSpanFormatter: chainFormatters([inputFormatter, outputFormatter]),
})
```

#### 非同步格式化器 {/* #async-formatters */}

自訂 span 格式化器支援非同步操作，例如從外部 API 或數據庫取得數據，為 span 補充資訊：

```ts
import type { CustomSpanFormatter } from '@mastra/core/observability'

// Async formatter that enriches spans with user data
const userEnrichmentFormatter: CustomSpanFormatter = async span => {
  const userId = span.metadata?.userId
  if (!userId) return span

  // Fetch user data from your API or database
  const userData = await fetchUserData(userId)

  return {
    ...span,
    metadata: {
      ...span.metadata,
      userName: userData.name,
      userEmail: userData.email,
      department: userData.department,
    },
  }
}

// Async formatter that looks up additional context
const contextEnrichmentFormatter: CustomSpanFormatter = async span => {
  if (span.type !== SpanType.AGENT_RUN) return span

  // Fetch experiment configuration
  const experimentConfig = await getExperimentConfig(span.metadata?.experimentId)

  return {
    ...span,
    metadata: {
      ...span.metadata,
      experimentVariant: experimentConfig?.variant,
      experimentGroup: experimentConfig?.group,
    },
  }
}

// Use async formatters with an exporter
const exporter = new BraintrustExporter({
  customSpanFormatter: userEnrichmentFormatter,
})

// Or chain sync and async formatters together
const exporter = new LangfuseExporter({
  customSpanFormatter: chainFormatters([
    plainTextFormatter, // sync
    userEnrichmentFormatter, // async
    contextEnrichmentFormatter, // async
  ]),
})
```

:::note
非同步格式化器會增加 span 匯出延遲。請讓非同步操作盡快完成（低於 100 毫秒），避免拖慢應用。對於經常存取的數據，可考慮使用快取。
:::

## 序列化選項 {/* #serialization-options */}

序列化選項控制 span 數據（輸入、輸出和屬性）在匯出前如何截斷。處理大型載荷、深層巢狀物件，或優化 Trace 儲存時，這些選項很有用。

### 設定 {/* #configuration-1 */}

在可觀測性設定中加入 `serializationOptions`：

```ts title="src/mastra/index.ts"
import { Mastra } from '@mastra/core'
import { Observability } from '@mastra/observability'

export const mastra = new Mastra({
  observability: new Observability({
    configs: {
      default: {
        serviceName: 'my-service',
        serializationOptions: {
          maxStringLength: 2048, // Maximum length for string values (default: 131072)
          maxDepth: 10, // Maximum depth for nested objects (default: 8)
          maxArrayLength: 100, // Maximum number of items in arrays (default: 50)
          maxObjectKeys: 75, // Maximum number of keys in objects (default: 50)
        },
        exporters: [new MastraStorageExporter()],
      },
    },
  }),
})
```

### 可用選項 {/* #available-options */}

| 選項 | 預設值 | 說明 |
| - | - | - |
| `maxStringLength` | 131072 (128 KB) | 字串值的最大長度；超過後會截斷。 |
| `maxDepth` | 8 | 巢狀物件的最大深度；更深層級會被省略。 |
| `maxArrayLength` | 50 | 陣列的最大元素數；多餘元素會被省略。 |
| `maxObjectKeys` | 50 | 物件的最大鍵數；多餘的鍵會被省略。 |

### 使用場景 {/* #use-cases-1 */}

**提高限制以便除錯**：提高這些上限，可以擷取大型文件、API 回應及其他數據結構的更多脈絡：

```ts oxfmt:false
serializationOptions: {
  maxStringLength: 262144, // Capture longer text content (256 KB)
  maxDepth: 12,            // Handle deeply nested JSON responses
  maxArrayLength: 200,     // Keep more items from large lists
}
```

**縮小正式環境中的 Trace 體積**：不需要完整載荷時，降低上限可減少儲存成本並改善性能：

```ts oxfmt:false
serializationOptions: {
  maxStringLength: 256,   // Truncate strings aggressively
  maxDepth: 3,            // Shallow object representation
  maxArrayLength: 10,     // Keep only first few items
  maxObjectKeys: 20,      // Limit object keys
}
```

所有選項均可省略；未指定時使用上表所示的預設值。

## 取得 Trace ID {/* #retrieving-trace-ids */}

啟用追蹤後，執行 Agent 或 Workflow 的回應會包含 `traceId`，可用於在可觀測性平台中查找完整 Trace。這有助於除錯、客戶支援，或將 Trace 與系統中的其他事件關聯起來。

### Agent Trace ID {/* #agent-trace-ids */}

`generate` 和 `stream` 方法都會在回應中傳回 Trace ID：

```ts
// Using generate
const result = await agent.generate('Hello')

console.log('Trace ID:', result.traceId)

// Using stream
const streamResult = await agent.stream('Tell me a story')

console.log('Trace ID:', streamResult.traceId)
```

### Workflow Trace ID {/* #workflow-trace-ids */}

Workflow 執行也會傳回 Trace ID：

```ts
// Create a workflow run
const run = await mastra.getWorkflow('myWorkflow').createRun()

// Start the workflow
const result = await run.start({
  inputData: { data: 'process this' },
})

console.log('Trace ID:', result.traceId)

// Or stream the workflow
const { stream, getWorkflowState } = run.stream({
  inputData: { data: 'process this' },
})

// Get the final state which includes the trace ID
const finalState = await getWorkflowState()
console.log('Trace ID:', finalState.traceId)
```

### 使用 Trace ID {/* #using-trace-ids */}

獲得 Trace ID 後，可以：

1. **在 Studio 中查找 Trace**：打開 Trace 視圖，按 ID 搜尋。
1. **在外部平台中查詢 Trace**：在 Langfuse、Braintrust、MLflow 或其他可觀測性平台中使用該 ID。
1. **關聯日誌**：將 Trace ID 寫入應用日誌，以便交叉查找。
1. **分享以協助除錯**：向支援團隊或開發者提供 Trace ID 供其排查。

只有啟用追蹤時才可能獲得 Trace ID。如果追蹤已關閉，或抽樣排除了該請求，`traceId` 會是 `undefined`。

## 集成外部追蹤系統 {/* #integrating-with-external-tracing-systems */}

如果應用已使用 OpenTelemetry 或 Datadog 等分布式追蹤系統，可以將 Mastra Trace 接入父 Trace 脈絡，從而串聯應用及其中 Mastra Agent 或 Workflow 呼叫的請求路徑。

### 傳入外部 Trace ID {/* #passing-external-trace-ids */}

透過 `tracingOptions` 參數指定父系統的 Trace 脈絡：

```ts
// Get trace context from your existing tracing system
const parentTraceId = getCurrentTraceId() // Your tracing system
const parentSpanId = getCurrentSpanId() // Your tracing system

// Execute Mastra operations as part of the parent trace
const result = await agent.generate('Analyze this data', {
  tracingOptions: {
    traceId: parentTraceId,
    parentSpanId: parentSpanId,
  },
})

// The Mastra trace will now appear as a child in your distributed trace
```

### OpenTelemetry 集成 {/* #opentelemetry-integration */}

透過 OpenTelemetry 集成，Mastra Trace 可以直接出現在現有可觀測性平台中：

```ts
import { trace } from '@opentelemetry/api'

// Get the current OpenTelemetry span
const currentSpan = trace.getActiveSpan()
const spanContext = currentSpan?.spanContext()

if (spanContext) {
  const result = await agent.generate(userMessage, {
    tracingOptions: {
      traceId: spanContext.traceId,
      parentSpanId: spanContext.spanId,
    },
  })
}
```

### Workflow 集成 {/* #workflow-integration */}

Workflow 也支援相同的 Trace 傳遞方式：

```ts
const workflow = mastra.getWorkflow('data-pipeline')
const run = await workflow.createRun()

const result = await run.start({
  inputData: { data: '...' },
  tracingOptions: {
    traceId: externalTraceId,
    parentSpanId: externalSpanId,
  },
})
```

### 將執行巢狀到先前的 Mastra 執行之下 {/* #nesting-a-run-under-an-earlier-mastra-run */}

`parentSpanId` 可以指向兩類 span。一類屬於您自己的追蹤系統，如上面的範例。此時，Mastra 會將該執行視為其匯出 Trace 的頂層，由該執行設定 Trace 名稱、輸入、輸出和標籤。

另一類是同一條 Trace 中較早的 Mastra 執行，例如對已完成對話評分的 LLM 裁判。此時設定 `nestUnderParent: true`。新執行會成為該 span 的子節點，Trace 則保留最初啟動執行的名稱、輸入、輸出、標籤、使用者和會話。

```ts
const turn = await assistant.generate('When does my order ship?')

await judge.generate(`Grade this answer: ${turn.text}`, {
  tracingOptions: {
    traceId: turn.traceId,
    parentSpanId: turn.spanId,
    nestUnderParent: true,
  },
})
```

`nestUnderRun()` 輔助函式可根據先前執行的結果生成相同選項：

```ts
import { nestUnderRun } from '@mastra/core/observability'

await judge.generate(`Grade this answer: ${turn.text}`, {
  tracingOptions: nestUnderRun(turn),
})
```

兩次執行可以位於不同處理程序。如果缺少有效的 `traceId` 或 `parentSpanId`，Mastra 會忽略 `nestUnderParent`；如果追蹤橋接在另一條 Trace 中啟動執行，也會忽略該選項。[Langfuse](/integrations/observability/langfuse) 和 [Braintrust](/integrations/observability/braintrust) exporter 會使用此選項。其他 exporter 僅應用標籤規則。

### ID 格式要求 {/* #id-format-requirements */}

Mastra 會驗證 Trace ID 和 span ID，以確保兼容：

* **Trace ID**：1–32 個十六進位字元（OpenTelemetry 使用 32 個）。
* **span ID**：1–16 個十六進位字元（OpenTelemetry 使用 16 個）。

對無效 ID，Mastra 會記錄錯誤並繼續執行：

* 無效 Trace ID → 生成新的 Trace ID
* 無效父 span ID → 忽略父子關係

因此，即使輸入格式錯誤，追蹤也不會導致應用崩潰。

### 範例：Express 中間件 {/* #example-express-middleware */}



```ts
import { trace } from '@opentelemetry/api'
import express from 'express'

const app = express()

app.post('/api/analyze', async (req, res) => {
  // Get current OpenTelemetry context
  const currentSpan = trace.getActiveSpan()
  const spanContext = currentSpan?.spanContext()

  const result = await agent.generate(req.body.message, {
    tracingOptions: spanContext
      ? {
          traceId: spanContext.traceId,
          parentSpanId: spanContext.spanId,
        }
      : undefined,
  })

  res.json(result)
})
```

這會生成一條包含 HTTP 請求處理過程和 Mastra Agent 執行過程的分布式 Trace，可在所選可觀測性平台中查看。

### MCP 呼叫 {/* #mcp-calls */}

Model Context Protocol（MCP）呼叫毋須額外設定，就能連結呼叫方與伺服器端的 Trace。Agent 或 Workflow 透過 `MCPClient` 呼叫 Tool 時，處理請求的 `MCPServer` 會保留自己的 Trace，並記錄指向 Tool 呼叫 span 的連結；該 Tool 呼叫 span 也會反向連結到伺服器端 span。兩端各自保留 Trace、根 span 及 Trace 摘要。如果伺服器端使用追蹤橋接，而其 HTTP 監測機制沿用呼叫方的 Trace，該請求便會加入該 Trace。Mastra 儲存會將連結與 span 一起保存；支援 span 連結的 exporter 也會傳送這些連結。

非 Mastra 軟件位於任一端時也適用。詳情參閱 [`MCPServer` 參考文件](/reference/tools/mcp-server#linking-to-the-callers-trace)；如需傳送自己的 Trace 脈絡，參閱 [`MCPClient` 參考文件](/reference/tools/mcp-client)。

## 追蹤哪些操作 {/* #what-gets-traced */}

Mastra 會自動為以下操作建立 span：

### Agent 操作 {/* #agent-operations */}

* **Agent 執行**：包含指令和 Tool 的完整執行過程。
* **訊號觸發的執行**：`AGENT_RUN` span 在 `attributes.signal` 下記錄起始訊號的 `id`、`type`、`tagName` 和 `attributes`。
* **LLM 呼叫**：記錄模型交互、token 用量和參數。
* **Tool 執行**：記錄函式呼叫的輸入和輸出。
* **Memory 操作**：記錄 Thread 及語意召回。

### Workflow 操作 {/* #workflow-operations */}

* **Workflow 執行**：記錄從開始到結束的完整執行過程。
* **單一步驟**：記錄步驟處理過程及其輸入/輸出。
* **控制流**：記錄條件分支、循環和並行執行。
* **等待操作**：記錄延遲和事件等待。
