# 反饋

反饋記錄會記錄人工參與的訊號，例如讚好或不讚好、評分、留言及更正。如要把用戶、QA、Studio 或系統的審閱資料連結到 Trace 或 Span，並與其他可觀測性訊號一併查詢，可使用反饋。

有別於指標和分數，反饋通常由人員或審閱 Workflow 提供。數值反饋可以彙總、分組、繪成時間趨勢圖，亦可查詢百分位數。

## 何時使用反饋 {/* #when-to-use-feedback */}

- 收集用戶對 Agent 回覆的滿意度評分。
- 將 QA 留言或更正與所審閱的 Trace 一同儲存。
- 按 Agent、環境或實驗建立評分儀表板。

## 加入反饋 {/* #add-feedback */}

在應用程式碼中使用 `mastra.observability.addFeedback()`，可為 Trace 或 Span 加上註記。可觀測性入口不一定提供此輔助方法，請確認目前的實作支援它。所有用戶端方法見[用戶端 SDK 可觀測性參考](/reference/client-js/observability)。

```typescript title="src/mastra/feedback.ts"
if (!mastra.observability.addFeedback) {
  throw new Error('Feedback is not supported by the active observability implementation')
}

await mastra.observability.addFeedback({
  traceId: 'trace-123',
  spanId: 'span-456',
  feedback: {
    feedbackSource: 'user',
    feedbackType: 'rating',
    value: 1,
    comment: 'The answer solved my issue.',
  },
})
```

所有已設定且支援反饋的匯出器都會收到反饋，並各自處理相應的目的地。即使本機儲存沒有該 Trace，亦不會妨礙反饋傳至 Mastra Platform 或其他匯出器。

[`MastraStorageExporter`](/docs/observability/integrations/exporters/mastra-storage) 會先從已設定的儲存區尋找 Trace 或 Span，再儲存反饋。重試後如仍找不到目標，便會記錄警告並跳過本機寫入。請在進程結束前調用 `mastra.observability.flush()` 或 `shutdown()`，完成尚未交付的反饋。

## 查找訊息的 Trace {/* #find-the-trace-for-a-message */}

反饋通常針對用戶已讀過的訊息，所以需要該訊息的 `traceId`。無論是在串流結果內，還是日後從 Memory 取回，助理訊息都會在 `content.metadata` 包含這個值：

```typescript title="src/mastra/message-trace.ts"
const agent = mastra.getAgent('weatherAgent')
const memory = await agent.getMemory()

const { messages } = await memory!.recall({ threadId, perPage: false })

const message = messages.find(m => m.id === messageId)
const traceId = message?.content.metadata?.traceId
```

此值指向該次執行結果所列 `traceId` 的同一個 Trace。因此，無論是在生成訊息時收集反饋，還是其後就已儲存的訊息收集反饋，兩者都會連結到同一個 Trace。關閉追蹤時產生的訊息沒有 `traceId`。

### 在 `useChat` 內讀取 Trace ID {/* #read-the-trace-id-in-usechat */}

[`chatRoute()`](/reference/ai-sdk/chat-route) 和 [`handleChatStream()`](/reference/ai-sdk/handle-chat-stream) 會把該次執行的 `traceId` 傳給 `messageMetadata` 回調。在 `start` 部分傳回該值，用戶端便可從即時訊息取得，無須查詢伺服器：

```typescript title="src/mastra/index.ts"
chatRoute({
  path: '/chat/:agentId',
  messageMetadata: ({ part, traceId }) => (part.type === 'start' ? { traceId } : undefined),
})
```

```tsx title="app/chat.tsx"
const { messages } = useChat<UIMessage<{ traceId?: string }>>()

const lastMessage = messages.at(-1)
const traceId = lastMessage?.role === 'assistant' ? lastMessage.metadata?.traceId : undefined
```

如使用 `messageMetadataSchema` 驗證元數據，請加入 `traceId: z.string().optional()`。將 `traceId` 連同用戶的投票發送至自己的路由，再在該處調用 `addFeedback()`。由於此值來自用戶端，加入反饋前須確認帶有該 `traceId` 的訊息屬於調用者。

## 建立反饋 {/* #create-feedback */}

每次調用 `createFeedback()` 均須提供 `feedbackType` 和 `value`。如要把反饋連結到 Trace 或指定的 Span，請加入 `traceId` 或 `spanId`。你亦可用 `feedbackSource` 提供選填的字串元數據，例如 `user`、`qa`、`studio` 或 `system`。

在儲存層寫入時，請一併提供 `timestamp`，因為此方法會直接寫入儲存區。

```typescript
const observability = await mastra.getStorage()!.getStore('observability')

await observability!.createFeedback({
  feedback: {
    feedbackId: 'feedback-rating-1',
    timestamp: new Date(),
    traceId: 'trace-123',
    spanId: 'span-456',
    feedbackSource: 'user',
    feedbackType: 'rating',
    value: 1,
    comment: 'The answer solved my issue.',
    tags: ['production'],
  },
})

await observability!.createFeedback({
  feedback: {
    feedbackId: 'feedback-comment-1',
    timestamp: new Date(),
    feedbackSource: 'qa',
    feedbackType: 'comment',
    value: 'Needs a citation before shipping.',
    experimentId: 'support-agent-eval',
  },
})
```

## 列出反饋 {/* #list-feedback */}

可用 `listFeedback()` 逐頁查閱原始記錄，或透過增量模式輪詢。

```typescript
const result = await observability!.listFeedback({
  filters: {
    feedbackType: 'rating',
    feedbackSource: 'user',
    timestamp: { start: new Date(Date.now() - 7 * 24 * 60 * 60 * 1000) },
  },
  pagination: { page: 0, perPage: 20 },
  orderBy: { field: 'timestamp', direction: 'DESC' },
})

console.log(result.feedback, result.pagination?.hasMore)
```

篩選條件涵蓋 `traceId`、`spanId` 等目標欄位，`feedbackType`、`feedbackSource`、`feedbackUserId` 等反饋欄位，以及 `entityName`、`environment`、`experimentId` 和 `tags` 等共用上下文欄位。所有可用欄位見 [`FeedbackFilter`](/reference/observability/feedback#feedbackfilter)。透過 HTTP 調用時，這些欄位會以查詢參數傳送，例如 `GET /api/observability/feedback?traceId=trace-123&environment=production`。另見[列表查詢參數](/reference/observability/feedback#list-query-parameters)。

```typescript
await observability!.listFeedback({
  filters: {
    traceId: 'trace-123',
    feedbackType: ['rating', 'thumbs'],
    tags: ['production'],
  },
})
```

## 刪除反饋 {/* #delete-feedback */}

可用 `deleteFeedback()` 按 ID 刪除反饋記錄，例如移除載有敏感資料的留言。每次請求最多接收 1,000 個 `feedbackIds`，刪除操作具冪等性。選填欄位 `organizationId` 按組織篩選，`resourceId` 則按資源篩選，可各自使用或一併提供。在 Studio 內，Trace 或 Span 的 **Feedback** 分頁會為每則留言提供刪除操作。以 `deleteTraces()` 刪除 Trace 時，也會刪除連結到該 Trace 的反饋。詳見[刪除 Trace](/reference/client-js/observability#deleting-traces)。

```typescript
await observability!.deleteFeedback({
  feedbackIds: ['feedback-1', 'feedback-2'],
})
```

已刪除的記錄亦會從反饋分析中移除。ClickHouse 會用輕量刪除隱藏資料列，但不保證即時從實體儲存清除。因此，開源部署須設定[可觀測性資料保留期](/reference/storage/retention)，以便徹底清除這些記錄。刪除成功後，系統會把相關請求標記為已套用；如刪除失敗，請求仍維持未套用，仍然可見的反饋可繼續更新，也可再次調用刪除 API 重試。在 ClickHouse 上，下次更新審閱狀態時也會重試刪除。如重試成功，系統會回報找不到該反饋；若再次失敗，便會儲存新狀態並傳回刪除錯誤。開源部署沒有背景協調程序。請為每種可觀測性訊號設定保留期，使刪除請求在其保護的訊號資料列到期之後才到期。如有任何訊號不設保留期限，刪除請求也不會到期，以免已刪除的資料重新出現。在 ClickHouse 上，刪除 API 不會變更獨立的增量游標表。表內的資料列只存放識別碼，不含反饋內容，並會在兩日內到期。

## 查詢反饋分析資料 {/* #query-feedback-analytics */}

OLAP 反饋查詢會處理數值型的 `value` 欄位，適用於評分、以 `1` 和 `-1` 表示的讚好或不讚好、QA 數值評分及其他數值反饋。

```typescript
const rating = await observability!.getFeedbackAggregate({
  feedbackType: 'rating',
  feedbackSource: 'user',
  aggregation: 'avg',
  comparePeriod: 'previous_day',
})

const byAgent = await observability!.getFeedbackBreakdown({
  feedbackType: 'rating',
  groupBy: ['entityName'],
  aggregation: 'avg',
  filters: { environment: 'production' },
})

const ratingsOverTime = await observability!.getFeedbackTimeSeries({
  feedbackType: 'rating',
  aggregation: 'avg',
  interval: '1h',
  groupBy: ['feedbackSource'],
})
```

所有欄位、篩選條件、傳回類型及百分位數查詢參數見[反饋參考](/reference/observability/feedback)。

本機執行環境會在 `/api/observability/feedback` 提供列表路由，並在相關路徑提供分析功能。詳見 [HTTP 路由表](/reference/observability/feedback#http-routes)及[列表查詢參數](/reference/observability/feedback#list-query-parameters)。Mastra Platform 另有獨立的託管查詢 API，不設版本。區域端點、身分驗證及專案範圍見 [Feedback API](/docs/mastra-platform/api#feedback-api)。

## 將反饋匯出到 Mastra Platform {/* #export-feedback-to-mastra-platform */}

[`MastraPlatformExporter`](/reference/observability/tracing/exporters/mastra-platform-exporter) 會將反饋傳至 Mastra Platform，由平台按需要尋找目標 Trace 或 Span。毋須在本機儲存 Trace；如要同時保留本機副本，才需要加入 `MastraStorageExporter`。

Studio 會把反饋送到負責讀取 Trace 的後端。如由開源伺服器處理建立反饋的 HTTP 請求，伺服器會將反饋儲存在本機，並通知已設定的匯出器。匯出器以非同步方式交付，因此 HTTP 回應成功時，記錄未必已在遠端目的地顯示。直接寫入儲存區會繞過匯出器。

## 將反饋匯出到外部平台 {/* #export-feedback-to-external-platforms */}

反饋經可觀測性事件匯流排傳送，因此支援反饋的匯出器會自動轉發。[PostHog 匯出器](/reference/observability/tracing/exporters/posthog#feedback-export)會以原生 `$ai_feedback` 事件發送反饋，而有關事件會在 PostHog 內相應的 Trace 顯示。
