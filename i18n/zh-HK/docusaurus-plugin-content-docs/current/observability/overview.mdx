# 可觀測性

Mastra 的可觀測性系統可讓你查閱每次 Agent 運行、Workflow 步驟、Tool 呼叫和模型互動。Agent 的行為受模型回應、提示、Tool、記憶及 Workflow 狀態影響，透過可觀測性功能，從開發初期便可檢視運行時的決策。

可先參閱以下與 Trace 有關的頁面：

- [**用量**](/docs/observability/tracing/overview)：查閱一次執行的 Span 層級、輸入、輸出、token 用量、時間資訊及 Trace 上下文。
- [**日誌**](/docs/observability/logging)：轉送應用程式和 Mastra 內部的結構化日誌記錄，並自動關聯至 Trace。
- [**意見回饋**](/docs/observability/feedback)：儲存與 Trace 及 Span 相連的評分、評論、修正內容及其他審閱訊號。
- [**儲存**](#storage)：選擇後端，用於持久儲存 Trace 和日誌、匯總指標及查詢意見回饋。

透過[**指標**](/docs/observability/metrics/overview)分析從 Span 匯總的用量、效能及成本資料，毋須額外加入量測程式碼。可在[**設定**](#configuration)中啟用應用程式所需的訊號及匯出器。

## 可觀測性的使用情境 {/* #when-to-use-observability */}

- 查閱完整的決策路徑、Tool 呼叫及模型回應，排查 Agent 的異常行為。
- 監察 Agent、Workflow 及 Tool 的延遲，找出效能瓶頸。
- 持續追蹤 token 用量及估算成本，以控制開支。
- 追蹤 Workflow 各步驟的執行情況，診斷故障。
- 比較調整提示或模型前後的 Agent 表現。

## 各類資料之間的關聯 {/* #how-the-pieces-fit-together */}

設定可觀測性後，每次 Agent 運行、Workflow 執行、Tool 呼叫和模型互動均會產生一個 [Span](https://opentelemetry.io/docs/concepts/signals/traces/#spans)。Mastra 會把相關的 Span 組成 Trace，以分層時間軸呈現請求的完整生命週期。

Span 結束時，Mastra 會自動擷取耗時、token 數量和估算成本，毋須額外編寫程式碼。[Studio](/docs/studio/observability) 會以這些指標提供匯總儀表板。

在受追蹤的上下文內，每次呼叫 `logger.info()`、`logger.warn()` 或 `logger.error()` 都會加上當前的 Trace ID 及 Span ID。這些 ID 讓你可從日誌條目直接找到產生該條目的 Trace。

意見回饋可記錄評分、評論及修正內容等人工審閱訊號。回饋可連結至 Trace 及 Span，並透過儲存指標的同一個可觀測性儲存查詢。

這些記錄共用 Trace ID、Span ID、實體類型和實體名稱等關聯欄位。當指標急升時，可透過這些欄位找出相關的 Trace、日誌及意見回饋。

## 快速入門 {/* #quickstart */}

安裝 `@mastra/observability` 和支援 Trace 及指標的儲存後端：

```bash npm2yarn
npm install @mastra/observability @mastra/libsql @mastra/duckdb
```

然後在 Mastra 實例中設定可觀測性。以下示例採用組合式儲存，將可觀測性資料送往支援指標匯總的 DuckDB，其餘資料則儲存在 LibSQL：

```ts title="src/mastra/index.ts"
import { Mastra } from '@mastra/core/mastra'
import { LibSQLStore } from '@mastra/libsql'
import { DuckDBStore } from '@mastra/duckdb'
import { MastraCompositeStore } from '@mastra/core/storage'
import {
  Observability,
  MastraStorageExporter,
  MastraPlatformExporter,
  SensitiveDataFilter,
} from '@mastra/observability'

export const mastra = new Mastra({
  storage: new MastraCompositeStore({
    id: 'composite-storage',
    default: new LibSQLStore({
      id: 'mastra-storage',
      url: 'file:./mastra.db',
    }),
    domains: {
      observability: await new DuckDBStore().getStore('observability'),
    },
  }),
  observability: new Observability({
    configs: {
      default: {
        serviceName: 'mastra',
        exporters: [
          new MastraStorageExporter(), // Persists observability events to Mastra Storage
          new MastraPlatformExporter(), // Sends observability events to Mastra platform (if MASTRA_PLATFORM_ACCESS_TOKEN is set)
        ],
        spanOutputProcessors: [
          new SensitiveDataFilter(), // Redacts sensitive data like passwords, tokens, keys
        ],
      },
    },
  }),
})
```

上述設定會啟用追蹤、日誌轉送及指標。Mastra 亦支援 Langfuse、Datadog 等外部追蹤 Provider，以及任何兼容 OpenTelemetry 的平台。如要把資料傳送到外部 Provider，同時保留透過 Mastra Studio 存取資料的功能，請見[保留 Studio 存取](#maintaining-studio-access)。

## 設定 {/* #configuration */}

只須在 Mastra 實例設定一次可觀測性，設定便會套用至 Trace、日誌及指標。

### 基本設定 {/* #basic-config */}

可觀測性設定一般包括以下項目：

- `serviceName`：匯出可觀測性資料時附加的服務識別碼。
- `exporters`：接收 Trace、日誌及衍生指標的一個或多個目的地。
- `spanOutputProcessors`：匯出 Span 前執行的轉換。

### 保留 Studio 存取 {/* #maintaining-studio-access */}

加入外部匯出器時，可保留 `MastraStorageExporter` 以繼續在 Studio 查閱可觀測性資料，或保留 `MastraPlatformExporter` 以使用 Mastra Platform 託管的可觀測性功能。兩者亦可同時保留。

以下示例只展示可觀測性設定。儲存須另行設定。

```ts title="src/mastra/observability.ts"
import { Observability, MastraStorageExporter, MastraPlatformExporter } from '@mastra/observability'
import { ArizeExporter } from '@mastra/arize'

export const observability = new Observability({
  configs: {
    production: {
      serviceName: 'my-service',
      exporters: [
        new ArizeExporter({
          endpoint: process.env.PHOENIX_COLLECTOR_ENDPOINT,
          apiKey: process.env.PHOENIX_API_KEY,
        }),
        new MastraStorageExporter(),
        new MastraPlatformExporter(),
      ],
    },
  },
})
```

### 在無伺服器環境中送出待匯出的資料 {/* #flushing-in-serverless-environments */}

在無伺服器環境中，請在執行環境暫停或結束前，讓可觀測性匯出器送出尚待匯出的資料：

```ts
await mastra.observability.flush()
```

在無伺服器環境中，請以外部儲存代替本機檔案儲存。如何選擇儲存及設定路由，請見[儲存](#storage)。

### 使用多組設定 {/* #multi-config-setup */}

如果不同環境或請求類型需要不同的匯出器或取樣方式，可準備多組設定，並在運行時以 `configSelector` 選擇要採用的一組。

```ts title="src/mastra/index.ts"
import { Mastra } from '@mastra/core'
import { Observability, MastraStorageExporter } from '@mastra/observability'
import { LangfuseExporter } from '@mastra/langfuse'

const storageExporter = new MastraStorageExporter()
const langfuseExporter = new LangfuseExporter()

export const mastra = new Mastra({
  observability: new Observability({
    configs: {
      development: {
        serviceName: 'my-service-dev',
        exporters: [storageExporter],
      },
      production: {
        serviceName: 'my-service-prod',
        exporters: [storageExporter, langfuseExporter],
      },
    },
    configSelector: () => process.env.NODE_ENV || 'development',
  }),
})
```

有關 Trace 取樣，請見[追蹤](/docs/observability/tracing/overview)。

## 儲存 {/* #storage */}

儲存後端決定哪些可觀測性訊號可持久儲存、有哪些查詢可用，以及可否匯總指標。請使用專用的可觀測性儲存，與應用程式的主要儲存分開。

### 支援的訊號 {/* #signal-support */}

儲存支援視乎訊號和工作負載。`MastraStorageExporter` 可將 Trace 持久儲存至 ClickHouse、PostgreSQL、MSSQL、MongoDB 及 LibSQL。指標需要支援分析的儲存後端：

- DuckDB：建議用於本機測試及開發。
- ClickHouse：適合可觀測性資料量較大的正式環境。
- `PostgresStoreVNext`：啟用可觀測性領域後便支援指標。查詢時須指定時間範圍，以免掃描整個分區。
- Mastra Platform：使用 `MastraPlatformExporter` 接駁託管的可觀測性服務，毋須自行管理後端。

完整的 Provider 清單及支援的追蹤策略見 [Mastra Storage 匯出器](/docs/observability/integrations/exporters/mastra-storage#storage-provider-support)。如主要儲存不支援可觀測性，或工作負載需要獨立調整規模，請使用組合式儲存，將 `observability` 領域的資料送往獨立後端。

### 本機開發 {/* #local-development */}

本機開發可使用以下設定：

- 以 `LibSQLStore` 作為應用程式的主要儲存。
- 以 `DuckDBStore` 儲存 `observability` 領域的資料。
- 使用 `MastraStorageExporter`，以便從本機 Studio 存取資料。

### 正式環境部署 {/* #production-deployment */}

可觀測性流量通常比應用程式的其他流量更偏重寫入。正式環境可按以下方式設定：

- 如自行儲存可觀測性資料，可在 `observability` 領域使用 `MastraStorageExporter` 配合 ClickHouse。
- 使用 `MastraPlatformExporter` 接駁 Mastra Platform 的託管可觀測性服務，毋須自行管理後端。
- 如可觀測性資料須採用有別於應用程式主要資料的後端或擴展策略，請使用組合式儲存。

後端兼容性及匯出器的分批處理方式，請見 [Mastra Storage 匯出器](/docs/observability/integrations/exporters/mastra-storage)。
