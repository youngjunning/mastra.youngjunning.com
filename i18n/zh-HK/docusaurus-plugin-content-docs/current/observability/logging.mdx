# 日誌

Mastra 的日誌以結構化格式記錄函式執行情況、輸入資料和輸出回應。

部署到 Mastra Platform 後，可在儀表板查閱日誌。若使用自託管或自訂環境，則可按傳輸設定將日誌寫入檔案或送往外部服務。

<Inject>
  **供 AI Agent 使用：**執行 `npx mastra api log list '{"level":"error","page":0,"perPage":50}'` 可直接查閱近期的錯誤日誌，毋須開啟 Studio 或編寫臨時指令碼。此指令須連接正在運行並已設定可觀測性日誌的 Mastra 伺服器。可用 `npx mastra dev` 啟動本機伺服器，或用 `--url` 傳入可連接伺服器的基礎 URL。設定其他篩選條件前，請先執行 `npx mastra api log list --schema`。使用 `npx skills add mastra-ai/skills --skill mastra` 安裝 Mastra 的 Skill，可取得 API CLI 指令查找、目標選擇、結構定義、身份驗證及錯誤處理的完整指引。
</Inject>

## 透過 `PinoLogger` 設定日誌 {/* #configuring-logs-with-pinologger */}

透過 CLI [初始化 Mastra 專案](/docs)時，專案預設附有 `PinoLogger`。

```typescript title="src/mastra/index.ts"
import { Mastra } from '@mastra/core/mastra'
import { PinoLogger } from '@mastra/loggers'

export const mastra = new Mastra({
  logger: new PinoLogger({
    name: 'Mastra',
    level: 'info',
  }),
})
```

可用設定選項見 [PinoLogger](/reference/logging/pino-logger)。

## 將日誌寫入可觀測性儲存 {/* #logging-to-observability-storage */}

設定[可觀測性](/docs/observability/overview)後，日誌記錄呼叫會自動轉送至可觀測性儲存。應用程式和 Mastra 內部元件的 `debug`、`info`、`warn`、`error` 及 `trackException` 呼叫均會與 Trace 一併儲存。低於 `logging.level` 所設最低級別的日誌會被篩走。

毋須修改程式碼。支援轉接器的日誌記錄器（`PinoLogger` 及 `ConsoleLogger`）會把每筆記錄寫到各自的目的地，並以同一筆記錄產生匯出的日誌。Mastra 會封裝不支援轉接器的自訂日誌記錄器，讓日誌同時寫入原有記錄器及可觀測性系統。

### 與 Trace 關聯的日誌輸出 {/* #trace-correlated-log-output */}

在受追蹤的操作中記錄日誌時，包括 Agent 運行、Workflow 步驟或 Tool 呼叫，Mastra 會把 `trace_id` 和 `span_id` 加入日誌記錄器的原生輸出。兩個欄位採用 W3C Trace Context 格式，對應 Studio 顯示的 Trace，讓你可直接從標準輸出的一行日誌找到相關的 Trace。

如需在標準輸出取得機器可解析的 JSON，請在 `PinoLogger` 設定 `prettyPrint: false`。預設已啟用易讀格式，輸出為文字：

```typescript title="src/mastra/index.ts"
import { Mastra } from '@mastra/core/mastra'
import { PinoLogger } from '@mastra/loggers'

export const mastra = new Mastra({
  logger: new PinoLogger({ name: 'Mastra', level: 'info', prettyPrint: false }),
})
```

輸出的記錄如下：

```json
{
  "level": 30,
  "time": 1755522000000,
  "name": "Mastra",
  "trace_id": "0af7651916cd43dd8448eb211c80319c",
  "span_id": "b7ad6b7169203331",
  "msg": "tool executed"
}
```

操作如沒有受到追蹤，輸出便會省略這些欄位。`ConsoleLogger` 會將同樣的欄位放入物件，作為額外參數附加至主控台輸出。`PinoLogger` 則會把這些欄位送到所有目的地，包括標準輸出、檔案及自訂傳輸。如果自行提供 pino `mixin`，其欄位會保留，但如有衝突，會優先採用 `trace_id` 和 `span_id`。

可在 `loggerOptions` 個別控制 Trace 關聯及日誌匯出：

```typescript title="src/mastra/index.ts"
import { Mastra } from '@mastra/core/mastra'
import { PinoLogger } from '@mastra/loggers'

export const mastra = new Mastra({
  logger: new PinoLogger({ name: 'Mastra', level: 'info' }),
  loggerOptions: {
    correlation: true, // inject trace_id/span_id into native log output (default: true)
    export: false, // keep trace-correlated output without storing logs in observability (default: true)
  },
})
```

### 自訂日誌記錄器 {/* #custom-loggers */}

自訂的 `IMastraLogger` 實作仍然可用。Mastra 會透過已棄用的雙寫後備機制，將日誌呼叫轉送到可觀測性系統，日誌記錄器的原生輸出則不會加入 `trace_id` 或 `span_id`。如要在輸出中關聯 Trace，請實作 `@mastra/core/logger` 提供的 `__attachObservability()` 轉接器鉤子：

```typescript
import { MastraLogger, buildLogRecordData } from '@mastra/core/logger'
import type { LoggerAdapterContext } from '@mastra/core/logger'

class MyLogger extends MastraLogger {
  #adapterContext?: LoggerAdapterContext

  __attachObservability(ctx: LoggerAdapterContext): void {
    this.#adapterContext = ctx
  }

  #log(level: 'debug' | 'info' | 'warn' | 'error', message: string, args: unknown[]): void {
    const ctx = this.#adapterContext
    // Inject trace fields into your native record when correlation is enabled
    const traceFields = ctx?.options.correlation ? ctx.resolveTraceFields() : undefined
    console[level === 'debug' ? 'info' : level](
      message,
      ...args,
      ...(traceFields ? [traceFields] : []),
    )
    // Export the same record to observability when export is enabled
    if (ctx?.options.export) {
      ctx.getLogSink()?.[level](message, buildLogRecordData(args))
    }
  }

  debug(message: string, ...args: unknown[]): void {
    this.#log('debug', message, args)
  }

  info(message: string, ...args: unknown[]): void {
    this.#log('info', message, args)
  }

  warn(message: string, ...args: unknown[]): void {
    this.#log('warn', message, args)
  }

  error(message: string, ...args: unknown[]): void {
    this.#log('error', message, args)
  }
}
```

### 設定可觀測性日誌級別 {/* #configuring-observability-log-level */}

可觀測性儲存接收的日誌級別可獨立於主控台日誌記錄器設定。在可觀測性實例的設定中加入 `logging` 選項：

```typescript {12-15} title="src/mastra/index.ts"
import { Mastra } from '@mastra/core/mastra'
import { PinoLogger } from '@mastra/loggers'
import { Observability, MastraStorageExporter } from '@mastra/observability'

export const mastra = new Mastra({
  logger: new PinoLogger({ name: 'Mastra', level: 'debug' }),
  observability: new Observability({
    configs: {
      default: {
        serviceName: 'my-app',
        exporters: [new MastraStorageExporter()],
        logging: {
          enabled: true, // set to false to disable log forwarding
          level: 'info', // minimum level: 'debug' | 'info' | 'warn' | 'error' | 'fatal'
        },
      },
    },
  }),
})
```

在此示例中，主控台會輸出 `debug` 或以上級別的日誌，而可觀測性儲存只會寫入 `info` 或以上級別的日誌。開發時仍可在主控台查閱詳細資料，儲存空間則可保持精簡。

| 選項 | 類型 | 預設值 | 說明 |
| - | - | - | - |
| `enabled` | `boolean` | `true` | 設為 `false` 即停止向可觀測性儲存轉送所有日誌。 |
| `level` | `LogLevel` | `'warn'` | 最低嚴重程度。低於此級別的日誌會被捨棄。 |

### 查詢日誌 {/* #querying-logs */}

寫入可觀測性儲存的日誌，可透過 Mastra 客戶端 SDK 查詢：

```typescript
import { MastraClient } from '@mastra/client-js'

const client = new MastraClient()

const logs = await client.listLogsVNext({
  filters: { level: 'error' },
  pagination: { page: 1, perPage: 50 },
  orderBy: { field: 'timestamp', direction: 'desc' },
})
```

若使用 DuckDB 或 ClickHouse 等持久儲存後端，重啟後仍可查閱日誌，以分析過往記錄。

## 自訂日誌 {/* #customizing-logs */}

在 Workflow 步驟及 Tool 內，均可透過 `mastra.getLogger()` 取得日誌記錄器實例。記錄器支援標準嚴重程度級別 `debug`、`info`、`warn` 及 `error`。

### 在 Workflow 步驟內記錄日誌 {/* #logging-from-workflow-steps */}

在 Workflow 步驟的 `execute` 函式內，可透過 `mastra` 參數取得日誌記錄器，記下與該步驟執行有關的訊息。

```typescript {6-7} title="src/mastra/workflows/test-workflow.ts" oxfmt:false
import { createWorkflow, createStep } from "@mastra/core/workflows";
import { z } from "zod";

const step1 = createStep({
  execute: async ({ mastra }) => {
    const logger = mastra.getLogger();
    logger.info("workflow info log");

    return {
      output: ""
    };
  }
});

export const testWorkflow = createWorkflow({...})
  .then(step1)
  .commit();
```

### 在 Tool 內記錄日誌 {/* #logging-from-tools */}

Tool 同樣可透過 `mastra` 參數存取日誌記錄器，記下該 Tool 在執行期間的活動。

```typescript {6-7} title="src/mastra/tools/test-tool.ts"
import { createTool } from '@mastra/core/tools'
import { z } from 'zod'

export const testTool = createTool({
  execute: async (inputData, context) => {
    const logger = context?.mastra.getLogger()
    logger?.info('tool info log')

    return {
      output: '',
    }
  },
})
```

### 為日誌附加資料 {/* #logging-with-additional-data */}

日誌記錄方法可透過選用的第二個參數接收額外資料。傳入結構化物件後，便可在可觀測性儲存中篩選日誌。

```typescript {9} title="src/mastra/workflows/test-workflow.ts" oxfmt:false
import { createWorkflow, createStep } from "@mastra/core/workflows";
import { z } from "zod";

const step1 = createStep({
  execute: async ({ mastra }) => {
    const testAgent = mastra.getAgent("testAgent");
    const logger = mastra.getLogger();

    logger.info("workflow info log", { agent: testAgent });

    return {
      output: ""
    };
  }
});

export const testWorkflow = createWorkflow({...})
  .then(step1)
  .commit();
```
