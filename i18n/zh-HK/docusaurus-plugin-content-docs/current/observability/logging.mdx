# 記錄

Mastra 的日誌系統以結構化格式擷取函數執行、輸入資料和輸出響應。

部署到 Mastra 平台時，日誌會顯示在儀表板中。在自架或自訂環境中，日誌可以根據配置的傳輸定向到檔案或外部服務。

<Inject>
  **對於人工智慧Agent：**&#x8DD1;步`npx mastra api log list '{"level":"error","page":0,"perPage":50}'` to inspect recent error logs directly instead of opening Studio or writing a temporary script. The command requires a running Mastra server with observability logging configured; start the local server with `npx mastra dev`，或傳遞可存取伺服器的基本 URL`--url`。跑步`npx mastra api log list --schema`在建造不同的過濾器之前。安裝 Mastra 的技能`npx skills add mastra-ai/skills --skill mastra`取得完整的 API CLI 發現、定位、架構、驗證和錯誤處理指南。
</Inject>

## 配置日誌`PinoLogger` {/* #configuring-logs-with-pinologger */}

什麼時候[initializing a new Mastra project](/docs) using the CLI, `PinoLogger` is included by default.

```typescript title="src/mastra/index.ts"
import { Mastra } from '@mastra/core/mastra'
import { PinoLogger } from '@mastra/loggers'

export const mastra = new Mastra({
  logger: new PinoLogger({
    name: 'Mastra',
    level: 'info',
  }),
})
```

訪問[PinoLogger](/reference/logging/pino-logger) for all available configuration options.

## 記錄到可觀察性存儲 {/* #logging-to-observability-storage */}

什麼時候[observability](/docs/observability/overview) is configured, logger calls are automatically forwarded to your observability storage. Every `debug`, `info`, `warn`, `error`, and `trackException` call from your application and from Mastra's internal components is stored alongside your traces, subject to `logging.level`, which filters out anything below the configured minimum level.

無需更改程式碼。带适配器支持的记录仪（`PinoLogger` and `ConsoleLogger`) write each record to their own destinations and derive the exported log from that same record. Custom loggers without adapter support are wrapped so they write to both the original logger and the observability system simultaneously.

### 追蹤相關的日誌輸出 {/* #trace-correlated-log-output */}

當追蹤操作（Agent程式運行、Workflow步驟或Tool呼叫）內發生日誌呼叫時，Mastra 會注入`trace_id` and `span_id` into the logger's native output. The fields use W3C trace context format and match the trace shown in Studio, so you can correlate a stdout log line with its trace directly.

若要在標準輸出上取得機器可解析的 JSON，請配置`PinoLogger` with `prettyPrint: false`, pretty printing is enabled by default and produces human-readable text instead of JSON:

```typescript title="src/mastra/index.ts"
import { Mastra } from '@mastra/core/mastra'
import { PinoLogger } from '@mastra/loggers'

export const mastra = new Mastra({
  logger: new PinoLogger({ name: 'Mastra', level: 'info', prettyPrint: false }),
})
```

記錄如下圖所示：

```json
{
  "level": 30,
  "time": 1755522000000,
  "name": "Mastra",
  "trace_id": "0af7651916cd43dd8448eb211c80319c",
  "span_id": "b7ad6b7169203331",
  "msg": "tool executed"
}
```

在追蹤操作之外，欄位將被省略。`ConsoleLogger` appends the same fields as an object argument to its console output instead. With `PinoLogger`, the fields reach every destination: stdout, files, and custom transports. If you supply your own pino `mixin`, its fields are preserved, but `trace_id` and `span_id` win on conflicts.

相關和導出可以獨立控制`loggerOptions` configuration:

```typescript title="src/mastra/index.ts"
import { Mastra } from '@mastra/core/mastra'
import { PinoLogger } from '@mastra/loggers'

export const mastra = new Mastra({
  logger: new PinoLogger({ name: 'Mastra', level: 'info' }),
  loggerOptions: {
    correlation: true, // inject trace_id/span_id into native log output (default: true)
    export: false, // keep trace-correlated output without storing logs in observability (default: true)
  },
})
```

### 自訂記錄器 {/* #custom-loggers */}

風俗`IMastraLogger` implementations keep working: Mastra uses a deprecated dual-write fallback that forwards log calls to observability without adding `trace_id` or `span_id` to the logger's native output. To get trace-correlated output, implement the `__attachObservability()` adapter hook from `@mastra/core/logger`:

```typescript
import { MastraLogger, buildLogRecordData } from '@mastra/core/logger'
import type { LoggerAdapterContext } from '@mastra/core/logger'

class MyLogger extends MastraLogger {
  #adapterContext?: LoggerAdapterContext

  __attachObservability(ctx: LoggerAdapterContext): void {
    this.#adapterContext = ctx
  }

  #log(level: 'debug' | 'info' | 'warn' | 'error', message: string, args: unknown[]): void {
    const ctx = this.#adapterContext
    // Inject trace fields into your native record when correlation is enabled
    const traceFields = ctx?.options.correlation ? ctx.resolveTraceFields() : undefined
    console[level === 'debug' ? 'info' : level](
      message,
      ...args,
      ...(traceFields ? [traceFields] : []),
    )
    // Export the same record to observability when export is enabled
    if (ctx?.options.export) {
      ctx.getLogSink()?.[level](message, buildLogRecordData(args))
    }
  }

  debug(message: string, ...args: unknown[]): void {
    this.#log('debug', message, args)
  }

  info(message: string, ...args: unknown[]): void {
    this.#log('info', message, args)
  }

  warn(message: string, ...args: unknown[]): void {
    this.#log('warn', message, args)
  }

  error(message: string, ...args: unknown[]): void {
    this.#log('error', message, args)
  }
}
```

### 配置可觀察性日誌級別 {/* #configuring-observability-log-level */}

您可以獨立於控制台記錄器控制哪些日誌等級到達可觀察性儲存。添加一個`logging` option to your observability instance configuration:

```typescript {12-15} title="src/mastra/index.ts"
import { Mastra } from '@mastra/core/mastra'
import { PinoLogger } from '@mastra/loggers'
import { Observability, MastraStorageExporter } from '@mastra/observability'

export const mastra = new Mastra({
  logger: new PinoLogger({ name: 'Mastra', level: 'debug' }),
  observability: new Observability({
    configs: {
      default: {
        serviceName: 'my-app',
        exporters: [new MastraStorageExporter()],
        logging: {
          enabled: true, // set to false to disable log forwarding
          level: 'info', // minimum level: 'debug' | 'info' | 'warn' | 'error' | 'fatal'
        },
      },
    },
  }),
})
```

在此範例中，控制台記錄器輸出從下列位置開始的所有級別`debug`, but only `info` and above are written to observability storage. This keeps your storage clean while still having verbose console output during development.

|選項|類型 |預設 |描述 |
| - | - | - | - |
|`enabled` | `boolean` | `true` | Set to `false` to disable all log forwarding to observability storage. |
| `level` | `LogLevel` | `'warn'` | Minimum severity level. Logs below this level are discarded. |

### 查詢日誌 {/* #querying-logs */}

寫入可觀察性儲存的日誌可透過 Mastra 用戶端 SDK 進行查詢：

```typescript
import { MastraClient } from '@mastra/client-js'

const client = new MastraClient()

const logs = await client.listLogsVNext({
  filters: { level: 'error' },
  pagination: { page: 1, perPage: 50 },
  orderBy: { field: 'timestamp', direction: 'desc' },
})
```

當使用 DuckDB 或 ClickHouse 等持久性儲存後端時，日誌在重新啟動後仍可儲存並可用於歷史分析。

## 自訂日誌 {/* #customizing-logs */}

Mastra 透過以下方式提供對記錄器實例的訪問`mastra.getLogger()` method, available inside both workflow steps and tools. The logger supports standard severity levels: `debug`, `info`, `warn`, and `error`.

### 從Workflow步驟記錄 {/* #logging-from-workflow-steps */}

`mastra` parameter inside the `execute` function. You can log messages relevant to the step's execution.

```typescript {6-7} title="src/mastra/workflows/test-workflow.ts" oxfmt:false
import { createWorkflow, createStep } from "@mastra/core/workflows";
import { z } from "zod";

const step1 = createStep({
  execute: async ({ mastra }) => {
    const logger = mastra.getLogger();
    logger.info("workflow info log");

    return {
      output: ""
    };
  }
});

export const testWorkflow = createWorkflow({...})
  .then(step1)
  .commit();
```

### 從Tool記錄 {/* #logging-from-tools */}

同樣，Tool可以透過以下方式存取記錄器實例`mastra` parameter. Use this to log tool-specific activity during execution.

```typescript {6-7} title="src/mastra/tools/test-tool.ts"
import { createTool } from '@mastra/core/tools'
import { z } from 'zod'

export const testTool = createTool({
  execute: async (inputData, context) => {
    const logger = context?.mastra.getLogger()
    logger?.info('tool info log')

    return {
      output: '',
    }
  },
})
```

### 使用附加數據記錄 {/* #logging-with-additional-data */}

記錄器方法接受附加資料的可選第二個參數。傳遞結構化物件以使日誌在可觀察性儲存中可過濾。

```typescript {9} title="src/mastra/workflows/test-workflow.ts" oxfmt:false
import { createWorkflow, createStep } from "@mastra/core/workflows";
import { z } from "zod";

const step1 = createStep({
  execute: async ({ mastra }) => {
    const testAgent = mastra.getAgent("testAgent");
    const logger = mastra.getLogger();

    logger.info("workflow info log", { agent: testAgent });

    return {
      output: ""
    };
  }
});

export const testWorkflow = createWorkflow({...})
  .then(step1)
  .commit();
```
