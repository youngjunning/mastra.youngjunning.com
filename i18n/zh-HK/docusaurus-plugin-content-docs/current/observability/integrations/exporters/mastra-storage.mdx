# 儲存匯出器

`MastraStorageExporter` 會將 Trace 寫入你已設定的儲存後端，以便在 Studio 查閱，毋須使用外部服務。

:::note

`MastraStorageExporter` 之前稱為 `DefaultExporter`。為保持向後兼容，`@mastra/observability` 仍會匯出原本的 `DefaultExporter` 類別，但它已被棄用。新程式碼應使用 `MastraStorageExporter`。

:::

:::warning[正式環境的可觀測性]
正式環境的可觀測性資料可能很快令通用資料庫不勝負荷。高流量應用程式應透過[複合儲存](/reference/storage/composite)，將可觀測性儲存範疇導向 [ClickHouse](/integrations/databases/clickhouse)。詳見[正式環境建議](#production-recommendations)。
:::

## 設定 {/* #configuration */}

### 先決條件 {/* #prerequisites */}

1. **儲存後端**：設定儲存 Provider，例如 libSQL 或 PostgreSQL。
1. **Studio**：安裝 Studio，以便在本機查閱 Trace。

### 基本設定 {/* #basic-setup */}

```typescript title="src/mastra/index.ts"
import { Mastra } from '@mastra/core'
import { Observability, MastraStorageExporter } from '@mastra/observability'
import { LibSQLStore } from '@mastra/libsql'

export const mastra = new Mastra({
  storage: new LibSQLStore({
    id: 'mastra-storage',
    url: 'file:./mastra.db', // Required for trace persistence
  }),
  observability: new Observability({
    configs: {
      local: {
        serviceName: 'my-service',
        exporters: [new MastraStorageExporter()],
      },
    },
  }),
})
```

### 建議設定 {/* #recommended-configuration */}

將 MastraStorageExporter 加入可觀測性設定：

```typescript
import { Mastra } from '@mastra/core'
import {
  Observability,
  MastraStorageExporter,
  MastraPlatformExporter,
  SensitiveDataFilter,
} from '@mastra/observability'
import { LibSQLStore } from '@mastra/libsql'

export const mastra = new Mastra({
  storage: new LibSQLStore({
    id: 'mastra-storage',
    url: 'file:./mastra.db',
  }),
  observability: new Observability({
    configs: {
      default: {
        serviceName: 'mastra',
        exporters: [
          new MastraStorageExporter(), // Persists observability events to Mastra Storage
          new MastraPlatformExporter(), // Sends observability events to Mastra platform (requires MASTRA_PLATFORM_ACCESS_TOKEN)
        ],
        spanOutputProcessors: [new SensitiveDataFilter()],
      },
    },
  }),
})
```

## 同時匯出至儲存後端及 Platform {/* #export-to-storage-and-platform */}

在 Mastra Platform，`MASTRA_DEPLOYMENT_ID` 不為空時，預設會停用 `MastraStorageExporter` 和已棄用的 `DefaultExporter`，其他匯出器維持啟用。下述選項只適用於 `MastraStorageExporter`。即使把開關設為 `true`，Platform 上的 `DefaultExporter` 仍會停用。要使用此選項，請遷移至 `MastraStorageExporter`。

:::warning 即使開啟選項，仍會阻止寫入本機儲存

`retainStorageExporterOnPlatform: true` **不會**容許 Platform 將可觀測性資料寫入記憶體、本機 libSQL 或 DuckDB。如果可觀測性範疇回報資料會持久儲存於本機，內置儲存匯出器仍會停用，不會將 Trace、日誌、指標、評分或意見回饋寫入該資料庫。其他匯出器則繼續接收事件。

:::

更新配接器並設定 `retainStorageExporterOnPlatform: true` 後，Platform 的行為如下：

| 可觀測性資料庫 | 在 Platform 上匯出到儲存後端 |
| - | - |
| PostgreSQL | 容許 |
| 遠端 libSQL/Turso（`libsql://` 或 `https://`） | 容許 |
| 本機 libSQL（`file:` 或 `:memory:`） | 阻止 |
| 設有遠端同步 URL 的 libSQL 嵌入式複本 | 阻止：仍然會在本機寫入 |
| DuckDB，包括記憶體資料庫 | 阻止 |
| `InMemoryStore`，包括沒有設定儲存時的後備方案 | 阻止 |

如要在使用 Platform 可觀測性功能的同時繼續寫入自己的遠端資料庫，請在可觀測性設定將 [`retainStorageExporterOnPlatform`](/reference/observability/tracing/configuration#observabilityinstanceconfig) 設為 `true`：

```typescript
import { Observability, MastraStorageExporter, MastraPlatformExporter } from '@mastra/observability'

const observability = new Observability({
  configs: {
    production: {
      serviceName: 'my-service',
      retainStorageExporterOnPlatform: true,
      exporters: [new MastraStorageExporter(), new MastraPlatformExporter()],
    },
  },
})
```

將這個 `observability` 實例連同已設定的 `storage` Provider 傳給 `new Mastra()`。選項只影響這組設定，包括日後註冊到同一設定的匯出器。它不會自動設定資料庫或加入匯出器。其他設定仍然採用預設的停用行為，除非亦開啟選項。

限制只適用於**可觀測性範疇**，而該範疇可以選用有別於應用程式預設儲存的 Provider。其他儲存範疇不會因此停用。Platform 以外的本機可觀測性儲存可繼續使用。

要啟用此項限制，請在升級 `@mastra/observability` 時，一併升級 `@mastra/core` 及所用的 `@mastra/libsql` 或 `@mastra/duckdb` 配接器。未提供 `persistenceLocation` 能力的舊版或自訂配接器會沿用原有的選擇啟用行為，不會接受本機持久儲存檢查。

匯出器受阻時會在初始化期間記錄警告。即使日誌設定隱藏了警告，限制仍然有效。如雙重匯出沒有寫入你的資料庫，請對照上表核對可觀測性 Provider，並設定遠端資料庫。重試或增加批次間隔，均不能啟用已被阻止的匯出器。

## Studio {/* #studio */}

透過 Studio 查閱 Trace：

1. 啟動 Studio。
1. 前往 Observability。
1. 篩選及搜尋本機 Trace。
1. 查看 Span 的詳細資料。

## 追蹤策略 {/* #tracing-strategies */}

MastraStorageExporter 會按儲存 Provider 自動選取最合適的追蹤策略。有需要時亦可自行指定。

### 可選策略 {/* #available-strategies */}

| 策略 | 說明 | 適用情況 |
| - | - | - |
| **realtime** | 即時處理每個事件 | 開發、除錯、低流量 |
| **batch-with-updates** | 暫存事件並分批寫入，支援完整生命週期 | 資料量較少的正式環境 |
| **insert-only** | 只處理已結束的 Span，略過更新 | 資料量較大的正式環境 |
| **event-sourced** | Span 開始和結束時各寫一列，讀取時合併 | 資料量較大的正式環境、進行中的 Trace |

### 設定策略 {/* #strategy-configuration */}

```typescript
new MastraStorageExporter({
  strategy: 'auto', // Default - let storage provider decide
  // or explicitly set:
  // strategy: 'realtime' | 'batch-with-updates' | 'insert-only' | 'event-sourced'

  // Batching configuration (applies to both batch-with-updates and insert-only)
  maxBatchSize: 1000, // Max spans per batch
  maxBatchWaitMs: 5000, // Max wait before flushing
  maxBufferSize: 10000, // Max spans to buffer
})
```

## 儲存 Provider 支援情況 {/* #storage-provider-support */}

不同儲存 Provider 支援的追蹤策略各異。部分可應付正式環境的可觀測性工作量，其餘主要供本機開發使用。

將策略設為 `'auto'` 時，`MastraStorageExporter` 會自動按儲存 Provider 選擇最合適的策略。如指定了不受該 Provider 支援的策略，匯出器會記錄警告，並改用該 Provider 的首選策略。

### 支援可觀測性的 Provider {/* #providers-with-observability-support */}

| 儲存 Provider | 首選策略 | 支援的策略 | 建議用途 |
| - | - | - | - |
| **[ClickHouse](/integrations/databases/clickhouse)** | insert-only | insert-only | 正式環境（資料量大） |
| **[PostgresStore](/integrations/databases/postgresql)** | batch-with-updates | batch-with-updates, insert-only | 正式環境（資料量少） |
| **[PostgresStoreVNext](/integrations/databases/postgresql)** | event-sourced | event-sourced | 正式環境（資料量大） |
| **[MSSQL](/integrations/databases/mssql)** | batch-with-updates | batch-with-updates, insert-only | 正式環境（資料量少） |
| **[MongoDB](/integrations/databases/mongodb)** | batch-with-updates | batch-with-updates, insert-only | 正式環境（資料量少） |
| **[OracleDB](/integrations/databases/oracledb)** | batch-with-updates | batch-with-updates, insert-only | 正式環境（資料量少） |
| **[libSQL](/integrations/databases/libsql)** | batch-with-updates | batch-with-updates, insert-only | 預設儲存，適合開發 |

:::note

在 `insert-only` 策略下，只有已結束的 Span 才會持久儲存，Span 的開始和更新事件都會略過。因此，Trace 要等根 Span 結束後才會在 Studio 顯示，以 `status: 'running'` 篩選 Trace 亦不會有結果。`PostgresStoreVNext` 則採用 `event-sourced` 追蹤策略，在維持只追加寫入之餘，仍可查看進行中的 Trace。

:::

### 不支援可觀測性的 Provider {/* #providers-without-observability-support */}

以下儲存 Provider **不支援**可觀測性範疇。如使用其中一個 Provider 而又需要可觀測性功能，請透過[複合儲存](/reference/storage/composite)將可觀測性資料轉送到支援的 Provider：

- [Convex](/integrations/databases/convex)
- [DynamoDB](/integrations/databases/dynamodb)
- [Cloudflare D1](/integrations/databases/cloudflare-d1)
- [Cloudflare Durable Objects](/integrations/databases/cloudflare-kv)
- [Upstash](/integrations/databases/upstash)
- [LanceDB](/integrations/databases/lancedb)

### 策略的優點 {/* #strategy-benefits */}

- **realtime**：即時查看資料，最適合除錯。
- **batch-with-updates**：吞吐量提升 10 至 100 倍，支援 Span 的完整生命週期。
- **insert-only**：資料庫操作再減少 70%，適合分析用途。
- **event-sourced**：與 insert-only 一樣只追加寫入，運行期間仍可在 Studio 查看進行中的 Trace。

## 正式環境建議 {/* #production-recommendations */}

正式環境中的可觀測性資料增長很快。一次 Agent 互動可以產生數百個 Span，高流量應用程式每日可以產生數千條 Trace。大部分通用資料庫沒有針對這類密集、只追加的寫入作最佳化。

### 建議在高資料量的正式環境使用 ClickHouse {/* #recommended-clickhouse-for-high-volume-production */}

[ClickHouse](/integrations/databases/clickhouse) 是為大規模分析而設的欄式資料庫。正式環境的可觀測性資料建議使用 ClickHouse，原因如下：

- **寫入經最佳化**：每秒可處理數百萬次插入。
- **高效壓縮**：減低 Trace 資料的儲存成本。
- **快速查詢**：欄式儲存可迅速查找及彙總 Trace。
- **原生時間序列支援**：內置按時間保留資料和分區的功能。

### 使用複合儲存 {/* #using-composite-storage */}

如使用不支援可觀測性的 Provider（例如 Convex 或 DynamoDB），或想改善效能，可透過[複合儲存](/reference/storage/composite#specialized-storage-for-observability)將可觀測性資料送到 ClickHouse，其餘資料則保留在主要資料庫。

## 批次處理方式 {/* #batching-behavior */}

### 寫入緩衝資料的條件 {/* #flush-triggers */}

兩種批次策略（`batch-with-updates` 及 `insert-only`）遇到下列任何情況，都會把緩衝的 Trace 寫入儲存：

1. **達到批次大小**：緩衝區的 Span 數量達到 `maxBatchSize`。
1. **達到等候時間**：自首個事件起已過 `maxBatchWaitMs`。
1. **緊急寫入**：緩衝區接近 `maxBufferSize` 上限。
1. **關閉**：強制寫入全部待處理事件。

### 錯誤處理 {/* #error-handling */}

MastraStorageExporter 提供適合正式環境的錯誤處理：

- **重試機制**：採用指數退避（500 毫秒、1 秒、2 秒、4 秒）。
- **短暫故障**：按退避策略自動重試。
- **持續故障**：嘗試 4 次均失敗後捨棄該批資料。
- **緩衝區溢出**：避免儲存服務中斷時出現記憶體問題。

## 被捨棄的可觀測性事件 {/* #dropped-observability-events */}

`DefaultExporter` 無法持久儲存可觀測性資料時，會發出結構化的捨棄事件。可透過 `onDroppedEvent` 註冊匯出器或橋接元件，將捨棄事件轉送至警示或監察系統。

事件會因以下原因被捨棄：

- `unsupported-storage`：儲存 Provider 未實作該類型的訊號。
- `retry-exhausted`：匯出器對該批資料重試最多 `maxRetries` 次後將其捨棄。
- `span-not-updatable`：採用 `realtime` 或 `batch-with-updates` 時，Span 的更新或結束事件雖已送達儲存層，卻未有套用，因為該 Span 從未儲存或已經結束。已結束的 Span 不會再改動。

以下例子示範如何把捨棄事件的詳細資料轉送到監察端點：

```typescript title="src/mastra/observability.ts"
import { BaseExporter } from '@mastra/observability'
import type { ObservabilityDropEvent, TracingEvent } from '@mastra/core/observability'

class DropAlertExporter extends BaseExporter {
  name = 'drop-alerts'

  async onDroppedEvent(event: ObservabilityDropEvent) {
    await fetch('https://monitoring.example.com/observability-drops', {
      method: 'POST',
      headers: { 'content-type': 'application/json' },
      body: JSON.stringify({
        count: event.count,
        signal: event.signal,
        reason: event.reason,
        exporterName: event.exporterName,
      }),
    })
  }

  protected async _exportTracingEvent(_event: TracingEvent) {}
}
```

## 設定例子 {/* #configuration-examples */}

```typescript
// Zero config - recommended for most users
new MastraStorageExporter()

// Development override
new MastraStorageExporter({
  strategy: 'realtime', // Immediate visibility for debugging
})

// High-throughput production
new MastraStorageExporter({
  maxBatchSize: 2000, // Larger batches
  maxBatchWaitMs: 10000, // Wait longer to fill batches
  maxBufferSize: 50000, // Handle longer outages
})

// Low-latency production
new MastraStorageExporter({
  maxBatchSize: 100, // Smaller batches
  maxBatchWaitMs: 1000, // Flush quickly
})
```
