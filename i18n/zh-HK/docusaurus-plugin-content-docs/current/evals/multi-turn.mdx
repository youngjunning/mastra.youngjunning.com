# 多輪對話評估

多輪評估測試 Agent 在對話中的行為。請以 `inputs` 陣列提供多筆輸入，取代單一 `input`。系統會在同一對話串依次將各項輸入送給 Agent，評分器會收到各輪累積的輸出。

## 多輪評估的適用情況 {/* #when-to-use-multi-turn-evals */}

- Agent 使用記憶，並須取回早前各輪的上下文
- Agent 須回答承接較早回應的追問
- 需要核對對話中呼叫工具的次序
- Agent 執行包含多個步驟的 Workflow（搜尋、確認、執行）

## 快速入門 {/* #quickstart */}

```typescript title="src/evals/conversation-eval.ts"
import { runEvals } from '@mastra/core/evals'
import { checks } from '@mastra/evals/checks'
import { weatherAgent } from '../agents'

const result = await runEvals({
  data: [
    {
      inputs: [
        'What is the weather in Brooklyn?',
        'What about tomorrow?',
        'Compare the two forecasts.',
      ],
    },
  ],
  target: weatherAgent,
  scorers: [checks.calledTool('get_weather', { times: 2 }), checks.includes('Brooklyn')],
})
```

每輪均以同一對話串 ID 呼叫 `agent.generate()`。Agent 可讀取完整對話紀錄，評分器則會收到所有輪次累積的輸出訊息。

:::warning[內置 LLM 評分器只為一輪評分]

內置 LLM 評分器（包括評分準則、答案相關性、忠實度，以及[評分器兼容性](#scorer-compatibility)所列的其他評分器）只讀取一則助理訊息，所以使用 `inputs` 時只會評估最後一輪回應。要就整段對話作語義評分，可使用 [`createMultiTurnJudgeScorer()`](/reference/evals/multi-turn-judge)，以同一準則一併評估助理的各輪回應，或透過逐輪設定的 [`turns[].scorers`](#per-turn-assertions-with-turns) 評估各輪輸出。

:::

## 取回先前輪次的內容須配置記憶 {/* #memory-is-required-for-cross-turn-recall */}

Agent 須**配置記憶儲存**才能取回之前各輪的內容。共用的對話串 ID 讓每輪可存取較早的輪次，但只有 Agent 配置了記憶，對話串才會保存紀錄。未配置記憶時，輸入仍會依次處理，輸出亦會累積供評分，但每筆輸入獨立執行，Agent 無法取回先前內容。對沒有記憶的 Agent 使用 `inputs` 時，`runEvals` 會記錄警告。

`runEvals` 會產生共用的 `threadId` 並注入 `resourceId`，以識別對話。Mastra 記憶按資源和對話串劃分訊息，因此兩個值缺一不可。預設會從新建的對話串推導資源，隔離各段對話。若要固定使用某個資源，例如沿用現有用戶的記憶，請傳入 `targetOptions.memory.resource`。對話串仍由 `runEvals` 管理，毋須自行提供：

```typescript
await runEvals({
  target: weatherAgent,
  data: [{ inputs: ['What is the weather in Brooklyn?', 'What about tomorrow?'] }],
  scorers: [checks.similarity('weather forecast')],
  targetOptions: { memory: { resource: 'user-42' } },
})
```

有關配置記憶儲存的方法，請參閱[記憶](/docs/memory/overview)。

## 運作方式 {/* #how-it-works */}

數據項目包含 `inputs` 陣列時，`runEvals` 會：

1. 為對話建立新對話串（具備獨有的 `threadId`）和資源，並保留呼叫方提供的 `targetOptions.memory.resource`
1. 在該對話串透過 `agent.generate()` 依次傳送各項輸入
1. 累積各輪的全部輸出訊息
1. 將全部累積輸出交給評分器評估

評分器會收到整段對話的輸出，涵蓋所有輪次。

## 評分方式 {/* #scoring-semantics */}

為多輪數據項目編寫評分器時，請留意：

- **`run.output` 是各輪累積的輸出。** `checks.includes`、`checks.calledTool`、`checks.similarity` 等依輸出評分的評分器會評估整段對話。例如，`checks.calledTool('get_weather', { times: 2 })` 會合計所有輪次的呼叫次數。
- **`run.input` 只載有首輪輸入。** 比較輸入和輸出的評分器，包括忠實度、答案相關性及其他參照輸入的 LLM 評分器，只能讀取第一則用戶訊息。多輪評估宜採用按輸出檢查的評分器，或自行編寫直接讀取累積 `run.output` 的評分器。

### 評分器兼容性 {/* #scorer-compatibility */}

累積輸出只有在評分器悉數讀取時才有用：

| 評分器 | 使用 `inputs` 時會讀取的內容 |
| - | - |
| [Quick Checks](/docs/evals/quick-checks)（`checks.calledTool`、`checks.includes`、`checks.similarity`、`checks.noToolErrors` 等） | 整段對話。工具呼叫檢查會合計各輪的呼叫次數，文本檢查則會搜尋助理的全部文本。 |
| [多輪評判評分器](/reference/evals/multi-turn-judge) | 助理的所有輪次，一併按一項以淺白英文寫成的準則評分。 |
| 內置 LLM 評分器：評分準則、答案相關性、答案相似度、忠實度、幻覺、偏見、毒性、上下文精確率、上下文召回率、上下文相關性、噪聲敏感度、提示詞對齊、摘要 | 只讀取最後一則包含文本的助理訊息。參照輸入的評分器亦只會讀取首輪輸入。 |
| 執行軌跡評分器（`AgentScorerConfig.trajectory`） | 如有 Trace，會讀取最後一輪的 Span，否則讀取所有累積訊息中的工具呼叫。 |
| 自訂評分器 | 視乎評分器從 `run.output` 讀取哪些內容。 |

### 評估整段對話 {/* #grading-a-whole-conversation */}

要一併評估各輪，請使用 [`createMultiTurnJudgeScorer()`](/reference/evals/multi-turn-judge)。它會整理助理各輪的對話紀錄，再由評判模型按一項以淺白英文寫成的準則評估整段對話，給出 `1` 或 `0` 分：

```typescript title="src/evals/trip-planning-eval.ts"
import { runEvals } from '@mastra/core/evals'
import { createMultiTurnJudgeScorer } from '@mastra/evals/scorers/prebuilt'
import { weatherAgent } from '../agents'

const result = await runEvals({
  data: [
    {
      inputs: [
        "How's the weather in London?",
        'And Paris?',
        'Should I pack an umbrella for London?',
      ],
    },
  ],
  target: weatherAgent,
  scorers: [
    {
      scorer: createMultiTurnJudgeScorer({
        model: '__GATEWAY_ANTHROPIC_MODEL_HAIKU__',
        criterion:
          'The agent provided forecasts for London and Paris, and gave weather-appropriate packing advice.',
      }),
      threshold: 1,
    },
  ],
})
```

如果準則無法表達你想評估的內容，可自行編寫評分器，從 `run.output` 取得助理訊息。[`extractAgentResponseMessages()`](/reference/evals/scorer-utils#extractagentresponsemessages) 會依次回傳每則助理訊息的文本：

```typescript title="src/evals/conversation-judge.ts"
import { createScorer } from '@mastra/core/evals'
import { extractAgentResponseMessages } from '@mastra/evals/scorers/utils'
import { z } from 'zod'

export const conversationJudge = createScorer({
  id: 'conversation-judge',
  name: 'Conversation Judge',
  description: 'Grades every assistant turn in a conversation against one criterion',
  type: 'agent',
  judge: {
    model: '__GATEWAY_ANTHROPIC_MODEL_HAIKU__',
    instructions: 'You grade multi-turn assistant transcripts against a single criterion.',
  },
})
  .analyze({
    description: 'Judge the transcript as a whole',
    outputSchema: z.object({ satisfied: z.boolean(), reason: z.string() }),
    createPrompt: ({ run }) => {
      const transcript = extractAgentResponseMessages(run.output)
        .map((text, index) => `Turn ${index + 1}: ${text}`)
        .join('\n\n')

      return `Grade this conversation:\n\n${transcript}\n\nCriterion: the assistant keeps the forecast consistent across turns.`
    },
  })
  .generateScore(({ results }) => (results.analyzeStepResult?.satisfied ? 1 : 0))
  .generateReason(({ results }) => results.analyzeStepResult?.reason ?? '')
```

將它傳給 `runEvals`，用法與其他評分器相同。完整的 `createScorer()` 流程請參閱[自訂評分器](/docs/evals/custom-scorers)。

## 透過 `turns` 逐輪作斷言 {/* #per-turn-assertions-with-turns */}

使用 `inputs` 會就**累積**的輸出給出單一分數，可能掩蓋個別輪次的問題。例如，依輸出執行的 `checks.includes('Brooklyn')` 只要在 _任何_ 一輪找到 Brooklyn 即會通過，即使後續一輪出錯也一樣。

如須斷言**指定輪次**的行為正確，請用 `turns`。每輪是一個物件，包含各自的 `input`，也可設定 `gates` 或 `scorers`，只評估**當輪**的輸入及輸出：

```typescript title="src/evals/per-turn-eval.ts"
import { runEvals } from '@mastra/core/evals'
import { checks } from '@mastra/evals/checks'
import { weatherAgent } from '../agents'

const result = await runEvals({
  data: [
    {
      turns: [
        {
          input: 'What is the weather in Brooklyn?',
          gates: [checks.calledTool('get_weather')],
        },
        {
          // The follow-up must call the tool again — it can't be satisfied
          // by the first turn's tool call.
          input: 'What about tomorrow?',
          gates: [checks.calledTool('get_weather')],
          scorers: [{ scorer: checks.similarity('tomorrow forecast'), threshold: 0.5 }],
        },
      ],
    },
  ],
  target: weatherAgent,
})

result.verdict // 'passed' | 'scored' | 'failed'
result.turnResults // per-turn gate/threshold/scorer outcomes
```

逐輪評估的規則如下：

- 每輪的門檻檢查或評分器**只會收到當輪**的 `run.input` 和 `run.output`，不會讀取累積的對話。其他輪次的輸出無法滿足檢查，而 `run.input` 載有受評估輪次的輸入。
- 各輪結果會計入[判定](/docs/evals/gates-and-verdicts)。任何一輪未通過門檻檢查，判定即為 `failed`。若門檻檢查均通過，但有一輪未達分數門檻，則判定為 `scored`。
- `result.turnResults[i]` 回報各輪的 `gateResults`、`thresholdResults` 和 `scores`，可準確找出失敗的輪次。如有多段對話，會按輪次索引取平均值。
- 未設 `gates` 或 `scorers` 的輪次只推進對話。
- 頂層的 `scorers` 和 `gates` 仍會評估所有累積輸出，因此可以同時要求「這一輪必須呼叫工具」及「答案提到 Brooklyn」。
- Agent 如已配置儲存，各輪的評分器及門檻檢查結果會像頂層分數一樣持久保存，可在分數儲存系統查閱。每筆保存的逐輪分數均以輪次索引（`metadata.turnIndex`）為標籤，沿用對話的 `threadId`，並附有該輪 Trace Span 的連結。

整段對話只需一個分數時可用 `inputs`。如須核對個別輪次是否正確，請用 `turns`。同一數據項目內，`turns` 不可與 `input` 或 `inputs` 並用。

## 配合門檻檢查及分數門檻 {/* #combining-with-gates-and-thresholds */}

多輪數據項目支援[門檻檢查及判定](/docs/evals/gates-and-verdicts)。請使用按輸出評分的評分器，讓門檻檢查涵蓋整段對話：

```typescript title="src/evals/memory-eval.ts"
import { runEvals } from '@mastra/core/evals'
import { checks } from '@mastra/evals/checks'

const result = await runEvals({
  data: [
    {
      inputs: ['My favorite city is Brooklyn.', 'What is the weather in my favorite city?'],
    },
  ],
  target: weatherAgent,
  gates: [checks.calledTool('get_weather')],
  scorers: [{ scorer: checks.similarity('Brooklyn weather forecast'), threshold: 0.5 }],
})

result.verdict // 'passed' | 'scored' | 'failed'
```

## 混合使用單輪及多輪數據項目 {/* #mixing-single-turn-and-multi-turn */}

一次 `runEvals` 呼叫可同時包含單輪及多輪數據項目：

```typescript title="src/evals/mixed-eval.ts"
const result = await runEvals({
  data: [
    { input: 'What is the weather in Brooklyn?' },
    {
      inputs: ['My favorite city is Brooklyn.', 'What is the weather in my favorite city?'],
    },
  ],
  target: weatherAgent,
  scorers: [checks.includes('Brooklyn')],
})
```

單輪項目照常使用 `input`。多輪項目使用 `inputs`，毋須提供 `input`。

## 驗證參數 {/* #validation */}

如所提供的 `inputs` 是空陣列，`runEvals` 會拋出 `MastraError`：

```typescript
// Throws: 'inputs' must be a non-empty array
await runEvals({
  data: [{ inputs: [] }],
  target: myAgent,
  scorers: [myScorer],
})
```
