# Vitest 整合

透過 `@mastra/evals/vitest` 整合 [`runEvals`](/reference/evals/run-evals) 和 [Vitest](https://vitest.dev/)，便可像執行一般測試一樣執行評估。評估不達標時，鏈式斷言會令測試失敗，報告器則會在測試輸出列出分數表。

先安裝 `@mastra/evals` 和 `vitest`（版本 3、4 或 5）：

```bash
npm install @mastra/evals vitest
```

## 設定 Vitest {/* #configuring-vitest */}

在 `vitest.config.ts` 註冊報告器和配對器：

```typescript title="vitest.config.ts"
import { defineConfig } from 'vitest/config'
import { MastraEvalsReporter } from '@mastra/evals/vitest'

export default defineConfig({
  test: {
    reporters: ['default', new MastraEvalsReporter()],
    setupFiles: ['@mastra/evals/vitest/setup'],
  },
})
```

設定檔會為 `expect` 註冊自訂配對器。你亦可在自己的設定檔呼叫 `registerEvalMatchers()`，此函數由 `@mastra/evals/vitest` 提供。

## 用 `expectEvals` 斷言資料集結果 {/* #asserting-on-a-dataset-with-expectevals */}

`expectEvals` 會在一般的 `test()` 執行 `runEvals` 評估，並斷言最低通過率。它接受與 `runEvals` 相同的設定：作為 `target` 的 Agent 或 Workflow、`data` 資料項目，以及 `scorers`、`gates` 或門檻。每項關卡都會判定各資料項目是否通過，所以 `toPass(0.8)` 要求最少 80% 的項目通過所有關卡。評分器門檻仍以各項的平均分數判定，不論通過率多少，平均分都必須達標：

```typescript title="tests/weather-agent.eval.test.ts"
import { test } from 'vitest'
import { expectEvals } from '@mastra/evals/vitest'
import { checks } from '@mastra/evals/checks'
import { mastra } from '../src/mastra'

test('weather agent calls the tool and answers relevantly', { timeout: 60_000 }, async () => {
  await expectEvals({
    target: mastra.getAgent('weatherAgent'),
    data: [{ input: "What's the weather in London?" }],
    gates: [checks.calledTool('weatherTool'), checks.noToolErrors(), checks.includes('London')],
    scorers: [{ scorer: mastra.getScorer('answerRelevancyScorer'), threshold: 0.7 }],
  }).toPass(0.8)
})
```

`toPass()` 未傳入參數時，所有資料項目都要通過每項關卡。請等候斷言完成：它會傳回完整的 `RunEvalsResult` 以供進一步檢查，並將本次運行的分數附加到目前的測試，讓 `MastraEvalsReporter` 顯示。

使用 LLM 的評估耗時遠超 Vitest 預設的 5 秒時限。請為個別測試傳入 `timeout`，或在 Vitest 設定中指定 `testTimeout`。

## 用 `expectEval` 進行矩陣測試 {/* #matrix-testing-with-expecteval */}

`expectEval` 用於評估單個項目，`data` 接收一個項目而非陣列。配合 `test.for` 或 `test.each` 使用，每個項目各有一項測試及一筆報告紀錄，毋須按資料集匯總為單一結果：

```typescript title="tests/weather-agent.matrix.eval.test.ts"
import { test } from 'vitest'
import { expectEval } from '@mastra/evals/vitest'
import { checks } from '@mastra/evals/checks'
import { mastra } from '../src/mastra'

test.for([
  { input: "What's the weather in London?", groundTruth: 'London' },
  { input: "What's the weather in Tokyo?", groundTruth: 'Tokyo' },
  { input: "What's the weather in Sydney?", groundTruth: 'Sydney' },
])('weather agent: $input', { timeout: 60_000 }, async item => {
  await expectEval({
    target: mastra.getAgent('weatherAgent'),
    data: item,
    gates: [checks.calledTool('weatherTool'), checks.includes(item.groundTruth)],
  }).toPass()
})
```

每個項目獨立判定是否通過。單項出現回歸時，報告會顯示該項測試失敗，毋須從整體通過率下降推斷。

## 使用配對器斷言結果 {/* #asserting-on-results-with-matchers */}

如需更細緻地檢查結果，可直接在一般的 `test()` 呼叫 `runEvals`，再用自訂配對器檢查結果：

```typescript title="tests/weather-agent.matchers.eval.test.ts"
import { test, expect } from 'vitest'
import { runEvals } from '@mastra/core/evals'
import { checks } from '@mastra/evals/checks'
import { mastra } from '../src/mastra'

test('weather agent quality', { timeout: 60_000 }, async () => {
  const result = await runEvals({
    target: mastra.getAgent('weatherAgent'),
    data: [{ input: "What's the weather in London?" }],
    scorers: [mastra.getScorer('answerRelevancyScorer')],
    gates: [checks.noToolErrors()],
  })

  expect(result).toHaveVerdict('passed')
  expect(result).toPassGates()
  expect(result).toHaveScoreAbove('answer-relevancy-scorer', 0.7)
})
```

可用的配對器如下：

- `toHaveVerdict(verdict)`：斷言本次運行的判定結果（`"passed"`、`"scored"` 或 `"failed"`）。
- `toHaveScoreAbove(scorerName, min)` / `toHaveScoreBelow(scorerName, max)`：斷言評分器的平均分數。按類別設定的評分器採用以點分隔的路徑，例如 `"agent.my-scorer"` 或 `"steps.step-1.my-scorer"`。
- `toPassGates()`：確認所有關卡均已通過；未設定關卡則斷言失敗。
- `toPassThresholds()`：確認所有評分器均達到門檻；未設定門檻則斷言失敗。

## 評估 Workflow {/* #evaluating-a-workflow */}

Workflow 也可用作評估目標。用 `WorkflowScorerConfig` 物件設定 `scorers`，便可評分 Workflow 輸出、個別步驟或步驟執行軌跡，並在配對器中以點分隔的路徑引用巢狀分數：

```typescript title="tests/weather-workflow.eval.test.ts"
import { test, expect } from 'vitest'
import { runEvals } from '@mastra/core/evals'
import { mastra } from '../src/mastra'

test('weather workflow runs fetch-weather then plan-activities', { timeout: 60_000 }, async () => {
  const result = await runEvals({
    target: mastra.getWorkflow('weatherWorkflow'),
    data: [
      {
        input: { city: 'London' },
        expectedTrajectory: {
          steps: [
            { stepType: 'workflow_step', name: 'fetch-weather' },
            { stepType: 'workflow_step', name: 'plan-activities' },
          ],
        },
      },
      {
        input: { city: 'Tokyo' },
        expectedTrajectory: {
          steps: [
            { stepType: 'workflow_step', name: 'fetch-weather' },
            { stepType: 'workflow_step', name: 'plan-activities' },
          ],
        },
      },
    ],
    scorers: {
      trajectory: [mastra.getScorer('trajectoryAccuracyScorer')],
    },
  })

  expect(result).toHaveScoreAbove('trajectory.code-trajectory-accuracy-scorer', 0.9)
})
```

這個 Workflow 的 `plan-activities` 步驟會在運行時呼叫 `mastra.getAgent('weatherAgent')`，只有經 `mastra.getWorkflow()` 取得評估目標時才可這樣做。完整的 `WorkflowScorerConfig` 結構請參閱 [`runEvals` 參考文件](/reference/evals/run-evals#workflow-evaluation)。

## 閱讀報告器輸出 {/* #reading-the-reporter-output */}

運行完成後，`MastraEvalsReporter` 會為每項評估測試列出分數表：

```text
 Mastra Evals

✓ weather agent calls the tool and answers relevantly (1 item)
   check-called-tool (gate)                        1.0  ✓
   check-no-tool-errors (gate)                     1.0  ✓
   check-includes (gate)                           1.0  ✓
   answer-relevancy-scorer (threshold: min 0.7)    0.9  ✓

 Eval runs: 1 (1 passed)
```

每筆紀錄均列出運行的判定、關卡、門檻和各評分器的平均分。報告器會讀取 `expectEval` 和 `expectEvals` 附加到 `task.meta.mastraEval` 的元資料，因此支援並行測試檔案，以及任何填入該欄位的測試。

## 速率限制和並行運行 {/* #rate-limits-and-concurrency */}

Vitest 會並行執行測試檔案，`runEvals` 亦接受自己的 `concurrency` 選項，兩者疊加會令 LLM 請求量倍增。如觸及 Provider 的速率限制，請調低評估選項的 `concurrency`，或在 Vitest 設定中指定 `fileParallelism: false`。
