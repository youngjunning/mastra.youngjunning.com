# Evals

傳統軟件測試有明確的合格與不合格條件，AI 則可能對相同輸入給出不同輸出。**評分器**借助可量化的指標衡量 Agent 的質素。

評分器是自動化測試，以模型、規則及統計方法評估 Agent 的輸出。評分器回傳的**分數**通常介乎 0 至 1，量化輸出符合評估準則的程度。你可以依據分數客觀追蹤表現、比較不同做法，以及找出 AI 系統可改善的地方。你也可以用自己的提示詞和評分函數自訂評分器。

評分器可在雲端執行，即時取得結果，亦可接入 CI/CD 流程，持續測試和監察 Agent。

評分器衡量單次輸出。要持續改善 Agent，可一併使用[數據集](/docs/evals/datasets)和[實驗](/docs/evals/experiments)。數據集保存有版本記錄的測試個案，實驗則在數據集上執行 Agent 或 Workflow，可選擇為每項結果評分，並保留結果以供比較。[建立評估循環](/docs/guides/build-an-eval-loop)示範如何配合使用。

:::tip[📹 觀看短片]

觀看 [Mastra Evals 概覽](https://www.youtube.com/watch?v=12WN6u2DrBk)，了解評估入門概念和判斷 Agent 質素的方法。

:::

## 評分器類型 {/* #types-of-scorers */}

Mastra 提供多款評分器，各有用途。常見類型如下：

1. **文本評分器**：評估 Agent 回應的準確度、可靠性及理解上下文的能力
1. **分類評分器**：量度數據是否準確歸入預設類別
1. **提示詞工程評分器**：探討不同指令和輸入格式帶來的影響

## 安裝 {/* #installation */}

要使用 Mastra 的評分器，請安裝 `@mastra/evals` 套件。

```bash npm2yarn
npm install @mastra/evals@latest
```

## 即時評估 {/* #live-evaluations */}

**即時評估**可在 Agent 和 Workflow 運作時自動為 AI 輸出評分。評分器伴隨 AI 系統非同步執行，毋須手動或分批進行評估，即可持續監察質素。

### 為 Agent 加入評分器 {/* #adding-scorers-to-agents */}

你可以為 Agent 加入內置評分器，自動評估輸出。所有可用選項載於[內置評分器完整清單](/docs/evals/built-in-scorers)。

```typescript title="src/mastra/agents/evaluated-agent.ts"
import { Agent } from '@mastra/core/agent'
import { createAnswerRelevancyScorer, createToxicityScorer } from '@mastra/evals/scorers/prebuilt'

export const evaluatedAgent = new Agent({
  id: 'evaluated-agent',
  scorers: {
    relevancy: {
      scorer: createAnswerRelevancyScorer({ model: '__GATEWAY_OPENAI_MODEL_LUNA__' }),
      sampling: { type: 'ratio', rate: 0.5 },
    },
    safety: {
      scorer: createToxicityScorer({ model: '__GATEWAY_OPENAI_MODEL_LUNA__' }),
      sampling: { type: 'ratio', rate: 1 },
    },
  },
})
```

### 為 Workflow 步驟配置評分器 {/* #adding-scorers-to-workflow-steps */}

你亦可為個別 Workflow 步驟配置評分器，評估流程中特定環節的輸出。每個評分器都會收到對應步驟的輸入及輸出，因此可以逐步衡量質素，而非只為最終答案評分：

```typescript title="src/mastra/workflows/content-generation.ts"
import { createWorkflow, createStep } from '@mastra/core/workflows'
import { z } from 'zod'
import { customStepScorer } from '../scorers/custom-step-scorer'

const contentStep = createStep({
  id: 'content-step',
  inputSchema: z.object({ topic: z.string() }),
  outputSchema: z.object({ content: z.string() }),
  scorers: {
    customStepScorer: {
      scorer: customStepScorer(),
      sampling: {
        type: 'ratio',
        rate: 1, // Score every step execution
      },
    },
  },
  execute: async ({ inputData }) => {
    return { content: await generateContent(inputData.topic) }
  },
})

export const contentWorkflow = createWorkflow({
  id: 'content-workflow',
  inputSchema: z.object({ topic: z.string() }),
  outputSchema: z.object({ content: z.string() }),
})
  .then(contentStep)
  .commit()
```

有關步驟層級的 `scorers` API，請參閱 [Step 類別參考](/reference/workflows/step#scoring-step-output)。

### 即時評估如何運作 {/* #how-live-evaluations-work */}

**非同步執行**：即時評估在背景進行，不會阻礙 Agent 回應或 Workflow 執行。AI 系統在評估監察期間仍可正常回應。

**抽樣控制**：`sampling.rate` 參數（0 至 1）決定有多少比例的輸出會接受評分：

- `1.0`：為全部回應評分（100%）
- `0.5`：為一半回應評分（50%）
- `0.1`：為 10% 的回應評分
- `0.0`：停用評分

每條 Trace 是否入選由 Trace ID 決定，並非隨機抽樣，因此：

- 抽樣率相同的評分器會為同一批 Trace 評分，因此可用相同流量比較分數。
- 重新執行同一條 Trace 會得出相同的抽樣結果，因此可重現抽樣範圍。

未配置可觀測性時，執行並無 Trace，會改用執行 ID 決定是否抽樣。如果 [Trace 抽樣](../observability/tracing/overview)沒有抽中該 Trace，評分器會略過整次執行，因此未保存的 Trace 不會產生分數。

**篩選評分對象**：可選的 `filter` 參數在執行上下文上套用宣告式謂詞，限定哪些執行可接受評分。篩選早於抽樣，故 `sampling.rate` 只適用於符合條件的執行：

```typescript title="src/mastra/agents/evaluated-agent.ts"
import { Agent } from '@mastra/core/agent'

export const myAgent = new Agent({
  // ...
  scorers: {
    relevancy: {
      scorer: createAnswerRelevancyScorer({ model: '__GATEWAY_OPENAI_MODEL_LUNA__' }),
      filter: {
        op: 'eq',
        left: { path: 'requestContext.plan' },
        right: { literal: 'enterprise' },
      },
      sampling: { type: 'ratio', rate: 0.1 },
    },
  },
})
```

這項配置只會為企業計劃流量的 10% 評分。要以不同抽樣率為不同組別的流量評分，可用互補的篩選條件綁定同一評分器兩次。

謂詞可引用 `requestContext.*`、`entity.*`、`entityType`、`source`、`threadId`、`resourceId` 及 `projectId`。可做比較（`eq`、`ne`、`lt`、`lte`、`gt`、`gte`）、成員檢查（`in`、`notIn`）、存在檢查（`exists`、`notExists`）、真值判斷（`truthy`、`falsy`）和布林組合（`and`、`or`、`not`）。如篩選條件引用未知的根欄位，建立 Agent 時便會報錯，避免在執行時無聲略過評分。篩選條件採用純 JSON，因此不受持久化 Agent 狀態序列化影響。

評分資格篩選決定 _是否執行評分器_。要篩選 _評分器執行後可讀取哪些訊息_，請用 [`filterRun()`](/reference/evals/filter-run)。資格篩選無法讀取執行的輸入或輸出。如評分資格取決於執行期間的行為，例如有否呼叫指定工具，請在評分器步驟回傳 [`notScorable()`](/reference/evals/not-scorable)，其餘步驟會略過，分數亦不會保存。

**自動儲存**：所有評分結果都會自動存入已配置數據庫的 `mastra_scorers` 表，方便分析長期表現。

## 持久保存分數 {/* #score-persistence */}

要持久保存分數，Mastra 實例須配置 `storage`，而評分器亦須在該實例註冊。註冊後，Mastra 便可在寫入分數前，透過 [`getScorerById()`](/reference/core/getScorerById) 查找評分器的元數據（名稱、描述和類型）。

綁定到 Agent 或 Workflow 步驟的評分器會自動註冊。直接傳給 [`runEvals()`](/reference/evals/run-evals) 的評分器，包括 [Quick Checks](/docs/evals/quick-checks)，須透過 [`Mastra` 類別](/reference/core/mastra-class)的 `scorers` 選項註冊：

```typescript title="src/mastra/index.ts"
import { Mastra } from '@mastra/core'
import { LibSQLStore } from '@mastra/libsql'
import { checks } from '@mastra/evals/checks'
import { createAnswerRelevancyScorer } from '@mastra/evals/scorers/prebuilt'
import { myAgent } from './agents/my-agent'

export const mastra = new Mastra({
  agents: { myAgent },
  storage: new LibSQLStore({ url: 'file:./mastra.db' }),
  scorers: {
    calledTool: checks.calledTool('get_weather'),
    includes: checks.includes('Brooklyn'),
    relevancy: createAnswerRelevancyScorer({ model: '__GATEWAY_OPENAI_MODEL_LUNA__' }),
  },
})
```

查找時只比較評分器 ID，故註冊實例與評估實例可使用不同配置。所有 `checks.calledTool()` 實例的 ID 均為 `check-called-tool`，只需註冊一個，便涵蓋你評估的所有工具名稱。

隨分數保存的 `description` 取決於註冊實例所用的參數。使用 `checks.calledTool('')` 仍能保存分數，但描述會是 `Checks that "" was called`，因此請傳入具代表性的值。

略過註冊不會改變評分結果，但每次儲存都會失敗，並出現 `Scorer with id <id> not found` 警告，分數亦不會寫入儲存系統。

## Trace 評估 {/* #trace-evaluations */}

除了即時評估，你亦可用評分器評估過往 Agent 互動或 Workflow 所產生的 Trace。

這尤其適合分析過往表現、排查問題或分批進行評估。

:::note[須配置可觀測性]

要為 Trace 評分，先要在 Mastra 實例配置可觀測性以收集 Trace 數據。設定方法請參閱[追蹤文件](../observability/tracing/overview)。

:::

## Studio {/* #studio */}

要為 Trace 評分，請先在 Mastra 實例註冊評分器：

```typescript
const mastra = new Mastra({
  scorers: {
    answerRelevancy: myAnswerRelevancyScorer,
    responseQuality: myResponseQualityScorer,
  },
})
```

註冊後，你可以在 Studio 的 **Observability** 部分以互動方式為 Trace 評分，亦可在 Studio 管理評分器、查閱分數和執行實驗。

- **評分器清單**：瀏覽所有已註冊的評分器及其描述，並查看每個評分器連結了多少個 Agent 和 Workflow。
- **評分結果**：選取評分器後，可分頁查閱它給出的所有分數。按一下相應列即可開啟詳情面板，查看分數、評分理由、輸入、輸出及評判模型所用的提示詞。你可以在面板將任何結果儲存為數據集項目，供日後實驗使用。
- **Agent 的 Evaluate 分頁**：開啟任何 Agent 的 Evaluate 分頁，即可管理評分器及數據集，亦可執行實驗。實驗結果會列出每個項目的分數、合格或不合格狀態及版本標籤。
- **Trace 評分**：在 Observability 部分對任何歷史 Trace 或 Span 執行評分器，以評估以往的互動。可按 Agent 或 Workflow 篩選分數。
