# 埃瓦爾斯

雖然傳統的軟體測試具有明確的通過/失敗條件，但人工智慧輸出是不確定的，它們可能會隨著相同的輸入而變化。**Scorers**透過提供衡量Agent品質的量化指標來幫助彌補這一差距。

評分器是使用模型分級、基於規則和統計方法評估Agent輸出的自動化測試。得分手歸來**scores**: numerical values (typically between 0 and 1) that quantify how well an output meets your evaluation criteria. These scores enable you to objectively track performance and compare different approaches while identifying areas for improvement in your AI systems. Scorers can be customized with your own prompts and scoring functions.

記分員可以在雲端運行以捕獲即時結果。評分器還可以成為 CI/CD 管道的一部分，用於隨著時間的推移測試和監控Agent。

記分員測量單一輸出。要隨著時間的推移改進Agent，請將它們與[datasets](/docs/evals/datasets), which store versioned test cases, and [experiments](/docs/evals/experiments), which run an agent or workflow against a dataset, optionally score each result, and keep the results for comparison. [Build an eval loop](/docs/guides/build-an-eval-loop)一起使用它們。

## 得分手的類型 {/* #types-of-scorers */}

Mastra 提供不同類型的記分器，每種記分器都有特定的用途。以下是一些常見的類型：

1. **文字記分器**：評估座席響應的準確性、可靠性和上下文理解
2. **分類記分員**：測量基於預定義類別的資料分類的準確性
3. **即時工程記分員**：探索不同指令和輸入格式的影響

## 安裝 {/* #installation */}

若要存取 Mastra 的記分器功能，請安裝`@mastra/evals` package.

```bash npm2yarn
npm install @mastra/evals@latest
```

## 現場評估 {/* #live-evaluations */}

**現場評估**讓您在Agent程式和Workflow運行時即時自動對 AI 輸出進行評分。評分器不是手動或批次運行評估，而是與 AI 系統一起非同步運行，提供持續的品質監控。

### 向Agent商添加記分員 {/* #adding-scorers-to-agents */}

您可以為Agent程式新增內建記分器以自動評估其輸出。請參閱[full list of built-in scorers](/docs/evals/built-in-scorers) for all available options.

```typescript title="src/mastra/agents/evaluated-agent.ts"
import { Agent } from '@mastra/core/agent'
import { createAnswerRelevancyScorer, createToxicityScorer } from '@mastra/evals/scorers/prebuilt'

export const evaluatedAgent = new Agent({
  id: 'evaluated-agent',
  scorers: {
    relevancy: {
      scorer: createAnswerRelevancyScorer({ model: '__GATEWAY_OPENAI_MODEL_LUNA__' }),
      sampling: { type: 'ratio', rate: 0.5 },
    },
    safety: {
      scorer: createToxicityScorer({ model: '__GATEWAY_OPENAI_MODEL_LUNA__' }),
      sampling: { type: 'ratio', rate: 1 },
    },
  },
})
```

### 將記分員新增至Workflow步驟 {/* #adding-scorers-to-workflow-steps */}

您也可以將評分員新增到各個Workflow步驟中，以評估流程中特定點的輸出。每個評分者都會收到該步驟自己的輸入和輸出，因此您可以衡量每個步驟的質量，而不僅僅是對最終答案進行評分：

```typescript title="src/mastra/workflows/content-generation.ts"
import { createWorkflow, createStep } from '@mastra/core/workflows'
import { z } from 'zod'
import { customStepScorer } from '../scorers/custom-step-scorer'

const contentStep = createStep({
  id: 'content-step',
  inputSchema: z.object({ topic: z.string() }),
  outputSchema: z.object({ content: z.string() }),
  scorers: {
    customStepScorer: {
      scorer: customStepScorer(),
      sampling: {
        type: 'ratio',
        rate: 1, // Score every step execution
      },
    },
  },
  execute: async ({ inputData }) => {
    return { content: await generateContent(inputData.topic) }
  },
})

export const contentWorkflow = createWorkflow({
  id: 'content-workflow',
  inputSchema: z.object({ topic: z.string() }),
  outputSchema: z.object({ content: z.string() }),
})
  .then(contentStep)
  .commit()
```

對於階梯級`scorers` API, see the [Step class reference](/reference/workflows/step#scoring-step-output).

### 即時評估如何運作 {/* #how-live-evaluations-work */}

**非同步執行**：即時評估在背景運行，不會阻止Agent回應或Workflow執行。您的人工智慧系統在即時評估對其進行監控的同時保持回應。

**取樣控制**： 這`sampling.rate` parameter (0-1) controls what fraction of outputs get scored:

* `1.0`：每個答案進行評分（100%）
* `0.5`：佔所有回覆的一半 (50%)
* `0.1`：對 10% 的答案進行評分
* `0.0`：禁用評分

每條軌跡的取樣都是確定性的：決策源自於軌跡 ID，而不是隨機抽取。在實踐中：

* 以相同速率配置的評分器會對相同的追蹤進行評分，因此它們的分數在共享流量上具有可比性。
* 重新運行相同的追蹤會產生相同的採樣決策，因此採樣的覆蓋範圍是可重現的。

當運行沒有追蹤（未配置可觀察性）時，決策將改為從運行 ID 派生。如果[trace sampling](../observability/tracing/overview) declined the trace, scorers skip that run entirely, so scores aren't created for traces that were never stored.

**資格過濾器**`filter` parameter uses a declarative predicate over the run context to restrict scorer eligibility. Because filtering occurs before sampling, `sampling.rate` applies only to matching runs:

```typescript title="src/mastra/agents/evaluated-agent.ts"
import { Agent } from '@mastra/core/agent'

export const myAgent = new Agent({
  // ...
  scorers: {
    relevancy: {
      scorer: createAnswerRelevancyScorer({ model: '__GATEWAY_OPENAI_MODEL_LUNA__' }),
      filter: {
        op: 'eq',
        left: { path: 'requestContext.plan' },
        right: { literal: 'enterprise' },
      },
      sampling: { type: 'ratio', rate: 0.1 },
    },
  },
})
```

這僅佔企業計畫流量的 10%，其餘均不得分。若要以不同的速率對不同的片段進行評分，請使用互補過濾器將相同評分器綁定兩次。

謂詞可以參考`requestContext.*`, `entity.*`, `entityType`, `source`, `threadId`, `resourceId`, and `projectId`. They support comparisons (`eq`, `ne`, `lt`, `lte`, `gt`, `gte`), membership (`in`, `notIn`), existence (`exists`, `notExists`), truthiness (`truthy`, `falsy`), and boolean composition (`and`, `or`, `not`). A filter that references an unknown root fails at agent construction rather than silently skipping scoring at runtime. Filters are plain JSON, so they're unaffected by durable agent state serialization.

資格過濾器決定*whether a scorer runs*; to filter *which messages a scorer sees* once it runs, use [`filterRun()`](/reference/evals/filter-run). Filters can't see the run's input or output. When eligibility depends on what happened in the run, such as whether a specific tool was called, return [`notScorable()`](/reference/evals/not-scorable) from a scorer step instead: the remaining steps are skipped and no score is stored.

**自動儲存**：所有評分結果自動儲存於`mastra_scorers` table in your configured database, allowing you to analyze performance trends over time.

## 分數持久性 {/* #score-persistence */}

當 Mastra 實例有時，分數會被保留`storage` configured, and when the scorer is registered on that instance. Registration is what lets Mastra resolve the scorer's metadata (name, description, type) through [`getScorerById()`](/reference/core/getScorerById) before writing the score.

您附加到Agent商或Workflow步驟的記分員會自行註冊。您直接傳給的得分手[`runEvals()`](/reference/evals/run-evals), including [Quick Checks](/docs/evals/quick-checks), need the `scorers` option on the [`Mastra` class](/reference/core/mastra-class):

```typescript title="src/mastra/index.ts"
import { Mastra } from '@mastra/core'
import { LibSQLStore } from '@mastra/libsql'
import { checks } from '@mastra/evals/checks'
import { createAnswerRelevancyScorer } from '@mastra/evals/scorers/prebuilt'
import { myAgent } from './agents/my-agent'

export const mastra = new Mastra({
  agents: { myAgent },
  storage: new LibSQLStore({ url: 'file:./mastra.db' }),
  scorers: {
    calledTool: checks.calledTool('get_weather'),
    includes: checks.includes('Brooklyn'),
    relevancy: createAnswerRelevancyScorer({ model: '__GATEWAY_OPENAI_MODEL_LUNA__' }),
  },
})
```

此查找僅比較記分器 ID，這允許註冊實例使用與評估實例不同的配置。每一個`checks.calledTool()` instance uses the ID `check-called-tool`. Registering one therefore covers every tool name you evaluate.

這些論點仍然影響著`description` stored alongside each score, which comes from the registered instance, not the one you evaluate with. `checks.calledTool('')` is accepted and persists scores fine, but stores `Checks that "" was called`, so pass a representative value.

跳過註冊不會改變評分結果，但每次儲存都會失敗並顯示`Scorer with id <id> not found` warning and the scores never reach the store.

## 追蹤評估 {/* #trace-evaluations */}

除了即時評估之外，您還可以使用評分器來評估座席互動和Workflow的歷史追蹤。

這對於分析過去的效能或偵錯問題，或執行批量評估特別有用。

:::注意\[需要可觀察性]

若要對追蹤進行評分，您必須先在 Mastra 實例中配置可觀察性以收集追蹤資料。看[Tracing documentation](../observability/tracing/overview) for setup instructions.

:::

## 工作室 {/* #studio */}

要對痕跡進行評分，您首先需要向 Mastra 實例註冊您的評分器：

```typescript
const mastra = new Mastra({
  scorers: {
    answerRelevancy: myAnswerRelevancyScorer,
    responseQuality: myResponseQualityScorer,
  },
})
```

註冊後，您可以在 Studio 中以互動方式對痕跡進行評分**Observability** section. Open Studio to manage scorers and review scores, plus run experiments.

* **進球名單**：瀏覽所有註冊的記分員及其描述，以及每位記分員所附加的Agent和Workflow的數量。
* **評分結果**：選擇一個記分器以查看其產生的每個樂譜的分頁清單。點擊某一行可開啟詳細面板，顯示評分值、原因、輸入、輸出以及評審所使用的提示。在此面板中，將任何結果儲存為資料集專案以供將來的實驗使用。
* **Agent評估選項卡**：開啟任何Agent程式上的「評估」標籤以管理評分器和資料集。您也可以在那裡進行實驗。實驗結果顯示每個項目的分數以及通過/失敗狀態和版本標籤。
* **追蹤評分**：在可觀察性部分中，針對任何歷史追蹤或跨度運行評分器以評估過去的交互作用。按Agent或Workflow過濾分數。
