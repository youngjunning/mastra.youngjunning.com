# 內置評分器

Mastra 內置一套評分器，供你評估 AI 輸出。這套評分器針對常見的評估情況設計，可以直接用於 Agent 和 Workflow。

如要自行建立評分器，可參閱[自訂評分器](/docs/evals/custom-scorers)指南。

## 可供使用的評分器 {/* #available-scorers */}

### 準確性和可靠性 {/* #accuracy-and-reliability */}

這類評分器會檢查 Agent 的答案是否正確、符合事實和完整：

- [`answer-relevancy`](/reference/evals/answer-relevancy)：評估答覆有多切合輸入的查詢（`0-1`，分數愈高愈好）
- [`answer-similarity`](/reference/evals/answer-similarity)：用於 CI/CD 測試，以語義分析比較 Agent 的輸出和標準答案（`0-1`，分數愈高愈好）
- [`faithfulness`](/reference/evals/faithfulness)：衡量答覆有多準確地反映所提供的上下文（`0-1`，分數愈高愈好）
- [`hallucination`](/reference/evals/hallucination)：辨識與事實不符或沒有根據的說法（`0-1`，分數愈低愈好）
- [`completeness`](/reference/evals/completeness)：檢查答覆有否包含所有所需資訊（`0-1`，分數愈高愈好）
- [`content-similarity`](/reference/evals/content-similarity)：按字元比對文字，量度相似程度（`0-1`，分數愈高愈好）
- [`textual-difference`](/reference/evals/textual-difference)：量度字串之間的文字差異（`0-1`，分數愈高代表愈相似）
- [`tool-call-accuracy`](/reference/evals/tool-call-accuracy)：檢查 LLM 有否從可用的 Tool 當中作出正確選擇（`0-1`，分數愈高愈好）
- [`trajectory-accuracy`](/reference/evals/trajectory-accuracy)：評估所有類型的 span 是否按預期順序執行，包括 Tool 和模型的活動，以及 Workflow 步驟（`0-1`，分數愈高愈好）
- [`prompt-alignment`](/reference/evals/prompt-alignment)：量度 Agent 的答覆有多符合使用者提示的意圖、要求、完整程度和格式（`0-1`，分數愈高愈好）
- [`multi-turn-judge`](/reference/evals/multi-turn-judge)：按以淺白英文寫成的準則，為[多輪對話](/docs/evals/multi-turn)中助手的每輪答覆評分（`0` 或 `scale`，預設為 `1`）

### 上下文品質 {/* #context-quality */}

這類評分器會評估生成答覆時所用上下文的質素和相關程度：

- [`context-precision`](/reference/evals/context-precision)：以平均精確率均值評估上下文的排序；相關內容排得愈前，得分愈高（`0-1`，分數愈高愈好）
- [`context-relevance`](/reference/evals/context-relevance)：按相關程度及使用紀錄衡量上下文是否有用，並找出欠缺的上下文（`0-1`，分數愈高愈好）

:::tip[上下文評分器選擇]

- 若排序會影響結果，而你需要標準的資訊檢索指標，可使用 **Context Precision**（適合評估 RAG 排序）。
- 如需仔細衡量相關程度，並查看哪些上下文獲採用、哪些仍然欠缺，可使用 **Context Relevance**。

兩個上下文評分器都支援：

* **靜態情境**：預定義的上下文數組
* **動態上下文提取**：使用自訂函數從運行中提取上下文（非常適合 RAG 系統、向量資料庫等）

:::

### 輸出品質 {/* #output-quality */}

這些評分者評估對格式、風格和安全要求的遵守：

- [`tone-consistency`](/reference/evals/tone-consistency)：衡量語氣的正式程度、複雜程度和風格是否一致（`0-1`，分數愈高愈好）
- [`toxicity`](/reference/evals/toxicity)：識別有害或不當內容（`0-1`，分數愈低愈好）
- [`bias`](/reference/evals/bias)：找出輸出可能帶有的偏見（`0-1`，分數愈低愈好）
- [`keyword-coverage`](/reference/evals/keyword-coverage)：評估輸出如何使用技術術語（`0-1`，分數愈高愈好）

### 快速檢查 {/* #quick-checks */}

這組輕量評分器不用調用 LLM，即可快速執行結果確定的斷言。用法可參閱[快速檢查](/docs/evals/quick-checks)指南。

* [`checks.includes`](/reference/evals/checks#checksincludesexpected-options)：如果輸出包含子字串 (`0` or `1`)
* [`checks.excludes`](/reference/evals/checks#checksexcludesunwanted-options)：如果輸出不包含子字串（`0` or `1`)
* [`checks.equals`](/reference/evals/checks#checksequalsexpected-options)：如果輸出與字串匹配則得分 1，預設會忽略大小寫（`0` or `1`)
* [`checks.matches`](/reference/evals/checks#checksmatchespattern-options)：如果輸出與正規表示式匹配，則得分 1（`0` or `1`)
- [`checks.similarity`](/reference/evals/checks#checkssimilarityexpected-options)：以 Dice 係數量度字串相似程度（`0-1`，亦可按閾值給予二元分數）
* [`checks.calledTool`](/reference/evals/checks#checkscalledtooltoolname-options)：如果某個Tool被呼叫至少 N 次，則得分 1（`0` or `1`)
* [`checks.didNotCall`](/reference/evals/checks#checksdidnotcalltoolname)：如果未呼叫Tool則得 1 分（`0` or `1`)
* [`checks.toolOrder`](/reference/evals/checks#checkstoolorderexpectedorder)：如果依序呼叫Tool則得 1 分（`0` or `1`)
* [`checks.maxToolCalls`](/reference/evals/checks#checksmaxtoolcallsmax)：如果Tool呼叫次數在限制範圍內，則得分 1（`0` or `1`)
* [`checks.usedNoTools`](/reference/evals/checks#checksusednotools)：如果沒有呼叫任何Tool，則得分 1（`0` or `1`)
* [`checks.noToolErrors`](/reference/evals/checks#checksnotoolerrors)：如果Tool呼叫沒有錯誤，則得分 1（`0` or `1`)
