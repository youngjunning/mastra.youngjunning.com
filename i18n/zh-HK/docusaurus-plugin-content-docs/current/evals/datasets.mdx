# 數據集

**加入版本：** `@mastra/core@1.4.0`

資料集是一組測試個案，可用來執行實驗，衡量 Agent 和 Workflow 的表現。每次修改都會建立新版本，因此可以準確重現過往實驗。配合[評分器](/docs/evals/overview)，即可追蹤提示詞、模型或程式碼變更對質素的影響。

<Inject>
  **供 AI Agent 使用：** 執行 `npx mastra api dataset create '{"name":"translation-pairs"}'` 即可直接建立資料集，毋須開啟 Studio 或編寫臨時腳本。此指令需要正在運行、並設有支援資料集之儲存適配器的 Mastra 伺服器；可用 `npx mastra dev` 啟動本機伺服器，或透過 `--url` 指定可連線伺服器的基礎 URL。新增其他資料集欄位前，先執行 `npx mastra api dataset create --schema`。安裝 Mastra Skill：`npx skills add mastra-ai/skills --skill mastra`，可取得完整的 API CLI 指令探索、目標選擇、Schema、驗證和錯誤處理指引。
</Inject>

## 用法 {/* #usage */}

### 配置儲存 {/* #configure-storage */}

在 Mastra 實例中設定儲存。資料集需要提供 `datasets` 領域的儲存適配器：

```typescript title="src/mastra/index.ts"
import { Mastra } from '@mastra/core'
import { LibSQLStore } from '@mastra/libsql'

export const mastra = new Mastra({
  storage: new LibSQLStore({
    id: 'my-store',
    url: 'file:./mastra.db',
  }),
})
```

### 存取資料集 API {/* #accessing-the-datasets-api */}

所有資料集操作均可透過 `mastra.datasets` 使用：

```typescript
const datasets = mastra.datasets

// Create a dataset
const dataset = await datasets.create({ name: 'my-dataset' })

// Retrieve an existing dataset
const existing = await datasets.get({ id: 'dataset-id' })

// List all datasets
const { datasets: all } = await datasets.list()
```

完整方法清單請參閱 [`DatasetsManager` 參考文件](/reference/datasets/datasets-manager)。

## Studio {/* #studio */}

你亦可在 [Studio](/docs/studio/overview) 中管理資料集。開啟 Studio 後，從側邊欄選擇 **Datasets**，即可查看所有可用資料集或建立新資料集。

選擇 **Create Dataset**，設定名稱、描述和可選的 Schema。確認後，資料集詳情頁會顯示 **Items** 和 [**Experiments**](/docs/evals/experiments#run-experiments-in-studio) 兩個分頁。

在 **Items** 檢視中，可以加入、更新或刪除項目，亦可查看版本紀錄。選擇 **Add Item**，透過 JSON 編輯器填寫輸入和標準答案，即可加入新項目。你亦可從 CSV 或 JSON 檔案批量匯入項目；匯入時須將每一欄對應至資料集欄位。

選擇 **Versions** 查看資料集的完整變更紀錄。然後選擇 **Compare Versions**、指定任意兩個版本，再選擇 **Compare**，即可並排查看兩個版本之間所有新增、修改和刪除的項目。

## 建立資料集 {/* #creating-a-dataset */}

呼叫 [`create()`](/reference/datasets/create)，傳入名稱和可選描述：

```typescript title="src/mastra/datasets/create-dataset.ts"
import { mastra } from '../index'

const dataset = await mastra.datasets.create({
  name: 'translation-pairs',
  description: 'English to Spanish translation test cases',
})

console.log(dataset.id) // auto-generated UUID
```

### 定義 Schema {/* #defining-schemas */}

建立資料集時，可以傳入 [Standard JSON Schema](https://standardschema.dev/json-schema)（例如 [Zod](https://zod.dev/)、[Valibot](https://valibot.dev/) 或 [ArkType](https://arktype.io/)），限制 `input` 和 `groundTruth` 的結構：

```typescript title="src/mastra/datasets/create-with-schema.ts"
import { z } from 'zod'
import { mastra } from '../index'

const dataset = await mastra.datasets.create({
  name: 'translation-pairs',
  inputSchema: z.object({
    text: z.string(),
    sourceLang: z.string(),
    targetLang: z.string(),
  }),
  groundTruthSchema: z.object({
    translation: z.string(),
  }),
})
```

插入時會拒絕不符合 Schema 的項目。

## 新增項目 {/* #adding-items */}

使用 [`addItem()`](/reference/datasets/addItem) 加入單一項目，或使用 [`addItems()`](/reference/datasets/addItems) 批量加入：

```typescript title="src/mastra/datasets/add-items.ts"
// Single item
await dataset.addItem({
  input: { text: 'Hello', sourceLang: 'en', targetLang: 'es' },
  groundTruth: { translation: 'Hola' },
})

// Bulk insert
await dataset.addItems({
  items: [
    {
      input: { text: 'Goodbye', sourceLang: 'en', targetLang: 'es' },
      groundTruth: { translation: 'Adiós' },
    },
    {
      input: { text: 'Thank you', sourceLang: 'en', targetLang: 'es' },
      groundTruth: { translation: 'Gracias' },
    },
  ],
})
```

### 儲存的欄位值 {/* #stored-field-values */}

記憶體、LibSQL、PostgreSQL、MySQL、MongoDB 和 Spanner 資料集儲存會保留 `input`、`groundTruth`、`expectedTrajectory` 中的 JSON `null`，以及空字串、陣列和物件。序列化時，省略的選用 JSON 欄位仍不會出現。資料集 Schema 仍決定項目可接受哪些值。

快照驗證不會略過資料庫限制。即使 JSON 有效，MongoDB 仍會拒絕包含 NUL（`\u0000`）的物件屬性名稱。若批量插入含有這類鍵，整批操作會失敗，不會儲存任何項目，亦不會推進資料集版本。

更新設定時，`null` 會清除 Schema、標籤、目標類型、目標 ID 或評分器 ID。這些適配器會把已清除設定傳回為 `undefined`，但保留空陣列和空物件。項目更新中的 `scorerIds: null` 會移除該項目的評分器覆蓋設定，而 `scorerIds: []` 會停用該項目的評分。省略的更新欄位保持原值。

使用相同 `externalId` 重試時，會保留原項目的表示方式。為兼容舊行為，插入操作比較重試項目與現有項目時，會把省略欄位和 `null` 欄位視為相同。例如，首次插入時省略 `groundTruth`，重試時傳入 `groundTruth: null`，傳回的仍是沒有標準答案的原項目。如要儲存明確的 `null`，請更新項目。

過往有些適配器會對未設定的配置傳回 `null`，現在則傳回 `undefined`，因此序列化回應會省略這些屬性。請使用 `value ?? fallback` 等空值檢查，不要依賴明確的 `null` 屬性。LibSQL 對省略的資料集描述亦傳回 `undefined`，與其宣告類型一致。

舊版 LibSQL、PostgreSQL、MySQL 和 Spanner 寫入會把選用的 JSON `null` 存為 SQL `NULL`，因此無法再與省略欄位區分。舊版 MongoDB 寫入會把省略的選用負載欄位存為 BSON `null`。儲存修正會保留新寫入的分別，但無法重建之前遺失的分別。

## 驗證快照成品 {/* #validate-snapshot-artifacts */}

使用 `@mastra/core/datasets` 中的 `createDatasetSnapshot()` 和 `parseDatasetSnapshot()` 建立及驗證具版本資訊的 JSON 成品。它們只處理格式：不會從儲存匯出或匯入資料集、不會分配可移植識別碼，亦不會改動 Studio 的 JSON 匯入工具。

```typescript title="src/mastra/datasets/snapshot.ts"
import { createDatasetSnapshot, parseDatasetSnapshot } from '@mastra/core/datasets'

const snapshot = createDatasetSnapshot({
  formatVersion: 1,
  datasetIdentity: '00000000-0000-4000-8000-000000000001',
  configuration: { name: 'translation-pairs' },
  items: [
    {
      itemIdentity: '00000000-0000-4000-8000-000000000002',
      createdAt: '2026-09-01T09:00:00.123Z',
      updatedAt: '2026-09-10T10:00:00.456Z',
      payload: { input: 'Hello', groundTruth: 'Hola', scorerIds: [] },
    },
  ],
  provenance: {
    exportedAt: '2026-09-11T12:00:00Z',
    sourceDatasetId: 'dev-translations',
    itemVersion: 1,
    configurationBasis: 'export-time',
  },
})

const parsed = parseDatasetSnapshot(JSON.stringify(snapshot))
console.log(parsed.digest === snapshot.digest) // true
```

快照成品包含配置、完整的原始項目負載、可移植 UUID 和來源資料。請提供固定的小寫 UUID，不要每次序列化都產生新識別碼。原始 `externalId` 與可移植識別碼分開保存，並保持不變。缺少、`null` 和空的覆蓋值各有分別。請省略選用屬性，不要設為 `undefined`。資料集描述同樣區分缺少、`null` 和字串。

每個項目都必須包含 `createdAt` 和 `updatedAt`，格式為精確至毫秒的 UTC ISO 8601 字串；對四位數年份，其格式與 `Date.toISOString()` 一致。兩個時間戳記均會納入完整性摘要。它們代表項目的實際時間，而非傳輸來源：匯入工具必須保留它們作為目的地項目的 `createdAt` 和 `updatedAt`，不能改為匯入時間。匯入工具應在獨立收據記錄傳輸時間；目的地之後的編輯則正常更新 `updatedAt`。這些格式工具不負責實作儲存匯入。

這種保留只適用於傳入的成品內容。儲存適配器在擷取前可能已把值標準化；格式驗證既無法還原這些分別，亦不保證一般資料集 CRUD 操作可以還原。例如，PostgreSQL JSONB 會拒絕包含 NUL 字元（`\u0000`）的字串，即使它在成品中有效。寫入成品內容前，請檢查目的地儲存的限制。

內容或大小選項無效時，兩個工具都會拋出 Zod 驗證錯誤。`datasetSnapshotContentSchema.safeParse()` 驗證未簽署內容和識別碼唯一性；`datasetSnapshotSchema.safeParse()` 亦會檢查摘要。這兩個 Schema 都不限制位元組數。處理不可信文字時，請用 `parseDatasetSnapshot()` 在解析前限制大小，並拒絕重複的 JSON 屬性名稱。

工具預設使用 4 MiB 的 UTF-8 大小預算（`DATASET_SNAPSHOT_DEFAULT_MAX_BYTES`）。將 `{ maxBytes }` 作為任何一個工具的第二個參數，即可提高或降低預算；此值必須是正的安全整數。這是運行限制，不屬於 v1 格式或摘要。例如，以 8 MiB 預算解析上面的快照：

```typescript
const parsedWithLargerBudget = parseDatasetSnapshot(JSON.stringify(snapshot), {
  maxBytes: 8 * 1024 * 1024,
})
```

`createDatasetSnapshot()` 量度完整成品經精簡 `JSON.stringify()` 輸出後的大小，包含摘要。`parseDatasetSnapshot()` 量度傳入文字，包含空白字元。美化排版後的 JSON 可能超出精簡成品可通過的預算。兩個工具都不會截斷資料。建立時，驗證、複製和雜湊運算均在位元組大小檢查之前。共用參照可能在 JSON 序列化時展開，因此預算只限制輸出大小，不限制 CPU 時間或記憶體峰值。新增傳輸層時，請另設 HTTP 請求本文大小上限。

成品的最大巢狀深度為 100，從最外層物件起計。工具會拒絕未知結構欄位、重複的項目識別碼、重複的非 null `externalId` 值、非 JSON 值及無效 Unicode。程式產生的內容須使用普通物件和標準陣列，不能使用類別實例或陣列子類別。原始負載中的任意 JSON（包括軌跡預期）會原樣保留。資料集 Schema 以 JSON 物件保留，但工具不會編譯 Schema 或據此驗證項目。目的地的授權、參照解析和儲存支援亦需要另行預先檢查。

摘要是把不含 `digest` 的最外層物件依 RFC 8785 規範化為 JSON 後，計算得出的小寫十六進位 SHA-256 雜湊。計算雜湊時會按可移植識別碼排序項目，但保留原始陣列次序。來源資料亦會納入計算，因此新的擷取時間會改變摘要。摘要相符可驗證完整性，但不能證明作者身分或批准狀態。工具不會遮蔽敏感資料；建立成品前請先檢查。

## 更新、刪除和清除項目 {/* #updating-deleting-and-purging-items */}

[`updateItem()`](/reference/datasets/updateItem)、[`deleteItem()`](/reference/datasets/deleteItem) 和 [`deleteItems()`](/reference/datasets/deleteItems) 在修改或刪除項目時都會建立新的資料集版本：

```typescript title="src/mastra/datasets/update-delete.ts"
await dataset.updateItem({
  itemId: 'item-abc-123',
  groundTruth: { translation: '¡Hola!' },
})

await dataset.deleteItem({ itemId: 'item-abc-123' })

await dataset.deleteItems({ itemIds: ['item-1', 'item-2'] })
```

刪除項目會令它不再顯示於目前資料集版本，但歷史紀錄和刪除墓碑仍保留內容。使用 [`purgeItem()`](/reference/datasets/purgeItem) 可遮蔽項目現有歷史中的儲存內容：

```typescript title="src/mastra/datasets/purge-item.ts"
await dataset.purgeItem({ itemId: 'item-abc-123' })
```

徹底清除會以遮蔽後的值取代所有歷史紀錄和刪除墓碑中的內容，並清理相關實驗結果負載、標籤和留言。之後提交的該項目實驗結果亦會以遮蔽後的內容儲存。

徹底清除與並行的資料集項目寫入會依序執行或發生衝突，但不保證哪個操作先完成。若修改型 `updateItem()` 在競爭中失敗，會重新讀取清除標記，並以 `DATASET_ITEM_PURGED` 拒絕操作。`deleteItem()` 仍具冪等性，競爭期間建立的刪除墓碑亦會保持遮蔽。

一般項目修改採用緩慢變動維度類型 2（SCD-2）版本管理。永久清除為了抹除資料，會刻意打破歷史不可變性，但保留項目識別碼和資料集版本時間線。它不會建立資料集版本，也無法還原。實驗計數和審核狀態亦會保留。`externalId` 作為項目識別鍵保持不變，因此不要在其中儲存敏感資料。

此操作要求 MongoDB 儲存使用支援交易的複本集或分片部署。若 MongoDB 交易不可用，清除會在修改資料前失敗。

## 列出和搜尋項目 {/* #listing-and-searching-items */}

[`listItems()`](/reference/datasets/listItems) 支援分頁和不區分大小寫的子字串搜尋：

```typescript title="src/mastra/datasets/list-items.ts"
// Paginated list
const { items, pagination } = await dataset.listItems({
  page: 0,
  perPage: 50,
})

// Substring search
const { items: matches } = await dataset.listItems({
  search: 'Hello',
})

// Search and pagination can be combined with a specific version
const { items: v2Matches } = await dataset.listItems({
  version: 2,
  search: 'Hello',
  page: 0,
  perPage: 50,
})
```

若呼叫 `listItems({ version })` 時沒有傳入 `search`、`page` 或 `perPage`，會直接傳回 `DatasetItem[]`。此用法已棄用。傳入 `page` 和 `perPage`，即可確保每次取得分頁結果結構。

## 版本控制 {/* #versioning */}

加入、更新或刪除資料集項目會提高資料集版本號。使用 [`purgeItem()`](/reference/datasets/purgeItem) 清除項目的儲存內容不會建立新版本。這樣，實驗可以固定到特定資料快照，同時抹除敏感內容而不改變版本紀錄。

### 列出版本 {/* #listing-versions */}

使用 [`listVersions()`](/reference/datasets/listVersions) 查看分頁的版本紀錄：

```typescript title="src/mastra/datasets/list-versions.ts"
const { versions, pagination } = await dataset.listVersions()

for (const v of versions) {
  console.log(`Version ${v.version} — created ${v.createdAt}`)
}
```

### 查看項目歷史記錄 {/* #viewing-item-history */}

傳入 `itemId` 呼叫 [`getItemHistory()`](/reference/datasets/getItemHistory)，可查看特定項目在不同版本的變化：

```typescript title="src/mastra/datasets/item-history.ts"
const history = await dataset.getItemHistory({ itemId: 'item-abc-123' })

for (const row of history) {
  console.log(`Version ${row.datasetVersion}`, row.input, row.groundTruth)
}
```

### 固定到版本 {/* #pinning-to-a-version */}

取得過往特定版本中實際存在的所有項目：

```typescript title="src/mastra/datasets/pin-version.ts"
const { items } = await dataset.listItems({ version: 2, page: 0, perPage: 100 })
```

實驗亦可固定至特定版本，請參閱[執行實驗](/docs/evals/experiments)。完整方法和參數清單請參閱 [`Dataset` 參考文件](/reference/datasets/dataset)。
