# 觀察記憶

**添加於：** `@mastra/memory@1.1.0`

觀察記憶體 (OM) 允許Agent在任務執行期間在一個執行緒中工作，並且上下文保持較小、集中且提示快取友好。一個**Observer** agent turns older messages into short, dated observations in the background, and a **Reflector**Agent在成長時會濃縮這些觀察。Agent會完整地查看最近的訊息，並將之前的所有內容視為觀察結果。

對於不只執行一次性摘要或單一Workflow步驟的任何Agent，請使用 OM。每個採取多個步驟的Agent都會受益：聊天助理、編碼Agent、瀏覽器Agent、運行數小時的支援線程。

## 快速入門 {/* #quickstart */}

安裝`@mastra/memory` and a [storage adapter](/docs/storage#supported-providers). The examples below use `@mastra/libsql`, which stores data locally in a `memory.db`文件。

```bash npm2yarn
npm install @mastra/memory@latest @mastra/libsql@latest
```

OM 需要支援它的儲存（`@mastra/libsql`, `@mastra/pg`, `@mastra/mysql`, `@mastra/mongodb`, `@mastra/convex`或者`@mastra/oracledb`)，每個呼叫都有一個線程，以及`observationalMemory: true`。該腳本將記憶體儲存在本地 LibSQL 檔案中，並在一個執行緒上呼叫Agent程式兩次：

```typescript title="src/observational-memory.ts"
import { Agent } from '@mastra/core/agent'
import { LibSQLStore } from '@mastra/libsql'
import { Memory } from '@mastra/memory'

const memory = new Memory({
  storage: new LibSQLStore({
    id: 'memory-storage',
    url: 'file:./memory.db',
  }),
  options: {
    // highlight-next-line
    observationalMemory: true,
  },
})

const agent = new Agent({
  id: 'memory-agent',
  name: 'Memory Agent',
  instructions: 'You are a helpful assistant.',
  model: '__GATEWAY_OPENAI_MODEL_LUNA__',
  memory,
})

const memoryOptions = {
  resource: 'user-123',
  thread: 'conversation-123',
}

const first = await agent.generate('Remember that my favorite color is blue.', {
  memory: memoryOptions,
})
console.log(first.text)

const second = await agent.generate('What is my favorite color?', {
  memory: memoryOptions,
})
console.log(second.text)
```

`resource`識別使用者或實體，並且`thread` identifies the conversation. Reuse both to continue the conversation. Nothing is observed in this short exchange. Once the thread's message history passes 30,000 tokens, OM starts replacing older messages with observations.

如果您的 Mastra 實例已有存儲，您可以離開`storage` out of `Memory` and it uses that.

要觀看 OM 工作，請打開**Memory** tab of the agent in [Studio](/docs/studio/overview). Progress bars show how close messages and observations are to their thresholds, and **Analyze observations** opens the observation log and its history.

## 好處 {/* #benefits */}

* **長任務停留在一個執行緒中**：Agent繼續工作超過其上下文限制，而不會壓縮，也不會丟失早期的決策。
* **提示快取**：觀察附加到一個穩定的前綴，而不是每輪都檢索，這使得提供者可以從其提示快取中服務大部分每個請求。看[cost and latency](#cost-and-latency).
* **較小的背景**：原始訊息和Tool結果壓縮為密集的觀察日誌，從而降低每次呼叫的成本和延遲。
* **更少的上下文腐爛**：Agent程式讀取重要的內容，而不是陳舊的Tool輸出和噪音，這使其能夠在長時間會話中繼續執行任務。

Mastra 自己的Agent在 OM 上運行。[Mastra Code](https://code.mastra.ai/), a coding agent for the terminal, uses it so a session can run for days without compacting. [Mastra Factory](https://factory.mastra.ai/) runs its planning, implementation and review sessions on Mastra Code. Each agent keeps the context of a long task from start to finish.

## 它是如何運作的 {/* #how-it-works */}

每次Agent程式回應時，它都會讀取一個上下文窗口，其中包含系統提示字元、最近的訊息和任何注入的上下文。它攜帶的原始歷史越多，它的性能就越差，大多數代幣不再需要繼續執行任務。 OM 壓縮了該歷史。

### 觀察結果 {/* #observations */}

當線程未觀察到的消息傳遞時`observation.messageTokens` (default 30,000), the Observer writes observations: short, dated notes about what happened.

```md
Date: 2026-01-15

- 🔴 12:10 User is building a Next.js app with Supabase auth, due in 1 week (meaning January 22nd 2026)
  - 🔴 12:10 App uses server components with client-side hydration
  - 🟡 12:12 User asked about middleware configuration for protected routes
  - 🔴 12:15 User stated the app name is "Acme Dashboard"
```

觀察到的訊息離開上下文窗口，觀察結果取代它們，通常小 5 到 40 倍。每個頁面快照看到 50,000 個令牌的瀏覽器Agent最終會攜帶數百個有關頁面上的內容及其用途的令牌。

在同步觀察過程中，觀察者也會記錄一個**current task** and a **suggested response**. These help the agent pick up where it left off. With `observation.threadTitle` enabled, it can suggest a new thread title when the topic changes.

觀察者會在其評論的歷史記錄中看到附件。成绩单保留占位符，例如`[Image #1: reference-board.png]`, and the attachments themselves are forwarded beside the text. See [choosing models](#choosing-models) for Observers that can't read attachments.

### 反思 {/* #reflections */}

`reflection.observationTokens` (default 40,000), the Reflector rewrites the whole log: it merges related items, condenses older ones more and keeps recent detail. Its output becomes the new log, and new observations append after it. The log stays around the reflection threshold however long the thread runs.

Agent的上下文分為三層：

1. **最近消息**：目前任務的確切對話。
2. **觀察結果**：自上次反射以來觀察者所看到的情況。
3. **反思**：之前所有內容的濃縮日誌。

### 背景如何隨時間變化 {/* #how-context-changes-over-time */}

在預設設定下，上下文視窗循環增大和縮小：

<OmContextOverTimeImage />

1. **0 到 30,000 個代幣**：訊息歷史記錄增長。在後台，觀察者準備每 6,000 個令牌的觀察結果（`observation.bufferTokens: 0.2`).
2. **已達 3 萬人**：準備好的觀察激活。觀察到的訊息離開上下文，並且大約 6,000 個最近訊息的標記保留（`observation.bufferActivation: 0.8` keeps 20% of the threshold).
3. **重複**：歷史成長回到 30,000，然後再次縮小。每個週期都會在觀察日誌中添加一點內容。
4. **觀察次數達 40,000**：Reflector 將日誌重寫為較小的日誌。

閾值標誌著工作開始的時間。當背景觀察落後時，歷史記錄可能會超過 30,000 個代幣。在`observation.blockAfter` (default `1.2`, or 36,000 tokens) the agent waits for a synchronous observation. See [when buffering falls behind](/reference/memory/observational-memory#when-buffering-falls-behind).

令牌計數是本地的`tokenx` estimates. The provider's own count is often higher, especially with attachments.

### 上下文溢出恢復 {/* #context-overflow-recovery */}

在 OM 的估計達到閾值之前，提供者可以拒絕超出其上下文視窗的請求。當發生這種情況時，OM 會啟動任何準備好的觀察，觀察仍待處理的所有內容，並使用較小的上下文重試該請求一次。預設此功能處於啟用狀態；放`observation.observeOnContextOverflow: false` to let the error reach your code instead.

## 選擇型號 {/* #choosing-models */}

觀察者和反射器是在Agent旁邊運行的模型呼叫。預設兩者都使用`model: 'auto'`, which resolves each time a role runs:

1. `google/gemini-2.5-flash`當 Google 可用時：`GOOGLE_GENERATIVE_AI_API_KEY` is set, or your `canUseProvider` function returns `true` for `'google'`.
2. 否則，例如來自主模型提供者的低成本模型`anthropic/claude-haiku-4-5` for an Anthropic agent.
3. 否則，主模型本身。

`auto`讀取主模型的`provider/model` ID. When that isn't known, such as a model created with a custom URL, API key or gateway, `auto` uses the main model itself, because a sibling model isn't known to share that route.

放`model` to use one model for both roles:

```typescript
const memory = new Memory({
  options: {
    observationalMemory: {
      model: 'deepseek/deepseek-flash',
    },
  },
})
```

使用具有大上下文視窗（128,000 個標記或更多）的模型，該模型的速度足以在背景運行。馬斯特拉已經測試過`google/gemini-2.5-flash`, `__GATEWAY_OPENAI_MODEL_LUNA__`, `__GATEWAY_ANTHROPIC_MODEL_HAIKU__` and `deepseek/deepseek-flash`.

若要為每個角色使用不同的模型，請設定`observation.model` and `reflection.model` instead, and leave the top-level `model` out. Setting both throws. Some models keep so much detail that their reflections can stay above the threshold; in testing, `google/gemini-2.5-flash` did this. A common split uses a detail-preserving model as the Observer and one that condenses more readily, such as `deepseek/deepseek-flash`, as the Reflector. See [different models per agent](/reference/memory/observational-memory#different-models-per-agent).

### 調整自動選擇 {/* #tune-automatic-selection */}

這些`observationalMemory` options adjust what `auto` picks:

* `autoModels`：例如，替換提供者的低成本選擇`{ openai: '__GATEWAY_OPENAI_MODEL_LUNA__' }`.
* `canUseProvider`： 告訴`auto` whether the current request can use a provider, when credentials are per tenant or per request rather than in the server's environment. It receives the provider ID and `{ requestContext }`.
* `resolveModel`：使用您自己的憑證或路由自行建立所選模型。它接收具体的模型 ID，从不`'auto'`.

```typescript
const memory = new Memory({
  options: {
    observationalMemory: {
      autoModels: { openai: '__GATEWAY_OPENAI_MODEL_LUNA__' },
      canUseProvider: (provider, { requestContext }) => hasCredentials(provider, requestContext),
      resolveModel: (modelId, { requestContext }) => createRoutedModel(modelId, requestContext),
    },
  },
})
```

`resolveAutoModelId(mainModelId, { autoModels })`從`@mastra/memory` returns the model `auto` would pick, for showing the effective model in a settings UI.

### 代幣分層模型 {/* #token-tiered-models */}

**添加於：** `@mastra/memory@1.10.0`

`ModelByInputTokens`根據每個觀察者或反射器所呼叫的大小來選擇模型：

```typescript
import { Memory, ModelByInputTokens } from '@mastra/memory'

const memory = new Memory({
  options: {
    observationalMemory: {
      observation: {
        model: new ModelByInputTokens({
          upTo: {
            5_000: 'openrouter/mistralai/ministral-8b-2512',
            20_000: 'openrouter/mistralai/mistral-small-2603',
            40_000: '__GATEWAY_OPENAI_MODEL_LUNA__',
            1_000_000: '__GATEWAY_GOOGLE_MODEL_FLASH__',
          },
        }),
      },
      reflection: {
        model: new ModelByInputTokens({
          upTo: {
            20_000: '__GATEWAY_OPENAI_MODEL_LUNA__',
            100_000: 'deepseek/deepseek-flash',
          },
        }),
      },
    },
  },
})
```

每一層都需要一個特定的模型 ID，而不是`'auto'`. Each `upTo` key is an inclusive upper bound. A call larger than the biggest key throws, so make the last tier cover the largest input you expect.

### 附件和純文字觀察員 {/* #attachments-and-text-only-observers */}

預設情況下，觀察者接收影像和 PDF（`observation.observeAttachments: ['image/*', 'application/pdf']`). Other attachments are left out, and their placeholders stay in the transcript. Change it when your Observer model handles more or less:

* `false`: 不發送附件。將其用於純文字觀察者。
* `true`: 發送每個附件。
* MIME 類型列表，例如`['image/*']`: send only matching attachments. Matching is case-insensitive and `*` matches any subtype.
* `'auto'`：當提供者註冊表表示觀察者模型接受多模式輸入時發送附件。當沒有模型資料時，所有內容都會被發送。

```typescript
const memory = new Memory({
  options: {
    observationalMemory: {
      observation: {
        model: 'deepseek/deepseek-flash',
        observeAttachments: false,
      },
    },
  },
})
```

相同的濾鏡適用於Tool結果內的影像和檔案。Agent程式記錄為不可用的附件（因為無法再下載）永遠不會發送。看[attachment download failures](/docs/agents/processors#recover-from-attachment-download-failures).

## 成本和延遲 {/* #cost-and-latency */}

每一次觀察和反思都是一次模型呼叫。預設情況下，線程大約每 6,000 個新訊息令牌就會調用一次 Observer 調用，而每當日誌達到 40,000 個令牌時，線程就會調用一次 Reflector。作為回報，每個主Agent呼叫都會讀取最多數萬個令牌的上下文，而不是整個執行緒。觀察前綴很少更改，因此提示快取會繼續工作：使用者通常會看到 OM 的提示快取命中率為 97% 到 99%。

觀察者在後台提前運行（非同步緩衝），因此Agent不會停下來等待它。這些設定控制時間：

|設定|預設 |它控制什麼 |
| - | - | - |
|`observation.bufferTokens` | `0.2` | How often the Observer runs in the background, as a fraction of `messageTokens` (`0.2` is every 6,000 tokens at the default threshold), or an absolute token count such as `5000`. `false` turns buffering off. |
| `observation.bufferActivation` | `0.8` | How much of the message window clears when observations activate. `0.8` keeps 20% of `messageTokens`. Lower values keep more recent messages. |
| `observation.blockAfter` | `1.2` | When the agent waits for a synchronous observation because buffering fell behind, as a multiple of `messageTokens` (`1.2` is 36,000 tokens), or an absolute count of 100 or more. `1` observes synchronously at `messageTokens`. |

若要變更 OM 觀察和反映的時間，請設定閾值：

```typescript
const memory = new Memory({
  options: {
    observationalMemory: {
      observation: {
        messageTokens: 30_000,
      },
      reflection: {
        observationTokens: 40_000,
      },
    },
  },
})
```

### 長時間運行Tool調用 {/* #long-runs-of-tool-calls */}

執行長鏈Tool呼叫的Agent程式（例如編碼和瀏覽器Agent程式）會在每個步驟重新發送相同的不斷增長的前綴，並且提供者從提示快取中提供大部分前綴。對於這些Agent，將觀察閾值提高到遠高於預設值，例如提高到 60,000 到 80,000 個令牌，這樣 OM 壓縮的頻率就會降低，並且每次運行的更多內容都會被快取：

```typescript
const memory = new Memory({
  options: {
    observationalMemory: {
      observation: {
        messageTokens: 70_000,
      },
    },
  },
})
```

將閾值保持在主模型的上下文視窗內。`bufferTokens`, `bufferActivation` and `blockAfter` are fractions of `messageTokens` by default, so they scale with it.

### 提示快取過期時激活 {/* #activate-when-the-prompt-cache-expires */}

一旦提示快取過期，下一個請求無論如何都會為整個上下文支付全額。`activateAfterIdle` makes OM activate its prepared observations when a thread has been idle that long, so the request after a pause sends a smaller, compressed context. It isn't set by default. Set it to `'auto'` to use the active provider's prompt cache TTL (for example 5 minutes for Anthropic, 1 hour for DeepSeek):

```typescript
const memory = new Memory({
  options: {
    observationalMemory: {
      activateAfterIdle: 'auto',
    },
  },
})
```

看[early activation](/reference/memory/observational-memory#early-activation) for fixed durations, per-provider values and activating when the provider changes.

### 同步觀察 {/* #synchronous-observation */}

若要同步觀察，請設定`observation.bufferTokens: false`. That turns off background buffering for both observations and reflections, and the agent pauses while each one runs.

`shareTokenBudget: true`讓訊息歷史借用觀察預算中未使用的部分，因此在觀察開始之前，當日誌較小時，最多會保留約 70,000 個訊息標記。它需要`observation.bufferTokens: false`. See [shared token budget](/reference/memory/observational-memory#shared-token-budget).

## 線程和跨線程內存 {/* #threads-and-cross-thread-memory */}

### 線程範圍（預設） {/* #thread-scope-default */}

每個線程都有自己的觀察。每個呼叫都需要一個線程：沒有線程，OM 會拋出異常`OBSERVATIONAL_MEMORY_THREAD_ID_REQUIRED`, so that unrelated threads never share one observation record.

:::警告
當客戶端應用程式呼叫您的Agent程式時，僅發送新訊息而不是完整的對話。 OM 已經從儲存中載入了線程的歷史記錄。看[message history](/docs/memory/message-history) for how Mastra handles echoed history and when to use `retainFullInput`.
:::

OM 在一個線程中記住。要让Agent到达用户的其他线程，请打开[retrieval mode](#retrieval-mode), which gives it a `recall` tool for the raw messages behind observations and for other threads of the same resource.

### 檢索方式 {/* #retrieval-mode */}

觀察結果刪除了原來的措詞。透過檢索模式，每個觀察組都與其來自的消息保持鏈接，並且Agent會獲得一個`recall` tool to read them back, including exact wording and tool output.

`retrieval: true`讓Agent瀏覽原始訊息、列出資源的執行緒並讀取其他執行緒。不需要向量存儲。

`retrieval: { vector: true }`使用配置的向量存儲和嵌入器在觀察組上添加語義搜索`Memory`. With a vector store that generates embeddings itself, leave the `embedder` out. See [server-side embeddings](/docs/memory/semantic-recall#server-side-embeddings). New observation groups are indexed in the background as they're created.

```typescript
const memory = new Memory({
  storage,
  vector: myVectorStore,
  embedder: myEmbedder,
  options: {
    observationalMemory: {
      retrieval: { vector: true },
    },
  },
})
```

召回Tool的範圍是`'resource'` by default, so it can reach every thread of the resource. Set `retrieval: { scope: 'thread' }` to limit it to the current thread. Use `retrieval.instructions` to add app-specific guidance after the built-in recall instructions, for example "Prefer the current conversation when it already contains the answer."

請參閱[recall tool reference](/reference/memory/observational-memory#recall-tool) for its modes, detail levels and pagination.

### 資源範圍（已棄用） {/* #resource-scope-deprecated */}

:::警告\[已棄用]

`scope: 'resource'`已棄用並將在未來版本中刪除。第一次使用資源範圍建立 OM 時，Mastra 會記錄一則警告。刪除`scope` option to use thread scope, and use [retrieval mode](#retrieval-mode) for cross-thread continuity. [Knowledge](/docs/knowledge/overview), now in alpha, gives agents shared information across threads and is planned to replace resource scope.

:::

資源範圍在資源的所有執行緒之間共用一個觀察記錄。它的工作效果比線程作用域差得多：

* **提示快取**：觀察任何執行緒都會更改每個其他執行緒的上下文，這會破壞其快取的前綴。
* **Agent了解**：每個執行緒都可以看到來自其他執行緒的觀察結果，並且Agent可以繼續另一個執行緒啟動的工作。
* **表現**：來自所有執行緒的未觀察到的訊息會一起處理，這對於具有多個執行緒的使用者來說很慢。資源範圍也會關閉非同步緩衝。

切換到執行緒範圍不會遷移資源範圍的觀察值。每個執行緒都使用自己的執行緒範圍記錄（如果有的話），或開始為空，並且不會再次觀察到在資源範圍下已觀察到的訊息。

## 擷取器 {/* #extractors */}

提取器在觀察的同時保留特定的值。內建當前任務、建議回應和線程標題使用相同的管道。此範例提取一個小的用戶設定檔：

```typescript title="src/mastra/agents/assistant.ts"
import { Agent } from '@mastra/core/agent'
import { Extractor, Memory } from '@mastra/memory'
import { z } from 'zod'

const memory = new Memory({
  options: {
    observationalMemory: {
      observation: {
        extract: [
          new Extractor({
            name: 'User profile',
            instructions: 'Extract stable user profile facts that should be remembered.',
            schema: z.object({
              preferredName: z.string().optional(),
              timezone: z.string().optional(),
              tools: z.array(z.string()).optional(),
            }),
          }),
        ],
      },
    },
  },
})

export const assistant = new Agent({
  id: 'assistant',
  name: 'Assistant',
  instructions: 'You are a helpful assistant.',
  model: '__GATEWAY_OPENAI_MODEL_LUNA__',
  memory,
})
```

帶有一個提取器`schema` runs as a follow-up structured-output request. Without a schema it's an inline string extractor, emitted directly in the Observer or Reflector response:

```typescript
new Extractor({
  name: 'Mood',
  instructions: 'Extract the user mood as a short phrase.',
})
```

預設情況下，提取器會在以後的運行中看到其最後的值。放`includePreviousExtraction: false` to hide it:

```typescript
new Extractor({
  name: 'Latest blocker',
  instructions: 'Extract any blockers the agent is running into.',
  includePreviousExtraction: false,
})
```

`instructions`和`schema` can be functions when they depend on runtime context, such as the memory instance or request context:

```typescript
new Extractor({
  name: 'Workspace summary',
  instructions: ({ memory }) =>
    memory ? 'Extract workspace facts for this memory instance.' : 'Extract workspace facts.',
})
```

使用`onExtracted` to normalize a value before it's persisted:

```typescript
new Extractor({
  name: 'Project status',
  instructions: 'Extract the current project status.',
  schema: z.string(),
  onExtracted: ({ current }) => current.trim().toLowerCase(),
})
```

`onExtracted`還收到`previous` and `sendSignal`, so it can tell the agent when a value changes. The hook runs on every extraction, so compare `previous` with `current` before sending a signal; otherwise each observation sends another one.

失敗的提取器會在 OM 標記中報告，並且不會刪除成功的提取器中的值。請參閱[Extractor API](/reference/memory/observational-memory#extractor-api) for the full shape.

### 從流中讀取提取的值 {/* #read-extracted-values-from-a-stream */}

當 OM 完成觀察或反射時，提取器結果就會到達。從流中讀取兩個完成資料部分：

```typescript title="src/run.ts"
import { assistant } from './mastra/agents/assistant'

const stream = await assistant.stream('Remember that I prefer dark mode.', {
  memory: { resource: 'user-123', thread: 'conversation-123' },
})

for await (const chunk of stream.fullStream) {
  if (chunk.type === 'data-om-observation-end' || chunk.type === 'data-om-buffering-end') {
    const { operationType, extractedValues = {}, extractionFailures = [] } = chunk.data

    for (const [slug, value] of Object.entries(extractedValues)) {
      console.log(`${operationType} extractor ${slug}:`, value)
    }

    for (const failure of extractionFailures) {
      console.error(`Extractor ${failure.slug} failed:`, failure.error)
    }
  }
}
```

`extractedValues`由每個提取器的彈頭鍵控。這兩個欄位都是可選的。

`data-om-observation-end`報告同步完成。`data-om-buffering-end` reports finished background work: its extractor values are persisted at once, but the buffered observations stay inactive until activation. `operationType` says whether the work was an observation or a reflection. See [`data-om-observation-end`](/reference/memory/observational-memory#data-om-observation-end) and [`data-om-buffering-end`](/reference/memory/observational-memory#data-om-buffering-end) for the payloads.
