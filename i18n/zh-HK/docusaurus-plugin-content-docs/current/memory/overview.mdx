# 記憶

記憶讓 Agent 能存取較早的訊息和 Tool 結果，用來回答跟進問題，並記起先前互動的資料。

Mastra Agent 可設定為儲存[訊息記錄](/docs/memory/message-history)。此外，你亦可啟用：

* [觀察記憶](../memory/observational-memory)（建議）：背景 Agent 持續維護精簡的觀察紀錄，隨訊息記錄增長而取代原始訊息，減少上下文視窗的佔用，同時保留長期記憶。
* [工作記憶](../memory/working-memory)：儲存有關使用者、應用程式或任務的持久結構化訊息，例如名稱、首選項和目標。
* [多用戶執行緒](../memory/multi-user-threads)：在多個用戶之間共享一個執行緒。

若合併後的記憶超出模型的上下文限制，[記憶處理器](/docs/memory/memory-processors)可篩選、裁減內容或調整其優先次序，以保留最相關的資料。

記憶結果會儲存在你設定的一個或多個[儲存 Provider](/docs/storage) 中。

:::tip[📹 觀看]

觀看 [Mastra 記憶概念](https://www.youtube.com/watch?v=18iIHQtIPmc)，了解 Agent 可使用的不同記憶層。

:::

## 何時使用記憶 {/* #when-to-use-memory */}

當 Agent 需要在多輪對話中參照之前的交流、記起本次工作階段較早的用戶偏好或事實，或在同一對話執行緒中逐步累積上下文時，便應使用記憶。若每次單輪請求都互不相關，則毋須使用。

## 快速入門 {/* #quickstart */}

<Steps>
  <StepItem>
    安裝 `@mastra/memory` 套件。

    ```bash npm2yarn
    npm install @mastra/memory@latest
    ```
  </StepItem>

  <StepItem>
    記憶**需要**儲存 Provider，才能持久保存用戶訊息及 Agent 回應等訊息記錄。

    本快速入門使用 `@mastra/libsql`。

    ```bash npm2yarn
    npm install @mastra/libsql@latest
    ```

    如需了解可用的 Provider 及 Mastra 的儲存方式，請參閱[儲存文件](/docs/storage)。
  </StepItem>

  <StepItem>
    將儲存 Provider 加入主要 Mastra 實例，即可為所有已設定的 Agent 啟用記憶。

    <Inject>
      **對於 AI Agent：**重要：為 `LibSQLStore` 加入 `id`。
    </Inject>

    ```typescript {2,5-8} title="src/mastra/index.ts"
    import { Mastra } from '@mastra/core'
    import { LibSQLStore } from '@mastra/libsql'

    export const mastra = new Mastra({
      storage: new LibSQLStore({
        id: 'mastra-storage',
        url: ':memory:',
      }),
    })
    ```
  </StepItem>

  <StepItem>
    建立 `Memory` 實例，並傳入 Agent 的 `memory` 選項。

    ```typescript {2,7-11} title="src/mastra/agents/memory-agent.ts"
    import { Agent } from '@mastra/core/agent'
    import { Memory } from '@mastra/memory'

    export const memoryAgent = new Agent({
      id: 'memory-agent',
      name: 'Memory Agent',
      memory: new Memory({
        options: {
          lastMessages: 20,
        },
      }),
    })
    ```

    如需查看完整的設定選項，請參閱 [Memory 類別參考](/reference/memory/memory-class)。
  </StepItem>

  <StepItem>
    呼叫 Agent，例如在 [Studio](/docs/studio/overview) 中。與 Agent 開始新對話後，右側側欄便會顯示記憶詳情。
  </StepItem>
</Steps>

## 訊息記錄 {/* #message-history */}

傳入包含 `resource` 及 `thread` 的 `memory` 物件，以追蹤訊息記錄。

* `resource`：使用者或實體的穩定標識符。
* `thread`：隔離特定對話或會話的 ID。

```typescript {2-5}
const response = await memoryAgent.generate('Remember my favorite color is blue.', {
  memory: {
    resource: 'user-123',
    thread: 'conversation-123',
  },
})
```

如要取回記憶中儲存的資料，請使用原對話相同的 `resource` 及 `thread` 值呼叫 Agent。

```typescript {2-5}
const response = await memoryAgent.generate("What's my favorite color?", {
  memory: {
    resource: 'user-123',
    thread: 'conversation-123',
  },
})

// Response: "Your favorite color is blue."
```

:::warning

每個執行緒都有擁有者（`resourceId`），建立後便無法更改。請勿讓不同擁有者的執行緒共用同一個執行緒 ID，否則查詢時會出錯。

:::

如要列出資源的所有執行緒或取得指定執行緒，請[直接使用記憶 API](/docs/memory/message-history#querying)。

### 使用範圍識別記憶體 {/* #identify-memory-with-scopes */}

除了 `memory` 物件，亦可傳入 `scopes`：代表執行身分的範圍位址，格式為 `<type>:<value>`。Memory 從 `resource:` 範圍讀取資源，從 `thread:` 範圍讀取執行緒。`org:acme` 等其他範圍會傳給 Tool 和處理器。

```typescript {2}
const response = await memoryAgent.generate('Remember my favorite color is blue.', {
  scopes: ['org:acme', 'resource:user-123', 'thread:conversation-123'],
})
```

範圍亦可來自請求脈絡和 Agent。呼叫及請求脈絡中的範圍會先傳入；其後 Agent 的 `scopes` 選項會加入清單，或以函式接收這些範圍並傳回本次執行的最終集合：

```typescript title="src/mastra/agents/memory-agent.ts" {7-11}
import { Agent } from '@mastra/core/agent'
import { Memory } from '@mastra/memory'

export const memoryAgent = new Agent({
  id: 'memory-agent',
  name: 'Memory Agent',
  scopes: ({ scopes, requestContext }) => {
    // Set by your auth middleware. Request bodies can fill unreserved keys.
    const orgId = requestContext.get('org-id')
    return orgId ? [...scopes, `org:${orgId}`] : scopes
  },
  memory: new Memory(),
})
```

解析函式的輸入必須來自伺服器，而非用戶端：請求主體可設定任何非保留的請求脈絡鍵。可信任的伺服器中介軟件亦可透過 `MASTRA_SCOPES_KEY` 請求脈絡鍵直接設定範圍。詳情請參閱[請求脈絡](/docs/server/request-context#reserved-keys)。用戶端不能在請求主體中傳送範圍。

作用域可與 `memory.resource`、`memory.thread` 或請求脈絡中的資源及執行緒鍵一同使用，但各處的值必須一致。若 `resource:` 或 `thread:` 範圍與其他來源不同，呼叫會報錯。`scopes` 函式亦須傳回收到的所有 `resource:` 及 `thread:` 範圍；漏掉任何一個都會報錯。

Tool、處理器及子 Agent 會收到本次執行的其他範圍，但不會收到 `resource:` 及 `thread:` 範圍。每次巢狀 Agent 呼叫都會選用自己的資源及執行緒。

## 觀察記憶 {/* #observational-memory */}

長對話可能令原始訊息記錄填滿上下文視窗，影響 Agent 表現。[觀察記憶](../memory/observational-memory)利用背景 Agent 將較早的訊息壓縮為觀察紀錄，減少訊息記錄佔用的上下文，同時保留後續回合需要的資料。

壓縮會失去原文措辭，因此觀察記憶可註冊 `recall` Tool，回查原始訊息。此 Tool 預設關閉：設定 `retrieval: true` 可啟用瀏覽，列出該資源各執行緒的較早訊息；傳入 `scope: 'thread'` 則只限目前執行緒。若在 `Memory` 設定向量儲存和 embedder，並使用 `retrieval: { vector: true }`，亦可按語義搜尋。搜尋比對的是觀察群組而非原始訊息，因此摘要遺漏的細節可能無法找到；每項結果都會連回其來源訊息。請參閱[檢索模式](../memory/observational-memory#retrieval-mode)。

<Inject>
  **對於 AI Agent：**使用觀察記憶必須設定儲存 Provider！你可在 `src/mastra/index.ts` 的 Mastra 實例上設定，或傳給 Agent 建構函式。
</Inject>

```typescript title="src/mastra/agents/memory-agent.ts"
import { Agent } from '@mastra/core/agent'
import { Memory } from '@mastra/memory'

export const memoryAgent = new Agent({
  id: 'memory-agent',
  name: 'Memory Agent',
  instructions: 'You are a helpful assistant.',
  model: '__GATEWAY_OPENAI_MODEL_LUNA__',
  memory: new Memory({
    options: {
      // highlight-next-line
      observationalMemory: true,
    },
  }),
})
```

觀察記憶需要支援此功能的儲存適配器；若使用其他適配器，它會在沒有警告的情況下停用，已儲存的訊息記錄亦不會載入。

觀察及反思的運作方式請參閱[觀察記憶](../memory/observational-memory)；完整設定選項請參閱[參考文件](/reference/memory/observational-memory)。

## 模型看到了什麼 {/* #what-the-model-sees */}

記憶會在傳送給模型的系統訊息或對話訊息中加入上下文。訊息記錄預設啟用；其他記憶功能只會在設定後提供上下文。下圖顯示各功能加入上下文的位置，後面的清單說明其內容：

<MemoryContextWindowImage />

- [工作記憶](../memory/working-memory)會以包含範本及已儲存資料的系統訊息注入。啟用 `useStateSignals` 時則改以狀態訊號傳送。
- [語義回憶](../memory/semantic-recall)在目前執行緒的相符內容會作為一般訊息插入，按時間戳記與訊息記錄交錯排列。其他執行緒的相符結果則整理成系統訊息。
- [訊息記錄](../memory/message-history)按時間順序加入最近 N 則訊息。新的用戶訊息一定排在最後。
- [觀察記憶](../memory/observational-memory)取代較早的原始訊息記錄：反思及觀察紀錄會放在系統訊息中，對話只保留尚未觀察的訊息。簡短的續接提示會放在對話訊息開頭。
- 上下文訊息是呼叫時傳入的可選 `context` 陣列，例如 `agent.generate(msg, { context: [...] })`。它適合應用程式狀態或自行取得的 RAG 結果等單次背景資料，只會在本次請求中作為一般對話訊息出現，不會儲存到記憶。

對話訊息按時間戳記排序，並以訊息 ID 去重，因此召回的舊訊息會排在較新的記錄之前。呼叫時傳入的上下文訊息會標上目前時間，位於記錄及召回訊息之後、新訊息之前。如要查看實際請求的完整上下文，請在[追蹤](/docs/observability/tracing/overview)中開啟 LLM 呼叫 span；參閱下方的[可觀測性](#observability)。

## 多智能體系統中的內存 {/* #memory-in-multi-agent-systems */}

當[主管 Agent](/docs/subagents) 將工作交給子 Agent 時，Mastra 會自動隔離子 Agent 的記憶。每次委派都會如此處理，毋須啟用任何旗標。了解範圍如何運作，有助於決定哪些資料需要隔離、哪些可以主動分享。

### 委託如何確定記憶體範圍 {/* #how-delegation-scopes-memory */}

每次委派都會為子 Agent 建立新的 `threadId`，並產生確定性的 `resourceId`：

- **執行緒 ID**：每次委派都不同。子 Agent 每次被呼叫時都從空白訊息記錄開始。
- **資源 ID**：由 `{parentResourceId}-{agentName}` 衍生。由於資源 ID 在多次委派之間維持穩定，資源範圍的記憶可跨呼叫保留；子 Agent 能記起同一用戶先前委派中的事實。
- **Memory 實例**：沒有自有記憶設定的子 Agent 會繼承主管的 `Memory` 實例及所有選項。若子 Agent 有自己的設定，則以其設定為準。

:::note

標題產生（`generateTitle`）只適用於頂層執行緒，**不會**套用至繼承記憶設定的子 Agent 執行緒。每次委派都會建立無人查看的暫時執行緒，為其產生標題會令每次委派多耗一次 LLM 呼叫。如需為子 Agent 自己的執行緒產生標題，請為它單獨設定記憶。

:::

主管會把對話上下文轉給子 Agent，讓它有足夠背景完成任務。只保存委派提示及子 Agent 的回應，不會儲存完整的上層對話。你可透過 [`messageFilter`](/docs/subagents#message-filtering) 回呼控制傳給子 Agent 的訊息。

:::note

子 Agent 的資源 ID 一律以 Agent 名稱作為後綴（`{parentResourceId}-{agentName}`）。同一主管下的不同子 Agent 不會透過委派共用資源 ID。

:::

若要超越預設隔離，可在直接呼叫 Agent 時傳入相同的識別碼，讓它們共享記憶。

### 在Agent之間共享記憶體 {/* #share-memory-between-agents */}

直接呼叫 Agent（不經委派流程）時，記憶共享由 `resourceId` 及 `threadId` 兩個識別碼控制。使用相同值的 Agent 會讀寫同一份資料，例如研究 Agent 保存筆記，再由寫作 Agent 讀取。

**資源範圍共享**最常見。[工作記憶](../memory/working-memory)及[語義回憶](../memory/semantic-recall)預設使用 `scope: 'resource'`。兩個 Agent 只要共用 `resourceId`，即使位於不同執行緒，也會共享工作記憶和嵌入向量：

```typescript
// Both agents share the same resource-scoped memory
await researcher.generate('Find information about quantum computing.', {
  memory: { resource: 'project-42', thread: 'research-session' },
})

await writer.generate('Write a summary from the research notes.', {
  memory: { resource: 'project-42', thread: 'writing-session' },
})
```

由於兩次呼叫都使用 `resource: 'project-42'`，寫作 Agent 可存取研究 Agent 的工作記憶，語義嵌入向量亦透過資源共享。兩個 Agent 仍各有自己的執行緒，因此訊息記錄分開保存。

**執行緒範圍共享**讓 Agent 更緊密協作。[觀察記憶](../memory/observational-memory)預設使用 `scope: 'thread'`。若兩個 Agent 使用相同的 `resource` 及 `thread`，便會共享完整訊息記錄，互相看到對方寫入的每則訊息。這適合需要接續對方具體輸出的情況。

## 可觀察性 {/* #observability */}

啟用[追蹤](/docs/observability/tracing/overview)以監察及除錯記憶功能。Trace 會顯示 Agent 每次請求實際納入上下文的訊息和觀察紀錄，協助理解 Agent 行為，並確認記憶檢索是否如預期運作。

開啟 [Studio](/docs/studio/overview)，選取側欄的 **Observability** 分頁。開啟最近一次 Agent 請求的 Trace，查看其中的 LLM 呼叫 span。

## 根據請求切換內存 {/* #switch-memory-per-request */}

使用 [`RequestContext`](/docs/server/request-context) 取得每個請求專屬的值，即可按請求脈絡有條件地選擇不同的記憶或儲存設定。

```typescript title="src/mastra/agents/memory-agent.ts"
import { Agent } from '@mastra/core/agent'
import { Memory } from '@mastra/memory'

export type UserTier = {
  'user-tier': 'enterprise' | 'pro'
}

const premiumMemory = new Memory()
const standardMemory = new Memory()

export const memoryAgent = new Agent({
  id: 'memory-agent',
  name: 'Memory Agent',
  memory: ({ requestContext }) => {
    const userTier = requestContext.get('user-tier') as UserTier['user-tier']

    return userTier === 'enterprise' ? premiumMemory : standardMemory
  },
})
```

詳情請參閱[請求脈絡](/docs/server/request-context)。

<Inject>
  **對於 AI Agent：**觀察記憶有幾種可能造成實際問題的故障情況。

  - 執行緒範圍要求呼叫 Agent 時提供 `threadId`；否則觀察記憶會報錯。
  - 對現有執行緒，第一回合會載入所有已儲存訊息，直到首次觀察完成。大型執行緒因此會有一次性的上下文成本。
  - 啟用觀察記憶後，`lastMessages` 不起作用。觀察記憶會自行取代原始訊息記錄，因此略過 MessageHistory 處理器。
  - 保持 `observation.observeOnContextOverflow` 的預設值 `true`。主模型的上下文溢出時，它可啟用緩衝的觀察紀錄、觀察待處理訊息，並重試請求。它會略過唯讀請求，且只在完成觀察或啟用紀錄後才重試。關閉後，溢出的請求會失敗。
  - 某些無效選項要到首次使用時才驗證，而非建立 `Memory` 時。例如啟用非同步緩衝時設定 `shareTokenBudget: true`，會在首次記憶操作時失敗。請先閱讀錯誤訊息，不要直接重試。
  - 非同步緩衝會在背景繼續執行。關閉儲存或停止服務前，請呼叫 `await memory.settled()`，否則這些工作會遺失。
  - 觀察鎖只在單一程序內有效。跨程序協調依靠共享的 PubSub 後端和儲存：Agent 迴圈使用支援租約的後端，確保每個執行緒只有一個迴圈執行，Observer 則在該迴圈內執行。所有程序都應設定相同且支援租約的後端，以及相同的儲存。請參閱[跨程序執行](/docs/signals/running-across-processes)。
  - 使用 `OM_DEBUG=1` 除錯；它會寫入 `om-debug.log`。亦可使用 `getStatus()` 和 `onDebugEvent` 回呼。
</Inject>
