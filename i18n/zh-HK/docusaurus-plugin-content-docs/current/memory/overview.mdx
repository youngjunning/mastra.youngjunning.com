# 記憶

記憶體使您的Agent可以存取早期的消息和Tool結果。Agent可以使用此上下文來回答後續問題並回憶先前互動中的信息。

MastraAgent可以配置為存儲[message history](/docs/memory/message-history). Additionally, you can enable:

* [觀察記憶](../memory/observational-memory)
* [工作記憶](../memory/working-memory)：儲存有關使用者、應用程式或任務的持久結構化訊息，例如名稱、首選項和目標。
* [多用戶執行緒](../memory/multi-user-threads)：在多個用戶之間共享一個執行緒。

如果組合記憶體超出模型的上下文限制，[memory processors](/docs/memory/memory-processors) can filter, trim, or prioritize content so the most relevant information is preserved.

記憶體結果將儲存在您配置的一個或多個[storage providers](/docs/storage).

:::提示\[📹觀看]

手錶[Mastra memory concepts](https://www.youtube.com/watch?v=18iIHQtIPmc) for a conceptual overview of the memory layers agents can use.

:::

## 何時使用記憶體 {/* #when-to-use-memory */}

當您的Agent需要維護引用先前交換的多輪對話或回憶會話早期的用戶偏好或事實，或隨著時間的推移在對話線程中建立上下文時，請使用記憶體。跳過單輪請求的內存，其中每個交互都是獨立的。

## 訊息記錄 {/* #message-history */}

透過一個`memory` object with `resource` and `thread` to track message history.

* `resource`：使用者或實體的穩定標識符。
* `thread`：隔離特定對話或會話的 ID。

```typescript {2-5}
const response = await memoryAgent.generate('Remember my favorite color is blue.', {
  memory: {
    resource: 'user-123',
    thread: 'conversation-123',
  },
})
```

要調用儲存在記憶體中的信息，請使用相同的信息致電客服人員`resource` and `thread` values used in the original conversation.

```typescript {2-5}
const response = await memoryAgent.generate("What's my favorite color?", {
  memory: {
    resource: 'user-123',
    thread: 'conversation-123',
  },
})

// Response: "Your favorite color is blue."
```

：：：警告

每個線程都有一個所有者（`resourceId`) that can't be changed after creation. Avoid reusing the same thread ID for threads with different owners, as this will cause errors when querying.

:::

要列出資源的所有線程，或檢索特定線程，[use the memory API directly](/docs/memory/message-history#querying).

### 使用範圍識別記憶體 {/* #identify-memory-with-scopes */}

而不是一個`memory` object, you can pass `scopes`: the addresses a run acts as, written as `<type>:<value>`. Memory reads the resource from a `resource:` scope and the thread from a `thread:` scope. Other scopes, such as `org:acme`, are passed to tools and processors.

```typescript {2}
const response = await memoryAgent.generate('Remember my favorite color is blue.', {
  scopes: ['org:acme', 'resource:user-123', 'thread:conversation-123'],
})
```

範圍也可以來自請求上下文和Agent。呼叫範圍和請求上下文首先到達。Agent的`scopes` option then adds a list to them, or a function receives them and returns the run's final set:

```typescript title="src/mastra/agents/memory-agent.ts" {7-11}
import { Agent } from '@mastra/core/agent'
import { Memory } from '@mastra/memory'

export const memoryAgent = new Agent({
  id: 'memory-agent',
  name: 'Memory Agent',
  scopes: ({ scopes, requestContext }) => {
    // Set by your auth middleware. Request bodies can fill unreserved keys.
    const orgId = requestContext.get('org-id')
    return orgId ? [...scopes, `org:${orgId}`] : scopes
  },
  memory: new Memory(),
})
```

解析器的輸入必須來自伺服器，而不是客戶端：請求正文可以設定任何未保留的請求上下文鍵。受信任的伺服器中間件還可以直接使用`MASTRA_SCOPES_KEY` request context key. Visit [Request Context](/docs/server/request-context#reserved-keys) for details. Clients can't send scopes in a request body.

您可以將範圍與`memory.resource`, `memory.thread`, or the resource and thread request context keys, as long as they agree. If a `resource:` or `thread:` scope names a different value than another source, the call throws an error. A `scopes` function must also return every `resource:` and `thread:` scope it receives. Dropping one throws an error.

Tool、處理器和子Agent程式接收運行的其他範圍，但不接收其範圍`resource:` and `thread:` scopes. Each nested agent call picks its own resource and thread.

## 觀察記憶 {/* #observational-memory */}

長對話可能會用原始訊息歷史記錄填充上下文視窗並降低Agent效能。[Observational Memory](../memory/observational-memory) uses background agents to compress older messages into observations. This reduces the context used by message history while retaining information for later turns.

壓縮會失去精確的措辭，因此觀察記憶可以註冊一個`recall` tool that goes back to the original messages. The tool is off by default: set `retrieval: true` to enable browsing, which lists earlier messages across the resource's threads unless you pass `scope: 'thread'`. With `retrieval: { vector: true }` plus a vector store and embedder on `Memory`, it can also search by meaning. That search matches observation groups rather than raw messages, so a detail the summary dropped may not turn up, and each hit links back to the messages it came from. See [retrieval mode](../memory/observational-memory#retrieval-mode).

<Inject>
  **對於人工智慧Agent：**&#x4F7F;用觀察記憶需要儲存提供者！您需要在 Mastra 實例上將其設定為`src/mastra/index.ts` or pass it to the Agent constructor.
</Inject>

```typescript title="src/mastra/agents/memory-agent.ts"
import { Agent } from '@mastra/core/agent'
import { Memory } from '@mastra/memory'

export const memoryAgent = new Agent({
  id: 'memory-agent',
  name: 'Memory Agent',
  instructions: 'You are a helpful assistant.',
  model: '__GATEWAY_OPENAI_MODEL_LUNA__',
  memory: new Memory({
    options: {
      // highlight-next-line
      observationalMemory: true,
    },
  }),
})
```

觀察記憶需要一個支援它的儲存適配器，如果使用任何其他適配器，它會在沒有警告的情況下關閉，並且不會載入儲存的歷史記錄。

看[Observational Memory](../memory/observational-memory) for details on how observations and reflections work, and [the reference](/reference/memory/observational-memory) for all configuration options.

## 模型看到了什麼 {/* #what-the-model-sees */}

記憶體將上下文添加到發送到模型的系統訊息或對話訊息中。預設啟用訊息歷史記錄。其他記憶體功能僅在配置時才提供上下文。該圖顯示了每個功能添加其上下文的位置，下面的列表解釋了它的貢獻：

<MemoryContextWindowImage />

* [工作記憶](../memory/working-memory)作為包含模板和儲存資料的系統訊息注入。和`useStateSignals`, it's delivered as a state signal instead.
* [語意回憶](../memory/semantic-recall)當前線程中的匹配項將作為常規訊息插入，並按時間戳與訊息歷史記錄交錯。來自其他執行緒的匹配會被格式化為系統訊息。
* [訊息記錄](../memory/message-history)按時間順序新增最後 N 則訊息。您的新訊息總是最後出現。
* [觀察記憶](../memory/observational-memory)取代舊的原始歷史記錄：反思和觀察存在於系統訊息中，只有尚未觀察到的訊息才會保留在對話中。在對話訊息的開頭放置一個簡短的繼續提醒。
* 上下文訊息是可選的`context` array passed on a call, for example `agent.generate(msg, { context: [...] })`. Use them for one-off background such as app state or your own RAG results. They appear as regular conversation messages for that request only and are never saved to memory.

對話訊息按時間戳排序，並按訊息 ID 進行重複資料刪除，因此調用的較舊訊息會出現在最近歷史記錄之前。在呼叫時傳遞的上下文訊息會標有當前時間，這將它們放置在歷史記錄和調用之後但在新訊息之前。若要檢查真實請求的確切上下文，請使用[Tracing](/docs/observability/tracing/overview) and open the LLM call spans, see [Observability](#observability) below.

## 多智能體系統中的內存 {/* #memory-in-multi-agent-systems */}

當一個[supervisor agent](/docs/subagents) delegates to a subagent, Mastra isolates subagent memory automatically. No flag enables this as it happens on every delegation. Understanding how this scoping works lets you decide what stays private and what to share intentionally.

### 委託如何確定記憶體範圍 {/* #how-delegation-scopes-memory */}

每個代表團都創造了一個新的`threadId` and a deterministic `resourceId` for the subagent:

* **線程ID**：每個代表團都是唯一的。每次呼叫子Agent時都會以乾淨的訊息歷史記錄開始。
* **資源ID**: 推導為`{parentResourceId}-{agentName}`. Because the resource ID is stable across delegations, resource-scoped memory persists between calls. A subagent remembers facts from previous delegations by the same user.
* **記憶體實例**：沒有自己記憶的子Agent繼承了主管的記憶`Memory` instance and all configured options. If the subagent defines its own, that takes precedence.

：：：筆記

標題生成（`generateTitle`) is a top-level thread concern and **isn't** applied to inherited subagent threads. Because each delegation creates an ephemeral thread that no one sees, running title generation for it would waste an LLM call per delegation. To generate titles for a subagent's own threads, give that subagent its own memory configuration.

:::

主管將其對話上下文轉發給子Agent，以便它有足夠的背景來完成任務。僅保存委託提示和子Agent程式的回應。不儲存完整的家長對話。您可以使用以下命令控制哪些訊息到達子Agent[`messageFilter`](/docs/subagents#message-filtering) callback.

：：：筆記

子Agent資源 ID 始終以Agent名稱作為後綴 (`{parentResourceId}-{agentName}`). Different subagents under the same supervisor never share a resource ID through delegation.

:::

為了超越這種預設隔離，您可以在直接呼叫Agent時透過傳遞匹配標識符來在Agent之間共享記憶體。

### 在Agent之間共享記憶體 {/* #share-memory-between-agents */}

當您直接呼叫Agent程式（在委託流程之外）時，記憶體共享由兩個識別碼控制：`resourceId` and `threadId`. Agents that use the same values read and write to the same data. This is useful when agents collaborate on a shared context, for example, a researcher that saves notes and a writer that reads them.

**資源範圍共享**是最常見的模式。[Working memory](../memory/working-memory) and [semantic recall](../memory/semantic-recall) default to `scope: 'resource'`. If two agents share a `resourceId`, they share working memory and embeddings, even across different threads:

```typescript
// Both agents share the same resource-scoped memory
await researcher.generate('Find information about quantum computing.', {
  memory: { resource: 'project-42', thread: 'research-session' },
})

await writer.generate('Write a summary from the research notes.', {
  memory: { resource: 'project-42', thread: 'writing-session' },
})
```

因為兩個調用都使用`resource: 'project-42'`, the writer can access the researcher's working memory. Semantic embeddings are also shared through the resource. Each agent still has its own thread, so message histories stay separate.

**線程範圍的共享**提供更緊密的耦合。[Observational Memory](../memory/observational-memory) uses `scope: 'thread'` by default. If two agents use the same `resource` and `thread`, they share the full message history. Each agent sees every message the other has written. This is useful when agents need to build on each other's exact outputs.

## 可觀察性 {/* #observability */}

使能夠[Tracing](/docs/observability/tracing/overview) to monitor and debug memory in action. Traces show you exactly which messages and observations the agent included in its context for each request, helping you understand agent behavior and verify that memory retrieval is working as expected.

打開[Studio](/docs/studio/overview) and select the **Observability** tab in the sidebar. Open the trace of a recent agent request and look for its LLM call spans.

## 根據請求切換內存 {/* #switch-memory-per-request */}

使用[`RequestContext`](/docs/server/request-context) to access request-specific values. This lets you conditionally select different memory or storage configurations based on the context of the request.

```typescript title="src/mastra/agents/memory-agent.ts"
import { Agent } from '@mastra/core/agent'
import { Memory } from '@mastra/memory'

export type UserTier = {
  'user-tier': 'enterprise' | 'pro'
}

const premiumMemory = new Memory()
const standardMemory = new Memory()

export const memoryAgent = new Agent({
  id: 'memory-agent',
  name: 'Memory Agent',
  memory: ({ requestContext }) => {
    const userTier = requestContext.get('user-tier') as UserTier['user-tier']

    return userTier === 'enterprise' ? premiumMemory : standardMemory
  },
})
```

訪問[Request Context](/docs/server/request-context) for more information.

<Inject>
  **對於人工智慧Agent：**&#x89C0;察記憶有一些會導致實際問題的故障模式。

  * 線程作用域需要一個`threadId` when you call the agent. Without one, Observational Memory throws.
  * 在現有線程上，第一輪加載每個存儲的訊息，直到第一個觀察完成。大線程會付出一次性上下文成本。
  * `lastMessages`在觀察記憶下不執行任何操作。它取代了原始歷史記錄本身，因此跳過了 MessageHistory 處理器。
  * 離開`observation.observeOnContextOverflow` at its default `true`. When the main model's context overflows, it can activate buffered observations, observe pending messages, and retry the request. It skips read-only requests and only retries when it observed or activated something. With it off, the overflowing request fails.
  * 一些無效選項在第一次使用時驗證，而不是在建置時驗證`Memory`. For example, `shareTokenBudget: true` with async buffering enabled fails on the first memory operation. Read the error instead of retrying.
  * 透過非同步緩衝，工作在後台繼續進行。稱呼`await memory.settled()` before closing storage or shutting down, or that work is lost.
  * 觀察互斥鎖僅在一個進程內運作。跨進程，協調來自共享的 PubSub 後端和儲存：Agent循環使用帶有租約的後端來為每個執行緒運行一個循環，而觀察者在該循環內運行。使用具有租約和相同儲存的相同後端配置每個進程。看[Running across processes](/docs/signals/running-across-processes).
  * 偵錯用`OM_DEBUG=1`, which writes `om-debug.log`, plus `getStatus()` and the `onDebugEvent` callback.
</Inject>
