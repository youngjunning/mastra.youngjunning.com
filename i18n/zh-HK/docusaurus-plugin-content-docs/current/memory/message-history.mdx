# 訊息紀錄

訊息紀錄是最基本亦最重要的記憶形式。它讓 LLM 在上下文窗口中看到近期訊息，使 Agent 可以參照較早的對話，連貫地回應。

你亦可擷取訊息紀錄，在介面顯示以往的對話。

:::note
每則訊息都屬於一個執行緒（即一段對話）及一個資源（相關用戶或其他實體）。詳見[執行緒與資源](#threads-and-resources)。
:::

## 執行緒與資源 {/* #threads-and-resources */}

Mastra 以兩個標識組織對話：

- **執行緒**：包含一連串訊息的對話工作階段。
- **資源**：擁有執行緒的實體，例如用戶、機構、項目，或應用程式中的其他業務實體。

Studio 會自動產生執行緒及資源 ID。自行呼叫 `stream()` 或 `generate()` 時，請明確提供這兩個標識。

## 開始使用 {/* #getting-started */}

安裝 Mastra 記憶模組及資料庫適用的[儲存適配器](/docs/storage#supported-providers)。以下例子使用 `@mastra/libsql`，把資料存於本機 `mastra.db` 檔案。

```bash npm2yarn
npm install @mastra/memory@latest @mastra/libsql@latest
```

訊息紀錄需要儲存適配器持久保存對話。如尚未設定，請在 Mastra 實例設定儲存空間：

```typescript title="src/mastra/index.ts"
import { Mastra } from '@mastra/core'
import { LibSQLStore } from '@mastra/libsql'

export const mastra = new Mastra({
  storage: new LibSQLStore({
    id: 'mastra-storage',
    url: 'file:./mastra.db',
  }),
})
```

在 Agent 中建立 [`Memory`](/reference/memory/memory-class) 實例：

```typescript title="src/mastra/agents/test-agent.ts"
import { Memory } from '@mastra/memory'
import { Agent } from '@mastra/core/agent'

export const agent = new Agent({
  id: 'test-agent',
  memory: new Memory({
    options: {
      lastMessages: 10,
    },
  }),
})
```

呼叫 Agent 時，訊息會自動存入資料庫。你可指定 `threadId`、`resourceId` 及可選的 `metadata`：

<Tabs>
  <TabItem value="generate" label=".generate()">
    ```typescript
    await agent.generate('Hello', {
      memory: {
        thread: {
          id: 'thread-123',
          title: 'Support conversation',
          metadata: { category: 'billing' },
        },
        resource: 'user-456',
      },
    })
    ```
  </TabItem>

  <TabItem value="stream" label=".stream()">
    ```typescript
    await agent.stream('Hello', {
      memory: {
        thread: {
          id: 'thread-123',
          title: 'Support conversation',
          metadata: { category: 'billing' },
        },
        resource: 'user-456',
      },
    })
    ```
  </TabItem>
</Tabs>

:::note

呼叫 `agent.generate()` 或 `agent.stream()` 時，系統會自動建立執行緒和訊息；亦可透過 [`createThread()`](/reference/memory/createThread) 及 [`saveMessages()`](/reference/memory/memory-class) 手動建立。

:::

訊息紀錄有兩種用法：

- **自動加入上下文**：Mastra 自動把近期訊息放入上下文窗口。預設保留 10 則訊息，讓 Agent 掌握對話脈絡；需要時可用 `lastMessages` 調整。
- [**手動查詢**](#querying)：使用 `recall()` 直接查詢執行緒及訊息，更精確地決定哪些記憶進入上下文窗口，或在介面展示對話紀錄。

:::note

`lastMessages` 會計入所有已儲存訊息，包括 Tool 呼叫、Tool 結果及各種[訊號](/docs/signals/sending-signals)，因此一個對話回合可能增加多則訊息。窗口亦會隨每次請求向前移動：執行緒超出上限後，最早的訊息每回合都會離開上下文，改變提示的開頭，使 Provider 提示快取失效。長對話可使用能保持提示前綴穩定的 [Observational Memory](/docs/memory/observational-memory)。

:::

### 從用戶端傳送訊息 {/* #sending-messages-from-a-client */}

在用戶端應用程式使用記憶時，**只傳送新訊息**，毋須傳入整段對話紀錄。Mastra 會從儲存空間載入較早的訊息。

AI SDK 例子請參閱[使用 Mastra Memory](/integrations/agentic-ui/ai-sdk-ui#using-mastra-memory)。

<details>
  <summary>傳入完整輸入紀錄</summary>

  Mastra 載入已儲存訊息前，會過濾用戶端回傳的歷史。訊息 ID 相符時，它會以已儲存副本為基礎，保留時間戳記及 Provider 中繼資料，同時保留新的 Tool 結果。

  如自行組合請求輸入，且需完全依照所傳內容處理，可在該次呼叫的 `memory.options` 設定 `retainFullInput: true`，或在記憶建構選項設定，使整個 Agent 都套用。這會停用輸入過濾，但仍會載入已儲存歷史。尚未儲存的每則輸入訊息都會存入執行緒，包括少樣本例子。
</details>

### 按 token 數量限制歷史 {/* #limit-history-by-tokens */}

訊息數量不能準確反映上下文大小：一項 Tool 結果可能只有幾個 token，亦可能有數千個。可用 `messageHistory` 把近期歷史限制在 token 預算內：

```typescript title="src/mastra/agents/test-agent.ts"
import { Agent } from '@mastra/core/agent'
import { Memory } from '@mastra/memory'

export const agent = new Agent({
  id: 'test-agent',
  memory: new Memory({
    options: {
      messageHistory: { maxTokens: 8_000, atMaxRemoveTokens: 2_000 },
    },
  }),
})
```

Mastra 以完整提示計算 `maxTokens`，包括記憶中的歷史、系統指令、上下文及目前回合。超出預算時，Mastra 會移除最早的記憶訊息，直至提示不超過 `maxTokens - atMaxRemoveTokens`。`atMaxRemoveTokens` 預設為 `maxTokens` 的 25%。分批移除歷史能讓提示前綴在數個回合內保持穩定，有助 Provider 提示快取繼續生效。

系統訊息、上下文、目前回合的輸入及 Agent 回應不會被刪減。相關的 Tool 呼叫與結果會一併移除。如這些受保護內容本身超過 `maxTokens`，Mastra 會移除所有記憶歷史，但仍保留受保護內容。

已刪減的訊息仍保存在儲存空間。Agent 執行時，Mastra 會為每個執行緒持久保存一個邊界，讓這些訊息不再進入後續回合。只設定 `messageHistory` 而不設定 `lastMessages`，會停用預設的 10 則訊息上限；兩者都設定，可同時限制數量及 token 數。把 `maxTokens` 設為 `0` 可停用訊息紀錄。

:::tip

啟用記憶後，[Studio](/docs/studio/overview) 會利用訊息紀錄，在聊天側邊欄顯示以往對話。

:::

## 產生執行緒標題 {/* #thread-title-generation */}

啟用 `generateTitle` 後，Mastra 可按對話記錄自動產生具描述性的執行緒標題。建立執行緒清單或側邊欄顯示標題的聊天介面時，可使用此選項。

```typescript title="src/mastra/agents/support-agent.ts"
import { Agent } from '@mastra/core/agent'
import { Memory } from '@mastra/memory'

export const supportAgent = new Agent({
  id: 'support-agent',
  name: 'Support agent',
  instructions: 'Answer customer support questions.',
  model: '__GATEWAY_OPENAI_MODEL__',
  memory: new Memory({
    options: {
      generateTitle: true,
    },
  }),
})
```

Agent 回應後才會非同步產生標題，不影響回應時間。

### 在串流中傳送產生的標題 {/* #streaming-the-generated-title */}

標題預設在背景產生，執行串流不會等待，所以 HTTP 用戶端要到下次擷取執行緒時才能看到標題。設定 `emitEvent: true`，可改由本次執行串流傳送：串流會等待標題，並在 `finish` 前發出暫時性的 `data-thread-title` 區塊。

```typescript title="src/mastra/agents/support-agent.ts"
import { Agent } from '@mastra/core/agent'
import { Memory } from '@mastra/memory'

export const supportAgent = new Agent({
  id: 'support-agent',
  name: 'Support agent',
  instructions: 'Answer customer support questions.',
  model: '__GATEWAY_OPENAI_MODEL__',
  memory: new Memory({
    options: {
      generateTitle: {
        emitEvent: true,
      },
    },
  }),
})
```

串流接收方會收到包含已保存標題的區塊，聊天介面便可更新執行緒清單項目，毋須輪詢：

```typescript oxfmt:false
for await (const chunk of stream.fullStream) {
  if (chunk.type === 'data-thread-title') {
    renameThreadInSidebar(chunk.data.threadId, chunk.data.title)
  }
}
```

這個區塊只供即時傳送，不會儲存為對話訊息。由於串流會等待標題，`emitEvent` 會延遲產生標題那一回合的 `finish`：可能是執行緒首回合，也可能是 `minMessages` 設定較高門檻後的回合。如希望標題產生完全不阻塞串流，請保持關閉。

:::note

`emitEvent` 適用於 `stream()` 執行。`generate()` 傳回 JSON，無法帶上該區塊，因此仍以非阻塞方式產生標題。[持久化及事件式 Agent](/docs/harness/durable-agents) 暫時亦不發出此區塊。這些情況下，標題仍會產生並保存。

:::

如要優化成本或行為，可提供較小的 [`model`](/models) 及自訂 `instructions`：

```typescript title="src/mastra/agents/support-agent.ts"
import { Agent } from '@mastra/core/agent'
import { Memory } from '@mastra/memory'

export const supportAgent = new Agent({
  id: 'support-agent',
  name: 'Support agent',
  instructions: 'Answer customer support questions.',
  model: '__GATEWAY_OPENAI_MODEL__',
  memory: new Memory({
    options: {
      generateTitle: {
        model: '__GATEWAY_OPENAI_MODEL_LUNA__',
        instructions: 'Generate a one-word title.',
      },
    },
  }),
})
```

## 存取記憶 {/* #accessing-memory */}

如要查詢、複製或刪除執行緒及訊息，請在 Agent 呼叫 `getMemory()`：

```typescript
const agent = mastra.getAgentById('test-agent')
const memory = await agent.getMemory()
```

使用 `Memory` 實例查詢已儲存的執行緒及訊息，或複製對話。

## 查詢 {/* #querying */}

以下方法可取得執行緒及訊息，用於在介面展示對話紀錄，或實作自訂記憶擷取。

:::warning
記憶系統不會強制執行存取控制。查詢前，務必在應用程式邏輯確認目前用戶有權存取所查詢的 `resourceId`。
:::

### 執行緒 {/* #threads */}

使用 [`listThreads()`](/reference/memory/listThreads) 取得某資源的執行緒：

```typescript
const result = await memory.listThreads({
  filter: { resourceId: 'user-123' },
  perPage: false,
})
```

對執行緒分頁：

```typescript
const result = await memory.listThreads({
  filter: { resourceId: 'user-123' },
  page: 0,
  perPage: 10,
})

console.log(result.threads) // thread objects
console.log(result.hasMore) // more pages available?
```

亦可按中繼資料篩選及控制排序：

```typescript
const result = await memory.listThreads({
  filter: {
    resourceId: 'user-123',
    metadata: { status: 'active' },
  },
  orderBy: { field: 'createdAt', direction: 'DESC' },
})
```

使用 [`getThreadById()`](/reference/memory/getThreadById) 按 ID 取得單一執行緒：

```typescript
const thread = await memory.getThreadById({ threadId: 'thread-123' })
```

### 訊息 {/* #messages */}

取得執行緒後，使用 [`recall()`](/reference/memory/recall) 擷取訊息。它支援分頁、[語義搜尋](/docs/memory/semantic-recall)及可選的日期篩選。

取得不分頁的執行緒歷史。Recall 預設隱藏提醒訊號；傳入 `hideSignals: false` 可顯示這些訊號，傳入 `true` 可隱藏所有已識別的訊號，亦可傳入陣列排除指定類型。比對規則及優先次序請參閱[訊號可見性與兼容性](/reference/memory/recall#signal-visibility)。

```typescript
const { messages } = await memory.recall({
  threadId: 'thread-123',
  perPage: false,
})
```

對訊息分頁：

```typescript
const { messages } = await memory.recall({
  threadId: 'thread-123',
  page: 0,
  perPage: 50,
})
```

按日期範圍篩選：

```typescript
const { messages } = await memory.recall({
  threadId: 'thread-123',
  filter: {
    dateRange: {
      start: new Date('2025-01-01'),
      end: new Date('2025-06-01'),
    },
  },
})
```

按淺層訊息中繼資料篩選：

```typescript
const { messages } = await memory.recall({
  threadId: 'thread-123',
  filter: {
    metadata: {
      category: 'billing',
      escalated: true,
      priority: 2,
      archivedAt: null,
    },
  },
})
```

中繼資料篩選只比對淺層純量值：`string`、有限的 `number`、`boolean` 及 `null`。

所有指定的中繼資料鍵均採 AND 語義。`null` 條件只比對明確的 `null` 值；缺少的鍵不會相符。

中繼資料鍵須以字母或底線開頭，只可包含英數字元；長度不可超過 128 個字元，也不可使用 `__proto__`、`constructor`、`prototype` 等保留的原型鍵。

效能視乎儲存後端。有些後端可把部分篩選條件下推至資料庫；其他後端會先套用執行緒、資源及日期限制，再掃描候選訊息，最後才分頁。

按 ID 取得單一訊息：

```typescript
const { messages } = await memory.recall({
  threadId: 'thread-123',
  include: [{ id: 'msg-123' }],
})
```

按 ID 取得多則訊息及前後文：

```typescript
const { messages } = await memory.recall({
  threadId: 'thread-123',
  include: [
    { id: 'msg-123' },
    {
      id: 'msg-456',
      withPreviousMessages: 3,
      withNextMessages: 1,
    },
  ],
})
```

按語義搜尋（設定方法請參閱[語義召回](/docs/memory/semantic-recall)）：

```typescript
const { messages } = await memory.recall({
  threadId: 'thread-123',
  vectorSearchString: 'project deadline discussion',
  threadConfig: {
    semanticRecall: true,
  },
})
```

### 介面格式 {/* #ui-format */}

訊息查詢傳回 `MastraDBMessage[]` 格式。前端顯示前，可能需要轉換成 UI 函式庫要求的格式。例如，[`toAISdkV5Messages`](/reference/ai-sdk/to-ai-sdk-v5-messages) 可轉成 AI SDK UI 格式。

## 複製執行緒 {/* #thread-cloning */}

複製執行緒會一併複製原有訊息，可用於建立對話分支、在可能造成破壞的操作前建立檢查點，或測試對話的不同版本。

```typescript
const { thread, clonedMessages } = await memory.cloneThread({
  sourceThreadId: 'thread-123',
  title: 'Branched conversation',
})
```

可按數量或日期範圍篩選複製的訊息，並指定自訂執行緒 ID。亦有工具方法可檢查複製關係。

如毋須傳回已複製的訊息，例如分叉較長的執行緒，可使用 `copyThread()`。此方法不會傳回訊息內容；在 LibSQL 及 PostgreSQL，資料列直接在資料庫內複製。啟用語義召回時，已複製訊息仍會分批讀回，以產生嵌入向量。

完整 API 請參閱 [`cloneThread()`](/reference/memory/cloneThread)、[`copyThread()`](/reference/memory/copyThread) 及[複製工具方法](/reference/memory/clone-utilities)。

## 刪除訊息 {/* #deleting-messages */}

使用 [`deleteMessages()`](/reference/memory/deleteMessages) 從執行緒移除訊息。可按訊息 ID 刪除，或清空整個執行緒。
