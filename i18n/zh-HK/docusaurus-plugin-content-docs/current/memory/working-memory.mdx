# 工作記憶

[訊息紀錄](/docs/memory/message-history)及[語義召回](./semantic-recall)協助 Agent 記住對話；工作記憶則讓 Agent 在多次互動之間持續保存用戶資訊。

工作記憶是 Agent 隨時可用的記事區，保留與用戶或任務有關的關鍵資訊，例如姓名、偏好及對話中的其他重要細節。

這有助維持一直相關、應隨時提供給 Agent 的狀態。

如使用 [Observational Memory](/docs/memory/observational-memory)，`observationalMemory.observation.manageWorkingMemory` 可讓 OM 為 Agent 更新工作記憶。

:::tip[📹 觀看]

觀看 [Mastra 工作記憶](https://www.youtube.com/watch?v=UMy_JHLf1n8\&pp=ygUVbWFzdHJhIHdvcmtpbmcgbWVtb3J5)，了解 Agent 如何在多次互動之間保留用戶資訊。

:::

工作記憶可按兩種範圍持久保存：

- **資源範圍**（預設）：同一用戶的所有對話執行緒共用記憶
- **執行緒範圍**：每個對話執行緒的記憶互相獨立

**注意：**切換範圍後，Agent 看不到另一範圍的記憶；執行緒範圍與資源範圍的記憶完全分開。

## 快速入門 {/* #quickstart */}

以下是為 Agent 啟用工作記憶的基本範例：

```typescript {11-15}
import { Agent } from '@mastra/core/agent'
import { Memory } from '@mastra/memory'

// Create agent with working memory enabled
const agent = new Agent({
  id: 'personal-assistant',
  name: 'PersonalAssistant',
  instructions: 'You are a helpful personal assistant.',
  model: '__GATEWAY_OPENAI_MODEL__',
  memory: new Memory({
    options: {
      workingMemory: {
        enabled: true,
      },
    },
  }),
})
```

## 運作方式 {/* #how-it-works */}

工作記憶是一段 Markdown 文字，Agent 可持續更新，保存長期相關的資訊。

## 記憶的持久化範圍 {/* #memory-persistence-scopes */}

工作記憶支援兩種範圍，讓你決定記憶如何跨對話保存：

### 資源範圍記憶（預設） {/* #resource-scoped-memory-default */}

工作記憶預設會在同一用戶（`resourceId`）的所有對話執行緒之間保留：

```typescript
const memory = new Memory({
  storage,
  options: {
    workingMemory: {
      enabled: true,
      scope: 'resource', // Memory persists across all user threads
      template: `# User Profile
- **Name**:
- **Location**:
- **Interests**:
- **Preferences**:
- **Long-term Goals**:
`,
    },
  },
})
```

**適用情況：**

- 記住用戶偏好的個人助理
- 持續掌握客戶背景的客服機械人
- 追蹤學生進度的教育應用程式

### 在 Agent 中使用 {/* #usage-with-agents */}

使用資源範圍記憶時，請在記憶選項傳入 `resource` 參數：

```typescript
// Resource-scoped memory requires resource
const response = await agent.generate('Hello!', {
  memory: {
    thread: 'conversation-123',
    resource: 'user-alice-456', // Same user across different threads
  },
})
```

### 執行緒範圍記憶 {/* #thread-scoped-memory */}

執行緒範圍的工作記憶只屬於個別對話執行緒，每個執行緒都有獨立記憶：

```typescript
const memory = new Memory({
  storage,
  options: {
    workingMemory: {
      enabled: true,
      scope: 'thread', // Memory is isolated per thread
      template: `# User Profile
- **Name**:
- **Interests**:
- **Current Goal**:
`,
    },
  },
})
```

**適用情況：**

- 分別討論不同主題的對話
- 臨時或只與單次對話有關的資訊
- 每個執行緒都需要工作記憶，但執行緒短暫且互不相關的 Workflow

## 存儲適配器支持 {/* #storage-adapter-support */}

資源範圍的工作記憶需要儲存適配器支援 `mastra_resources` 資料表：

### 支援的儲存適配器 {/* #supported-storage-adapters */}

- **libSQL** (`@mastra/libsql`)
- **PostgreSQL** (`@mastra/pg`)
- **OracleDB** (`@mastra/oracledb`)
- **Upstash** (`@mastra/upstash`)
- **MongoDB** (`@mastra/mongodb`)

## 自訂模板 {/* #custom-templates */}

範本指引 Agent 在工作記憶中追蹤及更新哪些資訊。未提供範本時，Mastra 使用預設範本。請因應 Agent 的用途自訂範本，讓它記住最相關的內容。如執行緒由多人共用，請參閱[多用戶執行緒](./multi-user-threads)。

以下自訂範本示範用戶在訊息中提供相關資料後，Agent 如何保存姓名、所在地、時區等資訊：

```typescript {5-28}
const memory = new Memory({
  options: {
    workingMemory: {
      enabled: true,
      template: `
# User Profile

## Personal info

- Name:
- Location:
- Timezone:

## Preferences

- Communication Style: [e.g., Formal, Casual]
- Project Goal:
- Key Deadlines:
  - [Deadline 1]: [Date]
  - [Deadline 2]: [Date]

## Session state

- Last Task Discussed:
- Open Questions:
  - [Question 1]
  - [Question 2]
`,
    },
  },
})
```

## 設計有效的模板 {/* #designing-effective-templates */}

結構清晰的範本，讓 Agent 更容易分析及更新資訊。可把範本當作助理需要持續填寫的簡短表格。


- **標籤簡短明確。**避免長段落或過長標題。使用 `## Personal Info` 或 `- Name:` 等簡短標籤，讓更新內容易讀，亦較不易被截斷。
- **大小寫一致。**`Timezone:` 和 `timezone:` 等寫法不一致，可能令更新結果混亂。標題及清單標籤請統一使用標題式大小寫或小寫。

- **佔位文字精簡。**可用 `[e.g., Formal]` 或 `[Date]` 等提示，協助 LLM 填入正確位置。

- **長值適當縮寫。**如只需簡短形式，可用 `- Name: [First name or nickname]` 或 `- Address (short):` 等指引，毋須要求完整法定內容。
- **在 `instructions` 說明更新規則。**可直接在 Agent 的 `instructions` 欄位，指定何時及如何填入或清除範本內容。


### 其他範本形式 {/* #alternative-template-styles */}

如只需記錄少數項目，可用簡短的單一區塊：

```typescript
const basicMemory = new Memory({
  options: {
    workingMemory: {
      enabled: true,
      template: `User Facts:\n- Name:\n- Favorite Color:\n- Current Topic:`,
    },
  },
})
```

如偏好敘述方式，亦可用簡短段落保存主要事實：

```typescript
const paragraphMemory = new Memory({
  options: {
    workingMemory: {
      enabled: true,
      template: `Important Details:\n\nKeep a short paragraph capturing the user's important facts (name, main goal, current task).`,
    },
  },
})
```

## 結構化工作記憶 {/* #structured-working-memory */}

工作記憶也可用結構化 schema 定義，而非 Markdown 範本，例如 [Standard JSON Schema](https://standardschema.dev/json-schema)（[Zod](https://zod.dev/)、[Valibot](https://valibot.dev/)、[ArkType](https://arktype.io/) 等）。使用 schema 時，Agent 會以符合該 schema 的 JSON 物件查看及更新工作記憶。

可指定 `template` 或 `schema`，但不能兩者同時指定。如兩者都省略，Mastra 便使用預設工作記憶範本。

### 範例：以 schema 定義工作記憶 {/* #example-schema-based-working-memory */}

```typescript
import { z } from 'zod'
import { Memory } from '@mastra/memory'

const userProfileSchema = z.object({
  name: z.string().optional(),
  location: z.string().optional(),
  timezone: z.string().optional(),
  preferences: z
    .object({
      communicationStyle: z.string().optional(),
      projectGoal: z.string().optional(),
      deadlines: z.array(z.string()).optional(),
    })
    .optional(),
})

const memory = new Memory({
  options: {
    workingMemory: {
      enabled: true,
      schema: userProfileSchema,
      // template: ... (do not set)
    },
  },
})
```

提供 schema 後，Agent 會把工作記憶當作 JSON 物件接收。例如：

```json
{
  "name": "Sam",
  "location": "Berlin",
  "timezone": "CET",
  "preferences": {
    "communicationStyle": "Formal",
    "projectGoal": "Launch MVP",
    "deadlines": ["2025-07-01"]
  }
}
```

### schema 記憶的合併語義 {/* #merge-semantics-for-schema-based-memory */}

以 schema 定義的工作記憶採用**合併語義**：Agent 只須提供要新增或更新的欄位，原有欄位會自動保留。

- **物件欄位深度合併：**只更新已提供的欄位，其餘不變。
- **將欄位設為 `null` 便會刪除：**該欄位會明確地從記憶移除。
- **陣列整體取代：**提供陣列欄位時，會取代原有整個陣列，不會逐項合併。

### 並發更新 {/* #concurrent-updates */}

設定 `scope: 'resource'` 並使用支援原子合併的儲存適配器（目前為 `@mastra/pg`）時，每次合併都在鎖定資料列的資料庫交易中進行。不同程序同時更新不同欄位的變更都會保留。其他適配器在應用程式層合併，只會把同一程序內的寫入依次處理。

如要在自己的程式碼中合併部分更新，請呼叫 `memory.mergeWorkingMemory()`：

```typescript
await memory.mergeWorkingMemory({
  threadId: 'thread-1',
  resourceId: 'user-123',
  workingMemory: { preferences: { tone: 'formal' } },
})
```

如工作記憶並非 schema 形式且採資源範圍，或儲存適配器不支援原子合併，此方法會擲出錯誤。如需後備方案，請先檢查 `await memory.supportsAtomicWorkingMemoryMerge()`。

## 在範本和模式之間進行選擇 {/* #choosing-between-template-and-schema */}

- 如希望 Agent 以用戶資料或記事等自由文字維護記憶，請使用 **template**（Markdown）。範本採用**取代語義**：每次更新時，Agent 都須提供完整記憶內容。
- 如需要可驗證、方便程式存取的結構化、類型安全 JSON 資料，請使用 **schema**。`workingMemory.schema` 接受任何兼容 `PublicSchema` 的 schema，例如 Zod v3、v4；也支援 JSON Schema 及已符合標準的 schema。Agent 只提供待更新欄位時，**合併語義**會保留其他欄位。
- 同一時間只能啟用一種模式：不支援同時設定 `template` 及 `schema`。

## 範例：多步驟保留 {/* #example-multi-step-retention */}

以下簡要展示 `User Profile` 範本如何在一段簡短對話中逐步更新：


```nohighlight
# User Profile

## Personal info

- Name:
- Location:
- Timezone:

--- After user says "My name is **Sam** and I'm from **Berlin**" ---

# User Profile
- Name: Sam
- Location: Berlin
- Timezone:

--- After user adds "By the way I'm normally in **CET**" ---

# User Profile
- Name: Sam
- Location: Berlin
- Timezone: CET
```

之後 Agent 可在回應中直接提到 `Sam` 或 `Berlin`，毋須再問，因為這些資訊已保存在工作記憶。


若 Agent 未如預期更新工作記憶，可在它的 `instructions` 設定加入系統指令，說明**如何**及**何時**使用範本。


## 設定初始工作記憶 {/* #setting-initial-working-memory */}

Agent 通常透過 `updateWorkingMemory` Tool 更新工作記憶；你亦可在建立或更新執行緒時，以程式設定初始工作記憶。這適合注入姓名、偏好等用戶資料，讓 Agent 隨時取用，毋須在每次請求重新傳入。

### 透過執行緒中繼資料設定工作記憶 {/* #setting-working-memory-via-thread-metadata */}

建立執行緒時，可透過中繼資料的 `workingMemory` 鍵提供初始工作記憶：

```typescript title="src/app/medical-consultation.ts"
// Create a thread with initial working memory
const thread = await memory.createThread({
  threadId: 'thread-123',
  resourceId: 'user-456',
  title: 'Medical Consultation',
  metadata: {
    workingMemory: `# Patient Profile
- Name: John Doe
- Blood Type: O+
- Allergies: Penicillin
- Current Medications: None
- Medical History: Hypertension (controlled)
`,
  },
})

// The agent will now have access to this information in all messages
await agent.generate("What's my blood type?", {
  memory: {
    thread: thread.id,
    resource: 'user-456',
  },
})
// Response: "Your blood type is O+."
```

### 以程式更新工作記憶 {/* #updating-working-memory-programmatically */}

亦可更新現有執行緒的工作記憶：

```typescript title="src/app/medical-consultation.ts"
// Update thread metadata to add/modify working memory
await memory.updateThread({
  id: 'thread-123',
  title: thread.title,
  metadata: {
    ...thread.metadata,
    workingMemory: `# Patient Profile
- Name: John Doe
- Blood Type: O+
- Allergies: Penicillin, Ibuprofen  // Updated
- Current Medications: Lisinopril 10mg daily  // Added
- Medical History: Hypertension (controlled)
`,
  },
})
```

### 直接更新記憶 {/* #direct-memory-update */}

另一方法是直接呼叫 `updateWorkingMemory`：

```typescript title="src/app/medical-consultation.ts"
await memory.updateWorkingMemory({
  threadId: 'thread-123',
  resourceId: 'user-456', // Required for resource-scoped memory
  workingMemory: 'Updated memory content...',
})
```

## 唯讀工作記憶 {/* #read-only-working-memory */}

有時你希望 Agent 可以讀取工作記憶，但不可修改。適用於：

- **路由 Agent**：需要上下文，但不應更新用戶資料。
- **子 Agent**：在多 Agent 系統中需要參考記憶，但不負責維護。

如要啟用唯讀模式，請在記憶選項設定 `readOnly: true`：

```typescript
const response = await agent.generate('What do you know about me?', {
  memory: {
    thread: 'conversation-123',
    resource: 'user-alice-456',
    options: {
      readOnly: true, // Working memory is provided but cannot be updated
    },
  },
})
```

## 選用狀態訊號（實驗性） {/* #opt-in-to-state-signals-experimental */}

工作記憶預設會作為系統訊息的一部分提供給模型。設定 `useStateSignals: true`，可改用[狀態訊號](/docs/signals/state-signals)傳遞：

```typescript
const memory = new Memory({
  storage: new LibSQLStore({ id: 'mastra-storage', url: 'file:./mastra.db' }),
  options: {
    workingMemory: {
      enabled: true,
      template: '# User\n- name:\n- location:',
      useStateSignals: true, // experimental: deliver as state signal
    },
  },
})
```

變更如下：

- **儲存方式相同。**仍會讀寫同一資源或執行緒的 `workingMemory` 欄位。
- **Tool 結構相同，只是改名。**寫入仍經同一底層 Tool；這條路徑把它註冊為 `setWorkingMemory`，而非 `updateWorkingMemory`。更名可避免舊版過濾器移除 Tool 呼叫部分，讓它保留為一般審核紀錄，下一個模型步驟亦可自動取得新值。
- **只改變傳遞方式。**`Memory` 不再把工作記憶加入系統提示，而是自動附加 `WorkingMemoryStateProcessor`，以 `stateId: 'working-memory'` 發出目前工作記憶的 `state` 訊號。

同時保有標準狀態訊號的優點：執行緒範圍的追蹤中繼資料、透過 `cacheKey` 去重使相同快照只發出一次，以及舊快照移出上下文視窗時由 `contextWindow.hasSnapshot` 重新注入。

預設值 `useStateSignals: false` 維持現有系統訊息行為。範本式工作記憶的 `version: 'vnext'` 不支援 `useStateSignals`。
