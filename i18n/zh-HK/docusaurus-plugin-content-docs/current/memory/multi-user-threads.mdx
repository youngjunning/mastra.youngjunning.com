# 多人共用對話執行緒

多名用戶可共用同一個 Mastra 對話執行緒。以 [`sendMessage()`](/docs/signals/sending-signals) 傳送每名用戶的訊息，並在訊息的 `attributes` 標明發言者。Mastra 會把訊息呈現為附有這些屬性的 `<user>` 標籤，讓 Agent 在當前輪次或日後讀取對話記錄時，都可辨認各名參與者。

## 何時使用多人共用對話執行緒 {/* #when-to-use-multi-user-threads */}

多人透過同一個 Agent 處理同一主題時，可共用對話執行緒，例如：

- 由編輯、覆核及審批人員參與的協作文件
- 由同一個助理服務多名參與者的群組聊天
- 各角色有不同權限的覆核流程

## 所有參與者使用同一個 `resourceId` {/* #share-one-resourceid-across-all-participants */}

每個對話執行緒只屬於一個 `resourceId`，因此所有參與者要傳入同一個值。單人應用程式預設用用戶 ID；共用時可用對話本身決定 `resourceId`，例如共用文件用 `doc_${docId}`，群組聊天用 `room_${roomId}`。所有人指定同一個 `resourceId` 和 `threadId`，即可讀寫同一份對話記錄。

## 每則訊息附上發言者身份 {/* #send-each-message-with-the-speakers-identity */}

以包含 `contents` 和 `attributes` 的物件傳入訊息。每項屬性都會成為模型讀取的 `<user>` 標籤上的 XML 屬性：

```typescript title="src/mastra/send.ts"
agent.sendMessage(
  {
    contents: 'Please make the cover page teal.',
    attributes: { name: 'Alice', role: 'editor' },
  },
  { resourceId: 'doc_42', threadId: 'doc_42' },
)
```

此模型接收：

```xml
<user name="Alice" role="editor">Please make the cover page teal.</user>
```

Mastra 會自動逸出屬性值。屬性名稱必須是有效的 XML 名稱，例如 `name`、`role` 或 `user_id`。名稱無效時，在為模型呈現訊息時會出現 `Invalid signal XML attribute name` 錯誤。屬性會隨訊息儲存，之後載入對話記錄時，模型仍可分辨各句話出自誰人。

## 向 Agent 說明如何讀取標籤 {/* #tell-the-agent-how-to-read-the-tag */}

在 Agent 的指令說明 `<user>` 標籤及其屬性。Agent 要設定 `memory`，才可將訊息儲存在對話執行緒：

```typescript title="src/mastra/agents/collab.ts"
import { Agent } from '@mastra/core/agent'
import { LibSQLStore } from '@mastra/libsql'
import { Memory } from '@mastra/memory'

const memory = new Memory({
  storage: new LibSQLStore({ id: 'collab-storage', url: 'file:./collab.db' }),
  options: {
    lastMessages: 20,
  },
})

export const collabAgent = new Agent({
  id: 'collab',
  name: 'CollabAgent',
  model: '__GATEWAY_OPENAI_MODEL_LUNA__',
  memory,
  instructions: `
You are a collaborative document assistant. Several people talk to you in the same thread.

Each user message arrives in a <user> tag whose attributes say who sent it:

  <user name="Alice" role="editor">...message text...</user>

Address people by name. Editors propose changes and reviewers approve them.
When you refer to something said earlier, name the person who said it.
  `.trim(),
})
```

把每位參與者的訊息送往同一個對話執行緒。執行緒閒置時，`sendMessage()` 會啟動一次執行，`accepted` 會取得該次執行的輸出：

```typescript title="src/mastra/send.ts"
import { collabAgent } from './agents/collab'

const doc = { resourceId: 'doc_42', threadId: 'doc_42' }

async function send(speaker: { name: string; role: string }, text: string) {
  const { accepted } = collabAgent.sendMessage({ contents: text, attributes: speaker }, doc)
  const result = await accepted
  if (result.action === 'wake') {
    return (await result.output.getFullOutput()).text
  }
}

await send({ name: 'Alice', role: 'editor' }, 'Please make the cover page teal.')
await send({ name: 'Bob', role: 'reviewer' }, 'I want QA sign-off before we publish.')
await send({ name: 'Alice', role: 'editor' }, 'Who asked for QA sign-off?')
// The agent answers that Bob asked for it.
```

若 Agent 仍在回覆其他人，Mastra 會把新訊息送進當前輪次，`accepted` 會回傳 `action: 'deliver'`。實際應用程式應從[對話執行緒串流](/docs/signals/thread-streams)顯示回覆，毋須逐次取用 `sendMessage()` 的結果，所有參與者便可看到同一段對話。

## 搭配不同的 Memory 層 {/* #combining-with-memory-layers */}

按對話須保留各發言者資料的時長，選擇合適的 Memory 層：

- **簡短對話**，或需要逐字記錄發言內容及發言者時：只用[訊息記錄](#message-history-alone)。
- **持續多時的對話執行緒**如超出上下文視窗：使用 [Observational Memory](#with-observational-memory)。

### 只使用訊息記錄 {/* #message-history-alone */}

`lastMessages` 會將較早的訊息連同 `<user>` 屬性帶回上下文，因此在不同輪次仍可辨認發言者。上面的 Agent 例子採用此設定。

### 使用 Observational Memory {/* #with-observational-memory */}

[Observational Memory](/docs/memory/observational-memory)（OM）以觀察記錄取代較早的訊息，使較長的共用對話執行緒仍可放在上下文視窗內。請在同一個 `Memory` 實例上啟用：

```typescript title="src/mastra/agents/collab-om.ts"
import { LibSQLStore } from '@mastra/libsql'
import { Memory } from '@mastra/memory'

const memory = new Memory({
  storage: new LibSQLStore({ id: 'collab-storage', url: 'file:./collab.db' }),
  options: {
    observationalMemory: true,
  },
})
```

OM 會取代 `lastMessages` 載入對話記錄的機制；使用 OM 時請勿設定 `lastMessages`。

Observer 會保留發言者屬性，讓觀察記錄可辨識每句話出自誰人。附有 `attributes: { name: 'Alice', role: 'editor' }` 的訊息會標示為 `User (name="Alice" role="editor")`；沒有屬性的訊息只會標為 `User`。

## 安全 {/* #security */}

請在伺服器按已驗證身份的用戶設定屬性，切勿從請求主體取得。若客戶端可自行設定 `name`，用戶便可能冒認他人。請用[請求上下文](/docs/server/request-context)從身份驗證層讀取已驗證的用戶，並在呼叫 `sendMessage()` 前建立 `attributes`。
