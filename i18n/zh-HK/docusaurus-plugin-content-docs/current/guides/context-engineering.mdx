# 情境工程

{/* vale ai-tells.VerbTricolon = NO */}

模型只能使用其上下文視窗中可用的資訊。這可能包括當前對話、記住的細節、應用程式資料、Tool結果或知識庫中的相關段落。

上下文工程是決定模型應該看到什麼資訊以及何時看到的實踐。我們的目標不是提供盡可能多的內容，而是保持上下文的相關性和最新性。上下文太少會使模型無法獲得所需的資訊；太多可能會使重要細節更難找到，增加成本，並在模型達到其上下文限制之前降低響應品質。

Mastra 提供了不同的方法來將資訊帶入上下文、保持資訊隨時間可用、在需要時檢索資訊以及隨著任務的增長減少或隔離資訊。本指南解釋了何時使用每種機制以及它們如何組合在一起。

{/* vale ai-tells.VerbTricolon = YES */}

|需要|以 | 開頭模型看到了什麼 |
| - | - | - |
|穩定的身份、規則或約束|[Instructions](#instructions) | System context on each model call |
| Data from a database or API | [Tools](#tools) | Tool definitions followed by selected results |
| Current customer or application data | [內聯上下文](#inline-context)|資料插入到用戶訊息中 |
|龐大、穩定的知識庫 |[抹布](#rag)|索引中語意相關的區塊 |
|使用者或組織管理的文件 |[檔案系統](#filesystems)|透過讀取或搜尋Tool選擇的檔案 |
|最近的談話或持久的事實|[記憶](#memory)|歷史、觀察或檢索的記憶 |
|一場長時間的對話 |[觀察記憶](#observational-memory)|密集觀察加上最近未觀察到的訊息|
|運行期間發生新事件或更改狀態 |[訊號](#signals)|用戶訊息、反應訊息、通知訊息或狀態訊息 |
|僅某些任務需要說明 |[動態技能](#dynamic-skills)

## 指示 {/* #instructions */}

一個Agent的[`instructions`](/reference/agents/agent#constructor-parameters) define its stable identity, behavior, and constraints. They're system messages and appear before conversation messages in the model request.

```typescript title="src/mastra/agents/support-agent.ts"
import { Agent } from '@mastra/core/agent'

export const supportAgent = new Agent({
  id: 'support-agent',
  name: 'Support Agent',
  instructions: `You help customers understand their account.
    Use plain language and don't invent account details.`,
  model: '__GATEWAY_OPENAI_MODEL__',
})
```

讓說明集中在適用於大多數通話的行為上。新增目前帳戶資料、檢索到的文件或特定於任務的詳細資訊會使基本提示變得更大且更難以重複使用。

指令也可以在運行時解析[`RequestContext`](/docs/server/request-context):

```typescript title="src/mastra/agents/support-agent.ts"
instructions: ({ requestContext }) => {
  const name = requestContext.get('name')

  return `You help ${name} understand their account.`
}
```

使用`RequestContext` when instructions depend on data that changes with each request, such as the current user, tenant, locale, role, or feature flags. Anything evaluated when the agent is constructed, including an interpolated `new Date()`, is fixed for the life of the process, so compute time-dependent values inside a callback and pass an explicit timezone:

```typescript title="src/mastra/agents/support-agent.ts"
instructions: () =>
  `You help customers understand their account.
  Today is ${new Date().toLocaleDateString('en-US', { timeZone: 'America/New_York' })}.`
```

解析回呼中的日期意味著長時間運行的伺服器會在午夜後選取新的一天，並且明確`timeZone` keeps the date stable regardless of the host's timezone. If the date must refresh across tool continuations or coexist with Studio instruction overrides, use a [`processInputStep`](/reference/processors/processor-interface#processinputstep) processor instead.

：：：提示

如果解析的指令經常更改，模型提供者可能無法重複使用相同的提示快取前綴。首先保持穩定的部分，然後透過訊息或訊號來傳遞頻繁變化的背景。

手錶[this short video on prompt caching](https://youtu.be/eBB0dBqfvuQ) to learn how cacheable prompt prefixes reduce latency and cost.

## 內聯上下文 {/* #inline-context */}

大多數應用程式透過將相關值插入到目前訊息中來傳遞運行時上下文。當您的程式碼已經載入客戶或應用程式資料時，這很有效：

```typescript
const customer = await db.customer.findById(customerId)

await supportAgent.generate(`
  Customer: ${customer.name}
  Plan: ${customer.plan}
  Question: ${question}
`)
```

選擇並標記模型所需的字段，而不是序列化整個資料庫記錄。這樣可以使提示更小，並使每個值的含義更加清晰。

啟用記憶體後，Mastra 會保存目前使用者訊息。不要插入不應出現在對話歷史記錄中的敏感或臨時資料。

對於不太常見的情況，即背景應該影響一個回應而不保存為對話歷史記錄，請傳遞一個[`context`](/reference/agents/generate) message:

```typescript
await supportAgent.generate('Recommend the next action.', {
  context: [{ role: 'user', content: 'The customer has an unresolved billing dispute.' }],
})
```

模型會看到目前執行的背景，但 Mastra 不會將其儲存到記憶體中。使用`context` when persisting the background would pollute the conversation or expose temporary application state on later turns.

## Tool {/* #tools */}

[Tool](/docs/agents/tools)是從資料庫、API 或服務取得目前資料的建議方法。模型決定何時需要資料並提供Tool參數，而您的應用程式控制查詢和傳回的欄位。

```typescript title="src/mastra/tools/customer-tool.ts"
import { createTool } from '@mastra/core/tools'
import { z } from 'zod'

export const getCustomer = createTool({
  id: 'get-customer',
  description: 'Gets the current profile and plan for a customer',
  inputSchema: z.object({ customerId: z.string() }),
  execute: async ({ customerId }) => {
    const customer = await db.customer.findById(customerId)
    return { name: customer.name, plan: customer.plan, status: customer.status }
  },
})
```

使用[`toModelOutput`](/docs/agents/tools#shape-output-for-the-model) when application code needs the full result but the model needs a smaller representation.

## 抹布 {/* #rag */}

[檢索增強生成 (RAG)](/reference/rag/overview)從索引語料庫中檢索語意相關的區塊。它仍然適合大型、穩定的知識庫，使用者可以在其中提出開放式問題，而這些問題不能清楚地映射到結構化資料庫查詢。

```typescript
import { ModelRouterEmbeddingModel } from '@mastra/core/llm'
import { createVectorQueryTool } from '@mastra/rag'

const knowledgeBase = createVectorQueryTool({
  vectorStoreName: 'knowledgeBase',
  indexName: 'support-docs',
  model: new ModelRouterEmbeddingModel('openai/text-embedding-3-small'),
})
```

註冊引用的向量存儲`vectorStoreName` on the same Mastra instance as the agent. Mastra supports [multiple vector databases](/reference/rag/vector-databases). RAG is often exposed through a tool, as in this example. The design choice is whether the agent needs semantic retrieval or can query the source directly.

現在許多應用程式都是從直接的、特定於來源的Tool開始的。模型在選擇它們方面變得越來越好，直接查詢通常更簡單、更便宜，因為它不需要分塊、嵌入和向量索引管道。當實際需要對非結構化內容進行語義搜尋時，請選擇 RAG，然後使用元資料過濾器、重新排名和保守的方法來約束返回的上下文`topK`.

## 檔案系統 {/* #filesystems */}

一個[filesystem](/docs/sandbox/filesystem) gives an agent persistent access to documents and other files. Files can live in a local directory or in providers such as Amazon S3, AgentFS, or Google Drive. The agent receives built-in tools to list, read, and search them.

```typescript title="src/mastra/workspace.ts"
import { LocalFilesystem, Workspace } from '@mastra/core/workspace'

export const workspace = new Workspace({
  filesystem: new LocalFilesystem({ basePath: './knowledge-base' }),
  bm25: true,
  autoIndexPaths: ['**/*.md'],
})

// Agents receive tools including mastra_workspace_read_file, mastra_workspace_list_files,
// mastra_workspace_grep, mastra_workspace_search, and mastra_workspace_index.
await workspace.init()
```

[Workspace搜尋](/docs/sandbox/search)支援 BM25 關鍵字搜尋、向量語義搜尋或兩者的混合。使用文件系統作為個人助理，處理使用者的文件或團隊成員在 Google Drive 等服務中更新的組織知識庫。搜尋針對Workspace索引執行，因此必須先對已變更的檔案建立索引，然後Agent程式才能檢索其最新內容。

：：：提示

檔案系統搜尋也可以使用向量，因此它與 RAG 重疊。當真實來源是Agent可能需要列出、讀取或更新的一組檔案時，請選擇檔案系統。當檢索是主要要求且來源內容不需要像檔案一樣運作時，請選擇獨立的 RAG 管道。

## 記憶 {/* #memory */}

[記憶](/docs/memory/overview)為座席提供跨輪對話的連貫性。它將最近的訊息和記住的細節帶入上下文中，而不需要應用程式每次都重新發送完整的記錄。

記憶體需要一個儲存提供者。每個呼叫還標識一個`resource` that owns the memory and a `thread` that identifies the conversation. Reuse both values to continue the same conversation:

```typescript title="src/mastra/agents/assistant.ts"
import { Agent } from '@mastra/core/agent'
import { Memory } from '@mastra/memory'

export const assistant = new Agent({
  id: 'assistant',
  name: 'Assistant',
  model: '__GATEWAY_OPENAI_MODEL__',
  memory: new Memory({
    options: {
      lastMessages: 20,
    },
  }),
})

await assistant.generate('Help me plan the next project milestone.', {
  memory: {
    resource: 'user-123',
    thread: 'project-456',
  },
})
```

此範例假設儲存體是在註冊的 Mastra 實例上配置的或直接在`Memory`. `lastMessages` controls how many recent messages Mastra loads from the thread. The default is 10.

訊息歷史記錄非常適合較短的對話，其中最近的對話包含Agent所需的上下文。因為`lastMessages` window slides forward on every request, each turn past the limit removes the oldest message from the start of the prompt and invalidates the provider prompt cache. For long-running conversations, Mastra recommends [Observational Memory](/docs/memory/observational-memory), which keeps recent conversation available and turns older history into a dense observation log while keeping the prompt prefix stable for caching.

## 觀察記憶 {/* #observational-memory */}

對話歷史記錄隨著每個用戶訊息、回應和Tool呼叫而增長。即使在達到模型的硬上下文限制之前，長文本也會增加成本並使模型更難找到相關細節。壓縮用較小的表示法取代舊的、冗長的歷史記錄。

[觀察記憶](/docs/memory/observational-memory)持續處理這個問題。觀察者將舊的訊息和Tool互動轉化為密集的觀察結果，而定期反射則重新組織和壓縮這些觀察。

你不需要配置`lastMessages` when Observational Memory is enabled. Observational Memory manages history itself, keeping recent unobserved messages in context and replacing older messages with observations.

```typescript title="src/mastra/agents/assistant.ts"
import { Agent } from '@mastra/core/agent'
import { Memory } from '@mastra/memory'

export const assistant = new Agent({
  id: 'assistant',
  name: 'Assistant',
  model: '__GATEWAY_OPENAI_MODEL__',
  memory: new Memory({
    options: {
      observationalMemory: true,
    },
  }),
})
```

觀察到訊息後，模型會收到觀察日誌、最近未觀察到的訊息以及繼續提醒。由於延遲提示在緩衝區塊啟動時可能已過時，因此非同步緩衝觀察不會產生連續提示（`currentTask` or `suggestedResponse`). The raw messages remain stored but no longer occupy the active model context.

觀察結果以穩定的區塊的形式添加，這有助於提供者重複使用現有的提示前綴。觀察記憶體還可以在提示快取可能過期後或Agent更改提供者之前啟動緩衝觀察。

## 訊號 {/* #signals */}

[訊號](/docs/signals/overview)將訊息或系統產生的上下文新增至記憶體支援的執行緒。傳遞取決於執行緒的狀態：訊號可以喚醒空閒Agent或進入活動循環。它還可以等待下一個回合或持續存在而不喚醒Agent。

狀態訊號需要記憶體和現有線程。通知收件匣訊號需要具有通知支援的儲存適配器。

|應用程式介面 |使用|情境行為 |
| - | - | - |
|`sendMessage()` | User input that the active agent should see now | Enters the active loop or wakes an idle thread |
| `queueMessage()` | User input that should wait for the next turn | Starts after the current run finishes |
| `sendSignal()` | Background results, policy reminders, or external events | Adds reactive or notification context according to its delivery options |
| `sendStateSignal()` | Browser state, editor state, task state, or another changing value | Maintains a thread-scoped state lane with snapshots and deltas |

使用`sendSignal()` for context produced by the system rather than the user:

```typescript
const result = agent.sendSignal(
  {
    type: 'notification',
    contents: 'CI failed on pull request 123: three tests failed.',
    attributes: { source: 'github', pullRequest: 123 },
  },
  {
    resourceId: 'user-123',
    threadId: 'project-456',
  },
)

await result.accepted
```

處理器可以在期間發送反應訊號`processInputStep()`. This is useful for guidance that depends on the current step or a recent tool result. Set `transient: true` when the signal should reach only the current model call. Re-send it when needed instead of storing repeated reminders in conversation history.

狀態訊號代表隨時間變化的上下文。對於每個狀態通道，Mastra 都會追蹤快照和增量，以便在前一個快照離開活動上下文視窗後重新插入新的快照。使用`computeStateSignal()` when a processor owns the state. This lane can keep working memory and browser context available alongside task lists, even after history or Observational Memory removes older messages.

訊號會在目前回合附近附加不斷變化的上下文，而不是重寫Agent的基本指令。因此，瞬態和狀態訊號可以保留更穩定的提示前綴，同時保持當前指導和狀態對模型可見。

## 動態技能 {/* #dynamic-skills */}

[Agent技巧](/docs/skills)讓Agent僅在需要時載入特定於任務的指令，而不是在其基本指令中攜帶每個流程。使用它們作為適用於某些請求的專門指導，並使預設上下文保持較小。

## 情境控制 {/* #context-control */}

情境控制限制了模型隨著任務的成長所看到的內容。壓縮和處理器減少了一個Agent內的上下文，而子Agent邊界控制了Agent之間的移動。

### 壓實 {/* #compaction */}

如果您使用過 Claude Code，您可能會在長時間會話期間看到壓縮發生。 Mastra 團隊喜歡開玩笑，「朋友不讓朋友做壓縮」。

壓縮會等到對話達到令牌閾值。然後它會總結文字記錄並替換先前的訊息。這是一個生硬的後退。壓縮回合增加了延遲，單一摘要必須代表之前發生的所有內容。重複的總結可能會使時間順序變得扁平或失去後來變得重要的細節。

更喜歡[Observational Memory](#observational-memory) for long-running conversations. It can process history asynchronously in the background while preserving temporal context. Reflection revisits accumulated memories and naturally prunes details that no longer matter. Mastra doesn't provide compaction out of the box, though you could implement it with a custom [processor](/docs/agents/processors).

### 處理器 {/* #processors */}

[處理器](/docs/agents/processors)控制進入模型上下文的內容，並且可以在模型呼叫之前重寫內容。當資訊應保留在儲存的歷史記錄或應用程式輸出中但不需要在每個步驟中傳回模型時，請使用它們。

例如，`ToolCallFilter` removes old tool arguments and results from the next model request without deleting those messages from storage. The model gets a smaller prompt, while your application can still display or inspect the complete interaction.

使用`processInput()` or `processInputStep()` to change the active message list. Those changes may later be saved to memory. Use `processLLMRequest()` when a rewrite should apply only to the current provider call and leave memory untouched.

Mastra 包含一些針對上下文膨脹的常見來源的控制項：

* [`toModelOutput`](/docs/agents/tools#shape-output-for-the-model)
* [`ToolCallFilter`](/reference/processors/tool-call-filter)：從模型輸入中刪除舊的Tool呼叫和結果，同時將它們保留在記憶體和 UI 中。
* [`ToolSearchProcessor`](/reference/processors/tool-search-processor)
* [`TokenLimiter`](/reference/processors/token-limiter-processor)：修剪非系統訊息，直到提示符合令牌預算。

開始於[`toModelOutput`](/docs/agents/tools#shape-output-for-the-model) for verbose tool results and `ToolCallFilter` for old tool interactions. Add `TokenLimiter` as a final budget guard rather than relying on the model's maximum context window.

### 子Agent {/* #subagents */}

上下文膨脹的一個常見原因是傳入和傳出過多的信息[subagents](/docs/subagents). A subagent gets a separate model context for its delegated task, but the boundary still needs deliberate controls.

預設情況下，Mastra 將家長的對話轉發給子Agent。使用`messageFilter` to pass only the messages that specialist needs:

```typescript
await supervisor.generate('Investigate the failed deployment.', {
  delegation: {
    messageFilter: ({ messages }) => messages.slice(-10),
  },
})
```

另一方面，Mastra 預設將子Agent程式的文字傳回父模型，同時保持巢狀Tool呼叫和元資料可供應用程式程式碼使用。離開`includeSubAgentToolResultsInModelContext` disabled unless the parent must reason over those details. Use `onDelegationStart` to refine the child prompt and `onDelegationComplete` to reduce or replace the text returned to the parent.

看[Subagents](/docs/subagents) for delegation hooks, memory isolation, iteration monitoring, and result controls.
