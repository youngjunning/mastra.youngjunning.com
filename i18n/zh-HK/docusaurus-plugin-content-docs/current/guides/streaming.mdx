# 串流媒體

Mastra 支援來自Agent和Workflow的即時增量回應，讓使用者在生成時查看輸出，而不是等待完成。這對於聊天、長格式內容、多步驟Workflow或任何需要即時回饋的場景非常有用。

## 入門 {/* #getting-started */}

[`Agent.stream()`](/reference/streaming/agents/stream)是Agent的標準流 API。它返回一個`MastraModelOutput` that exposes `textStream`對於漸進式文本和承諾，例如`text`, `steps`， 和`usage`當流結束時解決。

## 與Agent進行串流 {/* #streaming-with-agents */}

傳遞一個字串作為基本提示。提供多個上下文時，請使用字串陣列。訊息物件數組`role` and `content` gives you precise control over roles and conversational flow.

### 使用`Agent.stream()` {/* #using-agentstream */}

一個`textStream` breaks the response into chunks as it's generated, allowing output to stream progressively instead of arriving all at once. Iterate over the `textStream` using a `for await` loop to inspect each stream chunk.

```typescript
const testAgent = mastra.getAgent('testAgent')

const stream = await testAgent.stream([{ role: 'user', content: 'Help me organize my day' }])

for await (const chunk of stream.textStream) {
  process.stdout.write(chunk)
}
```

訪問[Agent.stream()](/reference/streaming/agents/stream) for more information.

：：：提示

對於派遣的Agent商[background tasks](/docs/harness/background-tasks), use `stream()` with the [`untilIdle` option](/reference/streaming/agents/stream#parameters), such as `untilIdle: true`, to keep the stream open until those tasks complete and the agent has had a chance to respond to their results. This option requires agent memory.

:::

### Agent流屬性 {/* #agent-stream-properties */}

Agent流提供對這些回應屬性的存取：

* **`stream.textStream`**：發出文字區塊的可讀流。
* **`stream.text`**：解析為全文回應的承諾。
* **`stream.steps`**
* **`stream.finishReason`**
* **`stream.usage`**：解析令牌使用資訊的承諾。
* **`stream.objectStream`**&#x548C;**`stream.object`**: Partial and final structured output when `structuredOutput` is passed.

請參閱[`MastraModelOutput` reference](/reference/streaming/agents/MastraModelOutput) for the complete set of properties.

### 人工智慧SDK集成 {/* #ai-sdk-integration */}

使用`toAISdkStream()` and `toAISdkMessages()` to convert Mastra streams and stored messages to AI SDK-compatible formats. The converters default to AI SDK v5 for backward compatibility. Pass the version that matches your installed AI SDK, such as `version: 'v7'` for AI SDK v7.

```typescript
import { toAISdkStream } from '@mastra/ai-sdk'

const testAgent = mastra.getAgent('testAgent')
const stream = await testAgent.stream([{ role: 'user', content: 'Help me organize my day' }])

const aiSDKStream = toAISdkStream(stream, {
  from: 'agent',
  version: 'v7',
})
```

將儲存的訊息轉換為`useChat()`'s `initialMessages` with `toAISdkMessages()`:

```typescript
import { toAISdkMessages } from '@mastra/ai-sdk/ui'

const initialMessages = toAISdkMessages([{ role: 'user', content: 'Hello' }], { version: 'v7' })
```

[AI SDK UI](/integrations/agentic-ui/ai-sdk-ui), which covers `handleChatStream()`, `handleWorkflowStream()`, and `handleNetworkStream()`. Pass the version that matches your installed AI SDK to these handlers too. See the [`toAISdkStream()`](/reference/ai-sdk/to-ai-sdk-stream) and [`toAISdkMessages()`](/reference/ai-sdk/to-ai-sdk-messages) references for all options.

## 透過Workflow進行串流傳輸 {/* #streaming-with-workflows */}

來自Workflow的串流傳回描述運行生命週期的結構化事件序列，而不是增量文字區塊。這種基於事件的格式使得在使用建立運行後可以即時追蹤和回應Workflow進度`.createRun()`.

### 使用`Run.stream()` {/* #using-runstream */}

這`stream()` method returns a `WorkflowRunOutput`. Its `fullStream` property is a `ReadableStream` of workflow events.

```typescript
const run = await testWorkflow.createRun()

const stream = run.stream({
  inputData: {
    value: 'initial data',
  },
})

for await (const chunk of stream.fullStream) {
  console.log(chunk)
}
```

訪問[Run.stream()](/reference/streaming/workflows/stream) for more information.

### 輸出來自`Run.stream()` {/* #output-from-runstream */}

活動包括`runId` and `from` at the top level, so you can identify the workflow run without inspecting the payload.

```typescript oxfmt:false
{
  type: 'workflow-start',
  runId: '1eeaf01a-d2bf-4e3f-8d1b-027795ccd3df',
  from: 'WORKFLOW',
  payload: {
    workflowId: 'testWorkflow'
  }
}
```

### Workflow屬性 {/* #workflow-stream-properties */}

Workflow提供對這些回應屬性的存取：

* **`stream.status`**：Workflow運作的狀態。
* **`stream.result`**：Workflow運作的結果。
* **`stream.usage`**：Workflow運行的總令牌使用量。

來自Agent或Workflow的串流提供了對 LLM 輸出或Workflow運作狀態的即時可見性。將此回饋直接傳遞給用戶，或在應用程式中使用它來顯示Workflow狀態的變化。

從Agent或Workflow發出的事件代表產生和執行的不同階段，例如執行開始時、產生文字時或呼叫Tool時。

## 事件類型 {/* #event-types */}

Agent和Workflow在執行期間發出不同的事件類型。

### Agent活動 {/* #agent-events */}

常見的Agent事件包括：

* **`start`**：Agent運行開始。
* **`text-start`**, **`text-delta`**, and **`text-end`**: The start and end events mark text generation boundaries. Delta events carry incremental text.
* **`reasoning-start`**, **`reasoning-delta`**, and **`reasoning-end`**: The start and end events mark reasoning generation boundaries. Delta events carry incremental reasoning.
* **`tool-call`**&#x548C;**`tool-result`**: A tool is called and returns a result.
* **`step-start`**&#x548C;**`step-finish`**: A model step begins and ends.
* **`finish`**：Agent運行完成。

此列表並不詳盡。請參閱[`ChunkType` reference](/reference/streaming/ChunkType) for all agent chunk types and payloads.

### Workflow事件 {/* #workflow-events */}

Workflow事件包括：

* **`workflow-start`**：Workflow開始運作。
* **`workflow-step-start`**：Workflow步驟開始。
* **`workflow-step-output`**：步驟發出自訂輸出。
* **`workflow-step-progress`**
* **`workflow-step-result`**：一個步驟完成並產生一個結果。
* **`workflow-finish`**：Workflow運作完成。
* **`workflow-paused`**, **`workflow-step-suspended`**, and **`workflow-canceled`**: The workflow run is interrupted.

請參閱[`Run.stream()` reference](/reference/streaming/workflows/stream) for workflow event details.

## 編寫器API {/* #writer-api */}

這`writer` API is shared by tools and workflow steps. See the Tools and Workflows docs for feature-specific examples.

## Agent使用Tool {/* #agent-using-tool */}

Agent流可以與Tool呼叫結合，允許Tool輸出直接寫入Agent的流響應中。這將Tool活動顯示為互動的一部分。

```typescript {2,9}
import { Agent } from '@mastra/core/agent'
import { testTool } from '../tools/test-tool'

export const testAgent = new Agent({
  id: 'test-agent',
  name: 'Test Agent',
  instructions: 'You are a weather agent.',
  model: '__GATEWAY_OPENAI_MODEL__',
  tools: { testTool },
})
```

### 使用`context.writer` {/* #using-contextwriter */}

這`context.writer` object is available in a tool's `execute()` function and can emit custom events, data, or values into the active stream. Tools use these events to provide intermediate results or status updates during execution.

：：：警告

你必須`await` the call to `writer.write()` or else you will lock the stream and get a `WritableStream is locked` error.

:::

```typescript {4,7,14}
import { createTool } from '@mastra/core/tools'

export const testTool = createTool({
  execute: async (inputData, context) => {
    const { value } = inputData

    await context?.writer?.write({
      type: 'custom-event',
      status: 'pending',
    })

    const response = await fetch()

    await context?.writer?.write({
      type: 'custom-event',
      status: 'success',
    })

    return {
      value: '',
    }
  },
})
```

您也可以使用`writer.custom()` to emit top-level stream chunks. This is useful when integrating with UI frameworks.

```typescript {4,7,14}
import { createTool } from '@mastra/core/tools'

export const testTool = createTool({
  execute: async (inputData, context) => {
    const { value } = inputData

    await context?.writer?.custom({
      type: 'data-tool-progress',
      status: 'pending',
    })

    const response = await fetch()

    await context?.writer?.custom({
      type: 'data-tool-progress',
      status: 'success',
    })

    return {
      value: '',
    }
  },
})
```

### 瞬態資料區塊 {/* #transient-data-chunks */}

預設情況下，`data-*` chunks emitted with `writer.custom()` are persisted to storage as part of the message history. For chunks that are only needed during live streaming, such as progress updates or verbose log output, set `transient: true` to skip storage persistence. Transient chunks are still streamed to the client in real time but aren't saved to the database.

```typescript {4}
await context?.writer?.custom({
  type: 'data-build-log',
  data: { line: 'Compiling module 3 of 12...' },
  transient: true,
})
```

當資料很大或頻率很高且僅在即時會話期間相關時，請使用瞬態區塊。頁面刷新後，瞬態區塊不再可用。僅從儲存載入Tool的傳回值和任何非瞬態區塊。

## 使用`writer` argument {/* #using-the-writer-argument */}

這`writer` argument is passed to a workflow step's `execute` function and can emit custom events, data, or values into the active stream. Workflow steps use these events to provide intermediate results or status updates during execution.

：：：警告

你必須`await` the call to `writer.write(...)` or else you will lock the stream and get a `WritableStream is locked` error.

:::

```typescript {8,11,18}
import { createStep } from '@mastra/core/workflows'
import { z } from 'zod'

export const testStep = createStep({
  id: 'test-step',
  inputSchema: z.object({ url: z.url() }),
  outputSchema: z.object({ status: z.number() }),
  execute: async ({ inputData, writer }) => {
    const { url } = inputData

    await writer.write({
      type: 'custom-event',
      status: 'pending',
    })

    const response = await fetch(url)

    await writer.write({
      type: 'custom-event',
      status: 'success',
    })

    return {
      status: response.status,
    }
  },
})
```
