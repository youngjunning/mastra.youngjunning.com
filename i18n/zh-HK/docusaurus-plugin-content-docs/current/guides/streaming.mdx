# 串流

Mastra 的 Agent 及 Workflow 支援即時傳送逐步產生的回應，讓用戶在執行完成前已可看到輸出。這適用於聊天、長篇內容、多步驟 Workflow，以及其他需要即時回饋的情況。

## 開始使用 {/* #getting-started */}

[`Agent.stream()`](/reference/streaming/agents/stream) 是 Agent 的標準串流 API。它傳回 `MastraModelOutput`，透過 `textStream` 可逐步讀取文字，`text`、`steps` 及 `usage` 等 Promise 則在串流結束時取得結果。

## Agent 串流 {/* #streaming-with-agents */}

簡單提示可傳入單一字串。如需提供多段上下文，可使用字串陣列。要精確控制訊息角色及對話流程，可傳入由包含 `role` 及 `content` 的訊息物件組成的陣列。

### 使用 `Agent.stream()` {/* #using-agentstream */}

`textStream` 會在產生回應時將回應分成文字區塊，逐一傳送。使用 `for await` 迴圈遍歷 `textStream`，即可查看每個區塊。

```typescript
const testAgent = mastra.getAgent('testAgent')

const stream = await testAgent.stream([{ role: 'user', content: 'Help me organize my day' }])

for await (const chunk of stream.textStream) {
  process.stdout.write(chunk)
}
```

詳情見 [Agent.stream()](/reference/streaming/agents/stream)。

:::tip

如 Agent 會派送[背景工作](/docs/harness/background-tasks)，可在調用 `stream()` 時使用 [`untilIdle` 選項](/reference/streaming/agents/stream#parameters)，例如 `untilIdle: true`。串流會繼續開啟，直至工作完成，而且 Agent 有機會回應工作結果。這個選項要求 Agent 啟用 Memory。

:::

### `Agent.stream()` 的輸出 {/* #output-from-agentstream */}

Agent 產生的回應會透過串流傳送。

```text
Of course!
To help you organize your day effectively, I need a bit more information.
Here are some questions to consider:
...
```

### Agent 串流屬性 {/* #agent-stream-properties */}

Agent 串流提供以下回應屬性：

- **`stream.textStream`**：送出文字區塊的可讀串流。
- **`stream.text`**：完成時取得完整文字回應的 Promise。
- **`stream.steps`**：完成時取得已完成模型步驟的 Promise。
- **`stream.finishReason`**：完成時取得 Agent 停止串流原因的 Promise。
- **`stream.usage`**：完成時取得 token 用量資料的 Promise。
- **`stream.objectStream`** 及 **`stream.object`**：傳入 `structuredOutput` 時，分別提供部分及最終的結構化輸出。

完整屬性清單見 [`MastraModelOutput` 參考](/reference/streaming/agents/MastraModelOutput)。

### 接駁 AI SDK {/* #ai-sdk-integration */}

使用 `toAISdkStream()` 及 `toAISdkMessages()` 將 Mastra 串流及已儲存的訊息轉成 AI SDK 相容格式。為保持向後相容，轉換函數預設使用 AI SDK v5。請按已安裝的 AI SDK 傳入相應版本，例如 AI SDK v7 使用 `version: 'v7'`。

```typescript
import { toAISdkStream } from '@mastra/ai-sdk'

const testAgent = mastra.getAgent('testAgent')
const stream = await testAgent.stream([{ role: 'user', content: 'Help me organize my day' }])

const aiSDKStream = toAISdkStream(stream, {
  from: 'agent',
  version: 'v7',
})
```

用 `toAISdkMessages()` 轉換已儲存的訊息，再供 `useChat()` 的 `initialMessages` 使用：

```typescript
import { toAISdkMessages } from '@mastra/ai-sdk/ui'

const initialMessages = toAISdkMessages([{ role: 'user', content: 'Hello' }], { version: 'v7' })
```

路由處理函數可參閱 [AI SDK UI](/integrations/agentic-ui/ai-sdk-ui)，當中介紹 `handleChatStream()`、`handleWorkflowStream()` 及 `handleNetworkStream()`。調用這些函數時，同樣須傳入與已安裝的 AI SDK 相符的版本。所有選項見 [`toAISdkStream()`](/reference/ai-sdk/to-ai-sdk-stream) 及 [`toAISdkMessages()`](/reference/ai-sdk/to-ai-sdk-messages) 的參考文件。

## Workflow 串流 {/* #streaming-with-workflows */}

Workflow 串流會傳回一系列描述執行生命週期的結構化事件，而非逐段傳送文字。透過 `.createRun()` 建立一次執行後，便可利用這些事件即時追蹤 Workflow 進度並作出回應。

### 使用 `Run.stream()` {/* #using-runstream */}

`stream()` 方法傳回 `WorkflowRunOutput`。其 `fullStream` 屬性是傳送 Workflow 事件的 `ReadableStream`。

```typescript
const run = await testWorkflow.createRun()

const stream = run.stream({
  inputData: {
    value: 'initial data',
  },
})

for await (const chunk of stream.fullStream) {
  console.log(chunk)
}
```

詳情見 [Run.stream()](/reference/streaming/workflows/stream)。

### `Run.stream()` 的輸出 {/* #output-from-runstream */}

事件頂層包含 `runId` 及 `from`，毋須查看承載內容，便可識別是哪一次 Workflow 執行。

```typescript oxfmt:false
{
  type: 'workflow-start',
  runId: '1eeaf01a-d2bf-4e3f-8d1b-027795ccd3df',
  from: 'WORKFLOW',
  payload: {
    workflowId: 'testWorkflow'
  }
}
```

### Workflow 串流屬性 {/* #workflow-stream-properties */}

Workflow 串流提供以下回應屬性：

- **`stream.status`**：Workflow 執行的狀態。
- **`stream.result`**：Workflow 執行的結果。
- **`stream.usage`**：Workflow 該次執行的 token 總用量。

透過 Agent 或 Workflow 串流，可即時取得大型語言模型的輸出或 Workflow 的執行狀態。你可直接向用戶提供回饋，或在應用程式即時顯示 Workflow 的狀態變化。

Agent 或 Workflow 發出的事件代表產生內容及執行的不同階段，例如開始執行、產生文字或調用 Tool。

## 事件類型 {/* #event-types */}

Agent 及 Workflow 的串流會在執行期間發出不同類型的事件。

### Agent 事件 {/* #agent-events */}

常見的 Agent 事件包括：

- **`start`**：Agent 開始執行。
- **`text-start`**、**`text-delta`** 及 **`text-end`**：開始及結束事件標記何時開始和結束產生文字，增量事件則帶有新產生的文字。
- **`reasoning-start`**、**`reasoning-delta`** 及 **`reasoning-end`**：開始及結束事件標記何時開始和結束產生推理內容，增量事件則帶有新增的推理內容。
- **`tool-call`** 及 **`tool-result`**：調用 Tool 並傳回結果。
- **`step-start`** 及 **`step-finish`**：模型步驟開始及結束。
- **`finish`**：Agent 完成執行。

此處只列出常見事件。完整的 Agent 區塊類型及承載內容見 [`ChunkType` 參考](/reference/streaming/ChunkType)。

### Workflow 事件 {/* #workflow-events */}

Workflow 事件包括：

- **`workflow-start`**：Workflow 開始執行。
- **`workflow-step-start`**：Workflow 的一個步驟開始。
- **`workflow-step-output`**：步驟發出自訂輸出。
- **`workflow-step-progress`**：步驟報告進度。
- **`workflow-step-result`**：步驟完成並傳回結果。
- **`workflow-finish`**：Workflow 完成執行。
- **`workflow-paused`**、**`workflow-step-suspended`** 及 **`workflow-canceled`**：Workflow 執行中斷。

Workflow 事件的詳情見 [`Run.stream()` 參考](/reference/streaming/workflows/stream)。

## 查看 Agent 串流 {/* #inspecting-agent-streams */}

使用 `for await` 迴圈遍歷 `stream.fullStream`，即可查看發出的所有事件區塊。

```typescript
const testAgent = mastra.getAgent('testAgent')

const stream = await testAgent.stream([{ role: 'user', content: 'Help me organize my day' }])

for await (const chunk of stream.fullStream) {
  console.log(chunk)
}
```

詳情見 [Agent.stream()](/reference/streaming/agents/stream)。

## Writer API {/* #writer-api */}

Tool 及 Workflow 步驟共用 `writer` API。個別功能的使用例子見 Tool 及 Workflow 文件。

## 在 Agent 串流中使用 Tool {/* #agent-using-tool */}

Agent 串流可配合調用 Tool，直接將 Tool 輸出寫入 Agent 的串流回應，在互動過程中顯示 Tool 活動。

```typescript {2,9}
import { Agent } from '@mastra/core/agent'
import { testTool } from '../tools/test-tool'

export const testAgent = new Agent({
  id: 'test-agent',
  name: 'Test Agent',
  instructions: 'You are a weather agent.',
  model: '__GATEWAY_OPENAI_MODEL__',
  tools: { testTool },
})
```

### 使用 `context.writer` {/* #using-contextwriter */}

在 Tool 的 `execute()` 函數可用 `context.writer` 物件向目前的串流發出自訂事件、數據或值。Tool 可利用這些事件在執行期間提供中間結果或狀態更新。

:::warning

必須用 `await` 等候 `writer.write()` 調用完成，否則串流會被鎖定，並出現 `WritableStream is locked` 錯誤。

:::

```typescript {4,7,14}
import { createTool } from '@mastra/core/tools'

export const testTool = createTool({
  execute: async (inputData, context) => {
    const { value } = inputData

    await context?.writer?.write({
      type: 'custom-event',
      status: 'pending',
    })

    const response = await fetch()

    await context?.writer?.write({
      type: 'custom-event',
      status: 'success',
    })

    return {
      value: '',
    }
  },
})
```

亦可用 `writer.custom()` 發出頂層串流區塊，方便接駁 UI 框架。

```typescript {4,7,14}
import { createTool } from '@mastra/core/tools'

export const testTool = createTool({
  execute: async (inputData, context) => {
    const { value } = inputData

    await context?.writer?.custom({
      type: 'data-tool-progress',
      status: 'pending',
    })

    const response = await fetch()

    await context?.writer?.custom({
      type: 'data-tool-progress',
      status: 'success',
    })

    return {
      value: '',
    }
  },
})
```

### 暫態數據區塊 {/* #transient-data-chunks */}

預設情況下，`writer.custom()` 發出的 `data-*` 區塊會作為訊息記錄的一部分持久儲存。若只需在即時串流期間使用某些區塊，例如進度更新或詳細日誌，可設定 `transient: true` 略過持久儲存。暫態區塊仍會即時傳到客戶端，但不會存入數據庫。

```typescript {4}
await context?.writer?.custom({
  type: 'data-build-log',
  data: { line: 'Compiling module 3 of 12...' },
  transient: true,
})
```

若數據量大或頻繁產生，而且只在即時工作階段有用，可使用暫態區塊。重新載入頁面後，暫態區塊便無法再取得。系統只會從儲存層載入 Tool 的傳回值及非暫態區塊。

## 使用 `writer` 參數 {/* #using-the-writer-argument */}

`writer` 參數會傳入 Workflow 步驟的 `execute` 函數，可向目前的串流發出自訂事件、數據或值。Workflow 步驟可透過這些事件在執行期間提供中間結果或狀態更新。

:::warning

必須用 `await` 等候 `writer.write(...)` 調用完成，否則串流會被鎖定，並出現 `WritableStream is locked` 錯誤。

:::

```typescript {8,11,18}
import { createStep } from '@mastra/core/workflows'
import { z } from 'zod'

export const testStep = createStep({
  id: 'test-step',
  inputSchema: z.object({ url: z.url() }),
  outputSchema: z.object({ status: z.number() }),
  execute: async ({ inputData, writer }) => {
    const { url } = inputData

    await writer.write({
      type: 'custom-event',
      status: 'pending',
    })

    const response = await fetch(url)

    await writer.write({
      type: 'custom-event',
      status: 'success',
    })

    return {
      status: response.status,
    }
  },
})
```
