# 多 Agent 系統

多 Agent 系統由多個 Agent 分擔任務。在 Mastra 中，一般會組合 Agent、Workflow 或兩者，讓各個部分都有清晰的分工。

目標是將正確的上下文、Tool和職責分配給正確的元件。當這種劃分清晰時，多智能體系統比一個背負著長提示和太多Tool或職責的智能體系統更容易推理。

## 何時使用多Agent系統 {/* #when-to-use-multi-agent-systems */}

如果單一 Agent 已無法合理承擔整項工作，可採用多 Agent 系統。

這種情況常出現在以下情況：

* 任務涵蓋不同類型的工作，例如研究、規劃、寫作或評論。
* 一個Agent需要太多的上下文或太多的Tool。
* 任務的各個部分應該並行運行。
* 不同的階段需要不同的提示、模型或護欄。
* 您希望路由、執行和綜合之間有清晰的界限。

盡可能從一名Agent商開始。當添加的結構明顯提高品質、速度或可靠性時，添加更多Agent。

如果系統需要清楚劃分各個組件的上下文、決策和職責，多 Agent 模式便能派上用場。設計時的關鍵是確定任務在各個階段由哪個組件主導。

## 交接 {/* #handoffs */}

切換模式將控制權從一個Agent轉移到另一個Agent。與主管模式不同，第一個Agent不會負責整個任務。相反，活躍的專家掌控了互動的下一部分。

當下一位專家應該直接繼續互動而不是透過中央協調員報告時，請使用交接。權衡是上下文管理變得更加重要，因為系統必須決定下一個Agent繼承什麼以及保留什麼範圍。

在 Mastra 中，可配合 [Agent](/docs/agents/overview)、[Workflow](/docs/workflows/overview) 和 [Memory](/docs/memory/overview) 實作交接。Workflow 可以分派任務，但這種模式的重點是由下一個 Agent 接手。

## Workflow {/* #workflows */}

Workflow模式定義了程式碼中的執行路徑。您無需要求Agent決定接下來會發生什麼，而是透過步驟、分支、循環和並行區塊來定義序列。

當任務被很好地理解並且執行路徑預先已知時，使用Workflow。主要優點是可預測性：顯式結構使系統更易於調試和審計。代價是靈活性，因為當任務隨著展開而改變時，Workflow的適應性較差。

Mastra 的 [Workflow](/docs/workflows/overview) 可實作交接和共同評議等協調模式。無論調用哪些 Agent，控制邏輯都由 Workflow 本身掌握。

## 主管模式 {/* #supervisors */}

主管模式讓一名首席Agent控制整個任務。主管決定何時委派、呼叫哪位專家、傳遞什麼情境、如何組合結果。

當任務是開放式的並且事先不知道完整的序列時，請使用此模式。例如，一項研究任務可能需要根據早期步驟發現的內容進行不同的調查。主管可以隨著任務的展開進行調整。
權衡是主管成為主要協調點。這使得模式變得靈活，但也意味著結果在很大程度上取決於良好的委派行為和明確的子Agent邊界。

在 Mastra 中，這種模式由[主管 Agent](/docs/subagents) 實現。主管 Agent 透過 `agents` 屬性定義子 Agent，再用 `stream()` 或 `generate()` 協調它們。Mastra 提供委派鉤子及訊息篩選，並將不同 Agent 的 Memory 隔離。

:::tip

可參閱[主管 Agent 教學](https://mastra.ai/blog/build-a-research-coordinator-with-supervisor-agents)，跟隨當中的步驟操作。

:::

## 共同評議 {/* #council */}

共同評議由多個 Agent 各自處理同一問題，再比較或綜合各自的輸出，得出最終答案。主管模式會拆分問題，共同評議則會保留同一個問題，以收集不同觀點。

如問題含糊、需要作出判斷或影響重大，而答案質素比速度更重要，可採用共同評議。由於多個 Agent 刻意重複處理同一問題，通常比其他模式耗時更長，消耗的 Token 也更多。

Mastra 沒有專為共同評議而設的原語。可用 [Agent](/docs/agents/overview) 和 [Workflow](/docs/workflows/overview) 實作：同時執行多個 Agent，收集輸出後，再加入最後的綜合或審查步驟。`.parallel()` 等 Workflow 控制流程方法可用來安排這些步驟。

## 選擇協調模式 {/* #choosing-a-pattern */}

這些模式的主要區別在於它們如何分配控制：

| 模式 | 由誰主導 | 適用情況 | 取捨 | 在 Mastra 中的實作 |
| - | - | - | - | - |
| 交接 | 目前負責的專家 Agent | 工作須在不同專家 Agent 之間交接 | 更依賴上下文傳遞 | 結合 Agent、Workflow 和 Memory |
| Workflow | 執行圖 | 已知執行路徑 | 任務有變時較難調整 | [Workflow](/docs/workflows/overview) |
| Supervisor agents | One lead agent | Delegation must adapt during execution | Results depend on good coordination and clear boundaries | [Supervisor agents](/docs/subagents) |
| Council | Final synthesis step | The task needs multiple independent perspectives | Higher cost and latency | Agents with workflow parallelism |

在實踐中，這些模式經常組合在一起：

* Workflow可以包含一個或多個主管驅動的步驟。
* 切換流程可以從路由Workflow開始。
- 可在 Workflow 內進行共同評議，然後將結果交到最後的審批步驟。
* 主管可以將具有固定內部結構的任務委託給Workflow。

根據協調問題而不是任務標籤選擇模式。
