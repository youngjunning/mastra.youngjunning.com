# Knowledge

**加入版本：** `@mastra/core@1.82.0`

Knowledge 是 Agent 共用的資料空間，用來整理毋須依附個別對話的資料，例如政策、產品文件、慣例、操作手冊及其他 Agent 的經驗。Agent 用 Tool 搜尋、讀取及寫入資料。釘選的頁面會經 [Signal](/docs/signals/overview) 加入 Agent 的上下文，並在執行期間保持最新。

:::alpha

Knowledge 仍處於 Alpha 階段，API 可能隨版本改變。每次呼叫 Tool 都會檢查存取權限，但目前未能保證各範圍相互隔離。切勿把不能讓其他客戶或用戶取得的內容存入 Knowledge。目前亦未內置匯入工具或保留機制。

:::

## Knowledge 是甚麼 {/* #what-knowledge-is */}

Knowledge 以頁面和筆記組成圖結構，再劃分為多個範圍。

- **頁面**記錄一個主題，包含名稱、簡介及 Markdown 內文。頁面可像資料夾般分層；例如 `org:acme#policies/refund` 是 `org:acme` 範圍內 `policies` 下的 `refund` 頁面。
- **筆記**是在頁面補充的簡短事實，會標明作者。人和 Agent 均可新增筆記，毋須重寫頁面。
- **連結**把頁面連接起來。頁面內文和筆記可用 `[[org:acme#policies/refund]]` 連到其他頁面。閱讀頁面時，也會顯示提及該頁面的筆記。這些連結讓 Knowledge 成為圖結構，而非單純的文件清單。
- **範圍**是圖內獨立的一部分，例如 `org:acme` 或 `team:acme:support`。先宣告所需的範圍類型，再由伺服器指定每次 Agent **執行**持有的範圍。
- **角色**決定一次執行在範圍內可做的事：檢視者可讀取，貢獻者可新增頁面及筆記，編輯者可修改頁面，擁有者亦可刪除頁面並在各範圍之間移動頁面。每次呼叫 Tool 都會按範圍宣告的規則判定角色，不會按用戶儲存角色。

## 何時使用 Knowledge {/* #when-to-use-knowledge */}

[Memory](/docs/memory/overview) 保留對話內容，讓 Agent 在同一個執行緒繼續工作。Knowledge 保存個別對話結束後仍有用的資料，供不同執行緒、Agent 和人員共用。

如希望 Agent 做到以下各項，可使用 Knowledge：

- **遵守更新後的規則。** 釘選政策頁面後，有讀取權限的 Agent 每輪都可看到頁面。修改頁面後，運作中的 Agent 會在下一輪收到新版。
- **由同一個 Agent 服務多個客戶或團隊。** 每個客戶或團隊各有存放頁面的範圍。伺服器為每次執行傳入的範圍，會決定該次可讀取哪些頁面。
- **沿用其他 Agent 的經驗。** Agent 把決策、慣例及操作手冊要點寫成頁面或附有作者資料的筆記，其他 Agent 和人員都可查找及補充。
- **在 Agent 之間交接工作。** 研究 Agent 寫下研究結果，規劃 Agent 在下方補上計劃，編程 Agent 再從同一範圍讀取兩項內容。
- **按現有資料回答。** 把文件或政策載入一個範圍，再為 Agent 提供唯讀 Tool，讓它有資料可查。

## 快速入門 {/* #quickstart */}

建立 Knowledge 實例，宣告所用的範圍類型，再將實例加入 Agent。`tools: true` 會為 Agent 提供搜尋、讀取和寫入頁面的工具。把實例連同 `KNOWLEDGE_ROUTES` 註冊到 `Mastra` 後，即可在 Studio 瀏覽內容：

```typescript title="src/mastra/index.ts"
import { Mastra } from '@mastra/core'
import { Agent } from '@mastra/core/agent'
import { Knowledge, knowledgeMemoryScopes } from '@mastra/core/knowledge'
import { LibSQLStore } from '@mastra/libsql'
import { Memory } from '@mastra/memory'
import { KNOWLEDGE_ROUTES } from '@mastra/server/server-adapter'

const storage = new LibSQLStore({ id: 'storage', url: 'file:./mastra.db' })

export const knowledge = new Knowledge({
  id: 'company',
  storage,
  scopes: { ...knowledgeMemoryScopes() },
  tools: true,
})

export const agent = new Agent({
  id: 'assistant',
  name: 'Assistant',
  instructions: 'You help your team and keep its knowledge up to date.',
  model: '__GATEWAY_OPENAI_MODEL__',
  memory: new Memory({ storage }),
  knowledge,
})

export const mastra = new Mastra({
  agents: { agent },
  knowledge: { company: knowledge },
  server: { apiRoutes: [...KNOWLEDGE_ROUTES] },
})
```

`tools` 預設關閉。即使已把 Knowledge 加入 Agent，仍須開啟此選項才會提供工具。Memory 並非必需；每次呼叫都傳入 `scopes` 便可運作，但[釘選上下文](/docs/knowledge/pinned-context)仍需要 Memory。

`knowledgeMemoryScopes()` 宣告三種範圍，分別對應每個組織、每名用戶（`resource:`）及每個對話執行緒（`thread:`）。每次執行都會指定持有的範圍。以下指令碼為同一組織的 Dana 和 Bea 分別執行 Agent，兩人各用自己的對話執行緒：

```typescript title="src/try-knowledge.ts"
import { mastra } from './mastra'

const agent = mastra.getAgent('agent')

await agent.generate('Our refund window is 30 days. Save that for the team.', {
  scopes: ['org:acme', 'resource:dana', 'thread:dana-1'],
})

const answer = await agent.generate('How long is our refund window?', {
  scopes: ['org:acme', 'resource:bea', 'thread:bea-1'],
})

console.log(answer.text)
```

`resource:` 和 `thread:` 範圍亦會告知 Memory 對話屬於哪名用戶和哪個執行緒。實際應用程式應由伺服器程式碼按已驗證身份的用戶決定範圍，切勿從模型或請求主體取得。要為每個請求設定範圍，請參閱[設定執行的範圍](/docs/knowledge/scopes-and-access#set-a-runs-scopes)。

在 Dana 的執行中，Agent 呼叫 `knowledge_page`，把頁面儲存至 `org:acme` 範圍，並取得類似 `{ "page": { "name": "Refund window", "ref": "org:acme#refunds", "scope": "org:acme", "version": 1 } }` 的結果。到 Bea 執行時，Agent 呼叫 `knowledge_search` 找到 `org:acme#refunds`，再用 `knowledge_read` 讀取頁面，回答退款期限為 30 日。搜尋只會回傳該次執行有權讀取的頁面，因此持有另一個 `org:` 範圍的執行無法找到 Acme 的頁面。

要查看頁面，可執行 `mastra dev`，開啟 Studio 後選擇 **Knowledge**。Agent 寫入的頁面會在 `org:acme` 範圍顯示。
