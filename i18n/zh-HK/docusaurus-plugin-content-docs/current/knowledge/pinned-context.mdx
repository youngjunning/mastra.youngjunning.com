# 固定上下文

固定上下文可將選定的 Knowledge 頁面保留在 Agent 每輪的上下文，省去搜尋。適合存放毋須特別提出也適用的長期指示、硬性規則及持續偏好。固定頁面每輪均會消耗 token，其餘內容可留待 Agent 有需要時搜尋和讀取。

您可以透過兩種方式固定頁面：

| | 在設定中固定 | 由 Agent 固定 |
| - | - | - |
| 設定方式 | 由你在範圍聲明中設定 | 由 Agent 使用固定工具設定 |
| 提供予 | 持有該類範圍的每次執行 | 持有固定對象所涵蓋範圍的每次執行 |
| 額度用盡時 | 一律提供頁面，有需要時截短 | 列出頁面名稱，供 Agent 開啟 |
| 移除方式 | 修改聲明 | 由 Agent 取消固定 |

兩種方式都要求該次執行有權讀取頁面。固定操作本身不會授予頁面存取權限。

:::alpha

Knowledge 目前處於 alpha 階段，API 或會隨版本更改。

:::

## 啟用固定上下文 {/* #turn-on-pinned-context */}

Agent 須啟用 Memory 才可使用固定上下文。在 `Knowledge` 實例設定 `pinnedContext`：

```typescript title="src/mastra/knowledge.ts"
import { Knowledge, knowledgeMemoryScopes } from '@mastra/core/knowledge'
import { LibSQLStore } from '@mastra/libsql'

export const knowledge = new Knowledge({
  id: 'acme',
  storage: new LibSQLStore({ id: 'knowledge', url: 'file:./mastra.db' }),
  tools: true,
  pinnedContext: { maxTokens: 1000 },
  scopes: {
    ...knowledgeMemoryScopes(),
    // scope declarations, see below
  },
})
```

`pinnedContext: true` 容許每輪最多固定 20 個頁面，額度為 500 個 token。如模型的上下文視窗較大，可提高 `maxTokens`。Knowledge 每輪均可使用全數額度。

固定頁面經由[狀態訊號](/docs/signals/state-signals)傳給 Agent。首輪會收到額度內的所有固定頁面，往後每輪只會收到變更。若首輪快照已離開上下文，例如經 Observational Memory 壓縮，下一輪會再次收到完整快照。正在運行的 Agent 會在下一輪收到固定頁面的修訂，提示快取亦可繼續使用。沒有 Memory 的 Agent 不會收到固定頁面，並會記錄一次警告。

## 在設定中固定頁面 {/* #pin-pages-in-config */}

範圍聲明中的 `pinnedContext` 列出持有該範圍的每次執行都會收到的頁面。此例中，每次以客服角色執行時都會收到所屬組織的退款政策：

```typescript title="src/mastra/knowledge.ts" oxfmt:false
scopes: {
  ...knowledgeMemoryScopes(),
  'role:$orgId:support': {
    description: 'Customer support agents',
    pinnedContext: ['policy:$orgId#refund-policy'],
  },
  'policy:$orgId': {
    description: 'Company policies',
    access: [{ principal: 'org:$orgId', role: 'viewer' }],
    pages: [
      { key: 'refund-policy', name: 'Refund Policy', description: 'Refund limits and approvals' },
    ],
  },
},
```

每項均為頁面路徑，佔位符取值自該次執行持有的範圍。持有 `role:acme:support` 的執行會收到 `policy:acme#refund-policy`，持有 `role:globex:support` 則會收到 `policy:globex#refund-policy`。執行亦須有權讀取頁面，此處的權限來自 `org:` 範圍：

| 執行持有的範圍 | 會否收到這份固定的退款政策 |
| - | - |
| `org:acme`, `role:acme:support` | 會 |
| `org:acme`, `role:acme:sales` | 不會，但可使用工具讀取該頁面 |
| `org:globex`, `role:globex:support` | 不會，會收到 `policy:globex#refund-policy` |

Knowledge 每次執行都會查找路徑。請按例子把路徑指向目標範圍 `pages` 中聲明的範本頁面。工具無法搬移範本頁面，因此固定設定會繼續有效。若頁面尚未存在或沒有正文，系統不會提供內容，亦不會報錯。此處的客服執行只有查看權限，請在伺服器調用 [`upsertPage()`](/docs/knowledge/load-your-content) 寫入政策正文。

即使超出額度，設定中固定的頁面仍會提供。Agent 無法取消固定。如要移除，請修改聲明。

## 讓 Agent 固定頁面 {/* #let-agents-pin-pages */}

Agent 可在執行時透過 [`knowledge_pin`](/reference/knowledge/knowledge-tools#knowledge_pin) 工具固定或取消固定頁面。每項固定設定都有**接收對象**，指哪些範圍的執行會收到頁面。例如，Agent 可為 `role:acme:support` 固定退款政策。即使頁面搬移，Agent 儲存的設定仍會指向該頁面。

要固定或取消固定頁面，運行需要以下兩項：

- 在頁面所屬範圍具有 `editor` 權限。
- 執行須持有接收對象的每個範圍，或透過規則在相應範圍取得 `editor` 權限。

此例中，政策管理員可為所屬組織的客服執行固定頁面：

```typescript title="src/mastra/knowledge.ts" oxfmt:false
scopes: {
  ...knowledgeMemoryScopes(),
  'role:$orgId:policy-admin': { description: 'Edits company policy' },
  'role:$orgId:support': {
    description: 'Customer support agents',
    access: [{ principal: 'role:$orgId:policy-admin', role: 'editor' }],
  },
  'policy:$orgId': {
    description: 'Company policies',
    access: [
      { principal: 'org:$orgId', role: 'viewer' },
      { principal: 'role:$orgId:policy-admin', role: 'owner' },
    ],
  },
},
```

Acme 的政策管理員可為 `role:acme:support` 固定頁面，但不可為 `role:globex:support` 固定。客服執行仍須有權讀取才會收到頁面。

角色範圍的 `editor` 權限亦容許該次執行在該範圍建立頁面。如無 `self` 規則，任何人都無法讀取這些頁面。請將頁面放在 `policy:` 等內容範圍內，角色範圍只用於指定接收對象。

## 固定頁面清單 {/* #pinned-listings */}

固定清單會將某個範圍或頁面之下的頁面目錄放入上下文，格式與 [`knowledge_list`](/reference/knowledge/knowledge-tools#knowledge_list) 回傳的內容相同，包括各頁面的參照、名稱及子頁面數目。如 Agent 需要知道有哪些頁面及其位置，例如文件網站的各個部分，可固定清單，讓 Agent 透過 `knowledge_read` 直接讀取所需頁面。如每輪均需要頁面內容，便固定頁面本身。

在範圍的 `pinnedContext` 加入 `{ list, depth }` 即可固定清單。`list` 指定範圍或頁面路徑，`depth` 指定往下顯示的層數，介乎 1 至 3，預設為 1：

```typescript title="src/mastra/knowledge.ts"
import { Knowledge, knowledgeMemoryScopes } from '@mastra/core/knowledge'
import { LibSQLStore } from '@mastra/libsql'

export const knowledge = new Knowledge({
  id: 'docs',
  storage: new LibSQLStore({ id: 'knowledge', url: 'file:./mastra.db' }),
  tools: true,
  pinnedContext: true,
  scopes: {
    ...knowledgeMemoryScopes(),
    'site:$siteId': {
      description: 'A website',
      access: [{ principal: 'self', role: 'viewer' }],
      pinnedContext: [{ list: 'site:$siteId', depth: 1 }],
    },
  },
})
```

持有 `site:mastra` 的每次執行都會收到這份清單：

```text
Pages under site:mastra (site:mastra, depth 1):
- site:mastra#docs — Docs (2 children)
- site:mastra#blog — Blog
- site:mastra#pricing — Pricing
```

固定清單與固定頁面適用相同規則：

- 與 `knowledge_list` 相同，清單只顯示該次執行有權讀取的頁面。如無權讀取清單所指的範圍或頁面，便不會收到內容。
- 當新增、重新命名或刪除列出的頁面時，它會在下一輪更新。
- 清單佔用 `maxPins` 的一個名額，並與固定頁面共用 `maxTokens` 額度。

清單超出額度時，會逐層列出可放入的頁面：先第一層，再第二層，最多到 `depth` 層。如有頁面未列出，清單末尾會提示 Agent 使用 `knowledge_list` 繼續查看。預設額度為 500 個 token，較大的範圍可能只顯示第一層。可調高 `maxTokens` 以顯示更深層的頁面。清單上限詳見[限制](/reference/knowledge/limits)。

Agent 可在執行時調用 `knowledge_pin` 並傳入 `kind: "list"` 固定清單，所需角色與固定頁面相同。上述 `site:` 的執行只有查看權限，因此須由在 `site:mastra` 具備 `editor` 規則的執行發出調用：

```json
{ "op": "pin", "kind": "list", "depth": 2, "page": "site:mastra#docs", "audience": ["site:mastra"] }
```

同一頁面可同時固定頁面本身及頁面清單，兩項設定各自固定和取消。參數詳見 [`knowledge_pin`](/reference/knowledge/knowledge-tools#knowledge_pin)。

## 每次執行會收到甚麼 {/* #what-a-run-receives */}

在每一輪中，Knowledge 都會以以下順序建立運行的固定上下文：

1. 該次執行持有的所有範圍在設定中固定的頁面及清單。如超出額度，每項會截短至平均分配的額度。
1. Agent 為該次執行持有的任何範圍固定的頁面及清單。優先次序較高的先列出，同級時較新的優先。已在設定固定的項目不會重複。
1. 額度不足以容納的固定項目只會列出名稱，Agent 可用讀取工具開啟。

截短的頁面末尾會提示 Agent 讀取餘下內容。

範圍的 `pinnedContextPriority` 設定其優先次序，預設為 `0`。`knowledgeMemoryScopes()` 為 `thread:`、`resource:` 和 `org:` 分別設定 2、1、0，所以單一用戶的固定項目優先於整個組織的固定項目。
