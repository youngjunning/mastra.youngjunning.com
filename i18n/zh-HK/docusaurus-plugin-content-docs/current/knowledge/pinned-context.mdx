# 固定上下文

固定上下文每次都會將選定的知識頁面保留在Agent的上下文中，因此Agent程式無需搜尋它們。將其用於無論是否有人要求都適用的長期指示、嚴格規則和持久偏好。固定頁面每次都會花費代幣。將其他所有內容保留在Agent搜尋的頁面中，並在需要時閱讀。

您可以透過兩種方式固定頁面：

| |固定在配置 |由Agent固定 |
| - | - | - |
|由 | 設定您，在範圍聲明中 |一個Agent，用圖釘Tool|
|交付至 |每次運行都擁有該類型的範圍 |每一次在圖釘觀眾中佔據一定範圍的運行 |
|當預算滿的時候 |總是交付，如有需要則縮短 |按名稱列出，以便Agent可以打開它 |
|刪除者 |更改聲明 |特工解鎖 |

無論哪種方式，只有當運行可以讀取頁面時，它才會獲得固定頁面。 PIN 永遠不會授予對頁面的存取權限。

：：：阿爾法

知識處於阿爾法階段。其 API 可能會在不同版本之間變更。

:::

## 開啟固定上下文 {/* #turn-on-pinned-context */}

固定上下文需要Agent上的記憶體。放`pinnedContext` on the `Knowledge` instance:

```typescript title="src/mastra/knowledge.ts"
import { Knowledge, knowledgeMemoryScopes } from '@mastra/core/knowledge'
import { LibSQLStore } from '@mastra/libsql'

export const knowledge = new Knowledge({
  id: 'acme',
  storage: new LibSQLStore({ id: 'knowledge', url: 'file:./mastra.db' }),
  tools: true,
  pinnedContext: { maxTokens: 1000 },
  scopes: {
    ...knowledgeMemoryScopes(),
    // scope declarations, see below
  },
})
```

`pinnedContext: true`每回合最多允許 20 個固定頁面和 500 個令牌。增加`maxTokens` for models with large context windows. Knowledge can use the whole budget on every turn.

固定頁面作為Agent到達Agent[state signal](/docs/signals/state-signals). The first turn gets every pinned page that fits the budget, and later turns get only what changed. If that first snapshot leaves the context, for example when Observational Memory compresses it, the next turn gets a full snapshot again. An edit to a pinned page reaches running agents on their next turn, and the prompt cache stays warm. An agent without Memory gets no pinned pages and logs a warning once.

## 在配置中固定頁面 {/* #pin-pages-in-config */}

範圍聲明的`pinnedContext` lists pages that every run holding that scope gets. Here, every support run gets its org's refund policy:

```typescript title="src/mastra/knowledge.ts" oxfmt:false
scopes: {
  ...knowledgeMemoryScopes(),
  'role:$orgId:support': {
    description: 'Customer support agents',
    pinnedContext: ['policy:$orgId#refund-policy'],
  },
  'policy:$orgId': {
    description: 'Company policies',
    access: [{ principal: 'org:$orgId', role: 'viewer' }],
    pages: [
      { key: 'refund-policy', name: 'Refund Policy', description: 'Refund limits and approvals' },
    ],
  },
},
```

每個條目都是一個頁面路徑。它的佔位符從運行所保留的範圍中取得它們的值。跑步控股`role:acme:support` gets `policy:acme#refund-policy`, and a run holding `role:globex:support` gets `policy:globex#refund-policy`. The run must also be able to read the page, here through its `org:` scope:

|跑跑步|取得退款政策固定 |
| - | - |
|`org:acme`, `role:acme:support` | Yes |
| `org:acme`, `role:acme:sales` | No, but it can read the page with the tools |
| `org:globex`, `role:globex:support` | No, it gets `policy:globex#refund-policy` instead |

知識在每次跑步時都會找出路徑。將其指向目標範圍中聲明的範本頁面`pages`, as in the example. Because tools can't move template pages, the pin keeps working. A pin whose page doesn't exist yet, or has no body, delivers nothing and reports no error. Support runs here are only viewers, so write the policy's body from your server with [`upsertPage()`](/docs/knowledge/load-your-content).

即使超出預算，固定在配置中的頁面也始終會交付。特工無法取消它們。若要刪除一個，請變更聲明。

## 讓Agent固定頁面 {/* #let-agents-pin-pages */}

Agent在運行時使用以下命令固定和取消固定頁面[`knowledge_pin`](/reference/knowledge/knowledge-tools#knowledge_pin) tool. Each pin has an **audience**: the scopes whose runs get the page. For example, an agent can pin the refund policy for `role:acme:support`. A pin an agent stores follows its page when the page moves.

要固定或取消固定頁面，運行需要以下兩項：

* `editor`在頁面的範圍內。
* 對於觀眾中的每個範圍，要么持有它，要么擁有`editor` on it through a rule.

在這裡，政策管理員可以固定頁面以在自己的組織中運行支援：

```typescript title="src/mastra/knowledge.ts" oxfmt:false
scopes: {
  ...knowledgeMemoryScopes(),
  'role:$orgId:policy-admin': { description: 'Edits company policy' },
  'role:$orgId:support': {
    description: 'Customer support agents',
    access: [{ principal: 'role:$orgId:policy-admin', role: 'editor' }],
  },
  'policy:$orgId': {
    description: 'Company policies',
    access: [
      { principal: 'org:$orgId', role: 'viewer' },
      { principal: 'role:$orgId:policy-admin', role: 'owner' },
    ],
  },
},
```

Acme 策略管理員可以固定`role:acme:support`, but not for `role:globex:support`. Support runs still need to be able to read the page to get it.

`editor`在角色作用域上還允許運行在那裡創建頁面，並且沒有人可以在沒有權限的情況下讀取這些頁面`self` rule. Keep pages in content scopes such as `policy:`, and use role scopes only as audiences.

## 固定列表 {/* #pinned-listings */}

固定清單將某個範圍下的頁面或頁面放入上下文中，其方式[`knowledge_list`](/reference/knowledge/knowledge-tools#knowledge_list) returns them: each page's ref, name and child count. Pin a listing when the agent needs to know what exists and where, such as the sections of a docs site, so it can go straight to the right page with `knowledge_read`. Pin a page when the agent needs its content on every turn.

將清單新增至範圍`pinnedContext` as `{ list, depth }`. `list` names a scope or a page path, and `depth` is how many levels below it to show, from 1 to 3 (default 1):

```typescript title="src/mastra/knowledge.ts"
import { Knowledge, knowledgeMemoryScopes } from '@mastra/core/knowledge'
import { LibSQLStore } from '@mastra/libsql'

export const knowledge = new Knowledge({
  id: 'docs',
  storage: new LibSQLStore({ id: 'knowledge', url: 'file:./mastra.db' }),
  tools: true,
  pinnedContext: true,
  scopes: {
    ...knowledgeMemoryScopes(),
    'site:$siteId': {
      description: 'A website',
      access: [{ principal: 'self', role: 'viewer' }],
      pinnedContext: [{ list: 'site:$siteId', depth: 1 }],
    },
  },
})
```

每次跑步堅持`site:mastra` gets the listing:

```text
Pages under site:mastra (site:mastra, depth 1):
- site:mastra#docs — Docs (2 children)
- site:mastra#blog — Blog
- site:mastra#pricing — Pricing
```

清單遵循與固定頁面相同的規則：

* 它只顯示運行可以讀取的頁面，與`knowledge_list`. A run that can't read the listed scope or page gets nothing.
* 當新增、重新命名或刪除列出的頁面時，它會在下一輪更新。
* 它需要一個引腳槽`maxPins` and shares the `maxTokens` budget with pinned pages.

不適合的清單一次填入一個等級：每個適合的第一級頁面，然後是第二級頁面，一直到`depth`. When pages are left out, it ends with a pointer that tells the agent to continue with `knowledge_list`. With the default 500-token budget, a large scope may show only its first level, so raise `maxTokens` to show deeper levels. See [Limits](/reference/knowledge/limits) for the listing caps.

Agent在運行時固定列表`knowledge_pin` and `kind: "list"`, which needs the same roles as pinning a page. The `site:` runs above are only viewers, so this call needs a run with an `editor` rule on `site:mastra`:

```json
{ "op": "pin", "kind": "list", "depth": 2, "page": "site:mastra#docs", "audience": ["site:mastra"] }
```

頁面可以同時具有頁面固定和列表固定，並且每個固定和取消固定都是分開的。看[`knowledge_pin`](/reference/knowledge/knowledge-tools#knowledge_pin) for the arguments.

## 跑步收到什麼 {/* #what-a-run-receives */}

在每一輪中，Knowledge 都會以以下順序建立運行的固定上下文：

1. 對於運行所包含的每個範圍，頁面和清單固定在配置中。如果超出預算，每個人都會縮短到均等份額。
2. 由Agent程式針對運行所涉及的任何範圍固定的頁面和列表，首先是最高優先級，然後是最新的。已在配置中的引腳不會重複。
3. 不適合的引腳按名稱列出，因此Agent可以使用讀取Tool打開它們。



範圍的`pinnedContextPriority` sets its priority, `0` by default. `knowledgeMemoryScopes()` gives `thread:` a priority of 2, `resource:` 1 and `org:` 0, so a pin for one user ranks above a pin for the whole org.
