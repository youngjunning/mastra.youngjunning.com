# Monorepo

從 monorepo 部署 Mastra，做法與部署獨立應用程式相同。這份指南集中說明 monorepo 需要留意的地方。基本建構及部署步驟見[部署 Mastra 伺服器](/docs/deployment/mastra-server)。

## 支援哪些 monorepo 工具 {/* #supported-monorepos */}

Mastra 支援以下工具：

- npm 工作區
- pnpm 工作區
- Yarn 工作區
- Turborepo

已知限制如下：

- Bun 工作區：部分支援，有已知問題
- Nx：可使用 Nx [支援的相依性管理策略](https://nx.dev/concepts/decisions/dependency-management)，前提是各工作區套件內都有 `package.json`

## 目錄結構示例 {/* #example-structure */}

以下示例把 Mastra 應用程式放在 `apps/api`：

```text
apps/
├── api/
│   ├── src/
│   │   └── mastra/
│   │       ├── agents/
│   │       ├── tools/
│   │       ├── workflows/
│   │       └── index.ts
│   ├── package.json
│   └── tsconfig.json
└── web/
packages/
├── ui/
└── utils/
package.json
```

## 從 monorepo 建構 {/* #building-from-a-monorepo */}

透過 monorepo 工具對準要建構的套件執行指令，無須加上特別的命令列選項。

例如：

<Tabs>
  <TabItem value="npm" label="npm">
    ```bash
    npm run build --workspace=apps/api
    ```
  </TabItem>

  <TabItem value="pnpm" label="pnpm">
    ```bash
    pnpm --filter api run build
    ```
  </TabItem>

  <TabItem value="yarn" label="yarn">
    ```bash
    yarn workspace api build
    ```
  </TabItem>

  <TabItem value="turborepo" label="Turborepo">
    ```bash
    turbo run build --filter=api
    ```
  </TabItem>
</Tabs>

套件的 `build` 指令碼應運行 `mastra build`：

```json title="apps/api/package.json"
{
  "scripts": {
    "build": "mastra build"
  }
}
```

## 工作區套件 {/* #workspace-packages */}

如果 Mastra 應用程式需要匯入其他工作區套件，Mastra 會自動處理：

- 如套件已用 `tsc`、`tsdown` 等工具預先編譯，Mastra 會匯入編譯後的 JavaScript
- 如套件包含未經編譯的 TypeScript，Mastra 會在建構時轉譯

一般無須額外配置；若匯入工作區套件時出現問題，可將該套件加入 [`transpilePackages`](/reference/configuration#bundlertranspilepackages)：

```typescript title="src/mastra/index.ts"
import { Mastra } from '@mastra/core'

export const mastra = new Mastra({
  bundler: {
    transpilePackages: ['@my-org/utils'],
  },
})
```

`bundler` 必須是傳入 `new Mastra()` 的物件的最外層屬性。入口檔案支援的結構見[建構時配置](/docs/deployment/mastra-server#build-time-configuration)。

## 環境變數 {/* #environment-variables */}

`.env` 檔案應放在 Mastra 應用程式的目錄，例如 `apps/api/.env`，不應放在 monorepo 的根目錄。

## 部署配置 {/* #deployment-configuration */}

部署到雲端服務時，請留意部署目標是否指向正確的套件。常見錯誤是選了 monorepo 根目錄，漏選應用程式目錄（例如 `apps/api`）。

大部分雲端服務都讓你在管理介面或配置檔案指定根目錄。

## 管理相依套件 {/* #dependency-management */}

為免版本衝突或建構出錯，請保持各套件的相依性一致：

- 在 monorepo 根目錄使用**同一份鎖定檔**，讓各套件解析到相同的版本
- 統一 **共用程式庫**（例如 Mastra 或框架）的版本，以免重複

### 跳過安裝相依套件 {/* #skipping-dependency-installation */}

在預設設定下，`mastra build` 會把套件管理工具的鎖定檔複製到 `.mastra/output`，再由套件管理工具一次過更新鎖定檔並安裝相依套件。在 CI 也會照常更新。若原本沒有鎖定檔，Mastra 會使用 npm 並產生 `package-lock.json`。Bazel 等封閉式建構系統會從外部提供 `node_modules`，並在沒有網絡的沙盒執行。此時安裝相依套件並無必要，亦會令建構失敗。

把 `MASTRA_BUILD_SKIP_INSTALL` 設為 `true` 或 `1`，便可跳過更新鎖定檔和在輸出目錄安裝相依套件的步驟：

```bash
MASTRA_BUILD_SKIP_INSTALL=1 mastra build
```

啟用後，你須自行在輸出目錄提供 `node_modules`。

## 排解問題 {/* #troubleshooting */}

### 找不到工作區套件 {/* #workspace-package-not-found */}

如果 Mastra 無法解析某個工作區套件，請檢查：

- 該套件已列在 `package.json` 的相依項目中
- 鎖定檔已更新（可執行 `pnpm install` 或 `npm install` 等指令）
- 該套件有有效的 `main` 或 `exports` 欄位，並在其 `package.json` 中設定

### 工作區套件出現 TypeScript 錯誤 {/* #typescript-errors-from-workspace-packages */}

若類型錯誤來自未編譯的工作區套件，可以採用以下其中一個做法：

- 先建構該套件（建議採用，可加快 Mastra 的建構）
- 在 Mastra 配置中把該套件加入 [`transpilePackages`](/reference/configuration#bundlertranspilepackages)
