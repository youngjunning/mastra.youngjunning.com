# Mastra 伺服器

Mastra 會把應用程式編譯為獨立的 Node.js 伺服器，可在任何支援 Node.js、Bun 或 Deno 的平台上運行。

:::tip

本指南介紹如何部署由 `mastra build` 產生的獨立伺服器。如需將 Mastra 整合到現有的 Express 或 Hono 應用程式，請見[伺服器轉接器](/docs/server/server-adapters)。

:::

## 建置應用程式 {/* #building-your-application */}

在專案的根目錄執行建置指令：

```bash
mastra build
```

建置會建立 `.mastra` 目錄，內有可供正式環境使用的伺服器。各項可用選項見 [`mastra build` 參考文件](/reference/cli/mastra#mastra-build)。

## 建置輸出 {/* #build-output */}

建置後，Mastra 會建立以下目錄結構：

```text
.mastra/
├── .build/                # Intermediate build artifacts (module maps, analysis)
└── output/
    ├── index.mjs          # Server entry point
    ├── mastra.mjs         # Your bundled Mastra configuration
    ├── tools.mjs          # Aggregated tool exports
    ├── tools/             # Individual tool bundles
    ├── package.json       # Production dependencies
    ├── node_modules/      # Installed dependencies
    ├── .npmrc             # Copied from your project (if present)
    ├── <static assets>     # Contents of src/mastra/public, merged into the output root
    └── playground/        # Studio UI (if --studio flag used)
```

`output` 目錄已包含運行所需的內容，可複製到任何伺服器直接運行。

:::warning[請勿將資料庫檔案放在 `src/mastra/public`]

建置時會把 `src/mastra/public` 的內容複製到 `.mastra/output`，並覆寫同名檔案。因此，儲存在 `public` 的 SQLite 資料庫會一併複製到建置輸出。`file:./mastra.db` 等 URL 以伺服器的運行目錄為基準解析。若從輸出目錄運行，伺服器開啟的便是資料庫副本，對副本的修改會在下次建置時遺失。請將資料庫檔案放在 `public` 之外。

:::

## 運行伺服器 {/* #running-the-server */}

可透過 Mastra CLI 啟動伺服器：

```bash
mastra start
```

亦可直接透過 Node.js 運行：

```bash
node .mastra/output/index.mjs
```

`mastra start` 指令亦提供以下功能：

- 從 `.env.production` 及 `.env` 載入環境變數。
- 缺少模組時會提供錯誤訊息，協助排查問題。
- 處理程序訊號，以便有序關閉。

各項可用選項見 [`mastra start` 參考文件](/reference/cli/mastra#mastra-start)。

## 建置設定 {/* #build-configuration */}

### 建置時的設定 {/* #build-time-configuration */}

建置應用程式時，Mastra 會讀取 `bundler`、`deployer` 及 `server` 選項。這些選項須為傳給 `new Mastra()` 的物件的直接屬性，建置程序才可擷取。

入口檔案可採用以下寫法：

```typescript title="src/mastra/index.ts"
import { Mastra } from '@mastra/core/mastra'

export const mastra = new Mastra({
  bundler: {
    externals: ['sharp'],
  },
  server: {
    port: 4111,
  },
})
```

各選項的值可來自變數、匯入或函式呼叫，但選項本身須是物件的直接屬性。請勿透過呼叫工廠函式或展開物件，間接帶入建置時的選項：

```typescript title="src/mastra/index.ts"
import { Mastra } from '@mastra/core/mastra'

const options = {
  bundler: {
    externals: ['sharp'],
  },
}

// These patterns prevent Mastra from extracting `bundler` during the build.
export const mastra = new Mastra(createMastraOptions())
export const otherMastra = new Mastra({ ...options })
```

如 Mastra 無法擷取某個選項，建置時會按該選項的預設行為處理。可用的 `bundler`、`deployer` 及 `server` 設定見[設定參考](/reference/configuration)。

### 公開資源資料夾 {/* #public-folder */}

如果 Mastra 目錄包含 `public` 資料夾（`src/mastra/public`），建置時會把當中的內容複製到輸出目錄。伺服器會以靜態資源的形式提供這些檔案。

### Mastra 設定 {/* #mastra-configuration */}

建置程序會按 Mastra 實例的設定執行。CORS、逾時及中介軟件等伺服器行為見[伺服器概覽](/docs/server/overview)。完整選項見[設定參考](/reference/configuration)。

## 建置流程 {/* #build-process */}

建置會按以下步驟進行：

1. **尋找入口檔案**：在 Mastra 目錄查找 `index.ts` 或 `index.js`。
1. **掃描 Tool 檔案**：找出符合 `{mastraDir}/tools/**/*.{js,ts}` 的檔案，並排除測試檔案。
1. **分析依賴項目**：判斷哪些套件須打包，哪些須另行安裝。
1. **打包程式碼**：使用 Rollup，採用 tree shaking，並可選擇產生 source map。
1. **建立伺服器**：產生以 Hono 為基礎的 HTTP 伺服器，輸出為 `index.mjs`。
1. **安裝依賴項目**：在輸出目錄執行 `npm install`。
1. **複製資源**：如有 `public` 資料夾或 `.npmrc`，便會一併複製。

## 環境變數 {/* #environment-variables */}

| 變數 | 說明 |
| - | - |
| `PORT` | 伺服器連接埠，預設為 `4111`。 |
| `MASTRA_STUDIO_PATH` | Studio 建置目錄的路徑，預設為 `./playground`。 |
| `MASTRA_SKIP_DOTENV` | 設定後會略過 `.env` 檔案的載入。 |
| `NODE_OPTIONS` | Node.js 選項，例如建置遇到記憶體問題時可用 `--max-old-space-size=4096`。 |

## 伺服器端點 {/* #server-endpoints */}

建置後的伺服器會提供健康檢查、Agent、Workflow 等端點：

| 端點 | 說明 |
| - | - |
| `GET /health` | 健康檢查端點，回傳 `200 OK`。 |
| `GET /api/openapi.json` | OpenAPI 規格，在啟用 `server.build.openAPIDocs` 時提供。 |
| `GET /swagger-ui` | 互動式 API 文件，在啟用 `server.build.swaggerUI` 時提供。 |

如需查閱所有端點，請執行 `mastra dev` 並前往 `http://localhost:4111/swagger-ui`。

如要加入自己的端點，請見[自訂 API 路由](/docs/server/custom-api-routes)。

## 有序關閉及滾動部署 {/* #graceful-shutdown-and-rolling-deploys */}

產生的伺服器預設會處理 `SIGINT` 和 `SIGTERM`。它會停止接受新連線，讓處理中的請求及串流有時間完成，最多等候 [`server.drainTimeout`](/reference/configuration#serverdraintimeout) 指定的時間，然後執行 `mastra.shutdown()`。關閉時，仍在執行的 Workflow（包括持久化 Agent 的執行）同樣有這段時間完成，之後才會關閉工作程序和發佈／訂閱機制的訂閱。若限時過後持久化 Agent 仍在執行，系統會將其停止並解除對該次執行的佔用，讓服務下次啟動時可立即復原。預設等候時間為 5 秒。收到第二次訊號會立即終止程序。如需自行管理訊號，請見 [`server.handleShutdownSignals`](/reference/configuration#serverhandleshutdownsignals)。

隨後，關閉流程會交還該程序仍持有的 Agent 對話執行緒上的執行：

- 尚在執行的作業會被中止，後續步驟不再啟動。其他程序中監察該對話執行緒的客戶端會看到執行結束，未完成的回應不會儲存。
- 等待 Tool 審批或已暫停的執行會維持暫停，可從其他程序恢復。如果同一步驟仍有 Tool 呼叫在執行，會先將該呼叫中止，處理方式與仍在執行的作業相同。
- 系統會立即嘗試解除對話執行緒的租約，讓其他程序毋須等候租約到期，便可在該執行緒啟動新的執行。如中止的作業未能及時停止（例如 Tool 呼叫忽略中止要求），或租約後端沒有回應或未能解除租約，租約會保留至到期。

等候時間結束後，交還執行最多可能再需約 1.5 秒。

如託管平台的終止寬限期可容納較長的 Agent 回合，可調高 `drainTimeout`。HTTP 及 Workflow 會先後等候完成，須為兩段等候時間、交還對話執行緒上的執行所需的約 1.5 秒，以及關閉時的清理預留足夠時間。

如自行呼叫 `mastra.shutdown()`，可傳入 `drainTimeout`，指定等候進行中的 Workflow 完成的時限：

```typescript
await mastra.shutdown({ drainTimeout: 30_000 })
```

```typescript title="src/mastra/index.ts"
import { Mastra } from '@mastra/core/mastra'

export const mastra = new Mastra({
  server: {
    drainTimeout: 240_000,
  },
})
```

一般的 `agent.stream()` 呼叫在伺服器程序退出後無法恢復。如果串流結束時未收到預期的終止事件，應將該回合視為中斷，讓客戶端重試或協調狀態。如需在更換程序後繼續執行回合，請使用[持久化 Agent](/docs/harness/durable-agents)。[故障復原](/docs/harness/durable-agents#crash-recovery)需要共用的持久執行儲存及[具冪等性的 Tool](/docs/harness/durable-agents#make-tools-safe-to-repeat)。預設事件快取只存於記憶體，因此如需在重啟後重播遺漏的事件，還須使用 Redis 等共用的持久快取。如有多個副本，復原時須使用支援執行隔離（run fencing）的儲存轉接器，或使用所有副本均共用同一租約的 PubSub 後端。見[多實例部署](/docs/harness/durable-agents#multi-instance-deployments)。

## 故障排查 {/* #troubleshooting */}

### 建置期間出現記憶體錯誤 {/* #memory-errors-during-build */}

如遇上 `JavaScript heap out of memory` 錯誤：

```bash
NODE_OPTIONS="--max-old-space-size=4096" mastra build
```
