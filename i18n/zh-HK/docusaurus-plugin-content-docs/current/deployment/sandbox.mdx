# Sandbox

`@mastra/deployer-sandbox` 會把包含 Studio 的完整 Mastra 伺服器部署至臨時 Workspace Sandbox，並返回可存取的公開 URL。再次部署時，部署器可略過安裝依賴套件，因此可能更快完成。

Sandbox 部署適用於：

- Agent 建立的應用程式：由 Agent 產生並部署 Mastra 專案，驗證結果。
- 持續整合 (CI)：啟動實際伺服器進行檢查，完成後移除。
- 即時預覽：合併前與團隊分享可運作的 Agent。
- 多租戶不可信程式碼：為每名用戶運行與自身基礎設施隔離的 Mastra 實例。

Sandbox 有由 Provider 強制執行的運行時間上限，亦會到期。正式環境託管方式見[部署概覽](/docs/deployment/overview)。

## 支援的 Sandbox {/* #supported-sandboxes */}

部署器適用於任何支援網絡連接（公開連接埠 URL）的 Workspace Sandbox：

* [Vercel Sandbox](/integrations/sandboxes/vercel#vercel-sandbox) (`@mastra/vercel`)
* [E2B](/integrations/sandboxes/e2b) (`@mastra/e2b`)
* [Daytona](/integrations/sandboxes/daytona) (`@mastra/daytona`)

Provider 開發者可在 [`WorkspaceSandbox`](/reference/workspace/sandbox) 實作可選的 `networking` 功能，加入支援。

## 快速入門 {/* #quickstart */}

安裝部署器及所選的 Sandbox Provider。以下示例使用 Vercel Sandbox：

```bash npm2yarn
npm install @mastra/deployer-sandbox @mastra/vercel
```

在 `src/mastra/index.ts` 配置部署器。`sandboxName` 用作部署標識；之後以相同名稱部署，會重用現有 Sandbox。

```typescript title="src/mastra/index.ts"
import { Mastra } from '@mastra/core/mastra'
import { SandboxDeployer } from '@mastra/deployer-sandbox'
import { VercelSandbox } from '@mastra/vercel'

export const mastra = new Mastra({
  deployer: new SandboxDeployer({
    sandbox: new VercelSandbox({
      sandboxName: 'my-preview',
      timeout: 2_400_000, // 40 minutes
      ports: [4111],
    }),
  }),
})
```

Vercel 有兩個附加要求：

- `timeout` 不可超過方案容許的 Sandbox 最長存續時間；Pro 方案為 45 分鐘。設定更高的值會令 Vercel API 返回 400，部署失敗。
- 在 `ports` 聲明伺服器連接埠。與 E2B、Daytona 不同，Vercel 只開放建立時聲明的連接埠。

在一個命令中建置和部署：

```bash
mastra build
```

配置 `SandboxDeployer()` 後，`mastra build` 會封裝專案並部署至 Sandbox。部署時會輸出 API 和 Studio URL，並在 `.mastra/output` 寫入 `sandbox-deployment.json` 清單：

```text
API:    https://<sandbox-id>-4111.vercel.run/api
Studio: https://<sandbox-id>-4111.vercel.run
```

若 Sandbox Provider 提供到期時間，清單便會包含 `expiresAt`。

重新部署至同一 Sandbox 時，如輸入沒有改變，便會略過安裝依賴套件。輸入雜湊涵蓋 `package.json`、安裝指令及一併封裝的鎖定檔。

### URL 對應的服務 {/* #what-the-urls-serve */}

Studio URL 是 Sandbox 根網址，不含 `/api`。在瀏覽器開啟即可使用 Studio。若部署時設定 `studio: false`，根網址會改為顯示 Mastra 歡迎頁面。

API URL 只是下層端點的前綴，例如 `/api/agents`。`/api` 本身沒有處理程式，所以即使伺服器運作正常，在瀏覽器開啟它仍會返回「Not Found」。

若要檢查部署，請直接呼叫端點：

```bash
curl -s -X POST https://4111-<sandbox-id>.e2b.app/api/agents/weatherAgent/generate \
  -H "Content-Type: application/json" \
  -d '{"messages":[{"role":"user","content":"Weather in London"}]}' | jq -r '.text'
```

### Provider 憑證 {/* #provider-credentials */}

各 Provider 使用自己的憑證驗證身分。請設定目標 Sandbox 所需的憑證：

```bash title=".env"
# E2B
E2B_API_KEY=

# Daytona
DAYTONA_API_KEY=

# Vercel
VERCEL_TOKEN=
VERCEL_TEAM_ID=
VERCEL_PROJECT_ID=
```

各 Provider 亦接受以建構函式選項傳入憑證。自行託管的 E2B 及 Daytona 分別使用 `E2B_DOMAIN` 或 `DAYTONA_API_URL`。

與 `mastra dev` 不同，`mastra build` 不會載入 `.env` 檔案。部署會在建置期間執行，因此從環境讀取憑證的 Sandbox Provider，例如使用 `E2B_API_KEY` 的 E2B，會讀到空值，並因身分驗證錯誤而部署失敗。

在 `src/mastra/index.ts` 加上 `import 'dotenv/config'` 並不能解決問題。為找出部署器，建置程序只會從入口檔案擷取 `deployer` 選項，並透過 tree shaking 移除其他內容，包括該匯入。

建置前先把 `.env` 檔案載入 shell 環境。可以使用 [`dotenv-cli`](https://www.npmjs.com/package/dotenv-cli)：

```bash npm2yarn
npm install --save-dev dotenv-cli
```

```json title="package.json"
{
  "scripts": {
    "deploy": "dotenv -e .env -- mastra build"
  }
}
```

之後執行 `npm run deploy`。腳本名稱應反映它會部署，因為配置 `SandboxDeployer()` 後，`mastra build` 就會執行部署。請與一般的 `build` 腳本分開，以免託管平台或 CI 工作執行 `npm run build` 時意外部署 Sandbox。

在持續整合 (CI) 中，應以 secret 形式匯出憑證。無論採用甚麼方式，變數都須存在於 shell 環境，而非只存放在 `.env` 檔案。

上述要求適用於部署器在本機所需的憑證。已部署伺服器需要的變數則另行處理：部署器會讀取 `.env`、`.env.production` 和 `.env.local`，並把變數注入 Sandbox。詳見[保安](#security)。

### 使用E2B {/* #using-e2b */}

對 E2B 而言，`id` 用來標識部署。後續使用相同值部署時，會重新連接現有 Sandbox，不論它正運行還是已暫停。

```typescript title="src/mastra/index.ts"
import { SandboxDeployer } from '@mastra/deployer-sandbox'
import { E2BSandbox } from '@mastra/e2b'

const deployer = new SandboxDeployer({
  sandbox: new E2BSandbox({
    id: 'my-preview',
    template: 'base',
    timeout: 3_600_000, // 1 hour
  }),
})
```

除非需要掛載檔案系統，否則應傳入 `template: 'base'`；若未傳入，Provider 首次使用時會建立自訂的 Filesystem in Userspace (FUSE) 範本。E2B 會暫停而非停止：`stop()` 為整部虛擬機器 (VM) 建立快照，包括記憶體和正在運行的進程。暫停的 Sandbox 喚醒後，Mastra 伺服器會從暫停處繼續，不用像 Vercel 一樣重新啟動。

### 使用 Daytona {/* #using-daytona */}

在 Daytona，`id` 用來標識部署。後續以相同值部署，會重新連接現有 Sandbox。設定 `public: true`，可讓預覽 URL 毋須權杖即可存取。

```typescript title="src/mastra/index.ts"
import { SandboxDeployer } from '@mastra/deployer-sandbox'
import { DaytonaSandbox } from '@mastra/daytona'

const deployer = new SandboxDeployer({
  sandbox: new DaytonaSandbox({
    id: 'my-preview',
    public: true,
    autoStopInterval: 30, // minutes
  }),
})
```

Daytona Sandbox 停止後保留檔案系統，但不保留正在運行的進程。因此與 Vercel 類似，使用 `wake: true` 喚醒時，解析器會重新啟動伺服器。

Daytona 按目的地過濾對外流量。某些主機的傳輸層安全協定 (TLS) 連線正常，另一些則在交握時被重設；Agent 或工具只會看到 Node 的一般錯誤 `fetch failed`。開始排查程式碼前，先在 Sandbox 內對同一主機執行 `curl`，確認是否為連線問題：

```typescript
const sandbox = new DaytonaSandbox({ id: 'my-preview' })
await sandbox.start()

const result = await sandbox.executeCommand('curl -v --max-time 10 https://api.example.com')
console.info(result.stdout, result.stderr)
```

TLS 交握時出現 `Connection reset by peer`，問題便較可能是流量過濾，而非 Agent。請 Daytona 支援團隊開放該目的地。受限制的 Daytona 方案也會封鎖雲端儲存端點；掛載輔助函式會回報專用錯誤。

## 以程式設計方式部署 {/* #deploying-programmatically */}

`deployToSandbox()` 不經過打包器，直接部署預先建置的輸出目錄。與 `SandboxDeployer()` 不同，只有傳入 `studio: true` 才會包含 Studio。可在 CI 或 Agent 程式碼中使用：

```typescript
import { deployToSandbox } from '@mastra/deployer-sandbox'
import { VercelSandbox } from '@mastra/vercel'

const deployment = await deployToSandbox({
  sandbox: new VercelSandbox({ sandboxName: 'ci-smoke', ports: [4111] }),
  dir: '.mastra/output',
})

console.info(deployment.url) // https://<sandbox-id>-4111.vercel.run
await deployment.logs() // tail the server log
await deployment.stop() // stop the sandbox (resumable)
await deployment.destroy() // permanently delete the sandbox
```

## 生命週期 {/* #lifecycle */}

### 管理部署 {/* #managing-a-deployment */}

使用 `@mastra/deployer-sandbox/client` 匯出的伺服器端專用 `getDeployment()`，取得現有部署。它以 Provider 專屬配置標識 Sandbox，例如 Vercel 的 `sandboxName`，或 E2B、Daytona 的 `id`。查詢不依賴當初建立部署的進程，亦可從其他伺服器端服務或 CI 使用。

```typescript title="scripts/stop.ts"
import { getDeployment } from '@mastra/deployer-sandbox/client'
import { VercelSandbox } from '@mastra/vercel'

const deployment = await getDeployment({
  sandbox: new VercelSandbox({ sandboxName: 'my-preview', ports: [4111] }),
  port: 4111,
})

console.info(deployment.status, deployment.url)
await deployment.logs() // tail the server log
await deployment.stop() // stop the sandbox (resumable)
await deployment.destroy() // permanently delete the sandbox
```

傳入 `wake: true`，可在返回前恢復已停止的 Sandbox。只有恢復後伺服器不健康時，才會重新啟動。亦可使用 Provider 工具，例如 `vercel sandbox ls`、`vercel sandbox stop` 及 `vercel sandbox rm`。

### 過期時間和 URL {/* #expiry-and-urls */}

Sandbox 按 Provider 的運行時間限制到期。若 Provider 回報到期時間，部署日誌會記錄，程式亦可透過 `deployment.expiresAt` 讀取。

Sandbox 停止再恢復後，URL 可能改變。URL 只是連線位址；Sandbox 身分（例如 `sandboxName`）才是穩定的操作依據。以下路由層級用來處理 URL 變更。

## 路由層 {/* #routing-tiers */}

### 第 1 層：直接 URL {/* #tier-1-direct-url */}

直接使用列印的 URL 進行開發、演示和 CI，其中每次部署都可以使用新的 URL。

### 第 2 層：運行時解析 {/* #tier-2-resolve-at-runtime */}

`getDeployment()` 在運行時解析當前 URL，使用方毋須保存可能已失效的 URL。任何知道 Sandbox 名稱的伺服器都能解析，即使它位於另一個程式碼庫：

```typescript title="app/api/agent-url/route.ts"
import { getDeployment } from '@mastra/deployer-sandbox/client'
import { VercelSandbox } from '@mastra/vercel'

const deployment = await getDeployment({
  sandbox: new VercelSandbox({ sandboxName: 'my-preview', ports: [4111] }),
  wake: true,
})

console.info(deployment.url, deployment.status)
```

使用預設的 `wake: false`，不會啟動 Sandbox，只會取得可供處理的 `{ url, status }`。解析 URL、`stop()` 和 `destroy()` 會按名稱連接現有 Sandbox，卻不會恢復它；因此對已停止 Sandbox 進行生命週期操作，不會喚醒它或開始計費。使用 `wake: true` 時，Sandbox 會恢復；若伺服器沒有回應，便會重新啟動。是否需要重啟視乎 Provider：Vercel 和 Daytona 只恢復檔案系統，不恢復運行中的進程；E2B 則恢復包含伺服器進程的整部 VM。

:::warning

`@mastra/deployer-sandbox/client` 只供伺服器端使用。解析 Sandbox 所需的 Provider 憑證絕不可傳到瀏覽器。在瀏覽器環境匯入模組會拋出錯誤。

:::

### 第 3 層：最終使用者的穩定 URL {/* #tier-3-stable-url-for-end-users */}

在自己的網域提供固定 URL 給最終用戶，再透過路由處理程式代理或 Edge Config 別名，從伺服器端把請求轉發至 Sandbox。

以下示例採用 Vercel 和 Next.js，但任何能轉發請求的伺服器端框架或 Provider 都可運用同一做法。

- **路由處理程式代理。** `createSandboxHandler()` 會快取 Sandbox URL，並在連線層出錯後重新解析，應對 URL 變更及冷啟喚醒：

  ```typescript title="app/api/[...path]/route.ts"
  import { createSandboxHandler, getDeployment } from '@mastra/deployer-sandbox/client'
  import { VercelSandbox } from '@mastra/vercel'

  const handler = createSandboxHandler({
    resolve: async () => {
      const deployment = await getDeployment({
        sandbox: new VercelSandbox({ sandboxName: 'my-preview', ports: [4111] }),
        wake: true,
      })
      return deployment.url!
    },
  })

  export { handler as GET, handler as POST }
  ```

- **Edge Config 別名。** 在部署器設定 `alias` 選項，使 [Vercel Edge Config](https://vercel.com/docs/edge-config) 項目在每次部署後指向當前 URL：

  ```typescript title="src/mastra/index.ts"
  const deployer = new SandboxDeployer({
    sandbox: new VercelSandbox({ sandboxName: 'my-preview', ports: [4111] }),
    alias: { edgeConfigId: 'ecfg_...', key: 'my-preview', token: process.env.VERCEL_TOKEN! },
  })
  ```

  然後在 Next.js 中介軟件使用 `createSandboxProxy()` 重寫請求：

  ```typescript title="middleware.ts"
  import { createSandboxProxy } from '@mastra/deployer-sandbox/client'

  export const middleware = createSandboxProxy({ key: 'my-preview' })
  export const config = { matcher: '/api/:path*' }
  ```

## 持續集成範例 {/* #ci-example */}

在每個拉取請求上部署預覽：

```yaml title=".github/workflows/preview.yml"
name: Sandbox preview
on: pull_request

jobs:
  preview:
    runs-on: ubuntu-latest
    env:
      VERCEL_TOKEN: ${{ secrets.VERCEL_TOKEN }}
      VERCEL_TEAM_ID: ${{ secrets.VERCEL_TEAM_ID }}
      VERCEL_PROJECT_ID: ${{ secrets.VERCEL_PROJECT_ID }}
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-node@v4
        with:
          node-version: 22
      - run: npm ci
      - run: npx mastra build
      - run: curl --fail "$(jq -r .url .mastra/output/sandbox-deployment.json)/api"
```

## 安全 {/* #security */}

- Sandbox URL 是公開的。任何知道 URL 的人都能存取 Mastra 伺服器，包括 Studio。除一次性預覽外，應啟用[伺服器身分驗證](/docs/auth/overview)。
- `.env` 檔案中的環境變數會注入遠端 Sandbox VM，供伺服器運行。部署日誌會為此輸出警告。不要部署不適合放在共用預覽伺服器的機密。
- 如需限制第 3 層流量，請向 `createSandboxHandler()` 或 `createSandboxProxy()` 傳入 `secret`。這些輔助函式會把該值放入轉發請求的 `x-mastra-sandbox-secret` 標頭。配置[伺服器身分驗證](/docs/auth/overview)以強制要求此標頭，便可拒絕直接訪問 Sandbox URL 的請求，同時容許透過自有網域訪問。
