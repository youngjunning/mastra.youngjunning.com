# 目標

**加入版本** `@mastra/core@1.43.0`

目標是儲存在 Thread 內的長期指令。Agent 會在各輪迭代繼續推進，直至評判模型裁定目標已達成，或執行預算用盡。

目標會保存在 Thread 狀態，重新載入後仍然有效。即使正在執行的一輪途中收到新訊息，迴圈也會繼續評估目標。

目標沿用 [`isTaskComplete`](/docs/subagents) 的機制。LLM 在每輪迭代為 Agent 的輸出評分，決定迴圈是否繼續。目標會持久保存在 Thread 狀態，並透過 `Agent` 方法設定和更新，毋須在每次呼叫 `stream()` 時傳入選項。

## 適合使用目標的情況 {/* #when-to-use-goals */}

若希望 Agent 在多輪迭代及訊息中持續推進同一目標，毋須每次呼叫都重傳達成條件，可設定目標。

* Agent 要繼續推進，直至評判模型確認完成。
* 執行途中收到新訊息後仍須繼續工作，新訊息亦會按同一目標評估。
* 重新載入 Thread 或重啟程序後，仍須保留目標。

如只需在單次 `stream()` 呼叫中檢查有否完成，請使用 [`isTaskComplete`](/docs/subagents)。

## 快速入門 {/* #quickstart */}

目標需要已配置的 [儲存](/docs/storage) 後端，以及使用 Memory 的 Thread。先為 Agent 加入 `goal` 配置及指定評判模型，再為 Thread 設定目標。

```typescript title="src/mastra/agents/worker.ts" {8-11}
import { Agent } from '@mastra/core/agent'

const worker = new Agent({
  id: 'worker',
  name: 'worker',
  instructions: 'You complete software tasks end to end.',
  model: '__GATEWAY_OPENAI_MODEL__',
  memory,
  goal: {
    judge: '__GATEWAY_OPENAI_MODEL_LUNA__',
    maxRuns: 50,
  },
})

// Set the durable objective for a thread.
await worker.setObjective('Add and test a /health endpoint', {
  threadId,
  resourceId,
})

// The objective is judged each iteration until it's complete or maxRuns is hit.
const stream = await worker.stream('Start working on the goal', {
  memory: { thread: threadId, resource: resourceId },
})
```

`goal` 配置會自動註冊狀態訊號投影，模型毋須額外設定，便可在上下文看到以 `<current-objective>` 呈現的目前目標。

## 目標評估的運作方式 {/* #how-the-goal-step-works */}

目標評估在 Agent 執行迴圈內緊接 `isTaskComplete` 運行。Agent 提出實際候選答案時，這個步驟會按目標為對話評分，決定迴圈是否繼續。

* **尚未達成目標，仍有預算** → 迴圈繼續。每次評估的回饋都會加入上下文，讓 Agent 在下一輪改進。
* **已達成目標** → 迴圈停止，目標標記為 `done`。
* **預算用盡** (`runsUsed >= maxRuns`) → 迴圈停止，目標標記為 `paused`。調高 `maxRuns` 並恢復目標，即可繼續。

與 `isTaskComplete` 一樣，若迭代在處理背景工作、仍在工具呼叫迴圈內，或只更新工作記憶，就會略過這個步驟。

每次評估都會發出具有類型定義的 `goal` 串流區塊，供介面在執行期間顯示進度。其類型為 `GoalEvaluationPayload`，包括 `objective`、`iteration`、`maxRuns`、`passed`、`status`、`results`、`reason`、`duration`、`timedOut`、`maxRunsReached` 及 `suppressFeedback`。

**目標評估須有可用的評判模型才會啟動。** 若個別目標的覆寫設定及 Agent 的 `goal.judge` 都無法提供評判模型，此步驟不會評分、耗用預算或發出 `goal` 區塊。Mastra 會先檢查評判模型，再選擇 Scorer，所以自訂 `goal.scorer` 亦須能解析出評判模型。

設定依次採用個別目標記錄、Agent 的 `goal` 配置及內置預設值（`maxRuns` 為 `50`，並使用預設評判提示）。

### 評判模型與 Scorer {/* #judge-and-scorer */}

`goal.judge` 與 `goal.scorer` 分工不同。`goal.scorer` 是產生分數的評估流程，迴圈按分數決定是否繼續。`goal.judge` 是預設流程用來評分的模型。

省略 `scorer` 時，Mastra 會建立預設 Scorer，由 LLM 評判。達成目標時傳回 `1`；評判模型認為 Agent 正等待用戶輸入時傳回 `0.5`；其他情況傳回 `0`。分數為 `0.5` 時，自動迴圈會停止，目標仍未完成，所以 Agent 的下一輪仍會接受評估。可用以下項目配置預設 Scorer。

* `goal.judge` 指定判斷是否達成目標的模型。
* `goal.prompt` 為評判模型提供額外指令，預設採用內置的目標評判提示。
* `goal.tools` 指定評判模型作出判斷前可呼叫的唯讀驗證工具，讓它核實實際工作成果，避免只按 Agent 的文字評分。
* `goal.maxSteps` 限制評判模型本身的執行迴圈步數，預設為 `5`。

傳入 `goal.scorer` 可用自訂 [Scorer](/reference/evals/create-scorer) 取代預設流程，接受 Scorer 實例或已註冊的 Scorer ID。自訂 Scorer 自行評判，因此 `goal.prompt`、`goal.tools` 及 `goal.maxSteps` 不再適用，Mastra 亦不會為評判另行解析模型。如 `goal.judge` 是解析函數，仍會執行，但其傳回值會被捨棄。

可用 `judge`、`maxRuns` 及 `prompt` 配置預設 Scorer。

```typescript title="src/mastra/agents/worker.ts"
import { Agent } from '@mastra/core/agent'

const worker = new Agent({
  id: 'worker',
  name: 'worker',
  instructions: 'You complete software tasks end to end.',
  model: '__GATEWAY_OPENAI_MODEL__',
  memory,
  goal: {
    // A resolver function lets you inject provider credentials and read the
    // current judge selection at runtime; returning `undefined` keeps the
    // goal step a no-op.
    judge: ({ requestContext }) => resolveJudgeModel(requestContext),
    maxRuns: 30,
    prompt: 'Only mark the goal complete when tests pass.',
  },
})
```

如要由自訂 Scorer 作出判斷，可把它作為 `scorer` 傳入，並保留 `judge` 設定，因為啟動時仍會檢查評判模型。

```typescript oxfmt:false
goal: {
  judge: '__GATEWAY_OPENAI_MODEL_LUNA__',
  // Replaces the built-in judge pipeline. `prompt`, `tools`, and `maxSteps` no longer apply.
  scorer: 'tests-pass',
}
```

## 管理目標 {/* #managing-the-objective */}

可用 `Agent` 方法管理 Thread 的目標。這些方法需要儲存後端及 `threadId`。如執行沒有使用 Memory，呼叫不會有任何作用。

```typescript title="src/mastra/objective.ts"
// Read the current objective record.
const record = await worker.getObjective({ threadId })

// Update options on the active objective (only provided fields are written;
// unset fields fall back to the agent's `goal` config).
await worker.updateObjectiveOptions({ threadId, maxRuns: 100 })

// Drop the objective.
await worker.clearObjective({ threadId })
```

目標記錄可包含 `activeDurationMs`，讓介面顯示 Agent 推進目標的時間。Agent 推進有效目標時，Mastra 會累加此值，並在執行結束或等待工具審批時保存。沒有值時視為零，時長只計算 Agent 的執行時間，與目標建立後經過的總時間有別。

`setObjective` 或 `updateObjectiveOptions` 寫入的個別目標設定優先於 Agent 的 `goal` 配置，優先次序會保存在 Thread 狀態。完整區塊結構見 [ChunkType 參考的 `GoalEvaluationPayload`](/reference/streaming/ChunkType)。
