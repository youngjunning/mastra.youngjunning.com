# Harness

Harness 讓 Agent 持續處理複雜的長期目標，工作進度可保存、查閱和調整。即使重試或執行中斷，進度亦會保留。人員和其他系統可以查看進度、補充上下文、批准操作、調整方向或停止 Agent。

凡是需要持續跟進的工作，都可以使用 Agent Harness。例如，編碼 Agent 可跟進修改以完成 CI 和審查，軟件工廠（如 [Mastra Factory](https://factory.mastra.ai)）可協調多項並行任務，SRE Agent 可按事故發展調整處理方式，市場拓展 Agent 則可因應客戶帳戶、訊號及對話的變化行動。

在 Mastra，Harness 是一組管理 Agent 的功能，適用於超出單次連續執行的工作。你可按需要單獨或組合使用這些功能。

## 何時使用 Harness {/* #when-to-use-a-harness */}

按 Agent 的需要選擇起點，可同時採用多項功能。

| 需要 | 可用功能 | 用途 |
| - | - | - |
| 客戶端斷線或伺服器重啟後仍可存取執行 | [持久化 Agent](/docs/harness/durable-agents) | 保存執行狀態，讓客戶端重新連接該次執行的串流。 |
| 執行耗時的 Tool、Workflow 或子 Agent，毋須阻塞主流程 | [背景任務](/docs/harness/background-tasks) | 非同步完成工作，然後將結果傳回 Agent。 |
| 讓 Agent 持續工作直至達成目標 | [目標](/docs/harness/goals) | 評估對話執行緒內的目標，直至完成或用盡執行預算。 |
| 定期自動開始工作 | [排程](/docs/harness/schedules) | 按 cron 排程啟動獨立執行，或向現有對話執行緒發送提示。 |
| 補充上下文、改變現有工作的方向，或喚醒閒置對話執行緒 | [訊號](/docs/signals/overview) | 即時傳送輸入，或保留到下一輪。 |
| 回應 GitHub、Slack、持續整合或其他外部系統的變動 | [訊號供應商](/docs/signals/signal-providers) | 追蹤訂閱，將符合條件的事件轉送至 Agent 的對話執行緒。 |
| 建構支援工作階段、模式、狀態、審批和事件的互動產品，或讓用戶調整方向、將後續工作排入隊列及停止執行 | [AgentController](/docs/harness/agent-controller) | 讓獨立的工作階段共用 Agent 執行環境，並各自控制執行。 |
| 為 Agent 提供檔案、Shell 和編碼工作所需的預設設定 | [`createCodingAgent()`](/reference/coding-agent/create-coding-agent) | 建立已設定 Workspace、任務追蹤和重試的標準 Agent。 |
