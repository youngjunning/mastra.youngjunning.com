# Agent Controller

`AgentController` 是互動式 Agent 應用程式共用的執行時宿主，負責協調模式、模型、儲存、Workspace、Tool 審批、子 Agent 及頻道。每位用戶或進行中的任務，都透過獨立的 [`Session`](/reference/agent-controller/session) 運作。

[Mastra Code](https://code.mastra.ai) 和 [Mastra Factory](https://factory.mastra.ai) 是 AgentController 的代表性實作。這兩款程式開發 Agent 支援多種模型、持久對話，以及先規劃後執行的工作流程。逐步建立 TUI 的方法可參閱[建立程式開發 Agent](https://mastra.ai/blog/building-a-coding-agent)。

如果託管的 Agent 會在程式碼庫中工作，請用 [`createCodingAgent()`](/reference/coding-agent/create-coding-agent) 建立，而非 `new Agent()`。它會回傳標準 `Agent`，當中已有 Workspace、任務追蹤及模型暫時性錯誤的重試機制；Mastra Code 亦採用這些預設設定。

## 何時使用 Agent Controller {/* #when-to-use-the-agent-controller */}

當應用程式需要以下功能時，可使用 Agent Controller：

- 多種 Agent 模式共用同一條對話執行緒（例如規劃 → 建構 → 審查）
- 在 UI 與 Agent 執行循環之間加入控制層（切換模型、保留狀態、管理執行緒）
- 透過 Tool 審批流程及權限政策，由人手把關
- 編排子 Agent，將範圍明確的子任務交給只獲准使用指定 Tool 的 Agent
- 重新啟動後保留執行緒及選定的執行緒設定，同時隔離各 Session 的即時狀態

你亦可在 [Agent 類別](/docs/agents/overview)之上自行組合這些功能；它提供完整的 Agent 執行循環、Tool 及記憶功能。AgentController 為持續運作的 Session 提供一套有明確設計取捨的預設行為，讓 Agent 以協作者的方式工作，而非只處理單次請求。需要完全掌控或採用請求回應式呼叫時，直接使用 Agent 類別；需要持續對話而不想自行建立 Session 執行時，則選用 AgentController。

## 快速入門 {/* #quickstart */}

先建立作為底層執行者的 [`Agent`](/reference/agents/agent)、儲存及 [`Workspace`](/reference/workspace/workspace-class)。呼叫一次 [`controller.init()`](/reference/agent-controller/agent-controller-class#init)，再透過 [`controller.createSession()`](/reference/agent-controller/agent-controller-class#createsessionoptions) 建立 Session。使用 [`session.subscribe()`](/reference/agent-controller/session#subscribelistener) 訂閱事件，並透過 [`session.sendMessage()`](/reference/agent-controller/session#sendmessage-content-files-requestcontext-author-) 傳送任務：

```typescript title="src/mastra/agent-controller.ts"
import { Agent } from '@mastra/core/agent'
import { AgentController } from '@mastra/core/agent-controller'
import { LocalFilesystem, Workspace } from '@mastra/core/workspace'
import { LibSQLStore } from '@mastra/libsql'

const agent = new Agent({
  id: 'assistant',
  name: 'Assistant',
  instructions: 'Help the user plan and complete tasks.',
  model: '__GATEWAY_OPENAI_MODEL__',
})

const controller = new AgentController({
  id: 'assistant-controller',
  agent,
  storage: new LibSQLStore({
    id: 'agent-controller-storage',
    url: 'file:./mastra.db',
  }),
  workspace: new Workspace({
    id: 'assistant-workspace',
    filesystem: new LocalFilesystem({ basePath: './workspace' }),
  }),
  modes: [
    {
      id: 'plan',
      name: 'Plan',
      metadata: { default: true },
      instructions: 'Reason about the task before making changes.',
    },
    {
      id: 'build',
      name: 'Build',
      instructions: 'Implement the approved plan.',
    },
  ],
})

await controller.init()

const session = await controller.createSession({
  resourceId: 'user-123',
})

const unsubscribe = session.subscribe(event => {
  if (event.type === 'message_update' && event.event.type === 'text-delta') {
    process.stdout.write(event.event.delta)
  }
})

await session.sendMessage({ content: 'Plan a small TypeScript CLI.' })
unsubscribe()
```

每則訊息會先發出包含初始訊息的 `message_start` 事件，再發出零個或多個包含精簡增量資料的 `message_update` 事件，最後發出載有訊息 ID 的 `message_end` 事件。需要重建完整訊息時，請按 ID 套用更新。

同一個 Controller 可供多個 Session 使用。不要把目前的 Session 儲存在 Controller 上，也不要經 Controller 層級的訊息方法分派工作。

## 了解執行時模型 {/* #understand-the-runtime-model */}

Controller、Session 及執行緒的生命週期各不相同：

- **Controller**：共用設定與執行時服務的宿主。初始化一次後即可重複使用。
- **Session**：供一位用戶、一項任務或一個並行工作單位使用的獨立即時執行時，以 Session ID 識別。它保存目前模式、模型、狀態、事件匯流排、執行狀態、授權及目前綁定的執行緒。
- **執行緒**：儲存訊息與執行緒設定的對話。設定儲存後，即使 Controller 或程序重新建立，執行緒仍可保留。

Session 承載的是即時狀態。任意的 [`session.state`](/reference/agent-controller/session#state) 資料、權限授權、待審批事項及進行中的執行，不會在程序重新建立後自動恢復。執行緒訊息與部分執行緒設定，包括目前模式及模型，可透過儲存保留；但切換模式不會改變模型。

## Session 與執行緒 {/* #sessions-and-threads */}

`createSession()` 會按 Session 的 `id` 取得現有實例或建立新實例。`resourceId` 指定 Session 的執行緒及資源範圍記憶由誰擁有。省略 `id` 時，預設使用 `resourceId`：

```typescript
const webSession = await controller.createSession({
  id: 'user-123:web',
  resourceId: 'user-123',
})

const sameWebSession = await controller.getSession('user-123:web')

const workerSession = await controller.createSession({
  id: 'user-123:background-worker',
  resourceId: 'user-123',
})

console.log(webSession === sameWebSession) // true
console.log(webSession === workerSession) // false
```

不同 ID 的 Session 各有獨立的事件匯流排、執行循環、狀態、模式及模型選擇，以及目前綁定的執行緒。不過，它們儲存的執行緒及資源範圍記憶仍可屬於同一個 `resourceId`，所以按資源列出執行緒時，會取得兩個 Session 的執行緒。

當宿主必須把 Session 綁定至指定執行緒時，請傳入 `threadId`。Controller 會切換至現有執行緒；如果該 ID 不存在，便會建立執行緒。即使 `createSession()` 回傳的是快取 Session，此行為亦適用：

```typescript
const session = await controller.createSession({
  id: 'user-123:web',
  resourceId: 'user-123',
  threadId: 'support-ticket-42',
})
```

使用 [`session.thread.create()`](/reference/agent-controller/session#sessionthreadcreate-title-id-requestcontext-) 及 [`session.thread.switch()`](/reference/agent-controller/session#sessionthreadswitch-threadid-emitevent-requestcontext-)，讓同一個即時 Session 在不同對話之間切換。

### 轉移執行緒擁有權 {/* #transfer-thread-ownership */}

每條新執行緒會在 `metadata.ownerId` 記錄其持久擁有者，並在 `metadata.createdBy` 記錄最初建立者。兩者預設為 Session 宿主的 `ownerId`。擁有權轉移後，`createdBy` 仍保持不變。

透過 `session.thread` 讀取目前執行緒的擁有者並轉移擁有權：

```typescript
const currentOwnerId = await session.thread.getOwner()

await session.thread.transferOwnership({
  toOwnerId: 'user-456',
})
```

同一程序內的轉移會按次序執行。如果宿主需要跨程序、可持久保存的比較並設定操作，應先在自己的儲存提交變更，再呼叫 `transferOwnership()`，把擁有者同步至目前執行緒。

每次執行開始時，都會擷取執行緒擁有者的快照。Tool 及其他動態執行時程式碼可從 `AgentControllerRequestContext.threadOwnerId` 讀取該值。若擁有權在執行期間改變，本次執行仍使用舊快照，下次執行才會取得新擁有者。`context.session.ownerId` 則維持為目前程序中 Session 宿主的身分。

### 從客戶端列出已儲存的訊息 {/* #list-stored-messages-from-the-client */}

使用 Agent Controller 客戶端，分頁讀取執行緒中儲存的訊息。傳入選項物件後，結果亦會附有分頁中繼資料：

```typescript
import { MastraClient } from '@mastra/client-js'

const client = new MastraClient({ baseUrl: 'http://localhost:4111' })
const session = client.getAgentController('assistant-controller').session('user-123')

const result = await session.listMessages('support-ticket-42', {
  page: 0,
  perPage: 20,
  orderBy: { field: 'createdAt', direction: 'DESC' },
  filter: {
    dateRange: { start: new Date('2026-01-01') },
  },
})

console.log(result.messages)
console.log(result.total)
console.log(result.hasMore)
```

`page` 由零開始。沒有指定 `perPage` 時，使用儲存層預設的每頁 40 則訊息。`include` 可按 ID 取得指定訊息及相鄰訊息。`limit` 是已棄用的 `perPage` 別名；現有分頁呼叫仍可用 `{ limit, page }`，但配合 `orderBy`、`filter` 或 `include` 使用時，必須改用 `perPage`。如需以陣列形式取得最新一段訊息，仍可使用數字參數形式 `session.listMessages(threadId, limit)`；結果按由舊至新的次序排列。

## 切換模式與模型 {/* #switch-modes-and-models */}

模式會調整共用底層 Agent 所用的指令及 Tool，而不會更換 Session 或執行緒。請在 Controller 上設定各模式專用的 Tool 及可見範圍：

```typescript
const modes = [
  {
    id: 'plan',
    name: 'Plan',
    metadata: { default: true },
    instructions: 'Investigate the task and propose a plan.',
    additionalTools: { searchDocs },
    availableTools: ['searchDocs', 'submit_plan'],
    transitionsTo: 'build',
  },
  {
    id: 'build',
    name: 'Build',
    instructions: 'Implement the approved plan.',
  },
]
```

`tools` 與 `additionalTools` 是兩種互斥的模式專用 Tool 輸入。Controller 有共用底層 Agent 時，任一輸入都會把 Tool 疊加至該 Agent 的 Tool。用 `availableTools` 限制模式最終可使用的 Tool 名稱。權限政策中的拒絕規則仍優先於此允許清單。

用 [`session.mode.switch()`](/reference/agent-controller/session#sessionmodeswitch-modeid-) 切換即時 Session 的模式。透過 [`session.mode.get()`](/reference/agent-controller/session#sessionmodeget) 或 [`session.mode.resolve()`](/reference/agent-controller/session#sessionmoderesolve) 讀取目前模式：

```typescript
await session.mode.switch({ modeId: 'build' })

console.log(session.mode.get()) // "build"
console.log(session.mode.resolve().instructions)
```

透過 [`session.model.switch()`](/reference/agent-controller/session#sessionmodelswitchmodelid-options) 獨立切換模型，再用 [`session.model.get()`](/reference/agent-controller/session#sessionmodelget) 查看目前選擇。此選擇會儲存為執行緒目前的模型，所以 Session 切換模式後仍會沿用：

```typescript
await session.model.switch('__GATEWAY_ANTHROPIC_MODEL_SONNET__')

console.log(session.model.get())
```

### 選擇 Observational Memory 模型 {/* #select-observational-memory-models */}

Observer 及 reflector 的模型選擇互不影響。每個角色可以指定模型，亦可由宿主按目前主模型及 Session 狀態自動選擇。

要設定自動選擇，請提供同步解析器，並讓它回傳具體模型 ID：

```typescript
const controller = new AgentController({
  // ...
  omConfig: {
    observerModel: 'auto',
    reflectorModel: 'auto',
    defaultObserverModelId: '__GATEWAY_OPENAI_MODEL_LUNA__',
    defaultReflectorModelId: '__GATEWAY_OPENAI_MODEL_LUNA__',
    resolveAutoModelId: ({ currentModelId }) => currentModelId,
  },
})
```

`session.om.observer.model()` 回傳 `'auto'` 或具體模型 ID；`session.om.observer.modelId()` 則回傳實際生效的具體模型。因此，宿主可切換主模型，而無需重寫角色的自動選擇設定。

可以只把其中一個角色重設為自動選擇，不影響另一角色：

```typescript
await session.om.observer.switchModel({ modelId: 'auto' })
```

如果解析器回傳 `undefined` 或拋出錯誤，該角色會改用具體的 `defaultObserverModelId` 或 `defaultReflectorModelId` 作後備。明確指定模型的方法可參閱 [`Session` Observational Memory API](/reference/agent-controller/session#observational-memory)。

## 管理執行緒及狀態 {/* #manage-threads-and-state */}

透過 [`session.thread.list()`](/reference/agent-controller/session#sessionthreadlistoptions) 列出已儲存的對話：

```typescript
const thread = await session.thread.create({ title: 'Release planning' })
const threads = await session.thread.list()

await session.thread.switch({ threadId: thread.id })
console.log(threads.length)
```

以 `session.state` 保存 Session 的結構化即時狀態。可用 [`session.state.get()`](/reference/agent-controller/session#sessionstateget) 讀取，並用 [`session.state.set()`](/reference/agent-controller/session#sessionstatesetupdates) 更新。如需驗證及預設值，可在 Controller 上定義 `stateSchema` 及 `initialState`：

```typescript
console.log(session.state.get())

await session.state.set({ activeProject: 'docs-site' })
```

`session.state.get()` 會回傳快照。`set()` 會驗證更新內容，再將其合併到 Session 狀態。除非宿主明確負責持久化及還原，否則請把這些資料視為即時 Session 狀態。

## 審批 Tool 並恢復暫停的執行 {/* #approve-tools-and-resume-suspensions */}

權限政策會決定 Tool 是獲准執行、遭拒絕，還是送到 UI 等待審批。可在 Controller 上使用 `toolCategoryResolver`，把自訂 Tool 對應至類別：

```typescript
const controller = new AgentController({
  toolCategoryResolver: toolName => {
    if (toolName === 'delete_project') return 'execute'
    return null
  },
})
```

政策允許的 Tool 呼叫不會暫停執行。對一般 `Agent` 而言，如果同一步驟中的 Tool 呼叫都毋須審批，亦不會暫停，它們會並行執行。持久化 Agent 則會逐一執行，除非 Session 的 `yolo` 狀態已啟用。

用 [`session.permissions.setForCategory()`](/reference/agent-controller/session#sessionpermissionssetforcategory-category-policy-) 設定類別政策，並用 [`session.permissions.setForTool()`](/reference/agent-controller/session#sessionpermissionssetfortool-toolname-policy-) 設定個別 Tool 的政策：

```typescript
await session.permissions.setForCategory({
  category: 'execute',
  policy: 'ask',
})

await session.permissions.setForTool({
  toolName: 'delete_project',
  policy: 'deny',
})
```

若政策結果是 `ask`，請訂閱審批事件，再透過 [`session.respondToToolApproval()`](/reference/agent-controller/session#respondtotoolapproval-decision-toolcallid-requestcontext-declinecontext-) 回傳用戶的決定：

```typescript
session.subscribe(event => {
  if (event.type === 'tool_approval_required') {
    session.respondToToolApproval({
      toolCallId: event.toolCallId,
      decision: 'approve',
    })
  }
})
```

`always_allow_category` 決定會向觸發審批的執行緒授予該 Tool 類別的權限。此授權並非持久化的程序層級權限。

[`ask_user`](/reference/tools/ask-user-tool) 及 [`submit_plan`](/reference/tools/submit-plan-tool) 等互動式 Tool 會改用可恢復的 Tool 暫停機制。請用 [`session.respondToToolSuspension()`](/reference/agent-controller/session#respondtotoolsuspension-resumedata-address-toolcallid-requestcontext-) 恢復執行：

```typescript
session.subscribe(event => {
  if (event.type === 'tool_suspended' && event.toolName === 'ask_user') {
    void session.respondToToolSuspension({
      toolCallId: event.toolCallId,
      resumeData: 'Use SQLite.',
    })
  }
})
```

對於 `submit_plan`，可傳入 `{ action: 'approved' }` 或 `{ action: 'rejected', feedback }` 來恢復。計劃獲批後，可先切換至 `transitionsTo` 指定的模式，再繼續執行。

內置 `submit_plan` Tool 接收的是計劃檔案路徑，而非計劃內容。Agent 會先把計劃寫入檔案，再提交路徑，因此需要可寫入的檔案系統，例如 Workspace 檔案系統。應用程式如要顯示計劃供審批，應讀取所提交 `path` 指向的檔案。

## 把任務交給子 Agent {/* #delegate-to-subagents */}

在 Controller 上設定可用的子 Agent 類型。之後，內置的 `subagent` Tool 就能按這些定義委派指定任務：

```typescript
const controller = new AgentController({
  tools: {
    searchDocs,
  },
  subagents: [
    {
      id: 'code-reviewer',
      name: 'Code reviewer',
      description: 'Review a change for correctness and regressions.',
      instructions: 'Inspect the change and report actionable findings.',
      allowedControllerTools: ['searchDocs'],
      allowedWorkspaceTools: ['view', 'find_files'],
      defaultModelId: '__GATEWAY_OPENAI_MODEL_LUNA__',
    },
  ],
})
```

一般子 Agent 會以其設定的指令及受限 Tool 組合啟動。若子 Agent 應複製父執行緒，並使用父 Agent 的指令及 Tool，請設定 `forked: true`。分支子 Agent 保留父層提示詞前綴，忽略定義中的指令、Tool、允許清單及預設模型，並要求 Controller 啟用記憶功能。

用 [`session.subagents.model.set()`](/reference/agent-controller/session#sessionsubagentsmodelset-modelid-agenttype-) 設定共用的預設子 Agent 模型，或為指定 Agent 類型選擇模型。用 [`session.subagents.model.get()`](/reference/agent-controller/session#sessionsubagentsmodelget-agenttype-) 查詢目前選擇：

```typescript
await session.subagents.model.set({
  modelId: '__GATEWAY_OPENAI_MODEL_LUNA__',
})

await session.subagents.model.set({
  agentType: 'code-reviewer',
  modelId: '__GATEWAY_ANTHROPIC_MODEL_SONNET__',
})

const reviewerModel = session.subagents.model.get({
  agentType: 'code-reviewer',
})
```

選擇結果會寫入執行緒設定。按 Agent 類型指定的模型，優先於 Session 的預設子 Agent 模型。

## 連接聊天頻道 {/* #connect-chat-channels */}

把頻道轉接器傳給 Controller，並在 [`Mastra`](/reference/core/mastra-class) 實例中註冊：

```typescript title="src/mastra/index.ts"
import { Mastra } from '@mastra/core'
import { AgentController } from '@mastra/core/agent-controller'
import { createSlackAdapter } from '@chat-adapter/slack'

const controller = new AgentController({
  id: 'support-controller',
  agent,
  storage,
  workspace,
  modes,
  channels: {
    adapters: {
      slack: createSlackAdapter(),
    },
    resolveResourceId: ({ thread, message, defaultResourceId }) => {
      if (thread.isDM) return message.author.userId
      return defaultResourceId
    },
    onSessionStart: async ({ session, thread }) => {
      const plan = await billing.planFor(thread.resourceId)
      await session.model.switch(plan.modelId)
    },
  },
})

export const mastra = new Mastra({
  agentControllers: { controller },
  storage,
})
```

把各平台的 webhook 指向此 Controller 專屬的路由：

```text
/api/agent-controllers/<CONTROLLER_ID>/channels/<PLATFORM>/webhook
```

每條外部聊天執行緒都會對應一個 Controller Session 及一條 Mastra 執行緒。預設情況下，新 Session 的資源 ID 取自轉接器的聊天執行緒 ID，並加上 `channel:` 前綴。可用 `resolveResourceId` 把私人訊息對應至現有的應用程式用戶，或指定其他記憶擁有者。此回呼只影響新執行緒；現有執行緒會保留已儲存的資源 ID。

頻道 Session 由 Controller 建立，而非由應用程式碼建立，因此要在 `onSessionStart` 中設定。每個 Session 在綁定對應執行緒後、處理第一則訊息前，會執行此回呼一次。頻道 Session 起初採用 Controller 的預設設定，可在此指定模型及記憶設定。同一執行緒的後續訊息會重用 Session，不會再次呼叫回呼。錯誤會記錄在日誌中並被略過，所以即使設定失敗，Session 仍會回覆訊息。

### 授權並路由頻道 Session {/* #authorize-and-route-channel-sessions */}

`onSessionStart` 在 Session 建立後才執行，而且會略過錯誤，因此不能用來拒絕請求。如宿主需要決定是否容許建立 Session，請使用 `resolveSession`。它會取代內置的 Session 建立程序，並在 Session 存在前執行。拋出錯誤會在 Controller 建立 Session 或呼叫模型前拒絕請求。Mastra 會記錄拒絕事件，聊天執行緒不會收到訊息，所以授權說明不會送達頻道。

```typescript oxfmt:false
channels: {
  adapters: { slack: createSlackAdapter() },
  resolveSession: async ({ controller, thread, requestContext }) => {
    const install = await installs.authorize(requestContext.get('teamId'))

    return controller.createSession({
      id: `${install.id}:${thread.id}`,
      resourceId: thread.resourceId,
      threadId: thread.id,
      ownerId: controller.id,
      requestContext,
    })
  },
}
```

在 `thread.resourceId` 之下建立 Session。由於 Session 只能綁定自己擁有的執行緒，如要為對應執行緒指定不同擁有者，請使用 `resolveResourceId`。傳入 `threadId: thread.id`，讓 Session 直接開啟對應執行緒。否則，帶有標籤或 `projectPath` 的 Session 不會把對應執行緒視為自己所有，會先建立額外的空執行緒，再切換過去。Session 按 `id` 取得或建立；若同一執行緒需要分開的 Session，請為每個安裝實例或主體指定獨立 `id`。

其他故障，例如儲存中斷或解析器依賴項出錯，仍會向執行緒傳送錯誤，避免故障機械人看起來像刻意保持沉默。若要在程式碼中區分，拒絕請求會產生 `ChannelSessionRejectedError`，原始錯誤保存在其 `cause` 中。

用戶回覆審批卡片時，`resolveSession` 亦會連同該動作的請求內容一起執行。共用安裝實例會重新驗證審批者，而不會直接信任最初發送訊息的人。

### 處理失效的審批 {/* #handle-stale-approvals */}

審批關卡保存在記憶體中，因此重新啟動後才收到的審批回覆都已失效。Mastra 絕不會為失效的操作執行 Tool。請用 `onStaleToolApproval` 處理用戶回覆的那次嘗試，避免直接捨棄：

```typescript oxfmt:false
channels: {
  adapters: { slack: createSlackAdapter() },
  onStaleToolApproval: async ({ decision, toolCallId, runId, memory }) => {
    await runs.markInterrupted({ runId, toolCallId, decision, threadId: memory.thread })
  },
}
```

`runId` 是產生審批卡片時的執行 ID，即用戶回覆的那次嘗試；重新啟動後應以此作準處理。Session 自身目前的執行 ID 會另以 `currentRunId` 傳入，此時通常是 `null`，或已是另一筆執行。

Controller 的頻道 Session 及自動審批狀態只保存在記憶體中，因此請使用長期運作的伺服器。待處理的審批及即時 Session 狀態不會在程序重新啟動後保留。無法顯示審批控制項的轉接器會自動執行 Tool，不顯示審批提示，避免執行一直暫停。

頻道轉接器設定及各平台 webhook 配置可參閱 [Channels](/docs/channels)。

## 連接 UI {/* #connect-a-ui */}

連接方式取決於 UI 的執行位置。終端 UI 或持有 Controller 的伺服器，可直接持有 `Session` 物件並訂閱事件。瀏覽器 UI 在另一個程序中，須經 Controller 的 HTTP 路由及 [`@mastra/client-js`](/reference/client-js/mastra-client) 存取同一個 Session。

### 伺服器端 Session {/* #server-side-sessions */}

訂閱 Session 事件即可取得增量更新。當 UI 需要完整的畫面快照時，可透過 [`session.displayState.get()`](/reference/agent-controller/session#sessiondisplaystateget) 取得彙整後的顯示狀態：

```typescript
const unsubscribe = session.subscribe(event => {
  if (event.type === 'display_state_changed') {
    render(event.displayState)
  }
})

render(session.displayState.get())

// Call when the UI disconnects.
unsubscribe()
```

訂閱按 Session 隔離。同一 Controller 上其他 Session 的事件不會傳給這個監聽器。完整的 TUI 範例可參閱[建立程式開發 Agent](https://mastra.ai/blog/building-a-coding-agent)。

### 客戶端 Session {/* #client-side-sessions */}

[`client.getAgentController(key).session(sessionId)`](/reference/client-js/agent-controller) 會回傳以 Session ID 定位的客戶端。請傳入 Controller 在 `new Mastra({ agentControllers })` 中註冊時使用的 key；它可能與 Controller 的 `id` 不同。伺服器會按 ID 取得或建立 Session，因此 `create()` 會恢復現有對話，不會另開新對話。多個 Session 共用同一資源時，請把 `resourceId` 傳給 `create()`；否則資源 ID 預設等於 Session ID：

```typescript title="src/components/agent-session.ts"
import { MastraClient } from '@mastra/client-js'

const client = new MastraClient({ baseUrl: 'http://localhost:4111' })
const session = client.getAgentController('coding-controller').session('user-123')

await session.create()

const subscription = await session.subscribe({
  onEvent: event => handleEvent(event),
  onError: error => showDisconnected(error),
  onReconnect: () => {
    void session.state().then(resync).catch(showDisconnected)
  },
  reconnect: true,
})

// Call when the UI disconnects.
subscription.unsubscribe()
```

`subscribe()` 與程序內的監聽器不同：它接收選項物件，而且是非同步方法。串流建立後，其 Promise 才會完成；無法連線時則會拒絕，亦不會留下背景訂閱。`reconnect: true` 會在現有串流中斷後，以指數退避方式重新連線。如果連線仍開啟但不再傳輸資料，例如裝置進入休眠，只要在 `idleTimeoutMs`（預設 `60000`）內連伺服器心跳也未收到，就會視為中斷。

伺服器不會重播串流中斷期間錯過的事件，因此請在 `onReconnect` 中讀取 `session.state()`，取得目前模式、模型及執行緒。客戶端沒有 `session.displayState.get()`。

透過 `session.sendMessage(content)` 傳送工作，或用 `session.sendMessage({ content, files })` 附加 base64 編碼檔案。回覆會以訂閱的 `message_*` 事件送達，並非呼叫的回傳值。收到 `tool_approval_required` 事件時，用 `session.approveTool(toolCallId, approved)` 回覆；收到 `tool_suspended` 事件時，用 `session.respondToToolSuspension(toolCallId, resumeData)` 恢復。

`onEvent` 會收到 Session 發出的所有事件。事件類型及縮小其型別範圍的方法可參閱 [Agent Controller API](/reference/client-js/agent-controller#events)。
