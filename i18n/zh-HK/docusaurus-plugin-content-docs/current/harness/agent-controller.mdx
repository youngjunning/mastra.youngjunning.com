# Agent控制器

`AgentController`是互動式Agent應用程式的共享運行時主機。它協調模式、模型、儲存、工作空間、Tool批准、子Agent和通道。每個使用者或活動任務透過一個隔離的工作[`Session`](/reference/agent-controller/session).

[馬斯特拉代碼](https://code.mastra.ai)和[Mastra Factory](https://factory.mastra.ai) are the flagship AgentController implementations. They're coding agents with multi-model support, persistent conversations, and plan-then-execute workflows. Read [Building a coding agent](https://mastra.ai/blog/building-a-coding-agent) for a step-by-step TUI guide.

當您託管的Agent程式在程式碼庫中工作時，請使用以下命令建立它[`createCodingAgent()`](/reference/coding-agent/create-coding-agent) instead of `new Agent()`. It returns a standard `Agent` that already has a workspace, task tracking, and retries for transient model errors, which are the defaults Mastra Code runs on.

## 何時使用Agent控制器 {/* #when-to-use-the-agent-controller */}

當您的應用程式需要時，請使用Agent控制器：

* 共享一個對話線程的多種Agent模式（例如，計劃→建置→審查）
* UI 與Agent循環之間的控制層（模型切換、狀態持久性、執行緒管理）
* 人機互動門控的Tool審批流程與權限策略
* 子Agent編排，使用受限Tool委派重點子任務
* 重新啟動後持久線程和選定的線程設置，每個會話具有隔離的實時狀態

您可以自己將所有這些組裝在[Agent class](/docs/agents/overview), which exposes the full agent loop, tools, and memory. The AgentController provides opinionated defaults for an ongoing session where the agent acts as a collaborator rather than a one-shot endpoint. Use the Agent class directly for full control or request-response calls. Choose AgentController for ongoing sessions without building your own session runtime.

## 快速入門 {/* #quickstart */}

[`Agent`](/reference/agents/agent), storage, and [`Workspace`](/reference/workspace/workspace-class). Call [`controller.init()`](/reference/agent-controller/agent-controller-class#init) once, then use [`controller.createSession()`](/reference/agent-controller/agent-controller-class#createsessionoptions) to create a Session. Subscribe with [`session.subscribe()`](/reference/agent-controller/session#subscribelistener) and send work with [`session.sendMessage()`](/reference/agent-controller/session#sendmessage-content-files-requestcontext-author-):

```typescript title="src/mastra/agent-controller.ts"
import { Agent } from '@mastra/core/agent'
import { AgentController } from '@mastra/core/agent-controller'
import { LocalFilesystem, Workspace } from '@mastra/core/workspace'
import { LibSQLStore } from '@mastra/libsql'

const agent = new Agent({
  id: 'assistant',
  name: 'Assistant',
  instructions: 'Help the user plan and complete tasks.',
  model: '__GATEWAY_OPENAI_MODEL__',
})

const controller = new AgentController({
  id: 'assistant-controller',
  agent,
  storage: new LibSQLStore({
    id: 'agent-controller-storage',
    url: 'file:./mastra.db',
  }),
  workspace: new Workspace({
    id: 'assistant-workspace',
    filesystem: new LocalFilesystem({ basePath: './workspace' }),
  }),
  modes: [
    {
      id: 'plan',
      name: 'Plan',
      metadata: { default: true },
      instructions: 'Reason about the task before making changes.',
    },
    {
      id: 'build',
      name: 'Build',
      instructions: 'Implement the approved plan.',
    },
  ],
})

await controller.init()

const session = await controller.createSession({
  resourceId: 'user-123',
})

const unsubscribe = session.subscribe(event => {
  if (event.type === 'message_update' && event.event.type === 'text-delta') {
    process.stdout.write(event.event.delta)
  }
})

await session.sendMessage({ content: 'Plan a small TypeScript CLI.' })
unsubscribe()
```

每個訊息都會發出一個`message_start` event with the initial message, zero or more `message_update` events with compact deltas, and a `message_end` event containing the message ID. Apply updates by ID when you need to reconstruct the complete message.

對多個會話使用相同的控制器。不要在控制器上儲存目前會話或透過控制器級訊息方法路由工作。

## 了解運行時模型 {/* #understand-the-runtime-model */}

控制器、會話和執行緒有不同的生命週期：

* **控制器**：用於配置和運行時服務的共享主機。初始化一次並重複使用。
* **會議**：一個使用者、任務或並發工作的隔離即時執行時，透過其會話 ID 進行尋址。它擁有活動模式、模型、狀態、事件匯流排、運行狀態、授權和當前執行緒綁定。
* **線**：包含訊息和線程設定的儲存對話。當您配置儲存時，執行緒可以在控制器和進程重新建立後繼續存在。

會話是即時狀態。隨意的[`session.state`](/reference/agent-controller/session#state), permission grants, pending approvals, and active runs don't automatically survive process recreation. Thread messages and selected thread settings, including the active mode and the current model, can persist through storage, but switching modes doesn't change the model.

## 會話和執行緒 {/* #sessions-and-threads */}

`createSession()`透過會話獲取或創建`id`. The `resourceId` names who owns the session's threads and resource-scoped memory. When you omit `id`, it defaults to `resourceId`:

```typescript
const webSession = await controller.createSession({
  id: 'user-123:web',
  resourceId: 'user-123',
})

const sameWebSession = await controller.getSession('user-123:web')

const workerSession = await controller.createSession({
  id: 'user-123:background-worker',
  resourceId: 'user-123',
})

console.log(webSession === sameWebSession) // true
console.log(webSession === workerSession) // false
```

具有不同 ID 的會話具有單獨的事件匯流排、運行循環、狀態、模式和模型選擇以及當前執行緒綁定。它們儲存的線程和資源範圍記憶體仍然屬於共享`resourceId`, so listing threads by resource returns both sessions' threads.

經過`threadId` when the host must bind the Session to an exact thread. The controller switches to the existing thread or creates it with that ID when it's missing. This behavior also applies when `createSession()` returns a cached Session:

```typescript
const session = await controller.createSession({
  id: 'user-123:web',
  resourceId: 'user-123',
  threadId: 'support-ticket-42',
})
```

使用[`session.thread.create()`](/reference/agent-controller/session#sessionthreadcreate-title-id-requestcontext-) and [`session.thread.switch()`](/reference/agent-controller/session#sessionthreadswitch-threadid-emitevent-requestcontext-) to move one live Session between conversations.

### 轉移執行緒所有權 {/* #transfer-thread-ownership */}

每個新線程都將其持久性所有者存儲在`metadata.ownerId` and its original creator in `metadata.createdBy`. Both default to the Session host's `ownerId`. `createdBy` doesn't change when ownership transfers.

讀取活動線程的所有者並將其傳遞給`session.thread`:

```typescript
const currentOwnerId = await session.thread.getOwner()

await session.thread.transferOwnership({
  toOwnerId: 'user-456',
})
```

傳輸在一個進程內串行進行。需要持久跨進程比較和設定的主機應先將其提交到自己的儲存中，然後調用`transferOwnership()` to mirror the owner onto the active thread.

每次運行都會在啟動時拍攝執行緒所有者的快照。Tool和其他動態運行時程式碼可以從中讀取該值`AgentControllerRequestContext.threadOwnerId`. If ownership changes during a run, the active run keeps the old snapshot and the next run receives the new owner. `context.session.ownerId` remains the identity of the process-local Session host.

### 列出客戶端儲存的訊息 {/* #list-stored-messages-from-the-client */}

使用Agent控制器客戶端來翻閱執行緒的儲存訊息。傳遞選項物件會傳回帶有分頁元資料的訊息：

```typescript
import { MastraClient } from '@mastra/client-js'

const client = new MastraClient({ baseUrl: 'http://localhost:4111' })
const session = client.getAgentController('assistant-controller').session('user-123')

const result = await session.listMessages('support-ticket-42', {
  page: 0,
  perPage: 20,
  orderBy: { field: 'createdAt', direction: 'DESC' },
  filter: {
    dateRange: { start: new Date('2026-01-01') },
  },
})

console.log(result.messages)
console.log(result.total)
console.log(result.hasMore)
```

`page`是零索引的。省略`perPage` uses the storage default of 40 messages. Use `include` to request a message by ID with adjacent messages. `limit` is a deprecated alias for `perPage`; existing paged callers may use `{ limit, page }`, but must use `perPage` with `orderBy`, `filter`, or `include`. The existing numeric form, `session.listMessages(threadId, limit)`, remains available when you need the newest message window as an array, ordered oldest-first.

## 切換模式和型號 {/* #switch-modes-and-models */}

模式變更共享後備Agent使用的指令和Tool，而不替換會話或執行緒。在控制器上配置特定於模式的Tool和可見性：

```typescript
const modes = [
  {
    id: 'plan',
    name: 'Plan',
    metadata: { default: true },
    instructions: 'Investigate the task and propose a plan.',
    additionalTools: { searchDocs },
    availableTools: ['searchDocs', 'submit_plan'],
    transitionsTo: 'build',
  },
  {
    id: 'build',
    name: 'Build',
    instructions: 'Implement the approved plan.',
  },
]
```

`tools`和`additionalTools` are mutually exclusive inputs for adding mode-specific tools. When the controller has a shared backing agent, either input layers those tools onto the agent's tools. Use `availableTools` to restrict the final exposed tool names for a mode. Permission denies still take precedence over this allowlist.

切換即時會話[`session.mode.switch()`](/reference/agent-controller/session#sessionmodeswitch-modeid-). Read the active mode with [`session.mode.get()`](/reference/agent-controller/session#sessionmodeget) or [`session.mode.resolve()`](/reference/agent-controller/session#sessionmoderesolve):

```typescript
await session.mode.switch({ modeId: 'build' })

console.log(session.mode.get()) // "build"
console.log(session.mode.resolve().instructions)
```

獨立切換模型[`session.model.switch()`](/reference/agent-controller/session#sessionmodelswitchmodelid-options), then read the active selection with [`session.model.get()`](/reference/agent-controller/session#sessionmodelget). The selection is stored as the thread's current model and remains active when the Session changes modes:

```typescript
await session.model.switch('__GATEWAY_ANTHROPIC_MODEL_SONNET__')

console.log(session.model.get())
```

### 選擇觀察記憶模型 {/* #select-observational-memory-models */}

觀察者和反射器模型的選擇是獨立的。每個角色都可以使用主機從活動主模型和會話狀態解析的明確模型或自動選擇。

使用返回特定模型 ID 的同步解析器配置自動選擇：

```typescript
const controller = new AgentController({
  // ...
  omConfig: {
    observerModel: 'auto',
    reflectorModel: 'auto',
    defaultObserverModelId: '__GATEWAY_OPENAI_MODEL_LUNA__',
    defaultReflectorModelId: '__GATEWAY_OPENAI_MODEL_LUNA__',
    resolveAutoModelId: ({ currentModelId }) => currentModelId,
  },
})
```

`session.om.observer.model()`回報`'auto'` or a concrete model ID. `session.om.observer.modelId()` returns the effective concrete model. A host can therefore change the main model without rewriting automatic role settings.

將一個角色重置為自動選擇而不更改另一個角色：

```typescript
await session.om.observer.switchModel({ modelId: 'auto' })
```

如果解析器傳回`undefined` or throws, the role uses its concrete `defaultObserverModelId` or `defaultReflectorModelId` fallback. See the [`Session` Observational Memory API](/reference/agent-controller/session#observational-memory) for explicit selection.

## 管理線程和狀態 {/* #manage-threads-and-state */}

列出儲存的對話[`session.thread.list()`](/reference/agent-controller/session#sessionthreadlistoptions):

```typescript
const thread = await session.thread.create({ title: 'Release planning' })
const threads = await session.thread.list()

await session.thread.switch({ threadId: thread.id })
console.log(threads.length)
```

使用`session.state` for structured live state associated with the Session. Read it with [`session.state.get()`](/reference/agent-controller/session#sessionstateget) and write updates with [`session.state.set()`](/reference/agent-controller/session#sessionstatesetupdates). Define `stateSchema` and `initialState` on the controller when you need validation and defaults:

```typescript
console.log(session.state.get())

await session.state.set({ activeProject: 'docs-site' })
```

`session.state.get()`返回快照。`set()` validates and merges the update into the Session state. Treat this state as live Session data unless your host explicitly persists and restores it.

## 批准Tool並恢復暫停 {/* #approve-tools-and-resume-suspensions */}

權限策略決定是否允許、拒絕Tool或將Tool傳送至 UI 進行批准。將自訂Tool對應到類別`toolCategoryResolver` on the controller:

```typescript
const controller = new AgentController({
  toolCategoryResolver: toolName => {
    if (toolName === 'delete_project') return 'execute'
    return null
  },
})
```

呼叫規則允許的Tool不會暫停運作。定期上`Agent`, tool calls in one step run concurrently when none of them needs approval or can suspend. Durable agents run them one at a time unless the session's `yolo` state is on.

配置類別策略[`session.permissions.setForCategory()`](/reference/agent-controller/session#sessionpermissionssetforcategory-category-policy-) and tool policies with [`session.permissions.setForTool()`](/reference/agent-controller/session#sessionpermissionssetfortool-toolname-policy-):

```typescript
await session.permissions.setForCategory({
  category: 'execute',
  policy: 'ask',
})

await session.permissions.setForTool({
  toolName: 'delete_project',
  policy: 'deny',
})
```

當政策決定`ask`, subscribe for the approval event and return the user's decision with [`session.respondToToolApproval()`](/reference/agent-controller/session#respondtotoolapproval-decision-toolcallid-requestcontext-declinecontext-):

```typescript
session.subscribe(event => {
  if (event.type === 'tool_approval_required') {
    session.respondToToolApproval({
      toolCallId: event.toolCallId,
      decision: 'approve',
    })
  }
})
```

這`always_allow_category` decision grants the tool category for the gate's thread. Grants aren't durable process-level permissions.

互動式Tool，例如[`ask_user`](/reference/tools/ask-user-tool) and [`submit_plan`](/reference/tools/submit-plan-tool) use resumable tool suspensions instead. Resume them with [`session.respondToToolSuspension()`](/reference/agent-controller/session#respondtotoolsuspension-resumedata-address-toolcallid-requestcontext-):

```typescript
session.subscribe(event => {
  if (event.type === 'tool_suspended' && event.toolName === 'ask_user') {
    void session.respondToToolSuspension({
      toolCallId: event.toolCallId,
      resumeData: 'Use SQLite.',
    })
  }
})
```

為了`submit_plan`, resume with `{ action: 'approved' }` or `{ action: 'rejected', feedback }`. An approved plan can switch to the mode configured by `transitionsTo` before the run continues.

內建的`submit_plan` tool takes a plan file path, not the plan text. The agent writes the plan to a file and submits its path. It needs a filesystem it can write to, such as a workspace filesystem. To show the plan for approval, your app reads the file at the submitted `path`.

## 委託給子Agent {/* #delegate-to-subagents */}

在控制器上配置可用的子Agent程式類型。內建的`subagent` tool can then delegate focused tasks using those definitions:

```typescript
const controller = new AgentController({
  tools: {
    searchDocs,
  },
  subagents: [
    {
      id: 'code-reviewer',
      name: 'Code reviewer',
      description: 'Review a change for correctness and regressions.',
      instructions: 'Inspect the change and report actionable findings.',
      allowedControllerTools: ['searchDocs'],
      allowedWorkspaceTools: ['view', 'find_files'],
      defaultModelId: '__GATEWAY_OPENAI_MODEL_LUNA__',
    },
  ],
})
```

常規子Agent程式從其配置的指令和受限Tool集開始。放`forked: true` when the child should clone the parent thread and run with the parent agent's instructions and tools. Forked subagents preserve the parent prompt prefix, ignore the definition's instructions, tools, allowlists, and default model, and require memory on the controller.

使用[`session.subagents.model.set()`](/reference/agent-controller/session#sessionsubagentsmodelset-modelid-agenttype-) to store one default subagent model or a model for a specific agent type. Read the selection with [`session.subagents.model.get()`](/reference/agent-controller/session#sessionsubagentsmodelget-agenttype-):

```typescript
await session.subagents.model.set({
  modelId: '__GATEWAY_OPENAI_MODEL_LUNA__',
})

await session.subagents.model.set({
  agentType: 'code-reviewer',
  modelId: '__GATEWAY_ANTHROPIC_MODEL_SONNET__',
})

const reviewerModel = session.subagents.model.get({
  agentType: 'code-reviewer',
})
```

這些選擇將寫入線程設定。Agent類型選擇優先於會話的預設子Agent模型。

## 連接聊天頻道 {/* #connect-chat-channels */}

[`Mastra`](/reference/core/mastra-class) instance:

```typescript title="src/mastra/index.ts"
import { Mastra } from '@mastra/core'
import { AgentController } from '@mastra/core/agent-controller'
import { createSlackAdapter } from '@chat-adapter/slack'

const controller = new AgentController({
  id: 'support-controller',
  agent,
  storage,
  workspace,
  modes,
  channels: {
    adapters: {
      slack: createSlackAdapter(),
    },
    resolveResourceId: ({ thread, message, defaultResourceId }) => {
      if (thread.isDM) return message.author.userId
      return defaultResourceId
    },
    onSessionStart: async ({ session, thread }) => {
      const plan = await billing.planFor(thread.resourceId)
      await session.model.switch(plan.modelId)
    },
  },
})

export const mastra = new Mastra({
  agentControllers: { controller },
  storage,
})
```

將每個平台 Webhook 指向特定於控制器的路由：

```text
/api/agent-controllers/<CONTROLLER_ID>/channels/<PLATFORM>/webhook
```

每個外部聊天執行緒對應到一個控制器會話和 Mastra 執行緒。預設情況下，新會話使用從適配器的聊天執行緒 ID 派生的資源 ID，前綴為`channel:`. Use `resolveResourceId` to map direct messages to an existing application user or choose another memory owner. The callback only affects new threads. An existing thread keeps its stored resource ID.

通道會話是由控制器而不是您的程式碼創建的，因此`onSessionStart` is where you configure them. It runs once per session, after the session is bound to its mapped thread and before the first message is handled. A channel session starts with controller defaults, so this is where you set its model and memory settings. Later messages in the same thread reuse the session and don't call it again. Errors are logged and swallowed so a session that can't be configured still answers the message.

### 授權和路由通道會話 {/* #authorize-and-route-channel-sessions */}

`onSessionStart`在會話存在後運行併吞掉錯誤，因此它無法拒絕請求。使用`resolveSession` when your host decides whether a session may exist. It replaces the built-in session creation and runs before any session exists. Throwing refuses the request before the controller creates a session or calls the model. Mastra logs the refusal and leaves the chat thread silent, so your authorization message never reaches the channel.

```typescript oxfmt:false
channels: {
  adapters: { slack: createSlackAdapter() },
  resolveSession: async ({ controller, thread, requestContext }) => {
    const install = await installs.authorize(requestContext.get('teamId'))

    return controller.createSession({
      id: `${install.id}:${thread.id}`,
      resourceId: thread.resourceId,
      threadId: thread.id,
      ownerId: controller.id,
      requestContext,
    })
  },
}
```

在下面創建會話`thread.resourceId`. Because a session can bind only threads it owns, use `resolveResourceId` to assign a different owner to the mapped thread. Pass `threadId: thread.id` so the session opens on the mapped thread. Without it, a session that has tags or a `projectPath` doesn't treat the mapped thread as its own, so it creates an extra empty thread before switching to the mapped one. Sessions are get-or-create by `id`. Give each installation or principal its own `id` when one thread needs separate sessions.

不是拒絕的故障（儲存中斷、解析器依賴項中的錯誤）仍然會向執行緒發布錯誤，因此損壞的機器人看起來不像沉默的機器人。如果您需要在自己的程式碼中區分它們，則拒絕是`ChannelSessionRejectedError` with the original error as its `cause`.

`resolveSession`當使用者使用該操作的請求上下文回答批准卡時也會運作。共用安裝會重新驗證核准者，而不是信任發送原始訊息的人。

### 處理過時的批准 {/* #handle-stale-approvals */}

批准門存在於記憶體中，因此重新啟動後回答的每個批准都會過時。 Mastra 絕不會為了陳舊的操作而運行該Tool。使用`onStaleToolApproval` to settle the attempt the user answered, instead of dropping it:

```typescript oxfmt:false
channels: {
  adapters: { slack: createSlackAdapter() },
  onStaleToolApproval: async ({ decision, toolCallId, runId, memory }) => {
    await runs.markInterrupted({ runId, toolCallId, decision, threadId: memory.thread })
  },
}
```

`runId`是提交批准卡的运行，这是用户回答的尝试，也是您在重新启动后解决的尝试。會話自己的運行單獨傳遞為`currentRunId`, and is usually `null` or a different run by then.

控制器通道會話和自動批准狀態保存在記憶體中，因此請使用長期存在的伺服器。待批准和即時會話狀態不會在流程重新啟動後繼續存在。無法呈現核准控制項的轉接器會在沒有核准提示的情況下自動執行Tool，因此運作不會保持暫停狀態。

看[Channels](/docs/channels) for adapter setup and platform-specific webhook configuration.

## 連結使用者介面 {/* #connect-a-ui */}

連接方式取決於 UI 的運作位置。擁有控制器的終端 UI 或伺服器持有`Session` object and subscribes to it directly. A browser UI runs in a different process, so it reaches the same session over the controller's HTTP routes with [`@mastra/client-js`](/reference/client-js/mastra-client).

### 伺服器端會話 {/* #server-side-sessions */}

訂閱會話事件以取得增量更新。讀取縮小的顯示狀態[`session.displayState.get()`](/reference/agent-controller/session#sessiondisplaystateget) when the UI needs a complete render snapshot:

```typescript
const unsubscribe = session.subscribe(event => {
  if (event.type === 'display_state_changed') {
    render(event.displayState)
  }
})

render(session.displayState.get())

// Call when the UI disconnects.
unsubscribe()
```

訂閱是透過會話隔離的。來自同一控制器上另一個會話的事件不會傳遞到此偵聽器。閱讀[Building a coding agent](https://mastra.ai/blog/building-a-coding-agent) guide for a complete TUI example.

### 客戶端會話 {/* #client-side-sessions */}

[`client.getAgentController(key).session(sessionId)`](/reference/client-js/agent-controller)傳回由其會話 ID 尋址的會話用戶端。傳送控制器註冊的密鑰`new Mastra({ agentControllers })`, which can differ from the controller's `id`. Sessions are get-or-create on the server, so `create()` resumes an existing conversation instead of forking it. Pass `resourceId` to `create()` when several sessions share one resource; otherwise the resource defaults to the session id:

```typescript title="src/components/agent-session.ts"
import { MastraClient } from '@mastra/client-js'

const client = new MastraClient({ baseUrl: 'http://localhost:4111' })
const session = client.getAgentController('coding-controller').session('user-123')

await session.create()

const subscription = await session.subscribe({
  onEvent: event => handleEvent(event),
  onError: error => showDisconnected(error),
  onReconnect: () => {
    void session.state().then(resync).catch(showDisconnected)
  },
  reconnect: true,
})

// Call when the UI disconnects.
subscription.unsubscribe()
```

`subscribe()`與進程內偵聽器不同，它採用一個選項物件並且是異步的。一旦流建立，它的承諾就會解決，而當它無法連接時，它就會拒絕。被拒絕的呼叫不會在後台留下任何運行。`reconnect: true` re-establishes a stream that drops after it was established, with exponential backoff. A connection that stays open but stops delivering data, for example after the device sleeps, counts as a drop once no data, including server heartbeats, arrives for `idleTimeoutMs` (default `60000`).

伺服器不會重播串流關閉時錯過的事件，因此請閱讀`session.state()` from `onReconnect` for the current mode, model, and thread. The client surface has no `session.displayState.get()`.

發送作品給`session.sendMessage(content)`, or `session.sendMessage({ content, files })` to attach base64-encoded files. The reply arrives as `message_*` events on the subscription, not as the return value of the call. Answer a `tool_approval_required` event with `session.approveTool(toolCallId, approved)`, and a `tool_suspended` event with `session.respondToToolSuspension(toolCallId, resumeData)`.

`onEvent`接收會話發出的每個事件。請參閱[Agent Controller API](/reference/client-js/agent-controller#events) reference for the event types and how to narrow them.
