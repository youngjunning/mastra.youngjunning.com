# 定時排程

**加入版本：** `@mastra/core@1.50.0`

排程按 cron 指定的時間運行 Agent。每次觸發，Mastra 都會把提示詞以[訊號](/docs/signals/sending-signals)送到對話執行緒，或透過 [`agent.generate()`](/reference/agents/generate) 啟動一次不依附執行緒的運行。排程適合處理每日摘要、定期檢查等重複工作，也可定時在對話中發出提醒。

排程會持久儲存，服務重啟或重新部署後仍然有效。運行期間可用 [`mastra.schedules`](/reference/schedules/overview) 這個統一介面新增、讀取、更新和刪除排程。要管理 [Workflow 排程](/docs/workflows/scheduled-workflows)，可用同一介面，把 `agentId` 換成 `workflowId`。

:::note

排程需要實作 schedules 功能的[儲存](/docs/storage)配接器。支援哪些配接器及 API 的行為，詳見 [`mastra.schedules` 參考](/reference/schedules/overview)。

:::

即使排程已儲存，亦不代表每次觸發都一定送達。發佈採取盡力而為的方式：排程器最多嘗試發佈三次，用盡次數或發佈端故障，均可能令今次觸發跳過。跳過的觸發不會補發，之後仍可按周期繼續觸發。故障回報及手動重跑須知見[排程傳送保證](/reference/schedules/overview#delivery-guarantees)。

## 快速入門 {/* #quickstart */}

以下排程每小時運行一次 `pinger` Agent。由於沒有連結執行緒，每次觸發都會獨立運行 `agent.generate()`。

```typescript title="src/mastra/schedules.ts"
import { Mastra } from '@mastra/core'
import { Agent } from '@mastra/core/agent'
import { LibSQLStore } from '@mastra/libsql'

const pinger = new Agent({
  id: 'pinger',
  name: 'Pinger',
  instructions: 'Report the current system status in one sentence.',
  model: '__GATEWAY_OPENAI_MODEL__',
})

const mastra = new Mastra({
  agents: { pinger },
  storage: new LibSQLStore({ id: 'mastra-storage', url: 'file:./mastra.db' }),
})

await mastra.schedules.create({
  agentId: 'pinger',
  cron: '0 * * * *',
  prompt: 'Give me a status update.',
})
```

排程只會在有 Mastra 背景 [Worker](/docs/deployment/workers) 運行的程序中觸發。`mastra dev` 和 `mastra build` 產生的伺服器會代為啟動背景 Worker。若使用[伺服器配接器](/docs/server/server-adapters)或自行編寫的指令碼，須呼叫 `mastra.startWorkers()`，否則排程雖會儲存，卻不會觸發。請參閱[啟動背景 Worker](/docs/server/server-adapters#start-background-workers)。

## 觸發周期 {/* #cadence */}

排程按 cron 表達式觸發。`cron` 欄位接受標準的 5、6 或 7 段表達式，建立和更新排程時會驗證。

`croner` 的簡寫亦可用，例如 `@hourly`、`@daily`、`@weekly`、`@monthly` 及 `@midnight`。要指定日子與時間的組合，直接填寫 cron 欄位：

```typescript
// Every weekday at 9am
await mastra.schedules.create({
  agentId: 'pinger',
  cron: '0 9 * * 1-5',
  prompt: 'Start-of-day check.',
})
```

可將 `timezone` 設為 IANA 時區，例如 `America/New_York`，避免觸發時間取決於主機的地區設定。如省略，cron 便會按照主機的本地時區計算。

如果想讓 cron 表達式較易閱讀，可用 [`cron-time-generator`](https://www.npmjs.com/package/cron-time-generator) 一類第三方工具建立，再將產生的值傳給 `cron`。

## 有無連結執行緒的排程 {/* #threadless-and-threaded-schedules */}

Agent 排程有兩種觸發模式，視乎有沒有提供 `threadId`。

### 不連結執行緒 {/* #threadless */}

沒有 `threadId` 時，排程每次觸發都會獨立運行 `agent.generate()`，不會寫入對話執行緒。這個模式最簡單，適用於狀態檢查、報告，以及其他無須參照對話內容的工作。

### 連結執行緒 {/* #threaded */}

提供 `threadId` 後，排程會向指定執行緒發送[訊號](/docs/signals/sending-signals)，將提示詞加到 Agent 的對話中。提供 `threadId` 時亦須一併提供 `resourceId`。

```typescript title="src/mastra/schedules.ts"
await mastra.schedules.create({
  agentId: 'pinger',
  cron: '0 9 * * *',
  prompt: 'Summarize anything new since yesterday.',
  threadId: 'thread-123',
  resourceId: 'user-456',
})
```

連結執行緒的排程可以指定更多欄位，例如訊號類型、XML 標籤、標籤屬性，以及執行緒活躍或閒置時怎樣傳送。這些欄位跟 [`agent.sendSignal()`](/docs/signals/sending-signals) 的選項相對應，並維持可序列化為 JSON，以便隨排程儲存。

使用這些欄位須提供 `threadId`。完整的輸入結構見 [Agent 排程輸入參考](/reference/schedules/overview#createinput)。

```typescript
await mastra.schedules.create({
  agentId: 'pinger',
  cron: '0 9 * * *',
  prompt: 'Summarize anything new since yesterday.',
  threadId: 'thread-123',
  resourceId: 'user-456',
  tagName: 'check-in', // renders as <check-in>…</check-in>
  attributes: { source: 'cron' },
  ifActive: { behavior: 'discard' }, // skip if the thread is mid-stream
  ifIdle: {
    behavior: 'wake', // wake the agent if the thread is idle
    streamOptions: { requestContext: { locale: 'en-US' } },
  },
})
```

每次觸發都會把 `providerOptions` 合併到訊號的承載資料中，無論排程有沒有連結執行緒。

## 管理排程 {/* #managing-schedules */}

所有排程操作均可透過 `mastra.schedules` 完成，包括建立、讀取、更新、暫停、恢復、手動運行及刪除。

```typescript
const schedule = await mastra.schedules.create({
  agentId: 'pinger',
  cron: '0 * * * *',
  prompt: 'Status check.',
})

await mastra.schedules.pause(schedule.id)
await mastra.schedules.resume(schedule.id)
await mastra.schedules.run(schedule.id) // Fire once now, off-schedule
```

`pause` 和 `resume` 的結果會持久儲存。`run` 即時觸發一次，原定周期不受影響。完整的方法、篩選條件和可更新欄位見 [`mastra.schedules` 參考](/reference/schedules/overview)。

### Workflow 排程 {/* #workflow-schedules */}

同一服務亦可建立運行 Workflow 的排程。請傳入 `workflowId` 及 Workflow 所需欄位：

```typescript
await mastra.schedules.create({
  workflowId: 'daily-report',
  cron: '0 9 * * *',
  inputData: { userId: 'system' },
})
```

以這種方式建立的 Workflow 排程，獨立於 `createWorkflow` 中以宣告方式設定的 `schedule` 欄位。有關宣告寫法及 Studio 畫面，請參閱 [Workflow 排程](/docs/workflows/scheduled-workflows)。

### 自訂 ID {/* #custom-ids */}

如要事先指定一個日後用來查找、更新或刪除排程的識別碼，請傳入 `id`。

```typescript
await mastra.schedules.create({
  id: 'nightly-summary',
  agentId: 'pinger',
  cron: '0 9 * * *',
  prompt: 'Summarize anything new since yesterday.',
})
```

ID 正規化的規則及重複 ID 的處理方式，見 [`create(input)` 參考](/reference/schedules/overview#createinput)。

### 透過客戶端管理 {/* #from-the-client */}

`@mastra/client-js` 經 `/api/schedules` 路由提供相同操作，讓你在另一個程序或用戶介面管理排程。客戶端方法見 [client-js Agent 排程參考](/reference/client-js/agents#agent-schedules)。

## 生命週期鉤子 {/* #lifecycle-hooks */}

鉤子可在 Agent 排程生命週期的特定階段運行程式碼，例如計算今次觸發的參數或處理觸發結果。在 `Mastra` 建構函數的 `schedules` 下設定鉤子。所有 Agent 排程共用一組同層的鉤子；每次呼叫的上下文包含對應的 `agentId`，可用於區分各 Agent 的處理方式。鉤子在 `Mastra` 層級設定，適用於以程式碼定義及從儲存載入的 Agent。

```typescript title="src/mastra/index.ts"
import { Mastra } from '@mastra/core'
import { LibSQLStore } from '@mastra/libsql'

const mastra = new Mastra({
  agents: { pinger },
  storage: new LibSQLStore({ id: 'mastra-storage', url: 'file:./mastra.db' }),
  schedules: {
    prepare: async ({ agentId, schedule, trigger }) => {
      // Return overrides, null to skip this fire, or undefined for defaults
      return { prompt: `Status as of ${trigger.firedAt.toISOString()}` }
    },
    onFinish: async ({ agentId, outcome, runId }) => {
      // Runs on any non-error, non-abort outcome. For a threaded schedule, this is the hand-off, not the end of the run
    },
    onError: async ({ agentId, phase, error }) => {
      // Runs when prepare or the signal threw, or a threadless run failed without aborting
    },
    onAbort: async ({ agentId, runId }) => {
      // Runs when a threadless run was aborted
    },
  },
})
```

可用的鉤子如下：

- `prepare`：在觸發前運行。回傳物件可覆寫今次觸發的參數，例如 `prompt` 或 `threadId`；回傳 `null` 會跳過今次觸發；回傳 `undefined` 則使用已儲存的預設值。
- `onFinish`：每次觸發只要沒有出錯或中止，便會呼叫一次。連結執行緒的排程如果啟動一次新的運行，運行一開始便會以 `outcome: 'succeeded'` 呼叫鉤子，毋須等候完成。
- `onError`：`prepare` 或訊號處理失敗後運行。如排程沒有 `threadId`，Agent 運行因中止以外的錯誤而失敗時亦會呼叫。
- `onAbort`：沒有 `threadId` 的排程若有一次運行被中止，便會呼叫。

如有提供 `threadId`，Worker 把提示詞送到執行緒後不會等候運行。運行開始後的錯誤或中止，會在該執行緒的這次運行中反映，不會透過 `onError` 或 `onAbort` 回報。

如需在運行完成後處理結果，請使用不連結執行緒的排程。如需生命週期狀態、清理、重試或多個步驟，請用 [Workflow 排程](/docs/workflows/scheduled-workflows)。

每個鉤子的上下文都帶有 `schedule`、`trigger`，以及今次排程所觸發的 Agent 的 `agentId`。

鉤子擲出的例外會被捕捉並記錄，不會改變 Worker 的處理流程，亦不會觸發其他鉤子。

## 在 Mastra Code 定期發送提示詞 {/* #recurring-prompts-in-mastra-code */}

Mastra Code 提供 `/schedules` 指令，可在目前的對話執行緒加入定期發送的提示詞。跟 `mastra.schedules` 不同，這些排程只存在於建立它們的 Mastra Code 程序，不會寫入儲存；每次觸發都直接用 `agent.sendSignal()` 發送到執行緒。

執行 `/schedules` 可開啟選單，當中有 **Create schedule**，並逐項列出目前執行緒的排程。建立排程的步驟如下：

1. 選擇每次觸發的內容來源：提示詞（**Prompt**）、每次觸發都會重新讀取的提示詞檔案（**Prompt file**），或每次觸發都會運行的指令碼（**Script**）。
1. 輸入提示詞內容或檔案路徑。路徑以項目根目錄為準。如果選擇指令碼，可另加提示詞，在指令碼輸出後一併送出。
1. 選用 `1m` 至 `1d` 之間的周期，或輸入 `20m`、`3h` 一類的設定。分鐘間隔必須能整除一小時，小時間隔則須能整除一日。
1. 確認。

指令碼由項目根目錄運行，逾時為 60 秒。標準輸出、標準錯誤輸出及結束代碼會組成提示詞。額外的提示詞不會傳給指令碼。

選取現有排程後，可使用 **Run now**、**Pause** 或 **Resume**，以及 **Delete**。**Run now** 即時觸發一次，原來的周期維持不變；暫停的排程也適用。如果同一排程仍有一次觸發在運行，則跳過今次觸發。

每次觸發都以 `user` 類型的訊號進入執行緒，在對話記錄內顯示為 `schedule` 項目，附有排程 ID、周期、來源和指令碼結束狀態。如果執行緒正在運行，Agent 會把提示詞作為下一項輸入，跟你在運行期間輸入訊息一樣。執行緒閒置時則會被喚醒並運行。程序中任何執行緒的排程都可觸發，毋須在終端機選中該執行緒。執行 `/new` 後，新建立的排程會連結到新的執行緒。

使用時留意以下行為：

- **只限當前工作階段。** 排程只在建立它的 Mastra Code 程序中有效，程序結束便會停止。即使共用資料庫，其他 Mastra Code 程序也不會看見或觸發這些排程。
- **對齊時鐘刻度。** `5m` 會在 :00、:05、:10 等時刻觸發，並非在建立後五分鐘才觸發；`1d` 會在本地午夜觸發。跟 cron 一樣，按小時及按日的周期以當地時鐘為準，會隨夏令時間調整。電腦休眠期間錯過的觸發，以及計時器遲了超過一分鐘的觸發，都會跳過。排程到下一個預定時刻便會繼續。
- **跳過重疊的觸發。** 到了下一個觸發時間，如果指令碼仍在運行，就跳過今次。

### Agent 排程工具 {/* #agent-schedule-tools */}

在 `/settings` 開啟 **Experimental schedule tools** 並重啟後，Agent 可以用以下工具管理同一批排程：`schedule_create`、`schedule_list`、`schedule_update`（暫停或刪除）、`schedule_resume` 和 `schedule_run`。這些工具只可查看及修改呼叫工具的那次運行所屬執行緒中的排程。排程每次觸發都可運行指令碼，因此除非已啟用 YOLO 模式，否則 `schedule_create`、`schedule_resume` 和 `schedule_run` 都需要跟運行 shell 指令相同的批准。對話記錄會把 Agent 建立的排程標示為 `created by agent`。
