# PubSub

Mastra 採用發佈／訂閱（pub/sub）系統作為內部事件匯流排。元件向主題發佈事件，其他元件則訂閱主題並回應事件。後端決定事件在單一程序內、同一主機的多個程序之間，還是跨實例傳遞。

只需在 `Mastra` 實例設定一次後端，整個系統便會共用。預設採用程序內後端，毋須另行設定。

## Mastra 如何使用 PubSub {/* #how-mastra-uses-pubsub */}

多個內置系統經同一條匯流排發佈和訂閱事件：

- **執行 Workflow**：排程器發佈 `workflow.start` 事件，由持續運行的 Worker 接收並執行 Workflow。執行期間的步驟和生命週期事件亦透過 PubSub 傳送。
- **排程 Workflow**：排程器向 Workflow 主題發佈事件，派發已到執行時間的工作。詳見[排程 Workflow](/docs/workflows/scheduled-workflows)。
- **背景工作**：工作管理器將工作派給一組 Worker，並向訂閱者分發工作生命週期的更新，讓背景工作串流保持即時。詳見[背景工作串流](/docs/harness/background-tasks#subscribe-to-all-task-events)。
- **Agent 訊號**：向正在運行的 Agent 傳送訊號時，系統會向執行緒主題發佈事件，即使該 Agent 在另一程序運行也收得到。
- **可恢復串流**：串流片段按每次運行發佈，客戶端重新連接後可重播錯過的片段。

這些系統共用一條匯流排，因此你選擇的後端會同時套用至所有系統。

## 事件傳送模式 {/* #delivery-modes */}

按 [`PubSub`](/reference/pubsub/base) 的介面規範，後端以以下其中一種模式傳送事件：

- **拉取**：消費者主動從後端讀取事件，Mastra 透過持續運行的 Worker 迴圈處理。[`RedisStreamsPubSub`](/reference/pubsub/redis-streams) 等分散式後端採用此模式。
- **推送**：消費者毋須提出請求，事件會在程序內或經 HTTP 送達。預設的 [`EventEmitterPubSub`](/reference/pubsub/event-emitter) 在程序內推送事件。

訂閱者亦可透過消費者群組分工。同組成員分攤事件，每個事件在組內只處理一次。沒有加入群組的訂閱者各自收到全部事件。

## 預設後端 {/* #default-backend */}

如未設定 `pubsub` 選項，Mastra 會採用 [`EventEmitterPubSub`](/reference/pubsub/event-emitter)。它使用 Node.js 的 [`EventEmitter`](https://nodejs.org/api/events.html#class-eventemitter) 在程序內傳送事件，毋須外部服務。

```typescript title="src/mastra/index.ts"
import { Mastra } from '@mastra/core'

// No pubsub option: Mastra uses EventEmitterPubSub
export const mastra = new Mastra({})
```

事件只在程序內傳送，不會持久保存，也不會送達其他程序。預設後端適合單一實例，足以應付大部分應用程式的需要。

## 選擇後端 {/* #choosing-a-backend */}

在 `Mastra` 實例以 `pubsub` 選項選擇後端。各後端都遵循相同的 [`PubSub`](/reference/pubsub/base) 介面規格，應用程式其他部分毋須改動。

選擇後端取決於訂閱者在哪裏運行。

| 後端 | 範圍 | 模式 | 套件 |
| - | - | - | - |
| [`EventEmitterPubSub`](/reference/pubsub/event-emitter) | 單一程序 | 拉取及推送 | `@mastra/core` |
| [`UnixSocketPubSub`](/reference/pubsub/unix-socket-pubsub) | 單一主機、多個程序 | 推送 | `@mastra/core` |
| [`RedisStreamsPubSub`](/reference/pubsub/redis-streams) | 分散式、多部主機 | 拉取 | `@mastra/redis-streams` |
| [`GoogleCloudPubSub`](/reference/pubsub/google-cloud-pubsub) | 分散式、多部主機 | 拉取 | `@mastra/google-cloud-pubsub` |

### 一台主機上的多個進程 {/* #multiple-processes-on-one-host */}

同一部主機的多個程序需要共用事件串流時，可使用 [`UnixSocketPubSub`](/reference/pubsub/unix-socket-pubsub)。它透過 Unix domain socket 傳送事件，並選出一個程序作為中介；中介結束時，其餘程序會重新選出中介。

```typescript title="src/mastra/index.ts"
import { Mastra } from '@mastra/core'
import { UnixSocketPubSub } from '@mastra/core/events'

export const mastra = new Mastra({
  pubsub: new UnixSocketPubSub('/tmp/mastra/events.sock'),
})
```

### 分散式部署 {/* #distributed-deployments */}

如在多個實例或主機上運行，而且每個實例都需要接收相同事件，請使用分散式後端。例如，一個實例處理的請求可能需要觸及另一實例正在執行的工作。

例如，向正在運行的 Agent 發送訊號時，事件必須跨程序送至負責該次運行的實例。若使用預設的程序內後端，該實例不會收到事件。

如儲存配接器不支援執行隔離（run fencing），[持久化 Agent](/docs/harness/durable-agents#run-ownership) 從故障復原時亦依賴後端。系統會利用後端租約判斷是否有其他實例仍在推進該次運行。`RedisStreamsPubSub` 支援跨主機租約，`GoogleCloudPubSub` 則不支援。

以下兩種後端均可跨程序和主機傳送事件，並持久保存事件，以便再次傳送。

以下例子使用 [Redis Streams](https://redis.io/docs/latest/develop/data-types/streams/)：

```typescript title="src/mastra/index.ts"
import { Mastra } from '@mastra/core'
import { RedisStreamsPubSub } from '@mastra/redis-streams'

export const mastra = new Mastra({
  pubsub: new RedisStreamsPubSub({
    url: 'redis://localhost:6379',
  }),
})
```

以下例子使用 [Google Cloud Pub/Sub](https://cloud.google.com/pubsub/docs)：

```typescript title="src/mastra/index.ts"
import { Mastra } from '@mastra/core'
import { GoogleCloudPubSub } from '@mastra/google-cloud-pubsub'

export const mastra = new Mastra({
  pubsub: new GoogleCloudPubSub({
    projectId: 'my-project',
  }),
})
```

## 可恢復串流 {/* #resumable-streams */}

可恢復串流讓客戶端重新連接後重播錯過的事件，後端須保留近期紀錄。[`RedisStreamsPubSub`](/reference/pubsub/redis-streams) 等分散式後端會持久保存事件，本身已支援重播。

程序內傳送不保留歷史紀錄。要為 [`EventEmitterPubSub`](/reference/pubsub/event-emitter) 加入重播功能，可用 [`CachingPubSub`](/reference/pubsub/caching-pubsub) 包裝它。它按主題記錄已發佈的事件，讓較遲加入或重新連接的訂閱者先補收事件，再接收即時事件。

```typescript title="src/mastra/index.ts"
import { Mastra } from '@mastra/core'
import { CachingPubSub, EventEmitterPubSub } from '@mastra/core/events'
import { InMemoryServerCache } from '@mastra/core/cache'

const cache = new InMemoryServerCache()

export const mastra = new Mastra({
  pubsub: new CachingPubSub(new EventEmitterPubSub(), cache),
})
```

完整的事件傳送規範及各後端的設定選項，請參閱 [PubSub 參考文件](/reference/pubsub/base)。
