# 內建MCP伺服器

Mastra 伺服器向您公開您的Agent、Workflow和Tool[Model Context Protocol (MCP)](https://modelcontextprotocol.io/introduction)客戶在`/api/mcp`。你沒有定義一個`MCPServer`對於它：在網站上註冊的每個Agent商、Workflow和Tool`Mastra`實例可用，您稍後新增的Agent程式會自動出現。

每個 MCP Tool都是現有 HTTP 路由的薄包裝器。呼叫執行與 HTTP 請求相同的驗證、驗證、RBAC、FGA 和所有權檢查，並使用相同的`RequestContext`. An MCP client can never do more than the same user can do over the HTTP API.

使用內建伺服器讓編碼助理和其他 MCP 用戶端驅動您已經執行的 Mastra 應用程式。要使用您自己的提示和資源發布一組精心挑選的原語，請創建一個[`MCPServer`](/docs/connections/mcp#expose-a-mastra-mcp-server) instead.

## 安裝 {/* #installation */}

端點使用`@mastra/mcp`, which `@mastra/server` declares as an optional peer dependency. Install it in your project to enable the built-in server:

```bash npm2yarn
npm install @mastra/mcp@latest
```

沒有它，伺服器的其餘部分仍然可以工作，並且`/api/mcp` answers with HTTP 501 and a JSON-RPC error that says to install the package. `mastra build` only adds `@mastra/mcp` to the build output when your project installs it.

## 上菜時 {/* #when-its-served */}

|環境 |任職於`/api/mcp` |
| - | - |
| `mastra dev` | Yes, also without auth. Requests with a foreign `Origin` or `Host` header are rejected to block DNS rebinding. This also blocks tunnels and LAN IP addresses. To reach the endpoint from another machine, set `server.host` to the hostname or IP address clients connect to. Binding to `0.0.0.0` doesn't allow other hosts. |
| Production build with `server.auth` | Yes. Every request needs a bearer token. |
| Production build without `server.auth`|不，端點回傳 404。

放`server.mcp.enabled` to override the default. `false` turns the endpoint off everywhere. `true` serves it even without `server.auth` and logs a warning, because anyone who can reach the server can then call your agents, workflows, and tools.

## 連線客戶端 {/* #connect-a-client */}

啟動開發伺服器，然後將客戶端指向端點。克勞德代碼：

```bash
claude mcp add --transport http mastra http://localhost:4111/api/mcp
```

配置身份驗證後，傳遞不記名令牌：

```bash
claude mcp add --transport http mastra https://my-app.example.com/api/mcp \
  --header "Authorization: Bearer $MASTRA_TOKEN"
```

若要從命令列檢查Tool，請使用[MCP Inspector](https://github.com/modelcontextprotocol/inspector):

```bash
npx @modelcontextprotocol/inspector --cli http://localhost:4111/api/mcp \
  --transport http --header "Authorization: Bearer $MASTRA_TOKEN" --method tools/list
```

遊標和 VS Code 從 JSON 檔案讀取伺服器。將其添加到`.cursor/mcp.json` for Cursor:

```json title=".cursor/mcp.json"
{
  "mcpServers": {
    "mastra": {
      "url": "http://localhost:4111/api/mcp",
      "headers": { "Authorization": "Bearer <your-token>" }
    }
  }
}
```

或者到`.vscode/mcp.json` for VS Code:

```json title=".vscode/mcp.json"
{
  "servers": {
    "mastra": {
      "type": "http",
      "url": "http://localhost:4111/api/mcp",
      "headers": { "Authorization": "Bearer <your-token>" }
    }
  }
}
```

省略`headers` when the server runs without `server.auth`. Clients that take only a URL and can't send an `Authorization` header, such as custom connectors in the Claude apps, need [OAuth discovery](#oauth-discovery) and an identity provider that lets them sign in.

端點使用無狀態 Streamable HTTP 並使用 MCP`2026-07-28` and the 2025 revisions that current clients use, so no session is kept between requests.

### 在工作室 {/* #in-studio */}

這**MCP Servers** page in Studio shows the built-in server as **Mastra (built-in)**, above the MCP servers you register yourself. It shows the endpoint URL (including a custom `server.mcp.path` or `apiPrefix`), whether the endpoint is open or protected by `server.auth`, the toolsets it serves (`include` and `exclude` aren't reflected there), and copyable setup for Claude Code, Cursor, VS Code, and the MCP Inspector. The setup uses a `<your-token>` placeholder. Replace it with your own bearer token. If the endpoint is turned off, or `@mastra/mcp` isn't installed, the card says why and how to fix it.

端點 URL 是根據 Studio 用於存取您的伺服器的位址建立的。如果 MCP 用戶端透過不同的公用 URL（例如在Agent程式後面）到達伺服器，請在設定中使用該 URL。和[OAuth discovery](#oauth-discovery), a client that can sign in doesn't need the `Authorization` header.

Studio 從中讀取此內容`GET /api/mcp/builtin`, which needs the `mcp:read` permission. Studio doesn't list the server's tools or let you try them, because the tool list depends on the caller's token. Connect a client to see your tools.

## Tool {/* #tools */}

伺服器將Tool分組到Tool集中。本節涵蓋`agents`, `workflows`, and `tools`; see [Memory, observability, and agent builder](#memory-observability-and-agent-builder) for the others. Agents and workflows are reached through operation tools that take the id as an argument. The tool list stays the same size however many agents you add.

請參閱[built-in MCP tools reference](/reference/server/builtin-mcp-tools) for every tool's arguments, route, and permission.

|Tool組 |Tool|支援 HTTP 路由 |
| - | - | - |
|`agents` | `list_agents`, `get_agent`, `call_agent` | `GET /agents`, `GET /agents/:agentId`, `POST /agents/:agentId/generate` |
| `workflows` | `list_workflows`, `get_workflow`, `start_workflow`, `get_workflow_run`, `resume_workflow_run`, `cancel_workflow_run` | `GET /workflows`, `GET /workflows/:workflowId`, `POST /workflows/:workflowId/start-async`, `GET /workflows/:workflowId/runs/:runId`, `POST /workflows/:workflowId/resume-async`, `POST /workflows/:workflowId/runs/:runId/cancel` |
| `tools` | `tool_<id>`對於每個註冊的Tool|`POST /tools/:toolId/execute` |

* 當呼叫者最多可以看到`enumLimit` agents or workflows (25 by default), the `agentId` and `workflowId` arguments list the allowed ids. Above that they're plain strings, and the client calls `list_agents` or `list_workflows` to find ids.
* 當呼叫者可以看到超過`enumLimit` tools, the `tool_<id>` tools are replaced by `list_tools`, `get_tool`, and `call_tool`.
* `call_agent`返回回應文字和`threadId`. Pass the `threadId` back to continue the conversation in the agent's memory. A call without a `threadId` starts a new thread, so a client that never passes one stores a thread for each call.
* `start_workflow`等待運行完成或暫停。暫停的運行返回其`runId` and suspend payload. Continue it with `resume_workflow_run`.
* 沒有Agent的`description` get a generic one and a warning in the logs. Add descriptions so clients can pick the right agent.

### 特色Agent商和Workflow {/* #featured-agents-and-workflows */}

列出Agent商和Workflow`featured` to give them a dedicated tool. A featured workflow's tool takes the workflow's input schema directly:

```typescript title="src/mastra/index.ts"
import { Mastra } from '@mastra/core'

export const mastra = new Mastra({
  // ...agents, workflows, tools
  server: {
    mcp: {
      featured: { agents: ['support-agent'], workflows: ['refund'] },
    },
  },
})
```

這增加了`agent_support-agent` and `workflow_refund` next to the operation tools.

## 選擇要公開的內容 {/* #choose-what-to-expose */}

使用`include` and `exclude` to select primitives by id. Each entry matches both a primitive's own `id` and the key it's registered under in `new Mastra({ ... })`, so `deleteAccountTool` and `delete-account` select the same tool. `exclude` wins over `include`. Excluded primitives are hidden from the tool list, and calling one by either name fails as not found. This includes passing an excluded agent's id to the memory tools. Observability tools aren't filtered: their results can still include traces, logs, and scores from excluded primitives. The selection only affects MCP. The HTTP routes are unchanged.

```typescript title="src/mastra/index.ts"
import { Mastra } from '@mastra/core'

export const mastra = new Mastra({
  server: {
    mcp: {
      toolsets: ['agents', 'tools'],
      include: { agents: ['support-agent', 'billing-agent'] },
      exclude: { tools: ['delete-account'] },
    },
  },
})
```

放`readOnly: true` to serve only tools whose backing route needs a `read` permission, such as `list_agents` and `get_workflow_run`.

客戶端可以縮小每個連線的配置範圍`?toolsets=agents,tools` or the `X-MCP-Toolsets` header, and `?readonly=1` or the `X-MCP-Readonly` header. These can only remove tools, never add tools the configuration doesn't serve.

## 身份驗證和權限 {/* #authentication-and-permissions */}

端點僅接受來自`Authorization: Bearer` header, verified by `server.auth`. Session cookies, the `apiKey` query parameter, and Studio's auth configuration don't apply to it, so a browser session can't be used to reach it from another site. Other routes keep their existing auth behavior.

和[RBAC](/docs/auth/overview) configured, MCP access needs two permissions on top of the route permissions:

* `mcp:read`連接並列出Tool。
* `mcp:execute`查看並呼叫任何Tool。沒有它的呼叫者會得到一個空的Tool列表，即使它可以透過 HTTP 執行相同的操作。

每次呼叫還需要備份路由的許可，例如`agents:execute` for `call_agent` and `workflows:execute` for `start_workflow`. The default `viewer` role has `mcp:read` but not `mcp:execute`; `member`, `admin`, and `owner` have both. These are the same permissions that guard the routes of `MCPServer` instances you register, so a role granted them for your own MCP servers can also use the built-in one.

Tool清單按呼叫者過濾。當呼叫者在其中看到Agent和Workflow時，它們就會出現`GET /agents` or `GET /workflows`, including [FGA](/docs/auth/fga) read checks. Tools the caller would get a 403 for are hidden. Every call is checked again when it runs, so a stale list can't be used to bypass a permission.

執行緒和運行所有權的工作方式與 HTTP API 類似：使用者無法繼續另一個使用者的執行緒或恢復另一個使用者的Workflow運行。

入站不記名令牌不會作為參數傳遞給Tool，也不會轉發給其他伺服器。Tool收到相同的訊息`RequestContext` as the equivalent HTTP request.

## 記憶體、可觀察性和Agent構建器 {/* #memory-observability-and-agent-builder */}

這些Tool集預設為啟用狀態。每個Tool僅在伺服器可以支援時才提供服務，每個Tool都使用相同的權限和所有權檢查來呼叫為其列出的 HTTP 路由。

|Tool組 |Tool|任職時間 |
| - | - | - |
|`memory` | `list_threads`, `get_thread`, `list_messages`, `search_memory`, `get_memory_status`, `get_observations`, `create_thread`, `update_thread`, `clone_thread`, `save_messages` | An agent has memory, or stored agents are configured |
| `observability` | `query_traces`, `aggregate_traces`, `query_spans`, `aggregate_spans`, `query_threads`, `get_trace_query_fields`, `get_trace_query_values`, `get_trace`, `get_span`, `get_trace_trajectory`, `list_logs`, `list_traces` | Storage has an observability domain |
| `observability_analytics` | `analyze_metrics`, `analyze_scores`, `analyze_feedback`, `list_metric_names`, `list_scores`, `list_feedback` | Storage has an observability domain |
| `stored_agents` | `list_available_models`, `list_stored_agents`, `get_stored_agent`, `create_stored_agent`, `update_stored_agent`|這[編輯](/docs/studio/editor)並配置了Agent存儲域|

* 記憶Tool需要`agentId` and `threadId`. `resourceId` defaults to the caller when `server.auth` maps users to resources with `mapUserToResourceId`, and a caller can't read or write another resource's threads, messages, or Observational Memory. Without that mapping, a supplied `resourceId` is used as is, as on the HTTP API.
* 可觀察性Tool取決於儲存支援的內容。具有追蹤查詢的存儲，例如 DuckDB，提供服務`query_traces` and the other query tools; a store without them serves `list_traces` instead. Tools for logs, metrics, scores, and feedback appear only when the store implements them.
* `get_trace`返迴光追蹤：每個跨度的 ID、父級、名稱、類型、計時、狀態和實體。稱呼`get_span` for one span's input, output, and attributes. List and trace results are kept under about 40,000 characters. A cut result says how to get the rest: a smaller page size, or `get_trace` with the returned `nextOffset`. A single item that's still too big, such as a message with an inline image, comes back with its long values cut and marked. `get_span` returns a span in full. `get_observations` cuts an oversized record the same way.
* `analyze_metrics`, `analyze_scores`, and `analyze_feedback` take an `op` of `aggregate`, `breakdown`, `timeseries`, or `percentiles`. Each op runs the matching `/observability/<source>/<op>` route.
* `create_stored_agent`和`update_stored_agent` publish the change by default, so the agent can be called with `call_agent` right away. Pass `autoPublish: false` to keep a draft. The `agentId` argument of `call_agent` lists only the agents that existed when the client fetched the tool list, so a client must list the tools again before it can call a newly created agent.

在唯讀模式下，查詢和聚合Tool保持可用，因為它們的路由需要`observability:read`, even though they're `POST` routes. Memory and stored-agent writes are removed. `get_observations` stays, without its `waitForPending` option, because waiting runs a route that needs `memory:write`. Callers without `memory:write` also get `get_observations` without that option.

：：：警告

可觀察性資料的範圍不限於呼叫者。任何有`observability:read` can read every user's traces, logs, scores, and feedback, over MCP and over HTTP. The default `viewer` role includes it through `*:read`. Leave out the observability toolsets, or remove `observability:read` from roles that shouldn't see other users' data:

```typescript title="src/mastra/index.ts"
import { Mastra } from '@mastra/core'

export const mastra = new Mastra({
  server: {
    mcp: { toolsets: ['agents', 'workflows', 'tools', 'memory', 'stored_agents'] },
  },
})
```

### Agent創建Agent {/* #agents-creating-agents */}

`create_stored_agent`讓 MCP 客戶端建立其他客戶端隨後可以呼叫的Agent程式。它需要`stored-agents:write`. A created agent is owned by the caller and is private by default. Without a caller identity, such as when `server.auth` isn't configured, the agent has no owner and is public, even with `visibility: 'private'`. Other users don't see a private agent in `list_agents` or `list_stored_agents`, and unless they're admins or granted that agent by id, calling it answers as if it doesn't exist, the same as over HTTP. Set `visibility: 'public'` to let every user call it. Only the owner, admins, and users granted that agent by id can edit it either way. An agent with no owner can be edited by any user with `stored-agents:write`. See [stored agent visibility](/docs/studio/editor#visibility). When the agent builder restricts models, the MCP tools accept only allowed models for the agent's model (the `provider` and `name` it runs, in each conditional variant), for any model named in `defaultOptions` (such as `structuredOutput.model`), for each enabled entry of the fallback `modelList`, for the memory models (the Observational Memory observer and reflector models and the title model), and for the `model` of every input and output processor step, at any depth of the processor graph. They also reject anything that would run on a default model the policy can't check: `observationalMemory: true`, an Observational Memory config without a `model`, memory left out on create (which the agent builder fills with Observational Memory on its default model), or a processor that needs a model, such as `moderation`, without one. Set an allowed `model` instead. A stored `model` takes only `provider`, `name`, and model settings such as `temperature`. Other keys, such as `modelId` or `providerId`, are rejected. If the agent builder's policy can't be loaded, the tools return an error instead of saving unchecked. `list_available_models` returns the allowed models. The HTTP route doesn't apply this check, so a user who can call `POST /stored/agents` directly can still save any model. Embedding models (`memory.embedder`) aren't on the builder's model list and aren't checked. Tool allowlists aren't checked when an agent is saved, so a created agent can use any tool the server has. Its tools run with the permissions of the user who calls it.

觀察記憶體僅在執行緒達到其令牌閾值（預設為 30,000 個令牌）後才開始觀察。對於簡短的演示，設置較低的`observation.messageTokens` so the agent learns from a few messages. Observational Memory processes messages in the background, so right after `call_agent`, call `get_observations` with `waitForPending: true` to wait (up to 30 seconds) for it to finish before reading.

## OAuth 發現 {/* #oauth-discovery */}

什麼時候`server.auth` is configured, the endpoint tells MCP clients how to get a token, following the [MCP authorization spec](https://modelcontextprotocol.io/specification/draft/basic/authorization). A request without a valid token gets a `401` whose `WWW-Authenticate` header points at the endpoint's protected-resource metadata ([RFC 9728](https://datatracker.ietf.org/doc/html/rfc9728)):

```http
HTTP/1.1 401 Unauthorized
WWW-Authenticate: Bearer resource_metadata="https://my-app.example.com/.well-known/oauth-protected-resource/api/mcp"
```

當請求攜帶驗證失敗的令牌時，例如因為過期，標頭還包括`error="invalid_token"`. Other routes return their `401` without this header.

元數據是公開的並提供於`/.well-known/oauth-protected-resource/api/mcp` and `/.well-known/oauth-protected-resource`, outside the API prefix:

```json
{
  "resource": "https://my-app.example.com/api/mcp",
  "authorization_servers": ["https://my-tenant.us.auth0.com/"],
  "bearer_methods_supported": ["header"]
}
```

一位客戶讀到`authorization_servers`, runs the OAuth flow against your identity provider, and retries with the access token. Mastra doesn't act as an authorization server. Whether a client can sign in without a pre-registered OAuth app depends on your identity provider supporting dynamic client registration or client ID metadata documents.

Mastra 填充元數據`server.mcp.oauth` and from your auth provider:

* `resource`預設為從請求派生的端點 URL。在Agent或負載平衡器後面，請求可能攜帶內部主機，因此設定`server.mcp.oauth.resource` to the public URL. It must be an absolute `https` URL (`http` is allowed for `localhost`) without a fragment. An invalid value logs an error and turns OAuth discovery off, but the token audience is still checked against it, so MCP requests are rejected until you fix the value.
* 挑戰中的元資料 URL 所使用的來源`resource` with the endpoint's path on the server, for example `/.well-known/oauth-protected-resource/api/mcp`. If your proxy serves the endpoint under a different public path, it must also forward that well-known URL to Mastra.
* `authorization_servers`當提供者知道其發行者時來自該提供者（見下表）。否則設定`server.mcp.oauth.authorizationServers`. Without either, the field is left out and clients need a token configured by hand.
* `scopes_supported`僅當您設定時才包含在內`server.mcp.oauth.scopesSupported`.

```typescript title="src/mastra/index.ts"
import { Mastra } from '@mastra/core'
import { MastraAuthWorkos } from '@mastra/auth-workos'

export const mastra = new Mastra({
  server: {
    auth: new MastraAuthWorkos(),
    mcp: {
      oauth: {
        resource: 'https://my-app.example.com/api/mcp',
        authorizationServers: ['https://my-app.authkit.app'],
      },
    },
  },
})
```

### 代幣受眾 {/* #token-audience */}

環境`server.mcp.oauth.resource` also makes the endpoint check that a token was issued for it: the token's `aud` claim must include the `resource` value. A token for another API gets a `401` with `error="invalid_token"`, so a token leaked from a different service can't be replayed against your MCP endpoint. Without `resource`, any token your auth provider accepts works, as it did before. The check only applies to `/api/mcp`: other routes still accept a token issued for a different API. The comparison is exact, so `https://my-app.example.com/api/mcp/` with a trailing slash doesn't match `https://my-app.example.com/api/mcp`.

配置您的身分提供者以向該受眾頒發令牌，例如透過註冊`resource` URL as an API identifier in Auth0. Auth0 also verifies its own `audience` option (`AUTH0_AUDIENCE`), so either set that option to the `resource` URL or issue tokens whose `aud` includes both values.

|Provider|授權伺服器公佈 |觀眾檢查`resource` |
| - | - | - |
| [`MastraJwtAuth`](/reference/auth/jwt) | `issuer` option | Yes |
| [Auth0](/reference/auth/auth0) | `https://<domain>/` | Yes |
| [Okta](/reference/auth/okta) | `issuer` option | No. Okta checks the token against its own `audience` option, so set that to the `resource` URL. |
| [Clerk](/reference/auth/clerk) | Frontend API URL from the publishable key. Your OAuth application must issue JWT access tokens (the default for applications created since January 2026). Opaque tokens are rejected. | No |
| [Supabase](/reference/auth/supabase) | `<url>/auth/v1`. Clients can only sign in there if the OAuth 2.1 server is turned on for your Supabase project. | No |
| [`CompositeAuth`](/docs/auth/composite-auth) | All inner providers' servers | Delegated to the provider that authenticated the token |
| WorkOS, Google, Neon, Firebase, Better Auth, custom providers | Set `authorizationServers` | No |

什麼時候`resource` is set and a provider can't check the audience, Mastra logs a warning at startup and accepts that provider's tokens for any audience. This keeps API keys and other opaque tokens working. To reject them on `/api/mcp` instead, set `requireAudience: true`:

```typescript title="src/mastra/index.ts"
import { Mastra } from '@mastra/core'
import { CompositeAuth, SimpleAuth } from '@mastra/core/server'
import { MastraJwtAuth } from '@mastra/auth'

const jwtAuth = new MastraJwtAuth({
  jwksUri: 'https://auth.example.com/.well-known/jwks.json',
  issuer: 'https://auth.example.com/',
})
const apiKeyAuth = new SimpleAuth({ tokens: { [process.env.API_KEY!]: { id: 'ci' } } })

export const mastra = new Mastra({
  server: {
    auth: new CompositeAuth([jwtAuth, apiKeyAuth]),
    mcp: {
      oauth: { resource: 'https://my-app.example.com/api/mcp', requireAudience: true },
    },
  },
})
```

和`requireAudience`, a request authenticated by a provider without an audience check, such as `SimpleAuth`, gets a `401` with `error="invalid_token"` on `/api/mcp`. Inside `CompositeAuth`, only requests accepted by those providers are rejected. Other routes still accept them. `requireAudience` needs `resource`, and without `resource` nothing is checked.

客製化提供者透過實施來選擇加入`verifyAudience()` and `getOAuthMetadata()`, see [custom auth providers](/docs/auth/custom-auth-provider).

### 連接 OAuth 用戶端 {/* #connect-an-oauth-client */}

使用支援動態客戶端註冊的身份提供程序，添加不帶令牌的伺服器，客戶端在首次使用時運行登入流程：

```bash
claude mcp add --transport http mastra https://my-app.example.com/api/mcp
```

否則，獲取訪問令牌`resource` audience from your identity provider and pass it as a header:

```bash
claude mcp add --transport http mastra https://my-app.example.com/api/mcp \
  --header "Authorization: Bearer $MASTRA_TOKEN"
```

端點不返回`403` with `error="insufficient_scope"` yet. A caller without `mcp:read` gets a plain `403`, because Mastra permissions aren't OAuth scopes a client could request.

## 限制 {/* #limitations */}

* Workflow在 MCP 請求內同步運作。長時間運行的Workflow受伺服器請求逾時的限制。
* 沒有針對每個基元的選擇退出`Agent`, `Workflow`, or tool constructors yet. Use `server.mcp.include` and `server.mcp.exclude`.
* 工作記憶體、刪除執行緒或儲存的Agent以及記分器和Workspace管理都不會公開。
