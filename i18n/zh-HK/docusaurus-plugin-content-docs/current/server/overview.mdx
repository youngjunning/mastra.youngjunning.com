# 伺服器

Mastra 以 HTTP 伺服器運作，經 API 端點提供 Agent、Workflow 等功能，並處理請求路由、中介軟件、身份驗證及串流回應。

:::note

本文說明傳入 `Mastra` 建構函數的 [`server`](/reference/configuration#server-options) 設定。如要以自己的 HTTP 伺服器（例如 Hono 或 Express）執行 Mastra，請參閱[伺服器配接器](/docs/server/server-adapters)。

:::

## 伺服器功能 {/* #server-features */}

- **[中介軟件](/docs/server/middleware)**：攔截請求以驗證身份、記錄日誌、處理 CORS 或加入當次請求的上下文。
- **[自訂 API 路由](/docs/server/custom-api-routes)**：加入可存取 Mastra 實例的 HTTP 端點。
- **[請求上下文](/docs/server/request-context)**：按執行時條件將個別請求的資料傳給 Agent、Tool 和 Workflow。
- **[伺服器配接器](/docs/server/server-adapters)**：以 Express、Hono 或自有 HTTP 伺服器執行 Mastra，取代自動產生的伺服器。
- **[自訂配接器](/docs/server/custom-adapters)**：為官方未有支援的框架編寫配接器。
- **[Mastra 客戶端 SDK](/docs/server/mastra-client)**：提供型別安全的客戶端，讓瀏覽器或伺服器呼叫 Agent、Workflow 和 Tool。
- **[內置 MCP 伺服器](/docs/server/mcp)**：Claude Code、Cursor 等 MCP 客戶端可經 `/api/mcp` 呼叫 Agent、Workflow 和 Tool，並採用與 HTTP API 相同的身份驗證及權限。
- **[A2A](/docs/connections/a2a)**：以 A2A Agent 卡和任務串流公開 Agent，並支援推送通知。
- **[身份驗證](/docs/auth/overview)**：以 JWT、Clerk、Supabase、Firebase、Auth0 或 WorkOS 保護端點。

## 配置 {/* #configuration */}

要設定伺服器，可把 `server` 物件傳給 `Mastra` 建構函數：

```typescript title="src/mastra/index.ts"
import { Mastra } from '@mastra/core'

export const mastra = new Mastra({
  server: {
    port: 3000, // Defaults to PORT env var or 4111
    host: '0.0.0.0', // Defaults to MASTRA_HOST env var or 'localhost'
  },
})
```

所有伺服器選項詳見[設定參考](/reference/configuration#server-options)。

## 部署您的伺服器 {/* #deploy-your-server */}

任何兼容 Node.js 的環境均可部署 Mastra 伺服器。可透過 [Mastra 平台](/docs/mastra-platform/overview) 或自有基礎設施部署至正式環境，詳見[部署文件](/docs/deployment/overview)。

## 伺服器架構 {/* #server-architecture */}

Mastra 採用 [Hono](https://hono.dev) 作為底層 HTTP 伺服器框架。以 `mastra build` 建置應用程式時，會在 `.mastra` 目錄產生基於 Hono 的 HTTP 伺服器。

伺服器提供：

- 所有已註冊 Agent 和 Workflow 的 API 端點
- 自訂 API 路由和中介軟體
- 支援不同 Provider 的身份驗證
- 用於執行時設定的請求上下文
- 遮蓋串流中的敏感資料，保障回應安全

## REST API {/* #rest-api */}

可在 [http://localhost:4111/api/openapi.json](http://localhost:4111/api/openapi.json) 查看 OpenAPI 規格。當中列出所有可用端點，以及每個端點的請求和回應結構。

在 [http://localhost:4111/swagger-ui](http://localhost:4111/swagger-ui) 開啟 Swagger UI，便可直接在瀏覽器查看及測試 API 端點。

:::note

正式環境預設停用 OpenAPI 和 Swagger 端點。如需啟用，請分別把 [`server.build.openAPIDocs`](/reference/configuration#serverbuild) 及 [`server.build.swaggerUI`](/reference/configuration#serverbuild) 設為 `true`。

:::

## OpenAI Responses API {/* #openai-responses-api */}

Mastra 提供兼容 OpenAI 的 Responses 和 Conversations 路由，讓你透過 Responses API 使用 Mastra Agent。路由在 Agent、Memory 和儲存之上提供配接功能，由指定的 Mastra Agent 處理請求，並不直接代理 Provider。

這些 API 目前處於實驗階段。

以 `agent_id` 選擇處理請求的 Mastra Agent。首次請求直接指定 Agent，其後可經 `previous_response_id` 延續已儲存的對話。傳入 `model` 可只替換當次請求使用的模型，省略則沿用 Agent 的模型。

Responses 路由支援串流和函數呼叫（Tool），可用 `previous_response_id` 接續已儲存的回應、以 `conversation_id` 指定對話執行緒、經 `providerOptions` 轉傳 Provider 專用選項，以及經 `text.format` 輸出 JSON。

請求及回應的完整規格見 [Responses API 參考](/reference/client-js/responses)及 [Conversations API 參考](/reference/client-js/conversations)。[伺服器路由](/reference/server/routes#responses-api)列出所有 HTTP 路由。

## 遮蓋串流資料 {/* #stream-data-redaction */}

串流傳送 Agent 回應時，HTTP 層會在每個資料區塊送出前遮蓋系統提示詞、Tool 定義、API 金鑰等資料。此功能預設啟用。

只有使用[伺服器配接器](/docs/server/server-adapters#stream-data-redaction)才可調整這項設定。配接器亦預設遮蓋串流中的敏感資料。

## TypeScript 配置 {/* #typescript-configuration */}

Mastra 要求 `module` 及 `moduleResolution` 採用兼容新版 Node.js 的設定，並不支援 `CommonJS` 或 `node` 等舊選項。

下方的 `types` 選項需要 `@types/node`。透過 [`create-mastra`](/reference/cli/create-mastra) 建立的項目已包含這個套件；如項目尚未安裝，可按以下方式加入：

```bash npm2yarn
npm install -D @types/node
```

```json {4-5} title="tsconfig.json"
{
  "compilerOptions": {
    "target": "ES2022",
    "module": "ES2022",
    "moduleResolution": "bundler",
    "esModuleInterop": true,
    "forceConsistentCasingInFileNames": true,
    "strict": true,
    "skipLibCheck": true,
    "types": ["node"],
    "noEmit": true,
    "outDir": "dist"
  },
  "include": ["src/**/*"]
}
```
