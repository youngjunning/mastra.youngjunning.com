# Server Adapter

Server Adapter 讓你以自己的 HTTP 伺服器執行 Mastra，而毋須使用 `mastra build` 產生的 Hono 伺服器。你可更靈活地設定自訂中介軟件次序、身分驗證、日誌及部署，同時仍可將 Mastra 接入任何 Node.js 應用程式，毋須改變 Agent 或 Workflow 的執行方式。

:::warning

Server Adapter 使用你傳入的 `mastra` 實例，不會執行檔案式自動探索。請在程式碼中將 Agent 註冊至該實例。如需使用檔案式 Agent，請透過 `mastra dev` 或 `mastra build` 將 Mastra 作為獨立伺服器執行。

:::

## 何時使用伺服器適配器 {/* #when-to-use-server-adapters */}

* 您希望 Mastra 的端點自動添加到現有應用程式中
* 您需要直接存取伺服器實例以進行自訂配置
- 團隊希望使用其他伺服器框架，而非 `mastra build` 建立的 Hono 伺服器。

:::tip

如部署毋須自訂伺服器，請使用 `mastra build`。它會設定伺服器、註冊中介軟件，並按項目設定套用部署設定。請參閱[伺服器設定](/docs/server/overview)。

如需配合 Server Adapter 使用 [Studio](/docs/studio/overview)，請透過 [`mastra studio`](/reference/cli/mastra#mastra-studio) 單獨啟動 Studio 介面。

:::

## 初始化流程 {/* #initialization-flow */}

呼叫 `init()` 會依次執行四個步驟。了解此流程有助於在指定位置插入自己的中介軟件。

1. `registerContextMiddleware()`：將 Mastra 實例、請求上下文、Tool和中止訊號附加到每個請求。這使得 Mastra 可用於所有後續中間件和路由處理程序。
1. `registerAuthMiddleware()`：初始化時執行 Adapter 的身分驗證 Hook。官方 Adapter 在 Mastra 註冊內置路由和 `registerApiRoute()` 路由時直接執行驗證；直接在框架註冊的路由如需 Mastra 驗證，應使用 Adapter 匯出的 `createAuthMiddleware()`。
1. `registerUserMiddleware()`：註冊來自 `server.middleware` 設定及 `mastra.setServerMiddleware()` 的[中介軟件](/docs/server/middleware)。這些處理函數使用 Hono 簽名，因此 Hono 類 Adapter（`@mastra/hono` 及基於它的 Adapter）會掛載它們；其他 Adapter 會記錄警告，而非默默忽略設定。
1. `registerRoutes()`：註冊 Agent、Workflow 等功能的所有 Mastra API 路由。如已設定 MCP Server，亦會註冊 MCP 路由。

### 手動初始化 {/* #manual-initialization */}

如需自訂中介軟件次序，請分別呼叫各方法，而非使用 `init()`。這可讓中介軟件在 Mastra 上下文建立前執行，或在不同初始化步驟之間插入邏輯。

```typescript title="server.ts" oxfmt:false
const server = new MastraServer({ app, mastra });

// Your middleware first
app.use(loggingMiddleware);

server.registerContextMiddleware();

// Middleware that needs Mastra context
app.use(customMiddleware);

// Registers `server.middleware` and `setServerMiddleware()` middleware
server.registerUserMiddleware();

await server.registerRoutes();

// Routes after Mastra
app.get('/health', ...);
```

:::tip

當您需要在 Mastra 上下文可用之前運行中間件時，或者當您需要在上下文和身份驗證步驟之間插入中間件時，請使用手動初始化。

:::

## 啟動後台工作者 {/* #start-background-workers */}

`init()` 只註冊中介軟件和路由，不會啟動 Mastra 的背景 [Worker](/docs/deployment/workers)。`mastra build` 產生的伺服器會自動啟動；使用 Server Adapter 時，需自行呼叫 `mastra.startWorkers()`。

如果沒有此調用，以下功能將永遠不會運行：

- [排程 Workflow](/docs/workflows/scheduled-workflows)：不會建立排程記錄，亦不會觸發 cron。
- 透過 `mastra.schedules` 建立的 [Agent 排程](/docs/harness/schedules)
* 您在 Mastra 實例上註冊的事件偵聽器
- [復原循環](/docs/workflows/overview#recovery-loop)：此伺服器啟動後，如預設引擎的 Workflow 執行實例停止，便不會重新啟動。

伺服器開始監聽後，呼叫一次 `startWorkers()`：

```typescript title="server.ts"
import express from 'express'
import { MastraServer } from '@mastra/express'
import { mastra } from './mastra'

const app = express()
app.use(express.json())

const server = new MastraServer({ app, mastra })
await server.init()

const httpServer = app.listen(4111, async () => {
  try {
    await mastra.startWorkers()
  } catch (error) {
    console.error('Failed to start background workers', error)
    httpServer.close(() => process.exit(1))
  }
})

process.on('SIGTERM', async () => {
  await mastra.shutdown()
  process.exit(0)
})
```

`startWorkers()` 具冪等性，重複呼叫不會有額外效果。`mastra.shutdown()` 會停止 Worker，並在關閉 Worker 和 pub/sub 訂閱前，等待進行中的 Workflow 執行完成或暫停。等待受 `drainTimeout` 限制（預設 5 秒）；逾時未結束的執行會被放棄並記錄警告。

如 Worker 在[獨立程序](/docs/deployment/workers#split-processes)運行，請勿在 API 程序呼叫 `startWorkers()`，應改在 Worker 程序啟動。

## 新增自訂路線 {/* #adding-custom-routes */}

您可以將自己的路線與 Mastra 的路線一起添加到應用程式中。

- 在 `init()` **之前**新增的路由無法存取 Mastra 上下文。
- 在 `init()` **之後**新增的路由可存取 Mastra 上下文（Mastra 實例、請求上下文、已驗證用戶等）。
- 如需 Mastra 管理的身分驗證及 `requiresAuth` 等路由中繼資料，請優先使用 `registerApiRoute()`。
- 直接在框架應用程式掛載的路由如需 Mastra 身分驗證，請使用 Adapter 匯出的 `createAuthMiddleware()` 輔助函數。

詳情請參閱 [Elysia](/reference/server/elysia-adapter#adding-custom-routes)、[Express](/reference/server/express-adapter#adding-custom-routes) 及 [Hono](/reference/server/hono-adapter#adding-custom-routes) 的「新增自訂路由」章節。

## 路由前綴 {/* #route-prefixes */}

Mastra 路由預設註冊於 `/api/agents`、`/api/workflows` 等路徑。可用 `prefix` 選項更改前綴，適合 API 版本管理，或接入已有 `/api` 路由的應用程式。

```typescript
const server = new MastraServer({
  app,
  mastra,
  prefix: '/api/v2',
})
```

使用此前綴後，Mastra 路由會變成 `/api/v2/agents`、`/api/v2/workflows` 等。直接加到應用程式的自訂路由不受此前綴影響。

[內置 MCP Server](/docs/server/mcp) 亦會隨此前綴移至 `/api/v2/mcp`。其 OAuth 中繼資料仍位於伺服器根路徑下的 `/.well-known/oauth-protected-resource/api/v2/mcp`。

## OpenAPI 規範 {/* #openapi-spec */}

Mastra 可為所有已註冊路由產生 OpenAPI 規格，方便產生文件或客戶端，亦可與 API 工具整合。設定 `openapiPath` 選項即可啟用：

```typescript
const server = new MastraServer({
  app,
  mastra,
  openapiPath: '/openapi.json',
})
```

規格根據各路由定義的 Zod Schema 產生，並在指定路徑提供。它包含所有 Mastra 路由，以及透過 `createRoute()` 建立的自訂路由。

## 串流數據遮蓋 {/* #stream-data-redaction */}

透過 HTTP 串流傳送 Agent 回應時，HTTP 串流層會在數據區塊送到客戶端前遮蓋其中的敏感資訊，避免以下內容意外外洩：

* 系統提示和坐席指令
* Tool定義及其參數
* 請求正文中的 API 金鑰和其他憑證
* 內部配置數據

遮蓋發生在 HTTP 邊界，因此 `onStepFinish` 等內部回呼仍可存取完整請求數據，用於除錯及可觀測性分析。

遮蓋預設啟用，可透過 `streamOptions` 設定。只有內部服務或除錯確實需要在串流回應中取得完整請求數據時，才設定 `redact: false`。

```typescript
const server = new MastraServer({
  app,
  mastra,
  streamOptions: {
    redact: true, // Default
  },
})
```

完整設定選項請參閱 [MastraServer](/reference/server/mastra-server)。

## 每個路由的身份驗證覆蓋 {/* #per-route-auth-overrides */}

在 Mastra 實例上配置身份驗證後，預設情況下所有路由都需要身份驗證。有時您需要例外：公共衛生檢查端點或 Webhook 接收器，或需要更嚴格控制的管理路由。

使用 `customRouteAuthConfig` 覆蓋特定路由的身分驗證行為。鍵格式為 `METHOD:PATH`，方法可為 `GET`、`POST`、`PUT`、`DELETE` 或 `ALL`。路徑支援萬用字元（`*`），可匹配多條路由。值為 `false` 時路由公開，為 `true` 時要求身分驗證。

```typescript
const server = new MastraServer({
  app,
  mastra,
  customRouteAuthConfig: new Map([
    // Public health check
    ['GET:/api/health', false],
    // Public API spec
    ['GET:/api/openapi.json', false],
    // Public webhook endpoints
    ['POST:/api/webhooks/*', false],
    // Require auth even if globally disabled
    ['POST:/api/admin/reset', true],
    // Protect all methods on internal routes
    ['ALL:/api/internal/*', true],
  ]),
})
```

完整設定選項請參閱 [MastraServer](/reference/server/mastra-server)。

建立 Adapter 後，你可能仍需存取底層框架應用程式，例如將它傳給平台的 `serve` 函數，或從其他模組新增路由。

## 伺服器配置與適配器選項 {/* #server-config-vs-adapter-options */}

使用 Server Adapter 時，設定來自兩處：傳給 `Mastra` 建構函數的 Mastra `server` 設定，以及 Adapter 建構函數的選項。了解各選項的來源，可避免設定看似未生效時感到困惑。

### 由適配器使用 {/* #used-by-adapters */}

Adapter 從 `mastra.getServer()` 讀取以下設定：

|選項 |說明 |
| - | - |
| `auth` | 身分驗證設定，供 `registerAuthMiddleware()` 使用。 |
| `apiRoutes` | 自訂 [`registerApiRoute()`](/reference/server/register-api-route) 路由，由 `registerCustomApiRoutes()` 註冊；設定 `openapiPath` 後會加入 OpenAPI 規格。Adapter 建構函數的 `customApiRoutes` 選項會覆蓋此清單。 |
| `bodySizeLimit` | 預設請求主體大小上限，單位為位元組。可透過 Adapter 的 `bodyLimitOptions` 覆蓋。 |
| `onError` | 路由處理程式發生未處理錯誤時呼叫的自訂錯誤處理函數。請參閱 [server.onError](/reference/configuration#serveronerror)。 |
| `middleware` | 用戶提供的[中介軟件](/docs/server/middleware)，由 `registerUserMiddleware()` 註冊。Hono 類 Adapter 會執行；Elysia、Express、Fastify、Koa 和 NestJS 則會記錄警告，因為 Hono 處理函數無法在這些框架執行。 |

### 僅適配器建構函數 {/* #adapter-constructor-only */}

這些選項直接傳遞給適配器建構函數，而不是從 Mastra 配置中讀取：

|選項 |說明 |
| - | - |
| `prefix` | 路由路徑前綴 |
| `openapiPath` | OpenAPI 規格端點 |
| `bodyLimitOptions` | 請求主體大小上限及自訂錯誤處理函數 |
| `streamOptions` | 串流數據遮蓋設定 |
| `customRouteAuthConfig` | 個別路由的身分驗證覆蓋規則 |
| `mcpOptions` | MCP 傳輸選項（例如透過 `setRequestAuth` 控制 `context.mcp.extra.authInfo`） |

### 不被適配器使用 {/* #not-used-by-adapters */}

以下 `server` 設定選項只供 `mastra build` 使用；直接使用 Adapter 時不會生效：

|選項 |使用者 |
| - | - |
|`port`, `host` | `mastra dev`, `mastra build` |
| `cors` | `mastra build` 會加入 CORS 中介軟件 |
| `timeout` | `mastra build` |

使用轉接器時，直接使用您的框架配置這些功能。例如，使用 Hono 或 Express 的內建 CORS 套件新增 CORS 中間件，並在呼叫框架的監聽函數時設定連接埠。

## MCP支援 {/* #mcp-support */}

如 Mastra 實例已設定 MCP Server，Server Adapter 會在 `registerRoutes()` 階段註冊 MCP（Model Context Protocol）路由。MCP 讓外部工具和服務連接 Mastra Server，並與 Agent 互動。

每個 Server 透過 Streamable HTTP 公開於 `/api/mcp/:serverId/mcp`。傳輸層預設會在請求之間保留工作階段狀態。對 Cloudflare Workers 或 Vercel Edge 等無伺服器環境，可設定 `mcpOptions: { serverless: true }`，以無狀態模式運行，不管理工作階段。

透過 `mcpOptions` 控制已驗證主體的資訊如何傳給 Tool。使用 Mastra Deployer（標準的 `mastra dev` / `mastra build` 流程）時，請在 Server 設定中指定：

```typescript
const mastra = new Mastra({
  server: {
    mcpOptions: {
      setRequestAuth: (req, requestContext) => {
        req.auth = requestContext.get('mcpAuth')
      },
    },
  },
})
```

手動建立 Server Adapter 時，直接傳入 `mcpOptions`：

```typescript
const server = new MastraServer({
  app,
  mastra,
  mcpOptions: {
    setRequestAuth: (req, requestContext) => {
      req.auth = requestContext.get('mcpAuth')
    },
  },
})
```

設定詳情及 MCP Server 的設置方式請參閱 [MCP](/docs/connections/mcp)。
