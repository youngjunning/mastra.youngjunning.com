# 中間件

Mastra 伺服器可在呼叫 API 路由處理函數前後執行自訂中間件，例如驗證身份、寫入日誌、注入個別請求的上下文，或加入 CORS 標頭。

中間件接收 [Hono](https://hono.dev) 的 `Context`（`c`）及 `next` 函數。傳回 `Response` 會提前結束請求處理。呼叫 `next()` 就會繼續執行下一個中間件或路由處理函數。

:::note

中間件處理函數採用 Hono 的簽署格式，可在 `mastra dev`、`mastra build`、[Hono 介接器](/reference/server/hono-adapter) 及建基於它的 `@mastra/next`、`@mastra/tanstack-start` 等環境執行。其他框架（Elysia、Express、Fastify、Koa、NestJS）的介接器無法執行 Hono 處理函數，若已設定中間件，啟動時會寫入警告日誌。請透過各框架本身的 API 註冊中間件。

以 `requiresAuth: false` 宣告為公開的路由一律略過用戶中間件，因此框架必須保持可用的端點（例如 Studio 登入路由）不受封鎖。

:::

```typescript
import { Mastra } from '@mastra/core'

export const mastra = new Mastra({
  server: {
    middleware: [
      {
        handler: async (c, next) => {
          // Example: Add authentication check
          const authHeader = c.req.header('Authorization')
          if (!authHeader) {
            return new Response('Unauthorized', { status: 401 })
          }

          await next()
        },
        path: '/api/*',
      },
      // Add a global request logger
      async (c, next) => {
        console.log(`${c.req.method} ${c.req.url}`)
        await next()
      },
    ],
  },
})
```

如要為個別路由加入中間件，請在呼叫 `registerApiRoute` 時傳入 `middleware` 選項：

```typescript
registerApiRoute('/my-custom-route', {
  method: 'GET',
  middleware: [
    async (c, next) => {
      console.log(`${c.req.method} ${c.req.url}`)
      await next()
    },
  ],
  handler: async c => {
    const mastra = c.get('mastra')
    return c.json({ message: 'Hello, world!' })
  },
})
```

## 常見例子 {/* #common-examples */}

### 封鎖內置路由組 {/* #block-built-in-route-groups */}

Mastra 沒有移除內置路由或設定許可清單的選項。在使用 Hono 的服務中，可直接傳回回應並略過 `next()`，令指定路由組無法存取：

```typescript title="src/mastra/index.ts"
import { Mastra } from '@mastra/core'

const notFound = async () => new Response('Not Found', { status: 404 })

export const mastra = new Mastra({
  server: {
    middleware: [
      { path: '/api/memory/*', handler: notFound },
      { path: '/api/logs/*', handler: notFound },
      { path: '/api/observability/*', handler: notFound },
    ],
  },
})
```

每個萬用字元模式會同時封鎖路由組本身及其下層路由。例如，`/api/logs/*` 會封鎖 `/api/logs` 及 `/api/logs/transports`。其他路由組仍然可用。

產生的伺服器會將 `server.apiPrefix` 傳給 Hono 介接器的 [`prefix` 建構選項](/reference/server/hono-adapter#constructor-parameters)，為內置路由加上前綴。中間件路徑按原樣註冊，必須寫明已設定的前綴。例如，設定 `apiPrefix: '/api/v2'` 時，請用 `/api/v2/memory/*`。自訂 API 路由必須位於已設定的 API 前綴以外，因此不會被這些模式封鎖。

Mastra 會略過以 `requiresAuth: false` 宣告為公開的路由，所以這種做法無法封鎖它們。使用非 Hono 伺服器介接器時，請透過框架註冊同等的中間件。

執行 `mastra dev` 期間，可以在 [OpenAPI 規格](http://localhost:4111/api/openapi.json)查看完整的內置路由清單，包括 MCP 路由。探索 API 及生產環境設定請參閱[伺服器概覽](/docs/server/overview#rest-api)。

若使用中間件驗證身份而沒有使用 `server.auth`，建議預設拒絕存取，請求通過驗證後才放行，毋須逐一列出受保護的路徑。請涵蓋整個 API 前綴，讓 REST 路由及 MCP 傳輸都受到保護。

### 使用 `RequestContext` {/* #using-requestcontext */}

伺服器執行時，可由中間件從請求擷取資料並填入 `RequestContext`。這個例子根據 Cloudflare 的 `CF-IPCountry` 標頭設定 `temperature-unit`，讓回應配合用戶所在的地區。

```typescript title="src/mastra/index.ts"
import { Mastra } from '@mastra/core'
import { RequestContext } from '@mastra/core/request-context'
import { testWeatherAgent } from './agents/test-weather-agent'

export const mastra = new Mastra({
  agents: { testWeatherAgent },
  server: {
    middleware: [
      async (context, next) => {
        const country = context.req.header('CF-IPCountry')
        const requestContext = context.get('requestContext')

        requestContext.set('temperature-unit', country === 'US' ? 'fahrenheit' : 'celsius')

        await next()
      },
    ],
  },
})
```

### 授權（用戶隔離） {/* #authorization-user-isolation */}

身份驗證用來確認用戶身份，授權則決定用戶可存取哪些內容。

若伺服器未強制限制資源範圍，也沒有其他授權政策，已驗證身份的呼叫端可以跨資源列出對話串，並存取其中的訊息及工作記憶。沒有範圍限制的清單就可能披露對話串 ID，呼叫端毋須猜測。若要按用戶或租戶隔離記憶，請設定 `mapUserToResourceId`，或在中間件設定可信的資源 ID。

共享應用程式可能有意容許跨資源存取。資源 ID 可識別用戶、租戶、項目或其他分組。請按可存取資源的人員選擇授權政策。

如要按已驗證身份的用戶限制記憶及對話串，最簡單的方法是在身份驗證設定中加入 `mapUserToResourceId` 回呼：

```typescript
import { Mastra } from '@mastra/core'

export const mastra = new Mastra({
  server: {
    auth: {
      authenticateToken: async token => {
        return verifyToken(token) // { id: 'user-123', orgId: 'org-456', ... }
      },
      mapUserToResourceId: user => user.id,
    },
  },
})
```

身份驗證成功後，系統會將已驗證身份的用戶物件傳給 `mapUserToResourceId`，並將傳回值寫入請求上下文的 `MASTRA_RESOURCE_ID_KEY`。所有伺服器介接器（Hono、Express、Next.js 等）均適用。

設定回呼後，必須傳回非空字串。如回呼拋出例外，或傳回 `null`、`undefined`、空字串、只含空白的字串或非字串值，身份驗證中間件會在執行路由前拒絕請求並傳回 500。所有須進行身份驗證的請求均適用，包括與記憶無關的路由。客戶端提供的資源 ID 無法覆蓋失敗的映射。

使用 `CompositeAuth` 時，這項要求適用於實際驗證請求的 Provider。未設定映射函數的 Provider 會沿用原有行為，即使組合內的其他 Provider 已設定映射函數。Studio 已設定的身份驗證映射函數亦須通過同樣的檢查。

沒有映射函數時，單靠身份驗證無法隔離用戶。請在中間件設定可信的資源 ID，或以其他方式強制執行授權。

資源 ID 可用 `user.id` 以外的值。以下是常見做法：

```typescript
// Per-user within an organization
mapUserToResourceId: user => `${user.orgId}:${user.id}`

// From a JWT claim
mapUserToResourceId: user => user.tenantId

// Composite key
mapUserToResourceId: user => `${user.workspaceId}:${user.projectId}:${user.id}`
```

設定資源 ID 後，伺服器會自動執行以下操作：

- **篩選對話串清單**，只傳回已設定資源範圍內的對話串。
- **檢查對話串存取權限**，如要存取其他資源的對話串，便傳回 403。
- **限制建立對話串**，新對話串必須使用已設定的資源 ID。
- **檢查訊息操作**（包括刪除），確保訊息所屬的對話串在已設定的資源範圍內。

即使客戶端傳入 `?resourceId=other-resource-id`，仍以伺服器設定的值為準。嘗試存取其他資源的對話串或訊息會收到 403。映射至同一資源 ID 的用戶共享該資源範圍。

#### 進階：在中間件設定資源 ID {/* #advanced-setting-resource-id-in-middleware */}

遇上較複雜的情況，例如要從資料庫查詢資源 ID，可直接在中間件設定 `MASTRA_RESOURCE_ID_KEY`：

```typescript
import { Mastra } from '@mastra/core'
import { MASTRA_RESOURCE_ID_KEY } from '@mastra/core/request-context'
import { getAuthenticatedUser } from '@mastra/server/auth'

export const mastra = new Mastra({
  server: {
    auth: {
      authenticateToken: async token => verifyToken(token),
    },
    middleware: [
      {
        path: '/api/*',
        handler: async (c, next) => {
          const token = c.req.header('Authorization')
          if (!token) {
            return c.json({ error: 'Unauthorized' }, 401)
          }

          const user = await getAuthenticatedUser<{ id: string }>({
            mastra: c.get('mastra'),
            token,
            request: c.req.raw,
          })
          const requestContext = c.get('requestContext')

          if (!user) {
            return c.json({ error: 'Unauthorized' }, 401)
          }

          requestContext.set(MASTRA_RESOURCE_ID_KEY, user.id)
          return next()
        },
      },
    ],
  },
})
```

`server.middleware` 會先於 Mastra 的每條路由身份驗證檢查執行。中間件如需已驗證身份的用戶，可呼叫 `getAuthenticatedUser()` 從已設定的身份驗證 Provider 取得用戶，並沿用路由原有的驗證流程。

#### 使用 `MASTRA_THREAD_ID_KEY` {/* #using-mastra_thread_id_key */}

亦可設定 `MASTRA_THREAD_ID_KEY`，覆蓋客戶端提供的對話串 ID：

```typescript
import { MASTRA_RESOURCE_ID_KEY, MASTRA_THREAD_ID_KEY } from '@mastra/core/request-context'

// Force operations to use a specific thread
requestContext.set(MASTRA_THREAD_ID_KEY, validatedThreadId)
```

這樣可將操作限於已循其他途徑驗證的指定對話串。

### CORS 支援 {/* #cors-support */}

```typescript oxfmt:false
{
  handler: async (c, next) => {
    c.header('Access-Control-Allow-Origin', '*');
    c.header(
      'Access-Control-Allow-Methods',
      'GET, POST, PUT, DELETE, OPTIONS',
    );
    c.header(
      'Access-Control-Allow-Headers',
      'Content-Type, Authorization',
    );

    if (c.req.method === 'OPTIONS') {
      return new Response(null, { status: 204 });
    }

    await next();
  },
}
```

### 請求日誌 {/* #request-logging */}

```typescript oxfmt:false
{
  handler: async (c, next) => {
    const start = Date.now();
    await next();
    const duration = Date.now() - start;
    console.log(`${c.req.method} ${c.req.url} - ${duration}ms`);
  },
}
```
