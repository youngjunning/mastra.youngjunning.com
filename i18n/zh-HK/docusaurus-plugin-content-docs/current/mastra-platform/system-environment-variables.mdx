# 系統環境變數

Mastra 平台每次部署都會注入一組環境變數，記錄程式碼所在項目和環境的識別資料、執行區域，以及各個已連接的[託管資料庫](/docs/mastra-platform/database)的憑證。

讀取方式與其他環境變數相同：

```ts
const environmentName = process.env.MASTRA_ENVIRONMENT_NAME
```

系統變數的名稱已保留。你儲存的同名變數仍會留在項目或環境記錄內，但執行時只會取得最後套用的平台變數值。

## 項目和環境變數 {/* #project-and-environment-variables */}

每次部署均會注入下列變數。

| 變數 | 值 |
| - | - |
| `MASTRA_PROJECT_ID` | 此次部署的項目 ID |
| `MASTRA_ENVIRONMENT_ID` | 環境 ID，環境改名後亦不變 |
| `MASTRA_ENVIRONMENT_NAME` | 環境名稱，例如 `production` |
| `MASTRA_ENVIRONMENT_SLUG` | 用於環境路由的 slug |
| `MASTRA_PLATFORM_REGION` | 環境所在區域，為 `US` 或 `EU` |
| `MASTRA_PLATFORM_ACCESS_TOKEN` | 此次部署呼叫平台 API 所用的權杖，包括可觀測性 API |
| `MASTRA_PLATFORM_BUCKET_NAME` | 為環境的 [Workspace](/docs/mastra-platform/workspaces) 提供儲存空間的儲存桶，啟用 Workspace 後設定 |
| `MASTRA_WORKERS` | 如項目宣告了 Worker，主服務會將此值設為 `false`，讓 Worker 只在各自的服務執行 |

## 託管資料庫變數 {/* #managed-database-variables */}

連接託管資料庫後，平台會將連線變數加入資料庫涵蓋的環境。每個供應商均使用固定的變數名稱。

| 供應商 | 變數 |
| - | - |
| Turso | `TURSO_DATABASE_URL`, `TURSO_AUTH_TOKEN` |
| Neon | `DATABASE_URL` |
| Postgres | `DATABASE_URL` |
| Redis | `REDIS_URL` |

託管 Redis 尚未向所有組織開放。如你的組織未啟用此功能，Redis 便不會出現在資料庫選項內，亦無法連接。

變數值會在部署時解析，不會儲存在項目內。如環境層級和項目層級的資料庫屬同一供應商，該環境會以環境層級資料庫的值取代項目層級的值。

## 優先次序 {/* #precedence */}

部署會按以下次序解析變數。如名稱相同，以最後套用的值為準：

1. 儲存在目標部署環境的變數。平台不會讀取其他環境的變數。仍使用[舊版部署流程](/docs/mastra-platform/deploy#migrating-from-server-and-studio-deploys)的項目會改用項目內儲存的變數。
1. 該環境的託管資料庫變數。
1. 平台變數。

系統值最後套用，因此有同名變數時以系統值為準。你儲存的值仍會保留在記錄內，並繼續顯示在控制台，但運作中的服務不會收到這些值。環境變數頁面以警告圖示標示哪些值已被覆蓋。

單獨連接至某個環境的資料庫，只會在該環境內覆蓋同一供應商的項目層級資料庫。如要讓指定環境使用另一個資料庫，請連接[環境層級資料庫](/docs/mastra-platform/database#attach-with-the-cli)，毋須手動覆寫連線變數。

要查看環境執行時使用的變數，可將它們下載至本機檔案：

```bash
mastra env vars pull staging --output .env.staging
```

檔案不會儲存託管變數的值，只會在註解中列出變數名稱。
