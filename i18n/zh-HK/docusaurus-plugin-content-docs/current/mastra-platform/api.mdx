## Feedback API {/* #feedback-api */}

Feedback API 用於列出及分析匯出到 Mastra Platform Observability 的回饋。此 API 沒有版本劃分，因此不保證向後兼容。速率限制、資料保留期限，以及從資料攝取到可查詢的延遲，均未列入公開合約。

這些端點的查詢參數、請求內容及回應類型，與 Mastra 運行時的回饋路由相同。完整規格見[回饋參考文件](/reference/observability/feedback)，包括[列表查詢參數](/reference/observability/feedback#list-query-parameters)及 [`FeedbackFilter`](/reference/observability/feedback#feedbackfilter)。

請使用環境所屬資料駐留區域的根 URL：

| 區域 | 根 URL |
| - | - |
| 美國 | `https://observability.mastra.ai/api/observability` |
| 歐盟 | `https://observability.eu.mastra.ai/api/observability` |

遙測資料留在其駐留區域。查詢另一個區域，不會返回該環境的紀錄。環境與區域的對應關係見[可觀測性同區部署](/docs/mastra-platform/regions#observability-co-location)。

### 身分驗證及項目範圍 {/* #authentication-and-project-scope */}

每個請求都需要 Platform 存取權杖。可在 [Mastra Platform](https://projects.mastra.ai) 建立，或使用設定 Platform 時寫入 `.env` 的權杖。

加入 `X-Mastra-Project-Id` 可把結果限定至一個項目。如省略，查詢會涵蓋權杖所屬機構可存取的所有項目回饋。

```bash
curl -sS "https://observability.mastra.ai/api/observability/feedback?page=0&perPage=20&feedbackType=rating" \
  -H "Authorization: Bearer $MASTRA_PLATFORM_ACCESS_TOKEN" \
  -H "X-Mastra-Project-Id: $MASTRA_PROJECT_ID" | jq
```

請使用機構範圍的 Platform 存取權杖；不接受 `mk_*` 等 Gateway 推理密鑰。即使提供項目 ID，查詢仍只限權杖所屬機構。

### 端點 {/* #endpoints */}

| 方法 | 端點 | 說明 |
| - | - | - |
| GET | `/feedback` | 列出回饋紀錄 |
| POST | `/feedback/aggregate` | 返回單一匯總值 |
| POST | `/feedback/breakdown` | 按維度將回饋分組 |
| POST | `/feedback/timeseries` | 按時間間隔將回饋分組 |
| POST | `/feedback/percentiles` | 返回百分位數序列 |

列表端點會把每個 [`FeedbackFilter`](/reference/observability/feedback#feedbackfilter) 欄位當作同名查詢參數，例如 `traceId`、`spanId`、`feedbackType`、`feedbackSource`、`environment`、`entityName`、`experimentId` 或 `tags`。如要傳入多個值，可重複參數，例如 `feedbackType=rating&feedbackType=thumbs`。

```bash
curl -sS "https://observability.mastra.ai/api/observability/feedback?traceId=trace-123&environment=production" \
  -H "Authorization: Bearer $MASTRA_PLATFORM_ACCESS_TOKEN" \
  -H "X-Mastra-Project-Id: $MASTRA_PROJECT_ID" | jq
```

| 參數 | 說明 |
| - | - |
| `page`, `perPage` | 由零開始的頁碼及每頁筆數（1 至 100）；預設為 `0` 及 `10`。 |
| `field`, `direction` | 按 `timestamp` 以 `ASC` 或 `DESC` 排序；預設為 `DESC`。 |
| `mode=delta` | 由分頁切換至增量輪詢。 |
| `after` | 上一次增量回應的游標；只適用於增量模式。 |
| `limit` | 每次增量輪詢最多取得的更新數（1 至 100）；只適用於增量模式。 |

回應包含 `feedback` 陣列，以及分頁或增量中繼資料。完整參數規格，包括以 JSON 編碼的 `timestamp` 等物件篩選條件，見回饋參考文件的[列表查詢參數](/reference/observability/feedback#list-query-parameters)。

分析端點接受與[回饋參考文件](/reference/observability/feedback)相同的 JSON 請求格式，並返回相同類型的結果。分析只處理數值回饋。

```bash
curl -sS "https://observability.mastra.ai/api/observability/feedback/aggregate" \
  -X POST \
  -H "Authorization: Bearer $MASTRA_PLATFORM_ACCESS_TOKEN" \
  -H "X-Mastra-Project-Id: $MASTRA_PROJECT_ID" \
  -H "Content-Type: application/json" \
  --data '{"feedbackType":"rating","feedbackSource":"user","aggregation":"avg"}' | jq
```

憑證無效時，API 返回 `401`；機構授權失敗時返回 `403`；查詢參數或 JSON 請求內容格式錯誤時返回 `400`。

託管的可觀測性服務沒有建立回饋的路由。請按[匯出回饋至 Mastra Platform](/docs/observability/feedback#export-feedback-to-mastra-platform)的說明，從應用程式匯出回饋。

### 身分驗證及項目範圍 {/* #authentication-and-project-scope-1 */}

每個請求都需要 Platform 存取權杖。可在 [Mastra Platform](https://projects.mastra.ai) 建立，或使用設定 Platform 時寫入 `.env` 的權杖。

加入 `X-Mastra-Project-Id` 可把結果限定至一個項目。如省略，查詢會涵蓋權杖所屬機構可存取的所有項目指標。

```bash
curl -sS "https://observability.mastra.ai/api/observability/discovery/metric-names?prefix=mastra_model_" \
  -H "Authorization: Bearer $MASTRA_PLATFORM_ACCESS_TOKEN" \
  -H "X-Mastra-Project-Id: $MASTRA_PROJECT_ID" | jq
```

請使用機構範圍的 Platform 存取權杖；不接受 `mk_*` 等 Gateway 推理密鑰。即使提供項目 ID，查詢仍只限權杖所屬機構。

### 端點 {/* #endpoints-1 */}

| 方法 | 端點 | 說明 |
| - | - | - |
| GET | `/metrics` | 列出原始指標紀錄 |
| POST | `/metrics/aggregate` | 返回單一匯總值 |
| POST | `/metrics/breakdown` | 按維度將指標分組 |
| POST | `/metrics/timeseries` | 按時間間隔將指標分組 |
| POST | `/metrics/percentiles` | 返回單一指標的百分位數序列 |
| GET | `/discovery/metric-names` | 列出指標名稱 |
| GET | `/discovery/metric-label-keys` | 列出某指標的標籤鍵 |
| GET | `/discovery/metric-label-values` | 列出某指標標籤鍵的值 |

列表及探索端點透過查詢參數接收參數。各端點接受哪些參數，見指標查詢參考文件的 [`listMetrics(args)`](/reference/observability/metrics/queries#listmetricsargs) 及[指標探索](/reference/observability/metrics/queries#metric-discovery)。

分析端點接受與[指標查詢參考文件](/reference/observability/metrics/queries#analytics-methods)相同的 JSON 請求內容，並返回相同類型的結果，包括 `name`、`aggregation`、`filters`、`groupBy`、`interval`、`percentiles`、`comparePeriod`、`limit`、`orderDirection` 及 `distinctColumn`。

```bash
curl -sS "https://observability.mastra.ai/api/observability/metrics/aggregate" \
  -X POST \
  -H "Authorization: Bearer $MASTRA_PLATFORM_ACCESS_TOKEN" \
  -H "X-Mastra-Project-Id: $MASTRA_PROJECT_ID" \
  -H "Content-Type: application/json" \
  --data '{"name":["mastra_model_total_input_tokens","mastra_model_total_output_tokens"],"aggregation":"sum","filters":{"timestamp":{"start":"2026-09-13T00:00:00Z","end":"2026-10-13T00:00:00Z"}},"comparePeriod":"previous_period"}' | jq
```

`filters.timestamp` 可省略。沒有 `start` 及 `end` 時，查詢涵蓋所有保留資料。`comparePeriod` 則必須同時提供 `start` 及 `end`；否則上一期間的欄位為 `null`。

憑證無效時，API 返回 `401`；機構授權失敗時返回 `403`；查詢參數或 JSON 請求內容格式錯誤時返回 `400`。

#### `MastraClient` {/* #mastraclient */}

`@mastra/client-js` 中的 `MastraClient` 提供分析及探索方法。把 `baseUrl` 設為區域主機網址，不要包含 `/api/observability` 路徑：

```typescript
import { MastraClient } from '@mastra/client-js'

const mastraClient = new MastraClient({
  baseUrl: 'https://observability.mastra.ai',
  headers: {
    Authorization: `Bearer ${process.env.MASTRA_PLATFORM_ACCESS_TOKEN}`,
    'X-Mastra-Project-Id': process.env.MASTRA_PROJECT_ID!,
  },
})

const result = await mastraClient.getMetricAggregate({
  name: ['mastra_model_total_input_tokens', 'mastra_model_total_output_tokens'],
  aggregation: 'sum',
})
```

#### CLI {/* #cli */}

[`mastra api metric`](/reference/cli/mastra#mastra-api-metric-aggregate) 指令預設連接美國端點。如要查詢歐盟區域，請傳入 `--url`：

```bash
mastra api --url https://observability.eu.mastra.ai metric aggregate '<json>'
```
