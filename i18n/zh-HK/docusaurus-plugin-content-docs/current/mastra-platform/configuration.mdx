# 配置

`.mastra-project.json`設定檔並解析來自平台和（可選）本地的環境變量`.env`文件。

本頁解釋了這兩種機制。

## 專案配置 {/* #project-config */}

這`.mastra-project.json` file is auto-generated on your first [`mastra deploy`](/docs/mastra-platform/deploy). It links your local project to a platform project. The [GitHub integration](/docs/mastra-platform/github) writes the same file into linked repositories.

將其提交到版本控制，以便後續部署（包括來自 CI）針對正確的項目。

您的文件將如下所示：

```json title=".mastra-project.json"
{
  "projectId": "06daaac4-89b1-40f0-9e3f-0993e039a627",
  "projectName": "my-project",
  "organizationId": "org_01KNA5YSP52SX4M6YVSXC2MAHP"
}
```

|領域 |描述 |
| - | - |
|項目編號 |項目的 UUID。建立項目時分配。 |
|項目名稱 |人類可讀的項目名稱。用作儀表板和 CLI 輸出中的顯示標籤。 |
|組織ID |擁有該專案的組織。所有部署、API 金鑰和資源都僅限於該組織。 |

## 環境變數 {/* #environment-variables */}

本機環境檔案是可選的。[`mastra deploy`](/docs/mastra-platform/deploy) resolves variables from three sources:

* **託管變數**：由平台資源注入，例如[hosted databases](/docs/mastra-platform/database). The platform defines these, and you can't edit them.
* **儲存變數**：透過儀表板保存在專案或環境中。在每次部署時按原樣使用，無需本地文件。
* **本地環境文件**：部署在頂部的第一層本機環境檔案：`--env-file` you pass, `.env.<environment>` when you deploy with `--env`, or the only `.env*` file in the project. If several exist, the CLI asks you to choose one. Variables from different local files aren't merged.

若要將部署固定到特定的環境檔案而不是依賴預設選擇，請傳遞`--env-file`:

```bash
mastra deploy --env-file .env.production --yes
```

在部署之前檢查和清理本機環境文件，以避免上傳僅開發或個人機密。

### 可觀察性 {/* #observability */}

以下環境變數配置 Mastra 平台上的 Observability 產品。

|變數|描述 |
| - | - |
|`MASTRA_PLATFORM_ACCESS_TOKEN` | Org-scoped access token. The CLI writes this during observability provisioning and uses it for platform authentication. |
| `MASTRA_PROJECT_ID` | UUID of the platform project. `MastraPlatformExporter` uses it to link observability data to the platform project. Studio and Server deploys read the project ID from `.mastra-project.json`. |
| `MASTRA_PLATFORM_OBSERVABILITY_ENDPOINT` | Optional observability endpoint override for `MastraPlatformExporter` and Studio. Set it to your region's collector, for example `https://observability.eu.mastra.ai`, when your project isn't in the default US region. Defaults to `https://observability.mastra.ai`. |
| `MASTRA_ORG_ID` | Overrides the active organization for CLI commands. You can also set it with the `--org` flag on supported commands. |

`MastraPlatformExporter`讀`MASTRA_PLATFORM_ACCESS_TOKEN` to authenticate platform export.

## 多種環境 {/* #multiple-environments */}

單一專案跨多個專案運行相同的程式碼庫[environments](/docs/mastra-platform/environments), such as `production` and `staging`. Each environment has its own URL and its own stored variables, plus its own deploy history. One `.mastra-project.json` file covers all of them:

```bash
mastra deploy --env production --yes
mastra deploy --env staging --env-file .env.staging --yes
```

:::注意
早期的平台版本需要每個環境一個專案。環境取代了這一模式，因此保留一個專案並部署到環境中。
:::
