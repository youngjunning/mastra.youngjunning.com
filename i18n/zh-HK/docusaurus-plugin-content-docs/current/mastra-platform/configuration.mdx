# 設定

部署至 Mastra Platform 時，CLI 會產生 `.mastra-project.json` 設定檔，並讀取平台提供的環境變數。你亦可選擇加入本機的 `.env` 檔案。

本頁說明項目設定檔和環境變數如何運作。

## 項目設定 {/* #project-config */}

首次執行 [`mastra deploy`](/docs/mastra-platform/deploy) 時，CLI 會自動建立 `.mastra-project.json`，把本機項目連結至平台項目。[GitHub 整合](/docs/mastra-platform/github)也會將同一個檔案寫入已連結的儲存庫。

請將設定檔提交至版本控制系統，確保之後的部署（包括經 CI 部署）都會使用正確的項目。

以下是設定檔的例子。

```json title=".mastra-project.json"
{
  "projectId": "06daaac4-89b1-40f0-9e3f-0993e039a627",
  "projectName": "my-project",
  "organizationId": "org_01KNA5YSP52SX4M6YVSXC2MAHP"
}
```

| 欄位 | 說明 |
| - | - |
| projectId | 建立項目時獲分配的 UUID。 |
| projectName | 方便閱讀的項目名稱，在儀表板及 CLI 輸出中用作顯示標籤。 |
| organizationId | 項目所屬的組織。所有部署、API 密鑰和資源都限於該組織。 |

## 環境變數 {/* #environment-variables */}

你毋須準備本機環境變數檔。[`mastra deploy`](/docs/mastra-platform/deploy) 會從以下三個來源讀取變數。

- **受管理的變數**由[託管資料庫](/docs/mastra-platform/database)等平台資源注入。這類變數由平台定義，你無法修改。
- **已儲存的變數**經儀表板儲存在項目或環境內。每次部署都直接使用這些值，毋須提供本機檔案。
- **本機環境變數檔**。部署時會在平台變數之上套用一份本機檔案，可以是 `--env-file` 指定的檔案、透過 `--env` 部署時對應的 `.env.<environment>`，或項目內唯一的 `.env*` 檔案。如有多份可用檔案，CLI 會提示你選擇。不同本機檔案的變數不會合併。

傳入 `--env-file` 即可指定部署所用的環境變數檔，毋須依賴預設選擇。

```bash
mastra deploy --env-file .env.production --yes
```

部署前請檢查並清理本機環境變數檔，以免上載僅供開發使用或屬於個人的機密資料。

### Observability {/* #observability */}

以下環境變數用於設定 Mastra Platform 的 Observability 產品。

| 變數 | 說明 |
| - | - |
| `MASTRA_PLATFORM_ACCESS_TOKEN` | 組織層級的存取權杖。CLI 會在佈建可觀測性服務時寫入此權杖，並用它向平台驗證身份。 |
| `MASTRA_PROJECT_ID` | 平台項目的 UUID。`MastraPlatformExporter` 以此將可觀測性資料連結至平台項目。部署 Studio 及 Server 時，會從 `.mastra-project.json` 讀取項目 ID。 |
| `MASTRA_PLATFORM_OBSERVABILITY_ENDPOINT` | 可選，用於覆寫 `MastraPlatformExporter` 和 Studio 使用的可觀測性端點。如項目不在預設的美國區域，請設為該區域的收集端點，例如 `https://observability.eu.mastra.ai`。預設為 `https://observability.mastra.ai`。 |
| `MASTRA_ORG_ID` | 覆寫 CLI 指令目前使用的組織。你亦可在支援的指令中加入 `--org` 來指定組織。 |

`MastraPlatformExporter` 會讀取 `MASTRA_PLATFORM_ACCESS_TOKEN`，以便在向平台匯出資料時驗證身份。

## 多個環境 {/* #multiple-environments */}

同一項目可在多個[環境](/docs/mastra-platform/environments)（例如 `production` 和 `staging`）執行同一套程式碼。各個環境都有獨立的 URL、已儲存的變數及部署記錄，並共用一份 `.mastra-project.json` 檔案。

```bash
mastra deploy --env production --yes
mastra deploy --env staging --env-file .env.staging --yes
```

:::note
舊版平台要求每個環境使用獨立項目。現在可保留一個項目，再部署至各個環境。
:::
