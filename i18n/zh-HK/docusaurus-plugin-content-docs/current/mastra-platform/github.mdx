# Mastra 平台的 GitHub 整合

GitHub 整合將 Mastra 平台專案連結到 GitHub 儲存庫。當您將變更推送到儲存庫時，Studio 和 Server 將自動部署。

:::note
此整合僅適用於 GitHub.com 上託管的儲存庫。目前不支援自架 GitHub Enterprise 實例。
:::

連結儲存庫後，平台：

- 每次推送至已設定的分支時，建構並部署 Studio 和 Server。
- 為從範本建立的項目配置託管資料庫及 Gateway API 金鑰。
- 顯示每次部署涉及的提交、分支及 Pull Request 資料。
- 透過 GitHub 檢查回報建構狀態，並在項目控制台顯示即時狀態標記及內嵌日誌。

## 何時使用 GitHub 整合 {/* #when-to-use-the-github-integration */}

當您需要以下任一功能時，請選擇 GitHub 整合：

- 推送至 `main` 或任何其他分支時部署，亦可為 Studio 和 Server 使用不同分支。
- 由平台根據 Mastra 範本建立項目，包括新的儲存庫、託管資料庫及 Gateway API 金鑰。
- 在平台控制台查看 Pull Request 及提交資料，方便排查問題。

如需臨時部署或使用 GitHub 以外的 CI 服務，仍可使用 CLI（`mastra studio deploy` 及 `mastra server deploy`）。只用 CLI 的流程請參閱 [Studio](/docs/mastra-platform/studio) 及 [Server](/docs/mastra-platform/server)。

## 安裝 Mastra GitHub 應用程式 {/* #install-the-mastra-github-app */}

此整合由 Mastra GitHub 應用程式提供支援。

應用程式會讀取儲存庫內容，監聽已設定分支的 `push` 事件，並透過 GitHub 檢查回報部署狀態。

<Steps>
  <StepItem>
    在 [Mastra 平台控制台](https://projects.mastra.ai) 開啟組織設定，找到 **GitHub App** 部分。
  </StepItem>

  <StepItem>
    選擇 **Install GitHub App**，再選擇要安裝至哪個 GitHub 帳戶或組織。

    若你並非 GitHub 組織的擁有者，GitHub 會建立有待管理員批准的**安裝申請**。控制台會一併追蹤待批申請及已完成的安裝。
  </StepItem>

  <StepItem>
    選擇應用程式可以存取的儲存庫。您可以限制特定儲存庫或授予帳戶上所有儲存庫的存取權限。

    您可以隨時從 GitHub 的應用程式設定撤銷或變更儲存庫存取權限。
  </StepItem>
</Steps>

:::note
若 GitHub 其後更新應用程式所需的權限，控制台會顯示**權限已過時**的警告及批准連結。管理員重新批准前，儲存庫操作會回傳 `403`。
:::

### 待處理的安裝請求 {/* #pending-installation-requests */}

當非管理員在組織上請求應用程式時，該請求將保持待處理狀態，直到組織管理員在 GitHub.com 上批准為止。儀表板：

- 在活動安裝旁邊列出待處理的請求。
- 允許同一使用者同時要求存取多個 GitHub 帳戶。
- 當您開啟頁面時，根據 GitHub 協調待處理狀態，刪除管理員已拒絕的請求或請求者已撤回的請求。

如要取消待批申請，請在控制台選擇該申請旁的 **Cancel**。

## 從範本建立項目 {/* #create-a-project-from-a-template */}

模板是最快的入門方式。該平台從 Mastra 模板創建一個新的儲存庫，並將其連結到一個新專案。然後，它提供模板聲明的任何託管資料庫並運行第一次部署。

<Steps>
  <StepItem>
    在控制台選擇 **Create project**，再選擇 **Start from a template**。
  </StepItem>

  <StepItem>
    選擇一個範本並選擇擁有新儲存庫的 GitHub 帳戶。為儲存庫命名並選擇它是否應該是私有的。
  </StepItem>

  <StepItem>
    配置範本的託管資料庫要求。範本可以聲明所需的資料庫（例如 Turso 或 Neon），您可以根據要求選擇提供者和區域。
  </StepItem>

  <StepItem>
    加入範本需要的環境變數，例如 AI Provider 的 API 金鑰。平台會自動設定 `MASTRA_GATEWAY_API_KEY` 及 `MASTRA_PLATFORM_ACCESS_TOKEN`，讓範本中調用 Gateway 的程式碼在首次部署便可運行。
  </StepItem>

  <StepItem>
    選擇 **Create project**。平台會建立包含 `.mastra-project.json` 設定檔的儲存庫、配置託管資料庫，再觸發 Studio 和 Server 的首次部署。
  </StepItem>
</Steps>

首次部署會等託管資料庫配置完成才開始，所以範本首次建構時便可取得用於連接資料庫的環境變數。

## 連結現有儲存庫 {/* #link-an-existing-repository */}

當您在 GitHub 儲存庫中已有 Mastra 專案時，請使用此流程。

<Steps>
  <StepItem>
    在控制台選擇 **Create project**，再選擇 **Connect an existing repository**。亦可開啟現有項目，在項目設定選擇 **Link repository**。
  </StepItem>

  <StepItem>
    選擇一個安裝，然後選擇儲存庫。儲存庫搜尋適用於應用程式在該安裝上有權存取的每個儲存庫。
  </StepItem>

  <StepItem>
    選擇 Studio 和 Server 的部署分支。兩個目標預設均使用儲存庫的預設分支，亦可分別使用不同分支。

    你可在項目停用 Studio 或 Server。若兩個目標均已設定，手動部署面板 **Deploy from GitHub** 預設會同時選取兩者。
  </StepItem>

  <StepItem>
    選擇 **Link repository**。平台會檢查儲存庫是否已有指向其他項目的 `.mastra-project.json` 檔案。如有，控制台會顯示警告，並提供 **Overwrite** 選項，讓你在連結時取代該檔案。
  </StepItem>
</Steps>

連結後，下一次推送到配置的分支會觸發部署。

### `.mastra-project.json`衝突 {/* #mastra-projectjson-conflicts */}

平台會在每個已連結的儲存庫寫入 `.mastra-project.json` 檔案，以識別項目。如果儲存庫已有此檔案，控制台會在提交連結前檢查內容：

- **遺失的**：平台在連結上建立文件。
- **匹配**：該文件已指向您正在連結的項目，因此無需進行任何更改。
- **衝突**

檔案結構請參閱[設定](/docs/mastra-platform/configuration)。

## 透過推送觸發部署 {/* #push-to-deploy */}

連結儲存庫後，每次推送到配置的分支都會觸發部署：

- 推送至 **Studio 分支**會觸發 Studio 部署。
- 推送至 **Server 分支**會觸發 Server 部署。
- 如果兩個目標共用一個分支，則一次推送會觸發兩個目標並行部署。

每個部署都帶有提交 SHA、分支和（如果可用）引入提交的拉取請求編號。建置在平台內運行，並在提交上運行檢查時將狀態報告回 GitHub。

每個部署目標同一時間只執行一次建構。如建構期間收到新推送，平台會取消同一目標仍在輪候的舊建構，執行最新的建構。Studio 和 Server 的建構會分別追蹤，兩者均已設定時可並行執行。

### 手動 GitHub 部署 {/* #manual-github-deploys */}

毋須推送也可在控制台觸發部署。開啟項目並選擇 **Deploy from GitHub**，選定部署目標（Studio、Server 或兩者）及分支後提交。平台會部署該分支的最新提交，並記錄為 **GitHub Workflow** 部署。

## 追蹤部署 {/* #track-deploys */}

從範本建立項目或連結儲存庫後，**Setup** 頁面會為每個部署目標顯示一行。每行均會：

- 顯示即時狀態徽章，輪詢部署至完成。
- 透過部署 ID 連結到部署詳細資訊頁面。
- 提供 **Show logs** 開關，在頁面內以串流顯示建構及執行日誌。部署期間，每三秒輪詢一次 Server 日誌。

## 權限和撤銷 {/* #permissions-and-revocation */}

若要停止從儲存庫部署，請執行下列其中一項操作：

- 在 **Project settings → Repository** 解除項目與儲存庫的連結。項目會保留歷史記錄，日後可連結其他儲存庫。
- 在 GitHub.com 撤銷 Mastra GitHub App 存取儲存庫的權限。現有部署會繼續運行，之後的推送不會再觸發部署。
- **卸載 GitHub 應用程式**來自 GitHub 帳戶。這將刪除對該帳戶上每個儲存庫的存取權限。

若 GitHub 撤銷或輪換應用程式的安裝權杖，讀取儲存庫時會回傳 `github_app_permissions_outdated` 錯誤，控制台會提示管理員重新批准權限。
