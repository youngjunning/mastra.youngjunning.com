# 地區

區域控制平台環境的運作位置、平台環境的位置[hosted database](/docs/mastra-platform/database)放置，以及其Observability資料的儲存位置。該區域在創建環境時是固定的，以後無法更改。

Mastra 平台目前提供兩個居住區，`us` and `eu`，由 Railway 上的特定計算區域支援。資料庫和可觀察性自動遵循環境區域。

## 選擇地區 {/* #choose-a-region */}

經過`--region` when creating or first deploying to an environment:

```bash
mastra deploy --env production --region eu
mastra env create staging --region us
```

兩個都`mastra deploy --region` and `mastra env create --region` accept either the `us` / `eu`下表中的簡寫或規範鐵路區域代碼。推薦的形式是簡寫形式。

不傳遞region時預設為`us`, which resolves to `pdx` (Portland, Oregon).

## 可用地區 {/* #available-regions */}

居住選擇器提供跨越兩個區域的四個鐵路區域。`us` and `eu` shorthand resolve to the underlined default in each zone.

|專區 |鐵路代碼|地點 |
| - | - | - |
|`us` | `pdx` (default) | Portland, Oregon |
| `us` | `iad` | Ashburn, Virginia |
| `us` | `sfo` | San Francisco, California |
| `eu` | `ams`（預設）|荷蘭阿姆斯特丹 |

當您需要將環境固定到特定資料中心時，請直接傳遞 Railway 代碼。透過`us` selects `pdx`, and passing `eu` selects `ams`.

:::注意
部署管道中存在其他鐵路區域（例如新加坡、`sin`) but aren't offered in the residency selector yet, because hosted databases and observability don't have local placement outside the US and EU. Passing an unrecognized region falls back to the US default rather than pinning to it.
:::

## 託管資料庫放置 {/* #hosted-database-placement */}

當您附加一個[environment-scoped database](/docs/mastra-platform/database), the platform picks the provider region closest to the environment. This is server-authoritative, so an explicit `--region` on `mastra env db create <env>` is ignored. The environment's region is the source of truth.

|環境區域 |圖爾索地區 | Postgres（Neon）區域 |
| - | - | - |
|`pdx` | `sjc` (San Jose) | `aws-us-west-2` (Oregon) |
| `iad` | `iad` (Ashburn) | `aws-us-east-1` (N. Virginia) |
| `sfo` | `sjc` (San Jose) | `aws-us-west-2` (Oregon) |
| `ams` | `ams`（阿姆斯特丹）|`aws-eu-central-1`（法蘭克福）|

專案範圍的資料庫（跨環境共享）接受明確的`--region` because they aren't bound to a single environment. Use a provider region ID for the flag, not the `us` / `eu` shorthand:

```bash
mastra env db create --kind turso --region fra
mastra env db create --kind neon --region aws-us-east-1
```

Turso 提供 20 多個區域，Postgres (Neon) 可在美國、歐盟和亞太地區的 AWS 和 Azure 區域使用。請參閱[Turso regions list](https://docs.turso.tech/features/data-edge#locations) and [Neon regions list](https://neon.com/docs/introduction/regions) for the full set. Passing a code not offered by the provider fails at attach time with the provider's error.

## Observability共置 {/* #observability-co-location */}

Observability攝取目前在兩個區域運行：**US** (Iowa, `us-central1`) and **EU** (Amsterdam). Every environment's traces, logs, and metrics are routed to the ingest region that matches its residency zone:

|環境區域 |可觀測區域 |
| - | - |
|`pdx`, `iad`, `sfo`, `us` shorthand | US (Iowa) |
| `ams`, `eu` shorthand | EU (Amsterdam) |

鐵路和資料庫提供者提供的區域多於Observability攝取的區域，因此某些組合無法完全共置。環境在`us` zone always send telemetry to US ingest, while those in the `eu` zone use EU ingest. This routing applies even when the underlying Railway region is a city without a dedicated ingest endpoint. Data residency is preserved at the zone level. Telemetry from an `eu` environment never crosses into the US.
