# 區域

區域決定平台環境在哪裏運行、[託管資料庫](/docs/mastra-platform/database)設在哪裏，以及可觀測性資料在哪裏儲存。區域在建立環境時確定，其後無法更改。

Mastra Platform 目前設有 `us` 及 `eu` 兩個資料存放範圍，由 Railway 的指定運算區域提供支援。資料庫及可觀測性服務會自動按環境的區域配置。

## 選擇區域 {/* #choose-a-region */}

建立環境或首次部署至該環境時，請指定 `--region`。

```bash
mastra deploy --env production --region eu
mastra env create staging --region us
```

`mastra deploy --region` 及 `mastra env create --region` 均接受 `us` / `eu` 簡寫，亦可使用下表的正式 Railway 區域代碼。建議採用簡寫。

如沒有指定區域，預設使用 `us`，即俄勒岡州波特蘭的 `pdx`。

## 可用區域 {/* #available-regions */}

資料存放地選擇器在兩個地理範圍內提供四個 Railway 區域。`us` 及 `eu` 簡寫會各自選取所屬範圍的預設區域。

| 地理範圍 | Railway 代碼 | 位置 |
| - | - | - |
| `us` | `pdx`（預設） | 俄勒岡州波特蘭 |
| `us` | `iad` | 維珍尼亞州阿什本 |
| `us` | `sfo` | 加州三藩市 |
| `eu` | `ams`（預設） | 荷蘭阿姆斯特丹 |

如要將環境固定在指定資料中心，請直接傳入 Railway 區域代碼。傳入 `us` 會選取 `pdx`，傳入 `eu` 則會選取 `ams`。

:::note
部署流水線另有其他 Railway 區域，例如新加坡（`sin`）。由於託管資料庫和可觀測性服務未能在美國及歐盟以外就近部署，選擇器暫未提供這些區域。如傳入未能識別的區域，平台會改用美國的預設區域。
:::

## 託管資料庫的位置 {/* #hosted-database-placement */}

連結[環境層級的資料庫](/docs/mastra-platform/database)時，平台會選用供應商最接近該環境的區域。位置由伺服器按環境區域決定，因此 `mastra env db create <env>` 即使有指定 `--region`，該參數亦會被忽略。

| 環境區域 | Turso 區域 | Postgres（Neon）區域 |
| - | - | - |
| `pdx` | `sjc`（聖荷西） | `aws-us-west-2`（俄勒岡州） |
| `iad` | `iad`（阿什本） | `aws-us-east-1`（維珍尼亞州北部） |
| `sfo` | `sjc`（聖荷西） | `aws-us-west-2`（俄勒岡州） |
| `ams` | `ams`（阿姆斯特丹） | `aws-eu-central-1`（法蘭克福） |

項目層級的資料庫由多個環境共用，並無綁定單一環境，因此可指定 `--region`。請為此參數提供供應商的區域 ID，避免使用 `us` / `eu` 簡寫。

```bash
mastra env db create --kind turso --region fra
mastra env db create --kind neon --region aws-us-east-1
```

Turso 提供超過 20 個區域，Postgres（Neon）則涵蓋 AWS 及 Azure 在美國、歐盟及亞太的多個區域。完整名單見 [Turso 區域列表](https://docs.turso.tech/features/data-edge#locations)及 [Neon 區域列表](https://neon.com/docs/introduction/regions)。如傳入供應商不支援的代碼，連結資料庫時會失敗，並回傳供應商的錯誤訊息。

## 可觀測性資料的區域路由 {/* #observability-co-location */}

可觀測性資料目前在兩個區域收集，分別是**美國**（艾奧瓦州，`us-central1`）及**歐盟**（阿姆斯特丹）。各環境的 Trace、日誌和指標都會送往其資料存放範圍所對應的收集區域。

| 環境區域 | 可觀測性資料收集區域 |
| - | - |
| `pdx`、`iad`、`sfo`、簡寫 `us` | 美國（艾奧瓦州） |
| `ams`、簡寫 `eu` | 歐盟（阿姆斯特丹） |

Railway 和資料庫供應商的區域比可觀測性資料收集區域多，因此部分組合無法設於同一地點。`us` 範圍內的環境一律將遙測資料送往美國收集端，`eu` 範圍內的環境則會送往歐盟。即使 Railway 區域所在的城市沒有專用收集端點，仍會按此規則傳送。資料仍留在所屬的地理範圍內，`eu` 環境的遙測資料不會傳至美國。
