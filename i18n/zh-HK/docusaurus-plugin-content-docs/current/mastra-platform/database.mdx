# 託管資料庫

你可在 CLI 或[平台](/docs/mastra-platform/overview)的專案設定佈建全託管資料庫，再將它連接到專案。Mastra 會透過你選用的供應商建立資料庫，妥善儲存憑證，並在資料庫就緒後將連線資料注入執行期間的環境變數。你無須複製或設定連線字串。

```bash
mastra env db create --kind turso
```

## 何時需要託管資料庫 {/* #when-to-use-hosted-databases */}

如專案需要由平台管理的持久儲存，可使用託管資料庫，例如：

- **Agent 記憶**：長期保留對話記錄及工作記憶，並可跨工作階段進行語義檢索。
- **應用程式資料**：儲存及讀取專案執行期間所需的關聯式或結構化資料。
- **向量搜尋**：儲存嵌入向量，供檢索增強生成及語義搜尋使用。

## 資料庫供應商 {/* #providers */}

託管資料庫目前有 Turso、Neon 及 Postgres 三個供應商，MongoDB 即將推出。連接資料庫時先選擇供應商，再於程式碼中把注入的變數接到相應的 Mastra 儲存配接器。

每個供應商都會注入一組固定名稱的變數。例如，Neon 和 Postgres 均只注入 `DATABASE_URL`，Turso 則使用另外的 `TURSO_*` 變數。變數名稱在同一環境內不得重複，所以每個名稱最多只能用於一個資料庫。由於 Neon 和 Postgres 都會注入 `DATABASE_URL`，同一環境只可選用其中之一；Turso 則可與其中任何一款一同使用。

對大部分以 Agent 為主的專案，**Turso** 是最容易入手的選擇。它提供兼容 SQLite 的輕量引擎，適合儲存 Agent 記憶和對話記錄，亦可按租戶隔離資料。如需要可從手提電腦、其他服務或遷移工具連線的公開無伺服器 Postgres，請選 **Neon**。如工作負載必須留在部署的私有網絡內，請選 **Postgres**：它與你的伺服器一同運作，而且只可由該伺服器連線。**MongoDB**（_即將推出_）將提供文件儲存及內置向量搜尋，適合難以用 SQL 表達的工作負載。

| 供應商 | 引擎 | 網絡 | 適用情況 |
| - | - | - | - |
| **Turso** | LibSQL，兼容 SQLite | 公開 | Agent 記憶、按租戶隔離 |
| **Neon** | 支援分支的無伺服器 Postgres | 公開 | 需要從部署環境外部存取的關聯式工作負載 |
| **Postgres** | 託管 PostgreSQL | VPC（私有） | 必須留在部署環境私有網絡內的關聯式工作負載 |
| **MongoDB** | 文件及向量搜尋 | _有待確定_ | 文件儲存、向量搜尋（_即將推出_） |

## 資料庫適用範圍 {/* #database-scope */}

連接資料庫時，可選擇以下其中一種範圍：

- **環境範圍**：預設選項。資料庫只連接至一個環境，讓各環境的資料互相隔離，例如為正式及預備環境各設一個資料庫。專案只有一個環境時，`mastra env db create` 會自動選用；如有多個環境，CLI 會提示你選擇。
- **專案範圍**：由專案下所有[環境](/docs/mastra-platform/environments)共用一個資料庫。加上 `--shared` 即可啟用；其變數會在每次部署時注入。

適用範圍會在連接資料庫時設定，並顯示於 `mastra env db list`。

同一供應商的適用範圍不可重疊。專案範圍的資料庫已將變數注入所有環境，再連接同一供應商的環境範圍資料庫便會因變數名稱衝突而被拒絕。如要由共用資料庫改為每個環境各用一個，須先刪除專案範圍的資料庫，再為各個環境連接資料庫。刪除操作會銷毀供應商端的資料庫及當中所有資料，因此切換前請先匯出需要保留的資料。不同環境各自的資料庫不會衝突，每次部署只會收到本身環境的變數。

## 用 CLI 連接資料庫 {/* #attach-with-the-cli */}

無須預先執行此指令。如專案需要託管資料庫但尚未連接，`mastra deploy` 會在部署前檢查時提示你連接資料庫。確認後可留在 CLI 繼續部署。如你的組織同時可使用 Neon 和 Postgres，而缺少的是 `DATABASE_URL`，提示會讓你選擇要佈建哪一款。

你亦可預先建立及連接資料庫。CLI 會輪詢資料庫的狀態直至就緒，需時數秒：

```bash
# Scoped to a single environment (the CLI picks the only one, or prompts if there are several)
mastra env db create --kind turso

# Scoped to a specific environment
mastra env db create staging --kind turso

# Shared by all environments
mastra env db create --kind turso --shared
```

支援的類型有 `turso`、`neon`（公開的無伺服器 Postgres）及 `postgres`（由 VPC 隔離的 Postgres）。可用的實用選項如下：

- `--shared`：連接所有環境共用的專案範圍資料庫。不可同時指定環境引數。
- `--name <name>`：資料庫名稱，預設按專案的 slug 產生。
- `--region <region>`：專案範圍資料庫在供應商端的區域 ID，例如 `fra`。環境範圍的資料庫會自動設於環境所在區域附近，明確指定的 `--region` 不會生效。
- `--no-wait`：即時傳回，毋須輪詢。其後可用 `mastra env db show` 查閱進度。
- `--json`：輸出機器可讀的結果。若專案有多個環境，使用 `--json` 時必須指定環境引數或 `--shared`，系統不會顯示互動提示。

查閱及管理已連接的資料庫：

```bash
mastra env db list
mastra env db show <database>
mastra env db delete <database>
```

`mastra env db list` 會顯示每個資料庫的類型、狀態、範圍及注入的變數名稱。`mastra env db show` 會列出連線指引，並隱藏機密值。加上 `--show-secrets` 即可顯示這些值。`mastra env db delete` 會永久刪除供應商端的資料庫及所有資料。建立和刪除資料庫均須具備所屬組織的管理員角色。

## 在專案設定連接資料庫 {/* #attach-from-project-settings */}

<Steps>
  <StepItem>
    在[平台](/docs/mastra-platform/overview)開啟專案，然後前往 **Project Settings**。
  </StepItem>

  <StepItem>
    開啟 **Database** 部分，再選取 **Add database**。
  </StepItem>

  <StepItem>
    選取**供應商**（Turso、Neon 或 Postgres）。連接前仍可更改選擇。
  </StepItem>

  <StepItem>
    設定資料庫：

    - **Name**：資料庫在專案內的標籤。
    - **Region**：託管資料庫的區域。請選擇最接近用戶的區域。Turso 預設為 `sjc`（聖何塞），在全球提供 20 多個地點。Neon 預設為 `aws-us-west-2`，可使用美國、歐盟及亞太地區的 AWS 和 Azure 區域。Postgres 會在部署所用的同一個私有網絡運作，並沿用環境的 Railway 區域（美國、歐盟或亞太地區）。
  </StepItem>

  <StepItem>
    選取 **Attach database**。系統會在背景佈建，資料庫的初始狀態為 `provisioning`，待供應商完成設定後便會變為 `ready`。連線資料會自動注入專案，成為伺服器執行期間的環境變數。
  </StepItem>
</Steps>

透過專案設定連接的資料庫適用於整個專案。如要連接只適用於單一環境的資料庫，請使用 [CLI](#attach-with-the-cli)。

## 在程式碼中連接資料庫 {/* #connect-from-your-code */}

前往 **Project Settings → Database** 查看資料庫狀態。背景設定仍在進行時，已連接的資料庫會顯示 `provisioning`。狀態變為 `ready` 時，平台已將連線資料注入受管理的環境變數。

開啟狀態為 `ready` 的資料庫，便可查看相關變數和程式碼片段。可按下例用這些變數設定 Mastra 儲存配接器。

### 圖爾索 (LibSQL) {/* #turso-libsql */}

Turso 提供兩個環境變數：`TURSO_DATABASE_URL` 及 `TURSO_AUTH_TOKEN`。以下例子使用這些變數透過 [LibSQLStore](/integrations/databases/libsql) 連線。

```ts title="src/mastra/storage.ts" caption="Connect a Turso (LibSQL) database"
import { LibSQLStore } from '@mastra/libsql'

export const storage = new LibSQLStore({
  id: 'mastra-storage',
  url: process.env.TURSO_DATABASE_URL!,
  authToken: process.env.TURSO_AUTH_TOKEN!,
})
```

安裝配接器：

```bash npm2yarn
npm install @mastra/libsql@latest
```

### Neon 和 Postgres {/* #neon-and-postgres */}

Neon（公開的無伺服器資料庫）和 Postgres（由 VPC 隔離）均只提供一個 `DATABASE_URL` 連線字串，因此可以使用相同的 [PostgresStore](/integrations/databases/postgresql) 程式碼。每個環境只可用其中一款。

```ts title="src/mastra/storage.ts" caption="Connect a Neon or Postgres database"
import { PostgresStore } from '@mastra/pg'

export const storage = new PostgresStore({
  connectionString: process.env.DATABASE_URL!,
})
```

安裝配接器：

```bash npm2yarn
npm install @mastra/pg@latest
```

只有已部署的伺服器可以連接由 VPC 隔離的 Postgres，本機開發時無法直接連線。開發時可將 `DATABASE_URL` 指向本機的 Postgres 或 Neon 分支，部署時再由平台注入受管理的值。

將 `storage` 實例傳入 `Mastra` 設定，供 Agent、Memory 及 Workflow 使用：

```ts title="src/mastra/index.ts"
import { Mastra } from '@mastra/core'
import { storage } from './storage'

export const mastra = new Mastra({
  storage,
})
```

## 環境變數 {/* #environment-variables */}

每個供應商都會注入一組固定的受管理環境變數。資料庫狀態為 `ready` 時，專案可在執行期間使用這些變數，無須自行定義。

| 提供商 | 变量 |
| - | - |
|圖爾索 |`TURSO_DATABASE_URL`, `TURSO_AUTH_TOKEN` |
| Neon | `DATABASE_URL` |
| Postgres | `DATABASE_URL` |

:::警告
請將連線憑證視為機密。驗證權杖（`TURSO_AUTH_TOKEN`）和 Postgres 連線字串（`DATABASE_URL`）均可取得完整的資料存取權限。平台預設會隱藏這些值，只有在要求查看時才會顯示。
:::

## 管理資料庫 {/* #manage-a-database */}

- **查閱連線資料**：在專案設定內開啟狀態為 `ready` 的資料庫，便可看到環境變數及可直接複製貼上的程式碼片段。
- **刪除**：從專案移除資料庫時，供應商端的資料庫亦會被刪除，已注入的環境變數也會清除。操作無法復原，請確認已不再需要相關資料。
