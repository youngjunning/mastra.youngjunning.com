# 工作空間

Mastra 平台在部署時會為 Agent 配置一組運行資源，稱為 Workspace。每個環境各自使用一個 Workspace，使 `production` 和 `staging` 保持隔離。

每個 Workspace 均提供兩種資源：

- 一個供檔案系統使用的**儲存桶**，由 [`PlatformFilesystem`](/reference/workspace/platform-filesystem) 封裝。儲存桶持久保存所屬環境的資料，供 Agent 在多次運行之間讀寫。
- 一個供執行指令的**按需沙箱池**，由 [`PlatformSandbox`](/reference/workspace/platform-sandbox) 封裝。每個 `PlatformSandbox` 實例會在 `start()` 時配置自己的遠端沙箱，在 `destroy()` 時銷毀。Agent 通常在同一會話內為不同工作啟動多個沙箱，用完便釋放。

每個 Workspace 只供一個[環境](/docs/mastra-platform/environments) 使用，`production` 和 `staging` 不會共用儲存桶或沙箱池。平台負責配置資源、驗證身分及清理閒置資源。

## 何時配置 Workspace {/* #when-workspaces-are-provisioned */}

新項目預設啟用 Workspace。建立環境時，平台會自動配置儲存桶，並在背景預熱沙箱基礎映像，讓首次呼叫 `PlatformSandbox` 時能快速啟動。

現有項目如未啟用，可在 Workspaces 分頁選擇 **Enable workspaces**。啟用後，每個環境都會獲配置儲存桶。

若環境的資源配置失敗，例如沙箱供應商負載過高，Workspaces 分頁會顯示錯誤並讓你重試。環境仍會建立，只有 Workspace 在重試前無法使用。

## 在程式碼中使用 Workspace {/* #use-the-workspace-from-your-code */}

安裝 Provider 套件：

```bash npm2yarn
npm install @mastra/platform-workspace
```

將各 Provider 組成一個 Workspace，再註冊到 Mastra：

```typescript title="src/mastra/workspace.ts"
import { Workspace } from '@mastra/core/workspace'
import { PlatformFilesystem, PlatformSandbox } from '@mastra/platform-workspace'

export const workspace = new Workspace({
  filesystem: new PlatformFilesystem(),
  sandbox: new PlatformSandbox(),
})
```

```typescript title="src/mastra/index.ts"
import { Mastra } from '@mastra/core'
import { workspace } from './workspace'

export const mastra = new Mastra({
  workspace,
})
```

`PlatformFilesystem` 和 `PlatformSandbox` 從環境變數取得設定，在平台上毋須傳入選項。平台會在部署時注入變數。詳見[環境變數](#environment-variables)。

## 一個儲存桶，多個沙箱 {/* #one-bucket-many-sandboxes */}

設計 Agent 時，要留意 `PlatformFilesystem` 和 `PlatformSandbox` 的生命週期有別。

**`PlatformFilesystem` 提供長期存取環境儲存桶的介面。** 使用它的請求及 Agent 都會讀寫同一個物件儲存空間。除非你明確刪除資料，否則 Agent 寫入的內容下次請求時仍然可見。

**`PlatformSandbox` 是配置臨時沙箱的客戶端。** 每個 `PlatformSandbox` 實例各自管理一個遠端沙箱：

- `start()` 會配置新沙箱；如已傳入 `sandboxId`，便會重新連接原有沙箱。
- `executeCommand()` 在沙箱內執行指令。
- `stop()` 會釋放目前程序的租約，遠端沙箱不受影響。虛擬機按環境的閒置政策繼續運行，稍後呼叫 `start()` 時可傳入已儲存的 `sandboxId` 重新連接。若只沿用相同的 `id`，平台會配置新沙箱；如該 `id` 有復原檢查點，新沙箱會以它作為初始狀態。
- `destroy()` 會釋放虛擬機。在 Railway 上，亦會刪除與呼叫方提供的復原 `id` 關聯的檢查點。在 E2B 上只會終止虛擬機，你建立的快照仍由你管理。

採用同一靜態設定的請求和 Agent 會共用一個 `PlatformSandbox`，不會按請求或記憶執行緒另建沙箱。`PlatformFilesystem` 是獨立的 Provider，即使同時設定兩者，環境的儲存桶也不會掛載到沙箱內。

如 Agent 需要另一個隔離環境，例如為每項工作分配沙箱、為每個用戶劃分租戶，或避免背景工作影響共用的 shell 狀態，請另建一個 `PlatformSandbox`：

```typescript title="src/mastra/tools/run-in-fresh-sandbox.ts"
import { PlatformSandbox } from '@mastra/platform-workspace'

export async function runInFreshSandbox(command: string) {
  const sandbox = new PlatformSandbox()
  await sandbox.start()
  try {
    return await sandbox.executeCommand(command)
  } finally {
    await sandbox.destroy()
  }
}
```

也可將已設定的沙箱作為範本，複製出一批沙箱。副本會沿用憑證、環境、網絡隔離和預設值，毋須重複設定：

```typescript
const template = new PlatformSandbox({ networkIsolation: 'PRIVATE' })

const perProjectSandbox = template.clone({ id: `project-${projectId}` })
await perProjectSandbox.start()
```

有關完整生命週期、檢查點復原、重新連接及複製選項，請參閱 [`PlatformSandbox` 參考文件](/reference/workspace/platform-sandbox)。

## 環境變數 {/* #environment-variables */}

部署至設有 Workspace 的平台環境時，平台會自動提供以下變數：

| 變數 | 用途 |
| - | - |
| `MASTRA_PLATFORM_ACCESS_TOKEN` | 平台簽發的 JSON Web Token (JWT)，供 Workspace Provider 驗證身分，僅適用於部署所屬的組織和項目。 |
| `MASTRA_PROJECT_ID` | 部署所屬的項目。 |
| `MASTRA_ENVIRONMENT_ID` | 部署所屬的環境，用來選擇平台使用的沙箱池。 |
| `MASTRA_PLATFORM_BUCKET_NAME` | 環境關聯的儲存桶名稱，指定 `PlatformFilesystem` 讀寫哪個儲存桶。 |

以上變數名稱由平台保留。如項目明確設定同名變數，平台管理的值會優先使用。

## 本機開發 {/* #local-development */}

在本機的 `.env` 檔案加入這四個變數，即可沿用相同的 Provider。你可在項目的 **Workspaces** 分頁取得項目、環境及儲存桶的值。要設定 `MASTRA_PLATFORM_ACCESS_TOKEN`，請在組織設定的 **API Tokens** 建立 `sk_` API 權杖。平台部署則使用注入的 JWT。

```bash title=".env"
MASTRA_PLATFORM_ACCESS_TOKEN=sk_your-api-token
MASTRA_PROJECT_ID=your-project-id
MASTRA_ENVIRONMENT_ID=your-environment-id
MASTRA_PLATFORM_BUCKET_NAME=your-bucket-name
```

`PlatformFilesystem` 和 `PlatformSandbox` 在本機和平台的行為相同，兩者均連到該環境的同一儲存桶及沙箱池。如要隔離正式環境的資料，本機運行時請使用 `staging` 或 `preview` 環境的變數。

如要完全離線開發而不連接平台，可在本機建置中改用 [`LocalFilesystem`](/reference/workspace/local-filesystem) 及 [`LocalSandbox`](/reference/workspace/local-sandbox)。

## 查看 Workspace {/* #inspect-the-workspace */}

平台項目的 Workspaces 分頁按環境顯示：

- 儲存桶的狀態及內容，並可上載、下載或刪除。
- 近期的沙箱會話，以及各自的指令、結束代碼及運行時間。
- 資源配置失敗的記錄，可選擇 **Retry** 重試。
