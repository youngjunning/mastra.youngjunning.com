# Connect

:::beta 公开测试

Mastra Connect 在測試階段可於 Mastra 平台免費使用。

:::

Connect 管理 [Mastra 平台](/docs/mastra-platform/overview)項目與 GitHub、Slack、Linear 等服務之間的連線。`@mastra/connect` 套件讓應用程式透過三種方式使用這些連線：

- **工具** 讓 Agent 呼叫服務供應商的 API。Connect 提供現成工具，並透過平台代理傳送工具請求。代理會加入憑證及更新 OAuth 權杖。
- **頻道** 讓用戶經 Slack、Telegram、Discord 或 Microsoft Teams 與 Agent 對話。Connect 向 Mastra 的[頻道](/docs/channels) Provider 提供憑證。
- **原始憑證** 讓程式碼在現有工具未能滿足需要時，直接呼叫服務供應商的 SDK。

本頁說明各服務供應商通用的設定。個別供應商的連線步驟和功能載於其[整合頁面](#providers)。

## 何时使用 Connect {/* #when-to-use-connect */}

如要由平台管理服務供應商帳戶，可使用 Connect，應用程式毋須儲存憑證或更新 OAuth 權杖。新增或更換連線時毋須修改 Agent 程式碼。工具解析器會在更新快取時取得連線變更，毋須重新部署。

Connect 需要平台項目，但應用程式可以在本機或自己的基礎設施運行。Connect 工具及頻道可配合[自訂工具](/docs/agents/tools)及[自行管理的頻道](/docs/channels)使用。

## 連線如何運作 {/* #how-connections-work */}

**服務供應商**指可連接的服務，以 `linear` 或 `google-mail` 等 ID 識別。每條**連線**授權該服務的一個帳戶。連線屬於機構，可將同一連線連結至多個項目，毋須再次授權。

同一項目可建立多條連線至同一供應商，例如不同 Slack 工作空間的帳戶。請為每條連線設定不同的顯示名稱，讓 Agent 選擇正確的帳戶。

各服務供應商的功能和授權方式各有不同。有些用 OAuth，有些需要 API 金鑰，頻道也可能需要在供應商的控制台設定機械人或應用程式。各供應商的整合頁面會列明要求。

## 开始使用 {/* #get-started */}

你需要一個 Mastra 平台項目，以及已使用 `mastra auth login` 登入的 [`mastra` CLI](/reference/cli/mastra)。

### 安装软件包 {/* #install-the-package */}

```bash npm2yarn
npm install @mastra/connect
```

### 配置环境 {/* #configure-the-environment */}

應用程式以存取權杖向平台驗證身份。請為應用程式建立權杖：

```bash
mastra auth tokens create my-app
```

請將權杖儲存為 `MASTRA_PLATFORM_ACCESS_TOKEN`，即 `@mastra/connect` 讀取的變數名稱。CLI 建議用 `MASTRA_API_TOKEN`，但 `@mastra/connect` 會略過這個名稱。請將權杖及項目 ID 加入應用程式的環境變數：

```bash title=".env"
MASTRA_PLATFORM_ACCESS_TOKEN=your-token
MASTRA_PROJECT_ID=your-project-id
```

地區和其他選用變數請參閱[環境變數](/reference/connect/tools#environment-variables)。

### 連接帳戶 {/* #connect-an-account */}

先在供應商的[整合頁面](#providers)找出 ID，再將該 ID 傳給 `mastra connect add`。例如，若要授權 Linear 帳戶：

```bash
mastra connect add linear
```

請在包含 `.env` 檔案的目錄執行指令。CLI 會引導你完成供應商的授權流程。執行 [`mastra connect list`](/reference/cli/mastra#mastra-connect-list) 可查看項目可用的服務供應商及其連線狀態。要為連線命名、移除或更換連線，請參閱 [`mastra connect` 參考](/reference/cli/mastra#mastra-connect)。

## 為 Agent 加入工具 {/* #add-tools-to-an-agent */}

将 [`tools()`](/reference/connect/tools) 传给 Agent 的 `tools` 选项：

```typescript title="src/mastra/agents/ops.ts"
import { Agent } from '@mastra/core/agent'
import { tools } from '@mastra/connect'

export const opsAgent = new Agent({
  id: 'ops',
  name: 'ops',
  instructions: 'You help the team track work in Linear and GitHub.',
  model: '__GATEWAY_OPENAI_MODEL_LUNA__',
  tools: tools(),
})
```

如沒有傳入選項，Agent 會取得所有已連線並提供工具集的供應商的工具。每個工具鍵均以供應商前綴起首，例如 `linear_list_issues`。前綴可能與供應商 ID 不同，例如 `google-calendar` 的工具以 `google_calendar_` 起首。[供應商工具集參考](/reference/connect/providers)列出所有鍵。部分供應商透過託管的 Model Context Protocol（MCP）伺服器提供工具，同樣使用 `tools()` API，但在執行時才探索工具。

如要同時保留自己的工具，請在 `tools` 函數展開解析器的結果。工具鍵重複時，以自己的工具為準：

```typescript title="src/mastra/agents/ops.ts"
import { Agent } from '@mastra/core/agent'
import { tools } from '@mastra/connect'
import { weatherTool } from '../tools/weather'

const connectTools = tools()

export const opsAgent = new Agent({
  id: 'ops',
  name: 'ops',
  instructions: 'You help the team track work in Linear and GitHub.',
  model: '__GATEWAY_OPENAI_MODEL_LUNA__',
  tools: async ctx => ({ ...(await connectTools(ctx)), weatherTool }),
})
```

## 選擇工具及要求審批 {/* #choose-tools-and-require-approval */}

只向 Agent 提供所需工具。以 `providers` 選擇供應商，以 `allowTools` 允許指定的工具鍵，並以 `requireApproval` 暫停選定工具，待審批後才執行：

```typescript
tools({
  providers: {
    linear: {
      allowTools: ['linear_list_issues', 'linear_create_issue'],
      requireApproval: ['linear_create_issue'],
    },
  },
})
```

工具預設毋須審批即可執行。傳入 `requireApproval: true` 可要求審批供應商的所有工具。工具集及 MCP 供應商均支援審批。處理審批請求的方法請參閱[人工介入指南](/docs/agents/human-in-the-loop)。

若供應商有多條連線，工具集會加入 `<provider>__list_connections` 工具。該供應商的其他工具以 `connection_name` 輸入選擇帳戶。如要固定使用同一連線，請為供應商設定 `connectionId`。

[`tools()` 參考](/reference/connect/tools#parameters)說明排除篩選條件、萬用字元模式、按請求調整的選項及快取。

## 加入頻道 {/* #add-channels */}

將 [`channels()`](/reference/connect/channels) 傳給 `Mastra` 建構函數：

```typescript title="src/mastra/index.ts"
import { Mastra } from '@mastra/core'
import { channels } from '@mastra/connect'
import { assistant } from './agents/assistant'

export const mastra = new Mastra({
  agents: { assistant },
  channels: await channels(),
})
```

這會註冊頻道 Provider 及其 Webhook 路由。要讓頻道運作，須分兩步設定：

1. **連接服務供應商。** 平台連線會儲存機械人或應用程式的憑證。步驟載於各供應商的整合頁面：[Slack](/integrations/channels/slack#agent-chat)、[Discord](/integrations/channels/discord#agent-chat)、[Telegram](/integrations/channels/telegram#connect) 及 [Microsoft Teams](/integrations/channels/teams#agent-chat)。
1. **在 Agent 安裝頻道。** 在 Studio 將頻道連接至 Agent，用戶便可向該 Agent 傳送訊息。

服務供應商必須可透過公開 URL 連到伺服器，才能傳送 Webhook 及執行 OAuth 回呼。Mastra 平台會提供這個 URL。如在其他環境託管，請將 `MASTRA_SERVER_URL` 設為伺服器的公開 URL。本機開發時請使用公開的 HTTPS 通道。

[`channels()` 參考](/reference/connect/channels)涵蓋供應商選擇、啟動錯誤及連線更新，並說明如何[同時使用 Connect 頻道與自行管理的頻道](/reference/connect/channels#combine-with-self-managed-channels)，以及[按頻道調整工具](/reference/connect/channels#vary-tools-by-channel)。

## 使用原始凭据 {/* #use-a-raw-credential */}

以連線 ID 呼叫 [`credential()`](/reference/connect/credential)，便可在程式碼取得該連線的憑證。需要使用供應商的 SDK 或工具未涵蓋的 API 時，可用這種做法。

## 安全模型 {/* #security-model */}

呼叫工具時，平台會在伺服器端為請求加入憑證，應用程式不會收到憑證。平台記錄每次經代理的呼叫，以供審計及統計工具用量，但不會記錄工具參數或結果。

經代理的請求只可連到供應商的 API 主機。部分連線容許使用其他主機，例如 Supabase 項目的 URL。Agent 可取得哪些工具，以及哪些呼叫須審批，均由你的程式碼控制。

`credential()` 會把原始憑證的秘密值傳回應用程式。使用該憑證發出的請求會繞過代理，既不受代理的主機限制，也不會留下代理呼叫記錄。請勿將憑證寫入日誌或在 Agent 輸出中傳回。

## 排解問題 {/* #troubleshooting */}

呼叫供應商失敗，大多源於連線的憑證或設定。`proxy_error` 的 `status` 及 `detail` 屬性載有供應商的回應。

- **狀態 `401`：** 憑證可能已過期、被撤銷或已輪換。如需更換憑證，請[重新授權連線](/reference/cli/mastra#replace-a-connection-that-needs-reauthorization)。
- **狀態 `403`：** 請檢查供應商回應，確認是否欠缺授權範圍、受到資源限制或須符合帳戶要求。以 `allowTools` 篩選工具不會改變憑證的權限。
- **沒有某供應商的工具：** 執行 `mastra connect list` 檢查項目及連線狀態，並核對所選供應商和工具篩選條件。確認已安裝的 `@mastra/connect` 版本附有該工具集。查看應用程式日誌有否 `[@mastra/connect] Skipping` 警告，這表示有連線未能解析。

所有錯誤代碼請參閱[錯誤參考](/reference/connect/tools#errors)。
