# Mastra 平台的可觀測性

Mastra 平台可觀測性會收集 Mastra 應用程式的 Trace、日誌、指標、評分和回饋。使用它即可取得代管的可觀測性，毋須部署 Studio 或 Server，亦毋須設定本機可觀測性儲存。

## 快速入門 {/* #quickstart */}

選擇適合項目的設定方式。

### 新專案 {/* #new-project */}

建立代管的 Mastra 項目，並在提示時啟用 Mastra 平台可觀測性：

```bash npm2yarn
npm create mastra@latest
```

create 指令會向 Mastra 平台驗證身分並建立可觀測性項目，然後建立存取 Token，把 `MASTRA_PLATFORM_ACCESS_TOKEN` 和 `MASTRA_PROJECT_ID` 寫入 `.env`。

### 現有項目 {/* #existing-project */}

如要在現有應用程式中加入 Mastra，請執行 `mastra init`，並在提示時啟用 Mastra 可觀測性：

```bash npm2yarn
npx mastra init
```

init 指令可選擇現有平台項目或建立新項目，然後建立存取 Token，把憑證寫入 `.env`。

## 手動配置 {/* #configure-manually */}

若跳過平台設定或自動建立失敗，請手動設定。

1. 在 [Mastra 平台](https://projects.mastra.ai)建立或開啟項目。
1. 為項目所屬機構建立存取 Token。
1. 從項目頁面複製項目 ID。
1. 把這兩個值加入 `.env`：

```bash title=".env"
MASTRA_PLATFORM_ACCESS_TOKEN=<your-platform-access-token>
MASTRA_PROJECT_ID=<your-project-id>
```

在可觀測性設定中註冊 [`MastraPlatformExporter`](/reference/observability/tracing/exporters/mastra-platform-exporter)：

```typescript title="src/mastra/index.ts"
import { Mastra } from '@mastra/core/mastra'
import { MastraPlatformExporter, Observability } from '@mastra/observability'

export const mastra = new Mastra({
  observability: new Observability({
    configs: {
      default: {
        serviceName: 'my-service',
        exporters: [new MastraPlatformExporter()],
      },
    },
  }),
})
```

Exporter 會從環境讀取存取 Token 和項目 ID。請固定 `serviceName`，以便篩選可觀測性資料時區分應用程式和部署。

`MastraPlatformExporter` 會傳送已結束的 Span、日誌、指標、評分和回饋。它會暫存事件，累積至 1,000 個事件或等待五秒後傳送一批。模型 Chunk Span 不會匯出。

:::note

`MastraPlatformExporter` 已取代 `CloudExporter`。`CloudExporter` 仍可用於向後兼容，但已棄用。新程式碼請使用 `MastraPlatformExporter`。

:::

### 將資料儲存在本地 {/* #store-data-locally */}

若亦想把可觀測性資料持久化至已設定的 Mastra 儲存，並在本機 Studio 中查看，請加入 `MastraStorageExporter`：

```typescript title="src/mastra/index.ts"
import { Mastra } from '@mastra/core/mastra'
import { MastraPlatformExporter, MastraStorageExporter, Observability } from '@mastra/observability'

export const mastra = new Mastra({
  observability: new Observability({
    configs: {
      default: {
        serviceName: 'my-service',
        exporters: [new MastraPlatformExporter(), new MastraStorageExporter()],
      },
    },
  }),
})
```

儲存要求和設定請參閱 [Mastra 儲存 Exporter](/docs/observability/integrations/exporters/mastra-storage)。

## 查看可觀測性資料 {/* #view-observability-data */}

在 [Mastra 平台](https://projects.mastra.ai)開啟項目，即可查看匯出的 Trace、日誌、指標和評分，毋須部署 Studio 或 Server。匯出的回饋可透過下述代管回饋 API 查詢。

維持一致的 `serviceName`，即可按特定應用程式或部署篩選資料。

## 查詢可觀測性資料 {/* #query-observability-data */}

使用 Mastra CLI 在終端機瀏覽代管 Trace：

```bash npm2yarn
npx mastra api trace list
```

CLI 從項目環境讀取 `MASTRA_PLATFORM_ACCESS_TOKEN` 和 `MASTRA_PROJECT_ID`，預設連至美國可觀測性端點。其他驗證方式和區域端點請參閱 [CLI 目標解析](/reference/cli/mastra#target-resolution)。

使用 `mastra api trace query` 按 Trace 欄位或相關 Span 尋找已完成的 Trace。例如，找出根 Span 耗時超過五秒的 Trace：

```bash
npx mastra api trace query '{
  "timeRange": {
    "from": "2026-08-01T00:00:00.000Z",
    "to": "2026-08-08T00:00:00.000Z"
  },
  "where": {
    "op": "gt",
    "left": { "path": "durationMs" },
    "right": { "literal": 5000 }
  },
  "page": { "limit": 25 }
}'
```

請選擇涵蓋已匯出 Trace、且在方案資料保留期內的時間範圍，並確保 `from` 早於 `to`。結果位於 `data.traces`。

Mastra 平台沿用 Mastra Server 的查詢和彙總請求結構。HTTP 端點、篩選器、回應格式、分頁和探索方式請參閱 [Trace 和 Span 查詢參考文件](/reference/observability/tracing/advanced-queries)：

| 工作 | CLI 指令 | 參考文件 |
| - | - | - |
| 尋找相符的 Trace | `mastra api trace query` | [查詢 Trace](/reference/observability/tracing/advanced-queries#query-traces) |
| 尋找個別 Span，包括巢狀執行 | `mastra api span query` | [查詢 Span](/reference/observability/tracing/advanced-queries#query-spans) |
| 彙總相符的 Trace | `mastra api trace aggregate` | [彙總 Trace](/reference/observability/tracing/advanced-queries#aggregate-traces) |
| 彙總個別 Span | `mastra api span aggregate` | [彙總 Span](/reference/observability/tracing/advanced-queries#aggregate-spans) |

每個指令都接收一個 JSON 參數，回應內容位於 `data` 之下。

### 平台範圍和差異 {/* #platform-scope-and-differences */}

使用 HTTP 標頭 `X-Mastra-Project-Id` 選擇單一項目。CLI 會從 `MASTRA_PROJECT_ID`、明確指定的標頭或項目設定中設定它。若沒有指定項目範圍，具機構層級存取權的憑證可跨項目查詢；綁定項目的憑證仍只可存取其項目。項目範圍須與查詢條件分開指定：不要在 `where` 中加入 `projectId`。

平台新增以下欄位和分組方式：

| 操作 | 平台新增功能 |
| - | - |
| `queryTraces()` 和 `querySpans()` | 每項結果都包含 `projectId`。 |
| `aggregateTraces()` | 支援 `groupBy: ['projectId']` 和 `countDistinct.projectId`。 |
| `aggregateSpans()` | 支援 `groupBy: ['projectId']`，但不支援 `countDistinct.projectId`。 |

資料保留期限取決於方案：Starter 為 15 日、Teams 為 6 個月，Enterprise 則可自訂。現行方案限制請參閱[收費頁面](https://mastra.ai/pricing)。

### 其他可觀測數據 {/* #other-observability-data */}

匯出的回饋可透過 HTTP 查詢。目前狀態、區域端點、驗證、項目範圍，以及 `traceId` 和 `environment` 等查詢參數，請參閱[回饋 API](/docs/mastra-platform/api#feedback-api)。

匯出的指標可透過 HTTP、`MastraClient` 或 `mastra api metric` 查詢。區域端點、驗證、項目範圍和支援的端點請參閱[指標 API](/docs/mastra-platform/api#metrics-api)。

## 匯入現有 Trace {/* #import-existing-traces */}

使用 `mastra traces import`，可把受支援 Provider 的現有 Trace 紀錄移至現有 Mastra 平台項目。此指令會在來源端讀取並驗證完整 Trace，轉換成 Mastra Span，再透過共用流程完成準備、上傳、續傳和驗證。

匯入指令目前支援 Langfuse。新增其他 Provider 適配器後，亦可沿用相同的指令流程。

| Provider | 指令參數 | 來源要求 |
| - | - | - |
| Langfuse | `langfuse` | Langfuse Cloud 或自行託管的 Langfuse v4 或更新版本 |

### 先決條件 {/* #prerequisites */}

開始匯入前，你需要：

- 一個 Mastra 平台項目。
- 透過 `mastra auth login` 完成 Mastra 平台驗證；無互動環境則提供 `MASTRA_API_TOKEN` 和 `MASTRA_ORG_ID`。
- 互動式登入時供上傳和回讀使用的 `MASTRA_PLATFORM_ACCESS_TOKEN`。試行毋須此 Token。
- 受支援來源 Provider 的憑證。
- 足夠的本機磁碟空間，用來暫存已準備的 Trace。

### 配置目的地 {/* #configure-the-destination */}

互動式匯入時，請登入並選擇目的地項目所屬機構：

```bash
npx mastra auth login
npx mastra auth orgs switch
```

互動式登入可用於搜尋項目。上傳或驗證 Trace 前，請設定目的地項目使用的平台存取 Token：

```bash title=".env"
MASTRA_PLATFORM_ACCESS_TOKEN=<mastra-platform-access-token>
```

若 `mastra init` 已為項目設定可觀測性，可使用它寫入 `.env` 的 Token；否則，請在 [Mastra 平台](https://projects.mastra.ai)建立存取 Token。

`--dry-run` 毋須此 Token，因為試行不會連線至收集器或查詢 API。

`--target-project` 指定接收 Trace 的 Mastra 平台目的地項目。可傳入項目名稱、slug 或 ID，亦可設定 `MASTRA_PROJECT_ID`：

```bash
npx mastra traces import langfuse --target-project my-mastra-project --dry-run
```

`--target-project` 優先於 `MASTRA_PROJECT_ID`。若兩者都沒有提供，CLI 會使用 `.mastra-project.json` 中連結的項目。

來源項目不是指令列選項，而是由 `.env` 中的 Provider 憑證決定。上傳任何內容前，準備摘要會列出來源項目。

對無互動環境，請設定 API Token 和機構 ID。指令使用 `MASTRA_API_TOKEN` 搜尋項目、上傳和回讀。亦須設定項目 ID 或傳入 `--target-project`：

```bash title=".env"
MASTRA_API_TOKEN=<mastra-api-token>
MASTRA_ORG_ID=<organization-id>
MASTRA_PROJECT_ID=<project-id>
```

### 配置Langfuse {/* #configure-langfuse */}

Langfuse API 金鑰只屬於一個 Langfuse 項目，因此亦決定來源項目。請在 Langfuse [建立項目 API 金鑰](https://langfuse.com/docs/api-and-data-platform/features/public-api)，然後把它們加入執行指令所在目錄的 `.env` 或 `.env.local`：

```bash title=".env"
LANGFUSE_PUBLIC_KEY=<langfuse-public-key>
LANGFUSE_SECRET_KEY=<langfuse-secret-key>
```

Langfuse Cloud 預設使用 `https://cloud.langfuse.com` 的歐盟區域。若使用美國、日本、HIPAA Cloud 或自行託管的實例，請把 `LANGFUSE_BASE_URL` 設為對應的[區域主機](https://langfuse.com/security/data-regions)或自行託管實例的來源網址：

```bash title=".env"
LANGFUSE_BASE_URL=https://us.cloud.langfuse.com
```

### 預覽導入 {/* #preview-the-import */}

上傳前先試行：

```bash
npx mastra traces import langfuse --target-project my-mastra-project --dry-run
```

試行會讀取來源資料，在本機準備有效的 Mastra Trace，並報告：

- 來源 Langfuse 項目的名稱和 ID，以及目的地 Mastra 平台項目。
- 固定的匯入時間範圍。
- 已準備和已跳過的 Trace 及 Span 數量。
- 已準備的本機資料大小。
- `report.json` 中的 Provider 警告和跳過原因。

試行不會上傳 Trace。指令會輸出一條 `--resume` 指令，之後可直接上傳已準備的資料，毋須重新讀取來源。

### 選擇導入視窗 {/* #choose-the-import-window */}

預設選取截至匯入開始時的過去 30 日。使用 `--since` 和 `--until` 可選擇較短的時間範圍：

```bash
npx mastra traces import langfuse \
  --target-project my-mastra-project \
  --since "$SINCE" \
  --until "$UNTIL" \
  --dry-run
```

把 `SINCE` 和 `UNTIL` 設為 ISO 8601 日期或時間戳記，並遵守以下規則：

- `--until` 必須在過去 30 日內，而且不能是未來時間。
- `--since` 必須早於 `--until`，而且在過去 30 日內。
- 所選時間範圍不能超過 30 日。
- 若只設定 `--until`，預設開始時間為目前時間往前 30 日。

這個 30 日匯入範圍與方案的資料保留期限互相獨立。

舊參數 `--from` 和 `--to` 仍可使用，但它們是 `--since` 和 `--until` 已棄用的隱藏別名，不會出現在指令說明中。新指令請使用 `--since` 和 `--until`。

Trace 是否納入匯入，取決於根 Observation 的開始時間。Langfuse 適配器會在所選時間範圍找出根節點，再讀取每條所選 Trace 目前可用的全部 Observation。若可用的父子樹或時間戳記無效，便會跳過整條 Trace。

### 上傳並驗證 {/* #upload-and-verify */}

執行指令時不傳入 `--dry-run`，即可上傳已準備的 Trace：

```bash
npx mastra traces import langfuse --target-project my-mastra-project
```

CLI 會顯示準備摘要，並在上傳前要求確認。自動化環境可傳入 `--yes` 跳過提示：

```bash
npx mastra traces import langfuse --target-project my-mastra-project --yes
```

匯入工具會把每條 Trace 完整放入同一個上傳請求，並只在 Mastra 平台確認整批資料後記錄進度檢查點。來源或目的地的暫時故障會進行有限次重試。

所有已準備的 Trace 獲確認後，匯入工具會回讀最多 10 條 Trace 的固定樣本，核對 Span ID、父子連結、名稱、Span 類型、事件標記、時間戳記及是否有錯誤。它不會回讀或比較輸入、輸出、屬性、中繼資料或標籤。

若尚未能回讀，或樣本 Trace 有差異，匯入會暫停並保留已準備的資料。恢復匯入可重試驗證，毋須再次上傳已確認的 Trace。

### 恢復導入 {/* #resume-an-import */}

試行、取消、中斷、上傳失敗或暫停驗證後，若匯入尚未完成，請使用 CLI 輸出的原本指令恢復：

```bash
npx mastra traces import langfuse \
  --resume 00000000-0000-0000-0000-000000000000 \
  --target-project my-mastra-project
```

恢復匯入時必須使用原本的 Provider 和目的地項目。已儲存的時間範圍不能更改，因此 `--resume` 不得與 `--since`、`--until` 或 `--dry-run` 同時使用。

恢復方式取決於指令中斷的位置：

- 準備階段中斷：重新讀取並準備來源資料。
- 上傳階段中斷：從第一條尚未確認的 Trace 開始。
- 驗證暫停：重新回讀驗證，不重複上傳已確認的 Trace。
- 匯入已完成：報告已完成狀態，並重試餘下的本機清理。

### 本地文件和清理 {/* #local-files-and-cleanup */}

匯入狀態儲存於：

```text
~/.mastra/imports/traces/<target-project-id>/<import-id>/
```

| 檔案 | 用途 | 生命週期 |
| - | - | - |
| `manifest.json` | 儲存來源身分、時間範圍、數量和已確認進度。 | 完成後保留。 |
| `traces.jsonl` | 每行儲存一條完整且已標準化的 Trace。 | 試行和未完成匯入時保留，驗證成功後刪除。 |
| `report.json` | 儲存數量、警告、跳過樣本和驗證結果。 | 寫入後保留。 |

這些檔案可能包含 Trace 內容。Mastra 建立匯入目錄和檔案時，會把權限限制為本機用戶。請保護執行匯入的裝置和帳戶。

### 導入的資料和限制 {/* #imported-data-and-limits */}

Langfuse 匯入有以下行為：

- Observation 會成為 Mastra Span，並保留父子關係和時間戳記。
- Langfuse `AGENT`、`TOOL` 和 `EVALUATOR` Observation，以及包含 `gen_ai.operation.name: invoke_agent` 等 OpenTelemetry GenAI 屬性的普通 Span，會保留其 Primitive 類型和名稱。Mastra 平台會像處理原生 Trace 一樣，在 Primitive type 和 Primitive name 欄顯示它們，並納入相應篩選器。
- 支援的欄位（例如名稱、輸入、輸出、錯誤、模型詳情、用量、成本、標籤和來源背景）會在存在時對應。
- 你在 Langfuse 設定的環境（例如 `staging`）會保留。Langfuse 內置的 `default` 環境不會複製；這些 Trace 在 Mastra 中沒有環境，Mastra Studio 會在每個環境顯示它們。
- 目的地 Trace 和 Span ID 具確定性。原始 Langfuse ID 保留在 Span 中繼資料中，方便關聯。
- 未知的 Langfuse Observation 類型會變成通用 Span，並發出警告，不會悄悄丟棄。
- 只匯入 Trace Observation。評分、回饋、資料集、附件和日誌均不會匯入。

共用匯入工具亦受以下限制：

- 每次匯入所準備的本機 Trace 資料上限為 5 GiB。若達到上限，請縮短時間範圍。
- 單條完整 Trace 必須符合匯入工具 4 MiB 上傳負載上限。超出上限會被跳過，並記錄 `trace_too_large` 原因。
- 不會把一條 Trace 拆分至多個上傳請求。

試行或完成匯入後，請查看 `report.json`，核對實際準備、跳過、確認和驗證的內容。

完整選項和環境變數請參閱 [`mastra traces import` CLI 參考文件](/reference/cli/mastra#mastra-traces-import)。
