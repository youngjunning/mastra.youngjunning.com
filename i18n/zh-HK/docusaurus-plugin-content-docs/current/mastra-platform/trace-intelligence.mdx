# Mastra 平台的 Trace Intelligence

Trace Intelligence 分析 Mastra Observability 收集的 Trace，生成四個內置維度的 Trace 訊號，以及項目啟用的自訂訊號，再把相似的 Trace 訊號歸納為主題，辨識 Agent 互動中反覆出現的模式。

你可透過 Trace Intelligence 了解以下問題：

- 用戶想完成甚麼？
- 哪些目標較常達成，哪些會停滯或遇到阻礙？
- 成功與未成功的互動各涉及哪些 Agent 行為？
- 用戶情緒與目標和結果有何關係？

:::warning 封閉測試
Trace Intelligence 只開放予部分獲邀的 Mastra 平台項目。
:::

## 取得存取權限 {/* #get-access */}

1. 提交 [Trace Intelligence 封閉測試表格](https://mastra.ai/trace-intelligence)，申請使用權限。
1. 確認已啟用 [Mastra 平台的 Observability](/docs/mastra-platform/observability)，而且 **Traces** 列出已完成的 Agent Trace。
1. 版本須達 `@mastra/core@1.53.0` 及 `mastra@1.20.2` 或以上。升級後，為獲准參與測試的項目部署或重新部署 Studio。封閉測試期間不支援本機 Studio 或只部署 Server。
1. 開啟已部署的 Studio，在側欄選擇 **Intelligence**。
1. 向 Agent 傳送具代表性的流量，並等候分析。

Mastra 將項目納入測試後，毋須更改 Agent 的定義或調用方式。

### 當數據可用時 {/* #when-data-is-available */}

Trace Intelligence 須處理同一個 Agent 足夠數量的 Trace，才可辨識重複模式。該 Agent 至少有 **100 條已完成的 Trace** 經處理後，通常便會出現首批主題。

分析流程以非同步方式運行，**Traces** 可能已顯示 100 條，分析仍未就緒。達到門檻後或需數分鐘。無法分析的 Trace 不計算在內，所以 100 條是最低要求，介面未必在達標一刻更新。

Trace Intelligence 會隨新增的 Trace 自動更新。至少兩類 Trace 訊號已有主題後，Studio 才可顯示關係圖。

請採用具代表性的流量。重複傳送少量測試提示可能令結果欠缺代表性，例如只得一個涵蓋範圍過廣的主題，或大部分摘要都歸入 Noise。

## 了解分析 {/* #understand-the-analysis */}

每條已完成且可分析的 Trace 都會產生以下四種內置 Trace 訊號，以及項目已啟用的自訂訊號：

| Trace 訊號 | 含義 |
| - | - |
| **Goal** | 用戶想達成的目標或完成的事項。 |
| **Outcome** | 最終狀態：完成、部分完成、受阻、失敗、未解決或不明確。 |
| **Behavior** | 可觀察到的 Agent 動作及模式，包括使用工具、遺漏、重試、失敗和復原。 |
| **Sentiment** | 用戶的情緒狀態或態度。 |

系統將相似的 Trace 訊號歸納為主題。各類訊號獨立分組，同一條 Trace 可在 Goal、Outcome、Behavior 和 Sentiment 分別歸入不同主題。

### 主題和關係 {/* #themes-and-relationships */}

關係圖連接相鄰 Trace 訊號欄的主題：

- **節點**代表一個主題，數字為所選快照中歸入該主題的不重複 Trace 數目。
- **連帶**連接相鄰兩欄中有共同 Trace 的主題，寬度代表共同的 Trace 數目。
- 將游標移到節點或連帶上，或把焦點移到該元素，即可單獨查看其關係。

圖表呈現的是關聯，不能據此判斷因果關係或執行次序。例如，Goal 與 Outcome 之間的連帶表示兩個主題出現在同一批 Trace，並不表示目標導致了結果。

### Other 和 Noise {/* #other-and-noise */}

各節點顯示在所選快照中歸入該主題的不重複 Trace 數目。主題詳情亦會列出所佔比例，例如「此快照的 70 條 Trace 中有 28 條屬於此主題（40%）」。

Studio 顯示各類 Trace 訊號最常見的主題，亦可能將較小的主題合併至 **Other**，以保留總數並讓圖表易於閱讀。

**Noise** 包含在所選快照中未能穩定歸入反覆出現主題的摘要。這未必代表有錯誤或互動質素欠佳，當中可能有罕見請求、新出現的模式、意思不明的互動或無關個案。Noise 佔比較高，可能表示流量差異很大，或數據不足以形成穩定主題。

### 快照 {/* #snapshots */}

快照涵蓋滾動分析視窗內的一組 Trace。快照可以重疊，因此不要將各自的 Trace 數目相加。各段時間的流量可能有變，比較時應同時查看主題的 Trace 數目及其在快照中所佔的比例。

主題在不同快照之間可以延續、消失、拆分、合併或再次出現。主題名稱和描述屬於生成的摘要，不宜當作固定分類。

## 使用 Trace Intelligence 頁面 {/* #use-the-trace-intelligence-page */}

1. 開啟 **Intelligence** 查看實體清單。你可搜尋或排序，再選擇實體查看分析。
1. 選擇圖中的主題以開啟詳情，並篩選各欄，只顯示包含該主題的 Trace。
1. 詳情面板列出主題描述、快照佔比、分頁顯示的例子摘要，以及 Trace 數目隨時間變化的趨勢。
1. 選擇 **Clear filter**，再次查看完整的關係圖。

實體在訊號仍在收集或處理時已會列出。清單顯示各實體已分析的 Trace 數目、已就緒及已啟用的訊號數目、生命週期狀態和上次更新時間。

### 配置自訂訊號 {/* #configure-a-custom-signal */}

組織管理員可直接在 Intelligence 設定自訂訊號：

1. 返回實體清單，選擇 **Signal settings**。
1. 選擇 **Create signal**，填寫固定的訊號名稱、顯示標籤、描述和指令，然後儲存。整個組織共用定義及其版本。
1. 在 **Current project** 啟用訊號。設定只影響目前的項目，並適用於隨後處理的 Trace。
1. 在清單中開啟實體，查看訊號如何從收集轉為處理，再到就緒。

你可修改自訂訊號的標籤、描述或指令。更改指令會建立新版本，只適用於新的 Trace。你亦可封存不應再供使用的定義，或稍後還原已封存的定義。

您也可以：

- 在關係圖選擇 **Noise**，查看所佔比例及生成的例子摘要。
- 拖動圖表上方的欄標題，重新排列 Trace 訊號欄，從另一角度查看關係。
- 在時間軸選擇快照，或選擇 **Play** 查看主題隨時間的變化。
- 切換至 **Compare**，查看兩個時間點之間有哪些主題擴大、縮小、進入或離開範圍。亦可選擇 **Lifelines**，追蹤各主題在整段所選時間內所佔的比例。

快照包含超過 2,000 條 Trace 時，無法按主題篩選關係圖，但仍可選擇主題查看詳情。

## 故障排除 {/* #troubleshooting */}

### 側欄沒有 Intelligence {/* #intelligence-isnt-in-the-sidebar */}

請確認 Mastra 已將正確的項目納入測試、目前的 Mastra 版本支援測試版，並且你已重新部署 Studio。封閉測試不支援本機 Studio。

### 找不到某個 Agent {/* #an-agent-is-missing */}

確認 **Traces** 已列出該 Agent 已完成的 Trace，並確認項目已加入測試。系統開始產生訊號後，Trace Intelligence 便會列出實體，毋須等首批主題就緒。如剛達到 100 條，請等候非同步處理。

### 無法查看關係圖 {/* #the-relationship-flow-is-unavailable */}

至少兩類 Trace 訊號須已有主題，關係圖才可顯示。請繼續傳送具代表性的流量，並等候處理完成。

### 大部分摘要歸入 Noise {/* #most-summaries-are-noise */}

收集更多具代表性的流量，再比較較後的快照。差異大或罕見的互動較難分組，重複的測試提示則可能令分佈欠缺代表性。

## 封閉測試的限制 {/* #private-beta-limitations */}

- Trace Intelligence 只供已加入測試的項目在已部署的 Studio 使用。
- 首次分析要求每個 Agent 至少有 100 條經處理的 Trace。部分 Agent 或需要更多。
- 結果取決於所收集 Trace 的多樣性和質素。
- 測試期間，Trace 訊號摘要、主題標籤、分組、門檻和介面行為均可能改變。

提交意見時，請附上組織 ID、項目 ID、Agent ID、所選快照，以及能說明問題的主題或 Noise 例子。
