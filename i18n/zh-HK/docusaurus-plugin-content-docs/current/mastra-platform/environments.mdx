# 環境

每個平台項目都包含一個或多個環境。

環境是一個獨立的部署目標，具有自己的 URL、環境變數和部署歷史記錄。也可以有自己的[hosted database](/docs/mastra-platform/database).

使用環境來運行`production`, `staging`，以及單一專案中相同程式碼庫的預覽版本。

你的第一個[`mastra deploy`](/docs/mastra-platform/deploy) creates the `production` environment. Create more with the CLI or by deploying to a name that doesn't exist yet.

## 創造環境 {/* #create-an-environment */}

明確建立環境：

```bash
mastra env create staging
```

或讓部署建立它，這會提示您確認：

```bash
mastra deploy --env staging
```

`mastra env create`預設為`staging` type. Pass `--type` to set `staging` or `preview` explicitly, and `--region`選擇環境運行的位置：

```bash
mastra env create eu-preview --type preview --region eu
```

每個項目都有一個`production` environment, created by your first deploy. The region is fixed at creation. Attached databases are placed near the environment automatically, while observability data goes to the ingest region for the matching residency zone. See [Regions](/docs/mastra-platform/regions) for supported regions and database placement, along with observability co-location. The number of environments per project depends on your plan.

## 列出環境 {/* #list-environments */}

```bash
mastra env list
```

輸出顯示每個環境的名稱、區域、活動部署狀態以及附加資料庫注入的託管環境變數。經過`--json` for machine-readable output in CI.

全部`mastra env` commands resolve their project from the `--project` flag, the `MASTRA_PROJECT_ID` environment variable, or the `.mastra-project.json` file written by your first deploy, in that order. Run them from your project directory and you never need to name the project.

## 環境變數 {/* #environment-variables */}

環境從兩個範圍解析其變數：

* **託管變數**：由附件注入[hosted databases](/docs/mastra-platform/database) (for example `TURSO_DATABASE_URL`) and by the platform itself. The platform defines these, and you can't edit them. See [System environment variables](/docs/mastra-platform/system-environment-variables) for the full list.
* **環境範圍的變數**：透過儀表板儲存在每個環境中。當您將一個變數應用於多個環境時，每個環境都會保留自己的副本。將這些值用於環境之間不同的值，例如用於登台和生產服務的 API 金鑰。

環境範圍的變數是描述的儲存變數[Deploy](/docs/mastra-platform/deploy#environment-variables) page. A deploy of one environment uses only that environment's variables. Projects still on the [legacy pipeline](/docs/mastra-platform/deploy#migrating-from-server-and-studio-deploys) store their variables on the project instead, and every deploy of that project uses them.

部署開始時應用變數。要將更改的變數套用到正在執行的服務而不需要完全重新部署：

```bash
mastra env restart staging
```

若要查看環境部署實際運行的設置，以及按名稱列出的託管變量，請將它們拉入本機環境檔案中。每個環境都是獨立的。該文件永遠不會混合在另一個環境的值中：

```bash
mastra env vars pull staging --output .env.staging
```

託管變數值在部署時注入，並且永遠不會寫入檔案。它們僅顯示為名稱註釋。

:::注意
環境變數不會覆蓋託管資料庫變數。若要將環境指向不同的資料庫，請附加[environment-scoped database](/docs/mastra-platform/database#attach-with-the-cli) instead.
:::

## 部署歷史記錄 {/* #deploy-history */}

列出跨所有環境的部署，或過濾到一個：

```bash
mastra env deploys
mastra env deploys staging
```

每行顯示部署狀態、環境、時間戳記以及目前處於活動狀態的部署。部署轉換透過**queued → uploading → starting → deploying → running**, and the platform reports **running** only when the new version is serving traffic. Deploys triggered from GitHub first build from source, so they pass through **building** between **queued** and **uploading**.

## 隔離環境數據 {/* #isolate-an-environments-data */}

預設情況下，託管資料庫的範圍僅限於單一環境，因此生產和暫存每個資料庫都會讀取和寫入自己的資料庫：

```bash
mastra env db create production --kind turso --name my-project-production-db
mastra env db create staging --kind turso --name my-project-staging-db
```

如果您希望在每個環境中共享一個資料庫，請將其附加到`--shared` instead: `mastra env db create --kind turso --shared`.

每個環境可以為每個提供者使用一個資料庫。現有的共享 (`--shared`) database from the same provider creates a variable-name conflict with an environment-scoped database. Export any data you need to keep before running `mastra env db delete`, because this command destroys the shared provider database and its data. See [Hosted databases](/docs/mastra-platform/database) for the full scoping model.

## 刪除環境 {/* #delete-an-environment */}

```bash
mastra env delete staging
```

CLI 在刪除之前要求確認。刪除環境會刪除其部署和儲存的變數。
