# 環境

每個平台項目都包含一個或多個環境。

環境是一個獨立的部署目標，具有自己的 URL、環境變數和部署歷史記錄。也可以有自己的[hosted database](/docs/mastra-platform/database).

使用環境來運行`production`, `staging`，以及單一專案中相同程式碼庫的預覽版本。

首次執行 [`mastra deploy`](/docs/mastra-platform/deploy) 便會建立 `production` 環境。如要新增環境，可使用 CLI，或部署至尚未存在的環境名稱。

## 建立環境 {/* #create-an-environment */}

明確建立環境：

```bash
mastra env create staging
```

或讓部署建立它，這會提示您確認：

```bash
mastra deploy --env staging
```

`mastra env create` 預設採用 `staging` 類型。可透過 `--type` 指明 `staging` 或 `preview`，並以 `--region` 選擇環境在哪個區域運行：

```bash
mastra env create eu-preview --type preview --region eu
```

每個項目只有一個 `production` 環境，由首次部署建立，區域一經選定便不能更改。所連接的資料庫會自動設於環境附近；可觀測性資料則會送往相應資料存放區所屬的接收區域。支援的區域、資料庫的位置和可觀測性資料的同區配置，詳見[區域](/docs/mastra-platform/regions)。每個項目的環境數目視乎所用計劃。

## 列出環境 {/* #list-environments */}

```bash
mastra env list
```

輸出會顯示各環境的名稱、區域、現行部署的狀態，以及相連資料庫注入的受管理環境變數。CI 可加上 `--json`，取得程式可讀取的輸出。

所有 `mastra env` 指令會依次查看 `--project` 選項、`MASTRA_PROJECT_ID` 環境變數，以及首次部署時寫入的 `.mastra-project.json` 檔案，以確定所用項目。在項目目錄執行，便毋須另行指定項目。

## 環境變數 {/* #environment-variables */}

環境從兩個範圍解析其變數：

- **受管理變數**：由相連的[託管資料庫](/docs/mastra-platform/database)（例如 `TURSO_DATABASE_URL`）或平台本身注入。這些變數由平台定義，不能編輯。完整清單見[系統環境變數](/docs/mastra-platform/system-environment-variables)。
* **環境範圍的變數**：透過儀表板儲存在每個環境中。當您將一個變數應用於多個環境時，每個環境都會保留自己的副本。將這些值用於環境之間不同的值，例如用於登台和生產服務的 API 金鑰。

環境專用變數即[部署](/docs/mastra-platform/deploy#environment-variables)一頁所述的已儲存變數。部署個別環境時，只會採用該環境的變數。仍使用[舊版部署流程](/docs/mastra-platform/deploy#migrating-from-server-and-studio-deploys)的項目，會把變數儲存在項目層級，該項目每次部署均會使用這些變數。

部署開始時應用變數。要將更改的變數套用到正在執行的服務而不需要完全重新部署：

```bash
mastra env restart staging
```

若要查看環境部署實際運行的設置，以及按名稱列出的託管變量，請將它們拉入本機環境檔案中。每個環境都是獨立的。該文件永遠不會混合在另一個環境的值中：

```bash
mastra env vars pull staging --output .env.staging
```

託管變數值在部署時注入，並且永遠不會寫入檔案。它們僅顯示為名稱註釋。

:::note
環境變數不會覆蓋託管資料庫變數。如要環境使用另一個資料庫，請連接[環境專用資料庫](/docs/mastra-platform/database#attach-with-the-cli)。
:::

## 部署歷史記錄 {/* #deploy-history */}

列出跨所有環境的部署，或過濾到一個：

```bash
mastra env deploys
mastra env deploys staging
```

每列顯示部署狀態、環境、時間戳記及目前生效的部署。部署依次經過 **queued → uploading → starting → deploying → running**；平台只會在新版本開始處理流量後顯示 **running**。GitHub 觸發的部署會先從原始碼建置，因此 **queued** 和 **uploading** 之間還有 **building**。

## 隔離環境數據 {/* #isolate-an-environments-data */}

託管資料庫預設只供一個環境使用，因此正式環境和預備環境會各自讀寫自己的資料庫：

```bash
mastra env db create production --kind turso --name my-project-production-db
mastra env db create staging --kind turso --name my-project-staging-db
```

如想多個環境共用同一個資料庫，可用 `--shared` 連接：`mastra env db create --kind turso --shared`。

每個環境只可使用每個 Provider 的一個資料庫。若同一 Provider 已有共用資料庫（`--shared`），其變數名稱便會與環境專用資料庫衝突。執行 `mastra env db delete` 前，須匯出要保留的資料；此指令會刪除該 Provider 的共用資料庫及其中的資料。完整的適用範圍見[託管資料庫](/docs/mastra-platform/database)。

## 刪除環境 {/* #delete-an-environment */}

```bash
mastra env delete staging
```

CLI 在刪除之前要求確認。刪除環境會刪除其部署和儲存的變數。
