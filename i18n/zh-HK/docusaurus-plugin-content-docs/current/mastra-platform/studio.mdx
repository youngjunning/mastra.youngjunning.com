# Mastra 平台上的 Studio

Mastra 平台的 Studio 是託管的視覺化工作區，可測試 Agent、執行 Workflow 和查看追蹤記錄。你可以和團隊共用 Studio，無須自行託管 Studio 介面。

你可按下文透過 CLI 部署 Studio，也可連結 GitHub 儲存庫，在推送變更時觸發部署。連結儲存庫的步驟見 [GitHub 整合](/docs/mastra-platform/github)。

## 快速上手 {/* #quickstart */}

<Steps>
  <StepItem>
    按照[入門指南](/docs)建立首個 Mastra 項目。
  </StepItem>

  <StepItem>
    全域安裝 `mastra` CLI：

    ```bash npm2yarn
    npm install -g mastra
    ```
  </StepItem>

  <StepItem>
    用以下一條指令部署 Studio：

    ```bash
    mastra deploy
    ```

    部署成功後，CLI 會輸出已部署的 Studio 實例網址。
  </StepItem>
</Steps>

首次部署時，CLI 會提示你建立新項目或選取現有項目，然後在項目目錄建立 `.mastra-project.json`。這個檔案把本機項目連結至平台項目，內含 `projectId`、`projectName` 及 `organizationId`。請把檔案提交到儲存庫，讓 CI/CD 識別部署的目標項目。

## 部署如何運作 {/* #how-deploy-works */}

`mastra deploy` 會建構項目，把 `src/mastra/` 編譯至 `.mastra/output`，再把輸出打包成 ZIP 檔，上載並部署至雲端沙盒。

部署狀態依次為 **queued → uploading → starting → deploying → running**，如有問題則轉為 **failed**。如果項目已有沙盒正在執行，平台會直接更新該沙盒，期間無須停機；否則會建立新沙盒。平台按環境分配實例網址，同一環境即使重新部署，網址也會維持不變。

所有命令列選項及 CI/CD 用法見 [`mastra deploy` CLI 參考](/reference/cli/mastra#mastra-deploy)。

## 身份驗證 {/* #authentication */}

Mastra 平台預設為所有已部署的 Studio 啟用平台身份驗證，你無須另作設定。只有所屬平台組織的成員可用自己的平台帳戶登入並存取 Studio。

平台身份驗證只適用於 Studio 介面。伺服器的 API 路由由你自己的 [`server.auth`](/docs/studio/auth) 配置管理；沒有配置的話，路由仍然開放。

### 角色及權限 {/* #roles-and-permissions */}

平台身份驗證會按以下配對，把組織角色轉為 Studio 權限：

| 平台角色 | Studio 權限 |
| - | - |
| `admin` | 完整存取權限（`*`） |
| `member` | 可讀取及執行 |
| `viewer` | 唯讀 |

如要自行設定角色與權限的配對，請在 Mastra 配置中設定 `roleMapping`（位於 `studio.rbac` 內）。自訂配對會取代平台預設值。權限格式見[以角色為基礎的存取控制](/docs/studio/auth#role-based-access-control)。

### 使用自選身份驗證服務 {/* #bring-your-own-auth */}

如要讓已部署的 Studio 改用自選的身份驗證供應商，請為項目設定以下環境變數：

```bash
MASTRA_PLATFORM_STUDIO_AUTH=disabled
```

把變數加入部署用的環境變數檔案，或透過管理介面儲存在項目中，再重新部署。停用平台身份驗證後，部署不會更改你的身份驗證和 RBAC 配置。跟自行託管一樣，Studio 的登入流程會由你選用的供應商處理。`studio.auth` 保護 Studio 介面，`server.auth` 則保護 API 路由。如未設定 `studio.auth`，Studio 請求會改用 `server.auth`。

:::warning
停用平台身份驗證後，平台帳戶將無法用來登入。如果沒有配置自己的身份驗證供應商就停用平台驗證，已部署的 Studio 和所有 API 路由都可公開存取。
:::

若啟用平台身份驗證並同時配置自己的 `studio.auth`，兩個供應商都會驗證權杖，但登入畫面只提供平台登入。要透過自選供應商登入，請停用平台身份驗證。

## 環境變數檔案 {/* #environment-files */}

本機的環境變數檔案可省略。若項目目錄有 `.env` 或 `.env.*` 檔案，部署時會把當中的環境變數一併打包。

如有多份環境變數檔案，CLI 會提示你選取一份。要直接指定檔案而不經互動提示，請傳入 `--env-file`：

```bash
mastra deploy --env-file .env.production --yes
```

如要在 `production` 和 `staging` 使用同一套程式碼，請用 [`mastra deploy --env`](/docs/mastra-platform/deploy#deploy-to-another-environment)。運作詳情見[環境](/docs/mastra-platform/environments)。

## 無須互動即可建立新項目 {/* #create-a-new-project-non-interactively */}

首次執行時，`mastra deploy` 可以建立項目。如果 `--project <name>` 找不到相符的現有項目，CLI 會用該值作為新項目名稱，並在確認後建立。加入 `--yes` 即可用指令碼自動執行整個流程：

```bash
mastra deploy --project "my-new-project" --yes
```

在 CI 或使用 AI 編程 Agent 時，請採用上面的做法，因為 `mastra studio projects create` 只支援互動操作。
