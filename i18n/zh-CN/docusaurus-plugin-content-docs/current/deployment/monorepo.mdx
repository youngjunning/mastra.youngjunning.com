# Monorepo

在 monorepo 中部署 Mastra 的流程与部署独立应用相同。本指南介绍 monorepo 特有的注意事项。基本构建和部署步骤请参阅[部署 Mastra 服务器](/docs/deployment/mastra-server)。

## 支持的 monorepo 工具 {/* #supported-monorepos */}

Mastra 支持以下工具：

- npm 工作区
- pnpm 工作区
- Yarn 工作区
- Turborepo

已知限制：

- Bun 工作区：仅部分支持，存在已知问题
- Nx：可以采用 Nx [支持的依赖管理策略](https://nx.dev/concepts/decisions/dependency-management)，但每个工作区包中都要有 `package.json`

## 目录结构示例 {/* #example-structure */}

本例中的 Mastra 应用位于 `apps/api`：

```text
apps/
├── api/
│   ├── src/
│   │   └── mastra/
│   │       ├── agents/
│   │       ├── tools/
│   │       ├── workflows/
│   │       └── index.ts
│   ├── package.json
│   └── tsconfig.json
└── web/
packages/
├── ui/
└── utils/
package.json
```

## 在 monorepo 中构建 {/* #building-from-a-monorepo */}

用 monorepo 工具针对正确的包运行构建命令即可，无需额外的命令行选项。

示例：

<Tabs>
  <TabItem value="npm" label="npm">
    ```bash
    npm run build --workspace=apps/api
    ```
  </TabItem>

  <TabItem value="pnpm" label="pnpm">
    ```bash
    pnpm --filter api run build
    ```
  </TabItem>

  <TabItem value="yarn" label="yarn">
    ```bash
    yarn workspace api build
    ```
  </TabItem>

  <TabItem value="turborepo" label="Turborepo">
    ```bash
    turbo run build --filter=api
    ```
  </TabItem>
</Tabs>

包的 `build` 脚本应执行 `mastra build`：

```json title="apps/api/package.json"
{
  "scripts": {
    "build": "mastra build"
  }
}
```

## 工作区包 {/* #workspace-packages */}

Mastra 应用从其他工作区包导入时，Mastra 会自动处理：

- 如果包已预先编译（例如用 `tsc` 或 `tsdown` 构建），Mastra 会导入编译后的 JavaScript
- 如果包中包含未编译的 TypeScript，Mastra 会在构建时转译

大多数情况下不需要配置。如果导入工作区包时遇到问题，请将该包加入 [`transpilePackages`](/reference/configuration#bundlertranspilepackages)：

```typescript title="src/mastra/index.ts"
import { Mastra } from '@mastra/core'

export const mastra = new Mastra({
  bundler: {
    transpilePackages: ['@my-org/utils'],
  },
})
```

`bundler` 应是传给 `new Mastra()` 的对象的直接属性。入口文件支持的结构见[构建时配置](/docs/deployment/mastra-server#build-time-configuration)。

## 环境变量 {/* #environment-variables */}

将 `.env` 文件放在 Mastra 应用目录内（例如 `apps/api/.env`）。不要放在 monorepo 根目录。

## 部署配置 {/* #deployment-configuration */}

部署到云服务时，请选择正确的包作为部署目标。常见错误是选了 monorepo 根目录，而没有选应用目录（例如 `apps/api`）。

大多数云服务支持通过控制台或配置文件指定根目录。

## 依赖管理 {/* #dependency-management */}

保持依赖一致，避免版本冲突和构建错误：

- 在 monorepo 根目录只保留**一个锁文件**，使所有包解析到相同的版本
- 统一 **共享库**（如 Mastra 或框架）的版本，避免重复

### 跳过依赖安装 {/* #skipping-dependency-installation */}

默认情况下，`mastra build` 将包管理器的锁文件复制到 `.mastra/output`，再通过一次包管理操作更新锁文件并安装依赖。CI 中也会更新锁文件。如果没有源锁文件，Mastra 会使用 npm 并生成 `package-lock.json`。Bazel 等密闭构建系统从外部提供 `node_modules`，并在无网络的沙箱中运行。在这种环境下，安装步骤是多余的，还会导致构建失败。

将 `MASTRA_BUILD_SKIP_INSTALL` 设为 `true` 或 `1`，即可跳过锁文件更新和输出目录中的依赖安装：

```bash
MASTRA_BUILD_SKIP_INSTALL=1 mastra build
```

启用此设置后，需要自行在输出目录提供 `node_modules`。

## 故障排查 {/* #troubleshooting */}

### 找不到工作区包 {/* #workspace-package-not-found */}

如果 Mastra 无法解析工作区包，请检查以下各项：

- 该包已列入 `package.json` 的依赖
- 锁文件已更新（例如运行 `pnpm install` 或 `npm install`）
- 该包的 `main` 或 `exports` 字段在其 `package.json` 中有效

### 工作区包中的 TypeScript 错误 {/* #typescript-errors-from-workspace-packages */}

如果未编译的工作区包出现类型错误，可以任选以下一种做法：

- 先构建该包（推荐，可加快 Mastra 构建）
- 在 Mastra 配置的 [`transpilePackages`](/reference/configuration#bundlertranspilepackages) 中添加该包
