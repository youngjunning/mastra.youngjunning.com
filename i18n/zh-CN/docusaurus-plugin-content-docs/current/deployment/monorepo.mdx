# 莫诺雷波

在 monorepo 中部署 Mastra 遵循与独立应用程序相同的过程。本指南涵盖了单一存储库特定的注意事项。有关核心构建和部署步骤，请参阅[Deploy a Mastra Server](/docs/deployment/mastra-server).

## 支持的单一仓库 {/* #supported-monorepos */}

马斯特拉适用于：

* npm Workspace
* pnpm Workspace
* 纱线Workspace
* 涡轮雷波

已知限制：

* Bun Workspace - 部分支持；已知问题
* Nx - 您可以使用 Nx[supported dependency strategies](https://nx.dev/concepts/decisions/dependency-management) but you need to have `package.json` files inside your workspace packages

## 结构示例 {/* #example-structure */}

在此示例中，Mastra 应用程序位于`apps/api`:

```text
apps/
├── api/
│   ├── src/
│   │   └── mastra/
│   │       ├── agents/
│   │       ├── tools/
│   │       ├── workflows/
│   │       └── index.ts
│   ├── package.json
│   └── tsconfig.json
└── web/
packages/
├── ui/
└── utils/
package.json
```

## 从单一存储库构建 {/* #building-from-a-monorepo */}

使用 monorepo Tool从正确的包运行构建命令。不需要特殊的标志。

示例：

<Tabs>
  <TabItem value="npm" label="npm">
    ```bash
    npm run build --workspace=apps/api
    ```
  </TabItem>

  <TabItem value="pnpm" label="pnpm">
    ```bash
    pnpm --filter api run build
    ```
  </TabItem>

  <TabItem value="yarn" label="yarn">
    ```bash
    yarn workspace api build
    ```
  </TabItem>

  <TabItem value="turborepo" label="Turborepo">
    ```bash
    turbo run build --filter=api
    ```
  </TabItem>
</Tabs>

你的包裹的`build` script should run `mastra build`:

```json title="apps/api/package.json"
{
  "scripts": {
    "build": "mastra build"
  }
}
```

## Workspace包 {/* #workspace-packages */}

当您的 Mastra 应用程序从其他Workspace包导入时，Mastra 会自动处理此问题：

* 如果包是预编译的（例如，使用`tsc` or `tsdown`), Mastra imports the compiled JavaScript
* 如果包包含未编译的 TypeScript，Mastra 会在构建期间对其进行转译

对于大多数设置，无需配置即可使用。如果您遇到Workspace包导入问题，请将包添加到[`transpilePackages`](/reference/configuration#bundlertranspilepackages):

```typescript title="src/mastra/index.ts"
import { Mastra } from '@mastra/core'

export const mastra = new Mastra({
  bundler: {
    transpilePackages: ['@my-org/utils'],
  },
})
```

保持`bundler` as a direct property in the object passed to `new Mastra()`. See [build-time configuration](/docs/deployment/mastra-server#build-time-configuration) for the supported entry-file shape.

## 环境变量 {/* #environment-variables */}

店铺`.env` files in the Mastra application directory (e.g., `apps/api/.env`), not the monorepo root.

## 部署配置 {/* #deployment-configuration */}

部署到云Provider时，请确保选择正确的包作为部署目标。选择 monorepo 根目录而不是应用程序目录（例如，`apps/api`) is a common mistake.

大多数Provider允许您在其仪表板或配置文件中指定根目录。

## 依赖管理 {/* #dependency-management */}

保持依赖关系一致以避免版本冲突和构建错误：

* 使用一个**single lockfile** at the monorepo root so all packages resolve the same versions
* 对齐版本**shared libraries** (like Mastra or frameworks) to prevent duplicates

### 跳过依赖安装 {/* #skipping-dependency-installation */}

默认情况下，`mastra build` copies your package manager's lockfile into `.mastra/output`, then updates the lockfile and installs dependencies in one package-manager operation. This update remains enabled in CI. If no source lockfile exists, Mastra uses npm and generates `package-lock.json`. Hermetic build systems (such as Bazel) supply `node_modules` externally and run in a network-less sandbox, where this install is both redundant and fatal.

放`MASTRA_BUILD_SKIP_INSTALL` to `true` or `1` to skip the lockfile update and output install:

```bash
MASTRA_BUILD_SKIP_INSTALL=1 mastra build
```

启用后，您有责任提供`node_modules` in the output directory yourself.

## 故障排除 {/* #troubleshooting */}

### 找不到Workspace包 {/* #workspace-package-not-found */}

如果 Mastra 无法解析Workspace包，请确保：

* 该软件包已列在您的`package.json` dependencies
* 您的锁定文件是最新的（`pnpm install`, `npm install`, etc.)
* 该包有一个有效的`main` or `exports` field in its `package.json`

### Workspace包中的 TypeScript 错误 {/* #typescript-errors-from-workspace-packages */}

如果您看到未编译的Workspace包中出现类型错误，请执行以下任一操作：

* 首先构建包（建议更快地构建 Mastra）
* 将包添加到[`transpilePackages`](/reference/configuration#bundlertranspilepackages) in your Mastra config
