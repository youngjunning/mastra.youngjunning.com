# 马斯特拉服务器

Mastra 将您的应用程序编译为独立的 Node.js 服务器，该服务器可以在支持 Node.js、Bun 或 Deno 的任何平台上运行。

：：：提示

本指南介绍了如何部署由`mastra build`. If you need to integrate Mastra into an existing Express or Hono application, see [Server Adapters](/docs/server/server-adapters)反而。

:::

## 构建您的应用程序 {/* #building-your-application */}

从项目根目录运行构建命令：

```bash
mastra build
```

这创建了一个`.mastra` directory containing your production-ready server. Read the [`mastra build`](/reference/cli/mastra#mastra-build) reference for all available flags.

## 构建输出 {/* #build-output */}

构建后，Mastra 创建以下结构：

```text
.mastra/
├── .build/                # Intermediate build artifacts (module maps, analysis)
└── output/
    ├── index.mjs          # Server entry point
    ├── mastra.mjs         # Your bundled Mastra configuration
    ├── tools.mjs          # Aggregated tool exports
    ├── tools/             # Individual tool bundles
    ├── package.json       # Production dependencies
    ├── node_modules/      # Installed dependencies
    ├── .npmrc             # Copied from your project (if present)
    ├── <static assets>     # Contents of src/mastra/public, merged into the output root
    └── playground/        # Studio UI (if --studio flag used)
```

这`output` directory is self-contained. You can copy it to any server and run it directly.

:::警告\[不要将数据库文件保存在`src/mastra/public`]

构建复制的内容`src/mastra/public` into `.mastra/output` and overwrites files with the same name. A SQLite database stored in `public` therefore ends up inside the build, and a URL such as `file:./mastra.db` resolves against the directory the server runs from. If that's the output directory, the server opens the copied database instead of the one you edit, and changes to it are lost on the next build. Keep database files outside `public`.

:::

## 运行服务器 {/* #running-the-server */}

使用 Mastra CLI 启动服务器：

```bash
mastra start
```

或者直接使用 Node.js 运行：

```bash
node .mastra/output/index.mjs
```

这`mastra start` command provides additional features:

* 从以下位置加载环境变量`.env.production` and `.env`
* 为丢失的模块提供有用的错误消息
* 处理进程信号以正常关闭

阅读[`mastra start`](/reference/cli/mastra#mastra-start) reference for all available flags.

## 构建配置 {/* #build-configuration */}

### 构建时配置 {/* #build-time-configuration */}

马斯特拉读到`bundler`, `deployer`, and `server` options while it builds your application. Keep those options as direct properties of the object passed to `new Mastra()` so the build can extract them.

以下条目文件形状有效：

```typescript title="src/mastra/index.ts"
import { Mastra } from '@mastra/core/mastra'

export const mastra = new Mastra({
  bundler: {
    externals: ['sharp'],
  },
  server: {
    port: 4111,
  },
})
```

每个选项的值可以来自变量、导入或函数调用。期权本身必须保持为直接财产。不要将构建时选项隐藏在工厂调用或对象扩展后面：

```typescript title="src/mastra/index.ts"
import { Mastra } from '@mastra/core/mastra'

const options = {
  bundler: {
    externals: ['sharp'],
  },
}

// These patterns prevent Mastra from extracting `bundler` during the build.
export const mastra = new Mastra(createMastraOptions())
export const otherMastra = new Mastra({ ...options })
```

当 Mastra 无法提取选项时，它会使用该选项的默认构建行为。请参阅[configuration reference](/reference/configuration) for the available `bundler`, `deployer`, and `server` settings.

### 公用文件夹 {/* #public-folder */}

如果一个`public` folder exists in your Mastra directory (`src/mastra/public`), its contents are copied to the output directory during build. These files are served as static assets by the server.

### 马斯特拉配置 {/* #mastra-configuration */}

构建过程尊重 Mastra 实例中的配置。对于 CORS、超时和中间件等服务器行为，请参阅[server overview](/docs/server/overview). For all available options, see the [configuration reference](/reference/configuration).

## 构建过程 {/* #build-process */}

构建遵循以下步骤：

1. **找到入口文件**：发现`index.ts` or `index.js` in your Mastra directory.
2. **发现Tool**：扫描匹配的Tool文件`{mastraDir}/tools/**/*.{js,ts}`, excluding test files.
3. **分析依赖关系**：确定要捆绑哪些软件包与外部安装哪些软件包。
4. **捆绑代码**：使用带有树摇动和可选源映射的 Rollup。
5. **生成服务器**：创建一个基于 Hono 的 HTTP 服务器`index.mjs`.
6. **安装依赖项**：运行`npm install` in the output directory.
7. **复制资产**: 副本`public` folder and `.npmrc` if present.

## 环境变量 {/* #environment-variables */}

|变量|描述 |
| - | - |
|`PORT` | Server port (default: `4111`) |
| `MASTRA_STUDIO_PATH` | Path to Studio build directory (default: `./playground`) |
| `MASTRA_SKIP_DOTENV` | Skip loading `.env` files when set |
| `NODE_OPTIONS` | Node.js options (e.g., `--max-old-space-size=4096` for build memory issues) |

## 服务器端点 {/* #server-endpoints */}

构建的服务器公开用于健康检查、Agent、Workflow程等的端点：

|端点 |描述 |
| - | - |
|`GET /health` | Health check endpoint, returns `200 OK` |
| `GET /api/openapi.json` | OpenAPI specification (if `server.build.openAPIDocs` is enabled). |
| `GET /swagger-ui` | Interactive API documentation (if `server.build.swaggerUI` is enabled) |

此列表并不详尽。要查看所有端点，请运行`mastra dev` and visit `http://localhost:4111/swagger-ui`.

要添加您自己的端点，请参阅[Custom API Routes](/docs/server/custom-api-routes).

## 优雅关闭和滚动部署 {/* #graceful-shutdown-and-rolling-deploys */}

默认情况下，生成的服务器句柄`SIGINT` and `SIGTERM`. It stops accepting connections, waits up to [`server.drainTimeout`](/reference/configuration#serverdraintimeout) for active requests and streams, then runs `mastra.shutdown()`. Shutdown gives in-flight workflow runs (including durable agent runs) the same drain window to finish before workers and pub/sub subscriptions are torn down. A durable agent run still executing after the window stops and releases its claim on the run, so the next boot can recover it right away. The drain timeout defaults to 5 seconds. A second signal terminates the process immediately. See [`server.handleShutdownSignals`](/reference/configuration#serverhandleshutdownsignals) if you need to manage signals yourself.

关闭然后交还Agent线程运行进程仍然保持：

* 仍在执行的运行将被中止，因此它不会启动进一步的步骤。从其他进程观察该线程的客户端会看到它结束，并且不会保存其部分响应。
* 等待Tool批准或暂停的运行将保持暂停状态，并且可以从另一个进程恢复。来自仍在执行的同一步骤的Tool调用将首先中止，就像仍在执行的运行一样。
* 线程租约会立即释放，因此另一个进程可以在该线程上开始运行，而无需等待租约到期。释放是尽力而为的：如果中止的运行没有及时停止（例如，忽略中止的Tool调用），或者租约后端没有应答或释放失败，则租约将保留直到到期。

在耗尽超时后，处理运行返回最多可能需要大约 1.5 秒。

增加`drainTimeout` when your hosting platform's termination grace period can accommodate longer turns. The HTTP drain and the workflow drain run one after the other, so keep enough time for both, plus about 1.5 seconds to hand back thread runs, plus shutdown cleanup.

如果你打电话`mastra.shutdown()` yourself, pass `drainTimeout` to control how long it waits for in-flight workflow runs:

```typescript
await mastra.shutdown({ drainTimeout: 30_000 })
```

```typescript title="src/mastra/index.ts"
import { Mastra } from '@mastra/core/mastra'

export const mastra = new Mastra({
  server: {
    drainTimeout: 240_000,
  },
})
```

一个平原`agent.stream()` call can't resume after its server process exits. If a stream ends without its expected terminal event, treat the turn as interrupted and let the client retry or reconcile it. Use [durable agents](/docs/harness/durable-agents) when turns must survive process replacement. [Crash recovery](/docs/harness/durable-agents#crash-recovery) requires shared persistent run storage and [idempotent tools](/docs/harness/durable-agents#make-tools-safe-to-repeat). Replaying missed events after a restart also requires a shared persistent cache such as Redis because the default event cache is in-memory. Recovering from multiple replicas requires a storage adapter that supports run fencing or a PubSub backend whose lease every replica shares. See [multi-instance deployments](/docs/harness/durable-agents#multi-instance-deployments).

```bash
NODE_OPTIONS="--max-old-space-size=4096" mastra build
```
