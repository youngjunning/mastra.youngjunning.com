# Mastra 服务器

Mastra 会将应用编译为独立的 Node.js 服务器，可在任何支持 Node.js、Bun 或 Deno 的平台上运行。

:::tip

本指南介绍如何部署由 `mastra build` 生成的独立服务器。要将 Mastra 集成到现有的 Express 或 Hono 应用中，请参阅[服务器适配器](/docs/server/server-adapters)。

:::

## 构建应用 {/* #building-your-application */}

在项目根目录运行构建命令：

```bash
mastra build
```

构建会创建 `.mastra` 目录，其中包含可用于生产环境的服务器。所有可用命令选项见 [`mastra build` 参考文档](/reference/cli/mastra#mastra-build)。

## 构建产物 {/* #build-output */}

构建完成后，Mastra 会生成以下目录结构：

```text
.mastra/
├── .build/                # Intermediate build artifacts (module maps, analysis)
└── output/
    ├── index.mjs          # Server entry point
    ├── mastra.mjs         # Your bundled Mastra configuration
    ├── tools.mjs          # Aggregated tool exports
    ├── tools/             # Individual tool bundles
    ├── package.json       # Production dependencies
    ├── node_modules/      # Installed dependencies
    ├── .npmrc             # Copied from your project (if present)
    ├── <static assets>     # Contents of src/mastra/public, merged into the output root
    └── playground/        # Studio UI (if --studio flag used)
```

`output` 目录是自包含的，可以复制到任意服务器上直接运行。

:::warning[请将数据库文件放在 `src/mastra/public` 之外]

构建时会将 `src/mastra/public` 的内容复制到 `.mastra/output`，并覆盖同名文件。因此，放在 `public` 中的 SQLite 数据库会被复制到构建产物中。像 `file:./mastra.db` 这样的 URL 会以服务器的运行目录为基准解析。如果服务器从输出目录运行，它打开的是数据库副本，你对该副本的修改会在下次构建时丢失。请将数据库文件放在 `public` 之外。

:::

## 运行服务器 {/* #running-the-server */}

使用 Mastra CLI 启动服务器：

```bash
mastra start
```

也可以直接用 Node.js 运行：

```bash
node .mastra/output/index.mjs
```

`mastra start` 命令还提供以下功能：

- 从 `.env.production` 和 `.env` 加载环境变量。
- 在缺少模块时提供明确的错误提示。
- 处理进程信号，实现优雅关闭。

所有可用命令选项见 [`mastra start` 参考文档](/reference/cli/mastra#mastra-start)。

## 构建配置 {/* #build-configuration */}

### 构建时配置 {/* #build-time-configuration */}

Mastra 在构建应用时读取 `bundler`、`deployer` 和 `server` 选项。请将它们直接写在传给 `new Mastra()` 的对象上，构建过程才能提取这些选项。

入口文件可以写成如下形式：

```typescript title="src/mastra/index.ts"
import { Mastra } from '@mastra/core/mastra'

export const mastra = new Mastra({
  bundler: {
    externals: ['sharp'],
  },
  server: {
    port: 4111,
  },
})
```

选项的值可以来自变量、导入或函数调用，但选项本身必须是对象的直接属性。请勿通过工厂函数调用或对象展开来间接提供构建时选项：

```typescript title="src/mastra/index.ts"
import { Mastra } from '@mastra/core/mastra'

const options = {
  bundler: {
    externals: ['sharp'],
  },
}

// These patterns prevent Mastra from extracting `bundler` during the build.
export const mastra = new Mastra(createMastraOptions())
export const otherMastra = new Mastra({ ...options })
```

如果 Mastra 无法提取某个选项，构建时会采用该选项的默认行为。可用的 `bundler`、`deployer` 和 `server` 设置见[配置参考](/reference/configuration)。

### 公开资源目录 {/* #public-folder */}

如果 Mastra 目录中有 `public` 文件夹（`src/mastra/public`），构建时会将其中的内容复制到输出目录。服务器会将这些文件作为静态资源提供。

### Mastra 配置 {/* #mastra-configuration */}

构建过程会使用 Mastra 实例中的配置。CORS、超时和中间件等服务器行为见[服务器概览](/docs/server/overview)，完整选项见[配置参考](/reference/configuration)。

## 构建流程 {/* #build-process */}

构建依次执行以下步骤：

1. **定位入口文件**：在 Mastra 目录中查找 `index.ts` 或 `index.js`。
1. **查找 Tool 文件**：扫描匹配 `{mastraDir}/tools/**/*.{js,ts}` 的文件，排除测试文件。
1. **分析依赖**：确定哪些包应打包，哪些应单独安装。
1. **打包代码**：使用 Rollup，启用 tree shaking，并可选择生成 source map。
1. **生成服务器**：将基于 Hono 的 HTTP 服务器生成为 `index.mjs`。
1. **安装依赖**：在输出目录中运行 `npm install`。
1. **复制资源**：如果存在 `public` 文件夹或 `.npmrc`，就将其复制过去。

## 环境变量 {/* #environment-variables */}

| 变量 | 说明 |
| - | - |
| `PORT` | 服务器端口，默认为 `4111`。 |
| `MASTRA_STUDIO_PATH` | Studio 构建目录的路径，默认为 `./playground`。 |
| `MASTRA_SKIP_DOTENV` | 设置后跳过加载 `.env` 文件。 |
| `NODE_OPTIONS` | Node.js 选项，例如构建时遇到内存问题可用 `--max-old-space-size=4096`。 |

## 服务器端点 {/* #server-endpoints */}

构建生成的服务器提供用于健康检查、Agent、Workflow 等功能的端点：

| 端点 | 说明 |
| - | - |
| `GET /health` | 健康检查端点，返回 `200 OK`。 |
| `GET /api/openapi.json` | OpenAPI 规范，启用 `server.build.openAPIDocs` 时提供。 |
| `GET /swagger-ui` | 交互式 API 文档，启用 `server.build.swaggerUI` 时提供。 |

要查看完整的端点列表，请运行 `mastra dev` 并访问 `http://localhost:4111/swagger-ui`。

要添加自己的端点，请参阅[自定义 API 路由](/docs/server/custom-api-routes)。

## 优雅关闭与滚动部署 {/* #graceful-shutdown-and-rolling-deploys */}

生成的服务器默认处理 `SIGINT` 和 `SIGTERM`。它先停止接受新连接，最多等待 [`server.drainTimeout`](/reference/configuration#serverdraintimeout) 指定的时间，让活跃的请求和流处理完毕，再调用 `mastra.shutdown()`。关闭时，正在执行的 Workflow（包括持久化 Agent 运行）也有同样长的等待时间可以完成，随后才会关闭 worker 和发布/订阅订阅项。超时后仍在执行的持久化 Agent 运行会停止并释放对该运行的占用，让服务下次启动时可以立即恢复。默认等待时间为 5 秒。收到第二次信号时，进程立即终止。若要自行处理信号，请参阅 [`server.handleShutdownSignals`](/reference/configuration#serverhandleshutdownsignals)。

然后，关闭流程会交还进程仍持有的 Agent 会话线程运行：

- 仍在执行的运行会被中止，不再启动后续步骤。其他进程中正在监听该会话线程的客户端会看到此次运行结束，其未完成的响应不会保存。
- 正在等待 Tool 审批或已暂停的运行会保持暂停，可从其他进程恢复。若同一步骤仍有 Tool 调用正在执行，会先中止该调用，处理方式与仍在执行的运行相同。
- 系统会立即尝试释放会话线程租约，使其他进程无需等待租约到期即可在该线程上启动运行。如果被中止的运行未及时停止（例如 Tool 调用忽略中止请求），或租约后端未响应或释放失败，租约会保留到期满。

超时后，交还运行最多还可能需要约 1.5 秒。

如果托管平台的终止宽限期允许更长的 Agent 轮次，可以增大 `drainTimeout`。HTTP 和 Workflow 会依次等待结束。请为两段等待、交还会话线程运行所需的约 1.5 秒，以及关闭时的清理预留足够时间。

如果自行调用 `mastra.shutdown()`，可传入 `drainTimeout`，控制它等待进行中的 Workflow 运行结束的时长：

```typescript
await mastra.shutdown({ drainTimeout: 30_000 })
```

```typescript title="src/mastra/index.ts"
import { Mastra } from '@mastra/core/mastra'

export const mastra = new Mastra({
  server: {
    drainTimeout: 240_000,
  },
})
```

普通的 `agent.stream()` 调用在服务器进程退出后无法恢复。如果流结束时未收到预期的终止事件，应将该轮次视为已中断，由客户端重试或协调状态。要让轮次在进程替换后仍可继续，请使用[持久化 Agent](/docs/harness/durable-agents)。[崩溃恢复](/docs/harness/durable-agents#crash-recovery)需要共享的持久化运行存储以及[幂等的 Tool](/docs/harness/durable-agents#make-tools-safe-to-repeat)。默认事件缓存位于内存中，因此要在重启后重放遗漏的事件，还需要 Redis 等共享的持久化缓存。从多个副本恢复时，需要支持运行隔离（run fencing）的存储适配器，或所有副本共享同一租约的 PubSub 后端。参见[多实例部署](/docs/harness/durable-agents#multi-instance-deployments)。

## 故障排查 {/* #troubleshooting */}

### 构建时出现内存错误 {/* #memory-errors-during-build */}

如果遇到 `JavaScript heap out of memory` 错误：

```bash
NODE_OPTIONS="--max-old-space-size=4096" mastra build
```
