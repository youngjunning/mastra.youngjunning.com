# Sandbox

`@mastra/deployer-sandbox` 将包含 Studio 的完整 Mastra 服务器部署到临时的 Workspace Sandbox，并返回可访问的公开 URL。再次部署时，部署器可以跳过安装依赖，因此可能更快完成。

Sandbox 部署适用于：

- Agent 构建的应用：Agent 生成 Mastra 项目并部署，以验证结果。
- 持续集成 (CI)：启动真实服务器完成检查，然后将其销毁。
- 即时预览：合并前与团队分享可运行的 Agent。
- 多租户不可信代码：为每位用户运行与自身基础设施隔离的 Mastra 实例。

Sandbox 有由 Provider 强制执行的运行时长上限，并且会过期。生产环境托管请参阅[部署概览](/docs/deployment/overview)。

## 支持的 Sandbox {/* #supported-sandboxes */}

部署器适用于任何支持联网能力（公开端口 URL）的 Workspace Sandbox：

* [Vercel Sandbox](/integrations/sandboxes/vercel#vercel-sandbox) (`@mastra/vercel`)
* [E2B](/integrations/sandboxes/e2b) (`@mastra/e2b`)
* [Daytona](/integrations/sandboxes/daytona) (`@mastra/daytona`)

Provider 开发者可在 [`WorkspaceSandbox`](/reference/workspace/sandbox) 上实现可选的 `networking` 能力，以提供支持。

## 快速入门 {/* #quickstart */}

安装部署器和所选的 Sandbox Provider。以下示例使用 Vercel Sandbox：

```bash npm2yarn
npm install @mastra/deployer-sandbox @mastra/vercel
```

在 `src/mastra/index.ts` 中配置部署器。`sandboxName` 标识这次部署；后续使用相同名称部署时会复用现有 Sandbox。

```typescript title="src/mastra/index.ts"
import { Mastra } from '@mastra/core/mastra'
import { SandboxDeployer } from '@mastra/deployer-sandbox'
import { VercelSandbox } from '@mastra/vercel'

export const mastra = new Mastra({
  deployer: new SandboxDeployer({
    sandbox: new VercelSandbox({
      sandboxName: 'my-preview',
      timeout: 2_400_000, // 40 minutes
      ports: [4111],
    }),
  }),
})
```

Vercel 有两个附加要求：

- `timeout` 不能超过套餐允许的 Sandbox 最长存活时间；Pro 套餐为 45 分钟。超出后，Vercel API 会返回 400，部署失败。
- 在 `ports` 中声明服务器端口。与 E2B 和 Daytona 不同，Vercel 只开放创建时声明的端口。

在一个命令中构建和部署：

```bash
mastra build
```

配置 `SandboxDeployer()` 后，`mastra build` 会打包项目并部署到 Sandbox。部署过程会输出 API 和 Studio URL，并在 `.mastra/output` 中写入 `sandbox-deployment.json` 清单：

```text
API:    https://<sandbox-id>-4111.vercel.run/api
Studio: https://<sandbox-id>-4111.vercel.run
```

如果 Sandbox Provider 报告了过期时间，清单中会包含 `expiresAt`。

重新部署到同一 Sandbox 时，只要输入未变化，就会跳过安装依赖。输入哈希涵盖 `package.json`、安装命令和打包的锁文件。

### 这些 URL 对应的服务 {/* #what-the-urls-serve */}

Studio URL 是 Sandbox 根地址，不带 `/api`。在浏览器中打开即可使用 Studio。如果部署时设置了 `studio: false`，根地址会改为显示 Mastra 欢迎页面。

API URL 只是其下各端点的前缀，例如 `/api/agents`。`/api` 本身没有处理程序，因此即使服务器正常，在浏览器中打开它也会返回 “Not Found”。

要检查部署，请直接调用端点：

```bash
curl -s -X POST https://4111-<sandbox-id>.e2b.app/api/agents/weatherAgent/generate \
  -H "Content-Type: application/json" \
  -d '{"messages":[{"role":"user","content":"Weather in London"}]}' | jq -r '.text'
```

### Provider 凭据 {/* #provider-credentials */}

每个 Provider 都使用自己的凭据进行身份认证。请设置部署目标 Sandbox 对应的凭据：

```bash title=".env"
# E2B
E2B_API_KEY=

# Daytona
DAYTONA_API_KEY=

# Vercel
VERCEL_TOKEN=
VERCEL_TEAM_ID=
VERCEL_PROJECT_ID=
```

每个 Provider 也接受通过构造函数选项传入这些凭据。自托管的 E2B 和 Daytona 安装分别使用 `E2B_DOMAIN` 或 `DAYTONA_API_URL`。

与 `mastra dev` 不同，`mastra build` 不会加载 `.env` 文件。部署发生在构建过程中，所以从环境变量读取凭据的 Sandbox Provider（例如读取 `E2B_API_KEY` 的 E2B）会读到空值，部署因身份认证错误而失败。

在 `src/mastra/index.ts` 中添加 `import 'dotenv/config'` 无法解决问题。为了找到部署器，构建过程只从入口文件提取 `deployer` 选项，并通过 tree shaking 移除其他内容，包括该导入。

构建前先将 `.env` 文件加载到 shell 环境。可以使用 [`dotenv-cli`](https://www.npmjs.com/package/dotenv-cli)：

```bash npm2yarn
npm install --save-dev dotenv-cli
```

```json title="package.json"
{
  "scripts": {
    "deploy": "dotenv -e .env -- mastra build"
  }
}
```

然后运行 `npm run deploy`。脚本名应反映其部署作用，因为配置了 `SandboxDeployer()` 后，`mastra build` 就会执行部署。请将它与普通的 `build` 脚本分开，避免托管平台或 CI 运行 `npm run build` 时意外部署 Sandbox。

在持续集成 (CI) 中，应将凭据作为 secret 导出。无论采用何种方式，变量都必须存在于 shell 环境，不能只保存在 `.env` 文件中。

上述要求适用于部署器在本机所需的凭据。已部署服务器所需的变量则另行处理：部署器会读取 `.env`、`.env.production` 和 `.env.local`，并将变量注入 Sandbox。参见[安全](#security)。

### 使用E2B {/* #using-e2b */}

在 E2B 中，`id` 用于标识部署。后续使用相同值部署时，会重新连接现有 Sandbox，无论它正在运行还是已暂停。

```typescript title="src/mastra/index.ts"
import { SandboxDeployer } from '@mastra/deployer-sandbox'
import { E2BSandbox } from '@mastra/e2b'

const deployer = new SandboxDeployer({
  sandbox: new E2BSandbox({
    id: 'my-preview',
    template: 'base',
    timeout: 3_600_000, // 1 hour
  }),
})
```

除非需要挂载文件系统，否则应传入 `template: 'base'`；若不传入，Provider 首次使用时会构建自定义的 Filesystem in Userspace (FUSE) 模板。E2B 会暂停而非停止：`stop()` 对整个虚拟机 (VM) 创建快照，包括内存和运行中的进程。暂停的 Sandbox 唤醒后，Mastra 服务器会从暂停处继续，无需像 Vercel 那样重新启动。

### 使用 Daytona {/* #using-daytona */}

在 Daytona 中，`id` 标识部署。后续使用相同值部署时会重新连接现有 Sandbox。设置 `public: true` 可让预览 URL 无须令牌即可访问。

```typescript title="src/mastra/index.ts"
import { SandboxDeployer } from '@mastra/deployer-sandbox'
import { DaytonaSandbox } from '@mastra/daytona'

const deployer = new SandboxDeployer({
  sandbox: new DaytonaSandbox({
    id: 'my-preview',
    public: true,
    autoStopInterval: 30, // minutes
  }),
})
```

停止 Daytona Sandbox 会保留文件系统，但不保留运行中的进程。因此，与 Vercel 类似，使用 `wake: true` 唤醒时，解析器会重新启动服务器。

Daytona 按目标地址过滤出站流量。请求某些主机时，传输层安全协议 (TLS) 连接正常；另一些主机会在握手时重置连接，Agent 或工具中只会看到 Node 的通用错误 `fetch failed`。排查代码前，先在 Sandbox 内对同一主机运行 `curl`，以排除代码问题：

```typescript
const sandbox = new DaytonaSandbox({ id: 'my-preview' })
await sandbox.start()

const result = await sandbox.executeCommand('curl -v --max-time 10 https://api.example.com')
console.info(result.stdout, result.stderr)
```

TLS 握手时出现 `Connection reset by peer`，说明问题指向出站过滤，而非 Agent。可请 Daytona 支持团队放行该目标地址。受限的 Daytona 套餐还会阻止访问云存储端点；挂载辅助函数会为此报告专门的错误。

## 以编程方式部署 {/* #deploying-programmatically */}

`deployToSandbox()` 不经过打包器，直接部署预先构建的输出目录。与 `SandboxDeployer()` 不同，只有传入 `studio: true` 才会包含 Studio。可在 CI 或 Agent 代码中使用：

```typescript
import { deployToSandbox } from '@mastra/deployer-sandbox'
import { VercelSandbox } from '@mastra/vercel'

const deployment = await deployToSandbox({
  sandbox: new VercelSandbox({ sandboxName: 'ci-smoke', ports: [4111] }),
  dir: '.mastra/output',
})

console.info(deployment.url) // https://<sandbox-id>-4111.vercel.run
await deployment.logs() // tail the server log
await deployment.stop() // stop the sandbox (resumable)
await deployment.destroy() // permanently delete the sandbox
```

## 生命周期 {/* #lifecycle */}

### 管理部署 {/* #managing-a-deployment */}

使用 `@mastra/deployer-sandbox/client` 中仅限服务器端的 `getDeployment()` 导出，获取现有部署。它根据 Provider 特定的配置标识 Sandbox，例如 Vercel 的 `sandboxName`，或 E2B、Daytona 的 `id`。查找操作不依赖创建部署的进程，因此可从其他服务器端服务或 CI 中调用。

```typescript title="scripts/stop.ts"
import { getDeployment } from '@mastra/deployer-sandbox/client'
import { VercelSandbox } from '@mastra/vercel'

const deployment = await getDeployment({
  sandbox: new VercelSandbox({ sandboxName: 'my-preview', ports: [4111] }),
  port: 4111,
})

console.info(deployment.status, deployment.url)
await deployment.logs() // tail the server log
await deployment.stop() // stop the sandbox (resumable)
await deployment.destroy() // permanently delete the sandbox
```

传入 `wake: true`，可在返回前恢复已停止的 Sandbox。仅在恢复后服务器不健康时才会重新启动。也可以使用 Provider 工具，例如 `vercel sandbox ls`、`vercel sandbox stop` 和 `vercel sandbox rm`。

### 过期时间和 URL {/* #expiry-and-urls */}

Sandbox 会按 Provider 的运行时长限制过期。如果 Provider 报告了过期时间，部署日志会记录它，也可通过 `deployment.expiresAt` 在程序中读取。

Sandbox 停止并恢复后，URL 可能变化。URL 只是连接地址；Sandbox 身份（例如 `sandboxName`）才是稳定标识。以下路由层级用于应对 URL 轮换。

## 路由层 {/* #routing-tiers */}

### 第 1 层：直接 URL {/* #tier-1-direct-url */}

直接使用打印的 URL 进行开发、演示和 CI，其中每次部署都可以使用新的 URL。

### 第 2 层：运行时解析 {/* #tier-2-resolve-at-runtime */}

`getDeployment()` 在运行时解析当前 URL，使用方就无须保留可能过期的 URL。任何知道 Sandbox 名称的服务器都可以解析 URL，即使它位于不同于 Mastra 项目的代码库中：

```typescript title="app/api/agent-url/route.ts"
import { getDeployment } from '@mastra/deployer-sandbox/client'
import { VercelSandbox } from '@mastra/vercel'

const deployment = await getDeployment({
  sandbox: new VercelSandbox({ sandboxName: 'my-preview', ports: [4111] }),
  wake: true,
})

console.info(deployment.url, deployment.status)
```

使用默认的 `wake: false` 时，不会启动 Sandbox，只返回可供处理的 `{ url, status }`。解析 URL、`stop()` 和 `destroy()` 都会按名称关联现有 Sandbox，不会恢复它；因此，对已停止 Sandbox 执行生命周期操作不会将其唤醒，也不会开始计费。使用 `wake: true` 时，Sandbox 会恢复；若服务器没有响应，则会重新启动。是否需要重启取决于 Provider：Vercel 和 Daytona 会恢复文件系统，但不恢复运行中的进程；E2B 则恢复包含服务器进程在内的整个 VM。

:::warning

`@mastra/deployer-sandbox/client` 仅供服务器端使用。解析 Sandbox 所需的 Provider 凭据绝不能传到浏览器。在浏览器环境中导入此模块会抛出错误。

:::

### 第 3 层：最终用户的稳定 URL {/* #tier-3-stable-url-for-end-users */}

在自己的域名下为最终用户提供稳定 URL，再通过路由处理程序代理或 Edge Config 别名，在服务器端将请求转发到 Sandbox。

下面的示例显示了 Vercel 和 Next.js 设置，但该概念适用于任何可以转发请求的服务器端框架或提供程序。

- **路由处理程序代理。** `createSandboxHandler()` 会缓存 Sandbox URL；发生连接级错误后会重新解析，可应对 URL 轮换和冷启动唤醒：

  ```typescript title="app/api/[...path]/route.ts"
  import { createSandboxHandler, getDeployment } from '@mastra/deployer-sandbox/client'
  import { VercelSandbox } from '@mastra/vercel'

  const handler = createSandboxHandler({
    resolve: async () => {
      const deployment = await getDeployment({
        sandbox: new VercelSandbox({ sandboxName: 'my-preview', ports: [4111] }),
        wake: true,
      })
      return deployment.url!
    },
  })

  export { handler as GET, handler as POST }
  ```

- **Edge Config 别名。** 在部署器上设置 `alias` 选项，使 [Vercel Edge Config](https://vercel.com/docs/edge-config) 中的条目在每次部署后指向当前 URL：

  ```typescript title="src/mastra/index.ts"
  const deployer = new SandboxDeployer({
    sandbox: new VercelSandbox({ sandboxName: 'my-preview', ports: [4111] }),
    alias: { edgeConfigId: 'ecfg_...', key: 'my-preview', token: process.env.VERCEL_TOKEN! },
  })
  ```

  然后在 Next.js 中间件中使用 `createSandboxProxy()` 重写请求：

  ```typescript title="middleware.ts"
  import { createSandboxProxy } from '@mastra/deployer-sandbox/client'

  export const middleware = createSandboxProxy({ key: 'my-preview' })
  export const config = { matcher: '/api/:path*' }
  ```

## 持续集成示例 {/* #ci-example */}

在每个拉取请求上部署预览：

```yaml title=".github/workflows/preview.yml"
name: Sandbox preview
on: pull_request

jobs:
  preview:
    runs-on: ubuntu-latest
    env:
      VERCEL_TOKEN: ${{ secrets.VERCEL_TOKEN }}
      VERCEL_TEAM_ID: ${{ secrets.VERCEL_TEAM_ID }}
      VERCEL_PROJECT_ID: ${{ secrets.VERCEL_PROJECT_ID }}
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-node@v4
        with:
          node-version: 22
      - run: npm ci
      - run: npx mastra build
      - run: curl --fail "$(jq -r .url .mastra/output/sandbox-deployment.json)/api"
```

## 安全 {/* #security */}

- Sandbox URL 是公开的。任何知道该 URL 的人都能访问 Mastra 服务器，包括 Studio。除一次性预览外，都应启用[服务器身份认证](/docs/auth/overview)。
- `.env` 文件中的环境变量会注入远程 Sandbox VM，供服务器运行。发生这种情况时，部署日志会输出警告。不要部署不适合放在共享预览服务器上的密钥。
- 如需限制第 3 层流量，可向 `createSandboxHandler()` 或 `createSandboxProxy()` 传入 `secret`。这些辅助函数会在转发请求的 `x-mastra-sandbox-secret` 标头中附带该值。配置[服务器身份认证](/docs/auth/overview)以强制要求此标头，从而拒绝直接访问 Sandbox URL 的请求，同时允许通过自己域名访问。
