# 部署

Mastra 应用可以部署到任何兼容 Node.js 的环境。你可以部署 Mastra 服务器，也可以将 Mastra 集成到现有 Web 框架。还可以使用云服务商，或使用 [Mastra Platform](/docs/mastra-platform/overview) 获取可观测性服务、部署 Studio 和服务器。

## 支持的运行时 {/* #runtime-support */}

Mastra 支持以下运行环境。

- Node.js `v22.13.0` 或更高版本
- Bun
- Deno
- Cloudflare

## 部署方式 {/* #deployment-options */}

### Mastra 服务器 {/* #mastra-server */}

Mastra 提供基于 Hono 的[服务器](/docs/server/overview)，可以独立部署。使用 `mastra build` 构建应用，再将产物部署到所选的虚拟机、容器或 PaaS 平台。

需要完全掌控基础设施、长期运行的进程或 WebSocket 连接时，请选择此方式。详情见 [Mastra 服务器部署指南](/docs/deployment/mastra-server)。

### Monorepo {/* #monorepo */}

在 Monorepo 中部署 Mastra 服务器时，可沿用独立部署的方法。

参阅 [Monorepo 部署文档](/docs/deployment/monorepo)。

### Mastra Platform {/* #mastra-platform */}

[Mastra Platform](/docs/mastra-platform/overview) 提供三款产品，用于部署、监控和管理基于 Mastra 框架构建的 AI 应用。

- [**Observability**](/docs/mastra-platform/observability)。独立托管服务，用于跨 Mastra 项目和部署搜索 Trace、日志和指标。
- [**Studio**](/docs/mastra-platform/studio)。托管的可视化环境，用于测试 Agent、运行 Workflow 和查看 Trace。
- [**Server**](/docs/mastra-platform/server)。生产部署环境，将 Mastra 应用作为 API 服务器运行。

更多信息见 [Mastra Platform 概览](/docs/mastra-platform/overview)。

### 云服务商 {/* #cloud-providers */}

Mastra 应用可以部署到云服务商和无服务器平台。Mastra 为 Vercel、Netlify 和 Cloudflare 提供可选的内置部署器，可为相应平台构建应用。构建完成后，通过平台本身部署产物。

如果需要自动扩缩容、希望尽量减少基础设施管理工作，或已在使用其中一个平台，可以选择此方式。

### Sandbox {/* #sandbox */}

将 Mastra 服务器部署到临时 Workspace Sandbox（如 Vercel Sandbox 或 E2B），几秒钟内即可获得可公开访问的 URL。

此方式适用于即时预览、从 CI 流水线部署、验证 Agent 构建的应用，或按用户运行不受信任的实例。参阅 [Sandbox 部署指南](/docs/deployment/sandbox)。

### Web 框架 {/* #web-framework */}

与 Web 框架集成后，Mastra 会按该框架的标准流程随应用一起部署。以下指南说明不同框架的部署配置要求。

将 Mastra 加入现有 Next.js 或 Astro 应用时，可参考以下指南。

- [在 Vercel 上使用 Next.js](/docs/deployment/web-framework#with-nextjs-on-vercel)
- [在 Vercel 上使用 Astro](/docs/deployment/web-framework#with-astro-on-vercel)
- [在 Netlify 上使用 Astro](/docs/deployment/web-framework#with-astro-on-netlify)

## Workflow 运行器 {/* #workflow-runners */}

Mastra Workflow 默认使用内置执行引擎。生产负载需要托管基础设施时，也可以将 Workflow 部署到 [Inngest](https://www.inngest.com) 等专用平台，使用步骤结果缓存、自动重试和实时监控。

有关执行选项，请参阅 [Workflow 运行器指南](/docs/deployment/workflow-runners)。配置步骤见 [Inngest 部署指南](/integrations/deploy/inngest)。

## Workers {/* #workers */}

在生产部署中，Mastra 可以将 Workflow 编排、Cron 调度和后台 Tool 执行放在独立于 API 服务器的专用 Worker 进程中。这样可以分别扩缩容并隔离故障。详情见 [Workers](/docs/deployment/workers)。
