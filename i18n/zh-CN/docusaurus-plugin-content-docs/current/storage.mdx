# 贮存

存储是 Mastra 运行时的持久层。它在流程重新启动后保持内存、Workflow状态、Observability数据、评估结果、计划和长期运行的Agent状态可用。

存储能力：

* [记忆](/docs/memory/overview)：消息历史记录、线程、资源和工作内存。
* [Workflow程](/docs/workflows/overview)：用于暂停和恢复Workflow程运行的持久快照。
* [可观察性](/docs/observability/overview)：跟踪、跨度、指标、日志和反馈。
* [埃瓦尔斯](/docs/evals/overview)：分数、数据集、实验和评估结果。
* [长期Agent](/docs/harness/durable-agents)：后台任务、计划、目标和线程状态。

## 何时配置存储 {/* #when-to-configure-storage */}

当状态必须在重新启动后保留或跨进程共享时，配置持久存储适配器。持久存储还可以在 Studio 中跨会话保持状态可见。默认内存存储对于测试和简短的本地实验很有用，但当进程退出时它会丢失数据。

当您的应用程序需要以下任何行为时，请使用存储：

* Agent会记住过去的消息或用户事实。
* Workflow程暂停并在重新启动后恢复。
* 跟踪、指标、日志、分数或反馈可供分析。
* 计划和后台任务在部署中继续进行。
* 多个运行时进程读取和写入相同的状态。

## 存储的工作原理 {/* #how-storage-works */}

Mastra 存储被组织成**domains**. A domain owns one type of runtime data, and a storage adapter implements one or more domains.

|域名 |它存储什么 |
| - | - |
|`memory` | Threads, messages, resources, working memory, and other agent memory state. |
| `workflows` | Workflow snapshots used to suspend and resume runs. |
| `observability` | Traces, spans, metrics, logs, and feedback. |
| `scores` | Eval score records. |
| `datasets` | Dataset records and dataset items used by evals and experiments. |
| `experiments` | Experiment runs and per-item experiment results. |
| `backgroundTasks` | Background task records and execution state. |
| `schedules` | Schedule definitions and trigger history. |
| `threadState` | Durable task, goal, and thread state. |

适配器支持因域而异。有关完整的域列表和内置架构，请参阅[storage overview reference](/reference/storage/overview).

## 按数据形状选择后端 {/* #choose-a-backend-by-data-shape */}

不同的域写入和查询不同类型的数据。根据域的访问模式选择后端：

* `memory`：在每个记住的Agent调用期间读取和写入行。使用事务数据库，例如 libSQL、PostgreSQL 或 MongoDB。
* `observability`：写入大量遥测数据并经常查询聚合。使用专用的Observability存储或在线分析处理 (OLAP) 后端，例如 ClickHouse 或 DuckDB。
* `workflows`：存储恢复运行时必须可用的持久快照。使用可靠的持久数据库。
* `scores`, `datasets`, and `experiments`: Store lower-frequency evaluation data that's often read later for analysis.
* `schedules`：存储时间表定义和火灾历史记录。使用实现计划域的适配器。

当域有不同的操作需求时，使用[composite storage](#composite-storage) to route each domain to the right backend.

## 本地开始 {/* #get-started-locally */}

对于本地开发，请使用 libSQL 和文件支持的数据库。它不需要单独的数据库服务器，并且在重新启动之间保留状态。

```typescript title="src/mastra/index.ts"
import { Mastra } from '@mastra/core'
import { LibSQLStore } from '@mastra/libsql'

export const mastra = new Mastra({
  storage: new LibSQLStore({
    id: 'mastra-storage',
    url: 'file:./mastra.db',
  }),
})
```

:::tip\[与 Studio 共享数据库]

跑步时`mastra dev` alongside your application, use an absolute path so both processes access the same database:

```typescript
url: 'file:/absolute/path/to/your/project/mastra.db'
```

相对路径如`file:./mastra.db` resolve based on each process's working directory, which may differ.

:::

Mastra 在首次使用时初始化所需的存储结构。

## 配置用于生产 {/* #configure-for-production */}

对于生产，请使用持久托管数据库。对于大多数团队来说，PostgreSQL 是一个很好的默认选择，因为它适用于事务运行时状态，并且作为托管服务广泛可用。

生产指导：

* 使用具有备份、监控和连接池功能的托管数据库。
* 保留本地文件数据库，例如`file:./mastra.db` out of multi-process production deployments.
* 路由大容量域，尤其是`observability`, to a dedicated backend with [composite storage](#composite-storage).
* 配置[retention](/reference/storage/retention) policies on the storage adapter or composite store, then call `storage.prune()` from a scheduler or maintenance job.
* 根据您的应用程序使用的域选择Provider。例如，调度需要一个适配器来实现`schedules` domain.

## 配置范围 {/* #configuration-scope */}

可以在 Mastra 实例级别或Agent级别配置存储。

### 实例级存储 {/* #instance-level-storage */}

实例级存储由在同一 Mastra 实例上注册的Agent、Workflow、可观察性、评估、计划和其他运行时功能共享。

<Tabs>
  <TabItem value="postgresql" label="PostgreSQL">
    ```typescript title="src/mastra/index.ts"
    import { Mastra } from '@mastra/core'
    import { PostgresStore } from '@mastra/pg'

    export const mastra = new Mastra({
      storage: new PostgresStore({
        id: 'mastra-storage',
        connectionString: process.env.DATABASE_URL,
      }),
    })
    ```
  </TabItem>

  <TabItem value="mongodb" label="MongoDB">
    ```typescript title="src/mastra/index.ts"
    import { Mastra } from '@mastra/core'
    import { MongoDBStore } from '@mastra/mongodb'

    export const mastra = new Mastra({
      storage: new MongoDBStore({
        id: 'mastra-storage',
        uri: process.env.MONGODB_URI,
        dbName: process.env.MONGODB_DB_NAME,
      }),
    })
    ```
  </TabItem>
</Tabs>

当大多数运行时域可以共享同一数据库时，请使用实例级存储。

### Agent级存储 {/* #agent-level-storage */}

Agent级存储配置在`Memory` instance. It overrides instance-level storage for that agent's memory data only.

```typescript title="src/mastra/agents/support-agent.ts"
import { Agent } from '@mastra/core/agent'
import { Memory } from '@mastra/memory'
import { PostgresStore } from '@mastra/pg'

export const supportAgent = new Agent({
  id: 'support-agent',
  name: 'Support agent',
  instructions: 'Answer customer support questions.',
  model: '__GATEWAY_OPENAI_MODEL__',
  memory: new Memory({
    storage: new PostgresStore({
      id: 'support-agent-storage',
      connectionString: process.env.SUPPORT_AGENT_DATABASE_URL,
    }),
  }),
})
```

当Agent需要隔离的内存边界或不同的内存后端时，请使用Agent级存储。

## 复合存储 {/* #composite-storage */}

[`MastraCompositeStore`](/reference/storage/composite)将域路由到不同的后端。当一个数据库不适合每个域时使用它。

以下示例使用 libSQL 作为默认存储并将Workflow状态路由到 PostgreSQL：

```typescript title="src/mastra/index.ts"
import { Mastra } from '@mastra/core'
import { MastraCompositeStore } from '@mastra/core/storage'
import { LibSQLStore } from '@mastra/libsql'
import { WorkflowsPG } from '@mastra/pg'

export const mastra = new Mastra({
  storage: new MastraCompositeStore({
    id: 'composite-storage',
    default: new LibSQLStore({
      id: 'default-storage',
      url: 'file:./mastra.db',
    }),
    domains: {
      workflows: new WorkflowsPG({
        connectionString: process.env.DATABASE_URL,
      }),
    },
  }),
})
```

您还可以路由`observability` to a dedicated analytics backend. See the [observability quickstart](/docs/observability/overview#quickstart) for an observability-specific example.
