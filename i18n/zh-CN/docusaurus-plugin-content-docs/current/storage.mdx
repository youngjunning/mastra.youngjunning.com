# 存储

存储是 Mastra 运行时的持久化层。进程重启后，记忆、Workflow 状态、可观测性数据、评估结果、调度计划和长时间运行的 Agent 状态仍然可用。

存储为以下功能保留数据：

- [Memory](/docs/memory/overview)：消息历史、线程、资源和工作记忆。
- [Workflow](/docs/workflows/overview)：用于暂停和恢复运行的持久化快照。
- [可观测性](/docs/observability/overview)：Trace、Span、指标、日志和反馈。
- [Evals](/docs/evals/overview)：分数、数据集、实验和评估结果。
- [长时间运行的 Agent](/docs/harness/durable-agents)：后台任务、调度计划、目标和线程状态。

## 何时配置存储 {/* #when-to-configure-storage */}

如果需要在重启后保留状态，或在多个进程间共享状态，请配置持久化存储适配器。这样也能在不同的 Studio 会话中查看同一份状态。默认的内存存储适合测试和短期本地实验，但进程退出后数据会丢失。

如果应用有以下任一需求，请配置存储：

- Agent 记住以往的消息或用户事实。
- Workflow 暂停后能在重启后恢复。
- 保留 Trace、指标、日志、分数或反馈以供分析。
- 调度计划和后台任务在重新部署后仍能继续运行。
- 多个运行时进程读写同一份状态。

## 存储的工作方式 {/* #how-storage-works */}

Mastra 按**域**组织存储。每个域负责一类运行时数据，一个存储适配器可实现一个或多个域。

| 域 | 存储内容 |
| - | - |
| `memory` | 线程、消息、资源、工作记忆及其他 Agent 记忆状态。 |
| `workflows` | 用于暂停和恢复运行的 Workflow 快照。 |
| `observability` | Trace、Span、指标、日志和反馈。 |
| `scores` | 评估分数记录。 |
| `datasets` | 用于评估和实验的数据集记录及数据项。 |
| `experiments` | 实验运行记录和各数据项的实验结果。 |
| `backgroundTasks` | 后台任务记录及执行状态。 |
| `schedules` | 调度计划定义和触发历史。 |
| `threadState` | 持久化的任务、目标及线程状态。 |

适配器支持的域各不相同。完整的域列表及内置模式见[存储参考概览](/reference/storage/overview)。

## 按数据访问模式选择后端 {/* #choose-a-backend-by-data-shape */}

不同域写入和查询的数据类型各不相同。请根据各域的访问模式选择后端：

- `memory`：每次调用启用记忆的 Agent 都会读写数据行。请使用支持事务的数据库，例如 libSQL、PostgreSQL 或 MongoDB。
- `observability`：写入大量遥测数据，且经常执行聚合查询。请使用专用的可观测性存储，或 ClickHouse、DuckDB 等联机分析处理（OLAP）后端。
- `workflows`：保存恢复运行时必须能够读取的持久化快照。请使用可靠的持久化数据库。
- `scores`、`datasets` 和 `experiments`：保存低频写入的评估数据，通常在后续分析时读取。
- `schedules`：保存调度计划定义和触发历史。请使用实现了调度域的适配器。

各域的运行需求不同时，可用[组合存储](#composite-storage)将各域路由到合适的后端。

## 在本地开始使用 {/* #get-started-locally */}

本地开发可以使用基于文件的 libSQL 数据库。它无需单独运行数据库服务器，也能在重启后保留状态。

```typescript title="src/mastra/index.ts"
import { Mastra } from '@mastra/core'
import { LibSQLStore } from '@mastra/libsql'

export const mastra = new Mastra({
  storage: new LibSQLStore({
    id: 'mastra-storage',
    url: 'file:./mastra.db',
  }),
})
```

:::tip[与 Studio 共享数据库]

如果要将 `mastra dev` 与应用一起运行，请使用绝对路径，让两个进程访问同一个数据库：

```typescript
url: 'file:/absolute/path/to/your/project/mastra.db'
```

`file:./mastra.db` 之类的相对路径以各进程的工作目录为基准，而这些目录可能不同。

:::

Mastra 会在首次使用时初始化所需的存储结构。

## 生产环境配置 {/* #configure-for-production */}

在生产环境中，请使用持久化的托管数据库。PostgreSQL 适合大多数团队作为默认选择，因为它能很好地处理需要事务的运行时状态，也有广泛可用的托管服务。

生产环境建议：

- 使用具备备份、监控和连接池的托管数据库。
- 不要在多进程生产部署中使用 `file:./mastra.db` 这类本地文件数据库。
- 用[组合存储](#composite-storage)将数据量大的域（尤其是 `observability`）路由到专用后端。
- 在存储适配器或组合存储中配置[保留](/reference/storage/retention)策略，再通过调度器或维护任务调用 `storage.prune()`。
- 根据应用使用的域选择 Provider。例如，调度计划需要实现 `schedules` 域的适配器。

## 配置范围 {/* #configuration-scope */}

可在 Mastra 实例级或 Agent 级配置存储。

### 实例级存储 {/* #instance-level-storage */}

同一 Mastra 实例上注册的 Agent、Workflow、可观测性、Evals、调度计划和其他运行时功能共用实例级存储。

<Tabs>
  <TabItem value="postgresql" label="PostgreSQL">
    ```typescript title="src/mastra/index.ts"
    import { Mastra } from '@mastra/core'
    import { PostgresStore } from '@mastra/pg'

    export const mastra = new Mastra({
      storage: new PostgresStore({
        id: 'mastra-storage',
        connectionString: process.env.DATABASE_URL,
      }),
    })
    ```
  </TabItem>

  <TabItem value="mongodb" label="MongoDB">
    ```typescript title="src/mastra/index.ts"
    import { Mastra } from '@mastra/core'
    import { MongoDBStore } from '@mastra/mongodb'

    export const mastra = new Mastra({
      storage: new MongoDBStore({
        id: 'mastra-storage',
        uri: process.env.MONGODB_URI,
        dbName: process.env.MONGODB_DB_NAME,
      }),
    })
    ```
  </TabItem>
</Tabs>

当大多数运行时数据域能共用同一个数据库时，请使用实例级存储。

### Agent 级存储 {/* #agent-level-storage */}

Agent 级存储配置在 `Memory` 实例上，仅针对该 Agent 的记忆数据覆盖实例级存储。

```typescript title="src/mastra/agents/support-agent.ts"
import { Agent } from '@mastra/core/agent'
import { Memory } from '@mastra/memory'
import { PostgresStore } from '@mastra/pg'

export const supportAgent = new Agent({
  id: 'support-agent',
  name: 'Support agent',
  instructions: 'Answer customer support questions.',
  model: '__GATEWAY_OPENAI_MODEL__',
  memory: new Memory({
    storage: new PostgresStore({
      id: 'support-agent-storage',
      connectionString: process.env.SUPPORT_AGENT_DATABASE_URL,
    }),
  }),
})
```

如果 Agent 需要隔离记忆数据，或需要使用不同的记忆后端，请使用 Agent 级存储。

## 组合存储 {/* #composite-storage */}

[`MastraCompositeStore`](/reference/storage/composite) 将不同的域路由到不同后端。如果一个数据库无法满足所有域的需求，可使用组合存储。

以下示例使用 libSQL 作为默认存储后端，并将 Workflow 状态存入 PostgreSQL：

```typescript title="src/mastra/index.ts"
import { Mastra } from '@mastra/core'
import { MastraCompositeStore } from '@mastra/core/storage'
import { LibSQLStore } from '@mastra/libsql'
import { WorkflowsPG } from '@mastra/pg'

export const mastra = new Mastra({
  storage: new MastraCompositeStore({
    id: 'composite-storage',
    default: new LibSQLStore({
      id: 'default-storage',
      url: 'file:./mastra.db',
    }),
    domains: {
      workflows: new WorkflowsPG({
        connectionString: process.env.DATABASE_URL,
      }),
    },
  }),
})
```

也可以将 `observability` 路由到专用的分析后端。相关示例见[可观测性快速入门](/docs/observability/overview#quickstart)。
