# 搜索

Agent查找包含以下内容的页面`knowledge_search`，它匹配开箱即用的单词。本页介绍关键字搜索如何查找页面，以及如何按含义添加搜索。

：：：阿尔法

知识处于阿尔法阶段。其 API 可能会在不同版本之间发生变化。

:::

## 搜索如何找到页面 {/* #how-search-finds-pages */}

`knowledge_search`将查询中的单词与页面名称、描述和正文以及注释文本进行匹配。包含更多查询单词的页面排名更高。名称中的一个单词在描述中的作用大于一个，并且描述中的一个单词在正文中的作用大于一个。页面在注释之前。

为了帮助搜索找到页面，请将人们搜索的单词放在其名称和描述中。完整排名顺序请参见[`knowledge_search`](/reference/knowledge/knowledge-tools#knowledge_search).

搜索仅返回运行可以读取的内容。

和`MongoDBStore`, pass `scope` to keep searches fast when runs can read many scopes. A search without `scope` first collects every scope the run can read, so it slows down as that number grows.

## 添加按含义搜索 {/* #add-search-by-meaning */}

通过一个`vector` store and an `embedder` to match pages and notes by meaning as well as by keyword. A search for "reimbursement" then finds a page about getting money back, with no shared word:

```typescript title="src/mastra/knowledge.ts"
import { Knowledge, knowledgeMemoryScopes } from '@mastra/core/knowledge'
import { ModelRouterEmbeddingModel } from '@mastra/core/llm'
import { LibSQLStore, LibSQLVector } from '@mastra/libsql'

export const knowledge = new Knowledge({
  id: 'company',
  storage: new LibSQLStore({ id: 'knowledge', url: 'file:./knowledge.db' }),
  vector: new LibSQLVector({ id: 'knowledge-vector', url: 'file:./knowledge.db' }),
  embedder: new ModelRouterEmbeddingModel('__GATEWAY_OPENAI_EMBEDDING_MODEL__'),
  scopes: { ...knowledgeMemoryScopes() },
  tools: true,
})
```

两者都通过或都不通过。[`embedderOptions`](/reference/knowledge/knowledge-class#constructor-options) works the same way it does in Memory.

`knowledge_search`然后按排名合并关键字和含义结果，因此紧密的含义匹配可以出现在名称匹配之前。每个语义命中都会通过运行的访问权限再次读取，然后才能在结果中占据一席之地，因此运行无法读取的命中将被删除，并且不会占用插槽。与 alpha 中的所有访问检查一样，这并不能保证[isolation boundary](/docs/knowledge/scopes-and-access). Search checks at most 1,000 semantic candidates, though, so when most close matches are unreadable, readable ones further down can be missed.

页面和注释在编写时嵌入。范围页面未嵌入，但其中的注释是嵌入的。长页面被嵌入到各个部分中，搜索仍然会返回每个页面一次。看[Limits](/reference/knowledge/limits) for the sizes.

知识不会嵌入已经存在的内容。添加之前写的页面和注释`vector` and `embedder` stay keyword-only until they change.

避免在已经嵌入内容的商店上切换嵌入器。知识还无法重新嵌入它：

* **不同维度：**&#x641C;索使用新索引，因此现有内容仅包含关键字，直到发生更改。
* **相同尺寸：**&#x641C;索继续使用旧向量并将它们与新模型的查询进行比较，这会给出较差的匹配，直到每个页面发生变化。

### 当嵌入失败时 {/* #when-embedding-fails */}

如果在写入页面或注释时嵌入或矢量写入失败，Knowledge 会在大约半秒、2 秒和 7.5 秒后再次尝试。这涵盖了一个扩展到零并且需要几秒钟才能唤醒的数据库。Provider标记为不可重试的错误（例如错误的 API 密钥）不会再次尝试。

如果每次尝试都失败，写入仍然会成功并且 Mastra 会记录警告。新页面或注释仅保留关键字。更新后的向量会保留其先前的向量，因此意味着搜索与其旧内容相匹配。两者都会持续到再次进行更改为止。一个`upsertPage()` call that comes back `unchanged` writes nothing, so it doesn't embed the page either.

如果嵌入器或向量存储在搜索过程中失败，搜索将返回关键字结果并记录警告。
