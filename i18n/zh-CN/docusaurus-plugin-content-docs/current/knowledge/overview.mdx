# Knowledge

**引入版本：** `@mastra/core@1.82.0`

Knowledge 为 Agent 提供一个共享空间，用来整理不属于单次对话的信息，例如政策、产品文档、约定、操作手册和其他 Agent 总结的经验。Agent 借助 Tool 搜索、读取和写入这些内容。固定的页面会通过 [Signal](/docs/signals/overview) 加入 Agent 的上下文，并在运行时保持最新。

:::alpha

Knowledge 目前处于 Alpha 阶段，API 可能随版本变化。每次调用 Tool 都会检查权限，但当前版本尚不保证不同作用域之间的隔离。绝不能让其他客户或用户看到的信息，请勿存入 Knowledge。当前也没有内置导入工具或保留策略。

:::

## 什么是 Knowledge {/* #what-knowledge-is */}

Knowledge 由页面和笔记组成图结构，并划分为多个作用域。

- **页面**记录一个主题，有名称、简短描述和 Markdown 正文。页面可像目录一样嵌套，例如 `org:acme#policies/refund` 表示在 `org:acme` 作用域中，`policies` 下的 `refund` 页面。
- **笔记**是在页面上补充的简短事实，附有作者信息。用户和 Agent 都可添加笔记，无需改写页面。
- **链接**连接页面。页面正文和笔记可用 `[[org:acme#policies/refund]]` 引用其他页面。阅读页面时，也能看到提到它的笔记。这些链接让 Knowledge 形成一张图，而不是一份文档清单。
- **作用域**是图中独立的一部分，例如 `org:acme` 或 `team:acme:support`。你声明所需的作用域类型，服务器为每次 Agent **运行**指定可用的作用域。
- **角色**决定某次运行在作用域内可做什么：查看者可读取，贡献者可添加页面和笔记，编辑者可修改页面，所有者还可以删除页面及跨作用域移动页面。每次调用 Tool 时，系统按作用域声明中的规则确定角色，无需按用户保存角色。

## 何时使用 Knowledge {/* #when-to-use-knowledge */}

[Memory](/docs/memory/overview) 保存对话内容，让 Agent 能在一个线程中继续工作。Knowledge 保存需要在对话结束后继续使用的信息，供不同线程、Agent 和用户共享。

如果希望 Agent 完成以下任务，可以使用 Knowledge：

- **遵循更新后的规则。** 固定政策页面后，有权读取的 Agent 每轮都能看到它。修改页面后，运行中的 Agent 会在下一轮看到新版本。
- **用同一个 Agent 服务多个客户或团队。** 各客户或团队的页面分属不同作用域，服务器为每次运行传入的作用域决定能读取哪些页面。
- **复用其他 Agent 的经验。** Agent 将决策、惯例和操作手册中的信息记在页面和注明作者的笔记中，供其他 Agent 和用户查找和补充。
- **在 Agent 之间交接任务。** 研究 Agent 写下发现，规划 Agent 在下面补充计划，编程 Agent 从同一作用域读取两者。
- **根据已有内容作答。** 将文档或政策加载到某个作用域，再给 Agent 配置只读 Tool。

## 快速入门 {/* #quickstart */}

创建 Knowledge 实例，声明它使用的作用域类型，再将其附加到 Agent。`tools: true` 会为 Agent 提供搜索、读取和写入页面的工具。用 `KNOWLEDGE_ROUTES` 在 `Mastra` 上注册实例后，就可在 Studio 中浏览内容：

```typescript title="src/mastra/index.ts"
import { Mastra } from '@mastra/core'
import { Agent } from '@mastra/core/agent'
import { Knowledge, knowledgeMemoryScopes } from '@mastra/core/knowledge'
import { LibSQLStore } from '@mastra/libsql'
import { Memory } from '@mastra/memory'
import { KNOWLEDGE_ROUTES } from '@mastra/server/server-adapter'

const storage = new LibSQLStore({ id: 'storage', url: 'file:./mastra.db' })

export const knowledge = new Knowledge({
  id: 'company',
  storage,
  scopes: { ...knowledgeMemoryScopes() },
  tools: true,
})

export const agent = new Agent({
  id: 'assistant',
  name: 'Assistant',
  instructions: 'You help your team and keep its knowledge up to date.',
  model: '__GATEWAY_OPENAI_MODEL__',
  memory: new Memory({ storage }),
  knowledge,
})

export const mastra = new Mastra({
  agents: { agent },
  knowledge: { company: knowledge },
  server: { apiRoutes: [...KNOWLEDGE_ROUTES] },
})
```

`tools` 默认关闭。即使 Agent 接入了 Knowledge，也要启用该选项才能使用工具。Memory 可选：只要每次调用都传入 `scopes`，没有 Memory 也可以使用 Knowledge，但[固定上下文](/docs/knowledge/pinned-context)需要 Memory。

`knowledgeMemoryScopes()` 声明三种作用域：每个组织、每个用户（`resource:`）及每个对话线程（`thread:`）各一个。每次运行都指定自己持有的作用域。以下脚本为同一组织中的 Dana 和 Bea 分别运行 Agent，两人各用自己的线程：

```typescript title="src/try-knowledge.ts"
import { mastra } from './mastra'

const agent = mastra.getAgent('agent')

await agent.generate('Our refund window is 30 days. Save that for the team.', {
  scopes: ['org:acme', 'resource:dana', 'thread:dana-1'],
})

const answer = await agent.generate('How long is our refund window?', {
  scopes: ['org:acme', 'resource:bea', 'thread:bea-1'],
})

console.log(answer.text)
```

`resource:` 和 `thread:` 作用域还会告诉 Memory 对话属于哪个用户和线程。在实际应用中，应由服务器代码为已通过身份验证的用户确定作用域，不能从模型或请求体获取。要为每次请求配置它们，请参阅[设置运行的作用域](/docs/knowledge/scopes-and-access#set-a-runs-scopes)。

处理 Dana 的请求时，Agent 调用 `knowledge_page`，在 `org:acme` 作用域保存页面，并收到类似 `{ "page": { "name": "Refund window", "ref": "org:acme#refunds", "scope": "org:acme", "version": 1 } }` 的结果。处理 Bea 的请求时，Agent 调用 `knowledge_search` 找到 `org:acme#refunds`，再用 `knowledge_read` 读取页面，回答退款期限是 30 天。搜索只返回本次运行可读取的页面，因此持有其他 `org:` 作用域的运行找不到 Acme 的页面。

要查看页面，请运行 `mastra dev`，打开 Studio 并选择 **Knowledge**。Agent 写入的页面会显示在 `org:acme` 作用域中。
