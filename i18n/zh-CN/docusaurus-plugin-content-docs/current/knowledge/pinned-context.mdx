# 固定上下文

固定上下文让选定的 Knowledge 页面保留在 Agent 每轮的上下文中，省去搜索。适合固定长期指令、硬性规则和持久偏好，无论用户是否提及都适用。固定页面每轮都会消耗 token，其他内容可留在普通页面中，让 Agent 按需搜索和读取。

您可以通过两种方式固定页面：

| | 在配置中固定 | 由 Agent 固定 |
| - | - | - |
| 设置方式 | 由你在作用域声明中设置 | 由 Agent 使用固定工具设置 |
| 接收方 | 持有该类型作用域的每次运行 | 持有固定对象所涵盖作用域的每次运行 |
| 预算用尽时 | 始终提供页面，必要时截短 | 列出页面名称，以便 Agent 打开 |
| 移除方式 | 修改声明 | 由 Agent 取消固定 |

无论哪种方式，运行都必须有权读取页面才能收到它。固定操作不会授予页面访问权限。

:::alpha

Knowledge 目前处于 alpha 阶段，API 可能随版本变化。

:::

## 启用固定上下文 {/* #turn-on-pinned-context */}

固定上下文要求 Agent 启用 Memory。在 `Knowledge` 实例上设置 `pinnedContext`：

```typescript title="src/mastra/knowledge.ts"
import { Knowledge, knowledgeMemoryScopes } from '@mastra/core/knowledge'
import { LibSQLStore } from '@mastra/libsql'

export const knowledge = new Knowledge({
  id: 'acme',
  storage: new LibSQLStore({ id: 'knowledge', url: 'file:./mastra.db' }),
  tools: true,
  pinnedContext: { maxTokens: 1000 },
  scopes: {
    ...knowledgeMemoryScopes(),
    // scope declarations, see below
  },
})
```

`pinnedContext: true` 允许每轮最多固定 20 个页面，预算为 500 token。对于上下文窗口较大的模型，可以提高 `maxTokens`。Knowledge 每轮都可以使用全部预算。

固定页面通过[状态信号](/docs/signals/state-signals)提供给 Agent。第一轮会收到所有能放进预算的固定页面，后续轮次只收到变化。如果第一轮快照离开上下文，例如被 Observational Memory 压缩，下一轮会重新收到完整快照。正在运行的 Agent 会在下一轮收到固定页面的修改，提示词缓存也能继续命中。未启用 Memory 的 Agent 不会收到固定页面，并会记录一次警告。

## 在配置中固定页面 {/* #pin-pages-in-config */}

作用域声明中的 `pinnedContext` 列出持有该作用域的每次运行都会收到的页面。此例中，每次以客服角色运行时都会收到所属组织的退款政策：

```typescript title="src/mastra/knowledge.ts" oxfmt:false
scopes: {
  ...knowledgeMemoryScopes(),
  'role:$orgId:support': {
    description: 'Customer support agents',
    pinnedContext: ['policy:$orgId#refund-policy'],
  },
  'policy:$orgId': {
    description: 'Company policies',
    access: [{ principal: 'org:$orgId', role: 'viewer' }],
    pages: [
      { key: 'refund-policy', name: 'Refund Policy', description: 'Refund limits and approvals' },
    ],
  },
},
```

每项都是页面路径，其中的占位符取值于此次运行持有的作用域。持有 `role:acme:support` 的运行会收到 `policy:acme#refund-policy`，持有 `role:globex:support` 的运行会收到 `policy:globex#refund-policy`。运行还必须能读取页面，本例通过 `org:` 作用域取得权限：

| 运行持有的作用域 | 是否收到此固定退款政策 |
| - | - |
| `org:acme`, `role:acme:support` | 会 |
| `org:acme`, `role:acme:sales` | 不会，但可用工具读取该页面 |
| `org:globex`, `role:globex:support` | 不会，收到的是 `policy:globex#refund-policy` |

Knowledge 会在每次运行时查找该路径。请像示例一样，让路径指向目标作用域的 `pages` 中声明的模板页面。工具无法移动模板页面，因此固定设置会持续有效。若页面尚不存在或没有正文，则不会提供内容，也不会报错。此处客服运行只有查看权限，请在服务端调用 [`upsertPage()`](/docs/knowledge/load-your-content) 写入政策正文。

即使超出预算，配置中固定的页面也始终会提供。Agent 无法解除固定。如需移除，请修改声明。

## 让 Agent 固定页面 {/* #let-agents-pin-pages */}

Agent 可在运行时用 [`knowledge_pin`](/reference/knowledge/knowledge-tools#knowledge_pin) 工具固定或取消固定页面。每项固定设置都有一组**接收对象**，即哪些作用域的运行会收到该页面。例如，Agent 可以为 `role:acme:support` 固定退款政策。如果页面移动，Agent 保存的固定设置会随页面更新。

要固定或取消固定页面，运行需要以下两项：

- 在页面所属作用域具有 `editor` 权限。
- 对于接收对象中的每个作用域，运行须持有该作用域，或通过规则取得其 `editor` 权限。

此例中，政策管理员可以为本组织的客服运行固定页面：

```typescript title="src/mastra/knowledge.ts" oxfmt:false
scopes: {
  ...knowledgeMemoryScopes(),
  'role:$orgId:policy-admin': { description: 'Edits company policy' },
  'role:$orgId:support': {
    description: 'Customer support agents',
    access: [{ principal: 'role:$orgId:policy-admin', role: 'editor' }],
  },
  'policy:$orgId': {
    description: 'Company policies',
    access: [
      { principal: 'org:$orgId', role: 'viewer' },
      { principal: 'role:$orgId:policy-admin', role: 'owner' },
    ],
  },
},
```

Acme 的政策管理员可为 `role:acme:support` 固定页面，但不能为 `role:globex:support` 固定。客服运行仍须有权读取页面才能收到它。

角色作用域上的 `editor` 权限也允许运行在该作用域创建页面。如果没有 `self` 规则，任何人都无法读取这些页面。请将页面放在 `policy:` 等内容作用域中，角色作用域仅用来指定接收对象。

## 固定页面列表 {/* #pinned-listings */}

固定列表会把某个作用域或页面下的页面目录放入上下文，格式与 [`knowledge_list`](/reference/knowledge/knowledge-tools#knowledge_list) 的返回值相同，包含各页面的引用、名称和子页面数量。需要让 Agent 知道有哪些页面及其位置时，可以固定列表。例如固定文档站点的栏目清单，Agent 就能用 `knowledge_read` 直接读取所需页面。若每轮都需要页面内容，则固定页面本身。

在作用域的 `pinnedContext` 中添加 `{ list, depth }` 来固定列表。`list` 指定作用域或页面路径，`depth` 指定向下显示的层数，范围为 1 至 3，默认是 1：

```typescript title="src/mastra/knowledge.ts"
import { Knowledge, knowledgeMemoryScopes } from '@mastra/core/knowledge'
import { LibSQLStore } from '@mastra/libsql'

export const knowledge = new Knowledge({
  id: 'docs',
  storage: new LibSQLStore({ id: 'knowledge', url: 'file:./mastra.db' }),
  tools: true,
  pinnedContext: true,
  scopes: {
    ...knowledgeMemoryScopes(),
    'site:$siteId': {
      description: 'A website',
      access: [{ principal: 'self', role: 'viewer' }],
      pinnedContext: [{ list: 'site:$siteId', depth: 1 }],
    },
  },
})
```

持有 `site:mastra` 的每次运行都会收到该列表：

```text
Pages under site:mastra (site:mastra, depth 1):
- site:mastra#docs — Docs (2 children)
- site:mastra#blog — Blog
- site:mastra#pricing — Pricing
```

固定列表遵循与固定页面相同的规则：

- 与 `knowledge_list` 一样，列表仅显示运行有权读取的页面。若无权读取列表所指的作用域或页面，运行不会收到任何内容。
- 当添加、重命名或删除列出的页面时，它会在下一轮更新。
- 列表占用 `maxPins` 的一个名额，并与固定页面共用 `maxTokens` 预算。

列表超出预算时，按层依次填充：先列出第一层能容纳的页面，再列第二层，最多到 `depth` 层。如果有页面未列出，列表末尾会提示 Agent 用 `knowledge_list` 继续查看。默认预算为 500 token，较大的作用域可能只能显示第一层。可以提高 `maxTokens` 来显示更深层的页面。列表上限见[限制](/reference/knowledge/limits)。

Agent 可以在运行时调用 `knowledge_pin` 并传入 `kind: "list"` 来固定列表，所需角色与固定页面相同。上面的 `site:` 运行只有查看权限，因此此调用需要由具备 `site:mastra` 上 `editor` 规则的运行发起：

```json
{ "op": "pin", "kind": "list", "depth": 2, "page": "site:mastra#docs", "audience": ["site:mastra"] }
```

同一个页面可同时固定正文和列表，两者各自固定或取消固定。参数见 [`knowledge_pin`](/reference/knowledge/knowledge-tools#knowledge_pin)。

## 每次运行会收到哪些内容 {/* #what-a-run-receives */}

在每一轮中，Knowledge 都会按以下顺序构建运行的固定上下文：

1. 此次运行持有的所有作用域在配置中固定的页面和列表。如果超出预算，每项按相同的份额截短。
1. Agent 为该次运行持有的任一作用域固定的页面和列表。优先级高的排在前面，同级时较新的在前。配置中已有的条目不会重复。
1. 预算内放不下的固定内容只列名称，Agent 可用读取工具打开。

截短后的页面末尾会提示 Agent 继续读取余下内容。

作用域的 `pinnedContextPriority` 决定其优先级，默认是 `0`。`knowledgeMemoryScopes()` 将 `thread:`、`resource:` 和 `org:` 的优先级分别设为 2、1 和 0，因此单个用户的固定条目排在整个组织的固定条目前面。
