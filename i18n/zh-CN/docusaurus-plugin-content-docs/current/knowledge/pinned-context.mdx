# 固定上下文

固定上下文每次都会将选定的知识页面保留在Agent的上下文中，因此Agent无需搜索它们。将其用于无论是否有人要求都适用的长期指示、严格规则和持久偏好。固定页面每次都会花费代币。将其他所有内容保留在Agent搜索的页面中，并在需要时阅读。

您可以通过两种方式固定页面：

| |固定在配置 |由Agent固定 |
| - | - | - |
|由 | 设置您，在范围声明中 |一个Agent，用图钉Tool|
|交付至 |每次运行都拥有该类型的范围 |每一次在图钉观众中占据一定范围的运行 |
|当预算满的时候 |始终交付，如有需要则缩短 |按名称列出，以便Agent可以打开它 |
|删除者 |更改声明 |特工将其解锁 |

无论哪种方式，只有当运行可以读取页面时，它才会获得固定页面。 PIN 永远不会授予对页面的访问权限。

：：：阿尔法

知识处于阿尔法阶段。其 API 可能会在不同版本之间发生变化。

## 打开固定上下文 {/* #turn-on-pinned-context */}

固定上下文需要Agent上的内存。放`pinnedContext` on the `Knowledge` instance:

```typescript title="src/mastra/knowledge.ts"
import { Knowledge, knowledgeMemoryScopes } from '@mastra/core/knowledge'
import { LibSQLStore } from '@mastra/libsql'

export const knowledge = new Knowledge({
  id: 'acme',
  storage: new LibSQLStore({ id: 'knowledge', url: 'file:./mastra.db' }),
  tools: true,
  pinnedContext: { maxTokens: 1000 },
  scopes: {
    ...knowledgeMemoryScopes(),
    // scope declarations, see below
  },
})
```

`pinnedContext: true`每回合最多允许 20 个固定页面和 500 个令牌。增加`maxTokens` for models with large context windows. Knowledge can use the whole budget on every turn.

固定页面作为Agent到达Agent[state signal](/docs/signals/state-signals). The first turn gets every pinned page that fits the budget, and later turns get only what changed. If that first snapshot leaves the context, for example when Observational Memory compresses it, the next turn gets a full snapshot again. An edit to a pinned page reaches running agents on their next turn, and the prompt cache stays warm. An agent without Memory gets no pinned pages and logs a warning once.

## 在配置中固定页面 {/* #pin-pages-in-config */}

范围声明的`pinnedContext` lists pages that every run holding that scope gets. Here, every support run gets its org's refund policy:

```typescript title="src/mastra/knowledge.ts" oxfmt:false
scopes: {
  ...knowledgeMemoryScopes(),
  'role:$orgId:support': {
    description: 'Customer support agents',
    pinnedContext: ['policy:$orgId#refund-policy'],
  },
  'policy:$orgId': {
    description: 'Company policies',
    access: [{ principal: 'org:$orgId', role: 'viewer' }],
    pages: [
      { key: 'refund-policy', name: 'Refund Policy', description: 'Refund limits and approvals' },
    ],
  },
},
```

每个条目都是一个页面路径。它的占位符从运行所保留的范围中获取它们的值。跑步控股`role:acme:support` gets `policy:acme#refund-policy`, and a run holding `role:globex:support` gets `policy:globex#refund-policy`. The run must also be able to read the page, here through its `org:` scope:

|跑步保持|获取退款政策固定 |
| - | - |
|`org:acme`, `role:acme:support` | Yes |
| `org:acme`, `role:acme:sales` | No, but it can read the page with the tools |
| `org:globex`, `role:globex:support` | No, it gets `policy:globex#refund-policy` instead |

知识在每次跑步时都会查找路径。将其指向目标范围中声明的模板页面`pages`, as in the example. Because tools can't move template pages, the pin keeps working. A pin whose page doesn't exist yet, or has no body, delivers nothing and reports no error. Support runs here are only viewers, so write the policy's body from your server with [`upsertPage()`](/docs/knowledge/load-your-content).

即使超出预算，固定在配置中的页面也始终会交付。特工无法取消它们。要删除一个，请更改声明。

## 让Agent固定页面 {/* #let-agents-pin-pages */}

Agent在运行时使用以下命令固定和取消固定页面[`knowledge_pin`](/reference/knowledge/knowledge-tools#knowledge_pin) tool. Each pin has an **audience**: the scopes whose runs get the page. For example, an agent can pin the refund policy for `role:acme:support`. A pin an agent stores follows its page when the page moves.

要固定或取消固定页面，运行需要以下两项：

* `editor`在页面的范围内。
* 对于观众中的每个范围，要么持有它，要么拥有`editor` on it through a rule.

在这里，政策管理员可以固定页面以在自己的组织中运行支持：

```typescript title="src/mastra/knowledge.ts" oxfmt:false
scopes: {
  ...knowledgeMemoryScopes(),
  'role:$orgId:policy-admin': { description: 'Edits company policy' },
  'role:$orgId:support': {
    description: 'Customer support agents',
    access: [{ principal: 'role:$orgId:policy-admin', role: 'editor' }],
  },
  'policy:$orgId': {
    description: 'Company policies',
    access: [
      { principal: 'org:$orgId', role: 'viewer' },
      { principal: 'role:$orgId:policy-admin', role: 'owner' },
    ],
  },
},
```

Acme 策略管理员可以固定`role:acme:support`, but not for `role:globex:support`. Support runs still need to be able to read the page to get it.

`editor`在角色作用域上还允许运行在那里创建页面，并且没有人可以在没有权限的情况下读取这些页面`self` rule. Keep pages in content scopes such as `policy:`, and use role scopes only as audiences.

## 固定列表 {/* #pinned-listings */}

固定列表将某个范围下的页面或页面放入上下文中，其方式[`knowledge_list`](/reference/knowledge/knowledge-tools#knowledge_list) returns them: each page's ref, name and child count. Pin a listing when the agent needs to know what exists and where, such as the sections of a docs site, so it can go straight to the right page with `knowledge_read`. Pin a page when the agent needs its content on every turn.

将列表添加到范围`pinnedContext` as `{ list, depth }`. `list` names a scope or a page path, and `depth` is how many levels below it to show, from 1 to 3 (default 1):

```typescript title="src/mastra/knowledge.ts"
import { Knowledge, knowledgeMemoryScopes } from '@mastra/core/knowledge'
import { LibSQLStore } from '@mastra/libsql'

export const knowledge = new Knowledge({
  id: 'docs',
  storage: new LibSQLStore({ id: 'knowledge', url: 'file:./mastra.db' }),
  tools: true,
  pinnedContext: true,
  scopes: {
    ...knowledgeMemoryScopes(),
    'site:$siteId': {
      description: 'A website',
      access: [{ principal: 'self', role: 'viewer' }],
      pinnedContext: [{ list: 'site:$siteId', depth: 1 }],
    },
  },
})
```

每次跑步坚持`site:mastra` gets the listing:

```text
Pages under site:mastra (site:mastra, depth 1):
- site:mastra#docs — Docs (2 children)
- site:mastra#blog — Blog
- site:mastra#pricing — Pricing
```

列表遵循与固定页面相同的规则：

* 它只显示运行可以读取的页面，与`knowledge_list`. A run that can't read the listed scope or page gets nothing.
* 当添加、重命名或删除列出的页面时，它会在下一轮更新。
* 它需要一个引脚槽`maxPins` and shares the `maxTokens` budget with pinned pages.

不适合的列表一次填充一个级别：每个适合的第一级页面，然后是第二级页面，一直到`depth`. When pages are left out, it ends with a pointer that tells the agent to continue with `knowledge_list`. With the default 500-token budget, a large scope may show only its first level, so raise `maxTokens` to show deeper levels. See [Limits](/reference/knowledge/limits) for the listing caps.

Agent在运行时固定列表`knowledge_pin` and `kind: "list"`, which needs the same roles as pinning a page. The `site:` runs above are only viewers, so this call needs a run with an `editor` rule on `site:mastra`:

```json
{ "op": "pin", "kind": "list", "depth": 2, "page": "site:mastra#docs", "audience": ["site:mastra"] }
```

页面可以同时具有页面固定和列表固定，并且每个固定和取消固定都是分开的。看[`knowledge_pin`](/reference/knowledge/knowledge-tools#knowledge_pin) for the arguments.

## 跑步收到什么 {/* #what-a-run-receives */}

在每一轮中，Knowledge 都会按以下顺序构建运行的固定上下文：

1. 对于运行所包含的每个范围，页面和列表固定在配置中。如果超出预算，每个人都会缩短到均等份额。
2. 由Agent针对运行所涉及的任何范围固定的页面和列表，首先是最高优先级，然后是最新的。已在配置中的引脚不会重复。
3. 不适合的引脚按名称列出，因此Agent可以使用读取Tool打开它们。

缩短的页面以注释结尾，告诉Agent阅读其余部分。

范围的`pinnedContextPriority` sets its priority, `0` by default. `knowledgeMemoryScopes()` gives `thread:` a priority of 2, `resource:` 1 and `org:` 0, so a pin for one user ranks above a pin for the whole org.
