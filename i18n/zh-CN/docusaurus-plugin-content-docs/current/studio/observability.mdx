# 工作室Observability

Studio 包含以下可观察性视图：

* **指标**用于汇总性能数据
* **痕迹**用于个别请求检查
* **日志**用于浏览内部和应用程序日志

所有这些都需要配置可观察性存储后端。

## 快速入门 {/* #quickstart */}

有关详细说明，请遵循[observability instructions](/docs/observability/overview). To get up and running quickly, add the `@mastra/observability` package to your project and configure it with [LibSQL](/integrations/databases/libsql) and [DuckDB](/integrations/vectors/duckdb) for a local development setup that supports both traces and metrics.

```bash npm2yarn
npm install @mastra/observability @mastra/libsql @mastra/duckdb
```

然后将以下内容添加到您的`src/mastra/index.ts`:

```ts title="src/mastra/index.ts"
import { Mastra } from '@mastra/core/mastra'
import { LibSQLStore } from '@mastra/libsql'
import { DuckDBStore } from '@mastra/duckdb'
import { MastraCompositeStore } from '@mastra/core/storage'
import {
  Observability,
  MastraStorageExporter,
  MastraPlatformExporter,
  SensitiveDataFilter,
} from '@mastra/observability'

export const mastra = new Mastra({
  // highlight-start
  storage: new MastraCompositeStore({
    id: 'composite-storage',
    default: new LibSQLStore({
      id: 'mastra-storage',
      url: 'file:./mastra.db',
    }),
    domains: {
      observability: await new DuckDBStore().getStore('observability'),
    },
  }),
  // highlight-end
  observability: new Observability({
    configs: {
      default: {
        serviceName: 'mastra',
        exporters: [
          new MastraStorageExporter(), // Persists observability events to Mastra Storage
          new MastraPlatformExporter(), // Sends observability events to Mastra platform (if MASTRA_PLATFORM_ACCESS_TOKEN is set)
        ],
        spanOutputProcessors: [
          new SensitiveDataFilter(), // Redacts sensitive data like passwords, tokens, keys
        ],
      },
    },
  }),
})
```

## 指标 {/* #metrics */}

一个仪表板，总结了可配置时间范围（过去 24 小时到 30 天）内的Agent、Workflow程和Tool性能。顶行显示Agent运行总数、模型成本、​​令牌消耗和平均评分器性能。下面，详细的卡片详细列出了模型使用情况和每个模型的成本、每个Agent的令牌使用情况、一段时间内的令牌使用情况和估计成本、已完成和错误计数的跟踪量、延迟百分位数（p50 和 p95）以及随时间变化的记分器趋势。

参观[metrics overview](/docs/observability/metrics/overview) for more details.

：：：笔记

指标需要支持它们的可观察性存储，例如 DuckDB、ClickHouse 或`PostgresStoreVNext` with its observability domain enabled. LibSQL, MSSQL, and MongoDB don't support metrics. In-memory storage resets on restart. See [storage support](/docs/observability/metrics/overview#storage-support) for the full list.

## 痕迹 {/* #traces */}

当您运行Agent或Workflow时，“Observability”选项卡会显示突出显示关键 AI 操作（例如模型调用、Tool执行和Workflow步骤）的跟踪。跟踪这些痕迹可以了解数据如何移动、时间花在哪里以及幕后发生了什么。

在跟踪列表上方，打开**Columns** to show or hide input, entity, duration, input token, output token, estimated cost, and custom metadata columns. Studio saves the selection in browser storage for the current Mastra server and API prefix.

自定义元数据列需要支持跟踪查询的可观察性存储（`queryTraces`), such as the DuckDB observability store in the [quickstart](#quickstart). In **Columns**, select **Add metadata column** and enter the top-level key used in `tracingOptions.metadata`.

对于不支持跟踪查询的存储（例如单独的 LibSQL），Studio 会隐藏**Add metadata column**. Advanced filters, including metadata and tags, are also unavailable. Storing metadata on spans doesn't enable these trace-list features.

令牌和估计成本列需要支持指标的可观察性存储。这些列隐藏在**Branches** view because several branch rows can belong to the same trace.

跟踪会过滤掉低级框架细节，以便您的跟踪保持专注且可读。访问[Traces usage](/docs/observability/tracing/overview) for more details.

要导出轨迹，请选择**Download trace JSON** in the trace panel header. This saves the entire trace as a `trace-<id>.json` file, with every span and its full input, output, metadata, and attributes. Use it to share a trace or attach it to a bug report, or alternatively build an evaluation dataset offline.

## 日志 {/* #logs */}

浏览转发到您的可观察性存储的内部 Mastra 日志。日志提供跨消息内容和实体名称（包括跟踪 ID）的全文搜索。日期预设范围从最近 24 小时到 30 天。多选过滤器涵盖级别和实体类型以及实体名称。选择日志将打开一个详细信息面板，显示完整消息、结构化数据和元数据。如果日志与跟踪相关，您可以直接移动到跟踪和跨度时间线。

配置Observability时，默认启用日志转发。看[logging](/docs/observability/logging) for level configuration, query examples, and customization details.
