# Studio 可观测性

Studio 包含以下可观察性视图：

- **Metrics**：查看汇总性能指标
- **Traces**：查看单次请求的执行情况
- **Logs**：浏览内部日志和应用日志

所有这些都需要配置可观察性存储后端。

## 快速入门 {/* #quickstart */}

详细配置见[可观测性指南](/docs/observability/overview)。如需快速搭建本地开发环境，请添加 `@mastra/observability`，并配置 [LibSQL](/integrations/databases/libsql) 和 [DuckDB](/integrations/vectors/duckdb)，以支持 Trace 和指标。

```bash npm2yarn
npm install @mastra/observability @mastra/libsql @mastra/duckdb
```

然后将以下内容添加到您的`src/mastra/index.ts`:

```ts title="src/mastra/index.ts"
import { Mastra } from '@mastra/core/mastra'
import { LibSQLStore } from '@mastra/libsql'
import { DuckDBStore } from '@mastra/duckdb'
import { MastraCompositeStore } from '@mastra/core/storage'
import {
  Observability,
  MastraStorageExporter,
  MastraPlatformExporter,
  SensitiveDataFilter,
} from '@mastra/observability'

export const mastra = new Mastra({
  // highlight-start
  storage: new MastraCompositeStore({
    id: 'composite-storage',
    default: new LibSQLStore({
      id: 'mastra-storage',
      url: 'file:./mastra.db',
    }),
    domains: {
      observability: await new DuckDBStore().getStore('observability'),
    },
  }),
  // highlight-end
  observability: new Observability({
    configs: {
      default: {
        serviceName: 'mastra',
        exporters: [
          new MastraStorageExporter(), // Persists observability events to Mastra Storage
          new MastraPlatformExporter(), // Sends observability events to Mastra platform (if MASTRA_PLATFORM_ACCESS_TOKEN is set)
        ],
        spanOutputProcessors: [
          new SensitiveDataFilter(), // Redacts sensitive data like passwords, tokens, keys
        ],
      },
    },
  }),
})
```

## 指标 {/* #metrics */}

指标面板汇总 Agent、Workflow 和 Tool 在指定时段内的性能，时间范围可从过去 24 小时调至过去 30 天。顶行显示 Agent 运行总次数、模型成本、Token 用量和评分器的平均表现。下方卡片展示各模型用量和成本、各 Agent 的 Token 用量、随时间变化的 Token 用量和估算成本、Trace 总量及完成和出错次数、延迟百分位数（p50 和 p95）以及评分趋势。

更多细节见[指标概览](/docs/observability/metrics/overview)。

:::note

指标需要支持该功能的可观测性存储，例如 DuckDB、ClickHouse，或已启用可观测性域的 `PostgresStoreVNext`。LibSQL、MSSQL 和 MongoDB 不支持指标。内存存储会在重启时清空。完整列表见[存储支持](/docs/observability/metrics/overview#storage-support)。

:::

## Trace {/* #traces */}

运行 Agent 或 Workflow 时，**Observability** 选项卡会显示 Trace，列出模型调用、Tool 执行和 Workflow 步骤等关键操作。沿着 Trace 可以查看数据流向、各处耗时和实际执行过程。

在 Trace 列表上方打开 **Columns**，可显示或隐藏输入、实体、耗时、输入 Token、输出 Token、估算成本及自定义元数据列。Studio 按当前 Mastra 服务器及 API 前缀将选择保存在浏览器中。

自定义元数据列需要支持 Trace 查询（`queryTraces`）的可观测性存储，例如[快速入门](#quickstart)中的 DuckDB。打开 **Columns**，选择 **Add metadata column**，然后输入 `tracingOptions.metadata` 中使用的顶层键。

存储不支持 Trace 查询时（例如只使用 LibSQL），Studio 会隐藏 **Add metadata column**，也无法使用元数据、标签等高级筛选。将元数据存入 span 并不会开启这些列表功能。

Token 和估算成本列需要支持指标的可观测性存储。由于多行分支可能属于同一个 Trace，**Branches** 视图始终隐藏这些列。

追踪会过滤底层框架细节，让 Trace 更容易阅读。详情见 [Trace 使用指南](/docs/observability/tracing/overview)。

要导出 Trace，请在详情面板顶部选择 **Download trace JSON**。Studio 会把完整 Trace 保存为 `trace-<id>.json`，其中含有每个 span 及其完整输入、输出、元数据和属性。可用该文件分享 Trace、随附在缺陷报告中，或离线构建评估数据集。

## 日志 {/* #logs */}

浏览转发到可观测性存储的 Mastra 内部日志。可全文搜索消息内容、实体名称和 Trace ID。预设时间范围从过去 24 小时到过去 30 天，可按级别、实体类型和实体名称多选筛选。选择一条日志后，详情面板会展示完整消息、结构化数据和元数据。如果日志关联了 Trace，可以直接跳转到该 Trace 及其 span 时间线。

配置可观测性后，系统默认转发日志。日志级别设置、查询示例及自定义方式见[日志指南](/docs/observability/logging)。
