# Studio 身份验证

在 Mastra 服务器上配置 [身份验证](/docs/auth/overview) 后，Studio 会自动显示登录页面并执行访问控制。同一份配置同时保护 Studio 界面和 API 路由。

未配置身份验证时，Studio 和所有 API 路由都可公开访问。

:::note

在生产环境中，使用第三方 Provider 的 Studio 登录页面、基于角色的访问控制（RBAC）和细粒度授权（FGA）需要 Mastra 企业版（EE）许可证。Simple Auth、JWT 和 API 路由的身份验证无需该许可证。开发环境中所有功能均可免许可证使用。参见 [需要 EE 许可证的功能](/docs/license#what-requires-an-ee-license)。如需了解更多，请 [联系销售](https://mastra.ai/contact)。

:::

:::note
部署在 Mastra 平台上的 Studio 使用平台注入的身份验证作为默认设置，只有你的组织成员可以登录。`server.auth` 仅适用于 API 路由。设置 `MASTRA_PLATFORM_STUDIO_AUTH=disabled` 可关闭平台身份验证。参见 [Mastra 平台上的身份验证](/docs/mastra-platform/studio#authentication)。
:::

## 何时使用 Studio 身份验证 {/* #when-to-use-studio-auth */}

* 多位团队成员需要通过同一个 Studio 部署使用 Agent、Workflow 和工具。
* 需要限制哪些人可以执行 Agent、编辑 Workflow 或删除数据集。
* 需要先通过登录页面验证身份，再允许访问 Studio。登录方式可以是 SSO、邮箱和密码，或同时提供两者。

## 快速入门 {/* #quickstart */}

在 Mastra 服务器配置中添加身份验证 Provider。此示例使用 [Simple Auth](/docs/auth/simple-auth) 演示最简配置。

```typescript title="src/mastra/index.ts"
import { Mastra } from '@mastra/core'
import { SimpleAuth } from '@mastra/core/server'

export const mastra = new Mastra({
  server: {
    auth: new SimpleAuth({
      tokens: {
        'my-api-key': {
          id: 'user-1',
          name: 'Alice',
          role: 'admin',
        },
      },
    }),
  },
})
```

配置完成后，Studio 会显示登录页面，所有 API 请求都必须通过身份验证。支持的 Provider 完整列表见 [身份验证文档](/docs/auth/overview)。

## 工作原理 {/* #how-it-works */}

设置 [`server.auth`](/reference/configuration#serverauth) 后，身份验证同时应用于两处。

* **Studio 界面**会显示登录页面。根据 Provider，用户可用 SSO、邮箱和密码登录，或在两种方式中任选其一。
* **API 路由**要求对所有内置路由（例如 `/api/agents/*` 和 `/api/workflows/*`）及自定义路由进行身份验证。无论请求来自 Studio 还是直接调用 API，都适用。

Studio 调用 `GET /api/auth/capabilities` 端点了解可用功能。响应会告诉 Studio 应显示哪些登录方式。如果用户已通过身份验证，响应还会包含用户信息和权限。

## 通过 URL 传递令牌 {/* #pass-a-token-through-the-url */}

其他应用嵌入 Studio 或提供指向 Studio 的链接时，可以通过 URL 参数 `auth_header` 传递授权令牌。外部应用如果已持有令牌，就可以直接打开已验证身份的 Studio 会话，跳过登录页面。

`auth_header` 的值始终写入 `Authorization` 请求头。该参数只设置这一个请求头，请在参数值中包含服务器要求的认证方案前缀，例如 `Bearer`。

打开 Studio 时，将令牌放在 URL 查询字符串中。

```text
https://your-studio-host/?auth_header=Bearer%20your-token
```

Studio 按以下方式处理令牌。

* 加载页面时读取一次 `auth_header`，并在该会话的每个 API 请求中将该值作为 `Authorization` 请求头发送。
* 从地址栏移除 `auth_header`，保留其他查询参数和 URL 片段。
* 仅将令牌保留在内存中，不写入浏览器本地存储。重新加载页面后令牌不会保留。

令牌通过 URL 参数传递，由宿主应用负责生成和传输 URL。浏览器历史记录、来源请求头和服务器访问日志都可能泄露 URL 参数。

## 基于角色的访问控制 {/* #role-based-access-control */}

RBAC 决定每位用户在 Studio 中可以看到什么、执行哪些操作。`server.auth` 负责确认用户身份，`server.rbac` 负责控制用户权限。

### 默认角色 {/* #default-roles */}

Mastra 提供四个默认角色，可从 `@mastra/core/auth/ee` 导入。

| 角色 | 权限 |
| - | - |
| `owner` | 完整权限（`*`） |
| `admin` | 可读取、写入、执行、发布和分享，无删除权限 |
| `member` | 可读取和执行 |
| `viewer` | 只读 |

### 启用 RBAC {/* #enable-rbac */}

使用 `StaticRBACProvider`，可采用默认角色，也可自行定义角色。

```typescript title="src/mastra/index.ts"
import { Mastra } from '@mastra/core'
import { SimpleAuth } from '@mastra/core/server'
import { StaticRBACProvider, DEFAULT_ROLES } from '@mastra/core/auth/ee'

export const mastra = new Mastra({
  server: {
    auth: new SimpleAuth({
      tokens: {
        'admin-key': { id: 'user-1', name: 'Alice', role: 'admin' },
        'viewer-key': { id: 'user-2', name: 'Bob', role: 'viewer' },
      },
    }),
    rbac: new StaticRBACProvider({
      roles: DEFAULT_ROLES,
      getUserRoles: user => [user.role],
    }),
  },
})
```

启用 RBAC 后，Studio 会隐藏用户无权执行的操作。例如，只读用户看不到删除按钮，成员无法修改 Agent 配置。

### 权限格式 {/* #permission-format */}

权限采用 `{resource}:{action}` 格式，可进一步限定到具体资源。

| 格式 | 含义 |
| - | - |
| `*` | 可完全访问所有资源 |
| `*:read` | 可读取所有资源 |
| `agents:*` | 可对 Agent 执行所有操作 |
| `agents:execute` | 仅可执行 Agent |
| `agents:read:my-id` | 可读取指定 ID 的 Agent |

资源包括 `agents`、`workflows`、`tools`、`datasets`、`memory`、`scores`、`observability`、`stored-agents`、`mcp` 等。操作包括 `read`、`write`、`create`、`delete`、`execute`、`publish` 和 `share`。

`mcp:read` 和 `mcp:execute` 控制对 [内置 MCP 服务器](/docs/server/mcp#authentication-and-permissions) 和已注册 `MCPServer` 实例路由的访问。默认的 `viewer` 角色只有 `mcp:read`，所以可以连接，但只会收到空工具列表。每次 MCP 工具调用也需要对应路由的权限，例如 `agents:execute`。

已存储的 Agent 默认仅对所有者可见。`stored-agents:*` 允许用户查看和编辑所有已存储的 Agent。`stored-agents:admin` 跳过所有者检查，但用户仍须具有各路由要求的权限，例如 `stored-agents:read` 或 `stored-agents:write`。默认的 `admin` 角色不含这两项权限。参见 [已存储 Agent 的可见性](/docs/studio/editor#visibility)。

### 映射外部 Provider 的角色 {/* #map-external-provider-roles */}

如果你的身份 Provider 已定义角色，例如 Clerk 组织或 WorkOS 群组，可使用 `roleMapping` 将这些角色映射为 Mastra 权限。

```typescript title="src/mastra/index.ts"
import { StaticRBACProvider } from '@mastra/core/auth/ee'

const rbac = new StaticRBACProvider({
  roleMapping: {
    'org:admin': ['*'],
    'org:member': ['*:read', '*:execute'],
    'org:viewer': ['*:read'],
  },
  getUserRoles: user => user.providerRoles,
})
```

## 登录方式 {/* #login-methods */}

Studio 根据身份验证 Provider 显示对应的登录页面。

| Provider 类型 | 登录界面 |
| - | - |
| 仅 SSO | SSO 按钮（例如“使用 WorkOS 登录”） |
| 仅邮箱和密码 | 邮箱和密码表单 |
| 两种方式 | SSO 按钮和邮箱密码表单 |

可按 Provider 启用或禁用注册。禁用后，Studio 会隐藏注册链接，只允许使用登录表单。
