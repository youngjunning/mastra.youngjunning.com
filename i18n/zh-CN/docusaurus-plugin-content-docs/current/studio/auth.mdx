# 工作室授权

当您配置时[authentication](/docs/auth/overview)在您的 Mastra 服务器上，Studio 会自动显示登录屏幕并强制执行访问控制。一种配置可以保护 Studio UI 和 API 路由的安全。

无需身份验证，Studio 和所有 API 路由均可公开访问。

：：：笔记

在生产中，带有第三方Provider的 Studio 登录屏幕、基于角色的访问控制 (RBAC) 和细粒度授权 (FGA) 需要 Mastra 企业版 (EE) 许可证。简单身份验证、JWT 和 API 路由上的身份验证则不然。每个功能都无需开发许可即可使用。看[what requires an EE license](/docs/license#what-requires-an-ee-license). [Contact sales](https://mastra.ai/contact) for more information.

:::

:::注意
部署在 Mastra 平台上的 Studio 的工作方式有所不同。默认情况下，平台会注入自己的身份验证，因此只有您的组织成员可以登录，并且您的`server.auth` applies to API routes only. Set `MASTRA_PLATFORM_STUDIO_AUTH=disabled` to opt out. See [Authentication on Mastra platform](/docs/mastra-platform/studio#authentication).
:::

## 何时使用 Studio Auth {/* #when-to-use-studio-auth */}

* 多个团队成员需要通过共享 Studio 部署与Agent、Workflow和Tool进行交互。
* 权限必须限制谁可以执行Agent或编辑Workflow，或者删除数据集。
* 登录屏幕（SSO、电子邮件/密码或两者）应控制对 Studio 部署的访问。

## 快速入门 {/* #quickstart */}

将身份验证提供程序添加到您的 Mastra 服务器配置中。本示例使用[Simple Auth](/docs/auth/simple-auth) for a minimal setup:

```typescript title="src/mastra/index.ts"
import { Mastra } from '@mastra/core'
import { SimpleAuth } from '@mastra/core/server'

export const mastra = new Mastra({
  server: {
    auth: new SimpleAuth({
      tokens: {
        'my-api-key': {
          id: 'user-1',
          name: 'Alice',
          role: 'admin',
        },
      },
    }),
  },
})
```

配置完成后，Studio 将显示登录屏幕并要求对所有 API 请求进行身份验证。参观[Auth docs](/docs/auth/overview) for a full list of supported providers.

## 它是如何运作的 {/* #how-it-works */}

环境[`server.auth`](/reference/configuration#serverauth) does two things at once:

* **工作室用户界面**：显示登录屏幕。用户通过 SSO、电子邮件/密码或两者登录，具体取决于Provider。
* **API路线**：需要对所有内置路由进行身份验证（`/api/agents/*`, `/api/workflows/*`, etc.) and custom routes. This applies whether requests come from Studio or direct API calls.

Studio 通过调用来检测可用功能`GET /api/auth/capabilities` endpoint. The response tells Studio which login methods to render and, if the user is already authenticated, includes their user info and permissions.

## 通过 URL 传递令牌 {/* #pass-a-token-through-the-url */}

当另一个应用程序嵌入或链接到 Studio 时，它可以通过`auth_header` URL parameter. This is useful when an external host already holds a token and wants to open an authenticated Studio session without showing the login screen.

这`auth_header` value always populates the `Authorization` request header. The parameter sets that one header only, so include any scheme prefix the server expects in the value, such as `Bearer`.

使用查询字符串中的令牌打开 Studio：

```text
https://your-studio-host/?auth_header=Bearer%20your-token
```

Studio 按如下方式处理令牌：

* 上面写着`auth_header` once on load and sends the value as the `Authorization` header on every API request in that session.
* 它删除了`auth_header` from the address bar while preserving other query parameters and the hash.
* 它将令牌仅保留在内存中，并且从不将其写入本地存储，因此它不会在页面重新加载时持续存在。

令牌包含在 URL 参数中，因此主机应用程序负责如何生成和传输该 URL。 URL 参数可以通过浏览器历史记录和引用标头以及服务器访问日志公开。

## 基于角色的访问控制 {/* #role-based-access-control */}

RBAC 可让您控制每个用户在 Studio 中可以看到的内容和可以执行的操作。它与身份验证分开：`server.auth` handles who the user is, while `server.rbac` handles what they can do.

### 默认角色 {/* #default-roles */}

Mastra 包括四个默认角色。从以下位置导入它们`@mastra/core/auth/ee`:

|角色 |权限 |
| - | - |
|`owner` | Full access (`*`) |
| `admin` | Read, write, execute, publish, and share (no delete) |
| `member` | Read and execute |
| `viewer` | Read-only |

### 启用角色控制 {/* #enable-rbac */}

使用`StaticRBACProvider` with the default roles or define your own:

```typescript title="src/mastra/index.ts"
import { Mastra } from '@mastra/core'
import { SimpleAuth } from '@mastra/core/server'
import { StaticRBACProvider, DEFAULT_ROLES } from '@mastra/core/auth/ee'

export const mastra = new Mastra({
  server: {
    auth: new SimpleAuth({
      tokens: {
        'admin-key': { id: 'user-1', name: 'Alice', role: 'admin' },
        'viewer-key': { id: 'user-2', name: 'Bob', role: 'viewer' },
      },
    }),
    rbac: new StaticRBACProvider({
      roles: DEFAULT_ROLES,
      getUserRoles: user => [user.role],
    }),
  },
})
```

当 RBAC 处于活动状态时，Studio 会隐藏用户无权执行的操作。查看者看不到删除按钮。成员无法修改Agent配置。

### 权限格式 {/* #permission-format */}

权限遵循模式`{resource}:{action}`, with optional resource-level scoping:

|图案|意义|
| - | - |
|`*` | Full access to everything |
| `*:read` | Read all resources |
| `agents:*` | All actions on agents |
| `agents:execute` | Execute agents only |
| `agents:read:my-id` | Read a specific agent by ID |

资源包括`agents`, `workflows`, `tools`, `datasets`, `memory`, `scores`, `observability`, `stored-agents`, `mcp`, and others. Actions are `read`, `write`, `create`, `delete`, `execute`, `publish`, and `share`.

`mcp:read`和`mcp:execute` gate the [built-in MCP server](/docs/server/mcp#authentication-and-permissions) and the routes of `MCPServer` instances you register. The default `viewer` role has `mcp:read` only, so a viewer can connect but gets an empty tool list. Each MCP tool call also needs the permission of the route it runs, such as `agents:execute`.

默认情况下，存储的Agent对其所有者是私有的。`stored-agents:*` lets a user see and edit every stored agent. `stored-agents:admin` lifts the owner check, but the user still needs each route's own permission, such as `stored-agents:read` or `stored-agents:write`. The default `admin` role doesn't include either. See [stored agent visibility](/docs/studio/editor#visibility).

### 映射外部Provider角色 {/* #map-external-provider-roles */}

如果您的身份Provider已定义角色（例如，文员组织或 WorkOS 组），请将它们映射到 Mastra 权限`roleMapping`:

```typescript title="src/mastra/index.ts"
import { StaticRBACProvider } from '@mastra/core/auth/ee'

const rbac = new StaticRBACProvider({
  roleMapping: {
    'org:admin': ['*'],
    'org:member': ['*:read', '*:execute'],
    'org:viewer': ['*:read'],
  },
  getUserRoles: user => user.providerRoles,
})
```

## 登录方式 {/* #login-methods */}

Studio 根据身份验证提供程序调整其登录屏幕：

|Provider类型 |登录界面 |
| - | - |
|仅限单点登录 | SSO 按钮（例如“使用 WorkOS 登录”）|
|仅凭证 |电子邮件和密码表格 |
|两者 | SSO 按钮和电子邮件/密码表单 |

每个Provider都可以启用或禁用注册。禁用后，Studio 会隐藏注册链接并强制使用登录表单。
