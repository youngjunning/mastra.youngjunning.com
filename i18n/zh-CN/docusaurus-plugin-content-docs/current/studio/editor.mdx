# 编辑

Editor 相当于 Mastra Agent 的 CMS。协作者无需访问代码库或编写代码，就能在 Studio 中调整 Agent 的指令和 Tool，并在上线前测试改动。

默认情况下，TypeScript 提供协作者可覆盖的初始值。若将某个字段交由 Editor 管理，Studio 就会独占该字段：请在 Studio 中定义它，并从 Agent 配置中省略。

[部署后的 Studio](/docs/studio/deployment) 让本地开发环境以外的协作者也能使用 Editor。

:::tip[📹 观看]

观看 [Mastra Editor 工作坊](https://www.youtube.com/watch?v=XTjuRoI7t_k\&pp=ygUWbWFzdHJhIGVkaXRvciB3b3Jrc2hvcA%3D%3D)，了解完整操作流程。

:::

## 何时使用编辑器 {/* #when-to-use-editor */}

当 Agent 由代码定义，但负责其行为的协作者不应修改代码库时，使用 Editor。指令或 Tool 经常变化、需要在交付用户前测试时，尤其适合使用。如果每次改动都由开发者负责，并随应用发布 Agent 配置，则应继续[在代码中配置 Agent](/docs/agents/overview)。

如果协作者需要直接在浏览器中创建和管理完全存储的 Agent，而非从代码定义的 Agent 开始，请使用 [Agent Builder](https://agent-builder.mastra.ai)。

## 快速入门 {/* #quickstart */}

安装 `@mastra/editor`。本快速入门使用 LibSQL 保存 Editor 的改动：

```bash npm2yarn
npm install @mastra/editor @mastra/libsql
```

向 `Mastra` 实例添加 `MastraEditor` 和存储。若已有存储，可直接复用，无需添加示例中的 LibSQL 存储。

```typescript title="src/mastra/index.ts"
import { Mastra } from '@mastra/core'
import { MastraEditor } from '@mastra/editor'
import { LibSQLStore } from '@mastra/libsql'

export const mastra = new Mastra({
  agents: {/* existing agents */},
  storage: new LibSQLStore({
    id: 'mastra-storage',
    url: 'file:./mastra.db',
  }),
  editor: new MastraEditor(),
})
```

## 在 Studio 中使用编辑器 {/* #use-editor-in-studio */}

在 [Studio](/docs/studio/overview) 中打开 **Agents**，选择 Agent，再选择 **Editor**。协作者可按该 Agent 的 Editor 权限更新指令和 Tool。

使用数据库存储时，可将改动保存为草稿进行测试，而不影响线上 Agent。准备就绪后再发布草稿。

## 指示 {/* #instructions */}

**Instructions** 区域显示 Agent 的指令。指令留在代码中时（默认），它以代码中的提示词为起点，协作者可覆盖它或添加指令块。若 `editor.instructions` 为 `true`，提示词由 Studio 管理：从代码中省略 `instructions`，并在运行 Agent 前于 Studio 发布一个版本。

指令块可包含当前请求中的值。例如，<code>{'{{userName}}'}</code> 可插入通过[请求上下文](/docs/server/request-context)提供的姓名。[显示条件](/reference/editor/prompt-blocks#display-conditions)可让指令块仅对特定客户、角色或功能开关显示。

### 提示块 {/* #prompt-blocks */}

提示块是保存后可供多个 Agent 使用的指令文本。在 **Prompts** 中创建并发布提示块，然后打开 Agent 的 **Instructions** 区域，选择 **Add block**。

例如，客服、退货和订单状态 Agent 都可能需要相同的退款政策。将政策保存为提示块并添加到各 Agent。政策变化时，只需更新并发布该提示块，无须逐个编辑三个 Agent。

提示块更新后，所有引用其已发布版本的 Agent 都会收到改动。草稿仅用于预览；发布提示块之前，不会影响线上 Agent。

模板语法、条件、版本和 API 详见[提示块参考文档](/reference/editor/prompt-blocks)。

## Tool {/* #tools */}

Tool 让 Agent 能执行操作。协作者可从 Editor 提供的 Tool 中选择，但不能在 Studio 中实现新 Tool。Tool 的来源决定了它如何供选用：

* **项目 Tool** 必须由开发者在 Mastra 项目中实现并注册。
* **集成 Tool** 在开发者注册 Composio 或 Arcade 等 Provider 后可用。协作者随后可浏览 Provider 目录并添加 Tool，无需先在代码中逐一添加。
* **MCP Tool** 在配置 MCP 客户端后可用。有权限的协作者可在 Studio 中创建客户端，再从其服务器公开的 Tool 中选择。

在 Agent 的 **Tools** 区域，协作者可添加所需 Tool，也可为该 Agent 重写某个 Tool 的描述。更具体的描述有助于 Agent 判断何时使用 Tool，而不必修改 Tool 本身。

### 项目Tool {/* #project-tools */}

开发者可在 `Mastra` 实例上注册项目 Tool，使其出现在 Editor 中：

```typescript title="src/mastra/index.ts"
import { Mastra } from '@mastra/core'
import { MastraEditor } from '@mastra/editor'
import { searchOrders } from './tools/search-orders'

export const mastra = new Mastra({
  tools: {
    searchOrders,
  },
  agents: {/* agents */},
  editor: new MastraEditor(),
})
```

Studio 的 Tool 选择器会列出该 Tool。若 Agent 允许编辑 Tool，协作者便可将它添加到 Agent。若 Tool 成员关系仍由代码管理，Agent 的 Editor 视图也会列出代码中已绑定的 Tool。

### 作曲 {/* #composio */}

[Composio](https://composio.dev) 提供 GitHub、Slack、Gmail 等服务的 Tool。使用 Composio API key 注册 Provider，即可在 Editor 中使用其 Tool 目录：

```typescript title="src/mastra/index.ts"
import { Mastra } from '@mastra/core'
import { MastraEditor } from '@mastra/editor'
import { ComposioToolProvider } from '@mastra/editor/composio'

export const mastra = new Mastra({
  agents: {/* agents */},
  editor: new MastraEditor({
    toolProviders: {
      composio: new ComposioToolProvider({
        apiKey: process.env.COMPOSIO_API_KEY!,
      }),
    },
  }),
})
```

Composio Tool ID 的格式如 `GITHUB_CREATE_ISSUE`。默认情况下，选中的 Tool 使用与 Agent 作者关联的连接。若需改用每位调用者自己的连接，请参阅[连接作用域](https://agent-builder.mastra.ai/tool-providers#connection-scope)。

### 拱廊 {/* #arcade */}

[Arcade](https://arcade.dev) 提供另一套内置身份验证的 Tool 目录。使用 Arcade API key 注册：

```typescript title="src/mastra/index.ts"
import { Mastra } from '@mastra/core'
import { MastraEditor } from '@mastra/editor'
import { ArcadeToolProvider } from '@mastra/editor/arcade'

export const mastra = new Mastra({
  agents: {/* agents */},
  editor: new MastraEditor({
    toolProviders: {
      arcade: new ArcadeToolProvider({
        apiKey: process.env.ARCADE_API_KEY!,
      }),
    },
  }),
})
```

Arcade Tool ID 使用 `Toolkit.ToolName` 格式，例如 `Github.GetRepository`。

### MCP 客户 {/* #mcp-clients */}

协作者还可在 Studio 中创建可复用的 MCP 客户端，并将其 Tool 添加到 Agent。已存储的客户端可启动本地 `stdio` 服务器，也可连接远程 HTTP 服务器。Tool 过滤器让每个 Agent 只使用所需的 Tool。

MCP 配置、条件、过滤与解析顺序详见 [Editor Tool 参考文档](/reference/editor/tools)；Provider 选项详见 [`ToolProvider`](/reference/editor/tool-provider)。

## 确定协作者可以编辑的内容 {/* #decide-what-collaborators-can-edit */}

`editor` 字段决定哪些字段由 Studio 管理。省略时，协作者可从代码中的值开始修改 Agent 指令、管理 Tool 及其描述。Agent 的 `id`、`name` 和模型配置仍由代码决定，除非显式启用模型编辑。

```typescript title="src/mastra/agents/support-agent.ts"
import { Agent } from '@mastra/core/agent'
import { searchOrders } from './tools/search-orders'

export const supportAgent = new Agent({
  id: 'support-agent',
  name: 'Support agent',
  instructions: 'Help customers with Acme products.',
  model: '__GATEWAY_OPENAI_MODEL__',
  tools: { searchOrders },
})
```

将字段设为 `true`，即交由 Studio 独占管理；此时须从代码中省略该字段：当 `editor.instructions` 为 `true` 时，TypeScript 会拒绝 `instructions`；当 `editor.tools` 为 `true` 时，会拒绝 `tools`。指令由 Studio 管理的 Agent，在包含指令的版本发布之前会保持不可运行。

```typescript title="src/mastra/agents/support-agent.ts"
import { Agent } from '@mastra/core/agent'
import { searchOrders } from './tools/search-orders'

export const supportAgent = new Agent({
  id: 'support-agent',
  name: 'Support agent',
  model: '__GATEWAY_OPENAI_MODEL__',
  tools: { searchOrders },
  editor: {
    instructions: true,
    tools: {
      description: true,
    },
  },
})
```

这里的指令由 Studio 管理，Tool 成员关系仍由代码管理；协作者只能改进 `searchOrders` 的描述。

| `editor` 的值 | 协作者可更改 | 代码必须提供 |
| - | - | - |
| 省略 | 指令、Tool 及 Tool 描述 | `instructions`；Tool 可选 |
| `false` | 无 | `instructions` |
| `{ instructions: true }` | 指令 | 无需 `instructions`；Tool 可选 |
| `{ tools: true }` | Tool 及其描述 | `instructions`；无需 `tools` |
| `{ tools: { description: true } }` | 代码中已有 Tool 的描述 | `instructions`；需要被描述的 Tool |
| `{ model: true }` | 静态模型回退列表 | 带有不可变条目 ID 的静态回退数组 |

若要在 Studio 中编辑模型，设置 `editor: { model: true }`，并在代码中将 `model` 定义为静态数组。为每个条目指定稳定的 `id`，以便 Editor 将保存的值匹配到代码中的模型设置。Studio 可以调整条目顺序、更改 Provider 和模型，并启用或停用条目。

函数形式的模型配置仍由代码管理，不能在 Studio 中编辑。完整配置见[编辑器覆盖设置](/reference/agents/agent#editor-overrides)。

## 选择更改的存储位置 {/* #choose-where-changes-are-stored */}

Editor 可将改动保存到已配置的数据库，或保存为仓库中的文件。

### 数据库存储 {/* #database-storage */}

默认使用数据库存储。Editor 使用 `Mastra` 实例上配置的存储，因此应用与 Editor 可共用同一后端。

若要为 Editor 数据使用单独的后端，请设置 [`MastraCompositeStore`](/reference/storage/composite#options) 上的 `editor` 选项。未显式指定路由的存储域仍使用其 `default` 存储。

以下示例将应用数据和 Editor 数据保存到不同的 LibSQL 文件：

```typescript title="src/mastra/index.ts"
import { Mastra } from '@mastra/core'
import { MastraCompositeStore } from '@mastra/core/storage'
import { MastraEditor } from '@mastra/editor'
import { LibSQLStore } from '@mastra/libsql'

export const mastra = new Mastra({
  agents: {/* existing agents */},
  storage: new MastraCompositeStore({
    id: 'mastra-storage',
    default: new LibSQLStore({
      id: 'app-storage',
      url: 'file:./mastra.db',
    }),
    editor: new LibSQLStore({
      id: 'editor-storage',
      url: 'file:./editor.db',
    }),
  }),
  editor: new MastraEditor(),
})
```

### 存储库文件 {/* #repository-files */}

使用代码作为来源时，覆盖文件会与应用代码一起保存。开发者可在拉取请求中审查文件，并随应用一起部署：

```typescript title="src/mastra/index.ts"
import { Mastra } from '@mastra/core'
import { MastraEditor } from '@mastra/editor'

export const mastra = new Mastra({
  agents: {/* existing agents */},
  editor: new MastraEditor({
    source: 'code',
    codePath: './mastra/editor',
  }),
})
```

此模式下，每个编辑过的 Agent 都有一个 JSON 覆盖文件。Editor 不会生成 TypeScript，也不会更改创建 Agent 的源码文件。默认情况下，ID 为 `support-agent` 的 Agent 会对应以下文件：

```text
mastra/editor/agents/support-agent.json
```

文件只包含 Editor 管理的部分。例如：

```json title="mastra/editor/agents/support-agent.json"
{
  "instructions": "Help customers with Acme products and answer in their language.",
  "tools": {
    "searchOrders": {
      "description": "Look up an order by its number"
    }
  }
}
```

Agent 的模型、名称及其他由代码管理的字段仍保留在 TypeScript 文件中。Mastra 会读取 JSON，并在 Agent 运行时应用这些值。

协作者在 Studio 保存时，可以将文件写入本地文件系统或下载。接入源码管理后，Studio 还可改为创建拉取请求，再由 Git 提供审查和版本历史。

文件位置和来源选项详见 [`MastraEditor`](/reference/editor/mastra-editor#source)。

## 版本控制 {/* #versioning */}

数据库支持的 Agent 和提示块区分草稿版与已发布版。保存操作会创建草稿，线上 Agent 继续使用已发布版；发布后草稿才会生效。恢复旧版本也会创建草稿，供协作者测试后再发布。

基于代码的 Agent 覆盖设置使用 JSON 文件和 Git 历史记录。

### 选择版本 {/* #select-a-version */}

应用可针对每个请求，通过传入状态（`published` 或 `draft`）或确切的版本 ID 来选择已存储版本：

```typescript title="Version selection"
const publishedAgent = await mastra.getAgentById('support-agent', {
  status: 'published',
})

const draftAgent = await mastra.getAgentById('support-agent', {
  status: 'draft',
})

const versionedAgent = await mastra.getAgentById('support-agent', {
  versionId: 'abc-123',
})
```

版本选择支持：

* 在 A/B 测试中比较两个版本。
* 在向所有人发布之前，先将草稿分发给一个小组。
* 保持发布版本的生产，同时使用最新的草稿。
* 将客户固定到特定版本。

主管 Agent 调用子 Agent 时，也可使用相同的版本控制。开发者可测试子 Agent 草稿，而不影响系统其他部分。

版本选择、子 Agent 行为、REST 端点和 SDK 方法详见 [Editor 版本参考文档](/reference/editor/versioning)。

## 可见性 {/* #visibility */}

配置 [`server.auth`](/docs/auth/overview) 后，每个已存储的 Agent 都有所有者和 `visibility`。在 Studio、通过 `POST /api/stored/agents` 或[内置 MCP 服务器](/docs/server/mcp)创建的 Agent，归创建者所有；除非设置 `visibility: 'public'`，否则默认为 `private`。所有者取自调用者经 `mapUserToResourceId` 映射得到的资源 ID；未配置映射时取其 `id`。未配置 `server.auth`，或调用者两者都没有时，已存储的 Agent 没有所有者，状态为 `public`，所有调用者均可使用。

| 身份 | 可查看及调用私有 Agent | 可编辑或删除 |
| - | - | - |
| 所有者 | 是 | 是 |
| 拥有 `*`、`stored-agents:*` 或 `stored-agents:admin` 的用户 | 是 | 是 |
| 按 Agent ID 获授权的用户，例如 `stored-agents:read:support-agent` 或 `stored-agents:edit:support-agent` | 有 `read` 授权时可以查看；`execute` 授权仅允许调用 | 有 `edit` 或 `delete` 授权时可以 |
| 其他所有人 | 否 | 否 |

此表仅说明所有权规则。每条路由仍会检查自身权限，例如编辑需要 `stored-agents:write`，调用需要 `agents:execute`；因此管理员权限或按 ID 授权还必须配合路由权限。按 ID 授权仅在按该 ID 请求 Agent 时生效，Agent 仍不会出现在这些用户的 `GET /api/agents` 或 `GET /api/stored/agents` 列表中。

`public` Agent 可供所有用户查看和调用，但只有表中的用户可编辑或删除。设置所有者机制之前保存的 Agent 仍对所有人可见，任何拥有路由权限的用户都可编辑或删除它们。代码定义的 Agent 不受影响，包括设置了 Editor 覆盖值的 Agent。

这些规则适用于所有查询 Agent 的路由，而不限于 `/api/stored/agents`。对其他用户而言，私有 Agent 就像不存在：`GET /api/agents` 不会列出它；该 Agent 的详情、版本、Workspace 和调度路由返回 `404`；记忆路由则按 Agent 不存在的情况响应。运行时通过 `POST /api/agents/:agentId/model` 更改模型需要编辑权限。`POST /api/agents/:agentId/clone` 会让调用者成为私有副本的所有者，并忽略请求体中的 `authorId`。

## 程序化访问 {/* #programmatic-access */}

Studio 中的全部功能，也可通过 [`mastra.getEditor()`](/reference/core/getEditor)、REST API 或 Client SDK 以编程方式使用。它们可用于批量更新脚本，或从代码初始化已存储的配置，也能支持根据[评估结果](/docs/evals/experiments)自动调整 Agent。

应用代码能访问 Mastra 实例时，调用 `mastra.getEditor()`：

```typescript title="src/scripts/update-agent.ts"
import { mastra } from '../mastra'

const editor = mastra.getEditor()!

await editor.agent.update({
  id: 'support-agent',
  instructions: 'Help customers with Acme products. Reply in their language.',
})
```

直接调用 `editor.agent.update()` 会把更改后的快照字段保存为新版本，但新版本初始为非活跃草稿。只有显式传入 `status` 或 `activeVersionId` 等记录字段时，该方法才会更改它们。在发布之前，线上 Agent 仍使用此前版本。若要发布，先获取草稿的版本 ID（例如通过 Client SDK 的 `listVersions()`），再显式赋值：

```typescript title="src/scripts/publish-agent.ts"
await editor.agent.update({
  id: 'support-agent',
  status: 'published',
  activeVersionId: versionId,
})
```

已存储 Agent 的 REST API 遵循相同规则。`PATCH /api/stored/agents/support-agent` 默认创建非活跃草稿，除非设置 `autoPublish: true`；`POST /api/stored/agents/support-agent/versions/:versionId/activate` 则发布已有版本。

默认服务器路径前缀为 `/api`。开发者可在服务器配置中自定义前缀。

草稿、发布与恢复的生命周期详见 [Editor 版本参考文档](/reference/editor/versioning)；可用操作详见 [`MastraEditor` 命名空间](/reference/editor/mastra-editor#namespaces)和 [Client SDK Agent API](/reference/client-js/agents#stored-agents)。
