# Studio

Studio 提供交互式界面，用于构建、测试和管理 Agent、Workflow 和工具。开发期间可以在本地运行，也可以添加[身份验证](/docs/studio/auth)，或者[部署到生产环境](/docs/studio/deployment)，让团队管理 Agent、监控性能，并通过内置可观测性功能了解运行情况。

:::tip[📹 观看视频]

观看 [Mastra Studio 概览](https://youtu.be/ojGu6Bi4wYk)，快速了解如何在 Studio 中构建、测试和管理 Agent。

:::

## 启动 Studio {/* #start-studio */}

如果用 `create mastra` 创建了应用，请使用 `dev` 脚本启动开发服务器，也可直接运行 `mastra dev`。

```bash npm2yarn
npm run dev
```

服务器启动后，您可以：

- 在 [`localhost:4111`](http://localhost:4111/) 打开 Studio 界面，与 Agent、Workflow 和工具交互。
- 访问 [`localhost:4111/swagger-ui`](http://localhost:4111/swagger-ui)，查看和试用底层 REST API。

您可以在 Studio 中实时编辑 [Agent](/docs/agents/overview)、[Workflow](/docs/workflows/overview) 以及 Mastra 应用的其他部分。

## 部署 Studio {/* #deploy-studio */}

准备与团队共享 Studio 时，可以使用 [Mastra 平台上的 Studio](/docs/mastra-platform/studio) 或自己的基础设施，将其部署到生产环境。具体做法见[部署文档](/docs/studio/deployment)。

## 基本组件 {/* #primitives */}

### Agent {/* #agents */}

直接和 Agent 对话，切换[模型](/models)，并调整 temperature 和 top-p 等设置，了解它们对输出的影响。

如果目录包含发布日期，模型选择器会在每个 Provider 下优先显示较新的模型。发布日期相同的模型按字母顺序排列。没有日期的模型也按字母顺序排列，并放在有日期的模型之后。

若要让模型选择器只显示来自您自己的[自定义网关](/models/gateways/custom-gateways)的模型，请设置 `AUTO_BLOCK_EXTERNAL_PROVIDERS=true`。参见[在 Studio 中仅显示自定义网关](/models/gateways/custom-gateways#showing-only-custom-gateways-in-studio)。

与 Agent 交互时，可以查看其推理过程和工具调用输出。还可以[查看链路追踪和日志](#observability)，了解回复是如何生成的。

如果回复包含 Markdown 表格，可选择表格上方的 **Copy table as markdown**，只复制表格。复制结果保留 Markdown 格式，并包含表格使用的链接定义和脚注定义。要下载 CSV，请展开复制按钮旁的箭头并选择 **Download CSV**。包含表格的文本片段流式传输并显示完毕后，即可进行这两项操作。此时 Agent 可能仍在运行工具或撰写后续片段。

CSV 只导出单元格中的纯文本。链接保留显示文字，脚注保留标记，URL 和脚注定义不会导出。对于可能被电子表格软件识别为公式的值，导出时会在开头加上单引号，使其按文本处理。普通的带符号数字原样保留。

还可以添加[评分器](#scorers)，持续衡量和比较回复质量。

要针对回复中的一段文字提问，请选中它并选择 **Add to chat**，也可以按 Tab 键把焦点移到该选项。添加的每段文字都会在聊天中显示编号批注气泡，消息框会显示批注数量，例如 **2 annotations**。选择气泡可添加批注或移除该段，也可打开计数列表来定位原文。发送时，Agent 会先收到编号后的段落引文及各自的批注，再收到您输入的文字。也可以只发送批注。如果选区横跨两条消息，则不会显示 **Add to chat**。

在 Agent 流式输出回复时，可以在同一对话中发送后续消息。Studio 会将该消息标为待确认。流确认后，回复会在这条消息下方继续显示。在其他 Studio 标签页中打开同一对话，也可以看到正在进行的流式输出。

通过 [Editor](/docs/studio/editor)，非技术团队成员也可以迭代 Agent、为每次修改保留版本，并在无需重新部署的情况下运行实验。

使用 [Agent Builder](https://agent-builder.mastra.ai) 的独立浏览器界面，创建和管理完全由存储管理的 Agent。

#### 模型面板 {/* #models-panel */}

打开 Agent 的 **Models** 面板，可按优先级查看主模型和备用模型。对于静态模型列表，可以调整模型顺序、启用或禁用备用模型，也可以更改 Provider 或模型。Studio 重新获取 Agent 时会同步面板。

Agent 设置 `editor: { model: true }` 后，这些修改会通过 [Editor](/docs/studio/editor#decide-what-collaborators-can-edit) 保存。这要求同时配置 `MastraEditor` 和 Agent 存储，缺少任何一项都会导致保存失败并返回 HTTP 500。未设置该选项时，修改只影响运行中服务器内存里的 Agent，服务器重启后就会丢失。其他 Agent 的持久化编辑进展见 [GitHub issue #27089](https://github.com/mastra-ai/mastra/issues/27089)。

由函数提供的模型列表可能随请求上下文变化，因此 Studio 将其显示为只读。请在代码中修改动态模型列表。

### Workflow {/* #workflows */}

以流程图查看 Workflow，并用自定义输入逐步执行。运行期间，界面会实时显示当前步骤和已经走过的路径。

Workflow 的链路追踪会显示工具调用、原始 JSON 输出和执行错误。

选择运行按钮旁的 **Run options**，为启动的运行设置 **Resource ID**。Studio 会按 Workflow 记住这个值，可通过 `GET /api/workflows/:workflowId/runs?resourceId=...` 列出 Studio 创建的运行。留空会创建不关联资源的运行。如果服务器从已验证的用户身份获取资源 ID，则以服务器的值为准。

### 处理器 {/* #processors */}

查看每个 Agent 绑定的输入和输出处理器。Agent 详情面板会列出所有处理器的名称和类型，让您在测试前确认防护机制、Token 限制器和自定义处理器是否已正确接入。

配置详情见[处理器](/docs/agents/processors)和[防护机制](/docs/agents/guardrails)。

### MCP 服务器 {/* #mcp-servers */}

可以列出接入 Mastra 实例的 MCP 服务器，并查看它们提供的工具。列表首项是 **Mastra (built-in)**，即位于 `/api/mcp` 的[内置 MCP 服务器](/docs/server/mcp#in-studio)。条目显示端点 URL、是否需要令牌，以及 Claude Code、Cursor、VS Code 和 MCP Inspector 的配置方法。

### 工具 {/* #tools */}

将工具交给 Agent 前，可以单独运行工具来观察和测试其行为。发生问题时，可单独重跑该工具以排查原因。

### Workspace {/* #workspaces */}

使用内置文件浏览器查看 Agent 的 Workspace 文件系统。可以切换挂载点、创建目录，以及查看带语法高亮的文件内容。在可写的 Workspace 中可以创建目录和删除文件，只读 Workspace 会有相应标记。文件树中会显示 Skill。可以从 [skills.sh](https://skills.sh) 安装社区 Skill、更新已安装的 Skill，或删除 Skill 文件夹来移除对应 Skill。

配置详情见 [Workspace](/docs/sandbox/overview)。

### 请求上下文 {/* #request-context */}

通过依赖注入将运行时变量传给 Agent 的指令和工具。可以用 JSON 编辑请求上下文。若 Agent 定义了 `requestContextSchema`，也可以用该 Schema 生成的表单编辑。变量值会在多次测试对话和实验之间保留，无需重启即可触发条件流程。

配置详情见[请求上下文](/docs/server/request-context)。

## 评估 {/* #evaluation */}

### 评分器 {/* #scorers */}

Scorers 标签页会在 Agent 的评分器运行时显示结果。消息经过 Agent 时，已定义的评分器会异步评估每项输出，并在此处显示结果。您可以了解评分器在不同交互中的表现、比较各测试用例的结果，并找出需要改进的地方。

### 数据集 {/* #datasets */}

创建和管理用于评估 Agent 和 Workflow 的测试用例集合。可以从 CSV 或 JSON 导入条目，为输入和标准答案定义 Schema，并固定到指定版本，以便精确复现实验。使用[评分器](/docs/evals/overview)运行实验，可比较提示词、模型或代码变更对质量的影响。

完整的 API 和版本管理说明见[数据集概览](/docs/evals/datasets)。

### 实验 {/* #experiments */}

让数据集的所有条目通过某个 Agent、Workflow 或评分器运行，并集中收集结果。选择目标后，可按需添加评分器并启动。结果视图会显示各条目的输入、输出、状态和评分明细。可并排查看两到十个实验，并与基准比较，衡量提示词、模型或代码变更的影响。

设置详情见[数据集概览](/docs/evals/datasets)。

## 设置 {/* #settings */}

可通过设置页面配置 Studio 与 Mastra 服务器之间的连接。页面包含以下选项：

- **Mastra instance URL**：Mastra 服务器的基础 URL，例如 `http://localhost:4111`。
- **API prefix**：所有 API 请求使用的可选路径前缀，默认为 `/api`。
- **Custom headers**：向每个请求添加键值对，可用于发送身份验证令牌或路由标头。
- **Theme**：切换深色、浅色或跟随系统的主题。

## 在代码中配置 {/* #code-configuration */}

除了[设置](#settings)界面，还可以通过 `src/mastra/index.ts` 中的 [`server`](/reference/configuration#server-options) 选项配置本地开发服务器和 Studio。

Studio 默认运行在 [http://localhost:4111](http://localhost:4111)。可以修改 [`host`](/reference/configuration#serverhost) 和 [`port`](/reference/configuration#serverport)。

Mastra 也支持使用 [`--https`](/reference/cli/mastra#--https) 参数进行 HTTPS 开发，自动为项目创建和管理证书。运行 `mastra dev --https` 时，会为 localhost 或配置的主机名生成私钥和证书。详情见 [HTTPS 参考](/reference/configuration#serverhttps)。
