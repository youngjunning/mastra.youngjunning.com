# 工作室

Studio 提供了一个交互式 UI，用于构建、测试和管理Agent、Workflow程和Tool。开发时本地运行，添加[authentication](/docs/studio/auth)， 或者[部署它](/docs/studio/deployment)到生产，以便您的团队可以管理Agent和监控性能，并通过内置的可观察性获得见解。

:::提示\[📹观看]

手表[Mastra Studio overview](https://youtu.be/ojGu6Bi4wYk) for a short walkthrough of building, testing, and managing agents in Studio.

:::

## 开始工作室 {/* #start-studio */}

如果您使用以下命令创建应用程序`create mastra`, start the development server using the `dev` script. You can also run it directly with `mastra dev`.

```bash npm2yarn
npm run dev
```

服务器运行后，您可以：

* 打开 Studio 用户界面[`localhost:4111`](http://localhost:4111/) to interact with your agents, workflows, and tools.
* 访问[`localhost:4111/swagger-ui`](http://localhost:4111/swagger-ui) to discover and interact with the underlying REST API.

Studio 可让您编辑您的[agents](/docs/agents/overview), [workflows](/docs/workflows/overview), and other parts of your Mastra application in real time.

## 部署工作室 {/* #deploy-studio */}

当您准备好与团队共享 Studio 时，您可以使用以下命令将其部署到生产环境：[Studio on Mastra platform](/docs/mastra-platform/studio) or your own infrastructure. Visit the [deployment docs](/docs/studio/deployment) to learn how.

## 基元 {/* #primitives */}

### Agent商 {/* #agents */}

直接与您的Agent聊天，切换[models](/models), and tweak settings like temperature and top-p to understand how they affect the output.

当目录包含发布日期时，模型选择器首先在每个提供程序中显示较新的版本。具有相同发布日期或没有发布日期的型号均按字母顺序排列。没有日期的型号出现在带日期的型号之后。

将模型选择器限制为您自己的模型[custom gateways](/models/gateways/custom-gateways), set `AUTO_BLOCK_EXTERNAL_PROVIDERS=true`. See [Showing only custom gateways in Studio](/models/gateways/custom-gateways#showing-only-custom-gateways-in-studio).

当您与Agent交互时，您可以遵循其推理并查看Tool调用输出。您还可以[observe](#observability) traces and logs to see how responses are generated.

对于响应中的降价表，请选择**Copy table as markdown** above the table to copy it without the surrounding message. The copied table preserves markdown formatting and includes any link and footnote definitions it uses. To download the table as CSV, open the arrow beside the copy button and select **Download CSV**. Both actions become available once the text segment containing the table finishes streaming and displaying. The agent may still be running tools or writing later segments.

CSV 导出包含纯单元格文本，包括链接标签而不是 URL。脚注标记会被保留，但它们的定义不包含在 CSV 中。可以解释为电子表格公式的值带有前导撇号，因此电子表格应用程序将它们视为文本。保留普通有符号数。

您还可以附上[scorers](#scorers) to measure and compare response quality over time.

要询问部分回复，请选择消息中的文本，然后选择**Add to chat**, or press Tab to reach it from the keyboard. Each passage you add gets a numbered comment bubble in the chat, and the message box counts them, for example **2 annotations**. Select a bubble to write a comment on that passage or remove it, or open the count to find a passage in the chat. When you send, the agent receives a numbered list of the passages, each quoted with its comment, ahead of what you type. You can also send the annotations without typing anything. A selection that spans two messages doesn't offer **Add to chat**.

您可以在Agent响应流期间在同一线程中发送后续消息。 Studio 将消息显示为待处理，直到流确认该消息，然后继续该后续消息下方的响应。打开相同线程的其他 Studio 选项卡可以观察活动流。

使用[Editor](/docs/studio/editor) to let non-technical team members iterate on agents and version every change, plus run experiments without redeploying.

使用[Agent Builder](https://agent-builder.mastra.ai) to create and manage fully stored agents through a separate browser-based interface.

#### 型号面板 {/* #models-panel */}

开通Agent**Models** panel to view its primary model and fallback models in priority order. For static model lists, you can reorder models, enable or disable fallbacks, and change the provider or model. The panel stays synchronized when Studio refetches the agent.

当Agent设置`editor: { model: true }`, these edits are saved through [Editor](/docs/studio/editor#decide-what-collaborators-can-edit). This requires a configured `MastraEditor` and agent storage; without either, saving fails with HTTP 500. Otherwise they change the running server's in-memory agent and are lost when the server restarts. Persistent editing for other agents is tracked in [GitHub issue #27089](https://github.com/mastra-ai/mastra/issues/27089).

函数值模型列表可能因请求上下文而异，因此 Studio 将它们显示为只读。改为在代码中更改动态模型列表。

### Workflow程 {/* #workflows */}

将您的Workflow程可视化为图表，并使用自定义输入逐步运行它。在执行过程中，界面会实时更新以显示活动步骤和所采取的路径。

Workflow程跟踪显示Tool调用和原始 JSON 输出，以及任何执行错误。

选择**Run options** beside the run button to set a **Resource ID** for the runs you start. Studio remembers the value per workflow, and the runs it creates are listed by `GET /api/workflows/:workflowId/runs?resourceId=...`. Leave it empty to create runs without a resource. When your server derives the resource ID from the authenticated user, that value takes precedence over the one you type.

### 处理器 {/* #processors */}

查看连接到每个Agent的输入和输出处理器。Agent详细信息面板按名称和类型列出了每个处理器，因此您可以验证护栏和令牌限制器，并且自定义处理器在测试前是否已正确连接。

看[processors](/docs/agents/processors) and [guardrails](/docs/agents/guardrails) for configuration details.

### MCP服务器 {/* #mcp-servers */}

列出连接到您的 Mastra 实例的 MCP 服务器并探索其可用Tool。该列表开头为**Mastra (built-in)**, the [built-in MCP server](/docs/server/mcp#in-studio) at `/api/mcp`, with its endpoint URL, whether it needs a token, and setup for Claude Code, Cursor, VS Code, and the MCP Inspector.

### Tool {/* #tools */}

在将Tool分配给Agent之前，自行运行Tool来观察行为并对其进行测试。如果出现问题，请单独重新运行Tool来调试问题。

### 工作空间 {/* #workspaces */}

使用内置文件浏览器浏览AgentWorkspace文件系统中的文件。在Workspace挂载之间切换、创建目录以及使用语法突出显示查看文件内容。可写工作空间允许创建目录和删除文件；只读Workspace有相应的标签。技能出现在文件树中。安装社区技能[skills.sh](https://skills.sh), update installed skills, or delete a skill folder to remove that skill.

看[workspaces](/docs/sandbox/overview) for configuration details.

### 请求上下文 {/* #request-context */}

设置通过依赖项注入流入Agent指令和Tool的运行时变量。当您的Agent定义了请求上下文时，将请求上下文编辑为 JSON 或使用架构驱动的表单`requestContextSchema`. Values persist across test chats and experiments, so you can trigger conditional flows without restarting.

看[request context](/docs/server/request-context) for configuration details.

## 评估 {/* #evaluation */}

### 得分手 {/* #scorers */}

记分员选项卡显示Agent记分员运行时的结果。当消息通过Agent时，定义的记分器会异步评估每个输出并在此处呈现其结果。您可以了解评分员如何响应不同的交互并比较测试用例的性能，并确定需要改进的领域。

### 数据集 {/* #datasets */}

创建和管理测试用例集合以评估您的Agent和Workflow程。从 CSV 或 JSON 导入项目并定义输入和真实模式，并固定到特定版本，以便您可以准确地重现实验。运行实验[scorers](/docs/evals/overview) to compare quality across prompts, models, or code changes.

看[datasets overview](/docs/evals/datasets) for the full API and versioning details.

### 实验 {/* #experiments */}

针对Agent、Workflow或记分器运行数据集中的所有项目，并将结果收集到一处。选择一个目标，可选择附加记分器，然后触发实验。结果视图显示每个项目的输入、输出、状态和个人分数细分。将两到十个实验与基线并排比较，以衡量提示、模型或代码更改的影响。

看[datasets overview](/docs/evals/datasets) for setup details.

## 设置 {/* #settings */}

配置 Studio 和 Mastra 服务器之间的连接。设置页面包括：

* **Mastra 实例 URL**：Mastra 服务器的基本 URL（例如`http://localhost:4111`).
* **API前缀**：所有 API 请求的可选路径前缀（默认为`/api`).
* **自定义标头**：添加随每个请求发送的键值对，对于身份验证令牌或路由标头很有用。
* **主题**：在深色、浅色或系统主题之间切换。

## 代码配置 {/* #code-configuration */}

除了[settings](#settings) UI, you can configure the local development server and Studio also through the [`server`](/reference/configuration#server-options) option in your `src/mastra/index.ts`.

默认情况下，Studio 运行于[http://localhost:4111](http://localhost:4111). You can change the [`host`](/reference/configuration#serverhost) and [`port`](/reference/configuration#serverport).

Mastra 还通过以下方式支持 HTTPS 开发[`--https`](/reference/cli/mastra#--https) flag, which automatically creates and manages certificates for your project. When you run `mastra dev --https`, a private key and certificate are generated for localhost (or your configured host). Visit the [HTTPS reference](/reference/configuration#serverhttps) to learn more.
