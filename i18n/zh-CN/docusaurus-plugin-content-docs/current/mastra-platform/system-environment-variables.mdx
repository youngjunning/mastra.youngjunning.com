# 系统环境变量

Mastra 平台会在每次部署中注入一组环境变量。它们保存代码运行所在的项目和环境的标识、代码运行的区域以及任何[hosted database](/docs/mastra-platform/database)附于其上。

您可以像读取任何其他变量一样读取它们：

```ts
const environmentName = process.env.MASTRA_ENVIRONMENT_NAME
```

系统变量被保留。使用这些名称之一存储的变量将保留在项目或环境记录中，但永远不会到达运行时，因为平台的值是最后应用的。

## 项目和环境变量 {/* #project-and-environment-variables */}

每次部署时注入。

|变量|价值|
| - | - |
|`MASTRA_PROJECT_ID` | ID of the project being deployed |
| `MASTRA_ENVIRONMENT_ID` | ID of the environment. Stable across renames |
| `MASTRA_ENVIRONMENT_NAME` | Name of the environment, such as `production` |
| `MASTRA_ENVIRONMENT_SLUG`|环境的路由slug |
|`MASTRA_PLATFORM_REGION`|环境运行的区域，`US`或者`EU` |
| `MASTRA_PLATFORM_ACCESS_TOKEN`|部署用于调用平台 API 的令牌，包括可观察性 |
|`MASTRA_PLATFORM_BUCKET_NAME`|支持环境的水桶[Workspace](/docs/mastra-platform/workspaces)。启用Workspace时设置 |
|`MASTRA_WORKERS`|设置为`false`当项目声明工作人员时在主服务上运行，因此它们仅在自己的服务中运行 |

## 托管数据库变量 {/* #managed-database-variables */}

附加托管数据库会将其连接变量添加到数据库覆盖的环境中。每个Provider的名称都是固定的。

|Provider|变量|
| - | - |
|图尔索 |`TURSO_DATABASE_URL`, `TURSO_AUTH_TOKEN` |
| Neon | `DATABASE_URL` |
| Postgres | `DATABASE_URL` |
| Redis | `REDIS_URL` |

尚未为每个组织启用托管 Redis。当您的组织关闭时，Redis 不会显示为数据库选项，并且附加它会失败。

值在部署时解析，并且永远不会存储在您的项目中。环境范围的数据库替换该环境的同一提供程序的项目范围的数据库的值。

## 优先级 {/* #precedence */}

部署按此顺序解析变量，最后一个获胜：

1. 您存储在正在部署的环境中的变量。其他环境的变量永远不会被读取。项目仍在进行中[legacy pipeline](/docs/mastra-platform/deploy#migrating-from-server-and-studio-deploys) use the variables stored on the project instead.
2. 该环境的托管数据库变量。
3. 平台变量。

系统值最后应用，因此它们在名称冲突中获胜。您的存储值保留在记录中并继续显示在仪表板中，但正在运行的服务永远看不到它。 “环境变量”页面用警告图标标记这些行，以便您可以知道哪些值被隐藏。

附加到单个环境的数据库会隐藏同一提供者的项目范围数据库，但仅限于该环境内部。要将一个环境指向不同的数据库，请附加一个[environment-scoped database](/docs/mastra-platform/database#attach-with-the-cli) rather than overwriting the connection variable by hand.

要查看环境运行的内容，请将其变量拉入本地文件：

```bash
mastra env vars pull staging --output .env.staging
```

托管值不会写入文件。它们仅显示为名称注释。
