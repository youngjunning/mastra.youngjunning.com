# 系统环境变量

Mastra 平台在每次部署时都会注入一组环境变量，其中包含代码所在的项目和环境的标识、运行区域，以及所关联的各个[托管数据库](/docs/mastra-platform/database)的连接凭据。

这些变量的读取方式与其他环境变量相同：

```ts
const environmentName = process.env.MASTRA_ENVIRONMENT_NAME
```

系统变量名是保留名称。即使在项目或环境中保存了同名变量，运行时也不会收到该值，因为平台的值最后应用。

## 项目和环境变量 {/* #project-and-environment-variables */}

每次部署时都会注入以下变量。

| 变量 | 值 |
| - | - |
| `MASTRA_PROJECT_ID` | 正在部署的项目 ID |
| `MASTRA_ENVIRONMENT_ID` | 环境 ID，重命名后保持不变 |
| `MASTRA_ENVIRONMENT_NAME` | 环境名称，例如 `production` |
| `MASTRA_ENVIRONMENT_SLUG` | 环境的路由 slug |
| `MASTRA_PLATFORM_REGION` | 环境运行的区域，`US` 或 `EU` |
| `MASTRA_PLATFORM_ACCESS_TOKEN` | 部署实例调用平台 API 所用的令牌，包括可观测性 API |
| `MASTRA_PLATFORM_BUCKET_NAME` | 为环境的 [Workspace](/docs/mastra-platform/workspaces) 提供存储的存储桶，启用 Workspace 时设置 |
| `MASTRA_WORKERS` | 项目声明了 Worker 时，主服务中的值设为 `false`，使 Worker 只在自己的服务中运行 |

## 托管数据库变量 {/* #managed-database-variables */}

关联托管数据库时，平台会将连接变量添加到该数据库覆盖的环境中。各数据库提供方都有固定的变量名。

| 提供方 | 变量 |
| - | - |
| Turso | `TURSO_DATABASE_URL`, `TURSO_AUTH_TOKEN` |
| Neon | `DATABASE_URL` |
| Postgres | `DATABASE_URL` |
| Redis | `REDIS_URL` |

部分组织尚未启用托管 Redis。如果你的组织未启用，Redis 不会出现在数据库选项中，尝试关联也会失败。

变量值在部署时解析，不会存储在项目中。对于同一数据库提供方，环境级数据库的变量值会在对应环境中覆盖项目级数据库的值。

## 优先级 {/* #precedence */}

部署时按以下顺序解析变量。同名时，后应用的值优先：

1. 保存在当前部署环境中的变量。平台不会读取其他环境的变量。仍使用[旧版部署流水线](/docs/mastra-platform/deploy#migrating-from-server-and-studio-deploys)的项目会改用项目中保存的变量。
1. 当前环境的托管数据库变量。
1. 平台变量。

系统值最后应用，因此会覆盖同名变量。原先保存的值仍保留在记录中，也会继续显示在控制台，但运行中的服务不会收到这些值。环境变量页面会用警告图标标出哪些值已被覆盖。

如果单独为某个环境关联了数据库，它只会在该环境中覆盖同一提供方的项目级数据库。如需让某个环境使用不同的数据库，请关联[环境级数据库](/docs/mastra-platform/database#attach-with-the-cli)，不要手动覆盖连接变量。

要查看环境运行时使用哪些变量，可将其变量拉取到本地文件：

```bash
mastra env vars pull staging --output .env.staging
```

文件中不会写入托管变量的值，只会以注释列出变量名。
