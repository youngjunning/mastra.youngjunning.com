# 地区

区域控制平台环境的运行位置、平台环境的位置[hosted database](/docs/mastra-platform/database)放置，以及其Observability数据的存储位置。该区域在创建环境时是固定的，以后无法更改。

Mastra 平台目前提供两个居住区，`us` and `eu`，由 Railway 上的特定计算区域支持。数据库和可观察性自动遵循环境区域。

## 选择地区 {/* #choose-a-region */}

经过`--region` when creating or first deploying to an environment:

```bash
mastra deploy --env production --region eu
mastra env create staging --region us
```

两个都`mastra deploy --region` and `mastra env create --region` accept either the `us` / `eu`下表中的简写或规范铁路区域代码。推荐的形式是简写形式。

不传递region时默认为`us`, which resolves to `pdx` (Portland, Oregon).

## 可用地区 {/* #available-regions */}

居住选择器提供跨越两个区域的四个铁路区域。`us` and `eu` shorthand resolve to the underlined default in each zone.

|专区 |铁路代码|地点 |
| - | - | - |
|`us` | `pdx` (default) | Portland, Oregon |
| `us` | `iad` | Ashburn, Virginia |
| `us` | `sfo` | San Francisco, California |
| `eu` | `ams`（默认）|荷兰阿姆斯特丹 |

当您需要将环境固定到特定数据中心时，请直接传递 Railway 代码。通过`us` selects `pdx`, and passing `eu` selects `ams`.

:::注意
部署管道中存在其他铁路区域（例如新加坡、`sin`) but aren't offered in the residency selector yet, because hosted databases and observability don't have local placement outside the US and EU. Passing an unrecognized region falls back to the US default rather than pinning to it.
:::

## 托管数据库放置 {/* #hosted-database-placement */}

当您附加一个[environment-scoped database](/docs/mastra-platform/database), the platform picks the provider region closest to the environment. This is server-authoritative, so an explicit `--region` on `mastra env db create <env>` is ignored. The environment's region is the source of truth.

|环境区域 |图尔索地区 | Postgres（Neon）区域 |
| - | - | - |
|`pdx` | `sjc` (San Jose) | `aws-us-west-2` (Oregon) |
| `iad` | `iad` (Ashburn) | `aws-us-east-1` (N. Virginia) |
| `sfo` | `sjc` (San Jose) | `aws-us-west-2` (Oregon) |
| `ams` | `ams`（阿姆斯特丹）|`aws-eu-central-1`（法兰克福）|

项目范围的数据库（跨环境共享）接受明确的`--region` because they aren't bound to a single environment. Use a provider region ID for the flag, not the `us` / `eu` shorthand:

```bash
mastra env db create --kind turso --region fra
mastra env db create --kind neon --region aws-us-east-1
```

Turso 提供 20 多个区域，Postgres (Neon) 可在美国、欧盟和亚太地区的 AWS 和 Azure 区域使用。请参阅[Turso regions list](https://docs.turso.tech/features/data-edge#locations) and [Neon regions list](https://neon.com/docs/introduction/regions) for the full set. Passing a code not offered by the provider fails at attach time with the provider's error.

## Observability共置 {/* #observability-co-location */}

Observability摄取目前在两个区域运行：**US** (Iowa, `us-central1`) and **EU** (Amsterdam). Every environment's traces, logs, and metrics are routed to the ingest region that matches its residency zone:

|环境区域 |可观测区域 |
| - | - |
|`pdx`, `iad`, `sfo`, `us` shorthand | US (Iowa) |
| `ams`, `eu` shorthand | EU (Amsterdam) |

铁路和数据库Provider提供的区域多于Observability摄取的区域，因此某些组合无法完全共置。环境在`us` zone always send telemetry to US ingest, while those in the `eu` zone use EU ingest. This routing applies even when the underlying Railway region is a city without a dedicated ingest endpoint. Data residency is preserved at the zone level. Telemetry from an `eu` environment never crosses into the US.
