# 区域

区域决定平台环境在哪里运行、[托管数据库](/docs/mastra-platform/database)部署在哪里，以及可观测性数据存放在哪里。创建环境时即确定区域，之后无法更改。

Mastra Platform 目前提供 `us` 和 `eu` 两个数据驻留地理范围，对应 Railway 的具体计算区域。数据库和可观测性服务会自动跟随环境区域。

## 选择区域 {/* #choose-a-region */}

创建环境或首次向该环境部署时，传入 `--region`。

```bash
mastra deploy --env production --region eu
mastra env create staging --region us
```

`mastra deploy --region` 和 `mastra env create --region` 均接受 `us` / `eu` 简写或下表中的正式 Railway 区域代码。建议使用简写。

未指定区域时，默认使用 `us`，对应俄勒冈州波特兰的 `pdx`。

## 可用区域 {/* #available-regions */}

区域选择器提供两个地理范围中的四个 Railway 区域。简写 `us` 和 `eu` 分别对应各自的默认区域。

| 地理范围 | Railway 代码 | 位置 |
| - | - | - |
| `us` | `pdx`（默认） | 俄勒冈州波特兰 |
| `us` | `iad` | 弗吉尼亚州阿什本 |
| `us` | `sfo` | 加利福尼亚州旧金山 |
| `eu` | `ams`（默认） | 荷兰阿姆斯特丹 |

如需将环境固定在特定数据中心，请直接传入 Railway 区域代码。传入 `us` 会选中 `pdx`，传入 `eu` 会选中 `ams`。

:::note
部署流水线中还有其他 Railway 区域，例如新加坡（`sin`）。由于托管数据库和可观测性服务在美国及欧盟以外尚不支持就近部署，这些区域暂未列入选择器。传入无法识别的区域时，平台会回退到美国默认区域。
:::

## 托管数据库的位置 {/* #hosted-database-placement */}

关联[环境级数据库](/docs/mastra-platform/database)时，平台会在供应商可用的区域中选择离该环境最近的区域。此决定由服务器作出，因此 `mastra env db create <env>` 中显式传入的 `--region` 不会生效，最终以环境区域为准。

| 环境区域 | Turso 区域 | Postgres（Neon）区域 |
| - | - | - |
| `pdx` | `sjc`（圣何塞） | `aws-us-west-2`（俄勒冈州） |
| `iad` | `iad`（阿什本） | `aws-us-east-1`（弗吉尼亚州北部） |
| `sfo` | `sjc`（圣何塞） | `aws-us-west-2`（俄勒冈州） |
| `ams` | `ams`（阿姆斯特丹） | `aws-eu-central-1`（法兰克福） |

项目级数据库由多个环境共享，不绑定单一环境，可以显式传入 `--region`。请为该参数提供供应商的区域 ID，避免使用 `us` / `eu` 简写。

```bash
mastra env db create --kind turso --region fra
mastra env db create --kind neon --region aws-us-east-1
```

Turso 提供 20 多个区域，Postgres（Neon）覆盖 AWS 和 Azure 在美国、欧盟和亚太的多个区域。完整列表见 [Turso 区域](https://docs.turso.tech/features/data-edge#locations)和 [Neon 区域](https://neon.com/docs/introduction/regions)。如果传入供应商不支持的代码，关联数据库时会失败，并返回供应商的错误。

## 可观测性数据的区域路由 {/* #observability-co-location */}

可观测性采集目前在两个区域运行，即**美国**（爱荷华州，`us-central1`）和**欧盟**（阿姆斯特丹）。每个环境的 Trace、日志和指标都会发往与其数据驻留范围一致的采集区域。

| 环境区域 | 可观测性数据采集区域 |
| - | - |
| `pdx`、`iad`、`sfo`、简写 `us` | 美国（爱荷华州） |
| `ams`、简写 `eu` | 欧盟（阿姆斯特丹） |

Railway 和数据库供应商提供的区域比可观测性采集区域更多，因此部分组合无法部署在同一地点。`us` 范围内的环境始终将遥测数据发送到美国采集端，`eu` 范围内的环境则发送到欧盟采集端。即使 Railway 所在城市没有专用采集端点，也遵循这一规则。数据仍保留在相应的地理范围内，`eu` 环境的遥测数据不会传到美国。
