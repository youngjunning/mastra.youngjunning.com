# 托管数据库

可以从 CLI 或[平台](/docs/mastra-platform/overview)的项目设置创建全托管数据库，并将其绑定到项目。Mastra 会通过你的 Provider 创建数据库并安全保存凭据。数据库就绪后，Mastra 会将连接信息注入运行时环境变量，无需复制或配置连接字符串。

```bash
mastra env db create --kind turso
```

## 何时使用托管数据库 {/* #when-to-use-hosted-databases */}

当项目需要由平台管理的持久存储时，可以使用托管数据库，例如：

- **Agent 记忆**：持久保存对话历史和工作记忆，并支持跨会话语义召回。
- **应用数据**：存取项目运行时所需的关系型或结构化数据。
- **向量搜索**：存储供检索增强生成（RAG）和语义搜索使用的嵌入向量。

## 数据库提供商 {/* #providers */}

目前可使用 Turso、Neon 和 Postgres 三种托管数据库，MongoDB 即将推出。绑定数据库时选择其中一种，再在代码中将注入的变量传给对应的 Mastra 存储适配器。

每个提供商注入的变量名都是固定的。例如，Neon 和 Postgres 各注入一个 `DATABASE_URL`，而 Turso 注入独立的 `TURSO_*` 变量。同一环境内的变量名必须唯一，因此每个变量名最多对应一个数据库。Neon 和 Postgres 都注入 `DATABASE_URL`，不能在同一环境中共存；Turso 可以和其中任一种搭配使用。

对于大多数以 Agent 为主的项目，**Turso** 最容易上手。它的轻量引擎兼容 SQLite，适合保存 Agent 记忆、对话历史，以及按租户隔离数据。如果需要能从自己的电脑、其他服务或迁移工具访问的公有无服务器 Postgres，请选择 **Neon**。如果工作负载必须留在部署的私有网络内，请选择 **Postgres**：它与服务器一起运行，只有该服务器可以访问。**MongoDB**（_即将推出_）将提供文档存储和内置向量搜索，适合不易用 SQL 表达的工作负载。

| 提供商 | 引擎 | 网络 | 适用场景 |
| - | - | - | - |
| **Turso** | LibSQL，兼容 SQLite | 公网 | Agent 记忆、按租户隔离 |
| **Neon** | 支持分支的无服务器 Postgres | 公网 | 需要从部署外部访问的关系型工作负载 |
| **Postgres** | 托管 PostgreSQL | VPC（私有） | 必须留在部署私有网络内的关系型工作负载 |
| **MongoDB** | 文档和向量搜索 | _待定_ | 文档存储、向量搜索（_即将推出_） |

## 数据库作用域 {/* #database-scope */}

绑定数据库时，可以选择以下两种作用域之一：

- **环境级**：默认选项。数据库只绑定到一个环境，以隔离各环境的数据，例如为生产和预发布环境分别使用独立的数据库。如果项目只有一个环境，`mastra env db create` 会自动选中它；如果有多个环境，CLI 会提示选择。
- **项目级**：项目的所有[环境](/docs/mastra-platform/environments)共用一个数据库。使用 `--shared` 启用，每次部署都会注入该数据库的变量。

作用域在绑定数据库时确定，可以用 `mastra env db list` 查看。

同一提供商的两个作用域不能重叠。项目级数据库已经向每个环境注入变量，再绑定同一提供商的环境级数据库会因变量名冲突而被拒绝。要从共享数据库改为每个环境使用独立数据库，请先删除项目级数据库，再为每个环境绑定一个数据库。删除操作会从提供商处销毁数据库及其全部数据，因此请在切换作用域前导出要保留的数据。属于不同环境的环境级数据库不会冲突，每次部署只接收当前环境的变量。

## 通过 CLI 绑定数据库 {/* #attach-with-the-cli */}

无需提前运行此命令。如果项目需要托管数据库但还没有配置，`mastra deploy` 会在部署预检时询问是否绑定一个。确认后，无需离开 CLI 即可继续部署。如果组织可以使用 Neon 和 Postgres，且缺少的变量是 `DATABASE_URL`，提示会让你选择要创建哪一种数据库。

也可以提前创建并绑定数据库。CLI 会轮询状态，直到数据库就绪，通常需要几秒：

```bash
# Scoped to a single environment (the CLI picks the only one, or prompts if there are several)
mastra env db create --kind turso

# Scoped to a specific environment
mastra env db create staging --kind turso

# Shared by all environments
mastra env db create --kind turso --shared
```

支持 `turso`、`neon`（公有无服务器 Postgres）和 `postgres`（VPC 隔离的 Postgres）。常用选项：

- `--shared`：绑定供所有环境共用的项目级数据库。不能与环境参数一起使用。
- `--name <name>`：数据库名称。默认根据项目 slug 生成。
- `--region <region>`：项目级数据库的提供商区域 ID，例如 `fra`。环境级数据库会自动放在靠近环境所在区域的位置；即使显式传入 `--region`，也会被忽略。
- `--no-wait`：立即返回，无需轮询。之后可用 `mastra env db show` 查看进度。
- `--json`：输出机器可读结果。项目有多个环境时，`--json` 要求提供环境参数或 `--shared`，不会弹出交互提示。

查看和管理已绑定的数据库：

```bash
mastra env db list
mastra env db show <database>
mastra env db delete <database>
```

`mastra env db list` 显示各数据库的类型、状态、作用域和注入的变量名。`mastra env db show` 会打印连接说明，并遮盖机密值。传入 `--show-secrets` 可查看这些值。`mastra env db delete` 会从提供商处永久删除数据库及其全部数据。创建和删除数据库需要所在组织的管理员角色。

## 在项目设置中绑定数据库 {/* #attach-from-project-settings */}

<Steps>
  <StepItem>
    在[平台](/docs/mastra-platform/overview)打开项目，进入 **Project Settings**。
  </StepItem>

  <StepItem>
    打开 **Database**，选择 **Add database**。
  </StepItem>

  <StepItem>
    选择**数据库提供商**（Turso、Neon 或 Postgres）。绑定前可更换提供商。
  </StepItem>

  <StepItem>
    配置数据库：

    - **Name**：数据库在项目中的标签。
    - **Region**：托管数据库的区域。请选择离用户最近的区域。Turso 默认使用 `sjc`（圣何塞），在全球有 20 多个可用地点。Neon 默认使用 `aws-us-west-2`，在美国、欧盟和亚太地区均有 AWS 和 Azure 区域可用。Postgres 与部署在同一私有网络中运行，区域与环境的 Railway 区域一致（美国、欧盟或亚太地区）。
  </StepItem>

  <StepItem>
    选择 **Attach database**。数据库会在后台创建，初始状态为 `provisioning`，提供商完成设置后变为 `ready`。连接信息会自动注入项目，作为服务器的运行时环境变量。
  </StepItem>
</Steps>

从项目设置绑定的数据库属于项目级。要绑定环境级数据库，请使用 [CLI](#attach-with-the-cli)。

## 从代码连接数据库 {/* #connect-from-your-code */}

在 **Project Settings → Database** 查看数据库状态。后台设置期间，已绑定的数据库显示为 `provisioning`。状态变为 `ready` 时，平台已经将其连接信息注入为托管环境变量。

打开状态为 `ready` 的数据库，可以查看这些变量和代码片段。如下所示，用这些变量配置 Mastra 存储适配器。

### 图尔索 (LibSQL) {/* #turso-libsql */}

Turso 提供两个环境变量：`TURSO_DATABASE_URL` 和 `TURSO_AUTH_TOKEN`。以下示例用这两个变量建立 [LibSQLStore](/integrations/databases/libsql) 连接。

```ts title="src/mastra/storage.ts" caption="Connect a Turso (LibSQL) database"
import { LibSQLStore } from '@mastra/libsql'

export const storage = new LibSQLStore({
  id: 'mastra-storage',
  url: process.env.TURSO_DATABASE_URL!,
  authToken: process.env.TURSO_AUTH_TOKEN!,
})
```

安装适配器：

```bash npm2yarn
npm install @mastra/libsql@latest
```

### Neon 和 Postgres {/* #neon-and-postgres */}

Neon（公有无服务器）和 Postgres（VPC 隔离）都只提供一个 `DATABASE_URL` 连接字符串，因此两者可使用相同的 [PostgresStore](/integrations/databases/postgresql) 代码。同一个环境只能使用其中一种。

```ts title="src/mastra/storage.ts" caption="Connect a Neon or Postgres database"
import { PostgresStore } from '@mastra/pg'

export const storage = new PostgresStore({
  connectionString: process.env.DATABASE_URL!,
})
```

安装适配器：

```bash npm2yarn
npm install @mastra/pg@latest
```

VPC 隔离的 Postgres 只能从已部署的服务器访问，因此本地开发时无法直接连接。开发时，将 `DATABASE_URL` 指向本地 Postgres 或 Neon 分支；部署时，则由平台注入托管值。

将 `storage` 实例传入 `Mastra` 配置，供 Agent、Memory 和 Workflow 使用：

```ts title="src/mastra/index.ts"
import { Mastra } from '@mastra/core'
import { storage } from './storage'

export const mastra = new Mastra({
  storage,
})
```

## 环境变量 {/* #environment-variables */}

每个提供商都会注入一组固定的托管环境变量。数据库状态为 `ready` 时，项目可在运行时使用这些变量，无需手动定义。

| 提供商 | 变量 |
| - | - |
|图尔索 |`TURSO_DATABASE_URL`, `TURSO_AUTH_TOKEN` |
| Neon | `DATABASE_URL` |
| Postgres | `DATABASE_URL` |

:::警告
请将连接凭据视为机密。认证令牌（`TURSO_AUTH_TOKEN`）和 Postgres 连接字符串（`DATABASE_URL`）都能授予对数据的完整访问权限。平台默认遮盖这些值，只有在请求查看时才显示。
:::

## 管理数据库 {/* #manage-a-database */}

- **查看连接信息**：在项目设置中打开状态为 `ready` 的数据库，即可查看其环境变量和可直接复制的代码片段。
- **删除**：从项目中移除数据库会删除提供商处的数据库，并清除已注入的环境变量。操作不可撤销，请确认不再需要其中的数据。
