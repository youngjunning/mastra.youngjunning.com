# 托管数据库

从 CLI 或您的系统配置完全托管的数据库[platform](/docs/mastra-platform/overview)项目设置并将其附加到您的项目。 Mastra 与您的Provider一起创建它并安全地存储凭据，并在数据库准备就绪时将连接详细信息作为运行时环境变量注入，因此无需复制或配置连接字符串。

```bash
mastra env db create --kind turso
```

## 何时使用托管数据库 {/* #when-to-use-hosted-databases */}

当您的项目需要由平台管理的持久存储时，请使用托管数据库，包括：

* **Agent记忆**：保留对话历史和工作记忆，以及跨会话的语义回忆。
* **应用数据**：存储和检索项目运行时所需的关系或结构化数据。
* **矢量搜索**：存储用于检索增强生成和语义搜索的嵌入。

## Provider {/* #providers */}

目前，托管数据库可通过三个Provider获得：Turso、Neon 和 Postgres，MongoDB 即将推出。附加数据库时选择一个，然后将其注入的变量连接到代码中匹配的 Mastra 存储适配器。

每个提供者都会注入一组固定的变量名称，例如，一个`DATABASE_URL` for both Neon and Postgres and separate `TURSO_*` variables for Turso. Those names must be unique within each environment, so a single environment can use at most one database per variable name. Because Neon and Postgres both inject `DATABASE_URL`, they're mutually exclusive within the same environment. Turso can be attached alongside either one.

对于大多数以Agent为中心的项目，**Turso** is the simplest starting point. It provides a lightweight, SQLite-compatible engine well suited to agent memory, conversation history, and per-tenant isolation. Choose **Neon** when you want a public, serverless Postgres you can reach from your laptop, other services, or a migration tool. Choose **Postgres** when your workload needs to stay on your deployment's private network: it runs alongside your server and is only reachable from it. **MongoDB** (*coming soon*) will add document storage and built-in vector search for workloads that don't map cleanly to SQL.

|Provider|发动机|网络|最适合 |
| - | - | - | - |
|**Turso** | LibSQL, SQLite-compatible | Public | Agent memory, per-tenant isolation |
| **Neon** | Serverless Postgres with branching | Public | Relational workloads reachable from outside your deployment |
| **Postgres** | Managed PostgreSQL | VPC (private) | Relational workloads that must stay on your deployment's private network |
| **MongoDB** | Document and vector search | *TBD* | Document storage, vector search (*coming soon*) |

## 数据库范围 {/* #database-scope */}

数据库附加在两个范围之一：

* **环境范围**：默认。连接到单个环境，以便数据在环境之间保持隔离（例如单独的生产数据库和登台数据库）。当你的项目只有一个环境时，`mastra env db create` picks it automatically; with several, the CLI prompts you to select one.
* **项目范围**：一个数据库由所有项目共享[environments](/docs/mastra-platform/environments). Opt in with `--shared`. Its variables are injected into every deploy.

范围是在附加数据库时设置的，并显示在`mastra env db list`.

同一Provider的范围不能重叠。由于项目范围的数据库已将其变量注入到每个环境中，因此附加同一提供程序的环境范围的数据库会因变量名称冲突而被拒绝。要从共享数据库移动到每个环境的数据库，请先删除项目范围的数据库，然后为每个环境附加一个数据库。删除数据库会破坏它以及提供程序及其所有数据，在切换范围之前导出您需要保留的任何内容。不同环境中的环境范围数据库永远不会冲突，每个部署仅接收其自己环境的变量。

## 使用 CLI 附加 {/* #attach-with-the-cli */}

您不必预先运行此命令。如果您的项目需要托管数据库但还没有，`mastra deploy` offers to attach one for you when the deploy preflight check runs. Say yes and the deploy continues without leaving the CLI. When both Neon and Postgres are available for your organization and the missing variable is `DATABASE_URL`, the prompt lets you choose which one to provision.

或者，提前创建并附加数据库。 CLI 会进行轮询，直到准备就绪，这需要几秒钟的时间：

```bash
# Scoped to a single environment (the CLI picks the only one, or prompts if there are several)
mastra env db create --kind turso

# Scoped to a specific environment
mastra env db create staging --kind turso

# Shared by all environments
mastra env db create --kind turso --shared
```

支持的种类有`turso`, `neon` (public serverless Postgres), and `postgres` (VPC-isolated Postgres). Useful flags:

* `--shared`：附加每个环境共享的项目范围数据库。不能与环境参数结合使用。
* `--name <name>`: 数据库名称。默认为从项目 slug 派生的名称。
* `--region <region>`：项目范围数据库的提供者区域 ID（例如`fra`). Environment-scoped databases are placed near the environment's region automatically, and an explicit `--region` is ignored.
* `--no-wait`：立即返回而不是轮询。稍后检查进度`mastra env db show`.
* `--json`：机器可读的输出。当项目有多个环境时，`--json` requires an environment argument or `--shared` (no interactive prompt).

检查和管理附加数据库：

```bash
mastra env db list
mastra env db show <database>
mastra env db delete <database>
```

`mastra env db list`显示每个数据库的种类、状态、范围和注入的变量名称。`mastra env db show` prints connection instructions with secret values masked. Pass `--show-secrets` to reveal them. `mastra env db delete` permanently deletes the database and all of its data with the provider. Creating and deleting databases requires the admin role in your organization.

## 从项目设置附加 {/* #attach-from-project-settings */}

<Steps>
  <StepItem>
    在中打开您的项目[platform](/docs/mastra-platform/overview) and go to **Project Settings**.
  </StepItem>

  <StepItem>
    打开**Database** section, then select **Add database**.
  </StepItem>

  <StepItem>
    选择一个**provider** (Turso, Neon, or Postgres). You can switch providers before attaching.
  </StepItem>

  <StepItem>
    配置数据库：

    * **姓名**：项目中数据库的标签。
    * **地区**：数据库所在的位置。选择最接近您的用户的区域。图尔索默认为`sjc` (San Jose) and is available in 20+ locations worldwide. Neon defaults to `aws-us-west-2` and is available across AWS and Azure regions in the US, EU, and APAC. Postgres runs on the same private network as your deployment. Its region follows the environment's Railway region (US, EU, or APAC).
  </StepItem>

  <StepItem>
    选择**Attach database**. Provisioning runs in the background. The database starts in a `provisioning` state and moves to `ready` once the provider finishes setup. Connection details are injected into your project as server runtime environment variables automatically.
  </StepItem>
</Steps>

从项目设置附加的数据库是项目范围的。使用[CLI](#attach-with-the-cli) to attach an environment-scoped database.

## 从您的代码连接 {/* #connect-from-your-code */}

检查数据库状态**Project Settings → Database**. An attached database shows `provisioning` while setup runs in the background. Once it's `ready`, the platform has injected its connection details as managed environment variables.

打开一个`ready` database to view those variables and a code snippet. Use the variables to configure a Mastra storage adapter, as shown below.

### 图尔索 (LibSQL) {/* #turso-libsql */}

Turso公开了两个环境变量：`TURSO_DATABASE_URL` and `TURSO_AUTH_TOKEN`. The following example connects a [LibSQLStore](/integrations/databases/libsql) using those variables.

```ts title="src/mastra/storage.ts" caption="Connect a Turso (LibSQL) database"
import { LibSQLStore } from '@mastra/libsql'

export const storage = new LibSQLStore({
  id: 'mastra-storage',
  url: process.env.TURSO_DATABASE_URL!,
  authToken: process.env.TURSO_AUTH_TOKEN!,
})
```

安装适配器：

```bash npm2yarn
npm install @mastra/libsql@latest
```

### Neon 和 Postgres {/* #neon-and-postgres */}

Neon（公共无服务器）和 Postgres（VPC 隔离）都公开一个`DATABASE_URL` connection string, so the same [PostgresStore](/integrations/databases/postgresql) code works for either. An environment can have one or the other, not both.

```ts title="src/mastra/storage.ts" caption="Connect a Neon or Postgres database"
import { PostgresStore } from '@mastra/pg'

export const storage = new PostgresStore({
  connectionString: process.env.DATABASE_URL!,
})
```

安装适配器：

```bash npm2yarn
npm install @mastra/pg@latest
```

VPC 隔离的 Postgres 只能从部署的服务器访问，因此本地开发无法直接连接到它。观点`DATABASE_URL` at a local Postgres (or a Neon branch) during development, then let the platform inject the managed value at deploy time.

通过`storage` instance to your `Mastra` configuration so agents, memory, and workflows can use it:

```ts title="src/mastra/index.ts"
import { Mastra } from '@mastra/core'
import { storage } from './storage'

export const mastra = new Mastra({
  storage,
})
```

## 环境变量 {/* #environment-variables */}

每个提供者都会注入一组固定的托管环境变量。当数据库处于运行时时，这些可用于您的项目`ready`. You don't define them yourself.

|Provider|变量|
| - | - |
|图尔索 |`TURSO_DATABASE_URL`, `TURSO_AUTH_TOKEN` |
| Neon | `DATABASE_URL` |
| Postgres | `DATABASE_URL` |

:::警告
将连接凭据视为机密。身份验证令牌 (`TURSO_AUTH_TOKEN`) and the Postgres connection string (`DATABASE_URL`) grant full access to your data. The platform masks them by default and only reveals them on request.
:::

## 管理数据库 {/* #manage-a-database */}

* **查看连接详细信息**: 打开一个`ready` database in your project settings to see its environment variables and a copy-pasteable code snippet.
* **删除**：从项目中删除数据库会随提供者一起删除该数据库并清除其注入的环境变量。这是不可逆转的，因此请确保您不再需要该数据。
