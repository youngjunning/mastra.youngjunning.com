# 工作空间

Workspace 是一组由 Mastra 平台分配的运行时资源，部署时会提供给 Agent。每个环境有各自的 Workspace，因此 `production` 和 `staging` 彼此隔离。

每个 Workspace 提供两种资源：

- 由 [`PlatformFilesystem`](/reference/workspace/platform-filesystem) 封装的**存储桶**，用于文件系统存储。数据按环境持久保存，Agent 可跨次运行读写。
- 由 [`PlatformSandbox`](/reference/workspace/platform-sandbox) 封装的**按需沙箱池**，用于执行命令。每个 `PlatformSandbox` 实例在 `start()` 时创建自己的远程沙箱，在 `destroy()` 时销毁它。Agent 通常在同一会话中启动多个沙箱，完成任务后释放。

Workspace 仅属于单个[环境](/docs/mastra-platform/environments)，`production` 和 `staging` 不共享存储桶或沙箱池。平台负责资源配置、身份验证和空闲清理。

## 何时配置 Workspace {/* #when-workspaces-are-provisioned */}

新项目默认启用 Workspace。创建环境时，平台会自动配置存储桶，并在后台预热沙箱基础镜像，加快首次 `PlatformSandbox` 调用的启动速度。

尚未启用的项目可在 Workspaces 选项卡点击 **Enable workspaces**，为每个环境配置存储桶。

如果某个环境的资源配置失败，例如沙箱提供方负载过高，Workspaces 选项卡会显示错误并提供重试操作。环境仍会创建，只有 Workspace 在重试前不可用。

## 在代码中使用 Workspace {/* #use-the-workspace-from-your-code */}

安装 Provider 包：

```bash npm2yarn
npm install @mastra/platform-workspace
```

将 Provider 组合成 Workspace，再注册到 Mastra：

```typescript title="src/mastra/workspace.ts"
import { Workspace } from '@mastra/core/workspace'
import { PlatformFilesystem, PlatformSandbox } from '@mastra/platform-workspace'

export const workspace = new Workspace({
  filesystem: new PlatformFilesystem(),
  sandbox: new PlatformSandbox(),
})
```

```typescript title="src/mastra/index.ts"
import { Mastra } from '@mastra/core'
import { workspace } from './workspace'

export const mastra = new Mastra({
  workspace,
})
```

`PlatformFilesystem` 和 `PlatformSandbox` 从环境变量读取配置，在平台上无需传入选项。平台会在部署时注入变量。参见[环境变量](#environment-variables)。

## 一个存储桶，多个沙箱 {/* #one-bucket-many-sandboxes */}

设计 Agent 时，要留意 `PlatformFilesystem` 和 `PlatformSandbox` 的生命周期不同。

**`PlatformFilesystem` 提供长期访问环境存储桶的接口。** 使用它的请求和 Agent 都读写同一份对象存储。除非显式删除，Agent 写入的数据在下次请求中仍可见。

**`PlatformSandbox` 是创建临时沙箱的客户端。** 每个 `PlatformSandbox` 实例管理一个远程沙箱：

- `start()` 创建新沙箱；如果传入 `sandboxId`，则重新连接原有沙箱。
- `executeCommand()` 在沙箱中执行命令。
- `stop()` 释放当前进程的租约，远程沙箱不受影响。虚拟机按环境的空闲策略继续运行；之后调用 `start()` 时传入保存的 `sandboxId` 即可重新连接。仅复用同一个 `id` 会创建新沙箱；若该 `id` 有恢复检查点，新沙箱会以此初始化。
- `destroy()` 释放虚拟机。在 Railway 上，它还会删除调用方传入的恢复 `id` 所关联的检查点。在 E2B 上，它只会关闭虚拟机，你创建的快照仍由你管理。

同一静态配置下，所有请求和 Agent 共用一个 `PlatformSandbox`，不会为每个请求或记忆线程另建沙箱。`PlatformFilesystem` 是独立的 Provider，同时配置两者也不会将环境的存储桶挂载到沙箱内。

如果 Agent 需要另一个隔离环境，例如按任务分配沙箱、按用户划分租户，或避免后台任务影响共享 Shell 状态，请另建一个 `PlatformSandbox`：

```typescript title="src/mastra/tools/run-in-fresh-sandbox.ts"
import { PlatformSandbox } from '@mastra/platform-workspace'

export async function runInFreshSandbox(command: string) {
  const sandbox = new PlatformSandbox()
  await sandbox.start()
  try {
    return await sandbox.executeCommand(command)
  } finally {
    await sandbox.destroy()
  }
}
```

也可以用已配置的沙箱作模板，克隆出一组沙箱。副本继承凭据、环境、网络隔离和默认值，无需重复配置：

```typescript
const template = new PlatformSandbox({ networkIsolation: 'PRIVATE' })

const perProjectSandbox = template.clone({ id: `project-${projectId}` })
await perProjectSandbox.start()
```

完整生命周期、检查点恢复、重新连接和克隆选项见 [`PlatformSandbox` 参考](/reference/workspace/platform-sandbox)。

## 环境变量 {/* #environment-variables */}

部署到有 Workspace 的平台环境时，平台会自动提供以下变量：

| 变量 | 说明 |
| - | - |
| `MASTRA_PLATFORM_ACCESS_TOKEN` | 平台签发的 JSON Web Token (JWT)，供 Workspace Provider 验证身份，仅适用于部署所属的组织和项目。 |
| `MASTRA_PROJECT_ID` | 部署所属的项目。 |
| `MASTRA_ENVIRONMENT_ID` | 部署所属的环境，决定平台使用哪个沙箱池。 |
| `MASTRA_PLATFORM_BUCKET_NAME` | 环境关联的存储桶名称，指定 `PlatformFilesystem` 读写哪个存储桶。 |

这些变量名由平台保留。即使项目显式设置同名变量，也以平台值为准。

## 本地开发 {/* #local-development */}

在本地 `.env` 文件写入四个变量即可复用这些 Provider。项目、环境和存储桶的值可从项目的 **Workspaces** 选项卡获取。对于 `MASTRA_PLATFORM_ACCESS_TOKEN`，请在组织设置的 **API Tokens** 中创建 `sk_` API 令牌。平台部署则使用注入的 JWT。

```bash title=".env"
MASTRA_PLATFORM_ACCESS_TOKEN=sk_your-api-token
MASTRA_PROJECT_ID=your-project-id
MASTRA_ENVIRONMENT_ID=your-environment-id
MASTRA_PLATFORM_BUCKET_NAME=your-bucket-name
```

`PlatformFilesystem` 和 `PlatformSandbox` 在本地和平台上的行为一致，连接所选环境的同一个存储桶和沙箱池。要隔离生产数据，本地运行时请用 `staging` 或 `preview` 环境的变量。

要完全离线开发，可在本地构建中改用 [`LocalFilesystem`](/reference/workspace/local-filesystem) 和 [`LocalSandbox`](/reference/workspace/local-sandbox)。

## 查看 Workspace {/* #inspect-the-workspace */}

平台项目的 Workspaces 选项卡按环境显示：

- 存储桶的状态和内容，可上传、下载或删除。
- 最近的沙箱会话、执行的命令、退出码和运行时长。
- 资源配置失败的记录，可点击 **Retry** 重试。
