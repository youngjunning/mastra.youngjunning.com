# 工作空间

Workspace是 Mastra 平台提供的一组运行时资源，并在部署时交给您的Agent。每个环境都有自己的Workspace，因此`production`和`staging`保持隔离。

每个Workspace都公开两种功能：

* 一**bucket** for filesystem storage, wrapped by [`PlatformFilesystem`](/reference/workspace/platform-filesystem). The bucket is a durable, environment-scoped store agents read from and write to across runs.
* 一池**on-demand sandboxes** for command execution, wrapped by [`PlatformSandbox`](/reference/workspace/platform-sandbox). Each `PlatformSandbox` instance provisions its own remote sandbox on `start()`并摧毁它`destroy()`。Agent通常会在每个会话中启动许多Sandbox，将它们用于任务，然后让它们离开。

Workspace的范围仅限于单个[environment](/docs/mastra-platform/environments), so `production` and `staging` don't share buckets or sandbox pools. The platform manages provisioning, authentication, and idle cleanup.

## 何时配置Workspace {/* #when-workspaces-are-provisioned */}

新项目默认启用Workspace。当您创建环境时，平台会自动为其配置一个存储桶。Sandbox基础图像在背景中被加热，因此第一个`PlatformSandbox` call starts quickly.

未选择加入的现有项目显示**Enable workspaces** action in the Workspaces tab. Enabling provisions a bucket for every environment on the project.

如果环境配置失败（例如，当Sandbox提供程序处于负载状态时），“Workspace”选项卡会显示失败并提供重试。环境本身还是被创造出来的。在您重试之前，只有Workspace不可用。

## 使用代码中的Workspace {/* #use-the-workspace-from-your-code */}

安装提供程序包：

```bash npm2yarn
npm install @mastra/platform-workspace
```

将提供者组成一个Workspace并将其注册到 Mastra：

```typescript title="src/mastra/workspace.ts"
import { Workspace } from '@mastra/core/workspace'
import { PlatformFilesystem, PlatformSandbox } from '@mastra/platform-workspace'

export const workspace = new Workspace({
  filesystem: new PlatformFilesystem(),
  sandbox: new PlatformSandbox(),
})
```

```typescript title="src/mastra/index.ts"
import { Mastra } from '@mastra/core'
import { workspace } from './workspace'

export const mastra = new Mastra({
  workspace,
})
```

`PlatformFilesystem`和`PlatformSandbox` read their configuration from environment variables, so you don't pass any options on the platform. The platform injects them at deploy time. See [Environment variables](#environment-variables).

## 一桶，多个Sandbox {/* #one-bucket-many-sandboxes */}

`PlatformFilesystem`和`PlatformSandbox` have different lifecycles, which matters when you design agents.

**`PlatformFilesystem`是环境桶的长寿命句柄。**&#x4F7F;用此提供程序的所有请求和Agent都会读取和写入相同的对象存储。Agent写入的任何内容在下一个请求中都是可见的，除非您明确删除它。

**`PlatformSandbox`是一个用于配置临时Sandbox的客户端。**&#x6BCF;个`PlatformSandbox` instance owns one remote sandbox:

* `start()`提供一个新的Sandbox（或者当你通过时重新附加`sandboxId`).
* `executeCommand()`针对它运行命令。
* `stop()`释放此进程的租约而不触及远程Sandbox。 VM 在环境的空闲策略下保持运行，稍后`start()` with the saved `sandboxId` reattaches to it. Reusing only the same `id` provisions a new sandbox, seeded from that `id`'s recovery checkpoint when one exists.
* `destroy()`释放虚拟机。在 Railway 上，它还会删除与调用者提供的恢复关联的恢复检查点`id`. On E2B, it only kills the VM, and any snapshot you captured remains yours to manage.

静态配置的`PlatformSandbox` is shared across every request and agent using that configuration rather than creating separate sandboxes for requests or memory threads. `PlatformFilesystem` is also a separate provider: configuring both providers doesn't mount the environment bucket inside the sandbox.

当您的Agent需要另一个隔离环境时，例如每个任务Sandbox、每个用户租户或不应触及共享 shell 状态的后台作业，请构造另一个`PlatformSandbox`:

```typescript title="src/mastra/tools/run-in-fresh-sandbox.ts"
import { PlatformSandbox } from '@mastra/platform-workspace'

export async function runInFreshSandbox(command: string) {
  const sandbox = new PlatformSandbox()
  await sandbox.start()
  try {
    return await sandbox.executeCommand(command)
  } finally {
    await sandbox.destroy()
  }
}
```

或者克隆已配置的Sandbox作为队列的模板。克隆继承凭据、环境、网络隔离和默认值，而不重复它们：

```typescript
const template = new PlatformSandbox({ networkIsolation: 'PRIVATE' })

const perProjectSandbox = template.clone({ id: `project-${projectId}` })
await perProjectSandbox.start()
```

看[`PlatformSandbox` reference](/reference/workspace/platform-sandbox) for the full lifecycle, checkpoint recovery, reattachment, and clone options.

## 环境变量 {/* #environment-variables */}

在具有Workspace的平台环境上运行的每个部署都会自动接收这些变量：

|变量|内容 |
| - | - |
|`MASTRA_PLATFORM_ACCESS_TOKEN` | Platform-issued JSON Web Token (JWT) the workspace providers use to authenticate. The token is scoped to the deploy's organization and project. |
| `MASTRA_PROJECT_ID` | Project the deploy belongs to. |
| `MASTRA_ENVIRONMENT_ID` | Environment the deploy belongs to. Selects which sandbox pool the platform uses. |
| `MASTRA_PLATFORM_BUCKET_NAME` | Bucket name attached to the environment. Selects which bucket `PlatformFilesystem` reads and writes. |

这些名称是保留的。如果您的项目明确设置了其中任何一个，则平台管理的值优先。

## 当地发展 {/* #local-development */}

通过将四个变量放入您的本地重用相同的提供程序`.env` file. Get the project, environment, and bucket values from your project's **Workspaces** tab. For `MASTRA_PLATFORM_ACCESS_TOKEN`, create an `sk_` API token on your organization's settings page under **API Tokens**. Platform deploys use an injected JWT instead.

```bash title=".env"
MASTRA_PLATFORM_ACCESS_TOKEN=sk_your-api-token
MASTRA_PROJECT_ID=your-project-id
MASTRA_ENVIRONMENT_ID=your-environment-id
MASTRA_PLATFORM_BUCKET_NAME=your-bucket-name
```

`PlatformFilesystem`和`PlatformSandbox` behave the same locally as on the platform, they connect to the same bucket and sandbox pool for that environment. Use a `staging` or `preview` environment's variables for local runs if you want to keep production data isolated.

对于从不接触平台的纯离线循环，请将提供者交换为[`LocalFilesystem`](/reference/workspace/local-filesystem) and [`LocalSandbox`](/reference/workspace/local-sandbox) in a local build.

## 检查工作空间 {/* #inspect-the-workspace */}

平台项目中的“Workspace”选项卡按环境显示：

* 存储桶状态及其内容，以及上传、下载和删除操作。
* 最近的Sandbox会话及其命令、退出代码和持续时间。
* 配置失败**Retry** action.
