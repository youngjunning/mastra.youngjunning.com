# Mastra 平台的 Trace Intelligence

Trace Intelligence 分析 Mastra Observability 采集的 Trace，生成四个内置维度及项目启用的自定义信号，再将相似的 Trace 信号聚类为主题，以找出 Agent 交互中反复出现的模式。

可以用 Trace Intelligence 探究以下问题：

- 用户想完成什么？
- 哪些目标通常能达成，哪些往往悬而未决或受阻？
- 成功和未成功的交互中分别出现了哪些 Agent 行为？
- 用户情绪与目标和结果有何关系？

:::warning 封闭测试
Trace Intelligence 仅向部分受邀的 Mastra 平台项目开放。
:::

## 获取访问权限 {/* #get-access */}

1. 提交 [Trace Intelligence 内测申请表](https://mastra.ai/trace-intelligence) 申请使用权限。
1. 确认已启用 [Mastra 平台的 Observability](/docs/mastra-platform/observability)，且 **Traces** 中显示已完成的 Agent Trace。
1. 至少需要 `@mastra/core@1.53.0` 和 `mastra@1.20.2`。升级后，为获准参加测试的项目部署或重新部署 Studio。内测期间不支持本地 Studio 或仅部署 Server。
1. 打开已部署的 Studio，在侧栏选择 **Intelligence**。
1. 向 Agent 发送有代表性的流量，并等待分析。

Mastra 将项目纳入测试后，无需修改 Agent 的定义或调用方式。

### 当数据可用时 {/* #when-data-is-available */}

Trace Intelligence 需要处理同一个 Agent 的足够多条 Trace，才能识别反复出现的模式。通常，该 Agent 至少有 **100 条已完成的 Trace** 得到处理后，才会出现首批主题。

分析流程异步运行，**Traces** 数量达到 100 时，分析可能尚未就绪。达到门槛后可能还需几分钟。无法分析的 Trace 不计入门槛。因此，100 是最低要求，界面不一定会在达到这个数值时更新。

收到更多 Trace 后，Trace Intelligence 会自动更新。Studio 要等至少两类 Trace 信号产生主题后，才能显示关系图。

使用有代表性的流量。反复发送少数测试提示词可能使结果失去代表性，例如只产生一个宽泛的主题，或大部分摘要都归入 Noise。

## 了解分析 {/* #understand-the-analysis */}

每条可分析的已完成 Trace 都会生成以下四种内置 Trace 信号，以及项目已启用的自定义信号：

| Trace 信号 | 含义 |
| - | - |
| **Goal** | 用户想实现的目标或想完成的事项。 |
| **Outcome** | 最终状态：完成、部分完成、受阻、失败、未解决或不明确。 |
| **Behavior** | 可观察到的 Agent 动作和模式，包括使用工具、遗漏、重试、失败和恢复。 |
| **Sentiment** | 用户的情绪状态或态度。 |

主题由相似的 Trace 信号聚类而成。各类信号独立聚类，因此同一条 Trace 可在 Goal、Outcome、Behavior 和 Sentiment 四个维度分别归入不同主题。

### 主题和关系 {/* #themes-and-relationships */}

关系图连接相邻 Trace 信号列中的主题：

- **节点**代表一个主题，数字是所选快照中归入该主题的不同 Trace 数量。
- **连带**连接相邻列中包含同一批 Trace 的主题。宽度表示共有的 Trace 数量。
- 将鼠标悬停在节点或连带上，或让它获得焦点，即可单独查看其关联。

图中展示的是关联，不能用来判断因果关系或执行顺序。例如，Goal 与 Outcome 之间的连带表示两个主题出现在同一批 Trace 中，不能据此推断目标导致了结果。

### Other 和 Noise {/* #other-and-noise */}

每个节点都显示所选快照中归入该主题的不同 Trace 数量。主题详情也显示占比，例如「此快照中共有 70 条 Trace，其中 28 条属于该主题（40%）」。

Studio 展示各类 Trace 信号最常见的主题，并可能将较小的主题合并到 **Other**，以保留总数并避免图表过于拥挤。

**Noise** 收录在所选快照中未能稳定归入任何重复主题的摘要。它不一定意味着错误或低质量交互，也可能包含少见的请求、新出现的模式、含义不明确的交互或不相关的情况。Noise 占比较高可能意味着流量非常多样，或数据不足以形成稳定主题。

### 快照 {/* #snapshots */}

快照涵盖滑动分析窗口内的一组 Trace。快照可能重叠，因此不要把计数相加。不同窗口的流量可能变化，比较时请同时参考主题的 Trace 数量和快照占比。

主题可能在不同快照间延续、消失、拆分、合并或再次出现。主题名称和描述是生成的摘要，不能当作固定分类。

## 使用 Trace Intelligence 页面 {/* #use-the-trace-intelligence-page */}

1. 打开 **Intelligence** 查看实体列表。搜索或排序后，选择实体查看分析。
1. 在图中选择主题，打开详情，并将各列筛选为包含该主题的 Trace。
1. 详情面板显示主题描述、快照占比、分页呈现的示例摘要，以及 Trace 数量随时间变化的趋势。
1. 选择 **Clear filter** 恢复完整的关系图。

信号仍在收集或处理时，实体就会出现在列表里。列表显示各实体已分析的 Trace 数量、已就绪和已启用的信号数量、生命周期状态和上次更新时间。

### 配置自定义信号 {/* #configure-a-custom-signal */}

组织管理员可直接在 Intelligence 中配置自定义信号：

1. 返回实体列表，选择 **Signal settings**。
1. 选择 **Create signal**，填写固定的信号名称、显示标签、描述和指令，然后保存。整个组织共用定义及其版本。
1. 在 **Current project** 下启用信号。设置仅影响当前项目，且只适用于之后处理的 Trace。
1. 从列表打开实体，查看信号从收集、处理到就绪的状态变化。

可以编辑自定义信号的标签、描述或指令。修改指令会创建新版本，仅对新的 Trace 生效。也可以归档不再需要使用的定义，或日后恢复已归档的定义。

您还可以：

- 在关系图中选择 **Noise** 查看其占比及生成的示例摘要。
- 拖动图表上方的列标题，调整 Trace 信号的列顺序，从不同角度查看关系。
- 在时间轴上选择快照，或选择 **Play** 观看主题随时间的变化。
- 切换到 **Compare**，查看两个时间点之间哪些主题扩大、缩小、新进入或退出范围。也可切换到 **Lifelines**，追踪各主题在整个所选范围内的占比。

快照包含超过 2,000 条 Trace 时，不能按主题筛选关系图，但仍可选择主题查看详情。

## 故障排除 {/* #troubleshooting */}

### 侧栏没有 Intelligence {/* #intelligence-isnt-in-the-sidebar */}

确认 Mastra 已将正确的项目纳入测试、当前 Mastra 版本与测试版兼容，并且已重新部署 Studio。封闭测试不支持本地 Studio。

### 找不到某个 Agent {/* #an-agent-is-missing */}

确认 **Traces** 列出了该 Agent 已完成的 Trace，且项目已加入测试。开始生成信号后，Trace Intelligence 就会列出实体，无需等待首批主题就绪。如果刚达到 100 条，请等待异步处理。

### 无法查看关系图 {/* #the-relationship-flow-is-unavailable */}

关系图需要至少两类 Trace 信号各自产生主题。继续发送有代表性的流量，并等待处理完成。

### 大部分摘要都归入 Noise {/* #most-summaries-are-noise */}

收集更多有代表性的流量，再比较之后的快照。差异较大或少见的交互更难归类，反复使用测试提示词则可能让分布失去代表性。

## 封闭测试的限制 {/* #private-beta-limitations */}

- 只有已加入测试的项目才能在已部署的 Studio 中使用 Trace Intelligence。
- 初次分析要求每个 Agent 至少有 100 条已处理的 Trace。部分 Agent 可能需要更多。
- 结果取决于采集到的 Trace 的多样性和质量。
- 测试期间，Trace 信号摘要、主题标签、聚类、阈值和界面行为均可能变化。

提交反馈时，请附上组织 ID、项目 ID、Agent ID、所选快照，以及能说明问题的主题或 Noise 示例。
