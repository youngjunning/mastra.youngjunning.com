# Mastra 平台上的追踪情报

跟踪智能可以发现座席交互中重复出现的模式。它分析 Mastra Observability 捕获的跟踪，并生成四个内置维度的跟踪信号以及为项目启用的任何自定义信号。然后，它将相似的跟踪信号聚集到主题中。

使用 Trace Intelligence 来调查以下问题：

* 用户想要实现什么目标？
* 哪些目标往往会成功、哪些目标尚未实现或受到阻碍？
* 成功和不成功的交互中会出现哪些Agent行为？
* 用户情绪与目标和结果有何关系？

:::警告私人测试版
Trace Intelligence 可通过邀请获得选定的 Mastra 平台项目。
:::

## 获取访问权限 {/* #get-access */}

1. 提交[Trace Intelligence private beta form](https://mastra.ai/trace-intelligence) to request access.
2. 确认[Mastra platform Observability](/docs/mastra-platform/observability) is enabled and that completed agent traces appear under **Traces**.
3. 至少需要`@mastra/core@1.53.0` and `mastra@1.20.2`. Upgrade your project then deploy or redeploy Studio for the enrolled project. Local Studio and server-only deployments aren't supported during the private beta.
4. 打开部署的Studio并选择**Intelligence** in the sidebar.
5. 将代表性流量发送给您的Agent并留出时间进行分析。

Mastra 注册项目后，您无需更改Agent定义或调用。

### 当数据可用时 {/* #when-data-is-available */}

跟踪智能需要来自一个Agent的足够的经过处理的跟踪来识别重复出现的模式。初始主题通常至少在**100 completed traces** from that agent have been processed.

下的跟踪计数**Traces** can reach 100 before Trace Intelligence is ready because the analysis pipeline runs asynchronously. Processing can take several minutes after the threshold is reached. Traces that can't be analyzed don't contribute. As a result, 100 is a minimum rather than an exact UI trigger.

随着更多跟踪到达，跟踪智能会自动更新。 Studio 需要至少两种跟踪信号类型的主题，然后才能显示关系流。

使用代表性流量。一小组重复的测试提示可能会产生不具有代表性的结果，例如一个广泛的主题或大部分是噪音。

## 了解分析 {/* #understand-the-analysis */}

每个可分析的已完成跟踪都会生成四个内置跟踪信号，以及为项目启用的任何自定义信号：

|跟踪信号|意义|
| - | - |
|**Goal** | What the user is trying to achieve or have completed. |
| **Outcome** | The final completed, partial, blocked, failed, unresolved, or unclear state. |
| **Behavior** | Observable agent actions and patterns, including tool use, omissions, retries, failures, and recovery. |
| **Sentiment** | The user's emotional state or attitude. |

主题是由相似的跟踪信号生成的簇。对于每个跟踪信号类型，聚类都是独立发生的。一条痕迹可以属于每个维度中的一个单独主题：目标、结果、行为和情绪。

### 主题和关系 {/* #themes-and-relationships */}

该流程图连接相邻跟踪信号列中的主题：

* 一个**node** represents a theme. Its count is the number of distinct traces assigned to that theme in the selected snapshot.
* 一个**ribbon** connects traces assigned to themes in both adjacent columns. Its width represents the shared trace count.
* 将鼠标悬停在节点或功能区上或将其聚焦以隔离其关系。

该流程显示关联，而不是因果关系或执行顺序。例如，目标和结果之间的丝带意味着两个主题出现在相同的轨迹中。它并不表明目标导致了结果。

### 其他和噪音 {/* #other-and-noise */}

每个节点都会显示其跟踪计数：在所选快照中分配给该主题的不同跟踪的数量。主题的详细信息还说明了其份额，例如“此快照中 70 条跟踪中的 28 条 (40%)”。

Studio 显示每种跟踪信号类型最常见的主题。它可以将较小的主题组合成**Other** to preserve totals without overcrowding the chart.

**噪音**包含与所选快照中的重复主题不一致的摘要。它不一定表示错误或低质量的交互。噪音可能包括罕见的请求和新出现的模式。它还可能包含不明确的交互或不相关的案例。较大的噪声份额可能表明流量变化很大或稳定主题的数据不足。

### 快照 {/* #snapshots */}

快照是一组轨迹上的移动分析窗口。快照可以重叠，因此不要将它们的跟踪计数加在一起。将主题的跟踪计数及其快照份额放在一起比较，因为窗口之间的流量可能会发生变化。

主题可以在快照中保留、消失、拆分、合并或返回。将主题名称和描述视为生成的摘要，而不是固定的分类法。

## 使用跟踪情报页面 {/* #use-the-trace-intelligence-page */}

1. 打开**Intelligence** to see the entity index. Search or sort the index, then select an entity to open its analysis.
2. 在流程中选择一个主题以打开其详细信息并过滤每一列以查找包含该主题的跟踪。
3. 详细信息面板显示主题的描述、快照份额、分页示例摘要以及跟踪计数随时间变化的趋势。
4. 选择**Clear filter** to restore the complete flow.

实体在其信号仍在收集或处理时出现。该索引显示每个实体的分析跟踪计数、就绪和启用的信号计数、生命周期状态和上次更新。

### 配置自定义信号 {/* #configure-a-custom-signal */}

组织管理员可以在不离开 Intelligence 的情况下配置自定义信号：

1. 返回实体索引并选择**Signal settings**.
2. 选择**Create signal**, provide a stable signal name, display label, description, and signal instructions, then save it. Definitions and their versions are shared across the organization.
3. 启用下信号**Current project**. Project enablement affects only the current project and applies to newly processed traces.
4. 从索引中打开一个实体，并在其从收集到处理并准备就绪时跟踪其信号状态。

您可以编辑自定义信号的标签、描述或说明。指令更改会创建新版本并仅适用于新跟踪。您还可以存档不再可用的定义或稍后恢复存档的定义。

您还可以：

* 选择**Noise** in the flow to inspect its share and generated example summaries.
* 拖动图表上方的列标题以重新排序跟踪信号列并查看不同的关系视角。
* 使用时间线选择快照，或选择**Play** to watch themes change over time.
* 切换到**Compare** to see which themes grew, shrank, entered the range, or left the range between two points in time, or **Lifelines** to follow each theme's share across the whole selected range.

对于具有超过 2,000 条跟踪的快照，无法按主题过滤流。选择主题仍会在那里打开其详细信息，而不过滤流程。

## 故障排除 {/* #troubleshooting */}

### 情报不在侧边栏中 {/* #intelligence-isnt-in-the-sidebar */}

确认 Mastra 注册了正确的项目，您使用与测试版兼容的 Mastra 版本，并且您重新部署了 Studio，因为私有测试版不支持本地 Studio。

### 缺少Agent {/* #an-agent-is-missing */}

确认其完整的跟踪列在下面**Traces** and that the project is enrolled. Trace Intelligence lists an entity after signal generation begins, before its first themes are ready. If it recently reached 100 traces, allow time for asynchronous processing.

### 关系流不可用 {/* #the-relationship-flow-is-unavailable */}

该流程需要至少两种跟踪信号类型的主题。继续发送代表性流量并允许处理完成。

### 大多数摘要都是噪音 {/* #most-summaries-are-noise */}

收集更具代表性的流量并比较稍后的快照。多样化或罕见的相互作用更难分组，而重复的测试提示可能会产生不具有代表性的分布。

## 内测限制 {/* #private-beta-limitations */}

* Trace Intelligence 仅适用于已部署 Studio 中已注册的项目。
* 初始分析需要每个Agent至少 100 个已处理的跟踪。有些Agent商可能需要更多。
* 结果取决于捕获痕迹的多样性和质量。
* 跟踪信号摘要、主题标签、聚类、阈值和 UI 行为在测试期间可能会发生变化。

报告反馈时，请包括组织 ID、项目 ID、Agent ID、选定的快照以及说明问题的主题或噪声示例。
