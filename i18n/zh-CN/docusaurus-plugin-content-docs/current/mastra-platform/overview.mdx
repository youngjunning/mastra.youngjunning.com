# 马斯特拉平台

这[Mastra platform](https://projects.mastra.ai)提供了三种用于部署、监控和管理使用 Mastra 框架构建的 AI 应用程序的产品：

* [**可观察性**](/docs/mastra-platform/observability)：每个平台项目的基准产品，具有跨 Mastra 项目和部署的可搜索跟踪、日志和指标
* [**工作室**](/docs/mastra-platform/studio)：用于测试Agent和运行Workflow程的托管可视环境，以及用于检查跟踪的Tool。从 Studio 开始还可以为您提供可观察性。
* [**服务器**](/docs/mastra-platform/server)：作为 API 服务器运行 Mastra 应用程序的生产部署目标。从服务器开始还可以为您提供可观察性。

使用单个命令进行部署，[`mastra deploy`](/docs/mastra-platform/deploy), or connect a GitHub repository for push-to-deploy. See the [GitHub integration](/docs/mastra-platform/github) for the repository-linked flow.

每个项目可以运行多个[**Environments**](/docs/mastra-platform/environments) (for example `production` and `staging`) and provision [**Hosted databases**](/docs/mastra-platform/database) from the CLI or project settings to persist application data. Each environment also gets a managed [**Workspace**](/docs/mastra-platform/workspaces) that gives agents a filesystem and sandbox with no manual configuration.

组织层面[**Alerts**](/docs/mastra-platform/alerts) notify your team when deploys fail or running services stop. Alerts can cover every project or selected projects and environments, with notifications sent to Slack, email, or webhooks.

[**连接**](/docs/mastra-platform/connect)将您的帐户存储在 Linear、Slack 和 GitHub 等Provider上，因此Agent可以将它们用作Tool和聊天渠道，而无需您创建Provider应用程序或管理 API 密钥。

[**追踪情报**](/docs/mastra-platform/trace-intelligence)在您的座席轨迹中查找重复出现的目标、结果、行为和情绪。 Trace Intelligence 已针对选定项目推出内测版。

## 开始使用 {/* #get-started */}

选择与您想要执行的操作相匹配的路径：

* **添加托管可观察性**： 使用[Observability](/docs/mastra-platform/observability) to collect searchable traces, logs, and metrics across projects and deploys. Start here if you want monitoring without deploying Studio or Server first.
* **部署工作室**： 使用[Studio](/docs/mastra-platform/studio) to host the visual development environment for your team. Start here if you want a shared UI for testing agents and running workflows, as well as inspecting traces.
* **部署服务器**： 使用[Server](/docs/mastra-platform/server) to run your Mastra application as a production API server. Start here when you’re ready to serve agents, tools, and workflows from the cloud.
* **建立一个软件工厂：**&#x90E8;署[Mastra Factory](https://factory.mastra.ai) to Mastra platform and connect your repository to turn issues into plans, implementations, and reviewed pull requests.

## 关键概念 {/* #key-concepts */}

**项目**是所有产品的共享父实体。单个项目可以包含每个产品：Observability、Studio 和 Server。项目属于**Organization**, which is the multi-tenant container for your team.

您的 Mastra 应用程序由三个构建块构建：

* [Agent商](/docs/agents/overview)：人工智能Agent可以使用Tool并遵循指令，同时保持上下文
* [Tool](/docs/agents/tools)：可供您的Agent使用的可调用功能和集成
* [Workflow程](/docs/workflows/overview)：协调Agent和Tool的多步骤编排管道

## 即将投入生产 {/* #going-to-production */}

在本地开发您的项目[`mastra dev`](/reference/cli/mastra#mastra-dev) and open [Studio](/docs/studio/overview) to test your agents, workflows, and tools in a visual environment.

准备好将应用程序部署到生产环境后，运行[`mastra deploy`](/reference/cli/mastra#mastra-deploy) to push your application to the cloud.

遵循[Deploy](/docs/mastra-platform/deploy) docs for step-by-step instructions.

如果您在自己的基础设施上托管 Mastra 应用程序，您仍然可以使用以下方式将Observability数据发送到 Mastra 平台：[MastraPlatformExporter](/docs/mastra-platform/observability).
