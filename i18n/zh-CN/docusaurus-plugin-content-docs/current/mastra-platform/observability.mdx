# Mastra 平台的可观测性

Mastra 平台可观测性收集 Mastra 应用的 Trace、日志、指标、评分和反馈。使用它可获得托管可观测性，无需部署 Studio 或 Server，也无需配置本地可观测性存储。

## 快速入门 {/* #quickstart */}

选择适合项目的配置方式。

### 新项目 {/* #new-project */}

创建托管的 Mastra 项目，并在提示时启用 Mastra 平台可观测性：

```bash npm2yarn
npm create mastra@latest
```

create 命令会向 Mastra 平台认证并创建可观测性项目，然后生成访问 Token，将 `MASTRA_PLATFORM_ACCESS_TOKEN` 和 `MASTRA_PROJECT_ID` 写入 `.env`。

### 现有项目 {/* #existing-project */}

如果要在现有应用中加入 Mastra，请运行 `mastra init`，并在提示时启用 Mastra 可观测性：

```bash npm2yarn
npx mastra init
```

init 命令可选择现有平台项目或创建新项目，然后生成访问 Token，将凭据写入 `.env`。

## 手动配置 {/* #configure-manually */}

如果跳过平台设置或自动配置失败，请手动配置。

1. 在 [Mastra 平台](https://projects.mastra.ai)创建或打开项目。
1. 为项目所属组织创建访问 Token。
1. 从项目页面复制项目 ID。
1. 将这两个值加入 `.env`：

```bash title=".env"
MASTRA_PLATFORM_ACCESS_TOKEN=<your-platform-access-token>
MASTRA_PROJECT_ID=<your-project-id>
```

在可观测性配置中注册 [`MastraPlatformExporter`](/reference/observability/tracing/exporters/mastra-platform-exporter)：

```typescript title="src/mastra/index.ts"
import { Mastra } from '@mastra/core/mastra'
import { MastraPlatformExporter, Observability } from '@mastra/observability'

export const mastra = new Mastra({
  observability: new Observability({
    configs: {
      default: {
        serviceName: 'my-service',
        exporters: [new MastraPlatformExporter()],
      },
    },
  }),
})
```

Exporter 会从环境中读取访问 Token 和项目 ID。保持 `serviceName` 稳定，以便在过滤可观测性数据时区分应用与部署。

`MastraPlatformExporter` 会发送已结束的 Span、日志、指标、评分和反馈。它会缓冲事件，在累积到 1,000 个事件或等待五秒后发送一批。模型 Chunk Span 不会导出。

:::note

`MastraPlatformExporter` 已取代 `CloudExporter`。`CloudExporter` 仍可用于向后兼容，但已弃用。新代码请使用 `MastraPlatformExporter`。

:::

### 将数据存储在本地 {/* #store-data-locally */}

如果还希望将可观测性数据持久化到已配置的 Mastra 存储，并在本地 Studio 中查看，请添加 `MastraStorageExporter`：

```typescript title="src/mastra/index.ts"
import { Mastra } from '@mastra/core/mastra'
import { MastraPlatformExporter, MastraStorageExporter, Observability } from '@mastra/observability'

export const mastra = new Mastra({
  observability: new Observability({
    configs: {
      default: {
        serviceName: 'my-service',
        exporters: [new MastraPlatformExporter(), new MastraStorageExporter()],
      },
    },
  }),
})
```

存储要求和配置请参阅 [Mastra 存储 Exporter](/docs/observability/integrations/exporters/mastra-storage)。

## 查看可观测性数据 {/* #view-observability-data */}

在 [Mastra 平台](https://projects.mastra.ai)打开项目，可查看导出的 Trace、日志、指标和评分，无需部署 Studio 或 Server。导出反馈可通过下述托管反馈 API 查询。

使用一致的 `serviceName`，可按特定应用或部署过滤数据。

## 查询可观测性数据 {/* #query-observability-data */}

使用 Mastra CLI 在终端浏览托管 Trace：

```bash npm2yarn
npx mastra api trace list
```

CLI 从项目环境读取 `MASTRA_PLATFORM_ACCESS_TOKEN` 和 `MASTRA_PROJECT_ID`，默认连接美国可观测性端点。其他认证方式和区域端点请参阅 [CLI 目标解析](/reference/cli/mastra#target-resolution)。

使用 `mastra api trace query` 根据 Trace 字段或关联的 Span 查找已完成的 Trace。例如，查找根 Span 耗时超过五秒的 Trace：

```bash
npx mastra api trace query '{
  "timeRange": {
    "from": "2026-08-01T00:00:00.000Z",
    "to": "2026-08-08T00:00:00.000Z"
  },
  "where": {
    "op": "gt",
    "left": { "path": "durationMs" },
    "right": { "literal": 5000 }
  },
  "page": { "limit": 25 }
}'
```

请选择包含已导出 Trace、且处于套餐数据保留期内的时间范围，并确保 `from` 早于 `to`。结果位于 `data.traces`。

Mastra 平台沿用 Mastra Server 的查询与聚合请求结构。HTTP 端点、过滤器、响应结构、分页和发现方法请参阅 [Trace 与 Span 查询参考文档](/reference/observability/tracing/advanced-queries)：

| 任务 | CLI 命令 | 参考文档 |
| - | - | - |
| 查找匹配的 Trace | `mastra api trace query` | [查询 Trace](/reference/observability/tracing/advanced-queries#query-traces) |
| 查找单个 Span，包括嵌套运行 | `mastra api span query` | [查询 Span](/reference/observability/tracing/advanced-queries#query-spans) |
| 统计匹配的 Trace | `mastra api trace aggregate` | [聚合 Trace](/reference/observability/tracing/advanced-queries#aggregate-traces) |
| 统计单个 Span | `mastra api span aggregate` | [聚合 Span](/reference/observability/tracing/advanced-queries#aggregate-spans) |

每条命令都接收一个 JSON 参数，响应内容位于 `data` 下。

### 平台范围和差异 {/* #platform-scope-and-differences */}

使用 HTTP 请求头 `X-Mastra-Project-Id` 选择单个项目。CLI 会从 `MASTRA_PROJECT_ID`、显式请求头或项目配置中设置该值。如果不指定项目范围，具有组织级访问权限的凭据可以跨项目查询；限定到项目的凭据仍只能访问其项目。项目范围与查询条件分开指定：不要在 `where` 中加入 `projectId`。

平台增加以下字段和分组方式：

| 操作 | 平台新增能力 |
| - | - |
| `queryTraces()` 和 `querySpans()` | 每条结果都包含 `projectId`。 |
| `aggregateTraces()` | 支持 `groupBy: ['projectId']` 和 `countDistinct.projectId`。 |
| `aggregateSpans()` | 支持 `groupBy: ['projectId']`，但不支持 `countDistinct.projectId`。 |

数据保留期取决于套餐：Starter 为 15 天，Teams 为 6 个月，Enterprise 为自定义时长。当前套餐限制请参阅[定价页](https://mastra.ai/pricing)。

### 其他可观测数据 {/* #other-observability-data */}

导出的反馈可通过 HTTP 查询。当前状态、区域端点、认证、项目范围，以及 `traceId` 和 `environment` 等查询参数，请参阅[反馈 API](/docs/mastra-platform/api#feedback-api)。

导出的指标可通过 HTTP、`MastraClient` 或 `mastra api metric` 查询。区域端点、认证、项目范围和支持的端点请参阅[指标 API](/docs/mastra-platform/api#metrics-api)。

## 导入现有 Trace {/* #import-existing-traces */}

使用 `mastra traces import`，可将受支持 Provider 的现有 Trace 历史迁移到现有 Mastra 平台项目。该命令从源端读取并验证完整 Trace，将其转换为 Mastra Span，然后使用统一流程完成准备、上传、续传和验证。

导入命令目前支持 Langfuse。添加其他 Provider 适配器后，也可沿用相同的命令流程。

| Provider | 命令参数 | 源端要求 |
| - | - | - |
| Langfuse | `langfuse` | Langfuse Cloud 或自托管 Langfuse v4 及以上版本 |

### 先决条件 {/* #prerequisites */}

开始导入前，你需要：

- 一个 Mastra 平台项目。
- 通过 `mastra auth login` 完成 Mastra 平台认证；无交互环境则提供 `MASTRA_API_TOKEN` 和 `MASTRA_ORG_ID`。
- 交互式登录时用于上传和回读的 `MASTRA_PLATFORM_ACCESS_TOKEN`。试运行不需要此 Token。
- 受支持源 Provider 的凭据。
- 足够的本地磁盘空间，用于临时存放准备好的 Trace。

### 配置目的地 {/* #configure-the-destination */}

交互式导入时，请登录并选择目标项目所属组织：

```bash
npx mastra auth login
npx mastra auth orgs switch
```

交互式登录允许发现项目。上传或验证 Trace 前，请设置目标项目使用的平台访问 Token：

```bash title=".env"
MASTRA_PLATFORM_ACCESS_TOKEN=<mastra-platform-access-token>
```

如果 `mastra init` 已为项目配置可观测性，可使用它写入 `.env` 的 Token；否则，请在 [Mastra 平台](https://projects.mastra.ai)创建访问 Token。

`--dry-run` 不需要此 Token，因为试运行不会连接收集器或查询 API。

`--target-project` 指定接收 Trace 的 Mastra 平台目标项目。可传入项目名称、slug 或 ID，也可设置 `MASTRA_PROJECT_ID`：

```bash
npx mastra traces import langfuse --target-project my-mastra-project --dry-run
```

`--target-project` 优先于 `MASTRA_PROJECT_ID`。如果两者都未提供，CLI 会使用 `.mastra-project.json` 中关联的项目。

源项目不是命令行选项，而是由 `.env` 中的 Provider 凭据确定。上传任何内容前，准备摘要会列出源项目。

对于无交互环境，请设置 API Token 和组织 ID。命令使用 `MASTRA_API_TOKEN` 发现项目、上传和回读。还需设置项目 ID 或传入 `--target-project`：

```bash title=".env"
MASTRA_API_TOKEN=<mastra-api-token>
MASTRA_ORG_ID=<organization-id>
MASTRA_PROJECT_ID=<project-id>
```

### 配置Langfuse {/* #configure-langfuse */}

Langfuse API 密钥只属于一个 Langfuse 项目，因此也决定了源项目。请在 Langfuse [创建项目 API 密钥](https://langfuse.com/docs/api-and-data-platform/features/public-api)，然后将其加入执行命令所在目录的 `.env` 或 `.env.local`：

```bash title=".env"
LANGFUSE_PUBLIC_KEY=<langfuse-public-key>
LANGFUSE_SECRET_KEY=<langfuse-secret-key>
```

Langfuse Cloud 默认使用 `https://cloud.langfuse.com` 的欧盟区域。若使用美国、日本、HIPAA Cloud 或自托管实例，请将 `LANGFUSE_BASE_URL` 设为对应的[区域主机](https://langfuse.com/security/data-regions)或自托管实例的源地址：

```bash title=".env"
LANGFUSE_BASE_URL=https://us.cloud.langfuse.com
```

### 预览导入 {/* #preview-the-import */}

上传前先试运行：

```bash
npx mastra traces import langfuse --target-project my-mastra-project --dry-run
```

试运行会读取源数据，在本地准备有效的 Mastra Trace，并报告：

- 源 Langfuse 项目的名称和 ID，以及目标 Mastra 平台项目。
- 固定的导入时间窗口。
- 已准备和已跳过的 Trace 与 Span 数量。
- 已准备的本地数据大小。
- `report.json` 中的 Provider 警告与跳过原因。

试运行不会上传 Trace。命令会输出一条 `--resume` 命令，可在以后不重新读取源数据的情况下上传已准备的数据。

### 选择导入窗口 {/* #choose-the-import-window */}

默认选择截至导入开始时的过去 30 天。使用 `--since` 和 `--until` 可选择更短的时间窗口：

```bash
npx mastra traces import langfuse \
  --target-project my-mastra-project \
  --since "$SINCE" \
  --until "$UNTIL" \
  --dry-run
```

将 `SINCE` 和 `UNTIL` 设为 ISO 8601 日期或时间戳，并遵守以下规则：

- `--until` 必须在过去 30 天内，且不能是未来时间。
- `--since` 必须早于 `--until`，且处于过去 30 天内。
- 所选时间窗口不能超过 30 天。
- 如果只设置 `--until`，默认开始时间是当前时间往前 30 天。

这个 30 天导入窗口与套餐的数据保留期相互独立。

旧参数 `--from` 和 `--to` 仍可用，但它们是 `--since` 和 `--until` 已弃用的隐藏别名，不会出现在命令帮助中。新命令请使用 `--since` 和 `--until`。

Trace 是否纳入导入，以根 Observation 的开始时间为准。Langfuse 适配器在所选窗口中找到根节点，再读取每条所选 Trace 当前可用的全部 Observation。如果可用的父子树或时间戳无效，就会跳过整条 Trace。

### 上传并验证 {/* #upload-and-verify */}

运行命令时不传 `--dry-run`，即可上传已准备的 Trace：

```bash
npx mastra traces import langfuse --target-project my-mastra-project
```

CLI 会显示准备摘要，并在上传前要求确认。在自动化环境中可传入 `--yes` 跳过提示：

```bash
npx mastra traces import langfuse --target-project my-mastra-project --yes
```

导入器会将每条 Trace 完整放入同一个上传请求，并只在 Mastra 平台确认整批数据后记录进度检查点。源端或目标端的临时故障会进行有限次数的重试。

所有已准备的 Trace 获确认后，导入器会回读最多 10 条 Trace 的确定性样本，核对 Span ID、父子关联、名称、Span 类型、事件标志、时间戳及是否存在错误。它不会回读或比较输入、输出、属性、元数据或标签。

如果尚无法回读，或样本 Trace 存在差异，导入会暂停并保留已准备的数据。恢复导入可重试验证，而无需再次上传已确认的 Trace。

### 恢复导入 {/* #resume-an-import */}

试运行、取消、中断、上传失败或暂停验证后，如导入尚未完成，请使用 CLI 输出的原始命令恢复：

```bash
npx mastra traces import langfuse \
  --resume 00000000-0000-0000-0000-000000000000 \
  --target-project my-mastra-project
```

恢复导入时必须使用原来的 Provider 和目标项目。已保存的时间窗口不能更改，因此 `--resume` 不得与 `--since`、`--until` 或 `--dry-run` 同时使用。

恢复方式取决于命令中断的位置：

- 准备阶段中断：重新读取并准备源数据。
- 上传阶段中断：从第一条未确认的 Trace 开始。
- 验证暂停：重新回读验证，不重复上传已确认的 Trace。
- 导入已完成：报告已完成状态，并重试剩余的本地清理。

### 本地文件和清理 {/* #local-files-and-cleanup */}

导入状态存储于：

```text
~/.mastra/imports/traces/<target-project-id>/<import-id>/
```

| 文件 | 用途 | 生命周期 |
| - | - | - |
| `manifest.json` | 保存源端身份、时间窗口、计数和已确认进度。 | 完成后保留。 |
| `traces.jsonl` | 每行保存一条完整且已规范化的 Trace。 | 试运行和未完成导入时保留，验证成功后删除。 |
| `report.json` | 保存计数、警告、跳过样本和验证结果。 | 写入后保留。 |

这些文件可能包含 Trace 内容。Mastra 创建导入目录和文件时，会将权限限制为本地用户。请保护运行导入的设备和账号。

### 导入的数据和限制 {/* #imported-data-and-limits */}

Langfuse 导入具有以下行为：

- Observation 会成为 Mastra Span，并保留父子关系和时间戳。
- Langfuse `AGENT`、`TOOL` 和 `EVALUATOR` Observation，以及包含 `gen_ai.operation.name: invoke_agent` 等 OpenTelemetry GenAI 属性的普通 Span，会保留其 Primitive 类型和名称。Mastra 平台会像处理原生 Trace 一样，在 Primitive type 和 Primitive name 列中显示，并纳入相应过滤器。
- 支持的字段（如名称、输入、输出、错误、模型详情、用量、成本、标签和源上下文）会在存在时映射。
- Langfuse 中自行设置的环境（如 `staging`）会保留。Langfuse 内置的 `default` 环境不会复制；这些 Trace 在 Mastra 中没有环境，Mastra Studio 会在每个环境中显示它们。
- 目标 Trace 和 Span ID 是确定性的。原始 Langfuse ID 保留在 Span 元数据中，用于关联。
- 未知的 Langfuse Observation 类型会变成通用 Span，并发出警告，不会被静默丢弃。
- 只导入 Trace Observation。评分、反馈、数据集、附件和日志都不会导入。

统一导入器还受以下限制：

- 每次导入准备的本地 Trace 数据上限为 5 GiB。如达到上限，请缩短时间窗口。
- 单条完整 Trace 必须符合导入器 4 MiB 上传负载上限。超出上限会被跳过，并记录 `trace_too_large` 原因。
- 不会将一条 Trace 拆分到多个上传请求中。

试运行或完成导入后，请查看 `report.json`，核对具体准备、跳过、确认和验证的内容。

完整选项和环境变量请参阅 [`mastra traces import` CLI 参考文档](/reference/cli/mastra#mastra-traces-import)。
