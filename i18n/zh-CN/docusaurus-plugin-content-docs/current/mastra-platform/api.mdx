## Feedback API {/* #feedback-api */}

Feedback API 用于列出和分析导出到 Mastra Platform Observability 的反馈。该 API 未设版本，因此不保证向后兼容。速率限制、数据保留期限以及从摄取到可查询的延迟均未作为公开契约发布。

这些端点的查询参数、请求体和响应类型与 Mastra 运行时的反馈路由相同。完整契约见[反馈参考文档](/reference/observability/feedback)，包括[列表查询参数](/reference/observability/feedback#list-query-parameters)和 [`FeedbackFilter`](/reference/observability/feedback#feedbackfilter)。

请使用环境所属数据驻留区域的根 URL：

| 区域 | 根 URL |
| - | - |
| 美国 | `https://observability.mastra.ai/api/observability` |
| 欧盟 | `https://observability.eu.mastra.ai/api/observability` |

遥测数据始终留在其驻留区域。查询另一区域不会返回该环境的记录。环境与区域的对应关系见[可观测性同区域部署](/docs/mastra-platform/regions#observability-co-location)。

### 身份认证与项目范围 {/* #authentication-and-project-scope */}

每个请求都需要 Platform 访问令牌。可在 [Mastra Platform](https://projects.mastra.ai) 创建，也可使用设置 Platform 时写入 `.env` 的令牌。

带上 `X-Mastra-Project-Id` 可将结果限定为一个项目。若省略，查询将涵盖该令牌所属组织可访问的所有项目中的反馈。

```bash
curl -sS "https://observability.mastra.ai/api/observability/feedback?page=0&perPage=20&feedbackType=rating" \
  -H "Authorization: Bearer $MASTRA_PLATFORM_ACCESS_TOKEN" \
  -H "X-Mastra-Project-Id: $MASTRA_PROJECT_ID" | jq
```

请使用组织范围的 Platform 访问令牌；不接受 `mk_*` 等 Gateway 推理密钥。即使提供项目 ID，查询仍只限于令牌所属组织。

### 端点 {/* #endpoints */}

| 方法 | 端点 | 说明 |
| - | - | - |
| GET | `/feedback` | 列出反馈记录 |
| POST | `/feedback/aggregate` | 返回一个聚合值 |
| POST | `/feedback/breakdown` | 按维度分组反馈 |
| POST | `/feedback/timeseries` | 按时间间隔分组反馈 |
| POST | `/feedback/percentiles` | 返回百分位数序列 |

列表端点将每个 [`FeedbackFilter`](/reference/observability/feedback#feedbackfilter) 字段作为同名查询参数，例如 `traceId`、`spanId`、`feedbackType`、`feedbackSource`、`environment`、`entityName`、`experimentId` 或 `tags`。如需指定多个值，可重复参数，例如 `feedbackType=rating&feedbackType=thumbs`。

```bash
curl -sS "https://observability.mastra.ai/api/observability/feedback?traceId=trace-123&environment=production" \
  -H "Authorization: Bearer $MASTRA_PLATFORM_ACCESS_TOKEN" \
  -H "X-Mastra-Project-Id: $MASTRA_PROJECT_ID" | jq
```

| 参数 | 说明 |
| - | - |
| `page`, `perPage` | 从零开始的页码和每页条数（1 至 100）；默认分别为 `0` 和 `10`。 |
| `field`, `direction` | 按 `timestamp` 以 `ASC` 或 `DESC` 排序；默认 `DESC`。 |
| `mode=delta` | 从分页切换为增量轮询。 |
| `after` | 上一次增量响应返回的游标；仅用于增量模式。 |
| `limit` | 每次增量轮询的更新数量上限（1 至 100）；仅用于增量模式。 |

响应包含 `feedback` 数组，以及分页或增量元数据。包括 `timestamp` 等以 JSON 编码的对象过滤器在内的完整参数契约，见反馈参考文档的[列表查询参数](/reference/observability/feedback#list-query-parameters)。

分析端点接受与[反馈参考文档](/reference/observability/feedback)相同的 JSON 请求结构，并返回相同类型的结果。分析只处理数值型反馈。

```bash
curl -sS "https://observability.mastra.ai/api/observability/feedback/aggregate" \
  -X POST \
  -H "Authorization: Bearer $MASTRA_PLATFORM_ACCESS_TOKEN" \
  -H "X-Mastra-Project-Id: $MASTRA_PROJECT_ID" \
  -H "Content-Type: application/json" \
  --data '{"feedbackType":"rating","feedbackSource":"user","aggregation":"avg"}' | jq
```

凭据无效时，API 返回 `401`；组织授权失败时返回 `403`；查询参数或 JSON 请求体格式错误时返回 `400`。

托管可观测性不提供创建反馈的路由。请按[将反馈导出到 Mastra Platform](/docs/observability/feedback#export-feedback-to-mastra-platform)的说明，从应用中导出反馈。

### 身份认证与项目范围 {/* #authentication-and-project-scope-1 */}

每个请求都需要 Platform 访问令牌。可在 [Mastra Platform](https://projects.mastra.ai) 创建，也可使用设置 Platform 时写入 `.env` 的令牌。

带上 `X-Mastra-Project-Id` 可将结果限定为一个项目。若省略，查询将涵盖该令牌所属组织可访问的所有项目中的指标。

```bash
curl -sS "https://observability.mastra.ai/api/observability/discovery/metric-names?prefix=mastra_model_" \
  -H "Authorization: Bearer $MASTRA_PLATFORM_ACCESS_TOKEN" \
  -H "X-Mastra-Project-Id: $MASTRA_PROJECT_ID" | jq
```

请使用组织范围的 Platform 访问令牌；不接受 `mk_*` 等 Gateway 推理密钥。即使提供项目 ID，查询仍只限于令牌所属组织。

### 端点 {/* #endpoints-1 */}

| 方法 | 端点 | 说明 |
| - | - | - |
| GET | `/metrics` | 列出原始指标记录 |
| POST | `/metrics/aggregate` | 返回一个聚合值 |
| POST | `/metrics/breakdown` | 按维度分组指标 |
| POST | `/metrics/timeseries` | 按时间间隔分组指标 |
| POST | `/metrics/percentiles` | 返回单个指标的百分位数序列 |
| GET | `/discovery/metric-names` | 列出指标名称 |
| GET | `/discovery/metric-label-keys` | 列出某指标的标签键 |
| GET | `/discovery/metric-label-values` | 列出某指标标签键的值 |

列表和发现端点通过查询参数接收参数。各端点接受的参数见指标查询参考文档中的 [`listMetrics(args)`](/reference/observability/metrics/queries#listmetricsargs) 和[指标发现](/reference/observability/metrics/queries#metric-discovery)。

分析端点接受与[指标查询参考文档](/reference/observability/metrics/queries#analytics-methods)相同的 JSON 请求体，并返回相同类型的结果，包括 `name`、`aggregation`、`filters`、`groupBy`、`interval`、`percentiles`、`comparePeriod`、`limit`、`orderDirection` 和 `distinctColumn`。

```bash
curl -sS "https://observability.mastra.ai/api/observability/metrics/aggregate" \
  -X POST \
  -H "Authorization: Bearer $MASTRA_PLATFORM_ACCESS_TOKEN" \
  -H "X-Mastra-Project-Id: $MASTRA_PROJECT_ID" \
  -H "Content-Type: application/json" \
  --data '{"name":["mastra_model_total_input_tokens","mastra_model_total_output_tokens"],"aggregation":"sum","filters":{"timestamp":{"start":"2026-09-13T00:00:00Z","end":"2026-10-13T00:00:00Z"}},"comparePeriod":"previous_period"}' | jq
```

`filters.timestamp` 可选。省略 `start` 和 `end` 时，查询会涵盖所有已保留的数据。`comparePeriod` 要求同时提供 `start` 和 `end`；否则，上一周期的字段为 `null`。

凭据无效时，API 返回 `401`；组织授权失败时返回 `403`；查询参数或 JSON 请求体格式错误时返回 `400`。

#### `MastraClient` {/* #mastraclient */}

`@mastra/client-js` 中的 `MastraClient` 提供分析和发现方法。将 `baseUrl` 设为区域主机地址，不要包含 `/api/observability` 路径：

```typescript
import { MastraClient } from '@mastra/client-js'

const mastraClient = new MastraClient({
  baseUrl: 'https://observability.mastra.ai',
  headers: {
    Authorization: `Bearer ${process.env.MASTRA_PLATFORM_ACCESS_TOKEN}`,
    'X-Mastra-Project-Id': process.env.MASTRA_PROJECT_ID!,
  },
})

const result = await mastraClient.getMetricAggregate({
  name: ['mastra_model_total_input_tokens', 'mastra_model_total_output_tokens'],
  aggregation: 'sum',
})
```

#### CLI {/* #cli */}

[`mastra api metric`](/reference/cli/mastra#mastra-api-metric-aggregate) 命令默认访问美国端点。要查询欧盟区域，请传入 `--url`：

```bash
mastra api --url https://observability.eu.mastra.ai metric aggregate '<json>'
```
