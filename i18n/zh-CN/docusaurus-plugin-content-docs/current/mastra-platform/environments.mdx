# 环境

每个平台项目都包含一个或多个环境。

环境是一个独立的部署目标，具有自己的 URL、环境变量和部署历史记录。也可以有自己的[hosted database](/docs/mastra-platform/database).

使用环境来运行`production`, `staging`，以及单个项目中相同代码库的预览版本。

首次执行 [`mastra deploy`](/docs/mastra-platform/deploy) 时会创建 `production` 环境。你可以用 CLI 创建更多环境，也可以部署到尚不存在的环境名称。

## 创建环境 {/* #create-an-environment */}

显式创建环境：

```bash
mastra env create staging
```

或者让部署创建它，这会提示您确认：

```bash
mastra deploy --env staging
```

`mastra env create` 默认创建 `staging` 类型的环境。用 `--type` 显式指定 `staging` 或 `preview`，用 `--region` 选择运行区域：

```bash
mastra env create eu-preview --type preview --region eu
```

每个项目只有一个 `production` 环境，由首次部署创建，区域创建后不可更改。关联的数据库会自动放在环境附近，可观测性数据则发往对应数据驻留区的接收区域。支持的区域、数据库放置规则及可观测性数据的同区域部署说明见[区域](/docs/mastra-platform/regions)。每个项目可创建的环境数量取决于你的套餐。

## 列出环境 {/* #list-environments */}

```bash
mastra env list
```

输出列出各环境的名称、区域、当前生效部署的状态，以及关联数据库注入的托管环境变量。在 CI 中传入 `--json` 可获取机器可读的输出。

所有 `mastra env` 命令依次从 `--project` 参数、`MASTRA_PROJECT_ID` 环境变量和首次部署写入的 `.mastra-project.json` 文件确定项目。直接在项目目录中运行命令即可，无需指定项目。

## 环境变量 {/* #environment-variables */}

环境从两个范围解析其变量：

- **托管变量**：由关联的[托管数据库](/docs/mastra-platform/database)（例如 `TURSO_DATABASE_URL`）或平台本身注入。变量由平台定义，无法编辑。完整列表见[系统环境变量](/docs/mastra-platform/system-environment-variables)。
* **环境范围的变量**：通过仪表板存储在每个环境中。当您将一个变量应用于多个环境时，每个环境都会保留自己的副本。将这些值用于环境之间不同的值，例如用于登台和生产服务的 API 密钥。

环境级变量就是[部署](/docs/mastra-platform/deploy#environment-variables)页中所述的已保存变量。部署某个环境时，只使用该环境的变量。仍走[旧版流水线](/docs/mastra-platform/deploy#migrating-from-server-and-studio-deploys)的项目在项目级保存变量，项目的每次部署都会使用这些变量。

部署开始时应用变量。要将更改的变量应用到正在运行的服务而不需要完全重新部署：

```bash
mastra env restart staging
```

要查看环境部署实际运行的设置，以及按名称列出的托管变量，请将它们拉入本地环境文件中。每个环境都是独立的。该文件永远不会混合在另一个环境的值中：

```bash
mastra env vars pull staging --output .env.staging
```

托管变量值在部署时注入，并且永远不会写入文件。它们仅显示为名称注释。

:::note
环境变量不会覆盖托管数据库变量。要切换数据库，请为该环境关联一个[环境级数据库](/docs/mastra-platform/database#attach-with-the-cli)。
:::

## 部署历史记录 {/* #deploy-history */}

列出跨所有环境的部署，或过滤到一个：

```bash
mastra env deploys
mastra env deploys staging
```

每行显示部署状态、环境、时间戳和当前生效的部署。状态按 **queued → uploading → starting → deploying → running** 推进；只有新版本开始处理流量后，平台才显示 **running**。由 GitHub 触发的部署会先从源码构建，因此在 **queued** 和 **uploading** 之间还有 **building**。

## 隔离环境数据 {/* #isolate-an-environments-data */}

托管数据库默认只供单个环境使用，因此生产环境和预发布环境各自读写自己的数据库：

```bash
mastra env db create production --kind turso --name my-project-production-db
mastra env db create staging --kind turso --name my-project-staging-db
```

如需让所有环境共用一个数据库，请用 `--shared` 关联：`mastra env db create --kind turso --shared`。

每个环境对每家 Provider 只能使用一个数据库。如果同一家 Provider 已有共享数据库（`--shared`），它会与环境级数据库发生变量名冲突。执行 `mastra env db delete` 前请导出需要保留的数据，因为该命令会删除这家 Provider 的共享数据库及其中的数据。完整的作用域规则参见[托管数据库](/docs/mastra-platform/database)。

## 删除环境 {/* #delete-an-environment */}

```bash
mastra env delete staging
```

CLI 在删除之前要求确认。删除环境会删除其部署和存储的变量。
