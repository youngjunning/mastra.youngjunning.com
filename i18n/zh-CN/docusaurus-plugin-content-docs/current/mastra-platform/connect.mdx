# Connect

:::beta 公开测试

公开测试期间，可在 Mastra 平台免费使用 Mastra Connect。

:::

Connect 在您的 [Mastra 平台](/docs/mastra-platform/overview)项目中管理 GitHub、Slack 和 Linear 等服务的连接。`@mastra/connect` 包通过三种方式向应用提供这些连接：

- **工具** 让 Agent 调用服务商的 API。Connect 提供现成的工具，并通过平台代理转发工具请求。代理会添加凭据并刷新 OAuth 令牌。
- **渠道** 让人们通过 Slack、Telegram、Discord 或 Microsoft Teams 与 Agent 对话。Connect 为 Mastra 的[渠道](/docs/channels) Provider 提供凭据。
- **原始凭据** 用于在现有工具无法满足需求时，从代码直接调用服务商的 SDK。

本页介绍所有服务商通用的设置。具体连接步骤和能力见各服务商的[集成页面](#providers)。

## 何时使用 Connect {/* #when-to-use-connect */}

如果希望由平台管理服务商账号，请使用 Connect。应用无需保存凭据或刷新 OAuth 令牌。新增或替换连接无需修改 Agent 代码。工具解析器会在刷新缓存后识别连接变更，无需重新部署。

Connect 需要平台项目，但应用可在本地或自己的基础设施上运行。Connect 工具和渠道可与[自定义工具](/docs/agents/tools)和[自行管理的渠道](/docs/channels)并用。

## 连接的工作方式 {/* #how-connections-work */}

**服务商**是可连接的服务，以 `linear` 或 `google-mail` 等 ID 标识。每条**连接**为该服务的一个账号授权。连接归组织所有，同一条连接可关联多个项目，无需重新授权。

一个项目可以为同一服务商建立多条连接，例如连接不同 Slack 工作区的账号。请为每条连接设置不同的显示名称，方便 Agent 选对账号。

不同服务商提供的功能和授权方式各不相同。有些使用 OAuth，有些需要 API 密钥，渠道还可能要求在服务商的控制台中配置机器人或应用。具体要求见各服务商的集成页面。

## 开始使用 {/* #get-started */}

您需要一个 Mastra 平台项目，并在 [`mastra` CLI](/reference/cli/mastra) 中用 `mastra auth login` 登录。

### 安装软件包 {/* #install-the-package */}

```bash npm2yarn
npm install @mastra/connect
```

### 配置环境 {/* #configure-the-environment */}

应用使用访问令牌向平台验证身份。请为应用创建一个令牌：

```bash
mastra auth tokens create my-app
```

将令牌保存为 `MASTRA_PLATFORM_ACCESS_TOKEN`，这是 `@mastra/connect` 读取的变量名。CLI 建议使用 `MASTRA_API_TOKEN`，但 `@mastra/connect` 会忽略这一名称。请将令牌和项目 ID 添加到应用的环境变量中：

```bash title=".env"
MASTRA_PLATFORM_ACCESS_TOKEN=your-token
MASTRA_PROJECT_ID=your-project-id
```

区域和其他可选变量见[环境变量](/reference/connect/tools#environment-variables)。

### 连接账号 {/* #connect-an-account */}

在服务商的[集成页面](#providers)找到其 ID，并将其传给 `mastra connect add`。例如，为 Linear 账号授权：

```bash
mastra connect add linear
```

在包含 `.env` 文件的目录运行命令。CLI 会引导您完成授权。运行 [`mastra connect list`](/reference/cli/mastra#mastra-connect-list) 可查看项目可用的服务商及其连接状态。如何命名、移除和替换连接，见 [`mastra connect` 参考](/reference/cli/mastra#mastra-connect)。

## 为 Agent 添加工具 {/* #add-tools-to-an-agent */}

将 [`tools()`](/reference/connect/tools) 传给 Agent 的 `tools` 选项：

```typescript title="src/mastra/agents/ops.ts"
import { Agent } from '@mastra/core/agent'
import { tools } from '@mastra/connect'

export const opsAgent = new Agent({
  id: 'ops',
  name: 'ops',
  instructions: 'You help the team track work in Linear and GitHub.',
  model: '__GATEWAY_OPENAI_MODEL_LUNA__',
  tools: tools(),
})
```

不传选项时，Agent 会获得所有已连接且提供工具集的服务商的工具。每个工具键都带服务商前缀，例如 `linear_list_issues`。前缀可能与服务商 ID 不同，例如 `google-calendar` 的工具以 `google_calendar_` 开头。[服务商工具集参考](/reference/connect/providers)列出了所有键。有些服务商通过托管的 Model Context Protocol（MCP）服务器提供工具。它们同样使用 `tools()` API，但工具在运行时发现。

若要同时保留自己的工具，请在 `tools` 函数中展开解析器返回的结果。键冲突时，自定义工具优先：

```typescript title="src/mastra/agents/ops.ts"
import { Agent } from '@mastra/core/agent'
import { tools } from '@mastra/connect'
import { weatherTool } from '../tools/weather'

const connectTools = tools()

export const opsAgent = new Agent({
  id: 'ops',
  name: 'ops',
  instructions: 'You help the team track work in Linear and GitHub.',
  model: '__GATEWAY_OPENAI_MODEL_LUNA__',
  tools: async ctx => ({ ...(await connectTools(ctx)), weatherTool }),
})
```

## 选择工具并设置审批 {/* #choose-tools-and-require-approval */}

只为 Agent 提供所需工具。用 `providers` 选择服务商，用 `allowTools` 放行指定的工具键，用 `requireApproval` 暂停选定的工具，等待审批后再执行：

```typescript
tools({
  providers: {
    linear: {
      allowTools: ['linear_list_issues', 'linear_create_issue'],
      requireApproval: ['linear_create_issue'],
    },
  },
})
```

默认情况下，工具无需审批即可运行。传入 `requireApproval: true` 可要求审批某个服务商的所有工具。工具集和 MCP 服务商均支持审批。处理审批请求的方法见[人工介入指南](/docs/agents/human-in-the-loop)。

如果某个服务商有多条连接，工具集会添加 `<provider>__list_connections` 工具。该服务商的其他工具均通过 `connection_name` 输入选择账号。若要始终使用同一条连接，请为该服务商设置 `connectionId`。

[`tools()` 参考](/reference/connect/tools#parameters)介绍排除过滤条件、通配符模式、按请求调整的选项，以及缓存。

## 添加渠道 {/* #add-channels */}

将 [`channels()`](/reference/connect/channels) 传给 `Mastra` 构造函数：

```typescript title="src/mastra/index.ts"
import { Mastra } from '@mastra/core'
import { channels } from '@mastra/connect'
import { assistant } from './agents/assistant'

export const mastra = new Mastra({
  agents: { assistant },
  channels: await channels(),
})
```

这样会注册渠道 Provider 及其 Webhook 路由。要启用渠道，需要分别完成两步：

1. **连接服务商。** 平台连接会保存机器人或应用的凭据。具体步骤请参阅集成页面：[Slack](/integrations/channels/slack#agent-chat)、[Discord](/integrations/channels/discord#agent-chat)、[Telegram](/integrations/channels/telegram#connect) 和 [Microsoft Teams](/integrations/channels/teams#agent-chat)。
1. **将渠道安装到 Agent。** 在 Studio 中将渠道连接到 Agent，用户就可以通过该渠道向 Agent 发送消息。

为了投递 Webhook 和执行 OAuth 回调，服务商必须能通过公开 URL 访问您的服务器。Mastra 平台会提供这个 URL。在其他环境托管时，请将 `MASTRA_SERVER_URL` 设为服务器的公开 URL。本地开发时请使用公开的 HTTPS 隧道。

[`channels()` 参考](/reference/connect/channels)介绍如何选择服务商、处理启动错误以及刷新连接，也说明如何[混用 Connect 渠道和自行管理的渠道](/reference/connect/channels#combine-with-self-managed-channels)，以及[按渠道调整工具](/reference/connect/channels#vary-tools-by-channel)。

## 使用原始凭据 {/* #use-a-raw-credential */}

将连接 ID 传给 [`credential()`](/reference/connect/credential)，即可在代码中获取连接的凭据。需要使用服务商的 SDK 或工具未覆盖的 API 时，可以这样做。

## 安全模型 {/* #security-model */}

调用工具时，平台在服务器端为请求添加凭据，应用始终不会收到凭据。平台会记录每次代理调用，以便审计和统计工具使用情况，但不记录工具参数或结果。

代理请求只能访问服务商的 API 主机。有些连接允许访问额外主机，例如 Supabase 项目的 URL。Agent 能用哪些工具、哪些调用需要审批，由您的代码决定。

`credential()` 会把原始凭据的密钥返回给应用。使用该凭据发出的请求会绕过代理，不受代理的主机限制，也不会进入代理的调用记录。请勿记录该凭据，也不要在 Agent 输出中返回它。

## 故障排查 {/* #troubleshooting */}

调用服务商失败，大多是连接凭据或配置所致。`proxy_error` 的 `status` 和 `detail` 属性包含服务商的响应。

- **状态 `401`：** 凭据可能已过期、撤销或轮换。若需要替换凭据，请[重新授权连接](/reference/cli/mastra#replace-a-connection-that-needs-reauthorization)。
- **状态 `403`：** 检查服务商的响应，确认是否缺少授权范围、资源是否受限，或账号是否有额外要求。`allowTools` 只筛选工具，不改变凭据的权限。
- **没有来自某服务商的工具：** 运行 `mastra connect list` 检查项目及连接状态。检查服务商选择和工具筛选配置，确认安装的 `@mastra/connect` 版本包含该工具集。在应用日志中查找 `[@mastra/connect] Skipping` 警告，这表示某条连接无法解析。

完整错误代码见[错误参考](/reference/connect/tools#errors)。
