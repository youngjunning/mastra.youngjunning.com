# 配置

部署到 Mastra Platform 时，CLI 会生成配置文件 `.mastra-project.json`，并读取平台上的环境变量。你也可以让它读取本地 `.env` 文件。

本页介绍项目配置文件和环境变量的读取规则。

## 项目配置 {/* #project-config */}

首次执行 [`mastra deploy`](/docs/mastra-platform/deploy) 时会自动生成 `.mastra-project.json` 文件，将本地项目关联到平台项目。[GitHub 集成](/docs/mastra-platform/github)也会向已关联的仓库写入同一文件。

将此文件提交到版本控制系统，确保后续部署（包括 CI 部署）都指向正确的项目。

文件示例如下。

```json title=".mastra-project.json"
{
  "projectId": "06daaac4-89b1-40f0-9e3f-0993e039a627",
  "projectName": "my-project",
  "organizationId": "org_01KNA5YSP52SX4M6YVSXC2MAHP"
}
```

| 字段 | 说明 |
| - | - |
| projectId | 项目的 UUID，在创建项目时分配。 |
| projectName | 便于阅读的项目名称，用作仪表板和 CLI 输出中的显示标签。 |
| organizationId | 项目所属的组织。所有部署、API 密钥和资源都归属于该组织。 |

## 环境变量 {/* #environment-variables */}

本地环境变量文件是可选的。[`mastra deploy`](/docs/mastra-platform/deploy) 从以下三个来源读取变量。

- **托管变量**由[托管数据库](/docs/mastra-platform/database)等平台资源注入，由平台定义，无法手动编辑。
- **已保存的变量**通过仪表板保存在项目或环境中。每次部署直接使用这些变量，无需本地文件。
- **本地环境变量文件**。部署时会在平台变量之上叠加一个本地文件，即通过 `--env-file` 指定的文件、使用 `--env` 时对应的 `.env.<environment>`，或项目中唯一的 `.env*` 文件。如果有多个候选文件，CLI 会提示选择。不同本地文件中的变量不会合并。

传入 `--env-file` 可明确指定部署使用的环境变量文件。

```bash
mastra deploy --env-file .env.production --yes
```

部署前，请检查本地环境变量文件并清除仅供开发使用或属于个人的敏感信息，以免上传。

### Observability {/* #observability */}

以下环境变量用于配置 Mastra Platform 的 Observability 产品。

| 变量 | 说明 |
| - | - |
| `MASTRA_PLATFORM_ACCESS_TOKEN` | 组织范围的访问令牌。CLI 在开通可观测性服务时写入该令牌，并用它通过平台身份验证。 |
| `MASTRA_PROJECT_ID` | 平台项目的 UUID。`MastraPlatformExporter` 用它将可观测性数据关联到平台项目。部署 Studio 和 Server 时从 `.mastra-project.json` 读取项目 ID。 |
| `MASTRA_PLATFORM_OBSERVABILITY_ENDPOINT` | 可选，用于覆盖 `MastraPlatformExporter` 和 Studio 的可观测性端点。如果项目不在默认的美国区域，请设为所在区域的采集端点，例如 `https://observability.eu.mastra.ai`。默认值为 `https://observability.mastra.ai`。 |
| `MASTRA_ORG_ID` | 覆盖 CLI 命令当前使用的组织。对于支持的命令，也可通过 `--org` 指定组织。 |

`MastraPlatformExporter` 读取 `MASTRA_PLATFORM_ACCESS_TOKEN`，用于向平台导出数据时进行身份验证。

## 多环境 {/* #multiple-environments */}

一个项目可以在多个[环境](/docs/mastra-platform/environments)（如 `production` 和 `staging`）中运行同一套代码。每个环境都有自己的 URL、已保存的变量和部署历史。所有环境共用一个 `.mastra-project.json` 文件。

```bash
mastra deploy --env production --yes
mastra deploy --env staging --env-file .env.staging --yes
```

:::note
早期平台版本要求每个环境各建一个项目。现在只需保留一个项目，再部署到不同环境。
:::
