# 配置

当您部署到 Mastra 平台时，CLI 会生成一个`.mastra-project.json`配置文件并解析来自平台和（可选）本地的环境变量`.env`文件。

本页解释了这两种机制。

## 项目配置 {/* #project-config */}

这`.mastra-project.json` file is auto-generated on your first [`mastra deploy`](/docs/mastra-platform/deploy). It links your local project to a platform project. The [GitHub integration](/docs/mastra-platform/github) writes the same file into linked repositories.

将其提交到版本控制，以便后续部署（包括来自 CI）针对正确的项目。

您的文件将如下所示：

```json title=".mastra-project.json"
{
  "projectId": "06daaac4-89b1-40f0-9e3f-0993e039a627",
  "projectName": "my-project",
  "organizationId": "org_01KNA5YSP52SX4M6YVSXC2MAHP"
}
```

|领域 |描述 |
| - | - |
|项目编号 |项目的 UUID。创建项目时分配。 |
|项目名称 |人类可读的项目名称。用作仪表板和 CLI 输出中的显示标签。 |
|组织ID |拥有该项目的组织。所有部署、API 密钥和资源都仅限于该组织。 |

## 环境变量 {/* #environment-variables */}

本地环境文件是可选的。[`mastra deploy`](/docs/mastra-platform/deploy) resolves variables from three sources:

* **托管变量**：由平台资源注入，例如[hosted databases](/docs/mastra-platform/database). The platform defines these, and you can't edit them.
* **存储变量**：通过仪表板保存在项目或环境中。在每次部署时按原样使用，无需本地文件。
* **本地环境文件**：部署在顶部的第一层本地环境文件：`--env-file` you pass, `.env.<environment>` when you deploy with `--env`, or the only `.env*` file in the project. If several exist, the CLI asks you to choose one. Variables from different local files aren't merged.

要将部署固定到特定的环境文件而不是依赖默认选择，请传递`--env-file`:

```bash
mastra deploy --env-file .env.production --yes
```

在部署之前检查并清理本地环境文件，以避免上传仅开发或个人机密。

### 可观察性 {/* #observability */}

以下环境变量配置 Mastra 平台上的 Observability 产品。

|变量|描述 |
| - | - |
|`MASTRA_PLATFORM_ACCESS_TOKEN` | Org-scoped access token. The CLI writes this during observability provisioning and uses it for platform authentication. |
| `MASTRA_PROJECT_ID` | UUID of the platform project. `MastraPlatformExporter` uses it to link observability data to the platform project. Studio and Server deploys read the project ID from `.mastra-project.json`. |
| `MASTRA_PLATFORM_OBSERVABILITY_ENDPOINT` | Optional observability endpoint override for `MastraPlatformExporter` and Studio. Set it to your region's collector, for example `https://observability.eu.mastra.ai`, when your project isn't in the default US region. Defaults to `https://observability.mastra.ai`. |
| `MASTRA_ORG_ID` | Overrides the active organization for CLI commands. You can also set it with the `--org` flag on supported commands. |

`MastraPlatformExporter`读`MASTRA_PLATFORM_ACCESS_TOKEN` to authenticate platform export.

## 多种环境 {/* #multiple-environments */}

单个项目跨多个项目运行相同的代码库[environments](/docs/mastra-platform/environments), such as `production` and `staging`. Each environment has its own URL and its own stored variables, plus its own deploy history. One `.mastra-project.json` file covers all of them:

```bash
mastra deploy --env production --yes
mastra deploy --env staging --env-file .env.staging --yes
```

:::注意
早期的平台版本需要每个环境一个项目。环境取代了这一模式，因此保留一个项目并部署到环境中。
:::
