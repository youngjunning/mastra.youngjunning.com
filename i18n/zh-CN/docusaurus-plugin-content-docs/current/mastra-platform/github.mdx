# Mastra 平台上的 GitHub 集成

GitHub 集成将 Mastra 平台项目链接到 GitHub 存储库。当您将更改推送到存储库时，Studio 和 Server 将自动部署。

:::注意
该集成仅适用于 GitHub.com 上托管的存储库。目前不支持自托管 GitHub Enterprise 实例。
:::

链接存储库后，平台：

* 每次推送到配置的分支时都会构建和部署 Studio 和 Server。
* 为从模板创建的项目提供托管数据库和网关 API 密钥。
* 显示每次部署的提交、分支和拉取请求上下文。
* 在检查运行时将构建状态报告回 GitHub，并通过实时状态徽章和内联日志报告到项目仪表板。

## 何时使用 GitHub 集成 {/* #when-to-use-the-github-integration */}

当您需要以下任一功能时，请选择 GitHub 集成：

* 推送部署自`main` or any other branch, including separate branches for Studio and Server.
* 托管的入门流程，从 Mastra 模板构建项目，包括新的存储库、托管数据库和网关 API 密钥。
* 在平台仪表板内拉取请求并提交上下文以进行分类。

CLI 流程（`mastra studio deploy` and `mastra server deploy`) is still available for ad-hoc deploys and CI providers other than GitHub. See [Studio](/docs/mastra-platform/studio) and [Server](/docs/mastra-platform/server) for the CLI-only path.

## 安装 Mastra GitHub 应用程序 {/* #install-the-mastra-github-app */}

该集成由 Mastra GitHub 应用程序提供支持。

该应用程序读取存储库内容并监听`push` events on the configured branches. It writes deploy status back as check runs.

<Steps>
  <StepItem>
    在[Mastra platform dashboard](https://projects.mastra.ai), open your organization settings. The page includes a **GitHub App** section.
  </StepItem>

  <StepItem>
    选择**Install GitHub App** and choose the GitHub account or organization to install on.

    如果您不拥有 GitHub 组织，GitHub 会创建一个待处理的组织**installation request** that an admin must approve. The dashboard tracks pending requests alongside completed installations.
  </StepItem>

  <StepItem>
    选择应用程序可以访问的存储库。您可以限制特定存储库或授予对帐户上所有存储库的访问权限。

    您可以随时从 GitHub 的应用程序设置撤销或更改存储库访问权限。
  </StepItem>
</Steps>

:::注意
如果 GitHub 稍后更新应用程序所需的权限，仪表板会显示**outdated permissions** warning with an approval link. Repository operations return a `403` until an admin re-approves.
:::

### 待处理的安装请求 {/* #pending-installation-requests */}

当非管理员在组织上请求应用程序时，该请求将保持待处理状态，直到组织管理员在 GitHub.com 上批准为止。仪表板：

* 在活动安装旁边列出待处理的请求。
* 允许同一用户同时请求访问多个 GitHub 帐户。
* 当您打开页面时，根据 GitHub 协调待处理状态，删除管理员已拒绝的请求或请求者已撤回的请求。

要取消待处理的请求，请选择**Cancel** next to it in the dashboard.

## 从模板创建项目 {/* #create-a-project-from-a-template */}

模板是最快的入门方式。该平台从 Mastra 模板创建一个新的存储库，并将其链接到一个新项目。然后，它提供模板声明的任何托管数据库并运行第一次部署。

<Steps>
  <StepItem>
    在仪表板中，选择**Create project** and choose **Start from a template**.
  </StepItem>

  <StepItem>
    选择一个模板并选择拥有新存储库的 GitHub 帐户。为存储库命名并选择它是否应该是私有的。
  </StepItem>

  <StepItem>
    配置模板的托管数据库要求。模板可以声明所需的数据库（例如 Turso 或 Neon），您可以根据要求选择Provider和区域。
  </StepItem>

  <StepItem>
    添加任何特定于模板的环境变量（例如，AI Provider API 密钥）。平台种子`MASTRA_GATEWAY_API_KEY` and `MASTRA_PLATFORM_ACCESS_TOKEN` automatically so that template code that talks to the Gateway works on the first deploy.
  </StepItem>

  <StepItem>
    选择**Create project**. The platform creates the repository with a `.mastra-project.json` config file, provisions its managed databases, then triggers the initial Studio and Server deploys.
  </StepItem>
</Steps>

初始部署在开始之前等待托管数据库完成配置，因此模板的第一次构建会看到数据库连接环境变量。

## 链接现有存储库 {/* #link-an-existing-repository */}

当您在 GitHub 存储库中已有 Mastra 项目时，请使用此流程。

<Steps>
  <StepItem>
    在仪表板中，选择**Create project** and choose **Connect an existing repository**, or open an existing project and select **Link repository** from the project settings.
  </StepItem>

  <StepItem>
    选择一个安装，然后选择存储库。存储库搜索适用于应用程序在该安装上有权访问的每个存储库。
  </StepItem>

  <StepItem>
    选择 Studio 和 Server 部署分支。两个目标都默认为存储库的默认分支，并且它们可以共享一个分支或使用不同的分支。

    您可以为项目禁用 Studio 或 Server。手册**Deploy from GitHub** drawer selects both targets by default when both are configured.
  </StepItem>

  <StepItem>
    选择**Link repository**. The platform validates that the repository doesn't already have a `.mastra-project.json` file pointing at a different project. If it does, the dashboard warns you and offers an **Overwrite** option that replaces the file on link.
  </StepItem>
</Steps>

链接后，下一次推送到配置的分支会触发部署。

### `.mastra-project.json`冲突 {/* #mastra-projectjson-conflicts */}

平台写了一个`.mastra-project.json` file into every linked repository to identify the project. When you link a repository that already has one of these files, the dashboard checks its contents before submitting:

* **丢失的**：平台在链接上创建文件。
* **匹配**：该文件已指向您正在链接的项目，因此无需进行任何更改。
* **冲突**：该文件指向不同的项目。您可以取消或显式覆盖该文件。

看[Configuration](/docs/mastra-platform/configuration) for the file's schema.

## 一键部署 {/* #push-to-deploy */}

链接存储库后，每次推送到配置的分支都会触发部署：

* 推动到**Studio branch** triggers a Studio deploy.
* 推动到**Server branch** triggers a Server deploy.
* 如果两个目标共享一个分支，则一次推送会触发两个目标并行部署。

每个部署都带有提交 SHA、分支和（如果可用）引入提交的拉取请求编号。构建在平台内运行，并在提交上运行检查时将状态报告回 GitHub。

每个部署目标一次仅运行一个构建。如果在构建过程中收到新的推送，平台会取消同一目标的较旧的排队构建并运行最新的构建。 Studio 和 Server 构建是独立跟踪的，因此在配置两个目标时它们可以并行运行。

### 手动 GitHub 部署 {/* #manual-github-deploys */}

您还可以从仪表板触发部署，而无需推送。打开项目并选择**Deploy from GitHub**. Choose the target (Studio, Server, or both) together with a branch, then submit. The platform runs the deploy against the head commit of that branch and records the trigger as a **GitHub Workflow** deploy.

## 跟踪部署 {/* #track-deploys */}

从模板创建项目或链接到存储库后，**Setup** page shows one row per deploy target. Each row:

* 显示实时状态徽章，轮询部署直至完成。
* 通过部署 ID 链接到部署详细信息页面。
* 暴露了一个**Show logs** toggle that streams build and runtime logs inline. Server logs poll every three seconds while the deploy is active.

## 权限和撤销 {/* #permissions-and-revocation */}

要停止从存储库进行部署，请执行以下操作之一：

* **取消链接存储库**从该项目中**Project settings → Repository**. The project keeps its history and you can re-link a different repository later.
* **删除存储库访问权限**适用于 GitHub.com 上的 Mastra GitHub 应用程序。现有部署继续运行，但没有新的推送触发部署。
* **卸载 GitHub 应用程序**来自 GitHub 帐户。这将删除对该帐户上每个存储库的访问权限。

如果 GitHub 撤销或轮换应用程序的安装令牌，存储库读取将返回`github_app_permissions_outdated` error and the dashboard prompts an admin to re-approve permissions.
