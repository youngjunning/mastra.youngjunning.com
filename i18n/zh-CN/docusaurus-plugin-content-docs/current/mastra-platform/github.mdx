# Mastra 平台的 GitHub 集成

GitHub 集成将 Mastra 平台项目链接到 GitHub 存储库。当您将更改推送到存储库时，Studio 和 Server 将自动部署。

:::note
该集成仅适用于 GitHub.com 上托管的存储库。目前不支持自托管 GitHub Enterprise 实例。
:::

链接存储库后，平台：

- 每次向已配置的分支推送变更时，构建并部署 Studio 和 Server。
- 为从模板创建的项目开通托管数据库并配置 Gateway API 密钥。
- 在每次部署中显示提交、分支和 Pull Request 的相关信息。
- 通过 GitHub 检查回报构建状态，同时在项目仪表板上显示实时状态标签和内嵌日志。

## 何时使用 GitHub 集成 {/* #when-to-use-the-github-integration */}

当您需要以下任一功能时，请选择 GitHub 集成：

- 推送到 `main` 或其他任意分支时触发部署，Studio 和 Server 也可以使用不同的分支。
- 由平台根据 Mastra 模板初始化项目，包括创建新仓库、开通托管数据库和配置 Gateway API 密钥。
- 在平台仪表板中查看 Pull Request 和提交信息，以便排查问题。

临时部署或使用 GitHub 以外的 CI 服务时，仍可使用 CLI（`mastra studio deploy` 和 `mastra server deploy`）。仅使用 CLI 的操作见 [Studio](/docs/mastra-platform/studio) 和 [Server](/docs/mastra-platform/server)。

## 安装 Mastra GitHub 应用程序 {/* #install-the-mastra-github-app */}

该集成由 Mastra GitHub 应用程序提供支持。

应用读取仓库内容，监听已配置分支上的 `push` 事件，并通过 GitHub 检查回报部署状态。

<Steps>
  <StepItem>
    在 [Mastra 平台仪表板](https://projects.mastra.ai) 中打开组织设置，找到 **GitHub App** 区域。
  </StepItem>

  <StepItem>
    选择 **Install GitHub App**，然后选择要安装应用的 GitHub 账号或组织。

    如果你不是 GitHub 组织的所有者，GitHub 会创建一条待审批的**安装请求**，须由管理员批准。仪表板会同时跟踪待审批请求和已完成的安装。
  </StepItem>

  <StepItem>
    选择应用程序可以访问的存储库。您可以限制特定存储库或授予对帐户上所有存储库的访问权限。

    您可以随时从 GitHub 的应用程序设置撤销或更改存储库访问权限。
  </StepItem>
</Steps>

:::note
如果 GitHub 后续更新了应用所需的权限，仪表板会显示**权限已过期**警告并提供审批链接。管理员重新批准前，仓库操作会返回 `403`。
:::

### 待处理的安装请求 {/* #pending-installation-requests */}

当非管理员在组织上请求应用程序时，该请求将保持待处理状态，直到组织管理员在 GitHub.com 上批准为止。仪表板：

- 在活动安装旁边列出待处理的请求。
- 允许同一用户同时请求访问多个 GitHub 帐户。
- 当您打开页面时，根据 GitHub 协调待处理状态，删除管理员已拒绝的请求或请求者已撤回的请求。

要取消待审批的请求，请在仪表板上选择该请求旁的 **Cancel**。

## 从模板创建项目 {/* #create-a-project-from-a-template */}

模板是最快的入门方式。该平台从 Mastra 模板创建一个新的存储库，并将其链接到一个新项目。然后，它提供模板声明的任何托管数据库并运行第一次部署。

<Steps>
  <StepItem>
    在仪表板中选择 **Create project**，然后选择 **Start from a template**。
  </StepItem>

  <StepItem>
    选择一个模板并选择拥有新存储库的 GitHub 帐户。为存储库命名并选择它是否应该是私有的。
  </StepItem>

  <StepItem>
    配置模板的托管数据库要求。模板可以声明所需的数据库（例如 Turso 或 Neon），您可以根据要求选择Provider和区域。
  </StepItem>

  <StepItem>
    添加模板所需的环境变量，例如 AI Provider 的 API 密钥。平台会自动设置 `MASTRA_GATEWAY_API_KEY` 和 `MASTRA_PLATFORM_ACCESS_TOKEN`，使模板中调用 Gateway 的代码在首次部署时即可运行。
  </StepItem>

  <StepItem>
    选择 **Create project**。平台会创建含有 `.mastra-project.json` 配置文件的仓库、开通托管数据库，再触发 Studio 和 Server 的首次部署。
  </StepItem>
</Steps>

首次部署会等托管数据库就绪后再开始，因此模板首次构建时就能读取数据库连接所需的环境变量。

## 链接现有存储库 {/* #link-an-existing-repository */}

当您在 GitHub 存储库中已有 Mastra 项目时，请使用此流程。

<Steps>
  <StepItem>
    在仪表板中选择 **Create project**，再选择 **Connect an existing repository**。也可以打开已有项目，在项目设置中选择 **Link repository**。
  </StepItem>

  <StepItem>
    选择一个安装，然后选择存储库。存储库搜索适用于应用程序在该安装上有权访问的每个存储库。
  </StepItem>

  <StepItem>
    选择 Studio 和 Server 的部署分支。两个目标均默认使用仓库的默认分支，可以共用同一分支，也可以各用不同分支。

    可以在项目中停用 Studio 或 Server。如果两个目标都已配置，手动部署面板 **Deploy from GitHub** 默认会同时选中两者。
  </StepItem>

  <StepItem>
    选择 **Link repository**。平台会检查仓库是否已有指向其他项目的 `.mastra-project.json`。如果有，仪表板会发出警告，并提供 **Overwrite** 选项，以便在关联时替换该文件。
  </StepItem>
</Steps>

链接后，下一次推送到配置的分支会触发部署。

### `.mastra-project.json`冲突 {/* #mastra-projectjson-conflicts */}

平台会在每个关联的仓库中写入 `.mastra-project.json` 文件来标识项目。如果仓库中已有该文件，仪表板会在提交关联操作前检查其内容：

- **丢失的**：平台在链接上创建文件。
- **匹配**：该文件已指向您正在链接的项目，因此无需进行任何更改。
- **冲突**：该文件指向不同的项目。您可以取消或显式覆盖该文件。

文件结构见[配置](/docs/mastra-platform/configuration)。

## 推送触发部署 {/* #push-to-deploy */}

链接存储库后，每次推送到配置的分支都会触发部署：

- 推送到 **Studio 分支**会触发 Studio 部署。
- 推送到 **Server 分支**会触发 Server 部署。
- 如果两个目标共享一个分支，则一次推送会触发两个目标并行部署。

每个部署都带有提交 SHA、分支和（如果可用）引入提交的拉取请求编号。构建在平台内运行，并在提交上运行检查时将状态报告回 GitHub。

每个部署目标同一时间只运行一个构建。如果构建期间收到新的推送，平台会取消同一目标尚在队列中的旧构建，并运行最新的构建。Studio 和 Server 的构建独立跟踪，因此两个目标都已配置时可并行构建。

### 手动 GitHub 部署 {/* #manual-github-deploys */}

无需推送也可从仪表板触发部署。打开项目，选择 **Deploy from GitHub**，选定部署目标（Studio、Server 或两者）和分支后提交。平台会部署该分支的最新提交，并把这次触发记录为 **GitHub Workflow** 部署。

## 跟踪部署 {/* #track-deploys */}

从模板创建项目或关联仓库后，**Setup** 页面会为每个部署目标显示一行。每行都会：

- 显示实时状态徽章，轮询部署直至完成。
- 通过部署 ID 链接到部署详细信息页面。
- 提供 **Show logs** 开关，在页面内实时展示构建日志和运行日志。部署期间，Server 日志每三秒轮询一次。

## 权限和撤销 {/* #permissions-and-revocation */}

要停止从存储库进行部署，请执行以下操作之一：

- 在 **Project settings → Repository** 中解除项目与仓库的关联。项目会保留历史记录，以后可以关联其他仓库。
- 在 GitHub.com 撤销 Mastra GitHub App 对仓库的访问权限。现有部署继续运行，后续推送不再触发部署。
- **卸载 GitHub 应用程序**来自 GitHub 帐户。这将删除对该帐户上每个存储库的访问权限。

如果 GitHub 撤销或轮换应用的安装令牌，读取仓库时会返回 `github_app_permissions_outdated` 错误，仪表板会提示管理员重新批准权限。
