# Mastra 平台上的 Studio

Mastra 平台上的 Studio 是一个托管的可视化工作区，可以测试 Agent、运行 Workflow 并查看追踪记录。如果想让团队共用 Studio，又不想自行托管 Studio 界面，可以使用这个工作区。

你可以按下方步骤通过 CLI 部署 Studio，也可以关联 GitHub 仓库，在推送时触发部署。关联仓库的步骤请参阅 [GitHub 集成](/docs/mastra-platform/github)。

## 快速入门 {/* #quickstart */}

<Steps>
  <StepItem>
    按照[入门指南](/docs)创建你的第一个 Mastra 项目。
  </StepItem>

  <StepItem>
    全局安装 `mastra` CLI：

    ```bash npm2yarn
    npm install -g mastra
    ```
  </StepItem>

  <StepItem>
    运行一条命令即可部署 Studio：

    ```bash
    mastra deploy
    ```

    部署成功后，CLI 会输出 Studio 实例的 URL。
  </StepItem>
</Steps>

首次部署时，CLI 会提示你创建新项目或选择已有项目，然后在项目目录中创建 `.mastra-project.json` 文件。该文件将本地项目关联到平台项目，包含 `projectId`、`projectName` 和 `organizationId`。将此文件提交到仓库，以便 CI/CD 确定部署目标项目。

## 部署流程 {/* #how-deploy-works */}

`mastra deploy` 会构建项目，将 `src/mastra/` 编译到 `.mastra/output`，然后把输出打包成 ZIP 产物，上传并部署到云端沙箱。

部署状态依次为 **queued → uploading → starting → deploying → running**，出错时则进入 **failed**。如果项目已有正在运行的沙箱，平台会就地更新，不会中断服务；否则会创建新的沙箱。实例 URL 按环境分配，在同一环境中重复部署时保持不变。

完整选项列表及 CI/CD 用法请参阅 [`mastra deploy` CLI 参考](/reference/cli/mastra#mastra-deploy)。

## 身份验证 {/* #authentication */}

Mastra 平台默认对每次部署的 Studio 启用平台身份验证，无需额外配置。只有你所在平台组织的成员可以用各自的平台账号登录并访问已部署的 Studio。

平台身份验证仅保护 Studio 界面。服务器 API 路由由你自己的 [`server.auth`](/docs/studio/auth) 配置控制；未配置时，路由保持开放。

### 角色与权限 {/* #roles-and-permissions */}

平台身份验证按以下规则将组织角色映射为 Studio 权限：

| 平台角色 | Studio 权限 |
| - | - |
| `admin` | 完全访问（`*`） |
| `member` | 读取和执行 |
| `viewer` | 只读 |

要自定义映射，请在 Mastra 配置的 `studio.rbac` 中设置 `roleMapping`。设置后，自定义映射会替换平台默认值。权限格式请参阅[基于角色的访问控制](/docs/studio/auth#role-based-access-control)。

### 使用自己的身份验证服务 {/* #bring-your-own-auth */}

要让已部署的 Studio 使用自己的身份验证提供商，请为项目设置以下环境变量，停用平台身份验证：

```bash
MASTRA_PLATFORM_STUDIO_AUTH=disabled
```

将该变量加入部署用的环境变量文件，或通过控制台将其保存到项目中，然后重新部署。停用平台身份验证后，部署过程会保留现有的身份验证和 RBAC 配置。Studio 登录流程由你自己的提供商处理，与自行托管时一样。`studio.auth` 保护 Studio 界面，`server.auth` 保护 API 路由。如果未设置 `studio.auth`，Studio 请求会使用 `server.auth`。

:::warning
停用平台身份验证后，无法再用平台账号登录。如果停用时没有配置自己的身份验证提供商，已部署的 Studio 及所有 API 路由都可公开访问。
:::

如果保留平台身份验证，同时配置了自己的 `studio.auth`，两个提供商都会验证令牌，但登录页面仅提供平台登录入口。要通过自己的提供商登录，请停用平台身份验证。

## 环境变量文件 {/* #environment-files */}

本地环境变量文件并非必需。如果项目目录中有 `.env` 或 `.env.*` 文件，部署时会将其中的环境变量一并打包。

如果有多个环境变量文件，CLI 会提示你选择。要以非交互方式指定文件，请传入 `--env-file`：

```bash
mastra deploy --env-file .env.production --yes
```

要在 `production` 和 `staging` 环境中运行同一套代码，请使用 [`mastra deploy --env`](/docs/mastra-platform/deploy#deploy-to-another-environment)。环境机制详见[环境](/docs/mastra-platform/environments)。

## 以非交互方式创建项目 {/* #create-a-new-project-non-interactively */}

首次运行时，`mastra deploy` 可以创建项目。如果 `--project <name>` 未匹配到现有项目，CLI 会把该值用作新项目名，并在确认后创建项目。加上 `--yes` 即可让整个流程在脚本中自动执行：

```bash
mastra deploy --project "my-new-project" --yes
```

在 CI 或 AI 编程 Agent 中请采用上述方式。`mastra studio projects create` 仅支持交互式操作。
