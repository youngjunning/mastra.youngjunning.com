# Mastra 平台上的工作室

Mastra 平台上的 Studio 是一个托管的可视化Workspace，用于测试Agent和运行Workflow程以及检查跟踪。当您想要与团队共享 Studio 而不自行托管 Studio UI 时，请使用它。

您可以从 CLI 部署 Studio，如下所示，或者链接 GitHub 存储库以进行推送部署。请参阅[GitHub integration](/docs/mastra-platform/github) for the repository-linked flow.

## 快速入门 {/* #quickstart */}

<Steps>
  <StepItem>
    遵循[get started guide](/docs) to create your first Mastra project.
  </StepItem>

  <StepItem>
    安装`mastra` CLI globally:

    ```bash npm2yarn
    npm install -g mastra
    ```
  </StepItem>

  <StepItem>
    使用单个命令部署 Studio：

    ```bash
    mastra deploy
    ```

    成功部署后，CLI 会输出已部署的 Studio 实例的 URL。
  </StepItem>
</Steps>

第一次部署时，CLI 会提示您创建新项目或选择现有项目。然后它创建一个`.mastra-project.json` file in your project directory. This file links your local project to a platform project. It contains the `projectId`, `projectName`, and `organizationId`. Commit this file to your repository so CI/CD knows which project to deploy to.

## 部署如何工作 {/* #how-deploy-works */}

这`mastra deploy` command builds your project and compiles `src/mastra/` into `.mastra/output`. It packages that output as an artifact ZIP, then uploads and deploys it to a cloud sandbox.

部署转换通过**queued → uploading → starting → deploying → running** or **failed** if something goes wrong. If a sandbox is already running for your project, the platform updates it in place with no downtime. Otherwise, it creates a fresh sandbox. Your instance URL is assigned per environment and remains stable across deploys to that environment.

请参阅[`mastra deploy` CLI reference](/reference/cli/mastra#mastra-deploy) for the full list of flags and CI/CD usage.

## 验证 {/* #authentication */}

默认情况下，Mastra 平台上部署的每个 Studio 都受到平台身份验证的保护。您的平台组织的成员使用其平台帐户登录，其他人无法访问已部署的 Studio。您无需配置任何内容即可获得此行为。

平台身份验证仅适用于 Studio UI。您的服务器的 API 路由由您自己控制[`server.auth`](/docs/studio/auth) configuration, or remain open if you haven't set one.

### 角色和权限 {/* #roles-and-permissions */}

平台身份验证将您的组织角色映射到 Studio 权限：

|平台角色|工作室权限|
| - | - |
|`admin` | Full access (`*`) |
| `member` | Read and execute |
| `viewer` | Read-only |

要自定义此映射，请设置`roleMapping` on `studio.rbac` in your Mastra configuration. When present, your mapping replaces the platform defaults. See [Role-based access control](/docs/studio/auth#role-based-access-control) for the permission format.

### 带上你自己的授权 {/* #bring-your-own-auth */}

要为已部署的 Studio 使用您自己的身份验证提供程序而不是平台身份验证，请在项目上设置环境变量：

```bash
MASTRA_PLATFORM_STUDIO_AUTH=disabled
```

将其添加到您部署时使用的 env 文件中，或通过仪表板将其存储在项目中，然后重新部署。禁用平台身份验证后，部署不会影响您的身份验证和 RBAC 配置。您自己的Provider驱动 Studio 登录流程，就像自托管部署一样。`studio.auth` protects the Studio UI, while `server.auth` protects your API routes. Studio requests fall back to `server.auth` when `studio.auth` isn't set.

:::警告
禁用平台身份验证会关闭平台帐户登录。如果您在没有配置自己的身份验证提供程序的情况下禁用它，则部署的 Studio 和所有 API 路由都可以公开访问。
:::

如果您启用平台身份验证并配置您自己的`studio.auth`, both providers validate tokens, but the login screen only offers the platform sign-in flow. To sign in through your own provider, disable platform auth.

## 环境文件 {/* #environment-files */}

本地环境文件是可选的。当一个`.env` or `.env.*` file is present in the project directory, the deploy bundles its environment variables.

当存在多个 env 文件时，CLI 会提示您选择一个。要以非交互方式选择，请传递`--env-file`:

```bash
mastra deploy --env-file .env.production --yes
```

跨运行相同的代码库`production` and `staging`, use [`mastra deploy --env`](/docs/mastra-platform/deploy#deploy-to-another-environment). See [Environments](/docs/mastra-platform/environments) for the full model.

## 以非交互方式创建一个新项目 {/* #create-a-new-project-non-interactively */}

在第一次运行时，`mastra deploy` can create a project. When `--project <name>` doesn't match an existing project, the CLI treats the value as a new project name and creates it after confirmation. Add `--yes` to make this flow fully scriptable:

```bash
mastra deploy --project "my-new-project" --yes
```

从 CI 或 AI 编码Agent中使用它，而不是`mastra studio projects create`, which is interactive only.
