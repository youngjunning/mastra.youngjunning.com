# Agent控制器

`AgentController`是交互式Agent应用程序的共享运行时主机。它协调模式、模型、存储、工作空间、Tool批准、子Agent和通道。每个用户或活动任务通过一个隔离的工作[`Session`](/reference/agent-controller/session).

[马斯特拉代码](https://code.mastra.ai)和[Mastra Factory](https://factory.mastra.ai) are the flagship AgentController implementations. They're coding agents with multi-model support, persistent conversations, and plan-then-execute workflows. Read [Building a coding agent](https://mastra.ai/blog/building-a-coding-agent) for a step-by-step TUI guide.

当您托管的Agent在代码库中工作时，请使用以下命令构建它[`createCodingAgent()`](/reference/coding-agent/create-coding-agent) instead of `new Agent()`. It returns a standard `Agent` that already has a workspace, task tracking, and retries for transient model errors, which are the defaults Mastra Code runs on.

## 何时使用Agent控制器 {/* #when-to-use-the-agent-controller */}

当您的应用程序需要时，请使用Agent控制器：

* 共享一个对话线程的多种Agent模式（例如，计划→构建→审查）
* UI 和Agent循环之间的控制层（模型切换、状态持久性、线程管理）
* 人机交互门控的Tool审批流程和权限策略
* 子Agent编排，使用受限Tool委派重点子任务
* 重新启动后持久线程和选定的线程设置，每个会话具有隔离的实时状态

您可以自己将所有这些组装在[Agent class](/docs/agents/overview), which exposes the full agent loop, tools, and memory. The AgentController provides opinionated defaults for an ongoing session where the agent acts as a collaborator rather than a one-shot endpoint. Use the Agent class directly for full control or request-response calls. Choose AgentController for ongoing sessions without building your own session runtime.

## 快速入门 {/* #quickstart */}

创建支持[`Agent`](/reference/agents/agent), storage, and [`Workspace`](/reference/workspace/workspace-class). Call [`controller.init()`](/reference/agent-controller/agent-controller-class#init) once, then use [`controller.createSession()`](/reference/agent-controller/agent-controller-class#createsessionoptions) to create a Session. Subscribe with [`session.subscribe()`](/reference/agent-controller/session#subscribelistener) and send work with [`session.sendMessage()`](/reference/agent-controller/session#sendmessage-content-files-requestcontext-author-):

```typescript title="src/mastra/agent-controller.ts"
import { Agent } from '@mastra/core/agent'
import { AgentController } from '@mastra/core/agent-controller'
import { LocalFilesystem, Workspace } from '@mastra/core/workspace'
import { LibSQLStore } from '@mastra/libsql'

const agent = new Agent({
  id: 'assistant',
  name: 'Assistant',
  instructions: 'Help the user plan and complete tasks.',
  model: '__GATEWAY_OPENAI_MODEL__',
})

const controller = new AgentController({
  id: 'assistant-controller',
  agent,
  storage: new LibSQLStore({
    id: 'agent-controller-storage',
    url: 'file:./mastra.db',
  }),
  workspace: new Workspace({
    id: 'assistant-workspace',
    filesystem: new LocalFilesystem({ basePath: './workspace' }),
  }),
  modes: [
    {
      id: 'plan',
      name: 'Plan',
      metadata: { default: true },
      instructions: 'Reason about the task before making changes.',
    },
    {
      id: 'build',
      name: 'Build',
      instructions: 'Implement the approved plan.',
    },
  ],
})

await controller.init()

const session = await controller.createSession({
  resourceId: 'user-123',
})

const unsubscribe = session.subscribe(event => {
  if (event.type === 'message_update' && event.event.type === 'text-delta') {
    process.stdout.write(event.event.delta)
  }
})

await session.sendMessage({ content: 'Plan a small TypeScript CLI.' })
unsubscribe()
```

每条消息都会发出一个`message_start` event with the initial message, zero or more `message_update` events with compact deltas, and a `message_end` event containing the message ID. Apply updates by ID when you need to reconstruct the complete message.

对多个会话使用相同的控制器。不要在控制器上存储当前会话或通过控制器级消息方法路由工作。

## 了解运行时模型 {/* #understand-the-runtime-model */}

控制器、会话和线程具有不同的生命周期：

* **控制器**：用于配置和运行时服务的共享主机。初始化一次并重复使用。
* **会议**：一个用户、任务或并发工作的隔离实时运行时，通过其会话 ID 进行寻址。它拥有活动模式、模型、状态、事件总线、运行状态、授权和当前线程绑定。
* **线**：包含消息和线程设置的存储对话。当您配置存储时，线程可以在控制器和进程重新创建后继续存在。

会话是实时状态。随意的[`session.state`](/reference/agent-controller/session#state), permission grants, pending approvals, and active runs don't automatically survive process recreation. Thread messages and selected thread settings, including the active mode and the current model, can persist through storage, but switching modes doesn't change the model.

## 会话和线程 {/* #sessions-and-threads */}

`createSession()`通过会话获取或创建`id`. The `resourceId` names who owns the session's threads and resource-scoped memory. When you omit `id`, it defaults to `resourceId`:

```typescript
const webSession = await controller.createSession({
  id: 'user-123:web',
  resourceId: 'user-123',
})

const sameWebSession = await controller.getSession('user-123:web')

const workerSession = await controller.createSession({
  id: 'user-123:background-worker',
  resourceId: 'user-123',
})

console.log(webSession === sameWebSession) // true
console.log(webSession === workerSession) // false
```

具有不同 ID 的会话具有单独的事件总线、运行循环、状态、模式和模型选择以及当前线程绑定。它们存储的线程和资源范围内存仍然属于共享`resourceId`, so listing threads by resource returns both sessions' threads.

经过`threadId` when the host must bind the Session to an exact thread. The controller switches to the existing thread or creates it with that ID when it's missing. This behavior also applies when `createSession()` returns a cached Session:

```typescript
const session = await controller.createSession({
  id: 'user-123:web',
  resourceId: 'user-123',
  threadId: 'support-ticket-42',
})
```

使用[`session.thread.create()`](/reference/agent-controller/session#sessionthreadcreate-title-id-requestcontext-) and [`session.thread.switch()`](/reference/agent-controller/session#sessionthreadswitch-threadid-emitevent-requestcontext-) to move one live Session between conversations.

### 转移线程所有权 {/* #transfer-thread-ownership */}

每个新线程都将其持久所有者存储在`metadata.ownerId` and its original creator in `metadata.createdBy`. Both default to the Session host's `ownerId`. `createdBy` doesn't change when ownership transfers.

读取活动线程的所有者并将其传递给`session.thread`:

```typescript
const currentOwnerId = await session.thread.getOwner()

await session.thread.transferOwnership({
  toOwnerId: 'user-456',
})
```

传输在一个进程内串行进行。需要持久跨进程比较和设置的主机应首先将其提交到自己的存储中，然后调用`transferOwnership()` to mirror the owner onto the active thread.

每次运行在启动时都会对线程所有者进行快照。Tool和其他动态运行时代码可以从中读取该值`AgentControllerRequestContext.threadOwnerId`. If ownership changes during a run, the active run keeps the old snapshot and the next run receives the new owner. `context.session.ownerId` remains the identity of the process-local Session host.

### 列出客户端存储的消息 {/* #list-stored-messages-from-the-client */}

使用Agent控制器客户端来翻阅线程的存储消息。传递选项对象会返回带有分页元数据的消息：

```typescript
import { MastraClient } from '@mastra/client-js'

const client = new MastraClient({ baseUrl: 'http://localhost:4111' })
const session = client.getAgentController('assistant-controller').session('user-123')

const result = await session.listMessages('support-ticket-42', {
  page: 0,
  perPage: 20,
  orderBy: { field: 'createdAt', direction: 'DESC' },
  filter: {
    dateRange: { start: new Date('2026-01-01') },
  },
})

console.log(result.messages)
console.log(result.total)
console.log(result.hasMore)
```

`page`是零索引的。省略`perPage` uses the storage default of 40 messages. Use `include` to request a message by ID with adjacent messages. `limit` is a deprecated alias for `perPage`; existing paged callers may use `{ limit, page }`, but must use `perPage` with `orderBy`, `filter`, or `include`. The existing numeric form, `session.listMessages(threadId, limit)`, remains available when you need the newest message window as an array, ordered oldest-first.

## 切换模式和型号 {/* #switch-modes-and-models */}

模式更改共享后备Agent使用的指令和Tool，而不替换会话或线程。在控制器上配置特定于模式的Tool和可见性：

```typescript
const modes = [
  {
    id: 'plan',
    name: 'Plan',
    metadata: { default: true },
    instructions: 'Investigate the task and propose a plan.',
    additionalTools: { searchDocs },
    availableTools: ['searchDocs', 'submit_plan'],
    transitionsTo: 'build',
  },
  {
    id: 'build',
    name: 'Build',
    instructions: 'Implement the approved plan.',
  },
]
```

`tools`和`additionalTools` are mutually exclusive inputs for adding mode-specific tools. When the controller has a shared backing agent, either input layers those tools onto the agent's tools. Use `availableTools` to restrict the final exposed tool names for a mode. Permission denies still take precedence over this allowlist.

切换实时会话[`session.mode.switch()`](/reference/agent-controller/session#sessionmodeswitch-modeid-). Read the active mode with [`session.mode.get()`](/reference/agent-controller/session#sessionmodeget) or [`session.mode.resolve()`](/reference/agent-controller/session#sessionmoderesolve):

```typescript
await session.mode.switch({ modeId: 'build' })

console.log(session.mode.get()) // "build"
console.log(session.mode.resolve().instructions)
```

独立切换模型[`session.model.switch()`](/reference/agent-controller/session#sessionmodelswitchmodelid-options), then read the active selection with [`session.model.get()`](/reference/agent-controller/session#sessionmodelget). The selection is stored as the thread's current model and remains active when the Session changes modes:

```typescript
await session.model.switch('__GATEWAY_ANTHROPIC_MODEL_SONNET__')

console.log(session.model.get())
```

### 选择观察记忆模型 {/* #select-observational-memory-models */}

观察者和反射器模型的选择是独立的。每个角色都可以使用主机从活动主模型和会话状态解析的显式模型或自动选择。

使用返回具体模型 ID 的同步解析器配置自动选择：

```typescript
const controller = new AgentController({
  // ...
  omConfig: {
    observerModel: 'auto',
    reflectorModel: 'auto',
    defaultObserverModelId: '__GATEWAY_OPENAI_MODEL_LUNA__',
    defaultReflectorModelId: '__GATEWAY_OPENAI_MODEL_LUNA__',
    resolveAutoModelId: ({ currentModelId }) => currentModelId,
  },
})
```

`session.om.observer.model()`回报`'auto'` or a concrete model ID. `session.om.observer.modelId()` returns the effective concrete model. A host can therefore change the main model without rewriting automatic role settings.

将一个角色重置为自动选择而不更改另一个角色：

```typescript
await session.om.observer.switchModel({ modelId: 'auto' })
```

如果解析器返回`undefined` or throws, the role uses its concrete `defaultObserverModelId` or `defaultReflectorModelId` fallback. See the [`Session` Observational Memory API](/reference/agent-controller/session#observational-memory) for explicit selection.

## 管理线程和状态 {/* #manage-threads-and-state */}

列出存储的对话[`session.thread.list()`](/reference/agent-controller/session#sessionthreadlistoptions):

```typescript
const thread = await session.thread.create({ title: 'Release planning' })
const threads = await session.thread.list()

await session.thread.switch({ threadId: thread.id })
console.log(threads.length)
```

使用`session.state` for structured live state associated with the Session. Read it with [`session.state.get()`](/reference/agent-controller/session#sessionstateget) and write updates with [`session.state.set()`](/reference/agent-controller/session#sessionstatesetupdates). Define `stateSchema` and `initialState` on the controller when you need validation and defaults:

```typescript
console.log(session.state.get())

await session.state.set({ activeProject: 'docs-site' })
```

`session.state.get()`返回快照。`set()` validates and merges the update into the Session state. Treat this state as live Session data unless your host explicitly persists and restores it.

## 批准Tool并恢复暂停 {/* #approve-tools-and-resume-suspensions */}

权限策略决定是否允许、拒绝Tool或将Tool发送到 UI 进行批准。将自定义Tool映射到类别`toolCategoryResolver` on the controller:

```typescript
const controller = new AgentController({
  toolCategoryResolver: toolName => {
    if (toolName === 'delete_project') return 'execute'
    return null
  },
})
```

调用规则允许的Tool不会暂停运行。定期上`Agent`, tool calls in one step run concurrently when none of them needs approval or can suspend. Durable agents run them one at a time unless the session's `yolo` state is on.

配置类别策略[`session.permissions.setForCategory()`](/reference/agent-controller/session#sessionpermissionssetforcategory-category-policy-) and tool policies with [`session.permissions.setForTool()`](/reference/agent-controller/session#sessionpermissionssetfortool-toolname-policy-):

```typescript
await session.permissions.setForCategory({
  category: 'execute',
  policy: 'ask',
})

await session.permissions.setForTool({
  toolName: 'delete_project',
  policy: 'deny',
})
```

当政策决定`ask`, subscribe for the approval event and return the user's decision with [`session.respondToToolApproval()`](/reference/agent-controller/session#respondtotoolapproval-decision-toolcallid-requestcontext-declinecontext-):

```typescript
session.subscribe(event => {
  if (event.type === 'tool_approval_required') {
    session.respondToToolApproval({
      toolCallId: event.toolCallId,
      decision: 'approve',
    })
  }
})
```

这`always_allow_category` decision grants the tool category for the gate's thread. Grants aren't durable process-level permissions.

交互式Tool，例如[`ask_user`](/reference/tools/ask-user-tool) and [`submit_plan`](/reference/tools/submit-plan-tool) use resumable tool suspensions instead. Resume them with [`session.respondToToolSuspension()`](/reference/agent-controller/session#respondtotoolsuspension-resumedata-address-toolcallid-requestcontext-):

```typescript
session.subscribe(event => {
  if (event.type === 'tool_suspended' && event.toolName === 'ask_user') {
    void session.respondToToolSuspension({
      toolCallId: event.toolCallId,
      resumeData: 'Use SQLite.',
    })
  }
})
```

为了`submit_plan`, resume with `{ action: 'approved' }` or `{ action: 'rejected', feedback }`. An approved plan can switch to the mode configured by `transitionsTo` before the run continues.

内置的`submit_plan` tool takes a plan file path, not the plan text. The agent writes the plan to a file and submits its path. It needs a filesystem it can write to, such as a workspace filesystem. To show the plan for approval, your app reads the file at the submitted `path`.

## 委托给子Agent {/* #delegate-to-subagents */}

在控制器上配置可用的子Agent类型。内置的`subagent` tool can then delegate focused tasks using those definitions:

```typescript
const controller = new AgentController({
  tools: {
    searchDocs,
  },
  subagents: [
    {
      id: 'code-reviewer',
      name: 'Code reviewer',
      description: 'Review a change for correctness and regressions.',
      instructions: 'Inspect the change and report actionable findings.',
      allowedControllerTools: ['searchDocs'],
      allowedWorkspaceTools: ['view', 'find_files'],
      defaultModelId: '__GATEWAY_OPENAI_MODEL_LUNA__',
    },
  ],
})
```

常规子Agent从其配置的指令和受限Tool集开始。放`forked: true` when the child should clone the parent thread and run with the parent agent's instructions and tools. Forked subagents preserve the parent prompt prefix, ignore the definition's instructions, tools, allowlists, and default model, and require memory on the controller.

使用[`session.subagents.model.set()`](/reference/agent-controller/session#sessionsubagentsmodelset-modelid-agenttype-) to store one default subagent model or a model for a specific agent type. Read the selection with [`session.subagents.model.get()`](/reference/agent-controller/session#sessionsubagentsmodelget-agenttype-):

```typescript
await session.subagents.model.set({
  modelId: '__GATEWAY_OPENAI_MODEL_LUNA__',
})

await session.subagents.model.set({
  agentType: 'code-reviewer',
  modelId: '__GATEWAY_ANTHROPIC_MODEL_SONNET__',
})

const reviewerModel = session.subagents.model.get({
  agentType: 'code-reviewer',
})
```

这些选择将写入线程设置。Agent类型选择优先于会话的默认子Agent模型。

## 连接聊天频道 {/* #connect-chat-channels */}

将通道适配器传递给控制器​​并将其注册到[`Mastra`](/reference/core/mastra-class) instance:

```typescript title="src/mastra/index.ts"
import { Mastra } from '@mastra/core'
import { AgentController } from '@mastra/core/agent-controller'
import { createSlackAdapter } from '@chat-adapter/slack'

const controller = new AgentController({
  id: 'support-controller',
  agent,
  storage,
  workspace,
  modes,
  channels: {
    adapters: {
      slack: createSlackAdapter(),
    },
    resolveResourceId: ({ thread, message, defaultResourceId }) => {
      if (thread.isDM) return message.author.userId
      return defaultResourceId
    },
    onSessionStart: async ({ session, thread }) => {
      const plan = await billing.planFor(thread.resourceId)
      await session.model.switch(plan.modelId)
    },
  },
})

export const mastra = new Mastra({
  agentControllers: { controller },
  storage,
})
```

将每个平台 Webhook 指向特定于控制器的路由：

```text
/api/agent-controllers/<CONTROLLER_ID>/channels/<PLATFORM>/webhook
```

每个外部聊天线程映射到一个控制器会话和 Mastra 线程。默认情况下，新会话使用从适配器的聊天线程 ID 派生的资源 ID，前缀为`channel:`. Use `resolveResourceId` to map direct messages to an existing application user or choose another memory owner. The callback only affects new threads. An existing thread keeps its stored resource ID.

通道会话是由控制器而不是您的代码创建的，因此`onSessionStart` is where you configure them. It runs once per session, after the session is bound to its mapped thread and before the first message is handled. A channel session starts with controller defaults, so this is where you set its model and memory settings. Later messages in the same thread reuse the session and don't call it again. Errors are logged and swallowed so a session that can't be configured still answers the message.

### 授权和路由通道会话 {/* #authorize-and-route-channel-sessions */}

`onSessionStart`在会话存在后运行并吞掉错误，因此它无法拒绝请求。使用`resolveSession` when your host decides whether a session may exist. It replaces the built-in session creation and runs before any session exists. Throwing refuses the request before the controller creates a session or calls the model. Mastra logs the refusal and leaves the chat thread silent, so your authorization message never reaches the channel.

```typescript oxfmt:false
channels: {
  adapters: { slack: createSlackAdapter() },
  resolveSession: async ({ controller, thread, requestContext }) => {
    const install = await installs.authorize(requestContext.get('teamId'))

    return controller.createSession({
      id: `${install.id}:${thread.id}`,
      resourceId: thread.resourceId,
      threadId: thread.id,
      ownerId: controller.id,
      requestContext,
    })
  },
}
```

在下面创建会话`thread.resourceId`. Because a session can bind only threads it owns, use `resolveResourceId` to assign a different owner to the mapped thread. Pass `threadId: thread.id` so the session opens on the mapped thread. Without it, a session that has tags or a `projectPath` doesn't treat the mapped thread as its own, so it creates an extra empty thread before switching to the mapped one. Sessions are get-or-create by `id`. Give each installation or principal its own `id` when one thread needs separate sessions.

不是拒绝的故障（存储中断、解析器依赖项中的错误）仍然会向线程发布错误，因此损坏的机器人看起来不像沉默的机器人。如果您需要在自己的代码中区分它们，则拒绝是`ChannelSessionRejectedError` with the original error as its `cause`.

`resolveSession`当用户使用该操作的请求上下文回答批准卡时也会运行。共享安装会重新验证批准者，而不是信任发送原始消息的人。

### 处理过时的批准 {/* #handle-stale-approvals */}

批准门存在于内存中，因此重新启动后回答的每个批准都会过时。 Mastra 绝不会为了陈旧的操作而运行该Tool。使用`onStaleToolApproval` to settle the attempt the user answered, instead of dropping it:

```typescript oxfmt:false
channels: {
  adapters: { slack: createSlackAdapter() },
  onStaleToolApproval: async ({ decision, toolCallId, runId, memory }) => {
    await runs.markInterrupted({ runId, toolCallId, decision, threadId: memory.thread })
  },
}
```

`runId`是提交批准卡的运行，这是用户回答的尝试，也是您在重新启动后解决的尝试。会话自己的运行单独传递为`currentRunId`, and is usually `null` or a different run by then.

控制器通道会话和自动批准状态保存在内存中，因此请使用长期存在的服务器。待批准和实时会话状态不会在流程重新启动后继续存在。无法呈现批准控件的适配器会在没有批准提示的情况下自动运行Tool，因此运行不会保持暂停状态。

看[Channels](/docs/channels) for adapter setup and platform-specific webhook configuration.

## 连接用户界面 {/* #connect-a-ui */}

连接方式取决于 UI 的运行位置。拥有控制器的终端 UI 或服务器持有`Session` object and subscribes to it directly. A browser UI runs in a different process, so it reaches the same session over the controller's HTTP routes with [`@mastra/client-js`](/reference/client-js/mastra-client).

### 服务器端会话 {/* #server-side-sessions */}

订阅会话事件以获取增量更新。读取缩小的显示状态[`session.displayState.get()`](/reference/agent-controller/session#sessiondisplaystateget) when the UI needs a complete render snapshot:

```typescript
const unsubscribe = session.subscribe(event => {
  if (event.type === 'display_state_changed') {
    render(event.displayState)
  }
})

render(session.displayState.get())

// Call when the UI disconnects.
unsubscribe()
```

订阅是通过会话隔离的。来自同一控制器上另一个会话的事件不会传递到此侦听器。阅读[Building a coding agent](https://mastra.ai/blog/building-a-coding-agent) guide for a complete TUI example.

### 客户端会话 {/* #client-side-sessions */}

[`client.getAgentController(key).session(sessionId)`](/reference/client-js/agent-controller)返回由其会话 ID 寻址的会话客户端。传递控制器注册的密钥`new Mastra({ agentControllers })`, which can differ from the controller's `id`. Sessions are get-or-create on the server, so `create()` resumes an existing conversation instead of forking it. Pass `resourceId` to `create()` when several sessions share one resource; otherwise the resource defaults to the session id:

```typescript title="src/components/agent-session.ts"
import { MastraClient } from '@mastra/client-js'

const client = new MastraClient({ baseUrl: 'http://localhost:4111' })
const session = client.getAgentController('coding-controller').session('user-123')

await session.create()

const subscription = await session.subscribe({
  onEvent: event => handleEvent(event),
  onError: error => showDisconnected(error),
  onReconnect: () => {
    void session.state().then(resync).catch(showDisconnected)
  },
  reconnect: true,
})

// Call when the UI disconnects.
subscription.unsubscribe()
```

`subscribe()`与进程内侦听器不同，它采用一个选项对象并且是异步的。一旦流建立，它的承诺就会解决，而当它无法连接时，它就会拒绝。被拒绝的呼叫不会在后台留下任何运行。`reconnect: true` re-establishes a stream that drops after it was established, with exponential backoff. A connection that stays open but stops delivering data, for example after the device sleeps, counts as a drop once no data, including server heartbeats, arrives for `idleTimeoutMs` (default `60000`).

服务器不会重放流关闭时错过的事件，因此请阅读`session.state()` from `onReconnect` for the current mode, model, and thread. The client surface has no `session.displayState.get()`.

发送作品给`session.sendMessage(content)`, or `session.sendMessage({ content, files })` to attach base64-encoded files. The reply arrives as `message_*` events on the subscription, not as the return value of the call. Answer a `tool_approval_required` event with `session.approveTool(toolCallId, approved)`, and a `tool_suspended` event with `session.respondToToolSuspension(toolCallId, resumeData)`.

`onEvent`接收会话发出的每个事件。请参阅[Agent Controller API](/reference/client-js/agent-controller#events) reference for the event types and how to narrow them.
