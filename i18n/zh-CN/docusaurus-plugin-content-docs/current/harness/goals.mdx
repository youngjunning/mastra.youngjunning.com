# 目标

**引入版本** `@mastra/core@1.43.0`

目标是一项保存在 Thread 中的长期指令。Agent 会在每轮迭代中继续推进，直到评判模型判定目标已达成，或运行预算用尽。

目标保存在 Thread 状态中，重新加载后仍然有效。即使当前轮次尚未结束时收到新消息，执行循环也会继续评估目标。

目标与 [`isTaskComplete`](/docs/subagents) 共用一套机制：LLM 充当评判员，每轮为 Agent 的输出打分，决定循环是否继续。目标会持久保存在 Thread 状态中，通过 `Agent` 方法设置和更新，无需在每次调用 `stream()` 时传入。

## 何时使用目标 {/* #when-to-use-goals */}

如果希望 Agent 跨多轮迭代和消息持续推进同一目标，又无需在每次调用时重传成功标准，可以设置目标。

* Agent 需要持续推进，直到评判模型确认完成。
* 运行期间收到新消息后仍需继续工作，执行中的新消息也会按同一目标评估。
* 重新加载 Thread 或重启进程后，目标必须保留。

如果只需在单次 `stream()` 调用中检查任务是否完成，请使用 [`isTaskComplete`](/docs/subagents)。

## 快速入门 {/* #quickstart */}

目标需要配置 [存储](/docs/storage) 后端，并使用由 Memory 支持的 Thread。为 Agent 添加 `goal` 配置并指定评判模型，再为 Thread 设置目标。

```typescript title="src/mastra/agents/worker.ts" {8-11}
import { Agent } from '@mastra/core/agent'

const worker = new Agent({
  id: 'worker',
  name: 'worker',
  instructions: 'You complete software tasks end to end.',
  model: '__GATEWAY_OPENAI_MODEL__',
  memory,
  goal: {
    judge: '__GATEWAY_OPENAI_MODEL_LUNA__',
    maxRuns: 50,
  },
})

// Set the durable objective for a thread.
await worker.setObjective('Add and test a /health endpoint', {
  threadId,
  resourceId,
})

// The objective is judged each iteration until it's complete or maxRuns is hit.
const stream = await worker.stream('Start working on the goal', {
  memory: { thread: threadId, resource: resourceId },
})
```

`goal` 配置会自动注册状态信号投影，无需额外设置，模型就能在上下文中以 `<current-objective>` 的形式看到当前目标。

## 目标评估如何运行 {/* #how-the-goal-step-works */}

目标评估步骤在 Agent 的执行循环中紧接 `isTaskComplete` 运行。Agent 给出实际候选答案时，该步骤会按目标为对话评分并决定是否继续循环。

* **目标未达成且仍有预算** → 循环继续。每次评估的反馈都会加入上下文，供 Agent 在下一轮改进。
* **目标已达成** → 循环停止，目标标记为 `done`。
* **预算耗尽** (`runsUsed >= maxRuns`) → 循环停止，目标标记为 `paused`。提高 `maxRuns` 后，恢复目标即可继续。

与 `isTaskComplete` 一样，当前迭代如果在执行后台任务、仍处于工具调用循环中，或只更新工作记忆，就会跳过该步骤。

每次评估都会发出一个有类型定义的 `goal` 流式数据块，供界面实时显示进度。其类型为 `GoalEvaluationPayload`，包含 `objective`、`iteration`、`maxRuns`、`passed`、`status`、`results`、`reason`、`duration`、`timedOut`、`maxRunsReached` 和 `suppressFeedback`。

**有可用的评判模型才会启用目标评估。** 如果目标专属设置和 Agent 的 `goal.judge` 都无法提供评判模型，该步骤不会评分、消耗预算或发出 `goal` 数据块。Mastra 会在选择 Scorer 前检查评判模型，因此使用自定义 `goal.scorer` 时也必须能解析出评判模型。

设置按以下优先级取值：目标记录中的值、Agent 的 `goal` 配置、内置默认值（`maxRuns` 为 `50`，并使用默认评判提示词）。

### 评判模型与 Scorer {/* #judge-and-scorer */}

`goal.judge` 和 `goal.scorer` 分工不同。`goal.scorer` 是产生分数的评估流程，循环根据分数决定是否继续。`goal.judge` 是默认流程调用的评判模型。

省略 `scorer` 时，Mastra 会创建一个默认 Scorer，由 LLM 负责评判。目标达到时返回 `1`，评判模型认为 Agent 正在等待用户输入时返回 `0.5`，其他情况返回 `0`。分数为 `0.5` 时，自动循环会停止，但目标仍未完成，因此 Agent 的下一轮仍会接受评估。可用以下设置配置默认 Scorer。

* `goal.judge` 指定用来判断目标是否达成的模型。
* `goal.prompt` 为评判模型提供额外指令。默认使用内置目标评判提示词。
* `goal.tools` 指定评判模型可在做决定前调用的只读验证工具，让它能核实实际工作成果，而非只根据 Agent 的文字评分。
* `goal.maxSteps` 限制评判模型自身执行循环的步数，默认为 `5`。

传入 `goal.scorer` 可将默认流程替换为自定义 [Scorer](/reference/evals/create-scorer)，接受 Scorer 实例或已注册的 Scorer ID。自定义 Scorer 自行评判，因此 `goal.prompt`、`goal.tools` 和 `goal.maxSteps` 不再适用，Mastra 也不会为评判另行解析模型。如果 `goal.judge` 是解析函数，它仍会运行，但返回值会被丢弃。

使用 `judge`、`maxRuns` 和 `prompt` 配置默认 Scorer。

```typescript title="src/mastra/agents/worker.ts"
import { Agent } from '@mastra/core/agent'

const worker = new Agent({
  id: 'worker',
  name: 'worker',
  instructions: 'You complete software tasks end to end.',
  model: '__GATEWAY_OPENAI_MODEL__',
  memory,
  goal: {
    // A resolver function lets you inject provider credentials and read the
    // current judge selection at runtime; returning `undefined` keeps the
    // goal step a no-op.
    judge: ({ requestContext }) => resolveJudgeModel(requestContext),
    maxRuns: 30,
    prompt: 'Only mark the goal complete when tests pass.',
  },
})
```

要由自定义 Scorer 作出判断，请将其作为 `scorer` 传入，并保留 `judge` 设置，因为启用时仍会检查评判模型。

```typescript oxfmt:false
goal: {
  judge: '__GATEWAY_OPENAI_MODEL_LUNA__',
  // Replaces the built-in judge pipeline. `prompt`, `tools`, and `maxSteps` no longer apply.
  scorer: 'tests-pass',
}
```

## 管理目标 {/* #managing-the-objective */}

用 `Agent` 方法管理 Thread 的目标。这些方法需要已配置存储和 `threadId`。如果运行未使用 Memory，调用不会产生任何效果。

```typescript title="src/mastra/objective.ts"
// Read the current objective record.
const record = await worker.getObjective({ threadId })

// Update options on the active objective (only provided fields are written;
// unset fields fall back to the agent's `goal` config).
await worker.updateObjectiveOptions({ threadId, maxRuns: 100 })

// Drop the objective.
await worker.clearObjective({ threadId })
```

目标记录包含可选的 `activeDurationMs`，供界面显示 Agent 推进目标所用的时间。Agent 为活动目标工作时，Mastra 会累加这个值，并在运行结束或等待工具审批时保存。缺省值视为零。该时长只统计 Agent 的执行时间，与目标创建后经过的总时间不同。

`setObjective` 或 `updateObjectiveOptions` 写入的目标专属设置优先于 Agent 的 `goal` 配置，该优先级保存在 Thread 状态中。完整数据块结构见 [ChunkType 参考中的 `GoalEvaluationPayload`](/reference/streaming/ChunkType)。
