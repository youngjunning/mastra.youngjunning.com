# Harness

Harness 让 Agent 能持续推进复杂的长期目标，同时保留进度、公开状态并接受引导。即使发生重试或中断，进度也会保留。人员和其他系统可以查看进度、补充上下文、批准操作、调整任务方向或停止 Agent。

凡是需要持续推进的工作，都可以用 Agent Harness。例如，编码 Agent 可以跟进代码变更的 CI 和评审，软件工厂（如 [Mastra Factory](https://factory.mastra.ai)）可以协调多个并行任务，SRE Agent 可以随故障进展调整处置方式，市场拓展 Agent 则可以根据客户账户、信号和对话的变化作出响应。

在 Mastra 中，Harness 是一组将 Agent 管理扩展到单次连续运行之外的功能。可按需单独或组合使用。

## 何时使用 Harness {/* #when-to-use-a-harness */}

根据 Agent 的需要选择切入点，可以使用其中一项或多项功能。

| 目标 | 从这里开始 | 作用 |
| - | - | - |
| 客户端断开或服务器重启后仍可继续访问运行 | [持久化 Agent](/docs/harness/durable-agents) | 保存运行状态，让客户端重新连接到该次运行的流。 |
| 运行耗时的 Tool、Workflow 或子 Agent 而不阻塞当前工作 | [后台任务](/docs/harness/background-tasks) | 异步完成工作并将结果返回给 Agent。 |
| 让 Agent 持续工作直至达成目标 | [目标](/docs/harness/goals) | 检查会话线程中的目标，直到目标完成或用尽运行预算。 |
| 定期自动启动工作 | [调度](/docs/harness/schedules) | 按 cron 计划启动独立运行，或向现有会话线程发送提示。 |
| 补充上下文、调整正在进行的工作，或唤醒空闲会话线程 | [信号](/docs/signals/overview) | 立即传入输入，或留待下一轮处理。 |
| 响应 GitHub、Slack、持续集成或其他外部系统中的变化 | [信号提供方](/docs/signals/signal-providers) | 跟踪订阅，将匹配的事件转发给 Agent 的会话线程。 |
| 构建支持会话、模式、状态、审批和事件的交互产品，或让用户调整方向、安排后续工作和停止运行 | [AgentController](/docs/harness/agent-controller) | 让相互隔离的会话共享 Agent 运行时，各会话独立控制自己的运行。 |
| 为 Agent 提供文件、Shell 和编码所需的默认配置 | [`createCodingAgent()`](/reference/coding-agent/create-coding-agent) | 创建已配置 Workspace、任务跟踪和重试的标准 Agent。 |
