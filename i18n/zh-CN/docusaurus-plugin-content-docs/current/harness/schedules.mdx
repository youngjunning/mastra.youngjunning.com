# 定时任务

**引入版本：** `@mastra/core@1.50.0`

定时任务按 cron 表达式运行 Agent。每次触发时，Mastra 会把提示词作为[信号](/docs/signals/sending-signals)投递到会话线程，或者发起一次不绑定线程的 [`agent.generate()`](/reference/agents/generate) 调用。你可以用它生成每日摘要、定期检查，或定时在对话中发出提醒。

定时任务会持久化，重启或重新部署后仍然有效。运行时通过 [`mastra.schedules`](/reference/schedules/overview) 统一创建、读取、更新和删除任务。同一个接口也管理 [Workflow 定时任务](/docs/workflows/scheduled-workflows)：用 `workflowId` 代替 `agentId` 即可。

:::note

定时任务需要实现 schedules 模块的[存储](/docs/storage)适配器。支持哪些适配器以及 API 如何工作，请参阅 [`mastra.schedules` 参考](/reference/schedules/overview)。

:::

持久化任务并不保证每次触发都能投递成功。调度器会尽力发布，最多尝试三次。如果尝试耗尽或发布端崩溃，本次触发可能被跳过。跳过的触发不会补发，但后续仍可按计划触发。如何报告失败以及手动重跑时应注意什么，请参阅[定时任务投递保证](/reference/schedules/overview#delivery-guarantees)。

## 快速入门 {/* #quickstart */}

以下任务每小时运行一次 `pinger` Agent。它不绑定会话线程，因此每次触发都会独立调用 `agent.generate()`。

```typescript title="src/mastra/schedules.ts"
import { Mastra } from '@mastra/core'
import { Agent } from '@mastra/core/agent'
import { LibSQLStore } from '@mastra/libsql'

const pinger = new Agent({
  id: 'pinger',
  name: 'Pinger',
  instructions: 'Report the current system status in one sentence.',
  model: '__GATEWAY_OPENAI_MODEL__',
})

const mastra = new Mastra({
  agents: { pinger },
  storage: new LibSQLStore({ id: 'mastra-storage', url: 'file:./mastra.db' }),
})

await mastra.schedules.create({
  agentId: 'pinger',
  cron: '0 * * * *',
  prompt: 'Give me a status update.',
})
```

只有在运行 Mastra 后台 [Worker](/docs/deployment/workers) 的进程中，定时任务才会触发。`mastra dev` 和 `mastra build` 生成的服务器会自动启动 Worker。如果使用[服务器适配器](/docs/server/server-adapters)或自定义脚本，请自行调用 `mastra.startWorkers()`，否则任务只会保存，不会触发。参阅[启动后台 Worker](/docs/server/server-adapters#start-background-workers)。

## 触发周期 {/* #cadence */}

定时任务按 cron 表达式触发。`cron` 字段支持标准的 5、6 或 7 段表达式，并在创建或更新任务时进行校验。

也可以使用 `croner` 的别名，例如 `@hourly`、`@daily`、`@weekly`、`@monthly` 和 `@midnight`。若要指定日期和时间的组合，请直接填写 cron 表达式：

```typescript
// Every weekday at 9am
await mastra.schedules.create({
  agentId: 'pinger',
  cron: '0 9 * * 1-5',
  prompt: 'Start-of-day check.',
})
```

将 `timezone` 设为 IANA 时区，例如 `America/New_York`，可以避免触发时间受宿主环境区域设置影响。省略时，cron 按主机的本地时区计算。

如果想以更易读的方式构造表达式，可以使用 [`cron-time-generator`](https://www.npmjs.com/package/cron-time-generator) 等第三方工具，将生成结果传给 `cron`。

## 是否绑定会话线程 {/* #threadless-and-threaded-schedules */}

Agent 定时任务有两种触发方式，取决于是否传入 `threadId`。

### 不绑定线程 {/* #threadless */}

未传入 `threadId` 时，每次触发都是一次独立的 `agent.generate()` 调用，不会向会话线程写入内容。这是最简单的方式，适合状态检查、报告生成等不需要对话上下文的工作。

### 绑定线程 {/* #threaded */}

传入 `threadId` 后，任务会向该线程发送[信号](/docs/signals/sending-signals)，将提示词加入 Agent 的对话。提供 `threadId` 时还必须提供 `resourceId`。

```typescript title="src/mastra/schedules.ts"
await mastra.schedules.create({
  agentId: 'pinger',
  cron: '0 9 * * *',
  prompt: 'Summarize anything new since yesterday.',
  threadId: 'thread-123',
  resourceId: 'user-456',
})
```

绑定线程的任务可通过额外字段指定信号类型、XML 标签及其属性，以及线程处于活动或空闲状态时的投递行为。这些字段与 [`agent.sendSignal()`](/docs/signals/sending-signals) 的选项对应，并保持可 JSON 序列化，以便随任务一起保存。

只有提供 `threadId` 才能使用这些字段。完整的输入结构请参阅 [Agent 定时任务输入参考](/reference/schedules/overview#createinput)。

```typescript
await mastra.schedules.create({
  agentId: 'pinger',
  cron: '0 9 * * *',
  prompt: 'Summarize anything new since yesterday.',
  threadId: 'thread-123',
  resourceId: 'user-456',
  tagName: 'check-in', // renders as <check-in>…</check-in>
  attributes: { source: 'cron' },
  ifActive: { behavior: 'discard' }, // skip if the thread is mid-stream
  ifIdle: {
    behavior: 'wake', // wake the agent if the thread is idle
    streamOptions: { requestContext: { locale: 'en-US' } },
  },
})
```

每次触发时，`providerOptions` 都会合并到信号载荷中，无论任务是否绑定线程。

## 管理定时任务 {/* #managing-schedules */}

所有定时任务操作都通过 `mastra.schedules` 完成，包括创建、读取、更新、暂停、恢复、手动运行和删除。

```typescript
const schedule = await mastra.schedules.create({
  agentId: 'pinger',
  cron: '0 * * * *',
  prompt: 'Status check.',
})

await mastra.schedules.pause(schedule.id)
await mastra.schedules.resume(schedule.id)
await mastra.schedules.run(schedule.id) // Fire once now, off-schedule
```

`pause` 和 `resume` 的状态变更会持久化。`run` 会立即触发一次任务，不影响原有周期。完整的方法、筛选条件和可更新字段请参阅 [`mastra.schedules` 参考](/reference/schedules/overview)。

### Workflow 定时任务 {/* #workflow-schedules */}

同一个服务也能定时运行 Workflow。请传入 `workflowId` 和 Workflow 所需的字段：

```typescript
await mastra.schedules.create({
  workflowId: 'daily-report',
  cron: '0 9 * * *',
  inputData: { userId: 'system' },
})
```

通过此方式创建的 Workflow 定时任务与 `createWorkflow` 中声明的 `schedule` 字段相互独立。有关声明式写法和 Studio 界面，请参阅[定时运行 Workflow](/docs/workflows/scheduled-workflows)。

### 自定义 ID {/* #custom-ids */}

如果希望之后用一个事先确定的标识来查找、更新或删除任务，请传入 `id`。

```typescript
await mastra.schedules.create({
  id: 'nightly-summary',
  agentId: 'pinger',
  cron: '0 9 * * *',
  prompt: 'Summarize anything new since yesterday.',
})
```

ID 的规范化规则和重复 ID 的处理方式请参阅 [`create(input)` 参考](/reference/schedules/overview#createinput)。

### 从客户端管理 {/* #from-the-client */}

`@mastra/client-js` 通过 `/api/schedules` 路由提供同样的操作，因此可以从另一个进程或用户界面管理定时任务。客户端方法列表见 [client-js 的 Agent 定时任务参考](/reference/client-js/agents#agent-schedules)。

## 生命周期钩子 {/* #lifecycle-hooks */}

钩子可在 Agent 定时任务生命周期的关键节点执行代码，例如计算本次触发的参数或处理触发结果。在 `Mastra` 构造函数的 `schedules` 下配置钩子。所有 Agent 的定时任务共用同一组平铺配置；每个钩子的上下文都提供本次触发的 `agentId`，可按它区分处理逻辑。这组钩子设在 `Mastra` 层级，因此同时适用于代码定义的 Agent 和存储中的 Agent。

```typescript title="src/mastra/index.ts"
import { Mastra } from '@mastra/core'
import { LibSQLStore } from '@mastra/libsql'

const mastra = new Mastra({
  agents: { pinger },
  storage: new LibSQLStore({ id: 'mastra-storage', url: 'file:./mastra.db' }),
  schedules: {
    prepare: async ({ agentId, schedule, trigger }) => {
      // Return overrides, null to skip this fire, or undefined for defaults
      return { prompt: `Status as of ${trigger.firedAt.toISOString()}` }
    },
    onFinish: async ({ agentId, outcome, runId }) => {
      // Runs on any non-error, non-abort outcome. For a threaded schedule, this is the hand-off, not the end of the run
    },
    onError: async ({ agentId, phase, error }) => {
      // Runs when prepare or the signal threw, or a threadless run failed without aborting
    },
    onAbort: async ({ agentId, runId }) => {
      // Runs when a threadless run was aborted
    },
  },
})
```

支持以下钩子：

- `prepare`：触发前执行。返回对象可覆盖本次触发的参数，如 `prompt` 或 `threadId`；返回 `null` 会跳过本次触发；返回 `undefined` 则使用已保存的默认值。
- `onFinish`：每次触发在没有出错或中止的情况下调用一次。若绑定线程的任务发起新的运行，运行一开始就会以 `outcome: 'succeeded'` 调用该钩子，无需等运行结束。
- `onError`：`prepare` 或信号处理失败后调用。对于没有 `threadId` 的任务，Agent 运行因非中止错误而失败时也会调用。
- `onAbort`：没有 `threadId` 的任务在运行被中止时调用。

对于指定了 `threadId` 的任务，Worker 将提示词发到线程后不会等待运行结束。运行开始后的错误和中止会反映在线程的该次运行中，不会触发 `onError` 或 `onAbort`。

如果需要在运行结束后执行操作，请使用不绑定线程的任务。如果需要管理生命周期状态、清理、重试或执行多个步骤，请使用 [Workflow 定时任务](/docs/workflows/scheduled-workflows)。

每个钩子的上下文除了包含 `schedule` 和 `trigger`，还包含 `agentId`，也就是本次任务触发的 Agent。

系统会捕获并记录钩子抛出的异常。这些异常不会改变 Worker 的处理流程，也不会触发其他钩子。

## 在 Mastra Code 中定期发送提示词 {/* #recurring-prompts-in-mastra-code */}

Mastra Code 的 `/schedules` 命令可以为当前会话线程设置周期性提示词。与 `mastra.schedules` 不同，这类任务仅存在于创建它们的 Mastra Code 进程中，不写入存储；每次触发都直接通过 `agent.sendSignal()` 向线程发送提示词。

运行 `/schedules` 会打开菜单，显示 **Create schedule** 和当前线程中的每项任务。创建步骤如下：

1. 选择每次触发时发送的内容：提示词（**Prompt**）、每次触发时重新读取的提示词文件（**Prompt file**），或每次触发时执行的脚本（**Script**）。
1. 输入提示词文本或文件路径。相对路径以项目根目录为基准。如果选择脚本，可以添加一段提示词，在脚本输出之后发送。
1. 选择从 `1m` 到 `1d` 的触发周期，或输入 `20m`、`3h` 等自定义周期。按分钟设置时，间隔必须能整除一小时；按小时设置时，间隔必须能整除一天。
1. 确认创建。

脚本从项目根目录运行，超时为 60 秒。标准输出、标准错误输出和退出码会用作提示词。附加的提示词不会传给脚本。

选中已有任务后，可选择 **Run now**、**Pause** 或 **Resume**，以及 **Delete**。**Run now** 会立即触发一次且不改变原定周期，已暂停的任务也可手动触发。如果同一任务的上次触发仍在运行，则跳过本次触发。

每次触发都会以 `user` 类型的信号进入线程，并在对话记录中显示为 `schedule` 条目，包含任务 ID、触发周期、来源和脚本退出状态。如果线程正在运行，Agent 会把提示词当作下一条输入，和你在运行中输入的消息一样。如果线程空闲，就会被唤醒并运行。进程中的所有线程都可以触发各自的任务，包括当前未在终端聚焦的线程。执行 `/new` 后，新建任务会绑定到新线程。

使用时请注意：

- **仅限当前会话。** 定时任务只存在于创建它们的 Mastra Code 进程中，进程退出后便停止。其他 Mastra Code 进程即使共用同一数据库，也无法看到或触发这些任务。
- **按整点刻度触发。** `5m` 在每小时的 :00、:05、:10 等时刻触发；首次触发时间并不固定为创建五分钟后。`1d` 在当地午夜触发。与 cron 一样，按小时或天设置的周期以当地钟表时间为准，适用夏令时切换。设备休眠期间错过的触发，以及计时器迟到超过一分钟的触发，都会跳过；任务将在下一个时间刻度继续触发。
- **跳过重叠的触发。** 到达下一次预定时间时，如果脚本仍在运行，就跳过这一次。

### Agent 定时任务工具 {/* #agent-schedule-tools */}

在 `/settings` 中启用 **Experimental schedule tools** 并重启后，Agent 可使用以下工具管理同一批定时任务：`schedule_create`、`schedule_list`、`schedule_update`（暂停或删除）、`schedule_resume` 和 `schedule_run`。这些工具只能查看和修改调用发生所在的运行线程中的任务。由于定时任务可在每次触发时执行脚本，除非启用了 YOLO 模式，否则 `schedule_create`、`schedule_resume` 和 `schedule_run` 需要与运行 shell 命令相同的批准。Agent 创建的任务会在对话记录中标记为 `created by agent`。
