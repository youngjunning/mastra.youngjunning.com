# 授权

Mastra 允许您选择处理身份验证的方式，以便您可以安全地访问您的 API 和[Studio](/docs/studio/overview)使用适合您的堆栈的身份系统。

您可以从基本的共享秘密 JWT 身份验证开始，并在需要更高级的身份功能时切换到已知的Provider。

## 身份验证保护什么 {/* #what-auth-secures */}

配置身份验证可以锁定两件事：

* **工作室用户界面**：Studio 显示登录屏幕（SSO、电子邮件/密码或两者）。当您还配置 RBAC 提供程序时，Studio 会强制实施基于角色的访问控制，以确定每个团队成员可以看到和执行的操作。
* **API路线**：内置路线（`/api/agents/*`, `/api/workflows/*`, etc.) and custom routes require authentication, whether requests come from Studio or direct API calls. A few built-in routes stay public, such as `GET /api/auth/capabilities`, which Studio uses to detect the login state.

默认情况下，您设置的Provider`server.auth` protects both. To give Studio its own provider, also set `studio.auth`. Requests from Studio, including its calls to API routes, then use `studio.auth` exclusively. All other requests keep using `server.auth`.

身份验证是可选的。如果未配置身份验证，则所有路由和 Studio 均可公开访问。可以使用以下命令在各个自定义路由上启用公共访问`requiresAuth: false`.

看[Custom API Routes](/docs/server/custom-api-routes#authentication) for controlling authentication on custom endpoints. Visit the [Studio Auth docs](/docs/studio/auth) for more on securing your Studio deployment.

:::警告
默认身份验证配置可保护`/api/*` and treats `/api`, `/api/auth/*` as public. When you set a custom `server.apiPrefix`, those defaults no longer match and built-in routes fall outside the protected pattern. Update `server.auth.protected` and `server.auth.public` to reference your new prefix.
:::

：：：笔记

Studio 身份验证目前受以下Provider支持：Simple Auth、JWT、WorkOS、Better Auth 和 Google。

:::
