# 身份验证

Mastra 支持多种身份验证方式。可选择适合现有技术栈的身份系统，保护 API 和 [Studio](/docs/studio/overview) 的访问。

可以先使用共享密钥进行基本的 JWT 身份验证，需要更高级的身份管理功能时，再切换到已有的身份提供方。

## 身份验证的保护范围 {/* #what-auth-secures */}

配置身份验证后，以下两处的访问会受到保护：

- **Studio 界面**：Studio 会显示登录页面，支持单点登录（SSO）、邮箱和密码登录，或同时支持两种方式。配置 RBAC 提供方后，Studio 还会按角色限制每位团队成员能查看的内容和能执行的操作。
- **API 路由**：无论请求来自 Studio 还是直接调用 API，内置路由（如 `/api/agents/*`、`/api/workflows/*`）和自定义路由都要求身份验证。少数内置路由仍然公开，例如 Studio 用来检测登录状态的 `GET /api/auth/capabilities`。

默认由 `server.auth` 中配置的提供方保护这两处。如需为 Studio 单独指定提供方，请同时设置 `studio.auth`。此后，来自 Studio 的所有请求（包括对 API 路由的调用）只使用 `studio.auth`，其他请求仍使用 `server.auth`。

身份验证是可选的。如果未配置，所有路由和 Studio 都可公开访问。也可在单条自定义路由上设置 `requiresAuth: false`，允许公开访问。

如何控制自定义端点的身份验证，请参阅[自定义 API 路由](/docs/server/custom-api-routes#authentication)。如何保护部署后的 Studio，请参阅 [Studio 身份验证文档](/docs/studio/auth)。

:::warning
默认的身份验证配置保护 `/api/*`，并将 `/api` 和 `/api/auth/*` 设为公开路由。如果自定义了 `server.apiPrefix`，默认规则将无法匹配新前缀，导致内置路由不再受保护。请更新 `server.auth.protected` 和 `server.auth.public`，使其使用新前缀。
:::

:::note

Studio 目前支持以下身份验证提供方：Simple Auth、JWT、WorkOS、Better Auth 和 Google。

:::
