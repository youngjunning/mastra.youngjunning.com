# Worker 身份验证

:::beta

在 API 稳定之前，可能会在没有重大版本更新的情况下发生重大更改。

:::

Worker 和 API 分属不同进程时，通过 HTTP 通信。编排 Worker 调用 API 的步骤执行端点，在 API 服务器上运行 Workflow 步骤。推送模式的 PubSub Broker（如采用推送模式的 Google Cloud Pub/Sub）也能直接向 API 的事件端点发送事件。这与拉取模式不同：拉取模式的 Worker 自行从 Broker 获取事件。配置了身份验证 Provider 后，这两个 HTTP 端点都需要验证身份。

## 工作原理 {/* #how-it-works */}

Worker 与 Mastra 服务器的其他请求共用身份验证流程。编排 Worker 在每个 HTTP 请求中附带凭证，由服务器配置的 `authenticateToken` Provider 验证。

|端点 |使用者 |目的|
| - | - | - |
| `POST /api/workflows/:workflowId/runs/:runId/steps/execute` | 编排 Worker，通过 `HttpRemoteStrategy` 调用 | 在 API 服务器上执行 Workflow 步骤 |
| `POST /api/workflows/events` | Push-mode brokers (GCP Pub/Sub, SNS) | Deliver workflow events to the API |

两条路线都有`requiresAuth: true`. When no auth provider is configured, they're publicly accessible.

:::warning

将工作程序部署为单独的进程时，请始终在服务器上配置身份验证提供程序。如果没有，步骤执行和事件端点将对任何调用者开放。

:::

## 设置 Worker 身份验证 {/* #setting-up-worker-auth */}

### 在服务器上配置身份验证提供者 {/* #configure-an-auth-provider-on-the-server */}

可以使用任意 Mastra 身份验证 Provider。`SimpleAuth` 适合验证 Worker 令牌：

```typescript title="src/mastra/index.ts"
import { Mastra } from '@mastra/core/mastra'
import { SimpleAuth } from '@mastra/core/server'

export const mastra = new Mastra({
  server: {
    auth: new SimpleAuth({
      tokens: {
        [process.env.WORKER_TOKEN!]: {
          id: 'worker',
          name: 'Orchestration Worker',
          role: 'worker',
        },
      },
    }),
  },
  // ... storage, pubsub, etc.
})
```

### 设置 Worker 令牌 {/* #set-the-worker-token */}

在每个 Worker 容器中，将 `MASTRA_WORKER_AUTH_TOKEN` 设为服务器的身份验证 Provider 能识别的令牌：

```yaml title="docker-compose.yml"
services:
  api:
    environment:
      WORKER_TOKEN: ${WORKER_TOKEN}
      # ... other env vars

  orchestration-worker:
    environment:
      MASTRA_WORKER_AUTH_TOKEN: ${WORKER_TOKEN}
      MASTRA_STEP_EXECUTION_URL: http://api:4111/api # Use HTTPS in production
      # ... other env vars
```

```bash title=".env"
WORKER_TOKEN=sk-worker-secret-token
```

示例中的 `http://` 用于本地开发。生产环境请使用 HTTPS URL，并在服务网格或入口控制器终止 TLS。参见[安全建议](#security-recommendations)。

编排 Worker 读取 `MASTRA_WORKER_AUTH_TOKEN`，并在每次执行步骤的请求中通过 `Authorization` 请求头发送 `Bearer` 令牌。

## 身份验证凭证类型 {/* #auth-credential-types */}

这`HttpRemoteStrategy` supports three credential formats. The default (`bearer`) covers most setups.

### Bearer 令牌 {/* #bearer-token */}

设置 `MASTRA_WORKER_AUTH_TOKEN` 后，该策略会发送 `Authorization: Bearer <token>`：

```bash
MASTRA_WORKER_AUTH_TOKEN=sk-worker-secret-token
```

### API 密钥标头 {/* #api-key-header */}

通过 `x-worker-api-key` 发送凭证，取代 `Authorization`：

```typescript
import { HttpRemoteStrategy } from '@mastra/core/worker'

const strategy = new HttpRemoteStrategy({
  serverUrl: 'http://api:4111/api', // Use HTTPS in production
  auth: { type: 'api-key', key: process.env.WORKER_API_KEY! },
})
```

服务器的身份验证 Provider 必须读取 `x-worker-api-key` 请求头来验证凭证。

### 自定义标头 {/* #custom-header */}

使用任何标头名称和值：

```typescript
import { HttpRemoteStrategy } from '@mastra/core/worker'

const strategy = new HttpRemoteStrategy({
  serverUrl: 'http://api:4111/api', // Use HTTPS in production
  auth: {
    type: 'header',
    name: 'X-Internal-Service-Key',
    value: process.env.INTERNAL_KEY!,
  },
})
```

## 推送模式下的 Broker 身份验证 {/* #push-mode-broker-auth */}

使用推送模式的 PubSub（如 Google Cloud Pub/Sub）时，Broker 直接将事件 POST 到 `/api/workflows/events` 端点，并附上自身凭证。例如，Google Cloud Pub/Sub 会发送由 Google 签名的 OIDC 令牌。

身份验证 Provider 的 `authenticateToken` 回调必须能识别 Broker 发送的凭证。具体的验证方式请查阅 Broker 的文档。

## 安全建议 {/* #security-recommendations */}

- **不同类型的 Worker 使用不同令牌。** 这样可以撤销某个 Worker 的访问权限，而不影响其他 Worker。
- **定期轮换令牌。** 更新 `WORKER_TOKEN` 环境变量，然后重启受影响的容器。
* **在生产中使用 TLS。**&#x57;orker 到 API 的通信应通过 HTTPS 进行，以保护传输中的令牌。这适用于所有环境，包括 Kubernetes 集群和 Docker 网络。使用服务网格（例如 Istio、Linkerd）或 TLS 终止入口来加密内部流量。
* **限制网络访问。**&#x6B65;骤执行和事件端点是内部的。如果可能，请使用网络策略或防火墙规则让它们远离公共互联网。
