# 工人

:::测试版

在 API 稳定之前，可能会在没有重大版本更新的情况下发生重大更改。

:::

当工作线程在与 API 不同的进程中运行时，它们通过 HTTP 进行通信。编排工作线程调用 API 的步骤执行端点以在 API 服务器上运行Workflow步骤。推送模式 PubSub Agent（例如推送模式下的 Google Cloud Pub/Sub）还可以将事件直接传递到 API 的事件端点。这是与拉模式工作人员不同的集成路径，拉模式工作人员从Agent本身拉取事件。配置身份验证提供程序时，两个 HTTP 端点都需要身份验证。

## 它是如何运作的 {/* #how-it-works */}

工作人员身份验证使用与 Mastra 服务器的其余部分相同的身份验证管道。编排工作人员通过每个 HTTP 请求发送凭据，以及服务器的配置`authenticateToken` provider validates them.

|端点 |使用者 |目的|
| - | - | - |
|`POST /api/workflows/:workflowId/runs/:runId/steps/execute` | Orchestration worker via `HttpRemoteStrategy` | Execute a workflow step on the API |
| `POST /api/workflows/events` | Push-mode brokers (GCP Pub/Sub, SNS) | Deliver workflow events to the API |

两条路线都有`requiresAuth: true`. When no auth provider is configured, they're publicly accessible.

：：：警告

将工作程序部署为单独的进程时，请始终在服务器上配置身份验证提供程序。如果没有，步骤执行和事件端点将对任何调用者开放。

:::

## 设置工人身份验证 {/* #setting-up-worker-auth */}

### 在服务器上配置身份验证提供者 {/* #configure-an-auth-provider-on-the-server */}

使用任何 Mastra 身份验证Provider。`SimpleAuth` works well for worker tokens:

```typescript title="src/mastra/index.ts"
import { Mastra } from '@mastra/core/mastra'
import { SimpleAuth } from '@mastra/core/server'

export const mastra = new Mastra({
  server: {
    auth: new SimpleAuth({
      tokens: {
        [process.env.WORKER_TOKEN!]: {
          id: 'worker',
          name: 'Orchestration Worker',
          role: 'worker',
        },
      },
    }),
  },
  // ... storage, pubsub, etc.
})
```

### 设置工人令牌 {/* #set-the-worker-token */}

在每个工作容器上，设置`MASTRA_WORKER_AUTH_TOKEN` to a token that the server's auth provider recognizes:

```yaml title="docker-compose.yml"
services:
  api:
    environment:
      WORKER_TOKEN: ${WORKER_TOKEN}
      # ... other env vars

  orchestration-worker:
    environment:
      MASTRA_WORKER_AUTH_TOKEN: ${WORKER_TOKEN}
      MASTRA_STEP_EXECUTION_URL: http://api:4111/api # Use HTTPS in production
      # ... other env vars
```

```bash title=".env"
WORKER_TOKEN=sk-worker-secret-token
```

这些示例使用`http://` for local development. In production, use HTTPS URLs and terminate TLS with a service mesh or ingress controller. See [Security recommendations](#security-recommendations).

编排工作者读取`MASTRA_WORKER_AUTH_TOKEN` and sends it as a `Bearer` token in the `Authorization` header on every step execution request.

## 身份验证凭证类型 {/* #auth-credential-types */}

这`HttpRemoteStrategy` supports three credential formats. The default (`bearer`) covers most setups.

### 不记名令牌 {/* #bearer-token */}

放`MASTRA_WORKER_AUTH_TOKEN` and the strategy sends `Authorization: Bearer <token>`:

```bash
MASTRA_WORKER_AUTH_TOKEN=sk-worker-secret-token
```

### API 密钥标头 {/* #api-key-header */}

将凭证发送为`x-worker-api-key` instead of `Authorization`:

```typescript
import { HttpRemoteStrategy } from '@mastra/core/worker'

const strategy = new HttpRemoteStrategy({
  serverUrl: 'http://api:4111/api', // Use HTTPS in production
  auth: { type: 'api-key', key: process.env.WORKER_API_KEY! },
})
```

您的服务器的身份验证提供者必须阅读`x-worker-api-key` header to validate this credential.

### 自定义标头 {/* #custom-header */}

使用任何标头名称和值：

```typescript
import { HttpRemoteStrategy } from '@mastra/core/worker'

const strategy = new HttpRemoteStrategy({
  serverUrl: 'http://api:4111/api', // Use HTTPS in production
  auth: {
    type: 'header',
    name: 'X-Internal-Service-Key',
    value: process.env.INTERNAL_KEY!,
  },
})
```

## 推送模式Agent身份验证 {/* #push-mode-broker-auth */}

当使用推送模式 PubSub（如 Google Cloud Pub/Sub）时，Agent将事件直接发布到`/api/workflows/events` endpoint. The broker attaches its own credentials. For example, Google Cloud Pub/Sub sends a Google-signed OIDC token.

您的授权Provider的`authenticateToken` callback must recognize whatever credential the broker sends. See your broker's documentation for the authentication scheme it uses.

## 安全建议 {/* #security-recommendations */}

* **为不同的工人类型使用不同的代币。**&#x8FD9;使您可以撤销对一名工作人员的访问权限，而不会影响其他工作人员。
* **按计划轮换令牌。**&#x66F4;新`WORKER_TOKEN` environment variable and restart the affected containers.
* **在生产中使用 TLS。**&#x57;orker 到 API 的通信应通过 HTTPS 进行，以保护传输中的令牌。这适用于所有环境，包括 Kubernetes 集群和 Docker 网络。使用服务网格（例如 Istio、Linkerd）或 TLS 终止入口来加密内部流量。
* **限制网络访问。**&#x6B65;骤执行和事件端点是内部的。如果可能，请使用网络策略或防火墙规则让它们远离公共互联网。
