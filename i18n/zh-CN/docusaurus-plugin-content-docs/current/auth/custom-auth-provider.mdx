# 自定义身份验证提供者

自定义身份验证 Provider 可接入内置 Provider 尚未支持的身份系统。继承 `MastraAuthProvider` 基类，即可与任意身份验证系统集成。

## 概述 {/* #overview */}

身份验证 Provider 负责对传入请求进行身份验证和授权：

* 令牌验证和用户提取
* 用户授权逻辑
* 基于路径的访问控制（公共/受保护的路由）

创建自定义身份验证 Provider，可支持：

* 自托管身份系统
* 自定义令牌格式或验证逻辑
* 特定场景的授权规则
* 企业 SSO 集成

## 创建自定义身份验证提供程序 {/* #creating-a-custom-auth-provider */}

继承 `MastraAuthProvider` 类并实现必需的方法：

```typescript
import { MastraAuthProvider } from '@mastra/core/server'
import type { MastraAuthProviderOptions, MastraAuthRequest } from '@mastra/core/server'

// Define your user type
type MyUser = {
  id: string
  email: string
  roles: string[]
}

// Define options for your provider
interface MyAuthOptions extends MastraAuthProviderOptions<MyUser> {
  apiUrl?: string
  apiKey?: string
}

export class MyAuthProvider extends MastraAuthProvider<MyUser> {
  protected apiUrl: string
  protected apiKey: string

  constructor(options?: MyAuthOptions) {
    // Call super with a name for logging/debugging
    super({ name: options?.name ?? 'my-auth' })

    const apiUrl = options?.apiUrl ?? process.env.MY_AUTH_API_URL
    const apiKey = options?.apiKey ?? process.env.MY_AUTH_API_KEY

    if (!apiUrl || !apiKey) {
      throw new Error(
        'Auth API URL and API key are required. Provide them in options or set MY_AUTH_API_URL and MY_AUTH_API_KEY environment variables.',
      )
    }

    this.apiUrl = apiUrl
    this.apiKey = apiKey

    // Register any custom options (authorizeUser override, public/protected paths)
    this.registerOptions(options)
  }

  /**
   * Verify the token and return the user
   * Return null if authentication fails
   */
  async authenticateToken(token: string, request: MastraAuthRequest): Promise<MyUser | null> {
    try {
      const response = await fetch(`${this.apiUrl}/verify`, {
        method: 'POST',
        headers: {
          'Content-Type': 'application/json',
          'X-API-Key': this.apiKey,
        },
        body: JSON.stringify({ token }),
      })

      if (!response.ok) {
        return null
      }

      const user = await response.json()
      return user
    } catch (error) {
      console.error('Token verification failed:', error)
      return null
    }
  }

  /**
   * Check if the authenticated user is authorized
   * Return true to allow access, false to deny
   */
  async authorizeUser(user: MyUser, request: MastraAuthRequest): Promise<boolean> {
    // Basic authorization: user must exist and have an ID
    return !!user?.id
  }
}
```

## 所需方法 {/* #required-methods */}

### `authenticateToken()` {/* #authenticatetoken */}

验证传入的令牌；令牌有效时返回用户对象，身份验证失败时返回 `null`。

```typescript oxfmt:false
async authenticateToken(token: string, request: MastraAuthRequest): Promise<TUser | null>
```

| 参数 | 类型 | 说明 |
| - | - | - |
| `token` | `string` | 从 `Authorization` 请求头提取的 Bearer 令牌 |
| `request` | `MastraAuthRequest` | 传入的请求。使用 `getRequestHeader()` 读取请求头，使用 `getWebRequest()` 获取底层 Web `Request`；两者均由 `@mastra/core/server` 导出 |

**返回值**：身份验证成功时返回用户对象，失败时返回 `null`。

令牌会自动从 `Authorization: Bearer <token>` 请求头中提取。如需读取其他请求头或 Cookie，请使用 `request` 参数。

### `authorizeUser()` {/* #authorizeuser */}

确定是否允许经过身份验证的用户访问资源。

```typescript oxfmt:false
async authorizeUser(user: TUser, request: MastraAuthRequest): Promise<boolean> | boolean
```

| 参数 | 类型 | 说明 |
| - | - | - |
| `user` | `TUser` | `authenticateToken` 返回的用户对象 |
| `request` | `MastraAuthRequest` | 传入的请求 |

**返回值**：返回 `true` 允许访问，返回 `false` 拒绝访问（响应为 403 Forbidden）。

## 可选方法 {/* #optional-methods */}

### `toMastraUser()` {/* #tomastrauser */}

将 Provider 专属的用户对象规范化为稳定的 `MastraUser` 结构。动态配置回调（例如动态 `instructions`、`model` 或 `tools`）会通过可选的 `user` 参数接收该结构。

```typescript oxfmt:false
toMastraUser(user: TUser): MastraUser
```

| 参数 | 类型 | 说明 |
| - | - | - |
| `user` | `TUser` | `authenticateToken` 返回的用户对象 |

**返回值**：一个 `MastraUser` 对象：`{ id: string, name?: string, email?: string, avatarUrl?: string, role?: string }`。

默认实现从 `id`、`sub` 或 `userId` 获取 `id`，从 `avatarUrl` 或 `picture` 获取 `avatarUrl`，并在存在时原样传递 `name`、`email` 和 `role`。如果你的用户类型将这些字段存放在其他位置，请重写此方法：

```typescript {8-14} title="src/mastra/auth/provider.ts"
import type { MastraUser } from '@mastra/core/auth'

export class MyAuthProvider extends MastraAuthProvider<MyUser> {
  async authenticateToken(token: string) {
    /* ... */
  }

  toMastraUser(user: MyUser): MastraUser {
    return {
      id: user.accountId,
      name: user.profile.displayName,
      role: user.permissions.primaryRole,
    }
  }
}
```

如果无法从用户对象中取得 `id`，规范化后的用户会被省略，回调收到的将是 `user: undefined`。原始用户对象仍可从请求上下文中获取。

## MCP OAuth 的可选方法 {/* #optional-methods-for-mcp-oauth */}

[内置 MCP 服务器](/docs/server/mcp#oauth-discovery)通过两个可选方法完成 OAuth 发现和受众检查。

`getOAuthMetadata()` 返回 MCP 客户端应使用的授权服务器，以及可选的作用域。`server.mcp.oauth.authorizationServers` 和 `server.mcp.oauth.scopesSupported` 的配置优先。

```typescript oxfmt:false
getOAuthMetadata(): { authorizationServers?: string[]; scopesSupported?: string[] } | undefined
```

设置 `server.mcp.oauth.resource` 后，`verifyAudience()` 会在 `/api/mcp` 上运行。它接收 `authenticateToken()` 返回的值和 `resource` URL，并判断令牌是否针对该资源签发。返回 `false` 时，请求会以 `401` 拒绝；如果未实现该方法，则不会检查受众，Mastra 会记录警告。

```typescript oxfmt:false
verifyAudience(user: TUser, audience: string): boolean | Promise<boolean>
```

以下示例适用于 `authenticateToken()` 返回已验证负载的 JWT Provider：

```typescript oxfmt:false
getOAuthMetadata() {
  return { authorizationServers: ['https://auth.example.com/'] }
}

verifyAudience(user: JwtPayload, audience: string) {
  return Array.isArray(user.aud) ? user.aud.includes(audience) : user.aud === audience
}
```

## 配置选项 {/* #configuration-options */}

`MastraAuthProviderOptions` 接口支持以下选项：

| 选项 | 类型 | 说明 |
| - | - | - |
| `name` | `string` | 用于日志记录和调试的 Provider 名称 |
| `authorizeUser` | `(user, request) => Promise<boolean> \| boolean` | 自定义授权函数 |
| `protected` | `(RegExp \| string \| [string, Methods \| Methods[]])[]` | 需要身份验证的路径 |
| `public` | `(RegExp \| string \| [string, Methods \| Methods[]])[]` | 绕过身份验证的路径，除非路由设置了 `requiresAuth: true` |

### 路径模式 {/* #path-patterns */}

使用模式匹配配置哪些路径需要身份验证：

```typescript
const auth = new MyAuthProvider({
  // Paths that require authentication
  protected: [
    '/api/*', // Wildcard: all /api routes
    '/admin/*', // Wildcard: all /admin routes
    /^\/secure\/.*/, // Regex pattern
  ],

  // Paths that bypass authentication
  public: [
    '/health', // Exact match
    '/api/status', // Exact match
    ['/api/webhook', 'POST'], // Only POST requests to /api/webhook
  ],
})
```

## 辅助实用程序 {/* #helper-utilities */}

`@mastra/auth` 包提供用于常见令牌验证场景的工具函数：

### JWT 验证 {/* #jwt-verification */}

```typescript
import { verifyHmac, verifyJwks, decodeToken, getTokenIssuer } from '@mastra/auth'

// Verify HMAC-signed JWT
const payload = await verifyHmac(token, 'your-secret-key')

// Verify with JWKS (for OAuth providers)
const payload = await verifyJwks(token, 'https://provider.com/.well-known/jwks.json')

// Decode without verification (for inspection)
const decoded = await decodeToken(token)

// Get the issuer from a decoded token
const issuer = getTokenIssuer(decoded)
```

### 示例：基于 JWKS 的Provider {/* #example-jwks-based-provider */}

```typescript
import { MastraAuthProvider } from '@mastra/core/server'
import type { MastraAuthProviderOptions } from '@mastra/core/server'
import { verifyJwks } from '@mastra/auth'
import type { JwtPayload } from '@mastra/auth'

type MyUser = JwtPayload

interface MyJwksAuthOptions extends MastraAuthProviderOptions<MyUser> {
  jwksUri?: string
  issuer?: string
}

export class MyJwksAuth extends MastraAuthProvider<MyUser> {
  protected jwksUri: string
  protected issuer: string

  constructor(options?: MyJwksAuthOptions) {
    super({ name: options?.name ?? 'my-jwks-auth' })

    const jwksUri = options?.jwksUri ?? process.env.MY_JWKS_URI
    const issuer = options?.issuer ?? process.env.MY_AUTH_ISSUER

    if (!jwksUri) {
      throw new Error('JWKS URI is required')
    }

    this.jwksUri = jwksUri
    this.issuer = issuer ?? ''

    this.registerOptions(options)
  }

  async authenticateToken(token: string): Promise<MyUser | null> {
    try {
      const payload = await verifyJwks(token, this.jwksUri)

      // Optionally validate issuer
      if (this.issuer && payload.iss !== this.issuer) {
        return null
      }

      return payload
    } catch {
      return null
    }
  }

  async authorizeUser(user: MyUser): Promise<boolean> {
    // Check token hasn't expired
    if (user.exp && user.exp * 1000 < Date.now()) {
      return false
    }
    return !!user.sub
  }
}
```

## 自定义授权逻辑 {/* #custom-authorization-logic */}

提供自定义 `authorizeUser` 函数来覆盖默认授权逻辑：

```typescript
const auth = new MyAuthProvider({
  apiUrl: process.env.MY_AUTH_API_URL,
  apiKey: process.env.MY_AUTH_API_KEY,

  // Custom authorization: require admin role for all requests
  async authorizeUser(user, request) {
    return user.roles.includes('admin')
  },
})
```

### 基于角色的授权 {/* #role-based-authorization */}

```typescript
import { getWebRequest } from '@mastra/core/server'

const auth = new MyAuthProvider({
  async authorizeUser(user, request) {
    const webRequest = getWebRequest(request)
    if (!webRequest) {
      return false
    }

    const path = new URL(webRequest.url).pathname
    const method = webRequest.method

    // Admin routes require admin role
    if (path.startsWith('/admin/')) {
      return user.roles.includes('admin')
    }

    // Write operations require write role
    if (['POST', 'PUT', 'PATCH', 'DELETE'].includes(method)) {
      return user.roles.includes('write') || user.roles.includes('admin')
    }

    // Read operations allowed for all authenticated users
    return true
  },
})
```

## 测试自定义身份验证提供程序 {/* #testing-custom-auth-providers */}

使用 Vitest 的测试结构示例：

```typescript
import { describe, it, expect, vi, beforeEach } from 'vitest'
import { MyAuthProvider } from './my-auth-provider'

// Mock fetch for API calls
global.fetch = vi.fn()

describe('MyAuthProvider', () => {
  const mockOptions = {
    apiUrl: 'https://auth.example.com',
    apiKey: 'test-api-key',
  }

  beforeEach(() => {
    vi.clearAllMocks()
  })

  describe('initialization', () => {
    it('should initialize with provided options', () => {
      const auth = new MyAuthProvider(mockOptions)
      expect(auth).toBeInstanceOf(MyAuthProvider)
    })

    it('should throw error when required options are missing', () => {
      expect(() => new MyAuthProvider({})).toThrow('Auth API URL and API key are required')
    })
  })

  describe('authenticateToken', () => {
    it('should return user when token is valid', async () => {
      const mockUser = { id: 'user123', email: 'test@example.com', roles: ['read'] }
      ;(fetch as any).mockResolvedValue({
        ok: true,
        json: () => Promise.resolve(mockUser),
      })

      const auth = new MyAuthProvider(mockOptions)
      const result = await auth.authenticateToken('valid-token', {} as any)

      expect(fetch).toHaveBeenCalledWith(
        'https://auth.example.com/verify',
        expect.objectContaining({
          method: 'POST',
          body: JSON.stringify({ token: 'valid-token' }),
        }),
      )
      expect(result).toEqual(mockUser)
    })

    it('should return null when token is invalid', async () => {
      ;(fetch as any).mockResolvedValue({ ok: false })

      const auth = new MyAuthProvider(mockOptions)
      const result = await auth.authenticateToken('invalid-token', {} as any)

      expect(result).toBeNull()
    })
  })

  describe('authorizeUser', () => {
    it('should return true when user has valid id', async () => {
      const auth = new MyAuthProvider(mockOptions)
      const result = await auth.authorizeUser(
        { id: 'user123', email: 'test@example.com', roles: [] },
        {} as any,
      )

      expect(result).toBe(true)
    })

    it('should return false when user has no id', async () => {
      const auth = new MyAuthProvider(mockOptions)
      const result = await auth.authorizeUser(
        { id: '', email: 'test@example.com', roles: [] },
        {} as any,
      )

      expect(result).toBe(false)
    })
  })

  describe('custom authorization', () => {
    it('should use custom authorizeUser when provided', async () => {
      const auth = new MyAuthProvider({
        ...mockOptions,
        authorizeUser: user => user.roles.includes('admin'),
      })

      const adminUser = { id: 'user123', email: 'admin@example.com', roles: ['admin'] }
      const regularUser = { id: 'user456', email: 'user@example.com', roles: ['read'] }

      expect(await auth.authorizeUser(adminUser, {} as any)).toBe(true)
      expect(await auth.authorizeUser(regularUser, {} as any)).toBe(false)
    })
  })

  describe('route configuration', () => {
    it('should store public routes configuration', () => {
      const publicRoutes = ['/health', '/api/status']
      const auth = new MyAuthProvider({
        ...mockOptions,
        public: publicRoutes,
      })

      expect(auth.public).toEqual(publicRoutes)
    })

    it('should store protected routes configuration', () => {
      const protectedRoutes = ['/api/*', '/admin/*']
      const auth = new MyAuthProvider({
        ...mockOptions,
        protected: protectedRoutes,
      })

      expect(auth.protected).toEqual(protectedRoutes)
    })
  })
})
```

## 错误处理 {/* #error-handling */}

提供常见故障场景的描述性错误：

```typescript
export class MyAuthProvider extends MastraAuthProvider<MyUser> {
  constructor(options?: MyAuthOptions) {
    super({ name: options?.name ?? 'my-auth' })

    const apiUrl = options?.apiUrl ?? process.env.MY_AUTH_API_URL
    const apiKey = options?.apiKey ?? process.env.MY_AUTH_API_KEY

    if (!apiUrl) {
      throw new Error(
        'Missing MY_AUTH_API_URL. Set the environment variable or pass apiUrl in options.',
      )
    }

    if (!apiKey) {
      throw new Error(
        'Missing MY_AUTH_API_KEY. Set the environment variable or pass apiKey in options.',
      )
    }

    this.apiUrl = apiUrl
    this.apiKey = apiKey
    this.registerOptions(options)
  }

  async authenticateToken(token: string): Promise<MyUser | null> {
    if (!token || typeof token !== 'string') {
      return null // Immediate safe fail
    }

    try {
      const response = await fetch(`${this.apiUrl}/verify`, {
        method: 'POST',
        headers: {
          'Content-Type': 'application/json',
          'X-API-Key': this.apiKey,
        },
        body: JSON.stringify({ token }),
      })

      if (!response.ok) {
        return null
      }

      return await response.json()
    } catch (error) {
      // Log error for debugging, but don't expose details to client
      console.error('Auth verification error:', error)
      return null
    }
  }
}
```

## 内置Provider {/* #built-in-providers */}

Mastra 内置以下身份验证 Provider，可作为实现参考：

* **MastraJwtAuth**：使用 HMAC 密钥验证 JWT（`@mastra/auth`）
* **MastraAuthClerk**：Clerk 身份验证（`@mastra/auth-clerk`）
* **MastraAuthAuth0**：Auth0 身份验证（`@mastra/auth-auth0`）
* **MastraAuthSupabase**：Supabase 身份验证（`@mastra/auth-supabase`）
* **MastraAuthFirebase**：Firebase 身份验证（`@mastra/auth-firebase`）
* **MastraAuthWorkos**：WorkOS 身份验证（`@mastra/auth-workos`）
* **MastraAuthBetterAuth**：Better Auth 集成（`@mastra/auth-better-auth`）
* **SimpleAuth**：用于开发的令牌到用户映射（`@mastra/core/server`）
