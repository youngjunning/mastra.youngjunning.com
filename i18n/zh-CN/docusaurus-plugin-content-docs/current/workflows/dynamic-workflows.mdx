# 动态 Workflow

:::beta

在 API 稳定之前，即使主版本号不变，也可能出现不兼容的变更。

:::

动态 Workflow 用数据定义 Workflow。其定义是一个描述数据结构和步骤图的 JSON 文档。Mastra 验证定义后，将其注册为可运行的 Workflow 并持久化存储，以便在进程重启后恢复。

定义不包含 JavaScript 闭包，因此任何能生成 JSON 的工具都能创建 Workflow，例如 HTTP 客户端、LLM、可视化编辑器或自建工具。注册后，动态 Workflow 使用与代码定义的 Workflow 相同的执行 API。

## 何时使用动态 Workflow {/* #when-to-use-dynamic-workflows */}

如果用户、Agent、可视化编辑器或外部系统需要创建 Workflow，又不想改动应用代码或重新部署，就可以使用动态 Workflow。

如果 Workflow 属于应用源码，或需要自定义步骤函数，请继续用 [`createWorkflow()`](/docs/workflows/overview) 定义。动态 Workflow 可以调用已在 `Mastra` 实例上注册的 Agent、Tool 和 Workflow。

## 快速入门 {/* #quickstart */}

以下示例注册一个 Tool，通过动态 Workflow 调用它，然后运行该 Workflow。`LibSQLStore` 会将定义保存在 `mastra.db` 中，以便 Mastra 重启后恢复。

```typescript title="src/dynamic-workflow.ts"
import { Mastra } from '@mastra/core/mastra'
import { createTool } from '@mastra/core/tools'
import { LibSQLStore } from '@mastra/libsql'
import { z } from 'zod'

const greetingTool = createTool({
  id: 'create-greeting',
  description: 'Create a greeting for a name',
  inputSchema: z.object({
    name: z.string(),
  }),
  outputSchema: z.object({
    message: z.string(),
  }),
  execute: async ({ name }) => ({
    message: `Hello, ${name}!`,
  }),
})

const mastra = new Mastra({
  storage: new LibSQLStore({
    id: 'mastra-storage',
    url: 'file:./mastra.db',
  }),
  tools: { 'create-greeting': greetingTool },
})

await mastra.addDynamicWorkflow({
  id: 'greeting-workflow',
  description: 'Create a greeting for the supplied name',
  inputSchema: {
    type: 'object',
    properties: {
      name: { type: 'string' },
    },
    required: ['name'],
  },
  outputSchema: {
    type: 'object',
    properties: {
      message: { type: 'string' },
    },
    required: ['message'],
  },
  graph: [
    {
      type: 'tool',
      id: 'greet',
      toolId: 'create-greeting',
    },
  ],
})

const workflow = mastra.getWorkflow('greeting-workflow')
const run = await workflow.createRun()
const result = await run.start({
  inputData: { name: 'Ada' },
})

if (result.status === 'success') {
  console.log(result.result.message)
}
```

Workflow 输出 `Hello, Ada!`。[`addDynamicWorkflow()`](/reference/core/addDynamicWorkflow) 会先验证定义，再更新存储和运行中的 Workflow 注册表。

定义需要能序列化为 JSON 再读回，因此使用 JSON Schema。`graph` 描述要调用哪些已注册的组件，以及数据如何在组件之间传递。完整的字段和图条目见[动态 Workflow 定义参考](/reference/workflows/dynamic-workflow-definition)。

## 构建和更新定义 {/* #build-and-update-definitions */}

任何能生成 JSON 的系统都能提供定义。例如，API 路由可以接收可视化编辑器创建的定义，并直接注册：

```typescript
const definition = await request.json()
await mastra.addDynamicWorkflow(definition)
```

### 先注册依赖 {/* #register-dependencies-first */}

添加动态 Workflow 前，先在同一个 `Mastra` 实例上注册它引用的组件。Agent 和嵌套 Workflow 使用各自的 ID，Tool 使用它在 `Mastra` 的 `tools` 对象中的键。快速入门示例先用 `create-greeting` 注册 Tool，再用 `toolId` 引用该键。

如果某一步的输出和下一步的输入不匹配，请使用 `mapping` 条目。映射可读取 Workflow 输入、前序步骤的结果、Workflow 状态及请求上下文。支持的映射描述符见[定义参考](/reference/workflows/dynamic-workflow-definition#mapping-steps)。

### 替换 Workflow {/* #replace-a-workflow */}

添加具有相同 `id` 的新定义，即可替换持久化定义及当前注册的 Workflow：

```typescript
await mastra.addDynamicWorkflow(updatedDefinition)
```

新的运行使用更新后的步骤图，已经开始的运行继续使用原来的图。

### 一次添加嵌套 Workflow {/* #add-nested-workflows-together */}

当根 Workflow 引用了尚未注册的辅助 Workflow 时，用 [`addDynamicWorkflows()`](/reference/core/addDynamicWorkflows) 一次添加全部定义：

```typescript
await mastra.addDynamicWorkflows([rootDefinition, helperDefinition])
```

Mastra 会整体验证这组定义，并根据依赖关系确定注册顺序。如果验证失败，一个定义也不会注册。

### 通过 HTTP 管理定义 {/* #manage-definitions-over-http */}

应用无需直接访问 `Mastra` 实例，也能管理动态 Workflow。可使用以下任一接口：

- [Client SDK 的 Workflow API](/reference/client-js/workflows)：从 JavaScript 或 TypeScript 客户端调用 `upsertDynamicWorkflow()`。
- [服务器路由](/reference/server/routes)：将定义发送到 `POST /api/stored/workflows`。

在要求身份验证的服务器上，管理动态 Workflow 需要 `stored-workflows:read` 和 `stored-workflows:write` 权限，运行已注册的 Workflow 需要 `workflows:execute` 权限。

### 持久化定义 {/* #persist-definitions */}

持久化定义使用 `workflowDefinitions` 存储域。Mastra 启动时从存储加载有效定义，并按依赖顺序注册。

即使没有支持此存储域的适配器，`addDynamicWorkflow()` 仍会在内存中注册 Workflow，但进程重启后定义会丢失。适配器支持情况见[存储参考](/reference/storage/overview)。
