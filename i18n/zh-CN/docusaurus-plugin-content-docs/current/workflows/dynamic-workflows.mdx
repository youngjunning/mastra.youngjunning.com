# 动态Workflow程

:::测试版

在 API 稳定之前，可能会在没有重大版本更新的情况下发生重大更改。

:::

动态Workflow是以数据而不是代码表示的Workflow定义。定义是一个 JSON 文档，用于描述Workflow的架构和步骤图。 Mastra 验证定义并将其注册为可运行的Workflow程，然后将其保留在存储中，以便它在流程重新启动后仍然存在。

由于定义不包含 JavaScript 闭包，因此任何生成 JSON 的内容都可以创建Workflow。来源包括 HTTP 客户端或 LLM。可视化编辑器或您自己的Tool也可以生成定义。注册后，动态Workflow将通过与代码定义Workflow相同的执行 API 运行。

## 何时使用动态Workflow程 {/* #when-to-use-dynamic-workflows */}

当用户、Agent、可视化编辑器或外部系统需要创建Workflow而不更改应用程序代码或再次部署时，请使用动态Workflow。

继续定义Workflow程[`createWorkflow()`](/docs/workflows/overview) when the workflow belongs in your application source or needs custom step functions. Dynamic workflows can invoke agents, tools, and workflows that are already registered on the `Mastra` instance.

## 快速入门 {/* #quickstart */}

以下示例注册一个Tool并从动态Workflow中调用它。然后它运行Workflow程。`LibSQLStore` persists the definition in `mastra.db`, so Mastra can restore it after a restart.

```typescript title="src/dynamic-workflow.ts"
import { Mastra } from '@mastra/core/mastra'
import { createTool } from '@mastra/core/tools'
import { LibSQLStore } from '@mastra/libsql'
import { z } from 'zod'

const greetingTool = createTool({
  id: 'create-greeting',
  description: 'Create a greeting for a name',
  inputSchema: z.object({
    name: z.string(),
  }),
  outputSchema: z.object({
    message: z.string(),
  }),
  execute: async ({ name }) => ({
    message: `Hello, ${name}!`,
  }),
})

const mastra = new Mastra({
  storage: new LibSQLStore({
    id: 'mastra-storage',
    url: 'file:./mastra.db',
  }),
  tools: { 'create-greeting': greetingTool },
})

await mastra.addDynamicWorkflow({
  id: 'greeting-workflow',
  description: 'Create a greeting for the supplied name',
  inputSchema: {
    type: 'object',
    properties: {
      name: { type: 'string' },
    },
    required: ['name'],
  },
  outputSchema: {
    type: 'object',
    properties: {
      message: { type: 'string' },
    },
    required: ['message'],
  },
  graph: [
    {
      type: 'tool',
      id: 'greet',
      toolId: 'create-greeting',
    },
  ],
})

const workflow = mastra.getWorkflow('greeting-workflow')
const run = await workflow.createRun()
const result = await run.start({
  inputData: { name: 'Ada' },
})

if (result.status === 'success') {
  console.log(result.result.message)
}
```

Workflow程打印`Hello, Ada!`. Calling [`addDynamicWorkflow()`](/reference/core/addDynamicWorkflow) validates the definition before it changes storage or the live workflow registry.

该定义使用 JSON 架构，因为它必须在 JSON 往返过程中幸存下来。这`graph` describes which registered components to invoke and how data moves between them. See the [dynamic workflow definition reference](/reference/workflows/dynamic-workflow-definition) for every field and graph entry.

## 构建和更新定义 {/* #build-and-update-definitions */}

定义可以来自任何生成 JSON 的源。例如，API 路由可以接受可视化编辑器创建的定义并直接注册：

```typescript
const definition = await request.json()
await mastra.addDynamicWorkflow(definition)
```

### 先注册依赖 {/* #register-dependencies-first */}

在同一组件上注册引用的组件`Mastra` instance before adding the dynamic workflow. Agent and nested workflow entries use their intrinsic IDs. A tool entry uses its key from the `Mastra` `tools` object. The quickstart registers the tool under `create-greeting` before referencing that key with `toolId`.

使用一个`mapping` entry when one step's output doesn't match the next step's input. Mapping entries can read data from the workflow input and previous step results, along with workflow state and request context. The [definition reference](/reference/workflows/dynamic-workflow-definition#mapping-steps) lists the supported mapping descriptors.

### 替换Workflow程 {/* #replace-a-workflow */}

添加具有相同内容的新定义`id` to replace the persisted definition and live registration:

```typescript
await mastra.addDynamicWorkflow(updatedDefinition)
```

新的运行使用更新的图表。已经开始的运行将继续其原始图表。

### 将嵌套Workflow程添加在一起 {/* #add-nested-workflows-together */}

当根Workflow引用尚未注册的帮助程序Workflow时，请添加完整的Workflow集[`addDynamicWorkflows()`](/reference/core/addDynamicWorkflows):

```typescript
await mastra.addDynamicWorkflows([rootDefinition, helperDefinition])
```

Mastra 将捆绑包作为一个单元进行验证，并根据依赖关系确定注册顺序。如果验证失败，则不会注册任何定义。

### 通过 HTTP 管理定义 {/* #manage-definitions-over-http */}

应用程序不需要直接访问`Mastra` instance to manage dynamic workflows. Use one of these interfaces:

* [客户端 SDK Workflow程 API](/reference/client-js/workflows)： 称呼`upsertDynamicWorkflow()` from a JavaScript or TypeScript client.
* [服务器路由](/reference/server/routes)：将定义发送至`POST /api/stored/workflows`.

在经过身份验证的服务器上，动态Workflow管理需要`stored-workflows:read` and `stored-workflows:write` permissions. Running the registered workflow requires `workflows:execute`.

### 保留定义 {/* #persist-definitions */}

存储的定义使用`workflowDefinitions` storage domain. On startup, Mastra loads active definitions from storage and registers them in dependency order.

如果没有支持该域的存储适配器，`addDynamicWorkflow()` still registers the workflow in memory, but the definition is lost when the process restarts. See the [storage reference](/reference/storage/overview) for adapter support.
