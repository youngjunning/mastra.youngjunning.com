# 快照

在 Mastra 中，快照是 Workflow 在某一时刻完整运行状态的可序列化表示。它包含从原暂停点继续运行所需的全部信息，包括：

- 各步骤的当前状态
- 已完成步骤的输出
- Workflow 已走过的执行路径
- 所有暂停的步骤及其元数据
- 各步骤剩余的重试次数
- 恢复运行所需的其他上下文数据

每当 Workflow 暂停，Mastra 都会自动创建和管理快照，并将其持久化到配置的存储系统。

## 快照在暂停和恢复中的作用 {/* #the-role-of-snapshots-in-suspend-and-resume */}

快照是 Mastra 实现暂停和恢复的关键。当 Workflow 步骤调用 `await suspend()` 时：

1. Workflow 在调用处暂停。
1. 系统将 Workflow 的当前状态记录为快照。
1. 系统将快照持久化到存储系统。
1. 该步骤的状态标记为 `'suspended'`（已暂停）。
1. 稍后在暂停的步骤上调用 `resume()` 时，系统读取快照。
1. Workflow 从原暂停点继续运行。

你可以借助这一机制实现人工参与的 Workflow，处理限流、等待外部资源，或构建可能需要长时间暂停的复杂分支 Workflow。

## 快照包含哪些内容 {/* #snapshot-anatomy */}

每个快照都包含 `runId`、输入、步骤状态（`success`、`suspended` 等）、暂停和恢复时传入的数据（如有），以及最终输出。恢复运行时便可取得完整的上下文。

## 保存和读取快照 {/* #how-snapshots-are-saved-and-retrieved */}

快照保存在配置的存储系统中。默认使用 libSQL，也可改用 Upstash、PostgreSQL 或 OracleDB。每份快照都保存在 `workflow_snapshots` 表中，由 Workflow 的 `runId` 标识。

### 保存快照 {/* #saving-snapshots */}

Workflow 暂停时，Mastra 会按以下流程自动保存快照：

1. 步骤执行期间调用 `suspend()` 函数，触发快照流程。
1. `WorkflowInstance.suspend()` 方法记录已暂停的状态机。
1. 系统调用 `persistWorkflowSnapshot()` 保存当前状态。
1. 系统将快照序列化，存入所配置数据库的 `workflow_snapshots` 表。
1. 存储记录包含 Workflow 名称、运行 ID 和序列化后的快照。

### 读取快照 {/* #retrieving-snapshots */}

Workflow 恢复时，Mastra 会按以下流程读取已保存的快照：

1. 调用 `resume()` 方法并传入指定的步骤 ID。
1. 使用 `loadWorkflowSnapshot()` 从存储中加载快照。
1. 解析快照，为恢复运行做好准备。
1. 根据快照中的状态重建 Workflow 的运行。
1. 恢复暂停的步骤，继续运行。

```typescript
const storage = mastra.getStorage()
const workflowStore = await storage?.getStore('workflows')

const snapshot = await workflowStore?.loadWorkflowSnapshot({
  runId: '<run-id>',
  workflowName: '<workflow-id>',
})

console.log(snapshot)
```

## 快照的存储选项 {/* #storage-options-for-snapshots */}

快照通过 `Mastra` 类上配置的 `storage` 实例持久化。注册到同一 Mastra 实例的所有 Workflow 共用这一存储层。Mastra 支持多种存储选项，以适应不同环境。

```typescript title="src/mastra/index.ts"
import { Mastra } from '@mastra/core'
import { LibSQLStore } from '@mastra/libsql'
import { approvalWorkflow } from './workflows'

export const mastra = new Mastra({
  storage: new LibSQLStore({
    id: 'mastra-storage',
    url: ':memory:',
  }),
  workflows: { approvalWorkflow },
})
```

## 最佳实践 {/* #best-practices */}

1. **确保数据可序列化**：快照中的所有数据都必须能序列化，即可转换为 JSON。
1. **控制快照大小**：避免在 Workflow 上下文中直接存储大型数据对象。只保存引用（例如 ID），在需要时再读取数据。
1. **仔细选择恢复时的上下文**：恢复 Workflow 时，请谨慎选择要提供的上下文；它会与现有快照数据合并。
1. **设置监控**：监控已暂停的 Workflow，尤其是长时间运行的 Workflow，确保它们能够正常恢复。
1. **考虑存储扩展**：如果应用中有大量暂停的 Workflow，请确保存储方案的容量能满足需求。

## 自定义快照元数据 {/* #custom-snapshot-metadata */}

通过定义 `suspendSchema`，可以在暂停 Workflow 时附加自定义元数据。这些数据会保存在快照中，恢复 Workflow 时可供使用。

```typescript {30-34} title="src/mastra/workflows/test-workflow.ts"
import { createWorkflow, createStep } from '@mastra/core/workflows'
import { z } from 'zod'

const approvalStep = createStep({
  id: 'approval-step',
  description: 'Accepts a value, waits for confirmation',
  inputSchema: z.object({
    value: z.number(),
    user: z.string(),
    requiredApprovers: z.array(z.string()),
  }),
  suspendSchema: z.object({
    message: z.string(),
    requestedBy: z.string(),
    approvers: z.array(z.string()),
  }),
  resumeSchema: z.object({
    confirm: z.boolean(),
    approver: z.string(),
  }),
  outputSchema: z.object({
    value: z.number(),
    approved: z.boolean(),
  }),
  execute: async ({ inputData, resumeData, suspend }) => {
    const { value, user, requiredApprovers } = inputData
    const { confirm } = resumeData ?? {}

    if (!confirm) {
      return await suspend({
        message: 'Workflow suspended',
        requestedBy: user,
        approvers: [...requiredApprovers],
      })
    }

    return {
      value,
      approved: confirm,
    }
  },
})
```

### 提供恢复数据 {/* #providing-resume-data */}

恢复暂停的步骤时，用 `resumeData` 传入结构化输入。该数据必须符合步骤的 `resumeSchema`。

```typescript {14-20}
const workflow = mastra.getWorkflow('approvalWorkflow')

const run = await workflow.createRun()

const result = await run.start({
  inputData: {
    value: 100,
    user: 'Michael',
    requiredApprovers: ['manager', 'finance'],
  },
})

if (result.status === 'suspended') {
  const resumedResult = await run.resume({
    step: 'approval-step',
    resumeData: {
      confirm: true,
      approver: 'manager',
    },
  })
}
```
