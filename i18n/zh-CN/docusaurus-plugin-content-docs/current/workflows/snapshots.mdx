# 快照

在 Mastra 中，快照是Workflow在特定时间点的完整执行状态的可序列化表示。快照捕获从中断位置恢复Workflow程所需的所有信息，包括：

* Workflow程中每个步骤的当前状态
* 已完成步骤的输出
* Workflow程的执行路径
* 任何暂停的步骤及其元数据
* 每个步骤的剩余重试次数
* 恢复执行所需的附加上下文数据

每当Workflow程暂停时，Mastra 都会自动创建和管理快照，并将其保留到配置的存储系统中。

## 快照在挂起和恢复中的作用 {/* #the-role-of-snapshots-in-suspend-and-resume */}

快照是实现 Mastra 暂停和恢复功能的关键机制。当Workflow程步骤调用时`await suspend()`:

1. Workflow执行在该确切点暂停
2. Workflow程的当前状态被捕获为快照
3. 快照持久化到存储
4. Workflow步骤被标记为“已暂停”，状态为`'suspended'`
5. 后来，当`resume()` is called on the suspended step, the snapshot is retrieved
6. Workflow执行从停止的地方继续执行

该机制提供了一种强大的方法来实现人机交互Workflow程、处理速率限制、等待外部资源以及实现可能需要长时间暂停的复杂分支Workflow程。

## 快照解剖 {/* #snapshot-anatomy */}

每个快照包括`runId`, input, step status (`success`, `suspended`, etc.), any suspend and resume payloads, and the final output. As a result, full context is available when resuming execution.

## 如何保存和检索快照 {/* #how-snapshots-are-saved-and-retrieved */}

快照保存到配置的存储系统中。默认情况下，它们使用 libSQL，但您可以配置 Upstash、PostgreSQL 或 OracleDB。每个快照都保存在`workflow_snapshots` table and identified by the workflow's `runId`.

### 保存快照 {/* #saving-snapshots */}

当Workflow程暂停时，Mastra 通过以下步骤自动保留Workflow程快照：

1. 这`suspend()` function in a step execution triggers the snapshot process
2. 这`WorkflowInstance.suspend()` method records the suspended machine
3. `persistWorkflowSnapshot()`被调用来保存当前状态
4. 快照被序列化并存储在配置的数据库中`workflow_snapshots` table
5. 存储记录包括Workflow名称、运行 ID 和序列化快照

### 检索快照 {/* #retrieving-snapshots */}

当Workflow程恢复时，Mastra 通过以下步骤检索持久快照：

1. 这`resume()` method is called with a specific step ID
2. 快照是使用以下方式从存储加载的`loadWorkflowSnapshot()`
3. 快照已解析并准备恢复
4. 使用快照状态重新创建Workflow执行
5. 暂停的步骤恢复，继续执行

```typescript
const storage = mastra.getStorage()
const workflowStore = await storage?.getStore('workflows')

const snapshot = await workflowStore?.loadWorkflowSnapshot({
  runId: '<run-id>',
  workflowName: '<workflow-id>',
})

console.log(snapshot)
```

## 快照的存储选项 {/* #storage-options-for-snapshots */}

快照是使用`storage` instance configured on the `Mastra` class. This storage layer is shared across all workflows registered to that instance. Mastra supports multiple storage options for flexibility in different environments.

```typescript title="src/mastra/index.ts"
import { Mastra } from '@mastra/core'
import { LibSQLStore } from '@mastra/libsql'
import { approvalWorkflow } from './workflows'

export const mastra = new Mastra({
  storage: new LibSQLStore({
    id: 'mastra-storage',
    url: ':memory:',
  }),
  workflows: { approvalWorkflow },
})
```

## 最佳实践 {/* #best-practices */}

1. **确保可串行性**：任何需要包含在快照中的数据都必须是可序列化的（可转换为 JSON）。
2. **最小化快照大小**：避免将大型数据对象直接存储在Workflow上下文中。相反，存储对它们的引用（如 ID）并在需要时检索数据。
3. **小心处理简历上下文**：恢复Workflow程时，请仔细考虑要提供的上下文。这将与现有快照数据合并。
4. **设置适当的监控**：对暂停的Workflow程（尤其是长时间运行的Workflow程）实施监控，并确保它们正确恢复。
5. **考虑存储扩展**：对于具有许多暂停Workflow程的应用程序，请确保您的存储解决方案已适当扩展。

## 自定义快照元数据 {/* #custom-snapshot-metadata */}

您可以在暂停Workflow程时附加自定义元数据，方法是定义`suspendSchema`. This metadata is stored in the snapshot and made available when the workflow is resumed.

```typescript {30-34} title="src/mastra/workflows/test-workflow.ts"
import { createWorkflow, createStep } from '@mastra/core/workflows'
import { z } from 'zod'

const approvalStep = createStep({
  id: 'approval-step',
  description: 'Accepts a value, waits for confirmation',
  inputSchema: z.object({
    value: z.number(),
    user: z.string(),
    requiredApprovers: z.array(z.string()),
  }),
  suspendSchema: z.object({
    message: z.string(),
    requestedBy: z.string(),
    approvers: z.array(z.string()),
  }),
  resumeSchema: z.object({
    confirm: z.boolean(),
    approver: z.string(),
  }),
  outputSchema: z.object({
    value: z.number(),
    approved: z.boolean(),
  }),
  execute: async ({ inputData, resumeData, suspend }) => {
    const { value, user, requiredApprovers } = inputData
    const { confirm } = resumeData ?? {}

    if (!confirm) {
      return await suspend({
        message: 'Workflow suspended',
        requestedBy: user,
        approvers: [...requiredApprovers],
      })
    }

    return {
      value,
      approved: confirm,
    }
  },
})
```

### 提供简历数据 {/* #providing-resume-data */}

使用`resumeData` to pass structured input when resuming a suspended step. It must match the step’s `resumeSchema`.

```typescript {14-20}
const workflow = mastra.getWorkflow('approvalWorkflow')

const run = await workflow.createRun()

const result = await run.start({
  inputData: {
    value: 100,
    user: 'Michael',
    requiredApprovers: ['manager', 'finance'],
  },
})

if (result.status === 'suspended') {
  const resumedResult = await run.resume({
    step: 'approval-step',
    resumeData: {
      confirm: true,
      approver: 'manager',
    },
  })
}
```
