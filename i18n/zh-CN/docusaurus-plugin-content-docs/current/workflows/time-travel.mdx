# 时间回溯

借助时间回溯，可以使用已保存的快照或自行提供的上下文，从任意指定步骤重新执行 Workflow。

可以用它调试失败的 Workflow、用不同输入测试单个步骤，或直接从出错处恢复，免去重跑整个 Workflow。对于尚未执行过的 Workflow，也可以从任意指定步骤开始执行。

## 时间回溯的工作原理 {/* #how-time-travel-works */}

对一次 Workflow 运行调用 `timeTravel()` 时：

1. 如果存储中有快照，Workflow 会将其加载。
1. 根据快照或提供的上下文重建目标步骤之前的结果。
1. 使用提供或重建的输入数据，从指定步骤开始执行。
1. Workflow 从该步骤继续执行直至完成。

如果记录运行后 Workflow 定义有变（例如步骤改名），或该次运行未到达目标之前的某一步，时间回溯会在执行任何步骤前失败并给出具体错误，已保存的快照不会改变。

时间回溯依赖持久化的 Workflow 快照，因此必须配置存储。

## 基本用法 {/* #basic-usage */}

使用 `run.timeTravel()` 从指定步骤重新执行 Workflow：

```typescript
import { mastra } from './mastra'

const workflow = mastra.getWorkflow('myWorkflow')
const run = await workflow.createRun()

const result = await run.timeTravel({
  step: 'step2',
  inputData: { previousStepResult: 'custom value' },
})
```

## 指定目标步骤 {/* #specifying-the-target-step */}

您可以使用步骤引用或步骤 ID 指定目标步骤：

### 使用步骤参考 {/* #using-step-reference */}

```typescript
const result = await run.timeTravel({
  step: step2,
  inputData: { value: 10 },
})
```

### 使用步骤 ID {/* #using-step-id */}

```typescript
const result = await run.timeTravel({
  step: 'step2',
  inputData: { value: 10 },
})
```

### 嵌套 Workflow 中的步骤 {/* #nested-workflow-steps */}

对于嵌套 Workflow 中的步骤，可使用点号表示法、步骤 ID 数组或步骤引用数组：

```typescript
// Using dot notation
const result = await run.timeTravel({
  step: 'nestedWorkflow.step3',
  inputData: { value: 10 },
})

// Using array of step IDs
const result = await run.timeTravel({
  step: ['nestedWorkflow', 'step3'],
  inputData: { value: 10 },
})

// Using array of step references
const result = await run.timeTravel({
  step: [nestedWorkflow, step3],
  inputData: { value: 10 },
})
```

## 提供执行上下文 {/* #providing-execution-context */}

执行时间回溯时，可以提供上下文来指定先前步骤的状态：

```typescript {3-13}
const result = await run.timeTravel({
  step: 'step2',
  context: {
    step1: {
      status: 'success',
      payload: { value: 0 },
      output: { step1Result: 2 },
      startedAt: Date.now(),
      endedAt: Date.now(),
    },
  },
})
```

上下文对象以步骤 ID 为键存储结果。每个步骤结果包含：

- `status`：步骤的执行状态。常见值为 `success`、`failed` 或 `suspended`，也接受任何 Workflow 运行状态：`running`、`success`、`failed`、`tripwire`、`suspended`、`waiting`、`pending`、`canceled`、`bailed`、`paused` 或 `skipped`。
- `payload`：传递到步骤的输入数据
- `output`：步骤的输出数据（对于成功的步骤）
- `startedAt`：步骤开始时的时间戳
- `endedAt`：步骤结束时的时间戳（对于已完成的步骤）
- `suspendPayload`：传给 `suspend()` 的数据，适用于已挂起的步骤。
- `resumePayload`：传给 `resume()` 的数据，适用于已恢复的步骤。

## 重新执行失败的 Workflow {/* #re-running-failed-workflows */}

时间回溯尤其适合调试执行失败的 Workflow，或从失败中恢复：

```typescript
const workflow = mastra.getWorkflow('myWorkflow')
const run = await workflow.createRun()

// Initial run fails at step2
const failedResult = await run.start({
  inputData: { value: 1 },
})

if (failedResult.status === 'failed') {
  // Re-run from step2 with corrected input
  const recoveredResult = await run.timeTravel({
    step: 'step2',
    inputData: { step1Result: 5 }, // Provide corrected input
  })
}
```

## 回溯已挂起的 Workflow {/* #time-travel-with-suspended-workflows */}

时间回溯可以让已挂起的 Workflow 从更早的步骤恢复执行：

```typescript
const run = await workflow.createRun()

// Start workflow - suspends at promptAgent step
const initialResult = await run.start({
  inputData: { input: 'test' },
})

if (initialResult.status === 'suspended') {
  // Time travel back to an earlier step with resume data
  const result = await run.timeTravel({
    step: 'getUserInput',
    resumeData: {
      userInput: 'corrected input',
    },
  })
}
```

## 流式接收回溯结果 {/* #streaming-time-travel-results */}

使用 `timeTravelStream()` 接收回溯执行过程中的流式事件：

```typescript
const run = await workflow.createRun()

const stream = run.timeTravelStream({
  step: 'step2',
  inputData: { value: 10 },
})

for await (const event of stream.fullStream) {
  console.log(event.type, event.payload)
}

const result = await stream.result

if (result.status === 'success') {
  console.log(result.result)
}
```

## 为时间回溯提供初始状态 {/* #time-travel-with-initial-state */}

执行时间回溯时，可以提供初始状态来设置 Workflow 级别的状态：

```typescript
const result = await run.timeTravel({
  step: 'step2',
  inputData: { value: 10 },
  initialState: {
    counter: 5,
    metadata: { source: 'time-travel' },
  },
})
```

## 错误处理 {/* #error-handling */}

时间回溯在特定情况下会抛出错误。执行前，它会以原子操作取得该次运行的执行权，确保同一时间只有一个调用可以继续。并发调用会抛出 `WORKFLOW_TIME_TRAVEL_ALREADY_CLAIMED`，如果该次运行已在执行，则抛出 `WORKFLOW_TIME_TRAVEL_RUN_RUNNING`。参见[并发回溯调用](/reference/workflows/run-methods/timeTravel#concurrent-time-travel-calls)。

### Workflow 正在执行 {/* #running-workflow */}

无法对正在执行的 Workflow 进行时间回溯：

```typescript
try {
  await run.timeTravel({ step: 'step2' })
} catch (error) {
  // "This workflow run is still running, cannot time travel"
}
```

### 步骤 ID 无效 {/* #invalid-step-id */}

如果当前 Workflow 定义中不存在目标步骤，则时间旅行会抛出异常：

```typescript
try {
  await run.timeTravel({ step: 'nonExistentStep' })
} catch (error) {
  // "Cannot time travel to step 'nonExistentStep': the step does not exist in the current execution graph. ..."
}
```

错误还会列出运行快照中记录的最多 10 个步骤 ID（如有更多，则注明其余 ID 的数量），并确认已保存的快照未被修改。如果没有记录任何步骤结果，则会显示 `Time travel target step not found in execution graph: 'nonExistentStep'. Verify the step id/path.`。

### 输入数据无效 {/* #invalid-input-data */}

启用 `validateInputs` 后，时间回溯会按步骤的 schema 验证输入数据：

```typescript
try {
  await run.timeTravel({
    step: 'step2',
    inputData: { invalidField: 'value' },
  })
} catch (error) {
  // "Invalid inputData: \n- step1Result: Required"
}
```

## 嵌套 Workflow 的上下文 {/* #nested-workflows-context */}

回溯到嵌套 Workflow 内部的步骤时，可以同时为父 Workflow 和嵌套 Workflow 的步骤提供上下文：

```typescript
const result = await run.timeTravel({
  step: 'nestedWorkflow.step3',
  context: {
    step1: {
      status: 'success',
      payload: { value: 0 },
      output: { step1Result: 2 },
      startedAt: Date.now(),
      endedAt: Date.now(),
    },
    nestedWorkflow: {
      status: 'running',
      payload: { step1Result: 2 },
      startedAt: Date.now(),
    },
  },
  nestedStepsContext: {
    nestedWorkflow: {
      step2: {
        status: 'success',
        payload: { step1Result: 2 },
        output: { step2Result: 3 },
        startedAt: Date.now(),
        endedAt: Date.now(),
      },
    },
  },
})
```

## 使用案例 {/* #use-cases */}

### 调试失败的步骤 {/* #debugging-failed-steps */}

使用相同或修改后的输入重新运行失败的步骤以诊断问题：

```typescript
const result = await run.timeTravel({
  step: failedStepId,
  context: originalContext, // Use context from the failed run
})
```

### 在新的 Workflow 运行中测试步骤逻辑 {/* #testing-step-logic-on-new-workflow-run */}

用指定输入在一次新的 Workflow 运行中单独测试步骤逻辑，无需从头执行 Workflow。

```typescript
const result = await run.timeTravel({
  step: 'processData',
  inputData: { testData: 'specific test case' },
})
```

### 从暂时性故障中恢复 {/* #recovering-from-transient-failures */}

重新运行由于临时问题（网络错误、速率限制）而失败的步骤：

```typescript
// After fixing the external service issue
const result = await run.timeTravel({
  step: 'callExternalApi',
  inputData: savedInputData,
})
```
