# 时间旅行

时间旅行允许您使用存储的快照数据或您提供的自定义上下文从任何特定步骤开始重新执行Workflow程。

这对于调试失败的Workflow程或使用不同的输入测试各个步骤，或者从错误中恢复而不重新运行整个Workflow程非常有用。您还可以使用时间旅行从任何特定步骤开始执行尚未运行的Workflow程。

## 时间旅行如何运作 {/* #how-time-travel-works */}

当你打电话时`timeTravel()` on a workflow run:

1. Workflow程从存储加载现有快照（如果可用）
2. 目标步骤之前的步骤结果是根据快照或提供的上下文重建的
3. 使用提供的或重构的输入数据从指定步骤开始执行
4. Workflow程从那时起继续完成

如果自记录运行以来Workflow定义已更改（例如，重命名了步骤），或者记录的运行从未到达目标之前的步骤，则时间旅行会在执行任何操作之前失败并出现描述性错误，并且存储的快照保持不变。

时间旅行需要配置存储，因为它依赖于持久的Workflow快照。

## 基本用法 {/* #basic-usage */}

使用`run.timeTravel()` to re-execute a workflow from a specific step:

```typescript
import { mastra } from './mastra'

const workflow = mastra.getWorkflow('myWorkflow')
const run = await workflow.createRun()

const result = await run.timeTravel({
  step: 'step2',
  inputData: { previousStepResult: 'custom value' },
})
```

## 指定目标步骤 {/* #specifying-the-target-step */}

您可以使用步骤引用或步骤 ID 指定目标步骤：

### 使用步骤参考 {/* #using-step-reference */}

```typescript
const result = await run.timeTravel({
  step: step2,
  inputData: { value: 10 },
})
```

### 使用步骤 ID {/* #using-step-id */}

```typescript
const result = await run.timeTravel({
  step: 'step2',
  inputData: { value: 10 },
})
```

### 嵌套Workflow程步骤 {/* #nested-workflow-steps */}

对于嵌套Workflow程内的步骤，请使用点表示法、步骤 IDS 数组或步骤引用数组：

```typescript
// Using dot notation
const result = await run.timeTravel({
  step: 'nestedWorkflow.step3',
  inputData: { value: 10 },
})

// Using array of step IDs
const result = await run.timeTravel({
  step: ['nestedWorkflow', 'step3'],
  inputData: { value: 10 },
})

// Using array of step references
const result = await run.timeTravel({
  step: [nestedWorkflow, step3],
  inputData: { value: 10 },
})
```

## 提供执行上下文 {/* #providing-execution-context */}

您可以提供上下文来指定时间旅行时先前步骤的状态：

```typescript {3-13}
const result = await run.timeTravel({
  step: 'step2',
  context: {
    step1: {
      status: 'success',
      payload: { value: 0 },
      output: { step1Result: 2 },
      startedAt: Date.now(),
      endedAt: Date.now(),
    },
  },
})
```

上下文对象包含由步骤 ID 键入的步骤结果。每一步结果包括：

* `status`：步骤的执行状态。常见`success`, `failed`, or `suspended`, but any workflow run status is accepted: `running`, `success`, `failed`, `tripwire`, `suspended`, `waiting`, `pending`, `canceled`, `bailed`, `paused`， 或者`skipped`
* `payload`：传递到步骤的输入数据
* `output`：步骤的输出数据（对于成功的步骤）
* `startedAt`：步骤开始时的时间戳
* `endedAt`：步骤结束时的时间戳（对于已完成的步骤）
* `suspendPayload`：数据传递到`suspend()` (for suspended steps)
* `resumePayload`：数据传递到`resume()` (for resumed steps)

## 重新运行失败的Workflow程 {/* #re-running-failed-workflows */}

时间旅行对于调试和从失败的Workflow执行中恢复特别有用：

```typescript
const workflow = mastra.getWorkflow('myWorkflow')
const run = await workflow.createRun()

// Initial run fails at step2
const failedResult = await run.start({
  inputData: { value: 1 },
})

if (failedResult.status === 'failed') {
  // Re-run from step2 with corrected input
  const recoveredResult = await run.timeTravel({
    step: 'step2',
    inputData: { step1Result: 5 }, // Provide corrected input
  })
}
```

## 暂停Workflow程的时间旅行 {/* #time-travel-with-suspended-workflows */}

您可以通过时间旅行来恢复先前步骤中暂停的Workflow程：

```typescript
const run = await workflow.createRun()

// Start workflow - suspends at promptAgent step
const initialResult = await run.start({
  inputData: { input: 'test' },
})

if (initialResult.status === 'suspended') {
  // Time travel back to an earlier step with resume data
  const result = await run.timeTravel({
    step: 'getUserInput',
    resumeData: {
      userInput: 'corrected input',
    },
  })
}
```

## 流式传输时间旅行结果 {/* #streaming-time-travel-results */}

使用`timeTravelStream()` to receive streaming events during time travel execution:

```typescript
const run = await workflow.createRun()

const stream = run.timeTravelStream({
  step: 'step2',
  inputData: { value: 10 },
})

for await (const event of stream.fullStream) {
  console.log(event.type, event.payload)
}

const result = await stream.result

if (result.status === 'success') {
  console.log(result.result)
}
```

## 初始状态的时间旅行 {/* #time-travel-with-initial-state */}

您可以在时间旅行时提供初始状态来设置Workflow级别状态：

```typescript
const result = await run.timeTravel({
  step: 'step2',
  inputData: { value: 10 },
  initialState: {
    counter: 5,
    metadata: { source: 'time-travel' },
  },
})
```

## 错误处理 {/* #error-handling */}

时间旅行在特定情况下会引发错误。在运行任何内容之前，时间旅行会自动声明运行，因此一次仅进行一个调用。并发调用抛出异常`WORKFLOW_TIME_TRAVEL_ALREADY_CLAIMED`, or `WORKFLOW_TIME_TRAVEL_RUN_RUNNING` if the run is already executing. See [Concurrent time travel calls](/reference/workflows/run-methods/timeTravel#concurrent-time-travel-calls).

### 运行Workflow程 {/* #running-workflow */}

您无法时间旅行到当前正在运行的Workflow程：

```typescript
try {
  await run.timeTravel({ step: 'step2' })
} catch (error) {
  // "This workflow run is still running, cannot time travel"
}
```

### 步骤 ID 无效 {/* #invalid-step-id */}

如果当前Workflow定义中不存在目标步骤，则时间旅行会抛出异常：

```typescript
try {
  await run.timeTravel({ step: 'nonExistentStep' })
} catch (error) {
  // "Cannot time travel to step 'nonExistentStep': the step does not exist in the current execution graph. ..."
}
```

该错误还列出了运行快照中记录的最多 10 个步骤 ID（以及所有剩余 ID 的计数），并确认存储的快照未被修改。如果运行没有记录步骤结果，则会显示错误`Time travel target step not found in execution graph: 'nonExistentStep'. Verify the step id/path.` instead.

### 输入数据无效 {/* #invalid-input-data */}

什么时候`validateInputs` is enabled, time travel validates the input data against the step's schema:

```typescript
try {
  await run.timeTravel({
    step: 'step2',
    inputData: { invalidField: 'value' },
  })
} catch (error) {
  // "Invalid inputData: \n- step1Result: Required"
}
```

## 嵌套Workflow上下文 {/* #nested-workflows-context */}

当时间进入嵌套Workflow程时，您可以为父Workflow程步骤和嵌套Workflow程步骤提供上下文：

```typescript
const result = await run.timeTravel({
  step: 'nestedWorkflow.step3',
  context: {
    step1: {
      status: 'success',
      payload: { value: 0 },
      output: { step1Result: 2 },
      startedAt: Date.now(),
      endedAt: Date.now(),
    },
    nestedWorkflow: {
      status: 'running',
      payload: { step1Result: 2 },
      startedAt: Date.now(),
    },
  },
  nestedStepsContext: {
    nestedWorkflow: {
      step2: {
        status: 'success',
        payload: { step1Result: 2 },
        output: { step2Result: 3 },
        startedAt: Date.now(),
        endedAt: Date.now(),
      },
    },
  },
})
```

## 使用案例 {/* #use-cases */}

### 调试失败的步骤 {/* #debugging-failed-steps */}

使用相同或修改后的输入重新运行失败的步骤以诊断问题：

```typescript
const result = await run.timeTravel({
  step: failedStepId,
  context: originalContext, // Use context from the failed run
})
```

### 在新Workflow程运行中测试步骤逻辑 {/* #testing-step-logic-on-new-workflow-run */}

在新的Workflow运行中使用特定输入测试各个步骤，这对于测试步骤逻辑而无需从头开始Workflow执行非常有用。

```typescript
const result = await run.timeTravel({
  step: 'processData',
  inputData: { testData: 'specific test case' },
})
```

### 从暂时性故障中恢复 {/* #recovering-from-transient-failures */}

重新运行由于临时问题（网络错误、速率限制）而失败的步骤：

```typescript
// After fixing the external service issue
const result = await run.timeTravel({
  step: 'callExternalApi',
  inputData: savedInputData,
})
```
