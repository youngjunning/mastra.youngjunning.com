# 流式传输

Mastra 的 Agent 和 Workflow 支持实时返回增量响应，用户可以边生成边查看输出，无须等到执行完成。这适用于聊天、长篇内容、多步骤 Workflow，以及其他需要即时反馈的场景。

## 快速入门 {/* #getting-started */}

[`Agent.stream()`](/reference/streaming/agents/stream) 是 Agent 的标准流式传输 API。它返回一个 `MastraModelOutput`，其中的 `textStream` 用于逐步读取文本，`text`、`steps` 和 `usage` 等 Promise 会在流结束时兑现。

## Agent 流式传输 {/* #streaming-with-agents */}

对于简单的提示词，传入一个字符串即可。要提供多段上下文，请使用字符串数组。要精确控制消息角色和对话流程，请使用消息对象数组，其中每个对象包含 `role` 和 `content`。

### 使用 `Agent.stream()` {/* #using-agentstream */}

`textStream` 会在生成响应时将其拆分成文本块，逐块发送。使用 `for await` 循环遍历 `textStream`，即可查看各个数据块。

```typescript
const testAgent = mastra.getAgent('testAgent')

const stream = await testAgent.stream([{ role: 'user', content: 'Help me organize my day' }])

for await (const chunk of stream.textStream) {
  process.stdout.write(chunk)
}
```

详情请参阅 [Agent.stream()](/reference/streaming/agents/stream)。

:::tip

对于会派发[后台任务](/docs/harness/background-tasks)的 Agent，请在调用 `stream()` 时使用 [`untilIdle` 选项](/reference/streaming/agents/stream#parameters)，例如 `untilIdle: true`。这样，流会一直保持开启，直到这些任务完成且 Agent 有机会响应任务结果。此选项要求 Agent 启用 Memory。

:::

### `Agent.stream()` 的输出 {/* #output-from-agentstream */}

Agent 生成的响应会以流的形式输出。

```text
Of course!
To help you organize your day effectively, I need a bit more information.
Here are some questions to consider:
...
```

### Agent 流的属性 {/* #agent-stream-properties */}

Agent 流提供以下响应属性：

- **`stream.textStream`**：发出文本块的可读流。
- **`stream.text`**：兑现时提供完整文本响应的 Promise。
- **`stream.steps`**：兑现时提供已完成模型步骤的 Promise。
- **`stream.finishReason`**：兑现时提供 Agent 停止流式传输原因的 Promise。
- **`stream.usage`**：兑现时提供 token 用量信息的 Promise。
- **`stream.objectStream`** 和 **`stream.object`**：传入 `structuredOutput` 时，分别提供部分和最终的结构化输出。

完整属性列表请参阅 [`MastraModelOutput` 参考](/reference/streaming/agents/MastraModelOutput)。

### 集成 AI SDK {/* #ai-sdk-integration */}

使用 `toAISdkStream()` 和 `toAISdkMessages()` 将 Mastra 流及已保存的消息转换为 AI SDK 兼容格式。为保持向后兼容，转换函数默认使用 AI SDK v5。请传入与已安装的 AI SDK 一致的版本，例如 AI SDK v7 对应 `version: 'v7'`。

```typescript
import { toAISdkStream } from '@mastra/ai-sdk'

const testAgent = mastra.getAgent('testAgent')
const stream = await testAgent.stream([{ role: 'user', content: 'Help me organize my day' }])

const aiSDKStream = toAISdkStream(stream, {
  from: 'agent',
  version: 'v7',
})
```

使用 `toAISdkMessages()` 转换已保存的消息，供 `useChat()` 的 `initialMessages` 使用：

```typescript
import { toAISdkMessages } from '@mastra/ai-sdk/ui'

const initialMessages = toAISdkMessages([{ role: 'user', content: 'Hello' }], { version: 'v7' })
```

有关路由处理函数，请参阅 [AI SDK UI](/integrations/agentic-ui/ai-sdk-ui)，其中介绍了 `handleChatStream()`、`handleWorkflowStream()` 和 `handleNetworkStream()`。调用这些函数时，也请传入与已安装的 AI SDK 一致的版本。有关全部选项，请参阅 [`toAISdkStream()`](/reference/ai-sdk/to-ai-sdk-stream) 和 [`toAISdkMessages()`](/reference/ai-sdk/to-ai-sdk-messages) 的参考文档。

## Workflow 流式传输 {/* #streaming-with-workflows */}

Workflow 返回的是一系列描述运行生命周期的结构化事件，而非逐步生成的文本块。通过 `.createRun()` 创建一次运行后，即可根据这些事件实时跟踪并响应 Workflow 的进度。

### 使用 `Run.stream()` {/* #using-runstream */}

`stream()` 方法返回 `WorkflowRunOutput`。它的 `fullStream` 属性是承载 Workflow 事件的 `ReadableStream`。

```typescript
const run = await testWorkflow.createRun()

const stream = run.stream({
  inputData: {
    value: 'initial data',
  },
})

for await (const chunk of stream.fullStream) {
  console.log(chunk)
}
```

详情请参阅 [Run.stream()](/reference/streaming/workflows/stream)。

### `Run.stream()` 的输出 {/* #output-from-runstream */}

事件的顶层包含 `runId` 和 `from`，无须检查载荷即可识别对应的 Workflow 运行。

```typescript oxfmt:false
{
  type: 'workflow-start',
  runId: '1eeaf01a-d2bf-4e3f-8d1b-027795ccd3df',
  from: 'WORKFLOW',
  payload: {
    workflowId: 'testWorkflow'
  }
}
```

### Workflow 流的属性 {/* #workflow-stream-properties */}

Workflow 流提供以下响应属性：

- **`stream.status`**：Workflow 运行的状态。
- **`stream.result`**：Workflow 运行的结果。
- **`stream.usage`**：Workflow 本次运行的总 token 用量。

通过 Agent 或 Workflow 的流，可以实时查看大语言模型的输出或 Workflow 的运行状态。你可以直接把反馈传给用户，也可以在应用中随 Workflow 状态变化更新显示。

Agent 或 Workflow 发出的事件对应生成和执行的不同阶段，例如开始运行、生成文本或调用 Tool。

## 事件类型 {/* #event-types */}

Agent 流和 Workflow 流会在执行期间发出不同类型的事件。

### Agent 事件 {/* #agent-events */}

常见的 Agent 事件包括：

- **`start`**：Agent 开始运行。
- **`text-start`**、**`text-delta`** 和 **`text-end`**：开始和结束事件标记文本生成的边界，增量事件携带新增文本。
- **`reasoning-start`**、**`reasoning-delta`** 和 **`reasoning-end`**：开始和结束事件标记推理内容生成的边界，增量事件携带新增的推理内容。
- **`tool-call`** 和 **`tool-result`**：调用 Tool 并返回结果。
- **`step-start`** 和 **`step-finish`**：模型步骤开始和结束。
- **`finish`**：Agent 完成运行。

此处仅列出常见事件。有关所有 Agent 数据块类型及其载荷，请参阅 [`ChunkType` 参考](/reference/streaming/ChunkType)。

### Workflow 事件 {/* #workflow-events */}

Workflow 事件包括：

- **`workflow-start`**：Workflow 开始运行。
- **`workflow-step-start`**：Workflow 的一个步骤开始。
- **`workflow-step-output`**：步骤发出自定义输出。
- **`workflow-step-progress`**：步骤报告进度。
- **`workflow-step-result`**：步骤完成并返回结果。
- **`workflow-finish`**：Workflow 完成运行。
- **`workflow-paused`**、**`workflow-step-suspended`** 和 **`workflow-canceled`**：Workflow 运行中断。

有关 Workflow 事件的详细说明，请参阅 [`Run.stream()` 参考](/reference/streaming/workflows/stream)。

## 查看 Agent 流 {/* #inspecting-agent-streams */}

用 `for await` 循环遍历 `stream.fullStream`，即可查看发出的所有事件块。

```typescript
const testAgent = mastra.getAgent('testAgent')

const stream = await testAgent.stream([{ role: 'user', content: 'Help me organize my day' }])

for await (const chunk of stream.fullStream) {
  console.log(chunk)
}
```

详情请参阅 [Agent.stream()](/reference/streaming/agents/stream)。

## Writer API {/* #writer-api */}

Tool 和 Workflow 步骤共用 `writer` API。具体用法示例请参阅 Tool 和 Workflow 文档。

## 在 Agent 的流式传输中使用 Tool {/* #agent-using-tool */}

Agent 流式传输可以与 Tool 调用结合使用，将 Tool 输出直接写入 Agent 的流式响应，从而在交互过程中展示 Tool 活动。

```typescript {2,9}
import { Agent } from '@mastra/core/agent'
import { testTool } from '../tools/test-tool'

export const testAgent = new Agent({
  id: 'test-agent',
  name: 'Test Agent',
  instructions: 'You are a weather agent.',
  model: '__GATEWAY_OPENAI_MODEL__',
  tools: { testTool },
})
```

### 使用 `context.writer` {/* #using-contextwriter */}

在 Tool 的 `execute()` 函数中，可使用 `context.writer` 对象向当前流发出自定义事件、数据或值。Tool 可借此在执行期间提供中间结果或状态更新。

:::warning

必须用 `await` 等待 `writer.write()` 调用完成，否则流会被锁定，并出现 `WritableStream is locked` 错误。

:::

```typescript {4,7,14}
import { createTool } from '@mastra/core/tools'

export const testTool = createTool({
  execute: async (inputData, context) => {
    const { value } = inputData

    await context?.writer?.write({
      type: 'custom-event',
      status: 'pending',
    })

    const response = await fetch()

    await context?.writer?.write({
      type: 'custom-event',
      status: 'success',
    })

    return {
      value: '',
    }
  },
})
```

也可使用 `writer.custom()` 发出顶层流数据块，便于与 UI 框架集成。

```typescript {4,7,14}
import { createTool } from '@mastra/core/tools'

export const testTool = createTool({
  execute: async (inputData, context) => {
    const { value } = inputData

    await context?.writer?.custom({
      type: 'data-tool-progress',
      status: 'pending',
    })

    const response = await fetch()

    await context?.writer?.custom({
      type: 'data-tool-progress',
      status: 'success',
    })

    return {
      value: '',
    }
  },
})
```

### 瞬态数据块 {/* #transient-data-chunks */}

默认情况下，`writer.custom()` 发出的 `data-*` 数据块会作为消息历史的一部分持久化。对于只在实时传输期间需要的数据块（例如进度更新或详细日志输出），可以设置 `transient: true` 跳过持久化。瞬态块仍会实时传输到客户端，但不会保存到数据库。

```typescript {4}
await context?.writer?.custom({
  type: 'data-build-log',
  data: { line: 'Compiling module 3 of 12...' },
  transient: true,
})
```

如果数据量大或产生频繁，且只在当前实时会话中有用，可使用瞬态块。刷新页面后，瞬态块将不可用，存储层只会加载 Tool 的返回值和非瞬态块。

## 使用 `writer` 参数 {/* #using-the-writer-argument */}

Workflow 步骤的 `execute` 函数会收到 `writer` 参数，可用它向当前流发出自定义事件、数据或值。Workflow 步骤通过这些事件在执行期间提供中间结果或状态更新。

:::warning

必须用 `await` 等待 `writer.write(...)` 调用完成，否则流会被锁定，并出现 `WritableStream is locked` 错误。

:::

```typescript {8,11,18}
import { createStep } from '@mastra/core/workflows'
import { z } from 'zod'

export const testStep = createStep({
  id: 'test-step',
  inputSchema: z.object({ url: z.url() }),
  outputSchema: z.object({ status: z.number() }),
  execute: async ({ inputData, writer }) => {
    const { url } = inputData

    await writer.write({
      type: 'custom-event',
      status: 'pending',
    })

    const response = await fetch(url)

    await writer.write({
      type: 'custom-event',
      status: 'success',
    })

    return {
      status: response.status,
    }
  },
})
```
