# 上下文工程

{/* vale ai-tells.VerbTricolon = NO */}

模型只能利用上下文窗口中的信息，例如当前对话、记住的细节、应用数据、Tool 结果或知识库中的相关段落。

上下文工程是决定模型应在何时看到哪些信息。目标是保持信息相关且及时，而非尽可能多。信息太少，模型缺少必要依据；太多，则重要细节更难找到，成本增加，甚至在达到上下文上限前就降低回答质量。

Mastra 提供多种机制，可将信息引入上下文、长期保留、按需检索，并在任务扩展时压缩或隔离。本指南说明何时使用各机制及其如何配合。

{/* vale ai-tells.VerbTricolon = YES */}

| 需求 | 从何入手 | 模型看到的内容 |
| - | - | - |
| 稳定的身份、规则或约束 | [指令](#instructions) | 每次模型调用的系统上下文 |
| 数据库或 API 数据 | [Tool](#tools) | Tool 定义及选定的结果 |
| 当前客户或应用数据 | [内联上下文](#inline-context) | 插入用户消息中的数据 |
| 大型且稳定的知识库 | [RAG](#rag) | 索引中语义相关的内容块 |
| 用户或组织管理的文档 | [文件系统](#filesystems) | 通过读取或搜索 Tool 选取的文件 |
| 最近的对话或持久事实 | [记忆](#memory) | 消息历史、观察记录或检索到的记忆 |
| 长时间运行的对话 | [观察记忆](#observational-memory) | 精简的观察记录及最近尚未观察的消息 |
| 运行期间的新事件或状态变化 | [Signals](#signals) | 用户、响应式、通知或状态消息 |
| 仅部分任务需要的指令 | [动态 Skill](#dynamic-skills) | Skill 元数据，以及按需加载的指令 |

## 指示 {/* #instructions */}

Agent 的 [`instructions`](/reference/agents/agent#constructor-parameters) 定义稳定的身份、行为和约束。它们属于系统消息，出现在模型请求的对话消息之前。

```typescript title="src/mastra/agents/support-agent.ts"
import { Agent } from '@mastra/core/agent'

export const supportAgent = new Agent({
  id: 'support-agent',
  name: 'Support Agent',
  instructions: `You help customers understand their account.
    Use plain language and don't invent account details.`,
  model: '__GATEWAY_OPENAI_MODEL__',
})
```

指令应聚焦适用于大多数调用的行为。加入当前账户数据、检索文档或任务专属细节，会让基础提示词变长且更难复用。

指令也可以在运行时从 [`RequestContext`](/docs/server/request-context) 解析：

```typescript title="src/mastra/agents/support-agent.ts"
instructions: ({ requestContext }) => {
  const name = requestContext.get('name')

  return `You help ${name} understand their account.`
}
```

如果指令依赖每次请求都会变化的数据，例如当前用户、租户、locale、角色或功能开关，请使用 `RequestContext`。Agent 构造时求值的内容，包括插入的 `new Date()`，在进程生命周期内都不会变化。因此，应在回调中计算随时间变化的值，并显式传入时区：

```typescript title="src/mastra/agents/support-agent.ts"
instructions: () =>
  `You help customers understand their account.
  Today is ${new Date().toLocaleDateString('en-US', { timeZone: 'America/New_York' })}.`
```

在回调中解析日期，长时间运行的服务器就能在午夜后获取新日期；显式设置 `timeZone` 可避免主机时区影响日期。如果日期必须在 Tool 续接时刷新，或需与 Studio 的指令覆盖设置共存，请改用 [`processInputStep`](/reference/processors/processor-interface#processinputstep) 处理器。

:::tip

如果解析后的指令频繁变化，模型 Provider 可能无法复用提示词缓存的相同前缀。将稳定部分放在前面，频繁变化的背景信息则通过消息或信号传递。

观看[这段关于提示词缓存的短视频](https://youtu.be/eBB0dBqfvuQ)，了解可缓存的提示词前缀如何降低延迟和成本。

:::

## 内联上下文 {/* #inline-context */}

多数应用通过将相关值插入当前消息来传递运行时上下文。如果代码已加载客户或应用数据，这种方式很合适：

```typescript
const customer = await db.customer.findById(customerId)

await supportAgent.generate(`
  Customer: ${customer.name}
  Plan: ${customer.plan}
  Question: ${question}
`)
```

选择并标记模型所需的字段，而不是序列化整个数据库记录。这样可以使提示更小，并使每个值的含义更加清晰。

启用记忆后，Mastra 会保存当前用户消息。不要插入不应留在对话历史中的敏感或临时数据。

如果背景信息只需影响一次响应，不应保存到对话历史，可传入 [`context`](/reference/agents/generate) 消息：

```typescript
await supportAgent.generate('Recommend the next action.', {
  context: [{ role: 'user', content: 'The customer has an unresolved billing dispute.' }],
})
```

模型会在本次执行中看到这些背景信息，但 Mastra 不会将其保存到记忆中。如果保存背景信息会污染对话，或让临时应用状态在后续轮次暴露，请使用 `context`。

## Tool {/* #tools */}

[Tool](/docs/agents/tools) 是从数据库、API 或服务获取当前数据的推荐方式。模型决定何时取数并提供 Tool 参数，应用则控制查询及返回字段。

```typescript title="src/mastra/tools/customer-tool.ts"
import { createTool } from '@mastra/core/tools'
import { z } from 'zod'

export const getCustomer = createTool({
  id: 'get-customer',
  description: 'Gets the current profile and plan for a customer',
  inputSchema: z.object({ customerId: z.string() }),
  execute: async ({ customerId }) => {
    const customer = await db.customer.findById(customerId)
    return { name: customer.name, plan: customer.plan, status: customer.status }
  },
})
```

应用代码需要完整结果、模型只需精简表示时，使用 [`toModelOutput`](/docs/agents/tools#shape-output-for-the-model)。

## RAG {/* #rag */}

[检索增强生成 (RAG)](/reference/rag/overview)从索引语料库中检索语义相关的块。它仍然适合大型、稳定的知识库，用户可以在其中提出开放式问题，而这些问题不能清楚地映射到结构化数据库查询。

```typescript
import { ModelRouterEmbeddingModel } from '@mastra/core/llm'
import { createVectorQueryTool } from '@mastra/rag'

const knowledgeBase = createVectorQueryTool({
  vectorStoreName: 'knowledgeBase',
  indexName: 'support-docs',
  model: new ModelRouterEmbeddingModel('openai/text-embedding-3-small'),
})
```

将 `vectorStoreName` 引用的向量存储注册到 Agent 所在的 Mastra 实例。Mastra 支持[多种向量数据库](/reference/rag/vector-databases)。如本例所示，RAG 常通过 Tool 提供。关键在于判断 Agent 需要语义检索，还是可以直接查询数据源。

现在许多应用会先使用直连特定数据源的 Tool。模型更擅长选择这类 Tool，而直接查询通常更简单、更便宜，因为不需要切块、嵌入和向量索引流程。仅在确实需要检索非结构化内容的语义时选择 RAG，并用元数据过滤、重排序及保守的 `topK` 限制返回的上下文。

## 文件系统 {/* #filesystems */}

[文件系统](/docs/sandbox/filesystem)让 Agent 持续访问文档和其他文件。文件可位于本地目录，或 Amazon S3、AgentFS、Google Drive 等 Provider 中。Agent 会获得用于列出、读取和搜索文件的内置 Tool。

```typescript title="src/mastra/workspace.ts"
import { LocalFilesystem, Workspace } from '@mastra/core/workspace'

export const workspace = new Workspace({
  filesystem: new LocalFilesystem({ basePath: './knowledge-base' }),
  bm25: true,
  autoIndexPaths: ['**/*.md'],
})

// Agents receive tools including mastra_workspace_read_file, mastra_workspace_list_files,
// mastra_workspace_grep, mastra_workspace_search, and mastra_workspace_index.
await workspace.init()
```

[Workspace 搜索](/docs/sandbox/search)支持 BM25 关键词搜索、向量语义搜索及混合搜索。当个人助理需要处理用户文件，或团队通过 Google Drive 等服务更新组织知识库时，可使用文件系统。搜索基于 Workspace 索引，因此文件变更后必须先更新索引，Agent 才能检索到最新内容。

:::tip

文件系统搜索也可使用向量，因此与 RAG 有功能重叠。如果事实来源是一组 Agent 可能需要列出、读取或更新的文件，选用文件系统；如果主要需求是检索，且内容无需按文件处理，则选用独立的 RAG 流程。

:::

## 记忆 {/* #memory */}

[记忆](/docs/memory/overview)让 Agent 的多轮对话保持连贯。它将最近消息及记住的细节带入上下文，应用无需每轮重新发送完整对话记录。

记忆需要存储 Provider。每次调用还须指定拥有该记忆的 `resource`，以及标识对话的 `thread`。复用这两个值，才能继续同一对话：

```typescript title="src/mastra/agents/assistant.ts"
import { Agent } from '@mastra/core/agent'
import { Memory } from '@mastra/memory'

export const assistant = new Agent({
  id: 'assistant',
  name: 'Assistant',
  model: '__GATEWAY_OPENAI_MODEL__',
  memory: new Memory({
    options: {
      lastMessages: 20,
    },
  }),
})

await assistant.generate('Help me plan the next project milestone.', {
  memory: {
    resource: 'user-123',
    thread: 'project-456',
  },
})
```

本例假设存储已配置在注册的 Mastra 实例上，或直接配置在 `Memory` 上。`lastMessages` 控制 Mastra 从线程加载的最近消息数量，默认值为 10。

消息历史适合较短的对话，最近几轮通常足以提供所需上下文。`lastMessages` 窗口每次请求都会前移；超过上限后，每轮都会从提示词开头移除最旧消息，使 Provider 的提示词缓存失效。对于长对话，Mastra 推荐[观察记忆](/docs/memory/observational-memory)：它保留近期对话，将旧历史整理为精简的观察日志，同时保持提示词前缀稳定，利于缓存。

## 观察记忆 {/* #observational-memory */}

对话历史记录随着每条用户消息、响应和Tool调用而增长。即使在达到模型的硬上下文限制之前，长文本也会增加成本并使模型更难找到相关细节。压缩用较小的表示取代旧的、冗长的历史记录。

[观察记忆](/docs/memory/observational-memory)持续处理这些增长的历史。Observer 将旧消息和 Tool 交互整理为精简的观察记录，定期反思再重组并压缩这些记录。

启用观察记忆后，无需配置 `lastMessages`。观察记忆自行管理历史：在上下文中保留最近尚未观察的消息，并用观察记录取代较早的消息。

```typescript title="src/mastra/agents/assistant.ts"
import { Agent } from '@mastra/core/agent'
import { Memory } from '@mastra/memory'

export const assistant = new Agent({
  id: 'assistant',
  name: 'Assistant',
  model: '__GATEWAY_OPENAI_MODEL__',
  memory: new Memory({
    options: {
      observationalMemory: true,
    },
  }),
})
```

消息被观察后，模型会收到观察日志、最近尚未观察的消息和续接提醒。异步缓冲的观察记录不会生成续接提示（`currentTask` 或 `suggestedResponse`），因为缓冲内容激活时，延迟生成的提示可能已过时。原始消息仍保存在存储中，但不再占用当前模型上下文。

观察记录以稳定的块追加，帮助 Provider 复用现有提示词前缀。观察记忆也可在提示词缓存即将过期时，或 Agent 切换 Provider 前，激活已缓冲的观察记录。

## 信号 {/* #signals */}

[信号](/docs/signals/overview)将消息或系统生成的上下文添加到内存支持的线程中。传递取决于线程的状态：信号可以唤醒空闲Agent或进入活动循环。它还可以等待下一个回合或持续存在而不唤醒Agent。

状态信号需要记忆和现有线程；通知收件箱信号需要支持通知的存储适配器。

| API | 用途 | 上下文行为 |
| - | - | - |
| `sendMessage()` | 当前运行中的 Agent 应立即看到的用户输入 | 进入活动循环，或唤醒空闲线程 |
| `queueMessage()` | 应等待下一轮的用户输入 | 当前运行结束后开始处理 |
| `sendSignal()` | 后台结果、策略提醒或外部事件 | 按传递选项加入响应式或通知上下文 |
| `sendStateSignal()` | 浏览器、编辑器、任务等不断变化的状态 | 通过快照和增量维护线程作用域的状态通道 |

对由系统而非用户产生的上下文，使用 `sendSignal()`：

```typescript
const result = agent.sendSignal(
  {
    type: 'notification',
    contents: 'CI failed on pull request 123: three tests failed.',
    attributes: { source: 'github', pullRequest: 123 },
  },
  {
    resourceId: 'user-123',
    threadId: 'project-456',
  },
)

await result.accepted
```

处理器可在 `processInputStep()` 期间发送响应式信号，提供依赖当前步骤或近期 Tool 结果的指导。若信号只应送达当前模型调用，请设置 `transient: true`。需要时重新发送，避免把重复提醒存入对话历史。

状态信号表示随时间变化的上下文。Mastra 会为每条状态通道追踪快照和增量；当旧快照离开活动上下文窗口后，可重新插入最新快照。处理器负责状态时，可使用 `computeStateSignal()`。即使消息历史或观察记忆移除了旧消息，此通道仍能让工作记忆、浏览器上下文与任务列表一起保持可用。

信号会在当前回合附近附加不断变化的上下文，而不是重写Agent的基本指令。因此，瞬态和状态信号可以保留更稳定的提示前缀，同时保持当前指导和状态对模型可见。

## 动态技能 {/* #dynamic-skills */}

[Agent Skill](/docs/skills) 让 Agent 只在需要时加载任务专属指令，无需将所有流程都放进基础指令。适用于部分请求才需用到的专门指导，也能缩小默认上下文。

## 上下文控制 {/* #context-control */}

上下文控制限制了模型随着任务的增长所看到的内容。压缩和处理器减少了一个Agent内的上下文，而子Agent边界控制了Agent之间的移动。

### 压实 {/* #compaction */}

如果用过 Claude Code，你可能见过长会话中的上下文压缩。Mastra 团队有句玩笑话：“朋友不会让朋友做上下文压缩。”

上下文压缩会等到对话达到 token 阈值，才总结记录并替换旧消息。这是较粗糙的兜底机制：压缩轮次增加延迟，一份摘要还必须概括此前所有内容。反复摘要可能抹平时间顺序，或丢失后来才显得重要的细节。

长对话优先使用[观察记忆](#observational-memory)。它能在后台异步处理历史，同时保留时间脉络。反思会重新审视累积的记忆，自然淘汰不再重要的细节。Mastra 没有开箱即用的上下文压缩，但可通过自定义[处理器](/docs/agents/processors)实现。

### 处理器 {/* #processors */}

[处理器](/docs/agents/processors)控制进入模型上下文的内容，并可以在模型调用之前重写内容。当信息应保留在存储的历史记录或应用程序输出中但不需要在每个步骤中发送回模型时，请使用它们。

例如，`ToolCallFilter` 会从下一次模型请求中移除旧 Tool 的参数和结果，但不会从存储中删除这些消息。模型收到更短的提示词，应用仍可显示或检查完整交互。

使用 `processInput()` 或 `processInputStep()` 更改当前消息列表；这些改动之后可能保存到记忆中。如果改写仅应作用于当前 Provider 调用，而不应影响记忆，请使用 `processLLMRequest()`。

Mastra 包含一些针对上下文膨胀的常见来源的控件：

* [`toModelOutput`](/docs/agents/tools#shape-output-for-the-model)：将冗长的 Tool 结果替换为更精简的模型输入。
* [`ToolCallFilter`](/reference/processors/tool-call-filter)：从模型输入中删除旧的Tool调用和结果，同时将它们保留在内存和 UI 中。
* [`ToolSearchProcessor`](/reference/processors/tool-search-processor)：以搜索与加载 Tool 取代庞大的 Tool 目录。
* [`TokenLimiter`](/reference/processors/token-limiter-processor)：修剪非系统消息，直到提示符合令牌预算。

对于冗长的 Tool 结果，先使用 [`toModelOutput`](/docs/agents/tools#shape-output-for-the-model)；对于旧 Tool 交互，先使用 `ToolCallFilter`。将 `TokenLimiter` 作为最后的预算保护，而不要只依赖模型的最大上下文窗口。

### 子Agent {/* #subagents */}

上下文膨胀的常见原因，是向[子 Agent](/docs/subagents) 传递或从其接收过多信息。子 Agent 有独立的模型上下文来执行委派任务，但这一边界仍需有意识地控制。

默认情况下，Mastra 会将父 Agent 的对话转发给子 Agent。使用 `messageFilter` 只传入该专门 Agent 所需的消息：

```typescript
await supervisor.generate('Investigate the failed deployment.', {
  delegation: {
    messageFilter: ({ messages }) => messages.slice(-10),
  },
})
```

反过来，Mastra 默认将子 Agent 的文本返回给父模型，同时保留嵌套的 Tool 调用和元数据，供应用代码使用。除非父模型必须分析这些细节，否则保持 `includeSubAgentToolResultsInModelContext` 禁用。使用 `onDelegationStart` 调整子 Agent 提示词，并用 `onDelegationComplete` 缩减或替换返回给父模型的文本。

委派钩子、记忆隔离、迭代监控和结果控制详见[子 Agent](/docs/subagents)。
