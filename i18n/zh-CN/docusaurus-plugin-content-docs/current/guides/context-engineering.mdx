# 情境工程

{/* vale ai-tells.VerbTricolon = NO */}

模型只能使用其上下文窗口中可用的信息。这可能包括当前对话、记住的细节、应用程序数据、Tool结果或知识库中的相关段落。

上下文工程是决定模型应该看到什么信息以及何时看到的实践。我们的目标不是提供尽可能多的内容，而是保持上下文的相关性和最新性。上下文太少会使模型无法获得所需的信息；太多可能会使重要细节更难找到，增加成本，并在模型达到其上下文限制之前降低响应质量。

Mastra 提供了不同的方法来将信息带入上下文、保持信息随时间可用、在需要时检索信息以及随着任务的增长减少或隔离信息。本指南解释了何时使用每种机制以及它们如何组合在一起。

{/* vale ai-tells.VerbTricolon = YES */}

|需要|以 | 开头模型看到了什么 |
| - | - | - |
|稳定的身份、规则或约束|[Instructions](#instructions) | System context on each model call |
| Data from a database or API | [Tools](#tools) | Tool definitions followed by selected results |
| Current customer or application data | [内联上下文](#inline-context)|数据插入到用户消息中 |
|庞大、稳定的知识库 |[抹布](#rag)|索引中语义相关的块 |
|用户或组织管理的文档 |[文件系统](#filesystems)|通过读取或搜索Tool选择的文件 |
|最近的谈话或持久的事实|[记忆](#memory)|历史、观察或检索的记忆 |
|一场长时间的对话 |[观察记忆](#observational-memory)|密集观察加上最近未观察到的消息|
|运行期间发生新事件或更改状态 |[信号](#signals)|用户消息、反应消息、通知消息或状态消息 |
|仅某些任务需要说明 |[动态技能](#dynamic-skills)|技能元数据，后跟按需加载的说明 |

## 指示 {/* #instructions */}

一个Agent的[`instructions`](/reference/agents/agent#constructor-parameters) define its stable identity, behavior, and constraints. They're system messages and appear before conversation messages in the model request.

```typescript title="src/mastra/agents/support-agent.ts"
import { Agent } from '@mastra/core/agent'

export const supportAgent = new Agent({
  id: 'support-agent',
  name: 'Support Agent',
  instructions: `You help customers understand their account.
    Use plain language and don't invent account details.`,
  model: '__GATEWAY_OPENAI_MODEL__',
})
```

让说明集中于适用于大多数通话的行为。添加当前帐户数据、检索到的文档或特定于任务的详细信息会使基本提示变得更大并且更难以重用。

指令也可以在运行时解析[`RequestContext`](/docs/server/request-context):

```typescript title="src/mastra/agents/support-agent.ts"
instructions: ({ requestContext }) => {
  const name = requestContext.get('name')

  return `You help ${name} understand their account.`
}
```

使用`RequestContext` when instructions depend on data that changes with each request, such as the current user, tenant, locale, role, or feature flags. Anything evaluated when the agent is constructed, including an interpolated `new Date()`, is fixed for the life of the process, so compute time-dependent values inside a callback and pass an explicit timezone:

```typescript title="src/mastra/agents/support-agent.ts"
instructions: () =>
  `You help customers understand their account.
  Today is ${new Date().toLocaleDateString('en-US', { timeZone: 'America/New_York' })}.`
```

解析回调中的日期意味着长时间运行的服务器会在午夜后选取新的一天，并且显式`timeZone` keeps the date stable regardless of the host's timezone. If the date must refresh across tool continuations or coexist with Studio instruction overrides, use a [`processInputStep`](/reference/processors/processor-interface#processinputstep) processor instead.

：：：提示

如果解析的指令经常更改，模型提供者可能无法重用相同的提示缓存前缀。首先保持稳定的部分，然后通过消息或信号来传递频繁变化的背景。

手表[this short video on prompt caching](https://youtu.be/eBB0dBqfvuQ) to learn how cacheable prompt prefixes reduce latency and cost.

:::

## 内联上下文 {/* #inline-context */}

大多数应用程序通过将相关值插入到当前消息中来传递运行时上下文。当您的代码已经加载客户或应用程序数据时，这很有效：

```typescript
const customer = await db.customer.findById(customerId)

await supportAgent.generate(`
  Customer: ${customer.name}
  Plan: ${customer.plan}
  Question: ${question}
`)
```

选择并标记模型所需的字段，而不是序列化整个数据库记录。这样可以使提示更小，并使每个值的含义更加清晰。

启用内存后，Mastra 会保存当前用户消息。不要插入不应出现在对话历史记录中的敏感或临时数据。

对于不太常见的情况，即背景应该影响一个响应而不保存为对话历史记录，请传递一个[`context`](/reference/agents/generate) message:

```typescript
await supportAgent.generate('Recommend the next action.', {
  context: [{ role: 'user', content: 'The customer has an unresolved billing dispute.' }],
})
```

模型会看到当前执行的背景，但 Mastra 不会将其保存到内存中。使用`context` when persisting the background would pollute the conversation or expose temporary application state on later turns.

## Tool {/* #tools */}

[Tool](/docs/agents/tools)是从数据库、API 或服务获取当前数据的推荐方法。模型决定何时需要数据并提供Tool参数，而您的应用程序控制查询和返回的字段。

```typescript title="src/mastra/tools/customer-tool.ts"
import { createTool } from '@mastra/core/tools'
import { z } from 'zod'

export const getCustomer = createTool({
  id: 'get-customer',
  description: 'Gets the current profile and plan for a customer',
  inputSchema: z.object({ customerId: z.string() }),
  execute: async ({ customerId }) => {
    const customer = await db.customer.findById(customerId)
    return { name: customer.name, plan: customer.plan, status: customer.status }
  },
})
```

使用[`toModelOutput`](/docs/agents/tools#shape-output-for-the-model) when application code needs the full result but the model needs a smaller representation.

## 抹布 {/* #rag */}

[检索增强生成 (RAG)](/reference/rag/overview)从索引语料库中检索语义相关的块。它仍然适合大型、稳定的知识库，用户可以在其中提出开放式问题，而这些问题不能清楚地映射到结构化数据库查询。

```typescript
import { ModelRouterEmbeddingModel } from '@mastra/core/llm'
import { createVectorQueryTool } from '@mastra/rag'

const knowledgeBase = createVectorQueryTool({
  vectorStoreName: 'knowledgeBase',
  indexName: 'support-docs',
  model: new ModelRouterEmbeddingModel('openai/text-embedding-3-small'),
})
```

注册引用的向量存储`vectorStoreName` on the same Mastra instance as the agent. Mastra supports [multiple vector databases](/reference/rag/vector-databases). RAG is often exposed through a tool, as in this example. The design choice is whether the agent needs semantic retrieval or can query the source directly.

现在许多应用程序都是从直接的、特定于源的Tool开始的。模型在选择它们方面变得越来越好，而且直接查询通常更简单、更便宜，因为它不需要分块、嵌入和向量索引管道。当实际需要对非结构化内容进行语义搜索时，请选择 RAG，然后使用元数据过滤器、重新排名和保守的方法来约束返回的上下文`topK`.

## 文件系统 {/* #filesystems */}

一个[filesystem](/docs/sandbox/filesystem) gives an agent persistent access to documents and other files. Files can live in a local directory or in providers such as Amazon S3, AgentFS, or Google Drive. The agent receives built-in tools to list, read, and search them.

```typescript title="src/mastra/workspace.ts"
import { LocalFilesystem, Workspace } from '@mastra/core/workspace'

export const workspace = new Workspace({
  filesystem: new LocalFilesystem({ basePath: './knowledge-base' }),
  bm25: true,
  autoIndexPaths: ['**/*.md'],
})

// Agents receive tools including mastra_workspace_read_file, mastra_workspace_list_files,
// mastra_workspace_grep, mastra_workspace_search, and mastra_workspace_index.
await workspace.init()
```

[Workspace搜索](/docs/sandbox/search)支持 BM25 关键字搜索、向量语义搜索或两者的混合。使用文件系统作为个人助理，处理用户的文件或团队成员在 Google Drive 等服务中更新的组织知识库。搜索针对Workspace索引运行，因此必须先对更改的文件建立索引，然后Agent才能检索其最新内容。

：：：提示

文件系统搜索也可以使用向量，因此它与 RAG 重叠。当真实来源是Agent可能需要列出、读取或更新的一组文件时，请选择文件系统。当检索是主要要求并且源内容不需要像文件一样运行时，请选择独立的 RAG 管道。

## 记忆 {/* #memory */}

[记忆](/docs/memory/overview)为座席提供跨轮对话的连贯性。它将最近的消息和记住的细节带入上下文中，而不需要应用程序每次都重新发送完整的记录。

内存需要一个存储提供者。每个调用还标识一个`resource` that owns the memory and a `thread` that identifies the conversation. Reuse both values to continue the same conversation:

```typescript title="src/mastra/agents/assistant.ts"
import { Agent } from '@mastra/core/agent'
import { Memory } from '@mastra/memory'

export const assistant = new Agent({
  id: 'assistant',
  name: 'Assistant',
  model: '__GATEWAY_OPENAI_MODEL__',
  memory: new Memory({
    options: {
      lastMessages: 20,
    },
  }),
})

await assistant.generate('Help me plan the next project milestone.', {
  memory: {
    resource: 'user-123',
    thread: 'project-456',
  },
})
```

该示例假设存储是在注册的 Mastra 实例上配置的，或者直接在`Memory`. `lastMessages` controls how many recent messages Mastra loads from the thread. The default is 10.

消息历史记录非常适合较短的对话，其中最近的对话包含Agent所需的上下文。因为`lastMessages` window slides forward on every request, each turn past the limit removes the oldest message from the start of the prompt and invalidates the provider prompt cache. For long-running conversations, Mastra recommends [Observational Memory](/docs/memory/observational-memory), which keeps recent conversation available and turns older history into a dense observation log while keeping the prompt prefix stable for caching.

## 观察记忆 {/* #observational-memory */}

对话历史记录随着每条用户消息、响应和Tool调用而增长。即使在达到模型的硬上下文限制之前，长文本也会增加成本并使模型更难找到相关细节。压缩用较小的表示取代旧的、冗长的历史记录。

[观察记忆](/docs/memory/observational-memory)持续处理这个问题。观察者将旧的消息和Tool交互转化为密集的观察结果，而定期反射则重新组织和压缩这些观察结果。

你不需要配置`lastMessages` when Observational Memory is enabled. Observational Memory manages history itself, keeping recent unobserved messages in context and replacing older messages with observations.

```typescript title="src/mastra/agents/assistant.ts"
import { Agent } from '@mastra/core/agent'
import { Memory } from '@mastra/memory'

export const assistant = new Agent({
  id: 'assistant',
  name: 'Assistant',
  model: '__GATEWAY_OPENAI_MODEL__',
  memory: new Memory({
    options: {
      observationalMemory: true,
    },
  }),
})
```

观察到消息后，模型会收到观察日志、最近未观察到的消息以及继续提醒。由于延迟提示在缓冲块激活时可能已过时，因此异步缓冲观察不会生成连续提示（`currentTask` or `suggestedResponse`). The raw messages remain stored but no longer occupy the active model context.

观察结果以稳定的块的形式添加，这有助于提供者重用现有的提示前缀。观察内存还可以在提示缓存可能过期后或Agent更改提供程序之前激活缓冲观察。

## 信号 {/* #signals */}

[信号](/docs/signals/overview)将消息或系统生成的上下文添加到内存支持的线程中。传递取决于线程的状态：信号可以唤醒空闲Agent或进入活动循环。它还可以等待下一个回合或持续存在而不唤醒Agent。

状态信号需要内存和现有线程。通知收件箱信号需要具有通知支持的存储适配器。

|应用程序接口 |使用|情境行为 |
| - | - | - |
|`sendMessage()` | User input that the active agent should see now | Enters the active loop or wakes an idle thread |
| `queueMessage()` | User input that should wait for the next turn | Starts after the current run finishes |
| `sendSignal()` | Background results, policy reminders, or external events | Adds reactive or notification context according to its delivery options |
| `sendStateSignal()` | Browser state, editor state, task state, or another changing value | Maintains a thread-scoped state lane with snapshots and deltas |

使用`sendSignal()` for context produced by the system rather than the user:

```typescript
const result = agent.sendSignal(
  {
    type: 'notification',
    contents: 'CI failed on pull request 123: three tests failed.',
    attributes: { source: 'github', pullRequest: 123 },
  },
  {
    resourceId: 'user-123',
    threadId: 'project-456',
  },
)

await result.accepted
```

处理器可以在期间发送反应信号`processInputStep()`. This is useful for guidance that depends on the current step or a recent tool result. Set `transient: true` when the signal should reach only the current model call. Re-send it when needed instead of storing repeated reminders in conversation history.

状态信号代表随时间变化的上下文。对于每个状态通道，Mastra 都会跟踪快照和增量，以便在前一个快照离开活动上下文窗口后重新插入新的快照。使用`computeStateSignal()` when a processor owns the state. This lane can keep working memory and browser context available alongside task lists, even after history or Observational Memory removes older messages.

信号会在当前回合附近附加不断变化的上下文，而不是重写Agent的基本指令。因此，瞬态和状态信号可以保留更稳定的提示前缀，同时保持当前指导和状态对模型可见。

## 动态技能 {/* #dynamic-skills */}

[Agent技巧](/docs/skills)让Agent仅在需要时加载特定于任务的指令，而不是在其基本指令中携带每个过程。使用它们作为适用于某些请求的专门指导，并使默认上下文保持较小。

## 上下文控制 {/* #context-control */}

上下文控制限制了模型随着任务的增长所看到的内容。压缩和处理器减少了一个Agent内的上下文，而子Agent边界控制了Agent之间的移动。

### 压实 {/* #compaction */}

如果您使用过 Claude Code，您可能会在长时间会话期间看到压缩发生。 Mastra 团队喜欢开玩笑，“朋友不让朋友做压缩”。

压缩会等到对话达到令牌阈值。然后它会总结文字记录并替换之前的消息。这是一个生硬的后退。压缩回合增加了延迟，并且单个摘要必须代表之前发生的所有内容。重复的总结可能会使时间顺序变得扁平或丢失后来变得重要的细节。

更喜欢[Observational Memory](#observational-memory) for long-running conversations. It can process history asynchronously in the background while preserving temporal context. Reflection revisits accumulated memories and naturally prunes details that no longer matter. Mastra doesn't provide compaction out of the box, though you could implement it with a custom [processor](/docs/agents/processors).

### 处理器 {/* #processors */}

[处理器](/docs/agents/processors)控制进入模型上下文的内容，并可以在模型调用之前重写内容。当信息应保留在存储的历史记录或应用程序输出中但不需要在每个步骤中发送回模型时，请使用它们。

例如，`ToolCallFilter` removes old tool arguments and results from the next model request without deleting those messages from storage. The model gets a smaller prompt, while your application can still display or inspect the complete interaction.

使用`processInput()` or `processInputStep()` to change the active message list. Those changes may later be saved to memory. Use `processLLMRequest()` when a rewrite should apply only to the current provider call and leave memory untouched.

Mastra 包含一些针对上下文膨胀的常见来源的控件：

* [`toModelOutput`](/docs/agents/tools#shape-output-for-the-model)：用较小的面向模型的表示替换详细的Tool结果。
* [`ToolCallFilter`](/reference/processors/tool-call-filter)：从模型输入中删除旧的Tool调用和结果，同时将它们保留在内存和 UI 中。
* [`ToolSearchProcessor`](/reference/processors/tool-search-processor)：用搜索和加载Tool替换大型Tool目录。
* [`TokenLimiter`](/reference/processors/token-limiter-processor)：修剪非系统消息，直到提示符合令牌预算。

开始于[`toModelOutput`](/docs/agents/tools#shape-output-for-the-model) for verbose tool results and `ToolCallFilter` for old tool interactions. Add `TokenLimiter` as a final budget guard rather than relying on the model's maximum context window.

### 子Agent {/* #subagents */}

上下文膨胀的一个常见原因是传入和传出过多的信息[subagents](/docs/subagents). A subagent gets a separate model context for its delegated task, but the boundary still needs deliberate controls.

默认情况下，Mastra 将家长的对话转发给子Agent。使用`messageFilter` to pass only the messages that specialist needs:

```typescript
await supervisor.generate('Investigate the failed deployment.', {
  delegation: {
    messageFilter: ({ messages }) => messages.slice(-10),
  },
})
```

另一方面，Mastra 默认将子Agent的文本返回到父模型，同时保持嵌套Tool调用和元数据可供应用程序代码使用。离开`includeSubAgentToolResultsInModelContext` disabled unless the parent must reason over those details. Use `onDelegationStart` to refine the child prompt and `onDelegationComplete` to reduce or replace the text returned to the parent.

看[Subagents](/docs/subagents) for delegation hooks, memory isolation, iteration monitoring, and result controls.
