# 工作记忆

尽管[message history](/docs/memory/message-history)和[语义回忆](./semantic-recall)帮助Agent记住对话，工作记忆使他们能够在交互过程中维护有关用户的持久信息。

工作记忆是Agent的活动暂存器：它保留有关用户或任务的关键信息。它可以在对话过程中保留一个人的姓名、偏好或其他重要细节。

这对于维护始终相关且始终可供Agent使用的持续状态非常有用。

如果你使用[Observational Memory](/docs/memory/observational-memory), `observationalMemory.observation.manageWorkingMemory` lets OM update working memory for the agent.

:::提示\[📹观看]

手表[Mastra working memory](https://www.youtube.com/watch?v=UMy_JHLf1n8\&pp=ygUVbWFzdHJhIHdvcmtpbmcgbWVtb3J5) to see how agents keep persistent user context available across interactions.

:::

工作记忆可以在两个不同的范围内持续存在：

* **资源范围**（默认）：内存在同一用户的所有对话线程中持续存在
* **线程范围**：每个会话线程的内存是隔离的

**要求：**&#x5728;范围之间切换意味着Agent不会看到来自其他范围的内存 - 线程范围内存与资源范围内存完全分开。

## 快速入门 {/* #quickstart */}

以下是设置具有工作内存的Agent的最小示例：

```typescript {11-15}
import { Agent } from '@mastra/core/agent'
import { Memory } from '@mastra/memory'

// Create agent with working memory enabled
const agent = new Agent({
  id: 'personal-assistant',
  name: 'PersonalAssistant',
  instructions: 'You are a helpful personal assistant.',
  model: '__GATEWAY_OPENAI_MODEL__',
  memory: new Memory({
    options: {
      workingMemory: {
        enabled: true,
      },
    },
  }),
})
```

## 它是如何运作的 {/* #how-it-works */}

工作记忆是一个 Markdown 文本块，Agent可以随着时间的推移更新它以连续存储相关信息。

## 内存持久性范围 {/* #memory-persistence-scopes */}

工作记忆可以在两个不同的范围内运行，允许您选择记忆在对话中持续存在的方式：

### 资源范围内存（默认） {/* #resource-scoped-memory-default */}

默认情况下，工作内存在同一用户 (resourceId) 的所有对话线程中保持不变，从而启用持久的用户内存：

```typescript
const memory = new Memory({
  storage,
  options: {
    workingMemory: {
      enabled: true,
      scope: 'resource', // Memory persists across all user threads
      template: `# User Profile
- **Name**:
- **Location**:
- **Interests**:
- **Preferences**:
- **Long-term Goals**:
`,
    },
  },
})
```

**使用案例：**

* 记住用户偏好的个人助理
* 维护客户背景的客户服务机器人
* 跟踪学生进度的教育应用程序

### 与Agent一起使用 {/* #usage-with-agents */}

使用资源范围内存时，请确保传递`resource` parameter in the memory options:

```typescript
// Resource-scoped memory requires resource
const response = await agent.generate('Hello!', {
  memory: {
    thread: 'conversation-123',
    resource: 'user-alice-456', // Same user across different threads
  },
})
```

### 线程范围内存 {/* #thread-scoped-memory */}

线程范围内存将工作内存与各个对话线程隔离。每个线程维护自己的隔离内存：

```typescript
const memory = new Memory({
  storage,
  options: {
    workingMemory: {
      enabled: true,
      scope: 'thread', // Memory is isolated per thread
      template: `# User Profile
- **Name**:
- **Interests**:
- **Current Goal**:
`,
    },
  },
})
```

**使用案例：**

* 关于不同主题的不同对话
* 临时或特定于会话的信息
* 每个线程都需要工作内存但线程是短暂的并且彼此不相关的Workflow

## 存储适配器支持 {/* #storage-adapter-support */}

资源范围的工作内存需要特定的存储适配器来支持`mastra_resources` table:

### 支持的存储适配器 {/* #supported-storage-adapters */}

* **库SQL** (`@mastra/libsql`)
* **PostgreSQL** (`@mastra/pg`)
* **甲骨文数据库** (`@mastra/oracledb`)
* **乌普斯塔什** (`@mastra/upstash`)
* **MongoDB** (`@mastra/mongodb`)

## 自定义模板 {/* #custom-templates */}

模板指导Agent跟踪和更新工作记忆中的哪些信息。当您未提供模板时，Mastra 将使用默认模板。为Agent的用例定义自定义模板，以便它记住最相关的信息。对于多个用户共享的线程，请参阅[Multi-user threads](./multi-user-threads).

以下是自定义模板的示例。在此示例中，一旦用户发送包含任何信息的消息，Agent就会存储用户名、位置、时区等：

```typescript {5-28}
const memory = new Memory({
  options: {
    workingMemory: {
      enabled: true,
      template: `
# User Profile

## Personal info

- Name:
- Location:
- Timezone:

## Preferences

- Communication Style: [e.g., Formal, Casual]
- Project Goal:
- Key Deadlines:
  - [Deadline 1]: [Date]
  - [Deadline 2]: [Date]

## Session state

- Last Task Discussed:
- Open Questions:
  - [Question 1]
  - [Question 2]
`,
    },
  },
})
```

## 设计有效的模板 {/* #designing-effective-templates */}

结构良好的模板可以让Agent轻松解析和更新信息。治疗
模板作为您希望助手保持最新的简短形式。

* **简短、集中的标签。**&#x907F;免段落或很长的标题。保持标签简短（例如`## Personal Info` or `- Name:`) so updates are readable and less likely to be truncated.
* **使用一致的外壳。**&#x5927;小写不一致 (`Timezone:` vs `timezone:`) can cause messy
  updates. Stick to Title Case or lower case for headings and bullet labels.
* **尽量减少占位符文本。**&#x4F7F;用提示，例如`[e.g., Formal]` or `[Date]` to help the LLM
  fill in the correct spots.
* **缩写很长的值。**&#x5982;果您只需要一个简短的表格，请包括类似的指导`- Name: [First name or nickname]` or `- Address (short):` rather than the full legal text.
* **提及更新规则`instructions`.**&#x60A8;可以指示如何以及何时填充或清除部分内容
  模板直接在Agent的`instructions` field.

### 替代模板样式 {/* #alternative-template-styles */}

如果您只需要几个项目，请使用较短的单个块：

```typescript
const basicMemory = new Memory({
  options: {
    workingMemory: {
      enabled: true,
      template: `User Facts:\n- Name:\n- Favorite Color:\n- Current Topic:`,
    },
  },
})
```

如果您喜欢更具叙述性的风格，您还可以以短段落格式存储关键事实：

```typescript
const paragraphMemory = new Memory({
  options: {
    workingMemory: {
      enabled: true,
      template: `Important Details:\n\nKeep a short paragraph capturing the user's important facts (name, main goal, current task).`,
    },
  },
})
```

## 结构化工作记忆 {/* #structured-working-memory */}

工作记忆也可以使用结构化模式而不是 Markdown 模板来定义。一个[Standard JSON Schema](https://standardschema.dev/json-schema) ([Zod](https://zod.dev/), [Valibot](https://valibot.dev/), [ArkType](https://arktype.io/), etc.). When using a schema, the agent will see and update working memory as a JSON object matching your schema.

您可以指定`template` or `schema`, but not both. If you omit both, Mastra uses the default working memory template.

### 示例：基于模式的工作内存 {/* #example-schema-based-working-memory */}

```typescript
import { z } from 'zod'
import { Memory } from '@mastra/memory'

const userProfileSchema = z.object({
  name: z.string().optional(),
  location: z.string().optional(),
  timezone: z.string().optional(),
  preferences: z
    .object({
      communicationStyle: z.string().optional(),
      projectGoal: z.string().optional(),
      deadlines: z.array(z.string()).optional(),
    })
    .optional(),
})

const memory = new Memory({
  options: {
    workingMemory: {
      enabled: true,
      schema: userProfileSchema,
      // template: ... (do not set)
    },
  },
})
```

提供架构后，Agent会接收 JSON 对象形式的工作内存。例如：

```json
{
  "name": "Sam",
  "location": "Berlin",
  "timezone": "CET",
  "preferences": {
    "communicationStyle": "Formal",
    "projectGoal": "Launch MVP",
    "deadlines": ["2025-07-01"]
  }
}
```

### 基于模式的内存的合并语义 {/* #merge-semantics-for-schema-based-memory */}

基于模式的工作记忆使用**merge semantics**, meaning the agent only needs to include fields it wants to add or update. Existing fields are preserved automatically.

* **对象字段深度合并：**&#x4EC5;更新提供的字段；其他保持不变
* **设置一个字段为`null` to delete it:**&#x8FD9;会显式地从内存中删除该字段
* **数组被完全替换：**&#x5F53;提供数组字段时，它将替换现有数组（数组不会逐元素合并）

### 并发更新 {/* #concurrent-updates */}

和`scope: 'resource'` and a storage adapter that supports atomic merges (currently `@mastra/pg`), each merge runs inside a row-locked database transaction. Concurrent updates to different fields from separate processes are all kept. Other adapters merge in the application, which only serializes writers inside a single process.

要合并您自己的代码的部分更新，请调用`memory.mergeWorkingMemory()`:

```typescript
await memory.mergeWorkingMemory({
  threadId: 'thread-1',
  resourceId: 'user-123',
  workingMemory: { preferences: { tone: 'formal' } },
})
```

如果工作内存不是基于模式和资源范围的，或者存储适配器不支持原子合并，则会抛出该错误。查看`await memory.supportsAtomicWorkingMemoryMerge()` first if you need to fall back.

## 在模板和模式之间进行选择 {/* #choosing-between-template-and-schema */}

* 使用一个**template** (Markdown) if you want the agent to maintain memory as a free-form text block, such as a user profile or scratchpad. Templates use **replace semantics**: the agent must provide the complete memory content on each update.
* 使用一个**schema** for structured, type-safe JSON data that supports validation and programmatic access. The `workingMemory.schema` field accepts any `PublicSchema`-compatible schema, such as Zod v3 or v4. JSON Schema and already-standard schemas are also supported. **Merge semantics** preserve existing fields when the agent provides only the fields to update.
* 一次只能激活一种模式：同时设置两种模式`template` and `schema` isn't supported.

## 示例：多步骤保留 {/* #example-multi-step-retention */}

下面是如何进行的简化视图`User Profile` template updates across a short user
conversation:

```nohighlight
# User Profile

## Personal info

- Name:
- Location:
- Timezone:

--- After user says "My name is **Sam** and I'm from **Berlin**" ---

# User Profile
- Name: Sam
- Location: Berlin
- Timezone:

--- After user adds "By the way I'm normally in **CET**" ---

# User Profile
- Name: Sam
- Location: Berlin
- Timezone: CET
```

Agent现在可以参考`Sam` or `Berlin` in later responses without requesting the information
again because it has been stored in working memory.

如果您的Agent没有按照您的预期正确更新工作内存，您可以添加系统
说明*how* and *when* to use this template in your agent's `instructions` setting.

## 设置初始工作记忆 {/* #setting-initial-working-memory */}

虽然Agent通常通过以下方式更新工作记忆`updateWorkingMemory` tool, you can also set initial working memory programmatically when creating or updating threads. This is useful for injecting user data (like their name, preferences, or other info) that you want available to the agent without passing it in every request.

### 通过线程元数据设置工作内存 {/* #setting-working-memory-via-thread-metadata */}

创建线程时，可以通过元数据提供初始工作内存`workingMemory` key:

```typescript title="src/app/medical-consultation.ts"
// Create a thread with initial working memory
const thread = await memory.createThread({
  threadId: 'thread-123',
  resourceId: 'user-456',
  title: 'Medical Consultation',
  metadata: {
    workingMemory: `# Patient Profile
- Name: John Doe
- Blood Type: O+
- Allergies: Penicillin
- Current Medications: None
- Medical History: Hypertension (controlled)
`,
  },
})

// The agent will now have access to this information in all messages
await agent.generate("What's my blood type?", {
  memory: {
    thread: thread.id,
    resource: 'user-456',
  },
})
// Response: "Your blood type is O+."
```

### 以编程方式更新工作内存 {/* #updating-working-memory-programmatically */}

您还可以更新现有线程的工作内存：

```typescript title="src/app/medical-consultation.ts"
// Update thread metadata to add/modify working memory
await memory.updateThread({
  id: 'thread-123',
  title: thread.title,
  metadata: {
    ...thread.metadata,
    workingMemory: `# Patient Profile
- Name: John Doe
- Blood Type: O+
- Allergies: Penicillin, Ibuprofen  // Updated
- Current Medications: Lisinopril 10mg daily  // Added
- Medical History: Hypertension (controlled)
`,
  },
})
```

### 直接内存更新 {/* #direct-memory-update */}

或者，使用`updateWorkingMemory` method directly:

```typescript title="src/app/medical-consultation.ts"
await memory.updateWorkingMemory({
  threadId: 'thread-123',
  resourceId: 'user-456', // Required for resource-scoped memory
  workingMemory: 'Updated memory content...',
})
```

## 只读工作内存 {/* #read-only-working-memory */}

在某些情况下，您可能希望Agent能够访问工作内存数据，但无法对其进行修改。这对于：

* **路由Agent**需要上下文但不应更新用户配置文件
* **分Agent**在应该引用但不拥有内存的多Agent系统中

要启用只读模式，请设置`readOnly: true` in the memory options:

```typescript
const response = await agent.generate('What do you know about me?', {
  memory: {
    thread: 'conversation-123',
    resource: 'user-alice-456',
    options: {
      readOnly: true, // Working memory is provided but cannot be updated
    },
  },
})
```

## 选择状态信号（实验） {/* #opt-in-to-state-signals-experimental */}

默认情况下，工作内存作为系统消息的一部分到达模型。您可以选择将其作为[state signal](/docs/signals/state-signals) instead by setting `useStateSignals: true`:

```typescript
const memory = new Memory({
  storage: new LibSQLStore({ id: 'mastra-storage', url: 'file:./mastra.db' }),
  options: {
    workingMemory: {
      enabled: true,
      template: '# User\n- name:\n- location:',
      useStateSignals: true, // experimental: deliver as state signal
    },
  },
})
```

有何变化：

* **存储是相同的。**&#x76F8;同的资源/线程`workingMemory` field is read and written.
* **该Tool具有相同的形状，但以新名称显示。**&#x5199;入仍然通过相同的底层Tool进行；在此路径上它被注册为`setWorkingMemory` (instead of `updateWorkingMemory`). The rename keeps legacy strip filters from removing tool-call parts so they persist as a normal audit trail and the next model step picks the new value up automatically.
* **仅限送货。**&#x800C;不是折叠到系统提示符中，`Memory` auto-attaches a `WorkingMemoryStateProcessor` that emits the current working memory as a `state` signal with `stateId: 'working-memory'`.

您继承了标准状态信号的好处：线程范围的跟踪元数据，`cacheKey` dedup so identical snapshots are only emitted once, and `contextWindow.hasSnapshot` re-injection when an older snapshot rolls out of the window.

默认（`useStateSignals: false`) keeps the existing system-message behavior unchanged. `useStateSignals` isn't supported with template working memory `version: 'vnext'`.
