# 工作记忆

[消息历史](/docs/memory/message-history)和[语义召回](./semantic-recall)帮助 Agent 记住对话；工作记忆则让 Agent 跨多次交互持续保存有关用户的信息。

工作记忆是 Agent 正在使用的便笺：其中保留与用户或任务有关的关键信息，例如姓名、偏好及对话中的其他重要细节。

它适合维护始终相关、需要随时提供给 Agent 的持续状态。

如果使用 [Observational Memory](/docs/memory/observational-memory)，`observationalMemory.observation.manageWorkingMemory` 可让 OM 为 Agent 更新工作记忆。

:::tip[📹 观看]

观看 [Mastra 工作记忆](https://www.youtube.com/watch?v=UMy_JHLf1n8\&pp=ygUVbWFzdHJhIHdvcmtpbmcgbWVtb3J5)，了解 Agent 如何在多次交互中持续保留用户上下文。

:::

工作记忆可按两种范围持久化：

- **资源范围**（默认）：同一用户的所有对话线程共享工作记忆
- **线程范围**：各对话线程的工作记忆相互隔离

**注意：**切换范围后，Agent 不会看到另一范围的记忆；线程范围与资源范围的记忆完全独立。

## 快速入门 {/* #quickstart */}

以下是为 Agent 启用工作记忆的最小示例：

```typescript {11-15}
import { Agent } from '@mastra/core/agent'
import { Memory } from '@mastra/memory'

// Create agent with working memory enabled
const agent = new Agent({
  id: 'personal-assistant',
  name: 'PersonalAssistant',
  instructions: 'You are a helpful personal assistant.',
  model: '__GATEWAY_OPENAI_MODEL__',
  memory: new Memory({
    options: {
      workingMemory: {
        enabled: true,
      },
    },
  }),
})
```

## 工作原理 {/* #how-it-works */}

工作记忆是一段 Markdown 文本，Agent 可以随时间更新，保存持续相关的信息。

## 记忆的持久化范围 {/* #memory-persistence-scopes */}

工作记忆支持两种范围，你可以据此决定记忆如何跨对话保留：

### 资源范围的记忆（默认） {/* #resource-scoped-memory-default */}

默认情况下，工作记忆会跨同一用户（`resourceId`）的所有对话线程保留：

```typescript
const memory = new Memory({
  storage,
  options: {
    workingMemory: {
      enabled: true,
      scope: 'resource', // Memory persists across all user threads
      template: `# User Profile
- **Name**:
- **Location**:
- **Interests**:
- **Preferences**:
- **Long-term Goals**:
`,
    },
  },
})
```

**适用场景：**

- 记住用户偏好的个人助理
- 持续掌握客户背景的客服机器人
- 跟踪学生进度的教育应用

### 在 Agent 中使用 {/* #usage-with-agents */}

使用资源范围的记忆时，务必在记忆选项中传入 `resource` 参数：

```typescript
// Resource-scoped memory requires resource
const response = await agent.generate('Hello!', {
  memory: {
    thread: 'conversation-123',
    resource: 'user-alice-456', // Same user across different threads
  },
})
```

### 线程范围的记忆 {/* #thread-scoped-memory */}

线程范围的工作记忆仅用于单个对话线程。各线程都有独立的记忆：

```typescript
const memory = new Memory({
  storage,
  options: {
    workingMemory: {
      enabled: true,
      scope: 'thread', // Memory is isolated per thread
      template: `# User Profile
- **Name**:
- **Interests**:
- **Current Goal**:
`,
    },
  },
})
```

**适用场景：**

- 分别讨论不同主题的对话
- 临时或仅与当前会话有关的信息
- 每个线程都需要工作记忆、但线程短暂且互不关联的 Workflow

## 存储适配器支持 {/* #storage-adapter-support */}

资源范围的工作记忆要求存储适配器支持 `mastra_resources` 表：

### 支持的存储适配器 {/* #supported-storage-adapters */}

- **libSQL** (`@mastra/libsql`)
- **PostgreSQL** (`@mastra/pg`)
- **OracleDB** (`@mastra/oracledb`)
- **Upstash** (`@mastra/upstash`)
- **MongoDB** (`@mastra/mongodb`)

## 自定义模板 {/* #custom-templates */}

模板指引 Agent 在工作记忆中跟踪和更新哪些信息。未提供模板时，Mastra 使用默认模板。请根据 Agent 的用途定义自定义模板，使其记住最重要的信息。对于多人共享的线程，参阅[多用户线程](./multi-user-threads)。

下面的自定义模板示例会在用户消息包含相关信息后，让 Agent 保存姓名、位置、时区等内容：

```typescript {5-28}
const memory = new Memory({
  options: {
    workingMemory: {
      enabled: true,
      template: `
# User Profile

## Personal info

- Name:
- Location:
- Timezone:

## Preferences

- Communication Style: [e.g., Formal, Casual]
- Project Goal:
- Key Deadlines:
  - [Deadline 1]: [Date]
  - [Deadline 2]: [Date]

## Session state

- Last Task Discussed:
- Open Questions:
  - [Question 1]
  - [Question 2]
`,
    },
  },
})
```

## 设计有效的模板 {/* #designing-effective-templates */}

结构清晰的模板让 Agent 更易解析和更新信息。可以把模板看作需要由助理持续填写的简短表单。


- **标签简短且聚焦。**避免长段落或过长标题。使用 `## Personal Info` 或 `- Name:` 等短标签，使更新结果易读且不易被截断。
- **大小写一致。**`Timezone:` 与 `timezone:` 等不一致的写法会使更新结果混乱。标题和列表标签应统一使用标题式大小写或小写。

- **占位文本精简。**可用 `[e.g., Formal]` 或 `[Date]` 等提示，帮助 LLM 填写正确的位置。

- **过长的值适当缩写。**若只需要简短形式，可写成 `- Name: [First name or nickname]` 或 `- Address (short):`，而非要求完整的法定文本。
- **在 `instructions` 中说明更新规则。**可以直接在 Agent 的 `instructions` 字段中指明何时及如何填写或清除模板内容。


### 其他模板形式 {/* #alternative-template-styles */}

如果只需记录少数项目，可使用简短的单块模板：

```typescript
const basicMemory = new Memory({
  options: {
    workingMemory: {
      enabled: true,
      template: `User Facts:\n- Name:\n- Favorite Color:\n- Current Topic:`,
    },
  },
})
```

若偏好叙述式表达，也可以用简短段落保存关键事实：

```typescript
const paragraphMemory = new Memory({
  options: {
    workingMemory: {
      enabled: true,
      template: `Important Details:\n\nKeep a short paragraph capturing the user's important facts (name, main goal, current task).`,
    },
  },
})
```

## 结构化工作记忆 {/* #structured-working-memory */}

工作记忆也可使用结构化 schema，而非 Markdown 模板。例如 [Standard JSON Schema](https://standardschema.dev/json-schema)（[Zod](https://zod.dev/)、[Valibot](https://valibot.dev/)、[ArkType](https://arktype.io/) 等）。使用 schema 时，Agent 以符合该 schema 的 JSON 对象查看和更新工作记忆。

可以指定 `template` 或 `schema`，但不能同时指定。两者都省略时，Mastra 使用默认工作记忆模板。

### 示例：基于 schema 的工作记忆 {/* #example-schema-based-working-memory */}

```typescript
import { z } from 'zod'
import { Memory } from '@mastra/memory'

const userProfileSchema = z.object({
  name: z.string().optional(),
  location: z.string().optional(),
  timezone: z.string().optional(),
  preferences: z
    .object({
      communicationStyle: z.string().optional(),
      projectGoal: z.string().optional(),
      deadlines: z.array(z.string()).optional(),
    })
    .optional(),
})

const memory = new Memory({
  options: {
    workingMemory: {
      enabled: true,
      schema: userProfileSchema,
      // template: ... (do not set)
    },
  },
})
```

提供 schema 后，Agent 会以 JSON 对象接收工作记忆。例如：

```json
{
  "name": "Sam",
  "location": "Berlin",
  "timezone": "CET",
  "preferences": {
    "communicationStyle": "Formal",
    "projectGoal": "Launch MVP",
    "deadlines": ["2025-07-01"]
  }
}
```

### 基于 schema 的记忆合并语义 {/* #merge-semantics-for-schema-based-memory */}

基于 schema 的工作记忆采用**合并语义**：Agent 只需提供要新增或更新的字段，现有字段会自动保留。

- **对象字段深度合并：**仅更新提供的字段，其余字段保持不变。
- **将字段设为 `null` 即可删除：**该字段会明确地从记忆中移除。
- **数组整体替换：**提供数组字段时，将完全替换原数组，而非逐项合并。

### 并发更新 {/* #concurrent-updates */}

当 `scope: 'resource'` 搭配支持原子合并的存储适配器（目前为 `@mastra/pg`）时，每次合并都在锁定行的数据库事务中进行。来自不同进程、针对不同字段的并发更新都能保留。其他适配器在应用层合并，只会串行处理同一进程内的写入。

若要从自己的代码合并部分更新，请调用 `memory.mergeWorkingMemory()`：

```typescript
await memory.mergeWorkingMemory({
  threadId: 'thread-1',
  resourceId: 'user-123',
  workingMemory: { preferences: { tone: 'formal' } },
})
```

如果工作记忆并非基于 schema 且采用资源范围，或者存储适配器不支持原子合并，该方法会抛出错误。若需回退处理，请先检查 `await memory.supportsAtomicWorkingMemoryMerge()`。

## 在模板和模式之间进行选择 {/* #choosing-between-template-and-schema */}

- 如果希望 Agent 以用户资料或便笺等自由文本维护记忆，请使用 **template**（Markdown）。模板采用**替换语义**：Agent 每次更新都必须提供完整记忆内容。
- 如需支持验证和程序化访问的结构化、类型安全 JSON 数据，请使用 **schema**。`workingMemory.schema` 接受任何兼容 `PublicSchema` 的 schema，包括 Zod v3、v4；也支持 JSON Schema 及已符合标准的 schema。Agent 只提供要更新的字段时，**合并语义**会保留其余字段。
- 同一时间只能启用一种模式：不能同时设置 `template` 和 `schema`。

## 示例：多步骤保留 {/* #example-multi-step-retention */}

下方简要展示 `User Profile` 模板如何在一段简短对话中逐步更新：


```nohighlight
# User Profile

## Personal info

- Name:
- Location:
- Timezone:

--- After user says "My name is **Sam** and I'm from **Berlin**" ---

# User Profile
- Name: Sam
- Location: Berlin
- Timezone:

--- After user adds "By the way I'm normally in **CET**" ---

# User Profile
- Name: Sam
- Location: Berlin
- Timezone: CET
```

此后 Agent 可在后续回复中直接引用 `Sam` 或 `Berlin`，无需再次询问，因为这些信息已保存在工作记忆中。


如果 Agent 未按预期更新工作记忆，可在其 `instructions` 设置中增加系统指令，说明**如何**及**何时**使用该模板。


## 设置初始工作记忆 {/* #setting-initial-working-memory */}

虽然 Agent 通常通过 `updateWorkingMemory` Tool 更新工作记忆，你也可以在创建或更新线程时，以代码设置初始工作记忆。这样就能注入姓名、偏好等用户数据，而无须每次请求都再次传入。

### 通过线程元数据设置工作记忆 {/* #setting-working-memory-via-thread-metadata */}

创建线程时，可通过元数据中的 `workingMemory` 键提供初始工作记忆：

```typescript title="src/app/medical-consultation.ts"
// Create a thread with initial working memory
const thread = await memory.createThread({
  threadId: 'thread-123',
  resourceId: 'user-456',
  title: 'Medical Consultation',
  metadata: {
    workingMemory: `# Patient Profile
- Name: John Doe
- Blood Type: O+
- Allergies: Penicillin
- Current Medications: None
- Medical History: Hypertension (controlled)
`,
  },
})

// The agent will now have access to this information in all messages
await agent.generate("What's my blood type?", {
  memory: {
    thread: thread.id,
    resource: 'user-456',
  },
})
// Response: "Your blood type is O+."
```

### 以代码更新工作记忆 {/* #updating-working-memory-programmatically */}

也可以更新现有线程的工作记忆：

```typescript title="src/app/medical-consultation.ts"
// Update thread metadata to add/modify working memory
await memory.updateThread({
  id: 'thread-123',
  title: thread.title,
  metadata: {
    ...thread.metadata,
    workingMemory: `# Patient Profile
- Name: John Doe
- Blood Type: O+
- Allergies: Penicillin, Ibuprofen  // Updated
- Current Medications: Lisinopril 10mg daily  // Added
- Medical History: Hypertension (controlled)
`,
  },
})
```

### 直接更新记忆 {/* #direct-memory-update */}

也可以直接调用 `updateWorkingMemory` 方法：

```typescript title="src/app/medical-consultation.ts"
await memory.updateWorkingMemory({
  threadId: 'thread-123',
  resourceId: 'user-456', // Required for resource-scoped memory
  workingMemory: 'Updated memory content...',
})
```

## 只读工作记忆 {/* #read-only-working-memory */}

有时需要让 Agent 读取工作记忆，但不允许修改，例如：

- **路由 Agent**：需要上下文，但不应更新用户资料。
- **子 Agent**：在多 Agent 系统中需要查阅记忆，却不负责维护。

要启用只读模式，请在记忆选项中设置 `readOnly: true`：

```typescript
const response = await agent.generate('What do you know about me?', {
  memory: {
    thread: 'conversation-123',
    resource: 'user-alice-456',
    options: {
      readOnly: true, // Working memory is provided but cannot be updated
    },
  },
})
```

## 启用状态信号（实验性） {/* #opt-in-to-state-signals-experimental */}

默认情况下，工作记忆作为系统消息的一部分提供给模型。设置 `useStateSignals: true`，也可以选择将其作为[状态信号](/docs/signals/state-signals)传递：

```typescript
const memory = new Memory({
  storage: new LibSQLStore({ id: 'mastra-storage', url: 'file:./mastra.db' }),
  options: {
    workingMemory: {
      enabled: true,
      template: '# User\n- name:\n- location:',
      useStateSignals: true, // experimental: deliver as state signal
    },
  },
})
```

具体变化如下：

- **存储方式不变。**仍读写相同的资源或线程 `workingMemory` 字段。
- **Tool 结构不变，但使用新名称。**写入仍通过同一个底层 Tool；此路径将其注册为 `setWorkingMemory`（而非 `updateWorkingMemory`）。更名可避免旧版过滤器移除 Tool 调用片段，使其作为常规审计记录持久化，后续模型步骤也能自动读取新值。
- **仅改变传递方式。**`Memory` 不再把工作记忆并入系统提示词，而是自动附加 `WorkingMemoryStateProcessor`，以 `stateId: 'working-memory'` 发出当前工作记忆的 `state` 信号。

因此也能获得标准状态信号的优势：线程范围的跟踪元数据、通过 `cacheKey` 去重使相同快照只发出一次，以及旧快照离开上下文窗口后由 `contextWindow.hasSnapshot` 重新注入。

默认值 `useStateSignals: false` 维持现有系统消息行为。模板式工作记忆的 `version: 'vnext'` 不支持 `useStateSignals`。
