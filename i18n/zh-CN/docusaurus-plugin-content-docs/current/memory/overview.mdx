# 记忆

内存使您的Agent可以访问早期的消息和Tool结果。Agent可以使用此上下文来回答后续问题并回忆以前交互中的信息。

MastraAgent可以配置为存储[message history](/docs/memory/message-history). Additionally, you can enable:

* [观察记忆](../memory/observational-memory)（推荐）：使用后台Agent来维护密集的观察日志，随着原始消息历史记录的增长而替换它。这可以使上下文窗口保持较小，同时保留长期记忆。
* [工作记忆](../memory/working-memory)：存储有关用户、应用程序或任务的持久结构化信息，例如名称、首选项和目标。
* [多用户线程](../memory/multi-user-threads)：在多个用户之间共享一个线程。

如果组合内存超出模型的上下文限制，[memory processors](/docs/memory/memory-processors) can filter, trim, or prioritize content so the most relevant information is preserved.

内存结果将存储在您配置的一个或多个[storage providers](/docs/storage).

:::提示\[📹观看]

手表[Mastra memory concepts](https://www.youtube.com/watch?v=18iIHQtIPmc) for a conceptual overview of the memory layers agents can use.

:::

## 何时使用内存 {/* #when-to-use-memory */}

当您的Agent需要维护引用先前交换的多轮对话或回忆会话早期的用户偏好或事实，或者随着时间的推移在对话线程中构建上下文时，请使用内存。跳过单轮请求的内存，其中每个交互都是独立的。

## 消息记录 {/* #message-history */}

通过一个`memory` object with `resource` and `thread` to track message history.

* `resource`：用户或实体的稳定标识符。
* `thread`：隔离特定对话或会话的 ID。

```typescript {2-5}
const response = await memoryAgent.generate('Remember my favorite color is blue.', {
  memory: {
    resource: 'user-123',
    thread: 'conversation-123',
  },
})
```

要调用存储在内存中的信息，请使用相同的信息致电客服人员`resource` and `thread` values used in the original conversation.

```typescript {2-5}
const response = await memoryAgent.generate("What's my favorite color?", {
  memory: {
    resource: 'user-123',
    thread: 'conversation-123',
  },
})

// Response: "Your favorite color is blue."
```

：：：警告

每个线程都有一个所有者（`resourceId`) that can't be changed after creation. Avoid reusing the same thread ID for threads with different owners, as this will cause errors when querying.

:::

要列出资源的所有线程，或检索特定线程，[use the memory API directly](/docs/memory/message-history#querying).

### 使用范围识别内存 {/* #identify-memory-with-scopes */}

而不是一个`memory` object, you can pass `scopes`: the addresses a run acts as, written as `<type>:<value>`. Memory reads the resource from a `resource:` scope and the thread from a `thread:` scope. Other scopes, such as `org:acme`, are passed to tools and processors.

```typescript {2}
const response = await memoryAgent.generate('Remember my favorite color is blue.', {
  scopes: ['org:acme', 'resource:user-123', 'thread:conversation-123'],
})
```

范围也可以来自请求上下文和Agent。调用范围和请求上下文首先到达。Agent的`scopes` option then adds a list to them, or a function receives them and returns the run's final set:

```typescript title="src/mastra/agents/memory-agent.ts" {7-11}
import { Agent } from '@mastra/core/agent'
import { Memory } from '@mastra/memory'

export const memoryAgent = new Agent({
  id: 'memory-agent',
  name: 'Memory Agent',
  scopes: ({ scopes, requestContext }) => {
    // Set by your auth middleware. Request bodies can fill unreserved keys.
    const orgId = requestContext.get('org-id')
    return orgId ? [...scopes, `org:${orgId}`] : scopes
  },
  memory: new Memory(),
})
```

解析器的输入必须来自服务器，而不是客户端：请求正文可以设置任何未保留的请求上下文键。受信任的服务器中间件还可以直接使用`MASTRA_SCOPES_KEY` request context key. Visit [Request Context](/docs/server/request-context#reserved-keys) for details. Clients can't send scopes in a request body.

您可以将范围与`memory.resource`, `memory.thread`, or the resource and thread request context keys, as long as they agree. If a `resource:` or `thread:` scope names a different value than another source, the call throws an error. A `scopes` function must also return every `resource:` and `thread:` scope it receives. Dropping one throws an error.

Tool、处理器和子Agent接收运行的其他范围，但不接收其范围`resource:` and `thread:` scopes. Each nested agent call picks its own resource and thread.

## 观察记忆 {/* #observational-memory */}

长对话可能会用原始消息历史记录填充上下文窗口并降低Agent性能。[Observational Memory](../memory/observational-memory) uses background agents to compress older messages into observations. This reduces the context used by message history while retaining information for later turns.

压缩会丢失精确的措辞，因此观察记忆可以注册一个`recall` tool that goes back to the original messages. The tool is off by default: set `retrieval: true` to enable browsing, which lists earlier messages across the resource's threads unless you pass `scope: 'thread'`. With `retrieval: { vector: true }` plus a vector store and embedder on `Memory`, it can also search by meaning. That search matches observation groups rather than raw messages, so a detail the summary dropped may not turn up, and each hit links back to the messages it came from. See [retrieval mode](../memory/observational-memory#retrieval-mode).

<Inject>
  **对于人工智能Agent：**&#x4F7F;用观察记忆需要存储Provider！您需要在 Mastra 实例上将其设置为`src/mastra/index.ts` or pass it to the Agent constructor.
</Inject>

```typescript title="src/mastra/agents/memory-agent.ts"
import { Agent } from '@mastra/core/agent'
import { Memory } from '@mastra/memory'

export const memoryAgent = new Agent({
  id: 'memory-agent',
  name: 'Memory Agent',
  instructions: 'You are a helpful assistant.',
  model: '__GATEWAY_OPENAI_MODEL_LUNA__',
  memory: new Memory({
    options: {
      // highlight-next-line
      observationalMemory: true,
    },
  }),
})
```

观察记忆需要一个支持它的存储适配器，如果使用任何其他适配器，它会在没有警告的情况下关闭，并且不会加载存储的历史记录。

看[Observational Memory](../memory/observational-memory) for details on how observations and reflections work, and [the reference](/reference/memory/observational-memory) for all configuration options.

## 模型看到了什么 {/* #what-the-model-sees */}

内存将上下文添加到发送到模型的系统消息或对话消息中。默认情况下启用消息历史记录。其他内存功能仅在配置时才提供上下文。该图显示了每个功能添加其上下文的位置，下面的列表解释了它的贡献：

<MemoryContextWindowImage />

* [工作记忆](../memory/working-memory)作为包含模板和存储数据的系统消息注入。和`useStateSignals`, it's delivered as a state signal instead.
* [语义回忆](../memory/semantic-recall)当前线程中的匹配项将作为常规消息插入，并按时间戳与消息历史记录交错。来自其他线程的匹配会被格式化为系统消息。
* [消息记录](../memory/message-history)按时间顺序添加最后 N 条消息。您的新消息总是最后出现。
* [观察记忆](../memory/observational-memory)取代旧的原始历史记录：反思和观察存在于系统消息中，只有尚未观察到的消息才会保留在对话中。在对话消息的开头放置一个简短的继续提醒。
* 上下文消息是可选的`context` array passed on a call, for example `agent.generate(msg, { context: [...] })`. Use them for one-off background such as app state or your own RAG results. They appear as regular conversation messages for that request only and are never saved to memory.

对话消息按时间戳排序，并按消息 ID 进行重复数据删除，因此调用的较旧消息会出现在最近历史记录之前。在呼叫时传递的上下文消息会标有当前时间，这将它们放置在历史记录和调用之后但在新消息之前。要检查真实请求的确切上下文，请使用[Tracing](/docs/observability/tracing/overview) and open the LLM call spans, see [Observability](#observability) below.

## 多智能体系统中的内存 {/* #memory-in-multi-agent-systems */}

当一个[supervisor agent](/docs/subagents) delegates to a subagent, Mastra isolates subagent memory automatically. No flag enables this as it happens on every delegation. Understanding how this scoping works lets you decide what stays private and what to share intentionally.

### 委托如何确定内存范围 {/* #how-delegation-scopes-memory */}

每个代表团都创造了一个新的`threadId` and a deterministic `resourceId` for the subagent:

* **线程ID**：每个代表团都是唯一的。每次调用子Agent时都会以干净的消息历史记录开始。
* **资源ID**: 推导为`{parentResourceId}-{agentName}`. Because the resource ID is stable across delegations, resource-scoped memory persists between calls. A subagent remembers facts from previous delegations by the same user.
* **内存实例**：没有自己记忆的子Agent继承了主管的记忆`Memory` instance and all configured options. If the subagent defines its own, that takes precedence.

：：：笔记

标题生成（`generateTitle`) is a top-level thread concern and **isn't** applied to inherited subagent threads. Because each delegation creates an ephemeral thread that no one sees, running title generation for it would waste an LLM call per delegation. To generate titles for a subagent's own threads, give that subagent its own memory configuration.

:::

主管将其对话上下文转发给子Agent，以便它有足够的背景来完成任务。仅保存委托提示和子Agent的响应。不存储完整的家长对话。您可以使用以下命令控制哪些消息到达子Agent[`messageFilter`](/docs/subagents#message-filtering) callback.

：：：笔记

子Agent资源 ID 始终以Agent名称作为后缀 (`{parentResourceId}-{agentName}`). Different subagents under the same supervisor never share a resource ID through delegation.

:::

为了超越这种默认隔离，您可以在直接调用Agent时通过传递匹配标识符来在Agent之间共享内存。

### 在Agent之间共享内存 {/* #share-memory-between-agents */}

当您直接调用Agent（在委托流程之外）时，内存共享由两个标识符控制：`resourceId` and `threadId`. Agents that use the same values read and write to the same data. This is useful when agents collaborate on a shared context, for example, a researcher that saves notes and a writer that reads them.

**资源范围共享**是最常见的模式。[Working memory](../memory/working-memory) and [semantic recall](../memory/semantic-recall) default to `scope: 'resource'`. If two agents share a `resourceId`, they share working memory and embeddings, even across different threads:

```typescript
// Both agents share the same resource-scoped memory
await researcher.generate('Find information about quantum computing.', {
  memory: { resource: 'project-42', thread: 'research-session' },
})

await writer.generate('Write a summary from the research notes.', {
  memory: { resource: 'project-42', thread: 'writing-session' },
})
```

因为两个调用都使用`resource: 'project-42'`, the writer can access the researcher's working memory. Semantic embeddings are also shared through the resource. Each agent still has its own thread, so message histories stay separate.

**线程范围的共享**提供更紧密的耦合。[Observational Memory](../memory/observational-memory) uses `scope: 'thread'` by default. If two agents use the same `resource` and `thread`, they share the full message history. Each agent sees every message the other has written. This is useful when agents need to build on each other's exact outputs.

## 可观察性 {/* #observability */}

使能够[Tracing](/docs/observability/tracing/overview) to monitor and debug memory in action. Traces show you exactly which messages and observations the agent included in its context for each request, helping you understand agent behavior and verify that memory retrieval is working as expected.

打开[Studio](/docs/studio/overview) and select the **Observability** tab in the sidebar. Open the trace of a recent agent request and look for its LLM call spans.

## 根据请求切换内存 {/* #switch-memory-per-request */}

使用[`RequestContext`](/docs/server/request-context) to access request-specific values. This lets you conditionally select different memory or storage configurations based on the context of the request.

```typescript title="src/mastra/agents/memory-agent.ts"
import { Agent } from '@mastra/core/agent'
import { Memory } from '@mastra/memory'

export type UserTier = {
  'user-tier': 'enterprise' | 'pro'
}

const premiumMemory = new Memory()
const standardMemory = new Memory()

export const memoryAgent = new Agent({
  id: 'memory-agent',
  name: 'Memory Agent',
  memory: ({ requestContext }) => {
    const userTier = requestContext.get('user-tier') as UserTier['user-tier']

    return userTier === 'enterprise' ? premiumMemory : standardMemory
  },
})
```

访问[Request Context](/docs/server/request-context) for more information.

<Inject>
  **对于人工智能Agent：**&#x89C2;察记忆有一些会导致实际问题的故障模式。

  * 线程作用域需要一个`threadId` when you call the agent. Without one, Observational Memory throws.
  * 在现有线程上，第一轮加载每个存储的消息，直到第一个观察完成。大线程会付出一次性上下文成本。
  * `lastMessages`在观察记忆下不执行任何操作。它取代了原始历史记录本身，因此跳过了 MessageHistory 处理器。
  * 离开`observation.observeOnContextOverflow` at its default `true`. When the main model's context overflows, it can activate buffered observations, observe pending messages, and retry the request. It skips read-only requests and only retries when it observed or activated something. With it off, the overflowing request fails.
  * 一些无效选项在第一次使用时验证，而不是在构建时验证`Memory`. For example, `shareTokenBudget: true` with async buffering enabled fails on the first memory operation. Read the error instead of retrying.
  * 通过异步缓冲，工作在后台继续进行。称呼`await memory.settled()` before closing storage or shutting down, or that work is lost.
  * 观察互斥锁仅在一个进程内起作用。跨进程，协调来自共享的 PubSub 后端和存储：Agent循环使用带有租约的后端来为每个线程运行一个循环，而观察者在该循环内运行。使用具有租约和相同存储的相同后端配置每个进程。看[Running across processes](/docs/signals/running-across-processes).
  * 调试用`OM_DEBUG=1`, which writes `om-debug.log`, plus `getStatus()` and the `onDebugEvent` callback.
</Inject>
