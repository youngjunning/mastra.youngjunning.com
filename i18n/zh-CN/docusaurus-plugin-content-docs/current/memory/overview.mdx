# 记忆

记忆让 Agent 能访问先前的消息和 Tool 结果，以便回答后续问题，并回忆此前交互中的信息。

Mastra Agent 可以配置为保存[消息历史](/docs/memory/message-history)。此外，你还可以启用：

* [观察记忆](../memory/observational-memory)（推荐）：后台 Agent 会持续维护精简的观察日志，并随着消息历史增长取代原始消息。这样既能缩小上下文窗口占用，也能保留长期记忆。
* [工作记忆](../memory/working-memory)：存储有关用户、应用程序或任务的持久结构化信息，例如名称、首选项和目标。
* [多用户线程](../memory/multi-user-threads)：在多个用户之间共享一个线程。

如果组合后的记忆超过模型的上下文限制，[记忆处理器](/docs/memory/memory-processors)可过滤、裁剪或按优先级选择内容，以保留最相关的信息。

记忆结果会保存在你配置的一个或多个[存储 Provider](/docs/storage) 中。

:::tip[📹 观看]

观看 [Mastra 记忆概念](https://www.youtube.com/watch?v=18iIHQtIPmc)，了解 Agent 可使用的各层记忆。

:::

## 何时使用记忆 {/* #when-to-use-memory */}

当 Agent 需要在多轮对话中引用之前的交流、回忆本次会话早期的用户偏好或事实，或在同一对话线程中逐步积累上下文时，使用记忆。对于每次交互都相互独立的单轮请求，则无需使用。

## 快速入门 {/* #quickstart */}

<Steps>
  <StepItem>
    安装 `@mastra/memory` 包。

    ```bash npm2yarn
    npm install @mastra/memory@latest
    ```
  </StepItem>

  <StepItem>
    记忆**需要**存储 Provider，才能持久保存用户消息和 Agent 响应等消息历史。

    本快速入门使用 `@mastra/libsql`。

    ```bash npm2yarn
    npm install @mastra/libsql@latest
    ```

    如需了解可用的 Provider 及 Mastra 的存储方式，请参阅[存储文档](/docs/storage)。
  </StepItem>

  <StepItem>
    将存储 Provider 添加到主要 Mastra 实例，即可为所有已配置的 Agent 启用记忆。

    <Inject>
      **对于 AI Agent：**重要：为 `LibSQLStore` 添加 `id`。
    </Inject>

    ```typescript {2,5-8} title="src/mastra/index.ts"
    import { Mastra } from '@mastra/core'
    import { LibSQLStore } from '@mastra/libsql'

    export const mastra = new Mastra({
      storage: new LibSQLStore({
        id: 'mastra-storage',
        url: ':memory:',
      }),
    })
    ```
  </StepItem>

  <StepItem>
    创建 `Memory` 实例，并将其传入 Agent 的 `memory` 选项。

    ```typescript {2,7-11} title="src/mastra/agents/memory-agent.ts"
    import { Agent } from '@mastra/core/agent'
    import { Memory } from '@mastra/memory'

    export const memoryAgent = new Agent({
      id: 'memory-agent',
      name: 'Memory Agent',
      memory: new Memory({
        options: {
          lastMessages: 20,
        },
      }),
    })
    ```

    如需查看完整的配置选项，请参阅 [Memory 类参考](/reference/memory/memory-class)。
  </StepItem>

  <StepItem>
    调用 Agent，例如在 [Studio](/docs/studio/overview) 中。打开与 Agent 的新对话，查看右侧边栏，其中会显示记忆详情。
  </StepItem>
</Steps>

## 消息记录 {/* #message-history */}

传入包含 `resource` 和 `thread` 的 `memory` 对象，以追踪消息历史。

* `resource`：用户或实体的稳定标识符。
* `thread`：隔离特定对话或会话的 ID。

```typescript {2-5}
const response = await memoryAgent.generate('Remember my favorite color is blue.', {
  memory: {
    resource: 'user-123',
    thread: 'conversation-123',
  },
})
```

要取回记忆中保存的信息，请使用原对话相同的 `resource` 和 `thread` 值调用 Agent。

```typescript {2-5}
const response = await memoryAgent.generate("What's my favorite color?", {
  memory: {
    resource: 'user-123',
    thread: 'conversation-123',
  },
})

// Response: "Your favorite color is blue."
```

:::warning

每个线程都有一个所有者（`resourceId`），创建后无法更改。不要为不同所有者的线程重复使用同一个线程 ID，否则查询时会出错。

:::

要列出某个资源的所有线程或获取特定线程，请[直接使用记忆 API](/docs/memory/message-history#querying)。

### 使用范围识别内存 {/* #identify-memory-with-scopes */}

除了 `memory` 对象，也可以传入 `scopes`：运行所代表的作用域地址，格式为 `<type>:<value>`。Memory 从 `resource:` 作用域读取资源，从 `thread:` 作用域读取线程。`org:acme` 等其他作用域则传给 Tool 和处理器。

```typescript {2}
const response = await memoryAgent.generate('Remember my favorite color is blue.', {
  scopes: ['org:acme', 'resource:user-123', 'thread:conversation-123'],
})
```

作用域也可以来自请求上下文和 Agent。调用及请求上下文中的作用域会先传入；随后，Agent 的 `scopes` 选项会追加列表，或通过函数接收这些作用域并返回本次运行最终使用的集合：

```typescript title="src/mastra/agents/memory-agent.ts" {7-11}
import { Agent } from '@mastra/core/agent'
import { Memory } from '@mastra/memory'

export const memoryAgent = new Agent({
  id: 'memory-agent',
  name: 'Memory Agent',
  scopes: ({ scopes, requestContext }) => {
    // Set by your auth middleware. Request bodies can fill unreserved keys.
    const orgId = requestContext.get('org-id')
    return orgId ? [...scopes, `org:${orgId}`] : scopes
  },
  memory: new Memory(),
})
```

解析函数的输入必须来自服务器，而不是客户端：请求体可设置任何非保留的请求上下文键。受信任的服务器中间件也可通过 `MASTRA_SCOPES_KEY` 请求上下文键直接设置作用域。详情请参阅[请求上下文](/docs/server/request-context#reserved-keys)。客户端不能在请求体中发送作用域。

作用域可以与 `memory.resource`、`memory.thread` 或请求上下文中的资源及线程键同时使用，但各处的值必须一致。如果 `resource:` 或 `thread:` 作用域与其他来源的值不同，调用会报错。`scopes` 函数也必须返回它收到的所有 `resource:` 和 `thread:` 作用域；漏掉任何一个都会报错。

Tool、处理器和子 Agent 会收到本次运行的其他作用域，但不会收到 `resource:` 和 `thread:` 作用域。每次嵌套的 Agent 调用都会选择自己的资源和线程。

## 观察记忆 {/* #observational-memory */}

长对话可能使原始消息历史占满上下文窗口，降低 Agent 性能。[观察记忆](../memory/observational-memory)利用后台 Agent 将较早的消息压缩为观察记录，在保留供后续轮次使用的信息的同时，减少消息历史占用的上下文。

压缩会丢失原文措辞，因此观察记忆可以注册 `recall` Tool，回查原始消息。该 Tool 默认关闭：设置 `retrieval: true` 可启用浏览，列出该资源所有线程中的较早消息；传入 `scope: 'thread'` 则仅限当前线程。若在 `Memory` 上配置向量存储和 embedder，并设置 `retrieval: { vector: true }`，还可按语义搜索。搜索匹配的是观察组而非原始消息，因此摘要遗漏的细节可能无法检索；每条结果都会链接到其来源消息。参阅[检索模式](../memory/observational-memory#retrieval-mode)。

<Inject>
  **对于 AI Agent：**使用观察记忆必须配置存储 Provider！可以在 `src/mastra/index.ts` 的 Mastra 实例上设置，也可以传给 Agent 构造函数。
</Inject>

```typescript title="src/mastra/agents/memory-agent.ts"
import { Agent } from '@mastra/core/agent'
import { Memory } from '@mastra/memory'

export const memoryAgent = new Agent({
  id: 'memory-agent',
  name: 'Memory Agent',
  instructions: 'You are a helpful assistant.',
  model: '__GATEWAY_OPENAI_MODEL_LUNA__',
  memory: new Memory({
    options: {
      // highlight-next-line
      observationalMemory: true,
    },
  }),
})
```

观察记忆需要支持该功能的存储适配器；使用其他适配器时，它会在没有警告的情况下关闭，已保存的历史消息也不会加载。

观察与反思的工作方式详见[观察记忆](../memory/observational-memory)；完整配置选项请参阅[参考文档](/reference/memory/observational-memory)。

## 模型看到了什么 {/* #what-the-model-sees */}

记忆会向发送给模型的系统消息或对话消息添加上下文。消息历史默认启用；其他记忆功能仅在配置后才会提供上下文。下图展示各功能添加上下文的位置，随后列表说明具体内容：

<MemoryContextWindowImage />

- [工作记忆](../memory/working-memory)会作为包含模板和已存数据的系统消息注入。启用 `useStateSignals` 时，则改以状态信号传递。
- [语义召回](../memory/semantic-recall)在当前线程匹配的内容会作为普通消息插入，并按时间戳与消息历史交错排列。其他线程的匹配结果则会整理成系统消息。
- [消息历史](../memory/message-history)按时间顺序加入最近 N 条消息。新的用户消息始终排在最后。
- [观察记忆](../memory/observational-memory)取代较早的原始消息历史：反思和观察记录位于系统消息中，对话只保留尚未观察的消息。简短的续接提示会放在对话消息开头。
- 上下文消息是调用时传入的可选 `context` 数组，例如 `agent.generate(msg, { context: [...] })`。它适用于应用状态或自有 RAG 结果等单次背景信息，仅在本次请求中作为普通对话消息出现，不会保存到记忆。

对话消息按时间戳排序，并按消息 ID 去重，因此召回的旧消息会出现在较新的历史消息之前。调用时传入的上下文消息会标记当前时间，位于历史及召回消息之后、新消息之前。要查看真实请求的确切上下文，可在[追踪](/docs/observability/tracing/overview)中打开 LLM 调用 span；参见下方的[可观测性](#observability)。

## 多智能体系统中的内存 {/* #memory-in-multi-agent-systems */}

当[主管 Agent](/docs/subagents) 将任务委派给子 Agent 时，Mastra 会自动隔离子 Agent 的记忆。每次委派都会这样处理，无需启用任何开关。了解作用域规则，有助于决定哪些信息应保持隔离、哪些可以主动共享。

### 委托如何确定内存范围 {/* #how-delegation-scopes-memory */}

每次委派都会为子 Agent 创建新的 `threadId`，并生成确定性的 `resourceId`：

- **线程 ID**：每次委派都唯一。子 Agent 每次被调用时都会从空白消息历史开始。
- **资源 ID**：按 `{parentResourceId}-{agentName}` 派生。由于资源 ID 在多次委派之间保持稳定，资源作用域的记忆可跨调用持续存在；子 Agent 能记住同一用户此前委派中的事实。
- **Memory 实例**：没有自有记忆配置的子 Agent 会继承主管的 `Memory` 实例及其全部选项。若子 Agent 定义了自己的配置，则以其自身配置为准。

:::note

标题生成（`generateTitle`）只适用于顶层线程，**不会**应用于继承记忆配置的子 Agent 线程。每次委派都会创建无人查看的临时线程，为其生成标题会在每次委派时浪费一次 LLM 调用。如果需要为子 Agent 自己的线程生成标题，应给它单独配置记忆。

:::

主管会将对话上下文转给子 Agent，使其有足够背景完成任务。只保存委派提示和子 Agent 的响应，不存储完整的父 Agent 对话。你可以通过 [`messageFilter`](/docs/subagents#message-filtering) 回调控制传给子 Agent 的消息。

:::note

子 Agent 的资源 ID 始终以 Agent 名称作为后缀（`{parentResourceId}-{agentName}`）。同一主管下的不同子 Agent 不会通过委派共享资源 ID。

:::

若要突破默认隔离，可在直接调用 Agent 时传入相同的标识符，让它们共享记忆。

### 在Agent之间共享内存 {/* #share-memory-between-agents */}

直接调用 Agent（不经过委派流程）时，记忆共享由 `resourceId` 和 `threadId` 两个标识符控制。使用相同值的 Agent 会读写同一份数据，例如研究 Agent 保存笔记、写作 Agent 读取笔记。

**资源作用域共享**最常见。[工作记忆](../memory/working-memory)和[语义召回](../memory/semantic-recall)默认使用 `scope: 'resource'`。两个 Agent 只要共享 `resourceId`，即使处于不同线程，也会共享工作记忆和嵌入向量：

```typescript
// Both agents share the same resource-scoped memory
await researcher.generate('Find information about quantum computing.', {
  memory: { resource: 'project-42', thread: 'research-session' },
})

await writer.generate('Write a summary from the research notes.', {
  memory: { resource: 'project-42', thread: 'writing-session' },
})
```

由于两次调用都使用 `resource: 'project-42'`，写作 Agent 能访问研究 Agent 的工作记忆，语义嵌入向量也通过资源共享。两个 Agent 仍各有自己的线程，因此消息历史彼此独立。

**线程作用域共享**会使 Agent 更紧密地协作。[观察记忆](../memory/observational-memory)默认使用 `scope: 'thread'`。如果两个 Agent 使用相同的 `resource` 和 `thread`，便会共享完整消息历史，互相看到对方写入的每条消息。这适用于需要直接接续对方具体输出的场景。

## 可观察性 {/* #observability */}

启用[追踪](/docs/observability/tracing/overview)以监控和调试记忆功能。Trace 会显示 Agent 每次请求实际纳入上下文的消息和观察记录，帮助理解 Agent 行为，并确认记忆检索是否如预期工作。

打开 [Studio](/docs/studio/overview)，选择侧边栏中的 **Observability** 标签页。打开最近一次 Agent 请求的 Trace，查看其中的 LLM 调用 span。

## 根据请求切换内存 {/* #switch-memory-per-request */}

使用 [`RequestContext`](/docs/server/request-context) 获取请求专属的值，即可根据请求上下文有条件地选择不同的记忆或存储配置。

```typescript title="src/mastra/agents/memory-agent.ts"
import { Agent } from '@mastra/core/agent'
import { Memory } from '@mastra/memory'

export type UserTier = {
  'user-tier': 'enterprise' | 'pro'
}

const premiumMemory = new Memory()
const standardMemory = new Memory()

export const memoryAgent = new Agent({
  id: 'memory-agent',
  name: 'Memory Agent',
  memory: ({ requestContext }) => {
    const userTier = requestContext.get('user-tier') as UserTier['user-tier']

    return userTier === 'enterprise' ? premiumMemory : standardMemory
  },
})
```

更多信息请参阅[请求上下文](/docs/server/request-context)。

<Inject>
  **对于 AI Agent：**观察记忆有几种可能造成实际问题的故障情况。

  - 线程作用域要求调用 Agent 时提供 `threadId`；否则观察记忆会报错。
  - 对现有线程，首轮会加载所有已存消息，直到首次观察完成。大型线程因此会承担一次性的上下文成本。
  - 启用观察记忆后，`lastMessages` 不起作用。观察记忆会自行取代原始消息历史，因此会跳过 MessageHistory 处理器。
  - 保持 `observation.observeOnContextOverflow` 的默认值 `true`。主模型上下文溢出时，它可激活缓冲的观察记录、观察待处理消息并重试请求。它会跳过只读请求，且仅在完成观察或激活后才重试。关闭后，溢出的请求会失败。
  - 某些无效选项要到首次使用时才验证，而非构造 `Memory` 时。例如启用异步缓冲时设置 `shareTokenBudget: true`，会在首次记忆操作时报错。请阅读错误信息，不要直接重试。
  - 异步缓冲会在后台继续工作。关闭存储或停止服务前，请调用 `await memory.settled()`，否则这些工作会丢失。
  - 观察锁仅在单个进程内有效。跨进程协调依靠共享的 PubSub 后端和存储：Agent 循环使用支持租约的后端，保证每个线程只有一个循环运行，Observer 则在该循环中运行。所有进程都应配置相同的支持租约的后端及相同的存储。参阅[跨进程运行](/docs/signals/running-across-processes)。
  - 使用 `OM_DEBUG=1` 进行调试；它会写入 `om-debug.log`。还可使用 `getStatus()` 和 `onDebugEvent` 回调。
</Inject>
