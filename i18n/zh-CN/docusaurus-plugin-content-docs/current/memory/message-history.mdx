# 消息历史

消息历史是最基础也最重要的记忆形式。它让 LLM 在上下文窗口中看到近期消息，使 Agent 能引用先前对话并连贯地回应。

也可以检索消息历史，在界面中显示过去的对话。

:::note
每条消息都属于一个线程（即一段对话）和一个资源（关联的用户或其他实体）。详见[线程与资源](#threads-and-resources)。
:::

## 线程与资源 {/* #threads-and-resources */}

Mastra 使用两个标识符组织对话：

- **线程**：包含一系列消息的对话会话。
- **资源**：拥有线程的实体，例如用户、组织、项目或应用中的其他领域实体。

Studio 会自动生成线程 ID 和资源 ID。自行调用 `stream()` 或 `generate()` 时，请明确传入这两个标识符。

## 开始使用 {/* #getting-started */}

安装 Mastra 记忆模块和适用于数据库的[存储适配器](/docs/storage#supported-providers)。下例使用 `@mastra/libsql`，将数据保存在本地 `mastra.db` 文件。

```bash npm2yarn
npm install @mastra/memory@latest @mastra/libsql@latest
```

消息历史需要存储适配器来持久化对话。如果尚未配置，请为 Mastra 实例设置存储：

```typescript title="src/mastra/index.ts"
import { Mastra } from '@mastra/core'
import { LibSQLStore } from '@mastra/libsql'

export const mastra = new Mastra({
  storage: new LibSQLStore({
    id: 'mastra-storage',
    url: 'file:./mastra.db',
  }),
})
```

在 Agent 中实例化 [`Memory`](/reference/memory/memory-class)：

```typescript title="src/mastra/agents/test-agent.ts"
import { Memory } from '@mastra/memory'
import { Agent } from '@mastra/core/agent'

export const agent = new Agent({
  id: 'test-agent',
  memory: new Memory({
    options: {
      lastMessages: 10,
    },
  }),
})
```

调用 Agent 时，消息会自动保存到数据库。你可以指定 `threadId`、`resourceId` 及可选的 `metadata`：

<Tabs>
  <TabItem value="generate" label=".generate()">
    ```typescript
    await agent.generate('Hello', {
      memory: {
        thread: {
          id: 'thread-123',
          title: 'Support conversation',
          metadata: { category: 'billing' },
        },
        resource: 'user-456',
      },
    })
    ```
  </TabItem>

  <TabItem value="stream" label=".stream()">
    ```typescript
    await agent.stream('Hello', {
      memory: {
        thread: {
          id: 'thread-123',
          title: 'Support conversation',
          metadata: { category: 'billing' },
        },
        resource: 'user-456',
      },
    })
    ```
  </TabItem>
</Tabs>

:::note

调用 `agent.generate()` 或 `agent.stream()` 时，系统会自动创建线程和消息。也可以通过 [`createThread()`](/reference/memory/createThread) 和 [`saveMessages()`](/reference/memory/memory-class) 手动创建。

:::

消息历史有两种用法：

- **自动纳入上下文**：Mastra 会自动把近期消息加入上下文窗口。默认保留 10 条消息，让 Agent 了解当前对话；需要时可通过 `lastMessages` 调整。
- [**手动查询**](#querying)：使用 `recall()` 直接查询线程和消息，以更精确地决定哪些记忆进入上下文窗口，或在界面中展示对话历史。

:::note

`lastMessages` 统计所有已存储消息，包括 Tool 调用、Tool 结果及各种[信号](/docs/signals/sending-signals)，因此一个对话回合可能增加多条消息。窗口也会随每次请求向前移动：线程超过上限后，每回合都会有最早的消息离开上下文，改变提示词的开头，使 Provider 提示词缓存失效。对于长对话，可使用能保持提示词前缀稳定的 [Observational Memory](/docs/memory/observational-memory)。

:::

### 从客户端发送消息 {/* #sending-messages-from-a-client */}

客户端使用记忆时，**只发送新消息**，不要传入完整的对话历史。Mastra 会从存储中加载之前的消息。

AI SDK 示例参阅[使用 Mastra Memory](/integrations/agentic-ui/ai-sdk-ui#using-mastra-memory)。

<details>
  <summary>传入完整的输入历史</summary>

  Mastra 会在加载已存储消息前，过滤客户端回传的历史。消息 ID 匹配时，它以已存储副本为基础，保留时间戳和 Provider 元数据，同时纳入新的 Tool 结果。

  如果由你自行组装请求输入，且需要完全按原样处理，可在本次调用的 `memory.options` 中设置 `retainFullInput: true`，或在记忆构造选项中设置，使其对整个 Agent 生效。这会禁用输入过滤，但仍会加载已存储历史。每条尚未存储的输入消息都会保存到线程中，包括少样本示例。
</details>

### 按 token 数量限制历史 {/* #limit-history-by-tokens */}

消息条数并不能准确反映上下文大小：一个 Tool 结果可能只有几个 token，也可能有数千个。可使用 `messageHistory`，让近期历史保持在 token 预算内：

```typescript title="src/mastra/agents/test-agent.ts"
import { Agent } from '@mastra/core/agent'
import { Memory } from '@mastra/memory'

export const agent = new Agent({
  id: 'test-agent',
  memory: new Memory({
    options: {
      messageHistory: { maxTokens: 8_000, atMaxRemoveTokens: 2_000 },
    },
  }),
})
```

Mastra 将完整提示词计入 `maxTokens`，包括记忆中的历史、系统指令、上下文和当前回合。超出预算时，Mastra 会从最早的记忆消息开始删除，直到提示词不超过 `maxTokens - atMaxRemoveTokens`。`atMaxRemoveTokens` 默认为 `maxTokens` 的 25%。分批移除历史可使提示词前缀在多个回合中保持稳定，有利于复用 Provider 提示词缓存。

系统消息、上下文、当前回合的输入及 Agent 响应不会被裁剪。关联的 Tool 调用和结果会一起移除。如果这些受保护内容本身超过 `maxTokens`，Mastra 会删除全部记忆历史，但仍保留受保护内容。

裁剪掉的消息仍保留在存储中。Agent 运行时，Mastra 会为每个线程持久化一个边界，使这些消息不再进入后续回合。只设置 `messageHistory` 而不设置 `lastMessages`，会停用默认的 10 条消息上限；两者都设置可同时限制条数和 token 数。将 `maxTokens` 设为 `0` 可停用消息历史。

:::tip

启用记忆后，[Studio](/docs/studio/overview) 会利用消息历史在聊天侧边栏展示以往对话。

:::

## 生成线程标题 {/* #thread-title-generation */}

启用 `generateTitle` 后，Mastra 可根据对话记录自动生成有描述性的线程标题。构建在线程列表或侧边栏展示标题的聊天界面时，可使用此选项。

```typescript title="src/mastra/agents/support-agent.ts"
import { Agent } from '@mastra/core/agent'
import { Memory } from '@mastra/memory'

export const supportAgent = new Agent({
  id: 'support-agent',
  name: 'Support agent',
  instructions: 'Answer customer support questions.',
  model: '__GATEWAY_OPENAI_MODEL__',
  memory: new Memory({
    options: {
      generateTitle: true,
    },
  }),
})
```

Agent 回应后才会异步生成标题，不影响回应时间。

### 在流中返回生成的标题 {/* #streaming-the-generated-title */}

默认情况下，标题在后台生成，运行的响应流不会等待，因此 HTTP 客户端要等下次获取线程时才能看到标题。设置 `emitEvent: true`，即可在本次响应流中传递标题：响应流会等待标题，并在 `finish` 前发出临时的 `data-thread-title` 数据块。

```typescript title="src/mastra/agents/support-agent.ts"
import { Agent } from '@mastra/core/agent'
import { Memory } from '@mastra/memory'

export const supportAgent = new Agent({
  id: 'support-agent',
  name: 'Support agent',
  instructions: 'Answer customer support questions.',
  model: '__GATEWAY_OPENAI_MODEL__',
  memory: new Memory({
    options: {
      generateTitle: {
        emitEvent: true,
      },
    },
  }),
})
```

流消费者会收到包含已持久化标题的数据块，聊天界面便可更新线程列表中的标题，无需轮询：

```typescript oxfmt:false
for await (const chunk of stream.fullStream) {
  if (chunk.type === 'data-thread-title') {
    renameThreadInSidebar(chunk.data.threadId, chunk.data.title)
  }
}
```

该数据块是临时的：它会传给流消费者，但不会作为对话消息保存。由于响应流会等待标题，`emitEvent` 会延迟生成标题的回合中的 `finish`：可能是线程的首个回合，也可能是在 `minMessages` 设置了更高阈值后的回合。若希望标题生成完全不阻塞响应流，请保持关闭。

:::note

`emitEvent` 仅适用于 `stream()` 运行。`generate()` 返回 JSON，无法携带此数据块，因此标题仍在后台生成。[持久化与事件驱动 Agent](/docs/harness/durable-agents) 暂时也不会发出此数据块。这些情况下，标题仍会生成并持久化。

:::

如需优化成本或生成行为，可提供更小的 [`model`](/models) 和自定义 `instructions`：

```typescript title="src/mastra/agents/support-agent.ts"
import { Agent } from '@mastra/core/agent'
import { Memory } from '@mastra/memory'

export const supportAgent = new Agent({
  id: 'support-agent',
  name: 'Support agent',
  instructions: 'Answer customer support questions.',
  model: '__GATEWAY_OPENAI_MODEL__',
  memory: new Memory({
    options: {
      generateTitle: {
        model: '__GATEWAY_OPENAI_MODEL_LUNA__',
        instructions: 'Generate a one-word title.',
      },
    },
  }),
})
```

## 访问记忆 {/* #accessing-memory */}

要查询、克隆或删除线程和消息，可在 Agent 上调用 `getMemory()`：

```typescript
const agent = mastra.getAgentById('test-agent')
const memory = await agent.getMemory()
```

使用 `Memory` 实例查询已存储线程、消息，或克隆对话。

## 查询 {/* #querying */}

以下方法可获取线程和消息，用于在界面中展示对话历史，或实现自定义记忆检索。

:::warning
记忆系统不负责执行访问控制。运行查询前，务必在应用逻辑中确认当前用户有权访问所查询的 `resourceId`。
:::

### 线程 {/* #threads */}

使用 [`listThreads()`](/reference/memory/listThreads) 获取某资源的线程：

```typescript
const result = await memory.listThreads({
  filter: { resourceId: 'user-123' },
  perPage: false,
})
```

对线程进行分页：

```typescript
const result = await memory.listThreads({
  filter: { resourceId: 'user-123' },
  page: 0,
  perPage: 10,
})

console.log(result.threads) // thread objects
console.log(result.hasMore) // more pages available?
```

也可以按元数据筛选并控制排序：

```typescript
const result = await memory.listThreads({
  filter: {
    resourceId: 'user-123',
    metadata: { status: 'active' },
  },
  orderBy: { field: 'createdAt', direction: 'DESC' },
})
```

使用 [`getThreadById()`](/reference/memory/getThreadById) 按 ID 获取单个线程：

```typescript
const thread = await memory.getThreadById({ threadId: 'thread-123' })
```

### 消息 {/* #messages */}

获得线程后，使用 [`recall()`](/reference/memory/recall) 检索消息。它支持分页、[语义搜索](/docs/memory/semantic-recall)及可选的日期筛选。

不分页地获取线程历史。Recall 默认隐藏提醒信号；传入 `hideSignals: false` 可显示这些信号，传入 `true` 可隐藏所有已识别信号，也可传入数组排除指定类型。匹配规则及优先级参阅[信号可见性与兼容性](/reference/memory/recall#signal-visibility)。

```typescript
const { messages } = await memory.recall({
  threadId: 'thread-123',
  perPage: false,
})
```

对消息进行分页：

```typescript
const { messages } = await memory.recall({
  threadId: 'thread-123',
  page: 0,
  perPage: 50,
})
```

按日期范围筛选：

```typescript
const { messages } = await memory.recall({
  threadId: 'thread-123',
  filter: {
    dateRange: {
      start: new Date('2025-01-01'),
      end: new Date('2025-06-01'),
    },
  },
})
```

按浅层消息元数据筛选：

```typescript
const { messages } = await memory.recall({
  threadId: 'thread-123',
  filter: {
    metadata: {
      category: 'billing',
      escalated: true,
      priority: 2,
      archivedAt: null,
    },
  },
})
```

元数据筛选器只匹配浅层标量值：`string`、有限的 `number`、`boolean` 和 `null`。

所有指定的元数据键采用 AND 语义。`null` 筛选条件只匹配显式 `null` 值；缺失的元数据键不匹配。

元数据键必须以字母或下划线开头，且只能包含字母数字字符；长度不得超过 128 个字符，也不能使用 `__proto__`、`constructor` 或 `prototype` 等保留的原型键。

性能取决于存储后端。有些后端可将部分筛选条件下推到数据库；其他后端会先应用线程、资源及日期约束，再扫描候选消息，最后才分页。

按 ID 获取单条消息：

```typescript
const { messages } = await memory.recall({
  threadId: 'thread-123',
  include: [{ id: 'msg-123' }],
})
```

按 ID 获取多条消息及其周边上下文：

```typescript
const { messages } = await memory.recall({
  threadId: 'thread-123',
  include: [
    { id: 'msg-123' },
    {
      id: 'msg-456',
      withPreviousMessages: 3,
      withNextMessages: 1,
    },
  ],
})
```

按语义搜索（设置方法参阅[语义召回](/docs/memory/semantic-recall)）：

```typescript
const { messages } = await memory.recall({
  threadId: 'thread-123',
  vectorSearchString: 'project deadline discussion',
  threadConfig: {
    semanticRecall: true,
  },
})
```

### 界面格式 {/* #ui-format */}

消息查询返回 `MastraDBMessage[]` 格式。前端展示前，可能需要转换成界面库所需格式。例如，[`toAISdkV5Messages`](/reference/ai-sdk/to-ai-sdk-v5-messages) 可转换为 AI SDK UI 格式。

## 克隆线程 {/* #thread-cloning */}

克隆线程会复制现有线程及其消息，适用于对话分支、潜在破坏性操作前创建检查点，或测试对话的不同版本。

```typescript
const { thread, clonedMessages } = await memory.cloneThread({
  sourceThreadId: 'thread-123',
  title: 'Branched conversation',
})
```

可按条数或日期范围筛选要克隆的消息，并指定自定义线程 ID。也可使用工具方法查看克隆关系。

如果无需返回复制的消息，例如分叉较长的线程，可使用 `copyThread()`。它从不返回消息内容；对于 LibSQL 和 PostgreSQL，记录在数据库内直接复制。启用语义召回时，仍会分批读回复制的消息以生成嵌入。

完整 API 参阅 [`cloneThread()`](/reference/memory/cloneThread)、[`copyThread()`](/reference/memory/copyThread) 和[克隆工具方法](/reference/memory/clone-utilities)。

## 删除消息 {/* #deleting-messages */}

使用 [`deleteMessages()`](/reference/memory/deleteMessages) 移除线程中的消息。可以按消息 ID 删除，也可以清空线程的所有消息。
