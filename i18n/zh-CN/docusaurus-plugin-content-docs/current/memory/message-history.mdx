# 消息记录

消息历史是最基本、最重要的记忆形式。它使法学硕士可以在上下文窗口中查看最近的消息，使您的Agent能够参考早期的交换并做出一致的响应。

您还可以检索消息历史记录以在 UI 中显示过去的对话。

:::注意
每条消息都属于一个线程（对话）和一个资源（与其关联的用户或实体）。看[Threads and resources](#threads-and-resources) for more detail.
:::

## 线程和资源 {/* #threads-and-resources */}

Mastra 使用两个标识符组织对话：

* **线**：包含一系列消息的对话会话。
* **资源**：拥有线程的实体，例如用户、组织、项目或应用程序中的其他域实体。

Studio 会自动为您生成线程和资源 ID。打电话时`stream()` or `generate()` yourself, provide these identifiers explicitly.

## 入门 {/* #getting-started */}

安装 Mastra 内存模块以及[storage adapter](/docs/storage#supported-providers) for your database. The examples below use `@mastra/libsql`, which stores data locally in a `mastra.db` file.

```bash npm2yarn
npm install @mastra/memory@latest @mastra/libsql@latest
```

消息历史记录需要存储适配器来保存对话。如果您尚未在 Mastra 实例上配置存储，请执行以下操作：

```typescript title="src/mastra/index.ts"
import { Mastra } from '@mastra/core'
import { LibSQLStore } from '@mastra/libsql'

export const mastra = new Mastra({
  storage: new LibSQLStore({
    id: 'mastra-storage',
    url: 'file:./mastra.db',
  }),
})
```

实例化一个[`Memory`](/reference/memory/memory-class) instance in your agent:

```typescript title="src/mastra/agents/test-agent.ts"
import { Memory } from '@mastra/memory'
import { Agent } from '@mastra/core/agent'

export const agent = new Agent({
  id: 'test-agent',
  memory: new Memory({
    options: {
      lastMessages: 10,
    },
  }),
})
```

当您呼叫Agent时，消息会自动保存到数据库中。您可以指定一个`threadId`, `resourceId`, and optional `metadata`:

<Tabs>
  <TabItem value="generate" label=".generate()">

    ```typescript
    await agent.generate('Hello', {
      memory: {
        thread: {
          id: 'thread-123',
          title: 'Support conversation',
          metadata: { category: 'billing' },
        },
        resource: 'user-456',
      },
    })
    ```

  </TabItem>

    ```typescript
      memory: {
        thread: {
          id: 'thread-123',
          title: 'Support conversation',
          metadata: { category: 'billing' },
        },
        resource: 'user-456',
      },
    })
    ```
  </TabItem>
</Tabs>

：：：笔记

当您调用时会自动创建线程和消息`agent.generate()` or `agent.stream()`, but you can also create them manually with [`createThread()`](/reference/memory/createThread) and [`saveMessages()`](/reference/memory/memory-class).

:::

您可以通过两种方式使用此历史记录：

* **自动纳入**：Mastra 自动在上下文窗口中包含最近的消息。默认的 10 条消息使客服人员能够专注于对话。调整它与`lastMessages` when needed.
* [**手动查询**](#querying)：要获得更多控制，请直接使用查询线程和消息`recall()`. Use the results to choose which memories enter the context window or to render conversation history in your UI.

：：：笔记

`lastMessages`计算每条存储的消息，包括Tool调用、Tool结果和[signals](/docs/signals/sending-signals) of any kind, so a single turn can add several messages to the count. The window also slides forward on every request: once a thread grows past the limit, the oldest message leaves context on each turn, which changes the start of the prompt and invalidates the provider prompt cache. For long-running conversations, use [Observational Memory](/docs/memory/observational-memory), which keeps the prompt prefix stable.

:::

### 从客户端发送消息 {/* #sending-messages-from-a-client */}

当您在客户端应用程序中使用内存时，发送**only the new message** instead of the full conversation history. Mastra loads previous messages from storage.

AI SDK示例请参见[Using Mastra Memory](/integrations/agentic-ui/ai-sdk-ui#using-mastra-memory).

<details>
  <summary>传递完整的输入历史记录</summary>

  Mastra 在加载存储的消息之前过滤客户端回显的历史记录。当消息 ID 匹配时，它会使用存储的副本作为基础，保留存储的时间戳和提供者元数据，同时保留新的Tool结果。

  如果您自己组装请求输入并需要完全按照发送的方式对其进行处理，请设置`retainFullInput: true` on `memory.options` for that call, or in the memory constructor options to apply it agent-wide. This disables input filtering, but stored history still loads. Every input message that isn't already stored is saved to the thread, including few-shot examples.
</details>

### 通过令牌限制历史记录 {/* #limit-history-by-tokens */}

消息计数不能很好地反映上下文大小：Tool结果可能是几个令牌或数千个。使用`messageHistory` to keep recent history within a token budget instead:

```typescript title="src/mastra/agents/test-agent.ts"
import { Agent } from '@mastra/core/agent'
import { Memory } from '@mastra/memory'

export const agent = new Agent({
  id: 'test-agent',
  memory: new Memory({
    options: {
      messageHistory: { maxTokens: 8_000, atMaxRemoveTokens: 2_000 },
    },
  }),
})
```

Mastra 计算完整的提示`maxTokens`, including remembered history, system instructions, context, and the current turn. When the prompt exceeds the budget, Mastra removes the oldest remembered messages until the prompt is at most `maxTokens - atMaxRemoveTokens`. `atMaxRemoveTokens` defaults to 25% of `maxTokens`. Removing history in chunks keeps the prompt prefix stable across several turns, which helps provider prompt caches stay warm.

系统消息、上下文、当前回合的输入和Agent的响应永远不会被修剪。链接的Tool调用和结果会一起删除。如果仅受保护的内容超过`maxTokens`, Mastra removes all remembered history but keeps the protected content.

修剪后的邮件保留在存储中。在Agent运行期间，Mastra 会保留每个线程的边界，以便将它们排除在以后的轮次之外。环境`messageHistory` without `lastMessages` disables the default 10-message cap. Set both to combine a count cap with a token budget. Set `maxTokens` to `0` to disable message history.

：：：提示

当内存启用时，[Studio](/docs/studio/overview) uses message history to display past conversations in the chat sidebar.

:::

## 话题标题生成 {/* #thread-title-generation */}

当以下情况发生时，Mastra 可以从对话记录中自动生成描述性话题标题：`generateTitle` is enabled. Use this option when you build a chat interface that renders conversation titles in a thread list or sidebar.

```typescript title="src/mastra/agents/support-agent.ts"
import { Agent } from '@mastra/core/agent'
import { Memory } from '@mastra/memory'

export const supportAgent = new Agent({
  id: 'support-agent',
  name: 'Support agent',
  instructions: 'Answer customer support questions.',
  model: '__GATEWAY_OPENAI_MODEL__',
  memory: new Memory({
    options: {
      generateTitle: true,
    },
  }),
})
```

标题生成在Agent响应后异步运行，不会影响响应时间。

### 流式传输生成的标题 {/* #streaming-the-generated-title */}

默认情况下，标题生成在后台运行，并且运行的流不会等待它，因此 HTTP 客户端只能在下一个线程获取时看到标题。放`emitEvent: true` to deliver the title on the run's stream instead: the stream waits for the title and emits a transient `data-thread-title` chunk before `finish`.

```typescript title="src/mastra/agents/support-agent.ts"
import { Agent } from '@mastra/core/agent'
import { Memory } from '@mastra/memory'

export const supportAgent = new Agent({
  id: 'support-agent',
  name: 'Support agent',
  instructions: 'Answer customer support questions.',
  model: '__GATEWAY_OPENAI_MODEL__',
  memory: new Memory({
    options: {
      generateTitle: {
        emitEvent: true,
      },
    },
  }),
})
```

流使用者接收带有持久标题的块，因此聊天 UI 可以重命名其线程列表条目而无需轮询：

```typescript oxfmt:false
for await (const chunk of stream.fullStream) {
  if (chunk.type === 'data-thread-title') {
    renameThreadInSidebar(chunk.data.threadId, chunk.data.title)
  }
}
```

该块是暂时的：它被传递给流消费者，但从未作为对话消息的一部分持久存在。因为流等待标题，`emitEvent` delays the stream's `finish` on the turn that generates the title: the first turn of a thread, or a later turn when `minMessages` sets a higher threshold. Leave it off to keep title generation fully non-blocking.

：：：笔记

`emitEvent`适用于`stream()` runs. `generate()` returns JSON and can't carry the chunk, so it keeps non-blocking title generation. [Durable and evented agents](/docs/harness/durable-agents) don't emit this chunk yet. In all of these cases the title is still generated and persisted.

:::

为了优化成本或行为，请提供更小的[`model`](/models) and custom `instructions`:

```typescript title="src/mastra/agents/support-agent.ts"
import { Agent } from '@mastra/core/agent'
import { Memory } from '@mastra/memory'

export const supportAgent = new Agent({
  id: 'support-agent',
  name: 'Support agent',
  instructions: 'Answer customer support questions.',
  model: '__GATEWAY_OPENAI_MODEL__',
  memory: new Memory({
    options: {
      generateTitle: {
        model: '__GATEWAY_OPENAI_MODEL_LUNA__',
        instructions: 'Generate a one-word title.',
      },
    },
  }),
})
```

## 访问内存 {/* #accessing-memory */}

要访问内存函数以查询、克隆或删除线程和消息，请调用`getMemory()` on an agent:

```typescript
const agent = mastra.getAgentById('test-agent')
const memory = await agent.getMemory()
```

使用`Memory` instance to query stored threads and messages or clone a conversation.

## 查询 {/* #querying */}

使用这些方法来获取线程和消息，以便在 UI 中显示对话历史记录或自定义内存检索逻辑。

:::警告
内存系统不强制执行访问控制。在运行任何查询之前，请在应用程序逻辑中验证当前用户是否有权访问`resourceId` being queried.
:::

### 线程数 {/* #threads */}

使用[`listThreads()`](/reference/memory/listThreads) to retrieve threads for a resource:

```typescript
const result = await memory.listThreads({
  filter: { resourceId: 'user-123' },
  perPage: false,
})
```

通过线程分页：

```typescript
const result = await memory.listThreads({
  filter: { resourceId: 'user-123' },
  page: 0,
  perPage: 10,
})

console.log(result.threads) // thread objects
console.log(result.hasMore) // more pages available?
```

您还可以按元数据进行过滤并控制排序顺序：

```typescript
const result = await memory.listThreads({
  filter: {
    resourceId: 'user-123',
    metadata: { status: 'active' },
  },
  orderBy: { field: 'createdAt', direction: 'DESC' },
})
```

要按 ID 获取单个线程，请使用[`getThreadById()`](/reference/memory/getThreadById):

```typescript
const thread = await memory.getThreadById({ threadId: 'thread-123' })
```

### 留言 {/* #messages */}

一旦有了线程，就可以使用[`recall()`](/reference/memory/recall) to retrieve its messages. It supports pagination and [semantic search](/docs/memory/semantic-recall), with optional date filtering.

获取线程的历史记录而不分页。 Recall默认隐藏提醒信号；经过`hideSignals: false` to include them, `true` to hide all recognized signals, or an array to omit selected types. See [signal visibility and compatibility](/reference/memory/recall#signal-visibility) for matching rules and precedence.

```typescript
const { messages } = await memory.recall({
  threadId: 'thread-123',
  perPage: false,
})
```

通过消息分页：

```typescript
const { messages } = await memory.recall({
  threadId: 'thread-123',
  page: 0,
  perPage: 50,
})
```

按日期范围过滤：

```typescript
const { messages } = await memory.recall({
  threadId: 'thread-123',
  filter: {
    dateRange: {
      start: new Date('2025-01-01'),
      end: new Date('2025-06-01'),
    },
  },
})
```

按浅层消息元数据过滤：

```typescript
const { messages } = await memory.recall({
  threadId: 'thread-123',
  filter: {
    metadata: {
      category: 'billing',
      escalated: true,
      priority: 2,
      archivedAt: null,
    },
  },
})
```

元数据过滤器仅匹配浅标量值：`string`, finite `number`, `boolean`, and `null`.

所有指定的元数据键都使用 AND 语义。一个`null` filter matches only an explicit `null` value. A missing metadata key doesn't match.

元数据键必须以字母或下划线开头，并且仅包含字母数字字符。它们必须为 128 个字符或更少，并且不能使用保留的原型键，例如`__proto__`, `constructor`, or `prototype`.

性能取决于存储后端。一些后端可以将过滤器的一部分推送到数据库中，而其他后端则在应用线程、资源和日期约束之后但在分页之前扫描候选消息。

通过ID获取单条消息：

```typescript
const { messages } = await memory.recall({
  threadId: 'thread-123',
  include: [{ id: 'msg-123' }],
})
```

通过 ID 和周围上下文获取多条消息：

```typescript
const { messages } = await memory.recall({
  threadId: 'thread-123',
  include: [
    { id: 'msg-123' },
    {
      id: 'msg-456',
      withPreviousMessages: 3,
      withNextMessages: 1,
    },
  ],
})
```

按含义搜索（参见[Semantic recall](/docs/memory/semantic-recall) for setup):

```typescript
const { messages } = await memory.recall({
  threadId: 'thread-123',
  vectorSearchString: 'project deadline discussion',
  threadConfig: {
    semanticRecall: true,
  },
})
```

### 用户界面格式 {/* #ui-format */}

消息查询返回`MastraDBMessage[]` format. To display messages in a frontend, you may need to convert them to a format your UI library expects. For example, [`toAISdkV5Messages`](/reference/ai-sdk/to-ai-sdk-v5-messages) converts messages to AI SDK UI format.

## 线程克隆 {/* #thread-cloning */}

线程克隆创建现有线程及其消息的副本。这对于在潜在破坏性操作之前分支对话或创建检查点，或者测试对话的变体非常有用。

```typescript
const { thread, clonedMessages } = await memory.cloneThread({
  sourceThreadId: 'thread-123',
  title: 'Branched conversation',
})
```

您可以按计数或日期范围过滤克隆消息并指定自定义线程 ID。实用方法也可用于检查克隆关系。

如果您不需要返回复制的消息，例如在分叉长线程时，请使用`copyThread()`. It never returns message payloads, and on LibSQL and PostgreSQL the rows are copied inside the database. When semantic recall is enabled, the copied messages are still read back in batches to generate embeddings.

看[`cloneThread()`](/reference/memory/cloneThread), [`copyThread()`](/reference/memory/copyThread), and [clone utilities](/reference/memory/clone-utilities) for the full API.

## 删除消息 {/* #deleting-messages */}

要从线程中删除消息，请使用[`deleteMessages()`](/reference/memory/deleteMessages). You can delete by message ID or clear all messages from a thread.
