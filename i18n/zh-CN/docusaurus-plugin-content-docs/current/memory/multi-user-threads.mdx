# 多用户线程

单个 Mastra 线程可以由多个用户共享。发送每个用户的消息[`sendMessage()`](/docs/signals/sending-signals)并将扬声器放入消息中`attributes`。 Mastra 将消息呈现为`<user>`标签携带这些属性，因此Agent可以在现在以及稍后从历史记录中加载消息时区分参与者。

## 何时使用多用户线程 {/* #when-to-use-multi-user-threads */}

当多人通过一个Agent处理同一主题时，请使用多用户线程：

* 与编辑、审阅者和批准者协作的文档
* 一名助手为多名参与者提供服务的群聊
* 审查不同角色具有不同权限的情况

## 分享一个`resourceId` across all participants {/* #share-one-resourceid-across-all-participants */}

一个线程恰好属于一个`resourceId`, so everyone on a shared thread needs to pass the same value. Instead of a user ID (the default for single-user apps), key `resourceId` on the conversation itself, for example `doc_${docId}` for a shared document or `room_${roomId}` for a group chat. With everyone pointing at the same `resourceId` and `threadId`, they read and write the same history.

## 发送带有说话者身份的每条消息 {/* #send-each-message-with-the-speakers-identity */}

将消息作为对象传递`contents` and `attributes`. Each attribute becomes an XML attribute on the `<user>` tag the model reads:

```typescript title="src/mastra/send.ts"
agent.sendMessage(
  {
    contents: 'Please make the cover page teal.',
    attributes: { name: 'Alice', role: 'editor' },
  },
  { resourceId: 'doc_42', threadId: 'doc_42' },
)
```

该模型接收：

```xml
<user name="Alice" role="editor">Please make the cover page teal.</user>
```

Mastra 为您转义属性值。属性名称必须是有效的 XML 名称，例如`name`, `role` or `user_id`. Any other name fails with `Invalid signal XML attribute name` when the message is rendered for the model. The attributes are stored with the message, so when history loads on a later turn, the model still sees who said what.

## 告诉Agent如何读取标签 {/* #tell-the-agent-how-to-read-the-tag */}

描述`<user>` tag and its attributes in the agent's instructions. The agent needs `memory` so its messages are stored on the thread:

```typescript title="src/mastra/agents/collab.ts"
import { Agent } from '@mastra/core/agent'
import { LibSQLStore } from '@mastra/libsql'
import { Memory } from '@mastra/memory'

const memory = new Memory({
  storage: new LibSQLStore({ id: 'collab-storage', url: 'file:./collab.db' }),
  options: {
    lastMessages: 20,
  },
})

export const collabAgent = new Agent({
  id: 'collab',
  name: 'CollabAgent',
  model: '__GATEWAY_OPENAI_MODEL_LUNA__',
  memory,
  instructions: `
You are a collaborative document assistant. Several people talk to you in the same thread.

Each user message arrives in a <user> tag whose attributes say who sent it:

  <user name="Alice" role="editor">...message text...</user>

Address people by name. Editors propose changes and reviewers approve them.
When you refer to something said earlier, name the person who said it.
  `.trim(),
})
```

将每个参与者的消息发送到同一个线程。当线程空闲时，`sendMessage()` starts a run and `accepted` resolves with its output:

```typescript title="src/mastra/send.ts"
import { collabAgent } from './agents/collab'

const doc = { resourceId: 'doc_42', threadId: 'doc_42' }

async function send(speaker: { name: string; role: string }, text: string) {
  const { accepted } = collabAgent.sendMessage({ contents: text, attributes: speaker }, doc)
  const result = await accepted
  if (result.action === 'wake') {
    return (await result.output.getFullOutput()).text
  }
}

await send({ name: 'Alice', role: 'editor' }, 'Please make the cover page teal.')
await send({ name: 'Bob', role: 'reviewer' }, 'I want QA sign-off before we publish.')
await send({ name: 'Alice', role: 'editor' }, 'Who asked for QA sign-off?')
// The agent answers that Bob asked for it.
```

当客服人员仍在回复其他人时收到消息时，Mastra 将其传递到正在运行的回合中，而不是开始新的回合，并且`accepted` resolves with `action: 'deliver'`. In a live app, render replies from the [thread stream](/docs/signals/thread-streams) rather than from each `sendMessage()` call. That way every participant sees the same conversation.

## 与记忆层结合 {/* #combining-with-memory-layers */}

根据对话需要记住每个参与者的时间来选择记忆层：

* **简短的对话**，或者当您需要逐字记录谁说了什么时：使用[message history alone](#message-history-alone).
* **长时间运行的线程**超出上下文窗口：使用[Observational Memory](#with-observational-memory).

### 仅消息历史记录 {/* #message-history-alone */}

`lastMessages`将较早的消息带回到上下文中`<user>` attributes, so attribution survives across turns. The agent example above uses this setup.

### 具有观察记忆 {/* #with-observational-memory */}

[观察记忆](/docs/memory/observational-memory)(OM) 通过用观察替换旧消息，在上下文窗口内保留一个长共享线程。在相同的情况下启用它`Memory`:

```typescript title="src/mastra/agents/collab-om.ts"
import { LibSQLStore } from '@mastra/libsql'
import { Memory } from '@mastra/memory'

const memory = new Memory({
  storage: new LibSQLStore({ id: 'collab-storage', url: 'file:./collab.db' }),
  options: {
    observationalMemory: true,
  },
})
```

OM 取代`lastMessages` history loading, so leave `lastMessages` out when OM is on.

观察者保留说话者的属性，因此观察结果表明谁说了什么。发送的消息`attributes: { name: 'Alice', role: 'editor' }` is labeled `User (name="Alice" role="editor")`. Messages sent without attributes are labeled plain `User`.

## 安全 {/* #security */}

从经过身份验证的用户（而不是请求正文）设置服务器上的属性。如果客户可以选择自己的`name`, one user can impersonate another. Use [request context](/docs/server/request-context) to read the verified user from your auth layer and build the `attributes` before calling `sendMessage()`.
