# 多人共享线程

同一个 Mastra 线程可由多个用户共享。用 [`sendMessage()`](/docs/signals/sending-signals) 发送每位用户的消息，在消息的 `attributes` 中标明发言者。Mastra 将消息渲染为带这些属性的 `<user>` 标签，这样 Agent 在当前轮次或之后读取历史消息时，都能分辨不同的参与者。

## 何时使用多人共享线程 {/* #when-to-use-multi-user-threads */}

多人通过同一个 Agent 协作时，可以使用共享线程，例如：

- 有编辑、审阅和审批人员参与的协作文档
- 由一个助手服务多位参与者的群聊
- 不同角色拥有不同权限的审查流程

## 所有参与者共用一个 `resourceId` {/* #share-one-resourceid-across-all-participants */}

每个线程只属于一个 `resourceId`，因此共享线程的所有人都必须传入同一个值。单用户应用默认使用用户 ID；共享时，请用对话本身标识 `resourceId`，例如共享文档用 `doc_${docId}`，群聊用 `room_${roomId}`。所有人指向同一个 `resourceId` 和 `threadId`，就能读写同一份历史记录。

## 随消息发送发言者身份 {/* #send-each-message-with-the-speakers-identity */}

将消息作为包含 `contents` 和 `attributes` 的对象传入。模型读取的 `<user>` 标签会把每项属性呈现为 XML 属性：

```typescript title="src/mastra/send.ts"
agent.sendMessage(
  {
    contents: 'Please make the cover page teal.',
    attributes: { name: 'Alice', role: 'editor' },
  },
  { resourceId: 'doc_42', threadId: 'doc_42' },
)
```

该模型接收：

```xml
<user name="Alice" role="editor">Please make the cover page teal.</user>
```

Mastra 会自动转义属性值。属性名必须是有效的 XML 名称，如 `name`、`role` 或 `user_id`。无效的名称会在为模型渲染消息时报出 `Invalid signal XML attribute name`。属性随消息一起保存，因此后续轮次加载历史时，模型仍能分辨谁说了什么。

## 告诉 Agent 如何读取标签 {/* #tell-the-agent-how-to-read-the-tag */}

在 Agent 的指令中描述 `<user>` 标签及其属性。Agent 需要配置 `memory`，才能把消息保存到线程中：

```typescript title="src/mastra/agents/collab.ts"
import { Agent } from '@mastra/core/agent'
import { LibSQLStore } from '@mastra/libsql'
import { Memory } from '@mastra/memory'

const memory = new Memory({
  storage: new LibSQLStore({ id: 'collab-storage', url: 'file:./collab.db' }),
  options: {
    lastMessages: 20,
  },
})

export const collabAgent = new Agent({
  id: 'collab',
  name: 'CollabAgent',
  model: '__GATEWAY_OPENAI_MODEL_LUNA__',
  memory,
  instructions: `
You are a collaborative document assistant. Several people talk to you in the same thread.

Each user message arrives in a <user> tag whose attributes say who sent it:

  <user name="Alice" role="editor">...message text...</user>

Address people by name. Editors propose changes and reviewers approve them.
When you refer to something said earlier, name the person who said it.
  `.trim(),
})
```

把每位参与者的消息发到同一个线程。线程空闲时，`sendMessage()` 会启动一次运行，`accepted` 会解析为该次运行的输出：

```typescript title="src/mastra/send.ts"
import { collabAgent } from './agents/collab'

const doc = { resourceId: 'doc_42', threadId: 'doc_42' }

async function send(speaker: { name: string; role: string }, text: string) {
  const { accepted } = collabAgent.sendMessage({ contents: text, attributes: speaker }, doc)
  const result = await accepted
  if (result.action === 'wake') {
    return (await result.output.getFullOutput()).text
  }
}

await send({ name: 'Alice', role: 'editor' }, 'Please make the cover page teal.')
await send({ name: 'Bob', role: 'reviewer' }, 'I want QA sign-off before we publish.')
await send({ name: 'Alice', role: 'editor' }, 'Who asked for QA sign-off?')
// The agent answers that Bob asked for it.
```

如果 Agent 正在回复其他人，Mastra 会把新消息送入当前轮次，`accepted` 会解析为 `action: 'deliver'`。实际应用中应从[线程流](/docs/signals/thread-streams)渲染回复，避免分别使用每次 `sendMessage()` 的结果，这样所有参与者看到的是同一段对话。

## 搭配不同的 Memory 层 {/* #combining-with-memory-layers */}

根据对话需要保留发言者信息的时长，选择合适的 Memory 层：

- **简短对话**，或需要逐字记录谁说了什么时：仅使用[消息历史](#message-history-alone)。
- **长期对话**，长度超过上下文窗口时：使用 [Observational Memory](#with-observational-memory)。

### 仅使用消息历史 {/* #message-history-alone */}

`lastMessages` 会将较早的消息连同 `<user>` 属性带回上下文，因此跨轮次仍能识别发言者。上面的 Agent 示例采用了这种设置。

### 使用 Observational Memory {/* #with-observational-memory */}

[Observational Memory](/docs/memory/observational-memory)（OM）会用观察记录替换较早的消息，使较长的共享线程保持在上下文窗口内。请在同一个 `Memory` 实例上启用它：

```typescript title="src/mastra/agents/collab-om.ts"
import { LibSQLStore } from '@mastra/libsql'
import { Memory } from '@mastra/memory'

const memory = new Memory({
  storage: new LibSQLStore({ id: 'collab-storage', url: 'file:./collab.db' }),
  options: {
    observationalMemory: true,
  },
})
```

OM 会替代 `lastMessages` 的历史加载机制，所以启用 OM 时不要设置 `lastMessages`。

Observer 会保留发言者属性，让观察记录表明谁说了什么。带 `attributes: { name: 'Alice', role: 'editor' }` 的消息会标记为 `User (name="Alice" role="editor")`；没有属性的消息只标记为 `User`。

## 安全 {/* #security */}

请在服务器上根据通过身份验证的用户设置属性，严禁从请求体获取属性。客户端如果能自行指定 `name`，用户就可能冒充其他人。请通过[请求上下文](/docs/server/request-context)从身份验证层获取已验证的用户，并在调用 `sendMessage()` 之前构建 `attributes`。
