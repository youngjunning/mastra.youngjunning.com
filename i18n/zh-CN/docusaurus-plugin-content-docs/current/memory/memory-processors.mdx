# 记忆处理器

启用记忆的 Agent 在处理消息时，记忆处理器会转换和过滤这些消息。它们管理上下文窗口限制、移除多余内容，并优化送往语言模型的信息。

Agent 启用记忆后，Mastra 会在其处理器流水线中加入记忆处理器。这些处理器会检索消息历史、工作记忆和语义相关的消息，并在模型响应后持久化新消息。

记忆处理器是专门处理记忆相关消息及状态的[处理器](/docs/agents/processors)。

## 内置记忆处理器 {/* #built-in-memory-processors */}

启用记忆后，Mastra 会自动添加以下处理器。只有存在记忆存储且需要加载已存历史时，才会添加 `MemoryInputFilter`：

### `MemoryInputFilter` {/* #memoryinputfilter */}

在记忆加载器运行前，裁剪客户端回传的历史。对于已有线程，只保留当前用户回合或新工具结果。对于空线程，保留完整初始输入，并从 Assistant 片段中移除可能指向存储中不存在条目的 Provider 条目元数据。设置 `retainFullInput: true` 后，会跳过裁剪和元数据清理，原样处理输入，但仍会加载已存历史。

默认先运行此处理器，使 `MessageHistory`、`SemanticRecall` 和 Observational Memory 只接收所需的新输入。

### `MessageHistory` {/* #messagehistory */}

检索消息历史并持久化新消息。

**配置如下：**

```typescript
memory: new Memory({
  options: {
    lastMessages: 10,
  },
})
```

**Mastra 内部会：**

1. 创建配置了 `lastMessages: 10` 的 `MessageHistory` 处理器
1. 将其添加到 Agent 输入处理器中（在 LLM 之前运行）
1. 将其添加到 Agent 输出处理器中（在 LLM 之后运行）

**它的作用：**

- **输入**：从存储中获取最近 10 条消息，放在对话前面
- **输出**：模型响应后将新消息持久化到存储

**示例：**

```typescript
import { Agent } from '@mastra/core/agent'
import { Memory } from '@mastra/memory'
import { LibSQLStore } from '@mastra/libsql'
import { openai } from '@ai-sdk/openai'

const agent = new Agent({
  id: 'test-agent',
  name: 'Test Agent',
  instructions: 'You are a helpful assistant',
  model: '__GATEWAY_OPENAI_MODEL__',
  memory: new Memory({
    storage: new LibSQLStore({
      id: 'memory-store',
      url: 'file:memory.db',
    }),
    options: {
      lastMessages: 10, // MessageHistory processor automatically added
    },
  }),
})
```

### `SemanticRecall` {/* #semanticrecall */}

根据当前输入检索语义相关的消息，并为新消息生成嵌入向量。

**配置如下：**

```typescript
memory: new Memory({
  semanticRecall: { enabled: true },
  vector: myVectorStore,
  embedder: myEmbedder,
})
```

**Mastra 内部会：**

1. 创建 `SemanticRecall` 处理器
1. 将其添加到 Agent 输入处理器中（在 LLM 之前运行）
1. 将其添加到 Agent 输出处理器中（在 LLM 之后运行）
1. 要求配置向量存储；除非向量存储自行生成嵌入向量，否则还需配置嵌入模型

**它的作用：**

- **输入**：通过向量相似度搜索找到相关历史消息，放在对话前面
- **输出**：为新消息生成嵌入向量并存入向量存储，供后续检索

**示例：**

```typescript
import { Agent } from '@mastra/core/agent'
import { Memory } from '@mastra/memory'
import { LibSQLStore } from '@mastra/libsql'
import { PineconeVector } from '@mastra/pinecone'
import { ModelRouterEmbeddingModel } from '@mastra/core/llm'
import { openai } from '@ai-sdk/openai'

const agent = new Agent({
  name: 'semantic-agent',
  instructions: 'You are a helpful assistant with semantic memory',
  model: '__GATEWAY_OPENAI_MODEL__',
  memory: new Memory({
    storage: new LibSQLStore({
      id: 'memory-store',
      url: 'file:memory.db',
    }),
    vector: new PineconeVector({
      id: 'memory-vector',
      apiKey: process.env.PINECONE_API_KEY!,
    }),
    embedder: new ModelRouterEmbeddingModel('openai/text-embedding-3-small'),
    semanticRecall: { enabled: true }, // SemanticRecall processor automatically added
  }),
})
```

### `WorkingMemory` {/* #workingmemory */}

管理跨对话的工作记忆状态。

**配置如下：**

```typescript
memory: new Memory({
  workingMemory: { enabled: true },
})
```

**Mastra 内部会：**

1. 创建 `WorkingMemory` 处理器
1. 将其添加到 Agent 输入处理器中（在 LLM 之前运行）
1. 要求配置存储适配器

**它的作用：**

- **输入**：检索当前线程的工作记忆状态，放在对话前面
- **输出**：不处理输出

**示例：**

```typescript
import { Agent } from '@mastra/core/agent'
import { Memory } from '@mastra/memory'
import { LibSQLStore } from '@mastra/libsql'
import { openai } from '@ai-sdk/openai'

const agent = new Agent({
  name: 'working-memory-agent',
  instructions: 'You are an assistant with working memory',
  model: '__GATEWAY_OPENAI_MODEL__',
  memory: new Memory({
    storage: new LibSQLStore({
      id: 'memory-store',
      url: 'file:memory.db',
    }),
    workingMemory: { enabled: true }, // WorkingMemory processor automatically added
  }),
})
```

## 手动控制与去重 {/* #manual-control-and-deduplication */}

如果手动将记忆处理器加入 `inputProcessors` 或 `outputProcessors`，Mastra **不会**再自动添加该处理器。手动配置可让你完全控制处理器的顺序：

```typescript
import { Agent } from '@mastra/core/agent'
import { Memory } from '@mastra/memory'
import { MessageHistory } from '@mastra/core/processors'
import { TokenLimiter } from '@mastra/core/processors'
import { LibSQLStore } from '@mastra/libsql'
import { openai } from '@ai-sdk/openai'

// Custom MessageHistory with different configuration
const customMessageHistory = new MessageHistory({
  storage: new LibSQLStore({ id: 'memory-store', url: 'file:memory.db' }),
  lastMessages: 20,
})

const agent = new Agent({
  name: 'custom-memory-agent',
  instructions: 'You are a helpful assistant',
  model: '__GATEWAY_OPENAI_MODEL__',
  memory: new Memory({
    storage: new LibSQLStore({ id: 'memory-store', url: 'file:memory.db' }),
    options: {
      lastMessages: 10, // This would normally add MessageHistory(10)
    },
  }),
  inputProcessors: [
    customMessageHistory, // Your custom one is used instead
    new TokenLimiter({ limit: 4000 }), // Runs after your custom MessageHistory
  ],
})
```

## 处理器执行顺序 {/* #processor-execution-order */}

将 Guardrail 与记忆结合使用时，必须了解执行顺序：

### 输入处理器 {/* #input-processors */}

```text
[Memory Processors] → [Your inputProcessors]
```

1. **记忆处理器先运行**：依次为 `MemoryInputFilter`、`WorkingMemory`、`MessageHistory` 和 `SemanticRecall`
1. **自定义输入处理器随后运行**：Guardrail、过滤器、验证器

因此，在自定义处理器验证或过滤输入之前，记忆处理器已经加载了消息历史。

### 输出处理器 {/* #output-processors */}

```text
[Your outputProcessors] → [Memory Processors]
```

1. **自定义输出处理器先运行**：Guardrail、过滤器、验证器
1. **记忆处理器随后运行**：`SemanticRecall`（生成嵌入向量）、`MessageHistory`（持久化）

此顺序的设计遵循**默认安全**原则：如果输出 Guardrail 调用 `abort()`，记忆处理器就不会运行，**也不会保存任何消息**。

## Guardrail 与记忆 {/* #guardrails-and-memory */}

默认执行顺序让 Guardrail 具备安全的行为：

### 输出 Guardrail（推荐） {/* #output-guardrails-recommended */}

输出 Guardrail 在记忆处理器保存消息**之前**运行。如果 Guardrail 中止执行：

- 触发 tripwire
- 跳过记忆处理器
- **不会将任何消息持久化到存储**

```typescript
import { Agent } from '@mastra/core/agent'
import { Memory } from '@mastra/memory'
import { openai } from '@ai-sdk/openai'

// Output guardrail that blocks inappropriate content
const contentBlocker = {
  id: 'content-blocker',
  processOutputResult: async ({ messages, abort }) => {
    const hasInappropriateContent = messages.some(msg => containsBadContent(msg))
    if (hasInappropriateContent) {
      abort('Content blocked by guardrail')
    }
    return messages
  },
}

const agent = new Agent({
  id: 'safe-agent',
  name: 'safe-agent',
  instructions: 'You are a helpful assistant',
  model: '__GATEWAY_OPENAI_MODEL__',
  memory: new Memory({ options: { lastMessages: 10 } }),
  // Your guardrail runs BEFORE memory saves
  outputProcessors: [contentBlocker],
})

// If the guardrail aborts, nothing is saved to memory
const result = await agent.generate('Hello')
if (result.tripwire) {
  console.log('Blocked:', result.tripwire.reason)
  // Memory is empty - no messages were persisted
}
```

### 输入 Guardrail {/* #input-guardrails */}

输入 Guardrail 在记忆处理器加载历史**之后**运行。如果 Guardrail 中止执行：

- 触发 tripwire
- 不调用 LLM
- 跳过输出处理器（包括记忆持久化）
- **不会将任何消息持久化到存储**

```typescript
// Input guardrail that validates user input
const inputValidator = {
  id: 'input-validator',
  processInput: async ({ messages, abort }) => {
    const lastUserMessage = messages.findLast(m => m.role === 'user')
    if (isInvalidInput(lastUserMessage)) {
      abort('Invalid input detected')
    }
    return messages
  },
}

const agent = new Agent({
  id: 'validated-agent',
  name: 'validated-agent',
  instructions: 'You are a helpful assistant',
  model: '__GATEWAY_OPENAI_MODEL__',
  memory: new Memory({ options: { lastMessages: 10 } }),
  // Your guardrail runs AFTER memory loads history
  inputProcessors: [inputValidator],
})
```

### 小结 {/* #summary */}

| Guardrail 类型 | 运行时机 | 中止时 |
| - | - | - |
| 输入 | 记忆处理器加载历史后 | 不调用 LLM，不保存内容 |
| 输出 | 记忆处理器保存内容前 | 不向存储写入内容 |

两种情况都能防止 Guardrail 拦截的不当内容被持久化到记忆中。

## 中止运行与已保存的消息 {/* #aborted-runs-and-saved-messages */}

调用者取消运行，以及处理器通过 `abort()` 阻止运行，都会停止生成，但两者保存的内容不同：

| 停止运行的方式 | 记忆处理器 | 持久化的内容 |
| - | - | - |
| 调用者传入的 `abortSignal` | 仍会运行 | 用户消息，以及用户已看到的 Assistant 文本 |
| 处理器内调用 `abort()` | 跳过 | 不保存内容；tripwire 阻止写入 |

调用者取消后，运行仍像其他运行一样经过输出处理器，因此内置的 `MessageHistory` 会保存线程。部分回答会作为普通 Assistant 消息存储，不含错误片段；下一轮因此从用户实际读到的内容继续。

```typescript
import { Agent } from '@mastra/core/agent'
import { Memory } from '@mastra/memory'

const memory = new Memory({ options: { lastMessages: 20 } })
const agent = new Agent({
  id: 'writer',
  name: 'writer',
  instructions: 'You write step-by-step migration guides.',
  model: '__GATEWAY_OPENAI_MODEL__',
  memory,
})

const controller = new AbortController()
const stream = await agent.stream('Write the migration guide.', {
  memory: { thread: 'thread-1', resource: 'user-1' },
  abortSignal: controller.signal,
  onAbort: ({ steps, text }) => {
    console.log(`Aborted after ${steps.length} steps with ${text?.length ?? 0} characters streamed`)
  },
})

let streamed = ''
for await (const chunk of stream.fullStream) {
  if (chunk.type !== 'text-delta') continue
  streamed += chunk.payload.text
  if (streamed.length > 200) controller.abort()
}

// The partial answer is already in the thread
const { messages } = await memory.recall({ threadId: 'thread-1', resourceId: 'user-1' })
```

`onAbort` 接收取消前已完成的步骤，以及正在执行的步骤已流式输出的 Assistant 文本。中止生命周期的详情，包括通过 `runId` 中止持久化运行的情况，见 [`stream()` 参考文档](/reference/streaming/agents/stream#aborting-a-run)。

## 处理大型附件 {/* #handling-large-attachments */}

部分存储 Provider 会限制记录大小，而 base64 编码的文件附件可能超出限制：

| Provider | 记录大小上限 |
| - | - |
|[DynamoDB](/integrations/databases/dynamodb) | 400 KB |
| [Convex](/integrations/databases/convex) | 1 MiB |
| [Cloudflare D1](/integrations/databases/cloudflare-d1) | 1 MiB |

PostgreSQL、MongoDB 和 libSQL 具有更高的限制，并且通常不受影响。

使用输入处理器先将附件上传到外部存储，再在消息持久化之前用 URL 引用替换附件。

```typescript title="src/mastra/processors/attachment-uploader.ts"
import type { Processor } from '@mastra/core/processors'
import type { MastraDBMessage } from '@mastra/core/memory'

export class AttachmentUploader implements Processor {
  id = 'attachment-uploader'

  async processInput({ messages }: { messages: MastraDBMessage[] }) {
    return Promise.all(messages.map(message => this.processMessage(message)))
  }

  async processMessage(message: MastraDBMessage) {
    const attachments = message.content.experimental_attachments
    if (!attachments?.length) return message

    const uploaded = await Promise.all(
      attachments.map(async attachment => {
        if (!attachment.url?.startsWith('data:')) return attachment

        const url = await this.upload(attachment.url, attachment.contentType)
        return { ...attachment, url }
      }),
    )

    return { ...message, content: { ...message.content, experimental_attachments: uploaded } }
  }

  async upload(dataUri: string, contentType?: string): Promise<string> {
    const base64 = dataUri.split(',')[1]
    const buffer = Buffer.from(base64, 'base64')

    throw new Error('Implement upload() with your storage provider')
  }
}
```

在 Agent 中使用此处理器：

```typescript title="src/mastra/agents/support-agent.ts"
import { Agent } from '@mastra/core/agent'
import { Memory } from '@mastra/memory'
import { AttachmentUploader } from '../processors/attachment-uploader'

export const supportAgent = new Agent({
  id: 'support-agent',
  name: 'Support agent',
  instructions: 'Answer customer support questions.',
  model: '__GATEWAY_OPENAI_MODEL__',
  memory: new Memory({ options: { lastMessages: 10 } }),
  inputProcessors: [new AttachmentUploader()],
})
```
