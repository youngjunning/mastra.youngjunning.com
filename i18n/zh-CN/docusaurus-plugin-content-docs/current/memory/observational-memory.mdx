# 观察记忆

**添加于：** `@mastra/memory@1.1.0`

观察内存 (OM) 允许Agent在任务执行期间在一个线程中工作，并且上下文保持较小、集中且提示缓存友好。一个**Observer** agent turns older messages into short, dated observations in the background, and a **Reflector**Agent在成长时会浓缩这些观察结果。Agent会完整地查看最近的消息，并将之前的所有内容视为观察结果。

对于不只执行一次性摘要或单个Workflow程步骤的任何Agent，请使用 OM。每个采取多个步骤的Agent都会受益：聊天助手、编码Agent、浏览器Agent、运行数小时的支持线程。

## 快速入门 {/* #quickstart */}

安装`@mastra/memory` and a [storage adapter](/docs/storage#supported-providers). The examples below use `@mastra/libsql`, which stores data locally in a `memory.db`文件。

```bash npm2yarn
npm install @mastra/memory@latest @mastra/libsql@latest
```

OM 需要支持它的存储（`@mastra/libsql`, `@mastra/pg`, `@mastra/mysql`, `@mastra/mongodb`, `@mastra/convex`或者`@mastra/oracledb`)，每个调用都有一个线程，以及`observationalMemory: true`。该脚本将内存存储在本地 LibSQL 文件中，并在一个线程上调用Agent两次：

```typescript title="src/observational-memory.ts"
import { Agent } from '@mastra/core/agent'
import { LibSQLStore } from '@mastra/libsql'
import { Memory } from '@mastra/memory'

const memory = new Memory({
  storage: new LibSQLStore({
    id: 'memory-storage',
    url: 'file:./memory.db',
  }),
  options: {
    // highlight-next-line
    observationalMemory: true,
  },
})

const agent = new Agent({
  id: 'memory-agent',
  name: 'Memory Agent',
  instructions: 'You are a helpful assistant.',
  model: '__GATEWAY_OPENAI_MODEL_LUNA__',
  memory,
})

const memoryOptions = {
  resource: 'user-123',
  thread: 'conversation-123',
}

const first = await agent.generate('Remember that my favorite color is blue.', {
  memory: memoryOptions,
})
console.log(first.text)

const second = await agent.generate('What is my favorite color?', {
  memory: memoryOptions,
})
console.log(second.text)
```

`resource`识别用户或实体，并且`thread` identifies the conversation. Reuse both to continue the conversation. Nothing is observed in this short exchange. Once the thread's message history passes 30,000 tokens, OM starts replacing older messages with observations.

如果您的 Mastra 实例已有存储，您可以离开`storage` out of `Memory` and it uses that.

要观看 OM 工作，请打开**Memory** tab of the agent in [Studio](/docs/studio/overview). Progress bars show how close messages and observations are to their thresholds, and **Analyze observations** opens the observation log and its history.

## 好处 {/* #benefits */}

* **长任务停留在一个线程中**：Agent继续工作超过其上下文限制，而不会压缩，也不会丢失早期的决策。
* **提示缓存**：观察附加到一个稳定的前缀，而不是每轮都检索，这使得提供者可以从其提示缓存中服务大部分每个请求。看[cost and latency](#cost-and-latency).
* **较小的背景**：原始消息和Tool结果压缩为密集的观察日志，从而降低每次调用的成本和延迟。
* **更少的上下文腐烂**：Agent读取重要的内容，而不是陈旧的Tool输出和噪音，这使其能够在长时间会话中继续执行任务。

Mastra 自己的Agent在 OM 上运行。[Mastra Code](https://code.mastra.ai/), a coding agent for the terminal, uses it so a session can run for days without compacting. [Mastra Factory](https://factory.mastra.ai/) runs its planning, implementation and review sessions on Mastra Code. Each agent keeps the context of a long task from start to finish.

## 它是如何运作的 {/* #how-it-works */}

每次Agent响应时，它都会读取一个上下文窗口，其中包含系统提示符、最近的消息和任何注入的上下文。它携带的原始历史越多，它的性能就越差，并且大多数代币不再需要继续执行任务。 OM 压缩了该历史。

### 观察结果 {/* #observations */}

当线程未观察到的消息传递时`observation.messageTokens` (default 30,000), the Observer writes observations: short, dated notes about what happened.

```md
Date: 2026-01-15

- 🔴 12:10 User is building a Next.js app with Supabase auth, due in 1 week (meaning January 22nd 2026)
  - 🔴 12:10 App uses server components with client-side hydration
  - 🟡 12:12 User asked about middleware configuration for protected routes
  - 🔴 12:15 User stated the app name is "Acme Dashboard"
```

观察到的消息离开上下文窗口，观察结果取代它们，通常小 5 到 40 倍。每个页面快照看到 50,000 个令牌的浏览器Agent最终会携带数百个有关页面上的内容及其用途的令牌。

在同步观察过程中，观察者也会记录一个**current task** and a **suggested response**. These help the agent pick up where it left off. With `observation.threadTitle` enabled, it can suggest a new thread title when the topic changes.

观察者会在其评论的历史记录中看到附件。成绩单保留占位符，例如`[Image #1: reference-board.png]`, and the attachments themselves are forwarded beside the text. See [choosing models](#choosing-models) for Observers that can't read attachments.

### 反思 {/* #reflections */}

当观察通过时`reflection.observationTokens` (default 40,000), the Reflector rewrites the whole log: it merges related items, condenses older ones more and keeps recent detail. Its output becomes the new log, and new observations append after it. The log stays around the reflection threshold however long the thread runs.

Agent的上下文分为三层：

1. **最近消息**：当前任务的确切对话。
2. **观察结果**：自上次反射以来观察者所看到的情况。
3. **反思**：之前所有内容的浓缩日志。

### 背景如何随时间变化 {/* #how-context-changes-over-time */}

在默认设置下，上下文窗口循环增大和缩小：

<OmContextOverTimeImage />

1. **0 到 30,000 个代币**：消息历史记录增长。在后台，观察者准备每 6,000 个令牌的观察结果（`observation.bufferTokens: 0.2`).
2. **已达 30,000 人**：准备好的观察激活。观察到的消息离开上下文，并且大约 6,000 个最近消息的标记保留（`observation.bufferActivation: 0.8` keeps 20% of the threshold).
3. **重复**：历史增长回到 30,000，然后再次缩小。每个周期都会向观察日志添加一点内容。
4. **观察次数达到 40,000**：Reflector 将日志重写为较小的日志。

阈值标志着工作开始的时间。当背景观察落后时，历史记录可能会超过 30,000 个代币。在`observation.blockAfter` (default `1.2`, or 36,000 tokens) the agent waits for a synchronous observation. See [when buffering falls behind](/reference/memory/observational-memory#when-buffering-falls-behind).

令牌计数是本地的`tokenx` estimates. The provider's own count is often higher, especially with attachments.

### 上下文溢出恢复 {/* #context-overflow-recovery */}

在 OM 的估计达到阈值之前，提供者可以拒绝超出其上下文窗口的请求。当发生这种情况时，OM 会激活任何准备好的观察，观察仍待处理的所有内容，并使用较小的上下文重试该请求一次。默认情况下此功能处于启用状态；放`observation.observeOnContextOverflow: false` to let the error reach your code instead.

## 选择型号 {/* #choosing-models */}

观察者和反射器是在Agent旁边运行的模型调用。默认情况下两者都使用`model: 'auto'`, which resolves each time a role runs:

1. `google/gemini-2.5-flash`当 Google 可用时：`GOOGLE_GENERATIVE_AI_API_KEY` is set, or your `canUseProvider` function returns `true` for `'google'`.
2. 否则，例如来自主模型Provider的低成本模型`anthropic/claude-haiku-4-5` for an Anthropic agent.
3. 否则，主模型本身。

`auto`读取主模型的`provider/model` ID. When that isn't known, such as a model created with a custom URL, API key or gateway, `auto` uses the main model itself, because a sibling model isn't known to share that route.

放`model` to use one model for both roles:

```typescript
const memory = new Memory({
  options: {
    observationalMemory: {
      model: 'deepseek/deepseek-flash',
    },
  },
})
```

使用具有大上下文窗口（128,000 个标记或更多）的模型，该模型的速度足以在后台运行。马斯特拉已经测试过`google/gemini-2.5-flash`, `__GATEWAY_OPENAI_MODEL_LUNA__`, `__GATEWAY_ANTHROPIC_MODEL_HAIKU__` and `deepseek/deepseek-flash`.

要为每个角色使用不同的模型，请设置`observation.model` and `reflection.model` instead, and leave the top-level `model` out. Setting both throws. Some models keep so much detail that their reflections can stay above the threshold; in testing, `google/gemini-2.5-flash` did this. A common split uses a detail-preserving model as the Observer and one that condenses more readily, such as `deepseek/deepseek-flash`, as the Reflector. See [different models per agent](/reference/memory/observational-memory#different-models-per-agent).

### 调整自动选择 {/* #tune-automatic-selection */}

这些`observationalMemory` options adjust what `auto` picks:

* `autoModels`：例如，替换Provider的低成本选择`{ openai: '__GATEWAY_OPENAI_MODEL_LUNA__' }`.
* `canUseProvider`： 告诉`auto` whether the current request can use a provider, when credentials are per tenant or per request rather than in the server's environment. It receives the provider ID and `{ requestContext }`.
* `resolveModel`：使用您自己的凭据或路由自行创建所选模型。它接收具体的模型 ID，从不`'auto'`.

```typescript
const memory = new Memory({
  options: {
    observationalMemory: {
      autoModels: { openai: '__GATEWAY_OPENAI_MODEL_LUNA__' },
      canUseProvider: (provider, { requestContext }) => hasCredentials(provider, requestContext),
      resolveModel: (modelId, { requestContext }) => createRoutedModel(modelId, requestContext),
    },
  },
})
```

`resolveAutoModelId(mainModelId, { autoModels })`从`@mastra/memory` returns the model `auto` would pick, for showing the effective model in a settings UI.

### 代币分层模型 {/* #token-tiered-models */}

**添加于：** `@mastra/memory@1.10.0`

`ModelByInputTokens`根据每个观察者或反射器调用的大小选择模型：

```typescript
import { Memory, ModelByInputTokens } from '@mastra/memory'

const memory = new Memory({
  options: {
    observationalMemory: {
      observation: {
        model: new ModelByInputTokens({
          upTo: {
            5_000: 'openrouter/mistralai/ministral-8b-2512',
            20_000: 'openrouter/mistralai/mistral-small-2603',
            40_000: '__GATEWAY_OPENAI_MODEL_LUNA__',
            1_000_000: '__GATEWAY_GOOGLE_MODEL_FLASH__',
          },
        }),
      },
      reflection: {
        model: new ModelByInputTokens({
          upTo: {
            20_000: '__GATEWAY_OPENAI_MODEL_LUNA__',
            100_000: 'deepseek/deepseek-flash',
          },
        }),
      },
    },
  },
})
```

每一层都需要一个具体的模型 ID，而不是`'auto'`. Each `upTo` key is an inclusive upper bound. A call larger than the biggest key throws, so make the last tier cover the largest input you expect.

### 附件和纯文本观察员 {/* #attachments-and-text-only-observers */}

默认情况下，观察者接收图像和 PDF（`observation.observeAttachments: ['image/*', 'application/pdf']`). Other attachments are left out, and their placeholders stay in the transcript. Change it when your Observer model handles more or less:

* `false`: 不发送附件。将其用于纯文本观察者。
* `true`: 发送每个附件。
* MIME 类型列表，例如`['image/*']`: send only matching attachments. Matching is case-insensitive and `*` matches any subtype.
* `'auto'`：当提供者注册表表示观察者模型接受多模式输入时发送附件。当没有模型数据时，所有内容都会被发送。

```typescript
const memory = new Memory({
  options: {
    observationalMemory: {
      observation: {
        model: 'deepseek/deepseek-flash',
        observeAttachments: false,
      },
    },
  },
})
```

相同的过滤器适用于Tool结果内的图像和文件。Agent记录为不可用的附件（因为无法再下载）永远不会发送。看[attachment download failures](/docs/agents/processors#recover-from-attachment-download-failures).

## 成本和延迟 {/* #cost-and-latency */}

每一次观察和反思都是一次模型调用。默认情况下，线程大约每 6,000 个新消息令牌就会调用一次 Observer 调用，而每当日志达到 40,000 个令牌时，线程就会调用一次 Reflector。作为回报，每个主Agent调用都会读取最多数万个令牌的上下文，而不是整个线程。观察前缀很少更改，因此提示缓存会继续工作：用户通常会看到 OM 的提示缓存命中率为 97% 到 99%。

观察者在后台提前运行（异步缓冲），因此Agent不会停下来等待它。这些设置控制时间：

|设置|默认 |它控制什么 |
| - | - | - |
|`observation.bufferTokens` | `0.2` | How often the Observer runs in the background, as a fraction of `messageTokens` (`0.2` is every 6,000 tokens at the default threshold), or an absolute token count such as `5000`. `false` turns buffering off. |
| `observation.bufferActivation` | `0.8` | How much of the message window clears when observations activate. `0.8` keeps 20% of `messageTokens`. Lower values keep more recent messages. |
| `observation.blockAfter` | `1.2` | When the agent waits for a synchronous observation because buffering fell behind, as a multiple of `messageTokens` (`1.2` is 36,000 tokens), or an absolute count of 100 or more. `1` observes synchronously at `messageTokens`. |

要更改 OM 观察和反映的时间，请设置阈值：

```typescript
const memory = new Memory({
  options: {
    observationalMemory: {
      observation: {
        messageTokens: 30_000,
      },
      reflection: {
        observationTokens: 40_000,
      },
    },
  },
})
```

### 长时间运行Tool调用 {/* #long-runs-of-tool-calls */}

运行长链Tool调用的Agent（例如编码和浏览器Agent）会在每一步重新发送相同的不断增长的前缀，并且提供程序从提示缓存中提供大部分前缀。对于这些Agent，将观察阈值提高到远高于默认值，例如提高到 60,000 到 80,000 个令牌，这样 OM 压缩的频率就会降低，并且每次运行的更多内容都会被缓存：

```typescript
const memory = new Memory({
  options: {
    observationalMemory: {
      observation: {
        messageTokens: 70_000,
      },
    },
  },
})
```

将阈值保持在主模型的上下文窗口内。`bufferTokens`, `bufferActivation` and `blockAfter` are fractions of `messageTokens` by default, so they scale with it.

### 提示缓存过期时激活 {/* #activate-when-the-prompt-cache-expires */}

一旦提示缓存过期，下一个请求无论如何都会为整个上下文支付全价。`activateAfterIdle` makes OM activate its prepared observations when a thread has been idle that long, so the request after a pause sends a smaller, compressed context. It isn't set by default. Set it to `'auto'` to use the active provider's prompt cache TTL (for example 5 minutes for Anthropic, 1 hour for DeepSeek):

```typescript
const memory = new Memory({
  options: {
    observationalMemory: {
      activateAfterIdle: 'auto',
    },
  },
})
```

看[early activation](/reference/memory/observational-memory#early-activation) for fixed durations, per-provider values and activating when the provider changes.

### 同步观察 {/* #synchronous-observation */}

要同步观察，请设置`observation.bufferTokens: false`. That turns off background buffering for both observations and reflections, and the agent pauses while each one runs.

`shareTokenBudget: true`让消息历史借用观察预算中未使用的部分，因此在观察开始之前，当日志较小时，最多会保留大约 70,000 个消息标记。它需要`observation.bufferTokens: false`. See [shared token budget](/reference/memory/observational-memory#shared-token-budget).

## 线程和跨线程内存 {/* #threads-and-cross-thread-memory */}

### 线程范围（默认） {/* #thread-scope-default */}

每个线程都有自己的观察结果。每个调用都需要一个线程：没有线程，OM 会抛出异常`OBSERVATIONAL_MEMORY_THREAD_ID_REQUIRED`, so that unrelated threads never share one observation record.

:::警告
当客户端应用程序呼叫您的Agent时，仅发送新消息而不是完整的对话。 OM 已经从存储中加载了线程的历史记录。看[message history](/docs/memory/message-history) for how Mastra handles echoed history and when to use `retainFullInput`.
:::

OM 在一个线程中记住。要让Agent到达用户的其他线程，请打开[retrieval mode](#retrieval-mode), which gives it a `recall` tool for the raw messages behind observations and for other threads of the same resource.

### 检索方式 {/* #retrieval-mode */}

观察结果删除了原来的措辞。通过检索模式，每个观察组都与其来自的消息保持链接，并且Agent会获得一个`recall` tool to read them back, including exact wording and tool output.

`retrieval: true`让Agent浏览原始消息、列出资源的线程并读取其他线程。不需要矢量存储。

`retrieval: { vector: true }`使用配置的向量存储和嵌入器在观察组上添加语义搜索`Memory`. With a vector store that generates embeddings itself, leave the `embedder` out. See [server-side embeddings](/docs/memory/semantic-recall#server-side-embeddings). New observation groups are indexed in the background as they're created.

```typescript
const memory = new Memory({
  storage,
  vector: myVectorStore,
  embedder: myEmbedder,
  options: {
    observationalMemory: {
      retrieval: { vector: true },
    },
  },
})
```

召回Tool的范围是`'resource'` by default, so it can reach every thread of the resource. Set `retrieval: { scope: 'thread' }` to limit it to the current thread. Use `retrieval.instructions` to add app-specific guidance after the built-in recall instructions, for example "Prefer the current conversation when it already contains the answer."

请参阅[recall tool reference](/reference/memory/observational-memory#recall-tool) for its modes, detail levels and pagination.

### 资源范围（已弃用） {/* #resource-scope-deprecated */}

:::警告\[已弃用]

`scope: 'resource'`已弃用并将在未来版本中删除。第一次使用资源范围创建 OM 时，Mastra 会记录一条警告。删除`scope` option to use thread scope, and use [retrieval mode](#retrieval-mode) for cross-thread continuity. [Knowledge](/docs/knowledge/overview), now in alpha, gives agents shared information across threads and is planned to replace resource scope.

:::

资源范围在资源的所有线程之间共享一个观察记录。它的工作效果比线程作用域差得多：

* **提示缓存**：观察任何线程都会更改每个其他线程的上下文，这会破坏其缓存的前缀。
* **Agent了解**：每个线程都可以看到来自其他线程的观察结果，并且Agent可以继续另一个线程启动的工作。
* **表现**：来自所有线程的未观察到的消息会一起处理，这对于具有多个线程的用户来说很慢。资源范围还会关闭异步缓冲。

切换到线程范围不会迁移资源范围的观察。每个线程都使用自己的线程范围记录（如果有的话），或者开始为空，并且不会再次观察到在资源范围下已观察到的消息。

## 提取器 {/* #extractors */}

提取器在观察的同时保留特定的值。内置当前任务、建议响应和线程标题使用相同的管道。此示例提取一个小的用户配置文件：

```typescript title="src/mastra/agents/assistant.ts"
import { Agent } from '@mastra/core/agent'
import { Extractor, Memory } from '@mastra/memory'
import { z } from 'zod'

const memory = new Memory({
  options: {
    observationalMemory: {
      observation: {
        extract: [
          new Extractor({
            name: 'User profile',
            instructions: 'Extract stable user profile facts that should be remembered.',
            schema: z.object({
              preferredName: z.string().optional(),
              timezone: z.string().optional(),
              tools: z.array(z.string()).optional(),
            }),
          }),
        ],
      },
    },
  },
})

export const assistant = new Agent({
  id: 'assistant',
  name: 'Assistant',
  instructions: 'You are a helpful assistant.',
  model: '__GATEWAY_OPENAI_MODEL_LUNA__',
  memory,
})
```

带有一个提取器`schema` runs as a follow-up structured-output request. Without a schema it's an inline string extractor, emitted directly in the Observer or Reflector response:

```typescript
new Extractor({
  name: 'Mood',
  instructions: 'Extract the user mood as a short phrase.',
})
```

默认情况下，提取器会在以后的运行中看到其最后的值。放`includePreviousExtraction: false` to hide it:

```typescript
new Extractor({
  name: 'Latest blocker',
  instructions: 'Extract any blockers the agent is running into.',
  includePreviousExtraction: false,
})
```

`instructions`和`schema` can be functions when they depend on runtime context, such as the memory instance or request context:

```typescript
new Extractor({
  name: 'Workspace summary',
  instructions: ({ memory }) =>
    memory ? 'Extract workspace facts for this memory instance.' : 'Extract workspace facts.',
})
```

使用`onExtracted` to normalize a value before it's persisted:

```typescript
new Extractor({
  name: 'Project status',
  instructions: 'Extract the current project status.',
  schema: z.string(),
  onExtracted: ({ current }) => current.trim().toLowerCase(),
})
```

`onExtracted`还收到`previous` and `sendSignal`, so it can tell the agent when a value changes. The hook runs on every extraction, so compare `previous` with `current` before sending a signal; otherwise each observation sends another one.

失败的提取器会在 OM 标记中报告，并且不会删除成功的提取器中的值。请参阅[Extractor API](/reference/memory/observational-memory#extractor-api) for the full shape.

### 从流中读取提取的值 {/* #read-extracted-values-from-a-stream */}

当 OM 完成观察或反射时，提取器结果就会到达。从流中读取两个完成数据部分：

```typescript title="src/run.ts"
import { assistant } from './mastra/agents/assistant'

const stream = await assistant.stream('Remember that I prefer dark mode.', {
  memory: { resource: 'user-123', thread: 'conversation-123' },
})

for await (const chunk of stream.fullStream) {
  if (chunk.type === 'data-om-observation-end' || chunk.type === 'data-om-buffering-end') {
    const { operationType, extractedValues = {}, extractionFailures = [] } = chunk.data

    for (const [slug, value] of Object.entries(extractedValues)) {
      console.log(`${operationType} extractor ${slug}:`, value)
    }

    for (const failure of extractionFailures) {
      console.error(`Extractor ${failure.slug} failed:`, failure.error)
    }
  }
}
```

`extractedValues`由每个提取器的弹头键控。这两个字段都是可选的。

`data-om-observation-end`报告同步完成。`data-om-buffering-end` reports finished background work: its extractor values are persisted at once, but the buffered observations stay inactive until activation. `operationType` says whether the work was an observation or a reflection. See [`data-om-observation-end`](/reference/memory/observational-memory#data-om-observation-end) and [`data-om-buffering-end`](/reference/memory/observational-memory#data-om-buffering-end) for the payloads.
