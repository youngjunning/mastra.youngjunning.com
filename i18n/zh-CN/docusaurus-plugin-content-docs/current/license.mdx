# 许可证

Mastra 采用双许可模式。大部分代码采用 Apache License 2.0，企业专用功能采用 Mastra Enterprise License。

- Mastra 仓库中任何名为 `ee/` 的目录下的所有内容，包括但不限于：

  - `@mastra/core/auth/ee`
  - `@mastra/core/agent-builder/ee`
  - `@mastra/editor/ee`

  均按 [`ee/LICENSE`](https://github.com/mastra-ai/mastra/blob/main/ee/LICENSE) 中规定的条款授权。

- Mastra 软件包含的所有第三方组件均按各组件所有者提供的原始许可证授权。

- 不在上述目录内、也不受上述限制的内容，按 Apache License 2.0 授权。

## 哪些功能需要企业版许可证 {/* #what-requires-an-ee-license */}

是否需要 Mastra 企业版（EE）许可证，取决于配置了哪些功能，与安装的软件包无关。下表列出了在生产环境中需要许可证的功能。开发和测试时，所有功能都可免许可证使用。

| 功能 | 生产环境是否需要 EE 许可证 |
| - | - |
| 使用任意提供方为 API 路由配置身份验证（`server.auth`），包括 Simple Auth、JWT、Auth0、Better Auth、Clerk、Firebase、Google、Neon、Okta、Supabase 和 WorkOS | 否 |
| Studio 使用 Simple Auth、JWT 或 Mastra 平台身份验证 | 否 |
| 使用第三方提供方的 Studio 登录页面（SSO 按钮或邮箱和密码表单） | 是 |
| 使用任意提供方，通过 `server.rbac` 或 `studio.rbac` 配置基于角色的访问控制（RBAC） | 是 |
| 通过 `server.fga` 或 `studio.fga` 配置细粒度授权（FGA） | 是 |
| Agent Builder | 是 |

### 生产环境缺少有效许可证时 {/* #without-a-license-in-production */}

请在环境变量 `MASTRA_LICENSE_KEY` 中设置许可证密钥。Mastra 也会读取旧版环境变量 `MASTRA_EE_LICENSE`。如果生产环境没有有效密钥：

- **RBAC、FGA 或 Agent Builder**：服务器不会启动，错误信息会指出哪个功能需要许可证。
- **使用第三方提供方的 Studio 登录页面**：Studio 会隐藏登录页面，API 路由的身份验证仍然有效。

## Mastra Enterprise License {/* #mastra-enterprise-license */}

任何名为 `ee/` 的目录中的代码（例如 `@mastra/core/auth/ee`）均按 Mastra Enterprise License 提供源代码。将这些功能用于生产环境需要有效的企业许可证，开发和测试则可自由使用。详情请[联系销售团队](https://mastra.ai/contact)。
