# 执照

Mastra 使用双许可证模型，其中 Apache License 2.0 用于大部分代码库，Mastra Enterprise License 用于企业特定功能。

* 驻留在名为的任何目录下的所有内容`ee/` within Mastra's repository, including but not limited to:

  * `@mastra/core/auth/ee`
  * `@mastra/core/agent-builder/ee`
  * `@mastra/editor/ee`

  已根据中定义的许可证获得许可[`ee/LICENSE`](https://github.com/mastra-ai/mastra/blob/main/ee/LICENSE).

* Mastra 软件中包含的所有第三方组件均根据适用组件所有者提供的原始许可证获得许可。

* 上述目录或限制之外的内容可在“Apache License 2.0”下使用。

## 什么需要 EE 许可证 {/* #what-requires-an-ee-license */}

您是否需要 Mastra 企业版 (EE) 许可证取决于您配置的功能，而不是您安装的软件包。该表显示了哪些功能在生产中需要许可证。每个功能都无需开发和测试许可即可使用。

|特色 |生产中需要 EE 许可证 |
| - | - |
| API 路由上的身份验证（`server.auth`) with any provider, including Simple Auth, JWT, Auth0, Better Auth, Clerk, Firebase, Google, Neon, Okta, Supabase, and WorkOS | No |
| Studio with Simple Auth, JWT, or Mastra platform auth | No |
| Studio sign-in screen (an SSO button or an email and password form) with a third-party provider | Yes |
| Role-based access control (RBAC) with `server.rbac` or `studio.rbac`, using any provider | Yes |
| Fine-grained authorization (FGA) with `server.fga` or `studio.fga`|是的 |
|Agent生成器|是的 |

### 无生产许可证 {/* #without-a-license-in-production */}

在中设置您的许可证密钥`MASTRA_LICENSE_KEY` environment variable. Mastra also reads the older `MASTRA_EE_LICENSE` variable. Without a valid key in production:

* **RBAC、FGA 或Agent生成器**：服务器无法启动，并且错误指出需要许可证的功能。
* **Studio 登录屏幕与第三方Provider**：Studio 隐藏登录屏幕。 API 路由上的身份验证继续有效。
