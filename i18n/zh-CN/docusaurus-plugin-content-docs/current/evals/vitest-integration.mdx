# Vitest 集成

`@mastra/evals/vitest` 将 [`runEvals`](/reference/evals/run-evals) 接入 [Vitest](https://vitest.dev/)，让评估像普通测试一样运行。评估未通过时，链式断言会让测试失败；报告器会在测试输出中打印分数表。

先安装 `@mastra/evals` 和 `vitest`（版本 3、4 或 5）：

```bash
npm install @mastra/evals vitest
```

## 配置 Vitest {/* #configuring-vitest */}

在 `vitest.config.ts` 中注册报告器和匹配器：

```typescript title="vitest.config.ts"
import { defineConfig } from 'vitest/config'
import { MastraEvalsReporter } from '@mastra/evals/vitest'

export default defineConfig({
  test: {
    reporters: ['default', new MastraEvalsReporter()],
    setupFiles: ['@mastra/evals/vitest/setup'],
  },
})
```

设置文件会为 `expect` 注册自定义匹配器。也可以在自己的设置文件中调用 `@mastra/evals/vitest` 提供的 `registerEvalMatchers()`。

## 用 `expectEvals` 断言数据集结果 {/* #asserting-on-a-dataset-with-expectevals */}

`expectEvals` 在普通的 `test()` 内运行 `runEvals` 评估，并断言最低通过率。它接受与 `runEvals` 相同的配置：作为 `target` 的 Agent 或 Workflow、`data` 数据项，以及 `scorers`、`gates` 或阈值。每个门禁对每个数据项给出通过或失败的判定，因此 `toPass(0.8)` 要求至少 80% 的数据项通过所有门禁。评分阈值仍按各项的平均分判定，无论通过率如何，都必须达标：

```typescript title="tests/weather-agent.eval.test.ts"
import { test } from 'vitest'
import { expectEvals } from '@mastra/evals/vitest'
import { checks } from '@mastra/evals/checks'
import { mastra } from '../src/mastra'

test('weather agent calls the tool and answers relevantly', { timeout: 60_000 }, async () => {
  await expectEvals({
    target: mastra.getAgent('weatherAgent'),
    data: [{ input: "What's the weather in London?" }],
    gates: [checks.calledTool('weatherTool'), checks.noToolErrors(), checks.includes('London')],
    scorers: [{ scorer: mastra.getScorer('answerRelevancyScorer'), threshold: 0.7 }],
  }).toPass(0.8)
})
```

不传参数时，`toPass()` 要求每个数据项通过所有门禁。务必等待断言完成：它会返回完整的 `RunEvalsResult`，便于进一步检查，并把本次运行的分数附到当前测试中，供 `MastraEvalsReporter` 显示。

使用 LLM 的评估耗时远超 Vitest 默认的 5 秒超时。请为单个测试传入 `timeout`，或在 Vitest 配置中设置 `testTimeout`。

## 用 `expectEval` 进行矩阵测试 {/* #matrix-testing-with-expecteval */}

`expectEval` 用于单个数据项：`data` 接收一项数据，不接收数组。与 `test.for` 或 `test.each` 搭配使用时，每个数据项都有独立的测试和报告条目，不再按数据集汇总结果：

```typescript title="tests/weather-agent.matrix.eval.test.ts"
import { test } from 'vitest'
import { expectEval } from '@mastra/evals/vitest'
import { checks } from '@mastra/evals/checks'
import { mastra } from '../src/mastra'

test.for([
  { input: "What's the weather in London?", groundTruth: 'London' },
  { input: "What's the weather in Tokyo?", groundTruth: 'Tokyo' },
  { input: "What's the weather in Sydney?", groundTruth: 'Sydney' },
])('weather agent: $input', { timeout: 60_000 }, async item => {
  await expectEval({
    target: mastra.getAgent('weatherAgent'),
    data: item,
    gates: [checks.calledTool('weatherTool'), checks.includes(item.groundTruth)],
  }).toPass()
})
```

各数据项独立判定通过或失败。一项出现回归时，会直接显示对应测试失败，而不会只表现为总通过率下降。

## 使用匹配器断言结果 {/* #asserting-on-results-with-matchers */}

若要更精细地检查结果，可在普通的 `test()` 中直接调用 `runEvals`，再用自定义匹配器断言返回结果：

```typescript title="tests/weather-agent.matchers.eval.test.ts"
import { test, expect } from 'vitest'
import { runEvals } from '@mastra/core/evals'
import { checks } from '@mastra/evals/checks'
import { mastra } from '../src/mastra'

test('weather agent quality', { timeout: 60_000 }, async () => {
  const result = await runEvals({
    target: mastra.getAgent('weatherAgent'),
    data: [{ input: "What's the weather in London?" }],
    scorers: [mastra.getScorer('answerRelevancyScorer')],
    gates: [checks.noToolErrors()],
  })

  expect(result).toHaveVerdict('passed')
  expect(result).toPassGates()
  expect(result).toHaveScoreAbove('answer-relevancy-scorer', 0.7)
})
```

可用的匹配器：

- `toHaveVerdict(verdict)`：断言本次运行的判定结果（`"passed"`、`"scored"` 或 `"failed"`）。
- `toHaveScoreAbove(scorerName, min)` / `toHaveScoreBelow(scorerName, max)`：断言评分器的平均分。按类别配置的评分器使用点分路径，例如 `"agent.my-scorer"` 或 `"steps.step-1.my-scorer"`。
- `toPassGates()`：断言所有门禁均通过。未配置门禁时，断言失败。
- `toPassThresholds()`：断言所有评分器阈值均达标。未配置阈值时，断言失败。

## 评估 Workflow {/* #evaluating-a-workflow */}

Workflow 也可以作为评估目标。将 `WorkflowScorerConfig` 对象用作 `scorers`，即可对 Workflow 输出、单个步骤或步骤执行轨迹评分。在匹配器中用点分路径引用嵌套分数：

```typescript title="tests/weather-workflow.eval.test.ts"
import { test, expect } from 'vitest'
import { runEvals } from '@mastra/core/evals'
import { mastra } from '../src/mastra'

test('weather workflow runs fetch-weather then plan-activities', { timeout: 60_000 }, async () => {
  const result = await runEvals({
    target: mastra.getWorkflow('weatherWorkflow'),
    data: [
      {
        input: { city: 'London' },
        expectedTrajectory: {
          steps: [
            { stepType: 'workflow_step', name: 'fetch-weather' },
            { stepType: 'workflow_step', name: 'plan-activities' },
          ],
        },
      },
      {
        input: { city: 'Tokyo' },
        expectedTrajectory: {
          steps: [
            { stepType: 'workflow_step', name: 'fetch-weather' },
            { stepType: 'workflow_step', name: 'plan-activities' },
          ],
        },
      },
    ],
    scorers: {
      trajectory: [mastra.getScorer('trajectoryAccuracyScorer')],
    },
  })

  expect(result).toHaveScoreAbove('trajectory.code-trajectory-accuracy-scorer', 0.9)
})
```

此 Workflow 的 `plan-activities` 步骤会在运行时调用 `mastra.getAgent('weatherAgent')`。这只有在通过 `mastra.getWorkflow()` 获取评估目标时才有效。完整的 `WorkflowScorerConfig` 结构见 [`runEvals` 参考](/reference/evals/run-evals#workflow-evaluation)。

## 查看报告器输出 {/* #reading-the-reporter-output */}

运行结束后，`MastraEvalsReporter` 会为每个评估测试打印分数表：

```text
 Mastra Evals

✓ weather agent calls the tool and answers relevantly (1 item)
   check-called-tool (gate)                        1.0  ✓
   check-no-tool-errors (gate)                     1.0  ✓
   check-includes (gate)                           1.0  ✓
   answer-relevancy-scorer (threshold: min 0.7)    0.9  ✓

 Eval runs: 1 (1 passed)
```

每个条目显示本次运行的判定结果、门禁、阈值和各评分器的平均分。报告器会读取 `expectEval` 和 `expectEvals` 写入 `task.meta.mastraEval` 的元数据，因此支持并行执行的测试文件，也支持任何填充该字段的测试。

## 速率限制和并发 {/* #rate-limits-and-concurrency */}

Vitest 会并行运行测试文件，`runEvals` 也有自己的 `concurrency` 选项，两层并发叠加会成倍增加 LLM 请求量。如果触发模型 Provider 的速率限制，请降低评估选项中的 `concurrency`，或在 Vitest 配置中设置 `fileParallelism: false`。
