# 维泰集成

这`@mastra/evals/vitest`模块集成[`runEvals`](/reference/evals/run-evals)和[维泰斯特](https://vitest.dev/)因此评估的行为就像常规测试一样。当评估未通过时，流畅的断言将导致测试失败，报告者会在运行器输出中打印分数表。

要使用它，请安装`@mastra/evals` and `vitest` (version 3, 4, or 5):

```bash
npm install @mastra/evals vitest
```

## 配置Vitest {/* #configuring-vitest */}

注册记者和匹配者`vitest.config.ts`:

```typescript title="vitest.config.ts"
import { defineConfig } from 'vitest/config'
import { MastraEvalsReporter } from '@mastra/evals/vitest'

export default defineConfig({
  test: {
    reporters: ['default', new MastraEvalsReporter()],
    setupFiles: ['@mastra/evals/vitest/setup'],
  },
})
```

设置文件在上注册自定义匹配器`expect`. Alternatively, call `registerEvalMatchers()` from `@mastra/evals/vitest` in your own setup file.

## 对数据集进行断言`expectEvals` {/* #asserting-on-a-dataset-with-expectevals */}

`expectEvals`运行一个`runEvals` evaluation inside a regular `test()` and asserts a minimum pass rate. It accepts the same configuration as `runEvals`: a `target` agent or workflow, `data` items, and `scorers`, `gates`，或阈值。盖茨对每个项目的通过/失败进行评分，因此`toPass(0.8)`要求至少 80% 的物品通过每个门。评分者阈值仍然比较各个项目的平均分数，并且无论比率如何都必须通过：

```typescript title="tests/weather-agent.eval.test.ts"
import { test } from 'vitest'
import { expectEvals } from '@mastra/evals/vitest'
import { checks } from '@mastra/evals/checks'
import { mastra } from '../src/mastra'

test('weather agent calls the tool and answers relevantly', { timeout: 60_000 }, async () => {
  await expectEvals({
    target: mastra.getAgent('weatherAgent'),
    data: [{ input: "What's the weather in London?" }],
    gates: [checks.calledTool('weatherTool'), checks.noToolErrors(), checks.includes('London')],
    scorers: [{ scorer: mastra.getScorer('answerRelevancyScorer'), threshold: 0.7 }],
  }).toPass(0.8)
})
```

`toPass()`如果没有参数，则要求每个项目都通过每个门。始终等待断言：它会以完整的方式解决`RunEvalsResult` for further checks and attaches the run's scores to the current test so `MastraEvalsReporter` displays them.

LLM 支持的评估比 Vitest 默认的 5 秒超时慢得多，因此请通过每次测试`timeout` (or set `testTimeout` in the Vitest config).

## 矩阵测试`expectEval` {/* #matrix-testing-with-expecteval */}

`expectEval`是单项变体：`data` is one item instead of an array. Combine it with `test.for` (or `test.each`) to get one test (and one reporter entry) per data item instead of one aggregated result per dataset:

```typescript title="tests/weather-agent.matrix.eval.test.ts"
import { test } from 'vitest'
import { expectEval } from '@mastra/evals/vitest'
import { checks } from '@mastra/evals/checks'
import { mastra } from '../src/mastra'

test.for([
  { input: "What's the weather in London?", groundTruth: 'London' },
  { input: "What's the weather in Tokyo?", groundTruth: 'Tokyo' },
  { input: "What's the weather in Sydney?", groundTruth: 'Sydney' },
])('weather agent: $input', { timeout: 60_000 }, async item => {
  await expectEval({
    target: mastra.getAgent('weatherAgent'),
    data: item,
    gates: [checks.calledTool('weatherTool'), checks.includes(item.groundTruth)],
  }).toPass()
})
```

每个项目独立通过或失败。单一回归显示为一次失败的测试，而不是降低的总通过率。

## 使用匹配器对结果进行断言 {/* #asserting-on-results-with-matchers */}

如需更细粒度的控制，请致电`runEvals` directly inside a regular `test()` and use the custom matchers on the result:

```typescript title="tests/weather-agent.matchers.eval.test.ts"
import { test, expect } from 'vitest'
import { runEvals } from '@mastra/core/evals'
import { checks } from '@mastra/evals/checks'
import { mastra } from '../src/mastra'

test('weather agent quality', { timeout: 60_000 }, async () => {
  const result = await runEvals({
    target: mastra.getAgent('weatherAgent'),
    data: [{ input: "What's the weather in London?" }],
    scorers: [mastra.getScorer('answerRelevancyScorer')],
    gates: [checks.noToolErrors()],
  })

  expect(result).toHaveVerdict('passed')
  expect(result).toPassGates()
  expect(result).toHaveScoreAbove('answer-relevancy-scorer', 0.7)
})
```

可用的匹配器：

* `toHaveVerdict(verdict)`：断言运行的结论（`"passed"`, `"scored"`, or `"failed"`).
* `toHaveScoreAbove(scorerName, min)` / `toHaveScoreBelow(scorerName, max)`: asserts a scorer's average score. Categorized scorer configs use dot-paths, for example `"agent.my-scorer"` or `"steps.step-1.my-scorer"`.
* `toPassGates()`：断言所有门都已通过。未配置门时失败。
* `toPassThresholds()`：断言所有得分者阈值均已通过。未配置阈值时失败。

## 评估Workflow程 {/* #evaluating-a-workflow */}

Workflow程也是有效的目标。使用一个`WorkflowScorerConfig` object for `scorers` to score the workflow output, individual steps, or the step execution trajectory, and reference nested scores with dot-paths in the matchers:

```typescript title="tests/weather-workflow.eval.test.ts"
import { test, expect } from 'vitest'
import { runEvals } from '@mastra/core/evals'
import { mastra } from '../src/mastra'

test('weather workflow runs fetch-weather then plan-activities', { timeout: 60_000 }, async () => {
  const result = await runEvals({
    target: mastra.getWorkflow('weatherWorkflow'),
    data: [
      {
        input: { city: 'London' },
        expectedTrajectory: {
          steps: [
            { stepType: 'workflow_step', name: 'fetch-weather' },
            { stepType: 'workflow_step', name: 'plan-activities' },
          ],
        },
      },
      {
        input: { city: 'Tokyo' },
        expectedTrajectory: {
          steps: [
            { stepType: 'workflow_step', name: 'fetch-weather' },
            { stepType: 'workflow_step', name: 'plan-activities' },
          ],
        },
      },
    ],
    scorers: {
      trajectory: [mastra.getScorer('trajectoryAccuracyScorer')],
    },
  })

  expect(result).toHaveScoreAbove('trajectory.code-trajectory-accuracy-scorer', 0.9)
})
```

这`plan-activities` step in this workflow calls `mastra.getAgent('weatherAgent')` at runtime, which only works because the target was resolved with `mastra.getWorkflow()`. See the [`runEvals` reference](/reference/evals/run-evals#workflow-evaluation) for the full `WorkflowScorerConfig` shape.

## 阅读记者的输出 {/* #reading-the-reporter-output */}

`MastraEvalsReporter`运行完成后打印每个评估测试的分数表：

```text
 Mastra Evals

✓ weather agent calls the tool and answers relevantly (1 item)
   check-called-tool (gate)                        1.0  ✓
   check-no-tool-errors (gate)                     1.0  ✓
   check-includes (gate)                           1.0  ✓
   answer-relevancy-scorer (threshold: min 0.7)    0.9  ✓

 Eval runs: 1 (1 passed)
```

每个条目都会显示运行的结论、门数、阈值以及每个记分员的平均得分。记者查阅元数据得知`expectEval`/`expectEvals` attach to `task.meta.mastraEval`, so it works with parallel test files and any test that populates that field.

## 速率限制和并发数 {/* #rate-limits-and-concurrency */}

Vitest 并行运行测试文件，并且`runEvals` accepts its own `concurrency` option, so total LLM traffic is multiplied across both. If you hit provider rate limits, lower `concurrency` in your eval options or set `fileParallelism: false` in the Vitest config.
