# 多轮评估

多轮评估测试座席在对话中的行为。而不是单一的`input`，你提供一个`inputs`大批。每个条目都按顺序发送到同一线程上的Agent，记分员会看到所有回合的累积输出。

## 何时使用多轮评估 {/* #when-to-use-multi-turn-evals */}

* Agent使用记忆并且必须回忆起之前回合的上下文
* Agent处理取决于先前响应的后续问题
* 您需要验证对话中的Tool调用序列
* Agent运行多步骤Workflow程（搜索、确认、执行）

## 快速入门 {/* #quickstart */}

```typescript title="src/evals/conversation-eval.ts"
import { runEvals } from '@mastra/core/evals'
import { checks } from '@mastra/evals/checks'
import { weatherAgent } from '../agents'

const result = await runEvals({
  data: [
    {
      inputs: [
        'What is the weather in Brooklyn?',
        'What about tomorrow?',
        'Compare the two forecasts.',
      ],
    },
  ],
  target: weatherAgent,
  scorers: [checks.calledTool('get_weather', { times: 2 }), checks.includes('Brooklyn')],
})
```

每个回合运行`agent.generate()` with the same thread ID. The agent sees the full conversation history. Scorers receive the accumulated output messages from all turns.

:::警告\[预建法学硕士评判一级]

预建的 LLM 评判评分器（标题、答案相关性、忠诚度以及其他列出的内容）[Scorer compatibility](#scorer-compatibility)) read a single assistant message, so with `inputs` they grade only the last turn's response. For semantic grading across a conversation, use [`createMultiTurnJudgeScorer()`](/reference/evals/multi-turn-judge), which grades every assistant turn against one criterion, or per-turn [`turns[].scorers`](#per-turn-assertions-with-turns), where each turn grades its own output.

:::

## 交叉转弯回忆需要记忆 {/* #memory-is-required-for-cross-turn-recall */}

多轮召回取决于智能体的**memory store configured**. The shared thread ID is what lets each turn see the earlier ones, but a thread only persists history when the agent has memory. If the agent has no memory configured, the turns still run sequentially and their outputs still accumulate for scoring, but the agent won't recall earlier turns (each input runs in isolation). `runEvals` logs a warning when you use `inputs` on an agent without memory.

`runEvals`通过生成共享来管理对话身份`threadId` and injecting a `resourceId`. Mastra memory scopes messages by resource and thread, so recall requires both values. By default, deriving the resource from the generated thread isolates each conversation. Pass `targetOptions.memory.resource` to pin a resource, such as when reusing an existing user's memory; `runEvals` still owns the thread, so you don't provide one:

```typescript
await runEvals({
  target: weatherAgent,
  data: [{ inputs: ['What is the weather in Brooklyn?', 'What about tomorrow?'] }],
  scorers: [checks.similarity('weather forecast')],
  targetOptions: { memory: { resource: 'user-42' } },
})
```

看[Memory](/docs/memory/overview) for how to configure a memory store.

## 它是如何运作的 {/* #how-it-works */}

当数据项有一个`inputs` array, `runEvals`:

1. 创建一个新线程（唯一`threadId`) and resource for the conversation (a caller-provided `targetOptions.memory.resource` is preserved)
2. 通过顺序发送每个输入`agent.generate()` on that thread
3. 累积各回合的所有输出消息
4. 将全部累积输出传递给评分员进行评估

记分员可以看到完整的对话输出，包括每个回合。

## 评分语义 {/* #scoring-semantics */}

在为多回合项目编写记分器时，这些细节很重要：

* **`run.output`是每轮的累计输出。**&#x57FA;于输出的记分器：`checks.includes`, `checks.calledTool`, `checks.similarity`, and similar: evaluate the whole conversation. For example, `checks.calledTool('get_weather', { times: 2 })` counts calls across all turns.
* **`run.input`只是第一回合的输入。**&#x5C06;输入与输出（忠诚度、答案相关性和其他与输入相关的 LLM 评分者）进行比较的评分者只能看到第一条用户消息，而不是完整的对话。更喜欢基于输出的多轮检查，或构建读取累积值的记分器`run.output` directly.

### 记分员兼容性 {/* #scorer-compatibility */}

仅当记分员读取全部内容时，累积输出才有帮助：

|得分手 |它看到了什么`inputs` |
| - | - |
| [Quick Checks](/docs/evals/quick-checks): `checks.calledTool`, `checks.includes`, `checks.similarity`, `checks.noToolErrors`, and the rest | The whole conversation. Tool-call checks count calls across every turn, and text checks search all assistant text |
| [Multi-turn Judge scorer](/reference/evals/multi-turn-judge) | Every assistant turn, graded together against one plain-English criterion |
| Prebuilt LLM-judge scorers: rubric, answer relevancy, answer similarity, faithfulness, hallucination, bias, toxicity, context precision, context recall, context relevance, noise sensitivity, prompt alignment, summarization | Only the last assistant message that carries text. Input-relative judges also see only the first turn's input |
| Trajectory scorers (`AgentScorerConfig.trajectory`) | The last turn's span when traces are available, otherwise tool calls from all accumulated messages |
| Custom scorers | Whatever they read from `run.output` |

### 对整个对话进行评分 {/* #grading-a-whole-conversation */}

要一起判断每个回合，请使用[`createMultiTurnJudgeScorer()`](/reference/evals/multi-turn-judge). It builds a transcript of every assistant turn and asks a judge model whether the conversation satisfies one plain-English criterion, scoring `1` or `0`:

```typescript title="src/evals/trip-planning-eval.ts"
import { runEvals } from '@mastra/core/evals'
import { createMultiTurnJudgeScorer } from '@mastra/evals/scorers/prebuilt'
import { weatherAgent } from '../agents'

const result = await runEvals({
  data: [
    {
      inputs: [
        "How's the weather in London?",
        'And Paris?',
        'Should I pack an umbrella for London?',
      ],
    },
  ],
  target: weatherAgent,
  scorers: [
    {
      scorer: createMultiTurnJudgeScorer({
        model: '__GATEWAY_ANTHROPIC_MODEL_HAIKU__',
        criterion:
          'The agent provided forecasts for London and Paris, and gave weather-appropriate packing advice.',
      }),
      threshold: 1,
    },
  ],
})
```

要对标准无法表达的内容进行评分，请编写自己的评分器，从其中读取辅助消息`run.output`. [`extractAgentResponseMessages()`](/reference/evals/scorer-utils#extractagentresponsemessages) returns the text of each assistant message, in order:

```typescript title="src/evals/conversation-judge.ts"
import { createScorer } from '@mastra/core/evals'
import { extractAgentResponseMessages } from '@mastra/evals/scorers/utils'
import { z } from 'zod'

export const conversationJudge = createScorer({
  id: 'conversation-judge',
  name: 'Conversation Judge',
  description: 'Grades every assistant turn in a conversation against one criterion',
  type: 'agent',
  judge: {
    model: '__GATEWAY_ANTHROPIC_MODEL_HAIKU__',
    instructions: 'You grade multi-turn assistant transcripts against a single criterion.',
  },
})
  .analyze({
    description: 'Judge the transcript as a whole',
    outputSchema: z.object({ satisfied: z.boolean(), reason: z.string() }),
    createPrompt: ({ run }) => {
      const transcript = extractAgentResponseMessages(run.output)
        .map((text, index) => `Turn ${index + 1}: ${text}`)
        .join('\n\n')

      return `Grade this conversation:\n\n${transcript}\n\nCriterion: the assistant keeps the forecast consistent across turns.`
    },
  })
  .generateScore(({ results }) => (results.analyzeStepResult?.satisfied ? 1 : 0))
  .generateReason(({ results }) => results.analyzeStepResult?.reason ?? '')
```

传递给`runEvals` like any other scorer. See [Custom scorers](/docs/evals/custom-scorers) for the full `createScorer()` pipeline.

## 每回合断言`turns` {/* #per-turn-assertions-with-turns */}

这`inputs` form scores the **accumulated** output as a whole, a single score over every turn's output. That can hide per-turn failures: an output-based check like `checks.includes('Brooklyn')` passes if *any* turn mentions Brooklyn, even when the follow-up turn is broken.

当你需要断言**specific turn** behaved correctly, use `turns` instead. Each turn is an object with its own `input` and optional `gates`/`scorers` that evaluate **only that turn's** input and output:

```typescript title="src/evals/per-turn-eval.ts"
import { runEvals } from '@mastra/core/evals'
import { checks } from '@mastra/evals/checks'
import { weatherAgent } from '../agents'

const result = await runEvals({
  data: [
    {
      turns: [
        {
          input: 'What is the weather in Brooklyn?',
          gates: [checks.calledTool('get_weather')],
        },
        {
          // The follow-up must call the tool again — it can't be satisfied
          // by the first turn's tool call.
          input: 'What about tomorrow?',
          gates: [checks.calledTool('get_weather')],
          scorers: [{ scorer: checks.similarity('tomorrow forecast'), threshold: 0.5 }],
        },
      ],
    },
  ],
  target: weatherAgent,
})

result.verdict // 'passed' | 'scored' | 'failed'
result.turnResults // per-turn gate/threshold/scorer outcomes
```

语义：

* 每回合门或记分员收到**only that turn's** `run.input` and `run.output`, rather than the accumulated conversation. A different turn's output can't satisfy the check, and `run.input` contains the input for the turn being evaluated.
* 每回合的结果折算成[verdict](/docs/evals/gates-and-verdicts): a failing turn gate makes the verdict `failed`. A missed turn threshold (with gates passing) makes it `scored`.
* `result.turnResults[i]`报告每个回合的`gateResults`, `thresholdResults`, and `scores`. A failure points at the exact turn. Across multiple conversations, turn results are averaged by turn index.
* 一个回合没有`gates` or `scorers` advances the conversation.
* 顶级`scorers`/`gates` still run as a whole over the accumulated output, so you can combine "this turn must call the tool" with "the answer mentions Brooklyn."
* 当Agent配置了存储时，每个回合记分器/门结果都会像顶级分数一样保留，因此每回合结果会显示在您的分数存储中。每个存储的每回合分数都使用其回合索引作为标签（`metadata.turnIndex`) and shares the conversation's `threadId`. It also includes a link to that turn's trace span.

使用`inputs` when a single whole-conversation score over the whole conversation is enough. Use `turns` when correctness depends on individual turns. `turns` can't be combined with `input` or `inputs` in the same data item.

## 与门和阈值结合 {/* #combining-with-gates-and-thresholds */}

多轮数据项与[gates and verdicts](/docs/evals/gates-and-verdicts). Use output-based scorers so gating reflects the full conversation:

```typescript title="src/evals/memory-eval.ts"
import { runEvals } from '@mastra/core/evals'
import { checks } from '@mastra/evals/checks'

const result = await runEvals({
  data: [
    {
      inputs: ['My favorite city is Brooklyn.', 'What is the weather in my favorite city?'],
    },
  ],
  target: weatherAgent,
  gates: [checks.calledTool('get_weather')],
  scorers: [{ scorer: checks.similarity('Brooklyn weather forecast'), threshold: 0.5 }],
})

result.verdict // 'passed' | 'scored' | 'failed'
```

## 单匝和多匝混合 {/* #mixing-single-turn-and-multi-turn */}

单个`runEvals` call can include both single-turn and multi-turn data items:

```typescript title="src/evals/mixed-eval.ts"
const result = await runEvals({
  data: [
    { input: 'What is the weather in Brooklyn?' },
    {
      inputs: ['My favorite city is Brooklyn.', 'What is the weather in my favorite city?'],
    },
  ],
  target: weatherAgent,
  scorers: [checks.includes('Brooklyn')],
})
```

单转物品使用`input` as usual. Multi-turn items use `inputs`, `input` can be omitted entirely.

## 验证 {/* #validation */}

`runEvals`抛出一个`MastraError` if `inputs` is present but empty:

```typescript
// Throws: 'inputs' must be a non-empty array
await runEvals({
  data: [{ inputs: [] }],
  target: myAgent,
  scorers: [myScorer],
})
```
