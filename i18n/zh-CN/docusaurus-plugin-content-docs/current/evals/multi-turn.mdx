# 多轮评估

多轮评估用于测试 Agent 在整段对话中的行为。你提供的是 `inputs` 数组，而非单个 `input`。数组中的条目会在同一线程中依次发给 Agent，评分器会收到所有轮次累积的输出。

## 何时使用多轮评估 {/* #when-to-use-multi-turn-evals */}

- Agent 使用记忆，需要回忆前面轮次的上下文
- Agent 要处理依赖此前回复的追问
- 需要验证整段对话中的工具调用顺序
- Agent 执行多步骤 Workflow（搜索、确认、执行）

## 快速入门 {/* #quickstart */}

```typescript title="src/evals/conversation-eval.ts"
import { runEvals } from '@mastra/core/evals'
import { checks } from '@mastra/evals/checks'
import { weatherAgent } from '../agents'

const result = await runEvals({
  data: [
    {
      inputs: [
        'What is the weather in Brooklyn?',
        'What about tomorrow?',
        'Compare the two forecasts.',
      ],
    },
  ],
  target: weatherAgent,
  scorers: [checks.calledTool('get_weather', { times: 2 }), checks.includes('Brooklyn')],
})
```

每一轮都使用同一个线程 ID 调用 `agent.generate()`。Agent 能看到完整的对话历史，评分器会收到所有轮次累积的输出消息。

:::warning[内置 LLM 评分器只评估一轮]

内置 LLM 评分器（如评分准则、答案相关性、忠实度及[评分器兼容性](#scorer-compatibility)中列出的其他评分器）只读取一条助手消息，因此使用 `inputs` 时只评估最后一轮的回复。要对整段对话做语义评分，可用 [`createMultiTurnJudgeScorer()`](/reference/evals/multi-turn-judge) 按同一标准评估助手的所有轮次，或用逐轮的 [`turns[].scorers`](#per-turn-assertions-with-turns) 分别评估各轮输出。

:::

## 跨轮次回忆需要配置记忆 {/* #memory-is-required-for-cross-turn-recall */}

要回忆此前轮次的内容，Agent 必须**配置记忆存储**。各轮通过共享线程 ID 访问此前轮次，但只有启用记忆的 Agent 才会在线程中保留对话历史。未配置记忆时，各轮仍依次执行，输出也会累积用于评分，但每条输入会独立运行，Agent 无法回忆此前的内容。对没有记忆的 Agent 使用 `inputs` 时，`runEvals` 会记录警告。

`runEvals` 通过生成共享的 `threadId` 并注入 `resourceId` 来标识对话。Mastra 的记忆按资源和线程划分消息，因此回忆历史时需要这两个值。默认从生成的线程派生资源，使各段对话彼此隔离。要固定资源，例如复用现有用户的记忆，请传入 `targetOptions.memory.resource`。线程仍由 `runEvals` 管理，无需自行提供：

```typescript
await runEvals({
  target: weatherAgent,
  data: [{ inputs: ['What is the weather in Brooklyn?', 'What about tomorrow?'] }],
  scorers: [checks.similarity('weather forecast')],
  targetOptions: { memory: { resource: 'user-42' } },
})
```

配置记忆存储的方法见[记忆](/docs/memory/overview)。

## 工作原理 {/* #how-it-works */}

数据条目含有 `inputs` 数组时，`runEvals` 会：

1. 为对话创建新线程（拥有唯一的 `threadId`）和资源，保留调用方传入的 `targetOptions.memory.resource`
1. 在该线程中通过 `agent.generate()` 依次发送各条输入
1. 累积所有轮次的输出消息
1. 将累积的完整输出交给评分器评估

评分器可以看到完整的对话输出，覆盖每一轮。

## 评分语义 {/* #scoring-semantics */}

为多轮数据条目编写评分器时，请注意以下细节：

- **`run.output` 是所有轮次的累积输出。** `checks.includes`、`checks.calledTool`、`checks.similarity` 等基于输出的评分器会评估整段对话。例如，`checks.calledTool('get_weather', { times: 2 })` 会统计所有轮次中的调用。
- **`run.input` 只包含首轮输入。** 比较输入与输出的评分器（如忠实度、答案相关性及其他依赖输入的 LLM 评分器）只看到第一条用户消息，无法看到完整对话。多轮评估宜优先采用基于输出的检查，或编写直接读取累积 `run.output` 的评分器。

### 评分器兼容性 {/* #scorer-compatibility */}

评分器需要读完累积输出，才能充分利用这些信息：

| 评分器 | 使用 `inputs` 时可读取的内容 |
| - | - |
| [Quick Checks](/docs/evals/quick-checks)（`checks.calledTool`、`checks.includes`、`checks.similarity`、`checks.noToolErrors` 等） | 整段对话。工具调用检查会统计所有轮次的调用，文本检查会搜索助手的全部文本。 |
| [多轮判分评分器](/reference/evals/multi-turn-judge) | 助手的所有轮次，按一条用通俗英语写成的标准统一评分。 |
| 内置 LLM 评分器：评分准则、答案相关性、答案相似度、忠实度、幻觉、偏见、毒性、上下文精确率、上下文召回率、上下文相关性、噪声敏感度、提示词对齐、摘要 | 仅最后一条带文本的助手消息。依赖输入的评分器也只会读取首轮输入。 |
| 执行轨迹评分器（`AgentScorerConfig.trajectory`） | 有 Trace 时读取最后一轮的 Span，否则读取所有累积消息中的工具调用。 |
| 自定义评分器 | 由评分器从 `run.output` 读取的内容。 |

### 为整段对话评分 {/* #grading-a-whole-conversation */}

要综合评估所有轮次，请使用 [`createMultiTurnJudgeScorer()`](/reference/evals/multi-turn-judge)。它会整理助手所有轮次的文字记录，由判分模型判断对话是否符合一条用通俗英语写成的标准，给出 `1` 或 `0` 分：

```typescript title="src/evals/trip-planning-eval.ts"
import { runEvals } from '@mastra/core/evals'
import { createMultiTurnJudgeScorer } from '@mastra/evals/scorers/prebuilt'
import { weatherAgent } from '../agents'

const result = await runEvals({
  data: [
    {
      inputs: [
        "How's the weather in London?",
        'And Paris?',
        'Should I pack an umbrella for London?',
      ],
    },
  ],
  target: weatherAgent,
  scorers: [
    {
      scorer: createMultiTurnJudgeScorer({
        model: '__GATEWAY_ANTHROPIC_MODEL_HAIKU__',
        criterion:
          'The agent provided forecasts for London and Paris, and gave weather-appropriate packing advice.',
      }),
      threshold: 1,
    },
  ],
})
```

如果要评估的内容无法用这条标准表达，可编写自己的评分器，从 `run.output` 中读取助手消息。[`extractAgentResponseMessages()`](/reference/evals/scorer-utils#extractagentresponsemessages) 会按顺序返回每条助手消息的文本：

```typescript title="src/evals/conversation-judge.ts"
import { createScorer } from '@mastra/core/evals'
import { extractAgentResponseMessages } from '@mastra/evals/scorers/utils'
import { z } from 'zod'

export const conversationJudge = createScorer({
  id: 'conversation-judge',
  name: 'Conversation Judge',
  description: 'Grades every assistant turn in a conversation against one criterion',
  type: 'agent',
  judge: {
    model: '__GATEWAY_ANTHROPIC_MODEL_HAIKU__',
    instructions: 'You grade multi-turn assistant transcripts against a single criterion.',
  },
})
  .analyze({
    description: 'Judge the transcript as a whole',
    outputSchema: z.object({ satisfied: z.boolean(), reason: z.string() }),
    createPrompt: ({ run }) => {
      const transcript = extractAgentResponseMessages(run.output)
        .map((text, index) => `Turn ${index + 1}: ${text}`)
        .join('\n\n')

      return `Grade this conversation:\n\n${transcript}\n\nCriterion: the assistant keeps the forecast consistent across turns.`
    },
  })
  .generateScore(({ results }) => (results.analyzeStepResult?.satisfied ? 1 : 0))
  .generateReason(({ results }) => results.analyzeStepResult?.reason ?? '')
```

像其他评分器一样将它传给 `runEvals`。完整的 `createScorer()` 流程见[自定义评分器](/docs/evals/custom-scorers)。

## 使用 `turns` 逐轮断言 {/* #per-turn-assertions-with-turns */}

使用 `inputs` 会对各轮**累积**的输出给出一个总分，可能掩盖个别轮次的失败。例如，基于输出的 `checks.includes('Brooklyn')` 只要在 _任意_ 一轮看到 Brooklyn 就会通过，即使后续轮次出了问题。

要断言**某一轮**的行为正确，请使用 `turns`。每轮都是一个对象，有自己的 `input` 和可选的 `gates` 或 `scorers`，用于评估**该轮**的输入和输出：

```typescript title="src/evals/per-turn-eval.ts"
import { runEvals } from '@mastra/core/evals'
import { checks } from '@mastra/evals/checks'
import { weatherAgent } from '../agents'

const result = await runEvals({
  data: [
    {
      turns: [
        {
          input: 'What is the weather in Brooklyn?',
          gates: [checks.calledTool('get_weather')],
        },
        {
          // The follow-up must call the tool again — it can't be satisfied
          // by the first turn's tool call.
          input: 'What about tomorrow?',
          gates: [checks.calledTool('get_weather')],
          scorers: [{ scorer: checks.similarity('tomorrow forecast'), threshold: 0.5 }],
        },
      ],
    },
  ],
  target: weatherAgent,
})

result.verdict // 'passed' | 'scored' | 'failed'
result.turnResults // per-turn gate/threshold/scorer outcomes
```

逐轮评估的规则如下：

- 每轮的门禁或评分器**只接收该轮**的 `run.input` 和 `run.output`，不会收到整段对话的累积结果。其他轮次的输出无法让该检查通过，`run.input` 始终是当前评估轮次的输入。
- 逐轮结果会纳入最终[判定](/docs/evals/gates-and-verdicts)。有一轮未通过门禁，判定就是 `failed`。门禁都通过但有一轮未达到分数阈值，判定就是 `scored`。
- `result.turnResults[i]` 提供各轮的 `gateResults`、`thresholdResults` 和 `scores`。失败时可以定位到具体轮次。评估多段对话时，按轮次索引对结果取平均。
- 没有 `gates` 或 `scorers` 的轮次只推进对话。
- 顶层 `scorers` 和 `gates` 仍对累积输出整体执行，因此可以同时要求「这一轮必须调用工具」和「回答提到 Brooklyn」。
- 如果 Agent 配置了存储，每轮的评分器和门禁结果都会像顶层分数一样持久化，可在分数存储中查看。每条已保存的逐轮分数以轮次索引（`metadata.turnIndex`）为标签，共用对话的 `threadId`，并包含指向该轮 Trace Span 的链接。

只需给整段对话一个分数时，用 `inputs`。正确性取决于个别轮次时，用 `turns`。同一个数据条目中，`turns` 不能与 `input` 或 `inputs` 同时使用。

## 结合门禁和阈值 {/* #combining-with-gates-and-thresholds */}

多轮数据条目支持[门禁与判定](/docs/evals/gates-and-verdicts)。使用基于输出的评分器，让门禁覆盖整段对话：

```typescript title="src/evals/memory-eval.ts"
import { runEvals } from '@mastra/core/evals'
import { checks } from '@mastra/evals/checks'

const result = await runEvals({
  data: [
    {
      inputs: ['My favorite city is Brooklyn.', 'What is the weather in my favorite city?'],
    },
  ],
  target: weatherAgent,
  gates: [checks.calledTool('get_weather')],
  scorers: [{ scorer: checks.similarity('Brooklyn weather forecast'), threshold: 0.5 }],
})

result.verdict // 'passed' | 'scored' | 'failed'
```

## 混用单轮和多轮数据条目 {/* #mixing-single-turn-and-multi-turn */}

一次 `runEvals` 调用可以同时包含单轮和多轮数据条目：

```typescript title="src/evals/mixed-eval.ts"
const result = await runEvals({
  data: [
    { input: 'What is the weather in Brooklyn?' },
    {
      inputs: ['My favorite city is Brooklyn.', 'What is the weather in my favorite city?'],
    },
  ],
  target: weatherAgent,
  scorers: [checks.includes('Brooklyn')],
})
```

单轮条目照常使用 `input`。多轮条目使用 `inputs`，可以完全省略 `input`。

## 参数校验 {/* #validation */}

提供了 `inputs` 但数组为空时，`runEvals` 会抛出 `MastraError`：

```typescript
// Throws: 'inputs' must be a non-empty array
await runEvals({
  data: [{ inputs: [] }],
  target: myAgent,
  scorers: [myScorer],
})
```
