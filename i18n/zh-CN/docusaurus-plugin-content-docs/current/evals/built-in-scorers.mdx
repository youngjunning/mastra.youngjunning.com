# 内置评分器

Mastra 提供一套用于评估 AI 输出的内置评分器，针对常见评估场景做了优化，可直接用于 Agent 和 Workflow。

如需自行编写评分器，请参阅[自定义评分器](/docs/evals/custom-scorers)指南。

## 可用评分器 {/* #available-scorers */}

### 准确性和可靠性 {/* #accuracy-and-reliability */}

这些评分器评估 Agent 回答的正确性、真实性和完整性：

- [`answer-relevancy`](/reference/evals/answer-relevancy)：评估回答是否切合输入的问题（`0-1`，越高越好）
- [`answer-similarity`](/reference/evals/answer-similarity)：在 CI/CD 测试中通过语义分析比较 Agent 输出与标准答案（`0-1`，越高越好）
- [`faithfulness`](/reference/evals/faithfulness)：衡量回答是否准确反映给定的上下文（`0-1`，越高越好）
- [`hallucination`](/reference/evals/hallucination)：检测与事实矛盾或缺乏依据的说法（`0-1`，越低越好）
- [`completeness`](/reference/evals/completeness)：检查回答是否包含所有必要信息（`0-1`，越高越好）
- [`content-similarity`](/reference/evals/content-similarity)：逐字符匹配以衡量文本相似度（`0-1`，越高越好）
- [`textual-difference`](/reference/evals/textual-difference)：衡量字符串之间的文本差异（`0-1`，越高表示越相似）
- [`tool-call-accuracy`](/reference/evals/tool-call-accuracy)：评估 LLM 是否从可用工具中选对了 Tool（`0-1`，越高越好）
- [`trajectory-accuracy`](/reference/evals/trajectory-accuracy)：检查各类 span 的操作是否符合预期顺序，涵盖 Tool、模型活动和 Workflow 步骤（`0-1`，越高越好）
- [`prompt-alignment`](/reference/evals/prompt-alignment)：衡量 Agent 回答是否符合用户提示的意图、要求、完整性和格式（`0-1`，越高越好）
- [`multi-turn-judge`](/reference/evals/multi-turn-judge)：按用普通英语表述的标准，对[多轮对话](/docs/evals/multi-turn)中助手的每轮回复评分（`0` 或 `scale`，默认为 `1`）

### 上下文质量 {/* #context-quality */}

这些评分器衡量生成回答时所用上下文的质量和相关性：

- [`context-precision`](/reference/evals/context-precision)：用平均精度均值评估上下文排序，相关内容越靠前，得分越高（`0-1`，越高越好）
- [`context-relevance`](/reference/evals/context-relevance)：按相关程度和使用情况衡量上下文的作用，并检测缺失的上下文（`0-1`，越高越好）

:::tip[上下文评分器选择]

- 如果上下文顺序很重要，且需要标准的信息检索指标，请用 **Context Precision**（适合评估 RAG 排序）。
- 如果需要细查相关性、跟踪上下文使用情况并找出缺失内容，请用 **Context Relevance**。

两个上下文评分器都支持：

* **静态上下文**：预定义的上下文数组
* **动态上下文提取**：使用自定义函数从运行中提取上下文（非常适合 RAG 系统、矢量数据库等）

:::

### 输出质量 {/* #output-quality */}

这些评分者评估对格式、风格和安全要求的遵守情况：

- [`tone-consistency`](/reference/evals/tone-consistency)：衡量正式程度、复杂度和风格是否一致（`0-1`，越高越好）
- [`toxicity`](/reference/evals/toxicity)：检测有害或不当内容（`0-1`，越低越好）
- [`bias`](/reference/evals/bias)：检测输出中潜在的偏见（`0-1`，越低越好）
- [`keyword-coverage`](/reference/evals/keyword-coverage)：评估技术术语的使用情况（`0-1`，越高越好）

### 快速检查 {/* #quick-checks */}

这些轻量评分器无需调用 LLM，可以快速执行确定性断言。用法见[快速检查](/docs/evals/quick-checks)指南。

* [`checks.includes`](/reference/evals/checks#checksincludesexpected-options)：如果输出包含子字符串 (`0` or `1`)
* [`checks.excludes`](/reference/evals/checks#checksexcludesunwanted-options)：如果输出不包含子字符串（`0` or `1`)
* [`checks.equals`](/reference/evals/checks#checksequalsexpected-options)：如果输出与字符串匹配则得分 1，默认情况下忽略大小写（`0` or `1`)
* [`checks.matches`](/reference/evals/checks#checksmatchespattern-options)：如果输出与正则表达式匹配，则得分 1（`0` or `1`)
- [`checks.similarity`](/reference/evals/checks#checkssimilarityexpected-options)：用 Dice 系数衡量字符串相似度（`0-1`，也可按阈值给出二元分数）
* [`checks.calledTool`](/reference/evals/checks#checkscalledtooltoolname-options)：如果某个Tool被调用至少 N 次，则得分 1（`0` or `1`)
* [`checks.didNotCall`](/reference/evals/checks#checksdidnotcalltoolname)：如果未调用Tool则得 1 分（`0` or `1`)
* [`checks.toolOrder`](/reference/evals/checks#checkstoolorderexpectedorder)：如果按顺序调用Tool则得 1 分（`0` or `1`)
* [`checks.maxToolCalls`](/reference/evals/checks#checksmaxtoolcallsmax)：如果Tool调用次数在限制范围内，则得分 1（`0` or `1`)
* [`checks.usedNoTools`](/reference/evals/checks#checksusednotools)：如果没有调用任何Tool，则得分 1（`0` or `1`)
* [`checks.noToolErrors`](/reference/evals/checks#checksnotoolerrors)：如果Tool调用没有错误，则得分 1（`0` or `1`)
