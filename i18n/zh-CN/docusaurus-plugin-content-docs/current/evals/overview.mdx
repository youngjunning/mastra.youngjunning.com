# 埃瓦尔斯

虽然传统的软件测试具有明确的通过/失败条件，但人工智能输出是不确定的，它们可能会随着相同的输入而变化。**Scorers**通过提供衡量Agent质量的量化指标来帮助弥补这一差距。

评分器是使用模型分级、基于规则和统计方法评估Agent输出的自动化测试。得分手归来**scores**: numerical values (typically between 0 and 1) that quantify how well an output meets your evaluation criteria. These scores enable you to objectively track performance and compare different approaches while identifying areas for improvement in your AI systems. Scorers can be customized with your own prompts and scoring functions.

记分员可以在云端运行以捕获实时结果。评分器还可以成为 CI/CD 管道的一部分，用于随着时间的推移测试和监控Agent。

记分员测量单一输出。要随着时间的推移改进Agent，请将它们与[datasets](/docs/evals/datasets), which store versioned test cases, and [experiments](/docs/evals/experiments), which run an agent or workflow against a dataset, optionally score each result, and keep the results for comparison. [Build an eval loop](/docs/guides/build-an-eval-loop)一起使用它们。

## 得分手的类型 {/* #types-of-scorers */}

Mastra 提供不同类型的记分器，每种记分器都有特定的用途。以下是一些常见的类型：

1. **文本记分器**：评估座席响应的准确性、可靠性和上下文理解
2. **分类记分员**：测量基于预定义类别的数据分类的准确性
3. **即时工程记分员**：探索不同指令和输入格式的影响

## 安装 {/* #installation */}

要访问 Mastra 的记分器功能，请安装`@mastra/evals` package.

```bash npm2yarn
npm install @mastra/evals@latest
```

## 现场评估 {/* #live-evaluations */}

**现场评估**允许您在Agent和Workflow程运行时实时自动对 AI 输出进行评分。评分器不是手动或批量运行评估，而是与 AI 系统一起异步运行，提供持续的质量监控。

### 向Agent添加记分员 {/* #adding-scorers-to-agents */}

您可以向Agent添加内置记分器以自动评估其输出。请参阅[full list of built-in scorers](/docs/evals/built-in-scorers) for all available options.

```typescript title="src/mastra/agents/evaluated-agent.ts"
import { Agent } from '@mastra/core/agent'
import { createAnswerRelevancyScorer, createToxicityScorer } from '@mastra/evals/scorers/prebuilt'

export const evaluatedAgent = new Agent({
  id: 'evaluated-agent',
  scorers: {
    relevancy: {
      scorer: createAnswerRelevancyScorer({ model: '__GATEWAY_OPENAI_MODEL_LUNA__' }),
      sampling: { type: 'ratio', rate: 0.5 },
    },
    safety: {
      scorer: createToxicityScorer({ model: '__GATEWAY_OPENAI_MODEL_LUNA__' }),
      sampling: { type: 'ratio', rate: 1 },
    },
  },
})
```

### 将记分员添加到Workflow程步骤 {/* #adding-scorers-to-workflow-steps */}

您还可以将评分员添加到各个Workflow程步骤中，以评估流程中特定点的输出。每个评分者都会收到该步骤自己的输入和输出，因此您可以衡量每个步骤的质量，而不仅仅是对最终答案进行评分：

```typescript title="src/mastra/workflows/content-generation.ts"
import { createWorkflow, createStep } from '@mastra/core/workflows'
import { z } from 'zod'
import { customStepScorer } from '../scorers/custom-step-scorer'

const contentStep = createStep({
  id: 'content-step',
  inputSchema: z.object({ topic: z.string() }),
  outputSchema: z.object({ content: z.string() }),
  scorers: {
    customStepScorer: {
      scorer: customStepScorer(),
      sampling: {
        type: 'ratio',
        rate: 1, // Score every step execution
      },
    },
  },
  execute: async ({ inputData }) => {
    return { content: await generateContent(inputData.topic) }
  },
})

export const contentWorkflow = createWorkflow({
  id: 'content-workflow',
  inputSchema: z.object({ topic: z.string() }),
  outputSchema: z.object({ content: z.string() }),
})
  .then(contentStep)
  .commit()
```

对于阶梯级`scorers` API, see the [Step class reference](/reference/workflows/step#scoring-step-output).

### 实时评估如何运作 {/* #how-live-evaluations-work */}

**异步执行**：实时评估在后台运行，不会阻止Agent响应或Workflow程执行。您的人工智能系统在实时评估对其进行监控的同时保持响应。

**取样控制**： 这`sampling.rate` parameter (0-1) controls what fraction of outputs get scored:

* `1.0`：对每个回答进行评分（100%）
* `0.5`：占所有回复的一半 (50%)
* `0.1`：对 10% 的回答进行评分
* `0.0`：禁用评分

每条轨迹的采样都是确定性的：决策源自轨迹 ID，而不是随机抽取。在实践中：

* 以相同速率配置的评分器会对相同的跟踪进行评分，因此它们的分数在共享流量上具有可比性。
* 重新运行相同的跟踪会产生相同的采样决策，因此采样的覆盖范围是可重现的。

当运行没有跟踪（未配置可观察性）时，决策将改为从运行 ID 派生。如果[trace sampling](../observability/tracing/overview) declined the trace, scorers skip that run entirely, so scores aren't created for traces that were never stored.

**资格过滤器**: 可选的`filter` parameter uses a declarative predicate over the run context to restrict scorer eligibility. Because filtering occurs before sampling, `sampling.rate` applies only to matching runs:

```typescript title="src/mastra/agents/evaluated-agent.ts"
import { Agent } from '@mastra/core/agent'

export const myAgent = new Agent({
  // ...
  scorers: {
    relevancy: {
      scorer: createAnswerRelevancyScorer({ model: '__GATEWAY_OPENAI_MODEL_LUNA__' }),
      filter: {
        op: 'eq',
        left: { path: 'requestContext.plan' },
        right: { literal: 'enterprise' },
      },
      sampling: { type: 'ratio', rate: 0.1 },
    },
  },
})
```

这仅占企业计划流量的 10%，其余均不得分。要以不同的速率对不同的片段进行评分，请使用互补过滤器将同一评分器绑定两次。

谓词可以参考`requestContext.*`, `entity.*`, `entityType`, `source`, `threadId`, `resourceId`, and `projectId`. They support comparisons (`eq`, `ne`, `lt`, `lte`, `gt`, `gte`), membership (`in`, `notIn`), existence (`exists`, `notExists`), truthiness (`truthy`, `falsy`), and boolean composition (`and`, `or`, `not`). A filter that references an unknown root fails at agent construction rather than silently skipping scoring at runtime. Filters are plain JSON, so they're unaffected by durable agent state serialization.

资格过滤器决定*whether a scorer runs*; to filter *which messages a scorer sees* once it runs, use [`filterRun()`](/reference/evals/filter-run). Filters can't see the run's input or output. When eligibility depends on what happened in the run, such as whether a specific tool was called, return [`notScorable()`](/reference/evals/not-scorable) from a scorer step instead: the remaining steps are skipped and no score is stored.

**自动存储**：所有评分结果自动存储在`mastra_scorers` table in your configured database, allowing you to analyze performance trends over time.

## 分数持久性 {/* #score-persistence */}

当 Mastra 实例有时，分数会被保留`storage` configured, and when the scorer is registered on that instance. Registration is what lets Mastra resolve the scorer's metadata (name, description, type) through [`getScorerById()`](/reference/core/getScorerById) before writing the score.

您附加到Agent或Workflow程步骤的记分员会自行注册。您直接传给的得分手[`runEvals()`](/reference/evals/run-evals), including [Quick Checks](/docs/evals/quick-checks), need the `scorers` option on the [`Mastra` class](/reference/core/mastra-class):

```typescript title="src/mastra/index.ts"
import { Mastra } from '@mastra/core'
import { LibSQLStore } from '@mastra/libsql'
import { checks } from '@mastra/evals/checks'
import { createAnswerRelevancyScorer } from '@mastra/evals/scorers/prebuilt'
import { myAgent } from './agents/my-agent'

export const mastra = new Mastra({
  agents: { myAgent },
  storage: new LibSQLStore({ url: 'file:./mastra.db' }),
  scorers: {
    calledTool: checks.calledTool('get_weather'),
    includes: checks.includes('Brooklyn'),
    relevancy: createAnswerRelevancyScorer({ model: '__GATEWAY_OPENAI_MODEL_LUNA__' }),
  },
})
```

该查找仅比较记分器 ID，这允许注册实例使用与评估实例不同的配置。每一个`checks.calledTool()` instance uses the ID `check-called-tool`. Registering one therefore covers every tool name you evaluate.

这些论点仍然影响着`description` stored alongside each score, which comes from the registered instance, not the one you evaluate with. `checks.calledTool('')` is accepted and persists scores fine, but stores `Checks that "" was called`, so pass a representative value.

跳过注册不会改变评分结果，但每次保存都会失败并显示`Scorer with id <id> not found` warning and the scores never reach the store.

## 跟踪评估 {/* #trace-evaluations */}

除了实时评估之外，您还可以使用评分器来评估座席交互和Workflow程的历史跟踪。

这对于分析过去的性能或调试问题，或者运行批量评估特别有用。

:::注意\[需要可观察性]

要对跟踪进行评分，您必须首先在 Mastra 实例中配置可观察性以收集跟踪数据。看[Tracing documentation](../observability/tracing/overview) for setup instructions.

:::

## 工作室 {/* #studio */}

要对痕迹进行评分，您首先需要向 Mastra 实例注册您的评分器：

```typescript
const mastra = new Mastra({
  scorers: {
    answerRelevancy: myAnswerRelevancyScorer,
    responseQuality: myResponseQualityScorer,
  },
})
```

注册后，您可以在 Studio 中以交互方式对痕迹进行评分**Observability** section. Open Studio to manage scorers and review scores, plus run experiments.

* **进球名单**：浏览所有注册的记分员及其描述，以及每个记分员所附加的Agent和Workflow程的数量。
* **评分结果**：选择一个记分器以查看其生成的每个乐谱的分页列表。单击某一行可打开详细面板，显示评分值、原因、输入、输出以及评委使用的提示。在此面板中，将任何结果保存为数据集项目以供将来的实验使用。
* **Agent评估选项卡**：打开任何Agent上的“评估”选项卡以管理评分器和数据集。您还可以在那里进行实验。实验结果显示每个项目的分数以及通过/失败状态和版本标签。
* **跟踪评分**：在可观察性部分中，针对任何历史跟踪或跨度运行评分器以评估过去的交互。按Agent或Workflow程过滤分数。
