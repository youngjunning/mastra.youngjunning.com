# Evals

传统软件测试有明确的通过和失败条件，而 AI 的输出并非确定的，同样的输入也可能得到不同结果。**评分器**提供可量化的指标，用于衡量 Agent 的质量。

评分器是自动化测试，使用模型判分、规则和统计方法评估 Agent 的输出。它返回**分数**，通常为 0 到 1 的数值，表示输出符合评估标准的程度。通过分数，你可以客观地跟踪表现、比较不同方案，并找出 AI 系统中有待改进的地方。你可以用自己的提示词和评分函数自定义评分器。

评分器可以在云端运行，实时收集结果，也可以纳入 CI/CD 流水线，持续测试和监控 Agent。

评分器衡量单次输出。要持续改进 Agent，可以配合[数据集](/docs/evals/datasets)和[实验](/docs/evals/experiments)使用。数据集保存带版本的测试用例，实验让 Agent 或 Workflow 在数据集上运行，可选择为每条结果评分，并保留结果以供比较。[建立评估闭环](/docs/guides/build-an-eval-loop)介绍了如何配合使用。

:::tip[📹 观看视频]

观看 [Mastra Evals 概览](https://www.youtube.com/watch?v=12WN6u2DrBk)，了解评估的基本概念，以及如何判断 Agent 的质量。

:::

## 评分器类型 {/* #types-of-scorers */}

Mastra 提供多种评分器，各有不同用途。常见类型如下：

1. **文本评分器**：评估 Agent 回复的准确性、可靠性及其对上下文的理解
1. **分类评分器**：衡量按预定义类别对数据分类的准确性
1. **提示词工程评分器**：考察不同指令和输入格式的影响

## 安装 {/* #installation */}

要使用 Mastra 的评分器，请安装 `@mastra/evals` 包。

```bash npm2yarn
npm install @mastra/evals@latest
```

## 实时评估 {/* #live-evaluations */}

**实时评估**会在 Agent 和 Workflow 运行时自动为 AI 输出评分。评分器与 AI 系统并行异步运行，无需手动或批量发起评估，即可持续监控质量。

### 为 Agent 添加评分器 {/* #adding-scorers-to-agents */}

你可以给 Agent 添加内置评分器，自动评估其输出。所有可用选项见[内置评分器列表](/docs/evals/built-in-scorers)。

```typescript title="src/mastra/agents/evaluated-agent.ts"
import { Agent } from '@mastra/core/agent'
import { createAnswerRelevancyScorer, createToxicityScorer } from '@mastra/evals/scorers/prebuilt'

export const evaluatedAgent = new Agent({
  id: 'evaluated-agent',
  scorers: {
    relevancy: {
      scorer: createAnswerRelevancyScorer({ model: '__GATEWAY_OPENAI_MODEL_LUNA__' }),
      sampling: { type: 'ratio', rate: 0.5 },
    },
    safety: {
      scorer: createToxicityScorer({ model: '__GATEWAY_OPENAI_MODEL_LUNA__' }),
      sampling: { type: 'ratio', rate: 1 },
    },
  },
})
```

### 为 Workflow 步骤添加评分器 {/* #adding-scorers-to-workflow-steps */}

你也可以在单个 Workflow 步骤上添加评分器，评估流程中指定位置的输出。每个评分器都接收对应步骤的输入和输出，因此可以逐步衡量质量，而不只为最终答案评分：

```typescript title="src/mastra/workflows/content-generation.ts"
import { createWorkflow, createStep } from '@mastra/core/workflows'
import { z } from 'zod'
import { customStepScorer } from '../scorers/custom-step-scorer'

const contentStep = createStep({
  id: 'content-step',
  inputSchema: z.object({ topic: z.string() }),
  outputSchema: z.object({ content: z.string() }),
  scorers: {
    customStepScorer: {
      scorer: customStepScorer(),
      sampling: {
        type: 'ratio',
        rate: 1, // Score every step execution
      },
    },
  },
  execute: async ({ inputData }) => {
    return { content: await generateContent(inputData.topic) }
  },
})

export const contentWorkflow = createWorkflow({
  id: 'content-workflow',
  inputSchema: z.object({ topic: z.string() }),
  outputSchema: z.object({ content: z.string() }),
})
  .then(contentStep)
  .commit()
```

步骤级 `scorers` API 见 [Step 类参考](/reference/workflows/step#scoring-step-output)。

### 实时评估的工作原理 {/* #how-live-evaluations-work */}

**异步执行**：实时评估在后台运行，不阻塞 Agent 的响应或 Workflow 的执行。评估期间，AI 系统仍能照常响应。

**采样控制**：`sampling.rate` 参数（0 到 1）控制参与评分的输出比例：

- `1.0`：为每条回复评分（100%）
- `0.5`：为一半回复评分（50%）
- `0.1`：为 10% 的回复评分
- `0.0`：禁用评分

每条 Trace 的采样结果都是确定的，由 Trace ID 决定，而非随机抽取。这意味着：

- 采样率相同的评分器会为同一批 Trace 评分，可以在同一批流量上比较分数。
- 重新运行同一条 Trace，采样结果不变，因此能够复现采样覆盖范围。

未配置可观测性时，运行没有 Trace，改用运行 ID 决定是否采样。如果[Trace 采样](../observability/tracing/overview)没有选中该 Trace，评分器会跳过整次运行，以免给从未保存的 Trace 生成分数。

**评分资格过滤**：可选的 `filter` 参数通过对运行上下文声明谓词，限定评分器适用的运行。过滤先于采样，因此 `sampling.rate` 只对符合条件的运行生效：

```typescript title="src/mastra/agents/evaluated-agent.ts"
import { Agent } from '@mastra/core/agent'

export const myAgent = new Agent({
  // ...
  scorers: {
    relevancy: {
      scorer: createAnswerRelevancyScorer({ model: '__GATEWAY_OPENAI_MODEL_LUNA__' }),
      filter: {
        op: 'eq',
        left: { path: 'requestContext.plan' },
        right: { literal: 'enterprise' },
      },
      sampling: { type: 'ratio', rate: 0.1 },
    },
  },
})
```

此配置只对企业套餐流量中的 10% 评分。要按不同采样率为不同流量分组评分，可用互补的过滤器绑定同一个评分器两次。

谓词可以引用 `requestContext.*`、`entity.*`、`entityType`、`source`、`threadId`、`resourceId` 和 `projectId`。支持比较（`eq`、`ne`、`lt`、`lte`、`gt`、`gte`）、集合成员判断（`in`、`notIn`）、存在性判断（`exists`、`notExists`）、真值判断（`truthy`、`falsy`）和布尔组合（`and`、`or`、`not`）。过滤器如果引用未知的根字段，会在构建 Agent 时直接报错，避免运行时静默跳过评分。过滤器是纯 JSON，不受持久化 Agent 状态序列化的影响。

资格过滤决定 _是否运行评分器_。要筛选 _评分器运行后能看到的消息_，请用 [`filterRun()`](/reference/evals/filter-run)。资格过滤无法读取运行的输入或输出。如果评分资格取决于运行期间发生的事，例如是否调用了某个工具，请在评分器步骤中返回 [`notScorable()`](/reference/evals/not-scorable)。这样会跳过剩余步骤，也不会保存分数。

**自动存储**：所有评分结果都会自动保存在已配置数据库的 `mastra_scorers` 表中，便于分析长期表现趋势。

## 分数持久化 {/* #score-persistence */}

要持久化分数，必须为 Mastra 实例配置 `storage`，并在该实例上注册评分器。注册后，Mastra 才能在写入分数前通过 [`getScorerById()`](/reference/core/getScorerById) 查找评分器的元数据（名称、描述和类型）。

绑定到 Agent 或 Workflow 步骤的评分器会自动注册。直接传给 [`runEvals()`](/reference/evals/run-evals) 的评分器（包括 [Quick Checks](/docs/evals/quick-checks)）则需要通过 [`Mastra` 类](/reference/core/mastra-class)的 `scorers` 选项注册：

```typescript title="src/mastra/index.ts"
import { Mastra } from '@mastra/core'
import { LibSQLStore } from '@mastra/libsql'
import { checks } from '@mastra/evals/checks'
import { createAnswerRelevancyScorer } from '@mastra/evals/scorers/prebuilt'
import { myAgent } from './agents/my-agent'

export const mastra = new Mastra({
  agents: { myAgent },
  storage: new LibSQLStore({ url: 'file:./mastra.db' }),
  scorers: {
    calledTool: checks.calledTool('get_weather'),
    includes: checks.includes('Brooklyn'),
    relevancy: createAnswerRelevancyScorer({ model: '__GATEWAY_OPENAI_MODEL_LUNA__' }),
  },
})
```

查找时只比较评分器 ID，因此注册实例可以采用与实际评估实例不同的配置。所有 `checks.calledTool()` 实例都使用 ID `check-called-tool`，注册一个实例即可覆盖你评估的所有工具名称。

随每条分数保存的 `description` 由注册实例的参数决定。传入 `checks.calledTool('')` 虽然能正常保存分数，但描述会是 `Checks that "" was called`，因此应传入一个有代表性的值。

跳过注册不会影响评分结果，但每次保存都会失败并发出 `Scorer with id <id> not found` 警告，分数也不会写入存储。

## Trace 评估 {/* #trace-evaluations */}

除了实时评估，还可以用评分器评估 Agent 交互和 Workflow 产生的历史 Trace。

这适合分析历史表现、排查问题或批量运行评估。

:::note[需要配置可观测性]

要给 Trace 评分，必须先在 Mastra 实例中配置可观测性并收集 Trace 数据。配置步骤见[追踪文档](../observability/tracing/overview)。

:::

## Studio {/* #studio */}

要为 Trace 评分，先在 Mastra 实例上注册评分器：

```typescript
const mastra = new Mastra({
  scorers: {
    answerRelevancy: myAnswerRelevancyScorer,
    responseQuality: myResponseQualityScorer,
  },
})
```

注册后，你可以在 Studio 的 **Observability** 区域交互式地为 Trace 评分。你也可以在 Studio 中管理评分器、查看分数和运行实验。

- **评分器列表**：浏览所有已注册评分器及其描述，查看每个评分器关联的 Agent 和 Workflow 数量。
- **评分结果**：选择评分器，分页查看它生成的所有分数。点击任意一行打开详情面板，查看分数、评分理由、输入、输出以及判分模型使用的提示词。可将任意结果保存为数据集条目，供后续实验使用。
- **Agent 的 Evaluate 选项卡**：打开任意 Agent 的 Evaluate 选项卡，管理评分器和数据集，也可运行实验。实验结果会按条目显示分数、通过或失败状态以及版本标签。
- **Trace 评分**：在 Observability 区域，针对任意历史 Trace 或 Span 运行评分器，评估过去的交互。可以按 Agent 或 Workflow 筛选分数。
