# 数据集

**添加于：** `@mastra/core@1.4.0`

数据集是测试用例的集合，您可以对其运行实验以衡量Agent和Workflow程的执行情况。每个突变都会创建一个新版本，因此您可以准确地重现过去的实验。将数据集与[scorers](/docs/evals/overview) to track quality across prompts, models, or code changes.

<Inject>
  **对于人工智能Agent：**&#x8DD1;步`npx mastra api dataset create '{"name":"translation-pairs"}'` to create a dataset directly instead of opening Studio or writing a temporary script. The command requires a running Mastra server with a storage adapter that supports datasets; start the local server with `npx mastra dev`, or pass the reachable server's base URL with `--url`。跑步`npx mastra api dataset create --schema`在添加不同的数据集字段之前。安装 Mastra 的技能`npx skills add mastra-ai/skills --skill mastra`获取完整的 API CLI 发现、定位、架构、身份验证和错误处理指南。
</Inject>

## 用法 {/* #usage */}

### 配置存储 {/* #configure-storage */}

在您的 Mastra 实例中配置存储。数据集需要一个存储适配器来提供`datasets` domain:

```typescript title="src/mastra/index.ts"
import { Mastra } from '@mastra/core'
import { LibSQLStore } from '@mastra/libsql'

export const mastra = new Mastra({
  storage: new LibSQLStore({
    id: 'my-store',
    url: 'file:./mastra.db',
  }),
})
```

### 访问数据集 API {/* #accessing-the-datasets-api */}

所有数据集操作都可以通过`mastra.datasets`:

```typescript
const datasets = mastra.datasets

// Create a dataset
const dataset = await datasets.create({ name: 'my-dataset' })

// Retrieve an existing dataset
const existing = await datasets.get({ id: 'dataset-id' })

// List all datasets
const { datasets: all } = await datasets.list()
```

参观[`DatasetsManager` reference](/reference/datasets/datasets-manager) for the full list of methods.

## 工作室 {/* #studio */}

您还可以管理数据集[Studio](/docs/studio/overview). After opening Studio, select **Datasets** from the sidebar to see all your available datasets or create a new one.

要开始使用，请选择**Create Dataset** and set a name, description, and optional schemas. After confirming, you'll see the dataset details page with two tabs: **Items** and [**Experiments**](/docs/evals/experiments#run-experiments-in-studio).

在**Items** view you can add, update, and delete items, and view version history. Select **Add Item** to insert a new item with JSON editors for input and ground truth. From this view you can also import items in bulk from a CSV or JSON file. When importing, map each column to the corresponding dataset field.

选择**Versions** to see the full history of changes to the dataset. After selecting **Compare Versions**, choose any two versions and select **Compare** to see a side-by-side diff of all items that were added, changed, or removed between those versions.

## 创建数据集 {/* #creating-a-dataset */}

称呼[`create()`](/reference/datasets/create) with a name and optional description:

```typescript title="src/mastra/datasets/create-dataset.ts"
import { mastra } from '../index'

const dataset = await mastra.datasets.create({
  name: 'translation-pairs',
  description: 'English to Spanish translation test cases',
})

console.log(dataset.id) // auto-generated UUID
```

### 定义模式 {/* #defining-schemas */}

您可以强制执行形状`input` and `groundTruth` by passing a [Standard JSON Schema](https://standardschema.dev/json-schema) ([Zod](https://zod.dev/), [Valibot](https://valibot.dev/), [ArkType](https://arktype.io/), etc.) when creating the dataset:

```typescript title="src/mastra/datasets/create-with-schema.ts"
import { z } from 'zod'
import { mastra } from '../index'

const dataset = await mastra.datasets.create({
  name: 'translation-pairs',
  inputSchema: z.object({
    text: z.string(),
    sourceLang: z.string(),
    targetLang: z.string(),
  }),
  groundTruthSchema: z.object({
    translation: z.string(),
  }),
})
```

与架构不匹配的项目将在插入时被拒绝。

## 添加项目 {/* #adding-items */}

使用[`addItem()`](/reference/datasets/addItem) for a single item or [`addItems()`](/reference/datasets/addItems) to insert in bulk:

```typescript title="src/mastra/datasets/add-items.ts"
// Single item
await dataset.addItem({
  input: { text: 'Hello', sourceLang: 'en', targetLang: 'es' },
  groundTruth: { translation: 'Hola' },
})

// Bulk insert
await dataset.addItems({
  items: [
    {
      input: { text: 'Goodbye', sourceLang: 'en', targetLang: 'es' },
      groundTruth: { translation: 'Adiós' },
    },
    {
      input: { text: 'Thank you', sourceLang: 'en', targetLang: 'es' },
      groundTruth: { translation: 'Gracias' },
    },
  ],
})
```

### 存储的字段值 {/* #stored-field-values */}

内存中、LibSQL、PostgreSQL、MySQL、MongoDB 和 Spanner 数据集存储保留 JSON`null` in `input`, `groundTruth`, and `expectedTrajectory`, along with empty strings, arrays, and objects. Omitted optional JSON fields remain absent when serialized. Dataset schemas still determine which values an item accepts.

快照验证不会覆盖数据库限制。 MongoDB 拒绝包含 NUL 的对象属性名称（`\u0000`), even in valid JSON. A batch insert containing such keys fails without storing any items or advancing the dataset version.

对于配置更新，`null` clears schemas, tags, target type, target IDs, or scorer IDs. These adapters return cleared settings as `undefined`, while preserving empty arrays and objects. An item update with `scorerIds: null` removes its scorer override, whereas `scorerIds: []` disables scoring for that item. Omitted update fields leave existing values unchanged.

用同样的方法重试`externalId` retain the original item's representation. For backward compatibility, insert operations treat omitted and `null` payload fields as equivalent when comparing a retry with an existing item. For example, inserting an item without `groundTruth` and retrying with `groundTruth: null` returns the original item with no ground truth. Use an item update to store an explicit `null` instead.

取消设置的配置现在读取为`undefined` where some adapters previously returned `null`, so serialized responses omit those properties. Use nullish checks such as `value ?? fallback` rather than relying on an explicit `null` property. LibSQL also returns an omitted dataset description as `undefined`, matching its declared type.

较旧的 LibSQL、PostgreSQL、MySQL 和 Spanner 写入存储的可选 JSON`null` values as SQL `NULL`. Those values remain indistinguishable from omitted fields. Older MongoDB writes stored omitted optional payload fields as BSON `null`. The storage fixes preserve new writes but don't reconstruct previously lost distinctions.

## 验证快照工件 {/* #validate-snapshot-artifacts */}

使用`createDatasetSnapshot()` and `parseDatasetSnapshot()` from `@mastra/core/datasets` to create and validate a versioned JSON artifact. These are pure format utilities: they don't export from storage, import a dataset, allocate portable identities, or change Studio's JSON importer.

```typescript title="src/mastra/datasets/snapshot.ts"
import { createDatasetSnapshot, parseDatasetSnapshot } from '@mastra/core/datasets'

const snapshot = createDatasetSnapshot({
  formatVersion: 1,
  datasetIdentity: '00000000-0000-4000-8000-000000000001',
  configuration: { name: 'translation-pairs' },
  items: [
    {
      itemIdentity: '00000000-0000-4000-8000-000000000002',
      createdAt: '2026-09-01T09:00:00.123Z',
      updatedAt: '2026-09-10T10:00:00.456Z',
      payload: { input: 'Hello', groundTruth: 'Hola', scorerIds: [] },
    },
  ],
  provenance: {
    exportedAt: '2026-09-11T12:00:00Z',
    sourceDatasetId: 'dev-translations',
    itemVersion: 1,
    configurationBasis: 'export-time',
  },
})

const parsed = parseDatasetSnapshot(JSON.stringify(snapshot))
console.log(parsed.digest === snapshot.digest) // true
```

该工件包括配置、完整的创作项有效负载、可移植 UUID 和出处。提供稳定的小写 UUID，而不是在每次序列化时生成新的身份。撰写`externalId` values are separate from portable identity and remain unchanged. Absent, `null`, and empty overrides remain distinct. Omit optional properties rather than assigning `undefined`. Dataset descriptions also preserve absent, `null`, and string values.

每一项都需要`createdAt` and `updatedAt` as UTC ISO 8601 strings with millisecond precision, matching `Date.toISOString()` for four-digit years. Both timestamps are included in the integrity digest. They represent the item's actual dates, not transfer provenance: an importer must preserve them as the destination item's `createdAt` and `updatedAt`, rather than replacing them with import time. An importer records transfer time in a separate receipt, while later edits in the destination update `updatedAt` normally. Implementing storage import remains outside the scope of these format helpers.

此保留适用于提供的工件内容。存储适配器在捕获之前可能已经具有标准化值。格式验证既不恢复这些区别，也不保证普通数据集 CRUD 操作可以恢复它们。例如，PostgreSQL JSONB 拒绝包含 NUL 字符的字符串 (`\u0000`) even though they're valid in an artifact. Validate destination storage restrictions before writing artifact contents.

两个助手都会因内容或大小选项无效而引发 Zod 验证错误。`datasetSnapshotContentSchema.safeParse()` validates unsigned content and identity uniqueness, while `datasetSnapshotSchema.safeParse()` additionally checks the digest. These schemas don't enforce a byte limit. Use `parseDatasetSnapshot()` for untrusted text to enforce a size budget before parsing and reject duplicate JSON property names.

帮助程序默认为 4 MiB UTF-8 预算（`DATASET_SNAPSHOT_DEFAULT_MAX_BYTES`). Pass `{ maxBytes }` as the second argument to either helper to raise or lower it. The value must be a positive safe integer. This is an operational limit, not part of the v1 format or digest. For example, parse the snapshot above with an 8 MiB budget:

```typescript
const parsedWithLargerBudget = parseDatasetSnapshot(JSON.stringify(snapshot), {
  maxBytes: 8 * 1024 * 1024,
})
```

`createDatasetSnapshot()`测量完整工件的紧凑度`JSON.stringify()` output, including the digest. `parseDatasetSnapshot()` measures the supplied text, including whitespace. Pretty-printing can exceed a budget that accepts the compact artifact. Neither helper truncates data. During creation, validation, cloning, and hashing happen before the byte-size check. Because shared references can expand during JSON serialization, the budget limits output size without bounding CPU time or peak memory. When adding a transport, configure HTTP request-body limits separately from this budget.

工件的最大嵌套深度为 100（从封套根部开始测量）。它们拒绝未知的结构字段、重复的项目标识或非空`externalId` values, non-JSON values, and invalid Unicode. Programmatic content must use plain objects and standard arrays, not class instances or array subclasses. Arbitrary JSON inside authored payloads remains intact, including trajectory expectations. Dataset schemas are preserved as JSON objects, but these utilities don't compile them or validate items against them. Destination authorization, reference resolution, and storage support also require separate preflight checks.

摘要是信封的 RFC 8785 规范 JSON 表示形式的小写十六进制 SHA-256 哈希值，不包含`digest`. Items are sorted by portable identity for hashing, while authored array order is preserved. Provenance is covered, so a new capture time changes the digest. A matching digest verifies integrity but doesn't establish authorship or approval. Review sensitive data before creating an artifact, as the utilities don't redact it.

## 更新、删除和清除项目 {/* #updating-deleting-and-purging-items */}

[`updateItem()`](/reference/datasets/updateItem), [`deleteItem()`](/reference/datasets/deleteItem), and [`deleteItems()`](/reference/datasets/deleteItems) create new dataset versions as they modify or remove items:

```typescript title="src/mastra/datasets/update-delete.ts"
await dataset.updateItem({
  itemId: 'item-abc-123',
  groundTruth: { translation: '¡Hola!' },
})

await dataset.deleteItem({ itemId: 'item-abc-123' })

await dataset.deleteItems({ itemIds: ['item-1', 'item-2'] })
```

删除项目会在当前数据集版本中隐藏该项目，但会在历史行和删除逻辑删除中保留其内容。使用[`purgeItem()`](/reference/datasets/purgeItem) to redact the item's stored content across its existing history:

```typescript title="src/mastra/datasets/purge-item.ts"
await dataset.purgeItem({ itemId: 'item-abc-123' })
```

清除会用经过编辑的值替换每个历史行和删除逻辑删除中的内容，并清除链接的实验结果有效负载、标签和注释。稍后提交的该项目的实验结果也与经过编辑的内容一起存储。

清除与并发数据集项编写器序列化或冲突，但不保证哪个操作首先完成。如果一个突变`updateItem()` call loses the race, it re-reads the purge marker and rejects with `DATASET_ITEM_PURGED`. `deleteItem()` remains idempotent, and any deletion tombstone created during the race stays redacted.

正常项目突变使用缓慢变化的维度类型 2 (SCD-2) 版本控制。永久清除有意覆盖擦除的历史不变性，同时保留项目身份和数据集版本时间线。它不会创建数据集版本并且无法撤消。实验计数器和审核状态也被保留。避免将敏感数据存储在`externalId`, which remains unchanged as the item's identity key.

MongoDB 存储需要副本集或分片部署，并支持此操作的事务。当 MongoDB 事务不可用时，在更改数据之前清除会失败。

## 列出和搜索项目 {/* #listing-and-searching-items */}

[`listItems()`](/reference/datasets/listItems)支持分页和不区分大小写的子字符串搜索：

```typescript title="src/mastra/datasets/list-items.ts"
// Paginated list
const { items, pagination } = await dataset.listItems({
  page: 0,
  perPage: 50,
})

// Substring search
const { items: matches } = await dataset.listItems({
  search: 'Hello',
})

// Search and pagination can be combined with a specific version
const { items: v2Matches } = await dataset.listItems({
  version: 2,
  search: 'Hello',
  page: 0,
  perPage: 50,
})
```

呼唤`listItems({ version })` without `search`, `page`, or `perPage` returns a bare `DatasetItem[]`. This form is deprecated. Pass `page` and `perPage` to always receive the paginated shape.

## 版本控制 {/* #versioning */}

添加、更新或删除数据集项目会影响数据集版本。清除项目的存储内容[`purgeItem()`](/reference/datasets/purgeItem) doesn't create a new version. This lets you pin experiments to a specific snapshot of the data while erasing sensitive content without changing the version history.

### 列出版本 {/* #listing-versions */}

使用[`listVersions()`](/reference/datasets/listVersions) to see the paginated history of versions:

```typescript title="src/mastra/datasets/list-versions.ts"
const { versions, pagination } = await dataset.listVersions()

for (const v of versions) {
  console.log(`Version ${v.version} — created ${v.createdAt}`)
}
```

### 查看项目历史记录 {/* #viewing-item-history */}

通过调用查看特定项目如何跨版本更改[`getItemHistory()`](/reference/datasets/getItemHistory) with the `itemId`:

```typescript title="src/mastra/datasets/item-history.ts"
const history = await dataset.getItemHistory({ itemId: 'item-abc-123' })

for (const row of history) {
  console.log(`Version ${row.datasetVersion}`, row.input, row.groundTruth)
}
```

### 固定到版本 {/* #pinning-to-a-version */}

获取过去版本中存在的确切项目：

```typescript title="src/mastra/datasets/pin-version.ts"
const { items } = await dataset.listItems({ version: 2, page: 0, perPage: 100 })
```

您还可以将实验固定到某个版本，请参阅[running experiments](/docs/evals/experiments). Visit the [`Dataset` reference](/reference/datasets/dataset) for the full list of methods and parameters.
