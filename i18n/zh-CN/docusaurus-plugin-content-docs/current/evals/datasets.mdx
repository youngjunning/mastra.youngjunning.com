# 数据集

**引入版本：** `@mastra/core@1.4.0`

数据集是一组测试用例，可用于运行实验，衡量 Agent 和 Workflow 的表现。每次修改都会创建新版本，因此可以准确复现过去的实验。将数据集与[评分器](/docs/evals/overview)配合使用，以跟踪提示词、模型或代码变更对质量的影响。

<Inject>
  **供 AI Agent 使用：** 运行 `npx mastra api dataset create '{"name":"translation-pairs"}'` 可直接创建数据集，无需打开 Studio 或编写临时脚本。该命令需要正在运行、且配置了支持数据集的存储适配器的 Mastra 服务器；可用 `npx mastra dev` 启动本地服务器，或通过 `--url` 指定可访问服务器的基础 URL。添加其他数据集字段前，先运行 `npx mastra api dataset create --schema`。安装 Mastra Skill：`npx skills add mastra-ai/skills --skill mastra`，可获取完整的 API CLI 命令发现、目标选择、Schema、身份认证和错误处理指南。
</Inject>

## 用法 {/* #usage */}

### 配置存储 {/* #configure-storage */}

在 Mastra 实例中配置存储。数据集需要支持 `datasets` 域的存储适配器：

```typescript title="src/mastra/index.ts"
import { Mastra } from '@mastra/core'
import { LibSQLStore } from '@mastra/libsql'

export const mastra = new Mastra({
  storage: new LibSQLStore({
    id: 'my-store',
    url: 'file:./mastra.db',
  }),
})
```

### 访问数据集 API {/* #accessing-the-datasets-api */}

所有数据集操作均可通过 `mastra.datasets` 使用：

```typescript
const datasets = mastra.datasets

// Create a dataset
const dataset = await datasets.create({ name: 'my-dataset' })

// Retrieve an existing dataset
const existing = await datasets.get({ id: 'dataset-id' })

// List all datasets
const { datasets: all } = await datasets.list()
```

完整方法列表请参阅 [`DatasetsManager` 参考文档](/reference/datasets/datasets-manager)。

## Studio {/* #studio */}

你也可以在 [Studio](/docs/studio/overview) 中管理数据集。打开 Studio 后，从侧边栏选择 **Datasets**，即可查看所有可用数据集或创建新数据集。

选择 **Create Dataset**，设置名称、描述和可选 Schema。确认后，数据集详情页会显示 **Items** 和 [**Experiments**](/docs/evals/experiments#run-experiments-in-studio) 两个标签页。

在 **Items** 视图中，可以添加、更新或删除条目，也可以查看版本历史。选择 **Add Item**，通过 JSON 编辑器填写输入和标准答案，插入新条目。你还可以在这里从 CSV 或 JSON 文件批量导入条目；导入时须将每一列映射到相应的数据集字段。

选择 **Versions** 查看数据集的完整变更历史。然后选择 **Compare Versions**，指定任意两个版本，再选择 **Compare**，即可并排查看两个版本之间新增、修改和删除的所有条目。

## 创建数据集 {/* #creating-a-dataset */}

调用 [`create()`](/reference/datasets/create)，传入名称和可选描述：

```typescript title="src/mastra/datasets/create-dataset.ts"
import { mastra } from '../index'

const dataset = await mastra.datasets.create({
  name: 'translation-pairs',
  description: 'English to Spanish translation test cases',
})

console.log(dataset.id) // auto-generated UUID
```

### 定义 Schema {/* #defining-schemas */}

创建数据集时，可以传入 [Standard JSON Schema](https://standardschema.dev/json-schema)（例如 [Zod](https://zod.dev/)、[Valibot](https://valibot.dev/) 或 [ArkType](https://arktype.io/)），约束 `input` 和 `groundTruth` 的结构：

```typescript title="src/mastra/datasets/create-with-schema.ts"
import { z } from 'zod'
import { mastra } from '../index'

const dataset = await mastra.datasets.create({
  name: 'translation-pairs',
  inputSchema: z.object({
    text: z.string(),
    sourceLang: z.string(),
    targetLang: z.string(),
  }),
  groundTruthSchema: z.object({
    translation: z.string(),
  }),
})
```

插入时会拒绝不符合 Schema 的条目。

## 添加项目 {/* #adding-items */}

使用 [`addItem()`](/reference/datasets/addItem) 插入单个条目，或使用 [`addItems()`](/reference/datasets/addItems) 批量插入：

```typescript title="src/mastra/datasets/add-items.ts"
// Single item
await dataset.addItem({
  input: { text: 'Hello', sourceLang: 'en', targetLang: 'es' },
  groundTruth: { translation: 'Hola' },
})

// Bulk insert
await dataset.addItems({
  items: [
    {
      input: { text: 'Goodbye', sourceLang: 'en', targetLang: 'es' },
      groundTruth: { translation: 'Adiós' },
    },
    {
      input: { text: 'Thank you', sourceLang: 'en', targetLang: 'es' },
      groundTruth: { translation: 'Gracias' },
    },
  ],
})
```

### 存储的字段值 {/* #stored-field-values */}

内存、LibSQL、PostgreSQL、MySQL、MongoDB 和 Spanner 数据集存储会保留 `input`、`groundTruth`、`expectedTrajectory` 中的 JSON `null`，以及空字符串、数组和对象。序列化时，省略的可选 JSON 字段仍然不存在。数据集 Schema 仍决定条目可接受哪些值。

快照验证不会覆盖数据库限制。即使 JSON 有效，MongoDB 也会拒绝包含 NUL（`\u0000`）的对象属性名。若批量插入含有此类键，整个操作将失败，不存储任何条目，也不推进数据集版本。

更新配置时，`null` 会清除 Schema、标签、目标类型、目标 ID 或评分器 ID。这些适配器将已清除设置返回为 `undefined`，但保留空数组和空对象。条目更新中的 `scorerIds: null` 会移除该条目的评分器覆盖设置，而 `scorerIds: []` 会禁用该条目的评分。省略的更新字段保持原值。

使用相同 `externalId` 重试时，会保留原条目的表示形式。为兼容旧行为，插入操作在比较重试条目与现有条目时，将省略字段和 `null` 字段视为等价。例如，首次插入时省略 `groundTruth`，重试时传入 `groundTruth: null`，返回的仍是没有标准答案的原条目。若要存储显式 `null`，请更新条目。

过去某些适配器会对未设置的配置返回 `null`，现在则返回 `undefined`，因此序列化响应会省略这些属性。请使用 `value ?? fallback` 等空值检查，不要依赖显式 `null` 属性。LibSQL 对省略的数据集描述也返回 `undefined`，与其声明类型一致。

旧版 LibSQL、PostgreSQL、MySQL 和 Spanner 写入会将可选 JSON `null` 存为 SQL `NULL`，因此无法再与省略字段区分。旧版 MongoDB 写入会将省略的可选负载字段存为 BSON `null`。存储修复会保留新写入中的区别，但无法重建过去丢失的区别。

## 验证快照文件 {/* #validate-snapshot-artifacts */}

使用 `@mastra/core/datasets` 中的 `createDatasetSnapshot()` 和 `parseDatasetSnapshot()` 创建并验证带版本的 JSON 文件。它们仅处理格式：不会从存储导出、导入数据集、分配可移植 ID，也不会更改 Studio 的 JSON 导入器。

```typescript title="src/mastra/datasets/snapshot.ts"
import { createDatasetSnapshot, parseDatasetSnapshot } from '@mastra/core/datasets'

const snapshot = createDatasetSnapshot({
  formatVersion: 1,
  datasetIdentity: '00000000-0000-4000-8000-000000000001',
  configuration: { name: 'translation-pairs' },
  items: [
    {
      itemIdentity: '00000000-0000-4000-8000-000000000002',
      createdAt: '2026-09-01T09:00:00.123Z',
      updatedAt: '2026-09-10T10:00:00.456Z',
      payload: { input: 'Hello', groundTruth: 'Hola', scorerIds: [] },
    },
  ],
  provenance: {
    exportedAt: '2026-09-11T12:00:00Z',
    sourceDatasetId: 'dev-translations',
    itemVersion: 1,
    configurationBasis: 'export-time',
  },
})

const parsed = parseDatasetSnapshot(JSON.stringify(snapshot))
console.log(parsed.digest === snapshot.digest) // true
```

快照文件包含配置、完整的原始条目负载、可移植 UUID 和来源信息。请提供稳定的小写 UUID，不要每次序列化都生成新 ID。原始 `externalId` 与可移植 ID 分开保存，且保持不变。缺失、`null` 和空的覆盖值各有区别。请省略可选属性，不要赋值为 `undefined`。数据集描述同样区分缺失、`null` 和字符串。

每个条目都必须包含 `createdAt` 和 `updatedAt`，格式为精确到毫秒的 UTC ISO 8601 字符串；对四位年份，其格式与 `Date.toISOString()` 一致。两个时间戳都会计入完整性摘要。它们表示条目的实际时间，而非传输来源：导入器必须将它们保留为目标条目的 `createdAt` 和 `updatedAt`，不能替换为导入时间。导入器应在单独的回执中记录传输时间；目标端后续编辑则正常更新 `updatedAt`。这些格式工具不负责实现存储导入。

这种保留仅适用于传入的快照内容。存储适配器在采集前可能已归一化值；格式验证既无法恢复这些区别，也不保证普通数据集 CRUD 操作可以恢复。比如 PostgreSQL JSONB 会拒绝包含 NUL 字符（`\u0000`）的字符串，即使它在快照中有效。写入快照内容前，请检查目标存储的限制。

内容或大小选项无效时，两个工具都会抛出 Zod 验证错误。`datasetSnapshotContentSchema.safeParse()` 验证未签名内容及 ID 唯一性；`datasetSnapshotSchema.safeParse()` 还会检查摘要。这两个 Schema 都不限制字节数。对于不可信文本，请用 `parseDatasetSnapshot()` 在解析前限制大小，并拒绝重复的 JSON 属性名。

工具默认使用 4 MiB 的 UTF-8 大小预算（`DATASET_SNAPSHOT_DEFAULT_MAX_BYTES`）。将 `{ maxBytes }` 作为任一工具的第二个参数，可以调高或调低预算；该值必须是正的安全整数。这是运行限制，不属于 v1 格式或摘要。例如，以 8 MiB 预算解析上面的快照：

```typescript
const parsedWithLargerBudget = parseDatasetSnapshot(JSON.stringify(snapshot), {
  maxBytes: 8 * 1024 * 1024,
})
```

`createDatasetSnapshot()` 测量完整文件的紧凑 `JSON.stringify()` 输出，包括摘要。`parseDatasetSnapshot()` 测量传入文本，包括空白字符。美化后的 JSON 可能超出紧凑文件所能通过的预算。两个工具都不会截断数据。创建时，验证、克隆和哈希计算都先于字节大小检查。共享引用可能在 JSON 序列化时展开，因此预算限制输出大小，却不限制 CPU 时间或峰值内存。新增传输层时，请单独设置 HTTP 请求体大小上限。

文件最大嵌套深度为 100，从最外层对象计算。工具会拒绝未知结构字段、重复的条目 ID、重复的非 null `externalId` 值、非 JSON 值及无效 Unicode。程序生成的内容须使用普通对象和标准数组，不能使用类实例或数组子类。原始负载中的任意 JSON（包括轨迹预期）会原样保留。数据集 Schema 以 JSON 对象保留，但工具不会编译 Schema 或据此验证条目。目标端的授权、引用解析和存储支持也需要单独预检。

摘要是将不含 `digest` 的最外层对象按 RFC 8785 规范化为 JSON 后，计算所得的小写十六进制 SHA-256 哈希。计算哈希时按可移植 ID 排序条目，但保留原始数组顺序。来源信息也参与计算，因此新的采集时间会改变摘要。摘要匹配可验证完整性，但不能证明作者身份或批准状态。工具不会脱敏；创建文件前请检查敏感数据。

## 更新、删除和清除项目 {/* #updating-deleting-and-purging-items */}

[`updateItem()`](/reference/datasets/updateItem)、[`deleteItem()`](/reference/datasets/deleteItem) 和 [`deleteItems()`](/reference/datasets/deleteItems) 在修改或删除条目时都会创建新的数据集版本：

```typescript title="src/mastra/datasets/update-delete.ts"
await dataset.updateItem({
  itemId: 'item-abc-123',
  groundTruth: { translation: '¡Hola!' },
})

await dataset.deleteItem({ itemId: 'item-abc-123' })

await dataset.deleteItems({ itemIds: ['item-1', 'item-2'] })
```

删除条目会将其从当前数据集版本中隐藏，但历史记录和删除墓碑仍保留内容。使用 [`purgeItem()`](/reference/datasets/purgeItem) 可对条目现有历史中的存储内容进行脱敏：

```typescript title="src/mastra/datasets/purge-item.ts"
await dataset.purgeItem({ itemId: 'item-abc-123' })
```

彻底清除会用脱敏值替换所有历史记录和删除墓碑中的内容，并清理关联的实验结果负载、标签与评论。之后提交的该条目实验结果也会以脱敏内容存储。

彻底清除与并发的数据集条目写入会串行执行或发生冲突，但不保证哪个操作先完成。如果修改型 `updateItem()` 在竞争中失败，会重新读取清除标记，并以 `DATASET_ITEM_PURGED` 拒绝操作。`deleteItem()` 仍具有幂等性，竞争期间创建的删除墓碑也会保持脱敏。

普通条目变更采用缓慢变化维度类型 2（SCD-2）版本管理。永久清除为实现擦除，会有意突破历史不可变性，但保留条目 ID 和数据集版本时间线。它不创建数据集版本，也无法撤销。实验计数和审核状态同样保留。`externalId` 作为条目 ID 键保持不变，因此不要在其中存储敏感数据。

此操作要求 MongoDB 存储使用支持事务的副本集或分片部署。如果 MongoDB 事务不可用，清除会在修改数据前失败。

## 列出与搜索条目 {/* #listing-and-searching-items */}

[`listItems()`](/reference/datasets/listItems) 支持分页和不区分大小写的子字符串搜索：

```typescript title="src/mastra/datasets/list-items.ts"
// Paginated list
const { items, pagination } = await dataset.listItems({
  page: 0,
  perPage: 50,
})

// Substring search
const { items: matches } = await dataset.listItems({
  search: 'Hello',
})

// Search and pagination can be combined with a specific version
const { items: v2Matches } = await dataset.listItems({
  version: 2,
  search: 'Hello',
  page: 0,
  perPage: 50,
})
```

如果调用 `listItems({ version })` 时不传 `search`、`page` 或 `perPage`，会直接返回 `DatasetItem[]`。此用法已弃用。传入 `page` 和 `perPage`，可确保始终获得分页结果结构。

## 版本控制 {/* #versioning */}

添加、更新或删除数据集条目会提高数据集版本号。使用 [`purgeItem()`](/reference/datasets/purgeItem) 清除条目的存储内容不会创建新版本。这样，实验可以固定到特定数据快照，同时擦除敏感内容而不改变版本历史。

### 列出版本 {/* #listing-versions */}

使用 [`listVersions()`](/reference/datasets/listVersions) 查看分页的版本历史：

```typescript title="src/mastra/datasets/list-versions.ts"
const { versions, pagination } = await dataset.listVersions()

for (const v of versions) {
  console.log(`Version ${v.version} — created ${v.createdAt}`)
}
```

### 查看项目历史记录 {/* #viewing-item-history */}

传入 `itemId` 调用 [`getItemHistory()`](/reference/datasets/getItemHistory)，可查看特定条目在不同版本中的变化：

```typescript title="src/mastra/datasets/item-history.ts"
const history = await dataset.getItemHistory({ itemId: 'item-abc-123' })

for (const row of history) {
  console.log(`Version ${row.datasetVersion}`, row.input, row.groundTruth)
}
```

### 固定到版本 {/* #pinning-to-a-version */}

获取过去某个版本中实际存在的全部条目：

```typescript title="src/mastra/datasets/pin-version.ts"
const { items } = await dataset.listItems({ version: 2, page: 0, perPage: 100 })
```

实验也可以固定到某个版本，参见[运行实验](/docs/evals/experiments)。完整方法和参数列表请参阅 [`Dataset` 参考文档](/reference/datasets/dataset)。
