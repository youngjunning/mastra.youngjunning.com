# 定制记分器

使用`createScorer`构建自定义评估逻辑。每个步骤都可以使用 JavaScript 函数或基于 LLM 的提示对象，具体取决于您要评估的内容。

## 四步管道 {/* #the-four-step-pipeline */}

Mastra 的所有评分员都遵循一致的四步评估流程：

1. **预处理**（可选）：准备或转换输入/输出数据
2. **分析**（可选）：执行评估分析并收集见解
3. **生成分数**（必需）：将分析转换为数字分数
4. **生成原因**（可选）：生成人类可读的解释

结合**functions** and **prompt objects** within a scorer to use deterministic checks for some steps and LLM-based evaluation for others.

## 函数与提示对象 {/* #functions-vs-prompt-objects */}

**功能**使用 JavaScript 实现确定性逻辑。它们非常适合：

* 具有明确标准的算法评估
* 性能关键场景
* 与现有库集成
* 一致、可重复的结果

**提示对象**使用LLM作为评委进行评估。它们非常适合：

* 需要类人判断的主观评价
* 复杂的标准难以通过算法进行编码
* 自然语言理解任务
* 细致入微的情境评估

**“提示对象”是什么意思：**&#x6B65;骤不是一个函数，而是一个对象`description` + `createPrompt` (and `outputSchema` for `preprocess`/`analyze`). That object tells Mastra to run the judge LLM for the step and store the structured output in `results.<step>StepResult`.

您可以在单个评分器中混合和匹配方法 - 例如，使用用于预处理数据的函数和用于分析质量的 LLM。

## 初始化记分器 {/* #initializing-a-scorer */}

每个得分手都从`createScorer` factory function, which requires an id and description, and optionally accepts a type specification and judge configuration.

```typescript oxfmt:false
import { createScorer } from '@mastra/core/evals';

const glutenCheckerScorer = createScorer({
  id: 'gluten-checker',
  description: 'Check if recipes contain gluten ingredients',
  judge: {                    // Optional: for prompt object steps
    model: '__GATEWAY_OPENAI_MODEL__',
    instructions: 'You are a Chef that identifies if recipes contain gluten.'
  }
})
// Chain step methods here
.preprocess(...)
.analyze(...)
.generateScore(...)
.generateReason(...)
```

仅当您计划在任何步骤中使用提示对象时才需要判断配置。各个步骤可以使用自己的判断设置覆盖此默认配置。

如果所有步骤都是基于函数的，则永远不会调用判断并且没有判断输出。要查看 LLM 输出，请定义至少一个步骤作为提示对象并读取相应的步骤结果（例如，`results.analyzeStepResult`).

### 最小判断示例（提示对象） {/* #minimal-judge-example-prompt-object */}

此示例使用提示对象`analyze`, so the judge runs and its structured output is available as `results.analyzeStepResult`.

```typescript
import { createScorer } from '@mastra/core/evals'
import { z } from 'zod'

const quoteSourcesScorer = createScorer({
  id: 'quote-sources',
  description: 'Check if the response includes sources',
  judge: {
    model: '__GATEWAY_OPENAI_MODEL_LUNA__',
    instructions: 'You are a strict evaluator.',
  },
})
  .analyze({
    description: 'Detect whether sources are present',
    outputSchema: z.object({
      hasSources: z.boolean(),
      sources: z.array(z.string()),
    }),
    createPrompt: ({ run }) => `
Does the response contain sources? Extract them as a list.

Response:
${run.output}
`,
  })
  .generateScore(({ results }) => (results.analyzeStepResult.hasSources ? 1 : 0))

// Run the scorer and inspect judge output
const result = await quoteSourcesScorer.run({
  input: 'What is the capital of France?',
  output: 'Paris is the capital of France [1]. Source: [1] Wikipedia',
})

console.log(result.score) // 1
console.log(result.analyzeStepResult) // { hasSources: true, sources: ["Wikipedia"] }
```

### Agent评估的Agent类型 {/* #agent-type-for-agent-evaluation */}

为了类型安全以及与实时Agent评分和跟踪评分的兼容性，请使用`type: 'agent'` when creating scorers for agent evaluation. The same scorer can evaluate an agent and score traces:

```typescript
const myScorer = createScorer({
  type: 'agent', // Automatically handles agent input/output types
}).generateScore(({ run, results }) => {
  // run.output is automatically typed as ScorerRunOutputForAgent
  // run.input is automatically typed as ScorerRunInputForAgent
})
```

## 逐步细分 {/* #step-by-step-breakdown */}

### 预处理步骤（可选） {/* #preprocess-step-optional */}

当您需要提取特定元素或过滤内容，或者转换复杂的数据结构时，准备输入/输出数据。

**功能：** `({ run, results }) => any`

```typescript oxfmt:false
const glutenCheckerScorer = createScorer(...)
.preprocess(({ run }) => {
  // Extract and clean recipe text
  const recipeText = run.output.text.toLowerCase();
  const wordCount = recipeText.split(' ').length;

  return {
    recipeText,
    wordCount,
    hasCommonGlutenWords: /flour|wheat|bread|pasta/.test(recipeText)
  };
})
```

**提示对象：**&#x4F7F;用`description`, `outputSchema`, and `createPrompt` to structure LLM-based preprocessing.

```typescript oxfmt:false
const glutenCheckerScorer = createScorer(...)
.preprocess({
  description: 'Extract ingredients from the recipe',
  outputSchema: z.object({
    ingredients: z.array(z.string()),
    cookingMethods: z.array(z.string())
  }),
  createPrompt: ({ run }) => `
    Extract all ingredients and cooking methods from this recipe:
    ${run.output.text}

    Return JSON with ingredients and cookingMethods arrays.
  `
})
```

**数据流：**&#x7ED3;果可用于后续步骤，如下所示`results.preprocessStepResult`

### 分析步骤（可选） {/* #analyze-step-optional */}

执行核心评估分析，收集将为评分决策提供信息的见解。

**功能：** `({ run, results }) => any`

```typescript oxfmt:false
const glutenCheckerScorer = createScorer({...})
.preprocess(...)
.analyze(({ run, results }) => {
  const { recipeText, hasCommonGlutenWords } = results.preprocessStepResult;

  // Simple gluten detection algorithm
  const glutenKeywords = ['wheat', 'flour', 'barley', 'rye', 'bread'];
  const foundGlutenWords = glutenKeywords.filter(word =>
    recipeText.includes(word)
  );

  return {
    isGlutenFree: foundGlutenWords.length === 0,
    detectedGlutenSources: foundGlutenWords,
    confidence: hasCommonGlutenWords ? 0.9 : 0.7
  };
})
```

**提示对象：**&#x4F7F;用`description`, `outputSchema`, and `createPrompt` for LLM-based analysis.

```typescript oxfmt:false
const glutenCheckerScorer = createScorer({...})
.preprocess(...)
.analyze({
  description: 'Analyze recipe for gluten content',
  outputSchema: z.object({
    isGlutenFree: z.boolean(),
    glutenSources: z.array(z.string()),
    confidence: z.number().min(0).max(1)
  }),
  createPrompt: ({ run, results }) => `
    Analyze this recipe for gluten content:
    "${results.preprocessStepResult.recipeText}"

    Look for wheat, barley, rye, and hidden sources like soy sauce.
    Return JSON with isGlutenFree, glutenSources array, and confidence (0-1).
  `
})
```

**数据流：**&#x7ED3;果可用于后续步骤，如下所示`results.analyzeStepResult`

### `generateScore`步骤（必填） {/* #generatescore-step-required */}

将分析结果转换为数字分数。这是管道中唯一必需的步骤。

**功能：** `({ run, results }) => number`

```typescript oxfmt:false
const glutenCheckerScorer = createScorer({...})
.preprocess(...)
.analyze(...)
.generateScore(({ results }) => {
  const { isGlutenFree, confidence } = results.analyzeStepResult;

  // Return 1 for gluten-free, 0 for contains gluten
  // Weight by confidence level
  return isGlutenFree ? confidence : 0;
})
```

**提示对象：**&#x8BF7;参阅[`createScorer`](/reference/evals/create-scorer) API reference for details on using prompt objects with generateScore, including required `calculateScore` function.

**数据流：**&#x8BE5;分数可用于generateReason 作为`score` parameter

### `generateReason`步骤（可选） {/* #generatereason-step-optional */}

生成人类可读的分数解释，对于调试、透明度或用户反馈很有用。

**功能：** `({ run, results, score }) => string`

```typescript oxfmt:false
const glutenCheckerScorer = createScorer({...})
.preprocess(...)
.analyze(...)
.generateScore(...)
.generateReason(({ results, score }) => {
  const { isGlutenFree, glutenSources } = results.analyzeStepResult;

  if (isGlutenFree) {
    return `Score: ${score}. This recipe is gluten-free with no harmful ingredients detected.`;
  } else {
    return `Score: ${score}. Contains gluten from: ${glutenSources.join(', ')}`;
  }
})
```

**提示对象：**&#x4F7F;用`description` and `createPrompt` for LLM-generated explanations.

```typescript oxfmt:false
const glutenCheckerScorer = createScorer({...})
.preprocess(...)
.analyze(...)
.generateScore(...)
.generateReason({
  description: 'Explain the gluten assessment',
  createPrompt: ({ results, score }) => `
    Explain why this recipe received a score of ${score}.
    Analysis: ${JSON.stringify(results.analyzeStepResult)}

    Provide a clear explanation for someone with dietary restrictions.
  `
})
```

## 输入过滤 {/* #input-filtering */}

Agent对话可以包含数百条消息，其Tool调用和数据部分都附有系统元数据。大多数得分手只需要一个子集。在记分器管道执行之前，`prepareRun` option transforms the run data to reduce noise and keep each scorer focused.

### 声明式过滤`filterRun()` {/* #declarative-filtering-with-filterrun */}

这[`filterRun()`](/reference/evals/filter-run) utility creates a `prepareRun` function from declarative options:

```typescript title="src/mastra/scorers/tool-scorer.ts"
import { createScorer, filterRun } from '@mastra/core/evals'

const toolScorer = createScorer({
  id: 'tool-quality',
  description: 'Evaluates tool usage quality',
  type: 'agent',
  prepareRun: filterRun({
    partTypes: ['tool-invocation', 'text'],
    maxRememberedMessages: 20,
  }),
}).generateScore(({ run }) => {
  // run.input.rememberedMessages has only tool and text messages, max 20
  return 1
})
```

常见选项包括：

* `partTypes`：仅保留具有匹配部分类型的消息（例如，`'tool-invocation'`, `'text'`, `'reasoning'`)
* `toolNames`：仅保留涉及特定Tool的消息（例如，`['write_file', 'execute_command']`)
* `maxRememberedMessages`：限制上下文窗口大小
* `dropRequestContext`, `dropGroundTruth`, `dropExpectedTrajectory`: Remove unused fields

请参阅[`filterRun()` reference](/reference/evals/filter-run) for the full list of options.

### 风俗`prepareRun` functions {/* #custom-preparerun-functions */}

对于逻辑来说`filterRun()` doesn't cover, write a `prepareRun` function directly:

```typescript
import { createScorer } from '@mastra/core/evals'

const customScorer = createScorer({
  id: 'recent-output',
  description: 'Scores only the last response',
  type: 'agent',
  prepareRun: run => ({
    ...run,
    output: run.output.slice(-1), // Keep only the last message
    requestContext: undefined,
  }),
}).generateScore(({ run }) => {
  return run.output.length > 0 ? 1 : 0
})
```

这`prepareRun` function can also be async.

:::注意\[系统消息始终保留]

`filterRun()`从不过滤`systemMessages` or `taggedSystemMessages`. These contain agent instructions and are critical context for scoring.

:::

## 跳过无法得分的跑动 {/* #skipping-runs-that-cant-be-scored */}

一些记分器仅适用于运行的子集。判断退款处理情况的记分员对于未要求退款的运行没有任何评价。

返回[`notScorable()`](/reference/evals/not-scorable) from a function step to declare that the run has nothing to evaluate. Remaining steps are skipped and the run is left out of the scorer's aggregates:

```typescript title="src/mastra/scorers/refund-judge.ts"
import { createScorer, notScorable } from '@mastra/core/evals'
import { extractToolCalls } from '@mastra/evals/scorers/utils'

export const refundJudge = createScorer({
  id: 'refund-judge',
  description: 'Judges how well refund requests were handled',
  type: 'agent',
  judge: {
    model: '__GATEWAY_OPENAI_MODEL_LUNA__',
    instructions: 'You are a strict QA reviewer for customer-support refund handling.',
  },
})
  .preprocess(({ run }) => {
    const { tools } = extractToolCalls(run.output)
    return tools.includes('refundCustomer')
      ? { tools }
      : notScorable('refundCustomer was not called')
  })
  .generateScore({
    description: 'Score the refund handling from 0 to 1',
    createPrompt: ({ run }) =>
      `Rate this refund handling from 0 to 1:\n${JSON.stringify(run.output)}`,
  })
```

把支票放进去`preprocess` so it runs before any judge step. `notScorable()` is different from an [eligibility filter](/docs/evals/overview#how-live-evaluations-work): filters decide from request context whether the scorer runs at all, while `notScorable()` lets the scorer inspect the run's input and output first.

请参阅[`notScorable()` reference](/reference/evals/not-scorable) for the result shape and how live scoring, `runEvals()`, and experiments treat a skipped run.

## 确定法官的评分标准 {/* #anchoring-the-judges-score-scale */}

提示对象`generateScore` step asks the judge for `{ score: number }`. Mastra forwards whatever number comes back without clamping or normalizing it, so the prompt is the only thing defining your scale:

```typescript title="src/mastra/scorers/refund-judge.ts" oxfmt:false
.generateScore({
  description: 'Score the refund handling from 0 to 1',
  createPrompt: ({ run }) => `Rate this refund handling:
- 1.0: refund issued correctly, no policy breach
- 0.5: refund issued but policy explained poorly or a step was missed
- 0.0: refund not issued, or issued against policy

${JSON.stringify(run.output)}`,
})
```

`Rate this refund handling from 0 to 1`单独的评分标准的中间部分是不确定的，而评委们会以不同的方式填补这个空白。命名端点并描述至少一个中间值。将输出格式排除在提示之外：该步骤已要求法官提供`{ score: number }`, and a prompt that says "return only the number" makes the judge answer in a shape the step can't read. If your scorer must not drift outside a range, clamp or reject the value in a function step instead of trusting the judge.

这对于[gates](/docs/evals/gates-and-verdicts), whose thresholds must be between 0 and 1 even though the judge's number is stored exactly as returned. A prompt that asks for a 1 to 10 score makes a failing `2` pass every threshold you're allowed to set. The gate then never fires.

## 示例：创建自定义记分器 {/* #example-create-a-custom-scorer */}

Mastra 中的自定义记分器使用`createScorer` with four core components:

1. [**判断配置**](#judge-configuration)
2. [**分析步骤**](#analysis-step)
3. [**分数生成**](#score-generation)
4. [**理性生成**](#reason-generation)

这些组件共同允许您使用法学硕士作为评委来定义自定义评估逻辑。访问[createScorer](/reference/evals/create-scorer) for the full API and configuration options.

```typescript title="src/mastra/scorers/gluten-checker.ts"
import { createScorer } from '@mastra/core/evals'
import { z } from 'zod'

export const GLUTEN_INSTRUCTIONS = `You are a Chef that identifies if recipes contain gluten.`

export const generateGlutenPrompt = ({
  output,
}: {
  output: string
}) => `Check if this recipe is gluten-free.

Check for:
- Wheat
- Barley
- Rye
- Common sources like flour, pasta, bread

Example with gluten:
"Mix flour and water to make dough"
Response: {
  "isGlutenFree": false,
  "glutenSources": ["flour"]
}

Example gluten-free:
"Mix rice, beans, and vegetables"
Response: {
  "isGlutenFree": true,
  "glutenSources": []
}

Recipe to analyze:
${output}

Return your response in this format:
{
  "isGlutenFree": boolean,
  "glutenSources": ["list ingredients containing gluten"]
}`

export const generateReasonPrompt = ({
  isGlutenFree,
  glutenSources,
}: {
  isGlutenFree: boolean
  glutenSources: string[]
}) => `Explain why this recipe is${isGlutenFree ? '' : ' not'} gluten-free.

${glutenSources.length > 0 ? `Sources of gluten: ${glutenSources.join(', ')}` : 'No gluten-containing ingredients found'}

Return your response in this format:
"This recipe is [gluten-free/contains gluten] because [explanation]"`

export const glutenCheckerScorer = createScorer({
  id: 'gluten-checker',
  description: 'Check if the output contains any gluten',
  judge: {
    model: '__GATEWAY_OPENAI_MODEL_LUNA__',
    instructions: GLUTEN_INSTRUCTIONS,
  },
})
  .analyze({
    description: 'Analyze the output for gluten',
    outputSchema: z.object({
      isGlutenFree: z.boolean(),
      glutenSources: z.array(z.string()),
    }),
    createPrompt: ({ run }) => {
      const { output } = run
      return generateGlutenPrompt({ output: output.text })
    },
  })
  .generateScore(({ results }) => {
    return results.analyzeStepResult.isGlutenFree ? 1 : 0
  })
  .generateReason({
    description: 'Generate a reason for the score',
    createPrompt: ({ results }) => {
      return generateReasonPrompt({
        glutenSources: results.analyzeStepResult.glutenSources,
        isGlutenFree: results.analyzeStepResult.isGlutenFree,
      })
    },
  })
```

### 判断配置 {/* #judge-configuration */}

设置 LLM 模型并定义其作为领域专家的角色。

```typescript oxfmt:false
judge: {
  model: '__GATEWAY_OPENAI_MODEL_LUNA__',
  instructions: GLUTEN_INSTRUCTIONS,
}
```

### 分析步骤 {/* #analysis-step */}

定义法学硕士应如何分析输入以及返回什么结构化输出。

```typescript oxfmt:false
.analyze({
  description: 'Analyze the output for gluten',
  outputSchema: z.object({
    isGlutenFree: z.boolean(),
    glutenSources: z.array(z.string()),
  }),
  createPrompt: ({ run }) => {
    const { output } = run;
    return generateGlutenPrompt({ output: output.text });
  },
})
```

分析步骤使用提示对象来：

* 提供分析任务的清晰描述
* 使用标准 JSON 模式定义预期的输出结构（布尔结果和麸质源列表）
* 根据输入内容生成运行时提示

### 分数生成 {/* #score-generation */}

将法学硕士的结构化分析转换为数字分数。

```typescript oxfmt:false
.generateScore(({ results }) => {
  return results.analyzeStepResult.isGlutenFree ? 1 : 0;
})
```

分数生成功能获取分析结果并应用业务逻辑来生成分数。在这种情况下，法学硕士直接确定食谱是否不含麸质，因此我们使用该布尔结果：1 表示不含麸质，0 表示含有麸质。

### 理性生成 {/* #reason-generation */}

使用另一个 LLM 调用为分数提供人类可读的解释。

```typescript oxfmt:false
.generateReason({
  description: 'Generate a reason for the score',
  createPrompt: ({ results }) => {
    return generateReasonPrompt({
      glutenSources: results.analyzeStepResult.glutenSources,
      isGlutenFree: results.analyzeStepResult.isGlutenFree,
    });
  },
})
```

原因生成步骤使用布尔结果和分析步骤识别的特定麸质来源创建解释，帮助用户理解分配分数的原因。
