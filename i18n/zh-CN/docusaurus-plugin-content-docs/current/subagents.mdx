# 子 Agent

**引入版本：** `@mastra/core@1.8.0`

子 Agent 是负责特定任务的 Agent，其他 Agent 可以向它们委派工作。先将子 Agent 添加到父 Agent 的 `agents` 属性，再调用 [`Agent.stream()`](/reference/streaming/agents/stream) 或 [`Agent.generate()`](/reference/agents/generate)。父 Agent 根据自身指令及各子 Agent 的 `description`，决定何时以及如何委派任务。

## 何时使用子 Agent {/* #when-to-use-subagents */}

当任务需要不同专长的 Agent 协作时，可以使用子 Agent。父 Agent 决定何时委派任务，向各子 Agent 传递上下文，最后汇总它们的结果。

常见场景：

- 在研究和写作流程中，由一个 Agent 收集资料，另一个 Agent 撰写内容
- 多个阶段需要不同专业能力的任务
- 需要精细控制委派行为的任务

:::note

负责协调子 Agent 的父 Agent 通常称为监督 Agent。监督模式是 Mastra 构建多 Agent 系统的一种方式。其他方式请参阅[概念概览](/docs/guides/multi-agent-systems)。

:::

## 快速开始 {/* #quickstart */}

为子 Agent 编写明确的描述，再将它们添加到父 Agent：

```typescript title="src/mastra/agents/parent-agent.ts"
import { Agent } from '@mastra/core/agent'
import { Memory } from '@mastra/memory'
import { LibSQLStore } from '@mastra/libsql'

const researchAgent = new Agent({
  id: 'research-agent',
  // highlight-next-line
  description: 'Gathers factual information and returns bullet-point summaries.',
  model: '__GATEWAY_OPENAI_MODEL_LUNA__',
})

const writingAgent = new Agent({
  id: 'writing-agent',
  // highlight-next-line
  description: 'Transforms research into well-structured articles.',
  model: '__GATEWAY_OPENAI_MODEL_LUNA__',
})

// highlight-start
const parentAgent = new Agent({
  id: 'parent-agent',
  instructions: `You coordinate research and writing using specialized agents.
    Delegate to research-agent for facts, then writing-agent for content.`,
  model: '__GATEWAY_OPENAI_MODEL__',
  agents: { researchAgent, writingAgent },
  memory: new Memory({
    storage: new LibSQLStore({ id: 'storage', url: 'file:mastra.db' }),
  }),
})
// highlight-end

const stream = await parentAgent.stream('Research AI in education and write an article', {
  maxSteps: 10,
})

for await (const chunk of stream.textStream) {
  process.stdout.write(chunk)
}
```

## 委派钩子 {/* #delegation-hooks */}

委派钩子可在任务委派时拦截、修改或拒绝委派。可以在 Agent 的 `delegation` 配置在 `defaultOptions` 选项，也可以在每次调用时配置。

### `onDelegationStart` {/* #ondelegationstart */}

在父 Agent 向子 Agent 委派任务前调用。返回一个对象来控制此次委派：

- `proceed: true`：允许委派（默认行为）
- `proceed: false`：拒绝委派，并提供 `rejectionReason`
- `modifiedPrompt`：改写发送给子 Agent 的提示词
- `modifiedMaxSteps`：设置子 Agent 的迭代预算。此值会覆盖模型提供的 `maxSteps` 上限，因此既能提高也能降低预算
- `threadMetadata`：在创建子 Agent 的线程时附加元数据（例如 `tenantId`），以便通过 `memory.listThreads({ filter: { metadata } })` 过滤线程

:::note
监督模型向委派调用传入 `maxSteps` 时，Mastra 会将其限制在子 Agent 的 `defaultOptions.maxSteps` 以内。模型可以借此降低子 Agent 的预算，但不能提高预算。`modifiedMaxSteps` 在这一限制之后应用，会替换受限值，因此可以将预算提高到子 Agent 的默认值以上。可用它防止监督模型过早结束子 Agent 的工作。
:::

```typescript title="src/mastra/agents/parent-agent.ts"
const stream = await parentAgent.stream('Research AI trends', {
  maxSteps: 10,
  delegation: {
    onDelegationStart: async context => {
      console.log(`Delegating to: ${context.primitiveId}`)

      // Modify the prompt for a specific agent
      if (context.primitiveId === 'research-agent') {
        return {
          proceed: true,
          modifiedPrompt: `${context.prompt}\n\nFocus on 2024-2025 data.`,
          modifiedMaxSteps: 5,
        }
      }

      // Reject delegation after too many iterations
      if (context.iteration > 8) {
        return {
          proceed: false,
          rejectionReason: 'Max iterations reached. Synthesize current findings.',
        }
      }

      return { proceed: true }
    },
  },
})
```

`context` 对象包含：

| 属性 | 说明 |
| - | - |
| `primitiveId` | 接收委派的子 Agent ID |
| `prompt` | 父 Agent 发送的提示词 |
| `iteration` | 当前迭代次数 |
| `requestContext` | 子 Agent 本次运行将接收的请求上下文 |

### 委派边界的请求上下文 {/* #request-context-at-the-delegation-boundary */}

每次委派都会收到一份请求上下文：其中的条目从父 Agent 的运行中浅拷贝而来，但不包含仅适用于该次运行的身份键。在子 Agent 运行期间设置或删除条目，不会影响父 Agent 的上下文。要向此次委派传值，可在 `context.requestContext` 中设置条目；这段操作应放在 `onDelegationStart` 钩子中：

```typescript title="src/mastra/agents/parent-agent.ts"
const stream = await parentAgent.stream('Research AI trends', {
  maxSteps: 10,
  delegation: {
    onDelegationStart: async context => {
      context.requestContext.set('audience', 'technical')
    },
  },
})
```

子 Agent 可在 Tool 和动态配置中读取这些条目，例如 `instructions: ({ requestContext }) => ...`。详情请参阅[请求上下文](/docs/server/request-context)。要与持久化 Agent 配合使用，值必须能够序列化为 JSON。

### `onDelegationComplete` {/* #ondelegationcomplete */}

委派完成后调用。可以检查结果、提供反馈，或停止执行：

- `context.bail()`：立即停止父 Agent 的循环
- 返回 `{ feedback: '...' }`：将反馈保存到父 Agent 的记忆中，供下一轮使用
- 返回 `{ resultText: '...' }`：在当前运行中替换父模型看到的此次委派的 Tool 结果文本

当子 Agent 的原始结果可能误导父 Agent 时，设置 `resultText`。例如，子 Agent 在 Tool 调用步骤停止并返回空文本时，父模型可能误以为委派成功但没有内容。也可以将失败委派的错误文本替换为更有用的消息；这不会恢复委派，父 Agent 仍会收到失败的 Tool 结果。`feedback` 在下一轮生效，而 `resultText` 会立即影响父 Agent 的推理。

如果要在失败时停止父 Agent，并为后续轮次保存反馈，请调用 `bail()` 并返回 `feedback`：

```typescript title="src/mastra/agents/parent-agent.ts"
const stream = await parentAgent.stream('Research AI trends', {
  maxSteps: 10,
  delegation: {
    onDelegationComplete: async context => {
      console.log(`Completed: ${context.primitiveId}`)

      // Bail on errors
      if (context.error) {
        context.bail()
        return {
          feedback: `Delegation to ${context.primitiveId} failed: ${context.error}. Try a different approach.`,
        }
      }
    },
  },
})
```

`context` 对象包含：

| 属性 | 说明 |
| - | - |
| `primitiveId` | 已运行的子 Agent ID |
| `result` | 子 Agent 的响应；可用时包括 `text`、`usage`、`finishReason`、`subAgentToolResults`、`subAgentPendingToolCalls`、`subAgentThreadId` 和 `subAgentResourceId` |
| `success` | 委派是否成功 |
| `error` | 委派失败时的原始错误 |
| `messages` | 收集到的子 Agent 对话记录，包括可用的部分消息 |
| `bail()` | 停止父 Agent 循环的函数 |

#### 委派失败 {/* #failed-delegations */}

子 Agent 运行失败时，父模型会收到带有通用错误消息的失败 Tool 结果。这不会自动停止父 Agent；它可以解释失败原因，也可以尝试其他方法。若要停止其循环，请调用 `context.bail()`。

钩子会收到 `success: false`、原始 `error`，以及已收集的部分结果和消息。返回 `resultText` 可替换父模型看到的错误文本，但不会改变委派的失败状态，也不会丢弃原始原因。空字符串也是有效的替换值。

如果要让父 Agent 根据整理过的失败消息继续执行，而不停止循环，请返回 `resultText`，不要调用 `bail()`：

```typescript title="src/mastra/agents/parent-agent.ts"
const stream = await parentAgent.stream('Research AI trends', {
  maxSteps: 10,
  delegation: {
    onDelegationComplete: ({ success }) => {
      if (!success) {
        return {
          resultText: 'The delegated task failed. Try another approach.',
        }
      }
    },
  },
})
```

建议像示例一样返回经过整理的消息。返回 `{ resultText: error.message }` 会把底层错误消息直接传给父模型的 Provider，模型可能再将其转述给最终用户。Provider 错误可能包含敏感信息。通用的 `resultText` 也不能替代对日志、Trace 或流式错误载荷的脱敏策略。

对于作为[后台任务](/docs/harness/background-tasks)运行的委派，配置的重试可能让每次尝试都触发一次 `onDelegationComplete`。如果钩子有副作用，需要考虑重复调用。

### 钩子错误 {/* #hook-errors */}

默认情况下，委派钩子抛错后委派仍会继续：`onDelegationStart` 使用原始提示词继续执行，`messageFilter` 回退到未过滤的上下文，`onDelegationComplete` 保留子 Agent 的原始结果。若要让委派失败，请设置 `hookErrorStrategy: 'throw'`。

```typescript title="src/mastra/agents/parent-agent.ts"
const stream = await parentAgent.stream('Research AI trends', {
  maxSteps: 10,
  delegation: {
    hookErrorStrategy: 'throw',
    onDelegationComplete: async ({ result }) => {
      // If this throws, the parent sees a failed delegation instead of a
      // successful one whose result was silently dropped.
      await reportToAnalytics(result)
    },
  },
})
```

无论采用哪种策略，每次钩子失败都会记录到本次运行的请求上下文中，键为 `__mastra_delegationHookErrors`，值是由 `{ hook, primitiveId, toolCallId, runId, name, message }` 条目组成的列表，便于程序检测：

```typescript title="src/mastra/agents/parent-agent.ts"
import { RequestContext } from '@mastra/core/request-context'

const requestContext = new RequestContext()

await parentAgent.generate('Research AI trends', { maxSteps: 10, requestContext })

const hookErrors = requestContext.get('__mastra_delegationHookErrors') ?? []
```

当 `hookErrorStrategy` 为 `'throw'` 时，`onDelegationStart` 抛错会阻止子 Agent 运行；`messageFilter` 或 `onDelegationComplete` 抛错会作为失败的 Tool 调用呈现给父 Agent。如果 `onDelegationComplete` 在处理失败委派时抛错，对外呈现的仍是原始委派错误。钩子不会因自身的失败再次被调用。

## 消息过滤 {/* #message-filtering */}

默认情况下，子 Agent 会收到父 Agent 的完整对话上下文。使用 `messageFilter` 控制共享哪些消息，例如移除敏感数据或限制上下文长度。

```typescript title="src/mastra/agents/parent-agent.ts"
const stream = await parentAgent.stream('Research AI trends', {
  maxSteps: 10,
  delegation: {
    messageFilter: ({ messages, primitiveId, prompt }) => {
      // Remove messages containing sensitive data
      return messages
        .filter(msg => {
          const content =
            typeof msg.content === 'string' ? msg.content : JSON.stringify(msg.content)
          return !content.includes('confidential')
        })
        .slice(-10) // Only pass the last 10 messages
    },
  },
})
```

回调接收 `messages`（完整对话记录）、`primitiveId`（子 Agent ID）和 `prompt`（委派提示词）。返回过滤后的消息数组。

## 子 Agent 的结果上下文 {/* #subagent-result-context */}

子 Agent 完成后，父 Agent 的模型会在后续迭代中收到子 Agent 的文本响应。嵌套的 Tool 调用及子 Agent 元数据（如线程 ID 和资源 ID）不会加入父 Agent 的模型上下文。

应用代码和 UI 集成仍可从 Tool 结果载荷中检查 `subAgentToolResults` 和其余原始委派结果。

这样既保留了调试与展示所需的数据，也避免在父 Agent 下一次模型调用中传入嵌套的 Tool 参数或输出。

子 Agent 不能运行客户端 Tool（即没有 `execute` 函数的 Tool）。如果子 Agent 调用了这类 Tool，其运行会在该步骤停止，`finishReason: 'tool-calls'`。委派结果会在 `subAgentPendingToolCalls` 中列出未执行的调用，父 Agent 的模型会获知哪些 Tool 未运行，Mastra 也会记录警告。应将客户端 Tool 交给父 Agent；如果子 Agent 需要用户输入，则可在其 Tool 中使用 [`suspend()`](/docs/agents/human-in-the-loop#use-suspend-in-supervisor-agents)。

设置 `includeSubAgentToolResultsInModelContext`，可将完整的子 Agent 结果（包括嵌套的 Tool 结果和子 Agent 元数据）加入父 Agent 的模型上下文。

```typescript title="src/mastra/agents/parent-agent.ts"
await parentAgent.generate('Research AI trends', {
  delegation: {
    includeSubAgentToolResultsInModelContext: true,
  },
})
```

### 复用之前的子 Agent 结果 {/* #reusing-an-earlier-subagent-result */}

默认情况下，子 Agent 的结果以 Tool 结果形式传给父 Agent；这些结果会从转发给后续子 Agent 的上下文中移除。父 Agent 必须在下一次委派的提示词中复述之前的结果，这会消耗 token，也可能丢失细节。

设置 `enableResultReferences`，可以让后续委派原样复用之前的结果：

```typescript title="src/mastra/agents/parent-agent.ts"
await parentAgent.generate('Find and fix the token refresh bug', {
  delegation: {
    enableResultReferences: true,
  },
})
```

启用后：

- 每个成功且非空的子 Agent 结果都会获得一个引用 ID，例如 `explorer-1`。父 Agent 的模型会在子 Agent 文本后看到一行 `[ref: explorer-1]`。
- 委派 Tool 会增加 `contextFromRefs` 输入。父 Agent 可以传入先前的 ID：既可以是字符串（`["explorer-1"]`），也可以是带可选标签和备注的对象（`[{ ref: "explorer-1", as: "investigation", note: "bug location" }]`）。
- 被引用的文本会插入委派提示词之前，每个结果各占一个带标签的区块，内容与先前子 Agent 生成的文本完全一致。`onDelegationStart` 和 `messageFilter` 收到的是展开后的提示词。
- 如果 `onDelegationComplete` 返回 `resultText`，后续委派收到的是替换后的文本。

引用只保存在单次父 Agent 运行的内存中，不会持久化。被拒绝、失败、空结果和后台任务委派都不会获得引用 ID。遇到未知 ID 时，系统会记录警告并跳过该 ID，委派仍会继续。

被引用的文本来自另一个 Agent。每个区块会使用新生成、不可预测的标签，并提示接收方子 Agent 将内容视为数据。若子 Agent 会处理不可信输入，仍需在 `onDelegationStart` 或 Processor 中自行检查。

## 迭代监控 {/* #iteration-monitoring */}

父 Agent 每完成一次循环迭代，就会调用 `onIterationComplete`。可以用它监控执行情况、引导下一次迭代，或提前停止执行。

```typescript title="src/mastra/agents/parent-agent.ts"
const stream = await parentAgent.stream('Research AI trends', {
  maxSteps: 10,
  onIterationComplete: async context => {
    console.log(`Iteration ${context.iteration}/${context.maxIterations}`)
    console.log(`Finish reason: ${context.finishReason}`)

    // Inject feedback to guide the agent
    if (!context.text.includes('recommendations')) {
      return {
        continue: true,
        feedback: 'Please include specific recommendations in your analysis.',
      }
    }

    // Stop early when the response is sufficient
    if (context.text.length > 1000 && context.finishReason === 'stop') {
      return { continue: false }
    }

    return { continue: true }
  },
})
```

返回 `{ continue: true }` 可继续迭代，返回 `{ continue: false }` 可停止迭代。还可以通过 `feedback` 向对话注入指导信息。若同时设置 `feedback` 和 `continue: false`，模型可能再获得最后一轮机会，生成包含该反馈的文本响应。只有当前迭代仍处于活动状态（例如刚完成 Tool 调用）时，才会额外提供这一轮。

## 记忆隔离 {/* #memory-isolation */}

Mastra 在委派期间隔离子 Agent 的记忆。子 Agent 会收到完整对话上下文，以便做出判断，但只有本次委派的提示词和响应会保存到它的记忆中。

具体来说：

1. **转发完整上下文**：父 Agent 委派任务时，子 Agent 会收到父 Agent 对话中的所有消息
1. **仅保存本次委派内容**：只有委派提示词和子 Agent 的响应会写入子 Agent 的记忆
1. **每次调用使用新线程**：每次委派都使用唯一的线程 ID，确保彼此隔离

因此，子 Agent 既能获得所需上下文，又不会把父 Agent 的完整对话写进自己的记忆。详情请参阅[多 Agent 系统中的记忆](/docs/memory/overview#memory-in-multi-agent-systems)。

## Tool 审批的传递 {/* #tool-approval-propagation */}

Tool 审批会沿委派链传递。子 Agent 使用设置了 `requireApproval: true` 的 Tool 或调用 `suspend()` 时，审批请求会出现在父 Agent 的流中。

```typescript
const sensitiveDataTool = createTool({
  id: 'get-user-data',
  requireApproval: true,
  execute: async input => {
    return await database.getUserData(input.userId)
  },
})

const dataAgent = new Agent({
  id: 'data-agent',
  tools: { sensitiveDataTool },
})

const parentAgent = new Agent({
  id: 'parent-agent',
  agents: { dataAgent },
  memory: new Memory(),
})

const stream = await parentAgent.stream('Get data for user 123')

for await (const chunk of stream.fullStream) {
  if (chunk.type === 'tool-call-approval') {
    console.log('Tool requires approval:', chunk.payload.toolName)
  }
}
```

## 取消运行 {/* #cancellation */}

向父 Agent 的 [`stream()`](/reference/streaming/agents/stream) 或 [`generate()`](/reference/agents/generate) 调用传入 `abortSignal` 时，Mastra 会将同一个信号传给被委派的子 Agent。调用 `AbortController.abort()` 后，正在运行的子 Agent 会在下一步骤取消，而不会继续运行到结束。

```typescript
const controller = new AbortController()

const stream = await parentAgent.stream('Research AI trends', {
  abortSignal: controller.signal,
})

// Cancel the parent agent and any in-flight subagents
controller.abort()
```

## 任务完成评分 {/* #task-completion-scoring */}

Agent 不一定能在第一次尝试时给出完整、正确的结果。任务完成评分器会在每次迭代后检查任务是否完成；若检查未通过，父 Agent 会继续迭代。未通过的评分器反馈会加入对话上下文，让子 Agent 也能看到遗漏之处。

```typescript
import { createScorer } from '@mastra/core/evals'

const taskCompleteScorer = createScorer({
  id: 'task-complete',
  name: 'Task Completeness',
}).generateScore(async context => {
  const text = (context.run.output || '').toString()
  const hasAnalysis = text.includes('analysis')
  const hasRecommendations = text.includes('recommendation')
  return hasAnalysis && hasRecommendations ? 1 : 0
})

const stream = await parentAgent.stream('Research AI in education', {
  maxSteps: 10,
  isTaskComplete: {
    scorers: [taskCompleteScorer],
    strategy: 'all',
    onComplete: async result => {
      console.log('Task complete:', result.complete)
    },
  },
})
```

### 评分标准评分器 {/* #rubric-scorer */}

内置的评分标准评分器可让你以检查清单定义何为“正确”，并让 Agent 自我评估和迭代，直到满足所有标准或达到 `maxSteps`。

它采用 **LLM-as-judge** 方式：每次迭代后，由另一个评分模型根据评分标准评审 Agent 的输出。所有必需标准均通过时，循环结束；未通过的标准会将反馈加入对话，让 Agent 再次尝试。

这种方式最适合成功标准清晰、可验证的任务。用法如下：

```typescript title="src/mastra/agents/rubric-scorer.ts"
import { Agent } from '@mastra/core/agent'
import { createRubricScorer } from '@mastra/evals/scorers/prebuilt'

const parentAgent = new Agent({
  id: 'parent-agent',
  instructions: 'You coordinate research and writing using specialized agents.',
  model: '__GATEWAY_OPENAI_MODEL__',
  agents: { researchAgent, writingAgent },
})

const rubricScorer = createRubricScorer({
  model: '__GATEWAY_OPENAI_MODEL_LUNA__',
  criteria: [
    { description: 'The response includes an analysis section' },
    { description: 'The response includes concrete recommendations' },
  ],
})

const stream = await parentAgent.stream('Research AI in education', {
  maxSteps: 10,
  isTaskComplete: {
    scorers: [rubricScorer],
    strategy: 'all',
  },
})
```

完整 API 说明请参阅[评分标准评分器参考文档](/reference/evals/rubric)。

## 编写有效指令 {/* #writing-effective-instructions */}

清晰的指令是有效委派的基础。

父 Agent 的 `instructions` 应说明有哪些资源以及何时使用，并定义协作方式和成功标准。

每个子 Agent 都应有明确的 `description`，说明自身用途、返回格式，以及父 Agent 何时应使用它。

父 Agent 根据这些描述决定如何委派任务。

```typescript
const parentAgent = new Agent({
  id: 'parent-agent',
  instructions: `You coordinate research and writing tasks.

Available resources:
- researchAgent: Gathers factual data and sources (returns bullet points)
- writingAgent: Transforms research into narrative content (returns full paragraphs)

Delegation strategy:
1. For research requests: Delegate to researchAgent first
2. For writing requests: Delegate to writingAgent
3. For complex requests: Delegate to researchAgent first, then writingAgent

Success criteria:
- All user questions are fully answered
- Response is well-formatted and complete`,
  agents: { researchAgent, writingAgent },
})
```

## 在后台运行子 Agent {/* #running-subagents-in-the-background */}

子 Agent 的调用以 Tool 调用形式分派，因此可以作为[后台任务](/docs/harness/background-tasks)运行。一个或多个委派需要较长时间、又不希望阻塞父 Agent 的响应时，这很有用。

在 Mastra 实例上启用 [backgroundTasks 管理器](/reference/configuration#backgroundtasks)，再为父 Agent 的子 Agent 开启后台任务：

```typescript title="src/mastra/agents/parent-agent.ts"
import { Agent } from '@mastra/core/agent'

const parentAgent = new Agent({
  id: 'parent-agent',
  instructions: 'Coordinate research and writing using the available agents.',
  model: '__GATEWAY_OPENAI_MODEL__',
  agents: { researchAgent, writingAgent },
  // highlight-start
  backgroundTasks: {
    tools: {
      researchAgent: { enabled: true, timeoutMs: 900_000 },
      writingAgent: { enabled: true, timeoutMs: 900_000 },
    },
  },
  // highlight-end
})

const stream = await parentAgent.streamUntilIdle('Research AI in education and write an article', {
  memory: { thread: 't1', resource: 'u1' },
})
```

使用 [`streamUntilIdle()`](/reference/streaming/agents/streamUntilIdle) 而非 `stream()`，让流保持开启，直到子 Agent 完成任务且父 Agent 有机会响应其结果。

即使子 Agent 未列在父 Agent 的 `backgroundTasks.tools` 下，只要它自身有可在后台运行的 Tool，父 Agent 仍会将其作为后台任务分派，并沿用其配置。详情请参阅[继承子 Agent 的配置](/docs/harness/background-tasks#inheriting-from-the-subagent)。

## 子 Agent 版本控制 {/* #subagent-versioning */}

使用 [Editor](/docs/studio/editor) 时，可以控制父 Agent 在运行时使用各子 Agent 的哪个已存储版本。可在 Mastra 实例上设置版本覆盖，也可在每次调用时设置：

```typescript
const result = await parentAgent.generate('Research and write about AI safety', {
  versions: {
    agents: {
      'research-agent': { status: 'published' },
      'writing-agent': { versionId: 'draft-456' },
    },
  },
})
```

版本覆盖会沿委派链自动传递。版本解析顺序和服务端 API 的详情请参阅[子 Agent 版本控制](/reference/editor/versioning#sub-agent-versioning)。
