# 服务器

Mastra 以 HTTP 服务器运行，通过 API 端点提供 Agent、Workflow 等功能。服务器负责请求路由、执行中间件、身份验证和流式响应。

:::note

本文介绍传给 `Mastra` 构造函数的 [`server`](/reference/configuration#server-options) 配置项。要用自己的 HTTP 服务器（如 Hono 或 Express）运行 Mastra，请参阅[服务器适配器](/docs/server/server-adapters)。

:::

## 服务器功能 {/* #server-features */}

- **[中间件](/docs/server/middleware)**：拦截请求，执行身份验证、记录日志、处理 CORS 或注入当前请求的上下文。
- **[自定义 API 路由](/docs/server/custom-api-routes)**：添加可以访问 Mastra 实例的自定义 HTTP 端点。
- **[请求上下文](/docs/server/request-context)**：根据运行时条件，将当前请求的数据传给 Agent、Tool 和 Workflow。
- **[服务器适配器](/docs/server/server-adapters)**：用 Express、Hono 或自己的 HTTP 服务器运行 Mastra，替代自动生成的服务器。
- **[自定义适配器](/docs/server/custom-adapters)**：为尚未获得官方支持的框架编写适配器。
- **[Mastra 客户端 SDK](/docs/server/mastra-client)**：提供类型安全的客户端，可在浏览器或服务器中调用 Agent、Workflow 和 Tool。
- **[内置 MCP 服务器](/docs/server/mcp)**：Claude Code、Cursor 等 MCP 客户端可通过 `/api/mcp` 调用 Agent、Workflow 和 Tool，身份验证与权限规则和 HTTP API 相同。
- **[A2A](/docs/connections/a2a)**：通过 A2A Agent 卡片和任务流公开 Agent，并支持推送通知。
- **[身份验证](/docs/auth/overview)**：使用 JWT、Clerk、Supabase、Firebase、Auth0 或 WorkOS 保护端点。

## 配置 {/* #configuration */}

将 `server` 对象传给 `Mastra` 构造函数来配置服务器：

```typescript title="src/mastra/index.ts"
import { Mastra } from '@mastra/core'

export const mastra = new Mastra({
  server: {
    port: 3000, // Defaults to PORT env var or 4111
    host: '0.0.0.0', // Defaults to MASTRA_HOST env var or 'localhost'
  },
})
```

所有可用选项见[配置参考](/reference/configuration#server-options)。

## 部署您的服务器 {/* #deploy-your-server */}

Mastra 服务器可部署到任何兼容 Node.js 的环境。可以通过 [Mastra 平台](/docs/mastra-platform/overview) 或自己的基础设施部署到生产环境，具体步骤见[部署文档](/docs/deployment/overview)。

## 服务器架构 {/* #server-architecture */}

Mastra 用 [Hono](https://hono.dev) 作为底层 HTTP 服务器框架。运行 `mastra build` 构建应用时，会在 `.mastra` 目录中生成基于 Hono 的 HTTP 服务器。

服务器提供：

- 所有已注册 Agent 和 Workflow 的 API 端点
- 自定义 API 路由和中间件
- 支持多种 Provider 的身份验证
- 用于运行时配置的请求上下文
- 流式数据脱敏，保护响应中的敏感信息

## REST API {/* #rest-api */}

[http://localhost:4111/api/openapi.json](http://localhost:4111/api/openapi.json) 的 OpenAPI 规范列出了所有可用端点，并说明每个端点的请求和响应结构。

访问 [http://localhost:4111/swagger-ui](http://localhost:4111/swagger-ui) 打开 Swagger UI，可直接在浏览器里查看和测试端点。

:::note

生产环境默认禁用 OpenAPI 和 Swagger 端点。要启用它们，请分别将 [`server.build.openAPIDocs`](/reference/configuration#serverbuild) 和 [`server.build.swaggerUI`](/reference/configuration#serverbuild) 设为 `true`。

:::

## OpenAI Responses API {/* #openai-responses-api */}

Mastra 提供兼容 OpenAI 的 Responses 和 Conversations 路由，可通过 Responses API 使用 Mastra Agent。这些路由是在 Agent、Memory 和存储之上实现的适配层，由所选的 Mastra Agent 处理请求，而不是直接代理 Provider。

这些 API 目前处于实验阶段。

用 `agent_id` 选择处理请求的 Mastra Agent。首次请求直接发给 Agent，已保存对话的后续轮次可通过 `previous_response_id` 接续。传入 `model` 可仅为当前请求覆盖模型配置，省略则使用 Agent 已配置的模型。

Responses 路由支持流式响应和函数调用（Tool），还可用 `previous_response_id` 接续已保存的响应、用 `conversation_id` 指定对话线程、通过 `providerOptions` 透传 Provider 专用选项，以及通过 `text.format` 输出 JSON。

完整的请求和响应规范见 [Responses API 参考](/reference/client-js/responses)及 [Conversations API 参考](/reference/client-js/conversations)。全部 HTTP 路由见[服务器路由](/reference/server/routes#responses-api)。

## 流式数据脱敏 {/* #stream-data-redaction */}

以流式方式发送 Agent 响应时，HTTP 层会在发送每个数据块之前移除系统提示词、Tool 定义、API 密钥等数据。此功能默认启用。

只有使用[服务器适配器](/docs/server/server-adapters#stream-data-redaction)时才能配置这一行为。适配器也默认启用流式数据脱敏。

## TypeScript 配置 {/* #typescript-configuration */}

Mastra 要求 `module` 和 `moduleResolution` 的设置兼容现代 Node.js，不支持 `CommonJS` 或 `node` 等旧选项。

下方的 `types` 选项需要 `@types/node`。用 [`create-mastra`](/reference/cli/create-mastra) 创建的项目已包含这个包，其他项目如未安装，可手动添加：

```bash npm2yarn
npm install -D @types/node
```

```json {4-5} title="tsconfig.json"
{
  "compilerOptions": {
    "target": "ES2022",
    "module": "ES2022",
    "moduleResolution": "bundler",
    "esModuleInterop": true,
    "forceConsistentCasingInFileNames": true,
    "strict": true,
    "skipLibCheck": true,
    "types": ["node"],
    "noEmit": true,
    "outDir": "dist"
  },
  "include": ["src/**/*"]
}
```
