# Mastra 客户端

Mastra Client SDK 提供简洁、类型安全的接口，方便你在客户端与 [Mastra Server](/docs/server/overview) 交互。

## 前置条件 {/* #prerequisites */}

开始本地开发前，请确认：

- Node.js `v22.13.0` 或更高版本
- TypeScript `v4.7` 或更高版本（如果使用 TypeScript）
- 本地 Mastra 服务器已启动（通常监听端口 `4111`）

:::note

Mastra Client SDK 面向浏览器环境，使用浏览器原生的 `fetch` API 向 Mastra 服务器发送 HTTP 请求。

:::

## 安装 {/* #installation */}

使用 Mastra Client SDK 前，先安装所需依赖：

```bash npm2yarn
npm install @mastra/client-js@latest
```

### 初始化 `MastraClient` {/* #initialize-the-mastraclient */}

使用 `baseUrl` 初始化后，`MastraClient` 会提供类型安全的接口，用于调用 Agent、Tool 和 Workflow。

```typescript title="lib/mastra-client.ts"
import { MastraClient } from '@mastra/client-js'

export const mastraClient = new MastraClient({
  baseUrl: process.env.MASTRA_API_URL || 'http://localhost:4111',
})
```

## 核心 API {/* #core-apis */}

Mastra Client SDK 提供对 Mastra 服务器所提供的全部资源的访问。

- **[Agent](/reference/client-js/agents)**：生成响应并流式传输对话。
- **[A2A](/docs/connections/a2a)**：通过 Agent 卡发现 Agent，并使用基于任务的 A2A 流。
- **[Memory](/reference/client-js/memory)**：管理对话线程和消息历史。
- **[Tool](/reference/client-js/tools)**：执行和管理 Tool。
- **[Workflow](/reference/client-js/workflows)**：触发 Workflow 并跟踪执行情况。
- **[向量](/reference/client-js/vectors)**：使用向量嵌入进行语义搜索。
- **[Responses](/reference/client-js/responses)**：通过兼容 OpenAI 的接口将 Mastra Agent 用作 Responses API。该 API 目前处于实验阶段。
- **[Conversations](/reference/client-js/conversations)**：在将 Mastra Agent 用作 Responses API 时，访问其保存的对话线程和对话条目历史。该 API 目前处于实验阶段。
- **[日志](/reference/client-js/logs)**：查看日志并调试系统行为。
- **[可观测性](/reference/client-js/observability)**：查看应用性能和追踪活动。

## 创建并运行动态 Workflow {/* #create-and-run-dynamic-workflows */}

使用 `upsertDynamicWorkflow()` 创建或替换持久化的 Workflow 定义。操作成功时，系统会校验完整定义，并将其注册到运行中的 Mastra 实例。随后即可通过标准执行 API 运行该 Workflow。

以下示例展示映射 Workflow 的完整生命周期，包括创建、查看、执行和删除：

```typescript title="lib/dynamic-workflow.ts"
import { MastraClient } from '@mastra/client-js'
import type { UpsertDynamicWorkflowParams } from '@mastra/client-js'

const client = new MastraClient({
  baseUrl: process.env.MASTRA_API_URL || 'http://localhost:4111',
})

const definition = {
  id: 'greeting-workflow',
  description: 'Returns a greeting for the supplied name',
  inputSchema: {
    type: 'object',
    properties: { name: { type: 'string' } },
    required: ['name'],
  },
  outputSchema: {
    type: 'object',
    properties: { message: { type: 'string' } },
    required: ['message'],
  },
  graph: [
    {
      type: 'mapping',
      id: 'create-greeting',
      mapConfig: JSON.stringify({
        message: { template: 'Hello, ${initData.name}!' },
      }),
    },
  ],
} satisfies UpsertDynamicWorkflowParams

await client.upsertDynamicWorkflow(definition)

const dynamicWorkflow = client.getDynamicWorkflow(definition.id)
const dynamicDefinition = await dynamicWorkflow.details()

const workflow = client.getWorkflow(dynamicDefinition.id)
const run = await workflow.createRun()
const result = await run.startAsync({ inputData: { name: 'Ada' } })

console.log(result)

await dynamicWorkflow.delete()
```

使用 `listDynamicWorkflows()` 列出已持久化的定义。再次以同一 `id` 调用 `upsertDynamicWorkflow()`，会替换已保存的定义和运行时注册的 Workflow。

:::warning

持久化需要配置支持 `workflowDefinitions` 域的存储适配器。缺少该域时，Core 仍可在内存中注册 Workflow，但服务器的动态 Workflow API 无法在重启后保留它。

已保存的定义支持声明式 Agent、Tool、映射、嵌套 Workflow、并行、foreach、sleep、sleep-until、条件和循环条目。定义不能包含 JavaScript 闭包。条件与循环逻辑必须使用声明式谓词格式，且引用的 Agent、Tool 和嵌套 Workflow 必须已注册。

如果服务器启用了身份验证，操作定义需要 `stored-workflows:read` 或 `stored-workflows:write` 权限，运行 Workflow 则需要 `workflows:execute`。

:::

## 生成响应 {/* #generating-responses */}

将字符串提示词传给 `.generate()`：

```typescript
import { mastraClient } from 'lib/mastra-client'

const testAgent = async () => {
  try {
    const agent = mastraClient.getAgent('testAgent')

    const response = await agent.generate('Hello')

    console.log(response.text)
  } catch (error) {
    return 'Error occurred while generating response'
  }
}
```

:::note

调用 `.generate()` 时也可以传入消息对象数组，每个对象包含 `role` 和 `content`。详情请参阅 [.generate() 参考](/reference/client-js/agents#generate)。

:::

## 流式响应 {/* #streaming-responses */}

将字符串提示词传给 `.stream()`，即可实时接收响应：

```typescript
import { mastraClient } from 'lib/mastra-client'

const testAgent = async () => {
  try {
    const agent = mastraClient.getAgent('testAgent')

    const stream = await agent.stream('Hello')

    stream.processDataStream({
      onTextPart: text => {
        console.log(text)
      },
    })
  } catch (error) {
    return 'Error occurred while generating response'
  }
}
```

:::note

调用 `.stream()` 时也可以传入消息对象数组，每个对象包含 `role` 和 `content`。详情请参阅 [.stream() 参考](/reference/client-js/agents#stream)。

:::

## 配置选项 {/* #configuration-options */}

`MastraClient` 支持 `retries`、`backoffMs` 和 `headers` 等可选参数，用于控制请求行为，例如配置重试或附带诊断元数据。

```typescript title="lib/mastra-client.ts"
import { MastraClient } from '@mastra/client-js'

export const mastraClient = new MastraClient({
  retries: 3,
  backoffMs: 300,
  maxBackoffMs: 5000,
  headers: {
    'X-Development': 'true',
  },
})
```

更多配置选项请参阅 [MastraClient](/reference/client-js/mastra-client)。

## 凭证和会话 Cookie {/* #credentials-and-session-cookies */}

UI 和 Mastra API 分属不同源（主机、子域或端口不同）时，例如 Mastra Studio 和自定义服务器使用不同端口，可 **使用会话 Cookie 验证 Mastra API 请求**。为 `MastraClient` 添加 **`credentials: 'include'`**，使每个请求都携带用户登录后已有的 Cookie。缺少此设置时，即使已在浏览器中成功登录，也常会收到 Mastra 返回的 **`401`** 响应。

```typescript title="lib/mastra-client.ts"
import { MastraClient } from '@mastra/client-js'

export const mastraClient = new MastraClient({
  baseUrl: process.env.MASTRA_API_URL || 'http://localhost:4111',
  credentials: 'include',
})
```

**在服务器上允许携带凭证的跨源请求**。请参阅 [CORS：携带凭证的请求](https://developer.mozilla.org/en-US/docs/Web/HTTP/Guides/CORS#requests_with_credentials)。必须为 `Access-Control-Allow-Origin` 指定具体的源（不能用 `*`），并设置 `Access-Control-Allow-Credentials: true`，否则浏览器会在请求到达 Mastra 前拦截它。

**使用 `@mastra/react` 时**，用 `MastraReactProvider` 包裹应用，将 `baseUrl` 和 `apiPrefix` 设置为与服务器一致，并沿用默认的 `credentials: 'include'`。只有需要 `same-origin` 或 `omit` 行为时才更改 `credentials`。

## 支持取消请求 {/* #adding-request-cancelling */}

`MastraClient` 通过 Node.js 的标准 `AbortSignal` API 支持取消请求。例如，用户中止操作时可取消正在进行的请求，也可借此清理过期的网络请求。

将 `AbortSignal` 传给客户端构造函数，即可为所有请求启用取消功能。

```typescript {3,7} title="lib/mastra-client.ts"
import { MastraClient } from '@mastra/client-js'

export const controller = new AbortController()

export const mastraClient = new MastraClient({
  baseUrl: process.env.MASTRA_API_URL || 'http://localhost:4111',
  abortSignal: controller.signal,
})
```

### 使用 `AbortController` {/* #using-the-abortcontroller */}

调用 `.abort()` 会取消与该信号关联的所有进行中的请求。

```typescript
import { mastraClient, controller } from 'lib/mastra-client'

const handleAbort = () => {
  controller.abort()
}
```

## 客户端 Tool {/* #client-tools */}

使用 `createTool()` 函数直接在客户端应用中定义 Tool。调用 `.generate()` 或 `.stream()` 时，通过 `clientTools` 参数将这些 Tool 传给 Agent。

这样，Agent 就可以触发浏览器端的功能，例如操作 DOM、访问本地存储或使用其他 Web API。Tool 会在用户的浏览器环境中执行，无须在服务器端执行。

```typescript {26}
import { createTool } from '@mastra/client-js'
import { z } from 'zod'

const handleClientTool = async () => {
  try {
    const agent = mastraClient.getAgent('colorAgent')

    const colorChangeTool = createTool({
      id: 'color-change-tool',
      description: 'Changes the HTML background color',
      inputSchema: z.object({
        color: z.string(),
      }),
      outputSchema: z.object({
        success: z.boolean(),
      }),
      execute: async inputData => {
        const { color } = inputData

        document.body.style.backgroundColor = color
        return { success: true }
      },
    })

    const response = await agent.generate('Change the background to blue', {
      clientTools: { colorChangeTool },
    })

    console.log(response)
  } catch (error) {
    console.error(error)
  }
}
```

### 使用客户端 Tool 的 Agent {/* #client-tool-agent */}

这是一个标准的 Mastra [Agent](../agents/overview#quickstart)，配置为返回十六进制颜色代码，以配合上面定义的浏览器端 Tool 使用。

```typescript title="src/mastra/agents/color-agent"
import { Agent } from '@mastra/core/agent'

export const colorAgent = new Agent({
  id: 'color-agent',
  name: 'Color Agent',
  instructions: `You are a helpful CSS assistant.
  You can change the background color of web pages.
  Respond with a hex reference for the color requested by the user`,
  model: '__GATEWAY_OPENAI_MODEL__',
})
```

## 在服务器端使用 MastraClient {/* #use-mastraclient-on-the-server */}

服务器端 API 路由和无服务器函数（包括 action）也可以使用 `MastraClient`。用法相同，但你可能需要为客户端重新构造响应：

```typescript {8}
export async function action() {
  const agent = mastraClient.getAgent('testAgent')

  const stream = await agent.stream('Hello')

  return new Response(stream.body)
}
```
