# 定制适配器

当预构建的服务器适配器（Hono、Express、Fastify、Koa）不支持您的框架或者您有特定的请求/响应处理要求时，创建自定义适配器。

自定义适配器在 Mastra 的路由定义和框架的路由系统之间进行转换。您将使用框架的 API 实现注册中间件、处理请求和发送响应的方法。

使用以下任何预构建的服务器适配器：

* [@mastra/荣誉](/reference/server/hono-adapter)
* [@mastra/快递](/reference/server/express-adapter)
* [@mastra/fastify](/reference/server/fastify-adapter)
* [@mastra/koa](/reference/server/koa-adapter)

## 抽象类 {/* #abstract-class */}

这`MastraServer` abstract class from `@mastra/server/server-adapter` provides the foundation for all adapters. It handles route registration logic, parameter validation, and other shared functionality. Your custom adapter extends this class and implements the framework-specific parts.

该类采用三个代表框架类型的类型参数：

```typescript title="my-framework-adapter.ts"
import { MastraServer } from '@mastra/server/server-adapter'

export class MyFrameworkServer extends MastraServer<
  // Your framework's app type (e.g., FastifyInstance)
  MyApp,
  // Your framework's request type (e.g., FastifyRequest)
  MyRequest,
  // Your framework's response type (e.g., FastifyReply)
  MyResponse
> {
  // Implement abstract methods
}
```

这些类型参数可确保整个适配器实现的类型安全，并在访问特定于框架的 API 时启用正确的类型。

## 所需方法 {/* #required-methods */}

您必须实现这七个抽象方法。每个处理请求生命周期的特定部分，从附加上下文到发送响应。

### `registerContextMiddleware()` {/* #registercontextmiddleware */}

此方法首先运行并将 Mastra 上下文附加到每个传入请求。路由处理程序需要访问 Mastra 实例、Tool和其他上下文才能发挥作用。如何附加此上下文取决于您的框架，Express 使用`res.locals`, Hono uses `c.set()`, and other frameworks have their own patterns.

```typescript oxfmt:false
registerContextMiddleware(): void {
  this.app.use('*', (req, res, next) => {
    // Attach context to your framework's request/response
    res.locals.mastra = this.mastra;
    res.locals.requestContext = new RequestContext();
    res.locals.tools = this.tools;
    res.locals.abortSignal = createAbortSignal(req);
    next();
  });
}
```

要附加的上下文：

|关键|类型 |描述 |
| - | - | - |
|`mastra` | `Mastra` | The Mastra instance |
| `requestContext` | `RequestContext` | Request-scoped context map |
| `tools` | `Record<string, Tool>` | Available tools |
| `abortSignal` | `AbortSignal` | Request cancellation signal |
| `taskStore` | `InMemoryTaskStore`| A2A 任务存储（如果配置）|

### `registerAuthMiddleware()` {/* #registerauthmiddleware */}

注册身份验证和授权中间件。此方法应检查 Mastra 实例上是否配置了身份验证，如果没有，则完全跳过注册。配置身份验证后，您通常会注册两个中间件函数：一种用于身份验证（验证令牌并设置用户），另一种用于授权（检查用户是否可以访问所请求的资源）。

```typescript oxfmt:false
registerAuthMiddleware(): void {
  const authConfig = this.mastra.getServer()?.auth;
  if (!authConfig) return;

  // Register authentication (validate token, set user)
  this.app.use('*', async (req, res, next) => {
    const token = extractToken(req);
    const user = await authConfig.authenticateToken?.(token, req);
    if (!user) {
      return res.status(401).json({ error: 'Unauthorized' });
    }
    res.locals.user = user;
    next();
  });

  // Register authorization (check permissions)
  this.app.use('*', async (req, res, next) => {
    const allowed = await authConfig.authorize?.(
      req.path,
      req.method,
      res.locals.user,
      res
    );
    if (!allowed) {
      return res.status(403).json({ error: 'Forbidden' });
    }
    next();
  });
}
```

### `registerHttpLoggingMiddleware()` {/* #registerhttploggingmiddleware */}

注册请求日志记录中间件。`init()` calls this after the context, auth, and user middleware. Return early when request logging isn't enabled in `this.httpLoggingConfig`, and skip paths that `this.shouldLogRequest()` excludes. Implement this method as a no-op if your framework has no way to log requests.

```typescript oxfmt:false
registerHttpLoggingMiddleware(): void {
  if (!this.httpLoggingConfig?.enabled) return;

  this.app.use((req, res, next) => {
    if (!this.shouldLogRequest(req.path)) {
      return next();
    }

    const start = Date.now();
    const method = req.method;
    const path = req.path;

    res.on('finish', () => {
      const duration = Date.now() - start;
      const level = this.httpLoggingConfig?.level || 'info';
      const logData: Record<string, unknown> = {
        method,
        path,
        status: res.statusCode,
        duration: `${duration}ms`,
      };

      if (this.httpLoggingConfig?.includeQueryParams) {
        logData.query = req.query;
      }

      if (this.httpLoggingConfig?.includeHeaders) {
        const headers = { ...req.headers };
        for (const name of this.httpLoggingConfig.redactHeaders || []) {
          const key = name.toLowerCase();
          if (headers[key] !== undefined) headers[key] = '[REDACTED]';
        }
        logData.headers = headers;
      }

      this.logger[level](`${method} ${path} ${res.statusCode} ${duration}ms`, logData);
    });
    next();
  });
}
```

### `registerRoute()` {/* #registerroute */}

向您的框架注册单个路由。在初始化期间，每个 Mastra 路由都会调用该方法一次。它接收到一个`ServerRoute` object containing the path, HTTP method, handler function, and Zod schemas for validation. Your implementation should wire this up to your framework's routing system.

```typescript oxfmt:false
async registerRoute(
  app: MyApp,
  route: ServerRoute,
  { prefix }: { prefix?: string }
): Promise<void> {
  const path = `${prefix || ''}${route.path}`;
  const method = route.method.toLowerCase();

  app[method](path, async (req, res) => {
    try {
      // 1. Extract parameters
      const params = await this.getParams(route, req);

      // 2. Validate with Zod schemas
      const queryParams = await this.parseQueryParams(route, params.queryParams);
      const body = await this.parseBody(route, params.body);

      // 3. Build handler params
      const handlerParams = {
        ...params.urlParams,
        ...queryParams,
        ...(typeof body === 'object' ? body : {}),
        mastra: this.mastra,
        requestContext: res.locals.requestContext,
        tools: res.locals.tools,
        abortSignal: res.locals.abortSignal,
        taskStore: this.taskStore,
      };

      // 4. Call handler
      const result = await route.handler(handlerParams);

      // 5. Send response
      return this.sendResponse(route, res, result);
    } catch (error) {
      const status = error.status ?? error.details?.status ?? 500;
      return res.status(status).json({ error: error.message });
    }
  });
}
```

### `getParams()` {/* #getparams */}

从传入请求中提取 URL 参数、查询参数和请求正文。 Express 使用不同的框架以不同的方式公开这些值`req.params`, `req.query`, and `req.body`, while other frameworks may use different property names or require method calls. This method normalizes the extraction for your framework.

```typescript oxfmt:false
async getParams(
  route: ServerRoute,
  request: MyRequest
): Promise<{
  urlParams: Record<string, string>;
  queryParams: Record<string, string | string[]>; // repeated keys (?tag=a&tag=b) become arrays
  body: unknown;
}> {
  return {
    // From route path (e.g., :agentId)
    urlParams: request.params,
    // From URL query string
    queryParams: request.query,
    // From request body
    body: request.body,
  };
}
```

### `sendResponse()` {/* #sendresponse */}

根据路由的响应类型将响应发送回客户端。 Mastra 路由可以返回不同的响应类型：用于大多数 API 响应的 JSON 和用于Agent生成的流，以及用于 MCP 传输的特殊类型。您的实现应该针对您的框架适当地处理每种类型。

```typescript oxfmt:false
async sendResponse(
  route: ServerRoute,
  response: MyResponse,
  result: unknown
): Promise<unknown> {
  switch (route.responseType) {
    case 'json':
      return response.json(result);

    case 'stream':
      return this.stream(route, response, result);

    case 'datastream-response':
      // Return AI SDK Response directly
      return result;

    case 'mcp-http':
      // Handle MCP HTTP transport
      return this.handleMcpHttp(response, result);

    case 'mcp-sse':
      // Handle MCP SSE transport
      return this.handleMcpSse(response, result);

    default:
      return response.json(result);
  }
}
```

### `stream()` {/* #stream */}

处理Agent生成的流响应。当Agent生成响应时，它会生成一个块流，当这些块可用时应将其发送到客户端。此方法从流中读取数据，并可选择应用修订来隐藏敏感数据，然后再以适当的格式（SSE 或换行符分隔的 JSON）将块写入响应。

当客户端断开连接时取消流。对于具有可恢复流的Agent（例如持久Agent），取消是客户端离开的唯一信号。如果没有它，运行就不会保留重播，并且服务器会继续读取无人接收的流。客户端也可以在路由处理程序返回之前离开，因此`close` listener added afterward never fires.

如果您的框架写入 Node.js`ServerResponse`, use the helpers from `@mastra/server/server-adapter`:

* `cancelReaderOnResponseClose(reader, res)`当响应关闭时取消读取器，或者如果响应已经关闭则立即取消读取器。称呼`dispose()` before ending the response so a normal end doesn't cancel.
* `writeWithBackpressure(res, chunk)`当套接字缓冲区已满时，等待客户端赶上，因此缓慢的客户端不会使服务器缓冲整个流。

```typescript oxfmt:false
import type { ServerResponse } from 'node:http';
import { cancelReaderOnResponseClose, writeWithBackpressure } from '@mastra/server/server-adapter';

async stream(
  route: ServerRoute,
  res: ServerResponse,
  result: unknown
): Promise<unknown> {
  const isSSE = route.streamFormat === 'sse';

  // Set streaming headers based on format
  res.setHeader('Content-Type', isSSE ? 'text/event-stream' : 'text/plain');
  res.setHeader('Transfer-Encoding', 'chunked');

  const reader = result.fullStream.getReader();
  const readerCancel = cancelReaderOnResponseClose(reader, res);

  try {
    while (true) {
      const { done, value } = await reader.read();

      if (done) {
        break;
      }

      // Apply redaction if enabled
      const chunk = this.streamOptions.redact
        ? redactChunk(value)
        : value;

      // Format based on stream format
      if (isSSE) {
        await writeWithBackpressure(res, `data: ${JSON.stringify(chunk)}\n\n`);
      } else {
        await writeWithBackpressure(res, JSON.stringify(chunk) + '\x1E');
      }
    }

    // Send completion marker (SSE uses data: [DONE], other formats use record separator)
    if (isSSE) {
      await writeWithBackpressure(res, 'data: [DONE]\n\n');
    }
  } finally {
    readerCancel.dispose();
    res.end();
  }
}
```

如果您的框架返回一个 fetch`Response` instead, wrap the stream in a `ReadableStream` that reads one chunk per `pull()` and cancels the reader in its `cancel()`. Also cancel the reader when the request's `abortSignal` aborts: some runtimes never read or cancel the body of a request that closed while the route handler ran.

## 辅助方法 {/* #helper-methods */}

基类提供了您可以在实现中使用的辅助方法。它们处理参数验证和路由注册等常见任务，因此您无需重新实现它们：

|方法|描述 |
| - | - |
|`parsePathParams(route, params)` | Validate path params with Zod schema |
| `parseQueryParams(route, params)` | Validate query params with Zod schema |
| `parseBody(route, body)` | Validate body with Zod schema |
| `mergeRequestContext({ paramsRequestContext, bodyRequestContext })` | Merge request context from multiple sources |
| `registerRoutes()` | Register all Mastra routes (calls `registerRoute` for each) |
| `registerOpenAPIRoute(app, config, { prefix })` | Register OpenAPI spec endpoint |

这`parse*` methods use Zod schemas defined on each route to validate input and return typed results. If validation fails, they throw an error with details about what went wrong.

## 构造函数 {/* #constructor */}

您的适配器的构造函数应该接受与基类相同的选项并将它们传递给`super()`. You can add additional framework-specific options if needed:

```typescript oxfmt:false
constructor(options: {
  app: MyApp;
  mastra: Mastra;
  prefix?: string;
  openapiPath?: string;
  bodyLimitOptions?: BodyLimitOptions;
  streamOptions?: StreamOptions;
  customRouteAuthConfig?: Map<string, boolean>;
  tools?: ToolsInput;
  taskStore?: InMemoryTaskStore;
  customApiRoutes?: ApiRoute[];
  mcpOptions?: MCPOptions;
}) {
  super(options);
}
```

看[Server Adapters](/docs/server/server-adapters) for full documentation on each option.

## 完整示例 {/* #full-example */}

这是一个显示所有必需方法的框架实现。这对特定于框架的部分使用伪代码，替换为框架的实际 API：

```typescript title="my-framework-adapter.ts"
import { MastraServer, ServerRoute } from '@mastra/server/server-adapter'
import type { Mastra } from '@mastra/core'

export class MyFrameworkServer extends MastraServer<MyApp, MyRequest, MyResponse> {
  constructor(options: { app: MyApp; mastra: Mastra; prefix?: string }) {
    super(options)
  }

  registerContextMiddleware(): void {
    this.app.use('*', (req, res, next) => {
      res.locals.mastra = this.mastra
      res.locals.requestContext = this.mergeRequestContext({
        paramsRequestContext: req.query.requestContext,
        bodyRequestContext: req.body?.requestContext,
      })
      res.locals.tools = this.tools ?? {}
      res.locals.abortSignal = createAbortSignal(req)
      next()
    })
  }

  registerAuthMiddleware(): void {
    const authConfig = this.mastra.getServer()?.auth
    if (!authConfig) return
    // ... implement auth middleware
  }

  registerHttpLoggingMiddleware(): void {
    if (!this.httpLoggingConfig?.enabled) return
    // ... implement request logging
  }

  async registerRoute(
    app: MyApp,
    route: ServerRoute,
    { prefix }: { prefix?: string },
  ): Promise<void> {
    // ... implement route registration
  }

  async getParams(route: ServerRoute, request: MyRequest) {
    return {
      urlParams: request.params,
      queryParams: request.query,
      body: request.body,
    }
  }

  async sendResponse(route: ServerRoute, response: MyResponse, result: unknown) {
    if (route.responseType === 'stream') {
      return this.stream(route, response, result)
    }
    return response.json(result)
  }

  async stream(route: ServerRoute, response: MyResponse, result: unknown) {
    // ... implement streaming
  }
}
```

## 用法 {/* #usage */}

实现适配器后，请按照与提供的适配器相同的方式使用它：

```typescript title="server.ts"
import { MyFrameworkServer } from './my-framework-adapter'
import { mastra } from './mastra'

const app = createMyFrameworkApp()
const server = new MyFrameworkServer({ app, mastra })

await server.init()

app.listen(4111)
```

## 测试适配器兼容性 {/* #test-adapter-compatibility */}

使用`@mastra/server-adapters-test-suite` to run the same conformance tests as Mastra's official adapters. Install it with its peer dependencies in your adapter project:

```bash npm2yarn
npm install --save-dev @mastra/server-adapters-test-suite @mastra/core @mastra/mcp @mastra/server vitest zod
```

向路由套件提供特定于框架的设置和请求执行功能：

```typescript title="src/my-framework-adapter.test.ts"
import { createRouteAdapterTestSuite } from '@mastra/server-adapters-test-suite'
import { executeHttpRequest, setupAdapter } from './adapter-test-helpers'

createRouteAdapterTestSuite({
  suiteName: 'My framework adapter',
  setupAdapter,
  executeHttpRequest,
})
```

运行流断开套件以检查当客户端断开连接并等待慢速客户端时，适配器是否取消路由的流。`startServer` serves the route over real HTTP and returns its URL. When the suite passes `beforeContext`, run it as async middleware before your context middleware:

```typescript title="src/my-framework-adapter-stream.test.ts"
import { createStreamDisconnectTestSuite } from '@mastra/server-adapters-test-suite'
import { startMyFrameworkServer } from './adapter-test-helpers'

createStreamDisconnectTestSuite({
  startServer: async (route, { beforeContext } = {}) => {
    const { url, close } = await startMyFrameworkServer(route, { beforeContext })
    return { url, close }
  },
})
```

该包还提供模型上下文协议 (MCP)、多部分请求、HTTP 日志记录和主体限制测试的根导出。请参阅[package README](https://github.com/mastra-ai/mastra/tree/main/server-adapters/server-adapters-test-suite) for the supported peer dependency versions.
