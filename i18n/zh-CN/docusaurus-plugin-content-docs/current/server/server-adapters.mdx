# Server Adapter

Server Adapter 让你用自己的 HTTP 服务器运行 Mastra，而不必使用 `mastra build` 生成的 Hono 服务器。你可以更灵活地安排自定义中间件顺序、身份验证、日志及部署配置，同时仍可将 Mastra 集成到任意 Node.js 应用，不改变 Agent 或 Workflow 的执行方式。

:::warning

Server Adapter 使用传入的 `mastra` 实例，不会执行基于文件的自动发现。请在代码中将 Agent 注册到该实例。若要使用基于文件的 Agent，请通过 `mastra dev` 或 `mastra build` 将 Mastra 作为独立服务器运行。

:::

## 何时使用服务器适配器 {/* #when-to-use-server-adapters */}

* 您希望 Mastra 的端点自动添加到现有应用程序中
* 您需要直接访问服务器实例以进行自定义配置
- 团队希望使用其他服务器框架，而非 `mastra build` 创建的 Hono 服务器。

:::tip

如果部署不需要自定义服务器，请使用 `mastra build`。它会设置服务器、注册中间件，并根据项目配置应用部署设置。参见[服务器配置](/docs/server/overview)。

如果要将 [Studio](/docs/studio/overview) 与 Server Adapter 配合使用，请通过 [`mastra studio`](/reference/cli/mastra#mastra-studio) 单独启动 Studio 界面。

:::

## 配置 {/* #configuration */}

按常规方式初始化应用，然后传入 `app` 和 `src/mastra/index.ts` 中的主 `mastra` 实例来创建 `MastraServer`。调用 `init()` 会自动注册 Mastra 中间件及所有可用端点。你可以在 `init()` 前后继续添加自己的路由，它们会与 Mastra 端点一同运行。

<Tabs>
  <TabItem value="elysia" label="Elysia">
    ```typescript {7} title="src/elysia-server.ts"
    import { Elysia } from 'elysia'
    import { MastraServer } from '@mastra/elysia'
    import { mastra } from './mastra'

    const app = new Elysia()
    const server = new MastraServer({ app, mastra })

    await server.init()

    app.listen(4111)

    console.log('Server running on http://localhost:4111')
    ```

    :::info

    完整配置选项见 [Elysia Adapter](/reference/server/elysia-adapter) 文档。

    :::
  </TabItem>

  <TabItem value="express" label="Express">

## 初始化流程 {/* #initialization-flow */}

调用 `init()` 会按顺序执行四个步骤。了解该流程有助于在特定位置插入自己的中间件。

1. `registerContextMiddleware()`：将 Mastra 实例、请求上下文、Tool和中止信号附加到每个请求。这使得 Mastra 可用于所有后续中间件和路由处理程序。
1. `registerAuthMiddleware()`：初始化时运行适配器的身份验证 Hook。官方适配器在 Mastra 注册内置路由和 `registerApiRoute()` 路由时直接执行身份验证；直接在框架上注册的路由如需 Mastra 身份验证，应使用适配器导出的 `createAuthMiddleware()`。
1. `registerUserMiddleware()`：注册来自 `server.middleware` 配置和 `mastra.setServerMiddleware()` 的[中间件](/docs/server/middleware)。这些处理函数使用 Hono 签名，因此基于 Hono 的适配器（`@mastra/hono` 及其衍生适配器）会挂载它们；其他适配器会记录警告，而非静默忽略配置。
1. `registerRoutes()`：注册 Agent、Workflow 等功能的所有 Mastra API 路由。若已配置 MCP Server，也会注册 MCP 路由。

### 手动初始化 {/* #manual-initialization */}

若要自定义中间件顺序，请分别调用各方法，而非使用 `init()`。这样可让中间件在 Mastra 上下文建立前运行，或在不同初始化步骤之间插入逻辑。

```typescript title="server.ts" oxfmt:false
const server = new MastraServer({ app, mastra });

// Your middleware first
app.use(loggingMiddleware);

server.registerContextMiddleware();

// Middleware that needs Mastra context
app.use(customMiddleware);

// Registers `server.middleware` and `setServerMiddleware()` middleware
server.registerUserMiddleware();

await server.registerRoutes();

// Routes after Mastra
app.get('/health', ...);
```

:::tip

当您需要在 Mastra 上下文可用之前运行中间件时，或者当您需要在上下文和身份验证步骤之间插入中间件时，请使用手动初始化。

:::

## 启动后台工作者 {/* #start-background-workers */}

`init()` 只注册中间件和路由，不会启动 Mastra 的后台 [Worker](/docs/deployment/workers)。`mastra build` 生成的服务器会自动启动；使用 Server Adapter 时，需要自行调用 `mastra.startWorkers()`。

如果没有此调用，以下功能将永远不会运行：

- [定时 Workflow](/docs/workflows/scheduled-workflows)：不会创建调度记录，也不会触发 cron。
- 通过 `mastra.schedules` 创建的 [Agent 日程](/docs/harness/schedules)
* 您在 Mastra 实例上注册的事件侦听器
- [恢复循环](/docs/workflows/overview#recovery-loop)：此服务器启动后实例停止的默认引擎 Workflow 运行不会重启。

服务器开始监听后，调用一次 `startWorkers()`：

```typescript title="server.ts"
import express from 'express'
import { MastraServer } from '@mastra/express'
import { mastra } from './mastra'

const app = express()
app.use(express.json())

const server = new MastraServer({ app, mastra })
await server.init()

const httpServer = app.listen(4111, async () => {
  try {
    await mastra.startWorkers()
  } catch (error) {
    console.error('Failed to start background workers', error)
    httpServer.close(() => process.exit(1))
  }
})

process.on('SIGTERM', async () => {
  await mastra.shutdown()
  process.exit(0)
})
```

`startWorkers()` 是幂等的，重复调用不会产生额外效果。`mastra.shutdown()` 会停止 Worker，并在关闭 Worker 和 pub/sub 订阅前，等待进行中的 Workflow 运行完成或挂起。等待受 `drainTimeout` 限制（默认 5 秒）；超时未结束的运行会被放弃并记录警告。

如果 Worker 运行在[独立进程](/docs/deployment/workers#split-processes)中，请不要在 API 进程调用 `startWorkers()`，而应在 Worker 进程中启动。

## 添加自定义路线 {/* #adding-custom-routes */}

您可以将自己的路线与 Mastra 的路线一起添加到应用程序中。

- 在 `init()` **之前**添加的路由无法访问 Mastra 上下文。
- 在 `init()` **之后**添加的路由可以访问 Mastra 上下文（Mastra 实例、请求上下文、已验证用户等）。
- 如需 Mastra 管理的身份验证，以及 `requiresAuth` 等路由元数据，优先使用 `registerApiRoute()`。
- 直接在框架应用上挂载的路由如需 Mastra 身份验证，请使用适配器导出的 `createAuthMiddleware()` 辅助函数。

详情见 [Elysia](/reference/server/elysia-adapter#adding-custom-routes)、[Express](/reference/server/express-adapter#adding-custom-routes) 和 [Hono](/reference/server/hono-adapter#adding-custom-routes) 的“添加自定义路由”章节。

## 路由前缀 {/* #route-prefixes */}

Mastra 路由默认注册在 `/api/agents`、`/api/workflows` 等路径下。使用 `prefix` 选项可以修改前缀，适合 API 版本管理，或集成已有 `/api` 路由的应用。

```typescript
const server = new MastraServer({
  app,
  mastra,
  prefix: '/api/v2',
})
```

使用此前缀后，Mastra 路由变为 `/api/v2/agents`、`/api/v2/workflows` 等。直接添加到应用的自定义路由不受此前缀影响。

[内置 MCP Server](/docs/server/mcp) 也随此前缀移至 `/api/v2/mcp`。其 OAuth 元数据仍位于服务器根路径下的 `/.well-known/oauth-protected-resource/api/v2/mcp`。

## OpenAPI 规范 {/* #openapi-spec */}

Mastra 可为所有已注册路由生成 OpenAPI 规范，便于生成文档或客户端，也可与 API 工具集成。设置 `openapiPath` 选项即可启用：

```typescript
const server = new MastraServer({
  app,
  mastra,
  openapiPath: '/openapi.json',
})
```

规范根据各路由定义的 Zod Schema 生成，并在指定路径提供服务。它包含所有 Mastra 路由，以及通过 `createRoute()` 创建的自定义路由。

## 流数据脱敏 {/* #stream-data-redaction */}

通过 HTTP 流式传输 Agent 响应时，HTTP 流层会在向客户端发送数据块前遮盖其中的敏感信息，防止以下内容意外泄露：

* 系统提示和坐席指令
* Tool定义及其参数
* 请求正文中的 API 密钥和其他凭据
* 内部配置数据

脱敏发生在 HTTP 边界，因此 `onStepFinish` 等内部回调仍可访问完整请求数据，用于调试和可观测性分析。

脱敏默认启用，可通过 `streamOptions` 配置。只有内部服务或调试确实需要在流式响应中获取完整请求数据时，才设置 `redact: false`。

```typescript
const server = new MastraServer({
  app,
  mastra,
  streamOptions: {
    redact: true, // Default
  },
})
```

完整配置选项见 [MastraServer](/reference/server/mastra-server)。

## 每个路由的身份验证覆盖 {/* #per-route-auth-overrides */}

在 Mastra 实例上配置身份验证后，默认情况下所有路由都需要身份验证。有时您需要例外：公共健康检查端点或 Webhook 接收器，或者需要更严格控制的管理路由。

使用 `customRouteAuthConfig` 覆盖特定路由的身份验证行为。键的格式为 `METHOD:PATH`，其中方法可以是 `GET`、`POST`、`PUT`、`DELETE` 或 `ALL`。路径支持通配符（`*`），可匹配多个路由。值为 `false` 时路由公开，为 `true` 时要求身份验证。

```typescript
const server = new MastraServer({
  app,
  mastra,
  customRouteAuthConfig: new Map([
    // Public health check
    ['GET:/api/health', false],
    // Public API spec
    ['GET:/api/openapi.json', false],
    // Public webhook endpoints
    ['POST:/api/webhooks/*', false],
    // Require auth even if globally disabled
    ['POST:/api/admin/reset', true],
    // Protect all methods on internal routes
    ['ALL:/api/internal/*', true],
  ]),
})
```

完整配置选项见 [MastraServer](/reference/server/mastra-server)。

## 访问应用程序 {/* #accessing-the-app */}

创建适配器后，你可能仍需访问底层框架应用，例如将其传给平台的 `serve` 函数，或从其他模块添加路由。

```typescript
// Via the MastraServer instance
const app = server.getApp()

// Via the Mastra instance (available after adapter construction)
const app = mastra.getServerApp()
```

两种方法都返回相同的应用程序实例。根据范围使用更方便的选项。

## 服务器配置与适配器选项 {/* #server-config-vs-adapter-options */}

使用 Server Adapter 时，配置来自两个位置：传给 `Mastra` 构造函数的 Mastra `server` 配置，以及适配器构造函数的选项。了解各选项的来源，可避免设置未生效时产生困惑。

### 由适配器使用 {/* #used-by-adapters */}

Adapter 从 `mastra.getServer()` 读取以下设置：

|选项|描述 |
| - | - |
| `auth` | 身份验证配置，供 `registerAuthMiddleware()` 使用。 |
| `apiRoutes` | 自定义 [`registerApiRoute()`](/reference/server/register-api-route) 路由，由 `registerCustomApiRoutes()` 注册；设置 `openapiPath` 后会加入 OpenAPI 规范。Adapter 构造函数的 `customApiRoutes` 选项会覆盖此列表。 |
| `bodySizeLimit` | 默认请求体大小上限，单位为字节。可通过 Adapter 的 `bodyLimitOptions` 覆盖。 |
| `onError` | 路由处理程序发生未捕获错误时调用的自定义错误处理函数。参见 [server.onError](/reference/configuration#serveronerror)。 |
| `middleware` | 用户提供的[中间件](/docs/server/middleware)，由 `registerUserMiddleware()` 注册。基于 Hono 的 Adapter 会运行；Elysia、Express、Fastify、Koa 和 NestJS 则记录警告，因为 Hono 处理函数无法在这些框架中运行。 |

### 仅适配器构造函数 {/* #adapter-constructor-only */}

这些选项直接传递给适配器构造函数，而不是从 Mastra 配置中读取：

|选项|描述 |
| - | - |
| `prefix` | 路由路径前缀 |
| `openapiPath` | OpenAPI 规范端点 |
| `bodyLimitOptions` | 请求体大小上限及自定义错误处理函数 |
| `streamOptions` | 流式数据脱敏设置 |
| `customRouteAuthConfig` | 单路由身份验证覆盖规则 |
| `mcpOptions` | MCP 传输选项（例如通过 `setRequestAuth` 控制 `context.mcp.extra.authInfo`） |

### 不被适配器使用 {/* #not-used-by-adapters */}

以下 `server` 配置选项仅由 `mastra build` 使用；直接使用 Adapter 时不生效：

|选项 |使用者 |
| - | - |
|`port`, `host` | `mastra dev`, `mastra build` |
| `cors` | `mastra build` 会添加 CORS 中间件 |
| `timeout` | `mastra build` |

使用适配器时，直接使用您的框架配置这些功能。例如，使用 Hono 或 Express 的内置 CORS 包添加 CORS 中间件，并在调用框架的监听函数时设置端口。

## MCP支持 {/* #mcp-support */}

如果 Mastra 实例配置了 MCP Server，Server Adapter 会在 `registerRoutes()` 阶段注册 MCP（Model Context Protocol）路由。MCP 允许外部工具和服务连接 Mastra Server，并与 Agent 交互。

每个 Server 通过 Streamable HTTP 暴露在 `/api/mcp/:serverId/mcp`。传输层默认在请求间保留会话状态。对于 Cloudflare Workers 或 Vercel Edge 等无服务器环境，可设置 `mcpOptions: { serverless: true }`，以无状态模式运行，不管理会话。

通过 `mcpOptions` 控制已验证主体的信息如何传给 Tool。使用 Mastra Deployer（标准的 `mastra dev` / `mastra build` 路径）时，请在 Server 配置中设置：

```typescript
const mastra = new Mastra({
  server: {
    mcpOptions: {
      setRequestAuth: (req, requestContext) => {
        req.auth = requestContext.get('mcpAuth')
      },
    },
  },
})
```

手动创建 Server Adapter 时，直接传入 `mcpOptions`：

```typescript
const server = new MastraServer({
  app,
  mastra,
  mcpOptions: {
    setRequestAuth: (req, requestContext) => {
      req.auth = requestContext.get('mcpAuth')
    },
  },
})
```

配置详情以及 MCP Server 的设置方法见 [MCP](/docs/connections/mcp)。
