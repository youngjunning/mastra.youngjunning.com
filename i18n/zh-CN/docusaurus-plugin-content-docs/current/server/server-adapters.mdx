# 服务器适配器

服务器适配器允许您使用自己的 HTTP 服务器运行 Mastra，而不是使用由`mastra build`。它们提供对服务器设置的更多控制，包括自定义中间件排序、身份验证、日志记录和部署配置。您仍然可以将 Mastra 集成到任何 Node.js 应用程序中，而无需更改Agent或Workflow程的执行方式。

：：：警告

服务器适配器使用`mastra` instance you pass them and don't run file-based discovery. Register agents on that instance in code. To use file-based agents, run Mastra as a separate server with `mastra dev` or `mastra build`.

:::

## 何时使用服务器适配器 {/* #when-to-use-server-adapters */}

* 您希望 Mastra 的端点自动添加到现有应用程序中
* 您需要直接访问服务器实例以进行自定义配置
* 您的团队更喜欢使用另一个服务器框架，而不是由创建的 Hono 服务器`mastra build`.

：：：提示

对于没有自定义服务器要求的部署，请使用`mastra build` instead. It configures server setup and registers middleware, plus applies deployment settings based on your project configuration. See [Server Configuration](/docs/server/overview).

如果你想使用[Studio](/docs/studio/overview) with your server adapter, use [`mastra studio`](/reference/cli/mastra#mastra-studio) to only launch the Studio UI.

:::

## 配置 {/* #configuration */}

像往常一样初始化您的应用程序，然后创建一个`MastraServer` by passing in the `app` and your main `mastra` instance from `src/mastra/index.ts`. Calling `init()` automatically registers Mastra middleware and all available endpoints. Continue adding your own routes either before or after `init()`. They run alongside Mastra’s endpoints.

    import { mastra } from './mastra'

    const app = new Elysia()
    const server = new MastraServer({ app, mastra })

## 初始化流程 {/* #initialization-flow */}

呼唤`init()` runs four steps in order. Understanding this flow helps when you need to insert your own middleware at specific points.

1. `registerContextMiddleware()`：将 Mastra 实例、请求上下文、Tool和中止信号附加到每个请求。这使得 Mastra 可用于所有后续中间件和路由处理程序。
2. `registerAuthMiddleware()`：在初始化期间运行适配器身份验证挂钩。当 Mastra 注册内置路由时，官方适配器会强制执行内联身份验证`registerApiRoute()` routes, so raw framework routes should use the adapter's exported `createAuthMiddleware()` helper when they need Mastra auth.
3. `registerUserMiddleware()`：寄存器[middleware](/docs/server/middleware) from the `server.middleware` config and `mastra.setServerMiddleware()`. Middleware handlers use Hono's signature, so Hono-based adapters (`@mastra/hono` and the adapters built on it) mount them; other adapters log a warning instead of silently ignoring the config.
4. `registerRoutes()`：注册Agent、Workflow程和其他功能的所有 Mastra API 路由。如果配置了 MCP 服务器，还会注册 MCP 路由。

### 手动初始化 {/* #manual-initialization */}

对于自定义中间件排序，请单独调用每个方法，而不是`init()`. This is useful when you need middleware that runs before Mastra's context is set up, or when you need to insert logic between the initialization steps.

```typescript title="server.ts" oxfmt:false
const server = new MastraServer({ app, mastra });

// Your middleware first
app.use(loggingMiddleware);

server.registerContextMiddleware();

// Middleware that needs Mastra context
app.use(customMiddleware);

// Registers `server.middleware` and `setServerMiddleware()` middleware
server.registerUserMiddleware();

await server.registerRoutes();

// Routes after Mastra
app.get('/health', ...);
```

：：：提示

当您需要在 Mastra 上下文可用之前运行中间件时，或者当您需要在上下文和身份验证步骤之间插入中间件时，请使用手动初始化。

:::

## 启动后台工作者 {/* #start-background-workers */}

`init()`仅注册中间件和路由。它没有启动Mastra的背景[workers](/docs/deployment/workers). The server generated by `mastra build` starts them for you, but with a server adapter you call `mastra.startWorkers()` yourself.

如果没有此调用，以下功能将永远不会运行：

* [预定的Workflow程](/docs/workflows/scheduled-workflows)：不会创建计划行并且不会触发 cron 触发器。
* [Agent日程](/docs/harness/schedules)创建于`mastra.schedules`
* 您在 Mastra 实例上注册的事件侦听器
* 这[recovery loop](/docs/workflows/overview#recovery-loop): Default-engine workflow runs whose instance stops after this server booted aren't restarted.

称呼`startWorkers()` once, after the server starts listening:

```typescript title="server.ts"
import express from 'express'
import { MastraServer } from '@mastra/express'
import { mastra } from './mastra'

const app = express()
app.use(express.json())

const server = new MastraServer({ app, mastra })
await server.init()

const httpServer = app.listen(4111, async () => {
  try {
    await mastra.startWorkers()
  } catch (error) {
    console.error('Failed to start background workers', error)
    httpServer.close(() => process.exit(1))
  }
})

process.on('SIGTERM', async () => {
  await mastra.shutdown()
  process.exit(0)
})
```

`startWorkers()`是幂等的，因此第二次调用没有效果。`mastra.shutdown()` stops the workers and drains in-flight workflow runs into a finished or suspended state before workers and pub/sub subscriptions are torn down. The drain is bounded by `drainTimeout` (default 5 seconds), and runs that don't settle within it are abandoned with a warning.

如果你在一个[separate process](/docs/deployment/workers#split-processes), skip `startWorkers()` in the API process and start them in the worker process instead.

## 添加自定义路线 {/* #adding-custom-routes */}

您可以将自己的路线与 Mastra 的路线一起添加到应用程序中。

* 已添加路线**before** `init()` won't have Mastra context available.
* 已添加路线**after** `init()` have access to the Mastra context (the Mastra instance, request context, authenticated user, etc.).
* 当您需要 Mastra 管理的身份验证和路由元数据时，例如`requiresAuth`, prefer `registerApiRoute()`.
* 当您直接在框架应用程序上挂载路由时，请使用适配器的导出`createAuthMiddleware()` helper if those routes need Mastra auth.

访问“添加自定义路由”[Elysia](/reference/server/elysia-adapter#adding-custom-routes), [Express](/reference/server/express-adapter#adding-custom-routes), and [Hono](/reference/server/hono-adapter#adding-custom-routes) for more information.

## 路由前缀 {/* #route-prefixes */}

默认情况下，Mastra 路由注册于`/api/agents`, `/api/workflows`, etc. Use the `prefix` option to change this. This is useful for API versioning or when integrating with an existing app that has its own `/api` routes.

```typescript
const server = new MastraServer({
  app,
  mastra,
  prefix: '/api/v2',
})
```

有了这个前缀，Mastra 路线就变成了`/api/v2/agents`, `/api/v2/workflows`, etc. Custom routes you add directly to the app aren't affected by this prefix.

这[built-in MCP server](/docs/server/mcp) moves with the prefix to `/api/v2/mcp`. Its OAuth metadata stays at the server root, at `/.well-known/oauth-protected-resource/api/v2/mcp`.

## OpenAPI 规范 {/* #openapi-spec */}

Mastra 可以为所有注册的路线生成 OpenAPI 规范。这对于文档或客户端生成非常有用，包括与 API Tool的集成。通过设置启用它`openapiPath` option:

```typescript
const server = new MastraServer({
  app,
  mastra,
  openapiPath: '/openapi.json',
})
```

该规范是根据每个路由上定义的 Zod 架构生成的，并在指定路径上提供服务。它包括所有 Mastra 路线以及使用创建的任何自定义路线`createRoute()`.

## 流数据编辑 {/* #stream-data-redaction */}

当流Agent通过 HTTP 进行响应时，HTTP 流层会在将流块发送到客户端之前编辑敏感信息。这可以防止意外暴露：

* 系统提示和坐席指令
* Tool定义及其参数
* 请求正文中的 API 密钥和其他凭据
* 内部配置数据

此修订发生在 HTTP 边界，因此内部回调如下`onStepFinish` still have access to the full request data for debugging and observability purposes.

默认情况下，启用密文。通过配置此行为`streamOptions`. Set `redact: false` only for internal services or debugging scenarios where you need access to the full request data in stream responses.

```typescript
const server = new MastraServer({
  app,
  mastra,
  streamOptions: {
    redact: true, // Default
  },
})
```

看[MastraServer](/reference/server/mastra-server) for full configuration options.

## 每个路由的身份验证覆盖 {/* #per-route-auth-overrides */}

在 Mastra 实例上配置身份验证后，默认情况下所有路由都需要身份验证。有时您需要例外：公共健康检查端点或 Webhook 接收器，或者需要更严格控制的管理路由。

使用`customRouteAuthConfig` to override authentication behavior for specific routes. Keys follow the format `METHOD:PATH` where method is `GET`, `POST`, `PUT`, `DELETE`, or `ALL`. Paths support wildcards (`*`) for matching multiple routes. Setting a value to `false` makes the route public, while `true` requires authentication.

```typescript
const server = new MastraServer({
  app,
  mastra,
  customRouteAuthConfig: new Map([
    // Public health check
    ['GET:/api/health', false],
    // Public API spec
    ['GET:/api/openapi.json', false],
    // Public webhook endpoints
    ['POST:/api/webhooks/*', false],
    // Require auth even if globally disabled
    ['POST:/api/admin/reset', true],
    // Protect all methods on internal routes
    ['ALL:/api/internal/*', true],
  ]),
})
```

看[MastraServer](/reference/server/mastra-server) for full configuration options.

## 访问应用程序 {/* #accessing-the-app */}

创建适配器后，您可能仍然需要访问底层框架应用程序。将其传递到平台时这很有用`serve` function or when adding routes from another module.

```typescript
// Via the MastraServer instance
const app = server.getApp()

// Via the Mastra instance (available after adapter construction)
const app = mastra.getServerApp()
```

两种方法都返回相同的应用程序实例。根据范围使用更方便的选项。

## 服务器配置与适配器选项 {/* #server-config-vs-adapter-options */}

使用服务器适配器时，配置来自两个地方：Mastra`server` config (passed to the `Mastra` constructor) and the adapter constructor options. Understanding which options come from where helps avoid confusion when settings don't seem to take effect.

### 由适配器使用 {/* #used-by-adapters */}

适配器读取这些设置`mastra.getServer()`:

|选项|描述 |
| - | - |
|`auth` | Authentication config, used by `registerAuthMiddleware()`. |
| `apiRoutes` | Custom [`registerApiRoute()`](/reference/server/register-api-route) routes, registered by `registerCustomApiRoutes()` and added to the OpenAPI spec when `openapiPath` is set. The adapter constructor `customApiRoutes` option overrides this list. |
| `bodySizeLimit` | Default body size limit in bytes. Can be overridden per-adapter via `bodyLimitOptions`. |
| `onError` | Custom error handler called when an unhandled error occurs in a route handler. See [server.onError](/reference/configuration#serveronerror). |
| `middleware` | User [middleware](/docs/server/middleware), registered by `registerUserMiddleware()`. Hono-based adapters run it; Elysia, Express, Fastify, Koa, and NestJS log a warning because Hono handlers can't run there. |

### 仅适配器构造函数 {/* #adapter-constructor-only */}

这些选项直接传递给适配器构造函数，而不是从 Mastra 配置中读取：

|选项|描述 |
| - | - |
|`prefix` | Route path prefix |
| `openapiPath` | OpenAPI spec endpoint |
| `bodyLimitOptions` | Body size limit with custom error handler |
| `streamOptions` | Stream redaction settings |
| `customRouteAuthConfig` | Per-route auth overrides |
| `mcpOptions` | MCP transport options (e.g., `setRequestAuth` to control `context.mcp.extra.authInfo`) |

### 不被适配器使用 {/* #not-used-by-adapters */}

这些`server` config options are only used by `mastra build` and have no effect when using adapters directly:

|选项 |使用者 |
| - | - |
|`port`, `host` | `mastra dev`, `mastra build` |
| `cors` | `mastra build` adds CORS middleware |
| `timeout` | `mastra build` |

使用适配器时，直接使用您的框架配置这些功能。例如，使用 Hono 或 Express 的内置 CORS 包添加 CORS 中间件，并在调用框架的监听函数时设置端口。

## MCP支持 {/* #mcp-support */}

服务器适配器在期间注册MCP（模型上下文协议）路由`registerRoutes()` when MCP servers are configured in your Mastra instance. MCP allows external tools and services to connect to your Mastra server and interact with your agents.

每个服务器都暴露在`/api/mcp/:serverId/mcp` over Streamable HTTP. By default the transport keeps session state between requests. For serverless environments like Cloudflare Workers or Vercel Edge, set `mcpOptions: { serverless: true }` to run in stateless mode without session management.

经过`mcpOptions` to control how the authenticated principal reaches tools. When using the Mastra deployer (the standard `mastra dev` / `mastra build` path), set it in your server config:

```typescript
const mastra = new Mastra({
  server: {
    mcpOptions: {
      setRequestAuth: (req, requestContext) => {
        req.auth = requestContext.get('mcpAuth')
      },
    },
  },
})
```

手动创建服务器适配器时，传递`mcpOptions` directly:

```typescript
const server = new MastraServer({
  app,
  mastra,
  mcpOptions: {
    setRequestAuth: (req, requestContext) => {
      req.auth = requestContext.get('mcpAuth')
    },
  },
})
```

看[MCP](/docs/connections/mcp) for configuration details and how to set up MCP servers.
