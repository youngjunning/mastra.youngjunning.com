# 内置MCP服务器

Mastra 服务器向您公开您的Agent、Workflow程和Tool[Model Context Protocol (MCP)](https://modelcontextprotocol.io/introduction)客户在`/api/mcp`。你没有定义一个`MCPServer`对于它：在网站上注册的每个Agent、Workflow程和Tool`Mastra`实例可用，您稍后添加的Agent会自动出现。

每个 MCP Tool都是现有 HTTP 路由的薄包装器。调用运行与 HTTP 请求相同的验证、身份验证、RBAC、FGA 和所有权检查，并使用相同的`RequestContext`. An MCP client can never do more than the same user can do over the HTTP API.

使用内置服务器让编码助手和其他 MCP 客户端驱动您已经运行的 Mastra 应用程序。要使用您自己的提示和资源发布一组精​​心挑选的原语，请创建一个[`MCPServer`](/docs/connections/mcp#expose-a-mastra-mcp-server) instead.

## 安装 {/* #installation */}

端点使用`@mastra/mcp`, which `@mastra/server` declares as an optional peer dependency. Install it in your project to enable the built-in server:

```bash npm2yarn
npm install @mastra/mcp@latest
```

没有它，服务器的其余部分仍然可以工作，并且`/api/mcp` answers with HTTP 501 and a JSON-RPC error that says to install the package. `mastra build` only adds `@mastra/mcp` to the build output when your project installs it.

## 上菜时 {/* #when-its-served */}

|环境 |任职于`/api/mcp` |
| - | - |
| `mastra dev` | Yes, also without auth. Requests with a foreign `Origin` or `Host` header are rejected to block DNS rebinding. This also blocks tunnels and LAN IP addresses. To reach the endpoint from another machine, set `server.host` to the hostname or IP address clients connect to. Binding to `0.0.0.0` doesn't allow other hosts. |
| Production build with `server.auth` | Yes. Every request needs a bearer token. |
| Production build without `server.auth`|不，端点返回 404。

放`server.mcp.enabled` to override the default. `false` turns the endpoint off everywhere. `true` serves it even without `server.auth` and logs a warning, because anyone who can reach the server can then call your agents, workflows, and tools.

## 连接客户端 {/* #connect-a-client */}

启动开发服务器，然后将客户端指向端点。克劳德代码：

```bash
claude mcp add --transport http mastra http://localhost:4111/api/mcp
```

配置身份验证后，传递不记名令牌：

```bash
claude mcp add --transport http mastra https://my-app.example.com/api/mcp \
  --header "Authorization: Bearer $MASTRA_TOKEN"
```

要从命令行检查Tool，请使用[MCP Inspector](https://github.com/modelcontextprotocol/inspector):

```bash
npx @modelcontextprotocol/inspector --cli http://localhost:4111/api/mcp \
  --transport http --header "Authorization: Bearer $MASTRA_TOKEN" --method tools/list
```

光标和 VS Code 从 JSON 文件读取服务器。将其添加到`.cursor/mcp.json` for Cursor:

```json title=".cursor/mcp.json"
{
  "mcpServers": {
    "mastra": {
      "url": "http://localhost:4111/api/mcp",
      "headers": { "Authorization": "Bearer <your-token>" }
    }
  }
}
```

或者到`.vscode/mcp.json` for VS Code:

```json title=".vscode/mcp.json"
{
  "servers": {
    "mastra": {
      "type": "http",
      "url": "http://localhost:4111/api/mcp",
      "headers": { "Authorization": "Bearer <your-token>" }
    }
  }
}
```

省略`headers` when the server runs without `server.auth`. Clients that take only a URL and can't send an `Authorization` header, such as custom connectors in the Claude apps, need [OAuth discovery](#oauth-discovery) and an identity provider that lets them sign in.

端点使用无状态 Streamable HTTP 并使用 MCP`2026-07-28` and the 2025 revisions that current clients use, so no session is kept between requests.

### 在工作室 {/* #in-studio */}

这**MCP Servers** page in Studio shows the built-in server as **Mastra (built-in)**, above the MCP servers you register yourself. It shows the endpoint URL (including a custom `server.mcp.path` or `apiPrefix`), whether the endpoint is open or protected by `server.auth`, the toolsets it serves (`include` and `exclude` aren't reflected there), and copyable setup for Claude Code, Cursor, VS Code, and the MCP Inspector. The setup uses a `<your-token>` placeholder. Replace it with your own bearer token. If the endpoint is turned off, or `@mastra/mcp` isn't installed, the card says why and how to fix it.

端点 URL 是根据 Studio 用于访问您的服务器的地址构建的。如果 MCP 客户端通过不同的公共 URL（例如在Agent后面）到达服务器，请在设置中使用该 URL。和[OAuth discovery](#oauth-discovery), a client that can sign in doesn't need the `Authorization` header.

Studio 从中读取此内容`GET /api/mcp/builtin`, which needs the `mcp:read` permission. Studio doesn't list the server's tools or let you try them, because the tool list depends on the caller's token. Connect a client to see your tools.

## Tool {/* #tools */}

服务器将Tool分组到Tool集中。本节涵盖`agents`, `workflows`, and `tools`; see [Memory, observability, and agent builder](#memory-observability-and-agent-builder) for the others. Agents and workflows are reached through operation tools that take the id as an argument. The tool list stays the same size however many agents you add.

请参阅[built-in MCP tools reference](/reference/server/builtin-mcp-tools) for every tool's arguments, route, and permission.

|Tool组 |Tool|支持 HTTP 路由 |
| - | - | - |
|`agents` | `list_agents`, `get_agent`, `call_agent` | `GET /agents`, `GET /agents/:agentId`, `POST /agents/:agentId/generate` |
| `workflows` | `list_workflows`, `get_workflow`, `start_workflow`, `get_workflow_run`, `resume_workflow_run`, `cancel_workflow_run` | `GET /workflows`, `GET /workflows/:workflowId`, `POST /workflows/:workflowId/start-async`, `GET /workflows/:workflowId/runs/:runId`, `POST /workflows/:workflowId/resume-async`, `POST /workflows/:workflowId/runs/:runId/cancel` |
| `tools` | `tool_<id>`对于每个注册的Tool|`POST /tools/:toolId/execute` |

* 当呼叫者最多可以看到`enumLimit` agents or workflows (25 by default), the `agentId` and `workflowId` arguments list the allowed ids. Above that they're plain strings, and the client calls `list_agents` or `list_workflows` to find ids.
* 当呼叫者可以看到超过`enumLimit` tools, the `tool_<id>` tools are replaced by `list_tools`, `get_tool`, and `call_tool`.
* `call_agent`返回回复文本和`threadId`. Pass the `threadId` back to continue the conversation in the agent's memory. A call without a `threadId` starts a new thread, so a client that never passes one stores a thread for each call.
* `start_workflow`等待运行完成或暂停。暂停的运行返回其`runId` and suspend payload. Continue it with `resume_workflow_run`.
* 没有Agent的`description` get a generic one and a warning in the logs. Add descriptions so clients can pick the right agent.

### 特色Agent和Workflow程 {/* #featured-agents-and-workflows */}

列出Agent和Workflow程`featured` to give them a dedicated tool. A featured workflow's tool takes the workflow's input schema directly:

```typescript title="src/mastra/index.ts"
import { Mastra } from '@mastra/core'

export const mastra = new Mastra({
  // ...agents, workflows, tools
  server: {
    mcp: {
      featured: { agents: ['support-agent'], workflows: ['refund'] },
    },
  },
})
```

这增加了`agent_support-agent` and `workflow_refund` next to the operation tools.

## 选择要公开的内容 {/* #choose-what-to-expose */}

使用`include` and `exclude` to select primitives by id. Each entry matches both a primitive's own `id` and the key it's registered under in `new Mastra({ ... })`, so `deleteAccountTool` and `delete-account` select the same tool. `exclude` wins over `include`. Excluded primitives are hidden from the tool list, and calling one by either name fails as not found. This includes passing an excluded agent's id to the memory tools. Observability tools aren't filtered: their results can still include traces, logs, and scores from excluded primitives. The selection only affects MCP. The HTTP routes are unchanged.

```typescript title="src/mastra/index.ts"
import { Mastra } from '@mastra/core'

export const mastra = new Mastra({
  server: {
    mcp: {
      toolsets: ['agents', 'tools'],
      include: { agents: ['support-agent', 'billing-agent'] },
      exclude: { tools: ['delete-account'] },
    },
  },
})
```

放`readOnly: true` to serve only tools whose backing route needs a `read` permission, such as `list_agents` and `get_workflow_run`.

客户端可以缩小每个连接的配置范围`?toolsets=agents,tools` or the `X-MCP-Toolsets` header, and `?readonly=1` or the `X-MCP-Readonly` header. These can only remove tools, never add tools the configuration doesn't serve.

## 身份验证和权限 {/* #authentication-and-permissions */}

端点仅接受来自`Authorization: Bearer` header, verified by `server.auth`. Session cookies, the `apiKey` query parameter, and Studio's auth configuration don't apply to it, so a browser session can't be used to reach it from another site. Other routes keep their existing auth behavior.

和[RBAC](/docs/auth/overview) configured, MCP access needs two permissions on top of the route permissions:

* `mcp:read`连接并列出Tool。
* `mcp:execute`查看并调用任何Tool。没有它的调用者会得到一个空的Tool列表，即使它可以通过 HTTP 运行相同的操作。

每次呼叫还需要备份路由的许可，例如`agents:execute` for `call_agent` and `workflows:execute` for `start_workflow`. The default `viewer` role has `mcp:read` but not `mcp:execute`; `member`, `admin`, and `owner` have both. These are the same permissions that guard the routes of `MCPServer` instances you register, so a role granted them for your own MCP servers can also use the built-in one.

Tool列表按调用者进行过滤。当呼叫者在其中看到Agent和Workflow程时，它们就会出现`GET /agents` or `GET /workflows`, including [FGA](/docs/auth/fga) read checks. Tools the caller would get a 403 for are hidden. Every call is checked again when it runs, so a stale list can't be used to bypass a permission.

线程和运行所有权的工作方式与 HTTP API 类似：用户无法继续另一个用户的线程或恢复另一个用户的Workflow运行。

入站不记名令牌不会作为参数传递给Tool，也不会转发给其他服务器。Tool收到相同的信息`RequestContext` as the equivalent HTTP request.

## 内存、可观察性和Agent构建器 {/* #memory-observability-and-agent-builder */}

这些Tool集默认处于启用状态。每个Tool仅在服务器可以支持时才提供服务，并且每个Tool都使用相同的权限和所有权检查来调用为其列出的 HTTP 路由。

|Tool组 |Tool|任职时间 |
| - | - | - |
|`memory` | `list_threads`, `get_thread`, `list_messages`, `search_memory`, `get_memory_status`, `get_observations`, `create_thread`, `update_thread`, `clone_thread`, `save_messages` | An agent has memory, or stored agents are configured |
| `observability` | `query_traces`, `aggregate_traces`, `query_spans`, `aggregate_spans`, `query_threads`, `get_trace_query_fields`, `get_trace_query_values`, `get_trace`, `get_span`, `get_trace_trajectory`, `list_logs`, `list_traces` | Storage has an observability domain |
| `observability_analytics` | `analyze_metrics`, `analyze_scores`, `analyze_feedback`, `list_metric_names`, `list_scores`, `list_feedback` | Storage has an observability domain |
| `stored_agents` | `list_available_models`, `list_stored_agents`, `get_stored_agent`, `create_stored_agent`, `update_stored_agent`|这[编辑](/docs/studio/editor)并配置了Agent存储域|

* 记忆Tool需要`agentId` and `threadId`. `resourceId` defaults to the caller when `server.auth` maps users to resources with `mapUserToResourceId`, and a caller can't read or write another resource's threads, messages, or Observational Memory. Without that mapping, a supplied `resourceId` is used as is, as on the HTTP API.
* 可观察性Tool取决于存储支持的内容。具有跟踪查询的存储，例如 DuckDB，提供服务`query_traces` and the other query tools; a store without them serves `list_traces` instead. Tools for logs, metrics, scores, and feedback appear only when the store implements them.
* `get_trace`返回光跟踪：每个跨度的 ID、父级、名称、类型、计时、状态和实体。称呼`get_span` for one span's input, output, and attributes. List and trace results are kept under about 40,000 characters. A cut result says how to get the rest: a smaller page size, or `get_trace` with the returned `nextOffset`. A single item that's still too big, such as a message with an inline image, comes back with its long values cut and marked. `get_span` returns a span in full. `get_observations` cuts an oversized record the same way.
* `analyze_metrics`, `analyze_scores`, and `analyze_feedback` take an `op` of `aggregate`, `breakdown`, `timeseries`, or `percentiles`. Each op runs the matching `/observability/<source>/<op>` route.
* `create_stored_agent`和`update_stored_agent` publish the change by default, so the agent can be called with `call_agent` right away. Pass `autoPublish: false` to keep a draft. The `agentId` argument of `call_agent` lists only the agents that existed when the client fetched the tool list, so a client must list the tools again before it can call a newly created agent.

在只读模式下，查询和聚合Tool保持可用，因为它们的路由需要`observability:read`, even though they're `POST` routes. Memory and stored-agent writes are removed. `get_observations` stays, without its `waitForPending` option, because waiting runs a route that needs `memory:write`. Callers without `memory:write` also get `get_observations` without that option.

：：：警告

可观察性数据的范围不限于调用者。任何有`observability:read` can read every user's traces, logs, scores, and feedback, over MCP and over HTTP. The default `viewer` role includes it through `*:read`. Leave out the observability toolsets, or remove `observability:read` from roles that shouldn't see other users' data:

```typescript title="src/mastra/index.ts"
import { Mastra } from '@mastra/core'

export const mastra = new Mastra({
  server: {
    mcp: { toolsets: ['agents', 'workflows', 'tools', 'memory', 'stored_agents'] },
  },
})
```

### Agent创建Agent {/* #agents-creating-agents */}

`create_stored_agent`让 MCP 客户端创建其他客户端随后可以调用的Agent。它需要`stored-agents:write`. A created agent is owned by the caller and is private by default. Without a caller identity, such as when `server.auth` isn't configured, the agent has no owner and is public, even with `visibility: 'private'`. Other users don't see a private agent in `list_agents` or `list_stored_agents`, and unless they're admins or granted that agent by id, calling it answers as if it doesn't exist, the same as over HTTP. Set `visibility: 'public'` to let every user call it. Only the owner, admins, and users granted that agent by id can edit it either way. An agent with no owner can be edited by any user with `stored-agents:write`. See [stored agent visibility](/docs/studio/editor#visibility). When the agent builder restricts models, the MCP tools accept only allowed models for the agent's model (the `provider` and `name` it runs, in each conditional variant), for any model named in `defaultOptions` (such as `structuredOutput.model`), for each enabled entry of the fallback `modelList`, for the memory models (the Observational Memory observer and reflector models and the title model), and for the `model` of every input and output processor step, at any depth of the processor graph. They also reject anything that would run on a default model the policy can't check: `observationalMemory: true`, an Observational Memory config without a `model`, memory left out on create (which the agent builder fills with Observational Memory on its default model), or a processor that needs a model, such as `moderation`, without one. Set an allowed `model` instead. A stored `model` takes only `provider`, `name`, and model settings such as `temperature`. Other keys, such as `modelId` or `providerId`, are rejected. If the agent builder's policy can't be loaded, the tools return an error instead of saving unchecked. `list_available_models` returns the allowed models. The HTTP route doesn't apply this check, so a user who can call `POST /stored/agents` directly can still save any model. Embedding models (`memory.embedder`) aren't on the builder's model list and aren't checked. Tool allowlists aren't checked when an agent is saved, so a created agent can use any tool the server has. Its tools run with the permissions of the user who calls it.

观察内存仅在线程达到其令牌阈值（默认情况下为 30,000 个令牌）后才开始观察。对于简短的演示，设置较低的`observation.messageTokens` so the agent learns from a few messages. Observational Memory processes messages in the background, so right after `call_agent`, call `get_observations` with `waitForPending: true` to wait (up to 30 seconds) for it to finish before reading.

## OAuth 发现 {/* #oauth-discovery */}

什么时候`server.auth` is configured, the endpoint tells MCP clients how to get a token, following the [MCP authorization spec](https://modelcontextprotocol.io/specification/draft/basic/authorization). A request without a valid token gets a `401` whose `WWW-Authenticate` header points at the endpoint's protected-resource metadata ([RFC 9728](https://datatracker.ietf.org/doc/html/rfc9728)):

```http
HTTP/1.1 401 Unauthorized
WWW-Authenticate: Bearer resource_metadata="https://my-app.example.com/.well-known/oauth-protected-resource/api/mcp"
```

当请求携带验证失败的令牌（例如过期）时，标头还包括`error="invalid_token"`. Other routes return their `401` without this header.

元数据是公开的并提供于`/.well-known/oauth-protected-resource/api/mcp` and `/.well-known/oauth-protected-resource`, outside the API prefix:

```json
{
  "resource": "https://my-app.example.com/api/mcp",
  "authorization_servers": ["https://my-tenant.us.auth0.com/"],
  "bearer_methods_supported": ["header"]
}
```

一位客户读到`authorization_servers`, runs the OAuth flow against your identity provider, and retries with the access token. Mastra doesn't act as an authorization server. Whether a client can sign in without a pre-registered OAuth app depends on your identity provider supporting dynamic client registration or client ID metadata documents.

Mastra 填充元数据`server.mcp.oauth` and from your auth provider:

* `resource`默认为从请求派生的端点 URL。在Agent或负载均衡器后面，请求可能携带内部主机，因此设置`server.mcp.oauth.resource` to the public URL. It must be an absolute `https` URL (`http` is allowed for `localhost`) without a fragment. An invalid value logs an error and turns OAuth discovery off, but the token audience is still checked against it, so MCP requests are rejected until you fix the value.
* 挑战中的元数据 URL 使用的来源`resource` with the endpoint's path on the server, for example `/.well-known/oauth-protected-resource/api/mcp`. If your proxy serves the endpoint under a different public path, it must also forward that well-known URL to Mastra.
* `authorization_servers`当Provider知道其发行者时来自该Provider（见下表）。否则设置`server.mcp.oauth.authorizationServers`. Without either, the field is left out and clients need a token configured by hand.
* `scopes_supported`仅当您设置时才包含在内`server.mcp.oauth.scopesSupported`.

```typescript title="src/mastra/index.ts"
import { Mastra } from '@mastra/core'
import { MastraAuthWorkos } from '@mastra/auth-workos'

export const mastra = new Mastra({
  server: {
    auth: new MastraAuthWorkos(),
    mcp: {
      oauth: {
        resource: 'https://my-app.example.com/api/mcp',
        authorizationServers: ['https://my-app.authkit.app'],
      },
    },
  },
})
```

### 代币受众 {/* #token-audience */}

环境`server.mcp.oauth.resource` also makes the endpoint check that a token was issued for it: the token's `aud` claim must include the `resource` value. A token for another API gets a `401` with `error="invalid_token"`, so a token leaked from a different service can't be replayed against your MCP endpoint. Without `resource`, any token your auth provider accepts works, as it did before. The check only applies to `/api/mcp`: other routes still accept a token issued for a different API. The comparison is exact, so `https://my-app.example.com/api/mcp/` with a trailing slash doesn't match `https://my-app.example.com/api/mcp`.

配置您的身份Provider以向该受众颁发令牌，例如通过注册`resource` URL as an API identifier in Auth0. Auth0 also verifies its own `audience` option (`AUTH0_AUDIENCE`), so either set that option to the `resource` URL or issue tokens whose `aud` includes both values.

|Provider|授权服务器公布 |观众检查`resource` |
| - | - | - |
| [`MastraJwtAuth`](/reference/auth/jwt) | `issuer` option | Yes |
| [Auth0](/reference/auth/auth0) | `https://<domain>/` | Yes |
| [Okta](/reference/auth/okta) | `issuer` option | No. Okta checks the token against its own `audience` option, so set that to the `resource` URL. |
| [Clerk](/reference/auth/clerk) | Frontend API URL from the publishable key. Your OAuth application must issue JWT access tokens (the default for applications created since January 2026). Opaque tokens are rejected. | No |
| [Supabase](/reference/auth/supabase) | `<url>/auth/v1`. Clients can only sign in there if the OAuth 2.1 server is turned on for your Supabase project. | No |
| [`CompositeAuth`](/docs/auth/composite-auth) | All inner providers' servers | Delegated to the provider that authenticated the token |
| WorkOS, Google, Neon, Firebase, Better Auth, custom providers | Set `authorizationServers` | No |

什么时候`resource` is set and a provider can't check the audience, Mastra logs a warning at startup and accepts that provider's tokens for any audience. This keeps API keys and other opaque tokens working. To reject them on `/api/mcp` instead, set `requireAudience: true`:

```typescript title="src/mastra/index.ts"
import { Mastra } from '@mastra/core'
import { CompositeAuth, SimpleAuth } from '@mastra/core/server'
import { MastraJwtAuth } from '@mastra/auth'

const jwtAuth = new MastraJwtAuth({
  jwksUri: 'https://auth.example.com/.well-known/jwks.json',
  issuer: 'https://auth.example.com/',
})
const apiKeyAuth = new SimpleAuth({ tokens: { [process.env.API_KEY!]: { id: 'ci' } } })

export const mastra = new Mastra({
  server: {
    auth: new CompositeAuth([jwtAuth, apiKeyAuth]),
    mcp: {
      oauth: { resource: 'https://my-app.example.com/api/mcp', requireAudience: true },
    },
  },
})
```

和`requireAudience`, a request authenticated by a provider without an audience check, such as `SimpleAuth`, gets a `401` with `error="invalid_token"` on `/api/mcp`. Inside `CompositeAuth`, only requests accepted by those providers are rejected. Other routes still accept them. `requireAudience` needs `resource`, and without `resource` nothing is checked.

定制Provider通过实施来选择加入`verifyAudience()` and `getOAuthMetadata()`, see [custom auth providers](/docs/auth/custom-auth-provider).

### 连接 OAuth 客户端 {/* #connect-an-oauth-client */}

使用支持动态客户端注册的身份提供程序，添加不带令牌的服务器，客户端在首次使用时运行登录流程：

```bash
claude mcp add --transport http mastra https://my-app.example.com/api/mcp
```

否则，获取访问令牌`resource` audience from your identity provider and pass it as a header:

```bash
claude mcp add --transport http mastra https://my-app.example.com/api/mcp \
  --header "Authorization: Bearer $MASTRA_TOKEN"
```

端点不返回`403` with `error="insufficient_scope"` yet. A caller without `mcp:read` gets a plain `403`, because Mastra permissions aren't OAuth scopes a client could request.

## 局限性 {/* #limitations */}

* Workflow在 MCP 请求内同步运行。长时间运行的Workflow程受服务器请求超时的限制。
* 没有针对每个基元的选择退出`Agent`, `Workflow`, or tool constructors yet. Use `server.mcp.include` and `server.mcp.exclude`.
* 工作内存、删除线程或存储的Agent以及记分器和Workspace管理都不会公开。
