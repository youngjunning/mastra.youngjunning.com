# 中间件

Mastra 服务器可以在调用 API 路由处理函数之前或之后执行自定义中间件，例如进行身份验证、记录日志、注入请求上下文或添加 CORS 响应头。

中间件接收 [Hono](https://hono.dev) 的 `Context`（`c`）和 `next` 函数。返回 `Response` 会提前结束请求处理。调用 `next()` 则继续执行下一个中间件或路由处理函数。

:::note

中间件处理函数采用 Hono 的签名，可在基于 Hono 的服务中运行，包括 `mastra dev`、`mastra build`、[Hono 适配器](/reference/server/hono-adapter)，以及基于它的 `@mastra/next` 和 `@mastra/tanstack-start` 等适配器。其他框架（Elysia、Express、Fastify、Koa、NestJS）的适配器无法运行 Hono 处理函数，配置了中间件时会在启动时记录警告。请通过这些框架自己的 API 注册中间件。

通过 `requiresAuth: false` 声明为公开的路由始终跳过用户中间件。因此，中间件无法拦截框架必须保持可访问的端点，例如 Studio 登录路由。

:::

```typescript
import { Mastra } from '@mastra/core'

export const mastra = new Mastra({
  server: {
    middleware: [
      {
        handler: async (c, next) => {
          // Example: Add authentication check
          const authHeader = c.req.header('Authorization')
          if (!authHeader) {
            return new Response('Unauthorized', { status: 401 })
          }

          await next()
        },
        path: '/api/*',
      },
      // Add a global request logger
      async (c, next) => {
        console.log(`${c.req.method} ${c.req.url}`)
        await next()
      },
    ],
  },
})
```

要给单条路由添加中间件，请向 `registerApiRoute` 传入 `middleware` 选项：

```typescript
registerApiRoute('/my-custom-route', {
  method: 'GET',
  middleware: [
    async (c, next) => {
      console.log(`${c.req.method} ${c.req.url}`)
      await next()
    },
  ],
  handler: async c => {
    const mastra = c.get('mastra')
    return c.json({ message: 'Hello, world!' })
  },
})
```

## 常见示例 {/* #common-examples */}

### 拦截内置路由组 {/* #block-built-in-route-groups */}

Mastra 没有移除内置路由或为其设置允许列表的配置。在基于 Hono 的服务中，可以直接返回响应，跳过 `next()`，使指定路由组不可访问：

```typescript title="src/mastra/index.ts"
import { Mastra } from '@mastra/core'

const notFound = async () => new Response('Not Found', { status: 404 })

export const mastra = new Mastra({
  server: {
    middleware: [
      { path: '/api/memory/*', handler: notFound },
      { path: '/api/logs/*', handler: notFound },
      { path: '/api/observability/*', handler: notFound },
    ],
  },
})
```

每个通配符模式同时拦截路由组本身及其嵌套路由。例如，`/api/logs/*` 拦截 `/api/logs` 和 `/api/logs/transports`。其他路由组仍然可用。

生成的服务器会将 `server.apiPrefix` 传给 Hono 适配器的 [`prefix` 构造选项](/reference/server/hono-adapter#constructor-parameters)，为内置路由添加前缀。中间件路径按原样注册，必须显式包含配置的前缀。例如，设置 `apiPrefix: '/api/v2'` 时，请使用 `/api/v2/memory/*`。自定义 API 路由必须放在配置的 API 前缀之外，因此不受这些模式拦截。

Mastra 会跳过声明了 `requiresAuth: false` 的公开路由，因此这种方法无法拦截它们。使用非 Hono 适配器时，请通过服务器框架注册等效的中间件。

运行 `mastra dev` 时，可在 [OpenAPI 规范](http://localhost:4111/api/openapi.json)中查看完整的内置路由列表，包括 MCP 路由。API 探索和生产环境设置见[服务器概览](/docs/server/overview#rest-api)。

如果使用中间件进行身份验证且未使用 `server.auth`，建议采用默认拒绝策略，先验证请求再放行，避免逐一列举受保护路径。覆盖完整的 API 前缀，以保护 REST 路由和 MCP 传输。

### 使用 `RequestContext` {/* #using-requestcontext */}

可在服务器运行时的中间件中提取请求信息，填充 `RequestContext`。本例根据 Cloudflare 的 `CF-IPCountry` 请求头设置 `temperature-unit`，使响应符合用户所在地区的习惯。

```typescript title="src/mastra/index.ts"
import { Mastra } from '@mastra/core'
import { RequestContext } from '@mastra/core/request-context'
import { testWeatherAgent } from './agents/test-weather-agent'

export const mastra = new Mastra({
  agents: { testWeatherAgent },
  server: {
    middleware: [
      async (context, next) => {
        const country = context.req.header('CF-IPCountry')
        const requestContext = context.get('requestContext')

        requestContext.set('temperature-unit', country === 'US' ? 'fahrenheit' : 'celsius')

        await next()
      },
    ],
  },
})
```

### 授权（用户隔离） {/* #authorization-user-isolation */}

身份验证确认用户是谁，授权决定用户可以访问什么。

如果服务器未强制限制资源范围，也没有其他授权策略，已通过身份验证的调用方可以跨资源列出会话线程，访问其中的消息和工作记忆。未限定范围的列表就可能暴露线程 ID，调用方无需猜测。要为每个用户或租户隔离记忆，请配置 `mapUserToResourceId`，或在中间件中设置可信的资源 ID。

共享应用可能有意允许跨资源访问。资源 ID 可以标识用户、租户、项目或其他分组。请根据哪些人可以访问资源来选择授权策略。

要按已验证的用户限定记忆和会话线程，最简单的方法是在身份验证配置中设置 `mapUserToResourceId` 回调：

```typescript
import { Mastra } from '@mastra/core'

export const mastra = new Mastra({
  server: {
    auth: {
      authenticateToken: async token => {
        return verifyToken(token) // { id: 'user-123', orgId: 'org-456', ... }
      },
      mapUserToResourceId: user => user.id,
    },
  },
})
```

身份验证成功后，系统以已验证的用户对象调用 `mapUserToResourceId`，并将返回值写入请求上下文的 `MASTRA_RESOURCE_ID_KEY`。这适用于所有服务器适配器（Hono、Express、Next.js 等）。

配置此回调后，它必须返回非空字符串。如果回调抛出异常，或返回 `null`、`undefined`、空字符串、仅含空白的字符串或非字符串值，身份验证中间件会在运行路由前拒绝请求并返回 500。这适用于所有执行身份验证的请求，包括与记忆无关的路由。客户端提供的资源 ID 无法覆盖失败的映射。

使用 `CompositeAuth` 时，该要求适用于实际验证请求的 Provider。没有映射函数的 Provider 会沿用原有行为，即使组合中的其他 Provider 配置了映射函数。已配置的 Studio 身份验证映射函数也遵循相同的校验规则。

没有映射函数时，仅凭身份验证无法隔离用户。您需要在中间件中设置可信的资源 ID，或通过其他方式强制实施授权。

资源 ID 可以采用 `user.id` 以外的值。以下是常见方式：

```typescript
// Per-user within an organization
mapUserToResourceId: user => `${user.orgId}:${user.id}`

// From a JWT claim
mapUserToResourceId: user => user.tenantId

// Composite key
mapUserToResourceId: user => `${user.workspaceId}:${user.projectId}:${user.id}`
```

设置资源 ID 后，服务器会自动执行以下操作：

- **筛选线程列表**，仅返回配置的资源范围内的线程。
- **校验线程访问权限**，访问其他资源的线程时返回 403。
- **限制线程创建**，新建线程必须使用配置的资源 ID。
- **校验消息操作**（包括删除），确保消息所属的线程在配置的资源范围内。

即使客户端传入 `?resourceId=other-resource-id`，也以服务器设置的值为准。尝试访问其他资源的线程或消息会返回 403。映射到同一资源 ID 的用户共享该资源范围。

#### 进阶：在中间件中设置资源 ID {/* #advanced-setting-resource-id-in-middleware */}

对于较复杂的场景（例如从数据库查询资源 ID），可直接在中间件中设置 `MASTRA_RESOURCE_ID_KEY`：

```typescript
import { Mastra } from '@mastra/core'
import { MASTRA_RESOURCE_ID_KEY } from '@mastra/core/request-context'
import { getAuthenticatedUser } from '@mastra/server/auth'

export const mastra = new Mastra({
  server: {
    auth: {
      authenticateToken: async token => verifyToken(token),
    },
    middleware: [
      {
        path: '/api/*',
        handler: async (c, next) => {
          const token = c.req.header('Authorization')
          if (!token) {
            return c.json({ error: 'Unauthorized' }, 401)
          }

          const user = await getAuthenticatedUser<{ id: string }>({
            mastra: c.get('mastra'),
            token,
            request: c.req.raw,
          })
          const requestContext = c.get('requestContext')

          if (!user) {
            return c.json({ error: 'Unauthorized' }, 401)
          }

          requestContext.set(MASTRA_RESOURCE_ID_KEY, user.id)
          return next()
        },
      },
    ],
  },
})
```

`server.middleware` 在 Mastra 检查各路由的身份验证之前执行。中间件需要已验证的用户时，可调用 `getAuthenticatedUser()` 从配置的身份验证 Provider 获取用户，同时保留路由默认的验证流程。

#### 使用 `MASTRA_THREAD_ID_KEY` {/* #using-mastra_thread_id_key */}

也可以设置 `MASTRA_THREAD_ID_KEY`，覆盖客户端传入的线程 ID：

```typescript
import { MASTRA_RESOURCE_ID_KEY, MASTRA_THREAD_ID_KEY } from '@mastra/core/request-context'

// Force operations to use a specific thread
requestContext.set(MASTRA_THREAD_ID_KEY, validatedThreadId)
```

这样可以把操作限制在已通过其他方式验证的特定线程内。

### CORS 支持 {/* #cors-support */}

```typescript oxfmt:false
{
  handler: async (c, next) => {
    c.header('Access-Control-Allow-Origin', '*');
    c.header(
      'Access-Control-Allow-Methods',
      'GET, POST, PUT, DELETE, OPTIONS',
    );
    c.header(
      'Access-Control-Allow-Headers',
      'Content-Type, Authorization',
    );

    if (c.req.method === 'OPTIONS') {
      return new Response(null, { status: 204 });
    }

    await next();
  },
}
```

### 请求日志 {/* #request-logging */}

{
  handler: async (c, next) => {
    const start = Date.now();
    await next();

  },
}
