# 中间件

Mastra 服务器可以在 API 之前或之后执行自定义中间件功能
调用路由处理程序。这对于诸如身份验证之类的事情很有用，
记录、注入特定于请求的上下文或添加 CORS 标头。

中间件接收[Hono](https://hono.dev) `Context` (`c`）和一个`next`功能。如果它返回一个`Response`请求被短路。呼唤`next()`继续处理下一个中间件或路由处理程序。

：：：笔记

中间件处理程序使用 Hono 的签名，因此它们在基于 Hono 的服务上运行
路径：`mastra dev` and `mastra build`, the
[Hono adapter](/reference/server/hono-adapter), and adapters built on it such as
`@mastra/next` and `@mastra/tanstack-start`. Adapters for other frameworks
(Elysia, Express, Fastify, Koa, NestJS) can't run Hono handlers and log a
warning at startup when middleware is configured. Register middleware through
the framework's own API there instead.

用户中间件永远不会在声明为公共的路由上运行`requiresAuth: false`, so it can't block endpoints the framework needs to keep
reachable, such as the Studio sign-in routes.

:::

```typescript
import { Mastra } from '@mastra/core'

export const mastra = new Mastra({
  server: {
    middleware: [
      {
        handler: async (c, next) => {
          // Example: Add authentication check
          const authHeader = c.req.header('Authorization')
          if (!authHeader) {
            return new Response('Unauthorized', { status: 401 })
          }

          await next()
        },
        path: '/api/*',
      },
      // Add a global request logger
      async (c, next) => {
        console.log(`${c.req.method} ${c.req.url}`)
        await next()
      },
    ],
  },
})
```

要将中间件附加到单个路由，请通过`middleware` option to
`registerApiRoute`:

```typescript
registerApiRoute('/my-custom-route', {
  method: 'GET',
  middleware: [
    async (c, next) => {
      console.log(`${c.req.method} ${c.req.url}`)
      await next()
    },
  ],
  handler: async c => {
    const mastra = c.get('mastra')
    return c.json({ message: 'Hello, world!' })
  },
})
```

## 常见示例 {/* #common-examples */}

### 阻止内置路由组 {/* #block-built-in-route-groups */}

Mastra 不提供用于删除或将内置路由列入白名单的配置选项。在基于 Hono 的服务路径上，您可以通过返回响应而不调用来使所选路由组不可用`next()`:

```typescript title="src/mastra/index.ts"
import { Mastra } from '@mastra/core'

const notFound = async () => new Response('Not Found', { status: 404 })

export const mastra = new Mastra({
  server: {
    middleware: [
      { path: '/api/memory/*', handler: notFound },
      { path: '/api/logs/*', handler: notFound },
      { path: '/api/observability/*', handler: notFound },
    ],
  },
})
```

每个通配符模式都会阻止路由组本身及其嵌套路由。例如，`/api/logs/*` blocks `/api/logs` and `/api/logs/transports`. Other route groups remain available.

生成的服务器通行证`server.apiPrefix` to the Hono adapter's [`prefix` constructor option](/reference/server/hono-adapter#constructor-parameters), which prefixes built-in routes. Middleware paths are registered unchanged, so they must explicitly include the configured prefix. For example, with `apiPrefix: '/api/v2'`, use `/api/v2/memory/*`. Custom API routes must live outside the configured API prefix and aren't blocked by these patterns.

此方法无法阻止公开的路由`requiresAuth: false`, because Mastra skips user middleware for those routes. With a non-Hono server adapter, register equivalent middleware through the server framework instead.

期间`mastra dev`, inspect the full built-in route list, including MCP routes, in the [OpenAPI specification](http://localhost:4111/api/openapi.json). See the [server overview](/docs/server/overview#rest-api) for API exploration and production settings.

如果您使用中间件进行身份验证而不使用`server.auth`, prefer default-deny middleware that authenticates requests before allowing access, rather than enumerating protected paths. Include the full API prefix so REST routes alongside MCP transports are covered.

### 使用`RequestContext` {/* #using-requestcontext */}

您可以填充`RequestContext` in a runtime server middleware by extracting information from the request. In this example, the `temperature-unit` is set based on the Cloudflare `CF-IPCountry` header to ensure responses match the user's locale.

```typescript title="src/mastra/index.ts"
import { Mastra } from '@mastra/core'
import { RequestContext } from '@mastra/core/request-context'
import { testWeatherAgent } from './agents/test-weather-agent'

export const mastra = new Mastra({
  agents: { testWeatherAgent },
  server: {
    middleware: [
      async (context, next) => {
        const country = context.req.header('CF-IPCountry')
        const requestContext = context.get('requestContext')

        requestContext.set('temperature-unit', country === 'US' ? 'fahrenheit' : 'celsius')

        await next()
      },
    ],
  },
})
```

### 授权（用户隔离） {/* #authorization-user-isolation */}

身份验证验证用户是谁，而授权控制他们可以访问的内容。

如果没有服务器强制的资源范围或其他授权策略，经过身份验证的调用者可以跨资源列出线程并访问其消息和工作内存。调用者不需要猜测线程 ID：无范围列表可以公开它们。对于每用户或每租户的私有内存，配置`mapUserToResourceId` or set a trusted resource ID in middleware.

在共享应用程序中，跨资源访问可能是有意的。资源 ID 可以标识用户、租户、项目或其他分组。选择与谁可以访问这些资源相匹配的授权策略。

将内存和线程范围限定给经过身份验证的用户的最简单方法是`mapUserToResourceId` callback in the auth config:

```typescript
import { Mastra } from '@mastra/core'

export const mastra = new Mastra({
  server: {
    auth: {
      authenticateToken: async token => {
        return verifyToken(token) // { id: 'user-123', orgId: 'org-456', ... }
      },
      mapUserToResourceId: user => user.id,
    },
  },
})
```

认证成功后，`mapUserToResourceId` is called with the authenticated user object. The returned value is set as `MASTRA_RESOURCE_ID_KEY` on the request context, which works across all server adapters (Hono, Express, Next.js, etc.).

配置后，回调必须返回非空字符串。如果它抛出或返回`null`, `undefined`, an empty or whitespace-only string, or a non-string value, authentication middleware rejects the request with a 500 error before the route runs. This applies to all requests that run authentication, including non-memory routes. A client-provided resource ID can't override a failed mapping.

和`CompositeAuth`, this requirement applies to the provider that authenticated the request. A provider without a mapper keeps its existing behavior, even if another provider in the composite has one. The same validation applies to configured Studio auth mappers.

如果没有映射器，身份验证将无法实现用户隔离：您负责在中间件中设置可信资源 ID 或以其他方式强制执行授权。

资源 ID 不必是`user.id`. Common patterns:

```typescript
// Per-user within an organization
mapUserToResourceId: user => `${user.orgId}:${user.id}`

// From a JWT claim
mapUserToResourceId: user => user.tenantId

// Composite key
mapUserToResourceId: user => `${user.workspaceId}:${user.projectId}:${user.id}`
```

设置资源 ID 后，服务器会自动：

* **过滤线程列表**仅返回配置的资源范围内的线程
* **验证线程访问**如果访问属于不同资源的线程，则返回 403
* **强制创建线程**使用配置的资源 ID
* **验证消息操作**包括删除，确保消息属于配置的资源范围内的线程

即使客户通过了`?resourceId=other-resource-id`, the server-set value takes precedence. Attempts to access threads or messages belonging to a different resource return a 403 error. Users mapped to the same resource ID share that resource scope.

#### 高级：在中间件中设置资源ID {/* #advanced-setting-resource-id-in-middleware */}

对于更复杂的场景（例如，从数据库查找资源ID），您可以设置`MASTRA_RESOURCE_ID_KEY` directly in middleware:

```typescript
import { Mastra } from '@mastra/core'
import { MASTRA_RESOURCE_ID_KEY } from '@mastra/core/request-context'
import { getAuthenticatedUser } from '@mastra/server/auth'

export const mastra = new Mastra({
  server: {
    auth: {
      authenticateToken: async token => verifyToken(token),
    },
    middleware: [
      {
        path: '/api/*',
        handler: async (c, next) => {
          const token = c.req.header('Authorization')
          if (!token) {
            return c.json({ error: 'Unauthorized' }, 401)
          }

          const user = await getAuthenticatedUser<{ id: string }>({
            mastra: c.get('mastra'),
            token,
            request: c.req.raw,
          })
          const requestContext = c.get('requestContext')

          if (!user) {
            return c.json({ error: 'Unauthorized' }, 401)
          }

          requestContext.set(MASTRA_RESOURCE_ID_KEY, user.id)
          return next()
        },
      },
    ],
  },
})
```

`server.middleware`在 Mastra 的每条路由身份验证检查之前运行。当中间件需要经过身份验证的用户时，调用`getAuthenticatedUser()` to resolve it from the configured auth provider without changing the default route auth flow.

#### 使用`MASTRA_THREAD_ID_KEY` {/* #using-mastra_thread_id_key */}

您还可以设置`MASTRA_THREAD_ID_KEY` to override the client-provided thread ID:

```typescript
import { MASTRA_RESOURCE_ID_KEY, MASTRA_THREAD_ID_KEY } from '@mastra/core/request-context'

// Force operations to use a specific thread
requestContext.set(MASTRA_THREAD_ID_KEY, validatedThreadId)
```

当您想要将操作限制到已通过其他方式验证的特定线程时，这非常有用。

### CORS 支持 {/* #cors-support */}

```typescript oxfmt:false
{
  handler: async (c, next) => {
    c.header('Access-Control-Allow-Origin', '*');
    c.header(
      'Access-Control-Allow-Methods',
      'GET, POST, PUT, DELETE, OPTIONS',
    );
    c.header(
      'Access-Control-Allow-Headers',
      'Content-Type, Authorization',
    );

    if (c.req.method === 'OPTIONS') {
      return new Response(null, { status: 204 });
    }

    await next();
  },
}
```

### 请求记录 {/* #request-logging */}

```typescript oxfmt:false
{
  handler: async (c, next) => {
    const start = Date.now();
    await next();
    const duration = Date.now() - start;
    console.log(`${c.req.method} ${c.req.url} - ${duration}ms`);
  },
}
```
