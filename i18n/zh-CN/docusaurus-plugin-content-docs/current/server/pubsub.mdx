# 发布订阅

Mastra 使用发布/订阅 (pub/sub) 系统作为其内部事件总线。组件将事件发布到主题，其他组件订阅这些主题以做出反应。后端确定事件是在单个进程内、一台主机上的进程之间还是跨单独的实例传递。

设置后端一次`Mastra` instance for use throughout the system. The default is an in-process backend that requires no setup.

## Mastra 如何使用 PubSub {/* #how-mastra-uses-pubsub */}

多个内置系统通过相同的发布/订阅总线发布和订阅事件：

* **Workflow程执行**：调度程序发布一个`workflow.start` event, and a long-lived worker consumes it to run the workflow. Step and lifecycle events flow over pub/sub during execution.
* **预定的Workflow程**：调度程序通过发布到Workflow主题来调度到期运行。看[Scheduled workflows](/docs/workflows/scheduled-workflows).
* **后台任务**：任务管理器将工作分派给工作组，并将任务生命周期更新发送给订阅者，这就是后台任务流保持活动状态的方式。看[Background task streaming](/docs/harness/background-tasks#subscribe-to-all-task-events).
* **Agent信号**：向活动Agent运行发送信号会在线程主题上发布事件，因此在另一个进程中执行的运行会收到该信号。
* **可恢复的流**：每次运行都会发布流块，因此重新连接的客户端可以重播它错过的内容。

由于这些系统在一条总线上运行，因此您选择的后端会同时应用于所有系统。

## 交付方式 {/* #delivery-modes */}

后端以两种模式之一传递事件，由[`PubSub`](/reference/pubsub/base) contract:

* **拉**：消费者自行从后端读取数据，Mastra 通过长期工作循环来实现这一点。分布式后端，例如[`RedisStreamsPubSub`](/reference/pubsub/redis-streams) use this mode.
* **推**：事件在没有消费者询问的情况下到达，无论是在进程中还是通过 HTTP。默认[`EventEmitterPubSub`](/reference/pubsub/event-emitter) delivers this way in process.

订阅者还可以通过消费者组分发工作。同一组的成员拆分事件，以便每个事件处理一次。没有分组的订阅者会收到每个事件，从而将流扇出到所有未分组的订阅者。

## 默认后端 {/* #default-backend */}

当你没有设置`pubsub` option, Mastra uses [`EventEmitterPubSub`](/reference/pubsub/event-emitter). It delivers events in process using a Node.js [`EventEmitter`](https://nodejs.org/api/events.html#class-eventemitter), so it works without any external service.

```typescript title="src/mastra/index.ts"
import { Mastra } from '@mastra/core'

// No pubsub option: Mastra uses EventEmitterPubSub
export const mastra = new Mastra({})
```

由于它在进程中运行，因此事件不会持久存在，也不会到达其他进程。默认值适合单个实例，涵盖大多数应用程序。

## 选择后端 {/* #choosing-a-backend */}

设置`pubsub` option on the `Mastra` instance to choose a backend. Each backend implements the same [`PubSub`](/reference/pubsub/base) contract, so the rest of your application doesn't change.

决定性的问题是订户在哪里运行。

|后端 |范围 |模式|套餐 |
| - | - | - | - |
|[`EventEmitterPubSub`](/reference/pubsub/event-emitter) | Single process | Pull and push | `@mastra/core` |
| [`UnixSocketPubSub`](/reference/pubsub/unix-socket-pubsub) | Multiple processes, one host | Push | `@mastra/core` |
| [`RedisStreamsPubSub`](/reference/pubsub/redis-streams) | Distributed, multiple hosts | Pull | `@mastra/redis-streams` |
| [`GoogleCloudPubSub`](/reference/pubsub/google-cloud-pubsub) | Distributed, multiple hosts | Pull | `@mastra/google-cloud-pubsub` |

### 一台主机上的多个进程 {/* #multiple-processes-on-one-host */}

使用[`UnixSocketPubSub`](/reference/pubsub/unix-socket-pubsub) when several processes on the same machine need to share a stream. It delivers events over a Unix domain socket and elects one process as a broker. If the broker exits, the remaining processes elect a new one.

```typescript title="src/mastra/index.ts"
import { Mastra } from '@mastra/core'
import { UnixSocketPubSub } from '@mastra/core/events'

export const mastra = new Mastra({
  pubsub: new UnixSocketPubSub('/tmp/mastra/events.sock'),
})
```

### 分布式部署 {/* #distributed-deployments */}

当您运行多个实例或主机并且每个实例接收相同的事件时，请使用分布式后端。每当一个实例处理的请求必须到达另一个实例上运行的工作时，这一点就很重要。

例如，向Agent运行发送信号需要信号事件跨越进程边界到达拥有该运行的实例。使用进程内默认值时，该实例永远不会接收该事件。

[持久剂](/docs/harness/durable-agents#run-ownership)`RedisStreamsPubSub` provides leases across hosts. `GoogleCloudPubSub` doesn't.

下面的两个后端都跨进程和主机进行交付，并保留事件以进行重新交付。

下面的例子使用[Redis Streams](https://redis.io/docs/latest/develop/data-types/streams/):

```typescript title="src/mastra/index.ts"
import { Mastra } from '@mastra/core'
import { RedisStreamsPubSub } from '@mastra/redis-streams'

export const mastra = new Mastra({
  pubsub: new RedisStreamsPubSub({
    url: 'redis://localhost:6379',
  }),
})
```

下面的例子使用[Google Cloud Pub/Sub](https://cloud.google.com/pubsub/docs):

```typescript title="src/mastra/index.ts"
import { Mastra } from '@mastra/core'
import { GoogleCloudPubSub } from '@mastra/google-cloud-pubsub'

export const mastra = new Mastra({
  pubsub: new GoogleCloudPubSub({
    projectId: 'my-project',
  }),
})
```

## 可恢复的流 {/* #resumable-streams */}

可恢复的流允许客户端重新连接并重播它错过的事件，这需要后端保留最近的历史记录。分布式后端，例如[`RedisStreamsPubSub`](/reference/pubsub/redis-streams) persist events, so they support replay on their own.

进程内交付不保留历史记录。添加重播[`EventEmitterPubSub`](/reference/pubsub/event-emitter), wrap it in [`CachingPubSub`](/reference/pubsub/caching-pubsub), which records published events per topic so a late or reconnecting subscriber can catch up before continuing with live events.

```typescript title="src/mastra/index.ts"
import { Mastra } from '@mastra/core'
import { CachingPubSub, EventEmitterPubSub } from '@mastra/core/events'
import { InMemoryServerCache } from '@mastra/core/cache'

const cache = new InMemoryServerCache()

export const mastra = new Mastra({
  pubsub: new CachingPubSub(new EventEmitterPubSub(), cache),
})
```

参观[PubSub reference](/reference/pubsub/base) for the full delivery contract and the configuration options for each backend.
