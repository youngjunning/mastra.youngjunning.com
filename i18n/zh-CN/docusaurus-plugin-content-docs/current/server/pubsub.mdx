# PubSub

Mastra 使用发布/订阅（pub/sub）系统作为内部事件总线。组件向主题发布事件，其他组件订阅主题并响应事件。后端决定事件是在单个进程内、同一主机的多个进程之间，还是跨实例传递。

在 `Mastra` 实例上设置一次后端，整个系统即可共用。默认使用进程内后端，无需配置。

## Mastra 如何使用 PubSub {/* #how-mastra-uses-pubsub */}

多个内置系统通过同一条总线发布和订阅事件：

- **执行 Workflow**：调度器发布 `workflow.start` 事件，由长期运行的 Worker 消费事件并执行 Workflow。执行期间，步骤和生命周期事件也通过 PubSub 传递。
- **定时 Workflow**：调度器向 Workflow 主题发布事件，派发到期的运行任务。参见[定时 Workflow](/docs/workflows/scheduled-workflows)。
- **后台任务**：任务管理器将任务分派给一组 Worker，并向各订阅者广播任务生命周期更新，让后台任务流保持实时。参见[后台任务流](/docs/harness/background-tasks#subscribe-to-all-task-events)。
- **Agent 信号**：向正在运行的 Agent 发送信号时，系统会在线程主题上发布事件，因此即使本次运行位于另一个进程，也能收到信号。
- **可恢复流**：流数据块按运行发布，客户端重连后可重放错过的数据。

这些系统共用同一条总线，因此选择的后端对它们全部生效。

## 事件传递模式 {/* #delivery-modes */}

后端按 [`PubSub`](/reference/pubsub/base) 接口约定，以以下两种模式之一传递事件：

- **拉取**：消费者主动从后端读取事件。Mastra 通过持续运行的 Worker 循环拉取；[`RedisStreamsPubSub`](/reference/pubsub/redis-streams) 等分布式后端采用此模式。
- **推送**：消费者无需主动请求，事件会在进程内或通过 HTTP 送达。默认的 [`EventEmitterPubSub`](/reference/pubsub/event-emitter) 采用进程内推送。

订阅者还可以通过消费者组分担工作。同组成员分摊事件，每个事件在组内只处理一次。未分组的订阅者各自收到所有事件。

## 默认后端 {/* #default-backend */}

未设置 `pubsub` 选项时，Mastra 使用 [`EventEmitterPubSub`](/reference/pubsub/event-emitter)。它通过 Node.js 的 [`EventEmitter`](https://nodejs.org/api/events.html#class-eventemitter) 在进程内传递事件，无需外部服务。

```typescript title="src/mastra/index.ts"
import { Mastra } from '@mastra/core'

// No pubsub option: Mastra uses EventEmitterPubSub
export const mastra = new Mastra({})
```

事件只在进程内传递，不会持久化，也不会送达其他进程。默认后端适用于单实例部署，能满足大多数应用的需要。

## 选择后端 {/* #choosing-a-backend */}

通过 `Mastra` 实例的 `pubsub` 选项选择后端。所有后端都实现同一套 [`PubSub`](/reference/pubsub/base) 接口约定，应用的其余部分无需修改。

选择的关键是订阅者在哪里运行。

| 后端 | 范围 | 模式 | 包 |
| - | - | - | - |
| [`EventEmitterPubSub`](/reference/pubsub/event-emitter) | 单进程 | 拉取和推送 | `@mastra/core` |
| [`UnixSocketPubSub`](/reference/pubsub/unix-socket-pubsub) | 单主机，多进程 | 推送 | `@mastra/core` |
| [`RedisStreamsPubSub`](/reference/pubsub/redis-streams) | 分布式，多主机 | 拉取 | `@mastra/redis-streams` |
| [`GoogleCloudPubSub`](/reference/pubsub/google-cloud-pubsub) | 分布式，多主机 | 拉取 | `@mastra/google-cloud-pubsub` |

### 一台主机上的多个进程 {/* #multiple-processes-on-one-host */}

如果同一台机器上的多个进程需要共享事件流，请使用 [`UnixSocketPubSub`](/reference/pubsub/unix-socket-pubsub)。它通过 Unix 域套接字传递事件，并选举一个进程作为代理。代理退出时，其余进程会选举新的代理。

```typescript title="src/mastra/index.ts"
import { Mastra } from '@mastra/core'
import { UnixSocketPubSub } from '@mastra/core/events'

export const mastra = new Mastra({
  pubsub: new UnixSocketPubSub('/tmp/mastra/events.sock'),
})
```

### 分布式部署 {/* #distributed-deployments */}

如果部署在多个实例或主机上，且每个实例都要接收相同事件，请用分布式后端。例如，某个实例处理的请求需要通知另一个实例上正在执行的任务。

例如，向正在运行的 Agent 发送信号时，事件必须跨进程送达负责本次运行的实例。默认的进程内后端无法把事件送到该实例。

如果存储适配器不支持运行隔离（run fencing），[持久化 Agent](/docs/harness/durable-agents#run-ownership) 的崩溃恢复也取决于后端。恢复时，系统会利用后端租约判断是否仍有其他实例在推进本次运行。`RedisStreamsPubSub` 支持跨主机租约，`GoogleCloudPubSub` 不支持。

下面两种后端都能跨进程、跨主机传递事件，并持久化事件以便重新投递。

以下示例使用 [Redis Streams](https://redis.io/docs/latest/develop/data-types/streams/)：

```typescript title="src/mastra/index.ts"
import { Mastra } from '@mastra/core'
import { RedisStreamsPubSub } from '@mastra/redis-streams'

export const mastra = new Mastra({
  pubsub: new RedisStreamsPubSub({
    url: 'redis://localhost:6379',
  }),
})
```

以下示例使用 [Google Cloud Pub/Sub](https://cloud.google.com/pubsub/docs)：

```typescript title="src/mastra/index.ts"
import { Mastra } from '@mastra/core'
import { GoogleCloudPubSub } from '@mastra/google-cloud-pubsub'

export const mastra = new Mastra({
  pubsub: new GoogleCloudPubSub({
    projectId: 'my-project',
  }),
})
```

## 可恢复流 {/* #resumable-streams */}

可恢复流允许客户端重新连接后重放错过的事件，因此后端需要保留近期记录。[`RedisStreamsPubSub`](/reference/pubsub/redis-streams) 等分布式后端会持久化事件，自身就支持重放。

进程内传递不保留历史记录。要在 [`EventEmitterPubSub`](/reference/pubsub/event-emitter) 上加入重放，可用 [`CachingPubSub`](/reference/pubsub/caching-pubsub) 封装它。后者按主题记录已发布的事件，让稍后接入或重连的订阅者先补齐历史事件，再接收实时事件。

```typescript title="src/mastra/index.ts"
import { Mastra } from '@mastra/core'
import { CachingPubSub, EventEmitterPubSub } from '@mastra/core/events'
import { InMemoryServerCache } from '@mastra/core/cache'

const cache = new InMemoryServerCache()

export const mastra = new Mastra({
  pubsub: new CachingPubSub(new EventEmitterPubSub(), cache),
})
```

完整的事件传递约定和各后端的配置选项见 [PubSub 参考](/reference/pubsub/base)。
