# 人工介入

Agent 调用删除资源或执行耗时任务等涉及敏感操作的 Tool 时，有时也需要与 Workflow 相同的[人工介入（HITL）](/docs/workflows/human-in-the-loop)机制。你可以在 Tool 执行前挂起调用，等待人工批准或拒绝；Tool 也可以自行挂起，向用户请求更多信息。

## 何时使用人工介入 {/* #when-to-use-human-in-the-loop */}

- **破坏性或不可逆操作**：例如删除记录、发送邮件或处理付款。
- **高成本操作**：例如调用昂贵的第三方 API，需要先核对参数。
- **有条件的确认**：Tool 已开始执行，却发现完成前还需要用户确认或补充数据。

## 快速开始 {/* #quickstart */}

为 Tool 设置 `requireApproval: true`，再从流中检查 `tool-call-approval` 数据块，以批准或拒绝操作：

```typescript title="src/mastra/agents/index.ts"
import { Agent } from '@mastra/core/agent'
import { createTool } from '@mastra/core/tools'
import { z } from 'zod'

const deleteTool = createTool({
  id: 'delete-record',
  description: 'Delete a record by ID',
  inputSchema: z.object({ id: z.string() }),
  outputSchema: z.object({ deleted: z.boolean() }),
  requireApproval: true,
  execute: async ({ id }) => {
    await db.delete(id)
    return { deleted: true }
  },
})

const agent = new Agent({
  id: 'my-agent',
  name: 'My Agent',
  model: '__GATEWAY_OPENAI_MODEL_LUNA__',
  tools: { deleteTool },
})

const stream = await agent.stream('Delete record abc-123')

for await (const chunk of stream.fullStream) {
  if (chunk.type === 'tool-call-approval') {
    const approved = await agent.approveToolCall({ runId: stream.runId })
    for await (const c of approved.textStream) process.stdout.write(c)
  }
}
```

:::note

人工介入使用快照保存请求状态。请为 Mastra 实例配置[存储提供方](/docs/storage)，否则会出现“snapshot not found”错误。

Agent 运行的快照是最小化的恢复数据：仅保存恢复挂起运行所需的信息，并在运行结束后删除。执行记录请使用[追踪](/docs/observability/overview)，对话历史请使用[记忆](/docs/memory/overview)。

:::

## 审批机制 {/* #how-approval-works */}

Mastra 提供两种不同的 Tool 调用暂停机制：**执行前审批**和**运行时挂起**。

### 执行前审批 {/* #pre-execution-approval */}

执行前审批会在 Tool 的 `execute` 函数运行*之前*暂停调用。LLM 仍会选择 Tool 并提供参数，但只有你明确批准后才会执行 `execute`。

这些选项采用 OR 逻辑：只要*任意一项*为 `true`，调用就会暂停：

| 选项 | 设置位置 | 作用范围 |
| - | - | - |
| `requireToolApproval: true` | `stream()` / `generate()` 选项 | 暂停该请求中的**每一次** Tool 调用 |
| `requireApproval: true` | `createTool()` 定义 | 只暂停**该 Tool** 的调用 |

流会发出包含 `toolCallId`、`toolName` 和 `args` 的 `tool-call-approval` 数据块。使用流的 `runId` 调用 `approveToolCall()` 或 `declineToolCall()`，即可继续：

```typescript
const stream = await agent.stream("What's the weather in London?", {
  requireToolApproval: true,
})

for await (const chunk of stream.fullStream) {
  if (chunk.type === 'tool-call-approval') {
    console.log('Tool:', chunk.payload.toolName)
    console.log('Args:', chunk.payload.args)

    // Approve
    const approved = await agent.approveToolCall({ runId: stream.runId })
    for await (const c of approved.textStream) process.stdout.write(c)

    // Or decline
    const declined = await agent.declineToolCall({ runId: stream.runId })
    for await (const c of declined.textStream) process.stdout.write(c)
  }
}
```

#### 说明拒绝原因 {/* #explaining-a-decline */}

`declineToolCall()`、`declineToolCallGenerate()` 和 `declineNetworkToolCall()` 可接收可选的 `reason`。该原因会代替 Tool 结果返回给模型，使模型能够调整行为，而不是盲目重试。它也会写入 Tool 调用的 `approval` 元数据，供后续回看对话时使用。

```typescript
const declined = await agent.declineToolCall({
  runId: stream.runId,
  toolCallId,
  reason: 'Reading other users PII is not allowed, ask the user for their own email instead',
})
```

不提供 `reason` 时，模型会收到默认消息 `Tool call was not approved by the user`。

#### 使用函数进行条件审批 {/* #conditional-approval-with-a-function */}

除了布尔值，`requireToolApproval` 还可以接收一个函数，逐次决定是否审批。函数接收 `toolName`、模型传入的 `args`、`requestContext` 和 `workspace`。返回 `true` 表示需要审批，返回 `false` 表示允许执行。这样就能在运行时设置审批条件，例如只审批名称符合特定模式的 Tool：

```typescript
const stream = await agent.stream('Clean up old records', {
  requireToolApproval: ({ toolName }) => /^delete_/.test(toolName),
})
```

该函数可以是异步的。如果判断取决于 Tool 名称和参数，可以使用 [classifier](/docs/classifier) 估计调用是否需要人工审核：

```typescript title="src/mastra/agents/run-with-approval.ts"
import { Classifier } from '@mastra/core/classifier'
import { typeSafeAi } from '@ai-sdk/typesafe-ai'
import { agent } from './agent'

const approvalClassifier = new Classifier({
  id: 'tool-approval-classifier',
  model: typeSafeAi.decisionModel('__AI_SDK_TYPESAFE_DECISION_MODEL__'),
  questions: {
    requiresApproval: {
      type: 'boolean',
      instructions:
        'Does this tool call need human approval because it is destructive, irreversible, expensive, or handles sensitive data?',
    },
  },
})

const stream = await agent.stream('Clean up old records', {
  requireToolApproval: async ({ toolName, args }) => {
    const result = await approvalClassifier.decide({
      state: {
        toolName,
        argumentNames: Object.keys(args),
      },
    })

    // A refused question has no probability, so it falls back to requiring approval.
    return (result.answers.requiresApproval.probability ?? 1) >= 0.7
  },
})
```

示例只发送参数名，不发送参数值，因为 classifier 会把自身状态转发给配置的决策模型。如果决策必须使用参数值，请先遮蔽敏感数据，或选择符合受保护 Tool 数据处理要求的决策模型和提供方。

返回 `true` 会将 Tool 调用挂起，等待人工审批，并不会自动批准或拒绝。阈值应与 Agent 可用 Tool 的风险相匹配。如果 `requireToolApproval` 函数抛出异常，默认会要求审批。

运行时会将这一结果与 Tool 的 `requireApproval` 设置合并。布尔值 `true` 表示需要审批；`false` 不会取消 `requireToolApproval` 要求的审批。Tool 级别的 `requireApproval` 函数具有最终决定权，会覆盖该 Tool 的合并结果。

:::note

函数形式的 `requireToolApproval` 仅适用于普通的 `stream()` / `generate()` 调用。持久化 Agent 和已存储的 Agent 会保存选项，而函数无法序列化，因此只接受布尔值。在这些场景传入函数时，会回退为每次 Tool 调用都要求审批。

:::

#### 将审批绑定到确切的 Tool 参数 {/* #bind-approval-to-the-exact-tool-arguments */}

对于敏感 Tool，应将审批绑定到审核者看到的确切 Tool 名称和参数。如果执行前参数发生变化，就不应沿用原审批执行。

`tool-call-approval` 数据块已包含 `toolName`、`toolCallId` 和 `args`。可以在展示审批请求时为这些字段生成指纹。下例用 JSON 字符串作指纹；生产环境应改用 Tool 名称和参数的稳定哈希。

```typescript title="src/mastra/agents/approval-bound-agent.ts"
import { Agent } from '@mastra/core/agent'

// For your production usecase, build a stable hash of the tool name and args
function actionFingerprint(toolName: string, args: unknown) {
  const payload = JSON.stringify({ toolName, args })
  return `fingerprint-${payload}`
}

const sensitiveTools = new Set(['issue_refund', 'delete_record'])
const approvedFingerprints = new Set<string>()

export const approvalBoundAgent = new Agent({
  id: 'approval-bound-agent',
  name: 'Approval Bound Agent',
  model: '__GATEWAY_OPENAI_MODEL__',
  tools: { issueRefundTool, deleteRecordTool },
  hooks: {
    beforeToolCall: ({ toolName, input }) => {
      if (!sensitiveTools.has(toolName)) return

      const fingerprint = actionFingerprint(toolName, input)
      if (!approvedFingerprints.delete(fingerprint)) {
        return {
          proceed: false,
          output: `Tool call blocked: approval did not match ${toolName} arguments.`,
        }
      }
    },
  },
})
```

```typescript
const stream = await approvalBoundAgent.stream('Refund order ord-1042', {
  requireToolApproval: ({ toolName }) => sensitiveTools.has(toolName),
})

async function consumeApprovalStream(currentStream: typeof stream) {
  for await (const chunk of currentStream.fullStream) {
    if (chunk.type === 'tool-call-approval') {
      const { toolName, toolCallId, args } = chunk.payload
      const fingerprint = actionFingerprint(toolName, args)

      // Present toolName, args, and fingerprint to your approval UI.
      const approved = await showApprovalDialog({ toolName, args, fingerprint })

      const nextStream = approved
        ? await approveReviewedToolCall(currentStream.runId, toolCallId, fingerprint)
        : await approvalBoundAgent.declineToolCall({ runId: currentStream.runId, toolCallId })

      await consumeApprovalStream(nextStream)
    }
  }
}

async function approveReviewedToolCall(runId: string, toolCallId: string, fingerprint: string) {
  approvedFingerprints.add(fingerprint)
  return approvalBoundAgent.approveToolCall({ runId, toolCallId })
}

await consumeApprovalStream(stream)
```

在生产环境中，应将获批指纹存入持久存储，并按用户、运行、Tool 调用和策略版本限定范围。上面的 `Set` 刻意保持简化，以说明关键边界：审批只能消费一次，且只适用于审核时的同一组规范化 Tool 参数。

### 使用 `suspend()` 在运行时挂起 {/* #runtime-suspension-with-suspend */}

Tool 也可以在 `execute` 函数执行*过程中*调用 `suspend()` 暂停。当 Tool 开始运行后才发现需要用户补充信息或确认才能完成时，这种方式很有用。

流会发出 `tool-call-suspended` 数据块，其中包含由 Tool 的 `suspendSchema` 定义的自定义载荷。调用 `resumeStream()` 并传入符合 `resumeSchema` 的数据即可恢复运行。

```typescript
const weatherTool = createTool({
  id: 'get-weather',
  inputSchema: z.object({
    location: z.string().optional(),
  }),
  suspendSchema: z.object({
    question: z.string(),
  }),
  resumeSchema: z.object({
    location: z.string(),
  }),
  execute: async ({ location }, context) => {
    if (!location) {
      return await context?.agent?.suspend({
        question: 'Which city would you like the weather for?',
      })
    }
    return await fetchWeather(location)
  },
})
```

:::note

`suspend()` 不会抛出异常。调用后请立即返回，例如 `return await suspend({ ... })`；`await suspend(...)` 后面的代码仍会在 Tool 真正暂停前执行。

:::

如果 Tool 既需要用户提供结构化答案，又在子 Agent 中运行，请使用 `suspend()`，而不是不带 `execute` 的 Tool：子 Agent 无法运行客户端 Tool，但挂起请求可以通过 supervisor 向上传递。要通过 AI SDK 的 `useChat()` 恢复，请参阅[从 `useChat()` 恢复挂起的 Tool](/integrations/agentic-ui/ai-sdk-ui#resuming-a-suspended-tool-from-usechat)。

## 配合 `generate()` 审批 Tool {/* #tool-approval-with-generate */}

非流式场景也可在 `generate()` 中审批 Tool。需要审批时，`generate()` 会立即返回 `finishReason: 'suspended'`、包含 Tool 调用详情（`toolCallId`、`toolName`、`args`）的 `suspendPayload`，以及 `runId`。

```typescript
const output = await agent.generate('Find user John', {
  requireToolApproval: true,
})

if (output.finishReason === 'suspended') {
  console.log('Tool requires approval:', output.suspendPayload.toolName)

  // Approve
  const result = await agent.approveToolCallGenerate({
    runId: output.runId,
    toolCallId: output.suspendPayload.toolCallId,
  })
  console.log('Final result:', result.text)

  // Or decline
  const result = await agent.declineToolCallGenerate({
    runId: output.runId,
    toolCallId: output.suspendPayload.toolCallId,
  })
}
```

### stream() 与 generate() 对比 {/* #stream-vs-generate-comparison */}

| 方面 | `stream()` | `generate()` |
| - | - | - |
| 响应类型 | 流式数据块 | 完整响应 |
| 审批检测 | `tool-call-approval` 数据块 | `finishReason: 'suspended'` |
| 批准方法 | `approveToolCall({ runId })` | `approveToolCallGenerate({ runId, toolCallId })` |
| 拒绝方法 | `declineToolCall({ runId })` | `declineToolCallGenerate({ runId, toolCallId })` |
| 结果 | 可迭代的流 | 完整输出对象 |

:::note

`toolCallId` 对这四个方法均为可选参数。当可能同时存在多个待处理的 Tool 调用时（supervisor Agent 中很常见），请传入该参数。省略时，Agent 会恢复最近挂起的 Tool 调用。
:::

## Tool 级审批 {/* #tool-level-approval */}

除了在 Agent 级别暂停所有 Tool 调用，也可以只将特定 Tool 标记为需要审批。这样只有指定 Tool 会暂停，其他 Tool 可立即执行。

### 使用 `requireApproval` 审批 {/* #approval-using-requireapproval */}

在 Tool 定义中设置 `requireApproval: true`。无论 Agent 是否设置 `requireToolApproval`，该 Tool 都会在执行前暂停：

```typescript title="src/mastra/tools/test-tool.ts"
import { createTool } from '@mastra/core/tools'
import { z } from 'zod'

export const testTool = createTool({
  id: 'test-tool',
  description: 'Fetches weather for a location',
  inputSchema: z.object({
    location: z.string(),
  }),
  outputSchema: z.object({
    weather: z.string(),
  }),
  resumeSchema: z.object({
    approved: z.boolean(),
  }),
  execute: async inputData => {
    const response = await fetch(`https://wttr.in/${inputData.location}?format=3`)
    const weather = await response.text()

    return { weather }
  },
  requireApproval: true,
})
```

`requireApproval` 为 `true` 时，流会像 Agent 级审批一样发出 `tool-call-approval` 数据块。调用 `approveToolCall()` 或 `declineToolCall()` 即可继续：

```typescript
const stream = await agent.stream("What's the weather in London?")

for await (const chunk of stream.fullStream) {
  if (chunk.type === 'tool-call-approval') {
    console.log('Approval required for:', chunk.payload.toolName)
  }
}

const handleApproval = async () => {
  const approvedStream = await agent.approveToolCall({ runId: stream.runId })

  for await (const chunk of approvedStream.textStream) {
    process.stdout.write(chunk)
  }
  process.stdout.write('\n')
}
```

### 使用 `suspend()` 审批 {/* #approval-using-suspend */}

这种方式下，Agent 和 Tool 都不设置 `requireApproval`。Tool 的 `execute` 函数会在指定位置调用 `suspend()` 暂停，并向用户返回上下文或确认提示。适用于是否需要审批取决于运行时条件的场景。

```typescript title="src/mastra/tools/test-tool-b.ts"
import { createTool } from '@mastra/core/tools'
import { z } from 'zod'

export const testToolB = createTool({
  id: 'test-tool-b',
  description: 'Fetches weather for a location',
  inputSchema: z.object({
    location: z.string(),
  }),
  outputSchema: z.object({
    weather: z.string(),
  }),
  resumeSchema: z.object({
    approved: z.boolean(),
  }),
  suspendSchema: z.object({
    reason: z.string(),
  }),
  execute: async (inputData, context) => {
    const { resumeData: { approved } = {}, suspend } = context?.agent ?? {}

    if (!approved) {
      return suspend?.({ reason: 'Approval required.' })
    }

    const response = await fetch(`https://wttr.in/${inputData.location}?format=3`)
    const weather = await response.text()

    return { weather }
  },
})
```

此时流中会出现 `tool-call-suspended` 数据块，`suspendPayload` 包含 Tool 的 `suspendSchema` 定义的 `reason`。调用 `resumeStream`，传入符合 `resumeSchema` 的数据和 `runId`，即可继续：

```typescript
const stream = await agent.stream("What's the weather in London?")

for await (const chunk of stream.fullStream) {
  if (chunk.type === 'tool-call-suspended') {
    console.log(chunk.payload.suspendPayload)
  }
}

const handleResume = async () => {
  const resumedStream = await agent.resumeStream({ approved: true }, { runId: stream.runId })

  for await (const chunk of resumedStream.textStream) {
    process.stdout.write(chunk)
  }
  process.stdout.write('\n')
}
```

使用 `generate()` 时，结果的 `finishReason: 'suspended'`。来自 `suspend()` 的 Tool 数据位于 `suspendPayload.suspendPayload`。调用 `resumeGenerate()`，传入 `resumeSchema` 数据和 `runId`，即可继续：

```typescript
const output = await agent.generate("What's the weather in London?")

if (output.finishReason === 'suspended') {
  console.log(output.suspendPayload.suspendPayload) // { reason: 'Approval required.' }

  const resumed = await agent.resumeGenerate({ approved: true }, { runId: output.runId! })
  console.log(resumed.text)
}
```

挂起或待审批的 Tool 调用恢复后，流会先发出 `tool-call-resumed` 数据块，再发出相同 `toolCallId` 的 `tool-result`。其 `payload.kind` 为 `'suspension'` 或 `'approval'`，载荷还会重复原始 `args`、`suspendPayload` 和 `resumeSchema`。只有真正解除挂起或审批请求时，才会发出该数据块。

在 `@mastra/ai-sdk` 中，它会以 `data-tool-call-suspended` 部分（审批则为 `data-tool-call-approval`）到达，并带有 `resumed: true`，替换原部分且保留其载荷。可以据此标记问题已得到回答。不要根据 Tool 输出的形状推断：如果挂起来自子 Agent，委派调用的输出是子 Agent 的结果，而非用户的回答。

## 自动恢复 Tool {/* #automatic-tool-resumption */}

对于调用 `suspend()` 的 Tool，可以启用自动恢复，让 Agent 根据用户的下一条消息恢复挂起的 Tool。在 Agent 默认选项或单次请求中将 `autoResumeSuspendedTools` 设为 `true`：

```typescript title="src/mastra/agents/my-agent.ts"
import { Agent } from '@mastra/core/agent'
import { Memory } from '@mastra/memory'

const agent = new Agent({
  id: 'my-agent',
  name: 'My Agent',
  instructions: 'You are a helpful assistant',
  model: '__GATEWAY_OPENAI_MODEL_LUNA__',
  tools: { weatherTool },
  memory: new Memory(),
  defaultOptions: {
    autoResumeSuspendedTools: true,
  },
})
```

启用后，Agent 会在下一条用户消息到来时，从消息历史中检测挂起的 Tool，根据 Tool 的 `resumeSchema` 提取 `resumeData`，并自动恢复该 Tool。

自动恢复只适用于携带数据的 `suspend()` 流程，不会批准使用 `requireApproval` 的 Tool。后者仍会保持挂起，直到通过 `approveToolCall()`、`declineToolCall()`、`resumeStream({ approved: boolean })` 或等效 UI/API 操作明确批准或拒绝。

下面的示例展示完整的对话流程：

```typescript title="src/mastra/tools/weather-tool.ts"
import { createTool } from '@mastra/core/tools'
import { z } from 'zod'

const weatherTool = createTool({
  id: 'weather-tool',
  description: 'Fetches weather for a city',
  inputSchema: z.object({
    city: z.string(),
  }),
  outputSchema: z.object({
    weather: z.string(),
  }),
  suspendSchema: z.object({
    message: z.string(),
  }),
  resumeSchema: z.object({
    city: z.string(),
  }),
  execute: async (inputData, context) => {
    const { resumeData, suspend } = context?.agent ?? {}

    // If no city provided, ask the user
    if (!inputData.city && !resumeData?.city) {
      return suspend?.({ message: 'What city do you want to know the weather for?' })
    }

    const city = resumeData?.city ?? inputData.city
    const response = await fetch(`https://wttr.in/${city}?format=3`)
    const weather = await response.text()

    return { weather: `${city}: ${weather}` }
  },
})
```

```typescript
const stream = await agent.stream("What's the weather like?")

for await (const chunk of stream.fullStream) {
  if (chunk.type === 'tool-call-suspended') {
    console.log(chunk.payload.suspendPayload)
  }
}

// User sends follow-up on the same thread
const resumedStream = await agent.stream('San Francisco')
for await (const chunk of resumedStream.textStream) {
  process.stdout.write(chunk)
}
```

```text title="Console output"
User: "What's the weather like?"
Agent: "What city do you want to know the weather for?"

User: "San Francisco"
Agent: "The weather in San Francisco is: San Francisco: ☀️ +72°F"
```

第二条消息会自动恢复挂起的 Tool。Agent 从用户消息中提取 `{ city: "San Francisco" }`，作为 `resumeData` 传入。

### 使用条件 {/* #requirements */}

要让自动恢复生效，需要满足以下条件：

- **已配置 Memory**：Agent 需要借助 Memory 跨消息追踪挂起的 Tool。
- **同一线程**：后续消息必须使用相同的 Memory 线程和资源标识符。
- **已定义 `resumeSchema`**：Tool 必须定义 `resumeSchema`，Agent 才能知道要从用户消息中提取什么数据结构。

### 手动与自动恢复 {/* #manual-vs-automatic-resumption */}

| 方式 | 适用场景 |
| - | - |
| 手动（`resumeStream()`） | 程序控制、Webhook、按钮点击、外部触发器 |
| 自动（`autoResumeSuspendedTools`） | 用户通过自然语言提供恢复数据的对话流程 |

两种方式使用相同的 Tool 定义。只有消息历史中存在挂起的 Tool，且用户在同一线程发送新消息时，才会触发自动恢复。

## 重启后恢复 {/* #resuming-after-a-restart */}

前面的示例会在挂起与审批期间保存 `stream.runId`。只要进程仍在运行，这样做就可行；但在生产环境中，审批可能在页面刷新、服务器重启后，或通过负载均衡器转发到另一台服务器后才到达。

使用 [`listSuspendedRuns()`](/reference/agents/listSuspendedRuns) 从存储中重新查找某次对话的待处理运行：

```typescript
// In the request handler that receives the user's decision
const { runs } = await agent.listSuspendedRuns({
  threadId: 'thread-123',
  resourceId: 'user-456',
})

const run = runs[0]
const toolCall = run?.toolCalls[0]

if (run && toolCall) {
  let stream
  if (toolCall.requiresApproval) {
    // Suspended by requireApproval — approve or decline the tool call
    stream = await agent.approveToolCall({ runId: run.runId, toolCallId: toolCall.toolCallId })
  } else {
    // Suspended by suspend() — resume with the data the tool asked for
    console.log('Tool asked:', toolCall.suspendPayload)
    stream = await agent.resumeStream({ name: 'San Francisco' }, { runId: run.runId })
  }
  for await (const chunk of stream.textStream) process.stdout.write(chunk)
}
```

每条返回的运行都包含挂起的 Tool 调用（`toolCallId`、`toolName`、`args` 和 `requiresApproval`）。审批型挂起（`requiresApproval: true`）通过 `approveToolCall()` / `declineToolCall()` 处理；基于 `suspend()` 的挂起则带有 `suspendPayload`，并等待带恢复数据的 `resumeStream()`。因此，即使不在内存中保留状态，也能为两种流程重新构建正确的 UI。

`sendToolApproval()` 也会自动通过存储查找运行。如果 Memory 中没有该线程的活动运行，它会先在存储中搜索挂起的运行。若多个挂起运行匹配同一线程，请传入 `toolCallId`。

HTTP 接口 `GET /agents/:agentId/suspended-runs` 和客户端 SDK 的 [`agent.listSuspendedRuns()`](/reference/client-js/agents#listsuspendedruns) 也提供相同的查找能力，供浏览器中的审批 UI 直接重新发现待处理运行。

:::note

只有为 Mastra 实例配置持久化[存储提供方](/docs/storage)，挂起运行才能在重启后保留。默认的内存存储会在进程退出时丢失快照。

:::

### 崩溃后恢复决策 {/* #recovering-a-decision-after-a-crash */}

调用 `approveToolCall()`、`declineToolCall()` 或 `resumeStream()` 时，运行及其决策或恢复数据、目标 `toolCallId` 会一并在存储中被认领。如果负责恢复的进程在运行结束前停止，可从任意进程调用 `recoverResume()`，用已存储的决策完成该运行：

```typescript
const stream = await agent.recoverResume({ runId })

for await (const chunk of stream.textStream) process.stdout.write(chunk)
```

`recoverResume()` 只会接管已放弃的认领：尚未开始且认领已满 60 秒；或者在支持运行隔离栅栏的存储中，虽已开始但租约超过 60 秒未续期。此前调用会被 `AGENT_RESUME_ALREADY_CLAIMED` 拒绝。若运行尚未被任何恢复操作认领，则会被 `AGENT_RESUME_NOTHING_TO_RECOVER` 拒绝。

:::warning

恢复后的 Tool 调用会再次执行。认领是否放弃按时间判断，因此某个进程停滞 60 秒后可能仍在执行 Tool，而恢复操作也会执行它。请让有副作用的 Tool 能安全地重复执行，例如使用幂等键。

:::

## Tool 审批：supervisor Agent {/* #tool-approval-supervisor-agents */}

[supervisor Agent](/docs/subagents) 通过 `.stream()` 或 `.generate()` 协调多个子 Agent。当子 Agent 调用需要审批的 Tool 时，请求会沿委派链向上传递，并显示在 supervisor 层：

1. supervisor 将任务委派给子 Agent。
1. 子 Agent 调用设置了 `requireApproval: true` 或使用 `suspend()` 的 Tool。
1. 审批请求向上传递给 supervisor。
1. 你在 supervisor 层批准或拒绝。
1. 决策再向下传递给子 Agent。

Tool 审批也会跨多级委派传递。如果 supervisor 委派给子 Agent A，而 A 又委派给子 Agent B，B 调用设置了 `requireApproval: true` 的 Tool，审批请求仍会显示在最顶层 supervisor。

### 识别哪个子 Agent 的 Tool 暂停 {/* #identify-which-subagent-tool-paused */}

supervisor 会在自己的委派调用上报告子 Agent 的暂停，因此 `tool-call-approval` 或 `tool-call-suspended` 数据块中的 `toolCallId` 指向 supervisor 对子 Agent 的调用。批准、拒绝或恢复时，务必传入该 `toolCallId`。

要展示子 Agent 中究竟哪个 Tool 调用暂停，请读取同一载荷中的以下字段：

- `delegatedToolCallId`：子 Agent 中暂停的 Tool 调用 ID，可区分同一委派中的两次暂停，例如先提问再审批。
- `delegatedToolName`：子 Agent 中暂停的 Tool 名称。

即使经过多级委派，这两个字段也始终指向最深层、真正暂停的 Tool 调用。Memory 会随暂停一起保存它们，因此重新加载对话后仍可读取；`generate()` 也会在 `suspendPayload` 中返回它们。

```typescript
const stream = await supervisorAgent.stream('Draft and publish the report')

for await (const chunk of stream.fullStream) {
  if (chunk.type === 'tool-call-approval' || chunk.type === 'tool-call-suspended') {
    // Label the pause with the subagent tool call that caused it
    console.log('Paused:', chunk.payload.delegatedToolName, chunk.payload.delegatedToolCallId)

    // Pass the supervisor's delegation call when you approve, decline, or resume
    console.log('Resume with:', chunk.payload.toolCallId)
  }
}
```

### 在 supervisor Agent 中批准和拒绝 {/* #approve-and-decline-in-supervisor-agents */}

下例创建一个包含待审批 Tool 的子 Agent。Tool 触发审批请求时，该请求会以 `tool-call-approval` 数据块出现在 supervisor 的流中：

```typescript
import { Agent } from '@mastra/core/agent'
import { createTool } from '@mastra/core/tools'
import { Memory } from '@mastra/memory'
import { z } from 'zod'

const findUserTool = createTool({
  id: 'find-user',
  description: 'Finds user by ID in the database',
  inputSchema: z.object({
    userId: z.string(),
  }),
  outputSchema: z.object({
    user: z.object({
      id: z.string(),
      name: z.string(),
      email: z.string(),
    }),
  }),
  // highlight-next-line
  requireApproval: true,
  execute: async input => {
    const user = await database.findUser(input.userId)
    return { user }
  },
})

const dataAgent = new Agent({
  id: 'data-agent',
  name: 'Data Agent',
  description: 'Handles database queries and user data retrieval',
  model: '__GATEWAY_OPENAI_MODEL_LUNA__',
  tools: { findUserTool },
})

const supervisorAgent = new Agent({
  id: 'supervisor',
  name: 'Supervisor Agent',
  instructions: `You coordinate data retrieval tasks.
    Delegate to data-agent for user lookups.`,
  model: '__GATEWAY_OPENAI_MODEL__',
  agents: { dataAgent },
  memory: new Memory(),
})

const stream = await supervisorAgent.stream('Find user with ID 12345')

for await (const chunk of stream.fullStream) {
  // highlight-next-line
  if (chunk.type === 'tool-call-approval') {
    console.log('Tool requires approval:', chunk.payload.toolName)
    console.log('Arguments:', chunk.payload.args)

    // Approve the tool call
    // highlight-start
    const resumeStream = await supervisorAgent.approveToolCall({
      runId: stream.runId,
      toolCallId: chunk.payload.toolCallId,
    })
    //highlight-end

    for await (const resumeChunk of resumeStream.textStream) {
      process.stdout.write(resumeChunk)
    }

    // To decline instead, use:
    const declineStream = await supervisorAgent.declineToolCall({
      runId: stream.runId,
      toolCallId: chunk.payload.toolCallId,
    })
  }
}
```

### 在 supervisor Agent 中使用 `suspend()` {/* #use-suspend-in-supervisor-agents */}

Tool 也可以调用 [`suspend()`](#approval-using-suspend) 暂停执行并向用户返回上下文。与 `requireApproval` 一样，这种挂起也能沿 supervisor 的委派链传递，并显示在 supervisor 层：

```typescript title="src/mastra/tools/conditional-tool.ts"
import { createTool } from '@mastra/core/tools'
import { z } from 'zod'

const conditionalTool = createTool({
  id: 'conditional-operation',
  description: 'Performs an operation that may require confirmation',
  inputSchema: z.object({
    operation: z.string(),
  }),
  suspendSchema: z.object({
    message: z.string(),
  }),
  resumeSchema: z.object({
    confirmed: z.boolean(),
  }),
  execute: async (input, context) => {
    const { resumeData } = context?.agent ?? {}

    if (!resumeData?.confirmed) {
      return context?.agent?.suspend({
        message: `Confirm: ${input.operation}?`,
      })
    }

    // Proceed with operation
    return await performOperation(input.operation)
  },
})
```

```typescript
// When using this tool through a subagent in supervisor agents
for await (const chunk of stream.fullStream) {
  if (chunk.type === 'tool-call-suspended') {
    console.log('Tool suspended:', chunk.payload.suspendPayload.message)

    // Resume with confirmation
    const resumeStream = await supervisorAgent.resumeStream(
      { confirmed: true },
      { runId: stream.runId },
    )

    for await (const resumeChunk of resumeStream.textStream) {
      process.stdout.write(resumeChunk)
    }
  }
}
```

### supervisor Agent 配合 `generate()` 审批 {/* #supervisor-approval-with-generate */}

supervisor Agent 中的 Tool 审批请求也可以通过 `generate()` 传播：

```typescript
const output = await supervisorAgent.generate('Find user with ID 12345', {
  maxSteps: 10,
})

if (output.finishReason === 'suspended') {
  console.log('Tool requires approval:', output.suspendPayload.toolName)

  // Approve
  const result = await supervisorAgent.approveToolCallGenerate({
    runId: output.runId,
    toolCallId: output.suspendPayload.toolCallId,
  })

  console.log('Final result:', result.text)
}
```
