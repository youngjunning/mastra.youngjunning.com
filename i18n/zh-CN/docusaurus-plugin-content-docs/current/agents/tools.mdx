# 工具

Agent 使用工具调用 API、查询数据库，也可以运行代码库中的自定义函数。工具让 Agent 能以结构化方式访问数据并执行明确的操作，从而具备文本生成之外的能力。你还可以从远程 [MCP Server](/docs/connections/mcp) 加载工具，扩展 Agent 的能力。对于 Linear、Slack 和 GitHub 等服务，Mastra 平台上的 [Connect](/docs/mastra-platform/connect#add-tools-to-an-agent) 提供带有托管凭据的现成工具，也可以与自定义工具搭配使用。

<Inject>
  **供 AI Agent 参考：** `execute` 只有一种签名：`execute(inputData, context)`。第一个参数按 `inputSchema` 验证。运行时始终提供第二个参数，其中包含 `requestContext`、`tracingContext`、`abortSignal` 等执行元数据；不使用时可在函数签名中省略。其他签名形式已过时。直接运行 `npx mastra api tool execute weather-tool '{"location":"San Francisco"}'` 测试该工具，无需编写临时脚本。此命令需要运行中的 Mastra Server：可用 `npx mastra dev` 启动本地服务，或通过 `--url` 指定可访问服务的基地址。构造其他输入前，先运行 `npx mastra api tool execute --schema`。运行 `npx skills add mastra-ai/skills --skill mastra` 安装 Mastra Skill，获取完整的 API CLI 发现、目标定位、Schema、身份验证及错误处理指南。
</Inject>

## 何时使用工具 {/* #when-to-use-tools */}

当 Agent 需要从远程资源获取更多上下文或信息，或者需要运行代码执行特定操作时，可以使用工具。例如获取实时数据、返回格式一致且定义明确的结果，这些任务仅靠模型无法可靠完成。

## 快速开始 {/* #quickstart */}

从 `@mastra/core/tools` 导入 [`createTool`](/reference/tools/create-tool)，然后定义包含 `id`、`description`、`inputSchema`、`outputSchema` 和 `execute` 的工具。

以下示例创建一个从 API 获取天气数据的工具。`execute` 只有一种签名：`execute(inputData, context)`。第一个参数是经过 `inputSchema` 验证的输入；运行时始终将执行上下文作为第二个参数传入，不使用时可在函数签名中省略。也可以直接在函数签名中解构输入字段。

```typescript title="src/mastra/tools/weather-tool.ts"
import { createTool } from '@mastra/core/tools'
import { z } from 'zod'

export const weatherTool = createTool({
  id: 'weather-tool',
  description: 'Fetches weather for a location',
  inputSchema: z.object({
    location: z.string(),
  }),
  outputSchema: z.object({
    location: z.string(),
    temperatureCelsius: z.number(),
    conditions: z.string(),
  }),
  execute: async ({ location }, { abortSignal }) => {
    const response = await fetch(`https://wttr.in/${location}?format=j1`, {
      signal: abortSignal,
    })
    const data = await response.json()

    return {
      location,
      temperatureCelsius: Number(data.current_condition[0].temp_C),
      conditions: data.current_condition[0].weatherDesc[0].value,
    }
  },
})
```

创建工具时，描述应简洁，聚焦工具的主要用途。描述清楚的 Schema 名称也有助于 Agent 判断如何使用工具。有关属性、配置和示例，请参阅 [`createTool` 参考文档](/reference/tools/create-tool)。

要让 Agent 使用工具，请将其添加到 `Agent` 类的 `tools` 属性。在 Agent 的系统提示词中说明可用工具及其大致用途，有助于它判断何时调用工具。

```typescript {11} title="src/mastra/agents/weather-agent.ts"
import { Agent } from '@mastra/core/agent'
import { weatherTool } from '../tools/weather-tool'

export const weatherAgent = new Agent({
  id: 'weather-agent',
  name: 'Weather Agent',
  instructions: `
    You are a helpful weather assistant.
    Use the weatherTool to fetch current weather data.`,
  model: '__GATEWAY_OPENAI_MODEL__',
  tools: { weatherTool },
})
```

### 处理输出验证失败 {/* #handle-output-validation-failures */}

如果结果不符合 `outputSchema`，Mastra 会记录警告，并返回验证错误对象而非实际结果。模型会将此次调用视为失败，可能再次调用。对于结果产生时已完成副作用的工具，应设置 `outputValidation: 'warn'`：Mastra 仍会记录不匹配，但会原样返回实际结果，避免模型重复下单等操作。

```typescript title="src/mastra/tools/place-order-tool.ts"
import { createTool } from '@mastra/core/tools'
import { z } from 'zod'

export const placeOrderTool = createTool({
  id: 'place-order',
  description: 'Places an order and returns its id and total',
  inputSchema: z.object({ sku: z.string(), quantity: z.number().int().positive() }),
  outputSchema: z.object({ orderId: z.string(), total: z.number() }),
  outputValidation: 'warn',
  execute: async ({ sku, quantity }) => {
    return await orders.create({ sku, quantity })
  },
})
```

## 使用多个工具 {/* #multiple-tools */}

Agent 可以将复杂任务的不同部分交给多个工具处理。它会根据用户消息、自身指令，以及工具描述和 Schema 决定使用哪些工具。

```typescript {13} title="src/mastra/agents/weather-agent.ts"
import { Agent } from '@mastra/core/agent'
import { weatherTool } from '../tools/weather-tool'
import { hazardsTool } from '../tools/hazards-tool'

export const weatherAgent = new Agent({
  id: 'weather-agent',
  name: 'Weather Agent',
  instructions: `
    You are a helpful weather assistant.
    Use the weatherTool to fetch current weather data.
    Use the hazardsTool to provide information about potential weather hazards.`,
  model: '__GATEWAY_OPENAI_MODEL__',
  tools: { weatherTool, hazardsTool },
})
```

## 将 Agent 用作工具 {/* #agents-as-tools */}

通过 `agents` 配置添加子 Agent，即可创建 [Supervisor](/docs/subagents)。Mastra 会把每个子 Agent 转换为 `agent-<key>` 工具。为每个子 Agent 提供 `description`，帮助 Supervisor 判断何时委派任务。

```typescript title="src/mastra/agents/supervisor.ts"
import { Agent } from '@mastra/core/agent'

const writer = new Agent({
  id: 'writer',
  name: 'Writer',
  description: 'Drafts and edits written content',
  instructions: 'You are a skilled writer.',
  model: '__GATEWAY_OPENAI_MODEL__',
})

export const supervisor = new Agent({
  id: 'supervisor',
  name: 'Supervisor',
  instructions: 'Coordinate the writer to produce content.',
  model: '__GATEWAY_OPENAI_MODEL__',
  // highlight-next-line
  agents: { writer },
})
```

## 将 Workflow 用作工具 {/* #workflows-as-tools */}

通过 `workflows` 配置添加 Workflow。Mastra 会将每个 Workflow 转换为 `workflow-<key>` 工具，并使用其 `inputSchema` 和 `outputSchema`。为 Workflow 提供 `description`，帮助 Agent 判断何时触发它。


## 调整模型接收的输出 {/* #shape-output-for-the-model */}

如果工具返回了应用所需的丰富结构化数据，但只需给模型较简短或多模态的内容，可以使用 `toModelOutput`。这样既能让模型上下文保持精简，又能在应用中保留完整的工具结果。

```typescript title="src/mastra/tools/weather-tool.ts"
import { createTool } from '@mastra/core/tools'

export const weatherTool = createTool({
  execute: async ({ location }) => {
    const response = await fetch(`https://wttr.in/${location}?format=j1`)
    const data = await response.json()

    return {
      location,
      temperatureCelsius: Number(data.current_condition[0].temp_C),
      conditions: data.current_condition[0].weatherDesc[0].value,
      weatherIconUrl: data.current_condition[0].weatherIconUrl[0].value,
      source: data,
    }
  },
  toModelOutput: output => {
    return {
      type: 'content',
      value: [
        {
          type: 'text',
          text: `${output.location}: ${output.temperatureCelsius}°C and ${output.conditions}`,
        },
        { type: 'image-url', url: output.weatherIconUrl },
      ],
    }
  },
})
```

`toModelOutput` 也适用于客户端工具。通过 `clientTools` 传入的工具在客户端执行后，由客户端完成映射，并将转换后的输出与原始结果一同发送给服务器。对于定义在服务器上但没有 `execute` 函数的工具（由浏览器执行，并在下一次请求中发送结果），服务器端定义中的 `toModelOutput` 会处理传入的结果。模型接收转换后的内容，而不是原始工具结果。

## 在客户端运行的工具 {/* #tools-that-run-on-the-client */}

没有 `execute` 函数的工具是客户端工具，服务器无法执行它。模型调用该工具时，Agent 会在当前步骤停止；本次运行以 `finishReason: 'tool-calls'` 结束，直到工具返回结果，模型才会继续生成文本。根据模型是否需要结果选择相应模式：

- **客户端执行工具，模型需要结果**：省略 `execute`。客户端执行工具，将结果加入对话，再发起新请求，让 Agent 继续运行。使用 AI SDK 的 `useChat()` 时，请参阅[配合 `useChat()` 使用客户端工具](/integrations/agentic-ui/ai-sdk-ui#client-tools-with-usechat)。
- **客户端只需渲染工具调用**（例如商品卡片）：提供返回简短确认信息的 `execute`。Agent 会在同一次运行中继续执行，客户端根据工具输入渲染相应内容。返回简短值即可，不要重复返回输入，以免扩大模型上下文和已存储的消息。
- **工具需要用户提供结构化回答**（例如确认写入购物车）：在 `execute` 中调用 `suspend()`，收到用户回答后恢复执行。参阅[使用 `suspend()` 在运行时暂停](/docs/agents/human-in-the-loop#runtime-suspension-with-suspend)。

```typescript title="src/mastra/tools/show-product-tool.ts"
import { createTool } from '@mastra/core/tools'
import { z } from 'zod'

export const showProductTool = createTool({
  id: 'show-product',
  description: 'Shows a product card to the user',
  inputSchema: z.object({
    productId: z.string(),
  }),
  // highlight-next-line
  execute: async () => ({ rendered: true }),
})
```

子 Agent 无法运行客户端工具。如果子 Agent 调用没有 `execute` 的工具，它的运行会停止，Supervisor 会在委派结果的 `subAgentPendingToolCalls` 中收到未完成的工具调用。可以把客户端工具交给 Supervisor，或在子 Agent 的工具中使用 `suspend()`。暂停会传递到 Supervisor，参阅[在 Supervisor Agent 中使用 `suspend()`](/docs/agents/human-in-the-loop#use-suspend-in-supervisor-agents)。

## 转换供 UI 和对话记录使用的工具数据 {/* #transform-tool-payloads-for-ui-and-transcripts */}

如果工具返回应用所需的原始数据，但浏览器端的流或用户可见的对话记录只应接收更精简、更安全的数据格式，可以使用 `transform`。`transform` 与 `toModelOutput` 分工不同：`toModelOutput` 调整返回模型的数据；`transform` 则针对 `display` 和 `transcript` 目标，调整工具输入、输出、错误、审批数据和暂停数据。

工具级 `transform` 只处理明确定义的阶段。以下示例仅转换 `output`，因此存储的工具输入保持不变。如果已配置的转换失败，Mastra 不会为 `display` 或 `transcript` 目标回退到原始数据。没有可用的安全 `inputDelta` 转换时，输入增量会被抑制。

以下示例会从两个目标的数据中移除机密信息：

```typescript title="src/mastra/tools/customer-tool.ts"
import { createTool } from '@mastra/core/tools'
import { z } from 'zod'

export const customerTool = createTool({
  id: 'lookup-customer',
  description: 'Looks up a customer by id',
  inputSchema: z.object({
    customerId: z.string(),
  }),
  outputSchema: z.object({
    ssn: z.string(),
  }),
  execute: async ({ customerId }) => {
    // const response = await fetch(`https://your-crm.example.com/customers/${customerId}`)
    // const { ssn } = await response.json()
    return {
      ssn: '123-45-6789',
    }
  },
  // highlight-start
  transform: {
    display: {
      output: () => ({ ssn: '***-**-****' }),
    },
    transcript: {
      output: () => ({ ssn: '***-**-****' }),
    },
  },
  // highlight-end
})
```

应用代码仍会收到工具返回的原始 `ssn`。浏览器端的流接收 `display` 输出，用户可见的对话记录接收 `transcript` 输出。

如果 DurableAgent 可以在进程重启后完成工具调用，应在工具的 `transform.transcript` 配置中声明必要的对话记录脱敏规则。传给 DurableAgent 单次调用的转换只保存在进程内的运行注册表中，新进程无法恢复。持久化 Worker 会重新从已注册的工具读取工具级转换配置。

其他阶段包括 `input`、`inputDelta`、`error`、`approval`、`suspend` 和 `resume`，参阅 [`createTool()` 参考文档](/reference/tools/create-tool#example-with-transform)。如需对多个工具使用同一规则，可在 [`Agent` 构造函数](/reference/agents/agent#constructor-parameters)中配置 Agent 级 `transform` 策略。

## 在工具调用前后运行逻辑 {/* #run-logic-around-tool-calls */}

使用 `hooks` 可以在 Agent 每次调用工具之前和之后运行自定义逻辑。Hook 适用于所有工具来源：直接分配的工具、Memory 工具、Toolset、客户端工具、Agent 和 Workflow 工具，以及[工作区工具](/reference/workspace/workspace-class#tool-hooks)。常见用途包括日志、审计、输入验证和拦截特定调用。

```typescript title="src/mastra/agents/support-agent.ts"
import { Agent } from '@mastra/core/agent'
import { db } from '../db' // your application database client

export const supportAgent = new Agent({
  id: 'support-agent',
  name: 'support-agent',
  instructions: 'Help users with their questions.',
  model: '__GATEWAY_OPENAI_MODEL__',
  // highlight-start
  hooks: {
    beforeToolCall: ({ toolName, input }) => {
      console.log(`Running ${toolName}`, input)
    },
    afterToolCall: async ({ toolName, input, output, error }) => {
      await db.auditLog.insert({
        toolName,
        input,
        output,
        error: error ? String(error) : undefined,
      })
    },
  },
  // highlight-end
})
```

`afterToolCall` 必须返回 `void`（或 `Promise<void>`）。等待存储操作完成，但不要返回其结果。如果存储操作抛错，工具调用也会因此失败；若审计日志只需尽力写入，应在 Hook 内捕获错误。对于被 `beforeToolCall` 跳过或被拒绝的[执行前审批](/docs/agents/human-in-the-loop#pre-execution-approval)，`afterToolCall` 不会运行，应在处理这些决定的位置记录。

`beforeToolCall` 在工具执行前运行，会收到工具名称、输入和执行上下文。返回 `{ proceed: false, output }` 可完全跳过此次调用，Agent 会将 `output` 作为工具结果：

```typescript
const guardedAgent = new Agent({
  id: 'guarded-agent',
  name: 'guarded-agent',
  instructions: 'Run shell commands for the user.',
  model: '__GATEWAY_OPENAI_MODEL__',
  hooks: {
    beforeToolCall: ({ toolName, input }) => {
      const command = (input as { command?: string }).command ?? ''
      if (toolName === 'execute_command' && command.includes('rm -rf')) {
        return { proceed: false, output: 'Command blocked by policy.' }
      }
    },
  },
})
```

`afterToolCall` 在工具执行结束后运行，无论成功还是失败。成功时收到 `output`；如果工具抛错，则收到 `error`，Hook 运行后该错误会重新抛出。

### 为单次执行配置 Hook {/* #per-execution-hooks */}

向 `.generate()` 或 `.stream()` 传入 `hooks`，即可只为该次执行设置 Hook。单次执行的 Hook 会覆盖同名的 Agent 级 Hook：

```typescript
await supportAgent.generate('Look up the order status', {
  hooks: {
    beforeToolCall: ({ toolName }) => {
      console.log(`This run only: ${toolName}`)
    },
  },
})
```

Agent 级和单次执行的 Hook 按键合并：单次执行只提供 `beforeToolCall` 时，Agent 级的 `afterToolCall` 仍会保留。

## 流式处理 {/* #streaming */}

工具支持生命周期 Hook，用于监测流式执行的不同阶段，尤其适合日志和分析。

有关 `writer` API 的一般用法，请参阅[流式处理](/docs/guides/streaming#writer-api)。

### 可用的 Hook {/* #available-hooks */}

- **onInputStart**：工具调用的输入开始以流式方式传入时触发
- **onInputDelta**：每收到一段输入时触发
- **onInputAvailable**：完整输入解析并验证后触发
- **onOutput**：工具成功执行并产生输出后触发

有关所有生命周期 Hook 的详细说明，请参阅 [`createTool()` 参考文档](/reference/tools/create-tool#tool-lifecycle-hooks)。

### 示例：使用 `onInputAvailable` 和 `onOutput` {/* #example-using-oninputavailable-and-onoutput */}

```typescript
import { createTool } from '@mastra/core/tools'
import { z } from 'zod'

export const weatherTool = createTool({
  id: 'weather-tool',
  description: 'Get weather information',
  inputSchema: z.object({
    location: z.string(),
  }),
  outputSchema: z.object({
    location: z.string(),
    temperatureCelsius: z.number(),
    conditions: z.string(),
  }),
  // Called when the complete input is available
  onInputAvailable: ({ input, toolCallId }) => {
    console.log(`Weather requested for: ${input.location}`)
  },
  execute: async ({ location }) => {
    const weather = await fetchWeather(location)
    return weather
  },
  // Called after successful execution
  onOutput: ({ output, toolName }) => {
    console.log(`${toolName} result: ${output.temperatureCelsius}°C, ${output.conditions}`)
  },
})
```

### 在 UI 中显示流式工具输入 {/* #streaming-tool-input-in-uis */}

模型生成工具调用时，参数先通过 `tool-call-delta` 流块逐步到达，之后才会产生最终的 `tool-call` 流块。UI 可以监听相应的 `tool_input_start`、`tool_input_delta` 和 `tool_input_end` 事件，边接收边渲染参数，例如无需等待完整调用就显示文件路径或命令。

对累计的 `argsTextDelta` 片段使用部分 JSON 解析器，可在 JSON 尚未完整时提取可用的参数值。这支持实时差异预览（编辑工具）、流式文件内容（写入工具），以及即时显示搜索模式或文件路径。

## 控制工具选择 {/* #control-tool-selection */}

在运行时向 `.generate()` 或 `.stream()` 传入 `toolChoice` 或 `activeTools`，可控制 Agent 使用哪些工具。

```typescript
await agent.generate('Check the forecast', {
  toolChoice: 'required',
  activeTools: ['weatherTool'],
})
```

所有运行时选项（包括 `toolsets`、`clientTools` 和 `prepareStep`）请参阅 [`Agent.generate()` 参考文档](/reference/agents/generate)。

## 控制流响应中的 `toolName` {/* #control-toolname-in-stream-responses */}

流响应中的 `toolName` 由你使用的**对象键名**决定，而不是工具、Agent 或 Workflow 的 `id` 属性。

```typescript oxfmt:false
export const weatherTool = createTool({
  id: 'weather-tool',
})

// Using the variable name as the key
tools: { weatherTool }
// Stream returns: toolName: "weatherTool"

// Using the tool's id as the key
tools: { [weatherTool.id]: weatherTool }
// Stream returns: toolName: "weather-tool"

// Using a custom key
tools: { "my-custom-name": weatherTool }
// Stream returns: toolName: "my-custom-name"
```

这样可以指定工具在流中的名称。如果希望 `toolName` 与工具的 `id` 一致，请将工具的 `id` 用作对象键名。

### 将子 Agent 和 Workflow 用作工具 {/* #subagents-and-workflows-as-tools */}

子 Agent 和 Workflow 遵循同一规则：Mastra 会将对象键名前加上相应前缀，作为工具名称：

| 属性 | 前缀 | 示例键名 | `toolName` |
| - | - | - | - |
| `agents` | `agent-` | `weather` | `agent-weather` |
| `workflows` | `workflow-` | `research` | `workflow-research` |

```typescript
const orchestrator = new Agent({
  id: 'orchestrator',
  agents: {
    weather: weatherAgent, // toolName: "agent-weather"
  },
  workflows: {
    research: researchWorkflow, // toolName: "workflow-research"
  },
})
```

因此，对于子 Agent，你会在流响应中看到两个不同的标识符：

- 工具调用事件中的 `toolName: "agent-weather"`：生成的工具包装器名称
- `data-tool-agent` 流块中的 `id: "weather-agent"`：子 Agent 实际的 `id` 属性

## 内置工具 {/* #built-in-tools */}

Mastra 在 `@mastra/core/tools` 中提供与 Agent 无关的内置工具，为 Agent 添加交互和组织能力。

每个工具都有两个名称：代码中导入的导出名，以及模型在工具调用、Trace 和 `toolName` 字段中看到的工具 ID。

| 导出名 | 工具 ID | 用途 |
| - | - | - |
| `askUserTool` | `ask_user` | 向用户提问并等待回答 |
| `submitPlanTool` | `submit_plan` | 提交计划文件供用户审批 |
| `taskWriteTool` | `task_write` | 创建或替换结构化任务列表 |
| `taskUpdateTool` | `task_update` | 按 ID 更新一项已跟踪任务 |
| `taskCompleteTool` | `task_complete` | 将一项已跟踪任务标记为完成 |
| `taskCheckTool` | `task_check` | 检查任务列表的完成状态 |
| `webSearchTool` | `<provider.defined>` | 运行当前 Provider 的原生网页搜索 |
| `webFetchTool` | `web_fetch` | 按 URL 获取网页并返回其文本内容 |

### 使用 Provider 的网页搜索 {/* #use-provider-web-search */}

需要模型 Provider 运行其原生网页搜索工具时，从 `@mastra/core/tools` 导入 `webSearchTool`。Mastra 会在运行时根据当前模型解析该工具，再将由 Provider 管理的工具传给模型。

```typescript {2,10} title="src/mastra/agents/research-agent.ts"
import { Agent } from '@mastra/core/agent'
import { webSearchTool } from '@mastra/core/tools'

export const researchAgent = new Agent({
  id: 'research-agent',
  name: 'Research Agent',
  instructions: 'Use web search when you need current information.',
  model: 'openai/gpt-5.6-sol',
  tools: {
    search: webSearchTool,
  },
})
```

`webSearchTool` 支持 OpenAI、Anthropic、Google Gemini 和 xAI 模型。如果 Mastra 无法从当前模型识别这几种 Provider，Agent 运行会因 `MastraError` 失败。

解析后的工具 ID 由 Provider 决定：`openai.web_search`、`anthropic.web_search_20250305`、`google.google_search` 或 `xai.web_search`。

通过 Mastra Gateway 提供的模型（例如 `mastra/openai/gpt-5.6-sol`）会改用 Gateway 自带的网页搜索（`openrouter.web_search`）。Gateway 网页搜索的结果会直接出现在模型的文本响应中，不会产生单独的工具调用块或来源块。Gateway 不支持其他 Provider 原生工具，传入这类工具会使 Agent 运行因 `MastraError` 失败。

`search` 键只是 Agent 内部的工具名称；可以使用任意键名。`webSearchTool` 的值告诉 Mastra 使用 Provider 的网页搜索。

### 获取网页 {/* #fetch-a-web-page */}

需要 Agent 读取指定 URL 时，从 `@mastra/core/tools` 导入 `webFetchTool`。该工具通过 HTTP 或 HTTPS 请求页面，并返回文本内容及响应元数据。

```typescript {2,10} title="src/mastra/agents/reader-agent.ts"
import { Agent } from '@mastra/core/agent'
import { webFetchTool } from '@mastra/core/tools'

export const readerAgent = new Agent({
  id: 'reader-agent',
  name: 'Reader Agent',
  instructions: 'Fetch the page the user links to before answering.',
  model: 'openai/gpt-5.6-sol',
  tools: {
    fetch: webFetchTool,
  },
})
```

工具接受一个 `url` 输入，并返回 `content`、`truncated`、`status`、`statusText`、`contentType`、`url` 和 `ok`。它有以下限制：

- 只允许 `http:` 和 `https:` URL。
- 禁止请求 `localhost` 和私有或保留 IP 地址，包括 DNS 解析后指向这些地址的域名。
- 响应最多保留 100,000 个字符；截断时结果中的 `truncated: true`。
- 请求最多跟随 5 次重定向，超时时间为 15 秒。

失败时不会抛错。工具会返回 `isError: true`，并在 `content` 中说明原因，以便 Agent 重试或解释问题。

### 向用户提问 {/* #ask-the-user-a-question */}

导入 [`askUserTool`](/reference/tools/ask-user-tool) 并将其添加到 Agent 的工具集中。

该工具会暂停运行，并发送带有问题的 `tool-call-suspended` 事件。使用用户回答调用 `resumeStream()` 后，运行会继续。

```typescript title="src/mastra/agents/index.ts"
import { Agent } from '@mastra/core/agent'
import { askUserTool } from '@mastra/core/tools'

const agent = new Agent({
  id: 'assistant',
  name: 'Assistant',
  instructions: 'Ask the user for clarification when the request is ambiguous.',
  model,
  tools: { askUserTool },
})
```

以流式方式运行 Agent 并监听 `tool-call-suspended` 流块。`suspendPayload` 中包含问题和可选的结构化选项：

```typescript title="src/run.ts"
const stream = await agent.stream('Summarize my project')

for await (const chunk of stream.fullStream) {
  if (chunk.type === 'tool-call-suspended') {
    const { question, options } = chunk.payload.suspendPayload
    console.log(question)
    const answer = await getUserAnswer() // your UI logic
    const resumed = await agent.resumeStream(answer, { runId: stream.runId })
    for await (const c of resumed.textStream) process.stdout.write(c)
  }
}
```

`askUserTool` 支持自由文本、单选（`options` 数组）和多选（`selectionMode: 'multi_select'`）问题。将它与 `autoResumeSuspendedTools` 配合使用，Agent 即可在用户发送下一条聊天消息后自动恢复。详见[工具自动恢复](/docs/agents/human-in-the-loop#automatic-tool-resumption)。

### 提交计划供审核 {/* #submit-a-plan-for-review */}

导入 [`submitPlanTool`](/reference/tools/submit-plan-tool)，即可让 Agent 将计划写入文件并提交给用户审核。该工具会暂停运行，直到用户批准或拒绝：

```typescript title="src/run.ts"
for await (const chunk of stream.fullStream) {
  if (chunk.type === 'tool-call-suspended' && chunk.payload.toolName === 'submit_plan') {
    const { path } = chunk.payload.suspendPayload
    // Read and display the plan file, then resume:
    const resumed = await agent.resumeStream({ action: 'approved' }, { runId: stream.runId })
    for await (const c of resumed.textStream) process.stdout.write(c)
  }
}
```

### 任务跟踪 {/* #task-tracking */}

任务工具用于管理 Agent 运行期间的结构化持久任务列表。它们需要 [Memory](/docs/memory/overview)，才能将任务列表保存在某个 Thread 的存储空间内。

通过 [`TaskSignalProvider`](/reference/signals/task-signal-provider) 一次注册四个工具和 `TaskStateProcessor`，即可启用任务跟踪：

```typescript title="src/mastra/agents/index.ts"
import { Agent } from '@mastra/core/agent'
import { Memory } from '@mastra/memory'
import { TaskSignalProvider } from '@mastra/core/signals'

const agent = new Agent({
  id: 'coder',
  name: 'Coder',
  instructions: 'Track your progress with the task tools.',
  model,
  memory: new Memory(),
  signals: [new TaskSignalProvider()],
})
```

同一时间只能有一个任务处于 `in_progress` 状态。任务列表保存在 Thread 范围内的 `threadState` 存储域，并投射到 Agent 的[状态信号](/docs/signals/state-signals)通道，因此即使 Observational Memory 截断上下文，任务仍会保留。完整 Schema 参阅[任务工具参考文档](/reference/tools/task-tools)。

[AgentController](/docs/harness/agent-controller) 会在每种模式下自动加入所有内置工具，无需手动添加。关于 AgentController 的特定行为，请参阅[工具审批](/docs/harness/agent-controller#approve-tools-and-resume-suspensions)。
