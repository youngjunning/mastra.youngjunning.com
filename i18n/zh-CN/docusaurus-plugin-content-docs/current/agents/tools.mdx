# Tool

Agent使用Tool来调用 API 或查询数据库。他们还可以从您的代码库运行自定义函数。Tool通过提供对数据的结构化访问和执行明确定义的操作，为Agent提供了超越语言生成的功能。您还可以从远程加载Tool[MCP servers](/docs/connections/mcp)扩大Agent的能力。对于 Linear、Slack 和 GitHub 等服务，[连接](/docs/mastra-platform/connect#add-tools-to-an-agent)Mastra 平台提供带有托管凭据的现成Tool，您可以将其与您自己的凭据结合起来。

<Inject>
  **对于人工智能Agent：** `execute` has exactly one signature: `execute(inputData, context)`. The first parameter is validated against `inputSchema`。运行时总是提供第二个参数`requestContext`, `tracingContext`, `abortSignal`，以及其他执行元数据。不使用时可以省略。其他形状已经过时了。跑步`npx mastra api tool execute weather-tool '{"location":"San Francisco"}'`直接测试这个Tool，而不是编写临时脚本。该命令需要一个正在运行的 Mastra 服务器；启动本地服务器`npx mastra dev`，或传递可访问服务器的基本 URL`--url`。跑步`npx mastra api tool execute --schema`在构建不同的输入之前。安装 Mastra 的技能`npx skills add mastra-ai/skills --skill mastra`获取完整的 API CLI 发现、定位、架构、身份验证和错误处理指南。
</Inject>

## 何时使用Tool {/* #when-to-use-tools */}

当Agent需要来自远程资源的附加上下文或信息，或者需要运行执行特定操作的代码时，请使用Tool。这包括模型无法自行可靠处理的任务，例如获取实时数据或返回一致的、定义明确的输出。

## 快速入门 {/* #quickstart */}

进口[`createTool`](/reference/tools/create-tool) from `@mastra/core/tools` and define a tool with an `id`, `description`, `inputSchema`, `outputSchema`, and `execute` function.

此示例创建一个从 API 获取天气数据的Tool。`execute` has exactly one signature: `execute(inputData, context)`. The first parameter contains input validated against `inputSchema`. The runtime always provides the second parameter as the execution context, though you may omit it from your function signature when unused. You can destructure the input fields directly in the function signature.

```typescript title="src/mastra/tools/weather-tool.ts"
import { createTool } from '@mastra/core/tools'
import { z } from 'zod'

export const weatherTool = createTool({
  id: 'weather-tool',
  description: 'Fetches weather for a location',
  inputSchema: z.object({
    location: z.string(),
  }),
  outputSchema: z.object({
    location: z.string(),
    temperatureCelsius: z.number(),
    conditions: z.string(),
  }),
  execute: async ({ location }, { abortSignal }) => {
    const response = await fetch(`https://wttr.in/${location}?format=j1`, {
      signal: abortSignal,
    })
    const data = await response.json()

    return {
      location,
      temperatureCelsius: Number(data.current_condition[0].temp_C),
      conditions: data.current_condition[0].weatherDesc[0].value,
    }
  },
})
```

创建Tool时，请保持描述简洁并重点关注该Tool的用途，强调其主要用例。描述性架构名称还可以帮助指导Agent如何使用该Tool。参观[`createTool`](/reference/tools/create-tool) reference for more information on available properties, configurations, and examples.

要使Agent可以使用Tool，请将其添加到`tools` property on the `Agent` class. Mentioning available tools and their general purpose in the agent's system prompt helps the agent decide when to call a tool and when not to.

```typescript {11} title="src/mastra/agents/weather-agent.ts"
import { Agent } from '@mastra/core/agent'
import { weatherTool } from '../tools/weather-tool'

export const weatherAgent = new Agent({
  id: 'weather-agent',
  name: 'Weather Agent',
  instructions: `
    You are a helpful weather assistant.
    Use the weatherTool to fetch current weather data.`,
  model: '__GATEWAY_OPENAI_MODEL__',
  tools: { weatherTool },
})
```

### 处理输出验证失败 {/* #handle-output-validation-failures */}

当结果不匹配时`outputSchema`, Mastra logs a warning and returns a validation error object instead of the result. The model then treats the call as failed and may retry it. For tools whose side effects have already happened by the time the result is produced, set `outputValidation: 'warn'`. Mastra still logs the mismatch, but it returns the real result unchanged, which keeps the model from retrying an order that was already placed.

```typescript title="src/mastra/tools/place-order-tool.ts"
import { createTool } from '@mastra/core/tools'
import { z } from 'zod'

export const placeOrderTool = createTool({
  id: 'place-order',
  description: 'Places an order and returns its id and total',
  inputSchema: z.object({ sku: z.string(), quantity: z.number().int().positive() }),
  outputSchema: z.object({ orderId: z.string(), total: z.number() }),
  outputValidation: 'warn',
  execute: async ({ sku, quantity }) => {
    return await orders.create({ sku, quantity })
  },
})
```

```typescript {13} title="src/mastra/agents/weather-agent.ts"
    You are a helpful weather assistant.
    Use the weatherTool to fetch current weather data.

```

```typescript title="src/mastra/agents/supervisor.ts"
  instructions: 'Coordinate the writer to produce content.',
  model: '__GATEWAY_OPENAI_MODEL__',
  // highlight-next-line
  agents: { writer },
})
```

## 模型的形状输出 {/* #shape-output-for-the-model */}

使用`toModelOutput` when your tool returns rich structured data for your application, but you want the model to receive a smaller or multimodal representation. This keeps model context focused while preserving the full tool result in your app.

```typescript title="src/mastra/tools/weather-tool.ts"
import { createTool } from '@mastra/core/tools'

export const weatherTool = createTool({
  execute: async ({ location }) => {
    const response = await fetch(`https://wttr.in/${location}?format=j1`)
    const data = await response.json()

    return {
      location,
      temperatureCelsius: Number(data.current_condition[0].temp_C),
      conditions: data.current_condition[0].weatherDesc[0].value,
      weatherIconUrl: data.current_condition[0].weatherIconUrl[0].value,
      source: data,
    }
  },
  toModelOutput: output => {
    return {
      type: 'content',
      value: [
        {
          type: 'text',
          text: `${output.location}: ${output.temperatureCelsius}°C and ${output.conditions}`,
        },
        { type: 'image-url', url: output.weatherIconUrl },
      ],
    }
  },
})
```

`toModelOutput`也适用于客户端Tool。对于通过的Tool`clientTools`, the mapping runs on the client after the tool executes, and the transformed output is sent back to the server alongside the raw result. For tools defined on the server without an `execute` function (the browser runs the tool and sends the result back on the next request), the server definition's `toModelOutput` is applied to the incoming result. The model receives the transformed content instead of the raw tool result.

## 在客户端运行的Tool {/* #tools-that-run-on-the-client */}

没有Tool的Tool`execute` function is a client tool: the server can't run it. The agent stops at the step where the model called it. The run ends with `finishReason: 'tool-calls'`, and the model doesn't produce more text until the tool has a result. Pick the pattern that matches what the model needs back:

* **客户端运行该Tool，模型需要其结果**: 省略`execute`. The client runs the tool, adds the result to the conversation, and sends a new request so the agent continues. With AI SDK `useChat()`, see [client tools with `useChat()`](/integrations/agentic-ui/ai-sdk-ui#client-tools-with-usechat).
* **客户端只渲染调用**（例如产品卡）：为Tool提供`execute` that returns a short acknowledgement. The agent continues in the same run, and the client renders the tool part from its input. Return a small value instead of echoing the input so the model context and stored messages stay small.
* **该Tool需要用户提供结构化的答案**（例如确认购物车写入）：致电`suspend()` in `execute`, and resume with the user's answer. See [runtime suspension with `suspend()`](/docs/agents/human-in-the-loop#runtime-suspension-with-suspend).

```typescript title="src/mastra/tools/show-product-tool.ts"
import { createTool } from '@mastra/core/tools'
import { z } from 'zod'

export const showProductTool = createTool({
  id: 'show-product',
  description: 'Shows a product card to the user',
  inputSchema: z.object({
    productId: z.string(),
  }),
  // highlight-next-line
  execute: async () => ({ rendered: true }),
})
```

子Agent无法运行客户端Tool。当子Agent调用Tool时没有`execute`, its run stops and the supervisor receives the unresolved calls in `subAgentPendingToolCalls` on the delegation result. Give client tools to the supervisor, or use `suspend()` in the subagent's tool. Suspension propagates through the supervisor, see [use `suspend()` in supervisor agents](/docs/agents/human-in-the-loop#use-suspend-in-supervisor-agents).

## 转换 UI 和脚本的Tool负载 {/* #transform-tool-payloads-for-ui-and-transcripts */}

使用`transform` when a tool returns raw data your application needs, but browser-facing streams or user-visible transcript messages should receive a smaller or safer shape. `transform` is separate from `toModelOutput`: `toModelOutput` shapes the payload sent back to the model, while `transform` shapes tool input, output, errors, approval payloads, and suspension payloads for `display` and `transcript` targets.

Tool级转换仅更改其定义的阶段。在下面的例子中，仅`output` is transformed, so the stored tool input stays unchanged. If a transform is configured and it fails, Mastra doesn't fall back to the raw payload for display or transcript targets. Input deltas are suppressed when no safe `inputDelta` transform is available.

以下示例从两个目标中编辑秘密：

```typescript title="src/mastra/tools/customer-tool.ts"
import { createTool } from '@mastra/core/tools'
import { z } from 'zod'

export const customerTool = createTool({
  id: 'lookup-customer',
  description: 'Looks up a customer by id',
  inputSchema: z.object({
    customerId: z.string(),
  }),
  outputSchema: z.object({
    ssn: z.string(),
  }),
  execute: async ({ customerId }) => {
    // const response = await fetch(`https://your-crm.example.com/customers/${customerId}`)
    // const { ssn } = await response.json()
    return {
      ssn: '123-45-6789',
    }
  },
  // highlight-start
  transform: {
    display: {
      output: () => ({ ssn: '***-**-****' }),
    },
    transcript: {
      output: () => ({ ssn: '***-**-****' }),
    },
  },
  // highlight-end
})
```

您的应用程序代码仍然会收到原始数据`ssn` from the tool. Browser-facing streams get the `display` output, and user-visible transcript messages get the `transcript` output.

当 DurableAgent 可以在进程重新启动后完成Tool调用时，请在Tool的`transform.transcript` configuration. A per-invocation transform passed to the DurableAgent lives in the in-process run registry and can't be recovered in a fresh process. The durable worker re-resolves the tool-level transform from the registered tool.

对于更多阶段，包括`input`, `inputDelta`, `error`, `approval`, `suspend`, and `resume`, see the [`createTool()` reference](/reference/tools/create-tool#example-with-transform). For shared rules across several tools, configure the agent-level `transform` policy in the [`Agent` constructor](/reference/agents/agent#constructor-parameters).

## 围绕Tool调用运行逻辑 {/* #run-logic-around-tool-calls */}

使用`hooks` to run custom logic before and after every tool call an agent makes. Hooks apply to all tool sources: assigned tools, memory tools, toolsets, client tools, agent and workflow tools, and [workspace tools](/reference/workspace/workspace-class#tool-hooks). Common uses include logging, auditing, input validation, and blocking specific calls.

```typescript title="src/mastra/agents/support-agent.ts"
import { Agent } from '@mastra/core/agent'
import { db } from '../db' // your application database client

export const supportAgent = new Agent({
  id: 'support-agent',
  name: 'support-agent',
  instructions: 'Help users with their questions.',
  model: '__GATEWAY_OPENAI_MODEL__',
  // highlight-start
  hooks: {
    beforeToolCall: ({ toolName, input }) => {
      console.log(`Running ${toolName}`, input)
    },
    afterToolCall: async ({ toolName, input, output, error }) => {
      await db.auditLog.insert({
        toolName,
        input,
        output,
        error: error ? String(error) : undefined,
      })
    },
  },
  // highlight-end
})
```

`afterToolCall`必须返回`void` (or `Promise<void>`). Await your storage call, but don't return its result. If the storage call throws, the tool call fails with that error, so catch it inside the hook if audit logging should be best-effort. `afterToolCall` doesn't run for calls skipped by `beforeToolCall` or for declined [pre-execution approvals](/docs/agents/human-in-the-loop#pre-execution-approval), so record those decisions where you handle them.

`beforeToolCall`在Tool执行之前运行并接收Tool名称、输入和执行上下文。返回`{ proceed: false, output }` to skip the tool call entirely, the agent receives `output` as the tool result:

```typescript
const guardedAgent = new Agent({
  id: 'guarded-agent',
  name: 'guarded-agent',
  instructions: 'Run shell commands for the user.',
  model: '__GATEWAY_OPENAI_MODEL__',
  hooks: {
    beforeToolCall: ({ toolName, input }) => {
      const command = (input as { command?: string }).command ?? ''
      if (toolName === 'execute_command' && command.includes('rm -rf')) {
        return { proceed: false, output: 'Command blocked by policy.' }
      }
    },
  },
})
```

`afterToolCall`Tool完成后运行，无论成功还是失败。成功后会收到`output`; if the tool threw, it receives `error` instead and the error is re-thrown after the hook runs.

### 每次执行挂钩 {/* #per-execution-hooks */}

经过`hooks` to `.generate()` or `.stream()` to set hooks for a single execution. Per-execution hooks override matching agent-level hooks:

```typescript
await supportAgent.generate('Look up the order status', {
  hooks: {
    beforeToolCall: ({ toolName }) => {
      console.log(`This run only: ${toolName}`)
    },
  },
})
```

Agent级和每次执行挂钩按键合并：仅传递`beforeToolCall` at execution time keeps the agent-level `afterToolCall`.

## 流媒体 {/* #streaming */}

Tool支持生命周期挂钩，使您可以在流式传输期间监视Tool执行的不同阶段。这些钩子对于日志记录或分析特别有用。

对于通用的`writer` API usage, see [Streaming](/docs/guides/streaming#writer-api).

### 可用的挂钩 {/* #available-hooks */}

* **输入开始时**：当Tool调用输入流开始时调用
* **onInputDelta**：在输入的每个块流入时调用
* **输入可用时**：在解析和验证完整输入时调用
* **输出**：Tool成功执行并输出后调用

有关所有生命周期挂钩的详细文档，请参阅[createTool() reference](/reference/tools/create-tool#tool-lifecycle-hooks).

### 示例：使用`onInputAvailable` and `onOutput` {/* #example-using-oninputavailable-and-onoutput */}

```typescript
import { createTool } from '@mastra/core/tools'
import { z } from 'zod'

export const weatherTool = createTool({
  id: 'weather-tool',
  description: 'Get weather information',
  inputSchema: z.object({
    location: z.string(),
  }),
  outputSchema: z.object({
    location: z.string(),
    temperatureCelsius: z.number(),
    conditions: z.string(),
  }),
  // Called when the complete input is available
  onInputAvailable: ({ input, toolCallId }) => {
    console.log(`Weather requested for: ${input.location}`)
  },
  execute: async ({ location }) => {
    const weather = await fetchWeather(location)
    return weather
  },
  // Called after successful execution
  onOutput: ({ output, toolName }) => {
    console.log(`${toolName} result: ${output.temperatureCelsius}°C, ${output.conditions}`)
  },
})
```

### UI 中的流式Tool输入 {/* #streaming-tool-input-in-uis */}

当模型生成Tool调用时，参数逐渐到达`tool-call-delta` stream chunks before the final `tool-call` chunk. UIs can listen for the corresponding `tool_input_start`, `tool_input_delta`, and `tool_input_end` events to render tool arguments as they stream in, for example, showing a file path or command immediately rather than waiting for the complete tool call.

对累积的数据使用部分 JSON 解析器`argsTextDelta` fragments lets you extract usable argument values before the JSON is complete. It enables features like live diff previews for edit tools, streaming file content for write tools, and instant display of search patterns or file paths.

## 控制Tool选择 {/* #control-tool-selection */}

```typescript
await agent.generate('Check the forecast', {

  activeTools: ['weatherTool'],

```

## 控制`toolName` in stream responses {/* #control-toolname-in-stream-responses */}

这`toolName` in stream responses is determined by the **object key** you use, not the `id` property of the tool, agent, or workflow.

```typescript oxfmt:false
export const weatherTool = createTool({
  id: 'weather-tool',
})

// Using the variable name as the key
tools: { weatherTool }
// Stream returns: toolName: "weatherTool"

// Using the tool's id as the key
tools: { [weatherTool.id]: weatherTool }
// Stream returns: toolName: "weather-tool"

// Using a custom key
tools: { "my-custom-name": weatherTool }
// Stream returns: toolName: "my-custom-name"
```

这使您可以指定如何在流中识别Tool。如果你想要`toolName` to match the tool's `id`, use the tool's `id` as the object key.

### 作为Tool的子Agent和Workflow程 {/* #subagents-and-workflows-as-tools */}

子Agent和Workflow程遵循相同的模式。它们被转换为带有前缀的Tool，后跟您的对象键：

|物业 |前缀|示例键|`toolName` |
| - | - | - | - |
| `agents` | `agent-` | `weather` | `agent-weather` |
| `workflows` | `workflow-` | `research` | `workflow-research` |

```typescript
const orchestrator = new Agent({
  id: 'orchestrator',
  agents: {
    weather: weatherAgent, // toolName: "agent-weather"
  },
  workflows: {
    research: researchWorkflow, // toolName: "workflow-research"
  },
})
```

请注意，对于子Agent，您将在流响应中看到两个不同的标识符：

* `toolName: "agent-weather"`在Tool调用事件中：生成的Tool包装器名称
* `id: "weather-agent"`在`data-tool-agent` chunks: the subagent's actual `id` property

## 内置Tool {/* #built-in-tools */}

Mastra 包括与Agent无关的内置Tool`@mastra/core/tools` that add interactive and organizational capabilities to any agent.

每个Tool都有两个名称：您导入的导出以及模型在Tool调用、跟踪和Tool中看到的Tool ID`toolName` fields.

|出口|ToolID |目的|
| - | - | - |
|`askUserTool` | `ask_user` | Ask the user a question and wait for their answer |
| `submitPlanTool` | `submit_plan` | Submit a plan file for user approval |
| `taskWriteTool` | `task_write` | Create or replace a structured task list |
| `taskUpdateTool` | `task_update` | Update one tracked task by ID |
| `taskCompleteTool` | `task_complete` | Mark one tracked task completed |
| `taskCheckTool` | `task_check` | Check task list completion status |
| `webSearchTool` | `<provider.defined>` | Run the active provider's native web search |
| `webFetchTool` | `web_fetch` | Fetch a web page by URL and return its text content |

### 使用Provider网络搜索 {/* #use-provider-web-search */}

进口`webSearchTool` from `@mastra/core/tools` when you want the model provider to run its native web search tool. Mastra resolves it at run time from the active model, then passes the provider-managed tool to the model.

```typescript {2,10} title="src/mastra/agents/research-agent.ts"
import { Agent } from '@mastra/core/agent'
import { webSearchTool } from '@mastra/core/tools'

export const researchAgent = new Agent({
  id: 'research-agent',
  name: 'Research Agent',
  instructions: 'Use web search when you need current information.',
  model: 'openai/gpt-5.6-sol',
  tools: {
    search: webSearchTool,
  },
})
```

`webSearchTool`支持 OpenAI、Anthropic、Google Gemini 和 xAI 模型。如果 Mastra 无法从活动模型推断出这些提供者之一，则Agent运行失败并显示`MastraError`.

解析后的ToolID来自提供者：`openai.web_search`, `anthropic.web_search_20250305`, `google.google_search`, or `xai.web_search`.

通过 Mastra 网关提供服务的模型，例如`mastra/openai/gpt-5.6-sol`, use the gateway's own web search (`openrouter.web_search`) instead. Results from gateway web search arrive in the model's text response, without separate tool-call or source chunks. Other provider-native tools aren't available through the gateway, so passing one makes the agent run fail with a `MastraError`.

这`search` key is only the agent-local tool name. Use any key. The `webSearchTool` value tells Mastra to use provider web search.

### 获取网页 {/* #fetch-a-web-page */}

进口`webFetchTool` from `@mastra/core/tools` when the agent needs to read a specific URL. The tool requests the page over HTTP or HTTPS and returns its text content plus response metadata.

```typescript {2,10} title="src/mastra/agents/reader-agent.ts"
import { Agent } from '@mastra/core/agent'
import { webFetchTool } from '@mastra/core/tools'

export const readerAgent = new Agent({
  id: 'reader-agent',
  name: 'Reader Agent',
  instructions: 'Fetch the page the user links to before answering.',
  model: 'openai/gpt-5.6-sol',
  tools: {
    fetch: webFetchTool,
  },
})
```

该Tool需要一个`url` input and returns `content`, `truncated`, `status`, `statusText`, `contentType`, `url`, and `ok`. It applies these limits:

* 仅有的`http:` and `https:` URLs are allowed.
* 要求`localhost` and to private or reserved IP addresses are blocked, including addresses returned by DNS resolution.
* 响应被截断为 100,000 个字符，其中`truncated: true` in the result.
* 请求最多遵循 5 次重定向，并在 15 秒后超时。

失败不会抛出。Tool返回`isError: true` with the reason in `content`, so the agent can retry or explain the problem.

### 向用户提问 {/* #ask-the-user-a-question */}

进口[`askUserTool`](/reference/tools/ask-user-tool) and add it to the agent's toolset.

该Tool暂停运行并发出`tool-call-suspended` event with the question. It resumes when you call `resumeStream()` with the user's answer.

```typescript title="src/mastra/agents/index.ts"
import { Agent } from '@mastra/core/agent'
import { askUserTool } from '@mastra/core/tools'

const agent = new Agent({
  id: 'assistant',
  name: 'Assistant',
  instructions: 'Ask the user for clarification when the request is ambiguous.',
  model,
  tools: { askUserTool },
})
```

流式传输Agent并观看`tool-call-suspended` chunks. The `suspendPayload` contains the question and optional structured choices:

```typescript title="src/run.ts"
const stream = await agent.stream('Summarize my project')

for await (const chunk of stream.fullStream) {
  if (chunk.type === 'tool-call-suspended') {
    const { question, options } = chunk.payload.suspendPayload
    console.log(question)
    const answer = await getUserAnswer() // your UI logic
    const resumed = await agent.resumeStream(answer, { runId: stream.runId })
    for await (const c of resumed.textStream) process.stdout.write(c)
  }
}
```

`askUserTool`支持自由文本、单选（`options` array), and multi-select (`selectionMode: 'multi_select'`) prompts. Pair it with `autoResumeSuspendedTools` so the agent resumes automatically from the user's next chat message. See [Automatic tool resumption](/docs/agents/human-in-the-loop#automatic-tool-resumption) for details.

### 提交计划供审查 {/* #submit-a-plan-for-review */}

进口[`submitPlanTool`](/reference/tools/submit-plan-tool) to let the agent write a plan to a file and submit it for user review. The tool suspends the run until the user approves or rejects:

```typescript title="src/run.ts"
for await (const chunk of stream.fullStream) {
  if (chunk.type === 'tool-call-suspended' && chunk.payload.toolName === 'submit_plan') {
    const { path } = chunk.payload.suspendPayload
    // Read and display the plan file, then resume:
    const resumed = await agent.resumeStream({ action: 'approved' }, { runId: stream.runId })
    for await (const c of resumed.textStream) process.stdout.write(c)
  }
}
```

### 任务追踪 {/* #task-tracking */}

任务Tool管理Agent运行的结构化、持久的任务列表。他们需要[Memory](/docs/memory/overview) so the list is persisted in a thread-scoped store.

通过添加任务跟踪[`TaskSignalProvider`](/reference/signals/task-signal-provider), which bundles all four tools and the `TaskStateProcessor` in a single registration:

```typescript title="src/mastra/agents/index.ts"
import { Agent } from '@mastra/core/agent'
import { Memory } from '@mastra/memory'
import { TaskSignalProvider } from '@mastra/core/signals'

const agent = new Agent({
  id: 'coder',
  name: 'Coder',
  instructions: 'Track your progress with the task tools.',
  model,
  memory: new Memory(),
  signals: [new TaskSignalProvider()],
})
```

只能执行一项任务`in_progress` at a time. The list is stored in the thread-scoped `threadState` storage domain and projected onto the agent's [state-signal](/docs/signals/state-signals) lane, so it survives observational-memory truncation. See the [Task tools reference](/reference/tools/task-tools) for full schemas.

这[AgentController](/docs/harness/agent-controller) automatically includes all built-in tools in every mode, you don't need to add them manually. See [Tool approvals](/docs/harness/agent-controller#approve-tools-and-resume-suspensions) for AgentController-specific behavior.
