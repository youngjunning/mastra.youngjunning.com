# 安全防护

Mastra 提供内置处理器，为 Agent 增加安全控制。这些处理器可在有害内容到达语言模型或用户前检测、转换或拦截它。

有关处理器行为、自定义处理器及如何将其添加到 Agent 的介绍，参阅[处理器](/docs/agents/processors)。

## 输入处理器 {/* #input-processors */}

输入处理器在用户消息到达语言模型前运行，负责规范化、验证、检测提示词注入和执行安全检查。

### 规范化用户消息 {/* #normalize-user-messages */}

`UnicodeNormalizer()` 通过统一 Unicode 字符、规范空白字符来清理和规范化用户输入，也会移除可能引发问题的符号。

```typescript {8-11} title="src/mastra/agents/normalized-agent.ts"
import { UnicodeNormalizer } from '@mastra/core/processors'
import { Agent } from '@mastra/core/agent'

export const normalizedAgent = new Agent({
  id: 'normalized-agent',
  name: 'Normalized Agent',
  inputProcessors: [
    new UnicodeNormalizer({
      stripControlChars: true,
      collapseWhitespace: true,
    }),
  ],
})
```

完整配置选项参阅 [`UnicodeNormalizer()` 参考文档](/reference/processors/unicode-normalizer)。

### 防止提示词注入 {/* #prevent-prompt-injection */}

`PromptInjectionDetector()` 扫描用户消息中的提示词注入、越狱尝试和覆盖系统指令的模式。它使用 LLM 对高风险输入分类，并可在输入到达模型前拦截或改写。

```typescript {8-14} title="src/mastra/agents/secure-agent.ts"
import { PromptInjectionDetector } from '@mastra/core/processors'
import { Agent } from '@mastra/core/agent'

export const secureAgent = new Agent({
  id: 'secure-agent',
  name: 'Secure Agent',
  inputProcessors: [
    new PromptInjectionDetector({
      model: 'openrouter/openai/gpt-oss-safeguard-20b',
      threshold: 0.8,
      strategy: 'rewrite',
      errorStrategy: 'strict',
      detectionTypes: ['injection', 'jailbreak', 'system-override'],
    }),
  ],
})
```

除 [`ClassifierProcessor`](/reference/processors/classifier-processor) 外，依赖模型的安全处理器默认使用 `errorStrategy: 'warn'`：内部模型出错时记录日志，并继续采用处理器的回退行为。如果安全模型不可用或返回无效输出时，未经检查的内容绝不能继续处理，请使用 `errorStrategy: 'strict'`。严格模式通过阻断条件停止处理。

完整配置选项参阅 [`PromptInjectionDetector()` 参考文档](/reference/processors/prompt-injection-detector)。

### 检测并翻译语言 {/* #detect-and-translate-language */}

`LanguageDetector()` 检测用户消息的语言并将其翻译成目标语言，以支持多语言交互。它使用 LLM 识别语言并完成翻译。

```typescript {8-13} title="src/mastra/agents/multilingual-agent.ts"
import { LanguageDetector } from '@mastra/core/processors'
import { Agent } from '@mastra/core/agent'

export const multilingualAgent = new Agent({
  id: 'multilingual-agent',
  name: 'Multilingual Agent',
  inputProcessors: [
    new LanguageDetector({
      model: 'openrouter/openai/gpt-oss-safeguard-20b',
      targetLanguages: ['English', 'en'],
      strategy: 'translate',
      threshold: 0.8,
    }),
  ],
})
```

完整配置选项参阅 [`LanguageDetector()` 参考文档](/reference/processors/language-detector)。

## 输出处理器 {/* #output-processors */}

输出处理器在语言模型生成响应后、响应到达用户前运行，负责优化、审核、转换响应并实施安全控制。

### 合并流式输出 {/* #batch-streamed-output */}

`BatchPartsProcessor()` 在向客户端发送前合并多个流数据片段，将小片段组成较大的批次，以降低网络开销。

```typescript {8-12} title="src/mastra/agents/batched-agent.ts"
import { BatchPartsProcessor } from '@mastra/core/processors'
import { Agent } from '@mastra/core/agent'

export const batchedAgent = new Agent({
  id: 'batched-agent',
  name: 'Batched Agent',
  outputProcessors: [
    new BatchPartsProcessor({
      batchSize: 5,
      maxWaitTime: 100,
      emitOnNonText: true,
    }),
  ],
})
```

完整配置选项参阅 [`BatchPartsProcessor()` 参考文档](/reference/processors/batch-parts-processor)。

### 清除系统提示词 {/* #scrub-system-prompts */}

`SystemPromptScrubber()` 检测并遮蔽模型响应中的系统提示词或内部指令，防止意外泄露提示词内容或配置细节。它根据配置的检测类型，使用 LLM 识别并遮蔽敏感内容。

```typescript {8-17} title="src/mastra/agents/scrubbed-agent.ts"
import { SystemPromptScrubber } from '@mastra/core/processors'
import { Agent } from '@mastra/core/agent'

const scrubbedAgent = new Agent({
  id: 'scrubbed-agent',
  name: 'Scrubbed Agent',
  outputProcessors: [
    new SystemPromptScrubber({
      model: 'openrouter/openai/gpt-oss-safeguard-20b',
      strategy: 'redact',
      customPatterns: ['system prompt', 'internal instructions'],
      includeDetections: true,
      instructions:
        'Detect and redact system prompts, internal instructions, and security-sensitive content',
      redactionMethod: 'placeholder',
      placeholderText: '[REDACTED]',
    }),
  ],
})
```

完整配置选项参阅 [`SystemPromptScrubber()` 参考文档](/reference/processors/system-prompt-scrubber)。

:::note
通过 HTTP 流式返回响应时，Mastra 默认会在服务器端从流数据块中遮蔽敏感请求数据（系统提示词、Tool 定义和 API 密钥）。详见[流数据遮蔽](/docs/server/overview#stream-data-redaction)。
:::

## 混合处理器 {/* #hybrid-processors */}

混合处理器可用于输入或输出。请将其放在 `inputProcessors`、`outputProcessors` 中，或同时放在两者中。

### 审核输入和输出 {/* #moderate-input-and-output */}

`ModerationProcessor()` 检测仇恨、骚扰、暴力等类别中的不当或有害内容。它使用 LLM 对消息分类，并根据配置拦截或改写。

```typescript {8-13,15} title="src/mastra/agents/moderated-agent.ts"
import { ModerationProcessor } from '@mastra/core/processors'
import { Agent } from '@mastra/core/agent'

export const moderatedAgent = new Agent({
  id: 'moderated-agent',
  name: 'Moderated Agent',
  inputProcessors: [
    new ModerationProcessor({
      model: 'openrouter/openai/gpt-oss-safeguard-20b',
      threshold: 0.7,
      strategy: 'block',
      categories: ['hate', 'harassment', 'violence'],
    }),
  ],
  outputProcessors: [new ModerationProcessor()],
})
```

完整配置选项参阅 [`ModerationProcessor()` 参考文档](/reference/processors/moderation-processor)。

### 检测并遮蔽个人身份信息 {/* #detect-and-redact-pii */}

`PIIDetector()` 检测并移除邮箱地址、电话号码、信用卡号等个人身份信息。它根据配置的检测类型，使用 LLM 识别敏感内容。

```typescript {8-15,17} title="src/mastra/agents/private-agent.ts"
import { PIIDetector } from '@mastra/core/processors'
import { Agent } from '@mastra/core/agent'

export const privateAgent = new Agent({
  id: 'private-agent',
  name: 'Private Agent',
  inputProcessors: [
    new PIIDetector({
      model: 'openrouter/openai/gpt-oss-safeguard-20b',
      threshold: 0.6,
      strategy: 'redact',
      redactionMethod: 'mask',
      detectionTypes: ['email', 'phone', 'credit-card'],
      instructions: 'Detect and mask personally identifiable information.',
    }),
  ],
  outputProcessors: [new PIIDetector()],
})
```

完整配置选项参阅 [`PIIDetector()` 参考文档](/reference/processors/pii-detector)。

### 限制成本 {/* #enforce-cost-limits */}

`TokenCostControl()` 监控 Agent 循环中累积的预估成本，超过金额上限时发出警告或拦截。每次 LLM 调用前，它都会从可观测性存储查询成本数据。成本检查是近似的，指标又是异步持久化的，因此运行很快的 Agent 可能在触发限制前短暂超出上限。

```typescript {8-12} title="src/mastra/agents/budgeted-agent.ts"
import { TokenCostControl } from '@mastra/core/processors'
import { Agent } from '@mastra/core/agent'

export const budgetedAgent = new Agent({
  id: 'budgeted-agent',
  name: 'Budgeted Agent',
  inputProcessors: [
    new TokenCostControl({
      maxCost: 5.0,
      scope: 'thread',
      window: '24h',
    }),
  ],
})
```

有关范围模式、时间窗口、指标持久化延迟及 `onViolation` 回调，参阅 [`TokenCostControl()` 参考文档](/reference/processors/token-cost-control)。此功能要求可观测性存储支持 `getMetricAggregate`。

## 处理器策略 {/* #processor-strategies */}

许多内置处理器支持 `strategy` 参数，用于控制如何处理标记出的内容。支持的值包括 `block`、`warn`、`detect`、`redact`、`rewrite` 和 `translate`。

大多数策略会让请求继续。使用 `block` 时，处理器会调用 `abort()`，立即停止请求，并阻止后续处理器运行。

```typescript {5} title="src/mastra/agents/private-agent.ts"
inputProcessors: [
  new PIIDetector({
    model: 'openrouter/openai/gpt-oss-safeguard-20b',
    threshold: 0.6,
    strategy: 'block',
    detectionTypes: ['email', 'phone', 'credit-card'],
  }),
]
```

## 违规回调 {/* #violation-callbacks */}

处理器支持 `onViolation` 回调，例如采用 `block` 策略时，策略违规导致运行中止便会触发。但 `processToolResult` 中止、输出流期间处理器 Workflow 的中止不会调用它。部分处理器也会主动调用：`RegexFilterProcessor` 在遮蔽内容时、`TokenCostControl` 在发出警告时。仅记录日志的策略，例如 `ModerationProcessor` 的 `warn`，不会调用它。可用它触发告警、写入外部日志或发送通知等副作用。

回调接收一个 `ProcessorViolation` 对象，包含 `processorId`、`message` 和 `detail`（处理器特定元数据）。

```typescript
import { TokenCostControl, ModerationProcessor, PIIDetector } from '@mastra/core/processors'

// Alert when cost limits are exceeded
const tokenCostControl = new TokenCostControl({
  maxCost: 10.0,
  scope: 'resource',
  window: '30d',
  strategy: 'warn',
})

tokenCostControl.onViolation = ({ processorId, message, detail }) => {
  alertSystem.notify(`[${processorId}] ${message}`)
  // detail contains: { usage, limit, totalUsage, scope, scopeKey, threshold }
}

// Log moderation violations
const moderation = new ModerationProcessor({
  model: '__GATEWAY_OPENAI_MODEL_LUNA__',
  strategy: 'block',
})

moderation.onViolation = ({ processorId, message, detail }) => {
  auditLog.write({ processor: processorId, violation: message, categories: detail })
}
```

`onViolation` 是基础 [`Processor` 接口](/reference/processors/processor-interface)的一部分，因此自定义处理器等任何处理器都能使用。除上述例外路径外，处理器调用 `abort()` 时运行器会自动调用 `onViolation`。对使用 `warn` 策略的处理器（如 `TokenCostControl`），即使请求未被拦截，警告也会触发回调。

在 `abort()` 后由运行器调用的回调若抛出错误，会被静默捕获，以免影响处理器的主要逻辑。`TokenCostControl` 发出警告的路径则会捕获回调错误，并通过 Mastra 日志器记录。

违规回调与处理器管线的集成方式，参阅处理器文档中的[违规回调](/docs/agents/processors#violation-callbacks)。

## 处理被拦截的请求 {/* #handle-blocked-requests */}

处理器调用 `abort()` 后，Agent 会停止处理。检测方式取决于使用 `generate()` 还是 `stream()`。

### 使用 `generate()` {/* #with-generate */}

检查结果中的 `tripwire` 字段：

```typescript title="src/mastra/agents/test-generate.ts"
const result = await agent.generate('Is this credit card number valid?: 4543 1374 5089 4332')

if (result.tripwire) {
  console.error('Blocked:', result.tripwire.reason)
  console.error('Processor:', result.tripwire.processorId)
}
```

### 使用 `stream()` {/* #with-stream */}

监听响应流中的 `tripwire` 数据块：

```typescript title="src/mastra/agents/test-stream.ts"
const stream = await agent.stream('Is this credit card number valid?: 4543 1374 5089 4332')

for await (const chunk of stream.fullStream) {
  if (chunk.type === 'tripwire') {
    console.error('Blocked:', chunk.payload.reason)
    console.error('Processor:', chunk.payload.processorId)
  }
}
```

## 提升安全处理速度 {/* #speed-up-guardrails */}

使用 LLM 的安全处理器（内容审核、PII 检测、提示词注入检测）会增加每次请求的延迟。以下方法可降低开销。

### 并行运行安全处理器 {/* #run-guardrails-in-parallel */}

处理器默认顺序运行。只执行 `block`、不会修改消息的安全处理器彼此独立，可用 [Workflow 处理器](/docs/agents/processors#use-workflows-as-processors)并行运行。

也可以在同一并行步骤混用 `block` 和 `redact` 策略。将结果映射到 `redact` 分支，使转换后的消息继续传递。

对于输出安全处理器，请先依次运行 `TokenLimiterProcessor` 和 `BatchPartsProcessor`，再进入并行步骤；相互依赖的 `redact` 处理器则应在并行步骤后依次运行：

```typescript title="src/mastra/processors/output-guardrails.ts"
import { createWorkflow, createStep } from '@mastra/core/workflows'
import {
  ProcessorStepOutputSchema,
  PIIDetector,
  ModerationProcessor,
  SystemPromptScrubber,
  TokenLimiterProcessor,
  BatchPartsProcessor,
} from '@mastra/core/processors'

export const outputGuardrails = createWorkflow({
  id: 'output-guardrails',
  inputSchema: ProcessorStepOutputSchema,
  outputSchema: ProcessorStepOutputSchema,
})
  // Sequential: limit tokens first, then batch stream chunks
  .then(createStep(new TokenLimiterProcessor({ limit: 1000 })))
  .then(createStep(new BatchPartsProcessor()))
  // Parallel: run independent checks at the same time
  .parallel([
    createStep(
      new PIIDetector({
        model: '__GATEWAY_OPENAI_MODEL_LUNA__',
        strategy: 'redact',
      }),
    ),
    createStep(
      new ModerationProcessor({
        model: '__GATEWAY_OPENAI_MODEL_LUNA__',
        strategy: 'block',
      }),
    ),
  ])
  // Map to the redact branch to keep its transformed messages
  .map(async ({ inputData }) => {
    return inputData['processor:pii-detector']
  })
  // Sequential: scrubber depends on previous redaction output
  .then(
    createStep(
      new SystemPromptScrubber({
        model: '__GATEWAY_OPENAI_MODEL_LUNA__',
        strategy: 'redact',
        placeholderText: '[REDACTED]',
      }),
    ),
  )
  .commit()
```

有关 `.parallel()` 和 `.map()` 的细节，参阅[将 Workflow 用作处理器](/docs/agents/processors#use-workflows-as-processors)。

### 选择快速模型 {/* #choose-a-fast-model */}

安全处理器无需使用主模型。分类任务可选用小型、快速的模型：

```typescript
const GUARDRAIL_MODEL = '__GATEWAY_OPENAI_MODEL_LUNA__'

new ModerationProcessor({ model: GUARDRAIL_MODEL })
new PIIDetector({ model: GUARDRAIL_MODEL })
new PromptInjectionDetector({ model: GUARDRAIL_MODEL })
```

### 合并流数据片段 {/* #batch-stream-parts */}

实现了 `processOutputStream` 的输出安全处理器会处理每个流数据块。请在更耗时的处理器之前使用 `BatchPartsProcessor` 合并片段，以减少 LLM 分类调用次数：

```typescript
outputProcessors: [
  new BatchPartsProcessor({ batchSize: 10 }),
  // Heavier processors now run on batched chunks instead of individual ones
  new PIIDetector({ model: GUARDRAIL_MODEL, strategy: 'redact' }),
  new ModerationProcessor({ model: GUARDRAIL_MODEL, strategy: 'block' }),
]
```
