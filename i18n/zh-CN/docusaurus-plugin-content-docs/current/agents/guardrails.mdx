# 护栏

Mastra 提供内置处理器，为您的Agent添加安全控制。这些处理器在有害内容到达语言模型或用户之前对其进行检测、转换或阻止。

有关处理器行为和自定义处理器的介绍，包括如何将它们添加到Agent，请参阅[Processors](/docs/agents/processors).

## 输入处理器 {/* #input-processors */}

输入处理器在用户消息到达语言模型之前运行。它们处理规范化、验证、提示注入检测和安全检查。

### 规范化用户消息 {/* #normalize-user-messages */}

这`UnicodeNormalizer()` cleans and normalizes user input by unifying Unicode characters and standardizing whitespace. It also removes problematic symbols.

```typescript {8-11} title="src/mastra/agents/normalized-agent.ts"
import { UnicodeNormalizer } from '@mastra/core/processors'
import { Agent } from '@mastra/core/agent'

export const normalizedAgent = new Agent({
  id: 'normalized-agent',
  name: 'Normalized Agent',
  inputProcessors: [
    new UnicodeNormalizer({
      stripControlChars: true,
      collapseWhitespace: true,
    }),
  ],
})
```

访问[`UnicodeNormalizer()`](/reference/processors/unicode-normalizer) reference for a full list of configuration options.

### 防止提示注入 {/* #prevent-prompt-injection */}

这`PromptInjectionDetector()` scans user messages for prompt injection, jailbreak attempts, and system override patterns. It uses an LLM to classify risky input and can block or rewrite it before it reaches the model.

```typescript {8-14} title="src/mastra/agents/secure-agent.ts"
import { PromptInjectionDetector } from '@mastra/core/processors'
import { Agent } from '@mastra/core/agent'

export const secureAgent = new Agent({
  id: 'secure-agent',
  name: 'Secure Agent',
  inputProcessors: [
    new PromptInjectionDetector({
      model: 'openrouter/openai/gpt-oss-safeguard-20b',
      threshold: 0.8,
      strategy: 'rewrite',
      errorStrategy: 'strict',
      detectionTypes: ['injection', 'jailbreak', 'system-override'],
    }),
  ],
})
```

模型支持的护栏处理器，除了[`ClassifierProcessor`](/reference/processors/classifier-processor) default to `errorStrategy: 'warn'`, which logs internal model failures and continues with the processor's fallback. Use `errorStrategy: 'strict'` when unchecked content must not proceed if the guardrail model is unavailable or returns invalid output. Strict mode stops processing with a tripwire.

访问[`PromptInjectionDetector()`](/reference/processors/prompt-injection-detector) reference for a full list of configuration options.

### 检测并翻译语言 {/* #detect-and-translate-language */}

这`LanguageDetector()` detects and translates user messages into a target language, enabling multilingual support. It uses an LLM to identify the language and perform the translation.

```typescript {8-13} title="src/mastra/agents/multilingual-agent.ts"
import { LanguageDetector } from '@mastra/core/processors'
import { Agent } from '@mastra/core/agent'

export const multilingualAgent = new Agent({
  id: 'multilingual-agent',
  name: 'Multilingual Agent',
  inputProcessors: [
    new LanguageDetector({
      model: 'openrouter/openai/gpt-oss-safeguard-20b',
      targetLanguages: ['English', 'en'],
      strategy: 'translate',
      threshold: 0.8,
    }),
  ],
})
```

访问[`LanguageDetector()`](/reference/processors/language-detector) reference for a full list of configuration options.

## 输出处理器 {/* #output-processors */}

输出处理器在语言模型生成响应之后、到达用户之前运行。他们处理响应优化、调节、转换和安全控制。

### 批量流式输出 {/* #batch-streamed-output */}

这`BatchPartsProcessor()` combines multiple stream parts before emitting them to the client. This reduces network overhead by consolidating small chunks into larger batches.

```typescript {8-12} title="src/mastra/agents/batched-agent.ts"
import { BatchPartsProcessor } from '@mastra/core/processors'
import { Agent } from '@mastra/core/agent'

export const batchedAgent = new Agent({
  id: 'batched-agent',
  name: 'Batched Agent',
  outputProcessors: [
    new BatchPartsProcessor({
      batchSize: 5,
      maxWaitTime: 100,
      emitOnNonText: true,
    }),
  ],
})
```

访问[`BatchPartsProcessor()`](/reference/processors/batch-parts-processor) reference for a full list of configuration options.

### 擦洗系统提示 {/* #scrub-system-prompts */}

这`SystemPromptScrubber()` detects and redacts system prompts or internal instructions from model responses. It prevents unintended disclosure of prompt content or configuration details. It uses an LLM to identify and redact sensitive content based on configured detection types.

```typescript {8-17} title="src/mastra/agents/scrubbed-agent.ts"
import { SystemPromptScrubber } from '@mastra/core/processors'
import { Agent } from '@mastra/core/agent'

const scrubbedAgent = new Agent({
  id: 'scrubbed-agent',
  name: 'Scrubbed Agent',
  outputProcessors: [
    new SystemPromptScrubber({
      model: 'openrouter/openai/gpt-oss-safeguard-20b',
      strategy: 'redact',
      customPatterns: ['system prompt', 'internal instructions'],
      includeDetections: true,
      instructions:
        'Detect and redact system prompts, internal instructions, and security-sensitive content',
      redactionMethod: 'placeholder',
      placeholderText: '[REDACTED]',
    }),
  ],
})
```

访问[`SystemPromptScrubber()`](/reference/processors/system-prompt-scrubber) reference for a full list of configuration options.

:::注意
当通过 HTTP 传输响应时，Mastra 默认会在服务器级别从流块中编辑敏感请求数据（系统提示、Tool定义、API 密钥）。看[Stream data redaction](/docs/server/overview#stream-data-redaction) for details.
:::

## 混合处理器 {/* #hybrid-processors */}

混合处理器可以在输入或输出上运行。将它们放入`inputProcessors`, `outputProcessors`, or both.

### 适度的输入和输出 {/* #moderate-input-and-output */}

这`ModerationProcessor()` detects inappropriate or harmful content across categories like hate, harassment, and violence. It uses an LLM to classify the message and can block or rewrite it based on your configuration.

```typescript {8-13,15} title="src/mastra/agents/moderated-agent.ts"
import { ModerationProcessor } from '@mastra/core/processors'
import { Agent } from '@mastra/core/agent'

export const moderatedAgent = new Agent({
  id: 'moderated-agent',
  name: 'Moderated Agent',
  inputProcessors: [
    new ModerationProcessor({
      model: 'openrouter/openai/gpt-oss-safeguard-20b',
      threshold: 0.7,
      strategy: 'block',
      categories: ['hate', 'harassment', 'violence'],
    }),
  ],
  outputProcessors: [new ModerationProcessor()],
})
```

访问[`ModerationProcessor()`](/reference/processors/moderation-processor) reference for a full list of configuration options.

### 检测并编辑 PII {/* #detect-and-redact-pii */}

这`PIIDetector()` detects and removes personally identifiable information such as emails, phone numbers, and credit cards. It uses an LLM to identify sensitive content based on configured detection types.

```typescript {8-15,17} title="src/mastra/agents/private-agent.ts"
import { PIIDetector } from '@mastra/core/processors'
import { Agent } from '@mastra/core/agent'

export const privateAgent = new Agent({
  id: 'private-agent',
  name: 'Private Agent',
  inputProcessors: [
    new PIIDetector({
      model: 'openrouter/openai/gpt-oss-safeguard-20b',
      threshold: 0.6,
      strategy: 'redact',
      redactionMethod: 'mask',
      detectionTypes: ['email', 'phone', 'credit-card'],
      instructions: 'Detect and mask personally identifiable information.',
    }),
  ],
  outputProcessors: [new PIIDetector()],
})
```

访问[`PIIDetector()`](/reference/processors/pii-detector) reference for a full list of configuration options.

### 实施成本限制 {/* #enforce-cost-limits */}

这`TokenCostControl()` monitors cumulative estimated cost across the agentic loop, blocking or warning when a monetary limit is exceeded. It queries cost data from observability storage before each LLM call. Cost checks are approximate, metrics are persisted asynchronously, so fast-running agents may briefly exceed the configured limit before the guard triggers.

```typescript {8-12} title="src/mastra/agents/budgeted-agent.ts"
import { TokenCostControl } from '@mastra/core/processors'
import { Agent } from '@mastra/core/agent'

export const budgetedAgent = new Agent({
  id: 'budgeted-agent',
  name: 'Budgeted Agent',
  inputProcessors: [
    new TokenCostControl({
      maxCost: 5.0,
      scope: 'thread',
      window: '24h',
    }),
  ],
})
```

访问[`TokenCostControl()`](/reference/processors/token-cost-control) reference for scoping modes, time windows, metric persistence delays, and the `onViolation` callback. Requires observability storage with `getMetricAggregate` support.

## 处理器策略 {/* #processor-strategies */}

许多内置处理器支持`strategy` parameter that controls how they handle flagged content. Supported values include: `block`, `warn`, `detect`, `redact`, `rewrite`, and `translate`.

大多数策略允许请求继续。什么时候`block` is used, the processor calls `abort()`, which stops the request immediately and prevents subsequent processors from running.

```typescript {5} title="src/mastra/agents/private-agent.ts"
inputProcessors: [
  new PIIDetector({
    model: 'openrouter/openai/gpt-oss-safeguard-20b',
    threshold: 0.6,
    strategy: 'block',
    detectionTypes: ['email', 'phone', 'credit-card'],
  }),
]
```

## 违规回调 {/* #violation-callbacks */}

处理器支持`onViolation` callback that fires when a policy violation aborts the run, for example with the `block` strategy. Aborts from `processToolResult`, and from processor workflows while streaming output, don't call it. Some processors also call it directly: `RegexFilterProcessor` when it redacts content, and `TokenCostControl` when it warns. Strategies that only log, such as `ModerationProcessor`'s `warn`, don't call it. Use it for side effects like alerting, logging to external systems, or sending notifications.

回调收到一个`ProcessorViolation` object with `processorId`, `message`, and `detail` (processor-specific metadata).

```typescript
import { TokenCostControl, ModerationProcessor, PIIDetector } from '@mastra/core/processors'

// Alert when cost limits are exceeded
const tokenCostControl = new TokenCostControl({
  maxCost: 10.0,
  scope: 'resource',
  window: '30d',
  strategy: 'warn',
})

tokenCostControl.onViolation = ({ processorId, message, detail }) => {
  alertSystem.notify(`[${processorId}] ${message}`)
  // detail contains: { usage, limit, totalUsage, scope, scopeKey, threshold }
}

// Log moderation violations
const moderation = new ModerationProcessor({
  model: '__GATEWAY_OPENAI_MODEL_LUNA__',
  strategy: 'block',
})

moderation.onViolation = ({ processorId, message, detail }) => {
  auditLog.write({ processor: processorId, violation: message, categories: detail })
}
```

这`onViolation` property is part of the base [`Processor` interface](/reference/processors/processor-interface), so any processor, including custom ones, can use it. The runner automatically invokes `onViolation` when a processor calls `abort()`, except on the paths noted above. For processors using a `warn` strategy (like `TokenCostControl`), the callback also fires on warnings without blocking the request.

之后运行程序调用的回调抛出的错误`abort()` are silently caught to prevent interfering with the processor's main logic. On the `TokenCostControl` warning path, callback errors are caught and logged through the Mastra logger.

有关违规回调如何与处理器管道集成的更多信息，请参阅[Violation callbacks](/docs/agents/processors#violation-callbacks) in the Processors documentation.

## 处理被阻止的请求 {/* #handle-blocked-requests */}

当处理器调用`abort()`, the agent stops processing. How you detect this depends on whether you use `generate()` or `stream()`.

### 和`generate()` {/* #with-generate */}

检查`tripwire` field on the result:

```typescript title="src/mastra/agents/test-generate.ts"
const result = await agent.generate('Is this credit card number valid?: 4543 1374 5089 4332')

if (result.tripwire) {
  console.error('Blocked:', result.tripwire.reason)
  console.error('Processor:', result.tripwire.processorId)
}
```

### 和`stream()` {/* #with-stream */}

听听`tripwire` chunks in the stream:

```typescript title="src/mastra/agents/test-stream.ts"
const stream = await agent.stream('Is this credit card number valid?: 4543 1374 5089 4332')

for await (const chunk of stream.fullStream) {
  if (chunk.type === 'tripwire') {
    console.error('Blocked:', chunk.payload.reason)
    console.error('Processor:', chunk.payload.processorId)
  }
}
```

## 加快护栏速度 {/* #speed-up-guardrails */}

使用 LLM（审核、PII 检测、提示注入）的 Guardrail 处理器会增加每个请求的延迟。这些技术减少了这种开销。

### 平行运行护栏 {/* #run-guardrails-in-parallel */}

默认情况下，处理器按顺序运行。护栏仅`block` (and never mutate messages) are independent and can run using a [workflow processor](/docs/agents/processors#use-workflows-as-processors).

你也可以混合`block` and `redact` strategies in a single parallel step. Map to the `redact` branch so its transformed messages carry forward.

对于输出护栏，运行`TokenLimiterProcessor` and `BatchPartsProcessor` sequentially *before* the parallel step, and any `redact` processors that depend on each other sequentially *after* it:

```typescript title="src/mastra/processors/output-guardrails.ts"
import { createWorkflow, createStep } from '@mastra/core/workflows'
import {
  ProcessorStepOutputSchema,
  PIIDetector,
  ModerationProcessor,
  SystemPromptScrubber,
  TokenLimiterProcessor,
  BatchPartsProcessor,
} from '@mastra/core/processors'

export const outputGuardrails = createWorkflow({
  id: 'output-guardrails',
  inputSchema: ProcessorStepOutputSchema,
  outputSchema: ProcessorStepOutputSchema,
})
  // Sequential: limit tokens first, then batch stream chunks
  .then(createStep(new TokenLimiterProcessor({ limit: 1000 })))
  .then(createStep(new BatchPartsProcessor()))
  // Parallel: run independent checks at the same time
  .parallel([
    createStep(
      new PIIDetector({
        model: '__GATEWAY_OPENAI_MODEL_LUNA__',
        strategy: 'redact',
      }),
    ),
    createStep(
      new ModerationProcessor({
        model: '__GATEWAY_OPENAI_MODEL_LUNA__',
        strategy: 'block',
      }),
    ),
  ])
  // Map to the redact branch to keep its transformed messages
  .map(async ({ inputData }) => {
    return inputData['processor:pii-detector']
  })
  // Sequential: scrubber depends on previous redaction output
  .then(
    createStep(
      new SystemPromptScrubber({
        model: '__GATEWAY_OPENAI_MODEL_LUNA__',
        strategy: 'redact',
        placeholderText: '[REDACTED]',
      }),
    ),
  )
  .commit()
```

看[workflows as processors](/docs/agents/processors#use-workflows-as-processors) for more details on `.parallel()` and `.map()`.

### 选择快速型号 {/* #choose-a-fast-model */}

Guardrail 处理器不需要您的主要模型。使用小型、快速的模型来执行分类任务：

```typescript
const GUARDRAIL_MODEL = '__GATEWAY_OPENAI_MODEL_LUNA__'

new ModerationProcessor({ model: GUARDRAIL_MODEL })
new PIIDetector({ model: GUARDRAIL_MODEL })
new PromptInjectionDetector({ model: GUARDRAIL_MODEL })
```

### 批流部分 {/* #batch-stream-parts */}

输出护栏实现`processOutputStream` run on every streamed chunk. Use `BatchPartsProcessor` *before* heavier processors to combine chunks and reduce the number of LLM classification calls:

```typescript
outputProcessors: [
  new BatchPartsProcessor({ batchSize: 10 }),
  // Heavier processors now run on batched chunks instead of individual ones
  new PIIDetector({ model: GUARDRAIL_MODEL, strategy: 'redact' }),
  new ModerationProcessor({ model: GUARDRAIL_MODEL, strategy: 'block' }),
]
```
