# 结构化输出

结构化输出让 Agent 返回符合 schema 定义的对象，而不是文本。schema 告诉模型应生成哪些字段，模型会让最终结果符合该结构。通过 `response.object` 读取经过校验且带类型的结果。

## 何时使用结构化输出 {/* #when-to-use-structured-output */}

需要 Agent 返回数据对象而非文本时，请使用结构化输出。字段定义清楚后，API 调用、界面渲染和应用逻辑都能更方便地提取所需的值。

## 定义 schema {/* #define-schemas */}

要让 Agent 返回结构化数据，可用 [Standard JSON Schema](https://standardschema.dev/json-schema)（[Zod](https://zod.dev/)、[Valibot](https://valibot.dev/)、[ArkType](https://arktype.io/) 等）或 [JSON Schema](https://json-schema.org/) 定义预期输出。推荐使用 Zod 等库，因为它们支持 TypeScript 类型推断和运行时校验；需要与编程语言无关的格式时，JSON Schema 更合适。

<Tabs>
  <TabItem value="zod" label="Zod">
    使用 [Zod](https://zod.dev/) 定义 `output` 的结构：

    ```typescript
    import { z } from 'zod'

    const response = await testAgent.generate('Help me plan my day.', {
      structuredOutput: {
        schema: z.array(
          z.object({
            name: z.string(),
            activities: z.array(z.string()),
          }),
        ),
      },
    })

    console.log(response.object)
    ```
  </TabItem>

  <TabItem value="valibot" label="Valibot">
    使用 [Valibot](https://valibot.dev/) 定义 `output` 的结构：

    ```typescript
    import * as v from 'valibot'
    import { toStandardJsonSchema } from '@valibot/to-json-schema'

    const response = await testAgent.generate('Help me plan my day.', {
      structuredOutput: {
        schema: toStandardJsonSchema(
          v.array(
            v.object({
              name: v.string(),
              activities: v.array(v.string()),
            }),
          ),
        ),
      },
    })

    console.log(response.object)
    ```
  </TabItem>

  <TabItem value="arktype" label="ArkType">
    使用 [ArkType](https://arktype.io/) 定义 `output` 的结构：

    ```typescript
    import { type } from 'arktype'

    const response = await testAgent.generate('Help me plan my day.', {
      structuredOutput: {
        schema: type({
          name: 'string',
          activities: 'string[]',
        }).array(),
      },
    })

    console.log(response.object)
    ```
  </TabItem>

  <TabItem value="json-schema" label="JSON Schema">
    也可以用 JSON Schema 定义输出结构：

    ```typescript
    const response = await testAgent.generate('Help me plan my day.', {
      structuredOutput: {
        schema: {
          type: 'array',
          items: {
            type: 'object',
            properties: {
              name: { type: 'string' },
              activities: {
                type: 'array',
                items: { type: 'string' },
              },
            },
            required: ['name', 'activities'],
          },
        },
      },
    })

    console.log(response.object)
    ```
  </TabItem>
</Tabs>

完整配置选项请参阅 [`.generate()`](/reference/agents/generate)。

**输出示例：**

```json
[
  {
    "name": "Morning Routine",
    "activities": ["Wake up at 7am", "Exercise", "Shower", "Breakfast"]
  },
  {
    "name": "Work",

  },
  {

    "activities": ["Dinner", "Relax", "Read a book", "Sleep by 10pm"]
  }
]
```

## 读取结果 {/* #read-the-result */}

将预期结构传给 `structuredOutput.schema`，然后从 `response.object` 读取结果。该字段已经过解析和 schema 校验，无须自行处理。例外是 `errorStrategy: 'fallback'`：校验失败时，`response.object` 会返回已配置的 `fallbackValue`，该值不会经过 schema 校验。检查 `response.usedFallbackValue` 即可区分这两种情况。

```typescript
const response = await testAgent.generate('Help me plan my day.', { structuredOutput: { schema } })
const plan = response.object // typed from the schema you passed in
```

使用 `agent.stream()` 生成结构化输出时，请等待流结束再读取 `stream.object`。

## 流式结构化输出 {/* #stream-structured-output */}

流式响应也支持结构化输出。最终的结构化对象会出现在 `stream.fullStream` 中，流结束后也可从 `stream.object` 读取。文本流仍会发出数据块，其中是自然语言文本，不是结构化数据。

```typescript
import { z } from 'zod'

const stream = await testAgent.stream('Help me plan my day.', {
  structuredOutput: {
    schema: z.array(
      z.object({
        name: z.string(),
        activities: z.array(z.string()),
      }),
    ),
  },
})

for await (const chunk of stream.fullStream) {
  if (chunk.type === 'object-result') {
    console.log('\n', JSON.stringify(chunk, null, 2))
  }
  process.stdout.write(JSON.stringify(chunk))
}

console.log(await stream.object)

for await (const chunk of stream.textStream) {
  process.stdout.write(chunk)
}
```

## 用第二个 Agent 整理输出 {/* #structuring-agent */}

如果主 Agent 不擅长生成结构化输出，可以向 `structuredOutput` 提供 `model`。Mastra 会在内部使用第二个 Agent，从主 Agent 的自然语言响应中提取结构化数据。这会调用 LLM 两次：一次生成响应，一次将响应转成结构化对象。这样会增加一些延迟和成本，但可提高复杂结构化任务的准确率。

```typescript
import { z } from 'zod'

const response = await testAgent.generate('Analyze the TypeScript programming language.', {
  structuredOutput: {
    schema: z.object({
      overview: z.string(),
      strengths: z.array(z.string()),
      weaknesses: z.array(z.string()),
      useCases: z.array(
        z.object({
          scenario: z.string(),
          reasoning: z.string(),
        }),
      ),
      comparison: z.object({
        similarTo: z.array(z.string()),
        differentiators: z.array(z.string()),
      }),
    }),
    model: '__GATEWAY_OPENAI_MODEL__',
  },
})

console.log(response.object)
```

## 同时使用工具和结构化输出 {/* #combine-tools-and-structured-output */}

如果 Agent 同时配置了工具和结构化输出，部分模型无法同时使用这两项功能。这取决于底层模型 API 的限制。

如果启用结构化输出后工具没有被调用，或同时使用两项功能时报错，请尝试下列方案。

### 可选方案 {/* #workaround-options */}

如果模型不支持同时使用工具和结构化输出，有三种方案：

1. **使用 `jsonPromptInjection`**：设为 `'auto'`，支持时使用原生结构化输出，否则使用内联提示词注入；也可直接指定注入模式。
1. **使用单独的结构化模型**：给 `structuredOutput` 传入 `model`，用第二个 LLM 整理输出结构。
1. **使用 `prepareStep`**：在不同步骤处理工具和结构化输出。

以下各节详细说明这些方案。

## LLM 对结构化输出的支持 {/* #llm-structured-output-support */}

各 LLM 的 API 不同，对结构化输出的支持也不同。以下各节介绍如何应对模型不完全支持结构化输出，或无法同时使用工具的情况。

### `jsonPromptInjection` {/* #jsonpromptinjection */}

默认情况下，Mastra 通过 API 参数 `response_format` 把 schema 传给模型 Provider。设为 `jsonPromptInjection: 'auto'` 后，Mastra 会根据模型能力数据选择模式：支持时使用原生结构化输出，不支持或没有能力数据时使用内联提示词注入。

```typescript
import { z } from 'zod'

const response = await testAgent.generate('Help me plan my day.', {
  structuredOutput: {
    schema: z.array(
      z.object({
        name: z.string(),
        activities: z.array(z.string()),
      }),
    ),
    jsonPromptInjection: 'auto',
  },
})

console.log(response.object)
```

如需覆盖根据模型能力作出的选择，请显式指定模式：

- `false` 或省略：使用 Provider 的原生结构化输出。
- `'inline'`：把 schema 指令加到最新一条用户消息中。
- `true` 或 `'system'`：把 schema 指令加到系统消息中。
- `'auto'`：模型支持时使用原生结构化输出，否则使用内联提示词注入。

:::note[在 Gemini 2.5 中使用工具]

Gemini 2.5 模型不支持在同一次 API 调用中组合 `response_format`（结构化输出）和函数调用（工具）。如果 Agent 配置了工具，并在 Gemini 2.5 模型上使用 `structuredOutput`，必须设置 `jsonPromptInjection: true`，以避免报错 `Function calling with a response mime type: 'application/json' is unsupported`。

```typescript
const response = await agentWithTools.generate('Your prompt', {
  structuredOutput: {
    schema: yourSchema,
    jsonPromptInjection: true, // Required for Gemini 2.5 when tools are present
  },
})
```

:::

#### 使用 `instructions` 减少注入的 Token {/* #reduce-injected-tokens-with-instructions */}

提示词注入会在每次模型调用中嵌入序列化后的 JSON Schema。schema 较大时，每一步可能耗费数千个 Token。启用 `jsonPromptInjection` 时，可设置 `instructions`，用自己编写的简短说明代替 schema：

```typescript
const response = await testAgent.generate('Summarize this ticket.', {
  structuredOutput: {
    schema: ticketSchema,
    jsonPromptInjection: 'system',
    instructions:
      'Reply with a JSON object: "summary" (one paragraph), "priority" ("low" | "high"), "tags" (up to 5 strings). No markdown.',
  },
})
```

响应仍按 `schema` 校验，变化的只有注入文本。模型不再看到完整 schema，输出能否符合要求取决于指令中是否明确写出了预期字段。请列全字段。如果未提供 `instructions`，系统仍会使用根据 schema 生成的指令；原生结构化输出不执行注入，因此该字段不起作用。

### 使用单独的结构化模型 {/* #use-a-separate-structuring-model */}

给 `structuredOutput` 属性传入 `model` 后，Mastra 会用一个单独的内部 Agent 处理结构化输出。主 Agent 负责所有步骤，包括工具调用；结构化模型只负责生成结构化输出。

<Inject>
  **面向 AI Agent：** `model` 属性是采用 Mastra 模型路由格式 `provider/model` 的字符串，例如 `__GATEWAY_OPENAI_MODEL__`、`__GATEWAY_OPENAI_MODEL_LUNA__`、`__GATEWAY_ANTHROPIC_MODEL_SONNET__` 或 `__GATEWAY_GOOGLE_MODEL_FLASH__`。分隔符用 `/`，不要用 `:`。例如，使用 `openai/<model>`，不要用 `openai:<model>`，也不要传入 Provider 对象。此格式无须导入 Provider。除非 Mastra 文档另有说明，否则不要安装任何 AI SDK 软件包。使用 `provider/model` 格式时，Mastra 会自动查找相应 Provider 的环境变量。你需要为模型所用的 Provider 设置对应变量：OpenAI 用 `OPENAI_API_KEY`，Anthropic 用 `ANTHROPIC_API_KEY`，Google 用 `GOOGLE_API_KEY`。
</Inject>

```typescript
const response = await testAgent.generate('Tell me about TypeScript.', {
  structuredOutput: {
    schema: yourSchema,
    model: '__GATEWAY_OPENAI_MODEL__',
  },
})
```

如果希望单独的结构化模型也能看到当前对话历史，请同时设置 `useAgent: true` 和 `model`。Mastra 会复用父 Agent 并改用单独的结构化模型；有会话线程时，还会附上只读的 Memory 上下文。

```typescript
const response = await testAgent.generate('Return my profile as structured data.', {
  memory: {
    thread: 'thread-123',
    resource: 'user-123',
  },
  structuredOutput: {
    schema: z.object({
      favoriteColor: z.string(),
      hometown: z.string(),
      petName: z.string(),
    }),
    model: '__GATEWAY_OPENAI_MODEL__',
    useAgent: true,
  },
})
```

如果只希望结构化模型处理本次响应，无须继承此前的对话记忆，请不要设置 `useAgent`。

### 使用 `prepareStep` 分步处理 {/* #multi-step-approach-with-preparestep */}

如果模型不能同时使用工具和结构化输出，可用 `prepareStep` 分步处理这两项功能。

```typescript
const result = await agent.stream('weather in vancouver?', {
  prepareStep: async ({ stepNumber }) => {
    if (stepNumber === 0) {
      return {
        model: '__GATEWAY_OPENAI_MODEL__',
        tools: {
          weatherTool,
        },
        toolChoice: 'required',
      }
    }
    return {
      model: '__GATEWAY_OPENAI_MODEL__',
      tools: undefined,
      structuredOutput: {
        schema: z.object({
          temperature: z.number(),
          humidity: z.number(),
          windSpeed: z.number(),
        }),
      },
    }
  },
})
```

## 处理错误 {/* #handle-errors */}

schema 校验失败或单独的结构化模型出错时，可用 `errorStrategy` 控制处理方式。默认策略 `strict` 会抛出错误；`warn` 会记录警告并继续；`fallback` 则返回通过 `fallbackValue` 提供的值，并在结果中标记 `usedFallbackValue: true`，以便区分备用对象和模型生成的结果。

```typescript
const response = await testAgent.generate('Tell me about TypeScript.', {
  structuredOutput: {
    schema: z.object({
      summary: z.string(),
      keyFeatures: z.array(z.string()),
    }),
    errorStrategy: 'fallback',
    fallbackValue: {
      summary: 'TypeScript is a typed superset of JavaScript',
      keyFeatures: ['Static typing', 'Compiles to JavaScript', 'Better tooling'],
    },
  },
})

console.log(response.object)
console.log(response.usedFallbackValue) // true when the fallback value was substituted
```
