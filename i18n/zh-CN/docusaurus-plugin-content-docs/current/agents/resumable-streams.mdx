# 可恢复的流

可恢复流将Agent运行的每个块发布到 PubSub 主题，并保留这些事件的重播缓存。断开连接的客户端可以重新连接并追上，另一个读者可以遵循相同的运行`observe()`，任何读者都可以阻止它。

可恢复的流并不能使运行本身持久。重新连接不是崩溃恢复：如果运行Agent的进程停止，则运行停止，观察者会看到错误或仅看到其他内容。对于在进程重新启动后仍然存在的运行，请使用[durable agents](/docs/harness/durable-agents), which publish through the same stream layer.

## 默认值 {/* #defaults */}

|Agent|流 |
| - | - |
|注册于`Mastra` instance | On |
| Standalone (`new Agent()` without `Mastra`)|关闭 |
|普通Agent与`durable: true`|开启，包括独立Agent |
|普通Agent与`durable: false`|关闭，包括注册Agent|
|显式的`createDurableAgent()`包装|始终发布；经过`cache: false`到工厂禁用重播缓存，而不是传输历史记录|

注册Agent，无论是否持久，都会在`mastra.pubsub` and caches events in `mastra.serverCache`, or an in-memory cache when the server has none. Every `Mastra` instance that shares that PubSub and cache can observe the run. An agent-level `pubsub` takes precedence, except on the evented engine, whose steps always publish on `mastra.pubsub`.

## 配置流 {/* #configure-streams */}

放`durable` on the agent to turn streams on or off, or to pass your own PubSub and cache:

```typescript title="src/mastra/agents/support-agent.ts"
import { Agent } from '@mastra/core/agent'

export const supportAgent = new Agent({
  id: 'support-agent',
  name: 'Support agent',
  instructions: 'You help customers with their orders.',
  model: '__GATEWAY_OPENAI_MODEL_BASE__',
  durable: {
    // Keep finished runs replayable for 2 minutes instead of 30 seconds
    cleanupTimeoutMs: 120_000,
  },
})
```

|选项 |默认 |描述 |
| - | - | - |
|`pubsub` | `mastra.pubsub` | Bus the run is published on. Use a shared bus to follow runs across processes. |
| `cache` | `mastra.serverCache`, else an in-memory cache | Replay cache. Pass `false` to disable this cache. Transports such as Redis Streams can still replay retained history. |
| `shouldCache` | Every topic | Return `false` for a topic to skip caching it. |
| `cleanupTimeoutMs` | `30000` | How long after it finishes a run is cleared. `0`仅关闭此计时器。缓存自身的过期和驱逐仍然适用。 |

`durable: true`使用这些默认值打开流，包括独立Agent。

在平原上`Agent`, `durable` configures resumable streams only. For checkpoint-backed execution, wrap the agent explicitly with `createDurableAgent({ agent })`. To recover in-flight runs after a crash, also configure persistent workflow storage and `recovery: { durableAgents: 'auto' }`. For manual recovery instead, pass a `shouldPersistSnapshot` policy that includes `running` snapshots and call `recoverActiveRuns()` yourself. See [crash recovery](/docs/harness/durable-agents#crash-recovery) for setup and persistence policies.

配置包装器的流缓存并通过工厂的传输`cache`, `pubsub`, `shouldCache`, and `cleanupTimeoutMs` options.

## 关闭流 {/* #turn-streams-off */}

流是有成本的。每个块都会发布到 PubSub，并且在启用缓存的情况下，每个事件都会被存储，直到运行被清理。内存中的缓存就是进程内存。对于远程 PubSub 或 Redis 等缓存，它是每个块的网络写入。对于从不重新连接或观察运行的大容量Agent，请关闭流：

```typescript title="src/mastra/agents/batch-agent.ts"
import { Agent } from '@mastra/core/agent'

export const batchAgent = new Agent({
  id: 'batch-agent',
  name: 'Batch agent',
  instructions: 'You classify support tickets.',
  model: '__GATEWAY_OPENAI_MODEL_BASE__',
  durable: false,
})
```

要保持实时观察但跳过重播缓存，请传递`durable: { cache: false }`.

### 运行时间可以保持多长时间 {/* #how-long-runs-stay-available */}

运行完成后，执行进程会安排清理其事件和所有权记录`cleanupTimeoutMs`. The timer allows the process to exit before cleanup. Shared cache data then remains until expiry or eviction. Redis Streams retains its native topic data until `clearTopic()` succeeds or its idle TTL expires. The transport's default idle TTL is seven days. Configure `streamIdleTtlMs` to change it, or set it to `0` to disable transport expiry. A run parked on a tool approval or suspension isn't cleared by that timer, because resuming it continues on the same topic.

缓存限制了其他一切：

* 运行日志和所有权记录向缓存请求 24 小时 TTL。内存缓存至少使用此 TTL 来存储索引运行日志，除非禁用缓存过期。缓存条目限制可以更快地驱逐数据。
* 内存缓存默认保存 1,000 个条目。每次运行都使用多个条目（其事件日志、计数器及其所有权记录），因此大流量会更快地驱逐较旧的运行。
* 当运行的所有权记录被逐出或过期时，服务器的观察和中止路由返回 404。无法重播已驱逐的运行事件。

当运行必须在服务器之间保持可观察性或需要长时间批准等待时，请使用根据您的流量调整大小的共享缓存，例如 Redis。

## 跟随跑步 {/* #follow-a-run */}

共享 PubSub 总线的Agent之间的运行 ID 必须是唯一的。

称呼`observe()` with the run's ID to follow it from any agent instance that shares the bus. Without an offset, `observe()` replays the cached events and then delivers live ones. Replay needs the same replay cache too. An instance with its own cache receives only live events, unless the PubSub keeps history. When a run waits on a tool approval, the observation receives the approval request and stays open until the approved run finishes, errors or is aborted. Call `detach()` to stop following a parked run:

```typescript title="src/server/reconnect.ts"
import { supportAgent } from '../mastra/agents/support-agent'

export async function followRun(runId: string, request: Request) {
  const { output, detach } = await supportAgent.observe(runId)

  request.signal.addEventListener('abort', detach, { once: true })
  if (request.signal.aborted) detach()

  for await (const chunk of output.fullStream) {
    // Chunks from the run, including any missed while disconnected
  }
}
```

每个块来自`observe()` carries its run-log position as `chunk.index`. To resume an observation after a dropped connection, pass `index + 1` of the last chunk that has an index as `offset`. Chunks from a plain agent's `stream()`, and chunks delivered without a replay cache, carry no `index`, so a client that lost one of those connections should observe without an `offset`. The [`observe()` reference](/reference/agents/durable-agent#observerunid-options) covers which chunks carry no index, structured output, and replay limits.

通过 HTTP，观察无法恢复的运行会失败，而不是返回空流。未知的运行，或者其所有权记录过期或被驱逐的运行，回答 404，并且客户端以`MastraClientError` carrying that status rather than resolving to an empty, closed stream.

`agent.hasResumableStreams()`报告该Agent是否发布其运行，以及是否与它们一起发布`observe()` and the server's observe and abort routes can reach them. It's `true` for a durable agent and for any agent with streams on.

### 直到空闲流 {/* #until-idle-streams */}

`streamUntilIdle()`和`resumeStreamUntilIdle()` combine the initial run and background-task continuations in their `fullStream`. Without an offset, `observe(returnedRunId)` replays only the initial segment and closes at its finish event. It doesn't reconnect to the combined until-idle stream or replay later background-task answers. Supplying an explicit run ID doesn't change this limit. The same limit applies to durable agents.

## 停止跑步 {/* #stop-a-run */}

当流打开时，关闭的读取器不会停止运行。当客户端与服务器的流路由断开连接时，服务器会分离该读取器并且运行继续进行：它不断生成令牌、调用Tool并运行`onFinish`, so the client can reconnect. Stop it explicitly, or set `durable: false` on a plain agent whose runs should end with the request. A durable agent's run always continues after a disconnect. A detached run still ends when it finishes, when it's stopped, or when its step budget is spent. With neither `maxSteps` nor `stopWhen` set, each loop stops after five steps, excluding processor retries. The budget applies per loop invocation, with a fresh loop after an approval or background continuation.

使用以下之一显式停止运行：

* `observe(runId)`返回一个`abort()` function that asks a running run to stop wherever it executes. The request is best effort. It doesn't wait for confirmation, and a failed publish is only logged. Use the abort route below when you need confirmation. A run parked on an approval no longer listens for it, so stop a parked run with the abort route below, or with `POST /agents/:agentId/threads/abort` for a run in a memory thread.
* `agent.abortRunStream(runId)`停止此进程中的运行，并要求同一总线上的其他进程停止它。它返回`true` for a running run stopped in this process. A run parked on an approval outside a memory thread is cancelled here too, but the call returns `false`. A later approval in this process fails. The cancellation fence is process-local and leaves the shared snapshot intact. Another process can still approve that snapshot, so use the abort route below to stop a parked run in an app with more than one server. For a run elsewhere the request is best effort.
* 服务器的`POST /agents/:agentId/runs/:runId/abort` route stops a run on any server that shares the PubSub and cache, after checking the caller owns it. It returns `{ aborted: true }` once the process executing the run confirms it stopped. For a run of a durable agent (`DurableAgent` or `createDurableAgent`, including evented agents) parked on an approval, the route also records the cancellation in storage and returns `{ aborted: true }` after that write is saved. A later approval or resume of that run is then refused with `409 Conflict` (`AGENT_RESUME_ABORTED_RUN`) on every server that shares the storage. If a resume claims the run first, no cancellation is recorded, and the route stops the resumed run like any running run. On storage adapters without concurrent updates, such as Redis, Valkey and LanceDB, an abort and an approval that arrive at the same moment aren't serialized, so an approval that overlaps the abort can still run its tool even though the abort returns `{ aborted: true }`. Wait for that response before relying on the recorded cancellation, which Inngest agents don't write. The route returns `{ aborted: false }` for a finished run, and when nothing stopped the run and no process answers in time. Runs in a memory thread can also be stopped with `POST /agents/:agentId/threads/abort`, but that route doesn't record the cancellation in storage, so use the run abort route to stop a parked durable run in an app with more than one server.

和`durable: false` on a non-durable agent, closing the HTTP request aborts the run, as before.

## 跨服务器 {/* #across-servers */}

当多个服务器共享 PubSub 和缓存（例如 Redis）时，可以通过其中任何一个服务器来观察和停止在一台服务器上启动的运行：

* 每次运行都会在第一个事件之前将所有权记录（Agent、运行、资源和线程）写入缓存。服务器的观察和中止路由会根据该记录检查调用者，因此每个服务器上都会保留租户和线程检查。
* 未知、过期或被逐出的记录返回 404。如果无法读取缓存，路由将返回 503，而不是跳过检查。
* 和`durable: { cache: false }` the record is kept in `mastra.serverCache`, so ownership still works across servers. Replay then depends on the PubSub: one that keeps history, like Redis Streams, replays it, and an in-process bus delivers only live events.
* 使用默认的内存缓存和 PubSub，不会共享任何内容，因此只有运行Agent的服务器才能观察或停止其运行。
