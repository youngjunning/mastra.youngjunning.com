# 代码模式

**引入版本：** `@mastra/core@1.38.0`

代码模式让 Agent 在隔离的 Sandbox 中调用多个 Tool 完成计算，再返回一份更准确的响应。

模型会把逐轮调用 Tool 的工作交给一个函数，并针对用户的问题编写函数。这个函数把已有 Tool 作为 `external_*` 函数来调用，并精简或汇总结果，形成一份结构化答案。

[`createCodeMode()`](/reference/tools/create-code-mode) 返回此 Tool，默认 `id` 为 `execute_typescript`。可以配置 `id`，让同一 Agent 同时使用多个代码模式 Tool，并分别限制其可调用的 Tool（参见[为多个代码 Tool 划分调用范围](#scoping-tools-across-multiple-code-tools)）。

## 何时使用代码模式 {/* #when-to-use-code-mode */}

当 Agent 需要调用多个 Tool 来回答用户问题或完成复杂计算时，可以使用代码模式：

- 减少往返：一次 Tool 调用就能完成涉及多个 Tool 的查询，省去每次选取 Tool 时重复运行 Agent 循环的开销。
- 节省上下文：函数可以先精简或汇总大体量的 Tool 响应，再把结果返回给 Agent。
- 算术更准确：求和、求平均值等运算由 JavaScript 执行，无需模型预测 token。
- 提前规划：筛选、汇总和分支判断都在一个函数中完成，省去分轮处理。

## 工作原理 {/* #how-it-works */}

未启用代码模式时，涉及多个 Tool 的查询可能要经过多轮 Agent 循环。模型每轮选择一个 Tool 并读取结果，按需重复。

每一轮都会把完整的 Tool 响应加入 Agent 的上下文窗口，可能削弱推理效果并增加 token 用量。

启用代码模式后，Tool 仍在宿主机上运行，继续使用完整的验证、请求上下文和追踪机制。Sandbox 内只执行模型编写的编排代码。每次 `external_*` 调用都会转发给宿主机上的实际 Tool。函数可以先精简或汇总结果，再统一返回给 Agent。

函数在 [Workspace 的 Sandbox](/docs/sandbox/overview) 中运行。代码由模型编写，因此必须明确选定执行边界：传入 `sandbox`，或使用提供 Sandbox 的 Workspace。要在宿主机上执行，请显式传入 `new LocalSandbox()`。函数会以拥有宿主机权限的 `node` 进程运行，因此只应在受信任的开发环境或本地开发时使用。

自带执行边界的传输方式是例外。使用 [`IsolatedVmCodeModeTransport`](/reference/tools/isolated-vm-transport) 时，程序在进程内的 V8 隔离环境中运行，无需 Sandbox（参见[进程内隔离](#in-process-isolation)）。

## 快速入门 {/* #quickstart */}

`createCodeMode()` 返回 Tool 及生成的指令。未指定 `id` 时，Tool 的名称为 `execute_typescript`。将 Tool 和指令都添加到 Agent 中：

```typescript
import { Agent } from '@mastra/core/agent'
import { createCodeMode, createTool } from '@mastra/core/tools'
import { LocalSandbox } from '@mastra/core/workspace'
import { z } from 'zod'

const getTopProducts = createTool({
  id: 'getTopProducts',
  description: 'Get top selling products',
  inputSchema: z.object({ limit: z.number() }),
  outputSchema: z.object({
    products: z.array(z.object({ id: z.string(), name: z.string(), totalSales: z.number() })),
  }),
  execute: async ({ limit }) => fetchTopProducts(limit),
})

const getProductRatings = createTool({
  id: 'getProductRatings',
  description: 'Get ratings for a product',
  inputSchema: z.object({ productId: z.string() }),
  outputSchema: z.object({ ratings: z.array(z.object({ score: z.number() })) }),
  execute: async ({ productId }) => fetchRatings(productId),
})

const { tool, instructions } = createCodeMode({
  tools: { getTopProducts, getProductRatings },
  sandbox: new LocalSandbox(), // required; runs on the host — see "How it works"
})

const agent = new Agent({
  id: 'shop-assistant',
  name: 'shop-assistant',
  instructions: ['You are a helpful shopping assistant.', instructions],
  model: '__GATEWAY_OPENAI_MODEL__',
  tools: { execute_typescript: tool },
})
```

当用户问「排名前 5 的产品有哪些？它们的平均评分分别是多少？」时，模型只发出一次 `execute_typescript` 调用，由函数处理多个 Tool 调用：

```typescript
const top = await external_getTopProducts({ limit: 5 })
const ratings = await Promise.all(
  top.products.map(p => external_getProductRatings({ productId: p.id })),
)
return top.products.map((product, i) => {
  const scores = ratings[i].ratings.map(r => r.score)
  const avg = scores.reduce((sum, s) => sum + s, 0) / scores.length
  return {
    name: product.name,
    sales: product.totalSales,
    averageRating: Math.round(avg * 100) / 100,
  }
})
```

五项评分查询并行执行，JavaScript 算出平均值，Agent 最终收到一份结构化结果。

使用 `createCodeMode()` 时，可以参考以下做法：

- 让每个 Tool 专注完成一项任务，由模型在代码中将它们组合起来。
- 能用 `Promise.all` 并行执行调用时，代码模式的收益最大。

如需了解配置选项、返回值、结果结构和如何查看指令，请参阅 [`createCodeMode()` 参考文档](/reference/tools/create-code-mode)。

## 为多个代码 Tool 划分调用范围 {/* #scoping-tools-across-multiple-code-tools */}

`createCodeMode()` 会保留各自的允许列表。多次调用可为 Agent 创建多个代码 Tool，分别限定各自可用的 Tool 子集。每个实例只能调用本次 `createCodeMode()` 传入的 Tool 所对应的 `external_*` 函数。这些子集彼此隔离。

为每个 Tool 设置不同的 `id`，避免冲突，并将各 Tool 的指令添加到 Agent 中：

```typescript
const sales = createCodeMode({
  id: 'sales_code',
  tools: { listRecentOrders, getCustomer },
  sandbox,
})

const inventory = createCodeMode({
  id: 'inventory_code',
  tools: { listProducts, getSupplier },
  sandbox,
})

const agent = new Agent({
  id: 'ops-assistant',
  name: 'ops-assistant',
  instructions: ['You are an ops assistant.', sales.instructions, inventory.instructions],
  model: '__GATEWAY_OPENAI_MODEL__',
  tools: { sales_code: sales.tool, inventory_code: inventory.tool },
})
```

为 `sales_code` 生成的代码无法调用库存 Tool，反过来也一样。这样既能落实最小权限，也能缩小每个 Tool 的提示词范围。

## 已连接的 Tool {/* #connected-tools */}

要编排已连接到 Mastra Platform 的 Provider 所提供的 Tool，可以使用 [`tools().codeMode()`](/reference/connect/tools#code-mode)（来自 `@mastra/connect`）。它会在每次请求时根据当前连接生成代码 Tool 和指令，并保留需要审批的 Tool，供 Agent 直接调用。

## 远程 Sandbox {/* #remote-sandboxes */}

默认的传输方式会把程序写入宿主机的文件系统，再用 `node` 运行。与宿主机共享文件系统的 `LocalSandbox` 支持这种方式。在独立微型虚拟机中运行的远程 Sandbox（如 [E2B](/integrations/sandboxes/e2b)）没有这些宿主机路径，因此无法采用这种方式。

远程 Sandbox 需要一种能将程序写入 Sandbox 文件系统的传输方式。使用 E2B 时，把内置的 `E2BCodeModeTransport` 作为第二个参数传给 `createCodeMode`：

```typescript
import { createCodeMode } from '@mastra/core/tools'
import { E2BSandbox, E2BCodeModeTransport } from '@mastra/e2b'

const { tool, instructions } = createCodeMode(
  { tools, sandbox: new E2BSandbox() },
  new E2BCodeModeTransport(),
)
```

## 进程内隔离 {/* #in-process-isolation */}

若要在不启动新进程、也不使用远程 Sandbox 的情况下建立安全边界，请使用 [`IsolatedVmCodeModeTransport`](/reference/tools/isolated-vm-transport)（来自 `@mastra/isolated-vm`）。它在进程内的 V8 隔离环境中运行程序，无需 Sandbox。该环境无法访问文件系统、网络或进程，只能通过 `external_*` 函数调用宿主机上的 Tool。

```typescript
import { createCodeMode } from '@mastra/core/tools'
import { IsolatedVmCodeModeTransport } from '@mastra/isolated-vm'

const { tool, instructions } = createCodeMode(
  { tools }, // no sandbox needed
  new IsolatedVmCodeModeTransport({ memoryLimitMb: 128 }),
)
```

`isolated-vm` 是原生扩展。在 Node.js 20 及更高版本上，必须用 `--no-node-snapshot` 启动宿主进程。设置方法见 [IsolatedVmCodeModeTransport 参考文档](/reference/tools/isolated-vm-transport)。

如果宿主环境无法安装原生扩展或设置 Node.js 启动参数（常见于无服务器平台），可使用 [`QuickJsCodeModeTransport`](/reference/tools/quickjs-transport)（来自 `@mastra/quickjs`）。它通过编译为 WebAssembly 的 QuickJS 运行时提供同样的进程内隔离，但执行速度较慢：

```typescript
import { createCodeMode } from '@mastra/core/tools'
import { QuickJsCodeModeTransport } from '@mastra/quickjs'

const { tool, instructions } = createCodeMode(
  { tools }, // no sandbox needed
  new QuickJsCodeModeTransport({ memoryLimitMb: 128 }),
)
```

参见[选择传输方式](/reference/tools/quickjs-transport#choosing-a-transport)，了解各方式的对比。
