# LSP 代码检查

通过语言服务器协议（LSP），Agent 可以获取项目代码的语义信息。语言服务器理解编程语言和项目结构，因此可以识别符号的类型、声明、实现和诊断信息。

## LSP 能做什么 {/* #what-lsp-adds */}

文件和搜索工具能回答有关代码库的不同问题：

| 工具 | 适用场景 |
| - | - |
| `read_file` | 读取已知文件的确切内容和上下文 |
| `grep` | 在多个文件中查找文本或正则表达式匹配项 |
| [搜索](/docs/sandbox/search) | 按关键词或语义相似度检索已索引的文件 |
| LSP 检查 | 获取类型信息，在项目中追踪符号 |

LSP 检查是这些工具的补充。Agent 可以先用 `grep` 找到符号，再通过 LSP 检查找到其声明，最后用 `read_file` 读取完整实现后再修改。

## 配置 LSP {/* #set-up-lsp */}

LSP 会启动一个常驻的语言服务器进程，并与其交换 JSON-RPC 消息。启用前，请确认配置满足以下条件：

- 使用静态 [Sandbox](/docs/sandbox/overview)，其进程管理器的进程句柄要提供可读输出流和可写输入流。不支持 Sandbox 解析器。
- Mastra 应用已安装 `vscode-jsonrpc` 和 `vscode-languageserver-protocol` 包。
- 在运行 Sandbox 进程的环境中安装语言服务器的二进制文件及其运行时。
- 使用绝对路径指定项目根目录，且 Mastra 应用和 Sandbox 进程都能通过相同路径访问项目根目录及文件。

Mastra 内置了 TypeScript 和 JavaScript、Python、Go 及 Rust 的服务器定义，仍需安装对应的语言服务器二进制文件。对于其他文件类型，可以[注册其他服务器](#custom-language-servers)。

安装共用的协议包：

```bash npm2yarn
npm install vscode-jsonrpc vscode-languageserver-protocol
```

然后为项目安装语言服务器。例如，安装 TypeScript 和对应的语言服务器：

```bash npm2yarn
npm install typescript typescript-language-server
```

创建静态 `LocalSandbox`，将文件系统、Sandbox 和 LSP 根目录都指向同一目录：

```typescript title="src/mastra/workspaces.ts"
import { resolve } from 'node:path'
import { LocalFilesystem, LocalSandbox, Workspace } from '@mastra/core/workspace'

const projectPath = resolve('./workspace')

export const workspace = new Workspace({
  filesystem: new LocalFilesystem({
    basePath: projectPath,
  }),
  sandbox: new LocalSandbox({
    workingDirectory: projectPath,
  }),
  lsp: {
    root: projectPath,
  },
})
```

文件系统为 Agent 提供操作项目文件的工具。首次有 LSP 查询需要使用语言服务器时，Sandbox 会在同一目录启动它。如果缺少所需的协议包、进程管理器或服务器二进制文件，Mastra 会禁用 LSP，或报告没有可用的语言服务器。

## 使用 Agent 工具检查代码 {/* #inspect-code-with-the-agent-tool */}

启用 LSP 后，Agent 可以使用 `mastra_workspace_lsp_inspect`。输入指定文件，并将光标定位到一个符号上：

```json
{
  "path": "/absolute/path/to/workspace/src/orders.ts",
  "line": 10,
  "match": "const order = await <<<findOrder(orderId)"
}
```

`line` 从 1 开始计数。将该行内容复制到 `match`，然后紧挨着要检查的符号前插入一个 `<<<` 标记，只插入一次。该标记不属于源文件。

工具返回语言服务器能提供的字段：

| 字段 | 输出 |
| - | - |
| `hover` | 类型信息或文档，以及对应的标记类型 |
| `diagnostics` | 被检查行的诊断严重程度、消息和来源 |
| `definition` | 声明位置，文件可读时附带单行预览 |
| `implementation` | 实现位置 |
| `error` | 无法检查时返回配置、服务器或查询错误 |

工具会省略无法提供的结果字段。可以根据定义和实现的位置继续用 `read_file` 查看完整上下文。

## 调整 LSP 配置 {/* #configure-lsp */}

设置 `lsp: true` 可使用默认值。要控制根目录、服务器查找、超时或保留的客户端，请改用对象：

```typescript oxfmt:false
lsp: {
  root: projectPath,
  diagnosticTimeout: 4_000,
  initTimeout: 8_000,
  maxOpenClients: 4,
  disableServers: ['eslint'],
  binaryOverrides: {
    typescript: '/opt/mastra-tools/typescript-language-server --stdio',
  },
  searchPaths: ['/opt/mastra-tools'],
},
```

`binaryOverrides` 将内置服务器 ID 映射到完整启动命令。`searchPaths` 添加包根目录，其中 `node_modules` 可能包含所需模块或二进制文件。最后还可以设置 `packageRunner`，例如 `pnpm dlx`。这项后备机制默认关闭，因为它可能安装软件，或在某些项目结构中卡住。

`diagnosticTimeout` 控制直接调用 `getDiagnostics()` 和 `getDiagnosticsMulti()` API 时等待诊断的时长。Agent 检查工具目前最多等待五秒。

Mastra 通常从每个文件所在位置向上查找对应服务器的项目标记，以确定项目根目录。找不到标记时回退到 `lsp.root`。所有选项及默认值见 [LSP 配置参考](/reference/workspace/workspace-class)。

### 限制保留的客户端数量 {/* #limit-retained-clients */}

`maxOpenClients` 限制单个配置保留的语言服务器客户端数量，必须为正整数。达到上限时，Mastra 会在没有活动查询租约的客户端中关闭最久未使用的一个。

如果所有保留的客户端都有活动租约，下次获取时最多等待五秒，直到有租约释放。若仍无可用租约，`prepareQuery()` 和 `getDiagnostics()` 返回 `null`，`getDiagnosticsMulti()` 跳过无法获取客户端的服务器。省略 `maxOpenClients` 时不限制保留数量。Mastra Code 的默认上限是 `4`。

### 重命名工具 {/* #tool-name-remapping */}

通过 `tools` 配置 Agent 检查工具。例如，可添加以下条目来公开更短的名称：

```typescript
import { WORKSPACE_TOOLS } from '@mastra/core/workspace'

const tools = {
  [WORKSPACE_TOOLS.LSP.LSP_INSPECT]: {
    name: 'lsp_inspect',
  },
}
```

在配置中将 `tools` 与 `lsp` 放在同一级。`name` 更改对外显示的工具名称，配置键仍为 `WORKSPACE_TOOLS.LSP.LSP_INSPECT`。要移除工具，在同一条目中设置 `enabled: false`。

生成的 Agent 工具共用的审批设置、动态策略、输出限制和钩子，见[工具配置参考](/reference/workspace/workspace-class#tool-configuration)。

## 自定义语言服务器 {/* #custom-language-servers */}

如果某种语言没有内置支持，或需要替换内置定义，请在 `lsp.servers` 下添加服务器：

```typescript oxfmt:false
lsp: {
  root: projectPath,
  servers: {
    phpactor: {
      id: 'phpactor',
      name: 'Phpactor Language Server',
      languageIds: ['php'],
      extensions: ['.php'],
      markers: ['composer.json'],
      command: 'phpactor language-server',
      initializationOptions: {
        indexer: { enabled: true },
      },
    },
  },
},
```

每项定义支持以下字段：

| 字段 | 必填 | 说明 |
| - | - | - |
| `id` | 是 | 唯一的服务器 ID。使用内置 ID 可替换对应定义。 |
| `name` | 是 | 在日志和错误中显示的易读名称。 |
| `languageIds` | 是 | 服务器处理的 LSP 语言标识符。 |
| `extensions` | 是 | 服务器处理的文件扩展名，包含前导点。 |
| `markers` | 是 | 用于查找项目根目录的文件或目录。 |
| `command` | 是 | 启动服务器的完整命令。 |
| `initializationOptions` | 否 | 在 LSP 初始化握手时发送的设置。 |

自定义定义会与内置定义合并。若 `id` 相同，自定义定义将替换内置定义。如果服务器列出了多个语言 ID，Mastra 会将每个已配置的扩展名映射到第一个语言 ID。

## 直接查询 LSP {/* #query-lsp-directly */}

应用代码可以直接查询已配置的 LSP 管理器。`getDiagnostics()` 和 `getDiagnosticsMulti()` 在内部管理客户端租约以及文档打开和关闭的通知。

`prepareQuery()` 提供客户端，可直接查询悬停信息、定义、实现等。传入绝对文件路径后，它会打开文件并返回一个租约。请先关闭文件再释放租约，并将两次调用都放入 `finally` 块：

```typescript
async function inspectHover(filePath: string, line: number, character: number) {
  const query = await workspace.lsp?.prepareQuery(filePath)
  if (!query) return null

  try {
    return await query.client.queryHover(query.uri, {
      line,
      character,
    })
  } finally {
    query.client.notifyClose(filePath)
    query.release()
  }
}
```

直接使用客户端时，位置索引从 0 开始。设置了 `maxOpenClients` 时，未释放的租约可能导致空闲客户端无法被清理。清理时，Mastra 最多等待五秒让活动租约释放，随后会强制关闭语言服务器。受管理的 LSP 客户端会在 Sandbox 销毁前关闭。

## 限制 {/* #limitations */}

- LSP 仅支持有对应内置或自定义服务器的文件类型。
- 单凭文件系统无法运行语言服务器。LSP 需要带双向进程管理器的静态 Sandbox。
- `LocalFilesystem` 的目录隔离和 `allowedPaths` 不限制 LSP 检查。请将 `lsp.root` 限定在可信项目中。如果用户可提交不可信的宿主机路径，请勿对其开放 LSP 工具。
- 检查外部包时，可能定位到 `.d.ts` 等声明文件，而非运行时源码。
- 对于不支持的悬停、诊断、定义或实现查询，语言服务器可能省略相应结果。

### 远程 Sandbox {/* #remote-sandboxes */}

远程 LSP 仍依赖宿主机。语言服务器命令由远程 Sandbox 的进程管理器运行，但查找二进制文件、读取文件和部分源码预览仍在 Mastra 宿主机上完成。

只有满足以下全部条件时，才使用远程 LSP：

- 远程进程管理器提供可读输出流和可写输入流。
- 项目在 Mastra 宿主机和远程 Sandbox 上使用相同的绝对路径。
- 解析出的服务器命令已安装在远程镜像中。内置服务器通过 `binaryOverrides` 配置，自定义服务器通过 `lsp.servers.command` 配置。
- 宿主机可读取检查和定义预览所需的文件。

本地文件系统与远程 Sandbox 不会自动同步。仅安装在宿主机上的二进制文件无法在远程 Sandbox 中运行，仅存在于远程的文件也无法提供全部宿主机侧结果。对于只存在于远程的项目，在 LSP 能够不受后端限制地访问文件之前，请使用 `grep`、索引[搜索](/docs/sandbox/search)和 Sandbox 命令。
