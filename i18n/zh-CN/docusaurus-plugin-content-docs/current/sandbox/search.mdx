# 搜索与索引

搜索让 Agent 无需逐个读取文件，就能快速找到相关内容。它可与[直接访问文件系统](/docs/sandbox/filesystem#direct-filesystem-access)和[`mounts`](/docs/sandbox/filesystem#mounts)配合使用，但会将可搜索的内容存入独立索引。

查询读取的是索引，而非实时文件系统。因此，你也可以为数据库、API 或其他应用来源的内容建立索引。

## 快速入门 {/* #quickstart */}

启用 BM25 关键词搜索，将文档加入索引，然后执行搜索：

```typescript title="src/mastra/workspaces.ts"
import { LocalFilesystem, Workspace } from '@mastra/core/workspace'

const workspace = new Workspace({
  filesystem: new LocalFilesystem({ basePath: './workspace' }),
  bm25: true,
})

await workspace.index('/docs/guide.md', 'Reset passwords from the account settings page.')

const results = await workspace.search('password reset')

for (const result of results) {
  console.log(`${result.id}: ${result.score}`)
  console.log(result.content)
}
```

`workspace.index()` 的第一个参数是搜索结果中返回的文档 ID。本例中它看起来像文件路径，但 `index()` 不会读取或创建该文件。

配置搜索后，Agent 还会获得搜索和索引 Tool。参见 [Agent Tool](#agent-tools) 了解如何控制它们。

## 选择搜索模式 {/* #choose-a-search-mode */}

Mastra 支持三种搜索模式：

| 模式 | 适用场景 | 查询示例 |
| - | - | - |
| `bm25` | 精确术语、技术查询和代码 | "useState hook", "404 error", "config.yaml" |
| `vector` | 概念和自然语言问题 | "how to handle user authentication" |
| `hybrid` | 同时包含精确术语和概念的查询 | 大多数 Agent 搜索场景 |

如果调用 `workspace.search()` 时未指定模式，且同时配置了 BM25 和向量搜索，Mastra 会使用混合搜索；否则使用已配置的模式。

### BM25 关键词搜索 {/* #bm25-keyword-search */}

BM25 根据词频和文档长度为文档评分，无需外部服务或嵌入模型。传入 `bm25: true` 即可使用快速入门中的默认设置。

传入 `k1` 和 `b`，可调整词频饱和度和文档长度归一化：

```typescript title="src/mastra/workspaces.ts"
import { Workspace, LocalFilesystem } from '@mastra/core/workspace'

const workspace = new Workspace({
  filesystem: new LocalFilesystem({ basePath: './workspace' }),
  bm25: {
    k1: 1.5,
    b: 0.75,
  },
})
```

### 向量搜索 {/* #vector-search */}

向量搜索利用嵌入查找语义相近的内容。配置向量存储，以及每次嵌入一个字符串的函数：

```typescript title="src/mastra/workspaces.ts"
import { openai } from '@ai-sdk/openai'
import { Workspace, LocalFilesystem } from '@mastra/core/workspace'
import { PineconeVector } from '@mastra/pinecone'
import { embed } from 'ai'

const workspace = new Workspace({
  filesystem: new LocalFilesystem({ basePath: './workspace' }),
  vectorStore: new PineconeVector({
    id: 'workspace-search',
    apiKey: process.env.PINECONE_API_KEY!,
  }),
  embedder: async (text: string) => {
    const { embedding } = await embed({
      model: openai.embedding('__AI_SDK_OPENAI_EMBEDDING_MODEL__'),
      value: text,
    })
    return embedding
  },
})
```

#### 批量嵌入 {/* #batch-embedding */}

单文本嵌入函数会为每个文档单独调用一次 Provider。对于大型索引，使用 Provider 的批量 API，一次嵌入多个文档。

批量嵌入函数必须：

- 接收字符串数组。
- 按原顺序为每个字符串返回一个嵌入。
- 具有 `batch: true` 属性，以便 Mastra 在运行时识别。
- 可选设置 `maxBatchSize`，表示 Provider 接受的最大数组长度。

Mastra 会按 `maxBatchSize` 拆分较大的索引任务，并可并发处理各批。请将其设为 Provider 文档规定的上限：

| Provider | 最大输入数 |
| - | - |
| OpenAI | 2048 |
| Cohere | 96 |
| Voyage | 128 |

如果省略 `maxBatchSize`，Mastra 会使用内部批量大小。

将单文本嵌入器替换为批量嵌入器：

```typescript title="src/mastra/workspaces.ts"
import { openai } from '@ai-sdk/openai'
import { LocalFilesystem, Workspace } from '@mastra/core/workspace'
import { PineconeVector } from '@mastra/pinecone'
import { embedMany } from 'ai'

const model = openai.embedding('__AI_SDK_OPENAI_EMBEDDING_MODEL__')

const workspace = new Workspace({
  filesystem: new LocalFilesystem({ basePath: './workspace' }),
  vectorStore: new PineconeVector({
    id: 'workspace-search',
    apiKey: process.env.PINECONE_API_KEY!,
  }),
  embedder: Object.assign(
    async (texts: string[]) => {
      const { embeddings } = await embedMany({ model, values: texts })
      return embeddings
    },
    { batch: true as const, maxBatchSize: 2048 },
  ),
})
```

`Object.assign()` 将 `batch` 和 `maxBatchSize` 添加为函数属性。Mastra 将它们读取为元数据，不会传给 Provider。仍支持签名为 `(text: string) => Promise<number[]>` 的单文本嵌入函数。

### 服务器端嵌入 {/* #server-side-embeddings */}

有些向量存储会自行生成嵌入。使用此类存储时无需配置 `embedder`：Mastra 会发送文件文本，数据库在写入时嵌入文本，并在查询时嵌入搜索字符串。

MongoDB 通过[自动嵌入](/integrations/vectors/mongodb#automated-embedding)实现这一功能。在向量存储中指定 Voyage AI 模型：

```typescript title="src/mastra/workspaces.ts"
import { LocalFilesystem, Workspace } from '@mastra/core/workspace'
import { MongoDBVector } from '@mastra/mongodb'

const workspace = new Workspace({
  filesystem: new LocalFilesystem({ basePath: './workspace' }),
  vectorStore: new MongoDBVector({
    id: 'workspace-search',
    uri: process.env.MONGODB_URI!,
    dbName: process.env.MONGODB_DB_NAME!,
    // highlight-next-line
    autoEmbed: { model: 'voyage-4' },
  }),
})
```

MongoDB 会在后台嵌入新文档，因此刚加入索引的内容可能暂时不会出现在搜索结果中。有关自动嵌入的要求，请参阅 [MongoDB 参考文档](/integrations/vectors/mongodb#automated-embedding)。

其他所有存储都要求应用提供向量，因此仍需配置 `embedder`。

### 混合搜索 {/* #hybrid-search */}

同时配置 BM25 和向量搜索，以结合关键词和语义结果：

```typescript title="src/mastra/workspaces.ts"
import { Workspace, LocalFilesystem } from '@mastra/core/workspace'

const workspace = new Workspace({
  filesystem: new LocalFilesystem({ basePath: './workspace' }),
  bm25: true,
  vectorStore: pineconeVector,
  embedder: embedderFn,
})
```

### 自定义索引名称 {/* #custom-index-name */}

向量索引名称默认由清理后的 Workspace ID 加上 `_search` 组成；如果向量存储自行生成嵌入，则使用 `_search_selfembed`。如需稳定或共享的名称，请设置 `searchIndexName`：

```typescript title="src/mastra/workspaces.ts"
import { Workspace, LocalFilesystem } from '@mastra/core/workspace'

const workspace = new Workspace({
  filesystem: new LocalFilesystem({ basePath: './workspace' }),
  vectorStore: pineconeVector,
  embedder: embedderFn,
  // highlight-next-line
  searchIndexName: 'my_workspace_vectors',
})
```

名称必须以字母或 `_` 开头，只能包含字母、数字或 `_`，且最多 63 个字符。

## 索引内容 {/* #index-content */}

使用 `workspace.index()` 将提供的文本加入搜索索引。Mastra 会为 BM25 搜索分词；如果配置了向量搜索，还会生成嵌入。

文档 ID 不必对应文件系统中的现有文件。如果需要过滤结果或提供更多上下文，可添加元数据：

```typescript
await workspace.index('/docs/guide.md', 'Content of the guide...')

await workspace.index('/docs/api.md', apiDocContent, {
  metadata: {
    category: 'api',
    version: '2.0',
  },
})
```

手动索引适用于数据库记录和 API 响应，也适用于需要自行预处理、分块或注释内容的场景。

### 为应用内容建立索引 {/* #index-application-content */}

即使应用自行读取内容，Workspace 也必须配置 `filesystem`、`sandbox` 或 `skills` Provider，才能将内容传给 `workspace.index()`。否则，`Workspace` 构造函数会抛出 `Workspace requires at least a filesystem, sandbox, or skills`。

配置文件系统并不意味着 Agent 应使用它。默认情况下，使用此 Workspace 的 Agent 也会获得 `mastra_workspace_read_file` 和 `mastra_workspace_write_file` 等文件 Tool。若只想开放搜索，请先禁用所有 Workspace Tool，再重新启用搜索 Tool：

```typescript title="src/mastra/workspaces.ts"
import { LocalFilesystem, Workspace, WORKSPACE_TOOLS } from '@mastra/core/workspace'

const workspace = new Workspace({
  filesystem: new LocalFilesystem({ basePath: './workspace' }),
  bm25: true,
  tools: {
    enabled: false,
    [WORKSPACE_TOOLS.SEARCH.SEARCH]: { enabled: true },
  },
})

for (const document of documents) {
  await workspace.index(document.id, document.content)
}
```

应用仍直接调用 `workspace.index()`。Tool 设置只控制 Agent 可调用哪些 Tool。

### 保持文件和索引同步 {/* #keep-files-and-the-index-in-sync */}

文件系统与索引的变更互不关联。写入、编辑或删除文件不会更新索引内容，而 `workspace.index()` 也不会读取或修改文件。

要写入文件并让它可被搜索，需执行以下两步：

```typescript
const path = 'notes/launch.md'
const content = '# Launch notes\n\nShip the new dashboard on Friday.'
const filesystem = workspace.filesystem

if (!filesystem) {
  throw new Error('This operation requires a static filesystem')
}

await filesystem.writeFile(path, content)
await workspace.index(path, content)
```

编辑文件后，请再次索引其完整的更新内容。删除文件不会移除已索引的文档，Mastra 目前也没有公开删除单个索引文档的方法。如果 Agent 必须搜索文件系统的当前状态，而你不维护独立索引，请使用 `grep` 文件 Tool。

## 搜索内容 {/* #search-content */}

使用 `workspace.search()` 返回按相关性排序的文档：

```typescript
const results = await workspace.search('authentication flow', {
  topK: 10,
  mode: 'hybrid',
  vectorWeight: 0.5,
})
```

| 选项 | 说明 |
| - | - |
| `topK` | 结果数量上限。直接调用 API 时默认是 10，Agent 搜索 Tool 默认是 5。 |
| `mode` | 搜索模式：`'bm25'`、`'vector'` 或 `'hybrid'`。默认使用 Workspace 配置中最佳的可用模式。 |
| `minScore` | 移除低于此分数的结果。分数尺度取决于模式、向量 Provider 和索引内容。 |
| `vectorWeight` | 混合模式中向量分数的权重。`0` 表示向量分数权重为零，`1` 表示 BM25 分数权重为零，`0.5` 表示两者权重相同。 |
| `filter` | 向量检索所用的向量存储元数据过滤器。在混合模式中，它不会过滤仅由 BM25 返回的结果。语法取决于所配置的向量存储。 |

每个结果包含匹配的内容及其分数：

```typescript
interface SearchResult {
  id: string
  content: string
  score: number
  lineRange?: {
    start: number
    end: number
  }
  metadata?: Record<string, unknown>
  scoreDetails?: {
    vector?: number
    bm25?: number
  }
}
```

分数等级不可互换：

- 单独使用 BM25 搜索时返回原始 BM25 分数，不限于 0 到 1。
- 向量分数的含义取决于所配置的向量存储。
- 混合搜索在加权计算时对 BM25 分数做最小最大归一化，但保留向量 Provider 的原始分数。合成分数也不限于 0 到 1。
- `scoreDetails` 保留原始组成分数，包括未归一化的 BM25 分数。
- 请根据当前模式、向量 Provider 和索引内容调整 `minScore`，不要在不同索引之间沿用同一阈值。

## Agent Tool {/* #agent-tools */}

配置搜索后，Agent 会获得 `mastra_workspace_search` 和 `mastra_workspace_index`。你可以通过 `WORKSPACE_TOOLS.SEARCH` 分别配置它们。

如果 Agent 只应搜索现有内容而不能修改索引，请禁用索引 Tool：

```typescript title="src/mastra/workspaces.ts"
import { LocalFilesystem, Workspace, WORKSPACE_TOOLS } from '@mastra/core/workspace'

const workspace = new Workspace({
  filesystem: new LocalFilesystem({ basePath: './workspace' }),
  bm25: true,
  tools: {
    [WORKSPACE_TOOLS.SEARCH.INDEX]: {
      enabled: false,
    },
  },
})
```

索引 Tool 接收与 `workspace.index()` 相同的 `path`、`content` 和可选元数据。它可能触发嵌入调用和向量存储写入；如果 Agent 修改索引前需要人工审核，请要求批准：

```typescript title="src/mastra/workspaces.ts"
import { Workspace, LocalFilesystem } from '@mastra/core/workspace'

const workspace = new Workspace({
  filesystem: new LocalFilesystem({ basePath: './workspace' }),
  bm25: true,
  tools: {
    [WORKSPACE_TOOLS.SEARCH.INDEX]: {
      requireApproval: true,
    },
  },
})
```

`requireReadBeforeWrite` 适用于文件系统写入 Tool，不适用于索引变更。即使索引不会写入静态文件系统，只要该文件系统是只读的，Mastra 也会排除索引 Tool。

完整 Tool 列表请参阅[搜索 Tool 参考文档](/reference/workspace/workspace-class#search-tools)，通用设置请参阅 [Tool 配置参考文档](/reference/workspace/workspace-class#tool-configuration)。

## 自动索引 {/* #auto-indexing */}

使用 `autoIndexPaths` 在应用启动时为静态文件系统内容建立索引。

:::warning

`autoIndexPaths` 是在 `workspace.init()` 中运行的。将 Workspace 传给 `new Mastra({ workspace })` 只会注册，不会初始化 Workspace 或建立索引。除非由 `AgentController` 等其他运行时负责初始化，否则请调用并等待 `workspace.init()`。

```typescript
await workspace.init()
```

如果由应用负责初始化，请在启动时、开始处理请求前调用一次。

:::

在常规 Mastra 应用中，先构造 `Mastra`，让 Workspace 可使用其日志记录器，然后在模块启动时初始化 Workspace：

```typescript title="src/mastra/index.ts"
import { Mastra } from '@mastra/core'
import { LocalFilesystem, Workspace } from '@mastra/core/workspace'

const workspace = new Workspace({
  filesystem: new LocalFilesystem({ basePath: './workspace' }),
  bm25: true,
  autoIndexPaths: ['docs', 'support/faq'],
})

export const mastra = new Mastra({ workspace })

await workspace.init()
```

顶层 `await` 会让模块启动一直等待初始化完成。`init()` 返回时，Mastra 已尝试读取并索引所有匹配文件。

每个 `autoIndexPaths` 条目可以是文件、目录或 glob 模式。递归遍历目录和 glob 时最多深入十层：

```typescript title="src/mastra/index.ts"
import { Mastra } from '@mastra/core'
import { Workspace, LocalFilesystem } from '@mastra/core/workspace'

const workspace = new Workspace({
  filesystem: new LocalFilesystem({ basePath: './workspace' }),
  bm25: true,
  autoIndexPaths: ['docs/**/*.md', 'support/**/*.txt'],
})

export const mastra = new Mastra({ workspace })

await workspace.init()
```

自动索引支持静态 `filesystem` 或 `mounts`。路径中需包含挂载前缀，例如 `/docs/**/*.md`。它不支持文件系统解析器，因为 Workspace 初始化时尚未选定 Provider。请手动为解析器提供的内容建立索引。

初始化只扫描一次，不会监控后续变更。索引前会将大文件分块；在向量模式下还会生成嵌入。

尽量缩小配置路径的范围，避开依赖和输出目录，也不要包含二进制文件目录。大型向量索引应使用批量嵌入函数。

再次调用 `workspace.init()` 会重新扫描路径，并先清空进程内的 BM25 索引再重建。不要在 Agent 调用、Tool、Workflow 步骤或请求处理函数中调用它。

持久化向量索引的行为不同。自动索引会替换所读取的文件，但后续扫描时仍可能保留此前已删除文件对应的文档。如果向量需在进程重启后保留，请使用稳定的 Workspace `id` 或 `searchIndexName`，并根据向量存储的持久化行为规划清理。
