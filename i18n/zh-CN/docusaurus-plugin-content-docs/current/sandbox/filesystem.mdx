# 文件系统

文件系统为Agent提供了读取、写入、列出和执行的Tool。[searching](/docs/sandbox/search)文件。将其用作知识库或在临时Sandbox运行之间保留文件。

有两种方式配置文件：

* [直接文件系统访问](#direct-filesystem-access)用途`filesystem` with one filesystem provider or a [`CompositeFilesystem`](#manual-composition) that you create yourself.
* [坐骑](#mounts)用途`mounts` to create a `CompositeFilesystem` from path-prefixed providers. When a static sandbox and filesystem provider support mounting, Mastra automatically mounts the provider at its configured path. Remote sandbox mounts typically use Filesystem in Userspace (FUSE).

配置任一`filesystem` or `mounts`, not both. Configuring both throws a `WorkspaceError` with the code `INVALID_CONFIG`.

两种配置都提供Agent文件Tool。仅当Sandbox可以成功挂载提供程序时，Sandbox命令才能看到该提供程序。

配置文件系统为Agent提供了以下Tool：

|Tool|是否 |
| - | - |
|`mastra_workspace_read_file` | Reads all or part of a file. |
| `mastra_workspace_write_file` | Creates or overwrites a file. |
| `mastra_workspace_edit_file` | Replaces matching text in an existing file. |
| `mastra_workspace_list_files` | Lists files and directories. |
| `mastra_workspace_delete` | Deletes a file or directory. |
| `mastra_workspace_file_stat`|返回有关文件或目录的元数据。 |
|`mastra_workspace_mkdir`|创建一个目录和任何缺少的父目录。 |
|`mastra_workspace_grep`|使用正则表达式搜索文件内容。 |
|`mastra_workspace_ast_edit`|应用结构代码编辑。可用时间`@ast-grep/napi`已安装。 |
|`mastra_workspace_apply_patch`|在一次调用中创建、更新、移动和删除多个文件。默认关闭。 |

这`apply_patch` tool is opt-in. Enable it with its own entry in `tools`. Setting the top-level `tools.enabled` doesn't turn it on. The tool checks every change in the patch before it writes any file:

```typescript title="src/mastra/workspaces/index.ts"
import { Workspace, LocalFilesystem, WORKSPACE_TOOLS } from '@mastra/core/workspace'

export const workspace = new Workspace({
  filesystem: new LocalFilesystem({ basePath: './workspace' }),
  tools: {
    [WORKSPACE_TOOLS.FILESYSTEM.APPLY_PATCH]: { enabled: true },
  },
})
```

每个Provider都通过以下方式支持文件Tool`filesystem`. Sandbox mounting depends on both the filesystem provider and sandbox backend.

## 直接文件系统访问 {/* #direct-filesystem-access */}

使用`filesystem` when the agent should access a provider through file tools. It can also accept a resolver or a manually created `CompositeFilesystem`.

为本地知识库提供Agent文件Tool：

```typescript
import { LocalFilesystem, Workspace } from '@mastra/core/workspace'

const workspace = new Workspace({
  filesystem: new LocalFilesystem({
    basePath: './knowledge-base',
  }),
})
```

Agent接收Tool，例如`mastra_workspace_read_file`, `mastra_workspace_write_file`, `mastra_workspace_list_files`, and `mastra_workspace_grep`. Paths are resolved under `./knowledge-base`, and no sandbox or command tools are required.

看[Search](/docs/sandbox/search) to index the files for keyword or semantic retrieval. See the [filesystem tools reference](/reference/workspace/workspace-class#filesystem-tools) for every generated tool and its policies.

## 坐骑 {/* #mounts */}

使用`mounts` when programs inside a sandbox need to access persistent files by path. Mastra creates the mount automatically when the sandbox and filesystem provider support it. The agent still receives file tools, while command tools can run commands such as `ls`, `cat`, or `python` against the same files.

例如，将 S3 存储桶安装在`/workspace` inside a Daytona sandbox:

```typescript
import { Mastra } from '@mastra/core'
import { Workspace } from '@mastra/core/workspace'
import { DaytonaSandbox } from '@mastra/daytona'
import { S3Filesystem } from '@mastra/s3'

const workspace = new Workspace({
  mounts: {
    '/workspace': new S3Filesystem({
      bucket: process.env.S3_BUCKET!,
      region: 'us-east-1',
    }),
  },
  sandbox: new DaytonaSandbox(),
})

export const mastra = new Mastra({ workspace })
```

### 使用安装座 {/* #using-mounts */}

已通过Provider提供的文件显示在`/workspace`. The agent can call `read_file('/workspace/report.md')` or run `cat /workspace/report.md`. Files written through either interface are saved by the provider and remain available after the sandbox stops.

如果没有挂载，Agent仍然可以通过在Tool调用之间传递文件内容来将文件Tool与Sandbox命令结合起来。这适用于选定的文本文件。当程序需要目录树或需要处理大型文件或二进制文件时，挂载更适合。

：：：警告

文件Tool和命令Tool策略是独立的。需要批准`write_file`, for example, doesn't stop the agent from using `execute_command` to write the same mounted path. If files must only be accessed through file tools, disable sandbox command tools.

:::

### 路径 {/* #paths */}

挂载路径是向文件Tool以及成功Sandbox挂载后的命令公开的路径。底层提供程序可能会将这些文件存储在其他地方。

对于安装在以下位置的远程Provider`/workspace`:

* 文件Tool使用以下路径`/workspace/report.md`.
* 远程Sandbox命令通常使用相同的路径。
* 提供程序将路径映射到其配置的存储桶、前缀或远程目录。

`LocalSandbox`在其内部创建一个符号链接`workingDirectory` instead. A `/workspace` mount becomes `<workingDirectory>/workspace` on the host and is usually addressed as `workspace` by commands.

## 复合文件系统 {/* #composite-filesystem */}

这`mounts` option creates a `CompositeFilesystem`. This TypeScript path router presents several providers as one virtual directory tree.

### 多个文件系统 {/* #multiple-filesystems */}

在其安装路径下配置每个提供程序：

```typescript
import { Workspace } from '@mastra/core/workspace'
import { E2BSandbox } from '@mastra/e2b'
import { GCSFilesystem } from '@mastra/gcs'
import { S3Filesystem } from '@mastra/s3'

const workspace = new Workspace({
  mounts: {
    '/data': new S3Filesystem({
      bucket: 'agent-data',
      region: 'us-east-1',
    }),
    '/reports': new GCSFilesystem({
      bucket: 'agent-reports',
    }),
  },
  sandbox: new E2BSandbox({ id: 'analysis-sandbox' }),
})
```

使用此配置：

* `list_files('/')`返回虚拟目录`data` and `reports`.
* `read_file('/data/input.csv')`到 S3 Provider的路由。
* `write_file('/reports/summary.md')`路由至 Google Cloud Storage Provider。
* 当每个Sandbox挂载成功时，Sandbox命令使用相同的路径。

在将剩余路径传递给其提供者之前，复合材料会去除挂载前缀。挂载路径不能嵌套，因此同一组合不能同时包含两者`/data` and `/data/archive`.

### 没有Sandbox {/* #without-a-sandbox */}

您可以配置`mounts` without a sandbox. Mastra still creates the `CompositeFilesystem`, and all file tools work with mount-prefixed paths. The agent receives no command or process tools because no sandbox is configured.

### 手工构图 {/* #manual-composition */}

您还可以创建一个`CompositeFilesystem` yourself and pass it through `filesystem` for path routing without automatic sandbox mount wiring:

```typescript
import { CompositeFilesystem, LocalFilesystem, Workspace } from '@mastra/core/workspace'
import { S3Filesystem } from '@mastra/s3'

const filesystem = new CompositeFilesystem({
  mounts: {
    '/local': new LocalFilesystem({ basePath: './data' }),
    '/archive': new S3Filesystem({
      bucket: 'agent-archive',
      region: 'us-east-1',
    }),
  },
})

const workspace = new Workspace({ filesystem })
```

当应用程序的另一部分需要组合作为文件系统提供程序时，请使用手动组合。对于正常的Sandbox安装，`mounts` option performs the same routing setup with less configuration.

## 安装可用性 {/* #mount-availability */}

文件Tool和复合路由无需安装Sandbox即可工作。当远程Sandbox和文件系统提供程序支持挂载时，`mounts` automatically uses FUSE to make the files visible to commands. `LocalSandbox` uses symlinks instead.

内置Sandbox安装目前包括：

|沙盒后端 |文件系统Provider |
| - | - |
|`LocalSandbox` | `LocalFilesystem` |
| E2B | Amazon S3, Google Cloud Storage, Azure Blob Storage |
| Daytona | Amazon S3, Google Cloud Storage, Azure Blob Storage |
| Blaxel | Amazon S3, Google Cloud Storage |

远程安装可能需要`s3fs`, `gcsfuse`, or `blobfuse2` inside the sandbox. Some backends install missing software during startup, which can require network access and additional startup time. Other combinations require an [`onMount`](/reference/workspace/workspace-class#constructor-parameters) hook or provider-specific setup.

如果Sandbox安装不可用或失败，Workspace仍然可用。文件Tool继续通过其 SDK 访问提供程序，但命令看不到该路径。 Mastra 向Agent描述这些提供程序只能通过文件Tool使用。

## 每个用户或线程的文件系统 {/* #filesystems-per-user-or-thread */}

这`filesystem` option accepts a resolver when storage should vary by request, user, role, or tenant:

```typescript
const workspace = new Workspace({
  filesystem: ({ requestContext }) => {
    const userId = requestContext.get('user-id') as string

    return new S3Filesystem({
      bucket: process.env.S3_BUCKET!,
      region: process.env.S3_REGION!,
      prefix: `users/${userId}`,
    })
  },
})
```

每个用户都会获得一个单独的文件系统视图，文件Tool会自动从请求上下文中解析提供程序。

`mounts`不接受解析器，并且不能与Sandbox解析器结合使用。当每个用户或线程需要在单独的Sandbox内单独存储时，请在Sandbox解析器内创建并安装提供程序。看[Sandboxes per user or thread](/docs/sandbox/overview#sandboxes-per-user-or-thread).

## 政策和遏制 {/* #policies-and-containment */}

使用下面的单独常数`WORKSPACE_TOOLS.FILESYSTEM`, such as `WORKSPACE_TOOLS.FILESYSTEM.WRITE_FILE`, to configure each file tool. Set approval globally or per tool. Configure read-before-write and output limits on individual filesystem tool entries. See the [filesystem tool configuration reference](/reference/workspace/workspace-class#filesystem-tools).

`LocalFilesystem`包含访问权限`basePath` by default. Use `allowedPaths` when the agent needs specific directories outside that root:

```typescript
const workspace = new Workspace({
  filesystem: new LocalFilesystem({
    basePath: './knowledge-base',
    allowedPaths: ['../shared-policies'],
  }),
})
```

遏制适用于文件系统操作，包括文件Tool和搜索索引。它不限制 shell 命令。

放`readOnly: true` when the agent should use files without changing them. For a static provider, Mastra removes write-related file tools.

使用文件系统解析器，写入Tool保持注册状态，因为在请求运行之前不知道提供程序。提供程序在运行时拒绝写入尝试。

为了`LocalFilesystem` entries in a composite, keep `contained: true`, which is the default. Set `contained: false` only when unrestricted host filesystem access is intentional.
