# 文件系统

文件系统为 Agent 提供读取、写入、列出和[搜索](/docs/sandbox/search)文件的工具。你可以用它搭建知识库，或在临时 Sandbox 的多次运行之间保留文件。

有两种方式配置文件访问：

- [直接访问文件系统](#direct-filesystem-access)：使用 `filesystem` 接入单个文件系统提供方，或接入自行创建的 [`CompositeFilesystem`](#manual-composition)。
- [挂载](#mounts)：使用 `mounts` 将带路径前缀的提供方组成一个 `CompositeFilesystem`。如果静态 Sandbox 和文件系统提供方都支持挂载，Mastra 会自动将提供方挂载到指定路径。远程 Sandbox 通常使用用户空间文件系统（FUSE）挂载。

`filesystem` 和 `mounts` 只能配置其中一个。同时配置会抛出错误码为 `INVALID_CONFIG` 的 `WorkspaceError`。

两种配置都会为 Agent 提供文件工具。只有 Sandbox 成功挂载提供方后，其命令才能访问对应文件。

配置文件系统后，Agent 可使用以下工具：

| 工具 | 用途 |
| - | - |
| `mastra_workspace_read_file` | 读取文件的全部或部分内容。 |
| `mastra_workspace_write_file` | 创建或覆盖文件。 |
| `mastra_workspace_edit_file` | 替换现有文件中匹配的文本。 |
| `mastra_workspace_list_files` | 列出文件和目录。 |
| `mastra_workspace_delete` | 删除文件或目录。 |
| `mastra_workspace_file_stat` | 返回文件或目录的元数据。 |
| `mastra_workspace_mkdir` | 创建目录及所有缺失的父目录。 |
| `mastra_workspace_grep` | 使用正则表达式搜索文件内容。 |
| `mastra_workspace_ast_edit` | 按代码结构应用编辑。安装 `@ast-grep/napi` 后可用。 |
| `mastra_workspace_apply_patch` | 一次调用即可创建、更新、移动和删除多个文件。默认关闭。 |

`apply_patch` 工具需要显式启用。请在 `tools` 中为它单独配置，顶层的 `tools.enabled` 不会将它开启。该工具会先检查补丁中的每项变更，再写入文件：

```typescript title="src/mastra/workspaces/index.ts"
import { Workspace, LocalFilesystem, WORKSPACE_TOOLS } from '@mastra/core/workspace'

export const workspace = new Workspace({
  filesystem: new LocalFilesystem({ basePath: './workspace' }),
  tools: {
    [WORKSPACE_TOOLS.FILESYSTEM.APPLY_PATCH]: { enabled: true },
  },
})
```

[`LocalFilesystem`](/reference/workspace/local-filesystem) 连接到 Mastra 应用所在机器上的目录，适合本地开发，或访问已存放在应用主机上的文件。

### 其他文件系统 {/* #other-filesystems */}

如果文件位于应用主机之外，或已存放在外部服务中，请选用其他提供方：

## 直接访问文件系统 {/* #direct-filesystem-access */}

要让 Agent 通过文件工具访问提供方，请使用 `filesystem`。它也接受解析函数或手动创建的 `CompositeFilesystem`。

以下示例为 Agent 提供操作本地知识库的文件工具：

```typescript
import { LocalFilesystem, Workspace } from '@mastra/core/workspace'

const workspace = new Workspace({
  filesystem: new LocalFilesystem({
    basePath: './knowledge-base',
  }),
})
```

Agent 会获得 `mastra_workspace_read_file`、`mastra_workspace_write_file`、`mastra_workspace_list_files` 和 `mastra_workspace_grep` 等工具。路径在 `./knowledge-base` 下解析，无需 Sandbox 或命令工具。

参阅[搜索](/docs/sandbox/search)，了解如何为文件建立索引以进行关键词或语义检索。所有自动生成的工具及其策略见[文件系统工具参考](/reference/workspace/workspace-class#filesystem-tools)。

## 挂载 {/* #mounts */}

如果 Sandbox 中的程序需要按路径访问持久保存的文件，请使用 `mounts`。当 Sandbox 和文件系统提供方都支持挂载时，Mastra 会自动挂载。Agent 仍会获得文件工具，命令工具也可用 `ls`、`cat` 或 `python` 等命令操作同一批文件。

例如，将 S3 存储桶挂载到 Daytona Sandbox 中的 `/workspace`：

```typescript
import { Mastra } from '@mastra/core'
import { Workspace } from '@mastra/core/workspace'
import { DaytonaSandbox } from '@mastra/daytona'
import { S3Filesystem } from '@mastra/s3'

const workspace = new Workspace({
  mounts: {
    '/workspace': new S3Filesystem({
      bucket: process.env.S3_BUCKET!,
      region: 'us-east-1',
    }),
  },
  sandbox: new DaytonaSandbox(),
})

export const mastra = new Mastra({ workspace })
```

### 使用挂载 {/* #using-mounts */}

提供方已有的文件会出现在 `/workspace` 下。Agent 可以调用 `read_file('/workspace/report.md')` 或运行 `cat /workspace/report.md`。通过任一接口写入的文件都会由提供方保存，在 Sandbox 停止后仍可访问。

没有挂载时，Agent 仍可在工具调用间传递文件内容，将文件工具和 Sandbox 命令配合使用。这种方式适合部分文本文件。程序需要目录树，或需要处理大型文件或二进制文件时，挂载更合适。

:::warning

文件工具和命令工具的策略相互独立。例如，即使 `write_file` 需要审批，Agent 仍可用 `execute_command` 写入同一挂载路径。如果只允许通过文件工具访问文件，请禁用 Sandbox 的命令工具。

:::

### 路径 {/* #paths */}

挂载路径会提供给文件工具，在 Sandbox 中成功挂载后也会提供给命令。底层提供方可能将文件存储在别处。

以挂载到 `/workspace` 的远程提供方为例：

- 文件工具使用 `/workspace/report.md` 这样的路径。
- 远程 Sandbox 命令通常使用同一路径。
- 提供方将路径映射到配置的存储桶、前缀或远程目录。

`LocalSandbox` 则会在 `workingDirectory` 内创建符号链接。挂载路径 `/workspace` 在主机上对应 `<workingDirectory>/workspace`，命令通常以 `workspace` 访问。

## 组合文件系统 {/* #composite-filesystem */}

`mounts` 选项会创建 `CompositeFilesystem`。这是一个用 TypeScript 实现的路径路由器，将多个提供方呈现为一棵虚拟目录树。

### 多个文件系统 {/* #multiple-filesystems */}

在各自的挂载路径下配置提供方：

```typescript
import { Workspace } from '@mastra/core/workspace'
import { E2BSandbox } from '@mastra/e2b'
import { GCSFilesystem } from '@mastra/gcs'
import { S3Filesystem } from '@mastra/s3'

const workspace = new Workspace({
  mounts: {
    '/data': new S3Filesystem({
      bucket: 'agent-data',
      region: 'us-east-1',
    }),
    '/reports': new GCSFilesystem({
      bucket: 'agent-reports',
    }),
  },
  sandbox: new E2BSandbox({ id: 'analysis-sandbox' }),
})
```

使用此配置时：

- `list_files('/')` 返回虚拟目录 `data` 和 `reports`。
- `read_file('/data/input.csv')` 路由到 S3 提供方。
- `write_file('/reports/summary.md')` 路由到 Google Cloud Storage 提供方。
- 相应路径在 Sandbox 中成功挂载后，Sandbox 命令也会使用相同路径。

组合文件系统会去掉挂载前缀，再将剩余路径传给对应的提供方。挂载路径不能嵌套，因此同一个组合文件系统不能同时包含 `/data` 和 `/data/archive`。

### 不使用 Sandbox {/* #without-a-sandbox */}

不配置 Sandbox 也可以使用 `mounts`。Mastra 仍会创建 `CompositeFilesystem`，所有文件工具都能使用带挂载前缀的路径。由于未配置 Sandbox，Agent 不会获得命令或进程工具。

### 手动组合 {/* #manual-composition */}

你也可以自行创建 `CompositeFilesystem`，通过 `filesystem` 传入，即可路由路径，无需自动配置 Sandbox 挂载：

```typescript
import { CompositeFilesystem, LocalFilesystem, Workspace } from '@mastra/core/workspace'
import { S3Filesystem } from '@mastra/s3'

const filesystem = new CompositeFilesystem({
  mounts: {
    '/local': new LocalFilesystem({ basePath: './data' }),
    '/archive': new S3Filesystem({
      bucket: 'agent-archive',
      region: 'us-east-1',
    }),
  },
})

const workspace = new Workspace({ filesystem })
```

当应用的其他部分需要将组合文件系统作为提供方时，使用手动组合。对于常规 Sandbox 挂载，`mounts` 选项能用更少的配置实现相同的路由。

## 挂载支持 {/* #mount-availability */}

文件工具和组合路由无需 Sandbox 挂载即可使用。如果远程 Sandbox 和文件系统提供方都支持挂载，`mounts` 会自动使用 FUSE，让命令可以访问文件。`LocalSandbox` 则使用符号链接。

内置的 Sandbox 挂载目前支持以下组合：

| Sandbox 后端 | 文件系统提供方 |
| - | - |
| `LocalSandbox` | `LocalFilesystem` |
| E2B | Amazon S3, Google Cloud Storage, Azure Blob Storage |
| Daytona | Amazon S3, Google Cloud Storage, Azure Blob Storage |
| Blaxel | Amazon S3, Google Cloud Storage |

远程挂载可能需要在 Sandbox 内安装 `s3fs`、`gcsfuse` 或 `blobfuse2`。部分后端会在启动时安装缺失软件，可能需要网络访问，并延长启动时间。其他组合需要 [`onMount`](/reference/workspace/workspace-class#constructor-parameters) 钩子或提供方专用的配置。

无法挂载或挂载失败时，Workspace 仍可使用。文件工具会继续通过提供方的 SDK 访问文件，但命令无法访问该路径。Mastra 会告知 Agent，这些提供方只能通过文件工具访问。

## 按用户或线程划分文件系统 {/* #filesystems-per-user-or-thread */}

如果要根据请求、用户、角色或租户选择存储，`filesystem` 选项可以接收解析函数：

```typescript
const workspace = new Workspace({
  filesystem: ({ requestContext }) => {
    const userId = requestContext.get('user-id') as string

    return new S3Filesystem({
      bucket: process.env.S3_BUCKET!,
      region: process.env.S3_REGION!,
      prefix: `users/${userId}`,
    })
  },
})
```

每个用户都有独立的文件系统视图，文件工具会根据请求上下文自动解析对应的提供方。

`mounts` 不接受解析函数，也不能与 Sandbox 的解析函数一起使用。如果每个用户或线程都需要独立的 Sandbox 和存储，请在 Sandbox 解析函数中创建并挂载提供方。参阅[按用户或线程划分 Sandbox](/docs/sandbox/overview#sandboxes-per-user-or-thread)。

## 策略和访问范围 {/* #policies-and-containment */}

使用 `WORKSPACE_TOOLS.FILESYSTEM` 下的常量（如 `WORKSPACE_TOOLS.FILESYSTEM.WRITE_FILE`）逐一配置文件工具。审批可全局设置，也可按工具设置。在各文件系统工具的配置项内设置先读后写和输出限制。详情见[文件系统工具配置参考](/reference/workspace/workspace-class#filesystem-tools)。

`LocalFilesystem` 默认将访问限制在 `basePath` 内。如果 Agent 需要访问该根目录之外的特定目录，请使用 `allowedPaths`：

```typescript
const workspace = new Workspace({
  filesystem: new LocalFilesystem({
    basePath: './knowledge-base',
    allowedPaths: ['../shared-policies'],
  }),
})
```

此访问范围限制适用于文件系统操作，包括文件工具和搜索索引，不限制 Shell 命令。

如果 Agent 只能读取文件，请设置 `readOnly: true`。对于静态提供方，Mastra 会移除与写入相关的文件工具。

使用文件系统解析函数时，只有处理请求时才能确定提供方，因此写入工具仍会注册。提供方会在运行时拒绝写入。

对于组合文件系统中的 `LocalFilesystem` 条目，请保留默认设置 `contained: true`。只有确实要允许不受限制地访问主机文件系统时，才设置 `contained: false`。
