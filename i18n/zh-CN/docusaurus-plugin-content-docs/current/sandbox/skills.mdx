# 基于文件系统的 Skill

基于文件系统的 Skill 由包含可复用指令和辅助文件的目录组成。Mastra 按 `skills` 选项中的路径查找这些 Skill，使用该配置的所有 Agent 都可以使用它们。Skill 遵循 [Agent Skills 规范](https://agentskills.io)。

如果要在单个 Agent 的代码中直接定义 Skill，请使用 [Agent Skill](/docs/skills)。同一个 Agent 可以使用两种 Skill；名称冲突时，直接定义的 Agent Skill 优先。

## 快速入门 {/* #quickstart */}

创建一个包含 `SKILL.md` 文件的目录：

```markdown title="workspace/skills/code-review/SKILL.md"
---
name: code-review
description: Reviews code for bugs and readability issues
---

# Code review

Check the code for bugs, missing error handling, and unclear naming.
```

配置该目录：

```typescript title="src/mastra/workspaces.ts"
import { LocalFilesystem, Workspace } from '@mastra/core/workspace'

export const workspace = new Workspace({
  filesystem: new LocalFilesystem({
    basePath: './workspace',
  }),
  skills: ['skills'],
})
```

`skills` 中的路径相对于文件系统根目录，因此 Mastra 会找到 `./workspace/skills/code-review/SKILL.md`。使用此配置的 Agent 可以在请求需要时查找并加载 `code-review`。

## Skill 结构 {/* #skill-structure */}

每个 Skill 对应一个目录，必须包含 `SKILL.md`，也可以包含辅助文件：

```plaintext title="workspace/skills/code-review"
code-review/
  SKILL.md
  references/
    style-guide.md
  scripts/
    lint.ts
  assets/
    review-template.md
```

- `SKILL.md`：元数据和指令，Mastra 在 Agent 选用该 Skill 时加载
- `references/`：Agent 可按需阅读或搜索的文档
- `scripts/`：Skill 使用的脚本
- `assets/`：模板、图片等辅助文件

将主要流程写在 `SKILL.md` 中，详细资料放在 `references/` 中，供 Agent 按需读取。

## `SKILL.md` 格式 {/* #skillmd-format */}

YAML frontmatter 必须包含 `name` 和 `description`。`name` 必须与 Skill 的目录名一致，最多 64 个字符，只能使用小写字母、数字和连字符；连字符不能出现在首尾，也不能连续出现。Markdown 正文是加载 Skill 时返回给 Agent 的指令。

Mastra 也会读取可选字段 `license`、`compatibility`、`user-invocable` 和 `metadata`。完整的包格式和字段说明见 [Agent Skills 规范](https://agentskills.io/specification)。

## Agent 如何使用 Skill {/* #how-agents-use-skills */}

配置 Skill 后，Mastra 会把每个 Skill 的名称、描述、路径和来源类型加入系统消息。这样，Agent 无需将每份指令文件加载到上下文，就能知道有哪些 Skill 可用。

Mastra 还为 Agent 提供三个工具：

| 工具 | 用途 |
| - | - |
| `skill` | 加载 Skill 的 `SKILL.md` 指令，并列出参考资料、脚本和资源文件。 |
| `skill_read` | 读取所选 Skill 目录下任意文件的全部或部分内容。 |
| `skill_search` | 搜索 Skill 的名称、描述、指令和参考文件。 |

加载不保留状态。指令以工具结果的形式留在对话中；如果上下文压缩后不再包含这些指令，Agent 可以再次调用 `skill`。

### 关闭 Skill 列表 {/* #turn-off-the-skills-list */}

Skill 较多时，每次请求在系统消息中列出全部 Skill 都会消耗 token。添加 `SkillsProcessor` 并设置 `injectCatalog: false`，即可用一条简短指令替代列表，引导 Agent 用 `skill_search` 查找 Skill，再用 `skill` 加载：

```typescript title="src/mastra/agents/support-agent.ts"
import { Agent } from '@mastra/core/agent'
import { SkillsProcessor } from '@mastra/core/processors'
import { workspace } from '../workspaces'

export const supportAgent = new Agent({
  id: 'support-agent',
  name: 'Support Agent',
  instructions: 'You help customers with support requests.',
  model: '__GATEWAY_OPENAI_MODEL__',
  workspace,
  inputProcessors: [new SkillsProcessor({ injectCatalog: false })],
})
```

对于基于文件系统的 Skill 和 [Agent Skill](/docs/skills)，Agent 仍可使用 `skill`、`skill_read` 和 `skill_search`。无需配置搜索，`skill_search` 就能将查询词与 Skill 的名称、描述和内容进行匹配。如果 Skill 较多，可以在 Workspace 中配置 [BM25 或向量搜索](#search-skill-content)来改善排序。Agent Skill 始终会被索引。

如果只有几十个 Skill，可以保留默认列表：Agent 一次就能看到所有选项，而且列表作为稳定的前缀，可由 Provider 缓存。如果 Skill 达到约一百个，或需要控制系统消息的长度，可以关闭列表。无论添加多少 Skill，搜索指令的长度都不变。

[`SkillSearchProcessor`](/reference/processors/skill-search-processor) 也会隐藏列表，但它用自己的 `search_skills` 和 `load_skill` 替换标准工具，并且仅支持 Workspace Skill。两种处理器选一种即可；同时配置会让 Agent 获得两套工具。完整选项见 [`SkillsProcessor`](/reference/processors/skills-processor) 参考文档。

## 配置 Skill 路径 {/* #configure-skill-paths */}

`skills` 数组支持多种路径写法：

| 路径 | 查找方式 |
| - | - |
| `skills` | 在每个直属子目录中查找 `SKILL.md` 文件。 |
| `skills/code-review` | 直接加载一个 Skill 目录。 |
| `skills/code-review/SKILL.md` | 直接加载一个 Skill 文件。 |
| `./**/skills` | 找到匹配的目录，再到每个目录中查找 Skill。 |
| `./**/SKILL.md` | 查找并加载匹配的 Skill 文件。 |

可以添加多个条目，从项目、团队或软件包等不同的根目录查找 Skill。

glob 最多向下遍历基准目录下的四级目录。

如果配置了文件系统，Mastra 就在该文件系统中解析路径；否则会以应用进程的当前工作目录为基准，从本地磁盘读取。显式设置 [`skillSource`](#custom-skill-sources) 会替代这两种默认行为。

## 同名 Skill {/* #same-named-skills */}

Mastra 会在系统消息中逐一列出基于文件系统的 Skill，注明路径和来源类型。如果多个 Skill 同名，按名称查找时采用以下优先顺序：

1. 本地项目路径
1. `.mastra/skills` 下的托管路径
1. `node_modules` 下的外部路径

如果优先级最高的候选项中有多个来源类型相同的 Skill，Mastra 无法选择，会抛出错误。请重命名其中一个 Skill，或将其移到另一种来源。

Agent 可以将系统消息中的确切路径传给 `skill` 或 `skill_read`，跳过按名称查找。路径末尾可以带上或省略 `/SKILL.md`。如果配置中的多条路径解析到同一个规范目录，Mastra 会将它们视为别名，只列一次该 Skill。

直接定义的 [Agent Skill](/docs/skills) 先于基于文件系统的 Skill 解析。两者同名时，直接定义的 Skill 优先。

## 搜索 Skill 内容 {/* #search-skill-content */}

同时配置 Skill 和 [BM25 或向量搜索](/docs/sandbox/search) 后，Mastra 会自动索引每个 Skill 的名称、描述、`SKILL.md` 指令和参考文件。脚本和资源文件不纳入索引。

未配置 BM25 或向量搜索时，`skill_search` 会在名称、描述、指令和参考资料中进行不区分大小写的文本匹配。结果按命中的查询词数量排序，名称或描述中的命中权重更高。这样无需单独配置也能搜索 Skill；Skill 较多时，索引搜索可以提供结果排序与语义检索。

来自参考文件的结果包含文件路径，例如 `references/style-guide.md`，Agent 可以将其传给 `skill_read`。

Agent 查找不存在的 Skill 名称时，如果可用的 Skill 不超过 20 个，`skill` 和 `skill_read` 会全部列出。超过 20 个时，它们最多推荐五个相近结果，并提示 Agent 使用 `skill_search`，避免因名称输错而把整份列表加到对话中。

## 动态 Skill 路径 {/* #dynamic-skill-paths */}

如果可用路径取决于请求上下文，可传入同步或异步函数。以下示例为拥有 `developer` 角色的用户添加开发用的 Skill：

```typescript title="src/mastra/workspaces.ts"
import { LocalFilesystem, Workspace } from '@mastra/core/workspace'

const workspace = new Workspace({
  filesystem: new LocalFilesystem({ basePath: './workspace' }),
  skills: ({ requestContext }) => {
    const paths = ['skills']

    if (requestContext?.get('user-role') === 'developer') {
      paths.push('developer-skills')
    }

    return paths
  },
})
```

Mastra 每次执行时都会求值该函数，并将该请求对应的 Skill 集合提供给 Agent。返回的路径和静态数组一样，支持目录、文件和 glob。

## 自定义 Skill 来源 {/* #custom-skill-sources */}

如果 Skill 要来自已配置文件系统或本地磁盘以外的后端，请设置 `skillSource`。自定义来源负责按每条配置的路径查找 Skill 和读取文件。

例如，`CompositeVersionedSkillSource` 会从内容寻址的 Blob 存储挂载已发布的 Skill 版本，放到 Mastra 能查找到的目录下：

```typescript title="src/mastra/workspaces.ts"
import { CompositeVersionedSkillSource, Workspace } from '@mastra/core/workspace'

const skillSource = new CompositeVersionedSkillSource(
  [
    {
      dirName: 'code-review',
      tree: versionTree,
      versionCreatedAt,
    },
  ],
  blobStore,
)

const workspace = new Workspace({
  skills: ['.'],
  skillSource,
})
```

显式设置 `skillSource` 后，如果路径不存在，Mastra 不会回退到已配置的文件系统或本地磁盘。来源接口和相关选项见[配置参考](/reference/workspace/workspace-class#constructor-parameters)。
