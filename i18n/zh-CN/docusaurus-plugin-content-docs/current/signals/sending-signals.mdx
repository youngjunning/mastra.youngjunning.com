# 发送信号

用户有话要说时，发送消息；需要先完成当前回答时，将后续消息排入队列；应用需要补充上下文时，发送带类型的信号。三种方式都以线程为目标。通过[线程流](/docs/signals/thread-streams)接收 Agent 的输出。

示例使用[概览中的快速入门](/docs/signals/overview#quickstart)所创建的 `Agent` 和线程。要调用运行中服务器上的 Agent，请使用[客户端 SDK](/reference/client-js/agents) 或[服务器路由](/reference/server/routes#agent-message-routes)。方法参数和返回值见 [Agent 参考](/reference/agents/agent#thread-signals)。

## 发送消息 {/* #send-a-message */}

发送用户输入时，将线程标识符传给 [`sendMessage()`](/reference/agents/agent#sendmessagemessage-options)：

```typescript title="src/mastra/signals.ts"
const result = agent.sendMessage('Compare that with the previous option.', {
  resourceId: 'user_123',
  threadId: 'thread_456',
})

await result.accepted
```

`sendMessage()` 会立即返回。等待 `result.accepted` 可取得 Mastra 的路由决定，并捕获路由错误。可能的操作见[控制输入的投递时机](#control-when-input-arrives)。

Mastra 会先检查线程。空闲线程会启动一次运行；如果已有运行在进行，消息会交给该运行，模型会在下次请求时看到它。配置 Memory 后，消息会被保存，供后续运行和界面使用。中断行为见 [Agent 何时看到输入](#when-the-agent-sees-your-input)。

多人共用一个线程时，添加 `attributes`：

```typescript
const result = agent.sendMessage(
  {
    contents: 'Use the latest customer note too.',
    attributes: { name: 'Jane', sentFrom: 'slack' },
  },
  { resourceId: 'user_123', threadId: 'thread_456' },
)

await result.accepted
```

模型收到的是 `<user name="Jane" sentFrom="slack">Use the latest customer note too.</user>`。

## 将后续消息排入队列 {/* #queue-a-follow-up */}

如果要等当前回答完成后再让 Agent 看到下一条消息，请用 [`queueMessage()`](/reference/agents/agent#queuemessagemessage-options)：

```typescript title="src/mastra/signals.ts"
const result = agent.queueMessage('Also check whether the tests need updates.', {
  resourceId: 'user_123',
  threadId: 'thread_456',
})

await result.accepted
```

排队的输入会等当前运行结束，再启动一次新运行。如果线程空闲，会立即启动。[ `cancelQueuedMessages()`](/reference/agents/agent#cancelqueuedmessagesoptions) 可移除排队输入，不会停止正在进行的运行。跨进程取消仅尽力而为，且不会撤销已接受的输入。

[`queueSignal()`](/reference/agents/agent#queuesignalsignal-options) 用相同的方式将带类型的上下文排入队列，并保留信号的 `type`、`tagName` 和属性。

## 从系统发送上下文 {/* #send-context-from-a-system */}

用 [`sendSignal()`](/reference/agents/agent#sendsignalsignal-options) 补充应用中的上下文，例如后台任务的结果。信号类型和 XML 标签用于标识这些上下文：

```typescript title="src/mastra/signals.ts"
const result = agent.sendSignal(
  {
    type: 'reactive',
    tagName: 'ci-result',
    contents: 'CI failed on main: 3 tests failed.',
  },
  { resourceId: 'user_123', threadId: 'thread_456' },
)

await result.accepted
```

`type` 表示来源：`reactive` 对应系统或处理器的上下文，`notification` 对应外部事件。`tagName` 指定 XML 标签；未指定时，Mastra 使用类型名称，但 `reactive` 默认使用 `system-reminder`。

Mastra 原样传递 `contents`，并对属性值进行 XML 转义。与信号自身标签匹配的结束标签也会被转义，避免内容提前闭合元素。这无法防御提示词注入，请将转发的第三方文本视为不可信。为确保符合 XML 规则，`tagName` 和属性名只能包含字母、数字、句点、连字符或下划线，并且必须以字母或下划线开头。

与 `sendMessage()` 一样，`sendSignal()` 默认会投递输入。设置 `transient: true` 可让上下文只用于当前请求；Mastra 不会保存它，且临时信号不能是状态信号。有关 `attributes`、`metadata` 和 `providerOptions`，见 [Agent 参考](/reference/agents/agent#sendsignalsignal-options)。

## 在对话结束后保留输入 {/* #input-that-outlives-the-conversation */}

如果事件需要在收件箱中持久保存、按策略投递并供稍后读取，请使用 [`sendNotificationSignal()`](/reference/agents/agent#sendnotificationsignalnotification-options)。它也可以合并相关的待处理事件。调用 [`sendSignal({ type: 'notification' })`](/reference/agents/agent#sendsignalsignal-options) 只会添加上下文，不会创建收件箱记录。设置和投递规则见[通知](/docs/signals/notifications)。

对于随时间变化的具名上下文，例如浏览器当前页面，请用 [`sendStateSignal()`](/reference/agents/agent#sendstatesignalstate-options)。它发送完整快照或变更说明，无需添加聊天消息。如何保持上下文最新，见[状态信号](/docs/signals/state-signals)。

## 控制输入的投递时机 {/* #control-when-input-arrives */}

应用通常可以沿用默认行为：运行中的线程接收输入，空闲线程被唤醒。只有需要不同结果时才覆盖默认设置。

| 线程状态 | 默认行为 | 其他选项 |
| - | - | - |
| 运行中 | 投递给当前运行 | 保存但不投递，或丢弃 |
| 空闲 | 唤醒并启动新运行 | 保存但不运行，或丢弃 |

通过 `ifActive.behavior` 或 `ifIdle.behavior` 设置行为。例如，如果希望下次能读取某个事件，又不希望它自行启动运行，可以将其持久保存：

```typescript title="src/mastra/signals.ts"
const result = agent.sendSignal(
  {
    type: 'notification',
    contents: 'A new pull request is ready for review.',
  },
  {
    ...thread,
    ifIdle: { behavior: 'persist' },
  },
)

const { action } = await result.accepted

if (action === 'persist') {
  await result.persisted
}
```

此处只有线程空闲时才会保存输入。线程正在运行时，输入仍投递给当前运行，因此只有操作为 `persist` 时才会设置 `persisted`。

发送消息或信号会返回一个 `accepted` Promise。Mastra 决定如何处理输入时，它就会兑现，无需等待运行结束。`sendNotificationSignal()` 仅在其投递策略发出信号时才包含 `accepted`，因此请先检查 `decision`。`sendStateSignal()` 跳过未变化的快照时也会省略它。

`accepted` Promise 会兑现为以下操作之一：

- `wake`：当前进程已为此输入启动一次运行。
- `deliver`：输入已投递给某次运行，或另一个进程已接手启动运行。
- `persist`：输入将被保存，不投递，也不启动新运行。等待 `persisted` 确认写入。
- `discard`：输入已丢弃。
- `blocked`：线程中有暂停的运行，Mastra 无法启动新运行。

操作为 `wake` 时，结果包含该次运行的 `output` 流。运行启动后如果失败，错误会通过该流报告。路由失败则会拒绝 `accepted`。使用 [`persisted`](/reference/agents/agent#sendsignalsignal-options) 等待存储写入。

## Agent 何时看到输入 {/* #when-the-agent-sees-your-input */}

如果输入在模型请求期间到达，Mastra 可以取消该请求，并带上新输入重试。模型尚在等待首个 token，或只输出推理或元数据时，请求仍可中断。一旦模型输出文本、工具调用或其他内容，中断窗口便会关闭。重试在同一次运行的同一步骤中进行，使用新输入，不把被丢弃的响应写入历史记录。重试不占用 `maxSteps` 额度，也不改变 `stepNumber`。中断没有单独的次数限制，因此反复输入可能持续重启推理，直到请求完成、运行取消或超时。

请求一旦产生文本、工具调用或其他内容，就不再允许中断。之后到达的输入需要等到下一轮循环；正在运行的工具不会被取消或重复执行，排队的输入也不会插队。如果先达到 `maxSteps`，Mastra 可能保存排队输入，但不给出响应。

已经流式传输的推理内容可能继续显示，直到客户端重新加载历史记录。输入处理器会在请求取消前执行完毕；输出处理器会在下一次请求前结束，其副作用仍然保留。总用量不计入中断的请求，不过 Provider 仍可能计费。

模型以 XML 元素接收信号：`<user>`、表示响应式上下文的 `<system-reminder>`，以及表示外部事件的 `<notification>`。配置 Memory 后，已接受的非临时信号会写入线程历史记录。[状态信号](/docs/signals/state-signals)和[通知](/docs/signals/notifications)各有自己的格式。

## 停止运行或清除排队输入 {/* #stop-a-run-or-clear-queued-input */}

中止运行默认保留排队输入。要一并清除队列，请传入 `clearPendingSignals: true`：

```typescript
subscription.abort({ clearPendingSignals: true })
```

如果没有订阅，调用 [`agent.abortThreadStream()`](/reference/agents/agent#abortthreadstreamoptions) 并传入相同选项。监听器会保持订阅，之后的消息仍可启动运行。使用共享 PubSub 时，清除请求会送到负责处理的进程，但只清除该进程的本地队列。中止和取消都不会撤销已兑现的接受结果。后续延续运行彼此独立，中止原运行不会取消它们。

## AgentController 与 Session {/* #agentcontroller-and-session */}

大多数应用直接使用 `Agent` 的方法。AgentController 的 `Session` 封装这些方法，并管理订阅：

| 任务 | `Agent` | AgentController `Session` |
| - | - | - |
| 发送用户消息 | `agent.sendMessage()` | `session.sendMessage()` |
| 将用户的后续消息排队 | `agent.queueMessage()` | `session.queueMessage()` |
| 发送带类型的信号 | `agent.sendSignal()` | `session.sendSignal()` |
| 将带类型的信号排队 | `agent.queueSignal()` | `session.queueSignal()` |
| 发送通知 | `agent.sendNotificationSignal()` | `session.sendNotificationSignal()` |
| 写入状态信号 | `agent.sendStateSignal()` | `Session` 未提供此方法 |
| 订阅线程 | `agent.subscribeToThread()` | 由 `Session` 管理 |

有关 `Session` 如何管理线程和订阅，见 [Agent Controller](/docs/harness/agent-controller)。
