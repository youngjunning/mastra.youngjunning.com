# 发送信号

当用户有话要说时发送消息，当当前答案应该首先完成时排队跟进，或者当应用程序需要添加上下文时发送键入的信号。这三个目标都针对一个线程。您通过其接收Agent的输出[thread stream](/docs/signals/thread-streams).

这些示例使用`Agent` and thread from the [overview quickstart](/docs/signals/overview#quickstart)。要调用正在运行的服务器上的Agent，请使用[客户端SDK](/reference/client-js/agents)或者[服务器路由](/reference/server/routes#agent-message-routes)。这[Agent参考](/reference/agents/agent#thread-signals)列出方法参数和返回值。

## 发送消息 {/* #send-a-message */}

将线程标识符传递给[`sendMessage()`](/reference/agents/agent#sendmessagemessage-options) for user input:

```typescript title="src/mastra/signals.ts"
const result = agent.sendMessage('Compare that with the previous option.', {
  resourceId: 'user_123',
  threadId: 'thread_456',
})

await result.accepted
```

`sendMessage()`立即返回。等待`result.accepted` to wait for Mastra's routing decision and catch routing failures. [Control when input arrives](#control-when-input-arrives) lists the possible actions.

Mastra 首先检查线程。空闲线程开始运行。活动运行会获取该消息，并且模型会在下一个请求时看到该消息。通过内存，可以存储它以供以后运行和用户界面使用。[When the agent sees your input](#when-the-agent-sees-your-input) covers interruption.

添加`attributes` when several people share a thread:

```typescript
const result = agent.sendMessage(
  {
    contents: 'Use the latest customer note too.',
    attributes: { name: 'Jane', sentFrom: 'slack' },
  },
  { resourceId: 'user_123', threadId: 'thread_456' },
)

await result.accepted
```

该模型接收`<user name="Jane" sentFrom="slack">Use the latest customer note too.</user>`.

## 排队跟进 {/* #queue-a-follow-up */}

使用[`queueMessage()`](/reference/agents/agent#queuemessagemessage-options) when the current answer should finish before the agent sees the next message:

```typescript title="src/mastra/signals.ts"
const result = agent.queueMessage('Also check whether the tests need updates.', {
  resourceId: 'user_123',
  threadId: 'thread_456',
})

await result.accepted
```

排队输入等待活动运行完成，然后开始新的运行。在空闲线程上，它立即启动。[`cancelQueuedMessages()`](/reference/agents/agent#cancelqueuedmessagesoptions) removes queued input without stopping the active run. Cancellation is best-effort across processes and doesn't revoke accepted input.

[`queueSignal()`](/reference/agents/agent#queuesignalsignal-options)具有相同行为的队列类型上下文，但保留信号的`type`, `tagName`, and attributes.

## 从系统发送上下文 {/* #send-context-from-a-system */}

使用[`sendSignal()`](/reference/agents/agent#sendsignalsignal-options) to add context from your application, such as a background job result. The signal's type and XML tag identify the context:

```typescript title="src/mastra/signals.ts"
const result = agent.sendSignal(
  {
    type: 'reactive',
    tagName: 'ci-result',
    contents: 'CI failed on main: 3 tests failed.',
  },
  { resourceId: 'user_123', threadId: 'thread_456' },
)

await result.accepted
```

`type`描述来源：`reactive` for context from your system or a processor, `notification` for an external event. `tagName` sets the XML tag; without it Mastra uses the type name, except `reactive` defaults to `system-reminder`.

马斯特拉山口`contents` as written and XML-escapes attribute values. A closing tag matching the signal's own tag is escaped so content can't end it early; this isn't a prompt-injection defense, so treat forwarded third-party text as untrusted. Use XML-safe `tagName` and attribute names with letters, numbers, periods, hyphens, or the underscore character, starting with a letter or underscore.

喜欢`sendMessage()`, `sendSignal()` delivers by default. Set `transient: true` to apply context only to the current request; Mastra doesn't store it, and transient signals can't be state signals. The [Agent reference](/reference/agents/agent#sendsignalsignal-options) covers `attributes`, `metadata`, and `providerOptions`.

## 比对话更持久的输入 {/* #input-that-outlives-the-conversation */}

使用[`sendNotificationSignal()`](/reference/agents/agent#sendnotificationsignalnotification-options) when an event needs a durable inbox record, delivery policy, and later reading. It can also merge related pending events. Sending [`sendSignal({ type: 'notification' })`](/reference/agents/agent#sendsignalsignal-options) adds context without creating an inbox record. See [Notifications](/docs/signals/notifications) for the setup and delivery rules.

使用[`sendStateSignal()`](/reference/agents/agent#sendstatesignalstate-options) for named context that changes over time, such as the current browser page. Instead of adding a chat message, you send a full snapshot or a description of what changed. [State signals](/docs/signals/state-signals) explains how to keep that context current.

## 控制输入​​何时到达 {/* #control-when-input-arrives */}

应用程序通常保留默认值：活动线程接收输入并唤醒空闲线程。覆盖它们只会得到不同的结果。

|线程状态 |默认 |其他选项 |
| - | - | - |
|活跃|交付到活动运行 |坚持不交付，或者丢弃 |
|闲置|唤醒新的奔跑 |坚持不跑，或者放弃 |

设置行为`ifActive.behavior` or `ifIdle.behavior`. For example, an event that should be available next time but shouldn't start a run on its own can be persisted:

```typescript title="src/mastra/signals.ts"
const result = agent.sendSignal(
  {
    type: 'notification',
    contents: 'A new pull request is ready for review.',
  },
  {
    ...thread,
    ifIdle: { behavior: 'persist' },
  },
)

const { action } = await result.accepted

if (action === 'persist') {
  await result.persisted
}
```

只有空闲线程才会保留在这里。活动线程仍然会传递给正在运行的运行，因此`persisted` is set only when the action is `persist`.

消息和信号发送返回`accepted` promise. It resolves when Mastra decides what to do, not when a run finishes. `sendNotificationSignal()` includes `accepted` only when its delivery policy emits a signal, so check `decision` first. `sendStateSignal()` omits it when it skips an unchanged snapshot.

这`accepted` promise resolves with one of these actions:

* `wake`：此过程开始运行输入。
* `deliver`：输入已发送到运行，或者另一个进程接受了启动运行的责任。
* `persist`：输入将被存储，无需交付或重新运行。等待`persisted` to confirm the write.
* `discard`: 输入已被删除。
* `blocked`：暂停的运行阻止 Mastra 在线程上启动新的运行。

当动作是`wake`, the result carries the run's `output` stream. A run that fails after starting reports the error there. A routing failure rejects `accepted`. Use [`persisted`](/reference/agents/agent#sendsignalsignal-options) to wait for a storage write.

## 当Agent看到您的输入时 {/* #when-the-agent-sees-your-input */}

当模型请求期间输入到达时，Mastra 可以取消该请求并使用新输入重试。当模型仅生成推理或元数据或等待其第一个标记时，中断窗口保持打开状态。当模型生成文本、Tool调用或其他内容时，它会关闭。替换在同一运行和步骤中使用新输入重试，并将丢弃的响应保留在历史记录之外。它没有添加任何内容`maxSteps` and leaves `stepNumber` unchanged. There's no separate interruption limit, so repeated input can restart reasoning until the request completes, the run is cancelled, or its timeout expires.

一旦请求生成文本、Tool调用或其他内容，该窗口就会关闭。然后输入等待下一个循环边界。正在运行的Tool不会被取消或重复，排队的输入也不会向前跳转。如果`maxSteps` is reached first, Mastra may save queued input without a response.

已经流式传输的推理可能会保持可见，直到客户端重新加载历史记录。输入处理器在请求被取消之前完成；输出处理器在下一个请求之前稳定下来，并且它们的副作用仍然存在。使用总量不包括中断的请求，但Provider可能仍会计费。

信号以 XML 元素的形式到达模型：`<user>`, `<system-reminder>` for reactive context, and `<notification>` for external events. With Memory configured, accepted non-transient signals are written into thread history. [State signals](/docs/signals/state-signals) and [Notifications](/docs/signals/notifications) have their own shapes.

## 停止运行或清除排队的输入 {/* #stop-a-run-or-clear-queued-input */}

默认情况下，中止运行会保留排队的输入。经过`clearPendingSignals: true` to drop the queue too:

```typescript
subscription.abort({ clearPendingSignals: true })
```

没有订阅，请致电[`agent.abortThreadStream()`](/reference/agents/agent#abortthreadstreamoptions) with the same option. Listeners stay subscribed and a later message can start a run. With shared PubSub, the clear request reaches the owning process but clears only its local queue. Neither abort nor cancellation revokes an acceptance that already resolved. Continuations are separate, so aborting the original doesn't cancel them.

## AgentController 和会话 {/* #agentcontroller-and-session */}

大多数应用程序使用`Agent` methods directly. AgentController's `Session` wraps them and manages the subscription:

|任务|`Agent` | AgentController `Session` |
| - | - | - |
| Send a user message | `agent.sendMessage()` | `session.sendMessage()` |
| Queue a user follow-up | `agent.queueMessage()` | `session.queueMessage()` |
| Send a typed signal | `agent.sendSignal()` | `session.sendSignal()` |
| Queue a typed signal | `agent.queueSignal()` | `session.queueSignal()` |
| Send a notification | `agent.sendNotificationSignal()` | `session.sendNotificationSignal()` |
| Write a state signal | `agent.sendStateSignal()` | Not exposed on `Session` |
| Subscribe to a thread | `agent.subscribeToThread()` | Managed by `Session` |

看[Agent Controller](/docs/harness/agent-controller) for how `Session` manages threads and subscriptions.
