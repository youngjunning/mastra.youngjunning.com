# 状态信号

状态信号让模型了解随时间变化的情况，例如用户的浏览器页面或后台任务的进度。它在线程上有一个稳定的名称，例如`browser`，因此更新描述了跨轮的同一上下文。这些更新提供上下文而不是聊天消息。

应用代码、后台任务或集成负责提供更新。这段代码称为**生产者**。它可以发送描述当前完整状态的**快照**，也可以只发送描述变化的**增量**。Mastra 保存更新，并将更新文本纳入模型上下文；比较和合并状态值由生产者负责。

## 状态信号如何工作 {/* #how-state-signals-work */}

状态 `id` 标识的具名槽位也称为**状态通道**。先发一个快照建立通道，只要模型仍有理解增量所需的快照，就可以继续发送增量。如果旧快照已不在模型上下文中，或不确定增量能否说清变化，请发送新快照。

Mastra 记录每个状态 ID 当前的 `cacheKey` 和模式。如果两者都与收到的更新相同，[`sendStateSignal()`](/reference/agents/agent#sendstatesignalstate-options) 会跳过更新并返回 `{ skipped: true, reason: 'unchanged' }`。状态变化时，请更新缓存键。

状态信号是持久的，因此它们可以在以后的回合中存活下来，并且通过共享存储，进程可以重新启动。因为每个接受的更新都会成为上下文，所以在发送之前批量或总结频繁的更改。

用户输入请用 [`sendMessage()`](/reference/agents/agent#sendmessagemessage-options)。如果上下文仅用于一次模型请求，请发送[临时响应式信号](/docs/signals/sending-signals#send-context-from-a-system)。需要持久化收件箱记录和投递策略的外部事件，应通过[通知](/docs/signals/notifications)发送。

## 发送状态信号 {/* #send-a-state-signal */}

调用 `sendStateSignal()` 前，请先为 Agent 配置 [Memory](/docs/memory/overview)，并确认目标线程已存在。与发送用户消息不同，这个调用不能创建尚不存在的线程。

当生产者检测到更改时，发送这些字段：

* `id`：国家名称，例如`browser`.
- `mode`：完整状态用 `snapshot`，仅包含变化时用 `delta`。
* `cacheKey`：用于跳过重复更新的版本标识符。
* `contents`：模型读取的文本。
* `value`：适用于您的应用程序和处理器的可选结构化数据。它不会自动显示给模型。

[Agent 参考](/reference/agents/agent#sendstatesignalstate-options)列出了所有字段和返回值。

```typescript title="src/mastra/browser-watcher.ts"
await agent.sendStateSignal(
  {
    id: 'browser',
    mode: 'snapshot',
    cacheKey: 'browser:https://example.com:3-tabs',
    contents: 'Browser is open. Active tab URL: https://example.com. 3 open tabs.',
    value: {
      activeUrl: 'https://example.com',
      tabCount: 3,
      open: true,
    },
  },
  {
    resourceId: 'user_123',
    threadId: 'thread_456',
  },
)
```

## 计算处理器中的状态 {/* #compute-state-in-a-processor */}

由处理器管理状态通道时，请使用 [`computeStateSignal()`](/reference/processors/processor-interface#computestatesignal)。Mastra 在每个模型输入步骤中调用它一次，时机在 [`processInputStep()`](/reference/processors/processor-interface#processinputstep) 之后、模型请求定稿之前。处理器读取 `activeStateSignals`、最新快照和 `deltasSinceSnapshot`，无变化时返回 `undefined`。执行顺序请见[处理器指南](/docs/agents/processors)。

```typescript title="src/mastra/processors/browser-state.ts"
import type { ComputeStateSignalArgs, Processor } from '@mastra/core/processors'

export const browserStateProcessor: Processor = {
  id: 'browser-state',
  stateId: 'browser',
  computeStateSignal(args: ComputeStateSignalArgs) {
    const browser = readCurrentBrowserState()
    const previous = readMostRecentBrowserState(args.activeStateSignals)
    const changed = previous ? diffBrowserState(previous, browser) : browser
    const shouldRefreshSnapshot = Boolean(args.lastSnapshot && !args.contextWindow.hasSnapshot)

    if (previous && Object.keys(changed).length === 0 && !shouldRefreshSnapshot) {
      return
    }

    const isDelta = Boolean(previous && !shouldRefreshSnapshot)

    return {
      mode: isDelta ? 'delta' : 'snapshot',
      cacheKey: stableBrowserStateCacheKey(browser),
      contents: isDelta ? describeBrowserDelta(changed) : describeBrowserSnapshot(browser),
      value: browser,
      ...(isDelta ? { delta: changed } : {}),
    }
  },
}
```

示例中负责读取浏览器、比较状态、生成缓存键和描述的辅助函数，由应用提供。Mastra 提供 `lastSnapshot` 和 `deltasSinceSnapshot`，必要时从消息历史加载。处理器根据它们确定变更及要发送的文本。

## 内置用途 {/* #built-in-uses */}

Mastra 使用状态信号来实现长期上下文，并且相同的模式适用于您的应用程序：

- [浏览器](/docs/browser)上下文处理器在 `browser` 下维护当前页面和标签页。
* [目标](/docs/harness/goals)保持当前目标`goal` id.
* [任务追踪](/docs/agents/tools#task-tracking)通过存储任务状态[`TaskStateProcessor`](/reference/signals/task-signal-provider).
- 设置 `useStateSignals: true` 后，[工作记忆](/docs/memory/working-memory#opt-in-to-state-signals-experimental)可从系统提示移到 `working-memory` 状态信号中。

## 持久化和截断 {/* #persistence-and-truncation */}

状态信号不能是瞬态的。 Mastra 从持久历史记录中重建跟踪元数据，因此仅传递信号会破坏重复数据删除。通过共享存储，持久状态及其跟踪可以在重新启动后继续存在；如果没有它，新的流程就会在没有通道的情况下开始。

`contextWindow.hasSnapshot` 告诉处理器当前窗口是否已有该通道的快照。如果为 `false`，请返回新的 `snapshot`，让模型在旧状态消息被裁剪后仍能获知当前状态。
