# 信号

**添加于：** `@mastra/core@1.39.0`

你可以随时向 Agent 的[线程](/docs/memory/message-history#threads-and-resources)发送信号，即使 Agent 正在处理任务。输入可以是用户消息、后台任务的更新或外部事件。Mastra 根据每个信号的类型识别它携带的输入。

要连续对话，请通过信号发送输入，通过[线程流](/docs/signals/thread-streams)接收输出。先订阅流，有新输入时再发送。Mastra 默认把输入交给正在执行的运行，线程空闲时则开始一次运行。发送前无需检查 Agent 是否正在运行。

一次性请求可用 [`agent.stream()`](/reference/streaming/agents/stream) 启动运行并直接读取回复。它也能使用 Memory，但不会订阅同一线程的后续运行。

观看 [Mastra 信号概览](https://www.youtube.com/watch?v=7It2y89TVP4)，了解信号如何唤醒长时间运行的 Agent 并引导其执行。

## 快速入门 {/* #quickstart */}

创建一个Agent，订阅一个线程，然后将输入发送到该线程。首先订阅意味着当输入开始运行时订阅已经打开。

### 使用Agent {/* #use-an-agent */}

本例通过 [Memory](/docs/memory/overview) 将线程历史保存到本地 libSQL 数据库，因此后续运行和进程重启后都可继续同一段对话。Memory 可使用任一受支持的存储适配器。线程在首次运行时创建。

```typescript title="src/mastra/signals.ts"
import { Agent } from '@mastra/core/agent'
import { Memory } from '@mastra/memory'
import { LibSQLStore } from '@mastra/libsql'

const agent = new Agent({
  id: 'support-agent',
  name: 'Support Agent',
  instructions: 'Help the user compare options.',
  model: '__GATEWAY_OPENAI_MODEL__',
  memory: new Memory({
    storage: new LibSQLStore({
      id: 'signals-storage',
      url: 'file:./signals.db',
    }),
  }),
})

const thread = {
  resourceId: 'user_123',
  threadId: 'thread_456',
}

const subscription = await agent.subscribeToThread(thread)

const result = agent.sendMessage('Compare that with the previous option.', thread)
await result.accepted

for await (const chunk of subscription.stream) {
  console.log(chunk)
}
```

循环在 Agent 回复时逐块打印输出。运行结束后，订阅仍然有效，可接收同一线程中后续消息触发的输出。不再需要输出时，调用 `subscription.unsubscribe()`。参阅[发送信号](/docs/signals/sending-signals)，了解如何发送后续消息及其他输入。

### 使用客户端SDK {/* #use-the-client-sdk */}

通过 [`client.getAgent()`](/reference/client-js/mastra-client#methods) 操作时顺序相同：先调用 `subscribeToThread()`，然后向同一线程发送消息。客户端返回订阅流，运行仍由服务器管理。完整客户端示例见[线程流](/docs/signals/thread-streams)。

## 信号如何到达线程 {/* #how-signals-reach-a-thread */}

将输入发送到活动运行并不总是立即中断模型。 Mastra 会等待，直到运行可以接受它。如果当前的答案需要先完成，请改为排队后续答案。您还可以存储输入以供以后使用，而无需开始运行，或者根据线程的状态丢弃它。

[发送信号](/docs/signals/sending-signals#when-the-agent-sees-your-input)介绍了这些投递方式以及如何检查输入是否已被接收。如果应用使用多个进程运行，请[配置共享后端](/docs/signals/running-across-processes)，确保信号能送到管理线程的进程。

## 选择 API 界面 {/* #choose-an-api-surface */}

|表面|用它来 |规范参考|
| - | - | - |
| 直接调用 `Agent` 方法 | 持有 Agent 实例的服务器端代码 | [Agent 参考](/reference/agents/agent#thread-signals) |
| HTTP or the JavaScript client SDK | Applications that call a running Mastra server | [Server agent routes](/reference/server/routes#agent-message-routes), [`client.getAgent()`](/reference/client-js/agents) |
| AgentController `Session` | Long-running assistants and coding agents built on AgentController | [Agent Controller](/docs/harness/agent-controller) |

代码和 Agent 在同一侧运行时，先用 `Agent` 方法；代码需要调用服务器时，使用客户端 SDK。如果你已使用 [Agent Controller](/docs/harness/agent-controller)，其 `Session` 会管理线程和订阅。
