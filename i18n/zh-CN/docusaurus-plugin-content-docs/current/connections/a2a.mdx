# A2A (Agent-to-Agent)

Mastra 支持 [Agent-to-Agent (A2A) 协议](https://a2a-protocol.org/latest/) 0.3.0 版，可用于跨平台多 Agent 系统。通过 A2A，可以将 Mastra Agent 开放为远程 Agent，或将远程 A2A Agent 用作 Mastra 子 Agent。也可以使用 JavaScript 客户端 SDK 调用 A2A 端点。

A2A 是一种开放协议，用于跨网络、框架、厂商和语言边界向 Agent 委托工作。远程 Agent 无须公开自己的工具、提示词、记忆、Workflow 和基础设施，只需提供可供其他系统发现和调用的协议端点。

## 何时使用 A2A {/* #when-to-use-a2a */}

- 父 Agent 需要将工作委托给专门的远程 Agent。
- 远程 Agent 属于另一项服务、团队、厂商或运行时。
- 后端、浏览器应用或其他兼容 A2A 的系统需要通过程序访问 Mastra Agent。
- 长时间运行的远程任务需要任务 ID、状态更新、产出物、取消操作、重新订阅或推送通知。

## A2A 的运作方式 {/* #how-a2a-works */}

A2A 使用 Agent 卡片进行发现。卡片是通过约定的公开 URL 提供的 JSON 文档，描述远程 Agent，并包含接收 A2A JSON-RPC 请求的执行 URL。

使用 Mastra Server 默认的 `apiPrefix` 值 `/api` 时，注册为 `weather-agent` 的 Agent 会开放：

- Agent 卡片：`/api/.well-known/weather-agent/agent-card.json`
- 执行端点：`/api/a2a/weather-agent`

Agent 卡片包含 Agent 名称、描述、端点 URL、提供方、能力、安全元数据和技能等字段：

```json title="agent-card.json"
{
  "protocolVersion": "0.3.0",
  "name": "Weather Agent",
  "description": "Provides weather information.",
  "url": "https://agent.example.com/api/a2a/weather-agent",
  "version": "1.0",
  "provider": {
    "organization": "Acme",
    "url": "https://acme.example.com"
  },
  "capabilities": {
    "streaming": true,
    "pushNotifications": true,
    "stateTransitionHistory": false
  },
  "defaultInputModes": ["text/plain"],
  "defaultOutputModes": ["text/plain"],
  "skills": [
    {
      "id": "weather",
      "name": "weather",
      "description": "Gets weather conditions for a location.",
      "tags": ["tool"]
    }
  ]
}
```

A2A 用消息和任务表示工作。消息由文本、文件或结构化数据片段组成。

任务是带有 ID 和生命周期状态的有状态工作单元。客户端可以跟踪长时间运行的工作并发起后续对话，也可以取消任务，或在断线后重新订阅。

## 协议版本 {/* #protocol-versions */}

Mastra 在同一 Agent 卡片和执行 URL 上支持 A2A 协议 v0.3 与 v1.0。通过 `A2A-Version` 请求标头选择传输协议版本：

- 缺失、为空或为 `0.3`：使用现有的 v0.3 API。
* `1.0`：使用 v1.0 API。
- 其他值：返回 `VersionNotSupported` 协议错误。

`A2AAgent` 和 `MastraClient.getA2A()` 默认使用 v0.3。若要通过 v1.0 委托子 Agent，请在 `A2AAgent` 上设置 `protocolVersion: '1.0'`；若要直接发送 v1.0 请求，请使用 `MastraClient.getA2AV1()`。两种 v1.0 客户端都会自动发送 `A2A-Version: 1.0`。直接调用的 v1.0 客户端还提供 `tasks/list` 操作。

从 `@mastra/core/a2a/v1` 导入 v1.0 协议类型和编解码器。现有的 `@mastra/core/a2a/client` 导出仍使用 v0.3。

## 开始使用 {/* #get-started */}

A2A 在 Mastra 中有两条常见路径：

- 使用 `A2AAgent` 将远程 A2A Agent 用作 Mastra 子 Agent。
- 使用 `MastraClient.getA2A()` 向 Mastra A2A 端点发送请求。

当一个 Mastra Agent 需要向远程 Agent 委托工作时，使用 `A2AAgent`。当应用代码需要直接调用启用 A2A 的 Mastra 端点时，使用客户端 SDK。

## 将 A2A Agent 用作子 Agent {/* #consume-a2a-agents-as-subagents */}

使用 `A2AAgent` 封装远程 A2A Agent，再按照[监督者 Agent](/docs/subagents) 模式将它添加到父 Agent。如果远程服务器托管多个 Agent，或使用自定义的公开发现路径，应明确传入 Agent 卡片 URL。远程 Agent 要求 A2A v1.0 时，设置 `protocolVersion: '1.0'`；省略此项则使用 v0.3。

```typescript title="src/mastra/agents/support-agent.ts"
import { Agent } from '@mastra/core/agent'
import { A2AAgent } from '@mastra/core/a2a'

const remoteWeatherAgent = new A2AAgent({
  url: 'https://weather.example.com/api/.well-known/weather-agent/agent-card.json',
  protocolVersion: '1.0',
  headers: {
    Authorization: `Bearer ${process.env.WEATHER_AGENT_TOKEN}`,
  },
})

export const supportAgent = new Agent({
  id: 'support-agent',
  name: 'Support Agent',
  instructions: 'Answer user questions and delegate weather questions when needed.',
  model: '__GATEWAY_OPENAI_MODEL__',
  agents: {
    remoteWeatherAgent,
  },
})
```

如果 `url` 指向域名，`A2AAgent` 会从 `/.well-known/agent-card.json` 获取 Agent 卡片。遵循此发现路径的单 Agent 服务器可使用域名 URL；多 Agent 服务器则应传入完整卡片 URL，例如 `https://agent.example.com/api/.well-known/weather-agent/agent-card.json`。

执行期间，`A2AAgent` 会：

- 获取并缓存远程 Agent 卡片。
- 从卡片读取执行 URL 和能力。
- 对 v0.3 调用 `message/send` 或 `message/stream`；对 v1.0 调用 `SendMessage` 或 `SendStreamingMessage`。
- 将远程消息、任务、产出物和状态更新转换为 Mastra 子 Agent 的结果。
- 在远程任务需要后续输入或重新订阅时，支持 `resumeGenerate()` 和 `resumeStream()`。

如果远程卡片未声明支持流式传输，`A2AAgent.stream()` 会回退到非流式生成路径，并返回经过缓冲的流式结果。

## 使用客户端 SDK 发送请求 {/* #send-requests-with-the-client-sdk */}

应用代码要调用启用 A2A 的 Mastra Agent 时，使用 `MastraClient.getA2A()`。将 `baseUrl` 设为服务器源地址；如果服务器不使用默认的 `/api` 前缀，还需配置 `apiPrefix`。

```typescript title="src/a2a-client.ts"
import { MastraClient } from '@mastra/client-js'

const client = new MastraClient({
  baseUrl: 'https://agent.example.com',
  headers: {
    Authorization: `Bearer ${process.env.AGENT_API_TOKEN}`,
  },
})

const a2a = client.getA2A('weather-agent')
const card = await a2a.getAgentCard()

console.log(card.name, card.capabilities)
```

使用 `sendMessageStream()` 发送消息，并通过服务器发送事件 (SSE) 接收任务状态和产出物更新：

```typescript title="src/a2a-client.ts" oxfmt:false
const stream = a2a.sendMessageStream({
  message: {
    kind: 'message',
    role: 'user',
    messageId: crypto.randomUUID(),
    parts: [{ kind: 'text', text: "What's the weather in Prague?" }],
  },
})

for await (const event of stream) {
  if (event.kind === 'artifact-update') {
    console.log(event.artifact.parts)
  }
}
```

如果任务仍在运行时流连接中断，可使用 `resubscribeTask()` 继续接收任务的实时更新：

```typescript title="src/a2a-client.ts" oxfmt:false
const updates = a2a.resubscribeTask({
  id: 'task-123',
})

for await (const event of updates) {
  console.log(event)
}
```

### 使用 v1.0 客户端 {/* #use-the-v10-client */}

使用 `getA2AV1()` 选择 A2A v1.0 传输协议。协议包提供编解码器，可从 JSON 形态的输入创建 v1 请求值：

```typescript title="src/a2a-v1-client.ts"
import { ListTasksRequest } from '@mastra/core/a2a/v1'
import { MastraClient } from '@mastra/client-js'

const client = new MastraClient({
  baseUrl: 'https://agent.example.com',
})

const a2a = client.getA2AV1('weather-agent')
const response = await a2a.listTasks(
  ListTasksRequest.fromJSON({
    contextId: 'customer-support',
    pageSize: 20,
  }),
)

for (const task of response.tasks) {
  console.log(task.id, task.status)
}
```

v1.0 客户端支持 `getAgentCard()`、`sendMessage()`、`sendMessageStream()`、`getTask()`、`listTasks()`、`cancelTask()` 和 `resubscribeTask()`。

## 配置子 Agent 调用 {/* #configure-subagent-calls */}

`A2AAgent` 接受适用于需身份认证或受限环境的请求选项：

```typescript title="src/mastra/agents/support-agent.ts"
import { A2AAgent } from '@mastra/core/a2a'

const remoteWeatherAgent = new A2AAgent({
  url: 'https://weather.example.com/api/.well-known/weather-agent/agent-card.json',
  headers: {
    Authorization: `Bearer ${process.env.WEATHER_AGENT_TOKEN}`,
  },
  retries: 2,
  backoffMs: 250,
  maxBackoffMs: 1000,
  timeoutMs: 30_000,
})
```

运行时需要自定义 fetch 行为或取消请求时，还可以传入 `credentials`、`fetch` 和 `abortSignal`。

## 人工参与流程 {/* #human-in-the-loop */}

A2A 使用 `input-required` 任务状态表示人工参与 (HITL) 的工作。任务暂停等待输入时，客户端发送带有相同 `taskId` 的后续消息，补充所需输入，服务器随后继续执行任务。

Mastra 在服务端和客户端两个方向都将 Agent 的暂停机制映射到这一状态：

- **作为服务器**：开放的 Agent 暂停时，任务转为 `input-required`。这包括因[工具审批](/docs/agents/human-in-the-loop)或工具调用 `suspend()` 导致的暂停。任务状态消息包含文本提示，以及带有结构化 `suspendPayload` 和 `resumeSchema` 的数据片段。客户端发送带有相同 `taskId` 的后续 `message/send` 或 `message/stream` 请求，即可用所提供的输入恢复执行。
- **作为客户端**：远程任务进入 `input-required` 或 `auth-required` 时，`A2AAgent` 返回暂停结果，其中包含 `finishReason: 'suspended'` 和 `suspendPayload`。调用 `resumeGenerate()` 或 `resumeStream()`，即可用原始 `taskId` 将输入或凭据发回远程任务。

```typescript title="src/a2a-hitl.ts"
import { A2AAgent } from '@mastra/core/a2a'

const agent = new A2AAgent({
  url: 'https://agent.example.com/api/.well-known/booking-agent/agent-card.json',
})

const result = await agent.generate('Book a flight to Paris', { runId: 'run-1' })

if (result.finishReason === 'suspended') {
  // Inspect result.suspendPayload, collect input from a human,
  // then resume the remote task.
  const resumed = await agent.resumeGenerate({ approved: true }, { runId: 'run-1' })
  console.log(resumed.text)
}
```

对于 `input-required` 任务，后续消息可以通过结构化数据片段携带恢复数据，也可以将 JSON 或纯文本放在文本片段中。

如果恢复后的运行还需要输入，任务会再次进入 `input-required`，重复上述流程。要跨请求恢复暂停的运行，Mastra 服务器必须配置存储，以便还原暂停状态。

:::note
A2A 任务记录保存在内存中，因此只能由最初暂停任务的同一服务器进程恢复。服务器重启，或水平扩容部署未配置粘性路由，都会导致任务记录丢失；后续消息将因找不到任务而失败。
:::

## 推送通知 {/* #push-notifications */}

对于声明 `capabilities.pushNotifications` 的远程 Agent，Mastra 支持 A2A 推送通知。客户端无法保持流连接，或长时间运行的任务需要在原始请求结束后更新回调 URL 时，可以使用推送通知。

客户端获得任务 ID 后，可以为该任务注册回调 URL：

```typescript title="src/a2a-client.ts"
await a2a.setTaskPushNotificationConfig({
  taskId: 'task-123',
  pushNotificationConfig: {
    url: 'https://app.example.com/a2a/tasks',
    token: process.env.A2A_WEBHOOK_TOKEN,
  },
})
```

当任务进入 `completed`、`failed`、`canceled`、`rejected`、`input-required` 或 `auth-required` 状态时，Mastra Server 会向已注册的回调发送当前任务快照。推送通知仅尽力送达。应保护回调 URL、验证通知令牌，并避免将内部网络地址用作推送目标。

推送通知配置存储在内存中，服务器重启后必须重新注册。

## 签名并验证 Agent 卡片 {/* #sign-and-verify-agent-cards */}

Mastra 支持对 A2A Agent 卡片签名，客户端因而可以验证发现的卡片来自可信发布方，且传输过程中未被篡改。应在开放远程 Agent 的 Mastra 服务器上配置签名：

```typescript title="src/mastra/index.ts"
import { Mastra } from '@mastra/core/mastra'

export const mastra = new Mastra({
  server: {
    a2a: {
      agentCardSigning: {
        privateKey: process.env.A2A_AGENT_CARD_PRIVATE_KEY!,
        protectedHeader: {
          alg: 'ES256',
          kid: 'agent-card-key',
        },
      },
    },
  },
})
```

配置签名后，Mastra 会在 Agent 卡片中加入 `signatures` 数组。客户端验证需要主动启用；未签名的卡片仍按原样返回。

通过 `MastraClient.getA2A()` 验证已签名的卡片：

```typescript title="src/a2a-client.ts"
const card = await a2a.getAgentCard({
  verifySignature: {
    algorithms: ['ES256'],
    keyProvider: async ({ kid, jku }) => {
      return fetchTrustedPublicJwk({ kid, jku })
    },
  },
})

if (!card.signatures?.length) {
  throw new Error('Expected a signed A2A agent card.')
}
```

如果客户端必须在调用远程 Agent 前核实可信密钥，应在客户端验证签名。

## 验证子 Agent 卡片 {/* #verify-subagent-cards */}

父 Agent 在委托工作前需要验证远程 Agent 时，可使用 `verifyAgentCard`。验证钩子会收到已获取的 Agent 卡片，以及其获取位置和时间等上下文。

```typescript title="src/mastra/agents/support-agent.ts"
import { A2AAgent } from '@mastra/core/a2a'

const remoteWeatherAgent = new A2AAgent({
  url: 'https://weather.example.com/api/.well-known/weather-agent/agent-card.json',
  verifyAgentCard: {
    verify: async (card, context) => {
      if (card.provider?.organization !== 'Weather Inc') {
        throw new Error(`Unexpected provider for ${context.cardUrl}`)
      }
    },
  },
})
```

父 Agent 委托远程 Agent 之前，可通过此钩子检查提供方、端点、绑定证书的身份、卡片签名等信任要求。
