# MCP

马斯特拉支持[Model Context Protocol (MCP)](https://modelcontextprotocol.io/introduction)，一种用于将人工智能Agent连接到外部Tool和资源的开放标准。

使用[`MCPClient`](/reference/tools/mcp-client) to connect to MCP servers. Use [`MCPServer`](/reference/tools/mcp-server)将 Mastra Agent、Tool、Workflow程、提示和资源公开给其他 MCP 兼容系统。两人都讲 MCP`2026-07-28`对 stdio 和 Streamable HTTP 的修订。

对于托管 MCP 服务器，例如[Neon](/integrations/databases/neon#connect) and [Canva](/integrations/other/canva), [Connect](/docs/mastra-platform/connect) on Mastra platform can manage the OAuth flow and credentials for you, so agents get the server's tools through [`tools()`](/reference/connect/tools#mcp-providers)无需手动配置`MCPClient`.

:::注意
升级自`@mastra/mcp` 1.x? See the [migration guide](/reference/migrations/mcp-v2).
:::

有关凭据选择和权限边界，请参阅[Authentication and authorization with MCP](/docs/guides/mcp-authentication-authorization).

## 连接到 MCP 服务器 {/* #connect-to-mcp-servers */}

安装MCP包：

```bash npm2yarn
npm install @mastra/mcp@latest
```

使用本地命令或远程 URL 配置每个服务器：

```typescript title="src/mastra/mcp/client.ts"
import { MCPClient } from '@mastra/mcp'

export const mcpClient = new MCPClient({
  id: 'my-mcp-client',
  servers: {
    wikipedia: {
      command: 'npx',
      args: ['-y', 'wikipedia-mcp'],
    },
    weather: {
      url: new URL('https://weather.example.com/mcp'),
      requestInit: {
        headers: {
          Authorization: `Bearer ${process.env.WEATHER_API_KEY}`,
        },
      },
    },
  },
})
```

:::提示验证

对于 OAuth 保护的服务器，请使用`authenticate()` to complete the browser-based authorization flow. Visit [OAuth authentication](/reference/tools/mcp-client#oauth-authentication) for configuration details.

:::

将Tool从已配置的服务器传递到Agent：

```typescript {2,13} title="src/mastra/agents/assistant.ts"
import { Agent } from '@mastra/core/agent'
import { mcpClient } from '../mcp/client'

export const assistant = new Agent({
  id: 'assistant',
  name: 'Assistant',
  instructions: `
    Use the available MCP tools to answer questions.
    Include the source of any information you retrieve.
  `,
  model: '__GATEWAY_OPENAI_MODEL__',
  tools: await mcpClient.listTools(),
})
```

### 生成直接Tool调用的类型 {/* #generate-types-for-direct-tool-calls */}

对于稳定的服务器配置，请从已发布的Tool架构生成类型，而不是重新声明Tool参数和结果。此可选Workflow程使动态发现保持不变。

导出一个带有输出路径的客户端并传递生成的`MCPServers` interface to its constructor:

```typescript title="src/mcp/client.ts"
import { MCPClient } from '@mastra/mcp'
import type { MCPServers } from './mcp-types.generated'

export const mcp = new MCPClient<MCPServers>({
  id: 'weather-client',
  servers: { weather: { url: new URL(process.env.WEATHER_MCP_URL!) } },
  typegen: { outFile: 'src/mcp/mcp-types.generated.ts' },
})
```

放`WEATHER_MCP_URL` and configure any required authentication before running the command from your project root:

```bash npm2yarn
npx @mastra/mcp generate ./src/mcp/client.ts
```

生成的文件在第一次运行时可能不存在，因为它的导入是仅类型的。 Generation 无需进行类型检查即可加载 TypeScript 模块，并无需执行Tool即可列出架构。之后运行项目的类型检查。

使用其生成的参数调用已发现的Tool。以下假设服务器发布`get_weather` with a string `location` and numeric `temperature`:

```typescript title="src/mcp/call-weather.ts"
import { mcp } from './client'

try {
  const tools = await mcp.listTools()
  const weather = tools.weather_get_weather
  if (weather?.execute) {
    const result = await weather.execute({ location: 'Paris' })
    if (result && 'temperature' in result && typeof result.temperature === 'number') {
      console.log(result.temperature)
    }
  }
} finally {
  await mcp.disconnect()
}
```

Tool可能不存在，并且执行可能会返回协议信封、验证错误或`undefined` alongside structured output. Narrow the result before using it. Missing output schemas produce `unknown`.

传递多个显式客户端文件以生成多个输出。直接将客户端导出为命名或默认导出，使用不同的输出路径，并在服务器配置匹配时为独立客户端提供不同的 ID。输入和输出路径从命令的工作目录解析。同一客户端的重复导出均处理一次。

发现失败会使现有文件保持不变，模式问题生成也无法解决，例如引用循环、深度过大或未解析的本地引用。文件替换是每个文件的原子操作，而不是整个集合的操作。当服务器架构更改时，使用等效权限重新生成。在生成之前，请自行提供凭据并加载任何环境文件。导入客户端会执行其模块和传递导入，因此选择没有应用程序启动副作用的文件。交互式身份验证不是命令的一部分。

看[type generation reference](/reference/tools/mcp-client#generate-client-types) for export selection, instance caching, schema limitations, and failure handling.

### 静态和运行时Tool {/* #static-and-runtime-tools */}

根据服务器配置是否在请求之间发生变化来选择如何加载Tool：

| |静态Tool|运行时Tool集 |
| :- | :- | :- |
|方法|`await mcpClient.listTools()` | `await mcpClient.listToolsets()` |
| Use case | Shared, fixed configuration | Per-user or per-request configuration |
| Credentials | Shared by all requests | Can vary between requests |
| Agent API | `tools` in the `Agent` constructor | `toolsets` in `generate()` or `stream()` |
| Tool names | Prefixed with the server name, such as `weather_get_weather` | Raw tool names. Same-named tools from different servers collide. See [`listToolsets()`](/reference/tools/mcp-client#listtoolsets). |

前面的Agent示例使用静态Tool。对于运行时凭证，为请求创建客户端并在调用Agent时传递其Tool集：

```typescript {5-16,21} title="src/handle-request.ts"
import { MCPClient } from '@mastra/mcp'
import { mastra } from './mastra'

export async function handleRequest(prompt: string, apiKey: string) {
  const userMcpClient = new MCPClient({
    servers: {
      weather: {
        url: new URL('https://weather.example.com/mcp'),
        requestInit: {
          headers: { Authorization: `Bearer ${apiKey}` },
        },
      },
    },
  })

  const agent = mastra.getAgent('assistant')
  const response = await agent.generate(prompt, {
    toolsets: await userMcpClient.listToolsets(),
  })

  await userMcpClient.disconnect()
  return response.text
}
```

访问[`listTools()`](/reference/tools/mcp-client#listtools) and [`listToolsets()`](/reference/tools/mcp-client#listtoolsets) for their full APIs.

此示例在一个请求内完成。当Agent工作必须在请求结束后继续或在进程重新启动后继续运行时，请使用[durable agents](/docs/harness/durable-agents) or [background tasks](/docs/harness/background-tasks) instead of building your own task tracking. Call-time `toolsets` can't move to another process, so with a durable agent, load per-request MCP tools in the agent's `tools` function from [request context](/docs/server/request-context).

### Tool审批 {/* #tool-approval */}

放`requireToolApproval` on a server to require approval for all its tools:

```typescript
const mcpClient = new MCPClient({
  servers: {
    github: {
      url: new URL('https://github.example.com/mcp'),
      requireToolApproval: true,
    },
  },
})
```

您还可以提供一个根据Tool名称、参数或注释进行决定的函数：

```typescript
requireToolApproval: ({ toolName }) => toolName.startsWith('delete_')
```

将来自您无法控制的服务器的Tool注释视为不受信任的提示。访问[tool approval](/reference/tools/mcp-client#tool-approval) for the callback context and security guidance.

### 安全 {/* #security */}

MCP 服务器代表您的Agent运行代码并返回内容，因此请像任何其他外部依赖项一样谨慎地配置它们：

* **Stdio子进程环境**：子进程仅继承 MCP SDK 的策划环境白名单（例如`PATH` and `HOME` on POSIX), not the full parent environment. Set `inheritDefaultEnv: false` on a server to pass only the variables listed in `env`.
* **出站主机限制**： 放`allowedHosts` when HTTP server URLs come from untrusted configuration, to restrict the hosts the client can contact. The default fetch path blocks redirect hops before sending them; a custom `fetch` is validated against its final response URL only after the request, so it must enforce its own redirect policy when outbound contact must be prevented.
* **Tool响应信任**：Tool结果是不受信任的模型输入。使用[input and output processors](/docs/agents/processors) to sanitize content before it reaches the model, and `requireToolApproval` for sensitive tools.

参观[MCPClient security reference](/reference/tools/mcp-client#security) for enforcement details of each option.

## 公开 Mastra MCP 服务器 {/* #expose-a-mastra-mcp-server */}

创建一个`MCPServer` to expose Mastra primitives to external MCP clients:

```typescript title="src/mastra/mcp/server.ts"
import { MCPServer } from '@mastra/mcp'
import { assistant } from '../agents/assistant'
import { weatherTool } from '../tools/weather'
import { weatherWorkflow } from '../workflows/weather'

export const mcpServer = new MCPServer({
  id: 'my-mcp-server',
  name: 'My MCP Server',
  version: '1.0.0',
  agents: { assistant },
  tools: { weatherTool },
  workflows: { weatherWorkflow },
})
```

在主服务器上注册服务器`Mastra` instance:

```typescript title="src/mastra/index.ts"
import { Mastra } from '@mastra/core/mastra'
import { mcpServer } from './mcp/server'

export const mastra = new Mastra({
  mcpServers: { mcpServer },
})
```

:::提示验证

使用 OAuth 中间件保护 HTTP MCP 服务器。访问[OAuth protection](/reference/tools/mcp-server#oauth-protection) for setup instructions.

:::

注册服务器位于`/api/mcp/:serverId/mcp` over Streamable HTTP. Because every request is self-contained, the same server runs unchanged on long-lived hosts and serverless platforms.

需要用户提供某些信息才能完成呼叫的Tool`context.suspend()` with a payload and declares a `resumeSchema`. The server turns that into an `input_required` round and runs the tool again with the answer in `context.resumeData`. Clients answer those rounds with the `inputRequests` handler on their server definition. Visit [Asking the caller for input](/reference/tools/mcp-server#asking-the-caller-for-input) and [Answering input requests](/reference/tools/mcp-client#answering-input-requests).

参观[`MCPServer` reference](/reference/tools/mcp-server) for prompts, resources, transports, and other server options.

要在 Mastra 应用程序上公开每个Agent、Workflow程和Tool而不定义服务器，请使用[built-in MCP server](/docs/server/mcp) at `/api/mcp`.

### 发布stdio服务器包 {/* #publish-a-stdio-server-package */}

当您希望客户端通过以下命令在本地运行服务器时，打包使用标准输入/输出 (stdio) 传输的服务器`npx`. Create a separate executable entry point that starts the server:

```typescript title="src/mastra/mcp/stdio.ts"
#!/usr/bin/env node
import { mcpServer } from './server'

mcpServer.startStdio().catch(error => {
  console.error('Failed to start MCP server:', error)
  process.exit(1)
})
```

将入口点构建为可执行 Node.js 文件，然后指向包的`bin` field to that output. Include the built file in the published package and keep the shebang as its first line:

```json title="package.json"
{
  "bin": {
    "my-mcp-server": "dist/stdio.js"
  },
  "files": ["dist"]
}
```

发布包后，配置客户端以按包名称运行它：

```typescript title="src/mastra/mcp/client.ts"
import { MCPClient } from '@mastra/mcp'

const mcpClient = new MCPClient({
  servers: {
    myServer: {
      command: 'npx',
      args: ['-y', '@your-org/my-mcp-server@1.0.0'],
    },
  },
})
```

参观[npm package publishing documentation](https://docs.npmjs.com/creating-and-publishing-scoped-public-packages) for package naming, authentication, and publication commands.

## 构建 MCP 应用程序 {/* #build-mcp-apps */}

这[MCP Apps extension](https://github.com/modelcontextprotocol/ext-apps) lets MCP tools serve interactive HTML interfaces through `ui://` resources. Mastra Studio renders these apps in sandboxed iframes on tool pages and in agent chat.

当Tool结果受益于交互（例如表单、计算器、颜色选择器或数据可视化）时，请使用 MCP 应用程序。

### 定义应用程序资源 {/* #define-an-app-resource */}

返回一个短的`content` summary for the model and place UI data in `structuredContent`. Link the tool to its app by setting `mcp._meta.ui.resourceUri` to the same `ui://` URI used in `appResources`:

```typescript title="src/mastra/mcp/calculator.ts"
import { MCPServer } from '@mastra/mcp'
import { createTool } from '@mastra/core/tools'
import { z } from 'zod'

const calculatorTool = createTool({
  id: 'calculatorWithUI',
  description: 'Calculate the sum of two numbers',
  inputSchema: z.object({ num1: z.number(), num2: z.number() }),
  mcp: { _meta: { ui: { resourceUri: 'ui://calculator/main' } } },
  execute: async ({ num1, num2 }) => ({
    content: [{ type: 'text', text: 'The result is displayed in the calculator app.' }],
    structuredContent: { result: num1 + num2 },
  }),
})

const calculatorMcpServer = new MCPServer({
  id: 'calculator-app-server',
  name: 'Calculator App Server',
  version: '1.0.0',
  tools: { calculatorTool },
  appResources: {
    'ui://calculator/main': { name: 'Calculator', htmlPath: './src/mastra/mcp/calculator.html' },
  },
})
```

模型看到`content`, while the app receives `structuredContent`. Visit [`appResources`](/reference/tools/mcp-server#mcp-apps-appresources) for inline HTML, file paths, metadata, and content security policy options.

### 将应用程序连接到 Studio {/* #connect-the-app-to-studio */}

使用`App` class from `@modelcontextprotocol/ext-apps` inside the HTML resource. Register event handlers before calling `connect()`:

```html title="src/mastra/mcp/calculator.html"
<!doctype html>
<html>
  <body>
    <p id="result">Waiting for input</p>
    <button id="recalculate">Recalculate</button>

    <script type="module">
      import { App } from 'https://cdn.jsdelivr.net/npm/@modelcontextprotocol/ext-apps/+esm'

      const app = new App({ name: 'Calculator', version: '1.0.0' })
      let toolInput

      app.ontoolinput = params => {
        toolInput = params.arguments
      }

      document.querySelector('#recalculate').addEventListener('click', async () => {
        const result = await app.callServerTool({
          name: 'calculatorWithUI',
          arguments: toolInput,
        })
        document.querySelector('#result').textContent = JSON.stringify(result)
      })

      await app.connect()
    </script>
  </body>
</html>
```

访客端 API 服务于交互的不同部分：

|应用程序接口 |目的|
| :- | :- |
|`app.ontoolinput` | Receive the arguments from the host tool call |
| `app.callServerTool()` | Call an MCP tool from inside the iframe |
| `app.sendMessage()` | Add a user message to chat and start a new model turn |
| `app.connect()` | Connect to the host after registering event handlers |

参观外部[`App` API reference](https://apps.extensions.modelcontextprotocol.io/api/classes/app.App.html) for all guest-side methods and lifecycle hooks.

### 注册 MCP 应用程序 {/* #register-mcp-apps */}

将服务器注册到`Mastra` the same way as any other server in [Expose a Mastra MCP server](#expose-a-mastra-mcp-server), and pass its tool to the agent that should render the app.

对于实现 MCP 应用程序的外部 MCP 服务器，请使用以下命令加载其Tool`MCPClient.listTools()` and register its proxy so Studio can resolve the remote app resources:

```typescript title="src/mastra/remote-apps.ts"
import { Agent } from '@mastra/core/agent'
import { Mastra } from '@mastra/core/mastra'
import { mcpClient } from './mcp/client'

const tools = await mcpClient.listTools()
const mcpServers = mcpClient.toMCPServerProxies()

const agent = new Agent({
  id: 'remote-app-agent',
  name: 'Remote App Agent',
  instructions: 'Use the available remote tools.',
  model: '__GATEWAY_OPENAI_MODEL_LUNA__',
  tools,
})

export const mastra = new Mastra({
  agents: { agent },
  mcpServers,
})
```

Tool加载通过`listTools()` include a `serverId` in `_meta.ui`, allowing Studio to resolve each app resource without scanning every server. Visit [`toMCPServerProxies()`](/reference/tools/mcp-client#tomcpserverproxies) for proxy configuration details.

### Sandbox安全 {/* #sandbox-security */}

马斯特拉工作室使用[`@mcp-ui/client`](https://www.npmjs.com/package/@mcp-ui/client) to load app HTML through a sandbox proxy and communicate over JSON-RPC with `postMessage`.

应用程序 iframe 允许脚本、表单和弹出窗口。他们无法访问父页面的 DOM、cookie 或存储。主机控制与访客应用程序的所有通信。

## MCP 活动 {/* #mcp-events */}

MCP 事件让客户端在服务器上发生某些情况（例如打开票证或构建完成）时做出反应，而不是按计划调用Tool进行检查。服务器声明事件类型，客户端使用参数订阅，服务器通过与其Tool相同的 stdio 或 Streamable HTTP 传输传递每个匹配的事件。

:::警告
MCP活动实施[SEP-3415](https://github.com/modelcontextprotocol/modelcontextprotocol/pull/3415), a draft MCP extension. The wire format and the Mastra API are experimental and may change in any release.
:::

* **订阅：**&#x4E00;个客户端请求一种带有参数的事件类型，例如`{ project: 'web' }`. The server delivers only matching occurrences.
* **发生：**&#x4E00;项已交付的活动`eventId`, `name`, `timestamp`, and `data`. Delivery is at least once, and the client drops duplicates by `eventId` within a `dedupWindow` of recent ids. Handlers should still tolerate a repeat.
* **光标：**&#x4E8B;件序列中的不透明位置。保存它以便从以后的订阅中恢复。重播仅涵盖源保留的历史记录。一个`emit()` source buffers in one process, so a restart or another instance serving the subscription can miss occurrences, and durable replay needs a `poll` source backed by shared storage.

### 发布活动 {/* #publish-events */}

声明每种类型`defineEvent()` in the `events` option of `MCPServer`, then publish occurrences with `server.events.emit()`:

```typescript title="src/mastra/mcp/tickets.ts"
import { createTool } from '@mastra/core/tools'
import { MCPServer, defineEvent } from '@mastra/mcp'
import { z } from 'zod'

const ticket = z.object({ id: z.string(), project: z.string(), title: z.string() })

const server: MCPServer = new MCPServer({
  id: 'tickets',
  name: 'Tickets',
  version: '1.0.0',
  tools: {
    openTicket: createTool({
      id: 'openTicket',
      description: 'Opens a support ticket',
      inputSchema: ticket,
      execute: async input => server.events.emit('ticket.created', input),
    }),
  },
  events: {
    'ticket.created': defineEvent({
      description: 'A support ticket was opened',
      inputSchema: z.object({ project: z.string() }),
      payloadSchema: ticket,
      match: (args, data) => data.project === args.project,
    }),
  },
})
```

这些示例通过 HTTP 为该服务器提供服务，地址为`http://localhost:4111/mcp` with [`startHTTP()`](/reference/tools/mcp-server#starthttp).

`match`决定哪些订阅接收事件。它过滤客户端选择的参数，因此它不控制谁可以订阅；添加`authorize` to restrict callers, since it runs on every poll and every subscription open and rejects the request when it returns `false`. An event type takes its occurrences from either `server.events.emit()`, which serves push and poll from an in-process buffer, or a `poll` function that reads an external system and supports poll only.

### 订阅活动 {/* #subscribe-to-events */}

列出服务器提供的类型`mcp.events.list()`, then subscribe with `mcp.events.subscribe()`. The returned subscription is an async iterable of occurrences:

```typescript title="src/mastra/mcp/client.ts"
import { MCPClient } from '@mastra/mcp'

const mcp = new MCPClient({ servers: { tickets: { url: new URL('http://localhost:4111/mcp') } } })

const eventTypes = await mcp.events.list('tickets')
const subscription = await mcp.events.subscribe('tickets', 'ticket.created', { project: 'web' })

for await (const event of subscription) {
  console.log(event.eventId, event.data)
  if (subscription.cursor) await saveCursor('tickets:web', subscription.cursor)
}
```

`subscribe()`一旦服务器接受订阅就解决。新的订阅从现在开始，所以通过`options.cursor` to resume from a saved position. The client picks the first mode the event offers, in the order `webhook` when the client has `webhook` settings, then `push`, then `poll`, and reopens dropped streams on its own.

### 从事件开始运行 {/* #start-runs-from-events */}

在每次发生时启动一次Agent运行或Workflow运行的循环中进行订阅。该事件来自服务器，因此通过`event.data` as data rather than as instructions, and save `subscription.cursor` after handling each one. Because the loop handles one occurrence at a time and a slow run delays the next, when order doesn't matter you can start runs without awaiting them and save the cursor only after every earlier run has finished, since a crash otherwise loses the occurrences whose runs were still going.

在推送或 webhook 传递下，客户端缓冲循环未读取的事件，并且循环下降超过`maxBufferedEvents` behind loses the oldest ones and reports `MCP_EVENTS_BUFFER_OVERFLOW`. To deliver occurrences to agent threads as notifications instead of writing your own loop, use [`MCPEventsSignalProvider`](/reference/tools/mcp-client#events-in-agents-and-workflows-experimental).

当服务器位于远程且您的应用程序已提供 HTTP 服务时，请改用 Webhook 传递：启用`webhook` in `eventsOptions` on the server and `webhook` on the client, and each occurrence arrives as a POST to your endpoint. For delivery modes, error codes, buffers, retries, and the `poll` source example, visit the [`MCPServer` events reference](/reference/tools/mcp-server#events-experimental) and the [`MCPClient` events reference](/reference/tools/mcp-client#events-property-experimental). The [MCP events example](https://github.com/mastra-ai/mastra/tree/main/examples/mcp-events) runs the agent flow end to end against a local stdio server.
