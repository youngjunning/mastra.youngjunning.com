# MCP

马斯特拉支持[Model Context Protocol (MCP)](https://modelcontextprotocol.io/introduction)，一种用于将人工智能Agent连接到外部Tool和资源的开放标准。

使用 [`MCPClient`](/reference/tools/mcp-client) 连接 MCP 服务器。使用 [`MCPServer`](/reference/tools/mcp-server) 向其他兼容 MCP 的系统提供 Mastra Agent、Tool、Workflow、prompt 和 resource。两者均通过 stdio 和 Streamable HTTP 支持 MCP `2026-07-28` 版本。

对于 [Neon](/integrations/databases/neon#connect) 和 [Canva](/integrations/other/canva) 等托管 MCP 服务器，Mastra 平台上的 [Connect](/docs/mastra-platform/connect) 可代你管理 OAuth 流程和凭据，让 Agent 通过 [`tools()`](/reference/connect/tools#mcp-providers) 使用服务器的 Tool，无须手动配置 `MCPClient`。

:::note
从 `@mastra/mcp` 1.x 升级？请参见[迁移指南](/reference/migrations/mcp-v2)。
:::

有关凭据选择和权限边界，请参阅[Authentication and authorization with MCP](/docs/guides/mcp-authentication-authorization).

## 连接到 MCP 服务器 {/* #connect-to-mcp-servers */}

安装MCP包：

```bash npm2yarn
npm install @mastra/mcp@latest
```

使用本地命令或远程 URL 配置每个服务器：

```typescript title="src/mastra/mcp/client.ts"
import { MCPClient } from '@mastra/mcp'

export const mcpClient = new MCPClient({
  id: 'my-mcp-client',
  servers: {
    wikipedia: {
      command: 'npx',
      args: ['-y', 'wikipedia-mcp'],
    },
    weather: {
      url: new URL('https://weather.example.com/mcp'),
      requestInit: {
        headers: {
          Authorization: `Bearer ${process.env.WEATHER_API_KEY}`,
        },
      },
    },
  },
})
```

:::tip Authentication

对于受 OAuth 保护的服务器，使用 `authenticate()` 完成基于浏览器的授权流程。配置详情参见 [OAuth authentication](/reference/tools/mcp-client#oauth-authentication)。

:::

将Tool从已配置的服务器传递到Agent：

```typescript {2,13} title="src/mastra/agents/assistant.ts"
import { Agent } from '@mastra/core/agent'
import { mcpClient } from '../mcp/client'

export const assistant = new Agent({
  id: 'assistant',
  name: 'Assistant',
  instructions: `
    Use the available MCP tools to answer questions.
    Include the source of any information you retrieve.
  `,
  model: '__GATEWAY_OPENAI_MODEL__',
  tools: await mcpClient.listTools(),
})
```

### 生成直接Tool调用的类型 {/* #generate-types-for-direct-tool-calls */}

对于配置稳定的服务器，可以从已发布的 Tool schema 生成类型，无须重新声明 Tool 参数和结果。这个可选流程不影响动态发现。

指定输出路径导出客户端，并将生成的 `MCPServers` 接口传给构造函数：

```typescript title="src/mcp/client.ts"
import { MCPClient } from '@mastra/mcp'
import type { MCPServers } from './mcp-types.generated'

export const mcp = new MCPClient<MCPServers>({
  id: 'weather-client',
  servers: { weather: { url: new URL(process.env.WEATHER_MCP_URL!) } },
  typegen: { outFile: 'src/mcp/mcp-types.generated.ts' },
})
```

在项目根目录运行命令前，先设置 `WEATHER_MCP_URL` 并配置所需的身份验证：

```bash npm2yarn
npx @mastra/mcp generate ./src/mcp/client.ts
```

生成的文件在第一次运行时可能不存在，因为它的导入是仅类型的。 Generation 无需进行类型检查即可加载 TypeScript 模块，并无需执行Tool即可列出架构。之后运行项目的类型检查。

使用生成的参数调用已发现的 Tool。以下假设服务器发布的 `get_weather` 接收字符串 `location` 和数值 `temperature`：

```typescript title="src/mcp/call-weather.ts"
import { mcp } from './client'

try {
  const tools = await mcp.listTools()
  const weather = tools.weather_get_weather
  if (weather?.execute) {
    const result = await weather.execute({ location: 'Paris' })
    if (result && 'temperature' in result && typeof result.temperature === 'number') {
      console.log(result.temperature)
    }
  }
} finally {
  await mcp.disconnect()
}
```

Tool 可能不存在；执行结果除了结构化输出，也可能是协议封装、验证错误或 `undefined`。使用前应先收窄结果类型。缺少输出 schema 时，结果类型为 `unknown`。

传递多个显式客户端文件以生成多个输出。直接将客户端导出为命名或默认导出，使用不同的输出路径，并在服务器配置匹配时为独立客户端提供不同的 ID。输入和输出路径从命令的工作目录解析。同一客户端的重复导出均处理一次。

发现失败会使现有文件保持不变，模式问题生成也无法解决，例如引用循环、深度过大或未解析的本地引用。文件替换是每个文件的原子操作，而不是整个集合的操作。当服务器架构更改时，使用等效权限重新生成。在生成之前，请自行提供凭据并加载任何环境文件。导入客户端会执行其模块和传递导入，因此选择没有应用程序启动副作用的文件。交互式身份验证不是命令的一部分。

导出选择、实例缓存、schema 限制和失败处理参见[类型生成参考](/reference/tools/mcp-client#generate-client-types)。

### 静态和运行时Tool {/* #static-and-runtime-tools */}

根据服务器配置是否在请求之间发生变化来选择如何加载Tool：

| |静态Tool|运行时Tool集 |
| :- | :- | :- |
|方法|`await mcpClient.listTools()` | `await mcpClient.listToolsets()` |
| Use case | Shared, fixed configuration | Per-user or per-request configuration |
| 凭据 | 所有请求共用 | 可因请求而异 |
| Agent API | 在 `Agent` 构造函数中使用 `tools` | 在 `generate()` 或 `stream()` 中使用 `toolsets` |
| Tool 名称 | 以服务器名称为前缀，例如 `weather_get_weather` | 原始 Tool 名称。不同服务器中同名的 Tool 会冲突。参见 [`listToolsets()`](/reference/tools/mcp-client#listtoolsets)。 |

前面的Agent示例使用静态Tool。对于运行时凭证，为请求创建客户端并在调用Agent时传递其Tool集：

```typescript {5-16,21} title="src/handle-request.ts"
import { MCPClient } from '@mastra/mcp'
import { mastra } from './mastra'

export async function handleRequest(prompt: string, apiKey: string) {
  const userMcpClient = new MCPClient({
    servers: {
      weather: {
        url: new URL('https://weather.example.com/mcp'),
        requestInit: {
          headers: { Authorization: `Bearer ${apiKey}` },
        },
      },
    },
  })

  const agent = mastra.getAgent('assistant')
  const response = await agent.generate(prompt, {
    toolsets: await userMcpClient.listToolsets(),
  })

  await userMcpClient.disconnect()
  return response.text
}
```

完整 API 参见 [`listTools()`](/reference/tools/mcp-client#listtools) 和 [`listToolsets()`](/reference/tools/mcp-client#listtoolsets)。

此例在单次请求内完成。如果 Agent 工作需要在请求结束后继续，或要在进程重启后恢复，应使用[持久化 Agent](/docs/harness/durable-agents) 或[后台任务](/docs/harness/background-tasks)，无须自行实现任务跟踪。调用时传入的 `toolsets` 无法迁移到其他进程。因此，对持久化 Agent，应在 Agent 的 `tools` 函数中根据[请求上下文](/docs/server/request-context)加载每次请求的 MCP Tool。

### Tool审批 {/* #tool-approval */}

在服务器上设置 `requireToolApproval`，要求其所有 Tool 都经过审批：

```typescript
const mcpClient = new MCPClient({
  servers: {
    github: {
      url: new URL('https://github.example.com/mcp'),
      requireToolApproval: true,
    },
  },
})
```

您还可以提供一个根据Tool名称、参数或注释进行决定的函数：

```typescript
requireToolApproval: ({ toolName }) => toolName.startsWith('delete_')
```

不受你控制的服务器提供的 Tool annotation 只能当作不可信提示。回调上下文及安全指引参见 [Tool approval](/reference/tools/mcp-client#tool-approval)。

### 安全 {/* #security */}

MCP 服务器代表您的Agent运行代码并返回内容，因此请像任何其他外部依赖项一样谨慎地配置它们：

- **Stdio 子进程环境**：子进程只继承 MCP SDK 筛选后的环境变量允许列表（例如 POSIX 上的 `PATH` 和 `HOME`），而非父进程的完整环境。在服务器上设置 `inheritDefaultEnv: false`，只传递 `env` 中列出的变量。
- **出站主机限制**：如果 HTTP 服务器 URL 来自不可信配置，设置 `allowedHosts` 限制客户端可连接的主机。默认 fetch 路径会在发送请求前拦截重定向跳转；自定义 `fetch` 仅在请求发出后根据最终响应 URL 验证，因此如需阻止出站连接，必须自行执行重定向策略。
- **Tool 响应的可信度**：Tool 结果是传给模型的不可信输入。使用[输入和输出处理器](/docs/agents/processors)在内容到达模型前进行清理，并对敏感 Tool 设置 `requireToolApproval`。

每个选项的执行细节参见 [MCPClient 安全参考](/reference/tools/mcp-client#security)。

## 公开 Mastra MCP 服务器 {/* #expose-a-mastra-mcp-server */}

创建 `MCPServer`，向外部 MCP 客户端暴露 Mastra 组件：

```typescript title="src/mastra/mcp/server.ts"
import { MCPServer } from '@mastra/mcp'
import { assistant } from '../agents/assistant'
import { weatherTool } from '../tools/weather'
import { weatherWorkflow } from '../workflows/weather'

export const mcpServer = new MCPServer({
  id: 'my-mcp-server',
  name: 'My MCP Server',
  version: '1.0.0',
  agents: { assistant },
  tools: { weatherTool },
  workflows: { weatherWorkflow },
})
```

在主 `Mastra` 实例上注册服务器：

```typescript title="src/mastra/index.ts"
import { Mastra } from '@mastra/core/mastra'
import { mcpServer } from './mcp/server'

export const mastra = new Mastra({
  mcpServers: { mcpServer },
})
```

:::tip Authentication

通过 OAuth 中间件保护 HTTP MCP 服务器。设置方法参见 [OAuth protection](/reference/tools/mcp-server#oauth-protection)。

:::

注册的服务器通过 Streamable HTTP 在 `/api/mcp/:serverId/mcp` 提供服务。每次请求都独立完整，因此同一服务器可原样运行于常驻主机和 serverless 平台。

如果 Tool 完成前需要用户输入，可携带 payload 调用 `context.suspend()` 并声明 `resumeSchema`。服务器会将其转为一次 `input_required` 往返，收到答案后以 `context.resumeData` 再次运行 Tool。客户端通过服务器定义中的 `inputRequests` 处理器回应。参见[向调用方请求输入](/reference/tools/mcp-server#asking-the-caller-for-input)和[回应输入请求](/reference/tools/mcp-client#answering-input-requests)。

prompt、resource、transport 及其他服务器选项参见 [`MCPServer` 参考](/reference/tools/mcp-server)。

如果想在不定义服务器的情况下暴露 Mastra 应用中的所有 Agent、Workflow 和 Tool，可使用 `/api/mcp` 上的[内置 MCP 服务器](/docs/server/mcp)。

### 发布stdio服务器包 {/* #publish-a-stdio-server-package */}

如果希望客户端通过 `npx` 等命令在本地运行服务器，请将使用标准输入/输出（stdio）传输的服务器打包。创建一个单独的可执行入口来启动服务器：

```typescript title="src/mastra/mcp/stdio.ts"
#!/usr/bin/env node
import { mcpServer } from './server'

mcpServer.startStdio().catch(error => {
  console.error('Failed to start MCP server:', error)
  process.exit(1)
})
```

将入口构建为可执行的 Node.js 文件，然后让包的 `bin` 字段指向该输出。发布包时包含这个文件，并保留 shebang 作为首行：

```json title="package.json"
{
  "bin": {
    "my-mcp-server": "dist/stdio.js"
  },
  "files": ["dist"]
}
```

发布包后，配置客户端以按包名称运行它：

```typescript title="src/mastra/mcp/client.ts"
import { MCPClient } from '@mastra/mcp'

const mcpClient = new MCPClient({
  servers: {
    myServer: {
      command: 'npx',
      args: ['-y', '@your-org/my-mcp-server@1.0.0'],
    },
  },
})
```

包命名、身份验证和发布命令参见 [npm 包发布文档](https://docs.npmjs.com/creating-and-publishing-scoped-public-packages)。

## 构建 MCP 应用程序 {/* #build-mcp-apps */}

[MCP Apps 扩展](https://github.com/modelcontextprotocol/ext-apps)让 MCP Tool 通过 `ui://` resource 提供交互式 HTML 界面。Mastra Studio 会在 Tool 页面和 Agent 聊天中，以沙盒 iframe 渲染这些应用。

当Tool结果受益于交互（例如表单、计算器、颜色选择器或数据可视化）时，请使用 MCP 应用程序。

### 定义应用程序资源 {/* #define-an-app-resource */}

在 `content` 中返回供模型阅读的简短摘要，将 UI 数据放入 `structuredContent`。将 `mcp._meta.ui.resourceUri` 设为 `appResources` 中相同的 `ui://` URI，以把 Tool 关联到应用：

```typescript title="src/mastra/mcp/calculator.ts"
import { MCPServer } from '@mastra/mcp'
import { createTool } from '@mastra/core/tools'
import { z } from 'zod'

const calculatorTool = createTool({
  id: 'calculatorWithUI',
  description: 'Calculate the sum of two numbers',
  inputSchema: z.object({ num1: z.number(), num2: z.number() }),
  mcp: { _meta: { ui: { resourceUri: 'ui://calculator/main' } } },
  execute: async ({ num1, num2 }) => ({
    content: [{ type: 'text', text: 'The result is displayed in the calculator app.' }],
    structuredContent: { result: num1 + num2 },
  }),
})

const calculatorMcpServer = new MCPServer({
  id: 'calculator-app-server',
  name: 'Calculator App Server',
  version: '1.0.0',
  tools: { calculatorTool },
  appResources: {
    'ui://calculator/main': { name: 'Calculator', htmlPath: './src/mastra/mcp/calculator.html' },
  },
})
```

模型读取 `content`，应用接收 `structuredContent`。行内 HTML、文件路径、元数据和内容安全策略选项参见 [`appResources`](/reference/tools/mcp-server#mcp-apps-appresources)。

### 将应用程序连接到 Studio {/* #connect-the-app-to-studio */}

在 HTML resource 中使用 `@modelcontextprotocol/ext-apps` 的 `App` 类。调用 `connect()` 前先注册事件处理器：

```html title="src/mastra/mcp/calculator.html"
<!doctype html>
<html>
  <body>
    <p id="result">Waiting for input</p>
    <button id="recalculate">Recalculate</button>

    <script type="module">
      import { App } from 'https://cdn.jsdelivr.net/npm/@modelcontextprotocol/ext-apps/+esm'

      const app = new App({ name: 'Calculator', version: '1.0.0' })
      let toolInput

      app.ontoolinput = params => {
        toolInput = params.arguments
      }

      document.querySelector('#recalculate').addEventListener('click', async () => {
        const result = await app.callServerTool({
          name: 'calculatorWithUI',
          arguments: toolInput,
        })
        document.querySelector('#result').textContent = JSON.stringify(result)
      })

      await app.connect()
    </script>
  </body>
</html>
```

访客端 API 服务于交互的不同部分：

|应用程序接口 |目的|
| :- | :- |
| `app.ontoolinput` | 接收宿主 Tool 调用的参数 |
| `app.callServerTool()` | 在 iframe 内调用 MCP Tool |
| `app.sendMessage()` | 向聊天加入用户消息并开始新一轮模型调用 |
| `app.connect()` | 注册事件处理器后连接宿主 |

所有应用端方法和生命周期钩子参见外部 [`App` API 参考](https://apps.extensions.modelcontextprotocol.io/api/classes/app.App.html)。

### 注册 MCP 应用程序 {/* #register-mcp-apps */}

按照[暴露 Mastra MCP 服务器](#expose-a-mastra-mcp-server)中的方式，将服务器注册到 `Mastra`，并把 Tool 提供给需要渲染应用的 Agent。

对于实现 MCP Apps 的外部 MCP 服务器，使用 `MCPClient.listTools()` 加载其 Tool，并注册代理，以便 Studio 解析远程应用 resource：

```typescript title="src/mastra/remote-apps.ts"
import { Agent } from '@mastra/core/agent'
import { Mastra } from '@mastra/core/mastra'
import { mcpClient } from './mcp/client'

const tools = await mcpClient.listTools()
const mcpServers = mcpClient.toMCPServerProxies()

const agent = new Agent({
  id: 'remote-app-agent',
  name: 'Remote App Agent',
  instructions: 'Use the available remote tools.',
  model: '__GATEWAY_OPENAI_MODEL_LUNA__',
  tools,
})

export const mastra = new Mastra({
  agents: { agent },
  mcpServers,
})
```

通过 `listTools()` 加载的 Tool 会在 `_meta.ui` 中包含 `serverId`，让 Studio 无须扫描所有服务器就能解析各应用 resource。代理配置详情参见 [`toMCPServerProxies()`](/reference/tools/mcp-client#tomcpserverproxies)。

### Sandbox安全 {/* #sandbox-security */}

Mastra Studio 使用 [`@mcp-ui/client`](https://www.npmjs.com/package/@mcp-ui/client) 通过沙盒代理加载应用 HTML，并以 `postMessage` 进行 JSON-RPC 通信。

应用程序 iframe 允许脚本、表单和弹出窗口。他们无法访问父页面的 DOM、cookie 或存储。主机控制与访客应用程序的所有通信。

## MCP 活动 {/* #mcp-events */}

MCP 事件让客户端在服务器上发生某些情况（例如打开票证或构建完成）时做出反应，而不是按计划调用Tool进行检查。服务器声明事件类型，客户端使用参数订阅，服务器通过与其Tool相同的 stdio 或 Streamable HTTP 传输传递每个匹配的事件。

:::warning
MCP 事件实现了草案中的 MCP 扩展 [SEP-3415](https://github.com/modelcontextprotocol/modelcontextprotocol/pull/3415)。传输格式和 Mastra API 仍属实验性功能，任何版本都可能更改。
:::

- **订阅：** 客户端针对一种事件类型发出一次请求，可带 `{ project: 'web' }` 等参数。服务器只交付匹配的事件。
- **事件实例：** 一次交付的事件，包含 `eventId`、`name`、`timestamp` 和 `data`。交付保证至少一次；客户端会在最近 ID 的 `dedupWindow` 范围内按 `eventId` 去重。处理器仍须容忍重复事件。
- **游标：** 事件序列中的不透明位置。保存它，可在后续订阅时从该位置继续。重放仅覆盖事件源保留的历史。`emit()` 事件源仅在单一进程缓冲，因此重启或由另一实例处理订阅可能漏掉事件；持久重放需要共享存储支持的 `poll` 事件源。

### 发布活动 {/* #publish-events */}

在 `MCPServer` 的 `events` 选项中用 `defineEvent()` 声明每种类型，再用 `server.events.emit()` 发布事件实例：

```typescript title="src/mastra/mcp/tickets.ts"
import { createTool } from '@mastra/core/tools'
import { MCPServer, defineEvent } from '@mastra/mcp'
import { z } from 'zod'

const ticket = z.object({ id: z.string(), project: z.string(), title: z.string() })

const server: MCPServer = new MCPServer({
  id: 'tickets',
  name: 'Tickets',
  version: '1.0.0',
  tools: {
    openTicket: createTool({
      id: 'openTicket',
      description: 'Opens a support ticket',
      inputSchema: ticket,
      execute: async input => server.events.emit('ticket.created', input),
    }),
  },
  events: {
    'ticket.created': defineEvent({
      description: 'A support ticket was opened',
      inputSchema: z.object({ project: z.string() }),
      payloadSchema: ticket,
      match: (args, data) => data.project === args.project,
    }),
  },
})
```

示例使用 [`startHTTP()`](/reference/tools/mcp-server#starthttp)，通过 HTTP 在 `http://localhost:4111/mcp` 提供该服务器。

`match` 决定哪些订阅会收到事件实例。它根据客户端自选的参数筛选，不能控制谁有权订阅；应添加 `authorize` 限制调用方。此授權函式 在每次轮询和打开订阅时都会运行，返回 `false` 就拒绝请求。事件类型可以从 `server.events.emit()` 获取事件实例，由单一进程缓冲同时服务 push 和 poll；也可以使用读取外部系统的 `poll` 函数，但后者只支持 poll。

### 订阅活动 {/* #subscribe-to-events */}

先用 `mcp.events.list()` 列出服务器提供的事件类型，再用 `mcp.events.subscribe()` 订阅。返回的订阅是事件实例的异步可迭代对象：

```typescript title="src/mastra/mcp/client.ts"
import { MCPClient } from '@mastra/mcp'

const mcp = new MCPClient({ servers: { tickets: { url: new URL('http://localhost:4111/mcp') } } })

const eventTypes = await mcp.events.list('tickets')
const subscription = await mcp.events.subscribe('tickets', 'ticket.created', { project: 'web' })

for await (const event of subscription) {
  console.log(event.eventId, event.data)
  if (subscription.cursor) await saveCursor('tickets:web', subscription.cursor)
}
```

服务器接受订阅后，`subscribe()` 即完成。新订阅从当前时间开始；传入 `options.cursor` 可从保存的位置恢复。客户端会按以下顺序选择事件提供的第一种可用模式：客户端配置了 `webhook` 时先选 `webhook`，随后是 `push`，最后是 `poll`。连接中断后，客户端会自行重新打开流。

### 从事件开始运行 {/* #start-runs-from-events */}

在循环中订阅事件，每收到一个事件实例就启动一次 Agent run 或 Workflow run。事件来自服务器，因此应把 `event.data` 当作数据而非指令传入，并在处理每个事件后保存 `subscription.cursor`。循环一次只处理一个事件，慢速 run 会延迟下一个事件。如果顺序不重要，可以不等待就启动多个 run，但必须等所有更早启动的 run 完成后再保存游标，否则进程崩溃时仍在运行的事件会丢失。

采用 push 或 webhook 交付时，客户端会缓冲循环尚未读取的事件实例。如果循环落后超过 `maxBufferedEvents`，最旧的事件会丢失，并报告 `MCP_EVENTS_BUFFER_OVERFLOW`。如果想把事件作为通知交付给 Agent thread，而非自行编写循环，可使用 [`MCPEventsSignalProvider`](/reference/tools/mcp-client#events-in-agents-and-workflows-experimental)。

如果服务器位于远端，而应用已经提供 HTTP 服务，可以改用 webhook 交付：在服务器的 `eventsOptions` 启用 `webhook`，客户端也启用 `webhook`，每个事件实例都会以 POST 请求送达你的端点。交付模式、错误码、缓冲、重试及 `poll` 事件源示例参见 [`MCPServer` 事件参考](/reference/tools/mcp-server#events-experimental)和 [`MCPClient` 事件参考](/reference/tools/mcp-client#events-property-experimental)。[MCP 事件示例](https://github.com/mastra-ai/mastra/tree/main/examples/mcp-events)演示了 Agent 流程如何端到端连接本地 stdio 服务器。
