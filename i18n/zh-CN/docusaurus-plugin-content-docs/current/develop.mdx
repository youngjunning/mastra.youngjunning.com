# 开发

创建 Mastra 项目后，就可以开发、运行和测试 Agent。

## 在本地运行 Mastra {/* #run-mastra-locally */}

要快速查看 Agent 的运行效果，可以使用 [Mastra Studio](/docs/studio/overview)。在项目根目录运行 [`mastra dev`](/reference/cli/mastra#mastra-dev)，启动 Studio 和本地开发服务器。

```bash npm2yarn
npx mastra dev
```

访问 [`http://localhost:4111`](http://localhost:4111) 打开 Studio，测试 Agent 并查看运行记录。

开发服务器也会为 Agent、Tool 和 Workflow 提供 API。访问 [`http://localhost:4111/api`](http://localhost:4111/api) 查看可用接口，再用 [Mastra Client](/docs/server/mastra-client) 接入前端。

修改 `src/mastra/` 目录后，开发服务器会自动重启，开发时无需手动重启。

## 用 AI 辅助开发 {/* #build-with-ai */}

Mastra 提供 Skill 和 CLI，帮助编程 Agent 写出高质量的 Mastra 代码。

### Mastra Skills {/* #mastra-skills */}

AI 模型掌握的 Mastra API 信息可能已过时。[Mastra Skills](https://github.com/mastra-ai/skills) 为编程 Agent 提供实现指南和最佳实践，包括如何获取最新的 Mastra 文档。编程 Agent 还可以与 [Mastra Factory](https://factory.mastra.ai) 交互。

手动安装 Skill：

```bash npm2yarn
npx skills add mastra-ai/skills
```

定期更新 Skill，获取最新指南：

```bash npm2yarn
npx skills update mastra
```

:::note

用 [create mastra](/docs) 创建项目时，命令会自动安装 Mastra Skills，供编程 Agent 发现和使用。

:::

### Mastra CLI {/* #mastra-cli */}

通过 [`mastra` CLI](/reference/cli/mastra)，编程 Agent 可以反复测试改动并查看结果。该 CLI 提供对 Agent、Workflow、Tool、Memory、Evals、Trace 和日志的访问。

例如，编程 Agent 可以先运行一个 Agent，再拉取 Trace 检查结果：

```bash
npx mastra api --url http://localhost:4111 agent run agent '{"messages":"Hello"}'
npx mastra api --url http://localhost:4111 trace list
```

记得安装 [Mastra Skills](#mastra-skills)，让编程 Agent 知道如何使用 CLI。

## 项目结构 {/* #project-structure */}

采用框架时，项目结构是最早需要确定的事项之一。建议把框架代码放在 `src/mastra/` 下，将相关组件归入各自的文件或目录，再在 `src/mastra/index.ts` 中统一配置和注册。

最小的项目结构如下：

```text
src/
  mastra/
    agents/
      agent.ts
    tools/
      tool.ts
    workflows/
      workflow.ts
    scorers/
      scorer.ts
    skills.ts
    index.ts
```

默认布局和推荐约定见[项目结构参考](/reference/project-structure)。

## 基于文件的 Agent {/* #file-based-agents */}

:::note

只有运行 `mastra dev` 或 `mastra build` 时，Mastra 才会按文件自动发现 Agent。如果应用直接导入 `mastra`（包括通过 Web 框架或服务器适配器导入），请在代码中注册这些 Agent，或将 Mastra 作为独立服务器运行。

:::

:::tip[📹 观看视频]

[如何创建第一个基于文件的 Agent](https://www.youtube.com/watch?v=5Kfn-oYkJNg\&t=18s)

:::

使用基于文件的 Agent 时，Mastra 会从 `src/mastra/` 下支持的文件中自动[发现](/reference/file-based-agents/config#discovery-lifecycle) Agent 和相关组件。只需按约定组织文件，无须逐个导入组件并注册到 [`Mastra`](/reference/core/mastra-class) 实例。

文件布局直接反映项目结构。你和编程 Agent 都能从目录看懂各部分的关系，无须追查代码如何组装它们。

可以在整个项目中使用基于文件的 Agent，也可以逐步引入，让它与代码中定义的组件并存。目前尚未支持所有 Mastra 功能和使用场景。

### 创建第一个 Agent {/* #create-your-first-agent */}

每个基于文件的 Agent 在 `src/mastra/agents/` 下都有自己的目录。要创建可运行的 Agent，请添加 `config.ts` 来配置模型及运行时选项，再添加 `instructions.md` 来定义始终生效的提示词：

```text
src/mastra/agents/
  writing-assistant/
    config.ts
    instructions.md
```

目录名是 Agent 的默认 `id` 和 `name`。在此示例中，Mastra 将 Agent 注册为 `writing-assistant`。

```typescript title="src/mastra/agents/writing-assistant/config.ts"
import { agentConfig } from '@mastra/core/agent'

export default agentConfig({
  model: '__GATEWAY_OPENAI_MODEL__',
})
```

```markdown title="src/mastra/agents/writing-assistant/instructions.md"
Rewrite text clearly and concisely.
```

运行 `npx mastra dev`，在 Studio 中选择 `writing-assistant` 进行测试。

### 自动发现机制 {/* #how-discovery-works */}

Mastra 根据路径识别并命名用文件定义的功能。Agent 目录名决定默认的 `id` 和 `name`。例如，`tools/search_docs.ts` 将 Tool 注册为 `search_docs`，`skills/style-guide.md` 则将 Skill 注册为 `style-guide`。其他扩展路径见下表。

### 扩展 Agent {/* #extend-your-agent */}

要为 Agent 增加功能，请添加相应的文件或目录：

| 路径 | 提供的功能 |
| - | - |
| [`tools/<tool-name>.ts`](/reference/file-based-agents/tools) | 模型可调用的函数 |
| [`skills/<skill-name>.md`](/reference/file-based-agents/skills) | Agent 在相关场景下加载的详细指南 |
| [`memory.ts`](/reference/file-based-agents/memory) | 对话历史和工作上下文 |
| [`workspace.ts` 和 `workspace/`](/reference/file-based-agents/workspace) | 访问文件系统和 Shell |
| [`subagents/<agent-id>/`](/reference/file-based-agents/subagents) | 父 Agent 可以委派任务的专用 Agent |

把功能文件放在使用它们的 Agent 旁。开发服务器每次启动或重启时，Mastra 都会发现并注册这些文件。

完整的文件约定和配置选项见[基于文件的 Agent 参考](/reference/file-based-agents/config)。
