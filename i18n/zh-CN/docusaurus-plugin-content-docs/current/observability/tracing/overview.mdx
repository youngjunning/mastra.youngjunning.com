# 用法

追踪是一种可观测性信号，用于记录请求经过 Agent、Workflow、Tool 和模型调用的过程。Mastra 将每项操作表示为一个 span，并将相关 span 归入同一条 Trace，以便查看完整的执行路径。

本页重点介绍 Trace 的执行结果、span 层级、采样、元数据、过滤、Trace ID 和第三方追踪上下文。

<Inject>
  **供 AI Agent 使用：**运行 `npx mastra api trace list '{"page":0,"perPage":20}'`，即可直接查看最近的 Trace，无需打开 Studio 或编写临时脚本。此命令需要已配置可观测性且正在运行的 Mastra 服务器；可用 `npx mastra dev` 启动本地服务器，或通过 `--url` 指定可访问服务器的基础 URL。构造其他过滤条件前，先运行 `npx mastra api trace list --schema`。安装 Mastra Skill：`npx skills add mastra-ai/skills --skill mastra`，可获取完整的 API CLI 命令发现、目标指定、schema、身份验证及错误处理指南。
</Inject>

## 何时使用追踪 {/* #when-to-use-tracing */}

* 查看完整执行路径，排查 Agent 或 Workflow 的异常行为。
* 追踪单个请求中的模型调用、Tool 调用和 Workflow 步骤。
* 附加 Trace 专属的元数据和标签，以便过滤和排查。
* 将 Mastra Trace 接入第三方追踪系统。

## 开始使用 {/* #get-started */}

要开始追踪，请先在 Mastra 实例中配置可观测性，再运行 Agent 或 Workflow。可通过以下功能调整其行为：

* [配置](/docs/observability/overview#configuration)：可观测性的基础配置、多套配置，以及无服务器环境下缓冲数据的送出
* [存储](/docs/observability/overview#storage)：Trace、日志和指标的存储路由

## 执行结果 {/* #execution-outcomes */}

span 通过三个原生字段描述单次执行的结果：

* `outcome`：执行结果，例如 `success`、`error`、`abort`、`interrupted`、`suspend`、`limit`、`blocked` 或 `unknown`。
* `stopReason`：可选的机器可读原因，例如 `max_steps`、`guardrail` 或 `observer_failed`。
* `stopReasonContext`：关于该原因的简要可选信息，例如提供商错误码、处理器 ID、信号 ID 或相关 span ID。

若 outcome 为 `null` 或不存在，表示尚未记录结果。可用 `endTime` 判断 span 是否结束。旧版可观测性实现可能使已结束的 span 仍保留 `null`。恰好在允许的最后一步完成属于 `success`；用尽步数后仍需继续执行则是 `limit / max_steps`。

通过 `stopWhen` 或迭代 hook 按预设条件结束时，会记录 `success`，并以 `stop_condition` 或 `iteration_hook` 作为停止原因。委托成功后，若 supervisor 调用 `bail()`，则记录 `success / delegation_bail`。若被委托的 worker 失败后 hook 再退出，worker 保留自身的失败结果，supervisor 则记录 `interrupted / delegation_bail`；`stopReasonContext` 中包含 `causeOutcome`，以及已知时的 `causeStopReason`。

调用方取消时，目标运行记录 `abort / caller_cancelled`；因此而停止的未完成子 span 记录 `interrupted / caller_cancelled`。运行超时则在该运行上记录 `limit / timeout`，被超时中断的工作记录 `interrupted / timeout`。已完成的 span 保留原有结果。通用清理流程会将其余无法分类的 span 结束为 `unknown`。

若[护栏](/docs/agents/guardrails)触发 tripwire 并停止执行，结果为 `blocked / guardrail`。上下文会标明对应处理器：

```json
{
  "outcome": "blocked",
  "stopReason": "guardrail",
  "stopReasonContext": { "processorId": "moderation" }
}
```

对于 Mastra 生成的结果，`stopReasonContext` 是用于提示信息的扁平摘要，最多包含三个标量字段。它不包含原始错误消息、信号内容、tripwire 元数据或嵌套原因。字符串最多 128 个字符；超限的值会被省略。缺失信息不会补空字段，若没有可用信息，上下文为 `null`。

自定义生产者可以提供自己的结果字符串、停止原因和上下文对象。这些值会在 span 更新、导出和重建过程中保留，并遵循与 span 元数据相同的序列化限制。框架的允许列表仅适用于 Mastra 生成的上下文。

模型 chunk span 只在输出处理器接受或脱敏内容后才记录该内容。提供商的耗时和完成状态另行记录，不捕获原始 chunk 内容。Workflow 主动等待时记录 `suspend`；执行器停止并移交未完成工作时记录 `interrupted`，即使持久化的 Workflow 状态为 `waiting` 也是如此。

当 observer 失败并使主执行停止时，observer span 记录自身结果，主 span 报告 `interrupted / observer_failed`。上下文通过 `observerSpanId` 指向 observer 的 memory 操作，并用 `causeOutcome` 和 `causeStopReason` 概括其结果。例如，observer 因上下文窗口耗尽而停止时，其结果仍是 `limit / context_window_exceeded`；请查看该 span 获取诊断信息。信号中断只保留 `signalId` 和 `signalType`。

如果配置的失败策略允许主执行继续，主执行仍可能成功。护栏重试后若恢复，最终成功结果以及此前被拒绝尝试的独立结果都会保留。

`MastraStorageExporter` 和 `MastraPlatformExporter` 会在导出的 span 记录中携带这些字段。要持久化这些字段，存储实现也必须支持它们。

模型推理 span（`MODEL_INFERENCE`）衡量提供商执行过程并记录用量。模型 chunk span（`MODEL_CHUNK`）记录经输出处理器接受或转换后的内容。chunk 属于逻辑步骤（`MODEL_STEP`），因此缓冲的输出即使在提供商执行结束后才到达，也不会晚于其父 span 结束。在 Agent 流式处理路径中，推理 span 不再捕获响应输出；请改用处理后的 chunk span 或生成结果中的输出。

## 采样策略 {/* #sampling-strategies */}

采样用于控制收集哪些 Trace，以平衡可观测性需求与资源成本。

在高流量生产环境中，收集每条 Trace 可能既昂贵又没有必要。

采样策略可以捕获具有代表性的 Trace 子集，同时确保不会漏掉错误和重要操作的关键信息。

可在可观测性配置层设置采样：

```ts title="src/mastra/index.ts"
import { Mastra } from '@mastra/core'
import { Observability } from '@mastra/observability'

export const mastra = new Mastra({
  observability: new Observability({
    configs: {
      '10_percent': {
        serviceName: 'my-service',
        // Sample 10% of traces
        sampling: {
          type: 'ratio',
          probability: 0.1,
        },
        exporters: [new MastraStorageExporter()],
      },
    },
  }),
})
```

`sampling` 选项控制收集哪些 Trace，帮助平衡可观测性需求与资源成本。Mastra 支持四种采样策略：

1. **始终采样**：收集全部 Trace。适合需要完整可见性的开发、调试或低流量场景。

   ```ts
   sampling: {
     type: 'always'
   }
   ```

2. **从不采样**：完全关闭追踪。适合追踪没有价值的特定环境，或需要暂时关闭追踪但保留配置的情况。

   ```ts
   sampling: {
     type: 'never'
   }
   ```

3. **按比例采样**：随机采集一定比例的 Trace。适合希望获得统计洞察、又不想承担全量追踪成本的生产环境。概率取值为 0（不采集）到 1（全部采集）。

   ```ts oxfmt:false
   sampling: {
     type: 'ratio',
     probability: 0.1  // Sample 10% of traces
   }
   ```

4. **自定义采样**：根据请求上下文、元数据或业务规则实现采样逻辑。适合按用户等级、请求类型或错误条件采样等复杂场景。

   ```ts oxfmt:false
   sampling: {
     type: 'custom',
     sampler: (options) => {
       // Sample premium users at higher rate
       if (options?.metadata?.userTier === 'premium') {
         return Math.random() < 0.5; // 50% sampling
       }

       // Default 1% sampling for others
       return Math.random() < 0.01;
     }
   }
   ```

## 添加自定义元数据 {/* #adding-custom-metadata */}

添加自定义元数据，在 Trace 中记录应用特有的上下文，以便排查生产问题。

元数据可以包含业务逻辑信息和性能指标，也可以携带用户上下文或其他有助于解释执行过程的信息。

可通过追踪上下文向任意 span 添加元数据：

```ts
execute: async (inputData, context) => {
  const startTime = Date.now()
  const response = await fetch(inputData.endpoint)

  // Add custom metadata to the current span
  context?.tracingContext.currentSpan?.update({
    metadata: {
      apiStatusCode: response.status,
      endpoint: inputData.endpoint,
      responseTimeMs: Date.now() - startTime,
      userTier: inputData.userTier,
      region: process.env.AWS_REGION,
    },
  })

  return await response.json()
}
```

此处设置的元数据会显示在所有已配置的 exporter 中。

### 用部署环境标记 Trace {/* #tagging-traces-with-the-deployment-environment */}

在 Mastra 顶层设置 `environment`，即可自动为所有可观测性信号附上部署环境，而不必每次调用都传入 `tracingOptions.metadata.environment`。

```ts title="src/mastra/index.ts"
import { Mastra } from '@mastra/core'
import { Observability } from '@mastra/observability'

export const mastra = new Mastra({
  environment: 'production',
  observability: new Observability({
    configs: {
      default: {
        serviceName: 'my-service',
        exporters: [new MastraStorageExporter()],
      },
    },
  }),
})
```

如果未设置 `environment`，通过 `mastra dev` 启动的运行会使用 `development`（尽管开发服务器自身的 `NODE_ENV=production`）；其他情况下，Mastra 会回退到 `process.env.NODE_ENV`。若都未设置，该字段保持未定义，不会猜测其值。

每次调用传入的 `tracingOptions.metadata.environment` 始终优先，因此可以按需覆盖单次调用的环境值。

### 自动从 `RequestContext` 提取元数据 {/* #automatic-metadata-from-requestcontext */}

无需手动为每个 span 添加元数据。你可以让 Mastra 自动从 RequestContext 提取值，并附加到同一条 Trace 的所有 span。这有助于在整条 Trace 中一致地记录用户 ID、环境信息、功能开关及其他请求级数据。

#### 配置层提取 {/* #configuration-level-extraction */}

在追踪配置中指定要提取的 RequestContext 键。使用该配置创建的所有 span 都会自动将这些键对应的值加入元数据：

```ts title="src/mastra/index.ts"
import { Mastra } from '@mastra/core'
import { Observability } from '@mastra/observability'

export const mastra = new Mastra({
  observability: new Observability({
    configs: {
      default: {
        serviceName: 'my-service',
        requestContextKeys: ['userId', 'environment', 'tenantId'],
        exporters: [new MastraStorageExporter()],
      },
    },
  }),
})
```

现在，使用 RequestContext 执行 Agent 或 Workflow 时，这些值会被自动提取：

```ts
const requestContext = new RequestContext()
requestContext.set('userId', 'user-123')
requestContext.set('environment', 'production')
requestContext.set('tenantId', 'tenant-456')

// All spans in this trace automatically get userId, environment, and tenantId metadata
const result = await agent.generate('Hello', {
  requestContext,
})
```

#### 按请求添加 {/* #per-request-additions */}

可通过 `tracingOptions.requestContextKeys` 添加本次 Trace 专用的键；它们会与配置层的键合并：

```ts
const requestContext = new RequestContext()
requestContext.set('userId', 'user-123')
requestContext.set('environment', 'production')
requestContext.set('experimentId', 'exp-789')

const result = await agent.generate('Hello', {
  requestContext,
  tracingOptions: {
    requestContextKeys: ['experimentId'], // Adds to configured keys
  },
})

// All spans now have: userId, environment, AND experimentId
```

#### 提取嵌套值 {/* #nested-value-extraction */}

使用点号路径从 RequestContext 提取嵌套值：

```ts
export const mastra = new Mastra({
  observability: new Observability({
    configs: {
      default: {
        requestContextKeys: ['user.id', 'session.data.experimentId'],
        exporters: [new MastraStorageExporter()],
      },
    },
  }),
})

const requestContext = new RequestContext()
requestContext.set('user', { id: 'user-456', name: 'John Doe' })
requestContext.set('session', { data: { experimentId: 'exp-999' } })

// Metadata will include: { user: { id: 'user-456' }, session: { data: { experimentId: 'exp-999' } } }
```

#### 工作原理 {/* #how-it-works */}

1. **计算 TraceState**：创建根 span、启动 Trace 时，Mastra 合并配置层和请求层的键，确定要提取的内容。
2. **自动提取**：根 span（Agent 运行、Workflow 执行）自动从 RequestContext 提取元数据。
3. **子 span 提取**：创建子 span 时，若传入 `requestContext`，子 span 也可以提取元数据。
4. **元数据优先级**：span 选项中显式传入的元数据始终优先于提取的元数据。

### 为 Trace 添加标签 {/* #adding-tags-to-traces */}

标签是用于分类和过滤 Trace 的字符串标记。元数据包含结构化键值数据，标签则是便于快速过滤和组织的普通字符串。

执行 Agent 或 Workflow 时，通过 `tracingOptions.tags` 添加标签：

```ts
// With agents
const result = await agent.generate('Hello', {
  tracingOptions: {
    tags: ['production', 'experiment-v2', 'user-request'],
  },
})

// With workflows
const run = await mastra.getWorkflow('myWorkflow').createRun()
const result = await run.start({
  inputData: { data: 'process this' },
  tracingOptions: {
    tags: ['batch-processing', 'priority-high'],
  },
})
```

#### 标签的工作方式 {/* #how-tags-work */}

* **仅根 span**：标签只应用于 Trace 的根 span（Agent 运行或 Workflow 运行的 span）。
* **广泛支持**：大多数 exporter 都支持用标签过滤和搜索 Trace：
  * **Braintrust**：原生 `tags` 字段
  * **Langfuse**：Trace 上的原生 `tags` 字段
  * **ArizeExporter**：`tag.tags` OpenInference 属性
  * **OtelExporter**：`mastra.tags` span 属性
  * **OtelBridge**：`mastra.tags` span 属性
* **可与元数据组合**：同一次 `tracingOptions` 中可以同时使用 `tags` 和 `metadata`。

```ts
const result = await agent.generate([{ role: 'user', content: 'Analyze this' }], {
  tracingOptions: {
    tags: ['production', 'analytics'],
    metadata: { userId: 'user-123', experimentId: 'exp-456' },
  },
})
```

#### 常见标签用法 {/* #common-tag-patterns */}

* **环境**：`"production"`、`"staging"`、`"development"`
* **功能开关**：`"feature-x-enabled"`、`"beta-user"`
* **请求类型**：`"user-request"`、`"batch-job"`、`"scheduled-task"`
* **优先级**：`"priority-high"`、`"priority-low"`
* **实验**：`"experiment-v1"`、`"control-group"`、`"treatment-a"`

### 为 Trace 命名 {/* #naming-a-trace */}

同一个 Agent 或 Workflow 的每次运行默认使用相同的根 span 名称，例如 `workflow run: 'skill-analyze'`。如果一个 Workflow 会处理多种对象，可在 `tracingOptions` 中设置 `rootSpanName`，为每次运行命名。该名称会替换 Studio Trace 列表及支持显示 span 名称的 exporter 中的根 span 名称。

```ts
const run = await mastra.getWorkflow('skillAnalyze').createRun()

await run.start({
  inputData: { skillId: 'typescript' },
  tracingOptions: {
    rootSpanName: 'skill-analyze: typescript',
  },
})
```

该名称仅用于根 span，子 span 保留默认名称。Workflow 或 Agent ID 会单独存为 `entityId` 和 `entityName`，因此实体过滤仍然有效。

基于 OpenTelemetry 的 exporter 和 Langfuse exporter 会根据实体 ID 构造 span 和 Trace 名称，因此不受影响。若要命名 Langfuse Trace，请按 [Langfuse 集成文档](/integrations/observability/langfuse)设置 `metadata.traceName`。

### 隐藏敏感输入/输出 {/* #hiding-sensitive-inputoutput */}

处理敏感数据时，你可能希望避免在可观测性平台中记录输入和输出值。可在 `tracingOptions` 中使用 `hideInput` 和 `hideOutput`，从整条 Trace 的所有 span 中排除这些数据：

```ts
// Hide input data (e.g., user credentials, PII)
const result = await agent.generate([{ role: 'user', content: 'Process this sensitive data' }], {
  tracingOptions: {
    hideInput: true, // Input will be hidden from all spans
  },
})

// Hide output data (e.g., generated secrets, confidential results)
const result = await agent.generate([{ role: 'user', content: 'Generate API keys' }], {
  tracingOptions: {
    hideOutput: true, // Output will be hidden from all spans
  },
})

// Hide both input and output
const result = await agent.generate([{ role: 'user', content: 'Handle confidential request' }], {
  tracingOptions: {
    hideInput: true,
    hideOutput: true,
  },
})
```

#### 工作原理 {/* #how-it-works-1 */}

* **整条 Trace 生效**：在根 span 上设置后，这些选项会应用于 Trace 中的所有子 span，包括 Tool 调用和模型生成等。
* **导出时过滤**：执行期间数据仍可在内部使用，但导出 span 到可观测性平台时会排除这些数据。
* **可与其他选项组合**：`hideInput`/`hideOutput` 可以与 `tags`、`metadata` 及其他 `tracingOptions` 一同使用。

```ts
const result = await agent.generate([{ role: 'user', content: 'Sensitive operation' }], {
  tracingOptions: {
    hideInput: true,
    hideOutput: true,
    tags: ['sensitive-operation', 'pii-handling'],
    metadata: { operationType: 'credential-processing' },
  },
})
```

如需更精细地控制敏感数据，可使用 [Sensitive Data Filter](/reference/observability/tracing/processors/sensitive-data-filter) 处理器。它能遮盖密码、令牌、密钥等指定字段，同时保留其余输入和输出。

#### 子 span 与元数据提取 {/* #child-spans-and-metadata-extraction */}

在 Tool 或 Workflow 步骤内创建子 span 时，可传入 `requestContext` 参数，以启用元数据提取：

```ts
execute: async (inputData, context) => {
  // Create child span WITH requestContext - gets metadata extraction
  const dbSpan = context?.tracingContext.currentSpan?.createChildSpan({
    type: 'generic',
    name: 'database-query',
    requestContext: context?.requestContext, // Pass to enable metadata extraction
  })

  const results = await db.query('SELECT * FROM users')
  dbSpan?.end({ output: results })

  // Or create child span WITHOUT requestContext - no metadata extraction
  const cacheSpan = context?.tracingContext.currentSpan?.createChildSpan({
    type: 'generic',
    name: 'cache-check',
    // No requestContext - won't extract metadata
  })

  return results
}
```

你可以精确控制哪些子 span 包含 RequestContext 元数据。根 span（Agent 或 Workflow 执行）始终自动提取；子 span 只有在显式传入 `requestContext` 时才会提取。

## 创建子 span {/* #creating-child-spans */}

子 span 可追踪 Workflow 步骤或 Tool 内部的细粒度操作，例如数据库查询、API 调用、文件操作或复杂计算。这种层级结构有助于定位性能瓶颈，并了解操作的准确执行顺序。

在 Tool 调用或 Workflow 步骤中创建子 span，以追踪具体操作：

```ts
execute: async (inputData, context) => {
  // Create another child span for the main database operation
  const querySpan = context?.tracingContext.currentSpan?.createChildSpan({
    type: 'generic',
    name: 'database-query',
    input: { query: inputData.query },
    metadata: { database: 'production' },
  })

  try {
    const results = await db.query(inputData.query)
    querySpan?.end({
      output: results.data,
      metadata: {
        rowsReturned: results.length,
        queryTimeMs: results.executionTime,
        cacheHit: results.fromCache,
      },
    })
    return results
  } catch (error) {
    querySpan?.error({
      error,
      metadata: { retryable: isRetryableError(error) },
    })
    throw error
  }
}
```

子 span 会自动继承父 span 的 Trace 上下文，在可观测性平台中保持层级关系。

## span 格式化 {/* #span-formatting */}

Mastra 提供两种在 span 数据送达可观测性平台前进行转换的方式：**span 处理器**和**自定义 span 格式化器**。两者都能修改、过滤或丰富 Trace 数据，但作用层级和用途不同。

| 功能 | Span 处理器 | 自定义 span 格式化器 |
| - | - | - |
| 配置层级 | 可观测性配置 | 单个 exporter |
| 处理对象 | 内部 `Span` 对象 | 导出的 `ExportedSpan` 数据 |
| 适用范围 | 所有 exporter | 单个 exporter |
| 异步支持 | 否 | 是 |
| 用途 | 安全、过滤、信息补充 | 平台专属格式化、异步补充信息 |

需要对所有 exporter 应用同步转换（例如遮盖敏感数据）时，使用 **span 处理器**。如果不同 exporter 需要同一数据的不同表示形式（例如一个平台使用纯文本，另一个使用结构化数据），或需要从外部 API 获取数据等异步操作，则使用**自定义 span 格式化器**。

### span 处理器 {/* #span-processors */}

span 处理器会在导出前转换、过滤或丰富 Trace 数据。它们构成从创建 span 到导出的处理流水线，可用于安全、合规或调试。每个处理器运行一次，其结果影响所有 exporter。

#### 内置处理器 {/* #built-in-processors */}

* [Sensitive Data Filter](/reference/observability/tracing/processors/sensitive-data-filter) 会遮盖敏感信息，并在默认可观测性配置中启用。

#### 创建自定义处理器 {/* #creating-custom-processors */}

实现 `SpanOutputProcessor` 接口即可创建自定义 span 处理器。以下基础示例将 span 中的所有输入文本转为小写：

```ts title="src/processors/lowercase-input-processor.ts"
import type { SpanOutputProcessor, AnySpan } from '@mastra/core/observability'
import { Mastra } from '@mastra/core'
import { Observability } from '@mastra/observability'

export class LowercaseInputProcessor implements SpanOutputProcessor {
  name = 'lowercase-processor'

  process(span: AnySpan): AnySpan {
    span.input = `${span.input}`.toLowerCase()
    return span
  }

  async shutdown(): Promise<void> {
    // Cleanup if needed
  }
}

// Use the custom processor
export const mastra = new Mastra({
  observability: new Observability({
    configs: {
      development: {
        spanOutputProcessors: [new LowercaseInputProcessor(), new SensitiveDataFilter()],
        exporters: [new MastraStorageExporter()],
      },
    },
  }),
})
```

`process()` 必须修改收到的 span 并返回同一实例，或者返回 `undefined` 以丢弃该 span。不要返回副本（例如 `{ ...span, input: '...' }`）：`exportSpan()` 和 `isValid` 是实际 span 实例上的成员，副本无法导出。此时 Mastra 会记录处理器错误并丢弃该 span。

处理器按定义顺序执行，因此可以串联多个转换。常见用途包括：

* 遮盖密码、令牌和 API 密钥等敏感数据
* 添加环境专属元数据
* 按条件过滤 span
* 统一数据格式
* 补充业务上下文

## span 过滤 {/* #span-filtering */}

span 过滤可在数据抵达可观测性平台前减少噪声和按 span 计费的成本。可针对每个可观测性实例单独配置，让不同 exporter 或环境保留不同详细程度的数据。

* 使用 `excludeSpanTypes`，以少量配置排除整类 span。
* 需要根据导出的 span 数据执行自定义逻辑时，使用 `spanFilter`。

以下示例展示如何在同一配置中组合这两个选项：

```ts title="src/mastra/index.ts"
import { Mastra } from '@mastra/core'
import { SpanType } from '@mastra/core/observability'
import { Observability, MastraStorageExporter } from '@mastra/observability'
import { LangfuseExporter } from '@mastra/langfuse'

export const mastra = new Mastra({
  observability: new Observability({
    configs: {
      default: {
        serviceName: 'my-app',
        exporters: [new MastraStorageExporter(), new LangfuseExporter()],
        excludeSpanTypes: [SpanType.MODEL_CHUNK, SpanType.MODEL_STEP],
        spanFilter: span => {
          if (span.type === SpanType.TOOL_CALL && span.attributes?.success) {
            return false
          }

          return true
        },
      },
    },
  }),
})
```

过滤在导出时按以下顺序进行：

1. 除非 `includeInternalSpans` 为 `true`，否则先丢弃内部 span。
1. `excludeSpanTypes` 移除匹配的 span 类型。
1. `spanOutputProcessors` 转换剩余的 span。
1. `spanFilter` 决定是否保留最终导出的 span。

如果 `spanFilter` 抛出异常，Mastra 会保留 span 并记录错误，避免数据悄然丢失。完整 span 类型列表和更多示例见 [span 过滤参考文档](/reference/observability/tracing/span-filtering)。

### 自定义 span 格式化器 {/* #custom-span-formatters */}

自定义 span 格式化器可调整 span 在特定可观测性平台中的呈现方式。与 span 处理器不同，它按 exporter 配置，因此各目标平台可以使用不同格式，并且支持同步和异步操作。

#### 用途 {/* #use-cases */}

* **从 AI SDK 消息提取纯文本**：将结构化消息数组转换为可读文本。
* **转换输入/输出格式**：自定义特定平台的数据呈现方式。
* **平台专属字段映射**：按平台要求增减字段。
* **异步补充数据**：从外部 API 或数据库获取更多上下文。

#### 配置 {/* #configuration */}

在任意 exporter 配置中添加 `customSpanFormatter`：

```ts title="src/mastra/index.ts"
import { BraintrustExporter } from '@mastra/braintrust'
import { LangfuseExporter } from '@mastra/langfuse'
import { SpanType } from '@mastra/core/observability'
import type { CustomSpanFormatter } from '@mastra/core/observability'
import { Mastra } from '@mastra/core'
import { Observability } from '@mastra/observability'

// Formatter that extracts plain text from AI messages
const plainTextFormatter: CustomSpanFormatter = span => {
  if (span.type === SpanType.AGENT_RUN && Array.isArray(span.input)) {
    const userMessage = span.input.find(m => m.role === 'user')
    return {
      ...span,
      input: userMessage?.content ?? span.input,
    }
  }
  return span
}

export const mastra = new Mastra({
  observability: new Observability({
    configs: {
      default: {
        serviceName: 'my-service',
        exporters: [
          // Braintrust gets plain text formatting
          new BraintrustExporter({
            customSpanFormatter: plainTextFormatter,
          }),
          // Langfuse keeps the original structured format
          new LangfuseExporter(),
        ],
      },
    },
  }),
})
```

#### 串联多个格式化器 {/* #chaining-multiple-formatters */}

使用 `chainFormatters` 组合多个格式化器。链中可以同时包含同步和异步格式化器：

```ts
import { chainFormatters } from '@mastra/observability'

const inputFormatter: CustomSpanFormatter = span => ({
  ...span,
  input: extractPlainText(span.input),
})

const outputFormatter: CustomSpanFormatter = span => ({
  ...span,
  output: extractPlainText(span.output),
})

const exporter = new BraintrustExporter({
  customSpanFormatter: chainFormatters([inputFormatter, outputFormatter]),
})
```

#### 异步格式化器 {/* #async-formatters */}

自定义 span 格式化器支持异步操作，例如从外部 API 或数据库获取数据，为 span 补充信息：

```ts
import type { CustomSpanFormatter } from '@mastra/core/observability'

// Async formatter that enriches spans with user data
const userEnrichmentFormatter: CustomSpanFormatter = async span => {
  const userId = span.metadata?.userId
  if (!userId) return span

  // Fetch user data from your API or database
  const userData = await fetchUserData(userId)

  return {
    ...span,
    metadata: {
      ...span.metadata,
      userName: userData.name,
      userEmail: userData.email,
      department: userData.department,
    },
  }
}

// Async formatter that looks up additional context
const contextEnrichmentFormatter: CustomSpanFormatter = async span => {
  if (span.type !== SpanType.AGENT_RUN) return span

  // Fetch experiment configuration
  const experimentConfig = await getExperimentConfig(span.metadata?.experimentId)

  return {
    ...span,
    metadata: {
      ...span.metadata,
      experimentVariant: experimentConfig?.variant,
      experimentGroup: experimentConfig?.group,
    },
  }
}

// Use async formatters with an exporter
const exporter = new BraintrustExporter({
  customSpanFormatter: userEnrichmentFormatter,
})

// Or chain sync and async formatters together
const exporter = new LangfuseExporter({
  customSpanFormatter: chainFormatters([
    plainTextFormatter, // sync
    userEnrichmentFormatter, // async
    contextEnrichmentFormatter, // async
  ]),
})
```

:::note
异步格式化器会增加 span 导出延迟。请让异步操作尽快完成（低于 100 毫秒），避免拖慢应用。对于经常访问的数据，可考虑使用缓存。
:::

## 序列化选项 {/* #serialization-options */}

序列化选项控制 span 数据（输入、输出和属性）在导出前如何截断。处理大型载荷、深层嵌套对象，或优化 Trace 存储时，这些选项很有用。

### 配置 {/* #configuration-1 */}

在可观测性配置中添加 `serializationOptions`：

```ts title="src/mastra/index.ts"
import { Mastra } from '@mastra/core'
import { Observability } from '@mastra/observability'

export const mastra = new Mastra({
  observability: new Observability({
    configs: {
      default: {
        serviceName: 'my-service',
        serializationOptions: {
          maxStringLength: 2048, // Maximum length for string values (default: 131072)
          maxDepth: 10, // Maximum depth for nested objects (default: 8)
          maxArrayLength: 100, // Maximum number of items in arrays (default: 50)
          maxObjectKeys: 75, // Maximum number of keys in objects (default: 50)
        },
        exporters: [new MastraStorageExporter()],
      },
    },
  }),
})
```

### 可用选项 {/* #available-options */}

| 选项 | 默认值 | 说明 |
| - | - | - |
| `maxStringLength` | 131072 (128 KB) | 字符串值的最大长度；超过后会截断。 |
| `maxDepth` | 8 | 嵌套对象的最大深度；更深层级会被省略。 |
| `maxArrayLength` | 50 | 数组的最大元素数；多余元素会被省略。 |
| `maxObjectKeys` | 50 | 对象的最大键数；多余的键会被省略。 |

### 使用场景 {/* #use-cases-1 */}

**提高限制以便调试**：提高这些上限，可以捕获大型文档、API 响应及其他数据结构的更多上下文：

```ts oxfmt:false
serializationOptions: {
  maxStringLength: 262144, // Capture longer text content (256 KB)
  maxDepth: 12,            // Handle deeply nested JSON responses
  maxArrayLength: 200,     // Keep more items from large lists
}
```

**缩小生产环境中的 Trace 体积**：不需要完整载荷时，降低上限可减少存储成本并改善性能：

```ts oxfmt:false
serializationOptions: {
  maxStringLength: 256,   // Truncate strings aggressively
  maxDepth: 3,            // Shallow object representation
  maxArrayLength: 10,     // Keep only first few items
  maxObjectKeys: 20,      // Limit object keys
}
```

所有选项均可省略；未指定时使用上表所示的默认值。

## 获取 Trace ID {/* #retrieving-trace-ids */}

启用追踪后，执行 Agent 或 Workflow 的响应会包含 `traceId`，可用于在可观测性平台中查找完整 Trace。这有助于调试、客户支持，或将 Trace 与系统中的其他事件关联起来。

### Agent Trace ID {/* #agent-trace-ids */}

`generate` 和 `stream` 方法都会在响应中返回 Trace ID：

```ts
// Using generate
const result = await agent.generate('Hello')

console.log('Trace ID:', result.traceId)

// Using stream
const streamResult = await agent.stream('Tell me a story')

console.log('Trace ID:', streamResult.traceId)
```

### Workflow Trace ID {/* #workflow-trace-ids */}

Workflow 执行也会返回 Trace ID：

```ts
// Create a workflow run
const run = await mastra.getWorkflow('myWorkflow').createRun()

// Start the workflow
const result = await run.start({
  inputData: { data: 'process this' },
})

console.log('Trace ID:', result.traceId)

// Or stream the workflow
const { stream, getWorkflowState } = run.stream({
  inputData: { data: 'process this' },
})

// Get the final state which includes the trace ID
const finalState = await getWorkflowState()
console.log('Trace ID:', finalState.traceId)
```

### 使用 Trace ID {/* #using-trace-ids */}

获得 Trace ID 后，可以：

1. **在 Studio 中查找 Trace**：打开 Trace 视图，按 ID 搜索。
1. **在外部平台中查询 Trace**：在 Langfuse、Braintrust、MLflow 或其他可观测性平台中使用该 ID。
1. **关联日志**：将 Trace ID 写入应用日志，以便交叉查找。
1. **分享以协助调试**：向支持团队或开发者提供 Trace ID 供其排查。

只有启用追踪时才可能获得 Trace ID。如果追踪已关闭，或采样排除了该请求，`traceId` 会是 `undefined`。

## 集成外部追踪系统 {/* #integrating-with-external-tracing-systems */}

如果应用已使用 OpenTelemetry 或 Datadog 等分布式追踪系统，可以将 Mastra Trace 接入父 Trace 上下文，从而串联应用及其中 Mastra Agent 或 Workflow 调用的请求路径。

### 传入外部 Trace ID {/* #passing-external-trace-ids */}

通过 `tracingOptions` 参数指定父系统的 Trace 上下文：

```ts
// Get trace context from your existing tracing system
const parentTraceId = getCurrentTraceId() // Your tracing system
const parentSpanId = getCurrentSpanId() // Your tracing system

// Execute Mastra operations as part of the parent trace
const result = await agent.generate('Analyze this data', {
  tracingOptions: {
    traceId: parentTraceId,
    parentSpanId: parentSpanId,
  },
})

// The Mastra trace will now appear as a child in your distributed trace
```

### OpenTelemetry 集成 {/* #opentelemetry-integration */}

通过 OpenTelemetry 集成，Mastra Trace 可以直接出现在现有可观测性平台中：

```ts
import { trace } from '@opentelemetry/api'

// Get the current OpenTelemetry span
const currentSpan = trace.getActiveSpan()
const spanContext = currentSpan?.spanContext()

if (spanContext) {
  const result = await agent.generate(userMessage, {
    tracingOptions: {
      traceId: spanContext.traceId,
      parentSpanId: spanContext.spanId,
    },
  })
}
```

### Workflow 集成 {/* #workflow-integration */}

Workflow 也支持相同的 Trace 传递方式：

```ts
const workflow = mastra.getWorkflow('data-pipeline')
const run = await workflow.createRun()

const result = await run.start({
  inputData: { data: '...' },
  tracingOptions: {
    traceId: externalTraceId,
    parentSpanId: externalSpanId,
  },
})
```

### 将运行嵌套到先前的 Mastra 运行之下 {/* #nesting-a-run-under-an-earlier-mastra-run */}

`parentSpanId` 可以指向两类 span。一类属于你自己的追踪系统，如上面的示例。此时，Mastra 会将该运行视为其导出 Trace 的顶层，由该运行设置 Trace 名称、输入、输出和标签。

另一类是同一条 Trace 中较早的 Mastra 运行，例如对已完成对话评分的 LLM 裁判。此时设置 `nestUnderParent: true`。新运行会成为该 span 的子节点，Trace 则保留最初启动运行的名称、输入、输出、标签、用户和会话。

```ts
const turn = await assistant.generate('When does my order ship?')

await judge.generate(`Grade this answer: ${turn.text}`, {
  tracingOptions: {
    traceId: turn.traceId,
    parentSpanId: turn.spanId,
    nestUnderParent: true,
  },
})
```

`nestUnderRun()` 辅助函数可根据先前运行的结果生成相同选项：

```ts
import { nestUnderRun } from '@mastra/core/observability'

await judge.generate(`Grade this answer: ${turn.text}`, {
  tracingOptions: nestUnderRun(turn),
})
```

两次运行可以位于不同进程。如果缺少有效的 `traceId` 或 `parentSpanId`，Mastra 会忽略 `nestUnderParent`；如果追踪桥接在另一条 Trace 中启动运行，也会忽略该选项。[Langfuse](/integrations/observability/langfuse) 和 [Braintrust](/integrations/observability/braintrust) exporter 会使用此选项。其他 exporter 仅应用标签规则。

### ID 格式要求 {/* #id-format-requirements */}

Mastra 会验证 Trace ID 和 span ID，以确保兼容：

* **Trace ID**：1–32 个十六进制字符（OpenTelemetry 使用 32 个）。
* **span ID**：1–16 个十六进制字符（OpenTelemetry 使用 16 个）。

对无效 ID，Mastra 会记录错误并继续执行：

* 无效 Trace ID → 生成新的 Trace ID
* 无效父 span ID → 忽略父子关系

因此，即使输入格式错误，追踪也不会导致应用崩溃。

### 示例：Express 中间件 {/* #example-express-middleware */}

以下完整示例展示如何在 Express 应用中传递 Trace：

```ts
import { trace } from '@opentelemetry/api'
import express from 'express'

const app = express()

app.post('/api/analyze', async (req, res) => {
  // Get current OpenTelemetry context
  const currentSpan = trace.getActiveSpan()
  const spanContext = currentSpan?.spanContext()

  const result = await agent.generate(req.body.message, {
    tracingOptions: spanContext
      ? {
          traceId: spanContext.traceId,
          parentSpanId: spanContext.spanId,
        }
      : undefined,
  })

  res.json(result)
})
```

这会生成一条包含 HTTP 请求处理过程和 Mastra Agent 执行过程的分布式 Trace，可在所选可观测性平台中查看。

### MCP 调用 {/* #mcp-calls */}

Model Context Protocol（MCP）调用无需额外配置，就能关联调用方 Trace 与服务端 Trace。Agent 或 Workflow 通过 `MCPClient` 调用 Tool 时，处理请求的 `MCPServer` 会保留自己的 Trace，并记录指向 Tool 调用 span 的链接；该 Tool 调用 span 也会反向链接到服务端 span。两端各自保留 Trace、根 span 和 Trace 摘要。如果服务端使用追踪桥接，其 HTTP 插桩继续沿用调用方的 Trace，则该请求会加入调用方 Trace。Mastra 存储会随 span 保存这些链接；支持 span 链接的 exporter 也会发送它们。

非 Mastra 软件位于任一端时也适用。详情参阅 [`MCPServer` 参考文档](/reference/tools/mcp-server#linking-to-the-callers-trace)；如需发送自己的 Trace 上下文，参阅 [`MCPClient` 参考文档](/reference/tools/mcp-client)。

## 追踪哪些操作 {/* #what-gets-traced */}

Mastra 会自动为以下操作创建 span：

### Agent 操作 {/* #agent-operations */}

* **Agent 运行**：包含指令和 Tool 的完整执行过程。
* **信号触发的运行**：`AGENT_RUN` span 在 `attributes.signal` 下记录起始信号的 `id`、`type`、`tagName` 和 `attributes`。
* **LLM 调用**：记录模型交互、token 用量和参数。
* **Tool 执行**：记录函数调用的输入和输出。
* **Memory 操作**：记录 Thread 和语义召回。

### Workflow 操作 {/* #workflow-operations */}

* **Workflow 运行**：记录从开始到结束的完整执行过程。
* **单个步骤**：记录步骤处理过程及其输入/输出。
* **控制流**：记录条件分支、循环和并行执行。
* **等待操作**：记录延迟和事件等待。
