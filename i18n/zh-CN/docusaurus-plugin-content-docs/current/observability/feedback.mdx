# 反馈

反馈记录用于捕捉人工参与的信号，例如点赞或点踩、评分、评论和更正。需要将用户、QA、Studio 或系统的评审数据关联到 Trace 或 Span，并与其他可观测性信号一起查询时，可以使用反馈。

与指标和分数不同，反馈通常来自人工或评审 Workflow。数值型反馈支持聚合、分组、绘制时间序列图和查询百分位数。

## 何时使用反馈 {/* #when-to-use-feedback */}

- 收集用户对 Agent 回答的满意度评分。
- 将 QA 的评论或更正与相应的 Trace 一起保存。
- 按 Agent、环境或实验创建评分仪表盘。

## 添加反馈 {/* #add-feedback */}

在应用代码中调用 `mastra.observability.addFeedback()`，为 Trace 或 Span 添加反馈。该辅助方法在可观测性入口上是可选的，请先确认当前实现支持它。所有客户端方法见[客户端 SDK 可观测性参考](/reference/client-js/observability)。

```typescript title="src/mastra/feedback.ts"
if (!mastra.observability.addFeedback) {
  throw new Error('Feedback is not supported by the active observability implementation')
}

await mastra.observability.addFeedback({
  traceId: 'trace-123',
  spanId: 'span-456',
  feedback: {
    feedbackSource: 'user',
    feedbackType: 'rating',
    value: 1,
    comment: 'The answer solved my issue.',
  },
})
```

反馈会发给每个已配置且支持反馈的导出器，由各导出器独立处理自己的目标。即使本地存储中没有该 Trace，反馈仍可送达 Mastra Platform 或其他导出器。

[`MastraStorageExporter`](/docs/observability/integrations/exporters/mastra-storage) 在保存反馈前，会先从已配置的存储中查找 Trace 或 Span。如果重试后仍找不到目标，它会记录警告并跳过本地写入。请在进程退出前调用 `mastra.observability.flush()` 或 `shutdown()`，完成待处理的投递。

## 查找消息对应的 Trace {/* #find-the-trace-for-a-message */}

反馈通常针对用户已经读过的消息，因此你需要该消息的 `traceId`。无论从流式结果获取助手消息，还是之后从 Memory 召回消息，消息的 `content.metadata` 都包含该值：

```typescript title="src/mastra/message-trace.ts"
const agent = mastra.getAgent('weatherAgent')
const memory = await agent.getMemory()

const { messages } = await memory!.recall({ threadId, perPage: false })

const message = messages.find(m => m.id === messageId)
const traceId = message?.content.metadata?.traceId
```

该值与运行结果中的 `traceId` 指向同一个 Trace。因此，无论反馈是在生成消息时收集的，还是后来针对已保存的消息收集的，都会关联到同一个 Trace。关闭追踪时生成的消息没有 `traceId`。

### 在 `useChat` 中读取 Trace ID {/* #read-the-trace-id-in-usechat */}

[`chatRoute()`](/reference/ai-sdk/chat-route) 和 [`handleChatStream()`](/reference/ai-sdk/handle-chat-stream) 会将本次运行的 `traceId` 传给 `messageMetadata` 回调。在 `start` 部分返回它，客户端就能在实时消息中取得该值，无需查询服务器：

```typescript title="src/mastra/index.ts"
chatRoute({
  path: '/chat/:agentId',
  messageMetadata: ({ part, traceId }) => (part.type === 'start' ? { traceId } : undefined),
})
```

```tsx title="app/chat.tsx"
const { messages } = useChat<UIMessage<{ traceId?: string }>>()

const lastMessage = messages.at(-1)
const traceId = lastMessage?.role === 'assistant' ? lastMessage.metadata?.traceId : undefined
```

如果用 `messageMetadataSchema` 验证元数据，请加入 `traceId: z.string().optional()`。将 `traceId` 和用户的投票一起发送到自己的路由，然后在那里调用 `addFeedback()`。该值来自客户端，所以添加反馈前，请验证带有此 `traceId` 的消息确实属于调用者。

## 创建反馈 {/* #create-feedback */}

每次调用 `createFeedback()` 都必须提供 `feedbackType` 和 `value`。要将反馈关联到 Trace 或具体的 Span，请添加 `traceId` 或 `spanId`。还可以用 `feedbackSource` 提供可选的字符串元数据，例如 `user`、`qa`、`studio` 或 `system`。

在存储层调用时，请包含 `timestamp`，因为该方法会直接写入存储。

```typescript
const observability = await mastra.getStorage()!.getStore('observability')

await observability!.createFeedback({
  feedback: {
    feedbackId: 'feedback-rating-1',
    timestamp: new Date(),
    traceId: 'trace-123',
    spanId: 'span-456',
    feedbackSource: 'user',
    feedbackType: 'rating',
    value: 1,
    comment: 'The answer solved my issue.',
    tags: ['production'],
  },
})

await observability!.createFeedback({
  feedback: {
    feedbackId: 'feedback-comment-1',
    timestamp: new Date(),
    feedbackSource: 'qa',
    feedbackType: 'comment',
    value: 'Needs a citation before shipping.',
    experimentId: 'support-agent-eval',
  },
})
```

## 列出反馈 {/* #list-feedback */}

使用 `listFeedback()` 分页查看原始记录，或以增量模式轮询。

```typescript
const result = await observability!.listFeedback({
  filters: {
    feedbackType: 'rating',
    feedbackSource: 'user',
    timestamp: { start: new Date(Date.now() - 7 * 24 * 60 * 60 * 1000) },
  },
  pagination: { page: 0, perPage: 20 },
  orderBy: { field: 'timestamp', direction: 'DESC' },
})

console.log(result.feedback, result.pagination?.hasMore)
```

筛选条件包括 `traceId`、`spanId` 等目标字段，`feedbackType`、`feedbackSource`、`feedbackUserId` 等反馈字段，以及 `entityName`、`environment`、`experimentId` 和 `tags` 等共享上下文字段。完整字段见 [`FeedbackFilter`](/reference/observability/feedback#feedbackfilter)。使用 HTTP 时，这些字段作为查询参数传递，例如 `GET /api/observability/feedback?traceId=trace-123&environment=production`。详见[列表查询参数](/reference/observability/feedback#list-query-parameters)。

```typescript
await observability!.listFeedback({
  filters: {
    traceId: 'trace-123',
    feedbackType: ['rating', 'thumbs'],
    tags: ['production'],
  },
})
```

## 删除反馈 {/* #delete-feedback */}

使用 `deleteFeedback()` 按 ID 删除反馈记录，例如删除含有敏感数据的评论。每次请求最多接受 1,000 个 `feedbackIds`，删除操作是幂等的。可选字段 `organizationId` 和 `resourceId` 分别按组织和资源筛选，可以单独使用，也可以一起使用。在 Studio 的 Trace 或 Span 的 **Feedback** 选项卡中，每条评论都有删除操作。通过 `deleteTraces()` 删除 Trace，也会删除与之关联的反馈。参见[删除 Trace](/reference/client-js/observability#deleting-traces)。

```typescript
await observability!.deleteFeedback({
  feedbackIds: ['feedback-1', 'feedback-2'],
})
```

删除的记录也会从反馈分析中消失。ClickHouse 用轻量删除隐藏数据行，但不保证立即从物理存储中移除。因此，开源部署必须配置[可观测性数据保留期限](/reference/storage/retention)，才能彻底清除这些记录。删除成功后，相应请求会标记为已应用；如果失败，请求仍未应用，不会阻止更新尚可见的反馈，可再次调用删除 API 重试。在 ClickHouse 上，下次更新评审状态时也会重试删除。重试成功则报告找不到该反馈；再次失败则保存新状态，并返回删除错误。开源部署没有后台协调程序。请为每种可观测性信号设置保留期限，使删除请求在其保护的信号数据行到期后再到期。如果任何一种信号没有保留期限，删除请求也不会过期，以防已删除的数据重新出现。在 ClickHouse 上，删除 API 不会改动单独的增量游标表。该表只保存标识符，不保存反馈内容，其中的记录会在两天内过期。

## 查询反馈分析数据 {/* #query-feedback-analytics */}

OLAP 反馈查询针对数值型 `value` 字段，可用于查询评分、以 `1` 和 `-1` 编码的点赞或点踩、QA 数值评分及其他数值型反馈。

```typescript
const rating = await observability!.getFeedbackAggregate({
  feedbackType: 'rating',
  feedbackSource: 'user',
  aggregation: 'avg',
  comparePeriod: 'previous_day',
})

const byAgent = await observability!.getFeedbackBreakdown({
  feedbackType: 'rating',
  groupBy: ['entityName'],
  aggregation: 'avg',
  filters: { environment: 'production' },
})

const ratingsOverTime = await observability!.getFeedbackTimeSeries({
  feedbackType: 'rating',
  aggregation: 'avg',
  interval: '1h',
  groupBy: ['feedbackSource'],
})
```

完整字段、筛选条件、返回类型和百分位数查询参数见[反馈参考](/reference/observability/feedback)。

本地运行时在 `/api/observability/feedback` 提供列表路由，并在相关路径提供分析路由。参见 [HTTP 路由表](/reference/observability/feedback#http-routes)和[列表查询参数](/reference/observability/feedback#list-query-parameters)。Mastra Platform 提供独立的托管查询 API，不区分版本。区域端点、身份验证和项目作用域见 [Feedback API](/docs/mastra-platform/api#feedback-api)。

## 将反馈导出到 Mastra Platform {/* #export-feedback-to-mastra-platform */}

[`MastraPlatformExporter`](/reference/observability/tracing/exporters/mastra-platform-exporter) 将反馈发送到 Mastra Platform，由平台在需要时查找目标 Trace 或 Span。无需在本地存储 Trace。只有还想保留本地副本时，才需要添加 `MastraStorageExporter`。

Studio 将反馈发送到负责读取 Trace 的后端。如果由开源服务器处理 HTTP 创建请求，服务器会先在本地保存反馈，并通知已配置的导出器。导出器异步投递，因此即使 HTTP 请求成功，远端也可能还看不到这条记录。直接写入存储会绕过导出器。

## 将反馈导出到外部平台 {/* #export-feedback-to-external-platforms */}

反馈通过可观测性事件总线传递，支持反馈的导出器会自动转发。[PostHog 导出器](/reference/observability/tracing/exporters/posthog#feedback-export)将反馈作为原生 `$ai_feedback` 事件发送，该事件会出现在 PostHog 中关联的 Trace 上。
