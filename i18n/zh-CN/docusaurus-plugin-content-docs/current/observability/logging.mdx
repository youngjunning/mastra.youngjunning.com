# 日志

Mastra 以结构化日志记录函数执行、输入数据和输出响应。

部署到 Mastra Platform 后，可在仪表盘中查看日志。在自托管或自定义环境中，可根据传输配置将日志写入文件或发送到外部服务。

<Inject>
  **供 AI Agent 使用：**运行 `npx mastra api log list '{"level":"error","page":0,"perPage":50}'` 可直接查看近期错误日志，无需打开 Studio 或编写临时脚本。此命令要求 Mastra 服务器正在运行并已配置可观测性日志。使用 `npx mastra dev` 启动本地服务器，或用 `--url` 指定可访问服务器的基础 URL。要构造其他筛选条件，请先运行 `npx mastra api log list --schema`。运行 `npx skills add mastra-ai/skills --skill mastra` 安装 Mastra 的 Skill，获取关于 API CLI 命令发现、目标选择、参数结构、身份验证和错误处理的完整指南。
</Inject>

## 使用 `PinoLogger` 配置日志 {/* #configuring-logs-with-pinologger */}

使用 CLI [初始化 Mastra 项目](/docs)时，项目默认包含 `PinoLogger`。

```typescript title="src/mastra/index.ts"
import { Mastra } from '@mastra/core/mastra'
import { PinoLogger } from '@mastra/loggers'

export const mastra = new Mastra({
  logger: new PinoLogger({
    name: 'Mastra',
    level: 'info',
  }),
})
```

完整配置选项见 [PinoLogger](/reference/logging/pino-logger)。

## 将日志写入可观测性存储 {/* #logging-to-observability-storage */}

配置[可观测性](/docs/observability/overview)后，日志记录调用会自动转发至可观测性存储。应用及 Mastra 内部组件的 `debug`、`info`、`warn`、`error` 和 `trackException` 调用都会与 Trace 一同存储。低于 `logging.level` 指定的最低级别的日志会被过滤。

无需修改代码。支持适配器的日志记录器（`PinoLogger` 和 `ConsoleLogger`）会将每条记录写入各自的目标，并从同一条记录生成用于导出的日志。对于不支持适配器的自定义日志记录器，Mastra 会将其封装，使日志同时写入原记录器和可观测性系统。

### 输出与 Trace 关联的日志 {/* #trace-correlated-log-output */}

在已追踪的操作（Agent 运行、Workflow 步骤或 Tool 调用）中写日志时，Mastra 会将 `trace_id` 和 `span_id` 注入日志记录器的原生输出。这些字段使用 W3C Trace Context 格式，与 Studio 显示的 Trace 对应，因此可以直接从标准输出的日志行找到对应的 Trace。

要让标准输出生成机器可解析的 JSON，请将 `PinoLogger` 配置为 `prettyPrint: false`。默认开启的美化输出会生成便于阅读的文本：

```typescript title="src/mastra/index.ts"
import { Mastra } from '@mastra/core/mastra'
import { PinoLogger } from '@mastra/loggers'

export const mastra = new Mastra({
  logger: new PinoLogger({ name: 'Mastra', level: 'info', prettyPrint: false }),
})
```

生成的记录如下：

```json
{
  "level": 30,
  "time": 1755522000000,
  "name": "Mastra",
  "trace_id": "0af7651916cd43dd8448eb211c80319c",
  "span_id": "b7ad6b7169203331",
  "msg": "tool executed"
}
```

在没有追踪的操作中，输出不包含这些字段。`ConsoleLogger` 会将这些字段作为额外的对象参数附加到控制台输出。`PinoLogger` 则会把字段发送到所有目标，包括标准输出、文件及自定义传输目标。如果提供了自己的 pino `mixin`，其中的字段会保留，发生冲突时优先使用 `trace_id` 和 `span_id`。

可通过 `loggerOptions` 分别控制 Trace 关联和日志导出：

```typescript title="src/mastra/index.ts"
import { Mastra } from '@mastra/core/mastra'
import { PinoLogger } from '@mastra/loggers'

export const mastra = new Mastra({
  logger: new PinoLogger({ name: 'Mastra', level: 'info' }),
  loggerOptions: {
    correlation: true, // inject trace_id/span_id into native log output (default: true)
    export: false, // keep trace-correlated output without storing logs in observability (default: true)
  },
})
```

### 自定义日志记录器 {/* #custom-loggers */}

自定义的 `IMastraLogger` 实现仍可使用。Mastra 会通过已弃用的双写兼容机制，将日志调用转发到可观测性系统，但不会在日志记录器的原生输出中添加 `trace_id` 或 `span_id`。要在输出中关联 Trace，请实现 `@mastra/core/logger` 提供的 `__attachObservability()` 适配器钩子：

```typescript
import { MastraLogger, buildLogRecordData } from '@mastra/core/logger'
import type { LoggerAdapterContext } from '@mastra/core/logger'

class MyLogger extends MastraLogger {
  #adapterContext?: LoggerAdapterContext

  __attachObservability(ctx: LoggerAdapterContext): void {
    this.#adapterContext = ctx
  }

  #log(level: 'debug' | 'info' | 'warn' | 'error', message: string, args: unknown[]): void {
    const ctx = this.#adapterContext
    // Inject trace fields into your native record when correlation is enabled
    const traceFields = ctx?.options.correlation ? ctx.resolveTraceFields() : undefined
    console[level === 'debug' ? 'info' : level](
      message,
      ...args,
      ...(traceFields ? [traceFields] : []),
    )
    // Export the same record to observability when export is enabled
    if (ctx?.options.export) {
      ctx.getLogSink()?.[level](message, buildLogRecordData(args))
    }
  }

  debug(message: string, ...args: unknown[]): void {
    this.#log('debug', message, args)
  }

  info(message: string, ...args: unknown[]): void {
    this.#log('info', message, args)
  }

  warn(message: string, ...args: unknown[]): void {
    this.#log('warn', message, args)
  }

  error(message: string, ...args: unknown[]): void {
    this.#log('error', message, args)
  }
}
```

### 配置可观测性日志级别 {/* #configuring-observability-log-level */}

写入可观测性存储的日志级别可以独立于控制台配置。在可观测性实例的配置中添加 `logging` 选项：

```typescript {12-15} title="src/mastra/index.ts"
import { Mastra } from '@mastra/core/mastra'
import { PinoLogger } from '@mastra/loggers'
import { Observability, MastraStorageExporter } from '@mastra/observability'

export const mastra = new Mastra({
  logger: new PinoLogger({ name: 'Mastra', level: 'debug' }),
  observability: new Observability({
    configs: {
      default: {
        serviceName: 'my-app',
        exporters: [new MastraStorageExporter()],
        logging: {
          enabled: true, // set to false to disable log forwarding
          level: 'info', // minimum level: 'debug' | 'info' | 'warn' | 'error' | 'fatal'
        },
      },
    },
  }),
})
```

在这个示例中，控制台输出 `debug` 及以上级别的日志，可观测性存储只写入 `info` 及以上级别的日志。这样既可在开发时查看详细的控制台日志，又能减少存储中的低级别日志。

| 选项 | 类型 | 默认值 | 说明 |
| - | - | - | - |
| `enabled` | `boolean` | `true` | 设为 `false` 可停止向可观测性存储转发所有日志。 |
| `level` | `LogLevel` | `'warn'` | 最低严重级别。低于该级别的日志会被丢弃。 |

### 查询日志 {/* #querying-logs */}

可以通过 Mastra 客户端 SDK 查询写入可观测性存储的日志：

```typescript
import { MastraClient } from '@mastra/client-js'

const client = new MastraClient()

const logs = await client.listLogsVNext({
  filters: { level: 'error' },
  pagination: { page: 1, perPage: 50 },
  orderBy: { field: 'timestamp', direction: 'desc' },
})
```

使用 DuckDB 或 ClickHouse 等持久化存储后端时，重启后日志仍然可用，可以用来分析历史记录。

## 自定义日志 {/* #customizing-logs */}

在 Workflow 步骤和 Tool 中，都可以通过 `mastra.getLogger()` 获取日志记录器实例。记录器支持标准严重级别 `debug`、`info`、`warn` 和 `error`。

### 在 Workflow 步骤中记录日志 {/* #logging-from-workflow-steps */}

在 Workflow 步骤的 `execute` 函数中，通过 `mastra` 参数访问日志记录器，用于记录与该步骤执行相关的信息。

```typescript {6-7} title="src/mastra/workflows/test-workflow.ts" oxfmt:false
import { createWorkflow, createStep } from "@mastra/core/workflows";
import { z } from "zod";

const step1 = createStep({
  execute: async ({ mastra }) => {
    const logger = mastra.getLogger();
    logger.info("workflow info log");

    return {
      output: ""
    };
  }
});

export const testWorkflow = createWorkflow({...})
  .then(step1)
  .commit();
```

### 在 Tool 中记录日志 {/* #logging-from-tools */}

Tool 同样可以通过 `mastra` 参数访问日志记录器，记录该 Tool 执行期间的活动。

```typescript {6-7} title="src/mastra/tools/test-tool.ts"
import { createTool } from '@mastra/core/tools'
import { z } from 'zod'

export const testTool = createTool({
  execute: async (inputData, context) => {
    const logger = context?.mastra.getLogger()
    logger?.info('tool info log')

    return {
      output: '',
    }
  },
})
```

### 在日志中附加数据 {/* #logging-with-additional-data */}

日志记录方法可通过可选的第二个参数接收附加数据。传入结构化对象后，便可在可观测性存储中筛选日志。

```typescript {9} title="src/mastra/workflows/test-workflow.ts" oxfmt:false
import { createWorkflow, createStep } from "@mastra/core/workflows";
import { z } from "zod";

const step1 = createStep({
  execute: async ({ mastra }) => {
    const testAgent = mastra.getAgent("testAgent");
    const logger = mastra.getLogger();

    logger.info("workflow info log", { agent: testAgent });

    return {
      output: ""
    };
  }
});

export const testWorkflow = createWorkflow({...})
  .then(step1)
  .commit();
```
