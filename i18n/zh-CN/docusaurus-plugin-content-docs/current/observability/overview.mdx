# 可观察性

Mastra 的可观察性系统使您可以了解每个Agent运行、Workflow程步骤、Tool调用和模型交互。Agent行为取决于模型响应、提示、Tool、内存和Workflow程状态，因此可观察性可以帮助您从第一天开始检查运行时决策。

从跟踪相关的页面开始：

* [**用法**](/docs/observability/tracing/overview)：检查执行的跨度层次结构、输入、输出、令牌使用、计时和跟踪上下文。
* [**记录**](/docs/observability/logging)：转发来自应用程序和 Mastra 内部的结构化日志条目，自动与跟踪相关联。
* [**反馈**](/docs/observability/feedback)：存储与迹线和跨度关联的评级、评论、更正和其他评论信号。
* [**贮存**](#storage)：选择用于持久跟踪、日志、指标聚合和反馈查询的后端。

使用[**Metrics**](/docs/observability/metrics/overview) to analyze aggregate usage, performance, and cost data derived from spans. No additional instrumentation is required. Use [**Configuration**](#configuration) to enable the signals and exporters your application needs.

## 何时使用可观察性 {/* #when-to-use-observability */}

* 通过检查完整的决策路径、Tool调用和模型响应来调试意外的Agent行为。
* 监控Agent、Workflow程和Tool之间的延迟以识别瓶颈。
* 随着时间的推移跟踪代币消耗和估计成本以控制支出。
* 通过跟踪每个步骤的执行情况来诊断Workflow程故障。
* 比较提示或模型更改之前和之后的Agent性能。

## 各个部分如何组合在一起 {/* #how-the-pieces-fit-together */}

配置可观察性后，每个Agent运行、Workflow执行、Tool调用和模型交互都会生成一个[span](https://opentelemetry.io/docs/concepts/signals/traces/#spans). Mastra organizes related spans into traces that show the full request lifecycle as a hierarchical timeline.

当跨度结束时，Mastra 会提取持续时间、令牌计数和成本估算，而无需任何额外代码。这些指标为聚合仪表板提供支持[Studio](/docs/studio/observability).

每一个`logger.info()`, `logger.warn()`, or `logger.error()` call within a traced context is tagged with the current trace and span IDs. You can move from a log entry directly to the trace that produced it.

反馈记录人工审核信号，例如评级、评论和更正。反馈可以链接到跟踪和跨度，然后使用用于指标的相同可观察性存储进行查询。

这些记录共享相关字段，例如跟踪 ID、跨度 ID、实体类型和实体名称。您可以使用它们从指标峰值转移到其跟踪、日志和相关反馈。

## 快速入门 {/* #quickstart */}

安装`@mastra/observability` and storage backends that support traces and metrics:

```bash npm2yarn
npm install @mastra/observability @mastra/libsql @mastra/duckdb
```

然后在您的 Mastra 实例中配置可观察性。以下示例使用复合存储将Observability数据路由到 DuckDB（支持指标聚合），同时将其他所有内容保留在 LibSQL 中：

```ts title="src/mastra/index.ts"
import { Mastra } from '@mastra/core/mastra'
import { LibSQLStore } from '@mastra/libsql'
import { DuckDBStore } from '@mastra/duckdb'
import { MastraCompositeStore } from '@mastra/core/storage'
import {
  Observability,
  MastraStorageExporter,
  MastraPlatformExporter,
  SensitiveDataFilter,
} from '@mastra/observability'

export const mastra = new Mastra({
  storage: new MastraCompositeStore({
    id: 'composite-storage',
    default: new LibSQLStore({
      id: 'mastra-storage',
      url: 'file:./mastra.db',
    }),
    domains: {
      observability: await new DuckDBStore().getStore('observability'),
    },
  }),
  observability: new Observability({
    configs: {
      default: {
        serviceName: 'mastra',
        exporters: [
          new MastraStorageExporter(), // Persists observability events to Mastra Storage
          new MastraPlatformExporter(), // Sends observability events to Mastra platform (if MASTRA_PLATFORM_ACCESS_TOKEN is set)
        ],
        spanOutputProcessors: [
          new SensitiveDataFilter(), // Redacts sensitive data like passwords, tokens, keys
        ],
      },
    },
  }),
})
```

它支持跟踪、日志转发和指标。 Mastra 还支持外部跟踪Provider，例如 Langfuse、Datadog 和任何 OpenTelemetry 兼容平台。看[Maintaining Studio access](#maintaining-studio-access) to keep Mastra Studio access while sending data to an external provider.

## 配置 {/* #configuration */}

可观察性在 Mastra 实例上配置一次，并适用于跟踪、日志和指标。

### 基本配置 {/* #basic-config */}

可观察性配置通常包含：

* `serviceName`：附加到导出的Observability数据的服务标识符。
* `exporters`：跟踪、日志和派生指标的一个或多个目标。
* `spanOutputProcessors`：在导出跨度之前运行的转换。

### 维护 Studio 访问权限 {/* #maintaining-studio-access */}

当您添加外部导出器时，请保留`MastraStorageExporter` for Studio observability and/or `MastraPlatformExporter` for hosted Mastra platform observability.

以下示例仅显示可观察性配置。单独配置存储。

```ts title="src/mastra/observability.ts"
import { Observability, MastraStorageExporter, MastraPlatformExporter } from '@mastra/observability'
import { ArizeExporter } from '@mastra/arize'

export const observability = new Observability({
  configs: {
    production: {
      serviceName: 'my-service',
      exporters: [
        new ArizeExporter({
          endpoint: process.env.PHOENIX_COLLECTOR_ENDPOINT,
          apiKey: process.env.PHOENIX_API_KEY,
        }),
        new MastraStorageExporter(),
        new MastraPlatformExporter(),
      ],
    },
  },
})
```

### 无服务器环境中的刷新 {/* #flushing-in-serverless-environments */}

在无服务器环境中，在运行时暂停或退出之前刷新可观察性导出器：

```ts
await mastra.observability.flush()
```

在无服务器环境中使用外部存储而不是本地文件存储。看[Storage](#storage) for storage selection and routing.

### 多配置设置 {/* #multi-config-setup */}

当不同的环境或请求类型需要不同的导出器或采样行为时，请使用多个配置。在运行时选择活动配置`configSelector`.

```ts title="src/mastra/index.ts"
import { Mastra } from '@mastra/core'
import { Observability, MastraStorageExporter } from '@mastra/observability'
import { LangfuseExporter } from '@mastra/langfuse'

const storageExporter = new MastraStorageExporter()
const langfuseExporter = new LangfuseExporter()

export const mastra = new Mastra({
  observability: new Observability({
    configs: {
      development: {
        serviceName: 'my-service-dev',
        exporters: [storageExporter],
      },
      production: {
        serviceName: 'my-service-prod',
        exporters: [storageExporter, langfuseExporter],
      },
    },
    configSelector: () => process.env.NODE_ENV || 'development',
  }),
})
```

对于痕量采样，请参阅[Tracing](/docs/observability/tracing/overview).

## 贮存 {/* #storage */}

存储决定哪些可观察性信号持续存在、哪些查询可用以及指标聚合是否有效。使用专用的可观察性存储而不是主应用程序存储。

### 信号支持 {/* #signal-support */}

存储支持取决于信号和工作负载。`MastraStorageExporter` can persist traces to ClickHouse, PostgreSQL, MSSQL, MongoDB, and LibSQL. Metrics require an analytics-capable store:

* DuckDB：推荐用于本地测试和开发。
* ClickHouse：推荐用于大批量生产可观察性。
* `PostgresStoreVNext`：启用可观测域时支持指标。始终提供一个时间范围以避免完整分区扫描。
* Mastra 平台：使用`MastraPlatformExporter` for hosted observability without managing the backend yourself.

有关完整的Provider列表和支持的跟踪策略，请参阅[Mastra Storage exporter](/docs/observability/integrations/exporters/mastra-storage#storage-provider-support). Use composite storage to route the `observability` domain separately when your primary store doesn't support observability or when the workload needs independent scaling.

### 当地发展 {/* #local-development */}

对于本地开发，请使用：

* `LibSQLStore`用于主应用程序存储
* `DuckDBStore`为`observability` domain
* `MastraStorageExporter`用于本地工作室访问

### 生产部署 {/* #production-deployment */}

可观察性流量通常比应用程序的其余部分写入量更大。生产中：

* 使用`MastraStorageExporter` with ClickHouse for the `observability` domain when you keep observability in your own storage.
* 使用`MastraPlatformExporter` for hosted Mastra platform observability instead of managing the backend yourself.
* 当可观察性需要与主要应用程序数据不同的后端或扩展策略时，请使用复合存储。

有关后端兼容性详细信息和导出器批处理行为，请参阅[Mastra Storage exporter](/docs/observability/integrations/exporters/mastra-storage).
