# 可观测性

Mastra 的可观测性系统让你查看每次 Agent 运行、Workflow 步骤、Tool 调用及模型交互。Agent 的行为取决于模型响应、提示词、Tool、记忆和 Workflow 状态。通过可观测性功能，从开发之初就能检查运行时的决策。

可以先了解以下与 Trace 关联的功能：

- [**用量**](/docs/observability/tracing/overview)：查看某次执行的 Span 层级、输入、输出、token 用量、耗时和 Trace 上下文。
- [**日志**](/docs/observability/logging)：转发应用和 Mastra 内部的结构化日志条目，并自动关联到 Trace。
- [**反馈**](/docs/observability/feedback)：存储与 Trace 和 Span 关联的评分、评论、纠正内容及其他评审信号。
- [**存储**](#storage)：为持久化 Trace 和日志、汇总指标以及查询反馈选择存储后端。

使用[**指标**](/docs/observability/metrics/overview)分析从 Span 汇总得到的用量、性能和成本数据，无需额外埋点。通过[**配置**](#configuration)启用应用所需的信号和导出器。

## 何时使用可观测性 {/* #when-to-use-observability */}

- 查看完整的决策路径、Tool 调用和模型响应，排查 Agent 的异常行为。
- 监控 Agent、Workflow 和 Tool 的延迟，找出性能瓶颈。
- 持续跟踪 token 消耗和预估成本，控制支出。
- 逐步追踪执行过程，诊断 Workflow 故障。
- 比较更改提示词或模型前后的 Agent 表现。

## 各类数据如何关联 {/* #how-the-pieces-fit-together */}

配置可观测性后，每次 Agent 运行、Workflow 执行、Tool 调用和模型交互都会生成一个 [Span](https://opentelemetry.io/docs/concepts/signals/traces/#spans)。Mastra 将相关的 Span 组织为 Trace，以分层时间线展示请求的完整生命周期。

Span 结束时，Mastra 会自动提取耗时、token 数量和预估成本，无需编写额外代码。[Studio](/docs/studio/observability) 的汇总仪表盘使用这些指标。

在受追踪的上下文中，每次调用 `logger.info()`、`logger.warn()` 或 `logger.error()` 都会附带当前的 Trace ID 和 Span ID。通过这些 ID，可从日志条目直接定位到对应的 Trace。

反馈可以记录评分、评论和纠正内容等人工评审信号。可以将反馈关联到 Trace 和 Span，再通过存储指标的同一可观测性存储查询。

这些记录共用 Trace ID、Span ID、实体类型和实体名称等关联字段。发现指标突增时，可以通过这些字段找到对应的 Trace、日志及相关反馈。

## 快速入门 {/* #quickstart */}

安装 `@mastra/observability` 和支持 Trace 及指标的存储后端：

```bash npm2yarn
npm install @mastra/observability @mastra/libsql @mastra/duckdb
```

然后在 Mastra 实例中配置可观测性。以下示例使用组合存储，将可观测性数据路由到支持指标汇总的 DuckDB，其余数据保存在 LibSQL：

```ts title="src/mastra/index.ts"
import { Mastra } from '@mastra/core/mastra'
import { LibSQLStore } from '@mastra/libsql'
import { DuckDBStore } from '@mastra/duckdb'
import { MastraCompositeStore } from '@mastra/core/storage'
import {
  Observability,
  MastraStorageExporter,
  MastraPlatformExporter,
  SensitiveDataFilter,
} from '@mastra/observability'

export const mastra = new Mastra({
  storage: new MastraCompositeStore({
    id: 'composite-storage',
    default: new LibSQLStore({
      id: 'mastra-storage',
      url: 'file:./mastra.db',
    }),
    domains: {
      observability: await new DuckDBStore().getStore('observability'),
    },
  }),
  observability: new Observability({
    configs: {
      default: {
        serviceName: 'mastra',
        exporters: [
          new MastraStorageExporter(), // Persists observability events to Mastra Storage
          new MastraPlatformExporter(), // Sends observability events to Mastra platform (if MASTRA_PLATFORM_ACCESS_TOKEN is set)
        ],
        spanOutputProcessors: [
          new SensitiveDataFilter(), // Redacts sensitive data like passwords, tokens, keys
        ],
      },
    },
  }),
})
```

上述配置启用了追踪、日志转发和指标。Mastra 也支持 Langfuse、Datadog 等外部追踪 Provider，以及任何与 OpenTelemetry 兼容的平台。要在向外部 Provider 发送数据的同时保留对 Mastra Studio 的访问，请参阅[保留 Studio 访问能力](#maintaining-studio-access)。

## 配置 {/* #configuration */}

只需在 Mastra 实例上配置一次可观测性，即可应用于 Trace、日志和指标。

### 基本配置 {/* #basic-config */}

可观测性配置通常包含以下选项：

- `serviceName`：附加到导出的可观测性数据上的服务标识。
- `exporters`：接收 Trace、日志和派生指标的一个或多个目标。
- `spanOutputProcessors`：导出 Span 之前执行的转换。

### 保留 Studio 访问能力 {/* #maintaining-studio-access */}

添加外部导出器时，如需在 Studio 中查看可观测性数据，请保留 `MastraStorageExporter`。如需使用 Mastra Platform 托管的可观测性功能，请保留 `MastraPlatformExporter`。可按需保留其中一个或两个。

以下示例仅展示可观测性配置。存储需单独配置。

```ts title="src/mastra/observability.ts"
import { Observability, MastraStorageExporter, MastraPlatformExporter } from '@mastra/observability'
import { ArizeExporter } from '@mastra/arize'

export const observability = new Observability({
  configs: {
    production: {
      serviceName: 'my-service',
      exporters: [
        new ArizeExporter({
          endpoint: process.env.PHOENIX_COLLECTOR_ENDPOINT,
          apiKey: process.env.PHOENIX_API_KEY,
        }),
        new MastraStorageExporter(),
        new MastraPlatformExporter(),
      ],
    },
  },
})
```

### 在无服务器环境中刷新导出器 {/* #flushing-in-serverless-environments */}

在无服务器环境中，请在运行时暂停或退出之前刷新可观测性导出器，发送待导出的数据：

```ts
await mastra.observability.flush()
```

在无服务器环境中请使用外部存储。本页的[存储](#storage)一节介绍如何选择存储及配置数据路由。

### 使用多套配置 {/* #multi-config-setup */}

不同环境或请求类型需要采用不同的导出器或采样方式时，可以定义多套配置，再用 `configSelector` 在运行时选择要使用的配置。

```ts title="src/mastra/index.ts"
import { Mastra } from '@mastra/core'
import { Observability, MastraStorageExporter } from '@mastra/observability'
import { LangfuseExporter } from '@mastra/langfuse'

const storageExporter = new MastraStorageExporter()
const langfuseExporter = new LangfuseExporter()

export const mastra = new Mastra({
  observability: new Observability({
    configs: {
      development: {
        serviceName: 'my-service-dev',
        exporters: [storageExporter],
      },
      production: {
        serviceName: 'my-service-prod',
        exporters: [storageExporter, langfuseExporter],
      },
    },
    configSelector: () => process.env.NODE_ENV || 'development',
  }),
})
```

Trace 采样见[追踪](/docs/observability/tracing/overview)。

## 存储 {/* #storage */}

存储后端决定哪些可观测性信号可以持久化、支持哪些查询，以及能否汇总指标。请为可观测性使用独立于应用主存储的专用存储。

### 支持的信号 {/* #signal-support */}

选择存储时要考虑信号类型和工作负载。`MastraStorageExporter` 可以将 Trace 持久化到 ClickHouse、PostgreSQL、MSSQL、MongoDB 和 LibSQL。指标需要支持分析的存储后端：

- DuckDB：推荐用于本地测试和开发。
- ClickHouse：推荐用于生产环境中可观测性数据量较大的场景。
- `PostgresStoreVNext`：启用可观测性域后支持指标。查询时务必指定时间范围，避免扫描整个分区。
- Mastra Platform：使用 `MastraPlatformExporter` 接入托管的可观测性功能，无需自行管理后端。

完整的 Provider 列表以及支持的追踪策略见 [Mastra Storage 导出器](/docs/observability/integrations/exporters/mastra-storage#storage-provider-support)。如果主存储不支持可观测性，或可观测性负载需要独立扩缩容，请使用组合存储，将 `observability` 域的数据路由到单独的后端。

### 本地开发 {/* #local-development */}

本地开发时，可以采用以下配置：

- `LibSQLStore` 用于应用的主存储。
- `DuckDBStore` 用于 `observability` 域。
- `MastraStorageExporter` 用于在本地 Studio 中查看数据。

### 生产部署 {/* #production-deployment */}

可观测性数据通常比应用的其他数据更侧重写入。在生产环境中：

- 如果自行存储可观测性数据，在 `observability` 域使用 `MastraStorageExporter` 搭配 ClickHouse。
- 使用 `MastraPlatformExporter` 接入 Mastra Platform 托管的可观测性功能，无需自行管理后端。
- 如果可观测性数据与应用的主要数据需要不同的后端或扩缩容策略，请使用组合存储。

后端兼容性及导出器如何分批处理数据，见 [Mastra Storage 导出器](/docs/observability/integrations/exporters/mastra-storage)。
