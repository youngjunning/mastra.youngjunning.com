# 指标

当跟踪操作完成时，Mastra 会自动从跨度中导出指标。不需要单独的计量仪器。

马斯特拉发出：

* **持续时间指标**用于Agent运行、Workflow程、Tool、模型调用和处理器
* **代币使用指标**用于模型输入和输出，包括提供者报告时的详细令牌类别
* **成本估算**根据代币使用情况、Provider、模型和模型价格计算[models.dev](https://models.dev) or from a [custom gateway](/models/gateways/custom-gateways#model-pricing)

指标保留跟踪关联上下文，因此您可以通过查找相关跨度来调查图表中的更改。请参阅[Automatic metrics reference](/reference/observability/metrics/automatic-metrics) for metric names, labels, and cost fields.

## 何时使用指标 {/* #when-to-use-metrics */}

* 监控Agent、Tool、Workflow程和模型调用之间的延迟
* 随着时间的推移跟踪代币消耗和估计成本
* 比较不同Agent或Tool的成功率和错误率
* 衡量提示、模型或代码更改的效果

## 存储支持 {/* #storage-support */}

指标需要具有分析能力的可观察性存储：

* **鸭数据库**通过`@mastra/duckdb` is recommended for local development.
* **克利克屋**通过`@mastra/clickhouse` is recommended for high-volume production workloads.
* **PostgresStoreVNext**当其可观测域启用时支持指标。
* **内存存储**支持指标，但当进程重新启动时其数据会丢失。
* **谷歌云扳手**默认情况下禁用指标。放`disableMetrics: false` only for light workloads, or route metrics to a dedicated OLAP store.

其他存储适配器（包括 LibSQL、MSSQL 和 MongoDB）可以存储其他Observability信号，但不实现指标存储和查询。

## 设置本地指标 {/* #set-up-local-metrics */}

安装Observability、应用程序存储和 DuckDB 包：

```bash npm2yarn
npm install @mastra/observability @mastra/libsql @mastra/duckdb
```

配置将可观察性域路由到 DuckDB 的复合存储：

```ts title="src/mastra/index.ts"
import { Mastra } from '@mastra/core/mastra'
import { LibSQLStore } from '@mastra/libsql'
import { DuckDBStore } from '@mastra/duckdb'
import { MastraCompositeStore } from '@mastra/core/storage'
import { Observability, MastraStorageExporter, SensitiveDataFilter } from '@mastra/observability'

export const mastra = new Mastra({
  storage: new MastraCompositeStore({
    id: 'composite-storage',
    default: new LibSQLStore({
      id: 'mastra-storage',
      url: 'file:./mastra.db',
    }),
    domains: {
      observability: await new DuckDBStore().getStore('observability'),
    },
  }),
  observability: new Observability({
    configs: {
      default: {
        serviceName: 'mastra',
        exporters: [new MastraStorageExporter()],
        spanOutputProcessors: [new SensitiveDataFilter()],
      },
    },
  }),
})
```

`MastraStorageExporter`将指标保存到配置的可观察性存储中并使它们可供 Studio 使用。使用`MastraPlatformExporter` instead, or alongside it, to send metrics to Mastra Platform.

## 查看和查询指标 {/* #view-and-query-metrics */}

使用[Studio observability dashboard](/docs/studio/observability) to inspect KPI cards, breakdowns, and time-series charts. For custom dashboards and analysis, use the observability store, `@mastra/client-js`, HTTP endpoints, or CLI described in the [Metric queries reference](/reference/observability/metrics/queries).

在生产中，始终在指标查询中包含时间戳范围。时间限制限制了扫描的数据，并允许分区后端跳过不相关的分区或块。
