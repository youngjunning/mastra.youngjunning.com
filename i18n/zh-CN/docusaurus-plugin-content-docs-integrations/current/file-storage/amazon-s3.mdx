# Amazon S3

你可以将文件存储在 Amazon S3 或兼容 S3 的服务中，例如 Cloudflare R2、Neon Object Storage、MinIO、DigitalOcean Spaces 和 Tigris。接口详情请参阅 [WorkspaceFilesystem 接口](/reference/workspace/filesystem)。

## 安装 {/* #installation */}

```bash npm2yarn
npm install @mastra/s3
```

## 用法 {/* #usage */}

将 `S3Filesystem` 添加到 Workspace，再将该 Workspace 分配给 Agent。

```typescript
import { Agent } from '@mastra/core/agent'
import { Workspace } from '@mastra/core/workspace'
import { S3Filesystem } from '@mastra/s3'

const workspace = new Workspace({
  filesystem: new S3Filesystem({
    bucket: 'my-bucket',
    region: 'us-east-1',
    accessKeyId: process.env.AWS_ACCESS_KEY_ID,
    secretAccessKey: process.env.AWS_SECRET_ACCESS_KEY,
  }),
})

const agent = new Agent({
  id: 'file-agent',
  name: 'file-agent',
  model: '__GATEWAY_ANTHROPIC_MODEL_OPUS__',
  workspace,
})
```

### AWS 凭证 Provider 链 {/* #aws-credential-provider-chain */}

未提供凭证时，`S3Filesystem` 使用 AWS SDK 的默认凭证 Provider 链，自动从环境变量、`~/.aws` 配置文件、ECS 容器凭证、EC2 实例配置文件等标准来源查找凭证。

```typescript
import { S3Filesystem } from '@mastra/s3'

// SDK discovers credentials from the environment automatically
const filesystem = new S3Filesystem({
  bucket: 'my-bucket',
  region: 'us-east-1',
})
```

传入凭证 Provider 函数即可自动刷新凭证。部署到 ECS 或 Lambda，或通过 SSO 或 AssumeRole 获取会过期的临时凭证时，可以用这种方式续期。

如果要直接调用 `fromNodeProviderChain()`，请先安装 AWS SDK 的凭证 Provider 包。

```bash npm2yarn
npm install @aws-sdk/credential-providers
```

```typescript
import { S3Filesystem } from '@mastra/s3'
import { fromNodeProviderChain } from '@aws-sdk/credential-providers'

const filesystem = new S3Filesystem({
  bucket: 'my-bucket',
  region: 'us-east-1',
  credentials: fromNodeProviderChain(),
})
```

凭证 Provider 函数仅用于 `S3Filesystem` 的 API 调用。将文件系统挂载到 E2B 或 Daytona Sandbox 时，挂载配置仅接受静态的 `accessKeyId`、`secretAccessKey` 和 `sessionToken`，因此必须在挂载机制之外刷新凭证。挂载有效期和隔离要求见 [Daytona 中的临时凭证](/integrations/sandboxes/daytona#temporary-s3-credentials)。

### 按前缀限制权限 {/* #prefix-scoped-permissions */}

设置 `prefix` 后，初始化会调用 `ListObjectsV2`，传入规范化后带有末尾 `/` 的前缀和 `MaxKeys: 1`。凭证必须有权列出该前缀下的对象。未设置前缀时，初始化会调用 `HeadBucket`。这两种检查仅用于验证访问权限，不检查目录是否存在。

前缀仅限定文件系统寻址的对象键范围。要实现访问隔离，请通过存储 Provider 的策略将凭证的访问权限限制在该前缀下。将权限范围更广的上级凭证保留在后端。初始化带前缀的文件系统时，除了读写权限，还需要列举权限。

### Cloudflare R2 {/* #cloudflare-r2 */}

```typescript
import { S3Filesystem } from '@mastra/s3'

const filesystem = new S3Filesystem({
  bucket: 'my-r2-bucket',
  region: 'auto',
  endpoint: `https://${process.env.R2_ACCOUNT_ID}.r2.cloudflarestorage.com`,
  accessKeyId: process.env.R2_ACCESS_KEY_ID,
  secretAccessKey: process.env.R2_SECRET_ACCESS_KEY,
})
```

### Neon Object Storage {/* #neon-object-storage */}

```typescript
import { S3Filesystem } from '@mastra/s3'

const filesystem = new S3Filesystem({
  bucket: 'agent-files',
  region: process.env.AWS_REGION!,
  endpoint: process.env.AWS_ENDPOINT_URL_S3,
  accessKeyId: process.env.AWS_ACCESS_KEY_ID,
  secretAccessKey: process.env.AWS_SECRET_ACCESS_KEY,
})
```

`neon deploy` 和 `neon env pull` 会为当前 Neon 分支写入这些变量。请保留默认的路径式寻址。每个分支都有独立的端点和一份独立的文件副本。存储桶配置和分支用法见 [Neon Object Storage](/integrations/file-storage/neon)。

### MinIO {/* #minio */}

```typescript
import { S3Filesystem } from '@mastra/s3'

const filesystem = new S3Filesystem({
  bucket: 'my-bucket',
  region: 'us-east-1',
  endpoint: 'http://localhost:9000',
  accessKeyId: 'minioadmin',
  secretAccessKey: 'minioadmin',
})
```

### Tigris {/* #tigris */}

```typescript
import { S3Filesystem } from '@mastra/s3'

const filesystem = new S3Filesystem({
  bucket: 'my-bucket',
  region: 'auto',
  endpoint: 'https://t3.storage.dev',
  accessKeyId: process.env.TIGRIS_ACCESS_KEY_ID,
  secretAccessKey: process.env.TIGRIS_SECRET_ACCESS_KEY,
  forcePathStyle: false,
})
```

Tigris 使用虚拟托管式寻址，因此必须将 `forcePathStyle` 设为 `false`。提供自定义端点时，该参数默认为 `true`。请在 [Tigris 控制台](https://console.tigris.dev/)创建凭证。访问密钥以 `tid_` 开头，秘密访问密钥以 `tsec_` 开头。

## 方法 {/* #methods */}

S3Filesystem 实现了 [WorkspaceFilesystem 接口](/reference/workspace/filesystem)，提供以下所有标准文件系统方法。

* `readFile(path, options?)` - 读取文件内容
* `writeFile(path, content, options?)` - 将内容写入文件
* `appendFile(path, content)` - 在文件末尾追加内容
* `deleteFile(path, options?)` - 删除文件
* `copyFile(src, dest, options?)` - 复制文件
* `moveFile(src, dest, options?)` - 移动或重命名文件
* `mkdir(path, options?)` - 创建目录
* `rmdir(path, options?)` - 删除目录
* `readdir(path, options?)` - 列出目录内容
* `exists(path)` - 检查路径是否存在
* `stat(path)` - 获取文件或目录的元数据

### `init()` {/* #init */}

初始化文件系统，并验证凭证和存储桶的访问权限。

```typescript
await filesystem.init()
```

### `getInfo()` {/* #getinfo */}

返回此文件系统实例的元数据。

```typescript
const info = filesystem.getInfo()
// { id: '...', name: 'S3Filesystem', provider: 's3', status: 'ready' }
```

### `getMountConfig()` {/* #getmountconfig */}

返回挂载配置，供支持挂载此类文件系统的 Sandbox 使用。

```typescript
const config = filesystem.getMountConfig()
// { type: 's3', bucket: 'my-bucket', region: 'us-east-1', ... }
```

## 挂载到 E2B Sandbox {/* #mounting-in-e2b-sandboxes */}

将 S3Filesystem 挂载到 E2B Sandbox 后，即可像访问本地目录一样访问存储桶。

```typescript
import { Workspace } from '@mastra/core/workspace'
import { S3Filesystem } from '@mastra/s3'
import { E2BSandbox } from '@mastra/e2b'

const workspace = new Workspace({
  mounts: {
    '/data': new S3Filesystem({
      bucket: 'my-bucket',
      region: 'us-east-1',
      accessKeyId: process.env.AWS_ACCESS_KEY_ID,
      secretAccessKey: process.env.AWS_SECRET_ACCESS_KEY,
    }),
  },
  sandbox: new E2BSandbox({ id: 'dev-sandbox' }),
})
```

有关挂载的更多信息，请参阅 [E2BSandbox 参考文档](/integrations/sandboxes/e2b)。
