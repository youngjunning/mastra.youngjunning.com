# Google Drive

在 Mastra 中可以通过两种方式使用 Google Drive：

* **Agent 的 Tool**：Agent 可以通过 [Mastra Connect](/docs/mastra-platform/connect) 在整个 Google Drive 账号中查找、上传和整理文件。
* **[Workspace 文件系统](#workspace-filesystem)**：使用 `@mastra/google-drive` 包，将 Agent 的 Workspace 文件存储在同一个 Google Drive 文件夹中。

## Connect {/* #connect */}

开始前，请按 [Connect 设置步骤](/docs/mastra-platform/connect#get-started) 安装 `@mastra/connect` 并配置平台项目。

## Workspace 文件系统 {/* #workspace-filesystem */}

`GoogleDriveFilesystem` 将文件存储在同一个 Google Drive 文件夹中。每个目录都对应所配置的根目录下的一个 Drive 文件夹，路径遵循 POSIX 语义（例如 `/notes/todo.txt`）。有关接口的详细信息，请参阅 [WorkspaceFilesystem 接口](/reference/workspace/filesystem)。

### 安装 {/* #installation */}

```bash npm2yarn
npm install @mastra/google-drive
```

### 使用方法 {/* #usage */}

将 `GoogleDriveFilesystem` 添加到 Workspace，再将该 Workspace 分配给 Agent：

```typescript
import { Agent } from '@mastra/core/agent'
import { Workspace } from '@mastra/core/workspace'
import { GoogleDriveFilesystem } from '@mastra/google-drive'

const workspace = new Workspace({
  filesystem: new GoogleDriveFilesystem({
    folderId: process.env.GOOGLE_DRIVE_FOLDER_ID!,
    accessToken: process.env.GOOGLE_DRIVE_ACCESS_TOKEN!,
  }),
})

const agent = new Agent({
  id: 'drive-agent',
  name: 'Drive Agent',
  model: '__GATEWAY_OPENAI_MODEL_LUNA__',
  workspace,
})
```

#### 身份验证 {/* #authentication */}

选择以下一种身份验证方式：

* **`accessToken`**：预先获取的 OAuth 访问令牌。使用 `https://www.googleapis.com/auth/drive` 授权范围，令牌才能访问共享给对应身份的文件夹。
* **`getAccessToken`**：返回令牌的回调函数，适用于由外部机制刷新令牌的场景。
* **`serviceAccount`**：Google 服务账号。将目标文件夹共享给该服务账号的邮箱地址。

##### 服务账号 {/* #service-account */}

后端 Agent 推荐使用服务账号进行身份验证。这种方式无需用户授权，也无需自行处理令牌刷新。只需从服务账号的 JSON 密钥文件中获取**两个值**：`client_email` 和 `private_key`。

###### 设置服务账号 {/* #set-up-the-service-account */}

1. 打开 [Google Cloud 控制台](https://console.cloud.google.com/)，选择或创建项目。
2. 前往 **API 和服务 > 库**，搜索 **Google Drive API**，然后选择**启用**。
3. 前往 **API 和服务 > 凭据**，选择**创建凭据 > 服务账号**，然后填写表单。角色可以留空：Drive 权限通过共享文件夹授予，与 IAM 角色无关。
4. 打开刚创建的服务账号，进入**密钥**标签页，选择**添加密钥 > 创建新密钥 > JSON**。浏览器会下载一个 JSON 密钥文件。
5. 从 JSON 文件中复制 `client_email` 的值。共享 Drive 文件夹时，使用这个邮箱地址。

###### 将 Drive 文件夹共享给服务账号 {/* #share-the-drive-folder-with-the-service-account */}

服务账号拥有独立的 Google 身份。只有明确向它共享内容后，它才能看到相应的 Drive 内容。

1. 在 [Google Drive](https://drive.google.com/) 中打开目标文件夹。
2. 选择**共享**。
3. 粘贴服务账号的 `client_email` 邮箱地址。
4. 将角色设为**编辑者**（可读写）或**查看者**（仅可读取），然后选择**发送**。
5. 从 URL 中复制文件夹 ID，即 `https://drive.google.com/drive/folders/<folderId>` 中 `/folders/` 后的部分。

:::warning

服务账号无法在普通的“我的云端硬盘”文件夹中创建文件。服务账号没有个人 Drive 存储配额，因此它创建的文件必须归有存储配额的实体所有。如果只共享个人 Drive 文件夹，读取可以正常进行，但写入会因存储配额问题失败。

如需写入，请将文件夹放在**共享云端硬盘**（原团队云端硬盘）中，并将服务账号添加为该共享云端硬盘的成员。服务账号创建文件所需的存储配额由共享云端硬盘提供。

如果只从个人 Drive 文件夹读取数据，则不受此限制。

:::

###### 配置文件系统 {/* #configure-the-filesystem */}

从 JSON 文件中复制 `client_email` 和 `private_key`，将它们设为环境变量：

```bash filename=".env"
GOOGLE_DRIVE_FOLDER_ID=1AbCdEfGhIjKlMnOpQrStUvWxYz
GOOGLE_DRIVE_CLIENT_EMAIL=my-bot@my-project.iam.gserviceaccount.com
# Wrap the value in quotes — the key contains newlines that must be preserved.
GOOGLE_DRIVE_PRIVATE_KEY="-----BEGIN PRIVATE KEY-----\nMIIEvQIBADANBgkq...\n-----END PRIVATE KEY-----\n"
```

```typescript
import { GoogleDriveFilesystem } from '@mastra/google-drive'

const filesystem = new GoogleDriveFilesystem({
  folderId: process.env.GOOGLE_DRIVE_FOLDER_ID!,
  serviceAccount: {
    clientEmail: process.env.GOOGLE_DRIVE_CLIENT_EMAIL!,
    privateKey: process.env.GOOGLE_DRIVE_PRIVATE_KEY!,
  },
})
```

**无需**复制整个 JSON 文件，也无需传入 `project_id`、`client_id`、`private_key_id` 或 `token_uri` 等不会用到的字段。只有 `clientEmail` 和 `privateKey` 是必填项。`privateKeyId`、`scopes` 和 `subject` 均为可选项。`scopes` 默认为 `['https://www.googleapis.com/auth/drive']`，服务账号需要这一授权范围才能访问共享给它的文件夹。权限更窄的 `drive.file` 只允许访问应用自身创建的文件，因此访问共享给服务账号的文件夹时会返回 `404 Not Found`。

签名前，`GoogleDriveFilesystem` 会自动规范化 `privateKey` 字符串。它会移除两端的引号，包括 JSON 包装值中的转义引号，并将字面量 `\n` 转换为实际的换行符。它还会统一 `\r\n` 换行符并去掉末尾的逗号。无论 `.env` 加载器如何处理该值，密钥都可以正常使用。

###### 故障排除 {/* #troubleshoot */}

* **`404 File not found: <folderId>`**：服务账号无权访问该文件夹。确认文件夹已共享给 `client_email` 指定的确切地址，且文件夹 ID 与 URL 中的一致。
* **写入时出现 `storageQuotaExceeded`**：文件夹位于个人“我的云端硬盘”中。将文件夹移到共享云端硬盘，再将服务账号添加为成员。
* **`error:1E08010C:DECODER routines::unsupported`**：`privateKey` 的格式有误。确认该值包含完整的 PEM 块，并保留了换行（可以使用字面量 `\n`）。

#### 只读模式 {/* #read-only-mode */}

传入 `readOnly: true` 可阻止写入操作（`writeFile`、`appendFile`、`deleteFile`、`copyFile`、`moveFile`、`mkdir`、`rmdir`）。

```typescript
const filesystem = new GoogleDriveFilesystem({
  folderId,
  accessToken,
  readOnly: true,
})
```

### 方法 {/* #methods */}

GoogleDriveFilesystem 实现了 [WorkspaceFilesystem 接口](/reference/workspace/filesystem)，提供所有标准文件系统方法：

* `readFile(path, options?)`：下载文件内容
* `writeFile(path, content, options?)`：上传或覆盖文件
* `appendFile(path, content)`：读取文件，追加内容后重新上传
* `deleteFile(path, options?)`：删除文件
* `copyFile(src, dest, options?)`：调用 Drive 的 `files.copy` API 复制文件
* `moveFile(src, dest, options?)`：更改文件的父文件夹，将文件移到另一个文件夹
* `mkdir(path, options?)`：创建文件夹
* `rmdir(path, options?)`：删除文件夹
* `readdir(path, options?)`：列出文件夹内容（支持 `recursive` 递归列出和 `extension` 扩展名筛选）
* `stat(path)`：返回文件或文件夹在 Drive 中的元数据
* `exists(path)`：检查文件或文件夹是否存在

### 注意事项 {/* #notes */}

* Google Drive 允许同一文件夹中存在多个同名文件。`GoogleDriveFilesystem` 解析路径时会选取第一个匹配项，因此，如果依赖路径查找，请确保每个文件夹内的名称不重复。
* 未设置 `recursive`（默认情况）或将其设为 `true` 时，`writeFile` 会自动创建父文件夹。设为 `recursive: false` 时，父文件夹必须已存在。
* 写入时会检查 `WriteOptions` 中的 `expectedMtime`。如果已存储的 `modifiedTime` 与预期值不一致，写入会被拒绝并抛出 `StaleFileError`，以支持乐观并发控制。
* 此 Provider 只通过内置的 `fetch` 调用 Drive REST 端点（`https://www.googleapis.com/drive/v3` 和 `https://www.googleapis.com/upload/drive/v3`），无需额外依赖。
