# Vercel Files

你可以将文件存储到 [FilesSDK](https://files-sdk.dev) 支持的任何后端。FilesSDK 为 S3、Cloudflare R2、Google Cloud Storage、Azure Blob、Vercel Blob、MinIO、本地文件系统等提供统一的抽象层。有关接口的详细信息，请参阅 [WorkspaceFilesystem 接口](/reference/workspace/filesystem)。

如果希望通过同一个适配器用相同的代码对接多个存储后端，可以使用 `FilesSDKFilesystem`。只需更换底层驱动，Workspace 的设置可以保持原样。如果只使用一个后端，并且希望直接使用该后端的专用配置选项，建议选用对应的 Provider，例如 [`S3Filesystem`](/integrations/file-storage/amazon-s3) 或 [`GCSFilesystem`](/integrations/file-storage/google-cloud-storage)。

## 安装 {/* #installation */}

```bash npm2yarn
npm install @mastra/files-sdk files-sdk
```

`files-sdk` 是对等依赖项，需使用选定的适配器进行配置。

## 用法 {/* #usage */}

使用选定的适配器创建 FilesSDK 的 `Files` 实例，再将该实例传给 `FilesSDKFilesystem`。

```typescript
import { Agent } from '@mastra/core/agent'
import { Workspace } from '@mastra/core/workspace'
import { FilesSDKFilesystem } from '@mastra/files-sdk'
import { Files } from 'files-sdk'
import { s3 } from 'files-sdk/s3'

const files = new Files({
  adapter: s3({
    bucket: 'my-bucket',
    region: 'us-east-1',
  }),
})

const workspace = new Workspace({
  filesystem: new FilesSDKFilesystem({ files }),
})

const agent = new Agent({
  id: 'file-agent',
  name: 'file-agent',
  model: '__GATEWAY_ANTHROPIC_MODEL_OPUS__',
  workspace,
})
```

### 切换适配器 {/* #swapping-adapters */}

`FilesSDKFilesystem` 兼容所有 FilesSDK 适配器。替换创建驱动的工厂函数即可切换存储后端。

```typescript
import { Files } from 'files-sdk'
import { r2 } from 'files-sdk/r2'
import { gcs } from 'files-sdk/gcs'
import { azure } from 'files-sdk/azure'
import { neon } from 'files-sdk/neon'
import { fs } from 'files-sdk/fs'

// Cloudflare R2
const r2Files = new Files({ adapter: r2({ accountId, bucket, accessKeyId, secretAccessKey }) })

// Google Cloud Storage
const gcsFiles = new Files({ adapter: gcs({ bucket, projectId }) })

// Azure Blob
const azureFiles = new Files({ adapter: azure({ container, connectionString }) })

// Neon Object Storage (reads AWS_* variables from `neon env pull`)
const neonFiles = new Files({ adapter: neon({ bucket }) })

// Local filesystem (useful for tests and development)
const localFiles = new Files({ adapter: fs({ root: './workspace' }) })
```

完整的适配器列表和配置选项见 [FilesSDK 文档](https://files-sdk.dev)。

### 只读挂载 {/* #read-only-mounts */}

```typescript
const filesystem = new FilesSDKFilesystem({
  files,
  readOnly: true,
})
```

所有写入操作（`writeFile`、`appendFile`、`deleteFile`、`copyFile`、`moveFile`、`mkdir`、`rmdir`）都会抛出 `WorkspaceReadOnlyError`，读取操作仍可正常执行。

## 方法 {/* #methods */}

`FilesSDKFilesystem` 实现了 [WorkspaceFilesystem 接口](/reference/workspace/filesystem)，提供所有标准文件系统方法。

* `readFile(path, options?)` - 读取文件内容
* `writeFile(path, content, options?)` - 将内容写入文件
* `appendFile(path, content)` - 在文件末尾追加内容
* `deleteFile(path, options?)` - 删除文件
* `copyFile(src, dest, options?)` - 复制文件
* `moveFile(src, dest, options?)` - 移动或重命名文件
* `mkdir(path, options?)` - 创建目录（在对象存储中不执行任何操作）
* `rmdir(path, options?)` - 删除目录
* `readdir(path, options?)` - 列出目录内容
* `exists(path)` - 检查路径是否存在
* `stat(path)` - 获取文件或目录的元数据

### `init()` {/* #init */}

初始化文件系统，并验证所配置的适配器能否使用提供的凭据列出对象键。

```typescript
await filesystem.init()
```

### `getInfo()` {/* #getinfo */}

返回此文件系统实例的元数据。

```typescript
const info = filesystem.getInfo()
// { id: '...', name: 'FilesSDKFilesystem', provider: 'files-sdk', status: 'ready' }
```

### `files` {/* #files */}

底层 FilesSDK `Files` 实例可通过公开属性访问。需要直接调用适配器专属的 API 时，可以使用这个属性。

```typescript
const url = await filesystem.files.url('reports/q3.pdf')
```

## 对象存储语义 {/* #object-store-semantics */}

无论底层适配器是否采用层级结构（例如 `fs`），`FilesSDKFilesystem` 都会把配置的后端视为对象存储，使各适配器的行为保持一致。

* **`mkdir`** 不执行任何操作。只要存在以该目录路径为前缀的对象键，该目录就隐式存在。
* **`exists`** 仅在路径与某个文件的键完全匹配，或该路径作为前缀至少对应一个下级对象键时返回 `true`。采用层级结构的适配器中残留的空目录不计入。
* **`deleteFile`** 在对象键不存在时抛出 `FileNotFoundError`，传入 `{ force: true }` 时除外。
* **`deleteFile`** 在目标为目录时委托给 `rmdir({ recursive: true })`，行为与 [`S3Filesystem`](/integrations/file-storage/amazon-s3) 和 [`GCSFilesystem`](/integrations/file-storage/google-cloud-storage) 一致。
* **`moveFile`** 先执行 `copyFile`，再执行 `deleteFile`。这两个步骤并非 **原子操作**。如果复制成功后删除源文件失败，源文件和目标文件都会保留。
* **`appendFile`** 先读取内容，再修改并写回。并发向同一个对象键追加内容时，写入结果可能相互覆盖。对象存储本身就存在这种行为，FilesSDK 也遵循这一行为。
* **`readdir({ recursive: true })`** 会列出中间目录条目，例如在列出 `a/b` 的同时也列出 `a/b/c.txt`。
