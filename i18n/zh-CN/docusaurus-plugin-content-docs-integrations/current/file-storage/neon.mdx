# Neon Object Storage

[Neon Object Storage](https://neon.com/docs/storage/overview)是 Neon 项目内置的 S3 兼容存储服务。每个存储桶都归属一个分支。创建子分支时，父分支的文件会以写时复制的方式继承到子分支。Mastra 通过 [`S3Filesystem`](/integrations/file-storage/amazon-s3) 连接到这项服务，让 Agent 使用的 Workspace 文件与 [Neon Postgres](/integrations/databases/neon) 数据库中的行数据一起创建分支。接口详情请参见 [Workspace 文件系统接口](/reference/workspace/filesystem)。

## 开始之前 {/* #before-you-begin */}

你需要：

- 一个 [Neon](https://neon.com) 项目，位于支持对象存储的区域：`aws-us-east-1`、`aws-us-east-2`、`aws-eu-central-1` 或 `aws-ap-southeast-1`
- [Neon CLI](https://neon.com/docs/cli/install)

## 安装 {/* #installation */}

```bash npm2yarn
npm install @mastra/s3 @neon/config
```

## 创建存储桶 {/* #create-a-bucket */}

在项目根目录的 `neon.ts` 中声明存储桶：

```typescript title="neon.ts"
import { defineConfig } from '@neon/config/v1'

export default defineConfig({
  buckets: {
    'agent-files': {},
  },
})
```

存储桶默认为私有。设置 `access: 'public_read'` 可允许匿名读取。

将项目目录关联到 Neon 项目，然后在关联的分支上创建存储桶：

```bash
neon link
neon deploy
```

`neon deploy` 会创建存储桶，并将该分支的存储凭证写入 `.env`。如果 `.env` 不存在，则写入 `.env.local`。`mastra dev` 支持加载这两种文件。

如果要在不使用 `neon.ts` 的情况下创建存储桶，先运行 `neon bucket create agent-files`，再用以下命令手动拉取凭证：

```bash
neon env pull --service object-storage
```

## 环境变量 {/* #environment-variables */}

Neon 为对象存储设置以下四个环境变量：

| 变量 | 值 |
| - | - |
| `AWS_ACCESS_KEY_ID` | 分支凭证的访问密钥 ID |
| `AWS_SECRET_ACCESS_KEY` | 同一凭证的秘密访问密钥 |
| `AWS_ENDPOINT_URL_S3` | 该分支的 S3 端点 |
| `AWS_REGION` | 项目所在区域，例如 `us-east-2` |

凭证可用于其签发对象所在的分支及其子分支。在 [Neon Function](/integrations/deploy/neon) 中，Neon 会注入这些环境变量，因此无需 `.env` 文件。

## 用法 {/* #usage */}

将这些环境变量传给 `S3Filesystem`，再将 Workspace 分配给 Agent：

```typescript title="src/mastra/agents/file-agent.ts"
import { Agent } from '@mastra/core/agent'
import { Workspace } from '@mastra/core/workspace'
import { S3Filesystem } from '@mastra/s3'

const workspace = new Workspace({
  filesystem: new S3Filesystem({
    bucket: 'agent-files',
    region: process.env.AWS_REGION!,
    endpoint: process.env.AWS_ENDPOINT_URL_S3,
    accessKeyId: process.env.AWS_ACCESS_KEY_ID,
    secretAccessKey: process.env.AWS_SECRET_ACCESS_KEY,
  }),
})

export const fileAgent = new Agent({
  id: 'file-agent',
  name: 'file-agent',
  instructions: 'You manage files in the workspace.',
  model: '__GATEWAY_ANTHROPIC_MODEL_OPUS__',
  workspace,
})
```

务必设置 `endpoint`。Neon 只接受路径式请求，而 `S3Filesystem` 仅在设置 `endpoint` 时才会采用这种请求方式。如果省略该选项，AWS SDK 仍会读取 `AWS_ENDPOINT_URL_S3`，但会发送虚拟主机式请求（`agent-files.<endpoint-host>`），导致 TLS 验证失败。

`S3Filesystem` 能识别 Neon 端点，并将 `icon` 设为 `'neon'`、`displayName` 设为 `Neon Object Storage`。Studio 会在文件树中显示 Neon 挂载项。

通过 `prefix`，可以在同一个存储桶中为每个 Agent、用户或会话分别指定文件夹：

```typescript
const filesystem = new S3Filesystem({
  bucket: 'agent-files',
  prefix: `users/${userId}`,
  region: process.env.AWS_REGION,
  endpoint: process.env.AWS_ENDPOINT_URL_S3,
  accessKeyId: process.env.AWS_ACCESS_KEY_ID,
  secretAccessKey: process.env.AWS_SECRET_ACCESS_KEY,
})
```

前缀限制文件系统可寻址的对象键范围，不提供授权隔离。

## 分支 {/* #branches */}

每个分支都有自己的存储端点。新分支会继承创建时父分支中的所有存储桶和文件。子分支上的写入和删除不会影响父分支，父分支此后的写入也不会同步到子分支。

利用分支，可以在无需实际复制数据的情况下，为预览部署、测试运行或实验性 Agent 提供生产环境文件的完整副本：

```bash
neon checkout preview/new-tools --create
```

`neon checkout --create` 会创建分支，将该分支固定在 `.neon` 中，并将子分支的环境变量（包括存储端点）拉取到 `.env`。父分支的凭证也可用于子分支，但必须使用子分支的端点。删除该分支即可丢弃其中的文件。

## Skill Blob 存储 {/* #skill-blob-storage */}

`S3BlobStore` 存储由 [`MastraEditor`](/reference/editor/mastra-editor) 生成的、可按内容寻址的 Skill Blob。它接受相同的连接选项：

```typescript
import { S3BlobStore } from '@mastra/s3'

const blobStore = new S3BlobStore({
  bucket: 'agent-files',
  region: process.env.AWS_REGION!,
  endpoint: process.env.AWS_ENDPOINT_URL_S3,
  accessKeyId: process.env.AWS_ACCESS_KEY_ID,
  secretAccessKey: process.env.AWS_SECRET_ACCESS_KEY,
})
```

## FilesSDK 适配器 {/* #filessdk-adapter */}

如果使用 [`FilesSDKFilesystem`](/integrations/file-storage/vercel-files)，`neon` 适配器会读取相同的 `AWS_*` 环境变量。安装时一并安装该适配器加载的 AWS SDK 包：

```bash npm2yarn
npm install @mastra/files-sdk files-sdk @aws-sdk/client-s3 @aws-sdk/s3-presigned-post @aws-sdk/s3-request-presigner
```

```typescript
import { Workspace } from '@mastra/core/workspace'
import { FilesSDKFilesystem } from '@mastra/files-sdk'
import { Files } from 'files-sdk'
import { neon } from 'files-sdk/neon'

const workspace = new Workspace({
  filesystem: new FilesSDKFilesystem({
    files: new Files({ adapter: neon({ bucket: 'agent-files' }) }),
    icon: 'neon',
    displayName: 'Neon Object Storage',
  }),
})
```
