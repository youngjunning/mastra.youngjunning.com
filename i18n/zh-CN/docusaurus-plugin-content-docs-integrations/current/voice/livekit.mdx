# LiveKit

## 快速入门 {/* #quickstart */}

实时语音让用户可以在浏览器中或通过电话与 Mastra Agent 实时交谈。Mastra 使用 [LiveKit](https://livekit.io) 构建这项能力；LiveKit 是一个用于实时音视频的开源 WebRTC 平台。

[`@mastra/livekit`](#api-reference) 包将 Mastra Agent 接入 [LiveKit Agents 框架](https://docs.livekit.io/agents/)：LiveKit 负责音频处理流程，包括语音活动检测、流式语音转文字、语义轮次检测、插话打断和文字转语音。Mastra Agent 则使用自身的模型、Tool 和记忆生成每条回复。

需要低延迟、可打断的语音对话时，可以使用实时语音。如果要使用不依赖 LiveKit、由 Provider 提供的语音到语音功能，请参阅[语音到语音](/reference/voice/speech-to-speech)。

按照以下步骤，可以从空项目创建一个能够交谈的语音 Agent。语音会话需要配置两个部分：Mastra 服务器上用于发放访问令牌的 API 路由，以及运行音频处理流程、在每轮对话中调用 Agent 的独立 worker 进程。

<Steps>
  <StepItem>
    安装集成包，以及用于语音活动检测和轮次检测的 LiveKit 插件：

    ```bash npm2yarn
    npm install @mastra/livekit @livekit/agents @livekit/agents-plugin-silero @livekit/agents-plugin-livekit
    ```
  </StepItem>

  <StepItem>
    在 `.env` 文件中配置 LiveKit 凭据。你可以在 [LiveKit Cloud](https://cloud.livekit.io) 上创建免费项目，也可以使用 [`livekit-server --dev`](https://docs.livekit.io/home/self-hosting/local/) 运行本地服务器：

    ```bash title=".env"
    LIVEKIT_URL=wss://your-project.livekit.cloud
    LIVEKIT_API_KEY=your-api-key
    LIVEKIT_API_SECRET=your-api-secret
    ```
  </StepItem>

  <StepItem>
    在 Mastra 实例中添加语音 Agent，并开放连接路由。`liveKitConnectionRoute()` 辅助函数会添加 `POST /voice/livekit/connection-details` 端点，用于签发 LiveKit 令牌并将 Agent 分派到房间：

    ```typescript title="src/mastra/index.ts"
    import { Mastra } from '@mastra/core/mastra'
    import { Agent } from '@mastra/core/agent'
    import { liveKitConnectionRoute } from '@mastra/livekit'

    const supportAgent = new Agent({
      id: 'support',
      name: 'Support',
      instructions: 'You are a friendly phone support agent. Keep replies short and conversational.',
      model: '__GATEWAY_OPENAI_MODEL_LUNA__',
    })

    export const mastra = new Mastra({
      agents: { support: supportAgent },
      server: {
        apiRoutes: [liveKitConnectionRoute({ agentName: 'mastra-voice' })],
      },
    })
    ```
  </StepItem>

  <StepItem>
    创建 worker。它作为独立进程运行，接入 LiveKit 会话，并在每轮对话中调用 Agent。worker API 位于 `@mastra/livekit/worker` 入口，因此 Mastra 服务器无需加载 LiveKit Agents 运行时。本例使用 LiveKit Inference 模型字符串实现语音转文字和文字转语音，无需安装 Provider 插件：

    ```typescript title="src/mastra/voice-worker.ts"
    import { fileURLToPath } from 'node:url'
    import { createLiveKitWorker, runLiveKitWorker } from '@mastra/livekit/worker'
    import { mastra } from './index'

    export default createLiveKitWorker({
      mastra,
      agent: 'support',
      stt: 'deepgram/nova-3',
      tts: 'cartesia/sonic-3',
      turnDetection: 'multilingual',
      greeting: 'Hi! How can I help you today?',
    })

    if (process.argv[1] === fileURLToPath(import.meta.url)) {
      runLiveKitWorker({ entry: import.meta.url, agentName: 'mastra-voice' })
    }
    ```

    `agent` 选项指定由哪个 Mastra Agent 应答会话。可以像示例中一样传入固定的键，也可以省略它，改用分派元数据中的 `agentId`，让同一个 worker 服务 Mastra 实例中的所有 Agent。
  </StepItem>

  <StepItem>
    下载轮次检测和语音活动检测模型，此步骤只需执行一次。然后分别在两个终端中运行 worker 和 Mastra 服务器：

    ```bash
    npx livekit-agents download-files
    npx tsx src/mastra/voice-worker.ts dev
    ```

    ```bash npm2yarn
    npm run dev
    ```

    worker 会向 LiveKit 服务器注册并等待会话；`mastra dev` 则提供连接路由。
  </StepItem>

  </StepItem>

### 轮次检测与打断 {/* #turn-detection-and-interruptions */}

LiveKit 判断用户何时说完，以及 Agent 何时被打断。默认设置通常适用；如需调整，请配置 `turnHandling`：

```typescript title="src/mastra/voice-worker.ts"
export default createLiveKitWorker({
  mastra,
  agent: 'support',
  stt: 'deepgram/nova-3',
  tts: 'cartesia/sonic-3',
  turnDetection: 'multilingual',
  turnHandling: {
    endpointing: { mode: 'dynamic', minDelay: 300, maxDelay: 3000 },
    interruption: { minDuration: 500, resumeFalseInterruption: true },
  },
})
```

* `turnDetection: 'multilingual'`：在本地 CPU 上运行 LiveKit 的语义轮次结束检测模型。它读取实时转录文本，避免在用户尚未说完时截断发言。如果要根据静音判断发言结束，可改用 `'vad'` 或 `'stt'`。
* `endpointing`：限定用户停止说话后 Agent 的等待时长。
* `interruption`：控制插话打断。用户在 Agent 说话时插话，LiveKit 会停止播放并取消正在进行的 Mastra 流，令牌生成也会随之停止。
* `preemptiveGeneration`：在用户快要说完时提前启动 Mastra Agent 的回复生成，以缩短首个令牌的等待时间。worker 默认禁用此功能：每次提前生成都会使用临时转录文本运行 Mastra Agent；即使 LiveKit 随后丢弃该次运行，部分用户消息和一段从未说出口的回复也已经写入线程。如果延迟比线程历史的准确性更重要，可以通过 `preemptiveGeneration: { enabled: true }` 重新启用；如果两者都需要，可以让每轮运行以只读方式访问记忆。参阅[结合记忆使用提前生成](#preemptive-generation-with-memory)。

所有配置选项请参阅 [LiveKit 轮次检测文档](https://docs.livekit.io/agents/logic/turns/)。

要禁用语音活动检测，请在 `createLiveKitWorker()` 中设置 `vad: false`。worker 会向 LiveKit 传入 `null`；如果省略 `vad`，LiveKit 则会启用自带的检测器。禁用 VAD 时，请选择不依赖 VAD 的轮次检测模式，例如 `'manual'`。`sessionOptions` 中的值会覆盖 worker 生成的选项，包括 `vad`。

### 为每通电话配置语音和转录 {/* #per-call-voices-and-transcription */}

顶层的 `stt` 和 `tts` 选项适用于每通电话。如果要按通话选择配置，例如为不同租户指定不同的音色或语言，请改用 `configuration.stt` 和 `configuration.tts` 解析函数。每个解析函数在每通电话中运行一次，可获取分派元数据、请求上下文、房间名称和任务上下文，并返回对应顶层选项接受的值：插件实例或 Inference 模型字符串。返回 `undefined` 则回退到顶层选项。

以下示例根据分派元数据中的 `tenant`，为每个租户选择专属的文字转语音音色：

```typescript title="src/mastra/voice-worker.ts"
import * as cartesia from '@livekit/agents-plugin-cartesia'

// One voice id per tenant, resolved from the dispatch metadata on each call.
const tenantVoices: Record<string, string> = {
  meridian: 'your-cartesia-voice-id-1',
  coastal: 'your-cartesia-voice-id-2',
}
// The resolver runs during call setup, so cache plugin instances across calls.
const ttsByVoice = new Map<string, cartesia.TTS>()

export default createLiveKitWorker({
  mastra,
  agent: 'support',
  stt: 'deepgram/nova-3',
  tts: 'cartesia/sonic-3',
  configuration: {
    tts: ({ requestContext }) => {
      const voice = tenantVoices[requestContext?.tenant as string]
      if (!voice) return undefined // fall back to the top-level `tts`
      let tts = ttsByVoice.get(voice)
      if (!tts) {
        tts = new cartesia.TTS({ voice })
        ttsByVoice.set(voice, tts)
      }
      return tts
    },
  },
})
```

`configuration.stt` 也可以按通话配置转录，例如让不同租户使用不同的转录模型或语言。问候语同样支持按通话配置：`configuration.greeting.text` 接受使用相同通话上下文的解析函数，因此同一个 worker 可以用各租户自己的措辞开场。

### 为每通电话配置轮次检测 {/* #per-call-turn-detection */}

LiveKit 的 `TurnDetector` 类在构造时会读取任务的推理执行器，因此只能在 LiveKit 任务内部创建，不能在定义 worker 选项的模块顶层创建。要使用这类检测器，请设置 `configuration.turnDetection` 解析函数。它在每通电话中运行一次，获得与 `configuration.stt` 相同的通话上下文，并返回顶层 `turnDetection` 选项接受的值。返回 `undefined` 则回退到顶层选项。

```typescript title="src/mastra/voice-worker.ts"
import { turnDetector } from '@livekit/agents-plugin-livekit'

export default createLiveKitWorker({
  mastra,
  agent: 'support',
  stt: 'deepgram/nova-3',
  tts: 'cartesia/sonic-3',
  turnDetection: 'multilingual',
  configuration: {
    // Constructed inside the job, where the inference executor is available.
    turnDetection: () => new turnDetector.MultilingualModel(0.2),
  },
})
```

语义模型的推理运行器必须在 Agent 服务器启动前注册。因此，设置该解析函数后，worker 会预先导入 `@livekit/agents-plugin-livekit`。将顶层 `turnDetection` 设为 `'multilingual'` 或 `'english'`，可以只预注册对应模型；否则两种模型都会保持可用。

### 记忆与线程 {/* #memory-and-threads */}

如果最终选中的 Mastra Agent 配置了记忆，每通电话都会对应一个记忆线程：

* `thread` 优先使用分派元数据中的 `threadId`，没有时使用房间名称。
* `resource` 优先使用分派元数据中的 `resourceId`，没有时使用线程标识。请在此传入最终用户的 ID，以便将通话归到正确的用户下。Mastra Studio 会传入 Agent ID，这与其侧边栏列出线程的方式一致。
* 如果线程尚不存在，worker 会创建标题为“Voice call”、元数据为 `{ source: 'livekit' }` 的线程。说出的问候语会保存为第一条 assistant 消息，使线程呈现完整的通话转录内容；可通过 `persistGreeting: false` 禁用保存。

每轮只发送新的用户输入；Mastra Memory 会提供对话历史、语义检索结果和工作记忆。在连接请求体中传入 `threadId`，即可将会话绑定到已有线程，适合通过语音继续之前的文字对话。在 Studio 中，从已打开的聊天发起通话时，通话会绑定到该线程，每次对话后转录内容都会写入聊天记录。

用户打断 Agent 时，正在进行的生成会中止，该轮内容此时不会持久化。LiveKit 会在转录中保留用户实际听到的部分；下一轮中，worker 会重新发送这段已听到的内容，使线程记录与通话一致。如果用户打断后立即挂断，最后这段内容就不会被记录。详情及补录方法参阅[被打断的轮次](#interrupted-turns)。

#### 结合记忆使用提前生成 {/* #preemptive-generation-with-memory */}

LiveKit 的提前生成功能会根据临时转录文本调用 Mastra Agent，并在转录文本发生变化时丢弃相应的运行。插件无法区分试探性运行与正式轮次，因此设置 `memory` 后，每次运行都会持久化，被丢弃的运行也不例外。要在启用提前生成的同时保持线程记录准确，请在记忆映射中传入 `options: { readOnly: true }`。Agent 仍能读取线程中的历史、语义检索结果和工作记忆，但不会写入内容，因此试探性运行不会留下记录。此时，你需要自行保存已确认的轮次：监听 LiveKit 的 `ConversationItemAdded` 事件，该事件只会针对会话已确认的条目触发。消息沿用 LiveKit 的 ID，因此重试保存也不会产生重复记录。

```typescript title="src/mastra/voice-worker.ts"
import { voice } from '@livekit/agents'
import { createLiveKitWorker } from '@mastra/livekit/worker'
import { mastra } from './index'

export default createLiveKitWorker({
  mastra,
  agent: 'support',
  memory: ({ metadata, roomName }) => ({
    thread: metadata.threadId ?? roomName,
    resource: metadata.resourceId ?? roomName,
    options: { readOnly: true },
  }),
  turnHandling: { preemptiveGeneration: { enabled: true } },
  onSessionStart: async ({ session, ctx, agent }) => {
    const mapping = agent.memory
    const memory = await mastra.getAgent('support').getMemory()
    if (!mapping || !memory) return

    let shuttingDown = false
    const maxRetries = 5
    const retryTimers = new Set<ReturnType<typeof setTimeout>>()
    ctx.addShutdownCallback(async () => {
      shuttingDown = true
      for (const timer of retryTimers) clearTimeout(timer)
      retryTimers.clear()
    })

    session.on(voice.AgentSessionEventTypes.ConversationItemAdded, ({ item }) => {
      if (item.type !== 'message' || (item.role !== 'user' && item.role !== 'assistant')) return

      const persist = async (attempt = 0): Promise<void> => {
        try {
          await memory.saveMessages({
            messages: [
              {
                id: item.id,
                threadId: mapping.thread,
                resourceId: mapping.resource ?? mapping.thread,
                role: item.role,
                content: {
                  format: 2,
                  parts: [{ type: 'text', text: item.textContent ?? '' }],
                },
                type: 'text',
                createdAt: new Date(),
              },
            ],
          })
        } catch (error) {
          if (shuttingDown) return
          if (attempt >= maxRetries) {
            console.error(`Failed to persist committed voice item ${item.id}; giving up`, error)
            return
          }
          console.error(`Failed to persist committed voice item ${item.id}; retrying`, error)
          const delay = Math.min(1_000 * 2 ** attempt, 30_000)
          const timer = setTimeout(() => {
            retryTimers.delete(timer)
            void persist(attempt + 1)
          }, delay)
          retryTimers.add(timer)
        }
      }

      void persist()
    })
  },
})
```

`MastraVoiceAgent` 和 `MastraLLM` 也支持相同的 `options` 字段；通过远程传输时，该字段会作为请求体中的 `memory.options` 转发。

### Tool 运行期间播放语音 {/* #speak-while-tools-run */}

Tool 运行较慢时，语音对话不宜一直沉默。使用 `toolFeedback`，可以在 Mastra Agent 开始调用 Tool 时说一句简短的话：

```typescript title="src/mastra/voice-worker.ts"
export default createLiveKitWorker({
  mastra,
  agent: 'support',
  stt: 'deepgram/nova-3',
  tts: 'cartesia/sonic-3',
  toolFeedback: ({ toolName }) =>
    toolName === 'searchOrders' ? 'Let me look that up.' : undefined,
})
```

这句话会作为回复的一部分播放，并记录在转录文本中。

### 使用 Workflow 生成回复 {/* #generate-replies-with-a-workflow */}

默认情况下，worker 使用 Mastra Agent 生成每条回复。如果每轮需要执行多步逻辑，例如识别意图、选择处理路径、依次调用 Tool，再组织回复，可以改用 Mastra [Workflow](/docs/workflows/overview) 生成回复。此时设置 `workflow`，取代 `agent`。

LiveKit 仍负责音频处理流程，每轮调用 Mastra 一次，因此 Workflow 每轮都会运行至完成。Workflow 无法暂停或恢复，轮次之间也不会自动传递对话状态。通过 `workflowInput` 传入转录内容，让 Workflow 保持无状态：

```typescript title="src/mastra/voice-worker.ts"
import { createLiveKitWorker, chatContextToMessages } from '@mastra/livekit/worker'
import { mastra } from './index'

export default createLiveKitWorker({
  mastra,
  workflow: 'phoneConversation',
  workflowInput: ({ chatCtx }) => ({ history: chatContextToMessages(chatCtx) }),
  replyStep: 'generateResponse',
  stt: 'deepgram/nova-3',
  tts: 'cartesia/sonic-3',
  turnDetection: 'multilingual',
})
```

Workflow 流式输出的是结构化步骤事件，而非文本。要在文本生成过程中同步播放语音，回复步骤需要将 Agent 的文本流传给该步骤的 `writer`：

```typescript title="src/mastra/workflows/phone-conversation.ts"
import { createStep } from '@mastra/core/workflows'

const generateResponse = createStep({
  id: 'generateResponse',
  // input and output schemas omitted
  execute: async ({ inputData, mastra, writer, abortSignal }) => {
    const stream = await mastra.getAgent('voice').stream(inputData.history, { abortSignal })
    await stream.textStream.pipeTo(writer)
    return { assistantMessage: await stream.text }
  },
})
```

* `replyStep`：只播放指定步骤的输出。省略时，会播放所有写入各自 `writer` 的步骤输出。
* `resultText`：当没有步骤流式输出文本时，从最终运行结果生成回复的后备选项。通过 `writer` 流式输出可以缩短首个令牌的等待时间，因此优先使用它。
* `abortSignal`：将步骤的 `abortSignal` 传入 `agent.stream()`，以便用户插话时立即停止生成。用户打断后，worker 会取消该次运行。
* `generate`：如需完全控制回复生成，可以改为传入 `generate` 函数。它可以是任何将一轮对话转换为文本流的回复生成函数。

使用 Workflow 时，worker 不会像调用 Agent 的 `stream()` 那样自动持久化对话轮次。请在 Workflow 内保存对话历史，或以 LiveKit 转录内容为准，并在每轮将其传入。

### 将 Mastra 用作 LLM 组件 {/* #use-mastra-as-the-llm-component */}

`createLiveKitWorker()` 会代你管理 LiveKit 会话。如果要自行管理会话，请使用 [`MastraLLM`](#mastrallm)：这是一个标准的 LiveKit LLM 插件，可以将 Mastra Agent 放入你创建的 `voice.AgentSession` 的 `llm` 插槽。Mastra 应用、Agent 循环、Tool、记忆和可观测性功能都运行在 Mastra 服务器上，worker 通过 HTTP 访问它。worker 进程无需加载 Mastra 应用，也无需数据库或模型 Provider 的密钥。

```typescript title="src/mastra/voice-worker-plugin.ts"
import { fileURLToPath } from 'node:url'
import { defineAgent, voice } from '@livekit/agents'
import * as silero from '@livekit/agents-plugin-silero'
import { MastraLLM } from '@mastra/livekit/plugin'
import { runLiveKitWorker } from '@mastra/livekit/worker'

export default defineAgent({
  entry: async ctx => {
    await ctx.connect()

    const session = new voice.AgentSession({
      llm: new MastraLLM({
        remote: { baseUrl: process.env.MASTRA_URL!, agentId: 'support' },
        memory: { thread: ctx.room.name!, resource: 'user-7' },
      }),
      stt: 'deepgram/nova-3',
      tts: 'cartesia/sonic-3',
      vad: await silero.VAD.load(),
      // Required with `memory` unless memory.options.readOnly is set: LiveKit enables
      // preemptive generation by default.
      turnHandling: { preemptiveGeneration: { enabled: false } },
    })

    await session.start({
      // These instructions never reach the Mastra agent; its own instructions apply.
      agent: new voice.Agent({ instructions: 'Replies come from the Mastra agent.' }),
      room: ctx.room,
    })

    session.say('Hi! How can I help you today?')
  },
})

if (process.argv[1] === fileURLToPath(import.meta.url)) {
  runLiveKitWorker({ entry: import.meta.url, agentName: 'mastra-voice' })
}
```

两种方式使用相同的底层回复流程；根据会话由谁管理来选择：

| | `createLiveKitWorker()` | `MastraLLM` |
| - | - | - |
| 会话管理 | Worker 辅助函数创建并管理 `AgentSession` | 由你的代码创建会话，可自行配置所有 LiveKit 选项和钩子 |
| Mastra 应用运行位置 | Worker 进程中 | Mastra 服务器上，通过 HTTP 访问（或通过 `agent` 在进程内访问） |
| Worker 进程所需资源 | Mastra 应用、存储和模型 Provider 密钥 | LiveKit SDK，以及访问服务器的网络连接 |
| 内置功能 | 欢迎语、同意机制、Agent 主动挂断、对话线程初始化、可观测数据汇总 | 使用[会话辅助函数](#runendcall)实现所需功能 |
| 适用场景 | 快速构建可用的语音 Agent；Studio 语音模式 | 已有 LiveKit 应用，或需要全面控制会话 |

Tool 仍由 Mastra Agent 在服务器上执行。传给会话的 LiveKit 端 Tool 会被忽略。Worker 可通过 `toolFeedback`（语音过渡提示）、`onToolCall`（每次 Tool 调用开始时触发）和 `onTurnComplete`（每次回复结束后触发，包含文本、Tool 调用和 token 用量）获取 Tool 活动。要让 Agent 主动挂断，将 `onToolCall` 与 [`runEndCall()`](#runendcall) 配合使用即可。

:::warning
不要同时使用 `memory` 选项和 LiveKit 的 `preemptiveGeneration`；在自行创建的会话中，LiveKit 默认启用后者。预生成的回合在被 LiveKit 丢弃前，会把不完整的用户消息和一条从未播出的部分回复写入对话线程。你可以设置 `turnHandling: { preemptiveGeneration: { enabled: false } }`；也可以不使用 `memory`，每轮传入完整转录；或者设置 `memory.options.readOnly`，自行保存已确认的回合。详见[预生成与 Memory](#preemptive-generation-with-memory)。
:::

`MastraLLM` 也接受进程内的 Mastra `agent` 实例，让你自行管理会话而无需单独部署服务器；还可以传入自定义 `generate` 函数。远程传输能力也可以通过 [`createRemoteAgentReplyGenerator()`](#createremoteagentreplygenerator) 单独使用，并可接入 `createLiveKitWorker` 的 `generate` 选项，让内置功能齐全的 Worker 连接远程服务器。

### 服务器发起的会话 {/* #server-initiated-sessions */}

在自己的代码中调用 `dispatchVoiceSession()`，将语音 Agent 加入房间。例如，让 Agent 加入已有房间，或发起外呼 [SIP 通话](https://docs.livekit.io/sip/)：

```typescript
import { dispatchVoiceSession } from '@mastra/livekit'

await dispatchVoiceSession({
  roomName: 'support-call-42',
  agentName: 'mastra-voice',
  metadata: { agentId: 'support', threadId: 'thread-42', resourceId: 'user-7' },
})
```

### 通话录音 {/* #record-calls */}

向 `dispatchVoiceSession()` 或 `liveKitConnectionRoute()` 传入 `recording`，即可创建启用 [LiveKit 自动 egress](https://docs.livekit.io/transport/media/ingress-egress/egress/autoegress/) 的房间。Mastra 会先按录音配置创建房间，再将语音 Agent 分派进去。不传 `recording` 时，原有行为和返回值不变。

录音需要 LiveKit Cloud 或自托管的 [egress 服务](https://docs.livekit.io/transport/self-hosting/egress/)，以及输出存储位置。下面的示例将来电者和 Agent 的音频混合录制为一个 OGG 文件，存入 S3 存储桶。在服务器上配置 LiveKit 凭据的同时，设置 `RECORDINGS_S3_BUCKET`、`RECORDINGS_S3_REGION`、`RECORDINGS_S3_ACCESS_KEY` 和 `RECORDINGS_S3_SECRET`。

安装服务器 SDK 以使用其输出格式枚举：

```bash npm2yarn
npm install livekit-server-sdk
```

在仅服务器模块中定义录制设置：

```typescript title="src/mastra/recording.ts"
import type { LiveKitRecordingOptions } from '@mastra/livekit'
import { EncodedFileType } from 'livekit-server-sdk'

export const recording: LiveKitRecordingOptions = {
  room: {
    audioOnly: true,
    fileOutputs: [
      {
        fileType: EncodedFileType.OGG,
        filepath: 'calls/{room_name}.ogg',
        output: {
          case: 's3',
          value: {
            bucket: process.env.RECORDINGS_S3_BUCKET!,
            region: process.env.RECORDINGS_S3_REGION!,
            accessKey: process.env.RECORDINGS_S3_ACCESS_KEY!,
            secret: process.env.RECORDINGS_S3_SECRET!,
          },
        },
      },
    ],
  },
}
```

`LiveKitRecordingOptions` 接受用于创建 LiveKit `RoomEgress` 的配置，可以是普通对象，也可以是 SDK 实例。设置 `room.audioOnly: true` 可录制混合音频；使用 `tracks` 或 `participant` 可分别录制。Mastra 会将这些配置传给 LiveKit，不会替你选择文件格式或存储 Provider。其他输出位置参见 [LiveKit 输出选项](https://docs.livekit.io/transport/media/ingress-egress/egress/outputs/)。

对于出站电话，请在添加电话参与者之前配置录音：

```typescript title="src/start-call.ts"
import { randomUUID } from 'node:crypto'
import { dispatchVoiceSession } from '@mastra/livekit'
import { recording } from './mastra/recording'

const roomName = `support-call-${randomUUID()}`

await dispatchVoiceSession({
  roomName,
  metadata: { agentId: 'support', resourceId: 'caller-7' },
  recording,
})

// Add the phone participant to roomName through your existing LiveKit SIP code.
```

每次录音都使用新的房间名称，并等待分派完成后再拨号。如果房间已存在，`dispatchVoiceSession()` 会抛出 `LiveKitRecordingRoomConflictError`。可从 `@mastra/livekit` 导入该错误以处理冲突。检查房间是否存在与创建房间是两个独立请求，因此应用还必须防止其他进程并发创建同名房间。此选项无法在已有房间中开始录音，也无法补录此前的音频。

对于浏览器会话，将相同的设置传递到连接路由：

```typescript title="src/mastra/index.ts"
import { Mastra } from '@mastra/core/mastra'
import { liveKitConnectionRoute } from '@mastra/livekit'
import { recording } from './recording'

export const mastra = new Mastra({
  server: {
    apiRoutes: [liveKitConnectionRoute({ recording })],
  },
})
```

启用录音后，请求连接信息时，路由会在浏览器加入前创建房间并分派 Agent。响应仍为 `{ serverUrl, roomName, participantName, participantToken }`。录音配置和存储凭据保留在服务器上，不会写入入会令牌或 Agent 元数据。

该路由也接受同步或异步的 `recording` 回调。回调收到 `{ body, context, roomName }`，其中包含已确定的房间名称，服务器因此可以按会话选择录音配置。返回 `undefined` 可跳过该次请求的录音。路由不会直接从请求体读取录音配置。

如果录音房间已存在，路由会在分派 Agent 或签发令牌前返回 HTTP 409。其他创建房间或分派错误也会使操作失败；路由不会在失败时签发令牌。如果房间创建后分派失败，该房间仍会留在 LiveKit 中。配置成功也不能保证录音完成或上传成功。向用户提供录音前，应通过 LiveKit 的 [egress 事件](https://docs.livekit.io/intro/basics/rooms-participants-tracks/webhooks-events/#webhook-events)确认完成状态并获取文件信息。验证配置时，发起一次测试通话、结束房间，然后播放存储桶 `calls/` 下生成的文件，确认其中包含双方音频。

#### 录音生命周期与同意机制 {/* #recording-lifecycle-and-consent */}

启用 `recording` 后，录音会在创建房间时开始，早于浏览器连接或电话参与者加入。即使连接请求随后被放弃，也可能启动 Agent 并消耗录音与存储资源。向用户开放连接路由前，应配置身份验证和应用层限制。

`createConsentTool()` 和 `configuration.consentPolicy` 不控制 LiveKit egress，也不会延迟、暂停或停止自动录音。如果应用要求在通话中取得同意后才能采集音频，应先取得同意，再通过 LiveKit 的显式 egress API 在已有房间中开始录音。仅播放一段语音欢迎词无法控制录音开始。

录音遵循 LiveKit 房间的生命周期。仅断开 Agent 不一定会结束房间或完成文件。收到 egress 成功完成状态和文件结果后，才能将录音标记为就绪。配置失败和废弃房间的清理应由应用负责。

音频文件保存在配置的输出存储中，与 Mastra Memory、转录文本和 Trace 分开。删除 Mastra 对话线程不会删除录音。应用需要管理终端用户的存储访问权限、保留期限和下载链接。即使按会话选择录音配置，也应将存储凭据保留在服务器配置中。

### 在 Studio 中查看录音 {/* #review-recordings-in-studio */}

注册 `liveKitRecordingRoute()` 后，Studio 中语音通话的 Trace 面板会显示 **Review Audio** 按钮，点击可打开该通话的音频播放器。录音和 Trace 存储都必须已配置：路由会读取已保存的 `voice call` span，并将其 `roomName` 传给服务器端解析器。浏览器只需提供 Trace ID。

解析器返回 `{ url, expiresAt? }`；没有可用文件时返回 `undefined`。私有存储应使用短期有效的签名 URL。路由不会将播放 URL 保存到 Trace 中；每次打开查看界面时，Studio 都会重新请求 URL。文件缺失或播放出错时，界面会提供 **Refresh recording**，可在上传完成或链接过期后重试。

对于上面的 S3 配置，录音和播放应使用相同的 `calls/{room_name}.ogg` 对象键。即使房间已经结束，房间名称也必须在不同通话之间保持唯一。在应用中安装 AWS SDK：

```bash npm2yarn
npm install @aws-sdk/client-s3 @aws-sdk/s3-request-presigner
```

```typescript title="src/mastra/recording-playback.ts"
import {
  GetObjectCommand,
  HeadObjectCommand,
  S3Client,
  S3ServiceException,
} from '@aws-sdk/client-s3'
import { getSignedUrl } from '@aws-sdk/s3-request-presigner'
import { liveKitRecordingRoute } from '@mastra/livekit'
import { authorizeRecording } from './recording-access'

const s3 = new S3Client({
  region: process.env.RECORDINGS_S3_REGION!,
  credentials: {
    accessKeyId: process.env.RECORDINGS_S3_ACCESS_KEY!,
    secretAccessKey: process.env.RECORDINGS_S3_SECRET!,
  },
})

export const recordingReviewRoute = liveKitRecordingRoute({
  authorize: authorizeRecording,
  resolveRecording: async ({ roomName }) => {
    const object = {
      Bucket: process.env.RECORDINGS_S3_BUCKET!,
      Key: `calls/${roomName}.ogg`,
    }
    try {
      await s3.send(new HeadObjectCommand(object))
    } catch (error) {
      if (error instanceof S3ServiceException && error.$metadata.httpStatusCode === 404)
        return undefined
      throw error
    }
    const expiresIn = 15 * 60
    return {
      url: await getSignedUrl(
        s3,
        new GetObjectCommand({ ...object, ResponseContentType: 'audio/ogg' }),
        { expiresIn },
      ),
      expiresAt: new Date(Date.now() + expiresIn * 1000).toISOString(),
    }
  },
})
```

将 `recordingReviewRoute` 与 `liveKitConnectionRoute({ recording })` 一起加入 `server.apiRoutes`。保留默认路径 `GET /voice/livekit/recordings/:traceId`，以便 Studio 发现该路由。只要 Worker 已保存通话 Trace，且解析器能找到对应文件，就可以查看连接路由创建的录音，也可以查看服务器主动分派会话创建的录音。

录音查看路由默认要求身份验证，还必须显式提供 `authorize({ traceId, context })` 回调。在应用中实现 `authorizeRecording`，根据可信的归属或租户记录，检查已认证用户能否访问请求的 Trace。仅在允许访问时返回 `true`。用户通过身份验证，并不代表其拥有该录音的访问权。

即使 `requiresAuth` 为 `false`，缺少授权回调也会导致路由注册失败。访问被拒绝时，路由会在读取 Trace 存储或生成播放 URL 前返回 `403`。授权策略出错也会阻止解析。只有授权成功后，解析器才会收到已保存的 `span` 和请求 `context`。

:::warning

只在本地演示中使用 `requiresAuth: false`。它不会绕过必需的录音授权回调。如果演示用的授权策略允许访问所有录音，应明确将其限制在本地开发环境，并在部署前替换。

:::

仅有录音上传权限并不意味着可以播放。用于签名的凭据需要对录音对象具备 `s3:GetObject` 权限，`HEAD` 检查也需要该权限。若希望对象不存在时 S3 返回 `404` 而非 `403`，还需要 `s3:ListBucket`。应用可以使用独立的只读凭据提供播放能力。浏览器收到的临时 URL 可用于访问该文件，应将其视为敏感信息。参见 [S3 对象权限](https://docs.aws.amazon.com/AmazonS3/latest/API/API_HeadObject.html)和[预签名 URL](https://docs.aws.amazon.com/AmazonS3/latest/userguide/using-presigned-url.html)。

`liveKitRecordingRoute()` 不依赖特定存储。你可以从其他 Provider 解析 URL，也可以查询由 LiveKit 录音完成事件填充的录音索引。该路由不依赖 LiveKit 保留历史 egress 作业。如果使用带时间戳的文件名或更换存储桶，应在应用中保存房间与对象的映射，并通过映射查找文件，而非拼接对象键。

### 可观测性 {/* #observability */}

为 Mastra 实例配置[可观测性](/docs/observability/overview)后，Worker 会追踪每次通话。每个会话会创建一个 `voice call` span，并在其中记录：

- 每轮 Mastra Agent 的运行，包括模型生成、Tool 调用和 Memory 操作，记录方式与文本聊天相同。
- 各项 LiveKit 音频管道指标的子 span：语音转文本、文本转语音、话语结束检测（回合检测）、语音活动检测，以及模型首个 token 的生成时间。这些 span 包含文本 Trace 无法呈现的延迟和音频测量数据。
- 会话结束时写入 span 的各模型用量汇总，包括整通电话的 token、字符和音频总量。

Worker 是独立进程，因此存储后端必须支持服务器和 Worker 并发写入。基于 SQLite 的 [LibSQL](/integrations/databases/libsql) 可以使用，只允许单个写入者的存储则不行。Trace、Memory 和对话线程可以共用一个存储：

```typescript title="src/mastra/index.ts"
import { Mastra } from '@mastra/core/mastra'
import { LibSQLStore } from '@mastra/libsql'
import { Observability, MastraStorageExporter } from '@mastra/observability'

export const mastra = new Mastra({
  storage: new LibSQLStore({ id: 'voice-agent-storage', url: 'file:./voice-agent.db' }),
  observability: new Observability({
    configs: {
      default: {
        serviceName: 'voice-agent',
        exporters: [new MastraStorageExporter()],
      },
    },
  }),
})
```

Trace 默认开启。向 `createLiveKitWorker` 传入 `observability: false` 可将其关闭。

### 从应用中请求播放录音 {/* #request-recording-playback-from-your-application */}

从 `@mastra/livekit/client` 导入浏览器客户端辅助函数。使用该入口需要安装 1.x 系列中不低于 1.51.2 的 `@mastra/client-js`：

```bash npm2yarn
npm install @mastra/livekit @mastra/client-js
```

```typescript
import { MastraClient } from '@mastra/client-js'
import { getLiveKitRecording } from '@mastra/livekit/client'
import type { LiveKitRecordingResponse } from '@mastra/livekit/client'

const client = new MastraClient({
  baseUrl: 'https://mastra.example.com',
  credentials: 'include',
})

const recording: LiveKitRecordingResponse = await getLiveKitRecording(client, traceId)
if (recording.status === 'ready') {
  audioElement.src = recording.url
}
```

先在服务器上注册 [`liveKitRecordingRoute()`](#review-recordings-in-studio)。辅助函数请求其默认路径 `/voice/livekit/recordings/:traceId`，不受客户端 API 前缀影响。它会沿用客户端的身份验证请求头、Cookie、自定义 fetch 函数和中止信号。可以将 `{ signal }` 作为第三个参数传入，以取消单次请求。失败的请求会抛出 `MastraClientError`，不会自动重试。

`@mastra/client-js@1.51.2` 声明支持 Zod 3 和 4，但其依赖 `@ai-sdk/ui-utils@1.2.11` 将 Zod 3 声明为 peer dependency。使用 Zod 4 时，这种版本要求不一致可能导致严格执行依赖检查的 npm 安装失败。搭配该 SDK 使用 Zod `^3.25.76`，可同时满足两者的版本范围。不使用可选客户端 SDK 的服务器和 Worker 也支持 Zod 4。

`/client` 入口不会引入 LiveKit 服务器和 Worker 代码。其他集成入口不要求安装 `@mastra/client-js`。安装 `@mastra/livekit` 仍会安装该包的依赖；浏览器入口只控制哪些代码进入浏览器构建产物。存储凭据和录音授权逻辑仍保留在服务器端。

### 回合指标与播放完成状态 {/* #turn-metrics-and-playback-completion */}

`createLiveKitWorker()` 接受两个用于评估语音通话的观察回调：

```typescript title="src/mastra/voice-worker.ts"
import { createLiveKitWorker } from '@mastra/livekit/worker'

export default createLiveKitWorker({
  mastra,
  agent: 'support',
  onTurnMetrics: metrics => {
    console.info('voice metric', metrics)
  },
  onSpeechComplete: speech => {
    console.info('speech outcome', speech.speechId, speech.outcome)
  },
})
```

观察回调异步运行，音频管道不会等待它们。错误会被记录。回调中的处理应尽量简短。这两个回调都不会写入或同步 Memory。

`onTurnMetrics` 接收带版本信息的记录，其 phase 为 `phase: 'generation'` 或 `phase: 'speech'`。生成阶段记录包含 `turnId`、唯一的 `attemptId`、最终 `outcome`、`durationMs`、可选的 `firstTextMs`，以及 Tool 耗时。同一条用户消息对应的多次尝试共用一个回合 ID。Tool 耗时从桥接层收到调用开始，到收到结果为止；远程调用的耗时包含传输时间，并非纯粹的服务器执行时间。没有返回结果的 Tool 不会记录耗时。

语音阶段记录还包含 LiveKit 的 `speechId`。桥接层将回合 ID 和尝试 ID 放入助手消息元数据，以便播放后关联记录。对于没有对应助手消息的语音，例如尚未产生输出就被取消的语音，会以其语音 ID 作为回合 ID，并省略尝试 ID。不要根据事件到达顺序推断关联关系。

| 测量值 | 含义 |
| - | - |
| 生成阶段 `firstTextMs` | 从开始生成到首段文本送往语音合成的时间，可能包含过渡提示。 |
| 语音阶段 `firstAudioMs` | LiveKit 报告的、从来电者说话结束到首段输出音频出现的时间，可能包含过渡提示。 |
| 语音阶段 `completionMs` | 从来电者说话结束到输出音频播放完毕的时间。语音被打断、取消或失败时不提供此值。 |
| `speechStartedAt` / `speechEndedAt` | 可用时提供的播放时间戳，单位为 Unix 纪元毫秒。 |

缺失的测量值为 `undefined`，不是零。本地生成耗时使用单调时钟测量。LiveKit 的语音时间值会转换为毫秒。配置可观测性后，这些记录会作为事件出现在现有的 `voice call` Trace 中。LiveKit 提供语音 ID 时，音频管道指标事件会保留该 ID。

`onSpeechComplete` 在语音句柄结束时运行一次；如果会话关闭时该语音仍未结束，也会运行一次。回调提供语音指标，以及可选的 `playedText` 和 `transcriptSource`。结果可能是 `completed`、`interrupted`、`cancelled` 或 `failed`。语音生命周期结束并不代表一定产生了音频；应检查相应的音频测量值是否存在。

测量来源为 `server-playout`。根据输出端的同步能力，LiveKit 已确认的转录文本可能不完整，也可能只是估计值。它不能证明远端浏览器或电话听众听到了每个字。`transcriptSource: 'unavailable'` 表示没有可用的已确认助手转录文本。

继续使用 `onTurnComplete` 获取其原有的生成阶段结果。它可能在语音播放结束前触发，并报告 `interrupted: false`，即使来电者之后打断了音频。播放结果应通过 `onSpeechComplete` 获取。现有 Agent Memory 中可能已经保存了生成的文本；添加该钩子不会改变这一持久化行为。

对于自行管理的会话，应在 `session.start()` 之前调用 `@mastra/livekit/worker` 或 `@mastra/livekit/plugin` 导出的 `observeVoiceSession(session, { onTurnMetrics, onSpeechComplete })`。其返回值可用于移除观察回调，并将仍在等待的语音标记为已取消。Worker 会自动注册自己的观察回调。

### 语音片段边界 {/* #speech-segment-boundaries */}

内置 Agent、远程和 Workflow 回复生成器都会保留文本片段及 Tool 步骤的边界。Tool 反馈文本进入队列后会触发刷新，因此即使 Tool 仍在运行，确认语也能送达文本转语音环节。刷新会请求划分片段边界，但不能保证所有语音 Provider 都立即输出音频。

自定义生成器仍可返回字符串流。要显式标记边界，请返回 `ReadableStream<VoiceReplyChunk>`，并向其中加入 `VOICE_TEXT_FLUSH`；两者都从 `@mastra/livekit/worker` 和 `@mastra/livekit/plugin` 导出。直接读取回复生成器的消费者必须区分字符串与边界对象，不能将边界对象拼接进转录文本。

Worker 会将边界转换为 LiveKit 的 `FlushSentinel`。使用 `MastraLLM` 插件时，应为自行管理的 LiveKit Agent 添加节点适配器：

```typescript
import { voice } from '@livekit/agents'
import { MastraLLM, mastraLLMNode } from '@mastra/livekit/plugin'

class SupportAgent extends voice.Agent {
  override llmNode(...args: Parameters<voice.Agent['llmNode']>) {
    return mastraLLMNode(this, ...args)
  }
}

const session = new voice.AgentSession({
  llm: new MastraLLM({ agent: supportAgent }),
  // Configure STT and TTS for your application.
})
await session.start({ agent: new SupportAgent({ instructions: 'Support assistant' }), room })
```

没有适配器时，插件仍会输出文本，但 LiveKit 的默认节点不会将插件的边界元数据转换为刷新标记。在 Workflow 的回复步骤中使用 `pipeAgentReplyToWriter()`，可保留用于计算时间的边界和 Tool 结果。

### 部署 {/* #deployment */}

Worker 与 Mastra 服务器运行在不同进程中。使用生产环境命令将其部署为长期运行的 Node 服务：

```bash
node dist/voice-worker.js start
```

LiveKit 关于容量规划、优雅关闭和托管的指南仍然适用。参见[部署 Agent](https://docs.livekit.io/agents/ops/deployment/)。Worker 主动向 LiveKit 建立出站连接，因此无需开放入站端口。

### 工作原理 {/* #how-it-works */}

LiveKit 语音会话涉及三个部分：

1. Mastra 服务器生成 LiveKit 访问令牌，并将 Agent 分派到房间。分派请求携带 Mastra Agent ID、Memory 对话线程和资源等元数据。
2. LiveKit Agent Worker 作为独立的长期运行进程，接收任务并运行音频管道。音频通过 WebRTC 在浏览器与 Worker 之间传输，不经过 Mastra HTTP 服务器。
3. 用户每说完一轮，Worker 就将新输入传给 Mastra Agent 的 `stream()`，并朗读流式生成的文本。用户打断时，LiveKit 会取消该流，Mastra 随即停止生成。

对话历史保存在 Mastra Memory 中，因此语音会话和文本聊天可以共用一个对话线程。

## 升级到 0.5.0 {/* #upgrade-to-050 */}

0.5.0 预发布版本要求 LiveKit Agents 1.7.1 或更高的 1.x 版本。语音辅助函数使用 `FlushSentinel` 和 `SpeechHandle.exception()`，而 Agents 1.4.0 中没有这两个 API。部署前，请测试提供的预发布版本或软件包归档。修改依赖版本范围不会更新现有锁文件，因此安装后还需检查实际安装的版本。

如果你在早期快照中使用了 `client.getLiveKitRecording(traceId)`，请改用从 `@mastra/livekit/client` 导出的 `getLiveKitRecording(client, traceId)`。同时从该入口导入 `LiveKitRecordingResponse`，取代从 client-js 导入的 `GetLiveKitRecordingResponse`。

### 授权录音访问 {/* #authorize-recording-access */}

升级注册了 `liveKitRecordingRoute()` 的应用前，请添加 `authorize({ traceId, context })` 回调，检查已认证用户是否有权访问请求的 trace。即使设置了 `requiresAuth: false`，该回调也必不可少；缺少回调会在注册路由时抛出异常。只有确认允许访问时才返回 `true`，且该检查会在查询 trace 或解析播放 URL 之前进行。配置示例见[在 Studio 中查看录音](#review-recordings-in-studio)。

### 安装兼容的软件包 {/* #install-compatible-packages */}

Agents 及其插件应使用完全相同的发行版本。经过测试的基线版本如下：

| 软件包 | 版本 |
| - | - |
|`@livekit/agents` | `1.7.1` |
| `@livekit/agents-plugin-livekit` | `1.7.1` |
| `@livekit/agents-plugin-silero` | `1.7.1` |
| `@livekit/rtc-node` | `0.13.34` |
| `livekit-server-sdk` | `2.16.0` |

如果使用本地预发布软件包归档，请同时安装版本匹配的 LiveKit 软件包：

```bash npm2yarn
npm install ./mastra-livekit-0.5.0-next.0.tgz @livekit/agents@1.7.1 @livekit/agents-plugin-livekit@1.7.1 @livekit/agents-plugin-silero@1.7.1 @livekit/rtc-node@0.13.34 livekit-server-sdk@2.16.0
```

将归档路径替换为实际提供的预发布软件包。其他 `@livekit/agents-plugin-*` 软件包也应安装匹配的发行版本。Agents 1.7.1 和 Silero 1.7.1 要求 RTC `^0.13.34`；RTC 1.x 不满足该要求。不要通过忽略 peer dependency 错误来强行安装。

请使用 Node.js 22.13 或更高版本。`@mastra/livekit` 和 Agents 都要求 Zod `^3.25.76 || ^4.1.8`。安装 0.5.0 前，请先升级较旧的 Zod 版本。随后检查实际安装的依赖树，并初始化 worker 所需的模型：

```bash npm2yarn
npm ls @mastra/livekit @livekit/agents @livekit/agents-plugin-livekit @livekit/agents-plugin-silero @livekit/rtc-node
npx tsx src/mastra/voice-worker.ts download-files
```

集成代码与自定义 `voice.AgentSession` 应共用同一份已安装的 Agents。安装多份可能导致 LiveKit 的运行时类检查失败。

### 检查 VAD 和话轮结束检测 {/* #check-vad-and-turn-detection */}

现在，`vad: false` 会在创建会话时禁用 VAD。此前，worker 虽然会跳过插件预热，却向 LiveKit 传入 `undefined`，这可能启用 LiveKit 自带的 VAD。如果应用依赖此前的行为，请显式配置检测器。

```typescript title="src/mastra/voice-worker.ts"
import { createLiveKitWorker } from '@mastra/livekit/worker'
import { mastra } from './index'

export default createLiveKitWorker({
  mastra,
  agent: 'support',
  vad: false,
  turnDetection: 'manual',
})
```

默认配置仍会在预热期间加载 Silero 插件。`'english'` 和 `'multilingual'` 话轮结束检测选项仍会选择各自原有的文本模型。LiveKit 新增的 `inference.VAD` 和 `inference.TurnDetector` API 可通过现有的实例选项和解析函数选项使用；是否切换到这些 API 需要单独决定，因为这可能改变话语终点判定、模型下载和云端用量。

### 检查自定义 LiveKit Tool {/* #review-custom-livekit-tools */}

Mastra Tool 仍通过 Mastra Agent 运行。如果你还实现了 LiveKit Tool 或自定义 LiveKit 插件，请留意 Agents 1.4 之后的变化：

* `ToolContext` 是一个类。请使用其访问器和 `flatten()`，不要像处理普通对象一样枚举或修改它。
* 现在支持具名 Tool 列表和重名检查。匿名 Tool 的对象简写形式仍受支持，无需转换所有 Tool 映射。
* Provider Tool 使用 `ProviderTool` 的子类，取代旧的 `ProviderDefinedTool` API。

自定义插件的迁移详情见 [LiveKit Tool API](https://github.com/livekit/agents-js/blob/main/agents/src/llm/tool_context.ts)。

### 检查关闭流程 {/* #review-shutdown */}

`onCallEnd` 钩子仍使用 LiveKit 的 job 关闭回调。请确保清理工作在配置的关闭时限内完成，并验证来电方断开连接或 worker 收到关闭信号时，清理工作都能完成。

### 验证录音和通话 {/* #verify-recordings-and-calls */}

集成中的房间级 `recording` 配置和 S3 权限保持不变。LiveKit Agents 的 `AgentSession.start({ record })` 控制另一套会话录制与遥测功能。禁用其中一套不会禁用另一套。

推广预发布版本前，请分别测试浏览器通话和通过已配置 SIP 中继接入的电话通话。验证双方语音、中断、Tool、开场问候与同意流程、挂断、完整的 trace，以及 `onCallEnd`。启用录音时，请等待 S3 对象生成，再使用 **Review Audio** 播放录音。还应测试禁用录音，以及拒绝使用已有房间名称的情况。请在已安装模型文件和原生库的部署镜像上执行这些检查。

## API 参考 {/* #api-reference */}

`@mastra/livekit` 软件包将 Mastra Agent 接入 LiveKit Agents 框架。LiveKit 负责运行音频处理流程，包括语音活动检测、语音转文字、话轮结束检测、文字转语音和插话处理；该软件包则将回复生成接入 Mastra Agent 的 `stream()` 调用。

有关配置步骤和基本概念，请参阅[实时语音](#quickstart)。

该软件包提供三个入口：

* `@mastra/livekit`：服务端 API，包括 [`liveKitConnectionRoute()`](#livekitconnectionroute)、[`dispatchVoiceSession()`](#dispatchvoicesession)、[`pipeAgentReplyToWriter()`](#pipeagentreplytowriter)、[`serializeSessionMetadata()`](#livekitsessionmetadata) 和 [`createEndCallTool()`](#createendcalltool)。请在 Mastra 服务端代码中从此入口导入；此入口不会加载 LiveKit Agents 运行时。
* `@mastra/livekit/worker`：worker 运行时，包括 [`createLiveKitWorker()`](#createlivekitworker)、[`runLiveKitWorker()`](#runlivekitworker)、[`chatContextToMessages()`](#chatcontexttomessages)、每个会话使用的 Agent 类 [`MastraVoiceAgent`](#mastravoiceagent)，以及会话辅助函数 [`speakGreeting()`](#speakgreeting)、[`waitForAgentDoneSpeaking()`](#waitforagentdonespeaking) 和 [`runEndCall()`](#runendcall)。仅在 worker 入口文件中导入。
* `@mastra/livekit/plugin`：LLM 组件插件，包括 [`MastraLLM`](#mastrallm) 和 [`createRemoteAgentReplyGenerator()`](#createremoteagentreplygenerator)。在自行构建 `voice.AgentSession` 的 worker 中导入。`createRemoteAgentReplyGenerator()` 也从 `@mastra/livekit/worker` 导出，因为它可用于 `createLiveKitWorker()` 的 `generate` 选项。`MastraLLM` 仅由插件入口导出。

### `createLiveKitWorker()` {/* #createlivekitworker */}

创建一个使用 Mastra Agent 响应语音会话的 LiveKit Agent 定义。请将其作为 worker 入口文件的默认导出。

```typescript title="src/mastra/voice-worker.ts"
import { fileURLToPath } from 'node:url'
import { createLiveKitWorker, runLiveKitWorker } from '@mastra/livekit/worker'
import { mastra } from './index'

export default createLiveKitWorker({
  mastra,
  agent: 'support',
  stt: 'deepgram/nova-3',
  tts: 'cartesia/sonic-3',
  turnDetection: 'multilingual',
})

if (process.argv[1] === fileURLToPath(import.meta.url)) {
  runLiveKitWorker({ entry: import.meta.url, agentName: 'mastra-voice' })
}
```

### `MastraVoiceAgent` {/* #mastravoiceagent */}

这是 LiveKit `voice.Agent` 的子类，由 [`createLiveKitWorker()`](#createlivekitworker) 为每个会话创建。回复通过 Agent 的 `llmNode` 来自 Mastra Agent（或自定义 `generate` 来源）；音频循环、话轮检测和用户打断仍由 LiveKit 处理。如果由你管理 `voice.AgentSession`，也可以自行构造它。例如，无需语音转文本、文本转语音或运行中的 worker，就能用 `@livekit/agents` 的 `voice.testing` 测试基于 Mastra 的 Agent。`createMastraVoiceAgent(options)` 是功能等效的工厂函数。

```typescript title="src/mastra/voice-agent.test.ts"
import { supportAgent } from './agents/support'

const result = session.run({ userInput: 'What are your opening hours?' })

result.expect.nextEvent().isMessage({ role: 'assistant' })
result.expect.noMoreEvents()
```

### `MastraLLM` {/* #mastrallm */}

这是由 Mastra Agent 支持的标准 LiveKit LLM 插件（`llm.LLM`）。如果你自行构建 `voice.AgentSession`，并希望将 Mastra 放入 `llm` 位置，可以使用它。托管方式则可使用 [`createLiveKitWorker()`](#createlivekitworker)。如何选择，请参阅[将 Mastra 用作 LLM 组件](#use-mastra-as-the-llm-component)。

使用 `remote` 时，插件通过 HTTP 和 Server-Sent Events（SSE），从你的 Mastra 服务器流式获取每轮回复。Agent 循环、Tool 和内存功能在服务器端运行；打断 Agent 会中止服务器端的生成。

```typescript title="src/mastra/voice-worker-plugin.ts"
import { voice } from '@livekit/agents'
import { MastraLLM } from '@mastra/livekit/plugin'

const session = new voice.AgentSession({
  llm: new MastraLLM({
    remote: { baseUrl: process.env.MASTRA_URL!, agentId: 'support' },
    memory: { thread: callId, resource: userId },
  }),
  stt: 'deepgram/nova-3',
  tts: 'cartesia/sonic-3',
  // Required with `memory` unless memory.options.readOnly is set: LiveKit enables
  // preemptive generation by default.
  turnHandling: { preemptiveGeneration: { enabled: false } },
})
```

插件将 `provider` 报告为 `mastra`，将 `model` 报告为 Agent ID，因此 LiveKit 指标和故障切换适配器可以像识别其他 LLM 一样识别它。

#### 在 Mastra Agent 上运行 Tool {/* #tools-run-on-the-mastra-agent */}

Tool 在服务器端的 Mastra Agent 上定义和执行。插件不会转发 LiveKit 的 Tool 定义：如果会话传入非空的 `toolCtx`，插件会记录一次警告，列出被忽略的 Tool。所有 Tool 都必须在服务器端完成执行；需要审批或客户端执行的 Tool 会使该话轮失败并给出明确错误，而不会让通话一直等待。

worker 可通过 `toolFeedback`、`onToolCall` 和 `onTurnComplete` 获知 Tool 的活动。

#### 指令 {/* #instructions */}

LiveKit 会将你的 `voice.Agent` 的 `instructions` 注入每次请求的聊天上下文。插件会移除这些指令，因为服务器端 Mastra Agent 自身的指令才会用于生成回复。如需更改提示词，请修改 Mastra Agent。

#### 被打断的话轮 {/* #interrupted-turns */}

当用户打断回复时：

1. 插件取消流。服务器中止生成，不持久化该话轮的任何内容。
2. LiveKit 在聊天上下文中记录用户实际听到的回复片段，并将其标记为已打断。
3. 下一轮，插件会在新用户消息之前重新发送这段已播报的回复，使内存 thread 补齐记录，与通话内容一致。消息带有 LiveKit 消息 ID，服务器按 ID 去重，因此重试和重复发送都是幂等的。

如果用户打断回复后立即挂断，最后这段回复就不会被记录。如果对话记录必须包含它，请立即根据会话事件补录。由于使用同一个消息 ID，下一轮重新发送时会更新该消息，而不会产生重复记录：

```typescript title="src/mastra/voice-worker-plugin.ts"
import { voice } from '@livekit/agents'
import { MastraClient } from '@mastra/client-js'

const client = new MastraClient({ baseUrl: process.env.MASTRA_URL! })

session.on(voice.AgentSessionEventTypes.ConversationItemAdded, ({ item }) => {
  if (item.type !== 'message' || item.role !== 'assistant' || !item.interrupted) return
  void client.saveMessageToMemory({
    agentId: 'support',
    messages: [
      {
        id: item.id,
        threadId: callId,
        resourceId: userId,
        role: 'assistant',
        content: item.textContent ?? '',
        type: 'text',
        createdAt: new Date(),
      },
    ],
  })
})
```

#### 用量指标 {/* #usage-metrics */}

服务器报告某轮的 token 用量时，插件会将其传给 LiveKit。因此，与其他 LLM 插件一样，会话的 `metrics_collected` 事件包含首个 token 耗时、总耗时和 token 数量。同一个用量对象（`promptTokens`、`completionTokens`、`promptCachedTokens`、`totalTokens`）也会作为 `result.usage` 传入 `onTurnComplete`。

#### 错误和超时 {/* #errors-and-timeouts */}

传输层会抛出 LiveKit 的 `APIError` 类型（`APIStatusError`、`APIConnectionError`、`APITimeoutError`），因此会话的重试策略（`connOptions.maxRetry`）和 `FallbackAdapter` 故障切换机制照常工作。发出首个 token 后，该话轮不会重试：语音回复应尽快报错，避免重播用户已听过一部分的内容。

连接及首个 token 的超时监测使用会话的 `connOptions.timeoutMs`（默认 10 秒），因此即使服务器接受连接后始终不返回流，也不会无限期保持静音。

如果 Mastra 服务器在通话中发生故障，每次回复尝试都会在完成重试后以明确的错误类型失败；连续多次回复失败后，LiveKit 会关闭会话。如果能在重试次数耗尽前恢复服务器，通话就能在下一轮恢复。

#### 消息内容 {/* #message-content */}

消息提取仅保留文本：图像内容会被丢弃，音频内容只会以转录文本的形式保留。这不影响语音处理流程，但你自行注入聊天上下文的条目必须包含文本。

### `createRemoteAgentReplyGenerator()` {/* #createremoteagentreplygenerator */}

构建一个通过 HTTP/SSE 在**远程** Mastra 服务器上运行 Agent 循环的回复生成器。`MastraLLM` 的 `remote` 模式会在内部使用它。也可以将它传给 `createLiveKitWorker` 的 `generate` 选项，让功能完整的 worker 连接远程服务器：

```typescript title="src/mastra/voice-worker.ts"
import { createLiveKitWorker, createRemoteAgentReplyGenerator } from '@mastra/livekit/worker'
import { mastra } from './index'

export default createLiveKitWorker({
  mastra, // local instance for logger and worker config; replies come from the remote server
  generate: createRemoteAgentReplyGenerator({
    baseUrl: process.env.MASTRA_URL!,
    agentId: 'support',
  }),
  memory: ({ metadata, roomName }) => ({ thread: metadata.threadId ?? roomName }),
  stt: 'deepgram/nova-3',
  tts: 'cartesia/sonic-3',
})
```

使用 `generate` 路径时，worker 级别的 `toolFeedback` 和 `onTurnComplete` 选项不会生效，worker 的通话结束检测也不会触发。请改为将这些钩子传给生成器。

取消话轮（用户打断）会终止 HTTP 请求，从而中止服务器端的生成。错误会以 LiveKit `APIError` 类型抛出。`retries` 选项仅适用于建立初始连接的尝试。返回首个数据块后，该话轮不会重试。

### `waitForAgentDoneSpeaking()` {/* #waitforagentdonespeaking */}

当 Agent 不再生成或播放回复，即其状态不再是 `thinking` 或 `speaking` 时，Promise 兑现。如果 Agent 已空闲，则立即兑现；作为安全上限，最迟也会在 `maxWaitMs` 内兑现（默认 30 秒）。关闭会话前调用此函数，让结束语播放完毕，避免被截断。

### `runEndCall()` {/* #runendcall */}

Agent 请求挂断后，此函数会先等待 Agent 播放结束语，再不中断地播报可选的最终 `message`。随后删除房间并挂断来电方，包括 SIP 来电方。作业通过已注册的回调关闭。

在自行管理的会话中，将其与 [`MastraLLM`](#mastrallm) 的 `onToolCall` 及服务端 Agent 上的[结束通话 Tool](#createendcalltool) 配合使用，即可实现由 Agent 发起挂断：

```typescript title="src/mastra/voice-worker-plugin.ts"
import { MastraLLM } from '@mastra/livekit/plugin'
import { DEFAULT_END_CALL_TOOL, runEndCall } from '@mastra/livekit/worker'

let ending = false

const llm = new MastraLLM({
  remote: { baseUrl: process.env.MASTRA_URL!, agentId: 'support' },
  onToolCall: ({ toolName }) => {
    if (toolName !== DEFAULT_END_CALL_TOOL || ending) return
    ending = true
    void runEndCall(session, ctx, {}, console)
  },
})
```

导出的常量 `DEFAULT_END_CALL_TOOL`（`'endCall'`）、`DEFAULT_END_CALL_REASON` 和 `DEFAULT_END_CALL_MAX_WAIT_MS`（30000）保存了默认值。

### `createEndCallTool()` {/* #createendcalltool */}

```typescript title="src/mastra/agents/support-agent.ts"
import { Agent } from '@mastra/core/agent'
import { createEndCallTool } from '@mastra/livekit'

const supportAgent = new Agent({
  id: 'support',
  name: 'Support',
  instructions:
    'Help the caller. When everything is wrapped up, say goodbye and call endCall as your final action.',
  model: '__GATEWAY_OPENAI_MODEL_LUNA__',
```
