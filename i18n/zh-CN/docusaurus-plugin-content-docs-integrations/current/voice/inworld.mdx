# Inworld

## 语音 {/* #voice */}

Mastra 的 Inworld 语音实现通过 Inworld AI API 提供流式文本转语音（TTS）和批量语音转文本（STT）。它支持多种 TTS 和 STT 模型、可配置的音频编码，以及逐步输出的音频流。

如需实时、全双工的语音对话，同一软件包还导出了 [`InworldRealtimeVoice`](#realtime)。

### 使用示例 {/* #usage-example */}

```typescript
import { InworldVoice } from '@mastra/voice-inworld'

// Initialize with default configuration (uses INWORLD_API_KEY environment variable)
const voice = new InworldVoice()

// Initialize with custom configuration
const voice = new InworldVoice({
  speechModel: {
    name: 'inworld-tts-2',
    apiKey: 'your-api-key',
  },
  listeningModel: {
    name: 'groq/whisper-large-v3',
    apiKey: 'your-api-key',
  },
  speaker: 'Dennis',
})

// Text-to-Speech (streaming)
const audioStream = await voice.speak('Hello, world!')

// Speech-to-Text
const transcript = await voice.listen(audioStream)
```

### 注意事项 {/* #notes */}

* TTS 端点使用渐进式 NDJSON 流，因此无需等到完整响应到达，就可以开始播放音频。
* API 密钥可通过 `speechModel` 或 `listeningModel` 配置提供，也可使用 `INWORLD_API_KEY` 环境变量。TTS 和 STT 的密钥分别解析：为 `speechModel.apiKey` 和 `listeningModel.apiKey` 指定不同的值，即可让两个服务使用各自的凭据。如果只提供其中一个密钥，另一个服务会先复用该密钥，再回退到环境变量。
* `inworld-tts-2` 是默认的旗舰模型。可用 `deliveryMode`（`STABLE`、`BALANCED` 或 `CREATIVE`）调整其表达风格。`inworld-tts-2` 会忽略 `temperature` 选项。
* 与 `inworld-tts-1.5-max` 相比，`inworld-tts-1.5-mini` 的延迟更低，但音质也较低。

## 实时语音 {/* #realtime */}

`InworldRealtimeVoice` 类通过 WebSocket 使用 [Inworld AI 的 Realtime API](https://docs.inworld.ai/realtime/quickstart-websocket)，提供实时、全双工的语音交互。它支持语音对话、Tool 调用，以及语义语音活动检测、MCP Tool 路由和播放速度等 Inworld 专用会话选项。

Inworld 的传输协议遵循 OpenAI Realtime GA 规范，因此客户端和服务端的事件名称与 `@mastra/voice-openai-realtime` 一致。Provider 层面的区别包括：端点在 URL 中使用客户端生成的会话密钥；使用 `Authorization: Basic <key>` 请求头；通过带类型的构造函数 `session` 字段配置 Inworld 专用选项；以及通过 `session.providerData` 发送带类型的 `providerData` 对象，配置 STT、TTS、记忆、反馈语音和响应速度等 Inworld 扩展。

有关批量文本转语音和语音转文本的用法，请参阅 [`@mastra/voice-inworld`](#voice)。

### 使用示例 {/* #usage-example-1 */}

```typescript title="src/mastra/index.ts"
import { InworldRealtimeVoice } from '@mastra/voice-inworld'
import { playAudio, getMicrophoneStream } from '@mastra/node-audio'

// Initialize with INWORLD_API_KEY from the environment
const voice = new InworldRealtimeVoice()

// Or initialize with explicit configuration
const voiceWithConfig = new InworldRealtimeVoice({
  apiKey: 'your-inworld-api-key',
  model: 'inworld/models/gemma-4-26b-a4b-it',
  speaker: 'Sarah',
  instructions: 'You are a helpful voice assistant.',
  session: {
    audio: {
      output: { speed: 1.1 },
      input: { turn_detection: { type: 'semantic_vad', eagerness: 'high' } },
    },
  },
})

// Establish connection
await voice.connect()

// Listen for audio output (PCM16 @ 24 kHz by default)
voice.on('speaker', stream => {
  playAudio(stream)
})

voice.on('writing', ({ text, role }) => {
  console.log(`${role}: ${text}`)
})

// Convert text to speech
await voice.speak('Hello, how can I help you today?', {
  speaker: 'Hades',
})

// Stream microphone audio to the model
const microphoneStream = getMicrophoneStream()
await voice.send(microphoneStream)

// Clean up
voice.close()
```

> Inworld API 密钥已经过 Basic 编码。请将密钥原样填入 `INWORLD_API_KEY`；软件包不会再次编码。

#### `providerData`（Inworld 扩展） {/* #providerdata-inworld-extensions */}

`providerData` 是配置 Inworld 专用实时扩展的带类型对象。每次发送 `session.update` 时，它都会放在 `session.providerData` 下，并与通过 `session` 字段设置的 `session.providerData` 合并；键冲突时以构造函数中的 `providerData` 为准。

它包含五组扩展选项和两个会话级字段：

* `stt`：调整 STT，例如 `prompt`、`voice_profile`、`language_hints`，以及 VAD 或话轮结束阈值。
* `tts`：配置 TTS 分段和表达，例如 `segmenter_strategy`、`steering_handling`、`delivery_mode`、`conversational` 和 `user_turn_mode`。
* `memory`：配置自动滚动记忆，例如 `enabled`、`turn_interval` 和 `max_facts`。Inworld 会通过 `memory` 事件回传其状态。
* `backchannel`：用户说话时发出的简短应答，例如“嗯嗯”。音频通过 `backchannel` 事件到达。
* `responsiveness`：主响应生成期间提前播放的填充音频。填充音频复用常规的 `speaker` 和 `speaking` 事件，没有单独的事件。
* `user_id` 和 `metadata`：传递给 Inworld 的会话级标识信息。

```typescript
const voice = new InworldRealtimeVoice({
  providerData: {
    stt: { voice_profile: true, language_hints: ['en-US'] },
    tts: { delivery_mode: 'CREATIVE', segmenter_strategy: 'balanced' },
    memory: { enabled: true, turn_interval: 4 },
    backchannel: { enabled: true, max_per_turn: 1 },
    user_id: 'user-123',
  },
})
```

### 方法 {/* #methods-1 */}

#### `connect()` {/* #connect */}

打开 WebSocket 连接并发送初始 `session.update`；服务端以 `session.updated` 确认后，Promise 才会完成。调用 speak()、listen() 或 `send()` 之前必须先调用此方法。

如果 WebSocket 在打开前触发 `error` 或 `close`，或握手超过 `connectTimeoutMs`（默认 15 秒），Promise 会被拒绝，而不会产生未捕获的套接字错误。发生拒绝时，尚未完全建立的连接会被关闭。

```typescript
await voice.connect()
```

返回：`Promise<void>`

#### `speak()` {/* #speak */}

向模型发送文本消息并触发音频响应。返回的 Promise 只有在本次调用触发的响应完成整个生命周期（收到对应的 `response.done`）后才会完成；如果用户语音打断了响应，或发生传输错误，Promise 会被拒绝。

应依次调用 `speak()`。并发调用会共用同一组监听器，响应与调用的对应顺序没有定义。

##### `clearOutput()` {/* #clearoutput */}

清空服务端的整个输出音频缓冲区并停止播放。这也会停止正在播放的反馈语音。默认的插话处理方式（在 `interrupted` 时发送 `response.cancel`）不会影响反馈语音，应优先使用。只有需要清空全部输出时才使用 `clearOutput()`。

```typescript
voice.clearOutput()
```

返回：`void`

### 注意事项 {/* #notes-1 */}

* API 密钥可通过构造函数选项或 `INWORLD_API_KEY` 环境变量提供。密钥已经过 Basic 编码，不要再次编码。
* WebSocket URL 会附加 `?key=<sessionId>&protocol=realtime`。模型通过初始 `session.update` 配置，不放在 URL 中。
* 每次调用 `speak(input, { speaker })` 时，音色覆盖只对该响应生效（通过扁平的 `response.voice` 字段），不会修改会话。
* 音频输出默认为 24 kHz PCM16。也可以通过 `session.audio.output.format` 使用 8 kHz 电话音频格式 `audio/pcmu` 和 `audio/pcma`，或使用 `audio/float32`。
* 发送音频、调用 `speak()` 或 `listen()` 前，先调用 `connect()`。WebSocket 打开前发送的事件会进入队列，并在服务端以 `session.updated` 确认后发送。
* 必须调用 `close()` 或 `disconnect()` 关闭语音实例，以释放 WebSocket。
* 如果 `session` 未提供 `audio.input.turn_detection`，默认使用语义 VAD。可以传入自定义对象覆盖默认值，或传入 `null` 完全关闭话轮检测。
* `audio.input.transcription` 默认值为 `{ model: 'inworld/inworld-stt-1' }`，因此用户音频的 `writing` 事件默认可用。可以传入自定义对象覆盖默认值，或传入 `null` 关闭用户音频转写。
* `on()` 和 `off()` 按 `InworldVoiceEventMap` 提供类型。已知事件名称对应带类型的回调负载；未知名称的负载类型为 `unknown`。
