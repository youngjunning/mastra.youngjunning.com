# 世界中

## 嗓音 {/* #voice */}

Mastra 中的 Inworld 语音实现使用 Inworld AI 的 API 提供流式文本转语音 (TTS) 和批量语音转文本 (STT) 功能。它支持多种 TTS 和 STT 模型、可配置的音频编码和渐进式音频流。

对于实时、全双工语音转语音，相同的包导出[`InworldRealtimeVoice`](#realtime).

### 使用示例 {/* #usage-example */}

```typescript
import { InworldVoice } from '@mastra/voice-inworld'

// Initialize with default configuration (uses INWORLD_API_KEY environment variable)
const voice = new InworldVoice()

// Initialize with custom configuration
const voice = new InworldVoice({
  speechModel: {
    name: 'inworld-tts-2',
    apiKey: 'your-api-key',
  },
  listeningModel: {
    name: 'groq/whisper-large-v3',
    apiKey: 'your-api-key',
  },
  speaker: 'Dennis',
})

// Text-to-Speech (streaming)
const audioStream = await voice.speak('Hello, world!')

// Speech-to-Text
const transcript = await voice.listen(audioStream)
```

### 笔记 {/* #notes */}

* TTS 端点使用渐进式 NDJSON 流，因此可以在收到完整响应之前开始音频播放。
* API 密钥可以通过以下方式提供`speechModel` or `listeningModel` config, or the `INWORLD_API_KEY` environment variable. TTS and STT keys are resolved independently: passing distinct `speechModel.apiKey` and `listeningModel.apiKey` values lets each service use its own credential. If only one is provided, it's reused for both services as a fallback before the env var.
* `inworld-tts-2`是默认的旗舰机型。使用`deliveryMode` (`STABLE` | `BALANCED` | `CREATIVE`) to steer delivery style on this model. The `temperature` option is ignored on `inworld-tts-2`.
* 这`inworld-tts-1.5-mini` model offers lower latency at the cost of reduced voice quality compared to `inworld-tts-1.5-max`.

## 即时的 {/* #realtime */}

这`InworldRealtimeVoice` class provides real-time, full-duplex voice interaction using [Inworld AI's Realtime API](https://docs.inworld.ai/realtime/quickstart-websocket) over WebSockets. It supports speech-to-speech, tool calling, and Inworld-specific session knobs such as semantic voice activity detection, MCP tool routing, and playback speed.

Inworld 的有线协议是 OpenAI Realtime GA 规范，因此客户端和服务器事件名称匹配`@mastra/voice-openai-realtime`. The provider-level differences are the endpoint (which uses a client-generated session key in the URL), the `Authorization: Basic <key>` header, the typed `session` constructor field for Inworld-specific knobs, and a typed `providerData` object for Inworld extensions (STT, TTS, memory, back-channel, responsiveness) sent under `session.providerData`.

有关批量文本转语音和语音转文本的信息，请参阅[`@mastra/voice-inworld`](#voice).

### 使用示例 {/* #usage-example-1 */}

```typescript title="src/mastra/index.ts"
import { InworldRealtimeVoice } from '@mastra/voice-inworld'
import { playAudio, getMicrophoneStream } from '@mastra/node-audio'

// Initialize with INWORLD_API_KEY from the environment
const voice = new InworldRealtimeVoice()

// Or initialize with explicit configuration
const voiceWithConfig = new InworldRealtimeVoice({
  apiKey: 'your-inworld-api-key',
  model: 'inworld/models/gemma-4-26b-a4b-it',
  speaker: 'Sarah',
  instructions: 'You are a helpful voice assistant.',
  session: {
    audio: {
      output: { speed: 1.1 },
      input: { turn_detection: { type: 'semantic_vad', eagerness: 'high' } },
    },
  },
})

// Establish connection
await voice.connect()

// Listen for audio output (PCM16 @ 24 kHz by default)
voice.on('speaker', stream => {
  playAudio(stream)
})

voice.on('writing', ({ text, role }) => {
  console.log(`${role}: ${text}`)
})

// Convert text to speech
await voice.speak('Hello, how can I help you today?', {
  speaker: 'Hades',
})

// Stream microphone audio to the model
const microphoneStream = getMicrophoneStream()
await voice.send(microphoneStream)

// Clean up
voice.close()
```

> Inworld API 密钥已预先进行 Basic 编码。将它们逐字粘贴到`INWORLD_API_KEY`. The package doesn't re-encode them.

#### `providerData`（世界扩展） {/* #providerdata-inworld-extensions */}

`providerData`是用于 Inworld 特定实时扩展的类型化对象。它被发送到下面`session.providerData` on every `session.update`, and composes with any `session.providerData` you set via the `session` field: the constructor `providerData` wins on key collisions.

它有五个分支加上两个会话级字段：

* `stt`：STT调优，比如`prompt`, `voice_profile`, `language_hints`, and VAD or end-of-turn thresholds.
* `tts`：TTS分割和交付，例如`segmenter_strategy`, `steering_handling`, `delivery_mode`, `conversational`, and `user_turn_mode`.
* `memory`：自动滚动记忆，如`enabled`, `turn_interval`, and `max_facts`. Inworld echoes its state back through the `memory` event.
* `backchannel`：用户说话时的简短确认（“嗯嗯”）。音频到达`backchannel` event.
* `responsiveness`：主要响应生成时的早期填充音频。填充音频重用普通音频`speaker` and `speaking` events, so there are no distinct events.
* `user_id`和`metadata`: session-level identifiers passed through to Inworld.

```typescript
const voice = new InworldRealtimeVoice({
  providerData: {
    stt: { voice_profile: true, language_hints: ['en-US'] },
    tts: { delivery_mode: 'CREATIVE', segmenter_strategy: 'balanced' },
    memory: { enabled: true, turn_interval: 4 },
    backchannel: { enabled: true, max_per_turn: 1 },
    user_id: 'user-123',
  },
})
```

### 方法 {/* #methods-1 */}

#### `connect()` {/* #connect */}

打开 WebSocket 连接，发送初始信息`session.update`, and resolves once the server acknowledges with `session.updated`. Must be called before `speak()`, `listen()`, or `send()`.

预开盘`error` or `close` on the WebSocket (or a handshake that exceeds `connectTimeoutMs` (15s default)) surfaces as a rejected promise instead of an uncaught socket error. On reject, the half-open socket is closed.

```typescript
await voice.connect()
```

返回：`Promise<void>`

#### `speak()` {/* #speak */}

向模型发送文本消息并触发音频响应。返回的承诺仅在完整响应生命周期完成后才会解决（`response.done` for the response this call triggered), and rejects if the response is interrupted by user speech or if a transport error occurs.

串行`speak()` calls are the supported pattern. Concurrent calls share the same listener pool and have undefined response-pinning order.

##### `clearOutput()` {/* #clearoutput */}

清除服务器的整个输出音频缓冲区，停止播放。这也会停止任何飞行中的反向通道音频。默认打断路径 (`response.cancel` on `interrupted`) is back-channel-safe. Prefer it. Use `clearOutput()` only when you want to flush everything.

```typescript

```

返回：`void`

#### `close()`和`disconnect()` {/* #close-and-disconnect */}

这两种方法都会关闭 WebSocket 并将实例标记为已断开连接。

返回：`void`

#### `getSpeakers()` {/* #getspeakers-1 */}

返回与包捆绑在一起的精选语音列表。 Inworld 的目录比这个列表还要大；任何语音 ID 都可以传递到`speaker` at runtime.

返回：`Promise<Array<{ voiceId: string }>>`

#### `on()`和`off()` {/* #on-and-off */}

注册和删除事件侦听器。看[Events](#events) below.

### 笔记 {/* #notes-1 */}

* API 密钥可以通过构造函数选项或`INWORLD_API_KEY` environment variable. Keys are pre-Basic-encoded. Don't re-encode them.
* WebSocket URL 附加`?key=<sessionId>&protocol=realtime`. The model is configured via the initial `session.update`, not the URL.
* 每次通话`speak(input, { speaker })` scopes the voice override to a single response (via the flat `response.voice` field) and doesn't mutate the session.
* 音频输出默认为 24​​ kHz 的 PCM16。电话`audio/pcmu` and `audio/pcma` at 8 kHz, and `audio/float32`, are also supported via `session.audio.output.format`.
* 使用`connect()` before any send, speak, or listen call. Events sent before the WebSocket is open are queued and flushed once the server acknowledges `session.updated`.
* 语音实例必须关闭`close()` or `disconnect()` to release the WebSocket.
* `audio.input.turn_detection`默认为语义 VAD 时`session` doesn't supply it. Override with your own object, or pass `null` to disable turn detection entirely.
* `audio.input.transcription`默认为`{ model: 'inworld/inworld-stt-1' }`, so user-side `writing` events fire out of the box. Override with your own object, or pass `null` to disable user-side transcription.
* `on()`和`off()` are typed against `InworldVoiceEventMap`. Known event names yield a typed callback payload. Unknown names fall back to `unknown`.
