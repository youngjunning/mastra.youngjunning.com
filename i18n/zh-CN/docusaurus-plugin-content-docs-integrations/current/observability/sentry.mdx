# Sentry

[Sentry](https://sentry.io/) 是一款提供 AI 专用追踪功能的应用监控平台。Sentry 导出器按照 OpenTelemetry 语义约定将 Trace 发送到 Sentry，便于查看模型性能、token 用量和 Tool 执行情况。

## 安装 {/* #installation */}

```bash npm2yarn
npm install @mastra/sentry@latest
```

## 配置 {/* #configuration */}

### 准备工作 {/* #prerequisites */}

1. 在 [sentry.io](https://sentry.io/) 注册 **Sentry 账号**。
2. 在 Project Settings → Client Keys 中获取项目的 **DSN**（[数据源名称](https://docs.sentry.io/concepts/key-terms/dsn-explainer/)）。
3. 按以下示例设置**环境变量**。

```bash title=".env"
SENTRY_DSN=https://...@...sentry.io/...

# Optional
SENTRY_ENVIRONMENT=production
SENTRY_RELEASE=1.0.0
```

### 通过环境变量配置 {/* #zero-config-setup */}

设置环境变量后，创建导出器时无需传入配置。

```typescript title="src/mastra/index.ts"
import { Mastra } from '@mastra/core'
import { Observability } from '@mastra/observability'
import { SentryExporter } from '@mastra/sentry'

export const mastra = new Mastra({
  observability: new Observability({
    configs: {
      sentry: {
        serviceName: 'my-service',
        exporters: [new SentryExporter()],
      },
    },
  }),
})
```

### 显式配置 {/* #explicit-configuration */}

也可以直接向导出器传入凭据。显式传入的凭据优先于环境变量。

```typescript title="src/mastra/index.ts"
import { Mastra } from '@mastra/core'
import { Observability } from '@mastra/observability'
import { SentryExporter } from '@mastra/sentry'

export const mastra = new Mastra({
  observability: new Observability({
    configs: {
      sentry: {
        serviceName: 'my-service',
        exporters: [
          new SentryExporter({
            dsn: process.env.SENTRY_DSN!,
            environment: 'production',
            tracesSampleRate: 1.0, // Send 100% of transactions to Sentry
          }),
        ],
      },
    },
  }),
})
```

## 配置选项 {/* #configuration-options */}

### 完整配置 {/* #complete-configuration */}

```typescript
new SentryExporter({
  // Required settings
  dsn: process.env.SENTRY_DSN!, // Data Source Name - tells the SDK where to send events

  // Optional settings
  environment: 'production', // Deployment environment (enables filtering issues and alerts by environment)
  tracesSampleRate: 1.0, // Percentage of transactions sent to Sentry (0.0 = 0%, 1.0 = 100%)
  release: '1.0.0', // Version of your code deployed (helps identify regressions and track deployments)

  // Advanced Sentry options
  options: {
    // Any additional Sentry.NodeOptions
    integrations: [],
    beforeSend: event => event,
    // ... other Sentry SDK options
  },

  // Diagnostic logging
  logLevel: 'info', // debug | info | warn | error
})
```

### 采样配置 {/* #sampling-configuration */}

采样率决定发送到 Sentry 的事务占比。对于负载较高的应用，可以降低采样率。

```typescript
new SentryExporter({
  dsn: process.env.SENTRY_DSN!,
  tracesSampleRate: 0.1, // Send 10% of transactions to Sentry (recommended for high-load backends)
})
```

:::tip
开发时建议设为 `1.0`（100%）。生产环境中的高负载应用建议设为 `0.1` 到 `0.2`（10% 到 20%）。要完全关闭追踪，请省略 `tracesSampleRate`。将其设为 `0` 并不会完全关闭追踪。
:::

## Span 类型映射 {/* #span-type-mapping */}

Mastra 会自动将 Span 类型映射到对应的 Sentry 操作。

| Mastra SpanType | Sentry 操作 | 说明 |
| - | - | - |
| `AGENT_RUN` | `gen_ai.invoke_agent` | 包含子 Span MODEL\_GENERATION 的 token 用量 |
| `MODEL_GENERATION` | `gen_ai.chat` | 包含用量统计和流式传输数据 |
| `MODEL_STEP` | *（跳过）* | 跳过此类型以简化 Trace 层级 |
| `MODEL_CHUNK` | *（跳过）* | 数据汇总到 MODEL\_GENERATION 中 |
| `TOOL_CALL` | `gen_ai.execute_tool` | 记录 Tool 执行情况及其输入和输出 |
| `MCP_TOOL_CALL` | `gen_ai.execute_tool` | 记录 MCP Tool 执行情况 |
| `WORKFLOW_RUN` | `workflow.run` | |
| `WORKFLOW_STEP` | `workflow.step` | |
| `WORKFLOW_CONDITIONAL` | `workflow.conditional` | |
| `WORKFLOW_CONDITIONAL_EVAL` | `workflow.conditional` | |
| `WORKFLOW_PARALLEL` | `workflow.parallel` | |
| `WORKFLOW_LOOP` | `workflow.loop` | |
| `WORKFLOW_SLEEP` | `workflow.sleep` | |
| `WORKFLOW_WAIT_EVENT` | `workflow.wait` | |
| `PROCESSOR_RUN` | `ai.processor` | |
| `GENERIC` | `ai.span` | |

## OpenTelemetry 语义约定 {/* #opentelemetry-semantic-conventions */}

导出器遵循标准 GenAI 语义约定，并使用 Sentry 专用属性。

**MODEL\_GENERATION Span**

- `gen_ai.system`：模型提供商，例如 `openai` 或 `anthropic`
- `gen_ai.request.model`：请求的模型标识符，例如 `gpt-5.4`
- `gen_ai.response.model`：生成响应所用的模型
- `gen_ai.response.text`：响应中的文本
- `gen_ai.response.tool_calls`：生成过程中发起的 Tool 调用（JSON 数组）
- `gen_ai.usage.input_tokens`：输入 token 数量
- `gen_ai.usage.output_tokens`：输出 token 数量
- `gen_ai.request.temperature`：温度参数
- `gen_ai.request.stream`：请求是否启用流式传输
- `gen_ai.request.messages`：输入消息或提示词（JSON）
- `gen_ai.completion_start_time`：收到首个 token 的时刻

**TOOL\_CALL Span**

- `gen_ai.tool.name`：Tool 标识符
- `gen_ai.tool.type`：`function`
- `gen_ai.tool.call.id`：Tool 调用 ID
- `gen_ai.tool.input`：Tool 输入（JSON）
- `gen_ai.tool.output`：Tool 输出（JSON）
- `tool.success`：Tool 调用是否成功

**AGENT\_RUN Span**

- `gen_ai.agent.name`：Agent 标识符
- `gen_ai.pipeline.name`：Agent 名称（用于 Sentry AI 视图）
- `gen_ai.agent.instructions`：Agent 指令
- `gen_ai.response.model`：子 Span 中记录的生成模型
- `gen_ai.response.text`：子 Span 中记录的生成文本
- `gen_ai.usage.*`：子 Span 中记录的 token 用量

## 功能 {/* #features */}

- **Trace 层级**。保留 Span 之间的父子关系。
- **Token 用量追踪**。自动记录模型生成时的 token 用量。
- **Tool 调用追踪**。记录 Tool 执行情况及其输入和输出。
- **流式响应支持**。汇总流式返回的数据。
- **错误追踪**。自动记录错误状态并捕获异常。
- **Workflow 支持**。追踪 Workflow 的执行步骤。
- **简化 Trace 层级**。跳过 MODEL\_STEP 和 MODEL\_CHUNK Span，减少多余的追踪条目。
