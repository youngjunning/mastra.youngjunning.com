# Datadog

[Datadog](https://datadoghq.com/) 是功能全面的监控平台，提供专门的 LLM Observability 功能。Mastra 通过导出器发送已完成的跟踪数据，也可以通过桥接器实时集成 `dd-trace` 上下文。

## 导出器 {/* #exporter */}

Datadog 导出器将跟踪数据发送到 Datadog LLM Observability，帮助你了解模型性能、Token 用量和对话流程。

### 安装 {/* #installation */}

```bash npm2yarn
npm install @mastra/datadog@latest
```

### 配置 {/* #configuration */}

#### 前提条件 {/* #prerequisites */}

1. **Datadog 账户**：在 [datadoghq.com](https://datadoghq.com/) 注册，并启用 LLM Observability
2. **API 密钥**：在 Datadog 的 Organization Settings → API Keys 中获取 API 密钥
3. **环境变量**：设置凭据

```bash title=".env"
DD_API_KEY=your-datadog-api-key
DD_LLMOBS_ML_APP=my-llm-app
DD_SITE=datadoghq.com  # Optional: defaults to datadoghq.com
DD_ENV=production      # Optional: environment name
```

#### 零配置设置 {/* #zero-config-setup */}

设置环境变量后，无需传入配置即可使用导出器：

```typescript title="src/mastra/index.ts"
import { Mastra } from '@mastra/core'
import { Observability } from '@mastra/observability'
import { DatadogExporter } from '@mastra/datadog'

export const mastra = new Mastra({
  observability: new Observability({
    configs: {
      datadog: {
        serviceName: 'my-service',
        exporters: [new DatadogExporter()],
      },
    },
  }),
})
```

#### 显式配置 {/* #explicit-configuration */}

也可以直接传入凭据；直接传入的值优先于环境变量：

```typescript title="src/mastra/index.ts"
import { Mastra } from '@mastra/core'
import { Observability } from '@mastra/observability'
import { DatadogExporter } from '@mastra/datadog'

export const mastra = new Mastra({
  observability: new Observability({
    configs: {
      datadog: {
        serviceName: 'my-service',
        exporters: [
          new DatadogExporter({
            mlApp: process.env.DD_LLMOBS_ML_APP!,
            apiKey: process.env.DD_API_KEY!,
          }),
        ],
      },
    },
  }),
})
```

### 配置选项 {/* #configuration-options */}

#### 完整配置 {/* #complete-configuration */}

```typescript
new DatadogExporter({
  // Required settings
  mlApp: process.env.DD_LLMOBS_ML_APP!, // Groups traces under this ML app name
  apiKey: process.env.DD_API_KEY!, // Required for agentless mode (default)

  // Optional settings
  site: 'datadoghq.com', // Datadog site (datadoghq.eu, us3.datadoghq.com, etc.)
  service: 'my-service', // Service name (defaults to mlApp)
  env: 'production', // Environment name
  agentless: true, // true = direct HTTPS, false = local Datadog Agent

  // Advanced settings
  integrationsEnabled: false, // Enable dd-trace auto-instrumentation

  // Diagnostic logging
  logLevel: 'info', // debug | info | warn | error
})
```

#### 使用本地 Datadog Agent {/* #with-local-datadog-agent */}

如果本地运行着 Datadog Agent，可以通过它转发跟踪数据，而无需直接通过 HTTPS 发送：

```typescript
new DatadogExporter({
  mlApp: process.env.DD_LLMOBS_ML_APP!,
  agentless: false, // Use local Datadog Agent
  env: 'production',
})
```

注意：使用 Agent 模式时，API 密钥从本地 Datadog Agent 的配置中读取。

### Span 类型映射 {/* #span-type-mapping */}

Mastra 的 Span 类型会自动映射为 Datadog LLM Observability 的 Span 种类：

| Mastra SpanType | Datadog 种类 |
| - | - |
|`AGENT_RUN` | `agent` |
| `MODEL_GENERATION` | `workflow` |
| `MODEL_STEP` | `llm` |
| `TOOL_CALL` | `tool` |
| `MCP_TOOL_CALL` | `tool` |
| `WORKFLOW_RUN` | `workflow` |
| 其他 Workflow 类型 | `task` |
| `GENERIC` | `task` |

除非另有指定，其他或未来新增的 Mastra Span 类型默认映射为 `task`。

### 应用程序性能监控 {/* #application-performance-monitoring */}

以上内容介绍了 Mastra 与 [LLM Observability](https://docs.datadoghq.com/llm_observability/) 的集成。若要跟踪 Mastra HTTP 服务器路由的请求延迟、错误和服务拓扑，请直接使用 `dd-trace` 接入 Datadog Application Performance Monitoring（APM）。

#### APM 前提条件 {/* #apm-prerequisites */}

1. **Datadog Agent**：在同一主机上，或在网络可访问的位置安装 [Datadog Agent](https://docs.datadoghq.com/agent/)。它在 `localhost:8126` 接收来自 `dd-trace` 的跟踪数据，并转发给 Datadog。请按照 [Agent 安装指南](https://docs.datadoghq.com/agent/) 完成设置。
2. **dd-trace 包**：在项目中安装跟踪库：

   ```bash npm2yarn
   npm install dd-trace
   ```

:::note
APM 跟踪数据始终通过 Datadog Agent 发送。LLM Observability 还支持无 Agent 模式，可直接通过 HTTPS 发送到 Datadog。
:::

#### 仅 APM {/* #apm-only */}

在入口文件顶部、其他任何导入语句之前导入并初始化 `dd-trace`：

```typescript title="src/mastra/index.ts"
import tracer from 'dd-trace'

tracer.init({
  service: process.env.DD_SERVICE || 'my-mastra-app',
  env: process.env.DD_ENV || 'production',
  version: process.env.DD_VERSION,
})

import { Mastra } from '@mastra/core'

export const mastra = new Mastra({
  bundler: {
    externals: [
      'dd-trace',
      '@datadog/native-metrics',
      '@datadog/native-appsec',
      '@datadog/native-iast-taint-tracking',
      '@datadog/pprof',
    ],
  },
})
```

设置跟踪器元数据环境变量：

```bash title=".env"
DD_SERVICE=my-mastra-app
DD_ENV=production
DD_VERSION=1.0.0
```

`dd-trace` 会自动为常用 HTTP 框架添加跟踪支持，包括 Mastra 支持的[服务器适配器](/docs/server/server-adapters)。入站请求、出站 HTTP 调用和数据库查询都会作为 APM 跟踪数据显示在 Datadog 中。

#### APM 和 LLM Observability {/* #apm-and-llm-observability */}

创建 Mastra 实例前，先导入并初始化 `dd-trace`。`DatadogExporter` 会检测现有的 tracer，跳过重复初始化，并在 APM 配置的基础上添加 LLM Observability：

```typescript title="src/mastra/index.ts"
import tracer from 'dd-trace'

tracer.init({
  service: process.env.DD_SERVICE || 'my-mastra-app',
  env: process.env.DD_ENV || 'production',
  version: process.env.DD_VERSION,
})

import { Mastra } from '@mastra/core'
import { Observability } from '@mastra/observability'
import { DatadogExporter } from '@mastra/datadog'

export const mastra = new Mastra({
  observability: new Observability({
    configs: {
      datadog: {
        serviceName: 'my-mastra-app',
        exporters: [
          new DatadogExporter({
            mlApp: process.env.DD_LLMOBS_ML_APP!,
            apiKey: process.env.DD_API_KEY!,
          }),
        ],
      },
    },
  }),
  bundler: {
    externals: [
      'dd-trace',
      '@datadog/native-metrics',
      '@datadog/native-appsec',
      '@datadog/native-iast-taint-tracking',
      '@datadog/pprof',
    ],
  },
})
```

```bash title=".env"
DD_SERVICE=my-mastra-app
DD_ENV=production
DD_VERSION=1.0.0
DD_API_KEY=your-datadog-api-key
DD_LLMOBS_ML_APP=my-llm-app
```

服务器路由显示为 APM 跟踪数据，LLM 调用显示为 LLM Observability Span；两者在 Datadog 中归属同一服务。

:::note
务必在其他所有模块之前导入并初始化 `dd-trace`，以便它在加载时为 HTTP、数据库和框架库添加自动跟踪支持。
:::

### 故障排除 {/* #troubleshooting */}

#### 本机模块 ABI 不匹配 {/* #native-module-abi-mismatch */}

如果您看到类似以下错误：

```text
Error: No native build was found for runtime=node abi=137 platform=linuxglibc arch=x64
```

这表明当前 Node.js 版本与 `dd-trace` 的原生模块存在兼容性问题。这些原生模块是**可选的**，用于提供性能监控功能。

**解决方案：**

1. **使用 Node.js 22.x**：原生模块与 Node.js 22.x 的兼容性最好。

2. **忽略原生模块警告**：`@datadog/native-metrics`、`@datadog/native-appsec` 等原生模块是可选的。即使加载失败，核心跟踪功能仍可正常工作。

#### 打包器的外部依赖配置 {/* #bundler-externals-configuration */}

使用 esbuild、webpack 或 Mastra CLI 打包器时，可能需要将 `dd-trace` 及其依赖标记为外部依赖：

```typescript title="src/mastra/index.ts"
import { Mastra } from '@mastra/core'

export const mastra = new Mastra({
  bundler: {
    externals: [
      'dd-trace',
      '@datadog/native-metrics',
      '@datadog/native-appsec',
      '@datadog/native-iast-taint-tracking',
      '@datadog/pprof',
    ],
  },
})
```

## 桥接器 {/* #bridge */}

:::warning

Datadog Bridge 目前仍处于**实验阶段**。其 API 和配置选项可能在未来版本中变化。

:::

Datadog Bridge 在 Mastra 跟踪系统与 Datadog 之间建立双向集成。导出器在执行完成后发送跟踪数据；Bridge 则实时创建原生 `dd-trace` Span，使 Tool 和处理器中的自动跟踪 APM 操作（如 HTTP 调用和数据库查询）正确归入其父 Mastra Span。

### 何时使用 Bridge {/* #when-to-use-the-bridge */}

以下情况适合使用 `DatadogBridge`：

* 应用中使用 `dd-trace` 自动跟踪 HTTP 服务器、数据库客户端等
* 希望 Tool、MCP Tool 或输出处理器发起的 APM 服务调用归入相应的父 Mastra Span，而非请求处理程序
* 需要让 APM 跟踪数据与 LLM Observability 数据共享一致的跟踪拓扑
* 构建需要跨服务传播 Datadog 跟踪上下文的分布式系统

### 它是如何运作的 {/* #how-it-works */}

`DatadogBridge` 参与 `dd-trace` 流程的两个环节：

**APM 上下文传播（实时）：**

* 创建每个 Mastra Span 时，通过 `tracer.startSpan()` 创建对应的 `dd-trace` APM Span
* 执行期间，通过 `tracer.scope().activate()` 在 `dd-trace` 的作用域中激活该 APM Span
* 活动作用域中的自动跟踪操作以正确的 Mastra Span 为父级
* 如果没有明确的 Mastra 父 Span，则继承当前活动的 `dd-trace` 上下文，例如入站请求 Span

**LLM Observability 数据发送（Span 结束时）：**

* 通过 `dd-trace` 的 LLM Observability 流程发送标注，包括模型信息、Token 用量、输入输出和错误
* 通过嵌套的 `llmobs.trace()` 调用维护 Datadog LLM Observability 中的父子关系
* 复用与 [Datadog Exporter](#span-type-mapping) 相同的数据结构和 Span 类型映射

### 跟踪和日志关联 {/* #trace-and-log-correlation */}

如果没有 Bridge，Datadog Exporter 只会在跟踪完成后创建 LLM Observability Span。执行期间，作用域中没有对应的 `dd-trace` Span，因此 Tool 发起的 HTTP 或数据库调用会归入当时活动的 `dd-trace` Span，通常是入站请求处理程序。这样，MCP Tool 或输出处理器发起的服务调用就会显示为请求 Span 的子级，而不是实际发起调用的 Agent 或处理器 Span 的子级。

Bridge 会提前创建真实的 `dd-trace` Span，使自动跟踪运行时的作用域保持正确。

### 安装 {/* #installation-1 */}

```bash npm2yarn
npm install @mastra/datadog dd-trace
```

Bridge 需要安装 `dd-trace`，并通过本地 Datadog Agent（或兼容的 OTLP 接收器）接收 APM 数据。Agent 的设置方法请参阅 [APM 前提条件](#apm-prerequisites)。

### 配置 {/* #configuration-1 */}

使用 `DatadogBridge` 需要完成两步：

1. 初始化 `dd-trace`，使其自动跟踪功能能够为 HTTP、数据库和框架库添加支持
2. 在 Mastra 的可观测性配置中添加 `DatadogBridge`

#### 第 1 步：初始化 dd-trace {/* #step-1-initialize-dd-trace */}

必须在导入其他模块之前初始化 `dd-trace`，以便它在加载时为库添加自动跟踪支持。Bridge 会检测并复用已初始化的 tracer。

```typescript title="src/mastra/index.ts"
import tracer from 'dd-trace'

tracer.init({
  service: process.env.DD_SERVICE || 'my-mastra-app',
  env: process.env.DD_ENV || 'production',
  version: process.env.DD_VERSION,
})

import { Mastra } from '@mastra/core'
import { Observability } from '@mastra/observability'
import { DatadogBridge } from '@mastra/datadog'

// ...
```

:::note
在应用入口文件的最顶部、其他任何导入语句之前导入并初始化 `dd-trace`。
:::

#### 第 2 步：配置 Mastra {/* #step-2-mastra-configuration */}

在 Mastra 的可观测性配置中添加 `DatadogBridge`：

```typescript title="src/mastra/index.ts"
import { Mastra } from '@mastra/core'
import { Observability } from '@mastra/observability'

export const mastra = new Mastra({
  observability: new Observability({
    configs: {
      default: {
        serviceName: 'my-mastra-app',
        bridge: new DatadogBridge({
          mlApp: process.env.DD_LLMOBS_ML_APP!,
        }),
      },
    },
  }),
  bundler: {
    externals: [
      'dd-trace',
      '@datadog/native-metrics',
      '@datadog/native-appsec',
      '@datadog/native-iast-taint-tracking',
      '@datadog/pprof',
    ],
  },
})
```

```bash title=".env"
DD_SERVICE=my-mastra-app
DD_ENV=production
DD_VERSION=1.0.0
DD_LLMOBS_ML_APP=my-llm-app
```

初始化 `dd-trace` 后，APM 数据会发送到 `localhost:8126` 上的本地 Datadog Agent。Bridge 在同一个 tracer 上启用 LLM Observability，因此两类数据会在 Datadog 中归属同一服务。

使用 Bridge 时无需配置 Mastra 导出器；APM 和 LLM Observability 数据都通过 `dd-trace` 发送。如果还想将跟踪数据发送到其他目标，也可以添加 Mastra 导出器。

### Agent 模式与无 Agent 模式 {/* #agent-vs-agentless-mode */}

Bridge 默认使用 **Agent 模式**（`agentless: false`），假定本地 Datadog Agent 在 `localhost:8126` 运行并接收 APM 和 LLM Observability 数据。使用 `dd-trace` 自动跟踪时通常采用此配置，因为 APM 数据始终通过 Agent 发送。

如果没有本地 Datadog Agent，且只需要 LLM Observability 数据（不使用 APM 自动跟踪），可以启用无 Agent 模式，直接向 Datadog 发送数据。此时必须提供 API 密钥。

```typescript
new DatadogBridge({
  mlApp: process.env.DD_LLMOBS_ML_APP!,
  apiKey: process.env.DD_API_KEY!,
  agentless: true,
})
```

:::note
对于大多数 Bridge 用户，Agent 模式更合适。无 Agent 模式无法发送 APM 数据，因此启用后 LLM Observability 流量会与 APM 流量分开。如果只需 LLM Observability 且不使用 Agent，请改用 [Datadog Exporter](#exporter)。
:::

### 跟踪层次结构 {/* #trace-hierarchy */}

使用 `DatadogBridge` 后，跟踪数据在 `dd-trace` 与 Mastra 之间保持正确的层级关系。Tool 和处理器发起的服务调用会归入相应的 Mastra Span：

```text
HTTP POST /api/chat (from web framework instrumentation)
└── agent.orchestrator (from Mastra via DatadogBridge)
    ├── chat gpt-5.4 (LLM call)
    ├── tool.execute search (tool execution)
    │   └── HTTP GET api.example.com (auto-instrumented from inside the tool)
    └── processor.guardrail (output processor)
        └── HTTP POST guardrail-service/check (auto-instrumented from inside the processor)
```

在 Datadog 中，APM 跟踪数据展示完整拓扑；LLM Observability 展示 Agent 和 LLM 专属 Span，以及其输入、输出和 Token 指标。

### 跨度类型映射 {/* #span-type-mapping-1 */}

Bridge 为 LLM Observability 使用与 Datadog Exporter 相同的 Span 种类映射。参阅导出器章节中的 [Span 类型映射](#span-type-mapping)。

### 使用标签 {/* #using-tags */}

标签有助于在 Datadog 中分类和过滤跟踪数据。执行 Agent 或 Workflow 时可添加标签：

```typescript
const result = await agent.generate('Hello', {
  tracingOptions: {
    tags: ['production', 'experiment-v2', 'user-request'],
  },
})
```

采用 `key:value` 格式的标签（例如 `instance_name:career-scout-api`）会拆分为结构化标签项。不含冒号的标签，其值会设为 `true`。

### 将上下文键提升为平面标签 {/* #promoting-context-keys-to-flat-tags */}

使用 `requestContextKeys`，可将请求上下文或 Span 属性中的指定键提升为扁平、可索引的 LLM Observability 标签，以便在 Datadog 界面中过滤：

```typescript
new DatadogBridge({
  mlApp: process.env.DD_LLMOBS_ML_APP!,
  requestContextKeys: ['tenantId', 'agentId'],
})
```

提升后的键会从 `annotations.metadata` 中移除，并作为扁平标签添加到每个 LLM Observability Span。

### 故障排除 {/* #troubleshooting-1 */}

如果 APM Span 未按预期连接到 Mastra Span：

* 确认 `dd-trace` 在其他任何导入语句**之前**初始化（它需要在加载时为库添加跟踪支持）
* 确认本地 Datadog Agent 正在运行，并且可以访问 `localhost:8126`
* 确认在可观测性配置中将 `DatadogBridge` 设为 `bridge`，而非放入 `exporters`
* 确认没有同时将 `DatadogExporter` 加入 `exporters`；同时使用两者会重复发送 LLM Observability 数据

有关 `dd-trace` 原生模块兼容性和打包器外部依赖配置的问题，请参阅 [Datadog 导出器故障排除](#troubleshooting)。
