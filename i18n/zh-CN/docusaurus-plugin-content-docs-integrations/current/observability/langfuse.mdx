# Langfuse

[Langfuse](https://langfuse.com/) 是专为 LLM 应用设计的开源可观测性平台。Langfuse 导出器将 Trace 发送到 Langfuse，方便你详细查看模型性能、token 用量和对话流程。

## 安装 {/* #installation */}

```bash npm2yarn
npm install @mastra/langfuse@latest
```

## 配置 {/* #configuration */}

### 准备工作 {/* #prerequisites */}

1. **Langfuse 账号**：在 [cloud.langfuse.com](https://cloud.langfuse.com) 注册，或自行部署 Langfuse。
2. **API 密钥**：在 Langfuse 的 Settings → API Keys 中创建一对公钥和密钥。
3. **环境变量**：通过环境变量设置凭据。

```bash title=".env"
LANGFUSE_PUBLIC_KEY=pk-lf-xxxxxxxxxxxx
LANGFUSE_SECRET_KEY=sk-lf-xxxxxxxxxxxx
LANGFUSE_BASE_URL=https://cloud.langfuse.com  # Or your self-hosted URL
```

### 从环境变量读取配置 {/* #zero-config-setup */}

设置环境变量后，可以直接实例化导出器，无需传入配置：

```typescript title="src/mastra/index.ts"
import { Mastra } from '@mastra/core'
import { Observability } from '@mastra/observability'
import { LangfuseExporter } from '@mastra/langfuse'

export const mastra = new Mastra({
  observability: new Observability({
    configs: {
      langfuse: {
        serviceName: 'my-service',
        exporters: [new LangfuseExporter()],
      },
    },
  }),
})
```

### 显式配置 {/* #explicit-configuration */}

也可以直接传入凭据。传入的值优先于环境变量：

```typescript title="src/mastra/index.ts"
import { Mastra } from '@mastra/core'
import { Observability } from '@mastra/observability'
import { LangfuseExporter } from '@mastra/langfuse'

export const mastra = new Mastra({
  observability: new Observability({
    configs: {
      langfuse: {
        serviceName: 'my-service',
        exporters: [
          new LangfuseExporter({
            publicKey: process.env.LANGFUSE_PUBLIC_KEY!,
            secretKey: process.env.LANGFUSE_SECRET_KEY!,
            baseUrl: process.env.LANGFUSE_BASE_URL,
            environment: process.env.NODE_ENV,
            release: process.env.GIT_COMMIT,
          }),
        ],
      },
    },
  }),
})
```

## 配置选项 {/* #configuration-options */}

### 实时与批处理模式 {/* #realtime-vs-batch-mode */}

Langfuse 导出器有两种发送 Trace 的模式：

#### 实时模式（开发） {/* #realtime-mode-development */}

Trace 会立即显示在 Langfuse 仪表板上，便于调试：

```typescript
new LangfuseExporter({
  publicKey: process.env.LANGFUSE_PUBLIC_KEY!,
  secretKey: process.env.LANGFUSE_SECRET_KEY!,
  realtime: true, // Flush after each event
})
```

#### 批处理模式（生产） {/* #batch-mode-production */}

自动合并发送批次，以提高性能：

```typescript
new LangfuseExporter({
  publicKey: process.env.LANGFUSE_PUBLIC_KEY!,
  secretKey: process.env.LANGFUSE_SECRET_KEY!,
  realtime: false, // Default - batch traces
})
```

#### 调整高流量场景下的批处理参数 {/* #batch-tuning-for-high-volume-traces */}

如果你自行部署了 Langfuse，或流式运行每秒产生大量 span，可以调整 OTEL 的批次大小和发送间隔，以减轻 Langfuse 数据接收端点的请求压力：

```typescript
new LangfuseExporter({
  publicKey: process.env.LANGFUSE_PUBLIC_KEY!,
  secretKey: process.env.LANGFUSE_SECRET_KEY!,
  flushAt: 500, // Maximum spans per OTEL export batch
  flushInterval: 20, // Maximum seconds between flushes
})
```

要完全排除产生量大的 span 类型，例如流式响应中的 `MODEL_CHUNK`，请在可观测性配置中设置 [`excludeSpanTypes` 选项](/reference/observability/tracing/span-filtering)：

```typescript
import { SpanType } from '@mastra/core/observability'

new Observability({
  configs: {
    langfuse: {
      serviceName: 'my-service',
      exporters: [new LangfuseExporter()],
      excludeSpanTypes: [SpanType.MODEL_CHUNK],
    },
  },
})
```

### 完整配置 {/* #complete-configuration */}

```typescript
new LangfuseExporter({
  // Required credentials
  publicKey: process.env.LANGFUSE_PUBLIC_KEY!,
  secretKey: process.env.LANGFUSE_SECRET_KEY!,

  // Optional settings
  baseUrl: process.env.LANGFUSE_BASE_URL, // Default: https://cloud.langfuse.com
  realtime: process.env.NODE_ENV === 'development', // Dynamic mode selection
  flushAt: 500, // Maximum spans per OTEL export batch
  flushInterval: 20, // Maximum seconds between flushes
  logLevel: 'info', // Diagnostic logging: debug | info | warn | error

  // Langfuse-specific settings
  environment: process.env.NODE_ENV, // Shows in Langfuse UI for filtering
  release: process.env.GIT_COMMIT, // Git commit hash for version tracking
})
```

## 按 Agent 限定评估范围 {/* #scoping-evaluators-per-agent */}

通过筛选条件，可以让 Langfuse 评估器（如 LLM-as-a-Judge）只评估特定 Trace。Mastra 的 Langfuse 导出器会自动将每条 Trace 关联到发起运行的 Agent 或 Workflow，使 Trace 级筛选条件匹配到对应的运行。

对于根 span 为 `AGENT_RUN` 的 Trace，导出器会设置以下字段：

* `langfuse.trace.name`：Agent 名称。未设置名称时使用 Agent ID。
* `langfuse.trace.metadata.agentId`：Agent ID。
* `langfuse.trace.metadata.agentName`：Agent 名称。

根 span 为 `WORKFLOW_RUN` 时也采用同样的机制，导出器会设置 `langfuse.trace.metadata.workflowId` 和 `langfuse.trace.metadata.workflowName`。

要让评估器只评估指定的 Agent，请在 Langfuse 中选用以下任一筛选条件：

* **Trace name（Trace 名称）**：等于 Agent 名称，例如 `weather-agent`。
* **Metadata（元数据）**：`agentId` 等于 Agent ID。

Langfuse 评估器的 Trace 名称下拉列表会列出已出现的不同名称。Agent 至少生成一条 Trace 后，列表中就会出现对应的选项。

如果通过 `mastra.metadata.traceName` 自定义了 `traceName`，自定义值优先于默认的 Agent 名称。

通过 `tracingOptions.nestUnderParent` 启动的运行归属于已有 Trace。导出器不会用该运行的名称、输入、输出、元数据、用户或会话来设置 Trace 对应的字段。参见[将运行嵌套到先前的 Mastra 运行下](/docs/observability/tracing/overview#nesting-a-run-under-an-earlier-mastra-run)。

## 按 span 属性筛选观测记录 {/* #filtering-observations-by-span-attributes */}

Langfuse 的观测级评估器使用观测记录的顶层元数据进行筛选。对于 OpenTelemetry 导出器以 `mastra.<span_type>.<key>` 写入的每个标量 span 属性（字符串、数字或布尔值），Langfuse 导出器都会将其提升到 `langfuse.observation.metadata.<key>`，并将键名转换为 camelCase。导出器还会为每条观测记录设置 `agentId`、`agentName`、`spanType` 和 `operationName`。

对于 `MODEL_STEP` span，这会生成 `stepIndex` 和 `isContinued`。要对每次 Agent 运行只评估一次，且只评估生成最终答案的步骤，请为观测级评估器设置两个筛选条件：`spanType` 等于 `model_step`，且 `isContinued` 等于 `"false"`。

这些值以字符串形式发送，因此请使用 `"false"` 或 `"1"` 等字符串进行比较。span 的输入和输出仍按各自的规则映射，值为对象或数组的属性仅保留在嵌套的 `attributes` 元数据中。

## 自定义 Trace 元数据 {/* #custom-trace-metadata */}

Langfuse 只支持按顶层元数据筛选和分组 Trace。嵌套的元数据键不参与筛选或分组。

要添加自定义顶层元数据，请在 span 元数据的 `langfuse` 下设置相应的键。导出器会将每个键转发到 `langfuse.trace.metadata.<key>`，供 Langfuse 筛选：

```typescript
const tracingOptions = {
  metadata: {
    langfuse: {
      customerId: 'cust_123',
      tier: 'enterprise',
    },
  },
}
```

此示例会生成 `langfuse.trace.metadata.customerId` 和 `langfuse.trace.metadata.tier`。

导出器也会转发根 span 的元数据。Mastra 会在每个 Agent 和 Workflow 的根 span 上设置 `runId` 和 `resourceId`。你可以通过 `tracingOptions.metadata` 添加自定义键。导出器会将这些根 span 的键转发到 `langfuse.trace.metadata.<key>`。映射到 Langfuse 专用字段的键（`userId`、`sessionId`、`threadId`、`traceName` 和 `version`）不会重复写入 Trace 元数据。子 span 的其他元数据仍保留在对应的观测记录上。会话 ID 等专用字段遵循各自的映射规则。

注意事项：

* 保留键 `prompt` 用于[关联提示词](#prompt-linking)，不会作为 Trace 元数据转发。
* `agentId`、`agentName`、`workflowId` 和 `workflowName` 是保留的标识键，其值取自根 span，优先于同名的自定义值。
* `langfuse` 下的键优先于根 span 元数据中的同名键。
* Langfuse 将 Trace 元数据属性映射为字符串，因此导出器以字符串形式发送这些值。数字、布尔值和对象会经过 JSON 序列化。Langfuse Cloud 接收数据时会将它们还原为原始类型。

## 对话会话 {/* #conversation-sessions */}

导出器根据 span 元数据中的 `sessionId` 将 span 关联到 Langfuse 会话。如果缺少 `sessionId` 或其值为 `null`，则改用 `threadId`。如果显式将 `sessionId` 设为空字符串，导出器会跳过回退逻辑，不发送会话 ID。

使用 [Observational Memory](/docs/memory/observational-memory) 时，即使子 span 先于父 span 到达，Langfuse 导出器仍会将 observer 和 reflector 的 span 保留在调用方的会话中。显式设置的 `sessionId` 优先，包括空字符串。未显式设置时，导出器优先使用 Observational Memory 携带的原始调用方线程标识，再回退到 span 自身的 `threadId`。Observational Memory 从调用方 span 的非空 `threadId` 获取调用方标识，否则使用原始请求的线程 ID。嵌套观测会保留外层调用方的标识。

这种从线程 ID 回退到会话映射的机制是 Langfuse 导出器特有的。Observational Memory 不会为其他导出器根据线程 ID 生成通用的 `sessionId` 元数据。

observer 和 reflector 的内部执行线程各自独立。多线程观测以发起调用的一方的会话为准，批次中第一个线程的会话不参与选择。无论如何设置 `bufferOnIdle`，会话归属规则都适用，缓冲行为和 span 的父子关系也不会因此改变。

## 成本追踪 {/* #cost-tracking */}

只有当模型生成的成本元数据满足以下所有条件时，导出器才会将 Provider 报告的成本转发到 Langfuse 的 `cost_details` 字段：

* 该 span 是模型生成 span。
* `costContext.costMetadata.source` 为 `'provider_reported'`。
* `costContext.costUnit` 为 `'USD'`。
* `costContext.estimatedCost` 是有限的非负数。

导出器会跳过预估成本，让 Langfuse 按自己的定价模型计算。如果 Langfuse 中的生成记录缺少成本，请检查 Provider 是否报告成本。如果 Provider 未报告成本，请在 Langfuse 中配置模型价格。

具体规则见 [`LangfuseExporter` 参考文档](/reference/observability/tracing/exporters/langfuse#cost-tracking)。

## 关联提示词 {/* #prompt-linking */}

你可以将 LLM 生成记录与存储在 [Langfuse Prompt Management](https://langfuse.com/docs/prompt-management) 中的提示词关联，以追踪提示词版本并查看相关指标。

### 使用辅助函数（推荐） {/* #using-the-helper-recommended */}

将 `withLangfusePrompt` 与 `buildTracingOptions` 搭配使用，可以简化配置：

```typescript title="src/agents/support-agent.ts"
import { Agent } from '@mastra/core/agent'
import { buildTracingOptions } from '@mastra/observability'
import { LangfuseExporter, withLangfusePrompt } from '@mastra/langfuse'

const exporter = new LangfuseExporter()

// Fetch the prompt from Langfuse Prompt Management via the client
const prompt = await exporter.client.prompt.get('customer-support', { type: 'text' })

export const supportAgent = new Agent({
  id: 'support-agent',
  name: 'support-agent',
  instructions: prompt.compile(), // Use the prompt text from Langfuse
  model: '__GATEWAY_OPENAI_MODEL__',
  defaultGenerateOptions: {
    tracingOptions: buildTracingOptions(
      withLangfusePrompt({ name: prompt.name, version: prompt.version }),
    ),
  },
})
```

辅助函数 `withLangfusePrompt` 接收 `name` 和 `version` 字段，用于关联提示词。Langfuse v5 要求同时提供这两个字段。

### 手动传入字段 {/* #manual-fields */}

如果没有使用 Langfuse SDK，也可以手动传入字段：

```typescript
const tracingOptions = buildTracingOptions(withLangfusePrompt({ name: 'my-prompt', version: 1 }))
```

### 提示词对象字段 {/* #prompt-object-fields */}

提示词对象必须同时包含 `name` 和 `version`：

| 字段 | 类型 | 说明 |
| - | - | - |
| `name` | string | 提示词在 Langfuse 中的名称 |
| `version` | number | 提示词的版本号 |

在 `MODEL_GENERATION` span 上设置这些字段后，Langfuse 导出器会自动将生成记录关联到对应的提示词。

## 将现有 Trace 导入 Mastra Platform {/* #import-existing-traces-into-mastra-platform */}

Mastra CLI 可以从 Langfuse Cloud 或自行部署的 Langfuse v4 及更高版本实例导入历史 Trace 的观测记录。导入独立于本页介绍的导出器配置。有关凭据、试运行、恢复导入、验证和当前限制，请参阅[导入现有 Trace](/docs/mastra-platform/observability#import-existing-traces)。
