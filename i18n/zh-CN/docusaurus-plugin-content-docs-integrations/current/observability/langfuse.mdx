# 朗福斯

[朗福斯](https://langfuse.com/)是一个专门为LLM应用程序设计的开源可观测平台。 Langfuse 导出器将您的跟踪发送到 Langfuse，提供有关模型性能和令牌使用情况以及对话流的详细见解。

## 安装 {/* #installation */}

```bash npm2yarn
npm install @mastra/langfuse@latest
```

## 配置 {/* #configuration */}

### 先决条件 {/* #prerequisites */}

1. **浪熔账户**: 报名于[cloud.langfuse.com](https://cloud.langfuse.com) or deploy self-hosted
2. **API 密钥**：在 Langfuse 设置 → API 密钥中创建公钥/私钥对
3. **环境变量**：设置您的凭据

```bash title=".env"
LANGFUSE_PUBLIC_KEY=pk-lf-xxxxxxxxxxxx
LANGFUSE_SECRET_KEY=sk-lf-xxxxxxxxxxxx
LANGFUSE_BASE_URL=https://cloud.langfuse.com  # Or your self-hosted URL
```

### 零配置设置 {/* #zero-config-setup */}

设置环境变量后，无需配置即可使用导出器：

```typescript title="src/mastra/index.ts"
import { Mastra } from '@mastra/core'
import { Observability } from '@mastra/observability'
import { LangfuseExporter } from '@mastra/langfuse'

export const mastra = new Mastra({
  observability: new Observability({
    configs: {
      langfuse: {
        serviceName: 'my-service',
        exporters: [new LangfuseExporter()],
      },
    },
  }),
})
```

### 显式配置 {/* #explicit-configuration */}

您还可以直接传递凭据（优先于环境变量）：

```typescript title="src/mastra/index.ts"
import { Mastra } from '@mastra/core'
import { Observability } from '@mastra/observability'
import { LangfuseExporter } from '@mastra/langfuse'

export const mastra = new Mastra({
  observability: new Observability({
    configs: {
      langfuse: {
        serviceName: 'my-service',
        exporters: [
          new LangfuseExporter({
            publicKey: process.env.LANGFUSE_PUBLIC_KEY!,
            secretKey: process.env.LANGFUSE_SECRET_KEY!,
            baseUrl: process.env.LANGFUSE_BASE_URL,
            environment: process.env.NODE_ENV,
            release: process.env.GIT_COMMIT,
          }),
        ],
      },
    },
  }),
})
```

## 配置选项 {/* #configuration-options */}

### 实时与批处理模式 {/* #realtime-vs-batch-mode */}

Langfuse 导出器支持两种发送跟踪的模式：

#### 实时模式（开发） {/* #realtime-mode-development */}

跟踪立即出现在 Langfuse 仪表板中，非常适合调试：

```typescript
new LangfuseExporter({
  publicKey: process.env.LANGFUSE_PUBLIC_KEY!,
  secretKey: process.env.LANGFUSE_SECRET_KEY!,
  realtime: true, // Flush after each event
})
```

#### 批处理模式（生产） {/* #batch-mode-production */}

通过自动批处理获得更好的性能：

```typescript
new LangfuseExporter({
  publicKey: process.env.LANGFUSE_PUBLIC_KEY!,
  secretKey: process.env.LANGFUSE_SECRET_KEY!,
  realtime: false, // Default - batch traces
})
```

#### 大容量迹线的批量调整 {/* #batch-tuning-for-high-volume-traces */}

对于自托管 Langfuse 部署或每秒产生多个跨度的流式运行，您可以调整 OTEL 批量大小和刷新间隔，以减少 Langfuse 摄取端点上的请求压力：

```typescript
new LangfuseExporter({
  publicKey: process.env.LANGFUSE_PUBLIC_KEY!,
  secretKey: process.env.LANGFUSE_SECRET_KEY!,
  flushAt: 500, // Maximum spans per OTEL export batch
  flushInterval: 20, // Maximum seconds between flushes
})
```

完全抑制高容量跨度类型（例如`MODEL_CHUNK` spans from streamed responses), use the observability-level [`excludeSpanTypes` option](/reference/observability/tracing/span-filtering) rather than configuring the exporter:

```typescript
import { SpanType } from '@mastra/core/observability'

new Observability({
  configs: {
    langfuse: {
      serviceName: 'my-service',
      exporters: [new LangfuseExporter()],
      excludeSpanTypes: [SpanType.MODEL_CHUNK],
    },
  },
})
```

### 完整配置 {/* #complete-configuration */}

```typescript
new LangfuseExporter({
  // Required credentials
  publicKey: process.env.LANGFUSE_PUBLIC_KEY!,
  secretKey: process.env.LANGFUSE_SECRET_KEY!,

  // Optional settings
  baseUrl: process.env.LANGFUSE_BASE_URL, // Default: https://cloud.langfuse.com
  realtime: process.env.NODE_ENV === 'development', // Dynamic mode selection
  flushAt: 500, // Maximum spans per OTEL export batch
  flushInterval: 20, // Maximum seconds between flushes
  logLevel: 'info', // Diagnostic logging: debug | info | warn | error

  // Langfuse-specific settings
  environment: process.env.NODE_ENV, // Shows in Langfuse UI for filtering
  release: process.env.GIT_COMMIT, // Git commit hash for version tracking
})
```

## 每个Agent的范围评估员 {/* #scoping-evaluators-per-agent */}

Langfuse 评估器（例如 LLM-as-a-Judge）可以经过筛选，仅针对特定跟踪运行。 Mastra Langfuse 导出器自动将每个跟踪的范围限定为启动它的Agent或Workflow，因此跟踪级别过滤器解析为正确的运行。

对于根跨度为`AGENT_RUN`, the exporter sets:

* `langfuse.trace.name`：Agent名称（或 id，当未设置名称时）
* `langfuse.trace.metadata.agentId`: Agent ID
* `langfuse.trace.metadata.agentName`: Agent名称

这同样适用于`WORKFLOW_RUN` root spans, which set `langfuse.trace.metadata.workflowId` and `langfuse.trace.metadata.workflowName`.

要将评估器的范围限定为特定Agent，请在 Langfuse 中配置任一过滤器：

* **跟踪名称**: 等于Agent名称（例如，`weather-agent`).
* **元数据**: `agentId` equals the agent id.

Langfuse 评估器过滤器中的跟踪名称下拉列表列出了看到的每个不同值，因此每个Agent在生成至少一个跟踪后都会显示为自己的条目。

如果您设置了自定义`traceName` via `mastra.metadata.traceName`, your value takes precedence over the default agent name.

跑步开始于`tracingOptions.nestUnderParent` doesn't own the trace, so the exporter doesn't write the trace name, input, output, metadata, user, or session from it. See [Nesting a run under an earlier Mastra run](/docs/observability/tracing/overview#nesting-a-run-under-an-earlier-mastra-run).

## 按跨度属性过滤观测值 {/* #filtering-observations-by-span-attributes */}

Langfuse 中的观察级评估器对顶级观察元数据进行过滤。导出器提升 OpenTelemetry 导出器写入的每个标量跨度属性（字符串、数字或布尔值）`mastra.<span_type>.<key>` to `langfuse.observation.metadata.<key>`, with the key converted to camelCase. The exporter also sets `agentId`, `agentName`, `spanType`, and `operationName` on each observation.

对于一个`MODEL_STEP` span this produces `stepIndex` and `isContinued`. To judge each agent run once, against the step that produced the final answer, filter an observation-level evaluator on `spanType` equals `model_step` and `isContinued` equals `"false"`.

值作为字符串发送，因此请与字符串值进行比较，例如`"false"` or `"1"`. Span input and output keep their own mapping, and attributes that hold objects or arrays stay in the nested `attributes` metadata only.

## 自定义跟踪元数据 {/* #custom-trace-metadata */}

Langfuse 仅按顶级元数据对跟踪进行过滤和分组。嵌套元数据键不能用于过滤或分组。

要添加您自己的顶级元数据，请在下面设置键`langfuse` in your span metadata. The exporter forwards each key to `langfuse.trace.metadata.<key>`, where it becomes filterable in Langfuse:

```typescript
const tracingOptions = {
  metadata: {
    langfuse: {
      customerId: 'cust_123',
      tier: 'enterprise',
    },
  },
}
```

这个例子产生`langfuse.trace.metadata.customerId` and `langfuse.trace.metadata.tier`.

根跨度上的元数据也会被转发。马斯特拉套装`runId` and `resourceId` on every agent and workflow root span, and you can add your own keys through `tracingOptions.metadata`. The exporter forwards each of these root span keys to `langfuse.trace.metadata.<key>`. Keys that map to a dedicated Langfuse field (`userId`, `sessionId`, `threadId`, `traceName`, and `version`) are not duplicated as trace metadata. Other metadata on child spans stays on the observation. Dedicated fields such as session IDs follow their own mapping rules.

笔记：

* 保留的`prompt` key is used for [prompt linking](#prompt-linking) and isn't forwarded as trace metadata.
* 保留的身份密钥`agentId`, `agentName`, `workflowId`, and `workflowName` are set from the root span and take precedence over custom values with the same name.
* 下的按键`langfuse` take precedence over root span metadata with the same name.
* 值作为字符串发送，因为 Langfuse 将跟踪元数据属性映射为字符串。数字、布尔值和对象使用 JSON 进行序列化。 Langfuse Cloud 在摄取时将它们恢复为原始类型。

## 对话会 {/* #conversation-sessions */}

导出器使用以下命令将跨度元数据映射到 Langfuse 会话`sessionId`, or `threadId` when `sessionId` is absent or `null`. An explicit empty `sessionId` suppresses this fallback and sends no session ID.

为了[Observational Memory](/docs/memory/observational-memory), the Langfuse exporter keeps observer and reflector spans in the caller's session, even when child spans arrive before their parents. An explicit `sessionId`, including an empty string, takes precedence. Otherwise, the exporter uses the original caller thread carried by Observational Memory before falling back to the span's own `threadId`. Observational Memory captures that caller identity from the caller span's non-empty `threadId`, or the original request's thread ID. Nested observation preserves the outer caller identity.

这种线程到会话的回退是 Langfuse 特有的。观察记忆不能综合通用的记忆`sessionId` metadata from a thread ID for other exporters.

内部观察者和反射器执行线程保持独立。多线程观察使用调用方的会话，而不是批处理中的第一个线程。无论什么情况，此会话行为都适用`bufferOnIdle` setting and doesn't change buffering or span parentage.

## 成本追踪 {/* #cost-tracking */}

出口商将Provider报告的成本转发给 Langfuse`cost_details` field, but only when the generation's cost metadata meets every condition:

* 跨度是模型生成跨度。
* `costContext.costMetadata.source`是`'provider_reported'`.
* `costContext.costUnit`是`'USD'`.
* `costContext.estimatedCost`是一个有限的非负数。

预估成本故意不导出，因此 Langfuse 可以应用自己的定价模型。如果您的世代在 Langfuse 中显示缺失成本，请检查您的Provider是否报告成本；否则在 Langfuse 中配置型号价格。

请参阅[`LangfuseExporter` reference](/reference/observability/tracing/exporters/langfuse#cost-tracking) for the exact rules.

## 提示链接 {/* #prompt-linking */}

您可以将 LLM 生成链接到存储在中的提示[Langfuse Prompt Management](https://langfuse.com/docs/prompt-management). It enables version tracking and metrics for your prompts.

### 使用助手（推荐） {/* #using-the-helper-recommended */}

使用`withLangfusePrompt` with `buildTracingOptions` for the cleanest API:

```typescript title="src/agents/support-agent.ts"
import { Agent } from '@mastra/core/agent'
import { buildTracingOptions } from '@mastra/observability'
import { LangfuseExporter, withLangfusePrompt } from '@mastra/langfuse'

const exporter = new LangfuseExporter()

// Fetch the prompt from Langfuse Prompt Management via the client
const prompt = await exporter.client.prompt.get('customer-support', { type: 'text' })

export const supportAgent = new Agent({
  id: 'support-agent',
  name: 'support-agent',
  instructions: prompt.compile(), // Use the prompt text from Langfuse
  model: '__GATEWAY_OPENAI_MODEL__',
  defaultGenerateOptions: {
    tracingOptions: buildTracingOptions(
      withLangfusePrompt({ name: prompt.name, version: prompt.version }),
    ),
  },
})
```

这`withLangfusePrompt` helper accepts `name` and `version` fields for prompt linking. Langfuse v5 requires both fields.

### 手动字段 {/* #manual-fields */}

如果您不使用 Langfuse SDK，您还可以传递手动字段：

```typescript
const tracingOptions = buildTracingOptions(withLangfusePrompt({ name: 'my-prompt', version: 1 }))
```

### 提示对象字段 {/* #prompt-object-fields */}

提示对象需要两者`name` and `version`:

|领域 |类型 |描述 |
| - | - | - |
|`name` | string | The prompt name in Langfuse |
| `version` | number | The prompt version number |

当设置为`MODEL_GENERATION` span, the Langfuse exporter automatically links the generation to the corresponding prompt.
