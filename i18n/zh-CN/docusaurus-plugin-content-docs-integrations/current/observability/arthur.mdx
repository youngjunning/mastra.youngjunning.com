# Arthur

[Arthur](https://arthur.ai/) 通过开源的 [Arthur Engine](https://github.com/arthur-ai/arthur-engine) 为 AI 应用提供 Observability 和评估平台。Arthur 导出器通过 OpenTelemetry 发送 Trace，并遵循 [OpenInference](https://github.com/Arize-ai/openinference/tree/main/spec) 语义约定。

## 安装 {/* #installation */}

```bash npm2yarn
npm install @mastra/arthur@latest
```

## 配置 {/* #configuration */}

### 前置条件 {/* #prerequisites */}

1. **Arthur Engine 实例**：按照 [Docker Compose 部署指南](https://docs.arthur.ai/docs/arthur-genai-engine-docker-compose-deployment-guide)启动一个 Arthur Engine 实例
1. **API 密钥**：打开 `http://localhost:3030` 上的 Arthur Engine 界面，[生成 API 密钥](https://docs.arthur.ai/docs/api-keys-management)
1. **任务 ID**（可选）：[创建任务](https://docs.arthur.ai/docs/create-a-task)，以便将 Trace 路由到指定任务

### 任务路由 {/* #task-routing */}

Arthur Engine 通过两种方式将 Trace 与任务关联：

- **按服务名称**：在 Observability 配置中设置 `serviceName`。Arthur Engine 会自动将 Trace 路由到同名任务，如果该任务不存在，就会创建一个。
- **按任务 ID**：向导出器传入已有任务的 `taskId`，直接将 Trace 发送到指定任务。

如果同时提供两者，则优先使用 `taskId`。

### 环境变量 {/* #environment-variables */}

```bash title=".env"
# Required
ARTHUR_API_KEY=your-api-key
ARTHUR_BASE_URL=http://localhost:3030

# Optional - route traces to a pre-existing task by ID
ARTHUR_TASK_ID=your-task-id
```

### 零配置用法 {/* #zero-config-setup */}

设置环境变量后，无需额外配置即可使用导出器：

```typescript title="src/mastra/index.ts"
import { Mastra } from '@mastra/core'
import { Observability } from '@mastra/observability'
import { ArthurExporter } from '@mastra/arthur'

export const mastra = new Mastra({
  observability: new Observability({
    configs: {
      arthur: {
        serviceName: 'my-service',
        exporters: [new ArthurExporter()],
      },
    },
  }),
})
```

### 显式配置 {/* #explicit-configuration */}

你也可以直接传入凭据，传入的凭据优先于环境变量中的凭据：

```typescript title="src/mastra/index.ts"
import { Mastra } from '@mastra/core'
import { Observability } from '@mastra/observability'
import { ArthurExporter } from '@mastra/arthur'

export const mastra = new Mastra({
  observability: new Observability({
    configs: {
      arthur: {
        serviceName: 'my-service',
        exporters: [
          new ArthurExporter({
            apiKey: process.env.ARTHUR_API_KEY!,
            endpoint: process.env.ARTHUR_BASE_URL!,
            taskId: process.env.ARTHUR_TASK_ID,
          }),
        ],
      },
    },
  }),
})
```

## 配置选项 {/* #configuration-options */}

### 完整配置 {/* #complete-configuration */}

```typescript
new ArthurExporter({
  // Arthur Configuration
  apiKey: 'your-api-key', // Required
  endpoint: 'http://localhost:3030', // Required
  taskId: 'your-task-id', // Optional

  // Optional OTLP settings
  headers: {
    'x-custom-header': 'value', // Additional headers for OTLP requests
  },

  // Debug and performance tuning
  logLevel: 'debug', // Logging: debug | info | warn | error
  batchSize: 512, // Batch size before exporting spans
  timeout: 30000, // Timeout in ms before exporting spans

  // Custom resource attributes
  resourceAttributes: {
    'deployment.environment': process.env.NODE_ENV,
    'service.version': process.env.APP_VERSION,
  },
})
```

### 自定义元数据 {/* #custom-metadata */}

非保留的 Span 属性会序列化到 OpenInference 的 `metadata` 载荷中，并在 Arthur 中显示。你可以通过 `tracingOptions.metadata` 添加这些属性：

```ts
await agent.generate(input, {
  tracingOptions: {
    metadata: {
      companyId: 'acme-co',
      tier: 'enterprise',
    },
  },
})
```

导出器会自动排除保留字段，例如 `input`、`output`、`sessionId`、对话线程 ID、用户 ID 和 OpenInference ID。

## OpenInference 语义约定 {/* #openinference-semantic-conventions */}

此导出器实现了面向生成式 AI 应用的 [OpenInference 语义约定](https://github.com/Arize-ai/openinference/tree/main/spec)，使 Trace 在不同的 Observability 平台上采用统一的结构。
