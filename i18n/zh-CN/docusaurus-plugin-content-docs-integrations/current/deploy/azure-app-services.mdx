# Azure App Services

将 Mastra 应用部署到 Azure App Services。

:::note
本指南介绍如何部署 [Mastra 服务器](/docs/server/overview)。如果您使用的是[服务器适配器](/docs/server/server-adapters)或 [Web 框架](/docs/deployment/web-framework)，请按该框架的常规方式部署。
:::

## 开始之前 {/* #before-you-begin */}

您需要准备：

- 一个 [Mastra 应用](/docs)
- 一个拥有有效订阅的 [Azure 账户](https://azure.microsoft.com/)
- 一个包含您的 Mastra 应用的 [GitHub 仓库](https://github.com/)

:::warning
Azure App Services 的某些定价层使用临时文件系统，因此重新部署时，所有本地数据库文件都会丢失。如果您的 [LibSQLStore](/integrations/databases/libsql) 使用本地文件，请将其改为使用兼容 LibSQL 的远程数据库（例如 [Turso](https://turso.tech/)）。
:::

## 创建新的应用服务 {/* #create-a-new-app-service */}

以下步骤介绍如何创建一个新的 Azure App Service 来托管您的 Mastra 应用。完成后，应用运行所需的基础设施和环境就会配置好。

<Steps>
  <StepItem>
    登录 [Azure Portal](https://portal.azure.com)，打开 **[App Services](https://docs.microsoft.com/en-us/azure/app-service/)**，也可以在顶部搜索栏中搜索该服务。选择 **Create** 创建新的 App Service，然后在下拉菜单中选择 **Web App**。
  </StepItem>

  <StepItem>
    配置应用服务的各项设置：

    - **Subscription**：选择您的 Azure 订阅
    - **Resource Group**：创建新的资源组，或选择现有资源组
    - **Instance name**：为应用输入一个唯一的名称（该名称将成为应用 URL 的一部分）
    - **Publish**：选择 **Code**
    - **Runtime stack**：选择 **Node 22 LTS**
    - **Operating System**：选择 **Linux**
    - **Region**：选择靠近用户的区域
    - **Linux Plan**：能否选择计划取决于您选定的区域。如果可以选择，请挑选符合需求的计划。
    - 选择 **Review + Create**，等待验证完成后，再选择 **Create**。
  </StepItem>

  <StepItem>
    新的部署已触发。等待部署完成，然后在后续步骤部分选择 **Go to resource**。
  </StepItem>

  <StepItem>
    设置 GitHub 部署之前，请先配置环境变量。在左侧边栏中依次选择 **Settings** > **Environment variables**，然后添加所需的环境变量，例如：

    - Model Provider 的 API 密钥（例如 `OPENAI_API_KEY`）
    - 数据库连接字符串
    - Mastra 应用所需的其他配置值

    选择 **Apply** 保存更改。
  </StepItem>
</Steps>

## 通过 GitHub 部署 {/* #github-deployment */}

按以下步骤将 Azure App Service 连接到你的 GitHub 仓库，即可启用持续部署。此后，每次向仓库推送更改时，Azure 都会自动构建并部署你的应用。

<Steps>
  <StepItem>
    在左侧边栏中打开 **Deployment Center**，选择 **GitHub** 作为部署源。如果尚未在 Azure 中完成 GitHub 身份验证，请登录 GitHub。

    本示例继续使用 [GitHub Actions](https://docs.github.com/en/actions) 作为 Provider。选择你的组织、仓库和分支。

    Azure 会生成一个 GitHub Workflow 文件，你可以先预览再继续。选择页面顶部的 **Save** 按钮。
  </StepItem>

  <StepItem>
    Azure 创建 Workflow 后，会触发一次 GitHub Actions 运行，并将 Workflow 文件合并到你的分支。请**取消这次首次运行**，因为未做必要修改时，运行会失败。

    :::warning
    Azure 生成的默认 Workflow 无法成功部署 Mastra 应用，需要先修改。
    :::

    将最新更改拉取到本地仓库，然后修改生成的 Workflow 文件（`.github/workflows/main_<your-app-name>.yml`）：
  </StepItem>

  <StepItem>
    找到名为“npm install, build, and test”的步骤，然后执行以下操作：

    - 将步骤名称改为“npm install and build”
    - 如果你的 Mastra 应用尚未配置可正常运行的测试，请从 run 部分移除 `npm test` 命令，因为默认测试脚本会运行失败并中断部署。如果测试可以正常运行，可以保留该命令。
  </StepItem>

  <StepItem>
    找到“Zip artifact for deployment”步骤，将其中的 zip 命令替换为：

    ```yaml
    run: (cd .mastra/output && zip ../../release.zip -r .)
    ```

    这样，部署包就只包含 `.mastra/output` 中的构建产物。
  </StepItem>

  <StepItem>
    提交并推送对 Workflow 的修改。Azure 仪表板中的 **Deployment Center** 会自动触发构建。请查看部署进度，直至部署成功。
  </StepItem>
</Steps>

## 验证部署 {/* #verify-your-deployment */}

构建成功后，请等待片刻，让应用程序启动。你可以使用 Azure 门户 **Overview** 选项卡中提供的默认 URL 访问已部署的应用程序。应用程序地址为 `https://<your-app-name>.azurewebsites.net`。

从 Azure 门户复制 URL，然后在浏览器中访问 `https://<your-app-name>.azurewebsites.net/api/agents`。页面应显示 Agent 的 JSON 列表。

现在，你可以通过 HTTP 调用 Mastra 端点。

:::warning
在对外公开端点之前，请先配置[身份验证](/docs/auth/overview)。
:::
