# AWS Lambda

使用 Docker 容器将 Mastra 应用程序部署到 AWS Lambda[AWS Lambda Web Adapter](https://github.com/awslabs/aws-lambda-web-adapter)。此方法将您的 Mastra 服务器作为具有自动扩展功能的容器化 Lambda 函数运行。

:::注意
本指南涵盖了部署[Mastra server](/docs/server/overview). If you're using a [server adapter](/docs/server/server-adapters)或者[网络框架](/docs/deployment/web-framework)，按照您通常为该框架部署的方式进行部署。
:::

## 开始之前 {/* #before-you-begin */}

你需要：

* 一个[Mastra application](/docs)
* 一个[AWS account](https://aws.amazon.com/) with permissions for Lambda, ECR, and IAM
* **[AWS CLI](https://aws.amazon.com/cli/)**&#x5B89;装：运行`aws configure` to authenticate
* **[码头工人](https://www.docker.com/)**&#x5B89;装并运行

:::警告
在 AWS Lambda 上，文件系统是短暂的，因此任何本地数据库文件都将在调用之间丢失。如果您正在使用[LibSQLStore](/integrations/databases/libsql) with a local file, configure it to use a remote LibSQL-compatible database (for example, [Turso](https://turso.tech/)) instead.
:::

## 创建 Dockerfile {/* #create-a-dockerfile */}

创建一个`Dockerfile` in your project root:

```dockerfile title="Dockerfile"
FROM node:22-alpine

WORKDIR /app

# Install dependencies
COPY package*.json ./
RUN npm ci

# Copy source and build Mastra
COPY src ./src
RUN npx mastra build

# Alpine compatibility for some native deps
RUN apk add --no-cache gcompat

# Add the Lambda Web Adapter
COPY --from=public.ecr.aws/awsguru/aws-lambda-adapter:0.9.1 /lambda-adapter /opt/extensions/lambda-adapter

# Run as non-root
RUN addgroup -g 1001 -S nodejs && \
  adduser -S mastra -u 1001 && \
  chown -R mastra:nodejs /app

USER mastra

# Adapter / app configuration
ENV PORT=8080
ENV NODE_ENV=production
ENV AWS_LWA_READINESS_CHECK_PATH="/api"

# Start the Mastra server
CMD ["node", ".mastra/output/index.mjs"]
```

:::注意
这个 Dockerfile 使用 npm。如果您使用 pnpm、yarn 或其他包管理器，请相应地调整命令（例如`npm ci` won't work with pnpm lockfiles).
:::

## 构建并推送 Docker 镜像 {/* #build-and-push-the-docker-image */}

<Steps>
  <StepItem>
    设置部署的环境变量。对所有 AWS 服务（ECR、Lambda）使用同一区域，以避免资源未跨区域出现的问题：

    ```bash
    export PROJECT_NAME="your-mastra-app"
    export AWS_REGION="us-east-1"
    export AWS_ACCOUNT_ID=$(aws sts get-caller-identity --query Account --output text)
    ```
  </StepItem>

  <StepItem>
    构建您的 Docker 镜像。禁用 BuildKit 以确保映像与 Lambda 的容器运行时兼容：

    ```bash
    export DOCKER_BUILDKIT=0
    docker build --platform linux/arm64 -t "$PROJECT_NAME" .
    ```

    :::注意
    BuildKit 的默认图像格式可能会导致与 Lambda 的兼容性问题。环境`DOCKER_BUILDKIT=0` uses the classic builder, which produces images in a format Lambda reliably accepts.
    :::
  </StepItem>

  <StepItem>
    创建 Amazon ECR 存储库来存储您的 Docker 映像：

    ```bash
    aws ecr create-repository --repository-name "$PROJECT_NAME" --region "$AWS_REGION"
    ```
  </StepItem>

  <StepItem>
    登录 Amazon ECR：

    ```bash
    aws ecr get-login-password --region "$AWS_REGION" | \
      docker login --username AWS --password-stdin \
      "$AWS_ACCOUNT_ID.dkr.ecr.$AWS_REGION.amazonaws.com"
    ```
  </StepItem>

  <StepItem>
    标记您的图像并将其推送到 ECR：

    ```bash
    docker tag "$PROJECT_NAME":latest \
      "$AWS_ACCOUNT_ID.dkr.ecr.$AWS_REGION.amazonaws.com/$PROJECT_NAME":latest

    docker push \
      "$AWS_ACCOUNT_ID.dkr.ecr.$AWS_REGION.amazonaws.com/$PROJECT_NAME":latest
    ```
  </StepItem>
</Steps>

## 创建 Lambda 函数 {/* #create-the-lambda-function */}

<Steps>
  <StepItem>
    导航至[AWS Lambda Console](https://console.aws.amazon.com/lambda/) and click **Create function**. Make sure you have the same region selected as where you created your ECR repository.
  </StepItem>

  <StepItem>
    选择**Container image** and configure the function:

    * **函数名称**：输入名称（例如`mastra-app`)
    * **容器镜像URI**： 点击**Browse images**, select your ECR repository, and choose the `latest` tag
    * **建筑学**： 选择**arm64**

    点击**Create function** to create the Lambda function.
  </StepItem>

  <StepItem>
    配置内存和超时。前往**Configuration** > **General configuration** and click **Edit**:

    * **记忆**：512 MB（根据您的应用需求进行调整）
    * **暂停**：1 分钟或更长（默认 3 秒对于大多数 Mastra 应用程序来说太低）

    点击**Save**.
  </StepItem>

  <StepItem>
    添加环境变量。前往**Configuration** > **Environment variables** and click **Edit**. Add the variables your Mastra application needs:

    * `OPENAI_API_KEY`：您的 OpenAI API 密钥（如果使用 OpenAI）
    * `ANTHROPIC_API_KEY`：您的 Anthropic API 密钥（如果使用 Anthropic）
    * 根据需要提供其他特定于Provider的 API 密钥（例如`TURSO_DATABASE_URL` and `TURSO_AUTH_TOKEN` if using LibSQL with Turso)

    点击**Save**.
  </StepItem>

  <StepItem>
    启用函数 URL 以进行外部访问。前往**Configuration** > **Function URL** and click **Create function URL**:

    * **认证类型**： 选择**NONE** for public access
    * 在下面**Additional settings**, check **Configure cross-origin resource sharing (CORS)**, then configure:
      * **允许来源**: `*`
      * **允许标头**: `content-type` (`x-amzn-request-context` is also required when used with services like CloudFront/API Gateway)
      * **允许方法**: `*`

    点击**Save**.
  </StepItem>
</Steps>

## 验证您的部署 {/* #verify-your-deployment */}

<Steps>
  <StepItem>
    复制**Function URL** from the Lambda console and visit `<your-function-url>/api/agents` in your browser. You should see a JSON list of your agents.
  </StepItem>

  <StepItem>
    您现在可以通过 HTTP 调用 Mastra 端点。

    :::警告
    对于生产部署，设置[authentication](/docs/auth/overview) before exposing your endpoints publicly, restrict CORS origins to your trusted domains, use AWS IAM roles for secure access to other AWS services, and store sensitive environment variables in AWS Secrets Manager or Parameter Store.
    :::
  </StepItem>
</Steps>

## 后续步骤 {/* #next-steps */}

本指南提供了将 Mastra 部署到 AWS Lambda 的快速入门。对于生产工作负载，请考虑启用[CloudWatch monitoring](https://docs.aws.amazon.com/lambda/latest/dg/monitoring-cloudwatchlogs.html) for your Lambda function, setting up [AWS X-Ray](https://docs.aws.amazon.com/lambda/latest/dg/services-xray.html) for distributed tracing, and configuring [provisioned concurrency](https://docs.aws.amazon.com/lambda/latest/dg/provisioned-concurrency.html) for consistent performance.
