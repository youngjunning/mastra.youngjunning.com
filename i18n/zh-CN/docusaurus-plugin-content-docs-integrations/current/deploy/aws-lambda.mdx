# AWS Lambda

使用 Docker 容器和 [AWS Lambda Web Adapter](https://github.com/awslabs/aws-lambda-web-adapter)，将 Mastra 应用部署到 AWS Lambda。Mastra 服务器会以容器化 Lambda 函数的形式运行，并自动扩缩容。

:::注意
本指南介绍如何部署 [Mastra 服务器](/docs/server/overview)。如果你使用了[服务器适配器](/docs/server/server-adapters)或 [Web 框架](/docs/deployment/web-framework)，请按所用框架的常规方式部署。
:::

## 开始之前 {/* #before-you-begin */}

开始前请准备以下各项：

* 一个 [Mastra 应用](/docs)
* 一个拥有 Lambda、ECR 和 IAM 操作权限的 [AWS 账户](https://aws.amazon.com/)
* 安装 **[AWS CLI](https://aws.amazon.com/cli/)**，并运行 `aws configure` 配置身份验证
* 安装并启动 **[Docker](https://www.docker.com/)**

:::警告
AWS Lambda 的文件系统是临时的，本地数据库文件会在两次调用之间丢失。如果 [LibSQLStore](/integrations/databases/libsql) 使用的是本地文件，请将它配置为连接兼容 LibSQL 的远程数据库，例如 [Turso](https://turso.tech/)。
:::

## 创建 Dockerfile {/* #create-a-dockerfile */}

在项目根目录创建 `Dockerfile`：

```dockerfile title="Dockerfile"
FROM node:22-alpine

WORKDIR /app

# Install dependencies
COPY package*.json ./
RUN npm ci

# Copy source and build Mastra
COPY src ./src
RUN npx mastra build

# Alpine compatibility for some native deps
RUN apk add --no-cache gcompat

# Add the Lambda Web Adapter
COPY --from=public.ecr.aws/awsguru/aws-lambda-adapter:0.9.1 /lambda-adapter /opt/extensions/lambda-adapter

# Run as non-root
RUN addgroup -g 1001 -S nodejs && \
  adduser -S mastra -u 1001 && \
  chown -R mastra:nodejs /app

USER mastra

# Adapter / app configuration
ENV PORT=8080
ENV NODE_ENV=production
ENV AWS_LWA_READINESS_CHECK_PATH="/api"

# Start the Mastra server
CMD ["node", ".mastra/output/index.mjs"]
```

:::注意
此 Dockerfile 使用 npm。如果你使用 pnpm、yarn 或其他包管理器，请相应调整命令。例如，`npm ci` 无法使用 pnpm 的锁文件。
:::

## 构建并推送 Docker 镜像 {/* #build-and-push-the-docker-image */}

<Steps>
  <StepItem>
    设置部署所需的环境变量。ECR 和 Lambda 等 AWS 服务应使用同一区域，以免在其他区域找不到所需资源：

    ```bash
    export PROJECT_NAME="your-mastra-app"
    export AWS_REGION="us-east-1"
    export AWS_ACCOUNT_ID=$(aws sts get-caller-identity --query Account --output text)
    ```
  </StepItem>

  <StepItem>
    构建 Docker 镜像。禁用 BuildKit，确保镜像与 Lambda 的容器运行时兼容：

    ```bash
    export DOCKER_BUILDKIT=0
    docker build --platform linux/arm64 -t "$PROJECT_NAME" .
    ```

    :::注意
    BuildKit 默认生成的镜像格式可能与 Lambda 不兼容。设置 `DOCKER_BUILDKIT=0` 会改用传统构建器，生成 Lambda 能稳定接受的镜像格式。
    :::
  </StepItem>

  <StepItem>
    创建一个 Amazon ECR 仓库，用于存放 Docker 镜像：

    ```bash
    aws ecr create-repository --repository-name "$PROJECT_NAME" --region "$AWS_REGION"
    ```
  </StepItem>

  <StepItem>
    登录 Amazon ECR：

    ```bash
    aws ecr get-login-password --region "$AWS_REGION" | \
      docker login --username AWS --password-stdin \
      "$AWS_ACCOUNT_ID.dkr.ecr.$AWS_REGION.amazonaws.com"
    ```
  </StepItem>

  <StepItem>
    为镜像打上标签，然后推送到 ECR：

    ```bash
    docker tag "$PROJECT_NAME":latest \
      "$AWS_ACCOUNT_ID.dkr.ecr.$AWS_REGION.amazonaws.com/$PROJECT_NAME":latest

    docker push \
      "$AWS_ACCOUNT_ID.dkr.ecr.$AWS_REGION.amazonaws.com/$PROJECT_NAME":latest
    ```
  </StepItem>
</Steps>

## 创建 Lambda 函数 {/* #create-the-lambda-function */}

<Steps>
  <StepItem>
    打开 [AWS Lambda 控制台](https://console.aws.amazon.com/lambda/)，点击 **Create function**。确认当前选中的区域和创建 ECR 仓库时所用的区域一致。
  </StepItem>

  <StepItem>
    选择 **Container image**，然后配置函数：

    * **函数名称**：输入名称，例如 `mastra-app`。
    * **容器镜像 URI**：点击 **Browse images**，选择你的 ECR 仓库，再选择 `latest` 标签。
    * **架构**：选择 **arm64**。

    点击 **Create function** 创建 Lambda 函数。
  </StepItem>

  <StepItem>
    配置内存和超时时间。前往 **Configuration** > **General configuration**，点击 **Edit**：

    * **内存**：512 MB，可按应用需求调整。
    * **超时时间**：至少 1 分钟。默认的 3 秒对大多数 Mastra 应用来说太短。

    点击 **Save**。
  </StepItem>

  <StepItem>
    前往 **Configuration** > **Environment variables**，点击 **Edit**，然后添加 Mastra 应用所需的环境变量：

    * `OPENAI_API_KEY`：如果使用 OpenAI，请填入 OpenAI API 密钥。
    * `ANTHROPIC_API_KEY`：如果使用 Anthropic，请填入 Anthropic API 密钥。
    * 按需添加其他 Provider 所需的 API 密钥等配置。例如，将 LibSQL 与 Turso 搭配使用时，添加 `TURSO_DATABASE_URL` 和 `TURSO_AUTH_TOKEN`。

    点击 **Save**。
  </StepItem>

  <StepItem>
    启用函数 URL，允许从外部访问。前往 **Configuration** > **Function URL**，点击 **Create function URL**：

    * **身份验证类型**：选择 **NONE**，允许公开访问。
    * 在 **Additional settings** 中勾选 **Configure cross-origin resource sharing (CORS)**，然后设置以下各项：
      * **允许的来源**：`*`
      * **允许的请求头**：`content-type`。搭配 CloudFront 或 API Gateway 等服务时，还需允许 `x-amzn-request-context`。
      * **允许的请求方法**：`*`

    点击 **Save**。
  </StepItem>
</Steps>

## 验证部署 {/* #verify-your-deployment */}

<Steps>
  <StepItem>
    从 Lambda 控制台复制 **Function URL**，在浏览器中访问 `<your-function-url>/api/agents`。你应该会看到 JSON 格式的 Agent 列表。
  </StepItem>

  <StepItem>
    现在可以通过 HTTP 调用 Mastra 端点。

    :::警告
    在生产环境中，请先配置[身份验证](/docs/auth/overview)，再公开端点。将 CORS 允许的来源限制为可信域名，通过 AWS IAM 角色安全访问其他 AWS 服务，并将敏感环境变量存放在 AWS Secrets Manager 或 Parameter Store 中。
    :::
  </StepItem>
</Steps>

## 后续步骤 {/* #next-steps */}

以上步骤可以帮助你快速将 Mastra 部署到 AWS Lambda。对于生产工作负载，可以考虑为 Lambda 函数启用 [CloudWatch 监控](https://docs.aws.amazon.com/lambda/latest/dg/monitoring-cloudwatchlogs.html)，设置 [AWS X-Ray](https://docs.aws.amazon.com/lambda/latest/dg/services-xray.html) 进行分布式追踪，并配置[预置并发](https://docs.aws.amazon.com/lambda/latest/dg/provisioned-concurrency.html)以维持稳定的性能。
