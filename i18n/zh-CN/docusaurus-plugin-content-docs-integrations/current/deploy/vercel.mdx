# Vercel 部署器

通过 `@mastra/deployer-vercel` 将 Mastra 服务器部署为 Vercel 上的无服务器函数。部署器会打包代码并生成符合 Vercel [构建输出 API](https://vercel.com/docs/build-output-api/v3) 规范的 `.vercel/output` 目录，无需额外配置即可部署。

:::note
本指南介绍如何部署 [Mastra 服务器](/docs/server/overview)。如果使用[服务器适配器](/docs/server/server-adapters)或 [Web 框架](/docs/deployment/web-framework)，请遵循对应框架的常规部署方式。
:::

## 开始之前 {/* #before-you-begin */}

你需要一个 [Mastra 应用](/docs)和一个 [Vercel](https://vercel.com/) 账号。

:::warning
Vercel Functions 使用临时文件系统，因此配置的所有存储（包括 Observability 存储）都必须托管在外部。如果你使用文件 URL 配置 [LibSQLStore](/integrations/databases/libsql)，请改用远程托管的数据库。
:::

## 安装 {/* #installation */}

将 `@mastra/deployer-vercel` 包添加到项目中：

```bash npm2yarn
npm install @mastra/deployer-vercel@latest
```

导入 [`VercelDeployer`](/reference/deployer/vercel)，并在 Mastra 配置中将其设为部署器：

```typescript title="src/mastra/index.ts"
import { Mastra } from '@mastra/core'
// highlight-next-line
import { VercelDeployer } from '@mastra/deployer-vercel'

export const mastra = new Mastra({
  // highlight-next-line
  deployer: new VercelDeployer(),
})
```

## 部署 {/* #deploy */}

<Steps>
  <StepItem>
    将项目推送到远程 Git Provider（例如 GitHub），并将代码仓库连接到 Vercel。

    默认情况下，Vercel 会运行 `npm run build`，进而触发 `mastra build`。如果尚未配置构建脚本，请将 `"build": "mastra build"` 添加到 `package.json` 中。

    :::note

    请记得设置运行应用所需的环境变量，例如 [Model Provider](/models/providers) 的 API 密钥。

    :::
  </StepItem>

  <StepItem>
    准备就绪后，单击 **Deploy**，等待首次部署完成。
  </StepItem>

  <StepItem>
    访问 `https://<your-project>.vercel.app/api/agents` 验证部署；该地址应返回 Agent 的 JSON 列表。

    Mastra 服务器会为每个端点添加 `/api` 前缀，因此发起请求时，URL 中必须包含此前缀。
  </StepItem>

  <StepItem>
    现在可以通过 HTTP 调用 Mastra 的端点。

    :::warning
    在公开端点之前，请先配置[身份验证](/docs/auth/overview)。
    :::
  </StepItem>
</Steps>

## Studio {/* #studio */}

启用 `studio` 选项，即可将 [Studio](/docs/studio/overview) 与 API 一起部署。Studio 以静态资源的形式部署，由 Vercel 的边缘 CDN 提供，因此不会占用函数调用次数。

```typescript title="src/mastra/index.ts"
import { Mastra } from '@mastra/core'
import { VercelDeployer } from '@mastra/deployer-vercel'

export const mastra = new Mastra({
  deployer: new VercelDeployer({
    // highlight-next-line
    studio: true,
  }),
})
```

部署后，可以通过根 URL（`https://<your-project>.vercel.app/`）访问 Studio，API 仍位于 `/api/*`。Studio 会自动连接到同源 API，因此无需添加其他环境变量。

Studio 自身的页面由 CDN 提供，其余路径均转发到你的服务器，因此通过 [`registerApiRoute()`](/docs/server/custom-api-routes) 添加的路由仍可通过各自的路径访问。请避免为自定义路由使用 Studio 已有的路径（例如 `/agents` 或 `/workflows`），因为这些路径会优先由 Studio 处理。

:::warning
Studio 连接到 Mastra 服务器后，拥有对其中 Agent、Workflow 和 Tool 的完整访问权限。在生产环境中，请通过身份验证、VPN 等方式限制对 Studio 的访问，防止未经授权的访问。
:::

## 可选的配置覆盖项 {/* #optional-overrides */}

Vercel 部署器支持将配置选项写入 Vercel Output API 的函数配置。有关 `maxDuration`、`memory` 和 `regions` 等可用选项，请参阅 [`VercelDeployer` 参考文档](/reference/deployer/vercel#constructor-options)。

请求超时由两个独立的上限控制。`maxDuration`（单位为秒）限制 Vercel 允许函数运行的时间；Mastra 的 `server.timeout`（单位为毫秒，默认值为 `180000`）限制 Mastra 返回 `504 Gateway Timeout` 之前的等待时间。只提高 `maxDuration` 不会延长 Mastra 的 180 秒上限，因此对于运行 Workflow 等耗时较长的请求，需要同时提高这两个上限：

```typescript title="src/mastra/index.ts"
export const mastra = new Mastra({
  deployer: new VercelDeployer({ maxDuration: 600 }),
  server: { timeout: 600_000 },
})
```

有关详细信息，请参阅[请求超时](/reference/deployer/vercel#request-timeouts)。

## Observability {/* #observability */}

无服务器函数可能在返回响应后立即终止。尚未完成的异步任务（例如发送遥测数据）可能因此被中断。等待 `flush()` 执行完毕，可确保所有 Trace 都在函数退出前发出。

```typescript title="api/chat.ts"
import type { VercelRequest, VercelResponse } from '@vercel/node'
import { mastra } from '../src/mastra'

export default async function handler(req: VercelRequest, res: VercelResponse) {
  const { message } = req.body
  const agent = mastra.getAgent('myAgent')
  const result = await agent.generate([{ role: 'user', content: message }])

  await mastra.observability.flush()

  return res.json(result)
}
```

:::warning
Vercel 部署器不会调用 `flush`。如果需要调用，请自行封装处理函数，将调用逻辑加在返回响应之前。也可以部署到[虚拟机](/integrations/deploy/digital-ocean)等长期运行的服务器上，这样就不会遇到这个问题。
:::
