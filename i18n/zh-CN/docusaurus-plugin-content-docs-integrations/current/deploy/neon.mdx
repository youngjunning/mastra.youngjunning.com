# Neon

在你的 Neon 分支上，将 Mastra 服务器部署为 [Neon Function](https://neon.com/docs/compute/functions/overview)（一个长时间运行的 Node.js 进程）。Neon 会为函数分配一个可公开访问的 HTTPS URL，并根据该分支的 Postgres 数据库注入 `DATABASE_URL`。

Neon Functions 通过 `fetch` 处理程序接收请求。本指南使用 [Hono 服务器适配器](/docs/server/server-adapters)，无需运行 `mastra build` / `mastra start`。如果你的应用使用了 [Web 框架](/docs/deployment/web-framework)，请按该框架的常规流程部署。

Neon Functions 目前处于 Beta 阶段，仅在 AWS 美国东部（俄亥俄州）区域（`aws-us-east-2`）可用。请在该区域创建 Neon 项目。

## 开始之前 {/* #before-you-begin */}

你需要：

- 一个 [Mastra 应用](/docs)
- 一个 [Neon](https://neon.com) 账号
- 一个位于 `aws-us-east-2` 区域的 Neon 项目
- Node.js `v22.13.0` 或更高版本

Neon Functions 可能回收空闲的隔离运行环境，导致其中的内存数据和本地文件丢失。请使用 [连接 Neon 的 PostgresStore](/integrations/databases/neon) 替代使用文件 URL 的 [LibSQLStore](/integrations/databases/libsql)。工作区文件请存放在 [Neon Object Storage](/integrations/file-storage/neon)，以替代 [`LocalFilesystem`](/reference/workspace/local-filesystem)。

## 安装 {/* #installation */}

安装 [Neon CLI](https://neon.com/docs/cli/install)：

```bash npm2yarn
npm install -g neon
```

安装 Hono 适配器、Hono 和 `@neon/config`：

```bash npm2yarn
npm install @mastra/hono@latest hono @neon/config
```

## 配置 `neon.ts` {/* #configure-neonts */}

在项目根目录下创建 `neon.ts`。`neon deploy` 和 `neon dev` 都会读取此文件：

```typescript title="neon.ts"
import { defineConfig } from '@neon/config/v1'

export default defineConfig({
  preview: {
    aiGateway: true,
    functions: {
      mastra: {
        name: 'Mastra server',
        source: './src/index.ts',
      },
    },
  },
})
```

对象的键 `mastra` 是函数的 slug，首次部署后无法更改。

`aiGateway: true` 会在分支上启用 [Neon AI Gateway](/models/gateways/neon)。`neon deploy` 会注入 `NEON_AI_GATEWAY_BASE_URL` 和 `NEON_AI_GATEWAY_TOKEN`。当模型 ID 以 `neon/` 开头时，Mastra 会读取这两个变量。

如果要直接使用模型提供商的 API 密钥，请在函数的 `env` 字段中声明密钥，并改用该提供商的模型 ID，去掉 `neon/` 前缀。运行 `neon deploy` 时，配置会从 `process.env` 读取变量值：

```typescript title="neon.ts"
import { defineConfig } from '@neon/config/v1'

export default defineConfig({
  preview: {
    functions: {
      mastra: {
        name: 'Mastra server',
        source: './src/index.ts',
        env: {
          OPENAI_API_KEY: process.env.OPENAI_API_KEY!,
        },
      },
    },
  },
})
```

```bash
neon deploy --env .env
```

`--env` 会加载指定的文件，供执行配置时读取变量。部署时只会传入 `env` 中列出的变量。详情请参阅 [Neon Functions 环境变量](https://neon.com/docs/compute/functions/environment-variables)。

## 导出 Hono 的 fetch 处理程序 {/* #export-a-hono-fetch-handler */}

通过 [Hono 适配器](/reference/server/hono-adapter) 将 Mastra 接入 Hono，并将 Hono 应用设为默认导出。Neon Functions 会调用默认导出对象的 `fetch` 方法。

```typescript title="src/index.ts"
import { Hono } from 'hono'
import { HonoBindings, HonoVariables, MastraServer } from '@mastra/hono'
import { mastra } from './mastra'

const app = new Hono<{ Bindings: HonoBindings; Variables: HonoVariables }>()
const server = new MastraServer({ app, mastra })

await server.init()

export default app
```

在 `src/mastra/index.ts` 中，将 Agent 注册到 `mastra` 实例。

```typescript title="src/mastra/index.ts"
import { Mastra } from '@mastra/core/mastra'
import { Agent } from '@mastra/core/agent'

const assistant = new Agent({
  id: 'assistant',
  name: 'Assistant',
  instructions: 'You are a helpful assistant',
  model: 'neon/claude-fable-5',
})

export const mastra = new Mastra({
  agents: { assistant },
})
```

可用模型列表见 [Neon AI Gateway](/models/gateways/neon)。

## 部署 {/* #deploy */}

<Steps>
  <StepItem>
    在项目目录中运行以下命令，关联现有的 Neon 项目，或创建一个新项目：

    ```bash
    neon link
    ```

    `neon link` 会将项目上下文写入 `.neon`，并拉取当前分支的环境变量。
  </StepItem>

  <StepItem>
    部署函数：

    ```bash
    neon deploy
    ```

    CLI 会使用 esbuild 打包处理程序，上传构建产物，并等待部署状态变为 `completed`。如果在函数的 `env` 中声明了环境变量，请传入 `--env <file>`，让 `neon.ts` 能读取这些变量的值。
  </StepItem>

  <StepItem>
    获取可公开访问的 URL：

    ```bash
    neon functions get mastra
    ```

    `invocation_url` 的格式为 `https://<branch-id>-mastra.compute.<cell>.us-east-2.aws.neon.tech/`。
  </StepItem>

  <StepItem>
    访问 `https://<branch-id>-mastra.compute.<cell>.us-east-2.aws.neon.tech/api/agents` 验证部署。该地址应返回 JSON 格式的 Agent 列表。

    Mastra 服务器的所有 API 端点都带有 `/api` 前缀。发出请求时，请在 URL 路径中加上此前缀。

    Neon 会从当前分支注入 `DATABASE_URL`。如果在 `neon.ts` 中设置了 `aiGateway: true`，还会注入网关凭据。
  </StepItem>

  <StepItem>
    您现在可以通过 HTTP 调用 Mastra 端点。

    :::warning
    在公开 API 端点之前，请先配置 [身份验证](/docs/auth/overview)。函数 URL 可公开访问，详情请参阅 [Neon Functions 身份验证](https://neon.com/docs/compute/functions/authentication)。
    :::
  </StepItem>
</Steps>

## 本地开发 {/* #local-development */}

`neon dev` 会在本地运行 `neon.ts` 中声明的所有函数，支持热重载，并注入已关联分支的环境变量：

```bash
neon dev
```

在本地访问 `http://localhost:8787/api/agents`，即可调用 Mastra 服务器的 Agent 列表端点。
