# Render

可以通过两种方式结合使用 [Render](https://render.com/?utm_source=partner\&utm_medium=partnerships\&utm_campaign=2026_partnership_mastra) 与 Mastra：

* **Agent Tool**：让 Agent 通过 [Mastra Connect](/docs/mastra-platform/connect) 管理 Render 服务、环境变量、日志和指标。
* **[部署](#deploy-on-render)**：在 Render 上运行 Mastra 应用。

## 连接 {/* #connect */}

开始前，请按照 [Connect 设置指南](/docs/mastra-platform/connect#get-started)安装 `@mastra/connect` 并配置平台项目。

## 在 Render 上部署 {/* #deploy-on-render */}

可以将 Mastra API 作为 [Web Service](https://render.com/docs/web-services?utm_source=partner\&utm_medium=partnerships\&utm_campaign=2026_partnership_mastra) 部署在 Render 上，也可以通过 [Render Workflows](https://render.com/docs/workflows?utm_source=partner\&utm_medium=partnerships\&utm_campaign=2026_partnership_mastra) 运行具有独立重试策略的长时间任务。

选择适合您的应用程序的部署路径：

* **Mastra API**：将 Mastra [服务器](/docs/server/overview)部署为具有公开端点的 Web Service。[Web Services 指南](https://render.com/docs/web-services?utm_source=partner\&utm_medium=partnerships\&utm_campaign=2026_partnership_mastra)说明如何部署自定义代码或受支持的[服务器适配器](/docs/server/server-adapters)。
* **Mastra Workflow**：在单个任务中运行完整的 Mastra Workflow。Render 控制外层运行，Mastra 管理其中的步骤和状态。配置详情参见[定义 Workflow 任务](https://render.com/docs/workflows-defining?utm_source=partner\&utm_medium=partnerships\&utm_campaign=2026_partnership_mastra)。
* **分布式 Agent 操作**：为每个操作分别配置计算方案、超时和重试策略。Render Workflows 管理执行队列，并提供运行可观测性。

本节将构建一个编辑流水线，从三个角度并行评审草稿，再将反馈交给编辑 Agent。若要部署 Mastra API，或将完整的 Mastra Workflow 作为单个任务运行，请参阅上面的链接。

### Render Workflows 如何与 Mastra 集成 {/* #how-render-workflows-integrate-with-mastra */}

Mastra 提供 Agent 和应用逻辑，Render Workflows 则定义任务的执行边界。典型流水线分为三层：

1. 父 Render 任务协调运行。
2. 子 Render 任务调用 Mastra Agent，分别处理明确的工作。
3. 最后的 Render 任务汇总结果。

从一个 Render 任务调用另一个任务会创建链式任务运行。每次链式运行都在独立实例中执行，你可以单独设置该任务的计算资源、超时和重试策略。

本节的编辑流水线会并行从三个角度评审草稿，再由 Mastra 编辑 Agent 生成修订稿。你可以在[在线演示](https://render-workflows-mastra.onrender.com)中试用正在运行的版本。

### 设置 {/* #setup */}

你需要 Render 账号和 Render CLI。开发期间，CLI 会运行本地任务服务器；它也可以用于在 Render 上创建 Workflow 服务。

安装 CLI 并登录：

```bash
brew install render
render login
```

:::note
需要 Render CLI `v2.12.0` 或更高版本。其他安装方式参见 [Render CLI 文档](https://render.com/docs/cli?utm_source=partner\&utm_medium=partnerships\&utm_campaign=2026_partnership_mastra)。
:::

创建名为 `render-workflows` 的空 Mastra 项目：

```bash npm2yarn
npm create mastra@latest render-workflows -- --empty
```

```bash
cd render-workflows
```

安装 Render SDK：

```bash npm2yarn
npm install @renderinc/sdk tsx
```

设置模型 Provider 的 API 密钥。以下示例使用 OpenAI：

```text title=".env"
OPENAI_API_KEY=your_openai_api_key
```

任何受支持的 [Mastra 模型 Provider](/models)均可使用。

### 构建分布式 Agent 流水线 {/* #build-a-distributed-agent-pipeline */}

#### 创建 Agent {/* #create-the-agents */}

在 `src/mastra` 下创建 `agents` 目录，并在其中创建 `reviewer-agent.ts` 和 `editor-agent.ts`。定义这两个 Agent：

```ts title="src/mastra/agents/reviewer-agent.ts"
import { Agent } from '@mastra/core/agent'

export const reviewerAgent = new Agent({
  id: 'reviewer-agent',
  name: 'Reviewer Agent',
  model: '__GATEWAY_OPENAI_MODEL__',
  instructions: `
    Review the supplied draft only from the requested perspective.
    Identify concrete problems and recommend specific changes.
    Do not rewrite the full draft.
  `,
})
```

```ts title="src/mastra/agents/editor-agent.ts"
import { Agent } from '@mastra/core/agent'

export const editorAgent = new Agent({
  id: 'editor-agent',
  name: 'Editor Agent',
  model: '__GATEWAY_OPENAI_MODEL__',
  instructions: `
    Revise the supplied draft using the reviewers' feedback.
    Return the complete revised draft and nothing else.
    Preserve accurate details and do not introduce unsupported claims.
  `,
})
```

#### 配置 Mastra 实例 {/* #configure-the-mastra-instance */}

在 `src/mastra/index.ts` 中将两个 Agent 添加到 Mastra 实例：

```ts title="src/mastra/index.ts"
import { Mastra } from '@mastra/core/mastra'
import { editorAgent } from './agents/editor-agent.js'
import { reviewerAgent } from './agents/reviewer-agent.js'

export const mastra = new Mastra({
  agents: {
    editorAgent,
    reviewerAgent,
  },
})
```

通过 Mastra 实例获取 Agent，可以让它们访问日志、存储和可观测性等共享应用服务。

#### 创建评审任务 {/* #create-the-review-task */}

在 `src` 下创建 `tasks` 目录。评审 Agent 每次只处理一个评审角度；其计算方案、五分钟超时和重试策略仅适用于这一次分析。如果模型 Provider 暂时故障，可以重试当前分析，而不必重新运行其他评审任务。

```ts title="src/tasks/review-task.ts"
import { task } from '@renderinc/sdk/workflows'
import { mastra } from '../mastra/index.js'

type Review = {
  focus: string
  feedback: string
}

export const reviewDraft = task(
  {
    name: 'review_draft',
    plan: 'starter',
    timeoutSeconds: 300,
    retry: {
      maxRetries: 2,
      waitDurationMs: 1_000,
      backoffScaling: 2,
    },
  },
  async function reviewDraft(draft: string, focus: string): Promise<Review> {
    const reviewer = mastra.getAgentById('reviewer-agent')
    const response = await reviewer.generate(`
      Review this draft for ${focus}.
      Draft: ${draft}
    `)
    if (!response.text) {
      throw new Error(`The ${focus} review returned no text`)
    }
    return {
      focus,
      feedback: response.text,
    }
  },
)
```

#### 创建修订任务 {/* #create-the-revision-task */}

此任务汇总反馈并生成修订稿，使用比各评审任务更大的计算方案和更长的超时时间。

```ts title="src/tasks/revision-task.ts"
import { task } from '@renderinc/sdk/workflows'
import { mastra } from '../mastra/index.js'

type Review = {
  focus: string
  feedback: string
}

export const reviseDraft = task(
  {
    name: 'revise_draft',
    plan: 'standard',
    timeoutSeconds: 600,
    retry: {
      maxRetries: 2,
      waitDurationMs: 1_000,
      backoffScaling: 2,
    },
  },
  async function reviseDraft(draft: string, reviews: Review[]): Promise<{ draft: string }> {
    const editor = mastra.getAgentById('editor-agent')
    const response = await editor.generate(`
      Revise the draft using the review feedback.
      Draft: ${draft}
      Reviews: ${JSON.stringify(reviews, null, 2)}
    `)
    if (!response.text) {
      throw new Error('The editor returned no text')
    }
    return {
      draft: response.text,
    }
  },
)
```

#### 创建编排任务 {/* #create-the-orchestration-task */}

父任务通过 `Promise.all()` 并行发起三个评审任务，再将汇总后的反馈交给修订任务。此层不启用重试，因为每个子任务都有自己的重试策略。如果启用编排任务的重试，请确保再次执行不会重复触发外部副作用或其他非幂等操作。

```ts title="src/tasks/editorial-task.ts"
import { task } from '@renderinc/sdk/workflows'
import { reviewDraft } from './review-task.js'
import { reviseDraft } from './revision-task.js'

export const editorialPipeline = task(
  {
    name: 'editorial_pipeline',
    plan: 'starter',
    timeoutSeconds: 1_200,
    retry: {
      maxRetries: 0,
      waitDurationMs: 1_000,
      backoffScaling: 2,
    },
  },
  async function editorialPipeline(draft: string): Promise<{ draft: string }> {
    const focuses = ['technical clarity', 'structure and flow', 'reader usefulness']
    const reviews = await Promise.all(focuses.map(focus => reviewDraft(draft, focus)))
    return reviseDraft(draft, reviews)
  },
)
```

#### 注册任务 {/* #register-the-tasks */}

创建 `src/index.ts` 并导入编辑任务：

```ts title="src/index.ts"
import './tasks/editorial-task.js'
```

运行入口文件时，模块会加载，并注册其中通过 `task()` 定义的各个任务。

修改 `tsconfig.json`：

```json title="tsconfig.json"
{
  "compilerOptions": {
    "module": "NodeNext",
    "moduleResolution": "NodeNext",
    "rootDir": "src",
    "outDir": "dist",
    "noEmit": false
  }
}
```

将以下脚本添加到 `package.json`：

```json title="package.json"
{
  "scripts": {
    "build": "tsc",
    "dev:workflows": "tsx src/index.ts",
    "start:workflows": "node dist/index.js"
  }
}
```

以上文件构成完整的流水线。[render-examples/render-workflows-mastra](https://github.com/render-examples/render-workflows-mastra) 采用相同的 `src/` 目录结构，并添加了用于启动父任务的 Web 界面。

### 运行管道 {/* #run-the-pipeline */}

#### 本地运行 {/* #local */}

启动本地 Render Workflows 开发服务器：

```bash
render workflows dev -- "npm run dev:workflows"
```

在另一个终端中，列出已注册的任务：

```bash
render workflows tasks list --local
```

启动编辑管道：

```bash
render workflows tasks start editorial_pipeline \
  --local \
  --input='["Render Workflows runs long-running tasks outside the request lifecycle."]'
```

本地服务器将任务运行及其日志保存在内存中。运行结束后，可以通过 `render workflows runs list <task-name> --local` 查看。

#### 生产环境 {/* #production */}

要在 Render 上运行流水线，需要创建一个 *Workflow 服务*。该 Render 服务保存任务定义：它构建代码仓库、注册找到的每个任务，并为每次运行预置一个实例。

<Steps>
  <StepItem>
    #### 将项目推送到 Git 存储库 {/* #push-the-project-to-a-git-repository */}

    Render 从 GitHub、GitLab 或 Bitbucket 上的代码仓库构建 Workflow 服务，因此请将项目推送到其中一个平台。首次使用该平台时，Render 会请求访问代码仓库的权限。
  </StepItem>

  <StepItem>
    #### 创建 Workflow 服务 {/* #create-the-workflow-service */}

    在 [Render Dashboard](https://dashboard.render.com?utm_source=partner\&utm_medium=partnerships\&utm_campaign=2026_partnership_mastra) 中选择 **New > Workflow**，关联上一步的代码仓库，然后填写创建表单：

    | 字段 | 值 |
    | - | - |
    |**Language** | Node |
    | **Region** | 任务所连接的其他 Render 服务所在的区域 |
    | **Build Command** | `npm install && npm run build` |
    | **Start Command** | `npm run start:workflows` |

    点击 **Deploy Workflow**。Render 会构建项目并注册 `review_draft`、`revise_draft` 和 `editorial_pipeline`；随后可在该 Workflow 的 **Tasks** 页面看到这些任务。

    也可以通过 Render CLI 在终端中创建相同的服务：

    ```bash
    render workflows create \
      --name mastra-workflows \
      --repo . \
      --runtime node \
      --build-command "npm install && npm run build" \
      --run-command "npm run start:workflows"
    ```

    `--repo .` 会读取本地代码仓库的 `origin` 远端，因此必须先推送项目。
  </StepItem>

  <StepItem>
    #### 设置 Workflow 环境变量 {/* #set-the-workflows-environment-variables */}

    首次运行前，在 Dashboard 中为 Workflow 服务添加 `OPENAI_API_KEY`，或所选模型 Provider 的密钥。
  </StepItem>

  <StepItem>
    #### 启动运行 {/* #start-a-run */}

    ```bash
    render workflows tasks start mastra-workflows/editorial_pipeline \
      --input='["Render Workflows runs long-running tasks outside the request lifecycle."]'
    ```

    该标识符的第一部分是 Workflow 的 slug，第二部分是任务名称。两者都显示在 Render Dashboard 的任务页面上。如果你的 Workflow 名称不同，请使用该页面显示的 slug。

    在 Render Dashboard 中打开该 Workflow，可查看每个任务的运行、尝试次数、结果和日志流。
  </StepItem>
</Steps>

### 从您的应用程序触发 {/* #trigger-from-your-application */}

你可以使用 Render SDK，从 Mastra 应用、Web Service 或脚本异步触发流水线。

通过代码触发运行需要 Render API 密钥，可在 [Render 账号设置](https://render.com/docs/api?utm_source=partner\&utm_medium=partnerships\&utm_campaign=2026_partnership_mastra#1-create-an-api-key)中创建。请在调用方服务中设置：

```text title=".env"
RENDER_API_KEY=rnd_your_api_key
```

SDK 会自动从环境变量中读取 `RENDER_API_KEY`。

启动任务，并立即返回运行 ID：

```ts title="src/start-editorial-pipeline.ts"
import { Render } from '@renderinc/sdk'

const render = new Render()

export async function startEditorialPipeline(draft: string) {
  const run = await render.workflows.startTask('mastra-workflows/editorial_pipeline', [draft])

  return {
    taskRunId: run.taskRunId,
  }
}
```

`startTask()` 返回后，任务仍会继续运行。如果调用方需要等待完成结果，请改为调用 `await run.get()`。

请求处理程序返回任务运行 ID 后，应用即可响应，无需在整个流水线运行期间保持请求连接。
