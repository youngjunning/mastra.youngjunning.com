# 亚马逊基岩Agent核心

将您的 Mastra 应用程序部署到[Amazon Bedrock AgentCore Runtime](https://docs.aws.amazon.com/bedrock-agentcore/)使用[AgentCore CLI](https://github.com/aws/agentcore-cli)。 CLI 搭建了一个自带代码 (BYO) TypeScript 项目的支架，使用 AWS CodeBuild 构建容器，并配置运行时。部署不需要本地 Docker 守护程序。

本指南遵循[official AgentCore TypeScript walkthrough](https://docs.aws.amazon.com/bedrock-agentcore/latest/devguide/runtime-get-started-cli-typescript.html) and adapts it to call a Mastra agent from the invocation handler.

：：：笔记

有关完整 Mastra 服务器的基于 Lambda 的部署，请参阅[AWS Lambda guide](/integrations/deploy/aws-lambda). For a long-lived virtual machine, see the [Amazon EC2 guide](/integrations/deploy/amazon-ec2).

:::

## 开始之前 {/* #before-you-begin */}

你需要：

* 一个[AWS account](https://aws.amazon.com/) with permissions for Amazon Bedrock AgentCore, AWS CodeBuild, Amazon ECR, and AWS IAM
* [AWS CLI](https://aws.amazon.com/cli/)安装并经过身份验证（`aws configure` or `aws sso login`)
* Node.js`v22.13.0` or later installed
* [码头工人](https://www.docker.com/), [Podman](https://podman.io/), or [Finch](https://runfinch.com/) for local testing with `agentcore dev` (not required for `agentcore deploy`)

Amazon Bedrock AgentCore 运行时适用于[a subset of AWS Regions](https://docs.aws.amazon.com/bedrock-agentcore/latest/devguide/agentcore-regions.html). Use a region where AgentCore is available and where the foundation models you plan to call are enabled.

## 创建一个新的AgentCore项目 {/* #create-a-new-agentcore-project */}

运行以下命令创建新的AgentCore项目：

```bash npm2yarn
npx @aws/agentcore create --name MastraOnAgentCore --no-agent
```

导航到新创建的`MastraOnAgentCore` directory:

```bash
cd MastraOnAgentCore
```

初始化将在内部创建的 BYO TypeScript Agent`app/MastraAgent`:

```bash npm2yarn
npx @aws/agentcore add agent --name MastraAgent --type byo --build Container --language TypeScript --framework Strands --model-provider Bedrock --code-location app/MastraAgent
```

CLI 将修改`agentcore/agentcore.json` file and create an empty `app/MastraAgent` directory.

## 设置Agent项目 {/* #set-up-the-agent-project */}

导航至`app/MastraAgent` directory and initialize a new Node.js project:

```bash
cd app/MastraAgent
npm init --init-type=module -y
```

安装所需的依赖项。这`bedrock-agentcore` package provides the `BedrockAgentCoreApp` HTTP server that implements the [AgentCore Runtime service contract](https://docs.aws.amazon.com/bedrock-agentcore/latest/devguide/runtime-service-contract.html). The `@ai-sdk/amazon-bedrock` and `@aws-sdk/credential-providers` packages let the Mastra agent call Bedrock through the AgentCore Runtime execution role:

```bash npm2yarn
npm install bedrock-agentcore @opentelemetry/auto-instrumentations-node @ai-sdk/amazon-bedrock @aws-sdk/credential-providers --legacy-peer-deps
```

还要安装 TypeScript 和相关的开发依赖项：

```bash npm2yarn
npm install --save-dev typescript @types/node tsx
```

跑步[`mastra init`](/reference/cli/mastra#mastra-init) to set up a new Mastra project. The provider you choose at the prompt is overwritten in the next step, so any value works:

```bash npm2yarn
npx mastra@latest init
```

替换生成的`src/mastra/agents/weather-agent.ts` to use Amazon Bedrock. The original `memory: new Memory()` is removed because the storage layer is removed in the next step:

```ts title="app/MastraAgent/src/mastra/agents/weather-agent.ts"
import { Agent } from '@mastra/core/agent'
import { createAmazonBedrock } from '@ai-sdk/amazon-bedrock'
import { fromNodeProviderChain } from '@aws-sdk/credential-providers'
import { weatherTool } from '../tools/weather-tool.js'

const bedrock = createAmazonBedrock({
  credentialProvider: fromNodeProviderChain(),
})

export const weatherAgent = new Agent({
  id: 'weather-agent',
  name: 'Weather Agent',
  instructions:
    'You are a helpful weather assistant. Use the weatherTool to fetch current weather data.',
  model: bedrock('us.anthropic.claude-sonnet-4-6'),
  tools: { weatherTool },
})
```

：：：笔记

`fromNodeProviderChain()`让Agent通过标准 SDK 解析链（环境变量、共享配置文件、SSO 以及容器或 EC2 角色）获取 AWS 凭证，而不仅仅是环境变量。

:::

替换生成的`src/mastra/index.ts` to remove the default file-based storage and observability config. AgentCore Runtime containers run as a non-root user with a read-only application directory, so the default `LibSQLStore` can't open `./mastra.db` and the runtime fails at startup:

```ts title="app/MastraAgent/src/mastra/index.ts"
import { Mastra } from '@mastra/core/mastra'
import { PinoLogger } from '@mastra/loggers'
import { weatherWorkflow } from './workflows/weather-workflow.js'
import { weatherAgent } from './agents/weather-agent.js'

export const mastra = new Mastra({
  workflows: { weatherWorkflow },
  agents: { weatherAgent },
  logger: new PinoLogger({
    name: 'Mastra',
    level: 'info',
  }),
})
```

创建一个`tsconfig.json` file with the following content:

```json title="app/MastraAgent/tsconfig.json"
{
  "compilerOptions": {
    "outDir": "./dist",
    "rootDir": ".",
    "strict": true,
    "esModuleInterop": true,
    "skipLibCheck": true,
    "types": ["node"],
    "declaration": true,
    "target": "ES2022",
    "module": "NodeNext",
    "moduleResolution": "NodeNext",
    "forceConsistentCasingInFileNames": true
  },
  "include": ["*.ts", "src/**/*"],
  "exclude": ["node_modules", "dist"]
}
```

：：：笔记

添加后`tsconfig.json` file your editor will show errors inside the generated `src/mastra` project. This is expected since the configuration now requires file extensions on imports. You can fix these by adding `.js`, for example:

```ts title="app/MastraAgent/src/mastra/index.ts"
// Before
import { weatherWorkflow } from './workflows/weather-workflow'
// After
import { weatherWorkflow } from './workflows/weather-workflow.js'
```

:::

更新您的`package.json` to set the entry point and build scripts. Using `npm pkg set` preserves the dependencies that `mastra init` added:

```bash
npm pkg set main=dist/agent.js scripts.build=tsc scripts.start="node dist/agent.js" scripts.dev="npx tsx --watch agent.ts"
```

## 初始化Agent {/* #initialize-the-agent */}

创建一个`agent.ts` file. This handler is called for every `POST /invocations` request. Resolve the Mastra agent and call it inside the handler:

```ts title="app/MastraAgent/agent.ts"
import { BedrockAgentCoreApp } from 'bedrock-agentcore/runtime'
import { mastra } from './src/mastra/index.js'

const app = new BedrockAgentCoreApp({
  invocationHandler: {
    process: async (payload, context) => {
      const { prompt } = payload as { prompt: string }

      const agent = mastra.getAgentById('weather-agent')
      const response = await agent.generate(prompt, {
        runId: context.sessionId,
      })

      return response.text
    },
  },
})

app.run()
```

跑步`npm run build` to verify that your project compiles successfully.

## 创建 Dockerfile {/* #create-a-dockerfile */}

创建一个`Dockerfile` in the `app/MastraAgent` directory. Container-based deployment uses a multi-stage Docker build: the builder stage compiles TypeScript to JavaScript, and the production stage runs only the compiled output. The image runs as a non-root user for security, and exposes port 8080 (HTTP), port 8000 (MCP), and port 9000 (A2A). OpenTelemetry instrumentation is included automatically at startup.

```dockerfile title="app/MastraAgent/Dockerfile"
FROM node:22-slim AS builder

WORKDIR /app
COPY package*.json ./
RUN npm ci
COPY . .
RUN npm run build

FROM node:22-slim
WORKDIR /app
ENV AWS_REGION=us-east-1
COPY --from=builder /app/dist ./dist
COPY --from=builder /app/node_modules ./node_modules
COPY --from=builder /app/package*.json ./

RUN useradd -m bedrock_agentcore
USER bedrock_agentcore

EXPOSE 8080 8000 9000
CMD ["node", "--require", "@opentelemetry/auto-instrumentations-node/register", "dist/agent.js"]
```

：：：笔记

选择一个`AWS_REGION` that pairs with your Bedrock model ID prefix (`us.`, `jp.`, `eu.`, or `global.`).

:::

还创建一个`.dockerignore` file to exclude unnecessary files from the Docker build context:

```bash
node_modules
dist
.git
*.log
```

## 测试你的Agent {/* #test-your-agent */}

返回项目根目录：

```bash
cd ../..
```

在本地测试您的Agent：

```bash npm2yarn
npx @aws/agentcore dev --runtime MastraAgent
```

在单独的终端中，发送测试请求：

```bash npm2yarn
npx @aws/agentcore dev "What is the weather in Tokyo?"
```

## 部署您的Agent {/* #deploy-your-agent */}

设置 AWS 账户和区域`agentcore/aws-targets.json`:

```json title="agentcore/aws-targets.json"
[
  {
    "name": "default",
    "account": "123456789012",
    "region": "us-east-1"
  }
]
```

部署到 AgentCore 运行时。 CLI 使用 AWS CodeBuild 构建映像，将其推送到 Amazon ECR，并创建运行时和`DEFAULT` endpoint:

```bash npm2yarn
npx @aws/agentcore deploy
```

：：：笔记

设置Provider API 密钥和其他机密`agentcore/agentcore.json` under the agent's `environmentVariables` field before deploying.

:::

## 验证您的部署 {/* #verify-your-deployment */}

跑步`agentcore status` to view the runtime ARN, endpoint, and recent invocations. Then call the deployed agent from the CLI:

```bash
npx @aws/agentcore invoke "What is the weather in Tokyo?"
```

要在生成令牌时流式传输令牌，请使用`--stream`:

```bash
npx @aws/agentcore invoke --stream "Plan a 3-day trip to Tokyo"
```
