# Amazon Bedrock AgentCore

使用 [AgentCore CLI](https://github.com/aws/agentcore-cli) 将 Mastra 应用部署到 [Amazon Bedrock AgentCore Runtime](https://docs.aws.amazon.com/bedrock-agentcore/)。CLI 会为自带代码（BYO）的 TypeScript 项目生成脚手架，通过 AWS CodeBuild 构建容器，并创建运行时资源。部署时无需运行本地 Docker 守护进程。

本指南以 [AgentCore 官方 TypeScript 入门教程](https://docs.aws.amazon.com/bedrock-agentcore/latest/devguide/runtime-get-started-cli-typescript.html)为基础，将示例改为在调用处理函数中调用 Mastra Agent。

:::note

如需使用 Lambda 部署完整的 Mastra 服务器，请参阅 [AWS Lambda 指南](/integrations/deploy/aws-lambda)。如需在长期运行的虚拟机上部署，请参阅 [Amazon EC2 指南](/integrations/deploy/amazon-ec2)。

:::

## 前置条件 {/* #before-you-begin */}

你需要：

* 一个有权访问 Amazon Bedrock AgentCore、AWS CodeBuild、Amazon ECR 和 AWS IAM 的 [AWS 账号](https://aws.amazon.com/)
* 已安装并完成身份验证的 [AWS CLI](https://aws.amazon.com/cli/)（使用 `aws configure` 或 `aws sso login`）
* 已安装 Node.js `v22.13.0` 或更高版本
* [Docker](https://www.docker.com/)、[Podman](https://podman.io/) 或 [Finch](https://runfinch.com/)，用于通过 `agentcore dev` 进行本地测试（执行 `agentcore deploy` 时无需安装）

Amazon Bedrock AgentCore Runtime 仅在[部分 AWS 区域](https://docs.aws.amazon.com/bedrock-agentcore/latest/devguide/agentcore-regions.html)提供。请选择支持 AgentCore 且已启用你打算调用的基础模型的区域。

## 创建 AgentCore 项目 {/* #create-a-new-agentcore-project */}

运行以下命令创建 AgentCore 项目：

```bash npm2yarn
npx @aws/agentcore create --name MastraOnAgentCore --no-agent
```

进入刚创建的 `MastraOnAgentCore` 目录：

```bash
cd MastraOnAgentCore
```

初始化一个自带代码（BYO）的 TypeScript Agent，创建位置为 `app/MastraAgent`：

```bash npm2yarn
npx @aws/agentcore add agent --name MastraAgent --type byo --build Container --language TypeScript --framework Strands --model-provider Bedrock --code-location app/MastraAgent
```

CLI 会修改 `agentcore/agentcore.json`，并创建空的 `app/MastraAgent` 目录。

## 配置 Agent 项目 {/* #set-up-the-agent-project */}

进入 `app/MastraAgent` 目录，初始化 Node.js 项目：

```bash
cd app/MastraAgent
npm init --init-type=module -y
```

安装所需依赖。`bedrock-agentcore` 包提供 `BedrockAgentCoreApp` HTTP 服务器，该服务器实现了 [AgentCore Runtime 服务契约](https://docs.aws.amazon.com/bedrock-agentcore/latest/devguide/runtime-service-contract.html)。借助 `@ai-sdk/amazon-bedrock` 和 `@aws-sdk/credential-providers`，Mastra Agent 可以使用 AgentCore Runtime 的执行角色调用 Bedrock。

```bash npm2yarn
npm install bedrock-agentcore @opentelemetry/auto-instrumentations-node @ai-sdk/amazon-bedrock @aws-sdk/credential-providers --legacy-peer-deps
```

接着安装 TypeScript 和相关开发依赖：

```bash npm2yarn
npm install --save-dev typescript @types/node tsx
```

运行 [`mastra init`](/reference/cli/mastra#mastra-init) 初始化 Mastra 项目。提示选择 Provider 时任选一项即可，下一步会覆盖该设置。

```bash npm2yarn
npx mastra@latest init
```

替换生成的 `src/mastra/agents/weather-agent.ts`，让 Agent 使用 Amazon Bedrock。由于下一步会移除存储层，此处也要删掉原有的 `memory: new Memory()`。

```ts title="app/MastraAgent/src/mastra/agents/weather-agent.ts"
import { Agent } from '@mastra/core/agent'
import { createAmazonBedrock } from '@ai-sdk/amazon-bedrock'
import { fromNodeProviderChain } from '@aws-sdk/credential-providers'
import { weatherTool } from '../tools/weather-tool.js'

const bedrock = createAmazonBedrock({
  credentialProvider: fromNodeProviderChain(),
})

export const weatherAgent = new Agent({
  id: 'weather-agent',
  name: 'Weather Agent',
  instructions:
    'You are a helpful weather assistant. Use the weatherTool to fetch current weather data.',
  model: bedrock('us.anthropic.claude-sonnet-4-6'),
  tools: { weatherTool },
})
```

:::note

`fromNodeProviderChain()` 让 Agent 按 SDK 的标准凭证解析链获取 AWS 凭证，来源包括环境变量、共享配置文件、SSO 以及容器或 EC2 角色。

:::

替换生成的 `src/mastra/index.ts`，移除默认的文件存储和可观测性配置。AgentCore Runtime 容器以非 root 用户身份运行，应用目录为只读。默认的 `LibSQLStore` 因此无法打开 `./mastra.db`，导致运行时启动失败。

```ts title="app/MastraAgent/src/mastra/index.ts"
import { Mastra } from '@mastra/core/mastra'
import { PinoLogger } from '@mastra/loggers'
import { weatherWorkflow } from './workflows/weather-workflow.js'
import { weatherAgent } from './agents/weather-agent.js'

export const mastra = new Mastra({
  workflows: { weatherWorkflow },
  agents: { weatherAgent },
  logger: new PinoLogger({
    name: 'Mastra',
    level: 'info',
  }),
})
```

创建 `tsconfig.json`，写入以下内容：

```json title="app/MastraAgent/tsconfig.json"
{
  "compilerOptions": {
    "outDir": "./dist",
    "rootDir": ".",
    "strict": true,
    "esModuleInterop": true,
    "skipLibCheck": true,
    "types": ["node"],
    "declaration": true,
    "target": "ES2022",
    "module": "NodeNext",
    "moduleResolution": "NodeNext",
    "forceConsistentCasingInFileNames": true
  },
  "include": ["*.ts", "src/**/*"],
  "exclude": ["node_modules", "dist"]
}
```

:::note

添加 `tsconfig.json` 后，编辑器会在生成的 `src/mastra` 项目中报错，因为新配置要求导入路径包含文件扩展名。在相应路径末尾补上 `.js` 即可修复，例如：

```ts title="app/MastraAgent/src/mastra/index.ts"
// Before
import { weatherWorkflow } from './workflows/weather-workflow'
// After
import { weatherWorkflow } from './workflows/weather-workflow.js'
```

:::

更新 `package.json`，设置入口文件和构建脚本。使用 `npm pkg set` 可以保留 `mastra init` 添加的依赖。

```bash
npm pkg set main=dist/agent.js scripts.build=tsc scripts.start="node dist/agent.js" scripts.dev="npx tsx --watch agent.ts"
```

## 初始化 Agent {/* #initialize-the-agent */}

创建 `agent.ts`。每个 `POST /invocations` 请求都会触发这里定义的处理函数。在函数中获取并调用 Mastra Agent：

```ts title="app/MastraAgent/agent.ts"
import { BedrockAgentCoreApp } from 'bedrock-agentcore/runtime'
import { mastra } from './src/mastra/index.js'

const app = new BedrockAgentCoreApp({
  invocationHandler: {
    process: async (payload, context) => {
      const { prompt } = payload as { prompt: string }

      const agent = mastra.getAgentById('weather-agent')
      const response = await agent.generate(prompt, {
        runId: context.sessionId,
      })

      return response.text
    },
  },
})

app.run()
```

运行 `npm run build`，确认项目能够成功编译。

## 创建 Dockerfile {/* #create-a-dockerfile */}

在 `app/MastraAgent` 目录下创建 `Dockerfile`。容器部署采用 Docker 多阶段构建。构建阶段将 TypeScript 编译为 JavaScript，生产阶段仅运行编译产物。出于安全考虑，容器以非 root 用户身份运行，并暴露 8080（HTTP）、8000（MCP）和 9000（A2A）端口。启动时会自动加载 OpenTelemetry 插桩。

```dockerfile title="app/MastraAgent/Dockerfile"
FROM node:22-slim AS builder

WORKDIR /app
COPY package*.json ./
RUN npm ci
COPY . .
RUN npm run build

FROM node:22-slim
WORKDIR /app
ENV AWS_REGION=us-east-1
COPY --from=builder /app/dist ./dist
COPY --from=builder /app/node_modules ./node_modules
COPY --from=builder /app/package*.json ./

RUN useradd -m bedrock_agentcore
USER bedrock_agentcore

EXPOSE 8080 8000 9000
CMD ["node", "--require", "@opentelemetry/auto-instrumentations-node/register", "dist/agent.js"]
```

:::note

将 `AWS_REGION` 设置为与 Bedrock 模型 ID 前缀（`us.`、`jp.`、`eu.` 或 `global.`）匹配的区域。

:::

再创建 `.dockerignore`，将不需要的文件排除在 Docker 构建上下文之外：

```bash
node_modules
dist
.git
*.log
```

## 测试 Agent {/* #test-your-agent */}

回到项目根目录：

```bash
cd ../..
```

在本地启动 Agent 进行测试：

```bash npm2yarn
npx @aws/agentcore dev --runtime MastraAgent
```

另开一个终端，发送测试请求：

```bash npm2yarn
npx @aws/agentcore dev "What is the weather in Tokyo?"
```

## 部署 Agent {/* #deploy-your-agent */}

在 `agentcore/aws-targets.json` 中设置 AWS 账号和区域：

```json title="agentcore/aws-targets.json"
[
  {
    "name": "default",
    "account": "123456789012",
    "region": "us-east-1"
  }
]
```

部署到 AgentCore Runtime。CLI 会使用 AWS CodeBuild 构建镜像，将镜像推送到 Amazon ECR，并创建运行时及 `DEFAULT` 端点。

```bash npm2yarn
npx @aws/agentcore deploy
```

:::note

部署前，在 `agentcore/agentcore.json` 中该 Agent 的 `environmentVariables` 字段下设置 Provider API 密钥和其他机密信息。

:::

## 验证部署 {/* #verify-your-deployment */}

运行 `agentcore status` 查看运行时 ARN、端点和近期调用记录，然后通过 CLI 调用已部署的 Agent：

```bash
npx @aws/agentcore invoke "What is the weather in Tokyo?"
```

如需在生成 token 时实时接收输出，请使用 `--stream`：

```bash
npx @aws/agentcore invoke --stream "Plan a 3-day trip to Tokyo"
```
