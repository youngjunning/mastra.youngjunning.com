# 云耀

Mastra 提供两种 Cloudflare 存储实现：

* **Cloudflare KV** (`CloudflareKVStorage`): A globally distributed, eventually consistent key-value store
* **Cloudflare 耐用对象** (`CloudflareDOStorage`): A strongly consistent, SQLite-based storage using Durable Objects

:::警告\[不支持可观察性]

Cloudflare 存储**doesn't support the observability domain**. Traces from the `MastraStorageExporter` can't be persisted, and [Studio's](/docs/studio/overview) observability features won't work with Cloudflare as your only storage provider. To enable observability, use [composite storage](/reference/storage/composite#specialized-storage-for-observability)将Observability数据路由到受支持的Provider（例如 ClickHouse）。

:::

## 安装 {/* #installation */}

```bash npm2yarn
npm install @mastra/cloudflare@latest
```

## Cloudflare KV 存储 {/* #cloudflare-kv-storage */}

KV 存储实现使用 Cloudflare Workers KV 提供全球分布式、无服务器键值存储解决方案。

### 用法 {/* #usage */}

```typescript
import { CloudflareKVStorage } from '@mastra/cloudflare/kv'

// --- Example 1: Using Workers Binding ---
const storageWorkers = new CloudflareKVStorage({
  id: 'cloudflare-workers-storage',
  bindings: {
    threads: THREADS_KV, // KVNamespace binding for threads table
    messages: MESSAGES_KV, // KVNamespace binding for messages table
    // Add other tables as needed
  },
  keyPrefix: 'dev_', // Optional: isolate keys per environment
})

// --- Example 2: Using REST API ---
const storageRest = new CloudflareKVStorage({
  id: 'cloudflare-rest-storage',
  accountId: process.env.CLOUDFLARE_ACCOUNT_ID!, // Cloudflare Account ID
  apiToken: process.env.CLOUDFLARE_API_TOKEN!, // Cloudflare API Token
  namespacePrefix: 'dev_', // Optional: isolate namespaces per environment
})
```

### 附加说明 {/* #additional-notes */}

### 模式管理 {/* #schema-management */}

存储实现自动处理模式创建和更新。它创建以下表：

* `threads`：存储对话线程
* `messages`：存储单独的消息
* `metadata`：存储线程和消息的附加元数据

### 一致性和传播 {/* #consistency--propagation */}

Cloudflare KV 是最终一致的存储，这意味着写入后数据可能无法在所有区域立即可用。

:::警告\[正在跨 Workers 恢复运行]

对 KV 的写入可能需要大约 60 秒才能到达其他位置。如果一名工作人员暂停Workflow程或[durable agent](/docs/harness/durable-agents) run and a different Worker resumes it soon after, for example when a user approves a tool call quickly, the resume can read an older snapshot. It then fails with `AGENT_RESUME_NO_SNAPSHOT_FOUND` or `WORKFLOW_RUN_NOT_SUSPENDED`, or resumes from an earlier step.

如果运行可以由与暂停运行的不同的工作程序或进程恢复，请使用[Cloudflare Durable Objects storage](#cloudflare-durable-objects-storage) instead.

:::

### 关键结构和命名空间 {/* #key-structure--namespacing */}

Cloudflare KV 中的键的结构为可配置前缀和表特定格式的组合（例如，`threads:threadId`).
For Workers deployments, `keyPrefix` is used to isolate data within a namespace; for REST API deployments, `namespacePrefix` is used to isolate entire namespaces between environments or applications.

## Cloudflare 持久对象存储 {/* #cloudflare-durable-objects-storage */}

Durable Objects 存储实现使用 Cloudflare Durable Objects 提供高度一致、基于 SQLite 的存储。这对于需要事务一致性和 SQL 查询功能的应用程序来说是理想的选择。

### 用法 {/* #usage-1 */}

```typescript
import { DurableObject } from 'cloudflare:workers'
import { CloudflareDOStorage } from '@mastra/cloudflare/do'

class AgentDurableObject extends DurableObject<Env> {
  private storage: CloudflareDOStorage

  constructor(ctx: DurableObjectState, env: Env) {
    super(ctx, env)
    this.storage = new CloudflareDOStorage({
      sql: ctx.storage.sql,
      tablePrefix: 'mastra_', // Optional: prefix for table names
    })
  }

  async run() {
    const memory = await this.storage.getStore('memory')
    await memory?.saveThread({
      thread: { id: 'thread-1', resourceId: 'user-1', title: 'Chat', metadata: {} },
    })
  }
}
```

### 一致性强 {/* #strong-consistency */}

与 KV 不同，持久对象提供强一致性保证。持久对象中的所有读取和写入都是序列化的，使其非常适合快速、长时间运行的Agent。

### SQL 功能 {/* #sql-capabilities */}

持久对象存储在底层使用 SQLite，实现键值存储无法实现的高效查询、过滤和分页。

## 模式管理 {/* #schema-management-1 */}

两种存储实现都会自动处理模式创建和更新。他们创建了下表：

* `threads`：存储对话线程
* `messages`：存储单独的消息
* `workflow_snapshot`：存储Workflow运行状态

## 已弃用的别名 {/* #deprecated-aliases */}

为了向后兼容，可以使用以下别名：

```typescript
// These are deprecated - use CloudflareKVStorage and CloudflareDOStorage instead
import { CloudflareStore } from '@mastra/cloudflare/kv' // alias for CloudflareKVStorage
import { DOStore } from '@mastra/cloudflare/do' // alias for CloudflareDOStorage
```
