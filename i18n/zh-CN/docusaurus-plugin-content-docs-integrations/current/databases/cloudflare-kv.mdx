# Cloudflare

Mastra 提供两种 Cloudflare 存储实现：

* **Cloudflare KV**（`CloudflareKVStorage`）：全球分布式键值存储，提供最终一致性
* **Cloudflare Durable Objects**（`CloudflareDOStorage`）：基于 SQLite 的强一致性存储，由 Durable Objects 提供

:::warning[不支持可观测性]

Cloudflare 存储**不支持可观测性数据的存储**。仅使用 Cloudflare 存储时，`MastraStorageExporter` 导出的追踪数据无法持久化，[Studio](/docs/studio/overview) 的可观测性功能也无法使用。要启用可观测性，请使用[组合存储](/reference/storage/composite#specialized-storage-for-observability)，将可观测性数据路由到 ClickHouse 等支持该功能的存储提供方。

:::

## 安装 {/* #installation */}

```bash npm2yarn
npm install @mastra/cloudflare@latest
```

## Cloudflare KV 存储 {/* #cloudflare-kv-storage */}

此实现使用 Cloudflare Workers KV 提供全球分布式无服务器键值存储。

### 用法 {/* #usage */}

```typescript
import { CloudflareKVStorage } from '@mastra/cloudflare/kv'

// --- Example 1: Using Workers Binding ---
const storageWorkers = new CloudflareKVStorage({
  id: 'cloudflare-workers-storage',
  bindings: {
    threads: THREADS_KV, // KVNamespace binding for threads table
    messages: MESSAGES_KV, // KVNamespace binding for messages table
    // Add other tables as needed
  },
  keyPrefix: 'dev_', // Optional: isolate keys per environment
})

// --- Example 2: Using REST API ---
const storageRest = new CloudflareKVStorage({
  id: 'cloudflare-rest-storage',
  accountId: process.env.CLOUDFLARE_ACCOUNT_ID!, // Cloudflare Account ID
  apiToken: process.env.CLOUDFLARE_API_TOKEN!, // Cloudflare API Token
  namespacePrefix: 'dev_', // Optional: isolate namespaces per environment
})
```

### 附加说明 {/* #additional-notes */}

### 模式管理 {/* #schema-management */}

此存储实现会自动创建和更新数据库模式，并创建以下表：

* `threads`：存储对话线程
* `messages`：存储每条消息
* `metadata`：存储线程和消息的附加元数据

### 一致性和传播 {/* #consistency--propagation */}

Cloudflare KV 提供最终一致性。写入的数据可能无法立即在所有区域读取。

:::warning[在不同 Worker 之间恢复运行]

写入 KV 的数据可能需要约 60 秒才能传播到其他位置。如果一个 Worker 暂停了某次 Workflow 或[持久化 Agent](/docs/harness/durable-agents) 的运行，而另一个 Worker 很快就尝试恢复这次运行，例如用户很快批准了 Tool 调用，恢复时可能会读到旧的快照。这可能导致恢复失败并报出 `AGENT_RESUME_NO_SNAPSHOT_FOUND` 或 `WORKFLOW_RUN_NOT_SUSPENDED`，也可能导致运行从较早的步骤继续。

如果暂停和恢复同一次运行的可能是不同的 Worker 或进程，请改用 [Cloudflare Durable Objects 存储](#cloudflare-durable-objects-storage)。

:::

### 键结构与命名空间 {/* #key-structure--namespacing */}

Cloudflare KV 的键由可配置的前缀和各表特有的格式组成，例如 `threads:threadId`。
部署到 Workers 时，使用 `keyPrefix` 在同一个命名空间内隔离数据。通过 REST API 访问时，使用 `namespacePrefix` 为不同环境或应用划分各自的命名空间。

## Cloudflare Durable Objects 存储 {/* #cloudflare-durable-objects-storage */}

此实现通过 Cloudflare Durable Objects 提供基于 SQLite 的强一致性存储，适合需要事务一致性和 SQL 查询的应用。

### 用法 {/* #usage-1 */}

```typescript
import { DurableObject } from 'cloudflare:workers'
import { CloudflareDOStorage } from '@mastra/cloudflare/do'

class AgentDurableObject extends DurableObject<Env> {
  private storage: CloudflareDOStorage

  constructor(ctx: DurableObjectState, env: Env) {
    super(ctx, env)
    this.storage = new CloudflareDOStorage({
      sql: ctx.storage.sql,
      tablePrefix: 'mastra_', // Optional: prefix for table names
    })
  }

  async run() {
    const memory = await this.storage.getStore('memory')
    await memory?.saveThread({
      thread: { id: 'thread-1', resourceId: 'user-1', title: 'Chat', metadata: {} },
    })
  }
}
```

### 强一致性 {/* #strong-consistency */}

Durable Objects 保证强一致性。同一个 Durable Object 内的所有读写操作都按顺序执行，适合需要快速响应并长时间运行的 Agent。

### SQL 功能 {/* #sql-capabilities */}

Durable Objects 存储以 SQLite 为底层，可高效执行查询、筛选和分页，这些操作是键值存储无法提供的。

## 模式管理 {/* #schema-management-1 */}

两种存储实现都会自动创建和更新数据库模式，并创建以下表：

* `threads`：存储对话线程
* `messages`：存储每条消息
* `workflow_snapshot`：存储 Workflow 的运行状态

## 已弃用的别名 {/* #deprecated-aliases */}

为保持向后兼容，仍可使用以下别名：

```typescript
// These are deprecated - use CloudflareKVStorage and CloudflareDOStorage instead
import { CloudflareStore } from '@mastra/cloudflare/kv' // alias for CloudflareKVStorage
import { DOStore } from '@mastra/cloudflare/do' // alias for CloudflareDOStorage
```
