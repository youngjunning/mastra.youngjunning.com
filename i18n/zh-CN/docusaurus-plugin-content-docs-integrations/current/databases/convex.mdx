# Convex

Mastra 的 Convex 存储实现使用 [Convex](https://convex.dev) 提供无服务器存储。Convex 是一个支持实时同步和自动缓存的全栈 TypeScript 开发平台。

:::warning[不支持可观测性]

Convex 存储**不支持可观测性领域的数据**。`MastraStorageExporter` 生成的追踪记录无法持久化到 Convex。如果 Convex 是唯一的存储 Provider，[Studio](/docs/studio/overview) 的可观测性功能将无法使用。要启用这些功能，请使用[复合存储](/reference/storage/composite#specialized-storage-for-observability)，将可观测性数据交给 ClickHouse 等受支持的 Provider。

:::

:::warning[记录大小限制]
Convex 将**单条记录的大小限制为 1 MiB**。存储带有 Base64 编码附件（例如图片）的消息时，可能会超出此限制。请参阅[处理大型附件](/docs/memory/memory-processors#handling-large-attachments)了解解决方法，例如将附件上传到 S3、Cloudflare R2 或 [Convex 文件存储](https://docs.convex.dev/file-storage)等外部存储。
:::

## 安装 {/* #installation */}

```bash npm2yarn
npm install @mastra/convex@latest
```

## 配置 Convex {/* #convex-setup */}

使用 `ConvexStore` 前，请先在 Convex 项目中定义数据库模式并创建存储处理程序。
以下模式示例包含 `ConvexStore` 和 `ConvexServerCache` 的完整配置。如果只使用 `ConvexStore`，可以省略 `mastraCacheTable` 和 `mastraCacheListItemsTable`；如果还使用 `ConvexServerCache`，请保留这两张表并创建缓存处理程序。

### 1. 定义 Convex 数据库模式 {/* #1-set-up-convex-schema */}

在 `convex/schema.ts` 中添加以下代码：

```typescript
import { defineSchema } from 'convex/server'
import {
  mastraThreadsTable,
  mastraMessagesTable,
  mastraResourcesTable,
  mastraWorkflowSnapshotsTable,
  mastraScoresTable,
  mastraObservationalMemoryTable,
  mastraVectorIndexesTable,
  mastraVectorsTable,
  mastraCacheTable,
  mastraCacheListItemsTable,
  mastraDocumentsTable,
} from '@mastra/convex/schema'

export default defineSchema({
  mastra_threads: mastraThreadsTable,
  mastra_messages: mastraMessagesTable,
  mastra_resources: mastraResourcesTable,
  mastra_workflow_snapshots: mastraWorkflowSnapshotsTable,
  mastra_scorers: mastraScoresTable,
  mastra_observational_memory: mastraObservationalMemoryTable,
  mastra_vector_indexes: mastraVectorIndexesTable,
  mastra_vectors: mastraVectorsTable,
  mastra_cache: mastraCacheTable,
  mastra_cache_list_items: mastraCacheListItemsTable,
  mastra_documents: mastraDocumentsTable,
})
```

### 2. 创建存储处理程序 {/* #2-create-the-storage-handler */}

在 `convex/mastra/storage.ts` 中添加以下代码：

```typescript
import { mastraStorage } from '@mastra/convex/server'

export const handle = mastraStorage
```

如果使用 `ConvexServerCache`，请创建 `convex/mastra/cache.ts` 并添加以下代码：

```typescript
import { mastraCache } from '@mastra/convex/server'

export const handle = mastraCache
```

### 3. 部署到 Convex {/* #3-deploy-to-convex */}

```bash
npx convex dev
# or for production
npx convex deploy
```

## 用法 {/* #usage */}

```typescript
import { ConvexServerCache, ConvexStore } from '@mastra/convex'

const storage = new ConvexStore({
  id: 'convex-storage',
  deploymentUrl: process.env.CONVEX_URL!,
  adminAuthToken: process.env.CONVEX_ADMIN_KEY!,
})

const cache = new ConvexServerCache({
  deploymentUrl: process.env.CONVEX_URL!,
  adminAuthToken: process.env.CONVEX_ADMIN_KEY!,
})
```

## 构造函数示例 {/* #constructor-examples */}

```ts
import { ConvexServerCache, ConvexStore } from '@mastra/convex'

// Basic configuration
const store = new ConvexStore({
  id: 'convex-storage',
  deploymentUrl: 'https://your-project.convex.cloud',
  adminAuthToken: 'your-admin-token',
})

// With custom storage function path
const storeCustom = new ConvexStore({
  id: 'convex-storage',
  deploymentUrl: 'https://your-project.convex.cloud',
  adminAuthToken: 'your-admin-token',
  storageFunction: 'custom/path:handler',
})

// Server cache for durable stream replay and response caching
const cache = new ConvexServerCache({
  deploymentUrl: 'https://your-project.convex.cloud',
  adminAuthToken: 'your-admin-token',
  cacheFunction: 'mastra/cache:handle',
})
```

## 服务器缓存 {/* #server-cache */}

`ConvexServerCache` 基于 Convex 实现 Mastra 的服务器缓存约定。如果需要持久保存缓存状态，以支持持久化 Agent 的流式输出恢复、Workflow 流重放或响应缓存等功能，可以使用它。

`ConvexServerCache` 将每个列表项保存为独立的 Convex 文档，避免用于重放流的列表在同一文档内不断增长，有助于控制单条记录的大小。

每个标量缓存值和每个列表项各占一条 Convex 记录，都不得超出 Convex 的单条记录大小限制。重放超大列表中的一段内容时，仍受 Convex 的查询限制约束。

缓存清理和 `clear()` 分批执行，每批都有处理上限。一次客户端调用最多可循环执行 1,000 次 Convex 写入操作，每次最多处理 25 个列表项。`clear()` 正在清理某个键时，读取该键可能返回空结果，直到清理完成。

如果缓存命名空间很大，请分阶段清理，或使用范围更小的前缀，以免单次清理耗时过长。

分批清理期间，缓存元数据可能暂时进入内部 `deleted` 状态。下一轮清理会删除这些记录。在 `clear()` 完成前，请避免写入带有相同前缀的新值。

`clear()` 只删除已存储的 `keyPrefix` 与配置的 `keyPrefix` 完全一致的记录，不会通过字符串前缀匹配清除嵌套前缀下的记录。每次调用 `listPush()` 都会按缓存配置中的 `ttlMs` 刷新列表的生存时间。

请使用非空的 `keyPrefix`，除非确实希望 `clear()` 删除该部署中的所有缓存键。过期的列表记录会在读写过程中逐步回收。`clear()` 会删除该前缀下的所有记录。

`ConvexServerCache` 最适合持久保存中等频率的事件以供重放。对于高频 token 流，建议批量处理事件，或使用延迟更低的缓存后端。

`ConvexServerCache` 无法替代分布式发布/订阅传输机制。如果应用需要跨进程实时传递事件，请单独配置面向生产环境的发布/订阅后端。

## 附加说明 {/* #additional-notes */}

### 数据库模式管理 {/* #schema-management */}

存储实现为每个 Mastra 领域使用带有类型定义的 Convex 表：

| 领域 | Convex 表 | 用途 |
| - | - | - |
| 会话线程 | `mastra_threads` | 对话线程 |
| 消息 | `mastra_messages` | 聊天消息 |
| 资源 | `mastra_resources` | 用户的工作记忆 |
| 观察记忆 | `mastra_observational_memory` | 观察记忆的生成结果 |
| Workflow | `mastra_workflow_snapshots` | Workflow 状态 |
| 评分器 | `mastra_scorers` | 评估数据 |
| 缓存 | `mastra_cache` | 缓存值、计数器和列表元数据 |
| 缓存项 | `mastra_cache_list_items` | 缓存列表项 |
| 兜底存储 | `mastra_documents` | 未知表的数据 |

### 观察记忆 {/* #observational-memory */}

`ConvexStore` 支持[观察记忆](/docs/memory/observational-memory)。要启用此功能，请将 `mastraObservationalMemoryTable` 添加到 Convex 数据库模式中，再运行 `npx convex deploy` 重新部署。在引入此表之前创建的现有部署也需要进行相同的模式更新。

### 架构 {/* #architecture */}

所有带类型定义的表都包含：

* `id` 字段，用于保存 Mastra 的记录 ID（与 Convex 自动生成的 `_id` 不同）
* `by_record_id` 索引，用于按 Mastra ID 高效查找记录

这种设计符合 Mastra 的存储约定，同时利用了 Convex 的自动索引和实时功能。

### 环境变量 {/* #environment-variables */}

为您的部署设置这些环境变量：

* `CONVEX_URL`：您的 Convex 部署 URL
* `CONVEX_ADMIN_KEY`：管理员身份验证令牌（可在 Convex 控制台获取）
