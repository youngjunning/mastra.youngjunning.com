# Aurora DSQL

Aurora DSQL 存储实现通过 Amazon Aurora DSQL 提供存储，并使用 IAM 进行身份验证。

Aurora DSQL 不支持 PostgreSQL 扩展（`CREATE EXTENSION`），包括 `pgvector`。如需存储向量，请使用单独的向量存储，例如 `@mastra/s3vectors`。

## 安装 {/* #installation */}

```bash copy
npm install @mastra/dsql@beta
```

## 先决条件 {/* #prerequisites */}

- Amazon Aurora DSQL 集群
- 可通过 IAM 身份验证访问该 DSQL 集群的 AWS 凭证

## 用法 {/* #usage */}

```typescript copy showLineNumbers
import { DSQLStore } from '@mastra/dsql'

const storage = new DSQLStore({
  id: 'my-dsql-store',
  host: 'abc123.dsql.us-east-1.on.aws',
  // region is auto-detected from host, or specify explicitly:
  // region: 'us-east-1',
  // user: 'admin', // default
  // database: 'postgres', // default
})

// Initialize the store (creates tables if needed)
await storage.init()
```

## 构造函数示例 {/* #constructor-examples */}

可以通过以下方式实例化 DSQLStore：

```typescript copy showLineNumbers
import { DSQLStore } from '@mastra/dsql'

// Basic configuration (region auto-detected from host)
const store1 = new DSQLStore({
  id: 'my-dsql-store',
  host: 'abc123.dsql.us-east-1.on.aws',
})

// With explicit region and schema
const store2 = new DSQLStore({
  id: 'my-dsql-store',
  host: 'abc123.dsql.us-east-1.on.aws',
  region: 'us-east-1',
  schemaName: 'my_app',
})

// With custom credentials provider
import { fromNodeProviderChain } from '@aws-sdk/credential-providers'

const store3 = new DSQLStore({
  id: 'my-dsql-store',
  host: 'abc123.dsql.us-east-1.on.aws',
  customCredentialsProvider: fromNodeProviderChain(),
})

// With connection pool settings
const store4 = new DSQLStore({
  id: 'my-dsql-store',
  host: 'abc123.dsql.us-east-1.on.aws',
  max: 20,
  min: 2,
  idleTimeoutMillis: 300000,
  maxLifetimeSeconds: 3000,
  connectionTimeoutMillis: 10000,
})

// Using a pre-configured pg.Pool
import { Pool } from 'pg'
import { AuroraDSQLClient } from '@aws/aurora-dsql-node-postgres-connector'

const pool = new Pool({
  host: 'abc123.dsql.us-east-1.on.aws',
  Client: AuroraDSQLClient,
  region: 'us-east-1',
})

const store5 = new DSQLStore({
  id: 'my-dsql-store',
  pool,
})
```

## 补充说明 {/* #additional-notes */}

### 模式管理 {/* #schema-management */}

此存储实现会自动创建和更新模式，并创建以下表：

- `mastra_workflow_snapshot`：存储 Workflow 状态和执行数据
- `mastra_threads`：存储对话线程
- `mastra_messages`：存储单条消息
- `mastra_ai_spans`：存储用于可观测性的 span 数据
- `mastra_scorers`：存储评分和评估数据
- `mastra_resources`：存储资源的工作记忆数据
- `mastra_agents`：存储 Agent 数据

### 初始化 {/* #initialization */}

将存储实例传入 Mastra 类时，系统会在执行任何存储操作之前自动调用 `init()`：

```typescript copy showLineNumbers
import { Mastra } from '@mastra/core'
import { DSQLStore } from '@mastra/dsql'

const storage = new DSQLStore({
  id: 'my-dsql-store',
  host: 'abc123.dsql.us-east-1.on.aws',
})

const mastra = new Mastra({
  storage, // init() is called automatically
})
```

如果不通过 Mastra，而是直接使用存储实例，则必须显式调用 `init()` 来创建表：

```typescript copy showLineNumbers
import { DSQLStore } from '@mastra/dsql'

const storage = new DSQLStore({
  id: 'my-dsql-store',
  host: 'abc123.dsql.us-east-1.on.aws',
})

// Required when using storage directly
await storage.init()

// Access domain-specific stores via getStore()
const memoryStore = await storage.getStore('memory')
const thread = await memoryStore?.getThreadById({ threadId: '...' })
```

:::warning
如果未调用 `init()`，表就不会创建，存储操作可能静默失败或抛出错误。
:::

### 直接访问数据库和连接池 {/* #direct-database-and-pool-access */}

`DSQLStore` 将底层数据库客户端和 pg.Pool 实例作为公开字段提供：

```typescript copy showLineNumbers
storage.db // Database client for executing queries
storage.pool // Underlying pg.Pool instance
```

这些字段支持直接执行查询和自行管理事务。使用时请注意：

- 你需要自行正确处理连接和事务。
- 如果连接池由存储实例创建，关闭存储实例（`storage.close()`）时会销毁该连接池。
- 直接访问会绕过 `DSQLStore` 方法提供的其他逻辑或验证。

这种方式适用于需要底层访问能力的高级场景。

### Aurora DSQL 的特性 {/* #aurora-dsql-specifics */}

#### 仅支持 IAM 身份验证 {/* #iam-only-authentication */}

连接通过 IAM 进行身份验证，无需数据库密码。`@mastra/dsql` 使用 `@aws/aurora-dsql-node-postgres-connector` 生成短期有效的身份验证令牌。你可以通过 `customCredentialsProvider` 提供自定义凭证提供程序。

#### 单一数据库与基于模式的隔离 {/* #single-database-schema-based-isolation */}

每个集群仅提供一个名为 `postgres` 的数据库。逻辑隔离通过模式实现；`schemaName` 选项决定 Mastra 表创建在哪个模式中。

#### 不支持 PostgreSQL 扩展 {/* #no-postgresql-extensions */}

Aurora DSQL 不支持 `CREATE EXTENSION`，因此也不支持 `pgvector`、`PostGIS` 等扩展。如需存储向量，可在使用 `DSQLStore` 的同时使用 `@mastra/s3vectors` 等独立存储。

#### JSON 存储为文本 {/* #json-stored-as-text */}

JSON/JSONB 可用作查询类型，但不能用作列类型。`@mastra/dsql` 将元数据、内容等结构化字段存入 `TEXT` 列，并在查询时将其转换为 JSON。

#### 模式和 DDL 限制 {/* #schema-and-ddl-constraints */}

以下 PostgreSQL 功能不可用：

- 外键约束
- `TRUNCATE`
- 同步执行的 `CREATE INDEX`

索引通过 `CREATE INDEX ASYNC` 异步创建。存储实例的 `init()` 和索引辅助 API 均遵循这些限制。

#### 事务与乐观并发控制 {/* #transactions-and-optimistic-concurrency */}

Aurora DSQL 使用乐观并发控制（OCC）；发生资源争用时，可能返回可重试的 OCC 错误。事务的时长和大小都有限制。大规模批量操作应在应用层拆分为较小的批次。

#### 连接存活时间 {/* #connection-lifetime */}

单个连接的存活时间限制约为 60 分钟。默认设置 `maxLifetimeSeconds: 3300` 可确保连接在达到此限制前被回收。

## 使用示例 {/* #usage-example */}

### 为 Agent 添加记忆 {/* #adding-memory-to-an-agent */}

要让 Agent 使用 Aurora DSQL 存储记忆，请使用 `Memory` 类，并通过 `DSQLStore` 配置新的 `storage` 属性。`host` 应指向你的 Aurora DSQL 集群端点。

```typescript title="src/mastra/agents/example-dsql-agent.ts" copy showLineNumbers
import { Memory } from '@mastra/memory'
import { Agent } from '@mastra/core/agent'
import { DSQLStore } from '@mastra/dsql'

export const dsqlAgent = new Agent({
  id: 'dsql-agent',
  name: 'DSQL Agent',
  instructions:
    'You are an AI agent with the ability to automatically recall memories from previous interactions.',
  model: '__GATEWAY_OPENAI_MODEL__',
  memory: new Memory({
    storage: new DSQLStore({
      id: 'dsql-agent-storage',
      host: process.env.DSQL_HOST!,
    }),
    options: {
      generateTitle: true, // Explicitly enable automatic title generation
    },
  }),
})
```

### 使用 Agent {/* #using-the-agent */}

使用 `memoryOptions` 限定本次请求的记忆检索范围。设置 `lastMessages: 5`，限制按时间顺序召回的近期消息数量；使用 `semanticRecall` 获取最相关的 `topK: 3` 条消息，并通过 `messageRange: 2` 为每条匹配消息加入相邻消息作为上下文。

```typescript title="src/test-dsql-agent.ts" copy showLineNumbers
import 'dotenv/config'

import { mastra } from './mastra'

const threadId = '123'
const resourceId = 'user-456'

const agent = mastra.getAgent('dsql-agent')

const message = await agent.stream('My name is Mastra', {
  memory: {
    thread: threadId,
    resource: resourceId,
  },
})

await message.textStream.pipeTo(new WritableStream())

const stream = await agent.stream("What's my name?", {
  memory: {
    thread: threadId,
    resource: resourceId,
  },
  memoryOptions: {
    lastMessages: 5,
    semanticRecall: {
      topK: 3,
      messageRange: 2,
    },
  },
})

for await (const chunk of stream.textStream) {
  process.stdout.write(chunk)
}
```

## 索引管理 {/* #index-management */}

Aurora DSQL 存储提供索引管理功能，以优化查询性能。

### 自动创建的性能索引 {/* #automatic-performance-indexes */}

Aurora DSQL 存储会在初始化时，针对常见查询模式自动创建以下复合索引：

- `mastra_threads_resourceid_createdat_idx`：（resourceId、createdAt）
- `mastra_messages_thread_id_createdat_idx`：（thread_id、createdAt）
- `mastra_ai_spans_traceid_startedat_idx`：（traceId、startedAt）
- `mastra_ai_spans_parentspanid_startedat_idx`：（parentSpanId、startedAt）
- `mastra_ai_spans_name_idx`：（name）
- `mastra_ai_spans_spantype_startedat_idx`：（spanType、startedAt）
- `mastra_scores_trace_id_span_id_created_at_idx`：（traceId、spanId、createdAt）

Aurora DSQL 使用 `CREATE INDEX ASYNC` 异步创建这些索引。因此，调用 `init()` 后，新索引可能不会立即可用。即使索引尚未创建完成，存储实例仍可正常工作，但查询可能较慢。

### 创建自定义索引 {/* #creating-custom-indexes */}

可以创建其他索引，优化特定的查询模式：

```typescript copy showLineNumbers
await storage.createIndex({
  name: 'idx_threads_resource',
  table: 'mastra_threads',
  columns: ['resourceId'],
})

await storage.createIndex({
  name: 'idx_messages_composite',
  table: 'mastra_messages',
  columns: ['thread_id', 'createdAt'],
})
```

Aurora DSQL 不允许在 `CREATE INDEX ASYNC` 中使用 `ASC`/`DESC`。如果指定了这些修饰符，系统会自动将其移除。

### 管理索引 {/* #managing-indexes */}

列出并监控已有索引：

```typescript copy showLineNumbers
// List all indexes
const allIndexes = await storage.listIndexes()
console.log(allIndexes)
// [
//   {
//     name: 'mastra_threads_pkey',
//     table: 'mastra_threads',
//     columns: ['id'],
//     unique: true,
//     size: '16 KB',
//     definition: 'CREATE UNIQUE INDEX...'
//   },
//   ...

// List indexes for a specific table
const threadIndexes = await storage.listIndexes('mastra_threads')

// Get detailed statistics for an index
const stats = await storage.describeIndex('idx_threads_resource')
console.log(stats)
// {
//   name: 'idx_threads_resource',
//   table: 'mastra_threads',
//   columns: ['resourceId'],
//   unique: false,
//   size: '128 KB',
//   definition: 'CREATE INDEX idx_threads_resource...',
//   method: 'btree',
//   scans: 1542,
//   tuples_read: 45230,
//   tuples_fetched: 12050
// }

// Drop an index
await storage.dropIndex('idx_threads_status')
```

### 指定模式中的索引 {/* #schema-specific-indexes */}

使用自定义模式时，创建的索引名称会带有模式前缀：

```typescript copy showLineNumbers
const storage = new DSQLStore({
  id: 'my-dsql-store',
  host: 'abc123.dsql.us-east-1.on.aws',
  schemaName: 'custom_schema',
})

// Creates index as: custom_schema_idx_threads_status
await storage.createIndex({
  name: 'idx_threads_status',
  table: 'mastra_threads',
  columns: ['status'],
})
```
