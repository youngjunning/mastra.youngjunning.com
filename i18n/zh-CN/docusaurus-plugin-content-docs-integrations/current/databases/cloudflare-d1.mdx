# Cloudflare D1

Mastra 的 Cloudflare D1 存储使用 D1 作为无服务器 SQL 数据库，支持关系型数据操作和事务一致性。

:::warning[不支持可观测性]

Cloudflare D1 存储**不支持可观测性域**。`MastraStorageExporter` 导出的链路追踪数据无法持久化到 D1。如果 D1 是唯一的存储 Provider，[Studio](/docs/studio/overview) 的可观测性功能将无法使用。要启用可观测性，请使用[复合存储](/reference/storage/composite#specialized-storage-for-observability)，将可观测性数据发送到 ClickHouse 等支持该功能的 Provider。

:::

:::warning[单行大小限制]
Cloudflare D1 的**单行大小上限为 1 MiB**。存储包含 Base64 编码附件（例如图片）的消息时，可能会超出此限制。请参阅[处理大附件](/docs/memory/memory-processors#handling-large-attachments)，了解如何将附件上传到外部存储等解决办法。
:::

## 安装 {/* #installation */}

```bash npm2yarn
npm install @mastra/cloudflare-d1@latest
```

## 使用方法 {/* #usage */}

### 搭配 Mastra 的 CloudflareDeployer 使用 {/* #using-with-mastra-cloudflaredeployer */}

在 Cloudflare 上为 Mastra 使用 D1Store 时，标准做法是使用 `CloudflareDeployer`。从 `cloudflare:workers` 导入 `env`，然后直接在 `new Mastra({...})` 内初始化 `D1Store`。

```typescript title="src/mastra/index.ts"
import { env } from 'cloudflare:workers'
import { D1Store } from '@mastra/cloudflare-d1'
import { Mastra } from '@mastra/core'
import { CloudflareDeployer } from '@mastra/deployer-cloudflare'

export const mastra = new Mastra({
  storage: new D1Store({ binding: env.DB }),
  deployer: new CloudflareDeployer({
    name: 'my-worker',
    d1_databases: [
      {
        binding: 'DB',
        database_name: 'your-database-name',
        database_id: 'your-database-id',
      },
    ],
  }),
})
```

:::note
使用 `import { env } from 'cloudflare:workers'` 时，必须直接在 `new Mastra({...})` 内初始化 `D1Store`，不能将它提取为模块级变量。也可以等 `env` 可用后，在 `fetch` 处理函数内初始化 `D1Store`。详情请参阅 [CloudflareDeployer 参考文档](/reference/deployer/cloudflare#cloudflare-bindings)。
:::

### 在不提供 HTTP 路由的 Cloudflare Worker 中使用 {/* #using-in-a-cloudflare-worker-without-http-routes */}

如果只需在 Worker 中直接调用 Mastra（例如运行 Agent 或触发 Workflow），无需提供 HTTP 路由，就不必使用 `CloudflareDeployer`。从 Worker 的 `env` 参数获取 D1 绑定，然后通过代码调用 Mastra。

```typescript
import { D1Store } from '@mastra/cloudflare-d1'
import { Mastra } from '@mastra/core'

type Env = {
  DB: D1Database
}

export default {
  async fetch(request: Request, env: Env, ctx: ExecutionContext) {
    const mastra = new Mastra({
      storage: new D1Store({ binding: env.DB }),
    })

    const agent = mastra.getAgent('my-agent')
    const result = await agent.generate('Hello')

    return Response.json({ text: result.text })
  },
}
```

### 通过 REST API 访问 {/* #using-with-rest-api */}

在 Node.js、无服务器函数等 Workers 之外的环境中，请通过 REST API 访问 D1：

```typescript
import { D1Store } from '@mastra/cloudflare-d1'

const storage = new D1Store({
  accountId: process.env.CLOUDFLARE_ACCOUNT_ID!, // Cloudflare Account ID
  databaseId: process.env.CLOUDFLARE_D1_DATABASE_ID!, // D1 Database ID
  apiToken: process.env.CLOUDFLARE_API_TOKEN!, // Cloudflare API Token
  tablePrefix: 'dev_', // Optional: isolate tables per environment
})
```

### Wrangler 配置 {/* #wrangler-configuration */}

将 D1 数据库绑定添加到 `wrangler.toml`：

```toml
[[d1_databases]]
binding = "DB"
database_name = "your-database-name"
database_id = "your-database-id"
```

也可以添加到 `wrangler.jsonc`：

```jsonc
{
  "d1_databases": [
    {
      "binding": "DB",
      "database_name": "your-database-name",
      "database_id": "your-database-id",
    },
  ],
}
```

## 附加说明 {/* #additional-notes */}

### 数据库模式管理 {/* #schema-management */}

存储会自动创建和更新数据库模式，并创建以下表：

* `threads`：存储对话线程
* `messages`：存储每条消息
* `metadata`：存储线程和消息的附加元数据

### 初始化 {/* #initialization */}

将存储实例传给 Mastra 类后，Mastra 会在执行任何存储操作之前自动调用 `init()`：

```typescript
import { Mastra } from '@mastra/core'
import { D1Store } from '@mastra/cloudflare-d1'

type Env = {
  DB: D1Database
}

// In a Cloudflare Worker
export default {
  async fetch(request: Request, env: Env, ctx: ExecutionContext) {
    const storage = new D1Store({
      binding: env.DB,
    })

    const mastra = new Mastra({
      storage, // init() is called automatically
    })

    // Your handler logic here
    return new Response('Success')
  },
}
```

如果绕过 Mastra 直接使用存储，则必须显式调用 `init()` 来创建表：

```typescript
import { D1Store } from '@mastra/cloudflare-d1'

type Env = {
  DB: D1Database
}

// In a Cloudflare Worker
export default {
  async fetch(request: Request, env: Env, ctx: ExecutionContext) {
    const storage = new D1Store({
      id: 'd1-storage',
      binding: env.DB,
    })

    // Required when using storage directly
    await storage.init()

    // Access domain-specific stores via getStore()
    const memoryStore = await storage.getStore('memory')
    const thread = await memoryStore?.getThreadById({ threadId: '...' })

    return new Response('Success')
  },
}
```

:::warning
如果未调用 `init()`，就不会创建表，存储操作会静默失败或抛出错误。
:::

### 事务与一致性 {/* #transactions--consistency */}

Cloudflare D1 为单行操作提供事务保证。也可以将多个操作作为一个原子单元执行：要么全部成功，要么全部不生效。

### 创建和迁移表 {/* #table-creation--migrations */}

存储初始化时会自动创建表。可以通过 `tablePrefix` 选项隔离不同环境的表。添加列、修改数据类型或调整索引等更复杂的模式变更需要手动迁移，并应仔细规划，以免丢失数据。
