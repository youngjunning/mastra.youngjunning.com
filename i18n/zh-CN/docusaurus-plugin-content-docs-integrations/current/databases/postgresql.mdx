# PostgreSQL

PostgreSQL 存储实现使用 PostgreSQL 数据库提供生产就绪的存储解决方案。

## 安装 {/* #installation */}

```bash npm2yarn
npm install @mastra/pg@latest
```

## 用法 {/* #usage */}

```typescript
import { PostgresStore } from '@mastra/pg'

const storage = new PostgresStore({
  id: 'pg-storage',
  connectionString: process.env.DATABASE_URL,
})
```

## 构造函数示例 {/* #constructor-examples */}

你可以实例化`PostgresStore` in the following ways:

```ts
import { PostgresStore } from '@mastra/pg'
import { Pool } from 'pg'

// Using a connection string
const store1 = new PostgresStore({
  id: 'pg-storage-1',
  connectionString: 'postgresql://user:password@localhost:5432/mydb',
})

// Using a connection string with pool options
const store2 = new PostgresStore({
  id: 'pg-storage-2',
  connectionString: 'postgresql://user:password@localhost:5432/mydb',
  schemaName: 'custom_schema',
  max: 30, // Max pool connections
  idleTimeoutMillis: 60000, // Idle timeout
  ssl: { rejectUnauthorized: false },
})

// Using individual connection parameters
const store3 = new PostgresStore({
  id: 'pg-storage-3',
  host: 'localhost',
  port: 5432,
  database: 'mydb',
  user: 'user',
  password: 'password',
})

// Using a pre-configured pg.Pool (recommended for pool reuse)
const existingPool = new Pool({
  connectionString: 'postgresql://user:password@localhost:5432/mydb',
  max: 20,
  // ... your custom pool configuration
})

const store4 = new PostgresStore({
  id: 'pg-storage-4',
  pool: existingPool,
  schemaName: 'custom_schema', // optional
})
```

## 附加说明 {/* #additional-notes */}

### 模式管理 {/* #schema-management */}

存储实现自动处理模式创建和更新。它创建以下表：

* `mastra_workflow_snapshot`：存储Workflow状态和执行数据
* `mastra_evals`：存储评估结果和元数据
* `mastra_threads`：存储对话线程
* `mastra_messages`：存储单独的消息
* `mastra_traces`：存储遥测和跟踪数据
* `mastra_scorers`：存储评分和评价数据
* `mastra_resources`：存储资源工作内存数据
* `mastra_notifications`：存储通知收件箱记录和传递元数据

`PostgresStore`通过公开通知存储`getStore('notifications')`.

### 可观察性 {/* #observability */}

PostgreSQL 支持可观察性并可以处理低跟踪量。吞吐量容量取决于硬件、架构设计、索引和保留策略等部署因素，并且应针对您的特定环境进行验证。对于大批量生产环境，请考虑：

* 使用`insert-only` [tracing strategy](/docs/observability/integrations/exporters/mastra-storage#tracing-strategies) to reduce database write operations
* 设置表分区以有效保留数据
* 将可观察性迁移到[ClickHouse via composite storage](/reference/storage/composite#specialized-storage-for-observability) if you need to scale further

`PostgresStoreVNext`使用`event-sourced` [tracing strategy](/docs/observability/integrations/exporters/mastra-storage#tracing-strategies) instead. It writes one row when a span starts and another when it ends, never updating a row in place, and collapses those rows when a trace is read. Writes stay append-only, and traces appear in Studio while the run is still executing.

#### 过滤建议 {/* #filter-suggestions */}

Studio 的“跟踪”、“日志”和“指标”页面提供从Observability数据中发现的筛选器值（标签、服务名称、环境、实体名称、指标名称和标签）。这些值缓存在数据库中，并在缓存过时时在后台重新计算。

为了使大型数据集的刷新成本较低，它仅扫描过去 30 天的事件。不会建议仅出现在旧事件中的值，但按它们进行过滤仍然有效。使用`discovery` to change the window or how often it refreshes:

```typescript
import { PostgresStoreVNext } from '@mastra/pg'

const storage = new PostgresStoreVNext({
  id: 'pg-storage',
  connectionString: process.env.DATABASE_URL,
  observability: {
    connectionString: process.env.OBSERVABILITY_DATABASE_URL,
    discovery: {
      lookbackSeconds: 7 * 24 * 60 * 60, // scan the last 7 days; 0 scans all history
      ttlSeconds: 15 * 60, // refresh at most every 15 minutes
    },
  },
})
```

降低`lookbackSeconds` if refreshes are slow, and raise `ttlSeconds` if they run more often than your filter values change. Only one process refreshes a given cache entry at a time, so adding server instances doesn't multiply the work.

#### 日间分区 {/* #day-partitions */}

`PostgresStoreVNext`将Observability事件存储在按天分区的表中。如果安装了 TimescaleDB 或 pg\_partman，该扩展会为您创建分区。没有扩展名，`init()` creates the partitions for yesterday, today, and the next `futureDays` days (default 14), and a write that lands on a day inside that window with no partition creates it before it retries, so writes keep working after the pre-created window runs out. Rows dated outside the window are still rejected.

创建分区就是DDL。如果您的应用程序运行所使用的角色无法创建表，或者不拥有可观察性表，则写入会失败并出现命名表和缺失日期的错误，并且导出器在重试后会删除该批次。在该设置中，调用`ensurePartitions()` on a schedule, at least once every `futureDays` days, with a role that can create tables and owns the observability tables. It only extends the native day-partition window, and does nothing with TimescaleDB or pg\_partman. You can also install TimescaleDB, or pg\_partman with its background worker or a scheduled `run_maintenance()` call, so the database maintains the partitions itself.

更大的`futureDays` gives the scheduled job more time between runs:

```typescript
import { PostgresStoreVNext } from '@mastra/pg'

const storage = new PostgresStoreVNext({
  id: 'pg-storage',
  connectionString: process.env.DATABASE_URL,
  observability: {
    connectionString: process.env.OBSERVABILITY_DATABASE_URL,
    partitioning: {
      futureDays: 60, // pre-create 60 days of partitions on init()
    },
  },
})
```

然后打电话`ensurePartitions()` from the scheduled job:

```typescript
// OBSERVABILITY_DATABASE_URL connects as a role that owns the observability tables
await storage.ensurePartitions()
await storage.close()
```

### 初始化 {/* #initialization */}

当您将存储传递给 Mastra 类时，`init()` is called automatically before any storage operation:

```typescript
import { Mastra } from '@mastra/core'
import { PostgresStore } from '@mastra/pg'

const storage = new PostgresStore({
  id: 'pg-storage',
  connectionString: process.env.DATABASE_URL,
})

const mastra = new Mastra({
  storage, // init() is called automatically
})
```

如果您直接使用存储而不使用 Mastra，则必须致电`init()` explicitly to create the tables:

```typescript
import { PostgresStore } from '@mastra/pg'

const storage = new PostgresStore({
  id: 'pg-storage',
  connectionString: process.env.DATABASE_URL,
})

// Required when using storage directly
await storage.init()

// Access domain-specific stores via getStore()
const memoryStore = await storage.getStore('memory')
const thread = await memoryStore?.getThreadById({ threadId: '...' })
```

:::警告
如果`init()` isn't called, tables won't be created and storage operations will fail silently or throw errors.
:::

### 托管 PostgreSQL 和连接池 {/* #managed-postgresql-and-connection-poolers */}

`PostgresStore`使用他们提供给您的连接字符串连接到托管 PostgreSQL Provider。不需要特定于Provider的包。

`init()`在单个连接上运行所有架构更改，因此它通过事务模式连接池（例如 PgBouncer）工作。您可以使用提供程序的池连接字符串并让 Mastra 在启动时创建架构。

#### 单独的模式初始化 {/* #separate-schema-initialization */}

如果运行时数据库角色无法创建表或索引，请运行`init()` once during deployment with a role that can:

```typescript title="scripts/init-storage.ts"
import { PostgresStore } from '@mastra/pg'

const storage = new PostgresStore({
  id: 'pg-storage-init',
  connectionString: process.env.DATABASE_ADMIN_URL,
})

try {
  await storage.init()
  // Only needed if the application uses Knowledge
  await storage.initKnowledge()
} finally {
  await storage.close()
}
```

运行时角色需要对此脚本创建的表进行读写访问。看[PostgreSQL privileges](https://www.postgresql.org/docs/current/ddl-priv.html).

然后设置`disableInit: true` on the runtime store so it skips schema creation:

```typescript title="src/mastra/index.ts"
import { Mastra } from '@mastra/core'
import { PostgresStore } from '@mastra/pg'

export const mastra = new Mastra({
  storage: new PostgresStore({
    id: 'pg-storage',
    connectionString: process.env.DATABASE_URL,
    disableInit: true,
  }),
})
```

`disableInit: true`也明确表示`init()` calls a no-op, so leave it off the store in the deployment script.

### 使用现有池 {/* #using-an-existing-pool */}

如果您已经有`pg.Pool` in your application (e.g., shared with an ORM or for Row Level Security), you can pass it directly to `PostgresStore`:

```typescript
import { Pool } from 'pg'
import { PostgresStore } from '@mastra/pg'

// Your existing pool (shared across your application)
const pool = new Pool({
  connectionString: process.env.DATABASE_URL,
  max: 20,
})

const storage = new PostgresStore({
  id: 'shared-storage',
  pool: pool,
})
```

**池生命周期行为：**

* 当你**provide a pool**: Mastra uses your pool but **doesn't** close it when `store.close()` is called. You manage the pool lifecycle.
* 当马斯特拉**creates a pool**: Mastra owns the pool and will close it when `store.close()` is called.

### 直接数据库和池访问 {/* #direct-database-and-pool-access */}

`PostgresStore`公开高级用例的底层数据库客户端和池：

```typescript
store.db // DbClient - query interface with helpers (any, one, tx, etc.)
store.pool // pg.Pool - the underlying connection pool
```

**使用`store.db` for queries:**

```typescript
// Execute queries with helper methods
const users = await store.db.any('SELECT * FROM users WHERE active = $1', [true])
const user = await store.db.one('SELECT * FROM users WHERE id = $1', [userId])
const maybeUser = await store.db.oneOrNone('SELECT * FROM users WHERE email = $1', [email])

// Use transactions
const result = await store.db.tx(async t => {
  await t.none('INSERT INTO logs (message) VALUES ($1)', ['Started'])
  const data = await t.any('SELECT * FROM items')
  return data
})
```

**使用`store.pool` directly:**

```typescript
// Get a client for manual connection management
const client = await store.pool.connect()
try {
  await client.query('SET LOCAL app.user_id = $1', [userId])
  const result = await client.query('SELECT * FROM protected_table')
  return result.rows
} finally {
  client.release()
}
```

使用这些字段时：

* 您负责正确的连接和事务处理。
* 关闭商店（`store.close()`) will destroy the pool only if Mastra created it.
* 直接访问绕过 PostgresStore 方法提供的任何附加逻辑或验证。

此方法适用于需要低级别访问的高级场景。

### 与 Next.js 一起使用 {/* #using-with-nextjs */}

使用时`PostgresStore` in Next.js applications, [Hot Module Replacement (HMR)](https://nextjs.org/docs/architecture/fast-refresh) during development can cause multiple storage instances to be created, resulting in this warning:

```text
WARNING: Creating a duplicate database object for the same connection.
```

为了防止这种情况发生，请存储`PostgresStore` instance on the global object so it persists across HMR reloads:

```typescript title="src/mastra/storage.ts"
import { PostgresStore } from '@mastra/pg'
import { Memory } from '@mastra/memory'

// Extend the global type to include our instances
declare global {
  var pgStore: PostgresStore | undefined
  var memory: Memory | undefined
}

// Get or create the PostgresStore instance
function getPgStore(): PostgresStore {
  if (!global.pgStore) {
    if (!process.env.DATABASE_URL) {
      throw new Error('DATABASE_URL is not defined in environment variables')
    }
    global.pgStore = new PostgresStore({
      id: 'pg-storage',
      connectionString: process.env.DATABASE_URL,
      ssl: process.env.DATABASE_SSL === 'true' ? { rejectUnauthorized: false } : false,
    })
  }
  return global.pgStore
}

// Get or create the Memory instance
function getMemory(): Memory {
  if (!global.memory) {
    global.memory = new Memory({
      storage: getPgStore(),
    })
  }
  return global.memory
}

export const storage = getPgStore()
export const memory = getMemory()
```

然后在 Mastra 配置中使用导出的实例：

```typescript title="src/mastra/index.ts"
import { Mastra } from '@mastra/core/mastra'
import { storage } from './storage'

export const mastra = new Mastra({
  storage,
  // ...other config
})
```

该模式仅确保一个`PostgresStore` instance is created regardless of how many times the module is reloaded during development. The same pattern can be applied to other storage providers like `LibSQLStore`.

:::提示
这种单例模式仅在使用 HMR 进行本地开发时才需要。在生产版本中，模块仅加载一次。
:::

## 使用示例 {/* #usage-example */}

### 为Agent添加内存 {/* #adding-memory-to-an-agent */}

要将 PostgreSQL 内存添加到Agent，请使用`Memory` class and create a new `storage` key using `PostgresStore`. The `connectionString` can either be a remote location, or a local database connection.

```typescript title="src/mastra/agents/example-pg-agent.ts"
import { Memory } from '@mastra/memory'
import { Agent } from '@mastra/core/agent'
import { PostgresStore } from '@mastra/pg'

export const pgAgent = new Agent({
  id: 'pg-agent',
  name: 'PG Agent',
  instructions:
    'You are an AI agent with the ability to automatically recall memories from previous interactions.',
  model: '__GATEWAY_OPENAI_MODEL__',
  memory: new Memory({
    storage: new PostgresStore({
      id: 'pg-agent-storage',
      connectionString: process.env.DATABASE_URL!,
    }),
    options: {
      generateTitle: true, // Explicitly enable automatic title generation
    },
  }),
})
```

### 使用Agent {/* #using-the-agent */}

使用`memoryOptions` to scope recall for this request. Set `lastMessages: 5` to limit recency-based recall, and use `semanticRecall` to fetch the `topK: 3` most relevant messages, including `messageRange: 2` neighboring messages for context around each match.

```typescript title="src/test-pg-agent.ts"
import 'dotenv/config'

import { mastra } from './mastra'

const threadId = '123'
const resourceId = 'user-456'

const agent = mastra.getAgent('pg-agent')

const message = await agent.stream('My name is Mastra', {
  memory: {
    thread: threadId,
    resource: resourceId,
  },
})

await message.textStream.pipeTo(new WritableStream())

const stream = await agent.stream("What's my name?", {
  memory: {
    thread: threadId,
    resource: resourceId,
  },
  memoryOptions: {
    lastMessages: 5,
    semanticRecall: {
      topK: 3,
      messageRange: 2,
    },
  },
})

for await (const chunk of stream.textStream) {
  process.stdout.write(chunk)
}
```

## 指数管理 {/* #index-management */}

PostgreSQL 存储提供索引管理来优化查询性能。

### 默认索引 {/* #default-indexes */}

PostgreSQL 存储在初始化期间为常见查询模式创建复合索引：

* `mastra_threads_resourceid_createdat_idx`: (resourceId, 创建于 DESC)
* `mastra_messages_thread_id_createdat_idx`: (thread\_id, 创建于 DESC)
* `mastra_ai_spans_traceid_startedat_idx`: (traceId, 开始于 DESC)
* `mastra_ai_spans_parentspanid_startedat_idx`: (parentSpanId,startAt DESC)
* `mastra_ai_spans_name_startedat_idx`: (名称, 开始于 DESC)
* `mastra_ai_spans_scope_startedat_idx`：（范围，开始于 DESC）
* `mastra_scores_trace_id_span_id_created_at_idx`: (traceId、spanId、createAt DESC)
* `mastra_workflow_snapshot_name_createdat_idx`: (Workflow程名称，创建于 DESC)
* `mastra_workflow_snapshot_name_status_createdat_idx`: (workflow\_name, snapshot->>'status',createdAt DESC)，仅当`snapshot` column is `jsonb`

这些索引通过排序提高了过滤查询的性能，包括`dateRange` filters on message queries and Studio's workflow runs-list.

### 配置索引 {/* #configuring-indexes */}

您可以通过构造函数选项控制索引创建：

```typescript
import { PostgresStore } from '@mastra/pg'

// Skip default indexes (manage indexes separately)
const store = new PostgresStore({
  id: 'pg-storage',
  connectionString: process.env.DATABASE_URL,
  skipDefaultIndexes: true,
})

// Add custom indexes during initialization
const storeWithCustomIndexes = new PostgresStore({
  id: 'pg-storage',
  connectionString: process.env.DATABASE_URL,
  indexes: [
    {
      name: 'idx_threads_metadata_type',
      table: 'mastra_threads',
      columns: ["metadata->>'type'"],
    },
    {
      name: 'idx_messages_status',
      table: 'mastra_messages',
      columns: ["metadata->>'status'"],
    },
  ],
})
```

对于高级索引类型，您可以指定其他选项：

* `unique: true`对于独特的约束
* `where: 'condition'`对于部分索引
* `method: 'brin'`对于时间序列数据
* `storage: { fillfactor: 90 }`对于更新频繁的表
* `concurrent: true`用于非阻塞创建（默认）

### 通过 SQL 管理索引 {/* #managing-indexes-via-sql */}

对于高级索引管理（列出、删除、分析），请通过以下方式使用直接 SQL 查询`db` accessor:

```typescript
// List indexes for a table
const indexes = await storage.db.any(`
  SELECT indexname, indexdef
  FROM pg_indexes
  WHERE tablename = 'mastra_messages'
`)

// Drop an index
await storage.db.none('DROP INDEX IF EXISTS idx_my_custom_index')

// Analyze index usage
const stats = await storage.db.one(`
  SELECT idx_scan, idx_tup_read
  FROM pg_stat_user_indexes
  WHERE indexrelname = 'mastra_messages_thread_id_createdat_idx'
`)
```

### 索引类型和用例 {/* #index-types-and-use-cases */}

PostgreSQL提供了针对特定场景优化的不同索引类型：

|指数类型|最适合 |存储尺寸|速度|

|**btree** (default) | Range queries, sorting, general purpose | Moderate | Fast |
| **hash** | Equality comparisons only | Small | Very fast for `=` |
| **gin** | JSONB, arrays, full-text search | Large | Fast for contains |
| **gist** | Geometric data, full-text search | Moderate | Fast for nearest-neighbor |
| **spgist** | Non-balanced data, text patterns | Small | Fast for specific patterns |
| **brin** | Large tables with natural ordering | Very small | Fast for ranges |
