# PostgreSQL

PostgreSQL 存储实现提供基于 PostgreSQL 数据库、可用于生产环境的存储方案。

## 安装 {/* #installation */}

```bash npm2yarn
npm install @mastra/pg@latest
```

## 用法 {/* #usage */}

```typescript
import { PostgresStore } from '@mastra/pg'

const storage = new PostgresStore({
  id: 'pg-storage',
  connectionString: process.env.DATABASE_URL,
})
```

## 构造函数示例 {/* #constructor-examples */}

可以通过以下方式实例化 `PostgresStore`：

```ts
import { PostgresStore } from '@mastra/pg'
import { Pool } from 'pg'

// Using a connection string
const store1 = new PostgresStore({
  id: 'pg-storage-1',
  connectionString: 'postgresql://user:password@localhost:5432/mydb',
})

// Using a connection string with pool options
const store2 = new PostgresStore({
  id: 'pg-storage-2',
  connectionString: 'postgresql://user:password@localhost:5432/mydb',
  schemaName: 'custom_schema',
  max: 30, // Max pool connections
  idleTimeoutMillis: 60000, // Idle timeout
  ssl: { rejectUnauthorized: false },
})

// Using individual connection parameters
const store3 = new PostgresStore({
  id: 'pg-storage-3',
  host: 'localhost',
  port: 5432,
  database: 'mydb',
  user: 'user',
  password: 'password',
})

// Using a pre-configured pg.Pool (recommended for pool reuse)
const existingPool = new Pool({
  connectionString: 'postgresql://user:password@localhost:5432/mydb',
  max: 20,
  // ... your custom pool configuration
})

const store4 = new PostgresStore({
  id: 'pg-storage-4',
  pool: existingPool,
  schemaName: 'custom_schema', // optional
})
```

## 附加说明 {/* #additional-notes */}

### Schema 管理 {/* #schema-management */}

存储实现会自动创建和更新 schema，并创建以下表：

* `mastra_workflow_snapshot`：存储 Workflow 状态和执行数据
* `mastra_evals`：存储评估结果和元数据
* `mastra_threads`：存储对话线程
* `mastra_messages`：存储单条消息
* `mastra_traces`：存储遥测和追踪数据
* `mastra_scorers`：存储评分和评估数据
* `mastra_resources`：存储资源的工作记忆数据
* `mastra_notifications`：存储通知收件箱记录和投递元数据

`PostgresStore` 通过 `getStore('notifications')` 提供通知存储。

### 可观察性 {/* #observability */}

PostgreSQL 支持可观测性，能够处理少量 trace。吞吐能力取决于硬件、schema 设计、索引和数据保留策略等部署因素，应在实际环境中验证。对于 trace 量较大的生产环境，可以考虑：

* 使用 `insert-only` [追踪策略](/docs/observability/integrations/exporters/mastra-storage#tracing-strategies)，减少数据库写入操作
* 对表进行分区，以便高效保留数据
* 如需进一步扩容，通过[组合存储使用 ClickHouse](/reference/storage/composite#specialized-storage-for-observability) 承载可观测性数据

`PostgresStoreVNext` 则使用 `event-sourced` [追踪策略](/docs/observability/integrations/exporters/mastra-storage#tracing-strategies)。span 开始和结束时分别写入一行，不会原地更新记录；读取 trace 时再将这些记录合并。写入始终只追加，运行仍在执行时，Studio 中就能看到 trace。

#### 筛选值建议 {/* #filter-suggestions */}

Studio 的 Traces、Logs 和 Metrics 页面会根据可观测性数据提供筛选值建议，包括 tag、服务名称、环境、实体名称、指标名称和 label。这些值缓存在数据库中；缓存过期后会在后台重新计算。

为控制大型数据集的刷新成本，发现过程只扫描最近 30 天的事件。仅出现在更早事件中的值不会作为建议出现，但仍可用于筛选。使用 `discovery` 调整扫描范围或刷新频率：

```typescript
import { PostgresStoreVNext } from '@mastra/pg'

const storage = new PostgresStoreVNext({
  id: 'pg-storage',
  connectionString: process.env.DATABASE_URL,
  observability: {
    connectionString: process.env.OBSERVABILITY_DATABASE_URL,
    discovery: {
      lookbackSeconds: 7 * 24 * 60 * 60, // scan the last 7 days; 0 scans all history
      ttlSeconds: 15 * 60, // refresh at most every 15 minutes
    },
  },
})
```

如果刷新耗时较长，可降低 `lookbackSeconds`；如果刷新频率高于筛选值的变化频率，可提高 `ttlSeconds`。同一缓存条目每次只由一个进程刷新，因此增加服务器实例不会成倍增加刷新工作量。

#### 按日分区 {/* #day-partitions */}

`PostgresStoreVNext` 将可观测性事件存入按日分区的表。安装 TimescaleDB 或 pg\_partman 后，由相应扩展创建分区。未安装扩展时，`init()` 会为昨天、今天及之后 `futureDays` 天（默认 14 天）创建分区。如果写入日期在这个范围内但尚无分区，系统会先创建分区再重试，因此预建分区用尽后仍可继续写入。日期超出该范围的记录仍会被拒绝。

创建分区属于 DDL 操作。如果应用运行角色不能建表，或不是可观测性表的所有者，写入会失败；错误会指出表名和缺少分区的日期。exporter 重试后会丢弃该批次。在这种配置下，应使用具有建表权限且拥有可观测性表的角色，至少每隔 `futureDays` 天定时调用一次 `ensurePartitions()`。它只扩展原生按日分区的时间范围，对 TimescaleDB 或 pg\_partman 不起作用。也可以安装 TimescaleDB，或为 pg\_partman 启用后台 worker、定时调用 `run_maintenance()`，让数据库自行维护分区。

增大 `futureDays` 可以延长定时任务两次运行之间的间隔：

```typescript
import { PostgresStoreVNext } from '@mastra/pg'

const storage = new PostgresStoreVNext({
  id: 'pg-storage',
  connectionString: process.env.DATABASE_URL,
  observability: {
    connectionString: process.env.OBSERVABILITY_DATABASE_URL,
    partitioning: {
      futureDays: 60, // pre-create 60 days of partitions on init()
    },
  },
})
```

随后在定时任务中调用 `ensurePartitions()`：

```typescript
// OBSERVABILITY_DATABASE_URL connects as a role that owns the observability tables
await storage.ensurePartitions()
await storage.close()
```

### 初始化 {/* #initialization */}

将存储传入 Mastra 类后，系统会在执行任何存储操作前自动调用 `init()`：

```typescript
import { Mastra } from '@mastra/core'
import { PostgresStore } from '@mastra/pg'

const storage = new PostgresStore({
  id: 'pg-storage',
  connectionString: process.env.DATABASE_URL,
})

const mastra = new Mastra({
  storage, // init() is called automatically
})
```

如果绕过 Mastra 直接使用存储，必须显式调用 `init()` 来创建表：

```typescript
import { PostgresStore } from '@mastra/pg'

const storage = new PostgresStore({
  id: 'pg-storage',
  connectionString: process.env.DATABASE_URL,
})

// Required when using storage directly
await storage.init()

// Access domain-specific stores via getStore()
const memoryStore = await storage.getStore('memory')
const thread = await memoryStore?.getThreadById({ threadId: '...' })
```

:::warning
如果没有调用 `init()`，表就不会创建；存储操作可能静默失败或抛出错误。
:::

### 托管 PostgreSQL 和连接池 {/* #managed-postgresql-and-connection-poolers */}

`PostgresStore` 可使用托管 PostgreSQL Provider 提供的连接字符串建立连接，无需安装该 Provider 专用的包。

`init()` 在同一个连接上执行所有 schema 变更，因此可以通过 PgBouncer 等事务模式连接池运行。可以使用 Provider 提供的池化连接字符串，让 Mastra 在启动时创建 schema。

#### 单独初始化 schema {/* #separate-schema-initialization */}

如果运行时数据库角色无法创建表或索引，请在部署期间使用具备相应权限的角色运行一次 `init()`：

```typescript title="scripts/init-storage.ts"
import { PostgresStore } from '@mastra/pg'

const storage = new PostgresStore({
  id: 'pg-storage-init',
  connectionString: process.env.DATABASE_ADMIN_URL,
})

try {
  await storage.init()
  // Only needed if the application uses Knowledge
  await storage.initKnowledge()
} finally {
  await storage.close()
}
```

运行时角色需要对脚本创建的表拥有读写权限。参见 [PostgreSQL 权限文档](https://www.postgresql.org/docs/current/ddl-priv.html)。

然后在运行时存储实例上设置 `disableInit: true`，跳过 schema 创建：

```typescript title="src/mastra/index.ts"
import { Mastra } from '@mastra/core'
import { PostgresStore } from '@mastra/pg'

export const mastra = new Mastra({
  storage: new PostgresStore({
    id: 'pg-storage',
    connectionString: process.env.DATABASE_URL,
    disableInit: true,
  }),
})
```

设置 `disableInit: true` 后，即使显式调用 `init()` 也不会执行任何操作，因此部署脚本中的存储实例不要设置它。

### 使用现有连接池 {/* #using-an-existing-pool */}

如果应用中已有 `pg.Pool`（例如与 ORM 共用，或用于行级安全性），可以直接将其传给 `PostgresStore`：

```typescript
import { Pool } from 'pg'
import { PostgresStore } from '@mastra/pg'

// Your existing pool (shared across your application)
const pool = new Pool({
  connectionString: process.env.DATABASE_URL,
  max: 20,
})

const storage = new PostgresStore({
  id: 'shared-storage',
  pool: pool,
})
```

**连接池的生命周期：**

* **由你提供连接池**时：Mastra 使用该连接池，但调用 `store.close()` 时**不会**关闭它；连接池的生命周期由你管理。
* **由 Mastra 创建连接池**时：Mastra 拥有该连接池，调用 `store.close()` 时会将其关闭。

### 直接访问数据库和连接池 {/* #direct-database-and-pool-access */}

`PostgresStore` 暴露底层数据库客户端和连接池，供进阶场景使用：

```typescript
store.db // DbClient - query interface with helpers (any, one, tx, etc.)
store.pool // pg.Pool - the underlying connection pool
```

**使用 `store.db` 查询：**

```typescript
// Execute queries with helper methods
const users = await store.db.any('SELECT * FROM users WHERE active = $1', [true])
const user = await store.db.one('SELECT * FROM users WHERE id = $1', [userId])
const maybeUser = await store.db.oneOrNone('SELECT * FROM users WHERE email = $1', [email])

// Use transactions
const result = await store.db.tx(async t => {
  await t.none('INSERT INTO logs (message) VALUES ($1)', ['Started'])
  const data = await t.any('SELECT * FROM items')
  return data
})
```

**直接使用 `store.pool`：**

```typescript
// Get a client for manual connection management
const client = await store.pool.connect()
try {
  await client.query('SET LOCAL app.user_id = $1', [userId])
  const result = await client.query('SELECT * FROM protected_table')
  return result.rows
} finally {
  client.release()
}
```

使用这些字段时：

* 你需要自行正确管理连接和事务。
* 只有连接池由 Mastra 创建时，关闭存储（`store.close()`）才会销毁连接池。
* 直接访问会绕过 PostgresStore 方法提供的其他逻辑或验证。

这种方式适用于需要底层访问能力的进阶场景。

### 与 Next.js 一起使用 {/* #using-with-nextjs */}

在 Next.js 应用中使用 `PostgresStore` 时，开发期间的[热模块替换（HMR）](https://nextjs.org/docs/architecture/fast-refresh)可能创建多个存储实例，并出现以下警告：

```text
WARNING: Creating a duplicate database object for the same connection.
```

为避免这种情况，将 `PostgresStore` 实例保存在全局对象上，使其在 HMR 重新加载后仍可复用：

```typescript title="src/mastra/storage.ts"
import { PostgresStore } from '@mastra/pg'
import { Memory } from '@mastra/memory'

// Extend the global type to include our instances
declare global {
  var pgStore: PostgresStore | undefined
  var memory: Memory | undefined
}

// Get or create the PostgresStore instance
function getPgStore(): PostgresStore {
  if (!global.pgStore) {
    if (!process.env.DATABASE_URL) {
      throw new Error('DATABASE_URL is not defined in environment variables')
    }
    global.pgStore = new PostgresStore({
      id: 'pg-storage',
      connectionString: process.env.DATABASE_URL,
      ssl: process.env.DATABASE_SSL === 'true' ? { rejectUnauthorized: false } : false,
    })
  }
  return global.pgStore
}

// Get or create the Memory instance
function getMemory(): Memory {
  if (!global.memory) {
    global.memory = new Memory({
      storage: getPgStore(),
    })
  }
  return global.memory
}

export const storage = getPgStore()
export const memory = getMemory()
```

然后在 Mastra 配置中使用导出的实例：

```typescript title="src/mastra/index.ts"
import { Mastra } from '@mastra/core/mastra'
import { storage } from './storage'

export const mastra = new Mastra({
  storage,
  // ...other config
})
```

无论开发期间模块重新加载多少次，这种写法都只会创建一个 `PostgresStore` 实例。同样的方式也适用于 `LibSQLStore` 等其他存储 Provider。

:::tip
只有在本地开发使用 HMR 时才需要这种单例模式。生产构建中，模块只加载一次。
:::

## 使用示例 {/* #usage-example */}

### 为 Agent 添加记忆 {/* #adding-memory-to-an-agent */}

要为 Agent 添加基于 PostgreSQL 的记忆，请使用 `Memory` 类，并将通过 `PostgresStore` 创建的实例赋给 `storage` 键。`connectionString` 可以指向远程数据库，也可以是本地数据库连接。

```typescript title="src/mastra/agents/example-pg-agent.ts"
import { Memory } from '@mastra/memory'
import { Agent } from '@mastra/core/agent'
import { PostgresStore } from '@mastra/pg'

export const pgAgent = new Agent({
  id: 'pg-agent',
  name: 'PG Agent',
  instructions:
    'You are an AI agent with the ability to automatically recall memories from previous interactions.',
  model: '__GATEWAY_OPENAI_MODEL__',
  memory: new Memory({
    storage: new PostgresStore({
      id: 'pg-agent-storage',
      connectionString: process.env.DATABASE_URL!,
    }),
    options: {
      generateTitle: true, // Explicitly enable automatic title generation
    },
  }),
})
```

### 使用 Agent {/* #using-the-agent */}

使用 `memoryOptions` 限定本次请求的记忆检索范围。设置 `lastMessages: 5`，使基于近期消息的检索最多包含五条消息；使用 `semanticRecall` 获取最相关的 `topK: 3` 条消息，并通过 `messageRange: 2` 为每个匹配结果纳入相邻消息作为上下文。

```typescript title="src/test-pg-agent.ts"
import 'dotenv/config'

import { mastra } from './mastra'

const threadId = '123'
const resourceId = 'user-456'

const agent = mastra.getAgent('pg-agent')

const message = await agent.stream('My name is Mastra', {
  memory: {
    thread: threadId,
    resource: resourceId,
  },
})

await message.textStream.pipeTo(new WritableStream())

const stream = await agent.stream("What's my name?", {
  memory: {
    thread: threadId,
    resource: resourceId,
  },
  memoryOptions: {
    lastMessages: 5,
    semanticRecall: {
      topK: 3,
      messageRange: 2,
    },
  },
})

for await (const chunk of stream.textStream) {
  process.stdout.write(chunk)
}
```

## 索引管理 {/* #index-management */}

PostgreSQL 存储提供索引管理来优化查询性能。

### 默认索引 {/* #default-indexes */}

PostgreSQL 存储在初始化期间为常见查询模式创建复合索引：

* `mastra_threads_resourceid_createdat_idx`: (resourceId, createdAt DESC)
* `mastra_messages_thread_id_createdat_idx`: (thread_id, createdAt DESC)
* `mastra_ai_spans_traceid_startedat_idx`: (traceId, startedAt DESC)
* `mastra_ai_spans_parentspanid_startedat_idx`: (parentSpanId, startedAt DESC)
* `mastra_ai_spans_name_startedat_idx`: (name, startedAt DESC)
* `mastra_ai_spans_scope_startedat_idx`: (scope, startedAt DESC)
* `mastra_scores_trace_id_span_id_created_at_idx`: (traceId, spanId, createdAt DESC)
* `mastra_workflow_snapshot_name_createdat_idx`: (workflow_name, createdAt DESC)
* `mastra_workflow_snapshot_name_status_createdat_idx`: (workflow_name, snapshot->>'status', createdAt DESC)，仅当 `snapshot` 列为 `jsonb` 时创建

这些索引可提升带排序的筛选查询性能，包括消息查询中的 `dateRange` 筛选，以及 Studio 的 Workflow 运行列表。

### 配置索引 {/* #configuring-indexes */}

您可以通过构造函数选项控制索引创建：

```typescript
import { PostgresStore } from '@mastra/pg'

// Skip default indexes (manage indexes separately)
const store = new PostgresStore({
  id: 'pg-storage',
  connectionString: process.env.DATABASE_URL,
  skipDefaultIndexes: true,
})

// Add custom indexes during initialization
const storeWithCustomIndexes = new PostgresStore({
  id: 'pg-storage',
  connectionString: process.env.DATABASE_URL,
  indexes: [
    {
      name: 'idx_threads_metadata_type',
      table: 'mastra_threads',
      columns: ["metadata->>'type'"],
    },
    {
      name: 'idx_messages_status',
      table: 'mastra_messages',
      columns: ["metadata->>'status'"],
    },
  ],
})
```

对于高级索引类型，您可以指定其他选项：

* `unique: true`：创建唯一约束
* `where: 'condition'`：创建部分索引
* `method: 'brin'`：用于时间序列数据
* `storage: { fillfactor: 90 }`：用于频繁更新的表
* `concurrent: true`：以不阻塞写入的方式创建索引（默认）

### 指定 schema 的索引 {/* #schema-specific-indexes */}

使用自定义 schema 时，索引名称会以 schema 名称为前缀：

```typescript
const storage = new PostgresStore({
  id: 'pg-storage',
  connectionString: process.env.DATABASE_URL,
  schemaName: 'custom_schema',
  indexes: [
    {
      name: 'idx_threads_status',
      table: 'mastra_threads',
      columns: ['status'],
    },
  ],
})

// Creates index as: custom_schema_idx_threads_status
```

### 通过 SQL 管理索引 {/* #managing-indexes-via-sql */}

如需列出、删除或分析索引，可通过 `db` 访问器直接执行 SQL 查询：

```typescript
// List indexes for a table
const indexes = await storage.db.any(`
  SELECT indexname, indexdef
  FROM pg_indexes
  WHERE tablename = 'mastra_messages'
`)

// Drop an index
await storage.db.none('DROP INDEX IF EXISTS idx_my_custom_index')

// Analyze index usage
const stats = await storage.db.one(`
  SELECT idx_scan, idx_tup_read
  FROM pg_stat_user_indexes
  WHERE indexrelname = 'mastra_messages_thread_id_createdat_idx'
`)
```

### 索引类型和用例 {/* #index-types-and-use-cases */}

PostgreSQL 提供多种索引类型，分别针对不同场景优化：

| 索引类型 | 适用场景 | 存储空间 | 速度 |
| - | - | - | - |
| **btree**（默认） | 范围查询、排序、通用查询 | 中等 | 快 |
| **hash** | 仅用于等值比较 | 小 | `=` 比较非常快 |
| **gin** | JSONB、数组、全文搜索 | 大 | 包含关系查询快 |
| **gist** | 几何数据、全文搜索 | 中等 | 最近邻查询快 |
| **spgist** | 非均衡数据、文本模式 | 小 | 特定模式查询快 |
| **brin** | 具有自然顺序的大表 | 很小 | 范围查询快 |
