# DynamoDB

DynamoDB 存储适配器通过 [ElectroDB](https://electrodb.dev/) 实现单表设计，为 Mastra 提供大容量、高性能的 NoSQL 存储。

:::warning[不支持可观测性]

DynamoDB 存储**不支持可观测性数据**。`MastraStorageExporter` 导出的 Trace 无法持久化到 DynamoDB。仅使用 DynamoDB 作为存储 Provider 时，[Studio](/docs/studio/overview) 的可观测性功能无法使用。要启用这些功能，请使用[复合存储](/reference/storage/composite#specialized-storage-for-observability)，将可观测性数据交给支持该功能的 Provider，例如 ClickHouse。

:::

:::warning[数据项大小限制]
DynamoDB 对单个数据项设有 **400 KB 的大小上限**。存储含有 Base64 编码附件（例如图片）的消息时，可能超过此上限。有关将附件上传到外部存储等解决方法，请参阅[处理大型附件](/docs/memory/memory-processors#handling-large-attachments)。
:::

## 功能 {/* #features */}

* 采用高效的单表设计，满足 Mastra 的各类存储需求
* 通过 ElectroDB 以类型安全的方式访问 DynamoDB
* 支持配置 AWS 凭证、区域和端点
* 支持使用 AWS DynamoDB Local 进行本地开发
* 存储会话线程、消息、评估和 Workflow 数据
* 针对无服务器环境优化
* 支持按实体类型配置 TTL（生存时间），使数据自动过期

## 安装 {/* #installation */}

```bash npm2yarn
npm install @mastra/dynamodb@latest
```

## 前置条件 {/* #prerequisites */}

使用此包前，**必须**创建符合指定结构的 DynamoDB 表，其中包括主键和全局二级索引（GSI）。表及其索引需要在适配器之外预先创建。

请参阅 [TABLE\_SETUP.md](https://github.com/mastra-ai/mastra/blob/main/stores/dynamodb/TABLE_SETUP.md)，按照其中的 AWS CloudFormation 或 AWS CDK 说明配置好表，再继续操作。

## 用法 {/* #usage */}

### 基本用法 {/* #basic-usage */}

```typescript
import { Memory } from '@mastra/memory'
import { DynamoDBStore } from '@mastra/dynamodb'

// Initialize the DynamoDB storage
const storage = new DynamoDBStore({
  id: 'dynamodb', // Unique identifier for this storage instance
  config: {
    tableName: 'mastra-single-table', // Name of your DynamoDB table
    region: 'us-east-1', // Optional: AWS region, defaults to 'us-east-1'
    // endpoint: "http://localhost:8000", // Optional: For local DynamoDB
    // credentials: { accessKeyId: "YOUR_ACCESS_KEY", secretAccessKey: "YOUR_SECRET_KEY" } // Optional
  },
})

// Example: Initialize Memory with DynamoDB storage
const memory = new Memory({
  storage,
  options: {
    lastMessages: 10,
  },
})
```

### 使用 DynamoDB Local 进行本地开发 {/* #local-development-with-dynamodb-local */}

本地开发时，可以使用 [DynamoDB Local](https://docs.aws.amazon.com/amazondynamodb/latest/developerguide/DynamoDBLocal.html)。

1. **启动 DynamoDB Local，例如通过 Docker 启动。**

   ```bash
   docker run -p 8000:8000 amazon/dynamodb-local
   ```

2. **将 `DynamoDBStore` 配置为使用本地端点。**

   ```typescript
   import { DynamoDBStore } from '@mastra/dynamodb'

   const storage = new DynamoDBStore({
     id: 'dynamodb-local',
     config: {
       tableName: 'mastra-single-table', // Ensure this table is created in your local DynamoDB
       region: 'localhost', // Can be any string for local, 'localhost' is common
       endpoint: 'http://localhost:8000',
       // For DynamoDB Local, credentials are not typically required unless configured.
       // If you've configured local credentials:
       // credentials: { accessKeyId: "fakeMyKeyId", secretAccessKey: "fakeSecretAccessKey" }
     },
   })
   ```

   仍需在本地 DynamoDB 实例中创建表和 GSI。例如，可通过 AWS CLI 指定本地端点来创建。

## TTL（生存时间）配置 {/* #ttl-time-to-live-configuration */}

DynamoDB 的 TTL 功能可在指定时长过去后自动删除数据项，适用于以下场景。

* **优化成本**：自动删除旧数据，降低存储成本
* **管理数据生命周期**：落实数据保留策略，满足合规要求
* **维持性能**：避免表无限增长
* **满足隐私合规要求**：超过指定期限后自动清除个人数据

### 启用 TTL {/* #enabling-ttl */}

使用 TTL 必须完成以下两步。

1. **在 DynamoDBStore 中配置 TTL**，如下例所示。
2. **通过 AWS 控制台或 CLI 为 DynamoDB 表启用 TTL**，并指定属性名（默认为 `ttl`）。

```typescript
import { DynamoDBStore } from '@mastra/dynamodb'

const storage = new DynamoDBStore({
  name: 'dynamodb',
  config: {
    tableName: 'mastra-single-table',
    region: 'us-east-1',
    ttl: {
      // Messages expire after 30 days
      message: {
        enabled: true,
        defaultTtlSeconds: 30 * 24 * 60 * 60, // 30 days
      },
      // Threads expire after 90 days
      thread: {
        enabled: true,
        defaultTtlSeconds: 90 * 24 * 60 * 60, // 90 days
      },
      // Traces expire after 7 days with custom attribute name
      trace: {
        enabled: true,
        attributeName: 'expiresAt', // Custom TTL attribute
        defaultTtlSeconds: 7 * 24 * 60 * 60, // 7 days
      },
      // Workflow snapshots don't expire
      workflow_snapshot: {
        enabled: false,
      },
    },
  },
})
```

### 支持的实体类型 {/* #supported-entity-types */}

以下实体类型支持配置 TTL。

| 实体 | 说明 |
| - | - |
| `thread` | 会话线程 |
| `message` | 线程中的消息 |
| `trace` | 可观测性 Trace |
| `eval` | 评估结果 |
| `workflow_snapshot` | Workflow 状态快照 |
| `resource` | 用户或资源数据 |
| `score` | 评分结果 |

### 在 DynamoDB 表上启用 TTL {/* #enabling-ttl-on-your-dynamodb-table */}

在代码中配置 TTL 后，还必须为 DynamoDB 表启用 TTL。

**使用 AWS CLI**

```bash
aws dynamodb update-time-to-live \
  --table-name mastra-single-table \
  --time-to-live-specification "Enabled=true, AttributeName=ttl"
```

**使用 AWS 控制台**

1. 打开 DynamoDB 控制台。
2. 选择要配置的表。
3. 打开「其他设置」（Additional settings）选项卡。
4. 在「生存时间 (TTL)」（Time to Live (TTL)）部分，选择「管理 TTL」（Manage TTL）。
5. 启用 TTL 并指定属性名（默认为 `ttl`）。

:::note

DynamoDB 会在数据项过期后 48 小时内将其删除。实际删除前，仍可查询这些数据项。

:::

## AWS IAM 权限 {/* #aws-iam-permissions */}

运行代码所用的 IAM 角色或用户必须具有操作指定 DynamoDB 表及其索引的权限。使用以下策略示例时，请将 `${YOUR_TABLE_NAME}` 替换为实际表名，并将 `${YOUR_AWS_REGION}` 和 `${YOUR_AWS_ACCOUNT_ID}` 替换为对应的 AWS 区域和账户 ID。

```json
{
  "Version": "2012-10-17",
  "Statement": [
    {
      "Effect": "Allow",
      "Action": [
        "dynamodb:DescribeTable",
        "dynamodb:GetItem",
        "dynamodb:PutItem",
        "dynamodb:UpdateItem",
        "dynamodb:DeleteItem",
        "dynamodb:Query",
        "dynamodb:Scan",
        "dynamodb:BatchGetItem",
        "dynamodb:BatchWriteItem"
      ],
      "Resource": [
        "arn:aws:dynamodb:${YOUR_AWS_REGION}:${YOUR_AWS_ACCOUNT_ID}:table/${YOUR_TABLE_NAME}",
        "arn:aws:dynamodb:${YOUR_AWS_REGION}:${YOUR_AWS_ACCOUNT_ID}:table/${YOUR_TABLE_NAME}/index/*"
      ]
    }
  ]
}
```

## 使用要点 {/* #key-considerations */}

使用 DynamoDB 存储适配器时，请留意以下要点。

* **预先建表**：使用适配器前，必须按照 [TABLE\_SETUP.md](https://github.com/mastra-ai/mastra/blob/main/stores/dynamodb/TABLE_SETUP.md) 自行创建并配置 DynamoDB 表及其全局二级索引（GSI）。
* **单表设计**：Mastra 的会话线程、消息等数据集中存储在同一张 DynamoDB 表中。这种设计针对 DynamoDB 优化，有别于关系型数据库的存储方式。
* **了解 GSI**：熟悉 `TABLE_SETUP.md` 中的索引结构，有助于理解如何检索数据以及可以采用哪些查询模式。
* **ElectroDB**：适配器通过 ElectroDB 封装底层 DynamoDB 操作，并提供类型安全保障。

## 存储架构 {/* #architectural-approach */}

此适配器通过 [ElectroDB](https://electrodb.dev/) 实现 **单表设计**，这是 DynamoDB 常用的推荐做法。关系型数据库适配器（如 `@mastra/pg` 或 `@mastra/libsql`）通常使用多张表，每张表负责一种实体，例如会话线程或消息。

这一架构有三个特点。

* **利用 DynamoDB 的原生能力**：单表设计针对 DynamoDB 的键值访问和查询能力优化，相较于照搬关系模型，通常能获得更好的性能和容量表现。
* **在适配器之外管理表**：有些适配器可能提供通过代码建表的辅助函数。此适配器要求 **在使用前从外部创建 DynamoDB 表及其全局二级索引（GSI）**，并且仅操作已有的表结构。使用 AWS CloudFormation 或 CDK 的具体步骤见 [TABLE\_SETUP.md](https://github.com/mastra-ai/mastra/blob/main/stores/dynamodb/TABLE_SETUP.md)。
* **统一接口**：底层存储模型虽有差异，此适配器仍实现与其他适配器相同的 `MastraStorage` 接口，因此可以在 Mastra 的 `Memory` 组件中与其他适配器互换。

### Mastra 数据在单表中的组织方式 {/* #mastra-data-in-the-single-table */}

ElectroDB 在同一张 DynamoDB 表中管理并区分 Mastra 的各类实体，例如会话线程、消息、Trace、评估和 Workflow。它为每种实体定义专用模型，分别指定键结构和属性，使适配器能在一张表中高效存取多种数据。

例如，`Thread` 数据项可以使用 `THREAD#<threadId>` 作为主键，而属于该线程的 `Message` 数据项可以使用 `THREAD#<threadId>` 作为分区键、`MESSAGE#<messageId>` 作为排序键。`TABLE_SETUP.md` 详述的全局二级索引（GSI）针对不同实体的常见访问模式设计，例如获取某个线程中的全部消息，或查询与某个 Workflow 关联的 Trace。

### 单表设计的优点 {/* #advantages-of-single-table-design */}

在 DynamoDB 中使用 ElectroDB 实现单表设计，有以下优点。

1. **可能降低成本**：表越少，读写容量单位（RCU/WCU）的配置和管理越简单，尤其是在使用按需容量时。
2. **提升性能**：可以将相关数据存放在一起，也可通过 GSI 高效访问，从而加快常见查询。
3. **简化运维**：需要监控和备份的表更少，管理工作量也随之减少。
4. **简化访问模式**：ElectroDB 帮助管理单张表中的多种数据项类型和访问模式。
5. **支持事务**：需要时，可以通过 DynamoDB 事务操作同一张表中的不同实体类型。
