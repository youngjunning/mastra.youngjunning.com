# 谷歌云扳手

Google Cloud Spanner 存储实现为 Mastra 提供了水平高容量、高度一致的存储后端。它针对 Cloud Spanner 的 GoogleSQL 方言。

## 安装 {/* #installation */}

```bash npm2yarn
npm install @mastra/spanner@latest
```

## 用法 {/* #usage */}

```typescript
import { SpannerStore } from '@mastra/spanner'

const storage = new SpannerStore({
  id: 'spanner-storage',
  projectId: process.env.SPANNER_PROJECT_ID!,
  instanceId: process.env.SPANNER_INSTANCE_ID!,
  databaseId: process.env.SPANNER_DATABASE_ID!,
})
```

实例和数据库必须已存在。适配器在首次使用时创建所需的表，因此提供给 Spanner 客户端的凭据需要运行架构更改（或运行`storage.init()` once during a deploy step with elevated credentials).

## 构造函数示例 {/* #constructor-examples */}

你可以实例化`SpannerStore` in several ways:

```typescript
import { Spanner } from '@google-cloud/spanner'
import { SpannerStore } from '@mastra/spanner'

// Using projectId / instanceId / databaseId
const store1 = new SpannerStore({
  id: 'spanner-storage-1',
  projectId: 'my-gcp-project',
  instanceId: 'my-instance',
  databaseId: 'mastra',
})

// Reusing an existing Spanner Database handle
const spanner = new Spanner({ projectId: 'my-gcp-project' })
const database = spanner.instance('my-instance').database('mastra')

const store2 = new SpannerStore({
  id: 'spanner-storage-2',
  database,
})

// Using the local Spanner emulator (set the SPANNER_EMULATOR_HOST env var)
process.env.SPANNER_EMULATOR_HOST = 'localhost:9010'
const store3 = new SpannerStore({
  id: 'spanner-storage-emulator',
  projectId: 'test-project',
  instanceId: 'test-instance',
  databaseId: 'test-db',
  spannerOptions: { servicePath: 'localhost', port: 9010, sslCreds: undefined },
})
```

## 附加说明 {/* #additional-notes */}

### 模式管理 {/* #schema-management */}

存储适配器创建以下表，全部使用 GoogleSQL 方言：

* `mastra_workflow_snapshot`：Workflow状态和执行数据
* `mastra_threads`: 对话话题
* `mastra_messages`: 单独的消息
* `mastra_resources`：资源工作记忆
* `mastra_scorers`: 评价分数
* `mastra_background_tasks`：后台Tool执行状态
* `mastra_agents`：瘦Agent记录（id、状态、活动版本）
* `mastra_agent_versions`：版本化Agent配置快照
* `mastra_mcp_clients` / `mastra_mcp_client_versions`: MCP client configurations and their version history
* `mastra_mcp_servers` / `mastra_mcp_server_versions`: MCP server configurations and their version history
* `mastra_skills` / `mastra_skill_versions`: skill records and versioned skill snapshots (instructions, references, scripts, assets, content tree)
* `mastra_skill_blobs`：由 SHA-256 哈希键控的内容可寻址 Blob 存储，用于技能版本内容
* `mastra_prompt_blocks` / `mastra_prompt_block_versions`: prompt block records and versioned content snapshots (template content, rules, request-context schema)
* `mastra_scorer_definitions` / `mastra_scorer_definition_versions`: scorer definition records and versioned config snapshots (judge instructions, model, score range, preset config, default sampling)
* `mastra_schedules` / `mastra_schedule_triggers`: cron-driven workflow schedules and trigger history, consumed by Mastra's built-in `WorkflowScheduler`
* `mastra_workspaces` / `mastra_workspace_versions`: workspace records and versioned configuration snapshots (filesystem, sandbox, mounts, search, skills, tools)
* `mastra_datasets` / `mastra_dataset_items` / `mastra_dataset_versions`: evaluation datasets, SCD-2 versioned items, and version snapshots
* `mastra_experiments` / `mastra_experiment_results`: experiment runs and their per-item results
* `mastra_favorites`：每个用户最喜欢的Agent和技能，具有非规范化`favoriteCount` maintained on the parent record
* `mastra_channel_installations` / `mastra_channel_config`: multi-platform channel installations and per-platform configuration
* `mastra_ai_spans`：AI 跟踪跨度以实现可观察性（每跟踪和每跨度记录，用于为 Studio 跟踪 UI 提供支持）

表是用以下命令创建的`STRING(MAX)` for text and JSON payloads, `INT64`, `FLOAT64`, `BOOL`, and `TIMESTAMP`.

下表包含 Spanner 特定的`STORED` generated columns that the adapter populates from JSON payloads so common filters can use a regular secondary index instead of a `JSON_VALUE` scan:

* `mastra_workflow_snapshot.snapshotStatus`：提取物`$.status` from `snapshot`. Backs `listWorkflowRuns({ status })`.
* `mastra_schedules.target_workflow_id`：提取物`$.workflowId` from `target`. Backs `listSchedules({ workflowId })`.

两者都是通过添加的`ALTER TABLE ... ADD COLUMN IF NOT EXISTS` during `init()` and skipped under `initMode: 'validate'` (where the schema is owned externally). When the column is absent, the adapter falls back to a `JSON_VALUE` filter at runtime.

适配器不创建或使用架构。使用专用数据库进行隔离。

### 初始化 {/* #initialization */}

当您将存储传递给`Mastra` class, `init()` is called automatically before any storage operation:

```typescript
import { Mastra } from '@mastra/core'
import { SpannerStore } from '@mastra/spanner'

const storage = new SpannerStore({
  id: 'spanner-storage',
  projectId: process.env.SPANNER_PROJECT_ID!,
  instanceId: process.env.SPANNER_INSTANCE_ID!,
  databaseId: process.env.SPANNER_DATABASE_ID!,
})

const mastra = new Mastra({
  storage, // init() is called automatically
})
```

如果直接使用存储，则调用`init()` once before the first operation. Spanner doesn't allow concurrent schema changes, so `SpannerStore.init()` runs each domain's setup sequentially.

```typescript
const storage = new SpannerStore({
  id: 'spanner-storage',
  projectId: process.env.SPANNER_PROJECT_ID!,
  instanceId: process.env.SPANNER_INSTANCE_ID!,
  databaseId: process.env.SPANNER_DATABASE_ID!,
})

await storage.init()
const memory = await storage.getStore('memory')
const thread = await memory?.getThreadById({ threadId: '...' })
```

:::警告
如果`init()` isn't called and `disableInit` is true, the required tables won't exist and storage operations will fail.
:::

### GoogleSQL 细节 {/* #googlesql-specifics */}

有一些行为与其他关系适配器不同：

* 更新插入使用`INSERT OR UPDATE`. Spanner doesn't provide a `RETURNING` clause for upserts, so callers needing the post-write state must read it back.
* 不`TRUNCATE` exists. `dangerouslyClearAll()` issues `DELETE WHERE TRUE`.
* 标识符用反引号引用。
* DDL 通过应用`database.updateSchema(...)`, which is asynchronous (long-running operation).
* `NULLS FIRST/LAST`不支持。通过 NULL 处理来模拟排序`IS NULL` ordering key.
* 本机不支持 JSON 包含。`listTraces` `metadata` and `scope` filters compile to per-key `JSON_VALUE(...) = @v` equality checks, and `tags` filters compile to `EXISTS` over `JSON_QUERY_ARRAY(...)`. This differs from Postgres' `@>` containment operator (which can match nested structure in a single index scan): most one-shot lookups still work but deeply nested structural matches aren't expressible.

### 直接数据库访问 {/* #direct-database-access */}

`SpannerStore`公开底层的 Spanner 客户端对象：

```typescript
store.database // @google-cloud/spanner Database
store.instance // @google-cloud/spanner Instance (when created internally)
store.spanner // @google-cloud/spanner Spanner client (when created internally)
```

这些适用于高级场景，例如定制事务或模式自省。当您直接重用数据库时，您将绕过适配器的验证和 JSON 转换逻辑。

### 使用模拟器进行本地开发 {/* #local-development-with-the-emulator */}

使用 Docker 在本地运行 Cloud Spanner 模拟器：

```bash
docker run -p 9010:9010 -p 9020:9020 gcr.io/cloud-spanner-emulator/emulator
```

放`SPANNER_EMULATOR_HOST=localhost:9010` and create the instance and database before running your app:

```bash
gcloud spanner instances create test-instance --config=emulator-config --nodes=1
gcloud spanner databases create test-db --instance=test-instance
```

然后与 Node.js 进程中设置的相同环境变量连接。这`@google-cloud/spanner` client detects the emulator automatically.
