# ClickHouse

[ClickHouse](https://clickhouse.com/) 是为分析工作负载设计的列式数据库。`@mastra/clickhouse` 包为多个 Mastra 存储域提供适配器，也是生产环境可观测性的推荐后端。

ClickHouse 最常用于[组合存储](/reference/storage/composite)，专门承载可观测性数据，其余存储域由另一个数据库承载。

## 何时使用 ClickHouse {/* #when-to-use-clickhouse */}

适用于在生产环境中存储追踪、日志、指标、评分和反馈。

本地开发时，请组合使用 [LibSQL](/integrations/databases/libsql)（用于记忆和 Workflow）与 `@mastra/duckdb`（用于可观测性）。单独使用任何一个都无法覆盖开发环境的全部存储需求：LibSQL 未实现可观测性域，而 DuckDB 未实现其他存储域。示例参见[可观测性概览](/docs/observability/overview)。

## 安装 {/* #installation */}

```bash npm2yarn
npm install @mastra/clickhouse@latest
```

还需要运行中的 ClickHouse 服务器。托管和自行部署方案参见[托管选项](#hosting-options)。

## 用法 {/* #usage */}

### 使用 vNext 存储可观测性数据（推荐） {/* #observability-with-vnext-recommended */}

`ObservabilityStorageClickhouseVNext` 是当前的可观测性域实现。它采用基于 `ReplacingMergeTree` 的仅插入表结构，针对追踪、日志、指标、评分和反馈产生的数据量进行了优化。

将它与另一个存储适配器组合使用，避免可观测性数据的写入与应用数据争用资源：

```typescript title="src/mastra/index.ts"
import { Mastra } from '@mastra/core'
import { MastraCompositeStore } from '@mastra/core/storage'
import { PostgresStore } from '@mastra/pg'
import { ObservabilityStorageClickhouseVNext } from '@mastra/clickhouse'
import { Observability, MastraStorageExporter } from '@mastra/observability'

const observabilityStore = new ObservabilityStorageClickhouseVNext({
  url: process.env.CLICKHOUSE_URL!,
  username: process.env.CLICKHOUSE_USERNAME!,
  password: process.env.CLICKHOUSE_PASSWORD!,
})

export const mastra = new Mastra({
  storage: new MastraCompositeStore({
    id: 'composite-storage',
    default: new PostgresStore({
      id: 'pg',
      connectionString: process.env.DATABASE_URL!,
    }),
    domains: {
      observability: observabilityStore,
    },
  }),
  observability: new Observability({
    configs: {
      default: {
        serviceName: 'mastra',
        exporters: [new MastraStorageExporter()],
      },
    },
  }),
})
```

以 ClickHouse 作为可观测性后端时，`MastraStorageExporter` 会自动选择写入吞吐量最高的 `insert-only` 策略。详情参见[追踪策略](/docs/observability/integrations/exporters/mastra-storage#tracing-strategies)。

删除追踪时，关联同一追踪 ID 的 span、追踪根与分支、指标、日志、评分和反馈也会被删除。没有追踪 ID 的信号会保留。Mastra 会记录删除条件，并等待 ClickHouse 应用轻量级删除掩码。调用完成后，普通读取不再返回此次删除匹配的行。

轻量级删除只通过 ClickHouse 的 `_row_exists` 掩码隐藏行。数据何时从磁盘物理移除，取决于合并操作和部署时配置的保留 TTL。只有传入 `retention` 选项，`ObservabilityStorageClickhouseVNext` 才会设置保留期限；Mastra 不配置默认的保留 TTL。

当五类可观测性信号都设置了有限的保留期限时，Mastra 还会为删除请求设置 TTL，使其保留时间长于所保护的信号行。只要有一类信号的保留期限不受限制，删除请求就不会设置期限。计算方式参见[存储保留期限](/reference/storage/retention#clickhouse-native-ttl)。

更新反馈审核状态时，系统先读取当前行，再插入替代行，因此需要 `SELECT` 和 `INSERT` 权限，无需 `ALTER UPDATE`；插入物化视图会将每次更新发布给增量轮询。重新执行删除操作的更新还需要[初始化](#initialization)一节列出的删除权限。如果更新与同一反馈的删除操作同时发生，更新会重新执行删除并返回“未找到”，因此不会重新创建已删除的反馈。删除失败不会阻止审核状态更新，但下一次更新会重试删除：重试成功则返回“未找到”；再次失败则保存新状态，同时返回删除错误。如果网络错误或副本延迟导致审核状态行在删除成功后仍然存在，下一次更新该反馈时会再次删除它，并返回“未找到”。

### 使用旧版域存储可观测性数据 {/* #observability-with-the-legacy-domain */}

`ObservabilityStorageClickhouse` 是原有的可观测性适配器，仍支持尚未迁移到 vNext 表结构的项目。它与 vNext 类使用相同的配置结构。

```typescript
import { ObservabilityStorageClickhouse } from '@mastra/clickhouse'

const observabilityStore = new ObservabilityStorageClickhouse({
  url: process.env.CLICKHOUSE_URL!,
  username: process.env.CLICKHOUSE_USERNAME!,
  password: process.env.CLICKHOUSE_PASSWORD!,
})
```

新项目应使用 `ObservabilityStorageClickhouseVNext`。

### 从旧版迁移到 vNext {/* #migrating-from-legacy-to-vnext */}

要将旧版 `mastra_ai_spans` 表中的历史 span 迁移到 vNext 表结构，请运行：

```bash npm2yarn
npx mastra migrate
```

迁移会按天分批将 span 数据从 `mastra_ai_spans` 复制到 `mastra_span_events`，同时映射列并对旧版数据去重。原表会保留作为备份。迁移后，可通过 vNext 适配器在 Studio 中查看追踪。

:::note
迁移不会删除旧表。确认迁移结果后再手动删除。
:::

### 将 ClickHouse 用于所有存储域 {/* #clickhouse-for-every-domain */}

`ClickhouseStoreVNext` 使用 ClickHouse 承载 `memory`、`workflows` 和 `observability` 域，并自动使用 vNext 可观测性适配器。如果希望整个应用都使用 ClickHouse，又不想手动配置组合存储，可以使用它。

```typescript title="src/mastra/index.ts"
import { Mastra } from '@mastra/core'
import { ClickhouseStoreVNext } from '@mastra/clickhouse'

export const mastra = new Mastra({
  storage: new ClickhouseStoreVNext({
    id: 'clickhouse-storage',
    url: process.env.CLICKHOUSE_URL!,
    username: process.env.CLICKHOUSE_USERNAME!,
    password: process.env.CLICKHOUSE_PASSWORD!,
  }),
})
```

`ClickhouseStoreVNext` 接受与 `ClickhouseStore` 相同的配置，并在所有存储域之间复用同一个 ClickHouse 客户端。

#### 手动组合存储 {/* #manual-composition */}

`ClickhouseStore` 是使用旧版可观测性适配器承载所有存储域的既有类。新项目应优先使用 `ClickhouseStoreVNext`。如果需要定制组合存储，例如为某个存储域指定其他后端，请手动组合：

```typescript title="src/mastra/index.ts"
import { Mastra } from '@mastra/core'
import { MastraCompositeStore } from '@mastra/core/storage'
import { ClickhouseStore, ObservabilityStorageClickhouseVNext } from '@mastra/clickhouse'

const credentials = {
  url: process.env.CLICKHOUSE_URL!,
  username: process.env.CLICKHOUSE_USERNAME!,
  password: process.env.CLICKHOUSE_PASSWORD!,
}

export const mastra = new Mastra({
  storage: new MastraCompositeStore({
    id: 'composite-storage',
    default: new ClickhouseStore({ id: 'clickhouse-storage', ...credentials }),
    domains: {
      observability: new ObservabilityStorageClickhouseVNext(credentials),
    },
  }),
})
```

### 使用自定义 ClickHouse 客户端 {/* #bring-your-own-clickhouse-client */}

如果需要自定义请求超时、压缩或拦截器等连接设置，可以传入预先配置的客户端：

```typescript
import { createClient } from '@clickhouse/client'
import { ClickhouseStore } from '@mastra/clickhouse'

const client = createClient({
  url: process.env.CLICKHOUSE_URL!,
  username: process.env.CLICKHOUSE_USERNAME!,
  password: process.env.CLICKHOUSE_PASSWORD!,
  request_timeout: 60_000,
  compression: { request: true, response: true },
})

const storage = new ClickhouseStore({ id: 'clickhouse-storage', client })
```

`ObservabilityStorageClickhouse` 和 `ObservabilityStorageClickhouseVNext` 也接受相同形式的 `client` 参数。

`ClickhouseStore` 还接受 `ClickHouseClientConfigOptions` 的所有选项，例如 `database`、`request_timeout`、`compression`、`keep_alive` 和 `max_open_connections`。

`ClickhouseStore` 和 `ObservabilityStorageClickhouseVNext` 会将 `clickhouse_settings` 应用于各自执行的每条查询。对于 ClickHouse Cloud 等使用对象存储的服务，限制预读可降低每条可观测性查询的内存占用，但未命中本地缓存的查询可能变慢：

```typescript title="src/mastra/index.ts"
const observabilityStore = new ObservabilityStorageClickhouseVNext({
  url: process.env.CLICKHOUSE_URL!,
  username: process.env.CLICKHOUSE_USERNAME!,
  password: process.env.CLICKHOUSE_PASSWORD!,
  clickhouse_settings: {
    filesystem_prefetches_limit: 8,
  },
})
```

### 多副本集群 {/* #replicated-clusters */}

当 Mastra 通过负载均衡器向多副本 ClickHouse 集群写入时，使用 `replication`。

```typescript
const storage = new ClickhouseStoreVNext({
  id: 'clickhouse-storage',
  url: process.env.CLICKHOUSE_URL!,
  username: process.env.CLICKHOUSE_USERNAME!,
  password: process.env.CLICKHOUSE_PASSWORD!,
  replication: {
    cluster: 'company_cluster',
  },
})
```

设置 `replication` 后，Mastra 会将表引擎从 `MergeTree` 和 `ReplacingMergeTree` 分别改为 `ReplicatedMergeTree` 和 `ReplicatedReplacingMergeTree`。默认引擎参数为：

* `zookeeperPath`: `'/clickhouse/tables/{shard}/{database}/{table}'`
* `replicaName`: `'{replica}'`

这些默认值符合常见的自建集群约定。如果集群中现有表使用其他路径布局，例如不含 `{database}` 段的 `/clickhouse/tables/{shard}/{table}`，请显式设置匹配的 `zookeeperPath`。Mastra 不会从 Keeper 读取集群约定；路径不匹配会使 Mastra 的元数据写入与集群其余部分不同的分支。

```typescript
new ClickhouseStoreVNext({
  url: process.env.CLICKHOUSE_URL!,
  username: process.env.CLICKHOUSE_USERNAME!,
  password: process.env.CLICKHOUSE_PASSWORD!,
  replication: {
    cluster: 'company_cluster',
    zookeeperPath: '/clickhouse/tables/{shard}/{table}',
  },
})
```

设置 `cluster` 后，Mastra 会在其管理的建表、创建物化视图、列迁移、修改 TTL 和删表等 DDL 中添加 `ON CLUSTER`。

设置 `cluster` 后，`optimizeTable()` 和 `materializeTtl()` 等手动维护操作会在每个副本上运行。大型集群执行这些操作的开销可能很高，最好安排在非高峰时段；常规合并应交给后台合并队列，无需每次重启都主动触发。

如果现有 Mastra 表使用本地 `MergeTree` 或 `ReplacingMergeTree` 引擎，启用 `replication` 后初始化会失败。Mastra 不会自动转换本地表，因为跨副本复制并替换表不安全。启用复制前，需将相关表重建为 `Replicated*` 表。安全迁移的步骤是：重命名本地表，执行 `CREATE TABLE ... ENGINE = ReplicatedMergeTree(...) ON CLUSTER ...`，再执行 `INSERT INTO ... SELECT * FROM <renamed_local>`，最后删除 `<renamed_local>`。

不要在 ClickHouse Cloud 上设置 `replication`。Cloud 会在服务端将 `MergeTree` 改写为 `SharedMergeTree`；显式使用 `ReplicatedMergeTree` 会生成错误的 DDL。`replication` 仅适用于自建多副本集群。

### 可观测性域选项 {/* #observability-domain-options */}

`ObservabilityStorageClickhouse` 和 `ObservabilityStorageClickhouseVNext` 接受与 `ClickhouseStore` 相同的连接选项：`url`、`username`、`password` 或预先配置的 `client`。`ObservabilityStorageClickhouseVNext` 还接受 `retention`（按天设置的逐信号 TTL，参见 [ClickHouse 原生 TTL](/reference/storage/retention#clickhouse-native-ttl)）和 `traceQuery`（[追踪查询](/reference/observability/tracing/advanced-queries)的执行限制）。

## 托管选项 {/* #hosting-options */}

只要能够通过 HTTP 访问，就可以使用 ClickHouse。常见方案包括：

* **[ClickHouse Cloud](https://clickhouse.com/cloud)**：提供免费试用层级的托管服务。其连接信息可直接用于 `url`、`username` 和 `password`。
* **自行部署**：运行官方 [`clickhouse/clickhouse-server`](https://hub.docker.com/r/clickhouse/clickhouse-server) 容器，或通过[官方安装包](https://clickhouse.com/docs/en/install)安装。适用于 VPS、专用服务器或 Kubernetes。

本地开发时：

```bash
docker run -d --name mastra-clickhouse \
  -p 8123:8123 -p 9000:9000 \
  -e CLICKHOUSE_USER=default \
  -e CLICKHOUSE_PASSWORD=password \
  clickhouse/clickhouse-server
```

```typescript
new ObservabilityStorageClickhouseVNext({
  url: 'http://localhost:8123',
  username: 'default',
  password: 'password',
})
```

## 使用 Railway 和类似平台进行部署 {/* #deploying-with-railway-and-similar-platforms */}

[Railway](https://railway.com)、[Fly.io](https://fly.io)、[Render](https://render.com) 和 Heroku 等平台在临时文件系统上运行应用容器。DuckDB 等嵌入式可观测性后端需要可写且持久的本地文件，因此在这些平台上可能重启后丢失数据，甚至无法部署。

此时可使用 ClickHouse。通过 HTTP 访问 ClickHouse，同一套连接配置可用于不同的应用托管平台：

```typescript title="src/mastra/index.ts"
import { Mastra } from '@mastra/core'
import { MastraCompositeStore } from '@mastra/core/storage'
import { PostgresStore } from '@mastra/pg'
import { ObservabilityStorageClickhouseVNext } from '@mastra/clickhouse'
import { Observability, MastraStorageExporter } from '@mastra/observability'

export const mastra = new Mastra({
  storage: new MastraCompositeStore({
    id: 'composite-storage',
    default: new PostgresStore({
      id: 'pg',
      connectionString: process.env.DATABASE_URL!,
    }),
    domains: {
      observability: new ObservabilityStorageClickhouseVNext({
        url: process.env.CLICKHOUSE_URL!,
        username: process.env.CLICKHOUSE_USERNAME!,
        password: process.env.CLICKHOUSE_PASSWORD!,
      }),
    },
  }),
  observability: new Observability({
    configs: {
      default: {
        serviceName: 'mastra',
        exporters: [new MastraStorageExporter()],
      },
    },
  }),
})
```

使用以下任一选项配置数据库：

* **托管服务**：使用 ClickHouse Cloud，并在应用托管平台上设置 `CLICKHOUSE_URL`、`CLICKHOUSE_USERNAME` 和 `CLICKHOUSE_PASSWORD` 环境变量。
* **在 Railway 上自行部署**：使用官方 Docker 镜像为 Railway 项目添加 ClickHouse 服务，再通过 Railway 私有网络从应用服务访问它。

其他使用临时文件系统的托管平台也适用。若应用数据也需要存放在应用主机之外，请为 `default` 存储搭配托管 PostgreSQL 或 LibSQL/Turso 实例。

:::warning
不要将像 DuckDB 这样的嵌入式后端指向临时容器文件系统内的路径。当容器重新启动时，写入其中的数据会丢失，并且在某些平台上该路径是只读的。
:::

## 初始化 {/* #initialization */}

传入 `Mastra` 类后，`ClickhouseStore` 会自动调用 `init()`，创建表结构并执行待运行的迁移。通过 `MastraCompositeStore` 使用 `ObservabilityStorageClickhouseVNext` 时也是如此。

如果在 `Mastra` 之外管理存储，请显式调用 `init()`：

```typescript
import { ObservabilityStorageClickhouseVNext } from '@mastra/clickhouse'

const observability = new ObservabilityStorageClickhouseVNext({
  url: process.env.CLICKHOUSE_URL!,
  username: process.env.CLICKHOUSE_USERNAME!,
  password: process.env.CLICKHOUSE_PASSWORD!,
})

await observability.init()
```

在 CI/CD 流水线中，可以为 `ClickhouseStore` 设置 `disableInit: true`，并在使用高权限凭据的部署步骤中运行 `init()`。应用运行时凭据需要：

* 对 Mastra 表的 `SELECT` 和 `INSERT` 权限。
* 对需要删除数据的可观测性表的 `ALTER DELETE` 权限。在 ClickHouse 26.6 及更早版本中，轻量级删除还需要这些表的 `ALTER UPDATE` 权限；ClickHouse 26.7 已取消这一要求。

## 可观察性 {/* #observability */}

ClickHouse 是生产环境可观测性的推荐后端：

* **仅插入策略**：`MastraStorageExporter` 批量写入已完成的 span，无需逐个更新，因而可获得最高的写入吞吐量。
* **列式压缩**：与行式数据库中的相同数据相比，span 属性和日志载荷通常能获得更好的压缩效果。

完整的策略对照和生产环境指南参见 [`MastraStorageExporter` 参考文档](/docs/observability/integrations/exporters/mastra-storage#storage-provider-support)。
