# DuckDB

[DuckDB](https://duckdb.org/) 是一种嵌入式分析数据库，在应用进程内运行。`@mastra/duckdb` 包为本地开发提供基于 OLAP 的可观测性存储，无需运行外部服务即可存储链路追踪数据、日志、指标、评分和反馈。

如需进行向量搜索，请参阅 [DuckDB 向量存储参考文档](/integrations/vectors/duckdb)。向量存储使用同一个包中的独立 API。

## 何时使用 DuckDB {/* #when-to-use-duckdb */}

DuckDB 适合在本地开发可观测性功能。它采用嵌入式架构，以文件存储数据，无需启动单独的数据库服务器即可使用。它支持与 ClickHouse 相同的可观测性信号，可用于在部署到生产后端前测试仪表盘和探索链路追踪数据。

DuckDB 目前只实现了 `observability` 存储域。在[组合存储](/reference/storage/composite)中，可以搭配 [LibSQL](/integrations/databases/libsql) 等存储适配器来支持 `memory` 和 `workflows`。

:::warning
DuckDB 适用于开发环境，不建议用于生产。它在应用进程内运行，将数据持久化到单个本地文件，无法在使用临时文件系统的平台上运行，例如 Railway、Fly.io、Render、Heroku 或无服务器容器。生产环境中的可观测性存储请使用 [ClickHouse](/integrations/databases/clickhouse)。
:::

## 安装 {/* #installation */}

```bash npm2yarn
npm install @mastra/duckdb@latest
```

## 用法 {/* #usage */}

### 在组合存储中提供可观测性存储 {/* #as-the-observability-domain-in-a-composite-store */}

这是本地开发的标准配置。DuckDB 负责可观测性存储，LibSQL 负责其他存储域。

```typescript title="src/mastra/index.ts"
import { Mastra } from '@mastra/core'
import { MastraCompositeStore } from '@mastra/core/storage'
import { LibSQLStore } from '@mastra/libsql'
import { DuckDBStore } from '@mastra/duckdb'
import { Observability, MastraStorageExporter } from '@mastra/observability'

export const mastra = new Mastra({
  storage: new MastraCompositeStore({
    id: 'composite-storage',
    default: new LibSQLStore({
      id: 'mastra-storage',
      url: 'file:./mastra.db',
    }),
    domains: {
      observability: new DuckDBStore().observability,
    },
  }),
  observability: new Observability({
    configs: {
      default: {
        serviceName: 'mastra',
        exporters: [new MastraStorageExporter()],
      },
    },
  }),
})
```

通过 `.observability` 属性可以直接获取可观测性存储。也可以调用 `getStore()` 获取同一个存储实例，此方法适用于任何支持组合存储的适配器：

```typescript
const observability = await new DuckDBStore().getStore('observability')
```

### 独立使用 {/* #standalone */}

如果只需在 `Mastra` 的组合存储之外使用可观测性存储，可以直接创建 `DuckDBStore` 实例并访问其可观测性存储域：

```typescript
import { DuckDBStore } from '@mastra/duckdb'

const duckdb = new DuckDBStore({ path: './traces.duckdb' })
const observability = duckdb.observability

await observability.init()
```

### 内存数据库 {/* #in-memory-database */}

将路径设为 `:memory:` 即可使用临时的 DuckDB 内存实例。进程退出后数据会丢失，适合单元测试和短时运行的脚本。

```typescript
const duckdb = new DuckDBStore({ path: ':memory:' })
```

### 底层类型 {/* #lower-level-types */}

`@mastra/duckdb` 还导出 `DuckDBConnection` 和对应的 `DuckDBStorageConfig` 类型。通过 `DuckDBConnection`，多个 Mastra 存储实例可以共享同一个底层数据库。大多数应用无需直接使用这两个类型。

## 支持的存储域 {/* #supported-domains */}

DuckDB 目前只实现了一个存储域：

| 存储域 | 是否支持 |
| - | - |
| `observability` | 是 |
| `memory` | 否 |
| `workflows` | 否 |
| `scores` | 否 |
| `agents` | 否 |

如需覆盖所有存储域，请将 `DuckDBStore` 与支持其余存储域的适配器组合使用。本地开发通常搭配 [LibSQL](/integrations/databases/libsql)。

## 初始化 {/* #initialization */}

通过 `MastraCompositeStore` 将可观测性存储传给 `Mastra` 时，该存储域会在首次使用时自动初始化。如需在 `Mastra` 之外显式初始化，请调用可观测性存储的 `init()` 方法：

```typescript
import { DuckDBStore } from '@mastra/duckdb'

const duckdb = new DuckDBStore({ path: './traces.duckdb' })
await duckdb.observability.init()
```

## 可观测性策略 {/* #observability-strategy */}

DuckDB 支持 `MastraStorageExporter` 使用的 `event-sourced` 策略。该策略在内存中缓冲跨度数据，并批量写入已完成的事件，适合开发环境的流量规模。对于高流量的生产负载，请参阅 [`MastraStorageExporter` 支持的存储提供方](/docs/observability/integrations/exporters/mastra-storage#storage-provider-support)。
