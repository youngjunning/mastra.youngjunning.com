# 鸭数据库

[鸭数据库](https://duckdb.org/)是一个嵌入式、进程内分析数据库。这`@mastra/duckdb`包为本地开发提供了 OLAP 支持的可观察性存储，适用于跟踪、日志、指标、分数和反馈，而无需运行外部服务。

对于矢量搜索，请参阅[DuckDB vector store reference](/integrations/vectors/duckdb), which is a separate API in the same package.

## 何时使用 DuckDB {/* #when-to-use-duckdb */}

Observability特征的本地开发。 DuckDB 是嵌入式的、基于文件的，因此它不需要服务器并且可以立即启动。它支持与 ClickHouse 相同的可观察性信号，这使得它对于在部署到生产后端之前测试仪表板和跟踪探索非常有用。

DuckDB 目前仅实现了`observability` domain. Pair it with another storage adapter (such as [LibSQL](/integrations/databases/libsql)) for `memory` and `workflows`在一个[复合存储](/reference/storage/composite)设置。

:::警告
DuckDB 用于开发，不建议用于生产。它在进程内运行，持久保存到单个本地文件，并且不适用于具有临时文件系统的平台（例如 Railway、Fly.io、Render、Heroku 或无服务器容器）。对于生产可观察性，使用[ClickHouse](/integrations/databases/clickhouse).
:::

## 安装 {/* #installation */}

```bash npm2yarn
npm install @mastra/duckdb@latest
```

## 用法 {/* #usage */}

### 作为复合存储中的可观察域 {/* #as-the-observability-domain-in-a-composite-store */}

这是标准的本地开发设置。 LibSQL 处理其他领域，DuckDB 处理可观察性。

```typescript title="src/mastra/index.ts"
import { Mastra } from '@mastra/core'
import { MastraCompositeStore } from '@mastra/core/storage'
import { LibSQLStore } from '@mastra/libsql'
import { DuckDBStore } from '@mastra/duckdb'
import { Observability, MastraStorageExporter } from '@mastra/observability'

export const mastra = new Mastra({
  storage: new MastraCompositeStore({
    id: 'composite-storage',
    default: new LibSQLStore({
      id: 'mastra-storage',
      url: 'file:./mastra.db',
    }),
    domains: {
      observability: new DuckDBStore().observability,
    },
  }),
  observability: new Observability({
    configs: {
      default: {
        serviceName: 'mastra',
        exporters: [new MastraStorageExporter()],
      },
    },
  }),
})
```

这`.observability` accessor returns the observability domain store directly. The equivalent generic form uses `getStore()`, which works for any composite-style storage adapter:

```typescript
const observability = await new DuckDBStore().getStore('observability')
```

### 独立式 {/* #standalone */}

当您只需要外部可观察性存储时`Mastra` composite, instantiate `DuckDBStore` directly and access the observability domain:

```typescript
import { DuckDBStore } from '@mastra/duckdb'

const duckdb = new DuckDBStore({ path: './traces.duckdb' })
const observability = duckdb.observability

await observability.init()
```

### 内存数据库 {/* #in-memory-database */}

经过`:memory:` to use an ephemeral DuckDB instance. Data is lost when the process exits, which is appropriate for unit tests and short-lived scripts.

```typescript
const duckdb = new DuckDBStore({ path: ':memory:' })
```

### 较低级别类型 {/* #lower-level-types */}

`@mastra/duckdb`还出口`DuckDBConnection` for sharing a single underlying database across multiple Mastra storage instances, and the corresponding `DuckDBStorageConfig` type. Most applications won't need these directly.

## 支持的域 {/* #supported-domains */}

DuckDB目前实现了一种存储域：

|域名 |支持 |
| - | - |
|`observability` | Yes |
| `memory` | No |
| `workflows` | No |
| `scores` | No |
| `agents` | No |

对于完整的存储解决方案，请组成`DuckDBStore` with an adapter that covers the missing domains (most commonly [LibSQL](/integrations/databases/libsql) for local development).

## 初始化 {/* #initialization */}

当传递到`Mastra` through `MastraCompositeStore`, the observability domain initializes itself on first use. To run initialization explicitly outside of `Mastra`, call `init()` on the observability store:

```typescript
import { DuckDBStore } from '@mastra/duckdb'

const duckdb = new DuckDBStore({ path: './traces.duckdb' })
await duckdb.observability.init()
```

## 可观察性策略 {/* #observability-strategy */}

DuckDB 支持`event-sourced` strategy used by `MastraStorageExporter`, which buffers spans in memory and writes completed events in batches. This is appropriate for development-scale traffic. For high-volume production workloads, see [`MastraStorageExporter` storage provider support](/docs/observability/integrations/exporters/mastra-storage#storage-provider-support).
