# PG 向量存储

PgVector 类通过 [PostgreSQL](https://www.postgresql.org/) 的 [pgvector](https://github.com/pgvector/pgvector) 扩展提供向量搜索，让现有 PostgreSQL 数据库具备可靠的向量相似性搜索能力。

#### 内存要求 {/* #memory-requirements */}

HNSW 索引在构建期间需要大量共享内存。对于 100K 个向量：

* 低维（64d）：默认设置下约 60 MB
* 中等维度（256d）：默认设置下约 180 MB
* 高维（384d+）：默认设置下约 250 MB 或更多

较高的 M 值或 efConstruction 值会显著增加内存需求。必要时请调整系统的共享内存限制。

返回：

```typescript
interface PGIndexStats {
  dimension: number
  count: number
  metric: 'cosine' | 'euclidean' | 'dotproduct' | 'hamming' | 'jaccard'
  type: 'flat' | 'hnsw' | 'ivfflat'
  vectorType: 'vector' | 'halfvec' | 'bit' | 'sparsevec'
  config: {
    m?: number
    efConstruction?: number
    lists?: number
    probes?: number
  }
}
```

`count` 来自精确的 `SELECT COUNT(*)`，需要扫描整张表。因此，对于大型索引，应避免在高频执行路径中调用 `describeIndex()`。读写操作不会承担这项开销：它们只使用来自 Postgres 系统目录的索引元数据。

  },

  type: 'ivfflat',
  ivf: {

  },

})

## 索引配置指南 {/* #index-configuration-guide */}

### 性能优化 {/* #performance-optimization */}

#### IVFFlat 参数调整 {/* #ivfflat-tuning */}

* **lists 参数**：设为 `sqrt(n) * 2`，其中 n 为向量数量
* 列表越多，准确性越高，但构建时间越长
* 列表越少，构建越快，但准确性可能越低

#### HNSW 调整 {/* #hnsw-tuning */}

* **m 参数**：
  * 8-16：准确性适中，内存占用较低
  * 16-32：准确性高，内存占用适中
  * 32-64：准确性非常高，内存占用较高
* **efConstruction**：
  * 32-64：构建速度快，索引质量良好
  * 64-128：构建较慢，索引质量更好
  * 128-256：构建最慢，索引质量最好

### 索引重建行为 {/* #index-recreation-behavior */}

系统会自动检测配置变更，仅在必要时重建索引：

* 配置相同：保留索引，不重新创建
* 配置已变更：删除并重建索引
* 这样可避免不必要的索引重建造成性能问题

## 最佳实践 {/* #best-practices */}

* 定期评估索引配置，确保性能达到最佳。
* 根据数据集大小和查询需求调整 `lists`、`m` 等参数。
* 使用 `describeIndex()` **监控索引性能**并跟踪使用情况。
* 定期重建索引以保持效率，尤其是在数据发生大量变更后。

## 直接访问连接池 {/* #direct-pool-access */}

`PgVector` 类通过公开字段暴露其底层 PostgreSQL 连接池：

```typescript
pgVector.pool // instance of pg.Pool
```

直接访问连接池可用于直接执行 SQL 查询、事务或监控连接池状态等高级操作。直接使用连接池时：

* 使用客户端后，您需要自行调用 `client.release()` 释放它。
* 调用 `disconnect()` 后仍可访问连接池，但新的查询会失败。
* 直接访问会绕过 PgVector 方法提供的验证或事务逻辑。

这种设计支持高级用例，但要求使用者谨慎管理资源。

## 使用示例 {/* #usage-example */}

### 使用 fastembed 进行本地嵌入 {/* #local-embeddings-with-fastembed */}

嵌入是数值向量，Memory 的 `semanticRecall` 用它按语义而非关键词检索相关消息。此配置使用 `@mastra/fastembed` 生成向量嵌入。

首先安装 `fastembed`：

```bash npm2yarn
npm install @mastra/fastembed@latest
```

将以下内容添加到您的 Agent 中：

```typescript title="src/mastra/agents/example-pg-agent.ts"
import { Memory } from '@mastra/memory'
import { Agent } from '@mastra/core/agent'
import { PostgresStore, PgVector } from '@mastra/pg'
import { fastembed } from '@mastra/fastembed'

export const pgAgent = new Agent({
  id: 'pg-agent',
  name: 'PG Agent',
  instructions:
    'You are an AI agent with the ability to automatically recall memories from previous interactions.',
  model: '__GATEWAY_OPENAI_MODEL__',
  memory: new Memory({
    storage: new PostgresStore({
      id: 'pg-agent-storage',
      connectionString: process.env.DATABASE_URL!,
    }),
    vector: new PgVector({
      id: 'pg-agent-vector',
      connectionString: process.env.DATABASE_URL!,
    }),
    embedder: fastembed,
    options: {
      lastMessages: 10,
      semanticRecall: {
        topK: 3,
        messageRange: 2,
      },
    },
  }),
})
```
