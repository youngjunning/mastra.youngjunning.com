# PG矢量存储

PgVector 类提供向量搜索[PostgreSQL](https://www.postgresql.org/)和[PG向量](https://github.com/pgvector/pgvector)扩大。它在您现有的 PostgreSQL 数据库中提供可靠的矢量相似性搜索功能。

### 连接字符串 {/* #connection-string */}

```ts
import { PgVector } from '@mastra/pg'

```

```ts
const vectorStore = new PgVector({
```

#### 内存要求 {/* #memory-requirements */}

HNSW 索引在构建期间需要大量共享内存。对于 100K 向量：

* 小尺寸 (64d)：默认设置约 60MB
* 中等尺寸 (256d)：默认设置约 180MB
* 大尺寸 (384d+)：默认设置约 250MB+

较高的 M 值或 efConstruction 值将显着增加内存需求。如果需要，调整系统的共享内存限制。

返回：

```typescript
interface PGIndexStats {
  dimension: number
  count: number
  metric: 'cosine' | 'euclidean' | 'dotproduct' | 'hamming' | 'jaccard'
  type: 'flat' | 'hnsw' | 'ivfflat'
  vectorType: 'vector' | 'halfvec' | 'bit' | 'sparsevec'
  config: {
    m?: number
    efConstruction?: number
    lists?: number
    probes?: number
  }
}
```

`count`是一个精确的`SELECT COUNT(*)`, which scans the whole table, so avoid calling `describeIndex()` on a hot path for a large index. Reads and writes never pay for it: they only use the index metadata, which comes from the Postgres catalog.

```typescript

  type: 'hnsw',
  hnsw: {
    m: 8,
    efConstruction: 32,
  },
})

// Define IVF index
await pgVector.buildIndex('my_vectors', 'cosine', {
  type: 'ivfflat',
  ivf: {
    lists: 100,
  },
})

// Define flat index
await pgVector.buildIndex('my_vectors', 'cosine', {
  type: 'flat',
})
```

## 索引配置指南 {/* #index-configuration-guide */}

### 性能优化 {/* #performance-optimization */}

#### IVF平面调谐 {/* #ivfflat-tuning */}

* **列出参数**：设置为`sqrt(n) * 2` where n is the number of vectors
* 更多列表 = 更高的准确性，但构建时间更慢
* 更少的列表 = 更快的构建，但可能会降低准确性

#### HNSW 调整 {/* #hnsw-tuning */}

* **m参数**:
  * 8-16：中等精度，较低内存
  * 16-32：精度高，内存适中
  * 32-64：非常高精度，高内存
* **ef建筑**:
  * 32-64：构建速度快，质量好
  * 64-128：构建速度较慢，质量更好
  * 128-256：最慢的构建，最好的质量

### 休闲行为指数 {/* #index-recreation-behavior */}

系统自动检测配置更改，仅在必要时重建索引：

* 相同配置：保留索引（不重新创建）
* 更改的配置：索引被删除并重建
* 这可以防止不必要的索引重新创建带来的性能问题

## 最佳实践 {/* #best-practices */}

* 定期评估您的索引配置以确保最佳性能。
* 调整参数如`lists` and `m` based on dataset size and query requirements.
* **监控指数表现**使用`describeIndex()` to track usage
* 定期重建索引以保持效率，尤其是在大量数据更改之后

## 直接访问泳池 {/* #direct-pool-access */}

这`PgVector` class exposes its underlying PostgreSQL connection pool as a public field:

```typescript
pgVector.pool // instance of pg.Pool
```

直接池访问支持高级操作，例如直接 SQL 查询、事务或池状态监视。直接使用池时：

* 您负责释放客户（`client.release()`) after use.
* 调用后泳池仍可访问`disconnect()`, but new queries will fail.
* 直接访问绕过 PgVector 方法提供的任何验证或事务逻辑。

此设计支持高级用例，但需要用户仔细管理资源。

## 使用示例 {/* #usage-example */}

### 使用 fastembed 进行本地嵌入 {/* #local-embeddings-with-fastembed */}

嵌入是内存使用的数字向量`semanticRecall` to retrieve related messages by meaning (not keywords). This setup uses `@mastra/fastembed` to generate vector embeddings.

安装`fastembed` to get started:

```bash npm2yarn
npm install @mastra/fastembed@latest
```

将以下内容添加到您的Agent中：

```typescript title="src/mastra/agents/example-pg-agent.ts"
import { Memory } from '@mastra/memory'
import { Agent } from '@mastra/core/agent'
import { PostgresStore, PgVector } from '@mastra/pg'
import { fastembed } from '@mastra/fastembed'

export const pgAgent = new Agent({
  id: 'pg-agent',
  name: 'PG Agent',
  instructions:
    'You are an AI agent with the ability to automatically recall memories from previous interactions.',
  model: '__GATEWAY_OPENAI_MODEL__',
  memory: new Memory({
    storage: new PostgresStore({
      id: 'pg-agent-storage',
      connectionString: process.env.DATABASE_URL!,
    }),
    vector: new PgVector({
      id: 'pg-agent-vector',
      connectionString: process.env.DATABASE_URL!,
    }),
    embedder: fastembed,
    options: {
      lastMessages: 10,
      semanticRecall: {
        topK: 3,
        messageRange: 2,
      },
    },
  }),
})
```
