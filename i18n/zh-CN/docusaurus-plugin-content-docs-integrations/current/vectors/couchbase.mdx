# Couchbase 向量存储

`CouchbaseVector` 类通过 [Couchbase Vector Search](https://docs.couchbase.com/server/current/vector-search/vector-search.html) 提供向量搜索，可在现有 Couchbase 集合中高效执行相似性搜索。

## 前提条件 {/* #requirements */}

* **Couchbase Server 7.6.4 或更高版本**，或兼容的 Capella 集群
* Couchbase 部署中已**启用 Search Service**

## 安装 {/* #installation */}

```bash npm2yarn
npm install @mastra/couchbase@latest
```

## 使用示例 {/* #usage-example */}

```typescript
import { CouchbaseVector } from '@mastra/couchbase'

const store = new CouchbaseVector({
  id: 'couchbase-vector',
  connectionString: process.env.COUCHBASE_CONNECTION_STRING,
  username: process.env.COUCHBASE_USERNAME,
  password: process.env.COUCHBASE_PASSWORD,
  bucketName: process.env.COUCHBASE_BUCKET,
  scopeName: process.env.COUCHBASE_SCOPE,
  collectionName: process.env.COUCHBASE_COLLECTION,
})
```

## 方法 {/* #methods */}

### `createIndex()` {/* #createindex */}

在 Couchbase 中创建新的向量索引。

:::note

索引创建是异步的。调用 `createIndex` 后，应等待索引就绪再查询：小数据集通常需要 1 至 5 秒，大数据集可能更久。生产环境应轮询索引状态，而非等待固定时长。

:::

### `deleteVectors()` {/* #deletevectors */}

从已配置的 Couchbase 集合中按 ID 删除向量。传入非空 `ids` 数组可删除多个文档；不存在的 ID 会被忽略。不支持按筛选条件删除，传入 `filter` 会抛出 `MastraError`。`ids` 为空、同时传入 `ids` 和 `filter`，或两者都未传入，也会抛出错误。

```typescript
await store.deleteVectors({ indexName: 'my_index', ids: ['vec_1', 'vec_2'] })
```

## 错误处理 {/* #error-handling */}

向量存储会抛出可捕获的类型化错误：

```typescript
try {
  await store.query({
    indexName: 'my_index',
    queryVector: queryVector,
  })
} catch (error) {
  // Handle specific error cases
  if (error.message.includes('Invalid index name')) {
    console.error(
      'Index name must start with a letter or underscore and contain only valid characters.',
    )
  } else if (error.message.includes('Index not found')) {
    console.error('The specified index does not exist')
  } else {
    console.error('Vector store error:', error.message)
  }
}
```

## 注意事项 {/* #notes */}

* **删除索引：**删除 Search 索引不会删除关联 Couchbase 集合中的向量或文档。除非显式删除，数据会继续保留。
* **所需权限：**Couchbase 用户须有连接权限、目标集合的文档读写权限（`kv` 角色），以及相关 bucket/scope 的 Search 索引管理权限（`search_admin` 角色）。
* **索引定义与文档结构：**`createIndex` 为 `scopeName.collectionName` 中的文档创建 Search 索引定义，将 `embedding` 字段作为向量索引，将 `content` 字段作为文本索引。每个文档的向量保存在 `embedding` 中，元数据保存在 `metadata` 中。若 `metadata` 包含 `text` 属性，该属性也会复制到顶层 `content` 字段，以供文本搜索。
* **复制与持久性：**可考虑使用 Couchbase 内置的复制和持久化功能保障数据持久性，并定期监控索引统计信息，确保搜索效率。

## 局限性 {/* #limitations */}

* 创建索引需要时间，创建后立即查询可能受到影响。
* 只有在同一个 `CouchbaseVector` 实例上调用 `createIndex()` 创建新索引后，写入时才会检查向量维度。对已有索引调用 `createIndex()` 不会启用写入检查。启用后，`upsert()` 和 `updateVector()` 遇到维度不匹配会抛出错误。`query()` 始终会根据索引维度检查查询向量。
* `deleteVectors()` 仅支持按 ID 删除，不支持按元数据筛选条件删除。
* 向量写入和索引更新采用最终一致性，写入后不能立即保证强一致性。
