# Lance 向量存储

LanceVectorStore 类使用 [LanceDB](https://lancedb.github.io/lancedb/) 提供向量搜索。LanceDB 是基于 Lance 列式格式构建的嵌入式向量数据库，可为本地开发和生产部署提供高效存储与快速的相似度搜索。

## 工厂方法 {/* #factory-method */}

LanceVectorStore 采用工厂模式创建实例。应使用静态 create() 方法，而不是直接调用构造函数。

## 创建实例示例 {/* #constructor-examples */}

可以使用静态 `create()` 方法创建 `LanceVectorStore` 实例：

```ts
import { LanceVectorStore } from '@mastra/lance'

// Connect to a local database
const vectorStore = await LanceVectorStore.create('/path/to/db')

// Connect to a LanceDB cloud database
const cloudStore = await LanceVectorStore.create('db://host:port')

// Connect to a cloud database with options
const s3Store = await LanceVectorStore.create('s3://bucket/db', {
  storageOptions: { timeout: '60s' },
})
```

### `optimize()` {/* #optimize */}

#### 何时优化 {/* #when-to-optimize */}

`upsert()` 写入的行暂不在现有向量索引中。`query()` 仍会扫描这些未索引的行并返回它们，因此结果保持完整；但随着未索引行增多，查询会变慢。LanceDB 的 `fastSearch()` 则会完全跳过未索引的行。

`optimize()` 会将新行加入现有索引，而不会重新训练索引。如果数据分布变化很大，应改用 `deleteIndex()` 和 `createIndex()` 重建索引。

LanceDB 建议在大约修改 100,000 行或执行 20 次写入操作后进行优化。可以使用 `getIndexCoverage()` 制定自己的优化策略：

```typescript
const [coverage] = await store.getIndexCoverage({ indexName: 'docs' })
const total = coverage.numIndexedRows + coverage.numUnindexedRows

if (coverage.numUnindexedRows >= 1_000 && coverage.numUnindexedRows / total >= 0.1) {
  await store.optimize({ indexName: 'docs' })
}
```

托管版 LanceDB Cloud 和 Enterprise 会自动维护表，因此无需在这些环境中调用 `optimize()`。

## 最佳实践 {/* #best-practices */}

* 根据使用场景选择合适的索引类型：
  * 内存不受限时，HNSW 可提供更高的召回率和更好的性能
  * 对大型数据集，IVF 的内存利用率更高
* 对大型数据集，可考虑调整 `numPartitions` 和 `numSubVectors` 以优化性能
* 使用完数据库后，调用 `close()` 正确关闭连接
* 以一致的数据结构存储元数据，简化过滤操作
