# 兰斯矢量店

LanceVectorStore 类提供矢量搜索，使用[LanceDB](https://lancedb.github.io/lancedb/)，一个基于 Lance 柱状格式构建的嵌入式矢量数据库。它为本地开发和生产部署提供高效的存储和快速的相似性搜索。

## 工厂方法 {/* #factory-method */}

LanceVectorStore 使用工厂模式进行创建。你应该使用静态`create()` method rather than the constructor directly.

## 构造函数示例 {/* #constructor-examples */}

您可以创建一个`LanceVectorStore` instance using the static create method:

```ts
import { LanceVectorStore } from '@mastra/lance'

// Connect to a local database
const vectorStore = await LanceVectorStore.create('/path/to/db')

// Connect to a LanceDB cloud database
const cloudStore = await LanceVectorStore.create('db://host:port')

// Connect to a cloud database with options
const s3Store = await LanceVectorStore.create('s3://bucket/db', {
  storageOptions: { timeout: '60s' },
})
```

### `optimize()` {/* #optimize */}

运行 LanceDB 表维护。它压缩数据文件，将自索引构建以来写入的行添加到现有索引，并删除旧的表版本。马斯特拉从不自动调用它。一个进程中对同一个表的并发调用共享一次运行。

#### 何时优化 {/* #when-to-optimize */}

`upsert()`将行写入现有向量索引之外。`query()` still returns those rows by scanning them without the index, so results stay complete, but queries get slower as unindexed rows grow. LanceDB's `fastSearch()` skips unindexed rows entirely.

`optimize()`将新行添加到现有索引而不重新训练它。如果您的数据分布发生了很大变化，请使用以下命令重建索引`deleteIndex()` and `createIndex()` instead.

LanceDB 建议在大约 100,000 条修改行或 20 次写入操作后进行优化。使用`getIndexCoverage()` to build your own policy:

```typescript
const [coverage] = await store.getIndexCoverage({ indexName: 'docs' })
const total = coverage.numIndexedRows + coverage.numUnindexedRows

if (coverage.numUnindexedRows >= 1_000 && coverage.numUnindexedRows / total >= 0.1) {
  await store.optimize({ indexName: 'docs' })
}
```

托管LanceDB Cloud和Enterprise自动维护表，因此您无需调用`optimize()` there.

## 最佳实践 {/* #best-practices */}

* 使用适合您的用例的索引类型：
  * HNSW 在内存不受限制时提供更好的回忆和性能
  * IVF 可提高大型数据集的内存效率
* 为了获得大型数据集的最佳性能，请考虑调整`numPartitions` and `numSubVectors` values
* 使用`close()` method to properly close connections when done with the database
* 使用一致的模式存储元数据以简化过滤操作
