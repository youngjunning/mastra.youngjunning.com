# MongoDB 向量存储

`MongoDBVector` 类通过 [MongoDB Vector Search](https://www.mongodb.com/docs/atlas/atlas-vector-search/) 提供向量搜索，可在 MongoDB 集合中高效执行相似性搜索和元数据过滤。

## 安装 {/* #installation */}

```bash npm2yarn
npm install @mastra/mongodb@latest
```

## 使用示例 {/* #usage-example */}

```typescript
import { MongoDBVector } from '@mastra/mongodb'

const store = new MongoDBVector({
  id: 'mongodb-vector',
  uri: process.env.MONGODB_URI,
  dbName: process.env.MONGODB_DB_NAME,
})
```

### 自定义嵌入字段路径 {/* #custom-embedding-field-path */}

如果需要将嵌入存储在嵌套字段中，例如与现有 MongoDB 集合集成，请使用 `embeddingFieldPath` 选项：

```typescript
import { MongoDBVector } from '@mastra/mongodb'

const store = new MongoDBVector({
  id: 'mongodb-vector',
  uri: process.env.MONGODB_URI,
  dbName: process.env.MONGODB_DB_NAME,
  embeddingFieldPath: 'text.contentEmbedding', // Store embeddings at text.contentEmbedding
})
```

### `createSearchIndex()` {/* #createsearchindex */}

在向量索引对应的集合上创建 MongoDB Search（BM25/全文）索引，并将其记录为 `textQuery()` 和 `hybridQuery()` 使用的文本搜索索引。

**托管集合与自有集合：**

* 对于**托管索引**（创建时未指定 `collectionName`），`createIndex()` 已创建名为 `${collectionName}_search_index` 的*动态*全文索引，覆盖所有字符串字段。因此，只有需要**限定字段**的映射或**自定义索引名称**时，才需要调用 `createSearchIndex()`。
* 对于**自有索引**（创建时指定了 `collectionName`），`createIndex()` 不会自动创建全文索引。若要在调用方拥有的业务集合上使用 `textQuery()`/`hybridQuery()`，必须显式调用 `createSearchIndex()` 创建可能产生费用的文本索引。调用之前，`textQuery()`/`hybridQuery()` 会明确报错，而不会查询不存在的索引。

命名：

* 提供 `fields` 但**未**显式指定 `searchIndexName` 时，字段映射索引会使用**独立**的默认名称 `${collectionName}_${indexName}_search_fields_index`（每个逻辑索引各不相同），避免与托管集合自动创建的动态索引冲突而被静默忽略。该名称会持久记录为文本搜索索引，`textQuery()`/`hybridQuery()` 因而会自动使用限定字段的映射。
* 指定 `searchIndexName` 时，会使用并持久保存该确切名称。`textQuery()`/`hybridQuery()` 会自动找到已保存的名称；也可以通过各自的 `searchIndexName` / `textSearchIndexName` 参数覆盖单次调用使用的名称。

对于 `autoEmbed` 索引，`dimension` 从索引定义读取；若索引未指定维度，则报告 MongoDB 的默认值 `1024`。如果`autoEmbed` 索引未指定相似性函数，结果会省略 `metric`。由于生成的向量不存储在文档中，`count` 统计的是包含嵌入文本字段的文档数量。

### `deleteIndex()` {/* #deleteindex */}

删除向量索引。行为取决于索引的创建方式：

* **托管索引**（创建时未指定 `collectionName`）：删除整个集合及其中所有数据。
* **自有索引**（创建时指定了 `collectionName`）：删除 MongoDB vectorSearch 索引。如果 `createSearchIndex()` 还创建了配套的全文搜索索引，也会删除该索引。同一集合上的其他逻辑索引仍在引用的 vectorSearch 或全文索引会予以保留。调用方的业务集合及其文档不受影响。本存储绝不会删除不是由它创建的集合。

索引创建时会持久记录其自有集合类别，因此即使由另一个进程操作，也能正确应用删除规则，例如初始化任务创建索引后由长期运行的服务删除。请始终传入**逻辑索引名称**（调用 `createIndex` 时使用的 `indexName`），而非实际集合名称。

## 自动嵌入 {/* #automated-embedding */}

MongoDB 可以代为生成嵌入。创建索引时设置 `autoEmbed` 和 Voyage AI 模型，通过 `documents` 写入纯文本，再使用 `queryText` 搜索。应用程序无需运行嵌入 Provider，也无需传输向量。

```typescript
import { MongoDBVector } from '@mastra/mongodb'

const store = new MongoDBVector({
  id: 'mongodb-vector',
  uri: process.env.MONGODB_URI,
  dbName: process.env.MONGODB_DB_NAME,
})

// No `dimension`: the embedding model determines it.
await store.createIndex({
  indexName: 'movies',
  autoEmbed: { model: 'voyage-4' },
  filterFields: ['year'],
})

// Automated Embedding indexes build slower than client-embedded ones.
await store.waitForIndexReady({ indexName: 'movies', timeoutMs: 300000 })

// No `vectors`: MongoDB embeds the text as documents are written.
await store.upsert({
  indexName: 'movies',
  documents: [
    'A lonely astronaut adrift near a strange ocean planet.',
    'A heist crew robs a bank vault in Paris.',
  ],
  metadata: [{ year: 1972 }, { year: 2001 }],
})

// No `queryVector`: MongoDB embeds the query string with the same model.
const results = await store.query({
  indexName: 'movies',
  queryText: 'space opera about isolation',
  topK: 5,
  filter: { year: { $gt: 1970 } },
})
```

`autoEmbed` 索引定义接受的其他字段会原样传给 MongoDB，因此即使软件包未更新，也可以使用此版本发布后新增的选项。省略的选项沿用 MongoDB 的默认值。

**重要提示：**

* 自动嵌入是 **MongoDB 预览功能**。它需要支持自动嵌入的 Atlas 集群；本地开发可使用 `mongodb/mongodb-atlas-local:preview` 镜像。自行管理的部署还需为 `mongot` 配置 Voyage AI API 密钥。
* Voyage AI API 密钥必须通过 Atlas UI 进行配置。由 Voyage AI 直接颁发的密钥会被默认嵌入端点拒绝。
* **MongoDB 将生成的向量存储在集合之外**，因此文档仅包含文本。`autoEmbed` 索引不支持 `includeVector: true`，使用时会报错。
* 嵌入是异步生成的。即使索引报告就绪，查询也可以在写入后短时间内合法地不返回结果。
* 索引只能声明向量字段或 `autoEmbed` 字段，不能同时声明。省略 `autoEmbed` 即可继续自行提供向量；客户端生成嵌入的流程不变。
* 向 `autoEmbed` 索引传入 `vectors` 会报错，因为这些向量会写入索引不会读取的字段。
* 当 `document` 是生成嵌入所用的字段时，它不再是已声明的过滤字段，因此 `documentFilter` 会自动使用 `$match` 预过滤。通过 `filterFields` 声明的元数据过滤条件仍会下推到 `$vectorSearch`。
* `updateVector()` 不允许更新 `autoEmbed` 索引的向量。请改为使用新文本更新或插入文档，MongoDB 会重新生成嵌入。
* `queryVector` 仍可用于 `autoEmbed` 索引，但向量必须由兼容的模型生成，并与索引的 `quantization` 匹配；不匹配时 MongoDB 会拒绝查询。
* 文档和查询的嵌入生成均按 token 计费。

## 为现有集合建立索引 {/* #indexing-an-existing-collection */}

可以直接在现有业务集合上创建向量索引，而不使用托管集合。这样就能为 MongoDB 数据库中已有的文档增加向量搜索能力。

```typescript
import { MongoDBVector } from '@mastra/mongodb'

const store = new MongoDBVector({
  id: 'mongodb-vector',
  uri: process.env.MONGODB_URI,
  dbName: process.env.MONGODB_DB_NAME,
})

// Create a vector index on an existing 'transactions' collection
await store.createIndex({
  indexName: 'precedents',
  dimension: 1024,
  collectionName: 'transactions', // Use existing collection
  searchIndexName: 'txn_vec_idx', // Custom search index name
})

// Wait for the index to be ready
await store.waitForIndexReady({ indexName: 'precedents' })

// Query using document mode to get full source documents
const hits = await store.query({
  indexName: 'precedents',
  queryVector: embeddings,
  topK: 5,
  metadataMode: 'document', // Returns full document as metadata
})

// hits[0].metadata now contains all fields from the source document
console.log(hits[0].metadata.amount, hits[0].metadata.customField)

// Full-text / hybrid search on a BYO collection is opt-in: provision the text index first.
await store.createSearchIndex({ indexName: 'precedents', fields: ['note'] })
```

**重要提示：**

* 集合必须已经存在，且文档包含 `embedding` 字段，或包含所配置的自定义 `embeddingFieldPath` 字段。
* 指定 `collectionName` 后，本存储绝不会创建或删除该集合。
* **自有索引默认只读。** `upsert()`、`updateVector()`、`deleteVector()` 和 `deleteVectors()` 会明确报错，不会修改调用方的业务文档。若要允许本存储向集合写入嵌入或删除文档，须显式调用 `createIndex({ ..., allowWrites: true })`。该策略会持久保存，重启后仍然生效。旧版本写入且没有此标志的条目按只读处理，以安全方式拒绝写入。
* 查询时使用 `metadataMode: 'document'`，可将完整源文档作为 `metadata` 返回。
* 在 `'document'` 模式下，默认从 `metadata` 中省略嵌入字段；传入 `includeVector: true` 可保留该字段，并将其作为顶层 `vector` 返回。
* **`'document'` 模式的过滤作用于根文档字段**，而非嵌套的 `metadata.` 子文档。`filter: { lane: 'fraud' }` 匹配业务文档顶层的 `lane` 字段；在默认的 `'field'` 模式下，托管集合的裸字段名会改写为 `metadata.<field>`。下推过滤与 `$match` 回退路径都遵循此规则。
* **支持原生 `ObjectId` 类型的 `_id`。** 业务集合通常使用 `ObjectId` 作为键；查询结果会按 `QueryResult.id` 契约将 `_id` 转为字符串，`deleteVector()`/`updateVector()`/`deleteVectors()` 接受该字符串并匹配底层 `ObjectId` 文档。使用字符串 `_id` 的托管集合不受影响。
* 自有集合上的全文和混合搜索需要**显式启用**：系统不会自动创建全文索引，因此须在调用 `textQuery()`/`hybridQuery()` 前调用 `createSearchIndex()`。全文索引是异步构建的；若要立即执行文本或混合查询，请先调用 `waitForSearchIndexReady()`，或传入 `waitUntilReady: true`。
* 对自有索引调用 `deleteIndex()` 会删除向量索引，以及已创建的文本索引，但会**保留**集合及其中的文档。

## 最佳实践 {/* #best-practices */}

* 为过滤条件使用的元数据字段建立索引，以获得更好的查询性能。
* 在元数据中使用一致的字段命名以避免意外的查询结果。
* 定期监控索引和集合统计信息以确保高效搜索。
* 为现有集合建立索引时，确保所有文档都有必需的 `embedding` 字段。

### 在 `MongoDB` 中使用向量嵌入 {/* #vector-embeddings-with-mongodb */}

嵌入是数字向量，Memory 的 `semanticRecall` 用它按语义而非关键词检索相关消息。

:::note

建议在生产环境使用 MongoDB Vector Search。对于自行托管的部署，可通过 [Atlas CLI 创建本地 Atlas 部署](https://www.mongodb.com/docs/atlas/cli/current/atlas-cli-deploy-local/)来使用 Vector Search。

:::

此设置使用 FastEmbed（一种本地嵌入模型）来生成向量嵌入。
要使用它，请安装 `@mastra/fastembed`：

```bash npm2yarn
npm install @mastra/fastembed@latest
```

将以下内容添加到 Agent 中：

```typescript title="src/mastra/agents/example-mongodb-agent.ts"
import { Memory } from '@mastra/memory'
import { Agent } from '@mastra/core/agent'
import { MongoDBStore, MongoDBVector } from '@mastra/mongodb'
import { fastembed } from '@mastra/fastembed'

export const mongodbAgent = new Agent({
  id: 'mongodb-agent',
  name: 'mongodb-agent',
  instructions:
    'You are an AI agent with the ability to automatically recall memories from previous interactions.',
  model: '__GATEWAY_OPENAI_MODEL__',
  memory: new Memory({
    storage: new MongoDBStore({
      id: 'mongodb-storage',
      uri: process.env.MONGODB_URI!,
      dbName: process.env.MONGODB_DB_NAME!,
    }),
    vector: new MongoDBVector({
      id: 'mongodb-vector',
      uri: process.env.MONGODB_URI!,
      dbName: process.env.MONGODB_DB_NAME!,
    }),
    embedder: fastembed,
    options: {
      lastMessages: 10,
      semanticRecall: {
        topK: 3,
        messageRange: 2,
      },
      generateTitle: true, // generates descriptive thread titles automatically
    },
  }),
})
```
