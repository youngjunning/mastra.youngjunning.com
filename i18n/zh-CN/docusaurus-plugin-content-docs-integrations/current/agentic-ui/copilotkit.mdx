# CopilotKit

[CopilotKit](https://www.copilotkit.ai/) 提供 React 组件，帮助你快速将可定制的 AI 助手集成到应用中。结合 Mastra，你可以构建支持双向状态同步和交互式 UI 的 AI 应用。

CopilotKit 通过 [AG-UI 协议](https://docs.ag-ui.com/)与 Mastra 通信。`@ag-ui/mastra` 包将 Mastra Agent 暴露为 AG-UI 端点，供 CopilotKit 的 React hook 和组件使用。在普通聊天之外，你还可以实现[生成式 UI、人工参与和前端 Tool](#generative-ui)，并将同一个 Agent 部署到 [Slack 等消息渠道](#channels)。

有关 CopilotKit 的概念、组件和高级用法，请参阅 [CopilotKit 文档](https://docs.copilotkit.ai/)。

:::info

如果希望让 Mastra 直接运行在 Next.js API 路由中，请参阅 [CopilotKit 快速入门](https://docs.copilotkit.ai/mastra/quickstart)，了解这种全栈集成方式。

:::

访问 Mastra 的 [“UI Dojo”](https://ui-dojo.mastra.ai/)，查看 CopilotKit 与 Mastra 集成的实际示例。

## 集成指南 {/* #integration-guide */}

将 Mastra 作为独立服务器运行，再把使用 CopilotKit 的 Next.js 前端连接到它的 API 端点。

<Steps>
  <StepItem>
    设置目录结构，例如：

    ```bash
    project-root
    ├── mastra-server
    │   ├── src
    │   │   └── mastra
    │   └── package.json
    └── my-copilot-app
        └── package.json
    ```

    初始化 Mastra 服务器：

    ```bash npm2yarn
    npx create-mastra@latest
    ```

    此命令会打开交互式向导，搭建新的 Mastra 项目。按照提示创建服务器项目。

    进入刚创建的 Mastra 服务器目录：

    ```bash
    cd mastra-server # Replace with the actual directory name you provided
    ```

    至此，基础的 Mastra 服务器项目已准备就绪。

    :::note

    确保已在 `.env` 文件中为所用的 LLM Provider 设置相应的环境变量。

    :::
  </StepItem>

  <StepItem>
    使用 `@ag-ui/mastra` 提供的 `registerCopilotKit()` 辅助函数，为 CopilotKit 前端创建聊天路由。在 Mastra 项目中安装该包及其对等依赖：

    ```bash npm2yarn
    npm install @ag-ui/mastra @mastra/client-js @mastra/core @ag-ui/core @ag-ui/client @copilotkit/runtime
    ```

    在 `src/mastra/index.ts` 中注册聊天路由：

    ```typescript title="src/mastra/index.ts" {2,7-19}
    import { Mastra } from '@mastra/core/mastra'
    import { registerCopilotKit } from '@ag-ui/mastra/copilotkit'
    // Rest of the imports...

    export const mastra = new Mastra({
      // Rest of the configuration...
      server: {
        cors: {
          origin: '*',
          allowMethods: ['*'],
          allowHeaders: ['*'],
        },
        apiRoutes: [
          registerCopilotKit({
            path: '/copilotkit',
            resourceId: 'weatherAgent',
          }),
        ],
      },
    })
    ```

    这样，Mastra 实例中的 Agent 就会以兼容 CopilotKit 的格式暴露在 `/copilotkit` 路径。前端通过下文展示的 `agent` prop 选择要对话的 Agent。添加 CORS 配置，允许 CopilotKit 前端访问 Mastra 服务器。部署到生产环境时，应将允许的 CORS 来源限制为你的前端域名。
  </StepItem>

  <StepItem>
    使用以下命令运行 Mastra 服务器：

    ```bash npm2yarn
    npm run dev
    ```

    Mastra 服务器默认运行在 `http://localhost:4111`。设置 CopilotKit 前端期间，请保持服务器运行。
  </StepItem>

  <StepItem>
    返回上一级项目根目录。

    ```bash
    cd ..
    ```

    创建名为 `my-copilot-app` 的 Next.js 项目：

    ```bash npm2yarn
    npx create-next-app@latest my-copilot-app
    ```

    进入刚创建的 Next.js 项目目录：

    ```bash
    cd my-copilot-app
    ```
  </StepItem>

  <StepItem>
    安装用于显示聊天界面的 CopilotKit UI 包：

    ```bash npm2yarn
    npm install @copilotkit/react-ui @copilotkit/react-core
    ```

    打开 Next.js 应用的首页路由文件（通常是 `app/page.tsx` 或 `src/app/page.tsx`），将现有内容替换为以下代码，建立基础的 CopilotKit 聊天界面：

    ```typescript title="app/page.tsx" oxfmt:false
    import { CopilotChat } from '@copilotkit/react-ui'
    import { CopilotKit } from '@copilotkit/react-core'
    import '@copilotkit/react-ui/styles.css'

    export default function Home() {
      return (
        <CopilotKit runtimeUrl="http://localhost:4111/copilotkit" agent="weatherAgent">
          <CopilotChat
            labels={{
              title: 'Weather Agent',
              initial: 'Hi! 👋 Ask me about the weather, forecasts, and climate.',
            }}
          />
        </CopilotKit>
      )
    }
    ```

    `agent` prop 指定要路由到的 Mastra Agent，其值必须与 Mastra 实例的 `agents` 映射中的某个键一致。
  </StepItem>

  <StepItem>
    确保 Mastra 服务器和 CopilotKit 前端都在运行。启动 Next.js 开发服务器：

    ```bash npm2yarn
    npm run dev
    ```

    在浏览器中打开应用，与 Agent 对话。
  </StepItem>
</Steps>

现在，CopilotKit 前端已能与独立运行的 Mastra Agent 服务器通信。

## 聊天界面选项 {/* #chat-ui-options */}

`CopilotChat` 渲染嵌入页面、占满容器高度的聊天界面。CopilotKit 还提供另外两种可直接替换的界面，它们使用相同的 props：

- `CopilotSidebar`：停靠在应用侧边的可折叠面板。
- `CopilotPopup`：点击后打开聊天窗口的悬浮按钮。

替换组件即可切换界面形式。三者都通过同一个 `CopilotKit` Provider 连接：

```typescript title="app/page.tsx" oxfmt:false
import { CopilotSidebar } from '@copilotkit/react-ui'
import { CopilotKit } from '@copilotkit/react-core'
import '@copilotkit/react-ui/styles.css'

export default function Home() {
  return (
    <CopilotKit runtimeUrl="http://localhost:4111/copilotkit" agent="weatherAgent">
      <CopilotSidebar
        labels={{
          title: 'Weather Agent',
          initial: 'Hi! 👋 Ask me about the weather.',
        }}
      />
      {/* your app */}
    </CopilotKit>
  )
}
```

如果要使用自己的组件构建完全自定义的聊天 UI，请参阅 [CopilotKit 无界面 UI 指南](https://docs.copilotkit.ai/)。

## 生成式用户界面 {/* #generative-ui */}

生成式 UI 是指由 Agent 协助创建、用户可以与之交互的界面。CopilotKit 用一条轴线来组织这些界面，称为**生成式 UI 光谱**：一端由开发者控制（每个像素都由你决定），另一端由 Agent 创造（Agent 决定整个渲染界面）。选择哪一端，取决于你如何权衡可预测性与适用范围。

这一光谱分为三个层级：

| 层级 | 由谁控制界面 | 基本方式 |
| - | - | - |
| **受控** | 组件由你编写，Agent 选择使用哪个组件并提供数据。 | Tool 调用渲染、状态渲染、推理、将组件作为 Tool |
| **声明式** | Agent 输出结构化规格，前端从你注册的组件目录中组合界面。 | A2UI（固定 schema 和灵活变体） |
| **开放式** | 界面由其他地方（MCP 服务器）生成，并在你的应用中隔离运行。 | MCP Apps |

每个层级都使用通过 `registerCopilotKit()` 暴露的 Mastra Agent，并在前端搭配相应的 CopilotKit hook。完整概念请参阅 CopilotKit 的[生成式 UI 光谱](https://www.copilotkit.ai/generative-ui-spectrum)和[生成式 UI 概览](https://docs.copilotkit.ai/concepts/generative-ui-overview)。

:::tip

Mastra 的 [UI Dojo](https://ui-dojo.mastra.ai/) 提供可运行的 CopilotKit 示例。源代码位于 `src/pages/copilot-kit`。

:::

### 受控 {/* #controlled */}

你提供一组固定组件，由 Agent 选择要渲染的组件并提供数据。这种可预测、符合品牌规范的方式适合访问量大的界面。受控层级的基本方式使用 CopilotKit v2 API，从 `@copilotkit/react-core/v2` 导入。

#### Tool 调用渲染 {/* #tool-call-rendering */}

将 Agent 的 Tool 调用渲染为 React 组件。先照常在 Mastra 服务器上定义 Agent 和 Tool：

```typescript title="src/mastra/agents/weather-agent.ts"
import { Agent } from '@mastra/core/agent'
import { weatherTool } from '../tools/weather-tool'

export const weatherAgent = new Agent({
  id: 'weather-agent',
  name: 'Weather Agent',
  instructions: 'Use the weatherTool to fetch current weather data.',
  model: '__GATEWAY_OPENAI_MODEL__',
  tools: { weatherTool },
})
```

在前端使用 `useRenderTool`，按名称为该 Tool 注册渲染器。它只负责渲染，不会执行 Tool；`render` 函数会收到 Tool 调用的 `status`，并在 Agent 返回后收到 `result`：

```tsx title="app/page.tsx"
import { z } from 'zod'
import { CopilotChat } from '@copilotkit/react-ui'
import { CopilotKit, useRenderTool } from '@copilotkit/react-core/v2'
import { Weather } from '@/components/weather'

function Chat() {
  useRenderTool(
    {
      name: 'weatherTool',
      parameters: z.object({ location: z.string() }),
      render: ({ status, result }) => {
        if (status !== 'complete') {
          return <div>Retrieving weather...</div>
        }
        return <Weather {...result} />
      },
    },
    [],
  )

  return <CopilotChat labels={{ title: 'Weather Assistant' }} />
}

export default function Page() {
  return (
    <CopilotKit runtimeUrl="http://localhost:4111/copilotkit" agent="weatherAgent">
      <Chat />
    </CopilotKit>
  )
}
```

Mastra 会逐步流式传输 Tool 调用参数，因此参数到达时 `render` 函数会反复调用，界面也可以在 Agent 运行期间逐步呈现。

#### 将组件作为 Tool {/* #components-as-tools */}

注册 React 组件，让 Agent 像调用 Tool 一样调用它。CopilotKit 会在聊天内容中渲染该组件，并传入由 Zod schema 定义的类型化 props：

```tsx title="app/page.tsx"
import { z } from 'zod'
import { useComponent } from '@copilotkit/react-core/v2'

const schema = z.object({ text: z.string() })

function Callout({ text }: z.infer<typeof schema>) {
  return <div className="callout">{text}</div>
}

function Chat() {
  useComponent({ name: 'callout', render: Callout, parameters: schema }, [])
  return <CopilotChat labels={{ title: 'Assistant' }} />
}
```

Agent 像调用其他 Tool 一样调用 `callout`，CopilotKit 则用 Agent 传入的 props 渲染 `Callout`。

#### 状态渲染 {/* #state-rendering */}

根据 Agent 状态渲染 UI，并在状态流式更新时重新渲染。在 Mastra 中，Agent 状态是它的工作记忆；状态发生变化时会流式传输到客户端。使用 `useAgent` 读取状态；`agent.state` 具有响应性，因此组件会自动更新：

```tsx title="app/page.tsx"
import { useAgent } from '@copilotkit/react-core/v2'

function TaskBoard() {
  const { agent } = useAgent()
  const tasks = (agent.state.tasks as any[]) ?? []

  return (
    <ul>
      {tasks.map((task, i) => (
        <li key={i}>
          {task.title}: {task.status}
        </li>
      ))}
    </ul>
  )
}
```

#### 推理 {/* #reasoning */}

推理功能无需额外配置：当 Mastra Agent 使用支持推理的模型时，`CopilotChat` 会将模型的思考过程作为独立消息类型直接显示在聊天中。若要调整样式，可通过 `CopilotChat` 的 `reasoningMessage` 插槽传入自己的组件。详情请参阅 CopilotKit 的[生成式 UI 指南](https://docs.copilotkit.ai/)。

### 声明式 {/* #declarative */}

你无需为每个 Tool 注册固定组件，而是注册一个包含类型化基础组件的目录，让 Agent 根据每次请求将它们组合成 UI 树。CopilotKit 将这种方式称为 **A2UI**（Agent-to-UI），包括固定 schema 和灵活变体。它适合那些更看重覆盖范围、而非像素级精确度的长尾辅助交互。

最简单的方式是将组件目录传给 `<CopilotKit>` Provider。只需这一个 prop，就能启用 A2UI 渲染，并将 A2UI Tool 注入 Agent，无需修改后端：

```tsx title="app/page.tsx"
import { CopilotKit } from '@copilotkit/react-core/v2'
import { myCatalog } from './a2ui-catalog'

export default function Page() {
  return (
    <CopilotKit
      runtimeUrl="http://localhost:4111/copilotkit"
      agent="weatherAgent"
      a2ui={{ catalog: myCatalog }}
    >
      {/* your app */}
    </CopilotKit>
  )
}
```

目录定义基础组件及其 schema，也定义每种组件的渲染方式。在固定 schema 变体中，组件预先写好，Agent 的 Tool 只提供数据；灵活变体则允许 Agent 更自由地组合 UI 树。请参阅 CopilotKit 的 [A2UI 文档](https://docs.copilotkit.ai/a2a/generative-ui/a2ui)。

### 开放式 {/* #open-ended */}

在光谱的另一端，Agent 控制整个界面：UI 在其他地方生成，并在你的应用中通过 Sandbox 隔离运行。CopilotKit 通过 **MCP Apps** 支持这种方式，由 MCP 服务器提供在应用内渲染的 UI。这一层级以确定性换取新颖性，也是光谱中实验性最强的一端。

最简单的接入方式无需改动前端：现有的 `<CopilotKit>` Provider 即可。在后端通过 `mcpApps` 选项为 `registerCopilotKit()` 指定一个或多个 MCP 服务器；该选项会传递给 CopilotKit runtime：

```typescript title="src/mastra/index.ts"
registerCopilotKit({
  path: '/copilotkit',
  resourceId: 'weatherAgent',
  mcpApps: {
    servers: [{ type: 'http', url: 'http://localhost:3108/mcp', serverId: 'my-server' }],
  },
})
```

当 Agent 调用 MCP App Tool 时，CopilotKit 会获取该 Tool 的 UI 并在聊天中渲染，无需额外的前端代码。请参阅 CopilotKit 的 [MCP Apps 文档](https://docs.copilotkit.ai/agno/generative-ui/mcp-apps)。

## 应用程序控制和交互 {/* #app-control-and-interactivity */}

有些能力与[生成式 UI](#generative-ui) 光谱相关，却不属于其中的渲染层级：它们用于控制应用或在运行途中设置人工确认环节，而不是渲染 Agent 输出。CopilotKit 允许 Agent 操作应用，也能暂停并等待用户。两种模式都沿用同一套 Mastra 配置。

### 前端 Tool {/* #frontend-tools */}

让 Agent 能够操作应用。通过 `useFrontendTool` 在前端注册 Tool；Agent 调用它时，`handler` 会在浏览器中运行：

```tsx title="app/page.tsx"
import { CopilotChat } from '@copilotkit/react-ui'
import { CopilotKit, useFrontendTool } from '@copilotkit/react-core'

function Chat() {
  useFrontendTool({
    name: 'colorChangeTool',
    description: 'Changes the background color',
    parameters: [
      { name: 'color', type: 'string', description: 'The color to change to', required: true },
    ],
    handler: ({ color }) => {
      document.body.style.setProperty('--background', color)
    },
  })

  return <CopilotChat labels={{ title: 'Background Color Changer' }} />
}

export default function Page() {
  return (
    <CopilotKit runtimeUrl="http://localhost:4111/copilotkit" agent="bgColorAgent">
      <Chat />
    </CopilotKit>
  )
}
```

对应的 Mastra Agent 只是一个普通 Agent，其指令要求它使用请求的颜色调用 `colorChangeTool`。

CopilotKit 将前端 Tool 与共享状态、Agent 上下文一起归入独立的[应用控制](https://docs.copilotkit.ai/)概念。

### 人工参与 {/* #human-in-the-loop */}

在 Agent 运行途中暂停，等待用户批准、编辑或拒绝后再继续。使用 `useHumanInTheLoop`：其 `render` 函数会收到 `respond` 回调；调用该回调之前，Agent 的运行会一直暂停。

```tsx title="app/page.tsx"
import { CopilotChat } from '@copilotkit/react-ui'
import { CopilotKit, useHumanInTheLoop } from '@copilotkit/react-core'
import { StepsFeedback } from '@/components/steps-feedback'

function Chat() {
  useHumanInTheLoop({
    name: 'generate_task_steps',
    description: 'Generates a list of steps for the user to perform',
    parameters: [
      {
        name: 'steps',
        type: 'object[]',
        attributes: [
          { name: 'description', type: 'string' },
          { name: 'status', type: 'string', enum: ['enabled', 'disabled', 'executing'] },
        ],
      },
    ],
    available: 'enabled',
    // `respond` resumes the agent with the user's edited selection.
    render: ({ args, respond, status }) => (
      <StepsFeedback args={args} respond={respond} status={status} />
    ),
  })

  return <CopilotChat labels={{ title: 'Planning Agent' }} />
}

export default function Page() {
  return (
    <CopilotKit runtimeUrl="http://localhost:4111/copilotkit" agent="planningAgent">
      <Chat />
    </CopilotKit>
  )
}
```

在 `StepsFeedback` 中，让用户切换步骤，然后调用 `respond({ accepted: true, steps })` 恢复 Agent 运行，或调用 `respond({ accepted: false })` 拒绝。Agent 会读取返回值并据此继续运行。完整组件见 [UI Dojo](https://ui-dojo.mastra.ai/)。

上面的示例使用客户端 Tool：Agent 调用 `generate_task_steps`，前端通过 `respond` 完成调用。Mastra 也可以在服务器端暂停，在 Tool 执行前挂起调用，等待人工批准或提供输入。关于这种方式，后端请参阅 Mastra 的 [Agent 审批](/docs/agents/human-in-the-loop)指南，前端请参阅 CopilotKit 的 [`useHumanInTheLoop`](https://docs.copilotkit.ai/reference/hooks/useHumanInTheLoop) 参考文档。

## 消息渠道 {/* #channels */}

为应用内 AI 助手提供能力的同一个 Mastra Agent，也能作为机器人运行在消息平台上。CopilotKit 的 Channels SDK 可将 Agent 连接到 Slack 等平台，并在渠道内原生处理会话线程、Tool 调用、丰富的交互式消息和人工审批。

:::info

完整的平台设置说明见 [CopilotKit Channels 文档](https://docs.copilotkit.ai/slack/mastra)。本节介绍 Channels 如何与 Mastra Agent 配合。

:::

### 工作方式 {/* #how-it-fits-together */}

Mastra Agent 保持在原来的部署位置，通过 `registerCopilotKit()` 以 AG-UI 对外提供服务。渠道是使用 `@copilotkit/channels` 构建的独立常驻进程：为其接入一个或多个平台适配器，并将其指向 Agent。`createChannel` 接收适配器数组，因此单个进程可以同时服务多个平台。

安装 SDK，其中已包含各适配器所需的功能：

```bash npm2yarn
npm install @copilotkit/channels
```

```typescript title="channel.ts"
import { createChannel, Message, Section } from '@copilotkit/channels'
import { slack } from '@copilotkit/channels/slack'
import { mastraAgent } from './agent' // your AG-UI Mastra agent

const channel = createChannel({
  // Point the channel at your Mastra agent (an AbstractAgent, or a per-thread factory).
  agent: mastraAgent,
  adapters: [
    slack({
      botToken: process.env.SLACK_BOT_TOKEN!,
      appToken: process.env.SLACK_APP_TOKEN!,
    }),
  ],
})

channel.onMention(async ({ thread }) => {
  await thread.runAgent()
})

await channel.start()
```

Agent 接收标准 AG-UI 输入并发出标准 AG-UI 事件；平台相关机制由适配器处理，因此同一个 Mastra Agent 无须改动即可用于各个渠道。丰富的消息以 JSX 编写，再渲染为各平台的原生格式（例如 Slack 的 Block Kit）；如果平台没有对应能力，交互式卡片也会适当降级。

### Slack {/* #slack */}

[Slack 快速入门](https://docs.copilotkit.ai/slack/mastra)会带你从零开始创建可在渠道中通过 `@` 提及的机器人，并添加带交互按钮的卡片。Slack 使用 Socket Mode，主动向 Slack 建立出站 WebSocket 连接，因此开发时不需要公网 URL 或隧道。

在环境中设置 Slack 凭据：

- `SLACK_BOT_TOKEN`：机器人用户 OAuth 令牌（`xoxb-...`）
- `SLACK_APP_TOKEN`：具有 `connections:write` 权限范围的应用级令牌（`xapp-...`）

### 其他平台 {/* #other-platforms */}

Channels SDK 不仅支持 Slack。Microsoft Teams 等平台也使用同一套 `@copilotkit/channels` API：只需将对应的适配器加入 `adapters` 数组，Agent 的其余代码无需改动。当前支持的平台和各平台的设置方法见 [CopilotKit Channels 文档](https://docs.copilotkit.ai/slack/mastra)。

### 消息流程与架构 {/* #message-pipeline-and-architecture */}

托管渠道有意将凭据分开管理。如果 Mastra Agent 使用独立的模型密钥和 Tool，这一点尤其重要：

- **由你保管** Agent 逻辑、模型凭据和 Tool，并运行渠道进程。
- **由 CopilotKit Intelligence 管理**平台凭据、消息投递、注册、健康状态和重连。

用户向应用发送消息后，一轮交互开始。Intelligence 接收平台事件，网关将该轮交互交给你正在运行的渠道进程。Mastra Agent 运行并生成回复，Intelligence 再以平台原生内容的形式返回回复。平台凭据始终不会进入 Agent 进程；企业版 Intelligence 还可自行托管，以满足数据驻留要求。

:::note

默认情况下，交互操作保存在内存中，重启后会重置。为渠道配置持久化的操作和状态存储（Redis 或 Postgres），才能让按钮和每个线程的状态在重启后保留，并跨多个实例共享。

:::

## 配置选项 {/* #configuration-options */}

以下 `registerCopilotKit()` 选项可用于常见的集成场景：

| 选项 | 用途 |
| - | - |
| `path` | 设置路由路径，例如 `/copilotkit`。 |
| `resourceId` | 限定会话使用的 Mastra memory 范围。 |
| `cors` | 在 `server.cors` 之外配置单条路由的 CORS。 |
| `setContext` | 在 Agent 运行前填充请求上下文，例如认证信息或每位用户的资源 ID。 |
| `agents` | 提供预先构建的 AG-UI Agent，而不使用注册在 Mastra 实例上的 Agent。 |
| `tracingOptions` | 将 Mastra tracing 选项传递给每次 Agent 运行。 |

默认情况下，该端点会暴露 Mastra 实例上注册的所有 Agent，前端通过 `agent` prop 选择其中一个。其他 CopilotKit runtime 选项会传递给底层 runtime。例如，`mcpApps` 的用法见[开放式生成式 UI](#open-ended)。

## 部署 {/* #deployment */}

部署集成了 CopilotKit 的 Mastra 服务器时，必须将 `@copilotkit/runtime` 排除在打包产物之外。该包包含不兼容打包的依赖；如果将其打入包中，会导致 500 错误。

:::note

使用 `mastra dev` 开发时无需打包，因此不会遇到此问题。但运行 `mastra build` 准备部署时，就会遇到这一问题。

:::

将 `@copilotkit/runtime` 加入打包器的 externals 配置：

```typescript title="src/mastra/index.ts"
import { Mastra } from '@mastra/core/mastra'

export const mastra = new Mastra({
  bundler: {
    externals: ['@copilotkit/runtime'],
  },
})
```
