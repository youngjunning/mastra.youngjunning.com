# AI SDK UI

[AI SDK UI](https://sdk.vercel.ai) 是一套用于构建 AI 界面的 React 工具和组件。本指南介绍如何使用 `@mastra/ai-sdk` 将 Mastra 的输出转换为 AI SDK 兼容格式，以便在前端使用 AI SDK UI 的 Hook 和组件。

:::note
正在从 AI SDK v4 迁移到 v5？请参阅[迁移指南](/reference/migrations/ai-sdk-v4-to-v5)。
:::

:::tip

想查看更多示例？请访问 Mastra 的 [**UI Dojo**](https://ui-dojo.mastra.ai/)，或阅读 [Next.js 快速入门指南](/integrations/frameworks/next-js)。

:::

## 入门 {/* #getting-started */}

安装 `@mastra/ai-sdk` 包，即可将 Mastra 与 AI SDK UI 配合使用。`@mastra/ai-sdk` 包提供自定义 API 路由和工具，将 Mastra Agent 的输出以 AI SDK 兼容格式流式传输；其中包括聊天、Workflow 和 Agent 网络的路由处理函数，以及用于 UI 集成的工具函数和导出类型。

`@mastra/ai-sdk` 可与 AI SDK UI 的三个主要 Hook 配合使用：[`useChat()`](https://ai-sdk.dev/docs/ai-sdk-ui/chatbot)、[`useCompletion()`](https://ai-sdk.dev/docs/ai-sdk-ui/completion) 和 [`useObject()`](https://ai-sdk.dev/docs/ai-sdk-ui/object-generation)。

首先安装所需的包：

```bash npm2yarn
npm install @mastra/ai-sdk@latest @ai-sdk/react ai
```

安装完成后，可以按照下面的集成指南和实践示例继续操作。

## 集成指南 {/* #integration-guides */}

通常需要先创建 API 路由，以 AI SDK 兼容格式流式传输 Mastra 内容，再通过 `useChat()` 等 AI SDK UI Hook 调用这些路由。请选择一种方式：

- [Mastra 服务器](#mastras-server)
- [不依赖特定框架](#framework-agnostic)

设置好 API 路由后，就可以在 [`useChat()`](#usechat) Hook 中使用。

### Mastra 服务器 {/* #mastras-server */}

将 Mastra 作为独立服务器运行，再把前端（例如 Vite + React 应用）连接到它的 API 端点。此方式使用 Mastra 的[自定义 API 路由](/docs/server/custom-api-routes)功能。

:::note

Mastra 的 [**UI Dojo**](https://ui-dojo.mastra.ai/) 展示了这种架构。

:::

可以使用 [`chatRoute()`](/reference/ai-sdk/chat-route)、[`workflowRoute()`](/reference/ai-sdk/workflow-route) 和 [`networkRoute()`](/reference/ai-sdk/network-route) 创建 API 路由，以 AI SDK 兼容格式流式传输 Mastra 内容。路由创建后，即可在 [`useChat()`](#usechat) 中调用。

### 不依赖特定框架 {/* #framework-agnostic */}

如果使用 Next.js 或 Express 等框架，而不运行 Mastra 服务器，可以在自己的 API 路由处理函数中调用 [`handleChatStream()`](/reference/ai-sdk/handle-chat-stream)、[`handleWorkflowStream()`](/reference/ai-sdk/handle-workflow-stream) 和 [`handleNetworkStream()`](/reference/ai-sdk/handle-network-stream)。

这些函数返回 `ReadableStream`，可通过 [`createUIMessageStreamResponse()`](https://ai-sdk.dev/docs/reference/ai-sdk-ui/create-ui-message-stream-response) 将其封装为响应。

:::tip AI SDK 版本兼容性

为保持向后兼容，不依赖特定框架的处理函数默认使用 AI SDK v5。请传入与已安装 AI SDK 相匹配的版本；例如，使用 AI SDK v7 时传入 `version: 'v7'`。调用 `handleChatStream()` 和 `handleNetworkStream()` 时，将 `messages` 指定为已安装 `ai` 版本中的 `UIMessage[]`，可获得更准确的 TypeScript 类型推断。

:::

以下示例展示如何在 Next.js App Router 中使用这些函数。

### `useChat()` {/* #usechat */}

无论通过 [Mastra 服务器](#mastras-server)还是[自行选择的框架](#framework-agnostic)创建 API 路由，都可以在 `useChat()` Hook 中调用相应端点。

假设 `/chat` 路由使用天气 Agent，就可以像下面这样向它提问。请确保 `api` URL 指向正确的端点。

```ts {9} oxfmt:false
import { useChat } from '@ai-sdk/react'
import { useState } from 'react'
import { DefaultChatTransport } from 'ai'

export default function Chat() {
  const [inputValue, setInputValue] = useState('')
  const { messages, sendMessage } = useChat({
    transport: new DefaultChatTransport({
      api: 'http://localhost:4111/chat',
    }),
  })

  const handleFormSubmit = (e: React.FormEvent) => {
    e.preventDefault()
    sendMessage({ text: inputValue })
  }

  return (
    <div>
      <pre>{JSON.stringify(messages, null, 2)}</pre>
      <form onSubmit={handleFormSubmit}>
        <input
          value={inputValue}
          onChange={e => setInputValue(e.target.value)}
          placeholder="Name of the city"
        />
      </form>
    </div>
  )
}
```

可以使用 [`prepareSendMessagesRequest`](https://ai-sdk.dev/docs/reference/ai-sdk-ui/use-chat#transport.default-chat-transport.prepare-send-messages-request) 自定义发送到聊天路由的请求，例如传递额外的 Agent 配置。

### 断开连接后恢复聊天流 {/* #resume-a-chat-stream-after-a-disconnect */}

在 Mastra 路由上启用可恢复流：

```typescript title="src/mastra/index.ts"
import { Mastra } from '@mastra/core'
import { chatRoute } from '@mastra/ai-sdk'

export const mastra = new Mastra({
  server: {
    apiRoutes: [
      chatRoute({
        path: '/chat',
        agent: 'weatherAgent',
        resumable: true,
      }),
    ],
  },
})
```

向 `useChat()` 传入稳定的聊天 ID，并设置 `resume: true`。如果组件重新挂载时生成任务仍在运行，AI SDK UI 会通过 `GET /chat/:chatId/stream` 重新连接。

```tsx title="src/components/chat.tsx" oxfmt:false
import { useChat } from '@ai-sdk/react'
import { DefaultChatTransport } from 'ai'

export function Chat({ chatId }: { chatId: string }) {
  const { messages, sendMessage, status } = useChat({
    id: chatId,
    resume: true,
    transport: new DefaultChatTransport({
      api: 'http://localhost:4111/chat',
    }),
  })

  // ...render messages and call sendMessage()
}
```

将 `chatId` 保存在 URL、浏览器存储或应用状态中，以便刷新后复用同一值。只有仍在运行的任务可以恢复；已完成或不可用的任务会返回 `204`，因此已完成的聊天记录需要另行从记忆中加载。

可恢复模式允许生成任务在 POST 连接关闭后继续运行，因此 `useChat().stop()` 不会取消 Agent 任务。运行中任务的发现范围仅限当前进程，重新连接请求必须到达同一个仍在运行的 Mastra 服务器进程。

如果聊天使用资源 ID，认证中间件必须在请求上下文中设置 `MASTRA_RESOURCE_ID_KEY`。不能只通过 POST 请求体中的 `memory.resource` 传递资源 ID，因为重新连接时的 GET 请求没有请求体。

### 在 `useChat()` 中使用客户端 Tool {/* #client-tools-with-usechat */}

没有 `execute` 函数的 Tool 在客户端运行。模型调用它时，Agent 任务会在该步骤结束，流以状态为 `input-available` 的 `tool-{toolKey}` 部分结束。要让 Agent 继续运行，需要在浏览器中执行 Tool，通过 `addToolOutput()` 加入结果，再将对话发回服务器。设置 `sendAutomaticallyWhen` 后，上一条 assistant 消息中的每个 Tool 调用都有结果时，会自动发送下一次请求：

```tsx title="src/components/chat.tsx" oxfmt:false
import { useChat } from '@ai-sdk/react'
import { DefaultChatTransport, lastAssistantMessageIsCompleteWithToolCalls } from 'ai'

export default function Chat() {
  const { messages, sendMessage, addToolOutput } = useChat({
    transport: new DefaultChatTransport({
      api: 'http://localhost:4111/chat',
    }),
    sendAutomaticallyWhen: lastAssistantMessageIsCompleteWithToolCalls,
    async onToolCall({ toolCall }) {
      if (toolCall.toolName === 'addToCart') {
        const input = toolCall.input as { productId: string }
        const cart = await addToCartInBrowser(input.productId)

        // Don't await addToolOutput inside onToolCall to avoid deadlocks
        addToolOutput({ tool: 'addToCart', toolCallId: toolCall.toolCallId, output: cart })
      }
    },
  })

  // ...render messages and call sendMessage()
}
```

如果客户端只需要呈现 Tool 调用，模型不需要其结果，则可以为 Tool 提供一个返回简短确认信息的 `execute` 函数。这样 Agent 会在同一次请求中继续生成。请参阅[在客户端运行的 Tool](/docs/agents/tools#tools-that-run-on-the-client)。

子 Agent 无法运行客户端 Tool：浏览器不会收到子 Agent 的 Tool 调用。请在聊天路由直接连接的 Agent 上定义客户端 Tool。

### 从 `useChat()` 恢复已暂停的 Tool {/* #resuming-a-suspended-tool-from-usechat */}

Tool 调用 `suspend()` 时，流中会包含一个 `data-tool-call-suspended` 部分，其中有 `runId`、`toolCallId` 和 `suspendPayload`。要恢复任务，请在请求体中发送符合该 Tool 的 `resumeSchema` 的 `resumeData`，以及 `runId`。此时，`handleChatStream()` 和 `chatRoute()` 会调用 `agent.resumeStream()`，而不是启动新任务：

```tsx title="src/components/chat.tsx" oxfmt:false
const { messages, sendMessage } = useChat({
  transport: new DefaultChatTransport({
    api: 'http://localhost:4111/chat',
    prepareSendMessagesRequest: ({ messages, body }) => {
      const resume = body?.resume as { runId: string; resumeData: unknown } | undefined
      if (resume) {
        return { body: { messages, runId: resume.runId, resumeData: resume.resumeData } }
      }
      return { body: { messages } }
    },
  }),
})

// When the user confirms the suspended tool call:
sendMessage(
  { text: 'Confirmed' },
  { body: { resume: { runId: suspended.runId, resumeData: { confirmed: true } } } },
)
```

`suspended` 是 `messages` 中最后一个 `data-tool-call-suspended` 部分的 `data`。

如果 Tool 在[子 Agent](/docs/agents/human-in-the-loop#identify-which-subagent-tool-paused) 内运行，`data-tool-call-suspended` 和 `data-tool-call-approval` 部分中的 `toolCallId` 指的是上层 Agent 对子 Agent 的调用。这些部分还包含 `delegatedToolCallId` 和 `delegatedToolName`，用于标识子 Agent 中实际暂停的 Tool 调用。可以用它们标注显示给用户的提示；恢复时仍使用 `runId` 和 `toolCallId`。

## 使用 Mastra 记忆 {/* #using-mastra-memory */}

如果 Agent 配置了[记忆](/docs/memory/overview)，Mastra 会在服务器端从存储中加载对话历史。客户端只需发送新消息，无须发送完整历史记录。

发送完整历史记录既多余，也可能造成消息顺序错误，因为客户端时间戳可能与数据库中的时间戳冲突。Mastra 会先过滤客户端回传的历史消息，再加载已存储的消息；如果消息 ID 相同，则以存储的副本为基础，保留其时间戳、Provider 元数据和推理内容，仅叠加新的 Tool 结果。

```typescript
import { useChat } from '@ai-sdk/react'
import { DefaultChatTransport } from 'ai'

const { messages, sendMessage } = useChat({
  transport: new DefaultChatTransport({
    api: 'http://localhost:4111/chat/weatherAgent',
    prepareSendMessagesRequest({ messages }) {
      return {
        body: {
          messages: [messages[messages.length - 1]],
          memory: {
            thread: 'user-thread-123',
            resource: 'user-123',
          },
        },
      }
    },
  }),
})
```

请从应用自身的状态设置 `memory.thread` 和 `memory.resource`，例如 URL 参数、认证上下文或数据库。

有关 Mastra 记忆如何加载和保存消息，请参阅[消息历史记录](/docs/memory/message-history)。

[`chatRoute()`](/reference/ai-sdk/chat-route) 和 [`handleChatStream()`](/reference/ai-sdk/handle-chat-stream) 已支持记忆。请将客户端配置为仅发送新消息，并附上会话和资源标识符。

### `useCompletion()` {/* #usecompletion */}

`useCompletion()` Hook 用于前端与 Mastra Agent 之间的单轮文本补全：通过 HTTP 发送提示词，并接收流式响应。

前端代码可以这样编写：

```typescript title="app/page.tsx" oxfmt:false
import { useCompletion } from '@ai-sdk/react'

export default function Page() {
  const { completion, input, handleInputChange, handleSubmit } = useCompletion({
    api: '/api/completion',
  })

  return (
    <form onSubmit={handleSubmit}>
      <input name="prompt" value={input} onChange={handleInputChange} id="input" />
      <button type="submit">Submit</button>
      <div>{completion}</div>
    </form>
  )
}
```

## 自定义 UI {/* #custom-ui */}

自定义 UI（也称为生成式 UI）允许根据 Mastra 流式传来的数据呈现自定义 React 组件。除了直接显示文本或 JSON，还可以用可视化组件展示 Tool 输出、Workflow 进度、Agent 网络执行情况和自定义事件。

以下场景适合使用自定义 UI：

- 将 Tool 输出呈现为可视化组件，例如用天气卡片代替 JSON
- 用状态指示器展示 Workflow 步骤进度
- 逐步展示 Agent 网络的执行过程
- 在耗时操作期间展示进度指示器或状态更新

### 数据部分的类型 {/* #data-part-types */}

Mastra 将数据以消息中的“部分”流式传输到前端。每个部分的 `type` 决定如何呈现它。`@mastra/ai-sdk` 包会把 Mastra 的流转换成与 AI SDK 兼容的 [UI Message DataParts](https://ai-sdk.dev/docs/reference/ai-sdk-core/ui-message#datauipart)。

| 数据部分类型 | 来源 | 说明 |
| - | - | - |
| `tool-{toolKey}` | AI SDK 内置 | Tool 调用，状态包括 `input-available`、`output-available` 和 `output-error` |
| `data-workflow` | `workflowRoute()` | Workflow 执行状态快照，包含步骤状态和最终输出 |
| `data-workflow-step` | `workflowRoute()` | Workflow 步骤增量，包含发生变化的步骤的完整数据 |
| `data-network` | `networkRoute()` | Agent 网络的执行过程，包含按顺序排列的步骤和输出 |
| `data-tool-agent` | Tool 内的嵌套 Agent | 当前嵌套步骤仍在运行时的精简 Agent 快照 |
| `data-tool-agent-step` | Tool 内的嵌套 Agent | 嵌套步骤完成时发出的完整步骤数据 |
| `data-tool-workflow` | Tool 内的嵌套 Workflow | 从 Tool 的 `execute()` 中流式传出的 Workflow 输出 |
| `data-tool-network` | Tool 内的嵌套 Agent 网络 | 从 Tool 的 `execute()` 中流式传出的网络输出 |
| `data-{custom}` | `writer.custom()` | 用于进度指示器、状态更新等的自定义事件 |

### 渲染Tool输出 {/* #rendering-tool-outputs */}

Agent 调用 Tool 时，AI SDK 会自动创建 `tool-{toolKey}` 部分。其中包含 Tool 的状态和输出，可用于呈现自定义组件。

Tool 部分会依次经历以下状态：

- `input-streaming`：正在流式传输 Tool 输入（启用 Tool 调用流式传输时）
- `input-available`：Tool 已收到完整输入，等待执行
- `output-available`：Tool 执行完成并产生输出
- `output-error`：Tool 执行失败

下面的示例将天气 Tool 的输出呈现为自定义 `WeatherCard` 组件。

### 呈现 Workflow 数据 {/* #rendering-workflow-data */}

### 自定义事件 {/* #custom-events */}

在 Tool 的 `execute()` 函数中使用 `writer.custom()` 发出自定义数据部分，可在 Tool 执行期间更新进度指示器、状态或其他自定义 UI。

自定义事件的类型必须以 `data-` 开头，才能被识别为数据部分。

:::warning

必须对 `writer.custom()` 调用使用 `await`，否则可能出现 `WritableStream is locked` 错误。

:::

<Tabs>
  <TabItem value="backend" label="Backend">
    在 Tool 的 `execute()` 函数中使用 `writer.custom()`，在不同执行阶段发出以 `data-` 开头的自定义事件。

    ```typescript title="src/mastra/tools/task-tool.ts" {18-24,30-36}
    import { createTool } from '@mastra/core/tools'
    import { z } from 'zod'

    export const taskTool = createTool({
      id: 'process-task',
      description: 'Process a task with progress updates',
      inputSchema: z.object({
        task: z.string().describe('The task to process'),
      }),
      outputSchema: z.object({
        result: z.string(),
        status: z.string(),
      }),
      execute: async (inputData, context) => {
        const { task } = inputData

        // Emit "in progress" custom event
        await context?.writer?.custom({
          type: 'data-tool-progress',
          data: {
            status: 'in-progress',
            message: 'Gathering information...',
          },
        })

        // Simulate work
        await new Promise(resolve => setTimeout(resolve, 3000))

        // Emit "done" custom event
        await context?.writer?.custom({
          type: 'data-tool-progress',
          data: {
            status: 'done',
            message: `Successfully processed "${task}"`,
          },
        })

        return {
          result: `Task "${task}" has been completed successfully!`,
          status: 'completed',
        }
      },
    })
    ```

    ```typescript title="src/components/task-chat.tsx" {31-41,45} oxfmt:false
    import { useChat } from '@ai-sdk/react'

    import { useMemo } from 'react'

    type ProgressData = {
      status: 'in-progress' | 'done'
      message: string

    function ProgressIndicator({ progress }: { progress: ProgressData }) {
      return (
        <div className="progress-indicator">
          {progress.status === 'in-progress' ? (
            <span className="spinner" />
          ) : (
            <span className="check-icon" />

          })

      }, [messages])

      return (
        <div>
          {latestProgress && <ProgressIndicator progress={latestProgress} />}
          {messages.map(message => (
            <div key={message.id}>
              {message.parts.map((part, index) => {
    ```

### 经用户批准后恢复暂停的 Workflow {/* #workflow-suspendresume-with-user-approval */}

Workflow 可以暂停执行，等待用户输入后再继续。这适用于审批、确认和其他需要人工参与的场景。

此 Workflow 使用：

- `suspendSchema` / `resumeSchema`：定义暂停时发送的数据和恢复时接收的数据结构
- `suspend()`：暂停 Workflow，并将暂停时的数据发送到 UI
- `resumeData`：包含 Workflow 恢复时用户给出的答复
- `bail()`：提前退出 Workflow，例如用户拒绝时

<Tabs>
  <TabItem value="backend" label="Backend">
    创建等待批准时暂停的 Workflow 步骤。该步骤检查 `resumeData` 以判断是否正在恢复；首次执行时调用 `suspend()`。

    ```typescript title="src/mastra/workflows/approval-workflow.ts"
    import { createStep, createWorkflow } from '@mastra/core/workflows'
    import { z } from 'zod'

    const requestApproval = createStep({
      id: 'request-approval',
      inputSchema: z.object({ requestId: z.string(), summary: z.string() }),
      outputSchema: z.object({
        approved: z.boolean(),
        requestId: z.string(),
        approvedBy: z.string().optional(),
      }),
      resumeSchema: z.object({
        approved: z.boolean(),
        approverName: z.string().optional(),
      }),
      suspendSchema: z.object({
        message: z.string(),
        requestId: z.string(),
      }),
      execute: async ({ inputData, resumeData, suspend, bail }) => {
        // User rejected - bail out
        if (resumeData?.approved === false) {
          return bail({ message: 'Request rejected' })
        }
        // User approved - continue
        if (resumeData?.approved) {
          return {
            approved: true,
            requestId: inputData.requestId,
            approvedBy: resumeData.approverName || 'User',
          }
        }
        // First execution - suspend and wait
        return await suspend({
          message: `Please approve: ${inputData.summary}`,
          requestId: inputData.requestId,
        })
      },
    })

    export const approvalWorkflow = createWorkflow({
      id: 'approval-workflow',
      inputSchema: z.object({ requestId: z.string(), summary: z.string() }),
      outputSchema: z.object({
        approved: z.boolean(),
        requestId: z.string(),
        approvedBy: z.string().optional(),
      }),
    }).then(requestApproval)

    approvalWorkflow.commit()
    ```

    注册 Workflow。要在暂停和恢复之间保留状态，必须配置存储。

    ```typescript title="src/mastra/index.ts"
    import { Mastra } from '@mastra/core'
    import { workflowRoute } from '@mastra/ai-sdk'
    import { LibSQLStore } from '@mastra/libsql'

      workflows: { approvalWorkflow },
      storage: new LibSQLStore({
        id: 'mastra-storage',
        url: 'file:../mastra.db',
      }),

        apiRoutes: [
    ```

    检测 Workflow 何时暂停，并发送包含 `runId`、`step` 和 `resumeData` 的恢复数据。

    ```typescript title="src/components/approval-workflow.tsx" oxfmt:false
    import { useChat } from '@ai-sdk/react'
    import { DefaultChatTransport } from 'ai'
    import { useMemo, useState } from 'react'
    import type { WorkflowDataPart } from '@mastra/ai-sdk'

    type WorkflowData = WorkflowDataPart['data']

    export function ApprovalWorkflow() {
      const [requestId, setRequestId] = useState('')
      const [summary, setSummary] = useState('')

      const { messages, sendMessage, setMessages, status } = useChat({
        transport: new DefaultChatTransport({
          api: 'http://localhost:4111/workflow/approvalWorkflow',
          prepareSendMessagesRequest: ({ messages }) => {
            const lastMessage = messages[messages.length - 1]
            const text = lastMessage.parts.find(p => p.type === 'text')?.text
            const metadata = lastMessage.metadata as Record<string, string>

            // Resuming: send runId, step, and resumeData
            if (text === 'Approve' || text === 'Reject') {
              return {
                body: {
                  runId: metadata.runId,
                  step: 'request-approval',
                  resumeData: { approved: text === 'Approve' },
                },
              }
            }
            // Starting: send inputData
            return {
              body: { inputData: { requestId: metadata.requestId, summary: metadata.summary } },
            }
          },
        }),
      })

      // Find suspended workflow
      const suspended = useMemo(() => {
        for (const m of messages) {
          for (const p of m.parts) {
            if (p.type === 'data-workflow' && (p.data as WorkflowData).status === 'suspended') {
              return { data: p.data as WorkflowData, runId: p.id }
            }
          }
        }
        return null
      }, [messages])

      const handleApprove = () => {
        setMessages([])
        sendMessage({ text: 'Approve', metadata: { runId: suspended?.runId } })
      }

      const handleReject = () => {
        setMessages([])
        sendMessage({ text: 'Reject', metadata: { runId: suspended?.runId } })
      }

      return (
        <div>
          {!suspended ? (
            <form
              onSubmit={e => {
                e.preventDefault()
                setMessages([])
                sendMessage({ text: 'Start', metadata: { requestId, summary } })
              }}
            >
              <input
                value={requestId}
                onChange={e => setRequestId(e.target.value)}
                placeholder="Request ID"
              />
              <input value={summary} onChange={e => setSummary(e.target.value)} placeholder="Summary" />
              <button type="submit" disabled={status !== 'ready'}>
                Submit
              </button>
            </form>
          ) : (
            <div>
              <p>
                {
                  (suspended.data.steps['request-approval']?.suspendPayload as { message: string })
                    ?.message
                }
              </p>
              <button onClick={handleApprove}>Approve</button>
              <button onClick={handleReject}>Reject</button>
            </div>
          )}
        </div>
      )
    }
    ```
  </TabItem>
</Tabs>

要点：

- 可以通过 `step.suspendPayload` 访问暂停时的数据
- 要恢复，请在请求体中发送 `runId`、`step`（步骤 ID）和 `resumeData`
- 必须配置存储，才能在暂停和恢复之间保留 Workflow 状态

完整实现请参阅 UI Dojo 中的 [Workflow 暂停与恢复示例](https://github.com/mastra-ai/ui-dojo/blob/main/src/pages/ai-sdk/workflow-suspend-resume.tsx)。

### Tool 中的嵌套 Agent 流 {/* #nested-agent-streams-in-tools */}

Tool 可以在内部调用 Agent，并将其输出流式传回 UI。嵌套步骤仍在运行时会生成精简的 `data-tool-agent` 快照；嵌套步骤完成时会生成 `data-tool-agent-step` 部分；整个嵌套任务完成时，还会生成一份完整的 `data-tool-agent` 快照。

这两种部分都包含嵌套上层 Agent 链的委托元数据：

- `ancestry`：从外到内排列的委托路径。每个条目都有 `toolCallId`，还可能包含 `toolName` 和规范化的 `agentId`。
- `depth`：已知的 Agent 委托层级数。直接子 Agent 的深度为 `1`。
- `parentAgentId`：嵌套 Agent 的直接上层 Agent ID。直接子 Agent 不包含此字段，因为根上层 Agent 的 ID 不属于 Tool 封装数据。

该部分的 `id` 始终是嵌套 Agent 的任务 ID，因此随着任务继续运行，后续快照会更新同一份 UI 状态。

此模式使用：

- `context.mastra.getAgent()`：在 Tool 中获取 Agent 实例
- `agent.stream()`：流式传输 Agent 的响应
- `stream.fullStream.pipeTo(context.writer)`：将 Agent 的流导入 Tool 的 writer

  <TabItem value="backend" label="Backend">
    创建一个调用 Agent 并将其流导入 Tool writer 的 Tool。

    ```typescript title="src/mastra/tools/nested-agent-tool.ts"
    import { createTool } from '@mastra/core/tools'
    import { z } from 'zod'

    export const nestedAgentTool = createTool({
      id: 'nested-agent-stream',
      description: 'Analyze weather using a nested agent',
      inputSchema: z.object({
        city: z.string().describe('The city to analyze'),
      }),
      outputSchema: z.object({
        summary: z.string(),

      execute: async (inputData, context) => {
        const agent = context?.mastra?.getAgent('weatherAgent')
        if (!agent) {
          return { summary: 'Weather agent not available' }
        }

        const stream = await agent.stream(
          `Analyze the weather in ${inputData.city} and provide a summary.`,
        )

        // Pipe the agent's stream to emit data-tool-agent parts
        await stream.fullStream.pipeTo(context!.writer!)

        return { summary: (await stream.text) ?? 'No summary available' }
      },
    })
    ```

    ```typescript title="src/components/nested-agent-chat.tsx" oxfmt:false

    import { DefaultChatTransport } from 'ai'
    import { useState } from 'react'
    import type { AgentDataPart, AgentStepDataPart } from '@mastra/ai-sdk'

    export function NestedAgentChat() {
      const [input, setInput] = useState('')
      const { messages, sendMessage, status } = useChat({
        transport: new DefaultChatTransport({
          api: 'http://localhost:4111/chat/forecastAgent',
        }),
      })

      return (
        <div>
          <form
            onSubmit={e => {
              e.preventDefault()
              sendMessage({ text: input })
              setInput('')

          >
            <input value={input} onChange={e => setInput(e.target.value)} placeholder="Enter a city" />

              Get Forecast
            </button>
          </form>

          {messages.map(message => (
            <div key={message.id}>
              {message.parts.map((part, index) => {
                if (part.type === 'text') {
                  return <p key={index}>{part.text}</p>
                }
                if (part.type === 'data-tool-agent') {
                  const { id, data, depth, parentAgentId } = part as AgentDataPart
                  return (
                    <div key={index} className="nested-agent">
                      <strong>Nested Agent: {id}</strong>
                      <p>Delegation depth: {depth}</p>
                      {parentAgentId && <p>Parent agent: {parentAgentId}</p>}
                      {data.text && <p>{data.text}</p>}
                      {data.toolErrors?.map(toolError => (
                        <p key={toolError.toolCallId} className="nested-agent-error">
                          {toolError.toolName} failed: {toolError.errorText}
                        </p>
                      ))}
                    </div>
                  )
                }
                if (part.type === 'data-tool-agent-step') {
                  const { data } = part as AgentStepDataPart
                  return (
                    <div key={index} className="nested-agent-step">
                      <strong>Completed nested step {data.stepIndex + 1}</strong>
                      {data.step.text && <p>{data.step.text}</p>}
                    </div>
                  )
                }
                return null
              })}
            </div>
          ))}
        </div>
      )
    }
    ```

要点：

- 将 `fullStream` 导入 `context.writer` 会生成 `data-tool-agent` 部分
- 如需获取刚完成的嵌套步骤的完整数据，请读取 `data-tool-agent-step`
- `AgentDataPart` 和 `AgentStepDataPart` 都包含 `ancestry`、`depth` 和可选的 `parentAgentId` 字段
- `AgentDataPart` 的部分本身包含 `id`，其 `data.text` 是嵌套 Agent 当前的文本快照
- 嵌套 Agent 内抛出错误的 Tool 会记录在 `data.toolErrors` 中；每个条目为 `{ toolCallId, toolName, args?, errorText, providerExecuted? }`。`errorText` 是可安全序列化为 JSON 的字符串，因此错误传到客户端后不会变成 `{}`
- `toolErrors` 与 `toolCalls`、`toolResults` 一样，会在每个嵌套步骤边界重置。已完成步骤的错误可从 `data-tool-agent-step` 的 `data.step.toolErrors`，或最终快照的 `data.steps[]` 中读取
- 流结束后，Tool 仍会返回自己的输出

完整实现请参阅 UI Dojo 中的 [Tool 嵌套流示例](https://github.com/mastra-ai/ui-dojo/blob/main/src/pages/ai-sdk/tool-nested-streams.tsx)。

### 从 Workflow 步骤流式传输 Agent 文本 {/* #streaming-agent-text-from-workflow-steps */}

Workflow 步骤可以将 Agent 的流导入该步骤的 `writer`，实时传输 Agent 的文本输出。这样，用户不必等到步骤结束，就能在 Workflow 执行期间看到 Agent 的“思考”过程。

该模式使用：

- Workflow 步骤中的 `writer`：将 Agent 的 `fullStream` 导入步骤的 writer
- text 和 `data-workflow` 部分：前端同时接收流式文本和步骤进度

  <TabItem value="backend" label="Backend">
    创建一个 Workflow 步骤，将 Agent 的响应导入该步骤的 `writer`，以流式传输响应。

    ```typescript title="src/mastra/workflows/weather-workflow.ts"
    import { createStep, createWorkflow } from '@mastra/core/workflows'
    import { z } from 'zod'
    import { weatherAgent } from '../agents/weather-agent'

    const analyzeWeather = createStep({
      id: 'analyze-weather',
      inputSchema: z.object({ location: z.string() }),
      outputSchema: z.object({ analysis: z.string(), location: z.string() }),
      execute: async ({ inputData, writer }) => {
        const response = await weatherAgent.stream(
          `Analyze the weather in ${inputData.location} and provide insights.`,
        )

        // Pipe agent stream to step writer for real-time text streaming
        await response.fullStream.pipeTo(writer)

        return {
          analysis: await response.text,
          location: inputData.location,
        }
      },
    })

    const calculateScore = createStep({
      id: 'calculate-score',
      inputSchema: z.object({ analysis: z.string(), location: z.string() }),
      outputSchema: z.object({ score: z.number(), summary: z.string() }),
      execute: async ({ inputData }) => {
        const score = inputData.analysis.includes('sunny') ? 85 : 50
        return { score, summary: `Comfort score for ${inputData.location}: ${score}/100` }
      },
    })

    export const weatherWorkflow = createWorkflow({
      id: 'weather-workflow',
      inputSchema: z.object({ location: z.string() }),
      outputSchema: z.object({ score: z.number(), summary: z.string() }),
    })
      .then(analyzeWeather)
      .then(calculateScore)

    weatherWorkflow.commit()
    ```

### 展示分支 Workflow 的多阶段进度 {/* #multi-stage-progress-with-branching-workflows */}

对于包含条件分支的 Workflow（例如快速交付与标准交付），可以在自定义事件中加入标识符，以分别跟踪各分支的进度。

UI Dojo 示例通过事件数据中的 `stage` 字段标识正在执行的分支，例如 `"validation"`、`"standard-processing"` 或 `"express-processing"`。前端按该字段将事件分组，以流水线式界面展示进度。

请参阅 UI Dojo 中的后端实现 [branching-workflow.ts](https://github.com/mastra-ai/ui-dojo/blob/main/src/mastra/workflows/branching-workflow.ts) 和前端实现 [workflow-custom-events.tsx](https://github.com/mastra-ai/ui-dojo/blob/main/src/pages/ai-sdk/workflow-custom-events.tsx)。
