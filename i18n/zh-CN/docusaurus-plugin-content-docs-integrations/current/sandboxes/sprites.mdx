# Fly.io Sprites

通过官方 `@fly/sprites` SDK 在持久化的 [Fly.io Sprites](https://sprites.dev) 中执行命令。Sprite 是一种 Linux 虚拟机，可在多次运行之间保留文件系统，并在空闲时自动休眠。`SpritesSandbox` 按名称获取或创建 Sprite，让新进程可以重新访问同一批文件。命令执行支持流式输出、超时和取消，也支持向后台进程传入标准输入以及创建检查点。有关接口详情，请参阅 [WorkspaceSandbox 接口](/reference/workspace/sandbox)。

## 安装 {/* #installation */}

```bash npm2yarn
npm install @mastra/sprites
```

:::note
`@mastra/sprites` 依赖 `@fly/sprites` SDK，因此要求 Node.js 24 或更高版本。
:::

任选以下一种方式设置 Sprites API 令牌。

## 使用方法 {/* #usage */}

将 `SpritesSandbox` 添加到 Workspace，再将该 Workspace 分配给 Agent。

```typescript
import { Agent } from '@mastra/core/agent'
import { Workspace } from '@mastra/core/workspace'
import { SpritesSandbox } from '@mastra/sprites'

const workspace = new Workspace({
  sandbox: new SpritesSandbox({
    id: 'mastra-project',
    // token read from SPRITES_TOKEN
  }),
})

const agent = new Agent({
  id: 'code-agent',
  name: 'Code Agent',
  instructions: 'You are a coding assistant working in this workspace.',
  model: '__GATEWAY_ANTHROPIC_MODEL_SONNET__',
  workspace,
})

const response = await agent.generate(
  'Print "Hello, world!" and show the current working directory.',
)

console.log(response.text)
```

### 复用 Sprite {/* #reusing-a-sprite */}

`id` 是 Sprite 的名称。调用 `start()` 时，`SpritesSandbox` 会查找同名 Sprite 并重新连接。如果没有找到，就创建一个。之前会话写入的文件仍然保留。

```typescript
const first = new SpritesSandbox({ id: 'mastra-project' })
await first.executeCommand('sh', ['-c', 'echo hello > notes.txt'])
await first.stop()

// Later, possibly in another process
const second = new SpritesSandbox({ id: 'mastra-project' })
const result = await second.executeCommand('cat', ['notes.txt'])
console.log(result.stdout) // hello
```

如果你的账户中已有同名 Sprite，就会复用它，因此请为项目选择唯一的名称。省略 `id` 时会随机生成名称。

`spriteConfig`（内存、CPU、区域和存储）仅在创建 Sprite 时生效。

### 停止和销毁 {/* #stopping-and-destroying */}

`stop()` 和 `destroy()` 的行为如下。

* `stop()` 终止当前实例启动的后台进程并关闭 SDK 连接，同时保留 Sprite 及其文件系统。Sprite 空闲时会自动休眠，无需手动暂停。
* `destroy()` 永久删除 Sprite 及其文件系统。无需先调用 `start()`。如果 Sprite 已不存在，就视为已删除。

```typescript
const sandbox = new SpritesSandbox({ id: 'mastra-project' })

// Remove the Sprite when the project is finished
await sandbox.destroy()
```

### 检查点 {/* #checkpoints */}

`snapshot()` 为 Sprite 的当前状态创建检查点，并等待创建完成。

```typescript
await sandbox.snapshot()
```

检查点保存在 Sprite 内，无法用来启动另一个 Sandbox 或为其提供初始状态。因此，`supportsCheckpoints` 为 `false`，且 `SpritesSandbox` 未实现 `clone()`。要列出或恢复检查点，请通过 `sandbox.sprite` 使用 `@fly/sprites` SDK。

### 流式输出 {/* #streaming-output */}

传入 `onStdout` 和 `onStderr`，即可实时接收输出。

```typescript
await sandbox.executeCommand('npm', ['install'], {
  onStdout: data => process.stdout.write(data),
  onStderr: data => process.stderr.write(data),
  timeout: 120_000,
})
```

命令超时或其 `abortSignal` 触发时，命令会被终止，结果中会返回 `killed: true`。

## 后台进程 {/* #background-processes */}

`SpritesSandbox` 提供进程管理器，用于启动和管理后台进程。每个进程在独立的 Sprites exec 会话中运行，并支持通过 stdin 接收输入。

```typescript
const sandbox = new SpritesSandbox({ id: 'mastra-project' })
await sandbox.start()

const handle = await sandbox.processes.spawn('node server.js', {
  env: { PORT: '3000' },
  onStdout: data => console.log(data),
})

await handle.sendStdin('reload\n')
await handle.kill()
```

某个 `SpritesSandbox` 实例启动的进程对其他实例不可见。调用该实例的 `stop()` 会终止这些进程。

完整的 API 请参阅 [`SandboxProcessManager` 参考文档](/reference/workspace/process-manager)。

## 编辑器的 Provider {/* #editor-provider */}

将 Provider 注册到 `MastraEditor`，即可在运行时根据已保存的 Sandbox 配置创建实例。

```typescript
import { MastraEditor } from '@mastra/editor'
import { spritesSandboxProvider } from '@mastra/sprites'

const editor = new MastraEditor({
  sandboxes: { [spritesSandboxProvider.id]: spritesSandboxProvider },
})
```

有关如何注册自定义 Sandbox Provider，请参阅 [Sandbox Provider 参考文档](/reference/editor/sandbox-provider)。
