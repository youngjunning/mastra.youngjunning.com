# Apple Container

通过 Apple 的 [`container`](https://github.com/apple/container) CLI 在本地 OCI Linux 容器中执行命令。Provider 会启动一个长期运行的容器，并使用 `container exec` 执行 Workspace 命令。接口详情请参见 [WorkspaceSandbox 接口](/reference/workspace/sandbox)。

## 安装 {/* #installation */}

```bash npm2yarn
npm install @mastra/apple-container
```

需要一台运行 macOS 26 或更高版本、已安装 Apple `container` CLI 的 Apple 芯片 Mac。使用该 Provider 前，先启动容器系统：

```bash
container system start
```

## 用法 {/* #usage */}

将 `AppleContainerSandbox` 添加到 Workspace，并将该 Workspace 分配给 Agent：

```typescript
import { Agent } from '@mastra/core/agent'
import { Workspace } from '@mastra/core/workspace'
import { AppleContainerSandbox } from '@mastra/apple-container'

const workspace = new Workspace({
  sandbox: new AppleContainerSandbox({
    image: 'node:22-slim',
    volumes: {
      '/Users/me/project': '/workspace',
    },
    workingDirectory: '/workspace',
  }),
})

const agent = new Agent({
  id: 'dev-agent',
  name: 'Dev Agent',
  instructions: 'You are a coding assistant working in this workspace.',
  model: '__GATEWAY_ANTHROPIC_MODEL_SONNET__',
  workspace,
})

const response = await agent.generate('Run `node --version`.')
console.log(response.text)
```

## 环境变量 {/* #environment-variables */}

使用 `env` 设置容器级环境变量。也可以通过 `executeCommand` 的选项为单次命令传入环境变量：

```typescript
const sandbox = new AppleContainerSandbox({
  image: 'node:22-slim',
  env: {
    NODE_ENV: 'development',
  },
})

await sandbox.executeCommand('node', ['-e', 'console.log(process.env.TASK_ID)'], {
  env: { TASK_ID: '42' },
})
```

## 绑定挂载 {/* #bind-mounts */}

使用 `volumes` 选项将主机目录挂载到容器中：

```typescript
const sandbox = new AppleContainerSandbox({
  image: 'node:22-slim',
  volumes: {
    '/Users/me/project': '/workspace/project',
    '/Users/me/.npm': '/root/.npm',
  },
})
```

绑定挂载在创建容器时生效。主机路径必须在 Sandbox 启动前就已存在。

## 资源和平台选项 {/* #resource-and-platform-options */}

可以通过构造函数传入 Apple container CLI 选项：

```typescript
const sandbox = new AppleContainerSandbox({
  image: 'node:22-slim',
  volumes: {
    '/Users/me/project': '/workspace',
  },
  cpus: 2,
  memory: '2G',
  platform: 'linux/arm64',
  readonlyRootfs: true,
  tmpfs: ['/tmp'],
})
```

这些选项仅在创建新容器时生效。如果 Sandbox 重连到同名的现有容器，需要销毁并重新创建 Sandbox，才能应用已修改的运行时选项。
Apple 的 `--tmpfs` 只接受 `/tmp` 这样的容器路径，不接受 `/tmp:rw,size=256m` 这样的 Docker 风格配置。
启用 `readonlyRootfs` 时，确保 `workingDirectory` 指向镜像提供的路径或绑定挂载路径。也可以使用可写的 tmpfs。

## 安全模型 {/* #security-model */}

`AppleContainerSandbox` 通过主机上的 Apple `container` 服务运行本地容器。构造函数选项应作为可信的服务器端配置来处理：

* `volumes`、`mounts` 和 `publishedSockets` 可能让容器内的代码访问主机路径。
* `publishedPorts` 可能向主机或网络开放容器内服务。如果只需本地访问，应绑定到 `127.0.0.1`。
* `ssh` 会转发主机的 SSH Agent 套接字。
* `capAdd` 和 `virtualization` 会扩大容器内代码的能力。
* `containerBinary` 是供可信代码使用、仅能在构造函数中设置的特殊选项，不属于可序列化的编辑器 Provider 配置结构。

只授予工作负载必需的挂载和能力。只有现有容器带有与 Sandbox ID 匹配的 Mastra 所有权标签，才会重连。此 Provider 创建的容器还带有配置哈希标签；如果该标签存在，而镜像、命令、挂载、端口、能力或工作目录等不可变运行时选项发生变化，重连就会失败。

## 局限性 {/* #limitations */}

`AppleContainerSandbox` 通过 `executeCommand()` 支持在 Workspace 中执行前台命令。目前尚未提供用于后台进程或 LSP 会话的 `SandboxProcessManager`。

命令超时在容器内执行，因此容器运行时会清理超时的命令。中止信号只会取消主机 CLI 的等待过程；如果需要清理容器内的命令，就不应以中止信号代替命令超时。

## 重连 {/* #reconnection */}

`AppleContainerSandbox` 通过检查指定名称的容器来重连。调用 `start()` 时：

* 如果容器正在运行，则复用它。
* 如果容器已停止，则重新启动它。
* 如果容器不存在，则使用配置的镜像创建它。
* 如果同名容器没有匹配的 Mastra 所有权标签，则操作会失败，不会接管该容器。
* 如果 Mastra 所有的容器带有配置哈希标签，而该标签与不可变运行时选项不匹配，则操作会失败，不会复用该容器。

```typescript
const sandbox = new AppleContainerSandbox({ id: 'persistent-sandbox' })
await sandbox.start()

const sandbox2 = new AppleContainerSandbox({ id: 'persistent-sandbox' })
await sandbox2.start()
```

## 编辑器 Provider {/* #editor-provider */}

在 `MastraEditor` 中注册该 Provider，以还原已存储的 Sandbox 配置：

```typescript
import { MastraEditor } from '@mastra/editor'
import { appleContainerSandboxProvider } from '@mastra/apple-container'

const editor = new MastraEditor({
  sandboxes: {
    [appleContainerSandboxProvider.id]: appleContainerSandboxProvider,
  },
})
```
