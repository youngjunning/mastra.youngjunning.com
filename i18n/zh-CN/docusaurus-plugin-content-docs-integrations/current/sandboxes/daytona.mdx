# Daytona

在隔离的 [Daytona](https://www.daytona.io) 云端 Sandbox 中执行命令。支持多种运行时、资源配置、卷、快照、流式输出、Sandbox 重连、文件系统挂载（S3、GCS）和网络隔离。接口详情请参阅 [WorkspaceSandbox 接口](/reference/workspace/sandbox)。

## 安装 {/* #installation */}

```bash npm2yarn
npm install @mastra/daytona @daytona/sdk
```

可以通过以下三种方式之一设置 Daytona API 密钥。

<Tabs>
  <TabItem value="shell-export" label="在 Shell 中导出">
    ```bash
    export DAYTONA_API_KEY=your-api-key
    ```
  </TabItem>

  <TabItem value="env-file" label=".env 文件">
    ```bash
    DAYTONA_API_KEY=your-api-key
    ```
  </TabItem>

  <TabItem value="constructor" label="构造函数">
    ```typescript
    new DaytonaSandbox({ apiKey: 'your-api-key' })
    ```
  </TabItem>
</Tabs>

## 使用方法 {/* #usage */}

将 `DaytonaSandbox` 添加到 Workspace，并将其分配给 Agent：

```typescript
import { Agent } from '@mastra/core/agent'
import { Workspace } from '@mastra/core/workspace'
import { DaytonaSandbox } from '@mastra/daytona'

const workspace = new Workspace({
  sandbox: new DaytonaSandbox({
    language: 'typescript',
    timeout: 120_000,
  }),
})

const agent = new Agent({
  id: 'code-agent',
  name: 'Code Agent',
  instructions: 'You are a coding assistant working in this workspace.',
  model: '__GATEWAY_ANTHROPIC_MODEL_SONNET__',
  workspace,
})

const response = await agent.generate(
  'Print "Hello, world!" and show the current working directory.',
)

console.log(response.text)
// I'll run both commands simultaneously!
//
// Here are the results:
//
// 1. **Hello, world!** — Successfully printed the message.
// 2. **Current Working Directory** — `/home/daytona`
//
// Both commands ran in parallel and completed successfully!
```

### 使用快照 {/* #with-a-snapshot */}

使用预先构建的快照，省去环境设置时间：

```typescript
const workspace = new Workspace({
  sandbox: new DaytonaSandbox({
    snapshot: 'my-snapshot-id',
    timeout: 60_000,
  }),
})
```

### 使用自定义镜像和资源 {/* #custom-image-with-resources */}

使用自定义 Docker 镜像，并指定资源分配：

```typescript
const workspace = new Workspace({
  sandbox: new DaytonaSandbox({
    image: 'node:20-slim',
    resources: { cpu: 2, memory: 4, disk: 6 },
    language: 'typescript',
  }),
})
```

### 临时 Sandbox {/* #ephemeral-sandbox */}

对于一次性任务，可以在 Sandbox 停止后立即将其删除：

```typescript
const workspace = new Workspace({
  sandbox: new DaytonaSandbox({
    ephemeral: true,
    language: 'python',
  }),
})
```

### 流式输出 {/* #streaming-output */}

通过 `onStdout` 和 `onStderr` 回调实时获取命令输出：

```typescript
await sandbox.executeCommand('bash', ['-c', 'for i in 1 2 3; do echo "line $i"; sleep 1; done'], {
  onStdout: chunk => process.stdout.write(chunk),
  onStderr: chunk => process.stderr.write(chunk),
})
```

这两个回调均可省略，也可以分别使用。

### 重连 {/* #reconnection */}

提供相同的 `id` 即可重新连接到现有 Sandbox。重新连接后，其文件和状态保持不变：

```typescript
const sandbox = new DaytonaSandbox({ id: 'my-persistent-sandbox' })

// First session
await sandbox._start()
await sandbox.executeCommand('sh', ['-c', 'echo "session 1" > /tmp/state.txt'])
await sandbox._stop()

// Later — reconnects to the same sandbox
const sandbox2 = new DaytonaSandbox({ id: 'my-persistent-sandbox' })
await sandbox2._start()
const result = await sandbox2.executeCommand('cat', ['/tmp/state.txt'])
console.log(result.stdout) // "session 1"
```

如果 Sandbox 已停止或已归档，系统会自动将其重新启动。如果 Sandbox 已失效（已销毁或发生错误），则会创建一个新的 Sandbox。

### 文件系统挂载 {/* #filesystem-mounting */}

将 S3 或 GCS 存储桶挂载为 Sandbox 内的本地目录。

#### 通过 Workspace 挂载配置 {/* #via-workspace-mounts-config */}

最简单的方式是在 Sandbox 启动时自动挂载文件系统：

```typescript
import { Workspace } from '@mastra/core/workspace'
import { DaytonaSandbox } from '@mastra/daytona'
import { GCSFilesystem } from '@mastra/gcs'
import { S3Filesystem } from '@mastra/s3'

const workspace = new Workspace({
  mounts: {
    '/s3-data': new S3Filesystem({
      bucket: process.env.S3_BUCKET!,
      region: 'auto',
      accessKeyId: process.env.S3_ACCESS_KEY_ID,
      secretAccessKey: process.env.S3_SECRET_ACCESS_KEY,
      endpoint: process.env.S3_ENDPOINT, // e.g. https://<account-id>.r2.cloudflarestorage.com
    }),
    '/gcs-data': new GCSFilesystem({
      bucket: process.env.GCS_BUCKET!,
      projectId: 'my-project-id',
      credentials: JSON.parse(process.env.GCS_SERVICE_ACCOUNT_KEY!),
    }),
  },
  sandbox: new DaytonaSandbox({ language: 'python' }),
})
```

Workspace 启动时，文件系统会自动挂载到指定路径。此后，Sandbox 中运行的代码可以像访问本地目录一样访问 `/s3-data` 和 `/gcs-data` 中的文件。

#### 临时 S3 凭证 {/* #temporary-s3-credentials */}

使用临时凭证时，须将三个凭证值全部传给 `S3Filesystem`。Daytona 会将会话令牌转交给 s3fs：

```typescript
import { Workspace } from '@mastra/core/workspace'
import { DaytonaSandbox } from '@mastra/daytona'
import { S3Filesystem } from '@mastra/s3'

const workspace = new Workspace({
  mounts: {
    '/s3-data': new S3Filesystem({
      bucket: process.env.S3_BUCKET!,
      region: process.env.S3_REGION ?? 'us-east-1',
      endpoint: process.env.S3_ENDPOINT,
      prefix: 'resource-123/thread-456/',
      accessKeyId: process.env.SCOPED_S3_ACCESS_KEY_ID!,
      secretAccessKey: process.env.SCOPED_S3_SECRET_ACCESS_KEY!,
      sessionToken: process.env.SCOPED_S3_SESSION_TOKEN!,
    }),
  },
  sandbox: new DaytonaSandbox({ language: 'python', ephemeral: true }),
})
```

启动 Workspace 前，请向存储 Provider 获取只允许访问目标前缀的凭证。凭证的签发方式由 Provider 决定；Mastra 不会签发凭证，也不会限制凭证权限。`prefix` 只用于选择目录，并不能实施授权控制。请对每个请求进行身份验证，核查其资源和线程的访问权限，并为不同的安全范围使用不同的 Sandbox。

临时凭证在挂载开始时加载，之后不会自动刷新。主机端的凭证 Provider 函数也不会刷新已建立的挂载。请确保任务在凭证有效期内完成；后续任务应使用新凭证创建新的 Sandbox。重新连接 Sandbox 不会更新其凭证。

凭证会上传到私有目录中仅所有者可访问的文件。启动 s3fs 后，Daytona 会删除用于暂存临时凭证的文件和目录。守护进程仍会在其环境中保留凭证，因此以同一用户或 root 身份运行的 Sandbox 代码仍可能读取凭证。切勿提供超出 Sandbox 所需权限的凭证。使用长期凭证的挂载会在 s3fs 需要密码文件期间保留这些文件。卸载和重连时的清理流程会先确认守护进程已退出，再删除文件。如果守护进程仍在运行（包括挂载被移到一旁之后），或者无法检查其状态，系统会保留文件并记录警告。之后卸载同一路径时会再次尝试删除；删除 Sandbox 会移除所有剩余文件。

带前缀的文件系统在初始化时必须有权限列出该前缀。对于 s3fs，带前缀的挂载可能还需要在准确的 `<prefix>/` 键下存在一个零字节对象。请在挂载前创建这个目录标记。启动 s3fs 后，Daytona 会检查已挂载目录的元数据，但不会列出目录内容；检查超时时间为 15 秒，再过 5 秒会强制终止。检查失败会报告挂载失败。清理流程会尝试卸载失败的挂载；必要时会把卡住的挂载移到一旁，以便腾出原路径供重试。移开的旧挂载可能一直保留到 Sandbox 删除。此项启动检查不能保证单个文件可读写，也不能保证守护进程持续正常运行；请通过挂载路径实际验证读取和写入。

#### 通过 `sandbox.mount()` 挂载 {/* #via-sandboxmount */}

Sandbox 启动后，可以随时手动挂载：

#### S3 {/* #s3 */}

```typescript
import { S3Filesystem } from '@mastra/s3'

await sandbox.mount(
  new S3Filesystem({
    bucket: process.env.S3_BUCKET!,
    region: 'us-east-1',
    accessKeyId: process.env.S3_ACCESS_KEY_ID,
    secretAccessKey: process.env.S3_SECRET_ACCESS_KEY,
  }),
  '/data',
)
```

### 网络隔离 {/* #network-isolation */}

限制出站网络访问：

```typescript
const workspace = new Workspace({
  sandbox: new DaytonaSandbox({
    networkBlockAll: true,
    networkAllowList: '10.0.0.0/8,192.168.0.0/16',
  }),
})
```

对于软件包注册表和托管 API 等 IP 地址可能变化的服务，请使用 `domainAllowList`：

```typescript
const workspace = new Workspace({
  sandbox: new DaytonaSandbox({
    networkBlockAll: true,
    domainAllowList: 'registry.npmjs.org,*.githubusercontent.com',
  }),
})
```

两个允许列表都会在创建 Sandbox 时生效，并由 `clone()` 保留。若要在 Sandbox 启动后修改策略，请使用底层 Daytona Sandbox：

```typescript
await sandbox.instance.updateNetworkSettings({
  domainAllowList: 'api.example.com',
})
```

### Secrets {/* #secrets */}

可以注入凭证，而不向 Sandbox 中运行的代码暴露原始值。先通过 Daytona 控制台或 SDK 为组织创建一次 [Daytona Secret](https://www.daytona.io/docs/en/secrets/)，再将环境变量名映射到 Secret 名称：

```typescript
const workspace = new Workspace({
  sandbox: new DaytonaSandbox({
    secrets: {
      GITHUB_TOKEN: 'github-token',
    },
  }),
})
```

在 Sandbox 内，环境变量保存的是不透明占位符。向该 Secret 允许的主机发送 HTTPS 请求时，Daytona 的出口代理会在请求头中将占位符替换为实际值，因此原始凭证不会进入 Sandbox。Secrets 在创建 Sandbox 时生效，并由 `clone()` 保留。

### 计算机操作（桌面） {/* #computer-use-desktop */}

通过 `computerUse` 启用[计算机操作能力](/docs/sandbox/computer)，为 Sandbox 添加截图、鼠标和键盘控制。Sandbox 用于 Workspace 时，Agent 会自动获得 `mastra_workspace_computer_*` Tool。

计算机操作默认禁用。设置 `computerUse: true` 后，桌面进程（Xvfb、xfce4、x11vnc、noVNC）会在首次执行计算机操作时按需启动：

```typescript
const sandbox = new DaytonaSandbox({ computerUse: true })
await sandbox.start()

await sandbox.computer.leftClick(100, 200)
await sandbox.computer.type('hello')
const { data } = await sandbox.computer.screenshot() // PNG bytes

// Live desktop view via the noVNC preview link
const url = await sandbox.computer.streamUrl()
```

也可以传入选项对象配置此能力。例如，直接管理 Daytona 进程时，可以禁用桌面自动启动：

```typescript
const sandbox = new DaytonaSandbox({
  computerUse: { autoStart: false },
})

await sandbox.start()
await sandbox.daytona.computerUse.start()
```

对于 Daytona 专有的桌面 API（区域、压缩截图、屏幕录制、无障碍树），可以通过[直接访问 SDK](#direct-sdk-access) 使用 `sandbox.daytona.computerUse`。

## 后台进程 {/* #background-processes */}

`DaytonaSandbox` 内置进程管理器，可启动和管理后台进程。这些进程通过基于会话的命令执行机制在 Daytona 云端 Sandbox 中运行。

```typescript
const sandbox = new DaytonaSandbox({ language: 'typescript' })
await sandbox.start()

// Spawn a background process
const handle = await sandbox.processes.spawn('node server.js', {
  env: { PORT: '3000' },
  onStdout: data => console.log(data),
})

// Interact with the process
console.log(handle.stdout)
await handle.sendStdin('input\n')
await handle.kill()
```

完整 API 请参阅 [`SandboxProcessManager` 参考文档](/reference/workspace/process-manager)。

## 挂载云存储 {/* #mounting-cloud-storage */}

Daytona Sandbox 可以挂载 S3 或 GCS 存储桶，让 Sandbox 内的代码通过本地目录访问云存储。适用场景包括：

- 处理存储在云存储桶中的大型数据集
- 将输出文件直接写入云存储
- 在 Sandbox 会话之间共享数据

使用示例请参阅[文件系统挂载](#filesystem-mounting)。

Daytona Sandbox 使用 FUSE（用户空间文件系统）挂载云存储：

- **S3/R2**：通过 [s3fs-fuse](https://github.com/s3fs-fuse/s3fs-fuse) 挂载
- **GCS**：通过 [gcsfuse](https://github.com/GoogleCloudPlatform/gcsfuse) 挂载

如果 Sandbox 镜像中尚未安装所需的 FUSE 工具，系统会在挂载时自动安装。

### S3 环境变量 {/* #s3-environment-variables */}

| 变量 | 说明 |
| - | - |
| `S3_BUCKET` | 存储桶名称 |
| `S3_REGION` | AWS 区域；R2/MinIO 可使用 `auto` |
| `S3_ACCESS_KEY_ID` | 访问密钥 ID |
| `S3_SECRET_ACCESS_KEY` | 私有访问密钥 |
| `S3_ENDPOINT` | 端点 URL（仅用于 S3 兼容服务） |

### GCS 环境变量 {/* #gcs-environment-variables */}

| 变量 | 说明 |
| - | - |
| `GCS_BUCKET` | 存储桶名称 |
| `GCS_SERVICE_ACCOUNT_KEY` | 服务账号密钥 JSON（完整的 JSON 字符串，而非文件路径） |

### 通过快照减少冷启动延迟 {/* #reducing-cold-start-latency-with-a-snapshot */}

默认情况下，首次挂载时会通过 `apt` 安装 `s3fs` 和 `gcsfuse`，这会增加启动时间。为避免这部分耗时，可将它们预先构建到 Daytona 快照中，并通过 snapshot 选项传入快照名称。

**选项 1：声明式构建镜像**

```typescript
import { Daytona, Image } from '@daytona/sdk'

const template = Image.base('daytonaio/sandbox')
  .runCommands('sudo apt-get update -qq')
  .runCommands('sudo apt-get install -y s3fs')
  // gcsfuse requires the Google Cloud apt repository
  .runCommands(
    'sudo mkdir -p /etc/apt/keyrings && ' +
      'curl -fsSL https://packages.cloud.google.com/apt/doc/apt-key.gpg -o /tmp/gcsfuse-key.gpg && ' +
      'sudo gpg --batch --yes --dearmor -o /etc/apt/keyrings/gcsfuse.gpg /tmp/gcsfuse-key.gpg && ' +
      // Use gcsfuse-jammy for Ubuntu, gcsfuse-bookworm for Debian
      'echo "deb [signed-by=/etc/apt/keyrings/gcsfuse.gpg] https://packages.cloud.google.com/apt gcsfuse-jammy main" | sudo tee /etc/apt/sources.list.d/gcsfuse.list',
  )
  .runCommands('sudo apt-get update -qq && sudo apt-get install -y gcsfuse')

const daytona = new Daytona()

await daytona.snapshot.create(
  {
    name: 'cloud-fs-mounting',
    image: template,
  },
  { onLogs: console.log },
)
```

**选项 2：Dockerfile：**使用 [`Image.fromDockerfile()`](https://www.daytona.io/docs/typescript-sdk/image#fromdockerfile)

```dockerfile
FROM daytonaio/sandbox
RUN sudo apt-get update -qq
RUN sudo apt-get install -y s3fs
# Use gcsfuse-jammy for Ubuntu, gcsfuse-bookworm for Debian
RUN sudo mkdir -p /etc/apt/keyrings && curl -fsSL https://packages.cloud.google.com/apt/doc/apt-key.gpg -o /tmp/gcsfuse-key.gpg && sudo gpg --batch --yes --dearmor -o /etc/apt/keyrings/gcsfuse.gpg /tmp/gcsfuse-key.gpg && echo "deb [signed-by=/etc/apt/keyrings/gcsfuse.gpg] https://packages.cloud.google.com/apt gcsfuse-jammy main" | sudo tee /etc/apt/sources.list.d/gcsfuse.list
RUN sudo apt-get update -qq && sudo apt-get install -y gcsfuse
```

```typescript
import { Daytona, Image } from '@daytona/sdk'

const daytona = new Daytona()

await daytona.snapshot.create(
  {
    name: 'cloud-fs-mounting',
    image: Image.fromDockerfile('./Dockerfile'),
  },
  { onLogs: console.log },
)
```

然后在 Sandbox 配置中使用快照名称：

```typescript
const workspace = new Workspace({
  mounts: {
    '/s3-data': new S3Filesystem({/* ... */}),
    '/gcs-data': new GCSFilesystem({/* ... */}),
  },
  sandbox: new DaytonaSandbox({ snapshot: 'cloud-fs-mounting' }),
})
```

## 直接访问 SDK {/* #direct-sdk-access */}

通过底层 Daytona `Sandbox` 实例执行文件系统、git 等 `WorkspaceSandbox` 接口未提供的操作：

```typescript
const daytonaSandbox = sandbox.instance

// Upload a file
await daytonaSandbox.fs.uploadFile(Buffer.from('hello'), '/tmp/hello.txt')

// Run git operations
await daytonaSandbox.git.clone('https://github.com/org/repo', '/workspace/repo')
```

如果 Sandbox 尚未启动，`instance` getter 会抛出 `SandboxNotReadyError`。

## 沙盒创建模式 {/* #sandbox-creation-modes */}

`DaytonaSandbox` 根据提供的选项选择创建模式：

| 选项 | 创建模式 |
| - | - |
| 设置了 snapshot | 基于快照（`snapshot` 优先于 image） |
| 设置了 `image`，未设置 `snapshot` | 基于镜像（可同时指定 `resources`） |
| 两者均未设置 | 默认基于快照 |

仅在设置了 `image` 时才会应用资源配置。只传入 `resources` 而不设置 `image` 不会产生效果。
