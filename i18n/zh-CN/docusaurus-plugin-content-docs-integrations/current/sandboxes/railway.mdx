# Railway

在临时、隔离的 [Railway](https://docs.railway.com/sandboxes) Sandbox 中执行命令。每个 Sandbox 都是通过 Railway TypeScript SDK 按需创建的独立 Debian Linux 虚拟机。它支持流式命令输出、命令超时、可配置的空闲超时、`ISOLATED`/`PRIVATE` 网络隔离、通过 Railway 模板构建器创建自定义基础镜像、通过检查点恢复、分叉运行中的 Sandbox，以及按 ID 重新连接现有 Sandbox。接口详情请参阅 [WorkspaceSandbox 接口](/reference/workspace/sandbox)。

## 安装 {/* #installation */}

```bash npm2yarn
npm install @mastra/railway
```

可以通过以下三种方式之一设置 Railway 凭证。

<Tabs>
  <TabItem value="shell-export" label="在 Shell 中导出">

## 用法 {/* #usage */}

将 `RailwaySandbox` 添加到 Workspace，并将该 Workspace 分配给 Agent：

```typescript
import { Agent } from '@mastra/core/agent'
import { Workspace } from '@mastra/core/workspace'
import { RailwaySandbox } from '@mastra/railway'

const workspace = new Workspace({
  sandbox: new RailwaySandbox({
    // token + environmentId read from RAILWAY_API_TOKEN / RAILWAY_ENVIRONMENT_ID
    idleTimeoutMinutes: 30,
  }),
})

const agent = new Agent({
  id: 'code-agent',
  name: 'Code Agent',
  instructions: 'You are a coding assistant working in this workspace.',
  model: '__GATEWAY_ANTHROPIC_MODEL_SONNET__',
  workspace,
})

const response = await agent.generate(
  'Print "Hello, world!" and show the current working directory.',
)

console.log(response.text)
```

### 私有网络 {/* #private-networking */}

加入环境的私有网络，以访问其他 Railway 服务（例如 `postgres.railway.internal`）：

```typescript
const workspace = new Workspace({
  sandbox: new RailwaySandbox({
    networkIsolation: 'PRIVATE',
    env: { NODE_ENV: 'production' },
  }),
})
```

默认的 `ISOLATED` 模式仅允许访问外部互联网，无法连接私有网络。

### 自定义基础镜像（模板） {/* #custom-base-image-templates */}

预先安装软件包并执行初始化步骤，让每个 Sandbox 启动后即可使用。向 Railway 模板构建器传入构建回调；首次调用 `start()` 时会构建一次模板：

```typescript
const workspace = new Workspace({
  sandbox: new RailwaySandbox({
    template: t => t.withPackages('git', 'curl').run('npm i -g pnpm').workdir('/app'),
  }),
})
```

也可以传入预先构建的 `SandboxTemplate`，在多个 Sandbox 之间复用，无需重新构建。设置 `sandboxId` 后，模板会被忽略，因为重新连接会使用现有 Sandbox 的文件系统。

### 分叉运行中的 Sandbox {/* #forking-a-running-sandbox */}

将运行中 Sandbox 的文件系统克隆到新的独立 Sandbox。新 Sandbox 会重新启动，不会复制运行中的进程。返回的 `RailwaySandbox` 已启动：

```typescript
const child = await sandbox.fork({ idleTimeoutMinutes: 15 })

const result = await child.executeCommand('cat', ['/app/state.json'])
console.log(result.stdout)
```

分叉出的 Sandbox 会继承父 Sandbox 的凭证和默认设置，除非通过 `fork()` 选项覆盖。

### 检查点恢复 {/* #checkpoint-recovery */}

设置 `checkpointName`，可在 Railway 更换 Sandbox 后保留其文件系统。调用 `start()` 时，`RailwaySandbox` 会先尝试从检查点创建 Sandbox。如果检查点不存在，就从配置的模板或默认镜像创建 Sandbox，然后保存检查点。

```typescript
const sandbox = new RailwaySandbox({
  checkpointName: 'project-session-42',
  idleTimeoutMinutes: 30,
})
```

`RailwaySandbox` 会在空闲超时前不久刷新检查点。恢复操作使用最近一次成功保存的检查点，不会恢复运行中的进程，也不会恢复上次检查点之后的文件系统写入。

设置 `seedCheckpointName`，可在 `checkpointName` 尚不存在时提供仅供启动使用的备用检查点。若两个检查点都存在，Railway 会优先恢复 `checkpointName`。之后的快照只写入 `checkpointName`，因此每个 Sandbox 都有独立的恢复历史。

```typescript
const sandbox = new RailwaySandbox({
  checkpointName: 'project-session-42',
  seedCheckpointName: 'project-base',
})
```

更新文件系统后，调用 `snapshot()` 可立即保存到配置的检查点。若未配置 `checkpointName` 或 Sandbox 未运行，此方法会直接完成，不会保存快照。

```typescript
await sandbox.snapshot()
```

为每个独立的文件系统使用一个稳定的检查点名称。不要在不相关的会话或项目之间共享检查点名称。

### 克隆 Sandbox 的检查点 {/* #cloned-sandbox-checkpoints */}

当一个已配置的 `RailwaySandbox` 用作一组 Sandbox 的模板时，可以使用 `clone({ checkpointName })`：

```typescript
const template = new RailwaySandbox({ idleTimeoutMinutes: 30 })

const sessionSandbox = template.clone({
  id: 'session-42',
  checkpointName: 'project-session-42',
})

await sessionSandbox.start()
```

克隆出的 Sandbox 使用传给 `clone()` 的检查点。若未覆盖该设置，则继承模板 Sandbox 的 `checkpointName`。

### 流式输出 {/* #streaming-output */}

通过 `onStdout` 和 `onStderr` 回调实时接收命令输出：

```typescript
await sandbox.executeCommand('bash', ['-c', 'for i in 1 2 3; do echo "line $i"; sleep 1; done'], {
  onStdout: chunk => process.stdout.write(chunk),
  onStderr: chunk => process.stderr.write(chunk),
})
```

两个回调都是可选的并且可以独立使用。

### 重新附加到现有Sandbox {/* #reattaching-to-an-existing-sandbox */}

Railway Sandbox 可以在创建它的进程结束后继续运行。使用 Railway ID 重新连接，无需创建新的 Sandbox：

```typescript
const sandbox = new RailwaySandbox({ sandboxId: 'existing-railway-sandbox-id' })
await sandbox._start()

const result = await sandbox.executeCommand('cat', ['/tmp/state.txt'])
```

默认情况下（`reattach: 'best-effort'`），如果该 ID 对应的 Sandbox 已不存在或未运行，`start()` 会创建替代 Sandbox，并报告 `{ outcome: 'created' }`。如果替换 Sandbox 会导致应用依赖的状态悄然丢失，请设置 `reattach: 'required'`：

```typescript
const sandbox = new RailwaySandbox({
  sandboxId: 'existing-railway-sandbox-id',
  reattach: 'required',
})
```

设置 `reattach: 'required'` 后，如果 Sandbox 不存在或已停止，`start()` 会抛出 `code` 为 `SANDBOX_REATTACH_FAILED` 的 `SandboxError`，且不会创建新 Sandbox。错误的 `details` 包含 `provider`、`sandboxId` 和 `logicalId`（Sandbox 的逻辑 `id`）。网络故障、身份验证失败等其他错误会原样抛出。若要重新开始，请清除持久化的 `sandboxId`，并在构造 Sandbox 时不传入它。克隆实例会继承 `reattach` 设置。

## 后台进程 {/* #background-processes */}

`RailwaySandbox` 内置进程管理器，用于启动和管理后台进程。每个进程都作为 Railway `exec` 会话运行。

```typescript
const sandbox = new RailwaySandbox()
await sandbox.start()

// Spawn a background process
const handle = await sandbox.processes.spawn('node server.js', {
  env: { PORT: '3000' },
  onStdout: data => console.log(data),
})

// Interact with the process
console.log(handle.stdout)
await handle.kill()
```

Railway 的 `exec` API 不支持 stdin 流式传输，因此不支持 `sendStdin()`。

完整 API 请参阅 [`SandboxProcessManager` 参考文档](/reference/workspace/process-manager)。

## 编辑器 Provider {/* #editor-provider */}

在 `MastraEditor` 中注册 Provider，以便将已保存的 Sandbox 配置还原为运行时实例：

```typescript
import { railwaySandboxProvider } from '@mastra/railway'

const editor = new MastraEditor({
  sandboxes: { [railwaySandboxProvider.id]: railwaySandboxProvider },
})
```

有关注册自定义 Sandbox Provider 的详情，请参阅 [Sandbox Provider 参考文档](/reference/editor/sandbox-provider)。
