# Modal

在隔离的 [Modal](https://modal.com) 云端 Sandbox 中执行命令。Modal 的基础设施提供安全的临时运行环境。有关接口的详细信息，请参阅 [WorkspaceSandbox 接口](/reference/workspace/sandbox)。

## 安装 {/* #installation */}

```bash npm2yarn
npm install @mastra/modal
```

## 使用方式 {/* #usage */}

将 `ModalSandbox` 添加到 Workspace，再将该 Workspace 分配给 Agent：

```typescript
import { Agent } from '@mastra/core/agent'
import { Workspace } from '@mastra/core/workspace'
import { ModalSandbox } from '@mastra/modal'

const workspace = new Workspace({
  sandbox: new ModalSandbox({
    id: 'dev-sandbox',
    baseImage: 'ubuntu:22.04',
    timeoutMs: 60_000,
  }),
})

const agent = new Agent({
  id: 'dev-agent',
  model: '__GATEWAY_ANTHROPIC_MODEL_OPUS__',
  workspace,
})
```

## 身份验证 {/* #authentication */}

通过环境变量或构造函数选项设置 Modal 凭据：

```bash
MODAL_TOKEN_ID=ak-...
MODAL_TOKEN_SECRET=as-...
```

也可以直接向构造函数传入凭据：

```typescript
const sandbox = new ModalSandbox({
  tokenId: process.env.MODAL_TOKEN_ID,
  tokenSecret: process.env.MODAL_TOKEN_SECRET,
})
```

可在 [Modal 控制台](https://modal.com/settings/tokens)获取凭据。

## Sandbox 生命周期 {/* #sandbox-lifecycle */}

* **`_start()`**：尝试重新连接到正在运行的 Sandbox。如果找不到正在运行的 Sandbox，就使用此前调用 `_stop()` 时保存的最新快照创建一个。没有可用快照时，使用 `baseImage` 创建。
* **`_stop()`**：为文件系统创建快照，然后终止 Sandbox。快照保存在同一实例的内存中，供后续启动使用。
* **`_destroy()`**：终止 Sandbox，并丢弃所有已有快照。

```typescript
const sandbox = new ModalSandbox({
  id: 'dev-sandbox',
  baseImage: 'ubuntu:22.04',
  timeoutMs: 300_000,
})

await sandbox._start()
await sandbox.processes.spawn('npm install')
await sandbox._stop()
await sandbox._start()
```

## 存储卷与文件持久化 {/* #volumes-and-persistent-files */}

通过 `volumes` 选项挂载 [Modal Volumes](https://modal.com/docs/guide/volumes)，再用 `ModalFilesystem` 将挂载路径提供给 Agent 的 Workspace 文件 Tool。写入挂载路径下的文件在 Sandbox 重启后仍会保留。

```typescript
import { Workspace } from '@mastra/core/workspace'
import { ModalFilesystem, ModalSandbox } from '@mastra/modal'
import { ModalClient } from 'modal'

const modal = new ModalClient()
const privateVolume = await modal.volumes.fromName('agent-user-123', { createIfMissing: true })
const teamVolume = await modal.volumes.fromName('agent-team', { createIfMissing: true })

const sandbox = new ModalSandbox({
  id: 'agent-sandbox',
  workingDirectory: '/workspace',
  volumes: {
    '/mnt/agent': privateVolume,
    '/mnt/team': teamVolume,
  },
})

const workspace = new Workspace({
  sandbox,
  filesystem: new ModalFilesystem({ sandbox, basePath: '/mnt/agent' }),
})
```

`ModalFilesystem` 在 Sandbox 内执行文件操作，并将所有可访问的路径限制在 `basePath` 范围内。设置 `readOnly: true` 可拒绝写入。

其他 Sandbox 写入同一个卷的内容，只有在重新加载后才可见。对于长期运行的 Sandbox，调用 `reloadVolumes()` 即可读取这些更新：

```typescript
await sandbox.reloadVolumes()
```

:::note

请将工作目录设在所有卷的挂载路径之外，例如 `/workspace`。Modal 无法重新加载当前工作目录所在的卷，因此，如果 `workingDirectory` 等于某个挂载路径或位于其下，`ModalSandbox` 会抛出异常。

:::

## 后台进程 {/* #background-processes */}

`ModalSandbox` 内置进程管理器，可启动和管理后台进程。每次调用 `spawn()`，都会通过 Modal SDK 的 `Sandbox.exec()` API 创建一个新的 `ContainerProcess`。

```typescript
const sandbox = new ModalSandbox({ id: 'dev-sandbox' })
await sandbox._start()

// Spawn a background process
const handle = await sandbox.processes.spawn('node script.js', {
  env: { PORT: '3000' },
  onStdout: data => console.log(data),
})

// Wait for the process to complete
const result = await handle.wait()
console.log(result.exitCode)

// Kill the process
await handle.kill()
```

:::note

`sendStdin()` 不受支持。Modal JS SDK 的 `Sandbox.exec()` 未提供访问标准输入的接口。

:::

完整 API 请参阅 [`SandboxProcessManager` 参考文档](/reference/workspace/process-manager)。
