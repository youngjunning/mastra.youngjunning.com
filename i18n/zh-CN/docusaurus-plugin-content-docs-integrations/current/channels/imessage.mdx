# iMessage

iMessage 渠道让 Mastra Agent 接收 iMessage 私聊和群聊消息。[Photon](https://app.photon.codes) 和 [Linq](https://linqapp.com) 分别维护各自的 iMessage 适配器。Mastra 负责将适配器接入 Agent 并提供 Webhook 路由。号码开通、凭据配置和 Webhook 注册请参阅相应的适配器文档。

## 选择适配器 {/* #choose-an-adapter */}

两个适配器接入 Mastra 的方式相同，先选择你要使用的 Provider。

* **Photon** 提供托管和自托管两种 iMessage 服务，支持 Webhook，也可通过[网关监听器](#gateway-listener)保持连接并持续接收消息。
* **Linq** 提供托管的 iMessage、RCS 和 SMS API，通过 Webhook 接收事件，并支持双向映射 Tapback 回应和媒体内容。

## 安装适配器 {/* #install-the-adapter */}

<Tabs groupId="imessage-provider">
  <TabItem value="photon" label="Photon">
    安装 Photon iMessage 适配器。

    ```bash npm2yarn
    npm install @photon-ai/chat-adapter-imessage
    ```
  </TabItem>

  <TabItem value="linq" label="Linq">
    安装 Linq Chat SDK 适配器。

    ```bash npm2yarn
    npm install @linqapp/chat-sdk-adapter
    ```
  </TabItem>
</Tabs>

## 配置 Agent {/* #agent-configuration */}

在 Agent 的 `channels.adapters` 对象中调用适配器工厂函数。

<Tabs groupId="imessage-provider">
  <TabItem value="photon" label="Photon">
    ```typescript title="src/mastra/agents/imessage-agent.ts"
    import { Agent } from '@mastra/core/agent'
    import { createiMessageAdapter } from '@photon-ai/chat-adapter-imessage'

    export const imessageAgent = new Agent({
      id: 'imessage-agent',
      name: 'iMessage Agent',
      instructions: 'Answer questions and help with tasks over iMessage.',
      model: '__GATEWAY_OPENAI_MODEL__',
      channels: {
        adapters: {
          imessage: {
            adapter: createiMessageAdapter(),
            toolDisplay: 'text',
          },
        },
        threadContext: { maxMessages: 0 },
      },
    })
    ```

    Mastra 通常会在 Agent 首次被群聊消息提及时查询平台上的聊天记录。由于 Photon 适配器不支持该查询，请设置 `threadContext: { maxMessages: 0 }` 跳过这一步。
  </TabItem>

  <TabItem value="linq" label="Linq">
    ```typescript title="src/mastra/agents/imessage-agent.ts"
    import { Agent } from '@mastra/core/agent'
    import { createLinqAdapter } from '@linqapp/chat-sdk-adapter'

    export const imessageAgent = new Agent({
      id: 'imessage-agent',
      name: 'iMessage Agent',
      instructions: 'Answer questions and help with tasks over iMessage.',
      model: '__GATEWAY_OPENAI_MODEL__',
      channels: {
        adapters: {
          imessage: {
            adapter: createLinqAdapter({
              apiKey: process.env.LINQ_API_KEY!,
              signingSecret: process.env.LINQ_WEBHOOK_SECRET!,
            }),
            toolDisplay: 'text',
          },
        },
      },
    })
    ```

    直接向 `createLinqAdapter()` 传入凭据。`apiKey` 是你的 Linq API 密钥，`signingSecret` 来自 [Webhook 订阅](#webhook-url)。Linq 适配器可以获取会话历史，因此可以保留 `threadContext` 的默认行为。
  </TabItem>
</Tabs>

在 Mastra 实例中注册 Agent。

```typescript title="src/mastra/index.ts"
import { Mastra } from '@mastra/core'
import { imessageAgent } from './agents/imessage-agent'

export const mastra = new Mastra({
  agents: { imessageAgent },
})
```

使用 `imessage` 作为适配器的键名。Mastra 根据这个键名生成 Webhook 路径，并设置 `requestContext` 中的 `platform` 值。

iMessage 没有可用于批准或拒绝 Tool 调用的交互式卡片，因此两个适配器都需要设置 `toolDisplay: 'text'`，在消息中用文字说明 Tool 调用。Photon 不支持渲染卡片。Linq 会将卡片转换为纯文本，只显示按钮标签，无法触发对应操作。

:::warning

纯文本消息无法提交审批结果。设置了 `requireApproval: true` 的 Tool 会保持暂停，直到通过界面或 API 明确提交批准或拒绝，例如在 Studio 中操作。只有在其他入口可以处理审批时，才适合为 iMessage Agent 配置此类 Tool。参见 [Tool 审批](/docs/channels#tool-approval)。

:::

## 配置适配器 {/* #adapter-setup */}

<Tabs groupId="imessage-provider">
  <TabItem value="photon" label="Photon">
    参照 [Photon iMessage 适配器文档](https://github.com/photon-hq/vercel-chat-adapter-imessage)完成 iMessage 专用配置，包括开通号码、配置托管或自托管模式，以及注册 Webhook。适配器会根据你设置的环境变量选择模式。

    使用托管服务时，在 [app.photon.codes](https://app.photon.codes) 创建项目，然后用项目凭据设置以下环境变量。

    ```bash title=".env"
    IMESSAGE_PROJECT_ID=your-project-id
    IMESSAGE_PROJECT_SECRET=your-project-secret
    IMESSAGE_WEBHOOK_SECRET=your-webhook-signing-secret
    ```

    使用自托管服务器时，将适配器指向服务器的 gRPC 地址，格式为 `host:port`。适配器会移除 URL 中的协议部分。如果地址只有主机名，则会补上 `:443`。

    ```bash title=".env"
    IMESSAGE_SERVER_URL=imessage.example.com:443
    IMESSAGE_API_KEY=your-server-token
    IMESSAGE_PHONE=+15551234567
    ```

    `IMESSAGE_PHONE` 为可选项，用于在自托管服务器有多个号码时路由消息。也可以直接向 `createiMessageAdapter()` 传入这些值，包括传入 `credentials` 函数，在首次使用时从密钥存储中读取项目 ID 和密钥。
  </TabItem>

  <TabItem value="linq" label="Linq">
    参照 [Linq API 文档](https://docs.linqapp.com/)完成 Linq 专用配置，包括开通电话号码和获取 API 密钥。创建 Linq 账号，复制 API 密钥，然后设置 Agent 配置所读取的凭据。

    ```bash title=".env"
    LINQ_API_KEY=your-linq-api-key
    LINQ_WEBHOOK_SECRET=your-webhook-signing-secret
    ```

    `LINQ_WEBHOOK_SECRET` 是下一节创建 Webhook 订阅时返回的签名密钥。也可以通过适配器的 `baseURL` 选项指定其他 Linq API 基础 URL，例如 Sandbox 环境的地址。
  </TabItem>
</Tabs>

## Webhook URL {/* #webhook-url */}

Mastra 根据 Agent ID 和适配器的键名生成 iMessage Webhook 路由。

```text
/api/agents/imessage-agent/channels/imessage/webhook
```

以 Mastra 服务器的公网 URL 为基础 URL，拼接上述路径。

```text
https://your-app.example.com/api/agents/imessage-agent/channels/imessage/webhook
```

<Tabs groupId="imessage-provider">
  <TabItem value="photon" label="Photon">
    在 [Photon 控制台](https://app.photon.codes)注册此 URL，然后将返回的签名密钥设为 `IMESSAGE_WEBHOOK_SECRET`。密钥只在注册时显示一次。适配器会验证每次投递的签名，并拒绝签名不匹配的请求。仅托管模式支持 Webhook。
  </TabItem>

  <TabItem value="linq" label="Linq">
    创建 [Webhook 订阅](https://docs.linqapp.com/guides/webhooks/subscriptions/)，将此 URL 设为目标地址，并至少订阅以下事件。

    * `message.received`
    * `reaction.added`
    * `reaction.removed`

    将订阅返回的 `signing_secret` 设为 `LINQ_WEBHOOK_SECRET`。密钥只在创建订阅时显示一次，之后无法找回。适配器会验证每次投递的 HMAC 签名，检查是否存在重放请求，并拒绝签名不匹配的请求。
  </TabItem>
</Tabs>

:::note

两个 Provider 都只向公网 HTTPS 端点投递消息，`http://` 和 `localhost` 等私有地址均不受支持。本地开发时，请按[渠道概览](/docs/channels#webhook-routes)中的说明使用隧道。

:::

## 重复投递 {/* #duplicate-deliveries */}

Photon 和 Linq 在投递失败后按退避策略重试，采用至少一次投递机制，因此同一条消息可能重复送达。Chat SDK 通过渠道状态适配器过滤重复消息，Mastra 默认将去重键保存在内存中。这适用于单台持续运行的服务器。

服务器重启后，重复消息仍可能到达 Agent。在无服务器环境中，重试请求被转发到不同实例时也会发生这种情况。通过 `channels.state` 传入共享状态适配器，让各实例都能读取去重键。除了 iMessage 适配器，再安装一个状态适配器。

```bash npm2yarn
npm install @chat-adapter/state-redis
```

`createRedisState()` 读取 `REDIS_URL` 环境变量。

```typescript title="src/mastra/agents/imessage-agent.ts" oxfmt:false
import { createRedisState } from '@chat-adapter/state-redis'

channels: {
  adapters: {
    imessage: {
      adapter: createiMessageAdapter(),
      toolDisplay: 'text',
    },
  },
  state: createRedisState(),
},
```

如果使用会产生副作用的 Tool，去重尤其重要，因为用户会看到同一条消息被处理两次所产生的结果。

## 已读回执 {/* #read-receipts */}

iPhone 上的“信息”应用会为 Agent 发出的每条消息发送已读回执。Photon 适配器会把回执作为既无文本也无附件的入站消息传给 Mastra。Mastra 会跳过这些消息，避免 Agent 反复回复自己。回执的消息 ID 带有 `:read:` 后缀，在 `debug` 级别的日志中会标记为已跳过。

所有适配器都遵循同一规则。既无文本也无附件的入站消息不会触发 Agent 运行。自定义的 `onDirectMessage`、`onMention` 或 `onSubscribedMessage` 处理函数仍会收到这类消息，可以在调用 `defaultHandler` 前处理它们。

## 网关监听器 {/* #gateway-listener */}

在托管和自托管模式下，Photon 适配器都可以通过保持连接来实时接收消息，无需使用 Webhook。Linq 适配器通过 Webhook 接收事件，不提供网关模式。

Mastra 会在初始化时启动网关监听器，并在连接断开时重新连接。服务器持续运行时，无需添加 cron 任务或额外路由。使用 Webhook 时，在适配器配置中设置 `gateway: false` 即可关闭监听器。

```typescript title="src/mastra/agents/imessage-agent.ts" oxfmt:false
imessage: {
  adapter: createiMessageAdapter(),
  toolDisplay: 'text',
  gateway: false,
},
```

在无服务器平台上，建议优先使用 Webhook。网关监听器需要持续运行的进程。参见[无服务器部署](/docs/channels#serverless-deployment)。
