# Slack

Mastra 提供两种 Slack 集成方式。

* **Agent 的 Tool** 让 Agent 在 Slack 中执行操作，例如读取对话或发送消息。
* **与 Agent 聊天**让用户在 Slack 频道的消息串中或通过私信向 Agent 发送消息。Mastra 收到每条消息后都会运行 Agent，并将回复流式传回 Slack。Slack 适配器负责处理 Slack AI 状态指示和交互式卡片。

[Mastra Connect](/docs/mastra-platform/connect) 支持配置这两种集成，并将 Slack 凭据保存在 Mastra 平台上。若要使用聊天功能，也可以自行创建和管理 Slack 应用。

## 使用 Connect {/* #connect */}

开始之前，请按照 [Connect 配置指南](/docs/mastra-platform/connect#get-started)安装 `@mastra/connect` 并配置平台项目。

Slack Tool 和 Slack 聊天各自使用独立的连接和凭据。

* `slack` 为 Agent 的 Tool 授予访问 Slack Workspace 的权限。
* `slack-channels` 保存 Agent 聊天所需的应用配置令牌。

如果两种功能都需要，请分别添加这两个连接。

### 与 Agent 聊天 {/* #agent-chat */}

Slack 聊天使用应用配置令牌，由 Mastra 为每个 Agent 创建并管理一个 Slack 应用。通过[自行配置](#self-managed-setup)等方式创建的 Slack 应用不会用于此流程。

服务器需要一个 Slack 能访问的公网 URL，用于接收 webhook 请求和 OAuth 回调。Mastra 平台会提供这个 URL。如果部署在其他环境，请将 `MASTRA_SERVER_URL` 设为服务器的公网 URL。本地开发时，请使用可从公网访问的 HTTPS 隧道。

1. 打开 [Slack 应用管理页面](https://api.slack.com/apps)，进入 **Your App Configuration Tokens**。

2. 为 Agent 将要运行的 Slack Workspace 生成应用配置令牌。

3. 运行 `mastra connect add slack-channels` 并完成授权。平台会保存并轮换该配置凭据。

4. 将 [`channels()`](/reference/connect/channels) 的返回值传给 `Mastra` 构造函数，以注册 Slack 频道 Provider 及其路由。

   ```typescript title="src/mastra/index.ts"
   import { Mastra } from '@mastra/core'
   import { channels } from '@mastra/connect'
   import { assistant } from './agents/assistant'

   export const mastra = new Mastra({
     agents: { assistant },
     channels: await channels({ providers: ['slack'] }),
   })
   ```

   `channels()` 中的 `slack` 对应 `slack-channels` 连接。

5. 启动 Mastra 应用。

6. 在 Studio 中，将 Slack 频道连接到 Agent。Mastra 会创建 Slack 应用并返回授权 URL。打开该 URL，选择 Slack Workspace，然后授予机器人所请求的权限。

[默认 Slack 应用清单](/reference/channels/slack-provider#default-manifest)列出了所请求的权限范围和订阅的事件。

## 自行配置 Slack 应用 {/* #self-managed-setup */}

如果希望直接管理用于 Agent 聊天的 Slack 应用，请自行创建该应用，并将凭据保存在 Mastra 环境中。

### 安装 {/* #installation */}

安装 Chat SDK 提供的 Slack 适配器。

```bash npm2yarn
npm install @chat-adapter/slack
```

在 Agent 的 `channels.adapters` 对象中添加 `createSlackAdapter()`。

```typescript title="src/mastra/agents/your-agent.ts"
import { Agent } from '@mastra/core/agent'
import { createSlackAdapter } from '@chat-adapter/slack'

export const yourAgent = new Agent({
  id: 'your-agent',
  name: 'Your Agent',
  instructions: 'Help people plan tasks, answer questions, and coordinate work in Slack.',
  model: '__GATEWAY_ANTHROPIC_MODEL_OPUS__',
  channels: {
    adapters: {
      slack: createSlackAdapter(),
    },
  },
})
```

### 创建 Slack 应用 {/* #create-a-slack-app */}

在 Agent 将要运行的 Slack Workspace 中创建应用，即可连接 Agent。应用决定 Agent 在 Slack 中如何显示、可执行哪些操作以及会收到哪些事件。

本指南使用[应用清单](https://docs.slack.dev/app-manifests/configuring-apps-with-app-manifests/#creating_manifests)自动生成 Slack 应用的设置。将 Agent 添加到自己的 Slack Workspace 时，这是最快的方法。本指南不涉及其他 Slack Workspace 安装 Agent 时使用的平台 OAuth 流程。

按以下步骤从清单创建 Slack 应用。

1. 打开 [api.slack.com/apps](https://api.slack.com/apps)。
2. 选择 **Create an app**。
3. 选择 **From a manifest**。
4. 选择 Agent 将要运行的 Slack Workspace。
5. 粘贴下方的清单，然后选择 **Create**。Slack 支持 JSON 和 YAML，请根据创建应用对话框中显示的格式选择相应的标签页。

清单中的主要配置项如下。

* `display_information.name` 和 `features.bot_user.display_name` 设置 Agent 在 Slack 中的名称。名称可以随时修改，修改名称或权限后请重新安装应用。
* `app_home.messages_tab_enabled` 和 `app_home.messages_tab_read_only_enabled` 允许用户从 Slack 应用的 **Messages** 标签页发送私信。
* `always_online` 让 Slack 机器人账号始终显示为在线。
* `oauth_config.scopes.bot` 允许机器人在已加入的频道中发送和读取消息，也包含处理提及、收发私信和查询用户所需的权限。
* `event_subscriptions` 指定 Slack 要发送到 webhook 的消息事件。
* `interactivity` 启用交互式卡片，并指定 Slack 将卡片操作事件发送到哪个地址。

创建应用后，打开 **Install App**，选择 **Install to Workspace**，然后批准应用请求的权限。

### 设置 Slack 凭据 {/* #set-slack-credentials */}

在 Mastra 中设置 Slack 凭据，以便 Mastra 验证来自 Slack 的请求并向 Slack 发送消息。

从 Slack 应用设置中的以下位置复制凭据。

* **Basic Information** > **App Credentials** > **Signing Secret**
* **OAuth & Permissions** > **Bot User OAuth Token**

将复制的值设为 Mastra 环境中的变量。

```bash title=".env"
SLACK_SIGNING_SECRET=your-signing-secret
SLACK_BOT_TOKEN=xoxb-your-bot-token
```

Mastra 会自动读取这些环境变量。

### 配置 webhook 路由 {/* #configure-the-webhook-route */}

Slack 通过 webhook 将频道活动通知 Mastra。出现新消息、提及或用户操作交互式卡片等事件时，Slack 会调用 webhook 对应的 HTTP 端点。

Mastra 会自动为 Agent 注册以下 Slack webhook 路由。

```text
/api/agents/<YOUR-AGENT-ID>/channels/slack/webhook
```

将 Mastra 服务器的公网 URL 与生成的路由拼接起来，得到 webhook URL。

```text
https://<YOUR-PUBLIC-URL>/api/agents/<YOUR-AGENT-ID>/channels/slack/webhook
```

Slack 无法向 `localhost` 发送事件。本地开发时，请保持 Mastra 开发服务器运行，并通过隧道将 `http://localhost:4111` 暴露到公网，再到 Slack 保存请求 URL。

本地开发可以使用 `cloudflared` 或 `ngrok` 建立隧道。

```bash npm2yarn
npx cloudflared tunnel --url http://localhost:4111
```

将 `<YOUR-PUBLIC-URL>` 替换为隧道生成的主机名。以下是一个示例。

```text
https://abc123.trycloudflare.com/api/agents/your-agent/channels/slack/webhook
```

按以下步骤更新 Slack 中的请求 URL。

1. 在 Slack 应用设置中，打开 **Event Subscriptions**。
2. 将 **Request URL** 改为最终的 webhook URL。
3. 选择 **Save Changes**。
4. 打开 **Interactivity & Shortcuts**。
5. 将 **Request URL** 改为同一个 webhook URL。
6. 选择 **Save Changes**。
7. 如果 Slack 提示重新安装应用，请打开 **OAuth & Permissions**，选择 **Reinstall to Workspace**。

### 在 Slack 中测试对话 {/* #try-it-in-slack */}

在 Slack 中打开与机器人的私信对话，然后发送一条消息。应用清单包含 `message.im` 事件订阅和 `im:*` 权限，因此支持私信。

要在频道中使用 Agent，请先邀请 Slack 机器人加入该频道。

```text
/invite @your-bot-name
```

然后在频道中提及机器人。

```text
@your-bot-name What can you help me with?
```

Agent 会在同一个消息串中回复。回复内容取决于为 Agent 配置的模型、指令、记忆和 Tool。

## 身份验证与访问控制 {/* #authentication */}

Slack 适配器没有内置用户白名单。安装应用后，Slack Workspace 中的任何人都可以给 Agent 发私信，或在机器人已加入的频道中提及它。Slack 请求通过签名密钥逐一验证，Mastra 会针对 webhook 收到的每条有效消息运行 Agent。

访问控制主要依靠频道成员关系。机器人只接收私信和受邀加入的频道中的事件，因此用户能否通过频道联系 Agent 取决于机器人是否在该频道中。请只邀请机器人加入允许它回复的频道。要阻止用户通过某个频道访问 Agent，请将机器人移出该频道。

如需更精细地控制访问权限，可以按发送者身份判断。每个请求的频道[请求上下文](#request-context)都包含发送者的 Slack 用户 ID。可以在输入处理器或 Tool 中读取该 ID，在 Agent 执行操作前决定是否允许该用户访问。

### 服务器认证 {/* #server-authentication */}

Slack webhook 路由不受 Mastra [服务器认证](/docs/auth/overview)约束。由于 Slack 无法发送 Bearer 令牌，Mastra 会将频道 webhook 注册为公开路由，并使用 Slack 签名密钥验证每个请求。启用 [`MastraAuthSimple`](/docs/auth/simple-auth) 等认证 Provider 后，其余 API 仍受服务器认证保护，webhook 路由仍使用签名密钥。自行配置 Slack 应用时，请确保已设置 `SLACK_SIGNING_SECRET`，以便适配器拒绝未经 Slack 签名的请求。

### 外部频道 {/* #external-channels */}

[Slack Connect](https://slack.com/connect) 共享频道允许其他 Slack Workspace 的成员加入对话。如果 Slack Workspace 的成员将机器人添加到共享频道，该频道中的所有人都可以与 Agent 对话，包括组织外部的成员。能联系 Agent 的人也能接触它可访问的 Tool 和数据。

将机器人加入共享频道或外部频道，就相当于向这些参与者授予访问 Agent 的权限。添加前，请确认 Agent 可访问的 Tool 和数据可以安全地向外部成员开放。如需限制 Agent 回复哪些人，请按发送者的用户 ID 控制访问。

## 请求上下文 {/* #request-context */}

每收到一条消息，Mastra 都会将频道上下文对象存入[请求上下文](/docs/server/request-context)的 `channel` 键。该对象包含发送者在 Slack 中的显示名称和用户 ID、机器人的身份以及消息来源。可以在输入处理器或 Tool 中读取它，以识别用户或按对话类型执行不同的逻辑。

```typescript title="src/mastra/tools/whoami.ts"
import { createTool } from '@mastra/core/tools'
import type { ChannelContext } from '@mastra/core/channels'
import { z } from 'zod'

export const whoami = createTool({
  id: 'whoami',
  description: 'Return the Slack identity of the current user',
  inputSchema: z.object({}),
  execute: async (_input, context) => {
    const channel = context?.requestContext?.get('channel') as ChannelContext | undefined

    return {
      platform: channel?.platform,
      userId: channel?.userId,
      userName: channel?.userName,
      isDM: channel?.isDM,
    }
  },
})
```

频道上下文包含以下字段。

* `botMention`、`botUserId` 和 `botUserName` 标识机器人在 Slack 中的身份。
* `channelId` 和 `threadId` 标识消息所在的 Slack 频道和消息串。
* `isDM` 表示消息是否为私信。
* `platform` 是平台标识符。此适配器的取值为 `slack`。
* `userId` 和 `userName` 分别是发送者在 Slack 中的用户 ID 和显示名称。

Mastra 还会将这些上下文信息转换为一条简短的系统消息，让 Agent 知道当前平台、自身身份，以及对话发生在私信还是公开频道。要调整这一行为，请参阅频道概览中的[消息串上下文](/docs/channels#thread-context)。

## 生产部署 {/* #production-deployment */}

如果 Slack 应用由你自行管理，请在部署 Mastra 服务器时，将 Slack 应用设置中的两个请求 URL 都改为生产环境的 webhook URL。本地开发用的隧道 URL 是临时的，隧道重启后会变化。

在无服务器平台上运行频道集成时，可能需要配置 `waitUntil` 和共享的发布/订阅机制，以便后台处理回复和消息串租约能在短生命周期实例之间正常运作。请参阅频道概览中的[无服务器部署](/docs/channels#serverless-deployment)。

### 服务器空闲时的行为 {/* #idle-servers */}

平台服务器没有流量时会缩容至空闲状态，Slack 集成仍可正常工作。收到新的提及或私信等事件时，Slack 发送的 webhook 请求会唤醒服务器，让它恢复处理请求。空闲后的首次回复可能因启动而稍慢。Slack 要求在 3 秒内收到 `200` 确认响应，投递失败或超时时最多重试三次，因此冷启动很慢时，Agent 可能要等到 Slack 重试后才能回复。只要服务器保持运行，后续消息就会以正常速度得到回复。
