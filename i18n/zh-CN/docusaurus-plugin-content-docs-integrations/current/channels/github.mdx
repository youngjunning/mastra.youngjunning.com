# GitHub

可以通过两种方式在 Mastra 中使用 GitHub：

- **Agent Tool** 让 Agent 通过 [Mastra Connect](/docs/mastra-platform/connect) 操作仓库、议题、拉取请求、发行版和工作流运行记录。
- **[拉取请求信号](#pull-request-signals)**让 Agent 跟踪拉取请求（PR），并在 PR 发生变化时作出响应。

## 连接 {/* #connect */}

开始前，请按 [Connect 配置指南](/docs/mastra-platform/connect#get-started) 安装 `@mastra/connect` 并配置 Mastra 平台项目。Connect 将 GitHub 凭据保存在 Mastra 平台上，应用本身不存储这些凭据。

## 拉取请求信号 {/* #pull-request-signals */}

`@mastra/github-signals` Provider 轮询已订阅的 PR，并在发生相关活动时向 Agent 的会话线程发送[通知信号](/docs/signals/notifications)。它在你自己的基础设施上运行，通过 GitHub CLI 访问 GitHub，无需建立 Connect 连接。

### 安装 {/* #installation */}

安装 GitHub Signals 和本示例使用的记忆功能相关软件包：

```bash npm2yarn
npm install @mastra/github-signals @mastra/libsql @mastra/memory
```

### 前置条件 {/* #prerequisites */}

使用 GitHub Signals 前，请确认以下条件：

- 使用支持记忆和通知功能的 Mastra 存储适配器。Provider 将订阅保存在会话线程的元数据中，因此必须先创建该线程。
- `PATH` 中有 `gitcrawl` 命令，并且 `gitcrawl` 已配置为可访问要监控的仓库。Provider 会运行 `gitcrawl sync` 并读取其 SQLite 数据库。
- `PATH` 中有 `sqlite3` 命令。
- 已安装 [GitHub CLI](https://cli.github.com/) 并完成身份验证。Provider 根据 `gh api` 的实际响应检查仓库权限和 GitHub App 的所有者，再决定是否通知 Agent。

默认情况下，拥有 `admin`、`maintain` 或 `write` 权限的用户所发的评论可以触发通知。CodeRabbit 和 Devin 机器人的评论也明确获准触发通知。

检查机器人权限时，Provider 先将登录名与 `ignoredBots` 中的条目逐一精确匹配，忽略大小写。未命中忽略名单的机器人满足任一条件即可触发通知：机器人列在 `authorizedBots` 中；GitHub App 所有者是用户，且该用户在仓库中的权限列在 `authorizedPermissions` 中；或 GitHub App 与仓库属于同一组织。默认允许的权限为 `admin`、`maintain` 和 `write`。

如果查询 GitHub App 所有者失败、查询所需信息无法访问、返回结果格式错误或查询不受支持，Provider 会拒绝该机器人的评论。成功的查询结果会缓存 24 小时，失败的结果不缓存。

### Agent 与订阅 {/* #agent-and-subscription */}

创建一个 `GithubSignals` 实例并在 Agent 上注册。然后在 Mastra 实例上注册该 Agent 和一个存储适配器：

```typescript title="src/mastra/index.ts"
import { Agent } from '@mastra/core/agent'
import { Mastra } from '@mastra/core/mastra'
import { Memory } from '@mastra/memory'
import { GithubSignals } from '@mastra/github-signals'
import { LibSQLStore } from '@mastra/libsql'

export const githubSignals = new GithubSignals()

export const devAgent = new Agent({
  id: 'dev-agent',
  name: 'Development Agent',
  instructions: 'Triage pull request activity and help resolve issues.',
  model: '__GATEWAY_OPENAI_MODEL__',
  memory: new Memory(),
  signals: [githubSignals],
})

export const mastra = new Mastra({
  agents: { devAgent },
  storage: new LibSQLStore({
    id: 'mastra-storage',
    url: 'file:./mastra.db',
  }),
})
```

Agent 创建记忆会话线程后，为该线程订阅一个 PR。如果线程只需跟踪代码修订、作者有权限的最新 PR 评论，以及可检测到的评审讨论状态变化，请选择 `review` 模式：

```typescript
await githubSignals.subscribeThreadToPR({
  threadId: 'thread-123',
  resourceId: 'user-123',
  pr: {
    owner: 'acme',
    repo: 'web-app',
    number: 42,
  },
  mode: 'review',
})
```

Provider 会立即同步 PR，保存订阅，并开始每五分钟轮询一次。可在 `GithubSignals` 构造函数中设置 `pollIntervalMs` 来调整轮询间隔。如果进程重启，请为每条已持久化的线程订阅调用 `startPollingForThread()`，以恢复轮询。

每个会话线程同时只能有一个 GitHub Signals 订阅。为同一线程订阅另一个 PR 会替换原有订阅。

### 订阅模式 {/* #subscription-modes */}

GitHub Signals 支持两种订阅模式：

- `review`：跟踪 PR 源分支最新提交的变化、作者有权限的最新 PR 评论，以及可检测到的评审讨论状态变化，包括所有评审讨论均已解决的情况。
- `working`：跟踪 Provider 能检测到且可能触发通知的所有 PR 活动。包含评论内容的通知仍须通过现有权限检查。省略 `mode` 或已保存的订阅没有有效模式时，默认使用此模式。

两种模式对各类 PR 活动的处理如下：

| 拉取请求活动 | `working` | `review` |
| - | - | - |
| 首次获取 PR 状态 | 发送初始状态通知 | 保存所有游标，不发送通知。如果 PR 已关闭或合并，则发送通知并移除订阅 |
| 有新提交或发生强制推送 | 最新评论的作者有权限时发送通知 | 即使没有评论作者也会发送通知 |
| 最新 PR 评论有更新，且作者有权限 | 发送通知 | 发送通知 |
| 检测到评审讨论状态变化 | 仍有未解决的讨论时发送通知 | 发送通知，包括所有评审讨论均已解决时 |
| 持续集成检查启动、失败或恢复 | 发送通知 | 保存新状态，不发送通知 |
| 出现或解决合并冲突 | 发送通知 | 保存新状态，不发送通知 |
| 可触发通知的其他 PR 整体状态变化 | 通过相关权限检查后发送通知 | 保存新状态，不发送通知 |
| PR 未合并即关闭 | 发送通知并保留订阅 | 发送通知并移除订阅 |
| PR 重新打开 | 发送通知 | 不发送通知，因为 PR 关闭时已移除订阅 |
| PR 合并 | 发送通知并移除订阅 | 发送通知并移除订阅 |

评审模式使用 `gitcrawl` 提供的最新 PR 评论。快照不会区分 PR 上的一般讨论和针对代码行的评审评论。评论通知包含评论内容，因此要求评论作者具有相应权限。评审状态通知仅包含 Provider 生成的状态摘要，无需检查作者权限。

评审状态游标记录未解决的评审讨论数量，以及其中最新一条讨论的时间戳。数量降为零时会报告这一变化，但无法报告已解决讨论中的新回复。

如果在订阅时已知 PR 已关闭或合并，Provider 不会保存订阅，也不会发送活动通知。其他情况下，评审模式会保存首份可用且显示 PR 仍处于打开状态的快照，不发送通知。即使订阅时获取快照失败，要到后续轮询才首次取得快照，也会按同样的规则处理。如果首次可用的轮询快照或之后的快照显示 PR 已关闭或合并，Provider 会发送结束通知并移除订阅。若 PR 之后重新打开，需要重新订阅才能继续跟踪。

### 订阅 Tool {/* #subscription-tools */}

Provider 会为 Agent 添加 `github_subscribe_pr` 和 `github_unsubscribe_pr` 两个 Tool。订阅时可传入 `mode`：

```json
{
  "owner": "acme",
  "repo": "web-app",
  "number": 42,
  "mode": "review"
}
```

省略 `mode` 时使用 `working` 模式。如果只需查看一次 PR，无需订阅。

### MastraCode 命令 {/* #mastracode-commands */}

在 MastraCode 中，可以用 PR 编号、`owner/repo#number` 或完整的 GitHub PR URL 指定 PR。`--mode` 选项与其值之间用空格分隔：

```text
/github subscribe 42 --mode review
/github acme/web-app#42 --mode working
/github unsubscribe 42
/github debug
```

MastraCode 不接受 `--mode=review` 写法，也不接受模式值缺失、重复或无法识别的情况。取消订阅时不能使用模式选项。`/github debug` 会显示已保存的模式。旧版订阅中缺失或无效的模式值显示为 `working`。
