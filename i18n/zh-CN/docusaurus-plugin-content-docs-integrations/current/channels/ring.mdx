# Ring

通过 Ring 信号，Mastra Agent 可以接收门铃按下、移动侦测等来自 Ring 门铃和摄像头的事件。每个事件都会以[通知信号](/docs/signals/notifications)的形式进入 Agent 的线程。Agent 可以获取快照或视频片段，查看谁在门口。

事件和媒体均来自 [Ring Partner API](https://developer.amazon.com/docs/ring/api-documentation.html)。此 API 不提供灯光、警报器、门锁或双向通话功能。

## 安装 {/* #installation */}

安装所需的软件包：

```bash npm2yarn
npm install @mastra/ring-signals @mastra/libsql @mastra/memory
```

## 前提条件 {/* #prerequisites */}

使用 Ring 信号需要满足以下条件：

* 一台使用 Ring 付费套餐的 Ring 设备。套餐须包含 **Person, Package & Vehicle Alerts**，这样移动侦测事件才会报告检测到的对象。
* 在 [Ring Developer Console](https://developer.amazon.com/ring/console/apps) 中创建一个 **Private App** 类型的开发者应用，权限范围选 **Cameras and Doorbells**。保存 **Client ID**、**Client Secret** 和 **HMAC Signature Key**。
* 支持通道和通知的 Mastra 存储适配器。已关联的 Ring 账户保存在通道存储中，通知信号使用通知存储。
* 一个可从公网访问的 Mastra 服务器 HTTPS URL。Ring 会调用此服务器来关联账户和投递事件。本地开发时请使用隧道，例如 `npx cloudflared tunnel --url http://localhost:4111`。

将开发者应用的凭据添加到环境变量中：

```bash title=".env"
RING_CLIENT_ID=your-client-id
RING_CLIENT_SECRET=your-client-secret
RING_HMAC_KEY=your-hmac-signature-key
MASTRA_ENCRYPTION_KEY=a-long-random-string
RING_BASE_URL=http://localhost:4111
```

`MASTRA_ENCRYPTION_KEY` 用于加密存储的 Ring 令牌。未设置时，令牌会以未加密的形式保存，系统会记录一条警告。`RING_BASE_URL` 为可选项，用于指定快照和视频片段链接所指向的 Mastra 服务器地址。详见[媒体链接](#media-links)。

## 配置 Agent {/* #agent-configuration */}

将 `new RingSignals()` 添加到 Agent 的 `signals` 数组中：

```typescript title="src/mastra/agents/home-agent.ts"
import { Agent } from '@mastra/core/agent'
import { Memory } from '@mastra/memory'
import { RingSignals } from '@mastra/ring-signals'

export const homeAgent = new Agent({
  id: 'home-agent',
  name: 'Home Agent',
  instructions: 'Watch the front door and say briefly whether each event needs attention.',
  model: '__GATEWAY_OPENAI_MODEL__',
  memory: new Memory(),
  signals: [new RingSignals()],
})
```

默认从环境变量读取 `RING_CLIENT_ID`、`RING_CLIENT_SECRET`、`RING_HMAC_KEY` 和 `RING_BASE_URL`。如需覆盖这些值，请在配置中传入 `clientId`、`clientSecret`、`hmacKey` 和 `baseUrl`。所有选项及其默认值见 [RingSignals 参考文档](/reference/signals/ring-signals)。

在 Mastra 实例中注册 Agent 和存储适配器：

```typescript title="src/mastra/index.ts"
import { Mastra } from '@mastra/core'
import { LibSQLStore } from '@mastra/libsql'
import { homeAgent } from './agents/home-agent'

export const mastra = new Mastra({
  agents: { homeAgent },
  storage: new LibSQLStore({
    id: 'mastra-storage',
    url: 'file:./mastra.db',
  }),
})
```

## 账户关联 {/* #account-linking */}

关联后，Agent 就能接收该 Ring 账户的设备事件。请按以下顺序在两个站点完成设置：

1. 在 Amazon 开发者网站的 [Ring Developer Console](https://developer.amazon.com/ring/console/apps) 中配置开发者应用。
2. 在 [ring.com](https://ring.com) 上将开发者应用关联到拥有该设备的 Ring 账户。

### Ring 开发者控制台 {/* #ring-developer-console */}

Mastra 会自动在服务器的 `/ring` 路径下添加 Ring 所需的路由：

| Ring 设置项 | 路由 | 用途 |
| - | - | - |
| Account Link URL | `GET <server URL>/ring/link` | 完成账户关联并显示结果 |
| Token Exchange URL | `POST <server URL>/ring/token` | 用授权码换取令牌 |
| Webhook URL | `POST <server URL>/ring/webhook` | 投递门铃按下、移动侦测等事件 |
| App Homepage URL | `GET <server URL>/ring/home` | 从 Ring Appstore 的应用页面跳转到应用主页 |

Ring 调用这些路由时无需通过 Mastra 身份验证。Webhook 请求通过 Ring 签名验证，账户关联请求则通过 Ring 提供的关联随机数验证。

令牌路由本身不校验授权码，而是将每个授权码转发给 Ring，由 Ring 拒绝非其签发的授权码。为防止大量请求涌入，请在服务器中间件中对 `/ring/token` 限流。

每个 `RingSignals` 实例都会添加自己的路由。如果多个 Agent 使用 `RingSignals`，请为每个实例分别配置独立的 `routePrefix` 和 Ring 开发者应用。两个实例共用一个前缀时，Mastra 只会注册第一个实例的路由，第二个 Agent 收不到 Ring 事件。

1. 打开开发者应用的 **Account linking** 设置，填入表中的四个 URL。
2. 在 **Connect** 下选择 **Connect Ring account**，登录拥有设备的 Ring 账户。只有在这里连接的账户才能使用该私有开发者应用。

### ring.com {/* #ringcom */}

1. 在网页上登录 Ring 账户。
2. 打开开发者应用在 Ring Appstore 上的页面 `https://ring.com/appstore/<your-app>`。
3. 关联应用。完成后，页面会显示 `Ring account linked`。

已关联的应用会列在 Ring 账户的 [Integrations](https://account.ring.com/account/integrations) 页面，可以在此暂停或移除。

### 关联完成后 {/* #after-linking */}

账户令牌保存在通道存储中，并在过期前刷新。从 Ring 账户的 **Integrations** 中移除开发者应用时，Ring 会发送 `app_integration_removed` 事件，触发删除该账户的令牌。

一个 Agent 可以关联多个 Ring 账户。每个私有开发者应用最多可关联 10 个账户。每台设备都会匹配到拥有它的账户。

### 测试集成 {/* #test-the-integration */}

按下门铃。设备对应的线程会收到一条 `button_press` 通知，Agent 随后会作出响应。在 Studio 中打开该 Agent 即可查看线程，其 ID 与设备 ID 相同。

## 事件与优先级 {/* #events-and-priorities */}

Ring 事件以通知信号的形式投递。默认启用 `button_press`（优先级 `high`）和 `motion_detected`（优先级 `medium`）。所有事件类型及其默认设置见 [RingSignals 参考文档](/reference/signals/ring-signals#events)。

通过 `events` 可以修改默认设置或启用事件。要禁用某类事件，将对应条目设为 `false`：

```typescript
new RingSignals({
  events: {
    motion_detected: {
      priority: 'medium',
      summary: 'Motion was detected at the front door.',
      attributes: event => ({ ...event.data.attributes, location: 'front door' }),
    },
    device_offline: { priority: 'low', summary: 'Device went offline.', coalesce: true },
  },
})
```

Agent 可以读取每条通知的 `deviceId`、`timestamp` 和 `motionType` 属性。可通过 `attributes` 添加自定义属性，例如设备位置。

`coalesce` 将重复事件合并为一条待投递的通知，让[投递策略](/docs/signals/notifications)可以根据收到的事件数量采取相应操作。默认情况下，低优先级通知会批量汇总成一条摘要。

## 线程路由 {/* #thread-routing */}

默认情况下，每台 Ring 设备都有独立的线程。`threadId` 是设备 ID，`resourceId` 是 Agent ID。

可手动设置 `target.resourceId` 和 `target.threadId` 来指定自定义值：

```typescript
new RingSignals({
  target: { resourceId: 'home', threadId: 'ring-alerts' },
})
```

要按事件选择线程，将 `target` 设为函数。该函数接收 Ring 为该事件发送的 Webhook 负载，并返回该事件的路由目标。负载包含以下字段：

* `event.data.type`：事件类型，见[事件与优先级](#events-and-priorities)。
* `event.data.attributes.source`：设备事件取发送事件的设备 ID，应用集成事件取账户 ID，订阅事件取 `subscriptions`。
* `event.data.attributes.timestamp`：设备事件的发生时间，以 Unix 纪元起算的毫秒数表示。订阅事件没有此字段。
* `event.data.attributes.sub_type`：移动侦测事件的触发原因，取值为 `human`、`vehicle`、`package_delivery` 或 `other_motion`。关闭 Smart Alerts 时取 `motion`。订阅事件取 `paid` 或 `trial`。
* `event.meta.account_id`：设备所属的 Ring 账户 ID。

以下示例按活动类型分配线程。人员触发的移动侦测事件进入 `ring-human`，车辆触发的进入 `ring-vehicle`，其余以此类推。门铃按下事件没有 `sub_type`，因此进入 `ring-doorbell`：

```typescript
new RingSignals({
  target: event => {
    const activity = event.data.attributes.sub_type ?? 'doorbell'
    return { resourceId: 'home', threadId: `ring-${activity}` }
  },
})
```

返回 `undefined` 可丢弃该事件。此函数支持声明为 `async`。完整负载类型 `RingWebhookEvent` 见 [RingSignals 参考文档](/reference/signals/ring-signals#ringwebhookevent)。

## 获取快照和视频片段的 Tool {/* #snapshot-and-clip-tools */}

Agent 可以使用两个 Tool：

* `ring_snapshot`：获取事件的静态图像并传给模型，让 Agent 能够描述画面。如果事件刚发生时 Ring 没有可用图像，就使用事件发生前最近的一张。
* `ring_clip`：获取从事件发生时开始的视频片段。Ring 处理录像需要时间，Tool 会重试，直到片段可用。默认不将视频传给模型。详见[将媒体传给模型](#let-the-model-see-media)。

### 将媒体传给模型 {/* #let-the-model-see-media */}

`visibleToModel` 控制 Tool 是否把媒体本身传给模型。大多数模型支持图片，只有少数支持视频，因此 `ring_snapshot` 的默认值为 `true`，`ring_clip` 的默认值为 `false`。如果 Agent 使用支持视频输入的模型，例如 `__GATEWAY_GOOGLE_MODEL_FLASH__`，就可以为视频片段开启此选项：

```typescript
new RingSignals({
  tools: {
    clip: { visibleToModel: true },
  },
})
```

`visibleToModel` 为 `false` 时，模型只会收到 Tool 返回的文本和链接，无法描述媒体中的画面。

:::note

为视频片段开启 `visibleToModel` 前，请确认所用模型支持视频输入。Gemini 模型支持视频输入，Anthropic 和 OpenAI 的模型不支持。Anthropic 会丢弃视频并发出警告，其他模型 API 可能会拒绝请求。

视频的每一秒都会占用模型的上下文窗口。默认 15 秒的片段会消耗几千个 token。`durationMs` 设为上限 15 分钟时，可能消耗数十万个 token，因此让模型处理视频时应将 `durationMs` 设短一些。视频不会保存到 Agent 的记忆中，因此只在获取它的那一步占用上下文。

:::

### 媒体链接 {/* #media-links */}

Ring 不提供可分享的媒体链接。下载快照或视频片段需要 Ring 账户令牌，因此浏览器或聊天应用无法直接从 Ring 下载。设置 `baseUrl` 后，Tool 会返回指向你自己的服务器的签名链接，路径位于 `<baseUrl>/ring/media/` 下。打开链接时，服务器会从 Ring 获取媒体并转发。媒体不会持久化，最近获取的内容只在内存中缓存几分钟。

将 `RING_BASE_URL` 设为 Mastra 服务器的 URL。开发时使用 `http://localhost:4111` 或隧道 URL，生产环境使用部署后的 URL。

如果 `RING_BASE_URL` 和 `baseUrl` 都未设置，Tool 不会返回链接。Agent 仍可看到每张快照，聊天通道仍可收到附件，但应用没有可显示的链接。

### 在聊天通道中发送媒体附件 {/* #attach-media-in-chat-channels */}

如果 Agent 还接入了 iMessage 或 Slack 等[通道](/docs/channels)，用户无法在聊天中直接看到 Tool 的结果。Tool 会把快照和视频片段作为文件附件发送到通道线程，让用户在对话中收到媒体。Studio、网页和 API 的线程直接从 Tool 结果读取媒体，因此不会收到附件。

默认所有通道均支持附件，无需配置。可在各个 Tool 上通过以下选项调整附件行为：

* `attachment`：设为 `false` 可关闭附件。传入平台名称列表（例如 `['imessage', 'slack']`）时，仅在列出的平台上发送附件。
* `maxAttachmentBytes`：附件大小上限，以字节为单位。超出上限的文件不会作为附件发送。

以下示例只在 iMessage 和 Slack 上发送快照附件，并将 Discord 上的视频片段附件限制为 10 MB：

```typescript
new RingSignals({
  tools: {
    snapshot: { attachment: ['imessage', 'slack'] },
    clip: { maxAttachmentBytes: { discord: 10_000_000 } },
  },
})
```

平台名称是 Agent 的 `channels.adapters` 配置中对应适配器的键。以下 Agent 的平台名称为 `imessage` 和 `slack`：

```typescript oxfmt:false
channels: {
  adapters: {
    imessage: { adapter: createiMessageAdapter() },
    slack: { adapter: createSlackAdapter() },
  },
},
```

如果通道所属的平台未列入配置，或文件超过大小上限，Tool 会请 Agent 在回复中分享链接。此行为依赖 `baseUrl` 来生成链接。作为附件发送的文件不会保存到 Agent 的记忆中。

### 将 Ring 提醒发送到聊天中 {/* #send-ring-alerts-to-a-chat */}

要在聊天中接收 Ring 提醒，通道和 Ring 必须使用同一个线程。通过 `resolveResourceId` 和 `resolveThreadId` 为通道线程指定固定的资源 ID 和线程 ID，再将 `target` 设为相同的值。发送第一条消息前，将 `.env` 中的 `HOME_OWNER_USER_ID` 设为你在通道平台上的用户 ID（`message.author.userId`）。只有你发出的私信会进入 Ring 线程。群聊和其他发送者仍使用各自的线程，不会收到 Ring 提醒，但仍可请 Agent 获取 Ring 媒体，详见下方警告：

```typescript title="src/mastra/agents/home-agent.ts"
import { Agent } from '@mastra/core/agent'
import { Memory } from '@mastra/memory'
import { RingSignals } from '@mastra/ring-signals'
import { createiMessageAdapter } from '@photon-ai/chat-adapter-imessage'

const resourceId = 'home'
const threadId = 'ring-alerts'
// Your user ID on the channel platform
const ownerUserId = process.env.HOME_OWNER_USER_ID
if (!ownerUserId) {
  throw new Error('Set HOME_OWNER_USER_ID to your user ID on the channel platform')
}

export const homeAgent = new Agent({
  id: 'home-agent',
  name: 'Home Agent',
  instructions: 'Watch the front door and say briefly whether each event needs attention.',
  model: '__GATEWAY_OPENAI_MODEL__',
  memory: new Memory(),
  channels: {
    resolveResourceId: ({ thread, message, defaultResourceId }) =>
      thread.isDM && message.author.userId === ownerUserId ? resourceId : defaultResourceId,
    resolveThreadId: ctx => (ctx.resourceId === resourceId ? threadId : ctx.defaultThreadId),
    adapters: {
      imessage: { adapter: createiMessageAdapter() },
    },
  },
  signals: [
    new RingSignals({
      target: { resourceId, threadId },
    }),
  ],
})
```

通道收到第一条消息时会创建 `ring-alerts` 线程，后续 Ring 事件也会进入该线程。如果 Ring 事件先到，Ring 会先创建线程。通道无法接管已经存在的线程，因此会另建一个线程。

:::warning

在首个 Ring 事件到达之前，从通道向 Agent 发送一条消息。请使用新对话，因为两个解析函数只在线程创建时运行，添加解析函数之前开启的对话会继续使用原有线程。

任何能通过通道向 Agent 发消息的人，都可以请 Agent 使用 Ring Tool。请限制该平台上能够联系 Agent 的用户。

:::

## 局限性 {/* #limitations */}

* Ring 预期在五秒内收到 Webhook 响应。如果平台会让空闲服务器休眠，休眠后的首个事件可能延迟到达。
* Ring Partner API 无法访问启用端到端加密的设备。
* Ring 会为每张快照和每段视频添加水印。
* 只能获取账户关联后发生的事件所对应的快照和视频片段。
* Studio 会显示 Tool 返回的快照，但无法播放视频片段。请打开 Tool 结果中的视频 URL。
