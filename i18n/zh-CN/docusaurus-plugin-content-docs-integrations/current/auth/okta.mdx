# Okta

`@mastra/auth-okta` 包通过 Okta 为 Mastra 提供身份验证和基于角色的访问控制（RBAC）。它支持使用加密会话 Cookie 的 OAuth 2.0 / OIDC 登录流程，并将 Okta 用户组映射到 Mastra 权限。

## 准备工作 {/* #prerequisites */}

本指南使用 Okta 进行身份验证。请先完成以下准备工作。

1. 在 [okta.com](https://www.okta.com/) 创建 Okta 账号。
2. 在 Okta 管理控制台中配置 OAuth 应用，选择 Web 应用和授权码授权类型（Authorization Code）。
3. 将重定向 URI 添加到应用的登录重定向 URI 列表。
4. 创建 RBAC 所需的 API 令牌。

请确认已设置以下环境变量。

```env title=".env"
OKTA_DOMAIN=dev-123456.okta.com
OKTA_CLIENT_ID=your-client-id
OKTA_CLIENT_SECRET=your-client-secret
OKTA_REDIRECT_URI=http://localhost:4111/api/auth/callback
OKTA_COOKIE_PASSWORD=a-random-string-at-least-32-characters-long
OKTA_API_TOKEN=your-api-token
```

:::note

`OKTA_COOKIE_PASSWORD` 用于加密会话 Cookie。如果未设置，服务器将使用自动生成的值，重启后该值不会保留。请在生产环境中显式设置此变量。

仅当使用 `MastraRBACOkta` 将 Okta 用户组映射到权限时，才需要设置 `OKTA_API_TOKEN`。

:::

## 安装 {/* #installation */}

```bash npm2yarn
npm install @mastra/auth-okta
```

## 使用示例 {/* #usage-examples */}

### 使用环境变量的基本示例 {/* #basic-usage-with-environment-variables */}

设置上述环境变量后，构造函数的所有参数均可省略。

```typescript title="src/mastra/index.ts"
import { Mastra } from '@mastra/core'
import { MastraAuthOkta } from '@mastra/auth-okta'

export const mastra = new Mastra({
  server: {
    auth: new MastraAuthOkta(),
  },
})
```

### 为身份验证配置 RBAC {/* #auth-with-rbac */}

:::note

在生产环境中使用 RBAC 需要 Mastra Enterprise Edition（EE）许可证。开发环境无需许可证即可使用。请参阅[哪些功能需要 EE 许可证](/docs/license#what-requires-an-ee-license)。如需了解更多信息，请[联系销售团队](https://mastra.ai/contact)。

:::

添加 `MastraRBACOkta`，将 Okta 用户组映射到 Mastra 权限。

```typescript title="src/mastra/index.ts"
import { Mastra } from '@mastra/core'
import { MastraAuthOkta, MastraRBACOkta } from '@mastra/auth-okta'

export const mastra = new Mastra({
  server: {
    auth: new MastraAuthOkta(),
    rbac: new MastraRBACOkta({
      roleMapping: {
        Admin: ['*'],
        Engineering: ['agents:*', 'workflows:*', 'tools:*'],
        Viewer: ['agents:read', 'workflows:read'],
        _default: [], // users with unmapped groups get no permissions
      },
    }),
  },
})
```

### 搭配其他身份验证 Provider {/* #cross-provider-usage */}

可以用 Auth0、Clerk 等其他身份验证 Provider 处理登录，并使用 Okta 实施 RBAC。传入 `getUserId` 函数，从负责登录的 Provider 的用户对象中确定对应的 Okta 用户 ID。

```typescript title="src/mastra/index.ts"
import { Mastra } from '@mastra/core'
import { MastraAuthAuth0 } from '@mastra/auth-auth0'
import { MastraRBACOkta } from '@mastra/auth-okta'

export const mastra = new Mastra({
  server: {
    auth: new MastraAuthAuth0(),
    rbac: new MastraRBACOkta({
      getUserId: user => user.metadata?.oktaUserId || user.email,
      roleMapping: {
        Engineering: ['agents:*', 'workflows:*'],
        Admin: ['*'],
        _default: [],
      },
    }),
  },
})
```

:::note

要关联不同 Provider 中的同一用户，请将 Okta 用户 ID 保存在负责登录的 Provider 的用户元数据中。Mastra 会用这个 ID 从 Okta 获取该用户所属的用户组。

:::

完整的配置选项见 [MastraAuthOkta](/reference/auth/okta) 参考文档。

## 角色映射 {/* #role-mapping */}

`roleMapping` 选项将每个 Okta 用户组名称映射到一个 Mastra 权限字符串数组。权限字符串采用 `resource:action` 格式，支持通配符。

```typescript
const rbac = new MastraRBACOkta({
  roleMapping: {
    // full access to everything
    Admin: ['*'],

    // full access to agents and workflows
    Engineering: ['agents:*', 'workflows:*'],

    // read-only access
    Viewer: ['agents:read', 'workflows:read'],

    // users whose groups don't match any key above
    _default: [],
  },
})
```

如果用户所属的 Okta 用户组均未匹配到其他键，则为该用户分配 `_default` 键指定的权限。

## 客户端设置 {/* #client-side-setup */}

启用身份验证后，发往 Mastra 路由的请求必须通过身份验证。`MastraAuthOkta` 使用单点登录（SSO），用户通过 Okta 托管的登录页面验证身份。登录成功后，系统会自动设置加密的会话 Cookie。

### 使用 Cookie 维持会话（推荐） {/* #cookie-session-recommended */}

如果需要发送跨源请求，例如运行在 `:3000` 的前端调用 `:4111` 上的 Mastra，请在 Mastra 服务器的 CORS 配置中允许携带凭据。

```typescript title="src/mastra/index.ts"
import { Mastra } from '@mastra/core'

export const mastra = new Mastra({
  server: {
    auth: new MastraAuthOkta(),
    cors: {
      origin: 'http://localhost:3000',
      credentials: true,
    },
  },
})
```

将客户端配置为随请求发送凭据。

```typescript title="lib/mastra-client.ts"
import { MastraClient } from '@mastra/client-js'

export const mastraClient = new MastraClient({
  baseUrl: 'http://localhost:4111',
  credentials: 'include',
})
```

### Bearer 令牌 {/* #bearer-token */}

也可以将 Okta 令牌作为 Bearer 令牌发送。Mastra 使用 Okta 的 JWKS 端点验证令牌，令牌的 `aud` 声明必须与配置的受众匹配。受众默认为客户端 ID，可通过 `audience` 选项或 `OKTA_AUDIENCE` 覆盖。

Okta 会将客户端 ID 写入 **ID 令牌**的 `aud` 声明，因此 ID 令牌可使用默认受众。**访问令牌**携带的是签发该令牌的授权服务器的受众，请按授权服务器的类型配置相应的值。

* **组织授权服务器**（默认，签发方为 `https://{domain}`）。将受众设为 `https://{domain}`。
* **自定义授权服务器**（签发方为 `https://{domain}/oauth2/{name}`）。将受众设为 Okta 管理控制台中该服务器的受众值，例如 `api://default`。

```env title=".env"
OKTA_AUDIENCE=https://dev-123456.okta.com
```

传入数组即可接受多个受众。例如，可以同时接受浏览器发送的 ID 令牌和服务调用方发送的访问令牌，两类令牌均来自同一个 Provider。

```typescript title="src/mastra/index.ts"
new MastraAuthOkta({
  audience: ['your-client-id', 'https://dev-123456.okta.com'],
})
```

:::note

`audience` 仅适用于 Bearer 令牌。验证 SSO 登录流程中交换的 ID 令牌时，始终使用客户端 ID。

:::

```typescript title="lib/mastra-client.ts"
import { MastraClient } from '@mastra/client-js'

export const createMastraClient = (token: string) => {
  return new MastraClient({
    baseUrl: 'http://localhost:4111',
    headers: {
      Authorization: `Bearer ${token}`,
    },
  })
}
```

更多配置选项见 [Mastra Client SDK](/docs/server/mastra-client) 文档。

## 故障排除 {/* #troubleshooting */}

* **所有请求均返回 401**。确认 Okta 域名、客户端 ID 和客户端密钥正确，并检查 Okta 应用中的重定向 URI 是否与 `OKTA_REDIRECT_URI` 一致。
* **请求返回 401，服务器日志显示 `unexpected "aud" claim value`**。Bearer 令牌的受众与配置的受众不匹配。常见原因是发送了访问令牌，但受众仍是默认的客户端 ID。请将 `OKTA_AUDIENCE` 设为签发该令牌的授权服务器的受众值。参阅 [Bearer 令牌](#bearer-token)。
* **跨源请求未携带 Cookie**。在 `MastraClient` 中设置 `credentials: "include"`，并在 `server.cors` 中配置前端的源及 `credentials: true`。
* **服务器重启后会话丢失**。将 `OKTA_COOKIE_PASSWORD` 设为固定值，长度至少为 32 个字符。如果未设置，服务器每次重启都会使用新生成的密钥。
* **RBAC 返回的权限为空**。确认已设置 `OKTA_API_TOKEN`，且该令牌有权列出用户所属的组。检查 `roleMapping` 中的组名是否与 Okta 中的组名完全一致。
