# Google

`@mastra/auth-google` 软件包通过 Google Workspace 为 Mastra 提供身份验证和基于角色的访问控制（RBAC）。它支持 OAuth 2.0 / OIDC 登录流程，使用加密的会话 Cookie，验证 Google ID 令牌，并将 Google Workspace 群组映射到 Mastra 权限。

如果 Studio 用户通过 Google 登录，且你希望只允许一个或多个 Google Workspace 网域的用户访问，可以使用这个软件包。

## 先决条件 {/* #prerequisites */}

本指南使用 Google Workspace 进行身份验证。开始前，请完成以下准备：

1. 创建或选择 Google Cloud 项目
2. 为 Web 应用程序设置 OAuth 客户端
3. 将 Mastra SSO 回调 URL 添加到已获授权的重定向 URI 列表
4. 如果要使用 RBAC，请配置 Google Workspace 群组

如果通过 Google Groups 实现 RBAC，还需配置启用了全网域委派的 Google Workspace 服务账号，并授予该账号以下用于只读访问群组的 Directory API 权限范围：

```text
https://www.googleapis.com/auth/admin.directory.group.readonly
```

请设置以下环境变量。

```env title=".env"
GOOGLE_CLIENT_ID=your-client-id.apps.googleusercontent.com
GOOGLE_CLIENT_SECRET=your-client-secret
GOOGLE_REDIRECT_URI=http://localhost:4111/api/auth/sso/callback
GOOGLE_COOKIE_PASSWORD=a-random-string-at-least-32-characters-long
GOOGLE_ALLOWED_DOMAINS=example.com

GOOGLE_SERVICE_ACCOUNT_EMAIL=service-account@project.iam.gserviceaccount.com
GOOGLE_SERVICE_ACCOUNT_PRIVATE_KEY="-----BEGIN PRIVATE KEY-----\n...\n-----END PRIVATE KEY-----\n"
GOOGLE_WORKSPACE_ADMIN_EMAIL=admin@example.com
```

:::note[说明]

`GOOGLE_COOKIE_PASSWORD` 用于加密会话 Cookie。未设置时，系统会自动生成一个值，服务器重启后该值不会保留。请在生产环境中显式设置此变量。

`MastraAuthGoogle` 会自动读取 `GOOGLE_*` 身份验证变量。上面列出的服务账号变量由传给 `MastraRBACGoogle` 的配置代码读取。

:::

## 安装 {/* #installation */}

使用 `MastraAuthGoogle` 类之前，请先安装 `@mastra/auth-google` 软件包。

```bash npm2yarn
npm install @mastra/auth-google
```

## 使用示例 {/* #usage-examples */}

### 使用环境变量进行基本配置 {/* #basic-usage-with-environment-variables */}

设置上述环境变量后，可以省略所有构造函数参数：

```typescript title="src/mastra/index.ts"
import { Mastra } from '@mastra/core'
import { MastraAuthGoogle } from '@mastra/auth-google'

export const mastra = new Mastra({
  server: {
    auth: new MastraAuthGoogle(),
  },
})
```

:::warning[警告]

使用 `allowedDomains` 或 `GOOGLE_ALLOWED_DOMAINS` 将访问限制在指定的 Workspace 网域。Mastra 检查 Google 提供且已验证的 `hd` 声明，而不是电子邮件地址的后缀。

:::

### 自定义配置 {/* #custom-configuration */}

如果不想依赖环境变量，可以直接向构造函数传入配置选项：

```typescript title="src/mastra/index.ts"
import { Mastra } from '@mastra/core'
import { MastraAuthGoogle } from '@mastra/auth-google'

export const mastra = new Mastra({
  server: {
    auth: new MastraAuthGoogle({
      clientId: process.env.GOOGLE_CLIENT_ID,
      clientSecret: process.env.GOOGLE_CLIENT_SECRET,
      redirectUri: process.env.GOOGLE_REDIRECT_URI,
      allowedDomains: ['example.com'],
    }),
  },
})
```

### 身份验证与基于 Google Groups 的 RBAC {/* #auth-with-google-groups-rbac */}

:::note[说明]

在生产环境中使用 RBAC 需要 Mastra 企业版（EE）许可证。开发环境无需许可证。请参阅[哪些功能需要 EE 许可证](/docs/license#what-requires-an-ee-license)，或[联系销售团队](https://mastra.ai/contact)了解详情。

:::

添加 `MastraRBACGoogle`，将 Google Workspace 群组映射到 Mastra 权限：

```typescript title="src/mastra/index.ts"
import { Mastra } from '@mastra/core'
import { MastraAuthGoogle, MastraRBACGoogle } from '@mastra/auth-google'

export const mastra = new Mastra({
  server: {
    auth: new MastraAuthGoogle(),
    rbac: new MastraRBACGoogle({
      serviceAccount: {
        clientEmail: process.env.GOOGLE_SERVICE_ACCOUNT_EMAIL!,
        privateKey: process.env.GOOGLE_SERVICE_ACCOUNT_PRIVATE_KEY!,
        subject: process.env.GOOGLE_WORKSPACE_ADMIN_EMAIL!,
      },
      roleMapping: {
        'admins@example.com': ['*'],
        'engineering@example.com': ['agents:*', 'workflows:*', 'tools:*'],
        'viewers@example.com': ['agents:read', 'workflows:read'],
        _default: [], // users with unmapped groups get no permissions
      },
    }),
  },
})
```

### 搭配其他身份验证 Provider {/* #cross-provider-usage */}

可以使用 Auth0、Clerk 等其他身份验证 Provider 处理登录，并使用 Google Workspace 群组实施 RBAC。传入 `getUserKey` 函数，从该 Provider 的用户对象中取得 Google Directory API 所需的用户键：

```typescript title="src/mastra/index.ts"
import { Mastra } from '@mastra/core'
import { MastraAuthAuth0 } from '@mastra/auth-auth0'
import { MastraRBACGoogle } from '@mastra/auth-google'

export const mastra = new Mastra({
  server: {
    auth: new MastraAuthAuth0(),
    rbac: new MastraRBACGoogle({
      getUserKey: user => {
        if (!user || typeof user !== 'object') return undefined

        const { email } = user as { email?: unknown }
        return typeof email === 'string' ? email : undefined
      },
      serviceAccount: {
        clientEmail: process.env.GOOGLE_SERVICE_ACCOUNT_EMAIL!,
        privateKey: process.env.GOOGLE_SERVICE_ACCOUNT_PRIVATE_KEY!,
        subject: process.env.GOOGLE_WORKSPACE_ADMIN_EMAIL!,
      },
      roleMapping: {
        'engineering@example.com': ['agents:*', 'workflows:*'],
        'admins@example.com': ['*'],
        _default: [],
      },
    }),
  },
})
```

有关所有可用的配置选项，请参阅 [MastraAuthGoogle](/reference/auth/google)。

## 角色映射 {/* #role-mapping */}

`roleMapping` 选项将 Google Workspace 群组的电子邮件地址映射到由 Mastra 权限字符串组成的数组。权限采用 `resource:action` 格式，支持通配符：

```typescript
const rbac = new MastraRBACGoogle({
  roleMapping: {
    // full access to everything
    'admins@example.com': ['*'],

    // full access to agents and workflows
    'engineering@example.com': ['agents:*', 'workflows:*'],

    // read-only access
    'viewers@example.com': ['agents:read', 'workflows:read'],

    // users whose groups don't match any key above
    _default: [],
  },
})
```

默认使用群组的电子邮件地址作为角色 ID。若要按群组名称或其他属性映射，请使用 `mapGroupToRoles`。如果用户所属的 Google Workspace 群组均未匹配到其他键，则按 `_default` 键分配权限。

## 客户端设置 {/* #client-side-setup */}

启用身份验证后，发往 Mastra 路由的请求都需要通过身份验证。通过 `GOOGLE_CLIENT_SECRET` 启用 SSO 后，`MastraAuthGoogle` 会使用 Google 登录，并在登录成功后设置加密的会话 Cookie。

### Cookie 会话（推荐） {/* #cookie-session-recommended */}

如果需要发送跨源请求，例如运行在 `:3000` 的前端调用运行在 `:4111` 的 Mastra，请在 Mastra 服务器上启用 CORS 凭据支持：

```typescript title="src/mastra/index.ts"
import { Mastra } from '@mastra/core'

export const mastra = new Mastra({
  server: {
    auth: new MastraAuthGoogle(),
    cors: {
      origin: 'http://localhost:3000',
      credentials: true,
    },
  },
})
```

将客户端配置为随请求发送凭据：

```typescript title="lib/mastra-client.ts"
import { MastraClient } from '@mastra/client-js'

export const mastraClient = new MastraClient({
  baseUrl: 'http://localhost:4111',
  credentials: 'include',
})
```

### Bearer 令牌 {/* #bearer-token */}

也可以将 Google ID 令牌作为 Bearer 令牌发送。Mastra 使用从 Google 的 JSON Web 密钥集（JWKS）端点获取的密钥验证令牌：

```typescript title="lib/mastra-client.ts"
import { MastraClient } from '@mastra/client-js'

export const createMastraClient = (idToken: string) => {
  return new MastraClient({
    baseUrl: 'http://localhost:4111',
    headers: {
      Authorization: `Bearer ${idToken}`,
    },
  })
}
```

有关更多配置选项，请参阅 [Mastra Client SDK](/docs/server/mastra-client)。

## 故障排除 {/* #troubleshooting */}

* **登录后收到 401**：检查 `GOOGLE_CLIENT_ID`、`GOOGLE_CLIENT_SECRET` 和 `GOOGLE_REDIRECT_URI` 是否与 Google Cloud 中的 OAuth 客户端配置一致。
* **Workspace 用户无法访问**：确认 Google ID 令牌中的 `hd` 声明与 `GOOGLE_ALLOWED_DOMAINS` 中的某个网域匹配。
* **个人 Gmail 账号无法访问**：配置 `allowedDomains` 后，这是预期行为，因为个人 Gmail 账号没有 Workspace 的 `hd` 声明。
* **RBAC 返回默认权限**：系统未能解析出该用户的任何角色。请检查用户的电子邮件地址或自定义的 `getUserKey`，以及用户所属的 Google 群组和 `roleMapping`。如果 Directory API 查询失败，Provider 会抛出错误，而不是返回 `_default`。
* **跨源请求未发送 Cookie**：在 `MastraClient` 中设置 `credentials: "include"`，并在 `server.cors` 中指定前端的源并设置 `credentials: true`。
* **服务器重启后会话丢失**：将 `GOOGLE_COOKIE_PASSWORD` 设为至少 32 个字符的固定值。开发环境中未设置此变量时，系统会自动生成密钥，每次重启都会更换。
