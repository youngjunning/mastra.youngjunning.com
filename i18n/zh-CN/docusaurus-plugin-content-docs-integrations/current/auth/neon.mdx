# 氖

这`@mastra/auth-neon`包将 Mastra 连接到[霓虹灯认证](https://neon.com/docs/auth/overview)，基于 Better Auth 构建的托管身份验证服务，可将用户和会话存储在 Neon 数据库中。它验证作为不记名令牌发送的 Neon Auth JWT，验证 Neon Auth 会话 cookie，并让 Studio 用户使用其电子邮件和密码登录或注册。

## 先决条件 {/* #prerequisites */}

在 Neon 项目的分支上启用 Neon Auth[Neon Console](https://console.neon.tech). The **Auth** page shows the Neon Auth URL for that branch. Add it to your `.env` file:

```env title=".env"
NEON_AUTH_BASE_URL=https://ep-example-123456.neonauth.us-east-2.aws.neon.tech/neondb/auth
```

完全按照 Neon 显示的那样使用 URL，包括`/neondb/auth` path. Mastra derives the JWKS endpoint (`<NEON_AUTH_BASE_URL>/.well-known/jwks.json`) and the expected JWT issuer from it.

Neon Auth 仅接受来自受信任来源的登录请求。请求来自`localhost` work while **Allow localhost** is on. Before you deploy, add the domain that serves your Mastra server and Studio to the trusted domains in your Neon Auth settings. Otherwise Neon Auth rejects Studio sign-in with an `Invalid origin` error.

## 安装 {/* #installation */}

安装`@mastra/auth-neon` package:

```bash npm2yarn
npm install @mastra/auth-neon@latest
```

## 使用示例 {/* #usage-example */}

登记`MastraAuthNeon` as the server's auth provider:

```typescript {2,6} title="src/mastra/index.ts"
import { Mastra } from '@mastra/core'
import { MastraAuthNeon } from '@mastra/auth-neon'

export const mastra = new Mastra({
  server: {
    auth: new MastraAuthNeon(),
  },
})
```

`MastraAuthNeon`读`NEON_AUTH_BASE_URL` by default. You can pass `baseUrl` instead.

下每条路线`/api` now requires a Neon Auth credential. The provider accepts either of the following:

* **Neon Auth JWT**在`Authorization: Bearer <token>` header. Mastra verifies its signature against the Neon Auth JWKS, along with its issuer, audience, and expiry.
* **Neon Auth 会话 cookie** (`__Secure-neon-auth.session_token`). Mastra validates it with Neon Auth on each request.

访问[MastraAuthNeon](/reference/auth/neon) for all available configuration options.

## 工作室登录 {/* #studio-sign-in */}

Studio 会在以下情况下显示电子邮件和密码表单：`MastraAuthNeon` is configured. Mastra forwards the credentials to Neon Auth and stores the Neon Auth session cookie in the browser. Users created in Studio appear in your Neon Auth users list, and users created elsewhere in your app can sign in to Studio.

会话cookie已标记`Secure`, so browsers only store it when Studio is served over HTTPS or from `localhost`. Studio served over plain HTTP from another host can't stay signed in.

要仅允许现有用户，请关闭注册。这会隐藏注册表单并拒绝对 Mastra API 的注册请求：

```typescript title="src/mastra/index.ts"
new MastraAuthNeon({
  signUpEnabled: false,
})
```

注销 Studio 会清除其会话 cookie 并尝试撤销 Neon Auth 中的会话。如果 Neon Auth 请求失败，会话可能会保持活动状态。

## 客户端设置 {/* #client-side-setup */}

使用 Neon Auth SDK 的前端可以为登录用户请求短期 JWT 并将其发送到 Mastra。

### 检索 JWT {/* #retrieving-a-jwt */}

对于 Vite 前端，设置`VITE_NEON_AUTH_URL` in the frontend's `.env` file to the same Neon Auth URL used for `NEON_AUTH_BASE_URL` on the Mastra server.

使用`authClient.getSession()` from the [Neon Auth SDK](https://neon.com/docs/reference/javascript-sdk) after the user signs in. The session includes the JWT to send to Mastra:

```typescript title="lib/auth.ts"
import { createAuthClient } from '@neon/neon-js/auth'

export const authClient = createAuthClient(import.meta.env.VITE_NEON_AUTH_URL)

export async function getMastraToken() {
  const { data, error } = await authClient.getSession()
  if (error) throw error
  if (!data?.session) throw new Error('Not signed in to Neon Auth')
  return data.session.token
}
```

Neon Auth JWT 会在 15 分钟后过期。在每批 Mastra 调用之前请求一个新令牌，而不是存储一个。

参观[Neon Auth JWT guide](https://neon.com/docs/auth/guides/plugins/jwt) for cross-origin cookie requirements and other ways to obtain a token.

### 配置`MastraClient` {/* #configuring-mastraclient */}

在中传递 JWT`Authorization` header:

```typescript {6} title="lib/mastra/mastra-client.ts"
import { MastraClient } from '@mastra/client-js'

export const createMastraClient = (token: string) =>
  new MastraClient({
    baseUrl: 'https://<mastra-api-url>',
    headers: { Authorization: `Bearer ${token}` },
  })
```

访问[Mastra Client SDK](/docs/server/mastra-client) for more configuration options.

## 基于角色的访问控制 {/* #role-based-access-control */}

`MastraRBACNeon`从 Neon Auth 映射角色[organization plugin](https://neon.com/docs/auth/guides/plugins/organization) (`owner`, `admin`, and `member`) to Mastra permissions. Roles that aren't in `roleMapping` get the `_default` permissions:

```typescript {2,7-14} title="src/mastra/index.ts"
import { Mastra } from '@mastra/core'
import { MastraAuthNeon, MastraRBACNeon } from '@mastra/auth-neon'

export const mastra = new Mastra({
  server: {
    auth: new MastraAuthNeon(),
    rbac: new MastraRBACNeon({
      roleMapping: {
        owner: ['*'],
        admin: ['*'],
        member: ['agents:read', 'agents:execute', 'workflows:read'],
        _default: [],
      },
    }),
  },
})
```

对于会话 cookie 请求，Mastra 从 Neon Auth 读取用户在会话活动组织中的角色。放`organizationId` to always use one organization. Users who aren't members of that organization have no roles, so they get no permissions. Users without an active organization get their Neon Auth user role (for example, `user` or `admin`).

Neon Auth JWT 不包括组织角色。他们的`role` claim is always `authenticated`, which is the Postgres role for the Neon Data API, and Mastra ignores it. Bearer JWT requests therefore have no roles and get no permissions unless you resolve roles yourself with `getUserRoles`:

```typescript title="src/mastra/index.ts"
new MastraRBACNeon({
  roleMapping: { admin: ['*'], member: ['agents:read'], _default: [] },
  getUserRoles: async user => lookUpRolesInYourDatabase(user.id),
})
```

：：：笔记

RBAC 在生产中需要 Mastra Enterprise Edition (EE) 许可证。它在开发过程中无需许可证即可运行。看[what requires an EE license](/docs/license#what-requires-an-ee-license).

## 验证设置 {/* #verify-the-setup */}

启动 Mastra 服务器并在没有凭据的情况下调用受保护的路由：

```bash
curl -i http://localhost:4111/api/agents
```

响应是`401 Unauthorized`. Repeat the request with a Neon Auth JWT in the `Authorization: Bearer <token>` header to get `200 OK` with your agents. In Studio at `http://localhost:4111`, the sign-in form accepts the email and password of any Neon Auth user.
