# Neon

`@mastra/auth-neon` 包将 Mastra 接入 [Neon Auth](https://neon.com/docs/auth/overview)。Neon Auth 是基于 Better Auth 构建的托管身份验证服务，将用户和会话存储在你的 Neon 数据库中。该包会验证作为 Bearer 令牌发送的 Neon Auth JWT 和 Neon Auth 会话 Cookie，并让 Studio 用户通过邮箱和密码登录或注册。

## 先决条件 {/* #prerequisites */}

在 [Neon 控制台](https://console.neon.tech)中为 Neon 项目的一个分支启用 Neon Auth。**Auth** 页面会显示该分支的 Neon Auth URL。将该 URL 添加到 `.env` 文件中：

```env title=".env"
NEON_AUTH_BASE_URL=https://ep-example-123456.neonauth.us-east-2.aws.neon.tech/neondb/auth
```

请原样使用 Neon 显示的 URL，保留 `/neondb/auth` 路径。Mastra 会根据此 URL 确定 JWKS 端点（`<NEON_AUTH_BASE_URL>/.well-known/jwks.json`）和预期的 JWT 签发者。

Neon Auth 只接受来自受信任来源的登录请求。启用 **Allow localhost** 后，Neon Auth 会接受来自 `localhost` 的请求。部署前，请在 Neon Auth 设置中将 Mastra 服务器和 Studio 使用的域名加入受信任域名列表，否则 Neon Auth 会拒绝 Studio 登录并返回 `Invalid origin` 错误。

## 安装 {/* #installation */}

安装 `@mastra/auth-neon` 包：

```bash npm2yarn
npm install @mastra/auth-neon@latest
```

## 使用示例 {/* #usage-example */}

将 `MastraAuthNeon` 注册为服务器的身份验证 Provider：

```typescript {2,6} title="src/mastra/index.ts"
import { Mastra } from '@mastra/core'
import { MastraAuthNeon } from '@mastra/auth-neon'

export const mastra = new Mastra({
  server: {
    auth: new MastraAuthNeon(),
  },
})
```

`MastraAuthNeon` 默认读取 `NEON_AUTH_BASE_URL`。也可以直接传入 `baseUrl`。

完成配置后，访问 `/api` 下的每条路由都需要 Neon Auth 凭据。该 Provider 接受以下任一种凭据：

* **Neon Auth JWT**，通过 `Authorization: Bearer <token>` 请求头发送。Mastra 使用 Neon Auth 的 JWKS 验证签名，并检查签发者、受众和过期时间。
* **Neon Auth 会话 Cookie**（`__Secure-neon-auth.session_token`）。Mastra 会在每次请求时通过 Neon Auth 验证该 Cookie。

所有可用的配置选项见 [MastraAuthNeon](/reference/auth/neon)。

## 登录 Studio {/* #studio-sign-in */}

配置 `MastraAuthNeon` 后，Studio 会显示一个用于输入邮箱和密码的表单。Mastra 会将凭据转发给 Neon Auth，并将 Neon Auth 会话 Cookie 保存在浏览器中。在 Studio 中创建的用户会出现在 Neon Auth 的用户列表中，在应用其他地方创建的用户也可以登录 Studio。

会话 Cookie 带有 `Secure` 标记，因此只有通过 HTTPS 或从 `localhost` 访问 Studio 时，浏览器才会保存它。通过其他主机上的普通 HTTP 访问 Studio 时，无法保持登录状态。

如果只允许已有用户登录，请关闭注册。这样会隐藏注册表单，并拒绝发往 Mastra API 的注册请求：

```typescript title="src/mastra/index.ts"
new MastraAuthNeon({
  signUpEnabled: false,
})
```

退出 Studio 登录时，Mastra 会清除 Studio 的会话 Cookie，并尝试撤销 Neon Auth 中的会话。如果发往 Neon Auth 的请求失败，该会话可能仍然有效。

## 客户端设置 {/* #client-side-setup */}

使用 Neon Auth SDK 的前端可以为已登录的用户获取短期有效的 JWT，并将其发送给 Mastra。

### 获取 JWT {/* #retrieving-a-jwt */}

如果前端使用 Vite，请在前端的 `.env` 文件中将 `VITE_NEON_AUTH_URL` 设为与 Mastra 服务器上的 `NEON_AUTH_BASE_URL` 相同的 Neon Auth URL。

用户登录后，调用 [Neon Auth SDK](https://neon.com/docs/reference/javascript-sdk) 的 `authClient.getSession()`。返回的会话包含要发送给 Mastra 的 JWT：

```typescript title="lib/auth.ts"
import { createAuthClient } from '@neon/neon-js/auth'

export const authClient = createAuthClient(import.meta.env.VITE_NEON_AUTH_URL)

export async function getMastraToken() {
  const { data, error } = await authClient.getSession()
  if (error) throw error
  if (!data?.session) throw new Error('Not signed in to Neon Auth')
  return data.session.token
}
```

Neon Auth JWT 会在 15 分钟后过期。请在每批 Mastra 调用前重新获取令牌，无需保存令牌供后续批次复用。

:::note

跨源 Cookie 的要求及获取令牌的其他方式见 [Neon Auth JWT 指南](https://neon.com/docs/auth/guides/plugins/jwt)。

:::

### 配置 `MastraClient` {/* #configuring-mastraclient */}

通过 `Authorization` 请求头传递 JWT：

```typescript {6} title="lib/mastra/mastra-client.ts"
import { MastraClient } from '@mastra/client-js'

export const createMastraClient = (token: string) =>
  new MastraClient({
    baseUrl: 'https://<mastra-api-url>',
    headers: { Authorization: `Bearer ${token}` },
  })
```

更多配置选项见 [Mastra Client SDK](/docs/server/mastra-client)。

## 基于角色的访问控制 {/* #role-based-access-control */}

`MastraRBACNeon` 将 Neon Auth [组织插件](https://neon.com/docs/auth/guides/plugins/organization)的角色（`owner`、`admin` 和 `member`）映射到 Mastra 权限。未列在 `roleMapping` 中的角色使用 `_default` 权限：

```typescript {2,7-14} title="src/mastra/index.ts"
import { Mastra } from '@mastra/core'
import { MastraAuthNeon, MastraRBACNeon } from '@mastra/auth-neon'

export const mastra = new Mastra({
  server: {
    auth: new MastraAuthNeon(),
    rbac: new MastraRBACNeon({
      roleMapping: {
        owner: ['*'],
        admin: ['*'],
        member: ['agents:read', 'agents:execute', 'workflows:read'],
        _default: [],
      },
    }),
  },
})
```

收到携带会话 Cookie 的请求时，Mastra 会从 Neon Auth 读取用户在当前会话所选组织中的角色。设置 `organizationId` 可以固定使用同一个组织。非该组织成员的用户没有角色，因此也没有权限。对于未选择活动组织的用户，Mastra 使用其 Neon Auth 用户角色（例如 `user` 或 `admin`）。

Neon Auth JWT 不包含组织角色。其 `role` 声明始终为 Neon Data API 使用的 Postgres 角色 `authenticated`，Mastra 会忽略该声明。因此，携带 Bearer JWT 的请求默认没有角色，也没有权限。要为这类请求分配权限，请通过 `getUserRoles` 自行查找用户角色：

```typescript title="src/mastra/index.ts"
new MastraRBACNeon({
  roleMapping: { admin: ['*'], member: ['agents:read'], _default: [] },
  getUserRoles: async user => lookUpRolesInYourDatabase(user.id),
})
```

:::note

在生产环境中使用 RBAC 需要 Mastra Enterprise Edition (EE) 许可证。在开发环境中可以直接使用。详情见[哪些功能需要 EE 许可证](/docs/license#what-requires-an-ee-license)。

:::

## 验证设置 {/* #verify-the-setup */}

启动 Mastra 服务器，向受保护的路由发送不带凭据的请求：

```bash
curl -i http://localhost:4111/api/agents
```

服务器会返回 `401 Unauthorized`。在 `Authorization: Bearer <token>` 请求头中携带 Neon Auth JWT 后重新发送请求，服务器会返回 `200 OK` 和你的 Agent 列表。打开 `http://localhost:4111` 上的 Studio，可以在登录表单中使用任一 Neon Auth 用户的邮箱和密码登录。
