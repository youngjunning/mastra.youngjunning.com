# Agent 类

`Agent` 类是在 Mastra 中创建 AI Agent 的基础，提供生成响应、流式交互和语音功能。

## 使用示例 {/* #usage-examples */}

### 基本字符串指令 {/* #basic-string-instructions */}

传入字符串或字符串数组作为指令，是配置 Agent 最简单的方式。适用于只需提供提示词、无需额外配置的场景。

```typescript title="src/mastra/agents/string-agent.ts"
import { Agent } from '@mastra/core/agent'

// String instructions
export const agent = new Agent({
  id: 'test-agent',
  name: 'Test Agent',
  // highlight-next-line
  instructions: 'You are a helpful assistant that provides concise answers.',
  model: '__GATEWAY_OPENAI_MODEL__',
})

// System message object
export const agent2 = new Agent({
  id: 'test-agent-2',
  name: 'Test Agent 2',
  // highlight-start
  instructions: {
    role: 'system',
    content: 'You are an expert programmer',
  },
  // highlight-end
  model: '__GATEWAY_OPENAI_MODEL__',
})

// Array of system messages
export const agent3 = new Agent({
  id: 'test-agent-3',
  name: 'Test Agent 3',
  // highlight-start
  instructions: [
    { role: 'system', content: 'You are a helpful assistant' },
    { role: 'system', content: 'You have expertise in TypeScript' },
  ],
  // highlight-end
  model: '__GATEWAY_OPENAI_MODEL__',
})
```

### Provider 专属配置 {/* #provider-specific-configurations */}

各模型 Provider 还提供提示词缓存、推理设置等选项。可以在指令级别设置 `providerOptions`，为不同的 system 指令或提示词指定不同的缓存策略。

```typescript title="src/mastra/agents/core-message-agent.ts"
import { Agent } from '@mastra/core/agent'

export const agent = new Agent({
  id: 'core-message-agent',
  name: 'Core Message Agent',
  instructions: {
    role: 'system',
    content: 'You are a helpful assistant specialized in technical documentation.',
    // highlight-start
    providerOptions: {
      openai: {
        reasoningEffort: 'low',
      },
    },
    // highlight-end
  },
  model: '__GATEWAY_OPENAI_MODEL__',
})
```

### 混合指令格式 {/* #mixed-instruction-formats */}

```typescript title="src/mastra/agents/multi-message-agent.ts"
import { Agent } from '@mastra/core/agent'

// This could be customizable based on the user
const preferredTone = {
  role: 'system',
  content: 'Always maintain a professional and empathetic tone.',
}

export const agent = new Agent({
  id: 'multi-message-agent',
  name: 'Multi Message Agent',
  instructions: [
    { role: 'system', content: 'You are a customer service representative.' },
    preferredTone,
    {
      role: 'system',
      content: 'Escalate complex issues to human agents when needed.',
      providerOptions: {
        anthropic: { cacheControl: { type: 'ephemeral' } },
      },
    },
  ],
  model: '__GATEWAY_ANTHROPIC_MODEL_SONNET__',
})
```

## 模型字符串 {/* #model-strings */}

最简单的配置方式是将 `model` 设为 `provider/model` 格式的字符串，使用斜杠分隔 Provider 和模型名称。Mastra 会从环境变量中读取对应 Provider 的凭据，因此无需额外安装或导入 Provider 包。

常用的 Provider 字符串及凭据：

* **OpenAI**：`__GATEWAY_OPENAI_MODEL__` 使用 `OPENAI_API_KEY`。
* **Anthropic**：`__GATEWAY_ANTHROPIC_MODEL_SONNET__` 使用 `ANTHROPIC_API_KEY`。
* **Google**：`__GATEWAY_GOOGLE_MODEL_FLASH__` 使用 `GOOGLE_API_KEY` 或 `GOOGLE_GENERATIVE_AI_API_KEY`。

支持的模型 ID 参阅[模型列表](/models)；完整的 Provider 列表参阅[环境变量](/models/environment-variables)。

## Thread 信号 {/* #thread-signals */}

使用 Agent 信号将实时输入和上下文发送到 memory thread。消息 API 处理用户编写的输入；`sendSignal()` 是用于系统生成上下文的更底层 API。

目标 thread 正在运行时，`sendMessage()` 会将消息交给当前 Agent 循环。thread 空闲时，Mastra 默认会以该消息作为首条输入启动 stream。

```typescript title="src/mastra/signals.ts"
const subscription = await agent.subscribeToThread({
  resourceId: 'user-123',
  threadId: 'thread-abc',
})

void (async () => {
  for await (const chunk of subscription.stream) {
    console.log(chunk)
  }
})()

agent.sendMessage('Use the latest customer note too.', {
  resourceId: 'user-123',
  threadId: 'thread-abc',
  ifIdle: {
    streamOptions: {
      maxSteps: 3,
    },
  },
})
```

可用 `attributes` 标识共享 thread 中的不同用户。这些属性会渲染为 XML，让模型区分各条消息的发送者：

```typescript
agent.sendMessage(
  {
    contents: 'Can we simplify the API surface?',
    attributes: { name: 'Devin', from: 'slack' },
  },
  { resourceId: 'user-123', threadId: 'thread-abc' },
)
```

模型收到的内容如下：

```xml
<user name="Devin" from="slack">Can we simplify the API surface?</user>
```

如果消息需要根据 thread 是否正在运行携带不同的上下文，请使用 `ifActive.attributes` 和 `ifIdle.attributes`：

```typescript title="src/mastra/signals.ts"
agent.sendMessage(
  {
    contents: 'Also cover the edge cases.',
    attributes: { source: 'chat' },
  },
  {
    resourceId: 'user-123',
    threadId: 'thread-abc',
    ifActive: { attributes: { delivery: 'while-active' } },
    ifIdle: { attributes: { delivery: 'new-message' } },
  },
)
```

thread 正在运行时，模型看到：

```xml
<user source="chat" delivery="while-active">Also cover the edge cases.</user>
```

thread 空闲时，模型看到：

```xml
<user source="chat" delivery="new-message">Also cover the edge cases.</user>
```

UI 可以看到消息内容，也可以从信号消息中读取 `attributes` 和 `metadata` 以自定义呈现，例如显示用户名、头像或平台标识。

```typescript title="src/mastra/signals.ts"
    streamOptions: {
      maxSteps: 3,
    },
  },
})
```

返回 `{ accepted: Promise<SendAgentSignalAccepted>, signal: CreatedAgentSignal, persisted?: Promise<void> }`。`accepted` 在 Mastra 决定如何处理消息时解析：本进程运行 Agent（自行启动或赢得启动 lease）时为 `{ action: 'wake', runId, output }`；消息转发给现有运行（包括本进程输掉跨进程唤醒竞争）时为 `{ action: 'deliver', runId }`；没有运行启动时为 `{ action: 'persist' }` 或 `{ action: 'discard' }`。`runId` 是处理该消息的运行的权威 ID，仅在 `wake` 和 `deliver` 时存在。对于 `persist`/`discard`，可用 `result.signal.id` 关联已保存的消息。`accepted` 表示路由决策完成：`wake` 运行中的生成错误会通过 `output.consumeStream()` 暴露；只有消息完全无法路由或启动时（例如 Agent 配置错误）才会拒绝。`persisted` 仅在 `persist` 行为下存在，并在 Mastra 将消息写入 memory 后解析。`wake` 时，`output` 是可在进程内消费的 Agent stream。

### `queueMessage(message, options)` {/* #queuemessagemessage-options */}

将用户消息排队，供 thread 的下一轮处理。如果 thread 正在运行，Mastra 会等待当前运行结束，再用排队消息启动新运行；如果 thread 空闲，则立即启动运行。

```typescript
agent.queueMessage('Also check whether the tests need updates.', {
  resourceId: 'user-123',
  threadId: 'thread-abc',
})
```

`queueMessage()` 接收与 `sendMessage()` 结构相同的 `message` 和 `options`，并返回 `{ accepted: Promise<SendAgentSignalAccepted>, signal: CreatedAgentSignal, persisted?: Promise<void> }`；`accepted` 的语义也与 `sendMessage()` 相同。可传入可选的 `queueOwnerId`，对本地排队消息分组，以便观察和取消。owner ID 是本地元数据：不会随消息序列化，也不是授权机制。

使用 [`subscribeThreadEvents({ resourceId, threadId }, listener)`](/reference/signals/thread-events) 观察共享 thread 中本地待处理的消息。当前 listener 只接收 `queue-count-changed` 事件。订阅选项、计数语义、取消订阅行为及按 owner 范围观察的方式，参阅 [Thread 事件参考](/reference/signals/thread-events)。

### `queueSignal(signal, options)` {/* #queuesignalsignal-options */}

将带类型的信号排队，供 thread 的下一轮处理。其行为与 `queueMessage()` 相同，但可接收任意信号输入，并为排队的运行保留 `type`、`tagName` 和 `attributes`。

```typescript
agent.queueSignal(
  {
    type: 'reactive',
    tagName: 'skill',
    attributes: { name: 'triage' },
    contents: 'Triage the new issue.',
  },
  { resourceId: 'user-123', threadId: 'thread-abc' },
)
```

`queueSignal()` 接收与 `queueMessage()` 相同的 `options`（包括 `queueOwnerId`），并返回相同结构的结果。排队信号与 `queueMessage()` 共用队列，因此计入队列计数事件，也可以由 `cancelQueuedMessages()` 取消。

### `cancelQueuedMessages(options)` {/* #cancelqueuedmessagesoptions */}

取消待处理的输入，但不中止正在运行的任务。必须且只能提供一个选择条件：

* `signalIds` 取消同一 runtime 和 memory thread 上多个 Agent 的指定输入。包括等待运行准备的信号、当前运行中待处理的信号，以及等待后续运行的排队消息。
* `queueOwnerId` 只取消调用方 Agent 中属于该 owner 组的 `queueMessage()` 和 `queueSignal()` 条目，不影响其他 Agent 的输入或其他队列中的信号。

```typescript
const { cancelledSignalIds } = agent.cancelQueuedMessages({
  resourceId: 'user-123',
  threadId: 'thread-abc',
  signalIds: ['signal-123', 'signal-456'],
})
```

返回 `{ cancelledSignalIds: string[] }`，每个实际被此次调用取消的 ID 只出现一次。空数组表示选定信号中没有仍在本地待处理的项。等待获取或转移 lease 的信号仍可取消；一旦开始执行或转发，本地副本便不能再取消。

对于 `signalIds`，即使本地没有待处理项，Mastra 也会通过 PubSub 发布所有请求取消的 ID。订阅该 thread 的其他进程会取消匹配的待处理输入，包括等待 lease 的信号。传播是尽力而为且异步进行的，没有远端确认，因此本地结果为空并不表示其他进程中请求取消的信号仍在排队。按 owner 组取消只影响调用方 Agent 的本地队列。来自 `continueWithMessages()` 的后续执行、已保存的消息、state 更新及通知记录均不受影响。已完成的 accepted 确认也不会改变。

在 serverless 处理程序中，等待 `accepted` 解析，并将 `wake` 结果中的 output 交给平台对应的 `waitUntil` 机制，让赢得执行权的进程在 HTTP 响应返回后继续消费 stream。

```typescript
const result = agent.sendSignal(signal, { resourceId, threadId })
ctx.waitUntil(
  result.accepted.then(async accepted => {
    if (accepted.action === 'wake') {
      await accepted.output.consumeStream()
    }
  }),
)
```

### `sendStateSignal(state, options)` {/* #sendstatesignalstate-options */}

将带名称、属于指定 thread 的 state 上下文发送给正在运行的任务或 memory thread。适用于外部生产方维护会随时间变化的持久上下文，例如浏览器状态、编辑器状态或监视器输出。

```typescript
const result = await agent.sendStateSignal(

    mode: 'snapshot',
    cacheKey: 'browser:https://example.com:3-tabs',
    contents: 'Browser is open. Active tab URL: https://example.com. 3 open tabs.',
    value: {
      activeUrl: 'https://example.com',
      tabCount: 3,
      open: true,
    },
  },
  {
    resourceId: 'user-123',
    threadId: 'thread-abc',
  },
)
```

```typescript title="src/mastra/agents/support-agent.ts"
import { Agent } from '@mastra/core/agent'

export const supportAgent = new Agent({
  id: 'support-agent',
  name: 'Support Agent',
  instructions: 'Help the user triage updates.',
  model: '__GATEWAY_OPENAI_MODEL__',
  notifications: {
    deliveryPolicy: {
      priorities: {
        urgent: 'deliver',
      },
      decide: ({ record }) => {
        if (record.priority === 'low') {
          return {
            action: 'summarize',
            summaryAt: new Date(Date.now() + 30 * 60 * 1000),
          }
        }
      },
    },
  },
})
```

要呈现 thread 且不重放已完成的运行，请请求初始历史记录。第一个数据块包含已保存的消息：

```ts
const subscription = await agent.subscribeToThread({
  threadId: 'thread-abc',
  withInitialHistory: true,
})
for await (const chunk of subscription.stream) {
  if (chunk.type === 'thread-history') render(chunk.payload.messages)
  else handle(chunk)
}
```

`thread-history` 数据块包含最近的 `perPage` 条消息、`hasMore` 标志，以及 `activeRunId`（当前运行的 ID；空闲时为 `null`）。设置 `withRunStatus: true` 可接收[运行结果](/reference/streaming/ChunkType#thread-run-status)，包括每个仍保留的已完成运行的结果。只有请求相应选项时，这两类数据块才会加入推断出的订阅 stream 类型。数据结构参阅 [Thread 订阅数据块](/reference/streaming/ChunkType#thread-history)。

排除设置不会改变模型上下文、存储、共享广播或其他调用方的输出。它不是安全边界，也不能代替 `ifActive`/`ifIdle` 投递策略或 `transient` 持久化行为。此选项仅由进程内的 core API 支持，不适用于 HTTP 或 client-js 订阅请求。转换顺序，以及它与 recall 按已保存的精确类型匹配、历史记录默认隐藏提醒的区别，参阅 [stream 信号可见性](/reference/streaming/agents/stream#signal-visibility)。

## `generate()` 的 memory 选项 {/* #generate-memory-options */}

调用 `agent.generate()` 时传入 `memory`，可指定此次运行要读取和写入的对话 thread。常见结构是 `memory: { resource: string, thread: string }`：`resource` 标识所有者，`thread` 标识对话。概念说明参阅 [Thread 和 resource](/docs/memory/message-history#threads-and-resources)。

```typescript title="src/mastra/run.ts"
const response = await agent.generate('What did we decide about retries?', {
  memory: {
    resource: 'user-123',
    thread: 'support-thread-456',
  },
})
```

如果需要在调用期间创建或更新 thread 元数据，请使用 thread 对象：

```typescript title="src/mastra/run.ts"
const response = await agent.generate('Continue the support conversation.', {
  memory: {
    resource: 'user-123',
    thread: {
      id: 'support-thread-456',
      title: 'Billing support',
      metadata: { category: 'billing' },
    },
  },
})
```

## Tool hook {/* #tool-hooks */}

使用 `hooks`，可在 Agent 的每次 Tool 调用前后运行逻辑，包括分配给 Agent 的 Tool、memory Tool、Toolset、客户端 Tool 和 workspace Tool。

```typescript title="src/mastra/agents/hooked-agent.ts"
import { Agent } from '@mastra/core/agent'

export const agent = new Agent({
  id: 'support-agent',
  name: 'support-agent',
  instructions: 'Help users with their questions.',
  model: '__GATEWAY_OPENAI_MODEL__',
  // highlight-start
  hooks: {
    beforeToolCall: ({ toolName, input }) => {
      console.log(`Running ${toolName}`, input)
    },
    afterToolCall: ({ toolName, output, error }) => {
      console.log(`Finished ${toolName}`, { output, error })
    },
  },
  // highlight-end
})
```

`beforeToolCall` 可以通过返回 `{ proceed: false, output }` 跳过 Tool 调用。Agent 不会执行 Tool，而是将 `output` 用作 Tool 结果：

```typescript
const result = await agent.generate('Clean up old records', {
  hooks: {
    beforeToolCall: ({ toolName }) => {
      if (toolName === 'deleteRecord') {
        return { proceed: false, output: { blocked: true } }
      }
    },
  },
})
```

hook 上下文的 `metadata` 包含 `agentId` 和 `agentName`。传给 `generate()` 或 `stream()` 的执行专用 hook 会覆盖 Agent 级别的同名 hook。如果 [workspace](/reference/workspace/workspace-class) 也定义了 `tools.hooks`，workspace hook 会在 Agent hook 包装器内部运行。

## Editor 覆盖设置 {/* #editor-overrides */}

注册 [`MastraEditor`](/reference/editor/mastra-editor) 后，`editor` 字段控制 Agent 的哪些部分由代码定义、哪些由 Studio 管理。代码管理的字段在 Studio 中只读，保存覆盖设置时会被移除。Studio 管理的字段必须从代码中省略。Agent 会从已保存的覆盖设置读取这些字段；缺少字段时会拒绝运行。

<PropertiesTable
  content={[
{
  name: 'editor',
  type: 'false | { instructions?: boolean; tools?: boolean | { description?: boolean }; model?: boolean }',
  isOptional: true,
  description:
    '省略时允许编辑指令和 Tool，代码中的值用作默认值。设为 `false` 可锁定 Agent。设为 `instructions: true` 可将指令交由 Studio 管理，此时应从代码中删除 `instructions`。设为 `tools: true` 可将 Tool 成员及描述交由 Studio 管理，此时应从代码中删除 `tools`。设为 `tools: { description: true }` 可由代码管理 Tool 成员，同时仅允许编辑描述。设为 `model: true` 可允许编辑静态模型回退列表。',
},
]}
/>

字段由 Studio 管理时，TypeScript 不允许在代码中设置该字段：`editor: { instructions: true }` 与代码中的 `instructions`、`editor: { tools: true }` 与代码中的 `tools` 都会产生类型错误。若指令由 Studio 管理，在发布包含指令的已保存版本前，Agent 会拒绝运行。

Agent 的 `id` 和 `name` 始终由代码定义。除非设置 `model: true`，模型也由代码管理。模型管理支持条目具有不可变 ID 的静态回退数组。值为函数的模型配置不能通过 Editor 覆盖。用法参阅 [Editor](/docs/studio/editor)。
