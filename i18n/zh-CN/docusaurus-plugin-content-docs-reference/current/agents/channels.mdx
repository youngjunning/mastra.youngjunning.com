# Channels

**引入版本：** `@mastra/core@1.22.0`

Channels 将 Agent 连接到消息平台。通过 `Agent` 构造函数的 `channels` 属性配置。传入的对象类型为 `ChannelConfig`。概念和平台设置说明请参阅 [Channels 概览](/docs/channels)。

## 使用示例 {/* #usage-example */}

```typescript title="src/mastra/agents/support-agent.ts"
import { Agent } from '@mastra/core/agent'
import { createSlackAdapter } from '@chat-adapter/slack'
import { createDiscordAdapter } from '@chat-adapter/discord'

export const supportAgent = new Agent({
  id: 'support-agent',
  name: 'Support Agent',
  instructions: 'You are a helpful support assistant.',
  model: '__GATEWAY_OPENAI_MODEL__',
  channels: {
    adapters: {
      slack: createSlackAdapter(),
      discord: createDiscordAdapter(),
    },
  },
})
```

## 各适配器选项 {/* #per-adapter-options */}

将适配器封装为 `ChannelAdapterConfig` 对象，即可设置该适配器的选项：

```typescript title="src/mastra/agents/example.ts"
import { Agent } from '@mastra/core/agent'
import { createDiscordAdapter } from '@chat-adapter/discord'
import { createSlackAdapter } from '@chat-adapter/slack'

const agent = new Agent({
  id: 'example',
  name: 'Example',
  instructions: '...',
  model: '__GATEWAY_OPENAI_MODEL__',
  channels: {
    adapters: {
      discord: {
        adapter: createDiscordAdapter(),
        toolDisplay: 'text',
        cors: {
          origin: ['https://customer-saas.example'],
          credentials: true,
        },
        gateway: false,
      },
      slack: createSlackAdapter(), // Plain adapter uses defaults
    },
  },
})
```

## 工具显示模式 {/* #tool-display-modes */}

`toolDisplay` 控制工具调用在聊天中的显示方式。默认值 `'cards'` 会为每个工具发布一张「运行中…」卡片，并在得到结果后更新卡片，与旧版行为一致。所有适配器（包括 Slack）都以此为默认值。若要在 Slack 中分组显示工具状态，必须显式设置 `streaming: true` 和 `toolDisplay: 'grouped'`。`'text'` 的生命周期相同，但不使用丰富的 Block Kit 卡片，适合不擅长呈现卡片的平台。

`'timeline'` 和 `'grouped'` 会把工具状态作为内联 `task_update` 片段，与 Agent 文本一起流式传输。这两种模式需要 `streaming: true`，并依赖聊天适配器呈现片段。Slack 原生支持这两种模式；其他适配器在提供支持前可能只显示占位符。若禁用 `streaming`，Channel 会记录一次警告并回退到 `'cards'`。

`'hidden'` 会静默执行工具，只有输入状态提示正在进行的工作。

向 `toolDisplay` 传入函数可完全自定义呈现方式。函数接收 `ToolDisplayEvent`（`running` / `result` / `error` / `approval` / `approved` / `denied`）和 `ToolDisplayContext`（`{ mode, platform }`）。返回 `{ kind: 'post', message }` 可发布或编辑独立消息，返回 `{ kind: 'stream',
chunk }` 可推送到活动的流式组件，返回 `undefined` 则跳过该事件。

用户选择 Approve 或 Deny 后，Mastra 会发送 `approved` 或 `denied` 事件。两种事件都包含 `byUser`，即响应者的姓名；在私信中该值为 undefined。返回 `post` 结果会原位替换审批卡片。若函数不返回内容、返回空消息或抛出错误，Mastra 会显示默认的「Approved」或「Denied」卡片；非私信中卡片会显示用户姓名。

默认情况下，流式结果会在没有活动会话时开启新会话。若该片段只适用于现有会话，请设置 `openIfEmpty: false`。Mastra 在没有活动会话时会跳过该片段。静态 Channel 会忽略此选项，继续使用现有的纯文本回退行为。

```typescript
toolDisplay: event => {
  if (event.kind !== 'running') return undefined

  return {
    kind: 'stream',
    chunk: {
      type: 'task_update',
      id: event.toolCallId,
      title: event.displayName,
      status: 'in_progress',
    },
    openIfEmpty: false,
  }
}
```

批准/拒绝提示（`requireApproval`）在所有字符串模式下都会显示为单独的内置卡片，因为内联任务条目无法承载交互按钮。使用 `toolDisplay` 函数时，无论流式还是静态模式，函数都会收到 `approval` 事件；返回非空的 `{ kind: 'post', message }` 可用自定义消息（例如本地化文案）替换内置卡片。返回 `undefined`、空消息或 `{ kind: 'stream' }` 则会回退到内置卡片，以确保用户仍能批准或拒绝请求。按钮 ID 必须符合默认操作处理器预期的格式。参见[自定义审批卡片](#custom-approval-cards)。

```typescript title="src/mastra/agents/streaming.ts"
import { Agent } from '@mastra/core/agent'
import { createSlackAdapter } from '@chat-adapter/slack'

const agent = new Agent({
  id: 'streaming-agent',
  name: 'Streaming Agent',
  instructions: '...',
  model: '__GATEWAY_OPENAI_MODEL__',
  channels: {
    adapters: {
      slack: {
        adapter: createSlackAdapter(),
        streaming: true, // off by default on every adapter
        toolDisplay: 'timeline',
      },
    },
  },
})
```

### 自定义审批卡片 {/* #custom-approval-cards */}

自定义审批消息会替换内置卡片，但 Mastra 的默认 `onAction` 处理器仍负责处理按钮操作。只有按钮 ID 与以下格式完全匹配时，才会恢复已暂停的运行：

- 批准：`tool_approve:<toolCallId>`
- 拒绝：`tool_deny:<toolCallId>`

`<toolCallId>` 是 `approval` 事件中的 `event.toolCallId`。其他 ID（包括含多余空格的 ID）都无法匹配待审批项，运行会保持暂停。默认处理器也必须保持启用：不要设置 `handlers.onAction: false`；如果提供自定义 `onAction`，请调用 `defaultHandler()`，让审批点击得到处理。

自定义 `toolDisplay` 函数会替换所有工具事件的内置呈现器。下例仅呈现审批事件，因此其他工具调用不会发布内容；若希望显示这些调用，也须为 `result` 和 `error` 事件返回消息。

```typescript title="src/mastra/agents/localized-approval.ts"
import { Agent } from '@mastra/core/agent'
import { createSlackAdapter } from '@chat-adapter/slack'

const agent = new Agent({
  id: 'localized-approval-agent',
  name: 'Localized Approval Agent',
  instructions: '...',
  model: '__GATEWAY_OPENAI_MODEL__',
  channels: {
    adapters: {
      slack: {
        adapter: createSlackAdapter(),
        toolDisplay: event => {
          if (event.kind !== 'approval') return undefined

          return {
            kind: 'post',
            message: {
              type: 'card',
              title: `Approve ${event.displayName}?`,
              children: [
                {
                  type: 'actions',
                  children: [
                    {
                      type: 'button',
                      id: `tool_approve:${event.toolCallId}`,
                      label: 'Genehmigen',
                      style: 'primary',
                    },
                    {
                      type: 'button',
                      id: `tool_deny:${event.toolCallId}`,
                      label: 'Ablehnen',
                      style: 'danger',
                    },
                  ],
                },
              ],
            },
          }
        },
      },
    },
  },
})
```

## 生成式 UI 卡片 {/* #generative-ui-cards */}

:::warning[Experimental]
`generativeUI` 是实验性功能，可能在次要版本中变更。
:::

在 Slack 适配器上设置 `generativeUI: true` 后，Agent 可发布结构化卡片（状态摘要、键值字段、表格、图表、图像及链接按钮），代替冗长的 Markdown 回复。请先安装可选的 peer 依赖：

```bash npm2yarn
npm install @json-render/chat
```

`@json-render/chat` 需要 zod 4，因此仍使用 zod 3 的项目暂时无法启用 `generativeUI`。

`@mastra/core` 会在运行时加载 `@json-render/chat`，而 `mastra build` 和 `mastra deploy` 不会自行将其打包。请将其加入 [`bundler.dynamicPackages`](/reference/core/mastra-class)，使其包含在构建产物中：

```typescript title="src/mastra/index.ts"
import { Mastra } from '@mastra/core'
import { supportAgent } from './agents/support-agent'

export const mastra = new Mastra({
  agents: { supportAgent },
  bundler: { dynamicPackages: ['@json-render/chat'] },
})
```

在该适配器上运行时，Agent 会获得 `render_card` 工具，工具描述列出了可用组件。Agent 传入扁平的 `{ root, elements }` 规范，其中根元素是 `Card`：

```json
{
  "root": "card",
  "elements": {
    "card": { "type": "Card", "props": { "title": "Deploy status" }, "children": ["fields"] },
    "fields": { "type": "Fields", "children": ["env", "version"] },

  }
}
```

卡片发布后，工具返回 `{ ok: true, messageId }`。如果规范无效或超过平台限制（Slack 中每张卡片最多一张表格、100 行），工具不会发布卡片，而会返回 `{ ok: false, issues }`，以便 Agent 修正规范后重试。工具调用本身不会显示为工具卡片。目前不支持交互按钮。卡片可通过 `LinkButton` 链接到外部页面。

## 自定义输入状态 {/* #custom-typing-status */}

向 `typingStatus` 传入函数可自定义状态文案。每个流式片段都会调用该函数一次；返回字符串可设置状态，返回 `false` / `null` / `undefined` 则保持当前状态不变。返回值会去重，因此只有状态变化时才会调用平台接口。运行结束时，已设置的状态会自动清除，避免没有发布消息的运行在线程中留下过期状态。

`defaultTypingStatus` 从 `@mastra/core/channels` 导出，可在未自行处理的片段上回退到内置默认值。

```typescript title="src/mastra/agents/custom-typing.ts"
import { Agent } from '@mastra/core/agent'
import { defaultTypingStatus } from '@mastra/core/channels'
import { createDiscordAdapter } from '@chat-adapter/discord'

const agent = new Agent({
  id: 'custom-typing-agent',
  name: 'Custom Typing Agent',
  instructions: '...',
  model: '__GATEWAY_OPENAI_MODEL__',
  channels: {
    adapters: {
      discord: {
        adapter: createDiscordAdapter(),
        typingStatus: (chunk, ctx) => {
          if (chunk.type === 'tool-call' && chunk.payload.toolName === 'searchDocs') {
            return 'is searching docs…'
          }
          return defaultTypingStatus(chunk, ctx)
        },
      },
    },
  },
})
```

## 处理器 {/* #handlers */}

可以覆盖内置事件处理器。每个处理器可采用以下形式：

- **省略**：使用默认 Mastra 处理器（由 Agent 处理消息并发布响应），但 `onMessage` 默认禁用。
- **`false`**：完全禁用该处理器。
- **函数** `(thread, message, defaultHandler, ctx) => Promise<void>`：包装或替换默认处理器。
- 当 `chatOptions.concurrency` 策略将多个发送者的消息合并为一次分发时，每个发送者的轮次都会单独调用此函数，并带有各自的 `ctx`；`ctx.skipped` 保存该轮次中更早的批处理消息。

```typescript title="src/mastra/agents/custom-handlers.ts"
import { Agent } from '@mastra/core/agent'
import { createSlackAdapter } from '@chat-adapter/slack'

const agent = new Agent({
  id: 'custom-handler-agent',
  name: 'Custom Handler Agent',
  instructions: '...',
  model: '__GATEWAY_OPENAI_MODEL__',
  channels: {
    adapters: {
      slack: createSlackAdapter(),
    },
    handlers: {
      onMention: async (thread, message, defaultHandler) => {
        console.log('Received mention:', message.text)
        await defaultHandler(thread, message)
      },
      onDirectMessage: false,
    },
  },
})
```

若要在没有 @提及的情况下回复，请提供 `onMessage`。它接收 Bot 可读取、且尚未分派给私信、提及或已订阅线程处理器的所有消息。如果只希望回复某些 Channel，请在调用 `defaultHandler` 前按 Channel 筛选：

```typescript
import type { ChannelHandlers } from '@mastra/core/channels'

const handlers: ChannelHandlers = {
  onMessage: async (thread, message, defaultHandler) => {
    if (thread.channelId !== 'slack:C_SUPPORT') return
    await defaultHandler(thread, message)
  },
}
```

`defaultHandler` 会运行 Agent、发布响应并订阅该线程。线程中后续消息会交给 `onSubscribedMessage`。通过 `onMessage` 发起的运行，其 `channel.eventType` 为 `message`。当排队批次同时包含提及和未提及 Bot 的发送者时，若已启用该处理器，未提及者进入 `onMessage`；否则进入 `onMention`，若 `onMention` 为 `false` 则跳过。

`ChannelHandler` 函数签名：

```typescript
type ChannelHandler = (
  thread: Thread,
  message: Message,
  defaultHandler: (thread: Thread, message: Message) => Promise<void>,
  ctx: ChannelHandlerContext,
) => Promise<void>

type ChannelHandlerContext = {
  mastra?: Mastra
  requestContext: RequestContext
  readonly signalMetadata: Record<string, unknown>
  readonly skipped: readonly Message[]
}
```

`ctx.mastra` 是解析后的 `mastra` 实例，因此处理器无须额外传入访问器，就能访问存储或其他已注册的基础组件：

```typescript
onDirectMessage: async (thread, message, defaultHandler, ctx) => {
  const store = await ctx.mastra?.getStorage()?.getStore('memory')
  await defaultHandler(thread, message)
}
```

`ctx.requestContext` 是此消息即将启动的运行所用的 [`RequestContext`](/docs/server/request-context)，每条消息都会新建。在调用 `defaultHandler` 前写入的值会进入运行，同时保留 Mastra 随后添加的 Channel 条目：

```typescript
onDirectMessage: async (thread, message, defaultHandler, ctx) => {
  ctx.requestContext.set('locale', 'en-GB')
  await defaultHandler(thread, message)
}
```

运行从请求上下文读取的任何值，都可以像这样逐条消息确定，例如平台发送者对应哪个用户。

`ctx.signalMetadata` 是附加到此消息的 Agent Signal 上的元数据，每条消息都会新建。在调用 `defaultHandler` 前添加可 JSON 序列化且不敏感的值。Mastra 可能持久化 Signal 元数据，并通过 PubSub 发布。与 `ctx.requestContext` 不同，无论消息启动新运行还是送入已有的活动运行，它都会随消息传递。

设置 `burst`、`debounce` 或 `queue` 等 `chatOptions.concurrency` 策略时，`ctx.skipped` 按从旧到新的顺序列出 Chat SDK 在本轮次中合并的同一发送者的较早消息。没有合并消息时，该数组为空。

## Resource ID 解析 {/* #resource-id-resolution */}

Channel 线程的 Memory `resourceId` 默认是 `${platform}:${message.author.userId}`。发送者拥有按平台区分的 Memory。对于使用单点登录（SSO）等共享身份的应用，这会将同一用户的 Memory 分开：其飞书私信使用 `feishu:user_123`，Web 端则使用 `user_123`。

传入 `resolveResourceId` 可将 Memory 所有权与发送者身份分开确定。它只在创建新线程时运行。复用线程会保留已存储的 `resourceId`，不会调用此钩子，因此现有对话不依赖解析函数是否可用。返回 `ctx.defaultResourceId` 可沿用内置行为。

```typescript title="src/mastra/agents/sso-agent.ts"
import { Agent } from '@mastra/core/agent'
import { createSlackAdapter } from '@chat-adapter/slack'

const agent = new Agent({
  id: 'sso-agent',
  name: 'SSO Agent',
  instructions: '...',
  model: '__GATEWAY_OPENAI_MODEL__',
  channels: {
    adapters: {
      slack: createSlackAdapter(),
    },
    resolveResourceId: async ({ thread, message }) => {
      // DM: share resource-level memory with the web app by using the bare SSO id
      if (thread.isDM) {
        return await resolveSsoUserId(message)
      }
      // Group chat: the conversation owns the memory; the sender stays the actor
      return thread.channelId
    },
  },
})
```

## Thread ID 解析 {/* #thread-id-resolution */}

新建 Channel 线程在 Mastra 内部默认使用随机 UUID 作为线程 ID。传入 `resolveThreadId` 可自行指定 ID；例如将线程 ID 设为其会话 ID，使其与应用创建的线程命名一致。

此钩子在 `resolveResourceId` 之后运行，因此上下文中可以取得解析后的所有者。与 `resolveResourceId` 一样，它只在创建新线程时运行：复用线程保留已存储的 ID，不调用此钩子。返回的 ID 必须在整个 Memory 存储中唯一。如果它已属于现有线程，Mastra 会记录警告并改用生成的 ID，避免覆盖现有线程。返回 `ctx.defaultThreadId` 可沿用内置行为。

```typescript title="src/mastra/agents/session-agent.ts"
import { Agent } from '@mastra/core/agent'
import { createSlackAdapter } from '@chat-adapter/slack'

const agent = new Agent({
  id: 'session-agent',
  name: 'Session Agent',
  instructions: '...',
  model: '__GATEWAY_OPENAI_MODEL__',
  channels: {
    adapters: {
      slack: createSlackAdapter(),
    },
    // Owner: a session id resolved from the sender's linked account
    resolveResourceId: async ctx => resolveSessionId(ctx),
    // Thread id: align with the session id so app URLs that address
    // threads by session id resolve channel-created threads too
    resolveThreadId: ({ resourceId, defaultThreadId }) => {
      return isSessionId(resourceId) ? resourceId : defaultThreadId
    },
  },
})
```

## 内联媒体 {/* #inline-media */}

控制哪些附件类型（图像、视频、PDF 等）以文件片段形式发送给模型。不匹配的类型会以文本摘要描述，让 Agent 了解文件，同时避免不支持该类型的模型报错。

对于不匹配的类文本附件（`text/*`、JSON、YAML、XML 等），若适配器支持认证拉取（如 Slack 私有文件），会通过该方式下载并作为文本交给 Agent。超过 128 KB 的内容会截断。适配器报告大小超过 10 MB 的文件不会下载。

默认值（`['image/png', 'image/jpeg', 'image/webp', 'application/pdf']`）匹配主流视觉模型支持的格式。可覆盖 `inlineMedia` 来扩展列表（例如 `['image/*', 'audio/*']`），也可完全改用谓词函数。

支持的通配模式：

| 模式 | 匹配类型 |
| - | - |
| `image/*` | 所有图像类型（`image/png`、`image/jpeg` 等） |
| `video/*` | 所有视频类型 |
| `*` 或 `*/*` | 所有类型 |
| `application/pdf` | 精确匹配该类型 |

对于使用私有 CDN 的平台（如 Slack），Chat SDK 会使用认证凭据拉取附件。对于使用公共 CDN 的平台（如 Discord），附件 URL 会直接传给模型。

## 内联链接 {/* #inline-links */}

将消息文本中的 URL 转为文件片段，让模型处理链接内容，而非只看到原始 URL 文本。每个条目可以是字符串（域名模式），也可以是带有强制 MIME 类型的对象。

**字符串条目**匹配域名，并发送 HEAD 请求检测 Content-Type。解析出的类型会与 `inlineMedia` 对照，只有匹配的类型才会成为文件片段。

**对象条目**匹配域名并强制指定 MIME 类型，跳过 HEAD 请求和 `inlineMedia` 检查。适用于 YouTube 等站点：HEAD 请求返回 `text/html`，但模型会将该 URL 视为视频内容。

```typescript
type InlineLinkEntry =
  | string // Domain pattern (HEAD determines mime type)
  | { match: string; mimeType: string } // Domain + forced mime type (skips HEAD)
```

## `toChatLogger()` {/* #tochatlogger */}

将 Mastra logger 适配为 Chat SDK 的 `Logger` 接口。把结果传给适配器的 `logger` 选项，使其日志与应用其余部分使用同一 logger。何时使用请参阅[日志记录](/docs/channels#logging)。

import { toChatLogger } from '@mastra/core/channels'
import { createDiscordAdapter } from '@chat-adapter/discord'
import { PinoLogger } from '@mastra/loggers'

const logger = new PinoLogger({ name: 'app', level: 'info' })

const discord = createDiscordAdapter({
  logger: toChatLogger(logger, { component: 'discord', minLevel: 'warn' }),
})
