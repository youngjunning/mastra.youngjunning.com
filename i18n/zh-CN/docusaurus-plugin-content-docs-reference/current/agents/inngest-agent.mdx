# `createInngestAgent()`

:::beta

在 API 稳定之前，即使没有提高主版本号，也可能发生破坏性变更。

:::

`createInngestAgent()` 为现有的 [`Agent`](/reference/agents/agent) 添加由 [Inngest](https://www.inngest.com/docs) 驱动的持久化执行能力。与 [`createDurableAgent()`](/reference/agents/durable-agent#createdurableagentoptions) 一样，它通过 [PubSub](/docs/server/pubsub) 流式传输事件，并支持可恢复的 stream；不同的是，Agent 循环运行在 Inngest 的执行引擎上，而非当前进程中。需要让运行在进程重启后继续，或在分布式环境中执行时，请使用它。

如需在进程内持久化执行，请使用 [`createDurableAgent()`](/reference/agents/durable-agent#createdurableagentoptions)。如需在内置 Workflow 引擎上启动后无需等待结果的执行，请使用 [`createEventedAgent()`](/reference/agents/durable-agent#createeventedagentoptions)。

## 使用示例 {/* #usage-example */}

配置 Inngest 客户端，包装 Agent，将其注册到 Mastra，并暴露 Inngest 的 serve 端点：

```typescript title="src/mastra/index.ts"
import { Mastra } from '@mastra/core'
import { Agent } from '@mastra/core/agent'
import { createInngestAgent, serve as inngestServe } from '@mastra/inngest'
import { Inngest } from 'inngest'

const inngest = new Inngest({ id: 'my-app' })

const agent = new Agent({
  id: 'my-agent',
  name: 'My Agent',
  instructions: 'You are a helpful assistant',
  model: '__GATEWAY_OPENAI_MODEL__',
})

const durableAgent = createInngestAgent({ agent, inngest })

export const mastra = new Mastra({
  agents: { myAgent: durableAgent },
  server: {
    apiRoutes: [
      {
        path: '/inngest/api',
        method: 'ALL',
        createHandler: async ({ mastra }) => inngestServe({ mastra, inngest }),
      },
    ],
  },
})
```

以流式方式生成响应并读取结果：

```typescript
const { output, runId, cleanup } = await durableAgent.stream('Hello!')

const text = await output.text

cleanup()
```

## 方法 {/* #methods */}

### 执行 {/* #execution */}

#### `stream(messages, options?)` {/* #streammessages-options */}

使用 Inngest 的持久化执行引擎以流式方式生成响应。建立 PubSub 订阅后，Workflow 会由 Inngest 事件触发。

```typescript
const { output, runId, cleanup } = await durableAgent.stream('Hello!', {
  onChunk: chunk => console.log(chunk),
  onFinish: result => console.log('done', result),
})

const text = await output.text
cleanup()
```

返回：[`Promise<InngestAgentStreamResult>`](#inngestagentstreamresult)

#### `resume(runId, resumeData, options?)` {/* #resumerunid-resumedata-options */}

恢复暂停的 Inngest 运行，例如等待 Tool 审批后的运行。它先从存储中加载 Workflow 快照并找到暂停的步骤，再向 Inngest 发送恢复事件。

恢复后的输出包含暂停前的 Tool 调用和文本。为恢复这些内容，`resume()` 最多等待 10 秒，直到已存储的快照包含所有暂停的 Tool 调用。如果快照仍不完整，`resume()` 会以 `Cannot resume run <runId>: ...` 拒绝，并且不会发送恢复事件。运行保持暂停，因此可以再次调用 `resume()`。

```typescript
const { output, cleanup } = await durableAgent.resume(
  runId,
  {
    approved: true,
  },
  { threadId: 'thread-1', resourceId: 'user-1' },
)

await output.text
cleanup()
```

第三个参数除生命周期回调外，还接受 `threadId` 和 `resourceId`：

#### `generate(messages, options?)` {/* #generatemessages-options */}

在 Inngest 的持久化执行引擎上生成响应，并解析为单个 `FullOutput`。如果运行暂停，`generate()` 会返回 `finishReason: 'suspended'`。`runId` 选项可省略；省略时，`generate()` 会创建运行 ID，并通过 `result.runId` 返回。可使用 [`resumeGenerate()`](#resumegenerateresumedata-options) 继续运行。调用方需要暂停回调时，请使用带有 `onSuspended` 的 [`stream()`](#streammessages-options)。

```typescript
const result = await durableAgent.generate('Delete the old records', {
  requireToolApproval: true,
})

result.runId // Generated automatically
result.finishReason // 'suspended' when approval is required
```

返回：`Promise<FullOutput<TOutput>>`

#### `resumeGenerate(resumeData, options)` {/* #resumegenerateresumedata-options */}

恢复已暂停的 `generate()` 运行，并解析为单个 `FullOutput`。与 `Agent.resumeGenerate()` 一样，请将运行 ID 作为 `options.runId` 传入。旧参数顺序 `resumeGenerate(runId, resumeData, options?)` 仍可使用，但已弃用。

```typescript
if (!result.runId) {
  throw new Error('Run ID is missing')
}

const resumedResult = await durableAgent.resumeGenerate({ approved: true }, { runId: result.runId })
```

返回：`Promise<FullOutput<TOutput>>`

#### `observe(runId, options?)` {/* #observerunid-options */}

重新连接现有运行：先重放缓存的事件，再接收实时事件。网络断开后可使用此方法。传入 `offset` 可从指定位置开始重放。

```typescript
const { output, cleanup } = await durableAgent.observe(runId, {
  offset: 0,
  onChunk: chunk => console.log(chunk),
})

await output.text
```

`observe()` 的结果不包含 `threadId` 或 `resourceId`。

返回：`Promise<Omit<InngestAgentStreamResult, 'threadId' | 'resourceId'>>`

:::warning

`observe()` 返回的 `cleanup()` 会删除此次运行的注册表条目和缓存事件。只有在不再需要此次运行时才调用它。如果运行仍处于暂停状态，且你打算稍后恢复，请勿调用 `cleanup()`。

:::

#### `prepare(messages, options?)` {/* #preparemessages-options */}

为持久化执行准备运行，但不触发执行。返回可用于手动触发 Inngest Workflow 事件的序列化 Workflow 输入。

```typescript
const { runId, messageId, workflowInput, threadId, resourceId } = await durableAgent.prepare(
  'Summarize the document',
  {
    memory: { threadId: 'thread-1', resourceId: 'user-1' },
  },
)
```

返回：

```typescript
interface PrepareResult {
  runId: string
  messageId: string
  workflowInput: any
  threadId?: string
  resourceId?: string
}
```

## 事件大小限制 {/* #event-size-limit */}

Inngest Realtime 将单条消息的大小限制在约 512 KB。默认的 `InngestPubSub` 会将每个 stream 事件控制在 480 KB 以下：

* 超出大小限制的 `finish` 事件会在不包含 `output.steps` 的情况下发送。最终文本、用量和结束原因仍会送达，但该次运行的 stream 结果中，`steps`、`toolCalls` 和 `toolResults` 为空。
* 其他超出大小限制的事件，例如包含大型 Tool 结果的 `tool-result` 数据块，会被替换为 `data-oversized-event` 数据块。其 `data` 包含原始的 `eventType`、`chunkType`、`bytes` 和 `limit`。该数据块是临时的，不会保存到 memory。

两种情况都会记录警告。只有实时 stream 会被缩减；保存到 memory 的消息以及该次运行的 Workflow 快照仍保留完整数据。

为了避免限制：

* 返回较小的 Tool 结果，例如 ID 或摘要，并另行获取大型数据。
* 在 stream 结束后，从 memory 或该次 Workflow 运行中读取完整结果。
* 传入不受此限制的 `pubsub`，例如 [`RedisStreamsPubSub`](/reference/pubsub/redis-streams)：

```typescript title="src/mastra/index.ts"
import { createInngestAgent } from '@mastra/inngest'
import { RedisStreamsPubSub } from '@mastra/redis-streams'

const durableAgent = createInngestAgent({
  agent,
  inngest,
  pubsub: new RedisStreamsPubSub({ url: 'redis://localhost:6379' }),
})
```

## 提供 Inngest 函数 {/* #serving-inngest-functions */}

`@mastra/inngest` 包提供 `serve()` 和 `createServe()`，用于向 HTTP 框架注册 Inngest Workflow 函数。

### `serve(options)` {/* #serveoptions */}

使用 Hono（默认框架）提供 Mastra Workflow 服务。它会从 Mastra 收集所有由 Inngest 支持的 Workflow，并注册为 Inngest 函数。

```typescript
import { serve } from '@mastra/inngest'

app.use('/inngest/api', async c => {
  return serve({ mastra, inngest })(c)
})
```

### `createServe(adapter)` {/* #createserveadapter */}

接收任意 Inngest serve 适配器（如 `inngest/express`、`inngest/fastify`、`inngest/next`）并返回适用于该框架的 serve 函数的工厂方法。

```typescript title="Express"
import { createServe } from '@mastra/inngest'
import { serve } from 'inngest/express'

const serveExpress = createServe(serve)
app.use('/inngest/api', serveExpress({ mastra, inngest }))
```

```typescript title="Next.js"
import { createServe } from '@mastra/inngest'
import { serve } from 'inngest/next'

const serveNext = createServe(serve)
export const { GET, POST, PUT } = serveNext({ mastra, inngest })
```
