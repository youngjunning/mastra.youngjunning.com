# Agent.listSuspendedRuns()

**添加于：** `@mastra/core@1.43.0`

`.listSuspendedRuns()` 从 Workflow 快照存储中查找已暂停的 Agent 运行，包括等待 Tool 调用[审批](/docs/agents/human-in-the-loop)的运行，以及由调用 `suspend()` 的 Tool 暂停的运行。基于存储的发现机制在服务器重启后和多个服务器实例之间仍然有效。

将返回的 `runId` 传给 [`resumeStream()`](/docs/agents/human-in-the-loop#runtime-suspension-with-suspend)、`approveToolCall()` 或 `declineToolCall()`，即可继续运行。

过滤条件与 Workflow 运行列表 API（`listWorkflowRuns`）一致，并增加了 Agent 级别的 `threadId` 过滤条件。

## 使用示例 {/* #usage-example */}

查找某段对话中等待处理的运行并使其继续。根据 `requiresApproval` 选择方法：因等待审批而暂停时使用 `approveToolCall()` / `declineToolCall()`；使用 `resumeStream()` 并传入恢复数据，可继续由 `suspend()` 暂停的运行：

```typescript
const { runs } = await agent.listSuspendedRuns({
  threadId: 'thread-123',
  resourceId: 'user-456',
})

const run = runs[0]
const toolCall = run?.toolCalls[0]

if (run && toolCall) {
  const stream = toolCall.requiresApproval
    ? await agent.approveToolCall({ runId: run.runId, toolCallId: toolCall.toolCallId })
    : await agent.resumeStream({ name: 'San Francisco' }, { runId: run.runId })
}
```

## 发现范围 {/* #discovery-scope */}

结果仅属于调用 `listSuspendedRuns()` 的 Agent，因为快照会保存所属 Agent 的 ID。同一 Mastra 实例中其他 Agent 启动的运行不会返回。在[监督 Agent 配置](/docs/agents/human-in-the-loop#tool-approval-supervisor-agents)中，监督 Agent 可以找到自己需要恢复的外层运行；子 Agent 的内层运行只能从该子 Agent 查询。使用 `threadId` 和 `resourceId` 可将结果限定为一段对话。

运行快照只在等待输入期间保存，运行结束后即被删除，因此只能从存储中发现已暂停的运行。只有为 Mastra 实例配置了持久化[存储提供方](/docs/storage)，已暂停的运行才能在重启后保留。默认使用内存存储，重启后快照会丢失。

存储适配器支持时，`threadId` 和 `resourceId` 过滤条件会下推到存储查询。`@mastra/pg` 和 `@mastra/libsql` 在数据库内筛选匹配的运行，无需加载所有已暂停的快照；内存存储则筛选其内存记录。其他存储适配器先获取数据，再在进程内过滤。两种方式返回的结果相同。
