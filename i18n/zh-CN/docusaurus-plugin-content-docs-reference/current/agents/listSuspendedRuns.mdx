# Agent.listSuspendedRuns()

**添加于：** `@mastra/core@1.43.0`

这`.listSuspendedRuns()` method uses workflow snapshot storage to find suspended agent runs, including runs awaiting [approval](/docs/agents/human-in-the-loop)用于Tool调用并由调用的Tool暂停运行`suspend()`。服务器重新启动后，支持存储的发现可以在多个服务器实例中继续工作。

通过返回的`runId` to [`resumeStream()`](/docs/agents/human-in-the-loop#runtime-suspension-with-suspend), `approveToolCall()`, or `declineToolCall()`继续运行。

过滤器合约镜像了Workflow运行列表 API（`listWorkflowRuns`), plus the agent-level `threadId` filter.

## 使用示例 {/* #usage-example */}

发现对话的待运行并继续它。查看`requiresApproval` to pick the right continuation: `approveToolCall()` / `declineToolCall()` for approval suspensions, `resumeStream()` with resume data for `suspend()`-based suspensions:

```typescript
const { runs } = await agent.listSuspendedRuns({
  threadId: 'thread-123',
  resourceId: 'user-456',
})

const run = runs[0]
const toolCall = run?.toolCalls[0]

if (run && toolCall) {
  const stream = toolCall.requiresApproval
    ? await agent.approveToolCall({ runId: run.runId, toolCallId: toolCall.toolCallId })
    : await agent.resumeStream({ name: 'San Francisco' }, { runId: run.runId })
}
```

## 发现范围 {/* #discovery-scope */}

结果仅限于您致电的Agent`listSuspendedRuns()` on because snapshots persist the owning agent's id. Runs started by other agents on the same Mastra instance aren't returned. In [supervisor setups](/docs/agents/human-in-the-loop#tool-approval-supervisor-agents), the supervisor sees its outer run to resume, while a subagent's inner run is visible only from the subagent itself. Filter by `threadId` and `resourceId` to limit results to one conversation.

运行快照仅在运行等待输入时保留，并在运行完成后删除，因此挂起的运行是唯一可从存储中发现的运行。当 Mastra 实例具有持久性时，挂起的运行只能在重新启动后继续存在。[storage provider](/docs/storage) configured. With the default in-memory store, snapshots are lost on restart.

这`threadId` and `resourceId` filters are pushed down to the storage query where the adapter supports it. `@mastra/pg` and `@mastra/libsql` narrow matching runs inside the database instead of loading every suspended snapshot, and the in-memory store filters its in-memory records. Other storage adapters apply these filters in-process after fetching. Results are identical either way.
