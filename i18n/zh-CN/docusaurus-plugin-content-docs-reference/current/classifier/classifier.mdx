# Classifier

`Classifier` 使用决策模型针对共享状态回答一个或多个取值范围固定的问题。应用需要带类型的选项、数值评分或布尔概率，又不想解析生成文本时，可使用它。

Classifier 只返回评估结果。应用自行决定如何使用，例如选择路由，或将概率与安全阈值比较。

`Classifier` 需要决策模型（`DecisionModelV4`，或已弃用的 `EvaluationModelV4`；也可以包装在 `MastraDecisionModel` 中）。它不接受 `'provider/model'` 字符串、单独的模型 ID 或语言模型。

## 基本用法 {/* #basic-usage */}

本示例使用 [TypeSafe AI Provider](https://ai-sdk.dev/providers/ai-sdk-providers/typesafe-ai)。请确保已设置 `TYPESAFE_AI_API_KEY` 环境变量。若使用其他 Provider，请参阅[决策模型](#decision-models)。

安装 Provider 包：

```bash npm2yarn
npm install @ai-sdk/typesafe-ai
```

当每次评估都使用相同的问题集时，在构造函数中定义问题。保留问题对象字面量，以便 TypeScript 可以推断答案键和选择值。

```typescript
import { Classifier } from '@mastra/core/classifier'
import { typeSafeAi } from '@ai-sdk/typesafe-ai'

const classifier = new Classifier({
  id: 'request-classifier',
  model: typeSafeAi.decisionModel('__AI_SDK_TYPESAFE_DECISION_MODEL__'),
  questions: {
    route: {
      type: 'choice',
      instructions: 'Choose the team that should handle this request.',
      criteria: {
        billing: 'Questions about invoices, charges, or refunds',
        support: 'Questions about using or troubleshooting the product',
      },
    },
    urgent: {
      type: 'boolean',
      instructions: 'Does this request require an immediate response?',
    },
  },
})

const result = await classifier.decide({
  state: {
    subject: 'Duplicate charge',
    message: 'I was charged twice for the same subscription.',
  },
})

result.answers.route.choice // 'billing' | 'support' | undefined
result.answers.urgent.probability // P(true), from 0 to 1, or undefined
```

只有决策模型拒绝回答某个问题时，该字段才为 `undefined`。参见[被拒绝的问题](#refused-questions)。

决策模型会在相同的 `state` 下接收所有问题。若某个问题省略了 `instructions`，就会改用该问题的名称。

## 决策模型 {/* #decision-models */}

本页示例遵循 AI SDK 文档中的 [TypeSafe AI Provider 设置](https://ai-sdk.dev/providers/ai-sdk-providers/typesafe-ai#setup)。其他 AI SDK Provider（包括 OpenAI、Anthropic 和 Google）也提供 `decisionModel()` 工厂；此前的 `evaluationModel()` 仍作为已弃用的别名保留。Mastra 会调用 `doDecide()`；对较旧的 Provider，则回退调用 `doEvaluate()`。完整列表、支持的模型 ID 及各 Provider 回答问题的方式，请参阅 [Provider 模型](https://ai-sdk.dev/docs/ai-sdk-core/decisions#provider-models)。

每个 Provider 都导出一个现成实例，本页示例使用的就是这些实例。其他 Provider 请参阅 [AI SDK Provider](https://ai-sdk.dev/providers/ai-sdk-providers)。

通过调用工厂来显式传递密钥：

```typescript
import { createTypeSafeAi } from '@ai-sdk/typesafe-ai'

const model = createTypeSafeAi({ apiKey: process.env.TYPESAFE_AI_API_KEY }).decisionModel(
  '__AI_SDK_TYPESAFE_DECISION_MODEL__',
)
```

## 问题类型 {/* #question-types */}

问题名称会成为 `result.answers` 中的键。每个问题都可以有一个包含兼容 JSON 值的可选 `instructions` 字段。评判标准的值也可以是兼容 JSON 的数据，不限于字符串。

### 选择题 {/* #choice-questions */}

选择题会从非空的 `criteria` 对象中选出一个键。

```typescript
const questions = {
  sentiment: {
    type: 'choice',
    instructions: 'Classify the customer sentiment.',
    criteria: {
      positive: 'The customer is satisfied or complimentary.',
      neutral: 'The customer has no clear positive or negative sentiment.',
      negative: 'The customer is dissatisfied or frustrated.',
    },
  },
} as const
```

答案包含所选的 `choice`。如果 Provider 返回 `probabilities`，该对象必须包含每个选项的键，并且在 Provider 声明的舍入精度范围内，总和应为 `1`。

```typescript
const answer = {
  type: 'choice',
  choice: 'negative',
  probabilities: {
    positive: 0.05,
    neutral: 0.15,
    negative: 0.8,
  },
}
```

### 分数问题 {/* #score-questions */}

评分题使用至少有两个等级的有序数组。数组索引定义评分范围。若有三个标准，有效评分可从 `0` 到 `2`，包括小数。

```typescript
const questions = {
  quality: {
    type: 'score',
    instructions: 'Score the response quality.',
    criteria: ['Incorrect or unhelpful', 'Partially correct', 'Correct and complete'],
  },
} as const
```

提供者可以返回每个级别的分数和可选概率：

```typescript
const answer = {
  type: 'score',
  score: 1.7,
  probabilities: {
    '0': 0.05,
    '1': 0.2,
    '2': 0.75,
  },
}
```

### 布尔问题 {/* #boolean-questions */}

布尔题返回答案为 `true` 的估计概率。该值始终在 `0` 与 `1` 之间，并不表示“较有可能的结果”的置信度。

```typescript
const questions = {
  unsafe: {
    type: 'boolean',
    instructions: 'Does the message contain unsafe content?',
    criteria: {
      true: 'The message contains unsafe content.',
      false: 'The message is safe.',
    },
  },
} as const
```

布尔题的 `criteria` 字段是可选的。提供此字段时，其中 `true` 和 `false` 的描述也可以省略。

```typescript
const answer = {
  type: 'boolean',
  probability: 0.92,
}
```

### 拒答问题 {/* #refused-questions */}

决策模型可以拒绝回答任意问题，例如安全策略不允许回答时。被拒绝的问题会返回 `RefusalAnswer`，而不是选项、评分或布尔答案。同一次调用中的其他问题仍会返回各自答案。

```typescript
const answer = {
  type: 'refusal',
}
```

被拒绝的答案没有 `choice`、`score` 或 `probability`。因此，`answers.route.choice === 'billing'` 等相等性检查会得到 `false`。读取数值字段前，请先检查 `type`，并决定应用如何处理拒绝回答：

```typescript
const urgent = result.answers.urgent

if (urgent.type === 'refusal') {
  // Route to a human, block the input, or apply a default.
} else if (urgent.probability > 0.8) {
  // Escalate.
}
```

## 设计问题 {/* #designing-questions */}

以下规则有助于确保问题能根据状态得到回答：

- 每个问题只要求一个判断。如果任意两个字段的变化都可能改变同一答案，就无法据此稳定地路由。
- 保持标准互斥。`strong: 'A good fit'` 与 `partial: 'Maybe a fit'` 会让概率在两者之间分散。
- 为评分提供足够多的等级，以表示中间值。
- 如果列表不穷尽所有情况，加入兜底等级。没有 `other` 等级时，Classifier 必须将每项输入归入列出的某个团队。
- 将字段放在 `state` 中，而不是 `instructions` 中。这样只改一个字段时，也只会改变一个答案。

要检查问题设计是否合理，可改变状态中的一个字段，确认只有一个答案变化。

### 每次调用时提供问题 {/* #per-call-questions */}

若每次评估的问题集不同，请在构造函数中省略 `questions`。答案类型会根据该次调用提供的问题推断。

```typescript
import { Classifier } from '@mastra/core/classifier'
import { typeSafeAi } from '@ai-sdk/typesafe-ai'

const classifier = new Classifier({
  id: 'dynamic-classifier',
  model: typeSafeAi.decisionModel('__AI_SDK_TYPESAFE_DECISION_MODEL__'),
})

const result = await classifier.decide({
  state: { response: 'Your refund has been processed.' },
  questions: {
    tone: {
      type: 'choice',
      criteria: {
        empathetic: 'Acknowledges the customer and responds with care',
        neutral: 'States the outcome without emotional language',
      },
    },
  },
})

result.answers.tone.choice // 'empathetic' | 'neutral' | undefined
```

## 验证和错误 {/* #validation-and-errors */}

`Classifier` 会在调用 Provider 前验证输入，并在返回 Provider 输出前验证输出。

输入验证包括：

- `id` 必须是非空字符串。
- `state`、instructions 和 criteria 必须兼容 JSON。
- 问题对象和选择题标准不能为空。
- 评分标准必须包含至少两个已定义的等级。
- 决策模型必须支持每种问题类型。
- `maxRetries` 必须是非负整数。

Provider 的响应必须为每个问题恰好包含一个答案。每个答案必须符合问题类型，或明确表示拒答。Classifier 还会拒绝无效选项、超出范围的评分或概率、不完整的概率分布、非有限数的 Token 用量、格式错误的警告，以及无效的响应时间戳。

只有可重试的 AI SDK `APICallError` 错误才会重试，默认重试两次。可通过 `maxRetries` 修改次数。其他错误会立即使调用失败。若所有重试均失败，`decide()` 会重新抛出最后一次 Provider 错误。传入的中止信号触发时，调用会以该信号的中止原因被拒绝，即使取消发生在重试退避期间也是如此。

## 可观测性 {/* #observability */}

当存在活动的 Mastra Span 时，`decide()` 会创建一个 `CLASSIFIER_EVALUATION` 子 Span。Span 输入包含被评估的 `state` 和问题，输出包含答案及概率。Span 属性记录 Classifier 与模型标识符、Provider、问题数量与类型、尝试次数、耗时及 Token 用量。Token 用量也会生成 [Token 与成本指标](/reference/observability/metrics/automatic-metrics#token-usage-metrics)。

若不想在导出的 Trace 中包含状态和答案，请设置 `hideInput` 与 `hideOutput`；这两个选项位于调用 Classifier 的 Agent 或 Workflow 运行的 `tracingOptions` 中。参见[隐藏敏感输入与输出](/docs/observability/tracing/overview#hiding-sensitive-inputoutput)。

在 [Studio](/docs/studio/overview) 中按 Classifier 实体类型筛选 Trace，可单独查看 Classifier 调用。Workflow 中的 Classifier 步骤会在流程图中显示为 Classifier 节点。

## 自定义 Provider 响应 {/* #customize-provider-responses */}

`Classifier` 会自动用 `MastraDecisionModel` 包装原始 AI SDK 决策模型。如果 Provider 输出在验证前需要规范化，可传入自己的包装器。

```typescript
import { Classifier, MastraDecisionModel, type DecisionModelResult } from '@mastra/core/classifier'
import { typeSafeAi } from '@ai-sdk/typesafe-ai'

class NormalizedDecisionModel extends MastraDecisionModel {
  protected override transformResult(result: DecisionModelResult): DecisionModelResult {
    return {
      ...result,
      answers: normalizeAnswers(result.answers),
    }
  }
}

const classifier = new Classifier({
  id: 'normalized-classifier',
  model: new NormalizedDecisionModel(
    typeSafeAi.decisionModel('__AI_SDK_TYPESAFE_DECISION_MODEL__'),
  ),
})
```

`transformResult()` 在 Provider 调用之后、`Classifier` 验证响应之前运行。

`MastraEvaluationModel` 和 `EvaluationModelResult` 分别是 `MastraDecisionModel` 和 `DecisionModelResult` 已弃用的别名，将在未来版本移除。

## 注册分类器 {/* #registering-classifiers */}

在 `Mastra` 实例上注册 Classifier，可供整个应用共享，并通过键或 ID 获取。若评估已注册的 Classifier 时没有活动 Trace，它会启动根 `CLASSIFIER_EVALUATION` Span，并使用 `Mastra` 实例配置的可观测性 Provider。

```typescript title="src/mastra/index.ts"
import { Mastra } from '@mastra/core'
import { Classifier } from '@mastra/core/classifier'
import { typeSafeAi } from '@ai-sdk/typesafe-ai'

export const safety = new Classifier({
  id: 'safety',
  model: typeSafeAi.decisionModel('__AI_SDK_TYPESAFE_DECISION_MODEL__'),
  questions: {
    unsafe: { type: 'boolean' },
  },
})

export const mastra = new Mastra({
  classifiers: { safety },
})

mastra.getClassifier('safety')
mastra.getClassifierById('safety')
mastra.listClassifiers()
```

## 在 Workflow 中使用 Classifier {/* #using-classifiers-in-workflows */}

构造函数中已配置问题的 Classifier 可以通过 [`createStep(classifier)`](/reference/workflows/step) 或 [`.classifier()`](/reference/workflows/workflow-methods/classifier) 加入 Workflow。Workflow 输出包含完整的带类型 `answers` 和规范化的 `usage`。

```typescript
import { safety } from '../index'

const workflow = createWorkflow({
  id: 'ticket-triage',
  inputSchema: z.object({ message: z.string() }),
  outputSchema: z.any(),
})
  .map({ message: { initData: true, path: 'message' } })
  .classifier<typeof safety.questions>('safety')
  .commit()
```

字符串引用会在运行时通过 `Mastra` 实例解析。ID 不携带问题类型，因此请用类型参数提供这些类型，以保持答案带类型。在 Studio 中，Workflow 流程图会将该步骤显示为 Classifier 节点。

Workflow Adapter 不会在步骤输出中包含警告、原始 Provider 响应、Header 或 Provider 元数据。若需要这些 Provider 层面的细节，请直接调用 `decide()`，或查看 Classifier 的可观测性数据。
