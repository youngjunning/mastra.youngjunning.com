# 创建编码Agent()

**添加于：** `@mastra/core@1.48.0`

`createCodingAgent()`构建编码[`Agent`](/reference/agents/agent) with the essential defaults a coding agent always needs: a local workspace, the task-list signal provider when `memory`配置，网络重试错误处理器，以及目标判断提示。只供应`model`和`instructions`获取工作Agent，或覆盖任何默认值。

返回值是一个标准值`Agent`, so it works anywhere an `Agent` does: including as the agent passed to an [`AgentController`](/reference/agent-controller/agent-controller-class). The function lives in `@mastra/core` with no hosted service behind it, and every default it fills in is a primitive you can also configure on [`new Agent()`](/reference/agents/agent) yourself.

默认值匹配[Mastra Code](https://code.mastra.ai) runs on. The prompt, modes, and tools that make up that product aren't included: `createCodingAgent()` sets up only the runtime pieces listed under [Defaults](#defaults).

## 使用示例 {/* #usage-example */}

传递模型和说明。`createCodingAgent()` fills in the workspace and the error processors. The task signal provider is added when `memory` is configured, and the goal prompt when a `goal` is configured:

```typescript title="src/mastra/coding-agent.ts"
import { createCodingAgent } from '@mastra/core/coding-agent'

const agent = createCodingAgent({
  id: 'my-coding-agent',
  name: 'My Coding Agent',
  model: '__GATEWAY_OPENAI_MODEL_BASE__',
  instructions: 'You are a helpful coding assistant.',
})

const result = await agent.generate('Which test files mention the /health endpoint?')
```

Agent收到[workspace tools](/reference/workspace/workspace-class#filesystem-tools) for its resolved workspace, so `tools` is only needed for capabilities beyond the workspace, such as opening a pull request. Mastra also adds a description of the workspace to the system prompt.

：：：警告

默认Workspace使用应用程序进程的权限在主机上运行命令。看[Workspace](#workspace) for how to swap in an isolated sandbox.

:::

对于 Mastra Code 使用的行为提示，涵盖存储库探索、编辑、命令和提交、构建`instructions` with [`buildBasePrompt()`](/reference/coding-agent/build-base-prompt).

## 默认值 {/* #defaults */}

仅当您不提供相应字段时才会填写默认值。`signals` is the exception: the task signal provider is appended to the providers you pass.

|领域 |省略时默认 |
| - | - |
|`workspace` | A [`Workspace`](/reference/workspace/workspace-class) backed by `LocalFilesystem` and `LocalSandbox` rooted at the base path. |
| `signals` | A [`TaskSignalProvider`](/reference/signals/task-signal-provider), added only when `memory` is configured. |
| `errorProcessors` | Unknown stream-error retries with specialized ECONNRESET and bad-request policies, plus `PrefillErrorHandler`, `ProviderHistoryCompat`, and `CyberRefusalHandler`. |
| `outputProcessors` | [`CyberRefusalHandler`](/reference/processors/cyber-refusal-handler). |
| `maxProcessorRetries` | `DEFAULT_MAX_PROCESSOR_RETRIES`(3)，因此输出通道网络拒绝重试是有预算的。 |
|`goal.prompt` | `DEFAULT_GOAL_JUDGE_PROMPT`（仅当`goal`已配置）。 |

其他什么都不填写，没有默认的`model`, `instructions`, `tools`, `memory`, storage, or input processors.

每个默认值都有一个明确的选择退出：

|默认 |如何选择退出 |
| - | - |
|工作空间 |`workspace: undefined` |
| Task tracking | Don't configure `memory` on the agent |
| Error processors | `errorProcessorDefaults: false` |
| Output processors | `outputProcessors: []` |
| Processor retry budget | `maxProcessorRetries: 0` |
| Goal judge prompt | Omit `goal`, or pass your own `goal.prompt` |

### 工作空间 {/* #workspace */}

当`workspace` key is omitted, a local workspace rooted at `basePath` (default `process.cwd()`) is built:

```typescript
import { Workspace, LocalFilesystem, LocalSandbox } from '@mastra/core/workspace'

new Workspace({
  filesystem: new LocalFilesystem({ basePath }),
  sandbox: new LocalSandbox({ workingDirectory: basePath }),
})
```

要保持该形状但在不同的目录中工作，请传递`basePath`:

```typescript
import { createCodingAgent } from '@mastra/core/coding-agent'

const agent = createCodingAgent({
  id: 'my-coding-agent',
  name: 'My Coding Agent',
  model: '__GATEWAY_OPENAI_MODEL_BASE__',
  instructions: 'You are a helpful coding assistant.',
  basePath: '/srv/checkouts/my-app',
})
```

通过一个`workspace` to build the backends yourself. Here the agent reads the whole repository while commands run inside one package. A remote sandbox takes the place of `LocalSandbox` in the same slot, see [Sandbox](/docs/sandbox/overview) for the available backends and isolation options:

```typescript
import { createCodingAgent } from '@mastra/core/coding-agent'
import { LocalFilesystem, LocalSandbox, Workspace } from '@mastra/core/workspace'

const agent = createCodingAgent({
  id: 'my-coding-agent',
  name: 'My Coding Agent',
  model: '__GATEWAY_OPENAI_MODEL_BASE__',
  instructions: 'You are a helpful coding assistant.',
  workspace: new Workspace({
    filesystem: new LocalFilesystem({ basePath: '/srv/checkouts/my-app' }),
    sandbox: new LocalSandbox({ workingDirectory: '/srv/checkouts/my-app/packages/api' }),
  }),
})
```

选择退出（例如，当Workspace注入到[`AgentController`](/reference/agent-controller/agent-controller-class) level), pass `workspace: undefined` explicitly. An omitted key builds the default, an explicit `undefined` builds nothing:

```typescript
import { createCodingAgent } from '@mastra/core/coding-agent'

const agent = createCodingAgent({
  id: 'my-coding-agent',
  name: 'My Coding Agent',
  model: '__GATEWAY_OPENAI_MODEL_BASE__',
  instructions: 'You are a helpful coding assistant.',
  workspace: undefined, // opt out of the default workspace
})
```

### 信号 {/* #signals */}

[`TaskSignalProvider`](/reference/signals/task-signal-provider)添加了`task_write`, `task_update`, `task_complete`, and `task_check` [task tools](/reference/tools/task-tools) and persists the list in thread state, which gives the agent a durable plan across a multi-step request:

```typescript
import { createCodingAgent } from '@mastra/core/coding-agent'
import { Memory } from '@mastra/memory'

const agent = createCodingAgent({
  id: 'my-coding-agent',
  name: 'My Coding Agent',
  model: '__GATEWAY_OPENAI_MODEL_BASE__',
  instructions: 'Plan multi-step work with the task tools, then carry it out.',
  memory: new Memory(),
})
```

提供程序需要一个内存支持的线程，因此仅在以下情况下添加：`memory` is configured. With memory configured, the provider is merged into any `signals` you pass, which keeps task tracking from being dropped by custom providers. Passing `signals: []` alongside `memory` still yields the task provider. To run a memory-backed agent with no task tracking, configure the agent with [`new Agent()`](/reference/agents/agent) instead. Before `@mastra/core@1.49.0`, the provider was always added, which failed in memoryless contexts.

`TaskSignalProvider`不接受构造函数参数，因此自定义此默认值意味着选择Agent获取的其他提供程序：

```typescript
import { createCodingAgent } from '@mastra/core/coding-agent'
import { WebhookSignalProvider } from '@mastra/core/signals'
import { Memory } from '@mastra/memory'

const agent = createCodingAgent({
  id: 'my-coding-agent',
  name: 'My Coding Agent',
  model: '__GATEWAY_OPENAI_MODEL_BASE__',
  instructions: 'You are a helpful coding assistant.',
  memory: new Memory(),
  signals: [
    new WebhookSignalProvider({
      extractResourceId: payload => (payload as { repository: string }).repository,
    }),
  ],
})
```

该Agent获取 webhook 提供程序和任务提供程序。

### 错误处理器 {/* #error-processors */}

默认[`StreamErrorRetryProcessor`](/reference/processors/stream-error-retry-processor) applies these retry policies:

* 提供者元数据或特定匹配器未匹配的未知错误重试最多两次`3000ms` delay. Known authorization failures surface immediately.
* 网络重置（`ECONNRESET` / `socket hang up`) retry up to twice with exponential backoff (`1000ms * 2^retryCount`, capped at `30000ms`).
* 错误请求错误后重试一次`2000ms`.

特定的网络重置和错误请求策略优先于未知错误策略。通过`errorProcessors` sets the base list: any of the four shared defaults your list doesn't name by `id` is still added, at the position its `id` gives it. An empty list gets all four. Setting `errorProcessorDefaults: false` keeps your list exactly as given, adding none of the shared defaults. Without a list, the agent then runs no error processors. A `StreamErrorRetryProcessor` added this way uses the shared defaults, so it retries neither unknown errors nor bad-request (HTTP 400) responses. Supply your own instance in the list to keep either policy. `PrefillErrorHandler` and `ProviderHistoryCompat` are also included for provider compatibility: both repair errors caused by the shape of the message history, such as a provider rejecting a conversation that ends with an assistant message.

[`CyberRefusalHandler`](/reference/processors/cyber-refusal-handler)当 OpenAI 或 Anthropic 网络安全防护措施拒绝某个步骤时重试一次，这在普通编码工作中经常发生。它运行在两个`errorProcessors` (OpenAI refusals are API errors) and `outputProcessors` (Anthropic refusals finish the step). Passing either list replaces that half of the handler.

重试发生在`generate()` or `stream()` call that hit the error, so a recovered failure is invisible to your code. When the retries run out, the error surfaces the way any model error does: `generate()` rejects and `stream()` emits an `error` chunk. `generate()` and `stream()` also accept `errorProcessors` per call, which replaces the agent's stack for that request. See [Processors](/docs/agents/processors#error-processor-retry-limits) for `maxProcessorRetries`, the retry budget these processors share.

### 目标 {/* #goal */}

默认情况下没有配置目标。当你通过一个`goal` without a `prompt`, `DEFAULT_GOAL_JUDGE_PROMPT` is used. The `goal` config carries the judge and the run budget, while the objective itself is per thread and set with [`setObjective()`](/docs/harness/goals#managing-the-objective):

```typescript
import { createCodingAgent } from '@mastra/core/coding-agent'
import { Memory } from '@mastra/memory'

const agent = createCodingAgent({
  id: 'my-coding-agent',
  name: 'My Coding Agent',
  model: '__GATEWAY_OPENAI_MODEL_BASE__',
  instructions: 'You are a helpful coding assistant.',
  memory: new Memory(),
  goal: {
    judge: '__GATEWAY_OPENAI_MODEL_LUNA__',
    maxRuns: 50,
  },
})

const threadId = 'thread-1'
const resourceId = 'user-1'

await agent.setObjective('Get the test suite passing', { threadId, resourceId })
```

[目标](/docs/harness/goals)需要一个[storage](/docs/storage) backend and a memory-backed thread. Without a resolved `judge`, the goal step is a no-op.
