# createCodingAgent()

**引入版本：** `@mastra/core@1.48.0`

`createCodingAgent()` 用编码 Agent 所需的基本默认配置创建一个 [`Agent`](/reference/agents/agent)：本地 Workspace、配置 `memory` 时的任务列表信号 Provider、网络重试错误处理器，以及目标评判提示词。只需提供 `model` 和 `instructions` 即可创建可用的 Agent，也可以覆盖任意默认配置。

返回值是标准的 `Agent`，可用于任何接受 `Agent` 的地方，包括作为 [`AgentController`](/reference/agent-controller/agent-controller-class) 的 Agent。该函数位于 `@mastra/core`，不依赖托管服务；它设置的每项默认配置也都可以通过 [`new Agent()`](/reference/agents/agent) 自行配置。

这些默认配置与 [Mastra Code](https://code.mastra.ai) 使用的配置一致，但不包含该产品的提示词、模式和工具。`createCodingAgent()` 只设置[默认配置](#defaults)中列出的运行时组件。

## 使用示例 {/* #usage-example */}

传入模型和指令即可。`createCodingAgent()` 会补上 Workspace 和错误处理器；配置 `memory` 时会添加任务信号 Provider，配置 `goal` 时会添加目标提示词：

```typescript title="src/mastra/coding-agent.ts"
import { createCodingAgent } from '@mastra/core/coding-agent'

const agent = createCodingAgent({
  id: 'my-coding-agent',
  name: 'My Coding Agent',
  model: '__GATEWAY_OPENAI_MODEL_BASE__',
  instructions: 'You are a helpful coding assistant.',
})

const result = await agent.generate('Which test files mention the /health endpoint?')
```

Agent 会获得其 Workspace 对应的 [Workspace 工具](/reference/workspace/workspace-class#filesystem-tools)。因此，只有打开拉取请求等超出 Workspace 能力的操作才需要配置 `tools`。Mastra 还会在系统提示词中加入 Workspace 的说明。

:::warning

默认 Workspace 会以应用进程的权限在宿主机执行命令。如何改用隔离的 Sandbox，参见 [Workspace](#workspace)。

:::

如需 Mastra Code 使用的行为提示词，涵盖仓库探索、编辑、命令和提交，可将 `instructions` 用 [`buildBasePrompt()`](/reference/coding-agent/build-base-prompt) 构建。

## 默认值 {/* #defaults */}

只有未提供对应字段时才会填入默认值。`signals` 是例外：任务信号 Provider 会追加到传入的 Provider 中。

| 字段 | 省略时的默认值 |
| - | - |
|`workspace` | 以基础路径为根目录的 [`Workspace`](/reference/workspace/workspace-class)，由 `LocalFilesystem` 和 `LocalSandbox` 支撑。 |
| `signals` | [`TaskSignalProvider`](/reference/signals/task-signal-provider)，仅在配置 `memory` 时添加。 |
| `errorProcessors` | 未知流错误重试及专门的 ECONNRESET 和错误请求策略，加上 `PrefillErrorHandler`、`ProviderHistoryCompat` 和 `CyberRefusalHandler`。 |
| `outputProcessors` | [`CyberRefusalHandler`](/reference/processors/cyber-refusal-handler). |
| `maxProcessorRetries` | `DEFAULT_MAX_PROCESSOR_RETRIES`（3），为输出处理阶段的网络安全拒绝重试提供次数上限。 |
|`goal.prompt` | `DEFAULT_GOAL_JUDGE_PROMPT`（仅当`goal`已配置）。 |

除此之外不会填入其他配置；`model`、`instructions`、`tools`、`memory`、存储和输入处理器均没有默认值。

每项默认配置都有明确的关闭方式：

| 默认配置 | 如何关闭 |
| - | - |
|工作空间 |`workspace: undefined` |
| 任务跟踪 | 不为 Agent 配置 `memory` |
| 错误处理器 | `errorProcessorDefaults: false` |
| 输出处理器 | `outputProcessors: []` |
| 处理器重试次数 | `maxProcessorRetries: 0` |
| 目标评判提示词 | 省略 `goal`，或传入自定义的 `goal.prompt` |

### 工作空间 {/* #workspace */}

省略 `workspace` 字段时，会创建以 `basePath`（默认为 `process.cwd()`）为根目录的本地 Workspace：

```typescript
import { Workspace, LocalFilesystem, LocalSandbox } from '@mastra/core/workspace'

new Workspace({
  filesystem: new LocalFilesystem({ basePath }),
  sandbox: new LocalSandbox({ workingDirectory: basePath }),
})
```

如果只想更换工作目录，而沿用相同的 Workspace 结构，可传入 `basePath`：

```typescript
import { createCodingAgent } from '@mastra/core/coding-agent'

const agent = createCodingAgent({
  id: 'my-coding-agent',
  name: 'My Coding Agent',
  model: '__GATEWAY_OPENAI_MODEL_BASE__',
  instructions: 'You are a helpful coding assistant.',
  basePath: '/srv/checkouts/my-app',
})
```

也可以传入 `workspace`，自行配置后端。下例中，Agent 可以读取整个仓库，但命令只在其中一个包内执行。要使用远程 Sandbox，可在同一位置替换 `LocalSandbox`；可用后端和隔离选项参见 [Sandbox](/docs/sandbox/overview)：

```typescript
import { createCodingAgent } from '@mastra/core/coding-agent'
import { LocalFilesystem, LocalSandbox, Workspace } from '@mastra/core/workspace'

const agent = createCodingAgent({
  id: 'my-coding-agent',
  name: 'My Coding Agent',
  model: '__GATEWAY_OPENAI_MODEL_BASE__',
  instructions: 'You are a helpful coding assistant.',
  workspace: new Workspace({
    filesystem: new LocalFilesystem({ basePath: '/srv/checkouts/my-app' }),
    sandbox: new LocalSandbox({ workingDirectory: '/srv/checkouts/my-app/packages/api' }),
  }),
})
```

若要关闭默认 Workspace（例如已在 [`AgentController`](/reference/agent-controller/agent-controller-class) 层注入 Workspace），请显式传入 `workspace: undefined`。省略字段会创建默认 Workspace；显式设为 `undefined` 则不会创建：

```typescript
import { createCodingAgent } from '@mastra/core/coding-agent'

const agent = createCodingAgent({
  id: 'my-coding-agent',
  name: 'My Coding Agent',
  model: '__GATEWAY_OPENAI_MODEL_BASE__',
  instructions: 'You are a helpful coding assistant.',
  workspace: undefined, // opt out of the default workspace
})
```

### 信号 {/* #signals */}

[`TaskSignalProvider`](/reference/signals/task-signal-provider) 会添加 `task_write`、`task_update`、`task_complete` 和 `task_check` [任务工具](/reference/tools/task-tools)，并将任务列表持久化到线程状态，让 Agent 在多步骤请求中保留计划：

```typescript
import { createCodingAgent } from '@mastra/core/coding-agent'
import { Memory } from '@mastra/memory'

const agent = createCodingAgent({
  id: 'my-coding-agent',
  name: 'My Coding Agent',
  model: '__GATEWAY_OPENAI_MODEL_BASE__',
  instructions: 'Plan multi-step work with the task tools, then carry it out.',
  memory: new Memory(),
})
```

该 Provider 需要由 Memory 支撑的线程，因此仅在配置 `memory` 时添加。配置 Memory 后，它会与传入的 `signals` 合并，避免自定义 Provider 意外关闭任务跟踪。即使同时传入 `signals: []` 和 `memory`，任务 Provider 仍会添加。如需使用 Memory 但不启用任务跟踪，请改用 [`new Agent()`](/reference/agents/agent)。在 `@mastra/core@1.49.0` 之前，该 Provider 总会添加，因此在无 Memory 的场景中会失败。

`TaskSignalProvider` 不接受构造参数；自定义这项默认配置，实际上是选择 Agent 还会获得哪些其他 Provider：

```typescript
import { createCodingAgent } from '@mastra/core/coding-agent'
import { WebhookSignalProvider } from '@mastra/core/signals'
import { Memory } from '@mastra/memory'

const agent = createCodingAgent({
  id: 'my-coding-agent',
  name: 'My Coding Agent',
  model: '__GATEWAY_OPENAI_MODEL_BASE__',
  instructions: 'You are a helpful coding assistant.',
  memory: new Memory(),
  signals: [
    new WebhookSignalProvider({
      extractResourceId: payload => (payload as { repository: string }).repository,
    }),
  ],
})
```

该 Agent 会同时获得 webhook Provider 和任务 Provider。

### 错误处理器 {/* #error-processors */}

默认的 [`StreamErrorRetryProcessor`](/reference/processors/stream-error-retry-processor) 采用以下重试策略：

- 未被 Provider 元数据或特定匹配器识别的未知错误，最多重试两次，每次等待 `3000ms`；已知的授权失败会立即返回。
- 网络连接重置（`ECONNRESET` / `socket hang up`）最多重试两次，采用指数退避（`1000ms * 2^retryCount`，上限 `30000ms`）。
- 错误请求在等待 `2000ms` 后重试一次。

特定的网络连接重置和错误请求策略优先于未知错误策略。传入 `errorProcessors` 会设置基础列表：四个共享默认处理器中，凡是列表里没有以相同 `id` 指定的，仍会按其 `id` 对应的位置加入。因此，传入空数组也会得到全部四个。设置 `errorProcessorDefaults: false` 后则完全按传入列表执行，不添加共享默认处理器；若也未传入列表，Agent 就不会运行错误处理器。通过这种方式添加的 `StreamErrorRetryProcessor` 使用共享默认配置，不会重试未知错误或错误请求（HTTP 400）。若需保留这两种策略中的任一种，请在列表中传入自定义实例。`PrefillErrorHandler` 和 `ProviderHistoryCompat` 用于兼容 Provider：两者都会修复消息历史结构导致的错误，例如 Provider 拒绝以 assistant 消息结尾的对话。

当 OpenAI 或 Anthropic 的网络安全防护拒绝某个步骤时，[`CyberRefusalHandler`](/reference/processors/cyber-refusal-handler) 会重试一次；普通编码工作也经常遇到这种情况。它同时用于 `errorProcessors`（OpenAI 将拒绝作为 API 错误返回）和 `outputProcessors`（Anthropic 将拒绝作为步骤结果返回）。传入任一列表会替换该列表中的这一处理器。

重试发生在遇到错误的 `generate()` 或 `stream()` 调用内部，因此代码不会感知已恢复的失败。重试耗尽时，错误会按普通模型错误的方式返回：`generate()` 拒绝 Promise，`stream()` 发出 `error` chunk。`generate()` 和 `stream()` 也支持按次传入 `errorProcessors`，以替换本次请求中 Agent 的处理器列表。处理器共享的重试次数上限 `maxProcessorRetries` 参见[处理器](/docs/agents/processors#error-processor-retry-limits)。

### 目标 {/* #goal */}

默认情况下不会配置目标。传入 `goal` 但不提供 `prompt` 时，会使用 `DEFAULT_GOAL_JUDGE_PROMPT`。`goal` 配置包含评判模型和运行次数上限；目标内容则属于具体线程，通过 [`setObjective()`](/docs/harness/goals#managing-the-objective) 设置：

```typescript
import { createCodingAgent } from '@mastra/core/coding-agent'
import { Memory } from '@mastra/memory'

const agent = createCodingAgent({
  id: 'my-coding-agent',
  name: 'My Coding Agent',
  model: '__GATEWAY_OPENAI_MODEL_BASE__',
  instructions: 'You are a helpful coding assistant.',
  memory: new Memory(),
  goal: {
    judge: '__GATEWAY_OPENAI_MODEL_LUNA__',
    maxRuns: 50,
  },
})

const threadId = 'thread-1'
const resourceId = 'user-1'

await agent.setObjective('Get the test suite passing', { threadId, resourceId })
```

[目标](/docs/harness/goals)需要[存储](/docs/storage)后端和由 Memory 支撑的线程。若最终未解析到 `judge`，目标评判步骤不会执行任何操作。
