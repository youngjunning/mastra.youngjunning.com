# tools()

返回一个解析器，用于获取连接到 Mastra 平台项目的所有 Provider 的工具。将它传给 Agent 的 `tools` 选项后，Mastra 会在每次 `generate()` 和 `stream()` 时调用它。解析器会按 `ttlMs` 缓存工具；缓存过期后的下一次调用会触发后台刷新。

```typescript title="src/mastra/agents/ops.ts"
import { Agent } from '@mastra/core/agent'
import { tools } from '@mastra/connect'

export const opsAgent = new Agent({
  id: 'ops',
  name: 'ops',
  instructions: 'You help the team track work in Linear and GitHub.',
  model: '__GATEWAY_OPENAI_MODEL_LUNA__',
  tools: tools(),
})
```

返回：`ToolsResolver`，一个生成扁平工具记录的解析器，记录以工具键（例如 `linear_create_issue`）为索引。参见[解析器](#the-resolver)。

如需开始使用，参见 [Connect](/docs/mastra-platform/connect#add-tools-to-an-agent)。

### 按请求配置 {/* #per-request-options */}

传入回调而非选项对象，即可按请求调整配置，例如基于角色的筛选条件或审批策略。每次解析都会运行该回调（可同步或异步），并向它传入 Mastra 传给解析器的同一上下文；其中的 `requestContext` 会在解析器用作 Agent 的 `tools` 选项时被填充：

```typescript
const connected = tools(ctx => ({
  providers: {
    linear:
      ctx?.requestContext?.get('role') === 'viewer'
        ? { allowTools: ['linear_list_*'] }
        : { requireApproval: ['linear_delete_*'] },
  },
}))
```

解析器按不同选项值分别缓存快照，因此选项相同的请求会共用缓存，并遵循通常的 `ttlMs` 和过期时先返回旧值、后台重新验证的行为。不同调用返回的结构相同的选项视为同一值；但自定义 `client.fetch` 等不可序列化的值按身份比较。解析器最多为 32 种不同选项值保留缓存，超出后淘汰最近最少使用的一种。因此应从角色等有限的输入集合派生选项，避免使用无限变化的请求数据。

使用回调时，选项验证会在首次解析出某个选项值时进行，而非调用 `tools()` 时；验证错误会使该次解析失败。`refresh()` 会获取回调在无上下文时返回的选项对应的数据（与直接调用 `await connected()` 使用的变体相同），而 `disconnect()` 会关闭所有已缓存的变体。

## 解析器 {/* #the-resolver */}

返回的 `ToolsResolver` 会缓存工具。距上次获取未超过 `ttlMs` 时，直接返回缓存。过期后的首次调用仍会立即返回缓存，同时启动从平台后台获取数据的任务（过期时返回旧值并重新验证）。刷新成功后，后续调用使用新快照；刷新失败则继续使用缓存。只有调用解析器才会触发刷新，不会空闲轮询。可调用 `await connected.refresh()` 等待获取新工具记录。

如果需要普通的工具记录，例如在生成时传给 `toolsets` 选项，可直接调用解析器：

```typescript
import { tools } from '@mastra/connect'

const connected = tools()

const response = await agent.generate('Summarize my open issues.', {
  toolsets: { connect: await connected() },
})
```

解析器还提供以下手动控制方法：

- `refresh()` 立即从平台获取数据，随后更新缓存并返回工具记录。如果平台获取失败，则拒绝该 Promise。
- `disconnect()` 清除缓存快照，并关闭此解析器底层状态中的 MCP 传输。选项相同的解析器共享该状态，因此也会一同断开。后续解析会重建状态；之前已返回的 MCP 工具会在下次调用时重新连接。
- `with(extra)` 返回新解析器，将额外工具并入每次解析结果；工具键冲突时，额外工具优先。它接受静态工具记录或同步／异步函数，并支持链式调用。若要在 `tools` 回调中通过展开解析结果进行同样的合并，参见[向 Agent 添加工具](/docs/mastra-platform/connect#add-tools-to-an-agent)。
- `codeMode(options)` 通过 [Code Mode](#code-mode) 提供这些工具。

如果需要按工具键之外的条件筛选，或依据选项无法表达的数据筛选，可在 Agent 的 `tools` 函数中对解析结果做后处理。请在函数外创建一次解析器，以便共享缓存：

```typescript title="src/mastra/agents/ops.ts"
import { Agent } from '@mastra/core/agent'
import { tools } from '@mastra/connect'

const connectTools = tools({ providers: ['linear'] })
const viewerTools = new Set(['linear_list_issues'])

export const opsAgent = new Agent({
  id: 'ops',
  name: 'ops',
  instructions: 'You help the team track work in Linear.',
  model: '__GATEWAY_OPENAI_MODEL_LUNA__',
  tools: async ctx => {
    const all = await connectTools(ctx)

    if (ctx.requestContext?.get('role') === 'admin') {
      return all
    }
    return Object.fromEntries(Object.entries(all).filter(([key]) => viewerTools.has(key)))
  },
})
```

只有 `admin` 角色可使用所有工具。其他角色或未设置角色时，只能使用 viewer 子集。请在受信任的服务端代码中根据已认证用户设置 `role`。[按渠道调整工具](/reference/connect/channels#vary-tools-by-channel)对渠道消息采用相同模式。

错误处理取决于原因：

- 配置错误（缺少项目 ID 或令牌、Provider ID 格式错误、同一层级同时设置 `allowTools` 和 `disallowTools`、`ttlMs` 无效）会在调用 `tools()` 时抛出。使用[回调形式](#per-request-options)时，则会在首次解析出无效选项时失败。
- 如果平台目录确认某个已启用的 Provider ID 未知，解析会报 `invalid_options` 错误。单个 Provider 的筛选条件中有未知工具键或零匹配的通配符时也一样。如果无法访问目录，未知 ID 只会产生警告并被跳过。
- 如果缓存中已有快照，后台刷新失败时解析器会继续提供缓存中的工具集并发出警告；只有从未缓存过数据时才会拒绝请求。
- 某个 Provider 出现问题（例如连接需要重新授权）时，会记录警告并跳过该 Provider；其他 Provider 的工具仍会加载。

## Code Mode {/* #code-mode */}

`codeMode()` 通过 [Code Mode](/docs/agents/code-mode) 向 Agent 提供已连接的工具：Agent 编写一个 TypeScript 程序，以 `external_*` 函数调用工具，而非每个工具调用都占用独立步骤。当任务需要跨多个调用或 Provider 执行操作时可使用它，例如先列出一个 Provider 的条目，再到另一个 Provider 中逐一查询。

```typescript title="src/mastra/agents/ops.ts"
import { Agent } from '@mastra/core/agent'
import { LocalSandbox } from '@mastra/core/workspace'
import { tools } from '@mastra/connect'

const code = tools({ providers: ['linear', 'slack'] }).codeMode({ sandbox: new LocalSandbox() })

export const opsAgent = new Agent({
  id: 'ops',
  name: 'ops',
  instructions: async ctx => ['You help the team track work.', await code.instructions(ctx)],
  model: '__GATEWAY_OPENAI_MODEL_LUNA__',
  tools: code.tools,
})
```

:::warning

`LocalSandbox` 会以具有宿主机权限的 `node` 进程运行模型编写的程序。已连接工具返回的第三方数据（例如 Issue 文本）可能影响模型生成的代码。仅在受信任或本地开发场景使用 `LocalSandbox`。有关隔离方案，请参见 [Code Mode 工作原理](/docs/agents/code-mode#how-it-works)。

:::

`codeMode()` 返回 `tools` 和 `instructions` 两个函数，都需要传给 Agent。与解析器一样，它们会在每次请求时解析当前连接。随着 Provider 连接或断开，程序可调用的函数也会变化。同一请求中，两者使用同一次解析结果，指令不会声明程序无法调用的函数。

此方法接受所有 [`createCodeMode()` 选项](/reference/tools/create-code-mode)，但不包括 `tools`；可用选项为 `sandbox`、`timeout`、`id`。此外，还接受 `transport` 以使用[远程沙箱](/docs/agents/code-mode#remote-sandboxes)或[进程内隔离](/docs/agents/code-mode#in-process-isolation)，以及 `toolSearch` 以启用[工具搜索](#tool-search)。所有解析器都支持此方法，包括回调形式及 `with()` 返回的解析器。通过 `with()` 添加的额外工具也会成为程序可调用的函数。

有些工具会保留为 Agent 直接调用的工具，而不成为程序函数，因为它们会暂停 Agent 运行，程序内部无法执行这类调用：

- 通过 `requireApproval` 要求审批的工具。Agent 仍会等待用户批准每次调用。
- `request_connection` 工具，以便连接提示能暂停运行，直到用户完成连接。

对于 [MCP Provider](#mcp-providers)，`requireApproval` 列表会使该 Provider 的**所有**工具保留为直接工具，包括列表中未列出的工具。Mastra 在请求时发现 MCP 工具，并在每次调用时核对列表，因此 Code Mode 无法提前判断哪些调用需要审批，于是将该 Provider 的所有工具排除在程序之外。生成的 HTTP 工具则不同，只有匹配列表的工具保留为直接工具。

```typescript
// Every neon-mcp tool stays direct, not just neon-mcp_run_sql
const ops = tools({
  providers: { 'neon-mcp': { requireApproval: ['neon-mcp_run_sql'] } },
}).codeMode({ sandbox })
```

若要让程序调用该 Provider 的其他工具，可用 `disallowTools` 移除受审批限制的工具，而非对其设置审批。若仍需审批，Agent 就必须逐一调用该 Provider 的工具。

当没有可编排的工具（例如项目尚无连接）时，`tools` 只返回直接工具，`instructions` 返回空字符串。

### 工具搜索 {/* #tool-search */}

每次请求都在指令中声明全部函数会消耗上下文：仅 Linear 约需 4,000 个 Token，Linear、GitHub 和 Stripe 合计超过 20,000 个。启用工具搜索后，指令只列出函数名；Agent 会得到 `search_functions` 工具，用于检索所需函数的 TypeScript 声明。Agent 可按预期操作或列表中的准确名称搜索，再编写程序。程序仍能调用所有函数，只是声明改为按需检索。

如果声明所有函数需要超过约 10,000 个 Token，工具搜索会自动启用。也可设置 `toolSearch` 进行选择：

```typescript title="src/mastra/agents/ops.ts"
// Always list names only and search for declarations
const searching = tools().codeMode({ sandbox: new LocalSandbox(), toolSearch: true })

// Always declare every function up front
const declared = tools().codeMode({ sandbox: new LocalSandbox(), toolSearch: false })
```

## 选择 Provider {/* #choosing-providers */}

`providers` 的数组形式是允许列表，只返回列出的 Provider。若不设置此项，则包含所有已连接且具有受支持工具集的 Provider。列出的 Provider 若尚未在项目中建立连接，会先被跳过；连接建立后会自动纳入。记录形式中，`false` 可排除一个 Provider，即使 ID 不匹配任何 Provider 也不会报错。

使用数组可将发现范围限制为指定 Provider；使用记录则可配置指定 Provider，同时保留其他 Provider：

```typescript
const onlyLinear = tools({ providers: ['linear'] })
const allWithLinearApproval = tools({
  providers: { linear: { requireApproval: true } },
})
```

各 Provider 的 `allowTools` 和 `disallowTools` 工具键列于 [Provider 工具集参考](/reference/connect/providers)。

## 连接解析 {/* #connection-resolution */}

对于项目中已有连接的每个 Provider：

1. 显式设置的 `connectionId` 优先。
1. 否则，若只有一个活动连接，就自动使用它。
1. 否则，不固定连接，并在每次调用时选择：工具集会增加 `<provider>__list_connections` 工具；其他工具都要求输入 `connection_name`；Agent 根据 `list_connections` 返回的显示名称为每次调用选择连接。如果 `connection_name` 不匹配任何活动连接，该次调用会报 `unknown_connection` 错误。

合成的 `list_connections` 辅助工具无需审批；即使顶层 `allowTools` 或 `disallowTools` 筛选条件本会排除它，它仍可使用。

处于 `needs_reauth` 状态的连接会被跳过并记录警告，直至有人[重新授权](/reference/cli/mastra#replace-a-connection-that-needs-reauthorization)。

## MCP Provider {/* #mcp-providers */}

除了生成的工具集，解析器还会发现平台目录中声明支持 MCP 的已连接 Provider。发现的工具遵循同一扁平契约，以 `<provider-id>_<tool-name>` 作为命名空间。若一个 Provider 同时有生成的工具集和 MCP 能力，优先使用 MCP 目录。

应用仅发送自身的平台令牌。在向 Provider 的 MCP 服务器代理每个协议请求之前，平台会移除调用方身份认证，并注入 Provider 凭据。MCP 会话在刷新间复用；连接发生变化、Provider 断开或调用 `disconnect()` 时关闭。

发现的 MCP 工具与生成的工具遵循相同审批策略：默认无需审批，除非设置 `requireApproval`，例如 `'neon-mcp': { requireApproval: ['neon-mcp_run_sql'] }`。传入已移除的 `autoApproveTools` 键会在调用时抛出 `invalid_options` 错误。

## 环境变量 {/* #environment-variables */}

`tools()`、`channels()` 和 `credential()` 会读取以下环境变量。代码中传入的选项优先。

| 变量 | 用途 |
| - | - |
| `MASTRA_PLATFORM_ACCESS_TOKEN` | 用于认证每个请求的平台访问令牌 |
| `MASTRA_PLATFORM_SECRET_KEY` | 未设置 `MASTRA_PLATFORM_ACCESS_TOKEN` 时使用的后备令牌 |
| `MASTRA_PROJECT_ID` | 用于获取连接的项目 ID |
| `MASTRA_ORG_ID` | 组织 ID；设置后通过 `x-organization-id` 请求头发送 |
| `MASTRA_PLATFORM_REGION` | `us` 或 `eu`；选择 `https://integrations.us.mastra.ai` 或 `https://integrations.eu.mastra.ai`，而非默认的 `https://integrations.mastra.ai` |
| `MASTRA_INTEGRATIONS_API_URL` | Connect API 基础 URL；覆盖区域设置 |

## 错误 {/* #errors */}

抛出 `MastraConnectError`，其中包含 `code` 属性：

| 错误码 | 触发条件 |
| - | - |
| `missing_project_id` | 未配置项目 ID |
| `missing_access_token` | 未配置平台令牌 |
| `invalid_options` | Provider ID 未知或格式错误、筛选条件冲突、工具键或通配符重复或无匹配项，或 `ttlMs` 无效 |
| `unauthorized` | 平台拒绝令牌（401/403） |
| `proxy_error` | 代理到 Provider 的请求失败；`status` 和 `detail` 包含 Provider 响应 |
| `unknown_connection` | 工具调用传入的 `connection_name` 不匹配任何活动连接 |
| `platform_error` | 其他平台请求失败 |
