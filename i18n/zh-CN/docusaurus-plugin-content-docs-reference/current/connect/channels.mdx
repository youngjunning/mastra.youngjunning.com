# channels()

此函数根据 Mastra 平台项目关联的连接，返回可传给 `new Mastra({ channels })` 的动态频道解析器。启用的 Provider 实例只构造一次，且构造时不需要凭据，因此在构造 `Mastra` 时就能挂载其 Webhook 和 OAuth 路由。解析器会缓存项目连接；连接变化时，它会为这些实例绑定凭据，无需重新部署应用。

```typescript title="src/mastra/index.ts"
import { Mastra } from '@mastra/core'
import { channels } from '@mastra/connect'

export const mastra = new Mastra({
  agents: { assistant },
  channels: await channels(),
})
```

返回：`Promise<ChannelsResolver>`。参见[解析器](#the-resolver)。

各 Provider 的集成页面介绍了频道设置：[Slack](/integrations/channels/slack#agent-chat)、[Telegram](/integrations/channels/telegram#connect)、[Discord](/integrations/channels/discord#agent-chat) 和 [Microsoft Teams](/integrations/channels/teams#agent-chat)。实现分别来自按需加载的 `@mastra/slack`、`@mastra/telegram`、`@mastra/discord` 和 `@mastra/teams`。如果要在平台连接流程之外配置频道，可直接使用这些包。

设置 `MASTRA_ENCRYPTION_KEY` 后，Teams Provider 会用它加密已存储的 Bot 密钥。未设置时，密钥会从平台访问令牌派生；只要 Teams 连接处于活动状态，系统就会记录警告。轮换平台访问令牌会使已存储的 Bot 凭据无法读取，需要断开连接并重新连接以重新配置。没有 Teams 连接的项目不受影响。

## 解析器 {/* #the-resolver */}

解析出的 `ChannelsResolver` 符合 `@mastra/core` 的频道解析器契约：

* **可调用**：返回当前具有活动连接的 Provider 的 `Record<string, ChannelProvider>`。Mastra 在运行时调用它，并借助 TTL 缓存降低重复调用的开销。只有首次解析会等待平台响应。TTL 到期后，解析器立即返回旧快照，同时在后台刷新；若上次获取失败，则会在短暂冷却期内跳过刷新。因此，新连接可能比 TTL 指示的时间晚一次解析才出现。
* `getRoutes()`：同步返回所有已启用频道的 API 路由，以便 Mastra 在构造时挂载。无论 Provider 是否已有活动连接，这些路由都会存在。
* `refresh()`：立即从平台获取连接并更新缓存。如果获取失败，Promise 会被拒绝。
* `disconnect()`：清除缓存快照，使下次解析重新获取连接；它不会销毁 Provider、会话或凭据。

没有活动连接的 Provider 不会出现在解析结果中；其路由仍保持挂载，并会在关联连接后开始工作。

错误处理与 [`tools()`](/reference/connect/tools) 一致：配置错误（缺少项目 ID、无效的 `ttlMs`、未知或格式错误的 Provider ID，或同时使用 Slack 键的两种写法）会在调用时拒绝；单个 Provider 的问题（构造失败、`needs_reauth`、凭据同步失败）只会记录警告并跳过。若同一 Provider 有多个活动连接，解析器会警告并使用第一个；可通过 `providers.<id>.connectionId` 指定连接。首次解析时平台获取失败会导致拒绝。后台刷新失败会警告并保留缓存快照，而显式调用 `refresh()` 时获取失败会导致拒绝。

## 与自行管理的频道组合 {/* #combine-with-self-managed-channels */}

`channels()` 会替换整个 `channels` 选项，且没有内置工具可将其与自行构造的 Provider 合并。若部分频道使用 Connect，另一部分自行管理，请用一个解析器封装两者。封装结果必须可调用，并提供返回所有 Provider 路由的 `getRoutes()`，因为 Mastra 只会在构造时挂载一次频道路由：

```typescript title="src/mastra/index.ts"
import { Mastra } from '@mastra/core'
import { channels } from '@mastra/connect'
import { TelegramProvider } from '@mastra/telegram'
import { assistant } from './agents/assistant'

const connectChannels = await channels({ providers: ['slack', 'discord'] })
const telegram = new TelegramProvider()

export const mastra = new Mastra({
  agents: { assistant },
  channels: Object.assign(async () => ({ ...(await connectChannels()), telegram }), {
    getRoutes: () => [...connectChannels.getRoutes(), ...telegram.getRoutes()],
  }),
})
```

如示例中的数组形式所示，应从 Connect 选择中排除自行管理的频道。Mastra 不会检测两个 Provider 是否注册了同一条路由；若两处都启用同一频道，就会挂载冲突的 Webhook。请在封装器外只构造一次自行管理的 Provider：Mastra 对每个不同的 Provider 实例只会附加一次。凭据配置请参阅 [Telegram Provider 参考](/reference/channels/telegram-provider)。

## 按频道调整 Tool {/* #vary-tools-by-channel */}

频道消息会将 [`ChannelContext`](/integrations/channels/slack#request-context) 放在[请求上下文](/docs/server/request-context)的 `channel` 键下。其中包含平台、会话是否为私信（`isDM`）、频道和线程 ID，以及发送者的用户 ID 和姓名。Agent 的 `tools` 函数可读取这些信息，筛选 [`tools()`](/reference/connect/tools) 解析出的对象：

```typescript title="src/mastra/agents/assistant.ts"
import { Agent } from '@mastra/core/agent'
import type { ChannelContext } from '@mastra/core/channels'
import { tools } from '@mastra/connect'

const connectTools = tools({ providers: ['linear'] })
const readTools = new Set(['linear_list_issues'])

export const assistant = new Agent({
  id: 'assistant',
  name: 'assistant',
  instructions: 'You help the team track work in Linear from Slack and Discord.',
  model: '__GATEWAY_OPENAI_MODEL_LUNA__',
  tools: async ctx => {
    const channel = ctx.requestContext?.get('channel') as ChannelContext | undefined
    const all = await connectTools(ctx)

    if (channel?.isDM && ctx.requestContext?.get('role') === 'operator') {
      return all
    }
    return Object.fromEntries(Object.entries(all).filter(([key]) => readTools.has(key)))
  },
})
```

这里，只有应用识别为操作员的用户发送的私信才能使用完整的 Linear Tool 集；其他请求只能使用 `linear_list_issues`。验证发送者身份和权限后，应在可信的服务端代码中设置 `role`。不要仅凭会话类型授予写入权限。如果要通过选项筛选，而不是事后筛选，请参阅[单次请求选项](/reference/connect/tools#per-request-options)。

## Discord 权限 {/* #discord-permissions */}

Discord Bot 邀请 URL 会申请 `bot` 和 `applications.commands` 两个 scope，并请求以下权限：

* **查看频道**
* **发送消息**
* **在话题中发送消息**
* **嵌入链接**
* **附加文件**
* **阅读消息历史记录**
* **添加反应**
* **使用应用程序命令**

这些权限支持聊天、线程、文件、表情回应和斜杠命令，但不授予管理或频道管理权限。可通过 `providers.discord.providerOptions.permissions` 覆盖权限位字段。各位的值请参阅 [Discord 权限参考](https://discord.com/developers/docs/topics/permissions#permissions-bitwise-permission-flags)。

## 错误 {/* #errors */}

抛出 `MastraConnectError`，其中包含 `code` 属性：

| 错误代码 | 发生条件 |
| - | - |
| `missing_project_id` | 未配置项目 ID |
| `missing_access_token` | 未配置平台令牌 |
| `invalid_options` | Provider ID 未知或格式错误、同一配置中同时使用 `slack` 与 `slack-channels`、Provider 条目格式错误，或 `ttlMs` 无效 |
| `no_active_connection` | 频道需要凭据，但其 Provider 没有活动连接 |
| `unauthorized` | 平台拒绝了令牌（401/403） |
| `platform_error` | 其他平台请求失败 |
