# Mastra.getMCPServer()

`.getMCPServer()` 根据注册键（在 `mcpServers` 配置中注册服务器时使用的键）获取 MCP 服务器实例。如果要根据服务器自身的 `id` 属性查找，请使用 `.getMCPServerById()`。

## 使用示例 {/* #usage-example */}

```typescript
// Register an MCP server with a registry key
const myServer = new MCPServer({
  id: 'my-mcp-server',
  name: 'My Server',
  version: '1.0.0',
  tools: {/* ... */},
})

export const mastra = new Mastra({
  mcpServers: {
    customKey: myServer, // 'customKey' is the registry key
  },
})

// Retrieve by registry key
const server = mastra.getMCPServer('customKey')

// Alternatively, retrieve by intrinsic ID
const serverById = mastra.getMCPServerById('my-mcp-server')
```

## `MCPServerBase` 契约 {/* #the-mcpserverbase-contract */}

每个已注册的服务器都扩展 `MCPServerBase`，该基类来自 `@mastra/core/mcp`。`MCPServer` 类来自 `@mastra/mcp`，针对 MCP `2026-07-28` 协议实现该基类，并将 `mcpVersion` 设为 `2`。Tool 作者可接触到的契约包括 Tool 执行、暂停，以及下文所述的 `context.mcp` 结构。仅适用于 1.x、如今作为弃用存根保留在基类中的成员，参见[迁移指南](/reference/migrations/mcp-v2)。

### 请求用户输入的 Tool {/* #tools-that-ask-for-input */}

MCP 服务器运行普通的 `createTool` 定义。如果 Tool 需要用户提供信息才能完成，就像在 Agent 或 Workflow 中一样，需声明 `suspendSchema` 和 `resumeSchema`，并调用 `suspend()`。Core 以 `{ status: 'suspended', suspendPayload, resumeSchema }` 报告 `executeTool` 中发生的暂停。`MCPServer` 将其转换为协议层的一轮 `input_required` 交互，并通过 `resumeData` 中的回答恢复 Tool。

```typescript
import { createTool } from '@mastra/core/tools'
import { z } from 'zod'

const confirm = createTool({
  id: 'confirm',
  description: 'Ask for confirmation before charging',
  inputSchema: z.object({ amount: z.number() }),
  outputSchema: z.boolean(),
  suspendSchema: z.object({ phase: z.literal('confirm'), amount: z.number() }),
  resumeSchema: z.object({ confirmed: z.boolean() }),
  execute: async ({ amount }, context) => {
    if (!context.resumeData) {
      await context.suspend?.({ phase: 'confirm', amount })
      return
    }
    return context.resumeData.confirmed
  },
})
```

在 MCP 服务器或直接执行时，`suspend`、`resumeData` 和 `suspendPayload` 位于 Tool 上下文的顶层。Agent 和 Workflow 中的这些成员仍分别位于 `context.agent` 和 `context.workflow` 下，直到 `@mastra/core` 下一个主版本发布。`resumeSchema` 必须是仅包含基本类型字段的扁平对象，才能显示为输入表单。

每一轮都是独立请求。`resumeData` 只携带当前轮次的回答，并按 `resumeSchema` 验证；`suspendPayload` 携带 Tool 上次暂停时提交的数据。框架不会重放先前轮次，因此处理程序需根据明确命名的阶段分支处理，每轮都要重新授权，写入操作则依赖业务领域自身的幂等机制。由 Agent 和 Workflow 恢复的 Tool 也会收到 `suspendPayload`。

### `mcp` 上下文 {/* #the-mcp-context */}

Tool 会收到 `context.mcp`（`MCPToolExecutionContext`）：其中的 `extra` 包含请求的 `signal`、`requestId`、`authInfo` 和 `_meta`，此外还有 `log(level, message, data?)`、`progress({ progress, total?, message? })` 以及 `protocolVersion`（`'2026-07-28'`）。需要用户输入时，调用 `context.suspend()` 并读取 `context.resumeData`。该协议不支持服务器发起请求，因此已弃用的 `elicitation.sendRequest`、`extra.sendRequest` 和 `extra.sendNotification` 成员会抛出错误，并在错误消息中指出替代方式。

### 注册与执行 {/* #registration-and-execution */}

注册服务器时，其 Tool 也会注册到 Mastra 实例。`executeTool(toolId, args, context?)` 返回 `{ status: 'completed', output }`；如果 Tool 暂停，则返回 `{ status: 'suspended', suspendPayload, resumeSchema }`，其中 `resumeSchema` 为 JSON Schema。结果中没有表示失败的变体：Tool 抛错，或输入、恢复数据未通过其 schema 验证时，Promise 会被拒绝。REST 执行端点会返回暂停状态，而不会误报 Tool 已完成；下次调用时可传入 `resumeData` 和原样回传的 `suspendPayload`，继续执行 Tool。

如果某个注册键已被占用，再用该键注册另一台服务器仍会保留原有实例。注册键与服务器自身的 ID 是不同的概念。
