# Mastra.addDynamicWorkflows()

:::测试版

在 API 稳定之前，可能会在没有重大版本更新的情况下发生重大更改。

:::

这`.addDynamicWorkflows()` method adds a bundle of dynamic workflow definitions that may reference each other. The typical case is a root workflow plus helper workflows it nests, where none of the definitions exist yet.

整个捆绑包都经过预先验证。然后，成员按依赖顺序注册，因此助手始终位于嵌套它的Workflow之前。

[`addDynamicWorkflow()`](/reference/core/addDynamicWorkflow)是单成员的情况。

## 使用示例 {/* #usage-example */}

```typescript
await mastra.addDynamicWorkflows([
  helperDefinition, // nested by the root — order in the array doesn't matter
  rootDefinition, // graph contains { type: 'workflow', workflowId: helperDefinition.id }
])
```

## 退货 {/* #returns */}

一旦每个成员都经过验证、注册和持久化，承诺就会得到解决。

## 行为 {/* #behavior */}

* 引用根据实例的注册表并结合捆绑包自己的 ID 进行解析，因此根可以嵌套在同一调用中引入的帮助程序。注册顺序是从依赖图导出的，而不是数组顺序。
* 被拒绝的捆绑包不会注册任何内容。在任何内容发生变异之前，都会检测到重复的 ID、无效成员和依赖循环，并且如果注册或持久性中途失败，内存中的注册表将恢复到其之前的状态。
* 存储写入最后发生。中间捆绑包中的存储级故障可能会留下一些写入的行，但注册表仍会回滚，并且孤立的行在下次启动之前处于惰性状态。
