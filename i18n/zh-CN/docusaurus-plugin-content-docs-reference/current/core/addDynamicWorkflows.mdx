# Mastra.addDynamicWorkflows()

:::beta

在 API 稳定之前，即使不提升主版本号，也可能引入破坏性变更。

:::

`.addDynamicWorkflows()` 方法添加一组可能互相引用的动态 Workflow 定义。典型场景是一个根 Workflow 及其嵌套的辅助 Workflow，并且这些定义此前都尚未存在。

系统会预先验证整个定义包，然后按依赖顺序注册各成员，确保辅助 Workflow 总是在嵌套它的 Workflow 之前就绪。

[`addDynamicWorkflow()`](/reference/core/addDynamicWorkflow) 用于只添加一个成员的场景。

## 使用示例 {/* #usage-example */}

```typescript
await mastra.addDynamicWorkflows([
  helperDefinition, // nested by the root — order in the array doesn't matter
  rootDefinition, // graph contains { type: 'workflow', workflowId: helperDefinition.id }
])
```

## 返回值 {/* #returns */}

返回一个 Promise；所有成员完成验证、注册和持久化后，该 Promise 即完成。

## 行为 {/* #behavior */}

* 引用会从实例 registry 与定义包自身 ID 的并集中解析，因此根 Workflow 可以嵌套同一次调用中新增的辅助 Workflow。注册顺序由依赖图决定，与数组顺序无关。
* 被拒绝的定义包不会注册任何内容。系统会在修改任何内容前检测重复 ID、无效成员和依赖环；如果注册或持久化中途失败，内存中的 registry 会恢复到先前状态。
* 存储写入最后执行。如果定义包写入途中发生存储层故障，可能会留下部分已写入的行，但 registry 仍会回滚；这些孤立行在下次启动前不会生效。
