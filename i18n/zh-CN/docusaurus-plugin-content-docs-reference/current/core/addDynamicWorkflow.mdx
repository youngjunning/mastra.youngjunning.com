# Mastra.addDynamicWorkflow()

:::beta

API 稳定之前，可能出现不伴随主版本号升级的破坏性变更。

:::

`.addDynamicWorkflow()` 会验证动态 Workflow 定义，将其注册为实例中可运行的 Workflow，并通过 `workflowDefinitions` 存储域持久化。注册后，可像其他 Workflow 一样通过 [`getWorkflow()`](/reference/core/getWorkflow) 运行它。

完整配置示例参见[动态 Workflow](/docs/workflows/dynamic-workflows)；支持的字段和图节点参见[动态 Workflow 定义参考](/reference/workflows/dynamic-workflow-definition)。

## 使用示例 {/* #usage-example */}

```typescript
await mastra.addDynamicWorkflow({
  id: 'greeting-workflow',
  description: 'Returns a greeting for the supplied name',
  inputSchema: {
    type: 'object',
    properties: { name: { type: 'string' } },
    required: ['name'],
  },
  outputSchema: {
    type: 'object',
    properties: { message: { type: 'string' } },
    required: ['message'],
  },
  graph: [
    {
      type: 'mapping',
      id: 'create-greeting',
      mapConfig: JSON.stringify({
        message: { template: 'Hello, ${initData.name}!' },
      }),
    },
  ],
})

const run = await mastra.getWorkflow('greeting-workflow').createRun()
const result = await run.start({ inputData: { name: 'Ada' } })
```

## 返回值 {/* #returns */}

返回一个 Promise：定义完成验证和注册后兑现；如果存储提供 `workflowDefinitions` store，还会先完成持久化。

## 行为 {/* #behavior */}

- 在修改任何内容前，会完整验证定义的结构、引用及 schema 流。图中引用的 Agent、Tool 和 Workflow 必须已注册到当前实例。
- 使用已有 ID 添加定义，会同时替换已存储的定义和当前注册的 Workflow。运行中的任务仍使用启动时的图。
- 如果存储适配器不支持 `workflowDefinitions` 域，Workflow 仍会经过验证并注册到内存中，但重启后定义会丢失。
- 若要同时添加根 Workflow 及其嵌套的辅助 Workflow，请使用 [`addDynamicWorkflows()`](/reference/core/addDynamicWorkflows)。
