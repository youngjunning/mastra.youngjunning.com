# Mastra.addDynamicWorkflow()

:::测试版

在 API 稳定之前，可能会在没有重大版本更新的情况下发生重大更改。

:::

这`.addDynamicWorkflow()` method validates a dynamic workflow definition and registers it as a live workflow on the instance, persisting it through the `workflowDefinitions` storage domain. Once registered, the workflow runs like any other workflow via [`getWorkflow()`](/reference/core/getWorkflow).

看[Dynamic workflows](/docs/workflows/dynamic-workflows) for a complete setup example and the [dynamic workflow definition reference](/reference/workflows/dynamic-workflow-definition) for the accepted fields and graph entries.

## 使用示例 {/* #usage-example */}

```typescript
await mastra.addDynamicWorkflow({
  id: 'greeting-workflow',
  description: 'Returns a greeting for the supplied name',
  inputSchema: {
    type: 'object',
    properties: { name: { type: 'string' } },
    required: ['name'],
  },
  outputSchema: {
    type: 'object',
    properties: { message: { type: 'string' } },
    required: ['message'],
  },
  graph: [
    {
      type: 'mapping',
      id: 'create-greeting',
      mapConfig: JSON.stringify({
        message: { template: 'Hello, ${initData.name}!' },
      }),
    },
  ],
})

const run = await mastra.getWorkflow('greeting-workflow').createRun()
const result = await run.start({ inputData: { name: 'Ada' } })
```

## 退货 {/* #returns */}

一旦定义被验证和注册，就会解决的承诺，并在存储提供时持续存在`workflowDefinitions` store.

## 行为 {/* #behavior */}

* 在任何内容发生变化之前，定义都经过充分验证（结构、引用、模式流）。图表引用的Agent、Tool和Workflow必须已在实例上注册。
* 添加具有现有 ID 的定义会替换存储的定义和实时注册。飞行中的运行会保留开始时的图表。
* 没有支持的存储适配器`workflowDefinitions` domain, the workflow is still validated and registered in memory, but the definition is lost on restart.
* 要将根Workflow程及其嵌套的辅助Workflow程添加到一起，请使用[`addDynamicWorkflows()`](/reference/core/addDynamicWorkflows).
