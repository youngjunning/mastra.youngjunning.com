# MastraModelGateway

用于实现自定义模型网关的抽象基类。网关负责访问语言模型时与提供者相关的逻辑，包括提供者配置、身份验证、URL 构建和模型实例创建。

如果想以普通对象提供网关，而非继承基类，请使用 `MastraModelGatewayInterface`。

## 类概览 {/* #class-overview */}

安装此示例使用的 OpenAI 兼容提供者：

```bash npm2yarn
npm install @ai-sdk/openai-compatible
```

```typescript
import {
  MastraModelGateway,
  type GatewayLanguageModel,
  type ProviderConfig,
} from '@mastra/core/llm'
import { createOpenAICompatible } from '@ai-sdk/openai-compatible'

class MyCustomGateway extends MastraModelGateway {
  readonly id = 'custom'
  readonly name = 'My Custom Gateway'

  async fetchProviders(): Promise<Record<string, ProviderConfig>> {
    return {
      'my-provider': {
        name: 'My Provider',
        models: ['__GATEWAY_OPENAI_MODEL__', '__GATEWAY_ANTHROPIC_MODEL_SONNET__'],
        apiKeyEnvVar: 'MY_API_KEY',
        gateway: this.id,
      },
    }
  }

  buildUrl(modelId: string, envVars?: Record<string, string>): string {
    return 'https://api.my-provider.com/v1'
  }

  async getApiKey(modelId: string): Promise<string> {
    const apiKey = process.env.MY_API_KEY
    if (!apiKey) throw new Error('MY_API_KEY not set')
    return apiKey
  }

  async resolveLanguageModel({
    modelId,
    providerId,
    apiKey,
  }: {
    modelId: string
    providerId: string
    apiKey: string
  }): Promise<GatewayLanguageModel> {
    const baseURL = this.buildUrl(`${providerId}/${modelId}`)
    return createOpenAICompatible({
      name: providerId,
      apiKey,
      baseURL,
    }).chatModel(modelId)
  }
}
```

## 模型 ID 格式 {/* #model-id-format */}

对于真正的网关，网关 ID 用作前缀，模型按以下格式访问：

```text
[gateway-id]/[provider]/[model]
```

示例：

- `id = 'custom'` 的网关：`'custom/my-provider/model-1'`

也支持由两部分组成的 ID：

- `[gateway-id]/[model]`：适用于提供者 ID 与网关 ID 相同的网关，例如 `amazon-bedrock`。提供者 ID 会解析为网关 ID，因此 `'custom/model-1'` 会解析为提供者 `custom` 和模型 `model-1`。模型部分不能为空。
- `azure-openai/[deployment]`：Azure OpenAI 使用部署名称代替提供者和模型。
