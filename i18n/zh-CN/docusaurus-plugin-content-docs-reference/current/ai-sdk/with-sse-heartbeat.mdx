# withSseHeartbeat()

包装服务器发送事件（SSE）的 `Response`，在底层流空闲时定期发送 `: heartbeat` 注释。代理和负载均衡器往往会关闭长时间没有字节传输的连接，导致长时间推理或缓慢的 Tool 调用期间响应中断。

使用 [`handleChatStream()`](/reference/ai-sdk/handle-chat-stream)、[`handleWorkflowStream()`](/reference/ai-sdk/handle-workflow-stream) 或 [`handleNetworkStream()`](/reference/ai-sdk/handle-network-stream) 自行构建响应时，可使用此函数。[`chatRoute()`](/reference/ai-sdk/chat-route) 会通过 `heartbeatMs` 选项在内部应用相同的包装逻辑。

## 使用示例 {/* #usage-example */}

Next.js App Router 示例：

```typescript title="app/api/chat/route.ts"
import { handleChatStream, withSseHeartbeat } from '@mastra/ai-sdk'
import { createUIMessageStreamResponse } from 'ai'
import { mastra } from '@/src/mastra'

export async function POST(req: Request) {
  const params = await req.json()
  const stream = await handleChatStream({
    mastra,
    agentId: 'weatherAgent',
    version: 'v7',
    params,
  })
  return withSseHeartbeat(createUIMessageStreamResponse({ stream }), 15000)
}
```

应在响应编码后再进行包装。`handleChatStream()` 返回 UI 消息块流；心跳是原始 SSE 注释，只有这些块序列化为传输格式后才能插入。

## 返回值 {/* #returns */}

返回一个 `Response`，以流式传输原响应体，并在空闲时插入心跳注释。如果省略 `heartbeatMs`、其值小于等于 `0`，或响应没有正文，则原样返回输入的响应。

## 行为 {/* #behavior */}

- 心跳只会插入完整 SSE 帧之间，不会拆分尚未传输完的帧。
- 源数据、流结束和流错误始终优先于到期的心跳。
- 取消包装后的响应会同时取消源流，并清除待触发的心跳计时器。
- 启用心跳时，如果传入的值无法由计时器调度，就会抛出 `RangeError`（非有限数或大于 `2147483647` 的值）。开始流式传输前，可使用 `assertValidHeartbeatMs()` 对用户提供的配置执行同样的检查。
