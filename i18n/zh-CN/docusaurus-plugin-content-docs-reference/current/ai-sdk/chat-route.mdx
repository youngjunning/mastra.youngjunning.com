# 聊天路由()

以 AI SDK 格式为流Agent对话创建聊天路由处理程序。该函数注册一个 HTTP`POST`在以 AI SDK 兼容格式将响应流式传输到客户端之前接受消息并执行Agent的端点。在 a 内使用它[自定义API路由](/docs/server/custom-api-routes).

使用[`handleChatStream()`](/reference/ai-sdk/handle-chat-stream) if you need a framework-agnostic handler.

`chatRoute()`保留现有的 AI SDK v5/默认行为。如果您的应用程序是针对 AI SDK v6 输入的，请传递`version: 'v6'`.

:::note 断开连接行为

默认情况下，`chatRoute()` forwards the incoming request's `AbortSignal` to `agent.stream()`. If the client disconnects, Mastra aborts the in-flight generation.

放`resumable: true` to let the generation continue after a disconnect and allow AI SDK UI to reconnect to the active stream. Resumable chats don't support abort-based cancellation because `useChat().stop()` is indistinguishable from a refresh or network interruption at the server.

:::

## 使用示例 {/* #usage-example */}

此示例显示如何在`/chat` endpoint that uses an agent with the ID `weatherAgent`.

```typescript title="src/mastra/index.ts"
import { Mastra } from '@mastra/core'
import { chatRoute } from '@mastra/ai-sdk'

export const mastra = new Mastra({
  server: {
    apiRoutes: [
      chatRoute({
        path: '/chat',
        agent: 'weatherAgent',
      }),
    ],
  },
})
```

您还可以使用基于运行时定义的Agent路由`agentId`. The URL `/chat/weatherAgent` will resolve to the agent with the ID `weatherAgent`.

```typescript title="src/mastra/index.ts"
import { Mastra } from '@mastra/core'
import { chatRoute } from '@mastra/ai-sdk'

export const mastra = new Mastra({
  server: {
    apiRoutes: [
      chatRoute({
        path: '/chat/:agentId',
      }),
    ],
  },
})
```

## 可恢复的流 {/* #resumable-streams */}

放`resumable: true` on `chatRoute()` and `resume: true` on AI SDK UI's `useChat()` to reconnect after a refresh or network interruption. The route factory returns a two-item array containing:

* `POST <path>`：启动Agent运行。请求的 AI SDK 聊天 ID 成为 Mastra 内存线程 ID。
* `GET <path>/:chatId/stream`：重播缓存的事件并跟踪活动运行。路线返回`204` when the run is finished, unavailable, expired, or outside the caller's scope.

将返回的数组作为一个条目传递给`server.apiRoutes`. Mastra flattens nested route arrays during server configuration.

```typescript title="src/mastra/index.ts"
import { Mastra } from '@mastra/core'
import { chatRoute } from '@mastra/ai-sdk'

export const mastra = new Mastra({
  server: {
    apiRoutes: [
      chatRoute({
        path: '/chat/:agentId',
        resumable: true,
      }),
    ],
  },
})
```

主动运行发现是进程本地的。重新连接请求必须到达启动生成的同一正在运行的服务器进程。可恢复模式不转发请求`AbortSignal`, so `useChat().stop()` closes the client connection without cancelling the agent run.

如果聊天使用资源ID，则设置`MASTRA_RESOURCE_ID_KEY` in the request context through authentication middleware. Don't send the resource ID only as `memory.resource` in the POST body: the reconnecting GET request has no body, so `chatRoute()` rejects that configuration with `400`.

## 附加配置 {/* #additional-configuration */}

您可以使用[`prepareSendMessagesRequest`](https://ai-sdk.dev/docs/reference/ai-sdk-ui/use-chat#transport.default-chat-transport.prepare-send-messages-request) to customize the request sent to the chat route, for example to pass additional configuration to the agent:

```typescript
const { error, status, sendMessage, messages, stop } = useChat({
  transport: new DefaultChatTransport({
    api: 'http://localhost:4111/chat',
    prepareSendMessagesRequest({ messages }) {
      return {
        body: {
          // With memory configured, send only the new message. Mastra loads the
          // rest of the conversation from storage.
          messages: [messages[messages.length - 1]],
          // Pass memory config
          memory: {
            thread: 'user-1',
            resource: 'user-1',
          },
        },
      }
    },
  }),
})
```

没有记忆，发送完整`messages` array as the chat route uses it as the request context.

有了内存，存储的线程就是真相的来源，所以`regenerate` and editing an earlier message in `useChat` don't change it. To change stored history, use `memory.saveMessages` or the memory store's `updateMessages`, then send a new message.
