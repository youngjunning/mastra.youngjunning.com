# chatRoute()

创建以 AI SDK 格式串流传输 Agent 对话的聊天路由处理程序。此函数注册 HTTP `POST` 端点，接收消息、执行 Agent，再以兼容 AI SDK 的格式将响应串流传输给客户端。请在[自定义 API 路由](/docs/server/custom-api-routes)中使用。

如果需要与框架无关的处理程序，请使用 [`handleChatStream()`](/reference/ai-sdk/handle-chat-stream)。

`chatRoute()` 保持现有的 AI SDK v5 默认行为。如果应用使用 AI SDK v6 的类型定义，请传入 `version: 'v6'`。

:::note 断开连接时的行为

默认情况下，`chatRoute()` 会将传入请求的 `AbortSignal` 传给 `agent.stream()`。如果客户端断开连接，Mastra 会中止正在进行的生成。

设置 `resumable: true` 可让生成在断线后继续，并允许 AI SDK UI 重新连接正在运行的流。可恢复的聊天不支持基于 abort 的取消：服务器无法区分 `useChat().stop()`、页面刷新和网络中断。

:::

## 使用示例 {/* #usage-example */}

此示例展示如何在 `/chat` 端点设置使用 ID 为 `weatherAgent` 的 Agent 的聊天路由。

```typescript title="src/mastra/index.ts"
import { Mastra } from '@mastra/core'
import { chatRoute } from '@mastra/ai-sdk'

export const mastra = new Mastra({
  server: {
    apiRoutes: [
      chatRoute({
        path: '/chat',
        agent: 'weatherAgent',
      }),
    ],
  },
})
```

也可以根据 `agentId` 在运行时动态选择 Agent。URL `/chat/weatherAgent` 会解析到 ID 为 `weatherAgent` 的 Agent。

```typescript title="src/mastra/index.ts"
import { Mastra } from '@mastra/core'
import { chatRoute } from '@mastra/ai-sdk'

export const mastra = new Mastra({
  server: {
    apiRoutes: [
      chatRoute({
        path: '/chat/:agentId',
      }),
    ],
  },
})
```

## 可恢复的流 {/* #resumable-streams */}

设置 `resumable: true` 于 `chatRoute()`，并设置 `resume: true` 于 AI SDK UI 的 `useChat()`，即可在刷新页面或网络中断后重新连接。此路由工厂返回包含以下两项的数组：

- `POST <path>`：启动 Agent 运行。请求中的 AI SDK 聊天 ID 将成为 Mastra 记忆线程 ID。
- `GET <path>/:chatId/stream`：重放缓存事件并跟随正在进行的运行。运行已结束、不可用、已过期或不在调用方作用域内时，路由返回 `204`。

将返回的数组作为 `server.apiRoutes` 的一个条目传入。Mastra 在配置服务器时会展平嵌套的路由数组。

```typescript title="src/mastra/index.ts"
import { Mastra } from '@mastra/core'
import { chatRoute } from '@mastra/ai-sdk'

export const mastra = new Mastra({
  server: {
    apiRoutes: [
      chatRoute({
        path: '/chat/:agentId',
        resumable: true,
      }),
    ],
  },
})
```

活动运行的发现仅限当前进程。重新连接请求必须到达启动生成任务的同一个服务器进程。可恢复模式不会转发请求的 `AbortSignal`，因此 `useChat().stop()` 只会关闭客户端连接，不会取消 Agent 运行。

如果聊天使用资源 ID，请通过身份验证中间件在请求上下文中设置 `MASTRA_RESOURCE_ID_KEY`。不要只在 POST 请求体的 `memory.resource` 中传入资源 ID：重新连接的 GET 请求没有请求体，因此 `chatRoute()` 会以 `400` 拒绝这种配置。

## 附加配置 {/* #additional-configuration */}

可以使用 [`prepareSendMessagesRequest`](https://ai-sdk.dev/docs/reference/ai-sdk-ui/use-chat#transport.default-chat-transport.prepare-send-messages-request) 自定义发送到聊天路由的请求，例如向 Agent 传递额外配置：

```typescript
const { error, status, sendMessage, messages, stop } = useChat({
  transport: new DefaultChatTransport({
    api: 'http://localhost:4111/chat',
    prepareSendMessagesRequest({ messages }) {
      return {
        body: {
          // With memory configured, send only the new message. Mastra loads the
          // rest of the conversation from storage.
          messages: [messages[messages.length - 1]],
          // Pass memory config
          memory: {
            thread: 'user-1',
            resource: 'user-1',
          },
        },
      }
    },
  }),
})
```

不使用记忆时，请发送完整的 `messages` 数组，聊天路由会将其用作请求上下文。

使用记忆时，存储的线程是事实来源，因此 `regenerate` 和在 `useChat` 中编辑较早的消息都不会改变它。要修改已存储的历史，请使用 `memory.saveMessages` 或记忆存储的 `updateMessages`，然后发送新消息。
