# 快速检查

Quick Checks 是无需调用 LLM、可组合的轻量评分器，用于验证常见断言。凡是使用评分器的地方，都可以将它们加入现有的 `scorers: [...]` 数组，包括 `runEvals`、实时评分、实验和 Studio。

它们在内部都是标准的 `createScorer()` 实例，因此与其他评分器一样，支持可观测性、存储和流水线集成。

:::note[注册检查以持久化分数]

只有将检查与 `storage` 一同注册到 Mastra 实例上，其分数才会写入分数存储。每种检查都有固定的 id（例如，`checks.includes()` 对应 `check-includes`，`checks.calledTool()` 对应 `check-called-tool`）；因此，无论传入什么参数，注册一个实例即可覆盖该检查的所有调用。参见[分数持久化](/docs/evals/overview#score-persistence)。

:::

## 使用示例 {/* #usage-example */}

```typescript title="src/evals/weather-checks.ts"
import { checks } from '@mastra/evals/checks'
import { runEvals } from '@mastra/core/evals'
import { myAgent } from '../agents'

const result = await runEvals({
  data: [{ input: 'What is the weather in Brooklyn?' }],
  target: myAgent,
  scorers: [
    checks.includes('sunny'),
    checks.calledTool('get_weather'),
    checks.toolOrder(['get_weather', 'summarize']),
    checks.noToolErrors(),
  ],
})

console.log(result.scores)
```

## 文本检查 {/* #text-checks */}

### `checks.includes(expected, options?)` {/* #checksincludesexpected-options */}

如果 Agent 的输出文本包含预期子字符串，则得分为 1，否则为 0。

```typescript

checks.includes('Sunny', { ignoreCase: false })
```

## Tool 调用检查 {/* #tool-call-checks */}

### `checks.calledTool(toolName, options?)` {/* #checkscalledtooltoolname-options */}

如果 Agent 调用指定 Tool 的次数达到要求的下限，则得分为 1。

```typescript

checks.calledTool('search', { times: 2 })
```

### `checks.toolOrder(expectedOrder)` {/* #checkstoolorderexpectedorder */}

如果 Tool 的调用顺序符合指定顺序，则得分为 1。此检查采用宽松匹配，允许在预期的 Tool 调用之间插入其他 Tool 调用。

如果 Agent 的 Tool 调用次数不超过 `max`，则得分为 1。

### `checks.usedNoTools()` {/* #checksusednotools */}

如果 Agent 完全没有调用 Tool，则得分为 1。

```typescript
checks.usedNoTools()
```

返回值：未调用任何 Tool 时为 `1`，否则为 `0`。

### `checks.noToolErrors()` {/* #checksnotoolerrors */}

如果所有 Tool 调用都没有进入错误状态，则得分为 1。此检查会识别错误结果（存在 `result.error`）和未完成的 Tool 调用（`state === 'call'`）。

```typescript
checks.noToolErrors()
```

返回值：所有 Tool 调用均成功时为 `1`，否则为 `0`。

## 与其他评分器组合使用 {/* #combining-checks-with-other-scorers */}

检查可以与基于 LLM 和基于代码的评分器一起放入同一个 `scorers` 数组：

```typescript title="src/evals/combined-eval.ts"
import { checks } from '@mastra/evals/checks'
import { createAnswerRelevancyScorer } from '@mastra/evals/scorers/prebuilt'
import { runEvals } from '@mastra/core/evals'
import { myAgent } from '../agents'

const result = await runEvals({
  data: [{ input: 'What is the weather in Brooklyn?' }],
  target: myAgent,
  scorers: [
    // Zero-LLM checks
    checks.includes('Brooklyn'),
    checks.calledTool('get_weather'),
    checks.noToolErrors(),
    // LLM-based scorer
    createAnswerRelevancyScorer({ model: '__GATEWAY_OPENAI_MODEL_LUNA__' }),
  ],
})
```

## 多轮对话中的行为 {/* #multi-turn-behavior */}

检查会读取累积的 `run.output`，因此在[多轮评估](/docs/evals/multi-turn)中可以看到每一轮。`checks.calledTool('get_weather', { times: 2 })` 统计整个对话中的调用次数，`checks.includes()` 则搜索所有助手文本。如果只要求特定轮次满足检查，请使用该轮的 `turns[].scorers`。
