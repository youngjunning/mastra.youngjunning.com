# 总结记分员

这`createSummarizationScorer()`函数创建一个评分器，在两个轴上评估摘要：每个声明是否具有源文本支持以及摘要是否保留源信息。最终得分取两者中较低者。总结不能说是忠实而空洞，也不能说是彻底但错误。

摘要是Agent携带文本的最后一条消息，源文本默认为运行输入的第一条用户消息。经过`source` or `sourceExtractor`当被总结的文本位于其他地方时，例如Tool结果。

## 使用示例 {/* #usage-example */}

根据其浓缩的文档对摘要进行评分。

```typescript title="src/mastra/scorers/summarization.ts"
import { createSummarizationScorer } from '@mastra/evals/scorers/prebuilt'

const scorer = createSummarizationScorer({
  model: '__GATEWAY_OPENAI_MODEL__',
})

const result = await scorer.run({
  input: {
    inputMessages: [{ id: '1', role: 'user', content: sourceDocument }],
  },
  output: [{ id: '2', role: 'assistant', content: summary }],
})

console.log(result.score)
console.log(result.reason)
```

## 总结评价 {/* #summarization-evaluation */}

当Agent压缩文本时使用此记分器：

* 文件和成绩单摘要
* 支持主题和电子邮件摘要
* 将长输入压缩为短输出的任何步骤

轴分数是从这些判决中得出的，而不是存储的：对齐是`alignment` entries with `supported: true`, and coverage is the share of `questions` whose `coverage` entry has `answered: true`.

## 评分详情 {/* #scoring-details */}

### 两轴评估 {/* #two-axis-evaluation */}

记分器运行三步管道：

1. **来源判断**：摘要中的主张是根据来源提取和检查的，封闭式问题是从来源中提取的。每个问题都被写下来，所以来源回答“是”。
2. **覆盖范围**：每个问题都仅使用摘要来回答。
3. **评分**：计算两个比率，较低者为分数。

覆盖步骤作为单独的模型调用运行，从不接收源文本。能够看到消息来源的法官会从消息来源而不是摘要中回答问题，这将隐藏该轴存在的要衡量的遗漏。

### 评分公式 {/* #scoring-formula */}

```text
Alignment    = supported_claims / total_claims
Coverage     = answered_questions / total_questions
Summarization = min(Alignment, Coverage) × scale
```

当摘要没有提出任何主张或来源没有提出任何问题时，得分为 0。

### 分数解读 {/* #score-interpretation */}

这些范围采用默认值`scale` of 1. When using a custom scale, multiply accordingly.

* **0.9-1.0**：优秀的总结，忠实于来源并涵盖了要点
* **0.7-0.8**：很好的总结，有一个小遗漏或不受支持的细节
* **0.4-0.6**：总结一般，要么遗漏重要信息，要么偏离来源
* **0.1-0.3**：总结不佳，大部分来源已丢失或相互矛盾
* **0.0**：摘要没有提供任何可供判断的内容，或者未能支持任何主张。不回答任何问题的摘要也会获得此分数

### 读取两个轴 {/* #reading-the-two-axes */}

两个轴都会对运行结果做出判断：预处理步骤的对齐判断和分析步骤的覆盖判断。每个判决都包含其所属的主张或问题及其背后的原因。低对齐分数与低覆盖分数具有不同的含义：

* 低对齐分数和高覆盖率意味着摘要发明或扭曲了细节
* 低覆盖率分数和高对齐意味着摘要是准确的，但遗漏了太多内容

原因字段以产生分数的轴命名。

### 分数遗漏了什么 {/* #what-the-score-leaves-out */}

长度对乐谱没有影响。逐字重复源代码的摘要支持每个主张并回答每个问题，因此得分为 1。当压缩是您测试的一部分时，请添加您自己的长度检查。

### 成本 {/* #cost */}

每个评估都会调用三个模型。`maxQuestions` bounds the coverage half of the work, which otherwise grows with source length. Raise it for long documents where ten questions can't represent the content.

### 总结运行输入 {/* #summarizing-the-run-input */}

```typescript
const scorer = createSummarizationScorer({
  model: '__GATEWAY_OPENAI_MODEL__',
})
```

### 总结其他地方的文档 {/* #summarizing-a-document-from-elsewhere */}

```typescript
import { extractToolResults } from '@mastra/evals/scorers/utils'

const scorer = createSummarizationScorer({
  model: '__GATEWAY_OPENAI_MODEL__',
  options: {
    sourceExtractor: (input, output) => {
      return extractToolResults(output)
        .filter(({ toolName }) => toolName === 'fetchDocument')
        .map(({ result }) => String(result))
        .join('\n\n')
    },
    maxQuestions: 20,
  },
})
```

## 例子 {/* #example */}

根据一组文档评估摘要Agent：

```typescript title="src/example-summarization.ts"
import { runEvals } from '@mastra/core/evals'
import { createSummarizationScorer } from '@mastra/evals/scorers/prebuilt'
import { summarizerAgent } from './agent'

const scorer = createSummarizationScorer({
  model: '__GATEWAY_OPENAI_MODEL__',
  options: { maxQuestions: 10 },
})

const result = await runEvals({
  target: summarizerAgent,
  scorers: [scorer],
  data: [
    {
      input:
        'The company was founded in 1995 by John Smith. It started with 10 employees and grew to 500 by 2020. The company is based in Seattle.',
    },
  ],
  onItemComplete: ({ scorerResults }) => {
    console.log({
      score: scorerResults[scorer.id].score,
      reason: scorerResults[scorer.id].reason,
    })
  },
})

console.log(result.scores)
```

欲了解更多详情`runEvals`, see the [runEvals reference](/reference/evals/run-evals).

要将此记分员添加到Agent，请参阅[Scorers overview](/docs/evals/overview#adding-scorers-to-agents) guide.

## 与忠诚度的比较 {/* #comparison-with-faithfulness */}

|使用案例|总结|诚信|
| - | - | - |
|**What it measures** | Support and coverage together | Support only |
| **Judged against** | The source text being condensed | Retrieved context or tool results |
| **Catches omission** | Yes | No |
| **Needs the full source** | Yes | No, context alone is enough |

使用`faithfulness` when the question is whether an answer stays grounded in retrieved context. Use `summarization` when the output is meant to stand in for a longer text.
