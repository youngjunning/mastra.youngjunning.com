# createScorer

Mastra 提供统一的 `createScorer` 工厂函数，用于定义评估输入与输出的自定义评分器。每个评估步骤既可以使用原生 JavaScript 函数，也可以使用基于 LLM 的提示对象。自定义评分器可添加到 Agent 和 Workflow 步骤中。

## 如何创建自定义评分器 {/* #how-to-create-a-custom-scorer */}

使用 `createScorer` 工厂函数指定评分器名称、描述和可选的 judge 配置，再串联步骤方法构建评估流程。至少必须提供一个 `generateScore` 步骤。

**提示对象步骤**使用包含 `description` 和 `createPrompt` 的对象配置；`preprocess` 和 `analyze` 还可使用 `outputSchema`，`generateScore` 则不可使用。这类步骤会调用 judge LLM。**函数步骤**是普通函数，绝不会调用 judge。

```typescript
import { createScorer } from '@mastra/core/evals'

const scorer = createScorer({
  id: 'my-custom-scorer',
  name: 'My Custom Scorer', // Optional, defaults to id
  description: 'Evaluates responses based on custom criteria',
  type: 'agent', // Optional: for agent evaluation with automatic typing
  judge: {
    model: myModel,
    instructions: 'You are an expert evaluator...',
  },
})
  .preprocess({/* step config */})
  .analyze({/* step config */})
  .generateScore(({ run, results }) => {
    // Return a number
  })
  .generateReason({/* step config */})
```

此函数返回评分器构建器，可继续串联步骤方法。有关 `.run()` 方法及其输入和输出，请参阅 [MastraScorer 参考文档](./mastra-scorer)。

judge 只会在定义为**提示对象**的步骤中运行（提示模式下的 `preprocess`、`analyze`、`generateScore` 和 `generateReason`）。如果只使用函数步骤，就不会调用 judge，也没有可检查的 LLM 输出；分数和原因必须由函数生成。

提示对象步骤运行时，LLM 的结构化输出会存入对应的结果字段（`preprocessStepResult` 或 `analyzeStepResult`）。对于 `generateScore`，judge 返回 `{ score: number }`，其中的 `score` 即为评分器分数。

## 重试 judge 请求 {/* #retry-judge-requests */}

使用现有的 judge `errorProcessors` 配置，可在 judge 请求失败时重试瞬时故障。它不会重试评分器 Workflow、Trace 目标、批处理项、分数写入或已完成的评分器步骤。

`@mastra/core` `1.49.0` 不包含评分器的错误处理器配置。使用此配置前，请升级到支持评分器处理器的版本，或移植对应的局部改动。

以下示例使用有上限的重试次数。请将处理器的 `maxRetries` 与 `judge.maxProcessorRetries` 设为相同值，并将内部 judge Agent 的模型重试次数保持为默认值 `0`，避免模型重试使处理器尝试次数成倍增加。

```typescript title="src/mastra/scorers/response-quality.ts"
import { createScorer } from '@mastra/core/evals'
import { StreamErrorRetryProcessor } from '@mastra/core/processors'

const isTransientNetworkError = (error: unknown) =>
  error instanceof Error && /ECONNRESET|ETIMEDOUT|socket hang up/i.test(error.message)

const retryProcessor = new StreamErrorRetryProcessor({
  maxRetries: 2,
  maxRetryAfterMs: 30_000,
  delayMs: ({ retryCount }) => Math.min(1_000 * 2 ** retryCount, 30_000),
  matchers: [isTransientNetworkError],
  retryUnknownErrors: false,
})

export const responseQuality = createScorer({
  id: 'response-quality',
  description: 'Scores response quality',
  judge: {
    model: myModel,
    instructions: 'Return a score and concise reason.',
    errorProcessors: [retryProcessor],
    maxProcessorRetries: 2,
  },
})
  .generateScore({
    description: 'Score the response quality.',
    createPrompt: ({ run }) => `Score: ${run.output}`,
  })
  .generateReason({
    description: 'Explain the score.',
    createPrompt: () => 'Explain the score.',
  })
```

按此配置，失败的请求最多尝试访问 Provider 三次：初次请求加上两次处理器重试。如果 `generateScore` 已完成，而 `generateReason` 遇到可重试故障，则只重试 `generateReason`。

`StreamErrorRetryProcessor` 会根据 Provider 返回的可重试元数据及范围明确的自定义匹配器决定重试。`retryUnknownErrors` 默认关闭，因此身份验证、无效请求和上下文长度错误会立即失败，除非显式匹配它们。默认情况下，`Retry-After` 的上限为 `30_000` 毫秒；可用 `maxRetryAfterMs` 修改。

避免添加外层评分器或 Workflow 重试。除非有意接受额外的尝试次数，否则不要同时使用非零的模型重试设置和此处理器。

### 覆盖单个步骤的重试设置 {/* #override-retries-for-one-step */}

步骤级 `judge` 配置会覆盖评分器级 judge 字段。处理器数组会替换评分器级数组。若在步骤配置中省略 `maxProcessorRetries`，则继承评分器级的数值上限。

协调处理器重试需要使用 Mastra 当前生成 API 的 judge 模型。旧版模型适配器调用 [`generateLegacy()`](/reference/agents/generateLegacy)，会跳过错误处理器，并使用该 API 独立的 AI SDK `maxRetries` 默认值 `2`。

## 类型安全 {/* #type-safety */}

创建评分器时可指定输入和输出类型，以获得更好的类型推断和 IntelliSense 支持：

### Agent 类型快捷方式 {/* #agent-type-shortcut */}

评估 Agent 时，使用 `type: 'agent'` 即可自动获得正确的 Agent 输入和输出类型：

```typescript
import { createScorer } from '@mastra/core/evals'

// Agent scorer with automatic typing
const agentScorer = createScorer({
  id: 'agent-response-quality',
  description: 'Evaluates agent responses',
  type: 'agent', // Automatically provides ScorerRunInputForAgent/ScorerRunOutputForAgent
})
  .preprocess(({ run }) => {
    // run.input is automatically typed as ScorerRunInputForAgent
    const userMessage = run.inputData.inputMessages[0]?.content
    return { userMessage }
  })
  .generateScore(({ run, results }) => {
    // run.output is automatically typed as ScorerRunOutputForAgent
    const response = run.output[0]?.content
    return response.length > 10 ? 1.0 : 0.5
  })
```

### 使用泛型定义自定义类型 {/* #custom-types-with-generics */}

要自定义输入和输出类型，可使用泛型：

```typescript
import { createScorer } from '@mastra/core/evals'

type CustomInput = { query: string; context: string[] }
type CustomOutput = { answer: string; confidence: number }

const customScorer = createScorer<CustomInput, CustomOutput>({
  id: 'custom-scorer',
  description: 'Evaluates custom data',
}).generateScore(({ run }) => {
  // run.input is typed as CustomInput
  // run.output is typed as CustomOutput
  return run.output.confidence
})
```

### 内置 Agent 类型 {/* #built-in-agent-types */}

* **`ScorerRunInputForAgent`**：包含用于评估 Agent 的 `inputMessages`、`rememberedMessages`、`systemMessages` 和 `taggedSystemMessages`
* **`ScorerRunOutputForAgent`**：Agent 响应消息数组

使用这些类型可为评分逻辑提供自动补全、编译时校验和更清晰的文档。

## 使用 Agent 类型为 Trace 评分 {/* #trace-scoring-with-agent-types */}

使用 `type: 'agent'` 时，评分器既可直接添加到 Agent，也可为 Agent 交互产生的 Trace 评分。评分器会自动将 Trace 数据转换为相应的 Agent 输入和输出格式：

```typescript
const agentTraceScorer = createScorer({
  id: 'agent-trace-length',
  description: 'Evaluates agent response length',
  type: 'agent',
}).generateScore(({ run }) => {
  // Trace data is automatically transformed to agent format
  const userMessages = run.inputData.inputMessages
  const agentResponse = run.output[0]?.content

  // Score based on response length
  return agentResponse?.length > 50 ? 0 : 1
})

// Register with Mastra for trace scoring
const mastra = new Mastra({
  scorers: {
    agentTraceScorer,
  },
})
```
