# notScorable()

声明当前运行没有可供此评分器评估的内容。应从评分器的函数步骤（通常是 `preprocess`）直接返回该值。后续步骤会跳过，因此不会调用评判模型；平均分、门控和阈值只计入此评分器实际评估过的运行。

如果运行是否符合评估条件取决于它自身的输入或输出，例如是否调用了特定工具，请使用 `notScorable()`。如果条件能通过请求上下文或实体元数据表达，请改用[资格过滤器](/docs/evals/overview#how-live-evaluations-work)。操作示例见[自定义评分器：跳过无法评分的运行](/docs/evals/custom-scorers#skipping-runs-that-cant-be-scored)。

## 使用示例 {/* #usage-example */}

下面的评分器使用 LLM 评判退款处理情况。对于从未调用 `refundCustomer` 的运行，它会在请求评判模型前声明该运行无法评分：

```typescript title="src/mastra/scorers/refund-judge.ts"
import { createScorer, notScorable } from '@mastra/core/evals'
import { extractToolCalls } from '@mastra/evals/scorers/utils'

export const refundJudge = createScorer({
  id: 'refund-judge',
  description: 'Judges how well refund requests were handled',
  type: 'agent',
  judge: {
    model: '__GATEWAY_OPENAI_MODEL_LUNA__',
    instructions: 'You are a strict QA reviewer for customer-support refund handling.',
  },
})
  .preprocess(({ run }) => {
    const { tools } = extractToolCalls(run.output)
    return tools.includes('refundCustomer')
      ? { tools }
      : notScorable('refundCustomer was not called')
  })
  .generateScore({
    description: 'Score the refund handling from 0 to 1',
    createPrompt: ({ run }) =>
      `Rate this refund handling from 0 to 1:\n${JSON.stringify(run.output)}`,
  })
```

**返回：** `NotScorable`。这是评分器流水线可识别的不透明值。请直接从步骤返回它，不要将它包装在其他对象中。

## 行为 {/* #behavior */}

- 任何函数步骤都可以返回它：`preprocess`、`analyze`、`generateScore` 或 `generateReason`。提示对象步骤的输出由模型生成，因此不能返回它。
- 已完成的步骤会保留其结果。
- `scorer.run()` 返回包含 `notScorable: { step, reason? }` 且没有 `score` 键的结果。参见 [`MastraScorer`](/reference/evals/mastra-scorer)。
- 实时评分不会存储分数记录。[`runEvals()`](/reference/evals/run-evals) 不会将该运行计入平均分、门控、阈值或最终判定，但会将其计入 `summary.notScorable`。实验会设置 `score: null`、`error: null` 和 `notScorable`。
