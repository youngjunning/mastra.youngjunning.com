# 过滤器运行()

创建一个`prepareRun`来自声明性选项的函数。将结果传递给`createScorer()`过滤消息并限制上下文大小。它还会在评分器管道运行之前删除不必要的字段。

使用[`filterRun()`](#usage-example) for declarative filtering. Write a custom `prepareRun` function directly when you need imperative logic that `filterRun()`不涵盖。看[自定义评分器：输入过滤](/docs/evals/custom-scorers#input-filtering)了解更多。

## 使用示例 {/* #usage-example */}

以下示例创建一个仅查看Tool调用和文本消息的记分器，仅限于 20 条最近的上下文消息：

```typescript title="src/mastra/scorers/tool-scorer.ts"
import { createScorer, filterRun } from '@mastra/core/evals'

const toolScorer = createScorer({
  id: 'tool-usage',
  description: 'Evaluates tool usage patterns',
  type: 'agent',
  prepareRun: filterRun({
    partTypes: ['tool-invocation', 'text'],
    maxRememberedMessages: 20,
  }),
}).generateScore(({ run }) => {
  // run.input.rememberedMessages contains only tool and text messages
  // run.output contains only tool and text messages
  return 1
})
```

### 按Tool名称过滤 {/* #filter-by-tool-name */}

仅保留涉及特定Tool的消息：

```typescript
import { createScorer, filterRun } from '@mastra/core/evals'

const fileEditScorer = createScorer({
  id: 'file-edit-quality',
  description: 'Evaluates file editing patterns',
  type: 'agent',
  prepareRun: filterRun({
    toolNames: ['write_file', 'string_replace_lsp', 'view'],
  }),
}).generateScore(({ run }) => {
  // Only messages with these tool calls remain
  return 1
})
```

### 删除字段 {/* #drop-fields */}

删除记分员不需要的字段：

```typescript
import { createScorer, filterRun } from '@mastra/core/evals'

const simpleScorer = createScorer({
  id: 'response-length',
  description: 'Checks response length',
  type: 'agent',
  prepareRun: filterRun({
    dropRequestContext: true,
    dropExpectedTrajectory: true,
    dropGroundTruth: true,
    maxOutputMessages: 5,
  }),
}).generateScore(({ run }) => {
  return run.output.length > 0 ? 1 : 0
})
```

**返回：** `(run: ScorerRun) => ScorerRun`. A function suitable for the `prepareRun` option on [`createScorer()`](/reference/evals/create-scorer).

## 零件类型 {/* #part-types */}

这`partTypes` option accepts `MastraPartType` values. Each value is prefix-matched, so `'data-'` matches all data part types.

|类型 |描述 |
| - | - |
|`'text'` | Text content parts |
| `'tool-invocation'` | Tool call and result parts |
| `'reasoning'` | Chain-of-thought reasoning parts |
| `'step-start'` | Step marker parts |
| `'image'` | Image parts |
| `'file'` | File parts |
| `'source'` | Source reference parts |
| `'source-document'` | Source document parts |
| `'data-'` | All data parts (matches any `data-*` prefix) |
| `'data-om-'`|观察记忆数据部分|
|`'data-workspace-'`|Workspace数据部分 |
|`'data-sandbox-'`|沙盒数据部分 |
|`'data-tool-'`|Tool相关数据部分|

## 过滤行为 {/* #filtering-behavior */}

* **零件类型过滤**适用于两者`input.rememberedMessages` and `output` when they contain agent message arrays.
* **Tool名称过滤**仅影响包含Tool调用的消息。没有Tool调用的消息将按以下条件过滤`partTypes` only, and pass through when `partTypes` isn't set.
* **系统消息** (`systemMessages`, `taggedSystemMessages`) are never filtered, regardless of `partTypes` or `toolNames`.
* **消息限制** (`maxRememberedMessages`, `maxOutputMessages`) apply after type and tool filtering, taking the most recent messages.
* 当两者`partTypes` and `toolNames` are set, a message with tool invocations must satisfy both filters to be kept.
