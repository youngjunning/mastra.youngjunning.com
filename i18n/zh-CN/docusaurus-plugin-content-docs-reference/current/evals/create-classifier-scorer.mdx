# createClassifierScorer

`createClassifierScorer()` 将构造时配置的一个 [`Classifier`](/reference/classifier/classifier) 问题接入 Mastra 评分器流程。它返回带有数值 `score` 的标准 `MastraScorer`，并在 `analyzeStepResult` 中保留所选答案、概率、用量、警告以及安全的响应元数据。

每次运行评分器都会调用 `Classifier.decide()`，评估分类器中配置的所有问题，但只把 `question` 指定的问题的答案映射为 0 到 1 的分数。`question` 选项不会限制发送给模型的问题。此适配器不会聚合多个问题、应用布尔阈值、推断选项顺序，也不会调用第二个评判模型。

如果每次运行只想评估一个问题，请使用只配置该问题的独立分类器。例如，五个 rubric 评分器共用一个含五个问题的分类器时，每个评分器每次都会评估全部五个问题，而非只评估自己选中的问题。

Agent 评分器的运行数据包含消息对象，`Classifier.decide()` 无法直接接受，因此必须提供 `state`。可用它提取兼容 JSON 的文本，例如借助 `@mastra/evals/scorers/utils` 中的辅助函数。

## 示例 {/* #example */}

```typescript title="src/mastra/scorers/response-quality.ts"
import { Classifier } from '@mastra/core/classifier'
import { typeSafeAi } from '@ai-sdk/typesafe-ai'
import { createClassifierScorer } from '@mastra/core/evals'
import {
  getAssistantMessageFromRunOutput,
  getUserMessageFromRunInput,
} from '@mastra/evals/scorers/utils'

const responseJudge = new Classifier({
  id: 'response-judge',
  model: typeSafeAi.decisionModel('__AI_SDK_TYPESAFE_DECISION_MODEL__'),
  questions: {
    quality: {
      type: 'score',
      instructions: 'How well does the response answer the request?',
      criteria: ['Incorrect or irrelevant', 'Partially correct', 'Correct and complete'],
    },
    route: {
      type: 'choice',
      criteria: {
        correct: 'The response took the correct route',
        partiallyCorrect: 'The response took a partly correct route',
        incorrect: 'The response took the wrong route',
      },
    },
    factual: {
      type: 'boolean',
      criteria: { true: 'The response is factual', false: 'The response contains factual errors' },
    },
  },
})

export const qualityScorer = createClassifierScorer({
  id: 'response-quality',
  description: 'Scores response quality with the configured classifier',
  classifier: responseJudge,
  question: 'quality',
  type: 'agent',
  state: ({ run }) => ({
    input: getUserMessageFromRunInput(run.input) ?? '',
    output: getAssistantMessageFromRunOutput(run.output) ?? '',
  }),
})
```

此分类器配置了三个问题，供下方示例共用。每次调用 `qualityScorer.run()` 都会评估 `quality`、`route` 和 `factual`，但只有 `quality` 的答案决定分数。如果只想评估 `quality`，请从该分类器的 `questions` 中移除 `route` 和 `factual`。

对于有 N 项标准的评分问题，分类器会返回从 `0` 到 `N - 1` 的等级，`result.score` 则将该等级除以 `N - 1`。如果有三项标准，`Partially correct` 的分数为 `0.5`。

## 选择题 {/* #choice-questions */}

选择题必须为每个已配置选项明确映射一个介于 `0` 和 `1` 之间的分数；不假定选项顺序，也不使用后备值。

```typescript
const routeScorer = createClassifierScorer({
  id: 'route-score',
  classifier: responseJudge,
  question: 'route',
  type: 'agent',
  scores: {
    correct: 1,
    partiallyCorrect: 0.5,
    incorrect: 0,
  },
  state: ({ run }) => ({
    input: getUserMessageFromRunInput(run.input) ?? '',
    output: getAssistantMessageFromRunOutput(run.output) ?? '',
  }),
})
```

所选选项及其可选的概率分布仍可从 `result.analyzeStepResult.answer` 获取。

## 布尔问题 {/* #boolean-questions */}

对于布尔问题，`result.score` 是分类器估计的 `P(true)`，不会应用阈值，也不会将概率转换为 `0` 或 `1`。

```typescript
const factualityScorer = createClassifierScorer({
  id: 'factuality',
  classifier: responseJudge,
  question: 'factual',
  type: 'agent',
  state: ({ run }) => ({
    input: getUserMessageFromRunInput(run.input) ?? '',
    output: getAssistantMessageFromRunOutput(run.output) ?? '',
  }),
})
```

## 请求上下文 {/* #request-context */}

`state` 函数接收评分器运行数据，其中包括 `run.requestContext`，因此分类器输入可以包含租户策略等每次请求特有的细节。这样，同一个分类器就能根据请求方，对相同输出作出不同判断：

```typescript
import { RequestContext } from '@mastra/core/request-context'

export const policyScorer = createClassifierScorer({
  id: 'policy-factuality',
  classifier: responseJudge,
  question: 'factual',
  type: 'agent',
  state: ({ run }) => ({
    policy:
      (run.requestContext instanceof RequestContext
        ? run.requestContext.get('policy')
        : run.requestContext?.policy) ?? null,
    output: getAssistantMessageFromRunOutput(run.output) ?? '',
  }),
})
```

## 注册分类器 {/* #registered-classifiers */}

传入分类器 ID，评分器运行时就会从 Mastra 解析该分类器。还需将已配置的分类器类型和所选问题作为泛型参数提供，因为 TypeScript 无法从字符串 ID 推断它们。

```typescript
import { Mastra } from '@mastra/core/mastra'

const registeredScorer = createClassifierScorer<typeof responseJudge, 'quality'>({
  id: 'registered-response-quality',
  classifier: 'response-judge',
  question: 'quality',
  type: 'agent',
  state: ({ run }) => ({
    input: getUserMessageFromRunInput(run.input) ?? '',
    output: getAssistantMessageFromRunOutput(run.output) ?? '',
  }),
})

new Mastra({
  classifiers: { responseJudge },
  scorers: { registeredScorer },
})
```

如果尚未向 Mastra 注册分类器就运行引用其 ID 的评分器，调用会因错误而失败；错误中会指出分类器和评分器的 ID。直接传入已配置的分类器实例，则可跳过注册表解析。

## 错误 {/* #errors */}

内联分类器配置无效时，`createClassifierScorer()` 会抛出 `TypeError`：

* 分类器没有配置问题。
* 所选问题不存在。
* 选项映射遗漏了已配置选项、包含未知选项，或某个值不是介于 `0` 和 `1` 之间的有限数字。
* 评分题或布尔题收到了 `scores` 映射。

评分器运行期间发生错误时，`scorer.run()` 会以 `ScorerRunError` 失败，其 `failedStep` 为 `analyze`，原始错误可通过 `cause` 获取。包括以下情况：

* 分类器评估失败或未返回所选问题的答案。
* 决策模型拒绝回答所选问题。错误中会指出分类器、问题和评分器。
* 在评分器注册到 Mastra 前使用分类器 ID，或该 ID 不在 `classifiers` 中。
* 已注册的分类器对此评分器的配置无效。

## 结果证据 {/* #result-evidence */}

`result.analyzeStepResult` 包含：

* `question`：所选的问题键。
* `answer`：保留精确类型的选项、分数或布尔答案，包括可选的概率。
* `usage`：归一化后的分类器 token 用量。
* `warnings`、`rounding` 和 `providerMetadata`：决策模型返回的评估依据。
* `response`：安全的响应标识信息，包含 `id`、`timestamp` 和 `modelId`。

原始 Provider 响应正文和响应头不会复制到评分器结果中。如需完整的原始响应，请直接调用 `Classifier.decide()`。

分类器评估在评分器当前的 Trace 上下文中运行。
