# Multi-turn Judge 评分器

**引入版本：** `@mastra/evals@1.9.0`

`createMultiTurnJudgeScorer()` 创建由 LLM 担任评判者的评分器，依据一条自然语言标准评估整段对话。它返回**二元**分数：满足标准时为 `1`，否则为 `0`；`reason` 会列出标准及评判者的解释。

其他预置的 LLM 评判者只读取一条助手消息；此评分器会读取 `run.output` 中累积的每轮助手回复，因此适用于[多轮 `inputs`](/docs/evals/multi-turn)形式的 [`runEvals()`](/reference/evals/run-evals)。

## 在多轮评估中使用 {/* #usage-with-multi-turn-evals */}

将评分器传给 `runEvals`，同时提供 `inputs` 数组。发送给评判者的提示词包含每轮助手回复：

```typescript title="src/evals/trip-planning-eval.ts"
import { runEvals } from '@mastra/core/evals'
// highlight-next-line
import { createMultiTurnJudgeScorer } from '@mastra/evals/scorers/prebuilt'
import { weatherAgent } from '../agents'

const result = await runEvals({
  data: [
    {
      inputs: [
        "I'm planning a trip to London, Paris, and Tokyo next week.",
        "How's the weather looking in London?",
        'And Paris?',
        'Tokyo too?',
        'Should I pack an umbrella for the London leg?',
      ],
    },
  ],
  target: weatherAgent,
  scorers: [
    {
      // highlight-start
      scorer: createMultiTurnJudgeScorer({
        model: '__GATEWAY_ANTHROPIC_MODEL_HAIKU__',
        criterion:
          'The agent provided weather forecasts for London, Paris, and Tokyo, and gave weather-appropriate packing or clothing advice.',
      }),
      // highlight-end
      threshold: 1,
    },
  ],
})
```

使用 `threshold: 1` 将结果转换为通过或失败：分数只有两个值，因此任何更低的阈值都会始终判为通过。

## 持久化分数 {/* #persisting-scores */}

只有在 Mastra 实例上注册相同 ID 的评分器，分数才会写入分数存储。持久化过程通过 `Mastra.getScorerById()` 查找评分器元数据；由于只查找 ID，注册实例的 `criterion` 可以使用占位值：

```typescript title="src/mastra/index.ts"
import { Mastra } from '@mastra/core'
import { LibSQLStore } from '@mastra/libsql'
import { createMultiTurnJudgeScorer } from '@mastra/evals/scorers/prebuilt'

export const mastra = new Mastra({
  agents: { weatherAgent },
  storage: new LibSQLStore({ url: 'file:./mastra.db' }),
  scorers: {
    // highlight-start
    'multi-turn-judge-scorer': createMultiTurnJudgeScorer({
      model: '__GATEWAY_ANTHROPIC_MODEL_HAIKU__',
      criterion: 'placeholder',
    }),
    // highlight-end
  },
})
```

完整要求及未注册评分器时的警告，参见[分数持久化](/docs/evals/overview#score-persistence)。

## 评分细节 {/* #scoring-details */}

评分器分两个阶段运行：

1. **评判**：将 `run.output` 中的助手消息整理为带编号的对话记录，由评判者依据标准整体评估。仅包含工具调用或没有文本的轮次会跳过。
2. **计分**：判定为 `satisfied` 时得 `1` 分，其他结果得 `0` 分，再乘以 `scale`。

评判者只能看到助手回复，看不到用户的轮次或任何 Tool 结果。因此，应根据 Agent 的回复编写标准。这将评分内容限定为 Agent 自己的输出，但对于脱离用户问题便无法理解的回复（例如“是的，带一把。”），评判者也无法单独判断。如果标准依赖用户轮次，请用 `turns[].scorers` 逐轮评分，或编写同时呈现双方消息的[自定义评分器](/docs/evals/multi-turn)。

对话记录以不可信数据的形式传给评判者，并用明确的分隔符包围；提示词还要求忽略其中看似指令的内容，以免 Agent 回复通过提示注入获得通过判定。
