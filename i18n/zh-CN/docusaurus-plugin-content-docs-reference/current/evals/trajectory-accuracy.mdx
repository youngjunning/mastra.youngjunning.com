# 轨迹准确性评分器

Mastra 提供两种轨迹准确性评分器，用于评估 Agent 或 Workflow 是否按照预期的动作顺序执行：

1. **基于代码的评分器**——精确匹配步骤及其顺序，给出确定性结果
1. **基于 LLM 的评分器**——由 AI 从语义上评估轨迹质量和适宜性

两种评分器都适用于 Agent 和 Workflow。`runEvals` 管道会自动提取轨迹，因此评分器直接接收 `Trajectory` 对象。

## 提取轨迹 {/* #trajectory-extraction */}

`runEvals` 管道根据是否配置了可观测性存储，采用两种提取策略之一：

### 从 trace 提取（推荐） {/* #trace-based-extraction-preferred */}

如果目标的 `Mastra` 实例配置了存储，管道会从可观测性存储中获取完整执行 trace，并调用 `extractTrajectoryFromTrace()`。得到的分层轨迹包含嵌套的 `children`，能够反映完整执行树，包括 Workflow 步骤中的嵌套 Agent 运行、工具调用和模型生成。

例如，一个 Workflow 调用 Agent，而 Agent 再调用工具时，生成的轨迹如下：

```text
workflow_run
  └─ workflow_step (validate-input)
  └─ workflow_step (process-data)
       └─ agent_run (my-agent)
            └─ model_generation
            └─ tool_call (search)
            └─ model_generation
            └─ tool_call (summarize)
  └─ workflow_step (save-result)
```

### 回退提取方式 {/* #fallback-extraction */}

没有可用存储时，管道会回退到以下方式：

- **Agent：** `extractTrajectory()` 从 Agent 消息输出中的 `toolInvocations` 提取 `ToolCallStep` 条目，生成平铺的工具调用列表。
- **Workflow：** `extractWorkflowTrajectory()` 从 `stepResults` 提取 `WorkflowStepStep` 条目，生成平铺的 Workflow 步骤列表。

这些回退方式无法捕获嵌套执行，也无法捕获非工具调用的 span。

## 预期步骤 {/* #expected-steps */}

定义预期轨迹时，应使用 `ExpectedStep`，而非完整的 `TrajectoryStep` 判别联合类型。`ExpectedStep` 是与 `TrajectoryStep` 对应的判别联合类型：指定 `stepType` 后，即可获得该类型字段的自动补全，例如 `tool_call` 的 `toolArgs`、`model_generation` 的 `modelId`。各类型特有字段均为可选，因此只需断言关心的字段。

### 简单的预期步骤 {/* #simple-expected-steps */}

```typescript
const steps: ExpectedStep[] = [
  // Match by name only (any step type)
  { name: 'search' },

  // Match by name and step type (autocomplete for tool_call fields)
  { name: 'search', stepType: 'tool_call' },

  // Match with specific toolArgs (auto-compared when present)
  { name: 'search', stepType: 'tool_call', toolArgs: { query: 'weather' } },
```

### 嵌套预期 {/* #nested-expectations */}

每个预期步骤都可以包含带有独立评估规则的 `children` 配置，以便在层级结构的不同层级设置不同的顺序或比较规则。

```typescript
const scorer = createTrajectoryScorerCode({
  defaults: {
    ordering: 'strict',
    steps: [
      { name: 'validate-input', stepType: 'workflow_step' },
      {
        name: 'research-agent',
        stepType: 'agent_run',
        children: {
          // Sub-agent can call tools in any order
          ordering: 'unordered',
          steps: [
            { name: 'search', stepType: 'tool_call' },
            { name: 'summarize', stepType: 'tool_call' },
          ],
        },
      },
      { name: 'save-result', stepType: 'workflow_step' },
    ],
  },
})
```

在此示例中，父级 Workflow 要求其步骤严格按顺序执行，但嵌套的 `research-agent` 可以按任意顺序调用工具。

## 如何选择评分器 {/* #choosing-between-scorers */}

### 适合使用基于代码的评分器的情况 {/* #use-the-code-based-scorer-when */}

- 需要**确定且可复现**的结果
- 有**已知的预期轨迹**可供比较
- 需要验证**精确的步骤顺序**
- 重视速度和成本（无需调用 LLM）
- 正在 CI/CD 中运行自动化测试

### 适合使用基于 LLM 的评分器的情况 {/* #use-the-llm-based-scorer-when */}

- 需要从**语义上判断**步骤是否合适
- 最优轨迹**无法事先确定**，需要依据任务要求评估
- 需要检测**不必要、重复或缺失**的步骤
- 需要获得评分决策的**解释**
- 正在评估**生产环境中 Agent 的行为**

### 预期轨迹的来源 {/* #expected-trajectory-sources */}

基于代码的评分器按以下优先级获取 `expectedTrajectory`：

1. **构造函数选项**：创建评分器时传入的静态轨迹，适用于所有数据集条目。
1. **数据集条目**：数据集条目中的 `expectedTrajectory` 字段，由 `runEvals` 管道传入；各条目可以使用不同的预期轨迹。

```typescript title="src/static-expected.ts"
// Static: same expected trajectory for all items
const scorer = createTrajectoryAccuracyScorerCode({
  expectedTrajectory: {
    steps: [
      { stepType: 'tool_call', name: 'search' },
      { stepType: 'tool_call', name: 'summarize' },
    ],
  },
})
```

```typescript title="src/per-item-expected.ts"
// Per-item: each dataset item has its own expectedTrajectory
const scorer = createTrajectoryAccuracyScorerCode()

await runEvals({
  target: mastra.getAgent('myAgent'),
  scorers: { trajectory: [scorer] },
  data: [
    {
      input: 'Search and summarize weather',
      expectedTrajectory: {
        steps: [
          { stepType: 'tool_call', name: 'search' },
          { stepType: 'tool_call', name: 'summarize' },
        ],
      },
    },
    {
      input: 'Just search for weather',
      expectedTrajectory: {
        steps: [{ stepType: 'tool_call', name: 'search' }],
      },
    },
  ],
})
```

### 评估模式 {/* #evaluation-modes */}

基于代码的评分器根据 `ordering` 选择以下三种模式之一：

#### 严格模式（`ordering: 'strict'`） {/* #strict-mode-ordering-strict */}

只有完全匹配（步骤和顺序均相同，且没有额外或缺失的步骤）才得 `1.0`。其他情况会根据预期步骤在对应位置的匹配程度给部分分数，并对每个额外步骤扣分。例如，两个预期步骤之后多出一个步骤，得分为 `0.75`。

#### 宽松模式（`ordering: 'relaxed'`，默认） {/* #relaxed-mode-ordering-relaxed-default */}

允许额外步骤。预期步骤必须按正确的相对顺序出现。得分根据匹配的预期步骤数量计算，并可对额外或重复步骤扣分。

#### 无序模式（`ordering: 'unordered'`） {/* #unordered-mode-ordering-unordered */}

只检查每个预期步骤是否出现。忽略顺序；结果中会报告额外步骤，但不会因此扣分。

## 基于代码的评分细节 {/* #code-based-scoring-details */}

- **连续得分**：所有顺序模式都返回 0.0 到 1.0 之间的值。严格模式下，得分为按顺序匹配的预期步骤占比，再减去额外步骤的扣分；当 `allowRepeatedSteps` 为 `false` 时，还会扣除重复步骤的分数
- **确定性**：相同输入始终产生相同输出
- **快速**：无需调用外部 API

## 基于代码的评分器示例 {/* #code-based-scorer-examples */}

### 严格顺序的 Agent 轨迹 {/* #agent-trajectory-with-strict-ordering */}

验证 Agent 是否按精确的工具调用顺序执行：

```typescript title="src/example-strict-trajectory.ts"
import { createTrajectoryAccuracyScorerCode } from '@mastra/evals/scorers/prebuilt'
import { runEvals } from '@mastra/core/evals'

const scorer = createTrajectoryAccuracyScorerCode({
  expectedTrajectory: {
    steps: [
      { stepType: 'tool_call', name: 'auth-tool' },
      { stepType: 'tool_call', name: 'fetch-tool' },
    ],
  },
  comparisonOptions: { ordering: 'strict' },
})

const result = await runEvals({
  target: mastra.getAgent('myAgent'),
  scorers: { trajectory: [scorer] },
  data: [{ input: 'Get my data' }],
})

console.log(result.scores.trajectory['code-trajectory-accuracy-scorer']) // 1.0
```

### 宽松顺序的 Agent 轨迹 {/* #agent-trajectory-with-relaxed-ordering */}

只要预期步骤保持正确的相对顺序，即允许额外步骤：

```typescript title="src/example-relaxed-trajectory.ts"
const scorer = createTrajectoryAccuracyScorerCode({
  expectedTrajectory: {
    steps: [
      { stepType: 'tool_call', name: 'search-tool' },
      { stepType: 'tool_call', name: 'summarize-tool' },
    ],
  },
  comparisonOptions: { ordering: 'relaxed' },
})

// Agent called search-tool → log-tool → summarize-tool
// The extra log-tool is allowed in relaxed mode
// score: 0.75 — all expected steps matched, small penalty for extra step
```

### 功能 {/* #features */}

基于 LLM 的评分器能够：

- **感知任务的评估**：根据用户请求判断每个步骤是否必要
- **顺序评估**：判断步骤是否按合理顺序执行
- **缺失步骤检测**：识别本应执行的步骤
- **冗余检测**：标出不必要或重复的步骤
- **生成理由**：提供人类可读的评分解释

### 评估流程 {/* #evaluation-process */}

1. **接收轨迹**：从管道获取已提取的 `Trajectory` 对象
1. **分析步骤**：使用 LLM 判断各步骤是否必要、顺序是否合理
1. **计算得分**：必要性占 60%，顺序占 30%，再减去10% 的缺失步骤扣分
1. **生成理由**：提供人类可读的解释

## 基于 LLM 的评分细节 {/* #llm-based-scoring-details */}

- **小数得分**：返回 0.0 到 1.0 之间的值
- **感知上下文**：考虑用户意图和任务要求
- **解释得分**：提供评分理由
- **灵活**：有无预期轨迹均可使用

### 基于 LLM 的评分器选项 {/* #llm-based-scorer-options */}

```typescript

const guidedScorer = createTrajectoryAccuracyScorerLLM({

      { stepType: 'tool_call', name: 'search-tool' },
      { stepType: 'tool_call', name: 'summarize-tool' },
    ],
  },
})
```

### 评分行为 {/* #scoring-behavior */}

综合评分器评估四个维度：

1. **准确性**：将实际步骤与预期步骤匹配（如果配置了 `steps`），并采用指定的 `ordering` 模式。
1. **效率**：检查步骤预算（`maxSteps`、`maxTotalTokens`、`maxTotalDurationMs`）和重复调用（`noRedundantCalls`）。
1. **禁用规则**：检查禁止调用的工具或工具序列。无论其他维度得分如何，只要违反规则，得分立即变为 **0.0**。
1. **工具失败**：检测重试、回退和参数修正模式。

最终得分按启用维度的权重合成，并根据实际启用的维度归一化。默认权重分别为：准确性 0.4、效率 0.3、工具失败 0.2、禁用规则 0.1；可以通过 `weights` 自定义。违反禁用规则会使总分变为 0。存在嵌套评估时，顶层得分占 70%，嵌套得分的平均值占 30%。

### 按数据集条目设置预期 {/* #per-item-expectations */}

每个数据集条目都可以用自己的 `expectedTrajectory` 覆盖默认值，因此可以针对不同提示词设置不同预期：

```typescript title="src/unified-per-item.ts"
import { createTrajectoryScorerCode } from '@mastra/evals/scorers/prebuilt'
import { runEvals } from '@mastra/core/evals'

// Default blacklist applies to all items
const scorer = createTrajectoryScorerCode({
  defaults: {
    blacklistedTools: ['deleteAll'],
    maxSteps: 5,
  },
})

const result = await runEvals({
  target: mastra.getAgent('myAgent'),
  scorers: { trajectory: [scorer] },
  data: [
    {
      input: 'Search for weather',
      expectedTrajectory: {
        steps: [{ stepType: 'tool_call', name: 'search' }],
        maxSteps: 2,
      },
    },
    {
      input: 'Search and summarize',
      expectedTrajectory: {
        steps: [
          { stepType: 'tool_call', name: 'search' },
          { stepType: 'tool_call', name: 'summarize' },
        ],
      },
    },
  ],
})
```

## 在 `runEvals` 中使用轨迹评分器 {/* #using-trajectory-scorers-with-runevals */}

在评分器配置中，轨迹评分器位于 `trajectory` 键下。`runEvals` 管道会自动提取轨迹。

### 评估 Agent 轨迹 {/* #agent-trajectory-evaluation */}

```typescript title="src/agent-trajectory-eval.ts"
import { runEvals } from '@mastra/core/evals'
import { createTrajectoryAccuracyScorerCode } from '@mastra/evals/scorers/prebuilt'

const trajectoryScorer = createTrajectoryAccuracyScorerCode({
  expectedTrajectory: {
    steps: [
      { stepType: 'tool_call', name: 'search' },
      { stepType: 'tool_call', name: 'format' },
    ],
  },
})

const result = await runEvals({
  target: mastra.getAgent('myAgent'),
  scorers: {
    agent: [qualityScorer], // receives raw MastraDBMessage[] output
    trajectory: [trajectoryScorer], // receives pre-extracted Trajectory
  },
  data: [{ input: 'Find and format the data' }],
})

// result.scores.agent['quality'] — agent-level score
// result.scores.trajectory['code-trajectory-accuracy-scorer'] — trajectory score
```
