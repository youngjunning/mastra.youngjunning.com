# 轨迹精度记分器

Mastra 提供了两个轨迹准确性评分器，用于评估Agent或Workflow程是否遵循预期的操作序列：

1. **基于代码的记分器**- 使用精确的步骤匹配和排序进行确定性评估
2. **基于LLM的评分者**- 使用人工智能进行语义评估来评估轨迹质量和适当性

两名记分员都与Agent和Workflow程一起工作。这`runEvals` pipeline automatically extracts trajectories, so scorers receive a `Trajectory` object directly.

## 轨迹提取 {/* #trajectory-extraction */}

这`runEvals` pipeline uses two extraction strategies, depending on whether observability storage is configured:

### 基于痕迹的提取（首选） {/* #trace-based-extraction-preferred */}

当目标的`Mastra` instance has storage configured, the pipeline fetches the full execution trace from the observability store and calls `extractTrajectoryFromTrace()`. This produces a hierarchical trajectory with nested `children` that captures the complete execution tree. The tree includes nested agent runs and tool calls within workflow steps. It also includes model generations.

例如，调用Agent的Workflow程，Agent又调用Tool，会生成：

```text
workflow_run
  └─ workflow_step (validate-input)
  └─ workflow_step (process-data)
       └─ agent_run (my-agent)
            └─ model_generation
            └─ tool_call (search)
            └─ model_generation
            └─ tool_call (summarize)
  └─ workflow_step (save-result)
```

### 回退提取 {/* #fallback-extraction */}

当存储不可用时，管道会回退到：

* **Agent商：** `extractTrajectory()`, Extracts `ToolCallStep` entries from `toolInvocations` in the agent's message output. Produces a flat list of tool calls.
* **Workflow程：** `extractWorkflowTrajectory()`, Extracts `WorkflowStepStep` entries from `stepResults`. Produces a flat list of workflow steps.

这些回退不会捕获嵌套执行或非Tool调用范围。

## 预期步骤 {/* #expected-steps */}

定义预期轨迹时，使用`ExpectedStep` instead of the full `TrajectoryStep` discriminated union. `ExpectedStep` is a discriminated union that mirrors `TrajectoryStep`: when you specify a `stepType`, you get autocomplete for that variant's fields (e.g., `toolArgs` for `tool_call`, `modelId` for `model_generation`). All variant-specific fields are optional, so you only assert against what you care about.

忽略`stepType` entirely to match any step by name only.

### 简单的预期步骤 {/* #simple-expected-steps */}

```typescript
const steps: ExpectedStep[] = [
  // Match by name only (any step type)
  { name: 'search' },

  // Match by name and step type (autocomplete for tool_call fields)
  { name: 'search', stepType: 'tool_call' },

  // Match with specific toolArgs (auto-compared when present)
  { name: 'search', stepType: 'tool_call', toolArgs: { query: 'weather' } },

  // Match a model generation step by model ID
  { name: 'gpt-4o', stepType: 'model_generation', modelId: 'gpt-4o' },
]
```

### 嵌套期望 {/* #nested-expectations */}

每个预期步骤可以包括`children` config with its own evaluation rules. This lets you set different ordering or comparison rules at each level of the hierarchy.

```typescript
const scorer = createTrajectoryScorerCode({
  defaults: {
    ordering: 'strict',
    steps: [
      { name: 'validate-input', stepType: 'workflow_step' },
      {
        name: 'research-agent',
        stepType: 'agent_run',
        children: {
          // Sub-agent can call tools in any order
          ordering: 'unordered',
          steps: [
            { name: 'search', stepType: 'tool_call' },
            { name: 'summarize', stepType: 'tool_call' },
          ],
        },
      },
      { name: 'save-result', stepType: 'workflow_step' },
    ],
  },
})
```

在此示例中，父Workflow要求对其步骤进行严格排序，但嵌套Workflow`research-agent` allows its tool calls in any order.

## 在得分手之间进行选择 {/* #choosing-between-scorers */}

### 在以下情况下使用基于代码的评分器： {/* #use-the-code-based-scorer-when */}

* 你需要**deterministic, reproducible** results
* 你有一个**known expected trajectory** to compare against
* 您想要验证**exact step sequences**
* 速度和成本是优先考虑的（没有法学硕士呼叫）
* 您正在 CI/CD 中运行自动化测试

### 在以下情况下使用基于 LLM 的评分器： {/* #use-the-llm-based-scorer-when */}

* 你需要**semantic understanding** of whether steps were appropriate
* 最优轨迹**isn't predetermined** (evaluate based on task requirements)
* 你想要检测**unnecessary, redundant, or missing** steps
* 你需要**explanations** for scoring decisions
* 您正在评估**production agent behavior**

### 预期轨迹来源 {/* #expected-trajectory-sources */}

基于代码的记分器解决了`expectedTrajectory` from two sources, in order of priority:

1. **构造函数选项**：创建得分手时经过的静态轨迹。用于所有数据集项目。
2. **数据集项**： 一个`expectedTrajectory` field on the dataset item, passed through the `runEvals` pipeline. Allows different expected trajectories per item.

```typescript title="src/static-expected.ts"
// Static: same expected trajectory for all items
const scorer = createTrajectoryAccuracyScorerCode({
  expectedTrajectory: {
    steps: [
      { stepType: 'tool_call', name: 'search' },
      { stepType: 'tool_call', name: 'summarize' },
    ],
  },
})
```

```typescript title="src/per-item-expected.ts"
// Per-item: each dataset item has its own expectedTrajectory
const scorer = createTrajectoryAccuracyScorerCode()

await runEvals({
  target: mastra.getAgent('myAgent'),
  scorers: { trajectory: [scorer] },
  data: [
    {
      input: 'Search and summarize weather',
      expectedTrajectory: {
        steps: [
          { stepType: 'tool_call', name: 'search' },
          { stepType: 'tool_call', name: 'summarize' },
        ],
      },
    },
    {
      input: 'Just search for weather',
      expectedTrajectory: {
        steps: [{ stepType: 'tool_call', name: 'search' }],
      },
    },
  ],
})
```

### 评价模式 {/* #evaluation-modes */}

基于代码的记分器以三种模式之一运行`ordering`:

#### 严格模式（`ordering: 'strict'`) {/* #strict-mode-ordering-strict */}

只有完全匹配（相同的步骤、相同的顺序，没有任何额外或缺失）得分`1.0`. Anything else gets partial credit for the expected steps that matched in position, with a penalty deducted for each extra step. For example, the two expected steps followed by one extra step scores `0.75`.

#### 放松模式（`ordering: 'relaxed'`, default) {/* #relaxed-mode-ordering-relaxed-default */}

允许额外的步骤。预期步骤必须以正确的相对顺序出现。分数是根据匹配的预期步数计算的，并对额外或重复的步数可选择惩罚。

#### 无序模式（`ordering: 'unordered'`) {/* #unordered-mode-ordering-unordered */}

仅检查每个预期步骤是否存在。顺序被忽略，额外的步骤会在结果中报告，但不会受到惩罚。

## 基于代码的评分详细信息 {/* #code-based-scoring-details */}

* **连续得分**：在每种排序模式下返回 0.0 和 1.0 之间的值。在严格模式下，分数是按顺序匹配的预期步数的份额，减去额外步数的惩罚，并且当`allowRepeatedSteps` is `false`, repeated steps
* **确定性**：相同的输入总是产生相同的输出
* **快速地**: 没有外部API调用

## 基于代码的记分器示例 {/* #code-based-scorer-examples */}

### 严格排序的Agent轨迹 {/* #agent-trajectory-with-strict-ordering */}

验证Agent是否遵循准确的Tool调用顺序：

```typescript title="src/example-strict-trajectory.ts"
import { createTrajectoryAccuracyScorerCode } from '@mastra/evals/scorers/prebuilt'
import { runEvals } from '@mastra/core/evals'

const scorer = createTrajectoryAccuracyScorerCode({
  expectedTrajectory: {
    steps: [
      { stepType: 'tool_call', name: 'auth-tool' },
      { stepType: 'tool_call', name: 'fetch-tool' },
    ],
  },
  comparisonOptions: { ordering: 'strict' },
})

const result = await runEvals({
  target: mastra.getAgent('myAgent'),
  scorers: { trajectory: [scorer] },
  data: [{ input: 'Get my data' }],
})

console.log(result.scores.trajectory['code-trajectory-accuracy-scorer']) // 1.0
```

### 轻松排序的Agent轨迹 {/* #agent-trajectory-with-relaxed-ordering */}

只要预期步骤以正确的相对顺序出现，就允许额外的步骤：

```typescript title="src/example-relaxed-trajectory.ts"
const scorer = createTrajectoryAccuracyScorerCode({
  expectedTrajectory: {
    steps: [
      { stepType: 'tool_call', name: 'search-tool' },
      { stepType: 'tool_call', name: 'summarize-tool' },
    ],
  },
  comparisonOptions: { ordering: 'relaxed' },
})

// Agent called search-tool → log-tool → summarize-tool
// The extra log-tool is allowed in relaxed mode
// score: 0.75 — all expected steps matched, small penalty for extra step
```

评估Workflow的执行路径：

### 特征 {/* #features */}

基于法学硕士的评分器提供：

* **任务感知评估**：根据用户的请求评估每个步骤是否必要
* **订购评估**：评估步骤是否按逻辑顺序执行
* **缺失步骤检测**：标识应该采取的步骤
* **冗余检测**：标记不必要或重复的步骤
* **推理生成**：为评分决策提供人类可读的解释

### 评估流程 {/* #evaluation-process */}

1. **接收轨迹**：获取预提取的`Trajectory` object from the pipeline
2. **分析步骤**：使用法学硕士评估每个步骤的必要性和顺序
3. **生成分数**：计算分数，权重为 60% 必要性、30% 排序、减去 10% 缺失罚分
4. **产生推理**：提供人类可读的解释

## 基于LLM的评分细节 {/* #llm-based-scoring-details */}

* **分数分数**：返回 0.0 到 1.0 之间的值
* **情境感知**：考虑用户意图和任务要求
* **解释性的**：提供分数的推理
* **灵活的**：有或没有预期轨迹均可工作

### 评分行为 {/* #scoring-behavior */}

统一评分器评估四个维度：

1. **准确性**：将实际步骤与预期步骤进行匹配（如果`steps` is configured). Uses the `ordering` mode.
2. **效率**：检查步骤预算（`maxSteps`, `maxTotalTokens`, `maxTotalDurationMs`) and redundant calls (`noRedundantCalls`).
3. **黑名单**：检查禁止的Tool或序列。任何违规行为都会立即导致分数**0.0** regardless of other dimensions.
4. **Tool故障**：检测重试和回退模式。它还检测参数修正模式。

最终得分是活动维度的加权组合，根据活动维度进行标准化。默认权重为准确度 0.4、效率 0.3、Tool故障 0.2、黑名单 0.1，但您可以通过以下方式自定义权重：`weights` option. Blacklist violations override everything to 0. When nested evaluations are present, the score is 70% top-level and 30% nested average.

### 每件商品的期望 {/* #per-item-expectations */}

每个数据集项都可以用自己的值覆盖默认值`expectedTrajectory`. This lets you vary expectations per prompt:

```typescript title="src/unified-per-item.ts"
import { createTrajectoryScorerCode } from '@mastra/evals/scorers/prebuilt'
import { runEvals } from '@mastra/core/evals'

// Default blacklist applies to all items
const scorer = createTrajectoryScorerCode({
  defaults: {
    blacklistedTools: ['deleteAll'],
    maxSteps: 5,
  },
})

const result = await runEvals({
  target: mastra.getAgent('myAgent'),
  scorers: { trajectory: [scorer] },
  data: [
    {
      input: 'Search for weather',
      expectedTrajectory: {
        steps: [{ stepType: 'tool_call', name: 'search' }],
        maxSteps: 2,
      },
    },
    {
      input: 'Search and summarize',
      expectedTrajectory: {
        steps: [
          { stepType: 'tool_call', name: 'search' },
          { stepType: 'tool_call', name: 'summarize' },
        ],
      },
    },
  ],
})
```

### 示例：效率和黑名单 {/* #example-efficiency-and-blacklist */}

```typescript title="src/unified-scorer.ts"
import { createTrajectoryScorerCode } from '@mastra/evals/scorers/prebuilt'

const scorer = createTrajectoryScorerCode({
  defaults: {
    blacklistedTools: ['escalate', 'admin-override'],
    blacklistedSequences: [['escalate', 'admin-override']],
    maxSteps: 10,
    noRedundantCalls: true,
    maxRetriesPerTool: 2,
  },
  // Customize how dimensions contribute to the final score
  weights: {
    accuracy: 0.5, // prioritize step accuracy
    efficiency: 0.3,
    toolFailures: 0.1,
    blacklist: 0.1,
  },
})
```

## 使用轨迹记分器`runEvals` {/* #using-trajectory-scorers-with-runevals */}

轨迹记分器配置在`trajectory` key in the scorer config. The `runEvals` pipeline handles trajectory extraction automatically.

### 智能体轨迹评估 {/* #agent-trajectory-evaluation */}

```typescript title="src/agent-trajectory-eval.ts"
import { runEvals } from '@mastra/core/evals'
import { createTrajectoryAccuracyScorerCode } from '@mastra/evals/scorers/prebuilt'

const trajectoryScorer = createTrajectoryAccuracyScorerCode({
  expectedTrajectory: {
    steps: [
      { stepType: 'tool_call', name: 'search' },
      { stepType: 'tool_call', name: 'format' },
    ],
  },
})

const result = await runEvals({
  target: mastra.getAgent('myAgent'),
  scorers: {
    agent: [qualityScorer], // receives raw MastraDBMessage[] output
    trajectory: [trajectoryScorer], // receives pre-extracted Trajectory
  },
  data: [{ input: 'Find and format the data' }],
})

// result.scores.agent['quality'] — agent-level score
// result.scores.trajectory['code-trajectory-accuracy-scorer'] — trajectory score
```
