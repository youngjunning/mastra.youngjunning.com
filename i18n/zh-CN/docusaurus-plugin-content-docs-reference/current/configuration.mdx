# 配置

本参考列出 Mastra 支持的所有选项。通过实例化 [`Mastra` 类](/reference/core/mastra-class) 来初始化和配置 Mastra。

```ts title="src/mastra/index.ts"
import { Mastra } from '@mastra/core'

export const mastra = new Mastra({
  // Your options...
})
```

## 顶层选项 {/* #top-level-options */}

### agents {/* #agents */}

**类型：** `Record<string, Agent>`

按名称索引的 Agent 实例记录。Agent 是能够利用 AI 模型、Tool 和 Memory 自主决策并采取行动的系统。

详情请参阅 [Agent 文档](/docs/agents/overview)。

```typescript title="src/mastra/index.ts"
import { Mastra } from '@mastra/core'
import { Agent } from '@mastra/core/agent'

export const mastra = new Mastra({
  agents: {
    weatherAgent: new Agent({
      id: 'weather-agent',
      name: 'Weather Agent',
      instructions: 'You help with weather information',
      model: '__GATEWAY_OPENAI_MODEL__',
    }),
  },
})
```

### backgroundTasks {/* #backgroundtasks */}

**类型：** `BackgroundTaskManagerConfig`

启用并配置后台任务管理器。启用后，Agent 可以异步派发耗时的 Tool 调用（包括子 Agent 调用），同时继续运行 Agent 循环。任务会持久化，因此必须配置 `storage` 后端。

详情请参阅[后台任务文档](/docs/harness/background-tasks)。

```typescript title="src/mastra/index.ts"
import { Mastra } from '@mastra/core'
import { LibSQLStore } from '@mastra/libsql'

export const mastra = new Mastra({
  storage: new LibSQLStore({
    id: 'mastra-storage',
    url: 'file:./mastra.db',
  }),
  backgroundTasks: {
    enabled: true,
    globalConcurrency: 10,
    perAgentConcurrency: 5,
    backpressure: 'queue',
    defaultTimeoutMs: 300_000,
  },
})
```

### deployer {/* #deployer */}

**类型：** `IDeployer`

用于将应用发布到云平台的部署 Provider。

详情请参阅[部署文档](/docs/deployment/overview)。

```typescript title="src/mastra/index.ts"
import { Mastra } from '@mastra/core'
import { NetlifyDeployer } from '@mastra/deployer-netlify'

export const mastra = new Mastra({
  deployer: new NetlifyDeployer(),
})
```

### events {/* #events */}

**类型：** `Record<string, EventHandler | EventHandler[]>`

内部发布/订阅系统的事件处理器。将事件主题映射到相应的处理函数；事件发布到主题时会调用这些函数。

:::warning
此选项供 Mastra 的 Workflow 引擎内部使用。大多数用户无需配置。
:::

```typescript title="src/mastra/index.ts"
import { Mastra } from '@mastra/core'

export const mastra = new Mastra({
  events: {
    'my-topic': async event => {
      console.log('Event received:', event)
    },
  },
})
```

### gateways {/* #gateways */}

**类型：** `Record<string, MastraModelGateway>`

用于访问 LLM Provider 的自定义模型路由网关。网关负责各 Provider 的身份验证、URL 构造和模型解析。可用此选项支持自定义或自托管的 LLM Provider。

详情请参阅[自定义网关文档](/models/gateways/custom-gateways)。

```typescript title="src/mastra/index.ts"
import { Mastra } from '@mastra/core'
import { MyPrivateGateway } from './gateways'

export const mastra = new Mastra({
  gateways: {
    private: new MyPrivateGateway(),
  },
})
```

### idGenerator {/* #idgenerator */}

**类型：** `(context?: IdGeneratorContext) => string`\
**Default:** `crypto.randomUUID()`

用于创建唯一标识符的自定义 ID 生成函数。Mastra 会传入可选的上下文，让您能根据要创建的实体生成 ID。

`IdGeneratorContext` 包含：

- `idType`: `'thread' | 'message' | 'run' | 'step' | 'generic'`
- `source?`: `'agent' | 'workflow' | 'memory'`
- `entityId?`：请求生成 ID 的 Agent、Workflow 或 Memory 实体的 ID
- `threadId?`：适用时的线程 ID（例如创建消息 ID 时）
- `resourceId?`：适用时的资源 ID（例如按用户划分的线程）
- `role?`：创建消息 ID 时的消息角色
- `stepType?`：创建步骤 ID 时的 Workflow 步骤类型

:::warning

Mastra 内部使用此选项为 Workflow 运行、Agent 对话及其他资源创建 ID。大多数用户无需配置。

:::

```typescript title="src/mastra/index.ts"
import { v4 as uuid } from '@lukeed/uuid'
import { Mastra } from '@mastra/core'

export const mastra = new Mastra({
  idGenerator: context => {
    if (context?.idType === 'message' && context?.threadId) {
      return `msg-${context.threadId}-${uuid()}`
    }

    if (context?.idType === 'run' && context?.source && context?.entityId) {
      return `${context.source}-run-${context.entityId}-${uuid()}`
    }

    return uuid()
  },
})
```

### logger {/* #logger */}

**类型：** `IMastraLogger | false`\
**默认值：** `ConsoleLogger`，开发环境级别为 `INFO`，生产环境级别为 `WARN`

应用日志记录和调试所用的 Logger 实现。设为 `false` 可完全关闭日志。

详情请参阅[日志文档](/docs/observability/logging)。

```typescript title="src/mastra/index.ts"
import { Mastra } from '@mastra/core'
import { PinoLogger } from '@mastra/loggers'

export const mastra = new Mastra({
  logger: new PinoLogger({ name: 'MyApp', level: 'debug' }),
})
```

### mcpServers {/* #mcpservers */}

**类型：** `Record<string, MCPServerBase>`

向兼容 MCP（Model Context Protocol）的客户端提供 Mastra Tool、Agent、Workflow 和资源的 MCP 服务器。可用此选项编写自己的 MCP 服务器，供任何支持该协议的系统使用。

详情请参阅 [MCP 概述](/docs/connections/mcp)。

```typescript title="src/mastra/index.ts"
import { Mastra } from '@mastra/core'
import { MCPServer } from '@mastra/mcp'

const mcpServer = new MCPServer({
  id: 'my-mcp-server',
  name: 'My MCP Server',
  version: '1.0.0',
})

export const mastra = new Mastra({
  mcpServers: {
    myServer: mcpServer,
  },
})
```

### memory {/* #memory */}

**类型：** `Record<string, MastraMemory>`

可供 Agent 引用的 Memory 实例注册表，包括使用 `{ type: 'id', memoryId: '<key>' }` 的已存储 Agent。Memory 会保留过去对话中的相关信息，使 Agent 的多轮交互保持连贯。Mastra 支持保存近期消息的消息历史、保存用户长期信息的工作记忆，以及按相关性找回旧消息的语义检索。

详情请参阅 [Memory 文档](/docs/memory/overview)。

:::note

多数用户直接在 Agent 上配置 Memory。此顶层选项用于定义可由多个 Agent 共享的可复用 Memory 实例。

:::

```typescript title="src/mastra/index.ts"
import { Mastra } from '@mastra/core'
import { Memory } from '@mastra/memory'
import { LibSQLStore } from '@mastra/libsql'

export const mastra = new Mastra({
  storage: new LibSQLStore({
    id: 'mastra-storage',
    url: ':memory:',
  }),
  memory: {
    chatMemory: new Memory({
      options: {
        lastMessages: 20,
      },
    }),
  },
})
```

### observability {/* #observability */}

**类型：** `ObservabilityEntrypoint`

Mastra 为 AI 应用提供可观测性能力。可通过了解 AI 特有模式的 Tool 监控 LLM 操作、追踪 Agent 决策并调试复杂的 Workflow。追踪会记录模型交互、Agent 执行路径、Tool 调用和 Workflow 步骤。

详情请参阅[可观测性文档](/docs/observability/overview)。

```typescript title="src/mastra/index.ts"
import { Mastra } from '@mastra/core'
import { LibSQLStore } from '@mastra/libsql'
import { Observability, MastraStorageExporter } from '@mastra/observability'

export const mastra = new Mastra({
  storage: new LibSQLStore({
    id: 'mastra-storage',
    url: 'file:./mastra.db',
  }),
  observability: new Observability({
    configs: {
      default: {
        serviceName: 'my-app',
        exporters: [new MastraStorageExporter()],
      },
    },
  }),
})
```

### processors {/* #processors */}

**类型：** `Record<string, Processor>`

用于转换 Agent 输入和输出的 Processor。Processor 在 Agent 执行链的特定位置运行，可在输入到达语言模型前修改输入，也可在输出返回前修改输出。可用它添加护栏、检测提示词注入、审核内容或执行自定义业务逻辑。

详情请参阅 [Processor 文档](/docs/agents/processors)。

:::note

多数用户直接在 Agent 上配置 Processor。此顶层选项用于定义可由多个 Agent 共享的可复用 Processor 实例。

:::

```typescript title="src/mastra/index.ts"
import { Mastra } from '@mastra/core'
import { ModerationProcessor } from '@mastra/core/processors'

export const mastra = new Mastra({
  processors: {
    moderation: new ModerationProcessor({
      model: '__GATEWAY_OPENAI_MODEL_LUNA__',
      categories: ['hate', 'harassment', 'violence'],
    }),
  },
})
```

### pubsub {/* #pubsub */}

**类型：** `PubSub`\
**Default:** `EventEmitterPubSub`

组件间基于事件通信的发布/订阅系统。Mastra 内部用它处理 Workflow 事件及组件通信。

:::warning
此选项供 Mastra 内部使用。大多数用户无需配置。
:::

```typescript title="src/mastra/index.ts"
import { Mastra } from '@mastra/core'
import { CustomPubSub } from './pubsub'

export const mastra = new Mastra({
  pubsub: new CustomPubSub(),
})
```

### scorers {/* #scorers */}

**类型：** `Record<string, Scorer>`

Scorer 评估 Agent 响应与 Workflow 输出的质量。它们通过模型评分、规则和统计方法提供可量化指标，帮助衡量 Agent 质量、追踪表现、比较方案并发现改进空间。

详情请参阅 [Scorer 文档](/docs/evals/overview)。

:::note

多数用户直接在 Agent 上配置 Scorer。此顶层选项用于定义可由多个 Agent 共享的可复用 Scorer 实例。

:::

```typescript title="src/mastra/index.ts"
import { Mastra } from '@mastra/core'
import { createToxicityScorer } from '@mastra/evals/scorers/prebuilt'

export const mastra = new Mastra({
  scorers: {
    toxicity: createToxicityScorer({ model: '__GATEWAY_OPENAI_MODEL_LUNA__' }),
  },
})
```

### classifiers {/* #classifiers */}

**类型：** `Record<string, Classifier>`

Classifier 向决策模型提出关于应用状态的固定选项问题，并返回类型化答案。在这里注册可复用的 Classifier 后，可通过 `getClassifier()` 或 `getClassifierById()` 获取。若评估已注册的 Classifier 时没有活动 Trace，它会启动根 `CLASSIFIER_EVALUATION` span，使用 `Mastra` 实例配置的可观测性 Provider。

详情请参阅 [Classifier 参考](/reference/classifier/classifier)。

```typescript title="src/mastra/index.ts"
import { Mastra } from '@mastra/core'
import { Classifier } from '@mastra/core/classifier'
import { typeSafeAi } from '@ai-sdk/typesafe-ai'

const safety = new Classifier({
  id: 'safety',
  model: typeSafeAi.decisionModel('__AI_SDK_TYPESAFE_DECISION_MODEL__'),
  questions: {
    unsafe: {
      type: 'boolean',
      criteria: { true: 'Unsafe', false: 'Safe' },
    },
  },
})

export const mastra = new Mastra({
  classifiers: { safety },
})
```

详情请参阅[存储文档](/docs/storage)。

```typescript title="src/mastra/index.ts"
import { Mastra } from '@mastra/core'
import { LibSQLStore } from '@mastra/libsql'

export const mastra = new Mastra({
  storage: new LibSQLStore({
    id: 'mastra-storage',

  }),
})
```

### tools {/* #tools */}

**类型：** `Record<string, Tool>`

Tool 是 Agent 可复用的函数，用于与外部系统交互。每个 Tool 都定义了输入、输出及执行逻辑。

详情请参阅 [Tool 文档](/docs/agents/tools)。

:::note
多数用户直接在 Agent 上配置 Tool。此顶层选项用于定义可由多个 Agent 共享的可复用 Tool。
:::

```typescript title="src/mastra/index.ts"
import { Mastra } from '@mastra/core'
import { createTool } from '@mastra/core/tools'
import { z } from 'zod'

const weatherTool = createTool({
  id: 'get-weather',
  description: 'Fetches weather for a city',
  inputSchema: z.object({
    city: z.string(),
  }),
  execute: async () => {
    return { temperature: 20, conditions: 'Sunny' }
  },
})

export const mastra = new Mastra({
  tools: {
    weather: weatherTool,
  },
})
```

### vectors {/* #vectors */}

**类型：** `Record<string, MastraVector>`

用于语义搜索和向量嵌入的向量存储。可用于 RAG 流程、相似度搜索等基于嵌入的功能。Mastra 支持 Pinecone、带 pgvector 的 PostgreSQL、OracleDB、MongoDB 等向量数据库。

详情请参阅 [RAG 文档](/reference/rag/overview)。

:::note
多数用户在构建 RAG 流程时直接创建向量存储。此顶层选项用于定义可在应用中共享的可复用向量存储实例。
:::

```typescript title="src/mastra/index.ts"
import { Mastra } from '@mastra/core'
import { PineconeVector } from '@mastra/pinecone'

export const mastra = new Mastra({
```

## 打包器选项 {/* #bundler-options */}

### bundler.externals {/* #bundlerexternals */}

**类型：** `boolean | string[]`\
**Default:** `true`

运行 `mastra build` 时，Mastra 会将项目打包到 `.mastra/output` 目录。此选项控制哪些包不进入 bundle（标记为“external”），而由包管理器另行安装。当 Mastra 内置的打包器（[Rollup](https://rollupjs.org/configuration-options/#external)）无法顺利打包某些包时，此选项很有用。

默认情况下，`mastra build` 会将此选项设为 `true`。

各值的含义如下：

- `true`：将项目 `package.json` 中列出的所有依赖项标记为 external
- `false`：不将任何依赖项标记为 external；全部一起打包
- `string[]`：指定要标记为 external 的包名数组；其余包一起打包

```typescript title="src/mastra/index.ts"
import { Mastra } from '@mastra/core'

export const mastra = new Mastra({
  bundler: {
    externals: ['some-package', 'another-package'],
  },
})
```

**类型：** `boolean`\
**Default:** `false`

为打包产物生成 source map。启用后，`mastra dev` 和 `mastra start` 会使用 Node.js 的 `--enable-source-maps` 标志启动服务器，使堆栈跟踪指向源文件。

```typescript title="src/mastra/index.ts"
import { Mastra } from '@mastra/core'

export const mastra = new Mastra({
  bundler: {
    sourcemap: true,
  },
})
```

**类型：** `boolean`\
**Default:** `false`

压缩打包产物：移除注释和空白，并缩短局部标识符；导出的名称会保留。

默认关闭，以保持构建产物可读、堆栈跟踪可用。需要减小 bundle 大小时再启用，例如打包用于本地部署的容器镜像。`mastra dev` 不会压缩。

### bundler.transpilePackages {/* #bundlertranspilepackages */}

**类型：** `string[]`\
**Default:** `[]`

列出构建时需通过 esbuild 转译源代码的包。对于包含 TypeScript 或其他打包前需编译的代码的依赖项，使用此选项。

仅在直接导入尚未编译的源代码时需要此选项。已经编译为 CommonJS 或 ESM 的包无需列在这里。

Mastra 会自动检测 monorepo 中的 Workspace 包并加入此列表，因此通常只需指定需要转译的外部包。

构建时，Mastra 还会解析 `tsconfig.json` 中的 `baseUrl` 和 `paths` 别名，包括指向 TypeScript 源文件的 ESM 风格导入，例如 `~/utils/logger.js`。

```typescript title="src/mastra/index.ts"
import { Mastra } from '@mastra/core'

  bundler: {
    transpilePackages: ['@my-org/shared-utils'],
  },

```

### bundler.pnpmWorkspaceSettings {/* #bundlerpnpmworkspacesettings */}

**类型：** `Record<string, JSONValue>`\
**Default:** `{}`

使用 pnpm 安装部署依赖项时，显式指定写入生成的 `pnpm-workspace.yaml` 的设置。值可以是字符串、数字、布尔值、null、数组或嵌套对象。其他包管理器会忽略此选项。

此选项用于指定部署安装时应遵循的 pnpm 安装策略：

```typescript title="src/mastra/index.ts"
import { Mastra } from '@mastra/core'

export const mastra = new Mastra({
  bundler: {
    pnpmWorkspaceSettings: {
      blockExoticSubdeps: false,
      minimumReleaseAge: 0,
    },
  },
})
```

显式设置会覆盖从源 Workspace 复制的设置。省略此选项时，仍按原有方式只复制源 Workspace 设置的一个子集。

仅支持以下键：`allowBuilds`、`onlyBuiltDependencies`、`ignoredBuiltDependencies`、`minimumReleaseAge`、`minimumReleaseAgeExclude`、`trustPolicy`、`trustPolicyExclude`、`trustPolicyIgnoreAfter` 和 `blockExoticSubdeps`。其他键会在 pnpm 运行前报错，包括 Mastra 为部署产物生成的键（`packages`、`overrides`、`patchedDependencies`、`allowUnusedPatches`、`supportedArchitectures`、`nodeLinker`），以及会改变 TLS 验证、registry、网络访问、store 完整性、依赖扩展、catalog 或构建脚本权限的设置。`neverBuiltDependencies` 不受支持，因为 pnpm 10 会运行所有未列在其中的构建脚本。此选项不接受命令行标志，也不适合存放密钥。

显式设置的 `allowBuilds` 和 `onlyBuiltDependencies` 会采用与从源文件复制的构建许可相同的校验方式。

### server.auth {/* #serverauth */}

**类型：** `MastraAuthConfig | MastraAuthProvider`

服务器的身份验证配置。Mastra 支持 JWT、Clerk、Supabase、Firebase、WorkOS 和 Auth0 等多种身份验证 Provider。

详情请参阅[身份验证文档](/docs/auth/overview)。

`mapUserToResourceId` 回调将已验证的用户映射到用于 Memory/线程作用域的资源 ID。提供此回调时，它会在身份验证成功后调用，返回值会以 `MASTRA_RESOURCE_ID_KEY` 写入请求上下文。省略时，内置路由会回退使用客户端提供的资源 ID（例如 `memory.resource`），因此所有权检查会信任调用方。Mastra 会在这种情况下于启动时发出警告。详情请参阅[授权（用户隔离）](/docs/server/middleware#authorization-user-isolation)。

### server.handleShutdownSignals {/* #serverhandleshutdownsignals */}

**类型：** `boolean`\
**Default:** `true`

由 `mastra dev` 和 `mastra build` 生成的服务器是否自行安装 `SIGINT`／`SIGTERM` 处理器。默认收到信号后会开始优雅退出：服务器先停止接受新连接并等待进行中的请求完成，再调用 `mastra.shutdown()` 并退出进程（参阅 [`server.drainTimeout`](#serverdraintimeout)）。

设为 `handleShutdownSignals: false` 可自行处理信号，例如在 Mastra 配置模块中注册调用 `mastra.shutdown()` 的处理器：

```typescript title="src/mastra/index.ts"
import { Mastra } from '@mastra/core'

export const mastra = new Mastra({
  server: {
    handleShutdownSignals: false,
  },
})

let shuttingDown = false
const shutdown = async () => {
  if (shuttingDown) return
  shuttingDown = true
  // custom shutdown coordination
  await mastra.shutdown()
  process.exit(0)
}

process.once('SIGINT', shutdown)
process.once('SIGTERM', shutdown)
```

请注意以下限制：

- 如果没有自行注册处理器，Node.js 会按默认信号行为立即终止进程，不会等待请求完成。
- 自定义处理器无法访问生成的入口文件中的 HTTP 服务器句柄，因此无法等待进行中的 HTTP 请求完成。如果只需延长等待时间，优先调整 [`server.drainTimeout`](#serverdraintimeout)。如需完全控制服务器生命周期，请使用[服务器适配器](/docs/server/server-adapters)。
- 运行 `mastra dev` 时，内置处理器会在热重载之间释放存储资源（例如 DuckDB 文件锁）。关闭内置处理器且没有等效的自定义处理器，重载后可能发生锁冲突。

### server.middleware {/* #servermiddleware */}

**类型：** `Middleware | Middleware[]`

自定义 Middleware 可在路由处理器执行前后拦截请求，用于身份验证、日志记录、注入请求上下文或添加请求头。每个 Middleware 都会收到 Hono `Context` 和 `next` 函数。返回 `Response` 可提前结束请求；调用 `next()` 则继续处理。

详情请参阅 [Middleware 文档](/docs/server/middleware)。

```typescript title="src/mastra/index.ts"
import { Mastra } from '@mastra/core'

export const mastra = new Mastra({
  server: {
    middleware: [
      {
        handler: async (c, next) => {
          const authHeader = c.req.header('Authorization')
          if (!authHeader) {
            return new Response('Unauthorized', { status: 401 })
          }
          await next()
        },
        path: '/api/*',
      },
    ],
  },
})
```

### server.onError {/* #serveronerror */}

**类型：** `(err: Error, c: Context) => Response | Promise<Response>`

发生未处理错误时调用的自定义错误处理器。可用它自定义错误响应、将错误记录到 Sentry 等外部服务，或实现自己的错误格式。

所有服务器适配器都支持此钩子。`c` 参数提供兼容 Hono 的上下文对象；非 Hono 适配器（Koa、Express、Fastify）会提供 shim，其中包含 `c.json()`、`c.req.path` 等常用方法。

```typescript title="src/mastra/index.ts"
import { Mastra } from '@mastra/core'
import * as Sentry from '@sentry/node'

export const mastra = new Mastra({
  server: {
    onError: (err, c) => {
      Sentry.captureException(err)

      return c.json(
        {
          error: err.message,
          timestamp: new Date().toISOString(),
        },
        500,
      )
    },
  },
})
```

### server.onValidationError {/* #serveronvalidationerror */}

**类型：** `(error: ZodError, context: 'query' | 'body' | 'path') => { status: number; body: unknown } | undefined`

请求未通过 Zod schema 校验时调用的自定义处理器。可用它自定义校验错误响应、修改状态码，或按 API 规范设置错误格式。

返回 `{ status, body }` 对象可覆盖默认的 `400` 响应；返回 `undefined` 则沿用默认行为。所有服务器适配器（Hono、Express、Fastify、Koa）都支持此钩子。

`context` 参数表示请求的哪一部分未通过校验：

- `'query'`：查询参数
- `'body'`：请求体
- `'path'`：路径参数

```typescript title="src/mastra/index.ts"
import { Mastra } from '@mastra/core'

export const mastra = new Mastra({
  server: {
    onValidationError: (error, context) => ({
      status: 422,
      body: {
        ok: false,
        errors: error.issues.map(i => ({
          path: i.path.join('.'),
          message: i.message,
        })),
        source: context,
      },
    }),
  },
})
```

也可以对单条路由设置 `onValidationError`，该路由由 `createRoute()` 创建。路由级钩子优先于服务器级钩子。

### server.port {/* #serverport */}

**类型：** `number`\
**默认值：** `4111`（若设置了 `PORT` 环境变量，则使用该值）

Mastra 开发服务器绑定的端口。如果设置了 `PORT` 环境变量，它会覆盖默认值。

```typescript title="src/mastra/index.ts"
import { Mastra } from '@mastra/core'

export const mastra = new Mastra({
  server: {
    port: 8080,
  },
})
```

### server.drainTimeout {/* #serverdraintimeout */}

**类型：** `number`\
**Default:** `5000` (5 seconds)

服务器收到 `SIGINT` 或 `SIGTERM` 后，等待进行中请求完成的最长时间，单位为毫秒。值必须是 `0` 到 `2147483647` 之间的有限数值。在此期间，服务器停止接受新连接，并等待进行中的请求（包括活动流）完成；若先到截止时间，剩余 HTTP 连接将关闭。WebSocket 等升级连接会在进程退出时结束。无论如何，进程退出前都会调用 `mastra.shutdown({ drainTimeout })`，让进行中的 Workflow 运行（包括持久化 Agent 运行）在 Worker 和发布/订阅订阅被清理前，有相同时间完成或暂停。后台任务取消和 Worker 清理也共用这段时间。随后，生成的服务器还会最多等待 5 秒清理 Workspace 和 Storage。设为 `0` 会跳过两次等待。

滚动部署时，如果需要等待耗时的 Agent 交互或 Workflow 步骤完成，可提高此值。HTTP 请求等待与 Workflow 等待会依次运行，因此最坏情况应按此值的两倍再加 5 秒清理时间估算，并确保总和小于平台的宽限期（例如 Kubernetes 的 `terminationGracePeriodSeconds`）：

```typescript title="src/mastra/index.ts"
import { Mastra } from '@mastra/core'

export const mastra = new Mastra({
  server: {
    drainTimeout: 600000, // 10 minutes
  },
})
```

等待期间再次发送任一关闭信号，会跳过等待并立即终止进程。

### server.studioBase {/* #serverstudiobase */}

**类型：** `string`\
**Default:** `/`

托管 [Studio](/docs/studio/overview) 的基础路径。可用它将 Studio 放在现有应用的子路径，而不是根路径。

与现有应用或 Cloudflare Zero Trust 等受益于共用域名的认证工具集成时，此选项很有用。它也支持在同一域名下管理多个服务。

```typescript title="src/mastra/index.ts"
import { Mastra } from '@mastra/core'

export const mastra = new Mastra({
  server: {
    studioBase: '/my-mastra-studio',
  },
})
```

**URL 示例：**

- 默认：`http://localhost:4111/`（Studio 位于根路径）
- 设置 `studioBase`：`http://localhost:4111/my-mastra-studio/`（Studio 位于子路径）

### server.timeout {/* #servertimeout */}

**类型：** `number`\
**默认值：** `180000`（3 分钟）

请求超时时间，单位为毫秒。超过此时间的请求会被终止。

在无服务器平台上，此限制独立于平台的函数超时。例如，[Vercel Deployer](/reference/deployer/vercel#request-timeouts) 通过 `maxDuration`（秒）设置 Vercel 的上限，而 `server.timeout` 仍然生效，因此耗时请求需要同时提高两项上限。

```typescript title="src/mastra/index.ts"
import { Mastra } from '@mastra/core'

export const mastra = new Mastra({
  server: {
    timeout: 30000, // 30 seconds
  },
})
```
