# 配置

以下参考涵盖了 Mastra 中所有支持的选项。您可以通过实例化来初始化和配置 Mastra[`Mastra` class](/reference/core/mastra-class).

```ts title="src/mastra/index.ts"
import { Mastra } from '@mastra/core'

export const mastra = new Mastra({
  // Your options...
})
```

## 顶级选项 {/* #top-level-options */}

### Agent {/* #agents */}

**类型：** `Record<string, Agent>`

按名称键入的Agent实例的记录。Agent是自主系统，可以使用人工智能模型、Tool和内存做出决策并采取行动。

参观[Agents documentation](/docs/agents/overview) to learn more.

```typescript title="src/mastra/index.ts"
import { Mastra } from '@mastra/core'
import { Agent } from '@mastra/core/agent'

export const mastra = new Mastra({
  agents: {
    weatherAgent: new Agent({
      id: 'weather-agent',
      name: 'Weather Agent',
      instructions: 'You help with weather information',
      model: '__GATEWAY_OPENAI_MODEL__',
    }),
  },
})
```

### 后台任务 {/* #backgroundtasks */}

**类型：** `BackgroundTaskManagerConfig`

启用并配置后台任务管理器。启用后，Agent可以分派长时间运行的Tool调用（包括子Agent调用）以异步运行，同时Agent循环继续。任务是持久化的，所以配置的`storage` backend is required.

参观[Background tasks documentation](/docs/harness/background-tasks) to learn more.

```typescript title="src/mastra/index.ts"
import { Mastra } from '@mastra/core'
import { LibSQLStore } from '@mastra/libsql'

export const mastra = new Mastra({
  storage: new LibSQLStore({
    id: 'mastra-storage',
    url: 'file:./mastra.db',
  }),
  backgroundTasks: {
    enabled: true,
    globalConcurrency: 10,
    perAgentConcurrency: 5,
    backpressure: 'queue',
    defaultTimeoutMs: 300_000,
  },
})
```

**类型：** `Record<string, EventHandler | EventHandler[]>`

内部发布/订阅系统的事件处理程序。将事件主题映射到事件发布到这些主题时调用的处理程序函数。

```typescript title="src/mastra/index.ts"
    },
  },
})
```

**类型：** `Record<string, MastraModelGateway>`

```typescript title="src/mastra/index.ts"
  gateways: {
    private: new MyPrivateGateway(),
  },
})
```

### id生成器 {/* #idgenerator */}

**类型：** `(context?: IdGeneratorContext) => string`\
**Default:** `crypto.randomUUID()`

用于创建唯一标识符的自定义 ID 生成器功能。 Mastra 传递可选上下文，以便您可以根据正在创建的内容生成 ID。

`IdGeneratorContext`包括：

* `idType`: `'thread' | 'message' | 'run' | 'step' | 'generic'`
* `source?`: `'agent' | 'workflow' | 'memory'`
* `entityId?`：请求Agent/Workflow/内存实体的 ID
* `threadId?`：相关时的线程 ID（例如，创建消息 ID 时）
* `resourceId?`：相关的资源 ID（例如，用户范围的线程）
* `role?`：创建消息ID时的消息角色
* `stepType?`：创建步骤ID时的Workflow程步骤类型

：：：警告

Mastra 在内部使用它来为Workflow运行、Agent对话和其他资源创建 ID。大多数用户不需要配置此选项。

:::

```typescript title="src/mastra/index.ts"
import { v4 as uuid } from '@lukeed/uuid'
import { Mastra } from '@mastra/core'

export const mastra = new Mastra({
  idGenerator: context => {
    if (context?.idType === 'message' && context?.threadId) {
      return `msg-${context.threadId}-${uuid()}`
    }

    if (context?.idType === 'run' && context?.source && context?.entityId) {
      return `${context.source}-run-${context.entityId}-${uuid()}`
    }

    return uuid()
  },
})
```

**类型：** `IMastraLogger | false`\
**Default:** `ConsoleLogger` with `INFO` level in development, `WARN` in production

```typescript title="src/mastra/index.ts"
import { Mastra } from '@mastra/core'

  logger: new PinoLogger({ name: 'MyApp', level: 'debug' }),

```

### mcp服务器 {/* #mcpservers */}

**类型：** `Record<string, MCPServerBase>`

MCP（模型上下文协议）服务器，向 MCP 兼容客户端公开 Mastra Tool、Agent、Workflow程和资源。使用它来编写您自己的 MCP 服务器，任何支持该协议的系统都可以使用该服务器。

参观[MCP Overview](/docs/connections/mcp) to learn more.

```typescript title="src/mastra/index.ts"
import { Mastra } from '@mastra/core'
import { MCPServer } from '@mastra/mcp'

const mcpServer = new MCPServer({
  id: 'my-mcp-server',
  name: 'My MCP Server',
  version: '1.0.0',
})

export const mastra = new Mastra({
  mcpServers: {
    myServer: mcpServer,
  },
})
```

### 记忆 {/* #memory */}

**类型：** `Record<string, MastraMemory>`

可由Agent引用的内存实例注册表，包括使用的存储Agent`{ type: 'id', memoryId: '<key>' }`. Memory gives agents coherence across interactions by retaining relevant information from past conversations. Mastra supports message history for recent messages and working memory for persistent user-specific details. Semantic recall retrieves older messages based on relevance.

参观[Memory documentation](/docs/memory/overview) to learn more.

：：：笔记

大多数用户直接在Agent上配置内存。此顶级配置用于定义可在多个Agent之间共享的可重用内存实例。

:::

```typescript title="src/mastra/index.ts"
import { Mastra } from '@mastra/core'
import { Memory } from '@mastra/memory'
import { LibSQLStore } from '@mastra/libsql'

export const mastra = new Mastra({
  storage: new LibSQLStore({
    id: 'mastra-storage',
    url: ':memory:',
  }),
  memory: {
    chatMemory: new Memory({
      options: {
        lastMessages: 20,
      },
    }),
  },
})
```

### Observability {/* #observability */}

**类型：** `ObservabilityEntrypoint`

Mastra 为人工智能应用程序提供可观察性功能。使用了解 AI 特定模式的Tool监控 LLM 操作、跟踪Agent决策并调试复杂的Workflow程。跟踪捕获模型交互、Agent执行路径、Tool调用和Workflow程步骤。

参观[Observability documentation](/docs/observability/overview) to learn more.

```typescript title="src/mastra/index.ts"
import { Mastra } from '@mastra/core'
import { LibSQLStore } from '@mastra/libsql'
import { Observability, MastraStorageExporter } from '@mastra/observability'

export const mastra = new Mastra({
  storage: new LibSQLStore({
    id: 'mastra-storage',
    url: 'file:./mastra.db',
  }),
  observability: new Observability({
    configs: {
      default: {
        serviceName: 'my-app',
        exporters: [new MastraStorageExporter()],
      },
    },
  }),
})
```

参观[Processors documentation](/docs/agents/processors) to learn more.

：：：笔记

:::

```typescript title="src/mastra/index.ts"
import { Mastra } from '@mastra/core'
import { ModerationProcessor } from '@mastra/core/processors'

export const mastra = new Mastra({
  processors: {
    moderation: new ModerationProcessor({
```

### 分类器 {/* #classifiers */}

**类型：** `Record<string, Classifier>`

分类器向决策模型询问有关应用程序状态的固定选项问题并返回键入的答案。在这里注册可重用的分类器以检索它们`getClassifier()` or `getClassifierById()`. When a registered classifier is evaluated without an active trace, it starts a root `CLASSIFIER_EVALUATION` span through the `Mastra` instance's configured observability provider.

参观[Classifier reference](/reference/classifier/classifier) to learn more.

```typescript title="src/mastra/index.ts"
import { Mastra } from '@mastra/core'
import { Classifier } from '@mastra/core/classifier'
import { typeSafeAi } from '@ai-sdk/typesafe-ai'

const safety = new Classifier({
  id: 'safety',
  model: typeSafeAi.decisionModel('__AI_SDK_TYPESAFE_DECISION_MODEL__'),
  questions: {
    unsafe: {
      type: 'boolean',
      criteria: { true: 'Unsafe', false: 'Safe' },
    },
  },
})

export const mastra = new Mastra({
  classifiers: { safety },
})
```

### Tool {/* #tools */}

**类型：** `Record<string, Tool>`

Tool是可重用的功能，Agent可以使用它们与外部系统进行交互。每个Tool都定义输入、输出和执行逻辑。

参观[Tools documentation](/docs/agents/tools) to learn more.

:::注意
大多数用户直接在Agent上配置Tool。此顶级配置用于定义可在多个Agent之间共享的可重用Tool。
:::

```typescript title="src/mastra/index.ts"
import { Mastra } from '@mastra/core'
import { createTool } from '@mastra/core/tools'
import { z } from 'zod'

const weatherTool = createTool({
  id: 'get-weather',
  description: 'Fetches weather for a city',
  inputSchema: z.object({
    city: z.string(),
  }),
  execute: async () => {
    return { temperature: 20, conditions: 'Sunny' }
  },
})

export const mastra = new Mastra({
  tools: {
    weather: weatherTool,
  },
})
```

### Workspace {/* #workspace */}

**类型：** `Workspace`

Mastra Workspace为Agent提供了一个用于存储文件和执行命令的持久环境。Agent继承全局Workspace`Mastra` class unless they have their own workspace configured.

```typescript title="src/mastra/index.ts"
})
```

## 捆绑器选项 {/* #bundler-options */}

### 捆绑器.externals {/* #bundlerexternals */}

**类型：** `boolean | string[]`\
**Default:** `true`

什么时候`mastra build` is run, Mastra bundles your project into the `.mastra/output` directory. This option controls which packages are excluded from the bundle (marked as "external") and installed separately through a package manager. This is useful when the internal Mastra bundler ([Rollup](https://rollupjs.org/configuration-options/#external)) has trouble bundling packages.

默认情况下，`mastra build` sets this option to `true`.

这些值具有以下含义：

* `true`：项目中列出的所有依赖项`package.json` are marked as external
* `false`：没有依赖项被标记为外部；一切都捆绑在一起
* `string[]`：标记为外部的包名称数组，其余的将捆绑在一起

```typescript title="src/mastra/index.ts"
import { Mastra } from '@mastra/core'

export const mastra = new Mastra({
  bundler: {
    externals: ['some-package', 'another-package'],
  },
})
```

### server.handleShutdownSignals {/* #serverhandleshutdownsignals */}

**类型：** `boolean`\
**Default:** `true`

是否由服务器生成`mastra dev` and `mastra build` installs its own `SIGINT`/`SIGTERM` handlers. By default, receiving a signal begins graceful shutdown. The generated server stops accepting new connections and drains in-flight requests before it runs `mastra.shutdown()` and exits the process (see [`server.drainTimeout`](#serverdraintimeout)).

放`handleShutdownSignals: false` to manage signals yourself, for example with a handler registered in your Mastra config module that calls `mastra.shutdown()`:

```typescript title="src/mastra/index.ts"
import { Mastra } from '@mastra/core'

export const mastra = new Mastra({
  server: {
    handleShutdownSignals: false,
  },
})

let shuttingDown = false
const shutdown = async () => {
  if (shuttingDown) return
  shuttingDown = true
  // custom shutdown coordination
  await mastra.shutdown()
  process.exit(0)
}

process.once('SIGINT', shutdown)
process.once('SIGTERM', shutdown)
```

请注意以下注意事项：

* 如果没有您自己的处理程序，Node.js 将应用默认信号行为：进程立即终止，不会耗尽。
* 您的处理程序无法访问生成的条目文件中的 HTTP 服务器句柄，因此它无法耗尽正在进行的 HTTP 请求。如果您只需要更长的排水窗口，请选择[`server.drainTimeout`](#serverdraintimeout). For full control over the server lifecycle, use a [server adapter](/docs/server/server-adapters).
* 期间`mastra dev`, the built-in handlers release storage resources between hot reloads (for example, DuckDB file locks). Disabling them without an equivalent handler can cause lock conflicts after a reload.

### 服务器.onValidationError {/* #serveronvalidationerror */}

**类型：** `(error: ZodError, context: 'query' | 'body' | 'path') => { status: number; body: unknown } | undefined`

当请求未通过 Zod 模式验证时调用自定义处理程序。使用它来自定义验证错误响应并更改状态代码，或格式化错误以符合您的 API 标准。

* `'body'`: 请求体

```typescript title="src/mastra/index.ts"
      body: {
        ok: false,
        errors: error.issues.map(i => ({

          message: i.message,

        source: context,
      },
    }),
  },
})
```

### 服务器.drainTimeout {/* #serverdraintimeout */}

**类型：** `number`\
**Default:** `5000` (5 seconds)

服务器收到请求后耗尽正在进行的请求的最长时间（以毫秒为单位）`SIGINT` or `SIGTERM`. The value must be finite and between `0` and `2147483647`. During this window the server stops accepting new connections and waits for in-flight requests (including active streams) to finish; if the deadline passes first, remaining HTTP connections are closed. Upgraded connections such as WebSockets end when the process exits. Either way, `mastra.shutdown({ drainTimeout })` then runs before the process exits. It gives in-flight workflow runs (including durable agent runs) the same window to reach a finished or suspended state before workers and pub/sub subscriptions are torn down. Background task cancellation and worker teardown share that window. The generated server then allows up to 5 seconds for workspace and storage cleanup. Setting `0` skips both drains.

当滚动部署需要让长时间运行的Agent轮流或Workflow程步骤完成时，请增加此值。 HTTP 消耗和Workflow消耗相继运行。计划最坏的情况，即该值的两倍加上 5 秒的清理时间，并将总数保持在平台的宽限期以下（例如`terminationGracePeriodSeconds` on Kubernetes):

```typescript title="src/mastra/index.ts"
import { Mastra } from '@mastra/core'

export const mastra = new Mastra({
  server: {
    drainTimeout: 600000, // 10 minutes
  },
})
```

在排水期间再次发送任一关闭信号都会绕过它并立即终止该过程。

**类型：** `number`\
**Default:** `180000` (3 minutes)

请求超时（以毫秒为单位）。超过此持续时间的请求将被终止。

在无服务器平台上，此限制与平台自身的函数超时无关。例如，[Vercel deployer](/reference/deployer/vercel#request-timeouts) sets Vercel's limit with `maxDuration` (seconds) while `server.timeout` still applies, so long requests need both raised.

```typescript title="src/mastra/index.ts"
import { Mastra } from '@mastra/core'

export const mastra = new Mastra({
  server: {
    timeout: 30000, // 30 seconds
  },
})
```
