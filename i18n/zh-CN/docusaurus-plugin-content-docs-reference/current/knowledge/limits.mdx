# 限制

文本限制以 token 计数。计数是估算值，因此下表数值均为近似值。

：：：阿尔法

Knowledge 目前处于 alpha 阶段，其 API 可能在不同版本之间发生变化。

:::

| 项目 | 限制 |
| - | - |
| 笔记文本 | 250 tokens |
| 页面描述 | 100 tokens |
| 页面嵌套层级 | 10 层 |
| 单次移动的页面数（包含被移动页面下的全部页面） | 500 |
| `knowledge_search` 的结果数，以及每次 `knowledge_read` 返回的笔记和子页面数 | 默认 10，最多 50 |
| 页面正文或 `match` 结果（每次 `knowledge_read`） | 默认 1,000 tokens，最少 100 |
| 完整 `knowledge_read` 中保留的笔记，以及提及该页面的笔记 | 每个列表 1,000 tokens |
| `knowledge_list` 条目 | 默认 50，最多 100；默认约 1,000 tokens 以内 |
| `knowledge_list` 深度 | 默认 1 层，最多 3 层 |
| 每页用于语义搜索的 Embedding 分块 | 100 个，每块约 2,000 tokens |
| 每轮的固定上下文 | 默认 500 tokens，无上限 |
| 每轮固定的页面数 | 默认 20 |
| 固定列表的深度 | 默认 1 层，最多 3 层 |
| 每份固定列表中的页面数 | 在分配到的 token 预算内尽可能多，最多 1,000 |

写入内容超出限制时，操作会失败，模型会从工具结果中收到错误。工具 Schema 不显示 token 限制，因为 Schema 无法计算 token 数。

页面正文没有 token 上限。`knowledge_read` 会分段返回较长的正文，Agent 可按行 `range` [逐段编辑](/reference/knowledge/knowledge-tools#knowledge_page)。固定页面的正文会截断以适应固定上下文预算。参见[一次运行会收到什么](/docs/knowledge/pinned-context#what-a-run-receives)。

如果页面太长，无法放入一个 Embedding，就会按段落边界和标题前的位置将其切成相互重叠的分块。每个分块都以页面名称和描述开头。搜索只返回一次该页面，并按其最佳匹配分块排序。超过 100 个分块后，正文剩余部分只能通过关键词搜索找到。重写页面会替换其分块，删除页面会移除分块。

无法放入预算的固定页面会按以下方式处理：

- 配置中固定的页面绝不会被丢弃。如果仅这些页面就超出预算，每页会获得相同份额并被截断。
- 被截断的固定页面以 `[truncated — knowledge_read for the rest]` 结尾。
- 放不下的 Agent 固定页面会在一行中列出名称，最多列十个，其余计数，例如：`Also pinned (open with knowledge_read): Refund Policy, …and 3 more`。

固定列表计为一个固定项，并共享 token 预算。放不下的列表会逐层填充，且每个页面仍显示在其父页面下。若有页面被省略，列表末尾会显示 `…and 4 more; knowledge_list from: "site:mastra"`；如果未获取到全部页面而无法确定数量，则显示 `…and more`。再次固定列表会设置新的深度；如果已存储的列表与配置中的列表重复，只会提供一次。

如果某个 scope 声明的 `pinnedContext` 页面数超过 `maxPins`，或页面太多导致每页分到的 token 少于 50，Knowledge 会在启动时记录警告。

通过 `tools: { read: { maxTokens } }` 调整读取上限，参见 [`tools`](/reference/knowledge/knowledge-class#constructor-options)。通过 `pinnedContext: { maxPins, maxTokens }` 调整 `Knowledge` 的固定项限制。
