# 知识Tool

知识为Agent提供了六种Tool。Agent获得哪些取决于知识`tools`和`pinnedContext`选项，或传递给的组[`createTools()`](/reference/knowledge/knowledge-class#createtools)。看[Agent和Tool](/docs/knowledge/agents-and-tools)了解Agent如何使用它们。

|集团|Tool|启用者 |
| - | - | - |
|阅读 |`knowledge_list`, `knowledge_search`, `knowledge_read` | `tools: true` or `tools: { read: true }`|
|写 |`knowledge_page`, `knowledge_note` | `tools: true`或者`tools: { write: true }`|
|针脚 |`knowledge_pin` | `pinnedContext` |

每个Tool都根据运行的范围和知识声明赋予它们的角色进行操作。不包含范围的运行失败并显示：

```text
Knowledge tools need run scopes: give the agent or the call `scopes`, or run it with Memory.
```

Tool错误作为Tool结果而不是异常返回到模型。运行无法读取的页面或注释看起来不存在：错误表明未找到该页面或注释，但从未表示访问被拒绝。

：：：阿尔法

知识处于阿尔法阶段。其 API 可能会在不同版本之间发生变化。

:::

## 页面参考 {/* #page-references */}

参数命名`page` (and `into`, `parent`, `from`) take any of these:

* 页面 ID。
* 范围地址，例如`org:acme`, for the scope's own page.
* 页面路径，`<scope>#<key>[/<key>…]`, such as `policy:acme#refund-policy` or `org:acme#policies/refund`.
* 准确的页面名称。

在页面路径中，`/` before the `#` names a child scope, and a `/` after it names a child page. Leading, trailing and doubled slashes in the page part are dropped, so `org:acme#policies/` and `org:acme#policies` are the same page. Paths resolve when used. A moved page answers only to its new path.

与多个可读页面相匹配的名称将被候选人的参考文献拒绝：

```text
Knowledge page name "Chargeback Playbook" is ambiguous; use one of these refs: team:acme:billing#chargeback-playbook, team:acme:support#chargeback-playbook.
```

Tool结果按以下方式命名每个页面`ref`, which any of these arguments accepts:

* 范围页面的范围地址。
* 完整路径，每个级别都有一个键的页面，例如`docs:acme#guides/observability/logging`.
* 页面 ID，否则。

读取不存在的页面时会列出最多三个相近的匹配项`ref`.

## `knowledge_search` {/* #knowledge_search */}

搜索运行可以读取的页面和注释。

查询被分割成单词，并且引号被忽略。每个单词作为任何单词的一部分进行匹配，不区分大小写，因此`refund` matches `refunds`. A page matches when its name, description or body contains at least one of the words. A note matches when its own text does.

关键字结果按以下顺序排名：

1. 名称包含整个查询的页面。
2. 其他页面，按照它们包含的查询单词数量，然后按照单词的位置（名称高于描述，描述高于正文），然后是最近更新。
3. 注释，按它们包含多少个查询词，然后是最新的。

访问检查和`scope` filter results before ranking. `limit` applies after it. With `vector` and `embedder` on the Knowledge instance, keyword and semantic results are merged by rank, so this order no longer holds.

<PropertiesTable
  content={[
{
  name: 'query',
  type: 'string',
  description:
    'Words to look for. A result contains at least one of them, case-insensitively. An empty query returns nothing.',
},
{ name: 'scope', type: 'string[]', description: 'Only search pages in these scope addresses.', isOptional: true },
{ name: 'limit', type: 'number', description: 'Maximum results, 1 to 50.', isOptional: true, defaultValue: '10' },
]}
/>

退货`{ results }`, each `{ type: 'page', page }` or `{ type: 'note', page, note }`. These searches also return `more`:

* 没有找到任何内容的搜索表明不同的关键词或`knowledge_list`:

  ```text
  results: no page or note contains any word of "enterprise pricing tiers". Search again with different key words, or browse with knowledge_list.
  ```

* 一次充满的搜索`limit` says how many results were shown, and to narrow the query or raise `limit` (up to 50) when none of them fits.

`scope`仅采用范围地址。页面引用，例如`docs:acme#billing` is refused with a pointer to `knowledge_list`.

## `knowledge_list` {/* #knowledge_list */}

在起点下列出页面树，以便Agent可以在搜索或读取之前查看范围或部分的组织方式。没有`from`, it lists the scopes the run can read. Scopes the run can't read are left out.

<PropertiesTable
  content={[
{ name: 'from', type: 'string', description: 'Where to start: a page reference.', isOptional: true },
{
  name: 'depth',
  type: 'number',
  description: 'How many levels below `from` to list, 1 to 3.',
  isOptional: true,
  defaultValue: '1',
},
{ name: 'limit', type: 'number', description: 'Maximum entries, 1 to 100.', isOptional: true, defaultValue: '50' },
{
  name: 'descriptions',
  type: 'boolean',
  description: "Add each page's description to its entry.",
  isOptional: true,
  defaultValue: 'false',
},
{
  name: 'cursor',
  type: 'string',
  description:
    "The previous result's `nextCursor`, or the cursor `more` gives. Pass the same `from`. A cursor keeps the `depth` and `limit` of the result it came from.",
  isOptional: true,
},
]}
/>

退货`{ from?, entries, nextCursor?, more? }`. `from` is `{ ref, name }`. Each entry is `{ ref, name, depth, children, scope? }`, plus `description` when `descriptions` is `true`: `depth` is 1 for the starting point's children, `children` counts the readable child pages (and child scopes, for a scope), and `scope` is `true` for a scope.

结果停止于`limit` entries or at the read cap (about 1,000 tokens of entries by default), whichever comes first, and always holds at least one entry. When it stops early, `more` says how many entries were left out and gives the cursor that continues where it stopped.

## `knowledge_read` {/* #knowledge_read */}

读取页面：其正文、注释、子页面以及提及该页面的其他页面上的注释。作用域地址读取该作用域的页面，其中列出了其页面和子作用域。没有`page`, it lists the scopes the run holds.

完整读取返回`{ page, notes, children, childScopes?, mentionedIn, nextCursor?, mentionedInCursor?, more? }`, with the body on `page`. Anything cut short is listed in `more`, with how to get the rest:

* **身体。**&#x9002;合读取上限的主体（1,000 个令牌，除非[`tools.read.maxTokens`](/reference/knowledge/knowledge-class#constructor-options) sets it) comes back as `page.body`. A longer one comes back as `page.lines`, numbered (`12│text`), with `page.range`, the lines it covers, and `page.lineCount`. `more` says where to read on, such as `body: showing lines 1–40 of 412. Read on with from: {"line":41}.`
* **第一次读到很长的一页。**&#x7B80;单阅读（无`section` or `from`) of a body with headings shows the whole page at a glance instead: `page.lines` holds every heading with its line number and the first lines under it, shared out within the read cap, with `⋯ lines a–b` where lines are left out and `…` where a line is cut short. It has `page.lineCount` but no `page.range`, so it can't be written back: read a `section` or `from` a line first, and edit with the `range` that read returns. A body with no headings, or with more headings than fit in the cap, comes back as its first lines with `page.range` instead, plus `page.outline` of the headings it didn't reach (up to about 500 tokens of them).
* **注释和提及。**&#x6574;个读取最多可达`limit` notes and up to `limit` mentioning notes. Each list comes along while those fetched notes stay under 1,000 tokens. A longer list is replaced by `notesLeftOut` or `mentionedInLeftOut`, the number of notes fetched, and `more` says to read it with `notes: true` or `mentionedIn: true`. When there are more notes than `limit`, both that number and the token estimate in `more` cover only the fetched notes, so the list is larger.
* **子页面和范围。**&#x8FC7;去的`limit`, `more` says to list them with `knowledge_list`.

一个`range` is `{ start: { line, col? }, end: { line, col? } }`. Lines start at 1. A read gives `col` only when a line is too long for one read. It's 0-based, and an end `col` is exclusive. Pass a range to `knowledge_page` to replace those lines.

`match`回报`matches`, each `{ range, lines }`. When the matches run past the read cap (1,000 tokens by default), `more` gives the line to continue from, such as `match: stopped at about 1,000 tokens; more matches from line 120. Read again with the same match and from: {"line":120}.`

`outline`, `section`, `match` and `from` return only that part of the body, with no notes, child pages or mentions. Pass at most one of `outline`, `section` and `match`. `notes`, `mentionedIn` and both cursors return only those notes, with no body, and can't be combined with the body options:

```text
knowledge_read: read notes or mentionedIn on their own, without outline, section, match or from.
```

## `knowledge_page` {/* #knowledge_page */}

创建、编辑、移动、合并和删除页面。`scope` only names the destination: the home scope on create, the target scope on move. Edits and merges take no `scope`, and a delete ignores it. All three act on the page's own scope.

  isOptional: true,

一个`body` write without `range` is refused when the stored body is longer than one read returns (the read cap, 1,000 tokens by default). A `range` is refused without `expectedVersion`, when it starts after it ends or runs past the end of the body, and when it covers more than one read from its first line shows:

```text
Lines 1–150 run past what one knowledge_read from line 1 shows, so this can't be a range a read gave you. Edit the body part by part: write each part back with the range its own read returned.
```

一个`body` that still has the line numbers from a read is refused: `This body still has the line numbers a knowledge_read put in front of each line ("12│"). Write the text without them.`

|运营|需要的角色 |
| - | - |
|创造 （`write` without `page`) | `contributor` on `scope` |
| Edit (`write` with `page`) | `editor` on the page's scope |
| Move within a scope | `editor` on the page's scope |
| Move to another scope | `owner` on the page's scope and on `scope` |
| Merge | `owner` on the merged page's scope; on the scope of `into`, `editor` if it's the same scope and `owner` if it's another, since the merged page's children move there |
| Delete | `owner` on the page's scope |

模板页面，在范围中声明`pages`, can be edited, annotated with notes and merged into, but not moved, merged away or deleted, whatever the run's role.

范围页面的名称和描述来自配置，因此`write` on a scope page changes only its body. The scope page can't be moved, merged or deleted.

`delete`从读取、搜索和固定中删除页面。当页面具有子页面、范围页面和模板页面时，它会被拒绝。

错误：

```text
Creating a page needs scope and name.
Editing a page needs at least one of name, description or body.
Editing a page takes no scope, parent or key; use op "move" to relocate it.
Moving a page needs the destination scope.
Merging needs into: the page that remains.
"Escalation" has child pages; move or delete them first.
"org:acme" is a scope page; scope pages can't be moved, merged or deleted.
"org:acme" is a scope page; its name and description come from config, so only its body can be written.
Knowledge page "org:acme#policies/escalation" not found.
Knowledge page key "a/b" must not contain "/", "#" or "%"
Knowledge page key "escalation" already exists under page aa8f6099-6111-4952-b9cb-04cb97eb2bb5. Keys are unique among siblings; pick another key or move one of the pages.
"org:acme#policies/refund" is declared in config; change the scope's pages to move it.
"org:acme#policies/refund" is declared in config; change the scope's pages to remove it.
Editing a page needs editor on "team:acme:support"; this run has viewer there.
Moving a page across scopes needs owner on "org:acme"; this run has editor there.
Merging a page away needs owner on "team:acme:support"; this run has editor there.
Merging a page across scopes needs owner on "team-public:acme:support"; this run has editor there.
Deleting a page needs owner on "org:acme"; this run has editor there.
Knowledge page description exceeds the 100 token limit; put long-form text in the page body
Knowledge record version conflict: 37c1e879-b328-47a9-9d3c-5788ad35ca2d
```

## `knowledge_note` {/* #knowledge_note */}

添加、重新标记和删除注释。注释是一页上的一个持久事实。链接其他页面`[[Page Name]]`. Its stamp scopes say who can see it: a run reads a note when it can read the page and at least one stamp scope.

|运营|需要的角色 |
| - | - |
|`add` | `contributor` on the page's scope and on each stamp scope |

| `remove` | `editor` on the page's scope |

```text
Adding a note needs page and text.
Adding a note needs scope: the stamp scopes.
Adding a note needs contributor on "team:acme:support"; this run has viewer there.
Removing a note needs editor on "team:acme:support"; this run has viewer there.
Knowledge note text exceeds the 250 token limit; split it into separate notes or put long-form text in the page body
```

## `knowledge_pin` {/* #knowledge_pin */}

将页面或其下的页面列表固定到持有受众范围之一的每次运行、每次转动的上下文中，或将其取消固定。需要内存来传送引脚。看[Pinned context](/docs/knowledge/pinned-context).

<PropertiesTable
  content={[
{ name: 'op', type: "'pin' | 'unpin'", description: 'What to do.' },
{ name: 'page', type: 'string', description: 'The page to pin or unpin.' },
{ name: 'audience', type: 'string[]', description: 'Scope addresses whose runs receive the pin.' },
{
  name: 'kind',
  type: "'page' | 'list'",
  description:
    '`page` pins the page. `list` pins a listing of the pages under it. A page can have one pin of each kind, pinned and unpinned separately.',
  isOptional: true,
  defaultValue: "'page'",
},
{
  name: 'depth',
  type: 'number',
  description:
    'Levels a `list` pin shows below the page, 1 to 3. Pinning a listing again sets its new depth. Only with `op: "pin"` and `kind: "list"`.',
  isOptional: true,
  defaultValue: '1',
},
]}
/>

固定和取消固定的需要`editor` on the page's scope and, for each audience scope, holding it or `editor` on it. A pinned page reaches only runs that can read it, and a pinned listing shows only the pages the run can read. Pinning a listing needs a storage adapter version that stores pin kinds. With an older adapter, page pins still work and a listing pin is refused before anything is stored.

```text
Pinning a page needs editor on "policy:acme"; this run has viewer there.
Pinning for "role:acme:sales" needs holding it or editor on it; this run has neither.
Pin audience "project:x" does not match a declared scope type.
```

## 每个操作需要什么 {/* #what-each-operation-needs */}

|运营|角色 |上 |
| - | - | - |
|搜索、阅读、列出 |`viewer` | The page's scope |
| Create a page | `contributor` | `scope` |
| Edit a page | `editor` | The page's scope |
| Move within a scope | `editor` | The page's scope |
| Move to another scope | `owner` | Both scopes |
| Merge | `owner` | The page that goes away |
| | `editor` | The page that stays, in the same scope |
| | `owner` | The page that stays, in another scope |
| Delete a page | `owner` | The page's scope |
| Add a note | `contributor` | The page's scope and each stamp |
| Restamp, remove a note | `editor` | The page's scope (and `contributor` on each new stamp) |
| Pin, unpin a page or listing | `editor` | The page's scope, plus authority over each audience |

一个可以触及但需要更强角色的呼叫会为其所需的角色命名：

```text
Adding a note needs contributor on "team:acme:support"; this run has viewer there.
```
