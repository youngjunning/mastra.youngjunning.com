# 范围声明

这`scopes`选项开启[`Knowledge`](/reference/knowledge/knowledge-class)声明运行可以容纳的每个作用域类型以及谁在该类型的作用域上获得哪个角色。每个键都是一个模式或一个具体地址，每个值都是一个声明。当你构造它时，知识会检查整个对象。启动时出现拼写错误会失败，而不是默默地授予任何内容。看[范围和访问权限](/docs/knowledge/scopes-and-access)进行演练。

：：：阿尔法

知识处于阿尔法阶段。其 API 可能会在不同版本之间发生变化。

:::

## 使用示例 {/* #usage-example */}

```typescript title="src/mastra/knowledge.ts"
import { Knowledge, knowledgeMemoryScopes } from '@mastra/core/knowledge'

export const knowledge = new Knowledge({
  id: 'company',
  tools: true,
  scopes: {
    ...knowledgeMemoryScopes(),
    'team:$orgId:$teamId': {
      description: 'A team',
      displayLabel: '$teamId team',
      belongsTo: 'org:$orgId',
      access: [
        { principal: 'self', role: 'editor' },
        { principal: 'org:$orgId', role: 'viewer' },
      ],
      pages: [{ key: 'handbook', name: 'Team Handbook' }],
    },
  },
})
```

`scopes`是必须的。经过`{}` if the instance needs no scope types. [`knowledgeMemoryScopes()`](/reference/knowledge/knowledge-memory-scopes) returns the declarations for Memory's `resource:` and `thread:` scopes and a tenant scope.

## 模式和参数 {/* #patterns-and-params */}

一个键，例如`team:$orgId:$teamId` is a pattern. The text before the first `:` is the type, and each `$name` segment is a param. The address `team:acme:support` matches it with `$orgId = acme` and `$teamId = support`.

每个参数恰好匹配一个段，因此一个地址具有与其模式一样多的段。`resource:user:123` doesn't match `resource:$resourceId`. An ID that contains `:`, `/`, `#` or `%` is encoded into one segment, so user `user:123` is `resource:user%3A123`。构建地址[`encodeKnowledgeScopeId()`或者`knowledgeScopeAddress()`](/reference/knowledge/knowledge-memory-scopes#encodeknowledgescopeid)。内存 ID 已为您编码。

:::警告\[早期 alpha 版本存储的范围]

早期版本让最后一个参数采用地址的其余部分，包括原始冒号。以这种方式存储的范围，例如`resource:slack:U123` for Memory resource `slack:U123`, now has a new address, `resource:slack%3AU123`. Runs reach the new, empty scope. Pages, pins and notes under the old address stay in storage, but runs with that Memory resource no longer reach them, and Knowledge doesn't move them.

其地址现在与不同模式匹配的存储范围，例如`org:acme:viewer` stored as an `org:$orgId` scope before you declared `org:$orgId:viewer`, gets no rules from the new pattern. Using it as a scope of the new pattern throws.

:::

仅当没有地址可以匹配其中两个模式时，一个类型才可以有多个模式。具有不同段数的图案永远不会重叠。具有相同编号的模式在同一位置必须具有不同的文字文本：

```typescript oxfmt:false
scopes: {
  'role:$orgId:admin': { description: 'Org administrators' },
  'role:$orgId:support': { description: 'Support agents' },
}
```

重叠模式在启动时失败。它们之间没有优先级：

```text
Knowledge scope patterns "role:$orgId:$role" and "role:$orgId:admin" overlap; patterns of a type must be pairwise disjoint.
```

`kb:$orgId`和`kb:$orgId:public` can be declared together, because `kb:acme` and `kb:acme:public` have different numbers of segments. Each is its own scope with its own rules. Holding `kb:acme` gives no role on `kb:acme:public` unless a rule on `kb:$orgId:public` names `kb:$orgId`.

## 规则 {/* #rules */}

`access`列出规则。每个规则都会指定一个主体、运行必须保留的运行范围（要应用该规则）以及运行获得的角色。主体是声明的范围模式或`self`, the scope being accessed:

```typescript oxfmt:false
scopes: {
  ...knowledgeMemoryScopes(),
  'team:$orgId:$teamId': {
    description: 'A team',
    access: [
      { principal: 'self', role: 'editor' },
      { principal: 'org:$orgId', role: 'viewer' },
    ],
  },
}
```

* `self`是声明规则的范围。跑步控股`team:acme:support` is an editor there.
* `org:$orgId`绑定`$orgId` from the team's address. A run holding `org:acme` can read `team:acme:support`, and a run holding `org:globex` can't see it at all.

角色是`viewer`, `contributor`, `editor` and `owner`, each including the ones before it. What each role can do:

|角色 |可以|
| - | - |
|`viewer` | Search and read pages and notes |
| `contributor` | Create pages and add notes |
| `editor` | Edit a page's name, description and body, move pages within a scope, restamp and remove notes, and pin pages |
| `owner` | Move pages to another scope, merge pages away and delete pages |

看[what each operation needs](/reference/knowledge/knowledge-tools#what-each-operation-needs) for the role each tool operation checks.

主体的参数必须通过以下两种方式之一进行绑定：

* **来自地址前缀。**&#x4E3B;体的参数是目标模式的第一个参数，就像`org:$orgId` on `team:$orgId:$teamId`.
* **通过`belongsTo`.**&#x76EE;标的`belongsTo` pattern carries the params, as shown in the next section.

任何其他绑定在启动时都会失败：

```text
Knowledge rule principal "y:$b" on "x:$a:$b" would reach scopes that aren't an address prefix; reorder "x:$a:$b"'s params so the bound ones come first, or bind them through belongsTo.
```

每个主体也必须是声明的类型：

```text
Knowledge rule principal "org:$orgId" on "policy:$orgId" is not a declared scope type; declare it or fix the typo.
```

角色不会延续。跑步控股`org:acme` reads `team:acme:support` through its `org:$orgId` viewer rule, but it doesn't get the roles `team:acme:support` gives to other scopes. There's no inheritance either. A role on `org:acme` gives nothing on scopes placed under it unless a rule says so.

## 将示波器放置在`belongsTo` {/* #place-scopes-with-belongsto */}

`belongsTo`将一个范围放在树中另一个范围的下面。它本身不授予任何内容，但规则可以通过它绑定参数：

```typescript oxfmt:false
'project:$projectId': {
  belongsTo: 'org:$orgId',
  access: [
    { principal: 'self', role: 'editor' },
    { principal: 'org:$orgId', role: 'viewer' },
  ],
},
```

地址`project:p1` has no `$orgId`, so the `org:$orgId` rule binds it from the project's place in the tree. The first run that writes Knowledge while holding `project:p1` and exactly one `org:` scope places it under that scope, and the placement sticks. After that, a run holding `org:acme` can read `project:p1`, and a run holding `org:globex` can't.

只读取创建和放置任何内容的运行。直到进行写作`project:p1`, the `org:$orgId` rule gives nothing on it. A run that holds several `org:` scopes logs a warning and leaves the placement unchanged. A run that holds a different `org:` scope from the stored placement also logs a warning, and the placement stays.

## 子范围和键控页面 {/* #child-scopes-and-keyed-pages */}

`children`声明使用该类型的每个范围创建的范围，位于`<address>/<name>`. `pages` declares template pages, keyed pages every scope of the type has. A template can list its own `pages` to nest them:

```typescript oxfmt:false
'team:$orgId:$teamId': {
  access: [
    { principal: 'self', role: 'editor' },
    { principal: 'org:$orgId', role: 'viewer' },
  ],
  children: [
    {
      name: 'private',
      description: 'Only the team can read this',
      access: [{ principal: 'team:$orgId:$teamId', role: 'editor' }],
    },
  ],
  pages: [
    {
      key: 'handbook',
      name: 'Team Handbook',
      pages: [{ key: 'on-call', name: 'On-call rota' }],
    },
  ],
},
```

现在每支球队都有`team:acme:support/private`, a page the tools can name as `team:acme:support#handbook`, and a page under it at `team:acme:support#handbook/on-call`.

键在兄弟姐妹中是唯一的并且不能包含`/`, `#` or `%`. A duplicate or invalid key fails at startup.

模板页面属于配置：

* 写入的运行会创建其范围缺失的任何模板页面，包括您稍后添加到配置中的页面。仅读取的运行不会创建任何内容。已位于该路径的页面将被采用，并成为模板页面。
* Tool可以在通常的角色下编辑模板页面的名称、描述和正文，向其添加注释，以及将其他页面合并到其中。
* Tool无法移动模板页面或将其合并。他们得到`"team:acme:support#handbook" is declared in config; change the scope's pages to move it.`
* 您从中取出的页面`pages` becomes an ordinary page and keeps its key. Putting the template back adopts the page at that path, with its body and notes. If the page has moved, the next writing run creates a new one there.
* 如果主机代码通过存储删除了模板页面，则下一次写入运行会在该路径上创建一个新的空页面。

孩子没有从父母那里得到任何规则。列出它需要的每条规则，以及从父级地址绑定的参数。在孩子的规则中`self` is the child, which no run holds, so name the parent's pattern as the principal, as above. A run holding `org:acme` reads the team's pages but not the private child's.

## UI 的标签范围 {/* #label-scopes-for-uis */}

`displayLabel`为范围类型提供屏幕（例如 Studio）的简称。模型永远不会看到它。`description` is what the model reads. `$params` fill in from the address, and a concrete address's own label wins:

```typescript oxfmt:false
scopes: {
  'org:$orgId': {
    displayLabel: '$orgId organization',
    access: [{ principal: 'self', role: 'editor' }],
    children: [{ name: 'private', displayLabel: 'Private', access: [{ principal: 'org:$orgId', role: 'owner' }] }],
  },
  'org:acme': { displayLabel: 'Acme HQ' },
}
```

`knowledge.scopeLabel('org:globex')`回报`globex organization`, and `knowledge.scopeLabel('org:acme')` returns `Acme HQ`. See [`scopeLabel()`](/reference/knowledge/knowledge-class#scopelabel).

## 共享一个范围 {/* #share-one-scope */}

没有参数的键是一个具体的地址。它将规则添加到它匹配的一个模式中，用于单个范围：

```typescript oxfmt:false
'feature:$orgId:$featureId': { description: 'Product features' },
'feature:acme:a': {
  access: [
    { principal: 'team:acme:eng', role: 'editor' },
    { principal: 'team:acme:support', role: 'contributor' },
  ],
},
```

工程编辑功能 A，并且支持人员可以在其中添加注释和页面，而无需编辑工程页面。其他功能仅获取模式的规则。

首先声明模式。没有匹配模式的具体地址在启动时失败：

```text
Knowledge scope "feature:acme:a" doesn't match a declared pattern; declare its pattern first.
```

具体地址可以添加`description`, `displayLabel`, `access`, `pinnedContext` and `pinnedContextPriority`. Declare `belongsTo`, `children` and `pages` on the pattern.

## 运行范围 {/* #run-scopes */}

运行的范围来自主机代码：`MASTRA_SCOPES_KEY` request context key, the `scopes` option on a call, and the agent's `scopes` option. A list on the agent adds to the others. A function on the agent receives them and returns the final set. With Memory, a run also holds `resource:<resourceId>` and `thread:<threadId>`. See [set a run's scopes](/docs/knowledge/scopes-and-access#set-a-runs-scopes).

附加知识后，运行所拥有的每个范围都必须与声明的类型匹配。只命名运行的类型仍然需要声明，即使是空声明，例如`'role:$orgId:support': {}`.

一次运行只有一个内存资源和一个线程。`knowledgeMemoryScopes()` places a user's `resource:` scope under the org held by its first writing run, and that placement doesn't change. Give a user who works in several orgs a resource ID per org, such as `acme-dana` and `globex-dana`.

`MASTRA_SCOPES_KEY`被保留：服务器在请求正文中忽略它。它需要一个`@mastra/server` release that reserves it.

### 错误 {/* #errors */}

|错误 |原因 |
| - | - |
|`Knowledge run scope "project:x" does not match a declared scope type. …` | Knowledge has no declaration for a scope the run holds. |
| ``Knowledge tools need run scopes: give the agent or the call `scopes`, or run it with Memory.`` | The run has no scopes and no Memory. |
| `Agent request context "mastra__scopes" must be an array of "<type>:<value>" strings.` | A scope entry isn't a string. |
| `Invalid agent scope "Org:acme" in request context "mastra__scopes". …` | A scope isn't `<type>:<value>` with a lowercase type. |
| `The agent's scopes function dropped "resource:dana". …` | The agent's `scopes` function left out a `resource:` or `thread:` scope. |
| `Agent scopes contain more than one resource: …` | The run holds two `resource:` (or `thread:`) scopes. |
| `Agent scope "resource:cust-7" conflicts with option "memory.resource" "spec-1". …` | A `resource:` scope disagrees with `memory.resource`. |
| `AGENT_SCOPES_SERVER_OUTDATED` | Scopes came from the request context or the call behind an older `@mastra/server`. |

## 重命名或停用范围类型 {/* #rename-or-retire-a-scope-type */}

每个存储范围都会记住它创建时的声明键、前缀和`belongsTo` rules match on that key. Renaming a key in `scopes`, say `'team:$org:$team'` to `'team:$orgId:$teamId'`, would cut every existing team scope off from those rules. To prevent that, Knowledge checks the stored keys against `scopes` on first use and refuses to run while any is missing:

```text
Knowledge storage has scopes created from declarations this config doesn't declare: "team:$org:$team" (12 scopes). Restore each key in scopes, rename it with knowledge.renameScopeDeclaration(from, to), or keep the key with no access rules to retire it.
```

重命名密钥后`scopes`, move the stored scopes to the new key. Child scope keys such as `team:$org:$team/internal` move with it:

```typescript
await knowledge.renameScopeDeclaration('team:$org:$team', 'team:$orgId:$teamId')
```

重命名一步完成，并且在被拒绝时不会发生任何更改：当旧密钥仍在时`scopes`, the new key isn't, or a stored address doesn't match the new pattern.

在滚动部署期间，具有新配置的实例拒绝运行，直到发生重命名。重命名后，仍使用旧配置的实例会丢失前缀并且`belongsTo` rules on those scopes. Deploy the new config, then run the rename straight away.

要在不移动其范围的情况下退役类型，请将其密钥保留在`scopes` with no `access` rules. Its scopes stay stored, and no rule reaches them.
