# Knowledge 类

`Knowledge` 类保存页面和笔记，声明有哪些作用域、各主体在其中拥有什么角色，并为关联的 Agent 提供 Knowledge Tool。功能介绍与快速入门请参阅 [Knowledge](/docs/knowledge/overview)。

:::alpha

Knowledge 目前处于 alpha 阶段，API 可能在版本之间发生变化。

:::

## 使用示例 {/* #usage-example */}

```typescript title="src/mastra/knowledge.ts"
import { Knowledge, knowledgeMemoryScopes } from '@mastra/core/knowledge'
import { LibSQLStore } from '@mastra/libsql'

export const knowledge = new Knowledge({
  id: 'company',
  storage: new LibSQLStore({ id: 'knowledge', url: 'file:./knowledge.db' }),
  tools: true,
  scopes: {
    ...knowledgeMemoryScopes(),
    'team:$orgId:$teamId': {
      access: [
        { principal: 'self', role: 'editor' },
        { principal: 'org:$orgId', role: 'viewer' },
      ],
    },
  },
})
```

构造函数会抛出 `KnowledgeDeclarationError`：例如缺少 `scopes`，或声明无效（同一类型的两个模式重叠，或规则中的主体无法绑定）。缺少 `scopes` 时，错误消息为：

```text
Knowledge needs `scopes`: declare the scopes its runs hold, e.g. `scopes: { ...knowledgeMemoryScopes() }`, or `{}` for none.
```

## 方法 {/* #methods */}

### 工具 {/* #tools */}

#### `createTools()` {/* #createtools */}

```typescript oxfmt:false
createTools(options?: { read?: boolean; write?: boolean; pinnedContext?: boolean }): Record<string, Tool>
```

返回可显式连接的 Knowledge Tool，例如供未通过 `knowledge` 关联的 Agent 使用。每个选项都会覆盖实例上的对应 Tool 组；省略的选项沿用实例设置。若实例启用了 `pinnedContext`，`createTools({ write: false })` 仍会返回 `knowledge_pin`。参见 [Knowledge Tool](/reference/knowledge/knowledge-tools)。

```typescript
const tools = knowledge.createTools({ write: false })
// knowledge_list, knowledge_search, knowledge_read
```

#### `getInstructions()` {/* #getinstructions */}

```typescript oxfmt:false
getInstructions(options?: { read?: boolean; write?: boolean; pinnedContext?: boolean }): string
```

返回与 `createTools(options)` 配套的使用说明。其构造方式与关联 Agent 时相同：可以使用已启用 Tool 组的内置说明片段，也可以使用 `instructions` 选项生成的说明。

### 访问控制 {/* #access */}

#### `explainAccess()` {/* #explainaccess */}

```typescript oxfmt:false
explainAccess(
  runScopes: readonly string[],
  target: { scope: string } | { page: string },
): Promise<KnowledgeAccessExplanation>
```

说明持有 `runScopes` 的运行为什么能或不能访问某个作用域或页面。`runScopes` 是规范地址，包括 `resource:` 和 `thread:`（规范地址 `resource:slack%3AU123` 对应 Memory 资源 `slack:U123`）。`target.page` 接受页面 ID 或 `org:acme#policies/refund` 这样的页面路径。

```typescript
await knowledge.explainAccess(['org:acme'], { page: 'team:acme:support#refunds' })
// {
//   role: 'viewer',
//   reasons: [{ principal: 'org:acme', role: 'viewer', rule: 'team:$orgId:$teamId', via: 'rule' }],
//   page: { id: '…', scope: 'team:acme:support' },
// }

await knowledge.explainAccess(['org:globex'], { page: 'team:acme:support#refunds' })
// { role: null, reasons: [], page: { id: '…', scope: 'team:acme:support' }, reason: 'hidden' }
```

未声明的运行作用域会抛出错误，与运行开始时的行为相同：

```text
Knowledge run scope "project:x" does not match a declared scope type. Declare it in Knowledge `scopes` (for Memory's resource:/thread: scopes, spread `...knowledgeMemoryScopes()`).
```

未声明的 `target.scope` 会抛出 `Knowledge scope "project:x" does not match a declared scope type.`

:::warning

`explainAccess()` 只能由宿主调用。它能区分页面不存在和页面被隐藏，而运行绝不应得知这种区别。请勿通过 Agent Tool，或未实施管理员级身份验证的服务端路由，暴露此方法。

:::

#### `readScopeFor()` {/* #readscopefor */}

```typescript oxfmt:false
readScopeFor(principals: readonly string[]): Promise<KnowledgeReadScope>
```

返回 `principals` 持有者可以读取的内容：这些主体本身，以及其规则授予角色的所有作用域。角色不会继续传递到更深的作用域。宿主代码代表用户读取 Knowledge 时，请将结果作为 `read` 传给存储的读取方法。未声明的主体会抛出 `Knowledge run scope "project:x" does not match a declared scope type.`；空列表则无法读取任何内容。

#### `scopeGrants()` {/* #scopegrants */}

```typescript oxfmt:false
scopeGrants(scope: { address: string; parentAddress?: string | null }): KnowledgeScopeGrant[]
```

返回声明赋予其他作用域在当前作用域上的角色，形式为 `{ principal, role }`。每个主体只保留最高角色，且不包含 `self` 规则。此方法不读取存储。`parentAddress` 提供通过 `belongsTo` 绑定的规则所需的树形父级。它适用于展示作用域间访问关系的浏览界面；若要查看某次运行的权限，请使用 `explainAccess()`。

#### `scopeDeclaration()` {/* #scopedeclaration */}

```typescript oxfmt:false
scopeDeclaration(key: string): KnowledgeScopeDeclarationInfo | undefined
```

按声明键返回创建作用域时使用的声明，供界面显示：`{ key, description?, displayLabel?, belongsTo?, children }`。也支持 `org:$orgId/private` 这样的子键。不包含访问规则；查看规则请使用 `explainAccess()`。未知的键会返回 `undefined`。

#### `scopeLabel()` {/* #scopelabel */}

```typescript oxfmt:false
scopeLabel(address: string): string | undefined
```

返回作用域地址的 `displayLabel`，并填入其中的 `$params`：`'$orgId organization'` 用于 `org:$orgId` 时，会生成 `acme organization`，对应 `org:acme`。具体地址自身的 `displayLabel` 优先。若地址不匹配任何声明或没有标签，则返回 `undefined`。

### 宿主写入操作 {/* #host-writes */}

`upsertPage()`、`removePage()`、`addNote()`、`updateNote()` 和 `removeNote()` 只能由宿主调用：它们不会检查运行作用域或访问规则。请勿通过 Agent Tool，或未实施管理员级身份验证的服务端路由，暴露这些方法。

#### `upsertPage()` {/* #upsertpage */}

```typescript oxfmt:false
upsertPage(input: {
  scope: string
  path: string
  name: string
  description?: string
  body?: string
  author?: string
}): Promise<{ page: KnowledgePage; status: 'created' | 'updated' | 'unchanged' }>
```

创建或更新 `path` 对应的页面（键以 `/` 连接，例如 `guides/install`），并将其放在 `scope` 中；缺少的作用域和路径中间页面也会一并创建。再次写入同一路径会更新该页面。省略 `description` 或 `body` 时，会保留已存储的值。返回 `unchanged` 表示没有写入：页面版本不变，不触发变更事件，也不会重新生成嵌入。`author` 会记录为写入者，默认为 `host`。不含键的路径会抛出 `Knowledge page path "<path>" needs at least one key.`。参见[加载内容](/docs/knowledge/load-your-content)。

#### `removePage()` {/* #removepage */}

```typescript oxfmt:false
removePage(input: { scope: string; path: string; author?: string }): Promise<KnowledgePage | null>
```

删除 `path` 对应的页面，返回该页面；如果页面不存在，则返回 `null`。若页面有子页面，会抛出 `"<scope>#<path>" has child pages; remove them first.`；若它是模板页面，会抛出 `"<scope>#<path>" is declared in config; change the scope's pages to remove it.`。如果另一次写入先修改了页面，则直接抛出错误，不进行重试。

#### `addNote()` {/* #addnote */}

```typescript oxfmt:false
addNote(input: {
  scope: string
  path: string
  text: string
  when?: Date
  stamps?: string[]
  author?: string
}): Promise<KnowledgeNote>
```

向 `path` 对应的页面添加笔记。`text` 最多 250 个 Token。对现有页面的 `[[scope#path]]` 提及会将笔记链接到这些页面；其他 `[[...]]` 文本保持纯文本。`stamps` 是可看到该笔记的读者所属的作用域地址，默认使用页面的作用域。页面不存在时会抛出 `KnowledgeNotFoundError`。

#### `updateNote()` {/* #updatenote */}

```typescript oxfmt:false
updateNote(input: { id: string; text: string; when?: Date; stamps?: string[]; author?: string }): Promise<KnowledgeNote>
```

替换笔记时，会先添加新笔记，再删除旧笔记，最后返回带新 ID 的笔记。省略 `when` 或 `stamps`，或传入空值时，会保留其旧值。若添加后删除旧笔记失败，两条笔记都会留下，调用会抛错；请自行删除不需要的那条。如果旧笔记已被其他操作删除，新笔记也会被移除，不会留下任何笔记。

#### `removeNote()` {/* #removenote */}

```typescript oxfmt:false
removeNote(input: { id: string; author?: string }): Promise<KnowledgeNote | null>
```

删除笔记并返回该笔记；如果已被删除，则返回 `null`。

### 存储与维护 {/* #storage-and-maintenance */}

#### `getStorage()` {/* #getstorage */}

```typescript oxfmt:false
getStorage(): Promise<KnowledgeStorage>
```

返回 Knowledge 存储，供管理页面、删除操作和自定义导入脚本等宿主代码使用。其读取方法接受 `read`：`'all'` 会跳过角色检查。若读取应限于用户可见内容，请传入 `readScopeFor()` 的返回值。

```typescript
const store = await knowledge.getStorage()
const read = await knowledge.readScopeFor(['org:acme'])
const [scope] = await store.getScopesByAddress(['team:acme:support'])
const page = await store.getPageByPath({ scopeId: scope.id, path: ['handbook', 'refunds'], read })
```

#### `reindexLinks()` {/* #reindexlinks */}

```typescript oxfmt:false
reindexLinks(): Promise<number>
```

从所有页面正文重建页面链接索引，并返回索引的页面数量。正常写入会保持索引更新，因此此方法适用于索引建立前的页面，或直接写入存储的页面。它不需要向量存储。

#### `renameScopeDeclaration()` {/* #renamescopedeclaration */}

```typescript oxfmt:false
renameScopeDeclaration(from: string, to: string): Promise<number>
```

将从声明键 `from` 创建的已存储作用域及其子作用域（`from/<name>`），一步迁移到键 `to`，并返回迁移的作用域数量。若 `from` 仍存在于 `scopes` 中、`to` 不存在，或某个已存储地址不匹配 `to` 的模式，此方法会拒绝执行，且不做任何修改。在存储键与 `scopes` 一致之前，实例会拒绝运行。

在 MongoDB 上，重命名仅在副本集上的事务中运行。在独立服务器上，它不是原子的，并且中途失败可能会导致某些范围被重命名。

参见[重命名或停用作用域类型](/reference/knowledge/scope-declarations#rename-or-retire-a-scope-type)。

### 事件 {/* #events */}

#### `onChange()` {/* #onchange */}

```typescript oxfmt:false
onChange(listener: (event: KnowledgeChangeEvent) => void): () => void
```

每次通过此实例的存储完成写入后，都会调用 `listener`：包括 Tool 写入、通过 `getStorage()` 进行的宿主写入，以及新增作用域。返回值是一个取消监听的函数。可用它刷新实时界面。通过其他方式取得的存储所发生的写入，不会被此监听器看到。

事件只携带 ID，不携带内容或访问权限。因此，任何将事件转发给用户的服务，都必须通过 `readScopeFor()`，在该用户的可读作用域内重新读取各页面：

| `kind` | `op` | Fields |
| - | - | - |
| `scope` | `create` | `pageId`、`scopeId`（新作用域页面的 ID） |
| `page` | `create`、`update`、`move`、`merge`、`delete` | `pageId`、`scopeId`；`fromScopeId` 用于 `move` 和 `merge`；`sourceId` 用于 `merge`，表示被合并页面的 ID |
| `note` | `add`、`restamp`、`remove`、`restore` | `pageId`、`noteId` |
| `pin` | `add`、`remove` | `pageId` |

每个事件还包含 `knowledgeId` 和 `at`。创建作用域时只会发出一个 `scope` 事件，而不会为每个子作用域或模板页面分别发出，因此收到事件时应重新列出该作用域。监听器抛错会被记录，但不会导致写入失败。

```typescript
const unsubscribe = knowledge.onChange(event => {
  if (event.kind === 'page') refreshPage(event.pageId)
})
```

### 属性 {/* #properties */}

#### `pinnedContextEnabled` {/* #pinnedcontextenabled */}

`boolean`。表示 `pinnedContext` 是否已启用；启用后，关联 Agent 每轮都会收到置顶页面。
