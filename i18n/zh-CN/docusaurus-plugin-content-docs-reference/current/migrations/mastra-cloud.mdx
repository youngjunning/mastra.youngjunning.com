# 从 Mastra Cloud 迁移到 Mastra 平台

Mastra 平台以独立的 Studio 和 Server 产品、通过 CLI 执行的部署以及新的可观测性系统取代 Mastra Cloud。本指南将逐步介绍迁移过程。

## 主要变化 {/* #what-changed */}

| 方面 | Mastra Cloud | Mastra 平台 |
| - | - | - |
| **产品** | 单一项目 | 独立的 Studio 和 Server |
| **部署** | 推送后自动部署 | 通过 CLI 部署（`mastra studio deploy`、`mastra server deploy`） |
| **项目创建** | 从 GitHub 导入 | 首次部署时由 CLI 创建项目 |
| **存储** | 托管的 libSQL 数据库（Cloud Store）或自备数据库 | 自备托管数据库 |
| **可观测性** | 基于日志记录器 | 使用带有导出器的 `Observability` 类 |
| **环境变量** | 创建项目时设置 | 首次部署时从 `.env` 初始化，此后在控制台中管理 |
| **URL** | 单一 URL | Studio 和 Server 各有独立的 URL |

## 开始迁移前 {/* #before-you-start */}

<Steps>
  <StepItem>
    安装或更新 CLI：

    ```bash npm2yarn
    npm install -g mastra@latest
    ```
  </StepItem>

  <StepItem>
    登录：

    ```bash
    mastra auth login
    ```
  </StepItem>

  <StepItem>
    确认项目可以在本地构建：

    ```bash
    mastra build
    ```
  </StepItem>
</Steps>

## 将 Mastra Cloud Store 替换为托管数据库 {/* #replace-mastra-cloud-store-with-a-hosted-database */}

Mastra Cloud 曾提供由 [Turso](https://turso.tech) 支持的托管 libSQL 数据库，而 Mastra 平台不提供数据库托管服务。请将存储配置指向外部托管的数据库实例。

如果您原本就使用自备的托管数据库，请保留现有配置，并确保连接字符串通过控制台中的环境变量提供，而不是硬编码在代码中。

如果您使用 Cloud Store，请按以下步骤导出数据，并将其导入您自己管理的新 libSQL 数据库。

### 导出 Cloud Store 数据 {/* #export-your-cloud-store-data */}

导出 Cloud Store 数据有两种方式：从控制台下载，或使用 Turso CLI 手动生成数据库转储文件。

#### 方式 A：从控制台导出（推荐） {/* #option-a-export-from-the-dashboard-recommended */}

在 [Mastra 控制台](https://projects.mastra.ai)中打开项目，前往 **Runtime → Settings → Storage**，然后点击 **Export Database**。控制台会生成包含 Cloud Store 全部内容的 `.sql` 转储文件，并直接下载到“下载”文件夹。

下载完成后，将转储文件转换为 SQLite 数据库文件：

```bash
sqlite3 mydb.db < ~/Downloads/mastra-cloud-dump.sql
```

现在您有了可移植的 `mydb.db` 文件。在后续步骤中将其用作新数据库的数据源之前，可以先在本地检查或备份。

#### 方式 B：使用 Turso CLI 导出 {/* #option-b-export-via-the-turso-cli */}

如果您更习惯使用命令行，或需要编写导出脚本，可以通过 [Turso CLI](https://docs.turso.tech/cli) 直接生成数据库转储文件。此方式需要数据库 URL 和身份验证令牌，两者都可在控制台中找到。

<Steps>
  <StepItem>
    从控制台获取 Cloud Store 凭据。

    在 [Mastra 控制台](https://projects.mastra.ai)中打开项目，前往 **Runtime → Settings → Env Variables**。对于使用 Cloud Store 的项目，除您自行设置的变量外，系统还会注入以下两个变量：

    * `MASTRA_STORAGE_URL`：libSQL 连接字符串（例如 `libsql://<db-name>-<org>.turso.io`）。
    * `MASTRA_STORAGE_AUTH_TOKEN`：仅对该数据库有效、具有读取权限的身份验证令牌。

    每个变量都提供常规操作：通过眼睛图标显示或隐藏值，以及编辑、删除和复制值。使用 **Copy Value** 分别复制这两个值，供下方的转储命令使用。

    :::note
    只有启用了 Cloud Store 的项目才会显示这两个变量。如果您在 Mastra Cloud 中使用的是自备数据库，您已经有相应凭据，可以直接跳到[将 Mastra 应用连接到新数据库](#point-your-mastra-app-at-the-new-database)。
    :::

    :::note
    如果变量不存在、无法解密，或 Turso CLI 拒绝该令牌，请使用与 Mastra Cloud 账户关联的邮箱发送邮件至 [support@mastra.ai](mailto:support@mastra.ai)，索取待导出项目的 libSQL URL 和身份验证令牌，并附上项目名称或 ID。如果您的网络无法访问 CLI，支持团队也可以代您生成转储文件。
    :::
  </StepItem>

  <StepItem>
    安装 Turso CLI。

    ```bash title="macOS"
    brew install tursodatabase/tap/turso
    ```

    ```bash title="Linux / WSL"
    curl -sSfL https://get.tur.so/install.sh | bash
    ```

    有关 Windows 安装和无界面安装方式，请参阅 [Turso CLI 入门指南](https://docs.turso.tech/cli/introduction)。
  </StepItem>

  <StepItem>
    将数据库导出为 SQL 转储文件。

    将支持团队提供的凭据（或之前从控制台复制的值）设置为环境变量，然后把数据库转储到本地文件。如果 URL 来自控制台，请将其协议由 `libsql://` 改为 `https://`，因为传入 URL 和身份验证令牌时，Turso CLI 要求使用 HTTPS 格式。

    ```bash
    export MASTRA_STORAGE_URL="https://<db-name>-<org>.turso.io"
    export MASTRA_STORAGE_AUTH_TOKEN="<token-from-dashboard-or-support>"

    turso db shell "$MASTRA_STORAGE_URL?authToken=$MASTRA_STORAGE_AUTH_TOKEN" ".dump" > mastra-cloud-dump.sql
    ```

    :::warning
    将身份验证令牌嵌入连接字符串不如 Turso 推荐的方式安全：包含令牌的完整 URL 可能出现在命令历史记录、进程信息或终端输出中。Turso 建议先运行 `turso auth login`，再仅通过数据库名称生成转储文件：`turso db shell <database-name> ".dump" > mastra-cloud-dump.sql`。但此方式要求数据库属于您自己的 Turso 账户，而 Cloud Store 不满足这一条件，因此上面的环境变量示例可用于这次性导出。如果希望完全避免将令牌插入命令，请让支持团队代为生成转储文件并发送 SQL 文件给您。
    :::

    生成的 `mastra-cloud-dump.sql` 包含完整的数据库结构和数据，包括 thread 与消息历史、Workflow 快照、trace 和评估分数。继续操作前，请将文件妥善保存。
  </StepItem>
</Steps>

### 将转储文件导入新的 libSQL 数据库 {/* #load-the-dump-into-a-new-libsql-database */}

转储文件采用标准 SQL 格式，可导入任何兼容 libSQL 的数据库。以下示例使用新建的 Turso 托管数据库，以便沿用原有数据库类型，避免转换数据库结构。

<Steps>
  <StepItem>
    使用您自己的 Turso 账户登录 Turso CLI。

    ```bash
    turso auth login
    ```

    如果您没有 Turso 账户，CLI 会提示您创建。套餐详情请参阅 [Turso 定价](https://turso.tech/pricing)。
  </StepItem>

  <StepItem>
    创建新数据库并同时导入转储文件。

    ```bash
    turso db create mastra-migrated --from-dump ./mastra-cloud-dump.sql
    ```

    `--from-dump` 会在创建数据库时恢复本地 SQLite/libSQL 转储文件，比事后通过管道向 `turso db shell` 传送 SQL 语句更快、更安全。请选择靠近 Mastra Server 运行位置的区域，以降低延迟。可运行 `turso db locations` 查看可用区域；如果管理多个组，可传入 `--group <group-name>`。

    对于容量达数 GB 的转储文件，请添加 `--wait`，让 CLI 等待数据库完全可用后再退出。
  </StepItem>

  <StepItem>
    生成新数据库的连接凭据。

    ```bash
    turso db show mastra-migrated --url
    turso db tokens create mastra-migrated
    ```

    第一条命令输出 libSQL URL，第二条命令输出身份验证令牌。`LibSQLStore` 需要这两个值。
  </StepItem>
</Steps>

### 将 Mastra 应用连接到新数据库 {/* #point-your-mastra-app-at-the-new-database */}

将新凭据设置为环境变量，可写入本地 `.env` 文件，也可在 Mastra 平台控制台中设置：

```bash title=".env"
TURSO_DATABASE_URL="libsql://mastra-migrated-<org>.turso.io"
TURSO_AUTH_TOKEN="<token-from-turso-db-tokens-create>"
```

配置 `LibSQLStore`，使其读取这些环境变量：

```ts title="src/mastra/index.ts"
import { Mastra } from '@mastra/core/mastra'
import { LibSQLStore } from '@mastra/libsql'

export const mastra = new Mastra({
  storage: new LibSQLStore({
    id: 'libsql-storage',
    url: process.env.TURSO_DATABASE_URL!,
    authToken: process.env.TURSO_AUTH_TOKEN,
  }),
})
```

完整配置选项请参阅 [libSQL 存储参考文档](/integrations/databases/libsql)。

### 验证迁移结果 {/* #verify-the-migration */}

停用旧 Cloud 项目前，请确认新数据库能够提供应用所需的数据。

- 运行 `turso db shell mastra-migrated "SELECT name FROM sqlite_master WHERE type='table';"` 列出数据表。结果应包含由 Mastra 管理的表，例如 `mastra_threads`、`mastra_messages`、`mastra_workflow_snapshot` 和 `mastra_traces`。
- 对确定已有数据的表统计行数，例如运行 `turso db shell mastra-migrated "SELECT COUNT(*) FROM mastra_messages;"`，并与针对 Cloud Store URL 执行相同查询的结果比较。
- 使用新凭据启动 Mastra 应用，并确认现有 thread 或 Workflow 运行记录能在 [Studio](/docs/studio/observability) 中正常加载。

## 更新可观测性配置 {/* #update-observability-configuration */}

Mastra Cloud 使用基于日志记录器的追踪。Mastra 平台则使用 `Observability` 类，并明确配置导出器。

安装可观测性包：

```bash npm2yarn
npm install @mastra/observability
```

**迁移前（Mastra Cloud）：**

```ts title="src/mastra/index.ts"
import { Mastra } from '@mastra/core/mastra'
import { PinoLogger } from '@mastra/loggers'

export const mastra = new Mastra({
  logger: new PinoLogger({ name: 'my-app', level: 'info' }),
  // traces appear in Cloud dashboard automatically
})
```

**迁移后（Mastra 平台）：**

```ts title="src/mastra/index.ts"
import { Mastra } from '@mastra/core/mastra'
import {
  Observability,
  MastraStorageExporter,
  MastraPlatformExporter,
  SensitiveDataFilter,
} from '@mastra/observability'

export const mastra = new Mastra({
  observability: new Observability({
    configs: {
      default: {
        serviceName: 'my-app',
        exporters: [new MastraStorageExporter(), new MastraPlatformExporter()],
        spanOutputProcessors: [new SensitiveDataFilter()],
      },
    },
  }),
})
```

- `MastraStorageExporter` 将可观测性事件持久化到 Mastra Storage，供 [Studio](/docs/studio/observability) 使用。
- 设置 `MASTRA_PLATFORM_ACCESS_TOKEN` 后，`MastraPlatformExporter` 会将可观测性事件发送到 Mastra 平台。
- `SensitiveDataFilter` 会在导出前从 span 数据中遮盖密码、令牌和密钥。

完整配置方式（包括使用 DuckDB 存储指标的组合存储方案）请参阅[可观测性概览](/docs/observability/overview)。

## 部署 Studio {/* #deploy-studio */}

部署托管的 Studio 实例：

```bash
mastra studio deploy
```

CLI 会构建项目、上传构建产物，然后进行部署。首次部署时会创建 `.mastra-project.json`，将本地项目与平台项目关联。请将此文件提交到代码仓库。

本地环境文件是可选的。如果项目目录中存在 `.env` 或 `.env.*` 文件，部署时会包含其中的环境变量。

如果希望通过一次非交互式操作创建新的平台项目，无需单独运行 `mastra studio projects create`：使用 `--project` 指定名称，并使用 `--yes` 接受默认选项：

```bash
mastra studio deploy --project "my-new-project" --yes
```

详情请参阅 [Studio 部署文档](/docs/studio/deployment#mastra-platform)。

### 多个环境 {/* #multiple-environments */}

一个 Mastra 平台项目可在多个[环境](/docs/mastra-platform/environments)中运行同一套代码，例如 `production` 和 `staging`。使用统一的 [`mastra deploy`](/docs/mastra-platform/deploy) 命令分别部署到各环境：

```bash
mastra deploy --env production --yes
mastra deploy --env staging --env-file .env.staging --yes
```

每个环境都有专属的 URL、环境变量和部署历史记录。

## 部署 Server（可选） {/* #deploy-server-optional */}

如果需要生产环境的 API 端点，请部署 Server：

```bash
mastra server deploy
```

这会创建独立的部署，提供稳定的 API URL、环境变量管理和自定义域名支持。完整步骤请参阅 [Server 部署指南](/docs/mastra-platform/server)。

:::note
首次部署时会自动包含 `.env`、`.env.local` 和 `.env.production` 中的环境变量。此后请通过[网页控制台](https://projects.mastra.ai)管理环境变量。
首次部署前，请检查并清理这些文件，以免上传仅供开发使用或包含个人信息的密钥。
:::

## 配置 CI（可选） {/* #set-up-ci-optional */}

Mastra Cloud 在代码推送后自动部署。Mastra 平台通过 CLI 部署，因此您可以在任意 CI Provider 中运行部署命令。

### 先决条件 {/* #prerequisites */}

1. 创建 API 令牌：

   ```bash
   mastra auth tokens create ci-deploy
   ```

1. 将令牌保存为 GitHub Actions Secret（例如 `MASTRA_API_TOKEN`）。

1. 将首次手动部署生成的 `.mastra-project.json` 提交到代码仓库。

设置 `MASTRA_API_TOKEN` 后，CLI 会以无界面模式运行，并跳过所有交互式提示。

### 推送到 main 分支时部署 Server {/* #deploy-server-on-push-to-main */}

部署 Server 时，CLI 会从 `.mastra-project.json` 读取组织和项目，因此除了令牌，无需设置其他环境变量：

```yaml title=".github/workflows/deploy-server.yml"
name: Deploy to Mastra Server

on:
  push:
    branches: [main]

jobs:
  deploy:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: pnpm/action-setup@v4
      - uses: actions/setup-node@v4
        with:
          node-version: '22'
      - run: pnpm install
      - run: pnpm mastra server deploy --yes --config .mastra-project.json
        env:
          MASTRA_API_TOKEN: ${{ secrets.MASTRA_API_TOKEN }}
```

### 推送到 main 分支时部署 Studio {/* #deploy-studio-on-push-to-main */}

在无界面模式下部署 Studio 时，即使提供了 `--config`，仍需将 `MASTRA_ORG_ID` 和 `MASTRA_PROJECT_ID` 设置为环境变量：

```yaml title=".github/workflows/deploy-studio.yml"
name: Deploy to Mastra Studio

on:
  push:
    branches: [main]

jobs:
  deploy:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: pnpm/action-setup@v4
      - uses: actions/setup-node@v4
        with:
          node-version: '22'
      - run: pnpm install
      - run: pnpm mastra studio deploy --yes --config .mastra-project.json
        env:
          MASTRA_API_TOKEN: ${{ secrets.MASTRA_API_TOKEN }}
          MASTRA_ORG_ID: ${{ secrets.MASTRA_ORG_ID }}
          MASTRA_PROJECT_ID: ${{ secrets.MASTRA_PROJECT_ID }}
```

## 停用旧 Cloud 项目 {/* #decommission-old-cloud-project */}

将所有指向旧 Mastra Cloud URL 的客户端改为使用新的 Server 或 Studio URL。在 [Studio 可观测性控制台](/docs/studio/observability)确认新平台中可以看到 trace。确认所有功能正常后，再删除旧的 Mastra Cloud 项目。
