# 记忆

记忆配置中的部分参数现在需要显式设置；默认设置也已更新，以提升性能和可预测性。

## 变更 {/* #changed */}

### 语义召回和最近消息的默认设置 {/* #default-settings-for-semantic-recall-and-last-messages */}

默认设置已根据使用情况调整为更合理的值。`lastMessages` 的默认值从 40 降至 10；`semanticRecall` 和会话线程标题生成现在默认关闭。这些变更可提升性能，并减少意外的 LLM API 调用。

如果你依赖旧的默认设置，请在迁移时显式配置这些选项。

```diff
  const memory = new Memory({
    storage,
    vector,
    embedder,
+   options: {
+     lastMessages: 40, // Was default before
+     semanticRecall: {
+       topK: 2,
+       messageRange: 2,
+       scope: 'thread',
+     }, // Was enabled by default before
+     generateTitle: true, // Was enabled by default before
+   },
  });
```

### 默认记忆范围从 `thread` 改为 `resource` {/* #default-memory-scope-from-thread-to-resource */}

工作记忆和语义召回的默认范围均从 `'thread'` 改为 `'resource'`。这符合应用需要跨对话记住用户信息的常见场景。启用语义召回后，默认会搜索该用户的所有对话，而不只搜索当前会话线程。

如果你希望迁移后仍按对话线程隔离记忆，请显式设置 `scope: 'thread'`。

```diff
  const memory = new Memory({
    storage,
    vector,
    embedder,
    options: {
      workingMemory: {
        enabled: true,
+       scope: 'thread', // Explicitly set to thread-scoped
        template: `# User Profile...`,
      },
      semanticRecall: {
        topK: 3,
+       scope: 'thread', // Explicitly set to thread-scoped
      },
    },
  });
```

### 会话线程标题生成选项的位置 {/* #thread-title-generation-location */}

`generateTitle` 已从 `threads.generateTitle` 移至记忆选项的顶层。将该选项放在对应的配置层级后，API 也更简洁。

迁移时，请将 `generateTitle` 从 `threads` 配置移至 `options` 的顶层。

```diff
  const memory = new Memory({
    storage,
    vector,
    embedder,
    options: {
-     threads: {
-       generateTitle: true,
-     },
+     generateTitle: true,
    },
  });
```

### 优化语义召回的默认设置 {/* #semantic-recall-default-settings-optimization */}

语义召回的默认设置已根据 RAG 研究进行优化。`topK` 从 2 增至 4，`messageRange` 从 `{ before: 2, after: 2 }` 改为 `{ before: 1, after: 1 }`。这些变更只会略微增加消息数量，同时提高准确性。

如果你依赖之前的默认值，请在迁移时显式设置这些值。

```diff
  const memory = new Memory({
    storage,
    vector,
    embedder,
    options: {
      semanticRecall: {
+       topK: 2, // Was default before
+       messageRange: { before: 2, after: 2 }, // Was default before
      },
    },
  });
```

### `memory.readOnly` 移至 `memory.options.readOnly` {/* #memoryreadonly-moved-to-memoryoptionsreadonly */}

`readOnly` 属性已从 `memory` 选项的顶层移至 `options` 内，与 `lastMessages` 和 `semanticRecall` 等记忆配置选项保持一致。

迁移时，请将顶层的 `readOnly` 移入 `options`。

```diff
  agent.stream('Hello', {
    memory: {
      thread: threadId,
      resource: resourceId,
-     readOnly: true,
+     options: {
+       readOnly: true,
+     },
    },
  });
```

### `Memory.query()` 更名为 `Memory.recall()` {/* #memoryquery-renamed-to-memoryrecall */}

`Memory.query()` 方法已更名为 `Memory.recall()`。新方法统一返回更简洁的 `{ messages: MastraDBMessage[] }`，不再返回多种格式。新名称也更准确地描述了从记忆中检索消息的操作，使 API 更简洁。

迁移时，请将 `query()` 改为 `recall()`，并更新依赖旧返回格式的代码。

```diff
- const result = await memory.query({ threadId: 'thread-123' });
+ const result = await memory.recall({ threadId: 'thread-123' });
- // result: { messages: CoreMessage[], uiMessages: UIMessageWithMetadata[], messagesV2: MastraMessageV2[] }
+ // result: { messages: MastraDBMessage[] }
+ const messages = result.messages;
```

```bash

```

:::

### `Memory.recall()` 的参数变更 {/* #memoryrecall-parameter-changes */}

`Memory.recall()` 方法现在使用支持分页的 `StorageListMessagesInput` 格式，`vectorMessageSearch` 参数也已更名为 `vectorSearchString`。这些变更使记忆 API 与存储分页 API 保持一致，并统一了命名。

迁移时，请更新方法名、查询参数和向量搜索参数。

```diff
- memory.query({
+ memory.recall({
    threadId: 'thread-123',
-   vectorMessageSearch: 'What did we discuss?',
-   selectBy: { ... },
+   vectorSearchString: 'What did we discuss?',
+   page: 0,
+   perPage: 20,
+   orderBy: 'createdAt',
+   filter: { ... },
+   threadConfig: { semanticRecall: true },
  });
```

```bash

```

:::

### `MastraMessageV2` 类型更名为 `MastraDBMessage` {/* #mastramessagev2-type-renamed-to-mastradbmessage */}

`MastraMessageV2` 类型已更名为 `MastraDBMessage`，以更清楚地表明它是数据库中的消息格式。

迁移时，请将所有 `MastraMessageV2` 替换为 `MastraDBMessage`。

```diff
- import { MastraMessageV2 } from '@mastra/core';
- function yourCustomFunction(input: MastraMessageV2) {}
+ import type { MastraDBMessage } from '@mastra/core/agent';
+ function yourCustomFunction(input: MastraDBMessage) {}
```

## 已删除 {/* #removed */}

### 工作记忆的 `text-stream` 模式 {/* #working-memory-text-stream-mode */}

工作记忆的 `use: "text-stream"` 选项已删除，现在仅支持 `tool-call` 模式。移除可靠性较低的流式模式后，工作记忆 API 也更简洁。

迁移时，请删除 `use: "text-stream"` 选项。工作记忆将默认使用 `tool-call` 模式。

```diff
  const memory = new Memory({
    storage,
    vector,
    embedder,
    options: {
      workingMemory: {
        enabled: true,
-       use: 'text-stream',
        template: '...',
      },
    },
  });
```

### `Memory.rememberMessages()` 方法 {/* #memoryremembermessages-method */}

`Memory.rememberMessages()` 方法已删除。它与 `query()`（现为 `recall()`）功能相同，统一使用一个方法可简化 API。

迁移时，请将 `rememberMessages()` 调用改为 `recall()`。

```diff
- const { messages } = await memory.rememberMessages({
+ const { messages } = await memory.recall({
    threadId,
    resourceId,
  });
```

### 记忆方法的 `format` 参数 {/* #format-parameter-from-memory-methods */}

所有记忆读取方法的 `format` 参数均已删除，现在统一默认返回 `MastraDBMessage`。AI SDK 格式转换已移至 `@mastra/ai-sdk/ui` 中的专用工具函数。将 UI 专用转换代码移至独立包后，tree-shaking 效果也得到改善。

迁移时，请删除 `format` 参数，并使用转换函数获取 AI SDK 格式。

```diff
- const messages = await memory.getMessages({ threadId, format: 'v2' });
- const uiMessages = await memory.getMessages({ threadId, format: 'ui' });

+ const result = await memory.recall({ threadId });
+ const messages = result.messages; // Always MastraDBMessage[]
+
+ // Use conversion functions for AI SDK formats
+ import { toAISdkV5Messages } from '@mastra/ai-sdk/ui';
+ const uiMessages = toAISdkV5Messages(messages);
```

### `MastraMessageV3` 类型 {/* #mastramessagev3-type */}

`MastraMessageV3` 类型及相关转换方法已删除。消息现在直接在 `MastraMessageV2`（现为 `MastraDBMessage`）与 AI SDK v5 格式之间转换。移除中间格式后，整体结构更简洁。

迁移时，请使用 `MastraDBMessage` 存储消息，或直接使用 AI SDK v5 消息格式。

```diff
- import type { MastraMessageV3 } from '@mastra/core/agent';
- const v3Messages = messageList.get.all.v3();

+ // For storage
+ const v2Messages = messageList.get.all.v2();
+
+ // For AI SDK v5
+ const uiMessages = messageList.get.all.aiV5.ui();
+ const modelMessages = messageList.get.all.aiV5.model();
```

### 从 Memory 构造函数中移除 `processors` 配置 {/* #processors-config-from-memory-constructor */}

Memory 构造函数不再支持 `processors` 配置选项；继续使用会抛出错误。请在 Agent 层配置处理器，使其行为限定在 Agent 执行过程中。

迁移时，请通过 `inputProcessors` 和/或 `outputProcessors` 将处理器配置从 Memory 移至 Agent。

```diff
+ import { TokenLimiter } from '@mastra/core/processors';
+
  const memory = new Memory({
    storage,
    vector,
    embedder,
-   processors: [/* ... */],
  });

  const agent = new Agent({
    id: 'agent',
    memory,
+   inputProcessors: [
+     new TokenLimiter({ limit: 4000 }), // Limits historical messages to fit context window
+   ],
  });
```

此外，`@mastra/memory/processors` 导入路径已删除。请改从 `@mastra/core/processors` 导入处理器。详情参阅[处理器迁移指南](/reference/migrations/upgrade-to-v1/processors#memory-processor-exports-moved-to-core)。

关于如何在 Agent 中使用处理器，请参阅[处理器文档](/docs/agents/processors)。包含记忆功能的完整示例见 [TokenLimiter 参考文档](/reference/processors/token-limiter-processor#extended-usage-example)。
