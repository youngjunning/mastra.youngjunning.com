# Mastra 类

Mastra 类已调整结构，限制从包根路径导入，并改用 getter 方法代替直接访问属性。

## 变更 {/* #changed */}

### 从顶层导入改为子路径导入 {/* #top-level-imports-to-subpath-imports */}

`@mastra/core` 的主入口现在只导出 `Mastra` 和 `Config`。其他导出均移至子路径。这让打包工具更容易移除未使用的代码，从而改善 tree shaking 效果并减小打包体积。

迁移时，请将从 `@mastra/core` 导入的其他符号改为从对应子路径导入。

```diff
- import { Mastra, Agent, Workflow, createTool } from '@mastra/core';
+ import { Mastra, type Config } from '@mastra/core';
+ import { Agent } from '@mastra/core/agent';
+ import { Workflow } from '@mastra/core/workflows';
+ import { createTool } from '@mastra/core/tools';
```

:::tip[Codemod]

可以使用 Mastra 的 codemod CLI 自动更新代码：

```bash
npx @mastra/codemod@latest v1/mastra-core-imports .
```

:::

### 将 `experimental_auth` 改为 `auth` {/* #experimental_auth-to-auth */}

实验性身份验证配置已转为稳定功能，表示 auth API 现已稳定，可用于生产环境。

迁移时，请将 Mastra 配置中的 `experimental_auth` 键重命名为 `auth`。

```diff
  const mastra = new Mastra({
-   experimental_auth: {
+   auth: {
      provider: workos,
    },
  });
```

:::tip[Codemod]

可以使用 Mastra 的 codemod CLI 自动更新代码：

```bash
npx @mastra/codemod@latest v1/experimental-auth .
```

:::

### 所有 Mastra 基础组件都必须提供 `id` 参数 {/* #required-id-parameter-for-all-mastra-primitives */}

所有存储、向量存储、Agent、Workflow、MCP Server、Processor、Scorer 和 Tool 现在都必须在初始化时提供 `id` 参数。必填 ID 使 Mastra API 更统一，也有助于避免 ID 冲突。

这些基础组件现在也提供 `get`、`list` 和 `add` 函数。

迁移时，请为所有存储和向量存储实例添加 `id` 参数。如果多次实例化同一个存储或向量存储类，请确保每个实例的 ID 都不同。

```diff
- const storage = new LibSQLStore({
-   url: ':memory:',
- });
+ const storage = new LibSQLStore({
+   id: 'my-app-storage',
+   url: ':memory:',
+ });

- const vector = new PgVector({
-   connectionString: process.env.DATABASE_URL,
- });
+ const vector = new PgVector({
+   id: 'my-app-vector',
+   connectionString: process.env.DATABASE_URL,
+ });
```

为不同用途创建独立实例时，请使用有明确含义且互不重复的 ID：

```diff
  const agentMemory = new Memory({
    storage: new LibSQLStore({
-     url: 'file:./agent.db',
+     id: 'weather-agent-memory-storage',
+     url: 'file:./agent.db',
    }),
  });

  const mastra = new Mastra({
    storage: new LibSQLStore({
+     id: 'mastra-storage',
      url: ':memory:',
    }),
  });
```

### 获取所有实例的 API 从 `get<primitives>` 改为 `list<primitive>` {/* #primitive-plural-apis-changes-from-getprimitives-to-listprimitive */}

原本返回某类基础组件所有实例的 `get*` 函数，现已重命名为 `list*`，以更准确地体现其用途。

```diff
- const agents = mastra.getAgents();
+ const agents = mastra.listAgents();
- const vectors = mastra.getVectors();
+ const vectors = mastra.listVectors();
- const workflows = mastra.getWorkflows();
+ const workflows = mastra.listWorkflows();
- const scorers = mastra.getScorers();
+ const scorers = mastra.listScorers();
- const mcpServers = mastra.getMCPServers();
+ const mcpServers = mastra.listMCPServers();
- const logsByRunId = await mastra.getLogsByRunId({ runId: 'id', transportId: 'id' });
+ const logsByRunId = await mastra.listLogsByRunId({ runId: 'id', transportId: 'id' });
- const logs = await mastra.getLogs('transportId');
+ const logs = await mastra.listLogs('transportId');
```

:::tip[Codemod]

可以使用 Mastra 的 codemod CLI 自动更新代码：

```bash
npx @mastra/codemod@latest v1/mastra-plural-apis .
```

:::

### 每种基础组件都提供 `getById` 和 `get` 函数 {/* #each-primitive-has-a-getbyid-and-a-get-function */}

```typescript
mastra.getMCPServer('myServer') // Works (registry key)
mastra.getMCPServerById('my-mcp-server') // Works (intrinsic ID)
```

### Tool 注册现在使用自身的 ID {/* #tool-registration-now-uses-intrinsic-ids */}

从 Agent 或 MCP Server 向 Mastra 实例自动注册 Tool 时，现在使用 Tool 自身的 `id`，而不是配置对象中的键。这样可以避免多个 Agent 或 MCP Server 的 Tool 使用相同配置键时发生冲突。

迁移时，请将通过配置键引用 Tool 的代码改为使用 Tool 自身的 ID。

```diff
  const agent = new Agent({
    id: 'agent1',
    tools: {
      searchTool: weatherSearchTool,
    },
  });

- mastra.getTool('searchTool');
+ mastra.getTool(weatherSearchTool.id);
```
