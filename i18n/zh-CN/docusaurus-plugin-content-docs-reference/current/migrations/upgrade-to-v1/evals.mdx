# 评估与评分器

评估 API 已统一采用新的评分器系统，并更新了命名约定和配置要求。

## 变更 {/* #changed */}

### `getScorers` 改为 `listScorers` {/* #getscorers-to-listscorers */}

`getScorers()` 方法已重命名为 `listScorers()`。这一变更与整个 API 的命名约定一致：返回多个对象的获取方法使用 `list` 前缀。

迁移时，将所有 `getScorers()` 调用替换为 `listScorers()`。

```diff
- const scorers = mastra.getScorers();
+ const scorers = mastra.listScorers();
```

:::tip[Codemod]

可以使用 Mastra 的 codemod CLI 自动更新代码：

```bash
npx @mastra/codemod@latest v1/mastra-plural-apis .
```

:::

### `runExperiment` 改为 `runEvals` {/* #runexperiment-to-runevals */}

`runExperiment()` 函数已重命名为 `runEvals()`，以明确表明它用于运行评估。

迁移时，将函数调用中的 `runExperiment` 改为 `runEvals`。

```diff
- import { createScorer, runExperiment } from '@mastra/core/evals';
+ import { createScorer, runEvals } from '@mastra/core/evals';
  import { myAgent } from './agents/my-agent';

  const scorer = createScorer({
    id: 'helpfulness-scorer',
    // ...
  });

- const result = await runExperiment({ target: myAgent, scorers: [scorer], data: inputs });
+ const result = await runEvals({ target: myAgent, scorers: [scorer], data: inputs });
```

:::tip[Codemod]

可以使用 Mastra 的 codemod CLI 自动更新代码：

```bash
npx @mastra/codemod@latest v1/evals-run-experiment .
```

:::

### `getScorerByName` 改为 `getScorerById` {/* #getscorerbyname-to-getscorerbyid */}

`getScorerByName()` 方法已重命名为 `getScorerById()`。评分器现在必须提供 `id` 字段，而非 `name` 字段。这与 API 使用 `id` 标识实体的通用模式一致。

迁移时，更新方法调用和评分器配置，改用 `id` 而非 `name`。

```diff
  const scorer = createScorer({
-   name: 'helpfulness-scorer',
+   id: 'helpfulness-scorer',
    // ...
  });

- const scorer = mastra.getScorerByName('helpfulness-scorer');
+ const scorer = mastra.getScorerById('helpfulness-scorer');
```

:::tip[Codemod]

可以使用 Mastra 的 codemod CLI 自动更新代码：

```bash

```

:::

### 评分器配置从 `name` 改为 `id` {/* #scorer-configuration-from-name-to-id */}

评分器现在必须提供 `id` 字段，`name` 字段则变为可选。新字段使评分器与其他 Mastra 实体保持一致。

迁移时，更新评分器定义，将 `id` 用作必填字段。

```diff
  const scorer = createScorer({
-   name: 'helpfulness-scorer',
+   id: 'helpfulness-scorer',
+   name: 'Helpfulness Scorer', // optional
    // ...
  });
```

### 分数存储 API 改用 `listScoresBy*` 命名模式 {/* #storage-score-apis-to-listscoresby-pattern */}

分数存储 API 已重命名，统一采用 `listScoresBy*` 命名模式。这与存储 API 的通用命名约定一致。

迁移时，将分数查询方法改为使用新的命名模式。

```diff
- const scores = await storage.getScores({ scorerName: 'helpfulness-scorer' });
+ const scores = await storage.listScoresByScorerId({
+   scorerId: 'helpfulness-scorer',
+ });

// Also available:
// - listScoresByRunId
// - listScoresByEntityId
// - listScoresBySpan
```

### 预构建评分器统一从 `scorers/prebuilt` 路径导入 {/* #prebuilt-scorer-imports-to-scorersprebuilt-path */}

预构建评分器现在统一从 `@mastra/evals/scorers/prebuilt` 路径导入，不再分别使用 `scorers/llm` 和 `scorers/code` 路径。这简化了导入方式，也让预构建评分器的组织结构更加清晰。

迁移时，将导入语句改为使用新的 `scorers/prebuilt` 路径。

```diff
  // LLM-based scorers
- import { createHallucinationScorer } from '@mastra/evals/scorers/llm';
- import { createFaithfulnessScorer } from '@mastra/evals/scorers/llm';
+ import { createHallucinationScorer } from '@mastra/evals/scorers/prebuilt';
+ import { createFaithfulnessScorer } from '@mastra/evals/scorers/prebuilt';

  // Code-based scorers
- import { createContentSimilarityScorer } from '@mastra/evals/scorers/code';
- import { createCompletenessScorer } from '@mastra/evals/scorers/code';
+ import { createContentSimilarityScorer } from '@mastra/evals/scorers/prebuilt';
+ import { createCompletenessScorer } from '@mastra/evals/scorers/prebuilt';
```

:::tip[Codemod]

可以使用 Mastra 的 codemod CLI 自动更新代码：


### 评分器消息类型从 `UIMessage` 改为 `MastraDBMessage` {/* #scorer-message-types-from-uimessage-to-mastradbmessage */}

评分器的输入和输出类型现在使用 `MastraDBMessage[]`，不再使用 `UIMessage`。这使评分器与数据库持久化的消息格式保持一致，也保证了整个框架的一致性。

迁移时，更新评分器实现以使用 `MastraDBMessage` 类型，并通过嵌套的 `content` 结构访问消息内容。

```diff
  import type {
    ScorerRunInputForAgent,
    ScorerRunOutputForAgent
  } from '@mastra/core/evals';

- // ScorerRunInputForAgent uses UIMessage[]
- const inputMessages: UIMessage[] = run.input.inputMessages;
+ // ScorerRunInputForAgent now uses MastraDBMessage[]
+ import type { MastraDBMessage } from '@mastra/core/agent';
+ const inputMessages: MastraDBMessage[] = run.input.inputMessages;
```

### 消息内容改为嵌套结构 {/* #message-content-structure-to-nested-format */}

Tool 调用和文本内容现在通过嵌套的 `content` 对象访问，而非直接从消息的顶层属性获取。该嵌套结构与数据库消息格式及其类型一致。

迁移时，通过 `message.content.toolInvocations` 访问 Tool 调用；通过 `message.content.content` 或辅助函数 `getTextContentFromMastraDBMessage()` 获取文本。

```diff
+ import { getTextContentFromMastraDBMessage } from '@mastra/evals';
+
  const run = await scorer.run(testRun);

  // Accessing text content
- const text = message.content;
+ const text = getTextContentFromMastraDBMessage(message);
+ // or directly: message.content.content

  // Accessing tool invocations
- const toolCalls = message.toolInvocations;
+ const toolCalls = message.content.toolInvocations;
```

## 移除的内容 {/* #removed */}

### 旧版评估代码 {/* #legacy-evals-code */}

旧版评估代码已从 `@mastra/core` 中移除，包括旧版评估指标、评分器和评判器模块，以及基于钩子的自动评估代码。移除这些过时的评估方式简化了代码库。

迁移时，使用 `@mastra/core/evals` 或 `@mastra/evals` 中新的评估与评分器 API。

```diff
- // Legacy evals APIs
+ import { createScorer, runEvals } from '@mastra/core/evals';
+
+ const scorer = createScorer({
+   id: 'my-scorer',
+   // Use new scorer API
+ });
```

### Agent 的 `TMetrics` 泛型参数 {/* #agent-tmetrics-generic-parameter */}

`AgentConfig` 和 `Agent` 构造函数中的 `TMetrics` 泛型参数已移除。指标和评分器现在通过评分器 API 配置，不再属于 Agent 类型系统的一部分。这简化了 Agent 的类型签名。

迁移时，移除 `TMetrics` 泛型参数，并通过评分器 API 配置评分器。

```diff
- const agent = new Agent<AgentId, Tools, Metrics>({
+ const agent = new Agent<AgentId, Tools>({
    // ...
  });
```

### 与评估相关的类型导出 {/* #evals-related-type-exports */}

多个与评估相关的类型导出已移除，包括 `DeprecatedOutputOptions`、`Metric` 和处理器选项类型。这些类型现在仅供内部使用，或已被新的评分器 API 取代。这减少了 API 的公开范围。

迁移时，移除对这些类型的引用，改用新的评分器 API。

```diff
- import type {
-   DeprecatedOutputOptions,
-   Metric,
-   LanguageDetectorOptions,
-   ModerationOptions,
- } from '@mastra/core';
+ // Use new scorers API types
+ import type { Scorer } from '@mastra/core/evals';
```

### `createUIMessage` 测试辅助函数 {/* #createuimessage-test-helper */}

`createUIMessage()` 测试辅助函数已移除，由 `createTestMessage()` 取代。新函数创建具有嵌套内容结构的 `MastraDBMessage` 对象，并支持可选的 Tool 调用。这使测试工具与新的消息格式保持一致。

迁移时，将 `createUIMessage()` 调用替换为 `createTestMessage()`，并改用 `MastraDBMessage` 类型。

```diff
- import { createUIMessage } from '@mastra/evals';
+ import { createTestMessage } from '@mastra/evals';

  // Creating test messages
- const message = createUIMessage({
-   id: 'test-1',
+ const message = createTestMessage({
+   id: 'test-1', // optional, defaults to 'test-message'
    role: 'user',
    content: 'Hello',
    toolInvocations: [], // optional
  });
```
