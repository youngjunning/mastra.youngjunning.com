# Tool

Tool执行签名已更新为使用单独的输入和上下文参数以及重新组织的上下文属性。

## 改变了 {/* #changed */}

### `createTool`执行签名`(inputData, context)` format {/* #createtool-execute-signature-to-inputdata-context-format */}

全部`createTool` execute functions now use a signature with separate `inputData` and `context`参数而不是单个解构对象。Tool输入和执行上下文现在是独立传递的。

此签名更改仅适用于`createTool`. For workflow `createStep` calls, keep the `async (inputData, context)` signature.

要迁移，请更新`createTool` signatures to use `inputData` as the first parameter (typed from `inputSchema`) and `context` as the second parameter.

```diff
  createTool({
    id: 'weather-tool',
-   execute: async ({ context, requestContext, mastra }) => {
-     const location = context.location;
-     const userTier = requestContext.get('userTier');
-     return getWeather(location, userTier);
-   },
+   execute: async (inputData, context) => {
+     const location = inputData.location;
+     const userTier = context?.requestContext?.get('userTier');
+     return getWeather(location, userTier);
+   },
  });
```

### `createTool`上下文属性组织 {/* #createtool-context-properties-organization */}

上下文属性`createTool` are now organized into namespaces. Agent-specific properties are under `context.agent`, workflow-specific properties are under `context.workflow`, and MCP-specific properties are under `context.mcp`. The namespaces organize these properties under a clearer API surface.

对于在Agent内部执行的Tool，可以通过以下方式访问特定于Agent的属性`context.agent`.

```diff
  createTool({
    id: 'suspendable-tool',
    suspendSchema: z.object({ message: z.string() }),
    resumeSchema: z.object({ approval: z.boolean() }),
-   execute: async ({ context, suspend, resumeData }) => {
-     if (!resumeData) {
-       return await suspend({ message: 'Waiting for approval' });
-     }
-     if (resumeData.approval) {
-       return { success: true };
-     }
-   },
+   execute: async (inputData, context) => {
+     if (!context?.agent?.resumeData) {
+       return await context?.agent?.suspend({
+         message: 'Waiting for approval',
+       });
+     }
+     if (context.agent.resumeData.approval) {
+       return { success: true };
+     }
+   },
  });
```

对于在Workflow程内执行的Tool，可通过以下方式访问Workflow程特定的属性`context.workflow`.

```diff
  createTool({
    id: 'workflow-tool',
-   execute: async ({ workflowId, runId, state, setState }) => {
-     const currentState = state;
-     setState({ step: 'completed' });
-     return { result: 'done' };
-   },
+   execute: async (inputData, context) => {
+     const currentState = context?.workflow?.state;
+     context?.workflow?.setState({ step: 'completed' });
+     return { result: 'done' };
+   },
  });
```

这`suspendPayload` is validated against the `suspendSchema` when the tool is executed. What happens when the `suspendPayload` doesn't match the `suspendSchema` depends on how the tool runs:

* **Agent**：验证错误作为Tool输出返回，并记录警告，但暂停继续。
* **直接的`execute()` call**：验证错误作为Tool输出返回，而不记录警告。
* **Workflow程步骤**：该步骤因暂停数据验证错误而失败，并且Workflow运行失败。

此外，当该Tool恢复时，`resumeData` gets validated against the `resumeSchema`. If the resumeData doesn't match the `resumeSchema`, the tool will return a `ValidationError`, preventing the tool resumption.

要跳过`suspendSchema` or `resumeSchema` validation, don't define `suspendSchema` or `resumeSchema` in the tool creation.

:::注意
有关 MCP 特定Tool上下文更改，请参阅[MCP migration guide](/reference/migrations/upgrade-to-v1/mcp).
:::

### `RuntimeContext`到`RequestContext` {/* #runtimecontext-to-requestcontext */}

这`RuntimeContext` class has been renamed to `RequestContext` throughout the tool execution context. The new name identifies the class as request-specific data.

要迁移，请更新引用`runtimeContext` to `requestContext` in tool execution functions.

```diff
  createTool({
    id: 'my-tool',
    execute: async (inputData, context) => {
-     const userTier = context?.runtimeContext?.get('userTier');
+     const userTier = context?.requestContext?.get('userTier');
      return { result: userTier };
    },
  });
```

:::提示\[代码修改]

您可以使用 Mastra 的 codemod CLI 自动更新导入：

```bash
npx @mastra/codemod@latest v1/runtime-context .
```

:::

这适用于所有Tool执行，无论是直接调用还是通过Agent和Workflow调用。类型缩小可确保您正确处理验证错误并防止访问输出属性时出现运行时错误。

### Tool输出验证`outputSchema` {/* #tool-output-validation-with-outputschema */}

Tool带有`outputSchema` now validate their return values at runtime. Previously, `outputSchema` was only used for type inference - the output was never validated.

如果您的Tool返回的数据与其不匹配`outputSchema`, it will now return a `ValidationError` instead of the invalid data. This is the default `outputValidation: 'strict'` behavior. With [`outputValidation: 'warn'`](/reference/tools/create-tool), Mastra logs the mismatch and returns the original output unchanged.

要修复验证错误，请确保Tool的输出与架构定义匹配：

```diff
  const getUserTool = createTool({
    id: "get-user",
    outputSchema: z.object({
      id: z.string(),
      name: z.string(),
      email: z.string().email(),
    }),
    execute: async (inputData) => {
-     return { id: "123", name: "John" }; // Missing email
+     return { id: "123", name: "John", email: "john@example.com" };
    },
  });
```

当验证失败时，该Tool会返回`ValidationError`:

```diff
+ // Before v1 - invalid output would silently pass through
  await getUserTool.execute({});
- // { id: "123", name: "John" } - missing email
+ // {
+ //   error: true,
+ //   message: "Tool output validation failed for get-user. The tool returned invalid output:\n- email: Required\n\nReturned output: {...}",
+ //   validationErrors: { ... }
+ // }
```

### `tool.execute`返回类型包括`ValidationError` {/* #toolexecute-return-type-includes-validationerror */}

返回类型为`tool.execute` now includes `ValidationError` to handle validation failures. You must narrow the result type before accessing output schema properties to satisfy TypeScript's type checking.

打电话时`tool.execute`, check if the result contains an error before accessing output properties:

```typescript
const result = await getUserTool.execute({})

// Type-safe check for validation errors
if ('error' in result && result.error) {
  console.error('Validation failed:', result.message)
  console.error('Details:', result.validationErrors)
  return
}

// TypeScript knows result is valid here
console.log(result.id, result.name, result.email)
```

或者，更新`outputSchema` to match your actual output, or remove `outputSchema` entirely if you don't need validation.

### 直接Tool执行 {/* #direct-tool-execution */}

这`tool.execute` property is optional in the type system to support client-side tool definitions where execution logic is handled separately. When calling `execute` directly on a tool instance (rather than through agents or workflows), use optional chaining or non-null assertion:

```typescript
// Optional chaining (recommended)
const result = await weatherTool.execute?.({ location: 'New York' }, {})

// Non-null assertion (when you know execute exists)
const result = await weatherTool.execute!({ location: 'New York' }, {})
```
