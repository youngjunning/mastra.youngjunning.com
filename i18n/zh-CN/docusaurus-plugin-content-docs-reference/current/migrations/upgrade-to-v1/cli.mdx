# 命令行界面

通过删除部署命令、配置标志和启动文件，CLI 得到了简化。添加了新的迁移命令以帮助数据库架构升级。

## 额外 {/* #added */}

### `mastra migrate`命令 {/* #mastra-migrate-command */}

一个新的`mastra migrate` command helps run database migrations when upgrading Mastra versions. This is particularly useful when upgrading from older versions that may have data incompatibilities.

```bash
npx mastra migrate
```

该命令会捆绑您的项目并在运行任何必要的迁移之前连接到您配置的存储。它当前支持迁移重复的跨度条目，这可能会阻止创建唯一约束。

请参阅[Storage migration guide](/reference/migrations/upgrade-to-v1/storage#duplicate-spans-migration) for details on when this migration is needed.

## 已删除 {/* #removed */}

### `mastra deploy`命令 {/* #mastra-deploy-command */}

这`mastra deploy` command has been removed from the CLI. This change simplifies the CLI by removing vendor-specific deployment logic.

要迁移，请选择其中一项[deployment platforms](/docs/deployment/overview) of your choice.

### `--env`标志来自`mastra build` {/* #--env-flag-from-mastra-build */}

这`--env` flag has been removed from the `mastra build` command. This change simplifies the build command.

要迁移，请使用`mastra start --env <env>` to start the build output with a custom environment.

```diff
- mastra build --env production
+ mastra build
+ mastra start --env production
```

### `--port`标志来自`mastra dev` {/* #--port-flag-from-mastra-dev */}

这`--port` flag has been removed from the `mastra dev` command. Port configuration is now handled through the Mastra instance configuration. This change centralizes port configuration.

要迁移，请使用`server.port` on the Mastra instance instead of the CLI flag.

```ts
const mastra = new Mastra({
  server: {
    port: 3001,
  },
})
```

### CLI 中的遥测选项 {/* #telemetry-options-from-cli */}

这`telemetry` option has been removed from CLI commands including the `--no-telemetry` / `-nt` flag. Telemetry configuration has been removed from the CLI. This change reflects the move of telemetry features to the observability package.

要迁移，请从 CLI 命令中删除遥测标志。使用`@mastra/observability` for tracing features.
