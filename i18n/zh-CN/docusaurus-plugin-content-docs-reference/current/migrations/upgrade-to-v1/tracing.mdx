# 追踪

v1 重构了可观测性系统，并将其移至独立的 `@mastra/observability` 包。本指南介绍两条迁移路径，具体取决于您从哪个版本升级。

:::warning[升级后可观测性数据将停止传输]
如果您将 Mastra 包升级到 v1，却没有把 `telemetry:` 配置迁移为 `observability:`，旧配置会在运行时被忽略。服务仍会正常启动且不报错，但**跟踪、日志和指标都不会发送到任何目的地**。如果您此前将数据发送到 Mastra Cloud，其仪表板将不再显示数据。

请在升级 Mastra 包的同一次变更中完成迁移，并确认跟踪已出现在 [Mastra Studio](/docs/studio/observability) 中，然后再将升级视为完成。如果您此前使用 Mastra Cloud 托管服务，还需遵循 [Mastra Cloud 迁移指南](/reference/migrations/mastra-cloud)。新平台需要新的访问令牌和 Studio 项目，`MastraPlatformExporter` 才能将数据发送到该平台。
:::

:::note[导出器重命名]

`MastraPlatformExporter`（将数据发送到 Mastra 平台）取代原来的 `CloudExporter`；`MastraStorageExporter`（将数据持久化到 Mastra Storage）取代原来的 `DefaultExporter`。旧类仍可从 `@mastra/observability` 导入，行为也保持不变，但已被弃用。新代码应使用 `MastraPlatformExporter` 和 `MastraStorageExporter`。现有的 `CloudExporter` 或 `DefaultExporter` 导入在未来的主版本移除这些类之前仍可使用。

:::

## 迁移路径 {/* #migration-paths */}

### 从基于 OTEL 的遥测迁移（0.x） {/* #from-otel-based-telemetry-0x */}

如果您在 Mastra 中使用旧版 `telemetry:` 配置，需要迁移到经过全面重新设计的新系统。

**之前（0.x，带有 OTEL 遥测）：**

```typescript
import { Mastra } from '@mastra/core'

export const mastra = new Mastra({
  telemetry: {
    serviceName: 'my-app',
    enabled: true,
    sampling: {
      type: 'always_on',
    },
    export: {
      type: 'otlp',
      endpoint: 'http://localhost:4318',
    },
  },
})
```

**迁移后（v1 可观测性）：**

```typescript
import { Mastra } from '@mastra/core'
import {
  Observability,
  MastraStorageExporter,
  MastraPlatformExporter,
  SensitiveDataFilter,
} from '@mastra/observability'

export const mastra = new Mastra({
  observability: new Observability({
    configs: {
      default: {
        serviceName: 'mastra',
        exporters: [
          new MastraStorageExporter(), // Persists observability events to Mastra Storage
          new MastraPlatformExporter(), // Sends observability events to Mastra platform (if MASTRA_PLATFORM_ACCESS_TOKEN is set)
        ],
        spanOutputProcessors: [
          new SensitiveDataFilter(), // Redacts sensitive data like passwords, tokens, keys
        ],
      },
    },
  }),
})
```

此配置包含 `MastraStorageExporter`、`MastraPlatformExporter` 和 `SensitiveDataFilter` 处理器。完整配置选项请参阅[可观测性跟踪文档](/docs/observability/tracing/overview)。

#### 迁移后（v1 自定义配置） {/* #after-v1-with-custom-configuration */}

如果需要使用特定的导出器（例如 OTLP），请安装相应的导出器包并进行配置：

```bash npm2yarn
npm install @mastra/otel-exporter@latest @opentelemetry/exporter-trace-otlp-proto
```

```typescript
import { Mastra } from '@mastra/core'
import { Observability } from '@mastra/observability'
import { OtelExporter } from '@mastra/otel-exporter'

export const mastra = new Mastra({
  observability: new Observability({
    configs: {
      production: {
        serviceName: 'my-app',
        sampling: { type: 'always' },
        exporters: [
          new OtelExporter({
            provider: {
              custom: {
                endpoint: 'http://localhost:4318/v1/traces',
                protocol: 'http/protobuf',
              },
            },
          }),
        ],
      },
    },
  }),
})
```

主要变化：

1. 安装 `@mastra/observability` 包
2. 将 `telemetry:` 替换为 `observability: new Observability()`
3. 在 `configs:` 中显式配置 `MastraStorageExporter`、`MastraPlatformExporter` 和 `SensitiveDataFilter`
4. 将字符串形式的导出类型（`'otlp'`）改为导出器类实例（`new OtelExporter()`）

### 从 AI 追踪迁移 {/* #from-ai-tracing */}

如果您已升级到作为过渡方案的 AI 追踪系统，需要安装新包并显式配置。

**迁移前（AI 追踪）：**

```typescript
import { Mastra } from '@mastra/core'

export const mastra = new Mastra({
  observability: {
    default: { enabled: true },
  },
})
```

**迁移后（v1 可观测性）：**

```typescript
import { Mastra } from '@mastra/core'
import {
  Observability,
  MastraStorageExporter,
  MastraPlatformExporter,
  SensitiveDataFilter,
} from '@mastra/observability'

export const mastra = new Mastra({
  observability: new Observability({
    configs: {
      default: {
        serviceName: 'mastra',
        exporters: [new MastraStorageExporter(), new MastraPlatformExporter()],
        spanOutputProcessors: [new SensitiveDataFilter()],
      },
    },
  }),
})
```

主要变化：

1. 安装 `@mastra/observability` 包
2. 从 `@mastra/observability` 导入 `Observability`、导出器和处理器
3. 在 `configs` 中显式配置 `MastraStorageExporter`、`MastraPlatformExporter` 和 `SensitiveDataFilter`

## 变更内容 {/* #changed */}

### 包的导入路径 {/* #package-import-path */}

可观测性功能已移至独立的 `@mastra/observability` 包。

要迁移，请安装包并更新导入语句：

```bash npm2yarn
npm install @mastra/observability@latest
```

```diff
- import { Tracing } from '@mastra/core/observability';
+ import { Observability } from '@mastra/observability';
```

### 注册表配置 {/* #registry-configuration */}

可观测性注册表现在通过带有显式配置的 `Observability` 类实例进行配置，不再使用普通对象。

迁移时，请使用 `new Observability()` 显式配置导出器和处理器。

```diff
+ import {
+   Observability,
+   MastraStorageExporter,
+   MastraPlatformExporter,
+   SensitiveDataFilter,
+ } from '@mastra/observability';

  export const mastra = new Mastra({
-   observability: {
-     default: { enabled: true },
-   },
+   observability: new Observability({
+     configs: {
+       default: {
+         serviceName: 'mastra',
+         exporters: [new MastraStorageExporter(), new MastraPlatformExporter()],
+         spanOutputProcessors: [new SensitiveDataFilter()],
+       },
+     },
+   }),
  });
```

### 配置属性从 `processors` 改为 `spanOutputProcessors` {/* #configuration-property-processors-to-spanoutputprocessors */}

span 处理器的配置属性已从 `processors` 重命名为 `spanOutputProcessors`。

迁移时，请在配置对象中重命名此属性。

```diff
+ import { SensitiveDataFilter } from '@mastra/observability';

  export const mastra = new Mastra({
    observability: new Observability({
      configs: {
        production: {
          serviceName: 'my-app',
-         processors: [new SensitiveDataFilter()],
+         spanOutputProcessors: [new SensitiveDataFilter()],
          exporters: [...],
        },
      },
    }),
  });
```

### 导出器方法从 `exportEvent` 改为 `exportTracingEvent` {/* #exporter-method-exportevent-to-exporttracingevent */}

如果您实现了自定义导出器，其导出方法已从 `exportEvent` 重命名为 `exportTracingEvent`。

迁移时，请更新自定义导出器中的方法实现。

```diff
  export class MyExporter implements ObservabilityExporter {
-   exportEvent(event: TracingEvent): void {
+   exportTracingEvent(event: TracingEvent): void {
      // export logic
    }
  }
```

## 已删除 {/* #removed */}

### 基于 OTEL 的 `telemetry` 配置 {/* #otel-based-telemetry-configuration */}

0.x 中基于 OTEL 的 `telemetry` 配置已被移除。旧系统中的 `serviceName`、`sampling.type` 和 `export.type` 属性不再受支持。

迁移时，请按照上文“从基于 OTEL 的遥测迁移”一节操作。详细配置选项请参阅[可观测性跟踪文档](/docs/observability/tracing/overview)。

### 自定义检测文件 {/* #custom-instrumentation-files */}

系统不再自动检测 `/mastra` 中扩展名为 `.ts`、`.js` 或 `.mjs` 的检测文件，也不再支持通过独立文件添加自定义检测逻辑。

迁移时，请使用内置导出器系统，或通过 `ObservabilityExporter` 接口实现自定义导出器。

### `instrumentation.mjs` 文件 {/* #instrumentationmjs-files */}

如果您此前使用 `instrumentation.mjs` 文件初始化 OpenTelemetry 检测逻辑（在 AWS Lambda 等部署环境中较为常见），现在不再需要这些文件。新的可观测性系统直接在 Mastra 实例中配置。

#### 迁移前（0.x） {/* #before-0x */}

此前需要一个检测文件：

```javascript
// instrumentation.mjs
import { NodeSDK } from '@opentelemetry/sdk-node'
// ... OTEL setup
```

启动进程时还必须导入该文件：

```bash
node --import=./.mastra/output/instrumentation.mjs --env-file=".env" .mastra/output/index.mjs
```

#### 迁移后（v1） {/* #after-v1 */}

只需删除 `instrumentation.mjs` 文件，并在 Mastra 实例中配置可观测性：

```typescript
// src/mastra/index.ts
import {
  Observability,
  MastraStorageExporter,
  MastraPlatformExporter,
  SensitiveDataFilter,
} from '@mastra/observability'

export const mastra = new Mastra({
  observability: new Observability({
    configs: {
      default: {
        serviceName: 'mastra',
        exporters: [new MastraStorageExporter(), new MastraPlatformExporter()],
        spanOutputProcessors: [new SensitiveDataFilter()],
      },
    },
  }),
})
```

正常启动进程即可，无需使用 `--import` 标志：

```bash
node --env-file=".env" .mastra/output/index.mjs
```

不再需要独立的检测文件或特殊的启动标志。

| LangWatch | \<coming soon> | - | - |

### 安装 {/* #installation */}

**专用导出器**（Arize、Braintrust、Langfuse、LangSmith）：

```bash npm2yarn
npm install @mastra/[exporter-name]-exporter
```

**OpenTelemetry 导出器**（Dash0、Laminar、New Relic、SigNoz、Traceloop）：

```bash npm2yarn
npm install @mastra/otel-exporter@latest
```

还需安装该 Provider 所需的协议包（请参阅 [OTEL 指南](/integrations/observability/opentelemetry#exporter)）。
