# Workflow程

旧的Workflow程功能已被删除。

## 改变了 {/* #changed */}

### `getWorkflows`到`listWorkflows` {/* #getworkflows-to-listworkflows */}

这`mastra.getWorkflows()` method has been renamed to `mastra.listWorkflows()`. This change aligns with the naming convention used across the API where plural getter methods use the `list`前缀。

要迁移，请将所有调用替换为`mastra.getWorkflows()` with `mastra.listWorkflows()`.

```diff
- const workflows = mastra.getWorkflows();
+ const workflows = mastra.listWorkflows();
```

您可以使用 Mastra 的 codemod CLI 自动更新导入：

```bash
npx @mastra/codemod@latest v1/mastra-plural-apis .
```

### `RuntimeContext`到`RequestContext` in step context {/* #runtimecontext-to-requestcontext-in-step-context */}

参数名称`runtimeContext` has been changed to `requestContext` in workflow step execution context. This change aligns with the global rename for clarity.

要迁移，请更新引用`runtimeContext` to `requestContext` in step execution functions.

```diff
  createStep({
-   execute: async ({ runtimeContext } ) => {
-     const userTier = context.runtimeContext.get('userTier');
+   execute: async ({ requestContext } ) => {
+     const userTier = requestContext.get('userTier');
      return { result: userTier };
    },
  });
```

### `createRunAsync`到`createRun` {/* #createrunasync-to-createrun */}

这`createRunAsync()` method has been renamed to `createRun()`. This change simplifies the API by removing the redundant "Async" suffix since all run creation is asynchronous.

要迁移，请重命名方法调用`createRunAsync` to `createRun`.

```diff
- await workflow.createRunAsync({ input: { ... } });
+ await workflow.createRun({ input: { ... } });
```

### `runCount`到`retryCount` (deprecated) {/* #runcount-to-retrycount-deprecated */}

这`runCount` parameter has been deprecated in favor of `retryCount` in workflow step execution. The new name identifies the value as the number of retries. The old `runCount` still works but shows deprecation warnings.

要迁移，请重命名`runCount` to `retryCount` in step execution functions.

```diff
  createStep({
    execute: async (inputData, context) => {
-     console.log(`Step run ${context.runCount} times`);
+     console.log(`Step retry count: ${context.retryCount}`);
    },
  });
```

### `getInitData`返回未知 {/* #getinitdata-returns-unknown */}

这`getInitData` function in the execute function now returns unknown instead of any. You'll need to type it yourself.
To migrate, change `getInitData()` into `getInitData<any>()`

```diff
  createStep({
    execute: async ({ getInitData }) => {
-     const initData = getInitData();
-     if (initData.key === 'value') {}
+     const initData = getInitData<any>();
+     if (initData.key === 'value') {}
    },
  });
```

### 默认情况下验证输入 {/* #inputs-are-validated-by-default */}

以前，默认情况下不会验证输入。这[`validateInputs`](/reference/workflows/workflow#constructor-parameters) flag determines whether to validate the workflow inputs or not. This boolean has been flipped to `true`. If you want the old behavior or have workflows whose schemas don't need to be validated, set `validateInputs: false`.

```diff
createWorkflow({
+  options: {
+    validateInputs: false
+  }
})
```

### 步`suspendPayload` validation {/* #step-suspendpayload-validation */}

步`suspendPayload` is now validated for steps that have a `suspendSchema` defined. This also uses the `validateInputs` flag to determine whether to validate the `suspendPayload` or not.

```diff
  createStep({
    id: "suspend-resume-step",
    // ... other step properties
    suspendSchema: z.object({
      reason: z.string(),
      otherReason: z.string()
    }),
    execute: async ({ suspend, resumeData}) => {
      if (!resumeData) {
-       return suspend({ reason: "Suspension reason" }); // Missing otherReason
+       return suspend({ reason: "Suspension reason", otherReason: "Other reason" });
      }
    },
  });
```

### 分支结果字段现在是可选的 {/* #branch-result-fields-are-now-optional */}

这`.branch()` method now returns a schema where all branch output fields are optional. This reflects the runtime behavior where each branch only executes if its condition is truthy, so outputs from any branch may be undefined.

要迁移，请更新使用分支输出的所有代码以处理可选值。

```diff
  const workflow = createWorkflow({...})
    .branch([
      [condition1, stepA],  // outputSchema: { result: z.string() }
      [condition2, stepB],  // outputSchema: { data: z.number() }
    ])
-   // Previously: stepA.result typed as string, stepB.data typed as number
+   // Now: stepA.result typed as string | undefined, stepB.data typed as number | undefined
    .then(nextStep);
```

如果您的代码依赖于非可选类型，请在访问分支输出时添加运行时检查或提供默认值。

### `writableStream`到`outputWriter` in `Run.start()` & `Run.timeTravel()` {/* #writablestream-to-outputwriter-in-runstart--runtimetravel */}

这`writableStream` parameter in `Run.start()` and `Run.timeTravel()` has been replaced with `outputWriter`. Instead of passing a `WritableStream`, you now pass an async callback function that receives each workflow event chunk directly.

此更改简化了 API - 而不是创建一个`WritableStream` wrapper, you handle chunks directly in the callback.

**例子：**&#x5C06;Workflow事件流式传输到 HTTP 响应 (SSE)：

```diff
  const run = await workflow.createRun();

- const stream = new WritableStream({
-   write(chunk) {
-     response.write(`data: ${JSON.stringify(chunk)}\n\n`);
-   }
- });
- await run.start({ inputData, writableStream: stream });

+ await run.start({
+   inputData,
+   outputWriter: async (chunk) => {
+     response.write(`data: ${JSON.stringify(chunk)}\n\n`);
+   },
+ });
```

：：：笔记

这`writer` parameter passed to step `execute` functions isn't affected by this change. It remains a `ToolStream` that extends `WritableStream<unknown>` and provides `.write()` and `.custom()` methods:

```ts
createStep({
  id: 'my-step',
  execute: async ({ writer }) => {
    // This API is unchanged
    await writer.write({ data: 'some output' })
    await writer.custom({ type: 'custom-event', payload: {} })
  },
})
```

### `setState()`现在是异步的并且传递的数据经过验证 {/* #setstate-is-now-async-and-the-data-passed-is-validated */}

这`setState()` function is now async and validates data against the step's `stateSchema` when `validateInputs` is enabled. Pass only the fields you want to update, without spreading the previous state (`...state`).

要迁移，请更新`setState()` function to be async.

```diff
- setState({ ...state, sharedCounter: state.sharedCounter + 1 });
+ await setState({ sharedCounter: state.sharedCounter + 1 });
+ // await setState({ ...state, sharedCounter: state.sharedCounter + 1 });
+ // this also works, as the previous state spread remains supported
```

## 已删除 {/* #removed */}

### `streamVNext`, `resumeStreamVNext`, and `observeStreamVNext` methods {/* #streamvnext-resumestreamvnext-and-observestreamvnext-methods */}

实验的`streamVNext()`, `resumeStreamVNext()`, and `observeStreamVNext()` methods have been removed. These methods are now the standard implementation with updated event structures and return types.

要迁移，请使用标准`stream()`, `resumeStream()`, and `observeStream()` methods. Update event type checks to use workflow-prefixed names and access stream properties directly.

看[`Run.stream()`](/reference/streaming/workflows/stream), [`Run.resumeStream()`](/reference/streaming/workflows/resumeStream), and [`Run.observeStream()`](/reference/streaming/workflows/observeStream) for details.

### `suspend()`和`setState()` aren't available in step condition functions parameters {/* #suspend-and-setstate-arent-available-in-step-condition-functions-parameters */}

这`suspend()` and `setState()` functions aren't available in step condition function parameters.

要迁移，请使用`suspend()` function in the step execute function instead.

```diff
.dowhile(step, async ({ suspend, state, setState }) => {
- setState({...state, updatedState: "updated state"})
- await suspend({ reason: "Suspension reason" });
+ // Use the suspend/setState in the step execute function instead
});
```

这对于`dountil` and `branch` condition functions parameters.

### 旧Workflow程导出 {/* #legacy-workflows-export */}

这`./workflows/legacy` export path has been removed from `@mastra/core`. Legacy workflows are no longer supported.

要进行迁移，请使用新的Workflow程 API。不存在从遗留Workflow程直接迁移的路径。

```diff
- import { LegacyWorkflow } from '@mastra/core/workflows/legacy';
+ // Legacy workflows are no longer supported
+ // Migrate to the new workflow API
```

### `pipeThrough`和`pipeTo` methods from `WorkflowRunOutput` {/* #pipethrough-and-pipeto-methods-from-workflowrunoutput */}

这`pipeThrough()` and `pipeTo()` methods on `WorkflowRunOutput` are deprecated. These methods still work but show console warnings.

要迁移，请使用`fullStream` property instead of calling methods directly on the run output.

```diff
  const run = await workflow.createRun({ input: { ... } });
- await run.pipeTo(writableStream);
- const transformed = run.pipeThrough(transformStream);
+ await run.fullStream.pipeTo(writableStream);
+ const transformed = run.fullStream.pipeThrough(transformStream);
```

### 观看事件API {/* #watch-events-api */}

旧版监视事件已被删除并整合到 v2 事件 API 上。这`watch()` method and related watch endpoints are no longer available.

要迁移，请使用Workflow事件 API 或流式传输而不是监视事件。

```diff
- const workflow = mastraClient.getWorkflow('my-workflow');
- const run = await workflow.createRun();
- await run.watch((event) => {
-   console.log('Step completed:', event);
- });

+ const workflow = mastraClient.getWorkflow('my-workflow');
+ const run = await workflow.createRun();
+ const stream = await run.stream({ inputData: { ... } });
+ for await (const chunk of stream) {
+   console.log('Step completed:', chunk);
+ }
```

### `waitForEvent`应用程序编程接口 {/* #waitforevent-api */}

这`waitForEvent` API has been removed from workflows. Use the suspend/resume API instead.

要迁移，请使用挂起/恢复 API 等待Workflow执行里程碑。

```diff
- workflow.waitForEvent('step-complete', step1).commit();
+ workflow.then(step1).commit();
+ // Use suspend/resume API instead, in step1 execute function
createStep({
- execute: async (inputData, context) => {
-  // ... execution logic
- }
+ execute: async (inputData, context) => {
+   if (!context.resumeData) {
+     return context.suspend({})
+   }
+ }
});
+
+ // after workflow is suspended, you can resume it
+ const result = await run.start({ inputData: { ... } });
+ if (result.status === 'suspended') {
+   const resumedResult = await run.resume({
+     resumeData: {
+       event: 'step-complete',
+     },
+     step: 'step1',
+   });
+ }
```

### `sendEvent`应用程序编程接口 {/* #sendevent-api */}

这`sendEvent` API has been removed from workflows. Use the suspend/resume API instead.
