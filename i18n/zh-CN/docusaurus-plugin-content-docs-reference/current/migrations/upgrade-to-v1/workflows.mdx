# Workflow

旧版 Workflow 功能已移除。

## 变更 {/* #changed */}

### `getWorkflows` 更名为 `listWorkflows` {/* #getworkflows-to-listworkflows */}

`mastra.getWorkflows()` 已更名为 `mastra.listWorkflows()`。这与 API 中返回多个对象的方法统一使用 `list` 前缀的命名约定一致。

迁移时，将所有 `mastra.getWorkflows()` 调用替换为 `mastra.listWorkflows()`。

```diff
- const workflows = mastra.getWorkflows();
+ const workflows = mastra.listWorkflows();
```

:::tip[代码迁移]

可以使用 Mastra 的 codemod CLI 自动更新导入：

```bash
npx @mastra/codemod@latest v1/mastra-plural-apis .
```

:::

### 步骤上下文中的 `RuntimeContext` 更名为 `RequestContext` {/* #runtimecontext-to-requestcontext-in-step-context */}

Workflow 步骤执行上下文中的参数名已从 `runtimeContext` 改为 `requestContext`，与全局更名保持一致，含义也更明确。

迁移时，将步骤执行函数中对 `runtimeContext` 的引用改为 `requestContext`。

```diff
  createStep({
-   execute: async ({ runtimeContext } ) => {
-     const userTier = context.runtimeContext.get('userTier');
+   execute: async ({ requestContext } ) => {
+     const userTier = requestContext.get('userTier');
      return { result: userTier };
    },
  });
```

### `createRunAsync` 更名为 `createRun` {/* #createrunasync-to-createrun */}

`createRunAsync()` 已更名为 `createRun()`。由于创建运行实例始终是异步操作，移除多余的「Async」后缀使 API 更简洁。

迁移时，将方法调用中的 `createRunAsync` 改为 `createRun`。

```diff
- await workflow.createRunAsync({ input: { ... } });
+ await workflow.createRun({ input: { ... } });
```

### `runCount` 更名为 `retryCount`（已弃用旧名称） {/* #runcount-to-retrycount-deprecated */}

Workflow 步骤执行中的 `runCount` 参数已弃用，改用 `retryCount`。新名称明确表示该值是重试次数。旧的 `runCount` 仍可使用，但会显示弃用警告。

迁移时，将步骤执行函数中的 `runCount` 改为 `retryCount`。

```diff
  createStep({
    execute: async (inputData, context) => {
-     console.log(`Step run ${context.runCount} times`);
+     console.log(`Step retry count: ${context.retryCount}`);
    },
  });
```

### `getInitData` 返回 `unknown` {/* #getinitdata-returns-unknown */}

执行函数中的 `getInitData` 现在返回 `unknown`，而非 `any`。你需要自行指定类型。
迁移时，将 `getInitData()` 改为 `getInitData<any>()`。

```diff
  createStep({
    execute: async ({ getInitData }) => {
-     const initData = getInitData();
-     if (initData.key === 'value') {}
+     const initData = getInitData<any>();
+     if (initData.key === 'value') {}
    },
  });
```

### 默认验证输入 {/* #inputs-are-validated-by-default */}

以前默认不验证输入。[`validateInputs`](/reference/workflows/workflow#constructor-parameters) 标志决定是否验证 Workflow 输入，其默认值现已改为 `true`。如果需要沿用旧行为，或某些 Workflow 的 schema 无需验证，请设置 `validateInputs: false`。

```diff
createWorkflow({
+  options: {
+    validateInputs: false
+  }
})
```

### 验证步骤的 `suspendPayload` {/* #step-suspendpayload-validation */}

对于定义了 `suspendSchema` 的步骤，现在会验证其 `suspendPayload`。是否执行此验证同样由 `validateInputs` 标志决定。

```diff
  createStep({
    id: "suspend-resume-step",
    // ... other step properties
    suspendSchema: z.object({
      reason: z.string(),
      otherReason: z.string()
    }),
    execute: async ({ suspend, resumeData}) => {
      if (!resumeData) {
-       return suspend({ reason: "Suspension reason" }); // Missing otherReason
+       return suspend({ reason: "Suspension reason", otherReason: "Other reason" });
      }
    },
  });
```

### 分支结果字段现为可选字段 {/* #branch-result-fields-are-now-optional */}

`.branch()` 现在返回的 schema 中，所有分支输出字段都是可选的。这与运行时行为一致：只有条件为真时，对应分支才会执行，因此任一分支的输出都可能是 `undefined`。

迁移时，更新所有使用分支输出的代码，使其能够处理可选值。

```diff
  const workflow = createWorkflow({...})
    .branch([
      [condition1, stepA],  // outputSchema: { result: z.string() }
      [condition2, stepB],  // outputSchema: { data: z.number() }
    ])
-   // Previously: stepA.result typed as string, stepB.data typed as number
+   // Now: stepA.result typed as string | undefined, stepB.data typed as number | undefined
    .then(nextStep);
```

如果代码依赖非可选类型，请在访问分支输出时添加运行时检查或提供默认值。

### `Run.start()` 和 `Run.timeTravel()` 中的 `writableStream` 改为 `outputWriter` {/* #writablestream-to-outputwriter-in-runstart--runtimetravel */}

`Run.start()` 和 `Run.timeTravel()` 中的 `writableStream` 参数已替换为 `outputWriter`。现在需要传入异步回调函数，由它直接接收每个 Workflow 事件数据块，而不再传入 `WritableStream`。

这样无需创建 `WritableStream` 包装器，直接在回调函数中处理数据块即可，API 因此更简洁。

**示例：**将 Workflow 事件以流式方式发送到 HTTP 响应（SSE）：

```diff
  const run = await workflow.createRun();

- const stream = new WritableStream({
-   write(chunk) {
-     response.write(`data: ${JSON.stringify(chunk)}\n\n`);
-   }
- });
- await run.start({ inputData, writableStream: stream });

+ await run.start({
+   inputData,
+   outputWriter: async (chunk) => {
+     response.write(`data: ${JSON.stringify(chunk)}\n\n`);
+   },
+ });
```

:::note

传给步骤 `execute` 函数的 `writer` 参数不受此变更影响。它仍是扩展了 `WritableStream<unknown>` 的 `ToolStream`，并提供 `.write()` 和 `.custom()` 方法：

```ts
createStep({
  id: 'my-step',
  execute: async ({ writer }) => {
    // This API is unchanged
    await writer.write({ data: 'some output' })
    await writer.custom({ type: 'custom-event', payload: {} })
  },
})
```

:::

### `setState()` 现为异步函数，传入数据也会经过验证 {/* #setstate-is-now-async-and-the-data-passed-is-validated */}

`setState()` 现在是异步函数。启用 `validateInputs` 时，传入的数据会根据步骤的 `stateSchema` 进行验证。只需传入要更新的字段，无需展开先前的状态（`...state`）。

迁移时，以异步方式调用 `setState()`。

```diff
- setState({ ...state, sharedCounter: state.sharedCounter + 1 });
+ await setState({ sharedCounter: state.sharedCounter + 1 });
+ // await setState({ ...state, sharedCounter: state.sharedCounter + 1 });
+ // this also works, as the previous state spread remains supported
```

## 已删除 {/* #removed */}

### `streamVNext`、`resumeStreamVNext` 和 `observeStreamVNext` 方法 {/* #streamvnext-resumestreamvnext-and-observestreamvnext-methods */}

实验性的 `streamVNext()`、`resumeStreamVNext()` 和 `observeStreamVNext()` 方法已移除。它们现在已成为标准实现，事件结构和返回类型也已更新。

迁移时，使用标准的 `stream()`、`resumeStream()` 和 `observeStream()` 方法。更新事件类型检查，使用带 Workflow 前缀的名称，并直接访问流的属性。

详情请参阅 [`Run.stream()`](/reference/streaming/workflows/stream)、[`Run.resumeStream()`](/reference/streaming/workflows/resumeStream) 和 [`Run.observeStream()`](/reference/streaming/workflows/observeStream)。

### 步骤条件函数的参数中不再提供 `suspend()` 和 `setState()` {/* #suspend-and-setstate-arent-available-in-step-condition-functions-parameters */}

步骤条件函数的参数中不再提供 `suspend()` 和 `setState()`。

迁移时，改为在步骤的执行函数中使用 `suspend()`。

```diff
.dowhile(step, async ({ suspend, state, setState }) => {
- setState({...state, updatedState: "updated state"})
- await suspend({ reason: "Suspension reason" });
+ // Use the suspend/setState in the step execute function instead
});
```

`dountil` 和 `branch` 的条件函数参数也一样。

### 旧版 Workflow 导出路径 {/* #legacy-workflows-export */}

`@mastra/core` 中的 `./workflows/legacy` 导出路径已移除。旧版 Workflow 不再受支持。

迁移时，请使用新的 Workflow API。旧版 Workflow 没有直接迁移路径。

```diff
- import { LegacyWorkflow } from '@mastra/core/workflows/legacy';
+ // Legacy workflows are no longer supported
+ // Migrate to the new workflow API
```

### `WorkflowRunOutput` 的 `pipeThrough` 和 `pipeTo` 方法 {/* #pipethrough-and-pipeto-methods-from-workflowrunoutput */}

`WorkflowRunOutput` 上的 `pipeThrough()` 和 `pipeTo()` 方法已弃用。它们仍可使用，但会在控制台显示警告。

迁移时，使用 `fullStream` 属性，不要直接在运行结果上调用这些方法。

```diff
  const run = await workflow.createRun({ input: { ... } });
- await run.pipeTo(writableStream);
- const transformed = run.pipeThrough(transformStream);
+ await run.fullStream.pipeTo(writableStream);
+ const transformed = run.fullStream.pipeThrough(transformStream);
```

### watch 事件 API {/* #watch-events-api */}

旧版 watch 事件已移除，相关功能统一由 v2 事件 API 提供。`watch()` 方法及相关 watch 端点不再可用。

迁移时，使用 Workflow 事件 API 或流式传输代替 watch 事件。

```diff
- const workflow = mastraClient.getWorkflow('my-workflow');
- const run = await workflow.createRun();
- await run.watch((event) => {
-   console.log('Step completed:', event);
- });

+ const workflow = mastraClient.getWorkflow('my-workflow');
+ const run = await workflow.createRun();
+ const stream = await run.stream({ inputData: { ... } });
+ for await (const chunk of stream) {
+   console.log('Step completed:', chunk);
+ }
```

### `waitForEvent` API {/* #waitforevent-api */}

Workflow 中的 `waitForEvent` API 已移除。请改用 suspend/resume API。

迁移时，使用 suspend/resume API 等待 Workflow 执行到指定节点。

```diff
- workflow.waitForEvent('step-complete', step1).commit();
+ workflow.then(step1).commit();
+ // Use suspend/resume API instead, in step1 execute function
createStep({
- execute: async (inputData, context) => {
-  // ... execution logic
- }
+ execute: async (inputData, context) => {
+   if (!context.resumeData) {
+     return context.suspend({})
+   }
+ }
});
+
+ // after workflow is suspended, you can resume it
+ const result = await run.start({ inputData: { ... } });
+ if (result.status === 'suspended') {
+   const resumedResult = await run.resume({
+     resumeData: {
+       event: 'step-complete',
+     },
+     step: 'step1',
+   });
+ }
```

### `sendEvent` API {/* #sendevent-api */}

Workflow 中的 `sendEvent` API 已移除。请改用 suspend/resume API。
