---
title: "迁移指南模板"
description: "使用此迁移页面模板记录 v1 破坏性变更，包括包版本、变更前后示例、迁移步骤和验证指引。"
---

该模板是有关如何填充各个迁移指南的样式指南。使用此指南作为如何构建此目录中的文件的指南。你不能偏离这个结构。

遵循`.cursor/rules/writing-documentation.mdc`有关如何撰写散文内容的说明。

找到需要记录的所有更改后，您应该将它们分为两大组：“已更改”和“已删除”。

例子：

```md
## Changed

## Removed
```

所有更改都必须在这两个部分下进行。

每个更改（无论是“更改”还是“删除”）都应该是 h3 标题。您必须严格遵循该格式。

例子：

```md
## Changed

### `oldFunction` to `newFunction`
```

现在标题已经就位，您需要为每个更改遵循精确的结构。你不能偏离这个结构。

用一两句话简要描述变化。接下来用一句话解释一下为什么要改变。

每个更改的第三个元素必须是解释如何将现有代码迁移到新版本。保持简洁但清晰，尽量不要删减太多信息。之后必须使用“diff”语法提供代码块。在代码块内，您需要显示需要使用该 diff 语法进行更改的代码的“之前”和“之后”示例。

例子：

````md
## Changed

### `oldFunction` to `newFunction`

The `oldFunction` has been renamed to `newFunction`. This change improves clarity and consistency across the API.

To migrate, replace all instances of `oldFunction` with `newFunction` in your codebase.

```diff
- const result = oldFunction(args);
+ const result = newFunction(args);
```
````

如果迁移需要的步骤比查找和替换更多，您可以在代码块之前添加其他说明。如果需要多个步骤，请使用编号列表清楚地解释每个步骤。
