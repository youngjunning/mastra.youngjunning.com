# 升级到 Mastra v1

:::注意\[更新至最新0.x版本]
在升级到 v1 之前，请确保您已更新到 Mastra 的最新 0.x 版本。遵循[upgrade to latest 0.x guide](https://mastra.ai/guides/v0/migrations/upgrade-to-latest-0x)首先，然后返回此处完成 v1 迁移。
:::

Mastra v1 于 2026 年 1 月发布。我们建议使用 Mastra v1 启动任何新项目，或升级现有项目以继续接收更新和支持。

本指南涵盖从 Mastra 0.x 升级到 v1.0 时的重大更改。迁移按包和功能区域组织，以帮助您系统地更新代码库。

:::提示\[需要帮助吗？]
需要迁移方面的帮助吗？加入我们的[Discord community](https://discord.gg/mastra-ai) to ask questions.
:::

:::警告\[来自 Mastra Cloud？]
旧版 Mastra Cloud 产品已被替换为[Mastra platform](/docs/mastra-platform/overview), which splits hosting into two separate products: **Studio** (visual environment, observability) and **Server** (production API). Because old Mastra Cloud access tokens don't work with Mastra platform, create new ones with `mastra auth tokens create`.

如果您升级到 v1 软件包而不迁移您的`telemetry:` config to `observability:` and creating a Studio project, observability data will stop flowing. Follow the [Mastra Cloud migration guide](/reference/migrations/mastra-cloud) end to end.
:::

## 迁移策略 {/* #migration-strategy */}

### 将所有 Mastra 软件包更新为`latest` tag {/* #update-all-mastra-packages-to-latest-tag */}

使用包管理器更新项目的版本。更新**all** Mastra packages together to ensure compatibility (all `@mastra/*` packages and `mastra`).

以下是更新最常用软件包的方法：

```bash npm2yarn
npm install @mastra/core@latest @mastra/loggers@latest @mastra/memory@latest mastra@latest
```

安装任何其他 Mastra 软件包`@latest` tag and you'll get the latest v1 version available. Be sure to update all Mastra packages (especially if you're in a monorepo) to avoid version mismatches.

### 更新 Node.js 版本 {/* #update-nodejs-version */}

Mastra v1 需要 Node.js**22.13.0** or higher. Update your development and production environments accordingly.

### 完成迁移清单 {/* #go-through-migration-checklist */}

工作通过[migration checklist](#migration-checklist) below to update your codebase. Each item links to a detailed guide for that specific change.

:::注意\[代码模组]

我们准备了自动化[codemods](https://github.com/mastra-ai/mastra/tree/main/packages/codemod) for you. If you want, you can run all v1 codemods at once:

```bash
npx @mastra/codemod@latest v1
```

:::

:::注意\[需要迁移数据库]

如果您使用 PostgreSQL 或 LibSQL 存储，则需要运行数据库迁移。请参阅[Storage migration guide](/reference/migrations/upgrade-to-v1/storage#database-migration) for details.

:::

## 按地区划分的重大变化 {/* #breaking-changes-by-area */}

* **[马斯特拉级](/reference/migrations/upgrade-to-v1/mastra)**- 进口重组和财产准入变化。
* **[Agent类](/reference/migrations/upgrade-to-v1/agent)**- 语音方法移至命名空间和流 API 更新。
* **[Tool](/reference/migrations/upgrade-to-v1/tools)**- CreateTool 执行签名更改为单独的输入和上下文。
* **[Workflow程](/reference/migrations/upgrade-to-v1/workflows)**- 函数名称更改并删除了旧功能。
* **[记忆](/reference/migrations/upgrade-to-v1/memory)**- 配置现在需要显式参数并更改默认值。
* **[贮存](/reference/migrations/upgrade-to-v1/storage)**- 分页标准化，方法重命名为列表模式。
* **[向量](/reference/migrations/upgrade-to-v1/vectors)**- 矢量存储方法重命名为列表模式。
* **[抹布](/reference/migrations/upgrade-to-v1/rag)**- 为了清晰起见，更新了参数命名。
* **[MCP](/reference/migrations/upgrade-to-v1/mcp)**- 重新组织了Tool上下文并删除了已弃用的客户端类。
* **[追踪](/reference/migrations/upgrade-to-v1/tracing)**- OTEL 遥测技术被专用观测包和导出器取代。
* **[评估和记分员](/reference/migrations/upgrade-to-v1/evals)**- Scorers API 与新的命名约定相结合。
* **[命令行界面](/reference/migrations/upgrade-to-v1/cli)**- 删除命令和标志以简化界面。
* **[部署](/reference/migrations/upgrade-to-v1/deployment)**- CloudflareDeployer 配置更新为使用标准 wrangler.json 属性名称。
* **[客户端 SDK](/reference/migrations/upgrade-to-v1/client)**- 为保持一致性而重命名的类型和实用程序。
* **[语音套餐](/reference/migrations/upgrade-to-v1/voice)**- 包从语音重命名为语音。

## 迁移清单 {/* #migration-checklist */}

按顺序完成此清单，从影响大多数应用程序的高影响力更改开始。

:::注意\[代码模组]

我们准备了自动化[codemods](https://github.com/mastra-ai/mastra/tree/main/packages/codemod) for you. Throughout the migration guide you'll find instructions on how to use them for specific changes.

如果需要，您可以一次运行所有 v1 codemod：

```bash
npx @mastra/codemod@latest v1
```

:::

### 高影响力的变化 {/* #high-impact-changes */}

* 更新`createTool` tool signatures to `(inputData, context)` format - [Tools](/reference/migrations/upgrade-to-v1/tools)
* 重组`@mastra/core` imports to use subpath imports - [Mastra Class](/reference/migrations/upgrade-to-v1/mastra)
* 更新分页自`offset/limit` to `page/perPage` - [Storage](/reference/migrations/upgrade-to-v1/storage)
* 安装`@mastra/observability` and wrap configuration with `new Observability()` - [Tracing](/reference/migrations/upgrade-to-v1/tracing)
* 迁移自`telemetry:` to `observability:` configuration (if upgrading from 0.x OTEL) - [Tracing](/reference/migrations/upgrade-to-v1/tracing)

### 中等影响的变化 {/* #medium-impact-changes */}

* 重命名`RuntimeContext` to `RequestContext` throughout codebase - [Agent Class](/reference/migrations/upgrade-to-v1/agent), [Tools](/reference/migrations/upgrade-to-v1/tools), [Workflows](/reference/migrations/upgrade-to-v1/workflows)
* 更新存储方法`get*` to `list*` pattern - [Storage](/reference/migrations/upgrade-to-v1/storage)
* 用 getter 方法替换直接属性访问 -[Mastra Class](/reference/migrations/upgrade-to-v1/mastra), [Agent Class](/reference/migrations/upgrade-to-v1/agent)
* 如果依赖默认值则更新内存范围`thread` scope - [Memory](/reference/migrations/upgrade-to-v1/memory)
* 更新向量存储调用以按名称使用参数 -[Storage](/reference/migrations/upgrade-to-v1/storage)
* 消除`format` parameter from agent methods - [Agent Class](/reference/migrations/upgrade-to-v1/agent)
* 更新要使用的语音方法`agent.voice` namespace - [Agent Class](/reference/migrations/upgrade-to-v1/agent)
* 重命名配置属性`processors` to `spanOutputProcessors` (if using custom processors) - [Tracing](/reference/migrations/upgrade-to-v1/tracing)

### 影响较小的变更 {/* #low-impact-changes */}

* 重命名`keepSeparator` to `separatorPosition` in chunk options - [RAG](/reference/migrations/upgrade-to-v1/rag)
* 重命名`createRunAsync` to `createRun` - [Workflows](/reference/migrations/upgrade-to-v1/workflows)
* 更新语音包名称`@mastra/speech-*` to `@mastra/voice-*` - [Voice Packages](/reference/migrations/upgrade-to-v1/voice)
* 更新记分器方法：`runExperiment` → `runEvals`, `getScorerByName` → `getScorerById` - [Evals & Scorers](/reference/migrations/upgrade-to-v1/evals)
* 删除已弃用的 CLI 标志 -[CLI](/reference/migrations/upgrade-to-v1/cli)
* 更新客户端 SDK 类型`Get*` to `List*` - [Client SDKs](/reference/migrations/upgrade-to-v1/client)
* 代替`runCount` with `retryCount` - [Workflows](/reference/migrations/upgrade-to-v1/workflows)
* 更新自定义导出器方法`exportEvent` to `exportTracingEvent` (if using custom exporters) - [Tracing](/reference/migrations/upgrade-to-v1/tracing)
