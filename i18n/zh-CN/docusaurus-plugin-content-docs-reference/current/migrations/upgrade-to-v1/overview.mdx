# 升级到 Mastra v1

:::note[先更新到最新的 0.x 版本]
升级到 v1 前，请确保已将 Mastra 更新到最新的 0.x 版本。先按照[升级到最新 0.x 版本指南](https://mastra.ai/guides/v0/migrations/upgrade-to-latest-0x)操作，再返回此处完成 v1 迁移。
:::

Mastra v1 于 2026 年 1 月发布。我们建议新项目从 Mastra v1 开始，现有项目则升级到 v1，以继续获得更新和支持。

本指南介绍从 Mastra 0.x 升级到 v1.0 时的破坏性变更，并按软件包和功能领域组织迁移内容，帮助您系统地更新代码库。

:::tip[需要帮助？]
迁移过程中有疑问？欢迎加入我们的 [Discord 社区](https://discord.gg/mastra-ai)提问。
:::

:::warning[从 Mastra Cloud 迁移？]
旧版 Mastra Cloud 产品已由 [Mastra 平台](/docs/mastra-platform/overview)取代。新平台将托管功能拆分为两个独立产品：**Studio**（可视化环境和可观测性）与 **Server**（生产环境 API）。旧版 Mastra Cloud 的访问令牌不能用于 Mastra 平台，请使用 `mastra auth tokens create` 创建新令牌。

如果只升级到 v1 软件包，却没有将 `telemetry:` 配置迁移为 `observability:` 并创建 Studio 项目，可观测性数据将停止传输。请完整按照 [Mastra Cloud 迁移指南](/reference/migrations/mastra-cloud)操作。
:::

## 迁移策略 {/* #migration-strategy */}

### 将所有 Mastra 软件包更新到 `latest` 标签 {/* #update-all-mastra-packages-to-latest-tag */}

使用包管理器更新项目依赖。请**同时更新所有** Mastra 软件包（包括所有 `@mastra/*` 软件包和 `mastra`），以确保版本兼容。

以下是更新最常用软件包的方法：

```bash npm2yarn
npm install @mastra/core@latest @mastra/loggers@latest @mastra/memory@latest mastra@latest
```

安装其他 Mastra 软件包时也使用 `@latest` 标签，即可获取其最新的可用 v1 版本。务必更新所有 Mastra 软件包，尤其是在 monorepo 中，以免版本不一致。

### 更新 Node.js 版本 {/* #update-nodejs-version */}

Mastra v1 要求 Node.js 版本为 **22.13.0** 或更高。请相应更新开发环境和生产环境。

### 完成迁移清单 {/* #go-through-migration-checklist */}

按照下方的[迁移清单](#migration-checklist)更新代码库。每一项都链接到对应变更的详细指南。

:::note[Codemod]

我们提供了自动化 [codemod](https://github.com/mastra-ai/mastra/tree/main/packages/codemod)。您可以选择一次运行所有 v1 codemod：

```bash
npx @mastra/codemod@latest v1
```

:::

:::note[需要迁移数据库]

如果使用 PostgreSQL 或 LibSQL 存储，您需要执行数据库迁移。详情请参阅[存储迁移指南](/reference/migrations/upgrade-to-v1/storage#database-migration)。

:::

## 各领域的破坏性变更 {/* #breaking-changes-by-area */}

- **[Mastra 类](/reference/migrations/upgrade-to-v1/mastra)** — 调整导入路径和属性访问方式。
- **[Agent 类](/reference/migrations/upgrade-to-v1/agent)** — 语音方法移入命名空间，并更新流式 API。
- **[Tool](/reference/migrations/upgrade-to-v1/tools)** — `createTool` 的执行函数签名改为分别接收输入和上下文。
- **[Workflow](/reference/migrations/upgrade-to-v1/workflows)** — 更改函数名称并移除旧功能。
- **[内存](/reference/migrations/upgrade-to-v1/memory)** — 配置现在需要显式指定参数，默认值也已更改。
- **[存储](/reference/migrations/upgrade-to-v1/storage)** — 统一分页方式，并将方法重命名为 `list*` 模式。
- **[向量](/reference/migrations/upgrade-to-v1/vectors)** — 将向量存储方法重命名为 `list*` 模式。
- **[RAG](/reference/migrations/upgrade-to-v1/rag)** — 调整参数名称，使其含义更清晰。
- **[MCP](/reference/migrations/upgrade-to-v1/mcp)** — 调整 Tool 上下文结构，并移除已弃用的客户端类。
- **[追踪](/reference/migrations/upgrade-to-v1/tracing)** — 以专用的可观测性软件包和导出器取代 OTEL 遥测。
- **[评估与评分器](/reference/migrations/upgrade-to-v1/evals)** — 整合评分器 API，并采用新的命名约定。
- **[CLI](/reference/migrations/upgrade-to-v1/cli)** — 移除部分命令和选项，简化界面。
- **[部署](/reference/migrations/upgrade-to-v1/deployment)** — 更新 CloudflareDeployer 配置，改用标准的 wrangler.json 属性名称。
- **[客户端 SDK](/reference/migrations/upgrade-to-v1/client)** — 重命名类型和工具函数，保持命名一致。
- **[语音软件包](/reference/migrations/upgrade-to-v1/voice)** — 将软件包名称中的 `speech` 改为 `voice`。

## 迁移清单 {/* #migration-checklist */}

请按顺序完成清单，先处理影响大多数应用程序的变更。

:::note[Codemod]

我们提供了自动化 [codemod](https://github.com/mastra-ai/mastra/tree/main/packages/codemod)。本迁移指南会说明如何针对具体变更使用它们。

您也可以选择一次运行所有 v1 codemod：

```bash
npx @mastra/codemod@latest v1
```

:::

### 高影响变更 {/* #high-impact-changes */}

- 将 `createTool` 的 Tool 函数签名更新为 `(inputData, context)` 格式 — [Tool](/reference/migrations/upgrade-to-v1/tools)
- 将 `@mastra/core` 的导入改为子路径导入 — [Mastra 类](/reference/migrations/upgrade-to-v1/mastra)
- 将分页参数从 `offset/limit` 更新为 `page/perPage` — [存储](/reference/migrations/upgrade-to-v1/storage)
- 安装 `@mastra/observability`，并使用 `new Observability()` 包装配置 — [追踪](/reference/migrations/upgrade-to-v1/tracing)
- 如果从 0.x OTEL 升级，将 `telemetry:` 配置迁移为 `observability:` — [追踪](/reference/migrations/upgrade-to-v1/tracing)

### 中等影响变更 {/* #medium-impact-changes */}

- 将整个代码库中的 `RuntimeContext` 重命名为 `RequestContext` — [Agent 类](/reference/migrations/upgrade-to-v1/agent)、[Tool](/reference/migrations/upgrade-to-v1/tools)、[Workflow](/reference/migrations/upgrade-to-v1/workflows)
- 将存储方法从 `get*` 模式改为 `list*` 模式 — [存储](/reference/migrations/upgrade-to-v1/storage)
- 用 getter 方法替代直接访问属性 — [Mastra 类](/reference/migrations/upgrade-to-v1/mastra)、[Agent 类](/reference/migrations/upgrade-to-v1/agent)
- 如果依赖默认的 `thread` 作用域，请更新内存作用域配置 — [内存](/reference/migrations/upgrade-to-v1/memory)
- 更新向量存储调用，改用具名参数 — [存储](/reference/migrations/upgrade-to-v1/storage)
- 从 Agent 方法中移除 `format` 参数 — [Agent 类](/reference/migrations/upgrade-to-v1/agent)
- 改为通过 `agent.voice` 命名空间调用语音方法 — [Agent 类](/reference/migrations/upgrade-to-v1/agent)
- 如果使用自定义处理器，将配置属性 `processors` 重命名为 `spanOutputProcessors` — [追踪](/reference/migrations/upgrade-to-v1/tracing)

### 低影响变更 {/* #low-impact-changes */}

- 在文本分块选项中，将 `keepSeparator` 重命名为 `separatorPosition` — [RAG](/reference/migrations/upgrade-to-v1/rag)
- 将 `createRunAsync` 重命名为 `createRun` — [Workflow](/reference/migrations/upgrade-to-v1/workflows)
- 将语音软件包名称从 `@mastra/speech-*` 更新为 `@mastra/voice-*` — [语音软件包](/reference/migrations/upgrade-to-v1/voice)
- 更新评分器方法：`runExperiment` → `runEvals`，`getScorerByName` → `getScorerById` — [评估与评分器](/reference/migrations/upgrade-to-v1/evals)
- 移除已弃用的 CLI 选项 — [CLI](/reference/migrations/upgrade-to-v1/cli)
- 将客户端 SDK 类型从 `Get*` 更新为 `List*` — [客户端 SDK](/reference/migrations/upgrade-to-v1/client)
- 用 `retryCount` 替代 `runCount` — [Workflow](/reference/migrations/upgrade-to-v1/workflows)
- 如果使用自定义导出器，将其 `exportEvent` 方法更新为 `exportTracingEvent` — [追踪](/reference/migrations/upgrade-to-v1/tracing)
