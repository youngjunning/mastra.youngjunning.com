# 元数据过滤器

Mastra 基于 MongoDB/Sift 查询语法，为所有向量存储提供统一的元数据过滤语法。每种向量存储都会将过滤条件转换为自身的查询格式。例如，PgVector 使用 PostgreSQL JSONB 谓词；OracleDB 将元数据存储为 Oracle JSON，并将过滤条件编译为带绑定参数的 `JSON_VALUE`、`JSON_EXISTS`、`REGEXP_LIKE` 和 `LIKE` 谓词。

## 基本示例 {/* #basic-example */}

```typescript
import { PgVector } from '@mastra/pg'

const store = new PgVector({
  id: 'pg-vector',
  connectionString,
})

const results = await store.query({
  indexName: 'my_index',
  queryVector: queryVector,
  topK: 10,
  filter: {
    category: 'electronics', // Simple equality
    price: { $gt: 100 }, // Numeric comparison
    tags: { $in: ['sale', 'new'] }, // Array membership
  },
})
```

## 通用规则与限制 {/* #common-rules-and-restrictions */}

1. 字段名称不能：
   * 包含点 (.)，除非引用嵌套字段
   * 以 $ 开头或包含空字符
   * 为空字符串

2. 值必须：
   * 属于有效的 JSON 类型（字符串、数字、布尔值、对象或数组）
   * 不能是 `undefined`
   * 符合运算符要求的类型（例如，数值比较需要数字）

3. 逻辑运算符：
   * 必须包含有效条件
   * 不能为空
   * 必须正确嵌套
   * 只能在顶层使用或嵌套在其他逻辑运算符中
   * 不能在字段级别使用或嵌套在字段内
   * 不能在运算符内部使用
   * 有效的：`{ "$and": [{ "field": { "$gt": 100 } }] }`
   * 有效的：`{ "$or": [{ "$and": [{ "field": { "$gt": 100 } }] }] }`
   * 无效的：`{ "field": { "$and": [{ "$gt": 100 }] } }`
   * 无效的：`{ "field": { "$gt": { "$and": [{...}] } } }`

4. `$not` 运算符：
   * 必须是一个对象
   * 不能为空
   * 可用于字段级或顶层
   * 有效的：`{ "$not": { "field": "value" } }`
   * 有效的：`{ "field": { "$not": { "$eq": "value" } } }`

5. 运算符嵌套：
   * 逻辑运算符必须包含字段条件，而不是直接运算符
   * 有效的：`{ "$and": [{ "field": { "$gt": 100 } }] }`
   * 无效的：`{ "$and": [{ "$gt": 100 }] }`

## 各向量存储的注意事项 {/* #store-specific-notes */}

### Astra {/* #astra */}

* 使用点表示法支持嵌套字段查询
* 数组字段必须在元数据中显式定义为数组
* 元数据值区分大小写

### ChromaDB {/* #chromadb */}

* `where` 过滤器只返回元数据中存在被过滤字段的结果
* 空元数据字段不包含在筛选结果中
* 否定匹配必须存在元数据字段（例如，$ne 不会匹配缺少该字段的文档）

### Cloudflare Vectorize {/* #cloudflare-vectorize */}

* 在使用过滤之前需要显式元数据索引
* 使用 `createMetadataIndex()` 为需要过滤的字段建立索引
* 每个 Vectorize 索引最多 10 个元数据索引
* 字符串值的索引最多为前 64 个字节（在 UTF-8 边界上截断）
* 数值使用 float64 精度
* 过滤器 JSON 必须小于 2048 字节
* 字段名称不能包含点 (.) 或以 $ 开头
* 字段名称限制为 512 个字符
* 创建新的元数据索引以包含在过滤结果中后，必须重新插入向量
* 对于非常大的数据集（~10M+向量），范围查询可能会降低准确性

### libSQL {/* #libsql */}

* 支持使用点表示法的嵌套对象查询
* 验证数组字段以确保它们包含有效的 JSON 数组
* 数字比较保持正确的类型处理
* 条件中的空数组得到妥善处理
* 元数据存储在 JSONB 列中，以便高效查询

### OracleDB {/* #oracledb */}

* 元数据以 Oracle JSON 格式与每条 `VECTOR` 记录一同存储
* 标量比较使用 `JSON_VALUE`；数组、字段存在性及数组元素匹配检查使用 `JSON_EXISTS`
* `$regex` 使用 Oracle 的 `REGEXP_LIKE`；字符串 `$contains` 使用不区分大小写的 `LIKE`
* 嵌套字段支持点表示法，并转换为带引号的 Oracle JSON 路径
* 用户提供的元数据值作为参数绑定，而不是插入到 SQL 中

### PgVector {/* #pgvector */}

* 完全支持 PostgreSQL 原生 JSON 查询功能
* 使用本机数组函数有效处理数组操作
* 对数字、字符串和布尔值进行正确的类型处理
* 嵌套字段查询在内部使用 PostgreSQL 的 JSON 路径语法
* 元数据存储在 JSONB 列中以实现高效索引

### Pinecone {/* #pinecone */}

* 元数据字段名称限制为 512 个字符
* 数值必须在 ±1e38 范围内
* 元数据中的数组总大小限制为 64KB
* 嵌套对象用点表示法展平
* 元数据更新替换整个元数据对象

### Qdrant {/* #qdrant */}

* 支持使用嵌套条件的高级过滤
* 有效负载（元数据）字段必须显式索引以进行过滤
* 使用 `createPayloadIndex()` 为需要过滤的字段建立索引：

```typescript
// Index a field before filtering on it
await store.createPayloadIndex({
  indexName: 'my_index',
  fieldName: 'source',
  fieldSchema: 'keyword', // 'keyword' | 'integer' | 'float' | 'geo' | 'text' | 'bool' | 'datetime' | 'uuid'
})

// Now filtering works
const results = await store.query({
  indexName: 'my_index',
  queryVector: queryVector,
  filter: { source: 'document-a' },
})
```

* 高效处理地理空间查询
* 对 null 值和空值的特殊处理
* 特定于向量的过滤功能
* 日期时间值必须采用 RFC 3339 格式
* `$regex` 会转换为 Qdrant 的全文匹配，匹配完整词项，而非任意正则表达式或子字符串（例如，`{ name: { $regex: "item" } }` 不匹配 `"item1"`）。对于未建立索引的 payload 字段，v1.19.1 之前的 Qdrant 版本会回退到子字符串匹配

### Upstash {/* #upstash */}

* 元数据字段键的 512 个字符限制
* 查询大小有限（避免使用大型 IN 子句）
* 过滤器中不支持 null/未定义值
* 在内部转换为类似 SQL 的语法
* 区分大小写的字符串比较
* 元数据更新是原子的

### MongoDB {/* #mongodb */}

* 需要 MongoDB Atlas，或已启用 MongoDB Vector Search 的部署。此向量存储使用 `$vectorSearch` 聚合阶段进行查询。
* 直接使用 MongoDB 查询语法进行元数据过滤器，包括元数据中的嵌套字段和数组。
* 支持上表所列的比较、数组、逻辑和元素运算符，以及 `$regex` 和 `$size`。`$size` 接受整数，例如 `{ tags: { $size: 3 } }`。
* 使用 `filter` 匹配元数据对象中的字段，使用 `documentFilter` 匹配原始文档文本。两者可以用于同一次查询。
* 创建索引时，在 `filterFields` 中声明要过滤的元数据字段。如果过滤条件仅使用已声明字段和 MongoDB Vector Search 接受的运算符（`$and`、`$or`、`$eq`、`$ne`、`$gt`、`$gte`、`$lt`、`$lte`、`$in`、`$nin`），Mastra 会将其直接传给 `$vectorSearch`：

```typescript
await store.createIndex({
  indexName: 'my_index',
  dimension: 1536,
  filterFields: ['category', 'price'],
})
```

* 如果过滤条件引用未声明的字段或使用其他运算符，Mastra 会先过滤集合，再将匹配的文档 ID 传给 `$vectorSearch`。只有当 ID 集合未超过 MongoDB 的 16 MB BSON 文档限制时，这条回退路径才能工作。对于大型集合，一旦超出该限制，查询就会失败；因此，对大型数据集执行选择性过滤时，应声明过滤字段。

### Couchbase {/* #couchbase */}

* 目前不支持元数据过滤器。检索结果后必须在客户端进行过滤，或者直接使用 Couchbase SDK 的搜索功能进行更复杂的查询。

### Amazon S3 Vectors {/* #amazon-s3-vectors */}

* 相等比较的值必须是基本类型（字符串、数字或布尔值），不能是 `null`、`undefined`、数组、对象或 Date。范围运算符接受数字或 Date；Date 会转换为以毫秒计的 Unix 时间戳。
* `$in` 和 `$nin` 要求使用**非空的基本类型数组**。数组元素可以是 Date，且会转换为以毫秒计的 Unix 时间戳。**不支持数组相等比较**。
* 隐式 AND 会规范化为显式形式（`{a:1,b:2}` → `{$and:[{a:1},{b:2}]`）。逻辑运算符必须包含字段条件，且使用非空数组；只能出现在根层级或其他逻辑运算符内，不能出现在字段值中。
* 创建索引时列在 `nonFilterableMetadataKeys` 中的键会被存储，但不能用于过滤。此设置不可更改。
* `$exists` 要求布尔值。
* `undefined`、`null` 或空过滤条件均视为未设置过滤条件。
* 每个元数据键名称不得超过 63 个字符。
* 每个向量的总元数据：最多 40 KB（可过滤 + 不可过滤）
* 每个向量的元数据密钥总数：最多 10 个
* 每个向量的可过滤元数据：最多 2 KB
* 每个向量索引的不可过滤元数据键：最多 10 个
