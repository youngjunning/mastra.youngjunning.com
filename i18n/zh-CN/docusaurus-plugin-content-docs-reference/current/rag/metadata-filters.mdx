# 元数据过滤器

Mastra 基于 MongoDB/Sift 查询语法，在所有向量存储中提供统一的元数据过滤语法。每个矢量存储将这些过滤器转换为其本机查询格式。例如，PgVector 使用 PostgreSQL JSONB 谓词，而 OracleDB 将元数据存储为 Oracle JSON 并将过滤器编译为`JSON_VALUE`, `JSON_EXISTS`, `REGEXP_LIKE`， 和`LIKE`具有绑定值的谓词。

## 基本示例 {/* #basic-example */}

```typescript
import { PgVector } from '@mastra/pg'

const store = new PgVector({
  id: 'pg-vector',
  connectionString,
})

const results = await store.query({
  indexName: 'my_index',
  queryVector: queryVector,
  topK: 10,
  filter: {
    category: 'electronics', // Simple equality
    price: { $gt: 100 }, // Numeric comparison
    tags: { $in: ['sale', 'new'] }, // Array membership
  },
})
```

## 共同规则和限制 {/* #common-rules-and-restrictions */}

1. 字段名称不能：
   * 包含点 (.)，除非引用嵌套字段
   * 以 $ 开头或包含空字符
   * 为空字符串

2. 值必须是：
   * 有效的 JSON 类型（字符串、数字、布尔值、对象、数组）
   * 并非未定义
   * 为运算符正确键入（例如，用于数字比较的数字）

3. 逻辑运算符：
   * 必须包含有效条件
   * 不能为空
   * 必须正确嵌套
   * 只能在顶层使用或嵌套在其他逻辑运算符中
   * 不能在字段级别使用或嵌套在字段内
   * 不能在运算符内部使用
   * 有效的：`{ "$and": [{ "field": { "$gt": 100 } }] }`
   * 有效的：`{ "$or": [{ "$and": [{ "field": { "$gt": 100 } }] }] }`
   * 无效的：`{ "field": { "$and": [{ "$gt": 100 }] } }`
   * 无效的：`{ "field": { "$gt": { "$and": [{...}] } } }`

4. $非运算符：
   * 必须是一个对象
   * 不能为空
   * 可用于字段级别或顶级
   * 有效的：`{ "$not": { "field": "value" } }`
   * 有效的：`{ "field": { "$not": { "$eq": "value" } } }`

5. 运算符嵌套：
   * 逻辑运算符必须包含字段条件，而不是直接运算符
   * 有效的：`{ "$and": [{ "field": { "$gt": 100 } }] }`
   * 无效的：`{ "$and": [{ "$gt": 100 }] }`

## 商店特定注释 {/* #store-specific-notes */}

### 阿斯特拉 {/* #astra */}

* 使用点表示法支持嵌套字段查询
* 数组字段必须在元数据中显式定义为数组
* 元数据值区分大小写

### 色度数据库 {/* #chromadb */}

* 其中过滤器仅返回元数据中存在过滤字段的结果
* 空元数据字段不包含在筛选结果中
* 否定匹配必须存在元数据字段（例如，$ne 不会匹配缺少该字段的文档）

### Cloudflare 矢量化 {/* #cloudflare-vectorize */}

* 在使用过滤之前需要显式元数据索引
* 使用`createMetadataIndex()` to index fields you want to filter on
* 每个 Vectorize 索引最多 10 个元数据索引
* 字符串值的索引最多为前 64 个字节（在 UTF-8 边界上截断）
* 数值使用 float64 精度
* 过滤器 JSON 必须小于 2048 字节
* 字段名称不能包含点 (.) 或以 $ 开头
* 字段名称限制为 512 个字符
* 创建新的元数据索引以包含在过滤结果中后，必须重新插入向量
* 对于非常大的数据集（~10M+向量），范围查询可能会降低准确性

### 库SQL {/* #libsql */}

* 支持使用点表示法的嵌套对象查询
* 验证数组字段以确保它们包含有效的 JSON 数组
* 数字比较保持正确的类型处理
* 条件中的空数组得到妥善处理
* 元数据存储在 JSONB 列中，以便高效查询

### 甲骨文数据库 {/* #oracledb */}

* 元数据以 Oracle JSON 形式与每个元数据一起存储`VECTOR` row
* 标量比较使用`JSON_VALUE`, while array, existence, and element-match checks use `JSON_EXISTS`
* `$regex`使用Oracle`REGEXP_LIKE`; string `$contains` uses case-insensitive `LIKE`
* 嵌套字段支持点表示法，并转换为带引号的 Oracle JSON 路径
* 用户提供的元数据值作为参数绑定，而不是插入到 SQL 中

### 向量 {/* #pgvector */}

* 完全支持 PostgreSQL 原生 JSON 查询功能
* 使用本机数组函数有效处理数组操作
* 对数字、字符串和布尔值进行正确的类型处理
* 嵌套字段查询在内部使用 PostgreSQL 的 JSON 路径语法
* 元数据存储在 JSONB 列中以实现高效索引

### 松果 {/* #pinecone */}

* 元数据字段名称限制为 512 个字符
* 数值必须在 ±1e38 范围内
* 元数据中的数组总大小限制为 64KB
* 嵌套对象用点表示法展平
* 元数据更新替换整个元数据对象

### 奎德兰特 {/* #qdrant */}

* 支持使用嵌套条件的高级过滤
* 有效负载（元数据）字段必须显式索引以进行过滤
* 使用`createPayloadIndex()` to index fields you want to filter on:

```typescript
// Index a field before filtering on it
await store.createPayloadIndex({
  indexName: 'my_index',
  fieldName: 'source',
  fieldSchema: 'keyword', // 'keyword' | 'integer' | 'float' | 'geo' | 'text' | 'bool' | 'datetime' | 'uuid'
})

// Now filtering works
const results = await store.query({
  indexName: 'my_index',
  queryVector: queryVector,
  filter: { source: 'document-a' },
})
```

* 高效处理地理空间查询
* 对 null 值和空值的特殊处理
* 特定于向量的过滤功能
* 日期时间值必须采用 RFC 3339 格式
* `$regex`被转换为 Qdrant 的全文匹配，它匹配整个标记而不是任意正则表达式或子字符串（例如`{ name: { $regex: "item" } }` doesn't match `"item1"`). On unindexed payload fields, Qdrant versions before v1.19.1 fall back to substring matching

### 乌普斯塔什 {/* #upstash */}

* 元数据字段键的 512 个字符限制
* 查询大小有限（避免使用大型 IN 子句）
* 过滤器中不支持 null/未定义值
* 在内部转换为类似 SQL 的语法
* 区分大小写的字符串比较
* 元数据更新是原子的

### MongoDB {/* #mongodb */}

* 需要 MongoDB Atlas 或启用 MongoDB 矢量搜索的部署。商店查询`$vectorSearch` aggregation stage.
* 直接使用 MongoDB 查询语法进行元数据过滤器，包括元数据中的嵌套字段和数组。
* 支持上表中的比较、数组、逻辑和元素运算符，以及`$regex` and `$size`. `$size` takes an integer, as in `{ tags: { $size: 3 } }`.
* 使用`filter` to match fields in the metadata object and `documentFilter` to match the original document text. You can combine them in a single query.
* 声明您过滤的元数据字段`filterFields` when you create the index. Mastra passes filters that use only declared fields and the operators MongoDB Vector Search accepts (`$and`, `$or`, `$eq`, `$ne`, `$gt`, `$gte`, `$lt`, `$lte`, `$in`, `$nin`) directly to `$vectorSearch`:

```typescript
await store.createIndex({
  indexName: 'my_index',
  dimension: 1536,
  filterFields: ['category', 'price'],
})
```

* 引用未声明字段或使用其他运算符的过滤器采用后备路径：Mastra 预过滤集合并将匹配的文档 ID 传递给`$vectorSearch`. This works only while the ID set fits within MongoDB's 16 MB BSON document limit. On large collections the query fails once that limit is exceeded, so declare your filter fields for selective queries over large data sets.

### 沙发底座 {/* #couchbase */}

* 目前不支持元数据过滤器。检索结果后必须在客户端进行过滤，或者直接使用 Couchbase SDK 的搜索功能进行更复杂的查询。

### 亚马逊 S3 矢量图 {/* #amazon-s3-vectors */}

* 相等值必须是原语（字符串/数字/布尔值）。`null`/`undefined`, arrays, objects, and Date aren't allowed for equality. Range operators accept numbers or Date (Dates are normalized to epoch ms).
* `$in`/`$nin` require **non-empty arrays of primitives**. Date elements are allowed and normalized to epoch ms. **Array equality** isn't supported.
* 隐式 AND 被规范化 (`{a:1,b:2}` → `{$and:[{a:1},{b:2}]`). Logical operators must contain field conditions and use non-empty arrays. They may appear only at the root or within other logical operators (not inside field values).
* 列出的键`nonFilterableMetadataKeys` at index creation are stored but not filterable. This setting is immutable.
* $exists 需要一个布尔值。
* 未定义/空/空过滤器被视为无过滤器。
* 每个元数据键名称不得超过 63 个字符。
* 每个向量的总元数据：最多 40 KB（可过滤 + 不可过滤）
* 每个向量的元数据密钥总数：最多 10 个
* 每个向量的可过滤元数据：最多 2 KB
* 每个向量索引的不可过滤元数据键：最多 10 个
