# DatabaseConfig

`DatabaseConfig` 类型用于在使用向量查询 Tool 时指定数据库专属配置，以利用不同向量存储提供的功能和优化。

## 类型定义 {/* #type-definition */}

```typescript
export type DatabaseConfig = {
  pinecone?: PineconeConfig
  pgvector?: PgVectorConfig
  chroma?: ChromaConfig
  mongodb?: MongoDBConfig
  turbopuffer?: TurbopufferConfig
  [key: string]: any // Extensible for future databases
}
```

### `PgVectorConfig` {/* #pgvectorconfig */}

安装了 pgvector 扩展的 PostgreSQL 专属的配置选项。

  type: 'number',

  isOptional: true,
},
]}
/>

**性能调优建议：**

* **ef**：先设为 topK 的 2～4 倍，需要更高准确率时再增大
* **probes**：先设为 1～10，需要更高召回率时再增大
* **minScore**：根据结果质量要求，使用 0.5～0.9 之间的值

**适用场景：**

* 优化高负载场景下的性能
* 过滤不相关结果
* 调整搜索准确率与速度之间的取舍

  <TabItem value="runtime-override" label="运行时覆盖">
    ### 在运行时覆盖配置 {/* #runtime-configuration-override */}

    ```typescript
    import { RequestContext } from '@mastra/core/request-context'

    // Initial configuration
    const vectorTool = createVectorQueryTool({
      vectorStoreName: 'pinecone',
      indexName: 'documents',
      model: embedModel,
      databaseConfig: {
        pinecone: {
          namespace: 'development',
        },
      },
    })

    // Override at runtime
    const requestContext = new RequestContext()
    requestContext.set('databaseConfig', {
      pinecone: {
        namespace: 'production',
      },
    })

    await vectorTool.execute({ queryText: 'search query' }, { mastra, requestContext })
    ```
  </TabItem>

  <TabItem value="multi-database" label="多数据库">
    ### 多数据库配置 {/* #multi-database-configuration */}

    ```typescript
    import { RequestContext } from '@mastra/core/request-context'

    const vectorTool = createVectorQueryTool({
      vectorStoreName: 'pinecone',
      indexName: 'documents',
      model: embedModel,
    })

    // Select the store per request and pass only its matching config block
    const pineconeContext = new RequestContext()
    pineconeContext.set('vectorStoreName', 'pinecone')
    pineconeContext.set('databaseConfig', {
      pinecone: { namespace: 'default' },
    })

    const pgVectorContext = new RequestContext()
    pgVectorContext.set('vectorStoreName', 'pgVector')
    pgVectorContext.set('databaseConfig', {
      pgvector: { minScore: 0.8, ef: 150 },
    })

    await vectorTool.execute({ queryText: 'search query' }, { mastra, requestContext: pgVectorContext })
    ```

    :::note

    **多数据库支持**：无论查询哪个向量存储，所配置的所有数据库配置块都会合并到查询参数中。共用的参数名会影响实际执行查询的向量存储。例如，`pgvector.minScore` 会作为 `minScore` 传入；LibSQL 等其他存储也会读取它来过滤结果。因此，只传入与当前查询所用向量存储对应的配置块。

    :::
  </TabItem>

## 可扩展性 {/* #extensibility */}

`DatabaseConfig` 类型支持扩展。要添加对新向量数据库的支持：

```typescript
// 1. Define the configuration interface
export interface NewDatabaseConfig {
  customParam1?: string
  customParam2?: number
}

// 2. Extend DatabaseConfig type
export type DatabaseConfig = {
  pinecone?: PineconeConfig
  pgvector?: PgVectorConfig
  chroma?: ChromaConfig
  newdatabase?: NewDatabaseConfig
  [key: string]: any
}

// 3. Use in vector query tool
const vectorTool = createVectorQueryTool({
  vectorStoreName: 'newdatabase',
  indexName: 'documents',
  model: embedModel,
  databaseConfig: {
    newdatabase: {
      customParam1: 'value',
      customParam2: 42,
    },
  },
})
```

## 最佳实践 {/* #best-practices */}

1. **环境配置**：为不同环境使用不同的命名空间或配置
2. **性能调优**：从默认值开始，再根据实际需求调整
3. **质量过滤**：使用 minScore 过滤低质量结果
4. **运行时灵活性**：按运行时确定的需求覆盖配置
5. **文档记录**：记录配置选择，方便团队成员了解

## 迁移指南 {/* #migration-guide */}

现有向量查询 Tool 无需修改即可继续使用。要添加数据库配置：

```diff
const vectorTool = createVectorQueryTool({
  vectorStoreName: 'pinecone',
  indexName: 'documents',
  model: embedModel,
+ databaseConfig: {
+   pinecone: {
+     namespace: 'production'
+   }
+ }
});
```
