# 文档分块与嵌入

处理文档前，先根据内容创建 MDocument 实例。可以使用不同格式的内容初始化：

```ts
import { MDocument } from '@mastra/rag'

const doc = MDocument.fromText('Your plain text content...')
const docFromHTML = MDocument.fromHTML('<html>Your HTML content...</html>')
const docFromMarkdown = MDocument.fromMarkdown('# Your Markdown content...')
const docFromJSON = MDocument.fromJSON(`{ "key": "value" }`)
```

## 文档处理 {/* #document-processing */}

使用 `chunk` 将文档拆分为便于处理的块。Mastra 提供多种针对不同文档类型优化的分块策略：

* `recursive`：根据内容结构智能拆分
* `character`：按字符拆分
* `token`：按 token 拆分
* `markdown`：根据 Markdown 结构拆分
* `semantic-markdown`：根据相关标题组拆分 Markdown
* `html`：根据 HTML 结构拆分
* `json`：根据 JSON 结构拆分
* `latex`：根据 LaTeX 结构拆分
* `sentence`：按句子拆分

:::note
各策略接受的参数有所不同，分别针对相应的分块方式进行了优化。
:::

以下示例使用 `recursive` 策略：

```ts
const chunks = await doc.chunk({
  strategy: 'recursive',
  maxSize: 512,
  overlap: 50,
  separators: ['\n'],
  extract: {
    title: true, // Optionally extract a title for each chunk
  },
})
```

如果文本需要保留句子结构，可以使用 `sentence` 策略：

```ts
const chunks = await doc.chunk({
  strategy: 'sentence',
  maxSize: 450,
  minSize: 50,
  overlap: 0,
  sentenceEnders: ['.'],
})
```

如果 Markdown 文档需要保留各章节之间的语义关系，可以使用 `semantic-markdown` 策略：

```ts
const chunks = await doc.chunk({
  strategy: 'semantic-markdown',
  joinThreshold: 500,
  modelName: '__AI_SDK_OPENAI_MODEL_BASE__',
})
```

:::note
提取元数据时可能会调用 LLM，因此请确保已设置 API 密钥。
:::

有关分块策略的详细说明，请参阅 [`chunk()` 参考文档](/reference/rag/chunk)。

## 生成嵌入 {/* #embedding-generation */}

使用所选的 Provider 将文本块转换为嵌入。Mastra 通过模型路由器支持嵌入模型。

### 使用模型路由器 {/* #using-the-model-router */}

最简单的方法是向 Mastra 的模型路由器传入 `provider/model` 格式的字符串：

```ts
import { ModelRouterEmbeddingModel } from '@mastra/core/llm'
import { embedMany } from 'ai'

const { embeddings } = await embedMany({
  model: new ModelRouterEmbeddingModel('__GATEWAY_OPENAI_EMBEDDING_MODEL__'),
  values: chunks.map(chunk => chunk.text),
})
```

Mastra 支持 OpenAI 和 Google 的嵌入模型。完整的支持列表见[嵌入参考文档](/reference/rag/embeddings)。

模型路由器会自动从环境变量中查找 API 密钥。

嵌入函数返回向量，即表示文本语义的数字数组，可用于向量数据库中的相似性搜索。

### 配置嵌入维度 {/* #configuring-embedding-dimensions */}

嵌入模型通常输出固定维度的向量（例如，OpenAI 的 `__AI_SDK_OPENAI_EMBEDDING_MODEL__` 输出 1536 维向量）。
部分模型支持降低输出维度，这有助于：

* 降低向量数据库的存储需求
* 降低相似性搜索的计算成本

以下是一些支持调整维度的模型：

OpenAI（text-embedding-3 系列模型）：

```ts
import { ModelRouterEmbeddingModel } from '@mastra/core/llm'

const { embeddings } = await embedMany({
  model: new ModelRouterEmbeddingModel('__GATEWAY_OPENAI_EMBEDDING_MODEL__'),
  options: {
    dimensions: 256, // Only supported in text-embedding-3 and later
  },
  values: chunks.map(chunk => chunk.text),
})
```

Google（gemini-embedding-001）：

```ts
const { embeddings } = await embedMany({
  model: google('gemini-embedding-001', {
    outputDimensionality: 256, // Truncates excessive values from the end
  }),
  values: chunks.map(chunk => chunk.text),
})
```

:::important[向量数据库兼容性]
存储嵌入时，应将向量数据库索引的维度设为与嵌入模型的输出维度一致，避免维度不匹配造成错误或数据损坏。
:::

## 示例：完整流程 {/* #example-complete-pipeline */}

以下示例展示文档处理、嵌入生成和向量存储的完整流程：

```ts
import { ModelRouterEmbeddingModel } from '@mastra/core/llm'
import { PgVector } from '@mastra/pg'
import { MDocument } from '@mastra/rag'
import { embedMany } from 'ai'

const doc = MDocument.fromText(`
  Climate change poses significant challenges to global agriculture.
  Rising temperatures and changing precipitation patterns affect crop yields.
`)

const chunks = await doc.chunk({
  strategy: 'recursive',
  maxSize: 256,
  overlap: 50,
})

const { embeddings } = await embedMany({
  model: new ModelRouterEmbeddingModel('__GATEWAY_OPENAI_EMBEDDING_MODEL__'),
  values: chunks.map(chunk => chunk.text),
})

const vectorStore = new PgVector({
  id: 'pg-vector',
  connectionString: process.env.POSTGRES_CONNECTION_STRING,
})

await vectorStore.createIndex({
  indexName: 'embeddings',
  dimension: 1536,
})

await vectorStore.upsert({
  indexName: 'embeddings',
  vectors: embeddings,
})
```
