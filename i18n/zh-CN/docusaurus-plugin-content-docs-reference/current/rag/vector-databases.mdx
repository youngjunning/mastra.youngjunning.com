# 在向量数据库中存储嵌入

生成嵌入后，需要将其存储在支持向量相似度搜索的数据库中。Mastra 提供统一接口，供你在不同向量数据库中存储和查询嵌入。

## 支持的数据库 {/* #supported-databases */}

    <h3>使用 MongoDB Vector Search</h3>

    如果团队希望将向量搜索、全文搜索和业务数据集中在同一个数据库中，以降低基础设施复杂度，同时保持生产环境所需的性能，可以使用 MongoDB Vector Search。
    有关配置步骤和最佳实践，请参阅 [MongoDB Vector Search 官方文档](https://www.mongodb.com/docs/atlas/atlas-vector-search/vector-search-overview/?utm_campaign=devrel\&utm_source=third-party-content\&utm_medium=cta\&utm_content=mastra-docs)。

    <h3>将 VoyageAI 与 MongoDB 结合使用</h3>

    MongoDB 可直接使用针对检索任务优化的 VoyageAI 嵌入模型。完整示例和专用模型见 [VoyageAI 嵌入文档](/models/embeddings#voyageai)及 [MongoDB 向量数据库参考文档](/integrations/vectors/mongodb)。

    <h3>混合搜索（向量搜索与全文搜索）</h3>

    MongoDB 通过服务端的 `$rankFusion` 将向量相似度搜索与 BM25 全文搜索结合。该功能要求 MongoDB 8.0 或更高版本，从 8.1 起正式可用，并已在 MongoDB Atlas 8.0.x 中启用。可以用它合并语义检索和关键词检索的结果：

    ```ts
    await store.createSearchIndex({ indexName: 'myCollection', fields: ['text'] })
    const results = await store.hybridQuery({
      indexName: 'myCollection',
      queryVector: embedding,
      query: 'search terms',
      paths: ['text'],
      topK: 10,
    })
    ```

    有关 `createSearchIndex()`、`textQuery()` 和 `hybridQuery()` 的详情，请参阅 [MongoDB 向量数据库参考文档](/integrations/vectors/mongodb)。

    <h3>自动生成嵌入</h3>

    MongoDB 可以自行生成嵌入，因此应用中无需配置嵌入 Provider。创建索引时指定 `autoEmbed` 和 Voyage AI 模型，随后写入纯文本，并通过查询字符串进行搜索：

    ```ts
    await store.createIndex({
      indexName: 'myCollection',
      autoEmbed: { model: 'voyage-4' },
    })
    await store.upsert({
      indexName: 'myCollection',
      documents: chunks.map(chunk => chunk.text),
      metadata: chunks.map(chunk => ({ text: chunk.text })),
    })
    const results = await store.query({
      indexName: 'myCollection',
      queryText: 'search terms',
      topK: 10,
    })
    ```

    自动生成嵌入是 MongoDB 的预览功能，需要使用支持该功能的部署环境。支持的选项和具体要求见 [MongoDB 向量数据库参考文档](/integrations/vectors/mongodb#automated-embedding)。
  </TabItem>

## 使用向量存储 {/* #using-vector-storage */}

初始化后，所有向量存储都通过统一接口创建索引、插入或更新嵌入，以及执行查询。

### 创建索引 {/* #creating-indexes */}

在存储嵌入之前，您需要为嵌入模型创建一个具有适当维度大小的索引：

```ts title="store-embeddings.ts"
// Create an index with dimension 1536 (for __AI_SDK_OPENAI_EMBEDDING_MODEL__)
await store.createIndex({
  indexName: 'myCollection',
  dimension: 1536,
})
```

索引维度必须与所选嵌入模型的输出维度一致。常见维度如下：

* OpenAI `__AI_SDK_OPENAI_EMBEDDING_MODEL__`：1536 维（也可自定义，例如 256 维）
* `Cohere embed-multilingual-v3`：1024 维
* `VoyageAI voyage-3.5`：1024 维（也可设为 256、512、1024 或 2048 维）
* `Google gemini-embedding-001`：768 维（也可自定义）

:::warning
索引创建后无法更改维度。若要改用输出维度不同的模型，需要删除索引，再按新维度创建。
:::

### 数据库命名规则 {/* #naming-rules-for-databases */}

每个矢量数据库都对索引和集合强制执行特定的命名约定，以确保兼容性并防止冲突。

<Tabs>
  <TabItem value="mongodb" label="MongoDB">
    集合和索引名称必须：

    * 以字母或下划线开头
    * 长度最多 120 字节
    * 仅包含字母、数字、下划线字符或点
    * 不能包含 `$` 或空字符
    * 示例：`my_collection.123` 是有效名称
    * 示例：`my-index` 是无效名称（包含连字符）
    * 示例：`My$Collection` 是无效名称（包含 `$`）
  </TabItem>

  <TabItem value="pgVector" label="PgVector">
    索引名称必须：

    * 以字母或下划线开头
    * 仅包含字母、数字和下划线字符
    * 示例：`my_index_123` 是有效名称
    * 示例：`my-index` 是无效名称（包含连字符）
  </TabItem>

  <TabItem value="oracledb" label="OracleDB">
    索引名称是逻辑 Mastra 名称。 OracleDB 在内部将每个逻辑索引映射到物理 Oracle 表。

    逻辑索引名称必须：

    * 非空
    * 不超过 512 个字符
    * 在向量索引的生命周期内保持稳定
    * 示例：`my_collection_123` 是有效名称
    * 示例：`customer-support/docs:v1` 是有效名称，并会映射为安全的 Oracle 表名
  </TabItem>

  <TabItem value="pinecone" label="Pinecone">
    索引名称必须：

    * 仅使用小写字母、数字和破折号
    * 不包含点（用于 DNS 路由）
    * 不使用非拉丁字符或表情符号
    * 总长度（含项目 ID）少于 52 个字符
      * 示例：`my-index-123` 是有效名称
      * 示例：`my.index` 是无效名称（包含点）
  </TabItem>

  <TabItem value="qdrant" label="Qdrant">
    集合名称必须：

    * 长度为 1-255 个字符
    * 不包含任何以下特殊字符：
      * `< > : " / \ | ? *`
      * 空字符 (`\0`)
      * 单位分隔符 (`\u{1F}`)
    * 示例：`my_collection_123` 是有效名称
    * 示例：`my/collection` 是无效名称（包含斜杠）
  </TabItem>

  <TabItem value="chroma" label="Chroma">
    集合名称必须：

    * 长度为 3-63 个字符
    * 以字母或数字开头和结尾
    * 仅包含字母、数字、下划线字符或连字符
    * 不包含连续句点 (..)
    * 不是有效的 IPv4 地址
    * 示例：`my-collection-123` 是有效名称
    * 示例：`my..collection` 是无效名称（包含连续的点）
  </TabItem>

  <TabItem value="astra" label="Astra">
    集合名称必须：

    * 不能为空
    * 不超过 48 个字符
    * 仅包含字母、数字和 `_`
    * 示例：`my_collection_123` 是有效名称
    * 示例：`my-collection` 是无效名称（包含连字符）
  </TabItem>

  <TabItem value="libsql" label="libSQL">
    索引名称必须：

    * 以字母或下划线开头
    * 仅包含字母、数字和 `_`
    * 示例：`my_index_123` 是有效名称
    * 示例：`my-index` 是无效名称（包含连字符）
  </TabItem>

  <TabItem value="upstash" label="Upstash">
    命名空间名称必须：

    * 长度为 2-100 个字符
    * 仅包含：
      * 字母数字字符（a-z、A-Z、0-9）
      * 下划线、连字符、点
    * 不以特殊字符（\_、-、.）开头或结尾
    * 可以区分大小写
    * 示例：`MyNamespace123` 是有效名称
    * 示例：`_namespace` 是无效名称（以下划线开头）
  </TabItem>

  <TabItem value="weaviate" label="Weaviate">
    索引名称映射到 Weaviate 集合，其中：

    * Weaviate 大写（第一个字母大写）
    * 应仅包含字母、数字和 `_`
    * 必须以字母开头，因为只有第一个字符是大写的（前导数字或符号仍然无效）
    * 在集合描述中保留原始 Mastra 索引名称，因此 `listIndexes()` 和 `describeIndex()` 会返回你提供的名称
    * 示例：`my_collection` 存储为 `My_collection`，返回时仍为 `my_collection`
    * 示例：`123_collection` 是无效名称（以数字开头）
  </TabItem>

  <TabItem value="cloudflare" label="Cloudflare">
    索引名称必须：

    * 以字母开头
    * 少于 32 个字符
    * 仅包含小写 ASCII 字母、数字和破折号
    * 使用破折号代替空格
    * 示例：`my-index-123` 是有效名称
    * 示例：`My_Index` 是无效名称（包含大写字母和下划线）
  </TabItem>

  <TabItem value="opensearch" label="OpenSearch">
    索引名称必须：

    * 仅使用小写字母
    * 不以下划线字符或连字符开头
    * 不包含空格、逗号
    * 不包含特殊字符（例如`:`, `"`, `*`, `+`, `/`, `\`, `|`, `?`, `#`, `>`, `<`)
    * 示例：`my-index-123` 是有效名称
    * 示例：`My_Index` 是无效名称（包含大写字母）
    * 示例：`_myindex` 是无效名称（以下划线开头）
  </TabItem>

  <TabItem value="elasticsearch" label="Elasticsearch">
    索引名称必须：

    * 仅使用小写字母
    * 不超过255字节（算多字节字符）
    * 不以下划线字符、连字符或加号开头
    * 不包含空格、逗号

### 插入或更新嵌入 {/* #upserting-embeddings */}

创建索引后，可以存储嵌入及其基本元数据：

```ts title="store-embeddings.ts"
// Store embeddings with their corresponding metadata
await store.upsert({
  indexName: 'myCollection', // index name
  vectors: embeddings, // array of embedding vectors
  metadata: chunks.map(chunk => ({
    text: chunk.text, // The original text content
    id: chunk.id, // Optional unique identifier
  })),
})
```

插入或更新操作会：

* 接收嵌入向量数组及对应的元数据
* 按相同 ID 更新已有向量
* 为尚不存在的 ID 创建新向量
* 自动对大型数据集进行分批处理

## 添加元数据 {/* #adding-metadata */}

向量存储支持使用任何可序列化为 JSON 的字段作为元数据，以便筛选和组织数据。元数据没有固定模式，因此应统一字段命名，避免查询结果不符合预期。

:::warning
元数据对向量存储很重要。缺少元数据时，只有数值形式的嵌入，无法返回原始文本或筛选结果。至少应将源文本存为元数据。
:::

```ts
// Store embeddings with rich metadata for better organization and filtering
await store.upsert({
  indexName: 'myCollection',
  vectors: embeddings,
  metadata: chunks.map(chunk => ({
    // Basic content
    text: chunk.text,
    id: chunk.id,

    // Document organization
    source: chunk.source,
    category: chunk.category,

    // Temporal metadata
    createdAt: new Date().toISOString(),
    version: '1.0',

    // Custom fields
    language: chunk.language,
    author: chunk.author,
    confidenceScore: chunk.score,
  })),
})
```

使用元数据时请注意：

* 统一字段名，例如 `category` 与 `Category` 不一致会影响查询
* 只添加需要用于筛选或排序的字段，额外字段会增加开销
* 添加时间戳（例如 `createdAt`、`lastUpdated`），以跟踪内容是否仍然新近

## 删除向量 {/* #deleting-vectors */}

使用 `deleteVectors` 配合元数据筛选条件，删除与文档关联的嵌入。这适合在文档删除或更新后清理过期向量。

### 通过元数据过滤器删除 {/* #delete-by-metadata-filter */}

最常见的用例是当用户删除特定文档时删除该文档的所有向量：

```ts title="delete-vectors.ts"
// Delete all vectors for a specific document
await store.deleteVectors({
  indexName: 'myCollection',
  filter: { docId: 'document-123' },
})
```

这在以下情况下特别有用：

* 用户删除文档，您需要删除其所有块
* 您正在重新索引文档并希望首先删除旧向量
* 您需要清理特定用户或租户的向量

### 删除多个文档 {/* #delete-multiple-documents */}

您还可以使用复杂的过滤器来删除匹配多个条件的向量：

```ts title="delete-vectors-advanced.ts"
// Delete all vectors for multiple documents
await store.deleteVectors({
  indexName: 'myCollection',
  filter: {
    docId: { $in: ['doc-1', 'doc-2', 'doc-3'] },
  },
})

// Delete vectors for a specific user's documents
await store.deleteVectors({
  indexName: 'myCollection',
  filter: {
    $and: [{ userId: 'user-123' }, { status: 'archived' }],
  },
})
```

### 按向量 ID 删除 {/* #delete-by-vector-ids */}

如果您有特定的向量ID要删除，您可以直接传递它们：

```ts title="delete-by-ids.ts"
// Delete specific vectors by their IDs
await store.deleteVectors({
  indexName: 'myCollection',
  ids: ['vec-1', 'vec-2', 'vec-3'],
})
```

## 最佳实践 {/* #best-practices */}

* 批量插入前先创建索引
* 大量插入时使用批处理（upsert 方法会自动分批）
* 只存储查询需要使用的元数据
* 使嵌入维度与模型输出一致（例如，`__AI_SDK_OPENAI_EMBEDDING_MODEL__` 对应 1536 维）
