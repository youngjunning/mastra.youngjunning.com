# RAG 系统中的检索

存储嵌入后，您需要检索相关块来回答用户查询。

Mastra 提供灵活的检索选项，支持语义搜索、过滤和重新排名。

## 检索的工作原理 {/* #how-retrieval-works */}

1. 使用与文档嵌入相同的模型将用户的查询转换为嵌入
2. 使用向量相似度将此嵌入与存储的嵌入进行比较
3. 检索最相似的块并且可以选择：

* 按元数据过滤
* 重新排名以获得更好的相关性
* 通过知识图谱进行处理

## 基本检索 {/* #basic-retrieval */}

最简单的方法是直接语义搜索。该方法使用向量相似度来查找语义上与查询相似的块：

```ts
import { embed } from 'ai'
import { PgVector } from '@mastra/pg'
import { ModelRouterEmbeddingModel } from '@mastra/core/llm'

// Convert query to embedding
const { embedding } = await embed({
  value: 'What are the main points in the article?',
  model: new ModelRouterEmbeddingModel('openai/text-embedding-3-small'),
})

// Query vector store
const pgVector = new PgVector({
  id: 'pg-vector',
  connectionString: process.env.POSTGRES_CONNECTION_STRING,
})
const results = await pgVector.query({
  indexName: 'embeddings',
  queryVector: embedding,
  topK: 10,
})

// Display results
console.log(results)
```

这`topK` parameter specifies the maximum number of most similar results to return from the vector search.

每个结果都包含一个`id`, a similarity `score`, and the stored `metadata`. When you store chunk text in metadata, it's available as `metadata.text`:

```ts
[
  {
    id: 'chunk-1',
    score: 0.89,
    metadata: { text: 'Climate change poses significant challenges...', source: 'article1.txt' },
  },
  {
    id: 'chunk-2',
    score: 0.82,
    metadata: { text: 'Rising temperatures affect crop yields...', source: 'article1.txt' },
  },
]
```

结果还可以包括`vector` when you set `includeVector: true`, and `document` when the store returns the original document (Chroma only).

## 高级检索选项 {/* #advanced-retrieval-options */}

### 元数据过滤 {/* #metadata-filtering */}

根据元数据字段过滤结果以缩小搜索空间。这种方法 - 将向量相似性搜索与元数据过滤器相结合 - 有时称为混合向量搜索，因为它将语义搜索与结构化过滤标准合并。

当您拥有来自不同来源、不同时间段或具有特定属性的文档时，这非常有用。 Mastra 提供了统一的 MongoDB 风格的查询语法，适用于所有支持的向量存储。

有关可用运算符和语法的详细信息，请参阅[Metadata Filters Reference](/reference/rag/metadata-filters).

元数据过滤的常见用例：

* 按文档来源或类型过滤
* 按日期范围过滤
* 按特定类别或标签过滤
* 按数字范围（例如价格、评级）过滤
* 组合多个条件进行精准查询
* 按文档属性（例如语言、作者）过滤

### 应用过滤器的地方 {/* #where-the-filter-is-applied */}

矢量存储的不同之处在于*when* they apply a metadata filter, which affects how filtered queries scale.

MongoDB 可以评估向量索引本身内部的过滤器。这使查询保持单次往返`$vectorSearch`, so it avoids the pre-filter pass that collects matching document IDs and the 16 MB BSON limit that pass is subject to. Declaring the fields you filter on in `filterFields` when you create the index is what enables it:

```ts
// Declare the metadata fields you want to filter on
await mongoVector.createIndex({
  indexName: 'embeddings',
  dimension: 1536,
  filterFields: ['source', 'price', 'category', 'inStock', 'tags'],
})

// createIndex() returns before the index finishes building
await mongoVector.waitForIndexReady({ indexName: 'embeddings' })

// The filter is applied during the index search
const results = await mongoVector.query({
  indexName: 'embeddings',
  queryVector: embedding,
  topK: 10,
  filter: { source: 'article1.txt' },
})
```

仅当 Matra 引用的每个字段都在其中声明时，Mastra 才会将过滤器传递给索引`filterFields` and every operator is one the index accepts: `$and`, `$or`, `$eq`, `$ne`, `$gt`, `$gte`, `$lt`, `$lte`, `$in`, and `$nin`. A filter that uses an undeclared field or any other operator takes a fallback path: Mastra matches the collection first and passes the matching document IDs into the vector search. That fallback holds only while the ID set fits within MongoDB's 16 MB BSON document limit. On large collections the query fails once that limit is exceeded, so declare your filter fields when you expect selective filters over large data sets.

pgVector 将过滤器作为普通查询条件应用：

```ts
const results = await pgVector.query({
  indexName: 'embeddings',
  queryVector: embedding,
  topK: 10,
  filter: { source: 'article1.txt' },
})
```

使用 pgvector 0.8.0 或更高版本上的 HNSW 索引，PostgreSQL 会搜索索引并跳过与过滤器不匹配的行。当索引搜索无法填满时`topK`, pgVector reruns the query as an exact search.

对于旧 pgvector 版本上的 IVFFlat 或 HNSW，pgVector 会将查询向量与每个匹配行进行比较。结果是准确的，但工作量随着匹配行数的增加而增加。

对您过滤的元数据字段建立索引可以加快这两种情况的速度，并为 PostgreSQL 提供在它们之间进行选择所需的行数。

### 矢量查询Tool {/* #vector-query-tool */}

有时您希望让Agent能够直接查询矢量数据库。矢量查询Tool允许您的Agent负责检索决策，根据Agent对用户需求的理解，将语义搜索与可选的过滤和重新排名相结合。

```ts
import { createVectorQueryTool } from '@mastra/rag'
import { ModelRouterEmbeddingModel } from '@mastra/core/llm'

const vectorQueryTool = createVectorQueryTool({
  vectorStoreName: 'pgVector',
  indexName: 'embeddings',
  model: new ModelRouterEmbeddingModel('openai/text-embedding-3-small'),
})
```

创建Tool时，请特别注意Tool的名称和描述 - 这些有助于Agent了解何时以及如何使用检索功能。例如，您可以将其命名为“SearchKnowledgeBase”并将其描述为“搜索我们的文档以查找有关 X 主题的相关信息”。

这在以下情况下特别有用：

* 您的Agent需要在运行时决定检索哪些信息
* 检索过程需要复杂的决策
* 您希望Agent根据上下文组合多种检索策略

#### 数据库特定的配置 {/* #database-specific-configurations */}

矢量查询Tool支持特定于数据库的配置，使您能够使用不同矢量存储的独特功能和优化。

:::注意
这些配置用于**query-time options** like namespaces, performance tuning, and filtering, not for database connection setup.

连接凭据（URL、身份验证令牌）是在实例化向量存储类时配置的（例如，`new LibSQLVector({ url: '...' })`).
:::

```ts
import { createVectorQueryTool } from '@mastra/rag'
import { ModelRouterEmbeddingModel } from '@mastra/core/llm'

// Pinecone with namespace
const pineconeQueryTool = createVectorQueryTool({
  vectorStoreName: 'pinecone',
  indexName: 'docs',
  model: new ModelRouterEmbeddingModel('openai/text-embedding-3-small'),
  databaseConfig: {
    pinecone: {
      namespace: 'production', // Isolate data by environment
    },
  },
})

// pgVector with performance tuning
const pgVectorQueryTool = createVectorQueryTool({
  vectorStoreName: 'postgres',
  indexName: 'embeddings',
  model: new ModelRouterEmbeddingModel('openai/text-embedding-3-small'),
  databaseConfig: {
    pgvector: {
      minScore: 0.7, // Filter low-quality results
      ef: 200, // HNSW search parameter
      probes: 10, // IVFFlat probe parameter
    },
  },
})

// Chroma with advanced filtering
const chromaQueryTool = createVectorQueryTool({
  vectorStoreName: 'chroma',
  indexName: 'documents',
  model: new ModelRouterEmbeddingModel('openai/text-embedding-3-small'),
  databaseConfig: {
    chroma: {
      where: { category: 'technical' },
      whereDocument: { $contains: 'API' },
    },
  },
})

// LanceDB with table specificity
const lanceQueryTool = createVectorQueryTool({
  vectorStoreName: 'lance',
  indexName: 'documents',
  model: new ModelRouterEmbeddingModel('openai/text-embedding-3-small'),
  databaseConfig: {
    lance: {
      tableName: 'myVectors', // Specify which table to query
      includeAllColumns: true, // Include all metadata columns in results
    },
  },
})
```

**主要优点：**

* **松果命名空间**：按租户、环境或数据类型组织向量
* **pg向量优化**：使用 ef/probes 参数控制搜索精度和速度
* **质量过滤**：设置最小相似度阈值以提高结果相关性
* **LanceDB 表**：将数据分成表格，以便更好的组织和性能
* **运行时灵活性**：根据上下文在运行时覆盖配置

**常见用例：**

* 使用 Pinecone 命名空间的多租户应用程序
* 高负载场景下的性能优化
* 特定于环境的配置（dev/staging/prod）
* 质量控制的搜索结果
* 使用 LanceDB 的嵌入式、基于文件的矢量存储，用于边缘部署场景

您还可以使用请求上下文在运行时覆盖这些配置：

```ts
import { RequestContext } from '@mastra/core/request-context'

const requestContext = new RequestContext()
requestContext.set('databaseConfig', {
  pinecone: {
    namespace: 'runtime-namespace',
  },
})

await pineconeQueryTool.execute({ queryText: 'search query' }, { mastra, requestContext })
```

有关详细配置选项和高级用法，请参阅[Vector Query Tool Reference](/reference/tools/vector-query-tool).

### 重新排名 {/* #re-ranking */}

初始向量相似性搜索有时可能会错过详细的相关性。重新排名是一个计算成本更高的过程，但算法更准确，可以通过以下方式改进结果：

* 考虑词序和精确匹配
* 应用更高级的相关性评分
* 在查询和文档之间使用称为交叉注意力的方法

以下是如何使用重新排名：

```ts
import { rerankWithScorer as rerank, MastraAgentRelevanceScorer } from '@mastra/rag'

// Get initial results from vector search
const initialResults = await pgVector.query({
  indexName: 'embeddings',
  queryVector: queryEmbedding,
  topK: 10,
})

// Create a relevance scorer
const relevanceProvider = new MastraAgentRelevanceScorer(
  'relevance-scorer',
  '__GATEWAY_OPENAI_MODEL__',
)

// Re-rank the results
const rerankedResults = await rerank({
  results: initialResults,
  query,
  scorer: relevanceProvider,
  options: {
    weights: {
      semantic: 0.5, // How well the content matches the query semantically
      vector: 0.3, // Original vector similarity score
      position: 0.2, // Preserves original result ordering
    },
    topK: 10,
  },
})
```

权重控制不同因素如何影响最终排名：

* `semantic`：较高的值优先考虑语义理解和与查询的相关性
* `vector`：较高的值有利于原始向量相似度分数
* `position`：较高的值有助于保持结果的原始顺序

:::注意
为了使语义评分在重新排名期间正常工作，每个结果必须包含其文本内容`metadata.text` field.
:::

您还可以使用其他相关性评分提供程序，例如 Voyage AI、Cohere 或 ZeroEntropy：

```ts
import { VoyageRelevanceScorer } from '@mastra/voyageai'

const relevanceProvider = new VoyageRelevanceScorer({ model: 'rerank-2.5' })
```

```ts
const relevanceProvider = new CohereRelevanceScorer('rerank-v3.5')
```

```ts
const relevanceProvider = new ZeroEntropyRelevanceScorer('zerank-1')
```

Voyage AI 提供专用的重新排名模型：`rerank-2.5` and `rerank-2.5-lite` both allow up to 32,000 tokens for the query and any single document combined, and up to 600,000 tokens across a request. `VoyageRelevanceScorer` reads `VOYAGE_API_KEY` from the environment, or accepts an `apiKey` in its config.

重新排序的结果将向量相似性与语义理解相结合，以提高检索质量。

有关重新排名的更多详细信息，请参阅[rerank()](/reference/rag/rerankWithScorer) method.

对于遵循块之间连接的基于图的检索，请参阅[GraphRAG](/reference/rag/graph-rag-guide) documentation.
