# Run.startAsync()

`.startAsync()` 启动 Workflow 运行，无需等待运行完成。它会立即返回 `runId`，让 Workflow 在后台继续执行。适用于耗时较长的 Workflow 或定时任务，也可避免调用方一直等待运行结束。

## 使用示例 {/* #usage-example */}

```typescript
const run = await workflow.createRun()

// Fire-and-forget - returns immediately
const { runId } = await run.startAsync({
  inputData: {
    value: 'initial data',
  },
})

// Optionally poll for completion later
const state = await workflow.getWorkflowRunById(runId)
```

## 何时使用 `startAsync()` {/* #when-to-use-startasync */}

在以下场景使用 `startAsync()`，而不是 `start()`：

- **耗时较长的 Workflow**：运行可能需要几分钟或几小时。
- **定时或 cron 触发**：触发 Workflow 时不阻塞调度器。
- **避免轮询失败**：对于 Inngest Workflow，`start()` 会轮询运行结果；轮询可能失败并引发重试。`startAsync()` 可避免此问题。
- **后台处理**：将任务加入队列，异步处理结果。

## 检查 Workflow 状态 {/* #checking-workflow-status */}

调用 `startAsync()` 后，可使用 `workflow.getWorkflowRunById()` 检查运行状态。它返回包含 `status`、`steps`、`result` 和 `error` 的运行状态；如果找不到该运行，则返回 `null`。

如果未配置[存储](/docs/storage)，或者运行尚未持久化，该方法会返回内存中的状态：`isFromInMemory: true`、空的 `steps`，且没有 `result` 或 `error`。要在运行结束后读取结果，请配置存储。

```typescript
const state = await workflow.getWorkflowRunById(runId)

if (!state) {
  console.log('Workflow run not found')
} else if (state.status === 'success') {
  console.log('Workflow completed:', state.result)
} else if (state.status === 'failed') {
  console.log('Workflow failed:', state.error)
} else {
  console.log('Workflow status:', state.status)
}
```
