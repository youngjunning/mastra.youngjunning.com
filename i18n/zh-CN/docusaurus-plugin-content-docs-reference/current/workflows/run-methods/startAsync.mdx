# Run.startAsync()

这`.startAsync()`方法启动Workflow运行而不等待完成。它立即返回`runId`，允许Workflow程在后台执行。这对于长时间运行的Workflow程或计划任务非常有用。它还避免了Workflow程完成时的阻塞。

## 使用示例 {/* #usage-example */}

```typescript
const run = await workflow.createRun()

// Fire-and-forget - returns immediately
const { runId } = await run.startAsync({
  inputData: {
    value: 'initial data',
  },
})

// Optionally poll for completion later
const state = await workflow.getWorkflowRunById(runId)
```

## 何时使用`startAsync()` {/* #when-to-use-startasync */}

使用`startAsync()` instead of `start()` when:

* **长时间运行的Workflow程**：Workflow程可能需要几分钟或几小时才能完成
* **计划/cron 触发器**：您想要触发Workflow程而不阻塞调度程序
* **避免轮询失败**：通过 Ingest Workflow程，`start()` polls for completion which can fail and cause retries. `startAsync()` avoids this issue
* **后台处理**：您想要对工作进行排队并异步处理结果

## 检查Workflow程状态 {/* #checking-workflow-status */}

打电话后`startAsync()`, check the workflow status with `workflow.getWorkflowRunById()`. It returns the run state, including `status`, `steps`, `result`, and `error`, or `null` if the run isn't found.

未配置[storage](/docs/storage), or before the run is persisted, the method returns an in-memory state with `isFromInMemory: true`, empty `steps`, and no `result` or `error`. Configure storage to read a run's result after it finishes.

```typescript
const state = await workflow.getWorkflowRunById(runId)

if (!state) {
  console.log('Workflow run not found')
} else if (state.status === 'success') {
  console.log('Workflow completed:', state.result)
} else if (state.status === 'failed') {
  console.log('Workflow failed:', state.error)
} else {
  console.log('Workflow status:', state.status)
}
```
