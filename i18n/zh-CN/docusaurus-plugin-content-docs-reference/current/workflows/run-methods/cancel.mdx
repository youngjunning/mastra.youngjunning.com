# 运行.取消()

这`.cancel()`方法取消Workflow运行，停止执行并清理资源。

此方法会中止任何正在运行的步骤并将Workflow状态更新为“已取消”。它适用于主动运行的Workflow程和暂停/等待的Workflow程。

在默认引擎和事件引擎上，嵌套Workflow运行将与其父级一起取消，包括暂停的Workflow运行。呼唤`cancel()` on a run that's already canceled cancels any of its nested runs that are still suspended.

## 使用示例 {/* #usage-example */}

```typescript
const run = await workflow.createRun()

await run.cancel()
```

## 取消如何运作 {/* #how-cancellation-works */}

调用时，Workflow程将：

1. **触发中止信号**- 使用标准Web API AbortSignal来通知运行步骤
2. **防止后续步骤**- 不会执行进一步的步骤

## 中止信号行为 {/* #abort-signal-behavior */}

检查的步骤`abortSignal` parameter can respond to cancellation:

* 可以监听'abort'事件的步骤：`abortSignal.addEventListener('abort', callback)`
* 步骤可以检查是否已经中止：`if (abortSignal.aborted) { ... }`
* 对于取消超时、网络请求或长时间运行的操作很有用

步骤在执行过程中必须主动检查要取消的中止信号；否则，当前步骤将运行至完成，并且后续步骤不会执行。

## 扩展使用示例 {/* #extended-usage-examples */}

### 出错时取消Workflow程 {/* #cancelling-a-workflow-on-error */}

```typescript
const run = await workflow.createRun()

try {
  const result = await run.start({ inputData: { value: 'initial data' } })
} catch (error) {
  await run.cancel()
}
```

### 创建响应取消的步骤 {/* #creating-a-step-that-responds-to-cancellation */}

```typescript
const step = createStep({
  id: 'long-running-step',
  execute: async ({ inputData, abortSignal, abort }) => {
    const timeout = new Promise(resolve => {
      const timer = setTimeout(() => resolve('done'), 10000)

      // Clean up if canceled
      abortSignal.addEventListener('abort', () => {
        clearTimeout(timer)
        resolve('canceled')
      })
    })

    const result = await timeout

    // Check if aborted after async operation
    if (abortSignal.aborted) {
      return abort() // Stop execution
    }

    return { result }
  },
})
```
