# Run.cancel()

`.cancel()` 会取消一次 Workflow 运行，停止执行并清理资源。

此方法会中止正在执行的步骤，并将 Workflow 状态更新为 'canceled'。正在运行以及已暂停或等待中的 Workflow 均可取消。

对于默认引擎和事件驱动引擎，嵌套的 Workflow 运行会随父运行一同取消，包括已暂停的运行。对已经取消的运行再次调用 `cancel()`，仍会取消其中尚处于暂停状态的嵌套运行。

## 使用示例 {/* #usage-example */}

```typescript
const run = await workflow.createRun()

await run.cancel()
```

## 取消流程 {/* #how-cancellation-works */}

调用后，Workflow 会：

1. **触发中止信号** — 使用标准 Web API AbortSignal 通知正在执行的步骤。
1. **阻止后续步骤** — 后续步骤不会执行。

## 中止信号行为 {/* #abort-signal-behavior */}

检查 `abortSignal` 参数的步骤可以响应取消请求：

- 步骤可以监听 'abort' 事件：`abortSignal.addEventListener('abort', callback)`
- 步骤可以检查是否已中止：`if (abortSignal.aborted) { ... }`
- 可用于取消定时器、网络请求或长时间运行的操作

要在步骤执行过程中取消它，步骤必须主动检查中止信号；否则，当前步骤会执行完毕，但后续步骤不会运行。

## 扩展使用示例 {/* #extended-usage-examples */}

### 出错时取消 Workflow {/* #cancelling-a-workflow-on-error */}

```typescript
const run = await workflow.createRun()

try {
  const result = await run.start({ inputData: { value: 'initial data' } })
} catch (error) {
  await run.cancel()
}
```

### 创建响应取消的步骤 {/* #creating-a-step-that-responds-to-cancellation */}

```typescript
const step = createStep({
  id: 'long-running-step',
  execute: async ({ inputData, abortSignal, abort }) => {
    const timeout = new Promise(resolve => {
      const timer = setTimeout(() => resolve('done'), 10000)

      // Clean up if canceled
      abortSignal.addEventListener('abort', () => {
        clearTimeout(timer)
        resolve('canceled')
      })
    })

    const result = await timeout

    // Check if aborted after async operation
    if (abortSignal.aborted) {
      return abort() // Stop execution
    }

    return { result }
  },
})
```
