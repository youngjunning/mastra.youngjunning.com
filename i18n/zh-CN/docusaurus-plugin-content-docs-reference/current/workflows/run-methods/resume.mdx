# Run.resume()

`.resume()` 方法使用新数据恢复已暂停的 Workflow 运行，从指定步骤继续执行。

## 使用示例 {/* #usage-example */}

```typescript
const run = await workflow.createRun()

const result = await run.start({ inputData: { value: 'initial data' } })

if (result.status === 'suspended') {
  const resumedResults = await run.resume({
    resumeData: { value: 'resume data' },
  })
}
```

## 扩展使用示例 {/* #extended-usage-example */}

```typescript
if (result.status === 'suspended') {
  const resumedResults = await run.resume({
    step: result.suspended[0],
    resumeData: { value: 'resume data' },
  })
}
```

:::note

如果恰好只有一个步骤处于暂停状态，可以省略 `step` 参数，Workflow 会自动恢复该步骤。如果有多个步骤处于暂停状态，则必须明确指定要恢复的步骤。

:::

### 恢复 [`.foreach()`](../workflow-methods/foreach) 的单次迭代 {/* #resuming-a-single-foreach-iteration */}

如果 [`.foreach()`](../workflow-methods/foreach) 步骤的多次迭代都已暂停，可以通过 `forEachIndex`（从零开始）逐次恢复，并为每次迭代提供不同的 `resumeData`。未被 `forEachIndex` 指定的迭代会继续保持暂停，直到被恢复。

```typescript
// Resume only the second iteration (index 1) with its own data
await run.resume({
  step: 'approve',
  resumeData: { ok: true },
  forEachIndex: 1,
})

// Later, resume the first iteration with different data
await run.resume({
  step: 'approve',
  resumeData: { ok: false },
  forEachIndex: 0,
})
```

如果省略 `forEachIndex`，该步骤所有已暂停的迭代都会使用相同的 `resumeData` 恢复。

## 并发恢复调用 {/* #concurrent-resume-calls */}

每次暂停只能由一个 `resume()` 调用继续执行。在执行任何步骤之前，`resume()` 会以原子操作将存储的运行状态从 `suspended` 改为 `running`，从而取得该运行的处理权。如果其他调用方已取得处理权，此调用会抛出 `WORKFLOW_RESUME_ALREADY_CLAIMED`，且不执行任何步骤。因此，每次暂停之后的步骤及其副作用只会执行一次。

当恢复操作可能被多次触发时，这一点尤其重要，例如审批按钮被点击两次，或 webhook 被重试。多个服务器实例响应同一事件时也是如此。

```typescript
try {
  await run.resume({ step: 'approval', resumeData: { approved: true } })
} catch (error) {
  if (error.id === 'WORKFLOW_RESUME_ALREADY_CLAIMED') {
    // Another caller is already continuing this run. Re-read the run state
    // instead of resuming again.
  }
}
```

通过 HTTP 调用时，未能取得处理权的恢复请求会返回 `409 Conflict`。

[`timeTravel()`](./timeTravel#concurrent-time-travel-calls) 也以相同方式取得运行的处理权；未能取得处理权时会抛出 `WORKFLOW_TIME_TRAVEL_ALREADY_CLAIMED`。

:::note

报告支持 `supportsConcurrentUpdates()` 的存储适配器会以原子方式保证处理权的取得。不支持原子读改写的适配器（例如 ClickHouse、Cloudflare D1、Cloudflare KV、Cloudflare Durable Objects、LanceDB 和 Redis）无法提供此保证；当 `shouldPersistSnapshot` 排除 `running` 状态时，也会跳过取得处理权的步骤。

:::
