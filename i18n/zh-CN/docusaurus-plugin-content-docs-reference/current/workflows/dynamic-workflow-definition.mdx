# 动态Workflow程定义

:::测试版

在 API 稳定之前，可能会在没有重大版本更新的情况下发生重大更改。

:::

动态Workflow定义是与 JSON 兼容的`DynamicWorkflowGraph` accepted by [`Mastra.addDynamicWorkflow()`](/reference/core/addDynamicWorkflow), the stored-workflow server routes, and the Client SDK workflows API.

看[Dynamic workflows](/docs/workflows/dynamic-workflows) for a complete setup and usage example.

## 定义字段 {/* #definition-fields */}

|领域 |类型 |必填|描述 |
| - | - | - | - |
|`id` | `string` | Yes | Unique workflow ID. This is also the ID used to retrieve and run the workflow. |
| `description` | `string`|没有 |人类可读的描述 |
|`inputSchema` | `JsonSchema`|是的 |Workflow程输入的 JSON 架构 |
|`outputSchema` | `JsonSchema`|是的 |Workflow程输出的 JSON 架构 |
|`stateSchema` | `JsonSchema`|没有 |共享Workflow状态的 JSON 模式 |
|`requestContextSchema` | `JsonSchema`|没有 |从请求上下文读取值的 JSON 架构 |
|`metadata` | `Record<string, unknown>`|没有 |通过存储保存任意 JSON 元数据 |
|`graph` | `SerializedStepFlowEntry[]`|是的 |组成Workflow程的步骤条目 |

模式使用 JSON Schema 而不是 Zod，因此定义可以通过 JSON 进行往返。 Mastra 在注册Workflow程时将每个模式转换为 Zod。

```json
{
  "id": "greeting-workflow",
  "description": "Returns a greeting for the supplied name",
  "inputSchema": {
    "type": "object",
    "properties": { "name": { "type": "string" } },
    "required": ["name"]
  },
  "outputSchema": {
    "type": "object",
    "properties": { "message": { "type": "string" } },
    "required": ["message"]
  },
  "graph": [
    {
      "type": "mapping",
      "id": "create-greeting",
      "mapConfig": "{\"message\":{\"template\":\"Hello, ${initData.name}!\"}}"
    }
  ]
}
```

## 图表条目 {/* #graph-entries */}

条目在`graph` run in order. Each entry receives the previous entry's output, and the first entry receives the workflow input.

|条目类型 |描述 |
| - | - |
|`agent` | Invoke a registered agent |
| `classifier` | Evaluate data with a registered classifier |
| `tool` | Invoke a registered tool |
| `mapping` | Reshape data between steps |
| `workflow` | Invoke a registered workflow as a nested step |
| `parallel` | Run several steps concurrently and merge their outputs |
| `conditional` | Run every branch whose predicate is true, concurrently |
| `foreach` | Run one step per item of an array input |
| `loop` | Repeat a step while or until a predicate holds |
| `sleep` | Pause for a fixed duration |
| `sleepUntil` | Pause until a fixed date |

使用代码定义的Workflow程[`.agent()`](/reference/workflows/workflow-methods/agent), [`.classifier()`](/reference/workflows/workflow-methods/classifier), and [`.tool()`](/reference/workflows/workflow-methods/tool) produce the same declarative entries when serialized.

### 身份和显示字段 {/* #identity-and-display-fields */}

控制流条目接受可选字段来标识和描述条目而不影响执行：

|领域 |类型 |描述 |
| - | - | - |
|`id` | `string` | Stable identity for addressing the entry across edits and serialization. Optional on `parallel`, `conditional`, `foreach`, and `loop`; required on `mapping`, `sleep`, and `sleepUntil`. |
| `description` | `string` | Human-readable intent of the control-flow operation |
| `metadata` | `Record<string, unknown>` | Arbitrary JSON metadata preserved through storage, for example a display title for visual editors |

```json
{
  "type": "parallel",
  "id": "independent-enrichment",
  "description": "Run independent document enrichment tasks concurrently",
  "metadata": { "title": "Independent enrichment" },
  "steps": [
    { "type": "tool", "id": "extract-entities", "toolId": "entity-tool" },
    { "type": "tool", "id": "classify", "toolId": "classify-tool" }
  ]
}
```

所有三个场都可以在储存和再水化中幸存下来，并且它们出现在`serializedStepGraph` for API and Studio consumers. Agent and tool steps carry the equivalent information on their own `description` and `options.metadata` fields.

### Agent步骤 {/* #agent-steps */}

一个`agent` entry invokes a registered agent by ID. Agent steps accept `{ prompt: string }` as input and return `{ text: string }` by default.

```json
{
  "type": "agent",
  "id": "summarize",
  "agentId": "support-agent"
}
```

这`id` identifies this call site within the workflow. Later steps address the result as `stepResults.summarize`, regardless of the agent's own ID.

添加一个`outputSchema` to request structured output from the agent:

```json
{
  "type": "agent",
  "id": "extract-subtopics",
  "agentId": "support-agent",
  "outputSchema": {
    "type": "array",
    "items": {
      "type": "object",
      "properties": { "title": { "type": "string" } },
      "required": ["title"]
    }
  }
}
```

使用一个`mapping` entry before an agent to build its `{ prompt }` input from workflow data.

Agent条目接受`options` object:

```json
{
  "type": "agent",
  "id": "summarize",
  "agentId": "support-agent",
  "options": { "retries": 2, "metadata": { "team": "support" } }
}
```

步骤描述来自注册Agent。一个`description` set on the agent entry is ignored when the workflow is rehydrated.

仅有的`retries` and `metadata` persist. Function-valued options such as `onFinish` and function-valued `toolChoice` are rejected when a code-defined workflow is stored. Other agent call options don't persist.

### 分类器步骤 {/* #classifier-steps */}

一个`classifier` entry evaluates workflow data with a classifier registered on the `Mastra` instance. The classifier must have constructor-configured questions.

```json
{
  "type": "classifier",
  "id": "classify-ticket",
  "classifierId": "ticket-router",
  "options": {
    "maxRetries": 2,
    "retries": 1,
    "metadata": { "team": "support" }
  }
}
```

分类器评估完整的条目输入。添加前面的`mapping` entry when the classifier needs a selected or reshaped input.

分类器输出有两条稳定路径：

* `answers.<question>`包含键入的答案。其路线`choice`, `score`, or `probability` field according to the question type. Choice and score answers may include distributions. A refused question is `{ "type": "refusal" }` with no `choice`, `score`, or `probability`, so it matches no condition on those fields. Compare `answers.<question>.type` with `"refusal"` to route refusals explicitly.
* `usage`包含规范化的令牌使用情况。

使用现有的`conditional` entry to route on classifier output. For example, a following condition can compare `{ "path": "stepResults.classify-ticket.answers.route.choice" }` with `{ "literal": "billing" }`.

这`options` object can contain classifier model-call `maxRetries`, JSON-safe `providerOptions`, workflow step `retries`, and `metadata`. Classifier errors fail the workflow step.

### Tool步骤 {/* #tool-steps */}

一个`tool` entry invokes a tool by its registration key from the `Mastra` `tools` object. Mastra resolves the tool's input and output schemas from the registry when it registers the workflow.

```json
{
  "type": "tool",
  "id": "lookup",
  "toolId": "lookup-customer"
}
```

Tool条目接受相同的可选`description` and `options` fields as agent entries. Only `retries` and `metadata` persist.

### 绘图步骤 {/* #mapping-steps */}

一个`mapping` entry reshapes data. Its `mapConfig` is a JSON string that encodes an object. Each key becomes a key in the step output, and each descriptor defines one source.

当你打电话时[`Mastra.addDynamicWorkflow()`](/reference/core/addDynamicWorkflow) directly, `mapConfig` also accepts the object itself. Mastra encodes it to a JSON string before registering and storing the definition, so the persisted row is the same either way. A stored definition always carries the JSON string form.

|描述符|描述 |
| - | - |
|`{ "value": ... }` | A constant JSON value |
| `{ "template": "..." }` | A string built from `${...}` placeholders |
| `{ "initData": true, "path": "a.b" }` | A value from the workflow input |
| `{ "step": "step-id", "path": "a.b" }` | A value from a preceding step's output |
| `{ "requestContextPath": "a.b" }` | A value from the request context |

这`step` source also accepts an array of step IDs:

```json
{ "step": ["escalate", "auto-reply"], "path": "text" }
```

第一个列出的具有非空结果的步骤提供该值。这可以选择在 a 之后运行的分支`conditional` entry.

模板解析占位符`initData`, `inputData`, `state`, `requestContext`, and `stepResults.<step-id>`:

```json
{
  "type": "mapping",
  "id": "build-prompt",
  "mapConfig": "{\"prompt\":{\"template\":\"Summarize this request: ${initData.request}\"}}"
}
```

由模板解析的对象和数组被字符串化为 JSON。一个`null` value inside a present result renders as an empty string. A template that references a step without a successful output fails the run.

映射条目必须是顶级图形条目。它们不能放置在里面`parallel`, `conditional`, `foreach`, or `loop` containers.

### 嵌套Workflow程步骤 {/* #nested-workflow-steps */}

一个`workflow` entry invokes another registered workflow. The target can be code-defined or stored.

```json
{
  "type": "workflow",
  "id": "lookup-first",
  "workflowId": "lookup-customer-workflow"
}
```

这`id` identifies the call site. The same nested workflow can appear several times under different call-site IDs, and later steps address each result as `stepResults.<id>`. A `workflow` entry also accepts an optional `description`.

### 并行条目 {/* #parallel-entries */}

一个`parallel` entry runs several single steps concurrently and merges their outputs into an object keyed by step ID.

```json
{
  "type": "parallel",
  "steps": [
    { "type": "tool", "id": "first", "toolId": "lookup-customer" },
    { "type": "tool", "id": "second", "toolId": "lookup-customer" }
  ]
}
```

每个孩子必须是一个`agent`, `classifier`, `tool`, or `workflow` entry. All children receive the parallel entry's input directly.

### 有条件条目 {/* #conditional-entries */}

一个`conditional` entry pairs each step with a declarative predicate and runs every branch whose predicate is true.

```json
{
  "type": "conditional",
  "steps": [
    { "type": "agent", "id": "escalate", "agentId": "support-agent" },
    { "type": "agent", "id": "auto-reply", "agentId": "support-agent" }
  ],
  "predicates": [
    { "op": "eq", "left": { "path": "inputData.priority" }, "right": { "literal": "urgent" } },
    { "op": "ne", "left": { "path": "inputData.priority" }, "right": { "literal": "urgent" } }
  ]
}
```

每个孩子必须是一个`agent`, `classifier`, `tool`, or `workflow` entry, and each child needs a predicate. All children receive the conditional entry's input directly.

### 谓词 {/* #predicates */}

条件条目和循环使用 JSON 谓词 DSL。操作数是`{ "path": "..." }` references or `{ "literal": ... }` values. Paths resolve against `initData`, `inputData`, `stepResults`, and `state`.

|操作员|形状|
| - | - |
|`eq`, `ne`, `lt`, `lte`, `gt`, `gte` | `{ "op": "eq", "left": ..., "right": ... }` |
| `in`, `notIn` | `{ "op": "in", "value": ..., "set": [...] }` |
| `exists`, `notExists` | `{ "op": "exists", "path": "..." }` |
| `truthy`, `falsy` | `{ "op": "truthy", "value": ... }` |
| `and`, `or` | `{ "op": "and", "args": [...] }` |
| `not` | `{ "op": "not", "arg": ... }` |

丢失的路径不会抛出。基于路径的运算符返回`false` when the path can't be resolved. Use `exists` or `notExists` to distinguish a missing value from a falsy value.

### Foreach 条目 {/* #foreach-entries */}

一个`foreach` entry runs its body once for each item in an array input. The preceding entry must produce a raw array. Results preserve input order, and concurrency defaults to `1`.

```json
{
  "type": "foreach",
  "step": { "type": "workflow", "id": "write-blurb", "workflowId": "blurb-workflow" },
  "opts": { "concurrency": 3 }
}
```

身体可以是一个`agent`, `tool`, or `workflow` entry, but not a `mapping` entry.

### 循环条目 {/* #loop-entries */}

一个`loop` repeats one step while (`dowhile`) or until (`dountil`) a predicate holds.

```json
{
  "type": "loop",
  "loopType": "dountil",
  "step": { "type": "tool", "id": "poll", "toolId": "check-status" },
  "predicate": {
    "op": "eq",
    "left": { "path": "inputData.status" },
    "right": { "literal": "done" }
  }
}
```

循环体必须是单步，并且存储循环需要声明性谓词。

### 睡眠条目 {/* #sleep-entries */}

一个`sleep` entry pauses for a fixed number of milliseconds. A `sleepUntil` entry pauses until a fixed date represented by an ISO date string. Stored definitions require literal values.

```json
{ "type": "sleep", "id": "wait", "duration": 5000 }
```

```json
{ "type": "sleepUntil", "id": "wait-for-launch", "date": "2027-01-01T00:00:00.000Z" }
```

当必须在运行时计算持续时间或日期时，请使用代码定义的Workflow。

## 验证 {/* #validation */}

Mastra 在保留或注册定义之前验证定义：

* 结构：条目形状和必填字段，包括放置规则，例如仅顶级映射。
* 参考文献：各`agentId` and `workflowId` must resolve against the live registries or the same bundle. A `toolId` must match a tool registration key.
* 模式流：每个条目的输入必须与前面的输出兼容，包括推断的映射输出。

验证错误包括虚线路径，例如`graph.2.steps.0`, that identifies the invalid entry.
