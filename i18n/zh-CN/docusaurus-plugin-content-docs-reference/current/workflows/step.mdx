# Step 类

Step 类定义 Workflow 中的单个工作单元，封装执行逻辑、数据验证以及输入和输出处理。
还可以传入 Tool、Agent 或已配置的分类器，自动由其创建步骤。

## 使用示例 {/* #usage-example */}

```typescript title="src/mastra/workflows/test-workflow.ts"
import { createWorkflow, createStep } from '@mastra/core/workflows'
import { z } from 'zod'

const step1 = createStep({
  id: 'step-1',
  description: 'passes value from input to output',
  inputSchema: z.object({
    value: z.number(),
  }),
  outputSchema: z.object({
    value: z.number(),
  }),
  execute: async ({ inputData }) => {
    const { value } = inputData
    return {
      value,
    }
  },
})
```

## 从 Agent 创建步骤 {/* #creating-steps-from-agents */}

可以直接从 Agent 创建步骤。该步骤使用 Agent 的名称作为 ID。

### 基本 Agent 步骤 {/* #basic-agent-step */}

```typescript title="src/mastra/workflows/test-workflow.ts"
import { testAgent } from '../agents/test-agent'
import { createStep } from '@mastra/core/workflows'

const agentStep = createStep(testAgent)
// inputSchema: { prompt: string }
// outputSchema: { text: string }
```

### 带结构化输出的 Agent 步骤 {/* #agent-step-with-structured-output */}

传入 `structuredOutput`，让 Agent 返回带类型的结构化数据：

```typescript title="src/mastra/workflows/test-workflow.ts"
import { createStep } from '@mastra/core/workflows'
import { z } from 'zod'

const articleSchema = z.object({
  title: z.string(),
  summary: z.string(),
  tags: z.array(z.string()),
})

const agentStep = createStep(testAgent, {
  structuredOutput: { schema: articleSchema },
})
// inputSchema: { prompt: string }
// outputSchema: { title: string, summary: string, tags: string[] }
```

## 从分类器创建步骤 {/* #creating-steps-from-classifiers */}

将构造时已配置问题的 [`Classifier`](/reference/classifier/classifier) 传给 `createStep()`。默认情况下，分类器评估完整的 `inputData`。使用 `state` 可以从步骤上下文中选取一个 JSON 值。

```typescript title="src/mastra/workflows/ticket-triage.ts"
import { Classifier } from '@mastra/core/classifier'
import { typeSafeAi } from '@ai-sdk/typesafe-ai'
import { createStep } from '@mastra/core/workflows'

const router = new Classifier({
  id: 'ticket-router',
  model: typeSafeAi.decisionModel('__AI_SDK_TYPESAFE_DECISION_MODEL__'),
  questions: {
    route: {
      type: 'choice',
      criteria: {
        billing: 'Billing, invoices, and payments',
        support: 'Account access and product help',
        other: 'Anything else',
      },
    },
    urgent: { type: 'boolean' },
  },
})

const classifyTicket = createStep(router, {
  maxRetries: 2,
  retries: 1,
})
```

该步骤的类型化输出可安全表示为 JSON：

* `answers.route.choice` 是选中的选项字面值。
* `answers.urgent.probability` 是布尔答案为 `true` 的概率，而非经过阈值判断的布尔值。
* 选择题和评分题的答案可能包含概率分布。
* 决策模型拒绝回答的问题表示为 `{ type: 'refusal' }`，不含 `choice`、`score` 或 `probability`。
* `usage` 包含归一化后的 token 用量。

`maxRetries` 控制分类器的模型调用重试次数。`retries` 控制 Workflow 步骤的重试次数。Workflow 输出不包含分类器警告、响应元数据或原始 Provider 数据。

构造时未配置问题的分类器不能用作 Workflow 步骤。该步骤会评估其完整输入；如果需要选择或调整输入结构，请在前面添加 `.map()`。

## 对步骤输出评分 {/* #scoring-step-output */}

为步骤配置 `scorers`，即可在该步骤运行时自动评估其输出，而不只评估 Workflow 的最终答案。这适用于多步骤 Workflow 和 RAG Workflow：例如，可以查看检索步骤在后续步骤推理前是否返回了相关片段，从而定位质量下降的步骤。

每个评分器都会接收该步骤自身的 `input` 和 `output`。步骤成功后，评分异步执行，结果存储在该步骤的 Trace 中。使用 `sampling` 控制评分器的运行频率。

以下示例为检索步骤配置评分器，使每次执行都接受评分：

```typescript title="src/mastra/workflows/rag-workflow.ts"
import { createStep } from '@mastra/core/workflows'
import { z } from 'zod'
import { retrievalRelevanceScorer } from '../scorers/retrieval-relevance'

const retrievalStep = createStep({
  id: 'retrieval',
  inputSchema: z.object({ query: z.string() }),
  outputSchema: z.object({ query: z.string(), chunks: z.array(z.string()) }),
  scorers: {
    retrievalRelevance: {
      scorer: retrievalRelevanceScorer(),
      sampling: { type: 'ratio', rate: 1 },
    },
  },
  execute: async ({ inputData }) => {
    const chunks = await retrieve(inputData.query)
    return { query: inputData.query, chunks }
  },
})
```

为每个需要评估的步骤配置评分器，即可在多步骤 Workflow 中获得逐步骤的评分。评分范围限定在单个步骤，因此无需专门的跨步骤指标，也能看出质量在哪一步发生变化。

通过 [`Workflow.agent()`](/reference/workflows/workflow-methods/agent) 和 [`Workflow.tool()`](/reference/workflows/workflow-methods/tool) 添加的 Agent 和 Tool 步骤，也在步骤选项中支持相同的 `scorers` 选项。

:::note
参阅[评分器概览](/docs/evals/overview)，了解实时评估如何运行以及结果存储在何处；参阅[自定义评分器](/docs/evals/custom-scorers)，了解如何自行构建评分器。
:::
