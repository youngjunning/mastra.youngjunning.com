# Workflow\.agent()

`.agent()` 方法将 Agent 添加为声明式步骤。步骤接受 `{ prompt: string }` 作为输入，默认返回 `{ text: string }`。要根据 Workflow 数据构造 prompt，请在 Agent 步骤之前使用 `.map()`。

与使用 `createStep()` 包装 Agent 不同，`.agent()` 会在 Workflow 图中记录声明式条目。因此，同一张图可以序列化，并作为[动态 Workflow](/docs/workflows/dynamic-workflows) 持久化。

## 使用示例 {/* #usage-example */}

```typescript filename="src/mastra/workflows/test-workflow.ts"
workflow
  .map({ prompt: mapVariable({ initData: workflow, path: 'topic' }) })
  .agent(testAgent)
  .commit()
```

## 结构化输出 {/* #structured-output */}

步骤默认输出 `{ text: string }`。传入 `structuredOutput.schema` 后，步骤将改为返回该 schema 指定的结构。该 schema 也会成为步骤的输出 schema，使后续步骤能够以完整的类型安全性进行链式调用：

```typescript filename="src/mastra/workflows/test-workflow.ts"
import { z } from 'zod'

workflow
  .agent(testAgent, {
    structuredOutput: {
      schema: z.object({
        subtopics: z.array(z.string()),
      }),
    },
  })
  .commit()
```

## 通过 ID 引用 Agent {/* #referencing-an-agent-by-id */}

传入字符串即可引用已注册的 Agent，无需导入其实例。Workflow 运行时，该 Agent 必须已在 Mastra 实例上注册：

```typescript filename="src/mastra/workflows/test-workflow.ts"
workflow.agent('test-agent', { maxSteps: 3 }).commit()
```

## 持久化 Agent 步骤 {/* #persisting-agent-steps */}

使用 `.agent()` 构建的 Workflow 会序列化为与[动态 Workflow](/docs/workflows/dynamic-workflows) 相同的声明式条目。只有 `structuredOutput.schema`（以 JSON Schema 存储）、`retries` 和 `metadata` 能在存储后恢复。存储 Workflow 时，包含函数的选项（例如 `onFinish` 或值为函数的 `toolChoice`）会引发错误。
