# 处理器

基于文件的 Agent 会从其 `processors/` 目录中发现[处理器](/docs/agents/processors)。本页介绍基于文件的约定；内置处理器、自定义处理器、流式行为和高级模式请参阅处理器指南。

`processors/input/` 下的文件会在消息到达模型前运行；`processors/output/` 下的文件会在模型响应后运行。每个文件默认导出一个 [`Processor`](/reference/processors/processor-interface)，文件名将作为其发现键。

## 快速入门 {/* #quickstart */}

将处理器文件放在 `processors/input/` 下，即可添加输入处理器：

```typescript title="src/mastra/agents/weather/processors/input/pii.ts"
import { PIIDetector } from '@mastra/core/processors'

export default new PIIDetector({
  strategy: 'block',
})
```

此处理器会在用户消息到达模型前运行。

## 添加输出处理器 {/* #add-an-output-processor */}

输出处理器适合在返回模型响应前对其进行过滤或转换。此示例会从最终响应中脱敏处理个人身份信息（PII）。

```typescript title="src/mastra/agents/weather/processors/output/redact.ts"
import { PIIDetector } from '@mastra/core/processors'

export default new PIIDetector({
  strategy: 'redact',
})
```

## 顺序 {/* #ordering */}

发现的处理器会添加到 [`config.ts`](/reference/file-based-agents/config) 中定义的处理器之后，因此配置中的处理器会先运行。

```text title="Ordering"
config.inputProcessors → processors/input/* → model
model → config.outputProcessors → processors/output/* → response
```

如果 `config.inputProcessors` 或 `config.outputProcessors` 是函数，系统会忽略所发现的对应类型处理器并发出警告，因为函数形式的处理器无法静态合并。

如果 `config.ts` 导出的是 `new Agent()` 而非配置对象，Mastra 会直接使用该 Agent。系统会忽略在 `processors/input/` 和 `processors/output/` 下发现的文件并发出警告，因此应改为设置 `inputProcessors` 和 `outputProcessors` 到 `Agent` 上。

## 与配置的优先级关系 {/* #precedence-with-config */}

需要在运行时创建或由多个 Agent 共享的处理器，请在 `config.ts` 中配置。应与 Agent 一同审查的静态单 Agent 处理器，则使用基于文件的处理器。

优先级如下：

1. 函数形式的 `config.inputProcessors` 或 `config.outputProcessors`
1. 数组形式的 `config.inputProcessors` 或 `config.outputProcessors`
1. 在 `processors/input/` 或 `processors/output/` 下发现的文件

完整接口请参阅 [`Processor` 参考](/reference/processors/processor-interface)。
