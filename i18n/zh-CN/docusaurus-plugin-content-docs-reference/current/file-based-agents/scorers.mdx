# Scorer

基于文件的 Agent 会从其 `scorers/` 目录发现 Scorer。本页说明基于文件的约定；内置 Scorer、自定义 Scorer 和采样请参阅 [Scorer 指南](/docs/evals/overview)。

`scorers/` 下的每个文件默认导出一个 Scorer，文件名即为其键。默认导出可以是 [`MastraScorer`](/reference/evals/create-scorer)，也可以是 `{ scorer, sampling }` 条目。

## 快速入门 {/* #quickstart */}

在 Agent 的 `scorers/` 目录下放置文件即可添加 Scorer。以下示例使用[自定义 Scorer](/docs/evals/custom-scorers)：

```typescript title="src/mastra/agents/weather/scorers/relevance.ts"
import { createScorer } from '@mastra/core/evals'

export default createScorer({
  id: 'relevance',
  description: 'Scores how relevant the response is',
}).generateScore(() => 1)
```

此 Scorer 会以 `relevance` 为键注册到 `weather` Agent，效果与将其添加到 `config.scorers` 相同。

## 采样 {/* #sampling */}

要控制 Scorer 的运行频率，请默认导出 `{ scorer, sampling }` 条目，而不是单独的 Scorer：

```typescript title="src/mastra/agents/weather/scorers/relevance.ts"
import { createScorer } from '@mastra/core/evals'

const relevance = createScorer({
  id: 'relevance',
  description: 'Scores how relevant the response is',
}).generateScore(() => 1)

export default {
  scorer: relevance,
  sampling: { type: 'ratio', rate: 0.5 },
}
```

## 配置的优先级 {/* #precedence-with-config */}

发现的 Scorer 会与 [`config.ts`](/reference/file-based-agents/config) 中定义的 Scorer 合并。键冲突时，以 `config.scorers` 为准并发出警告。如果 `config.scorers` 是函数，则无法静态合并，已发现的 Scorer 会被忽略并发出警告。

键冲突时，优先级如下：

1. 函数形式的 `config.scorers`
1. 对象形式的 `config.scorers`
1. `scorers/` 下发现的文件

没有键冲突的已发现 Scorer 会保留。

完整 Scorer 接口请参阅 [`createScorer()`](/reference/evals/create-scorer)。
