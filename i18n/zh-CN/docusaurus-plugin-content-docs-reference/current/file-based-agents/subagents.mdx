# 子 Agent

基于文件的 Agent 可以声明 **subagents（子 Agent）**，将任务委托给具备专长的子 Agent。父 Agent 使用的模型会把每个子 Agent 视为一个以其目录命名的委托 Tool，并通过调用该 Tool 交出任务。子 Agent 的结果会返回父 Agent 的对话。

本页介绍基于文件的配置约定。有关更一般的委托模式、钩子、Memory 隔离、Tool 审批传递和评分，请参阅 [Supervisor Agent](/docs/subagents)。

## 快速入门 {/* #quickstart */}

在 `subagents/` 下为每个子 Agent 创建一个目录：

```text title="Subagent layout"
src/mastra/agents/
└── supervisor/
    ├── config.ts
    ├── instructions.md
    └── subagents/
        └── researcher/
            ├── config.ts
            ├── instructions.md
            └── tools/
                └── search.ts
```

Mastra 会将 `researcher` 组装成独立的 Agent，并将其接入主管 Agent 的 `agents` 映射。父 Agent 使用的模型可以通过生成的 `researcher` 委托 Tool 向其分派任务。

子 Agent 的 `config.ts` 必须设置非空的 `description`。父 Agent 使用的模型会根据该描述决定是否委托任务。

```typescript title="src/mastra/agents/supervisor/subagents/researcher/config.ts"
import { agentConfig } from '@mastra/core/agent'

export default agentConfig({
  model: '__GATEWAY_OPENAI_MODEL__',
  description: 'Researches a topic and returns cited findings.',
})
```

## 模型如何委托 {/* #how-the-model-delegates */}

子 Agent 的 `description` 是供父 Agent 使用的模型判断委托对象的路由说明。编写方式与 [Tool 描述](/reference/file-based-agents/tools#tool-options)相同：说明子 Agent 能做什么，以及何时应将任务委托给它。

如果发现的子 Agent 没有提供非空描述，构建会失败。例外情况是父 Agent 的 `config.ts` 导出了 `new Agent()`：此时会发出警告并忽略其 `subagents/` 目录，因此不会检查描述。应改为设置 `agents`，并将其配置在该 `Agent` 上。

## 隔离 {/* #isolation */}

子 Agent 彼此隔离，也不会继承父 Agent 的 Tool、Skill、Workspace、Memory、处理器或其他子 Agent。每个子 Agent 都是拥有自己目录的独立 Agent。

如果多个 Agent 需要共享同一个依赖项，请在代码中定义该依赖项，再通过各 Agent 的配置分别指定。

## 嵌套 {/* #nesting */}

子 Agent 也可以声明自己的 `subagents/` 目录，最多可在顶层 Agent 下嵌套三级。更深层的 `subagents/` 目录会被忽略，并产生警告。

```text title="Nested subagents"
src/mastra/agents/
└── supervisor/            # depth 0
    └── subagents/
        └── researcher/    # depth 1
            └── subagents/
                └── summarizer/ # depth 2
```

## 命名规则 {/* #naming-rules */}

- 子 Agent ID 与父 Agent 的某个 Tool 键冲突时，构建会失败。
- 同一父 Agent 下出现重复的子 Agent ID 时，构建会失败。
- 如果子 Agent ID 也存在于父 Agent 的 `config.agents` 中，则以 `config.agents` 中的条目为准，并记录警告。
- 如果 `config.agents` 是函数，则无法进行静态合并；发现的子 Agent 会被忽略，并记录警告。

## 示例 {/* #example */}

这个主管 Agent 负责协调研究与写作流程。`researcher` 子 Agent 拥有搜索 Tool，`writer` 子 Agent 则拥有用于起草文件的 Workspace。

```text title="Research supervisor"
src/mastra/agents/
└── research-supervisor/
    ├── config.ts
    ├── instructions.md
    └── subagents/
        ├── researcher/
        │   ├── config.ts
        │   ├── instructions.md
        │   └── tools/
        │       └── search_web.ts
        └── writer/
            ├── config.ts
            ├── instructions.md
            └── workspace/
                └── draft-template.md
```

```typescript title="src/mastra/agents/research-supervisor/config.ts"
import { agentConfig } from '@mastra/core/agent'

export default agentConfig({
  model: '__GATEWAY_OPENAI_MODEL__',
})
```

```markdown title="src/mastra/agents/research-supervisor/instructions.md"
You coordinate research and writing.

Delegate fact gathering to `researcher`. Delegate final drafting to `writer`.
```

```typescript title="src/mastra/agents/research-supervisor/subagents/researcher/config.ts"
import { agentConfig } from '@mastra/core/agent'

export default agentConfig({
  model: '__GATEWAY_OPENAI_MODEL_LUNA__',
  description: 'Use to gather facts, sources, and concise research notes for a topic.',
})
```

```typescript title="src/mastra/agents/research-supervisor/subagents/writer/config.ts"
import { agentConfig } from '@mastra/core/agent'

export default agentConfig({
  model: '__GATEWAY_OPENAI_MODEL__',
  description: 'Use to turn research notes into a structured draft.',
})
```
