# 工作空间

一个[workspace](/docs/sandbox/overview)集合文件系统访问和命令执行等功能。配置的后端决定哪些Tool可用。基于文件的Agent在通过以下方式发现时会自动获得默认Workspace`mastra dev`或者`mastra build`。此默认值包括文件系统访问和命令执行，因此Agent可以读取和写入文件以及运行 shell 命令，而无需额外配置。

使用此页面进行基于文件的约定。有关Workspace提供程序、Tool、搜索、生命周期和Sandbox的详细信息，请参阅[Sandbox](/docs/sandbox/overview).

## 默认Workspace {/* #default-workspace */}

没有`workspace.ts`, a file-based agent gets a default [`Workspace`](/reference/workspace/workspace-class) when the build provides a per-agent workspace path. The default workspace uses:

* [`LocalFilesystem`](/reference/workspace/local-filesystem)植根于Agent的捆绑Workspace目录。
* [`LocalSandbox`](/reference/workspace/local-sandbox)具有相同的工作目录。

这会自动提供Agent文件Tool和 shell Tool。默认Workspace是每个Agent的。子Agent在其父Agent的Workspace路径下获取嵌套Workspace目录。

## 禁用默认Workspace {/* #disable-the-default-workspace */}

放`workspace` to `undefined` in `config.ts` to create the agent without a workspace:

```typescript title="src/mastra/agents/weather/config.ts"
import { agentConfig } from '@mastra/core/agent'

export default agentConfig({
  model: '__GATEWAY_OPENAI_MODEL__',
  workspace: undefined,
})
```

当您禁用Workspace时，Agent不会接收自动文件和 shell Tool。

## 快速入门 {/* #quickstart */}

对于默认Workspace，不要添加文件。从这样的Agent目录开始：

```text title="Default workspace"
src/mastra/agents/weather/
├── config.ts
└── instructions.md
```

添加`workspace.ts` only when you need to customize the workspace:

```typescript title="src/mastra/agents/weather/workspace.ts"
import { Workspace, LocalFilesystem, LocalSandbox } from '@mastra/core/workspace'

export default new Workspace({
  name: 'weather-workspace',
  filesystem: new LocalFilesystem({ basePath: './data/weather' }),
  sandbox: new LocalSandbox({ workingDirectory: './data/weather' }),
})
```

参观[`Workspace` reference](/reference/workspace/workspace-class) for the full config.

## 何时自定义Workspace {/* #when-to-customize-the-workspace */}

当默认本地目录不够时自定义Workspace。常见原因包括：

* 将文件Tool指向不同的文件系统根目录。
* 在不同的Sandbox提供程序中运行 shell 命令。
* 使用 BM25 或矢量搜索添加Workspace搜索。
* 跨多个Agent共享一个Workspace。

有关提供程序模式和运行时行为，请参阅[sandbox guide](/docs/sandbox/overview) and [workspace search](/docs/sandbox/search).

## 运行时边界 {/* #runtime-boundary */}

Workspace文件系统控制文件Tool访问，Sandbox确定 shell 命令的运行位置。除非显式调用Workspace或Sandbox API，否则应用程序运行时代码仍会在您的应用程序或服务器进程中运行，包括[`tools/`](/reference/file-based-agents/tools).

## 种子文件 {/* #seed-files */}

添加一个`workspace/` directory to include starting files with the agent. Mastra mirrors files under `workspace/` into the agent's default runtime workspace at build time. The agent starts with those files on disk.

```text title="Seed files"
src/mastra/agents/weather/
├── config.ts
└── workspace/
    ├── README.md
    └── data/
        └── cities.json
```

这些文件被复制到捆绑的Workspace路径中，Workspace文件Tool和Sandbox命令可以在其中读取它们。镜像过程中会跳过符号链接的种子文件。

## 配置的优先级 {/* #precedence-with-config */}

`config.workspace`战胜`workspace.ts`, including when you set it to `undefined`. Otherwise, Mastra uses the default file-based workspace. See [`config.ts` precedence](/reference/file-based-agents/config#precedence) for the full merge table.
