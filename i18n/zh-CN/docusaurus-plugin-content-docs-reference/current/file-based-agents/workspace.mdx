# Workspace

[Workspace](/docs/sandbox/overview) 汇集文件系统访问、命令执行等能力；配置的后端决定可用的 Tool。通过 `mastra dev` 或 `mastra build` 发现基于文件的 Agent 时，Mastra 会自动为其提供默认 Workspace。默认 Workspace 包含文件系统访问和命令执行能力，因此 Agent 无需额外配置即可读写文件、运行 shell 命令。

本页介绍基于文件的 Agent 所遵循的约定。关于 Workspace Provider、Tool、搜索、生命周期和 Sandbox 的详情，请参阅 [Sandbox](/docs/sandbox/overview)。

## 默认 Workspace {/* #default-workspace */}

如果没有 `workspace.ts`，且构建过程为每个 Agent 提供了 Workspace 路径，基于文件的 Agent 就会获得默认 [`Workspace`](/reference/workspace/workspace-class)。默认 Workspace 使用：

- [`LocalFilesystem`](/reference/workspace/local-filesystem)：以 Agent 打包后的 Workspace 目录为根目录。
- [`LocalSandbox`](/reference/workspace/local-sandbox)：使用相同的工作目录。

这样会自动为 Agent 提供文件 Tool 和 shell Tool。每个 Agent 都有独立的默认 Workspace；子 Agent 的 Workspace 目录嵌套在父 Agent 的 Workspace 路径下。

## 禁用默认 Workspace {/* #disable-the-default-workspace */}

将 `workspace` 设为 `undefined`（在 `config.ts` 中），即可创建不带 Workspace 的 Agent：

```typescript title="src/mastra/agents/weather/config.ts"
import { agentConfig } from '@mastra/core/agent'

export default agentConfig({
  model: '__GATEWAY_OPENAI_MODEL__',
  workspace: undefined,
})
```

禁用 Workspace 后，Agent 不会自动获得文件 Tool 和 shell Tool。

## 快速入门 {/* #quickstart */}

使用默认 Workspace 时，无需添加额外文件。Agent 目录可以从以下结构开始：

```text title="Default workspace"
src/mastra/agents/weather/
├── config.ts
└── instructions.md
```

只有需要自定义 Workspace 时才添加 `workspace.ts`：

```typescript title="src/mastra/agents/weather/workspace.ts"
import { Workspace, LocalFilesystem, LocalSandbox } from '@mastra/core/workspace'

export default new Workspace({
  name: 'weather-workspace',
  filesystem: new LocalFilesystem({ basePath: './data/weather' }),
  sandbox: new LocalSandbox({ workingDirectory: './data/weather' }),
})
```

完整配置请参阅 [`Workspace` 参考文档](/reference/workspace/workspace-class)。

## 何时自定义 Workspace {/* #when-to-customize-the-workspace */}

默认本地目录无法满足需求时，可以自定义 Workspace。常见原因包括：

- 让文件 Tool 使用不同的文件系统根目录。
- 在其他 Sandbox Provider 中运行 shell 命令。
- 为 Workspace 添加 BM25 或向量搜索。
- 让多个 Agent 共用一个 Workspace。

有关 Provider 配置方式和运行时行为，请参阅 [Sandbox 指南](/docs/sandbox/overview)和 [Workspace 搜索](/docs/sandbox/search)。

## 运行时边界 {/* #runtime-boundary */}

Workspace 的文件系统控制文件 Tool 的访问范围，Sandbox 决定 shell 命令在哪里运行。应用运行时代码（包括 [`tools/`](/reference/file-based-agents/tools) 中的代码）仍在应用或服务器进程中运行，除非它显式调用 Workspace 或 Sandbox API。

## 初始文件 {/* #seed-files */}

添加 `workspace/` 目录，即可为 Agent 提供初始文件。构建时，Mastra 会将 `workspace/` 下的文件复制到 Agent 默认的运行时 Workspace；Agent 启动时，这些文件已经位于磁盘上。

```text title="Seed files"
src/mastra/agents/weather/
├── config.ts
└── workspace/
    ├── README.md
    └── data/
        └── cities.json
```

文件会复制到打包后的 Workspace 路径，供 Workspace 文件 Tool 和 Sandbox 命令读取。复制时会跳过符号链接形式的初始文件。

## 与 config 的优先级 {/* #precedence-with-config */}

`config.workspace` 的优先级高于 `workspace.ts`，即使将其设为 `undefined` 也是如此。否则，Mastra 使用默认的基于文件的 Workspace。完整合并规则请参阅 [`config.ts` 优先级](/reference/file-based-agents/config#precedence)。
