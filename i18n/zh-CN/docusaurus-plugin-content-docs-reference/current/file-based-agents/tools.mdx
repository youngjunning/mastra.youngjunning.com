# Tool

基于文件的 Agent 会发现 `.ts` 和 `.js` 文件，前提是它们直接位于 Agent 的 `tools/` 目录中。每个发现的文件都会在构建时导入，并且必须默认导出一个 Tool。只要是 Agent 的 `tools` 选项接受的 Tool，就可以放在这里，例如 [`createTool()`](/reference/tools/create-tool) 的返回值或 Vercel AI SDK 的 `tool()`。去掉扩展名的文件名就是模型调用该 Tool 时使用的键。

本页介绍基于文件的 Tool 约定。Tool 的 Schema、执行选项、输出格式处理和审批选项，见 [`createTool()` 参考文档](/reference/tools/create-tool)。

## 快速入门 {/* #quickstart */}

在 `tools/` 下每个文件放置一个 Tool。以下文件会以 `get_weather` 这个键提供给 Agent。

```typescript title="src/mastra/agents/weather/tools/get_weather.ts"
import { createTool } from '@mastra/core/tools'
import { z } from 'zod'

export default createTool({
  id: 'get_weather',
  description: 'Get the current weather for a location.',
  inputSchema: z.object({
    location: z.string(),
  }),
  outputSchema: z.object({
    location: z.string(),
    temperatureCelsius: z.number(),
    conditions: z.string(),
  }),
  execute: async ({ location }) => {
    return { location, temperatureCelsius: 21, conditions: 'sunny' }
  },
})
```

## 组织 Tool 文件 {/* #organizing-tools */}

每个 Tool 使用一个文件，并根据希望模型执行的操作为文件命名：

* 使用 `get_weather.ts`、`search_docs.ts` 或 `create_ticket.ts` 这样的名称。
* 避免 `helper.ts`、`api.ts` 或 `utils.ts` 等含义模糊的名称。
* 测试文件可以与 Tool 放在一起，命名为 `*.test.ts` 或 `*.spec.ts`；发现机制会忽略这些文件。
* 共享辅助代码应放在 `tools/` 之外，或放在 `tools/` 下不符合发现规则的文件中。

嵌套目录中的文件不会被发现为 Tool。要组织相关 Tool，请使用清晰的文件名前缀而不是子目录，例如 `calendar_create_event.ts` 和 `calendar_list_events.ts`。

## Tool 选项 {/* #tool-options */}

基于文件的约定只决定 Tool 的位置和注册方式；选项由 Tool 自身定义。对于通过 `createTool()` 创建的 Tool：

* 使用 `description` 告诉模型何时调用该 Tool。
* 使用 `inputSchema` 和 `outputSchema` 定义结构化输入和输出。
* 使用 `toModelOutput`，可以让模型看到不同于 `execute` 原始返回值的输出格式。
* 如果 Tool 执行前需要人工确认，使用 `requireApproval`。

完整选项见 [`createTool()` 参考文档](/reference/tools/create-tool)；审批流程见 [Tool 审批](/docs/harness/agent-controller#approve-tools-and-resume-suspensions)。Vercel AI SDK Tool 则使用 [AI SDK 的 `tool()` API](https://ai-sdk.dev/docs/reference/ai-sdk-core/tool)。

## 运行时边界 {/* #runtime-boundary */}

Agent 调用 Tool 时，Tool 代码会在应用或服务器的运行时中执行。如果 Tool 需要隔离文件系统或 shell 操作，请显式调用 [Workspace](/reference/file-based-agents/workspace) 或 Sandbox API。

## 配置的优先级 {/* #precedence-with-config */}

自动发现的 Tool 会与 `tools` 配置合并，该配置位于 [`config.ts`](/reference/file-based-agents/config)。如果键名冲突，以 `config.tools` 为准，同时记录警告。

如果 `config.tools` 是函数，系统会忽略自动发现的 Tool 并记录警告，因为函数形式的 Tool 配置无法静态合并。
