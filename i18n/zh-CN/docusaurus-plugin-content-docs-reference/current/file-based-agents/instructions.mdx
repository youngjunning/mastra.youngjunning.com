# 指示

Agent的指令保留其始终在线的系统提示：模型每次都会读取它。使用它们来定义Agent的身份、语气、角色和站立规则。

将它们写入Agent根目录下的两个文件之一。使用`instructions.md` when the prompt is fixed text. Use `instructions.ts`当提示需要代码时，例如当它是从共享常量构建或根据请求解析时。

说明始终在上下文中，因此请保留它们以确保适用于每个请求的稳定行为。将任何有条件的、大型的或以行动为导向的东西移入[`tools/`](/reference/file-based-agents/tools) or [`skills/`](/reference/file-based-agents/skills), which the model uses only when relevant.

## 快速入门 {/* #quickstart */}

添加一个`instructions.md` at the agent root. Whatever you write becomes the prompt, so the shortest version is a single sentence.

```markdown title="src/mastra/agents/weather/instructions.md"
You are a helpful weather assistant. Answer questions about current conditions and forecasts.
```

## 说明中包含哪些内容 {/* #what-goes-in-instructions */}

有效的指令涵盖了Agent行为中在请求之间不会改变的部分：

* 角色和身份
* 语气和风格
* 常设规则
* 输出格式

将有条件的、大型的或以行动为导向的指导移入[`tools/`](/reference/file-based-agents/tools) or [`skills/`](/reference/file-based-agents/skills), which the model uses only when relevant.

## TypeScript 中的说明 {/* #instructions-in-typescript */}

使用`instructions.ts` when markdown can't express the prompt. The file default-exports a string, a system message, a non-empty array of strings or system messages, or a function returning one, and `agentInstructions()` types the export without changing it.

当提示在代码中组装时导出字符串，例如从与应用程序的其余部分共享的常量：

```typescript title="src/mastra/agents/weather/instructions.ts"
import { agentInstructions } from '@mastra/core/agent'
import { SUPPORTED_UNITS } from '../../constants'

export default agentInstructions(`
You are a helpful weather assistant.
Report conditions using one of these units: ${SUPPORTED_UNITS.join(', ')}.
`)
```

当提示取决于请求时导出函数。 Mastra 每次都会调用它并传递请求上下文：

```typescript title="src/mastra/agents/support/instructions.ts"
import { agentInstructions } from '@mastra/core/agent'

export default agentInstructions(({ requestContext }) => {
  const tier = requestContext.get('tier') ?? 'standard'
  return `You are a support agent. Treat this as a ${tier}-tier customer.`
})
```

该函数可以是`async`. Alongside `requestContext`, it receives `mastra`, the Mastra instance the agent is registered with, so it can read from storage or another registered primitive before returning the prompt. `mastra` is optional in the function type, so guard its use (for example, `mastra?.getStorage()`).

这两个文件也可以存在于[subagent](/reference/file-based-agents/subagents) directory, which follows the same rules.

## 构建时行为 {/* #build-time-behavior */}

`instructions.md`和`instructions.ts` reach the deployed agent differently:

* `instructions.md`：Mastra 读取文件并在构建时将其内容内联到生成的代码中。
* `instructions.ts`：生成的代码导入模块，因此它像任何其他 TypeScript 文件一样捆绑在一起，并且可以从项目的其余部分导入。

在下面`mastra dev`, editing either file triggers a rebuild. In a deployed app neither file is read from disk at runtime, so changes take effect after the next build.

## 配置的优先级 {/* #precedence-with-config */}

指令可以来自`instructions.ts`, `instructions.md`, or the `instructions` field in [`config.ts`](/reference/file-based-agents/config):

* 运行时定义的（函数）`instructions` in `config.ts` wins over both files.
* 否则`instructions.ts` wins over `instructions.md`.
* `instructions.md`战胜静电`instructions` string in `config.ts`.
* 如果不存在，则构建失败并命名Agent目录。

在多个位置定义指令会记录一条警告，其中列出了两个源的名称以及哪个源获胜。每个Agent保留一个来源。
