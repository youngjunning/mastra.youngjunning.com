# 指令

Agent 的指令包含常驻的系统提示，模型每轮都会读取。用它来定义 Agent 的身份、语气、角色和长期规则。

将指令写在 Agent 根目录下的两个文件之一：固定文本使用 `instructions.md`；需要通过代码构建提示（例如引用共享常量或按请求动态生成）时使用 `instructions.ts`。

指令始终包含在上下文中，因此只应放入适用于每个请求的稳定行为。对于有条件、篇幅较长或偏向具体操作的内容，请放入 [`tools/`](/reference/file-based-agents/tools) 或 [`skills/`](/reference/file-based-agents/skills)；模型仅在相关时使用这些内容。

## 快速开始 {/* #quickstart */}

在 Agent 根目录添加 `instructions.md`。文件内容会直接成为提示，因此最简版本只需一句话。

```markdown title="src/mastra/agents/weather/instructions.md"
You are a helpful weather assistant. Answer questions about current conditions and forecasts.
```

## 指令应包含什么 {/* #what-goes-in-instructions */}

有效的指令应涵盖 Agent 在不同请求之间保持不变的行为：

- 角色与身份
- 语气与风格
- 长期适用的规则
- 输出格式

有条件、篇幅较长或偏向具体操作的指导，请移至 [`tools/`](/reference/file-based-agents/tools) 或 [`skills/`](/reference/file-based-agents/skills)；模型仅在相关时使用。

## 在 TypeScript 中编写指令 {/* #instructions-in-typescript */}

当 Markdown 无法表达所需提示时，使用 `instructions.ts`。该文件默认导出字符串、系统消息、由字符串或系统消息组成的非空数组，或返回其中一种值的函数。`agentInstructions()` 只为导出值提供类型，不会修改它。

当提示由代码拼接时，可以导出字符串，例如使用应用其他部分共享的常量：

```typescript title="src/mastra/agents/weather/instructions.ts"
import { agentInstructions } from '@mastra/core/agent'
import { SUPPORTED_UNITS } from '../../constants'

export default agentInstructions(`
You are a helpful weather assistant.
Report conditions using one of these units: ${SUPPORTED_UNITS.join(', ')}.
`)
```

当提示取决于请求时，可以导出函数。Mastra 每轮都会调用它，并传入请求上下文：

```typescript title="src/mastra/agents/support/instructions.ts"
import { agentInstructions } from '@mastra/core/agent'

export default agentInstructions(({ requestContext }) => {
  const tier = requestContext.get('tier') ?? 'standard'
  return `You are a support agent. Treat this as a ${tier}-tier customer.`
})
```

此函数可以是 `async`。除了 `requestContext`，它还会接收 Agent 所注册的 Mastra 实例 `mastra`，因此可在返回提示前从存储或其他已注册组件读取数据。函数类型中的 `mastra` 是可选的，使用前须检查，例如 `mastra?.getStorage()`。

这两种文件也可以放在 [subagent](/reference/file-based-agents/subagents) 目录中，规则相同。

## 构建时行为 {/* #build-time-behavior */}

`instructions.md` 和 `instructions.ts` 以不同方式进入已部署的 Agent：

- `instructions.md`：Mastra 在构建时读取文件，并将内容内联到生成的代码中。
- `instructions.ts`：生成的代码会导入该模块，因此它与其他 TypeScript 文件一样参与打包，也可以导入项目中的其他模块。

运行 `mastra dev` 时，编辑任一文件都会触发重新构建。应用部署后，运行时不会从磁盘读取这两个文件；修改要等到下次构建才会生效。

## 与配置的优先级关系 {/* #precedence-with-config */}

指令可以来自 `instructions.ts`、`instructions.md`，也可以来自 `instructions` 字段（位于 [`config.ts`](/reference/file-based-agents/config)）：

- 运行时定义的函数形式 `instructions`（位于 `config.ts`）优先于两个文件。
- 否则，`instructions.ts` 优先于 `instructions.md`。
- `instructions.md` 优先于静态的 `instructions` 字符串（位于 `config.ts`）。
- 如果三者都不存在，构建会失败，并指出 Agent 目录。

如果在多个位置定义指令，系统会记录警告，列出冲突来源及生效的来源。每个 Agent 只保留一个指令来源。
