# 存储

Mastra 从 `src/mastra/` 目录下的 `storage.ts` 文件读取项目的默认[存储](/docs/storage)。该文件默认导出的存储实例会取代 Memory、Workflow、可观测性及其他存储领域使用的内置内存存储。

本页介绍如何通过文件配置存储。后端选型、存储领域、数据保留和 Provider 的详情见[存储概览](/docs/storage)。

## 快速入门 {/* #quickstart */}

如果需要将数据保存在本地文件中，可以使用 [`LibSQLStore`](/integrations/databases/libsql)。

```typescript title="src/mastra/storage.ts"
import { LibSQLStore } from '@mastra/libsql'

export default new LibSQLStore({
  id: 'mastra-storage',
  url: 'file:./mastra.db',
})
```

Mastra 会先注册存储实例，再注册基于文件的 Agent 和 Workflow。依赖存储的组件会绑定到该实例，取代默认的内存存储。

## 生产环境的存储后端 {/* #production-backends */}

`storage.ts` 可以导出任意 Mastra 存储适配器，例如 LibSQL、PostgreSQL 或 MongoDB。配置方式、Provider 支持和 schema 详情见[存储概览](/docs/storage)、[可观测性信号支持](/docs/observability/overview#signal-support)及[存储参考](/reference/storage/overview)。

## 文件配置与代码配置的优先级 {/* #precedence-with-code */}

通过代码注册的存储优先于 `storage.ts`。整个项目只需一个存储实例时，可使用 `storage.ts`。如果存储设置取决于运行时的组件装配，请在 `src/mastra/index.ts` 中通过代码注册。
