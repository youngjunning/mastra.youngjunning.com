# 时间表

基于文件的Agent发现**schedules**从它的`schedules/`目录。每个文件都声明一个重复任务：一个 cron 表达式以及Agent在触发时应该执行的操作。 Mastra 在启动时将它们注册到计划存储中。计划Agent不需要运行时注册代码。

使用此页面进行基于文件的约定。要在运行时创建计划，请参阅[Schedules](/reference/schedules/overview).

`defineSchedule`重新出口自`@mastra/core/agent` so file-based agents need one import path. `@mastra/core/schedules` exports it too.

## 快速入门 {/* #quickstart */}

在agent下添加一个文件`schedules/` directory:

```typescript title="src/mastra/agents/support/schedules/heartbeat.ts"
import { defineSchedule } from '@mastra/core/agent'

export default defineSchedule({
  cron: '*/5 * * * *',
  prompt: 'Check system health and report any failures.',
})
```

每五分钟，Mastra 运行一次`support` agent with that prompt.

## 时间表身份 {/* #schedule-identity */}

时间表的 id 是其相对路径`schedules/` with the extension stripped, so nested directories are a way to group related schedules:

```text title="Schedule layout"
src/mastra/agents/
└── support/
    ├── config.ts
    ├── instructions.md
    └── schedules/
        ├── heartbeat.ts      # id: heartbeat
        ├── cleanup.md        # id: cleanup
        └── billing/
            └── sweep.ts      # id: billing/sweep
```

该 ID 在各个版本中都是稳定的，这让 Mastra 可以区分编辑后的时间表和新的时间表。重命名或移动文件被视为删除一个计划并创建另一个计划。

`heartbeat.ts`和`heartbeat.md` resolve to the same id, so declaring both is a build error.

## 执行模式 {/* #execution-modes */}

时间表恰好设置一种执行模式。设置两者或都不设置都会导致构建失败。

### 提示方式 {/* #prompt-mode */}

`prompt`使用固定消息运行所属Agent。当调度以线程为目标时，火灾会发送唤醒信号并返回而不等待运行，因为线程流运行时驱动运行完成，而无线程调度则等待`agent.generate` and doesn't finish until the run does.

```typescript title="src/mastra/agents/support/schedules/digest.ts"
import { defineSchedule } from '@mastra/core/agent'

export default defineSchedule({
  cron: '0 9 * * 1',
  timezone: 'America/New_York',
  prompt: 'Summarize last week and post the digest.',
})
```

### 处理程序模式 {/* #handler-mode */}

`handler`当计划触发时计算火灾参数。当提示取决于当前状态、应跳过某些触发或运行需要通道传递上下文时，请使用它。

```typescript title="src/mastra/agents/support/schedules/billing/sweep.ts"
import { defineSchedule } from '@mastra/core/agent'

export default defineSchedule({
  cron: '0 3 * * *',
  handler: async ({ mastra, agentId }) => {
    const overdue = await findOverdueInvoices()

    // Returning null skips this fire; nothing runs and the trigger is
    // recorded with outcome 'skipped'.
    if (overdue.length === 0) return null

    return {
      prompt: `Chase these overdue invoices: ${overdue.join(', ')}`,
      threadId: 'billing-ops',
      resourceId: agentId,
    }
  },
})
```

处理程序的返回值合并到计划的存储字段中。返回`undefined` applies no overrides. The fire falls back to those stored fields. Since a handler-mode schedule can't declare a `prompt`, that fire then fails for a missing prompt. Return a `prompt` to run, or `null` to skip.

处理程序是函数，因此它们无法保留在存储的计划行上。当计划触发时，Mastra 会在进程中解决这些问题。不提供提示（并且声明不提示）的处理程序模式计划会因原因而失败，而不是向Agent发送空消息。

进程内查找意味着运行调度程序的进程必须注册拥有Agent。正常部署会启动单个条目并免费获取该条目。独立工作人员需要与服务器相同的条目。从修剪过的条目启动一个，它没有可调用的处理程序。它的火不是熄灭而是熄灭。

### 降价时间表 {/* #markdown-schedules */}

一个`.md` schedule uses frontmatter for the cron and the document body as the prompt. This is prompt mode with more room to write:

```markdown title="src/mastra/agents/support/schedules/cleanup.md"
---
cron: '0 3 * * *'
timezone: 'UTC'
name: 'nightly cleanup'
---

Review tickets untouched for 30 days.

Close the ones that are clearly resolved and summarize the rest.
```

始终引用 cron。领先的`*` is a YAML alias, so `cron: */5 * * * *` is a parse error while `cron: "*/5 * * * *"` is fine.

Frontmatter 接受以下所有选项，除了`handler`, which needs a function and so needs a `.ts` or `.js` schedule module. `prompt` isn't settable either, because the body is the prompt. Unknown frontmatter fields fail the build rather than being silently ignored, so a typo like `ifIdel` is caught at build time.

## 测试开发中的时间表 {/* #testing-a-schedule-in-development */}

安排在其 cron 节奏上触发，这在迭代时是不切实际的。而是根据 id 按需触发一个：

```bash
# List schedules to find the id
curl http://localhost:4111/api/schedules

# Fire one now, out-of-band from its cron
curl -X POST http://localhost:4111/api/schedules/<scheduleId>/run
```

这记录了一个触发器`triggerKind: "manual"` and doesn't advance `nextFireAt`, so the regular cadence is unaffected. Studio lists the same schedules and their trigger history.

存储的 ID 是命名空间和 URL 编码的。`billing/sweep` on the `support` agent becomes `fsa_support__billing%2Fsweep`, so copy the id from the list response rather than assembling it by hand.

## 注册和生命周期 {/* #registration-and-lifecycle */}

Mastra 在启动时将声明的时间表同步到时间表存储中，并在Agent注册后再次同步。声明一个调度就足以启动调度程序，无需`scheduler: { enabled: true }` needed.

同步将每个声明的计划与其存储的行进行比较，并仅写入更改的内容：

* 新的计划文件创建一行。
* 编辑`cron` or `timezone` patches the row and recomputes the next fire time, so an edited schedule never fires on its old cadence.
* 删除或重命名计划文件会删除其行。
* 通过 API 暂停计划在重新部署后仍然有效。同步故意离开`status` alone.

同步仅删除属于当前进程中注册的Agent的行，因此保存Agent子集的进程永远不会删除其他Agent的计划。当Agent从项目中完全删除时，当调度程序发现没有Agent可以运行时，其剩余行将在下次触发时被清理。

运行时创建的时间表通过`mastra.schedules.create(...)` live in a separate namespace and are never touched by this sync.

## 限制 {/* #limits */}

**仅限根Agent。**&#x5411;顶级Agent声明时间表。一个`schedules/` directory under `subagents/` causes a build error because subagents are wired into their parent instead of being registered on the Mastra instance, leaving the scheduler unable to resolve them as targets. Give the parent the schedule and let it delegate.

**需要存储。**&#x7531;于计划是持久化的行，并且内存存储中的行在重新启动后无法继续存在，因此实例需要[storage](/reference/file-based-agents/storage) configured.

**主持。**&#x8C03;度程序作为 Mastra 进程内的后台工作程序运行，因此它需要一个主机来保持该进程处于活动状态。长时间运行的节点服务器和容器可以工作。冻结或回收请求之间的进程的环境（包括大多数无服务器功能平台）将错过火灾。使用平台自己的 cron 来调用那里的运行端点。

**代码定义的Agent。**&#x4E00;个Agent目录，其`config.ts` exports `new Agent({...})` is used verbatim, so its `schedules/` directory is ignored with a warning. Use `mastra.schedules.create(...)` for those.

## 例子 {/* #example */}

支持Agent有两个时间表：固定的每周摘要，以及仅在有事情要做时运行的夜间清理。

```text title="Scheduled support agent"
src/mastra/agents/
└── support/
    ├── config.ts
    ├── instructions.md
    └── schedules/
        ├── weekly-digest.md
        └── billing/
            └── sweep.ts
```

```typescript title="src/mastra/agents/support/config.ts"
import { agentConfig } from '@mastra/core/agent'

export default agentConfig({
  model: '__GATEWAY_OPENAI_MODEL__',
})
```

```markdown title="src/mastra/agents/support/schedules/weekly-digest.md"
---
cron: '0 9 * * 1'
timezone: 'America/New_York'
---

Summarize the past week's tickets and post the digest to the team channel.
```

```typescript title="src/mastra/agents/support/schedules/billing/sweep.ts"
import { defineSchedule } from '@mastra/core/agent'

export default defineSchedule({
  cron: '0 3 * * *',
  timezone: 'America/New_York',
  handler: async () => {
    const overdue = await findOverdueInvoices()
    if (overdue.length === 0) return null
    return { prompt: `Draft reminders for ${overdue.length} overdue invoices.` }
  },
})
```
