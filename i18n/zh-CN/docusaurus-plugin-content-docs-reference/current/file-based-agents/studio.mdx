# Studio

Mastra 从 `src/mastra/` 目录下的 `studio.ts` 文件读取 [Studio](/docs/studio/overview) 配置。该文件默认导出的 `StudioConfig` 对象负责身份验证和授权，决定谁可以访问 Studio，以及通过身份验证的用户可以执行哪些操作。

本页介绍如何通过文件配置 Studio。身份验证 Provider、基于角色的访问控制（RBAC）和细粒度授权（FGA）的详情见 [Studio 身份验证与授权](/docs/studio/auth)。

## 快速入门 {/* #quickstart */}

本地开发无需 `studio.ts`。启动开发服务器后即可打开 Studio。

```bash npm2yarn
npm run dev
```

本地开发时，打开 Studio 无需身份验证。准备保护共享环境或生产环境中的部署时，请添加 `studio.ts`。

## 添加身份验证 {/* #add-authentication */}

使用身份验证 Provider，要求用户登录后才能访问 Studio。本例使用 [WorkOS](/integrations/auth/workos)。

```typescript title="src/mastra/studio.ts"
import { MastraAuthWorkos } from '@mastra/auth-workos'
import type { StudioConfig } from '@mastra/core/server'

export default {
  auth: new MastraAuthWorkos(),
} satisfies StudioConfig
```

身份验证 Provider 确认用户是谁。要控制用户登录后能执行哪些操作，请在同一配置中添加 RBAC 或 FGA。完整示例见 [Studio 身份验证与授权](/docs/studio/auth)。

## 文件配置与代码配置的优先级 {/* #precedence-with-code */}

通过代码注册的 Studio 配置优先于 `studio.ts`。整个项目只需一套 Studio 配置时，可使用 `studio.ts`。如果身份验证依赖运行时的组件装配，请在 `src/mastra/index.ts` 中通过代码注册。
