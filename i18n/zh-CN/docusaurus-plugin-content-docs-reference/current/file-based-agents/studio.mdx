# 工作室

马斯特拉配置[Studio](/docs/studio/overview)从一个`studio.ts`直接在下面的文件`src/mastra/`。该文件默认导出一个`StudioConfig`Studio 身份验证和授权的对象：谁可以访问 Studio，以及经过身份验证的用户可以执行哪些操作。

使用此页面进行基于文件的约定。对于身份验证提供程序、基于角色的访问控制 (RBAC) 和细粒度授权 (FGA)，请参阅[Studio auth](/docs/studio/auth).

## 快速入门 {/* #quickstart */}

对于本地开发，您不需要`studio.ts`. Start the dev server and open Studio:

```bash npm2yarn
npm run dev
```

Studio 在本地开发中无需身份验证即可打开。添加`studio.ts` when you're ready to secure a shared or production deployment.

## 添加身份验证 {/* #add-authentication */}

使用身份验证提供程序要求用户先登录，然后才能访问 Studio。本示例使用[WorkOS](/integrations/auth/workos):

```typescript title="src/mastra/studio.ts"
import { MastraAuthWorkos } from '@mastra/auth-workos'
import type { StudioConfig } from '@mastra/core/server'

export default {
  auth: new MastraAuthWorkos(),
} satisfies StudioConfig
```

身份验证提供者处理用户是谁。对于用户登录后可以执行的操作，请在同一配置中添加 RBAC 或 FGA。看[Studio auth](/docs/studio/auth) for full examples.

## 代码优先级 {/* #precedence-with-code */}

代码注册的 Studio 配置获胜`studio.ts`. Use `studio.ts` when one project-wide Studio config is enough. Use code registration when auth depends on runtime wiring in `src/mastra/index.ts`.
