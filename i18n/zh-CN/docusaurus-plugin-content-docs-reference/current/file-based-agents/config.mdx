# config.ts

Agent 的 `config.ts` 设置模型和运行时选项。属于 [`Agent`](/reference/agents/agent) 本身的选项放在这里；指令、工具和技能等由同级文件提供。

## `config.ts` 中应包含什么 {/* #what-belongs-in-configts */}

`config.ts` 是基于文件的 Agent 配置模型和运行时选项的必需入口。模型、描述、默认执行选项、重试行为、评分器和显示标识等不需要单独文件的 Agent 级设置，都放在这里。

如果希望基于文件的路由将相邻配置合并到 Agent 中，请将它们放在同级文件。例如，用 `instructions.md` 保存始终生效的提示词，用 `tools/` 存放可供模型调用的操作。

## 快速开始 {/* #quickstart */}

以下 `config.ts` 和 `instructions.md` 文件共同创建一个可运行的基于文件的 Agent：

```typescript title="src/mastra/agents/weather/config.ts"
import { agentConfig } from '@mastra/core/agent'

export default agentConfig({
  model: '__GATEWAY_OPENAI_MODEL__',
})
```

```markdown title="src/mastra/agents/weather/instructions.md"
You are a helpful weather assistant. Answer questions about current conditions and forecasts.
```

Mastra 默认使用目录名 `weather` 作为 Agent 的 `id` 和 `name`。同级的 `instructions.md` 提供必需的指令。

## 设置模型 {/* #set-the-model */}

`model` 是 `agentConfig()` 中唯一的必填字段。如果 Agent 目录未提供模型，构建会失败。其他能力由同级文件提供，或使用默认值。

```typescript title="src/mastra/agents/weather/config.ts"
import { agentConfig } from '@mastra/core/agent'

export default agentConfig({
  model: '__GATEWAY_OPENAI_MODEL__',
})
```

## 从目录获取标识 {/* #identity-from-the-directory */}

基于文件的 Agent 默认使用目录名作为 `id` 和 `name`。对于 `src/mastra/agents/weather/`，除非覆盖这两个字段，否则 Mastra 会将 Agent 注册为 `weather`。

当稳定的路由键与显示名称需要不同时，可覆盖 `id` 或 `name`。

```typescript title="src/mastra/agents/weather/config.ts"
import { agentConfig } from '@mastra/core/agent'

export default agentConfig({
  id: 'weather-assistant',
  name: 'Weather Assistant',
  model: '__GATEWAY_OPENAI_MODEL__',
})
```

## 设置运行时选项 {/* #set-runtime-options */}

`agentConfig()` 接受 [`Agent` 构造函数选项](/reference/agents/agent#constructor-parameters)；其中 `id`、`name` 和同级文件对应的字段也可以通过基于文件的约定提供。完整选项列表请参阅 Agent 参考文档。

请注意：

- 基于文件的子 Agent 必须有非空的 `description`，因为父级模型会用它决定委派路由。
- `defaultOptions`、`maxRetries`、`scorers` 等 Agent 选项如果不需要单独文件，可以放在 `config.ts` 中。

## 相邻配置放在哪里 {/* #where-adjacent-settings-live */}

让 `config.ts` 专注于运行时选项。适合独立管理的配置放在同级文件中。

| 设置 | 文件或文件夹 | 放在这里的原因 |
| - | - | - |
| 指令 | [`instructions.md` 或 `instructions.ts`](/reference/file-based-agents/instructions) | 始终生效的提示词可直接作为 Markdown 阅读，也可在 TypeScript 中动态生成 |
| 工具 | [`tools/`](/reference/file-based-agents/tools) | 每个可调用操作都有独立的类型化模块 |
| 技能 | [`skills/`](/reference/file-based-agents/skills) | 按需加载的流程与始终生效的指令分开 |
| 记忆 | [`memory.ts`](/reference/file-based-agents/memory) | 配置持久化记忆，避免挤占运行时选项 |
| Workspace | [`workspace.ts`](/reference/file-based-agents/workspace) | 将文件和沙箱行为与模型设置分开配置 |
| Processor | [`processors/`](/reference/file-based-agents/processors) | 分离输入和输出处理管线 |
| 子 Agent | [`subagents/`](/reference/file-based-agents/subagents) | 每个专门的子 Agent 都有独立目录 |

## 优先级 {/* #precedence */}

`config.ts` 与 Agent 其他文件的合并规则如下：

| 类别 | 来源 A | 来源 B | 优先使用 |
| - | - | - | - |
| 指令 | 动态 `config.instructions` | [`instructions.ts` 或 `instructions.md`](/reference/file-based-agents/instructions) | 动态 `config.instructions` |
| 指令 | 静态 `config.instructions` | [`instructions.ts` 或 `instructions.md`](/reference/file-based-agents/instructions) | 指令文件 |
| 指令 | [`instructions.ts`](/reference/file-based-agents/instructions) | [`instructions.md`](/reference/file-based-agents/instructions) | `instructions.ts` |
| 工具 | `config.tools` | [`tools/`](/reference/file-based-agents/tools) | 两者合并；键冲突时以 `config.tools` 为准 |
| 工具 | 函数形式的 `config.tools` | [`tools/`](/reference/file-based-agents/tools) | 函数形式的 `config.tools`；忽略自动发现的工具 |
| 技能 | `config.skills` | [`skills/`](/reference/file-based-agents/skills) | 两者合并；名称冲突时以 `config.skills` 为准 |
| 技能 | 函数形式的 `config.skills` | [`skills/`](/reference/file-based-agents/skills) | 函数形式的 `config.skills`；忽略自动发现的技能 |
| 记忆 | `config.memory` | [`memory.ts`](/reference/file-based-agents/memory) | `config.memory` |
| Workspace | `config.workspace` | [`workspace.ts`](/reference/file-based-agents/workspace) | `config.workspace` |

如果缺少 `instructions.md`、`instructions.ts` 和 `config.instructions`，构建会失败。如果 `config.memory` 和 `memory.ts` 都缺失，Agent 将没有记忆。

## 发现流程 {/* #discovery-lifecycle */}

运行 `mastra dev` 或 `mastra build` 时，Mastra 打包器会发现基于文件的组件。发现过程中，它读取 `src/mastra/` 下受支持的文件，导入 TypeScript 和 JavaScript 模块，并读取 Markdown 指令和技能。之后，打包器复制 Workspace 初始文件，并将组装好的组件注册到 Mastra 应用。

发现完成后，基于文件的 Agent 与普通 [`Agent`](/reference/agents/agent) 一样运行。无论从 Agent API、Studio、Workflow 还是应用代码调用，都使用与代码定义的 Agent 相同的运行时。

发现机制以源码为依据，且采取保守策略。

它会跳过符号链接、测试文件和不属于 Agent 的目录。Workflow 和项目级单文件组件只有在默认导出时才会按文件路由。

通过 Mastra CLI 启动应用，以运行发现流程：

```bash npm2yarn
npx mastra dev
```

如果直接导入 `mastra` 实例，系统不会发现 `agents/<name>/` 目录及其他文件约定。将 Mastra 作为库使用时，请改为在代码中注册这些组件。
