# 配置.ts

一个Agent的`config.ts`设置其模型和运行时选项。将其用于属于[`Agent`](/reference/agents/agent)其本身，而兄弟文件则提供说明、Tool、技能等。

## 属于什么`config.ts` {/* #what-belongs-in-configts */}

`config.ts`是基于文件的Agent模型和运行时选项所需的入口点。当Agent不需要自己的文件时，将Agent级设置放在此处，例如模型、描述、默认执行选项、重试行为、记分器和显示身份。

当您希望基于文件的路由将相邻关注点合并到Agent中时，请将它们保留在同级文件中。例如，使用`instructions.md` for the always-on prompt and `tools/` for model-callable actions.

## 快速入门 {/* #quickstart */}

下列`config.ts` plus an `instructions.md` file creates a working file-based agent:

```typescript title="src/mastra/agents/weather/config.ts"
import { agentConfig } from '@mastra/core/agent'

export default agentConfig({
  model: '__GATEWAY_OPENAI_MODEL__',
})
```

```markdown title="src/mastra/agents/weather/instructions.md"
You are a helpful weather assistant. Answer questions about current conditions and forecasts.
```

马斯特拉使用`weather` directory name as the default agent `id` and `name`. The sibling `instructions.md` supplies the required instructions.

## 设置模型 {/* #set-the-model */}

这`model` field is the only required field in `agentConfig()`. The build fails when an agent directory doesn't provide a model. Other capabilities either come from sibling files or have defaults.

```typescript title="src/mastra/agents/weather/config.ts"
import { agentConfig } from '@mastra/core/agent'

export default agentConfig({
  model: '__GATEWAY_OPENAI_MODEL__',
})
```

## 来自目录的身份 {/* #identity-from-the-directory */}

基于文件的Agent`id` and `name` default to the directory name. For `src/mastra/agents/weather/`, Mastra registers the agent as `weather` unless you override those fields.

覆盖`id` or `name` when the stable routing key and the display name should differ.

```typescript title="src/mastra/agents/weather/config.ts"
import { agentConfig } from '@mastra/core/agent'

export default agentConfig({
  id: 'weather-assistant',
  name: 'Weather Assistant',
  model: '__GATEWAY_OPENAI_MODEL__',
})
```

## 设置运行时选项 {/* #set-runtime-options */}

`agentConfig()`接受[`Agent` constructor options](/reference/agents/agent#constructor-parameters), except that `id`, `name`, and sibling-file fields can be supplied by the file-based convention. Use the Agent reference for the full option list.

请注意：

* 基于文件的子Agent需要非空`description` because the parent model uses it for delegation routing.
* `defaultOptions`, `maxRetries`, `scorers`, and other Agent options can live in `config.ts` when they don't need their own file.

## 相邻设置所在的位置 {/* #where-adjacent-settings-live */}

保持`config.ts` focused on runtime options. Use sibling files for concerns that benefit from their own location.

|设置|文件或文件夹|为什么它住在那里|
| - | - | - |
|说明 |[`instructions.md` or `instructions.ts`](/reference/file-based-agents/instructions) | Keeps the always-on prompt readable as markdown, or computed in TypeScript |
| Tools | [`tools/`](/reference/file-based-agents/tools) | Gives each callable action its own typed module |
| Skills | [`skills/`](/reference/file-based-agents/skills) | Keeps load-on-demand procedures separate from always-on instructions |
| Memory | [`memory.ts`](/reference/file-based-agents/memory) | Configures persistent memory without crowding runtime options |
| Workspace | [`workspace.ts`](/reference/file-based-agents/workspace) | Configures files and sandbox behavior separately from model settings |
| Processors | [`processors/`](/reference/file-based-agents/processors) | Separates input and output processing pipelines |
| Subagents | [`subagents/`](/reference/file-based-agents/subagents) | Gives each specialist child agent its own directory |

## 优先级 {/* #precedence */}

`config.ts`根据以下规则与Agent的其他文件合并：

|域名 |来源A |来源 B |获胜者 |
| - | - | - | - |
|说明 |动态的`config.instructions` | [`instructions.ts` or `instructions.md`](/reference/file-based-agents/instructions) | Dynamic `config.instructions` |
| Instructions | Static `config.instructions` | [`instructions.ts` or `instructions.md`](/reference/file-based-agents/instructions) | The instructions file |
| Instructions | [`instructions.ts`](/reference/file-based-agents/instructions) | [`instructions.md`](/reference/file-based-agents/instructions) | `instructions.ts` |
| Tools | `config.tools` | [`tools/`](/reference/file-based-agents/tools) | Both merge; `config.tools` wins on key collisions |
| Tools | Function `config.tools` | [`tools/`](/reference/file-based-agents/tools) | Function `config.tools`;发现的Tool被忽略|
|技能 |`config.skills` | [`skills/`](/reference/file-based-agents/skills)|两者合并；`config.skills`名称冲突获胜 |
|技能 |功能`config.skills` | [`skills/`](/reference/file-based-agents/skills)|功能`config.skills`;发现技能被忽略|
|内存|`config.memory` | [`memory.ts`](/reference/file-based-agents/memory) | `config.memory`|
|工作空间 |`config.workspace` | [`workspace.ts`](/reference/file-based-agents/workspace) | `config.workspace` |

丢失的`instructions.md`, `instructions.ts`, and `config.instructions` fails the build. Missing both `config.memory` and `memory.ts` leaves the agent without memory.

## 发现生命周期 {/* #discovery-lifecycle */}

基于文件的原语由 Mastra 捆绑器在下面发现`mastra dev` and `mastra build`. During discovery, Mastra reads supported files under `src/mastra/` and imports TypeScript and JavaScript modules. It also reads markdown instructions and skills. The bundler then copies workspace seed files and registers the assembled primitives with your Mastra app.

发现后，基于文件的Agent正常运行[`Agent`](/reference/agents/agent). Calling it from the Agent API, Studio, workflows, or your application code uses the same runtime as a code-defined agent.

发现是基于来源的且保守的。

它会跳过符号链接、测试文件和非Agent目录的目录。Workflow程和单例项目文件仅在具有默认导出时才进行文件路由。

通过 Mastra CLI 启动您的应用程序，以便运行发现：

```bash npm2yarn
npx mastra dev
```

如果您导入您的`mastra` instance directly, `agents/<name>/` directories and the other conventions aren't discovered. When you consume Mastra as a library, register those primitives in code instead.
