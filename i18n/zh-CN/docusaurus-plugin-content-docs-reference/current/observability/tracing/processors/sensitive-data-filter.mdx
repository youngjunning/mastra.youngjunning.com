# 敏感数据过滤器

`SensitiveDataFilter`是一个跨度输出处理器，用于编辑字段名称与配置列表匹配的值。[`Observability`](/reference/observability/tracing/configuration#observabilityregistryconfig)默认情况下将其应用于普通的可观察性配置。

## 使用示例 {/* #usage-example */}

使用顶级配置自动应用的过滤器`sensitiveDataFilter` option. The filter runs after user-provided span output processors so it can redact values they add or expose.

```typescript title="src/mastra/index.ts"
import { Mastra } from '@mastra/core/mastra'
import { Observability, MastraStorageExporter } from '@mastra/observability'

export const mastra = new Mastra({
  observability: new Observability({
    configs: {
      default: {
        serviceName: 'my-service',
        exporters: [new MastraStorageExporter()],
      },
    },
    sensitiveDataFilter: {
      sensitiveFields: ['password', 'authorization', 'customerSecret'],
      redactionToken: '[HIDDEN]',
      redactionStyle: 'full',
    },
  }),
})
```

通过`sensitiveFields` replaces the default field list. Include every default field you still want to redact.

要禁用所有普通配置的自动过滤，请设置`sensitiveDataFilter` to `false`:

```typescript
new Observability({
  configs: {
    debug: {
      serviceName: 'debug-service',
      exporters: [new MastraStorageExporter()],
    },
  },
  sensitiveDataFilter: false,
})
```

如果普通配置已经包含`SensitiveDataFilter` in `spanOutputProcessors`, `Observability` uses that instance and doesn't add another. Pre-instantiated `ObservabilityInstance` values aren't modified. Add the processor when constructing those instances if they need filtering.

## 密文样式 {/* #redaction-styles */}

### 完全密文 {/* #full-redaction */}

完整编辑将每个匹配的原始值替换为`redactionToken`.

```jsonc oxfmt:false
// Before
{ "apiKey": "sk-abc123xyz789", "userId": "user_123" }

// After
{ "apiKey": "[REDACTED]", "userId": "user_123" }
```

### 部分编辑 {/* #partial-redaction */}

部分密文保留前三个字符。使用六个或更少字符的值`redactionToken` instead. Non-string primitive values are converted to strings before redaction.

```typescript
const filter = new SensitiveDataFilter({
  redactionStyle: 'partial',
})
```

```jsonc oxfmt:false
// Before
{ "apiKey": "sk-abc123xyz789" }

// After
{ "apiKey": "sk-…789" }
```

### 索引编辑 {/* #indexed-redaction */}

例如，索引编辑将每个唯一值替换为从与其匹配的第一个字段名称派生的稳定标记`[APIKEY_1]`. The same value maps to the same token across the spans of a trace while the trace's mapping is retained, so redacted values stay correlatable without exposing the raw value. Later occurrences under other sensitive fields reuse the first token.

```typescript
const filter = new SensitiveDataFilter({
  redactionStyle: 'indexed',
})
```

```jsonc oxfmt:false
// Before (two spans in the same trace)
[{ "apiKey": "sk-alice-key" }, { "apiKey": "sk-bob-key" }]

// After
[{ "apiKey": "[APIKEY_1]" }, { "apiKey": "[APIKEY_2]" }]
```

映射的范围是按跟踪确定的。每个跟踪都会重新编号，因此来自不同跟踪的标记无法链接。

状态以两种方式受到限制。过滤器保留 1000 个最近使用的跟踪的映射。除此之外，最近最少使用的跟踪将被逐出，并且到达已逐出跟踪的跨度会开始新的映射，因此后面的值可能会收到新的令牌。每个跟踪还跟踪最多 1000 个唯一值。一旦达到该上限，已跟踪的值将保留其代币，并且新值将被编辑`redactionToken`.

在分配标记之前，非字符串值将转换为字符串。

## 现场匹配 {/* #field-matching */}

在比较之前，字段名称为小写并去除非字母数字字符：

* `api-key`, `api_key`, `Api Key`, and `apiKey` normalize to `apikey`.
* 归一化后匹配准确。`token` matches `Token`, but doesn't match `promptTokens`, `tokenCount`, or `authToken`.

当匹配字段包含对象或数组时，过滤器会遍历该值并编辑其中的敏感字段，而不是替换完整的结构。

## 加工行为 {/* #processing-behavior */}

`process()`独立过滤这些顶级跨度字段：

* `attributes`
* `metadata`
* `input`
* `output`
* `errorInfo`
* `requestContext`

在每个字段中，处理器：

* 遍历嵌套对象和数组。
* 解析和过滤包含对象或数组的 JSON 字符串。然后它会序列化过滤后的值。
* 保留无效的 JSON 字符串不变。
* 果酱`Date` instances.
* 将重复的对象引用替换为`[Circular Reference]`.

如果过滤在一个顶级跨度字段中的任何位置失败，则该完整字段将替换为以下标记：

```typescript
{
  error: {
    processor: 'sensitive-data-filter'
  }
}
```

## 方法 {/* #methods */}

### 加工 {/* #processing */}

#### `process(span)` {/* #processspan */}

就地编辑所提供的跨度上支持的字段并返回相同的跨度。

```typescript
import type { AnySpan } from '@mastra/core/observability'
import { SensitiveDataFilter } from '@mastra/observability'

const filter = new SensitiveDataFilter()

export function redactSpan(span: AnySpan): AnySpan {
  return filter.process(span)
}
```
