# SensitiveDataFilter

`SensitiveDataFilter` 是一个 Span 输出处理器，会遮盖字段名与配置列表匹配的值。[`Observability`](/reference/observability/tracing/configuration#observabilityregistryconfig) 默认会将其应用于普通的可观测性配置。

## 使用示例 {/* #usage-example */}

使用顶层 `sensitiveDataFilter` 选项配置自动应用的过滤器。过滤器会在用户提供的 Span 输出处理器之后运行，因此也能遮盖这些处理器添加或暴露的值。

```typescript title="src/mastra/index.ts"
import { Mastra } from '@mastra/core/mastra'
import { Observability, MastraStorageExporter } from '@mastra/observability'

export const mastra = new Mastra({
  observability: new Observability({
    configs: {
      default: {
        serviceName: 'my-service',
        exporters: [new MastraStorageExporter()],
      },
    },
    sensitiveDataFilter: {
      sensitiveFields: ['password', 'authorization', 'customerSecret'],
      redactionToken: '[HIDDEN]',
      redactionStyle: 'full',
    },
  }),
})
```

传入 `sensitiveFields` 会替换默认字段列表。仍需遮盖的默认字段必须全部重新列入。

要关闭所有普通配置的自动过滤，请将 `sensitiveDataFilter` 设为 `false`：

```typescript
new Observability({
  configs: {
    debug: {
      serviceName: 'debug-service',
      exporters: [new MastraStorageExporter()],
    },
  },
  sensitiveDataFilter: false,
})
```

如果普通配置的 `spanOutputProcessors` 中已有 `SensitiveDataFilter`，`Observability` 会使用该实例，不再添加新的过滤器。预先实例化的 `ObservabilityInstance` 不会被修改；如果这些实例需要过滤，应在构造时添加处理器。

## 遮盖方式 {/* #redaction-styles */}

### 完全遮盖 {/* #full-redaction */}

完全遮盖会将每个匹配的基本类型值替换为 `redactionToken`。

```jsonc oxfmt:false
// Before
{ "apiKey": "sk-abc123xyz789", "userId": "user_123" }

// After
{ "apiKey": "[REDACTED]", "userId": "user_123" }
```

### 部分遮盖 {/* #partial-redaction */}

部分遮盖会保留值的前三个和后三个字符。长度不超过六个字符的值则改用 `redactionToken`。非字符串的基本类型值会先转换为字符串再遮盖。

```typescript
const filter = new SensitiveDataFilter({
  redactionStyle: 'partial',
})
```

```jsonc oxfmt:false
// Before
{ "apiKey": "sk-abc123xyz789" }

// After
{ "apiKey": "sk-…789" }
```

### 索引式遮盖 {/* #indexed-redaction */}

索引式遮盖会用稳定的标记替换每个不同的值。标记由首次匹配该值的字段名生成，例如 `[APIKEY_1]`。只要 Trace 的映射仍保留，同一值在该 Trace 的各个 Span 中都会映射到同一标记，因此无需暴露原值也能关联已遮盖的数据。即使该值后来出现在其他敏感字段中，也会复用最初的标记。

```typescript
const filter = new SensitiveDataFilter({
  redactionStyle: 'indexed',
})
```

```jsonc oxfmt:false
// Before (two spans in the same trace)
[{ "apiKey": "sk-alice-key" }, { "apiKey": "sk-bob-key" }]

// After
[{ "apiKey": "[APIKEY_1]" }, { "apiKey": "[APIKEY_2]" }]
```

映射以每条 Trace 为单位。每条 Trace 都会重新编号，因此无法通过标记关联不同 Trace 的数据。

状态有两项容量限制。过滤器保留最近使用的 1000 条 Trace 的映射；超出时会淘汰最久未使用的 Trace。之后到达的该 Trace 的 Span 会建立新映射，因此后续值可能获得新标记。每条 Trace 最多跟踪 1000 个不同的值。达到上限后，已跟踪的值仍使用原有标记，新值则使用 `redactionToken` 遮盖。

非字符串值会先转换为字符串，再分配标记。

## 字段匹配 {/* #field-matching */}

比较前，字段名会转成小写并移除非字母数字字符：

* `api-key`、`api_key`、`Api Key` 和 `apiKey` 都会规范化为 `apikey`。
* 规范化后执行精确匹配。`token` 会匹配 `Token`，但不会匹配 `promptTokens`、`tokenCount` 或 `authToken`。

如果匹配的字段包含对象或数组，过滤器会遍历该值并遮盖其中的敏感字段，而不会替换整个结构。

## 处理行为 {/* #processing-behavior */}

`process()` 会分别过滤以下顶层 Span 字段：

* `attributes`
* `metadata`
* `input`
* `output`
* `errorInfo`
* `requestContext`

对于每个字段，处理器会：

* 遍历嵌套对象和数组。
* 解析包含对象或数组的 JSON 字符串、过滤其中的值，再将结果序列化。
* 保留无效的 JSON 字符串，不作修改。
* 保留 `Date` 实例。
* 将重复的对象引用替换为 `[Circular Reference]`。

如果某个顶层 Span 字段中的任意位置过滤失败，整个字段会被替换为以下标记：

```typescript
{
  error: {
    processor: 'sensitive-data-filter'
  }
}
```

## 方法 {/* #methods */}

### 处理 {/* #processing */}

#### `process(span)` {/* #processspan */}

就地遮盖所提供 Span 中受支持的字段，并返回同一个 Span。

```typescript
import type { AnySpan } from '@mastra/core/observability'
import { SensitiveDataFilter } from '@mastra/observability'

const filter = new SensitiveDataFilter()

export function redactSpan(span: AnySpan): AnySpan {
  return filter.process(span)
}
```
