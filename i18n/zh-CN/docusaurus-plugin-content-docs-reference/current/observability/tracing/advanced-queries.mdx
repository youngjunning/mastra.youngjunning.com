# 查询轨迹和跨度

使用结构化过滤器查询完整的跟踪或跨度，或将它们聚合为计数、错误率、延迟百分位数、令牌和成本。每个操作都可以通过客户端 SDK、HTTP API 和 CLI 进行：

|运营|用它来 |客户端SDK | HTTP 端点 | CLI 命令 |
| - | - | - | - | - |
|[Query traces](#query-traces) | List traces matching root-span fields or conditions on related spans. | `queryTraces()` | `POST /api/observability/traces/query` | `mastra api trace query` |
| [查询跨度](#query-spans)|列出跨跟踪的各个跨度，包括嵌套Agent运行和Tool调用。 |`querySpans()` | `POST /api/observability/spans/query` | `mastra api span query` |
| [聚合痕迹](#aggregate-traces)|计算匹配轨迹的测量值，可以选择按时间分组或分桶。 |`aggregateTraces()` | `POST /api/observability/traces/aggregate` | `mastra api trace aggregate` |
| [聚合跨度](#aggregate-spans)|计算任意深度的单个匹配跨度的测量值。 |`aggregateSpans()` | `POST /api/observability/spans/aggregate` | `mastra api span aggregate` |

跟踪操作共享一个[trace selection](#select-traces): root-span predicates and `spans.some` / `spans.none` clauses. The span operations share a direct span predicate, without nested `spans` clauses. Reuse a selection between the query and aggregate operations for the same record type.

|选项 |查询踪迹 |查询范围 |聚合迹线或跨度 |
| - | - | - | - |
|最大时间范围持续时间 |无上限 |无上限 | 365 天 |
|分页 |键集、编号页面或增量轮询 |仅按键组 |没有分页；`limit` selects groups |
| `orderBy` shape | One-item array | One-item array | One object |

CLI 命令将过滤器和请求选项一起作为一个 JSON 参数，并将响应包装在`data`. To inspect a query result, use its `traceId` to [retrieve the full trace](/reference/client-js/observability#getting-a-specific-trace), or call `getSpan(traceId, spanId)` to retrieve one span.

端点使用与其他可观察性路由相同的身份验证，并且需要`observability:read` permission. Every request requires a time range.

这些 API 时间范围限制与数据保留是分开的。对于托管跟踪，您的平台计划的保留期适用。看[Query observability data on Mastra Platform](/docs/mastra-platform/observability#query-observability-data) for retention, project credentials, and regional endpoints.

## 选择轨迹 {/* #select-traces */}

每个请求都会选择具有两个字段的跟踪：

|领域 |必填|描述 |
| - | - | - |
|`timeRange` | Yes | Trace start-time boundary. `from` is inclusive and `to` is exclusive. Both values must be ISO timestamps, and `from` must be earlier than `to`. |
| `where` | No | Recursive trace predicate. Supports scalar conditions and `spans.some` or `spans.none` clauses. |

此选择与 8 月第一周的跟踪相匹配，其中包含有错误的Tool调用：

```typescript
const selection = {
  timeRange: {
    from: '2026-08-01T00:00:00.000Z',
    to: '2026-08-08T00:00:00.000Z',
  },
  where: {
    spans: {
      some: {
        op: 'and',
        args: [
          { op: 'eq', left: { path: 'spanType' }, right: { literal: 'tool_call' } },
          { op: 'exists', path: 'error' },
        ],
      },
    },
  },
}
```

相同的选择会从任一 API 返回相同的跟踪。聚合精确计算查询将列出的跟踪。

一个`spans.some` clause matches when one span satisfies all its conditions. In this example, the same span must be a tool call and have an error. Use `spans.none` to find traces with no spans matching the conditions.

Span 子句检查当前根跨度和当前子跨度。根`timeRange` applies only to the selected current root's `startedAt`. Related spans can participate even when their own timestamps are outside that range. Related records correlate only through a matching non-null `traceId`.

### 字段和运算符 {/* #fields-and-operators */}

|谓词上下文 |领域 |运营商|
| - | - | - |
|追踪|`traceId`, `threadId`, `resourceId`, `runId`, `sessionId`, `userId`, `organizationId`, `requestId`, `serviceName`, `experimentId`, `entityId`, `entityName`, `entityType`, `name`, `spanType`, `environment`, `status`, `outcome`, `stopReason` | `eq`, `ne`, `in`, `notIn`, `exists`, `notExists` |
| Trace metadata | `metadata.<key>` | `eq`, `ne`, `in`, `notIn`, `exists`, `notExists` |
| Trace | `startedAt`, `endedAt`, `durationMs`, `timeToFirstChunkMs`, `timeToFirstTokenMs` | `eq`, `ne`, `in`, `notIn`, `lt`, `lte`, `gt`, `gte`, `exists`, `notExists` |
| Trace | `tags` | `includes`, `notIncludes`, `exists`, `notExists` |
| Span | `name` | `eq`, `ne`, `in`, `notIn`, `exists`, `notExists`, `matches`, `notMatches` |
| Span | `spanType`, `model`, `provider`, `status`, `outcome`, `stopReason`, `entityType`, `entityId`, `entityName`, `entityVersionId`, `parentEntityVersionId`, `rootEntityVersionId`, `runId`, `sessionId`, `userId`, `organizationId`, `requestId`, `serviceName`, `experimentId` | `eq`, `ne`, `in`, `notIn`, `exists`, `notExists` |
| Span | `startedAt`, `endedAt`, `durationMs`, `timeToFirstChunkMs`, `timeToFirstTokenMs` | `eq`, `ne`, `in`, `notIn`, `lt`, `lte`, `gt`, `gte`, `exists`, `notExists`|
|跨度|`error` | `exists`, `notExists` |

跟踪范围`name`, `spanType`, and `entityId` read the current root span, so `{ op: 'eq', left: { path: 'spanType' }, right: { literal: 'workflow_run' } }` selects traces started by a workflow run. Inside `spans.some` or `spans.none`, the same fields match any span in the trace.

组成谓词`{ op: 'and', args: [...] }`, `{ op: 'or', args: [...] }`, and `{ op: 'not', arg: ... }`. Comparison predicates place a field reference on the left and a literal on the right. Membership predicates use a field reference in `value` and a homogeneous literal array in `set`. Tag predicates name the stored tag collection in `path`. `includes` and `notIncludes` also take one tag in `value`, while `exists` and `notExists` take only `op` and `path`. See [Filter by tags](#filter-by-tags). Text predicates use the comparison shape with a string literal. See [Filter by text](#filter-by-text).

字符串比较区分大小写，并且文字永远不会被强制。`matches` and `notMatches` are the exception: they compare words case-insensitively. Canonical string fields compare exact stored values. Metadata string values are trimmed before comparison, as described below. Duration, time-to-first-chunk, and time-to-first-token predicates require numbers, while timestamp predicates require ISO timestamp strings. A missing value satisfies neither positive nor ordered predicates, although it does satisfy the negative operators `ne` and `notIn`. Combine a negative predicate with `exists` when the field must also be present.

#### 按根持续时间过滤 {/* #filter-by-root-duration */}

在跟踪范围内，`durationMs` is the current completed root span's elapsed time in milliseconds. The value is derived from `endedAt - startedAt` when the query runs:

```typescript
const slowRootTraces = {
  op: 'gt',
  left: { path: 'durationMs' },
  right: { literal: 5000 },
}
```

此顶级谓词不检查子跨度。相比之下，`spans.some` with a `durationMs` predicate examines the current root span and current child spans, so a long child can satisfy that clause even when its root is shorter.

跟踪查询在评估谓词之前排除不完整的根。因此，`{ op: 'notExists', path: 'durationMs' }` doesn't find running traces or malformed roots without a usable `endedAt`.

#### 按第一个块或标记的时间进行过滤和排序 {/* #filter-and-sort-by-time-to-first-chunk-or-token */}

`timeToFirstChunkMs`持有一个跨度[time to first chunk (TTFC)](#time-to-first-chunk-ttfc), and `timeToFirstTokenMs` holds its [time to first token (TTFT)](#time-to-first-token-ttft). At trace scope, the fields read the root span's value. Inside `spans.some` or `spans.none`, they read each related span. Both fields also work in `orderBy`.

此谓词查找根Agent等待模型第一个令牌超过 2 秒的跟踪：

```typescript
const slowFirstToken = { op: 'gt', left: { path: 'timeToFirstTokenMs' }, right: { literal: 2000 } }
```

看[Missing first chunk and token values](#missing-first-chunk-and-token-values) for `null`, `0`, and the capabilities each use needs.

#### 按结果过滤 {/* #filter-by-outcome */}

`outcome`记录一个跨度如何结束，例如`success`, `error`, `abort`, `limit`, or `unknown`. `stopReason` records why, for example `max_steps`. Both are free strings, so custom spans can record their own values. They're separate from `status`, which still reads only whether the span recorded an error.

在跟踪范围内，这两个字段都会读取当前的根范围，即没有启动跟踪的父范围的范围。里面`spans.some` or `spans.none`, they read each related span. A trace whose root succeeded but whose tool call hit a step limit doesn't match a trace-scope `outcome` of `limit`. Find it through `spans.some`:

```typescript
const hitALimit = {
  spans: {
    some: { op: 'eq', left: { path: 'outcome' }, right: { literal: 'limit' } },
  },
}
```

由早于这些字段的 SDK 编写的 Span，或者仍在运行的根 Span，不会产生任何结果。缺失结果意味着“未记录”，永远不会成功。选择那些跨度`{ op: 'notExists', path: 'outcome' }`. As with other optional string fields, `ne` and `notIn` match spans with no value.

两个字段都支持`eq`, `ne`, `in`, `notIn`, `exists`, and `notExists`, group trace and span aggregates, and return values from value discovery. They can't sort individual trace or span query results. In aggregates, either field can be used in `orderBy` when it's included in `groupBy`. Results also return `stopReasonContext`, an object with details about the stop reason such as `{ maxSteps: 5 }`. `stopReasonContext` is returned only and can't be filtered, grouped, or sorted.

商店通过以下方式宣传支持`trace-query-outcome-fields` feature for trace queries and aggregates, and the `span-query-outcome-fields` feature for span queries and aggregates. The server reports them as the `traceQueryOutcomeFields` and `spanQueryOutcomeFields` capabilities. Against an older store, results omit the fields, and a request that uses them returns `501` before storage runs.

#### 按上下文标识符过滤 {/* #filter-by-context-identifiers */}

`runId`, `sessionId`, `userId`, and `organizationId` are available at trace scope and inside `spans.some` / `spans.none`. Trace-scope predicates read the current root span. Span-scope predicates bind to one related current span, so a run recorded only on a child span is found through `spans.some`:

```typescript
const sessionTracesWithRun = {
  op: 'and',
  args: [
    { op: 'eq', left: { path: 'organizationId' }, right: { literal: 'org-123' } },
    { op: 'eq', left: { path: 'sessionId' }, right: { literal: 'session-123' } },
    {
      spans: {
        some: { op: 'eq', left: { path: 'runId' }, right: { literal: 'run-42' } },
      },
    },
  ],
}
```

这些标识符支持`eq`, `ne`, `in`, `notIn`, `exists`, and `notExists`. Field discovery lists them, but value discovery doesn't return their recorded values. Stores advertise support through the `trace-query-context-ids` feature. A predicate on one of these fields against an older store returns `501` before storage runs, and field discovery omits them for that store.

`requestId`, `serviceName`, and `experimentId` work the same way, at trace scope and inside `spans.some` / `spans.none`. This predicate finds checkout requests that reached the `payments` service on a child span. The child span records `metadata: { serviceName: 'payments' }`; the root keeps `checkout`:

```typescript
const checkoutRequestsThroughPayments = {
  op: 'and',
  args: [
    { op: 'eq', left: { path: 'serviceName' }, right: { literal: 'checkout' } },
    { op: 'exists', path: 'requestId' },
    {
      spans: {
        some: { op: 'eq', left: { path: 'serviceName' }, right: { literal: 'payments' } },
      },
    },
  ],
}
```

商店通过以下方式宣传对这三个领域的支持`trace-query-context-fields` feature, reported as the `traceQueryContextFields` capability. Against an older store, a predicate on one of them returns `501` before storage runs, and field discovery omits them.

#### 按跨度属性过滤 {/* #filter-by-span-properties */}

里面的每一个条件`spans.some` or `spans.none` clause applies to the same current span. For example, this predicate finds a failed tool span whose name is `medication_lookup`; a matching name on one span and an error on another don't satisfy it:

```typescript
const failedMedicationLookup = {
  spans: {
    some: {
      op: 'and',
      args: [
        { op: 'eq', left: { path: 'name' }, right: { literal: 'medication_lookup' } },
        { op: 'eq', left: { path: 'spanType' }, right: { literal: 'tool_call' } },
        { op: 'exists', path: 'error' },
      ],
    },
  },
}
```

使用`status` for the derived `success` or `error` outcome. Use `error` when you only need to test whether error details are present.

`durationMs`是跨度经过的时间（以毫秒为单位）。跨度`startedAt` and `endedAt` conditions filter related spans independently of the top-level root `timeRange`:

```typescript
const slowModelCalls = {
  spans: {
    some: {
      op: 'and',
      args: [
        { op: 'eq', left: { path: 'spanType' }, right: { literal: 'model_generation' } },
        { op: 'gt', left: { path: 'durationMs' }, right: { literal: 5000 } },
        {
          op: 'gte',
          left: { path: 'startedAt' },
          right: { literal: '2026-07-15T00:00:00.000Z' },
        },
      ],
    },
  },
}
```

`model`和`provider` read the span's `model` and `provider` columns. When a column is empty, they fall back to the string `attributes.model` and `attributes.provider` values that older `@mastra/observability` versions exported, so existing filters keep matching older spans. Trace results omit `model` and `provider`, because a trace can match through one span while its other spans used a different model.

```typescript
const selectedModel = {
  spans: {
    some: {
      op: 'and',
      args: [
        {
          op: 'eq',
          left: { path: 'model' },
          right: { literal: '__AI_SDK_ANTHROPIC_MODEL_SONNET__' },
        },
        { op: 'eq', left: { path: 'provider' }, right: { literal: 'anthropic' } },
      ],
    },
  },
}
```

使用通用实体字段作为Tool和检索标识。版本字段让一个子句通过其实体谱系限定同一跨度：

```typescript
const versionedRetrieval = {
  spans: {
    some: {
      op: 'and',
      args: [
        { op: 'eq', left: { path: 'entityType' }, right: { literal: 'rag_ingestion' } },
        { op: 'eq', left: { path: 'entityId' }, right: { literal: 'medication-index' } },
        { op: 'eq', left: { path: 'entityVersionId' }, right: { literal: 'index-v3' } },
        { op: 'eq', left: { path: 'rootEntityVersionId' }, right: { literal: 'agent-v2' } },
      ],
    },
  },
}
```

#### 按元数据过滤 {/* #filter-by-metadata */}

使用`metadata.<key>` paths for custom dimensions stored on the current root span. Metadata predicates compare trimmed, non-empty string values exactly and case-sensitively. Leading and trailing whitespace in a stored string value is ignored. Values empty after trimming count as missing. Null, numeric, boolean, object, and array values also count as missing.

```typescript
const messageTrace = {
  op: 'and',
  args: [
    { op: 'eq', left: { path: 'metadata.messageId' }, right: { literal: 'message-123' } },
    { op: 'in', value: { path: 'metadata.actorRole' }, set: ['assistant', 'tool'] },
    { op: 'exists', path: 'metadata.protocolVersion' },
    {
      op: 'or',
      args: [
        { op: 'eq', left: { path: 'metadata.temporalRunId' }, right: { literal: 'run-456' } },
        { op: 'eq', left: { path: 'metadata.externalTraceId' }, right: { literal: 'trace-789' } },
      ],
    },
    { op: 'not', arg: { op: 'exists', path: 'metadata.parentMessageId' } },
  ],
}
```

该键必须命名一个顶级属性。空键和嵌套路径将被拒绝。元数据键不会被修剪，因此前导和尾随空格仍然是确切键标识的一部分。当元数据重复规范跟踪字段时，例如`resourceId`, `threadId`, or `environment`, prefer the canonical field because it uses the dedicated storage column. The `metadata.<key>` form remains available when you specifically need the value from the metadata object. Metadata and canonical values may differ.

跟踪查询发现返回在选定时间范围内观察到的可执行顶级字符串元数据字段。

#### 按标签过滤 {/* #filter-by-tags */}

标签是存储在当前根跨度上的字符串列表，因此它们使用集合运算符而不是标量`in` and `notIn` operators. This query finds production traces tagged for manual review that don't carry the `archived` tag:

```typescript
const manualReview = {
  op: 'and',
  args: [
    { op: 'eq', left: { path: 'environment' }, right: { literal: 'production' } },
    { op: 'includes', path: 'tags', value: 'manual-review' },
    { op: 'notIncludes', path: 'tags', value: 'archived' },
  ],
}
```

|操作员|匹配时间 |
| - | - |
|`includes` | The trace has the requested tag |
| `notIncludes` | The trace has at least one tag, but not the requested tag |
| `exists` | The trace has at least one tag |
| `notExists` | The trace has no tags |

标签作为整个字符串进行精确比较并区分大小写。`value` must be one string with at least one non-whitespace character. Combine several `includes` predicates with `and` or `or` to require or allow multiple tags. A trace with no recorded tags and a trace with an empty tag list behave the same: both satisfy `notExists`, neither satisfies `includes`, `notIncludes`, or `exists`. Use `{ op: 'not', arg: { op: 'includes', ... } }` when untagged traces should also match.

`tags`仅在跟踪谓词中可用。`in`, `notIn`, and the comparison operators are rejected for `tags`. Value discovery for `tags` returns each observed tag with the number of qualifying traces that carry it.

#### 按文本过滤 {/* #filter-by-text */}

除了精确比较之外，跨度名称还支持单词匹配。`matches` succeeds when the literal's words appear in the field, in order, as whole words. `notMatches` succeeds when the field exists but doesn't contain those words. This query finds traces with a span whose name contains the words "document search":

```typescript
const documentSearch = {
  spans: {
    some: {
      op: 'matches',
      left: { path: 'name' },
      right: { literal: 'document search' },
    },
  },
}
```

文字和存储的值都是小写的并分成单词。单词是一系列字母、数字和组合标记，因此任何其他字符，例如标点符号、空格或`_`, separates words. `incorrect` matches `This answer is incorrect.` but not `This was incorrectly formatted.`, and `gpt 5` matches `llm: 'gpt-5'`. A literal with several words must appear as a contiguous phrase in that order. Letters keep their accents: `café` doesn't match `cafe`. Text is composed to Unicode NFC first, so `café` matches whether the accent is stored as part of the letter or as a separate mark, and marks stay inside their word, so `नमस` doesn't match `नमस्ते`. The Turkish `İ` folds to `i`, and a Greek final `ς` equals `σ`. PostgreSQL lowercases letters according to the database locale, so a database created with the `C` locale doesn't fold the case of letters outside ASCII. Use a UTF-8 locale such as `en_US.UTF-8` for consistent results.

|操作员|匹配时间 |
| - | - |
|`matches` | The field contains the literal's words as a contiguous whole-word phrase |
| `notMatches` | The field is present and doesn't contain that phrase |

文字必须至少包含一个字母或数字；否则请求失败`422 TRACE_QUERY_INVALID`. A missing field satisfies neither operator. Use `{ op: 'not', arg: { op: 'matches', ... } }` when records without the field should also match. Text operators are available on span `name`. Other string fields, numbers, timestamps, tags, and metadata reject them. Substring, wildcard, regular-expression, and fuzzy matching aren't supported, and there is no search across several fields.

### 查询限制 {/* #query-limits */}

当查询超出以下任何限制时，规划器会在存储执行之前拒绝查询：

|输入 |最大|
| - | - |
|谓词嵌套深度 | 12 个级别 |
|谓词节点 | 100 | 100
|有关的`spans` clauses | 8 total |
| Values in one `in` or `notIn` set | 100 |
| Comparison literals and membership values | 1,000 total |
| String literal | 4,096 UTF-8 bytes |
| Raw predicate path | 128 UTF-8 bytes |
| `page.limit` | 1,000 |
| HTTP request body | 256 KiB |

每个比较文字都算作一个文字。每个成员`in` or `notIn` set also counts as one literal, even when the set is within its per-set limit.

Hono 和 Fastify 在 JSON 解析之前强制执行请求正文限制。 Express 和 Elysia 在路由处理程序或存储运行之前拒绝过大的主体，但主机框架可能已经在没有可靠的情况下解析了请求`Content-Length` header. Configure the host application's JSON parser or body limit when you need a hard pre-parse memory ceiling.

### 分页和错误 {/* #pagination-and-errors */}

#### 选择分页模式 {/* #choose-a-pagination-mode */}

跟踪查询支持三种互斥模式：

|模式|请求字段 |响应元数据 |
| - | - | - |
|键集，默认 |`page: { limit, after }` | `page: { next }` |
| Numbered pages | `pagination: { page, perPage }` | `pagination: { total, page, perPage, hasMore }` and, when delta polling is supported, `deltaCursor` |
| Delta polling | `mode: 'delta'`, optional top-level `after` and `limit` | `delta: { limit, hasMore }` and `deltaCursor` |

编号页是从零开始的。在每个请求中，它们的总数和行数的读取都是一致的。不要合并`page`, `pagination`, or delta mode. Top-level `after` and `limit` are accepted only in delta mode.

#### 加载编号页面后进行轮询 {/* #poll-after-loading-a-numbered-page */}

使用编号的响应`deltaCursor` to replace the numbered-page-to-delta-polling workflow of `listTracesLight()`. Results use `traces` instead of `spans` and contain completed traces only. The configured store must support delta polling.

```typescript
const timeRange = {
  from: '2026-08-01T00:00:00.000Z',
  to: '2026-08-08T00:00:00.000Z',
}
const initial = await mastraClient.queryTraces({
  timeRange,
  pagination: { page: 0, perPage: 100 },
})
if (!initial.deltaCursor) throw new Error('Delta polling is unavailable')

const traces = new Map(initial.traces.map(trace => [trace.traceId, trace]))
let after = initial.deltaCursor

async function poll() {
  let hasMore: boolean
  do {
    const result = await mastraClient.queryTraces({
      timeRange,
      mode: 'delta',
      after,
      limit: 100,
    })
    for (const trace of result.traces) traces.set(trace.traceId, trace)
    after = result.deltaCursor
    hasMore = result.delta.hasMore
  } while (hasMore)
}

await poll()
```

保持`after` and call `poll()` again at your application's polling interval. A trace can appear in the initial page and a later batch, or in multiple batches, so merge results by `traceId`. To load historical traces omitted from the initial page, request the remaining numbered pages.

没有 Delta 请求`after` returns an empty array and establishes the current cursor. It doesn't return historical matches. Always retain the returned cursor, including for empty batches. `hasMore` means another matching trace exists beyond the batch limit. Continue immediately while it's `true`.

增量排序使用存储摄取水印和特定于适配器的仲裁器，因此匹配时间戳不会使光标变得模糊。不要通过`orderBy` in delta mode. Keyset and delta cursors aren't interchangeable, and delta cursors can't move between storage adapters.

保持相同的标准化`where` predicate and exact `timeRange` bounds for every poll. The range continues to select root `startedAt`, even when a trace completes later. Changing `timeRange.to` to the current time invalidates the cursor. Reload a numbered page and use its cursor whenever the selection or authorization scope changes. You can change the batch limit without restarting.

可以返回新完成的根和光标后完成的根。选择根时会评估相关跨度，但稍后相关记录写入并不能保证再次发出跟踪。已删除的跟踪和停止匹配的跟踪不会作为删除或逻辑删除返回。当您需要协调这些更改时，请刷新编号页面。

ClickHouse 轮询是尽力而为。它的增量索引和跟踪记录使用单独的物化视图表。并发查询可以观察到一个表在另一个表之前的插入，如中所述[ClickHouse's materialized-view visibility rules](https://github.com/ClickHouse/clickhouse-docs/blob/main/knowledgebase/are_materialized_views_inserted_asynchronously.mdx). A poll can advance past an index entry before the matching trace becomes visible and miss that trace in later polls. Reload numbered pages periodically to reconcile these gaps.

ClickHouse 的增量索引保留两天的事件，并且不会回填历史行。在轮询中断时间超过此保留窗口后重新加载已编号的页面。增量轮询不是持久的更改源，并且不能保证传送每个匹配的跟踪。

#### 键集顺序和错误 {/* #keyset-ordering-and-errors */}

排序是确定性的。跟踪排序追加`traceId` ascending as a tie-breaker.

键集游标绑定到操作、接受的规范化查询和排序。更改跟踪选择、谓词或排序返回后重新使用键集光标`409`.

编号页切换游标和增量游标也绑定授权状态。对调用者角色或权限的更改使这些游标无效并返回`409`. If a delta poll returns `409`, reload the numbered pages and resume polling with the new `deltaCursor`. A malformed cursor returns `400`.

游标分页是确定性的，但它不是数据库快照。在页面请求之间写入的跟踪或替换信号可以更改后面的页面。

PostgreSQL 和 ClickHouse 默认在 15 秒后停止跟踪查询并返回`504` when the database timeout is exceeded. Set `observability.traceQueryTimeoutMs` on `PostgresStoreVNext`, or `observability.traceQuery.timeoutMs` on `ClickhouseStoreVNext`, to an integer from 1 through 300,000 milliseconds to change the timeout. DuckDB doesn't currently provide query-scoped timeout or cancellation through its driver wrapper, so this `504` guarantee doesn't apply to DuckDB.

|状态 |意义|
| - | - |
|`400` | Malformed JSON or malformed cursor. |
| `409` | The cursor doesn't match the query. |
| `413` | The request body exceeds 256 KiB. |
| `422` | The JSON is well formed, but the request is structurally or semantically invalid. The response includes stable issue codes and paths. Discovery validation uses `TRACE_QUERY_INVALID`. |
| `501` | The installed Core or configured observability store doesn't support the requested operation. Discovery returns `TRACE_QUERY_DISCOVERY_UNSUPPORTED` unless Core provides the discovery contract and the store implements both field and value discovery. |
| `503` | Discovery exceeded a backend memory or resource budget and returned `TRACE_QUERY_RESOURCE_LIMIT`. |
| `504` | A PostgreSQL or ClickHouse query exceeded its configured database execution timeout. Discovery returns `TRACE_QUERY_EXECUTION_TIMEOUT`. |

## 查询跨度 {/* #query-spans */}

使用`querySpans()`, `mastra api span query`, or `POST /api/observability/spans/query` to return completed span summaries across traces. It requires a positive ISO timestamp range over span start time and supports cursor pagination. This example finds tool calls that took at least one second:

```typescript
const result = await mastraClient.querySpans({
  timeRange: {
    from: '2026-10-01T00:00:00.000Z',
    to: '2026-10-02T00:00:00.000Z',
  },
  where: {
    op: 'and',
    args: [
      { op: 'eq', left: { path: 'spanType' }, right: { literal: 'tool_call' } },
      { op: 'gte', left: { path: 'durationMs' }, right: { literal: 1000 } },
    ],
  },
  orderBy: [{ field: 'startedAt', direction: 'desc' }],
  page: { limit: 100 },
})

// Pass result.page.next as page.after to continue with the same filters and ordering.
console.log(result.spans)
```

页面默认为 100 行，最多允许 1,000 行。响应是`{ spans, page: { next } }`, without a total count. Ordering accepts exactly one of `startedAt`, `endedAt`, `durationMs`, `timeToFirstChunkMs`, `timeToFirstTokenMs`, `model`, or `provider`, ascending or descending, and defaults to descending start time. Missing sort values appear last in both directions. Model and provider sorting is case-sensitive.

|领域 |运营商|
| - | - |
|`traceId`, `spanId`, `parentSpanId`, `threadId` | `eq`, `ne`, `in`, `notIn`, `exists`, `notExists` |
| `organizationId`, `resourceId`, `runId`, `sessionId`, `userId`, `requestId`, `serviceName`, `experimentId`, `environment`, `executionSource` | Same string operators |
| Entity, parent entity and root entity `Type`, `Id`, `Name`, `VersionId` fields, such as `parentEntityId` | Same string operators |
| `name`, `spanType`, `status` | Same string operators; `name` also accepts `matches` / `notMatches` for normalized whole words and phrases |
| `model`, `provider`, `outcome`, `stopReason` | Same string operators |
| `startedAt`, `endedAt`, `durationMs`, `timeToFirstChunkMs`, `timeToFirstTokenMs` | Comparisons, membership and presence |
| `error` | `exists`, `notExists` |

将谓词与`and`, `or` and `not`. Membership uses `{ op: 'in', value: { path: 'spanType' }, set: ['agent_run', 'tool_call'] }`. A span's status is `error` when it has an error and `success` otherwise.

每个摘要包括身份、上下文、实体沿袭、状态、时间戳、`durationMs`, model/provider and input/output/error previews.

查看`capabilities.spanQueryContextFields` from `getObservabilityCapabilities()` before filtering on `traceId`, `spanId`, `parentSpanId`, `threadId`, `resourceId`, `requestId`, `serviceName`, `experimentId`, `environment`, `executionSource`, or the parent/root entity `Type`, `Id`, and `Name` fields. If this capability is missing or false, requests using these filters return a structured `422` error. It doesn't gate `runId`, `sessionId`, `userId`, `organizationId`, or entity `VersionId` filters.

查看`capabilities.spanQueryModelFields` before filtering on `model` or `provider`. These filters read only the span's `model` and `provider` columns. `@mastra/observability` fills the columns only when a span has both a `model` and a `provider`, and versions before it filled them left them empty. Filters treat empty columns as missing, so `eq`, `in` and `exists` don't match those spans while `ne`, `notIn` and `notExists` do. Results still return `model` and `provider` for them from the span's attributes. Trace query `spans.some` filters fall back to the attributes and do match those spans. With an older adapter, requests using these filters return `501`.

查看`capabilities.spanQueryOutcomeFields` before filtering or grouping spans by `outcome` and `stopReason`. Rows then also include `outcome`, `stopReason` and `stopReasonContext`. These record how the span ended, separately from `status`, and are `null` when the span didn't record them. A missing outcome means "not recorded", not success. `stopReasonContext` can't be used in filters and is omitted when the store lacks `span-query-outcome-fields`. For traces, `capabilities.traceQueryOutcomeFields` enables the same fields on `queryTraces()` and `aggregateTraces()`, where they read the root span. With an older adapter, requests using these fields return `501`:

```typescript
const { capabilities } = await mastraClient.getObservabilityCapabilities()

if (capabilities.spanQueryOutcomeFields) {
  const limited = await mastraClient.querySpans({
    timeRange: { from: '2026-10-01T00:00:00.000Z', to: '2026-10-02T00:00:00.000Z' },
    where: { op: 'eq', left: { path: 'outcome' }, right: { literal: 'limit' } },
  })
  console.log(limited.spans.map(span => [span.stopReason, span.stopReasonContext]))
}
```

看[Filter by outcome](/reference/observability/tracing/advanced-queries#filter-by-outcome) for trace-scope and `spans.some` semantics.

DuckDB 返回`null` for parent/root entity type, ID and name on spans written before `@mastra/duckdb` stored them. Equality filters on these fields don't match those spans.

CLI 在以下情况下返回相同的响应`data`: read `data.spans` and pass `data.page.next` as `page.after`. Span queries support only keyset pagination, so reuse the same time range, predicate, and ordering when following the cursor. A malformed cursor returns `400`, while a cursor that doesn't match the query or scope returns `409`.

使用`mastra api trace span <traceId> <spanId>` or `getSpan(traceId, spanId)` to retrieve a selected span's full details.

## 聚合痕迹 {/* #aggregate-traces */}

使用`aggregateTraces()` or `POST /api/observability/traces/aggregate` to count the selected traces and compute measures over them. Add `groupBy` to split the result by up to two dimensions, and `interval` to split each group into time buckets. The response contains one row per group, or one row per group and bucket.

### 使用客户端 SDK 聚合跟踪 {/* #aggregate-traces-with-the-client-sdk */}

此请求根据一周内的数量、错误率和延迟对Agent进行比较：

```typescript
import { MastraClient } from '@mastra/client-js'

const mastraClient = new MastraClient({ baseUrl: 'http://localhost:4111' })

const { capabilities } = await mastraClient.getObservabilityCapabilities()

if (capabilities.traceAggregate) {
  const { rows, truncated } = await mastraClient.aggregateTraces({
    timeRange: {
      from: '2026-08-01T00:00:00.000Z',
      to: '2026-08-08T00:00:00.000Z',
    },
    where: { op: 'eq', left: { path: 'entityType' }, right: { literal: 'agent' } },
    groupBy: ['entityName'],
    measures: ['count', 'errorRate', 'duration.p95'],
    orderBy: { field: 'errorRate', direction: 'desc' },
    limit: 10,
  })
}
```

客户端重试服务器错误，例如`queryTraces()`, but doesn't retry `422` validation errors.

### 发送聚合 HTTP 请求 {/* #send-an-aggregate-http-request */}

以 JSON 正文形式发送相同的请求：

```bash
curl --request POST \
  --url http://localhost:4111/api/observability/traces/aggregate \
  --header 'Authorization: Bearer <token>' \
  --header 'Content-Type: application/json' \
  --data '{
    "timeRange": {
      "from": "2026-08-01T00:00:00.000Z",
      "to": "2026-08-08T00:00:00.000Z"
    },
    "where": { "op": "eq", "left": { "path": "entityType" }, "right": { "literal": "agent" } },
    "groupBy": ["entityName"],
    "measures": ["count", "errorRate", "duration.p95"],
    "orderBy": { "field": "errorRate", "direction": "desc" },
    "limit": 10
  }'
```

### 聚合请求字段 {/* #aggregate-request-fields */}

|领域 |必填|描述 |
| - | - | - |
|`timeRange` | Yes | Trace start-time boundary, as in [Select traces](#select-traces). The range can span up to 365 days. |
| `where` | No | Trace predicate, as in [Select traces](#select-traces). |
| `measures` | Yes | One or more distinct [measure names](#measures). |
| `groupBy` | No | Up to two distinct [dimensions](#dimensions). Defaults to `[]`, which treats all selected traces as one group. With `interval`, that group has one row per non-empty bucket. No matching traces returns no rows. |
| `interval` | No | Bucket width: `'1m'`, `'5m'`, `'15m'`, `'1h'`, or `'1d'`. See [Time buckets](#time-buckets). |
| `having` | No | Scalar predicate over measures that removes groups after grouping. See [Filter and order groups](#filter-and-order-groups). |
| `orderBy` | No | `{ field, direction }`. `field` is a requested measure, `count`, or a `groupBy` dimension, and `direction` is `asc` or `desc`. Defaults to `count desc`. |
| `limit` | No | Maximum number of groups. Defaults to 100 and has a maximum of 1,000. |

未知字段将被拒绝。聚合不分页。缩小选择范围，或者通过不同的衡量标准进行排名，当`truncated` is `true`.

### 方面 {/* #dimensions */}

维度读取每个选定迹线的当前根跨度：

|尺寸|笔记|
| - | - |
|`entityType`, `entityName`, `environment`, `status`, `serviceName`, `executionSource` | Root span attributes. |
| `threadId`, `resourceId`, `userId`, `sessionId`, `organizationId`, `experimentId` | Context identifiers recorded on the root span. |
| `name`, `spanType` | Root span name and type. Requires the `traceQueryRootSpanFields` capability. |
| `entityId` | Root span entity ID. Groups traces that have no `entityName`, such as scorer runs. Requires the `traceQueryRootEntityId` capability. |
| `outcome`, `stopReason` | How the root span ended and why. Traces whose root span didn't record a value group as `null`. Requires the `traceQueryOutcomeFields` capability. |
| `metadata.<key>` | One non-empty top-level metadata key. Values are trimmed. Missing, empty, and non-string values group as `null`. |

每个维度除了`executionSource` is also a trace-scope `where` field, so you can drill into a group by adding its values to the predicate. `traceId`, `spanId`, `runId`, and `requestId` aren't groupable. Traces with no value for a dimension form their own group with a `null` value. To select that group in a query, use `notExists` for the dimension instead of `eq` with `literal: null`.

#### 代币和成本衡量标准 {/* #token-and-cost-measures */}

令牌和成本度量读取为每个跟踪记录的模型使用指标，因此仅当存储保留所选时间范围的指标时它们才可用。当指标共享跟踪的数据时，该指标就属于该跟踪`traceId` and was recorded at or after `timeRange.from`. Every such metric counts, including usage recorded after `timeRange.to` and usage recorded before a suspend and resume. Retried metric exports are counted once.

记录至少一个使用指标的跟踪是承载使用情况的。`tokens.<kind>.sum` adds the tokens of a group's usage-bearing traces, and `tokens.<kind>.avg` divides that sum by the number of usage-bearing traces, not by `count`. Both are `null` when the group has no usage-bearing traces.

成本来自于总输入和总输出代币指标记录的估计成本。`cost.sum` adds the cost of traces with at least one priced metric, and `cost.avg` divides by the number of those traces. A partly priced call, where Mastra could price some token types but not others, adds the cost of the priced token types. A metric with any other pricing failure adds no cost.

当您请求任何`cost.*` measure, every row also includes a `cost` object:

|领域 |描述 |
| - | - |
|`coverage` | Fraction of usage-bearing traces whose usage was fully priced, from 0 to 1. A trace with a partly priced call isn't fully priced, so it lowers coverage even though its known cost is in `cost.sum`. `null` when the group has no usage-bearing traces. |
| `unit` | Cost unit of the priced metrics, such as `USD`. `'mixed'` when they use more than one unit, and `null` when none are priced. |

`cost.sum`和`cost.avg` are `null` when the group has no priced traces or `unit` is `'mixed'`. A coverage below 1 means the cost understates the group's spend. The `cost` object isn't a measure, so `having` and `orderBy` can't reference it.

### 第一个块的时间 (TTFC) {/* #time-to-first-chunk-ttfc */}

第一个块的时间 (TTFC) 是调用者等待第一个流式传输块的时间。`timeToFirstChunkMs` is the time from a span's start to the first chunk of its model response. Agent run and model spans record it when the model streams a response. On an agent run, it's measured from the run's start and includes work done before the first model call, such as input processors and memory recall.

这`timeToFirstChunk.*` measures aggregate the root span's `timeToFirstChunkMs`, the same value [`queryTraces()`](#query-traces) returns. To filter or sort by it, see [Filter and sort by time to first chunk or token](#filter-and-sort-by-time-to-first-chunk-or-token).

```typescript
const { capabilities } = await mastraClient.getObservabilityCapabilities()

if (capabilities.traceAggregate && capabilities.aggregateTimeToFirstMeasures) {
  const { rows } = await mastraClient.aggregateTraces({
    timeRange: {
      from: '2026-08-01T00:00:00.000Z',
      to: '2026-08-02T00:00:00.000Z',
    },
    where: { op: 'eq', left: { path: 'entityType' }, right: { literal: 'agent' } },
    groupBy: ['entityName'],
    measures: ['timeToFirstChunk.p50', 'timeToFirstChunk.p95', 'timeToFirstChunk.count'],
    orderBy: { field: 'timeToFirstChunk.p95', direction: 'desc' },
  })
}
```

### 第一个令牌的时间 (TTFT) {/* #time-to-first-token-ttft */}

第一个令牌的时间 (TTFT) 是从模型调用开始、提供者请求本身到调用流的第一个块的时间（以毫秒为单位）。与 TTFC 不同，它省略了 Mastra 在调用模型之前所做的工作，例如输入处理器。

这`timeToFirstToken.*` measures aggregate the root span's `timeToFirstTokenMs`. To filter or sort by it, see [Filter and sort by time to first chunk or token](#filter-and-sort-by-time-to-first-chunk-or-token). Compare TTFC with TTFT to see how much of an agent's wait comes from work before the model call.

### 第一个块和令牌跨度类型 {/* #first-chunk-and-token-span-types */}

这些跨度类型记录 TTFC 和 TTFT：

* `model_inference`：每个Provider调用。
* `model_step`：一代的每个步骤，以及流式传输该步骤的第一个块的推理值。
* `model_generation`：整个一代，仅具有其第一个流式推理的值。多步生成（例如Tool循环）仅报告其第一次调用。
* `agent_run`：Agent运行，并使用其自己的循环的第一个模型生成的值。其 TTFC 是从运行开始时测量的。

其他跨度（例如Tool调用和Workflow运行）不会记录这两个值。植根于Workflow的跟踪在跟踪范围内没有 TTFC 或 TTFT。

TTFT 测量一次，就`model_inference` span that streamed the chunk. A step with a fallback model or a retry takes the value of its first inference that streamed a chunk. A failed fallback attempt has a value only if it streamed a chunk before failing. An in-process agent retries a failed model call inside a single inference span. Its TTFT then includes the failed attempt and the retry wait. Durable agents open one inference span per attempt.

Mastra 存储将 TTFT 保留在自己的列中，而不是存储在存储中`attributes`. Read it from the span's `timeToFirstTokenMs` field.

### 缺少第一个块和令牌值 {/* #missing-first-chunk-and-token-values */}

其值为`null` when the span didn't stream a chunk. A value of `0` isn't missing. It means the first chunk arrived in the same millisecond the span started.

* 在谓词中，`null` counts as missing. It matches `notExists` and never matches ordered predicates.
* 在`orderBy`, missing values sort last in both directions, and `0` sorts as a value.
* 在聚合中，没有值的跨度和跟踪将被跳过，永远不会计为 0。

过滤、排序和聚合都需要存储功能。看[Check capabilities](#check-capabilities) for the `traceQueryTimeToFirstChunk`, `traceQueryTimeToFirstChunkSort`, `traceQueryTimeToFirstToken`, `traceQueryTimeToFirstTokenSort`, and `aggregateTimeToFirstMeasures` flags. Against an older store, results omit the unsupported fields, a request that uses them returns `501` before storage runs, and [field discovery](#discover-fields-and-values) omits them.

为了`timeToFirstChunk.*` and `timeToFirstToken.*`, `avg`, `min`, `max`, and the percentiles are `null` for a group where no trace has a value, and `.count` is the number of traces that do have one. Percentiles can be approximate, depending on the store. The measures require the `aggregateTimeToFirstMeasures` capability.

### 筛选和排序组 {/* #filter-and-order-groups */}

组是一组不同的组合`groupBy` values. `having`, `orderBy`, and `limit` operate on groups and use each group's measures over the whole time range, even when `interval` is set. The server applies `having` first, then orders the remaining groups and keeps the first `limit`. `truncated` is `true` when more groups remained than `limit`.

`having`使用带有度量名称作为路径的标量谓词形状，例如`{ op: 'gt', left: { path: 'duration.p95' }, right: { literal: 5000 } }`. It can reference requested measures and `count`, even when `count` isn't requested. It supports comparison operators, `in`, and `notIn` with number literals, combined with `and`, `or`, and `not`. Presence, tag, and text operators aren't supported. A `null` measure never satisfies a `having` comparison, so the group is removed.

此请求使Workflow程的 95% 持续时间超过 5 秒：

```typescript
const slowWorkflows = await mastraClient.aggregateTraces({
  timeRange: {
    from: '2026-08-01T00:00:00.000Z',
    to: '2026-08-08T00:00:00.000Z',
  },
  where: { op: 'eq', left: { path: 'entityType' }, right: { literal: 'workflow_run' } },
  groupBy: ['entityName'],
  measures: ['count', 'duration.p95', 'duration.p99'],
  having: { op: 'gt', left: { path: 'duration.p95' }, right: { literal: 5000 } },
  orderBy: { field: 'duration.p95', direction: 'desc' },
})
```

排序是确定性的。关系按维度值按升序排列。`null` measure and dimension values sort last in both directions.

### 时间桶 {/* #time-buckets */}

和`interval`, each group that survives `having` and `limit` expands into one row per non-empty bucket. Buckets are aligned to UTC, so `1d` buckets start at midnight UTC, and each row's `bucket` is the ISO start time of its bucket. A trace belongs to the bucket containing its root `startedAt`. Rows are ordered by group, then by `bucket` ascending.

没有痕迹的存储桶将被忽略，而不是作为零行返回。绘制图表时填补客户端上的空白。由于组在整个时间范围内排名第一，因此每个返回的组都包含其全系列的非空桶。

此请求返回每个Agent的每日令牌使用情况和成本：

```typescript
const dailyCost = await mastraClient.aggregateTraces({
  timeRange: {
    from: '2026-08-01T00:00:00.000Z',
    to: '2026-08-08T00:00:00.000Z',
  },
  where: { op: 'eq', left: { path: 'entityType' }, right: { literal: 'agent' } },
  groupBy: ['entityName'],
  interval: '1d',
  measures: ['count', 'tokens.total.sum', 'cost.sum', 'cost.avg'],
  orderBy: { field: 'cost.sum', direction: 'desc' },
  limit: 5,
})
```

### 总计限制和错误 {/* #aggregate-limits-and-errors */}

|限制|最大|
| - | - |
|时间范围 | 365 天 |
|`groupBy` dimensions | 2 |
| `limit` | 1,000 groups |
| Buckets in the time range | 1,000 |
| `limit` × buckets | 10,000 rows |

谓词限制来自[Query limits](#query-limits) apply to both `where` and `having`, and the request body is limited to 256 KiB. A time range that doesn't start on a bucket boundary touches one more bucket than its length divided by the interval. If the range has too many buckets, choose a wider `interval`. If `limit` × buckets exceeds 10,000, reduce `limit` or widen the interval.

PostgreSQL 和 ClickHouse 使用相同的[execution timeout](#keyset-ordering-and-errors) for aggregations as for trace queries, defaulting to 15 seconds. The timeout doesn't apply to DuckDB.

| - | - |

| `413` | The request body exceeds 256 KiB. |

## 聚合跨度 {/* #aggregate-spans */}

使用`aggregateSpans()` or `POST /api/observability/spans/aggregate` to compute measures over individual spans instead of traces. Trace aggregation only sees each trace's root span, so an agent run nested inside a workflow isn't counted. Span aggregation counts every span that matches, at any depth.

请求的形状与[`aggregateTraces()`](#aggregate-request-fields), with the same fixed measures, `having`, `orderBy`, `interval`, and shared limits. Its `where`, dimensions, and `countDistinct` fields follow the span contract below. Unsupported span aggregation returns `501 SPAN_AGGREGATE_UNSUPPORTED`.

### 使用客户端 SDK 聚合跨度 {/* #aggregate-spans-with-the-client-sdk */}

此请求按每天的状态对Agent运行进行计数，包括嵌套运行：

```typescript
const { capabilities } = await mastraClient.getObservabilityCapabilities()

if (capabilities.spanAggregate) {
  const { rows } = await mastraClient.aggregateSpans({
    timeRange: {
      from: '2026-08-01T00:00:00.000Z',
      to: '2026-08-08T00:00:00.000Z',
    },
    where: { op: 'eq', left: { path: 'spanType' }, right: { literal: 'agent_run' } },
    groupBy: ['status'],
    interval: '1d',
    measures: ['count', 'duration.p95'],
  })
}
```

将相同的正文发送至`POST /api/observability/spans/aggregate` to use HTTP directly.

### 量程选择 {/* #span-selection */}

聚合使用与以下相同的跨度谓词[`querySpans()`](#query-spans), with the ClickHouse selection differences described below:

* `timeRange`限制每个跨度的`startedAt`, and can span up to 365 days.
* `where`接受`querySpans()` fields and operators, such as `spanType`, `name`, `status`, `durationMs`, `model`, `provider`, entity and parent/root entity fields, and context identifiers. Like `querySpans()`, `model` and `provider` filters read only the span's columns, not its attributes.
* 只有完成的跨度才算数。当一个跨度被导出多次时，只有它的最新副本才有效。

`count`计算每个组或时间段中选定的跨度。桶使用每个跨度`startedAt`. `duration.*` measures read the span's own duration, and `errorCount` and `errorRate` read whether the span itself recorded an error.

`timeToFirstToken.*`和`timeToFirstChunk.*` read the span's own `timeToFirstTokenMs` and `timeToFirstChunkMs`. See [First chunk and token span types](#first-chunk-and-token-span-types) for which spans record them. Filter to `model_inference` for per-call TTFT, or to `agent_run` for latency as the caller of each agent sees it. Without a `spanType` filter, one agent call contributes its agent run, its model generation, and every model step and model inference.

在 ClickHouse 上，直接`spanType` `eq` or `in` predicate, or one immediately inside an `and`, can select the smaller branch table. All selected types must be branch types: `agent_run`, `workflow_run`, `processor_run`, `scorer_run`, `rag_ingestion`, `tool_call`, or `mcp_tool_call`. Every requested field must be available in that table. An equivalent `or` predicate doesn't select this optimization. The branch path can differ from `querySpans()`:

* 升级前写入的跨度`@mastra/clickhouse` 1.4, 1.5, or 1.6 aren't in the branch table, so older windows can count fewer spans.
* ClickHouse合并多次导出的span副本后，分支表保留最后写入的副本，而不是最后结束的副本。保留版本的状态和持续时间可能有所不同。即使跨度标识未更改，这也可能会更改过滤计数和组成员身份。

### 跨度尺寸 {/* #span-dimensions */}

|尺寸|笔记|
| - | - |
|`name`, `spanType`, `status` | The span's own name, type, and status. `status` is `error` when the span recorded an error and `success` otherwise. |
| `outcome`, `stopReason` | How the span ended and why. Spans without a recorded value group as `null`. Requires the `spanQueryOutcomeFields` capability. |
| `entityType`, `entityId`, `entityName` | The entity that produced the span. |
| `parentEntityType`, `parentEntityName`, `rootEntityType`, `rootEntityName` | The calling entity and the trace's root entity, such as the agent that made a model call. |
| `environment`, `serviceName`, `executionSource` | Deployment attributes recorded on the span. |
| `threadId`, `resourceId`, `userId`, `sessionId`, `organizationId`, `experimentId` | Context identifiers recorded on the span. |
| `model`, `provider` | The model and provider recorded on the span's `model` and `provider` columns, such as `__AI_SDK_ANTHROPIC_MODEL_SONNET__` and `anthropic`. Requires the `spanAggregateModelDimensions` capability. |

`countDistinct.<field>` 接受这些尺寸并且`traceId`, so `countDistinct.traceId` counts the traces the selected spans belong to. Span aggregation can't group by `metadata.<key>` or identity fields such as `traceId`, `spanId`, or `runId`.

就像`model` and `provider` filters, the `model` and `provider` dimensions read only the span's columns, not its attributes. Existing spans aren't backfilled, so spans exported before `@mastra/observability` filled the columns group under `null`, and `countDistinct.model` doesn't count them.

商店通过以下方式宣传支持`span-aggregate-model-dimensions` feature, and the server reports it as the `spanAggregateModelDimensions` capability. Against an older store, a request that groups by `model` or `provider` or counts their distinct values returns `501` before storage runs.

### Span代币和成本 {/* #span-tokens-and-cost */}

令牌和成本度量使用每个跨度记录的使用指标，并匹配`traceId` and `spanId`. The [trace token rules](#token-and-cost-measures) apply per span: metrics from `timeRange.from` on count, retried exports count once, and averages divide by usage-bearing spans.

使用量不会添加到父跨度中。模型调用记录使用情况`model_generation` spans, so an `agent_run` span has no tokens of its own unless a model call under it wasn't exported. When a `model_generation` span isn't exported, its usage is recorded on the nearest exported ancestor instead. For token totals per agent, select `model_generation` spans and group by the calling agent:

```typescript
const tokensByAgent = await mastraClient.aggregateSpans({
  timeRange: {
    from: '2026-08-01T00:00:00.000Z',
    to: '2026-08-08T00:00:00.000Z',
  },
  where: { op: 'eq', left: { path: 'spanType' }, right: { literal: 'model_generation' } },
  groupBy: ['parentEntityName'],
  measures: ['tokens.total.sum', 'cost.sum'],
  orderBy: { field: 'cost.sum', direction: 'desc' },
})
```

要比较模型，请将相同的跨度分组为`model`:

```typescript
const { capabilities } = await mastraClient.getObservabilityCapabilities()

if (capabilities.spanAggregateModelDimensions) {
  const { rows } = await mastraClient.aggregateSpans({
    timeRange: {
      from: '2026-08-01T00:00:00.000Z',
      to: '2026-08-08T00:00:00.000Z',
    },
    where: { op: 'eq', left: { path: 'spanType' }, right: { literal: 'model_generation' } },
    groupBy: ['provider', 'model'],
    measures: ['count', 'tokens.total.sum', 'cost.sum'],
  })
  // rows[0]: { dimensions: { provider: 'anthropic', model: '__AI_SDK_ANTHROPIC_MODEL_SONNET__' }, measures: { ... } }
}
```

### 列出组后面的跨度 {/* #list-the-spans-behind-a-group */}

聚合永远不会返回跨度记录。要检查一个组，请发送相同的`timeRange` and `where` to `querySpans()`, and add non-null dimension values as `eq` conditions. For a null dimension, use `notExists`, such as `{ op: 'notExists', path: 'entityName' }`. `eq` with `literal: null` is rejected. For example, add `{ op: 'eq', left: { path: 'status' }, right: { literal: 'error' } }` to list the failed agent runs from the first example.

## 可信租户范围 {/* #trusted-tenant-scope */}

为多个租户提供服务的主机在查询文档之外提供可信范围。服务器读取保留的`organizationId` request-context key, which only server-side authentication can set, and passes `{ organizationId }` to the planner. The scope is carried on the trusted plan and ANDed into every scan: current roots, related spans, the usage metrics read by token and cost measures, span aggregation, and both discovery routes. A related record from another tenant that shares a `traceId` never qualifies a trace.

直接调用存储的主机可以将更完整的范围传递给`planTraceQuery()`, `planTraceAggregate()`, `planSpanAggregate()`, `planTraceQueryObservedFields()`, and `planTraceQueryValues()`:

```typescript
const plan = planTraceQuery(parseTraceQueryRequest(request), {
  scope: { organizationId: 'org_123', resourceId: 'project_456' },
})
```

`resourceId`是可选的并在组织内缩小范围。键集和增量游标绑定到范围。在一个作用域下创建并在另一个作用域下重用的游标返回`409` before storage runs. A scoped request against an observability store or `@mastra/core` that predates tenant scope returns `501` instead of running unscoped. Stores advertise support through the `trace-query-tenant-scope` feature. Callers can't name `projectId` in predicates. An `organizationId` predicate compares recorded data and is ANDed with the scope, so it can only narrow the tenant's own traces and never widens it. Without a scope the routes behave as before, so self-hosted installations keep their own tenant model.

## 发现领域和价值 {/* #discover-fields-and-values */}

使用跟踪查询发现来构建字段和值自动完成功能，而无需扫描跟踪负载或将查询语法复制到客户端中。配置的可观察性存储必须支持`trace-query-discovery`.

CLI 不公开专用的发现命令，因此请使用下面的 SDK 方法或 HTTP 端点`POST /api/observability/traces/query/fields` and `POST /api/observability/traces/query/values`.

称呼`getTraceQueryFields()` for one predicate scope:

```typescript
const timeRange = {
  from: '2026-08-01T00:00:00.000Z',
  to: '2026-08-08T00:00:00.000Z',
}

const fields = await mastraClient.getTraceQueryFields({
  timeRange,
  predicateScope: 'trace',
  search: 'region',
  limit: 25,
})
```

该响应将规范字段与观察到的元数据字段分开：

```json
{
  "canonicalFields": [],
  "observedFields": [
    {
      "path": "metadata.region",
      "valueKind": "string",
      "operators": ["eq", "ne", "in", "notIn", "exists", "notExists"],
      "valueSuggestions": true,
      "occurrences": 125
    }
  ],
  "observedFieldsTruncated": false
}
```

规范字段来自用于验证跟踪查询的同一注册表。他们不消费`limit`. The canonical order follows that registry. `observedFields` contains top-level string `metadata.<key>` paths found on qualifying current root spans. These fields are ordered by `occurrences` descending, then by path. Nested metadata, keys containing `.`, empty keys, non-string values, and oversized paths are omitted.

`predicateScope`选择局部谓词语法。这不是授权范围：

| `predicateScope` | Example returned path | Query usage |
| - | - | - |
| `trace` | `environment` or `metadata.region` | Root `where` predicate |
| `spans` | `model` | Inside `spans.some` or `spans.none` |

字段选择器可以请求`trace` and `spans` scopes in parallel and label each field with its scope. Every returned path is directly accepted by `queryTraces()` in its matching scope. `metadata` by itself isn't a field. A user interface can offer manual metadata-key entry separately.

对于`trace` scope, when the server and store support aggregation, the fields response also includes an `aggregate` object that describes what `aggregateTraces()` accepts:

```json
{
  "aggregate": {
    "dimensions": [{ "path": "entityName", "valueKind": "string" }],
    "measures": [
      {
        "name": "duration.p95",
        "kind": "duration",
        "statistic": "p95",
        "unit": "milliseconds",
        "approximate": true
      }
    ]
  }
}
```

`dimensions`列出商店支持的规范维度。每观察到`metadata.<key>` field is also a dimension, and `countDistinct.<field>` accepts any dimension or `traceId`. `measures` lists each fixed measure with its `kind`, `unit`, and whether it's `approximate`.

用户选择一个字段后`valueSuggestions: true`, call `getTraceQueryValues()`:

```typescript
const abortController = new AbortController()
const suggestions = await mastraClient.getTraceQueryValues(
  {
    timeRange,
    predicateScope: 'trace',
    path: 'metadata.region',
    search: 'west',
    limit: 25,
  },
  { signal: abortController.signal },
)
```

```json
{
  "values": [
    { "value": "eu-west-1", "count": 82 },
    { "value": "us-west-2", "count": 43 }
  ],
  "valuesTruncated": false
}
```

Discovery 仅返回字符串值。缺失值、空字符串和大于 4,096 UTF-8 字节的字符串将被忽略。值的排序方式为`count` descending, then by value. Suggestions are advisory: `queryTraces()` continues to accept valid manual literals that discovery doesn't return.

值建议可用于这些规范字段：

|范围 |领域 |
| - | - |
|追踪|`entityName`, `entityType`, `name`, `spanType`, `environment`, `status`, `outcome`, `stopReason`, `tags` |
| Spans | `name`, `spanType`, `model`, `provider`, `status`, `outcome`, `stopReason`, `entityType`, `entityName` |

`outcome`和`stopReason` suggestions require the `traceQueryOutcomeFields` capability. Each executable top-level string `metadata.<key>` field also supports value suggestions in the `trace` scope. Identifiers, timestamps, durations, time to first chunk, time to first token, errors, and version IDs don't. The fields response still includes canonical fields with `valueSuggestions: false`. The values endpoint rejects those paths with `422 TRACE_QUERY_INVALID`.

两个发现请求都需要半开放时间范围。它们使用相同的当前记录语义`queryTraces()`: qualifying completed roots satisfy `from <= startedAt < to`, and related values come only from current records joined to those roots by `traceId`. Discovery doesn't accept or apply a draft `where` predicate.

`search`默认为空字符串，被修剪，并匹配不区分大小写的文字子字符串。字符如`%` and `_` have no wildcard meaning. An empty search returns the most frequent results. `limit` defaults to 25 and has a maximum of 100. Both endpoints fetch one extra result to set their truncation flag, but don't provide a cursor. When a flag is `true`, refine `search`. It doesn't imply that a next page is available. No matches return an empty array and `false` truncation.

如果发现超过其执行超时，则路由返回`504 TRACE_QUERY_EXECUTION_TIMEOUT`. If the backend exceeds a memory or resource budget, it returns `503 TRACE_QUERY_RESOURCE_LIMIT`. Neither failure returns partial suggestions or sets a truncation flag. Truncation only means a complete ranking was cut to the requested response limit.

ClickHouse 发现请求默认为 5 秒超时和每个查询 256 MiB 内存限制。配置这些`observability.traceQuery.discovery.timeoutMs` and `observability.traceQuery.discovery.memoryLimitBytes` on `ClickhouseStoreVNext`. Discovery falls back to `observability.traceQuery.timeoutMs` when its timeout isn't configured, without changing ordinary `queryTraces()` execution limits.

两条路线都需要`observability:read` and use the configured observability storage boundary. Don't send organization or project authorization fields in the request. Treat discovered paths, values, and counts as observability data.

## 局限性 {/* #limitations */}

查询和聚合 API 仅考虑已完成的跟踪和跨度，而不考虑正在运行的跟踪和跨度。跟踪查询无法返回自定义投影、嵌入证据或摘要，并且编号的跟踪页面包含总计数。跟踪聚合无法按除根跨度之外的跨度字段进行分组`name`, `spanType`, and `entityId`, or by `traceId` or `attributes.*`. Aggregation can't compute numeric measures over metadata, paginate groups, or zero-fill empty buckets. Span aggregation can't group by `model` or `provider`, and it attributes tokens only to the span that recorded them. The CLI's `mastra api trace aggregate` covers trace aggregation, and `mastra api span query` and `mastra api span aggregate` cover span queries and span aggregation.
