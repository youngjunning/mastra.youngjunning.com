# 奥泰布里奇酒店

：：：警告

OpenTelemetry Bridge 目前正在**experimental**. APIs and configuration options may change in future releases.

:::

实现 Mastra 跟踪和 OpenTelemetry 基础设施之间的双向集成。为 Mastra 操作创建本机 OTEL 跨度并从活动 OTEL 跨度继承上下文。还将 Mastra 日志事件转发到全球注册的 OTEL`LoggerProvider`, emitting each log under the OTEL context of the originating Mastra span so trace-log correlation works automatically.

### `onLogEvent` {/* #onlogevent */}

```typescript oxfmt:false
async onLogEvent(event: LogEvent): Promise<void>
```

将 Mastra 日志事件转发到全局注册的 OTEL`LoggerProvider`. Trace correlation is resolved in this order:

1. 如果日志带有`spanId` the bridge has an OTEL span for, the log is emitted under that span's stored OTEL context.
2. 否则，如果日志携带`traceId` and `spanId`, those IDs are attached to the emitted log record's `SpanContext`.
3. 否则，日志将在当前处于活动状态的任何 OTEL 上下文下发出。

如果没有`LoggerProvider` is registered globally, emission is a silent no-op.

### `flush` {/* #flush */}

```typescript oxfmt:false
async flush(): Promise<void>
```

强制刷新跟踪器提供程序和记录器提供程序（如果它们支持）`forceFlush`. The global providers are resolved at flush time, so a `LoggerProvider` registered after the bridge was constructed is flushed too. Useful in serverless environments where you need to drain telemetry before the runtime terminates. Call `sdk.shutdown()` as well before the process exits to wait for any batch your OTEL SDK has already started exporting. Neither this method nor the provider's own `forceFlush()` waits for that batch.

### `shutdown` {/* #shutdown */}

```typescript oxfmt:false
async shutdown(): Promise<void>
```

关闭桥梁并清理资源。结束任何未正确关闭的跨度，然后刷新提供程序以便导出这些跨度。

## 使用示例 {/* #usage-examples */}

### 基本用法 {/* #basic-usage */}

```typescript
import { Mastra } from '@mastra/core'
import { Observability } from '@mastra/observability'
import { OtelBridge } from '@mastra/otel-bridge'

const mastra = new Mastra({
  observability: new Observability({
    configs: {
      default: {
        serviceName: 'my-service',
        bridge: new OtelBridge(),
      },
    },
  }),
  agents: { myAgent },
})
```

### 与出口商联合 {/* #combined-with-exporters */}

该桥可以与出口商一起使用。桥接器处理 OTEL 上下文，而导出器将数据发送到其他目的地：

```typescript
import { Mastra } from '@mastra/core'
import { Observability, MastraStorageExporter } from '@mastra/observability'
import { OtelBridge } from '@mastra/otel-bridge'
import { LangfuseExporter } from '@mastra/langfuse'

const mastra = new Mastra({
  observability: new Observability({
    configs: {
      default: {
        serviceName: 'my-service',
        bridge: new OtelBridge(), // Handles OTEL context
        exporters: [
          new MastraStorageExporter(), // Studio access
          new LangfuseExporter({
            // Additional destination
            publicKey: process.env.LANGFUSE_PUBLIC_KEY,
            secretKey: process.env.LANGFUSE_SECRET_KEY,
          }),
        ],
      },
    },
  }),
})
```

## 设置要求 {/* #setup-requirements */}

该桥通过 OpenTelemetry 跟踪器提供程序创建跨度。对于要导出的 Mastra 跨度：

* **必须有可用的跟踪器提供程序。**&#x5728; Mastra 运行之前全局注册一个，例如通过调用`sdk.start()` on `NodeSDK` from `@opentelemetry/sdk-node`, or by calling `trace.setGlobalTracerProvider(provider)`. If the provider isn't registered globally, pass it with `new OtelBridge({ tracerProvider })`.
* **必须安装上下文管理器，Mastra 跨度才能嵌套在外部跨度下。** `NodeSDK` installs one automatically. Without a context manager, spans are still exported, but Mastra root spans can't read the active span, so they start new traces instead of joining the outer trace.

当没有可用的跟踪器提供程序时，Agent和Workflow仍会运行，但不会通过 OpenTelemetry 导出 Mastra 范围。网桥记录此警告一次：

```text
[OtelBridge] No OpenTelemetry tracer provider is registered globally, so Mastra spans will not be exported through OpenTelemetry. ...
```

请参阅[OtelBridge Guide](/integrations/observability/opentelemetry#bridge) for complete setup instructions, including how to configure OTEL instrumentation and run your application.

## 标签支持 {/* #tags-support */}

OtelBridge 支持跟踪标记以进行分类和过滤。标签仅应用于根跨度并作为`mastra.tags` attribute on native OTEL spans.

### 用法 {/* #usage */}

```typescript
const result = await agent.generate('Hello', {
  tracingOptions: {
    tags: ['production', 'experiment-v2', 'user-request'],
  },
})
```

### 标签如何存储 {/* #how-tags-are-stored */}

标签作为 JSON 字符串化数组存储在`mastra.tags` span attribute:

```json
{
  "mastra.tags": "[\"production\",\"experiment-v2\",\"user-request\"]"
}
```

该格式与所有 OTEL 兼容的后端和收集器兼容。
