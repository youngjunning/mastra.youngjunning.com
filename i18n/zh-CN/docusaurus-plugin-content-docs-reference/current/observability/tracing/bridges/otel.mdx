# OtelBridge

:::warning

OpenTelemetry Bridge 目前仍处于**实验阶段**。API 和配置选项可能在后续版本中变更。

:::

将 Mastra 追踪与 OpenTelemetry 基础设施双向集成：为 Mastra 操作创建原生 OTEL span，并继承当前 OTEL span 的上下文。它还会将 Mastra 日志事件转发至全局注册的 OTEL `LoggerProvider`，在事件来源 Mastra span 的 OTEL 上下文中发出日志，自动关联追踪与日志。

### `onLogEvent` {/* #onlogevent */}

```typescript oxfmt:false
async onLogEvent(event: LogEvent): Promise<void>
```

将 Mastra 日志事件转发至全局注册的 OTEL `LoggerProvider`。追踪关联按以下顺序确定：

1. 如果日志中的 `spanId` 对应 bridge 持有的 OTEL span，则在该 span 保存的 OTEL 上下文中发出日志。
1. 否则，如果日志同时包含 `traceId` 和 `spanId`，则将这两个 ID 附加到所发出日志记录的 `SpanContext`。
1. 否则，在当前活动的 OTEL 上下文中发出日志。

如果没有全局注册的 `LoggerProvider`，则不发出日志，也不报错。

### `flush` {/* #flush */}

```typescript oxfmt:false
async flush(): Promise<void>
```

如果 tracer provider 和 logger provider 支持 `forceFlush`，则强制刷新它们。全局 provider 会在刷新时获取，因此即使 `LoggerProvider` 在 bridge 创建后才注册，也会被刷新。这适用于需要在运行时终止前排空遥测数据的无服务器环境。进程退出前还应调用 `sdk.shutdown()`，等待 OTEL SDK 已开始导出的批次；此方法和 provider 自身的 `forceFlush()` 都不会等待该批次。

### `shutdown` {/* #shutdown */}

```typescript oxfmt:false
async shutdown(): Promise<void>
```

关闭 bridge 并清理资源。先结束未正确关闭的 span，再刷新 provider 以导出这些 span。

## 使用示例 {/* #usage-examples */}

### 基本用法 {/* #basic-usage */}

```typescript
import { Mastra } from '@mastra/core'
import { Observability } from '@mastra/observability'
import { OtelBridge } from '@mastra/otel-bridge'

const mastra = new Mastra({
  observability: new Observability({
    configs: {
      default: {
        serviceName: 'my-service',
        bridge: new OtelBridge(),
      },
    },
  }),
  agents: { myAgent },
})
```

### 与 Exporter 配合使用 {/* #combined-with-exporters */}

Bridge 可以与 Exporter 配合使用：Bridge 负责 OTEL 上下文，Exporter 则将数据发送至其他目标：

```typescript
import { Mastra } from '@mastra/core'
import { Observability, MastraStorageExporter } from '@mastra/observability'
import { OtelBridge } from '@mastra/otel-bridge'
import { LangfuseExporter } from '@mastra/langfuse'

const mastra = new Mastra({
  observability: new Observability({
    configs: {
      default: {
        serviceName: 'my-service',
        bridge: new OtelBridge(), // Handles OTEL context
        exporters: [
          new MastraStorageExporter(), // Studio access
          new LangfuseExporter({
            // Additional destination
            publicKey: process.env.LANGFUSE_PUBLIC_KEY,
            secretKey: process.env.LANGFUSE_SECRET_KEY,
          }),
        ],
      },
    },
  }),
})
```

## 设置要求 {/* #setup-requirements */}

Bridge 通过 OpenTelemetry tracer provider 创建 span。要导出 Mastra span，需满足以下条件：

- **必须提供 tracer provider。** 在 Mastra 运行前全局注册一个，例如调用 `@opentelemetry/sdk-node` 中 `NodeSDK` 的 `sdk.start()`，或调用 `trace.setGlobalTracerProvider(provider)`。如果没有全局注册，请通过 `new OtelBridge({ tracerProvider })` 传入。
- **要将 Mastra span 嵌套在外层 span 下，必须安装上下文管理器。** `NodeSDK` 会自动安装。没有上下文管理器时，span 仍可导出，但 Mastra 根 span 无法读取当前活动的 span，因此会启动新 trace，而不会加入外层 trace。

如果没有可用的 tracer provider，Agent 和 Workflow 仍会运行，但不会通过 OpenTelemetry 导出 Mastra span。Bridge 只会记录一次以下警告：

```text
[OtelBridge] No OpenTelemetry tracer provider is registered globally, so Mastra spans will not be exported through OpenTelemetry. ...
```

完整设置步骤（包括配置 OTEL 插桩和运行应用）请参阅 [OtelBridge 指南](/integrations/observability/opentelemetry#bridge)。

## 标签支持 {/* #tags-support */}

OtelBridge 支持为 trace 添加标签，以便分类和筛选。标签只应用于根 span，并作为原生 OTEL span 的 `mastra.tags` 属性保存。

### 用法 {/* #usage */}

```typescript
const result = await agent.generate('Hello', {
  tracingOptions: {
    tags: ['production', 'experiment-v2', 'user-request'],
  },
})
```

### 标签如何存储 {/* #how-tags-are-stored */}

标签以 JSON 字符串形式的数组存储在 span 的 `mastra.tags` 属性中：

```json
{
  "mastra.tags": "[\"production\",\"experiment-v2\",\"user-request\"]"
}
```

该格式与所有 OTEL 兼容的后端和收集器兼容。
