# 数据狗桥

：：：警告

Datadog 桥目前**experimental**. APIs and configuration options may change in future releases.

:::

启用 Mastra 跟踪和 Datadog 之间的双向集成。创建原生`dd-trace` APM spans in real time so that auto-instrumented operations inside tools and processors are correctly nested under their parent Mastra span. Emits LLM Observability data through `dd-trace`'s pipeline when spans end.

## 构造函数 {/* #constructor */}

```typescript oxfmt:false

```

## 方法 {/* #methods */}

### `createSpan` {/* #createspan */}

```typescript oxfmt:false
createSpan(options: CreateSpanOptions<SpanType>): SpanIds | undefined
```

在跨度构造期间由 Mastra Observability实例调用。通过以下方式急切地创建 dd-trace APM 跨度`tracer.startSpan()` and returns Mastra-compatible identifiers. The returned IDs are used by Mastra throughout the span's lifetime. The dd-trace span object is stored internally and used for scope activation.

**返回：** `SpanIds | undefined` - `{ spanId, traceId, parentSpanId }`, or `undefined` if the bridge is disabled.

### `executeInContext` {/* #executeincontext */}

```typescript oxfmt:false
executeInContext<T>(spanId: string, fn: () => Promise<T>): Promise<T>
```

在 Mastra span 的 dd-trace 上下文中执行异步函数。函数内部运行的 dd-trace 自动检测操作（HTTP、数据库等）将成为该跨度的父级。

### `flush` {/* #flush */}

```typescript oxfmt:false
async flush(): Promise<void>
```

将任何缓冲的 LLM Observability数据强制刷新到 Datadog，而无需关闭桥接器。在无服务器环境中很有用，您需要确保在运行时终止之前导出数据。

刷新是尽力而为：dd-trace 从后台编写器发送 LLM Observability数据，并且无法等待请求，因此`flush()` waits `flushGraceMs` (default 2000 ms) after asking dd-trace to flush, then flushes the APM exporter. Each flush that sent new data costs that full wait, so a serverless handler that awaits `flush()` per request pays it per request. Raise it if spans from short-lived processes are missing in Datadog, or set it to `0` to skip the wait when something else keeps the process alive.

### `shutdown` {/* #shutdown */}

```typescript oxfmt:false
async shutdown(): Promise<void>
```

强制完成任何未正确关闭的 APM 范围并刷新待处理的 LLM Observability数据。然后它会禁用集成并清除所有内部状态。

## 使用示例 {/* #usage-examples */}

### 基本用法 {/* #basic-usage */}

```typescript
import tracer from 'dd-trace'

tracer.init({
  service: process.env.DD_SERVICE || 'my-mastra-app',
  env: process.env.DD_ENV || 'production',
})

import { Mastra } from '@mastra/core'
import { Observability } from '@mastra/observability'
import { DatadogBridge } from '@mastra/datadog'

const mastra = new Mastra({
  observability: new Observability({
    configs: {
      default: {
        serviceName: 'my-mastra-app',
        bridge: new DatadogBridge({
          mlApp: process.env.DD_LLMOBS_ML_APP!,
        }),
      },
    },
  }),
  agents: { myAgent },
})
```

### 无Agent模式（仅LLM可观察性，无本地Agent） {/* #agentless-mode-llm-observability-only-no-local-agent */}

如果您没有本地 Datadog Agent 并且只需要 LLM Observability数据，请启用无Agent模式：

```typescript
new DatadogBridge({
  mlApp: process.env.DD_LLMOBS_ML_APP!,
  apiKey: process.env.DD_API_KEY!,
  agentless: true,
})
```

注意：APM 数据无法在无Agent模式下发送。如果您只需要LLM可观察性数据而不需要`dd-trace` APM, the [Datadog Exporter](/reference/observability/tracing/exporters/datadog) is a simpler choice.

### 与其他出口商 {/* #with-additional-exporters */}

该桥可以与非 Datadog 导出器结合使用，将跟踪发送到其他目的地：

```typescript
import { Mastra } from '@mastra/core'
import { Observability, MastraStorageExporter } from '@mastra/observability'
import { DatadogBridge } from '@mastra/datadog'

const mastra = new Mastra({
  observability: new Observability({
    configs: {
      default: {
        serviceName: 'my-mastra-app',
        bridge: new DatadogBridge({
          mlApp: process.env.DD_LLMOBS_ML_APP!,
        }),
        exporters: [
          new MastraStorageExporter(), // Studio access
        ],
      },
    },
  }),
})
```

:::注意
不要合并`DatadogBridge` with `DatadogExporter` in the same configuration. Both emit to LLM Observability and would double-write the same data.
:::

## 设置要求 {/* #setup-requirements */}

DatadogBridge 需要`dd-trace` to be initialized before any other imports so its auto-instrumentation can patch HTTP, database, and framework libraries at load time.

请参阅[DatadogBridge Guide](/integrations/observability/datadog#bridge) for complete setup instructions, including dd-trace initialization, bundler externals, and agent configuration.

## 跨度映射 {/* #span-mapping */}

Mastra 跨度类型映射到 Datadog LLM Observability跨度类型：

|马斯特拉 SpanType |数据狗种类 |
| - | - |
|`AGENT_RUN` | `agent` |
| `MODEL_GENERATION` | `workflow` |
| `MODEL_STEP` | `llm` |
| `TOOL_CALL` | `tool` |
| `MCP_TOOL_CALL` | `tool` |
| `WORKFLOW_RUN` | `workflow` |
| All other types | `task` |

## 标签支持 {/* #tags-support */}

`tracingOptions.tags`值成为结构化的LLM可观察性注释标签：`key:value` entries are split into key/value pairs, and tags without a colon are set to `true`.

```typescript
const result = await agent.generate('Hello', {
  tracingOptions: {
    tags: ['production', 'instance_name:career-scout-api'],
  },
})
```

这会产生：

```json
{
  "production": true,
  "instance_name": "career-scout-api"
}
```

## 环境变量 {/* #environment-variables */}

桥接器从这些环境变量中读取配置：

|变量|描述 |
| - | - |
|`DD_API_KEY` | Datadog API key (only required for agentless mode) |
| `DD_LLMOBS_ML_APP` | ML application name |
| `DD_SITE` | Datadog site |
| `DD_ENV` | Environment name |
| `DD_LLMOBS_AGENTLESS_ENABLED` | Set to `'true'` or `'1'` to enable agentless mode |
