# DatadogBridge

:::warning

Datadog Bridge 目前仍处于**实验阶段**。API 和配置选项可能在后续版本中变更。

:::

将 Mastra 追踪与 Datadog 双向集成。实时创建原生 `dd-trace` APM span，使 Tool 和处理器内通过自动插桩生成的操作正确嵌套在其父 Mastra span 下。span 结束时，通过 `dd-trace` 的管道发送 LLM Observability 数据。

## 构造函数 {/* #constructor */}

```typescript oxfmt:false
new DatadogBridge(config?: DatadogBridgeConfig)
```

## 方法 {/* #methods */}

### `createSpan` {/* #createspan */}

```typescript oxfmt:false
createSpan(options: CreateSpanOptions<SpanType>): SpanIds | undefined
```

在构建 span 时由 Mastra 可观测性实例调用。立即通过 `tracer.startSpan()` 创建 dd-trace APM span，并返回兼容 Mastra 的标识符。Mastra 在 span 的整个生命周期内使用这些 ID。dd-trace span 对象保存在内部，用于激活作用域。

**返回：** `SpanIds | undefined` - `{ spanId, traceId, parentSpanId }`；如果 Bridge 已禁用，则返回 `undefined`。

### `executeInContext` {/* #executeincontext */}

```typescript oxfmt:false
executeInContext<T>(spanId: string, fn: () => Promise<T>): Promise<T>
```

在 Mastra span 的 dd-trace 上下文中执行异步函数。函数内由 dd-trace 自动插桩的操作（HTTP、数据库等）会以该 span 为父 span。

### `flush` {/* #flush */}

```typescript oxfmt:false
async flush(): Promise<void>
```

强制将缓冲的 LLM Observability 数据刷新到 Datadog，而不关闭 Bridge。适用于需要在运行时终止前确保数据导出的无服务器环境。

刷新采用尽力而为的方式：dd-trace 通过后台写入器发送 LLM Observability 数据，无法等待请求完成。因此，要求 dd-trace 刷新后，`flush()` 会等待 `flushGraceMs`（默认 2000 毫秒），再刷新 APM Exporter。每次发送新数据的刷新都会产生完整的等待时间，因此无服务器处理程序若每次请求都等待 `flush()`，每次请求也都会等待。若短生命周期进程的 span 未出现在 Datadog 中，可延长等待时间；若有其他机制保持进程运行，可设为 `0` 跳过等待。

### `shutdown` {/* #shutdown */}

```typescript oxfmt:false
async shutdown(): Promise<void>
```

强制结束未正确关闭的 APM span，并刷新待发送的 LLM Observability 数据。随后禁用集成并清空所有内部状态。

## 使用示例 {/* #usage-examples */}

### 基本用法 {/* #basic-usage */}

```typescript
import tracer from 'dd-trace'

tracer.init({
  service: process.env.DD_SERVICE || 'my-mastra-app',
  env: process.env.DD_ENV || 'production',
})

import { Mastra } from '@mastra/core'
import { Observability } from '@mastra/observability'
import { DatadogBridge } from '@mastra/datadog'

const mastra = new Mastra({
  observability: new Observability({
    configs: {
      default: {
        serviceName: 'my-mastra-app',
        bridge: new DatadogBridge({
          mlApp: process.env.DD_LLMOBS_ML_APP!,
        }),
      },
    },
  }),
  agents: { myAgent },
})
```

### 无 Agent 模式（仅 LLM Observability，无本地 Agent） {/* #agentless-mode-llm-observability-only-no-local-agent */}

如果没有本地 Datadog Agent，且只需 LLM Observability 数据，请启用无 Agent 模式：

```typescript
new DatadogBridge({
  mlApp: process.env.DD_LLMOBS_ML_APP!,
  apiKey: process.env.DD_API_KEY!,
  agentless: true,
})
```

注意：无 Agent 模式无法发送 APM 数据。如果只需 LLM Observability 数据，而不需要 `dd-trace` APM，[Datadog Exporter](/reference/observability/tracing/exporters/datadog) 更简单。

### 与其他 Exporter 配合使用 {/* #with-additional-exporters */}

Bridge 可与非 Datadog Exporter 组合使用，将 trace 发送至其他目标：

```typescript
import { Mastra } from '@mastra/core'
import { Observability, MastraStorageExporter } from '@mastra/observability'
import { DatadogBridge } from '@mastra/datadog'

const mastra = new Mastra({
  observability: new Observability({
    configs: {
      default: {
        serviceName: 'my-mastra-app',
        bridge: new DatadogBridge({
          mlApp: process.env.DD_LLMOBS_ML_APP!,
        }),
        exporters: [
          new MastraStorageExporter(), // Studio access
        ],
      },
    },
  }),
})
```

:::note
不要在同一配置中同时使用 `DatadogBridge` 和 `DatadogExporter`。两者都会向 LLM Observability 发送数据，导致同一数据写入两次。
:::

## 设置要求 {/* #setup-requirements */}

DatadogBridge 要求在其他 import 之前初始化 `dd-trace`，以便自动插桩在加载 HTTP、数据库和框架库时对其进行修补。

完整设置步骤（包括 dd-trace 初始化、打包工具的 external 配置和 Agent 配置）请参阅 [DatadogBridge 指南](/integrations/observability/datadog#bridge)。

## 跨度映射 {/* #span-mapping */}

Mastra span 类型映射为 Datadog LLM Observability span 类别：

| Mastra SpanType | Datadog 类别 |
| - | - |
|`AGENT_RUN` | `agent` |
| `MODEL_GENERATION` | `workflow` |
| `MODEL_STEP` | `llm` |
| `TOOL_CALL` | `tool` |
| `MCP_TOOL_CALL` | `tool` |
| `WORKFLOW_RUN` | `workflow` |
| 其他所有类型 | `task` |

## 标签支持 {/* #tags-support */}

`tracingOptions.tags` 的值会成为结构化的 LLM Observability 注释标签：`key:value` 项拆分为键值对，不含冒号的标签则设为 `true`。

```typescript
const result = await agent.generate('Hello', {
  tracingOptions: {
    tags: ['production', 'instance_name:career-scout-api'],
  },
})
```

这会产生：

```json
{
  "production": true,
  "instance_name": "career-scout-api"
}
```

## 环境变量 {/* #environment-variables */}

桥接器从这些环境变量中读取配置：

|变量|描述 |
| - | - |
| `DD_API_KEY` | Datadog API 密钥（仅无 Agent 模式需要） |
| `DD_LLMOBS_ML_APP` | ML 应用名称 |
| `DD_SITE` | Datadog 站点 |
| `DD_ENV` | 环境名称 |
| `DD_LLMOBS_AGENTLESS_ENABLED` | 设为 `'true'` 或 `'1'` 可启用无 Agent 模式 |
