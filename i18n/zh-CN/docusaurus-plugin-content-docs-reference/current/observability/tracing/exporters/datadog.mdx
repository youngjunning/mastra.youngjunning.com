# 数据狗导出器

将跟踪数据发送到 Datadog 的 LLM Observability 产品以进行监控和分析。

:::注意
如果你也使用`dd-trace` APM auto-instrumentation and need it correctly parented under Mastra spans, use the [数据狗桥](/reference/observability/tracing/bridges/datadog)反而。导出器在执行完成后发送LLM Observability数据，因此它不参与`dd-trace`的直播范围。
:::

## 构造函数 {/* #constructor */}

```typescript oxfmt:false
new DatadogExporter(config: DatadogExporterConfig)
```

## `DatadogExporterConfig` {/* #datadogexporterconfig */}

interface DatadogExporterConfig extends BaseExporterConfig {
  apiKey?: string
  mlApp?: string
  site?: string
  service?: string
  env?: string

  integrationsEnabled?: boolean

* `logger?: IMastraLogger`- 记录器实例
* `logLevel?: LogLevel | 'debug' | 'info' | 'warn' | 'error'`- 日志级别（默认：INFO）

## 方法 {/* #methods */}

### `exportTracingEvent` {/* #exporttracingevent */}

```typescript oxfmt:false
async exportTracingEvent(event: TracingEvent): Promise<void>
```

将跟踪事件导出到 Datadog LLM Observability。

### 冲水 {/* #flush */}

```typescript oxfmt:false
async flush(): Promise<void>
```

强制将任何缓冲的跨度刷新到 Datadog，而不关闭导出器。在无服务器环境中很有用，您需要确保在运行时终止之前导出跨度。

刷新是尽力而为：dd-trace 从后台编写器发送 LLM Observability数据，并且无法等待请求，因此`flush()` waits `flushGraceMs` (default 2000 ms) after asking dd-trace to flush. Each flush that sent new data costs that full wait, so a serverless handler that awaits `flush()` per request pays it per request. Raise it if spans from short-lived processes are missing in Datadog, or set it to `0` to skip the wait when something else keeps the process alive.

### 关闭 {/* #shutdown */}

```typescript oxfmt:false
async shutdown(): Promise<void>
```

刷新待处理数据并关闭导出器。取消任何挂起的清理计时器并禁用 LLM 可观察性。

## 用法 {/* #usage */}

### 零配置（使用环境变量） {/* #zero-config-using-environment-variables */}

```typescript
import { DatadogExporter } from '@mastra/datadog'

// Reads from DD_LLMOBS_ML_APP, DD_API_KEY, DD_SITE, DD_ENV
const exporter = new DatadogExporter()
```

### 显式配置 {/* #explicit-configuration */}

```typescript
import { DatadogExporter } from '@mastra/datadog'

const exporter = new DatadogExporter({
  mlApp: 'my-llm-app',
  apiKey: process.env.DD_API_KEY,
  site: 'datadoghq.com',
  env: 'production',
})
```

### 使用本地 Datadog Agent {/* #with-local-datadog-agent */}

```typescript
const exporter = new DatadogExporter({
  mlApp: 'my-llm-app',
  agentless: false, // Use local Datadog Agent
  env: 'production',
})
```

## 跨度映射 {/* #span-mapping */}

Mastra 跨度类型映射到 Datadog LLM Observability跨度类型：

|马斯特拉 SpanType |数据狗种类 |
| - | - |
|`AGENT_RUN` | `agent` |
| `MODEL_GENERATION` | `workflow` |
| `MODEL_STEP` | `llm` |
| `TOOL_CALL` | `tool` |
| `MCP_TOOL_CALL` | `tool` |
| `PROVIDER_TOOL_CALL` | `tool` |
| `WORKFLOW_RUN` | `workflow`|
|所有其他类型 |`task` |

所有未映射的跨度类型（包括`MODEL_CHUNK`, `WORKFLOW_STEP`, `GENERIC`, and future span types) automatically default to `task`.

## 环境变量 {/* #environment-variables */}

导出器从这些环境变量中读取配置：

|变量|描述 |
| - | - |
|`DD_API_KEY` | Datadog API key |
| `DD_LLMOBS_ML_APP` | ML application name |
| `DD_SITE` | Datadog site |
| `DD_ENV` | Environment name |
| `DD_LLMOBS_AGENTLESS_ENABLED` | Set to 'false' or '0' to use local agent |
