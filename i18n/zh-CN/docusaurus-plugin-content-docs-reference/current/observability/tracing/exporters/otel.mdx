# OtelExporter

向兼容 OpenTelemetry 的可观测性平台发送追踪和日志。追踪采用标准化的 GenAI 语义约定。日志保留原始严重级别和消息内容，并通过 OTEL 日志记录自带的追踪上下文以及 `mastra.traceId` / `mastra.spanId` 属性关联到追踪。

## 构造函数 {/* #constructor */}

```typescript oxfmt:false
new OtelExporter(config: OtelExporterConfig)
```

## 元数据映射 {/* #metadata-mapping */}

使用 `metadataMapping`，可按后端要求将 `userId` 等元数据放在指定的 Span 属性名下：

```typescript
import { OtelExporter } from '@mastra/otel-exporter'

const exporter = new OtelExporter({
  provider: {
    custom: { endpoints: { traces: 'https://collector.example.com/v1/traces' } },
  },
  metadataMapping: { userId: 'user.id', tenantId: 'tenant.id' },
})
```

元数据为 `{ userId: 'user-123', tenantId: 'acme' }` 的 Span 会导出 `user.id` 和 `tenant.id`，同时保留现有的 `mastra.metadata.userId` 和 `mastra.metadata.tenantId` 属性。映射适用于包含所选元数据键的每个 Span，包括子 Span。

映射后的值均为字符串。对象和数组会进行 JSON 编码；缺失的键、`null`、`undefined` 和空字符串会被省略。`0` 和 `false` 分别变为 `"0"` 和 `"false"`。键按字面匹配，因此带点号的键不会选中嵌套属性。空的目标名称会被忽略。

显式映射会覆盖同名的现有属性。如果多个元数据键映射到同一名称，以最后一个非空值为准。映射不会影响日志记录或资源属性。

### 自定义信号端点 {/* #custom-signal-endpoints */}

`endpoint` 和 `endpoints` 只能提供其中之一。TypeScript 会拒绝同时包含两者的配置；运行时校验也会拒绝该配置，并在报错后禁用 exporter。

使用 `endpoints` 为每种信号提供准确的 URL。URL 会原样传给所选 exporter，不会增删或替换路径段。追踪与日志端点可以使用不同主机和互不相关的路径：

```typescript
import { OtelExporter } from '@mastra/otel-exporter'

const exporter = new OtelExporter({
  provider: {
    custom: {
      protocol: 'http/protobuf',
      endpoints: {
        traces: 'https://traces.example.com/api/ingest/?tenant=acme',
        logs: 'https://logs.example.com/events',
      },
    },
  },
})
```

至少提供一个信号端点。仅导出追踪时省略 `logs`；仅导出日志时省略 `traces`。即使已配置端点，`signals` 开关仍可禁用对应信号。协议和请求头适用于两个端点，所选协议必须支持该信号。自定义 `exporter` 实例仍会覆盖追踪传输方式。

也可以显式传入环境变量的值：

```typescript
const exporter = new OtelExporter({
  provider: {
    custom: {
      endpoints: {
        traces: process.env.OTEL_EXPORTER_OTLP_TRACES_ENDPOINT,
        logs: process.env.OTEL_EXPORTER_OTLP_LOGS_ENDPOINT,
      },
    },
  },
})
```

类型要求至少包含一个信号键；使用环境变量配置时，值可以是 `undefined`。运行时至少有一个 URL 必须非空。缺失的值会禁用对应信号。Mastra 不会自动加载端点环境变量。

为兼容现有配置，单数形式的 `endpoint` 保持原有行为：OTLP 信号路径从 collector URL 派生，Zipkin 则直接使用配置的 URL。自定义路径请改用 `endpoints`。

## 方法 {/* #methods */}

### `exportTracingEvent` {/* #exporttracingevent */}

```typescript oxfmt:false
async exportTracingEvent(event: TracingEvent): Promise<void>
```

将追踪事件导出到已配置的 OTEL 后端。

### flush {/* #flush */}

```typescript oxfmt:false
async flush(): Promise<void>
```

强制将缓冲的 Span 刷新到 OTEL 后端，而不关闭 exporter。适用于无服务器环境，可确保 Span 在运行时终止前导出。

### shutdown {/* #shutdown */}

```typescript oxfmt:false
async shutdown(): Promise<void>
```

刷新待处理的追踪并关闭 exporter。

## 协议要求 {/* #protocol-requirements */}

不同 provider 需要不同的 OTEL exporter 包。追踪和日志导出相互独立：如果只需追踪，仅安装追踪包；如果还需导出日志，则同时安装所选协议对应的追踪包和日志包。Zipkin 不支持 OTLP 日志。

| 协议 | 追踪包 | 日志包 |
| - | - | - |
| gRPC | `@opentelemetry/exporter-trace-otlp-grpc` (+ `@grpc/grpc-js`) | `@opentelemetry/exporter-logs-otlp-grpc` (+ `@grpc/grpc-js`) |
| HTTP/Protobuf | `@opentelemetry/exporter-trace-otlp-proto` | `@opentelemetry/exporter-logs-otlp-proto` |
| HTTP/JSON | `@opentelemetry/exporter-trace-otlp-http` | `@opentelemetry/exporter-logs-otlp-http` |
| Zipkin | `@opentelemetry/exporter-zipkin` | 不支持 |

## 标签支持 {/* #tags-support */}

OtelExporter 支持为追踪添加标签，以便分类和筛选。标签只应用于根 Span，并存储在 `mastra.tags` 属性中。

### 用法 {/* #usage */}

```typescript
const result = await agent.generate('Hello', {
  tracingOptions: {
    tags: ['production', 'experiment-v2', 'user-request'],
  },
})
```

### 标签的存储方式 {/* #how-tags-are-stored */}

为尽可能兼容各类后端，标签会以 JSON 字符串化数组的形式存储在 Span 的 `mastra.tags` 属性中：

```json
{
  "mastra.tags": "[\"production\",\"experiment-v2\",\"user-request\"]"
}
```

:::note
虽然 OpenTelemetry 规范支持原生数组属性，但许多后端（Jaeger、Zipkin、Tempo）对数组的支持有限。使用 JSON 字符串可确保各可观测性平台的行为一致。
:::
