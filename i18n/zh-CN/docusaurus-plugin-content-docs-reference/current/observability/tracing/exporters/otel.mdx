# 奥特尔出口商

将跟踪和日志发送到任何与 OpenTelemetry 兼容的可观测平台。跟踪使用标准化 GenAI 语义约定。日志携带其原始严重性和消息正文，并通过 OTEL 日志记录的本机跟踪上下文和跟踪与跟踪相关联。`mastra.traceId` / `mastra.spanId`属性。

## 构造函数 {/* #constructor */}

```typescript oxfmt:false
new OtelExporter(config: OtelExporterConfig)
```

## 元数据映射 {/* #metadata-mapping */}

使用`metadataMapping` when your backend expects metadata such as `userId` under a specific span attribute name:

```typescript
import { OtelExporter } from '@mastra/otel-exporter'

const exporter = new OtelExporter({
  provider: {
    custom: { endpoints: { traces: 'https://collector.example.com/v1/traces' } },
  },
  metadataMapping: { userId: 'user.id', tenantId: 'tenant.id' },
})
```

带有元数据的跨度`{ userId: 'user-123', tenantId: 'acme' }` exports both `user.id` and `tenant.id`, alongside the existing `mastra.metadata.userId` and `mastra.metadata.tenantId`属性。映射适用于包含所选元数据键的每个范围，包括子范围。

映射值是字符串。对象和数组是 JSON 编码的。钥匙丢失，`null`, `undefined`, and empty strings are omitted. `0` and `false` become `"0"` and `"false"`。键按字面匹配，因此包含点的键不会选择嵌套属性。空目标名称将被忽略。

显式映射会覆盖具有相同目标名称的现有属性。如果多个元数据键映射到同一名称，则最后一个具有非空值的映射获胜。映射不会影响日志记录或资源属性。

### 自定义信号端点 {/* #custom-signal-endpoints */}

供应任一`endpoint` or `endpoints`, never both. TypeScript rejects configurations with both options. Runtime validation also rejects them and disables the exporter with an error message.

使用`endpoints` to supply the exact URL for each signal. URLs are passed to the selected exporter without adding, removing, or replacing path segments. Trace and log endpoints can use different hosts and unrelated paths:

```typescript
import { OtelExporter } from '@mastra/otel-exporter'

const exporter = new OtelExporter({
  provider: {
    custom: {
      protocol: 'http/protobuf',
      endpoints: {
        traces: 'https://traces.example.com/api/ingest/?tenant=acme',
        logs: 'https://logs.example.com/events',
      },
    },
  },
})
```

提供至少一个信号端点。忽略`logs` for trace-only export or `traces` for log-only export. The `signals` toggles can still disable a configured signal. Protocol and headers apply to both endpoints. The selected protocol must support the signal. A custom `exporter` instance overrides trace transport as before.

您可以显式传递环境变量值：

```typescript
const exporter = new OtelExporter({
  provider: {
    custom: {
      endpoints: {
        traces: process.env.OTEL_EXPORTER_OTLP_TRACES_ENDPOINT,
        logs: process.env.OTEL_EXPORTER_OTLP_LOGS_ENDPOINT,
      },
    },
  },
})
```

该类型需要至少一个信号键并允许`undefined` values for environment-variable configuration. At runtime, at least one URL must be non-empty. A missing value disables that signal. Mastra doesn't load endpoint environment variables automatically.

奇异的`endpoint` option retains its existing behavior for compatibility: OTLP signal paths are derived from the collector URL, and Zipkin uses the configured URL directly. For custom paths, use `endpoints` instead.

## 方法 {/* #methods */}

### `exportTracingEvent` {/* #exporttracingevent */}

```typescript oxfmt:false
async exportTracingEvent(event: TracingEvent): Promise<void>
```

将跟踪事件导出到配置的 OTEL 后端。

### 冲水 {/* #flush */}

```typescript oxfmt:false
async flush(): Promise<void>
```

强制将任何缓冲的跨度刷新到 OTEL 后端，而无需关闭导出器。在无服务器环境中很有用，您需要确保在运行时终止之前导出跨度。

### 关闭 {/* #shutdown */}

```typescript oxfmt:false
async shutdown(): Promise<void>
```

刷新待处理的跟踪并关闭导出器。

## 协议要求 {/* #protocol-requirements */}

不同的Provider需要不同的 OTEL 导出程序包。跟踪和日志导出是独立的：如果您只需要跟踪，则仅安装跟踪包；如果您还需要日志导出，则安装所选协议的跟踪和日志包。 Zipkin 不支持 OTLP 日志。

|协议|追踪包 |日志包|
| - | - | - |
| gRPC |`@opentelemetry/exporter-trace-otlp-grpc` (+ `@grpc/grpc-js`) | `@opentelemetry/exporter-logs-otlp-grpc` (+ `@grpc/grpc-js`) |
| HTTP/Protobuf | `@opentelemetry/exporter-trace-otlp-proto` | `@opentelemetry/exporter-logs-otlp-proto` |
| HTTP/JSON | `@opentelemetry/exporter-trace-otlp-http` | `@opentelemetry/exporter-logs-otlp-http` |
| Zipkin | `@opentelemetry/exporter-zipkin` | not supported |

## 标签支持 {/* #tags-support */}

OtelExporter 支持跟踪标记以进行分类和过滤。标签仅应用于根跨度并存储为`mastra.tags` attribute.

### 用法 {/* #usage */}

```typescript
const result = await agent.generate('Hello', {
  tracingOptions: {
    tags: ['production', 'experiment-v2', 'user-request'],
  },
})
```

### 标签如何存储 {/* #how-tags-are-stored */}

标签作为 JSON 字符串化数组存储在`mastra.tags` span attribute for maximum backend compatibility:

```json
{
  "mastra.tags": "[\"production\",\"experiment-v2\",\"user-request\"]"
}
```

:::注意
虽然 OpenTelemetry 规范支持本机数组属性，但许多后端（Jaeger、Zipkin、Tempo）对数组的支持有限。 JSON 字符串确保所有可观察平台的行为一致。
:::
