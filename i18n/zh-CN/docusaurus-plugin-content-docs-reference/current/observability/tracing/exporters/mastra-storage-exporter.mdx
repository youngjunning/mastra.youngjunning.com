# MastraStorageExporter

通过自动批处理和重试逻辑将跟踪保留到 Mastra 的配置存储。

：：：笔记

`MastraStorageExporter`以前被称为`DefaultExporter`. The original `DefaultExporter`类仍然导出自`@mastra/observability`因此现有的导入仍然有效，但它已被弃用，并将在未来的主要版本中删除。新代码应该使用`MastraStorageExporter`.

:::

:::警告 平台存储限制

什么时候`MASTRA_DEPLOYMENT_ID` is set, this exporter is disabled by default. Set `retainStorageExporterOnPlatform: true` on the **observability config**, not the exporter constructor, to allow remote storage export. `InMemoryStore` (including the fallback when no storage is configured), local libSQL, embedded replicas, and DuckDB remain blocked when the adapter reports local persistence, even with the opt-in. No observability events are written to that local database, even if the initialization warning is hidden by your logging setup.

看[storage export on Platform](/docs/observability/integrations/exporters/mastra-storage#export-to-storage-and-platform) for the supported-provider table, adapter upgrade requirements, and a configuration example.

:::

## `MastraStorageExporterConfig` {/* #mastrastorageexporterconfig */}

```typescript
interface MastraStorageExporterConfig extends BaseExporterConfig {
  /** Opt-in byte flush thresholds. Omit to keep count-based batching. */
  byteBatching?: {
    maxBatchBytes?: number // Default: 8 MiB
    maxConcurrentWrites?: number // Default: 1
  }

  /** Maximum number of spans per batch. Default: 1000 */
  maxBatchSize?: number

  /** Maximum total buffer size before emergency flush. Default: 10000 */
  maxBufferSize?: number

  /** Maximum time to wait before flushing batch in milliseconds. Default: 5000 */
  maxBatchWaitMs?: number

  /** Maximum number of retry attempts. Default: 4 */
  maxRetries?: number

  /** Base retry delay in milliseconds (uses exponential backoff). Default: 500 */
  retryDelayMs?: number

  /** Tracing storage strategy or 'auto' for automatic selection. Default: 'auto' */
  strategy?: TracingStorageStrategy | 'auto'
}
```

延伸`BaseExporterConfig`, which includes:

* `logger?: IMastraLogger`- 记录器实例
* `logLevel?: LogLevel | 'debug' | 'info' | 'warn' | 'error'`- 日志级别（默认：INFO）

## 字节批处理 {/* #byte-batching */}

启用字节批处理`byteBatching: {}` or supply custom thresholds. The exporter ignores byte batching when the resolved strategy is `realtime`, which keeps its immediate, awaited writes:

```typescript
new MastraStorageExporter({
  byteBatching: {
    maxBatchBytes: 8 * 1024 * 1024,
    maxConcurrentWrites: 1,
  },
})
```

* `maxBatchBytes`默认情况下，当缓冲事件达到 8 MiB 时触发写入。较大的记录会完整发送，不会被截断或基于大小的丢弃。
* `maxConcurrentWrites`控制并发存储写入。默认值为 1。基于更新的跟踪策略始终一次使用一次写入来保留跨度顺序。

记录计数和基于计时器的刷新触发器仍然适用。当存储落后时，排队的记录会被保留，因此队列内存会增长。没有`byteBatching`, the exporter keeps its existing count-based batching behavior.

检查当前队列`exporter.getByteBatchingStats()`.

## `TracingStorageStrategy` {/* #tracingstoragestrategy */}

```typescript
type TracingStorageStrategy = 'realtime' | 'batch-with-updates' | 'insert-only'
```

### 策略行为 {/* #strategy-behaviors */}

* **即时的**：立即将每个事件持久保存到存储中
* **批量更新**：批量创建和单独更新，按顺序应用
* **仅插入**：仅处理SPAN\_ENDED事件，忽略更新

## 自动策略选择 {/* #automatic-strategy-selection */}

什么时候`strategy: 'auto'` (default), the exporter queries the storage adapter for its capabilities:

```typescript
interface TracingStrategy {
  /** Strategies supported by this adapter */
  supported: TracingStorageStrategy[]

  /** Preferred strategy for optimal performance */
  preferred: TracingStorageStrategy
}
```

出口商将：

1. 使用存储适配器的首选策略（如果可用）
2. 如果首选策略不可用，则回退到第一个支持的策略
3. 如果不支持用户指定的策略，则记录警告

## 批处理行为 {/* #batching-behavior */}

### 冲洗触发器 {/* #flush-triggers */}

当满足以下任何条件时，缓冲区将刷新：

* 缓冲区大小达到`maxBatchSize`
* 自第一个缓冲事件以来的时间超过`maxBatchWaitMs`
* 缓冲区大小达到`maxBufferSize` (emergency flush)
* `shutdown()`被称为

### 重试逻辑 {/* #retry-logic */}

使用指数退避重试失败的刷新：

* 重试延迟：`retryDelayMs * 2^attempt`
* 最大尝试次数：`maxRetries`
* 所有重试失败后批次将被丢弃

### 无序处理 {/* #out-of-order-handling */}

为了`batch-with-updates` strategy:

* 已创建的轨道
* 拒绝更新/结束尚未创建的跨度
* 记录无序事件的警告
* 维护有序更新的序列号

## 用法 {/* #usage */}

```typescript
import { MastraStorageExporter } from '@mastra/observability'

// Default configuration
const exporter = new MastraStorageExporter()

// Custom batching configuration
const customExporter = new MastraStorageExporter({
  maxBatchSize: 500,
  maxBatchWaitMs: 2000,
  strategy: 'batch-with-updates',
  logLevel: 'debug',
})
```

## 迁移自`DefaultExporter` {/* #migrating-from-defaultexporter */}

这两个类共享相同的构造函数签名和行为。要迁移，请替换导入和构造函数：

```typescript
// Before
import { DefaultExporter } from '@mastra/observability'
const exporter = new DefaultExporter()

// After
import { MastraStorageExporter } from '@mastra/observability'
const exporter = new MastraStorageExporter()
```

原来的`DefaultExporter` is preserved unchanged so dashboards or alert rules that match the previous `mastra-default-observability-exporter` exporter name keep working until you migrate.
