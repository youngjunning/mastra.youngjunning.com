# MastraStorageExporter

通过自动批处理和重试机制，将追踪数据持久化到 Mastra 配置的存储中。

:::note

`MastraStorageExporter` 以前称为 `DefaultExporter`。`@mastra/observability` 仍导出原有的 `DefaultExporter` 类，因此现有导入可以继续使用；但该类已弃用，并将在未来的主版本中移除。新代码应使用 `MastraStorageExporter`。

:::

:::warning 平台存储限制

设置 `MASTRA_DEPLOYMENT_ID` 后，此导出器默认停用。要允许导出到远程存储，请在**可观测性配置**中设置 `retainStorageExporterOnPlatform: true`，而不是在导出器构造函数中设置。即使选择启用，当适配器报告使用本地持久化时，`InMemoryStore`（包括未配置存储时的回退方案）、本地 libSQL、嵌入式副本和 DuckDB 仍会被禁止。即使日志设置隐藏了初始化警告，也不会向该本地数据库写入可观测性事件。

支持的提供商列表、适配器升级要求和配置示例，请参阅[平台上的存储导出](/docs/observability/integrations/exporters/mastra-storage#export-to-storage-and-platform)。

:::

## Span 预览 {/* #span-previews */}

`MastraStorageExporter` 会根据 span 类型自动生成简短易读的 `inputPreview`、`outputPreview` 和 `errorPreview` 摘要。每项预览最多包含 100 个字符；截断时会附加省略号。完整载荷仍可单独获取。

## `MastraStorageExporterConfig` {/* #mastrastorageexporterconfig */}

```typescript
interface MastraStorageExporterConfig extends BaseExporterConfig {
  /** Opt-in byte flush thresholds. Omit to keep count-based batching. */
  byteBatching?: {
    maxBatchBytes?: number // Default: 8 MiB
    maxConcurrentWrites?: number // Default: 1
  }

  /** Maximum number of spans per batch. Default: 1000 */
  maxBatchSize?: number

  /** Maximum total buffer size before emergency flush. Default: 10000 */
  maxBufferSize?: number

  /** Maximum time to wait before flushing batch in milliseconds. Default: 5000 */
  maxBatchWaitMs?: number

  /** Maximum number of retry attempts. Default: 4 */
  maxRetries?: number

  /** Base retry delay in milliseconds (uses exponential backoff). Default: 500 */
  retryDelayMs?: number

  /** Tracing storage strategy or 'auto' for automatic selection. Default: 'auto' */
  strategy?: TracingStorageStrategy | 'auto'
}
```

继承 `BaseExporterConfig`，其中包含：

* `logger?: IMastraLogger` — 日志记录器实例
* `logLevel?: LogLevel | 'debug' | 'info' | 'warn' | 'error'` — 日志级别（默认：INFO）

## 按字节批处理 {/* #byte-batching */}

使用 `byteBatching: {}` 启用按字节批处理，也可以指定自定义阈值。当解析出的策略为 `realtime` 时，导出器会忽略按字节批处理，继续立即写入并等待写入完成：

```typescript
new MastraStorageExporter({
  byteBatching: {
    maxBatchBytes: 8 * 1024 * 1024,
    maxConcurrentWrites: 1,
  },
})
```

* `maxBatchBytes`：缓冲事件默认达到 8 MiB 时触发写入。更大的记录会完整发送，不会因大小而截断或丢弃。
* `maxConcurrentWrites`：控制并发存储写入数，默认值为 1。基于更新的追踪策略始终逐次写入，以保持 span 顺序。

按记录数和计时器触发的刷新仍然有效。存储写入跟不上时，排队的记录会保留，因此队列占用的内存可能增长。未启用 `byteBatching` 时，导出器沿用按记录数批处理的行为。

使用 `exporter.getByteBatchingStats()` 查看当前队列。

## `TracingStorageStrategy` {/* #tracingstoragestrategy */}

```typescript
type TracingStorageStrategy = 'realtime' | 'batch-with-updates' | 'insert-only'
```

### 策略行为 {/* #strategy-behaviors */}

* **`realtime`**：立即将每个事件写入存储。
* **`batch-with-updates`**：分别批量处理创建和更新，并按顺序应用。
* **`insert-only`**：仅处理 `SPAN_ENDED` 事件，忽略更新。

## 自动策略选择 {/* #automatic-strategy-selection */}

当 `strategy: 'auto'`（默认值）时，导出器会查询存储适配器支持的能力：

```typescript
interface TracingStrategy {
  /** Strategies supported by this adapter */
  supported: TracingStorageStrategy[]

  /** Preferred strategy for optimal performance */
  preferred: TracingStorageStrategy
}
```

导出器将：

1. 使用存储适配器的首选策略（如果可用）
2. 如果首选策略不可用，则回退到第一个受支持的策略。
3. 如果用户指定的策略不受支持，则记录警告。

## 批处理行为 {/* #batching-behavior */}

### 刷新触发条件 {/* #flush-triggers */}

当满足以下任何条件时，缓冲区将刷新：

* 缓冲区大小达到 `maxBatchSize`。
* 距离第一个缓冲事件的时间超过 `maxBatchWaitMs`。
* 缓冲区大小达到 `maxBufferSize`（紧急刷新）。
* 调用 `shutdown()`。

### 重试逻辑 {/* #retry-logic */}

使用指数退避重试失败的刷新：

* 重试延迟：`retryDelayMs * 2^attempt`
* 最大尝试次数：`maxRetries`
* 所有重试失败后批次将被丢弃

### 乱序事件处理 {/* #out-of-order-handling */}

对于 `batch-with-updates` 策略：

* 跟踪哪些 span 已创建。
* 拒绝更新或结束尚未创建的 span。
* 对乱序事件记录警告。
* 维护序列号，确保更新按序进行。

## 用法 {/* #usage */}

```typescript
import { MastraStorageExporter } from '@mastra/observability'

// Default configuration
const exporter = new MastraStorageExporter()

// Custom batching configuration
const customExporter = new MastraStorageExporter({
  maxBatchSize: 500,
  maxBatchWaitMs: 2000,
  strategy: 'batch-with-updates',
  logLevel: 'debug',
})
```

## 迁移自`DefaultExporter` {/* #migrating-from-defaultexporter */}

两个类的构造函数签名和行为相同。迁移时替换导入和构造函数：

```typescript
// Before
import { DefaultExporter } from '@mastra/observability'
const exporter = new DefaultExporter()

// After
import { MastraStorageExporter } from '@mastra/observability'
const exporter = new MastraStorageExporter()
```

原有的 `DefaultExporter` 保持不变，因此在完成迁移前，匹配旧导出器名称 `mastra-default-observability-exporter` 的仪表板和告警规则仍可正常工作。
