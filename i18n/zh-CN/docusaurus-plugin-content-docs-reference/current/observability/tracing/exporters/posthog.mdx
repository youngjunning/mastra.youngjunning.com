# PosthogExporter

将 Tracing 数据发送到 PostHog，用于 AI 可观测性和分析。

## 构造函数 {/* #constructor */}

```typescript oxfmt:false
new PosthogExporter(config: PosthogExporterConfig)
```

## `PosthogExporterConfig` {/* #posthogexporterconfig */}

```typescript
interface PosthogExporterConfig extends BaseExporterConfig {
  apiKey?: string
  host?: string
  flushAt?: number
  flushInterval?: number
  serverless?: boolean
  defaultDistinctId?: string
  enablePrivacyMode?: boolean
}
```

继承 `BaseExporterConfig`，其中还包括：

* `logger?: IMastraLogger` - 日志记录器实例
* `logLevel?: LogLevel | 'debug' | 'info' | 'warn' | 'error'` - 日志级别（默认：INFO）

## 方法 {/* #methods */}

### `exportTracingEvent` {/* #exporttracingevent */}

```typescript oxfmt:false
async exportTracingEvent(event: TracingEvent): Promise<void>
```

将追踪事件导出到 PostHog。

### `onFeedbackEvent` {/* #onfeedbackevent */}

```typescript oxfmt:false
async onFeedbackEvent(event: FeedbackEvent): Promise<void>
```

将反馈事件导出到 PostHog。参见[反馈导出](#feedback-export)。

### flush {/* #flush */}

```typescript oxfmt:false
async flush(): Promise<void>
```

将缓冲的事件强制发送到 PostHog，但不关闭导出器。适用于需要在运行时终止前确保 Span 已导出的无服务器环境。

### 关闭 {/* #shutdown */}

```typescript oxfmt:false
async shutdown(): Promise<void>
```

刷新待发送的批量事件，并关闭 PostHog 客户端。

## 用法 {/* #usage */}

### 零配置（使用环境变量） {/* #zero-config-using-environment-variables */}

```typescript
import { PosthogExporter } from '@mastra/posthog'

// Reads from POSTHOG_API_KEY, POSTHOG_HOST
const exporter = new PosthogExporter()
```

### 显式配置 {/* #explicit-configuration */}

```typescript
import { PosthogExporter } from '@mastra/posthog'

const exporter = new PosthogExporter({
  apiKey: process.env.POSTHOG_API_KEY!,
  host: 'https://us.i.posthog.com',
  serverless: true,
})
```

## Span 类型映射 {/* #span-type-mapping */}

| Mastra Span 类型 | PostHog 事件类型 |
| - | - |
|`MODEL_INFERENCE` | `$ai_generation` |
| `MODEL_GENERATION` | `$ai_span` |
| `MODEL_STEP` | `$ai_span` |
| `MODEL_CHUNK` | `$ai_span` |
| `TOOL_CALL` | `$ai_span` |
| `MCP_TOOL_CALL` | `$ai_span` |
| `PROVIDER_TOOL_CALL` | `$ai_span` |
| `PROCESSOR_RUN` | `$ai_span` |
| `AGENT_RUN` | `$ai_span` |
| `WORKFLOW_RUN` | `$ai_span`|
| 所有其他 Workflow | `$ai_span` |
| `GENERIC` | `$ai_span` |

每次调用模型 Provider 都会产生一个 `MODEL_INFERENCE` Span，并导出为一条 `$ai_generation` 事件。事件包含模型、token 用量、输出，以及本次调用传入的工具定义（存于 `$ai_tools`）。其 `$ai_input` 是本次调用收到的对话：本次运行的输入消息，以及此前每次调用的输出和工具结果。一次运行调用模型三次，就会发送三条 `$ai_generation` 事件。

`MODEL_GENERATION` Span 包裹这些调用，并导出为 `$ai_span`。PostHog 仅汇总 `$ai_generation` 事件的 token 和费用，因此不会重复计算。若 `@mastra/core` 或 `@mastra/observability` 版本未记录 `MODEL_INFERENCE` Span，则 `MODEL_GENERATION` 会导出为 `$ai_generation`。

:::note

使用已弃用的 `generateLegacy()` 和 `streamLegacy()` 方法时，不会记录 `MODEL_INFERENCE` Span；其 `MODEL_GENERATION` Span 会导出为 `$ai_span`。这些运行不会向 PostHog 发送 `$ai_generation` 事件，也不会发送 token 或费用数据。请使用 `generate()` 和 `stream()` 保留这些数据。

:::

## 反馈导出 {/* #feedback-export */}

通过 [`addFeedback()`](/docs/observability/feedback) 记录的反馈会作为原生 `$ai_feedback` 事件导出到 PostHog。PostHog 会在关联的 Trace 上将其显示为 **User feedback**，无需额外配置。

```typescript
const trace = await mastra.observability.getRecordedTrace({ traceId })
await trace.addFeedback({
  feedbackType: 'thumbs',
  value: 'down',
  comment: 'Wrong answer',
})
```

反馈事件映射到这些 PostHog 属性：

| Mastra 反馈字段 | PostHog 属性 |
| - | - |
|`traceId` | `$ai_trace_id` |
| `comment`（没有 comment 时使用 `value`） | `$ai_feedback_text` |
| `feedbackId` | `feedback_id` |
| `feedbackType` | `feedback_type` |
| `value` | `feedback_value` |
| `feedbackSource` | `feedback_source` |
| `spanId` | `span_id` |
| `sourceId` | `source_id` |
| `metadata.sessionId` | `$ai_session_id` |
| `metadata`（其他键） | 自定义属性 |

没有 `traceId` 的反馈会被丢弃，因为 PostHog 通过 `$ai_trace_id` 将反馈关联到 Trace。事件的 distinct ID 依次取自 `feedbackUserId`、`metadata.userId`、`defaultDistinctId`，最后回退到 `anonymous`。
