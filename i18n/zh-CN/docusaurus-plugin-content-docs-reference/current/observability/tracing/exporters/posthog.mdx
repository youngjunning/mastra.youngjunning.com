# Posthog出口商

将跟踪数据发送到 PostHog 以进行 AI 观察和分析。

## 构造函数 {/* #constructor */}

```typescript oxfmt:false
new PosthogExporter(config: PosthogExporterConfig)
```

## `PosthogExporterConfig` {/* #posthogexporterconfig */}

```typescript
interface PosthogExporterConfig extends BaseExporterConfig {
  apiKey?: string
  host?: string
  flushAt?: number
  flushInterval?: number
  serverless?: boolean
  defaultDistinctId?: string
  enablePrivacyMode?: boolean
}
```

延伸`BaseExporterConfig`, which includes:

* `logger?: IMastraLogger`- 记录器实例
* `logLevel?: LogLevel | 'debug' | 'info' | 'warn' | 'error'`- 日志级别（默认：INFO）

## 方法 {/* #methods */}

### `exportTracingEvent` {/* #exporttracingevent */}

```typescript oxfmt:false
async exportTracingEvent(event: TracingEvent): Promise<void>
```

将跟踪事件导出到 PostHog。

### `onFeedbackEvent` {/* #onfeedbackevent */}

```typescript oxfmt:false
async onFeedbackEvent(event: FeedbackEvent): Promise<void>
```

将反馈事件导出到 PostHog。看[Feedback export](#feedback-export).

### 冲水 {/* #flush */}

```typescript oxfmt:false
async flush(): Promise<void>
```

强制将任何缓冲事件刷新到 PostHog，而不关闭导出器。在无服务器环境中很有用，您需要确保在运行时终止之前导出跨度。

### 关闭 {/* #shutdown */}

```typescript oxfmt:false
async shutdown(): Promise<void>
```

刷新待处理的批处理事件并关闭 PostHog 客户端。

## 用法 {/* #usage */}

### 零配置（使用环境变量） {/* #zero-config-using-environment-variables */}

```typescript
import { PosthogExporter } from '@mastra/posthog'

// Reads from POSTHOG_API_KEY, POSTHOG_HOST
const exporter = new PosthogExporter()
```

### 显式配置 {/* #explicit-configuration */}

```typescript
import { PosthogExporter } from '@mastra/posthog'

const exporter = new PosthogExporter({
  apiKey: process.env.POSTHOG_API_KEY!,
  host: 'https://us.i.posthog.com',
  serverless: true,
})
```

## 跨度类型映射 {/* #span-type-mapping */}

| Mastra 跨度类型 | PostHog 事件类型 |
| - | - |
|`MODEL_INFERENCE` | `$ai_generation` |
| `MODEL_GENERATION` | `$ai_span` |
| `MODEL_STEP` | `$ai_span` |
| `MODEL_CHUNK` | `$ai_span` |
| `TOOL_CALL` | `$ai_span` |
| `MCP_TOOL_CALL` | `$ai_span` |
| `PROVIDER_TOOL_CALL` | `$ai_span` |
| `PROCESSOR_RUN` | `$ai_span` |
| `AGENT_RUN` | `$ai_span` |
| `WORKFLOW_RUN` | `$ai_span`|
|所有其他Workflow程 |`$ai_span` |
| `GENERIC` | `$ai_span` |

对模型提供者的每次调用都是`MODEL_INFERENCE` span and is exported as one `$ai_generation` event. The event carries the model, token usage, output, and the tool definitions sent on that call as `$ai_tools`. Its `$ai_input` is the conversation that call received: the run's input messages, followed by the output and tool results of each earlier call in the run. A run that calls the model three times sends three `$ai_generation` events.

这`MODEL_GENERATION` span wraps those calls and is exported as `$ai_span`. PostHog only adds up tokens and cost on `$ai_generation` events. Tokens and cost aren't counted twice. With `@mastra/core` or `@mastra/observability` versions that don't record `MODEL_INFERENCE` spans, `MODEL_GENERATION` is exported as `$ai_generation`.

：：：笔记

运行已弃用的`generateLegacy()` and `streamLegacy()` methods don't record `MODEL_INFERENCE` spans. Their `MODEL_GENERATION` span is exported as `$ai_span`. These runs send no `$ai_generation` events and no token or cost data to PostHog. Use `generate()` and `stream()` to keep token and cost data.

:::

## 反馈导出 {/* #feedback-export */}

反馈记录为[`addFeedback()`](/docs/observability/feedback) is exported to PostHog as a native `$ai_feedback` event. PostHog shows it as **User feedback** on the linked trace. No extra configuration is needed.

```typescript
const trace = await mastra.observability.getRecordedTrace({ traceId })
await trace.addFeedback({
  feedbackType: 'thumbs',
  value: 'down',
  comment: 'Wrong answer',
})
```

反馈事件映射到这些 PostHog 属性：

|马斯特拉反馈领域 | PostHog 属性 |
| - | - |
|`traceId` | `$ai_trace_id` |
| `comment` (or `value` when no comment) | `$ai_feedback_text` |
| `feedbackId` | `feedback_id` |
| `feedbackType` | `feedback_type` |
| `value` | `feedback_value` |
| `feedbackSource` | `feedback_source` |
| `spanId` | `span_id` |
| `sourceId` | `source_id` |
| `metadata.sessionId` | `$ai_session_id` |
| `metadata` (other keys) | custom properties |

没有反馈`traceId` is dropped because PostHog anchors feedback to a trace through `$ai_trace_id`. The event's distinct ID resolves from `feedbackUserId`, then `metadata.userId`, then `defaultDistinctId`, then `anonymous`.
