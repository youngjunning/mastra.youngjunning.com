# DefaultExporter

**自 `@mastra/observability@1.12.0` 起弃用**，请改用 [`MastraStorageExporter`](/reference/observability/tracing/exporters/mastra-storage-exporter)。

:::warning[已弃用]

`DefaultExporter` 为向后兼容而保留，将在未来的大版本中移除。新项目请使用 [`MastraStorageExporter`](/reference/observability/tracing/exporters/mastra-storage-exporter)。两个类的构造函数、配置和运行时行为相同。`DefaultExporter` 保留原有 `mastra-default-observability-exporter` 导出器 `name`，因此依赖该名称的监控规则仍可正常工作。

:::

## `DefaultExporterConfig` {/* #defaultexporterconfig */}

```typescript
interface DefaultExporterConfig extends BaseExporterConfig {
  /** Maximum number of spans per batch. Default: 1000 */
  maxBatchSize?: number

  /** Maximum total buffer size before emergency flush. Default: 10000 */
  maxBufferSize?: number

  /** Maximum time to wait before flushing batch in milliseconds. Default: 5000 */
  maxBatchWaitMs?: number

  /** Maximum number of retry attempts. Default: 4 */
  maxRetries?: number

  /** Base retry delay in milliseconds (uses exponential backoff). Default: 500 */
  retryDelayMs?: number

  /** Tracing storage strategy or 'auto' for automatic selection. Default: 'auto' */
  strategy?: TracingStorageStrategy | 'auto'
}
```

继承 `BaseExporterConfig`，其中包括：

- `logger?: IMastraLogger` - 日志记录器实例
- `logLevel?: LogLevel | 'debug' | 'info' | 'warn' | 'error'` - 日志级别（默认值：INFO）

## `TracingStorageStrategy` {/* #tracingstoragestrategy */}

```typescript
type TracingStorageStrategy = 'realtime' | 'batch-with-updates' | 'insert-only'
```

### 策略行为 {/* #strategy-behaviors */}

- **realtime**：立即将每个事件持久化到存储中
- **batch-with-updates**：分别批量处理创建和更新事件，并按顺序应用
- **insert-only**：仅处理 SPAN_ENDED 事件，忽略更新

### flush {/* #flush */}

```typescript oxfmt:false
async flush(): Promise<void>
```

强制将所有缓冲事件写入存储，而不关闭导出器。适用于需要在运行时终止前确保 span 已导出的无服务器环境。

### 关闭 {/* #shutdown */}

```typescript oxfmt:false
async shutdown(): Promise<void>
```

刷新剩余缓冲事件并执行清理。

## 自动策略选择 {/* #automatic-strategy-selection */}

当 `strategy: 'auto'`（默认值）时，导出器会查询存储适配器支持的能力：

```typescript
interface TracingStrategy {
  /** Strategies supported by this adapter */
  supported: TracingStorageStrategy[]

  /** Preferred strategy for optimal performance */
  preferred: TracingStorageStrategy
}
```

导出器会：

1. 优先使用存储适配器的首选策略（如可用）
2. 若首选策略不可用，则回退到第一个受支持的策略
3. 若用户指定的策略不受支持，则记录警告

## 批处理行为 {/* #batching-behavior */}

### 刷新触发条件 {/* #flush-triggers */}

满足以下任一条件时，缓冲区会刷新：

- 缓冲区大小达到 `maxBatchSize`
- 自首个缓冲事件起经过的时间超过 `maxBatchWaitMs`
- 缓冲区大小达到 `maxBufferSize`（紧急刷新）
- 调用 `shutdown()`

### 重试逻辑 {/* #retry-logic */}

刷新失败后会按指数退避重试：

- 重试延迟：`retryDelayMs * 2^attempt`
- 最大尝试次数：`maxRetries`
- 所有重试均失败后丢弃该批次

当存储不支持某种信号或重试耗尽时，`DefaultExporter` 会发出 `ObservabilityDropEvent`，并由注册在导出器和 bridge 上的 `onDroppedEvent` 处理程序接收。该事件包含信号、原因、数量、导出器名称、已知时的存储名称，以及经过清理的错误详情。

### 乱序处理 {/* #out-of-order-handling */}

对于 `batch-with-updates` 策略：

- 跟踪哪些 span 已创建
- 拒绝对尚未创建的 span 执行更新或结束操作
- 对乱序事件记录警告
- 维护序列号，确保更新按顺序执行

## 用法 {/* #usage */}

```typescript
import { DefaultExporter } from '@mastra/observability'

// Default configuration
const exporter = new DefaultExporter()

// Custom batching configuration
const customExporter = new DefaultExporter({
  maxBatchSize: 500,
  maxBatchWaitMs: 2000,
  strategy: 'batch-with-updates',
  logLevel: 'debug',
})
```
