# 云导出器

**添加于：** `@mastra/observability@1.8.0`. **已弃用于`1.12.0`**&#x8D5E;成[`MastraPlatformExporter`](/reference/observability/tracing/exporters/mastra-platform-exporter).

:::警告\[已弃用]

`CloudExporter`仍然可用于向后兼容，但将在未来的主要版本中删除，因此使用[`MastraPlatformExporter`](/reference/observability/tracing/exporters/mastra-platform-exporter) for new projects. The classes have identical constructors and share environment variables and runtime behavior. To preserve existing monitoring rules, `CloudExporter` retains its original `mastra-cloud-observability-exporter` exporter `name` and `CLOUD_EXPORTER_*`错误 ID。

:::

将跟踪范围、日志、指标、分数和反馈发送到 Mastra 平台以进行在线可视化和监控。

## `CloudExporterConfig` {/* #cloudexporterconfig */}

```typescript
interface CloudExporterConfig extends BaseExporterConfig {
  /** Maximum number of spans per batch. Default: 1000 */
  maxBatchSize?: number

  /** Maximum wait time before flushing in milliseconds. Default: 5000 */
  maxBatchWaitMs?: number

  /** Maximum retry attempts. Default: 3 */
  maxRetries?: number

  /** Cloud access token (from env or config) */
  accessToken?: string

  /** Project ID for project-scoped collector routes (letters, numbers, hyphens, underscores) */
  projectId?: string

  /** Base cloud observability endpoint */
  endpoint?: string

  /** Explicit cloud traces endpoint override */
  tracesEndpoint?: string

  /** Explicit cloud logs endpoint override */
  logsEndpoint?: string

  /** Explicit cloud metrics endpoint override */
  metricsEndpoint?: string

  /** Explicit cloud scores endpoint override */
  scoresEndpoint?: string

  /** Explicit cloud feedback endpoint override */
  feedbackEndpoint?: string
}
```

延伸`BaseExporterConfig`, which includes:

* `logger?: IMastraLogger`- 记录器实例
* `logLevel?: LogLevel | 'debug' | 'info' | 'warn' | 'error'`- 日志级别（默认：INFO）

## 环境变量 {/* #environment-variables */}

如果配置中未提供，导出器将读取这些环境变量：

* `MASTRA_CLOUD_ACCESS_TOKEN`- 身份验证令牌`CloudExporter` requests
* `MASTRA_PROJECT_ID`- 派生项目范围的收集器路由时使用的项目 ID，例如`/projects/:projectId/ai/spans/publish`
* `MASTRA_CLOUD_TRACES_ENDPOINT`- 跟踪端点覆盖。传递基本来源或以以下结尾的完整跟踪发布 URL`/spans/publish`. The other signal endpoints are derived from it. Defaults to `https://observability.mastra.ai`

`CloudExporter`不读书`MASTRA_PLATFORM_OBSERVABILITY_ENDPOINT`. Use [`MastraPlatformExporter`](/reference/observability/tracing/exporters/mastra-platform-exporter) for that variable.

## 方法 {/* #methods */}

### `exportTracingEvent` {/* #exporttracingevent */}

```typescript oxfmt:false
async exportTracingEvent(event: TracingEvent): Promise<void>
```

处理云导出的跟踪事件。

仅有的`SPAN_ENDED` tracing events are exported. `SPAN_STARTED` and `SPAN_UPDATED` are ignored. Matching spans are buffered and uploaded to the Cloud traces endpoint on the next flush.

### `onLogEvent` {/* #onlogevent */}

```typescript oxfmt:false
async onLogEvent(event: LogEvent): Promise<void>
```

处理云导出的日志信号。

每一个`LogEvent` passed to this handler is buffered and exported to the Cloud logs endpoint derived from the configured base endpoint. Unlike tracing, there is no additional event-status filtering at the `CloudExporter` level. If the exporter is disabled, this method becomes a no-op.

### 冲水 {/* #flush */}

```typescript oxfmt:false

```

强制将所有缓冲事件刷新到 Mastra 平台，而无需关闭导出器。在无服务器环境中很有用，您需要确保在运行时终止之前导出跨度。

## 行为 {/* #behavior */}

### 验证 {/* #authentication */}

如果没有通过配置或环境变量提供访问令牌，则导出器：

* 记录带有注册信息的警告
* 作为无操作操作（丢弃所有事件）

### 配料 {/* #batching */}

导出器批量跟踪跨度、日志、指标、分数和反馈，以实现高效的网络使用：

* 当缓冲事件总数达到时刷新`maxBatchSize`
* 冲洗时`maxBatchWaitMs` elapsed since the first buffered signal in the batch
* 冲水`shutdown()`

### 错误处理 {/* #error-handling */}

* 使用指数退避重试`maxRetries` attempts
* 所有重试失败后删除批次
* 记录错误但继续处理新事件

### 端点路由 {/* #endpoint-routing */}

* 基本起源自动导出信号端点
* 没有`projectId`, derived routes use `/ai/{signal}/publish`
* 和`projectId` or `MASTRA_PROJECT_ID`, derived routes use `/projects/:projectId/ai/{signal}/publish`
* 即使在以下情况下，也会按原样使用显式完整发布 URL：`projectId` is configured

### 信号处理 {/* #signal-processing */}

* `exportTracingEvent()`只出口`SPAN_ENDED` tracing events
* `onLogEvent()`, `onMetricEvent()`, `onScoreEvent()`, and `onFeedbackEvent()` buffer every event they receive for that signal type
* 所有支持的信号批次都会在期间上传到其匹配的云发布端点`flush()` and `shutdown()`

## 用法 {/* #usage */}

```typescript
import { CloudExporter } from '@mastra/observability'

// Uses environment variable for token
const exporter = new CloudExporter()

// Explicit configuration
const customExporter = new CloudExporter({
  accessToken: 'your-token',
  projectId: 'project_123',
  maxBatchSize: 500,
  maxBatchWaitMs: 2000,
  logLevel: 'debug',
})
```
