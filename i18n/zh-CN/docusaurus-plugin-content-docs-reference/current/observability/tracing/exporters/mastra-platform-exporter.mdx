# MastraPlatformExporter

**引入版本：** `@mastra/observability@1.12.0`。早期版本（`@mastra/observability@1.8.0` 至 `1.11.x`）将同一 exporter 导出为现已弃用的 `CloudExporter`。

将追踪 Span、日志、指标、评分和反馈发送到 Mastra 平台，以便在线查看和监控。

:::note

`MastraPlatformExporter` 原名 `CloudExporter`。原有的 `CloudExporter` 类仍从 `@mastra/observability` 导出，因此现有导入仍可使用；不过该类已弃用，将在未来的主版本中移除。新代码应使用 `MastraPlatformExporter`。

:::

## Span 预览 {/* #span-previews */}

`MastraPlatformExporter` 会根据 Span 类型自动生成简短易读的 `inputPreview`、`outputPreview` 和 `errorPreview` 摘要。每项预览最多包含 100 个字符；截断时会加上省略号。完整载荷仍可单独获取。

## `MastraPlatformExporterConfig` {/* #mastraplatformexporterconfig */}

```typescript
interface MastraPlatformExporterConfig extends BaseExporterConfig {
  /** Maximum number of buffered events per batch (spans, logs, metrics, scores, feedback). Default: 1000 */
  maxBatchSize?: number

  /** Maximum wait time before flushing in milliseconds. Default: 5000 */
  maxBatchWaitMs?: number

  /** Opt into byte-triggered batches and upload concurrency control */
  byteBatching?: {
    maxBatchBytes?: number // Default: 8 MiB
    maxConcurrentUploads?: number // Default: 2
    uploadTimeoutMs?: number // Default: 30000
  }

  /** Maximum retry attempts for collector batches. Default: 3 */
  maxRetries?: number

  /** Mastra Observability access token (from env or config) */
  accessToken?: string

  /** Project ID for project-scoped collector routes (letters, numbers, hyphens, underscores) */
  projectId?: string

  /** Base observability endpoint */
  endpoint?: string

  /** Explicit traces endpoint override */
  tracesEndpoint?: string

  /** Explicit logs endpoint override */
  logsEndpoint?: string

  /** Explicit metrics endpoint override */
  metricsEndpoint?: string

  /** Explicit scores endpoint override */
  scoresEndpoint?: string

  /** Explicit feedback endpoint override */
  feedbackEndpoint?: string

  /**
   * When false, `accessToken`, `projectId` and the traces endpoint are taken
   * from config only and the environment variables below are ignored. Use this
   * when embedding Mastra in another tool so a user project's `.env` cannot
   * redirect the host's own telemetry. Default: true
   */
  resolveFromEnv?: boolean
}
```

继承 `BaseExporterConfig`，其中包括：

- `logger?: IMastraLogger` - Logger 实例
- `logLevel?: LogLevel | 'debug' | 'info' | 'warn' | 'error'` - 日志级别（默认：INFO）

## 环境变量 {/* #environment-variables */}

如果配置中未提供相应值，exporter 会读取以下环境变量：

- `MASTRA_PLATFORM_ACCESS_TOKEN` - `MastraPlatformExporter` 请求的身份验证令牌
- `MASTRA_PROJECT_ID` - 派生 `/projects/:projectId/ai/spans/publish` 等项目专属 collector 路由时使用的项目 ID
- `MASTRA_PLATFORM_OBSERVABILITY_ENDPOINT` - 覆盖可观测性端点。`@mastra/observability@1.17.4` 及以上版本的 exporter 会读取该变量。可传入 `https://observability.eu.mastra.ai` 这样的基础来源，或以 `/spans/publish` 结尾的完整追踪发布 URL。其他信号端点由此派生。默认值为 `https://observability.mastra.ai`
- `MASTRA_CLOUD_TRACES_ENDPOINT` - 旧版追踪端点覆盖项。两者均已设置时，优先于 `MASTRA_PLATFORM_OBSERVABILITY_ENDPOINT`

当 `resolveFromEnv` 为 `false` 时，上述环境变量均会被忽略。

### `exportTracingEvent` {/* #exporttracingevent */}

### flush {/* #flush */}

```typescript oxfmt:false

```

强制将缓冲区中的事件发送到 Mastra 平台，而不关闭 exporter。适用于无服务器环境，可确保 Span 在运行时终止前导出。

## 行为 {/* #behavior */}

### 身份验证 {/* #authentication */}

如果配置和环境变量均未提供访问令牌，exporter 将：

- 记录包含注册信息的警告
- 不执行实际操作（丢弃所有事件）

### 批处理 {/* #batching */}

exporter 会对追踪、日志、指标，以及已包含追踪详情的反馈和评分进行批处理：

- 缓冲事件总数达到 `maxBatchSize` 时发送批次
- 批次中第一条信号进入缓冲区后经过 `maxBatchWaitMs` 时发送批次
- 调用 `shutdown()` 时发送批次

### 反馈与评分投递 {/* #feedback-and-score-delivery */}

exporter 收到的反馈和评分可以通过 Trace ID 和可选的 Span ID 引用存储在 Platform 中的追踪。如果记录需要该追踪的详情，exporter 会立即发送记录，不等待批次。

短生命周期进程结束前调用 `flush()`，或在停止 exporter 时调用 `shutdown()`，以等待待处理的投递和重试。记录被接受或在失败后被丢弃时，这些方法才会完成。已接受的反馈和评分可能需要一段时间才会显示在 Platform 中。

### 按字节批处理 {/* #byte-batching */}

设置 `byteBatching`，即可根据序列化后的字节数发送批次，并控制并发上传数：

```typescript
import { MastraPlatformExporter } from '@mastra/observability'

const exporter = new MastraPlatformExporter({
  byteBatching: {
    maxBatchBytes: 8 * 1024 * 1024,
    maxConcurrentUploads: 2,
    uploadTimeoutMs: 30_000,
  },
})
```

未设置 `byteBatching` 时，exporter 保持原有的按记录数批处理行为。

- 默认情况下，批次达到 8 MiB 时，`maxBatchBytes` 会触发上传。更大的单条记录仍会完整发送，不会被截断或因大小而丢弃。
- `maxConcurrentUploads` 控制并发上传到 collector 的批次数，默认值为 2。
- `uploadTimeoutMs` 设置包括重试在内的上传时限，默认值为 30 秒。

按记录数和计时器触发发送的规则仍然有效。如果上传速度跟不上，排队记录会保留，因此队列占用的内存可能增长。

使用 `exporter.getByteBatchingStats()` 查看当前队列。

### 错误处理 {/* #error-handling */}

- 对 collector 批次采用指数退避重试，最多尝试 `maxRetries` 次
- 所有重试均失败后丢弃批次
- 记录错误，但继续处理新事件

`MastraPlatformExporter` 抛出的错误使用 `MASTRA_PLATFORM_EXPORTER_*` 作为 `id` 前缀。已弃用的 `CloudExporter` 仍发出以 `CLOUD_EXPORTER_*` 为前缀的错误 `id`。

### 配额暂停 {/* #quota-pause */}

当组织的可观测性配额用尽时，Mastra 平台会以 `402 Payment Required` 和 `x-mastra-observability: disabled` 响应头拒绝发布请求。exporter 在任意发布路由上收到 `402`（或该响应头）时，会：

- 丢弃被拒绝的批次，不再重试
- 暂停追踪、日志、指标、评分和反馈的 collector 批次，并丢弃缓冲区中及新进入的批次记录
- 记录遥测已暂停的警告
- 定期以空批次探测平台。间隔由 `x-mastra-observability-retry-after` 响应头指定（单位为秒）；如果没有该响应头，则每 5 分钟探测一次
- 平台不再返回 `402` 后，自动恢复导出并记录警告

探测计时器不会阻止 Node.js 进程退出，因此短生命周期和无服务器进程在暂停期间仍会正常退出。

每个 collector 请求（包括批次上传和追踪恢复探测）都包含 `x-mastra-observability-capabilities: quota-pause-v1` 请求头。它告知平台客户端支持配额暂停协议，因此平台可以安全地返回 `402`，而不必像处理会重试的旧客户端那样静默丢弃遥测数据。

### 端点路由 {/* #endpoint-routing */}

- 基础来源会自动派生信号端点
- 未设置 `projectId` 时，派生路由使用 `/ai/{signal}/publish`
- 设置 `projectId` 或 `MASTRA_PROJECT_ID` 后，派生路由使用 `/projects/:projectId/ai/{signal}/publish`
- 即使设置了 `projectId`，显式指定的完整发布 URL 也会原样使用

### 事件处理 {/* #event-processing */}

- `exportTracingEvent()` 只导出 `SPAN_ENDED` 追踪事件
- `onLogEvent()` 和 `onMetricEvent()` 会缓冲事件
- `onScoreEvent()` 和 `onFeedbackEvent()` 按[反馈与评分投递](#feedback-and-score-delivery)所述方式投递记录
- 在 `flush()` 和 `shutdown()` 期间，所有受支持的信号批次都会上传到各自对应的发布端点

## Span 传输格式 {/* #span-wire-format */}

这里记录发送到 Mastra 平台的 Span 结构，仅供参考：它并未从 `@mastra/observability` 导出，不应尝试导入。exporter 会展开原始 `AnyExportedSpan`（保留源字段名），再添加少量方便平台使用的别名字段：

```typescript
type MastraPlatformSpanRecord = AnyExportedSpan & {
  // Aliases derived from the source span
  spanId: string // alias for span.id
  spanType: string // alias for span.type
  startedAt: Date // alias for span.startTime
  endedAt: Date | null // alias for span.endTime ?? null
  error: AnyExportedSpan['errorInfo'] | null

  // Stamped at export time
  createdAt: Date
  updatedAt: Date | null
}
```

展开后的 `AnyExportedSpan` 还包含原有的 `id`、`type`、`name`、`traceId`、`parentSpanId`、`isRootSpan`、`isEvent`、`startTime`、`endTime`、`entityType`、`entityId`、`entityName`、`tags`、`attributes`、`metadata`、`input`、`output` 和 `errorInfo`。有关 `AnyExportedSpan`，请参阅[接口](/reference/observability/tracing/interfaces)。

## 用法 {/* #usage */}

```typescript
import { MastraPlatformExporter } from '@mastra/observability'

// Uses environment variable for token
const exporter = new MastraPlatformExporter()

// Explicit configuration
const customExporter = new MastraPlatformExporter({
  accessToken: 'your-token',
  projectId: 'project_123',
  maxBatchSize: 500,
  maxBatchWaitMs: 2000,
  logLevel: 'debug',
})
```

## 从 `CloudExporter` 迁移 {/* #migrating-from-cloudexporter */}

两个类的构造函数签名、环境变量和行为均相同。迁移时替换导入和构造函数：

```typescript
// Before
import { CloudExporter } from '@mastra/observability'
const exporter = new CloudExporter()

// After
import { MastraPlatformExporter } from '@mastra/observability'
const exporter = new MastraPlatformExporter()
```

原有的 `CloudExporter` 保持不变，因此匹配旧版 `CLOUD_EXPORTER_*` 错误 ID 或 exporter 名称 `mastra-cloud-observability-exporter` 的仪表板和告警规则，在迁移前仍可正常工作。
