# Mastra平台出口商

**添加于：** `@mastra/observability@1.12.0`。早期版本（`@mastra/observability@1.8.0`通过`1.11.x`) 导出与已弃用的相同的导出器`CloudExporter`.

将跟踪范围、日志、指标、分数和反馈发送到 Mastra 平台以进行在线可视化和监控。

：：：笔记

`MastraPlatformExporter`以前被称为`CloudExporter`. The original `CloudExporter` class is still exported from `@mastra/observability` so existing imports keep working, but it's deprecated and will be removed in a future major version. New code should use `MastraPlatformExporter`.

:::

## 跨度预览 {/* #span-previews */}

`MastraPlatformExporter`自动生成简短易读的`inputPreview`, `outputPreview`, and `errorPreview` summaries based on the span type. Each preview contains up to 100 characters plus an ellipsis when truncated. Full payloads remain available separately.

## `MastraPlatformExporterConfig` {/* #mastraplatformexporterconfig */}

```typescript
interface MastraPlatformExporterConfig extends BaseExporterConfig {
  /** Maximum number of buffered events per batch (spans, logs, metrics, scores, feedback). Default: 1000 */
  maxBatchSize?: number

  /** Maximum wait time before flushing in milliseconds. Default: 5000 */
  maxBatchWaitMs?: number

  /** Opt into byte-triggered batches and upload concurrency control */
  byteBatching?: {
    maxBatchBytes?: number // Default: 8 MiB
    maxConcurrentUploads?: number // Default: 2
    uploadTimeoutMs?: number // Default: 30000
  }

  /** Maximum retry attempts for collector batches. Default: 3 */
  maxRetries?: number

  /** Mastra Observability access token (from env or config) */
  accessToken?: string

  /** Project ID for project-scoped collector routes (letters, numbers, hyphens, underscores) */
  projectId?: string

  /** Base observability endpoint */
  endpoint?: string

  /** Explicit traces endpoint override */
  tracesEndpoint?: string

  /** Explicit logs endpoint override */
  logsEndpoint?: string

  /** Explicit metrics endpoint override */
  metricsEndpoint?: string

  /** Explicit scores endpoint override */
  scoresEndpoint?: string

  /** Explicit feedback endpoint override */
  feedbackEndpoint?: string

  /**
   * When false, `accessToken`, `projectId` and the traces endpoint are taken
   * from config only and the environment variables below are ignored. Use this
   * when embedding Mastra in another tool so a user project's `.env` cannot
   * redirect the host's own telemetry. Default: true
   */
  resolveFromEnv?: boolean
}
```

延伸`BaseExporterConfig`, which includes:

* `logger?: IMastraLogger`- 记录器实例
* `logLevel?: LogLevel | 'debug' | 'info' | 'warn' | 'error'`- 日志级别（默认：INFO）

## 环境变量 {/* #environment-variables */}

如果配置中未提供，导出器将读取这些环境变量：

* `MASTRA_PLATFORM_ACCESS_TOKEN`- 身份验证令牌`MastraPlatformExporter` requests
* `MASTRA_PROJECT_ID`- 派生项目范围的收集器路由时使用的项目 ID，例如`/projects/:projectId/ai/spans/publish`
* `MASTRA_PLATFORM_OBSERVABILITY_ENDPOINT`- 可观察性端点覆盖，由导出器读取`@mastra/observability@1.17.4` and later. Pass either a base origin such as `https://observability.eu.mastra.ai` or a full traces publish URL ending in `/spans/publish`. The other signal endpoints are derived from it. Defaults to `https://observability.mastra.ai`
* `MASTRA_CLOUD_TRACES_ENDPOINT`- 旧跟踪端点覆盖。优先于`MASTRA_PLATFORM_OBSERVABILITY_ENDPOINT` when both are set

当`resolveFromEnv` is `false`.

## 行为 {/* #behavior */}

### 验证 {/* #authentication */}

如果没有通过配置或环境变量提供访问令牌，则导出器：

* 记录带有注册信息的警告
* 作为无操作操作（丢弃所有事件）

### 配料 {/* #batching */}

导出器批量跟踪、日志和指标，以及已包含其跟踪详细信息的反馈和分数：

* 当缓冲事件总数达到时刷新`maxBatchSize`
* 冲洗时`maxBatchWaitMs` elapsed since the first buffered signal in the batch
* 冲水`shutdown()`

### 反馈和分数交付 {/* #feedback-and-score-delivery */}

导出器收到的反馈和分数可以使用其跟踪 ID 和可选的跨度 ID 引用平台中存储的跟踪。如果记录需要来自该跟踪的详细信息，导出器会立即发送它，而不是等待批次。

称呼`flush()` before ending a short-lived process, or `shutdown()` when stopping the exporter, to wait for pending deliveries and retries. These methods finish when records have been accepted or dropped after a failure. Accepted feedback and scores may take time to appear in Platform.

### 字节批处理 {/* #byte-batching */}

放`byteBatching` to flush by serialized byte size and control concurrent uploads:

```typescript
import { MastraPlatformExporter } from '@mastra/observability'

const exporter = new MastraPlatformExporter({
  byteBatching: {
    maxBatchBytes: 8 * 1024 * 1024,
    maxConcurrentUploads: 2,
    uploadTimeoutMs: 30_000,
  },
})
```

没有`byteBatching`, the exporter keeps its existing count-based batching behavior.

* `maxBatchBytes` 默认情况下，当批次达到 8 MiB 时触发上传。较大的记录会完整发送，不会被截断或基于大小的丢弃。
* `maxConcurrentUploads`控制并发收集器批量上传。默认为两个。
* `uploadTimeoutMs`设置上传截止日期，包括重试。默认值为 30 秒。

记录计数和基于计时器的刷新触发器仍然适用。当上传落后时，排队的记录将被保留，因此队列内存可能会增长。

检查当前队列`exporter.getByteBatchingStats()`.

### 错误处理 {/* #error-handling */}

* 对收集器批次使用指数退避重试`maxRetries` attempts
* 所有重试失败后删除批次
* 记录错误但继续处理新事件

引发的错误`MastraPlatformExporter` use the `MASTRA_PLATFORM_EXPORTER_*` `id` prefix. The deprecated `CloudExporter` continues to emit `CLOUD_EXPORTER_*` `id`s.

### 配额暂停 {/* #quota-pause */}

当组织用尽其可观察性配额时，Mastra 平台会拒绝发布请求`402 Payment Required` plus the `x-mastra-observability: disabled` header. When the exporter sees a `402` (or the header) on any publish route, it:

* 删除被拒绝的批次而不重试
* 暂停收集器批次以获取跟踪、日志、指标、分数和反馈，删除缓冲的和传入的批次记录
* 记录遥测已暂停的警告
* 使用空批次定期探测平台，使用来自`x-mastra-observability-retry-after` header (seconds), or every 5 minutes if the header is absent
* 一旦平台停止拒绝，自动恢复导出并记录警告`402`

探测计时器不会使 Node.js 进程保持活动状态，因此短暂的无服务器进程在暂停时会正常退出。

每个收集器请求（批量上传和跟踪恢复探测）都包括`x-mastra-observability-capabilities: quota-pause-v1` header. This tells the platform that the client understands the quota-pause contract, so it can safely respond with `402` instead of silently dropping telemetry for older clients that would retry it.

### 端点路由 {/* #endpoint-routing */}

* 基本起源自动导出信号端点
* 没有`projectId`, derived routes use `/ai/{signal}/publish`
* 和`projectId` or `MASTRA_PROJECT_ID`, derived routes use `/projects/:projectId/ai/{signal}/publish`
* 即使在以下情况下，也会按原样使用显式完整发布 URL：`projectId` is configured

### 事件处理 {/* #event-processing */}

* `exportTracingEvent()`只出口`SPAN_ENDED` tracing events
* `onLogEvent()`和`onMetricEvent()` buffer events
* `onScoreEvent()`和`onFeedbackEvent()` deliver records as described in [Feedback and score delivery](#feedback-and-score-delivery)
* 所有支持的信号批次都会在期间上传到其匹配的发布端点`flush()` and `shutdown()`

## 跨线格式 {/* #span-wire-format */}

发送到 Mastra 平台的每个跨度的形状记录在此处仅供参考：它不是从`@mastra/observability` and shouldn't be imported. The exporter spreads the original `AnyExportedSpan` (so the source field names are preserved) and layers a small set of platform-friendly aliases on top:

```typescript
type MastraPlatformSpanRecord = AnyExportedSpan & {
  // Aliases derived from the source span
  spanId: string // alias for span.id
  spanType: string // alias for span.type
  startedAt: Date // alias for span.startTime
  endedAt: Date | null // alias for span.endTime ?? null
  error: AnyExportedSpan['errorInfo'] | null

  // Stamped at export time
  createdAt: Date
  updatedAt: Date | null
}
```

传播`AnyExportedSpan` also carries the original `id`, `type`, `name`, `traceId`, `parentSpanId`, `isRootSpan`, `isEvent`, `startTime`, `endTime`, `entityType`, `entityId`, `entityName`, `tags`, `attributes`, `metadata`, `input`, `output`, and `errorInfo`. See [Interfaces](/reference/observability/tracing/interfaces) for `AnyExportedSpan`.

## 用法 {/* #usage */}

```typescript
import { MastraPlatformExporter } from '@mastra/observability'

// Uses environment variable for token
const exporter = new MastraPlatformExporter()

// Explicit configuration
const customExporter = new MastraPlatformExporter({
  accessToken: 'your-token',
  projectId: 'project_123',
  maxBatchSize: 500,
  maxBatchWaitMs: 2000,
  logLevel: 'debug',
})
```

## 迁移自`CloudExporter` {/* #migrating-from-cloudexporter */}

这两个类共享相同的构造函数签名、环境变量和行为。要迁移，请替换导入和构造函数：

```typescript
// Before
import { CloudExporter } from '@mastra/observability'
const exporter = new CloudExporter()

// After
import { MastraPlatformExporter } from '@mastra/observability'
const exporter = new MastraPlatformExporter()
```

原来的`CloudExporter` is preserved unchanged so dashboards or alert rules that match the previous `CLOUD_EXPORTER_*` error IDs or `mastra-cloud-observability-exporter` exporter name keep working until you migrate.
