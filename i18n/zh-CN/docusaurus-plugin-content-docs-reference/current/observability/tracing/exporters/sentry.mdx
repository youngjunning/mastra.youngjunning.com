# SentryExporter

使用 OpenTelemetry 语义约定，将追踪数据发送到 Sentry，用于 AI 追踪与监控。

## 构造函数 {/* #constructor */}

```typescript oxfmt:false
new SentryExporter(config: SentryExporterConfig)
```

## `SentryExporterConfig` {/* #sentryexporterconfig */}

```typescript
interface SentryExporterConfig extends BaseExporterConfig {
  dsn?: string
  environment?: string
  tracesSampleRate?: number
  release?: string
  options?: Partial<Sentry.NodeOptions>
}
```

扩展自 `BaseExporterConfig`，其中还包括：

- `logger?: IMastraLogger` - Logger 实例
- `logLevel?: LogLevel | 'debug' | 'info' | 'warn' | 'error'` - 日志级别（默认：INFO）

## 方法 {/* #methods */}

### `exportTracingEvent` {/* #exporttracingevent */}

```typescript oxfmt:false
async exportTracingEvent(event: TracingEvent): Promise<void>
```

将追踪事件导出到 Sentry。处理 SPAN_STARTED、SPAN_UPDATED 和 SPAN_ENDED 事件。

### 刷新 {/* #flush */}

```typescript oxfmt:false
async flush(): Promise<void>
```

强制将所有待处理的 Span 发送到 Sentry，不关闭导出器。最多等待 2 秒以发送数据。适用于需要在运行时结束前确保 Span 已导出的无服务器环境。

### 关闭 {/* #shutdown */}

```typescript oxfmt:false
async shutdown(): Promise<void>
```

关闭 Sentry 连接前结束所有活动 Span 并清除内部状态。最多等待 2 秒以发送待处理的数据。

## 用法 {/* #usage */}

### 零配置（使用环境变量） {/* #zero-config-using-environment-variables */}

```typescript
import { SentryExporter } from '@mastra/sentry'

// Reads from SENTRY_DSN, SENTRY_ENVIRONMENT, SENTRY_RELEASE
const exporter = new SentryExporter()
```

### 显式配置 {/* #explicit-configuration */}

```typescript
import { SentryExporter } from '@mastra/sentry'

const exporter = new SentryExporter({
  dsn: process.env.SENTRY_DSN,
  environment: 'production',
  tracesSampleRate: 1.0,
  release: '1.0.0',
})
```

### 配置采样 {/* #with-sampling */}

```typescript
const exporter = new SentryExporter({
  dsn: process.env.SENTRY_DSN,
  environment: 'production',
  tracesSampleRate: 0.1, // Send 10% of transactions to Sentry (recommended for high-load backends)
})
```

### 使用自定义 Sentry 选项 {/* #with-custom-sentry-options */}

```typescript
const exporter = new SentryExporter({
  dsn: process.env.SENTRY_DSN,
  environment: 'production',
  options: {
    integrations: [
      // Custom Sentry integrations
    ],
    beforeSend: event => {
      // Custom event processing
      return event
    },
  },
})
```

## Span 映射 {/* #span-mapping */}

Mastra Span 类型与 Sentry 操作的映射如下：

| Mastra SpanType | Sentry 操作 |
| - | - |
|`AGENT_RUN` | `gen_ai.invoke_agent` |
| `MODEL_GENERATION` | `gen_ai.chat` |
| `MODEL_STEP` | _(跳过)_ |
| `MODEL_CHUNK` | _(跳过)_ |
| `TOOL_CALL` | `gen_ai.execute_tool` |
| `MCP_TOOL_CALL` | `gen_ai.execute_tool` |
| `PROVIDER_TOOL_CALL` | `gen_ai.execute_tool` |
| `WORKFLOW_RUN` | `workflow.run` |
| `WORKFLOW_STEP` | `workflow.step` |
| `WORKFLOW_CONDITIONAL` | `workflow.conditional` |
| `WORKFLOW_CONDITIONAL_EVAL` | `workflow.conditional` |
| `WORKFLOW_PARALLEL` | `workflow.parallel` |
| `WORKFLOW_LOOP` | `workflow.loop` |
| `WORKFLOW_SLEEP` | `workflow.sleep` |
| `WORKFLOW_WAIT_EVENT` | `workflow.wait` |
| `PROCESSOR_RUN` | `ai.processor` |
| `GENERIC` | `ai.span` |

跳过 MODEL_STEP 和 MODEL_CHUNK Span 以简化追踪层级，其数据会汇总到 MODEL_GENERATION Span。

## 环境变量 {/* #environment-variables */}

导出器从以下环境变量读取配置：

| 变量 | 说明 |
| - | - |
| `SENTRY_DSN` | Data Source Name，指定 SDK 发送事件的目标位置 |
| `SENTRY_ENVIRONMENT` | 部署环境名称 |
| `SENTRY_RELEASE` | 已部署代码的版本 |

## `OpenTelemetry` 属性 {/* #opentelemetry-attributes */}

导出器设置以下标准 OpenTelemetry 属性：

**通用属性（所有 Span）：**

- `sentry.origin`：`auto.ai.mastra`（用于标识来自 Mastra 的 Span）
- `ai.span.type`：Mastra Span 类型
- `gen_ai.conversation.id`：聊天会话标识符，取自 `metadata.threadId`，用于在 Sentry 的 Conversations 视图中聚合 Span

**MODEL_GENERATION Span：**

* `gen_ai.operation.name`: `chat`
- `gen_ai.system`：模型提供方
- `gen_ai.request.model`：模型标识符
- `gen_ai.request.messages`：输入消息／提示词（JSON）
- `gen_ai.response.model`：响应模型
- `gen_ai.response.text`：输出文本
- `gen_ai.response.tool_calls`：生成过程中进行的 Tool 调用（JSON 数组）
- `gen_ai.usage.input_tokens`：输入 token 数
- `gen_ai.usage.output_tokens`：输出 token 数
- `gen_ai.usage.total_tokens`：token 总数
- `gen_ai.request.stream`：是否使用流式传输
- `gen_ai.request.temperature`：温度参数
- `gen_ai.completion_start_time`：首个 token 的生成时间

**TOOL_CALL Span：**

* `gen_ai.operation.name`: `execute_tool`
- `gen_ai.tool.name`：Tool 标识符
* `gen_ai.tool.type`: `function`
- `gen_ai.tool.call.id`：Tool 调用 ID
- `gen_ai.tool.input`：Tool 输入
- `gen_ai.tool.output`：Tool 输出
- `tool.success`：是否成功

**AGENT_RUN Span：**

* `gen_ai.operation.name`: `invoke_agent`
- `gen_ai.agent.name`：Agent 标识符
- `gen_ai.pipeline.name`：Agent 名称
- `gen_ai.agent.instructions`：Agent 指令
- `gen_ai.response.model`：子级生成使用的模型
- `gen_ai.response.text`：子级生成的输出
- `gen_ai.usage.*`：子级生成的 token 用量
