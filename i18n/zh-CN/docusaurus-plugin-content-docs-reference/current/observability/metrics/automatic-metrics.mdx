# 自动指标参考

Mastra 会自动从有追踪记录的执行过程中提取性能和用量指标。本页完整列出 Mastra 发出的指标名称、标签和上下文字段。

配置方法请参阅[指标概述](/docs/observability/metrics/overview)。

## Mastra 何时发出自动指标 {/* #when-mastra-emits-automatic-metrics */}

Span 结束时，Mastra 会从中提取指标。可观测性层检查每个已完成的 Span，计算持续时间，并从模型生成及分类器评估 Span 中读取 token 用量数据。无需手动埋点。

### 哪些因素决定指标能否使用 {/* #what-affects-whether-a-metric-is-available */}

满足以下条件时，指标会写入存储：

1. 已将 `MastraStorageExporter` 配置为导出器。
2. 存储后端支持指标（ClickHouse、DuckDB，或启用了可观测性域的 Postgres v-next）。

如果指标不可用，请参阅[故障排查](#troubleshooting)。

## 持续时间指标 {/* #duration-metrics */}

持续时间指标根据 Span 的开始和结束时间戳计算执行时间，单位为毫秒。每项持续时间指标都带有 `status` 标签，其值根据 Span 状态设为 `ok` 或 `error`。

|指标名称 |Span 类型|说明 |
| - | - | - |
|`mastra_agent_duration_ms` | `AGENT_RUN` | Agent 运行的执行时间 |
| `mastra_tool_duration_ms` | `TOOL_CALL`, `MCP_TOOL_CALL`, `PROVIDER_TOOL_CALL` | Tool 调用的执行时间，包括 MCP Tool 调用及由 Provider 执行的 Tool 调用 |
| `mastra_workflow_duration_ms` | `WORKFLOW_RUN`|Workflow 运行的执行时间 |
|`mastra_model_duration_ms` | `MODEL_GENERATION`|模型生成的执行时间 |
|`mastra_processor_duration_ms` | `PROCESSOR_RUN`|处理器运行的执行时间 |

## Token 用量指标 {/* #token-usage-metrics */}

Mastra 只会从包含 `usage` 数据的 `MODEL_GENERATION` 和 `CLASSIFIER_EVALUATION` Span 发出 token 指标。这些指标依赖 Provider 提供用量数据。

### 输入 token 指标 {/* #input-token-metrics */}

|指标名称 |说明 |
| - | - |
|`mastra_model_total_input_tokens` | 输入 token 总数 |
| `mastra_model_input_text_tokens` | 输入提示词中的文本 token 数 |
| `mastra_model_input_cache_read_tokens` | 从提示词缓存读取的 token 数（如 Anthropic） |
| `mastra_model_input_cache_write_tokens` | 写入提示词缓存的 token 数 |
| `mastra_model_input_cache_write_5m_tokens` | 写入提示词缓存、有效期为 5 分钟的 token 数（如 Anthropic） |
| `mastra_model_input_cache_write_1h_tokens` | 写入提示词缓存、有效期为 1 小时的 token 数（如 Anthropic） |
| `mastra_model_input_audio_tokens` | 输入中的音频 token 数（多模态模型） |
| `mastra_model_input_image_tokens` | 输入中的图像 token 数（视觉模型） |

### 输出 token 指标 {/* #output-token-metrics */}

|指标名称 |说明 |
| - | - |
|`mastra_model_total_output_tokens` | 输出 token 总数 |
| `mastra_model_output_text_tokens` | 模型输出中的文本 token 数 |
| `mastra_model_output_reasoning_tokens` | 推理或思维链 token 数（如 OpenAI o 系列） |
| `mastra_model_output_audio_tokens` | 模型输出中的音频 token 数 |
| `mastra_model_output_image_tokens` | 输出的图像 token 数 |

### Provider 报告的详细 token 类别 {/* #provider-reported-detailed-token-categories */}

除 `total_input` 和 `total_output` 之外，只有 Provider 报告了对应数据，Mastra 才会发出细分指标。如果某个类别的 token 数为零，该 Span 就不会产生对应指标。不同 Provider 报告的细节程度不同，例如并非所有 Provider 都会报告缓存或音频 token 数。

## 成本相关上下文 {/* #cost-related-context */}

### 何时附加成本上下文 {/* #when-cost-context-is-attached */}

如果 Provider 为每个已完成的模型步骤报告了有效成本，或价格注册表中有匹配的 Provider 和模型价格，Mastra 就会为 token 指标附加成本上下文。Mastra 将 Provider 报告的各步骤成本相加，得到整个查询的总成本。如果任何已完成步骤缺少有效的成本报告，Mastra 会改用价格注册表，而不会报告不完整的总成本。如果两个来源都不可用，Mastra 仍会发出 token 指标，但不附带成本字段。

调用方提供的 `costContext` 优先于 Provider 报告的成本和价格注册表的估算值。对于 Provider 报告的总成本，`costMetadata.source: 'provider_reported'`、`costMetadata.scope: 'query_total'` 和 `costMetadata.reportedStepCount` 分别标明来源、统计范围以及纳入总成本的已完成步骤数。

### 价格从何而来 {/* #where-prices-come-from */}

价格注册表使用 [models.dev](https://models.dev) 的模型价格。`@mastra/observability` 内置这些价格的快照，每次发布新版本时都会包含近期价格。价格变化后，已存储的成本估算值不会重新计算。[自定义网关](/models/gateways/custom-gateways#model-pricing)可以为 models.dev 未收录的模型返回自己的 `pricing`；这些价格只用于填补 models.dev 未提供价格的模型。

运行 `mastra dev` 时，Mastra 还会每天在后台从 models.dev 刷新一次价格；遇到没有价格的模型时也会刷新。成本估算不会等待刷新完成，因此首次调用新发布的模型时仍可能没有成本数据。在生产等其他环境中，可以设置 `MASTRA_AUTO_REFRESH_PRICING=true` 来启用刷新。

刷新后的价格缓存在 `~/.cache/mastra/pricing-data.json` 中，供后续进程复用。如果刷新失败，Mastra 会保留已有价格。

如果只想使用内置快照，请设置 `MASTRA_AUTO_REFRESH_PRICING=false`。设置 `MASTRA_OFFLINE=true` 也会关闭刷新。

### 可能包括哪些成本字段 {/* #what-cost-fields-may-be-included */}

|字段 |说明 |
| - | - |
|`provider` | Provider 名称（如 `openai`、`anthropic`） |
| `model` | 模型标识符（如 `gpt-4o`、`claude-sonnet-4-20250514`） |
| `estimatedCost` | 根据 token 数量和价格档位估算的成本，或 Provider 报告的总成本 |
| `costUnit` | 货币单位（如 `USD`） |
| `costMetadata` | 其他价格上下文，包括档位信息、错误详情，以及 Provider 报告的成本来源和统计范围 |

## 与 Trace 的关联 {/* #correlation-with-traces */}

### 指标如何关联 Span 和 Trace 上下文 {/* #how-metrics-relate-to-spans-and-trace-context */}

每项指标都带有一个来自产生该指标的 Span 的 `CorrelationContext` 快照。该上下文与指标值一起存储，可将指标精确关联到对应的 Span 和 Trace。

关联字段分为以下几类：

**Trace 关联**

* `traceId`：Trace 标识符
* `spanId`: Span 标识符
* `tags`：来自 Span 的标签

**实体层次结构**

* `entityType`, `entityId`, `entityName`: 产生指标的实体（如 Agent、Workflow）
* `parentEntityType`, `parentEntityId`, `parentEntityName`: 父实体
* `rootEntityType`, `rootEntityId`, `rootEntityName`: 调用链中的根实体

**身份**

* `userId`, `organizationId`, `resourceId`: 请求中的身份上下文
* `runId`, `sessionId`, `threadId`, `requestId`: 关联 ID

**部署**

* `environment`：部署环境（如 `production`、`staging`）
* `source`: 来源标识符
* `serviceName`：可观测性配置中的服务名称
* `experimentId`：实验标识符（如果适用）

### 为什么关联有助于调试 {/* #why-correlation-helps-with-debugging */}

在指标仪表板上发现延迟或 token 用量激增时，可以利用关联上下文直接查看产生该指标的 Trace，再检查其中的具体 Span。根因可能是 Tool 调用缓慢、提示词过长，也可能是意外错误。

## 故障排除 {/* #troubleshooting */}

### 没有可用的指标 {/* #no-metrics-are-available */}

* **已配置可观测性**: 检查 `Mastra` 实例是否配置了 `observability`，且至少包含一个导出器。
* **包含 `MastraStorageExporter` 或 `MastraPlatformExporter`**：Datadog、Langfuse 等其他导出器不会在 Mastra 中显示指标。要在本地 Studio 仪表板查看指标，需要 `MastraStorageExporter`；要在 Mastra 平台查看，则需要 `MastraPlatformExporter`。
* **存储支持指标**：指标需要支持分析的存储（ClickHouse、DuckDB，或启用了可观测性域的 Postgres v-next）。其他面向行的数据库（LibSQL、MSSQL）和文档存储（MongoDB）不支持指标。
* **采样率不为 0%**：如果采样概率为 `0` 或策略为 `never`，所有 Span 都会变成空操作，系统不会提取指标。

### 缺少持续时间指标 {/* #duration-metrics-are-missing */}

* **Span 有时间戳**：持续时间由 `startTime` 和 `endTime` 计算。如果缺少任一时间戳，该指标就会被跳过。
* **Span 类型对应持续时间指标**：只有 `AGENT_RUN`、`TOOL_CALL`、`MCP_TOOL_CALL`、`PROVIDER_TOOL_CALL`、`WORKFLOW_RUN`、`MODEL_GENERATION` 和 `PROCESSOR_RUN` Span 会产生持续时间指标。

### 缺少令牌指标 {/* #token-metrics-are-missing */}

* **Span 是模型生成或分类器评估**：只有 `MODEL_GENERATION` 和 `CLASSIFIER_EVALUATION` Span 会发出 token 指标。
* **Provider 报告用量**：模型 Provider 必须在响应中包含 `usage` 数据，系统才能发出 token 指标。
