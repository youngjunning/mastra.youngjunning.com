# 自动指标参考

Mastra 自动从跟踪的执行中提取性能和使用指标。此页面是 Mastra 发出的每个指标名称、标签和上下文字段的完整参考。

有关设置说明，请参阅[Metrics overview](/docs/observability/metrics/overview).

## 当 Mastra 发出自动指标时 {/* #when-mastra-emits-automatic-metrics */}

当跨度结束时，会从跨度中提取指标。可观察性层检查每个已完成的跨度，计算持续时间，并从模型生成和分类器评估跨度中读取令牌使用数据。无需手动仪器。

### 影响指标是否可用的因素有哪些 {/* #what-affects-whether-a-metric-is-available */}

指标在以下情况下到达存储：

1. `MastraStorageExporter`被配置为导出器。
2. 存储后端支持指标（ClickHouse、DuckDB 或启用可观察域的 Postgres v-next）。

如果指标不可用，请参阅[troubleshooting](#troubleshooting).

## 持续时间指标 {/* #duration-metrics */}

持续时间指标记录执行时间（以毫秒为单位），根据跨度的开始和结束时间戳计算。每个持续时间指标包括`status` label set to `ok` or `error`, derived from the span's status.

|指标名称 |跨度类型|描述 |
| - | - | - |
|`mastra_agent_duration_ms` | `AGENT_RUN` | Execution time of an agent run |
| `mastra_tool_duration_ms` | `TOOL_CALL`, `MCP_TOOL_CALL`, `PROVIDER_TOOL_CALL` | Execution time of a tool call, including MCP and provider-executed tool calls |
| `mastra_workflow_duration_ms` | `WORKFLOW_RUN`|Workflow程运行的执行时间 |
|`mastra_model_duration_ms` | `MODEL_GENERATION`|模型生成的执行时间 |
|`mastra_processor_duration_ms` | `PROCESSOR_RUN`|处理器运行的执行时间 |

## 代币使用指标 {/* #token-usage-metrics */}

令牌指标是从发出的`MODEL_GENERATION` and `CLASSIFIER_EVALUATION` spans that include `usage` data. Token metrics require usage data from the provider.

### 输入令牌指标 {/* #input-token-metrics */}

|指标名称 |描述 |
| - | - |
|`mastra_model_total_input_tokens` | Total input tokens |
| `mastra_model_input_text_tokens` | Text tokens in the input prompt |
| `mastra_model_input_cache_read_tokens` | Tokens read from prompt cache (e.g. Anthropic) |
| `mastra_model_input_cache_write_tokens` | Tokens written to prompt cache |
| `mastra_model_input_cache_write_5m_tokens` | Tokens written to prompt cache with a 5-minute TTL (e.g. Anthropic) |
| `mastra_model_input_cache_write_1h_tokens` | Tokens written to prompt cache with a 1-hour TTL (e.g. Anthropic) |
| `mastra_model_input_audio_tokens` | Audio tokens in the input (multimodal models) |
| `mastra_model_input_image_tokens` | Image tokens in the input (vision models) |

### 输出代币指标 {/* #output-token-metrics */}

|指标名称 |描述 |
| - | - |
|`mastra_model_total_output_tokens` | Total output tokens |
| `mastra_model_output_text_tokens` | Text tokens in the model's output |
| `mastra_model_output_reasoning_tokens` | Reasoning / chain-of-thought tokens (e.g. OpenAI o-series) |
| `mastra_model_output_audio_tokens` | Audio tokens in the model's output |
| `mastra_model_output_image_tokens` | Output image tokens |

### Provider报告的详细代币类别 {/* #provider-reported-detailed-token-categories */}

详细的细分指标（除了`total_input` and `total_output`) are only emitted when the provider reports them. If a category has zero tokens, the metric is skipped for that span. Different providers report different levels of detail. For example, not all providers report cache or audio tokens.

## 成本相关背景 {/* #cost-related-context */}

### 当附加成本上下文时 {/* #when-cost-context-is-attached */}

当提供者报告每个已完成的模型步骤的有效成本或当定价注册表具有提供者和模型的匹配条目时，成本上下文附加到令牌度量。 Mastra 将每一步提供程序的成本汇总到一个查询总计中。如果任何已完成的步骤缺少有效的报告成本，Mastra 将使用定价注册表而不是报告部分总计。如果两个来源都不可用，则仍会发出不带成本字段的令牌指标。

来电者提供的`costContext` takes precedence over provider-reported costs and pricing registry estimates. Provider-reported totals use `costMetadata.source: 'provider_reported'`, `costMetadata.scope: 'query_total'`, and `costMetadata.reportedStepCount` to identify the source, scope, and number of completed steps included in the total.

### 价格从何而来 {/* #where-prices-come-from */}

定价登记处使用的模型价格来自[models.dev](https://models.dev). `@mastra/observability` includes a snapshot of these prices, and each new release of the package includes recent prices. Stored cost estimates aren't recalculated when prices change. A [custom gateway](/models/gateways/custom-gateways#model-pricing) can return its own `pricing` for models that models.dev doesn't list. These prices only fill in models that models.dev doesn't price.

当你跑步时`mastra dev`, Mastra also refreshes prices from models.dev in the background once a day, and when a model has no price. Cost estimates don't wait for a refresh, so the first call to a newly released model can still have no cost. In other environments, such as production, you can turn on the refresh with `MASTRA_AUTO_REFRESH_PRICING=true`.

刷新的价格缓存在`~/.cache/mastra/pricing-data.json` and reused by later processes. If a refresh fails, Mastra keeps the prices it already has.

要仅使用捆绑快照，请设置`MASTRA_AUTO_REFRESH_PRICING=false`. Setting `MASTRA_OFFLINE=true` also turns off the refresh.

### 可能包括哪些成本字段 {/* #what-cost-fields-may-be-included */}

|领域 |描述 |
| - | - |
|`provider` | Provider name (e.g. `openai`, `anthropic`) |
| `model` | Model identifier (e.g. `gpt-4o`, `claude-sonnet-4-20250514`) |
| `estimatedCost` | Estimated cost from token count and pricing tier, or a total reported by the provider |
| `costUnit` | Currency unit (e.g. `USD`) |
| `costMetadata` | Additional pricing context, including tier information, error details, and provider-reported cost source and scope |

## 与迹线的相关性 {/* #correlation-with-traces */}

### 指标如何与跨度和跟踪上下文相关 {/* #how-metrics-relate-to-spans-and-trace-context */}

每个指标都带有一个`CorrelationContext` snapshot from the span that produced it. This context is stored alongside the metric value and links a metric to the exact span and trace.

相关字段使用以下类别：

**迹线相关性**

* `traceId`：跟踪标识符
* `spanId`: 跨度标识符
* `tags`：来自跨度的标签

**实体层次结构**

* `entityType`, `entityId`, `entityName`: The entity that produced the metric (e.g. agent, workflow)
* `parentEntityType`, `parentEntityId`, `parentEntityName`: The parent entity
* `rootEntityType`, `rootEntityId`, `rootEntityName`: The root entity in the call chain

**身份**

* `userId`, `organizationId`, `resourceId`: Identity context from the request
* `runId`, `sessionId`, `threadId`, `requestId`: Correlation IDs

**部署**

* `environment`：部署环境（例如`production`, `staging`)
* `source`: 源标识符
* `serviceName`：可观察性配置中的服务名称
* `experimentId`：实验标识符（如果适用）

### 为什么关联有助于调试 {/* #why-correlation-helps-with-debugging */}

当您在指标仪表板上发现延迟或令牌使用量激增时，关联上下文可让您直接钻取生成指标的跟踪。从那里您可以检查各个跨度。根本原因可能是Tool调用缓慢或提示较大。这也可能是意外错误。

## 故障排除 {/* #troubleshooting */}

### 没有可用的指标 {/* #no-metrics-are-available */}

* **可观察性已配置**: 验证您的`Mastra` instance has an `observability` config with at least one exporter.
* **`MastraStorageExporter`或者`MastraPlatformExporter` is present**：其他导出器（Datadog、Langfuse 等）不在 Mastra 中显示指标。`MastraStorageExporter` is required for the local Studio dashboard, and `MastraPlatformExporter` is required to view metrics in Mastra platform.
* **存储支持指标**：指标需要具有分析功能的存储（ClickHouse、DuckDB 或启用了可观察域的 Postgres v-next）。指标不支持其他面向行的数据库（LibSQL、MSSQL）和文档存储（MongoDB）。
* **抽样不是0%**：如果采样概率为`0` or strategy is `never`, all spans become no-ops and no metrics are extracted.

### 缺少持续时间指标 {/* #duration-metrics-are-missing */}

* **Span 有时间戳**：持续时间的计算方式为`startTime` and `endTime`. If either is missing, the metric is skipped.
* **Span 类型映射到度量**： 仅有的`AGENT_RUN`, `TOOL_CALL`, `MCP_TOOL_CALL`, `PROVIDER_TOOL_CALL`, `WORKFLOW_RUN`, `MODEL_GENERATION`, and `PROCESSOR_RUN` spans produce duration metrics.

### 缺少令牌指标 {/* #token-metrics-are-missing */}

* **Span是模型生成或分类器评估**：令牌指标仅从以下位置发出`MODEL_GENERATION` and `CLASSIFIER_EVALUATION` spans.
* **Provider报告使用情况**：模型提供者必须包括`usage` data in its response. Usage data is required to emit token metrics.
