# 反馈

**引入版本：** `@mastra/core@1.18.0`

反馈 API 存储和查询评分、赞踩、评论与纠正等人工反馈可观测性信号。用法示例请参阅[反馈指南](/docs/observability/feedback)。

## 使用示例 {/* #usage-example */}

以下示例通过可观测性入口为已持久化的 trace 记录评分。入口上的 `addFeedback()` 是可选方法，调用前请检查当前可观测性实现是否支持。

```typescript
if (!mastra.observability.addFeedback) {
  throw new Error('Feedback is not supported by the active observability implementation')
}

await mastra.observability.addFeedback({
  traceId: 'trace-123',
  spanId: 'span-456',
  feedback: {
    feedbackSource: 'user',
    feedbackType: 'rating',
    value: 1,
    comment: 'Helpful answer.',
  },
})
```

## 创建反馈 {/* #create-feedback */}

### `addFeedback(args)` {/* #addfeedbackargs */}

向已配置的 Exporter 发送针对 trace 或 span 的反馈。

```typescript
await mastra.observability.addFeedback?.({
  traceId: 'trace-123',
  spanId: 'span-456',
  feedback: {
    feedbackSource: 'user',
    feedbackType: 'rating',
    value: 1,
    comment: 'Helpful answer.',
  },
})
```

<PropertiesTable
  content={[
{ name: 'traceId', type: 'string', description: '关联反馈目标的 trace。', isOptional: true },
{ name: 'spanId', type: 'string', description: '关联反馈目标的 span。', isOptional: true },
{
  name: 'correlationContext',
  type: 'CorrelationContext',
  description: '实时 span 或 trace 上下文，可直接用于发送事件，无需从存储中重新加载目标。',
  isOptional: true,
},
{ name: 'feedback', type: 'FeedbackInput', description: '要添加的反馈内容。' },

未提供 `correlationContext` 时，每个 Exporter 在自己的目标端处理对应的 trace 或 span。`MastraStorageExporter` 从本地存储解析目标；本地查找失败不会阻止其他 Exporter。`MastraPlatformExporter` 不需要本地存储。使用 `flush()` 或 `shutdown()` 等待待发送的数据处理完毕。

本地查找需要取得目标 span 向上直到根 span 的完整父链，才能让反馈继承正确的根标签。如果重试后仍缺少任一祖先 span，存储 Exporter 会记录警告并跳过本地写入；其他 Exporter 仍会收到反馈。

### `createFeedback(args)` {/* #createfeedbackargs */}

通过可观测性存储域创建一条反馈记录。存储层调用会直接写入存储，因此需要包含 `timestamp`。

```typescript
await observability.createFeedback({
  feedback: {
    feedbackId: 'feedback-1',
    timestamp: new Date(),
    traceId: 'trace-123',
    spanId: 'span-456',
    feedbackSource: 'user',
    feedbackType: 'rating',
    value: 1,
    comment: 'Helpful answer.',
  },
})
```

HTTP 和客户端 SDK 的创建路由接受 `CreateFeedbackBody`，其中 `feedback.traceId` 必须为非空字符串，`spanId` 可选。客户端在重试前补充缺失的 `feedbackId` 和 ISO 格式的 `timestamp`；直接调用 OSS HTTP 时可省略，使用服务端默认值。可选的顶层 `contextMode` 用于选择使用提供的上下文，或解析已存储的 span；OSS 默认为 `"provided"`，Platform 默认为 `"resolve"`。请参阅[信号写入选项](/reference/client-js/observability#signal-write-options)：

```typescript
await mastraClient.createFeedback({
  feedback: {
    traceId: 'trace-123',
    spanId: 'span-456',
    feedbackSource: 'user',
    feedbackType: 'rating',
    value: 1,
  },
})
```

对于 OSS HTTP 请求，已认证用户的 ID 优先用作 `feedbackUserId`。没有已认证用户时，请显式提供 `feedbackUserId`，或将其留为 null 以提交匿名反馈。`userId` 表示 span 用户，不用作 HTTP 反馈作者。直接调用存储时，如果省略 `feedbackUserId`，仍可使用已弃用的 `userId` 作者别名；显式设置为 null 的作者保持 null。

### `batchCreateFeedback(args)` {/* #batchcreatefeedbackargs */}

通过可观测性存储域创建多条反馈记录。HTTP 路由和 `@mastra/client-js` 均不提供此方法。

```typescript
await observability.batchCreateFeedback({
  feedbacks: [
    {
      feedbackId: 'feedback-1',
      timestamp: new Date(),
      traceId: 'trace-123',
      feedbackSource: 'user',
      feedbackType: 'rating',
      value: 1,
    },
    {
      feedbackId: 'feedback-2',
      timestamp: new Date(),
      traceId: 'trace-123',
      feedbackSource: 'qa',
      feedbackType: 'comment',
      value: 'Needs a citation before shipping.',
    },
  ],
})
```

## 删除反馈 {/* #delete-feedback */}

### `deleteFeedback(args)` {/* #deletefeedbackargs */}

按 ID 删除最多 1,000 条反馈记录。此操作具有幂等性：不存在的 ID 会被忽略，空 `feedbackIds` 数组不执行任何操作。提供 `organizationId` 或 `resourceId` 时，只删除符合该范围的记录。

```typescript
await mastraClient.deleteFeedback({
  feedbackIds: ['feedback-1', 'feedback-2'],
})
```

<PropertiesTable

{

  type: 'string[]',
  description: '要删除的反馈记录 ID，最多接受 1,000 个。',
},
{
  name: 'organizationId',
  type: 'string',
  description: '仅删除属于此组织 ID 的记录。',
  isOptional: true,
},
{
  name: 'resourceId',
  type: 'string',
  description: '仅删除属于此资源 ID 的记录。',
  isOptional: true,
},
]}
/>

OSS HTTP 路由返回 `{ success: boolean }`。`mastraClient.deleteFeedback()` 返回 `Promise<{ success: boolean } | { accepted: true }>`，以兼容将批量删除排队处理的 Platform 后端。返回 accepted 表示清理已入队，在清理执行前记录仍可能可读。请参阅[客户端删除响应处理](/reference/client-js/observability#deleting-traces)。存储域方法返回 `Promise<void>`。超过 1,000 个 ID 的请求返回 `400`；运行低于 `1.66.0` 版本 `@mastra/core` 的服务端返回 `501`。ClickHouse vNext、PostgreSQL vNext、DuckDB 和内存存储支持删除。其他适配器（包括 LibSQL 和 MongoDB）会抛出 `OBSERVABILITY_STORAGE_DELETE_FEEDBACK_NOT_IMPLEMENTED`。

在 ClickHouse 中，删除操作对主反馈事件表执行轻量级删除，使记录不再出现在包括 OLAP 查询在内的读取结果中，但不保证立即从物理存储清除。因此，开源部署必须配置[可观测性保留期限](/reference/storage/retention)，以最终物理清除这些记录。每个删除请求成功后才标记为已应用；如果失败，请求仍处于未应用状态，不会阻止对仍可见反馈调用 `updateFeedbackReviewStatus()`，可再次调用 `deleteFeedback()` 重试。`updateFeedbackReviewStatus()` 也会重试删除：若重试成功，则抛出未找到错误；若再次失败，则保存新状态并抛出删除错误。开源部署没有后台协调程序。仅当五种信号都有有限保留期时，ClickHouse 才会为删除请求设置 TTL。请参阅 [ClickHouse 原生 TTL](/reference/storage/retention#clickhouse-native-ttl)。删除 API 不会改动独立的增量游标表；其中只存储标识符而非反馈内容，并在两天内过期。

### `deleteScores(args)` {/* #deletescoresargs */}

按 ID 删除最多 1,000 条评分记录。其行为与 `deleteFeedback()` 相同，只是以 `scoreIds` 代替 `feedbackIds`；Oracle Database 也支持此操作。不支持的适配器会抛出 `OBSERVABILITY_STORAGE_DELETE_SCORES_NOT_IMPLEMENTED`。

```typescript
await mastraClient.deleteScores({
  scoreIds: ['score-1', 'score-2'],
})
```

  feedbackType: 'rating',

  aggregation: 'avg',

```typescript

  feedbackType: 'rating',
  percentiles: [0.5, 0.95],
  interval: '1d',
})
```

## 替换反馈 {/* #replace-feedback */}

`PUT /api/observability/feedback/:feedbackId` 接受完整的 `{ feedback: { ... } }` 替换数据。保留原有的 `feedbackId`、`traceId` 和 `timestamp`，并包含所有需要保留的字段；省略的可选字段会被清除。URL 和请求体中的 ID 必须一致。请参阅[客户端示例](/reference/client-js/observability#replacing-feedback)。

OSS 在返回成功前写入已配置的存储，并分别通知支持此操作的 Exporter。`contextMode` 与创建时含义相同。在 `"resolve"` 模式下，本地 trace 或 span 必须存在。如果反馈记录不存在，会用完整的替换数据创建记录。更改现有记录的 trace 或时间戳会返回 `409`。

内存、PostgreSQL vNext、DuckDB 和 ClickHouse vNext 存储支持替换。请检查服务端的 `capabilities.feedbackReplacement`；不支持的版本返回 `501`。按顺序重试原始 HTTP 创建请求不会撤销替换。直接调用存储的 `createFeedback()` 仍具有 upsert 行为；传入 `onConflict: 'ignore'` 可保留现有记录。

ClickHouse 支持使用现有 schema，无需迁移。来自不同进程的并发写入可能竞争，因此无法保证重叠的创建和替换操作的执行顺序。使用此适配器时，请串行修改同一反馈记录。

若要向已配置的 Exporter 发送替换事件，而不依赖本地存储，请使用可观测性入口：

```typescript
await mastra.observability.replaceFeedback?.({
  traceId: 'trace-123',
  feedback: {
    feedbackId: 'feedback-1',
    timestamp: new Date('2026-11-11T12:00:00.123Z'),
    feedbackType: 'thumbs',
    value: -1,
  },
})
```

各 Exporter 独立处理自己的目标端。`MastraStorageExporter` 在需要时解析本地 span 上下文，`MastraPlatformExporter` 则向 Platform 发送 PUT 请求。不支持替换的 Exporter 会跳过该事件。`flush()` 和 `shutdown()` 会等待待发送的数据处理完毕。

## 更新审核状态 {/* #updating-review-status */}

若要在已配置的 Exporter 目标端更改审核状态，请传入反馈 ID，以及 `"reviewed"` 或 `"needs-review"`：

```typescript
await mastra.observability.updateFeedbackReviewStatus?.({
  feedbackId: 'feedback-123',
  reviewStatus: 'reviewed',
})
await mastra.observability.flush()
```

审核更新会发送给每个支持它的 Exporter，即使反馈未存储在本地也是如此。调用 `flush()` 或 `shutdown()` 以等待待发送的数据处理完毕。

## HTTP 路由 {/* #http-routes */}

这些路由属于 Mastra 运行时，使用其配置的可观测性存储。它们与[未版本化的 Mastra Platform Feedback API](/docs/mastra-platform/api#feedback-api) 不同；后者不提供反馈创建路由。

| 方法 | 路径 | 用途 | 权限 |
| - | - | - | - |
| `GET` | `/api/observability/feedback` | 列出反馈记录 | `observability:read` |
| `POST` | `/api/observability/feedback` | 创建反馈记录 | `observability:write` |
| `PUT` | `/api/observability/feedback/:feedbackId` | 完整替换反馈记录 | `observability:write` |
| `DELETE` | `/api/observability/feedback` | 按 ID 删除反馈记录 | `observability:delete` |
| `DELETE` | `/api/observability/scores` | 按 ID 删除评分记录 | `observability:delete` |
| `PATCH` | `/api/observability/feedback/:feedbackId/review-status` | 更新审核状态 | `observability:write` |
| `POST` | `/api/observability/feedback/aggregate` | 返回单个聚合值 | `observability:read` |
| `POST` | `/api/observability/feedback/breakdown` | 按维度对反馈分组 | `observability:read` |
| `POST` | `/api/observability/feedback/timeseries` | 按时间间隔将反馈分桶 | `observability:read` |
| `POST` | `/api/observability/feedback/percentiles` | 返回百分位数序列 | `observability:read` |

### 列出查询参数 {/* #list-query-parameters */}

`GET /api/observability/feedback` 通过 URL 查询参数接收参数。[Mastra Platform Feedback API](/docs/mastra-platform/api#feedback-api) 的 `GET /feedback` 端点也接受相同参数。

```bash
curl -sS "http://localhost:4111/api/observability/feedback?traceId=trace-123&environment=production&feedbackType=rating&page=0&perPage=20"
```

[`FeedbackFilter`](#feedbackfilter) 的每个字段都可作为同名顶层查询参数传入，例如 `traceId`、`spanId`、`feedbackType`、`feedbackSource`、`feedbackUserId`、`reviewStatus`、`entityName`、`environment`、`experimentId` 或 `tags`。对于接受数组的筛选条件，可重复传入参数，例如 `feedbackType=rating&feedbackType=thumbs`。对象型筛选条件（如 `timestamp`）需以 JSON 形式传入，例如将 `timestamp={"start":"2026-01-01T00:00:00Z"}` 进行 URL 编码。
