# WorkspaceSandbox

**添加于：** `@mastra/core@1.1.0`

这`WorkspaceSandbox` interface defines how workspaces execute commands and manage background processes.

## 方法 {/* #methods */}

### `start()` {/* #start */}

启动Sandbox并被自动调用`workspace.init()` or the first `executeCommand()` call.

```typescript
const result = await sandbox.start()
// { outcome: 'created' } — a fresh VM was created
// { outcome: 'connected' } — reconnected to an existing VM
// undefined — the provider does not report
```

**返回：** `void | Promise<SandboxStartResult | void>`

使用已知构建的Sandbox`id` resolves that id on `start()`: reconnect or resume the sandbox if it exists, create it if not (get-or-create). Providers that support this report a `SandboxStartResult`:

<PropertiesTable
  content={[
{
  name: 'outcome',
  type: "'created' | 'connected'",
  description:
    "`'created'` when a brand-new sandbox VM (or working directory) was provisioned; `'connected'` when the call reconnected to or resumed an existing one.",
},
]}
/>

合同返还之前的Provider`void`, which the base class treats as unknown.

提供程序使用以下方法之一实现启动生命周期（按优先顺序列出）。基类处理并发启动调用和状态管理，以及`onStart` hook and mount processing:

1. **采集原语**：实施保护`find()` (side-effect-free lookup by logical id, returning a provider-native handle or `undefined`), `connect(handle)` (wake/resume/adopt), and `create()` (provision fresh) without overriding `start()`. The base orchestrates find → connect → `{ outcome: 'connected' }`, else create → `{ outcome: 'created' }`。结果在结构上源自运行的分支。使用者`E2BSandbox`, `DaytonaSandbox`， 和`LocalSandbox`.
2. **`start()`覆盖返回`SandboxStartResult`**：对于其 API 是融合获取或创建的Provider，其中分解会添加往返（`PlatformSandbox`, `RailwaySandbox`).
3. **`start()`覆盖返回`void`**：遗留Provider，结果未知。

并发`start()` calls on one instance coalesce onto a single in-flight attempt, and joined callers share that attempt's result (all observe `outcome: 'created'` when the shared attempt created the VM). The in-flight slot is cleared when the attempt settles, so a failed start can be retried. For a sandbox already in the `running` state, `start()` resolves `{ outcome: 'connected' }` without re-invoking the provider.

结果也转发给`onStart` lifecycle hook as `{ sandbox, outcome }`.

### `onStart`（构造函数选项） {/* #onstart-constructor-option */}

`onStart`在Sandbox到达后，在启动生命周期内运行`running` status and before pending mounts are processed. It fires on every start regardless of trigger, whether an explicit call, a lazy `ensureRunning()` from a command, or a revival after the provider replaced the VM. Use this hook for once-per-VM setup: check `outcome` to decide whether to run setup or check that it already completed.

```typescript
new E2BSandbox({
  id: sessionId,
  onStart: async ({ sandbox, outcome }) => {
    if (outcome === 'created') {
      // Fresh VM: run the full setup.
      await runSetup(sandbox)
      return
    }
    // Reconnected: probe, and self-heal if setup never completed.
    const probe = await sandbox.executeCommand('test -d ~/repo/.git')
    if (probe.exitCode !== 0) await runSetup(sandbox)
  },
})
```

语义：

* 抛出的错误是致命的：`start()` rejects with the hook's error and the sandbox is marked `error`. A caller never observes a running sandbox whose setup hook failed. Nothing is latched, and the next `start()` (including the one triggered by the next lazy command) retries the hook. `onStop` and `onDestroy` remain non-fatal observers, because teardown proceeds best-effort.
* `outcome`区分分支：`'created'` means this start provisioned a fresh VM (run setup), `'connected'` means it reconnected or resumed (setup normally already ran, so probe when the hook must self-heal a crash between create and setup-complete). `undefined` means the provider doesn't report.
* 保持设置工作幂等。每当探测器决定应该重新运行时，钩子就会重新运行，并且检查点恢复的新虚拟机报告`outcome: 'created'`.
* Sandbox状态翻转为`running` before the hook executes (the hook runs commands through the sandbox's own command path), so commands issued concurrently through `ensureRunning()` can interleave with it. Callers awaiting the original `start()` always observe a sandbox whose hook finished.
* 该钩子在处理挂起的文件系统挂载之前运行，因此它不能依赖于挂载的路径。

### `setOnStart(update)` {/* #setonstartupdate */}

在构建后附加一个启动钩子，用于接收未构建的Sandbox的运行时。如果没有它，构造Sandbox的每个主机都必须接受一个钩子并将其传递给提供者构造函数，并且忘记的主机会使安装程序不运行而不会出现错误。

更新程序接收当前安装的挂钩，无论是`onStart` constructor option or one a previous call left behind, and returns the hook to install. Composing this way means a caller never discards a hook it didn't know about:

```typescript
sandbox.setOnStart?.(previous => async args => {
  await previous?.(args) // whatever prepared the sandbox runs first
  await mySetup(args)
})
```

语义：

* 错误仍然是致命的，与构造函数选项完全相同。因为每个钩子都等待下一个钩子，所以抛出会停止在其之后排序的钩子。
* 呼叫者选择顺序。等待`previous` first when your hook needs the workspace it prepares, or last when yours is the one preparing it.
* 忽略`previous` replaces the installed hook. That's supported, and it's how a caller takes over setup a runtime installed.
* 每个调用都会包装当前的钩子，因此每个Sandbox实例附加一次。附加到按请求运行的路径会在每次启动时堆叠重复的工作。
* 仅在调用后开始才能看到新的挂钩。

### `workingDirectory`（构造函数选项） {/* #workingdirectory-constructor-option */}

设置命令执行和进程生成的默认目录。当命令不提供每个命令时`cwd`, the sandbox runs it from this directory. A per-command `cwd` always wins. When neither is provided, each provider keeps its own default (E2B home, Docker `/workspace`, Vercel serverless `/tmp`, and so on).

```typescript
const sandbox = new E2BSandbox({ workingDirectory: '/home/user/my-repo' })
await sandbox.executeCommand('pwd') // /home/user/my-repo
await sandbox.executeCommand('pwd', [], { cwd: '/tmp' }) // /tmp
```

有效值可通过以下方式读取`sandbox.workingDirectory` getter. Providers that compute their value, such as Daytona's automatic probe or Docker's `/workspace` default, report the effective directory through the same getter.

语义：

* 该值按原样传递给提供程序，并且Sandbox不会创建目录。推荐绝对路径：`~`-prefixed paths only work where the provider documents expansion.
* 一些Provider将早期的选项名称保留为提供相同字段的已弃用别名：`workingDir` on Docker and Apple container, `workdir` on Modal. When both the alias and `workingDirectory` are set, `workingDirectory` wins.


### `setEnv(update)` {/* #setenvupdate */}

更新Sandbox的运行时环境。这些值被合并到Sandbox运行的每个命令中，包括`executeCommand()` and `processes.spawn()`, so credentials installed or rotated after the sandbox was created reach every subsequent command. Optional, so check for support or use optional chaining.

```typescript
sandbox.setEnv?.(env => ({ ...env, GH_TOKEN: token }))
```

更新程序接收当前环境的副本并返回替换，因此单个调用可以设置、取消设置或批量更新变量。删除密钥只会将其从Sandbox的运行时环境中删除，因此提供程序本身提供的值仍然适用。播种初始值`env` constructor option.

运行时环境适用于通过Sandbox执行的命令，而不是虚拟机自己的环境，因此它永远不会写入虚拟机，并且在提供程序暂停和恢复后仍然存在。当命令运行时，首先应用提供程序默认值，Sandbox的运行时环境将覆盖它们，并且每次调用`env` option on `executeCommand()` wins over both.

### `getEnv()` {/* #getenv */}

可用于`MastraSandbox`, not declared on the `WorkspaceSandbox` interface. Returns a copy of the sandbox's current runtime environment; because mutations to the returned object don't change the sandbox, use `setEnv()` for updates.

```typescript
const token = sandbox.getEnv().GH_TOKEN
```

**返回：** `Record<string, string | undefined>`

## 本机文件系统 {/* #native-filesystem */}

其提供者具有文件 API 的Sandbox将其公开在可选的`filesystem` property. Reads, writes, and listings take one request each, where the same work through `executeCommand()` takes a command per step. Paths are absolute inside the sandbox.

提供者拥有遏制：`filesystem` doesn't confine paths or symlinks to a workspace root. Fall back to `executeCommand()` when the property is absent:

```typescript
const pkg = sandbox.filesystem
  ? await sandbox.filesystem.readFile('/workspace/app/package.json', { encoding: 'utf-8' })
  : (await sandbox.executeCommand?.('cat', ['/workspace/app/package.json']))?.stdout
```

`E2BSandbox`总是暴露`filesystem`. With `PlatformSandbox`, the property is available only when the provider is `e2b` and returns `undefined` otherwise. To use it in a `Workspace`, pass it explicitly as the workspace `filesystem`, or call it directly.
