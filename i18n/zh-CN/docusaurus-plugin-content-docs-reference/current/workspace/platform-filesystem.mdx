# PlatformFilesystem

将文件存储在 Mastra Platform 的 Workspace 存储桶中。每个 Mastra Platform 环境可以有一个存储桶；`PlatformFilesystem` 为 Agent 提供对该存储桶的 `read`、`write`、`list`、`delete` 和 `move` 操作。

相关 Provider：[`S3Filesystem`](/integrations/file-storage/amazon-s3) 用于直接访问 S3，[`LocalFilesystem`](/reference/workspace/local-filesystem) 用于访问本地目录。

:::note

接口详情请参阅 [WorkspaceFilesystem 接口](/reference/workspace/filesystem)。

:::

## 安装 {/* #installation */}

```bash npm2yarn
npm install @mastra/platform-workspace
```

配置平台凭据。访问令牌、项目 ID 和存储桶名称默认从环境变量读取，因此在 Mastra Platform 部署中调用构造函数时可以不传入任何选项。

<Tabs>
  <TabItem value="env-file" label=".env 文件">
    ```bash
    MASTRA_PLATFORM_ACCESS_TOKEN=your-platform-access-token
    MASTRA_PROJECT_ID=your-project-id
    MASTRA_PLATFORM_BUCKET_NAME=your-bucket-name
    ```
  </TabItem>

  <TabItem value="constructor" label="构造函数">
    ```typescript
    new PlatformFilesystem({
      accessToken: 'your-platform-access-token',
      projectId: 'your-project-id',
      bucketName: 'your-bucket-name',
    })
    ```
  </TabItem>
</Tabs>

在 Mastra Platform 部署中，系统会自动注入 `MASTRA_PLATFORM_ACCESS_TOKEN`、`MASTRA_PROJECT_ID` 和 `MASTRA_PLATFORM_BUCKET_NAME`，因此调用构造函数时无需传入选项。本地开发时，`MASTRA_PLATFORM_ACCESS_TOKEN` 可以使用组织设置页面 **API Tokens** 下以 `sk_` 开头的 API 令牌。

## 用法 {/* #usage */}

将 `PlatformFilesystem` 添加到 Workspace，并将该 Workspace 分配给 Agent：

```typescript
import { Agent } from '@mastra/core/agent'
import { Workspace } from '@mastra/core/workspace'
import { PlatformFilesystem } from '@mastra/platform-workspace'

const workspace = new Workspace({
  filesystem: new PlatformFilesystem({
    // accessToken, projectId, bucketName all fall back to env vars
  }),
})

const agent = new Agent({
  id: 'file-agent',
  name: 'File Agent',
  instructions: 'You are a research assistant that reads and writes reports.',
  model: '__GATEWAY_ANTHROPIC_MODEL_SONNET__',
  workspace,
})
```

### 读取和写入文件 {/* #reading-and-writing-files */}

对象键的每个路径段都会进行百分号编码，因此文件名中的 `?`、`#`、`%`、`&`、`+` 和空格在整个读写过程中都能保留：

```typescript
const fs = new PlatformFilesystem()

await fs.writeFile('/analyses/repo.md', markdown)
const content = await fs.readFile('/analyses/repo.md')
const entries = await fs.readdir('/analyses')
await fs.moveFile('/analyses/repo.md', '/analyses/repo-final.md')
```

### 只读模式 {/* #read-only-mode */}

传入 `readOnly: true` 可将存储桶以只读方式挂载。任何修改操作都会抛出 `WorkspaceReadOnlyError`：

```typescript
const fs = new PlatformFilesystem({ readOnly: true })

await fs.readFile('/analyses/repo.md') // ok
await fs.writeFile('/analyses/repo.md', 'x') // throws WorkspaceReadOnlyError
```

### 覆盖语义 {/* #overwrite-semantics */}

`writeFile` 支持 `overwrite: false`；如果目标已存在，则会抛出 `FileExistsError`。

`copyFile` 和 `moveFile` 始终会覆盖目标。向任一方法传入 `overwrite: false` 会抛出错误，而不会静默覆盖。

### 追加文件 {/* #appending-files */}

`appendFile` 采用读取、修改、写入的过程，并非原子操作。对同一路径的并发追加可能相互覆盖。并发写入时，请使用 `writeFile` 写入不同的键。

## 错误 {/* #errors */}

文件系统专属错误与标准 Workspace 错误类型一致：

* `FileNotFoundError`：路径不存在。由 `readFile`、`stat` 和 `deleteFile` 抛出（设置 `force: true` 时除外）。
* `FileExistsError`：调用 `writeFile` 时传入了 `overwrite: false`，且目标已存在。
* `WorkspaceReadOnlyError`：对只读文件系统执行了修改操作。

其他 Platform API 错误会抛出 `PlatformApiError`。结构为 `{ error: { message, type } }` 的响应会被解析为 `.code`（供程序读取的错误类型）和 `.proxyMessage`（供人阅读的错误信息）：

```typescript
import { FileNotFoundError } from '@mastra/core/workspace'
import { PlatformApiError } from '@mastra/platform-workspace'

try {
  await fs.readFile('/missing.txt')
} catch (err) {
  if (err instanceof FileNotFoundError) {
    // handle missing file
  } else if (err instanceof PlatformApiError) {
    if (err.code === 'authentication_error') {
      // refresh token
    }
    console.error(err.status, err.code, err.proxyMessage)
  }
}
```

`FileNotFoundError`、`FileExistsError` 和 `WorkspaceReadOnlyError` 是从 `@mastra/core/workspace` 重新导出的标准 Workspace 错误类型。`PlatformApiError` 则是 `@mastra/platform-workspace` 专有的错误类型。

如果响应体不是 JSON，例如负载均衡器返回的 HTML 502 页面，`code` 和 `proxyMessage` 都是 `undefined`。
