# 本地文件系统

**添加于：** `@mastra/core@1.1.0`

将文件存储在本地文件系统上的目录中。接口详情请参见[WorkspaceFilesystem Interface](/reference/workspace/filesystem).

## 用法 {/* #usage */}

添加一个`LocalFilesystem` to a workspace and assign it to an agent. The agent can then read, write, and manage files as part of its tasks:

```typescript
import { Agent } from '@mastra/core/agent'
import { Workspace, LocalFilesystem } from '@mastra/core/workspace'

const workspace = new Workspace({
  filesystem: new LocalFilesystem({
    basePath: './workspace',
  }),
})

const agent = new Agent({
  id: 'file-agent',
  model: '__GATEWAY_OPENAI_MODEL__',
  workspace,
})

// The agent now has filesystem tools available
const response = await agent.generate('List all files in the workspace')
```

## 方法 {/* #methods */}

### `init()` {/* #init */}

初始化文件系统。如果基本目录不存在，则创建它。

```typescript
await filesystem.init()
```

呼叫者`workspace.init()`.

### 延迟初始化 {/* #lazy-initialization */}

如果尚未初始化，LocalFilesystem 将在第一次操作时初始化，并自动创建基目录。呼唤`init()` explicitly is optional but can be useful to pre-create directories before the first operation.

### `destroy()` {/* #destroy */}

清理文件系统资源。

```typescript
await filesystem.destroy()
```

呼叫者`workspace.destroy()`.

### `setAllowedPaths(pathsOrUpdater)` {/* #setallowedpathspathsorupdater */}

在运行时更新允许的路径。接受新的路径数组（替换当前路径）或接收当前路径并返回新路径集的更新程序回调。

```typescript
// Set directly
filesystem.setAllowedPaths(['/home/user/.config'])

// Update with callback
filesystem.setAllowedPaths(prev => [...prev, '/home/user/documents'])

// Clear all allowed paths
filesystem.setAllowedPaths([])
```

## 路径分辨率 {/* #path-resolution */}

### 如何`basePath` works {/* #how-basepath-works */}

这`basePath` option sets the root directory for all file operations. Paths passed to methods like `readFile()` are resolved as follows:

* 解析相对路径`basePath`: `docs/guide.md` → `<basePath>/docs/guide.md`
* 使用`.` to refer to the root of `basePath`, for example `readdir('.')`
* 绝对路径被视为主机路径，而不是内部路径`basePath`. With the default `contained: true`, any absolute path that falls outside `basePath` and the configured `allowedPaths` is rejected with a `PermissionError`
* `~`扩展到用户的主目录，因此它也是主机路径，并且受到相同的包含规则的约束

```typescript
const filesystem = new LocalFilesystem({
  basePath: './workspace',
})

// Resolves to ./workspace/docs/guide.md
await filesystem.readFile('docs/guide.md')
await filesystem.readFile('./docs/guide.md')

// Root of basePath
await filesystem.readdir('.')

// Throws a PermissionError with the default contained: true
await filesystem.readFile('/docs/guide.md')
```

读取外部主机绝对路径`basePath`, add them to `allowedPaths` or set `contained: false`. Prefer `allowedPaths` when only a few external directories are needed.

```typescript
const filesystem = new LocalFilesystem({
  basePath: './workspace',
  allowedPaths: ['/home/user/shared-docs'],
})

await filesystem.readFile('/home/user/shared-docs/guide.md')
```

### 挂载的文件系统 {/* #mounted-filesystems */}

当一个`LocalFilesystem` is mounted in a workspace through `CompositeFilesystem`, workspace-facing paths include the mount prefix. For example, with a mount at `/workspace`, the workspace path `/workspace/report.md` is passed to the underlying filesystem as `report.md`, relative to its `basePath`. See [Filesystem mounts](/docs/sandbox/filesystem#mounts) for mount configuration.

### 相对路径和执行上下文 {/* #relative-paths-and-execution-context */}

当您使用相对路径时`basePath`, it resolves from `process.cwd()`. In Mastra projects, the cwd changes based on how you run your code:

|背景 |工作目录 |`./workspace` resolves to |
| - | - | - |
| `mastra dev` | `./src/mastra/public/` | `./src/mastra/public/workspace` |
| `mastra start` | `./.mastra/output/` | `./.mastra/output/workspace` |
| Direct script | Where you ran the command | Relative to that location |

当相同的相对路径解析到不同的位置时，这可能会导致混乱。

### 推荐：使用绝对路径 {/* #recommended-use-absolute-paths */}

为了使所有执行上下文的路径保持一致，请使用带有绝对路径的环境变量：

```typescript
import { LocalFilesystem } from '@mastra/core/workspace'

const filesystem = new LocalFilesystem({
  basePath: process.env.WORKSPACE_PATH!,
})
```

放`WORKSPACE_PATH` in your environment to an absolute path like `/home/user/my-project/workspace`. It ensures the workspace path is consistent regardless of how you run your code.
