# LocalSandbox

**引入版本：** `@mastra/core@1.1.0`

在本地系统上执行命令。接口详情请参见 [WorkspaceSandbox 接口](/reference/workspace/sandbox)。

## 用法 {/* #usage */}

将 `LocalSandbox` 添加到 Workspace，并将该 Workspace 分配给 Agent。随后，Agent 就可以在执行任务时运行 shell 命令：

```typescript
import { Agent } from '@mastra/core/agent'
import { Workspace, LocalFilesystem, LocalSandbox } from '@mastra/core/workspace'

const workspace = new Workspace({
  filesystem: new LocalFilesystem({ basePath: './workspace' }),
  sandbox: new LocalSandbox({
    workingDirectory: './workspace',
    env: {
      NODE_ENV: 'development',
    },
  }),
})

const agent = new Agent({
  id: 'dev-agent',
  model: '__GATEWAY_OPENAI_MODEL__',
  workspace,
})

// The agent now has the execute_command tool available
const response = await agent.generate('Run npm install')
```

### 自动启动行为 {/* #auto-start-behavior */}

如果 `LocalSandbox` 尚未运行，它会在首次执行命令时自动启动。您也可以在应用启动时调用 `workspace.init()`，提前启动 Sandbox，避免首次执行命令时的延迟。

## 路径解析 {/* #path-resolution */}

### 相对路径和执行上下文 {/* #relative-paths-and-execution-context */}

如果为 `workingDirectory` 指定相对路径，该路径会相对于 `process.cwd()` 解析。在 Mastra 项目中，当前工作目录会因代码的运行方式而异：

| 运行方式 | 当前工作目录 | `./workspace` 解析为 |
| - | - | - |
| `mastra dev` | `./src/mastra/public/` | `./src/mastra/public/workspace` |
| `mastra start` | `./.mastra/output/` | `./.mastra/output/workspace` |
| 直接运行脚本 | 运行命令时所在的目录 | 该目录下的 `workspace` |

因此，同一个相对路径可能解析到不同的位置，容易造成困惑。

### 推荐：使用绝对路径 {/* #recommended-use-absolute-paths */}

为了使所有执行上下文的路径保持一致，请使用带有绝对路径的环境变量：

```typescript
import { LocalSandbox } from '@mastra/core/workspace'

const sandbox = new LocalSandbox({
  workingDirectory: process.env.WORKSPACE_PATH!,
})
```

将环境变量 `WORKSPACE_PATH` 设置为绝对路径，例如 `/home/user/my-project/workspace`。这样，无论以何种方式运行代码，命令都会在同一目录中执行。

## Windows shell {/* #windows-shell */}

`executeCommand(command, args)` 会按 POSIX shell 的规则为 `args` 加引号。在未启用隔离的原生 Windows 环境中，`LocalSandbox` 会通过 Git Bash 而非 `cmd.exe` 执行这些命令。它依次查找 `MASTRA_WINDOWS_SHELL` 指定的 shell、命令的 `PATH` 中 `git.exe` 旁的 `bin\bash.exe`，以及 `%ProgramFiles%\Git\bin\bash.exe`。如果找不到 shell，命令会回退到 `cmd.exe`，而后者无法解析按 POSIX 规则加引号的参数。不带 `args`、以单个字符串传入的命令始终通过 `cmd.exe` 执行；调用 `cmd`、`powershell` 或 `pwsh` 的 argv 形式命令也是如此。在 Git Bash 下，`LocalSandbox` 会设置 `MSYS_NO_PATHCONV=1` 和 `MSYS2_ARG_CONV_EXCL=*`，使 `/F` 等选项及 Windows 路径原样传给原生 Tool。

安装 [Git for Windows](https://git-scm.com/download/win) 即可获得 Git Bash。层级较深的仓库路径可能超过 Windows 的路径长度限制，因此还应运行 `git config --global core.longpaths true`。如果希望 argv 形式的命令继续通过 `cmd.exe` 执行，例如调用 `dir` 等 `cmd.exe` 内置命令，请将 `MASTRA_WINDOWS_SHELL` 设为 `cmd.exe` 的完整路径。

## 后台进程 {/* #background-processes */}

`LocalSandbox` 内置进程管理器，用于启动和管理后台进程。这些进程通过 `child_process.spawn` 作为本地计算机上的子进程运行。

```typescript
const sandbox = new LocalSandbox({ workingDirectory: './workspace' })
await sandbox.start()

// Spawn a background process
const handle = await sandbox.processes.spawn('node server.js')

// Read output, send stdin, signal EOF, and wait for completion
console.log(handle.stdout)
await handle.sendStdin('input\n')
await handle.closeStdin()
await handle.wait()
```

启用原生隔离（`seatbelt` 或 `bwrap`）后，启动的进程也会使用相同的隔离后端。

完整 API 请参见 [SandboxProcessManager 参考文档](/reference/workspace/process-manager)。

## 静态方法 {/* #static-methods */}

### `detectIsolation()` {/* #detectisolation */}

检测当前平台的最佳可用隔离后端。

```typescript
const detection = LocalSandbox.detectIsolation()
// { backend: 'seatbelt', available: true, message: 'Seatbelt available on macOS' }
```

## 环境隔离 {/* #environment-isolation */}

默认情况下，`LocalSandbox` 的环境中只包含 `PATH`。这样既能运行命令，又能避免意外泄露 API 密钥等机密信息。

```typescript
// Default: only PATH is available (commands work, secrets protected)
const secureSandbox = new LocalSandbox({
  workingDirectory: './workspace',
})

// Explicit: pass specific variables
const sandbox = new LocalSandbox({
  workingDirectory: './workspace',
  env: {
    NODE_ENV: 'development',
    API_URL: 'https://api.example.com',
  },
})

// Full access (use with caution)
const devSandbox = new LocalSandbox({
  workingDirectory: './workspace',
  env: process.env,
})
```

## 原生操作系统 Sandbox {/* #native-os-sandboxing */}

`LocalSandbox` 支持原生操作系统级 Sandbox，可提供额外的安全保护：

* **macOS**：使用 Seatbelt（`sandbox-exec`）隔离文件系统和网络
* **Linux**：使用 Bubblewrap（`bwrap`）进行命名空间隔离

```typescript
// Detect the best available backend for this platform
const detection = LocalSandbox.detectIsolation()
console.log(detection)
// { backend: 'seatbelt', available: true, message: '...' }

// Enable native sandboxing
const sandbox = new LocalSandbox({
  workingDirectory: './workspace',
  isolation: 'seatbelt', // or 'bwrap' on Linux
  nativeSandbox: {
    allowNetwork: false, // Block network access (default)
    readWritePaths: ['/tmp/extra'], // Additional writable paths
  },
})
```

启用隔离时：

* 文件写入仅限于 Workspace 目录、`readWritePaths` 和临时位置。在 macOS（seatbelt）上，还允许写入 `/private/tmp`、`/var/folders` 和 `/private/var/folders`。在 Linux（bubblewrap）上，`/tmp` 是 Sandbox 内部的私有 tmpfs，不会写入主机。
* 文件读取权限取决于隔离后端。在 macOS（seatbelt）上，可以读取所有位置，以满足系统可执行文件的访问需求。在 Linux（bubblewrap）上，生成的策略仅暴露选定的系统路径（如 `/usr`、`/lib`、`/bin` 和必要的 `/etc` 文件）、`readOnlyPaths`、`readWritePaths` 以及 Workspace。如果 `allowSystemBinaries` 不为 `false`，Node.js 所在目录、`/opt` 和 `/snap` 也可见。其他主机路径无法访问。如果设置了 `bwrapArgs`，它会替换生成的策略，因此只有您提供的参数决定哪些路径可见。
* 默认禁止访问网络。
* 进程隔离可防止 Sandbox 中的进程影响主机系统。

### Sandbox 配置文件的位置 {/* #sandbox-profile-location */}

在 macOS 上使用 seatbelt 隔离时，`LocalSandbox` 会在 `process.cwd()` 下的 `.sandbox-profiles/` 目录中生成配置文件，与工作目录分开：

```text
project/
├── .sandbox/                      # Default working directory (sandboxed)
│   └── ... files created by sandbox
├── .sandbox-profiles/             # Seatbelt profiles (outside sandbox)
│   └── seatbelt-a1b2c3d4.sb       # Hash based on workspace + config
└── ... your project files
```

配置文件名是 Workspace 路径和配置的哈希值。因此，配置相同的 Sandbox 会共享配置文件，配置不同的 Sandbox 则使用不同的文件，避免多个 Sandbox 同时运行时发生冲突。

将配置文件与工作目录分开，可防止 Sandbox 中的进程读取或修改自己的安全配置文件。配置文件在 Sandbox 启动时创建，在销毁时清除。
