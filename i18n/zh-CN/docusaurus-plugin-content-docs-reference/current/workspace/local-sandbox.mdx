# 本地沙盒

**添加于：** `@mastra/core@1.1.0`

在本地系统上执行命令。接口详情请参见[WorkspaceSandbox interface](/reference/workspace/sandbox).

## 用法 {/* #usage */}

添加一个`LocalSandbox` to a workspace and assign it to an agent. The agent can then execute shell commands as part of its tasks:

```typescript
import { Agent } from '@mastra/core/agent'
import { Workspace, LocalFilesystem, LocalSandbox } from '@mastra/core/workspace'

const workspace = new Workspace({
  filesystem: new LocalFilesystem({ basePath: './workspace' }),
  sandbox: new LocalSandbox({
    workingDirectory: './workspace',
    env: {
      NODE_ENV: 'development',
    },
  }),
})

const agent = new Agent({
  id: 'dev-agent',
  model: '__GATEWAY_OPENAI_MODEL__',
  workspace,
})

// The agent now has the execute_command tool available
const response = await agent.generate('Run npm install')
```

### 自动启动行为 {/* #auto-start-behavior */}

`LocalSandbox`如果尚未运行，则在第一次执行命令时自动启动。您还可以通过调用显式启动Sandbox`workspace.init()` at application startup to avoid first-command latency.

## 路径分辨率 {/* #path-resolution */}

### 相对路径和执行上下文 {/* #relative-paths-and-execution-context */}

当您使用相对路径时`workingDirectory`, it resolves from `process.cwd()`. In Mastra projects, the cwd changes based on how you run your code:

|背景 |工作目录 |`./workspace` resolves to |
| - | - | - |
| `mastra dev` | `./src/mastra/public/` | `./src/mastra/public/workspace` |
| `mastra start` | `./.mastra/output/` | `./.mastra/output/workspace` |
| Direct script | Where you ran the command | Relative to that location |

当相同的相对路径解析到不同的位置时，这可能会导致混乱。

### 推荐：使用绝对路径 {/* #recommended-use-absolute-paths */}

为了使所有执行上下文的路径保持一致，请使用带有绝对路径的环境变量：

```typescript
import { LocalSandbox } from '@mastra/core/workspace'

const sandbox = new LocalSandbox({
  workingDirectory: process.env.WORKSPACE_PATH!,
})
```

放`WORKSPACE_PATH` in your environment to an absolute path like `/home/user/my-project/workspace`. It ensures commands run from a consistent directory regardless of how you run your code.

## Windows外壳 {/* #windows-shell */}

`executeCommand(command, args)`引号`args` for a POSIX shell. On native Windows without isolation, `LocalSandbox` runs these commands through Git Bash instead of `cmd.exe`. It uses the shell in `MASTRA_WINDOWS_SHELL` if set, then the `bin\bash.exe` next to `git.exe` on the command's `PATH`, then `%ProgramFiles%\Git\bin\bash.exe`. If no shell is found, commands fall back to `cmd.exe`, which can't parse POSIX-quoted arguments. Commands passed as a single string without `args` always run through `cmd.exe`，就像 argv 调用一样`cmd`, `powershell`， 和`pwsh`。在 Git Bash 下，`LocalSandbox`套`MSYS_NO_PATHCONV=1`和`MSYS2_ARG_CONV_EXCL=*`所以切换就像`/F`Windows 路径到达本机Tool时保持不变。

安装[Git for Windows](https://git-scm.com/download/win) to get Git Bash. Deep repository paths can exceed the Windows path limit, so also run `git config --global core.longpaths true`. To keep running argv commands through `cmd.exe`, for example to call `cmd.exe` builtins like `dir`, set `MASTRA_WINDOWS_SHELL` to the full path of `cmd.exe`.

## 后台进程 {/* #background-processes */}

`LocalSandbox`包括一个内置的进程管理器，用于生成和管理后台进程。进程在本地计算机上作为子进程运行，使用`child_process.spawn`.

```typescript
const sandbox = new LocalSandbox({ workingDirectory: './workspace' })
await sandbox.start()

// Spawn a background process
const handle = await sandbox.processes.spawn('node server.js')

// Read output, send stdin, signal EOF, and wait for completion
console.log(handle.stdout)
await handle.sendStdin('input\n')
await handle.closeStdin()
await handle.wait()
```

当启用本机隔离时（`seatbelt` or `bwrap`), spawned processes are also wrapped with the same isolation backend.

看[`SandboxProcessManager` reference](/reference/workspace/process-manager) for the full API.

## 静态方法 {/* #static-methods */}

### `detectIsolation()` {/* #detectisolation */}

检测当前平台的最佳可用隔离后端。

```typescript
const detection = LocalSandbox.detectIsolation()
// { backend: 'seatbelt', available: true, message: 'Seatbelt available on macOS' }
```

## 环境隔离 {/* #environment-isolation */}

默认情况下，`LocalSandbox` only includes `PATH` in the environment. Commands can run without accidental exposure of API keys and secrets.

```typescript
// Default: only PATH is available (commands work, secrets protected)
const secureSandbox = new LocalSandbox({
  workingDirectory: './workspace',
})

// Explicit: pass specific variables
const sandbox = new LocalSandbox({
  workingDirectory: './workspace',
  env: {
    NODE_ENV: 'development',
    API_URL: 'https://api.example.com',
  },
})

// Full access (use with caution)
const devSandbox = new LocalSandbox({
  workingDirectory: './workspace',
  env: process.env,
})
```

## 本机操作系统Sandbox {/* #native-os-sandboxing */}

`LocalSandbox`支持本机操作系统级Sandbox以提高安全性：

* **macOS**：使用安全带（`sandbox-exec`) for filesystem and network isolation
* **Linux**：使用气泡膜（`bwrap`) for namespace isolation

```typescript
// Detect the best available backend for this platform
const detection = LocalSandbox.detectIsolation()
console.log(detection)
// { backend: 'seatbelt', available: true, message: '...' }

// Enable native sandboxing
const sandbox = new LocalSandbox({
  workingDirectory: './workspace',
  isolation: 'seatbelt', // or 'bwrap' on Linux
  nativeSandbox: {
    allowNetwork: false, // Block network access (default)
    readWritePaths: ['/tmp/extra'], // Additional writable paths
  },
})
```

启用隔离时：

* 文件写入仅限于Workspace目录，`readWritePaths`, and temporary locations. On macOS (seatbelt), writes are also allowed under `/private/tmp`, `/var/folders`, and `/private/var/folders`. On Linux (bubblewrap), `/tmp` is a private in-sandbox tmpfs that isn't written to the host.
* 文件读取取决于后端。在 macOS（安全带）上，任何地方都允许读取（系统二进制文件需要）。在 Linux (bubbblewrap) 上，生成的策略仅公开选定的系统路径（例如`/usr`, `/lib`, `/bin`, and essential `/etc` files), `readOnlyPaths`, `readWritePaths`, and the workspace. When `allowSystemBinaries` isn't `false`, the Node.js directory, `/opt`, and `/snap` are also visible. Other host paths aren't accessible. If you set `bwrapArgs`, it replaces the generated policy, so your arguments alone determine what's visible.
* 默认情况下阻止网络访问
* 进程隔离防止影响主机系统

### Sandbox配置文件位置 {/* #sandbox-profile-location */}

在 macOS 上使用安全带隔离时，`LocalSandbox` generates a profile file in a `.sandbox-profiles/` folder in `process.cwd()`, separate from the working directory:

```text
project/
├── .sandbox/                      # Default working directory (sandboxed)
│   └── ... files created by sandbox
├── .sandbox-profiles/             # Seatbelt profiles (outside sandbox)
│   └── seatbelt-a1b2c3d4.sb       # Hash based on workspace + config
└── ... your project files
```

配置文件名是工作空间路径和配置的哈希值，因此具有相同设置的Sandbox共享相同的配置文件，而不同的配置则获得单独的文件。这可以防止同时运行多个Sandbox时发生冲突。

这种分离可以防止沙盒进程读取或修改自己的安全配置文件。配置文件在Sandbox启动时创建，并在销毁时清除。
