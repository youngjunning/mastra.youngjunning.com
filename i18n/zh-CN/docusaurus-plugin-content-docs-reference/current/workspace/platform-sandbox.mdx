# 平台Sandbox

用于在 Mastra 平台环境中配置Sandbox的客户端。每个`PlatformSandbox`实例拥有一个远程Sandbox：`start()`规定它，`executeCommand()`与它对抗，并且`destroy()`把它撕下来。构建额外的实例来拥有额外的远程Sandbox。使用`clone()`从配置的模板派生它们（请参阅[克隆](#cloning-for-a-fleet-of-sandboxes)).

Sandbox从预构建的提供程序模板启动，其中已安装 Python 3、Node 22、TypeScript、tsx 和常见构建Tool。您还可以构建一个[reusable template](#reusable-templates) with the portable `Template()` builder. Pass a stable `id` to opt into [checkpoint recovery](#checkpoint-recovery) so a new sandbox boots from the previous one's filesystem.

相关Provider：[`RailwaySandbox`](/integrations/sandboxes/railway) for self-hosted Railway sandboxes, [`LocalSandbox`](/reference/workspace/local-sandbox) for local sandboxes.

：：：笔记

接口详情请参见[WorkspaceSandbox interface](/reference/workspace/sandbox).

## 安装 {/* #installation */}

```bash npm2yarn
npm install @mastra/platform-workspace
```

配置平台凭据。访问令牌、项目 ID 和环境 ID 会回退到环境变量，因此 Mastra 平台部署可以传递零个构造函数选项。

<Tabs>
  <TabItem value="env-file" label=".env file">

    ```bash
    MASTRA_PLATFORM_ACCESS_TOKEN=your-platform-access-token
    MASTRA_PROJECT_ID=your-project-id
    MASTRA_ENVIRONMENT_ID=your-environment-id
    ```
  </TabItem>

  <TabItem value="constructor" label="Constructor">
    ```typescript
    new PlatformSandbox({
      accessToken: 'your-platform-access-token',
      projectId: 'your-project-id',
      environmentId: 'your-environment-id',
    })
    ```
  </TabItem>
</Tabs>

在 Mastra 平台部署中，`MASTRA_PLATFORM_ACCESS_TOKEN`, `MASTRA_PROJECT_ID`, and `MASTRA_ENVIRONMENT_ID` are injected automatically, so the constructor can be called with no options. For local development, `MASTRA_PLATFORM_ACCESS_TOKEN` can contain an `sk_` API token from your organization's settings page under **API Tokens**.

Sandbox提供者从构造函数解析`sandboxProvider` option, then `SANDBOX_PROVIDER`, then defaults to `e2b`.

## 用法 {/* #usage */}

添加一个`PlatformSandbox` to a workspace and assign it to an agent:

```typescript
import { Agent } from '@mastra/core/agent'
import { Workspace } from '@mastra/core/workspace'
import { PlatformSandbox } from '@mastra/platform-workspace'

const workspace = new Workspace({
  sandbox: new PlatformSandbox({
    // accessToken, projectId, environmentId all fall back to env vars
    idleTimeoutMinutes: 30,
  }),
})

const agent = new Agent({
  id: 'code-agent',
  name: 'Code Agent',
  instructions: 'You are a coding assistant working in this workspace.',
  model: '__GATEWAY_ANTHROPIC_MODEL_SONNET__',
  workspace,
})

const response = await agent.generate(
  'Print "Hello, world!" and show the current working directory.',
)

console.log(response.text)
```

### 专用网络 {/* #private-networking */}

放`networkIsolation` to `PRIVATE` to join the environment's private network and reach other services running in the same Mastra Platform environment:

```typescript
const workspace = new Workspace({
  sandbox: new PlatformSandbox({
    networkIsolation: 'PRIVATE',
  }),
})
```

默认`ISOLATED` mode allows outbound internet access only, with no private network connectivity.

### 公共端口 {/* #public-ports */}

默认情况下，端口是私有的：打开一个端口需要登录预览链接。放`publicPorts` to let anyone with a port's URL reach it, for example a webhook receiver:

```typescript
const workspace = new Workspace({
  sandbox: new PlatformSandbox({
    publicPorts: true,
  }),
})
```

无论哪种方式，端口 URL 都是相同的。仅是否要求登录更改。该设置在创建Sandbox时是固定的，因此在重新附加时传递该设置不会对该Sandbox进行任何更改。克隆使用`publicPorts` option you passed, not the reattached sandbox's setting.

### 重新连接到正在运行的Sandbox {/* #reattaching-to-a-running-sandbox */}

通过现有的`sandboxId` to reattach to a live sandbox instead of creating a new one:

```typescript
const sandbox = new PlatformSandbox({
  sandboxId: 'sbx_abc123',
})
await sandbox.start()

const result = await sandbox.executeCommand('cat', ['/workspace/state.json'])
```

什么时候`sandboxId` is set, `environmentId` isn't required because the sandbox already exists.

从以下位置读取正在运行的Sandbox的平台 ID`sandboxId` property after `start()` and persist it for the next reattach. The property is `undefined` until the sandbox has started in the current process. The option passed to the constructor is a hint for `start()`. Before `start()` runs, `getInfo()` answers from local state and doesn't ask the platform about the hint. Under the default `reattach: 'best-effort'`, if the platform no longer knows the id, `start()` falls through to a fresh provision keyed by the sandbox's logical `id`. That fallback needs `environmentId` (or `MASTRA_ENVIRONMENT_ID`), so pass it whenever a hint might be stale; without it, `start()` throws `environmentId is required`.

`start()`报告`{ outcome: 'connected' }` on reattach and `{ outcome: 'created' }` on a fresh provision (including a checkpoint-recovered boot, which is a new VM even when its filesystem was restored). See [`start()`](/reference/workspace/sandbox#start) for the shared contract.

当一个新的Sandbox默默地失去你的应用程序所依赖的状态时，设置`reattach: 'required'`:

```typescript
const sandbox = new PlatformSandbox({
  sandboxId: 'sbx_abc123',
  reattach: 'required',
})
```

和`reattach: 'required'`, a reattach target the platform reports as missing (404), gone (410), or destroyed rejects `start()` with a `SandboxError` whose `code` is `SANDBOX_REATTACH_FAILED`, and no sandbox is provisioned. The error's `details` include `provider`, `sandboxId`, `logicalId` (the sandbox's logical `id`), and `reason`. Other errors propagate unchanged. To start fresh, clear your persisted `sandboxId` and construct the sandbox without it. Clones inherit the `reattach` setting.

### 可重复使用的模板 {/* #reusable-templates */}

将可重用的模板构建器传递给`PlatformSandbox`. A fresh sandbox start sends the serialized definition to Platform, which content-addresses it and starts or reuses the provider build. Sandbox creation never blocks on a build. When the exact template isn't built yet, Platform boots the sandbox on the best available fallback and rebuilds the requested template in the background. The fallback is a same-lineage stale template with matching resources when one exists, otherwise the provider base template:

```typescript
import { PlatformSandbox, Template } from '@mastra/platform-workspace'

const commitSha = process.env.REPOSITORY_COMMIT_SHA!
const template = Template()
  .cpuCount(4)
  .memoryMB(8_192)
  .setWorkdir('/workspace/repo')
  .setEnvs({ BUILD_CONFIG_MARKER: 'template-v1' })
  .aptInstall(['git', 'jq'])
  .runCmd('git clone https://github.com/mastra-ai/mastra.git /workspace/repo')
  .runCmd(`git checkout ${commitSha}`)
  .runCmd('pnpm install --frozen-lockfile')

const sandbox = new PlatformSandbox({
  environmentId: 'env_abc',
  sandboxProvider: 'e2b',
  template,
})
await sandbox.start()
```

`Template()`支持`cpuCount`, `memoryMB`, `docker`, `runCmd`, `setWorkdir`, `setEnvs`, `aptInstall`, `pipInstall`, and `npmInstall`. Platform serializes the builder internally and computes the content hash. Call `await template.build(options)` to start or reuse that provider build without provisioning a sandbox. It returns `ready`, `pending`, or `failed`, with the template ID and an optional retry hint or error.

对于E2B来说，`cpuCount()` and `memoryMB()` set the template build resources inherited by sandboxes created from the exact template or a resource-matched stale template. Both methods accept a positive safe integer. They default to 2 CPUs and 1,024 MB. Resource setters use last-value-wins semantics, and their effective values are part of the content identity. Omitting both setters is equivalent to explicitly selecting the defaults. If a pending build falls back to the provider base, that sandbox may use the provider's default resources. Check `templatePending` to detect this case.

`docker()`在 E2B 模板中安装 Docker Engine 和 Compose。该守护进程在第一次使用 Docker 时启动，因此从不使用它的Sandbox无需付费。 Docker 仅在启用时才是内容身份的一部分，因此没有它的模板会保留其 ID。 Docker 至少使用 2,048 MB 内存。

Railway 将命令、工作目录、环境和包操作转换为 Railway 模板指令。铁路目前忽视`cpuCount()` and `memoryMB()` because its sandbox template API doesn't expose matching resource settings.

对于公共 GitHub 存储库，`createRepoTemplate()` can resolve and build the commit-pinned definition lazily when `start()` needs a fresh sandbox:

```typescript
import { createRepoTemplate, PlatformSandbox } from '@mastra/platform-workspace'

const sandbox = new PlatformSandbox({
  environmentId: 'env_abc',
  template: createRepoTemplate({
    getRepositoryAccess: async () => ({ cloneUrl: 'https://github.com/mastra-ai/mastra.git' }),
    setupCommand: 'pnpm install --frozen-lockfile',
    memoryMB: 2048,
  }),
})
await sandbox.start()
```

`createRepoTemplate()`接受相同的`cpuCount`, `memoryMB`, and `docker` settings as the `Template()` builder methods, as plain options. They carry the identity and stale-fallback semantics described above. Omit them for the provider defaults.

`setupCommand`也接受一个数组。每个条目都作为其自己的缓存构建步骤运行。`workingDirectory` sets the cwd for the build and the sandbox, and the repository is cloned to `<workingDirectory>/<repo>`. `buildEnv` passes environment variables to the build steps only. They never enter the serialized definition. `buildEnvRevision` is an opaque id written ahead of the clone and setup steps. A new revision rebuilds them. Change it whenever `buildEnv` changes and never derive it from the values.

`getRepositoryAccess`镜像 Factory Sandbox上下文携带的解析器，因此主机可以直接传递其上下文；当它不存在时，`createRepoTemplate()` returns `undefined` and the sandbox boots the provider default. The resolver skips reattachment to an existing `sandboxId`; on a fresh start, it resolves the repository's default-branch head before Platform starts or reuses the corresponding template build. If the repository head can't be resolved or the provider build fails, sandbox creation continues with the provider's default template so runtime setup can perform a cold checkout. For private repositories, the short-lived authorization token is sent as an ephemeral build environment value that stays out of the serialized definition and the persisted template record. It has no effect on content identity.

#### 一个模板中的多个存储库 {/* #several-repositories-in-one-template */}

经过`repos` instead of `getRepositoryAccess` to clone several repositories into one sandbox, each with its own access resolver and `setupCommand` (a string or an array, each entry its own build step):

```typescript
const template = createRepoTemplate({
  repos: [
    {
      getRepositoryAccess: async () => ({ cloneUrl: 'https://github.com/mastra-ai/mastra' }),
      setupCommand: 'pnpm install --frozen-lockfile',
    },
    {
      getRepositoryAccess: async () => ({
        cloneUrl: 'https://github.com/mastra-ai/template-docs-expert',
      }),
      setupCommand: 'npm install',
    },
  ],
  workspaceSetupCommand: 'npm install --global @mastra/mcp-docs-server',
  continueOnSetupFailure: true,
  workingDirectory: '/home/user/repos',
})
```

每个存储库都被克隆到`<workingDirectory>/<repo>`. Public repositories are built before private ones, keeping the caller's order within each group. Private credentials are ephemeral build envs visible to every build step, so any repository's setup command can read every other repository's token: only list repositories whose setup commands you trust together.

`workspaceSetupCommand`设置每个存储库后在工作目录中运行。`continueOnSetupFailure` (default `false`) lets a failing setup command record its repository in `.mastra-sandbox/setup-failed` and continue instead of failing the build.

标记告诉会话图像已经运行了什么：`.mastra-sandbox/repos/<repo>` per repository and `.mastra-sandbox/workspace-setup` after the workspace commands, all under the working directory. With `continueOnSetupFailure`, check `.mastra-sandbox/setup-failed` first.

工作目录和有序存储库列表形成系列密钥，因此更改会启动一个冷启动的新系列，直到其第一个构建准备就绪，而对设置命令或凭据的编辑则保留在热系列中。如果任何条目的访问权限无法解决，模板将降级为仅资源，直到下一次解决为止。无法解析头部的存储库将被取消固定克隆，而其他存储库则保留其固定。

`createRepoTemplate()`还附加了一个独立于提交的`family` key to the definition (`repo:<cloneUrl>:<workingDirectory>/<repo>` for one repository, `repos:<hash>` over the working directory and the ordered clone URLs for a list). `family` groups successive builds of the "same thing", so every commit of the same repository belongs to the same family. Platform uses it to find a prior ready build in the same family and boot the new commit on that warm filesystem while the exact commit template builds in the background. For E2B, stale lookup is also partitioned by the effective CPU and memory settings so a fallback can't silently change the requested machine size. Callers using the raw `Template()` builder can attach their own family key with `.withFamily(key)` (any non-empty string up to 200 characters). Omit it to opt out of family fallback. The family key never influences the content-addressed template identity: two definitions that differ only in `family` share the same cache slot.

平台将构建状态存储在所选环境和Provider内的定义的服务器派生内容哈希下。

#### 观察待处理的模板构建 {/* #observing-a-pending-template-build */}

当Sandbox在后备模板（同一系列的资源匹配的先前成员或Provider基础）上启动时，平台响应包括`templatePending` field that `PlatformSandbox` surfaces for observability:

```typescript
await sandbox.start()
if (sandbox.templatePending) {
  // The sandbox is running on a fallback template.
  // A later start() of a sandbox with the same template definition
  // will pick up the exact template once the background build finishes.
  console.log('exact template still baking:', sandbox.templatePending.templateId)
}
```

`templatePending`当Sandbox在确切的模板上启动时未定义。`PlatformSandbox` never re-executes template operations inside a running sandbox. Reconcile any commit-specific filesystem state in your own runtime setup (for example, an `onStart` hook that runs `git fetch && git checkout <sha>`) exactly as you would with a fresh template. Reprovision on a later `start()` to pick up the ready exact template.

：：：警告

默认情况下，每个模板操作都会被序列化并发送到平台，平台根据所选提供程序的功能对其进行解释。使用`setEnvs(values, { ephemeral: true })` for short-lived build credentials: these values are sent separately and excluded from both content identity and persistence. They're unavailable at runtime and take precedence over serialized environment values with the same key. Supply them again on every build or fresh provision that may need to build. On Railway, the provider cache includes the transient build variables. Rotating a value can therefore trigger another provider build even though the Platform template ID stays stable.

### 检查点恢复 {/* #checkpoint-recovery */}

构造函数`id` (explicit or auto-generated) is sent to the platform on `POST /sandbox` as an advisory recovery key:

* 如果平台认可`id` from a previous session, the new sandbox boots from the most recent checkpoint of that earlier sandbox's filesystem instead of the base recipe.
* 如果`id` isn't recognised, the platform starts a fresh sandbox from the base recipe. Auto-generated ids never match, so omitting `id` disables checkpoint recovery.

通过一个稳定`id` to preserve a sandbox's filesystem across sessions or across a `destroy()`/`start()` cycle:

```typescript
const sandbox = new PlatformSandbox({
  id: `project-${projectId}`,
})
await sandbox.start() // Boots from the most recent checkpoint for this id, or fresh if unknown
```

检查点恢复比`sandboxId` reattachment. Reattaching (via `sandboxId`) rejoins the exact live sandbox and its running processes. Checkpoint recovery constructs a brand new sandbox and restores its filesystem from the latest checkpoint the platform captured for the previous sandbox with that `id`. Running processes and any filesystem writes made after the last checkpoint aren't restored.

称呼`snapshot()` after a filesystem update to capture the configured recovery checkpoint immediately. It resolves without capturing when the sandbox has no caller-provided `id` or isn't running.

```typescript
await sandbox.snapshot()
```

每个`id` maps to one independent filesystem. Reusing the same `id` across unrelated sandboxes causes the platform to boot them from each other's checkpoint.

放`seedCheckpointName` to provide a boot-only fallback when the checkpoint for `id` doesn't exist yet. The platform restores the checkpoint for `id` first when both exist. Later snapshots continue writing to the checkpoint for `id`. The seed remains unchanged.

```typescript
const sandbox = new PlatformSandbox({
  id: `project-session-${sessionId}`,
  seedCheckpointName: 'project-base',
})
```

### 克隆一组Sandbox {/* #cloning-for-a-fleet-of-sandboxes */}

`clone()`返回一个独立的兄弟姐妹`PlatformSandbox` that inherits credentials and defaults (access token, project, environment, provider, template, network isolation, timeout, instructions, env, idle timeout, public ports) with per-instance overrides. The returned sandbox is unstarted and provisions on its own `start()`, so `clone()` performs no I/O:

```typescript
const template = new PlatformSandbox({
  networkIsolation: 'PRIVATE',
  idleTimeoutMinutes: 30,
})

const perProject = template.clone({ id: `project-${projectId}` })
await perProject.start()
```

结合`clone()` with a stable `id` per clone to opt each clone into [checkpoint recovery](#checkpoint-recovery) independently.

### 执行命令 {/* #executing-commands */}

`executeCommand`在远程Sandbox上运行命令并返回其输出。经过`args` to have arguments safely shell-quoted:

```typescript
const result = await sandbox.executeCommand('python', ['analyze.py'], {
  timeout: 30_000,
  cwd: '/workspace',
  env: { INPUT: 'repo' },
})

console.log(result.stdout)
console.log(result.exitCode)
```

：：：警告

这`command` argument is a shell string and is concatenated verbatim into the remote shell. This lets you use pipes, redirects, and chaining (`ls -la | grep foo`) but means untrusted input must be passed through `args` (safely quoted) or shell-quoted by the caller. Untrusted `command` values allow arbitrary shell execution on the sandbox.

### 后台进程 {/* #background-processes */}

`sandbox.processes`在后台运行命令。当它们运行时输出流，您可以列出、附加和停止它们：

```typescript
const handle = await sandbox.processes.spawn('pnpm dev', {
  onStdout: data => console.log(data),
})

// Everything running in the sandbox, plus exited processes not read yet
const running = await sandbox.processes.list()

await handle.kill()
```

流程没有时间限制，除非您通过`timeout` to `spawn()` or the constructor. Call `get(pid)` to attach to a process this manager didn't start, for example after your app restarts. Output written before attaching isn't available.

长时间运行的进程的输出流会定期重新连接，并且进程会通过它继续运行。重新连接期间写入的输出会丢失，并且在其流重新连接时退出的进程会报告退出代码`1` from `wait()` instead of its real exit code.

### 端口 URL {/* #port-urls */}

`sandbox.networking.getPortUrl(port)`

```typescript
await sandbox.processes.spawn('pnpm dev --host 0.0.0.0 --port 3000')

const url = await sandbox.networking?.getPortUrl(3000)
// https://3000-<sandbox id>.sandbox.us.mastra.cloud/
```

默认情况下，端口是私有的：Sandbox组织成员登录 Mastra 后，会在浏览器中打开 URL。和[`publicPorts: true`](#public-ports), anyone with the URL can open it without signing in. You can share it, since it never expires, and opening it wakes a paused sandbox.

`networking`是`undefined` on a sandbox whose ports can't be opened. `getPortUrl()` returns `null` without starting the sandbox when the sandbox isn't running or has been destroyed, for a port that isn't a whole number from 1 to 65535, and for the sandbox's reserved control port. Other platform errors, such as an invalid access token, are thrown.

您控制的浏览器（例如Agent的浏览器）无法登录。`getPortAuthCookie(port)` returns a cookie that lets it open the port's URL for an hour without signing in. Don't share the cookie: anyone holding it can open the port.

```typescript
const cookie = await sandbox.getPortAuthCookie(3000)
if (cookie) await browserContext.addCookies([cookie])
```

## 错误 {/* #errors */}

平台 API 故障增加`PlatformApiError`. Structured `{ error: { message, type } }` responses are parsed into `.code` (machine-readable kind) and `.proxyMessage` (human string); the raw response body stays available on `.body`:

```typescript
import { PlatformApiError } from '@mastra/platform-workspace'

try {
  await sandbox.executeCommand('cat', ['/missing.txt'])
} catch (err) {
  if (err instanceof PlatformApiError) {
    if (err.code === 'not_found') {
      // handle missing resource
    } else if (err.code === 'authentication_error') {
      // refresh token
    }
    console.error(err.status, err.code, err.proxyMessage)
  }
}
```

`code`和`proxyMessage` are `undefined` when the response body isn't JSON, for example an HTML 502 from a load balancer.

`executeCommand`在 direct-exec 数据平面（铁路 TCP Agent的 WebSocket）上运行，并且还可以在不可恢复的故障时抛出两个类型的Sandbox错误：

```typescript
import { SandboxDestroyedError, SandboxExecTransportError } from '@mastra/platform-workspace'

try {
  await sandbox.executeCommand('pytest')
} catch (err) {
  if (err instanceof SandboxDestroyedError) {
    // /exec-lease returned 410; the sandbox has been destroyed.
    // The cached sandbox id and lease have already been cleared,
    // so reusing the instance will reprovision on the next call.
  } else if (err instanceof SandboxExecTransportError) {
    // Both the initial WebSocket attempt and the built-in retry
    // closed without an exit frame against a live sandbox.
    console.error(err.closeCode, err.closeReason, err.wsEndpoint)
  }
}
```

`SandboxExecTransportError`携带诊断字段（`opened`, `closeCode`, `closeReason`, `wsEndpoint`, plus `sandboxId`, `command`, and `attempts`) so operators can distinguish a broken Railway data plane from a failed command.
