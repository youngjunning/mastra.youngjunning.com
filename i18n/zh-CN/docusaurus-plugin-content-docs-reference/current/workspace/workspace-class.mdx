# 工作空间类

**添加于：** `@mastra/core@1.1.0`

这`Workspace` class combines a filesystem and sandbox to provide agents with file storage and command execution capabilities. It also supports BM25 and vector search for indexed content.

## 使用示例 {/* #usage-example */}

```typescript
import { Workspace, LocalFilesystem, LocalSandbox } from '@mastra/core/workspace'

const workspace = new Workspace({
  id: 'my-workspace',
  name: 'My Workspace',
  filesystem: new LocalFilesystem({
    basePath: './workspace',
  }),
  sandbox: new LocalSandbox({
    workingDirectory: './workspace',
  }),
  bm25: true,
  autoIndexPaths: ['docs'],
})
```

## Tool配置 {/* #tool-configuration */}

这`tools` option accepts a `WorkspaceToolsConfig` object that controls which workspace tools are enabled and their safety settings.

```typescript {2,7-16}
import { Workspace } from '@mastra/core/workspace'
import { WORKSPACE_TOOLS } from '@mastra/core/workspace'

const workspace = new Workspace({
  id: 'my-workspace',
  name: 'My Workspace',
  tools: {
    // Global defaults (apply to all tools)
    enabled: true,
    requireApproval: false,

    // Per-tool overrides using WORKSPACE_TOOLS constants
    [WORKSPACE_TOOLS.FILESYSTEM.WRITE_FILE]: {
      requireApproval: true,
    },
  },
})
```

配置对象有两种类型的设置：

* **全局设置**: `enabled` and `requireApproval` apply to all workspace tools unless overridden. `hooks` and `writeLockTimeoutMs` are global-only and can't be configured per tool.
* **每个Tool覆盖**： 使用`WORKSPACE_TOOLS` constants as keys to configure individual tools

每个Tool覆盖接受以下选项：

### Tool名称重新映射 {/* #tool-name-remapping */}

通过设置重命名WorkspaceTool`name` property on individual tool configs. The config key remains the original constant: only the name exposed to the agent changes.

```typescript {8,9}
import { Workspace } from '@mastra/core/workspace'
import { WORKSPACE_TOOLS } from '@mastra/core/workspace'

const workspace = new Workspace({
  id: 'my-workspace',
  name: 'My Workspace',
  tools: {
    [WORKSPACE_TOOLS.FILESYSTEM.READ_FILE]: { name: 'view' },
    [WORKSPACE_TOOLS.FILESYSTEM.GREP]: { name: 'search_content' },
  },
})
```

Tool名称在所有WorkspaceTool中必须是唯一的。设置与其他Tool的默认或自定义名称冲突的自定义名称会引发错误。

### 先读后写跟踪 {/* #read-before-write-tracking */}

什么时候`requireReadBeforeWrite` is enabled, write tools reject changes to files the agent hasn't read. When the agent runs with a memory thread inside a Mastra instance, read records are kept per thread in the `threadState` storage domain, the same store that holds task lists and goal objectives. Records automatically survive suspend/resume cycles (for example, a tool awaiting approval), later turns on the same thread, and process restarts on serverless runtimes when the configured storage adapter persists thread state. No configuration is needed beyond registering the agent with a Mastra instance that has storage.

如果文件在读取后在磁盘上发生更改，则写入仍会被拒绝，直到Agent重新读取它，并且成功的写入始终会清除记录，因此下一次编辑需要重新读取。每次运行时无需内存线程或 Mastra 存储磁道读取即可运行。

读取记录的范围仅限于从中读取的文件系统，由文件系统的提供程序和基本路径标识。没有基本路径的文件系统仅由提供者限定范围，因此同一提供者实例共享读取记录。如果线程在请求​​之间解析不同的文件系统（例如，根据请求上下文而变化的动态Workspace或文件系统），则必须在写入之前在新文件系统上重新读取先前读取的文件。具有相同配置的文件系统（例如两个`LocalFilesystem` instances with the same `basePath`) share read records.

### Tool挂钩 {/* #tool-hooks */}

放`tools.hooks` to run logic before and after every enabled workspace tool call. Hooks run after name remapping and receive both the exposed `toolName` and the original `workspaceToolName` in their context.

```typescript {6-14}
import { Workspace } from '@mastra/core/workspace'

const workspace = new Workspace({
  id: 'my-workspace',
  tools: {
    hooks: {
      beforeToolCall: ({ toolName, workspaceToolName, input }) => {
        console.log(`Running ${toolName} (${workspaceToolName})`, input)
      },
      afterToolCall: ({ toolName, output, error }) => {
        console.log(`Finished ${toolName}`, { output, error })
      },
    },
  },
})
```

## 方法 {/* #methods */}

### 生命周期 {/* #lifecycle */}

#### `init()` {/* #init */}

初始化Workspace并准备资源。

```typescript
await workspace.init()
```

呼唤`init()` is optional in most cases:

* **沙盒**：首先自动启动`executeCommand()` call. Use `init()` to avoid first-command latency.
* **文件系统**：创建基本目录并运行任何特定于提供程序的设置。某些提供程序会在第一次操作时自动创建目录。
* **搜索**：仅在使用时才需要`autoIndexPaths` for auto-indexing.

初始化执行：

* 启动文件系统提供程序（如果需要，创建基目录）
* 启动Sandbox提供程序（创建工作目录，如果配置则设置隔离）
* 索引文件来自`autoIndexPaths` for search

#### `stop()` {/* #stop */}

停止Workspace的实时资源而不破坏它们。

```typescript
await workspace.stop()
```

`stop()`在停止Sandbox提供程序之前关闭语言服务器和浏览器。远程Provider暂停或暂停Sandbox以便稍后恢复，同时`LocalSandbox` kills background processes and unmounts filesystems. Stopping isn't a teardown. The filesystem and search index remain available along with skills, and the next sandbox operation starts the sandbox again.

`mastra.shutdown()`来电`stop()` for registered workspaces. A process restart suspends remote sandboxes instead of deleting them. To fully tear a workspace down, call `destroy()` or `mastra.removeWorkspace(id, { destroy: true })` explicitly.

#### `destroy()` {/* #destroy */}

摧毁Workspace并清理资源。

```typescript
await workspace.destroy()
```

`destroy()`按顺序关闭Workspace拥有的资源：语言服务器、浏览器、Sandbox提供程序和文件系统提供程序。它还清除缓存的Sandbox引用。

称呼`destroy()` when your application is done with a workspace and its sandbox. To remove a workspace from the Mastra registry, use [`mastra.removeWorkspace()`](/reference/core/removeWorkspace).

`LocalFilesystem.destroy()`不删除磁盘上的文件。解析器支持的文件系统和Sandbox提供程序归您的应用程序所有，并且必须由您的应用程序清理。

#### `clearSandboxCache(cacheKey?)` {/* #clearsandboxcachecachekey */}

此方法不会清除 per-`RequestContext` weak cache. Those entries are garbage-collection managed.

Workspace不拥有解析器返回的Sandbox。此方法仅删除Workspace引用。在您自己的生命周期代码中销毁Sandbox。

```typescript
workspace.clearSandboxCache('thread-123')
workspace.clearSandboxCache()
```

## AgentTool {/* #agent-tools */}

Workspace根据配置向Agent提供Tool。

### 文件系统Tool {/* #filesystem-tools */}

配置文件系统时添加：

|Tool|描述 |
| - | - |
|`mastra_workspace_read_file` | Read file contents. Text files return as text (with optional line range). Images and PDFs return as native media parts the model can view directly. Other binaries return metadata only unless an explicit `encoding` is passed. |
| `mastra_workspace_write_file` | Create or overwrite a file with new content. Creates parent directories automatically. |
| `mastra_workspace_edit_file` | Edit an existing file by finding and replacing text. Useful for targeted changes without rewriting the entire file. |
| `mastra_workspace_list_files` | List directory contents as a tree structure. Supports recursive listing with depth limits, glob patterns, and `.gitignore` filtering (enabled by default: every `.gitignore` applies relative to its own directory, and `node_modules` is skipped unless the listed path is inside it). |
| `mastra_workspace_delete` | Delete a file or directory. Supports recursive deletion for directories. |
| `mastra_workspace_file_stat` | Get metadata about a file or directory including size, type, and modification time. |
| `mastra_workspace_mkdir` | Create a directory. Creates parent directories automatically if they don't exist. |
| `mastra_workspace_grep` | Search file contents using regex patterns. Supports glob filtering, context lines, and case-insensitive search. Applies `.gitignore` files the same way as `list_files` and skips `node_modules` unless the search path is inside it. When a matched line exceeds 500 characters, only its first 500 characters are shown, followed by `...` (context lines are shown in full). If the match is past that point, read the full line with `read_file`, using the reported line number as `offset`. |
| `mastra_workspace_apply_patch` | Create, update, move, and delete several files in one call using a patch. Opt-in: only added when `tools[WORKSPACE_TOOLS.FILESYSTEM.APPLY_PATCH].enabled` is set. The top-level `tools.enabled` doesn't enable it. The tool checks every hunk before writing and leaves all files unchanged if any hunk fails to match. |

使用静态文件系统，编写Tool（`write_file`, `edit_file`, `delete`, `mkdir`, `apply_patch`) are excluded when the filesystem is in read-only mode. With a [runtime-defined filesystem](/docs/sandbox/filesystem#filesystems-per-user-or-thread), write tools are always included and read-only is enforced at runtime.

这`read_file` tool accepts `mediaTypes` and `maxMediaBytes` options to control which mime types are surfaced to the model as native media parts and how large those files can be:

  },


### SandboxTool {/* #sandbox-tools */}

配置Sandbox时添加：

|Tool|描述 |
| - | - |
|`mastra_workspace_execute_command` | Execute a shell command. Returns stdout, stderr, and exit code. When the sandbox has a process manager, accepts `background: true` to spawn a long-running process and return a PID. |
| `mastra_workspace_get_process_output` | Get stdout, stderr, and status of a background process by PID. Accepts `tail` to limit output lines and `wait: true` to block until exit. Only available when the sandbox has a process manager. |
| `mastra_workspace_kill_process` | Kill a background process by PID. Returns the last 50 lines of output. Only available when the sandbox has a process manager. |

使用静态Sandbox，功能检查（`executeCommand`, `processes`) decide which tool variants are exposed. With a [runtime-defined sandbox](/docs/sandbox/overview#sandboxes-per-user-or-thread), all sandbox tools are registered and the runtime throws a clear error if the resolved sandbox doesn't implement a requested capability.

### 技能Tool {/* #skill-tools */}

配置技能时添加：

|Tool|描述 |
| - | - |
|`skill` | Activate a skill by name or path. Returns the skill's full instructions, references, scripts, and assets. |
| `skill_search` | Search skill names, descriptions, and content. Accepts an optional list of skill names to filter and a `topK` parameter. |
| `skill_read` | Read a specific file (reference, script, or asset) from a skill directory. |

当多个技能同名时，`list()` returns all of them. `get()` with a name applies tie-breaking (local > managed > external). If two skills share the same name and source type, `get()` throws an error. Pass a skill's full path to `get()` to bypass tie-breaking. See [Skills with the same name](/docs/sandbox/skills#same-named-skills) for details.
