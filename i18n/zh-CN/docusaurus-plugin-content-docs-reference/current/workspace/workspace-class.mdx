# Workspace 类

**引入版本：** `@mastra/core@1.1.0`

`Workspace` 类结合文件系统与 Sandbox，为 Agent 提供文件存储和命令执行能力，还支持对已索引内容进行 BM25 搜索和向量搜索。

## 使用示例 {/* #usage-example */}

```typescript
import { Workspace, LocalFilesystem, LocalSandbox } from '@mastra/core/workspace'

const workspace = new Workspace({
  id: 'my-workspace',
  name: 'My Workspace',
  filesystem: new LocalFilesystem({
    basePath: './workspace',
  }),
  sandbox: new LocalSandbox({
    workingDirectory: './workspace',
  }),
  bm25: true,
  autoIndexPaths: ['docs'],
})
```

对于由解析函数提供的 Sandbox，默认的 `'placeholder'` 模式可在构建 Workspace 指令时避免创建 Sandbox。如果指令必须来自解析得到的 Sandbox，请将 `instructions.dynamicSandbox` 设为 `'resolve'`：

```typescript
const workspace = new Workspace({
  sandbox: ({ requestContext }) => resolveSandbox(requestContext),
  instructions: { dynamicSandbox: 'resolve' },
})
```

这样会在构建指令时调用解析函数。如果要描述特定请求的环境而不创建 Sandbox，可以改为传入一个根据 `requestContext` 返回指令文本的函数。

## Tool 配置 {/* #tool-configuration */}

`tools` 选项接受 `WorkspaceToolsConfig` 对象，用于控制启用哪些 Workspace Tool 及其安全设置。

```typescript {2,7-16}
import { Workspace } from '@mastra/core/workspace'
import { WORKSPACE_TOOLS } from '@mastra/core/workspace'

const workspace = new Workspace({
  id: 'my-workspace',
  name: 'My Workspace',
  tools: {
    // Global defaults (apply to all tools)
    enabled: true,
    requireApproval: false,

    // Per-tool overrides using WORKSPACE_TOOLS constants
    [WORKSPACE_TOOLS.FILESYSTEM.WRITE_FILE]: {
      requireApproval: true,
    },
  },
})
```

配置对象包含两类设置：

* **全局设置**：`enabled` 和 `requireApproval` 应用于所有 Workspace Tool，除非被逐个 Tool 的设置覆盖。`hooks` 和 `writeLockTimeoutMs` 只能全局设置，不能逐个 Tool 配置。
* **逐个 Tool 覆盖**：使用 `WORKSPACE_TOOLS` 常量作为键，配置单个 Tool。

逐个 Tool 的配置支持以下选项：

`ToolConfigContext` 包含 `{ requestContext, workspace }`。执行时策略使用 `ToolConfigWithArgsContext`，其中还包含 Tool 的 `args`。

```typescript {5-13}
import { Workspace, WORKSPACE_TOOLS } from '@mastra/core/workspace'

const workspace = new Workspace({
  id: 'my-workspace',
  tools: {
    enabled: ({ requestContext }) => requestContext.get('workspace-tools') === true,
    [WORKSPACE_TOOLS.FILESYSTEM.WRITE_FILE]: {
      requireApproval: ({ args }) => (args.path as string).startsWith('/protected'),
      requireReadBeforeWrite: true,
    },
    [WORKSPACE_TOOLS.SANDBOX.EXECUTE_COMMAND]: {
      maxOutputTokens: 5000,
    },
  },
})
```

### Tool 名称重映射 {/* #tool-name-remapping */}

在单个 Tool 的配置中设置 `name` 属性即可重命名 Workspace Tool。配置键仍使用原常量，只有向 Agent 公开的名称会改变。

```typescript {8,9}
import { Workspace } from '@mastra/core/workspace'
import { WORKSPACE_TOOLS } from '@mastra/core/workspace'

const workspace = new Workspace({
  id: 'my-workspace',
  name: 'My Workspace',
  tools: {
    [WORKSPACE_TOOLS.FILESYSTEM.READ_FILE]: { name: 'view' },
    [WORKSPACE_TOOLS.FILESYSTEM.GREP]: { name: 'search_content' },
  },
})
```

所有 Workspace Tool 的名称必须唯一。如果自定义名称与其他 Tool 的默认名称或自定义名称冲突，就会抛出错误。

### 先读后写跟踪 {/* #read-before-write-tracking */}

启用 `requireReadBeforeWrite` 后，写入 Tool 会拒绝修改 Agent 尚未读取的文件。如果 Agent 在 Mastra 实例中使用记忆线程运行，读取记录会按线程保存在 `threadState` 存储域中，与任务列表和目标共用同一存储。只要配置的存储适配器会持久化线程状态，这些记录就能跨挂起与恢复（例如 Tool 等待审批）、同一线程的后续轮次，以及无服务器运行环境中的进程重启保留。除了在带存储的 Mastra 实例中注册 Agent，无需额外配置。

如果文件在读取后发生变化，Agent 必须重新读取，写入才会获准。成功写入后，读取记录会被清除，因此下次修改前仍须重新读取。没有记忆线程或 Mastra 存储时，读取记录仅在当前运行期间有效。

读取记录按文件系统隔离，文件系统由其 Provider 和基础路径标识。没有基础路径时只按 Provider 隔离，因此相同 Provider 的实例共享读取记录。如果同一线程在不同请求中解析到不同文件系统（例如 Workspace 或文件系统随请求上下文动态变化），写入前必须在新文件系统上重新读取文件。配置相同的文件系统（例如两个 `basePath` 相同的 `LocalFilesystem` 实例）共享读取记录。

### Tool 钩子 {/* #tool-hooks */}

设置 `tools.hooks`，可在每次调用已启用的 Workspace Tool 前后运行逻辑。钩子在名称重映射后运行，其上下文同时包含公开的 `toolName` 和原始的 `workspaceToolName`。

```typescript {6-14}
import { Workspace } from '@mastra/core/workspace'

const workspace = new Workspace({
  id: 'my-workspace',
  tools: {
    hooks: {
      beforeToolCall: ({ toolName, workspaceToolName, input }) => {
        console.log(`Running ${toolName} (${workspaceToolName})`, input)
      },
      afterToolCall: ({ toolName, output, error }) => {
        console.log(`Finished ${toolName}`, { output, error })
      },
    },
  },
})
```

## 方法 {/* #methods */}

### 生命周期 {/* #lifecycle */}

#### `init()` {/* #init */}

初始化 Workspace 并准备资源。

```typescript
await workspace.init()
```

大多数情况下无需显式调用 `init()`：

* **Sandbox**：首次调用 `executeCommand()` 时自动启动。可调用 `init()` 以避免首次执行命令的延迟。
* **文件系统**：创建基础目录并执行 Provider 特定的初始化。某些 Provider 会在首次操作时自动创建目录。
* **搜索**：只有使用 `autoIndexPaths` 自动索引时才需要调用。

初始化执行：

* 启动文件系统 Provider（必要时创建基础目录）
* 启动 Sandbox Provider（创建工作目录，并在配置后设置隔离环境）
* 为搜索索引 `autoIndexPaths` 指定的文件

#### `stop()` {/* #stop */}

停止 Workspace 的运行中资源，但不销毁它们。

```typescript
await workspace.stop()
```

`stop()` 会先关闭语言服务器和浏览器，再停止 Sandbox Provider。远程 Provider 会暂停 Sandbox，以便之后恢复；`LocalSandbox` 则会终止后台进程并卸载文件系统。停止并不等于销毁：文件系统、搜索索引和 Skill 仍然可用，下次执行 Sandbox 操作时会再次启动 Sandbox。

`mastra.shutdown()` 会对已注册的 Workspace 调用 `stop()`。进程重启时，远程 Sandbox 会被暂停，而非删除。要彻底销毁 Workspace，须显式调用 `destroy()` 或 `mastra.removeWorkspace(id, { destroy: true })`。

#### `destroy()` {/* #destroy */}

销毁 Workspace 并清理资源。

```typescript
await workspace.destroy()
```

`destroy()` 会依次关闭 Workspace 拥有的语言服务器、浏览器、Sandbox Provider 和文件系统 Provider，并清除缓存的 Sandbox 引用。

应用程序不再需要 Workspace 及其 Sandbox 时，应调用 `destroy()`。要从 Mastra 注册表移除 Workspace，请使用 [`mastra.removeWorkspace()`](/reference/core/removeWorkspace)。

`LocalFilesystem.destroy()` 不会删除磁盘上的文件。由解析函数返回的文件系统和 Sandbox Provider 归应用程序所有，须由应用程序自行清理。

#### `getInfo()` {/* #getinfo */}

```typescript
const info = await workspace.getInfo()
// { id, name, status, createdAt, lastAccessedAt, filesystem?, sandbox? }
```

传入 `resolveDynamicProviders: false` 可跳过文件系统解析函数。如果当前请求尚未解析该文件系统，它会被报告为 `{ provider: 'dynamic', status: 'pending' }`。`getInfo()` 绝不会调用 Sandbox 解析函数，因为解析 Sandbox 可能会创建实际基础设施。当前请求尚未解析的 Sandbox 也会被报告为 `{ provider: 'dynamic', status: 'pending' }`。

```typescript
const info = await workspace.getInfo({ resolveDynamicProviders: false })
```

## Agent Tool {/* #agent-tools */}

Workspace 根据配置向 Agent 提供 Tool。

### 文件系统 Tool {/* #filesystem-tools */}

配置文件系统时添加：

| Tool | 描述 |
| - | - |
| `mastra_workspace_read_file` | 读取文件内容。文本文件以文本形式返回（可指定行范围）；图片和 PDF 以模型可直接查看的原生媒体内容返回。其他二进制文件仅返回元数据，除非显式传入 `encoding`。 |
| `mastra_workspace_write_file` | 创建文件或用新内容覆盖文件，并自动创建父目录。 |
| `mastra_workspace_edit_file` | 通过查找和替换文本来编辑现有文件，适合局部修改，无需重写整个文件。 |
| `mastra_workspace_list_files` | 以树形结构列出目录内容。支持递归列出、深度限制、glob 模式和 `.gitignore` 过滤；默认情况下，各 `.gitignore` 相对于自身所在目录生效，且会跳过 `node_modules`，除非列出的路径位于其中。 |
| `mastra_workspace_delete` | 删除文件或目录，支持递归删除目录。 |
| `mastra_workspace_file_stat` | 获取文件或目录的元数据，包括大小、类型和修改时间。 |
| `mastra_workspace_mkdir` | 创建目录，并自动创建缺失的父目录。 |
| `mastra_workspace_grep` | 使用正则表达式搜索文件内容。支持 glob 过滤、上下文行和不区分大小写的搜索。与 `list_files` 一样应用 `.gitignore`，并跳过 `node_modules`，除非搜索路径位于其中。匹配行超过 500 个字符时，只显示前 500 个字符并附加 `...`（上下文行仍完整显示）。如果匹配位置在截断部分，可用报告的行号作为 `offset`，通过 `read_file` 读取完整内容。 |
| `mastra_workspace_apply_patch` | 通过一个补丁创建、更新、移动或删除多个文件。须显式将 `tools[WORKSPACE_TOOLS.FILESYSTEM.APPLY_PATCH].enabled` 设为开启；顶层 `tools.enabled` 不会启用它。写入前会检查所有补丁块；只要有一块不匹配，就不会更改任何文件。 |

### Sandbox Tool {/* #sandbox-tools */}

### Skill Tool {/* #skill-tools */}

配置 Skill 时添加：

| Tool | 描述 |
| - | - |
| `skill` | 按名称或路径激活 Skill，返回完整指令、参考资料、脚本和资源。 |
| `skill_search` | 搜索 Skill 名称、描述和内容。可传入 Skill 名称列表进行过滤，并用 `topK` 参数限制结果数量。 |

多个 Skill 同名时，`list()` 会返回全部结果；按名称调用 `get()` 时，按本地 > 托管 > 外部的顺序选择。如果两个 Skill 的名称和来源类型均相同，`get()` 会抛出错误。传入 Skill 的完整路径可跳过此选择规则。详见[同名 Skill](/docs/sandbox/skills#same-named-skills)。
