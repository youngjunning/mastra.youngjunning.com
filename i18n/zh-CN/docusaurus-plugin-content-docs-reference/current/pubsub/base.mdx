# PubSub

`PubSub` 是 Mastra 事件系统的抽象基类。它定义了所有发布订阅后端都必须实现的契约，让 Mastra 的其他部分无需了解底层传输方式，就能发布和订阅事件。

Mastra 内部使用发布订阅处理 Workflow 事件、流式输出和组件间通信。多数应用使用默认的 [`EventEmitterPubSub`](/reference/pubsub/event-emitter)，无需直接构造 `PubSub`。只有需要自定义传输时才实现此类。

内置实现包括 [`EventEmitterPubSub`](/reference/pubsub/event-emitter)、[`UnixSocketPubSub`](/reference/pubsub/unix-socket-pubsub)、[`CachingPubSub`](/reference/pubsub/caching-pubsub)、[`RedisStreamsPubSub`](/reference/pubsub/redis-streams) 和 [`GoogleCloudPubSub`](/reference/pubsub/google-cloud-pubsub)。

## 使用示例 {/* #usage-example */}

要添加自定义后端，请扩展 `PubSub` 并实现其四个抽象方法。

```typescript title="src/mastra/pubsub.ts"
import { PubSub } from '@mastra/core/events'
import type { Event, EventCallback, SubscribeOptions } from '@mastra/core/events'

export class CustomPubSub extends PubSub {
  async publish(topic: string, event: Omit<Event, 'id' | 'createdAt'>): Promise<void> {
    // Deliver the event to subscribers of `topic`.
  }

  async subscribe(topic: string, cb: EventCallback, options?: SubscribeOptions): Promise<void> {
    // Register `cb` to receive events published to `topic`.
  }

  async unsubscribe(topic: string, cb: EventCallback): Promise<void> {
    // Remove a previously registered callback.
  }

  async flush(): Promise<void> {
    // Wait for any in-flight deliveries to settle.
  }
}
```

将实例传给 [Mastra](/reference/core/mastra-class) 构造函数：

```typescript title="src/mastra/index.ts"
import { Mastra } from '@mastra/core'
import { CustomPubSub } from './pubsub'

export const mastra = new Mastra({
  pubsub: new CustomPubSub(),
})
```

## 投递模式 {/* #delivery-modes */}

`PubSub` 通过 `supportedModes` 属性声明支持的投递模式。Mastra 据此决定是否运行长期存活的 Worker 来拉取事件。

| 模式 | 说明 |
| - | - |
|`pull` | 消费者主动从 Broker 读取，例如使用 Redis Streams 的 `XREADGROUP`。Mastra 会运行编排 Worker 执行读取。 |
| `push` | 事件在进程内或通过 HTTP 端点主动送达，消费者无需请求，也不需要读取循环。 |

默认为 `['pull']`，因此自定义实现只有显式启用 push 投递才会改变现有行为。

## 方法 {/* #methods */}

### 核心方法 {/* #core-methods */}

#### `publish(topic, event)` {/* #publishtopic-event */}

将事件发布到主题。`id` 和 `createdAt` 字段由实现分配。

```typescript
await pubsub.publish('my-topic', {
  type: 'example',
  data: { value: 1 },
  runId: 'run-123',
})
```

#### `subscribe(topic, cb, options?)` {/* #subscribetopic-cb-options */}

注册回调，接收发布到主题的事件。设置 `options.group` 后，同组订阅者竞争消息，每个事件只投递给一名成员；未设置组时，每名订阅者都会收到每个事件。

传入 `options.batch` 可启用批量投递。回调签名不变：一批 N 个事件会按发布顺序触发 N 次连续的 `cb(event, ack, nack)` 调用。只有后端的 [`supportsNativeBatching`](#properties) 为 `true` 时才会批量投递；其他后端会忽略该选项，逐个投递事件。

将 `options.startFrom` 设为 `"latest"`，新消费者组就只接收创建后发布的事件。默认值 `"earliest"` 会包含保留的事件。已有消费者组继续使用当前检查点。

```typescript
await pubsub.subscribe(
  'my-topic',
  (event, ack, nack) => {
    console.log(event)
  },
  { startFrom: 'latest' },
)
```

#### `unsubscribe(topic, cb)` {/* #unsubscribetopic-cb */}

从主题中删除先前注册的回调。

```typescript
await pubsub.unsubscribe('my-topic', callback)
```

#### `flush()` {/* #flush */}

等待正在进行的投递结束。关闭前调用此方法，避免丢失事件。

```typescript
await pubsub.flush()
```

#### `clearTopic(topic)` {/* #cleartopictopic */}

当某个主题不再接收新事件时，删除其所有保留状态，包括缓存历史、持久化流条目和消费者组。Mastra 的运行生命周期（持久 Agent 和事件驱动的 Workflow 引擎）会在运行进入终态时自动调用此方法，避免按运行创建的主题在保留消息的传输后端持续累积。

默认实现不执行任何操作，因为 `EventEmitterPubSub` 等不按主题保留状态的传输后端无须清理。持久化消息的后端，例如 [`RedisStreamsPubSub`](/reference/pubsub/redis-streams)，会覆盖该方法。清理遵循尽力而为的契约：失败时记录日志而不抛出异常，因为调用方不会等待清理完成。

```typescript
await pubsub.clearTopic('workflow.events.v2.run-123')
```

#### `trimTopic(topic, { runId, producedBefore? })` {/* #trimtopictopic--runid-producedbefore- */}

删除该主题上所有以 `runId` 发布的保留条目，其他条目不受影响。运行成功完成且消息已保存到存储后，Mastra 会调用此方法，因此已完成运行的消息会从主题移除，而仍在执行或等待批准的运行会保留。默认实现不执行任何操作；[`RedisStreamsPubSub`](/reference/pubsub/redis-streams) 会覆盖它。该方法与 `clearTopic` 一样遵循尽力而为的契约。

传入 `producedBefore`（Unix 纪元毫秒）时，只删除 `data.producedAt` 不晚于该时间的条目；标记为 `data.pinned` 的批准及暂停提示会保留。Mastra 在运行尚未结束时使用此功能：每次中途保存运行消息后，都会从主题移除截至最后一个已完成步骤的内容。

```typescript
await pubsub.trimTopic('agent.thread.thread-abc', { runId: 'run-123' })
await pubsub.trimTopic('agent.thread.thread-abc', { runId: 'run-123', producedBefore: Date.now() })
```

### 重播方法 {/* #replay-methods */}

这些方法用于在连接中断后恢复流。默认实现会退回常规的 `subscribe`，因此不支持历史记录的后端只能接收实时事件。[`CachingPubSub`](/reference/pubsub/caching-pubsub) 会覆盖这些方法，以重播缓存事件。

#### `getHistory(topic, offset?)` {/* #gethistorytopic-offset */}

返回主题从 `offset` 开始的缓存事件。后端没有历史记录时返回空数组。

```typescript
const events = await pubsub.getHistory('my-topic', 0)
```

返回：`Promise<Event[]>`

#### `subscribeWithReplay(topic, cb)` {/* #subscribewithreplaytopic-cb */}

重播缓存的事件，然后订阅实时事件。

```typescript
await pubsub.subscribeWithReplay('my-topic', event => {
  console.log(event)
})
```

#### `subscribeFromOffset(topic, offset, cb)` {/* #subscribefromoffsettopic-offset-cb */}

从已知位置开始重播缓存的事件，然后订阅实时事件。当客户端知道其最后位置时，这比完整重播更有效。

```typescript
await pubsub.subscribeFromOffset('my-topic', 42, event => {
  console.log(event)
})
```
