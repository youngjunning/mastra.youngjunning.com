# ValkeyStreamsPubSub

`ValkeyStreamsPubSub` 是 [`PubSub`](/reference/pubsub/base) 和 [`LeaseProvider`](/reference/pubsub/lease-provider) 实现，通过 [Valkey GLIDE](https://github.com/valkey-io/valkey-glide) 以 Valkey Streams 为基础。它支持跨进程持久投递、消费者组、重新投递、主题清理和分布式租约。

适用于 Valkey 部署。对于 Redis 部署，请使用 [`RedisStreamsPubSub`](/reference/pubsub/redis-streams)，前提是使用官方 `redis` 客户端。两种集成提供相同的 Mastra 行为，并分别针对 Valkey 和 Redis 运行独立测试。

## 安装 {/* #installation */}

```bash npm2yarn
npm install @mastra/valkey-streams
```

## 使用示例 {/* #usage-example */}

```typescript title="src/mastra/index.ts"
import { Mastra } from '@mastra/core'
import { ValkeyStreamsPubSub } from '@mastra/valkey-streams'

export const mastra = new Mastra({
  pubsub: new ValkeyStreamsPubSub({
    url: 'valkey://localhost:6379',
  }),
})
```

## 投递行为 {/* #delivery-behavior */}

`ValkeyStreamsPubSub` 支持拉取式投递，但不支持数值型重放偏移量。同组订阅者通过共享消费者组竞争接收事件。未指定组的订阅者通过各自的私有消费者组接收扇出投递。

首次创建消费者组时，使用 `startFrom: "latest"` 可跳过已保留的条目。默认值 `"earliest"` 会先读取这些条目。

订阅者调用 `nack` 时，事件会以递增的 `deliveryAttempt` 重新发布，原事件则被确认。事件达到 `maxDeliveryAttempts` 后会被丢弃，不再重新投递。此外，每个订阅会定期回收同组中先前消费者已读取但未确认的事件；回收由 `reclaimIntervalMs` 和 `reclaimIdleMs` 控制。

订阅不会回收自身处理程序仍在处理的事件，因此慢速处理程序不会针对同一事件被调用两次。若处理程序卡住，同组中的另一消费者可在事件空闲达到 `reclaimIdleMs` 后回收它。单消费者组没有其他消费者执行回收，可设置 `inFlightTimeoutMs`，使订阅在超时后自行对事件执行 nack。

## 服务器配置 {/* #server-configuration */}

将 `maxmemory-policy` 设为 `noeviction`。消费者组、未确认条目和租约键都属于活动状态；服务器达到 `maxmemory` 时，任何允许驱逐的策略都会删除它们，导致事件和租约丢失。若设置了 `maxmemory` 且策略不是 `noeviction`，`ValkeyStreamsPubSub` 在首次连接后会记录一次警告。要清理未设置 TTL 的流，请使用 `valkey-cli` 并参照 [Redis Streams 操作手册](/reference/pubsub/redis-streams#reclaim-streams-created-without-a-ttl)。

## 清理和关闭 {/* #cleanup-and-shutdown */}

`clearTopic(topic)` 会删除主题流及其消费者组。`flush()` 会等待进行中的发布完成；`close()` 会停止订阅并关闭 GLIDE 连接。

```typescript
await pubsub.clearTopic('workflow.events.run-123')
await pubsub.flush()
await pubsub.close()
```
