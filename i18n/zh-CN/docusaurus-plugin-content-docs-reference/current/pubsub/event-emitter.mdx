# 事件发射器发布订阅

`EventEmitterPubSub`是默认值[`PubSub`](/reference/pubsub/base)执行。它使用 Node.js 传递进程内事件[`EventEmitter`](https://nodejs.org/api/events.html#class-eventemitter)，因此它无需任何外部服务即可工作。

将其用于单进程应用程序。对于一台主机上跨进程的交付，请参阅[`UnixSocketPubSub`](/reference/pubsub/unix-socket-pubsub). For distributed delivery, see [`RedisStreamsPubSub`](/reference/pubsub/redis-streams) or [`GoogleCloudPubSub`](/reference/pubsub/google-cloud-pubsub).

由于它是进程内的，因此事件不会持久存在，也不会与其他进程共享。把它包起来[`CachingPubSub`](/reference/pubsub/caching-pubsub) when you need replay for resumable streams.

## 使用示例 {/* #usage-example */}

`EventEmitterPubSub`当您未配置时自动使用`pubsub` option, so most applications never construct it directly. Create one explicitly only when you want to configure or share it.

```typescript title="src/mastra/index.ts"
import { Mastra } from '@mastra/core'
import { EventEmitterPubSub } from '@mastra/core/events'

export const mastra = new Mastra({
  pubsub: new EventEmitterPubSub(),
})
```

要与应用程序的其他部分共享发射器，请传递现有的`EventEmitter`:

```typescript
import EventEmitter from 'node:events'
import { EventEmitterPubSub } from '@mastra/core/events'

const emitter = new EventEmitter()
const pubsub = new EventEmitterPubSub(emitter)
```

要显示批量传送错误，请传递一个记录器：

```typescript
import { EventEmitterPubSub } from '@mastra/core/events'

const pubsub = new EventEmitterPubSub(undefined, { logger })
```

## 方法 {/* #methods */}

`EventEmitterPubSub`实施[`PubSub`](/reference/pubsub/base) contract. The methods below have behavior specific to this implementation.

### `subscribe(topic, cb, options?)` {/* #subscribetopic-cb-options */}

注册主题的回调。没有`options.group`, every subscriber receives every event. With a group, events are distributed round-robin across members of that group.

经过`options.batch` to opt in to batched delivery. See [Batching](#batching) below.

```typescript
await pubsub.subscribe('workflow.events', (event, ack, nack) => {
  console.log(event)
})
```

### `flush()` {/* #flush */}

等待任何待处理的重新投递`nack` to fire before resolving.

```typescript
await pubsub.flush()
```

### `close()` {/* #close */}

删除所有侦听器并取消挂起的重新传递。在正常关闭期间调用此方法。

```typescript
await pubsub.close()
```

## 再次投递 {/* #redelivery */}

当分组用户呼叫时`nack`, the event is redelivered to the group after a short delay, and its `deliveryAttempt` count increases. Calling `ack` clears the tracking for that event. Fan-out subscribers receive no-op `ack` and `nack` functions, since each event reaches every subscriber once.

## 配料 {/* #batching */}

`EventEmitterPubSub`荣誉`options.batch` natively. When a subscriber opts in, events are held in a per-subscriber in-memory buffer and delivered as consecutive callback invocations once a flush condition is met. Both fan-out and group subscribers can batch. See [`SubscribeBatchOptions`](/reference/pubsub/base#subscribebatchoptions) for the full policy.

```typescript
await pubsub.subscribe(
  'workflow.events',
  event => {
    console.log(event)
  },
  {
    batch: {
      maxSize: 10, // flush once 10 events have queued
      maxWaitMs: 500, // ...or after 500ms, whichever comes first
    },
  },
)
```

缓冲区位于内存中且针对每个进程，因此批处理状态不会持续存在，并且不会在重新启动后继续存在。触发的刷新`maxWaitMs` is best-effort: if a step such as a throwing `coalesce` fails, the error is surfaced through the configured `logger` rather than thrown. `flush()` drains every batched subscriber buffer before resolving.
