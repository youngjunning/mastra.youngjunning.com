# EventEmitterPubSub

`EventEmitterPubSub` 是默认的 [`PubSub`](/reference/pubsub/base) 实现。它使用 Node.js [`EventEmitter`](https://nodejs.org/api/events.html#class-eventemitter) 在进程内传递事件，因此无需外部服务。

适用于单进程应用。若要在同一主机的多个进程之间传递事件，请参阅 [`UnixSocketPubSub`](/reference/pubsub/unix-socket-pubsub)；若要在分布式环境中传递事件，请参阅 [`RedisStreamsPubSub`](/reference/pubsub/redis-streams) 或 [`GoogleCloudPubSub`](/reference/pubsub/google-cloud-pubsub)。

由于事件只在进程内传递，因此不会持久化，也不会与其他进程共享。若可恢复的流需要重放事件，请使用 [`CachingPubSub`](/reference/pubsub/caching-pubsub) 包装它。

## 使用示例 {/* #usage-example */}

`EventEmitterPubSub` 会在未配置 `pubsub` 选项时自动使用，因此大多数应用无需自行创建。只有需要配置或共享实例时才显式创建。

```typescript title="src/mastra/index.ts"
import { Mastra } from '@mastra/core'
import { EventEmitterPubSub } from '@mastra/core/events'

export const mastra = new Mastra({
  pubsub: new EventEmitterPubSub(),
})
```

若要与应用的其他部分共享事件发射器，请传入现有的 `EventEmitter`：

```typescript
import EventEmitter from 'node:events'
import { EventEmitterPubSub } from '@mastra/core/events'

const emitter = new EventEmitter()
const pubsub = new EventEmitterPubSub(emitter)
```

若要报告批量传递错误，请传入日志记录器：

```typescript
import { EventEmitterPubSub } from '@mastra/core/events'

const pubsub = new EventEmitterPubSub(undefined, { logger })
```

## 方法 {/* #methods */}

`EventEmitterPubSub` 实现了 [`PubSub`](/reference/pubsub/base) 契约。以下方法具有此实现特有的行为。

### `subscribe(topic, cb, options?)` {/* #subscribetopic-cb-options */}

为主题注册回调。未设置 `options.group` 时，每个订阅者都会收到每个事件；设置后，事件会在组成员之间轮流分配。

传入 `options.batch` 即可启用批量传递。详情请参阅下文的[批量处理](#batching)。

```typescript
await pubsub.subscribe('workflow.events', (event, ack, nack) => {
  console.log(event)
})
```

### `flush()` {/* #flush */}

等待由 `nack` 触发的待处理重新投递完成后再返回。

```typescript
await pubsub.flush()
```

### `close()` {/* #close */}

移除所有监听器并取消待处理的重新投递。请在正常关闭时调用。

```typescript
await pubsub.close()
```

## 重新投递 {/* #redelivery */}

组内订阅者调用 `nack` 后，事件会短暂延迟再投递给该组，`deliveryAttempt` 计数随之增加。调用 `ack` 会清除该事件的跟踪记录。扇出式订阅者收到的 `ack` 和 `nack` 函数不会执行任何操作，因为每个事件都会向每位订阅者传递一次。

## 批量处理 {/* #batching */}

`EventEmitterPubSub` 原生支持 `options.batch`。订阅者启用后，事件会暂存在该订阅者专属的内存缓冲区中；满足刷新条件时，回调会连续调用以传递这些事件。扇出式和分组订阅者都可以批量处理。完整策略请参阅 [`SubscribeBatchOptions`](/reference/pubsub/base#subscribebatchoptions)。

```typescript
await pubsub.subscribe(
  'workflow.events',
  event => {
    console.log(event)
  },
  {
    batch: {
      maxSize: 10, // flush once 10 events have queued
      maxWaitMs: 500, // ...or after 500ms, whichever comes first
    },
  },
)
```

缓冲区位于各进程的内存中，因此批量处理状态不会持久化，重启后也不会保留。由 `maxWaitMs` 触发的刷新会尽力完成：如果 `coalesce` 等步骤抛出错误，错误会通过配置的 `logger` 报告，而不会向外抛出。`flush()` 会清空所有批量订阅者的缓冲区，然后返回。
