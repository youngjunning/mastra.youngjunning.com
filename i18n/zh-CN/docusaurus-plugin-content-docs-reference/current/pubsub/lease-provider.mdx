# 租赁Provider

`LeaseProvider`是分布式租赁合约，与事件交付分开（[`PubSub`](/reference/pubsub/base)）。马斯特拉的[信号层](/docs/signals/overview)使用它跨多个进程（例如，无服务器调用）为资源（最常见的是线程键）选择单个所有者。所有者是唤醒并运行Agent流的进程，因此其他进程将后续工作路由到它，而不是启动竞争运行。

[持久剂](/docs/harness/durable-agents#run-ownership)当Workflow存储不支持运行防护时，还声明每次运行都通过租约，因此崩溃恢复可以判断另一个进程是否仍在驱动运行。

租赁与发布/订阅是分开的。一个`LeaseProvider` implementation needs actual lock coordination, whether through an atomic Redis operation such as `SET` or Lua or through an in-memory map for a single process. For backends that omit leasing, the signals runtime preserves single-process behavior with a no-op provider.

内置的[`RedisStreamsPubSub`](/reference/pubsub/redis-streams) implements `LeaseProvider`, which is what enables signals to coordinate across instances in distributed and serverless deployments.

## 使用示例 {/* #usage-example */}

你不构建一个`LeaseProvider` directly. Configure a pub/sub backend that implements it (such as `RedisStreamsPubSub`) on the `Mastra` constructor, and the signals runtime uses it automatically for cross-process coordination.

```typescript title="src/mastra/index.ts"
import { Mastra } from '@mastra/core'
import { RedisStreamsPubSub } from '@mastra/redis-streams'

export const mastra = new Mastra({
  // RedisStreamsPubSub implements both PubSub and LeaseProvider
  pubsub: new RedisStreamsPubSub({
    url: process.env.REDIS_URL,
  }),
})
```

要在自定义后端中实现租赁，请实现以下方法。信号运行时从结构上检测功能（因此它可以跨包边界工作），并且仅在所有方法都存在时才使用它。

```typescript title="src/mastra/pubsub.ts"
import { PubSub } from '@mastra/core/events'
import type { LeaseProvider } from '@mastra/core/events'

export class CustomPubSub extends PubSub implements LeaseProvider {
  async acquireLease(key: string, owner: string, ttlMs: number) {
    // Atomically claim the lease, or report the current holder.
    return { acquired: true, owner }
  }

  // ...getLeaseOwner, releaseLease, renewLease, transferLease
}
```

## 方法 {/* #methods */}

### 租赁 {/* #leasing */}

#### `acquireLease(key, owner, ttlMs)` {/* #acquireleasekey-owner-ttlms */}

以原子方式尝试获取密钥的租约。退货`{ acquired: true, owner }` if the caller claimed the lease, or `{ acquired: false, owner }` where `owner` is the current holder, so the caller can route follow-up work to them. A failed acquisition can omit `owner` when the holder is unknown, for example when the backend is closed or the competing lease expired before it could be read. Check for `owner` before routing to it. The same owner can call `acquireLease` idempotently to renew or re-claim.

```typescript
const result = await pubsub.acquireLease('thread:abc', runId, 15000)

if (result.acquired) {
  // This process owns the thread, so wake and run the agent.
} else if (result.owner) {
  // result.owner holds the lease, so route the signal to them.
} else {
  // The holder is unknown, so retry acquisition or report the failure instead of dropping the work.
}
```

返回：`Promise<{ acquired: boolean; owner?: string }>`

#### `getLeaseOwner(key)` {/* #getleaseownerkey */}

读取租约的当前所有者，或`undefined` if no lease is held.

```typescript
const owner = await pubsub.getLeaseOwner('thread:abc')
```

返回：`Promise<string | undefined>`

#### `releaseLease(key, owner)` {/* #releaseleasekey-owner */}

释放租约。如果调用者不是当前所有者，则这是一个无操作：实现在释放之前自动检查所有权，因此另一个所有者的并发更新永远不会被破坏。

```typescript
await pubsub.releaseLease('thread:abc', runId)
```

返回：`Promise<void>`

#### `renewLease(key, owner, ttlMs)` {/* #renewleasekey-owner-ttlms */}

续签拥有的现有租约`owner`, extending its TTL. Returns `true` if the renewal succeeded and the caller still owns the lease, or `false` if the lease was lost (TTL expired or another owner took it).

```typescript
const stillOwned = await pubsub.renewLease('thread:abc', runId, 15000)

if (!stillOwned) {
  // Lost the lease, so stop renewing and let the new owner take over.
}
```

返回：`Promise<boolean>`

#### `transferLease(key, fromOwner, toOwner, ttlMs)` {/* #transferleasekey-fromowner-toowner-ttlms */}

以原子方式转移持有的租约`fromOwner` to `toOwner` and refreshes its TTL without releasing the key in between. This gap-free primitive lets a follow-up owner take over the same key immediately after the current owner finishes. For example, a queued follow-up run can take over when a thread run completes. A naive release-then-acquire briefly leaves the key empty. A racing process could then win the freed lease and start a competing run.

退货`true` if `fromOwner` still held the lease and ownership moved to `toOwner`, or `false` if the lease was already lost, in which case the caller should fall back to a fresh `acquireLease`.

```typescript
const transferred = await pubsub.transferLease('thread:abc', currentRunId, nextRunId, 15000)

if (!transferred) {
  // Lease was lost, so acquire fresh instead.
  await pubsub.acquireLease('thread:abc', nextRunId, 15000)
}
```

返回：`Promise<boolean>`

:::警告
无法自动传输租约的后端必须使用尽力而为的方式`releaseLease(fromOwner)` followed by `acquireLease(toOwner)`. They must document that the swap is non-atomic because another process can claim the key between those calls. Keeping the method required gives callers one code path while making atomicity an explicit per-backend decision.
:::

## 能力检测 {/* #capability-detection */}

运行时检测到的信号`LeaseProvider` structurally rather than with `instanceof`, so detection works even when a separately published backend resolves a different copy of `@mastra/core`. A value is treated as a `LeaseProvider` when it exposes all five methods (`acquireLease`, `getLeaseOwner`, `releaseLease`, `renewLease`, `transferLease`).

当配置的 pub/sub 后端未实现时`LeaseProvider`, the runtime falls back to an always-win no-op provider. Every caller wins its own lease race, and release, renew, and transfer are inert, which preserves the expected single-process behavior.
