# LeaseProvider

`LeaseProvider` 定义分布式租约协议，与事件传递（[`PubSub`](/reference/pubsub/base)）相互独立。Mastra 的 [signals 层](/docs/signals/overview) 用它在多个进程（如无服务器调用）之间为资源（通常是线程键）选出唯一所有者。所有者进程负责唤醒并运行 Agent 流；其他进程会将后续工作路由给它，而不是启动竞争性运行。

当 Workflow 存储不支持运行隔离时，[持久化 Agent](/docs/harness/durable-agents#run-ownership) 也会通过租约认领每次运行，以便崩溃恢复时判断是否仍有其他进程在执行该运行。

租约与发布/订阅相互独立。`LeaseProvider` 实现必须真正协调锁，例如使用 Redis 的原子 `SET` 操作或 Lua，单进程场景则可使用内存映射。对于没有租约能力的后端，signals 运行时使用空操作 Provider，保留单进程行为。

内置的 [`RedisStreamsPubSub`](/reference/pubsub/redis-streams) 实现了 `LeaseProvider`，使 signals 能在分布式和无服务器部署中跨实例协调。

## 使用示例 {/* #usage-example */}

无需直接构造 `LeaseProvider`。配置实现该接口的发布/订阅后端（如 `RedisStreamsPubSub`）时，请将其传入 `Mastra` 构造函数，signals 运行时便会自动使用它协调跨进程工作。

```typescript title="src/mastra/index.ts"
import { Mastra } from '@mastra/core'
import { RedisStreamsPubSub } from '@mastra/redis-streams'

export const mastra = new Mastra({
  // RedisStreamsPubSub implements both PubSub and LeaseProvider
  pubsub: new RedisStreamsPubSub({
    url: process.env.REDIS_URL,
  }),
})
```

如需在自定义后端中实现租约，请实现下列方法。signals 运行时通过结构识别此能力（因此可跨 package 边界工作），并且仅在所有方法都存在时使用。

```typescript title="src/mastra/pubsub.ts"
import { PubSub } from '@mastra/core/events'
import type { LeaseProvider } from '@mastra/core/events'

export class CustomPubSub extends PubSub implements LeaseProvider {
  async acquireLease(key: string, owner: string, ttlMs: number) {
    // Atomically claim the lease, or report the current holder.
    return { acquired: true, owner }
  }

  // ...getLeaseOwner, releaseLease, renewLease, transferLease
}
```

## 方法 {/* #methods */}

### 租约操作 {/* #leasing */}

#### `acquireLease(key, owner, ttlMs)` {/* #acquireleasekey-owner-ttlms */}

以原子操作尝试取得指定键的租约。调用者取得租约时返回 `{ acquired: true, owner }`；否则返回 `{ acquired: false, owner }`，其中 `owner` 是当前持有者，调用者可将后续工作路由给它。如果持有者未知，例如后端已关闭，或竞争租约在读取前过期，失败结果可能不含 `owner`。路由前请先检查 `owner`。同一所有者可幂等调用 `acquireLease` 来续约或重新认领。

```typescript
const result = await pubsub.acquireLease('thread:abc', runId, 15000)

if (result.acquired) {
  // This process owns the thread, so wake and run the agent.
} else if (result.owner) {
  // result.owner holds the lease, so route the signal to them.
} else {
  // The holder is unknown, so retry acquisition or report the failure instead of dropping the work.
}
```

返回值：`Promise<{ acquired: boolean; owner?: string }>`

#### `getLeaseOwner(key)` {/* #getleaseownerkey */}

读取租约的当前所有者；若没有租约被持有，则返回 `undefined`。

```typescript
const owner = await pubsub.getLeaseOwner('thread:abc')
```

返回值：`Promise<string | undefined>`

#### `releaseLease(key, owner)` {/* #releaseleasekey-owner */}

释放租约。如果调用者不是当前所有者，则不执行任何操作：实现会在释放前以原子方式检查所有权，因此不会覆盖其他所有者的并发续约。

```typescript
await pubsub.releaseLease('thread:abc', runId)
```

返回值：`Promise<void>`

#### `renewLease(key, owner, ttlMs)` {/* #renewleasekey-owner-ttlms */}

延长由 `owner` 持有的现有租约的 TTL。续约成功且调用者仍持有租约时返回 `true`；若租约已失效（TTL 过期或被其他所有者取得），则返回 `false`。

```typescript
const stillOwned = await pubsub.renewLease('thread:abc', runId, 15000)

if (!stillOwned) {
  // Lost the lease, so stop renewing and let the new owner take over.
}
```

返回值：`Promise<boolean>`

#### `transferLease(key, fromOwner, toOwner, ttlMs)` {/* #transferleasekey-fromowner-toowner-ttlms */}

以原子方式将现有租约从 `fromOwner` 转给 `toOwner` 并刷新 TTL，中间不会释放键。这种无间隙操作使后续所有者能在当前所有者完成后立即接管同一键。例如，排队中的后续运行可在线程运行结束时接管。若先释放再获取，键会短暂处于无主状态，竞争进程可能抢先取得租约并启动冲突的运行。

返回 `true` 表示 `fromOwner` 仍持有租约且所有权已转给 `toOwner`；若租约已失效，返回 `false`，调用者此时应重新调用 `acquireLease`。

```typescript
const transferred = await pubsub.transferLease('thread:abc', currentRunId, nextRunId, 15000)

if (!transferred) {
  // Lease was lost, so acquire fresh instead.
  await pubsub.acquireLease('thread:abc', nextRunId, 15000)
}
```

返回值：`Promise<boolean>`

:::警告
无法以原子方式转移租约的后端，必须尽力先调用 `releaseLease(fromOwner)`，再调用 `acquireLease(toOwner)`。它们必须注明这次交接不是原子的，因为其他进程可能在两次调用之间认领该键。将此方法设为必需项，可让调用者使用同一条代码路径，同时明确各后端对原子性的选择。
:::

## 能力检测 {/* #capability-detection */}

signals 运行时检测 `LeaseProvider` 时依据结构，而非使用 `instanceof`，因此单独发布的后端即使解析到另一份 `@mastra/core` 也能被识别。一个值只有作为 `LeaseProvider` 提供全部五个方法（`acquireLease`、`getLeaseOwner`、`releaseLease`、`renewLease`、`transferLease`）时，才会被识别。

当配置的发布/订阅后端未实现 `LeaseProvider` 时，运行时会回退到始终判定获取成功的空操作 Provider。每个调用者都会赢得自己的租约竞争，而释放、续约和转移操作均不起作用，以保留预期的单进程行为。
