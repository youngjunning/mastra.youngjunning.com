# Agent.stream()

这`.stream()`该方法支持来自Agent的实时响应流，具有增强的功能和格式灵活性。此方法接受消息和可选的流媒体选项，提供当前的流媒体体验，同时支持 Mastra 的本机格式和 AI SDK v5+ 兼容性。

## 使用示例 {/* #usage-example */}

```ts
const stream = await agent.stream('message for agent')
```

：：：笔记

**型号兼容性**：此方法是为V2模型设计的。 V1 型号应使用[`.streamLegacy()`](./streamLegacy) method. The framework automatically detects your model version and will throw an error if there's a mismatch.

## `stopWhen`错误 {/* #stopwhen-errors */}

如果一个`stopWhen` predicate throws, `fullStream` rejects with that error without emitting a `step-finish`, `finish`, or `error` chunk for the failure. Catch the rejection around stream consumption:

```ts
async function consumeStream() {
  try {
    for await (const chunk of stream.fullStream) {
      console.log(chunk)
    }
  } catch (error) {
    console.error('stopWhen failed', error)
  }
}
```

持久传输根据序列化名称和消息重建跨进程错误。原始堆栈、原因和子类标识对流使用者不可用。

## 信号可见度 {/* #signal-visibility */}

信号，包括反应提醒，出现在`fullStream` by default. Set `hideSignals` to omit selected signal chunks from your stream:

```ts
const stream = await agent.stream('Review the latest changes', {
  hideSignals: ['reactive', 'system-reminder'],
})

for await (const chunk of stream.fullStream) {
  console.log(chunk)
}
```

放`hideSignals: true` to hide all recognized signal types, or `hideSignals: false` to show all signals. An array selects individual types.

该数组接受`user`, `state`, `reactive`, `notification`, and the legacy aliases `user-message` and `system-reminder`. An omitted option, `false`, or `[]` excludes nothing. Streaming normalizes `system-reminder`到`reactive`和`user-message`到`user`，然后匹配编码信号类型`data-signal`, `data-user-message`， 或者`data-user-message-pending`大块。未知或格式错误的信号块会通过，文本、错误和完成事件也是如此。

排除适用于之后`experimentalTransform`, so transforms still receive the unfiltered input. Adapters consuming `fullStream` inherit the filter, but aggregate `content`, `getFullOutput()`, response messages, callbacks, model context, and saved messages remain unchanged.

每个[thread subscription](/reference/agents/agent#subscribetothreadoptions) has its own exclusion policy, independent of the initiating stream.

同样的政策适用于`resumeStream()`, `untilIdle` continuations, and the deprecated `streamUntilIdle()` and `resumeStreamUntilIdle()` methods, including durable agents. Shared execution options also accept `hideSignals` on `generate()` and `resumeGenerate()`, but it doesn't filter their returned results. This option isn't available on HTTP or client-js request options or legacy `streamLegacy()` APIs.

与溪流不同，[memory recall](/reference/memory/recall) hides reminders by default for compatibility. Recall exclusions match stored types exactly rather than normalizing aliases. Use `['reactive', 'system-reminder']` to exclude both reminder representations across surfaces.

排除控制返回的数据，而不是授权或传送。它们不是安全边界。信号选项，例如`ifActive`, `ifIdle`, `persist`/`discard`, and `transient` retain their delivery and persistence meanings.

## 中止运行 {/* #aborting-a-run */}

通过一个[`abortSignal`](#parameters) to stop a run from outside the agent:

```ts
const controller = new AbortController()
const stream = await agent.stream('Summarize this repo', { abortSignal: controller.signal })

setTimeout(() => controller.abort(), 5_000)
```

abort 的作用和不作用：

* **该流携带一个`abort` chunk.**&#x5F53;信号触发时，运行将在下一次检查时停止，并且`fullStream` emits an `abort` chunk. The run's status ends as canceled with an `aborted` finish reason, and `onAbort` receives the steps that completed before the abort plus the assistant text streamed so far for the in-flight step.
* **中止是合作性的。**&#x5B83;在运行中的下一次检查时生效。它不会强制停止Tool代码或`onOutput` hook that's already executing, and side effects those started may still complete.
* **用户已经看到的文本被保存。**&#x4F7F;用可写内存，中止之前流式传输的辅助文本将作为普通辅助消息持久保存到线程，而不会出现错误部分。取消的运行仍会通过输出处理器，因此抛出异常的处理器仍会影响该保存。从未到达他们的输出不会被持久化。

要中止您不再持有手柄的运行，请使用`runId` with [`durableAgent.abortRunStream(runId)`](/reference/agents/durable-agent#abortrunstreamrunid), which ends the run the same way.

## 扩展使用示例 {/* #extended-usage-example */}

### Mastra 格式（默认） {/* #mastra-format-default */}

```ts title="index.ts"
import { stepCountIs } from 'ai-v5'

const stream = await agent.stream('Tell me a story', {
  stopWhen: stepCountIs(3), // Stop after 3 steps
  modelSettings: {
    temperature: 0.7,
  },
})

// Access text stream
for await (const chunk of stream.textStream) {
  console.log(chunk)
}

// or access full stream
for await (const chunk of stream.fullStream) {
  console.log(chunk)
}

// Get full text after streaming
const fullText = await stream.text
```

### 限制执行时间 {/* #limiting-execution-time */}

使用`modelSettings.timeout` to bound how long a run may take. `totalMs` limits the entire run, including every loop iteration, tool call and retry. `stepMs` limits a single model call, covering both establishing the stream and consuming it. `firstChunkMs` only applies to streaming calls and limits how long the model may take to emit its first content-bearing chunk.

```ts title="index.ts"
const stream = await agent.stream('Tell me a story', {
  modelSettings: {
    timeout: {
      totalMs: 30000, // fail the run if it takes longer than 30s
      stepMs: 10000, // fail an individual model call after 10s
      firstChunkMs: 3000, // fail a model call that produces no content within 3s
    },
  },
})
```

超出预算失败`MastraTimeoutError`, which carries a `timeoutType` of `'total'`, `'step'` or `'firstChunk'`. Each budget behaves differently when the agent is configured with fallback [`models`](/reference/agents/agent):

* 一个`totalMs` timeout ends the run immediately and doesn't try the next model, because it's a hard deadline for the run as a whole.
* 一个`stepMs` timeout isn't retried against the same model, but does advance to the next model, which makes it a way to fail over from a slow provider.
* 一个`firstChunkMs` timeout behaves like `stepMs`: it isn't retried against the same model, but does advance to the next model. Stream-start and metadata chunks don't satisfy the budget; only the first text, reasoning, tool call, file or source chunk does. Once content begins, only `stepMs` and `totalMs` remain active. Each provider retry attempt gets a fresh `firstChunkMs` budget.

嵌套`timeout` settings are merged per key across call-time and per-model `modelSettings`, so a per-model `stepMs` override keeps a call-time `firstChunkMs`.

### AI SDK v5+ 格式 {/* #ai-sdk-v5-format */}

要将流与 AI SDK v5（及更高版本）一起使用，您可以使用我们的实用函数对其进行转换`toAISdkStream`.

```ts title="index.ts"
import { stepCountIs, createUIMessageStreamResponse } from 'ai'
import { toAISdkStream } from '@mastra/ai-sdk'

const stream = await agent.stream('Tell me a story', {
  stopWhen: stepCountIs(3), // Stop after 3 steps
  modelSettings: {
    temperature: 0.7,
  },
})

// In an API route for frontend integration
return createUIMessageStreamResponse({
  stream: toAISdkStream(stream, { from: 'agent' }),
})
```

### 使用回调 {/* #using-callbacks */}

所有回调函数现在都可作为顶级属性使用，以获得更清晰的 API 体验。

```ts title="index.ts"
const stream = await agent.stream('Tell me a story', {
  onFinish: result => {
    console.log('Streaming finished:', result)
  },
  onStepFinish: step => {
    console.log('Step completed:', step)
  },
  onChunk: chunk => {
    console.log('Received chunk:', chunk)
  },
  onError: ({ error }) => {
    console.error('Streaming error:', error)
  },
  onAbort: ({ steps, text }) => {
    console.log('Stream aborted after', steps.length, 'steps')
    console.log('Partial text:', text)
  },
})

// Process the stream
for await (const chunk of stream.textStream) {
  console.log(chunk)
}
```

## 响应 WebSocket 传输 {/* #responses-websocket-transport */}

使用Provider选项选择响应 WebSocket 流式传输。这仅适用于流式调用，并且支持直接 OpenAI 模型和 Azure OpenAI 响应部署。如果 WebSocket 流不可用，Mastra 会回退到 HTTP 流。默认情况下，Mastra 在流结束时关闭 WebSocket。

```ts title="index.ts"
const stream = await agent.stream('Hello', {
  providerOptions: {
    openai: {
      transport: 'websocket', // 'websocket' | 'fetch' | 'auto'
      websocket: {
        url: 'wss://api.openai.com/v1/responses',
        closeOnFinish: true, // default
      },
    },
  },
})
```

对于 Azure OpenAI，请使用以下命令配置网关`useResponsesAPI: true`, then use `providerOptions.azure.transport`.

```ts title="index.ts"
const stream = await agent.stream('Hello', {
  providerOptions: {
    azure: {
      transport: 'websocket',
      store: false,
      websocket: { closeOnFinish: true },
    },
  },
})
```

要在流完成后保持连接打开，请设置`closeOnFinish: false` and close it manually.

```ts title="index.ts"
const stream = await agent.stream('Hello', {
  providerOptions: {
    openai: {
      transport: 'websocket',
      websocket: { closeOnFinish: false },
    },
  },
})

// Later, when you're done with the connection:
stream.transport?.close()
```

响应 WebSocket 连接一次运行一个响应。 Mastra 拒绝重叠的延续请求，其中包括`previous_response_id` on the same WebSocket transport. Wait for the active stream to finish before sending the next turn in the response chain.
