# Agent.stream()

`.stream()` 方法可实时流式返回 Agent 响应，提供更丰富的功能和灵活的格式。它接收消息和可选的流式选项，既支持 Mastra 原生格式，也兼容 AI SDK v5 及更新版本。

## 使用示例 {/* #usage-example */}

```ts
const stream = await agent.stream('message for agent')
```

:::note

**模型兼容性**：此方法适用于 V2 模型。V1 模型应使用 [`.streamLegacy()`](./streamLegacy)。框架会自动检测模型版本；如果版本不匹配，就会抛出错误。

:::

## `stopWhen`错误 {/* #stopwhen-errors */}

如果 `stopWhen` 谓词抛出错误，`fullStream` 会以该错误拒绝，而不会为此次失败发出 `step-finish`、`finish` 或 `error` 数据块。请在消费流时捕获该拒绝：

```ts
async function consumeStream() {
  try {
    for await (const chunk of stream.fullStream) {
      console.log(chunk)
    }
  } catch (error) {
    console.error('stopWhen failed', error)
  }
}
```

持久化传输会根据序列化后的错误名称和消息重建跨进程错误。流的消费方无法取得原始堆栈、cause 或子类身份。

## 信号可见性 {/* #signal-visibility */}

默认情况下，信号（包括响应式提醒）会出现在 `fullStream` 中。设置 `hideSignals` 可从流中省略指定的信号数据块：

```ts
const stream = await agent.stream('Review the latest changes', {
  hideSignals: ['reactive', 'system-reminder'],
})

for await (const chunk of stream.fullStream) {
  console.log(chunk)
}
```

设置 `hideSignals: true` 可隐藏所有已识别的信号类型；设置 `hideSignals: false` 可显示全部信号；传入数组则只隐藏指定类型。

数组可包含 `user`、`state`、`reactive`、`notification`，以及旧别名 `user-message` 和 `system-reminder`。省略该选项、传入 `false` 或 `[]` 均不会排除任何信号。流式处理会先将 `system-reminder` 规范化为 `reactive`，将 `user-message` 规范化为 `user`，再匹配 `data-signal`、`data-user-message` 或 `data-user-message-pending` 数据块中编码的信号类型。未知或格式错误的信号数据块，以及文本、错误和完成事件，都会照常通过。

排除规则在 `experimentalTransform` 之后应用，因此转换函数仍会收到未筛选的输入。消费 `fullStream` 的适配器会继承该筛选规则，但聚合的 `content`、`getFullOutput()`、响应消息、回调、模型上下文和已保存消息均不受影响。

每个[线程订阅](/reference/agents/agent#subscribetothreadoptions)都有独立的排除规则，不受启动该流时的设置影响。

相同规则也适用于 `resumeStream()`、`untilIdle` 后续轮次，以及已弃用的 `streamUntilIdle()` 和 `resumeStreamUntilIdle()`，包括持久化 Agent。共享执行选项也支持 `hideSignals`，可用于 `generate()` 和 `resumeGenerate()`，但不会筛选其返回结果。HTTP 或 client-js 请求选项以及旧版 `streamLegacy()` API 均不支持此选项。

与流式处理不同，为兼容旧行为，[Memory 召回](/reference/memory/recall)默认隐藏提醒。召回的排除规则会直接匹配存储的类型，不会规范化别名。使用 `['reactive', 'system-reminder']` 可在不同界面中同时排除两种提醒表示。

排除规则只控制返回的数据，不影响授权或投递，因此不构成安全边界。`ifActive`、`ifIdle`、`persist`/`discard` 和 `transient` 等信号选项仍保持各自的投递与持久化语义。

## 中止运行 {/* #aborting-a-run */}

传入 [`abortSignal`](#parameters)，即可从 Agent 外部中止运行：

```ts
const controller = new AbortController()
const stream = await agent.stream('Summarize this repo', { abortSignal: controller.signal })

setTimeout(() => controller.abort(), 5_000)
```

中止运行时的行为：

* **流会发出 `abort` 数据块。** Signal 触发后，运行会在下次检查时停止，`fullStream` 会发出 `abort` 数据块。运行状态以 `aborted` 结束原因为“已取消”；`onAbort` 会收到中止前已完成的步骤，以及当前步骤截至目前已流出的 assistant 文本。
* **中止采用协作方式。** 它在运行内部的下次检查时生效，不会强行停止已在执行的工具代码或 `onOutput` 钩子；它们启动的副作用仍可能完成。
* **用户已看到的文本会保存。** 如果 Memory 可写，中止前流出的 assistant 文本会作为普通 assistant 消息持久化到线程中，不包含错误部分。被取消的运行仍会经过输出处理器，因此处理器抛出的错误仍可能影响保存；未进入处理器的输出不会持久化。

如果已无法取得运行句柄，可使用 `runId` 调用 [`durableAgent.abortRunStream(runId)`](/reference/agents/durable-agent#abortrunstreamrunid)，以相同方式结束运行。


### 限制执行时间 {/* #limiting-execution-time */}

通过 `modelSettings.timeout` 限制运行时长。`totalMs` 限制整个运行，包括每次循环迭代、工具调用和重试；`stepMs` 限制单次模型调用，涵盖建立流连接和消费流的时间；`firstChunkMs` 仅适用于流式调用，限制模型发出首个含内容数据块的等待时间。

```ts title="index.ts"
const stream = await agent.stream('Tell me a story', {
  modelSettings: {
    timeout: {
      totalMs: 30000, // fail the run if it takes longer than 30s
      stepMs: 10000, // fail an individual model call after 10s
      firstChunkMs: 3000, // fail a model call that produces no content within 3s
    },
  },
})
```

超出时间预算会抛出 `MastraTimeoutError`，其 `timeoutType` 为 `'total'`、`'step'` 或 `'firstChunk'`。配置回退 [`models`](/reference/agents/agent) 时，各预算的行为不同：

* `totalMs` 超时会立即结束运行，不会尝试下一个模型，因为它是整个运行的硬性截止时间。
* `stepMs` 超时不会在同一个模型上重试，但会尝试下一个模型，可用于在 Provider 响应缓慢时故障转移。
* `firstChunkMs` 超时与 `stepMs` 类似：不会在同一模型上重试，但会尝试下一个模型。流开始和元数据数据块不算满足该预算；只有首个文本、推理、工具调用、文件或来源数据块才算。开始输出内容后，仅 `stepMs` 和 `totalMs` 继续生效。每次 Provider 重试都会重新计算 `firstChunkMs` 预算。

调用时设置的嵌套 `timeout` 与各模型的 `modelSettings` 会按键合并，因此模型级 `stepMs` 覆盖值不会清除调用级的 `firstChunkMs`。

### AI SDK v5+ 格式 {/* #ai-sdk-v5-format */}

若要将流用于 AI SDK v5 及以上版本，可使用 `toAISdkStream` 工具函数进行转换。

```ts title="index.ts"
import { stepCountIs, createUIMessageStreamResponse } from 'ai'
import { toAISdkStream } from '@mastra/ai-sdk'

const stream = await agent.stream('Tell me a story', {
  stopWhen: stepCountIs(3), // Stop after 3 steps

    temperature: 0.7,

// In an API route for frontend integration
return createUIMessageStreamResponse({
  stream: toAISdkStream(stream, { from: 'agent' }),
})
```

### 使用回调 {/* #using-callbacks */}

所有回调函数现在都可作为顶层属性传入，便于使用。

```ts title="index.ts"
const stream = await agent.stream('Tell me a story', {
  onFinish: result => {
    console.log('Streaming finished:', result)
  },
  onStepFinish: step => {
    console.log('Step completed:', step)
  },
  onChunk: chunk => {
    console.log('Received chunk:', chunk)
  },
  onError: ({ error }) => {
    console.error('Streaming error:', error)
  },
  onAbort: ({ steps, text }) => {
    console.log('Stream aborted after', steps.length, 'steps')
    console.log('Partial text:', text)
  },
})

// Process the stream
for await (const chunk of stream.textStream) {
  console.log(chunk)
}
```

## 响应 WebSocket 传输 {/* #responses-websocket-transport */}

通过 Provider 选项启用 Responses WebSocket 流式传输。它只适用于流式调用，支持直接使用 OpenAI 模型和 Azure OpenAI Responses 部署。如果 WebSocket 流不可用，Mastra 会回退到 HTTP 流式传输。默认情况下，流结束后 Mastra 会关闭 WebSocket。

```ts title="index.ts"
const stream = await agent.stream('Hello', {
  providerOptions: {
    openai: {
      transport: 'websocket', // 'websocket' | 'fetch' | 'auto'
      websocket: {
        url: 'wss://api.openai.com/v1/responses',
        closeOnFinish: true, // default
      },
    },
  },
})
```

对于 Azure OpenAI，先将网关配置为 `useResponsesAPI: true`，再使用 `providerOptions.azure.transport`。

```ts title="index.ts"
const stream = await agent.stream('Hello', {
  providerOptions: {
    azure: {
      transport: 'websocket',
      store: false,
      websocket: { closeOnFinish: true },
    },
  },
})
```

若要在流结束后保持连接打开，请设置 `closeOnFinish: false`，并在使用完毕后手动关闭。

```ts title="index.ts"
const stream = await agent.stream('Hello', {
  providerOptions: {
    openai: {
      transport: 'websocket',
      websocket: { closeOnFinish: false },
    },
  },
})

// Later, when you're done with the connection:
stream.transport?.close()
```

Responses WebSocket 连接一次只能处理一个响应。对于同一个 WebSocket 传输，Mastra 会拒绝同时包含 `previous_response_id` 的后续请求。请等当前流完成，再发送响应链中的下一轮请求。
