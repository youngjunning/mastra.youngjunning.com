# TaskSignalProvider

**新增于：** `@mastra/core@1.42.0`

通过一次 Agent 注册，集成内置任务 Tool（`task_write`、`task_update`、`task_complete`、`task_check`）和 `TaskStateProcessor`。借助它可以为 Agent 添加结构化、持久化的任务列表，无需分别配置 Tool 和处理器。

它扩展了 [`SignalProvider`](/reference/signals/signal-provider)。任务列表以 `task` 状态类型存储在线程范围的 `threadState` 存储域中，作为权威数据源；处理器再将其投影到 Agent 的 `tasks` 状态信号通道。因此，即使观测记忆被截断，任务列表仍会保留，也不会使提示词缓存失效。

## 使用示例 {/* #usage-example */}

在已配置 `Memory` 和 Mastra `storage` 的 Agent 上注册此 Provider：

```typescript title="src/mastra/index.ts"
import { Agent } from '@mastra/core/agent'
import { TaskSignalProvider } from '@mastra/core/signals'

const agent = new Agent({
  id: 'coder',
  name: 'coder',
  instructions: '...',
  model,
  memory,
  signals: [new TaskSignalProvider()],
})
```

Agent 会自动将四个任务 Tool 加入工具集，并把处理器注册到输入处理器链，无需额外配置。

任务跟踪需要由 Memory 支持的线程（`threadId` + `resourceId`）。若未配置 Memory，任务 Tool 不执行操作，并返回说明任务跟踪需要 Agent Memory 的结果。`threadState` 存储域默认使用内存实现，因此无需配置存储后端也能跟踪任务。

## 方法 {/* #methods */}

### 与 Agent 集成 {/* #agent-integration */}

将 Provider 传入 `signals` 后，Agent 会自动调用这些方法，通常无需手动调用。

#### `getTools()` {/* #gettools */}

返回以 Tool ID（`task_write`、`task_update`、`task_complete`、`task_check`）为键的四个任务 Tool。Agent 会将它们加入工具集。

```typescript
const tools = new TaskSignalProvider().getTools()
// { task_write, task_update, task_complete, task_check }
```

返回： `Record<string, Tool>`

#### `getInputProcessors()` {/* #getinputprocessors */}

返回 Provider 的 `TaskStateProcessor` 实例。Agent 将其注册到输入处理器链，并沿该链传递 Mastra 实例，使处理器能够解析 `threadState` 存储。

```typescript
const [processor] = new TaskSignalProvider().getInputProcessors()
// processor instanceof TaskStateProcessor
```

返回： `InputProcessorOrWorkflow[]`
