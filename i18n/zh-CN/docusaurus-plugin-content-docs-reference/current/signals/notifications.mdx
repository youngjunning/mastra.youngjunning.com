# Notifications

通知收件箱记录是 `agent.sendNotificationSignal()` 持久化的状态，与投递到线程的通知信号不是同一个对象。记录追踪路由、优先级、投递状态、去重和重试历史；信号的元数据包含记录的摘要及快照。

使用 [`Agent.sendNotificationSignal()`](/reference/agents/agent#sendnotificationsignalnotification-options) 创建记录；投递流程请参阅[通知指南](/docs/signals/notifications)。

## 合并待处理记录 {/* #coalescing-pending-records */}

`sendNotificationSignal()` 可以把新通知合并到现有待处理记录，而不是再创建一条。只有线程、来源、类型、Agent 和资源均相同的记录才会参与合并。

每个键都有不同的用途：

- `dedupeKey` 标识同一事件。重试或重复的 Webhook 应更新现有记录时，复用此键。
- `coalesceKey` 将相关事件归为一组。多个事件应合并为一条记录时使用，例如同一条流水线的多次失败。

两个键用途不同，但遵循相同的匹配规则。

当通知合并时：

- 新的 `summary` 和 `payload` 会替换旧值。
- 新通知提供 `priority` 时会更新优先级。
- `attributes` 和 `metadata` 会合并，新值优先。
- `coalescedCount` 增加。

## 优先级与状态 {/* #priorities-and-statuses */}

`NotificationPriority` 控制默认投递时机。

```typescript
type NotificationPriority = 'low' | 'medium' | 'high' | 'urgent'
```

`NotificationStatus` 表示记录的生命周期。

```typescript
type NotificationStatus =
  | 'pending'
  | 'delivered'
  | 'seen'
  | 'dismissed'
  | 'archived'
  | 'discarded'
  | 'failed'
```

`pending` 记录可以进入派发流程。`delivered` 表示已发出完整的通知信号。`seen`、`dismissed` 和 `archived` 是收件箱状态。`discarded` 表示投递策略拒绝该通知。`failed` 表示投递已达到五次尝试上限。

## 投递决策 {/* #delivery-decisions */}

投递策略会返回一个 `NotificationDeliveryDecision`。

```typescript
type NotificationDeliveryAction =
  | 'deliver'
  | 'queue'
  | 'defer'
  | 'summarize'
  | 'persist'
  | 'discard'

type NotificationDeliveryDecision = {
  action: NotificationDeliveryAction
  deliverAt?: Date
  summaryAt?: Date
  reason?: string
  streamOptions?: AgentExecutionOptions<unknown>
  hold?: boolean
}
```

`deliver` 立即发出完整的通知信号。`queue` 和 `defer` 让记录保持待处理，供稍后派发。`summarize` 发出摘要或安排稍后发出。`persist` 只存储记录，不发出信号。`discard` 将记录标记为已丢弃，不进行投递。

唤醒空闲线程进行投递时会附加 `streamOptions`。它们在投递时解析，因此即使通知经过延迟或摘要处理，仍可携带被唤醒线程需要的运行选项，例如模型选择。

`hold` 只在投递时生效。它让通知保持待处理，且不计为一次尝试，以便由另一进程的派发器投递。当某进程共享通知存储却无法运行目标线程时，可使用它。首次发送通知时会忽略 `hold`。

## 投递策略 {/* #delivery-policies */}

通过 Agent 构造函数的 `notifications.deliveryPolicy` 选项配置策略。

```typescript
type NotificationDeliveryPolicyConfig = {
  default?: NotificationDeliveryAction | NotificationDeliveryDecision
  priorities?: Partial<
    Record<NotificationPriority, NotificationDeliveryAction | NotificationDeliveryDecision>
  >
  sources?: Record<string, NotificationDeliveryAction | NotificationDeliveryDecision>
  decide?: (
    input: NotificationDeliveryPolicyInput,
  ) =>
    | NotificationDeliveryAction
    | NotificationDeliveryDecision
    | undefined
    | Promise<NotificationDeliveryAction | NotificationDeliveryDecision | undefined>
}

type NotificationDeliveryPolicyInput = {
  record: NotificationRecord
  threadState: 'active' | 'idle'
  now: Date
}
```

Mastra 按以下顺序评估该政策：

1. `decide`
1. `sources`：与 `record.source` 匹配
1. `priorities`：与 `record.priority` 匹配
4. `default`
1. 内置优先级策略

内置策略是：

| 优先级 | 空闲线程 | 运行中线程 |
| - | - | - |
| `urgent` | 立即投递 | 立即投递 |
| `high` | 立即投递 | 立即发出摘要，待线程空闲后再投递 |
| `medium` | 立即投递 | 批量汇总为摘要 |
| `low` | 批量汇总为摘要 | 批量汇总为摘要 |

自定义 `decide` 函数会在收到通知时运行；若当时的决策是延迟投递或安排摘要，投递时还会再次运行。记录中持久化的计划决定了投递时间和方式。投递时的决策只采纳 `streamOptions` 和 `hold`。请确保决策函数没有副作用。

## 已投递信号的元数据 {/* #delivered-signal-metadata */}

记录投递后，流的消费者会收到带有 `NotificationSignalMetadata` 的通知信号。

```typescript
type NotificationSignalMetadata = {
  signal: 'notification'
  recordId: string
  source: string
  kind: string
  priority: NotificationPriority
  status: NotificationStatus
  coalescedCount?: number
  deliveredAt?: string
  seenAt?: string
}
```

Mastra 发出摘要时，消费者会收到带有 `NotificationSummarySignalMetadata` 的摘要信号。

```typescript
type NotificationSummarySignalMetadata = {
  signal: 'summary'
  pending: number
  groups: Array<{ source: string; count: number }>
  byPriority: Partial<Record<NotificationPriority, number>>
  notificationIds: string[]
  priority?: NotificationPriority
}
```

这些元数据结构描述的是信号。存储的记录不是信号，信号也不包含记录的 `payload` 或重试历史。

## 存储 {/* #storage */}

通知记录需要支持 `notifications` 的存储域，例如 libSQL、PostgreSQL 或 MongoDB。否则，`sendNotificationSignal()` 无法存储记录。

`sendSignal({ type: 'notification' })` 会绕过收件箱存储，直接投递通知形式的上下文。若要让 Agent 读取和管理已存储的记录，请使用 [`createNotificationInboxTool()`](/reference/signals/create-notification-inbox-tool)。
