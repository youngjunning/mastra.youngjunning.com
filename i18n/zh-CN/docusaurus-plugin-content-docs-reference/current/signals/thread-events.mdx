# 线程事件

`subscribeThreadEvents()` 用于观察线程中本地待处理的输入。它只提供队列计数事件；负责流式输出 Agent 结果的 [`subscribeToThread()`](/reference/agents/agent#subscribetothreadoptions) 则是另一套订阅接口。

## `subscribeThreadEvents(scope, listener)` {/* #subscribethreadeventsscope-listener */}

订阅指定资源和线程的事件。

```typescript
const scope = {
  resourceId: 'user-123',
  threadId: 'thread-abc',
}

const unsubscribe = agent.subscribeThreadEvents(scope, event => {
  if (event.type === 'queue-count-changed') {
    console.log(`${event.count} messages are pending`)
  }
})

// Later, when you no longer need updates:
unsubscribe()
```

当线程上有活跃的运行，并调用 [`queueMessage()`](/reference/agents/agent#queuemessagemessage-options) 或 [`queueSignal()`](/reference/agents/agent#queuesignalsignal-options) 时，计数会变化。

订阅时，监听器会同步收到一次包含当前本地计数的初始事件；此后仅在计数变化时收到更新。返回的取消订阅函数可重复调用，且不会取消已排队的消息。

计数仅反映当前运行时的状态。使用同一运行时和 PubSub 实例的其他 Session 或 Agent 提交的消息也计入其中。

计数包括在本地 FIFO 队列中等待的消息，以及获取或转移租约期间尚未取消的消息。取消、移交执行、转发给其他所有者或执行失败时，计数会下降；模型生成结束时不会因此下降。空闲时调用 `queueMessage()` 会立即移交消息，不会形成可取消的待处理队列项。

计数仅涵盖 [`queueMessage()`](/reference/agents/agent#queuemessagemessage-options) 和 [`queueSignal()`](/reference/agents/agent#queuesignalsignal-options) 共用队列中的条目，不包括等待送入活跃运行的 Signal。

按所有者限定观察范围时，会同时匹配调用方 Agent、其本地运行时、资源、线程和所有者 ID。可使用 [`cancelQueuedMessages()`](/reference/agents/agent#cancelqueuedmessagesoptions) 取消指定的待处理输入或某个所有者组的输入。

AgentController Session 订阅后，即使尚未提交后续输入，也会观察共享线程的计数。`session.steer()` 会在发送新输入前中止当前运行，但不会清除已排队的后续输入。清理 Session 时会停止观察并取消未完成的本地准备工作，但已提交的消息仍留在 Agent 队列中。

## `AgentThreadEvent` {/* #agentthreadevent */}

目前唯一会发出的事件类型是 `queue-count-changed`。

```typescript
type AgentThreadEvent = {
  type: 'queue-count-changed'
  count: number
}
```

`count` 是所观察队列中本地待处理消息的数量。复合线程状态、单条消息的生命周期、运行和审批事件均不会作为公开线程事件发出。Mastra 今后可能将它们作为独立事件类型加入。
