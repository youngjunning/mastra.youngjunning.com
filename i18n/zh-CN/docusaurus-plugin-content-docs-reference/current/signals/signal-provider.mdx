# 信号提供者

**添加于：** `@mastra/core@1.42.0`

用于构建信号提供者的抽象基类。信号提供程序监视外部源（API、Webhook、事件流）并通过内置订阅注册表将通知信号推送到Agent线程中。

默认情况下，信号提供者不是处理器。需要拦截Agent执行的提供者从返回处理器`getInputProcessors()` or `getOutputProcessors()`. Providers that expose agent-callable tools return them from `getTools()`.

对于即用型基于 Webhook 的提供程序，请参阅[`WebhookSignalProvider`](/reference/signals/webhook-signal-provider).

## 使用示例 {/* #usage-example */}

每 30 秒检查一次 API 的轮询提供程序：

```typescript title="src/signals/slack-signals.ts"
import { SignalProvider } from '@mastra/core/signals'
import type { SignalSubscription } from '@mastra/core/signals'

class SlackSignals extends SignalProvider<'slack-signals'> {
  readonly id = 'slack-signals'
  readonly pollInterval = 30_000

  async poll(subscriptions: SignalSubscription[]) {
    for (const sub of subscriptions) {
      const messages = await fetchSlackMessages(sub.externalResourceId)
      if (messages.length > 0) {
        await this.notify(
          {
            source: 'slack',
            kind: 'new-messages',
            summary: `${messages.length} new messages in ${sub.externalResourceId}`,
          },
          { threadId: sub.threadId, resourceId: sub.resourceId },
        )
      }
    }
  }
}
```

向Agent商注册：

```typescript title="src/mastra/index.ts"
import { Agent } from '@mastra/core/agent'

const agent = new Agent({
  id: 'agent',
  signals: [new SlackSignals()],
})
```

Agent打电话`connect(this)` and registers any processors or tools the provider returns. It then starts polling.

## 方法 {/* #methods */}

### 联系 {/* #connection */}

#### `connect(agent)` {/* #connectagent */}

由Agent构造函数调用。建立双向链接，以便提供者可以将信号发送回Agent。建立链接后覆盖以运行其他设置。总是打电话`super.connect(agent)`.

```typescript
class MySignals extends SignalProvider<'my-signals'> {
  readonly id = 'my-signals'

  override connect(agent) {
    super.connect(agent)
    // additional setup after agent link is established
  }
}
```

#### `__registerMastra(mastra)` {/* #__registermastramastra */}

当提供者的Agent向 Mastra 实例注册时调用。覆盖以访问存储或其他 Mastra 服务。总是打电话`super.__registerMastra(mastra)`.

```typescript oxfmt:false
override __registerMastra(mastra) {
  super.__registerMastra(mastra)
  // this.mastra is now available
}
```

### 处理器和Tool集成 {/* #processor-and-tool-integration */}

#### `getInputProcessors()` {/* #getinputprocessors */}

返回输入处理器该提供者需要向Agent注册。当您的提供程序拦截Agent输入步骤（例如，注入上下文提示或检测Tool调用）时进行覆盖。

```typescript oxfmt:false
getInputProcessors() {
  return [this]
}
```

返回：`InputProcessorOrWorkflow[]`

#### `getOutputProcessors()` {/* #getoutputprocessors */}

返回输出处理器该提供者需要向Agent注册。当您的提供程序拦截Agent输出步骤时覆盖。

```typescript oxfmt:false
getOutputProcessors() {
  return [this]
}
```

返回：`OutputProcessorOrWorkflow[]`

#### `getTools()` {/* #gettools */}

返回该提供者向Agent公开的Tool。当您的Provider添加Agent可调用Tool（例如订阅或取消订阅命令）时进行覆盖。

```typescript oxfmt:false
getTools() {
  return {
    subscribe_pr: createTool({ /* ... */ }),
    unsubscribe_pr: createTool({ /* ... */ }),
  }
}
```

返回：`Record<string, unknown>`

### 订阅追踪 {/* #subscription-tracking */}

```typescript
)
```

### 轮询 {/* #polling */}

#### `poll(subscriptions)` {/* #pollsubscriptions */}

在每个轮询周期对所有活动订阅进行调用。覆盖以检查外部源并发出通知。该框架防止轮询周期重叠：如果`poll()` call takes longer than `pollInterval`, the next cycle is skipped.

```typescript oxfmt:false
async poll(subscriptions: SignalSubscription[]) {
  for (const sub of subscriptions) {
    const events = await checkExternalSource(sub.externalResourceId)
    for (const event of events) {
      await this.notify(
        { source: 'my-provider', kind: event.type, summary: event.message },
        { threadId: sub.threadId, resourceId: sub.resourceId },
      )
    }
  }
}
```

#### `startPolling()` {/* #startpolling */}

启动轮询计时器。之后由Agent致电`connect()`. Idempotent: calling multiple times has no effect.

```typescript
provider.startPolling()
```

#### `stopPolling()` {/* #stoppolling */}

停止轮询计时器。

```typescript
provider.stopPolling()
```

### 网络钩子 {/* #webhooks */}

#### `handleWebhook(request)` {/* #handlewebhookrequest */}

处理传入的 Webhook 请求。重写以解析有效负载并将其与订阅匹配。然后发出通知信号。看[`WebhookSignalProvider`](/reference/signals/webhook-signal-provider) for a ready-to-use implementation.

从返回的路由调用此方法[`getRoutes()`](#getroutes) or from your own HTTP endpoint, after verifying the webhook request.

```typescript oxfmt:false
async handleWebhook(request) {
  const payload = request.body as { repo: string, event: string }
  const subs = this.getSubscriptionsForResource(payload.repo)

  for (const sub of subs) {
    await this.notify(
      { source: 'github', kind: payload.event, summary: `Event on ${payload.repo}` },
      { threadId: sub.threadId, resourceId: sub.resourceId },
    )
  }

  return { status: 200, body: { matched: subs.length } }
}
```

返回：`Promise<{ status?: number; body?: unknown }>`

#### `getRoutes()` {/* #getroutes */}

返回该Provider在 Mastra 服务器上所需的 API 路由，例如 Webhook 接收器或 OAuth 回调。选修的。当Provider的Agent注册后，Mastra 将这些路由添加到`server.apiRoutes`, so you don't add them by hand.

Agent注册时会收集路由。如果您添加Agent`addAgent()` after the server has started, its provider routes aren't served until the server restarts. `removeAgent()` removes the agent's provider routes, unless another registered agent uses the same provider instance.

如果已注册具有相同方法和路径的路由，则现有路由获胜：

* 由多个Agent共享的提供者只需安装一次其路由。
* 一条路线在`server.apiRoutes` or a file-system route replaces the provider route, and Mastra logs a warning.
* 如果两个不同的Provider声明相同的路线，则安装第一个注册的Provider，并且 Mastra 会记录警告。

```typescript oxfmt:false
getRoutes() {
  return [
    registerApiRoute('/acme/webhook', {
      method: 'POST',
      requiresAuth: false,
      handler: async c => {
        // Public route: verify the sender before handling the payload
        const rawBody = await c.req.text()
        if (!verifyAcmeSignature(rawBody, c.req.header('x-acme-signature'))) {
          return c.json({ error: 'invalid signature' }, 401)
        }
        const result = await this.handleWebhook({ body: JSON.parse(rawBody), headers: c.req.header() })
        return c.json(result.body ?? {}, result.status ?? 200)
      },
    }),
  ]
}
```

返回：`ApiRoute[]`

Provider路线遵循与其他路线相同的规则[custom API routes](/docs/server/custom-api-routes#authentication). Adding a provider to an agent mounts its routes with no extra step from the user, so set access on each route deliberately:

* 当服务器配置了身份验证时，路由默认需要身份验证。
* 一条路线与`requiresAuth: false` is public. Verify the sender, for example with a webhook signature, before calling `handleWebhook()`.
* 应设置经过身份验证的路由`requiresPermission` or `fga`. When an FGA provider audits protected routes, routes with neither are reported at startup.
* 路径不能以服务器的开头`apiPrefix` (`/api` by default). The server throws at startup. Use a provider-specific prefix such as `/acme/...`.

### 生命周期 {/* #lifecycle */}

#### `start()` {/* #start */}

之后调用`connect()` to run async initialization. Override when setup requires the agent or Mastra instance to be available.

```typescript oxfmt:false
async start() {
  await this.loadInitialState()
}
```

#### `stop()` {/* #stop */}

打电话叫关机。默认实现停止轮询并清除所有订阅。

```typescript
provider.stop()
```
