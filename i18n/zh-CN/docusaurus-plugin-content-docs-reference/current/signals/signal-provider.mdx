# SignalProvider

**新增于：** `@mastra/core@1.42.0`

这是构建信号 Provider 的抽象基类。信号 Provider 监控外部来源（API、Webhook、事件流），并通过内置的订阅注册表向 Agent 线程推送通知信号。

信号 Provider 默认不是处理器。需要拦截 Agent 执行过程的 Provider，可通过 `getInputProcessors()` 或 `getOutputProcessors()` 返回处理器；需要向 Agent 提供可调用 Tool 的 Provider，可通过 `getTools()` 返回 Tool。

如需开箱即用、基于 Webhook 的 Provider，请参阅 [`WebhookSignalProvider`](/reference/signals/webhook-signal-provider)。

## 用法示例 {/* #usage-example */}

以下轮询 Provider 每 30 秒检查一次 API：

```typescript title="src/signals/slack-signals.ts"
import { SignalProvider } from '@mastra/core/signals'
import type { SignalSubscription } from '@mastra/core/signals'

class SlackSignals extends SignalProvider<'slack-signals'> {
  readonly id = 'slack-signals'
  readonly pollInterval = 30_000

  async poll(subscriptions: SignalSubscription[]) {
    for (const sub of subscriptions) {
      const messages = await fetchSlackMessages(sub.externalResourceId)
      if (messages.length > 0) {
        await this.notify(
          {
            source: 'slack',
            kind: 'new-messages',
            summary: `${messages.length} new messages in ${sub.externalResourceId}`,
          },
          { threadId: sub.threadId, resourceId: sub.resourceId },
        )
      }
    }
  }
}
```

将其注册到 Agent：

```typescript title="src/mastra/index.ts"
import { Agent } from '@mastra/core/agent'

const agent = new Agent({
  id: 'agent',
  signals: [new SlackSignals()],
})
```

Agent 会调用 `connect(this)`，注册 Provider 返回的处理器或 Tool，然后启动轮询。

## 方法 {/* #methods */}

### 连接 {/* #connection */}

#### `connect(agent)` {/* #connectagent */}

由 Agent 构造函数调用，建立双向连接，让 Provider 能向 Agent 发送信号。可覆盖此方法，在连接建立后执行额外设置；始终要调用 `super.connect(agent)`。

```typescript
class MySignals extends SignalProvider<'my-signals'> {
  readonly id = 'my-signals'

  override connect(agent) {
    super.connect(agent)
    // additional setup after agent link is established
  }
}
```

#### `__registerMastra(mastra)` {/* #__registermastramastra */}

当 Provider 所属的 Agent 注册到 Mastra 实例时调用。可覆盖此方法以访问存储或其他 Mastra 服务；始终要调用 `super.__registerMastra(mastra)`。

```typescript oxfmt:false
override __registerMastra(mastra) {
  super.__registerMastra(mastra)
  // this.mastra is now available
}
```

### 处理器与 Tool 集成 {/* #processor-and-tool-integration */}

#### `getInputProcessors()` {/* #getinputprocessors */}

返回需要注册到 Agent 的输入处理器。若 Provider 要拦截 Agent 输入阶段（例如注入上下文提示或检测 Tool 调用），请覆盖此方法。

```typescript oxfmt:false
getInputProcessors() {
  return [this]
}
```

返回：`InputProcessorOrWorkflow[]`

#### `getOutputProcessors()` {/* #getoutputprocessors */}

返回需要注册到 Agent 的输出处理器。若 Provider 要拦截 Agent 输出阶段，请覆盖此方法。

```typescript oxfmt:false
getOutputProcessors() {
  return [this]
}
```

返回：`OutputProcessorOrWorkflow[]`

#### `getTools()` {/* #gettools */}

返回此 Provider 向 Agent 提供的 Tool。若 Provider 添加订阅、取消订阅等 Agent 可调用的 Tool，请覆盖此方法。

```typescript oxfmt:false
getTools() {
  return {
    subscribe_pr: createTool({ /* ... */ }),
    unsubscribe_pr: createTool({ /* ... */ }),
  }
}
```

返回：`Record<string, unknown>`

### 订阅跟踪 {/* #subscription-tracking */}

#### `subscribe(target, externalResourceId, metadata?)` {/* #subscribetarget-externalresourceid-metadata */}

让一个线程订阅外部资源。此方法受保护，只能在 Provider 实现内部调用。

```typescript
const sub = this.subscribe(
  { threadId: 'thread-1', resourceId: 'user-1' },
  'github:mastra-ai/mastra#123',
  { pr: 123 },
)
```

返回：`SignalSubscription`，即新建订阅，或合并了元数据的现有订阅。

### 轮询 {/* #polling */}

#### `poll(subscriptions)` {/* #pollsubscriptions */}

每个轮询周期调用一次，并传入所有活跃订阅。可覆盖此方法来检查外部来源并发送通知。框架会避免轮询周期重叠：如果一次 `poll()` 的执行时间超过 `pollInterval`，则跳过下一周期。

```typescript oxfmt:false
async poll(subscriptions: SignalSubscription[]) {
  for (const sub of subscriptions) {
    const events = await checkExternalSource(sub.externalResourceId)
    for (const event of events) {
      await this.notify(
        { source: 'my-provider', kind: event.type, summary: event.message },
        { threadId: sub.threadId, resourceId: sub.resourceId },
      )
    }
  }
}
```

#### `startPolling()` {/* #startpolling */}

启动轮询定时器。Agent 在 `connect()` 后调用此方法。重复调用不会产生额外效果。

```typescript
provider.startPolling()
```

#### `stopPolling()` {/* #stoppolling */}

停止轮询定时器。

```typescript
provider.stopPolling()
```

### Webhook {/* #webhooks */}

#### `handleWebhook(request)` {/* #handlewebhookrequest */}

处理传入的 Webhook 请求。可覆盖此方法来解析载荷、匹配订阅并发送通知信号。现成实现参见 [`WebhookSignalProvider`](/reference/signals/webhook-signal-provider)。

验证 Webhook 请求后，从 [`getRoutes()`](#getroutes) 返回的路由或自定义 HTTP 端点调用此方法。

```typescript oxfmt:false
async handleWebhook(request) {
  const payload = request.body as { repo: string, event: string }
  const subs = this.getSubscriptionsForResource(payload.repo)

  for (const sub of subs) {
    await this.notify(
      { source: 'github', kind: payload.event, summary: `Event on ${payload.repo}` },
      { threadId: sub.threadId, resourceId: sub.resourceId },
    )
  }

  return { status: 200, body: { matched: subs.length } }
}
```

返回：`Promise<{ status?: number; body?: unknown }>`

#### `getRoutes()` {/* #getroutes */}

返回此 Provider 在 Mastra 服务器上需要的 API 路由，例如 Webhook 接收端点或 OAuth 回调。此方法可选。注册 Provider 所属 Agent 时，Mastra 会将这些路由加入 `server.apiRoutes`，无需手动添加。

注册 Agent 时会收集其路由。若服务器启动后才通过 `addAgent()` 添加 Agent，其 Provider 路由要到服务器重启后才能提供服务。调用 `removeAgent()` 会移除该 Agent 的 Provider 路由，除非另一个已注册 Agent 使用同一 Provider 实例。

若相同方法和路径的路由已注册，现有路由优先：

- 多个 Agent 共享一个 Provider 时，其路由只挂载一次。
- `server.apiRoutes` 中的路由或文件系统路由会取代 Provider 路由，Mastra 同时记录警告。
- 如果两个不同的 Provider 声明相同路由，先注册的路由会挂载，Mastra 同时记录警告。

```typescript oxfmt:false
getRoutes() {
  return [
    registerApiRoute('/acme/webhook', {
      method: 'POST',
      requiresAuth: false,
      handler: async c => {
        // Public route: verify the sender before handling the payload
        const rawBody = await c.req.text()
        if (!verifyAcmeSignature(rawBody, c.req.header('x-acme-signature'))) {
          return c.json({ error: 'invalid signature' }, 401)
        }
        const result = await this.handleWebhook({ body: JSON.parse(rawBody), headers: c.req.header() })
        return c.json(result.body ?? {}, result.status ?? 200)
      },
    }),
  ]
}
```

返回：`ApiRoute[]`

Provider 路由遵循其他[自定义 API 路由](/docs/server/custom-api-routes#authentication)的相同规则。将 Provider 加入 Agent 后，路由会自动挂载，因此应明确设置每条路由的访问权限：

- 服务器配置了身份验证时，路由默认需要身份验证。
- 设置 `requiresAuth: false` 的路由是公开路由。调用 `handleWebhook()` 前，应通过 Webhook 签名等方式验证发送方。
- 已通过身份验证的路由应设置 `requiresPermission` 或 `fga`。FGA Provider 审计受保护路由时，若两者都未设置，启动时会报告。
- 路径不能以服务器的 `apiPrefix`（默认为 `/api`）开头，否则服务器启动时会抛错。可使用 `/acme/...` 等 Provider 专属前缀。

### 生命周期 {/* #lifecycle */}

#### `start()` {/* #start */}

在 `connect()` 之后调用，用于异步初始化。若初始化需要访问 Agent 或 Mastra 实例，请覆盖此方法。

```typescript oxfmt:false
async start() {
  await this.loadInitialState()
}
```

#### `stop()` {/* #stop */}

关闭时调用。默认实现会停止轮询并清除所有订阅。

```typescript
provider.stop()
```

### 通知 {/* #notifications */}

```typescript
await this.notify(
  {
    source: 'my-provider',
    kind: 'pr-updated',
    summary: 'PR #123 was updated',
    priority: 'high',
    payload: { prNumber: 123 },
  },
  { threadId: 'thread-1', resourceId: 'user-1' },
)
```
