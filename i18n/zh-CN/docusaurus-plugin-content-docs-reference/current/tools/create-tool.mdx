# createTool()

使用 `createTool()` 函数可以定义供 Mastra Agent 执行的自定义 Tool，扩展 Agent 的能力，例如与外部系统交互、执行计算或访问特定数据。

## 使用示例 {/* #usage-example */}

```typescript title="src/mastra/tools/weather-tool.ts"
import { createTool } from '@mastra/core/tools'
import { z } from 'zod'

export const weatherTool = createTool({
  id: 'weather-tool',
  description: 'Get the current weather for a location',
  inputSchema: z.object({
    location: z.string(),
  }),
  outputSchema: z.object({
    location: z.string(),
    temperatureCelsius: z.number(),
    conditions: z.string(),
  }),
  execute: async ({ location }) => {
    return {
      location,
      temperatureCelsius: 21,
      conditions: 'sunny',
    }
  },
})
```

`execute` 的第一个参数是经过 `inputSchema` 验证的值。可以像 `{ location }` 一样，直接在函数签名中解构模式中定义的字段。第二个参数可选，包含执行上下文。

### 仅用于显示的 Tool {/* #display-only-tools */}

如果 Tool 只需让客户端显示内容，请设置 `renderOnly: true`，无需定义 `execute`：

```typescript
const showCard = createTool({
  id: 'show-card',
  description: 'Display a product card',
  inputSchema: z.object({ productId: z.string() }),
  renderOnly: true,
})
```

Mastra 会在流中发出 Tool 调用，并返回 `{ acknowledged: true }` 作为调用结果，Agent 无需等待客户端回复即可继续生成文本。子 Agent 的 Tool 也支持这种方式，其调用会以嵌套的 `tool-output` 流事件出现。不要为仅用于显示的 Tool 设置与确认结果不兼容的 `outputSchema`。确认结果只表示调用已发出，**不**表示浏览器已渲染内容。如果 Agent 需要根据客户端操作的结果继续处理，请省略 `execute`，由客户端返回结果。如果子 Agent 需要用户输入，也可以使用可挂起的服务端 Tool。

## 对 Tool 输入启用严格模式的示例 {/* #example-with-strict-tool-inputs */}

设置 `strict: true` 后，Mastra 会要求支持严格模式的模型 Provider 生成完全符合 Tool 架构定义的参数。

```typescript title="src/mastra/tools/weather-tool.ts"
import { createTool } from '@mastra/core/tools'
import { z } from 'zod'

export const weatherTool = createTool({
  id: 'weather-tool',
  description: 'Get the current weather for a location',
  strict: true,
  inputSchema: z.object({
    location: z.string(),
  }),
  outputSchema: z.object({
    location: z.string(),
    temperatureCelsius: z.number(),
    conditions: z.string(),
  }),
  execute: async ({ location }) => {
    return {
      location,
      temperatureCelsius: 21,
      conditions: 'sunny',
    }
  },
})
```

Mastra 仅向支持严格模式 Tool 调用的模型适配器传递 `strict: true`，对其他适配器则忽略此选项。

## `toModelOutput` 示例 {/* #example-with-tomodeloutput */}

当应用需要获取 Tool 返回的详细内部数据，而模型只需接收简化后的值或多模态内容时，请使用 `toModelOutput`。

```typescript title="src/mastra/tools/weather-tool.ts"
import { createTool } from '@mastra/core/tools'
import { z } from 'zod'

export const weatherTool = createTool({
  id: 'weather-tool',
  description: 'Get the current weather for a location',
  inputSchema: z.object({
    location: z.string(),
  }),
  outputSchema: z.object({
    location: z.string(),
    temperatureCelsius: z.number(),
    conditions: z.string(),
    radarImageUrl: z.string().url(),
  }),
  execute: async ({ location }) => ({
    location,
    temperatureCelsius: 21,
    conditions: 'sunny',
    radarImageUrl: 'https://example.com/radar/seattle.png',
  }),
  toModelOutput: output => {
    return {
      type: 'content',
      value: [
        {
          type: 'text',
          text: `${output.location}: ${output.temperatureCelsius}°C and ${output.conditions}`,
        },
        { type: 'image-url', url: output.radarImageUrl },
      ],
    }
  },
})
```

Tool 仍会向应用返回完整的 `execute` 结果，而模型收到的是经 `toModelOutput` 转换后的值。

`toModelOutput` 可以返回：

* `type: 'text'`
* `type: 'json'`
* `type: 'content'`，其中包含 `text`、`image-url`、`image-data`、`file-url`、`file-data`、`file-id`、`image-file-id` 或 `custom` 等内容部分

`toModelOutput` 也适用于由客户端执行且未定义 `execute` 函数的 Tool。客户端在下一次请求中发回 Tool 结果后，服务端会先用 Tool 定义中的 `toModelOutput` 转换结果，再交给模型。

## `transform` 示例 {/* #example-with-transform */}

如果 Tool 在运行时需要保留原始输入或输出，但用于界面展示的数据流或对话记录中的消息只需包含更精简或更安全的数据，请使用 `transform`。

```typescript title="src/mastra/tools/customer-tool.ts"
import { createTool } from '@mastra/core/tools'
import { z } from 'zod'

export const customerTool = createTool({
  id: 'lookup-customer',
  description: 'Looks up a customer',
  inputSchema: z.object({
    customerId: z.string(),
    internalPath: z.string(),
  }),
  outputSchema: z.object({
    displayName: z.string(),
    apiKey: z.string(),
    debugScore: z.number(),
  }),
  execute: async () => {
    return {
      displayName: 'Acme',
      apiKey: 'secret-value',
      debugScore: 0.97,
    }
  },
  transform: {
    display: {
      input: ({ input }) => ({ customerId: input?.customerId }),
      output: ({ output }) => ({ displayName: output?.displayName }),
      error: () => ({ message: 'Customer lookup failed' }),
    },
    transcript: {
      input: ({ input }) => ({ customerId: input?.customerId }),
      output: ({ output }) => ({ displayName: output?.displayName }),
      error: () => ({ message: 'Customer lookup failed' }),
    },
  },
})
```

Tool 仍会接收 `inputSchema` 所定义的原始输入值，并返回 `execute` 的原始结果。Mastra 会对流式发送给界面的数据应用 `display` 转换，并对用户可见的对话记录消息应用 `transcript` 转换。

## MCP 注解示例 {/* #example-with-mcp-annotations */}

通过 MCP（Model Context Protocol）公开 Tool 时，可以添加注解来描述 Tool 的行为，并自定义 Tool 在客户端的显示方式。这些 MCP 专用属性集中在 `mcp` 属性中：

```typescript title="src/mastra/tools/weather-tool.ts"
import { createTool } from '@mastra/core/tools'
import { z } from 'zod'

export const weatherTool = createTool({
  id: 'weather-tool',
  description: 'Get the current weather for a location',
  inputSchema: z.object({
    location: z.string().describe('City name or coordinates'),
  }),
  outputSchema: z.object({
    location: z.string(),
    temperatureCelsius: z.number(),
    conditions: z.string(),
  }),
  // MCP-specific properties
  mcp: {
    // Annotations for client behavior hints
    annotations: {
      title: 'Weather Lookup', // Human-readable display name
      readOnlyHint: true, // Tool doesn't modify environment
      destructiveHint: false, // Tool doesn't perform destructive updates
      idempotentHint: true, // Same args = same result
      openWorldHint: true, // Interacts with external API
    },
    // Custom metadata for client-specific functionality
    _meta: {
      version: '1.0.0',
      category: 'weather',
    },
  },
  execute: async ({ location }) => {
    return {
      location,
      temperatureCelsius: 21,
      conditions: 'sunny',
    }
  },
})
```

## Tool 生命周期钩子 {/* #tool-lifecycle-hooks */}

Tool 支持生命周期钩子，可用于监控 Tool 执行的各个阶段并作出响应。这些钩子尤其适合在流式传输期间记录日志、分析数据、执行验证和实时更新。

以下示例展示了配置所有生命周期钩子的 Tool：

```typescript title="src/mastra/tools/weather-tool.ts"
import { createTool } from '@mastra/core/tools'
import { z } from 'zod'

export const weatherTool = createTool({
  id: 'weather-tool',
  description: 'Get the current weather for a location',
  inputSchema: z.object({
    location: z.string(),
  }),
  outputSchema: z.object({
    location: z.string(),
    temperatureCelsius: z.number(),
    conditions: z.string(),
  }),
  execute: async ({ location }) => {
    return {
      location,
      temperatureCelsius: 21,
      conditions: 'sunny',
    }
  },
  onInputStart: ({ toolCallId }) => {
    console.log(`Tool call ${toolCallId} input started`)
  },
  onInputDelta: ({ inputTextDelta, toolCallId }) => {
    console.log(`Tool call ${toolCallId} received input chunk: ${inputTextDelta}`)
  },
  onInputAvailable: ({ input, toolCallId }) => {
    console.log(`Tool call ${toolCallId} received location: ${input.location}`)
  },
  onOutput: ({ output, toolCallId, toolName }) => {
    console.log(`Tool ${toolName} call ${toolCallId} returned conditions: ${output.conditions}`)
  },
})
```

### 可用钩子 {/* #available-hooks */}

#### `onInputStart` {/* #oninputstart */}

Tool 调用的输入开始流式传输时触发，此时尚未收到任何输入数据。

```typescript
export const tool = createTool({
  id: 'example-tool',
  description: 'Example tool with hooks',
  onInputStart: ({ toolCallId, messages, abortSignal }) => {
    console.log(`Tool ${toolCallId} input streaming started`)
  },
})
```

#### `onInputDelta` {/* #oninputdelta */}

输入文本流式传入时，每收到一个增量片段就会触发。可用于显示实时进度或解析部分 JSON。

```typescript
export const tool = createTool({
  id: 'example-tool',
  description: 'Example tool with hooks',
  onInputDelta: ({ inputTextDelta, toolCallId, messages, abortSignal }) => {
    console.log(`Received input chunk: ${inputTextDelta}`)
  },
})
```

#### `onInputAvailable` {/* #oninputavailable */}

收到完整的 Tool 输入，并按 `inputSchema` 完成解析和验证后触发。

```typescript
export const tool = createTool({
  id: 'example-tool',
  description: 'Example tool with hooks',
  inputSchema: z.object({
    location: z.string(),
  }),
  onInputAvailable: ({ input, toolCallId, messages, abortSignal }) => {
    console.log(`Tool received complete input:`, input)
    // input is fully typed based on inputSchema
  },
})
```

#### `onOutput` {/* #onoutput */}

服务端执行的 Tool 返回输出后，或服务端通过后续请求收到客户端执行 Tool 的成功结果后触发。可用于记录结果或触发后续操作。

```typescript
export const tool = createTool({
  id: 'example-tool',
  description: 'Example tool with hooks',
  outputSchema: z.object({
    result: z.string(),
  }),
  execute: async input => {
    return { result: 'Success' }
  },
  onOutput: ({ output, toolCallId, toolName, abortSignal }) => {
    console.log(`${toolName} execution completed:`, output)
    // output is fully typed based on outputSchema
  },
})
```

由客户端执行的 Tool 无需定义 `execute` 函数。浏览器执行 Tool 并在后续请求中发回结果，随后服务端运行 `onOutput`。成功结果必须能与对应的 Tool 调用关联，才会触发此钩子。AI SDK 中 `error-text` 和 `error-json` 等类型的错误结果不会触发 `onOutput`。

客户端发回执行结果时，后续请求必须同时包含助手发起的 Tool 调用和对应的 Tool 结果。`@mastra/client-js` 会自动发送这两部分。仅包含 Tool 结果的请求不会触发该钩子。对于客户端执行的结果，回调只会收到 `{ toolCallId, toolName, output, abortSignal }`。

请求按至少一次投递的语义处理，重试时钩子会再次运行。请确保钩子是幂等的，并将客户端输出视为不可信数据。服务端不会按 `outputSchema` 验证结果，因此 `output` 只有静态类型约束。

### 钩子执行顺序 {/* #hook-execution-order */}

对于由服务端执行的 Tool，典型流式调用会按以下顺序触发钩子：

1. **onInputStart**：输入开始流式传输
2. **onInputDelta**：每收到一个输入片段就触发一次
3. **onInputAvailable**：完整输入已解析并验证
4. Tool 的 **execute** 函数运行
5. **onOutput**：Tool 成功执行完毕

由客户端执行 Tool 时，模型流式输出 Tool 调用期间会完成步骤 1–3，随后由客户端执行 Tool，服务端不运行 `execute`。服务端在收到包含成功结果的后续请求时运行 `onOutput`。

### 钩子参数 {/* #hook-parameters */}

源码中定义的钩子回调参数如下：

* `onInputStart`：接收 `ToolCallOptions`，其中包括 `toolCallId`、`messages` 和 `abortSignal` 等字段。
* `onInputDelta`：接收 `{ inputTextDelta: string } & ToolCallOptions`。
* `onInputAvailable`：接收 `{ input: TSchemaIn } & ToolCallOptions`，其中 `input` 的类型由 `inputSchema` 推导。
* `onOutput`：接收 `{ output: TSchemaOut; toolName: string } & Omit<ToolCallOptions, 'messages'>`，其中 `output` 的类型由 `outputSchema` 推导。此钩子不会收到 `messages`。

### 错误处理 {/* #error-handling */}

钩子抛出的错误会被自动捕获并记录到控制台。Tool 会继续执行，调用也不会因此失败。
