# 隔离Vm代码模式传输

`IsolatedVmCodeModeTransport` 类在进程内的 V8 isolate 中运行 [Code mode](/docs/agents/code-mode) 程序，底层使用 [isolated-vm](https://github.com/laverdet/isolated-vm)。isolate 本身就是执行边界，因此无需工作区 Sandbox：程序无法访问文件系统、网络、进程或模块。它唯一可用的能力是 `external_*` 函数，这些函数会回调宿主上的真实工具。

与默认的 `StdioCodeModeTransport` 相比，此传输方式不会启动进程或写入临时文件，适合无法使用操作系统级隔离的 Serverless 和多租户宿主。

## 安装 {/* #installation */}

```bash npm2yarn
npm install @mastra/isolated-vm
```

`isolated-vm` 是原生扩展。常见平台有预编译二进制文件，因此通常无需额外设置。只有平台没有匹配的预编译版本、需要从源码编译时，才需要 C++ 工具链。

在 Node.js 20 及更高版本中，如果宿主进程启动时没有 `--no-node-snapshot`，创建 isolate 会导致崩溃。构造函数会将缺少此标志报告为错误。请在启动服务器时传入，或通过 `NODE_OPTIONS` 设置：

```bash
NODE_OPTIONS=--no-node-snapshot npm run dev
```

## 用法 {/* #usage */}

将此传输方式作为第二个参数传给 `createCodeMode()`。无需 `sandbox`：

```typescript
import { createCodeMode } from '@mastra/core/tools'
import { IsolatedVmCodeModeTransport } from '@mastra/isolated-vm'

const { tool, instructions } = createCodeMode(
  { tools: { getTopProducts, getProductRatings } },
  new IsolatedVmCodeModeTransport({ memoryLimitMb: 128 }),
)
```

## 工作原理 {/* #how-it-works */}

每次运行都会创建一个拥有独立堆内存的新 isolate。宿主先用 esbuild 去除 TypeScript 类型，再在 isolate 中执行程序。每次 `external_*` 调用都会以 JSON 字符串跨越隔离边界双向传递数据，因此宿主对象引用不会泄露给模型编写的代码。允许列表、工具验证、请求上下文和 Trace 都在宿主上运行，与其他传输方式相同。

配置项 `timeout`（由 `createCodeMode()` 设置）对异步卡住和同步无限循环都有效；每次运行后都会销毁 isolate。
