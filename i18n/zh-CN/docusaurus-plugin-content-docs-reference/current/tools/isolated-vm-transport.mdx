# 隔离Vm代码模式传输

这`IsolatedVmCodeModeTransport`班级跑步[编码方式](/docs/agents/code-mode)进程内 V8 隔离中的程序，由[隔离虚拟机](https://github.com/laverdet/isolated-vm)。隔离是执行边界，因此不需要WorkspaceSandbox：程序没有文件系统、网络、进程或模块访问权限。它唯一的能力是`external_*`函数，它回调主机上的真实Tool。

与默认值相比`StdioCodeModeTransport`, this transport spawns no processes and writes no temp files, which makes it a good fit for serverless and multi-tenant hosts where OS-level sandboxing isn't available.

## 安装 {/* #installation */}

```bash npm2yarn
npm install @mastra/isolated-vm
```

`isolated-vm`是一个原生插件。它为常见平台提供预构建的二进制文件，因此安装通常不需要额外的设置。仅在没有匹配预构建的平台上才需要 C++ Tool链，在该平台上它会回退到从源代码进行编译。

在 Node.js 20 及更高版本上，创建隔离会崩溃，除非主机进程以`--no-node-snapshot`. The constructor reports the missing flag as an error. Pass it when starting the server or through `NODE_OPTIONS`:

```bash
NODE_OPTIONS=--no-node-snapshot npm run dev
```

## 用法 {/* #usage */}

将传输作为第二个参数传递给`createCodeMode()`. No `sandbox` is needed:

```typescript
import { createCodeMode } from '@mastra/core/tools'
import { IsolatedVmCodeModeTransport } from '@mastra/isolated-vm'

const { tool, instructions } = createCodeMode(
  { tools: { getTopProducts, getProductRatings } },
  new IsolatedVmCodeModeTransport({ memoryLimitMb: 128 }),
)
```

## 它是如何运作的 {/* #how-it-works */}

每次运行都会创建一个具有自己的堆的新分离株。使用 esbuild 在主机上剥离 TypeScript，然后在隔离内评估程序。每一个`external_*` call crosses the isolate boundary as JSON strings in both directions, so no host object references leak into model-authored code. The allow-list, tool validation, request context, and tracing all run on the host, the same as with other transports.

这`timeout` configured on `createCodeMode()` applies to both asynchronous hangs and synchronous infinite loops, and the isolate is disposed after every run.
