# 任务 Tool

四个内置 Tool 独立于具体 Agent，用于管理 Agent 运行时的结构化任务列表。任务列表持久化在线程级 `threadState` 存储域中，并映射到 Agent 的[状态信号](/docs/signals/state-signals)通道，因此不会因[观察式记忆](/docs/memory/observational-memory)截断而丢失。

任务跟踪需要由记忆功能支持的线程（`threadId` + `resourceId`）。如果没有记忆功能，这些 Tool 会返回错误，说明任务跟踪需要 Agent 记忆功能。

推荐使用 [`TaskSignalProvider`](/reference/signals/task-signal-provider)：只需注册一次，即可同时配置全部四个 Tool 和 `TaskStateProcessor`。概念说明请参阅[内置 Tool](/docs/agents/tools#task-tracking)。

## 使用示例 {/* #usage-example */}

```typescript title="src/mastra/agents/index.ts"
import { Agent } from '@mastra/core/agent'
import { Memory } from '@mastra/memory'
import { TaskSignalProvider } from '@mastra/core/signals'

const agent = new Agent({
  id: 'coder',
  name: 'Coder',
  instructions: 'Track your progress with the task tools.',
  model,
  memory: new Memory(),
  signals: [new TaskSignalProvider()],
})
```

也可以直接导入这些 Tool。`taskWriteTool`、`taskUpdateTool`、`taskCompleteTool` 和 `taskCheckTool` 是导出名称；`task_write`、`task_update`、`task_complete` 和 `task_check` 是模型在 Tool 调用和追踪记录中看到的 Tool ID：

```typescript title="src/mastra/agents/index.ts"
import { taskWriteTool, taskUpdateTool, taskCompleteTool, taskCheckTool } from '@mastra/core/tools'
import { Agent } from '@mastra/core/agent'
import { Memory } from '@mastra/memory'

const agent = new Agent({
  id: 'coder',
  name: 'Coder',
  instructions: 'Track your progress with the task tools.',
  model,
  memory: new Memory(),
  tools: { taskWriteTool, taskUpdateTool, taskCompleteTool, taskCheckTool },
})
```

## `task_write` {/* #task_write */}

创建或替换整个任务列表。每次调用都会替换之前的列表。

### 输入模式 {/* #input-schema */}

<PropertiesTable
  content={[
{
  name: 'tasks',
  type: 'TaskItemInput[]',
  description: '更新后的完整任务列表。',
  isOptional: false,
  properties: [
    {
      type: 'TaskItemInput',
      parameters: [
        {
          name: 'id',
          type: 'string',
          description:
            "稳定的任务标识符（例如 'task_investigate_tests'）。更新任务时请保持不变；省略时会自动生成。",
          isOptional: true,
        },
        {
          name: 'content',
          type: 'string',
          description: "祈使句形式的任务描述（例如 '修复身份验证错误'）。",
        },
        {
          name: 'status',
          type: "'pending' | 'in_progress' | 'completed'",
          description: '任务的当前状态。',
        },
        {
          name: 'activeForm',
          type: 'string',
          description: "任务执行时显示的进行式描述（例如 '正在修复身份验证错误'）。",
        },
      ],
    },
  ],
},
]}
/>

### 输出 {/* #output */}

返回 `TaskToolResult`，其中包含易于阅读的 `content` 摘要、带有已分配 ID 的完整 `tasks` 数组，以及 `isError` 标志。

### 行为 {/* #behavior */}

* 同一次调用中的 ID 必须唯一。如果显式提供了重复的 ID，系统会生成替代 ID。
* 重写现有列表时，如果省略 ID，且只有一项任务明确匹配，系统会复用该任务原有的 ID，以保持标识符稳定。
* 同一时间只能有一项任务处于 `in_progress` 状态。提交多项处于 `in_progress` 状态的任务会返回错误。

## `task_update` {/* #task_update */}

通过稳定 ID 更新一项任务。只需提供发生变化的字段。

### 输入模式 {/* #input-schema-1 */}

<PropertiesTable
  content={[
{
  name: 'id',
  type: 'string',
  description: '要更新的任务的稳定标识符。',
  isOptional: false,
},
{
  name: 'content',
  type: 'string',
  description: '新的祈使句形式任务描述。',
  isOptional: true,
},
{
  name: 'status',
  type: "'pending' | 'in_progress' | 'completed'",
  description: '任务的新状态。',
  isOptional: true,
},
{
  name: 'activeForm',
  type: 'string',
  description: '新的进行式描述。',
  isOptional: true,
},
]}
/>

`content`、`status` 和 `activeForm` 中至少需要提供一项。

### 行为 {/* #behavior-1 */}

* 如果更新将某项任务设为 `in_progress`，其他处于 `in_progress` 状态的任务会自动改为 `pending`。
* 如果找不到指定 ID，会返回错误并列出可用的任务 ID。

## `task_complete` {/* #task_complete */}

通过稳定 ID 将一项任务标记为已完成。

### 输入模式 {/* #input-schema-2 */}

<PropertiesTable
  content={[
{
  name: 'id',
  type: 'string',
  description: '要标记为已完成的任务的稳定标识符。',
  isOptional: false,
},
]}
/>

### 行为 {/* #behavior-2 */}

如果找不到指定 ID，会返回错误并列出可用的任务 ID。
