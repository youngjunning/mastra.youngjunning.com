# IFGAProvider

`IFGAProvider` 接口定义细粒度授权（FGA）Provider。Mastra 会调用它，判断用户或系统执行者是否有权对特定资源执行某项操作。实现此接口，即可将 Mastra 接入 WorkOS Authorization 等 FGA 后端。

有关 FGA 的概念、配置，以及 Mastra 在生命周期中的哪些环节执行授权检查，请参阅[细粒度授权](/docs/auth/fga)。

:::note

在生产环境中使用 FGA 需要 Mastra 企业版（EE）许可证；开发环境无需许可证。请参阅[哪些功能需要 EE 许可证](/docs/license#what-requires-an-ee-license)。如需了解更多信息，请[联系销售团队](https://mastra.ai/contact)。

:::

## 使用示例 {/* #usage-example */}

以下示例实现了一个最简 Provider。`require` 通过抛出错误拒绝访问，`check` 则返回布尔值。

```typescript title="src/mastra/fga.ts"
import { FGADeniedError } from '@mastra/core/auth/ee'
import type { FGACheckParams, IFGAProvider, MastraFGAPermissionInput } from '@mastra/core/auth/ee'

class MyFGAProvider implements IFGAProvider {
  async check(user: any, params: FGACheckParams): Promise<boolean> {
    // Your authorization logic.
    return true
  }

  async require(user: any, params: FGACheckParams): Promise<void> {
    if (!(await this.check(user, params))) {
      throw new FGADeniedError(user, params.resource, params.permission)
    }
  }

  async filterAccessible<T extends { id: string }>(
    user: any,
    resources: T[],
    resourceType: string,
    permission: MastraFGAPermissionInput,
  ): Promise<T[]> {
    return resources
  }
}
```

## 方法 {/* #methods */}

### `check(user, params)` {/* #checkuser-params */}

返回 `user` 是否对该资源具有指定权限。适用于过滤资源或按条件显示界面等不应抛出错误的检查。

返回：`Promise<boolean>`

### `require(user, params)` {/* #requireuser-params */}

当 `user` 缺少指定权限时抛出 `FGADeniedError`。Mastra 会在其[授权执行点](/docs/auth/fga#enforcement-points)调用此方法。

返回：`Promise<void>`

### `filterAccessible(user, resources, resourceType, permission)` {/* #filteraccessibleuser-resources-resourcetype-permission */}

返回 `resources` 中 `user` 具有 `permission` 权限、可以访问的资源子集。

返回：`Promise<T[]>`

### `requireActor(actor, params)` {/* #requireactoractor-params */}

授权自主 Agent 或定时运行的 Agent 等非用户系统执行者。此方法可选。

系统执行者不会经过面向用户的 `require()` 路径，因此应实现 `requireActor`，对每个 Agent 执行最小权限控制。拒绝访问时抛出 `FGADeniedError`。如果 Provider 未实现 `requireActor`，Mastra 会保留可信执行者的绕过机制，即通过租户范围检查后允许访问。因此，新增此方法仍保持向后兼容。

应将 `actor.permissions` 视为不可信的权限声明。请以 `actor.agentId` 为键，从可信来源查询该 Agent 的正式授权，不要信任对象中直接提供的值。参阅[系统执行者](/docs/auth/fga#system-actors)。

```typescript
import { FGADeniedError } from '@mastra/core/auth/ee'
import type { ActorSignal, FGACheckParams, IFGAProvider } from '@mastra/core/auth/ee'

class MyFGAProvider implements IFGAProvider {
  // ...check, require, filterAccessible...

  async requireActor(actor: ActorSignal, params: FGACheckParams): Promise<void> {
    const agentId = actor === true ? undefined : actor.agentId
    // Resolve the agent's authoritative grants from a trusted source keyed by agentId.
    const granted = await this.grantsForAgent(agentId)
    const required = Array.isArray(params.permission) ? params.permission : [params.permission]
    if (!required.some(permission => granted.includes(permission))) {
      throw new FGADeniedError(null, params.resource, params.permission)
    }
  }
}
```

返回：`Promise<void>`

## `FGADeniedError` {/* #fgadeniederror */}

授权检查未通过时抛出此错误。`require` 和 `requireActor` 通过抛出此错误拒绝访问，Mastra 会将其作为 HTTP `403` 返回。

```typescript
import { FGADeniedError } from '@mastra/core/auth/ee'

throw new FGADeniedError(user, { type: 'agent', id: 'reporter' }, 'agents:execute')
// Optional fourth argument: a reason string included in the error message.
```
