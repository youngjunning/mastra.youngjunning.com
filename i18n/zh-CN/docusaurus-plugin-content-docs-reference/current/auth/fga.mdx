# IFGAProvider

这`IFGAProvider`接口定义了细粒度授权（FGA）提供者。 Mastra 调用它来决定用户或系统参与者是否可以对特定资源执行权限。实现它以将 Mastra 连接到 FGA 后端，例如 WorkOS Authorization。

有关 Mastra 强制执行 FGA 的概念、配置和生命周期点，请参阅[Fine-grained authorization](/docs/auth/fga).

：：：笔记

FGA 在生产中需要 Mastra 企业版 (EE) 许可证。它在开发过程中无需许可证即可运行。看[what requires an EE license](/docs/license#what-requires-an-ee-license). [Contact sales](https://mastra.ai/contact) for more information.

## 使用示例 {/* #usage-example */}

以下示例实现了一个最小提供程序。`require` throws to deny, and `check` returns a boolean.

```typescript title="src/mastra/fga.ts"
import { FGADeniedError } from '@mastra/core/auth/ee'
import type { FGACheckParams, IFGAProvider, MastraFGAPermissionInput } from '@mastra/core/auth/ee'

class MyFGAProvider implements IFGAProvider {
  async check(user: any, params: FGACheckParams): Promise<boolean> {
    // Your authorization logic.
    return true
  }

  async require(user: any, params: FGACheckParams): Promise<void> {
    if (!(await this.check(user, params))) {
      throw new FGADeniedError(user, params.resource, params.permission)
    }
  }

  async filterAccessible<T extends { id: string }>(
    user: any,
    resources: T[],
    resourceType: string,
    permission: MastraFGAPermissionInput,
  ): Promise<T[]> {
    return resources
  }
}
```

## 方法 {/* #methods */}

### `check(user, params)` {/* #checkuser-params */}

返回是否`user` has the permission on the resource. Use it for non-throwing checks, such as filtering or conditional UI.

返回：`Promise<boolean>`

### `require(user, params)` {/* #requireuser-params */}

投掷`FGADeniedError` when `user` lacks the permission. Mastra calls this at its [enforcement points](/docs/auth/fga#enforcement-points).

返回：`Promise<void>`

### `filterAccessible(user, resources, resourceType, permission)` {/* #filteraccessibleuser-resources-resourcetype-permission */}

返回的子集`resources` that `user` can access with `permission`.

返回：`Promise<T[]>`

### `requireActor(actor, params)` {/* #requireactoractor-params */}

授权非用户系统参与者，例如自主或调度Agent。选修的。

系统参与者跳过以用户为中心`require()` path, so implement `requireActor` to enforce per-agent least privilege for them. Throw `FGADeniedError` to deny. When a provider doesn't implement `requireActor`, Mastra preserves the trusted-actor bypass (allow after the tenant-scope check), so adding the method remains backward compatible.

对待`actor.permissions` as an untrusted claim. Resolve the agent's authoritative grants from a trusted source keyed by `actor.agentId`, rather than trusting the inline values. See [System actors](/docs/auth/fga#system-actors).

```typescript
import { FGADeniedError } from '@mastra/core/auth/ee'
import type { ActorSignal, FGACheckParams, IFGAProvider } from '@mastra/core/auth/ee'

class MyFGAProvider implements IFGAProvider {
  // ...check, require, filterAccessible...

  async requireActor(actor: ActorSignal, params: FGACheckParams): Promise<void> {
    const agentId = actor === true ? undefined : actor.agentId
    // Resolve the agent's authoritative grants from a trusted source keyed by agentId.
    const granted = await this.grantsForAgent(agentId)
    const required = Array.isArray(params.permission) ? params.permission : [params.permission]
    if (!required.some(permission => granted.includes(permission))) {
      throw new FGADeniedError(null, params.resource, params.permission)
    }
  }
}
```

返回：`Promise<void>`

## `FGADeniedError` {/* #fgadeniederror */}

当授权检查被拒绝时抛出。`require` and `requireActor` throw it to deny, and Mastra surfaces it as an HTTP `403`.

```typescript
import { FGADeniedError } from '@mastra/core/auth/ee'

throw new FGADeniedError(user, { type: 'agent', id: 'reporter' }, 'agents:execute')
// Optional fourth argument: a reason string included in the error message.
```
