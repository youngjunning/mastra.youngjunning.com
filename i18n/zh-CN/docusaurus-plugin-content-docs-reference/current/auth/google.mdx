# MastraAuthGoogle 和 MastraRBACGoogle 类

## MastraAuthGoogle 类 {/* #mastraauthgoogle-class */}

这`MastraAuthGoogle` class provides authentication for Mastra using Google Workspace. It implements an OAuth 2.0 / OIDC login flow with encrypted session cookies and verifies Google ID tokens. It integrates with the Mastra server through the `auth`选项。

### 使用示例 {/* #usage-example */}

```typescript title="src/mastra/index.ts"
import { Mastra } from '@mastra/core'
import { MastraAuthGoogle } from '@mastra/auth-google'

export const mastra = new Mastra({
  server: {
    auth: new MastraAuthGoogle({
      clientId: process.env.GOOGLE_CLIENT_ID,
      clientSecret: process.env.GOOGLE_CLIENT_SECRET,
      redirectUri: process.env.GOOGLE_REDIRECT_URI,
      allowedDomains: ['example.com'],
    }),
  },
})
```

：：：笔记

如果设置了所需的环境变量，则可以省略构造函数参数。在这种情况下，使用`new MastraAuthGoogle()` without any arguments.

:::

### 认证流程 {/* #authentication-flow */}

`MastraAuthGoogle`按以下顺序验证请求：

1. **会话 cookie。**&#x542F;用 SSO 后，提供程序将读取并解密加密的会话 cookie。有效的、未过期的会话对用户进行身份验证。
2. **Google ID 令牌后备**：如果不存在有效的会话 cookie，则验证`Authorization` header token against Google's JWKS endpoint.

认证后，`authorizeUser` checks that the user has a valid Google user ID, the token-derived expiration hasn't passed, and the user's verified `hd` claim matches `allowedDomains` when domains are configured.

### 认证方式 {/* #authentication-methods */}

#### `authenticateToken(token, request?)` {/* #authenticatetokentoken-request */}

验证 Google ID 令牌。启用 SSO 后，此方法会在验证承载令牌之前检查加密的会话 cookie。

```typescript
const user = await auth.authenticateToken(idToken, request)
```

返回：`Promise<GoogleUser | null>`

#### `getCurrentUser(request)` {/* #getcurrentuserrequest */}

从会话 cookie 或不记名 Google ID 令牌返回经过身份验证的用户。

```typescript
const user = await auth.getCurrentUser(request)
```

返回：`Promise<GoogleUser | null>`

#### `authorizeUser(user)` {/* #authorizeuseruser */}

退货`true` when the user has an ID, hasn't expired, and matches `allowedDomains` when domains are configured.

```typescript
const allowed = auth.authorizeUser(user)
```

返回：`boolean`

#### `getUser(userId)` {/* #getuseruserid */}

退货`null`. Google ID tokens are verified directly, so this provider doesn't perform user lookup by ID.

```typescript
const user = await auth.getUser(userId)
```

返回：`Promise<GoogleUser | null>`

## MastraRBACGoogle 类 {/* #mastrarbacgoogle-class */}

这`MastraRBACGoogle` class maps Google Workspace groups to Mastra permissions. It fetches user groups from the Google Admin SDK Directory API and resolves them against a configurable role mapping. Use it with `MastraAuthGoogle` or any other auth provider.

：：：笔记

RBAC 在生产中需要 Mastra Enterprise Edition (EE) 许可证。它在开发过程中无需许可证即可运行。看[what requires an EE license](/docs/license#what-requires-an-ee-license). [Contact sales](https://mastra.ai/contact) for more information.

:::

### 使用示例 {/* #usage-example-1 */}

使用`MastraRBACGoogle` alongside an auth provider by passing it to the `rbac` option:

```typescript title="src/mastra/index.ts"
import { Mastra } from '@mastra/core'
import { MastraAuthGoogle, MastraRBACGoogle } from '@mastra/auth-google'

export const mastra = new Mastra({
  server: {
    auth: new MastraAuthGoogle(),
    rbac: new MastraRBACGoogle({
      serviceAccount: {
        clientEmail: process.env.GOOGLE_SERVICE_ACCOUNT_EMAIL!,
        privateKey: process.env.GOOGLE_SERVICE_ACCOUNT_PRIVATE_KEY!,
        subject: process.env.GOOGLE_WORKSPACE_ADMIN_EMAIL!,
      },
      roleMapping: {
        'admins@example.com': ['*'],
        'engineering@example.com': ['agents:*', 'workflows:*', 'tools:*'],
        'viewers@example.com': ['agents:read', 'workflows:read'],
        _default: [],
      },
    }),
  },
})
```

要将 Google Workspace RBAC 与不同的身份验证Provider结合使用，请传递`getUserKey` function to resolve the Google Directory API user key from the other provider's user object:

```typescript title="src/mastra/index.ts"
import { Mastra } from '@mastra/core'
import { MastraAuthAuth0 } from '@mastra/auth-auth0'
import { MastraRBACGoogle } from '@mastra/auth-google'

export const mastra = new Mastra({
  server: {
    auth: new MastraAuthAuth0(),
    rbac: new MastraRBACGoogle({
      getUserKey: user => user.email,
      serviceAccount: {
        clientEmail: process.env.GOOGLE_SERVICE_ACCOUNT_EMAIL!,
        privateKey: process.env.GOOGLE_SERVICE_ACCOUNT_PRIVATE_KEY!,
        subject: process.env.GOOGLE_WORKSPACE_ADMIN_EMAIL!,
      },
      roleMapping: {
        'engineering@example.com': ['agents:*', 'workflows:*'],
        'admins@example.com': ['*'],
        _default: [],
      },
    }),
  },
})
```

### RBAC方法 {/* #rbac-methods */}

#### `getRoles(user)` {/* #getrolesuser */}

返回用户的 Google Workspace 群组角色 ID。

```typescript
const roles = await rbac.getRoles(user)
```

返回：`Promise<string[]>`

#### `getPermissions(user)` {/* #getpermissionsuser */}

返回从 Google Workspace 群组解析的 Mastra 权限，以及`roleMapping`.

```typescript
const permissions = await rbac.getPermissions(user)
```

返回：`Promise<string[]>`

#### `hasPermission(user, permission)` {/* #haspermissionuser-permission */}

检查用户是否有权限。

```typescript
const canReadAgents = await rbac.hasPermission(user, 'agents:read')
```

返回：`Promise<boolean>`

#### `hasRole(user, role)` {/* #hasroleuser-role */}

检查用户是否解析为特定的 Google Workspace 群组角色。

```typescript
const isAdmin = await rbac.hasRole(user, 'admins@example.com')
```

返回：`Promise<boolean>`

#### `hasAllPermissions(user, permissions)` {/* #hasallpermissionsuser-permissions */}

检查用户是否拥有所有请求的权限。

```typescript
const canManageAgents = await rbac.hasAllPermissions(user, ['agents:read', 'agents:update'])
```

返回：`Promise<boolean>`

#### `hasAnyPermission(user, permissions)` {/* #hasanypermissionuser-permissions */}

检查用户是否至少拥有一项请求的权限。

```typescript
const canReadSomething = await rbac.hasAnyPermission(user, ['agents:read', 'workflows:read'])
```

返回：`Promise<boolean>`

#### `getAvailableRoles()` {/* #getavailableroles */}

返回配置的角色ID`roleMapping`, excluding `_default`.

```typescript
const roles = await rbac.getAvailableRoles()
```

返回：`Promise<{ id: string; name: string }[]>`

#### `getPermissionsForRole(roleId)` {/* #getpermissionsforroleroleid */}

返回为角色 ID 配置的权限。

```typescript
const permissions = await rbac.getPermissionsForRole('engineering@example.com')
```

返回：`Promise<string[]>`

#### `clearCache()` {/* #clearcache */}

清除所有缓存的 Google Workspace 群组查找。

```typescript
rbac.clearCache()
```

返回：`void`

#### `clearUserCache(userKey)` {/* #clearusercacheuserkey */}

清除一个 Directory API 用户密钥（例如电子邮件地址）的缓存组查找。

```typescript
rbac.clearUserCache('user@example.com')
```

返回：`void`

#### `getCacheStats()` {/* #getcachestats */}

返回当前组查找缓存大小和最大大小。

```typescript
const stats = rbac.getCacheStats()
```

返回：`{ size: number; maxSize: number }`

### 附加配置 {/* #additional-configuration */}

`MastraRBACGoogle`用途`GET https://admin.googleapis.com/admin/directory/v1/groups?userKey=...` and handles pagination. Provide a service account with domain-wide delegation for production Google Workspace deployments, or pass `accessToken` / `getAccessToken` if your application already manages Google API tokens.

如果`user.groups` is already an array, `MastraRBACGoogle` uses that value and doesn't call the Directory API. An empty `groups` array means the user has no Google group roles and resolves to `_default` permissions when `_default` is configured.

`MastraRBACGoogle`不会自动读取服务帐户环境变量。通过以下方式传递服务帐户凭据`serviceAccount` option, or pass `accessToken` / `getAccessToken`.
