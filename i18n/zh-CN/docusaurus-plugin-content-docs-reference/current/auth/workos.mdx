# MastraAuthWorkos 类

`MastraAuthWorkos` 类通过 WorkOS 为 Mastra 提供身份验证。它使用 WorkOS 访问令牌验证传入的请求，并通过 `auth` 选项集成到 Mastra 服务器。

## 使用示例 {/* #usage-example */}

```typescript title="src/mastra/index.ts"
import { Mastra } from '@mastra/core'
import { MastraAuthWorkos } from '@mastra/auth-workos'

export const mastra = new Mastra({
  server: {
    auth: new MastraAuthWorkos({
      apiKey: process.env.WORKOS_API_KEY,
      clientId: process.env.WORKOS_CLIENT_ID,
    }),
  },
})
```

:::note

如果已设置所需的环境变量（`WORKOS_API_KEY` 和 `WORKOS_CLIENT_ID`），可以省略构造函数参数，直接使用 `new MastraAuthWorkos()`。

:::

## 默认授权行为 {/* #default-authorization-behavior */}

默认情况下，只要解析出的 WorkOS 用户对象同时包含 `id` 和 `workosId`，`MastraAuthWorkos` 就会允许该已认证用户访问。

1. **令牌验证**：通过 WorkOS 验证访问令牌有效且未过期
1. **获取用户**：从已验证的令牌中提取用户信息
1. **授权判定**：如果解析出的用户包含必需的标识符，就允许访问

默认情况下，`MastraAuthWorkos` 负责身份验证，不按角色限制访问。

## 加载 FGA 组织成员身份 {/* #fga-membership-loading */}

使用 `MastraFGAWorkos` 时，将 `fetchMemberships` 设为 `true`。这样会在身份验证期间加载用户的 WorkOS 组织成员身份，使 FGA 检查能够解析正确的组织成员身份 ID。

当 `fetchMemberships` 为 `false` 时，Mastra 不会在每次已认证请求中额外调用 WorkOS 的 `listOrganizationMemberships()`。

## 服务令牌和 JWT 声明 {/* #service-tokens-and-jwt-claims */}

如果 WorkOS JWT 模板包含自定义声明，可以将其直接映射到已认证的 `WorkOSUser`。

```typescript title="src/mastra/auth.ts"
import { MastraAuthWorkos } from '@mastra/auth-workos'

const auth = new MastraAuthWorkos({
  apiKey: process.env.WORKOS_API_KEY,
  clientId: process.env.WORKOS_CLIENT_ID,
  redirectUri: process.env.WORKOS_REDIRECT_URI,
  trustJwtClaims: true,
  jwtClaims: {
    organizationId: 'org_id',
    organizationMembershipId: 'urn:mastra:organization_membership_id',
  },
})
```

启用 `trustJwtClaims` 后，即使不适合通过 `getUser()` 查询服务主体，Mastra 仍可使用已验证的 Bearer 令牌完成身份验证。对于机器间调用，建议通过这种方式将预先解析的 `organizationMembershipId` 传给 FGA 检查。

## 自定义授权 {/* #custom-authorization */}

如果需要更严格的授权规则，可以继承 `MastraAuthWorkos` 并重写 `authorizeUser()`：

```typescript title="src/mastra/auth.ts"
import { MastraAuthWorkos } from '@mastra/auth-workos'
import type { HonoRequest } from 'hono'

class AdminOnlyWorkosAuth extends MastraAuthWorkos {
  async authorizeUser(user: any, _request: HonoRequest): Promise<boolean> {
    return user?.metadata?.role === 'admin'
  }
}
```

## WorkOS 用户类型 {/* #workos-user-type */}

`authorizeUser()` 和其他 WorkOS 身份验证钩子中的 `WorkOSUser` 类型，既包含 Mastra 规范化后的用户字段，也包含 WorkOS 专有元数据。WorkOS 允许管理员配置自定义 JWT 模板，因此具体结构取决于配置。下面是一个由 WorkOS 提供的用户对象示例：

```javascript oxfmt:false
{
  'urn:myapp:full_name': 'John Doe',
  'urn:myapp:email': 'john.doe@example.com',
  'urn:myapp:organization_tier': 'bronze',
  'urn:myapp:user_language': 'en',
  'urn:myapp:organization_domain': 'example.com',
  iss: 'https://api.workos.com/user_management/client_01ABC123DEF456GHI789JKL012',
  sub: 'user_01XYZ789ABC123DEF456GHI012',
  sid: 'session_01PQR456STU789VWX012YZA345',
  jti: '01MNO678PQR901STU234VWX567',
  org_id: 'org_01DEF234GHI567JKL890MNO123',
  role: 'member',
  roles: [ 'member' ],
  permissions: [],
  exp: 1758290589,
  iat: 1758290289
}
```

带有 `urn:myapp:` 前缀的属性，是在 WorkOS JWT 模板中配置的自定义声明。标准 JWT 声明包括 `sub`（用户 ID）、`iss`（签发者）和 `exp`（过期时间）；WorkOS 专有声明包括 `org_id`、`role` 和 `roles`。
