# MastraAuthAuth0 类

这`MastraAuthAuth0`类使用 Auth0 为 Mastra 提供身份验证。它使用 Auth0 颁发的 JWT 令牌验证传入请求，并使用`auth`选项。

## 使用示例 {/* #usage-example */}

```typescript title="src/mastra/index.ts"
import { Mastra } from '@mastra/core'
import { MastraAuthAuth0 } from '@mastra/auth-auth0'

export const mastra = new Mastra({
  server: {
    auth: new MastraAuthAuth0({
      domain: process.env.AUTH0_DOMAIN,
      audience: process.env.AUTH0_AUDIENCE,
    }),
  },
})
```

：：：笔记

如果需要环境变量（`AUTH0_DOMAIN` and `AUTH0_AUDIENCE`) are set. In that case, use `new MastraAuthAuth0()` without any arguments.

## 默认授权行为 {/* #default-authorization-behavior */}

默认情况下，`MastraAuthAuth0` validates Auth0 JWT tokens and allows access to all authenticated users:

1. **令牌验证**：使用 Auth0 的公钥 (JWKS) 验证 JWT 令牌
2. **签名验证**：确保令牌由您的 Auth0 租户签名
3. **过期检查**：验证令牌尚未过期
4. **观众验证**：确认令牌是为您的特定 API（受众）颁发的
5. **发行人验证**：确保令牌是由您的 Auth0 域颁发的

如果所有验证都通过，则认为用户已获得授权。要实现自定义授权逻辑（例如基于角色的访问控制），请提供自定义`authorizeUser` function.

## Auth0 用户类型 {/* #auth0-user-type */}

这`Auth0User` type used in the `authorizeUser` function corresponds to the decoded JWT token payload, which typically includes:

* `sub`：用户的唯一标识符（主题）
* `email`：用户的电子邮件地址（如果包含在令牌中）
* `email_verified`: 邮箱是否验证
* `name`：用户的显示名称（如果有）
* `picture`：用户个人资料图片的 URL（如果有）
* `iss`：令牌颁发者（您的 Auth0 域）
* `aud`：令牌受众（您的 API 标识符）
* `iat`：以时间戳发行的令牌
* `exp`: 令牌过期时间戳
* `scope`：授予令牌的范围
* 在 Auth0 租户中配置的自定义声明和应用程序元数据

可用的确切属性取决于您的 Auth0 配置、请求的范围以及您配置的任何自定义声明。

经过身份验证的用户的`id` is the token's `id` claim, or its `sub` claim when the token has no `id`. RBAC looks up roles by this `id`, and it owns the records the user creates unless `mapUserToResourceId` is set. See [user IDs from JWT providers](/docs/guides/authentication-identity#user-ids-from-jwt-providers).
