# MastraAuthAuth0 类

`MastraAuthAuth0` 类通过 Auth0 为 Mastra 提供身份验证。它使用 Auth0 签发的 JWT 验证传入请求，并通过 `auth` 选项接入 Mastra 服务器。

## 使用示例 {/* #usage-example */}

```typescript title="src/mastra/index.ts"
import { Mastra } from '@mastra/core'
import { MastraAuthAuth0 } from '@mastra/auth-auth0'

export const mastra = new Mastra({
  server: {
    auth: new MastraAuthAuth0({
      domain: process.env.AUTH0_DOMAIN,
      audience: process.env.AUTH0_AUDIENCE,
    }),
  },
})
```

:::note

如果已设置必需的环境变量 `AUTH0_DOMAIN` 和 `AUTH0_AUDIENCE`，可以省略构造函数参数，直接使用 `new MastraAuthAuth0()`。

:::

## 默认授权行为 {/* #default-authorization-behavior */}

默认情况下，`MastraAuthAuth0` 验证 Auth0 JWT，并允许所有已认证用户访问：

1. **令牌验证**：使用 Auth0 的公钥 (JWKS) 验证 JWT 令牌
2. **签名验证**：确保令牌由您的 Auth0 租户签名
3. **过期检查**：验证令牌尚未过期
4. **受众验证**：确认令牌是针对您的 API（audience）签发的
5. **签发者验证**：确保令牌由您的 Auth0 域名签发

所有验证通过后，用户即获得授权。如需实现基于角色的访问控制等自定义逻辑，请提供 `authorizeUser` 函数。

## Auth0 用户类型 {/* #auth0-user-type */}

`Auth0User` 类型在 `authorizeUser` 函数中对应解码后的 JWT 载荷，通常包含：

* `sub`：用户的唯一标识符（subject）
* `email`：用户的电子邮件地址（如果包含在令牌中）
* `email_verified`: 邮箱是否验证
* `name`：用户的显示名称（如果有）
* `picture`：用户个人资料图片的 URL（如果有）
* `iss`：令牌颁发者（您的 Auth0 域）
* `aud`：令牌受众（您的 API 标识符）
* `iat`：令牌签发时间戳
* `exp`: 令牌过期时间戳
* `scope`：令牌获授的 scope
* 在 Auth0 租户中配置的自定义 claim和应用程序元数据

可用的确切属性取决于您的 Auth0 配置、请求的 scope以及您配置的任何自定义 claim。

已认证用户的 `id` 取自令牌的 `id` claim；如果令牌没有该 claim，则取自 `sub` claim。令牌没有 `id` 时，这一回退规则同样适用。RBAC 根据 `id` 查找角色；除非设置了 `mapUserToResourceId`，用户创建的记录也归属于这一标识。参阅 [JWT Provider 的用户 ID](/docs/guides/authentication-identity#user-ids-from-jwt-providers)。
