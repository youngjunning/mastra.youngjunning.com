# Memory API

Memory API 提供管理 Mastra 对话线程和消息历史记录的方法。

## 获取所有线程 {/* #get-all-threads */}

获取指定资源的所有记忆线程：

```typescript
const threads = await mastraClient.listMemoryThreads({
  resourceId: 'resource-1',
  agentId: 'agent-1', // Optional - can be omitted if storage is configured
})
```

如果省略 `agentId`，且服务器已配置存储，系统会直接从存储中获取线程。这适用于多个 Agent 共享线程的场景，例如包含多个 Agent 步骤的 Workflow。

## 创建新线程 {/* #create-a-new-thread */}

创建记忆线程：

```typescript
const thread = await mastraClient.createMemoryThread({
  title: 'New Conversation',
  metadata: { category: 'support' },
  resourceId: 'resource-1',
  agentId: 'agent-1',
})
```

## 操作指定线程 {/* #working-with-a-specific-thread */}

获取指定记忆线程的实例：

```typescript
const thread = mastraClient.getMemoryThread({ threadId: 'thread-id', agentId: 'agent-id' })
```

## 线程方法 {/* #thread-methods */}

### 获取线程详情 {/* #get-thread-details */}

获取指定线程的详情：

```typescript
const details = await thread.get()
```

### 更新线程 {/* #update-thread */}

更新线程属性：

```typescript
const updated = await thread.update({
  title: 'Updated Title',
  metadata: { status: 'resolved' },
  resourceId: 'resource-1',
})
```

### 删除线程 {/* #delete-thread */}

删除线程及其消息：

```typescript
await thread.delete()
```

### 克隆线程 {/* #clone-thread */}

创建包含全部消息的线程副本：

```typescript
const { thread: clonedThread, clonedMessages } = await thread.clone()
```

指定选项进行克隆：

```typescript
const { thread: clonedThread, clonedMessages } = await thread.clone({
  newThreadId: 'custom-clone-id',
  title: 'Cloned Conversation',
  metadata: { branch: 'experiment-1' },
  options: {
    messageLimit: 10, // Only clone last 10 messages
  },
})
```

按消息条件筛选后克隆：

```typescript
const { thread: clonedThread } = await thread.clone({
  options: {
    messageFilter: {
      startDate: new Date('2024-01-01'),
      endDate: new Date('2024-01-31'),
    },
  },
})
```

克隆结果包含：

* `thread`：新建的线程副本，包含克隆元数据
* `clonedMessages`：克隆后的消息数组，每条消息都有新 ID

## 消息操作 {/* #message-operations */}

### 保存消息 {/* #save-messages */}

将消息保存到记忆系统：

```typescript
const result = await mastraClient.saveMessageToMemory({
  messages: [
    {
      role: 'user',
      content: 'Hello!',
      id: '1',
      threadId: 'thread-1',
      resourceId: 'resource-1',
      createdAt: new Date(),
      format: 2,
    },
  ],
  agentId: 'agent-1',
})

// result.messages contains the saved messages
console.log(result.messages)
```

### 获取线程消息 {/* #retrieve-thread-messages */}

获取记忆线程中的消息：

```typescript
// Get all messages in the thread (paginated)
const result = await thread.listMessages()
console.log(result.messages) // Array of messages
console.log(result.total) // Total count
console.log(result.hasMore) // Whether more pages exist

// Get messages with pagination
const result = await thread.listMessages({
  page: 0,
  perPage: 20,
})

// Get messages with ordering
const result = await thread.listMessages({
  orderBy: { field: 'createdAt', direction: 'ASC' },
})

// Get messages with shallow metadata filters
const result = await thread.listMessages({
  filter: {
    metadata: {
      category: 'billing',
      escalated: true,
      priority: 2,
      archivedAt: null,
    },
  },
})
```

元数据过滤器仅匹配浅层标量值：`string`、有限的 `number`、`boolean` 和 `null`。所有键值对都必须匹配（AND 语义）。`null` 只匹配明确设置为 `null` 的键。元数据键必须以字母或下划线开头，且只能包含字母、数字和下划线，长度上限为 128 个字符。不允许使用 `__proto__`、`constructor` 和 `prototype` 等保留的原型键。性能取决于服务器的存储后端；任意元数据过滤条件可能需要扫描候选消息。

### 删除消息 {/* #delete-messages */}

从线程中删除一条或多条消息：

```typescript
// Delete a single message
const result = await thread.deleteMessages('message-id')

// Delete multiple messages
const result = await thread.deleteMessages(['message-1', 'message-2', 'message-3'])

// Returns: { success: true, message: "Message deleted successfully" }
```

## 工作记忆 {/* #working-memory */}

工作记忆让 Agent 在多次交互中保留用户信息。作用范围可以是单个线程，也可以是某个资源（用户）的所有线程。

### 获取工作记忆 {/* #get-working-memory */}

获取线程当前的工作记忆：

```typescript
const workingMemory = await mastraClient.getWorkingMemory({
  agentId: 'agent-1',
  threadId: 'thread-1',
  resourceId: 'user-123', // Optional, required for resource-scoped memory
})
```

响应包含：

* `workingMemory`：当前工作记忆内容，为字符串或 `null`；使用 JSON 或基于 schema 的工作记忆模板时，内容为 JSON 编码的字符串
* `source`：工作记忆来自 `"thread"` 还是 `"resource"` 作用范围
* `workingMemoryTemplate`：工作记忆使用的模板（如已配置）
* `threadExists`：线程是否存在

### 更新工作记忆 {/* #update-working-memory */}

更新线程的工作记忆内容：

```typescript
await mastraClient.updateWorkingMemory({
  agentId: 'agent-1',
  threadId: 'thread-1',
  workingMemory: `# User Profile
- Name: John Doe
- Location: New York
- Preferences: Prefers formal communication
`,
  resourceId: 'user-123', // Optional, required for resource-scoped memory
})

// Returns: { success: true }
```

使用资源级工作记忆时，必须提供 `resourceId` 参数。这样，用户的工作记忆就能跨所有对话线程保留。

默认情况下，此调用会替换整条记录。对于基于 schema 的资源级工作记忆，可传入 `mode: 'merge'` 和 JSON 对象字符串，以原子方式深度合并所提供的字段。如果存储适配器不支持原子合并，服务器会返回 `400`；目前只有 `@mastra/pg` 支持。

```typescript
await mastraClient.updateWorkingMemory({
  agentId: 'agent-1',
  threadId: 'thread-1',
  resourceId: 'user-123',
  workingMemory: JSON.stringify({ city: 'Berlin' }),
  mode: 'merge',
})
```

### 获取记忆系统状态 {/* #get-memory-status */}

检查记忆系统的状态：

```typescript
const status = await mastraClient.getMemoryStatus('agent-id')
```
