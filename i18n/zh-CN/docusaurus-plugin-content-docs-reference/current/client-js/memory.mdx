# 内存API

Memory API 提供了管理 Mastra 中的对话线程和消息历史记录的方法。

## 获取所有线程 {/* #get-all-threads */}

检索特定资源的所有内存线程：

```typescript
const threads = await mastraClient.listMemoryThreads({
  resourceId: 'resource-1',
  agentId: 'agent-1', // Optional - can be omitted if storage is configured
})
```

什么时候`agentId` is omitted and storage is configured on the server, threads will be retrieved using storage directly. This is useful when multiple agents share the same threads (e.g., in workflows with multiple agent steps).

## 创建一个新线程 {/* #create-a-new-thread */}

创建一个新的内存线程：

```typescript
const thread = await mastraClient.createMemoryThread({
  title: 'New Conversation',
  metadata: { category: 'support' },
  resourceId: 'resource-1',
  agentId: 'agent-1',
})
```

## 使用特定线程 {/* #working-with-a-specific-thread */}

获取特定内存线程的实例：

```typescript
const thread = mastraClient.getMemoryThread({ threadId: 'thread-id', agentId: 'agent-id' })
```

## 线程方法 {/* #thread-methods */}

### 获取话题详细信息 {/* #get-thread-details */}

检索有关特定线程的详细信息：

```typescript
const details = await thread.get()
```

### 更新主题 {/* #update-thread */}

更新线程属性：

```typescript
const updated = await thread.update({
  title: 'Updated Title',
  metadata: { status: 'resolved' },
  resourceId: 'resource-1',
})
```

### 删除话题 {/* #delete-thread */}

删除线程及其消息：

```typescript
await thread.delete()
```

### 克隆线程 {/* #clone-thread */}

创建包含所有消息的线程的副本：

```typescript
const { thread: clonedThread, clonedMessages } = await thread.clone()
```

使用选项克隆：

```typescript
const { thread: clonedThread, clonedMessages } = await thread.clone({
  newThreadId: 'custom-clone-id',
  title: 'Cloned Conversation',
  metadata: { branch: 'experiment-1' },
  options: {
    messageLimit: 10, // Only clone last 10 messages
  },
})
```

使用消息过滤进行克隆：

```typescript
const { thread: clonedThread } = await thread.clone({
  options: {
    messageFilter: {
      startDate: new Date('2024-01-01'),
      endDate: new Date('2024-01-31'),
    },
  },
})
```

克隆响应包括：

* `thread`：新创建的克隆线程，带有克隆元数据
* `clonedMessages`：具有新 ID 的克隆消息数组

## 消息操作 {/* #message-operations */}

### 保存消息 {/* #save-messages */}

将消息保存到内存：

```typescript
const result = await mastraClient.saveMessageToMemory({
  messages: [
    {
      role: 'user',
      content: 'Hello!',
      id: '1',
      threadId: 'thread-1',
      resourceId: 'resource-1',
      createdAt: new Date(),
      format: 2,
    },
  ],
  agentId: 'agent-1',
})

// result.messages contains the saved messages
console.log(result.messages)
```

### 检索主题消息 {/* #retrieve-thread-messages */}

获取与内存线程关联的消息：

```typescript
// Get all messages in the thread (paginated)
const result = await thread.listMessages()
console.log(result.messages) // Array of messages
console.log(result.total) // Total count
console.log(result.hasMore) // Whether more pages exist

// Get messages with pagination
const result = await thread.listMessages({
  page: 0,
  perPage: 20,
})

// Get messages with ordering
const result = await thread.listMessages({
  orderBy: { field: 'createdAt', direction: 'ASC' },
})

// Get messages with shallow metadata filters
const result = await thread.listMessages({
  filter: {
    metadata: {
      category: 'billing',
      escalated: true,
      priority: 2,
      archivedAt: null,
    },
  },
})
```

元数据过滤器仅匹配浅标量值：`string`, finite `number`, `boolean`, and `null`. Every key-value pair must match with AND semantics. `null` matches only keys explicitly set to `null`. Metadata keys must start with a letter or underscore and contain only alphanumeric or underscore characters. The limit is 128 characters. Reserved prototype keys such as `__proto__`, `constructor`, and `prototype` aren't allowed. Performance depends on the server storage backend, and arbitrary metadata filters may scan candidate messages.

### 删除消息 {/* #delete-messages */}

从线程中删除一条或多条消息：

```typescript
// Delete a single message
const result = await thread.deleteMessages('message-id')

// Delete multiple messages
const result = await thread.deleteMessages(['message-1', 'message-2', 'message-3'])

// Returns: { success: true, message: "Message deleted successfully" }
```

## 工作记忆 {/* #working-memory */}

工作记忆允许Agent在交互过程中维护有关用户的持久信息。它的作用域可以是特定线程，也可以是资源（用户）的所有线程。

### 获取工作记忆 {/* #get-working-memory */}

检索线程的当前工作内存：

```typescript
const workingMemory = await mastraClient.getWorkingMemory({
  agentId: 'agent-1',
  threadId: 'thread-1',
  resourceId: 'user-123', // Optional, required for resource-scoped memory
})
```

响应内容包括：

* `workingMemory`：当前工作内存内容（字符串或`null`). When using a JSON or schema-based working memory template, the content is a JSON-encoded string
* `source`: 记忆是否来自`"thread"` or `"resource"` scope
* `workingMemoryTemplate`：用于工作记忆的模板（如果配置）
* `threadExists`: 线程是否存在

### 更新工作记忆 {/* #update-working-memory */}

更新线程的工作内存内容：

```typescript
await mastraClient.updateWorkingMemory({
  agentId: 'agent-1',
  threadId: 'thread-1',
  workingMemory: `# User Profile
- Name: John Doe
- Location: New York
- Preferences: Prefers formal communication
`,
  resourceId: 'user-123', // Optional, required for resource-scoped memory
})

// Returns: { success: true }
```

对于资源范围的工作内存，您必须提供`resourceId` parameter. It allows the memory to persist across all conversation threads for that user.

默认情况下，调用会替换整个记录。对于基于模式、资源范围的工作内存，通过`mode: 'merge'` with a JSON object string to deep-merge only the provided fields atomically. The server returns `400` if the storage adapter doesn't support atomic merges (currently only `@mastra/pg` does).

```typescript
await mastraClient.updateWorkingMemory({
  agentId: 'agent-1',
  threadId: 'thread-1',
  resourceId: 'user-123',
  workingMemory: JSON.stringify({ city: 'Berlin' }),
  mode: 'merge',
})
```

### 获取内存状态 {/* #get-memory-status */}

检查内存系统的状态：

```typescript
const status = await mastraClient.getMemoryStatus('agent-id')
```
