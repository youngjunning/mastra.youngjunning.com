# AgentAPI

Agents API 提供了与 Mastra AI Agent交互的方法，包括生成响应和流式交互。它还提供了管理AgentTool的方法。

## 获取所有Agent {/* #getting-all-agents */}

检索所有可用Agent的列表：

```typescript
const agents = await mastraClient.listAgents()
```

将Agent ID 记录返回到其序列化Agent配置。

## 与特定Agent合作 {/* #working-with-a-specific-agent */}

通过 ID 获取特定Agent的实例：

```typescript title="src/mastra/agents/my-agent.ts"
import { Agent } from '@mastra/core/agent'

export const myAgent = new Agent({
  id: 'my-agent',
})
```

```typescript
const agent = mastraClient.getAgent('my-agent')
```

## Agent方式 {/* #agent-methods */}

### `details()` {/* #details */}

检索有关Agent的详细信息：

```typescript
const details = await agent.details()
```

### `generate()` {/* #generate */}

从Agent生成响应：

```typescript
const response = await agent.generate(
  [
    {
      role: 'user',
      content: 'Hello, how are you?',
    },
  ],
  {
    memory: {
      thread: 'thread-abc', // Optional: Thread ID for conversation context
      resource: 'user-123', // Optional: Resource ID
    },
    structuredOutput: {}, // Optional: Structured Output configuration
  },
)
```

您还可以使用带有内存选项的简化字符串格式：

```typescript
const response = await agent.generate('Hello, how are you?', {
  memory: {
    thread: 'thread-1',
    resource: 'resource-1',
  },
})
```

### `stream()` {/* #stream */}

流式传输来自Agent的响应以进行实时交互：

```typescript
const response = await agent.stream('Tell me a story')

// Process data stream with the processDataStream util
response.processDataStream({
  onChunk: async chunk => {
    console.log(chunk)
  },
})
```

您还可以使用带有内存选项的简化字符串格式：

```typescript
const response = await agent.stream('Tell me a story', {
  memory: {
    thread: 'thread-1',
    resource: 'resource-1',
  },
  clientTools: { colorChangeTool },
})

response.processDataStream({
  onChunk: async chunk => {
    if (chunk.type === 'text-delta') {
      console.log(chunk.payload.text)
    }
  },
})
```

您还可以直接从响应正文中读取：

```typescript
const reader = response.body.getReader()
while (true) {
  const { done, value } = await reader.read()
  if (done) break
  console.log(new TextDecoder().decode(value))
}
```

#### 取消流 {/* #cancelling-a-stream */}

取消响应正文将中止底层 HTTP 请求并停止任何待处理的客户端Tool执行和后续请求：

```typescript
const response = await agent.stream('Tell me a story')
const reader = response.body.getReader()

const { value } = await reader.read()
await reader.cancel('user navigated away')
```

您还可以通过`abortSignal` to cancel from outside the stream. The same option is available on `streamUntilIdle()`, `resumeStream()`, `resumeStreamUntilIdle()`, `approveToolCall()`, `declineToolCall()`, `generate()`, and `generateLegacy()`:

```typescript
const controller = new AbortController()

const response = await agent.stream('Tell me a story', {
  abortSignal: controller.signal,
})

// Later
controller.abort()
```

#### AI SDK兼容格式 {/* #ai-sdk-compatible-format */}

从客户端流式传输 AI SDK 格式的部件`agent.stream(...)` response, wrap `response.processDataStream` into a `ReadableStream<ChunkType>` and use `toAISdkStream`:

```typescript title="client-ai-sdk-transform.ts"
import { createUIMessageStream } from 'ai'
import { toAISdkStream } from '@mastra/ai-sdk'
import type { ChunkType, MastraModelOutput } from '@mastra/core/stream'

const response = await agent.stream('Tell me a story')

const chunkStream: ReadableStream<ChunkType> = new ReadableStream<ChunkType>({
  start(controller) {
    response
      .processDataStream({
        onChunk: async chunk => controller.enqueue(chunk as ChunkType),
      })
      .finally(() => controller.close())
  },
})

const uiMessageStream = createUIMessageStream({
  execute: async ({ writer }) => {
    for await (const part of toAISdkStream(chunkStream as unknown as MastraModelOutput, {
      from: 'agent',
    })) {
      writer.write(part)
    }
  },
})

for await (const part of uiMessageStream) {
  console.log(part)
}
```

### `sendMessage()` {/* #sendmessage */}

将用户编写的输入发送到活动Agent运行或空闲内存线程。将此与`subscribeToThread()` so the client can render the stream that wakes from, or receives the message.

```typescript
const agent = mastraClient.getAgent('support-agent')

const result = await agent.sendMessage({
  message: {
    contents: 'Also consider the customer note I just added.',
    attributes: { sentFrom: 'web' },
  },
  resourceId: 'user-123',
  threadId: 'thread-abc',
})

console.log(result.runId)
```

`message`接受字符串、文本/文件部分的数组或带有以下内容的对象`contents`, `attributes`, `metadata`, and `providerOptions`.

### `queueMessage()` {/* #queuemessage */}

将用户编写的输入排队以供下一个线程轮流使用。如果线程处于活动状态，Mastra 将在当前运行完成后启动新的运行。如果线程空闲，Mastra 会立即开始运行。

```typescript
await agent.queueMessage({
  message: 'Also check whether the tests need updates.',
  resourceId: 'user-123',
  threadId: 'thread-abc',
})
```

### `queueSignal()` {/* #queuesignal */}

将键入的信号排队以供下一个线程轮流使用。它遵循与以下相同的顺序`queueMessage()`, but keeps the signal's `type`, `tagName`, and `attributes`.

```typescript
await agent.queueSignal({
  signal: {
    type: 'reactive',
    tagName: 'skill',
    attributes: { name: 'triage' },
    contents: 'Triage the new issue.',
  },
  resourceId: 'user-123',
  threadId: 'thread-abc',
})
```

### `sendSignal()` {/* #sendsignal */}

向活动Agent运行或内存线程发送较低级别的信号。将此用于系统生成的上下文，例如不需要收件箱存储的反应式提醒或通知形状的上下文。对于持久的通知记录，请使用服务器端[`Agent.sendNotificationSignal()`](/reference/agents/agent#sendnotificationsignalnotification-options) API. For user-authored input, prefer `sendMessage()` or `queueMessage()`.

```typescript
const agent = mastraClient.getAgent('support-agent')

const result = await agent.sendSignal({
  signal: {
    type: 'reactive',
    tagName: 'system-reminder',
    contents: 'Also consider the latest customer note.',
  },
  resourceId: 'user-123',
  threadId: 'thread-abc',
})

console.log(result.runId)
```

使用`ifActive.behavior` and `ifIdle.behavior` to control whether Mastra delivers, persists, discards, or wakes from a signal:

```typescript
await agent.sendSignal({
  signal: { type: 'reactive', tagName: 'system-reminder', contents: 'Store this for later.' },
  resourceId: 'user-123',
  threadId: 'thread-abc',
  ifIdle: {
    behavior: 'persist',
  },
})
```

经过`ifIdle.streamOptions` when the idle wake-up stream needs options such as model settings, tools, or runtime context:

```typescript
await agent.sendSignal({
  signal: { type: 'reactive', tagName: 'system-reminder', contents: 'Start from this signal.' },
  resourceId: 'user-123',
  threadId: 'thread-abc',
  ifIdle: {
    behavior: 'wake',
    streamOptions: {
      maxSteps: 3,
    },
  },
})
```

退货`{ accepted: true, runId: string }`.

### `subscribeToThread()` {/* #subscribetothread */}

订阅内存线程的原始流块。使用它来渲染可能由以下命令启动或继续的线程的输出`sendMessage()`, `queueMessage()`, `sendSignal()`, or server-side notification dispatch.

```typescript
const agent = mastraClient.getAgent('support-agent')

const subscription = await agent.subscribeToThread({
  resourceId: 'user-123',
  threadId: 'thread-abc',
})

await subscription.processDataStream({
  onChunk: chunk => {
    console.log(chunk)
  },
  reconnect: true,
})
```

经过`withInitialHistory: true` (or `{ perPage }`) to receive the stored messages as a first `thread-history` chunk instead of fetching history separately. Finished runs aren't replayed after it, so completed answers don't stream again on reconnect.

在React SDK中，`useChat()` exposes the `hasMore` flag from that first page as `initialHistoryPagination`, so you can decide whether to offer loading older messages without another history request:

```typescript
import { useChat } from '@mastra/react'

const { messages, initialHistoryPagination } = useChat({
  agentId: 'support-agent',
  resourceId: 'user-123',
  threadId: 'thread-abc',
  enableThreadSignals: true,
  withInitialHistory: { perPage: 20 },
})

// { hasMore: true }: older messages exist
// { hasMore: false }: the page reaches the start of the thread
// undefined: history is disabled, still loading, or the subscription ended
```

`initialHistoryPagination`只描述当前Agent、资源、线程的初始订阅页面`withInitialHistory` value. It isn't changed by live output or `setMessages()`. After you load older pages yourself, use the `hasMore` value from those responses.

`subscribeToThread()`返回底层证券`Response` plus a `processDataStream()` helper. The helper reads the subscription stream until the connection closes or the request is aborted. Pass `reconnect: true` to resubscribe when the transport closes or a reconnect request fails, such as after a proxy idle timeout. If a reconnect request fails with a 4xx status (for example `401` or `403`) or `501`, `processDataStream()` stops reconnecting and rejects with the original `MastraClientError`. `408` and `429` are still retried.

### `abortRun(runId)` {/* #abortrunrunid */}

通过其 ID 请求取消持久运行，包括没有内存线程的运行。取消响应正文或中止客户端范围的响应`abortSignal` only disconnects the observer from durable execution. A per-call `abortSignal` passed to a streaming method requests cancellation for you. Use `abortRun()` to stop a run without that signal.

```typescript
const runId = crypto.randomUUID()
const response = await agent.stream('Research this topic', { runId })

// When the user chooses Stop:
const { aborted } = await agent.abortRun(runId)
```

<PropertiesTable content={[{ name: 'runId', type: 'string', description: 'ID of the durable run to cancel.' }]} />

退货`{ aborted: boolean }`. A remote abort request is asynchronous, so `true` doesn't confirm that the worker has stopped. Unknown or completed runs return `false`. This method requires a durable agent and Agent execution permission. Run ownership checks apply. Runs with memory threads also require `memory:write` permission when fine-grained authorization is enabled. Non-durable agents return HTTP 501.

### `abortThread()` {/* #abortthread */}

请求取消线程的活动运行。放`clearPendingSignals: true` to clear pending signals before aborting.

```typescript
const { aborted } = await agent.abortThread({
  resourceId: 'user-123',
  threadId: 'thread-abc',
  clearPendingSignals: true,
})
```

Clear-on-abort affects the receiving server's local queues and is forwarded to the active owner. It isn't a global queue clear. Local pending signals are still cleared if no active run is found and `aborted` is `false`.

### `cancelQueuedMessages()` {/* #cancelqueuedmessages */}

取消选定的待处理信号而不停止活动运行。该操作涵盖处理此请求的服务器进程上共享同一内存线程的Agent之间的待处理输入。与核心方法不同，SDK 只接受信号 ID，而不接受`queueOwnerId`.

```typescript
const { cancelledSignalIds } = await agent.cancelQueuedMessages({
  resourceId: 'user-123',
  threadId: 'thread-abc',
  signalIds: ['signal-123', 'signal-456'],
})
```

退货`{ cancelledSignalIds: string[] }` with each ID cancelled on the receiving server process once. The response doesn't include remote acknowledgements. Signals already handed to execution or another owner aren't included. Missing, empty, or oversized ID lists return HTTP 400. Thread ownership restrictions apply to both cancellation routes.

服务器通过其共享的 PubSub 后端发布所有请求的 ID，即使接收进程中没有任何待处理的 ID。然后，其他订阅的实例可以删除匹配的挂起输入，但这种尽力而为的异步传播不会确认远程取消。取消不会撤消已保存的消息、状态更新、通知记录或接受确认。它不会取消继续`continueWithMessages()`.

服务器必须使用支持线程范围取消和中止清除的核心版本。升级`@mastra/core` alongside `@mastra/server`. Unsupported requests return HTTP 501 rather than using older cancellation behavior. With fine-grained authorization enabled, both cancellation routes require `memory:write` permission on the thread in addition to Agent execution permission.

### `streamUntilIdle()` {/* #streamuntilidle */}

流式传输响应并保持流打开，直到每个[background task](/docs/harness/background-tasks) dispatched during the run completes. The server re-enters the agentic loop on each task completion so the LLM can react to results in the same call. Requires background tasks to be [enabled on the Mastra instance](/reference/configuration#backgroundtasks) and a memory thread; otherwise the call uses a plain `stream()`.

```typescript
const response = await agent.streamUntilIdle('Research solana for me', {
  memory: {
    thread: 'thread-1',
    resource: 'resource-1',
  },
  maxIdleMs: 5 * 60_000, //optional
})

response.processDataStream({
  onChunk: async chunk => {
    if (chunk.type === 'background-task-completed') {
      console.log('task complete:', chunk.payload.taskId)
    }
  },
})
```

### `resumeStreamUntilIdle()` {/* #resumestreamuntilidle */}

使用自定义数据恢复挂起的Agent流，并保持流打开，直到每次[background task](/docs/harness/background-tasks) dispatched during the run completes. Use this to continue execution after a suspension point, such as a workflow suspend within an agent. Requires background tasks to be [enabled on the Mastra instance](/reference/configuration#backgroundtasks) and a memory thread; otherwise the call uses a plain `resumeStream()`:

```typescript
const response = await agent.resumeStreamUntilIdle(
  { approved: true, selectedOption: 'plan-b' },
  {
    memory: {
      thread: 'thread-1',
      resource: 'resource-1',
    },
    runId: 'run-123',
    toolCallId: 'tool-call-456', // optional
    maxIdleMs: 5 * 60_000, //optional
  },
)

await response.processDataStream({
  onChunk: chunk => {
    console.log(chunk)
  },
})
```

该流发出与以下相同的块类型`stream()`, plus `background-task-*` chunks for task lifecycle events. Visit [`Agent.streamUntilIdle()`](/reference/streaming/agents/streamUntilIdle) for the full server-side API and [background task chunks](/reference/streaming/ChunkType#background-task-chunks) for the payload shapes.

### `listSuspendedRuns()` {/* #listsuspendedruns */}

从存储中列出Agent的挂起运行：等待Tool调用批准或挂起的Tool的运行。发现由存储支持，因此它可以在服务器重新启动后跨服务器实例运行。通过返回的`runId` to `approveToolCall()`, `declineToolCall()`, or `resumeStream()`.

```typescript
const { runs, total } = await agent.listSuspendedRuns({
  threadId: 'thread-456',
  resourceId: 'user-123',
})

if (runs[0]) {
  console.log(runs[0].toolCalls) // [{ toolCallId, toolName, args, requiresApproval }]
  await agent.approveToolCall({
    runId: runs[0].runId,
    toolCallId: runs[0].toolCalls[0].toolCallId,
  })
}
```

接受可选过滤器（`threadId`, `resourceId`, `fromDate`, `toDate`) and pagination (`perPage`, `page`). Returns `{ runs, total }`, where `total` is the number of matching runs before pagination. See [`Agent.listSuspendedRuns()`](/reference/agents/listSuspendedRuns) for details on the returned run shape.

### `approveToolCall()` {/* #approvetoolcall */}

批准待处理的Tool调用并返回连续流。当您渲染批准响应中恢复的块时，请使用此选项。

```typescript
const response = await agent.approveToolCall({
  runId: 'run-123',
  toolCallId: 'tool-call-456',
})

response.processDataStream({
  onChunk: async chunk => {
    console.log(chunk)
  },
})
```

### `sendToolApproval()` {/* #sendtoolapproval */}

批准或拒绝订阅线程的待处理Tool调用。将此与`subscribeToThread()` when the resumed chunks should arrive through the existing thread subscription instead of a separate continuation stream.

```typescript
const result = await agent.sendToolApproval({
  resourceId: 'user-123',
  threadId: 'thread-456',
  toolCallId: 'tool-call-456',
  approved: true,
})

console.log(result.accepted)
```

退货`{ accepted: true, runId: string, toolCallId?: string }`.

### `declineToolCall()` {/* #declinetoolcall */}

拒绝挂起的Tool调用并返回连续流。当您渲染拒绝响应中恢复的块时，请使用此选项。通过可选的`reason` to tell the model why the call was rejected. The default is `Tool call was not approved by the user`.

```typescript
const response = await agent.declineToolCall({
  runId: 'run-123',
  toolCallId: 'tool-call-456',
  reason: 'This file is outside the allowed directory', // optional
})

response.processDataStream({
  onChunk: async chunk => {
    console.log(chunk)
  },
})
```

### `resumeStream()` {/* #resumestream */}

使用自定义数据恢复暂停的Agent流。使用它可以在暂停点后继续执行，例如Agent内的Workflow程暂停：

```typescript
const response = await agent.resumeStream(
  { approved: true, selectedOption: 'plan-b' },
  {
    runId: 'run-123',
    toolCallId: 'tool-call-456', // optional
  },
)

await response.processDataStream({
  onChunk: chunk => {
    console.log(chunk)
  },
})
```

### `approveToolCallGenerate()` {/* #approvetoolcallgenerate */}

使用时批准待处理的Tool调用`generate()` (non-streaming). Returns the complete response:

```typescript
const output = await agent.generate('Find user John', {
  requireToolApproval: true,
})

if (output.finishReason === 'suspended') {
  const result = await agent.approveToolCallGenerate({
    runId: output.runId,
    toolCallId: output.suspendPayload.toolCallId,
  })

  console.log(result.text)
}
```

### `declineToolCallGenerate()` {/* #declinetoolcallgenerate */}

使用时拒绝待处理的Tool调用`generate()` (non-streaming). Returns the complete response:

```typescript
const output = await agent.generate('Find user John', {
  requireToolApproval: true,
})

if (output.finishReason === 'suspended') {
  const result = await agent.declineToolCallGenerate({
    runId: output.runId,
    toolCallId: output.suspendPayload.toolCallId,
  })

  console.log(result.text)
}
```

## Agent日程 {/* #agent-schedules */}

使用客户端 SDK 调度方法来管理持久Agent调度`/api/schedules` routes. For concepts and server-side examples, see [Schedules](/docs/harness/schedules) and the [`mastra.schedules` reference](/reference/schedules/overview).

### `createSchedule()` {/* #createschedule */}

通过创建Agent计划`agentId`.

```typescript
const schedule = await mastraClient.createSchedule({
  agentId: 'pinger',
  cron: '0 * * * *',
  prompt: 'Give me a status update.',
})
```

## 客户端Tool {/* #client-tools */}

客户端Tool允许您在Agent请求时在客户端执行自定义功能。

```typescript
import { createTool } from '@mastra/client-js'
import { z } from 'zod'

const colorChangeTool = createTool({
  id: 'changeColor',
  description: 'Changes the background color',
  inputSchema: z.object({
    color: z.string(),
  }),
  execute: async inputData => {
    document.body.style.backgroundColor = inputData.color
    return { success: true }
  },
})

// Use with generate
const response = await agent.generate('Change the background to blue', {
  clientTools: { colorChangeTool },
})

// Use with stream
const response = await agent.stream('Tell me a story', {
  memory: {
    thread: 'thread-1',
    resource: 'resource-1',
  },
  clientTools: { colorChangeTool },
})

response.processDataStream({
  onChunk: async chunk => {
    if (chunk.type === 'text-delta') {
      console.log(chunk.payload.text)
    } else if (chunk.type === 'tool-call') {
      console.log(
        `calling tool ${chunk.payload.toolName} with args ${JSON.stringify(
          chunk.payload.args,
          null,
          2,
        )}`,
      )
    }
  },
})
```

### 塑造模型的客户端Tool输出 {/* #shape-client-tool-output-for-the-model */}

客户端Tool支持`toModelOutput` to control what the model receives, including multimodal content such as images. Because client tools execute locally, the mapping also runs on the client after `execute` completes. The client sends both the transformed output and the raw result back to the server, keeping the raw result available for storage and application logic.

```typescript
const screenshotTool = createTool({
  id: 'takeScreenshot',
  description: 'Takes a screenshot of the current page',
  inputSchema: z.object({}),
  execute: async () => {
    const base64 = await captureScreenshot()
    return { ok: true, data: base64 }
  },
  toModelOutput: output => ({
    type: 'content',
    value: [{ type: 'media', data: output.data, mediaType: 'image/jpeg' }],
  }),
})
```

### 追踪客户端Tool {/* #tracing-client-tools */}

什么时候`@mastra/observability` is installed and configured on the server, a client-side tool records a `CLIENT_TOOL_CALL` span as a child of the current `AGENT_RUN` span. The server creates that span when the model emits the client tool call and injects a W3C trace carrier into the outgoing tool-call chunk. It ends the span once the tool arguments are available. Without server-side observability configured, client tool tracing is a no-op.

客户端 SDK 还测量每个客户端Tool的挂钟持续时间`execute` function and sends it back to the server, where it's emitted as a `mastra_tool_duration_ms` metric with `toolType: "client"`.

从Tool内部获取更丰富的遥测数据`execute` function, use the `observe` helper on the execution context to add child spans and structured logs:

```typescript
import { createTool } from '@mastra/client-js'
import { z } from 'zod'

const fetchUserTool = createTool({
  id: 'fetchUser',
  description: 'Fetches the current user profile',
  inputSchema: z.object({ userId: z.string() }),
  execute: async ({ userId }, { observe }) => {
    observe.log('info', 'fetching user', { userId })
    const user = await observe.span('http GET /users', async () => {
      const res = await fetch(`/api/users/${userId}`)
      return res.json()
    })
    return user
  },
})
```

`observe`始终可用：当没有跟踪上下文处于活动状态时（例如在跟踪Agent外部运行），`span` runs the function directly and `log` is a no-op. No null-checking needed.

SDK 将收集器缓冲的所有内容序列化为 OTLP/JSON，并将其在下一个请求正文中发送回。服务器的`@mastra/observability` package validates that the spans belong to the correct trace (preventing cross-trace injection) and forwards each span/log into the same observability bus that server-side telemetry uses. Your existing exporters pick them up automatically after observability is configured.

## 存储Agent {/* #stored-agents */}

存储Agent是存储在数据库中的Agent配置，可以在运行时创建、更新和删除。它们通过键引用原语（Tool、Workflow程、其他Agent、记分器），这些原语在Agent实例化时从 Mastra 注册表中解析。内存被内联配置为`SerializedMemoryConfig` object with options such as `lastMessages` and `semanticRecall`.


具有分页和排序功能：

```typescript

  page: 0,
  perPage: 20,
  orderBy: {
    field: 'createdAt',
    direction: 'DESC',
  },
```

### `createStoredAgent()` {/* #createstoredagent */}

创建一个新的存储Agent：

```typescript
const agent = await mastraClient.createStoredAgent({
  id: 'my-agent',
  name: 'My Assistant',
  instructions: 'You are a helpful assistant.',
  model: {
    provider: 'openai',
    name: 'gpt-5.4',
  },
})
```

默认情况下，`createStoredAgent()` publishes the initial version immediately. Set `autoPublish` to `false` to create an unpublished draft that you can review before calling [`activateVersion()`](#activateversion):

```typescript
const draft = await mastraClient.createStoredAgent({
  id: 'draft-agent',
  name: 'Draft Assistant',
  instructions: 'You are a helpful assistant.',
  model: {
    provider: 'openai',
    name: '__AI_SDK_OPENAI_MODEL_BASE__',
  },
  autoPublish: false,
})
```

编辑器配置为`code` source always publish the initial version because saving writes the agent configuration to the file system.

具有所有选项：

```typescript
const agent = await mastraClient.createStoredAgent({
  id: 'full-agent',
  name: 'Full Agent',
  description: 'A fully configured agent',
  instructions: 'You are a helpful assistant.',

    provider: 'openai',
    name: 'gpt-5.4',

  workflows: { 'data-processing': {} },

      lastMessages: 20,
      semanticRecall: false,
    },
  },
  scorers: {
    'quality-scorer': {
      sampling: { type: 'ratio', rate: 0.1 },
    },
  },
  defaultOptions: {
    maxSteps: 10,
  },
  metadata: {
    version: '1.0',
    team: 'engineering',
  },
  durable: true,
})
```

#### 存储Agent的可恢复流 {/* #resumable-streams-for-stored-agents */}

放`durable` to configure [resumable streams](/docs/agents/resumable-streams) on the hydrated plain agent. Pass `true` to enable streams, `false` to disable them, or an object to tune stream cleanup:

```typescript
const agent = await mastraClient.createStoredAgent({
  id: 'durable-agent',
  name: 'Durable Agent',
  instructions: 'You are a helpful assistant.',
  model: {
    provider: 'openai',
    name: 'gpt-5.4',
  },
  durable: { cleanupTimeoutMs: 0 },
})
```

只接受可序列化的选项，缓存和 pubsub 继承自服务器的`Mastra` instance. Existing stored agents with `durable: true` also use this field for resumable streams only. To retain durable execution and checkpoint recovery, register a code agent wrapped with `createDurableAgent({ agent })`.
