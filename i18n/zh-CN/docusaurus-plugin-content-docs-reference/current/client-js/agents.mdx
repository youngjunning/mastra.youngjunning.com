# Agents API

Agents API 提供与 Mastra AI Agent 交互的方法，包括生成响应和流式交互，还提供管理 Agent 的 Tool 的方法。

## 获取所有Agent {/* #getting-all-agents */}

检索所有可用Agent的列表：

```typescript
const agents = await mastraClient.listAgents()
```

返回以 Agent ID 为键、序列化 Agent 配置为值的记录。

## 使用特定 Agent {/* #working-with-a-specific-agent */}

通过 ID 获取特定Agent的实例：

```typescript title="src/mastra/agents/my-agent.ts"
import { Agent } from '@mastra/core/agent'

export const myAgent = new Agent({
  id: 'my-agent',
})
```

```typescript
const agent = mastraClient.getAgent('my-agent')
```

## Agent 方法 {/* #agent-methods */}

### `details()` {/* #details */}

检索有关Agent的详细信息：

```typescript
const details = await agent.details()
```

### `generate()` {/* #generate */}

从Agent生成响应：

```typescript
const response = await agent.generate(
  [
    {
      role: 'user',
      content: 'Hello, how are you?',
    },
  ],
  {
    memory: {
      thread: 'thread-abc', // Optional: Thread ID for conversation context
      resource: 'user-123', // Optional: Resource ID
    },
    structuredOutput: {}, // Optional: Structured Output configuration
  },
)
```

您还可以使用带有内存选项的简化字符串格式：

```typescript
const response = await agent.generate('Hello, how are you?', {
  memory: {
    thread: 'thread-1',
    resource: 'resource-1',
  },
})
```

### `stream()` {/* #stream */}

流式传输来自Agent的响应以进行实时交互：

```typescript
const response = await agent.stream('Tell me a story')

// Process data stream with the processDataStream util
response.processDataStream({
  onChunk: async chunk => {
    console.log(chunk)
  },
})
```

您还可以使用带有内存选项的简化字符串格式：

```typescript
const response = await agent.stream('Tell me a story', {
  memory: {
    thread: 'thread-1',
    resource: 'resource-1',
  },
  clientTools: { colorChangeTool },
})

response.processDataStream({
  onChunk: async chunk => {
    if (chunk.type === 'text-delta') {
      console.log(chunk.payload.text)
    }
  },
})
```

您还可以直接从响应正文中读取：

```typescript
const reader = response.body.getReader()
while (true) {
  const { done, value } = await reader.read()
  if (done) break
  console.log(new TextDecoder().decode(value))
}
```

#### 取消流 {/* #cancelling-a-stream */}

取消响应正文将中止底层 HTTP 请求并停止任何待处理的客户端Tool执行和后续请求：

```typescript
const response = await agent.stream('Tell me a story')
const reader = response.body.getReader()

const { value } = await reader.read()
await reader.cancel('user navigated away')
```

也可以传入 `abortSignal`，从流外部取消请求。`streamUntilIdle()`、`resumeStream()`、`resumeStreamUntilIdle()`、`approveToolCall()`、`declineToolCall()`、`generate()` 和 `generateLegacy()` 也支持这一选项：

```typescript
const controller = new AbortController()

const response = await agent.stream('Tell me a story', {
  abortSignal: controller.signal,
})

// Later
controller.abort()
```

#### AI SDK兼容格式 {/* #ai-sdk-compatible-format */}

若要在客户端从 `agent.stream(...)` 的响应中获取 AI SDK 格式的流式内容，请将 `response.processDataStream` 封装为 `ReadableStream<ChunkType>`，再使用 `toAISdkStream`：

```typescript title="client-ai-sdk-transform.ts"
import { createUIMessageStream } from 'ai'
import { toAISdkStream } from '@mastra/ai-sdk'
import type { ChunkType, MastraModelOutput } from '@mastra/core/stream'

const response = await agent.stream('Tell me a story')

const chunkStream: ReadableStream<ChunkType> = new ReadableStream<ChunkType>({
  start(controller) {
    response
      .processDataStream({
        onChunk: async chunk => controller.enqueue(chunk as ChunkType),
      })
      .finally(() => controller.close())
  },
})

const uiMessageStream = createUIMessageStream({
  execute: async ({ writer }) => {
    for await (const part of toAISdkStream(chunkStream as unknown as MastraModelOutput, {
      from: 'agent',
    })) {
      writer.write(part)
    }
  },
})

for await (const part of uiMessageStream) {
  console.log(part)
}
```

### `sendMessage()` {/* #sendmessage */}

将用户输入发送给正在运行的 Agent 或空闲的记忆线程。配合 `subscribeToThread()` 使用，客户端即可渲染该消息唤醒线程或被当前运行接收后产生的流式输出。

```typescript
const agent = mastraClient.getAgent('support-agent')

const result = await agent.sendMessage({
  message: {
    contents: 'Also consider the customer note I just added.',
    attributes: { sentFrom: 'web' },
  },
  resourceId: 'user-123',
  threadId: 'thread-abc',
})

console.log(result.runId)
```

`message` 接受字符串、文本或文件片段数组，或包含 `contents`、`attributes`、`metadata` 和 `providerOptions` 的对象。

### `queueMessage()` {/* #queuemessage */}

将用户输入排入队列，供线程下一轮处理。如果线程正在运行，Mastra 会在当前运行结束后启动新运行；如果线程空闲，则会立即启动。

```typescript
await agent.queueMessage({
  message: 'Also check whether the tests need updates.',
  resourceId: 'user-123',
  threadId: 'thread-abc',
})
```

### `queueSignal()` {/* #queuesignal */}

将带类型的信号排入队列，供线程下一轮处理。其排序规则与 `queueMessage()` 相同，同时保留信号的 `type`、`tagName` 和 `attributes`。

```typescript
await agent.queueSignal({
  signal: {
    type: 'reactive',
    tagName: 'skill',
    attributes: { name: 'triage' },
    contents: 'Triage the new issue.',
  },
  resourceId: 'user-123',
  threadId: 'thread-abc',
})
```

### `sendSignal()` {/* #sendsignal */}

向正在运行的 Agent 或记忆线程发送底层信号。适用于无需存入收件箱的系统上下文，例如响应式提醒或通知类上下文。需要持久化通知记录时，请使用服务端 [`Agent.sendNotificationSignal()`](/reference/agents/agent#sendnotificationsignalnotification-options) API。对于用户输入，优先使用 `sendMessage()` 或 `queueMessage()`。

```typescript
const agent = mastraClient.getAgent('support-agent')

const result = await agent.sendSignal({
  signal: {
    type: 'reactive',
    tagName: 'system-reminder',
    contents: 'Also consider the latest customer note.',
  },
  resourceId: 'user-123',
  threadId: 'thread-abc',
})

console.log(result.runId)
```

使用 `ifActive.behavior` 和 `ifIdle.behavior` 控制 Mastra 如何投递、持久化或丢弃信号，以及是否由信号唤醒线程：

```typescript
await agent.sendSignal({
  signal: { type: 'reactive', tagName: 'system-reminder', contents: 'Store this for later.' },
  resourceId: 'user-123',
  threadId: 'thread-abc',
  ifIdle: {
    behavior: 'persist',
  },
})
```

如果唤醒空闲线程的流需要模型设置、Tool 或运行时上下文等选项，请传入 `ifIdle.streamOptions`：

```typescript
await agent.sendSignal({
  signal: { type: 'reactive', tagName: 'system-reminder', contents: 'Start from this signal.' },
  resourceId: 'user-123',
  threadId: 'thread-abc',
  ifIdle: {
    behavior: 'wake',
    streamOptions: {
      maxSteps: 3,
    },
  },
})
```

返回 `{ accepted: true, runId: string }`。

### `subscribeToThread()` {/* #subscribetothread */}

订阅记忆线程的原始流数据块。可用它渲染由 `sendMessage()`、`queueMessage()`、`sendSignal()` 或服务端通知派发启动或继续的线程所产生的输出。

```typescript
const agent = mastraClient.getAgent('support-agent')

const subscription = await agent.subscribeToThread({
  resourceId: 'user-123',
  threadId: 'thread-abc',
})

await subscription.processDataStream({
  onChunk: chunk => {
    console.log(chunk)
  },
  reconnect: true,
})
```

传入 `withInitialHistory: true`（或 `{ perPage }`），即可在首个 `thread-history` 数据块中接收已存储的消息，无需单独获取历史记录。之后不会重放已完成的运行，因此重新连接时不会再次流式返回已完成的回答。

在 React SDK 中，`useChat()` 通过 `initialHistoryPagination` 提供首页历史记录的 `hasMore` 标志，让你无需再次请求历史记录，就能判断是否提供加载更早消息的选项：

```typescript
import { useChat } from '@mastra/react'

const { messages, initialHistoryPagination } = useChat({
  agentId: 'support-agent',
  resourceId: 'user-123',
  threadId: 'thread-abc',
  enableThreadSignals: true,
  withInitialHistory: { perPage: 20 },
})

// { hasMore: true }: older messages exist
// { hasMore: false }: the page reaches the start of the thread
// undefined: history is disabled, still loading, or the subscription ended
```

`initialHistoryPagination` 仅描述当前 Agent、资源、线程及 `withInitialHistory` 值对应的初始订阅页。实时输出或 `setMessages()` 不会改变它。自行加载更早的页面后，请使用这些响应中的 `hasMore` 值。

`subscribeToThread()` 返回底层 `Response` 和 `processDataStream()` 辅助方法。该方法会持续读取订阅流，直到连接关闭或请求被中止。传入 `reconnect: true` 后，传输连接关闭或重新连接失败时会再次订阅，例如代理空闲超时之后。如果重新连接请求返回 4xx 状态码（如 `401` 或 `403`）或 `501`，`processDataStream()` 会停止重试，并以原始 `MastraClientError` 拒绝；`408` 和 `429` 仍会重试。

订阅还提供 `abort(options?)` 和 `unsubscribe()`。`await subscription.abort({ clearPendingSignals: true })` 会请求中止运行并清除待处理信号，但不会关闭订阅。省略该标志可保留待处理输入。`unsubscribe()` 会关闭订阅，但不会中止运行。

### `abortRun(runId)` {/* #abortrunrunid */}

通过 ID 请求取消持久化运行，包括没有记忆线程的运行。取消响应正文或中止客户端范围的 `abortSignal`，只会断开观察者与持久化执行的连接。向流式方法传入单次调用的 `abortSignal` 会请求取消运行。没有该信号时，可使用 `abortRun()` 停止运行。

```typescript
const runId = crypto.randomUUID()
const response = await agent.stream('Research this topic', { runId })

// When the user chooses Stop:
const { aborted } = await agent.abortRun(runId)
```

<PropertiesTable content={[{ name: 'runId', type: 'string', description: '要取消的持久化运行 ID。' }]} />

返回 `{ aborted: boolean }`。远程中止请求是异步的，因此 `true` 不表示执行进程已经停止。未知或已完成的运行返回 `false`。此方法要求使用持久化 Agent，并具备 Agent 执行权限；运行归属检查同样适用。启用细粒度授权后，带记忆线程的运行还需要 `memory:write` 权限。非持久化 Agent 返回 HTTP 501。

### `abortThread()` {/* #abortthread */}

请求取消线程中正在进行的运行。设置 `clearPendingSignals: true` 可在中止前清除待处理信号。

```typescript
const { aborted } = await agent.abortThread({
  resourceId: 'user-123',
  threadId: 'thread-abc',
  clearPendingSignals: true,
})
```

### `cancelQueuedMessages()` {/* #cancelqueuedmessages */}

取消选定的待处理信号，但不停止活动运行。该操作涵盖处理请求的服务器进程中，共享同一记忆线程的各个 Agent 的待处理输入。与核心方法不同，SDK 仅接受信号 ID，不接受 `queueOwnerId`。

```typescript
const { cancelledSignalIds } = await agent.cancelQueuedMessages({
  resourceId: 'user-123',
  threadId: 'thread-abc',
  signalIds: ['signal-123', 'signal-456'],
})
```

返回 `{ cancelledSignalIds: string[] }`，其中每个 ID 都在接收请求的服务器进程中取消一次。响应不包含远程实例的确认。已交给执行过程或其他持有者的信号不在其中。缺少 ID 列表、列表为空或超出数量限制时，返回 HTTP 400。两条取消路由都受线程归属限制。

服务器会通过共享的 PubSub 后端发布所有请求的 ID，即使接收进程中没有对应的待处理信号。其他订阅实例随后可以移除匹配的待处理输入，但这种尽力而为的异步传播不会确认远程取消。取消操作不会撤销已保存的消息、状态更新、通知记录或接受确认，也不会取消由 `continueWithMessages()` 发起的后续执行。

服务器必须使用支持整个线程范围内取消信号及中止时清除信号的核心版本。请同时升级 `@mastra/core` 和 `@mastra/server`。不支持的请求会返回 HTTP 501，而不会使用旧的取消行为。启用细粒度授权后，两条取消路由除要求 Agent 执行权限外，还要求对该线程拥有 `memory:write` 权限。

### `streamUntilIdle()` {/* #streamuntilidle */}

以流式方式返回响应，并保持连接，直到本次运行派发的所有[后台任务](/docs/harness/background-tasks)完成。每当一个任务完成，服务端都会重新进入 Agent 循环，让 LLM 在同一次调用中处理结果。此方法要求在 [Mastra 实例上启用后台任务](/reference/configuration#backgroundtasks)，且提供记忆线程；否则会退化为普通的 `stream()` 调用。

```typescript
const response = await agent.streamUntilIdle('Research solana for me', {
  memory: {
    thread: 'thread-1',
    resource: 'resource-1',
  },
  maxIdleMs: 5 * 60_000, //optional
})

response.processDataStream({
  onChunk: async chunk => {
    if (chunk.type === 'background-task-completed') {
      console.log('task complete:', chunk.payload.taskId)
    }
  },
})
```

### `resumeStreamUntilIdle()` {/* #resumestreamuntilidle */}

使用自定义数据恢复已挂起的 Agent 流，并保持流连接，直到本次运行派发的所有[后台任务](/docs/harness/background-tasks)完成。可用它从挂起点继续执行，例如 Agent 内的 Workflow 挂起。此方法要求在 [Mastra 实例上启用后台任务](/reference/configuration#backgroundtasks)，且提供记忆线程；否则会调用普通的 `resumeStream()`：

```typescript
const response = await agent.resumeStreamUntilIdle(
  { approved: true, selectedOption: 'plan-b' },
  {
    memory: {
      thread: 'thread-1',
      resource: 'resource-1',
    },
    runId: 'run-123',
    toolCallId: 'tool-call-456', // optional
    maxIdleMs: 5 * 60_000, //optional
  },
)

await response.processDataStream({
  onChunk: chunk => {
    console.log(chunk)
  },
})
```

该流会发出与 `stream()` 相同类型的数据块，还会发出表示任务生命周期事件的 `background-task-*` 数据块。完整的服务端 API 请参阅 [`Agent.streamUntilIdle()`](/reference/streaming/agents/streamUntilIdle)；数据结构请参阅[后台任务数据块](/reference/streaming/ChunkType#background-task-chunks)。

### `listSuspendedRuns()` {/* #listsuspendedruns */}

从存储中列出 Agent 的挂起运行，包括等待 Tool 调用审批或因 Tool 挂起而暂停的运行。由于从存储中查找，这些运行在服务器重启后及不同服务器实例上仍可被发现。将返回的 `runId` 传给 `approveToolCall()`、`declineToolCall()` 或 `resumeStream()`。

```typescript
const { runs, total } = await agent.listSuspendedRuns({
  threadId: 'thread-456',
  resourceId: 'user-123',
})

if (runs[0]) {
  console.log(runs[0].toolCalls) // [{ toolCallId, toolName, args, requiresApproval }]
  await agent.approveToolCall({
    runId: runs[0].runId,
    toolCallId: runs[0].toolCalls[0].toolCallId,
  })
}
```

支持可选筛选条件（`threadId`、`resourceId`、`fromDate`、`toDate`）和分页参数（`perPage`、`page`）。返回 `{ runs, total }`，其中 `total` 是分页前匹配的运行总数。返回的运行对象结构详见 [`Agent.listSuspendedRuns()`](/reference/agents/listSuspendedRuns)。

### `approveToolCall()` {/* #approvetoolcall */}

批准待处理的Tool调用并返回连续流。当您渲染批准响应中恢复的块时，请使用此选项。

```typescript
const response = await agent.approveToolCall({
  runId: 'run-123',
  toolCallId: 'tool-call-456',
})

response.processDataStream({
  onChunk: async chunk => {
    console.log(chunk)
  },
})
```

### `sendToolApproval()` {/* #sendtoolapproval */}

批准或拒绝已订阅线程中待处理的 Tool 调用。如果希望恢复执行后的数据块通过现有线程订阅到达，而非通过单独的后续执行流返回，请将此方法与 `subscribeToThread()` 配合使用。

```typescript
const result = await agent.sendToolApproval({
  resourceId: 'user-123',
  threadId: 'thread-456',
  toolCallId: 'tool-call-456',
  approved: true,
})

console.log(result.accepted)
```

返回 `{ accepted: true, runId: string, toolCallId?: string }`。

### `declineToolCall()` {/* #declinetoolcall */}

拒绝待处理的 Tool 调用并返回后续执行流。需要渲染拒绝响应中恢复执行后的数据块时，使用此方法。可通过可选的 `reason` 告诉模型拒绝原因。默认值为 `Tool call was not approved by the user`。

```typescript

  runId: 'run-123',
  toolCallId: 'tool-call-456',

})

response.processDataStream({
  onChunk: async chunk => {
    console.log(chunk)
  },
})
```

### `resumeStream()` {/* #resumestream */}

使用自定义数据恢复已挂起的 Agent 流。可用它从挂起点继续执行，例如 Agent 内的 Workflow 挂起：

```typescript

    toolCallId: 'tool-call-456', // optional
```

## 客户端Tool {/* #client-tools */}

客户端Tool允许您在Agent请求时在客户端执行自定义功能。

```typescript
import { createTool } from '@mastra/client-js'
import { z } from 'zod'

const colorChangeTool = createTool({
  id: 'changeColor',
  description: 'Changes the background color',
  inputSchema: z.object({
    color: z.string(),
  }),
  execute: async inputData => {
    document.body.style.backgroundColor = inputData.color
    return { success: true }
  },
})

// Use with generate
const response = await agent.generate('Change the background to blue', {
  clientTools: { colorChangeTool },
})

// Use with stream
const response = await agent.stream('Tell me a story', {
  memory: {
    thread: 'thread-1',
    resource: 'resource-1',
  },
  clientTools: { colorChangeTool },
})

response.processDataStream({
  onChunk: async chunk => {
    if (chunk.type === 'text-delta') {
      console.log(chunk.payload.text)
    } else if (chunk.type === 'tool-call') {
      console.log(
        `calling tool ${chunk.payload.toolName} with args ${JSON.stringify(
          chunk.payload.args,
          null,
          2,
        )}`,
      )
    }
  },
})
```

### 塑造模型的客户端Tool输出 {/* #shape-client-tool-output-for-the-model */}

客户端 Tool 支持通过 `toModelOutput` 控制模型接收的内容，包括图像等多模态内容。由于客户端 Tool 在本地执行，映射过程也会在 `execute` 完成后于客户端运行。客户端会将转换后的输出和原始结果一并发送回服务端，使原始结果仍可用于存储和应用逻辑。

```typescript
const screenshotTool = createTool({
  id: 'takeScreenshot',
  description: 'Takes a screenshot of the current page',
  inputSchema: z.object({}),
  execute: async () => {
    const base64 = await captureScreenshot()
    return { ok: true, data: base64 }
  },
  toModelOutput: output => ({
    type: 'content',
    value: [{ type: 'media', data: output.data, mediaType: 'image/jpeg' }],
  }),
})
```

### 追踪客户端Tool {/* #tracing-client-tools */}

服务端安装并配置 `@mastra/observability` 后，客户端 Tool 会记录一个 `CLIENT_TOOL_CALL` span，作为当前 `AGENT_RUN` span 的子节点。模型发出客户端 Tool 调用时，服务端创建该 span，并将 W3C Trace 上下文注入发出的 Tool 调用数据块；Tool 参数就绪后，该 span 结束。如果服务端未配置可观测性，客户端 Tool 追踪不会产生任何效果。

客户端 SDK 还会测量每个客户端 Tool 的 `execute` 函数耗费的实际时间，并将结果发回服务端，以 `toolType: "client"` 标记的 `mastra_tool_duration_ms` 指标记录。

要在 Tool 的 `execute` 函数内记录更丰富的遥测数据，可使用执行上下文中的 `observe` 辅助对象添加子 span 和结构化日志：

```typescript
import { createTool } from '@mastra/client-js'
import { z } from 'zod'

const fetchUserTool = createTool({
  id: 'fetchUser',
  description: 'Fetches the current user profile',
  inputSchema: z.object({ userId: z.string() }),
  execute: async ({ userId }, { observe }) => {
    observe.log('info', 'fetching user', { userId })
    const user = await observe.span('http GET /users', async () => {
      const res = await fetch(`/api/users/${userId}`)
      return res.json()
    })
    return user
  },
})
```

`observe` 始终可用。没有活动的追踪上下文时（例如在被追踪的 Agent 外部运行），`span` 会直接执行函数，`log` 不会执行任何操作，无需进行空值检查。

SDK 会将收集器缓冲的所有内容序列化为 OTLP/JSON，并在下一次请求的正文中发送回服务端。服务端的 `@mastra/observability` 包会验证各个 span 是否属于正确的 Trace（防止跨 Trace 注入），再将每个 span 和日志转发到服务端遥测数据使用的同一可观测性总线。配置可观测性后，现有的导出器会自动接收这些数据。

## 存储Agent {/* #stored-agents */}

存储型 Agent 是保存在数据库中的 Agent 配置，可在运行时创建、更新和删除。它们通过键引用 Tool、Workflow、其他 Agent 和评分器等基础组件；实例化 Agent 时，系统会从 Mastra 注册表解析这些引用。记忆配置以内联的 `SerializedMemoryConfig` 对象提供，可设置 `lastMessages` 和 `semanticRecall` 等选项。

```typescript
console.log(result.total) // Total count
```

具有分页和排序功能：

```typescript
const result = await mastraClient.listStoredAgents({
```

### `createStoredAgent()` {/* #createstoredagent */}

创建一个新的存储Agent：


默认情况下，`createStoredAgent()` 会立即发布初始版本。将 `autoPublish` 设为 `false`，可先创建未发布的草稿，审核后再调用 [`activateVersion()`](#activateversion)：

```typescript
    name: '__AI_SDK_OPENAI_MODEL_BASE__',

})
```

配置为 `code` 来源的编辑器始终会发布初始版本，因为保存操作会将 Agent 配置写入文件系统。

具有所有选项：

```typescript

  id: 'full-agent',
  name: 'Full Agent',

  instructions: 'You are a helpful assistant.',

    options: {
      lastMessages: 20,

  scorers: {
    'quality-scorer': {

    },
  },
  defaultOptions: {
    maxSteps: 10,
  },

    version: '1.0',

  },

})
```

#### 存储Agent的可恢复流 {/* #resumable-streams-for-stored-agents */}

设置 `durable`，可为还原后的普通 Agent 配置[可恢复流](/docs/agents/resumable-streams)。传入 `true` 启用可恢复流，传入 `false` 禁用，或传入对象调整流的清理行为：

```typescript
const agent = await mastraClient.createStoredAgent({
  id: 'durable-agent',
  name: 'Durable Agent',
  instructions: 'You are a helpful assistant.',
  model: {
    provider: 'openai',
    name: 'gpt-5.4',
  },
  durable: { cleanupTimeoutMs: 0 },
})
```

仅接受可序列化的选项；缓存和 PubSub 继承自服务端的 `Mastra` 实例。对于已有且设置了 `durable: true` 的存储型 Agent，此字段也仅用于可恢复流。如需保留持久化执行和检查点恢复，请注册使用 `createDurableAgent({ agent })` 包装的代码定义 Agent。
