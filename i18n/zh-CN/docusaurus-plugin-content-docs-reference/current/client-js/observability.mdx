# Observability API

Observability API 提供检索跟踪、监控应用性能、对跟踪评分以供评估，以及记录与跟踪和跨度关联的反馈的方法。

## 获取指定跟踪 {/* #getting-a-specific-trace */}

根据 ID 检索指定跟踪，包括其所有跨度及详细信息：

```typescript
const trace = await mastraClient.getTrace('trace-id-123')
```

## 筛选并获取跟踪 {/* #getting-traces-with-filtering */}

使用可选筛选条件，分页检索跟踪根跨度：

```typescript
const traces = await mastraClient.getTraces({
  pagination: {
    page: 1,
    perPage: 20,
    dateRange: {
      start: new Date('2024-01-01'),
      end: new Date('2024-01-31'),
    },
  },
  filters: {
    name: 'weather-agent', // Filter by trace name
    spanType: 'agent', // Filter by span type
    entityId: 'weather-agent-id', // Filter by entity ID
    entityType: 'agent', // Filter by entity type
  },
})

console.log(`Found ${traces.spans.length} root spans`)
console.log(`Total pages: ${traces.pagination.totalPages}`)

// To get the complete trace with all spans, use getTrace
const completeTrace = await mastraClient.getTrace(traces.spans[0].traceId)
```

## 列出供列表视图使用的跟踪 {/* #listing-traces-for-a-list-view */}

`listTracesLight()` 返回与跟踪列表相同的记录，但不包含 `input`、`output` 和 `attributes` 的完整数据。每条记录改为提供简短的 `inputPreview`、`outputPreview` 和 `errorPreview` 字符串（最多 100 个字符，截断时以 `…` 结尾），使列表无需传输完整数据即可显示预览列。记录还包含供内存上下文列使用的 `threadId` 和 `resourceId`。

同时显示大量跟踪时，优先使用此方法；仅在用户打开某条记录时获取其完整内容：

```typescript
const list = await mastraClient.listTracesLight({
  pagination: { page: 0, perPage: 25 },
  filters: { entityType: 'agent' },
})

for (const span of list.spans) {
  console.log(span.name, span.inputPreview)
}

// Fetch the full payload only for the trace the user selects
const selected = await mastraClient.getTrace(list.spans[0].traceId)
```

它接受与 `listTraces()` 相同的筛选、排序和增量轮询参数。确实需要完整跨度数据时，请使用 `listTraces()`。

## 查询跨度 {/* #querying-spans */}

`querySpans()` 返回跨跟踪的已完成跨度摘要。它要求提供按跨度开始时间划定的有效 ISO 时间戳范围，并支持游标分页：

```typescript
const result = await mastraClient.querySpans({
  timeRange: {
    from: '2026-10-01T00:00:00.000Z',
    to: '2026-10-02T00:00:00.000Z',
  },
  where: {
    op: 'and',
    args: [
      { op: 'eq', left: { path: 'threadId' }, right: { literal: 'thread-123' } },
      { op: 'gte', left: { path: 'durationMs' }, right: { literal: 1000 } },
    ],
  },
  orderBy: [{ field: 'startedAt', direction: 'desc' }],
  page: { limit: 100 },
})

// Pass result.page.next as page.after to continue with the same filters and ordering.
console.log(result.spans)
```

响应格式为 `{ spans, page: { next } }`。调用前请检查 `capabilities.spanQuery`；使用可选筛选条件前，还应检查对应字段的能力支持情况。字段、运算符、默认值、能力、响应详情及游标处理方式，请参阅[查询跨度](/reference/observability/tracing/advanced-queries#query-spans)。

### 聚合跨度 {/* #aggregate-spans */}

`aggregateSpans()` 对符合直接跨度谓词的已完成跨度进行分组。它为每个分组返回一行；设置 `interval` 后，为每个分组的每个非空时间段返回一行。它统计任意层级的跨度，包括跟踪聚合可能遗漏的嵌套 Agent 运行：

```typescript
const { capabilities } = await mastraClient.getObservabilityCapabilities()

if (capabilities.spanAggregate) {
  const { rows, truncated } = await mastraClient.aggregateSpans({
    timeRange: {
      from: '2026-10-01T00:00:00.000Z',
      to: '2026-10-08T00:00:00.000Z',
    },
    where: { op: 'eq', left: { path: 'spanType' }, right: { literal: 'agent_run' } },
    groupBy: ['status'],
    interval: '1d',
    measures: ['count', 'errorRate'],
  })
}
```

请求和响应结构与 `aggregateTraces()` 一致，但使用直接跨度谓词，以及 `spanType`、`name`、`parentEntityName` 等跨度维度。token 和费用指标归属于记录用量的跨度，不会累加到父跨度。调用前请检查 `capabilities.spanAggregate`；按 `model` 或 `provider` 分组或统计不同值前，请检查 `capabilities.spanAggregateModelDimensions`。使用旧版适配器时，这些请求会返回 `501`。

当 `capabilities.aggregateTimeToFirstMeasures` 为 `true` 时，`aggregateTraces()` 和 `aggregateSpans()` 均支持首个 token 耗时（TTFT）和首个数据块耗时（TTFC）指标，即 `timeToFirstToken.*` 和 `timeToFirstChunk.*`。没有记录相应值的跨度和跟踪会被跳过，不会按 0 计入。请参阅[首个数据块耗时（TTFC）](/reference/observability/tracing/advanced-queries#time-to-first-chunk-ttfc)和[首个 token 耗时（TTFT）](/reference/observability/tracing/advanced-queries#time-to-first-token-ttft)。

有关筛选、维度、各跨度的用量，以及如何列出分组中的跨度，请参阅[聚合跨度](/reference/observability/tracing/advanced-queries#aggregate-spans)。

## 查询线程 {/* #querying-threads */}

`queryTraceThreads()` 通过 `POST /observability/threads/query`，根据已完成的跟踪返回线程摘要。每行包含活动时间戳、跟踪数量、上下文和预览。没有线程 ID 的跟踪不会包含在结果中。

```typescript
const result = await mastraClient.queryTraceThreads({
  timeRange: {
    traces: {
      from: '2026-10-01T00:00:00.000Z',
      to: '2026-10-02T00:00:00.000Z',
    },
  },
  where: { op: 'eq', left: { path: 'status' }, right: { literal: 'error' } },
  orderBy: [{ field: 'endedAt', direction: 'desc' }],
  page: { limit: 100 },
})

for (const thread of result.threads) {
  console.log(thread.firstTraceId, thread.lastTraceId, thread.traceCount, thread.outputPreview)
}
```

### 线程时间范围 {/* #thread-time-ranges */}

只能选择一种时间条件。每个范围都需要 ISO 时间戳，且 `from` 必须早于 `to`。范围包含 `from`，不包含 `to`。

| 时间条件 | 匹配的线程 |
| - | - |
| `timeRange.traces: { from, to }` | 至少有一条跟踪在该时间范围内开始 |
| `timeRange.threads: { field: 'startedAt', from, to }` | 首次活动发生在该时间范围内 |
| `timeRange.threads: { field: 'endedAt', from, to }` | 最近一次活动发生在该时间范围内 |

例如，查找最近活动发生在 10 月 1 日的线程：

```typescript
const result = await mastraClient.queryTraceThreads({
  timeRange: {
    threads: {
      field: 'endedAt',
      from: '2026-10-01T00:00:00.000Z',
      to: '2026-10-02T00:00:00.000Z',
    },
  },
})
```

每行包含授权范围内保留的完整历史，包括时间范围前后的跟踪。筛选条件应用于这些完整记录。`environment` 筛选条件检查第一条跟踪的环境。

### 线程筛选条件 {/* #thread-filters */}

使用 `where` 筛选线程记录。可以通过 `and`、`or` 和 `not` 组合谓词。

| 字段 | 运算符 |
| - | - |
|`threadId`, `organizationId`, `firstTraceId`, `lastTraceId` | `eq`, `ne`, `in`, `notIn`, `exists`, `notExists` |
| `resourceId`, `userId`, `runId`, `sessionId`, `requestId`, `serviceName`, `experimentId`, `environment`, `executionSource` | 同上，使用字符串运算符 |
| `entityType`, `entityId`, `entityName`, `entityVersionId` | 同上，使用字符串运算符 |
| `status` | `eq`、`ne`、`in`、`notIn`，值为 `success` 或 `error` |
| `startedAt`, `endedAt`, `timeToFirstChunkMs`, `timeToFirstTokenMs` | `eq`, `ne`, `lt`, `lte`, `gt`, `gte`, `in`, `notIn`, `exists`, `notExists` |
| `traceCount` | `eq`, `ne`, `lt`, `lte`, `gt`, `gte` |

例如，筛选来自指定 Agent 且至少包含三条跟踪的线程：

```typescript
const result = await mastraClient.queryTraceThreads({
  timeRange: {
    traces: {
      from: '2026-10-01T00:00:00.000Z',
      to: '2026-10-02T00:00:00.000Z',
    },
  },
  where: {
    op: 'and',
    args: [
      { op: 'in', value: { path: 'entityId' }, set: ['support-agent', 'sales-agent'] },
      { op: 'gte', left: { path: 'traceCount' }, right: { literal: 3 } },
    ],
  },
})
```

使用存在性筛选条件 `{ op: 'exists', path: 'userId' }` 检查值是否非空。返回的记录包含 model、provider 和预览，但不能按这些字段筛选。

### 线程响应 {/* #thread-response */}

响应格式为 `{ threads, page: { next } }`，不包含总数。`threads` 中的每条记录包含以下字段：

| 返回字段 | 含义 |
| - | - |
| `threadId`, `organizationId` | 线程标识。不同组织中相同的线程 ID 仍分别表示不同的线程。 |
| `firstTraceId`, `lastTraceId` | 按开始时间排序的最早和最新跟踪。开始时间相同时，使用跟踪 ID 确定顺序。 |
| `resourceId`, `userId`, `runId`, `sessionId`, `requestId`, `serviceName`, `experimentId`, `environment`, `executionSource` | 第一条跟踪的上下文；缺失时为 `null`。 |
| `entityType`, `entityId`, `entityName`, `entityVersionId` | 第一条跟踪的实体信息。 |
| `startedAt`, `endedAt` | 线程内最早的开始时间和最晚的结束时间。 |
| `status` | 如果开始时间最晚的跟踪的根跨度发生错误，则为 `error`；否则为 `success`。 |
| `traceCount` | 线程中的逻辑跟踪数量。 |
| `inputPreview` | 第一条跟踪的输入预览。 |
| `outputPreview`, `errorPreview` | 开始时间最晚的跟踪的预览。 |
| `timeToFirstChunkMs` | 第一条跟踪的根 Agent 首个数据块耗时，单位为毫秒；不可用或根跨度不是 Agent 时为 `null`。 |
| `timeToFirstTokenMs` | 第一条跟踪的根 Agent 首个 token 耗时，单位为毫秒；`null` 的规则相同。仅在存储支持时提供。 |

较早开始的跟踪可能最后结束。此时它决定 `endedAt`，而状态及输出、错误预览仍取自开始时间最晚的跟踪。第一条跟踪缺失的值不会用后续跟踪的值填充。

### 线程排序和分页 {/* #thread-ordering-and-pagination */}

排序字段只能选择 `startedAt` 或 `endedAt`，排序方向为 `asc` 或 `desc`。默认按 `endedAt` 降序排列。每页默认 25 行，最多 100 行。翻页时，将 `result.page.next` 作为 `page.after` 传入，并保持时间条件、筛选条件、作用域和排序方式不变。游标为 `null` 表示没有更多页面。分页基于实时数据，因此新增跟踪可能使线程移动到其他页面。

要加载线程中的跟踪，请使用 [`queryTraces()`](#querying-traces)，按 `threadId` 筛选，并指定覆盖该线程活动时间的范围。

### 线程查询支持 {/* #thread-query-support */}

使用此接口前，请检查 `getObservabilityCapabilities()` 返回的 `capabilities.threadQueryRows`。该值缺失或为 `false` 表示无法获取完整线程记录。旧版核心包或存储包对此类请求返回结构化的 `501` 响应。混用不同版本的包时，仍可使用旧版标识查询请求。

当授权范围内的历史记录超过 250,000 行已存储的跟踪根记录（包括重复副本）时，ClickHouse 会拒绝范围过广的线程查询。缩小时间范围、减少候选线程后，查询仍可能成功。被拒绝的查询返回 `503 TRACE_QUERY_RESOURCE_LIMIT`，不包含部分结果。

## 查询跟踪 {/* #querying-traces */}

`queryTraces()` 根据跟踪字段及关联跨度上的条件查找已完成的逻辑跟踪。每次查询都必须指定 ISO 时间戳范围。

```typescript
const result = await mastraClient.queryTraces({
  timeRange: {
    from: '2026-08-01T00:00:00.000Z',
    to: '2026-08-08T00:00:00.000Z',
  },
  where: {
    spans: {
      some: {
        op: 'and',
        args: [
          { op: 'eq', left: { path: 'spanType' }, right: { literal: 'tool_call' } },
          { op: 'exists', path: 'error' },
        ],
      },
    },
  },
})
```

有关请求字段、谓词、限制、响应格式和错误，请参阅[查询跟踪](/reference/observability/tracing/advanced-queries#query-traces)。

### 加载页面并轮询跟踪 {/* #load-a-page-and-poll-for-traces */}

`queryTraces()` 支持通过 `page` 进行键集遍历、通过 `pagination` 进行页码分页，以及通过 `mode: 'delta'` 进行增量轮询。每次请求只能使用一种模式。从 `listTracesLight()` 迁移时，应读取 `traces` 而非 `spans`，并保留页码分页结果中的 `deltaCursor`：

```typescript
const timeRange = {
  from: '2026-08-01T00:00:00.000Z',
  to: '2026-08-08T00:00:00.000Z',
}
const initial = await mastraClient.queryTraces({
  timeRange,
  pagination: { page: 0, perPage: 100 },
})
if (!initial.deltaCursor) throw new Error('Delta polling is unavailable')

const changes = await mastraClient.queryTraces({
  timeRange,
  mode: 'delta',
  after: initial.deltaCursor,
  limit: 100,
})
```

按 `traceId` 合并 `changes.traces`，保留 `changes.deltaCursor`，并在 `changes.delta.hasMore` 为 `true` 时继续轮询。每次轮询都应保持相同的时间范围和谓词。结果仅包含已完成的跟踪；轮询不保证对关联记录更新、删除或不再符合条件的跟踪发出通知。

有关初始加载行为、游标有效期、数据保留及完整轮询示例，请参阅[增量轮询](/reference/observability/tracing/advanced-queries#poll-after-loading-a-numbered-page)。

### 聚合跟踪 {/* #aggregate-traces */}

`aggregateTraces()` 根据时间范围及可选的 `where` 谓词，对选中的跟踪进行分组。它为每个分组返回一行；设置 `interval` 后，为每个分组的每个非空时间段返回一行。它接受与 `queryTraces()` 相同的谓词。

```typescript
const { capabilities } = await mastraClient.getObservabilityCapabilities()

if (capabilities.traceAggregate) {
  const { rows, truncated } = await mastraClient.aggregateTraces({
    timeRange: {
      from: '2026-08-01T00:00:00.000Z',
      to: '2026-08-08T00:00:00.000Z',
    },
    where: { op: 'eq', left: { path: 'environment' }, right: { literal: 'production' } },
    groupBy: ['entityName'],
    interval: '1d',
    measures: ['count', 'errorRate', 'duration.p95', 'cost.sum'],
    orderBy: { field: 'count', direction: 'desc' },
    limit: 10,
  })
}
```

每行包含按 `groupBy` 字段命名的 `dimensions`、按指标名称命名的 `measures`；设置 `interval` 时还包含 `bucket` 时间戳，请求费用指标时还包含 `cost` 覆盖情况。匹配的分组数量超过 `limit` 时，`truncated` 为 `true`。调用前请检查 `capabilities.traceAggregate`。客户端会应用其配置的重试策略，但不会重试 `4xx`、`501`，以及错误码为 `TRACE_QUERY_EXECUTION_TIMEOUT` 的 `504` 响应。普通网关 `504` 响应仍可重试。

有关维度、指标、token 和费用的计算规则、时间段、限制及错误，请参阅[聚合跟踪](/reference/observability/tracing/advanced-queries#aggregate-traces)。

### 发现跟踪查询字段和值 {/* #discover-trace-query-fields-and-values */}

`getTraceQueryFields()` 返回指定谓词作用域的标准查询字段，以及已观察到的顶层字符串元数据字段。响应包含每个字段的值类型、支持的运算符，以及是否提供值建议。

```typescript
const timeRange = {
  from: '2026-08-01T00:00:00.000Z',
  to: '2026-08-08T00:00:00.000Z',
}

const fields = await mastraClient.getTraceQueryFields({
  timeRange,
  predicateScope: 'spans',
  search: 'model',
  limit: 25,
})
```

对于支持聚合的服务器，`trace` 作用域的响应还包含 `aggregate`：其中列出了可传给 `groupBy` 的 `dimensions` 和可请求的 `measures`。请参阅[发现字段和值](/reference/observability/tracing/advanced-queries#discover-fields-and-values)。

请在相同作用域内使用响应返回的原样局部路径。例如，`model` 应放在 `spans.some` 或 `spans.none` 谓词中。字段选择器可以并行获取 `trace` 和 `spans` 两个作用域的字段。

仅在选中 `valueSuggestions: true` 的字段后调用 `getTraceQueryValues()`：

```typescript
const controller = new AbortController()

const values = await mastraClient.getTraceQueryValues(
  {
    timeRange,
    predicateScope: 'spans',
    path: 'model',
    search: 'claude',
    limit: 25,
  },
  { signal: controller.signal },
)

// Cancel this autocomplete request when the search text changes.
controller.abort()
```

两种方法都支持不区分大小写的字面子字符串搜索，也接受空搜索词。数量限制默认为 25，最大为 100。结果先按出现次数排序，再按路径或值进行确定性排序。`observedFieldsTruncated` 和 `valuesTruncated` 表示调用方应缩小 `search` 的匹配范围。发现接口不提供游标。

建议结果有数量限制，仅供参考。即使建议不可用、为空或被截断，手动输入的值仍然有效。发现接口不接受草稿查询谓词。客户端不会重试这两种请求；每次调用传入的 `AbortSignal` 优先于 `MastraClient` 上配置的信号。

发现请求超时会返回 `504 TRACE_QUERY_EXECUTION_TIMEOUT`；后端内存或其他资源耗尽会返回 `503 TRACE_QUERY_RESOURCE_LIMIT`。这两种错误都不包含部分建议结果；截断标志只出现在成功且已完成排序的响应中。

## 删除跟踪 {/* #deleting-traces */}

删除跟踪及其关联的跨度、指标、日志、评分和反馈：

```typescript
const result = await mastraClient.deleteTraces({
  traceIds: ['trace-1', 'trace-2'],
})

if ('accepted' in result) {
  console.log('Deletion requested')
} else {
  console.log(result.success)
}
```

每次请求最多接受 1,000 个跟踪 ID，且不提供租户作用域字段。未关联跟踪的信号会保留。实验创建的跟踪与其他跟踪一样会被删除。

客户端支持两种响应格式：OSS 在完成删除操作后返回 `{ success: true }`；支持队列批量删除的 Platform 后端在接受清理请求后返回 `202 { accepted: true }`。请求被接受不代表读取时已看不到这些记录，因此报告删除完成前应检查响应。要在 Platform 上使用这些客户端方法，部署版本必须支持批量删除端点。

## 对跟踪评分 {/* #scoring-traces */}

使用已注册的评分器对指定跟踪评分，以供评估：

```typescript
const result = await mastraClient.score({
  scorerName: 'answer-relevancy',
  targets: [
    { traceId: 'trace-1', spanId: 'span-1' }, // Score specific span
    { traceId: 'trace-2' }, // Score specific span which defaults to the parent span
  ],
})
```

## 按跨度获取评分 {/* #getting-scores-by-span */}

检索跟踪中指定跨度的评分：

```typescript
const scores = await mastraClient.listScoresBySpan({
  traceId: 'trace-123',
  spanId: 'span-456',
  page: 1,
  perPage: 20,
})
```

## 根据 ID 获取评分 {/* #get-a-score-by-id */}

使用 `getScore()` 获取一条可观测性评分记录：

```typescript
const { score } = await mastraClient.getScore('score-id-123')
```

响应格式为 `{ score: record | null }`。评分不存在时，接口返回 HTTP 200 和 `{ score: null }`。
返回类型为 `GetScoreResponse`，由 `@mastra/client-js` 导出。

## 创建评分 {/* #creating-scores */}

为跟踪创建评分，也可以指定其中的跨度：

```typescript
const response = await mastraClient.createScore({
  score: {
    traceId: 'trace-123',
    spanId: 'span-456',
    scorerId: 'accuracy',
    score: 0.95,
  },
})
```

`createScore()` 要求 `score.traceId` 非空且不能只有空白字符；`spanId` 可选。每次调用中，客户端会为缺失的 `scoreId` 和 ISO `timestamp` 各生成一次，并在重试时复用。若要复用已有标识，请自行提供这些字段。有关上下文解析和重试行为，请参阅[信号写入选项](#signal-write-options)。

## 反馈 {/* #feedback */}

反馈方法通过已配置的 API 服务器创建、列出和查询人工反馈信号，例如评分、点赞、评论和更正。创建方法同时支持 OSS 和 Platform。Platform 以及支持反馈替换的 OSS 服务器可完整替换反馈。示例请参阅[反馈指南](/docs/observability/feedback)，完整结构请参阅[反馈参考](/reference/observability/feedback)。

### 根据 ID 获取反馈 {/* #get-feedback-by-id */}

使用 `getFeedback()` 获取一条反馈记录：

```typescript
const { feedback } = await mastraClient.getFeedback('feedback-id-123')
```

响应格式为 `{ feedback: record | null }`。记录不存在时，接口返回 HTTP 200 和 `{ feedback: null }`。
返回类型为 `GetFeedbackResponse`，由 `@mastra/client-js` 导出。

这两个获取方法都接受未经编码的 ID，并将其编码为 URL 路径段。它们使用客户端配置的 API 前缀、凭据和请求头。JSON 响应中的记录时间戳为 ISO 字符串。

### 创建反馈 {/* #creating-feedback */}

为跟踪创建反馈记录，也可以指定其中的跨度：

```typescript
const response = await mastraClient.createFeedback({
  feedback: {
    traceId: 'trace-123',
    spanId: 'span-456',
    feedbackSource: 'user',
    feedbackType: 'rating',
    value: 1,
    comment: 'Helpful answer.',
  },
})
```

`createFeedback()` 要求 `feedback.traceId` 非空且不能只有空白字符；`spanId` 可选。每次调用中，客户端会为缺失的 `feedbackId` 和 ISO `timestamp` 各生成一次，并在重试时复用。使用 `feedbackUserId` 标识反馈提交者；`userId` 标识跨度所属的用户。在 OSS 中，已认证的用户身份优先于提交的反馈提交者身份。

### 信号写入选项 {/* #signal-write-options */}

两种创建方法都允许在 `feedback` 或 `score` 包装字段旁传入可选的顶层 `contextMode`：

* `"provided"` 使用记录中的扁平化上下文字段，不查询跨度。缺失的上下文字段不会自动补全。
* `"resolve"` 从已存储的根跨度和可选的目标跨度获取上下文。根跨度的标签会被继承。记录中的元数据会覆盖同名的已存储元数据键。根跨度不存在时返回 `TRACE_NOT_FOUND`；目标跨度不存在时返回 `SPAN_NOT_FOUND`。

省略 `contextMode` 时使用服务器默认值：OSS 为 `"provided"`，Platform 为 `"resolve"`。客户端会保留字段的省略状态。若要求两种服务器行为一致，请显式选择模式。在 OSS 中，每个已配置的可信作用域字段都会覆盖调用方提供的值。在 provided 模式下，其他上下文字段仍采用调用方提供的值。例如，可信组织 ID 会覆盖 `organizationId`；如果未配置可信资源作用域，则不会清除 `resourceId`。

```typescript
const result = await mastraClient.createFeedback({
  contextMode: 'resolve',
  feedback: {
    traceId: 'trace-123',
    feedbackUserId: 'reviewer-1',
    feedbackType: 'thumbs',
    value: 1,
  },
})
```

可在可选的第二个参数中使用 `retries` 和 `anchorRetryTimeoutMs` 控制重试。网络错误和服务器错误遵循客户端的传输重试设置。只有错误码为 `TRACE_NOT_FOUND` 或 `SPAN_NOT_FOUND` 的 404 响应会触发锚点重试，最长持续至首次收到此类响应后的 30 秒。将 `anchorRetryTimeoutMs` 设为更短的时长，或设为 `0` 以禁用锚点重试。其他 404 错误以及认证或校验错误不会重试。

创建响应包含 `success` 和可选的 `data`。`data` 包含生成或提供的 `feedbackId`/`scoreId`、`traceId`、可为 null 的 `spanId`，以及标准化的 UTC `timestamp`。客户端也接受仅包含成功状态的响应。Platform 返回成功表示记录已发布，但读取接口可能无法立即查到该记录。直接调用 OSS HTTP 接口时，可以省略 ID 和时间戳，由服务器生成。

显式指定模式需要服务器支持。旧版服务器可能忽略 `contextMode`。向 Platform 发送 `"provided"` 前，请先部署其对传入上下文的支持。

### 替换反馈 {/* #replacing-feedback */}

`replaceFeedback()` 向 `PUT /api/observability/feedback/:feedbackId` 发送完整替换内容。请提供原始 `feedbackId`、`traceId` 和标准化的 `timestamp`，以及需要保留的所有反馈字段。Platform 和支持反馈替换的 OSS 服务器接受此方法。如果 OSS 存储适配器不支持替换，接口会返回 `501`。在 OSS 中提供编辑功能前，请检查 `capabilities.feedbackReplacement`；该能力缺失表示不可用。

```typescript
await mastraClient.replaceFeedback({
  feedback: {
    feedbackId: 'feedback-1',
    traceId: 'trace-123',
    timestamp: '2026-01-01T00:00:00.123Z',
    feedbackType: 'thumbs',
    value: -1,
    feedbackUserId: 'reviewer-1',
  },
})
```

如果创建响应包含 `data`，请使用其中的标准化时间戳。OSS 会以 `409` 拒绝修改原始跟踪或时间戳。Platform 将时间戳用作记录标识的一部分，因此也必须保留。客户端在重试时保持替换请求体不变，但每次被接受的 PUT 重试都是一次新的替换，可能覆盖其他编辑。要禁用自动重试，请将 `{ retries: 0, anchorRetryTimeoutMs: 0 }` 作为第二个参数传入。

### 删除反馈和评分 {/* #deleting-feedback-and-scores */}

根据 ID 删除反馈或评分记录。删除操作具有幂等性，因此不存在的 ID 会被忽略。每次请求最多接受 1,000 个 `feedbackIds` 或 1,000 个 `scoreIds`。可选的 `organizationId` 和 `resourceId` 字段将删除范围限制为作用域字段匹配的记录：

```typescript
await mastraClient.deleteFeedback({
  feedbackIds: ['feedback-1', 'feedback-2'],
  organizationId: 'org-1',
  resourceId: 'resource-1',
})

await mastraClient.deleteScores({
  scoreIds: ['score-1', 'score-2'],
  organizationId: 'org-1',
  resourceId: 'resource-1',
})
```

两种方法在 OSS 中都返回 `{ success: boolean }`；支持队列批量删除的 Platform 后端则返回 `{ accepted: true }`。响应处理方式请参阅[删除跟踪](#deleting-traces)。清理任务运行前，已接受删除的记录仍可能被读取。Platform 使用已认证的组织和项目作用域，请求体中的作用域字段无法覆盖它们。

### 列出反馈 {/* #listing-feedback */}

使用可选筛选条件分页检索反馈记录：

```typescript
const feedback = await mastraClient.listFeedback({
  filters: {
    feedbackType: 'rating',
    feedbackSource: 'studio',
  },
  pagination: { page: 0, perPage: 20 },
  orderBy: { field: 'timestamp', direction: 'DESC' },
})
```

`filters` 接受 [`FeedbackFilter`](/reference/observability/feedback#feedbackfilter) 的所有字段。客户端将这些字段作为 `GET /api/observability/feedback` 的查询参数发送。请参阅[列表查询参数](/reference/observability/feedback#list-query-parameters)。

### 聚合反馈 {/* #aggregating-feedback */}

聚合数值型反馈，例如以 `1` 和 `-1` 表示的评分或点赞、点踩：

```typescript
const averageRating = await mastraClient.getFeedbackAggregate({
  feedbackType: 'rating',
  aggregation: 'avg',
  comparePeriod: 'previous_day',
})
```

### 分组反馈 {/* #grouping-feedback */}

按可观测性维度对数值型反馈进行分组：

```typescript
const ratingsByAgent = await mastraClient.getFeedbackBreakdown({
  feedbackType: 'rating',
  groupBy: ['entityName'],
  aggregation: 'avg',
})
```

### 按时间查询反馈 {/* #querying-feedback-over-time */}

按时间间隔将数值型反馈划分为多个时间段：

```typescript
const ratingsOverTime = await mastraClient.getFeedbackTimeSeries({
  feedbackType: 'rating',
  interval: '1h',
  aggregation: 'avg',
  groupBy: ['feedbackSource'],
})
```

### 查询反馈百分位数 {/* #querying-feedback-percentiles */}

返回数值型反馈的百分位数序列：

```typescript
const ratingPercentiles = await mastraClient.getFeedbackPercentiles({

  percentiles: [0.5, 0.95],
  interval: '1d',
})
```
