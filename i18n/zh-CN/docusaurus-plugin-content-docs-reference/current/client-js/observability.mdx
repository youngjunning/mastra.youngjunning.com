# ObservabilityAPI

Observability API 提供了检索跟踪、监控应用程序性能、对跟踪进行评分以进行评估以及记录与跟踪和跨度相关的反馈的方法。

## 获取特定轨迹 {/* #getting-a-specific-trace */}

通过 ID 检索特定跟踪，包括其所有范围和详细信息：

```typescript
const trace = await mastraClient.getTrace('trace-id-123')
```

## 通过过滤获取痕迹 {/* #getting-traces-with-filtering */}

使用可选过滤检索跟踪根跨度的分页列表：

```typescript
const traces = await mastraClient.getTraces({
  pagination: {
    page: 1,
    perPage: 20,
    dateRange: {
      start: new Date('2024-01-01'),
      end: new Date('2024-01-31'),
    },
  },
  filters: {
    name: 'weather-agent', // Filter by trace name
    spanType: 'agent', // Filter by span type
    entityId: 'weather-agent-id', // Filter by entity ID
    entityType: 'agent', // Filter by entity type
  },
})

console.log(`Found ${traces.spans.length} root spans`)
console.log(`Total pages: ${traces.pagination.totalPages}`)

// To get the complete trace with all spans, use getTrace
const completeTrace = await mastraClient.getTrace(traces.spans[0].traceId)
```

## 列出列表视图的跟踪 {/* #listing-traces-for-a-list-view */}

`listTracesLight()`返回与跟踪列表相同的行，但不带`input`, `output` and `attributes` payloads. Each row carries short `inputPreview`, `outputPreview`和`errorPreview`改为字符串（最多 100 个字符，以`…`剪切时），因此列表可以渲染预览列，而无需传输整个有效负载，加上`threadId`和`resourceId`对于内存上下文列。

当您一次渲染许多跟踪时更喜欢它，并且仅在打开行时获取完整记录：

```typescript
const list = await mastraClient.listTracesLight({
  pagination: { page: 0, perPage: 25 },
  filters: { entityType: 'agent' },
})

for (const span of list.spans) {
  console.log(span.name, span.inputPreview)
}

// Fetch the full payload only for the trace the user selects
const selected = await mastraClient.getTrace(list.spans[0].traceId)
```

它接受与以下相同的过滤、排序和增量轮询参数：`listTraces()`. Use `listTraces()` when you actually need the full span payloads.

## 查询跨度 {/* #querying-spans */}

`querySpans()`返回跨迹线的完整跨度摘要。它需要跨度开始时间的正 ISO 时间戳范围，并支持光标分页：

```typescript
const result = await mastraClient.querySpans({
  timeRange: {
    from: '2026-10-01T00:00:00.000Z',
    to: '2026-10-02T00:00:00.000Z',
  },
  where: {
    op: 'and',
    args: [
      { op: 'eq', left: { path: 'threadId' }, right: { literal: 'thread-123' } },
      { op: 'gte', left: { path: 'durationMs' }, right: { literal: 1000 } },
    ],
  },
  orderBy: [{ field: 'startedAt', direction: 'desc' }],
  page: { limit: 100 },
})

// Pass result.page.next as page.after to continue with the same filters and ordering.
console.log(result.spans)
```

响应是`{ spans, page: { next } }`. Check `capabilities.spanQuery` before calling, and the field-specific capabilities before using optional filters. See [Query spans](/reference/observability/tracing/advanced-queries#query-spans) for fields, operators, defaults, capabilities, response details, and cursor handling.

### 聚合跨度 {/* #aggregate-spans */}

`aggregateSpans()`对与直接跨度谓词匹配的已完成跨度进行分组。当每组或每组和非空时间段返回一行时`interval` is set. It counts spans at any depth, such as nested agent runs that trace aggregation misses:

```typescript
const { capabilities } = await mastraClient.getObservabilityCapabilities()

if (capabilities.spanAggregate) {
  const { rows, truncated } = await mastraClient.aggregateSpans({
    timeRange: {
      from: '2026-10-01T00:00:00.000Z',
      to: '2026-10-08T00:00:00.000Z',
    },
    where: { op: 'eq', left: { path: 'spanType' }, right: { literal: 'agent_run' } },
    groupBy: ['status'],
    interval: '1d',
    measures: ['count', 'errorRate'],
  })
}
```

请求和响应结构如下`aggregateTraces()`, with direct span predicates and span dimensions such as `spanType`, `name`, and `parentEntityName`. Token and cost measures belong to the span that recorded the usage and aren't added to parent spans. Check `capabilities.spanAggregate` before calling, and `capabilities.spanAggregateModelDimensions` before grouping or counting distinct values by `model` or `provider`. With an older adapter, those requests return `501`.

两个都`aggregateTraces()` and `aggregateSpans()` accept time to first token (TTFT) and time to first chunk (TTFC) measures, `timeToFirstToken.*` and `timeToFirstChunk.*`, when `capabilities.aggregateTimeToFirstMeasures` is `true`. Spans and traces without a recorded value are skipped, never counted as 0. See [Time to first chunk (TTFC)](/reference/observability/tracing/advanced-queries#time-to-first-chunk-ttfc) and [Time to first token (TTFT)](/reference/observability/tracing/advanced-queries#time-to-first-token-ttft).

看[Aggregate spans](/reference/observability/tracing/advanced-queries#aggregate-spans) for selection, dimensions, per-span usage, and how to list the spans behind a group.

## 查询线程 {/* #querying-threads */}

`queryTraceThreads()`从已完成的跟踪中返回线程摘要`POST /observability/threads/query`. Each row includes activity timestamps, trace counts, context and previews. Traces without a thread ID aren't included.

```typescript
const result = await mastraClient.queryTraceThreads({
  timeRange: {
    traces: {
      from: '2026-10-01T00:00:00.000Z',
      to: '2026-10-02T00:00:00.000Z',
    },
  },
  where: { op: 'eq', left: { path: 'status' }, right: { literal: 'error' } },
  orderBy: [{ field: 'endedAt', direction: 'desc' }],
  page: { limit: 100 },
})

for (const thread of result.threads) {
  console.log(thread.firstTraceId, thread.lastTraceId, thread.traceCount, thread.outputPreview)
}
```

### 线程时间范围 {/* #thread-time-ranges */}

精确选择一个时间选择器。每个范围都需要 ISO 时间戳`from` earlier than `to`. The range includes `from` and excludes `to`.

|选择器|与 | 匹配线程
| - | - |
|`timeRange.traces: { from, to }` | At least one trace that started in the window |
| `timeRange.threads: { field: 'startedAt', from, to }` | Their first activity in the window |
| `timeRange.threads: { field: 'endedAt', from, to }` | Their last activity in the window |

例如，查找最近活动发生在 10 月 1 日的线程：

```typescript
const result = await mastraClient.queryTraceThreads({
  timeRange: {
    threads: {
      field: 'endedAt',
      from: '2026-10-01T00:00:00.000Z',
      to: '2026-10-02T00:00:00.000Z',
    },
  },
})
```

行包括授权范围内完整保留的历史记录，包括窗口之前和之后的痕迹。过滤器适用于这些完整的行。一个`environment` filter checks the first trace's environment.

### 螺纹过滤器 {/* #thread-filters */}

使用`where` to filter thread rows. Combine predicates with `and`, `or` and `not`.

|领域 |运营商|
| - | - |
|`threadId`, `organizationId`, `firstTraceId`, `lastTraceId` | `eq`, `ne`, `in`, `notIn`, `exists`, `notExists` |
| `resourceId`, `userId`, `runId`, `sessionId`, `requestId`, `serviceName`, `experimentId`, `environment`, `executionSource` | Same string operators |
| `entityType`, `entityId`, `entityName`, `entityVersionId`|相同的字符串运算符 |
|`status` | `eq`, `ne`, `in`, `notIn`，有值`success`或者`error` |
| `startedAt`, `endedAt`, `timeToFirstChunkMs`, `timeToFirstTokenMs` | `eq`, `ne`, `lt`, `lte`, `gt`, `gte`, `in`, `notIn`, `exists`, `notExists` |
| `traceCount` | `eq`, `ne`, `lt`, `lte`, `gt`, `gte` |

例如，过滤来自选定Agent且至少具有三个跟踪的线程：

```typescript
const result = await mastraClient.queryTraceThreads({
  timeRange: {
    traces: {
      from: '2026-10-01T00:00:00.000Z',
      to: '2026-10-02T00:00:00.000Z',
    },
  },
  where: {
    op: 'and',
    args: [
      { op: 'in', value: { path: 'entityId' }, set: ['support-agent', 'sales-agent'] },
      { op: 'gte', left: { path: 'traceCount' }, right: { literal: 3 } },
    ],
  },
})
```

存在过滤器的使用`{ op: 'exists', path: 'userId' }` to check for a non-null value. Model/provider and previews are available in returned rows but aren't filterable.

### 话题回复 {/* #thread-response */}

响应是`{ threads, page: { next } }`, without a total count. Each entry in `threads` contains these fields:

|返回字段 |意义|
| - | - |
|`threadId`, `organizationId` | Thread identity. Equal thread IDs in different organizations remain separate. |
| `firstTraceId`, `lastTraceId` | Earliest and latest trace by start time. Equal start times use trace ID as a deterministic tie-breaker. |
| `resourceId`, `userId`, `runId`, `sessionId`, `requestId`, `serviceName`, `experimentId`, `environment`, `executionSource` | First-trace context, or `null` when missing. |
| `entityType`, `entityId`, `entityName`, `entityVersionId` | First-trace entity. |
| `startedAt`, `endedAt` | Earliest start and maximum end time across the thread. |
| `status` | `error` when the last-started trace's root span has an error, otherwise `success`. |
| `traceCount` | Number of logical traces in the thread. |
| `inputPreview` | First trace's input preview. |
| `outputPreview`, `errorPreview` | Last-started trace's previews. |
| `timeToFirstChunkMs` | First trace's root agent time to first chunk, in milliseconds. `null` when unavailable or the root isn't an agent. |
| `timeToFirstTokenMs` | First trace's root agent time to first token, in milliseconds, with the same `null` rules. Present only when the store supports it. |

较早开始的跟踪可以最后完成。在这种情况下，它提供`endedAt`, while the last-started trace still supplies status and output/error previews. Missing first-trace values aren't replaced with values from a later trace.

### 线程排序和分页 {/* #thread-ordering-and-pagination */}

订购仅接受其中之一`startedAt` or `endedAt`, with direction `asc` or `desc`. The default is `endedAt` descending. Pages default to 25 rows and allow at most 100. Pass `result.page.next` as `page.after` with the same time selector, filters, scope and ordering. A `null` cursor means no more pages are available. Pagination reflects live data, so new traces can move a thread between pages.

要在线程中加载跟踪，请使用[`queryTraces()`](#querying-traces) with a `threadId` filter and a time range covering the thread's activity.

### 线程查询支持 {/* #thread-query-support */}

查看`capabilities.threadQueryRows` from `getObservabilityCapabilities()` before using this contract. A missing or false value means full thread rows aren't available. Older core or storage packages return a structured `501` for these requests. Legacy identity requests remain supported for mixed package versions.

当授权历史记录超过 250,000 条存储的跟踪根行（包括重复副本）时，ClickHouse 会拒绝宽线程查询。通过选择较少的候选线程，较窄的时间范围仍然可以成功。拒绝查询返回`503 TRACE_QUERY_RESOURCE_LIMIT` without partial results.

## 查询痕迹 {/* #querying-traces */}

`queryTraces()`使用相关跨度上的跟踪字段和条件查找完整的逻辑跟踪。每个查询都需要 ISO 时间戳范围。

```typescript
const result = await mastraClient.queryTraces({
  timeRange: {
    from: '2026-08-01T00:00:00.000Z',
    to: '2026-08-08T00:00:00.000Z',
  },
  where: {
    spans: {
      some: {
        op: 'and',
        args: [
          { op: 'eq', left: { path: 'spanType' }, right: { literal: 'tool_call' } },
          { op: 'exists', path: 'error' },
        ],
      },
    },
  },
})
```

看[Query traces](/reference/observability/tracing/advanced-queries#query-traces) for request fields, predicates, limits, response shapes, and errors.

### 加载页面并轮询痕迹 {/* #load-a-page-and-poll-for-traces */}

`queryTraces()`支持键集遍历`page`, numbered pages with `pagination`, and delta polling with `mode: 'delta'`. Use one mode per request. To migrate from `listTracesLight()`, read `traces` instead of `spans` and retain the numbered page's `deltaCursor`:

```typescript
const timeRange = {
  from: '2026-08-01T00:00:00.000Z',
  to: '2026-08-08T00:00:00.000Z',
}
const initial = await mastraClient.queryTraces({
  timeRange,
  pagination: { page: 0, perPage: 100 },
})
if (!initial.deltaCursor) throw new Error('Delta polling is unavailable')

const changes = await mastraClient.queryTraces({
  timeRange,
  mode: 'delta',
  after: initial.deltaCursor,
  limit: 100,
})
```

合并`changes.traces` by `traceId`, retain `changes.deltaCursor`, and continue while `changes.delta.hasMore` is `true`. Keep the same time range and predicate across polls. Only completed traces are returned; polling doesn't guarantee notifications for related-record updates, deletions, or traces that stop matching.

看[Delta polling](/reference/observability/tracing/advanced-queries#poll-after-loading-a-numbered-page) for bootstrap behavior, cursor lifetime, retention, and a complete polling loop.

### 聚合痕迹 {/* #aggregate-traces */}

`aggregateTraces()`按时间范围和可选的方式对选定的轨迹进行分组`where` predicate, and returns one row per group, or per group and non-empty time bucket when `interval` is set. It accepts the same predicates as `queryTraces()`.

```typescript
const { capabilities } = await mastraClient.getObservabilityCapabilities()

if (capabilities.traceAggregate) {
  const { rows, truncated } = await mastraClient.aggregateTraces({
    timeRange: {
      from: '2026-08-01T00:00:00.000Z',
      to: '2026-08-08T00:00:00.000Z',
    },
    where: { op: 'eq', left: { path: 'environment' }, right: { literal: 'production' } },
    groupBy: ['entityName'],
    interval: '1d',
    measures: ['count', 'errorRate', 'duration.p95', 'cost.sum'],
    orderBy: { field: 'count', direction: 'desc' },
    limit: 10,
  })
}
```

每行有`dimensions` keyed by `groupBy` field, `measures` keyed by measure name, a `bucket` timestamp when `interval` is set, and `cost` coverage when a cost measure is requested. `truncated` is `true` when more groups matched than `limit`. Check `capabilities.traceAggregate` before calling. The client applies its configured retry policy, except for `4xx` responses, `501`, and `504` responses with code `TRACE_QUERY_EXECUTION_TIMEOUT`, which aren't retried. Ordinary gateway `504` responses remain retryable.

看[Aggregate traces](/reference/observability/tracing/advanced-queries#aggregate-traces) for dimensions, measures, token and cost semantics, time buckets, limits, and errors.

### 发现跟踪查询字段和值 {/* #discover-trace-query-fields-and-values */}

`getTraceQueryFields()`返回一个谓词范围的规范查询字段和观察到的顶级字符串元数据字段。响应包括每个字段的值类型、支持的运算符以及值建议是否可用。

```typescript
const timeRange = {
  from: '2026-08-01T00:00:00.000Z',
  to: '2026-08-08T00:00:00.000Z',
}

const fields = await mastraClient.getTraceQueryFields({
  timeRange,
  predicateScope: 'spans',
  search: 'model',
  limit: 25,
})
```

对于`trace` scope on a server that supports aggregation, the response also includes `aggregate`: the `dimensions` you can pass to `groupBy` and the `measures` you can request. See [Discover fields and values](/reference/observability/tracing/advanced-queries#discover-fields-and-values).

使用具有相同范围的响应中的确切本地路径。例如，`model` belongs inside a `spans.some` or `spans.none` predicate. A field picker can fetch the `trace` and `spans` scopes in parallel.

称呼`getTraceQueryValues()` only after selecting a field with `valueSuggestions: true`:

```typescript
const controller = new AbortController()

const values = await mastraClient.getTraceQueryValues(
  {
    timeRange,
    predicateScope: 'spans',
    path: 'model',
    search: 'claude',
    limit: 25,
  },
  { signal: controller.signal },
)

// Cancel this autocomplete request when the search text changes.
controller.abort()
```

两种方法都使用不区分大小写的文字子字符串搜索并接受空搜索。限制默认为 25，不能超过 100。结果按出现次数排序，然后按路径或值确定。`observedFieldsTruncated` and `valuesTruncated` indicate that the caller should refine `search`. Discovery has no cursor.

建议是有限的和咨询性的。当建议不可用、为空或被截断时，手动值仍然有效。 Discovery 不接受草稿查询谓词。客户端不会重试任何一个请求，并且每次调用`AbortSignal` takes precedence over the signal configured on `MastraClient`.

发现超时拒绝`504 TRACE_QUERY_EXECUTION_TIMEOUT`. Backend memory or resource exhaustion rejects with `503 TRACE_QUERY_RESOURCE_LIMIT`. Neither error contains partial suggestions; truncation flags are only present on successful, completely ranked responses.

## 删除痕迹 {/* #deleting-traces */}

删除跟踪及其关联的跨度、指标、日志、分数和反馈：

```typescript
const result = await mastraClient.deleteTraces({
  traceIds: ['trace-1', 'trace-2'],
})

if ('accepted' in result) {
  console.log('Deletion requested')
} else {
  console.log(result.success)
}
```

每个请求最多接受 1,000 个跟踪 ID，并且没有租户范围字段。未链接到迹线的信号将被保留。实验创建的痕迹会像任何其他痕迹一样被删除。

客户端支持两种响应形态： OSS返回`{ success: true }` after its delete operation, while a Platform backend that supports queued batch deletion returns `202 { accepted: true }` after accepting cleanup. Acceptance doesn't mean records have disappeared from reads, so check the response before reporting deletion as complete. Using these client methods with Platform requires a deployment that supports the batch deletion endpoints.

## 通过ID获取分数 {/* #get-a-score-by-id */}

使用`getScore()` to retrieve one observability score:

```typescript
const { score } = await mastraClient.getScore('score-id-123')
```

响应是`{ score: record | null }`. A missing score returns HTTP 200 with `{ score: null }`.
The return type is `GetScoreResponse`, exported from `@mastra/client-js`.

## 创建分数 {/* #creating-scores */}

为跟踪创建一个分数，可以选择标识其中的跨度：

```typescript
const response = await mastraClient.createScore({
  score: {
    traceId: 'trace-123',
    spanId: 'span-456',
    scorerId: 'accuracy',
    score: 0.95,
  },
})
```

`createScore()`需要一个非空白`score.traceId`, with an optional `spanId`. The client generates a missing `scoreId` and ISO `timestamp` once per call and preserves them across retries. Supply these fields to reuse an existing identity. See [signal write options](#signal-write-options) for context resolution and retry behavior.

## 反馈 {/* #feedback */}

反馈方法通过配置的 API 服务器创建、列出和查询人机交互信号，例如评级、点赞、评论和更正。创建方法支持OSS和Platform。平台和OSS服务器支持完全替换，并提供反馈替换支持。请参阅[feedback guide](/docs/observability/feedback) for examples and the [feedback reference](/reference/observability/feedback) for full schemas.

### 通过ID获取反馈 {/* #get-feedback-by-id */}

使用`getFeedback()` to retrieve one feedback record:

```typescript
const { feedback } = await mastraClient.getFeedback('feedback-id-123')
```

响应是`{ feedback: record | null }`. A missing record returns HTTP 200 with `{ feedback: null }`.
The return type is `GetFeedbackResponse`, exported from `@mastra/client-js`.

两个 getter 都接受未编码的 ID 并将其编码为 URL 路径段。它们使用客户端配置的 API 前缀、凭据和标头。记录时间戳是 JSON 响应中的 ISO 字符串。

### 创建反馈 {/* #creating-feedback */}

为跟踪创建反馈记录，可以选择标识其中的跨度：

```typescript
const response = await mastraClient.createFeedback({
  feedback: {
    traceId: 'trace-123',
    spanId: 'span-456',
    feedbackSource: 'user',
    feedbackType: 'rating',
    value: 1,
    comment: 'Helpful answer.',
  },
})
```

`createFeedback()`需要一个非空白`feedback.traceId`, with an optional `spanId`. The client generates a missing `feedbackId` and ISO `timestamp` once per call and preserves them across retries. Set `feedbackUserId` to identify the feedback author. `userId` identifies the span's user. An authenticated OSS user takes precedence over a submitted feedback author.

### 信号写入选项 {/* #signal-write-options */}

两种创建方法都接受可选的顶级`contextMode` alongside the `feedback` or `score` wrapper:

* `"provided"`使用记录的扁平化上下文字段而不查找跨度。缺少的上下文字段不会得到丰富。
* `"resolve"`从存储的根和可选的目标跨度中获取上下文。根标签是继承的。记录元数据会覆盖匹配的存储元数据键。丢失的根返回`TRACE_NOT_FOUND`. A missing target returns `SPAN_NOT_FOUND`.

省略`contextMode` uses the server's default: `"provided"` on OSS and `"resolve"` on Platform. The client preserves omission. Select a mode explicitly when the same behavior is required on both servers. On OSS, each configured trusted scope field overrides caller input. In provided mode, other context fields remain caller-supplied. For example, a trusted organization ID overrides `organizationId` but doesn't clear `resourceId` when no trusted resource scope is configured.

```typescript
const result = await mastraClient.createFeedback({
  contextMode: 'resolve',
  feedback: {
    traceId: 'trace-123',
    feedbackUserId: 'reviewer-1',
    feedbackType: 'thumbs',
    value: 1,
  },
})
```

使用`retries` and `anchorRetryTimeoutMs` in the optional second argument to control retries. Network and server errors use the client's transport retry settings. Only 404s with `TRACE_NOT_FOUND` or `SPAN_NOT_FOUND` receive anchor retries, for at most 30 seconds after the first such response. Set `anchorRetryTimeoutMs` to a shorter window or `0` to disable them. Other 404s and authentication or validation errors are terminal.

创建响应包含`success` and optional `data` with the generated or supplied `feedbackId`/`scoreId`, `traceId`, nullable `spanId`, and normalized UTC `timestamp`. The client also accepts success-only responses. Platform success confirms publication. The record may not be immediately visible to reads. Direct OSS HTTP callers can omit the ID and timestamp to have the server generate them.

显式模式需要服务器支持。较旧的服务器可能会忽略`contextMode`. Deploy Platform's supplied-context support before sending `"provided"` there.

### 更换反馈 {/* #replacing-feedback */}

`replaceFeedback()`将完整替换发送至`PUT /api/observability/feedback/:feedbackId`. Include the original `feedbackId`, `traceId`, and normalized `timestamp`, along with all feedback fields to retain. Platform and OSS servers with feedback replacement support accept this method. OSS returns `501` when its storage adapter doesn't support replacement. For OSS, check `capabilities.feedbackReplacement` before offering edits. A missing capability means unavailable.

```typescript
await mastraClient.replaceFeedback({
  feedback: {
    feedbackId: 'feedback-1',
    traceId: 'trace-123',
    timestamp: '2026-01-01T00:00:00.123Z',
    feedbackType: 'thumbs',
    value: -1,
    feedbackUserId: 'reviewer-1',
  },
})
```

使用创建响应的标准化时间戳`data` when available. OSS rejects changes to the original trace or timestamp with `409`. Platform uses the timestamp as part of record identity, so preserve it there too. The client preserves the replacement body across retries, but each accepted PUT retry is a new replacement and can supersede another edit. Pass `{ retries: 0, anchorRetryTimeoutMs: 0 }` as the second argument to disable automatic retries.

### 删除反馈和分数 {/* #deleting-feedback-and-scores */}

按id删除反馈或评分记录。删除是幂等的，因此丢失的 id 会被忽略。每个请求最多接受 1,000 个`feedbackIds` or 1,000 `scoreIds`. Optional `organizationId` and `resourceId` fields restrict each deletion to records with matching scope fields:

```typescript
await mastraClient.deleteFeedback({
  feedbackIds: ['feedback-1', 'feedback-2'],
  organizationId: 'org-1',
  resourceId: 'resource-1',
})

await mastraClient.deleteScores({
  scoreIds: ['score-1', 'score-2'],
  organizationId: 'org-1',
  resourceId: 'resource-1',
})
```

两种方法都返回`{ success: boolean }` from OSS or `{ accepted: true }` from a Platform backend that supports queued batch deletion. See [Deleting traces](#deleting-traces) for response handling. Accepted records can remain readable until cleanup runs. Platform uses authenticated organization/project scope, which request-body scope fields can't override.

### 列表反馈 {/* #listing-feedback */}

使用可选过滤器检索分页反馈记录：

```typescript
const feedback = await mastraClient.listFeedback({
  filters: {
    feedbackType: 'rating',
    feedbackSource: 'studio',
  },
  pagination: { page: 0, perPage: 20 },
  orderBy: { field: 'timestamp', direction: 'DESC' },
})
```

`filters`接受每一个[`FeedbackFilter`](/reference/observability/feedback#feedbackfilter) field. The client sends them as query parameters on `GET /api/observability/feedback`. See [list query parameters](/reference/observability/feedback#list-query-parameters).

### 汇总反馈 {/* #aggregating-feedback */}

聚合数字反馈值，例如编码为的评级或拇指`1` and `-1`:

```typescript
const averageRating = await mastraClient.getFeedbackAggregate({
  feedbackType: 'rating',
  aggregation: 'avg',
  comparePeriod: 'previous_day',
})
```

### 分组反馈 {/* #grouping-feedback */}

按可观察性维度对数字反馈进行分组：

```typescript
const ratingsByAgent = await mastraClient.getFeedbackBreakdown({
  feedbackType: 'rating',
  groupBy: ['entityName'],
  aggregation: 'avg',
})
```

### 随着时间的推移查询反馈 {/* #querying-feedback-over-time */}

按间隔存储数字反馈：

```typescript
const ratingsOverTime = await mastraClient.getFeedbackTimeSeries({
  feedbackType: 'rating',
  interval: '1h',
  aggregation: 'avg',
  groupBy: ['feedbackSource'],
})
```

### 查询反馈百分位数 {/* #querying-feedback-percentiles */}

返回数字反馈值的百分位数系列：

```typescript
const ratingPercentiles = await mastraClient.getFeedbackPercentiles({
  feedbackType: 'rating',
  percentiles: [0.5, 0.95],
  interval: '1d',
})
```
