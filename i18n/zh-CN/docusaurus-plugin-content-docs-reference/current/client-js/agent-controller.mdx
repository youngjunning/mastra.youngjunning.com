# Agent Controller API

Agent Controller API 通过 HTTP 路由访问注册在 Mastra 实例上的 [`AgentController`](/reference/agent-controller/agent-controller-class)。浏览器或其他不持有控制器的进程可使用此 API；持有控制器的进程则使用进程内的 [`Session`](/reference/agent-controller/session)。

## 使用示例 {/* #usage-example */}

```typescript
import { MastraClient } from '@mastra/client-js'

const client = new MastraClient({ baseUrl: 'http://localhost:4111' })
const session = client.getAgentController('coding-controller').session('user-123')

await session.create()

const subscription = await session.subscribe({
  onEvent: event => handleEvent(event),
  onError: error => showDisconnected(error),
  onReconnect: () => {
    void session.state().then(resync).catch(showDisconnected)
  },
  reconnect: true,
})

await session.sendMessage('Summarize the open pull requests')

// Call when the UI disconnects.
subscription.unsubscribe()
```

## 列出 Agent Controller {/* #listing-agent-controllers */}

获取所连接的 Mastra 实例托管的 Agent Controller：

```typescript
const controllers = await client.listAgentControllers()
```

每个条目的 `id` 是控制器在 `new Mastra({ agentControllers })` 中注册时使用的键，而非控制器自身的 `id`。

## 使用指定的 Agent Controller {/* #working-with-a-specific-agent-controller */}

通过控制器在 `new Mastra({ agentControllers })` 中的注册键获取其实例。该键可能与控制器的 `id` 不同。本例应传入 `'coding'`，而非 `'coding-controller'`：

```typescript title="src/mastra/index.ts"
import { Mastra } from '@mastra/core'
import { AgentController } from '@mastra/core/agent-controller'

const codingController = new AgentController({ id: 'coding-controller', agent, modes })

export const mastra = new Mastra({
  agentControllers: { coding: codingController },
})
```

```typescript
const controller = client.getAgentController('coding')
```

### `listModes()` {/* #listmodes */}

列出控制器配置的模式，例如 `build` 和 `plan`。

返回：`Promise<AgentControllerModeInfo[]>`

### `listModels()` {/* #listmodels */}

列出控制器可用的模型及其认证状态和使用次数。

返回：`Promise<AgentControllerAvailableModel[]>`

### `listActiveRuns()` {/* #listactiveruns */}

列出控制器中所有资源正在执行的运行。

返回：`Promise<AgentControllerActiveRun[]>`

### `workspaceStatus()` {/* #workspacestatus */}

返回控制器的 Workspace 状态。

返回：`Promise<AgentControllerWorkspaceStatus>`

### `session(sessionId)` {/* #sessionsessionid */}

返回由会话 ID 定位的 `AgentControllerSession`。每个请求都发送到 `/agent-controller/:controllerId/sessions/:sessionId/...`。服务端会获取或创建会话，因此使用相同的 `sessionId` 调用 `create()` 会继续现有对话，不会创建分支。

共享同一资源、但使用不同会话 ID 的会话，各自拥有独立的运行循环、线程绑定、模式、模型及状态。其存储的线程和资源级记忆归共享资源所有。调用 `create()` 时传入资源：

```typescript
const runA = client.getAgentController('code').session('run-a')
await runA.create({ resourceId: 'factory-1' })

const runB = client.getAgentController('code').session('run-b')
await runB.create({ resourceId: 'factory-1' })
```

### `sendMessage(message, options?)` {/* #sendmessagemessage-options */}

向会话发送用户消息。可以传入字符串，或传入 `{ content, files }` 附加 Base64 编码的文件；每个文件的格式为 `{ data, mediaType, filename? }`。回复会通过订阅中的 `message_*` 事件送达，而不是作为调用的返回值。

通过 `options.requestContext` 将自定义上下文合并到本次运行的请求上下文中；服务端控制的键优先。

### `steer(message, options?)` {/* #steermessage-options */}

中止正在进行的运行，再将消息作为新一轮对话发送。可传入字符串，也可按 `sendMessage()` 的格式传入 `{ content, files }` 附加文件。

### `followUp(message, options?)` {/* #followupmessage-options */}

将后续消息加入队列。会话空闲时立即发送；有运行正在执行时，待其完成后发送。可传入字符串，也可按 `sendMessage()` 的格式传入 `{ content, files }` 附加文件。

### `abort()` {/* #abort */}

中止正在执行的运行。

### `approveTool(toolCallId, approved, options?)` {/* #approvetooltoolcallid-approved-options */}

批准或拒绝由 `tool_approval_required` 事件提出的待审批 Tool 调用。

### `respondToToolSuspension(toolCallId, resumeData, options?)` {/* #respondtotoolsuspensiontoolcallid-resumedata-options */}

恢复由 `tool_suspended` 事件报告的已暂停交互式 Tool。`resumeData` 的格式取决于 Tool：`ask_user` 使用 `string` 或 `string[]`，`request_access` 使用 `"Yes"` 或 `"No"`，`submit_plan` 使用 `PlanResume`。

```typescript
interface PlanResume {
  action: 'approved' | 'rejected'
  feedback?: string
  path?: string
  title?: string
  plan?: string
}
```

### `state(options?)` {/* #stateoptions */}

返回会话当前的模式、模型和线程，供 UI 初次加载及重连后重新同步使用。传入 `{ threadId }` 可读取指定线程的状态。

返回：`Promise<AgentControllerSessionState>`

### `setState(updates)` {/* #setstateupdates */}

将键值对合并到会话状态；未包含在请求数据中的现有键会保留。

### `switchMode(modeId)` {/* #switchmodemodeid */}

切换活动模式。

### `switchModel(modelId, options?)` {/* #switchmodelmodelid-options */}

切换会话使用的模型，并将其保存为当前线程的模型；模式切换不会影响此设置。第二个参数可传入 `{ thinkingLevel }`，以同时应用并保存思考级别。

```typescript
await session.switchModel('__GATEWAY_ANTHROPIC_MODEL_SONNET__', {
  thinkingLevel: 'high',
})
```

### `listThreads(options?)` {/* #listthreadsoptions */}

列出会话的线程，按时间从新到旧排序。传入 `{ limit }` 可限制数量，传入 `{ tags }` 可筛选匹配所有标签的线程。直接传入数字等同于 `{ limit }`。

返回：`Promise<AgentControllerThreadInfo[]>`

### `switchThread(threadId)` {/* #switchthreadthreadid */}

将会话切换到现有线程并重新绑定流和状态。

### `createThread(title?)` {/* #createthreadtitle */}

创建一个新线程并将会话绑定到它。

返回：`Promise<CreateAgentControllerThreadResponse>`

### `cloneThread(options?)` {/* #clonethreadoptions */}

克隆线程及其消息，然后将会话绑定到新线程。接受 `{ sourceThreadId?, title? }`。

返回：`Promise<CreateAgentControllerThreadResponse>`

### `renameThread(threadId, title)` {/* #renamethreadthreadid-title */}

重命名线程。

### `deleteThread(threadId)` {/* #deletethreadthreadid */}

删除一个线程。如果它是活动线程，则会话解除绑定。

### `listMessages(threadId, limit?)` {/* #listmessagesthreadid-limit */}

列出线程中的消息，并将 `createdAt` 转换为 `Date`。

返回：`Promise<MastraDBMessage[]>`

### `getGoal()`, `setGoal(objective, options?)`, `updateGoal(options)`, `clearGoal()` {/* #getgoal-setgoalobjective-options-updategoaloptions-cleargoal */}

读取、设置、更新和清除会话线程的目标。`setGoal` 接受 `{ judgeModelId?, maxRuns? }`；`updateGoal` 还接受 `status: 'active' | 'paused' | 'done'`。Agent 的循环内评估器会在每轮结束后评估进度，并通过 `goal_evaluation` 事件报告。

### `getPermissions()`, `setPermissionForCategory(category, policy)`, `setPermissionForTool(toolName, policy)` {/* #getpermissions-setpermissionforcategorycategory-policy-setpermissionfortooltoolname-policy */}

读取并设置各类别及各 Tool 的审批策略。

### `getResourceIds()`, `setResourceId(newResourceId)` {/* #getresourceids-setresourceidnewresourceid */}

读取会话的已知资源 ID 并更改会话的资源标识。

### `getOMRecord()` {/* #getomrecord */}

返回会话线程的观察内存记录。

### `sendNotification(input)` {/* #sendnotificationinput */}

向会话发送通知信号。Agent 的投递策略决定通知是立即唤醒空闲线程，还是暂存并在稍后汇总。

返回：`Promise<SendNotificationResult>`

## 事件 {/* #events */}

`onEvent` 接收会话发出的所有事件；通过 `event.type` 区分事件类型：

| 分组 | 事件 |
| - | - |
| 运行 | `agent_start`, `agent_end`, `usage_update`, `goal_evaluation`, `follow_up_queued` |
| Messages | `message_start`, `message_update`, `message_end` |
| Tools | `tool_input_start`, `tool_input_delta`, `tool_input_end`, `tool_start`, `tool_update`, `tool_end`, `shell_output`, `command_exit`, `tool_approval_required`, `tool_suspended`, `tool_suspension_cancelled`, `task_updated` |
| Session | `state_changed`, `display_state_changed`, `mode_changed`, `model_changed`, `thread_changed`, `thread_created`, `thread_deleted`, `thread_title_updated` |
| Subagents | `subagent_start`, `subagent_text_delta`, `subagent_tool_start`, `subagent_tool_end`, `subagent_end`, `subagent_model_changed`|
| 记忆 | `om_observation_start`, `om_observation_end`, `om_observation_failed`, `om_reflection_start`, `om_reflection_end`, `om_reflection_failed`, `om_buffering_start`, `om_buffering_end`, `om_buffering_failed`, `om_model_changed`, `om_activation`, `om_status`, `om_thread_title_updated`|
| Workspace | `workspace_ready`, `workspace_error`, `workspace_status_changed`|
| 诊断 | `info`, `error` |

通知以消息携带的 Agent 信号形式投递，而非 `notification` 或 `notification_summary` 类型的控制器事件。

消息的生命周期包含三种事件：

* `message_start` 携带初始的 `MastraDBMessage`，其中 `createdAt` 已转换为 `Date`。
* `message_update` 携带消息 `id`，以及精简的文本、推理内容或消息部分更新。
* `message_end` 携带已完成消息的 `id`。

`thread_created` 还携带线程数据，其中的时间戳已转换为 `Date`。

控制器可能发出 SDK 尚未定义类型的事件。`AgentControllerEvent` 是 `KnownAgentControllerEvent` 与 `OtherAgentControllerEvent` 的联合类型。由于 `OtherAgentControllerEvent.type` 是 `string`，将 `event.type` 与字符串字面量比较并不能收窄联合类型。先用 `isKnownAgentControllerEvent(event)` 收窄类型，再按 ID 重建消息：

```typescript
import {
  isKnownAgentControllerEvent,
  type AgentControllerEvent,
  type KnownAgentControllerEvent,
  type MastraDBMessage,
} from '@mastra/client-js'

type MessageUpdate = Extract<KnownAgentControllerEvent, { type: 'message_update' }>['event']

const activeMessages = new Map<string, MastraDBMessage>()

function applyUpdate(message: MastraDBMessage, update: MessageUpdate): MastraDBMessage {
  const parts = [...message.content.parts]

  if (update.type === 'text-delta') {
    const index = parts.findLastIndex(part => part.type === 'text')
    const part = parts[index]

    if (part?.type === 'text') {
      parts[index] = { ...part, text: part.text + update.delta }
    } else {
      parts.push({ type: 'text', text: update.delta })
    }
  } else if (update.type === 'reasoning-delta') {
    const part = parts[update.index]
    const reasoning = part?.type === 'reasoning' ? part.reasoning + update.delta : update.delta
    parts[update.index] = {
      ...(part?.type === 'reasoning' ? part : { type: 'reasoning' as const }),
      reasoning,
      details: [{ type: 'text', text: reasoning }],
    }
  } else {
    parts[update.index] = update.part
  }

  return { ...message, content: { ...message.content, parts } }
}

function handleEvent(event: AgentControllerEvent) {
  if (!isKnownAgentControllerEvent(event)) return

  switch (event.type) {
    case 'message_start':
      activeMessages.set(event.message.id, structuredClone(event.message))
      break
    case 'message_update': {
      const message = activeMessages.get(event.id)
      if (!message) break

      const updated = applyUpdate(message, event.event)
      activeMessages.set(event.id, updated)
      render(updated)
      break
    }
    case 'message_end': {
      const message = activeMessages.get(event.id)
      if (!message) break

      renderComplete(message)
      activeMessages.delete(event.id)
      break
    }
    case 'tool_approval_required':
      showApproval(event.toolCallId)
      break
  }
}
```

使用 `agentControllerMessageText(message)` 从重建消息的嵌套内容部分提取纯文本。
