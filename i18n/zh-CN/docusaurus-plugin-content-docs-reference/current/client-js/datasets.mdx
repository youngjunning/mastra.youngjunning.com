# 数据集API

数据集 API 公开了 Mastra 的数据集和实验路线`MastraClient`。它包括调用者驱动的实验方法和实验删除方法。调用者驱动的方法让您拥有的编排器（例如临时Workflow程）驱动实验循环，而 Mastra 充当记录系统。创建实验，然后让 Mastra 在服务器端执行每个项目`runExperimentItem`或摄取您自己计算的结果`submitExperimentResult`，并在运行完成后调用 Finalize。

项目运行、结果提交和最终确定可以安全地重试。仅当请求包含调用者提供的内容时，才能安全地重试创建`id`; without one, each retry creates a new experiment.

* `createDatasetExperiment`在调用者提供的上是幂等的`id`
* `runExperimentItem`和`submitExperimentResult` upsert on `(experimentId, itemId, attempt)`
* `finalizeExperiment`如果实验已完成，则返回存储的记录

## 使用示例 {/* #usage-example */}

```typescript
import { MastraClient } from '@mastra/client-js'

const client = new MastraClient({
  baseUrl: 'http://localhost:4111',
})

// 1. Create the experiment. Pass your orchestrator's run ID so a
//    retried workflow converges on the same experiment.
const { experimentId, totalItems, datasetVersion } = await client.createDatasetExperiment({
  datasetId: 'clinical-triage-evals',
  id: 'temporal-wf-run-42',
  targetType: 'agent',
  targetId: 'triage-agent',
  scorerIds: ['clinical-judge'],
})

// 2. Run one item per activity. Mastra executes the agent, runs the
//    scorers, and upserts the result. Retried activities converge on
//    a single row per (experimentId, itemId, attempt).
const { result, scores } = await client.runExperimentItem({
  datasetId: 'clinical-triage-evals',
  experimentId,
  itemId: 'item-1',
})

// 3. Finalize. The server computes succeeded/failed/skipped counts
//    from the persisted rows.
const experiment = await client.finalizeExperiment({
  datasetId: 'clinical-triage-evals',
  experimentId,
})
```

对于纯粹摄取，创建实验时无需`targetType`/`targetId` and replace step 2 with `submitExperimentResult`.

## 完成实验（） {/* #finalizeexperiment */}

标记调用者驱动的实验已完成。服务器通过计算持久结果行中的每个项目计数来为调用者处理簿记：`succeededCount` (at least one attempt without an error), `failedCount` (every attempt errored), and `skippedCount` (never submitted). Idempotent: finalizing an already-completed experiment returns the stored record.

## 删除数据集实验() {/* #deletedatasetexperiment */}

通过其数据集删除实验。服务器删除实验的Observability跟踪，包括其跨度和跟踪链接信号，然后删除实验及其结果记录。不受支持的存储会留下痕迹，并且服务器会记录警告。如果由于任何其他原因删除痕迹失败，则承诺将被拒绝，并且 Mastra 会保留实验及其结果记录，尽管某些痕迹可能已被删除。

```typescript
await client.deleteDatasetExperiment('dataset-id', 'experiment-id', {
  organizationId: 'organization-id',
  projectId: 'project-id',
})
```

## 清除数据集项() {/* #purgedatasetitem */}

从现有数据集历史记录和链接的实验结果中擦除项目的内容，包括结果标签和注释，同时保留版本历史记录、实验计数器和审核状态。稍后提交的项目结果将与经过编辑的内容一起存储，并且稍后的数据集项目更新将被拒绝。

```typescript
await client.purgeDatasetItem('dataset-id', 'item-id', {
  organizationId: 'organization-id',
  projectId: 'project-id',
})
```

可选的第三个参数将清除范围限定为租户组织和项目。服务器返回`404` when the dataset doesn't belong to that scope or the item has no history in the dataset.

退货`Promise<{ success: boolean }>`. The operation is idempotent and can't be undone. Purge serializes or conflicts with concurrent dataset item writers without guaranteeing which operation completes first. If a mutating item update loses the race, storage re-reads the purge marker and rejects it with `DATASET_ITEM_PURGED`. Deletes remain idempotent, and any deletion tombstone created during the race stays redacted. MongoDB storage requires a replica set or sharded deployment with transaction support. See [`dataset.purgeItem()`](/reference/datasets/purgeItem) for the complete purge behavior.
