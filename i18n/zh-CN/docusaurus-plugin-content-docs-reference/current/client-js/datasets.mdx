# 数据集 API

数据集 API 通过 `MastraClient` 提供 Mastra 的数据集和实验路由，包括由调用方驱动实验及删除实验的方法。调用方可以使用自己的编排器（例如 Temporal Workflow）控制实验循环，由 Mastra 保存权威记录。创建实验后，可以通过 `runExperimentItem` 让 Mastra 在服务端执行每个数据项，或通过 `submitExperimentResult` 提交自行计算的结果。运行结束时，再调用最终确认方法。

执行数据项、提交结果和最终确认均可安全重试。只有在请求中提供调用方指定的 `id` 时，创建实验才可安全重试；否则每次重试都会创建新实验。

* 提供调用方指定的 `id` 时，`createDatasetExperiment` 具有幂等性
* `runExperimentItem` 和 `submitExperimentResult` 根据 `(experimentId, itemId, attempt)` 更新或插入结果
* 如果实验已完成，`finalizeExperiment` 返回已保存的记录

## 使用示例 {/* #usage-example */}

```typescript
import { MastraClient } from '@mastra/client-js'

const client = new MastraClient({
  baseUrl: 'http://localhost:4111',
})

// 1. Create the experiment. Pass your orchestrator's run ID so a
//    retried workflow converges on the same experiment.
const { experimentId, totalItems, datasetVersion } = await client.createDatasetExperiment({
  datasetId: 'clinical-triage-evals',
  id: 'temporal-wf-run-42',
  targetType: 'agent',
  targetId: 'triage-agent',
  scorerIds: ['clinical-judge'],
})

// 2. Run one item per activity. Mastra executes the agent, runs the
//    scorers, and upserts the result. Retried activities converge on
//    a single row per (experimentId, itemId, attempt).
const { result, scores } = await client.runExperimentItem({
  datasetId: 'clinical-triage-evals',
  experimentId,
  itemId: 'item-1',
})

// 3. Finalize. The server computes succeeded/failed/skipped counts
//    from the persisted rows.
const experiment = await client.finalizeExperiment({
  datasetId: 'clinical-triage-evals',
  experimentId,
})
```

如果只需导入结果，创建实验时不要提供 `targetType` 和 `targetId`，并在第 2 步改用 `submitExperimentResult`。

## `runExperimentItem()` {/* #runexperimentitem */}

在服务端执行一个实验数据项：Mastra 使用实验目标处理该数据项，运行解析出的评分器，并根据 `(experimentId, itemId, attempt)` 更新或插入结果。实验必须在创建时指定目标。评分器的解析优先级与原生运行相同：实验的 `scorerIds` 高于数据项的 `scorerIds`，后者又高于数据集的 `scorerIds`。

## `finalizeExperiment()` {/* #finalizeexperiment */}

将由调用方驱动的实验标记为已完成。服务端根据已保存的结果记录计算各类数据项数量：`succeededCount` 表示至少有一次尝试未发生错误，`failedCount` 表示每次尝试都发生错误，`skippedCount` 表示从未提交结果。此操作具有幂等性：对已完成的实验再次调用会返回已保存的记录。

## 删除数据集实验() {/* #deletedatasetexperiment */}

通过所属数据集删除实验。服务端先删除实验的可观测性 Trace，包括其中的 span 和关联的信号，再删除实验及其结果记录。如果存储不支持删除 Trace，Trace 会保留，服务端会记录警告。如果因其他原因无法删除 Trace，Promise 会被拒绝，Mastra 会保留实验及其结果记录，但部分 Trace 可能已经删除。

```typescript
await client.deleteDatasetExperiment('dataset-id', 'experiment-id', {
  organizationId: 'organization-id',
  projectId: 'project-id',
})
```

## 清除数据集项() {/* #purgedatasetitem */}

从现有数据集历史和关联的实验结果中清除数据项内容，包括结果标签和评论，同时保留版本历史、实验计数及审核状态。之后为该数据项提交的结果会以内容已脱敏的形式保存；之后对该数据项的更新会被拒绝。

```typescript
await client.purgeDatasetItem('dataset-id', 'item-id', {
  organizationId: 'organization-id',
  projectId: 'project-id',
})
```

可选的第三个参数可将清除操作限定在指定租户的组织和项目范围内。如果数据集不属于该范围，或数据项在数据集中没有历史记录，服务端会返回 `404`。

返回 `Promise<{ success: boolean }>`。此操作具有幂等性，且不可撤销。清除操作会与并发的数据项写入串行执行或发生冲突，但不保证哪项操作先完成。如果修改数据项的操作在竞争中落后，存储层会重新读取清除标记，并以 `DATASET_ITEM_PURGED` 拒绝该操作。删除操作仍具有幂等性；竞争期间创建的删除墓碑记录也会保持脱敏。MongoDB 存储需要支持事务的副本集或分片部署。完整行为请参阅 [`dataset.purgeItem()`](/reference/datasets/purgeItem)。
