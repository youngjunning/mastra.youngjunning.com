# dataset.createExperiment()

**自以下版本加入：** `@mastra/core@1.61.0`

创建实验但不启动运行。由自己的编排器（例如 Temporal 工作流）按以下两种方式之一控制执行流程：

- **指定目标：**传入 `targetType` 和 `targetId`，然后对每个数据项调用 [`runExperimentItem()`](/reference/datasets/runExperimentItem)。Mastra 会执行目标，并在服务端运行评分器。
- **不指定目标：**省略这两个参数，在自己的基础设施上完成全部执行，并通过 [`submitExperimentResult()`](/reference/datasets/submitExperimentResult) 逐项提交结果。

两种方式最后都要调用 [`finalizeExperiment()`](/reference/datasets/finalizeExperiment)。

实验在创建时固定数据集版本。因此，即使数据集此后发生变化，提交的结果仍会按固定的数据项集合进行校验。

## 使用示例 {/* #usage-example */}

```typescript
import { Mastra } from '@mastra/core'

const mastra = new Mastra({/* storage config */})

const dataset = await mastra.datasets.get({ id: 'dataset-id' })

const { experimentId, totalItems, datasetVersion } = await dataset.createExperiment({
  id: 'temporal-wf-run-42', // optional: idempotent create on retry
  targetType: 'agent',
  targetId: 'translation-agent',
  scorers: ['accuracy'],
})
```

传入自定义 `id` 可使创建操作具备幂等性：使用同一 `id` 再次调用会返回已有实验，工作流活动重试时也不会重复创建。如果调用抛出 `EXPERIMENT_ID_CONFLICT` 错误，表示该 `id` 已属于其他数据集中的实验，或对应实验使用了不同目标。

`targetType` 和 `targetId` 必须同时提供，且创建实验时目标必须已在 Mastra 注册。`scorers` 需要指定目标，因为 Mastra 不会为无目标实验评分；此时应通过 `submitExperimentResult` 提交扁平化分数。
