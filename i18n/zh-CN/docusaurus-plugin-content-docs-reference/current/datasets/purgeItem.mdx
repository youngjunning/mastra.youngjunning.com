# 数据集.purgeItem()

**添加于：** `@mastra/core@1.65.0`

从每个历史版本、删除逻辑删除和链接的实验结果中永久清除数据集项目的内容。使用[`deleteItem()`](/reference/datasets/deleteItem) instead when you only need to remove an item from the current dataset version.

## 使用示例 {/* #usage-example */}

```typescript
import { Mastra } from '@mastra/core'

const mastra = new Mastra({/* storage config */})

const dataset = await mastra.datasets.get({ id: 'dataset-id' })

await dataset.purgeItem({ itemId: 'item-id' })
```

## 行为 {/* #behavior */}

清除会用编辑值替换现有历史记录行和删除逻辑删除中项目的内容字段，并向其元数据添加清除标记。相同的字段以及标签和注释将从链接到该数据集项目的实验结果中删除。清除后提交的实验结果写入与编辑内容一起存储。

清除与并发数据集项编写器序列化或冲突，但不保证哪个操作首先完成。如果一个突变`updateItem()` call loses the race, it re-reads the purge marker and rejects with `DATASET_ITEM_PURGED`. `deleteItem()` remains idempotent, and any deletion tombstone created during the race stays redacted.

正常项目突变使用缓慢变化的维度类型 2 (SCD-2) 版本控制。永久清除有意覆盖擦除的历史不变性，同时保留项目身份和数据集版本时间线。它不会创建新的数据集版本。版本固定读取仍然可以返回项目的行骨架，但其清除的内容不再可用。实验计数器和审核状态也被保留。

MongoDB 存储需要具有事务支持的副本集或分片部署。如果事务不可用，则操作会在更改项目或其实验结果之前失败。

`externalId`保持不变，因为 Mastra 使用它作为身份密钥。不要将敏感数据存储在`externalId`.

清除是幂等的并且无法撤消。
