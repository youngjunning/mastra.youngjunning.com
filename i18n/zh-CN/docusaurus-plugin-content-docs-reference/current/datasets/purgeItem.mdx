# dataset.purgeItem()

**新增于：** `@mastra/core@1.65.0`

从每个历史版本、删除墓碑以及关联的实验结果中永久清除数据项内容。如果只需从当前数据集版本中移除数据项，请改用 [`deleteItem()`](/reference/datasets/deleteItem)。

## 使用示例 {/* #usage-example */}

```typescript
import { Mastra } from '@mastra/core'

const mastra = new Mastra({/* storage config */})

const dataset = await mastra.datasets.get({ id: 'dataset-id' })

await dataset.purgeItem({ itemId: 'item-id' })
```

## 行为 {/* #behavior */}

永久清除会将现有历史记录和删除墓碑中的数据项内容字段替换为脱敏值，并在其元数据中添加清除标记。与该数据项关联的实验结果中，相同字段以及标签和评论也会被清除。清除后提交的实验结果写入会以脱敏内容存储。

永久清除会与并发的数据项写入串行执行或发生冲突，但不保证哪个操作先完成。如果修改型 `updateItem()` 调用在竞态中失败，它会重新读取清除标记，并以 `DATASET_ITEM_PURGED` 拒绝请求。`deleteItem()` 仍保持幂等，竞态期间创建的任何删除墓碑也会保持脱敏状态。

普通数据项变更使用渐变维度类型 2（SCD-2）版本控制。永久清除会为满足擦除需求而有意覆盖历史不可变性，同时保留数据项身份和数据集版本时间线。它不会创建新的数据集版本。固定版本读取仍可返回数据项的记录骨架，但已清除的内容不再可用。实验计数和审核状态也会保留。

MongoDB 存储需要支持事务的副本集或分片部署。如果事务不可用，操作会在更改数据项或其实验结果前失败。

`externalId` remains unchanged because Mastra uses it as an identity key. Don't store sensitive data in `externalId`.

永久清除是幂等操作，且无法撤销。
