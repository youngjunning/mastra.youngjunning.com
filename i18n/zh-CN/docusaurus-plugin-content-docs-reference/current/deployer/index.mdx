# Deployer

Deployer 通过打包代码、管理环境文件并使用 Hono 框架提供应用服务，负责部署独立运行的 Mastra 应用。具体实现必须针对目标部署环境定义部署方法。

## 使用示例 {/* #usage-example */}

要创建自定义 Deployer，可以继承抽象类 `Deployer`，并在 `deploy` 方法中实现目标环境所需的部署逻辑。例如：

```typescript
import { Deployer } from '@mastra/deployer'

class CustomDeployer extends Deployer {
  constructor() {
    super({ name: 'custom-deployer' })
  }

  async deploy(outputDirectory: string): Promise<void> {
    // Prepare the output directory
    await this.prepare(outputDirectory)

    // Bundle the application
    await this._bundle('server.ts', 'mastra.ts', {
      projectRoot: process.cwd(),
      outputDirectory,
    })

    // Custom deployment logic
  }
}
```

## 核心概念 {/* #core-concepts */}

### 部署生命周期 {/* #deployment-lifecycle */}

Deployer 抽象类实现了结构化的部署生命周期：

1. **初始化**：使用名称初始化 Deployer，并创建 Deps 实例来管理依赖。
1. **环境设置**：`getEnvFiles` 方法确定部署时使用的环境文件（`.env`、`.env.local`、`.env.production`）。
1. **准备**：继承自 Bundler 的 `prepare` 方法清理输出目录并创建必要的子目录。
1. **打包**：继承自 Bundler 的 `_bundle` 方法打包应用代码及其依赖。
1. **部署**：子类实现抽象方法 `deploy`，执行实际部署。

### 环境文件管理 {/* #environment-file-management */}

Deployer 类通过 `getEnvFiles` 方法提供内置的环境文件管理能力。该方法：

- 按优先级从低到高的预定顺序查找环境文件：`.env`、`.env.local`、`.env.production`
- 按此顺序返回所有存在的文件，因此后面文件中的值会覆盖前面文件中的值
- 如果没有找到环境文件，则返回空数组

```typescript oxfmt:false
getEnvFiles(): Promise<string[]> {
  const possibleFiles = ['.env', '.env.local', '.env.production'];
  const fileService = new FileService();

  return Promise.resolve(fileService.getExistingFiles(possibleFiles));
}
```

### 打包与部署的关系 {/* #bundling-and-deployment-relationship */}

Deployer 类继承 Bundler 类，使打包与部署之间的关系更加明确：

1. **打包是前提**：部署前必须先将应用代码打包成可部署的形式。
1. **共享基础能力**：打包与部署共用依赖管理和文件系统操作等基础能力。
1. **专门的部署逻辑**：打包负责封装代码，部署则增加针对目标环境的逻辑，将打包后的代码部署出去。
1. **可扩展性**：通过实现抽象方法 `deploy`，可以为不同目标环境创建专门的 Deployer。
