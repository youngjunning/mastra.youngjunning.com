# VercelDeployer

`VercelDeployer` 会打包 Mastra 服务器，并生成符合 Vercel [Build Output API](https://vercel.com/docs/build-output-api/v3) 的构建产物。Vercel 会直接将这些产物部署为无服务器函数。

## 安装 {/* #installation */}

要使用 `VercelDeployer`，请安装 `@mastra/deployer-vercel` 包：

```bash npm2yarn
npm install @mastra/deployer-vercel@latest
```

## 使用示例 {/* #usage-example */}

导入 `VercelDeployer`，并在 Mastra 配置中将其设为部署器：

```typescript title="src/mastra/index.ts"
import { Mastra } from '@mastra/core'
// highlight-next-line
import { VercelDeployer } from '@mastra/deployer-vercel'

export const mastra = new Mastra({
  // highlight-next-line
  deployer: new VercelDeployer(),
})
```

## 构造函数选项 {/* #constructor-options */}

部署器接受以下选项：

- `studio?: boolean`: 将 [Studio](/docs/studio/overview) 与 API 一起部署为由 Vercel Edge CDN 提供的静态资源。默认为 `false`。
- `maxDuration?: number`: 函数执行超时时间（秒）。此选项只设置 Vercel 的限制；Mastra 的请求超时需单独配置，参见[请求超时](#request-timeouts)。
- `memory?: number`: 函数内存（MB）
- `regions?: string[]`: 函数的部署区域（例如 `['sfo1','iad1']`）

`maxDuration`、`memory` 和 `regions` 选项会合并到 `.vercel/output/functions/index.func/.vc-config.json` 中，同时保留默认字段（`handler`、`launcherType`、`runtime`、`shouldAddHelpers`）。

### 自定义选项示例 {/* #example-with-overrides */}

```typescript title="src/mastra/index.ts"
import { Mastra } from '@mastra/core'
import { VercelDeployer } from '@mastra/deployer-vercel'

export const mastra = new Mastra({
  deployer: new VercelDeployer({
    studio: true,
    maxDuration: 600,
    memory: 1536,
    regions: ['sfo1', 'iad1'],
  }),
})
```

## 请求超时 {/* #request-timeouts */}

Vercel 的函数执行时限与 Mastra 的请求超时分别生效：

- **Vercel 函数执行时限**：由部署器的 `maxDuration` 选项设置，单位为秒。
- **Mastra 请求超时**：通过 `server.timeout` 在 `Mastra` 配置中设置，单位为毫秒。未设置时默认为 `180000`（180 秒）；超时请求会收到 `504 Gateway Timeout` 响应。

`maxDuration` 不会改变 `server.timeout`。即使 `maxDuration` 设置得更高，请求超过 180 秒仍会失败。因此，运行 Workflow 或流式 Agent 等耗时较长的请求时，需要同时提高这两个值：

```typescript title="src/mastra/index.ts"
import { Mastra } from '@mastra/core'
import { VercelDeployer } from '@mastra/deployer-vercel'

export const mastra = new Mastra({
  deployer: new VercelDeployer({
    maxDuration: 600, // seconds
  }),
  server: {
    timeout: 600_000, // milliseconds, keep at or below maxDuration
  },
})
```

## 构建产物 {/* #build-output */}

运行 `mastra build` 后，部署器会生成符合 Vercel [Build Output API (v3)](https://vercel.com/docs/build-output-api/v3) 的 `.vercel/output` 目录。其中包含路由配置和无服务器函数包，Vercel 可直接部署，无需检测框架。

构建产物包括：

- **config.json**：将请求转发给相应处理程序的路由配置
- **functions/**：打包为无服务器函数的 Mastra 服务器
- **static/**：Studio 单页应用的静态资源（仅在 `studio: true` 时生成）

未启用 Studio 时：

```bash
.vercel/
└── output/
    ├── config.json
    └── functions/
        └── index.func/
            ├── .vc-config.json
            ├── index.mjs
            └── node_modules/
```

启用 `studio: true` 时：

```bash
.vercel/
└── output/
    ├── config.json
    ├── static/
    │   ├── index.html
    │   └── assets/
    │       ├── *.js
    │       └── *.css
    └── functions/
        └── index.func/
            ├── .vc-config.json
            ├── index.mjs
            └── node_modules/
```

启用 Studio 后，路由会将 `/` 以及 Studio 构建产物的路由清单中列出的路径交给 `index.html`，由客户端处理路由；静态资源（JS、CSS）则由 Vercel Edge CDN 提供，不会调用函数。包括 `/api/*` 和通过 `registerApiRoute()` 注册的自定义路由在内，其他所有路径均由无服务器函数处理。如果自定义路由位于 Studio 路由之下（例如 `/agents/custom`），则会由 `index.html` 提供，因此应将自定义路由注册在 Studio 路由根路径之外。

此目录在构建时生成，不应提交到版本控制系统。
