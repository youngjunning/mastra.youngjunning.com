# Vercel部署器

这`VercelDeployer`捆绑您的 Mastra 服务器并生成符合 Vercel 的输出[构建输出 API](https://vercel.com/docs/build-output-api/v3)。 Vercel 将此输出直接部署为无服务器函数。

## 安装 {/* #installation */}

使用`VercelDeployer`, install the `@mastra/deployer-vercel` package:

```bash npm2yarn
npm install @mastra/deployer-vercel@latest
```

## 使用示例 {/* #usage-example */}

进口`VercelDeployer` and set it as the deployer in your Mastra configuration:

```typescript title="src/mastra/index.ts"
import { Mastra } from '@mastra/core'
// highlight-next-line
import { VercelDeployer } from '@mastra/deployer-vercel'

export const mastra = new Mastra({
  // highlight-next-line
  deployer: new VercelDeployer(),
})
```

## 构造函数选项 {/* #constructor-options */}

部署者接受以下选项：

* `studio?: boolean`： 部署[Studio](/docs/studio/overview) alongside your API as static assets served from Vercel's Edge CDN. Defaults to `false`.
* `maxDuration?: number`：函数执行超时（以秒为单位）。这仅设置了 Vercel 的限制； Mastra自己的请求超时是单独配置的，参见[Request timeouts](#request-timeouts).
* `memory?: number`：函数内存（以MB为单位）
* `regions?: string[]`：部署该功能的区域（例如`['sfo1','iad1']`)

这`maxDuration`, `memory`, and `regions` options are merged into `.vercel/output/functions/index.func/.vc-config.json` while preserving default fields (`handler`, `launcherType`, `runtime`, `shouldAddHelpers`).

### 具有覆盖的示例 {/* #example-with-overrides */}

```typescript title="src/mastra/index.ts"
import { Mastra } from '@mastra/core'
import { VercelDeployer } from '@mastra/deployer-vercel'

export const mastra = new Mastra({
  deployer: new VercelDeployer({
    studio: true,
    maxDuration: 600,
    memory: 1536,
    regions: ['sfo1', 'iad1'],
  }),
})
```

## 请求超时 {/* #request-timeouts */}

Vercel 的函数执行时间和 Mastra 的请求超时是分开强制执行的：

* **Vercel函数执行时间**：由部署者设置`maxDuration` option, in seconds.
* **Mastra 请求超时**: 设置为`server.timeout` in your `Mastra` config, in milliseconds. When unset it defaults to `180000` (180 seconds), and requests that exceed it are answered with `504 Gateway Timeout`.

`maxDuration`没有改变`server.timeout`. A request that takes longer than 180 seconds fails even if `maxDuration` is higher, so raise both when you run long requests such as workflow runs or streaming agents:

```typescript title="src/mastra/index.ts"
import { Mastra } from '@mastra/core'
import { VercelDeployer } from '@mastra/deployer-vercel'

export const mastra = new Mastra({
  deployer: new VercelDeployer({
    maxDuration: 600, // seconds
  }),
  server: {
    timeout: 600_000, // milliseconds, keep at or below maxDuration
  },
})
```

## 构建输出 {/* #build-output */}

运行后`mastra build`, the deployer generates a `.vercel/output` directory conforming to Vercel's [Build Output API (v3)](https://vercel.com/docs/build-output-api/v3). This directory contains routing configuration and serverless function bundles that Vercel deploys directly, bypassing framework detection.

输出包含：

* **配置.json**：将请求定向到适当处理程序的路由配置
* **功能/**：您的 Mastra 服务器捆绑为无服务器功能
* **静止的/**：Studio SPA 资产（仅当`studio: true`)

无工作室：

```bash
.vercel/
└── output/
    ├── config.json
    └── functions/
        └── index.func/
            ├── .vc-config.json
            ├── index.mjs
            └── node_modules/
```

和`studio: true`:

```bash
.vercel/
└── output/
    ├── config.json
    ├── static/
    │   ├── index.html
    │   └── assets/
    │       ├── *.js
    │       └── *.css
    └── functions/
        └── index.func/
            ├── .vc-config.json
            ├── index.mjs
            └── node_modules/
```

启用 studio 后，将配置路由，以便`/` and the Studio routes listed in the Studio build's route manifest are served from `index.html` for client-side routing, and static assets (JS, CSS) are served from Vercel's Edge CDN with no function invocations. All other paths, including `/api/*` and custom routes registered with `registerApiRoute()`, are handled by the serverless function. Custom routes that fall under a Studio route (for example, `/agents/custom`) are served from `index.html` instead, so register custom routes outside Studio's route roots.

该文件夹是在构建期间生成的，不应提交给版本控制。
