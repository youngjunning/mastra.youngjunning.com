# CloudflareDeployer

`CloudflareDeployer` 会打包 Mastra 服务器，并生成符合 Cloudflare [Wrangler 配置规范](https://developers.cloudflare.com/workers/wrangler/configuration/)的 `wrangler.jsonc` 文件。Cloudflare 会将其部署为 Cloudflare Worker。

## 安装 {/* #installation */}

要使用 `CloudflareDeployer`，请安装 `@mastra/deployer-cloudflare` 包：

```bash npm2yarn
npm install @mastra/deployer-cloudflare@latest
```

## 使用示例 {/* #usage-example */}

导入 `CloudflareDeployer`，并在 Mastra 配置中将其设为部署器：

```typescript title="src/mastra/index.ts"
import { Mastra } from '@mastra/core'
import { CloudflareDeployer } from '@mastra/deployer-cloudflare'

export const mastra = new Mastra({
  deployer: new CloudflareDeployer({
    name: 'your-project-name',
    routes: [
      {
        pattern: 'example.com/*',
        zone_name: 'example.com',
        custom_domain: true,
      },
    ],
    vars: {
      NODE_ENV: 'production',
    },
    d1_databases: [
      {
        binding: 'DB',
        database_name: 'my-database',
        database_id: 'd1-database-id',
        preview_database_id: 'your-preview-database-id',
      },
    ],
    kv_namespaces: [
      {
        binding: 'CACHE',
        id: 'kv-namespace-id',
      },
    ],
  }),
})
```

## 构造函数选项 {/* #constructor-options */}

`CloudflareDeployer` 构造函数接受与 `wrangler.jsonc` 相同的配置选项。所有可用选项请参阅 [Wrangler 配置文档](https://developers.cloudflare.com/workers/wrangler/configuration/)。

## 密钥 {/* #secrets */}

`.env` 文件中的环境变量不会写入 `wrangler.jsonc`，以免密钥被提交到源码仓库。

如需让 Cloudflare Worker 使用 `.env` 中的密钥，请将其上传为 [Cloudflare Secrets](https://developers.cloudflare.com/workers/configuration/secrets/)：

```bash
npx wrangler secret bulk .env
```

`vars` 在 `CloudflareDeployer` 构造函数中仅用于 `NODE_ENV` 等非敏感配置值。

## 构建产物 {/* #build-output */}

运行 `mastra build` 后，部署器会生成符合 Cloudflare [Wrangler 配置规范](https://developers.cloudflare.com/workers/wrangler/configuration/)的 `wrangler.jsonc` 文件。该文件指向 `.mastra/output` 中的文件，因此使用 Wrangler 部署前必须先运行 `mastra build`。

## Cloudflare 绑定 {/* #cloudflare-bindings */}

使用 Cloudflare 部署器时，可以在 Mastra 配置文件中从 `cloudflare:workers` 导入运行时绑定。Mastra 会自动保留 `cloudflare:workers` 这类基于协议的运行时导入，在 `mastra build` 期间不会尝试将其作为 npm 依赖安装。

```typescript title="src/mastra/index.ts"
import { env } from 'cloudflare:workers'
import { Mastra } from '@mastra/core'
import { registerApiRoute } from '@mastra/core/server'
import { CloudflareDeployer } from '@mastra/deployer-cloudflare'

export const mastra = new Mastra({
  deployer: new CloudflareDeployer({
    name: 'my-worker',
    kv_namespaces: [{ binding: 'CACHE', id: 'your-kv-namespace-id' }],
  }),
  server: {
    apiRoutes: [
      registerApiRoute('/bindings', {
        method: 'GET',
        requiresAuth: false,
        handler: async c => {
          await env.CACHE.put('status', 'ok')
          return c.json({ status: await env.CACHE.get('status') })
        },
      }),
    ],
  },
})
```

:::note[将绑定直接写在 `new Mastra({...})` 内]
Mastra 的 Babel 插件会延迟执行 `new Mastra(...)`，确保运行时 `env` 已可用。该调用之外的代码会在模块加载时求值，此时 `env` 尚未填充。

```typescript
// ✅ Works — binding is inside new Mastra(), so it's deferred
export const mastra = new Mastra({
  storage: new D1Store({ binding: env.DB }),
})

// ❌ Breaks — env.DB is undefined at module load
const storage = new D1Store({ binding: env.DB })
export const mastra = new Mastra({ storage })
```

:::
