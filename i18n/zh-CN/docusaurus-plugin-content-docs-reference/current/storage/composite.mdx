# 复合存储

`MastraCompositeStore` 可组合来自不同 Provider 的存储域。需要为不同用途使用不同数据库时，可以使用它。例如，用 LibSQL 存储记忆，用 PostgreSQL 存储 Workflow。

## 安装 {/* #installation */}

`MastraCompositeStore` 包含在 `@mastra/core` 中：

```bash npm2yarn
npm install @mastra/core@latest
```

还需要安装要组合使用的存储 Provider：

```bash npm2yarn
npm install @mastra/pg@latest @mastra/libsql@latest @mastra/mongodb@latest
```

## 存储域 {/* #storage-domains */}

Mastra 按域组织存储，每个域负责一种特定数据。不同域可以使用不同的存储适配器；各存储包会导出其实现的域类。

| 域 | 说明 |
| - | - |
| `memory` | Agent 对话的持久化存储，包括线程（对话会话）、消息、资源（用户身份）和工作记忆（跨对话保留的上下文）。 |
| `workflows` | Workflow 执行状态。Workflow 因等待人工输入、外部事件或定时恢复而暂停时，状态会持久化在这里，以便服务器重启后恢复执行。 |
| `scores` | Mastra Evals 系统的评估结果。分数和指标会持久化，供后续分析与比较。 |
| `observability` | 遥测数据，包括 Trace 和 Span。Agent 交互、Tool 调用和 LLM 请求产生的 Span 会汇集成 Trace，用于调试和性能分析。 |
| `agents` | 已存储 Agent 的配置。可在运行时定义和更新 Agent，无需部署代码。 |
| `datasets` | 实验运行使用的评估数据集，包含数据集定义、Schema 和带版本的条目。 |
| `experiments` | 实验运行及逐条实验结果，关联数据集和评估目标。 |

:::note

`MastraCompositeStore` 接受上述所有域键，但不同存储包支持的域并不相同。可以为不同域混用适配器，前提是对应适配器已实现并导出该域类。例如，`memory: new MemoryLibSQL(...)` 与 `workflows: new WorkflowsPG(...)` 可以组合，因为两个包都导出了相应的域类。

:::

## 用法 {/* #usage */}

### 基本组合 {/* #basic-composition */}

直接从各存储包导入域类并组合：

```typescript title="src/mastra/index.ts"
import { MastraCompositeStore } from '@mastra/core/storage'
import { WorkflowsPG, ScoresPG } from '@mastra/pg'
import { MemoryLibSQL } from '@mastra/libsql'
import { Mastra } from '@mastra/core'

export const mastra = new Mastra({
  storage: new MastraCompositeStore({
    id: 'composite',
    domains: {
      memory: new MemoryLibSQL({ url: 'file:./local.db' }),
      workflows: new WorkflowsPG({ connectionString: process.env.DATABASE_URL }),
      scores: new ScoresPG({ connectionString: process.env.DATABASE_URL }),
    },
  }),
})
```

### 使用默认存储 {/* #with-a-default-storage */}

使用 `default` 指定后备存储，再覆盖特定域：

```typescript title="src/mastra/index.ts"
import { MastraCompositeStore } from '@mastra/core/storage'
import { PostgresStore } from '@mastra/pg'
import { MemoryLibSQL } from '@mastra/libsql'
import { Mastra } from '@mastra/core'

const pgStore = new PostgresStore({
  id: 'pg',
  connectionString: process.env.DATABASE_URL,
})

export const mastra = new Mastra({
  storage: new MastraCompositeStore({
    id: 'composite',
    default: pgStore,
    domains: {
      memory: new MemoryLibSQL({ url: 'file:./local.db' }),
    },
  }),
})
```

### 混用后端 {/* #mixed-backends */}

使用各存储包的域类，将不同域路由到不同后端。以下示例把记忆和 Workflow 状态存入 MongoDB，把可观测性数据存入 ClickHouse：

```typescript title="src/mastra/index.ts"
import { Mastra } from '@mastra/core'
import { MastraCompositeStore } from '@mastra/core/storage'
import { ObservabilityStorageClickhouse } from '@mastra/clickhouse'
import { MemoryStorageMongoDB, WorkflowsStorageMongoDB } from '@mastra/mongodb'

export const mastra = new Mastra({
  storage: new MastraCompositeStore({
    id: 'composite',
    domains: {
      memory: new MemoryStorageMongoDB({
        uri: process.env.MONGODB_URI,
        dbName: 'mastra_memory',
      }),
      workflows: new WorkflowsStorageMongoDB({
        uri: process.env.MONGODB_URI,
        dbName: 'mastra_workflows',
      }),
      observability: new ObservabilityStorageClickhouse({
        url: process.env.CLICKHOUSE_URL,
        username: process.env.CLICKHOUSE_USERNAME,
        password: process.env.CLICKHOUSE_PASSWORD,
      }),
    },
  }),
})
```

### 禁用域 {/* #disabling-a-domain */}

将域设为 `false` 即可禁用。禁用的域不会回退到 `default`，因此该域的数据不会持久化：

```typescript title="src/mastra/index.ts"
import { MastraCompositeStore } from '@mastra/core/storage'
import { PostgresStore } from '@mastra/pg'
import { Mastra } from '@mastra/core'

const pgStore = new PostgresStore({
  id: 'pg',
  connectionString: process.env.DATABASE_URL,
})

export const mastra = new Mastra({
  storage: new MastraCompositeStore({
    id: 'composite',
    default: pgStore,
    domains: {
      // don't persist traces and spans
      observability: false,
    },
  }),
})
```

## 初始化 {/* #initialization */}

`MastraCompositeStore` 会独立初始化每个已配置的域。传给 Mastra 类时，系统会自动调用 `init()`：

```typescript title="src/mastra/index.ts"
import { MastraCompositeStore } from '@mastra/core/storage'
import { MemoryPG, WorkflowsPG, ScoresPG } from '@mastra/pg'
import { Mastra } from '@mastra/core'

const storage = new MastraCompositeStore({
  id: 'composite',
  domains: {
    memory: new MemoryPG({ connectionString: process.env.DATABASE_URL }),
    workflows: new WorkflowsPG({ connectionString: process.env.DATABASE_URL }),
    scores: new ScoresPG({ connectionString: process.env.DATABASE_URL }),
  },
})

export const mastra = new Mastra({
  storage, // init() called automatically
})
```

直接使用存储时，需显式调用 `init()`：

```typescript
import { MastraCompositeStore } from '@mastra/core/storage'
import { MemoryPG } from '@mastra/pg'

const storage = new MastraCompositeStore({
  id: 'composite',
  domains: {
    memory: new MemoryPG({ connectionString: process.env.DATABASE_URL }),
  },
})

await storage.init()

// Access domain-specific stores via getStore()
const memoryStore = await storage.getStore('memory')
const thread = await memoryStore?.getThreadById({ threadId: '...' })
```

## 关闭连接 {/* #closing-connections */}

`close()` 会释放复合存储所用各存储实例的连接，包括 `default`、`editor` 和使用独立客户端的域。即使多个域共用同一实例，每个存储实例也只关闭一次。将复合存储传给 Mastra 类时，`shutdown()` 会调用 `close()`：

```typescript title="src/mastra/index.ts"
import { MastraCompositeStore } from '@mastra/core/storage'
import { PostgresStore } from '@mastra/pg'
import { Mastra } from '@mastra/core'

const pgStore = new PostgresStore({
  id: 'pg-storage',
  connectionString: process.env.DATABASE_URL,
})

export const mastra = new Mastra({
  storage: new MastraCompositeStore({ id: 'composite', default: pgStore }),
})

process.on('SIGTERM', async () => {
  // Releases the Postgres pool, so the process can exit
  await mastra.shutdown()
})
```

若某个存储实例仅用于提供一个域，就无法通过复合存储访问它。请保留该实例的引用，并自行关闭：

```typescript title="src/mastra/index.ts"
import { MastraCompositeStore } from '@mastra/core/storage'
import { ClickhouseStore } from '@mastra/clickhouse'
import { PostgresStore } from '@mastra/pg'
import { Mastra } from '@mastra/core'

const pgStore = new PostgresStore({
  id: 'pg-storage',
  connectionString: process.env.DATABASE_URL,
})

const clickhouseStore = new ClickhouseStore({
  id: 'clickhouse-storage',
  url: process.env.CLICKHOUSE_URL,
  username: process.env.CLICKHOUSE_USERNAME,
  password: process.env.CLICKHOUSE_PASSWORD,
})

export const mastra = new Mastra({
  storage: new MastraCompositeStore({
    id: 'composite',
    default: pgStore,
    domains: { observability: clickhouseStore.stores?.observability },
  }),
})

process.on('SIGTERM', async () => {
  await mastra.shutdown()
  await clickhouseStore.close()
})
```

## 使用场景 {/* #use-cases */}

### 为不同工作负载使用不同数据库 {/* #separate-databases-for-different-workloads */}

开发时使用本地数据库，同时将生产数据保存在托管服务中：

```typescript
import { MastraCompositeStore } from '@mastra/core/storage'
import { MemoryPG, WorkflowsPG, ScoresPG } from '@mastra/pg'
import { MemoryLibSQL } from '@mastra/libsql'

const storage = new MastraCompositeStore({
  id: 'composite',
  domains: {
    // Use local SQLite for development, PostgreSQL for production
    memory:
      process.env.NODE_ENV === 'development'
        ? new MemoryLibSQL({ url: 'file:./dev.db' })
        : new MemoryPG({ connectionString: process.env.DATABASE_URL }),
    workflows: new WorkflowsPG({ connectionString: process.env.DATABASE_URL }),
    scores: new ScoresPG({ connectionString: process.env.DATABASE_URL }),
  },
})
```

### 为可观测性使用专用存储 {/* #specialized-storage-for-observability */}

生产环境中的可观测性数据可能很快压垮通用数据库。一次 Agent 交互就可能产生数百个 Span；高流量应用每天可能产生数千个 Trace。

**[ClickHouse](/integrations/databases/clickhouse)** 针对大规模、高写入量的分析负载进行了优化，因此推荐用于生产环境的可观测性数据。使用复合存储将可观测性数据路由到 ClickHouse，同时将其他数据保留在主数据库中：

```typescript
import { MastraCompositeStore } from '@mastra/core/storage'
import { MemoryPG, WorkflowsPG, ScoresPG } from '@mastra/pg'
import { ObservabilityStorageClickhouseVNext } from '@mastra/clickhouse'

const storage = new MastraCompositeStore({
  id: 'composite',
  domains: {
    memory: new MemoryPG({ connectionString: process.env.DATABASE_URL }),
    workflows: new WorkflowsPG({ connectionString: process.env.DATABASE_URL }),
    scores: new ScoresPG({ connectionString: process.env.DATABASE_URL }),
    observability: new ObservabilityStorageClickhouseVNext({
      url: process.env.CLICKHOUSE_URL,
      username: process.env.CLICKHOUSE_USERNAME,
      password: process.env.CLICKHOUSE_PASSWORD,
    }),
  },
})
```

:::note

`ObservabilityStorageClickhouseVNext` 是当前的可观测性域实现。旧版 `ObservabilityStorageClickhouse` 类也仍然导出，并继续支持尚未迁移的项目。详情参见 [ClickHouse 存储参考](/integrations/databases/clickhouse)。

:::

### 为多副本集群配置 ClickHouse 复制 {/* #replicated-clickhouse-for-multi-replica-clusters */}

对于自行管理、拥有多个副本的 ClickHouse 集群，设置 `replication` 后，Mastra 会使用 `ReplicatedMergeTree` 引擎，并在 DDL 中应用 `ON CLUSTER`：

```typescript
import { MastraCompositeStore } from '@mastra/core/storage'
import { MemoryPG, WorkflowsPG, ScoresPG } from '@mastra/pg'
import { ObservabilityStorageClickhouseVNext } from '@mastra/clickhouse'

const storage = new MastraCompositeStore({
  id: 'composite',
  domains: {
    memory: new MemoryPG({ connectionString: process.env.DATABASE_URL }),
    workflows: new WorkflowsPG({ connectionString: process.env.DATABASE_URL }),
    scores: new ScoresPG({ connectionString: process.env.DATABASE_URL }),
    observability: new ObservabilityStorageClickhouseVNext({
      url: process.env.CLICKHOUSE_URL,
      username: process.env.CLICKHOUSE_USERNAME,
      password: process.env.CLICKHOUSE_PASSWORD,
      replication: {
        cluster: 'production_cluster',
        // Optional (defaults shown):
        // zookeeperPath: '/clickhouse/tables/{shard}/{database}/{table}',
        // replicaName: '{replica}',
      },
    }),
  },
})
```

不要在 ClickHouse Cloud 上设置 `replication`。Cloud 会在服务端将 `MergeTree` 改写为 `SharedMergeTree`。完整配置结构及运维说明参见 [ClickHouse 存储参考](/integrations/databases/clickhouse)。

:::note

使用不支持可观测性的存储 Provider（如 Convex、DynamoDB 或 Cloudflare）时，也需要采用这种方式。支持的 Provider 完整列表参见 [MastraStorageExporter 文档](/docs/observability/integrations/exporters/mastra-storage#storage-provider-support)。

:::
