# 复合存储

`MastraCompositeStore`可以组成来自不同Provider的存储域。当您需要不同的数据库用于不同的目的时，请使用它。例如，使用 LibSQL 作为内存，使用 PostgreSQL 作为Workflow程。

## 安装 {/* #installation */}

`MastraCompositeStore`包含在`@mastra/core`:

```bash npm2yarn
npm install @mastra/core@latest
```

您还需要安装您想要组成的存储提供程序：

```bash npm2yarn
npm install @mastra/pg@latest @mastra/libsql@latest @mastra/mongodb@latest
```

## 存储域 {/* #storage-domains */}

Mastra 将存储组织成域，每个域处理特定类型的数据。每个域可以由不同的存储适配器支持，并且域类从每个存储包导出。

|域名 |描述 |
| - | - |
|`memory` | Conversation persistence for agents. Stores threads (conversation sessions), messages, resources (user identities), and working memory (persistent context across conversations). |
| `workflows` | Workflow execution state. When workflows suspend for human input, external events, or scheduled resumption, their state is persisted here to enable resumption after server restarts. |
| `scores` | Evaluation results from Mastra's evals system. Scores and metrics are persisted here for analysis and comparison over time. |
| `observability`|遥测数据包括轨迹和跨度。Agent交互、Tool调用和 LLM 请求生成收集到跟踪中的跨度，用于调试和性能分析。 |
|`agents`|存储的Agent的Agent配置。允许在运行时定义和更新Agent，而无需部署代码。 |
|`datasets`|用于实验运行的评估数据集。存储数据集定义、架构和版本化项目。 |
|`experiments`|实验运行和每项实验结果链接到数据集和目标。 |

：：：笔记

`MastraCompositeStore`接受上述所有域密钥，但存储适配器支持因软件包而异。您可以在每个域中混合使用适配器，但仅限于由这些适配器实现和导出的域。例如，`memory: new MemoryLibSQL(...)` and `workflows: new WorkflowsPG(...)` is valid because both packages export those domain classes.

:::

## 用法 {/* #usage */}

### 基本构成 {/* #basic-composition */}

直接从每个商店包导入域类并组合它们：

```typescript title="src/mastra/index.ts"
import { MastraCompositeStore } from '@mastra/core/storage'
import { WorkflowsPG, ScoresPG } from '@mastra/pg'
import { MemoryLibSQL } from '@mastra/libsql'
import { Mastra } from '@mastra/core'

export const mastra = new Mastra({
  storage: new MastraCompositeStore({
    id: 'composite',
    domains: {
      memory: new MemoryLibSQL({ url: 'file:./local.db' }),
      workflows: new WorkflowsPG({ connectionString: process.env.DATABASE_URL }),
      scores: new ScoresPG({ connectionString: process.env.DATABASE_URL }),
    },
  }),
})
```

### 使用默认存储 {/* #with-a-default-storage */}

使用`default` to specify a fallback storage, then override specific domains:

```typescript title="src/mastra/index.ts"
import { MastraCompositeStore } from '@mastra/core/storage'
import { PostgresStore } from '@mastra/pg'
import { MemoryLibSQL } from '@mastra/libsql'
import { Mastra } from '@mastra/core'

const pgStore = new PostgresStore({
  id: 'pg',
  connectionString: process.env.DATABASE_URL,
})

export const mastra = new Mastra({
  storage: new MastraCompositeStore({
    id: 'composite',
    default: pgStore,
    domains: {
      memory: new MemoryLibSQL({ url: 'file:./local.db' }),
    },
  }),
})
```

### 混合后端 {/* #mixed-backends */}

使用每个存储包中的域类将不同的域路由到不同的后端。以下示例将内存和Workflow状态存储在 MongoDB 中，然后将可观察性路由到 ClickHouse：

```typescript title="src/mastra/index.ts"
import { Mastra } from '@mastra/core'
import { MastraCompositeStore } from '@mastra/core/storage'
import { ObservabilityStorageClickhouse } from '@mastra/clickhouse'
import { MemoryStorageMongoDB, WorkflowsStorageMongoDB } from '@mastra/mongodb'

export const mastra = new Mastra({
  storage: new MastraCompositeStore({
    id: 'composite',
    domains: {
      memory: new MemoryStorageMongoDB({
        uri: process.env.MONGODB_URI,
        dbName: 'mastra_memory',
      }),
      workflows: new WorkflowsStorageMongoDB({
        uri: process.env.MONGODB_URI,
        dbName: 'mastra_workflows',
      }),
      observability: new ObservabilityStorageClickhouse({
        url: process.env.CLICKHOUSE_URL,
        username: process.env.CLICKHOUSE_USERNAME,
        password: process.env.CLICKHOUSE_PASSWORD,
      }),
    },
  }),
})
```

### 禁用域 {/* #disabling-a-domain */}

将域设置为`false` to disable it. A disabled domain doesn't fall back to `default`, so data for that domain isn't persisted:

```typescript title="src/mastra/index.ts"
import { MastraCompositeStore } from '@mastra/core/storage'
import { PostgresStore } from '@mastra/pg'
import { Mastra } from '@mastra/core'

const pgStore = new PostgresStore({
  id: 'pg',
  connectionString: process.env.DATABASE_URL,
})

export const mastra = new Mastra({
  storage: new MastraCompositeStore({
    id: 'composite',
    default: pgStore,
    domains: {
      // don't persist traces and spans
      observability: false,
    },
  }),
})
```

## 初始化 {/* #initialization */}

`MastraCompositeStore`独立初始化每个配置的域。当传到Mastra班时，`init()` is called automatically:

```typescript title="src/mastra/index.ts"
import { MastraCompositeStore } from '@mastra/core/storage'
import { MemoryPG, WorkflowsPG, ScoresPG } from '@mastra/pg'
import { Mastra } from '@mastra/core'

const storage = new MastraCompositeStore({
  id: 'composite',
  domains: {
    memory: new MemoryPG({ connectionString: process.env.DATABASE_URL }),
    workflows: new WorkflowsPG({ connectionString: process.env.DATABASE_URL }),
    scores: new ScoresPG({ connectionString: process.env.DATABASE_URL }),
  },
})

export const mastra = new Mastra({
  storage, // init() called automatically
})
```

如果直接使用存储，则调用`init()` explicitly:

```typescript
import { MastraCompositeStore } from '@mastra/core/storage'
import { MemoryPG } from '@mastra/pg'

const storage = new MastraCompositeStore({
  id: 'composite',
  domains: {
    memory: new MemoryPG({ connectionString: process.env.DATABASE_URL }),
  },
})

await storage.init()

// Access domain-specific stores via getStore()
const memoryStore = await storage.getStore('memory')
const thread = await memoryStore?.getThreadById({ threadId: '...' })
```

## 关闭连接 {/* #closing-connections */}

`close()`释放组合使用的存储的连接，包括`default` and `editor` stores and any domain with its own client. Each store closes once even if it backs several domains. When the composite is passed to the Mastra class, `shutdown()` calls `close()`:

```typescript title="src/mastra/index.ts"
import { MastraCompositeStore } from '@mastra/core/storage'
import { PostgresStore } from '@mastra/pg'
import { Mastra } from '@mastra/core'

const pgStore = new PostgresStore({
  id: 'pg-storage',
  connectionString: process.env.DATABASE_URL,
})

export const mastra = new Mastra({
  storage: new MastraCompositeStore({ id: 'composite', default: pgStore }),
})

process.on('SIGTERM', async () => {
  // Releases the Postgres pool, so the process can exit
  await mastra.shutdown()
})
```

您构建的仅用于提供域的存储无法通过组合访问。保留对它的引用并自行关闭它：

```typescript title="src/mastra/index.ts"
import { MastraCompositeStore } from '@mastra/core/storage'
import { ClickhouseStore } from '@mastra/clickhouse'
import { PostgresStore } from '@mastra/pg'
import { Mastra } from '@mastra/core'

const pgStore = new PostgresStore({
  id: 'pg-storage',
  connectionString: process.env.DATABASE_URL,
})

const clickhouseStore = new ClickhouseStore({
  id: 'clickhouse-storage',
  url: process.env.CLICKHOUSE_URL,
  username: process.env.CLICKHOUSE_USERNAME,
  password: process.env.CLICKHOUSE_PASSWORD,
})

export const mastra = new Mastra({
  storage: new MastraCompositeStore({
    id: 'composite',
    default: pgStore,
    domains: { observability: clickhouseStore.stores?.observability },
  }),
})

process.on('SIGTERM', async () => {
  await mastra.shutdown()
  await clickhouseStore.close()
})
```

## 使用案例 {/* #use-cases */}

### 针对不同工作负载的单独数据库 {/* #separate-databases-for-different-workloads */}

使用本地数据库进行开发，同时将生产数据保存在托管服务中：

```typescript
import { MastraCompositeStore } from '@mastra/core/storage'
import { MemoryPG, WorkflowsPG, ScoresPG } from '@mastra/pg'
import { MemoryLibSQL } from '@mastra/libsql'

const storage = new MastraCompositeStore({
  id: 'composite',
  domains: {
    // Use local SQLite for development, PostgreSQL for production
    memory:
      process.env.NODE_ENV === 'development'
        ? new MemoryLibSQL({ url: 'file:./dev.db' })
        : new MemoryPG({ connectionString: process.env.DATABASE_URL }),
    workflows: new WorkflowsPG({ connectionString: process.env.DATABASE_URL }),
    scores: new ScoresPG({ connectionString: process.env.DATABASE_URL }),
  },
})
```

### 用于可观察性的专门存储 {/* #specialized-storage-for-observability */}

可观察性数据很快就会压倒生产中的通用数据库。单个Agent交互可以生成数百个跨度，高流量应用程序每天可以生成数千个跟踪。

**[克利克屋](/integrations/databases/clickhouse)**&#x5EFA;议用于生产可观察性，因为它针对大容量、写入量大的分析工作负载进行了优化。使用复合存储将可观察性路由到 ClickHouse，同时将其他数据保留在主数据库中：

```typescript
import { MastraCompositeStore } from '@mastra/core/storage'
import { MemoryPG, WorkflowsPG, ScoresPG } from '@mastra/pg'
import { ObservabilityStorageClickhouseVNext } from '@mastra/clickhouse'

const storage = new MastraCompositeStore({
  id: 'composite',
  domains: {
    memory: new MemoryPG({ connectionString: process.env.DATABASE_URL }),
    workflows: new WorkflowsPG({ connectionString: process.env.DATABASE_URL }),
    scores: new ScoresPG({ connectionString: process.env.DATABASE_URL }),
    observability: new ObservabilityStorageClickhouseVNext({
      url: process.env.CLICKHOUSE_URL,
      username: process.env.CLICKHOUSE_USERNAME,
      password: process.env.CLICKHOUSE_PASSWORD,
    }),
  },
})
```

：：：笔记

`ObservabilityStorageClickhouseVNext`是当前的可观测域实现。遗产`ObservabilityStorageClickhouse` class is also exported and remains supported for projects that haven't migrated. See the [ClickHouse storage reference](/integrations/databases/clickhouse) for details.

:::

### 用于多副本集群的复制 ClickHouse {/* #replicated-clickhouse-for-multi-replica-clusters */}

对于具有多个副本的自管理 ClickHouse 集群，设置`replication` so Mastra emits `ReplicatedMergeTree` engines and applies `ON CLUSTER` to its DDL:

```typescript
import { MastraCompositeStore } from '@mastra/core/storage'
import { MemoryPG, WorkflowsPG, ScoresPG } from '@mastra/pg'
import { ObservabilityStorageClickhouseVNext } from '@mastra/clickhouse'

const storage = new MastraCompositeStore({
  id: 'composite',
  domains: {
    memory: new MemoryPG({ connectionString: process.env.DATABASE_URL }),
    workflows: new WorkflowsPG({ connectionString: process.env.DATABASE_URL }),
    scores: new ScoresPG({ connectionString: process.env.DATABASE_URL }),
    observability: new ObservabilityStorageClickhouseVNext({
      url: process.env.CLICKHOUSE_URL,
      username: process.env.CLICKHOUSE_USERNAME,
      password: process.env.CLICKHOUSE_PASSWORD,
      replication: {
        cluster: 'production_cluster',
        // Optional (defaults shown):
        // zookeeperPath: '/clickhouse/tables/{shard}/{database}/{table}',
        // replicaName: '{replica}',
      },
    }),
  },
})
```

不设置`replication` on ClickHouse Cloud. Cloud rewrites `MergeTree` to `SharedMergeTree` server-side. See the [ClickHouse storage reference](/integrations/databases/clickhouse) for the full config shape and operator notes.

：：：笔记

当使用不支持可观察性的存储Provider（例如 Convex、DynamoDB 或 Cloudflare）时，也需要这种方法。请参阅[MastraStorageExporter documentation](/docs/observability/integrations/exporters/mastra-storage#storage-provider-support) for the full list of supported providers.

:::
