# 快速适配器

这`@mastra/express`软件包提供了一个服务器适配器，用于运行 Mastra[表达](https://expressjs.com)。有关一般适配器概念（构造函数选项、初始化流程等），请参阅[服务器适配器](/docs/server/server-adapters).

## 安装 {/* #installation */}

安装 Express 适配器和 Express 框架：

```bash npm2yarn
npm install @mastra/express@latest express
```

## 使用示例 {/* #usage-example */}

```typescript title="server.ts"
import express from 'express'
import { MastraServer } from '@mastra/express'
import { mastra } from './mastra'

const app = express()
app.use(express.json()) // Required for body parsing

const server = new MastraServer({ app, mastra })
await server.init()

app.listen(4111, () => {
  console.log('Server running on port 4111')
})
```

快递要求`express.json()` middleware for JSON body parsing. Add it before creating the `MastraServer`. `init()` doesn't start Mastra's background workers. To run [scheduled workflows](/docs/workflows/scheduled-workflows), agent schedules, or event listeners, call `await mastra.startWorkers()` after the server starts listening. See [启动后台工作者](/docs/server/server-adapters#start-background-workers).

## 与霍诺的区别 {/* #differences-from-hono */}

|方面|快递|霍诺 |
| - | - | - |
|正文解析|需要`express.json()` | Handled by framework |
| Context storage | `res.locals` | `c.get()` / `c.set()` |
| Middleware signature | `(req, res, next)` | `(c, next)` |
| Streaming | `res.write()` / `res.end()` | `stream()`帮手|
|中止信号|创建自`res.on('close')`，仅当响应未完成时才中止 |`c.req.raw.signal` |

## 添加自定义路线 {/* #adding-custom-routes */}

直接将路线添加到 Express 应用程序：

```typescript title="server.ts"
const app = express()
app.use(express.json())

const server = new MastraServer({ app, mastra })

// Before init - runs before Mastra middleware
app.get('/early-health', (req, res) => res.json({ status: 'ok' }))

await server.init()

// After init - has access to Mastra context
app.get('/custom', (req, res) => {
  const mastraInstance = res.locals.mastra
  res.json({ agents: Object.keys(mastraInstance.listAgents()) })
})

app.listen(4111)
```

：：：提示

之前添加的路线`init()` run without Mastra context. Add routes after `init()` to access the Mastra instance and request context.

:::

当您需要 Mastra 管理的身份验证和路由元数据时，例如`requiresAuth`, prefer [`registerApiRoute()`](/reference/server/register-api-route). For raw Express routes mounted directly on `app`, use `createAuthMiddleware()`:

```typescript title="server.ts"
import express from 'express'
import { createAuthMiddleware, MastraServer } from '@mastra/express'
import { mastra } from './mastra'

const app = express()
app.use(express.json())

const server = new MastraServer({ app, mastra })
await server.init()

app.get('/custom/protected', createAuthMiddleware({ mastra }), (req, res) => {
  const user = res.locals.requestContext?.get('mastra__user')
  if (!user) {
    return res.status(401).json({ error: 'Unauthorized' })
  }
  res.json({ user })
})

app.get('/custom/public', createAuthMiddleware({ mastra, requiresAuth: false }), (req, res) => {
  res.json({ ok: true })
})
```

`createAuthMiddleware()`当 Mastra 服务器没有身份验证时，调用下一个处理程序而不进行身份验证`auth` config, or when the route matches a public pattern. Public patterns include the built-in defaults (`/api` and `/api/auth/*`) and any `auth.public` patterns you configure. In those cases `mastra__user` isn't set, so protected handlers should reject requests without it, as the example above does.

## 访问上下文 {/* #accessing-context */}

在 Express 中间件和路由中，通过以下方式访问 Mastra 上下文`res.locals`:

```typescript
app.get('/custom', (req, res) => {
  const mastra = res.locals.mastra
  const requestContext = res.locals.requestContext
  const abortSignal = res.locals.abortSignal

  const agent = mastra.getAgent('myAgent')
  res.json({ agent: agent.name })
})
```

可用属性`res.locals`:

|关键|描述 |
| - | - |
|`mastra` | Mastra instance |
| `requestContext` | Request context map |
| `abortSignal` | Request cancellation signal |
| `registeredTools` | Tools registered with the adapter |
| `taskStore` | Task store for A2A operations |
| `customRouteAuthConfig` | Per-route auth overrides |

配置身份验证后，使用以下命令读取经过身份验证的用户`res.locals.requestContext.get('mastra__user')`. Clients can't set the reserved `mastra__user` key through the `requestContext` query parameter or body. On raw Express routes, the value is only populated after [`createAuthMiddleware()`](#adding-custom-routes) runs, so apply it before trusting the user. Don't rely on the legacy `user` key for authorization. A client can supply it on routes without auth middleware.

## 添加中间件 {/* #adding-middleware */}

之前添加 Express 中间件`init()` to run it on every request. Mastra context isn't available at that point:

```typescript title="server.ts"
const app = express()
app.use(express.json())

// Runs on every request, before Mastra context exists
app.use((req, res, next) => {
  console.log(`${req.method} ${req.url}`)
  next()
})

const server = new MastraServer({ app, mastra })
await server.init()
```

之后添加中间件`init()` never runs for Mastra's routes. Express dispatches handlers in registration order, so middleware registered after the routes only applies to routes added later.

该适配器无法运行[`server.middleware`](/docs/server/middleware) handlers because they use Hono's signature, and it logs a warning when that option is set. If you need Express middleware between Mastra's context step and its routes, use the manual initialization flow below.

## 手动初始化 {/* #manual-initialization */}

对于自定义中间件排序，请单独调用每个方法，而不是`init()`. See [manual initialization](/docs/server/server-adapters#manual-initialization) for details.
