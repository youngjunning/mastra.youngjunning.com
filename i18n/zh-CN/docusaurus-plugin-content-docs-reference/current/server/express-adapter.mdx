# Express 适配器

`@mastra/express` 包提供服务器适配器，用于通过 [Express](https://expressjs.com) 运行 Mastra。有关构造函数选项、初始化流程等通用概念，请参阅[服务器适配器](/docs/server/server-adapters)。

## 安装 {/* #installation */}

安装 Express 适配器和 Express 框架：

```bash npm2yarn
npm install @mastra/express@latest express
```

## 使用示例 {/* #usage-example */}

```typescript title="server.ts"
import express from 'express'
import { MastraServer } from '@mastra/express'
import { mastra } from './mastra'

const app = express()
app.use(express.json()) // Required for body parsing

const server = new MastraServer({ app, mastra })
await server.init()

app.listen(4111, () => {
  console.log('Server running on port 4111')
})
```

Express 需要 `express.json()` 中间件来解析 JSON 请求体。请在创建 `MastraServer` 之前添加它。`init()` 不会启动 Mastra 的后台工作进程。要运行[定时 Workflow](/docs/workflows/scheduled-workflows)、Agent 定时任务或事件监听器，请在服务器开始监听后调用 `await mastra.startWorkers()`。请参阅[启动后台工作进程](/docs/server/server-adapters#start-background-workers)。

## 与 Hono 的区别 {/* #differences-from-hono */}

| 方面 | Express | Hono |
| - | - | - |
| 请求体解析 | 需要 `express.json()` | 由框架处理 |
| 上下文存储 | `res.locals` | `c.get()` / `c.set()` |
| 中间件签名 | `(req, res, next)` | `(c, next)` |
| 流式传输 | `res.write()` / `res.end()` | `stream()` 辅助函数 |
| AbortSignal | 基于 `res.on('close')` 创建，仅在响应尚未完成时中止 | `c.req.raw.signal` |

## 添加自定义路由 {/* #adding-custom-routes */}

直接向 Express 应用添加路由：

```typescript title="server.ts"
const app = express()
app.use(express.json())

const server = new MastraServer({ app, mastra })

// Before init - runs before Mastra middleware
app.get('/early-health', (req, res) => res.json({ status: 'ok' }))

await server.init()

// After init - has access to Mastra context
app.get('/custom', (req, res) => {
  const mastraInstance = res.locals.mastra
  res.json({ agents: Object.keys(mastraInstance.listAgents()) })
})

app.listen(4111)
```

:::tip

在 `init()` 之前添加的路由无法访问 Mastra 上下文。要访问 Mastra 实例和请求上下文，请在 `init()` 之后添加路由。

:::

如果需要由 Mastra 管理的身份验证以及 `requiresAuth` 等路由元数据，优先使用 [`registerApiRoute()`](/reference/server/register-api-route)。对于直接挂载到 `app` 的原生 Express 路由，请使用 `createAuthMiddleware()`：

```typescript title="server.ts"
import express from 'express'
import { createAuthMiddleware, MastraServer } from '@mastra/express'
import { mastra } from './mastra'

const app = express()
app.use(express.json())

const server = new MastraServer({ app, mastra })
await server.init()

app.get('/custom/protected', createAuthMiddleware({ mastra }), (req, res) => {
  const user = res.locals.requestContext?.get('mastra__user')
  if (!user) {
    return res.status(401).json({ error: 'Unauthorized' })
  }
  res.json({ user })
})

app.get('/custom/public', createAuthMiddleware({ mastra, requiresAuth: false }), (req, res) => {
  res.json({ ok: true })
})
```

如果 Mastra 服务器未配置 `auth`，或路由匹配公开路径模式，`createAuthMiddleware()` 会跳过身份验证并调用下一个处理程序。公开路径模式包括内置默认值（`/api` 和 `/api/auth/*`），以及你配置的任何 `auth.public` 模式。在这些情况下，`mastra__user` 不会被设置，因此受保护的处理程序应像上面的示例一样拒绝缺少该值的请求。

## 访问上下文 {/* #accessing-context */}

在 Express 中间件和路由中，通过 `res.locals` 访问 Mastra 上下文：

```typescript
app.get('/custom', (req, res) => {
  const mastra = res.locals.mastra
  const requestContext = res.locals.requestContext
  const abortSignal = res.locals.abortSignal

  const agent = mastra.getAgent('myAgent')
  res.json({ agent: agent.name })
})
```

`res.locals` 中的可用属性：

| 键 | 描述 |
| - | - |
| `mastra` | Mastra 实例 |
| `requestContext` | 请求上下文映射 |
| `abortSignal` | 请求取消信号 |
| `registeredTools` | 已向适配器注册的 Tool |
| `taskStore` | A2A 操作的任务存储 |
| `customRouteAuthConfig` | 针对各路由的身份验证覆盖配置 |

配置身份验证后，可以通过 `res.locals.requestContext.get('mastra__user')` 读取已验证的用户。客户端无法通过 `requestContext` 查询参数或请求体设置保留键 `mastra__user`。在原生 Express 路由上，该值仅在 [`createAuthMiddleware()`](#adding-custom-routes) 运行后才会填充，因此必须先应用该中间件，再信任此用户信息。不要依赖旧的 `user` 键进行授权；在没有身份验证中间件的路由上，客户端可以自行提供该值。

## 添加中间件 {/* #adding-middleware */}

要让 Express 中间件在每个请求上运行，请在 `init()` 之前添加它。此时 Mastra 上下文尚不可用：

```typescript title="server.ts"
const app = express()
app.use(express.json())

// Runs on every request, before Mastra context exists
app.use((req, res, next) => {
  console.log(`${req.method} ${req.url}`)
  next()
})

const server = new MastraServer({ app, mastra })
await server.init()
```

在 `init()` 之后添加的中间件不会在 Mastra 路由上运行。Express 按注册顺序分派处理程序，因此在这些路由之后注册的中间件只对后来添加的路由生效。

该适配器无法运行 [`server.middleware`](/docs/server/middleware) 处理程序，因为它们使用 Hono 的函数签名。设置该选项时，适配器会记录警告。如果需要在 Mastra 的上下文初始化步骤与路由之间运行 Express 中间件，请使用下文的手动初始化流程。
