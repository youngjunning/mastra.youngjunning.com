# 内置 MCP Tool

位于 `/api/mcp` 的[内置 MCP 服务器](/docs/server/mcp)会根据下列 Tool 集，为每位调用者生成可用的 Tool 列表。每个 Tool 都会在进程内调用表中列出的 HTTP 路由；除了 `mcp:read` 和 `mcp:execute`，调用者还需要该路由的权限。调用时会进行与 HTTP 请求相同的 FGA 和所有权检查。调用者无权访问其路由的 Tool 不会出现在列表中。

标有 `*` 的参数为必填项。路由均相对于 API 前缀（默认为 `/api`）。标记为只读的 Tool 带有 MCP `readOnlyHint` 注解，在设置 `readOnly: true` 或 `?readonly=1` 时仍然可用。

## `agents` {/* #agents */}

| Tool | 参数 | 路由 | 权限 |
| - | - | - | - |
|`list_agents` | `query` | `GET /agents` | `agents:read` |
| `get_agent` | `agentId*` | `GET /agents/:agentId` | `agents:read` |
| `call_agent` | `agentId*`, `message*`, `threadId`, `resourceId` | `POST /agents/:agentId/generate` | `agents:execute` |
| `agent_<id>` | `message*`, `threadId`, `resourceId` | `POST /agents/:agentId/generate` | `agents:execute` |

- `list_agents` 返回每个 Agent 的 `id`、`name` 和 `description`。`query` 只保留 ID 或名称包含指定文本的 Agent。
- `call_agent` 返回回复文本，以及供后续继续对话时传入的 `threadId`。
- `server.mcp.featured.agents` 中列出的每个 Agent 都会对应一个 `agent_<id>`。
- 如果调用者可见的 Agent 数量不超过 `enumLimit`（默认为 25），`agentId` 会列出允许使用的 ID。

## `workflows` {/* #workflows */}

| Tool | 参数 | 路由 | 权限 |
| - | - | - | - |
|`list_workflows` | `query` | `GET /workflows` | `workflows:read` |
| `get_workflow` | `workflowId*` | `GET /workflows/:workflowId` | `workflows:read` |
| `start_workflow` | `workflowId*`, `inputData`, `runId` | `POST /workflows/:workflowId/start-async` | `workflows:execute` |
| `get_workflow_run` | `workflowId*`, `runId*`, `fields` | `GET /workflows/:workflowId/runs/:runId` | `workflows:read` |
| `resume_workflow_run` | `workflowId*`, `runId*`, `step`, `resumeData` | `POST /workflows/:workflowId/resume-async` | `workflows:execute` |
| `cancel_workflow_run` | `workflowId*`, `runId*` | `POST /workflows/:workflowId/runs/:runId/cancel` | `workflows:execute` |
| `workflow_<id>` | Workflow 的输入模式 | `POST /workflows/:workflowId/start-async` | `workflows:execute` |

- `start_workflow`、`resume_workflow_run` 和 `workflow_<id>` 会等待运行结束或挂起。挂起的运行会返回 `status: 'suspended'`、`runId`、`suspendPayload` 和 `suspendedSteps`。
- `get_workflow_run` 的 `fields` 是从 `result`、`error`、`payload`、`steps` 和 `activeStepsPath` 中选出的字段，以逗号分隔。
- `cancel_workflow_run` 带有 MCP `destructiveHint` 注解。
- `server.mcp.featured.workflows` 中列出的每个 Workflow 都会对应一个 `workflow_<id>`。如果输入模式定义的类型不是对象，该 Tool 会通过 `inputData` 接收输入值。

## `tools` {/* #tools */}

如果调用者可见的 Tool 数量不超过 `enumLimit`，且有权调用它们，每个 Tool 都会有独立的条目：

| Tool | 参数 | 路由 | 权限 |
| - | - | - | - |
|`tool_<id>` | Tool 的输入模式 | `POST /tools/:toolId/execute` | `tools:execute` |

如果 Tool 数量超过 `enumLimit`，或者调用者无法调用 Tool（设置了 `readOnly: true` 或没有 `tools:execute` 权限），则会改用下列操作类 Tool。只有调用者有权调用 Tool 时才会提供 `call_tool`：

| Tool | 参数 | 路由 | 权限 |
| - | - | - | - |
|`list_tools` | `query` | `GET /tools` | `tools:read` |
| `get_tool` | `toolId*` | `GET /tools/:toolId` | `tools:read` |
| `call_tool` | `toolId*`, `data` | `POST /tools/:toolId/execute` | `tools:execute` |

如果 Tool 定义了自己的 `mcp.annotations`，其 `tool_<id>` 条目会使用这些注解。

## `memory` {/* #memory */}

| Tool | 参数 | 路由 | 权限 |
| - | - | - | - |
|`list_threads` | `agentId`, `resourceId`, `page`, `perPage` | `GET /memory/threads` | `memory:read` |
| `get_thread` | `threadId*`, `agentId` | `GET /memory/threads/:threadId` | `memory:read` |
| `list_messages` | `threadId*`, `agentId`, `page`, `perPage` | `GET /memory/threads/:threadId/messages` | `memory:read` |
| `search_memory` | `agentId*`, `searchQuery*`, `resourceId`, `threadId`, `limit` | `GET /memory/search` | `memory:read` |
| `get_memory_status` | `agentId*`, `resourceId`, `threadId` | `GET /memory/status`, `GET /memory/config` | `memory:read` |
| `get_observations` | `agentId*`, `threadId`, `resourceId`, `waitForPending` | `GET /memory/observational-memory` | `memory:read` |
| `create_thread` | `agentId*`, `resourceId`, `title`, `metadata`, `threadId` | `POST /memory/threads` | `memory:write` |
| `update_thread` | `threadId*`, `agentId*`, `title`, `metadata` | `PATCH /memory/threads/:threadId` | `memory:write` |
| `clone_thread` | `threadId*`, `agentId*`, `newThreadId`, `title`, `metadata`, `messageLimit` | `POST /memory/threads/:threadId/clone` | `memory:execute` |
| `save_messages` | `agentId*`, `messages*` | `POST /memory/save-messages` | `memory:write` |

- 如果 `server.auth` 设置了 `mapUserToResourceId`，`resourceId` 默认为当前调用者对应的资源 ID，且调用者无法读写其他资源的会话、消息或观察式记忆。否则，Tool 会使用客户端传入的 `resourceId`；要保持记忆私密，请设置 `mapUserToResourceId`。[FGA](/docs/auth/fga) 会保护会话，但仅传入 `resourceId` 调用 `get_observations` 时，默认 FGA 路由不会覆盖该调用。
- 不传 `threadId` 时，`get_observations` 会读取该资源的观察式记忆。`waitForPending: true` 最多等待 30 秒，让待处理的观察任务完成。只有调用者有权调用需要 `memory:write` 权限的 `POST /memory/observational-memory/buffer-status` 时，才会提供此选项。
- 除非设置了 `limit`，否则 `search_memory` 最多返回 20 条结果。

## `observability` {/* #observability */}

| Tool | 参数 | 路由 | 权限 |
| - | - | - | - |
|`query_traces` | `timeRange*`, `where`, `textSearch`, `rootSource`, `group`, `orderBy`, `page` | `POST /observability/traces/query` | `observability:read` |
| `aggregate_traces` | `timeRange*`, `measures*`, `where`, `groupBy`, `interval`, `having`, `orderBy`, `limit` | `POST /observability/traces/aggregate` | `observability:read` |
| `query_spans` | `timeRange*`, `where`, `textSearch`, `orderBy`, `page` | `POST /observability/spans/query` | `observability:read` |
| `aggregate_spans` | `timeRange*`, `measures*`, `where`, `groupBy`, `interval`, `having`, `orderBy`, `limit` | `POST /observability/spans/aggregate` | `observability:read` |
| `query_threads` | `timeRange*`, `where`, `orderBy`, `page` | `POST /observability/threads/query` | `observability:read` |
| `get_trace_query_fields` | `timeRange*`, `predicateScope*`, `search`, `limit` | `POST /observability/traces/query/fields` | `observability:read` |
| `get_trace_query_values` | `timeRange*`, `predicateScope*`, `path*`, `search`, `limit` | `POST /observability/traces/query/values` | `observability:read` |
| `list_traces` | `entityType`、`entityName`、`status`、`traceId`、`threadId`、`dateRange` 等筛选条件，以及 `page`、`perPage`、`field`、`direction` | `GET /observability/traces` | `observability:read` |
| `get_trace` | `traceId*`, `offset` | `GET /observability/traces/:traceId/light` | `observability:read` |
| `get_span` | `traceId*`, `spanId*` | `GET /observability/traces/:traceId/spans/:spanId` | `observability:read` |
| `get_trace_trajectory` | `traceId*` | `GET /observability/traces/:traceId/trajectory` | `observability:read` |
| `list_logs` | `level`、`traceId`、`entityName`、`threadId`、`timestamp` 等筛选条件，以及 `page`、`perPage`、`direction` | `GET /observability/logs` | `observability:read` |

- 支持链路追踪查询的存储后端会提供查询和聚合 Tool，而不提供 `list_traces`。不支持这类查询的后端则提供 `list_traces`。只有存储后端实现了日志功能时，才会提供 `list_logs`。
- `predicateScope` 可取 `trace`、`spans`、`scores` 或 `feedback`。`interval` 可取 `1m`、`5m`、`15m`、`1h` 或 `1d`。
- `get_trace` 返回精简的跨度记录。如果返回的追踪数据被截断，请将返回的 `nextOffset` 作为 `offset` 传入，以读取剩余记录。

## `observability_analytics` {/* #observability_analytics */}

| Tool | 参数 | 路由 | 权限 |
| - | - | - | - |
| `list_scores` | `scorerId`、`traceId`、`entityName`、`timestamp` 等筛选条件，以及 `page`、`perPage`、`field`、`direction` | `GET /observability/scores` | `observability:read` |
| `analyze_scores` | `op*`, `scorerId*`, `scoreSource`, `aggregation`, `filters`, `comparePeriod`, `groupBy`, `interval`, `percentiles` | `POST /observability/scores/<op>` | `observability:read` |
| `list_feedback` | `feedbackType`、`traceId`、`reviewStatus`、`timestamp` 等筛选条件，以及 `page`、`perPage`、`direction` | `GET /observability/feedback` | `observability:read` |
| `analyze_feedback` | `op*`, `feedbackType*`, `feedbackSource`, `aggregation`, `filters`, `comparePeriod`, `groupBy`, `interval`, `percentiles` | `POST /observability/feedback/<op>` | `observability:read` |
| `analyze_metrics` | `op*`, `name*`, `aggregation`, `distinctColumn`, `filters`, `comparePeriod`, `groupBy`, `limit`, `orderDirection`, `interval`, `percentiles` | `POST /observability/metrics/<op>` | `observability:read` |
| `list_metric_names` | `metricName`, `labelKey`, `prefix`, `limit` | `GET /observability/discovery/metric-names`, `metric-label-keys`, `metric-label-values` | `observability:read` |

- `op` 可取 `aggregate`、`breakdown`、`timeseries` 或 `percentiles`，并决定 Tool 调用的路由。
- `aggregation` 可取 `sum`、`avg`、`min`、`max`、`count`、`count_distinct` 或 `last`。`comparePeriod` 可取 `previous_period`、`previous_day` 或 `previous_week`。
- `list_metric_names` 列出指标名称。传入 `metricName` 时，它会列出该指标的标签键；同时传入 `metricName` 和 `labelKey` 时，它会列出该标签的值。
- 只有存储后端实现了对应的评分、反馈或指标查询功能时，才会提供相应 Tool。

## `stored_agents` {/* #stored_agents */}

| Tool | 参数 | 路由 | 权限 |
| - | - | - | - |
|`list_available_models` | 无 | `GET /editor/builder/models/available` | `stored-agents:read` |
| `list_stored_agents` | `status`, `page`, `perPage` | `GET /stored/agents` | `stored-agents:read` |
| `get_stored_agent` | `storedAgentId*` | `GET /stored/agents/:storedAgentId` | `stored-agents:read` |
| `create_stored_agent` | `name*`、`instructions*`、`model`、`tools`、`memory`、`visibility`、`autoPublish`、`id` 及其他已存储 Agent 字段 | `POST /stored/agents` | `stored-agents:write` |
| `update_stored_agent` | `storedAgentId*`、任意已存储 Agent 字段、`changeMessage`、`autoPublish` | `PATCH /stored/agents/:storedAgentId` | `stored-agents:write` |

- 除非 `status` 为 `draft` 或 `archived`，否则 `list_stored_agents` 返回已发布的 Agent；默认每页 100 个。
- 除非 `autoPublish` 为 `false`，否则 `create_stored_agent` 和 `update_stored_agent` 会发布变更。新建的 Agent 归调用者所有；除非 `visibility` 为 `public`，否则默认仅限调用者访问。参阅[已存储 Agent 的可见性](/docs/studio/editor#visibility)。
- 如果 Agent 构建器限制了可用模型，这两个 Tool 都会拒绝不允许的模型。`list_available_models` 返回允许使用的模型。
