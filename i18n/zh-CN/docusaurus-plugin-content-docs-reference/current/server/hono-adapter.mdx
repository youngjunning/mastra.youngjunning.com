# 荣誉适配器

这`@mastra/hono`软件包提供了一个服务器适配器，用于运行 Mastra[霍诺](https://hono.dev)。有关一般适配器概念（构造函数选项、初始化流程等），请参阅[服务器适配器](/docs/server/server-adapters).

## 安装 {/* #installation */}

安装Hono适配器和Hono框架：

```bash npm2yarn
npm install @mastra/hono@latest hono
```

## 使用示例 {/* #usage-example */}

```typescript title="server.ts"
import { Hono } from 'hono'
import { HonoBindings, HonoVariables, MastraServer } from '@mastra/hono'
import { mastra } from './mastra'

const app = new Hono<{ Bindings: HonoBindings; Variables: HonoVariables }>()
const server = new MastraServer({ app, mastra })

await server.init()

export default app
```

`init()`不会启动 Mastra 的后台工作人员。运行[scheduled workflows](/docs/workflows/scheduled-workflows), agent schedules, or event listeners, call `await mastra.startWorkers()` after the server starts listening. See [Start background workers](/docs/server/server-adapters#start-background-workers).

## 添加自定义路线 {/* #adding-custom-routes */}

直接将路线添加到 Hono 应用程序：

```typescript title="server.ts"
import { Hono } from 'hono'
import { HonoBindings, HonoVariables, MastraServer } from '@mastra/hono'

const app = new Hono<{ Bindings: HonoBindings; Variables: HonoVariables }>()
const server = new MastraServer({ app, mastra })

// Before init - runs before Mastra middleware
app.get('/early-health', c => c.json({ status: 'ok' }))

await server.init()

// After init - has access to Mastra context
app.get('/custom', c => {
  const mastraInstance = c.get('mastra')
  return c.json({ agents: Object.keys(mastraInstance.listAgents()) })
})
```

：：：提示

之前添加的路线`init()` run without Mastra context. Add routes after `init()` to access the Mastra instance and request context.

:::

当您需要 Mastra 管理的身份验证和路由元数据时，例如`requiresAuth`, prefer [`registerApiRoute()`](/reference/server/register-api-route). For raw Hono routes mounted directly on `app`, use `createAuthMiddleware()`:

```typescript title="server.ts"
import { Hono } from 'hono'
import { createAuthMiddleware, HonoBindings, HonoVariables, MastraServer } from '@mastra/hono'
import { mastra } from './mastra'

const app = new Hono<{ Bindings: HonoBindings; Variables: HonoVariables }>()
const server = new MastraServer({ app, mastra })

await server.init()

app.get('/custom/protected', createAuthMiddleware({ mastra }), c => {
  const user = c.get('requestContext').get('user')
  return c.json({ user })
})

app.get('/custom/public', createAuthMiddleware({ mastra, requiresAuth: false }), c => {
  return c.json({ ok: true })
})
```

## 访问上下文 {/* #accessing-context */}

在 Hono 中间件和路由处理程序中，通过以下方式访问 Mastra 上下文`c.get()`:

```typescript
app.get('/custom', async c => {
  const mastra = c.get('mastra')
  const requestContext = c.get('requestContext')
  const abortSignal = c.get('abortSignal')

  const agent = mastra.getAgent('myAgent')
  return c.json({ agent: agent.name })
})
```

可用的上下文键：

|关键|描述 |
| - | - |
|`mastra` | Mastra instance |
| `requestContext` | Request context map |
| `abortSignal` | Request cancellation signal |
| `registeredTools` | Tools registered with the adapter |
| `taskStore` | Task store for A2A operations |
| `customRouteAuthConfig` | Per-route auth overrides |
| `user` | Authenticated user (if auth configured) |

## 添加中间件 {/* #adding-middleware */}

添加 Hono 中间件`app.use()` before `init()` to run it on every request. Mastra context isn't available at that point:

```typescript title="server.ts"
import { Hono } from 'hono'
import { HonoBindings, HonoVariables, MastraServer } from '@mastra/hono'

const app = new Hono<{ Bindings: HonoBindings; Variables: HonoVariables }>()

// Runs on every request, before Mastra context exists
app.use('*', async (c, next) => {
  console.log(`${c.req.method} ${c.req.url}`)
  await next()
})

const server = new MastraServer({ app, mastra })
await server.init()
```

之后添加中间件`init()` never runs for Mastra's routes. Hono dispatches handlers in registration order, so middleware registered after the routes only applies to routes added later.

要在 Mastra 的路由上运行具有 Mastra 上下文的中间件，请使用[`server.middleware`](/docs/server/middleware) in the Mastra config. The adapter registers it during `init()`, after the context step and before any route. These handlers are skipped for routes declared public with `requiresAuth: false`, so they can't block endpoints such as the Studio sign-in routes:

```typescript title="src/mastra/index.ts"
import { Mastra } from '@mastra/core'

export const mastra = new Mastra({
  server: {
    middleware: [
      async (c, next) => {
        c.get('requestContext').set('locale', c.req.header('accept-language') ?? 'en')
        await next()
      },
    ],
  },
})
```
