# invokeRoute()

`invokeRoute()` 函数在进程内以调用方用户身份运行服务器路由，并返回该路由通过 HTTP 响应时会返回的内容。它要求请求上下文已经过 Mastra 服务器身份认证，然后执行与各适配器上的 HTTP 端点相同的检查：身份认证 Provider 的 `authorize`、`authorizeUser` 和 `rules`、schema 校验、RBAC 权限检查以及细粒度授权 (FGA)。

使用它可以通过其他通道（例如 MCP Tool）提供路由能力，无需经由 HTTP 服务器代理调用，同时避免两条调用路径的行为出现偏差。

## 使用示例 {/* #usage-example */}

```typescript title="src/mastra/tools/metric-aggregate.ts"
import { Mastra } from '@mastra/core/mastra'
import { RequestContext } from '@mastra/core/request-context'
import { createTool } from '@mastra/core/tools'
import { GET_METRIC_AGGREGATE } from '@mastra/server/handlers/observability'
import { invokeRoute } from '@mastra/server/server-adapter'
import { z } from 'zod'

export const agentRunCount = createTool({
  id: 'agentRunCount',
  description: 'Counts agent runs',
  inputSchema: z.object({}),
  execute: async (_input, { mastra, requestContext = new RequestContext() }) => {
    if (!(mastra instanceof Mastra)) throw new Error('agentRunCount must run inside Mastra')

    const { status, body } = await invokeRoute(GET_METRIC_AGGREGATE, {
      mastra,
      requestContext,
      body: { name: ['mastra_agent_duration_ms'], aggregation: 'count' },
    })
    if (status !== 200) throw new Error(`Metric aggregate failed with status ${status}`)
    return body
  },
})
```

## 行为 {/* #behavior */}

* **不会重复进行身份认证。** 配置了服务器或 Studio 身份认证时，请求上下文必须已包含 Mastra 服务器认证机制识别出的用户。否则，`invokeRoute()` 会直接返回 `401`，不执行处理程序。通过 Mastra 服务器适配器到达 MCP Tool 的请求会携带此上下文。
* **授权钩子接收 HTTP 路径。** `authorize()` 和 `rules` 接收路由的 HTTP 方法，以及由服务器 `apiPrefix`（默认 `/api`）和已填入路径参数的路由路径组成的完整路径。`authorize()` 不会收到适配器专用的请求上下文。
* **仅支持 JSON 路由。** 如果路由的 `responseType` 不是 JSON，例如流式路由或 MCP 传输路由，`invokeRoute()` 会抛出错误。
* **处理程序不会收到 HTTP 专用参数。** 处理程序会收到解析后的参数以及 `mastra`、`requestContext` 和 `abortSignal`。如果路由读取 `request`、`registeredTools`、`taskStore` 或 `routePrefix`，就不适合用此函数调用。

## 与 `dispatchRoute()` 的区别 {/* #differences-from-dispatchroute */}

[`dispatchRoute()`](/reference/server/dispatch-route) 对所有路由（包括流式路由）执行同样的检查，具体行为有以下区别：

* 配置了身份认证时，`invokeRoute()` 始终要求调用方具有已认证的用户身份。`dispatchRoute()` 允许没有用户身份的调用方访问认证配置中声明为公开的路径。
* `invokeRoute()` 使用服务器的 `apiPrefix` 构建传给 `authorize()` 和 `rules` 的路径。`dispatchRoute()` 使用提供该路由的服务器适配器的前缀。
* 与 HTTP 适配器一样，`invokeRoute()` 允许请求体字段覆盖同名的路径参数。`dispatchRoute()` 优先采用路径参数。
* `invokeRoute()` 返回 `{ status, body }`。`dispatchRoute()` 返回处理程序的原始结果，检查失败时则返回状态码和错误响应体。
