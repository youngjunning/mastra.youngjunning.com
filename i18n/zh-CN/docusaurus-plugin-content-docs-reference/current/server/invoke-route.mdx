# 调用路由()

这`invokeRoute()`函数作为调用用户在进程中运行服务器路由，并返回该路由通过 HTTP 应答的内容。它期望 Mastra 服务器身份验证已经验证的请求上下文，然后在每个适配器上应用与路由的 HTTP 端点相同的检查：您的身份验证提供者的`authorize`, `authorizeUser`， 和`rules`、架构验证、RBAC 权限和细粒度授权 (FGA)。

使用它通过另一个通道（例如 MCP Tool）公开路由，而无需通过 HTTP 服务器进行Agent，并且两者不会分开。

## 使用示例 {/* #usage-example */}

```typescript title="src/mastra/tools/metric-aggregate.ts"
import { Mastra } from '@mastra/core/mastra'
import { RequestContext } from '@mastra/core/request-context'
import { createTool } from '@mastra/core/tools'
import { GET_METRIC_AGGREGATE } from '@mastra/server/handlers/observability'
import { invokeRoute } from '@mastra/server/server-adapter'
import { z } from 'zod'

export const agentRunCount = createTool({
  id: 'agentRunCount',
  description: 'Counts agent runs',
  inputSchema: z.object({}),
  execute: async (_input, { mastra, requestContext = new RequestContext() }) => {
    if (!(mastra instanceof Mastra)) throw new Error('agentRunCount must run inside Mastra')

    const { status, body } = await invokeRoute(GET_METRIC_AGGREGATE, {
      mastra,
      requestContext,
      body: { name: ['mastra_agent_duration_ms'], aggregation: 'count' },
    })
    if (status !== 200) throw new Error(`Metric aggregate failed with status ${status}`)
    return body
  },
})
```

## 行为 {/* #behavior */}

* **不会重新运行身份验证。**&#x914D;置服务器或 Studio 身份验证时，请求上下文必须已包含已解析的用户 Mastra 服务器身份验证。否则`invokeRoute()` returns `401` without running the handler. Requests reaching an MCP tool through a Mastra server adapter carry this context.
* **授权挂钩查看 HTTP 路径。** `authorize()` and `rules` receive the route's path under the server's `apiPrefix` (`/api` by default), with path parameters filled in, and the route's method. `authorize()` gets no adapter-specific request context.
* **仅支持 JSON 路由。** `invokeRoute()` throws for routes with any other `responseType`, such as streaming or MCP transport routes.
* **不提供仅 HTTP 处理程序参数。**&#x5904;理程序接收解析后的参数，`mastra`, `requestContext`, and `abortSignal`, but not `request`, `registeredTools`, `taskStore`, or `routePrefix`. Routes that read those aren't suitable.

## 与的差异`dispatchRoute()` {/* #differences-from-dispatchroute */}

[`dispatchRoute()`](/reference/server/dispatch-route)对任何路由（包括流路由）运行相同的检查，并在以下方面有所不同：

* `invokeRoute()`配置 auth 时始终需要经过身份验证的用户。`dispatchRoute()` lets a caller without a user reach paths your auth config declares public.
* `invokeRoute()`构建路径`authorize()` and `rules` from the server's `apiPrefix`. `dispatchRoute()` uses the prefix of the server adapter that serves the route.
* `invokeRoute()`让主体字段覆盖具有相同名称的路径参数，就像 HTTP 适配器所做的那样。`dispatchRoute()` lets the path parameter win.
* `invokeRoute()`回报`{ status, body }`. `dispatchRoute()` returns the handler's raw result, or a status and error body when a check fails.
