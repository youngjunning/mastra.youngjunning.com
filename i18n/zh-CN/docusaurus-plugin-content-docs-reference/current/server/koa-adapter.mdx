# Koa 适配器

这`@mastra/koa`软件包提供了一个服务器适配器，用于运行 Mastra[相思木](https://koajs.com)。有关一般适配器概念（构造函数选项、初始化流程等），请参阅[服务器适配器](/docs/server/server-adapters).

## 安装 {/* #installation */}

安装 Koa 适配器和 Koa 框架：

```bash npm2yarn
npm install @mastra/koa@latest koa koa-bodyparser
```

## 使用示例 {/* #usage-example */}

```typescript title="server.ts"
import Koa from 'koa'
import bodyParser from 'koa-bodyparser'
import { MastraServer } from '@mastra/koa'
import { mastra } from './mastra'

const app = new Koa()
app.use(bodyParser())

const server = new MastraServer({ app, mastra })

await server.init()

app.listen(3000, () => {
  console.log('Server running on http://localhost:3000')
})
```

`init()`不会启动 Mastra 的后台工作人员。运行[scheduled workflows](/docs/workflows/scheduled-workflows), agent schedules, or event listeners, call `await mastra.startWorkers()` after the server starts listening. See [Start background workers](/docs/server/server-adapters#start-background-workers).

## 错误处理 {/* #error-handling */}

Koa 适配器遵循 Koa 的标准错误处理模式，通过 Koa 的中间件链从路由处理程序向上传播错误。您可以使用常规的 Koa 错误处理中间件：

```typescript title="server.ts"
const app = new Koa()
app.use(bodyParser())

// Your error middleware catches errors from Mastra route handlers
app.use(async (ctx, next) => {
  try {
    await next()
  } catch (err) {
    ctx.status = err.status || 500
    ctx.body = { error: err.message }
    // Log, report to Sentry, etc.
  }
})

const server = new MastraServer({ app, mastra })
await server.init()
```

这[`server.onError`](/reference/configuration#serveronerror) hook is also supported. When configured, it's called before the error propagates to middleware, and its response is used directly:

```typescript title="src/mastra/index.ts"
import { Mastra } from '@mastra/core'

const mastra = new Mastra({
  server: {
    onError: (err, c) => {
      console.error('Unhandled error:', err)
      return c.json({ error: err.message }, 500)
    },
  },
})
```

什么时候`init()` is used, a global error-handling middleware is also registered as a safety net. Errors that reach this middleware are emitted via `ctx.app.emit('error', err, ctx)` following the standard Koa convention. Client errors (4xx) and `501` errors already logged by the route handler are only emitted as `error` events when you register your own `error` listener; otherwise they go to `errorMonitor` listeners only.

## 保护原始路由 {/* #protecting-raw-routes */}

当您需要 Mastra 管理的身份验证和路由元数据时，例如`requiresAuth`, prefer [`registerApiRoute()`](/reference/server/register-api-route). For raw Koa routes mounted directly on the app, use `createAuthMiddleware()`:

```typescript title="server.ts"
import Koa from 'koa'
import { createAuthMiddleware, MastraServer } from '@mastra/koa'
import { mastra } from './mastra'

const app = new Koa()
const server = new MastraServer({ app, mastra })

await server.init()

app.use(createAuthMiddleware({ mastra }))
app.use(async ctx => {
  if (ctx.path !== '/custom/protected') return

  const user = ctx.state.requestContext.get('user')
  ctx.body = { user }
})
```

## 手动初始化 {/* #manual-initialization */}

对于自定义中间件排序，请单独调用每个方法，而不是`init()`. See [manual initialization](/docs/server/server-adapters#manual-initialization) for details.
