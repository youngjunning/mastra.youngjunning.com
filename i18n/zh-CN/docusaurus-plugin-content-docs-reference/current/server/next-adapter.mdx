# Next.js 适配器

这`@mastra/next`包将 Mastra 安装在 Next.js App Router 应用程序中。看[服务器适配器](/docs/server/server-adapters)对于一般适配器概念。

## 安装 {/* #installation */}

安装 Next.js 适配器及其 Hono 对等依赖项：

```bash npm2yarn
npm install @mastra/next@latest hono
```

## 使用示例 {/* #usage-example */}

在包罗万象的 App Router 路由中安装适配器：

```typescript title="app/api/[...mastra]/route.ts"
import { createNextRouteHandler } from '@mastra/next'
import { mastra } from '@/mastra'

export const { GET, POST, PUT, DELETE, PATCH, OPTIONS, HEAD } = createNextRouteHandler({
  mastra,
})
```

这`prefix` option defaults to `/api` and must match the catch-all route's mount path. For example, when mounting at `app/api/mastra/[...mastra]/route.ts`, use `createNextRouteHandler({ mastra, prefix: '/api/mastra' })`.

## 签名 {/* #signature */}

```typescript
function createNextRouteHandler(options: NextRouteHandlerOptions): NextRouteHandlers
```

## 返回值 {/* #return-value */}

返回一个`NextRouteHandlers` object with `GET`, `POST`, `PUT`, `DELETE`, `PATCH`, `OPTIONS`， 和`HEAD`特性。每个属性都是具有以下签名的处理程序：

```typescript
(request: Request) => Response | Promise<Response>
```

## 无服务器部署和延迟初始化 {/* #serverless-deployments--lazy-initialization */}

适配器同步导出其路由处理程序，然后创建底层 Hono 应用程序并`MastraServer` when the first request arrives. That initialized app is reused for subsequent requests in the same process, which supports serverless runtimes without top-level asynchronous initialization.

A2A 端点使用内存中的任务存储。任务状态仅在进程的生命周期内持续，并且不在无服务器实例之间共享。

## 体型限制 {/* #body-size-limit */}

请求正文的默认限制为 4.5 MB。超过接收限制的请求`{ error: 'Request body too large' }`.

放`server.bodySizeLimit` on the `Mastra` instance to configure the limit.

## 中间件 {/* #middleware */}

中间件配置为`server.middleware` or `setServerMiddleware()` runs through the adapter's Hono-based server, except on framework-public routes such as those marked `requiresAuth: false`. See [Server middleware](/docs/server/middleware).
