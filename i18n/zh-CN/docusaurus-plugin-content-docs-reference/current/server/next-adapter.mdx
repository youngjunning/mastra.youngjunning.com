# Next.js 适配器

`@mastra/next` 包将 Mastra 挂载到 Next.js App Router 应用中。通用概念请参阅[服务器适配器](/docs/server/server-adapters)。

## 安装 {/* #installation */}

安装 Next.js 适配器及其 Hono 对等依赖项：

```bash npm2yarn
npm install @mastra/next@latest hono
```

## 使用示例 {/* #usage-example */}

在包容所有子路径的 App Router 路由中挂载适配器：

```typescript title="app/api/[...mastra]/route.ts"
import { createNextRouteHandler } from '@mastra/next'
import { mastra } from '@/mastra'

export const { GET, POST, PUT, DELETE, PATCH, OPTIONS, HEAD } = createNextRouteHandler({
  mastra,
})
```

`prefix` 默认值为 `/api`，必须与该 catch-all 路由的挂载路径一致。例如，挂载到 `app/api/mastra/[...mastra]/route.ts` 时，应使用 `createNextRouteHandler({ mastra, prefix: '/api/mastra' })`。

## 签名 {/* #signature */}

```typescript
function createNextRouteHandler(options: NextRouteHandlerOptions): NextRouteHandlers
```

## 返回值 {/* #return-value */}

返回一个 `NextRouteHandlers` 对象，包含 `GET`、`POST`、`PUT`、`DELETE`、`PATCH`、`OPTIONS` 和 `HEAD` 属性。每个属性都是具有以下签名的处理函数：

```typescript
(request: Request) => Response | Promise<Response>
```

## Serverless 部署与延迟初始化 {/* #serverless-deployments--lazy-initialization */}

适配器先同步导出路由处理函数，在首个请求到达时再创建底层 Hono 应用和 `MastraServer`。初始化后的应用会在同一进程的后续请求中复用，因此 serverless 运行时无需在顶层进行异步初始化。

A2A 端点使用内存任务存储。任务状态仅在当前进程存活期间保留，不会在不同的 serverless 实例之间共享。

## 请求体大小限制 {/* #body-size-limit */}

请求体大小默认上限为 4.5 MB。超出上限的请求会收到 `{ error: 'Request body too large' }`。

设置 `server.bodySizeLimit` 即可调整 `Mastra` 实例的请求体大小上限。

## 中间件 {/* #middleware */}

通过 `server.middleware` 或 `setServerMiddleware()` 配置的中间件会经过适配器内基于 Hono 的服务器，但标记为 `requiresAuth: false` 等框架公开路由除外。详见[服务器中间件](/docs/server/middleware)。
