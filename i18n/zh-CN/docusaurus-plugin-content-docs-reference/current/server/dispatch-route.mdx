# dispatchRoute()

`dispatchRoute()` 函数以调用用户的身份在进程内运行服务器路由。它要求请求上下文已经通过 Mastra 服务器身份验证，然后执行服务器适配器处理该路由的 HTTP 请求时会执行的检查：身份验证 Provider 的 `authorize`、`authorizeUser` 和 `rules`、schema 验证、RBAC 权限检查，以及细粒度授权 (FGA)。如果相应的 HTTP 请求会被拒绝，它也不会放行调用。

可以用它基于内置路由构建另一种传输方式，流式路由也适用。若是从 Tool 调用 JSON 路由，[`invokeRoute()`](/reference/server/invoke-route) 提供了更精简的 API。

## 使用示例 {/* #usage-example */}

```typescript title="src/server/run-tool.ts"
import type { Mastra } from '@mastra/core/mastra'
import type { RequestContext } from '@mastra/core/request-context'
import { SERVER_ROUTES, dispatchRoute } from '@mastra/server/server-adapter'

const executeTool = SERVER_ROUTES.find(
  route => route.method === 'POST' && route.path === '/tools/:toolId/execute',
)!

export async function runWeatherTool(
  mastra: Mastra,
  requestContext: RequestContext,
  request: Request,
) {
  const outcome = await dispatchRoute(
    executeTool,
    { pathParams: { toolId: 'weather' }, body: { data: { city: 'Paris' } } },
    { mastra, requestContext, abortSignal: request.signal, request },
  )
  if (!outcome.ok) throw new Error(`Tool route failed with status ${outcome.status}`)
  return outcome.result
}
```

## 行为 {/* #behavior */}

* **不会重新进行身份验证。** 配置了服务器或 Studio 身份验证时，请求上下文必须已经包含 Mastra 服务器身份验证解析出的用户。否则，除非路由路径是公开的，`dispatchRoute()` 会返回 `401`。
* **授权钩子接收 HTTP 路径。** `authorize()`、`authorizeUser()` 和 `rules` 会收到路由的方法及其实际服务路径：适配器前缀加上填入路径参数后的路由路径。
* **使用提供服务的适配器的路径和检查。** 每个适配器会将自身绑定到它创建的请求上下文。绑定信息不在上下文条目中，因此 Agent 和 Tool 代码无法读取。使用该请求上下文调度路由时，会采用该适配器的前缀和覆盖配置，即使另一个适配器也在相同前缀下提供同一个 Mastra 实例。请求之外的调用会使用为该实例提供服务的唯一适配器，或使用 `context.routePrefix` 指定的适配器。如果无法确定适配器，或没有适配器为 `routePrefix` 提供服务，无用户的调用方会收到 `401`，其他调用方则会遇到异常。它不会自行从多个适配器中选择一个。
* **路径参数按 URL 规则检查。** 参数缺失、为空、不是字符串，或值为 `.` 或 `..` 时，会返回 `400`。可选的 `:param?` 可以省略。
* **路径参数优先。** 请求体或查询参数中与路径参数同名的字段会被覆盖，因此授权检查和处理程序都会针对路径指定的资源执行。
* **`protected` 模式不会让其他路径变成公开路径。** 配置了身份验证后，除非路由路径被声明为公开路径，否则仍须有用户，即使该路径不匹配你的 `protected` 模式。
* **适配器的覆盖配置同样生效。** 提供服务的 `MastraServer` 子类对 `checkRoutePermission()` 的覆盖也会在调度路由时运行。
* **`authorizeUser()` 接收模拟请求。** 该请求使用调度路由的路径和方法，带有 `context.request` 的请求头，但没有请求体。
* **服务器上下文不能来自输入。** `request`、`routePrefix`、`registeredTools` 和 `taskStore` 只能通过 `context` 传给处理程序，不能通过同名的请求体或查询字段传入。

## 自定义适配器 {/* #custom-adapters */}

继承 `MastraServer` 的适配器会告知 `dispatchRoute()` 它在哪个路径下提供路由。未继承 `MastraServer` 的适配器必须自行注册，并将返回的句柄绑定到它创建的每个请求上下文：

```typescript
import { bindDispatchAdapter, registerDispatchAdapter } from '@mastra/server/server-adapter'

const handle = registerDispatchAdapter(mastra, { prefix: '/api' })

// For each request:
bindDispatchAdapter(requestContext, handle)
```

未继承 `MastraServer` 的适配器在完成请求身份验证和参数验证后，可以调用 `authorizeRoute()`，执行与内置适配器相同的路由权限和 FGA 检查。允许调用时，它返回 `null`；拒绝调用时，它返回可发送给调用方的 `403` 错误。`checkRouteRBAC()` 仅执行权限检查。

```typescript
import { authorizeRoute } from '@mastra/server/server-adapter'

const denied = await authorizeRoute(mastra, route, params, requestContext)
if (denied)
  return Response.json({ error: denied.error, message: denied.message }, { status: denied.status })
```
