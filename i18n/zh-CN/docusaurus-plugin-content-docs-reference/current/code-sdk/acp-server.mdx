# ACP server

Mastra Code 通过 Agent Client Protocol (ACP) 提供编程 Agent 对话服务。ACP 客户端将服务器作为子进程启动，并通过标准输入和标准输出交换以换行符分隔的 JSON-RPC 消息。标准错误输出用于诊断信息。

此服务器将编辑器或其他 ACP 客户端连接到 Mastra Code。若要将 Mastra Agent 连接到外部 ACP 服务器，请使用 [ACP 连接](/docs/connections/acp)。

## 启动服务器 {/* #start-the-server */}

安装 `mastracode` CLI 后，将客户端配置为运行：

```bash
mastracode --acp
```

如果客户端支持命令和参数字段，可使用：

```json
{
  "command": "mastracode",
  "args": ["--acp"]
}
```

初始化后，客户端调用 `session/new`，传入绝对路径 `cwd` 和 `mcpServers` 数组。响应包含会话 ID 和可选的配置项。后续提示和配置请求都需携带此 ID。

## 身份验证 {/* #authentication */}

如果尚未配置模型 Provider，`session/new` 会返回 `auth_required` 错误；客户端随后可提供 `initialize` 响应列出的认证方法：

| 方法 ID | 类型 | 行为 |
| - | - | - |
| `openai-codex` | Agent | 打开浏览器，以 ChatGPT Plus 或 Pro 订阅登录。 |
| `kimi-for-coding` | Agent | 打开浏览器，批准 Kimi For Coding 设备登录。 |
| `xai` | Agent | 打开浏览器，批准 xAI 设备登录。 |
| `anthropic` | Terminal | 运行 `mastracode login --provider anthropic`，以 Claude Pro 或 Max 订阅登录。 |
| `github-copilot` | Terminal | 运行 `mastracode login --provider github-copilot`，使用 GitHub Copilot 登录。 |
| `mastracode-login` | Terminal | 运行 `mastracode login`，选择任意 Provider 或保存 API 密钥。 |

只有声明支持终端认证的客户端才会收到终端类认证方法。

对于 Agent 类认证方法，`authenticate` 会在服务器进程中完成登录，并在保存凭据后返回。如果 Provider 需要输入内容（如需要粘贴的验证码），请求会失败，并提示在终端运行 `mastracode login`。

服务器进程环境中的 API 密钥也视为已配置 Provider。ACP 会话不会将项目 `.env` 文件加载到共享进程环境中。新会话无需重启服务器即可读取已保存的凭据。如果默认模型的 Provider 未配置，新会话会改用已配置 Provider 的默认模型，例如在 Anthropic 登录后使用 `anthropic/claude-fable-5`。

## `acpMain(options?)` {/* #acpmainoptions */}

若要从 SDK 入口点启动同一服务器：

```typescript title="acp-server.ts"
import { acpMain } from '@mastra/code-sdk/acp/index'

await acpMain()
```

返回 `Promise<void>`。此入口点接管进程的标准流和信号处理程序。关闭标准输入会释放会话。收到 `SIGINT` 或 `SIGTERM` 后，进程最多等待十秒完成清理再退出。清理超时或服务器发生致命故障时，退出码为 `1`。

CLI 的 `--dangerous-auto-approve` 标志可启用同一批准覆盖选项。`coAuthor` 的默认值参见[提交署名](/reference/code-sdk/mount-agent-controller#commit-attribution)。

## 会话和 MCP 服务器 {/* #sessions-and-mcp-servers */}

每个会话都有独立的运行时和工作目录。服务器通过 stdio 或 HTTP 连接客户端提供的 Model Context Protocol (MCP) 服务器。不支持旧版 SSE 服务器；使用它们会返回无效参数错误。Stdio 进程接收会话的工作目录和提供的环境变量。HTTP 连接接收提供的请求头。服务器名称重复或客户端与服务器初始化失败时会返回错误。

同一会话内的提示和配置更改按顺序执行。不同会话可以并发执行。`session/cancel` 会停止指定会话当前正在运行的轮次，并取消排队中的提示。

## 模型和推理控制 {/* #model-and-reasoning-controls */}

`session/new` 响应通过 `configOptions` 提供模型、模式和推理强度的选项。将返回的选项值传给 `session/set_config_option`：

```typescript
await connection.setSessionConfigOption({
  sessionId,
  configId: 'thought_level',
  value: 'high',
})
```

模型选项保留完整的 Provider 路由 ID，且不列出未配置凭据的 Provider。即使发现结果未返回会话已保存的模型，该模型仍可使用。模式和模型更改会等待当前轮次结束。

推理强度选项遵循所选模型的策略。Provider 可能会调整请求的级别。每个会话启动时只读取一次默认设置；模式更改和显式选择的推理强度会持续生效。若要读取设置文件的后续修改，请启动新会话。

仍支持旧版 `session/set_mode` 和 `session/set_model` 请求。

## Skill 命令 {/* #skill-commands */}

收到 `session/new` 响应后，服务器会通过 `available_commands_update` 告知客户端可用的 Workspace Skill。客户端可在首次提示前提供 `/skill/<name>` 命令补全。服务器会在后续每次提示前刷新列表，若有变化则发送更新。

将命令作为文本提示发送，后面可附加说明：

```typescript
await connection.prompt({
  sessionId,
  prompt: [{ type: 'text', text: '/skill/review Check the current changes' }],
})
```

服务器会将 Skill 的指令和资源列表加入当前轮次。它会使用 Mastra Code 的项目与全局 Skill 目录。名称重复时，按 Workspace 目录顺序选择第一个可由用户调用的文件。标记为 `user-invocable: false` 的 Skill 不会显示，显式调用也会被拒绝。Skill 不存在时会返回无效参数错误，且不会启动推理。

`/goal` 等终端命令不会作为 ACP 命令提供。

## 权限和错误 {/* #permissions-and-errors */}

默认情况下，Tool 批准和 Sandbox 访问请求会交给客户端的权限界面处理。被拒绝的 Tool 不会执行。取消暂停中的权限请求时，系统会先记录拒绝再中止，因此后续轮次不会重放该请求。不支持自由文本 Tool 问题。`ask_user` Tool 已禁用。

Assistant 片段只包含 Assistant 输出；用户提示和内部系统信号不会作为 Assistant 回复发出。Provider 故障会返回 JSON-RPC 错误。达到 Token 上限时返回 `max_tokens`，内容过滤拒绝时返回 `refusal`，取消时返回 `cancelled`。

## 支持的协议范围 {/* #supported-protocol-profile */}

服务器支持 ACP v1 初始化、新会话、文本提示、文本资源、Assistant 与 Tool 更新、权限、取消、配置和命令发现。不声明支持会话加载。图像、音频及二进制资源提示会返回无效参数错误。

仓库的 ACP 一致性检查会按固定版本的上游 schema 验证消息，并用本地模型和 MCP fixture 测试构建后的 SDK。这些检查覆盖已实现的协议范围，但不代表上游认证、不保证支持所有可选 ACP 功能，也不能替代在客户端中测试真实 Provider 认证。
