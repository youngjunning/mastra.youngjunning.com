# 渠道Provider

`ChannelProvider`是平台集成实现的用于将Agent连接到消息传递平台的接口。Provider拥有完整的集成生命周期。这包括使用 OAuth 进行应用程序配置、使用事件处理进行 Webhook 路由、适配器创建和Agent连接以及凭证管理。

在 上注册Provider`Mastra` constructor under `channels`，由您选择的 id 键入。每个Provider的路由都会自动合并到服务器的 API 路由中，并且`initialize()`在 Mastra 启动期间运行。

```typescript title="src/mastra/index.ts"
import { Mastra } from '@mastra/core/mastra'
import { SlackProvider } from '@mastra/slack'

export const mastra = new Mastra({
  channels: {
    slack: new SlackProvider({
      refreshToken: process.env.SLACK_REFRESH_TOKEN!,
      baseUrl: process.env.MASTRA_BASE_URL,
    }),
  },
})
```

提供者的`baseUrl` is the public URL the platform sends webhooks and events to. In production this is your deployed Mastra server URL. For local development, the platform can't reach `http://localhost:4111`, so run a tunnel (such as [cloudflared](https://developers.cloudflare.com/cloudflare-one/connections/connect-networks/) or [ngrok](https://ngrok.com/)）并点`baseUrl`在隧道 URL 处（例如`https://abc123.trycloudflare.com`）以便事件到达您的本地开发流程。

马斯特拉包括[`SlackProvider`](/reference/channels/slack-provider) and [`TelegramProvider`](/reference/channels/telegram-provider) implementations. Build a custom provider by implementing this interface.

## 动态分辨率 {/* #dynamic-resolution */}

而不是静态记录，`channels` also accepts a resolver: an async function returning the current provider map, with a synchronous `getRoutes()` method. Mastra mounts the resolver's routes at construction and resolves providers at runtime, so connections added after boot become usable without a redeploy. The `channels()` helper from `@mastra/connect` returns a resolver backed by the Mastra platform.

```typescript title="src/mastra/index.ts"
import { Mastra } from '@mastra/core/mastra'
import { channels } from '@mastra/connect'

export const mastra = new Mastra({
  channels: await channels({ projectId: process.env.MASTRA_PROJECT_ID! }),
})
```

配置解析器后，调用`resolveChannels()` to get the current provider map. It also works with a static record, where it returns the record directly.

```typescript
const providers = await mastra.resolveChannels()
```

## 访问Provider {/* #accessing-a-provider */}

通过以下方式访问注册Provider`channels` getter, keyed by the id you registered it under. The getter is typed from the constructor config, so `mastra.channels.slack` is the concrete provider with its full method surface.

```typescript
await mastra.channels.slack.configure({ refreshToken })
```

当密钥仅在运行时已知时，请改为通过字符串 id 查找提供程序。`getChannelProvider` takes the concrete type as a generic, and `getChannelProviders` returns every registered provider keyed by id. With a [resolver](#dynamic-resolution), both return the latest resolved snapshot. Use `resolveChannels()` when you need providers that reflect the current platform state.

```typescript
import type { SlackProvider } from '@mastra/slack'

const slack = mastra.getChannelProvider<SlackProvider>('slack')
const all = mastra.getChannelProviders()
```
