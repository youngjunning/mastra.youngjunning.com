# TelegramProvider

`TelegramProvider` 通过 Bot API 将 Mastra Agent 连接到 Telegram Bot。将它注册到 `Mastra.channels` 后，即可管理 Bot 安装、选择 Webhook 或轮询投递、验证 Webhook 密钥、注册命令，并将 Telegram 对话路由到 Agent。

若希望由 Mastra 管理 Bot 的生命周期，请使用 `TelegramProvider`。如果要自行配置底层 Telegram Adapter 和 Webhook，请使用 [`createTelegramAdapter`](/integrations/channels/telegram)，并将它放在 Agent 的 `channels.adapters` 中。

## 使用示例 {/* #usage-example */}

先通过 [BotFather](https://t.me/botfather) 创建 Bot，设置 `TELEGRAM_BOT_TOKEN`，再用公开的基础 URL 注册 Provider，以便通过 Webhook 投递：

```typescript title="src/mastra/index.ts"
import { Agent } from '@mastra/core/agent'
import { Mastra } from '@mastra/core/mastra'
import { TelegramProvider } from '@mastra/telegram'

const supportAgent = new Agent({
  id: 'support',
  name: 'Support agent',
  instructions: 'Help users with product questions.',
  model: 'openai/gpt-5-mini',
})

const telegram = new TelegramProvider({
  baseUrl: 'https://your-app.example.com',
})

export const mastra = new Mastra({
  agents: { supportAgent },
  channels: { telegram },
})

await telegram.connect('support', {
  botToken: process.env.TELEGRAM_BOT_TOKEN,
})
```

省略 `botToken` 时，`connect()` 会创建待完成的安装并返回 BotFather 深层链接，而不会立即激活 Bot。

## 方法 {/* #methods */}

### 安装生命周期 {/* #installation-lifecycle */}

#### `connect(agentId, options)` {/* #connectagentid-options */}

将 Agent 连接到 Telegram Bot。Provider 会调用 `getMe` 验证 BotFather 令牌，准备选定的投递模式和命令，保存安装信息，然后激活 Adapter。

```typescript
const result = await telegram.connect('support', {
  botToken: process.env.TELEGRAM_BOT_TOKEN,
  name: 'Support bot',
  commands: [
    { command: 'help', description: 'Show support options' },
    { command: 'status', description: 'Check service status' },
  ],
})
```

`TelegramConnectOptions` 字段：

<PropertiesTable
  content={[
  {
    name: 'botToken',
    type: 'string',
    isOptional: true,
    description:
      "BotFather 令牌。提供时会立即完成连接；省略时，connect() 返回 BotFather 深层链接和待完成安装 ID。",
  },
  {
    name: 'name',
    type: 'string',
    isOptional: true,
    description: "Bot 的显示名称。默认使用 Bot 的 Telegram 用户名或名字。",
  },
  {
    name: 'commands',
    type: 'TelegramCommand[]',
    isOptional: true,
    description: "为此 Agent 注册的命令。覆盖 Provider 的默认命令。",
  },
]}
/>

返回：`Promise<ChannelConnectResult>`

#### `disconnect(agentId)` {/* #disconnectagentid */}

停止当前传输并删除已存储的安装信息。在 Webhook 模式下，还会移除 Telegram Webhook。

```typescript
await telegram.disconnect('support')
```

返回：`Promise<void>`

#### `listInstallations()` {/* #listinstallations */}

列出已激活和待完成的 Telegram 安装，但不暴露 Bot 或 Webhook 密钥令牌。

```typescript
const installations = await telegram.listInstallations()
```

返回：`Promise<ChannelInstallationInfo[]>`

#### `getInstallation(agentId)` {/* #getinstallationagentid */}

返回 Agent 的完整安装信息，包括敏感的 Bot 和 Webhook 令牌；若不存在安装，则返回 `null`。

```typescript
const installation = await telegram.getInstallation('support')
```

返回：`Promise<TelegramInstallation | null>`

### 配置和状态 {/* #configuration-and-status */}

#### `configure(credentials)` {/* #configurecredentials */}

在运行时更新 Bot API 的源地址或 Webhook 基础 URL。传入 `null` 不会产生效果，因为 Telegram 凭据属于各个 Bot 安装。

```typescript
await telegram.configure({
  baseUrl: 'https://new-app.example.com',
  apiBaseUrl: 'https://api.telegram.org',
})
```

返回：`Promise<void>`

#### `initialize()` {/* #initialize */}

Mastra 启动时会调用此方法：先从存储恢复已激活的安装并重建 Telegram Adapter，再重新连接已注册的 Agent。

```typescript
await telegram.initialize()
```

返回：`Promise<void>`

#### `isConfigured()` {/* #isconfigured */}

返回是否至少存在一个已激活的 Telegram 安装。

```typescript
const configured = telegram.isConfigured()
```

#### `getInfo()` {/* #getinfo */}

返回供 Editor UI 发现频道的元数据，包括连接状态，以及 `botToken` 与 `name` 的连接选项 Schema。

```typescript
const info = telegram.getInfo()
```

返回：`ChannelPlatformInfo`

#### `getAdapter(installationId)` {/* #getadapterinstallationid */}

返回已激活安装对应的实时 `TelegramAdapter`。

```typescript
const adapter = telegram.getAdapter(installationId)
```

返回：`TelegramAdapter | undefined`

#### `getRoutes()` {/* #getroutes */}

返回 Provider 的未认证 `POST /telegram/events/:webhookId` 路由。Mastra 会自动注册该路由。

```typescript
const routes = telegram.getRoutes()
```

返回：`ApiRoute[]`

## 投递模式 {/* #delivery-modes */}

- **`webhook`**：为每个 Bot 在 `/telegram/events/:webhookId` 下注册 Webhook，并验证 `X-Telegram-Bot-Api-Secret-Token` Header。
- **`polling`**：在启动 Telegram 的 `getUpdates` 循环前，移除现有 Webhook。
- **`auto`**：有公开基础 URL 时使用 Webhook，否则使用轮询。

生产环境应使用持久化频道存储，并设置 `encryptionKey` 或 `MASTRA_ENCRYPTION_KEY`，因为内存回退存储无法在重启后保留安装信息。
