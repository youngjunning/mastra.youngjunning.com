# Memory.recall()

`Memory.recall()` 方法从指定线程检索消息，支持分页、筛选选项和语义搜索。

## 使用示例 {/* #usage-example */}

```typescript
const { messages } = await memory.recall({
  threadId: 'thread-123',
  perPage: 20,
})
```

## 信号可见性 {/* #signal-visibility */}

`hideSignals` 只筛选本次调用返回的消息，不影响底层存储或后续模型请求。普通消息仍会返回。此选项不是安全边界，也不会改变 `ifActive`、`ifIdle` 或 `transient` 等信号投递和持久化策略。

### 默认值与优先级 {/* #defaults-and-precedence */}

| `hideSignals` | `includeSystemReminders` | 返回的信号 |
| - | - | - |
| 未提供 | 未提供或 `false` | 沿用隐藏提醒的历史行为 |
| 未提供 | `true` | 所有信号 |
| `false` 或 `[]` | 任意值 | 所有信号 |
| `true` | 任意值 | 不返回任何已识别信号，包括旧版提醒 |
| 非空列表 | 任意值 | 除匹配类型外的所有信号 |

与 [Agent 流](/reference/streaming/agents/stream)不同，为保持兼容性，recall 默认仍隐藏提醒。已弃用的 `includeSystemReminders` 仅在省略 `hideSignals` 时生效。

```typescript
const all = await memory.recall({
  threadId: 'thread-123',
  hideSignals: false,
})

const withoutSignals = await memory.recall({
  threadId: 'thread-123',
  hideSignals: true,
})

const withoutReminders = await memory.recall({
  threadId: 'thread-123',
  hideSignals: ['reactive', 'system-reminder'],
})
```

### 存储类型与旧版消息 {/* #stored-types-and-legacy-messages */}

Recall 匹配的是**存储中的精确类型**，不会对别名做归一化。例如，`['reactive']` 不会排除编码为 `system-reminder` 的记录，`['user']` 也不会排除编码为 `user-message` 的记录。现代流和订阅则会对这些别名做归一化。若要跨这些 API 排除两种提醒表示，请使用 `['reactive', 'system-reminder']`。

`data-signal` 或 `data-user-message` 片段中的已识别类型，优先于信号元数据和旧版提醒标记。signal-role 消息也可以在 `content.metadata.signal.type` 中编码类型。未知类型或格式错误的信号片段不会匹配排除条件，即使设置了 `hideSignals: true` 也一样。

如果不存在已识别的编码类型，那么按现有旧版提醒规则分类的消息会算作 `system-reminder`，而不是 `reactive`。这些规则包括：用户消息带有 `systemReminder` 或 `dynamicAgentsMdReminder` 元数据，或首个文本片段以 `<system-reminder` 开头。此类记录在使用 `['reactive']` 时仍可见，使用 `['system-reminder']` 时则会排除。

### 分页与 API 范围 {/* #pagination-and-api-scope */}

筛选在存储查询和分页之后执行。因此，某页可能少于 `perPage` 条消息，甚至为空，但 `total`、`hasMore` 和页面偏移量不变。总数仍描述底层查询的结果，而非筛选后的消息。

此选项适用于进程内的 `memory.recall()` 调用。本版本的 HTTP 和 client-js 契约尚未公开 `hideSignals`。

## 元数据筛选 {/* #metadata-filtering */}

使用 `filter.metadata` 匹配存储在消息上的浅层标量元数据：

```typescript
const { messages } = await memory.recall({
  threadId: 'thread-123',
  filter: {
    metadata: {
      category: 'billing',
      escalated: true,
      priority: 2,
      archivedAt: null,
    },
  },
})
```

所有元数据条件按 AND 语义组合。消息必须以相同类型精确匹配每个键和值。`null` 只匹配显式设为 `null` 的元数据，不匹配缺失的键。

元数据筛选只支持浅层标量值：`string`、有限的 `number`、`boolean` 和 `null`。不支持嵌套对象、数组、`NaN` 或无穷大。元数据键必须以字母或下划线开头，且只能包含字母、数字或下划线，最长 128 个字符。`__proto__`、`constructor` 和 `prototype` 等保留的原型键不可使用。性能取决于存储后端；任意元数据筛选可能需要扫描候选消息，因此尽可能用 `threadId`、`resourceId` 或 `dateRange` 缩小查询范围。

## 扩展示例 {/* #extended-usage-example */}

```typescript title="src/test-memory.ts"
import { mastra } from './mastra'

const agent = mastra.getAgent('agent')
const memory = await agent.getMemory()

// Retrieve messages with pagination
const { messages } = await memory!.recall({
  threadId: 'thread-123',
  perPage: 50,
  vectorSearchString: 'What messages are there?',
  include: [
    {
      id: 'msg-123',
    },
    {
      id: 'msg-456',
      withPreviousMessages: 3,
      withNextMessages: 1,
    },
  ],
  threadConfig: {
    semanticRecall: true,
  },
})

console.log(messages) // MastraDBMessage[]

// Fetch all messages without pagination
const allMessages = await memory!.recall({
  threadId: 'thread-123',
  perPage: false, // Fetch all
})

// Convert to AI SDK format if needed
import { toAISdkV5Messages } from '@mastra/ai-sdk/ui'
const uiMessages = toAISdkV5Messages(messages)
```
