# 内存.settled()

这`.settled()`方法解决一旦后台工作`Memory`实例启动已完成。Agent运行返回后，一些内存工作仍在继续：

* 观察内存周期（缓冲观察和反射，包括它们产生的嵌套Agent运行）
* 矢量清理开始于`deleteThread()` and `deleteMessages()`

在关闭您拥有的存储连接之前等待此方法。如果没有它，后台语句可以针对关闭的连接运行。当其他线程仍在使用存储时，作用域调用可以返回，因此调用`settled()` without a scope before closing shared storage.

该方法是在内存基类上声明的，因此它也可以在`MastraMemory` instance returned by `agent.getMemory()`. The `scope` parameter is only on `Memory` from `@mastra/memory`.

## 使用示例 {/* #usage-example */}

```typescript
await agent.generate('Hello', {
  memory: { thread: 'thread-123', resource: 'user-456' },
})

await memory.settled()
await store.close()
```

## 等待一场对话 {/* #wait-for-one-conversation */}

在繁忙的服务器上，等待所有工作可能需要很长时间，因为其他线程不断开始新工作。传递一个范围来等待更少。当观察内存使用线程作用域时，下面的调用等待`thread-123` only. When it uses resource scope, it waits for every thread under `user-456`:

```typescript
await memory.settled({ threadId: 'thread-123', resourceId: 'user-456' })
```

## 扩展使用示例 {/* #extended-usage-example */}

测试套件和短期进程是最常见需要此功能的地方，因为它们在运行完成后立即关闭存储。

```typescript title="src/test-memory.ts"
import { Memory } from '@mastra/memory'
import { PostgresStore } from '@mastra/pg'

const store = new PostgresStore({ connectionString })
const memory = new Memory({ storage: store })

// ... run your agent ...

// Wait for observational memory and vector cleanup to finish before closing.
await memory.settled()
await store.close()
```

<Callout type="note">
  `settled()`加入您调用时已开始的工作，以及任何
  工作排队的工作。这并不妨碍之后新工作的开始，
  因此，一旦您关心的Agent运行返回，请致电它。
</Callout>
