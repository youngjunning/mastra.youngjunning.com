# Memory.settled()

`.settled()` 方法会在该 `Memory` 实例启动的后台工作完成后兑现。有些内存工作会在 Agent 运行返回后继续执行：

- 观察式内存周期（缓冲的观察和反思，以及它们启动的嵌套 Agent 运行）
- 由 `deleteThread()` 和 `deleteMessages()` 启动的向量清理

关闭由你管理的存储连接前，请先等待此方法完成；否则后台语句可能仍会访问已关闭的连接。指定作用域的调用返回时，其他线程可能仍在使用存储，因此关闭共享存储前应调用不带作用域的 `settled()`。

此方法声明在内存基类上，因此也适用于 `MastraMemory` 实例（由 `agent.getMemory()` 返回）。`scope` 参数仅在 `Memory`（来自 `@mastra/memory`）上提供。

## 使用示例 {/* #usage-example */}

```typescript
await agent.generate('Hello', {
  memory: { thread: 'thread-123', resource: 'user-456' },
})

await memory.settled()
await store.close()
```

## 等待一场对话 {/* #wait-for-one-conversation */}

在繁忙的服务器上，其他线程会不断启动新工作，因此等待全部工作可能耗时很久。可传入作用域缩小等待范围。如果观察式内存使用线程作用域，下面的调用只等待 `thread-123`；如果使用资源作用域，则等待 `user-456` 下的所有线程。

```typescript
await memory.settled({ threadId: 'thread-123', resourceId: 'user-456' })
```

## 扩展使用示例 {/* #extended-usage-example */}

测试套件和短生命周期进程最常需要此方法，因为它们通常在运行结束后立即关闭存储。

```typescript title="src/test-memory.ts"
import { Memory } from '@mastra/memory'
import { PostgresStore } from '@mastra/pg'

const store = new PostgresStore({ connectionString })
const memory = new Memory({ storage: store })

// ... run your agent ...

// Wait for observational memory and vector cleanup to finish before closing.
await memory.settled()
await store.close()
```

<Callout type="note">
  `settled()` 会等待调用时已经开始的工作，以及这些工作随后排入队列的
  工作。它不会阻止之后启动的新工作，因此应在相关 Agent 运行返回后调用。
</Callout>
