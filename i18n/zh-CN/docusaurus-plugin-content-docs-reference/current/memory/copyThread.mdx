# Memory.copyThread()

`.copyThread()` 方法将现有线程及其消息复制到新线程。它与 [`cloneThread()`](/reference/memory/cloneThread) 一样，会复制工作记忆、观察记忆和语义召回嵌入，但不会返回复制后的消息。使用 `@mastra/libsql` 或 `@mastra/pg` 时，数据库会在内部复制数据行，因此复制过程不会将消息内容加载到 Node.js 进程中。仍需读取内容的情况请参阅[内存使用情况](#memory-usage)。

如果只需要新线程 ID，例如为子 Agent 创建对话分支，请使用 `copyThread()`。如果还需要在响应中获取复制后的消息，请使用 `cloneThread()`。

## 使用示例 {/* #usage-example */}

```typescript
import { Memory } from '@mastra/memory'
import { LibSQLStore } from '@mastra/libsql'

const memory = new Memory({
  storage: new LibSQLStore({ id: 'memory-store', url: 'file:./memory.db' }),
})

const { thread, messageIdMap } = await memory.copyThread({
  sourceThreadId: 'original-thread-123',
})
```

## 内存使用情况 {/* #memory-usage */}

`copyThread()` 专为大型线程设计：

* `@mastra/libsql` 和 `@mastra/pg` 使用 `INSERT … SELECT` 语句复制消息，因此复制过程不会将消息内容读入进程。
* 其他存储适配器通过自身现有的 `cloneThread()` 实现复制消息，可能会读取并重新写入每条消息。`copyThread()` 在返回前仍会丢弃消息内容。
* 启用语义召回后，会读回复制的消息以生成嵌入。系统按目标消息 ID 每批处理 100 条消息，因此内存中一次只保留一批。

`cloneThread()` 会调用 `copyThread()`，随后读回新线程中的消息，填充 `clonedMessages`。
