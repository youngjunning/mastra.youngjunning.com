# 内存.copyThread()

这`.copyThread()`方法将现有线程及其消息复制到新线程。它的行为就像[`cloneThread()`](/reference/memory/cloneThread)，包括工作记忆、观察记忆和语义回忆嵌入，但它不返回复制的消息。在`@mastra/libsql`和`@mastra/pg`这些行被复制到数据库内部，因此副本本身永远不会将消息内容加载到 Node.js 进程中。看[内存使用情况](#memory-usage)对于仍然读取内容的情况。

使用`copyThread()` when you only need the new thread ID, such as forking a conversation for a subagent. Use `cloneThread()` when you need the copied messages in the response.

## 使用示例 {/* #usage-example */}

```typescript
import { Memory } from '@mastra/memory'
import { LibSQLStore } from '@mastra/libsql'

const memory = new Memory({
  storage: new LibSQLStore({ id: 'memory-store', url: 'file:./memory.db' }),
})

const { thread, messageIdMap } = await memory.copyThread({
  sourceThreadId: 'original-thread-123',
})
```

## 内存使用情况 {/* #memory-usage */}

`copyThread()`专为大螺纹设计：

* `@mastra/libsql`和`@mastra/pg` copy messages with `INSERT … SELECT` statements, so the copy step doesn't read message content into the process.
* 其他存储适配器通过该适配器的现有存储适配器复制消息`cloneThread()` implementation, which may read and re-write each message. `copyThread()` still discards the payloads before returning.
* 当启用语义召回时，复制的消息将被读回以生成嵌入。这种情况按目标消息 ID 以 100 为一批进行，因此内存中一次仅保存一批。

`cloneThread()`来电`copyThread()` and then reads the new thread's messages back to populate `clonedMessages`.
