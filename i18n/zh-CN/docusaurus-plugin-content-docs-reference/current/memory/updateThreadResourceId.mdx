# Memory.updateThreadResourceId()

这`.updateThreadResourceId()`方法通过重新分配现有线程的所有权将其所有权转移到不同的资源`resourceId`。它更新线程及其所有关联消息，以便它们属于新资源，同时保留线程的原始消息`createdAt`时间戳。这对于将私有线程移动到共享Workspace等场景非常有用。

## 使用示例 {/* #usage-example */}

```typescript
import { Memory } from '@mastra/memory'
import { LibSQLStore } from '@mastra/libsql'

const memory = new Memory({
  storage: new LibSQLStore({ id: 'memory-store', url: 'file:./memory.db' }),
})

const thread = await memory.updateThreadResourceId({
  threadId: 'thread-123',
  resourceId: 'new-resource-456',
})
```

## 行为 {/* #behavior */}

* 线程的`resourceId` is reassigned to the new resource, and all of its messages are updated to reference the new resource.
* 该线程的原始`createdAt` timestamp is preserved. The `updatedAt` timestamp is refreshed.
* 如果线程已经属于目标资源，则该方法是无操作并返回现有线程。
* 如果线程不存在，该方法将引发错误。

## 安全 {/* #security */}

线程所有权转移会更改线程所属的资源，从而绕过正常的每个资源所有权检查。 HTTP 端点（`POST /memory/threads/:threadId/transfer`) is only available to privileged, non-resource-scoped callers. Requests made with a resolved resource scope are rejected, and when `server.auth` is configured without an FGA provider the endpoint also rejects unscoped requests rather than treating them as implicitly privileged. Perform transfers from a trusted service context rather than exposing this operation directly to end users.

与所有内存突变（删除线程、列出消息、写入工作内存）一样，该端点在根本没有配置身份验证的服务器上未经身份验证。配置`server.auth` (and, for per-resource enforcement, an FGA provider) before exposing the memory API to untrusted callers.
