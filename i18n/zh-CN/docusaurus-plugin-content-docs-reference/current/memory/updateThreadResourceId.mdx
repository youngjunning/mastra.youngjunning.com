# Memory.updateThreadResourceId()

`.updateThreadResourceId()` 通过重新分配现有线程的 `resourceId`，将其所有权转移给另一个资源。它会更新线程及其所有关联消息，使它们归属新资源，同时保留线程原有的 `createdAt` 时间戳。此方法适用于将私人线程移入共享 Workspace 等场景。

## 使用示例 {/* #usage-example */}

```typescript
import { Memory } from '@mastra/memory'
import { LibSQLStore } from '@mastra/libsql'

const memory = new Memory({
  storage: new LibSQLStore({ id: 'memory-store', url: 'file:./memory.db' }),
})

const thread = await memory.updateThreadResourceId({
  threadId: 'thread-123',
  resourceId: 'new-resource-456',
})
```

## 行为 {/* #behavior */}

- 线程的 `resourceId` 会被重新分配给新资源，其所有消息也会更新为引用新资源。
- 保留线程原有的 `createdAt` 时间戳，并刷新 `updatedAt` 时间戳。
- 如果线程已属于目标资源，方法不会执行更新，而是返回现有线程。
- 如果线程不存在，方法会抛出错误。

## 安全性 {/* #security */}

转移线程所有权会改变线程归属的资源，并绕过常规的按资源所有权检查。HTTP 端点（`POST /memory/threads/:threadId/transfer`）仅供不受资源范围约束的特权调用方使用。已解析出资源范围的请求会被拒绝；如果配置了 `server.auth`，但没有 FGA Provider，该端点也会拒绝无资源范围的请求，而不会默认将其视为特权请求。应在受信任的服务上下文中执行转移，不要直接向最终用户开放此操作。

与所有 Memory 操作（如删除线程、列出消息、写入工作记忆）一样，如果服务器完全未配置身份验证，此端点也没有身份验证保护。在向不受信任的调用方开放 Memory API 前，应配置 `server.auth`；如需按资源实施访问控制，还应配置 FGA Provider。
