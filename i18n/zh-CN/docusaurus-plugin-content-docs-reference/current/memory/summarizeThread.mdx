# Memory.summarizeThread()

这`.summarizeThread()`方法一次性总结了线程的对话。它从存储中加载线程的消息，并使用与支持相同的观察者管道来提取它们[观察记忆](/reference/memory/observational-memory)：作为独立调用，没有附加到Agent的观察记忆。

消息从最新的开始逐页加载，边界为`lastMessages` and `maxInputTokens`, so summarizing a long thread doesn't read its entire history from storage.

没有任何内容被写回到内存中。摘要和提取的值将返回给您（以及每个提取器的`onExtracted` hook), so you decide where they go: for example your own database.

当会话结束并且您想要整个对话的摘要或结构化提取（例如挂断时的语音呼叫）时，请使用此功能。对于您已有的消息（无需从线程加载它们），请使用独立的[`summarizeConversation()`](/reference/memory/summarizeConversation) function instead. It takes the same options with `messages` in place of `threadId`.

## 使用示例 {/* #usage-example */}

```typescript
const result = await memory.summarizeThread({
  model: '__GATEWAY_OPENAI_MODEL_LUNA__',
  threadId: 'thread-123',
  instructions: 'Summarize this voicemail call for the business owner.',
})
```

## 扩展使用示例 {/* #extended-usage-example */}

以下示例总结了已完成的语音呼叫并将结构化记录存储在应用程序自己的数据库中：

```typescript title="src/call-summary.ts"
import { Extractor } from '@mastra/memory'
import { z } from 'zod'
import { memory } from './mastra/memory'
import { callRecords } from './db'

const callSummary = new Extractor({
  name: 'call-summary',
  instructions: 'Return a concise summary of the call.',
  schema: z.object({
    summary: z.string(),
    sentiment: z.enum(['positive', 'neutral', 'negative']),
    requestedServices: z.array(z.string()),
  }),
  metadataKeyPath: false, // don't persist into memory metadata — the hook owns storage
  onExtracted: async ({ current, threadId, resourceId }) => {
    await callRecords.upsert({ callId: threadId, callerId: resourceId, record: current })
  },
})

export async function onCallEnd(threadId: string, resourceId: string) {
  await memory.summarizeThread({
    model: '__GATEWAY_OPENAI_MODEL_LUNA__',
    threadId,
    resourceId,
    instructions: 'Summarize this voicemail call for the business owner.',
    extract: [callSummary],
  })
}
```
