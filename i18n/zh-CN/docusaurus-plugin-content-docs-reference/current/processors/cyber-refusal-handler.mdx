# CyberRefusalHandler

当 Provider 的网络安全防护机制拒绝某个步骤时，`CyberRefusalHandler` 会重试该步骤一次。在 Agent 长时间运行的过程中，这类防护机制也可能拒绝普通的编码任务。许多此类拒绝属于误报，要求模型继续通常能让任务继续推进。如果重试后仍被拒绝，拒绝结果会保留，并以正常错误或停止的形式呈现。

该处理器支持两个 Provider，它们报告拒绝的方式不同：

- **OpenAI**：模型调用因 `cyber_policy` 错误（"This content was flagged for possible cybersecurity risk"）而失败。无论拒绝以 HTTP 错误还是流失败的形式返回，处理器都会匹配错误代码或错误消息。此类拒绝由 `processAPIError` 处理，该方法仅对 `errorProcessors` 中的处理器运行。
- **Anthropic**：步骤结束时，Provider 元数据中的结束原因为 `content-filter`，且 `stopDetails.category: 'cyber'`。此类拒绝由 `processOutputStep` 处理，该方法对 `outputProcessors` 中的处理器运行。重试前会回滚被拒绝的步骤，包括已生成的部分文本。

## 工作原理 {/* #how-it-works */}

对于 OpenAI 的拒绝：

1. 模型调用因 `cyber_policy` 错误而失败
1. `CyberRefusalHandler` 检查这是否是该步骤的首次重试
1. 发送 `system-reminder` 信号，其内容为 `continue`
1. 返回 `{ retry: true }`，然后再次调用同一个模型

对于 Anthropic 的拒绝：

1. 步骤因 `cyber` 分类器的拒绝而结束
1. `CyberRefusalHandler` 检查这是否是该步骤的首次重试
1. 调用 `abort('continue', { retry: true })`
1. 回滚被拒绝的步骤，将 `continue` 作为系统提醒追加后再次调用模型

每个步骤最多重试一次。步骤成功后，重试计数会重置，因此同一次运行中后续步骤若遭拒绝，仍可重试一次。

## 使用示例 {/* #usage-example */}

将 `CyberRefusalHandler` 同时添加到 `errorProcessors` 和 `outputProcessors`，以处理两个 Provider 的拒绝：

```typescript title="src/mastra/agents/coding-agent.ts"
import { Agent } from '@mastra/core/agent'
import { CyberRefusalHandler, StreamErrorRetryProcessor } from '@mastra/core/processors'

export const agent = new Agent({
  id: 'coding-agent',
  name: 'Coding Agent',
  instructions: 'You are a coding agent.',
  model: '__GATEWAY_OPENAI_MODEL__',
  errorProcessors: [new CyberRefusalHandler(), new StreamErrorRetryProcessor()],
  outputProcessors: [new CyberRefusalHandler()],
  maxProcessorRetries: 3,
})
```

在 `errorProcessors` 中，将其放在 [`StreamErrorRetryProcessor`](/reference/processors/stream-error-retry-processor) 之前。错误处理器遇到第一个返回 `{ retry: true }` 的处理器后就会停止；如果先执行通用重试处理器，被拒绝的请求将原样重发。

输出步骤的重试会计入 `maxProcessorRetries`，而且与错误处理路径不同，这里没有隐式默认值。无论 Agent 是否配置了 `errorProcessors`，都应显式设置该值，否则 Anthropic 的重试会被视为中止。

[`createCodingAgent()`](/reference/coding-agent/create-coding-agent) 默认会在两个处理器列表中加入该处理器。
