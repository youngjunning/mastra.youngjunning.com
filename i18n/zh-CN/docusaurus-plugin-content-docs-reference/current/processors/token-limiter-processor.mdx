# 令牌限制器处理器

这`TokenLimiterProcessor`限制消息中的令牌数量。根据`trimMode`，它充当提示处理器、输入处理器和输出处理器：

* **提示处理器** (`processLLMRequest`): In the default `best-fit` and `contiguous`修剪模式，在每次模型调用之前、Agent循环的每个步骤中强制执行提供程序提示上的输入预算。提示是在较早的提示处理器（例如`ToolCallFilter`）对其进行了转换，因此仅计算实际到达模型的令牌。Tool调用和Tool结果消息被分组，以便它们一起保留或删除，并且修剪是暂时的：存储的消息永远不会被修改。
* **输入处理器** (`processInput`): In `memory-only` trim mode, filters historical messages to fit within the context window before the agentic loop starts, prioritizing recent messages
* **输出处理器**：通过流式或非流式限制生成的响应令牌，并使用可配置的策略来处理超出的限制

## 使用示例 {/* #usage-example */}

```typescript
import { TokenLimiterProcessor } from '@mastra/core/processors'

const processor = new TokenLimiterProcessor({
  limit: 1000,
  strategy: 'truncate',
  countMode: 'cumulative',
})
```

## 输出流行为 {/* #output-stream-behavior */}

作为输出处理器，只有携带生成输出的部分才算作限制：`text-delta` and `object`. Lifecycle parts (such as `step-start`), reasoning deltas, response metadata, and tool parts (`tool-call`, `tool-result`) are neither counted nor withheld, so tool calls always reach the agentic loop and get executed.

使用默认的`truncate` strategy, the first time output is withheld the processor emits a transient `data-token-limit-reached` part on the stream:

```typescript oxfmt:false
for await (const part of stream.fullStream) {
  if (part.type === 'data-token-limit-reached') {
    console.log('output truncated at', part.data.limit, 'tokens')
  }
}
```

## 媒体令牌计数 {/* #media-token-counting */}

图像和文件附件是估计的而不是标记化的，包括`file` message parts and tool results shaped like `{ data, mediaType }`. Images use a flat per-image estimate; other media uses decoded byte size, while remote URLs and provider file ids use a flat fallback because their size isn't known locally. Encoded payloads such as base64 data are never counted as text, avoiding an inflated count that could truncate history unnecessarily.

## 错误行为 {/* #error-behavior */}

当修剪输入时，`TokenLimiterProcessor` throws a `TripWire` error in the following cases:

* **空消息**：如果没有要处理的非系统消息，则会抛出 TripWire，因为您无法发送没有消息的 LLM 请求。
* **系统消息超出限制**：如果单独的系统消息超出了令牌限制，则会引发 TripWire，因为您无法发送仅包含系统消息而没有用户/助理消息的 LLM 请求。
* **没有适合的消息**：如果没有消息符合剩余令牌预算，则会抛出 TripWire，因为您无法发送没有消息的 LLM 请求。

```typescript
import { TripWire } from '@mastra/core/agent'

try {
  await agent.generate('Hello')
} catch (error) {
  if (error instanceof TripWire) {
    console.log('Token limit error:', error.message)
  }
}
```

## 扩展使用示例 {/* #extended-usage-example */}

### 作为输入处理器（限制上下文窗口） {/* #as-an-input-processor-limit-context-window */}

使用`inputProcessors` to limit historical messages sent to the model, which helps stay within context window limits:

```typescript title="src/mastra/agents/context-limited-agent.ts"
import { Agent } from '@mastra/core/agent'
import { Memory } from '@mastra/memory'
import { TokenLimiterProcessor } from '@mastra/core/processors'

export const agent = new Agent({
  id: 'context-limited-agent',
  name: 'context-limited-agent',
  instructions: 'You are a helpful assistant',
  model: '__GATEWAY_OPENAI_MODEL__',
  memory: new Memory({/* ... */}),
  inputProcessors: [
    new TokenLimiterProcessor({ limit: 4000 }), // Limits historical messages to ~4000 tokens
  ],
})
```

### 作为每步处理器（限制多步代币增长） {/* #as-a-per-step-processor-limit-multi-step-token-growth */}

当Agent跨多个步骤使用Tool时（例如`maxSteps > 1`), each step accumulates conversation history from all previous steps. `TokenLimiterProcessor` applies its limit at every step, measuring the prompt that's about to be sent after any earlier prompt processors have run. To count the prompt the model actually receives, register the limiter after prompt-shrinking processors such as `ToolCallFilter`:

```typescript title="src/mastra/agents/multi-step-agent.ts"
import { Agent } from '@mastra/core/agent'
import { TokenLimiterProcessor } from '@mastra/core/processors'

export const agent = new Agent({
  id: 'multi-step-agent',
  name: 'multi-step-agent',
  instructions: 'You are a helpful research assistant with access to tools',
  model: '__GATEWAY_OPENAI_MODEL__',
  inputProcessors: [
    new TokenLimiterProcessor({ limit: 8000 }), // Applied at every step
  ],
})

// Each tool call step will be limited to ~8000 input tokens
const result = await agent.generate('Research this topic using your tools', {
  maxSteps: 10,
})
```

处理器Workflow程不运行`processLLMRequest`, so a `TokenLimiterProcessor` inside a processor workflow trims stored messages in `processInputStep`, before prompt processors such as `ToolCallFilter` remove anything from the request. To count the prompt the model receives, add the limiter directly to `inputProcessors`.

### 作为输出处理器（限制响应长度） {/* #as-an-output-processor-limit-response-length */}

使用`outputProcessors` to limit the length of generated responses:

```typescript title="src/mastra/agents/response-limited-agent.ts"
import { Agent } from '@mastra/core/agent'
import { TokenLimiterProcessor } from '@mastra/core/processors'

export const agent = new Agent({
  id: 'response-limited-agent',
  name: 'response-limited-agent',
  instructions: 'You are a helpful assistant',
  model: '__GATEWAY_OPENAI_MODEL__',
  outputProcessors: [
    new TokenLimiterProcessor({
      limit: 1000,
      strategy: 'truncate',
      countMode: 'cumulative',
    }),
  ],
})
```
