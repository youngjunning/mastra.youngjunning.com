# PrefillErrorHandler

`PrefillErrorHandler` 是处理助手回复预填充错误的**错误处理器**。当对话以助手消息结尾，而模型将请求理解为预填充助手回复并拒绝处理时，就会出现这种错误。

检测到此错误后，处理器会发送隐藏的 `system-reminder` 信号，内容为 `continue`，并指示重试。该提醒会作为信号元数据持久化，以便重建重试过程和保留原始历史记录；面向 UI 的标准消息转换则会将其隐藏。

Mastra 默认将此处理器加入每个 Agent 的 `errorProcessors`，位于 `ProviderHistoryCompat` 之后、`StreamErrorRetryProcessor` 之前。它只在第一次重试时起作用，因此无需配置。如需调整其行为，可提供自己的实例。列表中已有的处理器会保留；只有列表中不存在相同 `id` 时，才会加入默认实例。

## 工作原理 {/* #how-it-works */}

1. LLM API 调用失败，并返回已知的助手回复预填充拒绝消息
2. `PrefillErrorHandler` 检查当前是否为第一次重试
3. 它发送隐藏的 `system-reminder` 信号，内容为 `continue`
4. 它返回 `{ retry: true }`，指示使用修改后的消息重试 LLM 调用

处理器直接根据 API 的拒绝响应采取行动，不再重新检查对话当前是否以助手消息结尾。因此，即使上游已转换末尾消息的结构，只要模型提供方仍因预填充语义拒绝请求，处理器也能进行恢复。

## 使用示例 {/* #usage-example */}

如需调整预填充错误的恢复行为或明确其作用范围，请提供自己的实例。此时不会再加入默认的 `PrefillErrorHandler`：

```typescript title="src/mastra/agents/my-agent.ts"
import { Agent } from '@mastra/core/agent'
import { PrefillErrorHandler } from '@mastra/core/processors'

export const agent = new Agent({
  id: 'my-agent',
  name: 'my-agent',
  instructions: 'You are a helpful assistant.',
  model: '__GATEWAY_ANTHROPIC_MODEL_OPUS__',
  errorProcessors: [new PrefillErrorHandler()],
})
```

如需自定义恢复行为，可以提供实现了 `processAPIError` 方法的错误处理器：

```typescript title="src/mastra/agents/custom-error-handling.ts"
import { Agent } from '@mastra/core/agent'
import type { Processor } from '@mastra/core/processors'

const customErrorHandler: Processor = {
  id: 'custom-prefill-error-handler',
  processAPIError({ error, messageList, retryCount }) {
    // Your custom logic here
  },
}

export const agent = new Agent({
  id: 'my-agent',
  name: 'my-agent',
  instructions: 'You are a helpful assistant.',
  model: '__GATEWAY_ANTHROPIC_MODEL_OPUS__',
  errorProcessors: [customErrorHandler],
})
```
