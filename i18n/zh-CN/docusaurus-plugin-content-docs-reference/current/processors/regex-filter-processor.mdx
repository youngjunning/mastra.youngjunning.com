# RegexFilterProcessor

`RegexFilterProcessor` 使用正则表达式匹配来过滤、脱敏或阻止 Agent 消息中的内容，不会调用 LLM。

它支持针对常见模式（PII、密钥、URL）的内置预设，也支持自定义正则表达式规则。可用于输入、输出或两个阶段。

## 使用示例 {/* #usage-example */}

阻止输入消息中的 PII：

```typescript
import { RegexFilterProcessor } from '@mastra/core/processors'

const filter = new RegexFilterProcessor({
  presets: ['pii'],
  strategy: 'block',
  phase: 'input',
})
```

对输出中的密钥进行脱敏：

```typescript
import { RegexFilterProcessor } from '@mastra/core/processors'

const filter = new RegexFilterProcessor({
  presets: ['secrets'],
  strategy: 'redact',
  phase: 'output',
})
```

自定义规则：

```typescript
import { RegexFilterProcessor } from '@mastra/core/processors'

const filter = new RegexFilterProcessor({
  rules: [{ name: 'internal-id', pattern: /INTERNAL-\d{6}/g, replacement: '[INTERNAL_ID]' }],
  strategy: 'redact',
})
```

对于匹配内容较长的自定义规则，可以增大流式处理时保留的尾部窗口（例如固定长度的密钥，或
只有在结束分隔符到达后才能匹配的值）：

```typescript
import { RegexFilterProcessor } from '@mastra/core/processors'

const filter = new RegexFilterProcessor({
  rules: [
    {
      name: 'armored-key',
      pattern: /-----BEGIN KEY-----[A-Z]+-----END KEY-----/g,
      replacement: '[KEY]',
    },
  ],
  strategy: 'redact',
  streamCarryoverSize: 256,
})
```

将处理器挂载到 Agent：

```typescript
import { Agent } from '@mastra/core/agent'
import { RegexFilterProcessor } from '@mastra/core/processors'

const agent = new Agent({
  id: 'my-agent',
  name: 'my-agent',
  model: '__GATEWAY_OPENAI_MODEL_LUNA__',
  inputProcessors: [
    new RegexFilterProcessor({
      presets: ['pii', 'secrets'],
      strategy: 'block',
    }),
  ],
})
```

## 错误行为 {/* #error-behavior */}

使用默认的 `block` 策略时，只要有任何模式匹配，`RegexFilterProcessor` 就会抛出 `retry: false` 的 `TripWire` 错误。TripWire 元数据包含：

* `processorId`: `'regex-filter'`
* `matches`：匹配对象数组，字段包括 `rule`、`match`（已脱敏为 `'[REDACTED_MATCH]'`）和 `index`
* `strategy`: `'block'`

## 内置预设 {/* #built-in-presets */}

| 预设 | 匹配模式 | 默认替换文本 |
| - | - | - |
| `pii` | 电子邮件地址、电话号码、美国社会安全号码、信用卡号 | `[EMAIL]`、`[PHONE]`、`[SSN]`、`[CREDIT_CARD]` |
| `secrets` | API 密钥、Bearer Token、AWS 访问密钥 | `[API_KEY]`、`[BEARER_TOKEN]`、`[AWS_KEY]` |
| `urls` | HTTP/HTTPS URL | `[URL]` |

## 脱敏行为 {/* #redaction-behavior */}

每条规则独立匹配，因此两条规则可能匹配同一段文本。例如，没有分隔符的卡号可能同时匹配 `phone` 和 `credit-card`。重叠的匹配会合并为一个区域，并使用最长匹配对应的替换文本替换一次。

```typescript
const filter = new RegexFilterProcessor({
  presets: ['pii'],
  strategy: 'redact',
})

// "Charge 4111111111111111 today" becomes "Charge [CREDIT_CARD] today"
```

对于单独的匹配，替换字符串可以用 `$1` 或 `$&` 引用捕获组。多个匹配合并为一个区域时，替换字符串会原样插入。规则使用后顾或前瞻来匹配周围文本时也是如此；无论哪种情况，整个区域都会脱敏。

## 脱敏报告 {/* #redaction-reporting */}

由于 `redact` 策略会直接改写文本，下游代码无法判断改动了什么。可通过 `onViolation` 记录每条被脱敏的消息、消息片段和流式数据块的改动；偏移量相对于对应文本计算。异步回调会被等待，回调错误则会被捕获，因此审计接收端不可用不会导致请求失败。

```typescript
import { RegexFilterProcessor, type RegexRedactionDetail } from '@mastra/core/processors'

const filter = new RegexFilterProcessor({
  presets: ['pii'],
  strategy: 'redact',
})

filter.onViolation = async ({ detail }) => {
  const redaction = detail as RegexRedactionDetail

  for (const entry of redaction.redactions) {
    await auditLog.write({
      phase: redaction.phase,
      messageId: redaction.messageId,
      rule: entry.rule,
      offset: entry.index,
      length: entry.length,
    })
  }
}
```

回调会被等待；在 `processOutputStream` 中，每个包含匹配内容的数据块都会触发回调。请让回调快速完成，或将工作交给队列，避免缓慢的审计接收端阻塞流式响应。未设置回调时，`redact` 路径仍是同步的。

`block` 策略也通过同一回调报告。处理器运行器捕获 `TripWire` 时才调用该回调，因此此时的 `detail` 包含[错误行为](#error-behavior)中描述的 TripWire 元数据，而不是下面的结构。
