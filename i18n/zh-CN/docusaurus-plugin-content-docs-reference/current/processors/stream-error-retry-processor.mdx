# StreamErrorRetryProcessor

`StreamErrorRetryProcessor` 是一种**错误处理器**，用于重试暂时性的 LLM API 和流式传输故障。它内置了对 OpenAI Responses 流错误的匹配规则，也支持添加匹配器来识别其他 Provider 特有的错误格式。

Mastra 默认会将此处理器加入每个 Agent 的 `errorProcessors`，排在 `ProviderHistoryCompat`、`PrefillErrorHandler` 和 `UnsupportedFileHandler` 之后，位于最后。这样，负责修复请求的处理器可以先尝试修复，再由此处理器原样重试。默认实例设置 `maxRetries: 2`，除内置匹配规则外还包含连接重置匹配器；它不会重试未知错误，也不会再次发送修复处理器未能解决的错误请求（HTTP 400）。如需调整策略，可在 `errorProcessors` 中提供自己的实例。只有列表中缺少相同 `id` 时，Mastra 才会加入默认实例，因此你提供的实例会替代默认实例。

## 使用示例 {/* #usage-example */}

配置 `StreamErrorRetryProcessor`。使用相同的 `id` 时，不会再加入默认实例：

```typescript title="src/mastra/agents/openai-agent.ts"
import { Agent } from '@mastra/core/agent'
import { StreamErrorRetryProcessor } from '@mastra/core/processors'

export const agent = new Agent({
  id: 'openai-agent',
  name: 'openai-agent',
  instructions: 'You are a helpful assistant.',
  model: '__GATEWAY_OPENAI_MODEL_BASE__',
  errorProcessors: [new StreamErrorRetryProcessor({ maxRetries: 5 })],
  maxProcessorRetries: 5,
})
```

如果将 `maxRetries` 设为大于 `3`，还需同时设置 `maxProcessorRetries`；否则 Agent 会在错误处理器重试达到 `3` 次时停止。参见[重试次数限制](#retry-limits)。

如需仅运行自行配置的处理器、不合并任何默认处理器，请设置 `errorProcessorDefaults: false`。如果没有提供 `errorProcessors` 列表，Agent 此时只会运行 Memory 提供的错误处理器（如果有）；Memory 提供处理器时，重试上限为 `3`。参见[默认启用错误处理器](/docs/agents/processors#error-processors-are-enabled-by-default)。Agent 级别的空 `errorProcessors` 列表仍会使用默认处理器；调用时传入 `errorProcessors: []` 则会替换已解析的列表，但 Agent 仍会运行 Memory 提供的错误处理器。若为全部三个默认 id 提供自己的处理器，就会用这些实现替代所有默认处理器。

## 工作原理 {/* #how-it-works */}

处理器按以下顺序检查错误及其原因链：

- 匹配器结果：任一已配置的匹配器返回 `true`
- 内置的 OpenAI Responses 流错误匹配规则
- Provider 重试元数据：`isRetryable === true`

首个匹配结果决定重试策略。因此，即使内置匹配器也能匹配，同样会采用先匹配的自定义匹配器的 `maxRetries`、`delayMs` 和 `onRetry`。

错误可重试时，处理器返回 `{ retry: true }`，不会修改消息。

除非你自己的匹配器匹配到该错误，否则即使 Provider 元数据将其标记为可重试，处理器也绝不会重试凭证或配额被拒绝的错误。AI SDK 会将所有 `429` 错误标记为可重试，包括配额耗尽的情况。

设置 `delayMs` 后，处理器会先等待，再发出重试信号。对于 `ECONNRESET` 这类暂时性网络错误，这很有用，因为立即重试很可能再次失败。延迟时间可以是固定毫秒数，也可以是使用错误参数计算的函数，例如用于实现指数退避。

### 重试次数限制 {/* #retry-limits */}

`maxRetries` 默认为 `1`，限制此处理器请求重试的次数。Agent 还通过 `maxProcessorRetries` 限制处理器重试次数。配置了错误处理器但未设置 Agent 上限时，运行时上限为 `3`。

如果需要统一的重试预算，请将两个值明确设为相同的有限值。同时将该次调用的模型 `maxRetries` 设为 `0`，避免 Provider 尝试次数叠加。

### `Retry-After` 处理 {/* #retry-after-handling */}

对于带有 `Retry-After` 响应头的可重试错误，处理器会沿错误原因链读取不区分大小写的相对秒数或 HTTP 日期，并在 `delayMs` 与设定上限后的服务端延迟中取较长时间等待。

`maxRetryAfterMs` 默认为 `30_000`，只限制 Provider 给出的等待时间；明确设置的较长 `delayMs` 不受影响。无效或已过期的响应头会被忽略。

## 重试未知错误 {/* #retry-unknown-errors */}

设置 `retryUnknownErrors` 后，对于自定义匹配器、Provider 元数据和内置 OpenAI 匹配器均未确定策略的错误，也会进行重试。无论是否启用 `retryUnknownErrors`，自定义匹配器都会重试它所匹配的错误。未知错误重试使用处理器级别的 `maxRetries` 和 `delayMs`。已知的凭证及配额拒绝错误（包括 HTTP `401` 和 `403` 响应）不会被当作未知错误重试；但匹配到它们的自定义匹配器仍会重试：

```typescript title="src/mastra/agents/resilient-agent.ts"
import { Agent } from '@mastra/core/agent'
import { StreamErrorRetryProcessor } from '@mastra/core/processors'

export const agent = new Agent({
  id: 'resilient-agent',
  name: 'Resilient agent',
  instructions: 'You are a helpful assistant.',
  model: '__GATEWAY_OPENAI_MODEL_BASE__',
  errorProcessors: [
    new StreamErrorRetryProcessor({
      retryUnknownErrors: true,
      maxRetries: 2,
      delayMs: 3000,
    }),
  ],
})
```

具体的匹配器策略仍优先于未知错误的配置。此选项默认为 `false`，因此只有明确启用后才会重试未知错误。

## 延迟重试 {/* #delaying-retries */}

通过自定义匹配器配合 `delayMs`，可在等待一段时间后重试暂时性的网络连接重置：

```typescript title="src/mastra/agents/resilient-agent.ts"
import { Agent } from '@mastra/core/agent'
import { StreamErrorRetryProcessor } from '@mastra/core/processors'

const isECONNRESET = (error: unknown) => {
  if (!error || typeof error !== 'object') return false
  const code = (error as { code?: unknown }).code
  if (typeof code === 'string' && code.toUpperCase() === 'ECONNRESET') return true
  const message = error instanceof Error ? error.message : undefined
  return typeof message === 'string' && /econnreset|socket hang up/i.test(message)
}

export const agent = new Agent({
  id: 'resilient-agent',
  name: 'resilient-agent',
  instructions: 'You are a helpful assistant.',
  model: '__GATEWAY_OPENAI_MODEL_BASE__',
  errorProcessors: [
    new StreamErrorRetryProcessor({
      maxRetries: 2,
      delayMs: ({ retryCount }) => Math.min(1000 * 2 ** retryCount, 30000),
      matchers: [isECONNRESET],
    }),
  ],
})
```

## 默认的 OpenAI Responses 匹配器 {/* #default-openai-responses-matcher */}

`isRetryableOpenAIResponsesStreamError` 会匹配 `type: 'error'` 或 `type: 'response.failed'` 的 OpenAI Responses 流错误数据块。它使用 `@mastra/core/error` 中共用的 Provider 失败信息读取器解析每个数据块，并重试报告了速率限制、Provider 服务中断或超时的错误。作为后备规则，它也会重试明确提示可以重试的错误，例如 `You can retry your request`。凭证或配额拒绝错误绝不会重试。

`StreamErrorRetryProcessor` 默认包含此匹配器。你也可以将其导入，在自定义重试逻辑中复用。
