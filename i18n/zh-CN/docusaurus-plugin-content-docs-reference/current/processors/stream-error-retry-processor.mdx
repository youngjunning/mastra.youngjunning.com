# 流错误重试处理器

`StreamErrorRetryProcessor`是一个**错误处理器**重试暂时的 LLM API 和流失败。它包括针对 OpenAI 响应流错误的内置匹配，并支持针对其他特定于Provider的错误形状的附加匹配器。

Mastra 将此处理器添加到每个Agent的`errorProcessors` by default, last, after the `ProviderHistoryCompat`, `PrefillErrorHandler`， 和`UnsupportedFileHandler`默认情况下，因此修复请求的处理器在该请求保持不变重试之前就有机会。默认实例使用`maxRetries: 2`与内置匹配一起使用连接重置匹配器，并且它不会重试未知错误或重播修复处理器无法修复的错误请求（HTTP 400）响应。提供您自己的实例`errorProcessors`改变其政策。因为只有在默认情况下才会添加默认值`id`您的列表中缺少该实例，您的实例已被使用，并且默认实例未添加到它旁边。

## 使用示例 {/* #usage-example */}

配置`StreamErrorRetryProcessor`. Supplying the same `id` means the default isn't added:

```typescript title="src/mastra/agents/openai-agent.ts"
import { Agent } from '@mastra/core/agent'
import { StreamErrorRetryProcessor } from '@mastra/core/processors'

export const agent = new Agent({
  id: 'openai-agent',
  name: 'openai-agent',
  instructions: 'You are a helpful assistant.',
  model: '__GATEWAY_OPENAI_MODEL_BASE__',
  errorProcessors: [new StreamErrorRetryProcessor({ maxRetries: 5 })],
  maxProcessorRetries: 5,
})
```

放`maxProcessorRetries` alongside a `maxRetries` above `3`, because the agent stops error-processor retries at `3` when it's unset. See [Retry limits](#retry-limits).

要仅运行您配置的处理器，而不合并任何默认值，请设置`errorProcessorDefaults: false`. Without an `errorProcessors` list, the agent then runs only the error processors its memory contributes, if any. When memory contributes one, the retry cap of `3` applies. See [Error processors are enabled by default](/docs/agents/processors#error-processors-are-enabled-by-default). An empty agent-level `errorProcessors` list still gets the defaults. A call-time `errorProcessors: []` replaces the resolved list instead, though the agent still runs the error processors its memory contributes. Supplying your own processor for all three default ids replaces every default with your own implementation.

## 它是如何运作的 {/* #how-it-works */}

处理器按以下顺序检查错误及其原因链：

* 匹配器结果：任何返回的配置匹配器`true`
* 内置 OpenAI Responses 流错误匹​​配
* 提供者重试元数据：`isRetryable === true`

第一个匹配决定重试策略，因此配置的匹配器的`maxRetries`, `delayMs` and `onRetry` apply even when the built-in matcher would also match.

当错误可重试时，处理器返回`{ retry: true }`. It doesn't mutate messages.

除非您自己的匹配器之一与之匹配，否则处理器永远不会重试凭证或配额拒绝，即使提供程序元数据将其标记为可重试也是如此。 AI SDK标记了每一个`429` retryable, including an exhausted quota.

什么时候`delayMs` is set, the processor waits before signaling a retry. This is useful for transient network errors like `ECONNRESET` where immediately retrying is likely to fail again. The delay can be a fixed number of milliseconds or a function evaluated with the error args (for example, to implement exponential backoff).

### 重试限制 {/* #retry-limits */}

`maxRetries`默认为`1` and limits this processor's retry requests. The agent also limits processor retries with `maxProcessorRetries`. When error processors are configured without an agent limit, the runtime cap is `3`.

当您需要单个重试预算时，将这两个值显式设置为相同的界限值。保留模型`maxRetries` at `0` for that call to avoid multiplying provider attempts.

### `Retry-After`处理 {/* #retry-after-handling */}

对于可重试的错误`Retry-After` response header, the processor reads case-insensitive delta-seconds and HTTP-date values through the error cause chain. It waits for the longer of `delayMs` and the bounded server delay.

`maxRetryAfterMs`默认为`30_000`. It caps only provider-provided wait time. A longer explicit `delayMs` remains unchanged. Invalid or expired headers are ignored.

## 重试未知错误 {/* #retry-unknown-errors */}

放`retryUnknownErrors` to retry errors that no custom matcher, provider metadata, or built-in OpenAI matcher selects a policy for. Custom matchers retry the errors they match whether or not `retryUnknownErrors` is enabled. Unknown-error retries use the processor-level `maxRetries` and `delayMs` values. Known credential and quota refusals, including HTTP `401` and `403` responses, aren't retried as unknown errors. A custom matcher that matches them still retries them:

```typescript title="src/mastra/agents/resilient-agent.ts"
import { Agent } from '@mastra/core/agent'
import { StreamErrorRetryProcessor } from '@mastra/core/processors'

export const agent = new Agent({
  id: 'resilient-agent',
  name: 'Resilient agent',
  instructions: 'You are a helpful assistant.',
  model: '__GATEWAY_OPENAI_MODEL_BASE__',
  errorProcessors: [
    new StreamErrorRetryProcessor({
      retryUnknownErrors: true,
      maxRetries: 2,
      delayMs: 3000,
    }),
  ],
})
```

特定的匹配器策略仍然优先于未知错误值。该选项默认为`false`, so unknown errors aren't retried unless you enable it.

## 延迟重试 {/* #delaying-retries */}

使用`delayMs` with a custom matcher to retry transient network resets with a wait:

```typescript title="src/mastra/agents/resilient-agent.ts"
import { Agent } from '@mastra/core/agent'
import { StreamErrorRetryProcessor } from '@mastra/core/processors'

const isECONNRESET = (error: unknown) => {
  if (!error || typeof error !== 'object') return false
  const code = (error as { code?: unknown }).code
  if (typeof code === 'string' && code.toUpperCase() === 'ECONNRESET') return true
  const message = error instanceof Error ? error.message : undefined
  return typeof message === 'string' && /econnreset|socket hang up/i.test(message)
}

export const agent = new Agent({
  id: 'resilient-agent',
  name: 'resilient-agent',
  instructions: 'You are a helpful assistant.',
  model: '__GATEWAY_OPENAI_MODEL_BASE__',
  errorProcessors: [
    new StreamErrorRetryProcessor({
      maxRetries: 2,
      delayMs: ({ retryCount }) => Math.min(1000 * 2 ** retryCount, 30000),
      matchers: [isECONNRESET],
    }),
  ],
})
```

## 默认 OpenAI 响应匹配器 {/* #default-openai-responses-matcher */}

`isRetryableOpenAIResponsesStreamError`将 OpenAI 响应流错误块与`type: 'error'` or `type: 'response.failed'`. It reads each chunk with the shared provider-failure reader from `@mastra/core/error` and retries chunks that report a rate limit, a provider outage, or a timeout. As a fallback, it retries errors with explicit retry guidance such as `You can retry your request`. It never retries a credential or quota refusal.

`StreamErrorRetryProcessor`默认情况下包含此匹配器。您还可以导入它并在自定义重试逻辑中重用它。
