# 响应缓存

:::测试版

在 API 稳定之前，可能会在没有重大版本更新的情况下发生重大更改。

:::

`ResponseCache`是一个输入处理器，用于在Agent循环内的请求/响应边界上缓存 LLM 响应。它挂钩到`processLLMRequest` for cache lookup and short-circuits on a hit. It uses `processLLMResponse`写出完整的回复。

缓存键源自已解析的`LanguageModelV2Prompt` Mastra is about to send to the model (i.e. *after* memory has loaded and earlier input processors have transformed the prompt) so two users with different memory contexts produce different cache keys. Each step in an agentic tool loop is independently cached.

不存在用于响应缓存的Agent级选项。登记`ResponseCache` explicitly on `inputProcessors`. Per-call overrides flow through `RequestContext` via [`ResponseCache.context()`](#static-helpers)和[`ResponseCache.applyContext()`](#static-helpers).

## 使用示例 {/* #usage-example */}

```typescript
import { Agent } from '@mastra/core/agent'
import { InMemoryServerCache } from '@mastra/core/cache'
import { ResponseCache } from '@mastra/core/processors'

const cache = new InMemoryServerCache()

const agent = new Agent({
  id: 'search-agent',
  name: 'Search Agent',
  instructions: 'You answer questions concisely.',
  model: '__GATEWAY_OPENAI_MODEL_BASE__',
  inputProcessors: [new ResponseCache({ cache, ttl: 600 })],
})

// First call hits the LLM and writes to the cache.
await agent.generate('What is the capital of France?')

// Second identical call replays the cached response.
await agent.generate('What is the capital of France?')

// Force a fresh call but still update the cache.
await agent.generate('What is the capital of France?', {
  requestContext: ResponseCache.context({ bust: true }),
})
```

看[Response caching](/docs/agents/processors#response-caching) for the conceptual overview, scoping rules, and recommended deployment patterns.

## 静态助手 {/* #static-helpers */}

`ResponseCache`公开两个静态助手，用于设置每次调用覆盖`RequestContext`. The helpers keep the underlying context key a private implementation detail: prefer them over reading/writing the raw key.

### `ResponseCache.context(options)` {/* #responsecachecontextoptions */}

打造一个新鲜的`RequestContext` preloaded with per-call response cache overrides.

```typescript
await agent.stream('hello', {
  requestContext: ResponseCache.context({ key: 'custom', bust: true }),
})
```

### `ResponseCache.applyContext(requestContext, options)` {/* #responsecacheapplycontextrequestcontext-options */}

将每次调用响应缓存覆盖合并到现有的`RequestContext`. Returns the same context for chaining.

```typescript
const ctx = new RequestContext()
ctx.set('caller-meta', { userId: 'u-123' })
ResponseCache.applyContext(ctx, { bust: true })
await agent.stream('hello', { requestContext: ctx })
```

## 助手导出 {/* #helper-exports */}

* `buildResponseCacheKey(inputs)`：默认使用的确定性哈希。重新导出它以覆盖各个字段，同时保留标准密钥形状的其余部分。
* `DEFAULT_RESPONSE_CACHE_TTL_SECONDS`：默认`ttl` (`300`).
* `RESPONSE_CACHE_CONTEXT_KEY`： 这`RequestContext` key the static helpers write to. Exposed for advanced cases (e.g. clearing the override mid-pipeline). Prefer the helpers.
