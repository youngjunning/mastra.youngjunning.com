# UnsupportedFileHandler

`UnsupportedFileHandler` 是一个**错误处理器**。当模型拒绝用户发送的文件时，它会从提示中移除该文件，再次调用模型，让 Agent 能够继续工作。如果 Agent 的 Workspace 有 Sandbox，文件会上传到其中，并将路径提供给模型；否则，模型会收到替代文件的占位文本。

Mastra 默认将此处理器加入每个 Agent 的 `errorProcessors`，顺序位于 `PrefillErrorHandler` 之后、`StreamErrorRetryProcessor` 之前，无需额外配置。设置 `errorProcessorDefaults: false` 会将它与其他默认处理器一起关闭。

## 工作原理 {/* #how-it-works */}

1. 所有文件最初都会原样发送给模型。模型支持的文件类型因 Provider 而异，也会随时间变化，因此处理器不会预先判断。
1. 文件导致模型调用失败，可能有两种情况：
   - Provider SDK 在发出请求前拒绝该文件类型，并抛出包含媒体类型的 `UnsupportedFunctionalityError`。OpenAI 和 Anthropic 的 SDK 就会这样处理。
   - Provider 在 HTTP 响应中拒绝请求。错误信息通常不会提到文件：例如，Gemini 对某些文件类型会返回 `502`。只要请求包含非图像、非 PDF、非文本的文件，任何 API 错误都符合此处理条件，但表示稍后重试的状态码 `408`、`409`、`429`、`503` 或 `504` 除外：这些情况由 [`StreamErrorRetryProcessor`](/reference/processors/stream-error-retry-processor) 原样重发请求，文件也会一同发送。
1. 首次拒绝调用时，处理器会从提示中移除被拒绝的文件，以及其他所有非图像、非 PDF、非文本的文件。调用只会重试一次，这样便能在同一次重试中处理模型可能无法读取的所有文件。
1. 处理器返回 `{ retry: true }`，再次调用模型。如果仍然失败，错误会向外抛出。

如果 Agent 的 Workspace 有 Sandbox，每个文件都会按 [`FileUploadProcessor`](/reference/processors/file-upload-processor#upload-location) 的方式上传。模型会收到包含 Sandbox 路径的说明，Agent 因而可以用自己的 Tool 处理该文件：

```text
[File uploaded to the sandbox]
path: /home/user/uploads/thread-1/0b2f4c6e8a1d3f5b7c9e2a4d6f8b1c3e5a7d9f2b4c6e8a1d3f5b7c9e2a4d6f8b.xlsx
name: leads.xlsx
type: application/vnd.openxmlformats-officedocument.spreadsheetml.sheet
size: 48213 bytes
```

如果没有 Sandbox，或上传失败，模型会收到 Mastra 用于不可用附件的占位文本，本轮对话仍会继续。没有文件名时，占位文本会显示文件类型：

```text
[Attachment unavailable: leads.xlsx]
```

这里的 Sandbox 是当前步骤所用的 Workspace，也就是 Agent 的 Tool 使用的 Workspace。超过 10 MB 的文件不会上传，模型会收到说明原因的提示。

只有发送给模型的提示会改变。已存储的消息仍保留文件，因此线程、Studio 等客户端以及支持该类型的模型仍可访问它。即使线程已存有被拒绝的文件，下一轮仍可正常进行，因为每轮都会按相同方式处理该文件。

如需自行决定哪些文件进入 Sandbox，并在模型看到文件前完成上传，可将 `FileUploadProcessor` 加入 `inputProcessors`。

## 限制 {/* #limitations */}

- **跨线程共享的 Sandbox。** 文件默认写入 Agent 的 Sandbox，按线程分目录存放；目录只能隔开文件，不能保护文件。如果其他线程或用户共享该 Sandbox，任一线程的命令 Tool 都可以读取这些文件。处理私有文件时，请使用[每位用户或每个线程独立的 Sandbox](/docs/sandbox/overview#sandboxes-per-user-or-thread)。
- **仅再尝试一次。** 移除文件后如果调用仍失败，错误会向外抛出。只要请求中包含此类文件，发生 API 错误时就会移除文件并重试一次，即使错误并非由文件引起；表示稍后重试的状态码除外。不含此类文件的请求若因其他原因被拒绝，处理器不会介入。
