# MemoryInputFilter

`MemoryInputFilter` 是一个**输入处理器**，会在任何内存加载器读取消息之前，根据已存储的历史记录过滤请求输入。`Memory` 会自动将它添加到 `MessageHistory`、`WorkingMemory`、`SemanticRecall` 和 Observational Memory 之前；只有手动管理内存处理器时，才需要自行创建它。

## 使用示例 {/* #usage-example */}

```typescript
import { MemoryInputFilter } from '@mastra/core/processors'

const processor = new MemoryInputFilter({
  storage: memoryStorage,
})
```

## 行为 {/* #behavior */}

### 输入处理 {/* #input-processing */}

对于已有已存储消息的线程，处理器根据输入中的最后一条消息精简输入：

- **以一条或多条用户消息结束**：保留这些用户消息，并丢弃往前直到上一条助手消息之间的内容。连续的用户消息都会保留，因为它们都是新消息。如果那条助手消息包含客户端 Tool 的结果，还会保留其已存储副本中仍待完成的调用所对应的结果。`useChat` 在客户端 Tool 结果与下一条用户消息一起发送时，就会采用这种输入形式。
- **以助手消息结束**：只保留该消息末尾连续出现的客户端 Tool 结果。这对应客户端 Tool 流程：已存储的助手轮次包含待完成的调用，客户端随后返回结果。
- **以助手消息结束，但没有新的 Tool 结果**：只有该消息已存在于存储中时才丢弃它。未曾持久化的助手消息（例如内部指令消息）会保留。
- **没有新内容**：清空输入，仅凭已存储的历史记录继续运行。

对于没有已存储消息的线程，整个输入会用于初始化对话。处理器会从助手消息中移除 Provider 元数据，避免重放来自其他对话的服务端条目引用。

客户端 Tool 结果指处于 `result`、`output-error`、`output-denied` 或 `approval-responded` 状态的 Tool 调用。若某条助手消息未以其 ID 存储，处理器会丢弃其结果：AI SDK 客户端可能把多条服务端消息合并成一条具有新 ID 的 UI 消息，此时无法区分客户端结果与重复的服务端结果。

末尾的用户消息视为新消息，并按发送时的内容保留。没有 ID 时，服务端会为其分配 ID。客户端回传的已存储消息副本不会替换存储记录，因此该消息以存储的时间戳和 Provider 元数据为准。

### 以已存储消息为基础 {/* #stored-messages-as-the-base-layer */}

加载器会以 `memory` 来源添加已存储消息。如果已存储消息与输入消息的 ID 相同，则保留已存储副本中的文本、推理内容、Provider 元数据和 `createdAt`。仅当已存储副本中仍有待完成的调用时，才从输入中取用该调用的 Tool 结果，例如客户端 Tool 结果或审批答复。输入中的文本和元数据会被忽略，因此客户端无法通过发送不同的副本来修改已存储消息。如需修改，应直接更新存储中的消息。启用 `retainFullInput` 时也是如此。
