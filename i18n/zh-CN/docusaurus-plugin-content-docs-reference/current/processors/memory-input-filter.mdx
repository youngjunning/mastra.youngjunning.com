# 内存输入过滤器

这`MemoryInputFilter`是一个**输入处理器**在任何内存加载器读取请求输入之前，它会根据存储的历史记录过滤请求输入。它是自动添加的`Memory`领先于`MessageHistory`, `WorkingMemory`, `SemanticRecall`，和观察内存，因此当您手动管理内存处理器时，您只能自己构建它。

## 使用示例 {/* #usage-example */}

```typescript
import { MemoryInputFilter } from '@mastra/core/processors'

const processor = new MemoryInputFilter({
  storage: memoryStorage,
})
```

## 行为 {/* #behavior */}

### 输入处理 {/* #input-processing */}

对于已经存储消息的线程，根据其最后一条消息减少输入：

* **以一条或多条用户消息结束**：保留这些消息，并删除最后一条助理消息之前的所有内容。几个连续的用户消息都被保留，因为它们都是新的。如果该辅助消息携带客户端Tool结果，则其存储的副本仍待处理的呼叫的结果也会被保留。这是形状`useChat` sends when a client tool result goes out with the next user message.
* **以助理消息结束**：仅保留其客户端Tool结果的跟踪运行。这是客户端Tool流程，其中存储的助理轮次包含待处理的调用，并且客户端返回其结果。
* **以助理消息结束，没有新Tool结果**：仅当消息存在于存储中时才会删除该消息。从未保留的辅助消息（例如内部指令消息）会保留在原处。
* **不包含任何新内容**：输入被清除，并且仅根据存储的历史记录继续运行。

对于没有存储消息的线程，整个输入都会成为对话的种子。提供程序元数据从助理消息中删除，以便不会重播另一个对话中对服务器端项目的项目引用。

客户端Tool结果是Tool调用`result`, `output-error`, `output-denied`, or `approval-responded` state. An outcome on an assistant message that isn't stored under its ID is dropped, because the AI SDK client can fold several server messages into one UI message under a new ID, and then a client outcome can't be told apart from a duplicated server result.

尾随用户消息被视为新消息并保持发送状态。当它们没有携带 ID 时，服务器会分配一个。已存储消息的回显副本永远不会替换存储的行，因此存储的时间戳和提供程序元数据对该消息保持权威。

### 存储消息作为基础层 {/* #stored-messages-as-the-base-layer */}

加载器添加存储的消息`memory` source. When a stored message and an input message share an ID, the stored copy keeps its text, reasoning, provider metadata, and `createdAt`. The only thing taken from the input is a tool outcome for a call that's still pending in the stored copy, such as a client tool result or an approval answer. Text and metadata from the input are ignored, so a client can't change a stored message by sending a different copy of it. To change a stored message, update it in storage. This also applies with `retainFullInput`.
