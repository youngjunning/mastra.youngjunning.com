# ModelSelectionProcessor

`ModelSelectionProcessor` 对传入请求分类一次，然后覆盖本次运行所用的模型。它用于控制成本：将能力较强的模型设为 Agent 的默认模型；只有决策模型确信低成本模型能处理请求时，处理器才改用低成本模型。

:::warning
路由可能增加而非节省成本。不同模型之间不共享 Provider 的提示词缓存。每次切换模型都需要再次按全价处理对话，低成本模型也可能需要更多步骤才能完成任务。启用前，请根据自己的请求流量衡量成本和质量。参见[成本权衡](#cost-tradeoffs)。
:::

为每个模型说明适合处理的请求类型。处理器会为你创建 [Classifier](/reference/classifier/classifier)。处理器自身的 `model` 选项接收决策模型（`DecisionModelV4 | EvaluationModelV4 | MastraDecisionModel`），类型与 `Classifier` 接受的相同。该选项不支持 `'provider/model'` 字符串。Provider 的配置方法参见[决策模型](/reference/classifier/classifier#decision-models)：

```typescript title="src/mastra/agents/support-agent.ts"
import { Agent } from '@mastra/core/agent'
import { ModelSelectionProcessor } from '@mastra/core/processors'
import { typeSafeAi } from '@ai-sdk/typesafe-ai'

export const agent = new Agent({
  name: 'support-agent',
  instructions: 'Answer the user concisely.',
  model: '__GATEWAY_OPENAI_MODEL__',
  inputProcessors: [
    new ModelSelectionProcessor({
      model: typeSafeAi.decisionModel('__AI_SDK_TYPESAFE_DECISION_MODEL__'),
      choices: [
        {
          model: '__GATEWAY_OPENAI_MODEL_LUNA__',
          criteria:
            'Answerable in one or two sentences from general knowledge, with no reasoning steps',
        },
        {
          model: '__GATEWAY_OPENAI_MODEL__',
          criteria:
            'Requires multi-step reasoning, planning, weighing trade-offs, or careful judgment',
        },
      ],
    }),
  ],
})
```

每个选项指定一个模型及其适合处理的请求。分类器会根据这些描述判断每个请求，并交给选中的模型处理。

默认情况下，该决策适用于运行中的每一步。设置 `scope: 'first-step'` 可只路由首次模型调用，让后续步骤使用 Agent 配置的模型。这样，若任务比首条消息看起来更难，后续步骤便不会受首次决策约束；但如[路由范围](#routing-scope)所述，节省的成本也少得多。

## 决策回调 {/* #decision-callback */}

`onDecision` 每个请求触发一次，包括处理器未选择模型时。可用它记录处理请求的模型及选择的置信度：

```typescript
import { ModelSelectionProcessor } from '@mastra/core/processors'
import { typeSafeAi } from '@ai-sdk/typesafe-ai'
import { PinoLogger } from '@mastra/loggers'

const logger = new PinoLogger({ name: 'model-selection' })

new ModelSelectionProcessor({
  model: typeSafeAi.decisionModel('__AI_SDK_TYPESAFE_DECISION_MODEL__'),
  choices: [
    { model: '__GATEWAY_OPENAI_MODEL_LUNA__', criteria: 'Simple lookups' },
    { model: '__GATEWAY_OPENAI_MODEL__', criteria: 'Multi-step reasoning' },
  ],
  onDecision: decision => {
    logger.info('model routing', decision)
  },
})
```

决策结果包含实际使用的模型、选中的条件、该选择的置信度，以及未使用任何模型时的原因。使用 `select` 时，结果不包含 `choice` 或 `probability`。对于无文本或发生错误的情况，结果分别包含 `abstained: 'no-text'` 或 `abstained: 'error'`；当 `select` 返回 `undefined` 时，结果既不包含 `model`，也不包含 `abstained`：

## 现有分类器 {/* #existing-classifiers */}

传入 `classifier` 而非 `choices`，即可用自行配置的 [Classifier](/reference/classifier/classifier) 路由。同一个分类器还用于 scorer 或其他处理器时，这种方式尤其有用。通过 `select` 将分类结果映射到模型：

```typescript
import { Classifier } from '@mastra/core/classifier'
import { typeSafeAi } from '@ai-sdk/typesafe-ai'

const triage = new Classifier({
  id: 'triage',
  model: typeSafeAi.decisionModel('__AI_SDK_TYPESAFE_DECISION_MODEL__'),
  questions: {
    complexity: {
      type: 'choice',
      criteria: {
        trivial: 'Answerable in one or two sentences with no reasoning steps',
        complex: 'Requires multi-step reasoning or careful judgment',
      },
    },
  },
})

new ModelSelectionProcessor({
  classifier: triage,
  select: ({ complexity }) =>
    complexity.choice === 'trivial' ? '__GATEWAY_OPENAI_MODEL_LUNA__' : undefined,
})
```

返回 `undefined` 表示不选择模型，此时使用 Agent 配置的模型。

## 路由范围 {/* #routing-scope */}

运行中的每一步都会把截至目前的对话和所有 Tool 结果发送给模型。因此首次调用通常成本最低，而非最高；只路由首次调用能节省的成本很少。

在四步运行中，首次调用约占输入 token 的 14%，因此仅路由这一步，能获得的节省不到十分之一。该估算将所有输入 token 按全价计算。使用提示词缓存后，后续步骤的大部分输入会按折扣价读取缓存，所以路由后续步骤的节省也小于其 token 占比所暗示的数值。

因此默认使用 `scope: 'run'`。如果你更希望较长的运行在后续步骤回到能力较强的模型，而不持续沿用首次决策，可使用 `scope: 'first-step'`；但对于多步运行，它几乎不节省成本。

单步运行不受影响，因为只调用模型一次时，两种范围的行为相同。

## 多维度 {/* #multiple-dimensions */}

各选项的条件互斥，因此不适合依据多个独立维度路由的场景。此时可提出多个问题，并在 `select` 中组合答案。它接收完整类型信息的答案，路由策略由你的代码决定：

```typescript
import { Classifier } from '@mastra/core/classifier'
import { typeSafeAi } from '@ai-sdk/typesafe-ai'
import { ModelSelectionProcessor } from '@mastra/core/processors'

const triage = new Classifier({
  id: 'triage',
  model: typeSafeAi.decisionModel('__AI_SDK_TYPESAFE_DECISION_MODEL__'),
  questions: {
    complexity: {
      type: 'choice',
      criteria: {
        trivial: 'Answerable in one or two sentences with no reasoning steps',
        complex: 'Requires multi-step reasoning or careful judgment',
      },
    },
    sensitive: {
      type: 'boolean',
      criteria: {
        true: 'Involves money, credentials, legal, medical, or safety consequences',
        false: 'Routine request with no sensitive consequences',
      },
    },
  },
})

new ModelSelectionProcessor({
  classifier: triage,
  select: ({ complexity, sensitive }) => {
    // Never downgrade a sensitive request, however simple it looks.
    if (sensitive.probability >= 0.3) return undefined
    return complexity.choice === 'trivial' ? '__GATEWAY_OPENAI_MODEL_LUNA__' : undefined
  },
})
```

## 概率和`minProbability` {/* #probabilities-and-minprobability */}

选项的答案包含各条件的概率分布，路由决策的置信度是实际选中条件的概率。并非所有决策模型都会返回这一分布。

因此 `minProbability` 没有默认值。各设置的行为如下：

* **省略**：直接按选中的选项路由。分类器的答案就是最终决策。
* **设置**：只有概率达到或超过阈值才使用选中的模型。如果模型完全不返回概率分布，处理器会**放弃路由**，因为无法评估的阈值不能视为已满足。

如果决策模型不返回选项的概率分布，设置 `minProbability` 后，处理器会对每个请求放弃路由。可记录 `onDecision` 检查：若 `abstained` 为 `below-threshold` 且没有 `probability`，表示缺少概率分布，而非置信度偏低。

## 失败行为 {/* #failure-behavior */}

路由采用失败时放行策略。如果分类器出错，或分类器 ID 未注册，处理器会记录警告并使用 Agent 配置的模型。请求没有可供分类的用户文本时，处理器会放弃路由，不记录日志，并向 `onDecision` 报告 `abstained: 'no-text'`。使用 `choices` 时，若决策模型拒绝回答路由问题，处理器会放弃路由并报告 `abstained: 'refused'`。使用 `select` 时，回调会收到拒答结果，由你决定返回模型还是 `undefined`。对于成本优化，这样更稳妥：最坏也只是使用原本配置的模型并支付相应费用。

这与[工具审批](/docs/agents/human-in-the-loop)所需的失败时阻断策略相反：工具审批遇到不确定情况应上报，而不应直接放行。

失败时放行只针对路由决策，不针对所选模型。如果所选模型失败，而 Agent 配置了[回退模型](/models#model-fallbacks)，处理器会停止覆盖模型，交由下一个已配置模型处理请求。若只配置了一个模型，就没有回退选项，所选模型的错误会使运行失败。

## 成本权衡 {/* #cost-tradeoffs */}

每个请求都会额外调用一次分类器，以换取部分请求使用低成本模型。是否省钱取决于实际请求流量：

* **提示词缓存**：Provider 会按模型缓存提示词前缀，缓存输入的计费价格低于正常价格。模型之间不共享缓存。当一次调用切换到与上次不同的模型时，该模型必须按全价处理尚未缓存的对话；某些 Provider 还会收取缓存写入费用。每个请求单独分类，因此同一线程中的连续轮次可能交替使用不同模型。对于系统提示词、检索上下文或历史记录较长的 Agent，一次切换的额外费用可能超过低成本模型节省的费用。
* **低成本模型的额外工作**：低成本模型可能犯更多错误、执行更多步骤或调用更多 Tool 才能完成同一任务。若后续调用切回能力较强的模型，例如同一线程的下一个请求，或使用 `scope: 'first-step'` 时的第二步，低成本模型先前执行的每一步，包括 Tool 调用及结果，都会作为未缓存输入向能力较强的模型计费。

只有在实际请求中，不同模型的表现确有差异，路由才有价值。如果低成本模型的回答与能力较强的模型一样准确，直接将低成本模型设为默认值即可。

启用路由前，分别使用和不使用处理器运行一组实际请求样本，比较每项已完成任务的总成本，而非每个 token 的价格。计算缓存读写、分类器调用、额外步骤和后续请求，并检查被降级请求的回答质量。[Token 用量指标](/reference/observability/metrics/automatic-metrics#token-usage-metrics)会报告每次模型调用的缓存读写 token 数。

## 行为说明 {/* #behavior-notes */}

* 分类器在 `processInput` 中**每个请求只运行一次**，并非每步运行一次。决策保存在当前请求的状态中，供每一步读取。
* 仅对**最新一条用户消息**分类。系统提示词、检索上下文和先前轮次不会发送给分类器，因此上下文增长不会增加路由调用的输入量。像 `"now apply that to the rest"` 这样简短的后续消息，只会依据这句话路由。如果你的后续请求经常重新提出复杂推理任务，而非沿用已有结果，请保持能力较强的模型为默认值。
* 只向下切换模型。将能力较强的模型设为 Agent 默认值，由处理器改用低成本模型。错误决策会损害该请求的质量。默认的 `scope: 'run'` 会让错误降级影响运行中的每一步；即使任务比首条消息看起来更难，也会继续使用低成本模型。
* 处理器会在每个请求的关键路径上增加一次分类器往返调用，包括最终放弃路由的请求。
* 使用 `choices` 时，每个条件以对应模型命名，因此 `onDecision` 会将选中的模型报告为 `choice`。
