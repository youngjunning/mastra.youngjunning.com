# 版本控制

编辑器版本存储Agent和提示块。数据库支持的资源使用草稿和发布操作。代码支持的Agent会覆盖使用确定性文件和 Git 历史记录。

看[Editor versioning](/docs/studio/editor#versioning) for release and experimentation patterns.

## 数据库生命周期 {/* #database-lifecycle */}

资源记录存储一个`activeVersionId`, while individual snapshots don't store a lifecycle status.

|术语 |意义|
| - | - |
|最新 |最近创建的配置快照 |
|发表 |选择的快照`activeVersionId` |
| Draft | The latest snapshot when it differs from `activeVersionId`, or when no active version exists |
| Historical | Any other retained snapshot |

保存更改的快照字段会创建一个新的最新版本。仅保存相同的快照字段或更改元数据不会创建版本。

如果存在活动版本，则创建草稿不会更改处理已发布请求的版本。发布更新`activeVersionId`. Restoring a historical version copies its configuration into a new inactive draft.

直接命名空间方法和 REST API 都同意这一点。`editor.prompt.update()` and `editor.agent.update()` both create an inactive draft. Neither assigns the new version to `activeVersionId`. To publish a version from the SDK, pass it explicitly: `editor.agent.update({ id, status: 'published', activeVersionId: version.id })`. The stored-agent REST `PATCH`路线也会创建一个非活动草稿，除非`autoPublish`已启用，并且`POST /stored/agents/:id/versions/:versionId/activate`发布它。

当通用存储资源没有活动版本时，已发布的解决方案可以回退到最新快照。对于代码定义的Agent覆盖，请求`status: 'published'` without an active override returns the original code agent.

## 代码来源 {/* #code-source */}

和`source: 'code'`, active agent overrides are serialized as deterministic JSON under `<codePath>/agents/<encodedAgentId>.json`. The default `codePath` is `./mastra/editor`.

发布初始Agent以创建文件。稍后的服务器更新默认创建草稿，并在该版本激活时写入该文件。 Git 版本在 Studio 中是只读的，并使用提交消息作为其更改消息。默认历史记录扫描最多读取 50 个最近提交，并跳过解析的 JSON 快照未更改的连续提交。

看[`MastraEditor`](/reference/editor/mastra-editor#source) for source options.

## 选择Agent版本 {/* #select-an-agent-version */}

呼唤[`mastra.getAgentById()`](/reference/core/getAgentById) without a selector returns the registered code-defined agent. Pass `status` or `versionId` to apply a stored override. See [Select a version](/docs/studio/editor#select-a-version) for a TypeScript example.

使用默认服务器前缀，将选择器作为查询参数传递给`/api`:

```bash title="Version selection through the API"
# Published version
curl http://localhost:4111/api/agents/support-agent

# Latest draft
curl http://localhost:4111/api/agents/support-agent?status=draft

# Exact version
curl http://localhost:4111/api/agents/support-agent?versionId=abc-123
```

请参阅[Client SDK agents reference](/reference/client-js/agents#version-management) for Client SDK and React SDK selectors.

## 子Agent版本控制 {/* #sub-agent-versioning */}

版本覆盖通过传播[supervisor-agent delegation](/docs/subagents) in request context. Define selectors at three levels:

1. `Mastra`实例`versions`: Defaults for every invocation
2. 服务器请求体`versions`: Per-request values added to request context
3. 直接的`generate()` or `stream()` `versions`: Per-invocation values

条目按Agent ID 合并。对于相同的ID，优先级是**direct invocation > request body or existing request context > Mastra instance default**.

在 Mastra 实例上设置默认值：

```typescript title="src/mastra/index.ts"
import { Mastra } from '@mastra/core'
import { MastraEditor } from '@mastra/editor'

export const mastra = new Mastra({
  agents: { supervisor, researchAgent, writerAgent },
  editor: new MastraEditor(),
  versions: {
    agents: {
      'research-agent': { status: 'published' },
      'writer-agent': { versionId: 'abc-123' },
    },
  },
})
```

覆盖一个子Agent以进行直接调用：

```typescript title="src/routes/experiment.ts"
const result = await supervisor.generate('Research and write about AI safety', {
  versions: {
    agents: {
      'research-agent': { status: 'draft' },
    },
  },
})
```

或者在服务器请求正文中传递选择器：

```bash title="Per-request sub-agent versions"
curl -X POST http://localhost:4111/api/agents/supervisor/generate \
  -H "Content-Type: application/json" \
  -d '{
    "messages": [{ "role": "user", "content": "Research AI safety" }],
    "versions": {
      "agents": {
        "research-agent": { "status": "draft" }
      }
    }
  }'
```

如果未配置编辑器或无法解析版本，Mastra 会记录警告并使用代码定义的子Agent。

## 存储Agent REST API {/* #stored-agent-rest-api */}

默认 Mastra 服务器前缀是`/api`. A custom server prefix changes the paths below.

|方法|路径|描述 |
| - | - | - |
|`GET` | `/api/stored/agents` | List stored agents |
| `POST` | `/api/stored/agents` | Create a stored agent |
| `GET` | `/api/stored/agents/:storedAgentId` | Get a stored agent |
| `PATCH` | `/api/stored/agents/:storedAgentId` | Update a stored agent |
| `DELETE` | `/api/stored/agents/:storedAgentId` | Delete a stored agent |
| `GET` | `/api/stored/agents/:storedAgentId/dependents` | List readable dependents and count hidden cross-workspace references |
| `POST` | `/api/stored/agents/:storedAgentId/export` | Export the allowed override fields as deterministic JSON |

依赖者响应列出了调用者可读的Agent`id` and `name`. Its `hiddenCount` field counts cross-workspace references that the caller can't read, but only when the target agent is public.

版本管理路由嵌套在`/api/stored/agents/:storedAgentId/versions`. See [version management](/reference/client-js/agents#version-management) for operations and Client SDK methods.

客户端 SDK 公开`listStoredAgents()`, `createStoredAgent()`, and `getStoredAgent()`. The resource returned by `getStoredAgent(id)` includes methods for updates, deletion, dependents, export, and version management.
