# 版本管理

Editor 为已存储的 Agent 和提示块提供版本管理。数据库资源通过草稿和发布操作管理版本；代码定义的 Agent 覆盖则使用内容确定的文件和 Git 历史记录。

有关发布和实验方案，请参阅 [Editor 版本管理](/docs/studio/editor#versioning)。

## 数据库生命周期 {/* #database-lifecycle */}

资源记录保存 `activeVersionId`，各个快照本身不保存生命周期状态。

| 术语 | 含义 |
| - | - |
| 最新版本 | 最近创建的配置快照 |
| 已发布版本 | `activeVersionId` 指向的快照 |
| 草稿 | 与 `activeVersionId` 不同的最新快照，或没有活动版本时的最新快照 |
| 历史版本 | 保留的其他快照 |

保存已变更的快照字段会创建新的最新版本。保存相同的快照字段或仅修改元数据不会创建版本。

如果已有活动版本，创建草稿不会改变用于处理已发布请求的版本。发布会更新 `activeVersionId`。恢复历史版本时，会复制其配置并创建新的未激活草稿。

直接调用的命名空间方法与 REST API 遵循相同规则。`editor.prompt.update()` 和 `editor.agent.update()` 都会创建未激活草稿，不会将新版本赋给 `activeVersionId`。通过 SDK 发布版本时，须显式传入：`editor.agent.update({ id, status: 'published', activeVersionId: version.id })`。已存储 Agent 的 REST `PATCH` 路由也会创建未激活草稿，除非启用了 `autoPublish`；`POST /stored/agents/:id/versions/:versionId/activate` 则会发布该版本。

如果通用的已存储资源没有活动版本，解析已发布版本时可能回退到最新快照。对于代码定义的 Agent 覆盖，如果请求 `status: 'published'`，但没有活动覆盖版本，则返回原始的代码定义 Agent。

## 代码来源 {/* #code-source */}

当 `source: 'code'` 时，活动的 Agent 覆盖会以内容确定的 JSON 格式序列化到 `<codePath>/agents/<encodedAgentId>.json`。`codePath` 默认为 `./mastra/editor`。

首次发布 Agent 时会创建该文件。之后的服务器更新默认创建草稿，并在该版本激活时写入文件。Studio 中的 Git 版本为只读版本，以提交消息作为变更说明。默认历史扫描最多读取最近 50 个提交，并跳过解析后的 JSON 快照与前一个相同的连续提交。

有关来源选项，请参阅 [`MastraEditor`](/reference/editor/mastra-editor#source)。

## 选择 Agent 版本 {/* #select-an-agent-version */}

不传选择器调用 [`mastra.getAgentById()`](/reference/core/getAgentById) 时，返回已注册的代码定义 Agent。传入 `status` 或 `versionId` 可应用已存储的覆盖版本。TypeScript 示例见[选择版本](/docs/studio/editor#select-a-version)。

使用默认服务器前缀时，将选择器作为 `/api` 路径上的查询参数传入：

```bash title="Version selection through the API"
# Published version
curl http://localhost:4111/api/agents/support-agent

# Latest draft
curl http://localhost:4111/api/agents/support-agent?status=draft

# Exact version
curl http://localhost:4111/api/agents/support-agent?versionId=abc-123
```

有关 Client SDK 和 React SDK 的选择器，请参阅 [Client SDK Agent 参考文档](/reference/client-js/agents#version-management)。

## 子 Agent 版本管理 {/* #sub-agent-versioning */}

版本覆盖会通过请求上下文沿[监督 Agent 委派](/docs/subagents)传递。可在三个层级指定选择器：

1. `Mastra` 实例的 `versions`：每次调用的默认值
2. 服务器请求体中的 `versions`：添加到请求上下文的单次请求值
3. 直接调用 `generate()` 或 `stream()` 时的 `versions`：单次调用值

各条目按 Agent ID 合并。同一个 ID 的优先级为：**直接调用 > 请求体或已有请求上下文 > Mastra 实例默认值**。

在 Mastra 实例上设置默认值：

```typescript title="src/mastra/index.ts"
import { Mastra } from '@mastra/core'
import { MastraEditor } from '@mastra/editor'

export const mastra = new Mastra({
  agents: { supervisor, researchAgent, writerAgent },
  editor: new MastraEditor(),
  versions: {
    agents: {
      'research-agent': { status: 'published' },
      'writer-agent': { versionId: 'abc-123' },
    },
  },
})
```

为一次直接调用覆盖某个子 Agent：

```typescript title="src/routes/experiment.ts"
const result = await supervisor.generate('Research and write about AI safety', {
  versions: {
    agents: {
      'research-agent': { status: 'draft' },
    },
  },
})
```

也可以在服务器请求体中传入选择器：

```bash title="Per-request sub-agent versions"
curl -X POST http://localhost:4111/api/agents/supervisor/generate \
  -H "Content-Type: application/json" \
  -d '{
    "messages": [{ "role": "user", "content": "Research AI safety" }],
    "versions": {
      "agents": {
        "research-agent": { "status": "draft" }
      }
    }
  }'
```

如果未配置 Editor 或无法解析指定版本，Mastra 会记录警告并使用代码定义的子 Agent。

## 已存储 Agent REST API {/* #stored-agent-rest-api */}

Mastra 服务器的默认前缀是 `/api`。自定义服务器前缀会改变下列路径。

| 方法 | 路径 | 说明 |
| - | - | - |
| `GET` | `/api/stored/agents` | 列出已存储的 Agent |
| `POST` | `/api/stored/agents` | 创建已存储的 Agent |
| `GET` | `/api/stored/agents/:storedAgentId` | 获取已存储的 Agent |
| `PATCH` | `/api/stored/agents/:storedAgentId` | 更新已存储的 Agent |
| `DELETE` | `/api/stored/agents/:storedAgentId` | 删除已存储的 Agent |
| `GET` | `/api/stored/agents/:storedAgentId/dependents` | 列出可读取的依赖项，并统计隐藏的跨 Workspace 引用 |
| `POST` | `/api/stored/agents/:storedAgentId/export` | 将允许覆盖的字段导出为内容确定的 JSON |

依赖项响应按 `id` 和 `name` 列出调用方可读取的 Agent。仅当目标 Agent 为公开时，`hiddenCount` 字段才会统计调用方无法读取的跨 Workspace 引用。

版本管理路由嵌套在 `/api/stored/agents/:storedAgentId/versions` 下。有关操作和 Client SDK 方法，请参阅[版本管理](/reference/client-js/agents#version-management)。

Client SDK 提供 `listStoredAgents()`、`createStoredAgent()` 和 `getStoredAgent()`。`getStoredAgent(id)` 返回的资源包含更新、删除、查询依赖项、导出和版本管理方法。
