# Tool配置

编辑器将Tool选择存储为Agent版本的一部分。存储的配置可以添加已注册的Tool和来自集成Provider的Tool，以及来自模型上下文协议 (MCP) 客户端的Tool。

看[Editor tools](/docs/studio/editor#tools) for the Studio workflow and common uses.

## Tool来源 {/* #tool-sources */}

|来源 |描述 |
| - | - |
|注册Tool |在 Mastra 运行时Tool注册表中注册的Tool |
| MCP 客户 |存储的本地或远程 MCP 服务器配置公开的Tool |
|集成Tool|由遗留集成Provider配置解决的Tool |
|[Tool providers](/reference/editor/tool-provider) | Tools resolved by providers registered on `MastraEditor`, such as Composio or Arcade |

代码定义的Agent保留其现有Tool。这[`editor` override setting](/reference/agents/agent#editor-overrides) controls whether Editor can add and remove tools or only change descriptions.

## 描述覆盖 {/* #description-overrides */}

每个选定的Tool都可以存储特定于Agent的描述。描述改变了模型所看到的内容，而不修改原始Tool定义。

在仅描述模式下，编辑器仅将覆盖应用于代码定义Agent上已存在的Tool。对于 MCP Tool，Agent级描述优先于 MCP 客户端上存储的描述。

如果两个源解析相同的Tool ID，则较晚的源将替换完整的较早Tool，包括其描述。看[Resolution order](#resolution-order).

## 条件Tool集 {/* #conditional-tool-sets */}

编辑器可以存储条件变体`tools`, `mcpClients`, `integrationTools`, and `toolProviders` fields. At runtime, matching variants are shallow-merged based on request-context values.

规则语言使用与以下相同的运算符和嵌套行为[prompt block display conditions](/reference/editor/prompt-blocks#display-conditions).

条件适用于Tool字段变体或 MCP 客户端参考。每个Tool`rules` values in stored tool entries aren't evaluated by the current Editor resolver.

## 存储的 MCP 客户端 {/* #stored-mcp-clients */}

这`editor.mcp` namespace manages reusable MCP client configurations. See the [`mcp` namespace](/reference/editor/mastra-editor#namespaces) for CRUD method signatures.

`@mastra/mcp`是可选的对等依赖项`@mastra/editor`. Install it before configuring stored MCP clients so Editor can load their tools at runtime:

```bash npm2yarn
npm install @mastra/mcp
```

### 交通 {/* #transports */}

|交通 |存储的配置 |
| - | - |
|`stdio` | `command` with optional `args`, `env`, and `timeout` |
| HTTP | `url` with optional `timeout` |

存储的 HTTP 定义不接受任意标头。当保留`mastra__authToken` value is present in request context, Editor forwards it as an `Authorization: Bearer` header.

### 过滤 {/* #filtering */}

MCP Tool可以在两个级别列入许可名单：

1. **服务器级别**: 存储的服务器的`tools` map limits tools for every agent that uses the client. Omitting `tools` at this level exposes all of the server's tools.
2. **Agent级别**：Agent的 MCP 客户端引用限制该Agent的剩余Tool。省略`tools` at this level selects no tools.

Agent级Tool名称可以使用命名空间或裸名称。要选择Agent级别的每个剩余Tool，请传递显式的空`tools` map:

```typescript
const mcpClients = {
  'docs-client': { tools: {} }, // all tools
  'search-client': { tools: { docs_search: {} } }, // only docs_search
  'billing-client': {}, // no tools
}
```

### 命名空间 {/* #namespacing */}

MCPTool使用`serverName_toolName` IDs to avoid conflicts. A `search` tool from the `docs` server becomes `docs_search`.

## 决议顺序 {/* #resolution-order */}

编辑器按以下顺序合并Tool记录。后面的记录用相同的 ID 替换前面的记录。

1. 代码定义的Tool
2. 注册存储Tool
3. MCPTool
4. 遗留集成Tool
5. V1Tool-提供者Tool

独立存储Agent使用相同的顺序，无需代码定义的Tool。静态代码Agent覆盖在旧集成Tool之后停止。

尽可能使用跨源的唯一Tool ID。碰撞取代了完整的早期Tool，而不是合并其字段。
