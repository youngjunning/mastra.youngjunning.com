# Tool 配置

Editor 将选中的 Tool 作为 Agent 版本的一部分存储。存储的配置可以添加已注册的 Tool、来自集成 Provider 的 Tool，以及来自模型上下文协议（MCP）客户端的 Tool。

有关 Studio 中的操作流程和常见用途，请参阅 [Editor Tool](/docs/studio/editor#tools)。

## Tool 来源 {/* #tool-sources */}

| 来源 | 描述 |
| - | - |
| 已注册的 Tool | 在 Mastra 运行时 Tool 注册表中注册的 Tool |
| MCP 客户端 | 由已存储的本地或远程 MCP 服务器配置提供的 Tool |
| 集成 Tool | 通过旧版集成 Provider 配置解析的 Tool |
| [Tool Provider](/reference/editor/tool-provider) | 通过注册到 `MastraEditor` 的 Provider 解析的 Tool，例如 Composio 或 Arcade |

代码中定义的 Agent 会保留其现有 Tool。[`editor` 覆盖设置](/reference/agents/agent#editor-overrides)决定 Editor 可以添加和移除 Tool，还是只能修改描述。

## 描述覆盖 {/* #description-overrides */}

每个选中的 Tool 都可以存储专用于该 Agent 的描述。它会改变模型看到的内容，但不会修改原始 Tool 定义。

在仅允许修改描述的模式下，Editor 只会覆盖代码中定义的 Agent 已有 Tool 的描述。对于 MCP Tool，Agent 级描述优先于 MCP 客户端中存储的描述。

如果两个来源解析出相同的 Tool ID，后解析的 Tool 会整体替换先前的 Tool，包括其描述。请参阅[解析顺序](#resolution-order)。

## 条件 Tool 集合 {/* #conditional-tool-sets */}

Editor 可以为 `tools`、`mcpClients`、`integrationTools` 和 `toolProviders` 字段存储按条件生效的配置变体。运行时，系统根据请求上下文的值，对匹配的变体进行浅合并。

条件规则使用与[提示词块显示条件](/reference/editor/prompt-blocks#display-conditions)相同的运算符和嵌套规则。

条件可用于 Tool 字段的配置变体或 MCP 客户端引用。当前 Editor 解析器不会评估已存储 Tool 条目中每个 Tool 的 `rules` 值。

## 存储的 MCP 客户端 {/* #stored-mcp-clients */}

`editor.mcp` 命名空间管理可复用的 MCP 客户端配置。CRUD 方法签名请参阅 [`mcp` 命名空间](/reference/editor/mastra-editor#namespaces)。

`@mastra/mcp` 是 `@mastra/editor` 的可选 peer dependency。配置已存储的 MCP 客户端前，请先安装它，以便 Editor 在运行时加载这些客户端的 Tool：

```bash npm2yarn
npm install @mastra/mcp
```

### 传输方式 {/* #transports */}

| 传输方式 | 已存储的配置 |
| - | - |
| `stdio` | `command`，以及可选的 `args`、`env` 和 `timeout` |
| HTTP | `url`，以及可选的 `timeout` |

已存储的 HTTP 配置不支持任意请求头。如果请求上下文中包含预留值 `mastra__authToken`，Editor 会将它作为 `Authorization: Bearer` 请求头转发。

### 过滤 {/* #filtering */}

可以在两个层级为 MCP Tool 设置允许列表：

1. **服务器级别**：已存储服务器的 `tools` 映射会限制所有使用该客户端的 Agent 可用的 Tool。在此级别省略 `tools`，则会开放服务器的所有 Tool。
2. **Agent 级别**：Agent 的 MCP 客户端引用会进一步限制该 Agent 可用的 Tool。在此级别省略 `tools`，则不会选中任何 Tool。

Agent 级 Tool 名称可以带命名空间，也可以只写名称。要在 Agent 级别选中所有剩余 Tool，请明确传入空的 `tools` 映射：

```typescript
const mcpClients = {
  'docs-client': { tools: {} }, // all tools
  'search-client': { tools: { docs_search: {} } }, // only docs_search
  'billing-client': {}, // no tools
}
```

### 命名空间 {/* #namespacing */}

MCP Tool 使用 `serverName_toolName` 形式的 ID 避免冲突。例如，`search` Tool 来自 `docs` 服务器时，其 ID 为 `docs_search`。

## 解析顺序 {/* #resolution-order */}

Editor 按以下顺序合并 Tool 记录。若 ID 相同，后面的记录会替换前面的记录。

1. 代码中定义的 Tool
2. 已注册且已存储的 Tool
3. MCP Tool
4. 旧版集成 Tool
5. V1 Tool Provider 提供的 Tool

独立存储的 Agent 也遵循这一顺序，但没有代码中定义的 Tool。静态代码 Agent 的覆盖只处理到旧版集成 Tool，不包含 V1 Tool Provider。

尽量让不同来源的 Tool 使用唯一 ID。发生 ID 冲突时，后面的 Tool 会整体替换先前的 Tool，不会合并字段。
