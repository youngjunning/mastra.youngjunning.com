# ToolProvider

`ToolProvider` 接口定义了编辑器如何发现并解析外部平台的集成工具。Mastra 提供两个内置实现：`ComposioToolProvider` 和 `ArcadeToolProvider`。

有关 Provider 配置及 Studio 工作流程，参见[编辑器工具](/docs/studio/editor#tools)；有关已保存的工具选择及解析行为，参见[工具配置](/reference/editor/tools)。

## ToolProvider 接口 {/* #toolprovider-interface */}

Provider 提供元数据及旧版的发现、解析方法。Agent Builder 集成还可实现可选的 VNext 目录、连接、授权及健康检查方法。

## ComposioToolProvider {/* #composiotoolprovider */}

连接 [Composio](https://composio.dev)，使用其数百种集成工具。

### 使用示例 {/* #usage-example */}

```typescript title="src/mastra/index.ts"
import { MastraEditor } from '@mastra/editor'
import { ComposioToolProvider } from '@mastra/editor/composio'

const editor = new MastraEditor({
  toolProviders: {
    composio: new ComposioToolProvider({
      apiKey: process.env.COMPOSIO_API_KEY!,
    }),
  },
})
```

### 工具 slug {/* #tool-slugs */}

Composio 工具使用大写 slug 格式：`GITHUB_CREATE_ISSUE`、`SLACK_SEND_MESSAGE`。

### 身份认证 {/* #authentication */}

连接默认采用按作者划分的范围。设置 `defaultScope: 'caller-supplied'` 后，授权会按请求上下文中 `MASTRA_RESOURCE_ID_KEY` 解析出的调用方身份分组。请确保每个已认证请求都提供稳定且唯一的资源 ID。使用 `MastraAuthWorkos` 时，可配置 `mapUserToResourceId`，将该值设为已认证用户的资源 ID。

Provider 如何为工具调用解析 Composio 用户，取决于连接类型：

- **绑定作者的连接**（`kind: 'author'`）使用 Agent 作者的用户身份，对固定的已连接账户执行操作。
- **绑定执行者的连接**（`kind: 'invoker'`）使用已认证执行者的身份，对精确固定的账户执行操作。该账户也可以是其他用户通过 Composio 访问控制列表（ACL）共享给执行者的账户。用户 ID 优先取自已配置的 `userIdResolver`，否则取自已认证用户，绝不使用 Memory 的 `resourceId`。若无已认证用户且解析器也未返回结果，执行者身份解析会失败。
- **调用方提供的范围**（`scope: 'caller-supplied'`）优先使用已配置的 `userIdResolver`。否则，为兼容旧行为，回退到请求上下文中的 `resourceId`。若固定了具体的已连接账户，执行会路由到该账户；否则 Composio 会在用户分组中自动选择。

### 使用共享账户执行 {/* #execute-with-a-shared-account */}

Bob 需要使用 Alice 通过 Composio 共享的账户执行 Salesforce 工具。请区分以下几种身份：

| 身份 | 值 |
| - | - |
| Memory 资源 | `project_123` |
| Composio 用户 ID | `bob` |
| 已连接账户 | `ca_alice_salesforce` |

按常规方式注册 Provider。Mastra 服务端身份认证会将已认证用户写入请求上下文，因此大多数应用无须配置 `userIdResolver`：

```typescript title="src/mastra/index.ts"
import { Mastra } from '@mastra/core/mastra'
import { MastraEditor } from '@mastra/editor'
import { ComposioToolProvider } from '@mastra/editor/composio'

const editor = new MastraEditor({
  toolProviders: {
    composio: new ComposioToolProvider({
      apiKey: process.env.COMPOSIO_API_KEY!,
    }),
  },
})

export const mastra = new Mastra({ editor })
```

为 Agent 配置固定到 `ca_alice_salesforce` 的执行者连接。Bob 调用 Agent 时，Mastra 将 `bob` 作为 Composio 用户，并将固定的账户 ID 作为要使用的具体已连接账户。Memory 资源仍是 `project_123`。随后 Composio 检查该账户的 ACL 是否允许 Bob 执行操作。

### 创建共享账户 {/* #create-shared-accounts */}

设置 `sharedConnections`，使通过 `scope: 'shared'` 授权的连接创建为 Composio [SHARED 账户](https://docs.composio.dev/docs/shared-connections)：

```typescript title="src/mastra/index.ts"
new ComposioToolProvider({
  apiKey: process.env.COMPOSIO_API_KEY!,
  sharedConnections: {
    acl: { allowAllUsers: true, notAllowedUserIds: ['contractor_1'] },
  },
})
```

若未设置 `sharedConnections`，共享范围的连接会成为 `shared` 用户名下的 Composio PRIVATE 账户。对于需要自定义连接字段的工具包，Composio 不支持 SHARED 账户，因此授权会失败，而不会退回创建 PRIVATE 账户。

`listConnections()` 返回所请求用户的 PRIVATE 和 SHARED 账户，还会返回其他用户拥有且 ACL 授权给任一所请求用户的 SHARED 账户。可以像固定其他已连接账户一样固定这些账户。

### 将应用用户映射到 Composio 用户 {/* #map-application-users-to-composio-users */}

如果 Composio 用户 ID 与 Mastra 身份认证返回的 ID 不同，或应用必须在执行前授权已保存的固定账户，请使用 `userIdResolver`。

解析器返回 Composio 用户 ID，或返回 `undefined` 以采用 Provider 的默认解析方式。返回空字符串会抛出错误，不会悄然回退。解析器不能替换已连接账户。

此示例按组织为 Composio 用户 ID 添加命名空间，并让应用的授权层批准精确固定的账户：

```typescript title="src/mastra/index.ts"
import { MASTRA_USER_KEY } from '@mastra/server/auth'
import { ComposioToolProvider } from '@mastra/editor/composio'
import { canUseConnectedAccount } from './integration-authorization'

type AuthenticatedUser = {
  id: string
  organizationId: string
}

function isAuthenticatedUser(value: unknown): value is AuthenticatedUser {
  return (
    typeof value === 'object' &&
    value !== null &&
    'id' in value &&
    typeof value.id === 'string' &&
    'organizationId' in value &&
    typeof value.organizationId === 'string'
  )
}

const composio = new ComposioToolProvider({
  apiKey: process.env.COMPOSIO_API_KEY!,
  userIdResolver: async ({ requestContext, toolkit, connectedAccountId }) => {
    const user = requestContext?.getRaw(MASTRA_USER_KEY)
    if (!isAuthenticatedUser(user)) return undefined

    if (connectedAccountId) {
      const allowed = await canUseConnectedAccount({
        actorId: user.id,
        organizationId: user.organizationId,
        provider: 'composio',
        toolkit,
        connectedAccountId,
      })
      if (!allowed) {
        throw new Error('User cannot access this connected account')
      }
    }

    return `${user.organizationId}:${user.id}`
  },
})
```

创建 Composio 连接和共享账户 ACL 条目时，使用同一个带命名空间的 ID。例如在此配置中，Bob 的 Composio 用户 ID 为 `acme:bob`。

从 `userIdResolver` 抛出错误可拒绝请求。在解析已保存 Agent 的过程中，Mastra 会记录该失败并省略此连接关联的工具，因此不会向 Composio 发起工具调用；其他连接仍可继续解析。若直接调用 `resolveToolsVNext()`，则错误会返回给调用方。

### 连接管理工具 {/* #connection-management-tools */}

Composio 提供在 Agent 聊天中启动和监控授权的工具。设置 `allowedToolkits` 时，请包含 `composio`，使这些工具可用：

```typescript title="src/mastra/index.ts"
const editor = new MastraEditor({
  toolProviders: {
    composio: new ComposioToolProvider({
      apiKey: process.env.COMPOSIO_API_KEY!,
      allowedToolkits: ['composio', 'gmail'],
      defaultScope: 'caller-supplied',
    }),
  },
})
```

只添加 Agent 所需的连接管理工具：

| 工具 | 行为 |
| - | - |
| `COMPOSIO_MANAGE_CONNECTIONS` | 通过调用方拥有的会话，在聊天中创建授权链接。 |
| `COMPOSIO_WAIT_FOR_CONNECTIONS` | 等待调用方完成授权，然后 Agent 才继续执行。 |

`COMPOSIO_WAIT_FOR_CONNECTIONS` 是可选的。若不使用它，请完成授权并返回聊天，再让 Agent 继续。已连接账户仍与调用方资源 ID 关联，供后续请求使用。

### 工具 slug {/* #tool-slugs-1 */}

Arcade 工具使用 `Toolkit.ToolName` 格式，例如 `Github.GetRepository`、`Slack.SendMessage`。

### 身份认证 {/* #authentication-1 */}

旧版 Arcade 解析器优先使用请求上下文中的 `resourceId`，其次使用传入的 `userId`，最后回退到共享的 `default` 身份。仅在有意共享集成时使用 `default`。多租户隔离部署应提供可信、稳定的 `resourceId` 或显式 `userId`，因为两者都省略时，调用方之间不会隔离。
