# Tool提供者

这`ToolProvider`接口定义了编辑器如何发现和解析来自外部平台的集成Tool。 Mastra 包括两个内置实现：`ComposioToolProvider`和`ArcadeToolProvider`.

看[Editor tools](/docs/studio/editor#tools) for provider setup and the Studio workflow. See [tool configuration](/reference/editor/tools) for stored selections and resolution behavior.

## 组合Tool提供者 {/* #composiotoolprovider */}

连接到[Composio](https://composio.dev) for access to hundreds of integration tools.

### 使用示例 {/* #usage-example */}

```typescript title="src/mastra/index.ts"
import { MastraEditor } from '@mastra/editor'
import { ComposioToolProvider } from '@mastra/editor/composio'

const editor = new MastraEditor({
  toolProviders: {
    composio: new ComposioToolProvider({
      apiKey: process.env.COMPOSIO_API_KEY!,
    }),
  },
})
```

### Tool块 {/* #tool-slugs */}

Composio Tool使用大写 slug 格式：`GITHUB_CREATE_ISSUE`, `SLACK_SEND_MESSAGE`.

### 验证 {/* #authentication */}

默认情况下，连接使用每个作者范围。放`defaultScope: 'caller-supplied'` to bucket authorization by the caller identity resolved from `MASTRA_RESOURCE_ID_KEY` in request context. Ensure each authenticated request provides a stable, unique resource ID. When using `MastraAuthWorkos`, configure `mapUserToResourceId` to set this value from the authenticated user.

提供程序如何解析 Composio 用户的Tool调用取决于连接：

* **作者绑定的连接** (`kind: 'author'`) execute as the agent author's user against the pinned connected account.
* **调用者绑定的连接** (`kind: 'invoker'`) execute as the authenticated invoker against the exact pinned account, which may be an account another user shared with the invoker through Composio's access control list (ACL). The user ID comes from `userIdResolver` when configured, then the authenticated user, and never from the Memory `resourceId`. Invoker resolution fails when no authenticated user or resolver result exists.
* **调用者提供的范围** (`scope: 'caller-supplied'`) uses `userIdResolver` when configured. Otherwise, it falls back to the legacy `resourceId` from request context for backward compatibility. When a specific connected account is pinned, execution routes to that exact account. Otherwise, Composio auto-resolves within the user's bucket.

### 使用共享帐户执行 {/* #execute-with-a-shared-account */}

Bob 需要使用 Alice 通过 Composio 共享的帐户运行 Salesforce Tool。保持每个身份独立：

|身份 |价值|
| - | - |
|内存资源|`project_123` |
| Composio user ID | `bob` |
| Connected account | `ca_alice_salesforce` |

正常注册Provider。 Mastra 服务器身份验证将经过身份验证的用户写入请求上下文，因此大多数应用程序不需要`userIdResolver`:

```typescript title="src/mastra/index.ts"
import { Mastra } from '@mastra/core/mastra'
import { MastraEditor } from '@mastra/editor'
import { ComposioToolProvider } from '@mastra/editor/composio'

const editor = new MastraEditor({
  toolProviders: {
    composio: new ComposioToolProvider({
      apiKey: process.env.COMPOSIO_API_KEY!,
    }),
  },
})

export const mastra = new Mastra({ editor })
```

使用固定的调用程序连接配置Agent`ca_alice_salesforce`. When Bob invokes the agent, Mastra sends `bob` as the Composio user and the pinned account ID as the exact connected account. The Memory resource stays `project_123`. Composio then checks whether the account's ACL permits Bob to execute it.

### 创建共享帐户 {/* #create-shared-accounts */}

放`sharedConnections` to create Composio [SHARED accounts](https://docs.composio.dev/docs/shared-connections) for connections authorized with `scope: 'shared'`:

```typescript title="src/mastra/index.ts"
new ComposioToolProvider({
  apiKey: process.env.COMPOSIO_API_KEY!,
  sharedConnections: {
    acl: { allowAllUsers: true, notAllowedUserIds: ['contractor_1'] },
  },
})
```

没有`sharedConnections`, shared-scope connections are Composio PRIVATE accounts under the `shared` user. Composio doesn't support SHARED accounts for toolkits that require custom connection fields, so authorization fails for those toolkits instead of creating a PRIVATE account.

`listConnections()`返回所请求用户的 PRIVATE 和 SHARED 帐户，以及其 ACL 向所请求用户之一授予访问权限的其他用户所拥有的 SHARED 帐户。您可以像任何其他连接的帐户一样固定这些帐户。

### 将应用程序用户映射到 Composio 用户 {/* #map-application-users-to-composio-users */}

使用`userIdResolver` when your Composio user IDs differ from the IDs returned by Mastra authentication, or when your application must authorize the stored account pin before execution.

解析器返回 Composio 用户 ID，或者`undefined` to use the provider's default resolution. Returning an empty string throws instead of silently falling back. The resolver can't replace the connected account.

此示例按组织对 Composio 用户进行命名，并要求应用程序的授权层批准确切的帐户 PIN：

```typescript title="src/mastra/index.ts"
import { MASTRA_USER_KEY } from '@mastra/server/auth'
import { ComposioToolProvider } from '@mastra/editor/composio'
import { canUseConnectedAccount } from './integration-authorization'

type AuthenticatedUser = {
  id: string
  organizationId: string
}

function isAuthenticatedUser(value: unknown): value is AuthenticatedUser {
  return (
    typeof value === 'object' &&
    value !== null &&
    'id' in value &&
    typeof value.id === 'string' &&
    'organizationId' in value &&
    typeof value.organizationId === 'string'
  )
}

const composio = new ComposioToolProvider({
  apiKey: process.env.COMPOSIO_API_KEY!,
  userIdResolver: async ({ requestContext, toolkit, connectedAccountId }) => {
    const user = requestContext?.getRaw(MASTRA_USER_KEY)
    if (!isAuthenticatedUser(user)) return undefined

    if (connectedAccountId) {
      const allowed = await canUseConnectedAccount({
        actorId: user.id,
        organizationId: user.organizationId,
        provider: 'composio',
        toolkit,
        connectedAccountId,
      })
      if (!allowed) {
        throw new Error('User cannot access this connected account')
      }
    }

    return `${user.organizationId}:${user.id}`
  },
})
```

创建 Composio 连接和共享帐户 ACL 条目时使用相同的命名空间 ID。例如，在此设置中 Bob 的 Composio 用户 ID 是`acme:bob`.

抛出自`userIdResolver` to deny the request. During stored-agent resolution, Mastra logs the failure and omits tools associated with that connection, so no tool call reaches Composio. Other connections continue to resolve. When calling `resolveToolsVNext()` directly, the error is returned to the caller instead.

### 连接管理Tool {/* #connection-management-tools */}

Composio 提供了用于启动和监控Agent聊天授权的Tool。什么时候`allowedToolkits` is set, include `composio` to make these tools available:

```typescript title="src/mastra/index.ts"
const editor = new MastraEditor({
  toolProviders: {
    composio: new ComposioToolProvider({
      apiKey: process.env.COMPOSIO_API_KEY!,
      allowedToolkits: ['composio', 'gmail'],
      defaultScope: 'caller-supplied',
    }),
  },
})
```

仅添加Agent所需的连接管理Tool：

|Tool|行为 |
| - | - |
|`COMPOSIO_MANAGE_CONNECTIONS` | Creates an authorization link in chat through a session owned by the caller. |
| `COMPOSIO_WAIT_FOR_CONNECTIONS` | Waits for the caller to finish authorization before the agent continues. |

`COMPOSIO_WAIT_FOR_CONNECTIONS`是可选的。如果没有它，请完成授权并返回聊天。然后要求Agent继续。连接的帐户仍与调用者资源 ID 相关联，以供以后请求。

街机Tool的使用`Toolkit.ToolName` format: `Github.GetRepository`, `Slack.SendMessage`.

### 验证 {/* #authentication-1 */}

旧版 Arcade 解析器使用`resourceId` from request context when available, falling back to the supplied `userId` and then to a shared `default` identity. Reserve `default` for intentionally shared integrations, and provide a trusted, stable `resourceId` or explicit `userId` in tenant-isolated deployments because omitting both doesn't isolate callers.
