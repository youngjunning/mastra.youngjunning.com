# 提示块

提示块是由编辑器管理的可重复使用的指令模板。Agent的指令可以将内嵌文本与嵌入的提示块以及对独立版本提示块的引用结合起来。

看[Prompt blocks](/docs/studio/editor#prompt-blocks) for the Studio workflow and common uses.

## 块类型 {/* #block-types */}

|类型 |描述 |
| - | - |
|`text` | Free-form text stored only in the agent version |
| `prompt_block` | A prompt block embedded in the agent version |
| `prompt_block_ref`|对独立存储和版本控制的提示块的引用 |

引用的块在运行时解析。最终说明中省略了缺失或未发布的参考文献。解析的非空块用两个换行符连接。

以下示例将存储的块和内联文本附加到Agent：

```typescript title="src/scripts/attach-prompt.ts"
import { mastra } from '../mastra'

const editor = mastra.getEditor()!

await editor.agent.update({
  id: 'support-agent',
  instructions: [
    { type: 'prompt_block_ref', id: 'brand-voice' },
    { type: 'text', content: 'Answer only questions about Acme products.' },
  ],
})
```

## 模板值 {/* #template-values */}

模板在运行时解析请求上下文中的值。

|语法 |请求上下文 |输出|
| - | - | - |
|<code>{'{{userName}}'}</code> | `{ userName: 'Maya' }` | `Maya` |
| <code>{'{{user.name}}'}</code> | `{ user: { name: 'Maya' } }` | `Maya` |
| <code>{"{{task \u007c\u007c 'request'}}"}</code> | `{}` | `request` |
| <code>{'{{missingValue}}'}</code> | `{}` | `{{missingValue}}` |

变量名称必须以字母或下划线开头。后备必须是单引号或双引号字符串。没有后备的未解决占位符保持不变。对象和数组被序列化为 JSON。其他值将转换为字符串。

通过传递值[request context](/docs/server/request-context). Editor doesn't read a separate agent `variables` field.

## 显示条件 {/* #display-conditions */}

提示块可以包括控制其是否包含在最终指令中的显示条件。每个条件由三部分组成：

* **钥匙**：要检查的请求上下文字段，例如`user.role` or `account.plan`.
* **操作员**：进行比较，例如`equals`, `contains`, or `exists`.
* **价值**：要比较的值。这`exists` and `not_exists` operators don't need one.

例如，条件`user.role` `equals` `admin` includes the block only when request context contains `{ user: { role: 'admin' } }`.

|操作员|示例|当 | 时，该块被包含在内。
| - | - | - |
|`equals` / `not_equals` | `user.role` equals `admin` | The field strictly equals, or doesn't equal, the value |
| `contains` / `not_contains` | `user.tags` contains `beta` | A string contains the value or an array contains the item |
| `greater_than` / `less_than` | `order.total` greater than `100` | The numeric field is above or below the value |
| `greater_than_or_equal` / `less_than_or_equal` | `account.seats` greater than or equal to `10` | The numeric field is at or beyond the value |
| `in` / `not_in` | `user.region`在`['US', 'CA']`|该字段是否在提供的数组中 |
|`exists` / `not_exists` | `account.plan`存在 |该字段具有或不具有非空值 |

组将条件与`AND` or `OR`. For example, this group includes a block for admins on a paid plan:

```typescript
const rules = {
  operator: 'AND',
  conditions: [
    {
      field: 'user.role',
      operator: 'equals',
      value: 'admin',
    },
    {
      field: 'account.plan',
      operator: 'in',
      value: ['pro', 'enterprise'],
    },
  ],
}
```

支持点路径。空组的计算结果为`true`, and an unknown operator evaluates to `false`. The storage type supports up to three nested group levels.

始终包含无条件的块。

一个`prompt_block_ref` can also have its own `rules`. They apply only to that reference in that agent, so you can reuse one stored block under different conditions. If the stored block has rules too, both must pass.

### 具有后备功能的运行时槽 {/* #runtime-slot-with-a-fallback */}

合并内联`prompt_block` and a conditional `prompt_block_ref` to insert a value from request context and fall back to a shared stored block when the value is missing:

```typescript title="src/scripts/attach-prompt.ts"
await editor.agent.update({
  id: 'support-agent',
  instructions: [
    { type: 'text', content: 'Follow the platform safety policy.' },
    {
      type: 'prompt_block',
      content: '{{userPrompt}}',
      rules: {
        operator: 'AND',
        conditions: [
          { field: 'userPrompt', operator: 'exists' },
          { field: 'userPrompt', operator: 'not_equals', value: '' },
        ],
      },
    },
    {
      type: 'prompt_block_ref',
      id: 'default-user-prompt',
      rules: {
        operator: 'OR',
        conditions: [
          { field: 'userPrompt', operator: 'not_exists' },
          { field: 'userPrompt', operator: 'equals', value: '' },
        ],
      },
    },
  ],
})
```

当请求上下文包含非空时`userPrompt`, the agent receives that value. Otherwise, it receives the published `default-user-prompt` block. The stored block doesn't need to know about `userPrompt`.

：：：笔记

这`exists` operator treats an empty string as present. The extra `''` conditions make an empty `userPrompt` use the fallback too.

## 程序化API {/* #programmatic-api */}

通过访问提示块`mastra.getEditor().prompt`. See the [`prompt` namespace](/reference/editor/mastra-editor#namespaces) for complete method signatures.

创建提示块：

```typescript title="src/scripts/seed-prompts.ts"
import { mastra } from '../mastra'

const editor = mastra.getEditor()!

await editor.prompt.create({
  id: 'brand-voice',
  name: 'Brand voice',
  description: 'Acme tone and style guidelines',
  content: 'Write in a friendly, concise tone. Address the user as {{userName || "there"}}.',
})
```

更新现有块：

```typescript title="src/scripts/update-prompt.ts"
await editor.prompt.update({
  id: 'brand-voice',
  content: 'Write in a friendly, concise tone. Greet the user by name when available.',
})
```

`update()`当内容更改时创建新草稿。使用`list()` to paginate through stored blocks, `getById()` to fetch one block, and `preview(blocks, context)` to resolve templates and conditions with draft references.

## 休息API {/* #rest-api */}

默认 Mastra 服务器前缀是`/api`. A custom server prefix changes the paths below.

|方法|路径|描述 |
| - | - | - |
|`GET` | `/api/stored/prompt-blocks` | List stored prompt blocks |
| `POST` | `/api/stored/prompt-blocks` | Create a stored prompt block |
| `GET` | `/api/stored/prompt-blocks/:storedPromptBlockId` | Get a stored prompt block |
| `PATCH` | `/api/stored/prompt-blocks/:storedPromptBlockId` | Update a stored prompt block |
| `DELETE` | `/api/stored/prompt-blocks/:storedPromptBlockId` | Delete a stored prompt block |

## 版本解析 {/* #version-resolution */}

运行时引用解析活动的发布块。编辑器预览解析最新草稿。看[Editor versioning](/docs/studio/editor#versioning) for the shared draft, publish, and restore lifecycle.
