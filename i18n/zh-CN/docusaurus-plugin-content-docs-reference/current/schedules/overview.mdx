# `mastra.schedules`

**添加于：** `@mastra/core@1.50.0`

`mastra.schedules`是持久化 cron 计划的 CRUD 服务。使用它来创建、列出、更新、暂停、恢复、手动运行和删除Agent或Workflow程的计划。

有关使用模式和概念，请参阅[Schedules](/docs/harness/schedules).

## 交货保证 {/* #delivery-guarantees */}

预定的发布是尽最大努力，而不是至少一次交付。调度程序自动声明发生并推进`nextFireAt` before publishing the agent or workflow start event. An exhausted cron schedule is marked `completed` in that claim. Completion means there are no remaining occurrences, not that the target started or succeeded.

调度程序对同一声明的事件最多进行 3 次发布尝试，在尝试之间等待 100 毫秒，然后等待 200 毫秒。传输可以在返回错误之前接受事件，因此重试可以发布具有相同运行 ID 的重复项。

三个尝试均失败后，调度程序会记录调度 ID、运行 ID、调度的触发时间、`publicationOutcome: 'unknown'`, and `automaticReplay: false`. It invokes the configured `scheduler.onError` hook and attempts to record a trigger with outcome `failed`。此失败描述了发布尝试。这并不能证明目标从未开始。

一旦这些尝试用尽，调度程序就不会重播该事件。定期计划保持活动状态，并可以在下一个计划时间触发。终端计划保持完整状态，并在触发历史记录中记录任何故障详细信息。

成功领取后，会出现信息级别`Claimed schedule occurrence` log identifies the schedule ID, run ID, and scheduled fire time. A matching `Published schedule occurrence` log reports transport acceptance. If neither that success log nor the final failure log follows a claim, publication is unconfirmed. These logs aren't durable state: a crash between the claim commit and logging, or before logs are flushed, can leave no log record.

如果发布者进程在声明提交后终止，或者确认丢失，则可以跳过该事件，而不会触发失败。替换调度程序无法使用声明元数据或丢失的触发历史记录来区分未发布的事件与崩溃之前接受的事件。它不会重播事件或阻止以后重复发生的火灾。发布确认也不能保证目标执行，并且传输重新传递可能会产生重复。

在手动重新运行错过的工作之前，请独立检查目标执行和传输记录。仅缺少触发历史记录或失败的发布尝试并不能证明重新运行是安全的。

## 使用示例 {/* #usage-example */}

创建Agent计划：

```typescript title="src/mastra/schedules.ts"
const schedule = await mastra.schedules.create({
  agentId: 'pinger',
  cron: '0 * * * *',
  prompt: 'Give me a status update.',
})
```

创建Workflow程计划：

```typescript title="src/mastra/schedules.ts"
const schedule = await mastra.schedules.create({
  workflowId: 'daily-report',
  cron: '0 9 * * *',
  inputData: { reportType: 'summary' },
})
```

计划需要一个实现计划域的存储适配器。支持的适配器包括`@mastra/libsql`, `@mastra/pg`, `@mastra/mysql`, `@mastra/mongodb`, `@mastra/convex`, and `@mastra/spanner`.

要在固定时间运行一次，请传递`runAt` instead of `cron`:

```typescript
await mastra.schedules.create({
  workflowId: 'send-report',
  runAt: new Date(Date.now() + 60 * 60 * 1000), // One hour from now
})
```

### 更新时间表 {/* #update-schedules */}

#### `update(id, patch)` {/* #updateid-patch */}

更新时间表。改变`cron` or `timezone` recomputes the next fire time. Updating `status` from `paused` to `active` also recomputes the next fire time. A schedule becomes `completed` once its cron has no future occurrence. A cadence edit that leaves no future occurrence completes the row even when it was `paused`. Editing the cadence of a completed schedule reactivates it when the new cadence can still fire, and leaves it completed when it can't.

```typescript
const updated = await mastra.schedules.update('pinger', {
  cron: '*/30 * * * *',
  prompt: 'Give me a status update every 30 minutes.',
})
```

Agent日程补丁可以更新`cron`, `timezone`, `prompt`, `name`, `signalType`, `tagName`, `attributes`, `providerOptions`, `ifActive`, `ifIdle`, `metadata`, and `status`. `threadId` and `resourceId` aren't patchable. Create a new schedule when the thread target needs to change.

Workflow程计划补丁可以更新`cron`, `timezone`, `inputData`, `initialState`, `requestContext`, `resourceId`, `metadata`, and `status`. Agent-only patch fields such as `prompt`, `signalType`, and `ifIdle` throw on workflow schedules.

### 生命周期 {/* #lifecycle */}

#### `pause(id)` {/* #pauseid */}

暂停计划。暂停是持久且幂等的。暂停一个`completed` schedule throws a `409` error.

```typescript
const paused = await mastra.schedules.pause('pinger')
```

#### `resume(id)` {/* #resumeid */}

恢复暂停的计划并从当前时间重新计算下一次触发时间。一次性时间表保留其`runAt`; if it passed while the schedule was paused, the schedule fires on the next scheduler tick. A paused schedule whose cron has no future occurrence is completed instead of resumed. Resuming a `completed` schedule throws a `409` error; update its timing instead to reactivate it.

```typescript
const active = await mastra.schedules.resume('pinger')
```

#### `run(id)` {/* #runid */}

立即触发一次计划，而不改变其 cron 节奏。

```typescript
const run = await mastra.schedules.run('pinger')
```

对于Agent时间表，`claimId` uses `manual_<scheduleId>_<timestamp>`. For workflow schedules, `claimId` uses `sched_<scheduleId>_<timestamp>` and is reused as the workflow run ID.

#### `delete(id)` {/* #deleteid */}

删除计划。删除缺失的时间表是无操作的。

```typescript
await mastra.schedules.delete('pinger')
```

## 安排行为 {/* #schedule-behavior */}

* Agent计划 ID 使用`agent_` prefix. Workflow schedule IDs created through `mastra.schedules.create()` use the `schedule_` prefix.
* 线程Agent调度需要`resourceId` when `threadId` is set.
* 在Agent日程表上，`signalType`, `ifActive`, `ifIdle`, and `resourceId` require `threadId`. Workflow schedules accept `resourceId` without a thread.
* Workflow计划不接受仅限Agent的补丁字段，例如`prompt`, `signalType`, or `ifIdle`.
* `run()`立即发布手动触发并且不会更改存储的 cron 节奏。
* 时间表有三种状态：`active`, `paused`, and `completed`. A schedule becomes `completed` when it has no remaining automatic fires: after a one-off fires, when a bounded or exhausted cron has no future occurrence, or when declarative registration finds its timing has already passed. `update()` and `resume()` also mark exhausted cron schedules as completed. `run()` doesn't complete a one-off schedule.
* 更新中`runAt` on a one-off, or `endAt` on a cron schedule (`null` removes the bound), reactivates a `completed` schedule only if the resulting timing can still fire. A cron schedule with no occurrence before its new `endAt` remains completed.
* `list()`隐藏`completed` schedules unless you pass `status: 'completed'`.
