# `mastra.schedules`

**新增于：** `@mastra/core@1.50.0`

`mastra.schedules` 是持久化 cron 排程的 CRUD 服务，可创建、列出、更新、暂停、恢复、手动运行和删除 Agent 或 Workflow 排程。

用法和相关概念请参阅[排程](/docs/harness/schedules)。

## 投递保证 {/* #delivery-guarantees */}

定时发布采用尽力而为的方式，不保证至少投递一次。调度器会以原子操作认领一次触发，并在发布 Agent 或 Workflow 启动事件之前推进 `nextFireAt`。如果 cron 排程已无后续触发时机，它会在认领时标记为 `completed`。此状态仅表示没有剩余触发时机，不代表目标已启动或成功执行。

调度器对同一次已认领的触发最多尝试发布三次，前两次失败后分别等待 100 毫秒和 200 毫秒。传输层可能先接受事件再返回错误，因此重试可能以同一个 run ID 发布重复事件。

三次尝试均失败后，调度器会记录排程 ID、run ID、计划触发时间、`publicationOutcome: 'unknown'` 和 `automaticReplay: false`，调用配置的 `scheduler.onError` 钩子，并尝试记录结果为 `failed` 的触发事件。该失败只说明发布尝试的结果，不能证明目标从未启动。

尝试次数耗尽后，调度器不会重放这次触发。周期性排程仍保持活动状态，并可在下一个计划时间触发。终止的排程仍保持完成状态，触发历史中保留已记录的失败详情。

认领成功后，信息级 `Claimed schedule occurrence` 日志会标识排程 ID、run ID 和计划触发时间。对应的 `Published schedule occurrence` 日志表示传输层已接受事件。如果认领后既没有成功日志，也没有最终失败日志，就无法确认发布结果。这些日志不是持久状态：在认领事务提交后、写日志前发生崩溃，或日志刷新前发生崩溃，都可能没有日志记录。

如果发布进程在认领提交后终止，或确认信息丢失，该次触发可能被跳过，而不会留下失败的触发记录。替代调度器无法仅凭认领元数据或缺失的触发历史，区分事件未发布与事件在崩溃前已被接受。它不会重放该次触发，也不会阻止后续周期性触发。发布确认也不保证目标已执行，传输层重新投递仍可能产生重复事件。

手动重跑遗漏的任务前，请分别检查目标执行记录和传输记录。仅凭缺失的触发历史或一次发布失败，不能断定重跑是安全的。

## 用法示例 {/* #usage-example */}

创建 Agent 排程：

```typescript title="src/mastra/schedules.ts"
const schedule = await mastra.schedules.create({
  agentId: 'pinger',
  cron: '0 * * * *',
  prompt: 'Give me a status update.',
})
```

创建 Workflow 排程：

```typescript title="src/mastra/schedules.ts"
const schedule = await mastra.schedules.create({
  workflowId: 'daily-report',
  cron: '0 9 * * *',
  inputData: { reportType: 'summary' },
})
```

排程需要实现 schedules 域的存储适配器。支持的适配器包括 `@mastra/libsql`、`@mastra/pg`、`@mastra/mysql`、`@mastra/mongodb`、`@mastra/convex` 和 `@mastra/spanner`。

要在固定时间运行一次，请传入 `runAt` 而不是 `cron`：

```typescript
await mastra.schedules.create({
  workflowId: 'send-report',
  runAt: new Date(Date.now() + 60 * 60 * 1000), // One hour from now
})
```

```typescript
const schedule = await mastra.schedules.get('pinger')
```

### 更新排程 {/* #update-schedules */}

#### `update(id, patch)` {/* #updateid-patch */}

更新排程。修改 `cron` 或 `timezone` 会重新计算下次触发时间。将 `status` 从 `paused` 改为 `active` 也会重新计算。cron 不再有未来触发时机时，排程转为 `completed`。即使排程处于 `paused`，如果节奏变更后没有未来触发时机，该记录也会完成。修改已完成排程的节奏后，若新节奏仍能触发则重新激活，否则保持完成状态。

```typescript
const updated = await mastra.schedules.update('pinger', {
  cron: '*/30 * * * *',
  prompt: 'Give me a status update every 30 minutes.',
})
```

Agent 排程可更新 `cron`、`timezone`、`prompt`、`name`、`signalType`、`tagName`、`attributes`、`providerOptions`、`ifActive`、`ifIdle`、`metadata` 和 `status`。`threadId` 和 `resourceId` 不支持补丁更新；若要更换目标线程，请创建新排程。

Workflow 排程可更新 `cron`、`timezone`、`inputData`、`initialState`、`requestContext`、`resourceId`、`metadata` 和 `status`。对 Workflow 排程传入 `prompt`、`signalType` 或 `ifIdle` 等 Agent 专属补丁字段会抛出错误。

### 生命周期 {/* #lifecycle */}

#### `pause(id)` {/* #pauseid */}

暂停排程。暂停操作会持久化，且重复执行不会改变结果。暂停 `completed` 排程会抛出 `409` 错误。

```typescript
const paused = await mastra.schedules.pause('pinger')
```

#### `resume(id)` {/* #resumeid */}

恢复已暂停的排程，并从当前时间重新计算下次触发时间。单次排程保留原有 `runAt`；如果暂停期间已过了该时间，排程会在调度器下一次轮询时触发。暂停中的 cron 排程若无未来触发时机，会转为完成状态，而不会恢复。恢复 `completed` 排程会抛出 `409` 错误；要重新激活它，应更新触发时间。

```typescript
const active = await mastra.schedules.resume('pinger')
```

#### `run(id)` {/* #runid */}

立即手动触发排程一次，不改变其 cron 频率。

```typescript
const run = await mastra.schedules.run('pinger')
```

对于 Agent 排程，`claimId` 使用 `manual_<scheduleId>_<timestamp>`；对于 Workflow 排程，`claimId` 使用 `sched_<scheduleId>_<timestamp>`，并复用为 Workflow run ID。

#### `delete(id)` {/* #deleteid */}

删除排程。删除不存在的排程不会产生任何效果。

```typescript
await mastra.schedules.delete('pinger')
```

## 排程行为 {/* #schedule-behavior */}

- Agent 排程 ID 使用 `agent_` 前缀。通过 `mastra.schedules.create()` 创建的 Workflow 排程 ID 使用 `schedule_` 前缀。
- 带线程的 Agent 排程需要 `resourceId`，前提是设置了 `threadId`。
- 对 Agent 排程，`signalType`、`ifActive`、`ifIdle` 和 `resourceId` 都需要 `threadId`。Workflow 排程不使用线程也可接受 `resourceId`。
- Workflow 排程不接受 `prompt`、`signalType` 或 `ifIdle` 等 Agent 专属补丁字段。
- `run()` 会立即发布一次手动触发，不改变已存储的 cron 频率。
- 排程有 `active`、`paused` 和 `completed` 三种状态。没有剩余的自动触发时机时，排程会转为 `completed`：单次排程触发后、设有结束时间或已耗尽的 cron 排程没有未来触发时机时，或声明式注册发现计划时间已过时。`update()` 和 `resume()` 也会将已耗尽的 cron 排程标记为完成。`run()` 不会使单次排程完成。
- 更新单次排程的 `runAt`，或更新 cron 排程的 `endAt`（设为 `null` 可移除结束限制）时，只有新时间仍可触发，才会重新激活 `completed` 排程。如果新的 `endAt` 之前没有 cron 触发时机，排程仍保持完成状态。
- `list()` 默认隐藏 `completed` 排程；传入 `status: 'completed'` 才会显示。
