# Session

`Session` 是以会话 ID 注册的隔离运行时。多个会话可以共用同一资源；资源拥有其存储的线程及资源范围内的 Memory。Session 自行管理事件总线、线程绑定、状态、模式与模型选择、运行控制、审批、暂停、后续消息及显示状态。[`AgentController`](/reference/agent-controller/agent-controller-class) 提供共享的 Agent、配置、存储、工作区和服务。

通过 `controller.createSession()` 创建会话。直接构造 Session 或调用控制器内部的连接方法，不属于应用 API。

概念介绍见 [AgentController 概览](/docs/harness/agent-controller)。

## 使用示例 {/* #usage-example */}

以下示例使用受支持的控制器到会话调用流程。

```typescript
await controller.init()

const session = await controller.createSession({ resourceId: 'project-42' })
const unsubscribe = session.subscribe(event => {
  if (event.type === 'display_state_changed') {
    render(event.displayState)
  }
})

await session.sendMessage({ content: 'Review the current project.' })
unsubscribe()
```

## 方法 {/* #methods */}

### 身份与事件 {/* #identity-and-events */}

#### `getTags()` {/* #gettags */}

返回创建会话时提供的标签副本。

```typescript
const tags = session.getTags()
```

返回：`Record<string, string>`

#### `subscribe(listener)` {/* #subscribelistener */}

订阅此会话独立的事件总线。该方法返回取消订阅函数。

```typescript
const unsubscribe = session.subscribe(event => {
  console.log(event.type)
})

unsubscribe()
```

返回：`() => void`

### 消息与运行控制 {/* #messages-and-run-control */}

#### `sendMessage({ content, files?, requestContext?, author? })` {/* #sendmessage-content-files-requestcontext-author- */}

发送用户消息。如果当前没有活跃线程，会话会先创建一个线程。宿主已认证发送者时，请传入 `author`。

```typescript
await session.sendMessage({
  content: 'Summarize this file.',
  files: [{ data: fileContents, mediaType: 'text/plain', filename: 'notes.txt' }],
  author: { id: 'user-123' },
})
```

作者信息持久化在 `content.metadata.signal.author` 中。可通过 `getMessageAuthor(message)` 从 `@mastra/core/agent` 读取。若 `requestContext` 包含 `MASTRA_MESSAGE_AUTHOR_KEY`，且未显式传入 `author`，会话会使用该值。参见[保留键](/docs/server/request-context#reserved-keys)。

#### `queueMessage({ content, files?, requestContext?, author? })` {/* #queuemessage-content-files-requestcontext-author- */}

将消息加入队列供下次运行处理；会话空闲时则立即发送。作者元数据会随排队消息持久化。

#### `queueSignal(signal, { requestContext?, tracingContext?, tracingOptions? }?)` {/* #queuesignalsignal--requestcontext-tracingcontext-tracingoptions- */}

将带类型的信号加入队列供下次运行处理；会话空闲时则立即发送。信号会保留其 `type`、`tagName` 和 `attributes`。若需记录作者，请设置 `signal.author`；会话不会从 `requestContext` 自动填入作者，这与 `queueMessage()` 不同。

```typescript
await session.queueSignal({
  type: 'reactive',
  tagName: 'skill',
  attributes: { name: 'triage' },
  contents: 'Triage the new issue.',
})
```

#### `steer({ content, files?, requestContext?, author? })` {/* #steer-content-files-requestcontext-author- */}

中止当前运行，再将 `content` 作为新消息发送。可传入 `files` 附件，格式与 `sendMessage()` 相同：`{ data, mediaType, filename? }`。其中，文本文件的 `data` 为原始文本或 Base64 数据 URL；二进制文件则使用 Base64。

```typescript
await session.steer({ content: 'Focus on the failing tests.' })
```

#### `followUp({ content, files?, requestContext? })` {/* #followup-content-files-requestcontext- */}

运行中将后续消息入队；空闲时立即发送。传入 `files` 时，附件格式与 `steer()` 相同。

```typescript
await session.followUp({
  content: 'Then compare against this screenshot.',
  files: [{ data: screenshotBase64, mediaType: 'image/png', filename: 'expected.png' }],
})
```

#### `getCurrentRunId()` {/* #getcurrentrunid */}

返回当前流的运行 ID、已追踪的运行 ID；空闲时返回 `null`。

```typescript
const runId = session.getCurrentRunId()
```

返回：`string | null`

#### `abort()` {/* #abort */}

中止当前运行，并清除待处理暂停的显示状态。

```typescript
session.abort()
```

### 工作区 {/* #workspace */}

#### `getWorkspace()` {/* #getworkspace */}

返回为此会话解析出的工作区，并保留会话级覆盖配置。

工作区是可选的。若会话及 `AgentController` 都未配置工作区，会话仍可在没有文件系统或沙箱访问权限的情况下运行，此方法返回 `undefined`。使用前请检查返回值。

```typescript
const workspace = session.getWorkspace()
const skill = await workspace?.skills?.get('code-review')
```

返回：`Workspace | undefined`

### 会话授权 {/* #session-grants */}

会话范围内的授权可免提示自动批准工具调用。此类授权是临时的：会话重启时重置，且不会持久化。

#### `grantCategory(category)` {/* #grantcategorycategory */}

为当前会话授权一个工具类别。该类别的工具将自动获批。

```typescript
session.grantCategory('edit')
```

#### `grantTool(toolName)` {/* #granttooltoolname */}

为当前会话授权指定工具。

```typescript
session.grantTool('mastra_workspace_execute_command')
```

#### `getGrants()` {/* #getgrants */}

返回当前已授权的类别和工具。

```typescript
const grants = session.getGrants()
// { categories: string[], tools: string[] }
```

#### `hasCategoryGrant(category)` {/* #hascategorygrantcategory */}

返回指定类别是否具有仅存于内存的会话授权。

```typescript
const allowed = session.hasCategoryGrant('edit')
```

返回：`boolean`

#### `hasToolGrant(toolName)` {/* #hastoolgranttoolname */}

返回指定工具是否具有仅存于内存的会话授权。

```typescript
const allowed = session.hasToolGrant('write_file')
```

返回：`boolean`

### 工具审批 {/* #tool-approvals */}

#### `resolveToolApproval(toolName, scope?)` {/* #resolvetoolapprovaltoolname-scope */}

按显式工具规则、会话授权和类别规则计算后，返回实际生效的策略。

规则属于各自线程。将某次运行的 `RequestContext` 作为 `scope` 传入，可使用该运行所属线程的规则和授权。若以线程 ID 作为 `scope`，则以该线程的授权对照当前线程的规则。省略 `scope` 时使用当前线程。

```typescript
const policy = session.resolveToolApproval('execute_command')
const policyForRun = session.resolveToolApproval('write_file', requestContext)
```

返回：`PermissionPolicy`

#### `respondToToolApproval({ decision, toolCallId, requestContext?, declineContext? })` {/* #respondtotoolapproval-decision-toolcallid-requestcontext-declinecontext- */}

响应 `tool_approval_required` 事件产生的待处理工具审批请求。必须传入 `toolCallId` 以标识被暂停的调用，请使用事件中的 `toolCallId`。传入 `always_allow_category` 还会为该审批所属线程授权整个工具类别。

```typescript
session.respondToToolApproval({ decision: 'approve', toolCallId: event.toolCallId })
session.respondToToolApproval({ decision: 'decline', toolCallId: event.toolCallId })
session.respondToToolApproval({ decision: 'always_allow_category', toolCallId: event.toolCallId })
```

#### `respondToToolSuspension({ resumeData, address?, toolCallId?, requestContext? })` {/* #respondtotoolsuspension-resumedata-address-toolcallid-requestcontext- */}

使用应用提供的数据恢复暂停的工具调用。当前线程上的提示可传入 `toolCallId`。若需切换线程后恢复，请保存完整 `address`，即 `session.claimToolSuspension(toolCallId, runId)` 的返回值，并用它代替 `toolCallId`。

按地址恢复时，使用源线程的模式、模型及线程所拥有的偏好，而不选中该线程或替换当前线程的订阅。即使执行期间切换线程，工具状态回调仍绑定源线程。宿主拥有的自定义状态及权限规则仍由各线程共享。

进程重启后，可通过完整地址及控制器已配置的 Agent 恢复持久化暂停。恢复要求能够唯一确定来源 Agent，并通过现有的恢复授权检查。初始化失败时，该提示仍可重试，也不会结束其他线程的活跃运行。

```typescript
await session.respondToToolSuspension({
  toolCallId: event.toolCallId,
  resumeData: ['src'],
})
```

对于 `submit_plan`，传入 `{ action: 'approved' }` 或 `{ action: 'rejected', feedback }`。获批后，工具恢复前可以切换到 `transitionsTo` 配置的模式。

### Token 用量 {/* #token-usage */}

#### `getTokenUsage()` {/* #gettokenusage */}

返回当前线程累计 Token 用量的副本。

每个步骤结束后，执行中的运行会将 Token 用量保存到自身线程，包括恢复运行时 UI 已切换到另一线程的情况。如果存储操作失败，执行的所有者会保留测得的用量，并在下个步骤重试。仅订阅线程的会话只显示已保存的总量，不重复统计重放的步骤，也不再次保存用量。

```typescript
const usage = session.getTokenUsage()
// { promptTokens, completionTokens, totalTokens, ... }
```

## 身份 {/* #identity */}

`session.identity` 标识进程内的会话宿主：资源 ID、会话 `id` 及 `ownerId`。`id` 和 `ownerId` 在宿主生命周期内保持稳定，切换资源 ID 时不会改变。AgentController 不持久化活跃会话，也不会将这些值复制到 `SessionRecord`。

### `session.identity.getId()` {/* #sessionidentitygetid */}

返回稳定的会话 ID。

```typescript
const sessionId = session.identity.getId()
```

### `session.identity.getOwnerId()` {/* #sessionidentitygetownerid */}

返回进程内会话宿主稳定的所有者 ID。此值并非持久化的线程所有者。

```typescript
const ownerId = session.identity.getOwnerId()
```

### `session.identity.getResourceId()` {/* #sessionidentitygetresourceid */}

返回当前资源 ID。

```typescript
const resourceId = session.identity.getResourceId()
```

### `session.identity.getDefaultResourceId()` {/* #sessionidentitygetdefaultresourceid */}

返回创建会话时使用的资源 ID。

```typescript
const defaultResourceId = session.identity.getDefaultResourceId()
```

如需更改资源 ID，请调用 [`controller.setResourceId()`](/reference/agent-controller/agent-controller-class#setresourceidsession--resourceid-)；此操作也会清除当前线程。切换资源不会影响会话 `id` 和 `ownerId`。

## 线程 {/* #thread */}

`session.thread` 管理当前线程绑定及资源范围内的线程操作。配置存储后，已保存的线程和消息可在重建控制器后继续存在。会话创建或切换线程时，会从当前线程恢复模式、模型、思考级别、Token 用量、待处理运行及所有权等对话设置。活跃会话及其事件总线不会持久化。

新线程会把 Session 宿主的 `ownerId` 存入保留字段 `metadata.ownerId` 和 `metadata.createdBy`。克隆线程时，这两个字段均使用执行克隆的 Session 宿主。对没有 `metadata.ownerId` 的旧线程，读取时会视为由当前 Session 宿主拥有，但不会写入回填数据。

### `session.thread.create({ title?, id?, requestContext? })` {/* #sessionthreadcreate-title-id-requestcontext- */}

创建线程，将会话绑定到该线程并打开事件流。如果 Memory 是读取已登录用户的函数，请传入 `requestContext`。

对于以 `createInitialThread: false` 创建的会话，在首次绑定前显式选择的模式、模型及线程偏好会用于初始化第一个新线程。`ensureId()` 和第一条消息也遵循此规则。若创建失败，这些选择仍可用于重试。

会话绑定过一个对话后，每个新线程都会使用控制器默认值，而不沿用上个对话的选择，即使清除或删除绑定也是如此。打开已有线程时，则恢复该线程的设置，不使用尚未绑定时的初始选择。

```typescript
const thread = await session.thread.create({
  id: 'thread-7',
  title: 'Investigate login failure',
})
```

返回：`Promise<AgentControllerThread>`

### `session.thread.rename({ title })` {/* #sessionthreadrename-title- */}

重命名当前已保存的线程。

```typescript
await session.thread.rename({ title: 'Fix login failure' })
```

### `session.thread.clone({ sourceThreadId?, title?, resourceId?, requestContext? })` {/* #sessionthreadclone-sourcethreadid-title-resourceid-requestcontext- */}

克隆自己拥有的线程及其消息，再将会话绑定到克隆线程。如果 Memory 是读取已登录用户的函数，请传入 `requestContext`。

```typescript
const clone = await session.thread.clone({
  sourceThreadId: 'thread-7',
  title: 'Alternative approach',
})
```

返回：`Promise<AgentControllerThread>`

### `session.thread.switch({ threadId, emitEvent?, requestContext? })` {/* #sessionthreadswitch-threadid-emitevent-requestcontext- */}

切换至自己拥有的已保存线程，并恢复其模式、模型及观察记忆设置。如果 Memory 是读取已登录用户的函数，请传入 `requestContext`。

离开线程时，只有当前运行由此会话发起，才会取消该本地执行。若会话仅在监听另一会话发起的运行，切换时只会解除监听，不会取消运行。判断依据是当前操作的发起者，而非线程所有者。已暂停的工具提示可供日后恢复。

```typescript
await session.thread.switch({ threadId: 'thread-8' })
```

### `session.thread.delete({ threadId, requestContext? })` {/* #sessionthreaddelete-threadid-requestcontext- */}

删除自己拥有的线程。删除当前线程时也会清除绑定。如果 Memory 是读取已登录用户的函数，请传入 `requestContext`。

```typescript
await session.thread.delete({ threadId: 'thread-8' })
```

### `session.thread.getId()` {/* #sessionthreadgetid */}

返回当前线程 ID；未绑定线程时返回 `null`。

```typescript
const threadId = session.thread.getId()
```

### `session.thread.ensureId({ requestContext? })` {/* #sessionthreadensureid-requestcontext- */}

返回当前线程 ID；若尚未绑定线程，则创建新线程并绑定。并发调用会共用同一线程。适用于以 `createInitialThread: false` 创建的会话。

```typescript
const threadId = await session.thread.ensureId()
```

### `session.thread.getOwner({ threadId? })` {/* #sessionthreadgetowner-threadid- */}

返回线程的持久化所有者。省略 `threadId` 时读取当前线程。未选中线程时返回 `undefined`。对没有所有者信息的旧线程，返回 Session 宿主的 `ownerId`，但不写入回填数据。

```typescript
const ownerId = await session.thread.getOwner()
```

返回：`Promise<string | undefined>`

### `session.thread.transferOwnership({ toOwnerId, threadId? })` {/* #sessionthreadtransferownership-toownerid-threadid- */}

将 `toOwnerId` 存入线程的 `metadata.ownerId`，并发出 `thread_owner_changed` 事件。原有的 `metadata.createdBy` 不变。省略 `threadId` 时转移当前线程；提供 `threadId` 时转移该会话资源下指定线程，当前线程保持不变。

```typescript
await session.thread.transferOwnership({
  toOwnerId: 'user-456',
  threadId: 'thread-123',
})
```

返回：`Promise<void>`

所有权转移在单个进程内串行执行。若存储型应用需要跨进程、持久化的比较并设置操作，应先在自身存储中完成，再调用此方法同步结果。

成功更改后会发出：

```typescript
const event = {
  type: 'thread_owner_changed',
  threadId: 'thread-7',
  fromOwnerId: 'user-123',
  toOwnerId: 'user-456',
}
```

运行开始时会记录所有权快照。在 Agent 工具及动态运行时函数中，`AgentControllerRequestContext.threadOwnerId` 在该运行期间保持不变；转移要到下一次运行才可见。`AgentControllerRequestContext.session.ownerId` 仍标识进程内的 Session 宿主。

### `session.thread.list(options?)` {/* #sessionthreadlistoptions */}

列出存储中的线程。默认仅返回当前资源的线程，并隐藏临时分叉出来的子 Agent 线程。

```typescript
const threads = await session.thread.list()
const allThreads = await session.thread.list({ allResources: true })
const everything = await session.thread.list({ includeForkedSubagents: true })
```

### `session.thread.getById({ threadId })` {/* #sessionthreadgetbyid-threadid- */}

按 ID 返回单个线程；不存在时返回 `null`。

```typescript
const thread = await session.thread.getById({ threadId: 'thread-abc123' })
```

### `session.thread.listActiveMessages(options?)` {/* #sessionthreadlistactivemessagesoptions */}

读取当前线程的消息。未绑定线程时返回空数组。

```typescript
const messages = await session.thread.listActiveMessages({ limit: 50 })
```

### `session.thread.listMessages({ threadId, limit? })` {/* #sessionthreadlistmessages-threadid-limit- */}

读取指定线程的消息。

```typescript
const messages = await session.thread.listMessages({ threadId: 'thread-abc123' })
```

消息读取方法 `listActiveMessages`、`listMessages` 和 `firstUserMessage` 返回 `MastraDBMessage` 对象；`firstUserMessages` 返回以线程 ID 为键的 `Map<string, MastraDBMessage>`。每条消息都有 `role`、`id`、`createdAt` 和 `content` 对象；后者包含 `content.format` 及 `content.parts` 数组。文本、推理、工具调用及附件应从 `content.parts` 读取。系统提醒和通知等信号会作为独立消息返回，其 `role: 'signal'`。

### `session.thread.firstUserMessage({ threadId })` {/* #sessionthreadfirstusermessage-threadid- */}

读取线程的第一条用户消息；没有时返回 `null`。

```typescript
const firstMsg = await session.thread.firstUserMessage({
  threadId: 'thread-abc123',
})
```

### `session.thread.firstUserMessages({ threadIds })` {/* #sessionthreadfirstusermessages-threadids- */}

一次读取多个线程各自的第一条用户消息，并以映射形式返回。

```typescript
const firstByThread = await session.thread.firstUserMessages({
  threadIds: ['thread-a', 'thread-b'],
})
```

### `session.thread.getSetting({ key })` {/* #sessionthreadgetsetting-key- */}

读取当前线程元数据中的一个设置。

```typescript
const value = await session.thread.getSetting({ key: 'omThreshold' })
```

### `session.thread.setSetting({ key, value })` {/* #sessionthreadsetsetting-key-value- */}

将设置写入当前线程元数据。

```typescript
await session.thread.setSetting({ key: 'omThreshold', value: 0.8 })
```

### `session.thread.deleteSetting({ key })` {/* #sessionthreaddeletesetting-key- */}

从当前线程元数据删除设置。

```typescript
await session.thread.deleteSetting({ key: 'omThreshold' })
```

### `session.mode.get()` {/* #sessionmodeget */}

返回当前模式 ID。

```typescript
const modeId = session.mode.get()
```

### `session.mode.resolve()` {/* #sessionmoderesolve */}

返回当前模式对应的完整 `AgentControllerMode` 对象，依据控制器配置的模式解析。

```typescript
const mode = session.mode.resolve()
```

### `session.mode.switch({ modeId })` {/* #sessionmodeswitch-modeid- */}

切换到另一模式，将模式持久化到当前线程，并发出 `mode_changed` 事件。当前模型保持不变；如果宿主为不同模式分配不同模型，需要另行切换模型。

```typescript
await session.mode.switch({ modeId: 'build' })
```

## 模型 {/* #model */}

`session.model` 管理会话当前选择的唯一模型。

### `session.model.get()` {/* #sessionmodelget */}

返回当前模型 ID。

```typescript
const modelId = session.model.get()
```

### `session.model.displayName()` {/* #sessionmodeldisplayname */}

返回当前模型 ID 的最后一段，作为简短显示名称。未选择模型时返回 `'unknown'`。

```typescript
const name = session.model.displayName()
```

### `session.model.hasSelection()` {/* #sessionmodelhasselection */}

检查当前是否已选择模型。

```typescript
if (session.model.hasSelection()) {
  // Ready to send messages
}
```

### `session.model.set({ modelId })` {/* #sessionmodelset-modelid- */}

仅在内存中设置当前模型，不持久化、不报告模型使用情况，也不发出 `model_changed` 事件。

```typescript
session.model.set({ modelId: '__GATEWAY_ANTHROPIC_MODEL_SONNET__' })
```

### `session.model.switch(modelId, options?)` {/* #sessionmodelswitchmodelid-options */}

切换会话的当前模型。模型 ID 会持久化到线程的 `currentModelId`，并在恢复该线程时恢复。此方法还会向控制器的 `modelUseCountTracker` 报告选择，并发出 `model_changed` 事件。

传入 `{ thinkingLevel }` 作为第二个参数，可在一次操作中切换并持久化模型和思考级别。级别必须是 `'off'`、`'low'`、`'medium'`、`'high'`、`'xhigh'` 或 `'max'`，且控制器的状态 Schema 必须接受该值。发出事件前会先更新两个当前值。省略该选项时，保留现有的思考级别覆盖值。每个 `model_changed` 事件都包含当前的 `{ modelId, thinkingLevel }`，即使思考级别未变也是如此。会话未设置覆盖值时，级别为 `undefined`。

```typescript
await session.model.switch('__GATEWAY_ANTHROPIC_MODEL_SONNET__', {
  thinkingLevel: 'high',
})
```

客户端 SDK 提供等效的 `session.switchModel(modelId, { thinkingLevel })` 操作。

## 观察记忆 {/* #observational-memory */}

观察记忆的模型选择按角色分组在 `session.om.observer` 和 `session.om.reflector` 下。两种角色提供相同方法。选择意图与最终生效的具体模型 ID 是两个不同的值。

### `session.om.observer.model()` / `session.om.reflector.model()` {/* #sessionomobservermodel--sessionomreflectormodel */}

返回该角色配置的模型。

```typescript
const observerModel = session.om.observer.model()
const reflectorModel = session.om.reflector.model()
```

返回：`'auto' | string | undefined`

`'auto'` 表示跟随当前主模型；其他字符串表示显式模型 ID。

### `session.om.observer.modelId()` / `session.om.reflector.modelId()` {/* #sessionomobservermodelid--sessionomreflectormodelid */}

返回该角色实际生效的具体模型 ID。对于自动选择，控制器会以角色、当前主模型 ID 及只读会话状态调用 `omConfig.resolveAutoModelId`。如果解析器未返回模型或抛出错误，该角色会使用具体的 `omConfig` 后备模型。

```typescript
const observer = session.om.observer.modelId()
const reflector = session.om.reflector.modelId()
```

### `session.om.observer.threshold()` / `session.om.reflector.threshold()` {/* #sessionomobserverthreshold--sessionomreflectorthreshold */}

返回该角色以 Token 计的阈值（观察者的观察阈值，反思者的反思阈值）；未设置时返回 `undefined`。

```typescript
const observationThreshold = session.om.observer.threshold()
const reflectionThreshold = session.om.reflector.threshold()
```

### `session.om.observer.switchModel({ modelId })` / `session.om.reflector.switchModel({ modelId })` {/* #sessionomobserverswitchmodel-modelid---sessionomreflectorswitchmodel-modelid- */}

在自动选择与显式选择之间切换某个角色。传入 `'auto'` 可跟随当前主模型，传入具体模型 ID 则固定该角色的模型。切换为自动选择会清除该角色过时的具体模型 ID。另一个角色不受影响。发出的 `om_model_changed` 事件仍包含最终生效的具体 `modelId`。

```typescript
await session.om.observer.switchModel({ modelId: 'auto' })
await session.om.reflector.switchModel({
  modelId: '__GATEWAY_ANTHROPIC_MODEL_HAIKU__',
})
```

### `session.om.observer.resolvedModel()` / `session.om.reflector.resolvedModel()` {/* #sessionomobserverresolvedmodel--sessionomreflectorresolvedmodel */}

通过已配置的模型网关，将该角色的模型 ID 解析为模型实例。若未设置模型 ID 或未配置解析器，返回 `undefined`。

```typescript
const observerModel = session.om.observer.resolvedModel()
const reflectorModel = session.om.reflector.resolvedModel()
```

## 权限 {/* #permissions */}

`session.permissions` 管理 `session.state` 中的工具审批策略，即审批解析时使用的按类别和按工具规则。这些规则与[会话授权](#session-grants)中描述的内存授权不同。授权随活跃会话重置。除非宿主恢复相应的会话状态，否则权限规则也不会持久化。

### `session.permissions.getRules()` {/* #sessionpermissionsgetrules */}

返回当前权限规则；未设置时返回空规则（`{ categories: {}, tools: {} }`）。

```typescript
const rules = session.permissions.getRules()
// { categories: { execute: 'ask' }, tools: { dangerous_tool: 'deny' } }
```

### `session.permissions.setForCategory({ category, policy })` {/* #sessionpermissionssetforcategory-category-policy- */}

为工具类别设置审批策略（`'allow' | 'ask' | 'deny'`）。更改持久化到会话状态后，此方法才完成。

```typescript
await session.permissions.setForCategory({ category: 'execute', policy: 'ask' })
```

### `session.permissions.setForTool({ toolName, policy })` {/* #sessionpermissionssetfortool-toolname-policy- */}

为指定工具设置审批策略。工具级策略优先于类别级策略。持久化完成后，此方法才完成。

```typescript
await session.permissions.setForTool({ toolName: 'dangerous_tool', policy: 'deny' })
```

`session.subagents` 管理子 Agent 配置，目前在 `session.subagents.model` 下提供子 Agent 模型选择。

## 状态 {/* #state */}

`session.state` 同时提供当前对话由线程管理的偏好与由宿主管理的状态。更新会串行执行，并按传给 AgentController 的 `stateSchema` 验证。可见的状态变化会发出 `state_changed`。

线程管理的偏好包括思考级别、观察记忆设置及子 Agent 模型选择。切换线程不会改变宿主管理的自定义字段和权限规则，也不会持久化它们。

排队的写入会在异步更新及验证期间保留其源线程。因此，写入尚未完成时从 A 切换到 B，不会把 A 的偏好应用于 B。宿主字段更新仍影响宿主。保留运行的源线程视图与同一线程的当前视图共用更新顺序。恢复的运行可看到暂停期间的编辑。若没有源地址，影响对话显示的事件只会在该源为当前线程时发出。

在工具的控制器请求上下文中，`sessionId`、`resourceId` 和 `threadId` 分别标识会话、资源及当前线程。`state` 是创建上下文时获取的快照。写入后如需读取源线程的最新状态，请使用 `getState()` 或 `session.state.get()`。

### `session.state.get()` {/* #sessionstateget */}

返回当前状态快照的只读副本。

```typescript
const state = session.state.get()
```

### `session.state.set(updates)` {/* #sessionstatesetupdates */}

将部分更新合并到状态中。队列按顺序处理并发调用，在发出包含变更键的 `state_changed` 事件前，会按 Schema 验证更新。

```typescript
await session.state.set({ yolo: true })
```

### `session.state.update(updater)` {/* #sessionstateupdateupdater */}

基于当前快照运行更新函数，并在写入队列中原子地应用结果。需要读取最新状态后再修改时，请使用此方法。更新函数返回可合并的 `updates`、可选的 `events`，以及 `result` 值；后者也是 `update()` 最终返回的值。

```typescript
const added = await session.state.update(current => ({
  updates: { count: (current.count ?? 0) + 1 },
  result: (current.count ?? 0) + 1,
}))
```

## 持久化边界 {/* #persistence-boundaries */}

`Session` 是实时运行时对象。控制器或进程重建后，其事件总线、任意自定义状态、权限规则、临时授权、后续消息和活跃流不会自动恢复。宿主必须自行恢复所需的宿主状态。

配置存储后，线程、消息及 Token 用量会持久化；线程设置可恢复模式、模型和受支持的偏好。可恢复的设置包括思考级别、观察记忆，以及按 Agent 类型覆盖的子 Agent 模型选择。已持久化的暂停运行可通过完整暂停地址及来源 Agent 恢复，但任意自定义状态仍需由宿主管理持久化。

运行保留源线程视图期间，即使尽力持久化元数据失败，成功写入内存的偏好在返回该线程时仍可使用。冷启动只能恢复已持久化的设置和控制器默认值。

聊天渠道可以映射回已保存的线程；不过，`AgentControllerChannels` 仍在内存中维护渠道到会话的映射及自动审批状态。
