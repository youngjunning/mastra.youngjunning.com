# 会议

一个`Session`是在一个会话 ID 下注册的隔离运行时。多个会话可以共享一个资源，该资源拥有其存储的线程和资源范围的内存。它拥有其事件总线、线程绑定、状态、模式和模型选择、运行控制、批准、暂停、后续和显示状态。这[`AgentController`](/reference/agent-controller/agent-controller-class)提供共享Agent、配置、存储、Workspace和服务。

通过创建会话`controller.createSession()`. Direct construction and controller wiring methods aren't application APIs.

有关概念性介绍，请参阅[AgentController overview](/docs/harness/agent-controller).

## 使用示例 {/* #usage-example */}

以下示例使用受支持的控制器到会话流。

```typescript
await controller.init()

const session = await controller.createSession({ resourceId: 'project-42' })
const unsubscribe = session.subscribe(event => {
  if (event.type === 'display_state_changed') {
    render(event.displayState)
  }
})

await session.sendMessage({ content: 'Review the current project.' })
unsubscribe()
```

## 方法 {/* #methods */}

### 身份和事件 {/* #identity-and-events */}

#### `getTags()` {/* #gettags */}

返回创建会话时提供的标签的副本。

```typescript
const tags = session.getTags()
```

返回：`Record<string, string>`

#### `subscribe(listener)` {/* #subscribelistener */}

订阅此会话的隔离事件总线。该方法返回一个取消订阅函数。

```typescript
const unsubscribe = session.subscribe(event => {
  console.log(event.type)
})

unsubscribe()
```

返回：`() => void`

### 消息和运行控制 {/* #messages-and-run-control */}

#### `sendMessage({ content, files?, requestContext?, author? })` {/* #sendmessage-content-files-requestcontext-author- */}

发送用户消息。当没有线程处于活动状态时，会话首先创建一个线程。经过`author` when the host has authenticated the sender.

```typescript
await session.sendMessage({
  content: 'Summarize this file.',
  files: [{ data: fileContents, mediaType: 'text/plain', filename: 'notes.txt' }],
  author: { id: 'user-123' },
})
```

作者坚持下`content.metadata.signal.author`. Read it with `getMessageAuthor(message)` from `@mastra/core/agent`. When `requestContext` carries `MASTRA_MESSAGE_AUTHOR_KEY`, the session uses that value if `author` is omitted. See [Reserved keys](/docs/server/request-context#reserved-keys).

#### `queueMessage({ content, files?, requestContext?, author? })` {/* #queuemessage-content-files-requestcontext-author- */}

将消息排队以供下次运行，或在会话空闲时立即发送。作者元数据与排队的消息一起保留。

#### `queueSignal(signal, { requestContext?, tracingContext?, tracingOptions? }?)` {/* #queuesignalsignal--requestcontext-tracingcontext-tracingoptions- */}

将键入的信号排队以供下次运行，或在会话空闲时立即发送。信号保持不变`type`, `tagName`, and `attributes`. Set `signal.author` to record an author, because the session doesn't stamp one from `requestContext` as it does for `queueMessage()`.

```typescript
await session.queueSignal({
  type: 'reactive',
  tagName: 'skill',
  attributes: { name: 'triage' },
  contents: 'Triage the new issue.',
})
```

#### `steer({ content, files?, requestContext?, author? })` {/* #steer-content-files-requestcontext-author- */}

中止当前运行，然后发送`content` as a new message. Pass `files` to attach files in the same shape as `sendMessage()`: `{ data, mediaType, filename? }`, where `data` is raw text or a base64 data URL for text files, and base64 for binary files.

```typescript
await session.steer({ content: 'Focus on the failing tests.' })
```

#### `followUp({ content, files?, requestContext? })` {/* #followup-content-files-requestcontext- */}

在运行处于活动状态时对后续操作进行排队，或在空闲时立即发送它。经过`files` to attach files the same way as `steer()`.

```typescript
await session.followUp({
  content: 'Then compare against this screenshot.',
  files: [{ data: screenshotBase64, mediaType: 'image/png', filename: 'expected.png' }],
})
```

#### `getCurrentRunId()` {/* #getcurrentrunid */}

返回活动流运行标识符、跟踪的运行标识符，或者`null` while idle.

```typescript
const runId = session.getCurrentRunId()
```

返回：`string | null`

#### `abort()` {/* #abort */}

中止活动运行并清除挂起的暂停显示状态。

```typescript
session.abort()
```

### 工作空间 {/* #workspace */}

#### `getWorkspace()` {/* #getworkspace */}

返回为此会话解析的Workspace。这保留了会话级覆盖。

Workspace是可选的。当会话和`AgentController` configures one, the session still runs without filesystem or sandbox access, and this returns `undefined`. Check the result before using it.

```typescript
const workspace = session.getWorkspace()
const skill = await workspace?.skills?.get('code-review')
```

返回：`Workspace | undefined`

### 会议补助金 {/* #session-grants */}

会话范围授予自动批准Tool而无需提示。授权是短暂的：它们会在会话重新启动时重置并且永远不会保留。

#### `grantCategory(category)` {/* #grantcategorycategory */}

为当前会话授予Tool类别。此类别中的Tool是自动批准的。

```typescript
session.grantCategory('edit')
```

#### `grantTool(toolName)` {/* #granttooltoolname */}

为当前会话授予特定Tool。

```typescript
session.grantTool('mastra_workspace_execute_command')
```

#### `getGrants()` {/* #getgrants */}

返回当前授予的类别和Tool。

```typescript
const grants = session.getGrants()
// { categories: string[], tools: string[] }
```

#### `hasCategoryGrant(category)` {/* #hascategorygrantcategory */}

返回类别是否具有内存中会话授权。

```typescript
const allowed = session.hasCategoryGrant('edit')
```

返回：`boolean`

#### `hasToolGrant(toolName)` {/* #hastoolgranttoolname */}

返回Tool是否具有内存中会话授权。

```typescript
const allowed = session.hasToolGrant('write_file')
```

返回：`boolean`

### Tool批准 {/* #tool-approvals */}

#### `resolveToolApproval(toolName, scope?)` {/* #resolvetoolapprovaltoolname-scope */}

应用显式Tool规则、会话授权和类别规则后返回有效策略。

规则属于每个线程。通过跑步`RequestContext` as `scope` to use the rules and grants of the thread that run belongs to. A thread ID as `scope` checks that thread's grants against the current thread's rules. Without `scope`, the current thread is used.

```typescript
const policy = session.resolveToolApproval('execute_command')
const policyForRun = session.resolveToolApproval('write_file', requestContext)
```

返回：`PermissionPolicy`

#### `respondToToolApproval({ decision, toolCallId, requestContext?, declineContext? })` {/* #respondtotoolapproval-decision-toolcallid-requestcontext-declinecontext- */}

响应由以下人员提出的待处理Tool批准请求`tool_approval_required` event. `toolCallId` is required and identifies the parked call, so pass the `toolCallId` from the event. Pass `always_allow_category` to also grant the tool's whole category for the gate's thread.

```typescript
session.respondToToolApproval({ decision: 'approve', toolCallId: event.toolCallId })
session.respondToToolApproval({ decision: 'decline', toolCallId: event.toolCallId })
session.respondToToolApproval({ decision: 'always_allow_category', toolCallId: event.toolCallId })
```

#### `respondToToolSuspension({ resumeData, address?, toolCallId?, requestContext? })` {/* #respondtotoolsuspension-resumedata-address-toolcallid-requestcontext- */}

使用应用程序提供的数据恢复暂停的Tool。供应`toolCallId` for a prompt on the active thread. To resume after switching threads, retain the full `address` returned by `session.claimToolSuspension(toolCallId, runId)` and pass it instead of `toolCallId`.

寻址恢复使用源线程的模式、模型和线程拥有的首选项，而不选择该线程或替换活动线程的订阅。即使您在执行期间切换线程，Tool状态回调仍然绑定到源。主机拥有的自定义状态和权限规则保持共享。

进程重新启动后，完整地址可以通过控制器配置的Agent恢复持久挂起。恢复需要唯一标识的始发Agent和现有的恢复授权检查。设置失败会使提示可以重试，而无需完成另一个线程的活动运行。

```typescript
await session.respondToToolSuspension({
  toolCallId: event.toolCallId,
  resumeData: ['src'],
})
```

为了`submit_plan`, pass `{ action: 'approved' }` or `{ action: 'rejected', feedback }`. Approval can switch to the mode configured by `transitionsTo` before the tool resumes.

### 代币使用 {/* #token-usage */}

#### `getTokenUsage()` {/* #gettokenusage */}

返回活动线程的运行令牌使用计数的副本。

每个步骤完成时，执行运行都会将令牌使用情况保存到其自己的线程中，包括在选择另一个线程时恢复的运行。如果存储操作失败，执行所有者将保留测量的使用情况并重试下一步。仅订阅线程的会话会显示其保存的总数，而不会再次计算重播的步骤或保存使用情况。

```typescript
const usage = session.getTokenUsage()
// { promptTokens, completionTokens, totalTokens, ... }
```

## 身份 {/* #identity */}

`session.identity`标识进程本地会话主机：资源 ID 和会话`id`, plus an `ownerId`. The `id` and `ownerId` are stable for the life of the host and don't change when the resource ID is switched. AgentController doesn't persist the live session or mirror these values to a `SessionRecord`.

### `session.identity.getId()` {/* #sessionidentitygetid */}

返回稳定的会话标识符。

```typescript
const sessionId = session.identity.getId()
```

### `session.identity.getOwnerId()` {/* #sessionidentitygetownerid */}

返回进程本地会话主机的稳定所有者标识符。该值不是持久线程所有者。

```typescript
const ownerId = session.identity.getOwnerId()
```

### `session.identity.getResourceId()` {/* #sessionidentitygetresourceid */}

返回当前资源 ID。

```typescript
const resourceId = session.identity.getResourceId()
```

### `session.identity.getDefaultResourceId()` {/* #sessionidentitygetdefaultresourceid */}

返回创建会话所用的资源 ID。

```typescript
const defaultResourceId = session.identity.getDefaultResourceId()
```

要更改资源 ID，请使用[`controller.setResourceId()`](/reference/agent-controller/agent-controller-class#setresourceidsession--resourceid-), which also clears the active thread. The session `id` and `ownerId` aren't affected by resource switches.

## 线 {/* #thread */}

`session.thread`拥有活动线程绑定和资源范围的线程操作。配置存储后，存储的线程和消息可以在控制器重新创建后继续存在。当会话创建或切换线程时，会话设置（例如模式、模型、思维级别、令牌使用、挂起运行和所有权）将从活动线程中恢复。实时会话及其事件总线不会持续存在。

新线程存储会话主机的`ownerId` in the reserved `metadata.ownerId` and `metadata.createdBy` fields. Clones use the cloning Session host for both fields. Existing threads without `metadata.ownerId` read as owned by the current Session host without writing a backfill.

### `session.thread.create({ title?, id?, requestContext? })` {/* #sessionthreadcreate-title-id-requestcontext- */}

创建一个线程，将会话绑定到它，然后打开其事件流。经过`requestContext` when memory is a function that reads the signed-in user.

对于使用以下命令创建的会话`createInitialThread: false`, explicit mode, model, and thread-preference selections made before its first binding seed the first new thread. This also applies to `ensureId()` and the first message. Failed creation leaves those selections available for retry.

会话绑定对话后，每个新线程都会使用控制器默认值而不是前一个对话的选择，即使您清除或删除绑定也是如此。打开现有线程会恢复该线程的设置，而不是应用未绑定的启动选择。

```typescript
const thread = await session.thread.create({
  id: 'thread-7',
  title: 'Investigate login failure',
})
```

返回：`Promise<AgentControllerThread>`

### `session.thread.rename({ title })` {/* #sessionthreadrename-title- */}

重命名活动的存储线程。

```typescript
await session.thread.rename({ title: 'Fix login failure' })
```

### `session.thread.clone({ sourceThreadId?, title?, resourceId?, requestContext? })` {/* #sessionthreadclone-sourcethreadid-title-resourceid-requestcontext- */}

克隆拥有的线程及其消息，然后将会话绑定到克隆。经过`requestContext` when memory is a function that reads the signed-in user.

```typescript
const clone = await session.thread.clone({
  sourceThreadId: 'thread-7',
  title: 'Alternative approach',
})
```

返回：`Promise<AgentControllerThread>`

### `session.thread.switch({ threadId, emitEvent?, requestContext? })` {/* #sessionthreadswitch-threadid-emitevent-requestcontext- */}

切换到拥有的存储线程并水合其模式、模型和观察内存设置。经过`requestContext` when memory is a function that reads the signed-in user.

仅当此会话启动时，切换离开才会取消正在运行的本地执行。侦听另一个会话运行的会话会分离，但不会取消该运行。这遵循当前操作的发起者，而不是线程的所有权。停放的Tool提示仍可用于稍后恢复。

```typescript
await session.thread.switch({ threadId: 'thread-8' })
```

### `session.thread.delete({ threadId, requestContext? })` {/* #sessionthreaddelete-threadid-requestcontext- */}

删除拥有的线程。删除活动线程也会清除当前绑定。经过`requestContext` when memory is a function that reads the signed-in user.

```typescript
await session.thread.delete({ threadId: 'thread-8' })
```

### `session.thread.getId()` {/* #sessionthreadgetid */}

返回活动线程 ID，或者`null` when no thread is bound.

```typescript
const threadId = session.thread.getId()
```

### `session.thread.ensureId({ requestContext? })` {/* #sessionthreadensureid-requestcontext- */}

返回活动线程 ID，当没有绑定时创建并绑定一个新线程。并发调用共享一个线程。将其与使用以下命令创建的会话一起使用`createInitialThread: false`.

```typescript
const threadId = await session.thread.ensureId()
```

### `session.thread.getOwner({ threadId? })` {/* #sessionthreadgetowner-threadid- */}

返回线程的持久所有者。忽略`threadId` to read the active thread. The method returns `undefined` when no thread is selected. An owner-less legacy thread returns the Session host's `ownerId` without writing a backfill.

```typescript
const ownerId = await session.thread.getOwner()
```

返回：`Promise<string | undefined>`

### `session.thread.transferOwnership({ toOwnerId, threadId? })` {/* #sessionthreadtransferownership-toownerid-threadid- */}

店铺`toOwnerId` in the thread's `metadata.ownerId` and emit `thread_owner_changed`. The original `metadata.createdBy` value doesn't change. Without `threadId`, this transfers the active thread. With `threadId`, it transfers that thread of the session's resource and the active thread stays the same.

```typescript
await session.thread.transferOwnership({
  toOwnerId: 'user-456',
  threadId: 'thread-123',
})
```

返回：`Promise<void>`

传输在一个进程内串行进行。需要持久的跨进程比较和设置的存储支持的应用程序应首先在自己的存储中执行它，然后调用此方法来镜像结果。

成功的更改会发出：

```typescript
const event = {
  type: 'thread_owner_changed',
  threadId: 'thread-7',
  fromOwnerId: 'user-123',
  toOwnerId: 'user-456',
}
```

启动时运行快照所有权。在AgentTool和动态运行时函数中，`AgentControllerRequestContext.threadOwnerId` remains unchanged for the run's lifetime. A transfer becomes visible on the next run. `AgentControllerRequestContext.session.ownerId` continues to identify the process-local Session host.

### `session.thread.list(options?)` {/* #sessionthreadlistoptions */}

列出存储中的线程。默认情况下，仅返回当前资源的线程，并且隐藏临时分叉子Agent线程。

```typescript
const threads = await session.thread.list()
const allThreads = await session.thread.list({ allResources: true })
const everything = await session.thread.list({ includeForkedSubagents: true })
```

### `session.thread.getById({ threadId })` {/* #sessionthreadgetbyid-threadid- */}

按 ID 返回单个线程，或者`null` if it doesn't exist.

```typescript
const thread = await session.thread.getById({ threadId: 'thread-abc123' })
```

### `session.thread.listActiveMessages(options?)` {/* #sessionthreadlistactivemessagesoptions */}

检索活动线程的消息。当没有绑定线程时返回一个空数组。

```typescript
const messages = await session.thread.listActiveMessages({ limit: 50 })
```

### `session.thread.listMessages({ threadId, limit? })` {/* #sessionthreadlistmessages-threadid-limit- */}

检索特定线程的消息。

```typescript
const messages = await session.thread.listMessages({ threadId: 'thread-abc123' })
```

消息读取方法`listActiveMessages`, `listMessages`, and `firstUserMessage` return `MastraDBMessage` objects, while `firstUserMessages` returns a `Map<string, MastraDBMessage>` keyed by thread ID. Each message has a `role`, an `id`, a `createdAt`, and a `content` object with `content.format` and a `content.parts` array. Read text, reasoning, tool calls, and attachments from `content.parts`. Signals such as system reminders and notifications are returned as separate messages with `role: 'signal'`.

### `session.thread.firstUserMessage({ threadId })` {/* #sessionthreadfirstusermessage-threadid- */}

检索线程的第一条用户消息，或者`null` if none.

```typescript
const firstMsg = await session.thread.firstUserMessage({
  threadId: 'thread-abc123',
})
```

### `session.thread.firstUserMessages({ threadIds })` {/* #sessionthreadfirstusermessages-threadids- */}

一次检索多个线程的第一条用户消息，以映射形式返回。

```typescript
const firstByThread = await session.thread.firstUserMessages({
  threadIds: ['thread-a', 'thread-b'],
})
```

### `session.thread.getSetting({ key })` {/* #sessionthreadgetsetting-key- */}

从活动线程元数据中读取设置。

```typescript
const value = await session.thread.getSetting({ key: 'omThreshold' })
```

### `session.thread.setSetting({ key, value })` {/* #sessionthreadsetsetting-key-value- */}

将设置写入活动线程元数据。

```typescript
await session.thread.setSetting({ key: 'omThreshold', value: 0.8 })
```

### `session.thread.deleteSetting({ key })` {/* #sessionthreaddeletesetting-key- */}

从活动线程元数据中删除设置。

```typescript
await session.thread.deleteSetting({ key: 'omThreshold' })
```

## 模式 {/* #mode */}

`session.mode`拥有主动模式选择。

### `session.mode.get()` {/* #sessionmodeget */}

返回活动模式 ID。

```typescript
const modeId = session.mode.get()
```

### `session.mode.resolve()` {/* #sessionmoderesolve */}

返回完整的`AgentControllerMode` object for the active mode, resolved against the controller's configured modes.

```typescript
const mode = session.mode.resolve()
```

### `session.mode.switch({ modeId })` {/* #sessionmodeswitch-modeid- */}

切换到另一种模式，在活动线程上保留该模式，然后发出`mode_changed`. The active model stays the same unless you switch it separately, which is necessary when your host assigns different models to different modes.

```typescript
await session.mode.switch({ modeId: 'build' })
```

## 模型 {/* #model */}

`session.model`拥有会话的单个活动模型选择。

### `session.model.get()` {/* #sessionmodelget */}

返回活动模型 ID。

```typescript
const modelId = session.model.get()
```

### `session.model.displayName()` {/* #sessionmodeldisplayname */}

返回活动模型 ID 的最后一段作为短显示名称。退货`'unknown'` when no model is selected.

```typescript
const name = session.model.displayName()
```

### `session.model.hasSelection()` {/* #sessionmodelhasselection */}

检查当前是否选择了模型。

```typescript
if (session.model.hasSelection()) {
  // Ready to send messages
}
```

### `session.model.set({ modelId })` {/* #sessionmodelset-modelid- */}

在内存中设置活动模型，而不保留它、报告模型使用情况或发出`model_changed` event.

```typescript
session.model.set({ modelId: '__GATEWAY_ANTHROPIC_MODEL_SONNET__' })
```

### `session.model.switch(modelId, options?)` {/* #sessionmodelswitchmodelid-options */}

切换会话的活动模型。模型 ID 保留为线程的 ID`currentModelId` and restored with that thread. Reports the selection to the controller's `modelUseCountTracker` and emits a `model_changed` event.

经过`{ thinkingLevel }` as the second argument to switch and persist both values in one operation. The level must be `'off'`, `'low'`, `'medium'`, `'high'`, `'xhigh'`, or `'max'`, and the controller's state schema must accept it. Both live values are updated before events are emitted. Omitting the option preserves the existing thinking-level override. Every `model_changed` event includes the current `{ modelId, thinkingLevel }`, even when the thinking level is unchanged. The level is `undefined` when the session has no override.

```typescript
await session.model.switch('__GATEWAY_ANTHROPIC_MODEL_SONNET__', {
  thinkingLevel: 'high',
})
```

客户端 SDK 公开了与以下相同的操作`session.switchModel(modelId, { thinkingLevel })`.

## 观察记忆 {/* #observational-memory */}

观察记忆模型选择，按角色分组`session.om.observer` and `session.om.reflector`. Both roles expose the same methods. Selection intent and the effective concrete model ID are separate values.

### `session.om.observer.model()` / `session.om.reflector.model()` {/* #sessionomobservermodel--sessionomreflectormodel */}

返回角色的配置模型。

```typescript
const observerModel = session.om.observer.model()
const reflectorModel = session.om.reflector.model()
```

返回：`'auto' | string | undefined`

`'auto'`遵循活动的主模型。任何其他字符串都是显式模型 ID。

### `session.om.observer.modelId()` / `session.om.reflector.modelId()` {/* #sessionomobservermodelid--sessionomreflectormodelid */}

返回角色的有效具体模型 ID。对于自动选择，控制器调用`omConfig.resolveAutoModelId` with the role, current main model ID, and read-only session state. If that resolver returns no model or throws, the role uses its concrete `omConfig` fallback.

```typescript
const observer = session.om.observer.modelId()
const reflector = session.om.reflector.modelId()
```

### `session.om.observer.threshold()` / `session.om.reflector.threshold()` {/* #sessionomobserverthreshold--sessionomreflectorthreshold */}

返回角色的令牌阈值（观察者的观察阈值，反射器的反射阈值），或者`undefined` when unset.

```typescript
const observationThreshold = session.om.observer.threshold()
const reflectionThreshold = session.om.reflector.threshold()
```

### `session.om.observer.switchModel({ modelId })` / `session.om.reflector.switchModel({ modelId })` {/* #sessionomobserverswitchmodel-modelid---sessionomreflectorswitchmodel-modelid- */}

在自动选择和显式选择之间切换一种角色。经过`'auto'` to follow the active main model, or pass a concrete model ID to pin the role. Automatic selection clears the role's stale concrete model ID. The other role is unchanged. The emitted `om_model_changed` event continues to contain the effective concrete `modelId`.

```typescript
await session.om.observer.switchModel({ modelId: 'auto' })
await session.om.reflector.switchModel({
  modelId: '__GATEWAY_ANTHROPIC_MODEL_HAIKU__',
})
```

### `session.om.observer.resolvedModel()` / `session.om.reflector.resolvedModel()` {/* #sessionomobserverresolvedmodel--sessionomreflectorresolvedmodel */}

通过配置的模型网关将角色的模型 ID 解析为模型实例，或者`undefined` when no model ID is set or no resolver is configured.

```typescript
const observerModel = session.om.observer.resolvedModel()
const reflectorModel = session.om.reflector.resolvedModel()
```

## 权限 {/* #permissions */}

`session.permissions`拥有代表的Tool批准策略`session.state`: the per-category and per-tool rules consulted during approval resolution. These are distinct from the in-memory grants documented under [Session grants](#session-grants). Grants reset with the live session. Permission rules aren't durable unless the host restores the corresponding session state.

### `session.permissions.getRules()` {/* #sessionpermissionsgetrules */}

返回当前的权限规则，或者空规则(`{ categories: {}, tools: {} }`) when none are set.

```typescript
const rules = session.permissions.getRules()
// { categories: { execute: 'ask' }, tools: { dangerous_tool: 'deny' } }
```

### `session.permissions.setForCategory({ category, policy })` {/* #sessionpermissionssetforcategory-category-policy- */}

设置审批政策（`'allow' | 'ask' | 'deny'`) for a tool category. Resolves once the change is persisted to session state.

```typescript
await session.permissions.setForCategory({ category: 'execute', policy: 'ask' })
```

### `session.permissions.setForTool({ toolName, policy })` {/* #sessionpermissionssetfortool-toolname-policy- */}

设置特定Tool的批准策略。每个Tool的策略优先于类别策略。一旦坚持就解决了。

```typescript
await session.permissions.setForTool({ toolName: 'dangerous_tool', policy: 'deny' })
```

## 子Agent {/* #subagents */}

`session.subagents`拥有子Agent配置。目前它公开了子Agent模型选择`session.subagents.model`.

### `session.subagents.model.get({ agentType? })` {/* #sessionsubagentsmodelget-agenttype- */}

返回子Agent模型 ID，首选 per-`agentType` value when one is given, then the global subagent model, or `null` when neither is set.

```typescript
const modelId = session.subagents.model.get({ agentType: 'explore' })
```

### `session.subagents.model.set({ modelId, agentType? })` {/* #sessionsubagentsmodelset-modelid-agenttype- */}

设置子Agent模型 ID。通过一个`agentType` to set a per-type override, or omit it to set the global default. Persists to thread settings and emits a `subagent_model_changed` event.

```typescript
// Set the global subagent model
await session.subagents.model.set({ modelId: '__GATEWAY_ANTHROPIC_MODEL_SONNET__' })

// Set a per-type override
await session.subagents.model.set({
  modelId: '__GATEWAY_ANTHROPIC_MODEL_HAIKU__',
  agentType: 'explore',
})
```

## 显示状态 {/* #display-state */}

`session.displayState`拥有规范的`AgentControllerDisplayState` snapshot a UI renders from, and the reducer that keeps it in sync with every session event.

### `session.displayState.get()` {/* #sessiondisplaystateget */}

返回当前值`AgentControllerDisplayState` snapshot for UI rendering.

```typescript
const displayState = session.displayState.get()
```

### `session.displayState.restoreTasks(tasks)` {/* #sessiondisplaystaterestoretaskstasks */}

在 UI 重播持久任务Tool历史记录后恢复快照的任务部分。这是快照的纯粹更新，不会发出事件，因此在调用它后显式重新渲染。

```typescript
session.displayState.restoreTasks(replayedTasks)
```

每次事件发生后，会话都会发出`display_state_changed` with the latest snapshot. Subscribe with [`session.subscribe()`](#identity-and-events) or read the current value from `session.displayState.get()`.

## 状态 {/* #state */}

`session.state`公开活动对话的线程拥有的首选项以及主机拥有的状态。更新被序列化并根据`stateSchema` passed to the AgentController. Visible state changes emit `state_changed`.

线程拥有的偏好包括思维水平、观察记忆设置和子Agent模型选择。切换线程会使主机拥有的自定义字段和权限规则保持不变，并且不会保留它们。

排队写入通过异步更新和验证保持其源线程。在写入挂起时从 A 切换到 B 不会将 A 的首选项应用到 B。主机字段更新仍然会影响主机。保留运行和活动视图的同一线程共享更新排序。恢复运行后会看到在停止时所做的编辑。仅当该源处于活动状态时，才会发出没有源地址且影响对话显示的事件。

在Tool的控制器请求上下文中，`sessionId`, `resourceId`, and `threadId` identify the session, its resource, and its active thread. `state` is a snapshot taken when the context was built. Use `getState()` or `session.state.get()` to read the latest source-thread state after a write.

### `session.state.get()` {/* #sessionstateget */}

返回当前状态快照的只读副本。

```typescript
const state = session.state.get()
```

### `session.state.set(updates)` {/* #sessionstatesetupdates */}

将部分更新合并到状态中。队列按顺序应用并发调用，并在发出之前根据模式验证它们`state_changed` with the changed keys.

```typescript
await session.state.set({ yolo: true })
```

### `session.state.update(updater)` {/* #sessionstateupdateupdater */}

针对当前快照运行更新程序，并在写入队列中自动应用其结果。将此用于必须查看最新状态的读取-修改-写入更改。更新器返回可合并的`updates` and optional `events`, plus the `result` value that `update()` resolves to.

```typescript
const added = await session.state.update(current => ({
  updates: { count: (current.count ?? 0) + 1 },
  result: (current.count ?? 0) + 1,
}))
```

## 持久性边界 {/* #persistence-boundaries */}

一个`Session` is a live runtime object. Its event bus, arbitrary custom state, permission rules, permission grants, follow-ups, and active stream don't automatically survive controller or process recreation. The host must restore the host-owned state it needs.

配置的存储会保留线程和消息以及令牌使用情况，而线程设置会恢复模式、模型和支持的首选项。恢复的设置可以包括思维水平、观察记忆和具有每个Agent类型覆盖的子Agent模型选择。持久挂起的运行可以使用其完整挂起地址和原始Agent来恢复，但任意自定义状态仍然需要主机管理的持久性。

虽然运行保留了源线程视图，但即使尽力元数据持久性失败，返回到该线程时成功的内存中首选项写入仍然可用。冷重启只能恢复保留的设置和控制器默认值。

聊天频道可以映射回存储的线程。然而，`AgentControllerChannels` keeps channel-to-session and auto-approval state in memory.
