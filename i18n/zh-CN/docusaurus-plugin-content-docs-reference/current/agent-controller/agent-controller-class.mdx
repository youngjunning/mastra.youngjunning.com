# Agent控制器

这`AgentController`类是一个或多个的共享主机[`Session`](/reference/agent-controller/session)实例。初始化控制器，创建会话，然后使用`session.*`用于对话状态和运行控制的 API。

有关指导性介绍，请参阅[AgentController overview](/docs/harness/agent-controller).

## 使用示例 {/* #usage-example */}

以下示例初始化控制器并创建会话。它在发送消息之前订阅会话事件。

```typescript title="src/mastra/agent-controller.ts"
import { Agent } from '@mastra/core/agent'
import { AgentController } from '@mastra/core/agent-controller'
import { Workspace } from '@mastra/core/workspace'

const agent = new Agent({
  id: 'coding-agent',
  name: 'Coding agent',
  instructions: 'Help with software engineering tasks.',
  model: '__GATEWAY_ANTHROPIC_MODEL_SONNET__',
})

const controller = new AgentController({
  id: 'coding-controller',
  agent,
  workspace: new Workspace({ id: 'coding-workspace' }),
  modes: [{ id: 'build', name: 'Build', metadata: { default: true } }],
})

await controller.init()

const session = await controller.createSession({ resourceId: 'project-42' })
const unsubscribe = session.subscribe(event => {
  if (event.type === 'message_update' && event.event.type === 'text-delta') {
    process.stdout.write(event.event.delta)
  }
})

await session.sendMessage({ content: 'Review the project structure.' })
unsubscribe()
```

消息生命周期从初始消息开始`message_start`. Compact `message_update` events address the message by ID and carry text, reasoning, or part changes. `message_end` carries the ID to finalize.

## 方法 {/* #methods */}

### 会议 {/* #sessions */}

#### `createSession(options)` {/* #createsessionoptions */}

获取或创建在下面注册的实时会话`id`. Call `init()` before this method.

```typescript
const session = await controller.createSession({
  id: 'run-a',
  resourceId: 'project-42',
  threadId: 'thread-7',
})
```

相同`id` returns the same `Session` instance. Sessions with different ids are independent even when they share a `resourceId`: each has its own run loop, thread binding, mode, model, and state, while their stored threads and resource-scoped memory belong to the shared resource. When `id` is omitted, it defaults to `resourceId`, so one session per resource needs no id. When `threadId` is supplied, the method switches a cached session to that thread or creates the thread when it doesn't exist.

const session = await controller.getSession('run-a')

#### `onSessionCreated(listener, options?)` {/* #onsessioncreatedlistener-options */}

之后订阅进程本地通知`createSession()` materializes a new live session, with isolated listener errors prevented from affecting other listeners. Call the returned function to unsubscribe.

默认情况下，侦听器是“即发即忘”的。经过`{ blocking: true }` to make `createSession()` await the listener before resolving the new session, so the host can prepare session state before the caller can start a run. Blocking listeners run sequentially in registration order, before fire-and-forget listeners are notified. A blocking listener must not call `createSession()` for the same session `id`. That call would await its own hydration and deadlock.

```typescript
const unsubscribe = controller.onSessionCreated(
  async session => {
    const settings = await loadSettings(session.identity.getResourceId())
    if (settings) await session.state.set(settings)
  },
  { blocking: true },
)

// Default listeners stay fire-and-forget.
controller.onSessionCreated(session => {
  console.log(`Created ${session.identity.getResourceId()}`)
})
```

侦听器在每个新实现的会话中运行一次，而不是为稍后返回的缓存会话运行一次`createSession()` calls. They run only in the current process and aren't persisted events.

返回：`() => void`

#### `onSessionDeleted(listener)` {/* #onsessiondeletedlistener */}

之后订阅进程本地通知`deleteSession()` tears down a live session, with isolated listener errors prevented from affecting other listeners. Call the returned function to unsubscribe.

```typescript
const unsubscribe = controller.onSessionDeleted(session => {
  console.log(`Closed ${session.identity.getResourceId()}`)
})

await controller.createSession({ resourceId: 'project-42' })
await controller.deleteSession({ sessionId: 'project-42' })
unsubscribe()
```

该监听器是尽力而为的并且仅在当前进程中运行。这不是持久删除事件。

返回：`() => void`

#### `deleteSession({ sessionId })` {/* #deletesession-sessionid- */}

拆除在下面注册的物化会话`sessionId`. The method aborts active work, then removes thread subscriptions, the active thread lock, and the live session from the controller registry. It doesn't delete persisted threads or messages.

```typescript
const deleted = await controller.deleteSession({ sessionId: 'run-a' })
```

返回：`Promise<boolean>`. The result is `true` when a live session was removed and `false` when no matching live session exists or when another deletion is already in progress for the same session.

#### `setResourceId(session, { resourceId })` {/* #setresourceidsession--resourceid- */}

将实时会话移至另一个资源并清除其活动线程绑定。会话在其 id 下保持注册状态。

```typescript
await controller.setResourceId(session, { resourceId: 'project-43' })
```

#### `getKnownResourceIds(session)` {/* #getknownresourceidssession */}

列出存储线程中存在的资源标识符。

```typescript
const resourceIds = await controller.getKnownResourceIds(session)
```

返回：`Promise<string[]>`

#### `listActiveThreadRuns()` {/* #listactivethreadruns */}

列出此控制器上所有资源和线程上正在运行的每个运行。该列表来自进程内运行跟踪，因此它涵盖了当前进程启动的运行，并且不会创建或触及会话。

```typescript
const runs = controller.listActiveThreadRuns()
```

返回：`ActiveThreadRun[]`

  threadId: string

### 存储查询 {/* #storage-queries */}

这些方法读取存储的线程和消息，而无需创建会话或配置其Workspace。

#### `queryThreadById({ threadId })` {/* #querythreadbyid-threadid- */}

返回一个存储的线程，或者`null` when the thread or storage doesn't exist.

```typescript
const thread = await controller.queryThreadById({ threadId: 'thread-7' })
```

返回：`Promise<AgentControllerThread | null>`

#### `queryThreads(options)` {/* #querythreadsoptions */}

列出存储的线程。`resourceId` and `metadata` filter the results. Forked subagent threads are excluded unless `includeForkedSubagents` is `true`.

```typescript
const threads = await controller.queryThreads({
  resourceId: 'project-42',
  includeForkedSubagents: false,
  metadata: { repository: 'mastra' },
})
```

所有选项都是可选的。返回：`Promise<AgentControllerThread[]>`

#### `queryThreadMessages(options)` {/* #querythreadmessagesoptions */}

列出一个线程的存储消息，包括分页、排序、包含和过滤选项`StorageListMessagesInput`. `threadId` is required. The default order is newest first by `createdAt`. When `perPage` is omitted, storage uses 40 messages per page.

```typescript
const result = await controller.queryThreadMessages({
  threadId: 'thread-7',
  page: 0,
  perPage: 20,
  orderBy: { field: 'createdAt', direction: 'DESC' },
})
```

返回：`Promise<StorageListMessagesOutput>` with controller-format messages.

#### `generateThreadTitle(options)` {/* #generatethreadtitleoptions */}

从线程的对话中生成并存储标题，而无需创建会话。`threadId` is required. Optional fields include `sessionId`, `model`, and `requestContext`. Passing `sessionId` borrows a live session's agent and request context. The method throws when the thread doesn't exist and returns `undefined` when the model produces no title.

```typescript
const title = await controller.generateThreadTitle({
  threadId: 'thread-7',
  sessionId: 'run-a',
})
```

返回：`Promise<string | undefined>`

### 生命周期 {/* #lifecycle */}

#### `init()` {/* #init */}

初始化共享存储，将运行时服务传播给Agent，并启动配置的间隔处理程序。配置的Workspace在使用时会延迟初始化。重复调用重用相同的初始化承诺。

```typescript
await controller.init()
```

#### `initStorage()` {/* #initstorage */}

仅初始化控制器的存储层，无需配置Workspace或启动完整的控制器运行时。该方法是幂等的，用于直接存储查询。

```typescript
await controller.initStorage()
```

返回：`Promise<void>`

#### `destroy()` {/* #destroy */}

停止控制器拥有的间隔处理程序。这不会破坏控制器创建的会话。

```typescript
await controller.destroy()
```

#### `listAvailableModels()` {/* #listavailablemodels */}

列出已配置和内置网关的型号。每个型号的`useCount` comes from `modelUseCountProvider` when you configure one.

内置网关下载公共目录（models.dev 和 Netlify）。仅当尚未下载任何目录时，调用才会等待目录。之后，调用将返回上次下载的目录，包括下载失败时的情况。一旦超过 5 分钟，下一次调用就会在后台下载新的，而无需等待。 10 秒后再次检查已配置的网关和 API 密钥可用性。

```typescript
const models = await controller.listAvailableModels()
```

返回：`Promise<AvailableModel[]>`

#### `invalidateAvailableModelsCache()` {/* #invalidateavailablemodelscache */}

进行下一个`listAvailableModels()` call check configured gateways and API key availability again, and download the models.dev and Netlify catalogs again in the background. Call it after your app stores or removes a credential or changes a custom provider.

```typescript
controller.invalidateAvailableModelsCache()
```
