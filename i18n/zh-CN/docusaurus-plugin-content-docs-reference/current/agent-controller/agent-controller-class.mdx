# AgentController

`AgentController` 类为一个或多个 [`Session`](/reference/agent-controller/session) 实例提供共享宿主。先初始化 Controller 并创建 Session，再通过 `session.*` API 管理对话状态和运行控制。

入门介绍请参阅 [AgentController 概览](/docs/harness/agent-controller)。

## 使用示例 {/* #usage-example */}

以下示例初始化 Controller 并创建 Session，在发送消息前订阅 Session 事件。

```typescript title="src/mastra/agent-controller.ts"
import { Agent } from '@mastra/core/agent'
import { AgentController } from '@mastra/core/agent-controller'
import { Workspace } from '@mastra/core/workspace'

const agent = new Agent({
  id: 'coding-agent',
  name: 'Coding agent',
  instructions: 'Help with software engineering tasks.',
  model: '__GATEWAY_ANTHROPIC_MODEL_SONNET__',
})

const controller = new AgentController({
  id: 'coding-controller',
  agent,
  workspace: new Workspace({ id: 'coding-workspace' }),
  modes: [{ id: 'build', name: 'Build', metadata: { default: true } }],
})

await controller.init()

const session = await controller.createSession({ resourceId: 'project-42' })
const unsubscribe = session.subscribe(event => {
  if (event.type === 'message_update' && event.event.type === 'text-delta') {
    process.stdout.write(event.event.delta)
  }
})

await session.sendMessage({ content: 'Review the project structure.' })
unsubscribe()
```

消息生命周期始于 `message_start` 中的初始消息。简洁的 `message_update` 事件通过 ID 定位消息，并携带文本、推理内容或消息部分的变化。`message_end` 携带 ID，表示消息结束。

## 方法 {/* #methods */}

### Session {/* #sessions */}

#### `createSession(options)` {/* #createsessionoptions */}

获取或创建以 `id` 注册的实时 Session。调用此方法前须先调用 `init()`。

```typescript
const session = await controller.createSession({
  id: 'run-a',
  resourceId: 'project-42',
  threadId: 'thread-7',
})
```

相同的 `id` 会返回同一个 `Session` 实例。即使共用 `resourceId`，不同 ID 的 Session 仍彼此独立：各自拥有运行循环、线程绑定、模式、模型和状态，但其已存储的线程与资源级 Memory 属于同一资源。省略 `id` 时默认使用 `resourceId`，因此每个资源只需一个 Session 时无需指定 ID。传入 `threadId` 时，此方法会将已缓存的 Session 切换到该线程；若线程不存在则创建它。

#### `getSession(sessionId, requestContext?)` {/* #getsessionsessionid-requestcontext */}

返回以 `sessionId` 注册的实时 Session；如果当前没有对应的实时 Session，则返回 `undefined`。

```typescript
const session = await controller.getSession('run-a')
```

返回：`Promise<Session<TState> | undefined>`

#### `onSessionCreated(listener, options?)` {/* #onsessioncreatedlistener-options */}

在 `createSession()` 创建新的实时 Session 后订阅当前进程内的通知。某个监听器抛出的错误不会影响其他监听器。调用返回的函数可取消订阅。

默认情况下，监听器以即发即忘方式运行。传入 `{ blocking: true }` 后，`createSession()` 会等待监听器完成才返回新 Session，使宿主能够在调用方启动运行前准备 Session 状态。阻塞式监听器按注册顺序依次运行，之后才通知非阻塞式监听器。阻塞式监听器不得调用 `createSession()` 来创建具有相同 `id` 的 Session，否则它会等待自身的初始化完成而造成死锁。

```typescript
const unsubscribe = controller.onSessionCreated(
  async session => {
    const settings = await loadSettings(session.identity.getResourceId())
    if (settings) await session.state.set(settings)
  },
  { blocking: true },
)

// Default listeners stay fire-and-forget.
controller.onSessionCreated(session => {
  console.log(`Created ${session.identity.getResourceId()}`)
})
```

监听器只在每个新创建的 Session 上运行一次；以后调用 `createSession()` 返回缓存 Session 时不会再次运行。通知仅发生在当前进程中，不会作为事件持久化。

返回：`() => void`

#### `onSessionDeleted(listener)` {/* #onsessiondeletedlistener */}

在 `deleteSession()` 拆除实时 Session 后订阅当前进程内的通知。某个监听器抛出的错误不会影响其他监听器。调用返回的函数可取消订阅。

```typescript
const unsubscribe = controller.onSessionDeleted(session => {
  console.log(`Closed ${session.identity.getResourceId()}`)
})

await controller.createSession({ resourceId: 'project-42' })
await controller.deleteSession({ sessionId: 'project-42' })
unsubscribe()
```

此监听器只在当前进程中尽力运行，不属于持久化的删除事件。

返回：`() => void`

#### `deleteSession({ sessionId })` {/* #deletesession-sessionid- */}

拆除以 `sessionId` 注册的实时 Session。此方法先中止活动任务，再移除线程订阅、活动线程锁及 Controller 注册表中的实时 Session；不会删除已持久化的线程或消息。

```typescript
const deleted = await controller.deleteSession({ sessionId: 'run-a' })
```

返回：`Promise<boolean>`。移除了实时 Session 时为 `true`；没有匹配的实时 Session，或同一 Session 的另一次删除正在进行时为 `false`。

#### `setResourceId(session, { resourceId })` {/* #setresourceidsession--resourceid- */}

将实时 Session 移至另一资源，并清除其活动线程绑定。Session 仍以原 ID 注册。

```typescript
await controller.setResourceId(session, { resourceId: 'project-43' })
```

#### `getKnownResourceIds(session)` {/* #getknownresourceidssession */}

列出已存储线程中出现过的资源标识符。

```typescript
const resourceIds = await controller.getKnownResourceIds(session)
```

返回：`Promise<string[]>`

#### `listActiveThreadRuns()` {/* #listactivethreadruns */}

列出此 Controller 中跨所有资源和线程正在执行的运行。列表来自进程内运行跟踪，因此只涵盖当前进程启动的运行，不会创建或访问 Session。

```typescript
const runs = controller.listActiveThreadRuns()
```

返回：`ActiveThreadRun[]`

```typescript
interface ActiveThreadRun {
  runId: string
  resourceId?: string
  threadId: string
}
```

### 存储查询 {/* #storage-queries */}

这些方法无需创建 Session 或配置其 Workspace，即可读取已存储的线程和消息。

#### `queryThreadById({ threadId })` {/* #querythreadbyid-threadid- */}

返回一个已存储线程；线程或存储不存在时返回 `null`。

```typescript
const thread = await controller.queryThreadById({ threadId: 'thread-7' })
```

返回：`Promise<AgentControllerThread | null>`

#### `queryThreads(options)` {/* #querythreadsoptions */}

列出已存储的线程。`resourceId` 和 `metadata` 用于筛选结果。除非 `includeForkedSubagents` 为 `true`，否则不包含派生的子 Agent 线程。

```typescript
const threads = await controller.queryThreads({
  resourceId: 'project-42',
  includeForkedSubagents: false,
  metadata: { repository: 'mastra' },
})
```

所有选项都是可选的。返回：`Promise<AgentControllerThread[]>`

#### `queryThreadMessages(options)` {/* #querythreadmessagesoptions */}

根据 `StorageListMessagesInput` 的分页、排序、包含和筛选选项，列出某个线程中已存储的消息。必须提供 `threadId`。默认按 `createdAt` 从新到旧排序；省略 `perPage` 时，每页由存储层返回 40 条消息。

```typescript
const result = await controller.queryThreadMessages({
  threadId: 'thread-7',
  page: 0,
  perPage: 20,
  orderBy: { field: 'createdAt', direction: 'DESC' },
})
```

返回：`Promise<StorageListMessagesOutput>`，其中包含 Controller 格式的消息。

#### `generateThreadTitle(options)` {/* #generatethreadtitleoptions */}

无需创建 Session，即可根据线程对话生成并存储标题。`threadId` 必填；可选字段包括 `sessionId`、`model` 和 `requestContext`。传入 `sessionId` 时会借用实时 Session 的 Agent 和请求上下文。线程不存在时会抛出错误；模型未生成标题时返回 `undefined`。

```typescript
const title = await controller.generateThreadTitle({
  threadId: 'thread-7',
  sessionId: 'run-a',
})
```

返回：`Promise<string | undefined>`

### 生命周期 {/* #lifecycle */}

#### `init()` {/* #init */}

初始化共享存储，将运行时服务传给 Agent，并启动已配置的周期性处理器。配置的 Workspace 会在使用时按需初始化。重复调用会复用同一个初始化 Promise。

```typescript
await controller.init()
```

#### `initStorage()` {/* #initstorage */}

只初始化 Controller 的存储层，不配置 Workspace，也不启动完整的 Controller 运行时。此方法可重复调用，供直接查询存储时使用。

```typescript
await controller.initStorage()
```

返回：`Promise<void>`

#### `destroy()` {/* #destroy */}

停止由 Controller 管理的周期性处理器，但不会销毁其创建的 Session。

```typescript
await controller.destroy()
```

const modes = controller.listModes()

#### `listAvailableModels()` {/* #listavailablemodels */}

列出配置的网关及内置网关提供的模型。若配置了使用次数提供方，每个模型的 `useCount` 由 `modelUseCountProvider` 提供。

内置网关会下载公开模型目录（models.dev 和 Netlify）。只有尚未下载任何目录时，调用才会等待下载；之后会返回上次下载的目录，即使新下载失败也是如此。目录超过 5 分钟后，下次调用会在后台重新下载，不会等待。配置的网关和 API Key 可用性每 10 秒重新检查。

```typescript
const models = await controller.listAvailableModels()
```

返回：`Promise<AvailableModel[]>`

#### `invalidateAvailableModelsCache()` {/* #invalidateavailablemodelscache */}

让下一次 `listAvailableModels()` 调用重新检查配置的网关和 API Key 可用性，并在后台重新下载 models.dev 与 Netlify 的目录。应用保存或移除凭据、或更改自定义 Provider 后应调用此方法。

```typescript
controller.invalidateAvailableModelsCache()
```
