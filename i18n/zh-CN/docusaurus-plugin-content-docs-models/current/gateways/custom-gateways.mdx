# 自定义模型网关

通过自定义模型网关，你可以使用 `MastraModelGatewayInterface` 接口或 `MastraModelGateway` 基类，实现私有或专用的 LLM Provider 集成。

## 概述 {/* #overview */}

网关负责处理访问语言模型时的 Provider 专属逻辑：

- Provider 配置和模型发现
- 身份验证和 API 密钥管理
- 为 API 端点构建 URL
- 创建语言模型实例

## 何时使用自定义网关 {/* #when-to-use-custom-gateways */}

使用自定义网关，可将 Mastra 连接到自行运行的开放权重模型，例如 gpt-oss、Llama、Gemma、Mistral、Qwen 或 DeepSeek。以下情况适合自行托管：

- 行业规范不允许将 prompt 或客户数据发送到第三方 API（例如 HIPAA、GDPR、金融或国防领域）
- 模型调用量足够大，按 token 计费的 API 成本已高于运行自有 GPU
- 已使用内部数据微调开放权重模型，并希望 Agent 使用该模型
- 需要模型仅在主动升级时发生变化，以避免 Provider 更新破坏 prompt
- Agent 需要离线运行，或运行在隔离网络、边缘硬件，或与应用相同的数据中心

网关会列出端点后的模型，让这些模型获得带类型的模型 ID，并显示在 Studio 模型选择器中。网关还可以在每次调用时解析凭据；你也可以[限制 Studio 模型选择器](#showing-only-custom-gateways-in-studio)，仅显示自己的模型。

如果只是调用一个兼容 OpenAI API 的端点，则不需要网关：直接在模型配置中设置 `url` 即可。对于使用 `url` 的模型，Mastra 不会从环境变量读取 API 密钥，因此端点需要身份验证时还应设置 `apiKey`。参阅[在 Mastra 中使用本地模型](/models#use-local-models-with-mastra)。

## 创建自定义网关 {/* #creating-a-custom-gateway */}

普通对象形式的网关可实现 `MastraModelGatewayInterface`；类形式的网关可扩展 `MastraModelGateway` 基类。

### 选择普通对象还是类 {/* #choose-a-plain-object-or-a-class */}

两种形式在运行时的行为相同。基类提供默认的 `getId()`、`shouldEnable()`、`handlesModel()` 和 `serializeForSpan()` 方法；如果普通对象省略这些方法，Mastra 也会应用相同的默认实现。

网关配置固定且无状态时，可使用普通对象。以下情况应扩展 `MastraModelGateway`：

- 需要通过构造函数接收基础 URL 或 API 密钥等选项
- 需要保存私有状态，例如缓存的 token
- 需要运行多个实例，例如每个区域或版本各一个

以下示例使用普通对象实现该接口：

```typescript
import { type MastraModelGatewayInterface, type ProviderConfig } from '@mastra/core/llm';
import { createOpenAICompatible } from '@ai-sdk/openai-compatible-v5';

const myPrivateGateway: MastraModelGatewayInterface = {
  id: 'private',
  name: 'My Private Gateway',
  async fetchProviders(): Promise<Record<string, ProviderConfig>> {
    return {
      'my-provider': {
        name: 'My Provider',
        models: ['__GATEWAY_OPENAI_MODEL__'],
        apiKeyEnvVar: 'MY_API_KEY',
        gateway: 'private',
        url: 'https://api.myprovider.com/v1',
      },
    };
  },
  buildUrl() {
    return 'https://api.myprovider.com/v1';
  },
  async getApiKey() {
    return process.env.MY_API_KEY ?? '';
  },
  async resolveLanguageModel({ modelId, providerId, apiKey, headers }) {
    return createOpenAICompatible({
      name: providerId,
      apiKey,
      headers,
      baseURL: 'https://api.myprovider.com/v1',
    }).chatModel(modelId);
  },
};
```

以下示例扩展 `MastraModelGateway`，并通过构造函数接收 ID、基础 URL 和 API 密钥：

```typescript
import { MastraModelGateway, type GatewayLanguageModel, type ProviderConfig } from '@mastra/core/llm';
import { createOpenAICompatible } from '@ai-sdk/openai-compatible-v5';

interface MyPrivateGatewayOptions {
  id?: string;
  baseURL?: string;
  apiKey?: string;
}

class MyPrivateGateway extends MastraModelGateway {
  readonly id: string;
  readonly name = 'My Private Gateway';

  private readonly baseURL: string;
  private readonly apiKey?: string;

  constructor(options: MyPrivateGatewayOptions = {}) {
    super();
    this.id = options.id ?? 'private';
    this.baseURL = options.baseURL ?? 'https://api.myprovider.com/v1';
    this.apiKey = options.apiKey;
  }

  async fetchProviders(): Promise<Record<string, ProviderConfig>> {
    return {
      'my-provider': {
        name: 'My Provider',
        models: ['__GATEWAY_OPENAI_MODEL__', '__GATEWAY_ANTHROPIC_MODEL_SONNET__'],
        apiKeyEnvVar: 'MY_API_KEY',
        gateway: this.id,
        url: this.baseURL,
      },
    };
  }

  buildUrl(): string {
    return this.baseURL;
  }

  async getApiKey(): Promise<string> {
    const apiKey = this.apiKey ?? process.env.MY_API_KEY;
    if (!apiKey) {
      throw new Error('Missing MY_API_KEY environment variable');
    }
    return apiKey;
  }

  resolveLanguageModel({
    modelId,
    providerId,
    apiKey,
    headers,
  }: {
    modelId: string;
    providerId: string;
    apiKey: string;
    headers?: Record<string, string>;
  }): GatewayLanguageModel {
    return createOpenAICompatible({
      name: providerId,
      apiKey,
      headers,
      baseURL: this.baseURL,
      supportsStructuredOutputs: true,
    }).chatModel(modelId);
  }
}
```

如需为每个端点运行一个实例，请为各实例分配不同的 `id`。对于同一个 ID，Mastra 只保留最先注册的网关；该 ID 也是模型 ID 的前缀：

```typescript
import { Mastra } from '@mastra/core';

const mastra = new Mastra({
  gateways: {
    privateEu: new MyPrivateGateway({ id: 'private-eu', baseURL: 'https://eu.api.myprovider.com/v1' }),
    privateUs: new MyPrivateGateway({ id: 'private-us', baseURL: 'https://us.api.myprovider.com/v1' }),
  },
});

// Models: 'private-eu/my-provider/__GATEWAY_OPENAI_MODEL__' and 'private-us/my-provider/__GATEWAY_OPENAI_MODEL__'
```

### 由网关管理的身份验证 {/* #gateway-owned-authentication */}

如果凭据查找由网关负责，请添加 `resolveAuth`。Mastra 会先使用此 hook，之后才回退到 `getApiKey()`。

```typescript
const myPrivateGateway: MastraModelGatewayInterface = {
  // ...gateway fields and methods
  async resolveAuth() {
    const apiKey = process.env.MY_API_KEY;
    return apiKey ? { apiKey, source: 'gateway' } : undefined;
  },
};
```

## 注册自定义网关 {/* #registering-custom-gateways */}

### 初始化时 {/* #during-initialization */}

创建 Mastra 实例时，以记录形式传入网关：

```typescript
import { Mastra } from '@mastra/core';

const mastra = new Mastra({
  gateways: {
    myGateway: new MyPrivateGateway(),
    anotherGateway: new AnotherGateway(),
  },
});
```

### 初始化后 {/* #after-initialization */}

使用 `addGateway` 动态添加网关：

```typescript
const mastra = new Mastra();

// Add with explicit key
mastra.addGateway(new MyPrivateGateway(), 'myGateway');

// Add using gateway's ID
mastra.addGateway(new MyPrivateGateway());
// Stored with key 'my-private-gateway' (the gateway's id)
```

## 使用自定义网关 {/* #using-custom-gateways */}

以网关 ID 作为前缀，引用自定义网关中的模型：

```typescript
import { Agent } from '@mastra/core/agent';

const agent = new Agent({
  id: 'my-agent',
  name: 'My Agent',
  instructions: 'You are a helpful assistant',
  model: 'private/my-provider/__GATEWAY_OPENAI_MODEL__', // Uses MyPrivateGateway
});

mastra.addAgent(agent, 'myAgent');
```

创建 Agent 或使用模型时，Mastra 的模型路由器会根据模型 ID 自动选择合适的网关。网关 ID 用作前缀；如果没有匹配的自定义网关，则回退到内置网关。

### TypeScript 自动补全 {/* #typescript-autocomplete */}

#### 在开发环境中自动生成类型 {/* #automatic-type-generation-in-development */}

在开发模式（`MASTRA_DEV=true`）下运行时，Mastra 会自动为自定义网关生成 TypeScript 类型。

1. **设置环境变量**：
   ```bash
   export MASTRA_DEV=true
   ```

1. **注册网关**：
   ```typescript
   const mastra = new Mastra({
     gateways: {
       myGateway: new MyPrivateGateway(),
     },
   });
   ```

1. **自动生成类型**：
   - 添加网关时，Mastra 会与 GatewayRegistry 同步
   - 注册表会从自定义网关获取 Provider
   - TypeScript 类型会在 `~/.cache/mastra/` 中重新生成
   - IDE 会在数秒内读取新类型

1. **自动补全现已可用**：
   ```typescript
   const agent = new Agent({
     model: 'my-gateway-id/my-provider/model-1', // Full autocomplete!
   });
   ```

#### 工作原理 {/* #how-it-works */}

GatewayRegistry 每小时执行一次同步，以：
- 对所有已注册网关调用 `fetchProviders()`
- 生成 TypeScript 类型定义
- 将类型定义写入全局缓存和项目的 `dist/` 目录
- TypeScript 服务器会自动读取这些变更

:::tip
首次添加网关时，生成类型可能需要数秒。后续更新会每小时在后台执行。
:::

#### 手动生成类型的替代方法 {/* #manual-type-generation-alternatives */}

如果未在开发模式下运行，或需要立即更新类型：

**选项 1：使用类型断言（最简单）**
```typescript
const agent = new Agent({
  id: 'my-agent',
  name: 'my-agent',
  instructions: 'You are a helpful assistant',
  model: 'private/my-provider/model-1' as any, // Bypass type checking
});
```

**选项 2：创建自定义联合类型（类型安全）**
```typescript
import type { ModelRouterModelId } from '@mastra/core/llm';

// Define your custom model IDs
type CustomModelId =
  | 'private/my-provider/model-1'
  | 'private/my-provider/model-2'
  | 'private/my-provider/model-3';

// Combine with built-in models
type AllModelIds = ModelRouterModelId | CustomModelId;

const agent = new Agent({
  id: 'my-agent',
  name: 'my-agent',
  instructions: 'You are a helpful assistant',
  model: 'private/my-provider/model-1' satisfies AllModelIds,
});
```

**选项 3：全局扩展 ModelRouterModelId（高级）**
```typescript
// In a types.d.ts file in your project
// The import is required: it makes this file a module, so the block below
// merges into the existing types instead of replacing the module.
import '@mastra/core/llm';

declare module '@mastra/core/llm' {
  interface ProviderModelsMap {
    'my-provider': readonly ['model-1', 'model-2', 'model-3'];
  }
}
```

这会扩展内置类型，将自定义模型纳入其中，从而提供完整的自动补全支持。

## 网关管理 {/* #gateway-management */}

### getGateway(key) {/* #getgatewaykey */}

按注册键获取网关：

```typescript
const gateway = mastra.getGateway('myGateway');
console.log(gateway.name); // 'My Private Gateway'
```

### getGatewayById(id) {/* #getgatewaybyidid */}

按唯一 ID 获取网关：

```typescript
const gateway = mastra.getGatewayById('my-private-gateway');
console.log(gateway.name); // 'My Private Gateway'
```

以下情况适合使用此方法：
- 网关的显式 ID 与注册键不同
- 需要跨不同实例按 ID 查找网关
- 需要支持网关版本管理（例如 `'gateway-v1'`、`'gateway-v2'`）

如果没有已注册网关使用指定 ID，`getGatewayById()` 会抛出 `MastraError`，而不是返回 `undefined`。

### listGateways() {/* #listgateways */}

获取所有已注册网关：

```typescript
const gateways = mastra.listGateways();
console.log(Object.keys(gateways)); // ['myGateway', 'anotherGateway']
```

## 网关属性 {/* #gateway-properties */}

### 必填属性 {/* #required */}

| 属性 | 类型 | 说明 |
|----------|------|-------------|
| `id` | `string` | 网关的唯一标识符，用作模型字符串的网关前缀 |
| `name` | `string` | 便于阅读的网关名称 |

### 方法 {/* #methods */}

| 方法 | 说明 |
|--------|-------------|
| `fetchProviders()` | 获取 Provider 配置 |
| `buildUrl(modelId, envVars?)` | 为模型构建 API URL |
| `getApiKey(modelId)` | 获取用于身份验证的 API 密钥 |
| `resolveLanguageModel(args)` | 创建语言模型实例 |
| `getId()` | 获取网关 ID（返回 `id` 或 `name`） |

## Provider 配置 {/* #provider-configuration */}

`fetchProviders()` 方法返回由 `ProviderConfig` 对象组成的记录：

```typescript
interface ProviderConfig {
  name: string;                    // Display name
  models: string[];                // Available model IDs
  apiKeyEnvVar: string | string[]; // Environment variable(s) for API key
  gateway: string;                 // Gateway identifier
  url?: string;                    // Optional API base URL
  apiKeyHeader?: string;           // Optional custom auth header
  docUrl?: string;                 // Optional documentation URL
  pricing?: Record<string, ModelPricing>; // Optional prices per model ID
}
```

### 模型定价 {/* #model-pricing */}

models.dev 不会列出私有部署，因此相关调用在[指标](/docs/observability/metrics/overview)中没有成本。可以为每个模型添加 `pricing` 项，为其提供定价。价格以每 100 万 token 的美元金额计，并使用与 [models.dev](https://models.dev) 中模型 `cost` 相同的键：`input`、`output`、`cache_read`、`cache_write`、`reasoning`、`input_audio` 和 `output_audio`。`@mastra/observability` 会在首次调用无法定价的模型时读取这些价格，因此也能识别之后通过 `addGateway()` 添加的网关。在 `mastra dev` 下，或设置 `MASTRA_AUTO_REFRESH_PRICING=true` 后，Mastra 启动时也会读取价格，使首次调用也能计价。models.dev 的价格优先级更高。只有 models.dev 没有相应 Provider 和模型 ID 的价格时，才会采用网关价格；随后，该价格会用于这些 ID 的所有调用，包括直接调用。如果经销商费率必须与直接调用分开，请为其分配独立的 Provider ID。如果网关的 `fetchProviders()` 失败，系统会记录日志，并大约每小时重试一次。设置 `MASTRA_OFFLINE=true` 可跳过加载。由于格式与 models.dev 相同，还可以添加 `tiers` 以支持长上下文定价。

```typescript
async fetchProviders(): Promise<Record<string, ProviderConfig>> {
  return {
    'my-provider': {
      name: 'My Provider',
      models: ['model-1'],
      apiKeyEnvVar: 'MY_API_KEY',
      gateway: 'private',
      url: 'https://api.myprovider.com/v1',
      pricing: {
        'model-1': { input: 0.5, output: 1.5, cache_read: 0.05 },
      },
    },
  };
}
```

## 网关 ID 与键的区别 {/* #gateway-ids-vs-keys */}

请注意两者的区别：

- **键**：将网关添加到 Mastra 时使用的注册键（记录键）
- **ID**：网关的唯一标识符（使用 `id` 属性；如未设置，则使用 `name`）

```typescript
class VersionedGateway extends MastraModelGateway {
  readonly id = 'my-gateway-v2';     // Unique ID for versioning and prefixing
  readonly name = 'My Gateway';       // Display name
}

const mastra = new Mastra({
  gateways: {
    currentGateway: new VersionedGateway(), // Key: 'currentGateway'
  },
});

// Retrieve by key
const byKey = mastra.getGateway('currentGateway');

// Retrieve by ID
const byId = mastra.getGatewayById('my-gateway-v2');

// Both return the same gateway
console.log(byKey === byId); // true
```

## 模型 ID 格式 {/* #model-id-format */}

通过自定义网关访问的模型采用以下格式：

```
[gatewayId]/[provider]/[model]
```

示例：
- `private/my-provider/model-1`

## 高级示例 {/* #advanced-example */}

支持缓存、基于 token 的网关：

```typescript
class TokenGateway extends MastraModelGateway {
  readonly id = 'token-gateway-v1';
  readonly name = 'Token Gateway';

  private tokenCache: Map<string, { token: string; expiresAt: number }> = new Map();

  async fetchProviders(): Promise<Record<string, ProviderConfig>> {
    const response = await fetch('https://api.gateway.com/providers');
    const data = await response.json();

    return {
      provider: {
        name: data.name,
        models: data.models,
        apiKeyEnvVar: 'GATEWAY_TOKEN',
        gateway: this.id,
      },
    };
  }

  async buildUrl(modelId: string, envVars?: Record<string, string>): Promise<string> {
    const token = await this.getApiKey(modelId);
    const siteId = envVars?.SITE_ID || process.env.SITE_ID;

    const response = await fetch(`https://api.gateway.com/sites/${siteId}/token`, {
      headers: { Authorization: `Bearer ${token}` },
    });

    const { url } = await response.json();
    return url;
  }

  async getApiKey(modelId: string): Promise<string> {
    const cached = this.tokenCache.get(modelId);

    if (cached && cached.expiresAt > Date.now()) {
      return cached.token;
    }

    const token = process.env.GATEWAY_TOKEN;
    if (!token) {
      throw new Error('Missing GATEWAY_TOKEN');
    }

    // Cache token for 1 hour
    this.tokenCache.set(modelId, {
      token,
      expiresAt: Date.now() + 3600000,
    });

    return token;
  }

  async resolveLanguageModel({ modelId, providerId, apiKey }: {
    modelId: string;
    providerId: string;
    apiKey: string;
  }): Promise<LanguageModelV2> {
    const baseURL = await this.buildUrl(`${providerId}/${modelId}`);

    return createOpenAICompatible({
      name: providerId,
      apiKey,
      baseURL,
      supportsStructuredOutputs: true,
    }).chatModel(modelId);
  }
}
```

## 错误处理 {/* #error-handling */}

为常见故障场景提供说明清晰的错误信息：

```typescript
class RobustGateway extends MastraModelGateway {
  // ... properties

  async getApiKey(modelId: string): Promise<string> {
    const apiKey = process.env.MY_API_KEY;

    if (!apiKey) {
      throw new Error(
        `Missing MY_API_KEY environment variable for model: ${modelId}. ` +
        `Please set MY_API_KEY in your environment.`
      );
    }

    return apiKey;
  }

  async buildUrl(modelId: string, envVars?: Record<string, string>): Promise<string> {
    const baseUrl = envVars?.BASE_URL || process.env.BASE_URL;

    if (!baseUrl) {
      throw new Error(
        `No base URL configured for model: ${modelId}. ` +
        `Set BASE_URL environment variable or pass it in envVars.`
      );
    }

    return baseUrl;
  }
}
```

## 测试自定义网关 {/* #testing-custom-gateways */}

```typescript
import { describe, it, expect, beforeEach } from 'vitest';
import { Mastra } from '@mastra/core';

describe('MyPrivateGateway', () => {
  beforeEach(() => {

  it('should fetch providers', async () => {

    expect(providers['my-provider']).toBeDefined();

    const gateway = mastra.getGateway('private');
    expect(gateway.name).toBe('My Private Gateway');
  });

  it('should resolve models by ID', () => {
    const mastra = new Mastra({
      gateways: {
        key: new MyPrivateGateway(),
      },
    });

    const gateway = mastra.getGatewayById('my-private-gateway');
    expect(gateway).toBeDefined();
  });
});
```

## 最佳实践 {/* #best-practices */}

1. **使用含义明确的 ID 管理版本**：需要管理网关版本时，请设置明确的 `id` 值
   ```typescript
   readonly id = 'my-gateway-v1';
   ```

1. **正确处理错误**：抛出说明清晰且包含可执行建议的错误

1. **缓存高成本操作**：适时缓存 token、URL 或 Provider 配置

1. **验证环境变量**：在 `getApiKey` 和 `buildUrl` 中检查必需的环境变量

1. **为网关编写文档**：添加 JSDoc 注释，说明网关的用途和配置

1. **遵循命名约定**：为 Provider 和模型使用清晰一致的名称

1. **处理异步操作**：对网络请求和 I/O 操作使用 `async/await`

1. **充分测试**：为所有网关方法编写单元测试

## 在 Studio 中仅显示自定义网关 {/* #showing-only-custom-gateways-in-studio */}

默认情况下，**Studio** 会同时列出所有外部模型 Provider（例如 OpenAI、Anthropic 和 Gemini）以及已注册的自定义网关。如需隐藏外部 Provider，请设置 `AUTO_BLOCK_EXTERNAL_PROVIDERS` 环境变量：

```bash
AUTO_BLOCK_EXTERNAL_PROVIDERS=true
```

将该变量设置为 `true` 或 `1` 后，Mastra 只返回自行注册的网关所提供的 Provider。静态 Provider 注册表和内置网关（`models.dev`、`netlify` 和 `mastra`）会从模型选择器中隐藏。如果所有模型流量都通过单个私有网关路由，并且不希望显示其他 Provider，这项设置会很有用。该筛选器作用于服务器的 `GET /agents/providers` 端点，而 Studio 的模型选择器正是使用该端点，因此 API 客户端也不会看到外部 Provider。它只会改变列出的 Provider，并不会阻止 Agent 在代码中调用其他 Provider。

如果设置了该变量但未注册任何自定义网关，模型选择器将为空。请至少注册一个自定义网关，以显示其模型。

## 内置网关 {/* #built-in-gateways */}

Mastra 提供以下内置网关作为参考实现：

- **NetlifyGateway**：集成支持 token 交换的 Netlify AI Gateway
- **ModelsDevGateway**：models.dev 提供的 OpenAI 兼容 Provider 注册表

网关使用示例请参阅 [Netlify](/models/gateways/netlify)、[OpenRouter](/models/gateways/openrouter) 和 [Vercel](/models/gateways/vercel)。
