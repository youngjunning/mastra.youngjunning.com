# 定制模型网关

自定义模型网关允许您实施私人或专门的 LLM Provider与`MastraModelGatewayInterface`接口或`MastraModelGateway`基类。

## 概述 {/* #overview */}

网关处理用于访问语言模型的特定于提供者的逻辑：

* 提供者配置和模型发现
* 身份验证和 API 密钥管理
* API 端点的 URL 构造
* 语言模型实例创建

## 何时使用自定义网关 {/* #when-to-use-custom-gateways */}

使用自定义网关将 Mastra 连接到您自己运行的开放权重模型，例如 gpt-oss、Llama、Gemma、Mistral、Qwen 或 DeepSeek。自托管适合以下情况：

* 您的行业规则不允许向第三方 API 发送提示或客户数据（HIPAA、GDPR、金融、国防）
* 您进行了足够多的模型调用，每个代币 API 的定价成本都高于运行您自己的 GPU
* 您已经根据内部数据微调了开放权重模型，并希望您的Agent使用它
* 您需要一个仅在升级时才会更改的模型，因此提供程序更新不会破坏您的提示
* 您的Agent在气隙网络、边缘硬件或与您的应用程序相同的数据中心中离线运行

网关列出了端点背后的模型，以便它们获取键入的模型 ID 并显示在 Studio 模型选择器中。它还可以解析每次调用的凭据，并且您可以[limit the Studio model picker](#showing-only-custom-gateways-in-studio) to your own models.

要使用 OpenAI 兼容的 API 调用单个端点，您不需要网关：设置`url` in the model config instead. Mastra doesn't read an API key from environment variables for a `url` model, so also set `apiKey` when the endpoint requires authentication. See [Use local models with Mastra](/models#use-local-models-with-mastra).

## 创建自定义网关 {/* #creating-a-custom-gateway */}

实施`MastraModelGatewayInterface` for a plain object gateway, or extend the `MastraModelGateway` base class.

### 选择一个普通对象或一个类 {/* #choose-a-plain-object-or-a-class */}

两者在运行时的工作方式相同。基类提供默认值`getId()`, `shouldEnable()`, `handlesModel()`, and `serializeForSpan()` methods, and Mastra applies the same defaults to a plain object that leaves them out.

当网关具有固定配置且没有状态时，使用普通对象。延长`MastraModelGateway` when the gateway:

* 在其构造函数中采用选项，例如基本 URL 或 API 密钥
* 保留私有状态，例如缓存的令牌
* 作为多个实例运行，例如每个区域或版本一个实例

以下示例使用普通对象实现接口：

```typescript
import { type MastraModelGatewayInterface, type ProviderConfig } from '@mastra/core/llm';
import { createOpenAICompatible } from '@ai-sdk/openai-compatible-v5';

const myPrivateGateway: MastraModelGatewayInterface = {
  id: 'private',
  name: 'My Private Gateway',
  async fetchProviders(): Promise<Record<string, ProviderConfig>> {
    return {
      'my-provider': {
        name: 'My Provider',
        models: ['__GATEWAY_OPENAI_MODEL__'],
        apiKeyEnvVar: 'MY_API_KEY',
        gateway: 'private',
        url: 'https://api.myprovider.com/v1',
      },
    };
  },
  buildUrl() {
    return 'https://api.myprovider.com/v1';
  },
  async getApiKey() {
    return process.env.MY_API_KEY ?? '';
  },
  async resolveLanguageModel({ modelId, providerId, apiKey, headers }) {
    return createOpenAICompatible({
      name: providerId,
      apiKey,
      headers,
      baseURL: 'https://api.myprovider.com/v1',
    }).chatModel(modelId);
  },
};
```

下面的例子扩展了`MastraModelGateway` and takes its ID, base URL, and API key as constructor options:

```typescript
import { MastraModelGateway, type GatewayLanguageModel, type ProviderConfig } from '@mastra/core/llm';
import { createOpenAICompatible } from '@ai-sdk/openai-compatible-v5';

interface MyPrivateGatewayOptions {
  id?: string;
  baseURL?: string;
  apiKey?: string;
}

class MyPrivateGateway extends MastraModelGateway {
  readonly id: string;
  readonly name = 'My Private Gateway';

  private readonly baseURL: string;
  private readonly apiKey?: string;

  constructor(options: MyPrivateGatewayOptions = {}) {
    super();
    this.id = options.id ?? 'private';
    this.baseURL = options.baseURL ?? 'https://api.myprovider.com/v1';
    this.apiKey = options.apiKey;
  }

  async fetchProviders(): Promise<Record<string, ProviderConfig>> {
    return {
      'my-provider': {
        name: 'My Provider',
        models: ['__GATEWAY_OPENAI_MODEL__', '__GATEWAY_ANTHROPIC_MODEL_SONNET__'],
        apiKeyEnvVar: 'MY_API_KEY',
        gateway: this.id,
        url: this.baseURL,
      },
    };
  }

  buildUrl(): string {
    return this.baseURL;
  }

  async getApiKey(): Promise<string> {
    const apiKey = this.apiKey ?? process.env.MY_API_KEY;
    if (!apiKey) {
      throw new Error('Missing MY_API_KEY environment variable');
    }
    return apiKey;
  }

  resolveLanguageModel({
    modelId,
    providerId,
    apiKey,
    headers,
  }: {
    modelId: string;
    providerId: string;
    apiKey: string;
    headers?: Record<string, string>;
  }): GatewayLanguageModel {
    return createOpenAICompatible({
      name: providerId,
      apiKey,
      headers,
      baseURL: this.baseURL,
      supportsStructuredOutputs: true,
    }).chatModel(modelId);
  }
}
```

要为每个端点运行一个实例，请为每个实例提供自己的`id`. Mastra keeps only the first gateway registered with a given ID, and the ID is the model ID prefix:

```typescript
import { Mastra } from '@mastra/core';

const mastra = new Mastra({
  gateways: {
    privateEu: new MyPrivateGateway({ id: 'private-eu', baseURL: 'https://eu.api.myprovider.com/v1' }),
    privateUs: new MyPrivateGateway({ id: 'private-us', baseURL: 'https://us.api.myprovider.com/v1' }),
  },
});

// Models: 'private-eu/my-provider/__GATEWAY_OPENAI_MODEL__' and 'private-us/my-provider/__GATEWAY_OPENAI_MODEL__'
```

### 网关拥有的身份验证 {/* #gateway-owned-authentication */}

添加`resolveAuth` when the gateway owns credential lookup. Mastra uses this hook before falling back to `getApiKey()`.

```typescript
const myPrivateGateway: MastraModelGatewayInterface = {
  // ...gateway fields and methods
  async resolveAuth() {
    const apiKey = process.env.MY_API_KEY;
    return apiKey ? { apiKey, source: 'gateway' } : undefined;
  },
};
```

## 注册自定义网关 {/* #registering-custom-gateways */}

### 初始化期间 {/* #during-initialization */}

创建 Mastra 实例时将网关作为记录传递：

```typescript
import { Mastra } from '@mastra/core';

const mastra = new Mastra({
  gateways: {
    myGateway: new MyPrivateGateway(),
    anotherGateway: new AnotherGateway(),
  },
});
```

### 初始化后 {/* #after-initialization */}

使用动态添加网关`addGateway`:

```typescript
const mastra = new Mastra();

// Add with explicit key
mastra.addGateway(new MyPrivateGateway(), 'myGateway');

// Add using gateway's ID
mastra.addGateway(new MyPrivateGateway());
// Stored with key 'my-private-gateway' (the gateway's id)
```

## 使用自定义网关 {/* #using-custom-gateways */}

使用网关 ID 作为前缀的自定义网关的参考模型：

```typescript
import { Agent } from '@mastra/core/agent';

const agent = new Agent({
  id: 'my-agent',
  name: 'My Agent',
  instructions: 'You are a helpful assistant',
  model: 'private/my-provider/__GATEWAY_OPENAI_MODEL__', // Uses MyPrivateGateway
});

mastra.addAgent(agent, 'myAgent');
```

当您创建Agent或使用模型时，Mastra 的模型路由器会根据模型 ID 自动选择适当的网关。网关ID作为前缀。如果没有匹配的自定义网关，则会回退到内置网关。

### TypeScript 自动完成 {/* #typescript-autocomplete */}

#### 开发中的自动类型生成 {/* #automatic-type-generation-in-development */}

当在开发模式下运行时（`MASTRA_DEV=true`), Mastra automatically generates TypeScript types for your custom gateways.

1. **设置环境变量**:
   ```bash
   export MASTRA_DEV=true
   ```

2. **注册您的网关**:
   ```typescript
   const mastra = new Mastra({
     gateways: {
       myGateway: new MyPrivateGateway(),
     },
   });
   ```

3. **类型是自动生成的**:
   * 添加网关时，Mastra 会与 GatewayRegistry 同步
   * 注册表从您的自定义网关获取提供程序
   * TypeScript 类型在中重新生成`~/.cache/mastra/`
   * 您的 IDE 在几秒钟内即可获取新类型

4. **自动完成现在可以使用**:
   ```typescript
   const agent = new Agent({
     model: 'my-gateway-id/my-provider/model-1', // Full autocomplete!
   });
   ```

#### 它是如何运作的 {/* #how-it-works */}

GatewayRegistry 每小时运行一次同步：

* 通话`fetchProviders()` on all registered gateways
* 生成 TypeScript 类型定义
* 将它们写入全局缓存和您的项目的`dist/` directory
* 您的 TypeScript 服务器会自动获取更改

:::提示
第一次添加网关时，可能需要几秒钟的时间才能生成类型。随后的更新每小时在后台发生一次。
:::

#### 手动类型生成替代方案 {/* #manual-type-generation-alternatives */}

如果您没有在开发模式下运行或需要立即更新类型：

**选项 1：使用类型断言（最简单）**

```typescript
const agent = new Agent({
  id: 'my-agent',
  name: 'my-agent',
  instructions: 'You are a helpful assistant',
  model: 'private/my-provider/model-1' as any, // Bypass type checking
});
```

**选项 2：创建自定义类型联合（类型安全）**

```typescript
import type { ModelRouterModelId } from '@mastra/core/llm';

// Define your custom model IDs
type CustomModelId =
  | 'private/my-provider/model-1'
  | 'private/my-provider/model-2'
  | 'private/my-provider/model-3';

// Combine with built-in models
type AllModelIds = ModelRouterModelId | CustomModelId;

const agent = new Agent({
  id: 'my-agent',
  name: 'my-agent',
  instructions: 'You are a helpful assistant',
  model: 'private/my-provider/model-1' satisfies AllModelIds,
});
```

**选项 3：全局扩展 ModelRouterModelId（高级）**

```typescript
// In a types.d.ts file in your project
// The import is required: it makes this file a module, so the block below
// merges into the existing types instead of replacing the module.
import '@mastra/core/llm';

declare module '@mastra/core/llm' {
  interface ProviderModelsMap {
    'my-provider': readonly ['model-1', 'model-2', 'model-3'];
  }
}
```

这扩展了内置类型以包含您的自定义模型，为您提供全面的自动完成支持。

## 网关管理 {/* #gateway-management */}

### 获取网关（密钥） {/* #getgatewaykey */}

通过注册密钥检索网关：

```typescript
const gateway = mastra.getGateway('myGateway');
console.log(gateway.name); // 'My Private Gateway'
```

### 获取网关ID(id) {/* #getgatewaybyidid */}

通过唯一 ID 检索网关：

```typescript
const gateway = mastra.getGatewayById('my-private-gateway');
console.log(gateway.name); // 'My Private Gateway'
```

这在以下情况下很有用：

* 网关具有与其注册密钥不同的显式 ID
* 您需要跨不同实例通过 ID 查找网关
* 支持网关版本控制（例如，`'gateway-v1'`, `'gateway-v2'`)

`getGatewayById()`抛出一个`MastraError` if no registered gateway has the given ID. It doesn't return `undefined`.

### 列表网关() {/* #listgateways */}

获取所有已注册的网关：

```typescript
const gateways = mastra.listGateways();
console.log(Object.keys(gateways)); // ['myGateway', 'anotherGateway']
```

## 网关属性 {/* #gateway-properties */}

### 必需的 {/* #required */}

|物业 |类型 |描述 |
|----------|------|-------------|
|`id` | `string` | Unique identifier for the gateway, used as the gateway prefix for the model string |
| `name` | `string` | Human-readable gateway name |

### 方法 {/* #methods */}

|方法|描述 |
|--------|-------------|
|`fetchProviders()` | Fetch provider configurations |
| `buildUrl(modelId, envVars?)` | Build API URL for a model |
| `getApiKey(modelId)` | Get API key for authentication |
| `resolveLanguageModel(args)` | Create language model instance |
| `getId()` | Get gateway ID (returns `id` or `name`) |

## Provider配置 {/* #provider-configuration */}

这`fetchProviders()` method returns a record of `ProviderConfig` objects:

```typescript
interface ProviderConfig {
  name: string;                    // Display name
  models: string[];                // Available model IDs
  apiKeyEnvVar: string | string[]; // Environment variable(s) for API key
  gateway: string;                 // Gateway identifier
  url?: string;                    // Optional API base URL
  apiKeyHeader?: string;           // Optional custom auth header
  docUrl?: string;                 // Optional documentation URL
  pricing?: Record<string, ModelPricing>; // Optional prices per model ID
}
```

### 型号定价 {/* #model-pricing */}

models.dev 没有列出私有部署，因此它们的调用没有成本[metrics](/docs/observability/metrics/overview). Add a `pricing` entry per model to give them one. Prices are in USD per 1 million tokens and use the same keys as a model's `cost` on [models.dev](https://models.dev): `input`, `output`, `cache_read`, `cache_write`, `reasoning`, `input_audio`, and `output_audio`. `@mastra/observability` reads these prices on the first call to a model it can't price, which also picks up gateways added later with `addGateway()`. Under `mastra dev`, or with `MASTRA_AUTO_REFRESH_PRICING=true`, it also reads them when Mastra starts, so the first call is priced too. models.dev prices take precedence. A gateway price is used only when models.dev has none for that provider and model ID, and then it applies to every call with those IDs, including direct calls. Give a reseller its own provider ID when its rates must stay separate from direct calls. A gateway whose `fetchProviders()` fails is logged and retried about once an hour. Set `MASTRA_OFFLINE=true` to skip loading them. The same shape as models.dev also means you can add `tiers` for long-context pricing.

```typescript
async fetchProviders(): Promise<Record<string, ProviderConfig>> {
  return {
    'my-provider': {
      name: 'My Provider',
      models: ['model-1'],
      apiKeyEnvVar: 'MY_API_KEY',
      gateway: 'private',
      url: 'https://api.myprovider.com/v1',
      pricing: {
        'model-1': { input: 0.5, output: 1.5, cache_read: 0.05 },
      },
    },
  };
}
```

## 网关 ID 与密钥 {/* #gateway-ids-vs-keys */}

了解区别：

* **钥匙**：向Mastra添加网关时使用的注册密钥（记录密钥）
* **ID**：网关的唯一标识符（通过`id` property or `name` if not set)

```typescript
class VersionedGateway extends MastraModelGateway {
  readonly id = 'my-gateway-v2';     // Unique ID for versioning and prefixing
  readonly name = 'My Gateway';       // Display name
}

const mastra = new Mastra({
  gateways: {
    currentGateway: new VersionedGateway(), // Key: 'currentGateway'
  },
});

// Retrieve by key
const byKey = mastra.getGateway('currentGateway');

// Retrieve by ID
const byId = mastra.getGatewayById('my-gateway-v2');

// Both return the same gateway
console.log(byKey === byId); // true
```

## 高级示例 {/* #advanced-example */}

带缓存的基于令牌的网关：

```typescript
class TokenGateway extends MastraModelGateway {
  readonly id = 'token-gateway-v1';
  readonly name = 'Token Gateway';

  private tokenCache: Map<string, { token: string; expiresAt: number }> = new Map();

  async fetchProviders(): Promise<Record<string, ProviderConfig>> {
    const response = await fetch('https://api.gateway.com/providers');
    const data = await response.json();

    return {
      provider: {
        name: data.name,
        models: data.models,
        apiKeyEnvVar: 'GATEWAY_TOKEN',
        gateway: this.id,
      },
    };
  }

  async buildUrl(modelId: string, envVars?: Record<string, string>): Promise<string> {
    const token = await this.getApiKey(modelId);
    const siteId = envVars?.SITE_ID || process.env.SITE_ID;

    const response = await fetch(`https://api.gateway.com/sites/${siteId}/token`, {
      headers: { Authorization: `Bearer ${token}` },
    });

    const { url } = await response.json();
    return url;
  }

  async getApiKey(modelId: string): Promise<string> {
    const cached = this.tokenCache.get(modelId);

    if (cached && cached.expiresAt > Date.now()) {
      return cached.token;
    }

    const token = process.env.GATEWAY_TOKEN;
    if (!token) {
      throw new Error('Missing GATEWAY_TOKEN');
    }

    // Cache token for 1 hour
    this.tokenCache.set(modelId, {
      token,
      expiresAt: Date.now() + 3600000,
    });

    return token;
  }

  async resolveLanguageModel({ modelId, providerId, apiKey }: {
    modelId: string;
    providerId: string;
    apiKey: string;
  }): Promise<LanguageModelV2> {
    const baseURL = await this.buildUrl(`${providerId}/${modelId}`);

    return createOpenAICompatible({
      name: providerId,
      apiKey,
      baseURL,
      supportsStructuredOutputs: true,
    }).chatModel(modelId);
  }
}
```

## 错误处理 {/* #error-handling */}

提供常见故障场景的描述性错误：

```typescript
class RobustGateway extends MastraModelGateway {
  // ... properties

  async getApiKey(modelId: string): Promise<string> {
    const apiKey = process.env.MY_API_KEY;

    if (!apiKey) {
      throw new Error(
        `Missing MY_API_KEY environment variable for model: ${modelId}. ` +
        `Please set MY_API_KEY in your environment.`
      );
    }

    return apiKey;
  }

  async buildUrl(modelId: string, envVars?: Record<string, string>): Promise<string> {
    const baseUrl = envVars?.BASE_URL || process.env.BASE_URL;

    if (!baseUrl) {
      throw new Error(
        `No base URL configured for model: ${modelId}. ` +
        `Set BASE_URL environment variable or pass it in envVars.`
      );
    }

    return baseUrl;
  }
}
```

## 最佳实践 {/* #best-practices */}

1. **使用描述性 ID 进行版本控制**：设置显式`id` values when you need to version your gateways
   ```typescript
   readonly id = 'my-gateway-v1';
   ```

2. **实施正确的错误处理**：使用可操作的消息抛出描述性错误

3. **缓存昂贵的操作**：在适当的时候缓存令牌、URL 或提供程序配置

4. **验证环境变量**：检查所需的环境变量`getApiKey` and `buildUrl`

5. **记录您的网关**：添加 JSDoc 注释来解释网关的用途和配置

6. **遵循命名约定**：对提供者和模型使用清晰、一致的命名

7. **处理异步操作**： 使用`async/await` for network requests and I/O operations

8. **彻底测试**：为所有网关方法编写单元测试

## 在 Studio 中仅显示自定义网关 {/* #showing-only-custom-gateways-in-studio */}

默认情况下，**Studio** lists every external model provider (such as OpenAI, Anthropic, and Gemini) alongside any custom gateways you register. To hide the external providers, set the `AUTO_BLOCK_EXTERNAL_PROVIDERS` environment variable:

```bash
AUTO_BLOCK_EXTERNAL_PROVIDERS=true
```

当该变量设置为`true` or `1`, Mastra returns only the providers from gateways you register yourself. The static provider registry and the built-in gateways (`models.dev`, `netlify`, and `mastra`) are hidden from the model picker. This is useful when you route all model traffic through a single private gateway and don't want the other providers to appear. The filter applies to the server's `GET /agents/providers` endpoint, which Studio uses for the model picker, so API clients don't see the external providers either. It only changes which providers are listed. It doesn't stop agents from calling other providers in code.

设置此变量且未注册自定义网关后，模型选择器为空。注册至少一个自定义网关以公开其模型。
