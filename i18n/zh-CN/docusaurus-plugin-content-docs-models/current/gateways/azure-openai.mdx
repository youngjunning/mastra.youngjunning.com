# <img src="https://models.dev/logos/azure.svg" alt="Azure OpenAI 标志" className="inline w-8 h-8 mr-2 align-middle dark:invert dark:brightness-0 dark:contrast-200" />Azure OpenAI

Azure OpenAI 通过专用部署提供 OpenAI 模型的企业级访问，并提供安全性、合规性和 SLA 保障。

其他 Provider 使用固定的模型名称，Azure 则使用你在 Azure Portal 中设置的**部署名称**。

## 用法 {/* #usage */}

Azure OpenAI 网关默认不会注册。请将网关和使用它的 Agent 注册到同一个 Mastra 实例，否则解析 `azure-openai/...` 模型 ID 时会报错 `Could not find config for provider azure-openai`。

在 Agent 的模型 ID 中填写 Azure 部署名称：

```typescript title="src/mastra/agents/my-agent.ts"
import { Agent } from "@mastra/core/agent";

export const myAgent = new Agent({
  id: "my-agent",
  name: "My Agent",
  instructions: "You are a helpful assistant",
  model: "azure-openai/my-gpt-5-4-deployment", // Use your Azure deployment name (autocompleted in dev mode)
});
```

注册网关和 Agent：

```typescript title="src/mastra/index.ts"
import { Mastra } from "@mastra/core";
import { AzureOpenAIGateway } from "@mastra/core/llm";
import { myAgent } from "./agents/my-agent";

export const mastra = new Mastra({
  gateways: {
    "azure-openai": new AzureOpenAIGateway({
      resourceName: "my-openai-resource",
      apiKey: process.env.AZURE_API_KEY!,
      deployments: ["my-gpt-5-4-deployment"],
    }),
  },
  agents: { myAgent },
});
```

从 Mastra 实例获取 Agent，然后调用它：

```typescript
const agent = mastra.getAgent("myAgent");

// Generate a response
const response = await agent.generate("Hello!");

// Stream a response
const stream = await agent.stream("Tell me a story");
for await (const chunk of stream) {
  console.log(chunk);
}
```

其他身份验证和部署发现方式见[配置](#configuration)。

各地区可用的模型见 [Azure OpenAI 模型可用性](https://learn.microsoft.com/en-us/azure/ai-services/openai/concepts/models)。

## Azure 部署的工作原理 {/* #how-azure-deployments-work */}

Azure 模型 ID 遵循以下模式：`azure-openai/your-deployment-name`

部署名称**与你的 Azure 账号关联**，在 Azure Portal 创建部署时指定。常见示例包括：

* `azure-openai/my-gpt-5-4-deployment`
* `azure-openai/production-gpt-5-4`
* `azure-openai/staging-gpt-5-4-mini`

## 设置 {/* #setup */}

在 [Azure OpenAI Studio](https://oai.azure.com/) 中创建部署。资源名称和 API 密钥可在 Azure Portal 的“Keys and Endpoint”中查看。

## 配置 {/* #configuration */}

实例化网关并将其传递给 Mastra。常见的配置方式如下所示。

### 静态部署 {/* #static-deployments */}

提供来自 Azure 门户的部署名称。

```typescript
import { Mastra } from "@mastra/core";
import { AzureOpenAIGateway } from "@mastra/core/llm";

export const mastra = new Mastra({
  gateways: {
    "azure-openai": new AzureOpenAIGateway({
      resourceName: "my-openai-resource",
      apiKey: process.env.AZURE_API_KEY!,
      deployments: ["gpt-5-4-prod", "gpt-5-4-mini-dev"],
    }),
  },
});
```

### 动态发现 {/* #dynamic-discovery */}

提供管理 API 凭据后，网关会查询 Azure 管理 API，列出可用部署。

```typescript
import { Mastra } from "@mastra/core";
import { AzureOpenAIGateway } from "@mastra/core/llm";

export const mastra = new Mastra({
  gateways: {
    "azure-openai": new AzureOpenAIGateway({
      resourceName: "my-openai-resource",
      apiKey: process.env.AZURE_API_KEY!,
      management: {
        tenantId: process.env.AZURE_TENANT_ID!,
        clientId: process.env.AZURE_CLIENT_ID!,
        clientSecret: process.env.AZURE_CLIENT_SECRET!,
        subscriptionId: process.env.AZURE_SUBSCRIPTION_ID!,
        resourceGroup: "my-resource-group",
      },
    }),
  },
});
```

服务主体需要具有“Cognitive Services User”角色。详情请参阅 [Azure 文档](https://learn.microsoft.com/en-us/entra/identity-platform/howto-create-service-principal-portal)。

### Microsoft Entra ID 身份验证 {/* #microsoft-entra-id-authentication */}

如果 Azure OpenAI 资源已禁用 API 密钥，请改用 Microsoft Entra ID 身份验证。传入任何兼容 Azure SDK 的凭据，例如 `@azure/identity` 中的 `DefaultAzureCredential`。

如果使用 `DefaultAzureCredential`，请在 Mastra 项目中安装 `@azure/identity`。

```typescript
import { DefaultAzureCredential } from "@azure/identity";
import { Mastra } from "@mastra/core";
import { AzureOpenAIGateway } from "@mastra/core/llm";

export const mastra = new Mastra({
  gateways: {
    "azure-openai": new AzureOpenAIGateway({
      resourceName: "my-openai-resource",
      authentication: {
        type: "entraId",
        credential: new DefaultAzureCredential(),
      },
      deployments: ["gpt-5-4-prod", "gpt-5-4-mini-dev"],
    }),
  },
});
```

该身份需要调用 Azure OpenAI 的权限，例如 `Cognitive Services OpenAI User` 角色。

如果要指定某个托管身份，请传入 `ManagedIdentityCredential`。

```typescript
import { ManagedIdentityCredential } from "@azure/identity";

const credential = new ManagedIdentityCredential("client-id");
```

### Azure Responses API {/* #azure-responses-api */}

Azure OpenAI 通过 AI SDK Azure Provider 使用的 `v1` API 路径支持 Responses API。如果 Azure 资源和部署支持该路由，请设置 `useResponsesAPI: true`。此时网关默认使用 `apiVersion: "v1"` 和 `useDeploymentBasedUrls: false`。

```typescript
import { Mastra } from "@mastra/core";
import { AzureOpenAIGateway } from "@mastra/core/llm";

export const mastra = new Mastra({
  gateways: {
    "azure-openai": new AzureOpenAIGateway({
      resourceName: "my-openai-resource",
      apiKey: process.env.AZURE_API_KEY!,
      useResponsesAPI: true,
      deployments: ["my-gpt-5-4-deployment"],
    }),
  },
});
```

如果使用现有的 Azure chat completions 路由，请省略 `useResponsesAPI` 或将其设为 `false`。为保持兼容性，该路由默认沿用 `apiVersion: "2024-04-01-preview"` 和基于部署的 URL。

你也可以直接设置 `apiVersion` 和 `useDeploymentBasedUrls`。例如，将 `useDeploymentBasedUrls: false` 传给聊天模型的构造函数，以使用 Azure `v1` URL 格式。此时网关会将 `apiVersion` 默认设为 `"v1"`。仅传入 `apiVersion: "v1"` 时，为保持兼容性，网关仍默认使用基于部署的 URL。

请勿同时设置 `useResponsesAPI: true` 和 `useDeploymentBasedUrls: true`。Responses API 使用 Azure `v1` 路由，网关会拒绝这种组合。

正式发布的 `v1` 路由使用 `apiVersion: "v1"`。Microsoft 目前通过功能专用请求头（例如 `"aoai-evals": "preview"`）或 preview/alpha API 路径提供 `v1` 预览功能。如果 Azure Provider 配置需要 preview 查询参数值，网关仍接受 `apiVersion: "preview"` 与 `useDeploymentBasedUrls: false` 的组合。基于日期的 API 版本仅适用于旧版部署路由，因此当 `useResponsesAPI` 为 `true` 或 `useDeploymentBasedUrls` 为 `false` 时，网关会拒绝这些版本。

`v1` 路由沿用相同的 API 密钥和 Microsoft Entra ID 身份验证方式。

### Azure Responses 的 WebSocket 传输 {/* #azure-responses-websocket-transport */}

Azure OpenAI 的 Responses API 也支持 WebSocket。Agent 或 Tool 循环中，如果模型与 Tool 需要多次往返，可以使用此模式。单次请求和简短对话请继续使用标准 HTTP 传输。

WebSocket 传输需要 `useResponsesAPI: true`，因为 Azure 通过 `v1` Responses 路径提供此功能。然后在每次流式请求中设置 `providerOptions.azure.transport: "websocket"` 以启用。

```typescript
import { Agent } from "@mastra/core/agent";

const agent = new Agent({
  id: "azure-ws-agent",
  name: "Azure WebSocket Agent",
  instructions: "Use tools when they are useful.",
  model: "azure-openai/my-gpt-5-4-deployment",
});

const stream = await agent.stream("Find and improve the slow function.", {
  providerOptions: {
    azure: {
      transport: "websocket",
      store: false,
      websocket: {
        closeOnFinish: false,
      },
    },
  },
});

for await (const chunk of stream.textStream) {
  process.stdout.write(chunk);
}

stream.transport?.close();
```

要在后续对话轮次中保持连接，请设置 `closeOnFinish: false`。Azure 会在连接的本地内存中保存一条响应链，从最近的 `previous_response_id` 继续可以降低后续请求的延迟。每个连接一次只能处理一个响应，无法通过多路复用并行处理。

请勿在同一 WebSocket 连接上使用 `previous_response_id` 并发发送后续请求。Azure 每个连接一次只处理一个响应，因此 Mastra 会拒绝重叠的续接请求。请等当前流结束后再继续响应链。

### 严格结构化输出 {/* #strict-structured-output */}

网关默认在关闭严格模式的情况下发送[结构化输出](/docs/agents/structured-output)和 Tool 的 schema。此时模型可能省略字段，如果缺少必填字段，Mastra 校验就会失败。

设置 `providerOptions.azure.strictJsonSchema: true`，让 Azure 强制执行 schema：

```typescript
import { z } from "zod";

const response = await agent.generate("Summarize the ticket.", {
  structuredOutput: {
    schema: z.object({
      summary: z.string(),
      priority: z.enum(["low", "medium", "high"]).optional(),
    }),
  },
  providerOptions: {
    azure: { strictJsonSchema: true },
  },
});
```

启用严格模式后，Mastra 会先调整 schema，使其符合 Azure 的要求。所有字段都会列为必填，原本可选的字段允许传回 `null`，由 Mastra 转回 `undefined`。`uniqueItems`、`pattern` 和 `minimum` 等校验关键字会移入字段描述。Mastra 仍会根据原始 schema 校验结果。

网关使用的 AI SDK 5 Azure Provider 通过同一个开关控制输出 schema 和请求中的每个 Tool。Azure 严格模式无法表示 `z.record()` 这类允许任意键的对象。如果 Agent 的输出或 Tool schema 包含此类对象，请关闭严格模式。

`useResponsesAPI` 为 `true` 时使用 `azure` 键。对于 chat completions 路由，请改用 `providerOptions.openai.strictJsonSchema`。

## 配置参考 {/* #configuration-reference */}

|选项 |类型 |必填|描述 |
|--------|------|----------|-------------|
| `resourceName` | `string` | 是 | Azure OpenAI 资源名称 |
| `apiKey` | `string` | 是\* | “Keys and Endpoint”中的 API 密钥 |
| `authentication` | `object` | 否 | Microsoft Entra ID 身份验证 |
| `authentication.type` | `"entraId"` | 是\* | 身份验证模式 |
| `authentication.credential` | `TokenCredential` | 是\* | 用于 `entraId` 验证模式的 Azure SDK 兼容凭据 |
| `authentication.scope` | `string` | 否 | Token 范围（默认值为 `https://cognitiveservices.azure.com/.default`） |
| `apiVersion` | `string` | 否 | API 版本（默认为 `2024-04-01-preview`。`useResponsesAPI` 为 `true` 或 `useDeploymentBasedUrls` 为 `false` 时，默认为 `v1`） |
| `useResponsesAPI` | `boolean` | 否 | 通过 Azure OpenAI Responses API 解析部署（默认为 `false`） |
| `useDeploymentBasedUrls` | `boolean` | 否 | 使用基于 Azure 部署的 URL（默认为 `true`，`useResponsesAPI` 为 `true` 时默认为 `false`） |
| `deployments` | `string[]` | 否 | 静态模式使用的部署名称 |
| `management` | `object` | 否 | 管理 API 凭据 |
| `management.tenantId` | `string` | 是\* | Azure AD 租户 ID |
| `management.clientId` | `string` | 是\* | 服务主体的客户端 ID |
| `management.clientSecret` | `string` | 是\* | 服务主体的客户端密钥 |
| `management.subscriptionId` | `string` | 是\* | Azure 订阅 ID |
| `management.resourceGroup` | `string` | 是\* | 资源组名称 |

\* `apiKey` 和 `authentication.type: "entraId"` 二选一。如果提供 `management`，其子字段均为必填。
