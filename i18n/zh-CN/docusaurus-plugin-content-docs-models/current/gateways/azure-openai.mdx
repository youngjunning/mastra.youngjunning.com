Azure OpenAI 通过具有安全性、合规性和 SLA 保证的专用部署提供对 OpenAI 模型的企业级访问。

与其他具有固定模型名称的Provider不同，Azure 使用**deployment names** that you configure in the Azure Portal.

## 用法 {/* #usage */}

默认情况下，未注册 Azure OpenAI 网关。在您的 Mastra 实例上注册它，并注册在同一实例上使用它的Agent。否则`azure-openai/...` model IDs fail with `Could not find config for provider azure-openai`.

在Agent的模型 ID 中引用您的 Azure 部署名称：

```typescript title="src/mastra/agents/my-agent.ts"
import { Agent } from "@mastra/core/agent";

export const myAgent = new Agent({
  id: "my-agent",
  name: "My Agent",
  instructions: "You are a helpful assistant",
  model: "azure-openai/my-gpt-5-4-deployment", // Use your Azure deployment name (autocompleted in dev mode)
});
```

注册网关和Agent：

```typescript title="src/mastra/index.ts"
import { Mastra } from "@mastra/core";
import { AzureOpenAIGateway } from "@mastra/core/llm";
import { myAgent } from "./agents/my-agent";

export const mastra = new Mastra({
  gateways: {
    "azure-openai": new AzureOpenAIGateway({
      resourceName: "my-openai-resource",
      apiKey: process.env.AZURE_API_KEY!,
      deployments: ["my-gpt-5-4-deployment"],
    }),
  },
  agents: { myAgent },
});
```

从 Mastra 实例获取Agent并调用它：

```typescript
const agent = mastra.getAgent("myAgent");

// Generate a response
const response = await agent.generate("Hello!");

// Stream a response
const stream = await agent.stream("Tell me a story");
for await (const chunk of stream) {
  console.log(chunk);
}
```

看[Configuration](#configuration) for other authentication and deployment discovery options.

查看[Azure OpenAI model availability](https://learn.microsoft.com/en-us/azure/ai-services/openai/concepts/models) for region-specific options.

## Azure 部署的工作原理 {/* #how-azure-deployments-work */}

Azure 模型 ID 遵循以下模式：`azure-openai/your-deployment-name`

部署名称是**specific to your Azure account** and chosen when you create a deployment in Azure Portal. Common examples:

* `azure-openai/my-gpt-5-4-deployment`
* `azure-openai/production-gpt-5-4`
* `azure-openai/staging-gpt-5-4-mini`

## 设置 {/* #setup */}

创建部署于[Azure OpenAI Studio](https://oai.azure.com/). The resource name and API key are in Azure Portal under "Keys and Endpoint".

### 动态发现 {/* #dynamic-discovery */}

提供管理 API 凭据。网关查询 Azure 管理 API 以列出部署。

```typescript
import { Mastra } from "@mastra/core";
```

### Microsoft Entra ID 身份验证 {/* #microsoft-entra-id-authentication */}

当为 Azure OpenAI 资源禁用 API 密钥时，请使用 Microsoft Entra ID 身份验证。传递任何与 Azure SDK 兼容的凭据，例如`DefaultAzureCredential` from `@azure/identity`.

安装`@azure/identity` in your Mastra project if you use `DefaultAzureCredential`.

```typescript
import { DefaultAzureCredential } from "@azure/identity";
import { Mastra } from "@mastra/core";
import { AzureOpenAIGateway } from "@mastra/core/llm";

export const mastra = new Mastra({
  gateways: {
    "azure-openai": new AzureOpenAIGateway({
      resourceName: "my-openai-resource",
      authentication: {
        type: "entraId",
        credential: new DefaultAzureCredential(),
      },
      deployments: ["gpt-5-4-prod", "gpt-5-4-mini-dev"],
    }),
  },
});
```

身份需要调用 Azure OpenAI 的权限，例如`Cognitive Services OpenAI User` role.

对于特定的托管身份，通过`ManagedIdentityCredential` instead.

```typescript
import { ManagedIdentityCredential } from "@azure/identity";

const credential = new ManagedIdentityCredential("client-id");
```

### Azure 响应 API {/* #azure-responses-api */}

Azure OpenAI 通过以下方式支持响应 API`v1` API path used by the AI SDK Azure provider. Set `useResponsesAPI: true` when your Azure resource and deployment support that route. The gateway then uses `apiVersion: "v1"` and `useDeploymentBasedUrls: false` by default.

```typescript
import { Mastra } from "@mastra/core";
import { AzureOpenAIGateway } from "@mastra/core/llm";

export const mastra = new Mastra({
  gateways: {
    "azure-openai": new AzureOpenAIGateway({
      resourceName: "my-openai-resource",
      apiKey: process.env.AZURE_API_KEY!,
      useResponsesAPI: true,
      deployments: ["my-gpt-5-4-deployment"],
    }),
  },
});
```

保持`useResponsesAPI` omitted or set it to `false` for the existing Azure chat completions route. That path keeps `apiVersion: "2024-04-01-preview"` and deployment-based URLs by default for compatibility.

您仍然可以配置`apiVersion` and `useDeploymentBasedUrls` directly. For example, set `useDeploymentBasedUrls: false` to use the Azure `v1` URL shape with the chat model constructor; the gateway defaults `apiVersion` to `"v1"` for that route. Passing `apiVersion: "v1"` by itself keeps the existing deployment-based URL default for compatibility.

不要合并`useResponsesAPI: true` with `useDeploymentBasedUrls: true`; the gateway rejects that configuration because Responses API support uses the Azure `v1` route.

使用`apiVersion: "v1"` for the GA `v1` route. Microsoft currently exposes preview `v1` features through feature-specific headers, such as `"aoai-evals": "preview"`, or through preview/alpha API paths. The gateway still accepts `apiVersion: "preview"` with `useDeploymentBasedUrls: false` for Azure provider configurations that require the preview query value. Date-based API versions are only for the legacy deployment-based route, so the gateway rejects them when `useResponsesAPI` is `true` or `useDeploymentBasedUrls` is `false`.

相同的 API 密钥和 Microsoft Entra ID 身份验证模式可与`v1` route.

### Azure 响应 WebSocket 传输 {/* #azure-responses-websocket-transport */}

Azure OpenAI 还支持响应 API 上的 WebSocket 模式。将其用于具有许多模型Tool往返的Agent或Tool循环。为单次请求和简短对话保留标准 HTTP 传输。

WebSocket 传输需要`useResponsesAPI: true`, because Azure exposes it on the `v1` Responses path. Then opt in per stream request with `providerOptions.azure.transport: "websocket"`.

```typescript
import { Agent } from "@mastra/core/agent";

const agent = new Agent({
  id: "azure-ws-agent",
  name: "Azure WebSocket Agent",
  instructions: "Use tools when they are useful.",
  model: "azure-openai/my-gpt-5-4-deployment",
});

const stream = await agent.stream("Find and improve the slow function.", {
  providerOptions: {
    azure: {
      transport: "websocket",
      store: false,
      websocket: {
        closeOnFinish: false,
      },
    },
  },
});

for await (const chunk of stream.textStream) {
  process.stdout.write(chunk);
}

stream.transport?.close();
```

放`closeOnFinish: false` when you want to keep the socket open across follow-up turns. Azure keeps one response chain in connection-local memory, so continuing from the most recent `previous_response_id` can reduce continuation latency. The connection runs one response at a time and does not multiplex parallel runs.

不要发送重叠的后续请求`previous_response_id` on the same WebSocket transport. Mastra rejects overlapping continuation requests because Azure only keeps one in-flight response per connection. Wait for the active stream to finish before continuing the response chain.

### 严格的结构化输出 {/* #strict-structured-output */}

网关发送[structured output](/docs/agents/structured-output) schemas and tool schemas without strict mode by default. Without strict mode the model can leave out keys, and Mastra then fails validation when a required key is missing.

放`providerOptions.azure.strictJsonSchema: true` to have Azure enforce your schema:

```typescript
import { z } from "zod";

const response = await agent.generate("Summarize the ticket.", {
  structuredOutput: {
    schema: z.object({
      summary: z.string(),
      priority: z.enum(["low", "medium", "high"]).optional(),
    }),
  },
  providerOptions: {
    azure: { strictJsonSchema: true },
  },
});
```

启用严格模式后，Mastra 在发送架构之前准备好架构，以便 Azure 接受它们。每个键均按必需列出，可选键接受`null` and come back as `undefined`, and validation keywords such as `uniqueItems`, `pattern`, and `minimum` move into the field description. Mastra still validates the result against your original schema.

该设置涵盖输出架构和请求中的每个Tool，因为网关的 AI SDK 5 Azure 提供程序对两者使用一个标志。 Azure 严格模式无法使用自由格式键表达对象，例如`z.record()`, so keep strict mode off for agents whose output or tool schemas use them.

这`azure` key applies when `useResponsesAPI` is `true`. On the chat completions route, set `providerOptions.openai.strictJsonSchema` instead.

## 配置参考 {/* #configuration-reference */}

|选项 |类型 |必填|描述 |
|--------|------|----------|-------------|
|`resourceName` | `string` | Yes | Azure OpenAI resource name |
| `apiKey` | `string` | Yes\* | API key from "Keys and Endpoint" |
| `authentication` | `object` | No | Microsoft Entra ID authentication |
| `authentication.type` | `"entraId"` | Yes\* | Authentication mode |
| `authentication.credential` | `TokenCredential` | Yes\* | Azure SDK-compatible credential for `entraId` authentication mode |
| `authentication.scope` | `string` | No | Token scope (default: `https://cognitiveservices.azure.com/.default`) |
| `apiVersion` | `string` | No | API version (default: `2024-04-01-preview`, or `v1` when `useResponsesAPI` is `true` or `useDeploymentBasedUrls` is `false`) |
| `useResponsesAPI` | `boolean` | No | Resolve deployments through the Azure OpenAI Responses API (default: `false`) |
| `useDeploymentBasedUrls` | `boolean`|没有 |使用基于 Azure 部署的 URL（默认：`true`， 或者`false`什么时候`useResponsesAPI`是`true`) |
| `deployments` | `string[]`|没有 |静态模式的部署名称 |
|`management` | `object`|没有 |管理 API 凭证 |
|`management.tenantId` | `string`|是\* | Azure AD 租户 ID |
|`management.clientId` | `string`|是\* |服务主体客户端 ID |
|`management.clientSecret` | `string`|是\* |服务主体秘密 |
|`management.subscriptionId` | `string`|是\* | Azure 订阅 ID |
|`management.resourceGroup` | `string`|是\* |资源组名称|

\* 提供其中之一`apiKey` or `authentication.type: "entraId"`. Management fields are required if `management` is provided.
