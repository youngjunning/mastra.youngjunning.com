# 模型提供者

Mastra 提供了一个统一的界面，用于与多个Provider的法学硕士合作，让您可以通过单个 API 访问来自 223 个Provider的 8285 个模型。

## 特征 {/* #features */}

* **适用于任何型号的一个 API**：访问任何模型，无需安装和管理额外的提供程序依赖项。

* **访问最新的人工智能**：新模型发布后立即使用，无论它们来自哪个Provider。通过 Mastra 与Provider无关的界面避免Provider锁定。

* [**混合搭配模型**](#mix-and-match-models)：针对不同的任务使用不同的模型。例如，运行 GPT-5-mini 进行大上下文处理，然后切换到 Claude Opus 4.6 进行推理任务。

* [**模型后备**](#model-fallbacks)：如果某个Provider遇到中断，Mastra 可以在应用程序级别自动切换到另一个Provider，与 API 网关相比，最大限度地减少延迟。

## 基本用法 {/* #basic-usage */}

无论您使用的是 OpenAI、Anthropic、Google 还是 OpenRouter 等网关，请将模型指定为`"provider/model-name"` and Mastra handles the rest.

Mastra 读取相关的环境变量（例如`ANTHROPIC_API_KEY`) and routes requests to the provider. If an API key is missing, you'll get a clear runtime error showing exactly which variable to set.

## 混合搭配模型 {/* #mix-and-match-models */}

有些模型速度更快，但能力较差，而另一些模型则提供更大的上下文窗口或更强的推理能力。使用来自同一Provider的不同模型，或者跨Provider混合搭配以适应每项任务。

// Use a cost-effective model for document processing

## 动态模型选择 {/* #dynamic-model-selection */}

由于模型只是字符串，因此您可以根据[request context](/docs/server/request-context), variables, or any other logic.

```typescript title="src/mastra/agents/dynamic-assistant-agent.ts"
import { Agent } from "@mastra/core/agent";

const agent = new Agent({
  id: "dynamic-assistant",
  name: "Dynamic Assistant",
  model: ({ requestContext }) => {
    const provider = requestContext.get("provider-id");
    const model = requestContext.get("model-id");
    return `${provider}/${model}`;
  },
});
```

这使得强大的模式成为可能：

* A/B 测试 - 比较生产中的模型性能。
* 用户可选择的模型 - 让用户在您的应用程序中选择他们喜欢的模型。
* 多租户应用程序 - 每个客户都可以携带自己的 API 密钥和模型首选项。

## 特定于Provider的选项 {/* #provider-specific-options */}

不同的模型提供者公开自己的配置选项。使用 OpenAI，您可以调整`reasoningEffort`. With Anthropic, you might tune `cacheControl`. Mastra lets you set these specific `providerOptions` either at the agent level or per message.

```typescript title="src/mastra/agents/planner-agent.ts"
import { Agent } from "@mastra/core/agent";

// Agent level (apply to all future messages)
const planner = new Agent({
  id: "planner",
  name: "Planner",
  instructions: {
    role: "system",
    content: "You are a helpful assistant.",
    providerOptions: {
      openai: { reasoningEffort: "low" }
    }
  },
  model: "__GATEWAY_OPENAI_MODEL__",
});

const lowEffort =
  await planner.generate("Plan a simple 3 item dinner menu");

// Message level (apply only to this message)
const highEffort = await planner.generate([
  {
    role: "user",
    content: "Plan a simple 3 item dinner menu for a celiac",
    providerOptions: {
      openai: { reasoningEffort: "high" }
    }
  }
]);
```

## 模型后备 {/* #model-fallbacks */}

依赖单一模型会给您的应用程序带来单点故障。模型回退提供模型和提供者之间的自动故障转移。如果主要模型不可用，则会针对下一个配置的回退重试请求，直到成功。

```typescript title="src/mastra/agents/resilient-assistant-agent.ts"
import { Agent } from '@mastra/core/agent';

const agent = new Agent({
  id: 'resilient-assistant',
  name: 'Resilient Assistant',
  instructions: 'You are a helpful assistant.',
  model: [
    {
      model: "__GATEWAY_OPENAI_MODEL__",
      maxRetries: 3,
    },
    {
      model: "__GATEWAY_ANTHROPIC_MODEL_SONNET__",
      maxRetries: 2,
    },
    {
      model: "__GATEWAY_GOOGLE_MODEL_FLASH__",
      maxRetries: 2,
    },
  ],
});
```

Mastra 首先尝试您的主要模型。如果遇到 500 错误、速率限制或超时，它会自动切换到您的第一个后备。如果这也失败了，它就会转移到下一个。每个模型在继续之前都有自己的重试次数。

您的用户永远不会遇到中断 - 响应以相同的格式返回，只是来自不同的模型。当系统通过回退链时，错误上下文将被保留，确保干净的错误传播，同时保持流兼容性。

### 每个模型的设置 {/* #per-model-settings */}

每个后备条目可以携带自己的`modelSettings`, `providerOptions`, and `headers` — useful when models in the chain need different temperatures or provider-specific knobs to produce comparable output.

```typescript title="src/mastra/agents/tuned-resilient-agent.ts"
import { Agent } from '@mastra/core/agent';

const agent = new Agent({
  id: 'tuned-resilient',
  name: 'Tuned Resilient Agent',
  instructions: 'You are a helpful assistant.',
  model: [
    {
      model: '__GATEWAY_GOOGLE_MODEL_FLASH__',
      maxRetries: 2,
      modelSettings: { temperature: 0.3 },
      providerOptions: { google: { thinkingConfig: { thinkingBudget: 0 } } },
    },
    {
      model: '__GATEWAY_OPENAI_MODEL_LUNA__',
      maxRetries: 2,
      modelSettings: { temperature: 0.7 },
      providerOptions: { openai: { reasoningEffort: 'low' } },
    },
  ],
});
```

**优先级：**

* `modelSettings`和`providerOptions`: per-fallback entry overrides call-time options, which override agent `defaultOptions`. `modelSettings` shallow-merges by key. `providerOptions` deep-merges recursively, so nested provider config (e.g. `google.thinkingConfig`) preserves sibling keys across layers.
* `headers`: 通话时间`modelSettings.headers` overrides per-fallback `headers`, which overrides headers extracted from model-router models. Runtime headers (tracing, auth, tenancy) intentionally take precedence over model-level headers.

每个字段还接受一个函数`requestContext`, matching how dynamic models are resolved.

## 将本地模型与 Mastra 结合使用 {/* #use-local-models-with-mastra */}

Mastra 还支持本地模型，例如`gpt-oss`, `Qwen3`, `DeepSeek` and many more that you run on your own hardware. The application running your local model needs to provide an OpenAI-compatible API server for Mastra to connect to. We recommend using [LMStudio](https://lmstudio.ai/) (see [Running the LMStudio server](https://lmstudio.ai/docs/developer/core/server)).

对于自定义 OpenAI 兼容端点，`id` is the routing form that Mastra sends through the model router.

使用`provider/model` when the remote behaves like a direct provider and expects a bare model name such as `llama3.2`.

使用`gateway/provider/model` when the remote behaves like a model gateway and the upstream model namespace includes the provider, such as `mastra/google/gemini-2.5-flash` or `openrouter/google/gemini-2.5-flash`.

对于`url` it's **important** that you use the base URL of the OpenAI-compatible endpoint with Mastra's `model` setting and not the individual chat endpoints.

```typescript title="src/mastra/agents/my-agent.ts"
import { Agent } from "@mastra/core/agent";

const agent = new Agent({
  id: "my-agent",
  name: "My Agent",
  instructions: "You are a helpful assistant",
  model: {
    id: "custom/my-qwen3-model",
    url: "http://your-custom-openai-compatible-endpoint.com/v1"
  }
})
```

如果遥控器的行为类似于模型网关，请将网关前缀包含在`id`:

```typescript title="src/mastra/agents/my-agent.ts"
import { Agent } from "@mastra/core/agent";

const agent = new Agent({
  id: "my-agent",
  name: "My Agent",
  instructions: "You are a helpful assistant",
  model: {
    id: "mastra/google/gemini-2.5-flash",
    url: "http://your-custom-openai-compatible-endpoint.com/v1"
  }
})
```

### 选择 OpenAI 响应 API {/* #select-the-openai-responses-api */}

风俗`url` endpoints use the OpenAI Chat Completions API by default. If your endpoint exposes the OpenAI Responses API (`/v1/responses`) — for example to combine function tools with reasoning models on gateways that require it — set `api: "responses"`.

```typescript title="src/mastra/agents/my-agent.ts"
import { Agent } from "@mastra/core/agent";

const agent = new Agent({
  id: "my-agent",
  name: "My Agent",
  instructions: "You are a helpful assistant",
  model: {
    id: "custom/my-model",
    url: "http://your-custom-openai-compatible-endpoint.com/v1",
    api: "responses"
  }
})
```

什么时候`api` is omitted it defaults to `"chat"`, so existing configurations are unchanged.

### 自定义端点的Provider选项 {/* #provider-options-for-custom-endpoints */}

这`providerOptions` key that reaches a custom endpoint depends on the API it uses.

在默认的聊天完成路径上，使用模型的第一段`id` as the key. For `id: "lmstudio/qwen/qwen3-30b-a3b-2507"`, the key is `lmstudio`, and for `id: "openrouter/google/gemini-2.5-flash"`, it's `openrouter`. A camelCase form also works, for example `myServer` for `id: "my-server/my-model"`. If the segment contains a period, use the part before the first period.

例外的是`id` that starts with the prefix of an enabled gateway, where the key is the segment after the prefix. Netlify's gateway is always enabled, so for `id: "netlify/openai/gpt-4o"`, the key is `openai`. When `MASTRA_GATEWAY_API_KEY` is set or a `MastraGateway` with an API key is configured, `id: "mastra/google/gemini-2.5-flash"` uses `google`.

输入选项，例如`reasoningEffort` are mapped to their request field (`reasoning_effort`). Other keys, such as `parallel_tool_calls`, are copied into the request body as written. They replace any field of the same name that the AI SDK sets before them, including `model`, `temperature` from `modelSettings`, and the structured-output `response_format`. `reasoning_effort`, `verbosity`, `messages`, `tools`, and `tool_choice` are set after them, as are `stream` and `stream_options` when streaming, so those can't be replaced this way. Use `reasoningEffort` and `textVerbosity` instead of the first two.

```typescript title="src/mastra/agents/my-agent.ts"
import { Agent } from "@mastra/core/agent";

const agent = new Agent({
  id: "my-agent",
  name: "My Agent",
  instructions: "You are a helpful assistant",
  model: {
    id: "lmstudio/qwen/qwen3-30b-a3b-2507",
    url: "http://localhost:1234/v1"
  }
})
```

传递下面的选项`lmstudio` when you call the agent:

```typescript
const response = await agent.generate("Hello", {
  providerOptions: {
    lmstudio: {
      reasoningEffort: "low",
      parallel_tool_calls: false
    }
  }
})
```

其他键的行为有所不同，除非它们与`id`:

* `openaiCompatible`：仅应用键入的选项`user`, `reasoningEffort`, `textVerbosity`, and `strictJsonSchema`. Other keys under it are dropped. The `openai-compatible` spelling is deprecated. It still works but adds a warning to the result.
* `openai`：在聊天完成路径上被忽略，除非`openai` is itself the key from the `id`, as in `openai/my-model` or `openai.foo/my-model`. Then it works as described above. With `api: "responses"`, only `openai` applies, whatever the `id` prefix. On that path it takes only the OpenAI provider's typed options, such as `parallelToolCalls`, and other keys, such as `parallel_tool_calls`, are dropped.

不适用的键下的选项将被删除，且不会发出警告。如果某个选项对请求没有影响，请先检查密钥。
