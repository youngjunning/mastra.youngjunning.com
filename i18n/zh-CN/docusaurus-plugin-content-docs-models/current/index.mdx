# 模型 Provider

Mastra 提供统一接口，让你通过单个 API 使用多个 Provider 的 LLM，并访问来自 223 个 Provider 的 8285 个模型。

## 功能 {/* #features */}

- **一个 API 适配所有模型**：无需安装和管理额外的 Provider 依赖，即可访问任意模型。

- **使用最新 AI**：无论模型来自哪个 Provider，发布后即可使用。Mastra 不绑定特定 Provider 的接口，可避免供应商锁定。

- [**混用模型**](#mix-and-match-models)：为不同任务选用不同模型。例如，先用 GPT-5-mini 处理大上下文，再切换到 Claude Opus 4.6 执行推理任务。

- [**模型后备切换**](#model-fallbacks)：如果某个 Provider 服务中断，Mastra 可在应用层自动切换到其他 Provider；与 API 网关相比，这种方式可尽量减少延迟。

## 基本用法 {/* #basic-usage */}

无论使用 OpenAI、Anthropic、Google，还是 OpenRouter 等网关，只需将模型指定为 `"provider/model-name"`，其余部分由 Mastra 处理。

Mastra 会读取相应的环境变量（例如 `ANTHROPIC_API_KEY`），并将请求路由到对应 Provider。如果缺少 API 密钥，运行时错误会明确指出需要设置哪个变量。

## 动态选择模型 {/* #dynamic-model-selection */}

模型本质上是字符串，因此你可以根据[请求上下文](/docs/server/request-context)、变量或其他逻辑动态选择模型。

```typescript title="src/mastra/agents/dynamic-assistant-agent.ts"
import { Agent } from "@mastra/core/agent";

const agent = new Agent({
  id: "dynamic-assistant",
  name: "Dynamic Assistant",
  model: ({ requestContext }) => {
    const provider = requestContext.get("provider-id");
    const model = requestContext.get("model-id");
    return `${provider}/${model}`;
  },
});
```

这支持以下实用模式：

- A/B 测试——比较模型在生产环境中的表现。
- 由用户选择模型——让用户在应用中选择偏好的模型。
- 多租户应用——每位客户都可以使用自己的 API 密钥和模型偏好。

## Provider 专属选项 {/* #provider-specific-options */}

不同模型 Provider 会提供各自的配置选项。使用 OpenAI 时，可以调整 `reasoningEffort`；使用 Anthropic 时，可以调整 `cacheControl`。Mastra 支持在 Agent 层级或单条消息中设置这些特定的 `providerOptions`。

```typescript title="src/mastra/agents/planner-agent.ts"
import { Agent } from "@mastra/core/agent";

// Agent level (apply to all future messages)
const planner = new Agent({
  id: "planner",
  name: "Planner",
  instructions: {
    role: "system",
    content: "You are a helpful assistant.",
    providerOptions: {
      openai: { reasoningEffort: "low" }
    }
  },
  model: "__GATEWAY_OPENAI_MODEL__",
});

const lowEffort =
  await planner.generate("Plan a simple 3 item dinner menu");

// Message level (apply only to this message)
const highEffort = await planner.generate([
  {
    role: "user",
    content: "Plan a simple 3 item dinner menu for a celiac",
    providerOptions: {
      openai: { reasoningEffort: "high" }
    }
  }
]);
```

## 模型后备切换 {/* #model-fallbacks */}

只依赖单一模型会给应用带来单点故障。模型后备切换可在模型和 Provider 之间自动故障转移。如果主模型不可用，系统会依次使用已配置的后备模型重试请求，直到成功。

```typescript title="src/mastra/agents/resilient-assistant-agent.ts"
import { Agent } from '@mastra/core/agent';

const agent = new Agent({
  id: 'resilient-assistant',
  name: 'Resilient Assistant',
  instructions: 'You are a helpful assistant.',
  model: [
    {
      model: "__GATEWAY_OPENAI_MODEL__",
      maxRetries: 3,
    },
    {
      model: "__GATEWAY_ANTHROPIC_MODEL_SONNET__",
      maxRetries: 2,
    },
    {
      model: "__GATEWAY_GOOGLE_MODEL_FLASH__",
      maxRetries: 2,
    },
  ],
});
```

Mastra 会先尝试主模型。如果遇到 500 错误、速率限制或超时，系统会自动切换到第一个后备模型；如果仍然失败，则继续切换到下一个。切换前，每个模型都会按各自的重试次数重试。

用户不会感受到服务中断：响应格式保持不变，只是改由其他模型返回。系统沿后备链切换时会保留错误上下文，在维持流式传输兼容性的同时确保错误能够清晰传播。

### 单个模型的设置 {/* #per-model-settings */}

每个后备项都可以配置自己的 `modelSettings`、`providerOptions` 和 `headers`。如果后备链中的模型需要不同的 temperature 或 Provider 专属参数才能生成可比较的输出，这会很有用。

```typescript title="src/mastra/agents/tuned-resilient-agent.ts"
import { Agent } from '@mastra/core/agent';

const agent = new Agent({
  id: 'tuned-resilient',
  name: 'Tuned Resilient Agent',
  instructions: 'You are a helpful assistant.',
  model: [
    {
      model: '__GATEWAY_GOOGLE_MODEL_FLASH__',
      maxRetries: 2,
      modelSettings: { temperature: 0.3 },
      providerOptions: { google: { thinkingConfig: { thinkingBudget: 0 } } },
    },
    {
      model: '__GATEWAY_OPENAI_MODEL_LUNA__',
      maxRetries: 2,
      modelSettings: { temperature: 0.7 },
      providerOptions: { openai: { reasoningEffort: 'low' } },
    },
  ],
});
```

**优先级：**

- `modelSettings` 和 `providerOptions`：单个后备项会覆盖调用时选项，调用时选项又会覆盖 Agent 的 `defaultOptions`。`modelSettings` 按键浅合并；`providerOptions` 递归深合并，因此嵌套的 Provider 配置（例如 `google.thinkingConfig`）可在各层保留同级键。
- `headers`：调用时的 `modelSettings.headers` 会覆盖单个后备项的 `headers`，后者又会覆盖从模型路由器模型中提取的标头。运行时标头（追踪、身份验证和租户信息）会有意优先于模型层级标头。

每个字段也接受以 `requestContext` 为参数的函数，与动态模型的解析方式一致。

## 在 Mastra 中使用本地模型 {/* #use-local-models-with-mastra */}

Mastra 也支持在自有硬件上运行 `gpt-oss`、`Qwen3`、`DeepSeek` 等多种本地模型。运行本地模型的应用需要提供兼容 OpenAI 的 API 服务器，供 Mastra 连接。我们建议使用 [LMStudio](https://lmstudio.ai/)（参阅[运行 LMStudio 服务器](https://lmstudio.ai/docs/developer/core/server)）。

对于自定义的 OpenAI 兼容端点，`id` 是 Mastra 通过模型路由器发送的路由格式。

如果远程服务的行为类似直接 Provider，并且需要 `llama3.2` 这类不带命名空间的模型名称，请使用 `provider/model`。

如果远程服务的行为类似模型网关，并且上游模型命名空间包含 Provider，请使用 `gateway/provider/model`，例如 `mastra/google/gemini-2.5-flash` 或 `openrouter/google/gemini-2.5-flash`。

为 Mastra 的 `model` 设置 `url` 时，**务必**使用 OpenAI 兼容端点的基础 URL，而不是单个聊天端点。

```typescript title="src/mastra/agents/my-agent.ts"
import { Agent } from "@mastra/core/agent";

const agent = new Agent({
  id: "my-agent",
  name: "My Agent",
  instructions: "You are a helpful assistant",
  model: {
    id: "custom/my-qwen3-model",
    url: "http://your-custom-openai-compatible-endpoint.com/v1"
  }
})
```

如果远程服务的行为类似模型网关，请在 `id` 中加入网关前缀：
```typescript title="src/mastra/agents/my-agent.ts"
import { Agent } from "@mastra/core/agent";

const agent = new Agent({
  id: "my-agent",
  name: "My Agent",
  instructions: "You are a helpful assistant",
  model: {
    id: "mastra/google/gemini-2.5-flash",
    url: "http://your-custom-openai-compatible-endpoint.com/v1"
  }
})
```

### 选择 OpenAI Responses API {/* #select-the-openai-responses-api */}

自定义 `url` 端点默认使用 OpenAI Chat Completions API。如果端点公开 OpenAI Responses API（`/v1/responses`），例如需要在网关上将函数工具与推理模型结合使用，请设置 `api: "responses"`。

```typescript title="src/mastra/agents/my-agent.ts"
import { Agent } from "@mastra/core/agent";

const agent = new Agent({
  id: "my-agent",
  name: "My Agent",
  instructions: "You are a helpful assistant",
  model: {
    id: "custom/my-model",
    url: "http://your-custom-openai-compatible-endpoint.com/v1",
    api: "responses"
  }
})
```

省略 `api` 时，默认值为 `"chat"`，因此现有配置不受影响。

### 自定义端点的 Provider 选项 {/* #provider-options-for-custom-endpoints */}

传递到自定义端点的 `providerOptions` 键取决于该端点使用的 API。

在默认 Chat Completions 路径上，请使用模型 `id` 的第一段作为键。对于 `id: "lmstudio/qwen/qwen3-30b-a3b-2507"`，键是 `lmstudio`；对于 `id: "openrouter/google/gemini-2.5-flash"`，键是 `openrouter`。也可以使用 camelCase 形式，例如 `id: "my-server/my-model"` 对应 `myServer`。如果该段包含句点，请使用第一个句点之前的部分。

如果 `id` 以已启用网关的前缀开头，则属于例外情况：此时使用前缀后的第一段作为键。Netlify 网关始终启用，因此 `id: "netlify/openai/gpt-4o"` 的键是 `openai`。设置 `MASTRA_GATEWAY_API_KEY` 或配置带 API 密钥的 `MastraGateway` 后，`id: "mastra/google/gemini-2.5-flash"` 使用 `google`。

`reasoningEffort` 等类型化选项会映射到相应的请求字段（`reasoning_effort`）。`parallel_tool_calls` 等其他键会按原样复制到请求体中，并覆盖 AI SDK 此前设置的同名字段，包括 `model`、来自 `modelSettings` 的 `temperature`，以及结构化输出的 `response_format`。`reasoning_effort`、`verbosity`、`messages`、`tools` 和 `tool_choice` 会在这些键之后设置；流式传输时，`stream` 和 `stream_options` 也会随后设置，因此无法用这种方式覆盖。前两个字段应改用 `reasoningEffort` 和 `textVerbosity`。

```typescript title="src/mastra/agents/my-agent.ts"
import { Agent } from "@mastra/core/agent";

const agent = new Agent({
  id: "my-agent",
  name: "My Agent",
  instructions: "You are a helpful assistant",
  model: {
    id: "lmstudio/qwen/qwen3-30b-a3b-2507",
    url: "http://localhost:1234/v1"
  }
})
```

调用 Agent 时，请将选项放在 `lmstudio` 键下：

```typescript
const response = await agent.generate("Hello", {
  providerOptions: {
    lmstudio: {
      reasoningEffort: "low",
      parallel_tool_calls: false
    }
  }
})
```

除非其他键与从 `id` 得出的键一致，否则其行为如下：

- `openaiCompatible`：仅应用类型化选项 `user`、`reasoningEffort`、`textVerbosity` 和 `strictJsonSchema`；其下的其他键会被丢弃。`openai-compatible` 写法已弃用，虽然仍可使用，但会在结果中添加警告。
- `openai`：在 Chat Completions 路径上会被忽略，除非 `openai` 本身就是从 `id` 得出的键，例如 `openai/my-model` 或 `openai.foo/my-model`；此时其行为与上述说明一致。使用 `api: "responses"` 时，无论 `id` 前缀是什么，都只有 `openai` 生效。该路径只接受 OpenAI Provider 的类型化选项（例如 `parallelToolCalls`），`parallel_tool_calls` 等其他键会被丢弃。

不适用键下的选项会被直接丢弃，且不会发出警告。如果某个选项未影响请求，请先检查所用的键。
