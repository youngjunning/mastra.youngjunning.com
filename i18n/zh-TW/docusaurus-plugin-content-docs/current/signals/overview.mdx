# 訊號

**添加於：** `@mastra/core@1.39.0`

即使 Agent 正在工作，你也能隨時透過訊號將輸入送到它的[對話串](/docs/memory/message-history#threads-and-resources)。輸入可能是使用者訊息、背景工作的更新或外部事件。Mastra 會依訊號類型辨識其中的輸入。

對話持續進行時，以訊號傳送輸入，並透過[對話串串流](/docs/signals/thread-streams)接收輸出。先訂閱串流，有新輸入就送出。Mastra 預設會把輸入交給執行中的工作；對話串閒置時則啟動一次執行。送出前不必確認 Agent 是否正在執行。

若是單次請求，請用 [`agent.stream()`](/reference/streaming/agents/stream) 啟動一次執行並直接讀取回覆。它也能使用 Memory，但不會訂閱同一對話串之後的執行。

觀看 [Mastra 訊號概覽](https://www.youtube.com/watch?v=7It2y89TVP4)，了解如何用訊號喚醒並引導長時間執行的 Agent。

## 快速入門 {/* #quickstart */}

建立一個Agent，訂閱一個線程，然後將輸入傳送到該線程。首先訂閱意味著當輸入開始運行時訂閱已經開啟。

### 使用Agent {/* #use-an-agent */}

範例透過 [Memory](/docs/memory/overview) 把對話串記錄儲存在本機 libSQL 資料庫，因此下次執行或程序重新啟動後仍可繼續同一段對話。Memory 可搭配任何支援的儲存配接器。系統會在首次執行時建立對話串。

```typescript title="src/mastra/signals.ts"
import { Agent } from '@mastra/core/agent'
import { Memory } from '@mastra/memory'
import { LibSQLStore } from '@mastra/libsql'

const agent = new Agent({
  id: 'support-agent',
  name: 'Support Agent',
  instructions: 'Help the user compare options.',
  model: '__GATEWAY_OPENAI_MODEL__',
  memory: new Memory({
    storage: new LibSQLStore({
      id: 'signals-storage',
      url: 'file:./signals.db',
    }),
  }),
})

const thread = {
  resourceId: 'user_123',
  threadId: 'thread_456',
}

const subscription = await agent.subscribeToThread(thread)

const result = agent.sendMessage('Compare that with the previous option.', thread)
await result.accepted

for await (const chunk of subscription.stream) {
  console.log(chunk)
}
```

Agent 回覆時，迴圈會逐區塊印出輸出。執行結束後仍會維持訂閱，以接收同一對話串後續訊息所產生的輸出。不再需要輸出時，請呼叫 `subscription.unsubscribe()`。後續訊息及其他輸入的傳送方式請見[傳送訊號](/docs/signals/sending-signals)。

### 使用客戶端SDK {/* #use-the-client-sdk */}

使用 [`client.getAgent()`](/reference/client-js/mastra-client#methods) 時，順序相同：先呼叫 `subscribeToThread()`，再將訊息送到同一對話串。用戶端會傳回訂閱串流，執行仍由伺服器負責。完整範例請見[對話串串流](/docs/signals/thread-streams)。

## 訊號如何到達線程 {/* #how-signals-reach-a-thread */}

將輸入傳送到活動運行並不總是立即中斷模型。 Mastra 會等待，直到運行可以接受它。如果目前的答案需要先完成，請改為排隊後續答案。您還可以儲存輸入以供以後使用，而無需開始運行，或根據線程的狀態丟棄它。

[傳送訊號](/docs/signals/sending-signals#when-the-agent-sees-your-input)說明這些傳遞方式，以及如何確認輸入是否已接受。如果應用程式在多個程序中執行，請[設定共用後端](/docs/signals/running-across-processes)，讓訊號能送到執行該對話串的程序。

## 選擇 API 介面 {/* #choose-an-api-surface */}

|表面|用它來 |規範參考|
| - | - | - |
| 直接呼叫 `Agent` 方法 | 持有 Agent 執行個體的伺服器端程式碼 | [Agent 參考](/reference/agents/agent#thread-signals) |
| HTTP or the JavaScript client SDK | Applications that call a running Mastra server | [Server agent routes](/reference/server/routes#agent-message-routes), [`client.getAgent()`](/reference/client-js/agents) |
| AgentController `Session` | Long-running assistants and coding agents built on AgentController | [Agent Controller](/docs/harness/agent-controller) |

程式碼與 Agent 一起執行時，可先用 `Agent` 方法；透過伺服器呼叫時，則使用用戶端 SDK。若已採用 [Agent Controller](/docs/harness/agent-controller)，其 `Session` 會管理對話串與訂閱。
