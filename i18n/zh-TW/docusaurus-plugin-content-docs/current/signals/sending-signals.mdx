# 傳送訊號

使用者想說話時可傳送訊息；要等目前的回答完成，可將後續訊息排入佇列；應用程式需要補充上下文時，可傳送有類型的訊號。三者都以執行緒為對象，Agent 的輸出則透過[執行緒串流](/docs/signals/thread-streams)接收。

範例使用[概觀的快速入門](/docs/signals/overview#quickstart)中的 `Agent` 與執行緒。若要呼叫運作中伺服器上的 Agent，請使用[用戶端 SDK](/reference/client-js/agents) 或[伺服器路由](/reference/server/routes#agent-message-routes)。方法參數與回傳值請見 [Agent 參考文件](/reference/agents/agent#thread-signals)。

## 傳送訊息 {/* #send-a-message */}

傳送使用者輸入時，請將執行緒識別碼傳給 [`sendMessage()`](/reference/agents/agent#sendmessagemessage-options)：

```typescript title="src/mastra/signals.ts"
const result = agent.sendMessage('Compare that with the previous option.', {
  resourceId: 'user_123',
  threadId: 'thread_456',
})

await result.accepted
```

`sendMessage()` 會立刻回傳。等待 `result.accepted` 可取得 Mastra 的路由決策，並捕捉路由失敗。[控制輸入的遞送時機](#control-when-input-arrives)列出可能的動作。

Mastra 會先檢查執行緒。閒置時會開始一次執行；若正在執行，該次執行會接收訊息，模型在下一次請求時就會看到。若使用 Memory，訊息會儲存供後續執行與使用者介面取用。中斷行為請見 [Agent 何時收到輸入](#when-the-agent-sees-your-input)。

多人共用執行緒時，可加入 `attributes`：

```typescript
const result = agent.sendMessage(
  {
    contents: 'Use the latest customer note too.',
    attributes: { name: 'Jane', sentFrom: 'slack' },
  },
  { resourceId: 'user_123', threadId: 'thread_456' },
)

await result.accepted
```

模型會收到 `<user name="Jane" sentFrom="slack">Use the latest customer note too.</user>`。

## 將後續訊息排入佇列 {/* #queue-a-follow-up */}

若要等目前的回答結束，才讓 Agent 看到下一則訊息，請使用 [`queueMessage()`](/reference/agents/agent#queuemessagemessage-options)：

```typescript title="src/mastra/signals.ts"
const result = agent.queueMessage('Also check whether the tests need updates.', {
  resourceId: 'user_123',
  threadId: 'thread_456',
})

await result.accepted
```

佇列中的輸入會等目前的執行結束，再開始新一次執行。若執行緒閒置，就會立刻開始。[`cancelQueuedMessages()`](/reference/agents/agent#cancelqueuedmessagesoptions) 可移除佇列中的輸入，不會停止進行中的執行。跨行程取消採盡力而為的方式，也不會撤回已接受的輸入。

[`queueSignal()`](/reference/agents/agent#queuesignalsignal-options) 以相同方式將有類型的上下文排入佇列，同時保留訊號的 `type`、`tagName` 和屬性。

## 從系統傳送上下文 {/* #send-context-from-a-system */}

使用 [`sendSignal()`](/reference/agents/agent#sendsignalsignal-options) 補充應用程式的上下文，例如背景工作結果。訊號類型與 XML 標籤可識別這些上下文：

```typescript title="src/mastra/signals.ts"
const result = agent.sendSignal(
  {
    type: 'reactive',
    tagName: 'ci-result',
    contents: 'CI failed on main: 3 tests failed.',
  },
  { resourceId: 'user_123', threadId: 'thread_456' },
)

await result.accepted
```

`type` 說明來源：`reactive` 代表系統或處理器提供的上下文，`notification` 代表外部事件。`tagName` 用來設定 XML 標籤；若未設定，Mastra 會使用類型名稱，但 `reactive` 預設使用 `system-reminder`。

Mastra 會原樣傳遞 `contents`，並對屬性值做 XML 跳脫。與訊號標籤相符的結束標籤也會跳脫，以免內容提早關閉元素。這無法防禦提示詞注入，因此應將轉送的第三方文字視為不受信任。為符合 XML 規則，`tagName` 與屬性名稱只能包含字母、數字、句點、連字號或底線，且須以字母或底線開頭。

如同 `sendMessage()`，`sendSignal()` 預設會遞送輸入。設定 `transient: true` 後，上下文只套用於目前的請求；Mastra 不會儲存它，且暫時性訊號不能是狀態訊號。`attributes`、`metadata` 和 `providerOptions` 的說明請見 [Agent 參考文件](/reference/agents/agent#sendsignalsignal-options)。

## 在對話結束後保留輸入 {/* #input-that-outlives-the-conversation */}

事件需要在收件匣留下持久記錄、依政策遞送並供稍後讀取時，請用 [`sendNotificationSignal()`](/reference/agents/agent#sendnotificationsignalnotification-options)。它也能合併相關的待處理事件。呼叫 [`sendSignal({ type: 'notification' })`](/reference/agents/agent#sendsignalsignal-options) 只會加入上下文，並不建立收件匣記錄。設定方式與遞送規則請見[通知](/docs/signals/notifications)。

會隨時間改變的具名上下文，例如瀏覽器目前的頁面，可用 [`sendStateSignal()`](/reference/agents/agent#sendstatesignalstate-options) 傳送。請傳送完整快照或說明變更內容，不需新增聊天訊息。如何維持上下文最新，請見[狀態訊號](/docs/signals/state-signals)。

## 控制輸入的遞送時機 {/* #control-when-input-arrives */}

應用程式通常可保留預設行為：執行中的執行緒會接收輸入，閒置的執行緒則會被喚醒。需要其他結果時才覆寫設定。

| 執行緒狀態 | 預設行為 | 其他選項 |
| - | - | - |
| 執行中 | 遞送給目前的執行 | 儲存但不遞送，或捨棄 |
| 閒置 | 喚醒並開始新執行 | 儲存但不執行，或捨棄 |

用 `ifActive.behavior` 或 `ifIdle.behavior` 設定行為。例如，若要保留事件供下次取用，但不讓它自行啟動執行，可以將它儲存起來：

```typescript title="src/mastra/signals.ts"
const result = agent.sendSignal(
  {
    type: 'notification',
    contents: 'A new pull request is ready for review.',
  },
  {
    ...thread,
    ifIdle: { behavior: 'persist' },
  },
)

const { action } = await result.accepted

if (action === 'persist') {
  await result.persisted
}
```

此例只在執行緒閒置時儲存輸入。執行緒仍在執行時，輸入會遞送給該次執行，因此只在動作為 `persist` 時才設定 `persisted`。

傳送訊息或訊號會回傳 `accepted` Promise。Mastra 決定要採取的動作時，Promise 就會完成，不必等到執行結束。`sendNotificationSignal()` 只在遞送政策發出訊號時才包含 `accepted`，因此應先檢查 `decision`。`sendStateSignal()` 略過未變更的快照時，也不會回傳它。

`accepted` Promise 完成時會回傳下列其中一個動作：

- `wake`：此行程已為輸入開始一次執行。
- `deliver`：輸入已遞送給一次執行，或有其他行程接手啟動執行。
- `persist`：只儲存輸入，不遞送或開始新的執行。請等待 `persisted` 確認寫入。
- `discard`：輸入已捨棄。
- `blocked`：已有暫停的執行，使 Mastra 無法在這個執行緒開始新的執行。

動作為 `wake` 時，結果會帶有該次執行的 `output` 串流。若執行開始後失敗，錯誤會透過此串流回報。若是路由失敗，`accepted` 會遭拒。使用 [`persisted`](/reference/agents/agent#sendsignalsignal-options) 等待寫入儲存區。

## Agent 何時收到輸入 {/* #when-the-agent-sees-your-input */}

若輸入在模型請求期間抵達，Mastra 可以取消該請求，帶入新輸入後重試。模型等候第一個 token，或只產生推理內容或中繼資料時，仍可中斷。一旦模型產生文字、工具呼叫或其他內容，中斷時機便告結束。重試會在同一次執行的同一步驟使用新輸入，不會把已捨棄的回應寫入歷程。重試不計入 `maxSteps`，也不會變更 `stepNumber`。中斷次數沒有另外的上限，因此反覆收到輸入時可重啟推理，直到請求完成、執行取消或逾時。

請求一旦產生文字、工具呼叫或其他內容，就無法再中斷。之後的輸入會等到下一輪迴圈；執行中的工具不會取消或重複執行，佇列中的輸入也不會插隊。若先達到 `maxSteps`，Mastra 可能只儲存佇列中的輸入，不產生回應。

已透過串流送出的推理內容可能會繼續顯示，直到用戶端重新載入歷程。輸入處理器會在取消請求前執行完畢；輸出處理器會在下一次請求前結束，其副作用仍會保留。使用量總計不包含中斷的請求，但 Provider 仍可能收費。

訊號會以 XML 元素傳給模型：`<user>`、代表反應式上下文的 `<system-reminder>`，以及代表外部事件的 `<notification>`。設定 Memory 後，已接受的非暫時性訊號會寫入執行緒歷程。[狀態訊號](/docs/signals/state-signals)與[通知](/docs/signals/notifications)各有自己的格式。

## 停止執行或清除佇列輸入 {/* #stop-a-run-or-clear-queued-input */}

中止執行時，預設會保留佇列中的輸入。若要一併清除佇列，請傳入 `clearPendingSignals: true`：

```typescript
subscription.abort({ clearPendingSignals: true })
```

若未訂閱，請用相同選項呼叫 [`agent.abortThreadStream()`](/reference/agents/agent#abortthreadstreamoptions)。監聽器會維持訂閱，之後的訊息仍可啟動執行。使用共用 PubSub 時，清除請求會送達負責的行程，但只會清除該行程的本機佇列。中止或取消都無法撤回已完成的接受結果。接續執行是獨立的，中止原本的執行不會取消它們。

## AgentController 與 Session {/* #agentcontroller-and-session */}

多數應用程式會直接使用 `Agent` 的方法。AgentController 的 `Session` 封裝這些方法並管理訂閱：

| 工作 | `Agent` | AgentController `Session` |
| - | - | - |
| 傳送使用者訊息 | `agent.sendMessage()` | `session.sendMessage()` |
| 將使用者的後續訊息排入佇列 | `agent.queueMessage()` | `session.queueMessage()` |
| 傳送有類型的訊號 | `agent.sendSignal()` | `session.sendSignal()` |
| 將有類型的訊號排入佇列 | `agent.queueSignal()` | `session.queueSignal()` |
| 傳送通知 | `agent.sendNotificationSignal()` | `session.sendNotificationSignal()` |
| 寫入狀態訊號 | `agent.sendStateSignal()` | `Session` 未公開此方法 |
| 訂閱執行緒 | `agent.subscribeToThread()` | 由 `Session` 管理 |

`Session` 管理執行緒與訂閱的方式請見 [Agent Controller](/docs/harness/agent-controller)。
