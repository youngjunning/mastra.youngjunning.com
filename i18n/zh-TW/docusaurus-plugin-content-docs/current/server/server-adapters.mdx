# 伺服器適配器

伺服器適配器可讓您使用自己的 HTTP 伺服器來執行 Mastra，而不是使用由`mastra build`。它們提供對伺服器設定的更多控制，包括自訂中間件排序、身份驗證、日誌記錄和部署配置。您仍然可以將 Mastra 整合到任何 Node.js 應用程式中，而無需更改Agent程式或Workflow的執行方式。

：：：警告

伺服器適配器使用`mastra` instance you pass them and don't run file-based discovery. Register agents on that instance in code. To use file-based agents, run Mastra as a separate server with `mastra dev` or `mastra build`.

:::

## 何時使用伺服器適配器 {/* #when-to-use-server-adapters */}

* 您希望 Mastra 的端點自動添加到現有應用程式中
* 您需要直接存取伺服器實例以進行自訂配置
* `mastra build`.

：：：提示

對於沒有自訂伺服器要求的部署，請使用`mastra build` instead. It configures server setup and registers middleware, plus applies deployment settings based on your project configuration. See [Server Configuration](/docs/server/overview).

如果你想使用[Studio](/docs/studio/overview) with your server adapter, use [`mastra studio`](/reference/cli/mastra#mastra-studio) to only launch the Studio UI.

:::

## 配置 {/* #configuration */}

像往常一樣初始化您的應用程序，然後創建一個`MastraServer` by passing in the `app` and your main `mastra` instance from `src/mastra/index.ts`. Calling `init()` automatically registers Mastra middleware and all available endpoints. Continue adding your own routes either before or after `init()`. They run alongside Mastra’s endpoints.

<Tabs>
  <TabItem value="elysia" label="Elysia">
    ```typescript {7} title="src/elysia-server.ts"
    import { Elysia } from 'elysia'
    import { MastraServer } from '@mastra/elysia'
    import { mastra } from './mastra'

    const app = new Elysia()
    const server = new MastraServer({ app, mastra })

    await server.init()

    app.listen(4111)

    console.log('Server running on http://localhost:4111')
    ```

    :::資訊

    請參閱[Elysia Adapter](/reference/server/elysia-adapter) documentation for full configuration options.

    :::
  </TabItem>

  <TabItem value="express" label="Express">

## 初始化流程 {/* #initialization-flow */}

呼喚`init()` runs four steps in order. Understanding this flow helps when you need to insert your own middleware at specific points.

1. `registerContextMiddleware()`：將 Mastra 實例、請求上下文、Tool和中止訊號附加到每個請求。這使得 Mastra 可用於所有後續中間件和路由處理程序。
2. `registerAuthMiddleware()`：在初始化期間運行適配器身份驗證掛鉤。當 Mastra 註冊內建路由時，官方適配器會強制執行內聯身份驗證`registerApiRoute()` routes, so raw framework routes should use the adapter's exported `createAuthMiddleware()` helper when they need Mastra auth.
3. `registerUserMiddleware()`：暫存器[middleware](/docs/server/middleware) from the `server.middleware` config and `mastra.setServerMiddleware()`. Middleware handlers use Hono's signature, so Hono-based adapters (`@mastra/hono` and the adapters built on it) mount them; other adapters log a warning instead of silently ignoring the config.
4. `registerRoutes()`：註冊Agent、Workflow和其他功能的所有 Mastra API 路由。如果設定了 MCP 伺服器，也會註冊 MCP 路由。

### 手動初始化 {/* #manual-initialization */}

對於自訂中間件排序，請單獨呼叫每個方法，而不是`init()`. This is useful when you need middleware that runs before Mastra's context is set up, or when you need to insert logic between the initialization steps.

```typescript title="server.ts" oxfmt:false
const server = new MastraServer({ app, mastra });

// Your middleware first
app.use(loggingMiddleware);

server.registerContextMiddleware();

// Middleware that needs Mastra context
app.use(customMiddleware);

// Registers `server.middleware` and `setServerMiddleware()` middleware
server.registerUserMiddleware();

await server.registerRoutes();

// Routes after Mastra
app.get('/health', ...);
```

：：：提示

當您需要在 Mastra 上下文可用之前運行中間件時，或者當您需要在上下文和身份驗證步驟之間插入中間件時，請使用手動初始化。

:::

## 啟動後台工作者 {/* #start-background-workers */}

`init()`僅註冊中間件和路由。它沒有啟動Mastra的背景[workers](/docs/deployment/workers). The server generated by `mastra build` starts them for you, but with a server adapter you call `mastra.startWorkers()` yourself.

如果沒有此調用，以下功能將永遠不會運行：

* [預定的Workflow](/docs/workflows/scheduled-workflows)：不會建立計劃行並且不會觸發 cron 觸發器。
* [Agent日程](/docs/harness/schedules)創建於`mastra.schedules`
* 您在 Mastra 實例上註冊的事件偵聽器
* 這[recovery loop](/docs/workflows/overview#recovery-loop): Default-engine workflow runs whose instance stops after this server booted aren't restarted.

稱呼`startWorkers()` once, after the server starts listening:

```typescript title="server.ts"
import express from 'express'
import { MastraServer } from '@mastra/express'
import { mastra } from './mastra'

const app = express()
app.use(express.json())

const server = new MastraServer({ app, mastra })
await server.init()

const httpServer = app.listen(4111, async () => {
  try {
    await mastra.startWorkers()
  } catch (error) {
    console.error('Failed to start background workers', error)
    httpServer.close(() => process.exit(1))
  }
})

process.on('SIGTERM', async () => {
  await mastra.shutdown()
  process.exit(0)
})
```

`startWorkers()`是冪等的，因此第二次呼叫沒有效果。`mastra.shutdown()` stops the workers and drains in-flight workflow runs into a finished or suspended state before workers and pub/sub subscriptions are torn down. The drain is bounded by `drainTimeout` (default 5 seconds), and runs that don't settle within it are abandoned with a warning.

如果你在一個[separate process](/docs/deployment/workers#split-processes), skip `startWorkers()` in the API process and start them in the worker process instead.

## 新增自訂路線 {/* #adding-custom-routes */}

您可以將自己的路線與 Mastra 的路線一起添加到應用程式中。

* 已新增路線**before** `init()` won't have Mastra context available.
* 已新增路線**after** `init()` have access to the Mastra context (the Mastra instance, request context, authenticated user, etc.).
* 當您需要 Mastra 管理的身份驗證和路由元資料時，例如`requiresAuth`, prefer `registerApiRoute()`.
* 當您直接在框架應用程式上掛載路由時，請使用適配器的匯出`createAuthMiddleware()` helper if those routes need Mastra auth.

訪問“新增自訂路由”[Elysia](/reference/server/elysia-adapter#adding-custom-routes), [Express](/reference/server/express-adapter#adding-custom-routes), and [Hono](/reference/server/hono-adapter#adding-custom-routes) for more information.

## 路由前綴 {/* #route-prefixes */}

預設情況下，Mastra 路由註冊於`/api/agents`, `/api/workflows`, etc. Use the `prefix` option to change this. This is useful for API versioning or when integrating with an existing app that has its own `/api` routes.

```typescript
const server = new MastraServer({
  app,
  mastra,
  prefix: '/api/v2',
})
```

有了這個前綴，Mastra 路線就變成了`/api/v2/agents`, `/api/v2/workflows`, etc. Custom routes you add directly to the app aren't affected by this prefix.

這[built-in MCP server](/docs/server/mcp) moves with the prefix to `/api/v2/mcp`. Its OAuth metadata stays at the server root, at `/.well-known/oauth-protected-resource/api/v2/mcp`.

## OpenAPI 規範 {/* #openapi-spec */}

Mastra 可以為所有已註冊的路線產生 OpenAPI 規格。這對於文件或客戶端產生非常有用，包括與 API Tool的整合。透過設定啟用它`openapiPath` option:

```typescript
const server = new MastraServer({
  app,
  mastra,
  openapiPath: '/openapi.json',
})
```

該規範是根據每個路由上定義的 Zod 架構產生的，並在指定路徑上提供服務。它包括所有 Mastra 路線以及使用創建的任何自訂路線`createRoute()`.

## 串流資料編輯 {/* #stream-data-redaction */}

當流Agent程式透過 HTTP 回應時，HTTP 流層會在將流塊傳送到用戶端之前編輯敏感資訊。這可以防止意外暴露：

* 系統提示和坐席指令
* Tool定義及其參數
* 請求正文中的 API 金鑰和其他憑證
* 內部配置數據

此修訂發生在 HTTP 邊界，因此內部回呼如下`onStepFinish` still have access to the full request data for debugging and observability purposes.

預設情況下，啟用密文。透過配置此行為`streamOptions`. Set `redact: false` only for internal services or debugging scenarios where you need access to the full request data in stream responses.

```typescript
const server = new MastraServer({
  app,
  mastra,
  streamOptions: {
    redact: true, // Default
  },
})
```

看[MastraServer](/reference/server/mastra-server) for full configuration options.

## 每個路由的身份驗證覆蓋 {/* #per-route-auth-overrides */}

在 Mastra 實例上配置身份驗證後，預設情況下所有路由都需要身份驗證。有時您需要例外：公共衛生檢查端點或 Webhook 接收器，或需要更嚴格控制的管理路由。

使用`customRouteAuthConfig` to override authentication behavior for specific routes. Keys follow the format `METHOD:PATH` where method is `GET`, `POST`, `PUT`, `DELETE`, or `ALL`. Paths support wildcards (`*`) for matching multiple routes. Setting a value to `false` makes the route public, while `true` requires authentication.

```typescript
const server = new MastraServer({
  app,
  mastra,
  customRouteAuthConfig: new Map([
    // Public health check
    ['GET:/api/health', false],
    // Public API spec
    ['GET:/api/openapi.json', false],
    // Public webhook endpoints
    ['POST:/api/webhooks/*', false],
    // Require auth even if globally disabled
    ['POST:/api/admin/reset', true],
    // Protect all methods on internal routes
    ['ALL:/api/internal/*', true],
  ]),
})
```

看[MastraServer](/reference/server/mastra-server) for full configuration options.

## 訪問應用程式 {/* #accessing-the-app */}

建立適配器後，您可能仍需要存取底層框架應用程式。将其传递到平台时这很有用`serve` function or when adding routes from another module.

```typescript
// Via the MastraServer instance
const app = server.getApp()

// Via the Mastra instance (available after adapter construction)
const app = mastra.getServerApp()
```

兩種方法都傳回相同的應用程式實例。根據範圍使用更方便的選項。

## 伺服器配置與適配器選項 {/* #server-config-vs-adapter-options */}

使用伺服器適配器時，配置來自兩個地方：Mastra`server` config (passed to the `Mastra` constructor) and the adapter constructor options. Understanding which options come from where helps avoid confusion when settings don't seem to take effect.

### 由適配器使用 {/* #used-by-adapters */}

`mastra.getServer()`:

|選項|說明 |
| - | - |
|`auth` | Authentication config, used by `registerAuthMiddleware()`. |
| `apiRoutes` | Custom [`registerApiRoute()`](/reference/server/register-api-route) routes, registered by `registerCustomApiRoutes()` and added to the OpenAPI spec when `openapiPath` is set. The adapter constructor `customApiRoutes` option overrides this list. |
| `bodySizeLimit` | Default body size limit in bytes. Can be overridden per-adapter via `bodyLimitOptions`. |
| `onError` | Custom error handler called when an unhandled error occurs in a route handler. See [server.onError](/reference/configuration#serveronerror). |
| `middleware` | User [middleware](/docs/server/middleware), registered by `registerUserMiddleware()`. Hono-based adapters run it; Elysia, Express, Fastify, Koa, and NestJS log a warning because Hono handlers can't run there. |

### 僅適配器建構函數 {/* #adapter-constructor-only */}

這些選項直接傳遞給適配器建構函數，而不是從 Mastra 配置中讀取：

|選項|說明 |
| - | - |
|`prefix` | Route path prefix |
| `openapiPath` | OpenAPI spec endpoint |
| `bodyLimitOptions` | Body size limit with custom error handler |
| `streamOptions` | Stream redaction settings |
| `customRouteAuthConfig` | Per-route auth overrides |
| `mcpOptions` | MCP transport options (e.g., `setRequestAuth` to control `context.mcp.extra.authInfo`) |

### 不被適配器使用 {/* #not-used-by-adapters */}

這些`server` config options are only used by `mastra build` and have no effect when using adapters directly:

|選項 |使用者 |
| - | - |
|`port`, `host` | `mastra dev`, `mastra build` |
| `cors` | `mastra build` adds CORS middleware |
| `timeout` | `mastra build` |

使用轉接器時，直接使用您的框架配置這些功能。例如，使用 Hono 或 Express 的內建 CORS 套件新增 CORS 中間件，並在呼叫框架的監聽函數時設定連接埠。

## MCP支援 {/* #mcp-support */}

伺服器適配器在期間註冊MCP（模型上下文協定）路由`registerRoutes()` when MCP servers are configured in your Mastra instance. MCP allows external tools and services to connect to your Mastra server and interact with your agents.

每個伺服器都暴露在`/api/mcp/:serverId/mcp` over Streamable HTTP. By default the transport keeps session state between requests. For serverless environments like Cloudflare Workers or Vercel Edge, set `mcpOptions: { serverless: true }` to run in stateless mode without session management.

經過`mcpOptions` to control how the authenticated principal reaches tools. When using the Mastra deployer (the standard `mastra dev` / `mastra build` path), set it in your server config:

```typescript
const mastra = new Mastra({
  server: {
    mcpOptions: {
      setRequestAuth: (req, requestContext) => {
        req.auth = requestContext.get('mcpAuth')
      },
    },
  },
})
```

手動建立伺服器適配器時，傳遞`mcpOptions` directly:

```typescript
const server = new MastraServer({
  app,
  mastra,
  mcpOptions: {
    setRequestAuth: (req, requestContext) => {
      req.auth = requestContext.get('mcpAuth')
    },
  },
})
```

看[MCP](/docs/connections/mcp) for configuration details and how to set up MCP servers.
