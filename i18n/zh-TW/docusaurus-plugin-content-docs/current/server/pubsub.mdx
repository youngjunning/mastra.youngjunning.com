# PubSub

Mastra 以發布／訂閱（pub/sub）系統作為內部事件匯流排。元件將事件發布到主題，其他元件訂閱主題並回應事件。後端決定事件是在單一程序內、同一主機的多個程序之間，或跨執行個體傳遞。

只要在 `Mastra` 執行個體設定一次後端，整個系統就能共用。預設的程序內後端不必另外設定。

## Mastra 如何使用 PubSub {/* #how-mastra-uses-pubsub */}

多個內建系統透過同一條匯流排發布與訂閱事件：

- **執行 Workflow**：排程器發布 `workflow.start` 事件，由長時間執行的 Worker 接收並執行 Workflow。執行期間，步驟和生命週期事件也經 PubSub 傳遞。
- **排程 Workflow**：排程器向 Workflow 主題發布事件，派送已到執行時間的工作。請參閱[排程 Workflow](/docs/workflows/scheduled-workflows)。
- **背景工作**：工作管理員將工作派給一組 Worker，並將工作生命週期的更新分送給訂閱者，讓背景工作串流能即時更新。請參閱[背景工作串流](/docs/harness/background-tasks#subscribe-to-all-task-events)。
- **Agent 訊號**：向正在執行的 Agent 傳送訊號時，系統會在執行緒主題發布事件，讓其他程序中的這次執行也能收到訊號。
- **可續接的串流**：串流片段會依執行個別發布，用戶端重新連線後可以重播先前漏收的片段。

這些系統共用同一條匯流排，因此所選的後端會套用到所有系統。

## 事件傳遞模式 {/* #delivery-modes */}

依 [`PubSub`](/reference/pubsub/base) 的介面約定，後端會用以下其中一種模式傳遞事件：

- **拉取**：消費者主動從後端讀取事件。Mastra 以持續運作的 Worker 迴圈讀取；[`RedisStreamsPubSub`](/reference/pubsub/redis-streams) 等分散式後端採用這種模式。
- **推送**：消費者不必主動請求，事件會在程序內或透過 HTTP 送達。預設的 [`EventEmitterPubSub`](/reference/pubsub/event-emitter) 會在程序內推送。

訂閱者也能透過消費者群組分工。同組成員分攤事件，每個事件在組內只會處理一次。未加入群組的訂閱者各自收到所有事件。

## 預設後端 {/* #default-backend */}

若未設定 `pubsub` 選項，Mastra 會使用 [`EventEmitterPubSub`](/reference/pubsub/event-emitter)。它透過 Node.js 的 [`EventEmitter`](https://nodejs.org/api/events.html#class-eventemitter) 在程序內傳遞事件，不需要外部服務。

```typescript title="src/mastra/index.ts"
import { Mastra } from '@mastra/core'

// No pubsub option: Mastra uses EventEmitterPubSub
export const mastra = new Mastra({})
```

事件只在程序內傳遞，不會持久保存，也不會送到其他程序。預設後端適合單一執行個體，能滿足多數應用程式的需求。

## 選擇後端 {/* #choosing-a-backend */}

透過 `Mastra` 執行個體的 `pubsub` 選項設定後端。所有後端都實作相同的 [`PubSub`](/reference/pubsub/base) 介面，應用程式的其他部分不用修改。

選擇後端時，重點是訂閱者在哪裡執行。

| 後端 | 範圍 | 模式 | 套件 |
| - | - | - | - |
| [`EventEmitterPubSub`](/reference/pubsub/event-emitter) | 單一程序 | 拉取與推送 | `@mastra/core` |
| [`UnixSocketPubSub`](/reference/pubsub/unix-socket-pubsub) | 同一主機上的多個程序 | 推送 | `@mastra/core` |
| [`RedisStreamsPubSub`](/reference/pubsub/redis-streams) | 分散在多台主機 | 拉取 | `@mastra/redis-streams` |
| [`GoogleCloudPubSub`](/reference/pubsub/google-cloud-pubsub) | 分散在多台主機 | 拉取 | `@mastra/google-cloud-pubsub` |

### 一台主機上的多個進程 {/* #multiple-processes-on-one-host */}

同一台主機上的多個程序需要共用事件串流時，請使用 [`UnixSocketPubSub`](/reference/pubsub/unix-socket-pubsub)。它透過 Unix 網域通訊端傳遞事件，並選出一個程序當中介。如果中介結束，其他程序會選出新的中介。

```typescript title="src/mastra/index.ts"
import { Mastra } from '@mastra/core'
import { UnixSocketPubSub } from '@mastra/core/events'

export const mastra = new Mastra({
  pubsub: new UnixSocketPubSub('/tmp/mastra/events.sock'),
})
```

### 分散式部署 {/* #distributed-deployments */}

如果部署在多個執行個體或主機上，且每個執行個體都要接收相同事件，請使用分散式後端。例如，某個執行個體收到的請求需要通知另一個執行個體上的工作。

例如，要傳送訊號給正在執行的 Agent，訊號事件必須跨程序送到負責這次執行的個體。使用預設的程序內後端時，該個體收不到事件。

若儲存介接器不支援執行隔離（run fencing），[持久化 Agent](/docs/harness/durable-agents#run-ownership) 的當機復原也取決於後端。復原時會利用後端的租約判斷其他執行個體是否仍在推進這次執行。`RedisStreamsPubSub` 支援跨主機租約，`GoogleCloudPubSub` 則不支援。

以下兩種後端都能跨程序和主機傳遞事件，並持久保存事件以供重新傳遞。

以下範例使用 [Redis Streams](https://redis.io/docs/latest/develop/data-types/streams/)：

```typescript title="src/mastra/index.ts"
import { Mastra } from '@mastra/core'
import { RedisStreamsPubSub } from '@mastra/redis-streams'

export const mastra = new Mastra({
  pubsub: new RedisStreamsPubSub({
    url: 'redis://localhost:6379',
  }),
})
```

以下範例使用 [Google Cloud Pub/Sub](https://cloud.google.com/pubsub/docs)：

```typescript title="src/mastra/index.ts"
import { Mastra } from '@mastra/core'
import { GoogleCloudPubSub } from '@mastra/google-cloud-pubsub'

export const mastra = new Mastra({
  pubsub: new GoogleCloudPubSub({
    projectId: 'my-project',
  }),
})
```

## 可續接的串流 {/* #resumable-streams */}

可續接的串流讓用戶端重新連線後重播漏收的事件，因此後端要保留近期記錄。[`RedisStreamsPubSub`](/reference/pubsub/redis-streams) 等分散式後端會持久保存事件，本身就支援重播。

程序內傳遞不會保留歷史記錄。若要為 [`EventEmitterPubSub`](/reference/pubsub/event-emitter) 加入重播功能，可用 [`CachingPubSub`](/reference/pubsub/caching-pubsub) 封裝它。它會依主題記錄已發布的事件，讓稍後訂閱或重新連線的訂閱者先補收事件，再接收即時事件。

```typescript title="src/mastra/index.ts"
import { Mastra } from '@mastra/core'
import { CachingPubSub, EventEmitterPubSub } from '@mastra/core/events'
import { InMemoryServerCache } from '@mastra/core/cache'

const cache = new InMemoryServerCache()

export const mastra = new Mastra({
  pubsub: new CachingPubSub(new EventEmitterPubSub(), cache),
})
```

完整的事件傳遞約定及各後端的設定選項，請參閱 [PubSub 參考文件](/reference/pubsub/base)。
