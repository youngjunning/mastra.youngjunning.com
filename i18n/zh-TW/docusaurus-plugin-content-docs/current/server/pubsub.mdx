# 發布訂閱

Mastra 使用發布/訂閱 (pub/sub) 系統作為其內部事件總線。元件將事件發佈到主題，其他元件訂閱這些主題以做出反應。後端確定事件是在單一進程內、一台主機上的進程之間或跨單獨的實例傳遞。

設定後端一次`Mastra` instance for use throughout the system. The default is an in-process backend that requires no setup.

## Mastra 如何使用 PubSub {/* #how-mastra-uses-pubsub */}

多個內建系統透過相同的發布/訂閱匯流排發布和訂閱事件：

* **Workflow執行**：調度程序發布一個`workflow.start` event, and a long-lived worker consumes it to run the workflow. Step and lifecycle events flow over pub/sub during execution.
* **預定的Workflow**：調度程序透過發佈到Workflow主題來調度到期運行。看[Scheduled workflows](/docs/workflows/scheduled-workflows).
* **後台任務**：任務管理器將工作分派給工作群組，並將任務生命週期更新傳送給訂閱者，這就是後台任務流程保持活動狀態的方式。看[Background task streaming](/docs/harness/background-tasks#subscribe-to-all-task-events).
* **Agent訊號**：向活動Agent執行發送訊號會在執行緒主題上發布事件，因此在另一個進程中執行的運行會收到該訊號。
* **可恢復的串流**：每次運行都會發布流塊，因此重新連接的客戶端可以重播它錯過的內容。

由於這些系統會在一條總線上運行，因此您選擇的後端會同時套用於所有系統。

## 交付方式 {/* #delivery-modes */}

後端以兩種模式之一傳遞事件，由[`PubSub`](/reference/pubsub/base) contract:

* **拉**：消費者自行從後端讀取數據，Mastra 透過長期工作循環來實現這一點。分散式後端，例如[`RedisStreamsPubSub`](/reference/pubsub/redis-streams) use this mode.
* **推**：事件在沒有消費者詢問的情況下到達，無論是在進程中還是透過 HTTP。預設[`EventEmitterPubSub`](/reference/pubsub/event-emitter) delivers this way in process.

訂閱者也可以透過消費者群組分發工作。同一組的成員拆分事件，以便每個事件處理一次。沒有分組的訂閱者會收到每個事件，從而將流扇出到所有未分組的訂閱者。

## 預設後端 {/* #default-backend */}

當你沒有設定`pubsub` option, Mastra uses [`EventEmitterPubSub`](/reference/pubsub/event-emitter). It delivers events in process using a Node.js [`EventEmitter`](https://nodejs.org/api/events.html#class-eventemitter), so it works without any external service.

```typescript title="src/mastra/index.ts"
import { Mastra } from '@mastra/core'

// No pubsub option: Mastra uses EventEmitterPubSub
export const mastra = new Mastra({})
```

由於它在進程中運行，因此事件不會持久存在，也不會到達其他進程。預設值適合單一實例，涵蓋大多數應用程式。

## 選擇後端 {/* #choosing-a-backend */}

設定`pubsub` option on the `Mastra` instance to choose a backend. Each backend implements the same [`PubSub`](/reference/pubsub/base) contract, so the rest of your application doesn't change.

決定性的問題是訂戶在哪裡運行。

|後端 |範圍 |模式|套餐 |
| - | - | - | - |
|[`EventEmitterPubSub`](/reference/pubsub/event-emitter) | Single process | Pull and push | `@mastra/core` |
| [`UnixSocketPubSub`](/reference/pubsub/unix-socket-pubsub) | Multiple processes, one host | Push | `@mastra/core` |
| [`RedisStreamsPubSub`](/reference/pubsub/redis-streams) | Distributed, multiple hosts | Pull | `@mastra/redis-streams` |
| [`GoogleCloudPubSub`](/reference/pubsub/google-cloud-pubsub) | Distributed, multiple hosts | Pull | `@mastra/google-cloud-pubsub` |

### 一台主機上的多個進程 {/* #multiple-processes-on-one-host */}

使用[`UnixSocketPubSub`](/reference/pubsub/unix-socket-pubsub) when several processes on the same machine need to share a stream. It delivers events over a Unix domain socket and elects one process as a broker. If the broker exits, the remaining processes elect a new one.

```typescript title="src/mastra/index.ts"
import { Mastra } from '@mastra/core'
import { UnixSocketPubSub } from '@mastra/core/events'

export const mastra = new Mastra({
  pubsub: new UnixSocketPubSub('/tmp/mastra/events.sock'),
})
```

### 分散式部署 {/* #distributed-deployments */}

當您執行多個執行個體或主機並且每個執行個體接收相同的事件時，請使用分散式後端。每當一個實例處理的請求必須到達另一個實例上執行的工作時，這一點就很重要。

例如，向Agent程式運行發送訊號需要訊號事件跨越進程邊界到達擁有該運行的實例。使用進程內預設值時，該實例永遠不會接收該事件。

[持久劑](/docs/harness/durable-agents#run-ownership)當儲存適配器不支援運作防護時，崩潰復原還取決於後端。然後，恢復使用後端的租約來判斷另一個實例是否仍在驅動運行。`RedisStreamsPubSub` provides leases across hosts. `GoogleCloudPubSub` doesn't.

下面的兩個後端都跨進程和主機進行交付，並保留事件以進行重新交付。

[Redis Streams](https://redis.io/docs/latest/develop/data-types/streams/):

```typescript title="src/mastra/index.ts"
import { Mastra } from '@mastra/core'
import { RedisStreamsPubSub } from '@mastra/redis-streams'

export const mastra = new Mastra({
  pubsub: new RedisStreamsPubSub({
    url: 'redis://localhost:6379',
  }),
})
```

[Google Cloud Pub/Sub](https://cloud.google.com/pubsub/docs):

```typescript title="src/mastra/index.ts"
import { Mastra } from '@mastra/core'
import { GoogleCloudPubSub } from '@mastra/google-cloud-pubsub'

export const mastra = new Mastra({
  pubsub: new GoogleCloudPubSub({
    projectId: 'my-project',
  }),
})
```

## 可恢復的串流 {/* #resumable-streams */}

可恢復的串流允許客戶端重新連接並重播它錯過的事件，這需要後端保留最近的歷史記錄。分散式後端，例如[`RedisStreamsPubSub`](/reference/pubsub/redis-streams) persist events, so they support replay on their own.

進程內交付不保留歷史記錄。新增重播[`EventEmitterPubSub`](/reference/pubsub/event-emitter), wrap it in [`CachingPubSub`](/reference/pubsub/caching-pubsub), which records published events per topic so a late or reconnecting subscriber can catch up before continuing with live events.

```typescript title="src/mastra/index.ts"
import { Mastra } from '@mastra/core'
import { CachingPubSub, EventEmitterPubSub } from '@mastra/core/events'
import { InMemoryServerCache } from '@mastra/core/cache'

const cache = new InMemoryServerCache()

export const mastra = new Mastra({
  pubsub: new CachingPubSub(new EventEmitterPubSub(), cache),
})
```

參觀[PubSub reference](/reference/pubsub/base) for the full delivery contract and the configuration options for each backend.
