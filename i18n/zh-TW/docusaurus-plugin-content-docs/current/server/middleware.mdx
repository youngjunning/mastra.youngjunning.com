# 中介軟體

Mastra 伺服器可以在 API 之前或之後執行自訂中間件功能
呼叫路由處理程序。這對於諸如身份驗證之類的事情很有用，
記錄、注入特定於請求的上下文或新增 CORS 標頭。

中介軟體接收[Hono](https://hono.dev) `Context` (`c``next`功能。如果它回傳一個`Response`请求被短路。呼喚`next()`繼續處理下一個中介軟體或路由處理程序。



中間件處理程序使用 Hono 的簽名，因此它們在基於 Hono 的服務上運行
路徑：`mastra dev` and `mastra build`, the
[Hono adapter](/reference/server/hono-adapter), and adapters built on it such as
`@mastra/next` and `@mastra/tanstack-start`. Adapters for other frameworks
(Elysia, Express, Fastify, Koa, NestJS) can't run Hono handlers and log a
warning at startup when middleware is configured. Register middleware through
the framework's own API there instead.

用戶中間件永遠不會在聲明為公共的路由上運行`requiresAuth: false`, so it can't block endpoints the framework needs to keep
reachable, such as the Studio sign-in routes.

:::

```typescript
import { Mastra } from '@mastra/core'

export const mastra = new Mastra({
  server: {
    middleware: [
      {
        handler: async (c, next) => {
          // Example: Add authentication check
          const authHeader = c.req.header('Authorization')
          if (!authHeader) {
            return new Response('Unauthorized', { status: 401 })
          }

          await next()
        },
        path: '/api/*',
      },
      // Add a global request logger
      async (c, next) => {
        console.log(`${c.req.method} ${c.req.url}`)
        await next()
      },
    ],
  },
})
```

若要將中介軟體附加到單一路由，請透過`middleware` option to
`registerApiRoute`:

```typescript
registerApiRoute('/my-custom-route', {
  method: 'GET',
  middleware: [
    async (c, next) => {
      console.log(`${c.req.method} ${c.req.url}`)
      await next()
    },
  ],
  handler: async c => {
    const mastra = c.get('mastra')
    return c.json({ message: 'Hello, world!' })
  },
})
```

## 常見範例 {/* #common-examples */}

### 封鎖內建路由組 {/* #block-built-in-route-groups */}

Mastra 不提供用於刪除或將內建路由列入白名單的設定選項。在基於 Hono 的服務路徑上，您可以透過回傳回應而不呼叫來使所選路由組不可用`next()`:

```typescript title="src/mastra/index.ts"
import { Mastra } from '@mastra/core'

const notFound = async () => new Response('Not Found', { status: 404 })

export const mastra = new Mastra({
  server: {
    middleware: [
      { path: '/api/memory/*', handler: notFound },
      { path: '/api/logs/*', handler: notFound },
      { path: '/api/observability/*', handler: notFound },
    ],
  },
})
```

每個通配符模式都會阻止路由組本身及其嵌套路由。例如，`/api/logs/*` blocks `/api/logs` and `/api/logs/transports`. Other route groups remain available.

`server.apiPrefix` to the Hono adapter's [`prefix` constructor option](/reference/server/hono-adapter#constructor-parameters), which prefixes built-in routes. Middleware paths are registered unchanged, so they must explicitly include the configured prefix. For example, with `apiPrefix: '/api/v2'`, use `/api/v2/memory/*`. Custom API routes must live outside the configured API prefix and aren't blocked by these patterns.

此方法無法阻止公開的路由`requiresAuth: false`, because Mastra skips user middleware for those routes. With a non-Hono server adapter, register equivalent middleware through the server framework instead.

期間`mastra dev`, inspect the full built-in route list, including MCP routes, in the [OpenAPI specification](http://localhost:4111/api/openapi.json). See the [server overview](/docs/server/overview#rest-api) for API exploration and production settings.

如果您使用中間件進行驗證而不使用`server.auth`, prefer default-deny middleware that authenticates requests before allowing access, rather than enumerating protected paths. Include the full API prefix so REST routes alongside MCP transports are covered.

### 使用`RequestContext` {/* #using-requestcontext */}

您可以填充`RequestContext` in a runtime server middleware by extracting information from the request. In this example, the `temperature-unit` is set based on the Cloudflare `CF-IPCountry` header to ensure responses match the user's locale.

```typescript title="src/mastra/index.ts"
import { Mastra } from '@mastra/core'
import { RequestContext } from '@mastra/core/request-context'
import { testWeatherAgent } from './agents/test-weather-agent'

export const mastra = new Mastra({
  agents: { testWeatherAgent },
  server: {
    middleware: [
      async (context, next) => {
        const country = context.req.header('CF-IPCountry')
        const requestContext = context.get('requestContext')

        requestContext.set('temperature-unit', country === 'US' ? 'fahrenheit' : 'celsius')

        await next()
      },
    ],
  },
})
```

### 授權（使用者隔離） {/* #authorization-user-isolation */}



如果沒有伺服器強制的資源範圍或其他授權策略，經過驗證的呼叫者可以跨資源列出執行緒並存取其訊息和工作記憶體。呼叫者不需要猜測執行緒 ID：無範圍列表可以公開它們。對於每用戶或每租戶的私有內存，配置`mapUserToResourceId` or set a trusted resource ID in middleware.

在共享應用程式中，跨資源存取可能是有意的。資源 ID 可以識別使用者、租用戶、項目或其他分組。選擇與誰可以存取這些資源相符的授權策略。

將記憶體和執行緒範圍限定給經過驗證的使用者最簡單的方法是`mapUserToResourceId` callback in the auth config:

```typescript
import { Mastra } from '@mastra/core'

export const mastra = new Mastra({
  server: {
    auth: {
      authenticateToken: async token => {
        return verifyToken(token) // { id: 'user-123', orgId: 'org-456', ... }
      },
      mapUserToResourceId: user => user.id,
    },
  },
})
```

認證成功後，`mapUserToResourceId` is called with the authenticated user object. The returned value is set as `MASTRA_RESOURCE_ID_KEY` on the request context, which works across all server adapters (Hono, Express, Next.js, etc.).

配置後，回呼必須傳回非空字串。如果它拋出或返回`null`, `undefined`, an empty or whitespace-only string, or a non-string value, authentication middleware rejects the request with a 500 error before the route runs. This applies to all requests that run authentication, including non-memory routes. A client-provided resource ID can't override a failed mapping.

和`CompositeAuth`, this requirement applies to the provider that authenticated the request. A provider without a mapper keeps its existing behavior, even if another provider in the composite has one. The same validation applies to configured Studio auth mappers.

如果沒有映射器，身份驗證將無法實現使用者隔離：您負責在中間件中設定可信任資源 ID 或以其他方式強制執行授權。

資源 ID 不必是`user.id`. Common patterns:

```typescript
// Per-user within an organization
mapUserToResourceId: user => `${user.orgId}:${user.id}`

// From a JWT claim
mapUserToResourceId: user => user.tenantId

// Composite key
mapUserToResourceId: user => `${user.workspaceId}:${user.projectId}:${user.id}`
```

設定資源 ID 後，伺服器會自動：

* ****僅傳回配置的資源範圍內的執行緒
* **驗證線程訪問**如果存取屬於不同資源的線程，則傳回 403
* **強制創建線程**使用配置的資源 ID
* **驗證訊息操作**包括刪除，確保訊息屬於配置的資源範圍內的線程

即使客戶通過了`?resourceId=other-resource-id`, the server-set value takes precedence. Attempts to access threads or messages belonging to a different resource return a 403 error. Users mapped to the same resource ID share that resource scope.

#### 進階：在中間件中設定資源ID {/* #advanced-setting-resource-id-in-middleware */}

對於更複雜的場景（例如，從資料庫中尋找資源ID），您可以設定`MASTRA_RESOURCE_ID_KEY` directly in middleware:

```typescript
import { Mastra } from '@mastra/core'
import { MASTRA_RESOURCE_ID_KEY } from '@mastra/core/request-context'
import { getAuthenticatedUser } from '@mastra/server/auth'

export const mastra = new Mastra({
  server: {
    auth: {
      authenticateToken: async token => verifyToken(token),
    },
    middleware: [
      {
        path: '/api/*',
        handler: async (c, next) => {
          const token = c.req.header('Authorization')
          if (!token) {
            return c.json({ error: 'Unauthorized' }, 401)
          }

          const user = await getAuthenticatedUser<{ id: string }>({
            mastra: c.get('mastra'),
            token,
            request: c.req.raw,
          })
          const requestContext = c.get('requestContext')

          if (!user) {
            return c.json({ error: 'Unauthorized' }, 401)
          }

          requestContext.set(MASTRA_RESOURCE_ID_KEY, user.id)
          return next()
        },
      },
    ],
  },
})
```

`server.middleware`在 Mastra 的每個路由身份驗證檢查之前運行。當中間件需要經過身份驗證的使用者時，請調用`getAuthenticatedUser()` to resolve it from the configured auth provider without changing the default route auth flow.

#### 使用`MASTRA_THREAD_ID_KEY` {/* #using-mastra_thread_id_key */}

您也可以設定`MASTRA_THREAD_ID_KEY` to override the client-provided thread ID:

```typescript
import { MASTRA_RESOURCE_ID_KEY, MASTRA_THREAD_ID_KEY } from '@mastra/core/request-context'

// Force operations to use a specific thread
requestContext.set(MASTRA_THREAD_ID_KEY, validatedThreadId)
```

當您想要將操作限製到已透過其他方式驗證的特定執行緒時，這非常有用。

### CORS 支持 {/* #cors-support */}

```typescript oxfmt:false
{
  handler: async (c, next) => {
    c.header('Access-Control-Allow-Origin', '*');
    c.header(
      'Access-Control-Allow-Methods',
      'GET, POST, PUT, DELETE, OPTIONS',
    );
    c.header(
      'Access-Control-Allow-Headers',
      'Content-Type, Authorization',
    );

    if (c.req.method === 'OPTIONS') {
      return new Response(null, { status: 204 });
    }

    await next();
  },
}
```

```typescript oxfmt:false
{
  handler: async (c, next) => {
    const start = Date.now();
    await next();
    const duration = Date.now() - start;
    console.log(`${c.req.method} ${c.req.url} - ${duration}ms`);
  },
}
```
