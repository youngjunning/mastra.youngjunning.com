# 中介軟體

Mastra 伺服器可在呼叫 API 路由處理函式前後執行自訂中介軟體，例如驗證身分、寫入記錄、注入個別請求的情境資料，或加上 CORS 標頭。

中介軟體接收 [Hono](https://hono.dev) 的 `Context`（`c`）和 `next` 函式。傳回 `Response` 會提前結束請求處理。呼叫 `next()` 可繼續執行下一個中介軟體或路由處理函式。

:::note

中介軟體處理函式採用 Hono 的簽章，可在 `mastra dev`、`mastra build`、[Hono 介接器](/reference/server/hono-adapter) 及以其為基礎的 `@mastra/next`、`@mastra/tanstack-start` 等環境執行。其他框架（Elysia、Express、Fastify、Koa、NestJS）的介接器無法執行 Hono 處理函式，若已設定中介軟體，啟動時會記錄警告。請使用各框架自己的 API 註冊中介軟體。

以 `requiresAuth: false` 宣告為公開的路由一律略過使用者中介軟體，因此 Studio 登入路由等框架必須維持可用的端點不會遭到封鎖。

:::

```typescript
import { Mastra } from '@mastra/core'

export const mastra = new Mastra({
  server: {
    middleware: [
      {
        handler: async (c, next) => {
          // Example: Add authentication check
          const authHeader = c.req.header('Authorization')
          if (!authHeader) {
            return new Response('Unauthorized', { status: 401 })
          }

          await next()
        },
        path: '/api/*',
      },
      // Add a global request logger
      async (c, next) => {
        console.log(`${c.req.method} ${c.req.url}`)
        await next()
      },
    ],
  },
})
```

若要替個別路由加上中介軟體，請在呼叫 `registerApiRoute` 時傳入 `middleware` 選項：

```typescript
registerApiRoute('/my-custom-route', {
  method: 'GET',
  middleware: [
    async (c, next) => {
      console.log(`${c.req.method} ${c.req.url}`)
      await next()
    },
  ],
  handler: async c => {
    const mastra = c.get('mastra')
    return c.json({ message: 'Hello, world!' })
  },
})
```

## 常見範例 {/* #common-examples */}

### 封鎖內建路由群組 {/* #block-built-in-route-groups */}

Mastra 未提供移除內建路由或設定允許清單的選項。在使用 Hono 的服務中，可直接傳回回應並略過 `next()`，停用指定的路由群組：

```typescript title="src/mastra/index.ts"
import { Mastra } from '@mastra/core'

const notFound = async () => new Response('Not Found', { status: 404 })

export const mastra = new Mastra({
  server: {
    middleware: [
      { path: '/api/memory/*', handler: notFound },
      { path: '/api/logs/*', handler: notFound },
      { path: '/api/observability/*', handler: notFound },
    ],
  },
})
```

每個萬用字元模式都會封鎖路由群組本身和底下的巢狀路由。例如，`/api/logs/*` 會封鎖 `/api/logs` 和 `/api/logs/transports`。其他群組仍可使用。

產生的伺服器會將 `server.apiPrefix` 傳入 Hono 介接器的 [`prefix` 建構選項](/reference/server/hono-adapter#constructor-parameters)，替內建路由加上前綴。中介軟體的路徑會原樣註冊，需明確寫出設定的前綴。例如，設定 `apiPrefix: '/api/v2'` 後，請使用 `/api/v2/memory/*`。自訂 API 路由必須位於設定的 API 前綴之外，因此不受這些模式封鎖。

Mastra 會對以 `requiresAuth: false` 宣告為公開的路由略過使用者中介軟體，因此此做法無法封鎖這些路由。如果伺服器介接器並非基於 Hono，請透過伺服器框架註冊等效的中介軟體。

執行 `mastra dev` 時，可在 [OpenAPI 規格](http://localhost:4111/api/openapi.json)查看所有內建路由，包括 MCP 路由。探索 API 和設定正式環境的方式請參閱[伺服器概覽](/docs/server/overview#rest-api)。

如果透過中介軟體驗證身分且未使用 `server.auth`，建議預設拒絕存取，等請求通過驗證再放行，以免逐一列出受保護的路徑。請涵蓋完整的 API 前綴，將 REST 路由和 MCP 傳輸都納入保護。

### 使用 `RequestContext` {/* #using-requestcontext */}

可在伺服器執行時，由中介軟體從請求擷取資料並填入 `RequestContext`。此範例依 Cloudflare 的 `CF-IPCountry` 標頭設定 `temperature-unit`，讓回應符合使用者所在的地區。

```typescript title="src/mastra/index.ts"
import { Mastra } from '@mastra/core'
import { RequestContext } from '@mastra/core/request-context'
import { testWeatherAgent } from './agents/test-weather-agent'

export const mastra = new Mastra({
  agents: { testWeatherAgent },
  server: {
    middleware: [
      async (context, next) => {
        const country = context.req.header('CF-IPCountry')
        const requestContext = context.get('requestContext')

        requestContext.set('temperature-unit', country === 'US' ? 'fahrenheit' : 'celsius')

        await next()
      },
    ],
  },
})
```

### 授權（使用者隔離） {/* #authorization-user-isolation */}

身分驗證確認使用者是誰，授權則決定使用者可以存取哪些內容。

若伺服器未強制限制資源範圍，也沒有其他授權政策，通過身分驗證的呼叫端可以跨資源列出對話串、存取訊息與工作記憶。未限定範圍的清單就可能揭露對話串 ID，呼叫端無需猜測。若要依使用者或租用戶隔離記憶，請設定 `mapUserToResourceId`，或在中介軟體中設定可信任的資源 ID。

共用應用程式可能刻意允許跨資源存取。資源 ID 可識別使用者、租用戶、專案或其他群組。請依可存取資源的對象選擇授權政策。

若要依已驗證的使用者限制記憶與對話串，最簡單的方法是在身分驗證設定中加入 `mapUserToResourceId` 回呼：

```typescript
import { Mastra } from '@mastra/core'

export const mastra = new Mastra({
  server: {
    auth: {
      authenticateToken: async token => {
        return verifyToken(token) // { id: 'user-123', orgId: 'org-456', ... }
      },
      mapUserToResourceId: user => user.id,
    },
  },
})
```

身分驗證成功後，系統會將已驗證的使用者物件傳給 `mapUserToResourceId`，並將傳回值寫入請求情境的 `MASTRA_RESOURCE_ID_KEY`。這適用於所有伺服器介接器（Hono、Express、Next.js 等）。

設定此回呼後，它必須傳回非空字串。若回呼擲出例外，或傳回 `null`、`undefined`、空字串、僅含空白的字串或其他型別的值，身分驗證中介軟體會在路由執行前拒絕請求並傳回 500。所有執行身分驗證的請求均適用，包括與記憶無關的路由。用戶端提供的資源 ID 無法覆寫失敗的對應。

使用 `CompositeAuth` 時，這項要求適用於實際驗證請求的 Provider。未設定對應函式的 Provider 會維持原有行為，即使組合中的其他 Provider 已設定對應函式。已設定的 Studio 身分驗證對應函式也採用相同的檢查規則。

未設定對應函式時，僅驗證身分無法隔離使用者。請在中介軟體中設定可信任的資源 ID，或以其他方式強制執行授權。

資源 ID 可採用 `user.id` 以外的值。以下是常見做法：

```typescript
// Per-user within an organization
mapUserToResourceId: user => `${user.orgId}:${user.id}`

// From a JWT claim
mapUserToResourceId: user => user.tenantId

// Composite key
mapUserToResourceId: user => `${user.workspaceId}:${user.projectId}:${user.id}`
```

設定資源 ID 後，伺服器會自動執行下列操作：

- **篩選對話串清單**，只傳回設定資源範圍內的對話串。
- **檢查對話串存取權**，存取其他資源的對話串時傳回 403。
- **限制對話串建立**，新建對話串必須使用設定的資源 ID。
- **檢查訊息操作**（包括刪除），確認訊息所屬的對話串位於設定的資源範圍內。

即使用戶端傳入 `?resourceId=other-resource-id`，仍以伺服器設定的值為準。嘗試存取其他資源的對話串或訊息會收到 403。對應至相同資源 ID 的使用者共用該資源範圍。

#### 進階：在中介軟體中設定資源 ID {/* #advanced-setting-resource-id-in-middleware */}

若情境較複雜，例如需要從資料庫查詢資源 ID，可直接在中介軟體設定 `MASTRA_RESOURCE_ID_KEY`：

```typescript
import { Mastra } from '@mastra/core'
import { MASTRA_RESOURCE_ID_KEY } from '@mastra/core/request-context'
import { getAuthenticatedUser } from '@mastra/server/auth'

export const mastra = new Mastra({
  server: {
    auth: {
      authenticateToken: async token => verifyToken(token),
    },
    middleware: [
      {
        path: '/api/*',
        handler: async (c, next) => {
          const token = c.req.header('Authorization')
          if (!token) {
            return c.json({ error: 'Unauthorized' }, 401)
          }

          const user = await getAuthenticatedUser<{ id: string }>({
            mastra: c.get('mastra'),
            token,
            request: c.req.raw,
          })
          const requestContext = c.get('requestContext')

          if (!user) {
            return c.json({ error: 'Unauthorized' }, 401)
          }

          requestContext.set(MASTRA_RESOURCE_ID_KEY, user.id)
          return next()
        },
      },
    ],
  },
})
```

`server.middleware` 會在 Mastra 執行各路由的身分驗證檢查前執行。中介軟體若需取得已驗證的使用者，可呼叫 `getAuthenticatedUser()` 向設定的身分驗證 Provider 取得使用者，同時保留預設的路由驗證流程。

#### 使用 `MASTRA_THREAD_ID_KEY` {/* #using-mastra_thread_id_key */}

您也可以設定 `MASTRA_THREAD_ID_KEY`，覆寫用戶端提供的對話串 ID：

```typescript
import { MASTRA_RESOURCE_ID_KEY, MASTRA_THREAD_ID_KEY } from '@mastra/core/request-context'

// Force operations to use a specific thread
requestContext.set(MASTRA_THREAD_ID_KEY, validatedThreadId)
```

這樣可把操作限制在已透過其他方式驗證的特定對話串。

### CORS 支援 {/* #cors-support */}

```typescript oxfmt:false
{
  handler: async (c, next) => {
    c.header('Access-Control-Allow-Origin', '*');
    c.header(
      'Access-Control-Allow-Methods',
      'GET, POST, PUT, DELETE, OPTIONS',
    );
    c.header(
      'Access-Control-Allow-Headers',
      'Content-Type, Authorization',
    );

    if (c.req.method === 'OPTIONS') {
      return new Response(null, { status: 204 });
    }

    await next();
  },
}
```

{
  handler: async (c, next) => {

}
