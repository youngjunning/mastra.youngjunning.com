# 伺服器

Mastra 會以 HTTP 伺服器執行，將 Agent、Workflow 等功能公開為 API 端點。伺服器負責請求路由、執行中介軟體、身分驗證和串流回應。

:::note

本頁說明傳給 `Mastra` 建構函式的 [`server`](/reference/configuration#server-options) 設定選項。若要用自己的 HTTP 伺服器（例如 Hono 或 Express）執行 Mastra，請參閱[伺服器轉接器](/docs/server/server-adapters)。

:::

## 伺服器功能 {/* #server-features */}

- **[中介軟體](/docs/server/middleware)**：攔截請求，以進行身分驗證、記錄日誌、處理 CORS，或注入該請求的脈絡。
- **[自訂 API 路由](/docs/server/custom-api-routes)**：新增可存取 Mastra 執行個體的 HTTP 端點。
- **[請求脈絡](/docs/server/request-context)**：依執行階段條件，將該請求的值傳給 Agent、Tool 和 Workflow。
- **[伺服器轉接器](/docs/server/server-adapters)**：使用 Express、Hono 或自己的 HTTP 伺服器執行 Mastra，以取代自動產生的伺服器。
- **[自訂轉接器](/docs/server/custom-adapters)**：為官方尚未支援的框架撰寫轉接器。
- **[Mastra 用戶端 SDK](/docs/server/mastra-client)**：提供型別安全的用戶端，可從瀏覽器或伺服器呼叫 Agent、Workflow 和 Tool。
- **[內建 MCP 伺服器](/docs/server/mcp)**：讓 Claude Code、Cursor 等 MCP 用戶端透過 `/api/mcp` 呼叫 Agent、Workflow 和 Tool，並沿用 HTTP API 的身分驗證和權限規則。
- **[A2A](/docs/connections/a2a)**：透過 A2A Agent 卡片和任務串流公開 Agent，並支援推播通知。
- **[身分驗證](/docs/auth/overview)**：使用 JWT、Clerk、Supabase、Firebase、Auth0 或 WorkOS 保護端點。

## 配置 {/* #configuration */}

將 `server` 物件傳入 `Mastra` 建構函式，即可設定伺服器：

```typescript title="src/mastra/index.ts"
import { Mastra } from '@mastra/core'

export const mastra = new Mastra({
  server: {
    port: 3000, // Defaults to PORT env var or 4111
    host: '0.0.0.0', // Defaults to MASTRA_HOST env var or 'localhost'
  },
})
```

完整的選項清單請見[設定參考](/reference/configuration#server-options)。

## 部署您的伺服器 {/* #deploy-your-server */}

Mastra 伺服器可部署到任何相容於 Node.js 的環境。正式環境可以使用 [Mastra 平台](/docs/mastra-platform/overview) 或自有基礎設施，做法請見[部署文件](/docs/deployment/overview)。

## 伺服器架構 {/* #server-architecture */}

Mastra 的 HTTP 伺服器以 [Hono](https://hono.dev) 為底層框架。用 `mastra build` 建置應用程式時，會在 `.mastra` 目錄產生以 Hono 為基礎的 HTTP 伺服器。

伺服器提供：

- 所有已註冊 Agent 和 Workflow 的 API 端點
- 自訂 API 路由和中介軟體
- 支援多個 Provider 的身分驗證
- 供執行階段設定使用的請求脈絡
- 遮蔽串流資料中的敏感內容，保護回應

## REST API {/* #rest-api */}

[http://localhost:4111/api/openapi.json](http://localhost:4111/api/openapi.json) 的 OpenAPI 規格列出所有可用端點，以及各端點的請求與回應結構描述。

若要互動測試 API，請開啟 [http://localhost:4111/swagger-ui](http://localhost:4111/swagger-ui) 的 Swagger UI，在瀏覽器中瀏覽並測試端點。

:::note

正式環境預設停用 OpenAPI 和 Swagger 端點。若要啟用，請將 [`server.build.openAPIDocs`](/reference/configuration#serverbuild) 和 [`server.build.swaggerUI`](/reference/configuration#serverbuild) 分別設為 `true`。

:::

## OpenAI Responses API {/* #openai-responses-api */}

Mastra 提供與 OpenAI 相容的 Responses 和 Conversations 路由，讓你透過 Responses API 使用 Mastra Agent。這些路由是建立在 Agent、Memory 和儲存之上的轉接層，請求由選定的 Mastra Agent 處理，而非直接轉送給 Provider。

這些 API 目前處於實驗階段。

用 `agent_id` 指定負責處理請求的 Mastra Agent。初始請求直接指定 Agent；後續可用 `previous_response_id` 接續已儲存的對話。若要只為本次請求覆寫模型，請傳入 `model`；省略時沿用 Agent 設定的模型。

Responses 路由支援串流和函式呼叫（Tool），也能以 `previous_response_id` 接續已儲存的回應、以 `conversation_id` 指定對話串、透過 `providerOptions` 傳遞 Provider 專用選項，以及透過 `text.format` 輸出 JSON。

完整的請求與回應規格請見 [Responses API 參考](/reference/client-js/responses)和 [Conversations API 參考](/reference/client-js/conversations)。所有 HTTP 路由列於[伺服器路由](/reference/server/routes#responses-api)。

## 遮蔽串流資料 {/* #stream-data-redaction */}

以串流傳送 Agent 回應時，HTTP 層會在送出每個資料區塊前，遮蔽系統提示、Tool 定義、API 金鑰等資料。此功能預設啟用。

只有使用[伺服器轉接器](/docs/server/server-adapters#stream-data-redaction)時才能設定這項行為。轉接器也預設啟用串流資料遮蔽。

## TypeScript 配置 {/* #typescript-configuration */}

Mastra 要求 `module` 和 `moduleResolution` 的設定與新版 Node.js 相容，不支援 `CommonJS` 或 `node` 等舊選項。

下方的 `types` 選項需要 `@types/node`。以 [`create-mastra`](/reference/cli/create-mastra) 建立的專案已包含此套件；如果專案尚未安裝，請自行加入：

```bash npm2yarn
npm install -D @types/node
```

```json {4-5} title="tsconfig.json"
{
  "compilerOptions": {
    "target": "ES2022",
    "module": "ES2022",
    "moduleResolution": "bundler",
    "esModuleInterop": true,
    "forceConsistentCasingInFileNames": true,
    "strict": true,
    "skipLibCheck": true,
    "types": ["node"],
    "noEmit": true,
    "outDir": "dist"
  },
  "include": ["src/**/*"]
}
```
