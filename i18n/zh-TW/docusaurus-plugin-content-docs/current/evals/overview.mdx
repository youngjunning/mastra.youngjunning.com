# Evals

傳統軟體測試有明確的通過與失敗條件，但 AI 即使收到相同輸入，輸出也可能不同。**評分器**提供可量化的指標，用來衡量 Agent 的品質。

評分器是自動化測試，透過模型評分、規則和統計方法評估 Agent 的輸出。評分器傳回**分數**，通常是介於 0 和 1 之間的數值，反映輸出符合評估標準的程度。你可以據此客觀追蹤表現、比較不同做法，並找出 AI 系統中可改善之處。評分器可使用自訂提示詞及評分函式。

你可以在雲端執行評分器，取得即時結果，也能將它納入 CI/CD 管線，長期測試及監控 Agent。

評分器衡量單次輸出。若要持續改善 Agent，可以搭配[資料集](/docs/evals/datasets)與[實驗](/docs/evals/experiments)。資料集儲存有版本的測試案例，實驗則讓 Agent 或 Workflow 在資料集上執行，可選擇為每筆結果評分，並保留結果供比較。[建立評估循環](/docs/guides/build-an-eval-loop)說明如何搭配使用。

:::tip[📹 觀看影片]

觀看 [Mastra Evals 概覽](https://www.youtube.com/watch?v=12WN6u2DrBk)，認識評估的基本概念，以及如何看待 Agent 的品質。

:::

## 評分器類型 {/* #types-of-scorers */}

Mastra 提供不同用途的評分器，常見類型如下：

1. **文字評分器**：評估 Agent 回覆的準確性、可靠性及對上下文的理解
1. **分類評分器**：衡量資料依預定類別分類的準確性
1. **提示詞工程評分器**：檢視不同指示和輸入格式的影響

## 安裝 {/* #installation */}

若要使用 Mastra 評分器，請安裝 `@mastra/evals` 套件。

```bash npm2yarn
npm install @mastra/evals@latest
```

## 即時評估 {/* #live-evaluations */}

**即時評估**會在 Agent 和 Workflow 執行時，自動為 AI 輸出評分。評分器與 AI 系統同時非同步執行，無須手動或批次評估，即可持續監控品質。

### 為 Agent 加入評分器 {/* #adding-scorers-to-agents */}

你可以將內建評分器加入 Agent，自動評估輸出。可用的選項請見[內建評分器完整清單](/docs/evals/built-in-scorers)。

```typescript title="src/mastra/agents/evaluated-agent.ts"
import { Agent } from '@mastra/core/agent'
import { createAnswerRelevancyScorer, createToxicityScorer } from '@mastra/evals/scorers/prebuilt'

export const evaluatedAgent = new Agent({
  id: 'evaluated-agent',
  scorers: {
    relevancy: {
      scorer: createAnswerRelevancyScorer({ model: '__GATEWAY_OPENAI_MODEL_LUNA__' }),
      sampling: { type: 'ratio', rate: 0.5 },
    },
    safety: {
      scorer: createToxicityScorer({ model: '__GATEWAY_OPENAI_MODEL_LUNA__' }),
      sampling: { type: 'ratio', rate: 1 },
    },
  },
})
```

### 為 Workflow 步驟加入評分器 {/* #adding-scorers-to-workflow-steps */}

你也可以為個別 Workflow 步驟加入評分器，評估流程中指定步驟的輸出。評分器會收到該步驟的輸入與輸出，因此除了最終答案，也能衡量各步驟的品質：

```typescript title="src/mastra/workflows/content-generation.ts"
import { createWorkflow, createStep } from '@mastra/core/workflows'
import { z } from 'zod'
import { customStepScorer } from '../scorers/custom-step-scorer'

const contentStep = createStep({
  id: 'content-step',
  inputSchema: z.object({ topic: z.string() }),
  outputSchema: z.object({ content: z.string() }),
  scorers: {
    customStepScorer: {
      scorer: customStepScorer(),
      sampling: {
        type: 'ratio',
        rate: 1, // Score every step execution
      },
    },
  },
  execute: async ({ inputData }) => {
    return { content: await generateContent(inputData.topic) }
  },
})

export const contentWorkflow = createWorkflow({
  id: 'content-workflow',
  inputSchema: z.object({ topic: z.string() }),
  outputSchema: z.object({ content: z.string() }),
})
  .then(contentStep)
  .commit()
```

步驟層級的 `scorers` API 請見 [Step 類別參考](/reference/workflows/step#scoring-step-output)。

### 即時評估的運作方式 {/* #how-live-evaluations-work */}

**非同步執行**：即時評估在背景執行，無須等待評估就能回覆 Agent 請求或繼續執行 Workflow。AI 系統在受到監控的同時仍可正常回應。

**取樣控制**：`sampling.rate` 參數（0 到 1）決定要評分的輸出比例：

- `1.0`：為所有回覆評分（100%）
- `0.5`：為一半的回覆評分（50%）
- `0.1`：為 10% 的回覆評分
- `0.0`：停用評分

每筆 Trace 的取樣結果由 Trace ID 決定，並非隨機抽取，因此：

- 取樣率相同的評分器會對相同的 Trace 評分，因此可在同一批流量上比較分數。
- 重新執行同一筆 Trace 時，取樣結果不變，因此可重現取樣的涵蓋範圍。

如果未設定可觀測性，執行就沒有 Trace，改由執行 ID 決定是否取樣。如果 [Trace 取樣](../observability/tracing/overview)未選中該 Trace，評分器會跳過整次執行，因此從未儲存的 Trace 不會有分數。

**評分資格篩選**：選用的 `filter` 參數以宣告式述詞檢查執行上下文，限定哪些執行可以評分。篩選先於取樣，因此 `sampling.rate` 只套用到符合條件的執行：

```typescript title="src/mastra/agents/evaluated-agent.ts"
import { Agent } from '@mastra/core/agent'

export const myAgent = new Agent({
  // ...
  scorers: {
    relevancy: {
      scorer: createAnswerRelevancyScorer({ model: '__GATEWAY_OPENAI_MODEL_LUNA__' }),
      filter: {
        op: 'eq',
        left: { path: 'requestContext.plan' },
        right: { literal: 'enterprise' },
      },
      sampling: { type: 'ratio', rate: 0.1 },
    },
  },
})
```

這個設定只會為企業方案流量中的 10% 評分。若要依不同取樣率為不同流量分組評分，可以用互補的篩選條件將同一評分器繫結兩次。

述詞可參照 `requestContext.*`、`entity.*`、`entityType`、`source`、`threadId`、`resourceId` 和 `projectId`。支援比較（`eq`、`ne`、`lt`、`lte`、`gt`、`gte`）、成員資格（`in`、`notIn`）、是否存在（`exists`、`notExists`）、真值判斷（`truthy`、`falsy`）及布林組合（`and`、`or`、`not`）。若篩選條件參照未知的根欄位，建構 Agent 時就會報錯，避免在執行期間無聲略過評分。篩選條件是純 JSON，不受持久化 Agent 狀態序列化影響。

資格篩選決定 _評分器是否執行_。若要篩選 _執行後評分器可以讀取的訊息_，請使用 [`filterRun()`](/reference/evals/filter-run)。資格篩選無法讀取執行的輸入或輸出。若資格取決於執行時發生的事，例如有沒有呼叫特定工具，請從評分器步驟傳回 [`notScorable()`](/reference/evals/not-scorable)，這會略過其餘步驟，且不儲存分數。

**自動儲存**：所有評分結果會自動儲存到已設定資料庫的 `mastra_scorers` 資料表，方便分析長期表現趨勢。

## 分數持久化 {/* #score-persistence */}

當 Mastra 執行個體已設定 `storage` 且評分器已向該執行個體註冊時，分數就會寫入持久化儲存空間。註冊後，Mastra 就能在寫入分數前，透過 [`getScorerById()`](/reference/core/getScorerById) 取得評分器的中繼資料（名稱、描述、類型）。

附加到 Agent 或 Workflow 步驟的評分器會自動註冊。若直接將評分器傳給 [`runEvals()`](/reference/evals/run-evals)，包含 [Quick Checks](/docs/evals/quick-checks)，請透過 [`Mastra` 類別](/reference/core/mastra-class)的 `scorers` 選項註冊：

```typescript title="src/mastra/index.ts"
import { Mastra } from '@mastra/core'
import { LibSQLStore } from '@mastra/libsql'
import { checks } from '@mastra/evals/checks'
import { createAnswerRelevancyScorer } from '@mastra/evals/scorers/prebuilt'
import { myAgent } from './agents/my-agent'

export const mastra = new Mastra({
  agents: { myAgent },
  storage: new LibSQLStore({ url: 'file:./mastra.db' }),
  scorers: {
    calledTool: checks.calledTool('get_weather'),
    includes: checks.includes('Brooklyn'),
    relevancy: createAnswerRelevancyScorer({ model: '__GATEWAY_OPENAI_MODEL_LUNA__' }),
  },
})
```

查詢只比對評分器 ID，因此註冊的執行個體可採用與實際評估不同的設定。每個 `checks.calledTool()` 執行個體都使用 ID `check-called-tool`，所以註冊一次即可涵蓋所有受評估的工具名稱。

與分數一起儲存的 `description` 仍由註冊時使用的引數決定，來源是註冊的執行個體。使用 `checks.calledTool('')` 可正常儲存分數，但說明會是 `Checks that "" was called`，所以請傳入有代表性的值。

略過註冊不影響評分結果，但每次儲存都會失敗並發出 `Scorer with id <id> not found` 警告，因此分數不會寫入儲存空間。

## Trace 評估 {/* #trace-evaluations */}

除了即時評估，你也可以用評分器評估 Agent 互動和 Workflow 的歷史 Trace。

這特別適合分析過往表現、偵錯或批次執行評估。

:::note[必須先設定可觀測性]

若要為 Trace 評分，必須先在 Mastra 執行個體上設定可觀測性，以收集 Trace 資料。設定步驟請見[追蹤文件](../observability/tracing/overview)。

:::

## Studio {/* #studio */}

要為 Trace 評分，請先在 Mastra 執行個體上註冊評分器：

```typescript
const mastra = new Mastra({
  scorers: {
    answerRelevancy: myAnswerRelevancyScorer,
    responseQuality: myResponseQualityScorer,
  },
})
```

註冊後，你可以在 Studio 的 **Observability** 區域以互動方式為 Trace 評分，也能在 Studio 管理評分器、查看分數並執行實驗。

- **評分器清單**：瀏覽所有已註冊的評分器、說明，以及各評分器所附加的 Agent 和 Workflow 數目。
- **評分結果**：選取評分器後，可分頁查看它產生的所有分數。點選任一列以開啟詳細資料面板，查看分數、評分理由、輸入、輸出及評判模型使用的提示詞。你可以從面板將任何結果儲存為資料集項目，供日後實驗使用。
- **Agent 的 Evaluate 分頁**：開啟任一 Agent 的 Evaluate 分頁，即可管理評分器和資料集，也可以執行實驗。實驗結果會逐項顯示分數、通過或失敗狀態及版本標籤。
- **Trace 評分**：在 Observability 區域，對任一歷史 Trace 或 Span 執行評分器，評估過往互動。你可以依 Agent 或 Workflow 篩選分數。
