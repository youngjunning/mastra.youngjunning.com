# 數據集

**添加於：** `@mastra/core@1.4.0`

資料集是測試案例的集合，您可以對其執行實驗以衡量Agent和Workflow的執行情況。每個突變都會創建一個新版本，因此您可以準確地重現過去的實驗。將資料集與[scorers](/docs/evals/overview) to track quality across prompts, models, or code changes.

<Inject>
  **對於人工智慧Agent：**&#x8DD1;步`npx mastra api dataset create '{"name":"translation-pairs"}'` to create a dataset directly instead of opening Studio or writing a temporary script. The command requires a running Mastra server with a storage adapter that supports datasets; start the local server with `npx mastra dev`, or pass the reachable server's base URL with `--url`。跑步`npx mastra api dataset create --schema`在新增不同的資料集欄位之前。安裝 Mastra 的技能`npx skills add mastra-ai/skills --skill mastra`取得完整的 API CLI 發現、定位、架構、驗證和錯誤處理指南。
</Inject>

## 用法 {/* #usage */}

### 配置儲存 {/* #configure-storage */}

在您的 Mastra 實例中配置儲存。資料集需要一個儲存適配器來提供`datasets` domain:

```typescript title="src/mastra/index.ts"
import { Mastra } from '@mastra/core'
import { LibSQLStore } from '@mastra/libsql'

export const mastra = new Mastra({
  storage: new LibSQLStore({
    id: 'my-store',
    url: 'file:./mastra.db',
  }),
})
```

### 存取資料集 API {/* #accessing-the-datasets-api */}

所有資料集操作都可以透過`mastra.datasets`:

```typescript
const datasets = mastra.datasets

// Create a dataset
const dataset = await datasets.create({ name: 'my-dataset' })

// Retrieve an existing dataset
const existing = await datasets.get({ id: 'dataset-id' })

// List all datasets
const { datasets: all } = await datasets.list()
```

參觀[`DatasetsManager` reference](/reference/datasets/datasets-manager) for the full list of methods.

## 工作室 {/* #studio */}

您也可以管理資料集[Studio](/docs/studio/overview). After opening Studio, select **Datasets** from the sidebar to see all your available datasets or create a new one.

若要開始使用，請選擇**Create Dataset** and set a name, description, and optional schemas. After confirming, you'll see the dataset details page with two tabs: **Items** and [**Experiments**](/docs/evals/experiments#run-experiments-in-studio).

在**Items** view you can add, update, and delete items, and view version history. Select **Add Item** to insert a new item with JSON editors for input and ground truth. From this view you can also import items in bulk from a CSV or JSON file. When importing, map each column to the corresponding dataset field.

選擇**Versions** to see the full history of changes to the dataset. After selecting **Compare Versions**, choose any two versions and select **Compare** to see a side-by-side diff of all items that were added, changed, or removed between those versions.

## 建立資料集 {/* #creating-a-dataset */}

稱呼[`create()`](/reference/datasets/create) with a name and optional description:

```typescript title="src/mastra/datasets/create-dataset.ts"
import { mastra } from '../index'

const dataset = await mastra.datasets.create({
  name: 'translation-pairs',
  description: 'English to Spanish translation test cases',
})

console.log(dataset.id) // auto-generated UUID
```

### 定義模式 {/* #defining-schemas */}

您可以強制執行形狀`input` and `groundTruth` by passing a [Standard JSON Schema](https://standardschema.dev/json-schema) ([Zod](https://zod.dev/), [Valibot](https://valibot.dev/), [ArkType](https://arktype.io/), etc.) when creating the dataset:

```typescript title="src/mastra/datasets/create-with-schema.ts"
import { z } from 'zod'
import { mastra } from '../index'

const dataset = await mastra.datasets.create({
  name: 'translation-pairs',
  inputSchema: z.object({
    text: z.string(),
    sourceLang: z.string(),
    targetLang: z.string(),
  }),
  groundTruthSchema: z.object({
    translation: z.string(),
  }),
})
```

與架構不匹配的項目將在插入時被拒絕。

## 新增項目 {/* #adding-items */}

使用[`addItem()`](/reference/datasets/addItem) for a single item or [`addItems()`](/reference/datasets/addItems) to insert in bulk:

```typescript title="src/mastra/datasets/add-items.ts"
// Single item
await dataset.addItem({
  input: { text: 'Hello', sourceLang: 'en', targetLang: 'es' },
  groundTruth: { translation: 'Hola' },
})

// Bulk insert
await dataset.addItems({
  items: [
    {
      input: { text: 'Goodbye', sourceLang: 'en', targetLang: 'es' },
      groundTruth: { translation: 'Adiós' },
    },
    {
      input: { text: 'Thank you', sourceLang: 'en', targetLang: 'es' },
      groundTruth: { translation: 'Gracias' },
    },
  ],
})
```

### 儲存的欄位值 {/* #stored-field-values */}

記憶體中、LibSQL、PostgreSQL、MySQL、MongoDB 和 Spanner 資料集儲存保留 JSON`null` in `input`, `groundTruth`, and `expectedTrajectory`, along with empty strings, arrays, and objects. Omitted optional JSON fields remain absent when serialized. Dataset schemas still determine which values an item accepts.

快照驗證不會覆蓋資料庫限制。 MongoDB 拒絕包含 NUL 的物件屬性名稱（`\u0000`), even in valid JSON. A batch insert containing such keys fails without storing any items or advancing the dataset version.

對於配置更新，`null` clears schemas, tags, target type, target IDs, or scorer IDs. These adapters return cleared settings as `undefined`, while preserving empty arrays and objects. An item update with `scorerIds: null` removes its scorer override, whereas `scorerIds: []` disables scoring for that item. Omitted update fields leave existing values unchanged.

用同樣的方法重試`externalId` retain the original item's representation. For backward compatibility, insert operations treat omitted and `null` payload fields as equivalent when comparing a retry with an existing item. For example, inserting an item without `groundTruth` and retrying with `groundTruth: null` returns the original item with no ground truth. Use an item update to store an explicit `null` instead.

取消設定的配置現在讀取為`undefined` where some adapters previously returned `null`, so serialized responses omit those properties. Use nullish checks such as `value ?? fallback` rather than relying on an explicit `null` property. LibSQL also returns an omitted dataset description as `undefined`, matching its declared type.

較舊的 LibSQL、PostgreSQL、MySQL 和 Spanner 寫入儲存的可選 JSON`null` values as SQL `NULL`. Those values remain indistinguishable from omitted fields. Older MongoDB writes stored omitted optional payload fields as BSON `null`. The storage fixes preserve new writes but don't reconstruct previously lost distinctions.

## 驗證快照工件 {/* #validate-snapshot-artifacts */}

使用`createDatasetSnapshot()` and `parseDatasetSnapshot()` from `@mastra/core/datasets` to create and validate a versioned JSON artifact. These are pure format utilities: they don't export from storage, import a dataset, allocate portable identities, or change Studio's JSON importer.

```typescript title="src/mastra/datasets/snapshot.ts"
import { createDatasetSnapshot, parseDatasetSnapshot } from '@mastra/core/datasets'

const snapshot = createDatasetSnapshot({
  formatVersion: 1,
  datasetIdentity: '00000000-0000-4000-8000-000000000001',
  configuration: { name: 'translation-pairs' },
  items: [
    {
      itemIdentity: '00000000-0000-4000-8000-000000000002',
      createdAt: '2026-09-01T09:00:00.123Z',
      updatedAt: '2026-09-10T10:00:00.456Z',
      payload: { input: 'Hello', groundTruth: 'Hola', scorerIds: [] },
    },
  ],
  provenance: {
    exportedAt: '2026-09-11T12:00:00Z',
    sourceDatasetId: 'dev-translations',
    itemVersion: 1,
    configurationBasis: 'export-time',
  },
})

const parsed = parseDatasetSnapshot(JSON.stringify(snapshot))
console.log(parsed.digest === snapshot.digest) // true
```

該工件包括配置、完整的創作項目有效負載、可移植 UUID 和出處。提供穩定的小寫 UUID，而不是在每次序列化時產生新的身分。撰寫`externalId` values are separate from portable identity and remain unchanged. Absent, `null`, and empty overrides remain distinct. Omit optional properties rather than assigning `undefined`. Dataset descriptions also preserve absent, `null`, and string values.

`createdAt` and `updatedAt` as UTC ISO 8601 strings with millisecond precision, matching `Date.toISOString()` for four-digit years. Both timestamps are included in the integrity digest. They represent the item's actual dates, not transfer provenance: an importer must preserve them as the destination item's `createdAt` and `updatedAt`, rather than replacing them with import time. An importer records transfer time in a separate receipt, while later edits in the destination update `updatedAt` normally. Implementing storage import remains outside the scope of these format helpers.

`\u0000`) even though they're valid in an artifact. Validate destination storage restrictions before writing artifact contents.

兩個助手都會因為內容或大小選項無效而引發 Zod 驗證錯誤。`datasetSnapshotContentSchema.safeParse()` validates unsigned content and identity uniqueness, while `datasetSnapshotSchema.safeParse()` additionally checks the digest. These schemas don't enforce a byte limit. Use `parseDatasetSnapshot()` for untrusted text to enforce a size budget before parsing and reject duplicate JSON property names.

幫助程式預設為 4 MiB UTF-8 預算（`DATASET_SNAPSHOT_DEFAULT_MAX_BYTES`). Pass `{ maxBytes }` as the second argument to either helper to raise or lower it. The value must be a positive safe integer. This is an operational limit, not part of the v1 format or digest. For example, parse the snapshot above with an 8 MiB budget:

```typescript
const parsedWithLargerBudget = parseDatasetSnapshot(JSON.stringify(snapshot), {
  maxBytes: 8 * 1024 * 1024,
})
```

`createDatasetSnapshot()`測量完整工件的緊湊度`JSON.stringify()` output, including the digest. `parseDatasetSnapshot()` measures the supplied text, including whitespace. Pretty-printing can exceed a budget that accepts the compact artifact. Neither helper truncates data. During creation, validation, cloning, and hashing happen before the byte-size check. Because shared references can expand during JSON serialization, the budget limits output size without bounding CPU time or peak memory. When adding a transport, configure HTTP request-body limits separately from this budget.

工件的最大嵌套深度為 100（從封套根部開始測量）。它們拒絕未知的結構字段、重複的項目標識或非空`externalId` values, non-JSON values, and invalid Unicode. Programmatic content must use plain objects and standard arrays, not class instances or array subclasses. Arbitrary JSON inside authored payloads remains intact, including trajectory expectations. Dataset schemas are preserved as JSON objects, but these utilities don't compile them or validate items against them. Destination authorization, reference resolution, and storage support also require separate preflight checks.

摘要是信封的 RFC 8785 規範 JSON 表示形式的小寫十六進位 SHA-256 雜湊值，不包含`digest`. Items are sorted by portable identity for hashing, while authored array order is preserved. Provenance is covered, so a new capture time changes the digest. A matching digest verifies integrity but doesn't establish authorship or approval. Review sensitive data before creating an artifact, as the utilities don't redact it.

## 更新、刪除和清除項目 {/* #updating-deleting-and-purging-items */}

[`updateItem()`](/reference/datasets/updateItem), [`deleteItem()`](/reference/datasets/deleteItem), and [`deleteItems()`](/reference/datasets/deleteItems) create new dataset versions as they modify or remove items:

```typescript title="src/mastra/datasets/update-delete.ts"
await dataset.updateItem({
  itemId: 'item-abc-123',
  groundTruth: { translation: '¡Hola!' },
})

await dataset.deleteItem({ itemId: 'item-abc-123' })

await dataset.deleteItems({ itemIds: ['item-1', 'item-2'] })
```

刪除項目會在目前資料集版本中隱藏該項目，但會在歷史行和刪除邏輯刪除中保留其內容。使用[`purgeItem()`](/reference/datasets/purgeItem) to redact the item's stored content across its existing history:

```typescript title="src/mastra/datasets/purge-item.ts"
await dataset.purgeItem({ itemId: 'item-abc-123' })
```

清除會用經過編輯的值取代每個歷史行和刪除邏輯刪除中的內容，並清除連結的實驗結果有效負載、標籤和註解。稍後提交的該項目的實驗結果也與經過編輯的內容一起儲存。

清除與並發資料集項編寫器序列化或衝突，但不保證哪個操作會先完成。如果一個突變`updateItem()` call loses the race, it re-reads the purge marker and rejects with `DATASET_ITEM_PURGED`. `deleteItem()` remains idempotent, and any deletion tombstone created during the race stays redacted.

正常項目突變使用緩慢變化的維度類型 2 (SCD-2) 版本控制。永久清除有意覆蓋擦除的歷史不變性，同時保留專案身分和資料集版本時間軸。它不會建立資料集版本並且無法撤銷。實驗計數器和審核狀態也被保留。避免將敏感資料儲存在`externalId`, which remains unchanged as the item's identity key.

MongoDB 儲存需要副本集或分片部署，並支援此操作的交易。當 MongoDB 事務不可用時，在更改資料之前清除會失敗。

## {/* #listing-and-searching-items */}

[`listItems()`](/reference/datasets/listItems)支援分頁和不區分大小寫的子字串搜尋：

```typescript title="src/mastra/datasets/list-items.ts"
// Paginated list
const { items, pagination } = await dataset.listItems({
  page: 0,
  perPage: 50,
})

// Substring search
const { items: matches } = await dataset.listItems({
  search: 'Hello',
})

// Search and pagination can be combined with a specific version
const { items: v2Matches } = await dataset.listItems({
  version: 2,
  search: 'Hello',
  page: 0,
  perPage: 50,
})
```

呼喚`listItems({ version })` without `search`, `page`, or `perPage` returns a bare `DatasetItem[]`. This form is deprecated. Pass `page` and `perPage` to always receive the paginated shape.

## 版本控制 {/* #versioning */}

新增、更新或刪除資料集項目會影響資料集版本。清除項目的儲存內容[`purgeItem()`](/reference/datasets/purgeItem) doesn't create a new version. This lets you pin experiments to a specific snapshot of the data while erasing sensitive content without changing the version history.

### 列出版本 {/* #listing-versions */}

使用[`listVersions()`](/reference/datasets/listVersions) to see the paginated history of versions:

```typescript title="src/mastra/datasets/list-versions.ts"
const { versions, pagination } = await dataset.listVersions()

for (const v of versions) {
  console.log(`Version ${v.version} — created ${v.createdAt}`)
}
```

### 查看項目歷史記錄 {/* #viewing-item-history */}

透過呼叫查看特定項目如何跨版本更改[`getItemHistory()`](/reference/datasets/getItemHistory) with the `itemId`:

```typescript title="src/mastra/datasets/item-history.ts"
const history = await dataset.getItemHistory({ itemId: 'item-abc-123' })

for (const row of history) {
  console.log(`Version ${row.datasetVersion}`, row.input, row.groundTruth)
}
```

### 固定到版本 {/* #pinning-to-a-version */}

取得過去版本中存在的確切項目：

```typescript title="src/mastra/datasets/pin-version.ts"
const { items } = await dataset.listItems({ version: 2, page: 0, perPage: 100 })
```

您也可以將實驗固定在某個版本，請參閱[running experiments](/docs/evals/experiments). Visit the [`Dataset` reference](/reference/datasets/dataset) for the full list of methods and parameters.
