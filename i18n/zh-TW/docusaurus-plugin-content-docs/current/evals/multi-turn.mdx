# 多輪評估

多輪評估用來測試 Agent 在對話中的行為。請提供 `inputs` 陣列來取代單一 `input`。每個項目會在同一個執行緒中依序送給 Agent，評分器會讀取所有回合累積的輸出。

## 何時使用多輪評估 {/* #when-to-use-multi-turn-evals */}

- Agent 使用記憶，且必須記住先前回合的上下文
- Agent 需要處理依賴先前回覆的後續問題
- 需要驗證對話中的工具呼叫順序
- Agent 執行多步驟 Workflow（搜尋、確認、執行）

## 快速入門 {/* #quickstart */}

```typescript title="src/evals/conversation-eval.ts"
import { runEvals } from '@mastra/core/evals'
import { checks } from '@mastra/evals/checks'
import { weatherAgent } from '../agents'

const result = await runEvals({
  data: [
    {
      inputs: [
        'What is the weather in Brooklyn?',
        'What about tomorrow?',
        'Compare the two forecasts.',
      ],
    },
  ],
  target: weatherAgent,
  scorers: [checks.calledTool('get_weather', { times: 2 }), checks.includes('Brooklyn')],
})
```

每個回合都以同一個執行緒 ID 呼叫 `agent.generate()`。Agent 可以讀取完整的對話記錄，評分器則會收到各回合累積的輸出訊息。

:::warning[內建 LLM 評分器只評估一個回合]

內建 LLM 評分器（例如評分準則、答案相關性、忠實度，以及[評分器相容性](#scorer-compatibility)列出的其他項目）只會讀取一則助理訊息，因此使用 `inputs` 時，只會評估最後一個回合的回覆。若要評估整段對話的語意，可用 [`createMultiTurnJudgeScorer()`](/reference/evals/multi-turn-judge) 依同一項準則評估助理的所有回合，也可透過逐回合的 [`turns[].scorers`](#per-turn-assertions-with-turns) 分別為各回合的輸出評分。

:::

## 跨回合回憶需要記憶功能 {/* #memory-is-required-for-cross-turn-recall */}

若要讓 Agent 記得先前回合，必須**設定記憶儲存空間**。共用執行緒 ID 讓各回合可以讀取先前內容，但只有 Agent 具備記憶功能時，執行緒才會保存對話記錄。未設定記憶時，各回合仍會依序執行，輸出也會累積供評分，但每筆輸入獨立處理，Agent 無法記得先前回合。對沒有記憶的 Agent 使用 `inputs` 時，`runEvals` 會記錄警告。

`runEvals` 會產生共用的 `threadId` 並注入 `resourceId`，用來識別對話。Mastra 記憶依資源和執行緒區分訊息，因此要讀取先前內容，必須同時具備兩個值。預設會從產生的執行緒推導資源，讓各段對話彼此隔離。若要指定固定資源，例如沿用既有使用者的記憶，請傳入 `targetOptions.memory.resource`。執行緒仍由 `runEvals` 管理，無須自行提供：

```typescript
await runEvals({
  target: weatherAgent,
  data: [{ inputs: ['What is the weather in Brooklyn?', 'What about tomorrow?'] }],
  scorers: [checks.similarity('weather forecast')],
  targetOptions: { memory: { resource: 'user-42' } },
})
```

如需設定記憶儲存空間的步驟，請見[記憶](/docs/memory/overview)。

## 運作方式 {/* #how-it-works */}

資料項目含有 `inputs` 陣列時，`runEvals` 會：

1. 為對話建立新的執行緒（具備唯一的 `threadId`）和資源，並保留呼叫端提供的 `targetOptions.memory.resource`
1. 在該執行緒中透過 `agent.generate()` 依序傳送每筆輸入
1. 累積各回合的所有輸出訊息
1. 將累積的完整輸出交由評分器評估

評分器能取得完整的對話輸出，包含每個回合。

## 評分語意 {/* #scoring-semantics */}

為多輪資料項目撰寫評分器時，請留意下列細節：

- **`run.output` 包含所有回合累積的輸出。** `checks.includes`、`checks.calledTool`、`checks.similarity` 等以輸出為依據的評分器會評估整段對話。例如，`checks.calledTool('get_weather', { times: 2 })` 會計算所有回合的呼叫次數。
- **`run.input` 只有第一個回合的輸入。** 比對輸入和輸出的評分器（例如忠實度、答案相關性及其他依輸入評估的 LLM 評分器）只能看到第一則使用者訊息，無法讀取整段對話。多輪評估建議採用以輸出為依據的檢查，或建立直接讀取累積 `run.output` 的評分器。

### 評分器相容性 {/* #scorer-compatibility */}

評分器必須讀取全部累積輸出，這些輸出才有用：

| 評分器 | 使用 `inputs` 時可讀取的內容 |
| - | - |
| [Quick Checks](/docs/evals/quick-checks)（`checks.calledTool`、`checks.includes`、`checks.similarity`、`checks.noToolErrors` 等） | 完整對話。工具呼叫檢查會計算所有回合的呼叫次數，文字檢查則會搜尋助理的所有文字。 |
| [多輪評判評分器](/reference/evals/multi-turn-judge) | 助理的每個回合，依一項以淺白英文撰寫的準則一併評分。 |
| 內建 LLM 評分器：評分準則、答案相關性、答案相似度、忠實度、幻覺、偏誤、毒性、上下文精確率、上下文召回率、上下文相關性、雜訊敏感度、提示詞對齊、摘要 | 只有最後一則含文字的助理訊息。參照輸入的評分器也只能看到第一個回合的輸入。 |
| 執行軌跡評分器（`AgentScorerConfig.trajectory`） | 有 Trace 時讀取最後一個回合的 Span，否則讀取所有累積訊息中的工具呼叫。 |
| 自訂評分器 | 由評分器決定要從 `run.output` 讀取哪些內容。 |

### 為整段對話評分 {/* #grading-a-whole-conversation */}

若要一併評估所有回合，請使用 [`createMultiTurnJudgeScorer()`](/reference/evals/multi-turn-judge)。它會彙整助理每個回合的對話記錄，再請評判模型判斷對話是否符合一項以淺白英文撰寫的準則，給出 `1` 或 `0` 分：

```typescript title="src/evals/trip-planning-eval.ts"
import { runEvals } from '@mastra/core/evals'
import { createMultiTurnJudgeScorer } from '@mastra/evals/scorers/prebuilt'
import { weatherAgent } from '../agents'

const result = await runEvals({
  data: [
    {
      inputs: [
        "How's the weather in London?",
        'And Paris?',
        'Should I pack an umbrella for London?',
      ],
    },
  ],
  target: weatherAgent,
  scorers: [
    {
      scorer: createMultiTurnJudgeScorer({
        model: '__GATEWAY_ANTHROPIC_MODEL_HAIKU__',
        criterion:
          'The agent provided forecasts for London and Paris, and gave weather-appropriate packing advice.',
      }),
      threshold: 1,
    },
  ],
})
```

若評估內容無法用這項準則表達，可以自行撰寫評分器，從 `run.output` 讀取助理訊息。[`extractAgentResponseMessages()`](/reference/evals/scorer-utils#extractagentresponsemessages) 會依序傳回每則助理訊息的文字：

```typescript title="src/evals/conversation-judge.ts"
import { createScorer } from '@mastra/core/evals'
import { extractAgentResponseMessages } from '@mastra/evals/scorers/utils'
import { z } from 'zod'

export const conversationJudge = createScorer({
  id: 'conversation-judge',
  name: 'Conversation Judge',
  description: 'Grades every assistant turn in a conversation against one criterion',
  type: 'agent',
  judge: {
    model: '__GATEWAY_ANTHROPIC_MODEL_HAIKU__',
    instructions: 'You grade multi-turn assistant transcripts against a single criterion.',
  },
})
  .analyze({
    description: 'Judge the transcript as a whole',
    outputSchema: z.object({ satisfied: z.boolean(), reason: z.string() }),
    createPrompt: ({ run }) => {
      const transcript = extractAgentResponseMessages(run.output)
        .map((text, index) => `Turn ${index + 1}: ${text}`)
        .join('\n\n')

      return `Grade this conversation:\n\n${transcript}\n\nCriterion: the assistant keeps the forecast consistent across turns.`
    },
  })
  .generateScore(({ results }) => (results.analyzeStepResult?.satisfied ? 1 : 0))
  .generateReason(({ results }) => results.analyzeStepResult?.reason ?? '')
```

和其他評分器一樣，將它傳給 `runEvals`。完整的 `createScorer()` 流程請見[自訂評分器](/docs/evals/custom-scorers)。

## 使用 `turns` 做逐回合斷言 {/* #per-turn-assertions-with-turns */}

使用 `inputs` 時，各回合**累積**的輸出會合併成一個分數，可能掩蓋個別回合的失敗。例如，以輸出為依據的 `checks.includes('Brooklyn')` 只要在 _任一_ 回合找到 Brooklyn 就會通過，即使後續回合出錯也一樣。

若要斷言**特定回合**的行為正確，請使用 `turns`。每個回合都是一個物件，具有自己的 `input` 及選用的 `gates` 或 `scorers`，只評估**該回合**的輸入與輸出：

```typescript title="src/evals/per-turn-eval.ts"
import { runEvals } from '@mastra/core/evals'
import { checks } from '@mastra/evals/checks'
import { weatherAgent } from '../agents'

const result = await runEvals({
  data: [
    {
      turns: [
        {
          input: 'What is the weather in Brooklyn?',
          gates: [checks.calledTool('get_weather')],
        },
        {
          // The follow-up must call the tool again — it can't be satisfied
          // by the first turn's tool call.
          input: 'What about tomorrow?',
          gates: [checks.calledTool('get_weather')],
          scorers: [{ scorer: checks.similarity('tomorrow forecast'), threshold: 0.5 }],
        },
      ],
    },
  ],
  target: weatherAgent,
})

result.verdict // 'passed' | 'scored' | 'failed'
result.turnResults // per-turn gate/threshold/scorer outcomes
```

逐回合評估的運作方式如下：

- 每個回合的門檻檢查或評分器**只會收到該回合**的 `run.input` 和 `run.output`，無法讀取累積的對話。其他回合的輸出無法通過這項檢查，且 `run.input` 會包含目前評估回合的輸入。
- 各回合的結果會納入[判定](/docs/evals/gates-and-verdicts)。有回合未通過門檻檢查時，判定為 `failed`。若門檻檢查全數通過，但有回合未達分數門檻，判定為 `scored`。
- `result.turnResults[i]` 提供各回合的 `gateResults`、`thresholdResults` 和 `scores`。失敗時可以確認是哪個回合出錯。多段對話的結果會依回合索引取平均。
- 沒有 `gates` 或 `scorers` 的回合只會推進對話。
- 頂層的 `scorers` 和 `gates` 仍會針對累積輸出整體執行，因此可同時檢查「這一回合必須呼叫工具」與「回答提到 Brooklyn」。
- 若 Agent 已設定儲存空間，各回合的評分器和門檻檢查結果會像頂層分數一樣保存，可在分數儲存空間查看。每筆已儲存的回合分數都以回合索引（`metadata.turnIndex`）為標籤，並共用對話的 `threadId`，也含有該回合 Trace Span 的連結。

如果只需要整段對話的單一分數，請用 `inputs`。若正確性取決於個別回合，請用 `turns`。同一筆資料項目不能同時使用 `turns` 與 `input` 或 `inputs`。

## 搭配門檻檢查及分數門檻 {/* #combining-with-gates-and-thresholds */}

多輪資料項目可以搭配[門檻檢查與判定](/docs/evals/gates-and-verdicts)。請使用以輸出為依據的評分器，讓檢查反映整段對話：

```typescript title="src/evals/memory-eval.ts"
import { runEvals } from '@mastra/core/evals'
import { checks } from '@mastra/evals/checks'

const result = await runEvals({
  data: [
    {
      inputs: ['My favorite city is Brooklyn.', 'What is the weather in my favorite city?'],
    },
  ],
  target: weatherAgent,
  gates: [checks.calledTool('get_weather')],
  scorers: [{ scorer: checks.similarity('Brooklyn weather forecast'), threshold: 0.5 }],
})

result.verdict // 'passed' | 'scored' | 'failed'
```

## 混用單輪與多輪資料項目 {/* #mixing-single-turn-and-multi-turn */}

單次呼叫 `runEvals` 可以同時包含單輪與多輪資料項目：

```typescript title="src/evals/mixed-eval.ts"
const result = await runEvals({
  data: [
    { input: 'What is the weather in Brooklyn?' },
    {
      inputs: ['My favorite city is Brooklyn.', 'What is the weather in my favorite city?'],
    },
  ],
  target: weatherAgent,
  scorers: [checks.includes('Brooklyn')],
})
```

單輪項目照常使用 `input`。多輪項目使用 `inputs`，可完全省略 `input`。

## 參數驗證 {/* #validation */}

若提供的 `inputs` 是空陣列，`runEvals` 會擲出 `MastraError`：

```typescript
// Throws: 'inputs' must be a non-empty array
await runEvals({
  data: [{ inputs: [] }],
  target: myAgent,
  scorers: [myScorer],
})
```
