# 內建評分器

Mastra 內建一套評分器，可用來評估 AI 輸出。這些評分器針對常見的評估情境最佳化，可直接在 Agent 與 Workflow 中使用。

若要自行建立評分器，請參閱[自訂評分器](/docs/evals/custom-scorers)指南。

## 可用的評分器 {/* #available-scorers */}

### 準確性和可靠性 {/* #accuracy-and-reliability */}

這些評分器衡量 Agent 的回答是否正確、符合事實且完整：

- [`answer-relevancy`](/reference/evals/answer-relevancy)：評估回覆切合輸入問題的程度（`0-1`，分數越高越好）
- [`answer-similarity`](/reference/evals/answer-similarity)：透過語意分析比對 Agent 輸出與標準答案，用於 CI/CD 測試（`0-1`，分數越高越好）
- [`faithfulness`](/reference/evals/faithfulness)：衡量回覆忠實反映所提供脈絡的程度（`0-1`，分數越高越好）
- [`hallucination`](/reference/evals/hallucination)：找出與事實矛盾或缺乏依據的說法（`0-1`，分數越低越好）
- [`completeness`](/reference/evals/completeness)：檢查回覆是否涵蓋所有必要資訊（`0-1`，分數越高越好）
- [`content-similarity`](/reference/evals/content-similarity)：以字元層級的比對衡量文字相似度（`0-1`，分數越高越好）
- [`textual-difference`](/reference/evals/textual-difference)：衡量字串之間的文字差異（`0-1`，分數越高代表越相似）
- [`tool-call-accuracy`](/reference/evals/tool-call-accuracy)：評估 LLM 是否從可用的 Tool 中選到正確的項目（`0-1`，分數越高越好）
- [`trajectory-accuracy`](/reference/evals/trajectory-accuracy)：評估各類 span 的動作是否依預期順序執行，涵蓋 Tool 與模型活動及 Workflow 步驟（`0-1`，分數越高越好）
- [`prompt-alignment`](/reference/evals/prompt-alignment)：衡量 Agent 回覆是否符合使用者提示的意圖、需求、完整性與格式（`0-1`，分數越高越好）
- [`multi-turn-judge`](/reference/evals/multi-turn-judge)：依照以淺白英文撰寫的準則，逐輪評分[多輪對話](/docs/evals/multi-turn)中助理的回覆（`0` 或 `scale`，預設為 `1`）

### 上下文品質 {/* #context-quality */}

這些評分器衡量產生回覆時採用的脈絡是否相關、品質如何：

- [`context-precision`](/reference/evals/context-precision)：以平均精確率均值評估脈絡排序；相關內容越早出現，得分越高（`0-1`，分數越高越好）
- [`context-relevance`](/reference/evals/context-relevance)：依相關程度與使用情形衡量脈絡的效用，也能找出缺少的脈絡（`0-1`，分數越高越好）

:::tip[上下文評分器選擇]

- 若脈絡順序很重要，而且需要標準的資訊檢索指標，請用 **Context Precision**（適合評估 RAG 排序）。
- 若要詳細評估相關性、追蹤脈絡使用情形並找出缺漏，請用 **Context Relevance**。

兩個上下文評分器都支援：

* **靜態情境**：預定義的上下文數組
* **動態上下文提取**：使用自訂函數從運行中提取上下文（非常適合 RAG 系統、向量資料庫等）

:::

### 輸出品質 {/* #output-quality */}

這些評分者評估對格式、風格和安全要求的遵守：

- [`tone-consistency`](/reference/evals/tone-consistency)：衡量正式程度、複雜度與風格是否一致（`0-1`，分數越高越好）
- [`toxicity`](/reference/evals/toxicity)：偵測有害或不當內容（`0-1`，分數越低越好）
- [`bias`](/reference/evals/bias)：檢查輸出是否可能含有偏見（`0-1`，分數越低越好）
- [`keyword-coverage`](/reference/evals/keyword-coverage)：評估技術術語的使用情形（`0-1`，分數越高越好）

### 快速檢查 {/* #quick-checks */}

這些輕量評分器無須呼叫 LLM，就能快速執行確定性的斷言。用法請見[快速檢查](/docs/evals/quick-checks)指南。

* [`checks.includes`](/reference/evals/checks#checksincludesexpected-options)：如果輸出包含子字串 (`0` or `1`)
* [`checks.excludes`](/reference/evals/checks#checksexcludesunwanted-options)：如果輸出不包含子字串（`0` or `1`)
* [`checks.equals`](/reference/evals/checks#checksequalsexpected-options)：如果輸出與字串匹配則得分 1，預設會忽略大小寫（`0` or `1`)
* [`checks.matches`](/reference/evals/checks#checksmatchespattern-options)：如果輸出與正規表示式匹配，則得分 1（`0` or `1`)
- [`checks.similarity`](/reference/evals/checks#checkssimilarityexpected-options)：以 Dice 係數衡量字串相似度（`0-1`，也可依門檻給出二元分數）
* [`checks.calledTool`](/reference/evals/checks#checkscalledtooltoolname-options)：如果某個Tool被呼叫至少 N 次，則得分 1（`0` or `1`)
* [`checks.didNotCall`](/reference/evals/checks#checksdidnotcalltoolname)：如果未呼叫Tool則得 1 分（`0` or `1`)
* [`checks.toolOrder`](/reference/evals/checks#checkstoolorderexpectedorder)：如果依序呼叫Tool則得 1 分（`0` or `1`)
* [`checks.maxToolCalls`](/reference/evals/checks#checksmaxtoolcallsmax)：如果Tool呼叫次數在限制範圍內，則得分 1（`0` or `1`)
* [`checks.usedNoTools`](/reference/evals/checks#checksusednotools)：如果沒有呼叫任何Tool，則得分 1（`0` or `1`)
* [`checks.noToolErrors`](/reference/evals/checks#checksnotoolerrors)：如果Tool呼叫沒有錯誤，則得分 1（`0` or `1`)
