# Vitest 整合

`@mastra/evals/vitest` 將 [`runEvals`](/reference/evals/run-evals) 整合到 [Vitest](https://vitest.dev/)，讓評估像一般測試一樣執行。評估未通過時，鏈式斷言會使測試失敗；回報器會在測試輸出中列出分數表。

請先安裝 `@mastra/evals` 與 `vitest`（第 3、4 或 5 版）：

```bash
npm install @mastra/evals vitest
```

## 設定 Vitest {/* #configuring-vitest */}

在 `vitest.config.ts` 註冊回報器與比對器：

```typescript title="vitest.config.ts"
import { defineConfig } from 'vitest/config'
import { MastraEvalsReporter } from '@mastra/evals/vitest'

export default defineConfig({
  test: {
    reporters: ['default', new MastraEvalsReporter()],
    setupFiles: ['@mastra/evals/vitest/setup'],
  },
})
```

設定檔會為 `expect` 註冊自訂比對器。也可以在自己的設定檔中呼叫 `registerEvalMatchers()`，此函式由 `@mastra/evals/vitest` 提供。

## 使用 `expectEvals` 檢查資料集結果 {/* #asserting-on-a-dataset-with-expectevals */}

`expectEvals` 會在一般的 `test()` 中執行 `runEvals` 評估，並檢查最低通過率。它接受與 `runEvals` 相同的設定：用作 `target` 的 Agent 或 Workflow、`data` 資料項目，以及 `scorers`、`gates` 或門檻。每道關卡都會逐項判定是否通過，因此 `toPass(0.8)` 要求至少 80% 的項目通過所有關卡。評分器門檻仍以各項的平均分數判定，無論通過率為何，都必須達標：

```typescript title="tests/weather-agent.eval.test.ts"
import { test } from 'vitest'
import { expectEvals } from '@mastra/evals/vitest'
import { checks } from '@mastra/evals/checks'
import { mastra } from '../src/mastra'

test('weather agent calls the tool and answers relevantly', { timeout: 60_000 }, async () => {
  await expectEvals({
    target: mastra.getAgent('weatherAgent'),
    data: [{ input: "What's the weather in London?" }],
    gates: [checks.calledTool('weatherTool'), checks.noToolErrors(), checks.includes('London')],
    scorers: [{ scorer: mastra.getScorer('answerRelevancyScorer'), threshold: 0.7 }],
  }).toPass(0.8)
})
```

`toPass()` 未帶引數時，每個資料項目都必須通過所有關卡。務必等候斷言完成：它會傳回完整的 `RunEvalsResult`，方便進一步檢查，也會將本次執行的分數附在目前測試上，供 `MastraEvalsReporter` 顯示。

使用 LLM 的評估遠比 Vitest 預設的 5 秒逾時限制久，請為個別測試傳入 `timeout`，或在 Vitest 設定中指定 `testTimeout`。

## 使用 `expectEval` 進行矩陣測試 {/* #matrix-testing-with-expecteval */}

`expectEval` 是單筆版本：`data` 只接收一筆資料。搭配 `test.for` 或 `test.each` 時，各筆資料會各自產生一項測試及一筆報告記錄，不必將整個資料集彙整為單一結果：

```typescript title="tests/weather-agent.matrix.eval.test.ts"
import { test } from 'vitest'
import { expectEval } from '@mastra/evals/vitest'
import { checks } from '@mastra/evals/checks'
import { mastra } from '../src/mastra'

test.for([
  { input: "What's the weather in London?", groundTruth: 'London' },
  { input: "What's the weather in Tokyo?", groundTruth: 'Tokyo' },
  { input: "What's the weather in Sydney?", groundTruth: 'Sydney' },
])('weather agent: $input', { timeout: 60_000 }, async item => {
  await expectEval({
    target: mastra.getAgent('weatherAgent'),
    data: item,
    gates: [checks.calledTool('weatherTool'), checks.includes(item.groundTruth)],
  }).toPass()
})
```

各筆資料獨立判定是否通過。有一筆出現回歸時，對應的測試就會失敗，不會只反映在整體通過率上。

## 使用比對器檢查結果 {/* #asserting-on-results-with-matchers */}

若要更精細地檢查結果，可在一般的 `test()` 中直接呼叫 `runEvals`，再用自訂比對器檢查結果：

```typescript title="tests/weather-agent.matchers.eval.test.ts"
import { test, expect } from 'vitest'
import { runEvals } from '@mastra/core/evals'
import { checks } from '@mastra/evals/checks'
import { mastra } from '../src/mastra'

test('weather agent quality', { timeout: 60_000 }, async () => {
  const result = await runEvals({
    target: mastra.getAgent('weatherAgent'),
    data: [{ input: "What's the weather in London?" }],
    scorers: [mastra.getScorer('answerRelevancyScorer')],
    gates: [checks.noToolErrors()],
  })

  expect(result).toHaveVerdict('passed')
  expect(result).toPassGates()
  expect(result).toHaveScoreAbove('answer-relevancy-scorer', 0.7)
})
```

可用的比對器如下：

- `toHaveVerdict(verdict)`：檢查這次執行的判定（`"passed"`、`"scored"` 或 `"failed"`）。
- `toHaveScoreAbove(scorerName, min)` / `toHaveScoreBelow(scorerName, max)`：檢查評分器的平均分數。若設定按類別組織，請使用以點分隔的路徑，例如 `"agent.my-scorer"` 或 `"steps.step-1.my-scorer"`。
- `toPassGates()`：檢查所有關卡是否通過。未設定關卡時，斷言會失敗。
- `toPassThresholds()`：檢查所有評分器是否達到門檻。未設定門檻時，斷言會失敗。

## 評估 Workflow {/* #evaluating-a-workflow */}

Workflow 也能當作評估目標。將 `WorkflowScorerConfig` 物件傳給 `scorers`，就能對 Workflow 輸出、個別步驟或步驟的執行軌跡評分；比對器可用點分隔的路徑查找巢狀分數：

```typescript title="tests/weather-workflow.eval.test.ts"
import { test, expect } from 'vitest'
import { runEvals } from '@mastra/core/evals'
import { mastra } from '../src/mastra'

test('weather workflow runs fetch-weather then plan-activities', { timeout: 60_000 }, async () => {
  const result = await runEvals({
    target: mastra.getWorkflow('weatherWorkflow'),
    data: [
      {
        input: { city: 'London' },
        expectedTrajectory: {
          steps: [
            { stepType: 'workflow_step', name: 'fetch-weather' },
            { stepType: 'workflow_step', name: 'plan-activities' },
          ],
        },
      },
      {
        input: { city: 'Tokyo' },
        expectedTrajectory: {
          steps: [
            { stepType: 'workflow_step', name: 'fetch-weather' },
            { stepType: 'workflow_step', name: 'plan-activities' },
          ],
        },
      },
    ],
    scorers: {
      trajectory: [mastra.getScorer('trajectoryAccuracyScorer')],
    },
  })

  expect(result).toHaveScoreAbove('trajectory.code-trajectory-accuracy-scorer', 0.9)
})
```

這個 Workflow 的 `plan-activities` 步驟會在執行時呼叫 `mastra.getAgent('weatherAgent')`；只有透過 `mastra.getWorkflow()` 取得的評估目標才支援此用法。完整的 `WorkflowScorerConfig` 結構請參閱 [`runEvals` 參考文件](/reference/evals/run-evals#workflow-evaluation)。

## 查看回報器輸出 {/* #reading-the-reporter-output */}

執行結束後，`MastraEvalsReporter` 會為每項評估測試輸出分數表：

```text
 Mastra Evals

✓ weather agent calls the tool and answers relevantly (1 item)
   check-called-tool (gate)                        1.0  ✓
   check-no-tool-errors (gate)                     1.0  ✓
   check-includes (gate)                           1.0  ✓
   answer-relevancy-scorer (threshold: min 0.7)    0.9  ✓

 Eval runs: 1 (1 passed)
```

每筆記錄會列出執行判定、關卡、門檻及各評分器的平均分數。回報器會讀取 `expectEval` 和 `expectEvals` 附在 `task.meta.mastraEval` 上的中繼資料，因此可搭配平行執行的測試檔及任何填入此欄位的測試。

## 速率限制與並行執行 {/* #rate-limits-and-concurrency */}

Vitest 會平行執行測試檔，`runEvals` 也有自己的 `concurrency` 選項；兩層並行會使 LLM 流量成倍增加。若達到 Provider 的速率限制，請調低評估選項的 `concurrency`，或在 Vitest 設定中指定 `fileParallelism: false`。
