# 客製化記分器

使用`createScorer`建立自訂評估邏輯。每個步驟都可以使用 JavaScript 函數或基於 LLM 的提示對象，這取決於您要評估的內容。

## 四步驟管道 {/* #the-four-step-pipeline */}

Mastra 的所有評分員都遵循一致的四步驟評估流程：

1. **預處理**（可選）：準備或轉換輸入/輸出數據
2. **分析**（可選）：執行評估分析並收集見解
3. **產生分數**（必需）：將分析轉換為數字分數
4. **產生原因**（可選）：產生人類可讀的解釋

結合**functions** and **prompt objects** within a scorer to use deterministic checks for some steps and LLM-based evaluation for others.

## 函數與提示對象 {/* #functions-vs-prompt-objects */}

**功能**使用 JavaScript 實作確定性邏輯。它們非常適合：

* 具有明確標準的演算法評估
* 效能關鍵場景
* 與現有庫集成
* 一致、可重複的結果

**提示對象**使用LLM作為評審進行評估。它們非常適合：

* 需要類人判斷的主觀評價
* 複雜的標準難以透過演算法進行編碼
* 自然語言理解任務
* 細緻入微的情境評估

**「提示對象」是什麼意思：**&#x6B65;驟不是一個函數，而是一個對象`description` + `createPrompt` (and `outputSchema` for `preprocess`/`analyze`). That object tells Mastra to run the judge LLM for the step and store the structured output in `results.<step>StepResult`.

您可以在單一評分器中混合和匹配方法 - 例如，使用用於預處理資料的函數和用於分析品質的 LLM。

## 初始化記分器 {/* #initializing-a-scorer */}

每個得分手都從`createScorer` factory function, which requires an id and description, and optionally accepts a type specification and judge configuration.

```typescript oxfmt:false
import { createScorer } from '@mastra/core/evals';

const glutenCheckerScorer = createScorer({
  id: 'gluten-checker',
  description: 'Check if recipes contain gluten ingredients',
  judge: {                    // Optional: for prompt object steps
    model: '__GATEWAY_OPENAI_MODEL__',
    instructions: 'You are a Chef that identifies if recipes contain gluten.'
  }
})
// Chain step methods here
.preprocess(...)
.analyze(...)
.generateScore(...)
.generateReason(...)
```

僅當您計劃在任何步驟中使用提示物件時才需要判斷設定。各個步驟可以使用自己的判斷設定覆蓋此預設配置。

如果所有步驟都是基於函數的，則永遠不會呼叫判斷並且沒有判斷輸出。若要查看 LLM 輸出，請定義至少一個步驟作為提示物件並讀取對應的步驟結果（例如，`results.analyzeStepResult`).

### 最小判斷範例（提示物件） {/* #minimal-judge-example-prompt-object */}

此範例使用提示對象`analyze`, so the judge runs and its structured output is available as `results.analyzeStepResult`.

```typescript
import { createScorer } from '@mastra/core/evals'
import { z } from 'zod'

const quoteSourcesScorer = createScorer({
  id: 'quote-sources',
  description: 'Check if the response includes sources',
  judge: {
    model: '__GATEWAY_OPENAI_MODEL_LUNA__',
    instructions: 'You are a strict evaluator.',
  },
})
  .analyze({
    description: 'Detect whether sources are present',
    outputSchema: z.object({
      hasSources: z.boolean(),
      sources: z.array(z.string()),
    }),
    createPrompt: ({ run }) => `
Does the response contain sources? Extract them as a list.

Response:
${run.output}
`,
  })
  .generateScore(({ results }) => (results.analyzeStepResult.hasSources ? 1 : 0))

// Run the scorer and inspect judge output
const result = await quoteSourcesScorer.run({
  input: 'What is the capital of France?',
  output: 'Paris is the capital of France [1]. Source: [1] Wikipedia',
})

console.log(result.score) // 1
console.log(result.analyzeStepResult) // { hasSources: true, sources: ["Wikipedia"] }
```

### Agent評估的Agent類型 {/* #agent-type-for-agent-evaluation */}

為了類型安全以及與即時Agent評分和追蹤評分的兼容性，請使用`type: 'agent'` when creating scorers for agent evaluation. The same scorer can evaluate an agent and score traces:

```typescript
const myScorer = createScorer({
  type: 'agent', // Automatically handles agent input/output types
}).generateScore(({ run, results }) => {
  // run.output is automatically typed as ScorerRunOutputForAgent
  // run.input is automatically typed as ScorerRunInputForAgent
})
```

## 逐步細分 {/* #step-by-step-breakdown */}

### 預處理步驟（可選） {/* #preprocess-step-optional */}

當您需要提取特定元素或過濾內容，或轉換複雜的資料結構時，準備輸入/輸出資料。

**功能：** `({ run, results }) => any`

```typescript oxfmt:false
const glutenCheckerScorer = createScorer(...)
.preprocess(({ run }) => {
  // Extract and clean recipe text
  const recipeText = run.output.text.toLowerCase();
  const wordCount = recipeText.split(' ').length;

  return {
    recipeText,
    wordCount,
    hasCommonGlutenWords: /flour|wheat|bread|pasta/.test(recipeText)
  };
})
```

**提示對象：**&#x4F7F;用`description`, `outputSchema`, and `createPrompt` to structure LLM-based preprocessing.

```typescript oxfmt:false
const glutenCheckerScorer = createScorer(...)
.preprocess({
  description: 'Extract ingredients from the recipe',
  outputSchema: z.object({
    ingredients: z.array(z.string()),
    cookingMethods: z.array(z.string())
  }),
  createPrompt: ({ run }) => `
    Extract all ingredients and cooking methods from this recipe:
    ${run.output.text}

    Return JSON with ingredients and cookingMethods arrays.
  `
})
```

**資料流：**&#x7D50;果可用於後續步驟，如下所示`results.preprocessStepResult`

### 分析步驟（可選） {/* #analyze-step-optional */}

執行核心評估分析，收集將為評分決策提供資訊的見解。

**功能：** `({ run, results }) => any`

```typescript oxfmt:false
const glutenCheckerScorer = createScorer({...})
.preprocess(...)
.analyze(({ run, results }) => {
  const { recipeText, hasCommonGlutenWords } = results.preprocessStepResult;

  // Simple gluten detection algorithm
  const glutenKeywords = ['wheat', 'flour', 'barley', 'rye', 'bread'];
  const foundGlutenWords = glutenKeywords.filter(word =>
    recipeText.includes(word)
  );

  return {
    isGlutenFree: foundGlutenWords.length === 0,
    detectedGlutenSources: foundGlutenWords,
    confidence: hasCommonGlutenWords ? 0.9 : 0.7
  };
})
```

**提示對象：**&#x4F7F;用`description`, `outputSchema`, and `createPrompt` for LLM-based analysis.

```typescript oxfmt:false
const glutenCheckerScorer = createScorer({...})
.preprocess(...)
.analyze({
  description: 'Analyze recipe for gluten content',
  outputSchema: z.object({
    isGlutenFree: z.boolean(),
    glutenSources: z.array(z.string()),
    confidence: z.number().min(0).max(1)
  }),
  createPrompt: ({ run, results }) => `
    Analyze this recipe for gluten content:
    "${results.preprocessStepResult.recipeText}"

    Look for wheat, barley, rye, and hidden sources like soy sauce.
    Return JSON with isGlutenFree, glutenSources array, and confidence (0-1).
  `
})
```

**資料流：**&#x7D50;果可用於後續步驟，如下所示`results.analyzeStepResult`

### `generateScore`步驟（必填） {/* #generatescore-step-required */}

將分析結果轉換為數字分數。這是管道中唯一必要的步驟。

**功能：** `({ run, results }) => number`

```typescript oxfmt:false
const glutenCheckerScorer = createScorer({...})
.preprocess(...)
.analyze(...)
.generateScore(({ results }) => {
  const { isGlutenFree, confidence } = results.analyzeStepResult;

  // Return 1 for gluten-free, 0 for contains gluten
  // Weight by confidence level
  return isGlutenFree ? confidence : 0;
})
```

**提示對象：**&#x8ACB;參閱[`createScorer`](/reference/evals/create-scorer) API reference for details on using prompt objects with generateScore, including required `calculateScore` function.

**資料流：**&#x6B64;分數可用於generateReason 作為`score` parameter

### `generateReason`步驟（可選） {/* #generatereason-step-optional */}

產生人類可讀的分數解釋，對於調試、透明度或用戶回饋很有用。

**功能：** `({ run, results, score }) => string`

```typescript oxfmt:false
const glutenCheckerScorer = createScorer({...})
.preprocess(...)
.analyze(...)
.generateScore(...)
.generateReason(({ results, score }) => {
  const { isGlutenFree, glutenSources } = results.analyzeStepResult;

  if (isGlutenFree) {
    return `Score: ${score}. This recipe is gluten-free with no harmful ingredients detected.`;
  } else {
    return `Score: ${score}. Contains gluten from: ${glutenSources.join(', ')}`;
  }
})
```

**提示對象：**&#x4F7F;用`description` and `createPrompt` for LLM-generated explanations.

```typescript oxfmt:false
const glutenCheckerScorer = createScorer({...})
.preprocess(...)
.analyze(...)
.generateScore(...)
.generateReason({
  description: 'Explain the gluten assessment',
  createPrompt: ({ results, score }) => `
    Explain why this recipe received a score of ${score}.
    Analysis: ${JSON.stringify(results.analyzeStepResult)}

    Provide a clear explanation for someone with dietary restrictions.
  `
})
```

## 輸入過濾 {/* #input-filtering */}

Agent對話可​​以包含數百個訊息，其Tool呼叫和資料部分都附有系統元資料。大多數得分手只需要一個子集。在記分器管道執行之前，`prepareRun` option transforms the run data to reduce noise and keep each scorer focused.

### 聲明式過濾`filterRun()` {/* #declarative-filtering-with-filterrun */}

這[`filterRun()`](/reference/evals/filter-run) utility creates a `prepareRun` function from declarative options:

```typescript title="src/mastra/scorers/tool-scorer.ts"
import { createScorer, filterRun } from '@mastra/core/evals'

const toolScorer = createScorer({
  id: 'tool-quality',
  description: 'Evaluates tool usage quality',
  type: 'agent',
  prepareRun: filterRun({
    partTypes: ['tool-invocation', 'text'],
    maxRememberedMessages: 20,
  }),
}).generateScore(({ run }) => {
  // run.input.rememberedMessages has only tool and text messages, max 20
  return 1
})
```

常見選項包括：

* `partTypes`：僅保留具有匹配部分類型的消息（例如，`'tool-invocation'`, `'text'`, `'reasoning'`)
* `toolNames`：僅保留涉及特定Tool的訊息（例如，`['write_file', 'execute_command']`)
* `maxRememberedMessages`：限制上下文視窗大小
* `dropRequestContext`, `dropGroundTruth`, `dropExpectedTrajectory`: Remove unused fields

請參閱[`filterRun()` reference](/reference/evals/filter-run) for the full list of options.

### 風俗`prepareRun` functions {/* #custom-preparerun-functions */}

對於邏輯來說`filterRun()` doesn't cover, write a `prepareRun` function directly:

```typescript
import { createScorer } from '@mastra/core/evals'

const customScorer = createScorer({
  id: 'recent-output',
  description: 'Scores only the last response',
  type: 'agent',
  prepareRun: run => ({
    ...run,
    output: run.output.slice(-1), // Keep only the last message
    requestContext: undefined,
  }),
}).generateScore(({ run }) => {
  return run.output.length > 0 ? 1 : 0
})
```

這`prepareRun` function can also be async.

:::注意\[系統訊息始終保留]

`filterRun()`從不過濾`systemMessages` or `taggedSystemMessages`. These contain agent instructions and are critical context for scoring.

:::

## 跳過無法得分的跑動 {/* #skipping-runs-that-cant-be-scored */}

有些記分器僅適用於運行的子集。判斷退款處理情況的記分員對於未要求退款的運作沒有任何評價。

返回[`notScorable()`](/reference/evals/not-scorable) from a function step to declare that the run has nothing to evaluate. Remaining steps are skipped and the run is left out of the scorer's aggregates:

```typescript title="src/mastra/scorers/refund-judge.ts"
import { createScorer, notScorable } from '@mastra/core/evals'
import { extractToolCalls } from '@mastra/evals/scorers/utils'

export const refundJudge = createScorer({
  id: 'refund-judge',
  description: 'Judges how well refund requests were handled',
  type: 'agent',
  judge: {
    model: '__GATEWAY_OPENAI_MODEL_LUNA__',
    instructions: 'You are a strict QA reviewer for customer-support refund handling.',
  },
})
  .preprocess(({ run }) => {
    const { tools } = extractToolCalls(run.output)
    return tools.includes('refundCustomer')
      ? { tools }
      : notScorable('refundCustomer was not called')
  })
  .generateScore({
    description: 'Score the refund handling from 0 to 1',
    createPrompt: ({ run }) =>
      `Rate this refund handling from 0 to 1:\n${JSON.stringify(run.output)}`,
  })
```

把支票放進去`preprocess` so it runs before any judge step. `notScorable()` is different from an [eligibility filter](/docs/evals/overview#how-live-evaluations-work): filters decide from request context whether the scorer runs at all, while `notScorable()` lets the scorer inspect the run's input and output first.

請參閱[`notScorable()` reference](/reference/evals/not-scorable) for the result shape and how live scoring, `runEvals()`, and experiments treat a skipped run.

## 確定法官的評分標準 {/* #anchoring-the-judges-score-scale */}

提示對象`generateScore` step asks the judge for `{ score: number }`. Mastra forwards whatever number comes back without clamping or normalizing it, so the prompt is the only thing defining your scale:

```typescript title="src/mastra/scorers/refund-judge.ts" oxfmt:false
.generateScore({
  description: 'Score the refund handling from 0 to 1',
  createPrompt: ({ run }) => `Rate this refund handling:
- 1.0: refund issued correctly, no policy breach
- 0.5: refund issued but policy explained poorly or a step was missed
- 0.0: refund not issued, or issued against policy

${JSON.stringify(run.output)}`,
})
```

`Rate this refund handling from 0 to 1`單獨的評分標準的中間部分是不確定的，而評審們會以不同的方式填補這個空白。命名端點並描述至少一個中間值。将输出格式排除在提示之外：该步骤已要求法官提供`{ score: number }`, and a prompt that says "return only the number" makes the judge answer in a shape the step can't read. If your scorer must not drift outside a range, clamp or reject the value in a function step instead of trusting the judge.

這對於[gates](/docs/evals/gates-and-verdicts), whose thresholds must be between 0 and 1 even though the judge's number is stored exactly as returned. A prompt that asks for a 1 to 10 score makes a failing `2` pass every threshold you're allowed to set. The gate then never fires.

## 範例：建立自訂記分器 {/* #example-create-a-custom-scorer */}

Mastra 中的自訂記分器使用`createScorer` with four core components:

1. [**判斷配置**](#judge-configuration)
2. [**分析步驟**](#analysis-step)
3. [**分數生成**](#score-generation)
4. [**理性生成**](#reason-generation)

這些組件共同允許您使用法學碩士作為評審來定義自訂評估邏輯。訪問[createScorer](/reference/evals/create-scorer) for the full API and configuration options.

```typescript title="src/mastra/scorers/gluten-checker.ts"
import { createScorer } from '@mastra/core/evals'
import { z } from 'zod'

export const GLUTEN_INSTRUCTIONS = `You are a Chef that identifies if recipes contain gluten.`

export const generateGlutenPrompt = ({
  output,
}: {
  output: string
}) => `Check if this recipe is gluten-free.

Check for:
- Wheat
- Barley
- Rye
- Common sources like flour, pasta, bread

Example with gluten:
"Mix flour and water to make dough"
Response: {
  "isGlutenFree": false,
  "glutenSources": ["flour"]
}

Example gluten-free:
"Mix rice, beans, and vegetables"
Response: {
  "isGlutenFree": true,
  "glutenSources": []
}

Recipe to analyze:
${output}

Return your response in this format:
{
  "isGlutenFree": boolean,
  "glutenSources": ["list ingredients containing gluten"]
}`

export const generateReasonPrompt = ({
  isGlutenFree,
  glutenSources,
}: {
  isGlutenFree: boolean
  glutenSources: string[]
}) => `Explain why this recipe is${isGlutenFree ? '' : ' not'} gluten-free.

${glutenSources.length > 0 ? `Sources of gluten: ${glutenSources.join(', ')}` : 'No gluten-containing ingredients found'}

Return your response in this format:
"This recipe is [gluten-free/contains gluten] because [explanation]"`

export const glutenCheckerScorer = createScorer({
  id: 'gluten-checker',
  description: 'Check if the output contains any gluten',
  judge: {
    model: '__GATEWAY_OPENAI_MODEL_LUNA__',
    instructions: GLUTEN_INSTRUCTIONS,
  },
})
  .analyze({
    description: 'Analyze the output for gluten',
    outputSchema: z.object({
      isGlutenFree: z.boolean(),
      glutenSources: z.array(z.string()),
    }),
    createPrompt: ({ run }) => {
      const { output } = run
      return generateGlutenPrompt({ output: output.text })
    },
  })
  .generateScore(({ results }) => {
    return results.analyzeStepResult.isGlutenFree ? 1 : 0
  })
  .generateReason({
    description: 'Generate a reason for the score',
    createPrompt: ({ results }) => {
      return generateReasonPrompt({
        glutenSources: results.analyzeStepResult.glutenSources,
        isGlutenFree: results.analyzeStepResult.isGlutenFree,
      })
    },
  })
```

### 判斷配置 {/* #judge-configuration */}

設定 LLM 模型並定義其作為領域專家的角色。

```typescript oxfmt:false
judge: {
  model: '__GATEWAY_OPENAI_MODEL_LUNA__',
  instructions: GLUTEN_INSTRUCTIONS,
}
```

### 分析步驟 {/* #analysis-step */}

定義法學碩士應如何分析輸入以及返回什麼結構化輸出。

```typescript oxfmt:false
.analyze({
  description: 'Analyze the output for gluten',
  outputSchema: z.object({
    isGlutenFree: z.boolean(),
    glutenSources: z.array(z.string()),
  }),
  createPrompt: ({ run }) => {
    const { output } = run;
    return generateGlutenPrompt({ output: output.text });
  },
})
```

分析步驟使用提示物件來：

* 提供分析任務的清晰描述
* 使用標準 JSON 模式定義預期的輸出結構（布林結果和麩質源列表）
* 根據輸入內容產生運行時提示

### 分數生成 {/* #score-generation */}

將法學碩士的結構化分析轉換為數字分數。

```typescript oxfmt:false
.generateScore(({ results }) => {
  return results.analyzeStepResult.isGlutenFree ? 1 : 0;
})
```

分數產生功能可取得分析結果並應用業務邏輯來產生分數。在這種情況下，法學碩士直接確定食譜是否不含麩質，因此我們使用該布林結果：1 表示不含麩質，0 表示含有麩質。

### 理性生成 {/* #reason-generation */}

使用另一個 LLM 呼叫為分數提供人類可讀的解釋。

```typescript oxfmt:false
.generateReason({
  description: 'Generate a reason for the score',
  createPrompt: ({ results }) => {
    return generateReasonPrompt({
      glutenSources: results.analyzeStepResult.glutenSources,
      isGlutenFree: results.analyzeStepResult.isGlutenFree,
    });
  },
})
```

原因生成步驟使用布林結果和分析步驟識別的特定麩質來源來建立解釋，幫助使用者理解分配分數的原因。
