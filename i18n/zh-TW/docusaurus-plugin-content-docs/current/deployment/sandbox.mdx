# Sandbox

`@mastra/deployer-sandbox`將完整的 Mastra 伺服器（包括 Studio）部署到臨時Workspace沙箱中，並傳回即時公共 URL。重複部署可以更快完成，因為部署程式會跳過依賴項安裝。

使用Sandbox部署用於：

* Agent程式建置的應用程式：Agent程式產生 Mastra 專案並部署它以驗證結果。
* 持續整合 (CI)：啟動真實伺服器進行檢查，然後將其拆除。
* 即時預覽：在合併之前與您的團隊共用工作Agent程式。
* 多租用戶不受信任代碼：執行與基礎設施隔離的每位使用者 Mastra 實例。

沙箱具有Provider強制執行的運行時間上限並會過期。有關生產託管，請參閱[deployment overview](/docs/deployment/overview).

## 支持的沙箱 {/* #supported-sandboxes */}

部署程式可與任何支援網路（公用連接埠 URL）的Workspace沙箱搭配使用：

* [維塞爾沙箱](/integrations/sandboxes/vercel#vercel-sandbox) (`@mastra/vercel`)
* [E2B](/integrations/sandboxes/e2b) (`@mastra/e2b`)
* [代托納](/integrations/sandboxes/daytona) (`@mastra/daytona`)

`networking` capability on [`WorkspaceSandbox`](/reference/workspace/sandbox).

## 快速入門 {/* #quickstart */}

安裝您選擇的部署程式和沙箱Provider。此範例使用 Vercel 沙箱：

```bash npm2yarn
npm install @mastra/deployer-sandbox @mastra/vercel
```

在您的配置中配置部署程序`src/mastra/index.ts` file. The `sandboxName` identifies the deployment, so subsequent deployments with the same name reuse the existing sandbox.

```typescript title="src/mastra/index.ts"
import { Mastra } from '@mastra/core/mastra'
import { SandboxDeployer } from '@mastra/deployer-sandbox'
import { VercelSandbox } from '@mastra/vercel'

export const mastra = new Mastra({
  deployer: new SandboxDeployer({
    sandbox: new VercelSandbox({
      sandboxName: 'my-preview',
      timeout: 2_400_000, // 40 minutes
      ports: [4111],
    }),
  }),
})
```

Vercel 有兩個附加要求：

* `timeout`不能超過您的計劃的最大Sandbox生命週期，Pro 版為 45 分鐘。較高的值會使部署失敗，並顯示 Vercel API 的 400。
* 聲明伺服器連接埠`ports`. Vercel exposes only ports declared at creation, unlike E2B and Daytona.

在一個命令中建置和部署：

```bash
mastra build
```

當一個`SandboxDeployer()` is configured, `mastra build` bundles your project and deploys it into the sandbox. The deploy prints the API and Studio URLs and writes a `sandbox-deployment.json` manifest into `.mastra/output`:

```text
API:    https://<sandbox-id>-4111.vercel.run/api
Studio: https://<sandbox-id>-4111.vercel.run
```

清單包括`expiresAt` when the sandbox provider reports an expiration time.

當輸入未變更時，重新部署到同一沙箱，跳過依賴項安裝。輸入哈希覆蓋`package.json` and the install command together with the bundled lockfiles.

### URL 提供什麼服務 {/* #what-the-urls-serve */}

`/api`. Open it in a browser to use Studio. When the deploy runs with `studio: false`, the root serves the Mastra welcome page instead.

API URL只是其下面端點的前綴，例如`/api/agents`. `/api` has no handler of its own, so opening it in a browser returns a "Not Found" response even though the server is healthy.

若要檢查部署，請直接呼叫端點：

```bash
curl -s -X POST https://4111-<sandbox-id>.e2b.app/api/agents/weatherAgent/generate \
  -H "Content-Type: application/json" \
  -d '{"messages":[{"role":"user","content":"Weather in London"}]}' | jq -r '.text'
```

### Provider憑證 {/* #provider-credentials */}

每個Provider都使用自己的憑證進行身份驗證。將您部署的沙箱設定為：

```bash title=".env"
# E2B
E2B_API_KEY=

# Daytona
DAYTONA_API_KEY=

# Vercel
VERCEL_TOKEN=
VERCEL_TEAM_ID=
VERCEL_PROJECT_ID=
```

每個Provider也接受這些作為建構函數選項。自託管 E2B 和 Daytona 安裝需要`E2B_DOMAIN` or `DAYTONA_API_URL`.

不像`mastra dev`, `mastra build` doesn't load `.env` files. The deploy happens inside the build, so a sandbox provider that reads its credentials from the environment, such as E2B with `E2B_API_KEY`, sees an empty value and the deploy fails with an authentication error.

添加`import 'dotenv/config'` to `src/mastra/index.ts` doesn't fix this. To find the deployer, the build extracts only the `deployer` option from your entry file and tree-shakes everything else away, including that import.

載入`.env` file into the shell environment before the build runs. [`dotenv-cli`](https://www.npmjs.com/package/dotenv-cli) is one way to do that:

```bash npm2yarn
npm install --save-dev dotenv-cli
```

```json title="package.json"
{
  "scripts": {
    "deploy": "dotenv -e .env -- mastra build"
  }
}
```

然後運行`npm run deploy`. The script is named for what it does, since `mastra build` deploys once a `SandboxDeployer()` is configured. Keep it separate from a plain `build` script so a hosting platform or CI job that runs `npm run build` doesn't deploy a sandbox by accident.

在持續整合 (CI) 中，請將憑證匯出為機密。無論使用什麼機制，變數都必須存在於 shell 環境中，而不僅僅是存在於`.env` file.

這適用於部署者在您的電腦上所需的憑證。部署的伺服器需要的變數是單獨處理的：部署者讀取`.env`, `.env.production`, and `.env.local` and injects them into the sandbox. See [Security](#security).

### 使用E2B {/* #using-e2b */}

對 E2B 來說，`id` identifies the deployment, so subsequent deployments with the same value reconnect to the existing sandbox, whether it's running or paused.

```typescript title="src/mastra/index.ts"
import { SandboxDeployer } from '@mastra/deployer-sandbox'
import { E2BSandbox } from '@mastra/e2b'

const deployer = new SandboxDeployer({
  sandbox: new E2BSandbox({
    id: 'my-preview',
    template: 'base',
    timeout: 3_600_000, // 1 hour
  }),
})
```

經過`template: 'base'` unless you need filesystem mounts; without it, the provider builds a custom Filesystem in Userspace (FUSE) template on first use. E2B pauses instead of stopping: `stop()` snapshots the whole virtual machine (VM), including memory and running processes. When a paused sandbox wakes, the Mastra server resumes where it left off, and there's no relaunch step like on Vercel.

### 使用代托納 {/* #using-daytona */}

對代托納來說，`id` identifies the deployment, so subsequent deployments with the same value reconnect to the existing sandbox. Set `public: true` to make the preview URL accessible without a token.

```typescript title="src/mastra/index.ts"
import { SandboxDeployer } from '@mastra/deployer-sandbox'
import { DaytonaSandbox } from '@mastra/daytona'

const deployer = new SandboxDeployer({
  sandbox: new DaytonaSandbox({
    id: 'my-preview',
    public: true,
    autoStopInterval: 30, // minutes
  }),
})
```

停止 Daytona 沙箱會保留其檔案系統，但不會保留正在執行的進程，因此喚醒的工作方式與 Vercel 類似：解析器會重新啟動伺服器`wake: true`.

代托納過濾每個目的地的出站流量。對某些主機的請求通常透過傳輸層安全性 (TLS) 連接，而其他主機則在握手期間重置，這在Agent或Tool中作為 Node 的通用出現`fetch failed`. Rule out your code before debugging it, by running `curl` against the same host from inside the sandbox:

```typescript
const sandbox = new DaytonaSandbox({ id: 'my-preview' })
await sandbox.start()

const result = await sandbox.executeCommand('curl -v --max-time 10 https://api.example.com')
console.info(result.stdout, result.stderr)
```

一個`Connection reset by peer` during the TLS handshake points at the filtering rather than your agent. Ask Daytona support to allow the destination. Restricted Daytona tiers also block cloud storage endpoints, which the mount helpers report with a dedicated error.

## 以程式設計方式部署 {/* #deploying-programmatically */}

`deployToSandbox()`在沒有捆綁器的情況下部署預先建置的輸出目錄。不像`SandboxDeployer()`, it doesn't include Studio unless you pass `studio: true`. Use it in CI or from agent code:

```typescript
import { deployToSandbox } from '@mastra/deployer-sandbox'
import { VercelSandbox } from '@mastra/vercel'

const deployment = await deployToSandbox({
  sandbox: new VercelSandbox({ sandboxName: 'ci-smoke', ports: [4111] }),
  dir: '.mastra/output',
})

console.info(deployment.url) // https://<sandbox-id>-4111.vercel.run
await deployment.logs() // tail the server log
await deployment.stop() // stop the sandbox (resumable)
await deployment.destroy() // permanently delete the sandbox
```

## 生命週期 {/* #lifecycle */}

### 管理部署 {/* #managing-a-deployment */}

僅使用伺服器`getDeployment()` export from `@mastra/deployer-sandbox/client` to retrieve an existing deployment. It identifies the sandbox through provider-specific configuration, such as a Vercel `sandboxName` or an E2B or Daytona `id`. The lookup isn't tied to the process that created the deployment, so you can use it from another server-side service or in CI.

```typescript title="scripts/stop.ts"
import { getDeployment } from '@mastra/deployer-sandbox/client'
import { VercelSandbox } from '@mastra/vercel'

const deployment = await getDeployment({
  sandbox: new VercelSandbox({ sandboxName: 'my-preview', ports: [4111] }),
  port: 4111,
})

console.info(deployment.status, deployment.url)
await deployment.logs() // tail the server log
await deployment.stop() // stop the sandbox (resumable)
await deployment.destroy() // permanently delete the sandbox
```

經過`wake: true` to resume a stopped sandbox before returning. The server is relaunched only if it isn't healthy after the resume. Provider tooling works too, for example `vercel sandbox ls`, `vercel sandbox stop`, and `vercel sandbox rm`.

### 過期時間和 URL {/* #expiry-and-urls */}

沙箱根據Provider的運行時間限製到期。當Provider報告過期時間時，部署會記錄它並`deployment.expiresAt` exposes it programmatically.

當沙箱停止和恢復時，沙箱 URL 可能會發生變化。將 URL 視為管道和沙箱身分（例如，`sandboxName`) as the stable handle. The routing tiers below deal with URL rotation.

## 路由層 {/* #routing-tiers */}

### 第 1 層：直接 URL {/* #tier-1-direct-url */}

直接使用列印的 URL 進行開發、演示和 CI，其中每次部署都可以使用新的 URL。

### 第 2 層：運行時解析 {/* #tier-2-resolve-at-runtime */}

`getDeployment()`在運行時解析當前 URL，因此消費者永遠不會持有過時的 URL。任何知道沙箱名稱的伺服器都可以解析它，包括與 Mastra 專案不同的程式碼庫中的伺服器：

```typescript title="app/api/agent-url/route.ts"
import { getDeployment } from '@mastra/deployer-sandbox/client'
import { VercelSandbox } from '@mastra/vercel'

const deployment = await getDeployment({
  sandbox: new VercelSandbox({ sandboxName: 'my-preview', ports: [4111] }),
  wake: true,
})

console.info(deployment.url, deployment.status)
```

和`wake: false` (the default) the sandbox isn't started and you get `{ url, status }` to act on. Resolving the URL, `stop()`, and `destroy()` attach to the existing sandbox by name without resuming it, so lifecycle operations on a stopped sandbox never wake it or start billing. With `wake: true` the sandbox resumes and the server is relaunched if it isn't answering. Whether a relaunch is needed depends on the provider: Vercel and Daytona restore the filesystem but not running processes, while E2B resumes the whole VM including the server process.

：：：警告

`@mastra/deployer-sandbox/client`僅限伺服器。解析沙箱所使用的Provider憑證絕對不能到達瀏覽器。如果在瀏覽器上下文中匯入該模組，則會拋出異常。

:::

### 第 3 層：最終使用者的穩定 URL {/* #tier-3-stable-url-for-end-users */}

使用路由處理程序Agent程式或 Edge Config 別名，為最終用戶提供您自己網域上的穩定 URL 並轉送到沙箱伺服器端。

下面的範例顯示了 Vercel 和 Next.js 設置，但該概念適用於任何可以轉發請求的伺服器端框架或Provider。

* **路由處理程序Agent程式。** `createSandboxHandler()` caches the sandbox URL and re-resolves after a connection-level failure, which covers URL rotation and cold wakes:

  ```typescript title="app/api/[...path]/route.ts"
  import { createSandboxHandler, getDeployment } from '@mastra/deployer-sandbox/client'
  import { VercelSandbox } from '@mastra/vercel'

  const handler = createSandboxHandler({
    resolve: async () => {
      const deployment = await getDeployment({
        sandbox: new VercelSandbox({ sandboxName: 'my-preview', ports: [4111] }),
        wake: true,
      })
      return deployment.url!
    },
  })

  export { handler as GET, handler as POST }
  ```

* **邊緣配置別名。**&#x8A2D;定`alias` option on the deployer to keep a [Vercel Edge Config](https://vercel.com/docs/edge-config) item pointed at the current URL on every deploy:

  ```typescript title="src/mastra/index.ts"
  const deployer = new SandboxDeployer({
    sandbox: new VercelSandbox({ sandboxName: 'my-preview', ports: [4111] }),
    alias: { edgeConfigId: 'ecfg_...', key: 'my-preview', token: process.env.VERCEL_TOKEN! },
  })
  ```

  然後在 Next.js 中間件中重寫請求`createSandboxProxy()`:

  ```typescript title="middleware.ts"
  import { createSandboxProxy } from '@mastra/deployer-sandbox/client'

  export const middleware = createSandboxProxy({ key: 'my-preview' })
  export const config = { matcher: '/api/:path*' }
  ```

## 持續集成範例 {/* #ci-example */}

在每個拉取請求上部署預覽：

```yaml title=".github/workflows/preview.yml"
name: Sandbox preview
on: pull_request

jobs:
  preview:
    runs-on: ubuntu-latest
    env:
      VERCEL_TOKEN: ${{ secrets.VERCEL_TOKEN }}
      VERCEL_TEAM_ID: ${{ secrets.VERCEL_TEAM_ID }}
      VERCEL_PROJECT_ID: ${{ secrets.VERCEL_PROJECT_ID }}
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-node@v4
        with:
          node-version: 22
      - run: npm ci
      - run: npx mastra build
      - run: curl --fail "$(jq -r .url .mastra/output/sandbox-deployment.json)/api"
```

## 安全 {/* #security */}

* 沙箱 URL 是公開的。知道該 URL 的任何人都可以存取您的 Mastra 伺服器，包括 Studio。使能夠[server auth](/docs/auth/overview) for anything beyond throwaway previews.
* 來自您的環境變數`.env` files are injected into the remote sandbox VM so the server can run. The deploy logs a warning when this happens. Don't deploy secrets you wouldn't put on a shared preview server.
* 若要限制對第 3 層流量的訪問，請傳遞`secret` to `createSandboxHandler()` or `createSandboxProxy()`. These helpers attach the value to forwarded requests in the `x-mastra-sandbox-secret` header. Configure [server auth](/docs/auth/overview) to require the header so direct requests to the sandbox URL are rejected while traffic through your domain continues to work.
