# Sandbox

`@mastra/deployer-sandbox` 會將包含 Studio 的完整 Mastra 伺服器，部署到暫時性的 Workspace Sandbox，並回傳可使用的公開 URL。再次部署時，部署器可略過相依套件安裝，因此可能更快完成。

Sandbox 部署適用於：

- Agent 建立的應用程式：由 Agent 產生並部署 Mastra 專案，驗證產生的結果。
- 持續整合 (CI)：啟動實際伺服器進行檢查，完成後再移除。
- 即時預覽：合併前與團隊分享可運作的 Agent。
- 多租戶不受信任的程式碼：為每位使用者執行與自身基礎設施隔離的 Mastra 執行個體。

Sandbox 有由 Provider 強制執行的執行時間上限，也會過期。正式環境託管方式請參閱[部署概覽](/docs/deployment/overview)。

## 支援的 Sandbox {/* #supported-sandboxes */}

部署器適用於任何支援網路連線能力（公開連接埠 URL）的 Workspace Sandbox：

* [Vercel Sandbox](/integrations/sandboxes/vercel#vercel-sandbox) (`@mastra/vercel`)
* [E2B](/integrations/sandboxes/e2b) (`@mastra/e2b`)
* [Daytona](/integrations/sandboxes/daytona) (`@mastra/daytona`)

Provider 開發者可在 [`WorkspaceSandbox`](/reference/workspace/sandbox) 實作選用的 `networking` 功能，以加入支援。

## 快速入門 {/* #quickstart */}

安裝部署器及選用的 Sandbox Provider。以下以 Vercel Sandbox 為例：

```bash npm2yarn
npm install @mastra/deployer-sandbox @mastra/vercel
```

在 `src/mastra/index.ts` 中設定部署器。`sandboxName` 用來識別部署，後續使用相同名稱部署時，會重複使用現有的 Sandbox。

```typescript title="src/mastra/index.ts"
import { Mastra } from '@mastra/core/mastra'
import { SandboxDeployer } from '@mastra/deployer-sandbox'
import { VercelSandbox } from '@mastra/vercel'

export const mastra = new Mastra({
  deployer: new SandboxDeployer({
    sandbox: new VercelSandbox({
      sandboxName: 'my-preview',
      timeout: 2_400_000, // 40 minutes
      ports: [4111],
    }),
  }),
})
```

Vercel 有兩個附加要求：

- `timeout` 不能超過方案允許的 Sandbox 最長存續時間；Pro 方案為 45 分鐘。若設定更長時間，Vercel API 會回傳 400，導致部署失敗。
- 在 `ports` 中宣告伺服器連接埠。與 E2B、Daytona 不同，Vercel 只會開放建立時宣告的連接埠。

在一個命令中建置和部署：

```bash
mastra build
```

設定 `SandboxDeployer()` 後，`mastra build` 會封裝專案並部署至 Sandbox。部署時會顯示 API 和 Studio URL，並在 `.mastra/output` 寫入 `sandbox-deployment.json` 資訊清單：

```text
API:    https://<sandbox-id>-4111.vercel.run/api
Studio: https://<sandbox-id>-4111.vercel.run
```

若 Sandbox Provider 回報到期時間，資訊清單會包含 `expiresAt`。

重新部署到同一 Sandbox 時，若輸入未變，便會略過相依套件安裝。輸入雜湊涵蓋 `package.json`、安裝指令及封裝的鎖定檔。

### 這些 URL 提供的服務 {/* #what-the-urls-serve */}

Studio URL 是 Sandbox 根網址，不含 `/api`。在瀏覽器開啟即可使用 Studio。若部署時設定 `studio: false`，根網址會改為顯示 Mastra 歡迎頁面。

API URL 只是下層端點的前綴，例如 `/api/agents`。`/api` 本身沒有處理程式，因此即使伺服器運作正常，在瀏覽器開啟它仍會回傳「Not Found」。

若要檢查部署，請直接呼叫端點：

```bash
curl -s -X POST https://4111-<sandbox-id>.e2b.app/api/agents/weatherAgent/generate \
  -H "Content-Type: application/json" \
  -d '{"messages":[{"role":"user","content":"Weather in London"}]}' | jq -r '.text'
```

### Provider 憑證 {/* #provider-credentials */}

各 Provider 使用自己的憑證進行驗證。請設定部署目標 Sandbox 所需的憑證：

```bash title=".env"
# E2B
E2B_API_KEY=

# Daytona
DAYTONA_API_KEY=

# Vercel
VERCEL_TOKEN=
VERCEL_TEAM_ID=
VERCEL_PROJECT_ID=
```

各 Provider 也接受透過建構函式選項傳入這些憑證。自行託管的 E2B 和 Daytona 安裝分別使用 `E2B_DOMAIN` 或 `DAYTONA_API_URL`。

與 `mastra dev` 不同，`mastra build` 不會載入 `.env` 檔案。部署在建置過程中執行，因此從環境讀取憑證的 Sandbox Provider，例如使用 `E2B_API_KEY` 的 E2B，會讀到空值，並因驗證錯誤而部署失敗。

在 `src/mastra/index.ts` 加入 `import 'dotenv/config'` 無法解決問題。建置程序為了找出部署器，只會從進入點檔案擷取 `deployer` 選項，並透過 tree shaking 移除其他內容，包括該匯入。

建置前先將 `.env` 檔案載入 shell 環境。可以使用 [`dotenv-cli`](https://www.npmjs.com/package/dotenv-cli)：

```bash npm2yarn
npm install --save-dev dotenv-cli
```

```json title="package.json"
{
  "scripts": {
    "deploy": "dotenv -e .env -- mastra build"
  }
}
```

接著執行 `npm run deploy`。腳本名稱應反映它會部署，因為設定 `SandboxDeployer()` 後，`mastra build` 就會執行部署。請與一般的 `build` 腳本分開，以免託管平台或 CI 工作執行 `npm run build` 時意外部署 Sandbox。

在持續整合 (CI) 中，請改以 secret 匯出憑證。不論使用哪種方式，變數都必須存在於 shell 環境，不能只存放在 `.env` 檔案中。

上述規定適用於部署器在本機需要的憑證。已部署伺服器所需的變數則分開處理：部署器會讀取 `.env`、`.env.production` 和 `.env.local`，並將變數注入 Sandbox。請參閱[安全性](#security)。

### 使用E2B {/* #using-e2b */}

對 E2B 而言，`id` 用來識別部署。後續使用相同值部署，會重新連線至現有 Sandbox，不論它正在執行或已暫停。

```typescript title="src/mastra/index.ts"
import { SandboxDeployer } from '@mastra/deployer-sandbox'
import { E2BSandbox } from '@mastra/e2b'

const deployer = new SandboxDeployer({
  sandbox: new E2BSandbox({
    id: 'my-preview',
    template: 'base',
    timeout: 3_600_000, // 1 hour
  }),
})
```

除非需要掛載檔案系統，否則請傳入 `template: 'base'`；若未傳入，Provider 首次使用時會建立自訂的 Filesystem in Userspace (FUSE) 範本。E2B 會暫停而非停止：`stop()` 會為整部虛擬機器 (VM) 建立快照，包括記憶體和執行中的程序。暫停的 Sandbox 喚醒後，Mastra 伺服器會從原處繼續，不需要像 Vercel 一樣重新啟動。

### 使用 Daytona {/* #using-daytona */}

對 Daytona 而言，`id` 用來識別部署。後續使用相同值部署，會重新連線至現有 Sandbox。設定 `public: true`，可讓預覽 URL 不需權杖即可存取。

```typescript title="src/mastra/index.ts"
import { SandboxDeployer } from '@mastra/deployer-sandbox'
import { DaytonaSandbox } from '@mastra/daytona'

const deployer = new SandboxDeployer({
  sandbox: new DaytonaSandbox({
    id: 'my-preview',
    public: true,
    autoStopInterval: 30, // minutes
  }),
})
```

Daytona Sandbox 停止後會保留檔案系統，但不保留執行中的程序，因此喚醒方式與 Vercel 類似：使用 `wake: true` 時，解析器會重新啟動伺服器。

Daytona 依目的地篩選對外流量。某些主機的傳輸層安全協定 (TLS) 連線正常，另一些則在交握時被重設；Agent 或工具中只會顯示 Node 的一般錯誤 `fetch failed`。在除錯程式碼前，先從 Sandbox 內對同一主機執行 `curl`，確認是否為連線問題：

```typescript
const sandbox = new DaytonaSandbox({ id: 'my-preview' })
await sandbox.start()

const result = await sandbox.executeCommand('curl -v --max-time 10 https://api.example.com')
console.info(result.stdout, result.stderr)
```

TLS 交握時出現 `Connection reset by peer`，表示問題可能是流量篩選，而非 Agent。請 Daytona 支援團隊開放該目的地。受限制的 Daytona 方案也會封鎖雲端儲存端點；掛載輔助函式會回報專屬錯誤。

## 以程式設計方式部署 {/* #deploying-programmatically */}

`deployToSandbox()` 不經過打包器，直接部署預先建置的輸出目錄。與 `SandboxDeployer()` 不同，只有傳入 `studio: true` 才會包含 Studio。可在 CI 或 Agent 程式碼中使用：

```typescript
import { deployToSandbox } from '@mastra/deployer-sandbox'
import { VercelSandbox } from '@mastra/vercel'

const deployment = await deployToSandbox({
  sandbox: new VercelSandbox({ sandboxName: 'ci-smoke', ports: [4111] }),
  dir: '.mastra/output',
})

console.info(deployment.url) // https://<sandbox-id>-4111.vercel.run
await deployment.logs() // tail the server log
await deployment.stop() // stop the sandbox (resumable)
await deployment.destroy() // permanently delete the sandbox
```

## 生命週期 {/* #lifecycle */}

### 管理部署 {/* #managing-a-deployment */}

使用 `@mastra/deployer-sandbox/client` 匯出的伺服器端專用 `getDeployment()`，取得現有部署。它依 Provider 專屬設定識別 Sandbox，例如 Vercel 的 `sandboxName`，或 E2B、Daytona 的 `id`。查詢不受建立部署的程序限制，也能從其他伺服器端服務或 CI 使用。

```typescript title="scripts/stop.ts"
import { getDeployment } from '@mastra/deployer-sandbox/client'
import { VercelSandbox } from '@mastra/vercel'

const deployment = await getDeployment({
  sandbox: new VercelSandbox({ sandboxName: 'my-preview', ports: [4111] }),
  port: 4111,
})

console.info(deployment.status, deployment.url)
await deployment.logs() // tail the server log
await deployment.stop() // stop the sandbox (resumable)
await deployment.destroy() // permanently delete the sandbox
```

傳入 `wake: true`，即可在回傳前恢復已停止的 Sandbox。只有恢復後伺服器狀態不正常時，才會重新啟動。也可使用 Provider 工具，例如 `vercel sandbox ls`、`vercel sandbox stop` 和 `vercel sandbox rm`。

### 過期時間和 URL {/* #expiry-and-urls */}

Sandbox 會依 Provider 的執行時間限制到期。若 Provider 回報到期時間，部署日誌會記錄，也可透過 `deployment.expiresAt` 在程式中讀取。

Sandbox 停止後再恢復，URL 可能改變。URL 只是連線位址；Sandbox 識別資訊（例如 `sandboxName`）才是穩定的操作依據。以下路由層級用來處理 URL 輪替。

## 路由層 {/* #routing-tiers */}

### 第 1 層：直接 URL {/* #tier-1-direct-url */}

直接使用列印的 URL 進行開發、演示和 CI，其中每次部署都可以使用新的 URL。

### 第 2 層：運行時解析 {/* #tier-2-resolve-at-runtime */}

`getDeployment()` 會在執行階段解析目前的 URL，讓使用端不必保存可能失效的 URL。任何知道 Sandbox 名稱的伺服器都能解析，即使它位於另一個程式碼庫：

```typescript title="app/api/agent-url/route.ts"
import { getDeployment } from '@mastra/deployer-sandbox/client'
import { VercelSandbox } from '@mastra/vercel'

const deployment = await getDeployment({
  sandbox: new VercelSandbox({ sandboxName: 'my-preview', ports: [4111] }),
  wake: true,
})

console.info(deployment.url, deployment.status)
```

使用預設的 `wake: false` 時，不會啟動 Sandbox，只會取得可供後續處理的 `{ url, status }`。解析 URL、`stop()` 及 `destroy()` 會依名稱連結現有 Sandbox，但不會恢復它；因此對已停止 Sandbox 執行生命週期操作，不會將它喚醒或開始計費。使用 `wake: true` 時，Sandbox 會恢復；若伺服器沒有回應，便會重新啟動。是否需要重啟取決於 Provider：Vercel 和 Daytona 只恢復檔案系統，不恢復執行中的程序；E2B 則恢復包含伺服器程序的整部 VM。

:::warning

`@mastra/deployer-sandbox/client` 僅供伺服器端使用。解析 Sandbox 需要 Provider 憑證，絕不能傳到瀏覽器。在瀏覽器環境匯入此模組會擲出錯誤。

:::

### 第 3 層：最終使用者的穩定 URL {/* #tier-3-stable-url-for-end-users */}

在自己的網域上提供固定 URL 給終端使用者，再透過路由處理常式 Proxy 或 Edge Config 別名，於伺服器端轉送要求至 Sandbox。

下面的範例顯示了 Vercel 和 Next.js 設置，但該概念適用於任何可以轉發請求的伺服器端框架或Provider。

- **路由處理常式 Proxy。** `createSandboxHandler()` 會快取 Sandbox URL，並在連線層級失敗後重新解析，以處理 URL 輪替及冷啟喚醒：

  ```typescript title="app/api/[...path]/route.ts"
  import { createSandboxHandler, getDeployment } from '@mastra/deployer-sandbox/client'
  import { VercelSandbox } from '@mastra/vercel'

  const handler = createSandboxHandler({
    resolve: async () => {
      const deployment = await getDeployment({
        sandbox: new VercelSandbox({ sandboxName: 'my-preview', ports: [4111] }),
        wake: true,
      })
      return deployment.url!
    },
  })

  export { handler as GET, handler as POST }
  ```

- **Edge Config 別名。** 在部署器設定 `alias` 選項，讓 [Vercel Edge Config](https://vercel.com/docs/edge-config) 項目在每次部署後指向目前的 URL：

  ```typescript title="src/mastra/index.ts"
  const deployer = new SandboxDeployer({
    sandbox: new VercelSandbox({ sandboxName: 'my-preview', ports: [4111] }),
    alias: { edgeConfigId: 'ecfg_...', key: 'my-preview', token: process.env.VERCEL_TOKEN! },
  })
  ```

  接著在 Next.js 中介軟體使用 `createSandboxProxy()` 改寫要求：

  ```typescript title="middleware.ts"
  import { createSandboxProxy } from '@mastra/deployer-sandbox/client'

  export const middleware = createSandboxProxy({ key: 'my-preview' })
  export const config = { matcher: '/api/:path*' }
  ```

## 持續集成範例 {/* #ci-example */}

在每個拉取請求上部署預覽：

```yaml title=".github/workflows/preview.yml"
name: Sandbox preview
on: pull_request

jobs:
  preview:
    runs-on: ubuntu-latest
    env:
      VERCEL_TOKEN: ${{ secrets.VERCEL_TOKEN }}
      VERCEL_TEAM_ID: ${{ secrets.VERCEL_TEAM_ID }}
      VERCEL_PROJECT_ID: ${{ secrets.VERCEL_PROJECT_ID }}
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-node@v4
        with:
          node-version: 22
      - run: npm ci
      - run: npx mastra build
      - run: curl --fail "$(jq -r .url .mastra/output/sandbox-deployment.json)/api"
```

## 安全 {/* #security */}

- Sandbox URL 是公開的。任何知道 URL 的人都能存取 Mastra 伺服器，包括 Studio。除了一次性的預覽環境，請啟用[伺服器驗證](/docs/auth/overview)。
- `.env` 檔案中的環境變數會注入遠端 Sandbox VM，供伺服器執行。部署時會為此輸出警告。不要部署不適合放在共用預覽伺服器上的機密。
- 若要限制第 3 層流量，請將 `secret` 傳給 `createSandboxHandler()` 或 `createSandboxProxy()`。這些輔助函式會把該值附加在轉送要求的 `x-mastra-sandbox-secret` 標頭。設定[伺服器驗證](/docs/auth/overview)以要求此標頭，便能拒絕直接連至 Sandbox URL 的要求，同時維持透過自有網域的存取。
