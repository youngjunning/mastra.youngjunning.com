# Monorepo

在 monorepo 中部署 Mastra 的流程和部署獨立應用程式相同。本指南說明 monorepo 特有的注意事項。基本的建置及部署步驟，請見[部署 Mastra 伺服器](/docs/deployment/mastra-server)。

## 支援的 monorepo 工具 {/* #supported-monorepos */}

Mastra 可搭配下列工具使用：

- npm 工作區
- pnpm 工作區
- Yarn 工作區
- Turborepo

已知限制：

- Bun 工作區：僅支援部分功能，仍有已知問題
- Nx：可採用 Nx [支援的相依性管理策略](https://nx.dev/concepts/decisions/dependency-management)，但各工作區套件內都必須有 `package.json`

## 目錄結構範例 {/* #example-structure */}

在這個範例中，Mastra 應用程式位於 `apps/api`：

```text
apps/
├── api/
│   ├── src/
│   │   └── mastra/
│   │       ├── agents/
│   │       ├── tools/
│   │       ├── workflows/
│   │       └── index.ts
│   ├── package.json
│   └── tsconfig.json
└── web/
packages/
├── ui/
└── utils/
package.json
```

## 從 monorepo 建置 {/* #building-from-a-monorepo */}

使用 monorepo 工具在正確的套件執行建置指令，不必加上特殊旗標。

範例如下：

<Tabs>
  <TabItem value="npm" label="npm">
    ```bash
    npm run build --workspace=apps/api
    ```
  </TabItem>

  <TabItem value="pnpm" label="pnpm">
    ```bash
    pnpm --filter api run build
    ```
  </TabItem>

  <TabItem value="yarn" label="yarn">
    ```bash
    yarn workspace api build
    ```
  </TabItem>

  <TabItem value="turborepo" label="Turborepo">
    ```bash
    turbo run build --filter=api
    ```
  </TabItem>
</Tabs>

套件的 `build` 指令碼應執行 `mastra build`：

```json title="apps/api/package.json"
{
  "scripts": {
    "build": "mastra build"
  }
}
```

## 工作區套件 {/* #workspace-packages */}

Mastra 應用程式從其他工作區套件匯入內容時，Mastra 會自動處理：

- 如果套件已先編譯（例如以 `tsc` 或 `tsdown` 建置），Mastra 會匯入編譯後的 JavaScript
- 如果套件含有未編譯的 TypeScript，Mastra 會在建置時轉譯

大多數情況下無須額外設定。若匯入工作區套件時遇到問題，請將該套件加到 [`transpilePackages`](/reference/configuration#bundlertranspilepackages)：

```typescript title="src/mastra/index.ts"
import { Mastra } from '@mastra/core'

export const mastra = new Mastra({
  bundler: {
    transpilePackages: ['@my-org/utils'],
  },
})
```

讓 `bundler` 直接位於傳給 `new Mastra()` 的物件中。支援的進入點檔案格式請見[建置階段設定](/docs/deployment/mastra-server#build-time-configuration)。

## 環境變數 {/* #environment-variables */}

請把 `.env` 檔放在 Mastra 應用程式的目錄內（例如 `apps/api/.env`），不要放在 monorepo 根目錄。

## 部署設定 {/* #deployment-configuration */}

部署到雲端服務時，請選擇正確的套件作為部署目標。常見的錯誤是選到 monorepo 根目錄，而非應用程式的目錄（例如 `apps/api`）。

大多數服務可在管理介面或設定檔中指定根目錄。

## 相依性管理 {/* #dependency-management */}

讓相依套件保持一致，可避免版本衝突及建置錯誤：

- 在 monorepo 根目錄使用**單一鎖定檔**，讓所有套件解析到相同的版本
- 統一 **共用程式庫**（例如 Mastra 或應用程式框架）的版本，避免重複

### 略過安裝相依套件 {/* #skipping-dependency-installation */}

預設情況下，`mastra build` 會將套件管理工具的鎖定檔複製到 `.mastra/output`，再用一次套件管理操作更新鎖定檔並安裝相依套件。在 CI 中也會更新鎖定檔。若沒有原始鎖定檔，Mastra 會改用 npm 並產生 `package-lock.json`。Bazel 等隔離式建置系統會由外部提供 `node_modules`，並在無網路的沙箱中執行；在這種情況下，安裝相依套件既無必要，也會使建置失敗。

將 `MASTRA_BUILD_SKIP_INSTALL` 設為 `true` 或 `1`，即可略過鎖定檔更新與輸出目錄的相依套件安裝：

```bash
MASTRA_BUILD_SKIP_INSTALL=1 mastra build
```

啟用後，請自行在輸出目錄中提供 `node_modules`。

## 疑難排解 {/* #troubleshooting */}

### 找不到工作區套件 {/* #workspace-package-not-found */}

Mastra 無法解析工作區套件時，請確認：

- 該套件已列在 `package.json` 的相依項目中
- 鎖定檔已更新（例如執行 `pnpm install` 或 `npm install`）
- 該套件的 `main` 或 `exports` 欄位在其 `package.json` 中有效

### 工作區套件的 TypeScript 錯誤 {/* #typescript-errors-from-workspace-packages */}

如果未編譯的工作區套件發生型別錯誤，可採用下列任一做法：

- 先建置套件（建議採用此方式，可加快 Mastra 的建置速度）
- 將套件加入 Mastra 設定中的 [`transpilePackages`](/reference/configuration#bundlertranspilepackages)
