#

在 monorepo 中部署 Mastra 遵循與獨立應用程式相同的過程。本指南涵蓋了單一儲存庫特定的注意事項。有关核心构建和部署步骤，请参阅[Deploy a Mastra Server](/docs/deployment/mastra-server).

## 支援的單一倉庫 {/* #supported-monorepos */}

馬斯特拉適用於：

* npm Workspace
* pnpm Workspace
* 紗線Workspace
* 渦輪雷波

已知限制：

* Bun Workspace - 部分支援；已知問題
* Nx - 您可以使用 Nx[supported dependency strategies](https://nx.dev/concepts/decisions/dependency-management) but you need to have `package.json` files inside your workspace packages

## 結構範例 {/* #example-structure */}

在此範例中，Mastra 應用程式位於`apps/api`:

```text
apps/
├── api/
│   ├── src/
│   │   └── mastra/
│   │       ├── agents/
│   │       ├── tools/
│   │       ├── workflows/
│   │       └── index.ts
│   ├── package.json
│   └── tsconfig.json
└── web/
packages/
├── ui/
└── utils/
package.json
```

## Workspace包 {/* #workspace-packages */}

當您的 Mastra 應用程式從其他Workspace套件匯入時，Mastra 會自動處理此問題：

* 如果套件是預編譯的（例如，使用`tsc` or `tsdown`), Mastra imports the compiled JavaScript
* 如果套件包含未編譯的 TypeScript，Mastra 會在建置期間對其進行轉譯

[`transpilePackages`](/reference/configuration#bundlertranspilepackages):

```typescript title="src/mastra/index.ts"
import { Mastra } from '@mastra/core'

export const mastra = new Mastra({
  bundler: {
    transpilePackages: ['@my-org/utils'],
  },
})
```

保持`bundler` as a direct property in the object passed to `new Mastra()`. See [build-time configuration](/docs/deployment/mastra-server#build-time-configuration) for the supported entry-file shape.

## 環境變數 {/* #environment-variables */}

店鋪`.env` files in the Mastra application directory (e.g., `apps/api/.env`), not the monorepo root.

## 部署配置 {/* #deployment-configuration */}

部署到雲端Provider時，請確保選擇正確的套件作為部署目標。選擇 monorepo 根目錄而不是應用程式目錄（例如，`apps/api`) is a common mistake.

大多數Provider允許您在其儀表板或設定檔中指定根目錄。

## 依賴管理 {/* #dependency-management */}

保持依賴關係一致以避免版本衝突和建置錯誤：

* 使用一個**single lockfile** at the monorepo root so all packages resolve the same versions
* 對齊版本**shared libraries** (like Mastra or frameworks) to prevent duplicates

### 跳過依賴安裝 {/* #skipping-dependency-installation */}

預設情況下，`mastra build` copies your package manager's lockfile into `.mastra/output`, then updates the lockfile and installs dependencies in one package-manager operation. This update remains enabled in CI. If no source lockfile exists, Mastra uses npm and generates `package-lock.json`. Hermetic build systems (such as Bazel) supply `node_modules` externally and run in a network-less sandbox, where this install is both redundant and fatal.

放`MASTRA_BUILD_SKIP_INSTALL` to `true` or `1` to skip the lockfile update and output install:

```bash
MASTRA_BUILD_SKIP_INSTALL=1 mastra build
```

啟用後，您有責任提供`node_modules` in the output directory yourself.

## 故障排除 {/* #troubleshooting */}

### 找不到Workspace包 {/* #workspace-package-not-found */}

如果 Mastra 無法解析Workspace包，請確保：

* 該軟體包已列在您的`package.json` dependencies
* 您的鎖定檔案是最新的（`pnpm install`, `npm install`, etc.)
* 該包有一個有效的`main` or `exports` field in its `package.json`

### Workspace包中的 TypeScript 錯誤 {/* #typescript-errors-from-workspace-packages */}

如果您看到未編譯的Workspace套件中出現類型錯誤，請執行下列任一操作：

* 首先建置包（建議更快地建造 Mastra）
* 將包添加到[`transpilePackages`](/reference/configuration#bundlertranspilepackages) in your Mastra config
