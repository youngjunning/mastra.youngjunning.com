# 馬斯特拉伺服器

Mastra 將您的應用程式編譯為獨立的 Node.js 伺服器，該伺服器可以在支援 Node.js、Bun 或 Deno 的任何平台上運行。

：：：提示

本指南介紹如何部署由`mastra build`. If you need to integrate Mastra into an existing Express or Hono application, see [Server Adapters](/docs/server/server-adapters)反而。

:::

## 建立您的應用程式 {/* #building-your-application */}

從專案根目錄執行建置命令：

```bash
mastra build
```

這創建了一個`.mastra` directory containing your production-ready server. Read the [`mastra build`](/reference/cli/mastra#mastra-build) reference for all available flags.

## 建構輸出 {/* #build-output */}

建構後，Mastra 建立以下結構：

```text
.mastra/
├── .build/                # Intermediate build artifacts (module maps, analysis)
└── output/
    ├── index.mjs          # Server entry point
    ├── mastra.mjs         # Your bundled Mastra configuration
    ├── tools.mjs          # Aggregated tool exports
    ├── tools/             # Individual tool bundles
    ├── package.json       # Production dependencies
    ├── node_modules/      # Installed dependencies
    ├── .npmrc             # Copied from your project (if present)
    ├── <static assets>     # Contents of src/mastra/public, merged into the output root
    └── playground/        # Studio UI (if --studio flag used)
```

這`output` directory is self-contained. You can copy it to any server and run it directly.

:::警告\[不要將資料庫檔案儲存在`src/mastra/public`]

建構複製的內容`src/mastra/public` into `.mastra/output` and overwrites files with the same name. A SQLite database stored in `public` therefore ends up inside the build, and a URL such as `file:./mastra.db` resolves against the directory the server runs from. If that's the output directory, the server opens the copied database instead of the one you edit, and changes to it are lost on the next build. Keep database files outside `public`.

:::

## 運行伺服器 {/* #running-the-server */}

使用 Mastra CLI 啟動伺服器：

```bash
mastra start
```

或直接使用 Node.js 運行：

```bash
node .mastra/output/index.mjs
```

這`mastra start` command provides additional features:

* 從以下位置載入環境變量`.env.production` and `.env`
* 為遺失的模組提供有用的錯誤訊息
* 處理進程訊號以正常關閉

閱讀[`mastra start`](/reference/cli/mastra#mastra-start) reference for all available flags.

## 建置配置 {/* #build-configuration */}

### 建置時配置 {/* #build-time-configuration */}

馬斯特拉讀到`bundler`, `deployer`, and `server` options while it builds your application. Keep those options as direct properties of the object passed to `new Mastra()` so the build can extract them.

以下條目文件形狀有效：

```typescript title="src/mastra/index.ts"
import { Mastra } from '@mastra/core/mastra'

export const mastra = new Mastra({
  bundler: {
    externals: ['sharp'],
  },
  server: {
    port: 4111,
  },
})
```

每個選項的值可以來自變數、匯入或函數呼叫。選擇權本身必須保持為直接財產。不要將建置時選項隱藏在工廠呼叫或物件擴充後面：

```typescript title="src/mastra/index.ts"
import { Mastra } from '@mastra/core/mastra'

const options = {
  bundler: {
    externals: ['sharp'],
  },
}

// These patterns prevent Mastra from extracting `bundler` during the build.
export const mastra = new Mastra(createMastraOptions())
export const otherMastra = new Mastra({ ...options })
```

當 Mastra 無法提取選項時，它會使用該選項的預設建構行為。請參閱[configuration reference](/reference/configuration) for the available `bundler`, `deployer`, and `server` settings.

### 公用資料夾 {/* #public-folder */}

如果一個`public` folder exists in your Mastra directory (`src/mastra/public`), its contents are copied to the output directory during build. These files are served as static assets by the server.

### 馬斯特拉配置 {/* #mastra-configuration */}

建置過程尊重 Mastra 實例中的配置。有關 CORS、逾時和中間件等伺服器行為，請參閱[server overview](/docs/server/overview). For all available options, see the [configuration reference](/reference/configuration).

## 建構過程 {/* #build-process */}

建置遵循以下步驟：

1. **找到入口文件**：發現`index.ts` or `index.js` in your Mastra directory.
2. **發現Tool**：掃描匹配的Tool文件`{mastraDir}/tools/**/*.{js,ts}`, excluding test files.
3. **分析依賴關係**：確定要捆綁哪些軟體包與外部安裝哪些軟體包。
4. **捆綁程式碼**：使用帶有樹搖動和可選來源映射的 Rollup。
5. **產生伺服器**：建立一個基於 Hono 的 HTTP 伺服器`index.mjs`.
6. **安裝依賴項**：運行`npm install` in the output directory.
7. **複製資產**: 副本`public` folder and `.npmrc` if present.

## 環境變數 {/* #environment-variables */}

|變數|描述 |
| - | - |
|`PORT` | Server port (default: `4111`) |
| `MASTRA_STUDIO_PATH` | Path to Studio build directory (default: `./playground`) |
| `MASTRA_SKIP_DOTENV` | Skip loading `.env` files when set |
| `NODE_OPTIONS` | Node.js options (e.g., `--max-old-space-size=4096` for build memory issues) |

## 伺服器端點 {/* #server-endpoints */}

建置的伺服器公開用於健康檢查、Agent、Workflow等的端點：

|端點|描述 |
| - | - |
|`GET /health` | Health check endpoint, returns `200 OK` |
| `GET /api/openapi.json` | OpenAPI specification (if `server.build.openAPIDocs` is enabled). |
| `GET /swagger-ui` | Interactive API documentation (if `server.build.swaggerUI` is enabled) |

此列表並不詳盡。若要查看所有端點，請執行`mastra dev` and visit `http://localhost:4111/swagger-ui`.

若要新增您自己的端點，請參閱[Custom API Routes](/docs/server/custom-api-routes).

## 優雅關閉和滾動部署 {/* #graceful-shutdown-and-rolling-deploys */}

By default, the generated server handles`SIGINT` and `SIGTERM`. It stops accepting connections, waits up to [`server.drainTimeout`](/reference/configuration#serverdraintimeout) for active requests and streams, then runs `mastra.shutdown()`. Shutdown gives in-flight workflow runs (including durable agent runs) the same drain window to finish before workers and pub/sub subscriptions are torn down. A durable agent run still executing after the window stops and releases its claim on the run, so the next boot can recover it right away. The drain timeout defaults to 5 seconds. A second signal terminates the process immediately. See [`server.handleShutdownSignals`](/reference/configuration#serverhandleshutdownsignals) if you need to manage signals yourself.

關閉然後交還Agent執行緒運行進程仍然保持：

* 仍在執行的運行將被中止，因此它不會啟動進一步的步驟。從其他進程觀察該執行緒的用戶端會看到它結束，並且不會保存其部分回應。
* 等待Tool批准或暫停的運行將保持暫停狀態，並且可以從另一個進程恢復。來自仍在執行的相同步驟的Tool呼叫將首先中止，就像仍在執行的運行一樣。
* 線程租約會立即釋放，因此另一個進程可以在該線程上開始運行，而無需等待租約到期。釋放是盡力而為的：如果中止的運作沒有及時停止（例如，忽略中止的Tool呼叫），或者租約後端沒有應答或釋放失敗，則租約將保留直到到期。

在耗盡逾時後，處理運行返回最多可能需要大約 1.5 秒。

增加`drainTimeout` when your hosting platform's termination grace period can accommodate longer turns. The HTTP drain and the workflow drain run one after the other, so keep enough time for both, plus about 1.5 seconds to hand back thread runs, plus shutdown cleanup.

如果你打電話`mastra.shutdown()` yourself, pass `drainTimeout` to control how long it waits for in-flight workflow runs:

```typescript
await mastra.shutdown({ drainTimeout: 30_000 })
```

```typescript title="src/mastra/index.ts"
import { Mastra } from '@mastra/core/mastra'

export const mastra = new Mastra({
  server: {
    drainTimeout: 240_000,
  },
})
```

一個平原`agent.stream()` call can't resume after its server process exits. If a stream ends without its expected terminal event, treat the turn as interrupted and let the client retry or reconcile it. Use [durable agents](/docs/harness/durable-agents) when turns must survive process replacement. [Crash recovery](/docs/harness/durable-agents#crash-recovery) requires shared persistent run storage and [idempotent tools](/docs/harness/durable-agents#make-tools-safe-to-repeat). Replaying missed events after a restart also requires a shared persistent cache such as Redis because the default event cache is in-memory. Recovering from multiple replicas requires a storage adapter that supports run fencing or a PubSub backend whose lease every replica shares. See [multi-instance deployments](/docs/harness/durable-agents#multi-instance-deployments).

## 故障排除 {/* #troubleshooting */}

### 建置期間記憶體錯誤 {/* #memory-errors-during-build */}

如果你遇到`JavaScript heap out of memory` errors:

```bash
NODE_OPTIONS="--max-old-space-size=4096" mastra build
```
