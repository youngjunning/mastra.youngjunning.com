# Mastra 伺服器

Mastra 會將應用程式編譯成獨立的 Node.js 伺服器，可在任何支援 Node.js、Bun 或 Deno 的平台上執行。

:::tip

本指南說明如何部署 `mastra build` 產生的獨立伺服器。若要將 Mastra 整合至現有的 Express 或 Hono 應用程式，請參閱[伺服器轉接器](/docs/server/server-adapters)。

:::

## 建置應用程式 {/* #building-your-application */}

在專案根目錄執行建置指令：

```bash
mastra build
```

建置會建立 `.mastra` 目錄，內含可在正式環境使用的伺服器。所有可用旗標請參閱 [`mastra build` 參考文件](/reference/cli/mastra#mastra-build)。

## 建置輸出 {/* #build-output */}

建置完成後，Mastra 會產生以下目錄結構：

```text
.mastra/
├── .build/                # Intermediate build artifacts (module maps, analysis)
└── output/
    ├── index.mjs          # Server entry point
    ├── mastra.mjs         # Your bundled Mastra configuration
    ├── tools.mjs          # Aggregated tool exports
    ├── tools/             # Individual tool bundles
    ├── package.json       # Production dependencies
    ├── node_modules/      # Installed dependencies
    ├── .npmrc             # Copied from your project (if present)
    ├── <static assets>     # Contents of src/mastra/public, merged into the output root
    └── playground/        # Studio UI (if --studio flag used)
```

`output` 目錄包含執行所需的內容，可以複製到任何伺服器上直接執行。

:::warning[請將資料庫檔案放在 `src/mastra/public` 之外]

建置會把 `src/mastra/public` 的內容複製到 `.mastra/output`，並覆寫同名檔案。因此，放在 `public` 裡的 SQLite 資料庫會進入建置輸出。`file:./mastra.db` 這類 URL 會依伺服器啟動時所在的目錄解析。如果伺服器從輸出目錄執行，開啟的會是資料庫副本，對副本的變更將在下次建置時遺失。請將資料庫檔案放在 `public` 之外。

:::

## 執行伺服器 {/* #running-the-server */}

使用 Mastra CLI 啟動伺服器：

```bash
mastra start
```

也可以直接用 Node.js 執行：

```bash
node .mastra/output/index.mjs
```

`mastra start` 指令另有以下功能：

- 從 `.env.production` 和 `.env` 載入環境變數。
- 缺少模組時提供清楚的錯誤訊息。
- 處理程序訊號，讓伺服器能正常關閉。

所有可用旗標請參閱 [`mastra start` 參考文件](/reference/cli/mastra#mastra-start)。

## 建置設定 {/* #build-configuration */}

### 建置時的設定 {/* #build-time-configuration */}

Mastra 建置應用程式時會讀取 `bundler`、`deployer` 和 `server` 選項。請將這些選項直接寫成傳給 `new Mastra()` 的物件屬性，建置程序才能擷取。

進入點檔案可以寫成以下形式：

```typescript title="src/mastra/index.ts"
import { Mastra } from '@mastra/core/mastra'

export const mastra = new Mastra({
  bundler: {
    externals: ['sharp'],
  },
  server: {
    port: 4111,
  },
})
```

選項值可以來自變數、匯入或函式呼叫，但選項本身必須是物件的直接屬性。請避免透過工廠函式呼叫或物件展開間接提供建置選項：

```typescript title="src/mastra/index.ts"
import { Mastra } from '@mastra/core/mastra'

const options = {
  bundler: {
    externals: ['sharp'],
  },
}

// These patterns prevent Mastra from extracting `bundler` during the build.
export const mastra = new Mastra(createMastraOptions())
export const otherMastra = new Mastra({ ...options })
```

若 Mastra 無法擷取某個選項，建置時就會採用該選項的預設行為。可用的 `bundler`、`deployer` 和 `server` 設定請參閱[設定參考](/reference/configuration)。

### 公開資料夾 {/* #public-folder */}

如果 Mastra 目錄中有 `public` 資料夾（`src/mastra/public`），建置時會將其中的內容複製到輸出目錄。伺服器會以靜態資產的形式提供這些檔案。

### Mastra 設定 {/* #mastra-configuration */}

建置程序會套用 Mastra 執行個體的設定。CORS、逾時和中介軟體等伺服器行為請見[伺服器概覽](/docs/server/overview)，所有可用選項請見[設定參考](/reference/configuration)。

## 建置流程 {/* #build-process */}

建置會依序執行以下步驟：

1. **找出進入點檔案**：在 Mastra 目錄中尋找 `index.ts` 或 `index.js`。
1. **找出 Tool 檔案**：掃描符合 `{mastraDir}/tools/**/*.{js,ts}` 的檔案，排除測試檔案。
1. **分析相依套件**：判斷哪些套件要打包，哪些要另外安裝。
1. **打包程式碼**：使用 Rollup 進行 tree shaking，並可選擇產生 source map。
1. **產生伺服器**：將以 Hono 為基礎的 HTTP 伺服器產生為 `index.mjs`。
1. **安裝相依套件**：在輸出目錄執行 `npm install`。
1. **複製資產**：若有 `public` 資料夾或 `.npmrc`，就將其複製過去。

## 環境變數 {/* #environment-variables */}

| 變數 | 說明 |
| - | - |
| `PORT` | 伺服器連接埠，預設為 `4111`。 |
| `MASTRA_STUDIO_PATH` | Studio 建置目錄的路徑，預設為 `./playground`。 |
| `MASTRA_SKIP_DOTENV` | 設定後會略過載入 `.env` 檔案。 |
| `NODE_OPTIONS` | Node.js 選項，例如建置時遇到記憶體問題可使用 `--max-old-space-size=4096`。 |

## 伺服器端點 {/* #server-endpoints */}

建置產生的伺服器提供健康檢查、Agent、Workflow 等用途的端點：

| 端點 | 說明 |
| - | - |
| `GET /health` | 健康檢查端點，會傳回 `200 OK`。 |
| `GET /api/openapi.json` | OpenAPI 規格，啟用 `server.build.openAPIDocs` 時提供。 |
| `GET /swagger-ui` | 互動式 API 文件，啟用 `server.build.swaggerUI` 時提供。 |

若要查看所有端點，請執行 `mastra dev` 並前往 `http://localhost:4111/swagger-ui`。

若要新增自己的端點，請參閱[自訂 API 路由](/docs/server/custom-api-routes)。

## 正常關閉與滾動部署 {/* #graceful-shutdown-and-rolling-deploys */}

產生的伺服器預設會處理 `SIGINT` 和 `SIGTERM`。它會停止接受新連線，等待處理中的請求與串流結束，最多等候 [`server.drainTimeout`](/reference/configuration#serverdraintimeout) 指定的時間，然後執行 `mastra.shutdown()`。關閉時，執行中的 Workflow（包含持久化 Agent 的執行）有同樣長的時間可以完成，之後才會關閉工作程序與發布／訂閱機制的訂閱。持久化 Agent 若在時間用盡時仍在執行，就會停止並釋出對該次執行的占用，讓下次啟動時可以立即復原。預設等待時間為 5 秒。收到第二次訊號便會立即終止程序。若要自行管理訊號，請參閱 [`server.handleShutdownSignals`](/reference/configuration#serverhandleshutdownsignals)。

接著，關閉程序會交還該程序仍持有的 Agent 對話執行緒上的執行：

- 仍在執行的作業會中止，後續步驟也不會再啟動。其他程序中監看該對話執行緒的用戶端會看到執行結束，未完成的回應不會儲存。
- 等待 Tool 核准或已暫停的執行會維持暫停，可以從其他程序繼續執行。同一步驟若還有 Tool 呼叫正在執行，會先中止該呼叫，處理方式與仍在執行的作業相同。
- 系統會立即嘗試釋出對話執行緒的租約，讓其他程序不用等到租約到期，就能在該執行緒上啟動新的執行。如果中止的作業未及時停下（例如 Tool 呼叫忽略中止要求），或租約後端未回應或釋出失敗，租約會保留至到期為止。

等候時間用盡後，交還執行還可能需要最多約 1.5 秒。

若託管平台的終止寬限期能容納較長的 Agent 回合，可以增加 `drainTimeout`。HTTP 和 Workflow 會依序等待執行結束。請為兩段等待時間、交還對話執行緒上的執行所需的約 1.5 秒，以及關閉時的清理預留足夠時間。

若自行呼叫 `mastra.shutdown()`，可傳入 `drainTimeout`，控制它等候執行中的 Workflow 完成多久：

```typescript
await mastra.shutdown({ drainTimeout: 30_000 })
```

```typescript title="src/mastra/index.ts"
import { Mastra } from '@mastra/core/mastra'

export const mastra = new Mastra({
  server: {
    drainTimeout: 240_000,
  },
})
```

一般的 `agent.stream()` 呼叫在伺服器程序結束後就無法繼續。如果串流結束時未收到預期的終止事件，請將該回合視為中斷，交由用戶端重試或協調狀態。若回合必須在程序替換後繼續，請使用[持久化 Agent](/docs/harness/durable-agents)。[當機復原](/docs/harness/durable-agents#crash-recovery)需要共用的持久性執行儲存空間，以及[具冪等性的 Tool](/docs/harness/durable-agents#make-tools-safe-to-repeat)。預設事件快取位於記憶體中，因此若要在重啟後重播錯過的事件，還需要 Redis 等共用的持久性快取。若要在多個複本之間復原，需使用支援執行隔離（run fencing）的儲存轉接器，或所有複本皆共用同一租約的 PubSub 後端。請參閱[多執行個體部署](/docs/harness/durable-agents#multi-instance-deployments)。

## 疑難排解 {/* #troubleshooting */}

### 建置時發生記憶體錯誤 {/* #memory-errors-during-build */}

如果出現 `JavaScript heap out of memory` 錯誤：

```bash
NODE_OPTIONS="--max-old-space-size=4096" mastra build
```
