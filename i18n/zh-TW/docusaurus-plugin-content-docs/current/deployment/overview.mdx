# 部署

Mastra 應用程式可部署至任何與 Node.js 相容的環境。你可以部署 Mastra 伺服器，或整合至既有的 Web 框架。其他選項包括雲端供應商，以及提供可觀測性、Studio 與伺服器部署功能的 [Mastra Platform](/docs/mastra-platform/overview)。

## 支援的執行環境 {/* #runtime-support */}

Mastra 可在以下任一環境執行。

- Node.js `v22.13.0` 或更新版本
- Bun
- Deno
- Cloudflare

## 部署選項 {/* #deployment-options */}

### Mastra 伺服器 {/* #mastra-server */}

Mastra 提供以 Hono 為基礎的[伺服器](/docs/server/overview)，可獨立部署。使用 `mastra build` 建置應用程式，再將建置結果部署至選定的虛擬機器、容器或 PaaS 平台。

需要完整掌控基礎架構、長時間執行的程序或 WebSocket 連線時，可選用此方式。詳情請參閱 [Mastra 伺服器部署指南](/docs/deployment/mastra-server)。

### Monorepo {/* #monorepo */}

你可以將 Mastra 伺服器納入 Monorepo，並沿用獨立部署的方式。

請參閱 [Monorepo 部署文件](/docs/deployment/monorepo)。

### Mastra Platform {/* #mastra-platform */}

[Mastra Platform](/docs/mastra-platform/overview) 提供三項產品，可用來部署、監控及管理以 Mastra 框架建置的 AI 應用程式。

- [**Observability**](/docs/mastra-platform/observability)。獨立的託管產品，可跨 Mastra 專案及部署搜尋 Trace、日誌與指標。
- [**Studio**](/docs/mastra-platform/studio)。託管式視覺化環境，可用於測試 Agent、執行 Workflow，並檢視 Trace。
- [**Server**](/docs/mastra-platform/server)。正式環境的部署目標，可將 Mastra 應用程式當作 API 伺服器執行。

詳情請參閱 [Mastra Platform 總覽](/docs/mastra-platform/overview)。

### 雲端供應商 {/* #cloud-providers */}

Mastra 應用程式可部署至雲端供應商和無伺服器平台。Mastra 提供選用的內建部署器，可針對 Vercel、Netlify 或 Cloudflare 建置應用程式，再透過各平台部署建置結果。

若需要自動擴縮、希望減少基礎架構管理工作，或已在使用其中一個平台，可以採用此方式。

### Sandbox {/* #sandbox */}

將 Mastra 伺服器部署至暫時性的 Workspace Sandbox（例如 Vercel Sandbox 或 E2B），幾秒內即可取得可公開存取的 URL。

這種方式適合即時預覽、從 CI 流程部署、驗證 Agent 建置的應用程式，或為個別使用者執行不受信任的執行個體。請參閱 [Sandbox 部署指南](/docs/deployment/sandbox)。

### Web 框架 {/* #web-framework */}

將 Mastra 整合到 Web 框架後，依照框架的標準流程部署應用程式時，也會一併部署 Mastra。下列指南說明各框架的部署設定要求。

若要將 Mastra 加入既有的 Next.js 或 Astro 應用程式，請參閱以下指南。

- [在 Vercel 上使用 Next.js](/docs/deployment/web-framework#with-nextjs-on-vercel)
- [在 Vercel 上使用 Astro](/docs/deployment/web-framework#with-astro-on-vercel)
- [在 Netlify 上使用 Astro](/docs/deployment/web-framework#with-astro-on-netlify)

## Workflow 執行器 {/* #workflow-runners */}

Mastra Workflow 預設使用內建執行引擎。若正式環境的工作負載需要託管基礎架構，也可以將 Workflow 部署至 [Inngest](https://www.inngest.com) 等專用平台，使用步驟結果快取、自動重試與即時監控。

執行選項請參閱 [Workflow 執行器指南](/docs/deployment/workflow-runners)，設定步驟請參閱 [Inngest 部署指南](/integrations/deploy/inngest)。

## Workers {/* #workers */}

在正式環境中，Mastra 可將 Workflow 編排、Cron 排程及背景 Tool 執行交給獨立於 API 伺服器的專用 Worker 程序。這樣即可分別擴縮並隔離故障。詳見 [Workers](/docs/deployment/workers)。
