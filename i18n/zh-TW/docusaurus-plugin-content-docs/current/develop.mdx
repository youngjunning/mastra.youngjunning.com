# 開發

有了 Mastra 專案，就可以開始開發、執行及測試 Agent。

## 在本機執行 Mastra {/* #run-mastra-locally */}

透過 [Mastra Studio](/docs/studio/overview)，可以最快看到 Agent 的執行結果。請在專案根目錄執行 [`mastra dev`](/reference/cli/mastra#mastra-dev)，啟動 Studio 與本機開發伺服器。

```bash npm2yarn
npx mastra dev
```

在 [`http://localhost:4111`](http://localhost:4111) 開啟 Studio，即可測試 Agent 並檢查執行記錄。

開發伺服器也會公開 Agent、Tool 和 Workflow 的 API。前往 [`http://localhost:4111/api`](http://localhost:4111/api) 瀏覽可用端點，再透過 [Mastra Client](/docs/server/mastra-client) 串接前端。

只要 `src/mastra/` 目錄有變更，開發伺服器就會自動重新啟動。開發時無須手動重啟。

## 用 AI 輔助開發 {/* #build-with-ai */}

Mastra 提供 Skill 與 CLI，協助程式開發 Agent 寫出高品質的 Mastra 程式碼。

### Mastra Skills {/* #mastra-skills */}

AI 模型未必掌握最新的 Mastra API。[Mastra Skills](https://github.com/mastra-ai/skills) 會提供實作指引與最佳實務，並教程式開發 Agent 取得最新的 Mastra 文件。Agent 也能與 [Mastra Factory](https://factory.mastra.ai) 互動。

若要手動安裝 Skill，請執行：

```bash npm2yarn
npx skills add mastra-ai/skills
```

定期更新 Skill，即可取得最新指引：

```bash npm2yarn
npx skills update mastra
```

:::note

以 [create mastra](/docs) 建立專案時，指令會自動安裝 Mastra Skills，讓程式開發 Agent 能找到並使用。

:::

### Mastra CLI {/* #mastra-cli */}

透過 [`mastra` CLI](/reference/cli/mastra)，程式開發 Agent 可以反覆測試修改並檢查結果，也能存取 Agent、Workflow、Tool、Memory、Evals、Trace 和日誌。

例如，程式開發 Agent 可以先執行某個 Agent，再擷取 Trace 檢查結果：

```bash
npx mastra api --url http://localhost:4111 agent run agent '{"messages":"Hello"}'
npx mastra api --url http://localhost:4111 trace list
```

請記得安裝 [Mastra Skills](#mastra-skills)，讓程式開發 Agent 知道如何使用 CLI。

## 專案結構 {/* #project-structure */}

採用框架時，通常要先決定專案結構。建議將框架程式碼放在 `src/mastra/` 下，依元件分成個別檔案或資料夾，並集中在 `src/mastra/index.ts` 設定與註冊。

最精簡的專案結構如下：

```text
src/
  mastra/
    agents/
      agent.ts
    tools/
      tool.ts
    workflows/
      workflow.ts
    scorers/
      scorer.ts
    skills.ts
    index.ts
```

如需預設目錄結構與建議慣例，請參閱[專案結構參考](/reference/project-structure)。

## 以檔案定義的 Agent {/* #file-based-agents */}

:::note

只有執行 `mastra dev` 或 `mastra build` 時，Mastra 才會依檔案自動探索 Agent。應用程式若直接匯入 `mastra`，包括透過 Web 框架或伺服器轉接器匯入，請在程式碼中註冊這些 Agent，或將 Mastra 作為獨立伺服器執行。

:::

:::tip[📹 觀看影片]

[如何建立第一個以檔案定義的 Agent](https://www.youtube.com/watch?v=5Kfn-oYkJNg\&t=18s)

:::

採用以檔案定義的 Agent 時，Mastra 會從 `src/mastra/` 下支援的檔案自動[探索](/reference/file-based-agents/config#discovery-lifecycle) Agent 與相關元件。只要依照慣例配置檔案，就不用逐一匯入元件並註冊到 [`Mastra`](/reference/core/mastra-class) 執行個體。

從檔案配置就能看出專案架構。你和程式開發 Agent 不用追查程式碼如何串接，就能掌握各部分的關係。

你可以在整個專案採用以檔案定義的 Agent，也可以逐步導入，與程式碼定義的元件並用。目前仍有部分 Mastra 功能和使用情境尚未支援。

### 建立第一個 Agent {/* #create-your-first-agent */}

每個以檔案定義的 Agent 在 `src/mastra/agents/` 下都有專屬目錄。若要建立可執行的 Agent，請新增 `config.ts` 設定模型與執行階段選項，再新增 `instructions.md` 放入一律套用的提示：

```text
src/mastra/agents/
  writing-assistant/
    config.ts
    instructions.md
```

目錄名稱即為 Agent 預設的 `id` 和 `name`。在此範例中，Mastra 會將 Agent 註冊為 `writing-assistant`。

```typescript title="src/mastra/agents/writing-assistant/config.ts"
import { agentConfig } from '@mastra/core/agent'

export default agentConfig({
  model: '__GATEWAY_OPENAI_MODEL__',
})
```

```markdown title="src/mastra/agents/writing-assistant/instructions.md"
Rewrite text clearly and concisely.
```

執行 `npx mastra dev`，接著開啟 Studio，選取 `writing-assistant` 進行測試。

### 如何探索檔案 {/* #how-discovery-works */}

Mastra 根據路徑探索以檔案提供的功能並命名。Agent 目錄名稱決定預設的 `id` 和 `name`。例如，`tools/search_docs.ts` 會將 Tool 註冊為 `search_docs`，`skills/style-guide.md` 則將 Skill 註冊為 `style-guide`。下表列出擴充路徑。

### 擴充 Agent {/* #extend-your-agent */}

若要為 Agent 增加功能，請新增對應的檔案或目錄：

| 路徑 | 提供的功能 |
| - | - |
| [`tools/<tool-name>.ts`](/reference/file-based-agents/tools) | 模型可呼叫的函式 |
| [`skills/<skill-name>.md`](/reference/file-based-agents/skills) | Agent 視情境載入的詳細指引 |
| [`memory.ts`](/reference/file-based-agents/memory) | 對話歷程與工作脈絡 |
| [`workspace.ts` 與 `workspace/`](/reference/file-based-agents/workspace) | 檔案系統和 Shell 存取 |
| [`subagents/<agent-id>/`](/reference/file-based-agents/subagents) | 可接受上層 Agent 委派的專職 Agent |

將各功能的檔案放在使用它們的 Agent 旁。開發伺服器啟動或重新啟動時，Mastra 會探索並註冊這些檔案。

完整的檔案慣例與設定選項請見[以檔案定義的 Agent 參考](/reference/file-based-agents/config)。
