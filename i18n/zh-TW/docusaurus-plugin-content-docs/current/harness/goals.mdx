# 目標

**加入版本** `@mastra/core@1.43.0`

目標是保存在 Thread 中的長期指示。Agent 會在每次迭代持續推進，直到評判模型判定目標已達成，或執行預算用完。

目標儲存在 Thread 狀態中，重新載入後仍然有效。即使正在執行的輪次收到新訊息，迴圈也會繼續評估目標。

目標沿用 [`isTaskComplete`](/docs/subagents) 的機制。LLM 在每次迭代為 Agent 輸出評分，決定迴圈是否繼續。目標會持久儲存在 Thread 狀態中，以 `Agent` 方法設定及更新，不用在每次呼叫 `stream()` 時傳入選項。

## 何時使用目標 {/* #when-to-use-goals */}

若希望 Agent 跨多次迭代和訊息持續推進同一目標，且不必每次呼叫都重傳成功條件，可使用目標。

* Agent 要持續推進，直到評判模型確認完成。
* 執行中收到新訊息後仍須繼續工作，評判模型也會依同一個目標評估新訊息。
* 重新載入 Thread 或重新啟動程序後，仍須保留目標。

若只要在單次 `stream()` 呼叫中檢查是否完成，請使用 [`isTaskComplete`](/docs/subagents)。

## 快速入門 {/* #quickstart */}

目標需要已設定的 [儲存](/docs/storage) 後端，以及由 Memory 支援的 Thread。為 Agent 加入 `goal` 設定並指定評判模型，再為 Thread 設定目標。

```typescript title="src/mastra/agents/worker.ts" {8-11}
import { Agent } from '@mastra/core/agent'

const worker = new Agent({
  id: 'worker',
  name: 'worker',
  instructions: 'You complete software tasks end to end.',
  model: '__GATEWAY_OPENAI_MODEL__',
  memory,
  goal: {
    judge: '__GATEWAY_OPENAI_MODEL_LUNA__',
    maxRuns: 50,
  },
})

// Set the durable objective for a thread.
await worker.setObjective('Add and test a /health endpoint', {
  threadId,
  resourceId,
})

// The objective is judged each iteration until it's complete or maxRuns is hit.
const stream = await worker.stream('Start working on the goal', {
  memory: { thread: threadId, resource: resourceId },
})
```

`goal` 設定會自動註冊狀態訊號投影，模型無需額外設定就能在情境中看到以 `<current-objective>` 呈現的當前目標。

## 目標評估如何運作 {/* #how-the-goal-step-works */}

目標評估在 Agent 的執行迴圈內緊接 `isTaskComplete` 執行。Agent 提出實際可評估的候選答案時，此步驟會依目標為對話評分，並決定迴圈是否繼續。

* **尚未達成目標，且仍有預算** → 迴圈繼續。每次評估的回饋會加入情境，讓 Agent 在下一次迭代改進。
* **已達成目標** → 迴圈停止，目標標記為 `done`。
* **預算用完** (`runsUsed >= maxRuns`) → 迴圈停止，目標標記為 `paused`。調高 `maxRuns` 後，恢復目標即可繼續。

和 `isTaskComplete` 一樣，處理背景工作、仍在工具呼叫迴圈中，或只更新工作記憶的迭代，都會略過此步驟。

每次評估都會送出具有型別定義的 `goal` 串流區塊，供介面即時顯示進度。其型別為 `GoalEvaluationPayload`，包含 `objective`、`iteration`、`maxRuns`、`passed`、`status`、`results`、`reason`、`duration`、`timedOut`、`maxRunsReached` 及 `suppressFeedback`。

**必須取得評判模型，才會啟用目標評估。** 若目標的覆寫設定和 Agent 的 `goal.judge` 都無法提供評判模型，這個步驟便不會評分、耗用預算或送出 `goal` 區塊。Mastra 會在選擇 Scorer 前先檢查評判模型，因此自訂 `goal.scorer` 也需要能解析出評判模型。

設定依序取用個別目標紀錄、Agent 的 `goal` 設定與內建預設值（`maxRuns` 為 `50`，並採用預設評判提示）。

### 評判模型與 Scorer {/* #judge-and-scorer */}

`goal.judge` 和 `goal.scorer` 各有分工。`goal.scorer` 是產生分數的評估流程，迴圈依分數決定是否繼續。`goal.judge` 是預設流程呼叫的評判模型。

省略 `scorer` 時，Mastra 會建立預設的 Scorer，由 LLM 評判。達成目標時回傳 `1`，評判模型認為 Agent 正等待使用者輸入時回傳 `0.5`，其餘情況回傳 `0`。`0.5` 會停止自動迴圈，目標仍未完成，因此 Agent 的下一輪仍會受評估。可用下列項目設定預設 Scorer。

* `goal.judge` 指定判斷目標是否達成的模型。
* `goal.prompt` 提供額外指示給評判模型，預設使用內建的目標評判提示。
* `goal.tools` 指定評判模型下判斷前可呼叫的唯讀驗證工具，以查證實際成果，避免只根據 Agent 的文字評分。
* `goal.maxSteps` 限制評判模型本身的執行迴圈步數，預設為 `5`。

傳入 `goal.scorer`，即可用自訂 [Scorer](/reference/evals/create-scorer) 取代預設流程。可以傳入 Scorer 實例或已註冊的 Scorer ID。自訂 Scorer 自行評判，所以 `goal.prompt`、`goal.tools` 和 `goal.maxSteps` 不再適用，Mastra 也不會為了評判另外解析模型。若 `goal.judge` 是解析函式，它仍會執行，但回傳值會被捨棄。

用 `judge`、`maxRuns` 和 `prompt` 設定預設 Scorer。

```typescript title="src/mastra/agents/worker.ts"
import { Agent } from '@mastra/core/agent'

const worker = new Agent({
  id: 'worker',
  name: 'worker',
  instructions: 'You complete software tasks end to end.',
  model: '__GATEWAY_OPENAI_MODEL__',
  memory,
  goal: {
    // A resolver function lets you inject provider credentials and read the
    // current judge selection at runtime; returning `undefined` keeps the
    // goal step a no-op.
    judge: ({ requestContext }) => resolveJudgeModel(requestContext),
    maxRuns: 30,
    prompt: 'Only mark the goal complete when tests pass.',
  },
})
```

若要由自訂 Scorer 判斷，請以 `scorer` 傳入，同時保留 `judge` 設定，因為啟用時仍會檢查評判模型。

```typescript oxfmt:false
goal: {
  judge: '__GATEWAY_OPENAI_MODEL_LUNA__',
  // Replaces the built-in judge pipeline. `prompt`, `tools`, and `maxSteps` no longer apply.
  scorer: 'tests-pass',
}
```

## 管理目標 {/* #managing-the-objective */}

可用 `Agent` 方法管理 Thread 的目標。這些方法需要儲存後端和 `threadId`。若執行時未使用 Memory，呼叫不會有任何作用。

```typescript title="src/mastra/objective.ts"
// Read the current objective record.
const record = await worker.getObjective({ threadId })

// Update options on the active objective (only provided fields are written;
// unset fields fall back to the agent's `goal` config).
await worker.updateObjectiveOptions({ threadId, maxRuns: 100 })

// Drop the objective.
await worker.clearObjective({ threadId })
```

目標紀錄可包含 `activeDurationMs`，供介面顯示 Agent 推進目標所花的時間。Agent 為作用中的目標工作時，Mastra 會累加此值，並在執行結束或等待工具核准時儲存。欄位缺漏時視為零。這段時間只計入 Agent 實際執行的時間，與目標建立後經過的總時間有別。

`setObjective` 或 `updateObjectiveOptions` 寫入的個別目標設定優先於 Agent 的 `goal` 設定，且此優先順序會保留在 Thread 狀態中。完整區塊結構請見 [ChunkType 參考文件中的 `GoalEvaluationPayload`](/reference/streaming/ChunkType)。
