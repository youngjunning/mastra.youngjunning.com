# 排程

**加入版本：** `@mastra/core@1.50.0`

排程依 cron 設定的時間執行 Agent。每次觸發時，Mastra 可以把提示詞當作[訊號](/docs/signals/sending-signals)送入對話執行緒，也可以透過 [`agent.generate()`](/reference/agents/generate) 單獨執行一次。每日摘要、例行檢查，以及定時在對話中提醒，都適合用排程處理。

排程會持久儲存，重新啟動或部署後仍會保留。應用程式執行時，可透過統一的 [`mastra.schedules`](/reference/schedules/overview) 介面建立、讀取、更新或刪除排程。這個介面也能管理 [Workflow 排程](/docs/workflows/scheduled-workflows)，只要改傳 `workflowId`，不傳 `agentId`。

:::note

排程需要支援 schedules 領域的[儲存](/docs/storage)介接器。支援的介接器與 API 行為請見 [`mastra.schedules` 參考文件](/reference/schedules/overview)。

:::

即使排程已儲存，也不保證每次觸發都會送達。排程器會盡力發布，最多嘗試三次；若重試用盡，或發布端當機，該次觸發可能跳過。跳過的觸發不會補送，後續仍可按週期觸發。錯誤回報及手動重跑的注意事項請見[排程的投遞保證](/reference/schedules/overview#delivery-guarantees)。

## 快速上手 {/* #quickstart */}

下列排程每小時執行 `pinger` Agent 一次。由於沒有對話執行緒，每次觸發都是獨立的 `agent.generate()` 執行。

```typescript title="src/mastra/schedules.ts"
import { Mastra } from '@mastra/core'
import { Agent } from '@mastra/core/agent'
import { LibSQLStore } from '@mastra/libsql'

const pinger = new Agent({
  id: 'pinger',
  name: 'Pinger',
  instructions: 'Report the current system status in one sentence.',
  model: '__GATEWAY_OPENAI_MODEL__',
})

const mastra = new Mastra({
  agents: { pinger },
  storage: new LibSQLStore({ id: 'mastra-storage', url: 'file:./mastra.db' }),
})

await mastra.schedules.create({
  agentId: 'pinger',
  cron: '0 * * * *',
  prompt: 'Give me a status update.',
})
```

排程只能在已啟動 Mastra 背景 [Worker](/docs/deployment/workers) 的處理程序內觸發。`mastra dev` 和 `mastra build` 產生的伺服器會自動啟動 Worker。若改用[伺服器介接器](/docs/server/server-adapters)或自行撰寫指令碼，請自行呼叫 `mastra.startWorkers()`；否則只會儲存排程，不會觸發。請見[啟動背景 Worker](/docs/server/server-adapters#start-background-workers)。

## 觸發週期 {/* #cadence */}

排程按 cron 運算式觸發。`cron` 欄位接受標準的 5、6 或 7 欄運算式，建立或更新排程時會驗證格式。

也支援 `croner` 的別名，例如 `@hourly`、`@daily`、`@weekly`、`@monthly` 和 `@midnight`。若要搭配指定的日期和時間，直接填寫 cron 欄位：

```typescript
// Every weekday at 9am
await mastra.schedules.create({
  agentId: 'pinger',
  cron: '0 9 * * 1-5',
  prompt: 'Start-of-day check.',
})
```

在 `timezone` 指定 IANA 時區，例如 `America/New_York`，觸發時間就不受主機的地區設定影響。未指定時，cron 按主機的本機時區計算。

若想讓 cron 設定更容易閱讀，可用 [`cron-time-generator`](https://www.npmjs.com/package/cron-time-generator) 等第三方工具產生運算式，再將結果傳給 `cron`。

## 排程與對話執行緒 {/* #threadless-and-threaded-schedules */}

Agent 排程的兩種觸發模式，由是否指定 `threadId` 決定。

### 不使用執行緒 {/* #threadless */}

省略 `threadId` 時，每次觸發會各自執行一次 `agent.generate()`，不會寫入任何對話執行緒。這是最簡單的模式，適合狀態檢查、報表和其他不需要對話脈絡的工作。

### 使用執行緒 {/* #threaded */}

指定 `threadId` 時，排程會向該執行緒送出[訊號](/docs/signals/sending-signals)，把提示詞加入 Agent 的對話。指定 `threadId` 時也必須提供 `resourceId`。

```typescript title="src/mastra/schedules.ts"
await mastra.schedules.create({
  agentId: 'pinger',
  cron: '0 9 * * *',
  prompt: 'Summarize anything new since yesterday.',
  threadId: 'thread-123',
  resourceId: 'user-456',
})
```

使用執行緒時，可再設定訊號類型、XML 標籤、標籤屬性，以及執行緒運作中或閒置時的投遞方式。這些欄位對應 [`agent.sendSignal()`](/docs/signals/sending-signals) 接受的選項，可序列化為 JSON，因此能和排程一併儲存。

這些欄位都必須搭配 `threadId`。完整的輸入結構請見 [Agent 排程輸入參考](/reference/schedules/overview#createinput)。

```typescript
await mastra.schedules.create({
  agentId: 'pinger',
  cron: '0 9 * * *',
  prompt: 'Summarize anything new since yesterday.',
  threadId: 'thread-123',
  resourceId: 'user-456',
  tagName: 'check-in', // renders as <check-in>…</check-in>
  attributes: { source: 'cron' },
  ifActive: { behavior: 'discard' }, // skip if the thread is mid-stream
  ifIdle: {
    behavior: 'wake', // wake the agent if the thread is idle
    streamOptions: { requestContext: { locale: 'en-US' } },
  },
})
```

無論有沒有指定執行緒，每次觸發都會將 `providerOptions` 合併到訊號承載的資料中。

## 管理排程 {/* #managing-schedules */}

透過 `mastra.schedules` 可建立、讀取、更新、暫停、恢復、手動執行或刪除排程。

```typescript
const schedule = await mastra.schedules.create({
  agentId: 'pinger',
  cron: '0 * * * *',
  prompt: 'Status check.',
})

await mastra.schedules.pause(schedule.id)
await mastra.schedules.resume(schedule.id)
await mastra.schedules.run(schedule.id) // Fire once now, off-schedule
```

`pause` 和 `resume` 會保存變更後的狀態。`run` 會立即觸發一次，原本的觸發週期照常。完整的方法、篩選器和可更新欄位請見 [`mastra.schedules` 參考文件](/reference/schedules/overview)。

### Workflow 排程 {/* #workflow-schedules */}

同一個服務也可建立執行 Workflow 的排程。傳入 `workflowId` 和 Workflow 所需的欄位：

```typescript
await mastra.schedules.create({
  workflowId: 'daily-report',
  cron: '0 9 * * *',
  inputData: { userId: 'system' },
})
```

如此建立的 Workflow 排程與 `createWorkflow` 上宣告的 `schedule` 欄位各自獨立。宣告方式及 Studio 檢視畫面請見 [Workflow 排程](/docs/workflows/scheduled-workflows)。

### 自訂 ID {/* #custom-ids */}

如果日後想透過事先知道的識別碼查詢、更新或刪除排程，請傳入 `id`。

```typescript
await mastra.schedules.create({
  id: 'nightly-summary',
  agentId: 'pinger',
  cron: '0 9 * * *',
  prompt: 'Summarize anything new since yesterday.',
})
```

識別碼如何正規化以及重複時的處理方式，請見 [`create(input)` 參考文件](/reference/schedules/overview#createinput)。

### 從用戶端操作 {/* #from-the-client */}

`@mastra/client-js` 經由 `/api/schedules` 路由提供相同功能，因此可從其他處理程序或使用者介面管理排程。用戶端方法清單請見 [client-js 的 Agent 排程參考](/reference/client-js/agents#agent-schedules)。

## 生命週期鉤子 {/* #lifecycle-hooks */}

透過鉤子，你可以在 Agent 排程生命週期的關鍵時點執行程式碼，例如計算該次觸發的參數或處理結果。請在 `Mastra` 建構函式的 `schedules` 下設定。所有 Agent 排程都共用同一組未分層的鉤子。每次呼叫的上下文都有對應的 `agentId`，可依此套用各 Agent 的邏輯。鉤子設於 `Mastra` 層級，因此無論 Agent 是以程式碼定義或從儲存層載入，都適用。

```typescript title="src/mastra/index.ts"
import { Mastra } from '@mastra/core'
import { LibSQLStore } from '@mastra/libsql'

const mastra = new Mastra({
  agents: { pinger },
  storage: new LibSQLStore({ id: 'mastra-storage', url: 'file:./mastra.db' }),
  schedules: {
    prepare: async ({ agentId, schedule, trigger }) => {
      // Return overrides, null to skip this fire, or undefined for defaults
      return { prompt: `Status as of ${trigger.firedAt.toISOString()}` }
    },
    onFinish: async ({ agentId, outcome, runId }) => {
      // Runs on any non-error, non-abort outcome. For a threaded schedule, this is the hand-off, not the end of the run
    },
    onError: async ({ agentId, phase, error }) => {
      // Runs when prepare or the signal threw, or a threadless run failed without aborting
    },
    onAbort: async ({ agentId, runId }) => {
      // Runs when a threadless run was aborted
    },
  },
})
```

可設定下列鉤子：

- `prepare`：排程觸發前呼叫。回傳物件可覆寫該次觸發的參數，例如 `prompt` 或 `threadId`；回傳 `null` 可跳過；回傳 `undefined` 則沿用儲存的預設值。
- `onFinish`：每次觸發若未發生錯誤或中止，會呼叫一次。使用執行緒的排程若啟動新的執行，會在啟動當下以 `outcome: 'succeeded'` 呼叫，無須等到執行結束。
- `onError`：`prepare` 或訊號處理失敗後呼叫。若沒有指定 `threadId`，Agent 執行因中止以外的錯誤而失敗時，也會呼叫。
- `onAbort`：未設定 `threadId` 的排程，其中一次執行中止時呼叫。

指定 `threadId` 的排程，Worker 會把提示詞送入執行緒，不等待該次執行。執行開始後發生的錯誤或中止會反映在該執行緒的這次執行上，不會經由 `onError` 或 `onAbort` 回報。

若要在執行完成後處理結果，請使用無執行緒的排程。若需要生命週期狀態、清理、重試或多個步驟，請使用 [Workflow 排程](/docs/workflows/scheduled-workflows)。

每個鉤子的上下文都會提供 `schedule`、`trigger`，以及本次觸發所對應的 Agent 識別碼 `agentId`。

系統會攔截並記錄鉤子擲出的例外。這些例外不會改變 Worker 的處理流程，也不會觸發別的鉤子。

## 在 Mastra Code 定期送出提示詞 {/* #recurring-prompts-in-mastra-code */}

在 Mastra Code，可用 `/schedules` 指令替目前的對話執行緒設定週期性提示詞。這類排程與 `mastra.schedules` 不同，只留在建立排程的 Mastra Code 處理程序中，不會寫入儲存層；觸發時直接呼叫 `agent.sendSignal()` 將提示詞送入執行緒。

執行 `/schedules`，選單會列出 **Create schedule** 和目前執行緒上的各筆排程。建立流程如下：

1. 選擇每次觸發的來源：提示詞（**Prompt**）、每次重新讀取的提示詞檔案（**Prompt file**），或每次都會執行的指令碼（**Script**）。
1. 輸入提示詞或檔案路徑。路徑以專案根目錄為基準。如果選擇指令碼，可以加上一段提示詞，排在指令碼輸出之後送出。
1. 從 `1m` 到 `1d` 選擇週期，或自行輸入，例如 `20m` 或 `3h`。以分鐘為單位時，間隔須能整除一小時；以小時為單位時，須能整除一天。
1. 確認。

指令碼從專案根目錄執行，逾時為 60 秒。標準輸出、標準錯誤輸出與結束代碼會用於組成提示詞。補充的提示詞不會傳給指令碼。

選取已有的排程後，可用 **Run now**、**Pause** 或 **Resume**，以及 **Delete**。即使排程已暫停，**Run now** 也能立即觸發一次，並保留原有週期。如果同一排程上次觸發的工作還在執行，就跳過這一次。

每次觸發都會以 `user` 類型的訊號進入執行緒，在對話紀錄中顯示為 `schedule` 項目，附有排程 ID、週期、來源和指令碼結束狀態。執行緒忙碌時，正在執行的 Agent 會把提示詞當成下一筆輸入，就像你在執行期間輸入訊息一樣。閒置的執行緒則會喚醒並執行。即使執行緒目前未顯示在終端機，只要在同一處理程序內，排程就能觸發。使用 `/new` 後，新建的排程會連結到新的執行緒。

請留意下列行為：

- **範圍限於目前工作階段。** 排程只存在於建立它的 Mastra Code 處理程序中，結束程序也會停止排程。其他 Mastra Code 處理程序即使共用資料庫，也看不到這些排程，無法觸發。
- **依時鐘刻度觸發。** `5m` 會在 :00、:05、:10 等時間點觸發，並非從建立時間起算五分鐘；`1d` 會在本地午夜觸發。如同 cron，小時和天的週期依當地鐘錶時間執行，也採用日光節約時間的變更。電腦休眠時錯過的觸發，或計時器延遲超過一分鐘的觸發，都會略過。到了下一個預定時間點，排程會繼續。
- **略過重疊的觸發。** 若下一個觸發時間已到，指令碼仍在執行，就不執行這一次。

### Agent 排程工具 {/* #agent-schedule-tools */}

在 `/settings` 啟用 **Experimental schedule tools** 並重新啟動後，Agent 可用 `schedule_create`、`schedule_list`、`schedule_update`（暫停或刪除）、`schedule_resume` 和 `schedule_run` 管理相同的排程。工具只能查看或變更呼叫它的這次執行所在的執行緒上的排程。因為排程可在每次觸發時執行指令碼，除非開啟 YOLO 模式，否則 `schedule_create`、`schedule_resume` 和 `schedule_run` 都需要與執行 shell 指令相同的核准。由 Agent 建立的排程，在對話紀錄中會標示為 `created by agent`。
