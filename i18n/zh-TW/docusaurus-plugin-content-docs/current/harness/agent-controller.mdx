# Agent Controller

`AgentController` 是互動式 Agent 應用程式共用的執行階段宿主，負責協調模式、模型、儲存空間、Workspace、Tool 核准、子 Agent 與頻道。每位使用者或進行中的任務，都透過獨立的 [`Session`](/reference/agent-controller/session) 運作。

[Mastra Code](https://code.mastra.ai) 和 [Mastra Factory](https://factory.mastra.ai) 是 AgentController 的代表性實作。這兩款程式開發 Agent 支援多種模型、持久化對話，以及先規劃再執行的工作流程。逐步建立 TUI 的方法請參閱[建立程式開發 Agent](https://mastra.ai/blog/building-a-coding-agent)。

若託管的 Agent 會在程式碼庫中工作，請用 [`createCodingAgent()`](/reference/coding-agent/create-coding-agent) 建立，而非 `new Agent()`。它會回傳標準 `Agent`，預先具備 Workspace、任務追蹤，以及模型暫時性錯誤的重試機制；Mastra Code 也採用這些預設設定。

## 何時使用 Agent Controller {/* #when-to-use-the-agent-controller */}

應用程式需要以下功能時，可採用 Agent Controller：

- 多種 Agent 模式共用同一條對話執行緒（例如規劃 → 建置 → 審查）
- 在 UI 與 Agent 執行迴圈之間加入控制層（切換模型、保留狀態、管理執行緒）
- 以 Tool 核准流程和權限政策讓使用者把關
- 編排子 Agent，委派範圍明確且 Tool 受限的子任務
- 重新啟動後保留執行緒與選定的執行緒設定，同時隔離各 Session 的即時狀態

你也可以在 [Agent 類別](/docs/agents/overview)之上自行組合這些功能；它提供完整的 Agent 執行迴圈、Tool 和記憶體功能。AgentController 為持續進行的 Session 提供一套有明確設計取捨的預設行為，讓 Agent 以協作者的方式運作，而非只處理單次請求。若需要完全掌控或採用請求回應式呼叫，直接使用 Agent 類別；若要持續對話且不想自行建置 Session 執行階段，則使用 AgentController。

## 快速入門 {/* #quickstart */}

先建立作為底層執行者的 [`Agent`](/reference/agents/agent)、儲存空間及 [`Workspace`](/reference/workspace/workspace-class)。呼叫一次 [`controller.init()`](/reference/agent-controller/agent-controller-class#init)，接著透過 [`controller.createSession()`](/reference/agent-controller/agent-controller-class#createsessionoptions) 建立 Session。以 [`session.subscribe()`](/reference/agent-controller/session#subscribelistener) 訂閱事件，再以 [`session.sendMessage()`](/reference/agent-controller/session#sendmessage-content-files-requestcontext-author-) 傳送任務：

```typescript title="src/mastra/agent-controller.ts"
import { Agent } from '@mastra/core/agent'
import { AgentController } from '@mastra/core/agent-controller'
import { LocalFilesystem, Workspace } from '@mastra/core/workspace'
import { LibSQLStore } from '@mastra/libsql'

const agent = new Agent({
  id: 'assistant',
  name: 'Assistant',
  instructions: 'Help the user plan and complete tasks.',
  model: '__GATEWAY_OPENAI_MODEL__',
})

const controller = new AgentController({
  id: 'assistant-controller',
  agent,
  storage: new LibSQLStore({
    id: 'agent-controller-storage',
    url: 'file:./mastra.db',
  }),
  workspace: new Workspace({
    id: 'assistant-workspace',
    filesystem: new LocalFilesystem({ basePath: './workspace' }),
  }),
  modes: [
    {
      id: 'plan',
      name: 'Plan',
      metadata: { default: true },
      instructions: 'Reason about the task before making changes.',
    },
    {
      id: 'build',
      name: 'Build',
      instructions: 'Implement the approved plan.',
    },
  ],
})

await controller.init()

const session = await controller.createSession({
  resourceId: 'user-123',
})

const unsubscribe = session.subscribe(event => {
  if (event.type === 'message_update' && event.event.type === 'text-delta') {
    process.stdout.write(event.event.delta)
  }
})

await session.sendMessage({ content: 'Plan a small TypeScript CLI.' })
unsubscribe()
```

每則訊息會先發出含初始訊息的 `message_start` 事件，接著發出零個或多個含精簡差異資料的 `message_update` 事件，最後發出含訊息 ID 的 `message_end` 事件。需要重建完整訊息時，請依 ID 套用更新。

同一個 Controller 可供多個 Session 使用。請勿將目前的 Session 存在 Controller 上，也不要透過 Controller 層級的訊息方法轉送工作。

## 認識執行階段模型 {/* #understand-the-runtime-model */}

Controller、Session 與執行緒的生命週期不同：

- **Controller**：共用設定與執行階段服務的宿主。初始化一次即可重複使用。
- **Session**：供一位使用者、一項任務或一個並行工作單位使用的獨立即時執行階段，以 Session ID 識別。它保存目前模式、模型、狀態、事件匯流排、執行狀態、授權及目前綁定的執行緒。
- **執行緒**：儲存訊息及執行緒設定的對話。設定儲存空間後，即使 Controller 或處理程序重新建立，執行緒仍可保留。

Session 承載的是即時狀態。任意的 [`session.state`](/reference/agent-controller/session#state) 資料、權限授權、待核准項目和進行中的執行，不會在處理程序重新建立後自動恢復。執行緒訊息及部分執行緒設定，包括目前模式與模型，可透過儲存空間保留；但切換模式不會改變模型。

## Session 與執行緒 {/* #sessions-and-threads */}

`createSession()` 依 Session 的 `id` 取得既有實例或建立新實例。`resourceId` 指定 Session 的執行緒及資源範圍記憶體由誰擁有。若省略 `id`，預設使用 `resourceId`：

```typescript
const webSession = await controller.createSession({
  id: 'user-123:web',
  resourceId: 'user-123',
})

const sameWebSession = await controller.getSession('user-123:web')

const workerSession = await controller.createSession({
  id: 'user-123:background-worker',
  resourceId: 'user-123',
})

console.log(webSession === sameWebSession) // true
console.log(webSession === workerSession) // false
```

不同 ID 的 Session 有各自的事件匯流排、執行迴圈、狀態、模式與模型選擇，以及目前綁定的執行緒。不過，已儲存的執行緒和資源範圍記憶體仍可共用相同 `resourceId`，所以依資源列出執行緒時，會取得兩個 Session 的執行緒。

如果宿主必須將 Session 綁定到特定執行緒，請傳入 `threadId`。Controller 會切換至既有執行緒；若該 ID 尚不存在，就會建立執行緒。即使 `createSession()` 回傳快取中的 Session，這項行為仍會發生：

```typescript
const session = await controller.createSession({
  id: 'user-123:web',
  resourceId: 'user-123',
  threadId: 'support-ticket-42',
})
```

使用 [`session.thread.create()`](/reference/agent-controller/session#sessionthreadcreate-title-id-requestcontext-) 和 [`session.thread.switch()`](/reference/agent-controller/session#sessionthreadswitch-threadid-emitevent-requestcontext-)，讓同一個即時 Session 在不同對話間切換。

### 轉移執行緒擁有權 {/* #transfer-thread-ownership */}

每條新執行緒會將其持久擁有者記錄於 `metadata.ownerId`，並將原始建立者記錄於 `metadata.createdBy`。兩者預設為 Session 宿主的 `ownerId`。轉移擁有權不會變更 `createdBy`。

透過 `session.thread` 讀取目前執行緒的擁有者並轉移擁有權：

```typescript
const currentOwnerId = await session.thread.getOwner()

await session.thread.transferOwnership({
  toOwnerId: 'user-456',
})
```

同一個處理程序內的轉移作業會依序執行。如果宿主需要跨處理程序、可持久保存的比較並設定操作，應先在自己的儲存空間提交變更，再呼叫 `transferOwnership()`，將擁有者同步至目前執行緒。

每次執行開始時，都會擷取執行緒擁有者的快照。Tool 和其他動態執行階段程式碼可從 `AgentControllerRequestContext.threadOwnerId` 讀取這個值。若執行期間擁有權改變，本次執行仍使用舊快照，下次執行才會取得新擁有者。`context.session.ownerId` 則維持為目前處理程序中 Session 宿主的身分。

### 從用戶端列出已儲存的訊息 {/* #list-stored-messages-from-the-client */}

使用 Agent Controller 用戶端，分頁讀取執行緒中儲存的訊息。傳入選項物件時，結果也會包含分頁中繼資料：

```typescript
import { MastraClient } from '@mastra/client-js'

const client = new MastraClient({ baseUrl: 'http://localhost:4111' })
const session = client.getAgentController('assistant-controller').session('user-123')

const result = await session.listMessages('support-ticket-42', {
  page: 0,
  perPage: 20,
  orderBy: { field: 'createdAt', direction: 'DESC' },
  filter: {
    dateRange: { start: new Date('2026-01-01') },
  },
})

console.log(result.messages)
console.log(result.total)
console.log(result.hasMore)
```

`page` 從零開始。未指定 `perPage` 時，採用儲存空間預設的每頁 40 則訊息。`include` 可依 ID 取得指定訊息與相鄰訊息。`limit` 是已棄用的 `perPage` 別名；現有分頁呼叫仍可使用 `{ limit, page }`，但與 `orderBy`、`filter` 或 `include` 一起使用時，必須改用 `perPage`。若要以陣列取得最新一段訊息，仍可使用數字參數形式 `session.listMessages(threadId, limit)`；結果按由舊到新的順序排列。

## 切換模式與模型 {/* #switch-modes-and-models */}

模式會調整共用底層 Agent 使用的指令和 Tool，而不更換 Session 或執行緒。請在 Controller 上設定各模式專用的 Tool 與可見範圍：

```typescript
const modes = [
  {
    id: 'plan',
    name: 'Plan',
    metadata: { default: true },
    instructions: 'Investigate the task and propose a plan.',
    additionalTools: { searchDocs },
    availableTools: ['searchDocs', 'submit_plan'],
    transitionsTo: 'build',
  },
  {
    id: 'build',
    name: 'Build',
    instructions: 'Implement the approved plan.',
  },
]
```

`tools` 與 `additionalTools` 是兩種互斥的模式專用 Tool 輸入。當 Controller 有共用底層 Agent 時，任一輸入都會將 Tool 疊加至該 Agent 的 Tool。透過 `availableTools` 限制模式最終可使用的 Tool 名稱。權限政策中的拒絕規則仍優先於此允許清單。

使用 [`session.mode.switch()`](/reference/agent-controller/session#sessionmodeswitch-modeid-) 切換即時 Session 的模式。使用 [`session.mode.get()`](/reference/agent-controller/session#sessionmodeget) 或 [`session.mode.resolve()`](/reference/agent-controller/session#sessionmoderesolve) 讀取目前模式：

```typescript
await session.mode.switch({ modeId: 'build' })

console.log(session.mode.get()) // "build"
console.log(session.mode.resolve().instructions)
```

使用 [`session.model.switch()`](/reference/agent-controller/session#sessionmodelswitchmodelid-options) 獨立切換模型，再使用 [`session.model.get()`](/reference/agent-controller/session#sessionmodelget) 查看目前選擇。這項選擇會儲存為執行緒的目前模型，因此 Session 切換模式後仍會沿用：

```typescript
await session.model.switch('__GATEWAY_ANTHROPIC_MODEL_SONNET__')

console.log(session.model.get())
```

### 選擇 Observational Memory 模型 {/* #select-observational-memory-models */}

Observer 與 reflector 的模型選擇彼此獨立。每個角色可以指定模型，或由宿主依目前主模型及 Session 狀態自動選擇。

要設定自動選擇，請提供一個同步解析器，並讓它回傳具體的模型 ID：

```typescript
const controller = new AgentController({
  // ...
  omConfig: {
    observerModel: 'auto',
    reflectorModel: 'auto',
    defaultObserverModelId: '__GATEWAY_OPENAI_MODEL_LUNA__',
    defaultReflectorModelId: '__GATEWAY_OPENAI_MODEL_LUNA__',
    resolveAutoModelId: ({ currentModelId }) => currentModelId,
  },
})
```

`session.om.observer.model()` 會回傳 `'auto'` 或具體模型 ID；`session.om.observer.modelId()` 則回傳實際生效的具體模型。因此，宿主可更換主模型，而不用重寫各角色的自動選擇設定。

可以只將其中一個角色重設為自動選擇，不影響另一個角色：

```typescript
await session.om.observer.switchModel({ modelId: 'auto' })
```

若解析器回傳 `undefined` 或擲出錯誤，該角色會改用具體的 `defaultObserverModelId` 或 `defaultReflectorModelId` 作為備援。明確指定模型的方式請參閱 [`Session` Observational Memory API](/reference/agent-controller/session#observational-memory)。

## 管理執行緒與狀態 {/* #manage-threads-and-state */}

透過 [`session.thread.list()`](/reference/agent-controller/session#sessionthreadlistoptions) 列出已儲存的對話：

```typescript
const thread = await session.thread.create({ title: 'Release planning' })
const threads = await session.thread.list()

await session.thread.switch({ threadId: thread.id })
console.log(threads.length)
```

以 `session.state` 保存 Session 的結構化即時狀態。透過 [`session.state.get()`](/reference/agent-controller/session#sessionstateget) 讀取，並透過 [`session.state.set()`](/reference/agent-controller/session#sessionstatesetupdates) 更新。如需驗證及預設值，可在 Controller 上定義 `stateSchema` 與 `initialState`：

```typescript
console.log(session.state.get())

await session.state.set({ activeProject: 'docs-site' })
```

`session.state.get()` 回傳快照。`set()` 會驗證更新內容，再將其合併至 Session 狀態。除非宿主明確負責持久化及還原，否則請將其視為即時 Session 資料。

## 核准 Tool 並恢復暫停的執行 {/* #approve-tools-and-resume-suspensions */}

權限政策會決定 Tool 是獲准執行、遭到拒絕，還是送至 UI 等待核准。可在 Controller 上使用 `toolCategoryResolver`，將自訂 Tool 對應至類別：

```typescript
const controller = new AgentController({
  toolCategoryResolver: toolName => {
    if (toolName === 'delete_project') return 'execute'
    return null
  },
})
```

政策允許的 Tool 呼叫不會暫停執行。一般 `Agent` 在同一步驟中呼叫多個 Tool，且都不需核准也不會暫停時，這些呼叫會並行執行。持久化 Agent 則會逐一執行，除非 Session 的 `yolo` 狀態已啟用。

以 [`session.permissions.setForCategory()`](/reference/agent-controller/session#sessionpermissionssetforcategory-category-policy-) 設定類別政策，並以 [`session.permissions.setForTool()`](/reference/agent-controller/session#sessionpermissionssetfortool-toolname-policy-) 設定個別 Tool 的政策：

```typescript
await session.permissions.setForCategory({
  category: 'execute',
  policy: 'ask',
})

await session.permissions.setForTool({
  toolName: 'delete_project',
  policy: 'deny',
})
```

若政策結果為 `ask`，請訂閱核准事件，再透過 [`session.respondToToolApproval()`](/reference/agent-controller/session#respondtotoolapproval-decision-toolcallid-requestcontext-declinecontext-) 回傳使用者的決定：

```typescript
session.subscribe(event => {
  if (event.type === 'tool_approval_required') {
    session.respondToToolApproval({
      toolCallId: event.toolCallId,
      decision: 'approve',
    })
  }
})
```

`always_allow_category` 會針對觸發核准的執行緒授予該 Tool 類別的權限。這項授權並非持久化的處理程序層級權限。

[`ask_user`](/reference/tools/ask-user-tool) 與 [`submit_plan`](/reference/tools/submit-plan-tool) 等互動式 Tool 使用可恢復的 Tool 暫停機制。請用 [`session.respondToToolSuspension()`](/reference/agent-controller/session#respondtotoolsuspension-resumedata-address-toolcallid-requestcontext-) 恢復執行：

```typescript
session.subscribe(event => {
  if (event.type === 'tool_suspended' && event.toolName === 'ask_user') {
    void session.respondToToolSuspension({
      toolCallId: event.toolCallId,
      resumeData: 'Use SQLite.',
    })
  }
})
```

對於 `submit_plan`，可以傳入 `{ action: 'approved' }` 或 `{ action: 'rejected', feedback }` 來恢復。計畫獲准後，可先切換至 `transitionsTo` 指定的模式，再繼續執行。

內建 `submit_plan` Tool 接收的是計畫檔案路徑，不是計畫本文。Agent 會先將計畫寫入檔案，再提交路徑，因此需要可寫入的檔案系統，例如 Workspace 檔案系統。應用程式若要顯示計畫供核准，應讀取所提交 `path` 指向的檔案。

## 委派工作給子 Agent {/* #delegate-to-subagents */}

在 Controller 上設定可使用的子 Agent 類型。內建的 `subagent` Tool 隨後便能依這些定義委派特定工作：

```typescript
const controller = new AgentController({
  tools: {
    searchDocs,
  },
  subagents: [
    {
      id: 'code-reviewer',
      name: 'Code reviewer',
      description: 'Review a change for correctness and regressions.',
      instructions: 'Inspect the change and report actionable findings.',
      allowedControllerTools: ['searchDocs'],
      allowedWorkspaceTools: ['view', 'find_files'],
      defaultModelId: '__GATEWAY_OPENAI_MODEL_LUNA__',
    },
  ],
})
```

一般子 Agent 會以其設定的指令與受限 Tool 組合啟動。若子 Agent 應複製父執行緒，並使用父 Agent 的指令及 Tool，請設定 `forked: true`。分支子 Agent 保留父層提示詞前綴，忽略定義中的指令、Tool、允許清單和預設模型，且 Controller 必須啟用記憶體功能。

使用 [`session.subagents.model.set()`](/reference/agent-controller/session#sessionsubagentsmodelset-modelid-agenttype-) 設定共用的預設子 Agent 模型，或為特定 Agent 類型選擇模型。使用 [`session.subagents.model.get()`](/reference/agent-controller/session#sessionsubagentsmodelget-agenttype-) 查詢目前選擇：

```typescript
await session.subagents.model.set({
  modelId: '__GATEWAY_OPENAI_MODEL_LUNA__',
})

await session.subagents.model.set({
  agentType: 'code-reviewer',
  modelId: '__GATEWAY_ANTHROPIC_MODEL_SONNET__',
})

const reviewerModel = session.subagents.model.get({
  agentType: 'code-reviewer',
})
```

選擇結果會寫入執行緒設定。針對 Agent 類型指定的模型，優先於 Session 的預設子 Agent 模型。

## 連接聊天頻道 {/* #connect-chat-channels */}

將頻道轉接器傳給 Controller，並在 [`Mastra`](/reference/core/mastra-class) 實例中註冊：

```typescript title="src/mastra/index.ts"
import { Mastra } from '@mastra/core'
import { AgentController } from '@mastra/core/agent-controller'
import { createSlackAdapter } from '@chat-adapter/slack'

const controller = new AgentController({
  id: 'support-controller',
  agent,
  storage,
  workspace,
  modes,
  channels: {
    adapters: {
      slack: createSlackAdapter(),
    },
    resolveResourceId: ({ thread, message, defaultResourceId }) => {
      if (thread.isDM) return message.author.userId
      return defaultResourceId
    },
    onSessionStart: async ({ session, thread }) => {
      const plan = await billing.planFor(thread.resourceId)
      await session.model.switch(plan.modelId)
    },
  },
})

export const mastra = new Mastra({
  agentControllers: { controller },
  storage,
})
```

將各平台的 webhook 指向此 Controller 專屬的路由：

```text
/api/agent-controllers/<CONTROLLER_ID>/channels/<PLATFORM>/webhook
```

每條外部聊天執行緒都會對應一個 Controller Session 與一條 Mastra 執行緒。預設情況下，新 Session 的資源 ID 取自轉接器的聊天執行緒 ID，並加上 `channel:` 前綴。可透過 `resolveResourceId` 將私人訊息對應至現有的應用程式使用者，或指定其他記憶體擁有者。此回呼僅影響新執行緒；既有執行緒會保留已儲存的資源 ID。

頻道 Session 由 Controller 建立，而非由應用程式碼建立，因此需在 `onSessionStart` 中設定。每個 Session 在綁定對應執行緒後、處理第一則訊息前，會執行此回呼一次。頻道 Session 起初採用 Controller 的預設設定，可在此指定模型及記憶體設定。同一執行緒的後續訊息會重用該 Session，不會再次呼叫回呼。錯誤會記錄於日誌後略過，設定失敗的 Session 仍會回覆訊息。

### 授權並路由頻道 Session {/* #authorize-and-route-channel-sessions */}

`onSessionStart` 在 Session 建立後才執行，而且會略過錯誤，因此無法拒絕請求。若宿主需要決定是否允許建立 Session，請使用 `resolveSession`。它會取代內建的 Session 建立程序，並在 Session 存在前執行。擲出錯誤會在 Controller 建立 Session 或呼叫模型之前拒絕請求。Mastra 會記錄拒絕事件，聊天執行緒不會收到訊息，因此授權說明不會送達頻道。

```typescript oxfmt:false
channels: {
  adapters: { slack: createSlackAdapter() },
  resolveSession: async ({ controller, thread, requestContext }) => {
    const install = await installs.authorize(requestContext.get('teamId'))

    return controller.createSession({
      id: `${install.id}:${thread.id}`,
      resourceId: thread.resourceId,
      threadId: thread.id,
      ownerId: controller.id,
      requestContext,
    })
  },
}
```

在 `thread.resourceId` 之下建立 Session。由於 Session 只能綁定自身擁有的執行緒，若要替對應執行緒指定不同擁有者，請使用 `resolveResourceId`。傳入 `threadId: thread.id`，讓 Session 直接開啟對應執行緒。否則，帶有標籤或 `projectPath` 的 Session 不會將對應執行緒視為自身所有，會先建立額外的空執行緒，再切換過去。Session 依 `id` 取得或建立；若同一執行緒需要分開的 Session，請為每個安裝實例或主體指定獨立 `id`。

其他故障，例如儲存空間中斷或解析器相依元件的錯誤，仍會向執行緒傳送錯誤，避免故障機器人看似刻意保持沉默。若要在程式碼中區分，拒絕請求會產生 `ChannelSessionRejectedError`，原始錯誤保存在其 `cause` 中。

使用者回覆核准卡片時，`resolveSession` 也會連同該動作的請求內容一起執行。共用安裝實例會重新驗證核准者，而不直接信任最初傳送訊息的人。

### 處理失效的核准 {/* #handle-stale-approvals */}

核准關卡保存在記憶體中，因此重啟後才收到的核准回覆都已失效。Mastra 絕不會替失效的動作執行 Tool。請用 `onStaleToolApproval` 結清使用者回覆的那次嘗試，避免直接捨棄：

```typescript oxfmt:false
channels: {
  adapters: { slack: createSlackAdapter() },
  onStaleToolApproval: async ({ decision, toolCallId, runId, memory }) => {
    await runs.markInterrupted({ runId, toolCallId, decision, threadId: memory.thread })
  },
}
```

`runId` 是產生核准卡片時的執行 ID，也就是使用者回覆的那次嘗試；重啟後應以此結清。Session 自身目前的執行 ID 會另以 `currentRunId` 傳入，此時通常為 `null`，或已是另一筆執行。

Controller 的頻道 Session 與自動核准狀態只保存在記憶體中，因此請使用長期運作的伺服器。待處理的核准和即時 Session 狀態不會在處理程序重啟後保留。無法呈現核准控制項的轉接器會自動執行 Tool，不顯示核准提示，避免執行持續暫停。

頻道轉接器設定及各平台 webhook 設定請參閱 [Channels](/docs/channels)。

## 連接 UI {/* #connect-a-ui */}

連接方式取決於 UI 的執行位置。終端 UI 或持有 Controller 的伺服器，可直接持有 `Session` 物件並訂閱事件。瀏覽器 UI 在另一個處理程序中，須經由 Controller 的 HTTP 路由及 [`@mastra/client-js`](/reference/client-js/mastra-client) 存取同一個 Session。

### 伺服器端 Session {/* #server-side-sessions */}

訂閱 Session 事件可取得增量更新。當 UI 需要完整的畫面快照時，可透過 [`session.displayState.get()`](/reference/agent-controller/session#sessiondisplaystateget) 取得彙整後的顯示狀態：

```typescript
const unsubscribe = session.subscribe(event => {
  if (event.type === 'display_state_changed') {
    render(event.displayState)
  }
})

render(session.displayState.get())

// Call when the UI disconnects.
unsubscribe()
```

訂閱依 Session 隔離。同一 Controller 上其他 Session 的事件不會送到這個監聽器。完整的 TUI 範例請參閱[建立程式開發 Agent](https://mastra.ai/blog/building-a-coding-agent)。

### 用戶端 Session {/* #client-side-sessions */}

[`client.getAgentController(key).session(sessionId)`](/reference/client-js/agent-controller) 會回傳以 Session ID 定位的用戶端。請傳入 Controller 在 `new Mastra({ agentControllers })` 中註冊時使用的 key；它可能與 Controller 的 `id` 不同。伺服器會依 ID 取得或建立 Session，因此 `create()` 會恢復既有對話，不會另開新對話。多個 Session 共用一項資源時，請將 `resourceId` 傳給 `create()`；否則資源 ID 預設等於 Session ID：

```typescript title="src/components/agent-session.ts"
import { MastraClient } from '@mastra/client-js'

const client = new MastraClient({ baseUrl: 'http://localhost:4111' })
const session = client.getAgentController('coding-controller').session('user-123')

await session.create()

const subscription = await session.subscribe({
  onEvent: event => handleEvent(event),
  onError: error => showDisconnected(error),
  onReconnect: () => {
    void session.state().then(resync).catch(showDisconnected)
  },
  reconnect: true,
})

// Call when the UI disconnects.
subscription.unsubscribe()
```

`subscribe()` 與處理程序內的監聽器不同：它接收選項物件，且是非同步方法。串流建立後，其 Promise 才會完成；無法連線時則會拒絕，也不會留下背景訂閱。`reconnect: true` 會在既有串流中斷後，使用指數退避方式重新連線。若連線仍開啟卻不再傳輸資料，例如裝置休眠，只要在 `idleTimeoutMs`（預設 `60000`）內連伺服器心跳也未收到，就會視為中斷。

伺服器不會重播串流中斷期間錯過的事件，因此請在 `onReconnect` 中讀取 `session.state()`，取得目前模式、模型與執行緒。用戶端沒有 `session.displayState.get()`。

透過 `session.sendMessage(content)` 傳送工作，或用 `session.sendMessage({ content, files })` 附加 base64 編碼檔案。回覆會以訂閱的 `message_*` 事件送達，不是呼叫的回傳值。收到 `tool_approval_required` 事件時，使用 `session.approveTool(toolCallId, approved)` 回覆；收到 `tool_suspended` 事件時，使用 `session.respondToToolSuspension(toolCallId, resumeData)` 恢復。

`onEvent` 會收到 Session 發出的所有事件。事件類型及縮小其型別範圍的方法，請參閱 [Agent Controller API](/reference/client-js/agent-controller#events)。
