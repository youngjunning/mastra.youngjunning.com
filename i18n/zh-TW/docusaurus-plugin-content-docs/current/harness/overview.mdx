# Harness

Harness 讓 Agent 能長期推進複雜目標，並提供持久化、可檢視且可調整的執行方式。重試或中斷時會保留進度，人員或其他系統也能查看進度、補充上下文、核准動作、調整方向或停止 Agent。

需要持續進行的工作都適合使用 Agent Harness。例如，程式開發 Agent 可跟進變更的 CI 與審查，軟體工廠（如 [Mastra Factory](https://factory.mastra.ai)）可協調多項平行任務，SRE Agent 可隨事件發展調整處置方式，市場拓展 Agent 則能因應客戶帳戶、訊號與對話的變化。

在 Mastra 中，Harness 指一組可跨越單次連續執行來管理 Agent 的功能。你可以單獨採用其中一項，也可以依需求搭配使用。

## 何時使用 Harness {/* #when-to-use-a-harness */}

依 Agent 的需求選擇起點，可採用一項或多項功能。

| 需求 | 建議起點 | 用途 |
| - | - | - |
| 用戶端中斷連線或伺服器重新啟動後，仍可存取執行 | [持久化 Agent](/docs/harness/durable-agents) | 保存執行狀態，讓用戶端重新連上串流。 |
| 執行耗時的 Tool、Workflow 或子 Agent，避免阻塞目前的工作 | [背景工作](/docs/harness/background-tasks) | 以非同步方式完成工作，再將結果傳回 Agent。 |
| 讓 Agent 持續工作直到達成目標 | [目標](/docs/harness/goals) | 持續評估執行緒中的目標，直到完成或達到執行預算上限。 |
| 定期自動啟動工作 | [排程](/docs/harness/schedules) | 依 cron 排程啟動獨立執行，或將提示送到現有執行緒。 |
| 補充上下文、調整進行中的工作，或喚醒閒置執行緒 | [訊號](/docs/signals/overview) | 立即傳遞輸入，或留到下一輪使用。 |
| 回應 GitHub、Slack、持續整合或其他外部系統的變更 | [訊號提供者](/docs/signals/signal-providers) | 追蹤訂閱，將符合條件的事件轉送至 Agent 執行緒。 |
| 建立支援工作階段、模式、狀態、核准與事件的互動產品，或讓使用者調整方向、將後續工作排入佇列及停止執行 | [AgentController](/docs/harness/agent-controller) | 在共用的 Agent 執行階段中提供彼此隔離的工作階段，各自控管執行。 |
| 為 Agent 提供檔案、Shell 與程式開發所需的預設設定 | [`createCodingAgent()`](/reference/coding-agent/create-coding-agent) | 建立預先設定 Workspace、工作追蹤與重試功能的標準 Agent。 |
