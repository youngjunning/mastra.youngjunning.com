# Studio 身分驗證

在 Mastra 伺服器設定 [身分驗證](/docs/auth/overview) 後，Studio 會自動顯示登入畫面並執行存取控制。同一份設定可同時保護 Studio 介面和 API 路由。

若未設定身分驗證，Studio 和所有 API 路由皆可公開存取。

:::note

在正式環境中，使用第三方 Provider 的 Studio 登入畫面、角色型存取控制（RBAC）和細粒度授權（FGA）需要 Mastra 企業版（EE）授權。Simple Auth、JWT 與 API 路由的身分驗證無需此授權。開發環境中的所有功能皆可免授權使用。請見 [需要 EE 授權的功能](/docs/license#what-requires-an-ee-license)。如需更多資訊，請 [聯絡業務](https://mastra.ai/contact)。

:::

:::note
Studio 部署至 Mastra 平台時，預設會使用平台注入的身分驗證，只有你組織的成員可以登入。`server.auth` 只適用於 API 路由。若要停用平台身分驗證，請設定 `MASTRA_PLATFORM_STUDIO_AUTH=disabled`。請見 [Mastra 平台的身分驗證](/docs/mastra-platform/studio#authentication)。
:::

## 何時使用 Studio 身分驗證 {/* #when-to-use-studio-auth */}

* 多位團隊成員需要透過同一個 Studio 部署環境操作 Agent、Workflow 和工具。
* 需要限制哪些人可以執行 Agent、編輯 Workflow 或刪除資料集。
* 需要先透過登入畫面驗證身分，再開放存取 Studio。可提供 SSO、電子郵件與密碼，或兩種方式。

## 快速入門 {/* #quickstart */}

在 Mastra 伺服器的設定中加入身分驗證 Provider。此範例使用 [Simple Auth](/docs/auth/simple-auth) 示範最簡單的設定。

```typescript title="src/mastra/index.ts"
import { Mastra } from '@mastra/core'
import { SimpleAuth } from '@mastra/core/server'

export const mastra = new Mastra({
  server: {
    auth: new SimpleAuth({
      tokens: {
        'my-api-key': {
          id: 'user-1',
          name: 'Alice',
          role: 'admin',
        },
      },
    }),
  },
})
```

完成設定後，Studio 會顯示登入畫面，所有 API 請求都須通過身分驗證。支援的 Provider 完整清單請見 [身分驗證文件](/docs/auth/overview)。

## 運作方式 {/* #how-it-works */}

設定 [`server.auth`](/reference/configuration#serverauth) 會同時將身分驗證套用至下列兩處。

* **Studio 介面**會顯示登入畫面。視 Provider 而定，使用者可用 SSO 或電子郵件與密碼登入，也可能同時提供兩種方式。
* **API 路由**要求所有內建路由（例如 `/api/agents/*` 和 `/api/workflows/*`）及自訂路由都通過身分驗證。無論請求來自 Studio 或直接呼叫 API，都適用。

Studio 會呼叫 `GET /api/auth/capabilities` 端點取得可用功能。回應會指出 Studio 應顯示哪些登入方式。若使用者已通過身分驗證，回應也會包含使用者資訊和權限。

## 透過 URL 傳遞權杖 {/* #pass-a-token-through-the-url */}

其他應用程式內嵌 Studio 或提供 Studio 連結時，可透過 URL 參數 `auth_header` 傳遞授權權杖。若外部應用程式已有權杖，便可直接開啟已通過驗證的 Studio 工作階段，略過登入畫面。

`auth_header` 的值一律寫入 `Authorization` 請求標頭。此參數只設定這個標頭，請將伺服器要求的驗證方式前綴一併填入參數值，例如 `Bearer`。

開啟 Studio 時，請把權杖放在 URL 的查詢字串中。

```text
https://your-studio-host/?auth_header=Bearer%20your-token
```

Studio 會以下列方式處理權杖。

* 載入頁面時讀取一次 `auth_header`，在此工作階段的每個 API 請求中，將其值放入 `Authorization` 標頭送出。
* 從網址列移除 `auth_header`，保留其他查詢參數和 URL 片段。
* 只把權杖保存在記憶體中，不寫入瀏覽器的本機儲存空間。因此重新載入頁面後，權杖不會保留。

權杖透過 URL 參數傳遞，由主應用程式負責產生和傳送 URL。瀏覽器記錄、來源標頭和伺服器存取記錄都可能暴露 URL 參數。

## 角色型存取控制 {/* #role-based-access-control */}

RBAC 控制每位使用者在 Studio 中能看到的內容及可執行的操作。`server.auth` 負責確認使用者身分，`server.rbac` 則管理其操作權限。

### 預設角色 {/* #default-roles */}

Mastra 提供四種預設角色，可從 `@mastra/core/auth/ee` 匯入。

| 角色 | 權限 |
| - | - |
| `owner` | 完整存取權限（`*`） |
| `admin` | 可讀取、寫入、執行、發布和分享，無刪除權限 |
| `member` | 可讀取和執行 |
| `viewer` | 唯讀 |

### 啟用 RBAC {/* #enable-rbac */}

使用 `StaticRBACProvider` 時，可選用預設角色或自行定義角色。

```typescript title="src/mastra/index.ts"
import { Mastra } from '@mastra/core'
import { SimpleAuth } from '@mastra/core/server'
import { StaticRBACProvider, DEFAULT_ROLES } from '@mastra/core/auth/ee'

export const mastra = new Mastra({
  server: {
    auth: new SimpleAuth({
      tokens: {
        'admin-key': { id: 'user-1', name: 'Alice', role: 'admin' },
        'viewer-key': { id: 'user-2', name: 'Bob', role: 'viewer' },
      },
    }),
    rbac: new StaticRBACProvider({
      roles: DEFAULT_ROLES,
      getUserRoles: user => [user.role],
    }),
  },
})
```

啟用 RBAC 後，Studio 會隱藏使用者無權執行的操作。唯讀使用者看不到刪除按鈕，成員也無法修改 Agent 設定。

### 權限格式 {/* #permission-format */}

權限格式為 `{resource}:{action}`，也可進一步限定特定資源。

| 格式 | 意義 |
| - | - |
| `*` | 對所有資源有完整存取權限 |
| `*:read` | 可讀取所有資源 |
| `agents:*` | 可對 Agent 執行所有操作 |
| `agents:execute` | 僅可執行 Agent |
| `agents:read:my-id` | 可讀取指定 ID 的 Agent |

資源包括 `agents`、`workflows`、`tools`、`datasets`、`memory`、`scores`、`observability`、`stored-agents`、`mcp` 等。操作包括 `read`、`write`、`create`、`delete`、`execute`、`publish` 和 `share`。

`mcp:read` 和 `mcp:execute` 控制 [內建 MCP 伺服器](/docs/server/mcp#authentication-and-permissions) 和已註冊 `MCPServer` 實例路由的存取權限。預設的 `viewer` 角色僅有 `mcp:read`，因此可以連線，但只會取得空的工具清單。每次呼叫 MCP 工具也需要相應路由的權限，例如 `agents:execute`。

已儲存的 Agent 預設只有擁有者能存取。`stored-agents:*` 允許使用者檢視和編輯所有已儲存的 Agent。`stored-agents:admin` 可略過擁有者檢查，但使用者仍須具備各路由要求的權限，例如 `stored-agents:read` 或 `stored-agents:write`。預設的 `admin` 角色不含這兩項權限。請見 [已儲存 Agent 的可見性](/docs/studio/editor#visibility)。

### 對應外部 Provider 的角色 {/* #map-external-provider-roles */}

若你的身分 Provider 已定義角色，例如 Clerk 組織或 WorkOS 群組，可以使用 `roleMapping` 將角色對應到 Mastra 權限。

```typescript title="src/mastra/index.ts"
import { StaticRBACProvider } from '@mastra/core/auth/ee'

const rbac = new StaticRBACProvider({
  roleMapping: {
    'org:admin': ['*'],
    'org:member': ['*:read', '*:execute'],
    'org:viewer': ['*:read'],
  },
  getUserRoles: user => user.providerRoles,
})
```

## 登入方式 {/* #login-methods */}

Studio 會依身分驗證 Provider 顯示對應的登入畫面。

| Provider 類型 | 登入介面 |
| - | - |
| 僅 SSO | SSO 按鈕（例如「使用 WorkOS 登入」） |
| 僅電子郵件和密碼 | 電子郵件與密碼表單 |
| 兩種方式 | SSO 按鈕與電子郵件密碼表單 |

可逐一為 Provider 啟用或停用註冊。停用後，Studio 會隱藏註冊連結，只能使用登入表單。
