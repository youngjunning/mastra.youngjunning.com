# Studio 可觀測性

Studio 包含以下可觀察性視圖：

- **Metrics**：查看彙整後的效能資料
- **Traces**：檢視個別請求的執行細節
- **Logs**：瀏覽內部日誌與應用程式日誌

所有這些都需要配置可觀察性儲存後端。

## 快速入門 {/* #quickstart */}

完整設定請見[可觀測性指南](/docs/observability/overview)。若要快速開始，請在專案加入 `@mastra/observability`，搭配 [LibSQL](/integrations/databases/libsql) 與 [DuckDB](/integrations/vectors/duckdb)，讓本機開發環境同時支援 Trace 和指標。

```bash npm2yarn
npm install @mastra/observability @mastra/libsql @mastra/duckdb
```

然後將以下內容添加到您的`src/mastra/index.ts`:

```ts title="src/mastra/index.ts"
import { Mastra } from '@mastra/core/mastra'
import { LibSQLStore } from '@mastra/libsql'
import { DuckDBStore } from '@mastra/duckdb'
import { MastraCompositeStore } from '@mastra/core/storage'
import {
  Observability,
  MastraStorageExporter,
  MastraPlatformExporter,
  SensitiveDataFilter,
} from '@mastra/observability'

export const mastra = new Mastra({
  // highlight-start
  storage: new MastraCompositeStore({
    id: 'composite-storage',
    default: new LibSQLStore({
      id: 'mastra-storage',
      url: 'file:./mastra.db',
    }),
    domains: {
      observability: await new DuckDBStore().getStore('observability'),
    },
  }),
  // highlight-end
  observability: new Observability({
    configs: {
      default: {
        serviceName: 'mastra',
        exporters: [
          new MastraStorageExporter(), // Persists observability events to Mastra Storage
          new MastraPlatformExporter(), // Sends observability events to Mastra platform (if MASTRA_PLATFORM_ACCESS_TOKEN is set)
        ],
        spanOutputProcessors: [
          new SensitiveDataFilter(), // Redacts sensitive data like passwords, tokens, keys
        ],
      },
    },
  }),
})
```

## Mastra 平台 {/* #mastra-platform */}

有關跨專案和部署的託管追蹤、日誌和指標，請參閱[Observability on Mastra platform](/docs/mastra-platform/observability).

## 指標 {/* #metrics */}

指標儀表板彙整指定時間範圍內的 Agent、Workflow 與 Tool 效能，可選最近 24 小時至 30 天。第一列顯示 Agent 執行總次數、模型成本、Token 用量與評分器的平均表現。下方卡片進一步列出各模型的用量與成本、各 Agent 的 Token 用量、各時段的 Token 用量與預估費用、Trace 數量及完成和錯誤次數、延遲百分位數（p50 與 p95），以及評分趨勢。

詳情請見[指標概覽](/docs/observability/metrics/overview)。

:::note

指標須搭配支援這項功能的可觀測性儲存，例如 DuckDB、ClickHouse，或已啟用可觀測性網域的 `PostgresStoreVNext`。LibSQL、MSSQL 與 MongoDB 不支援指標。記憶體中的資料會在重新啟動時清除。完整清單請見[儲存支援](/docs/observability/metrics/overview#storage-support)。

:::

## Trace {/* #traces */}

執行 Agent 或 Workflow 時，**Observability** 分頁會顯示 Trace，標示模型呼叫、Tool 執行與 Workflow 步驟等關鍵操作。沿著 Trace 可查看資料如何傳遞、各操作花了多少時間，以及實際執行過程。

開啟 Trace 清單上方的 **Columns**，即可顯示或隱藏輸入、實體、耗時、輸入 Token、輸出 Token、預估費用與自訂中繼資料欄。Studio 會依目前的 Mastra 伺服器與 API 前綴，將選擇儲存在瀏覽器。

自訂中繼資料欄須搭配支援 Trace 查詢（`queryTraces`）的可觀測性儲存，例如[快速入門](#quickstart)中的 DuckDB。在 **Columns** 選擇 **Add metadata column**，再輸入 `tracingOptions.metadata` 使用的最上層鍵。

若儲存不支援 Trace 查詢（例如只用 LibSQL），Studio 會隱藏 **Add metadata column**，也無法使用中繼資料、標籤等進階篩選。把中繼資料存到 span 並不會啟用這些清單功能。

Token 和預估費用欄須搭配支援指標的可觀測性儲存。由於多列分支可能屬於同一個 Trace，**Branches** 檢視不會顯示這些欄位。

追蹤會篩除底層框架細節，讓 Trace 更容易閱讀。詳情請見 [Trace 使用指南](/docs/observability/tracing/overview)。

若要匯出 Trace，請在面板頂端選擇 **Download trace JSON**。完整 Trace 會儲存為 `trace-<id>.json`，包含每個 span 及其完整輸入、輸出、中繼資料與屬性。你可用這個檔案分享 Trace、附到錯誤回報，或離線建立評估資料集。

## 紀錄 {/* #logs */}

在此可瀏覽送往可觀測性儲存的 Mastra 內部日誌，並對訊息內容、實體名稱與 Trace ID 進行全文搜尋。日期預設範圍為最近 24 小時到 30 天，可依層級、實體類型與實體名稱進行多選篩選。選取日誌即可在詳細資料面板檢視完整訊息、結構化資料和中繼資料。若日誌與 Trace 關聯，可直接開啟該 Trace 和 span 時間軸。

設定可觀測性後，預設會啟用日誌轉送。層級設定、查詢範例及自訂方式請見[日誌指南](/docs/observability/logging)。
