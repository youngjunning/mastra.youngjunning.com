# 工作室Observability

Studio 包含以下可觀察性視圖：

* **指標**用於匯總性能數據
* **痕跡**用於個別請求檢查
* **紀錄**用於瀏覽內部和應用程式日誌

所有這些都需要配置可觀察性儲存後端。

## 快速入門 {/* #quickstart */}

有關詳細說明，請遵循[observability instructions](/docs/observability/overview). To get up and running quickly, add the `@mastra/observability` package to your project and configure it with [LibSQL](/integrations/databases/libsql) and [DuckDB](/integrations/vectors/duckdb) for a local development setup that supports both traces and metrics.

```bash npm2yarn
npm install @mastra/observability @mastra/libsql @mastra/duckdb
```

然後將以下內容添加到您的`src/mastra/index.ts`:

```ts title="src/mastra/index.ts"
import { Mastra } from '@mastra/core/mastra'
import { LibSQLStore } from '@mastra/libsql'
import { DuckDBStore } from '@mastra/duckdb'
import { MastraCompositeStore } from '@mastra/core/storage'
import {
  Observability,
  MastraStorageExporter,
  MastraPlatformExporter,
  SensitiveDataFilter,
} from '@mastra/observability'

export const mastra = new Mastra({
  // highlight-start
  storage: new MastraCompositeStore({
    id: 'composite-storage',
    default: new LibSQLStore({
      id: 'mastra-storage',
      url: 'file:./mastra.db',
    }),
    domains: {
      observability: await new DuckDBStore().getStore('observability'),
    },
  }),
  // highlight-end
  observability: new Observability({
    configs: {
      default: {
        serviceName: 'mastra',
        exporters: [
          new MastraStorageExporter(), // Persists observability events to Mastra Storage
          new MastraPlatformExporter(), // Sends observability events to Mastra platform (if MASTRA_PLATFORM_ACCESS_TOKEN is set)
        ],
        spanOutputProcessors: [
          new SensitiveDataFilter(), // Redacts sensitive data like passwords, tokens, keys
        ],
      },
    },
  }),
})
```

## 指標 {/* #metrics */}

一個儀表板，總結了可配置時間範圍（過去 24 小時到 30 天）內的Agent、Workflow和Tool性能。頂行顯示Agent運行總數、模型成本、​​令牌消耗和平均評分器性能。下面，詳細的卡片詳細列出了模型使用情況和每個模型的成本、每個Agent的令牌使用情況、一段時間內的令牌使用情況和估計成本、已完成和錯誤計數的追蹤量、延遲百分位數（p50 和 p95）以及隨時間變化的記分器趨勢。

參觀[metrics overview](/docs/observability/metrics/overview) for more details.



指標需要支援它們的可觀察性存儲，例如 DuckDB、ClickHouse 或`PostgresStoreVNext` with its observability domain enabled. LibSQL, MSSQL, and MongoDB don't support metrics. In-memory storage resets on restart. See [storage support](/docs/observability/metrics/overview#storage-support) for the full list.

## 痕跡 {/* #traces */}

當您執行Agent程式或Workflow時，「Observability」標籤會顯示突出顯示關鍵 AI 操作（例如模型呼叫、Tool執行和Workflow步驟）的追蹤。追蹤這些痕跡可以了解數據如何移動、時間花在哪裡以及幕後發生了什麼。

在追蹤列表上方，打開**Columns** to show or hide input, entity, duration, input token, output token, estimated cost, and custom metadata columns. Studio saves the selection in browser storage for the current Mastra server and API prefix.

自訂元資料列需要支援追蹤查詢的可觀察性儲存（`queryTraces`), such as the DuckDB observability store in the [quickstart](#quickstart). In **Columns**, select **Add metadata column** and enter the top-level key used in `tracingOptions.metadata`.

對於不支援追蹤查詢的儲存（例如單獨的 LibSQL），Studio 會隱藏**Add metadata column**. Advanced filters, including metadata and tags, are also unavailable. Storing metadata on spans doesn't enable these trace-list features.

令牌和估計成本列需要支援指標的可觀察性儲存。這些列隱藏在**Branches** view because several branch rows can belong to the same trace.

追蹤會過濾掉低階框架細節，以便您的追蹤保持專注且可讀。訪問[Traces usage](/docs/observability/tracing/overview) for more details.

若要匯出軌跡，請選擇**Download trace JSON** in the trace panel header. This saves the entire trace as a `trace-<id>.json` file, with every span and its full input, output, metadata, and attributes. Use it to share a trace or attach it to a bug report, or alternatively build an evaluation dataset offline.
