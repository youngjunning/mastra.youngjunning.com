# Studio

Studio 提供互動介面，可建立、測試及管理 Agent、Workflow 與工具。開發時可在本機執行，也可加入[身分驗證](/docs/studio/auth)，或[部署到正式環境](/docs/studio/deployment)，讓團隊管理 Agent、監控效能，並透過內建的可觀測性功能掌握執行情況。

:::tip[📹 觀看影片]

觀看 [Mastra Studio 概覽](https://youtu.be/ojGu6Bi4wYk)，快速了解如何在 Studio 建立、測試及管理 Agent。

:::

## 启动 Studio {/* #start-studio */}

若使用 `create mastra` 建立應用程式，請以 `dev` 指令碼啟動開發伺服器，也可直接執行 `mastra dev`。

```bash npm2yarn
npm run dev
```

服务器启动后，您可以：

- 在 [`localhost:4111`](http://localhost:4111/) 開啟 Studio 介面，與 Agent、Workflow 和工具互動。
- 前往 [`localhost:4111/swagger-ui`](http://localhost:4111/swagger-ui)，探索並試用底層 REST API。

Studio 讓您即時編輯 [Agent](/docs/agents/overview)、[Workflow](/docs/workflows/overview) 與 Mastra 應用程式的其他部分。

## 部署 Studio {/* #deploy-studio */}

若要與團隊共用 Studio，可以透過 [Mastra 平台上的 Studio](/docs/mastra-platform/studio) 或自己的基礎架構部署到正式環境。詳細步驟請參閱[部署文件](/docs/studio/deployment)。

## 基本元件 {/* #primitives */}

### Agent {/* #agents */}

直接與 Agent 對話、切換[模型](/models)，再調整 temperature 和 top-p 等設定，觀察它們如何影響輸出。

若目錄有提供發布日期，模型選擇器會在各 Provider 下優先顯示較新的模型。同日發布的模型依字母順序排列。沒有日期的模型也依字母排序，列在有日期的模型之後。

若要讓模型選擇器只列出自己[自訂閘道](/models/gateways/custom-gateways)的模型，請設定 `AUTO_BLOCK_EXTERNAL_PROVIDERS=true`。請參閱[在 Studio 只顯示自訂閘道](/models/gateways/custom-gateways#showing-only-custom-gateways-in-studio)。

與 Agent 互動時，可以查看推理過程及工具呼叫的輸出，也可[觀察追蹤記錄與日誌](#observability)，了解回覆的生成過程。

如果回覆有 Markdown 表格，可選取表格上方的 **Copy table as markdown**，單獨複製表格。複製結果會保留 Markdown 格式，並加入表格使用的連結與註腳定義。若要下載 CSV，請展開複製按鈕旁的箭頭，再選取 **Download CSV**。含有表格的文字片段串流完畢並完整顯示後，就能使用這兩項操作。此時 Agent 可能還在執行工具或撰寫後續片段。

CSV 會匯出儲存格的純文字。連結只保留顯示文字，註腳只保留標記，網址和註腳定義不會匯出。可能被試算表軟體解讀成公式的值，開頭會加上單引號，讓軟體當作文字處理。一般帶正負號的數字會原樣保留。

也可加入[評分器](#scorers)，持續衡量並比較回覆品質。

若要針對回覆中的一段文字提問，請選取該段，再選擇 **Add to chat**，也可按 Tab 鍵把焦點移到此選項。每個加入的段落都會在對話中顯示帶編號的註解泡泡，訊息輸入框會顯示總數，例如 **2 annotations**。選取泡泡可撰寫註解或移除該段，也可開啟計數清單，在對話中找到原文。送出後，Agent 會先收到依序編號的段落引文及各段註解，再收到您輸入的文字。也可以只送出註解。選取範圍若跨越兩則訊息，就不會提供 **Add to chat**。

Agent 串流回覆時，您可以在同一對話串傳送後續訊息。Studio 會先將訊息標為等待確認，等串流確認後，再在該訊息下方繼續顯示回覆。開啟同一對話串的其他 Studio 分頁也能看到正在進行的串流。

透過 [Editor](/docs/studio/editor)，非技術團隊成員也能持續調整 Agent、為每次變更保留版本，並在無須重新部署的情況下執行實驗。

使用 [Agent Builder](https://agent-builder.mastra.ai) 的獨立瀏覽器介面，建立和管理完整保存於儲存層的 Agent。

#### 模型面板 {/* #models-panel */}

開啟 Agent 的 **Models** 面板，即可依優先順序查看主要與備援模型。若是靜態模型清單，可重新排序、啟用或停用備援模型，也可變更 Provider 或模型。Studio 重新擷取 Agent 時，面板會同步更新。

Agent 設定 `editor: { model: true }` 時，這些修改會透過 [Editor](/docs/studio/editor#decide-what-collaborators-can-edit) 儲存。必須同時設定 `MastraEditor` 和 Agent 儲存空間，缺少任一項都會使儲存失敗並傳回 HTTP 500。未設定該選項時，修改只會套用到執行中伺服器記憶體內的 Agent，重新啟動後便會消失。其他 Agent 的持久化編輯進度請參閱 [GitHub issue #27089](https://github.com/mastra-ai/mastra/issues/27089)。

以函式提供的模型清單可能隨請求情境變化，因此在 Studio 中是唯讀的。若要修改動態模型清單，請直接修改程式碼。

### Workflow {/* #workflows */}

以流程圖查看 Workflow，並用自訂輸入逐步執行。執行時，介面會即時顯示目前步驟和經過的路徑。

Workflow 的追蹤記錄會顯示工具呼叫、原始 JSON 輸出及執行錯誤。

從執行按鈕旁選取 **Run options**，即可為要啟動的執行設定 **Resource ID**。Studio 會依 Workflow 記住這個值，可用 `GET /api/workflows/:workflowId/runs?resourceId=...` 列出 Studio 建立的執行。留空就會建立不關聯資源的執行。若伺服器依已驗證的使用者取得資源 ID，會優先採用伺服器的值。

### 处理器 {/* #processors */}

可查看各 Agent 掛載的輸入與輸出處理器。Agent 詳細資料面板會列出每個處理器的名稱和類型，方便在測試前確認防護機制、Token 限制器與自訂處理器都已正確接上。

設定方式請參閱[處理器](/docs/agents/processors)與[防護機制](/docs/agents/guardrails)。

### MCP 服务器 {/* #mcp-servers */}

可列出連接到 Mastra 執行個體的 MCP 伺服器，並查看它們提供的工具。清單第一項是 **Mastra (built-in)**，也就是位於 `/api/mcp` 的[內建 MCP 伺服器](/docs/server/mcp#in-studio)，其中提供端點 URL、是否需要權杖，以及 Claude Code、Cursor、VS Code 和 MCP Inspector 的設定方式。

### 工具 {/* #tools */}

將工具指派給 Agent 前，可先單獨執行，觀察及測試工具的行為。若發生問題，可單獨重跑該工具以偵錯。

### Workspace {/* #workspaces */}

使用內建檔案瀏覽器查看 Agent 的 Workspace 檔案系統。可切換掛載點、建立目錄，以及查看有語法醒目提示的檔案內容。可寫入的 Workspace 允許建立目錄和刪除檔案，唯讀的 Workspace 會加上標記。Skill 會出現在檔案樹中。您可以從 [skills.sh](https://skills.sh) 安裝社群 Skill、更新已安裝的 Skill，或刪除 Skill 資料夾來移除它。

配置详情见 [Workspace](/docs/sandbox/overview)。

### 請求情境 {/* #request-context */}

透過相依性注入將執行階段變數傳入 Agent 的指令與工具。可以 JSON 編輯請求情境，若 Agent 已定義 `requestContextSchema`，也可使用依該結構產生的表單。這些值會在測試對話和實驗之間保留，無須重新啟動即可觸發條件流程。

設定方式請參閱[請求情境](/docs/server/request-context)。

## 评估 {/* #evaluation */}

### 评分器 {/* #scorers */}

Scorers 分頁會在 Agent 的評分器執行時顯示結果。訊息經過 Agent 時，已定義的評分器會非同步評估每項輸出並在此顯示結果。您可以查看評分器在不同互動中的表現、比較各測試案例，並找出可改進之處。

### 資料集 {/* #datasets */}

建立並管理用於評估 Agent 與 Workflow 的測試案例集合。可從 CSV 或 JSON 匯入項目、定義輸入及標準答案的結構，並鎖定特定版本以完整重現實驗。使用[評分器](/docs/evals/overview)執行實驗，可比較提示詞、模型或程式碼變更對品質的影響。

完整的 API 和版本管理說明請參閱[資料集概覽](/docs/evals/datasets)。

### 实验 {/* #experiments */}

讓資料集的所有項目通過指定的 Agent、Workflow 或評分器，並集中收集結果。選取目標，視需要加上評分器，再啟動實驗。結果畫面會列出各項目的輸入、輸出、狀態與評分明細。可並排查看兩到十個實驗並與基準比較，衡量提示詞、模型或程式碼變更的影響。

設定方式請參閱[資料集概覽](/docs/evals/datasets)。

## 设置 {/* #settings */}

可在設定頁面設定 Studio 與 Mastra 伺服器的連線。頁面包含以下選項：

- **Mastra instance URL**：Mastra 伺服器的基底 URL，例如 `http://localhost:4111`。
- **API prefix**：所有 API 請求共用的選用路徑前綴，預設為 `/api`。
- **Custom headers**：在每個請求中加上鍵值對，可用來傳送身分驗證權杖或路由標頭。
- **Theme**：切換深色、淺色或跟隨系統的主題。

## 在代码中配置 {/* #code-configuration */}

除了[設定](#settings)介面，也可透過 `src/mastra/index.ts` 裡的 [`server`](/reference/configuration#server-options) 選項設定本機開發伺服器和 Studio。

Studio 預設在 [http://localhost:4111](http://localhost:4111) 執行。可變更 [`host`](/reference/configuration#serverhost) 與 [`port`](/reference/configuration#serverport)。

Mastra 也支援以 [`--https`](/reference/cli/mastra#--https) 旗標進行 HTTPS 開發，並自動建立及管理專案憑證。執行 `mastra dev --https` 時，會為 localhost 或您設定的主機產生私密金鑰和憑證。詳細資訊請參閱 [HTTPS 參考](/reference/configuration#serverhttps)。
