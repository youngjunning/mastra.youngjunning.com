# 可觀察性

Mastra 的可觀察性系統可讓您了解每個Agent程式運行、Workflow步驟、Tool呼叫和模型互動。Agent行為取決於模型回應、提示、Tool、記憶體和Workflow狀態，因此可觀察性可以幫助您從第一天開始檢查執行時間決策。

從追蹤相關的頁面開始：

* [**用法**](/docs/observability/tracing/overview)：檢查執行的跨距層次結構、輸入、輸出、令牌使用、計時和追蹤上下文。
* [**記錄**](/docs/observability/logging)：轉發來自應用程式和 Mastra 內部的結構化日誌條目，自動與追蹤相關聯。
* [**回饋**](/docs/observability/feedback)：儲存與跡線和跨度關聯的評分、評論、更正和其他評論訊號。
* [**貯存**](#storage)：選擇用於持久追蹤、日誌、指標聚合和回饋查詢的後端。

使用[**Metrics**](/docs/observability/metrics/overview) to analyze aggregate usage, performance, and cost data derived from spans. No additional instrumentation is required. Use [**Configuration**](#configuration) to enable the signals and exporters your application needs.

## 何時使用可觀察性 {/* #when-to-use-observability */}

* 透過檢查完整的決策路徑、Tool呼叫和模型回應來調試意外的Agent行為。
* 監控Agent商、Workflow和Tool之間的延遲以識別瓶頸。
* 隨著時間的推移追蹤代幣消耗和估計成本以控制支出。
* 透過追蹤每個步驟的執行情況來診斷Workflow故障。
* 比較提示或模型變更之前和之後的Agent性能。

## 各個部分如何組合在一起 {/* #how-the-pieces-fit-together */}

配置可觀察性後，每個Agent運行、Workflow執行、Tool呼叫和模型互動都會產生一個[span](https://opentelemetry.io/docs/concepts/signals/traces/#spans). Mastra organizes related spans into traces that show the full request lifecycle as a hierarchical timeline.

當跨度結束時，Mastra 會提取持續時間、令牌計數和成本估算，而無需任何額外程式碼。這些指標為聚合儀表板提供支援[Studio](/docs/studio/observability).

每一個`logger.info()`, `logger.warn()`, or `logger.error()` call within a traced context is tagged with the current trace and span IDs. You can move from a log entry directly to the trace that produced it.

回饋記錄人工審核訊號，例如評級、評論和更正。回饋可以連結到追蹤和跨度，然後使用用於指標的相同可觀察性儲存進行查詢。

這些記錄共用相關字段，例如追蹤 ID、跨度 ID、實體類型和實體名稱。您可以使用它們從指標峰值轉移到其追蹤、日誌和相關回饋。

## 快速入門 {/* #quickstart */}

安裝`@mastra/observability` and storage backends that support traces and metrics:

```bash npm2yarn
npm install @mastra/observability @mastra/libsql @mastra/duckdb
```

然後在您的 Mastra 實例中配置可觀察性。以下範例使用複合儲存將Observability資料路由到 DuckDB（支援指標聚合），同時將其他所有內容保留在 LibSQL 中：

```ts title="src/mastra/index.ts"
import { Mastra } from '@mastra/core/mastra'
import { LibSQLStore } from '@mastra/libsql'
import { DuckDBStore } from '@mastra/duckdb'
import { MastraCompositeStore } from '@mastra/core/storage'
import {
  Observability,
  MastraStorageExporter,
  MastraPlatformExporter,
  SensitiveDataFilter,
} from '@mastra/observability'

export const mastra = new Mastra({
  storage: new MastraCompositeStore({
    id: 'composite-storage',
    default: new LibSQLStore({
      id: 'mastra-storage',
      url: 'file:./mastra.db',
    }),
    domains: {
      observability: await new DuckDBStore().getStore('observability'),
    },
  }),
  observability: new Observability({
    configs: {
      default: {
        serviceName: 'mastra',
        exporters: [
          new MastraStorageExporter(), // Persists observability events to Mastra Storage
          new MastraPlatformExporter(), // Sends observability events to Mastra platform (if MASTRA_PLATFORM_ACCESS_TOKEN is set)
        ],
        spanOutputProcessors: [
          new SensitiveDataFilter(), // Redacts sensitive data like passwords, tokens, keys
        ],
      },
    },
  }),
})
```

它支援追蹤、日誌轉發和指標。 Mastra 也支援外部追蹤Provider，例如 Langfuse、Datadog 和任何 OpenTelemetry 相容平台。看[Maintaining Studio access](#maintaining-studio-access) to keep Mastra Studio access while sending data to an external provider.

## 配置 {/* #configuration */}

可觀察性在 Mastra 實例上配置一次，並適用於追蹤、日誌和指標。

### 基本配置 {/* #basic-config */}

可觀察性配置通常包含：

* `serviceName`：附加到導出的Observability資料的服務識別碼。
* `exporters`：追蹤、日誌和衍生指標的一個或多個目標。
* `spanOutputProcessors`：在導出跨距之前執行的轉換。

### 維護 Studio 存取權限 {/* #maintaining-studio-access */}

當您新增外部匯出器時，請保留`MastraStorageExporter` for Studio observability and/or `MastraPlatformExporter` for hosted Mastra platform observability.

以下範例僅顯示可觀察性配置。單獨配置儲存。

```ts title="src/mastra/observability.ts"
import { Observability, MastraStorageExporter, MastraPlatformExporter } from '@mastra/observability'
import { ArizeExporter } from '@mastra/arize'

export const observability = new Observability({
  configs: {
    production: {
      serviceName: 'my-service',
      exporters: [
        new ArizeExporter({
          endpoint: process.env.PHOENIX_COLLECTOR_ENDPOINT,
          apiKey: process.env.PHOENIX_API_KEY,
        }),
        new MastraStorageExporter(),
        new MastraPlatformExporter(),
      ],
    },
  },
})
```

### 無伺服器環境中的刷新 {/* #flushing-in-serverless-environments */}

在無伺服器環境中，在運行時暫停或退出之前刷新可觀察性導出器：

```ts
await mastra.observability.flush()
```

在無伺服器環境中使用外部儲存而不是本機檔案儲存。看[Storage](#storage) for storage selection and routing.

### 多配置設定 {/* #multi-config-setup */}

當不同的環境或請求類型需要不同的匯出器或取樣行為時，請使用多個設定。在运行时选择活动配置`configSelector`.

```ts title="src/mastra/index.ts"
import { Mastra } from '@mastra/core'
import { Observability, MastraStorageExporter } from '@mastra/observability'
import { LangfuseExporter } from '@mastra/langfuse'

const storageExporter = new MastraStorageExporter()
const langfuseExporter = new LangfuseExporter()

export const mastra = new Mastra({
  observability: new Observability({
    configs: {
      development: {
        serviceName: 'my-service-dev',
        exporters: [storageExporter],
      },
      production: {
        serviceName: 'my-service-prod',
        exporters: [storageExporter, langfuseExporter],
      },
    },
    configSelector: () => process.env.NODE_ENV || 'development',
  }),
})
```

有關微量採樣，請參閱[Tracing](/docs/observability/tracing/overview).

## 貯存 {/* #storage */}

儲存決定哪些可觀察性訊號持續存在、哪些查詢可用、指標聚合是否有效。使用專用的可觀察性儲存而不是主應用程式儲存。

### 訊號支援 {/* #signal-support */}

儲存支援取決於訊號和工作負載。`MastraStorageExporter` can persist traces to ClickHouse, PostgreSQL, MSSQL, MongoDB, and LibSQL. Metrics require an analytics-capable store:

* DuckDB：推薦用於本地測試和開發。
* ClickHouse：推薦用於大量生產可觀察性。
* `PostgresStoreVNext`：啟用可觀測域時支援指標。始終提供一個時間範圍以避免完整分區掃描。
* Mastra 平台：使用`MastraPlatformExporter` for hosted observability without managing the backend yourself.

[Mastra Storage exporter](/docs/observability/integrations/exporters/mastra-storage#storage-provider-support). Use composite storage to route the `observability` domain separately when your primary store doesn't support observability or when the workload needs independent scaling.

### 當地發展 {/* #local-development */}

對於本機開發，請使用：

* `LibSQLStore`用於主應用程式存儲
* `DuckDBStore`為`observability` domain
* `MastraStorageExporter`用於本地工作室訪問

### 生產部署 {/* #production-deployment */}

可觀察性流量通常比應用程式的其餘部分寫入量更大。生產中：

* 使用`MastraStorageExporter` with ClickHouse for the `observability` domain when you keep observability in your own storage.
* 使用`MastraPlatformExporter` for hosted Mastra platform observability instead of managing the backend yourself.
* 當可觀察性需要與主要應用程式資料不同的後端或擴展策略時，請使用複合存儲。

有關後端相容性詳細資訊和匯出器批次行為，請參閱[Mastra Storage exporter](/docs/observability/integrations/exporters/mastra-storage).
