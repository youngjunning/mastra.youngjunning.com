# 可觀測性

透過 Mastra 的可觀測性系統，你可以檢視每次 Agent 執行、Workflow 步驟、Tool 呼叫與模型互動。模型回應、提示、Tool、記憶及 Workflow 狀態都會影響 Agent 的行為，因此從開發第一天起，就能利用可觀測性檢查執行時的決策。

可以從以下與 Trace 關聯的功能開始：

- [**用量**](/docs/observability/tracing/overview)：檢視一次執行的 Span 階層、輸入、輸出、token 用量、耗時與 Trace 上下文。
- [**日誌**](/docs/observability/logging)：轉送應用程式及 Mastra 內部的結構化日誌，自動連結至 Trace。
- [**回饋**](/docs/observability/feedback)：儲存評分、意見、修正內容與其他審查訊號，並連結至 Trace 和 Span。
- [**儲存**](#storage)：選擇後端，以持久儲存 Trace 和日誌、彙總指標並查詢回饋。

使用[**指標**](/docs/observability/metrics/overview)分析從 Span 彙整的用量、效能與成本資料，無須額外加入量測程式碼。透過[**設定**](#configuration)啟用應用程式所需的訊號和匯出器。

## 何時使用可觀測性 {/* #when-to-use-observability */}

- 檢視完整決策路徑、Tool 呼叫與模型回應，釐清 Agent 的非預期行為。
- 監控 Agent、Workflow 和 Tool 的延遲，找出效能瓶頸。
- 追蹤一段時間內的 token 用量與估計成本，以控制支出。
- 追蹤各步驟的執行情況，找出 Workflow 失敗的原因。
- 比較變更提示或模型前後的 Agent 表現。

## 各類資料如何串連 {/* #how-the-pieces-fit-together */}

設定可觀測性後，每次 Agent 執行、Workflow 執行、Tool 呼叫與模型互動都會產生一個 [Span](https://opentelemetry.io/docs/concepts/signals/traces/#spans)。Mastra 將相關的 Span 組成 Trace，以階層式時間軸呈現請求的完整生命週期。

Span 結束時，Mastra 會自動擷取執行時間、token 數量與估計成本，無須另外撰寫程式碼。[Studio](/docs/studio/observability) 的彙總儀表板會使用這些指標。

在受追蹤的上下文中，每次呼叫 `logger.info()`、`logger.warn()` 或 `logger.error()` 都會標記目前的 Trace ID 和 Span ID，因此可從日誌直接找到產生該筆記錄的 Trace。

回饋會記錄評分、意見和修正內容等人工審查訊號。你可以將回饋連結至 Trace 與 Span，再透過存放指標的同一個可觀測性儲存空間查詢。

這些記錄共用 Trace ID、Span ID、實體類型和實體名稱等關聯欄位。指標突然升高時，可以利用這些欄位查找相關的 Trace、日誌與回饋。

## 快速上手 {/* #quickstart */}

安裝 `@mastra/observability` 及支援 Trace 和指標的儲存後端：

```bash npm2yarn
npm install @mastra/observability @mastra/libsql @mastra/duckdb
```

接著在 Mastra 執行個體中設定可觀測性。下列範例使用複合儲存，將可觀測性資料送到支援指標彙總的 DuckDB，其餘資料則放在 LibSQL：

```ts title="src/mastra/index.ts"
import { Mastra } from '@mastra/core/mastra'
import { LibSQLStore } from '@mastra/libsql'
import { DuckDBStore } from '@mastra/duckdb'
import { MastraCompositeStore } from '@mastra/core/storage'
import {
  Observability,
  MastraStorageExporter,
  MastraPlatformExporter,
  SensitiveDataFilter,
} from '@mastra/observability'

export const mastra = new Mastra({
  storage: new MastraCompositeStore({
    id: 'composite-storage',
    default: new LibSQLStore({
      id: 'mastra-storage',
      url: 'file:./mastra.db',
    }),
    domains: {
      observability: await new DuckDBStore().getStore('observability'),
    },
  }),
  observability: new Observability({
    configs: {
      default: {
        serviceName: 'mastra',
        exporters: [
          new MastraStorageExporter(), // Persists observability events to Mastra Storage
          new MastraPlatformExporter(), // Sends observability events to Mastra platform (if MASTRA_PLATFORM_ACCESS_TOKEN is set)
        ],
        spanOutputProcessors: [
          new SensitiveDataFilter(), // Redacts sensitive data like passwords, tokens, keys
        ],
      },
    },
  }),
})
```

上述設定會啟用追蹤、日誌轉送和指標。Mastra 也支援 Langfuse、Datadog 等外部追蹤 Provider，以及任何相容於 OpenTelemetry 的平台。若要在傳送資料給外部 Provider 的同時，繼續從 Mastra Studio 檢視資料，請參閱[保留 Studio 存取功能](#maintaining-studio-access)。

## 設定 {/* #configuration */}

可觀測性只需在 Mastra 執行個體中設定一次，即適用於 Trace、日誌和指標。

### 基本設定 {/* #basic-config */}

可觀測性設定通常包含以下選項：

- `serviceName`：附在匯出資料上的服務識別碼。
- `exporters`：接收 Trace、日誌與衍生指標的一個或多個目的地。
- `spanOutputProcessors`：在匯出 Span 前套用的轉換。

### 保留 Studio 存取功能 {/* #maintaining-studio-access */}

加入外部匯出器時，若要繼續在 Studio 查看可觀測性資料，請保留 `MastraStorageExporter`。若要使用 Mastra Platform 託管的可觀測性功能，請保留 `MastraPlatformExporter`。可以依需求保留其中一個或同時保留兩個。

下列範例只列出可觀測性設定。請另外設定儲存空間。

```ts title="src/mastra/observability.ts"
import { Observability, MastraStorageExporter, MastraPlatformExporter } from '@mastra/observability'
import { ArizeExporter } from '@mastra/arize'

export const observability = new Observability({
  configs: {
    production: {
      serviceName: 'my-service',
      exporters: [
        new ArizeExporter({
          endpoint: process.env.PHOENIX_COLLECTOR_ENDPOINT,
          apiKey: process.env.PHOENIX_API_KEY,
        }),
        new MastraStorageExporter(),
        new MastraPlatformExporter(),
      ],
    },
  },
})
```

### 在無伺服器環境中送出待匯出的資料 {/* #flushing-in-serverless-environments */}

在無伺服器環境中，請在執行環境暫停或結束前，讓可觀測性匯出器送出待匯出的資料：

```ts
await mastra.observability.flush()
```

無伺服器環境應使用外部儲存，避免依賴本機檔案。儲存空間的選擇與路由方式請參閱[儲存](#storage)。

### 使用多組設定 {/* #multi-config-setup */}

如果不同環境或請求類型需要不同的匯出器或取樣方式，可以使用多組設定，再透過 `configSelector` 在執行時選擇要套用的設定。

```ts title="src/mastra/index.ts"
import { Mastra } from '@mastra/core'
import { Observability, MastraStorageExporter } from '@mastra/observability'
import { LangfuseExporter } from '@mastra/langfuse'

const storageExporter = new MastraStorageExporter()
const langfuseExporter = new LangfuseExporter()

export const mastra = new Mastra({
  observability: new Observability({
    configs: {
      development: {
        serviceName: 'my-service-dev',
        exporters: [storageExporter],
      },
      production: {
        serviceName: 'my-service-prod',
        exporters: [storageExporter, langfuseExporter],
      },
    },
    configSelector: () => process.env.NODE_ENV || 'development',
  }),
})
```

Trace 取樣方式請參閱[追蹤](/docs/observability/tracing/overview)。

## 儲存 {/* #storage */}

儲存後端會決定可持久儲存哪些可觀測性訊號、能執行哪些查詢，以及能否彙總指標。請為可觀測性使用專用的儲存空間，與應用程式的主要儲存空間分開。

### 訊號支援 {/* #signal-support */}

儲存後端的支援情況取決於訊號與工作負載。`MastraStorageExporter` 可將 Trace 持久儲存到 ClickHouse、PostgreSQL、MSSQL、MongoDB 和 LibSQL。指標需要具備分析能力的儲存後端：

- DuckDB：建議用於本機測試和開發。
- ClickHouse：建議用於可觀測性資料量較大的正式環境。
- `PostgresStoreVNext`：啟用可觀測性網域後即支援指標。查詢時務必指定時間範圍，避免掃描整個分割區。
- Mastra Platform：使用 `MastraPlatformExporter` 即可使用託管的可觀測性功能，無須自行管理後端。

完整的 Provider 清單及支援的追蹤策略請見 [Mastra Storage 匯出器](/docs/observability/integrations/exporters/mastra-storage#storage-provider-support)。如果主要儲存空間不支援可觀測性，或可觀測性工作負載需要獨立調整規模，請使用複合儲存，將 `observability` 網域的資料導向個別的後端。

### 本機開發 {/* #local-development */}

在本機開發時，可採用以下設定：

- 將 `LibSQLStore` 用於應用程式的主要儲存空間。
- 將 `DuckDBStore` 用於 `observability` 網域。
- 使用 `MastraStorageExporter`，讓本機 Studio 可存取資料。

### 正式環境部署 {/* #production-deployment */}

相較於應用程式的其他資料，可觀測性資料通常有較高的寫入負載。正式環境可依下列方式配置：

- 自行儲存可觀測性資料時，為 `observability` 網域搭配使用 `MastraStorageExporter` 與 ClickHouse。
- 使用 `MastraPlatformExporter`，即可使用 Mastra Platform 託管的可觀測性功能，省去自行管理後端的工作。
- 如果可觀測性資料與應用程式的主要資料需要不同的後端或擴展策略，請使用複合儲存。

後端相容性及匯出器的批次處理方式，請參閱 [Mastra Storage 匯出器](/docs/observability/integrations/exporters/mastra-storage)。
