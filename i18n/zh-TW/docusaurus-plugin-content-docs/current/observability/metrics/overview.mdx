# 指標

受追蹤的作業結束後，Mastra 會根據 Span 自動產生指標，不必另外加入指標埋點。

Mastra 會產生下列指標。

- **執行時間**。記錄 Agent 執行、Workflow、Tool、模型呼叫與處理器的耗時。
- **Token 用量**。記錄模型輸入與輸出的用量。若供應商有提供各類 Token 的明細，也會納入。
- **成本估算**。依據 Token 用量、供應商、模型，以及 [models.dev](https://models.dev) 或[自訂閘道](/models/gateways/custom-gateways#model-pricing)提供的模型價格計算。

指標會保留與 Trace 的關聯。圖表出現變化時，可找到對應的 Span 進一步調查。指標名稱、標籤與成本欄位請參閱[自動指標參考](/reference/observability/metrics/automatic-metrics)。

## 何時使用指標 {/* #when-to-use-metrics */}

- 監控 Agent、Tool、Workflow 與模型呼叫的延遲
- 追蹤 Token 用量及估算成本的變化趨勢
- 比較各個 Agent 或 Tool 的成功率與錯誤率
- 衡量提示詞、模型或程式碼變更的成效

## 支援的儲存後端 {/* #storage-support */}

請使用具備分析功能的可觀測性儲存後端。

- **DuckDB**。本機開發建議透過 `@mastra/duckdb` 使用。
- **ClickHouse**。正式環境的工作負載較大時，建議透過 `@mastra/clickhouse` 使用。
- **PostgresStoreVNext**。啟用可觀測性網域後即支援指標。
- **記憶體儲存**。支援指標，但程序重新啟動後資料會遺失。
- **Google Cloud Spanner**。預設停用指標。只有在負載較輕時才設定 `disableMetrics: false`，也可以將指標導向專用的 OLAP 儲存後端。

LibSQL、MSSQL 和 MongoDB 等其他儲存配接器可以儲存其他可觀測性訊號，但不支援儲存或查詢指標。

## 在本機設定指標 {/* #set-up-local-metrics */}

安裝可觀測性、應用程式儲存與 DuckDB 套件。

```bash npm2yarn
npm install @mastra/observability @mastra/libsql @mastra/duckdb
```

設定複合儲存，將可觀測性網域導向 DuckDB。

```ts title="src/mastra/index.ts"
import { Mastra } from '@mastra/core/mastra'
import { LibSQLStore } from '@mastra/libsql'
import { DuckDBStore } from '@mastra/duckdb'
import { MastraCompositeStore } from '@mastra/core/storage'
import { Observability, MastraStorageExporter, SensitiveDataFilter } from '@mastra/observability'

export const mastra = new Mastra({
  storage: new MastraCompositeStore({
    id: 'composite-storage',
    default: new LibSQLStore({
      id: 'mastra-storage',
      url: 'file:./mastra.db',
    }),
    domains: {
      observability: await new DuckDBStore().getStore('observability'),
    },
  }),
  observability: new Observability({
    configs: {
      default: {
        serviceName: 'mastra',
        exporters: [new MastraStorageExporter()],
        spanOutputProcessors: [new SensitiveDataFilter()],
      },
    },
  }),
})
```

`MastraStorageExporter` 會將指標寫入設定的可觀測性儲存，讓 Studio 讀取。若要將指標傳送至 Mastra Platform，可改用 `MastraPlatformExporter`，或同時使用兩者。

## 檢視與查詢指標 {/* #view-and-query-metrics */}

在 [Studio 可觀測性儀表板](/docs/studio/observability)查看 KPI 卡片、分類明細與時間序列圖表。若要建立自訂儀表板或分析資料，可用 `@mastra/client-js`，也可使用[指標查詢參考](/reference/observability/metrics/queries)說明的可觀測性儲存、HTTP 端點或 CLI。

在正式環境查詢指標時，一律指定時間戳記範圍。限定時間可減少掃描的資料量，讓採用分割區的後端略過無關的分割區或資料區塊。
