# 回饋

回饋記錄可保留人工參與的訊號，例如按讚或倒讚、評分、留言和修正。若要將使用者、QA、Studio 或系統的審查資料連結至 Trace 或 Span，並與其他可觀測性訊號一併查詢，可使用回饋。

回饋通常由人員或審查 Workflow 提供，這點與指標及分數不同。數值型回饋可用來彙總、分組、繪製時間趨勢圖及查詢百分位數。

## 何時使用回饋 {/* #when-to-use-feedback */}

- 收集使用者對 Agent 回覆的滿意度評分。
- 將 QA 的留言或修正與受審查的 Trace 一起儲存。
- 依 Agent、環境或實驗建立評分儀表板。

## 新增回饋 {/* #add-feedback */}

在應用程式碼中呼叫 `mastra.observability.addFeedback()`，即可為 Trace 或 Span 加上註記。這個輔助方法是可觀測性進入點的選用功能，請先確認目前使用的實作有支援。所有用戶端方法請見[用戶端 SDK 可觀測性參考文件](/reference/client-js/observability)。

```typescript title="src/mastra/feedback.ts"
if (!mastra.observability.addFeedback) {
  throw new Error('Feedback is not supported by the active observability implementation')
}

await mastra.observability.addFeedback({
  traceId: 'trace-123',
  spanId: 'span-456',
  feedback: {
    feedbackSource: 'user',
    feedbackType: 'rating',
    value: 1,
    comment: 'The answer solved my issue.',
  },
})
```

回饋會傳給每個已設定且支援回饋的匯出器，並由它們各自處理目的地。即使本機儲存中找不到 Trace，回饋仍可傳到 Mastra Platform 或其他匯出器。

[`MastraStorageExporter`](/docs/observability/integrations/exporters/mastra-storage) 會先在已設定的儲存空間查找 Trace 或 Span，再儲存回饋。若重試後仍找不到目標，會記錄警告並略過本機寫入。請在行程結束前呼叫 `mastra.observability.flush()` 或 `shutdown()`，完成尚未送出的回饋。

## 尋找訊息對應的 Trace {/* #find-the-trace-for-a-message */}

回饋通常是針對使用者已讀過的訊息，所以需要該訊息的 `traceId`。無論是在串流結果中，或是稍後從 Memory 取回，助理訊息的 `content.metadata` 都會帶有這個值：

```typescript title="src/mastra/message-trace.ts"
const agent = mastra.getAgent('weatherAgent')
const memory = await agent.getMemory()

const { messages } = await memory!.recall({ threadId, perPage: false })

const message = messages.find(m => m.id === messageId)
const traceId = message?.content.metadata?.traceId
```

這個值與該次執行結果的 `traceId` 指向同一個 Trace。因此，在產生訊息時收集的回饋，與稍後針對已儲存訊息收集的回饋，都會連結到同一個 Trace。停用追蹤時產生的訊息沒有 `traceId`。

### 在 `useChat` 讀取 Trace ID {/* #read-the-trace-id-in-usechat */}

[`chatRoute()`](/reference/ai-sdk/chat-route) 和 [`handleChatStream()`](/reference/ai-sdk/handle-chat-stream) 會將該次執行的 `traceId` 傳給 `messageMetadata` 回呼。在 `start` 部分回傳這個值，用戶端就能直接從即時訊息取得，不必查詢伺服器：

```typescript title="src/mastra/index.ts"
chatRoute({
  path: '/chat/:agentId',
  messageMetadata: ({ part, traceId }) => (part.type === 'start' ? { traceId } : undefined),
})
```

```tsx title="app/chat.tsx"
const { messages } = useChat<UIMessage<{ traceId?: string }>>()

const lastMessage = messages.at(-1)
const traceId = lastMessage?.role === 'assistant' ? lastMessage.metadata?.traceId : undefined
```

若使用 `messageMetadataSchema` 驗證中繼資料，請加入 `traceId: z.string().optional()`。將 `traceId` 連同使用者的投票傳給自己的路由，再於該路由呼叫 `addFeedback()`。此值由用戶端提供，新增回饋前，請先確認具有該 `traceId` 的訊息確實屬於呼叫者。

## 建立回饋 {/* #create-feedback */}

每次呼叫 `createFeedback()` 都須提供 `feedbackType` 與 `value`。若要將回饋連結至 Trace 或特定 Span，可加入 `traceId` 或 `spanId`。另可用 `feedbackSource` 提供選填的字串中繼資料，例如 `user`、`qa`、`studio` 或 `system`。

從儲存層寫入時，請提供 `timestamp`，因為這個方法會直接寫入儲存空間。

```typescript
const observability = await mastra.getStorage()!.getStore('observability')

await observability!.createFeedback({
  feedback: {
    feedbackId: 'feedback-rating-1',
    timestamp: new Date(),
    traceId: 'trace-123',
    spanId: 'span-456',
    feedbackSource: 'user',
    feedbackType: 'rating',
    value: 1,
    comment: 'The answer solved my issue.',
    tags: ['production'],
  },
})

await observability!.createFeedback({
  feedback: {
    feedbackId: 'feedback-comment-1',
    timestamp: new Date(),
    feedbackSource: 'qa',
    feedbackType: 'comment',
    value: 'Needs a citation before shipping.',
    experimentId: 'support-agent-eval',
  },
})
```

## 列出回饋 {/* #list-feedback */}

使用 `listFeedback()` 分頁讀取原始記錄，或以增量模式輪詢。

```typescript
const result = await observability!.listFeedback({
  filters: {
    feedbackType: 'rating',
    feedbackSource: 'user',
    timestamp: { start: new Date(Date.now() - 7 * 24 * 60 * 60 * 1000) },
  },
  pagination: { page: 0, perPage: 20 },
  orderBy: { field: 'timestamp', direction: 'DESC' },
})

console.log(result.feedback, result.pagination?.hasMore)
```

可篩選 `traceId`、`spanId` 等目標欄位，`feedbackType`、`feedbackSource`、`feedbackUserId` 等回饋欄位，以及 `entityName`、`environment`、`experimentId` 與 `tags` 等共用上下文欄位。完整清單請見 [`FeedbackFilter`](/reference/observability/feedback#feedbackfilter)。透過 HTTP 呼叫時，以查詢參數傳入相同的欄位，例如 `GET /api/observability/feedback?traceId=trace-123&environment=production`。詳見[列表查詢參數](/reference/observability/feedback#list-query-parameters)。

```typescript
await observability!.listFeedback({
  filters: {
    traceId: 'trace-123',
    feedbackType: ['rating', 'thumbs'],
    tags: ['production'],
  },
})
```

## 刪除回饋 {/* #delete-feedback */}

使用 `deleteFeedback()` 依 ID 刪除回饋記錄，例如含有敏感資料的留言。每次請求最多接受 1,000 個 `feedbackIds`，刪除操作具等冪性。可選用 `organizationId` 依組織篩選，或用 `resourceId` 依資源篩選，也可以同時使用兩者。Studio 中 Trace 或 Span 的 **Feedback** 分頁上，每則留言都可個別刪除。使用 `deleteTraces()` 刪除 Trace 時，也會一併刪除關聯的回饋。請見[刪除 Trace](/reference/client-js/observability#deleting-traces)。

```typescript
await observability!.deleteFeedback({
  feedbackIds: ['feedback-1', 'feedback-2'],
})
```

已刪除的記錄也會從回饋分析中移除。ClickHouse 透過輕量刪除隱藏資料列，但不保證立即從實體儲存移除。因此，開放原始碼部署必須設定[可觀測性資料保留期限](/reference/storage/retention)，才能徹底清除這些記錄。刪除成功後，對應的請求會標記為已套用；若刪除失敗，請求仍未套用，不會阻擋更新仍可見的回饋，可再次呼叫刪除 API 重試。在 ClickHouse 上，下次更新審查狀態時也會重試刪除。若重試成功，會回報找不到該筆回饋；若再次失敗，會儲存新狀態並回傳刪除錯誤。開放原始碼部署沒有背景調節程序。請為每種可觀測性訊號設定保留期限，讓刪除請求晚於它所保護的訊號資料列到期。只要有任何訊號沒有保留期限，刪除請求也不會到期，以免已刪除的資料再次出現。在 ClickHouse 上，刪除 API 不會更動獨立的增量游標資料表。表內資料列只含識別碼，沒有回饋內容，並會在兩天內到期。

## 查詢回饋分析資料 {/* #query-feedback-analytics */}

OLAP 回饋查詢以數值型 `value` 欄位為對象，可用於評分、以 `1` 和 `-1` 表示的按讚或倒讚、QA 數值評分，以及其他數值型回饋。

```typescript
const rating = await observability!.getFeedbackAggregate({
  feedbackType: 'rating',
  feedbackSource: 'user',
  aggregation: 'avg',
  comparePeriod: 'previous_day',
})

const byAgent = await observability!.getFeedbackBreakdown({
  feedbackType: 'rating',
  groupBy: ['entityName'],
  aggregation: 'avg',
  filters: { environment: 'production' },
})

const ratingsOverTime = await observability!.getFeedbackTimeSeries({
  feedbackType: 'rating',
  aggregation: 'avg',
  interval: '1h',
  groupBy: ['feedbackSource'],
})
```

所有欄位、篩選條件、回傳型別及百分位數查詢參數，請見[回饋參考文件](/reference/observability/feedback)。

本機執行環境會在 `/api/observability/feedback` 提供列表路由，並在相關路徑提供分析功能。請見 [HTTP 路由表](/reference/observability/feedback#http-routes)與[列表查詢參數](/reference/observability/feedback#list-query-parameters)。Mastra Platform 另外提供未標示版本的託管查詢 API。區域端點、驗證方式及專案範圍請見 [Feedback API](/docs/mastra-platform/api#feedback-api)。

## 將回饋匯出至 Mastra Platform {/* #export-feedback-to-mastra-platform */}

[`MastraPlatformExporter`](/reference/observability/tracing/exporters/mastra-platform-exporter) 會將回饋傳送到 Mastra Platform，由平台在需要時查找目標 Trace 或 Span。不必在本機儲存 Trace。只有同時需要本機副本時，才需加入 `MastraStorageExporter`。

Studio 會把回饋傳給負責讀取 Trace 的後端。若由你的開放原始碼伺服器處理 HTTP 建立請求，伺服器會在本機儲存回饋，並通知已設定的匯出器。匯出器採非同步傳送，因此 HTTP 回應成功時，遠端未必已能看到這筆記錄。直接寫入儲存空間會略過匯出器。

## 將回饋匯出至外部平台 {/* #export-feedback-to-external-platforms */}

回饋會經由可觀測性事件匯流排傳遞，支援回饋的匯出器會自動轉送。[PostHog 匯出器](/reference/observability/tracing/exporters/posthog#feedback-export)會將回饋以原生 `$ai_feedback` 事件送出，並在 PostHog 中連結的 Trace 上顯示。
