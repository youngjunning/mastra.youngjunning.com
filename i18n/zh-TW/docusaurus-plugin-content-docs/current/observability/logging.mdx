# 日誌

Mastra 以結構化格式記錄函式執行、輸入資料與輸出回應。

部署至 Mastra Platform 後，日誌會顯示在儀表板。若採用自行託管或自訂環境，可以透過設定的傳輸機制將日誌寫入檔案或送往外部服務。

<Inject>
  **供 AI Agent 使用：**執行 `npx mastra api log list '{"level":"error","page":0,"perPage":50}'`，即可直接檢視近期的錯誤日誌，無須開啟 Studio 或撰寫臨時指令碼。此指令需要已啟動且已設定可觀測性日誌的 Mastra 伺服器。可用 `npx mastra dev` 啟動本機伺服器，或以 `--url` 指定可連線伺服器的基底 URL。設定其他篩選條件前，請先執行 `npx mastra api log list --schema`。執行 `npx skills add mastra-ai/skills --skill mastra` 安裝 Mastra 的 Skill，即可取得 API CLI 指令探索、目標選擇、結構描述、身分驗證及錯誤處理的完整指南。
</Inject>

## 使用 `PinoLogger` 設定日誌 {/* #configuring-logs-with-pinologger */}

使用 CLI [初始化 Mastra 專案](/docs)時，專案預設會包含 `PinoLogger`。

```typescript title="src/mastra/index.ts"
import { Mastra } from '@mastra/core/mastra'
import { PinoLogger } from '@mastra/loggers'

export const mastra = new Mastra({
  logger: new PinoLogger({
    name: 'Mastra',
    level: 'info',
  }),
})
```

所有設定選項請參閱 [PinoLogger](/reference/logging/pino-logger)。

## 將日誌寫入可觀測性儲存空間 {/* #logging-to-observability-storage */}

設定[可觀測性](/docs/observability/overview)後，記錄器呼叫會自動轉送到可觀測性儲存空間。應用程式與 Mastra 內部元件的每次 `debug`、`info`、`warn`、`error` 和 `trackException` 呼叫都會與 Trace 一起儲存。低於 `logging.level` 所設最低層級的日誌會被排除。

無須修改程式碼。支援轉接器的記錄器（`PinoLogger` 和 `ConsoleLogger`）會將每筆記錄寫入各自的目的地，再以同一筆記錄產生要匯出的日誌。若自訂記錄器不支援轉接器，Mastra 會加上一層包裝，讓日誌同時寫入原記錄器與可觀測性系統。

### 在日誌輸出中關聯 Trace {/* #trace-correlated-log-output */}

在受追蹤的操作（Agent 執行、Workflow 步驟或 Tool 呼叫）中寫入日誌時，Mastra 會將 `trace_id` 和 `span_id` 加入記錄器的原生輸出。這兩個欄位採用 W3C Trace Context 格式，與 Studio 顯示的 Trace 相符，因此你可以從標準輸出的一行日誌直接找到對應的 Trace。

若要讓標準輸出產生機器可剖析的 JSON，請將 `PinoLogger` 設為 `prettyPrint: false`。預設的美化輸出會產生便於閱讀的文字：

```typescript title="src/mastra/index.ts"
import { Mastra } from '@mastra/core/mastra'
import { PinoLogger } from '@mastra/loggers'

export const mastra = new Mastra({
  logger: new PinoLogger({ name: 'Mastra', level: 'info', prettyPrint: false }),
})
```

此時會產生以下記錄：

```json
{
  "level": 30,
  "time": 1755522000000,
  "name": "Mastra",
  "trace_id": "0af7651916cd43dd8448eb211c80319c",
  "span_id": "b7ad6b7169203331",
  "msg": "tool executed"
}
```

在未追蹤的操作中，輸出會省略這些欄位。`ConsoleLogger` 會把相同欄位組成物件，附加為主控台輸出的引數。`PinoLogger` 會將欄位寫到所有目的地，包括標準輸出、檔案及自訂傳輸。如果自行提供 pino `mixin`，其中的欄位仍會保留，衝突時以 `trace_id` 和 `span_id` 為準。

可透過 `loggerOptions` 分別設定 Trace 關聯與日誌匯出：

```typescript title="src/mastra/index.ts"
import { Mastra } from '@mastra/core/mastra'
import { PinoLogger } from '@mastra/loggers'

export const mastra = new Mastra({
  logger: new PinoLogger({ name: 'Mastra', level: 'info' }),
  loggerOptions: {
    correlation: true, // inject trace_id/span_id into native log output (default: true)
    export: false, // keep trace-correlated output without storing logs in observability (default: true)
  },
})
```

### 自訂記錄器 {/* #custom-loggers */}

自訂的 `IMastraLogger` 實作仍可運作。Mastra 會透過已淘汰的雙寫備援機制將日誌呼叫轉送到可觀測性系統，但記錄器的原生輸出不會加上 `trace_id` 或 `span_id`。若要讓輸出與 Trace 關聯，請實作 `@mastra/core/logger` 提供的 `__attachObservability()` 轉接器掛鉤：

```typescript
import { MastraLogger, buildLogRecordData } from '@mastra/core/logger'
import type { LoggerAdapterContext } from '@mastra/core/logger'

class MyLogger extends MastraLogger {
  #adapterContext?: LoggerAdapterContext

  __attachObservability(ctx: LoggerAdapterContext): void {
    this.#adapterContext = ctx
  }

  #log(level: 'debug' | 'info' | 'warn' | 'error', message: string, args: unknown[]): void {
    const ctx = this.#adapterContext
    // Inject trace fields into your native record when correlation is enabled
    const traceFields = ctx?.options.correlation ? ctx.resolveTraceFields() : undefined
    console[level === 'debug' ? 'info' : level](
      message,
      ...args,
      ...(traceFields ? [traceFields] : []),
    )
    // Export the same record to observability when export is enabled
    if (ctx?.options.export) {
      ctx.getLogSink()?.[level](message, buildLogRecordData(args))
    }
  }

  debug(message: string, ...args: unknown[]): void {
    this.#log('debug', message, args)
  }

  info(message: string, ...args: unknown[]): void {
    this.#log('info', message, args)
  }

  warn(message: string, ...args: unknown[]): void {
    this.#log('warn', message, args)
  }

  error(message: string, ...args: unknown[]): void {
    this.#log('error', message, args)
  }
}
```

### 設定可觀測性日誌層級 {/* #configuring-observability-log-level */}

可觀測性儲存空間與主控台記錄器可使用不同的日誌層級。請在可觀測性執行個體的設定中加入 `logging` 選項：

```typescript {12-15} title="src/mastra/index.ts"
import { Mastra } from '@mastra/core/mastra'
import { PinoLogger } from '@mastra/loggers'
import { Observability, MastraStorageExporter } from '@mastra/observability'

export const mastra = new Mastra({
  logger: new PinoLogger({ name: 'Mastra', level: 'debug' }),
  observability: new Observability({
    configs: {
      default: {
        serviceName: 'my-app',
        exporters: [new MastraStorageExporter()],
        logging: {
          enabled: true, // set to false to disable log forwarding
          level: 'info', // minimum level: 'debug' | 'info' | 'warn' | 'error' | 'fatal'
        },
      },
    },
  }),
})
```

在這個範例中，主控台會輸出 `debug` 及以上的所有日誌，可觀測性儲存空間則只寫入 `info` 及以上的日誌。這樣開發時仍可在主控台看到詳細資訊，儲存空間也能維持精簡。

| 選項 | 型別 | 預設值 | 說明 |
| - | - | - | - |
| `enabled` | `boolean` | `true` | 設為 `false` 即可停止將日誌轉送至可觀測性儲存空間。 |
| `level` | `LogLevel` | `'warn'` | 最低嚴重程度。低於此層級的日誌會被捨棄。 |

### 查詢日誌 {/* #querying-logs */}

可使用 Mastra 用戶端 SDK 查詢寫入可觀測性儲存空間的日誌：

```typescript
import { MastraClient } from '@mastra/client-js'

const client = new MastraClient()

const logs = await client.listLogsVNext({
  filters: { level: 'error' },
  pagination: { page: 1, perPage: 50 },
  orderBy: { field: 'timestamp', direction: 'desc' },
})
```

使用 DuckDB 或 ClickHouse 等持久性儲存後端時，重新啟動後仍可讀取日誌，供歷史分析使用。

## 自訂日誌內容 {/* #customizing-logs */}

Workflow 步驟和 Tool 都可使用 `mastra.getLogger()` 取得記錄器執行個體。記錄器支援標準的嚴重程度層級，包括 `debug`、`info`、`warn` 和 `error`。

### 在 Workflow 步驟中寫入日誌 {/* #logging-from-workflow-steps */}

在 Workflow 步驟的 `execute` 函式中，可透過 `mastra` 參數取得記錄器，寫入與這個步驟有關的執行資訊。

```typescript {6-7} title="src/mastra/workflows/test-workflow.ts" oxfmt:false
import { createWorkflow, createStep } from "@mastra/core/workflows";
import { z } from "zod";

const step1 = createStep({
  execute: async ({ mastra }) => {
    const logger = mastra.getLogger();
    logger.info("workflow info log");

    return {
      output: ""
    };
  }
});

export const testWorkflow = createWorkflow({...})
  .then(step1)
  .commit();
```

### 在 Tool 中寫入日誌 {/* #logging-from-tools */}

Tool 也可以透過 `mastra` 參數取得記錄器，寫入該 Tool 執行時的活動資訊。

```typescript {6-7} title="src/mastra/tools/test-tool.ts"
import { createTool } from '@mastra/core/tools'
import { z } from 'zod'

export const testTool = createTool({
  execute: async (inputData, context) => {
    const logger = context?.mastra.getLogger()
    logger?.info('tool info log')

    return {
      output: '',
    }
  },
})
```

### 在日誌中加入額外資料 {/* #logging-with-additional-data */}

記錄器方法的第二個參數為選填，可用來附加資料。傳入結構化物件後，就能在可觀測性儲存空間中篩選日誌。

```typescript {9} title="src/mastra/workflows/test-workflow.ts" oxfmt:false
import { createWorkflow, createStep } from "@mastra/core/workflows";
import { z } from "zod";

const step1 = createStep({
  execute: async ({ mastra }) => {
    const testAgent = mastra.getAgent("testAgent");
    const logger = mastra.getLogger();

    logger.info("workflow info log", { agent: testAgent });

    return {
      output: ""
    };
  }
});

export const testWorkflow = createWorkflow({...})
  .then(step1)
  .commit();
```
