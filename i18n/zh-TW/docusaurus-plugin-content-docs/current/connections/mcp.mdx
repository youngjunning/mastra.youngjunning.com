# MCP

馬斯特拉支持[Model Context Protocol (MCP)](https://modelcontextprotocol.io/introduction)，一種用於將人工智慧Agent連接到外部Tool和資源的開放標準。

使用[`MCPClient`](/reference/tools/mcp-client) to connect to MCP servers. Use [`MCPServer`](/reference/tools/mcp-server)將 Mastra Agent、Tool、Workflow、提示和資源公開給其他 MCP 相容系統。兩人都講 MCP`2026-07-28`對 stdio 和 Streamable HTTP 的修訂。

對於託管 MCP 伺服器，例如[Neon](/integrations/databases/neon#connect) and [Canva](/integrations/other/canva), [Connect](/docs/mastra-platform/connect) on Mastra platform can manage the OAuth flow and credentials for you, so agents get the server's tools through [`tools()`](/reference/connect/tools#mcp-providers)無需手動配置`MCPClient`.

:::注意
升級自`@mastra/mcp` 1.x? See the [migration guide](/reference/migrations/mcp-v2).
:::

有關憑證選擇和權限邊界，請參閱[Authentication and authorization with MCP](/docs/guides/mcp-authentication-authorization).

## 連接到 MCP 伺服器 {/* #connect-to-mcp-servers */}

安裝MCP包：

```bash npm2yarn
npm install @mastra/mcp@latest
```

使用本機命令或遠端 URL 設定每個伺服器：

```typescript title="src/mastra/mcp/client.ts"
import { MCPClient } from '@mastra/mcp'

export const mcpClient = new MCPClient({
  id: 'my-mcp-client',
  servers: {
    wikipedia: {
      command: 'npx',
      args: ['-y', 'wikipedia-mcp'],
    },
    weather: {
      url: new URL('https://weather.example.com/mcp'),
      requestInit: {
        headers: {
          Authorization: `Bearer ${process.env.WEATHER_API_KEY}`,
        },
      },
    },
  },
})
```

:::提示驗證

對於 OAuth 保護的伺服器，請使用`authenticate()` to complete the browser-based authorization flow. Visit [OAuth authentication](/reference/tools/mcp-client#oauth-authentication) for configuration details.

:::

將Tool從已配置的伺服器傳遞到Agent：

```typescript {2,13} title="src/mastra/agents/assistant.ts"
import { Agent } from '@mastra/core/agent'
import { mcpClient } from '../mcp/client'

export const assistant = new Agent({
  id: 'assistant',
  name: 'Assistant',
  instructions: `
    Use the available MCP tools to answer questions.
    Include the source of any information you retrieve.
  `,
  model: '__GATEWAY_OPENAI_MODEL__',
  tools: await mcpClient.listTools(),
})
```

### 產生直接Tool呼叫的類型 {/* #generate-types-for-direct-tool-calls */}

對於穩定的伺服器配置，請從已發佈的Tool架構產生類型，而不是重新聲明Tool參數和結果。此可選Workflow可讓動態發現保持不變。

導出一個帶有輸出路徑的客戶端並傳遞生成的`MCPServers` interface to its constructor:

```typescript title="src/mcp/client.ts"
import { MCPClient } from '@mastra/mcp'
import type { MCPServers } from './mcp-types.generated'

export const mcp = new MCPClient<MCPServers>({
  id: 'weather-client',
  servers: { weather: { url: new URL(process.env.WEATHER_MCP_URL!) } },
  typegen: { outFile: 'src/mcp/mcp-types.generated.ts' },
})
```

放`WEATHER_MCP_URL` and configure any required authentication before running the command from your project root:

```bash npm2yarn
npx @mastra/mcp generate ./src/mcp/client.ts
```

產生的檔案在第一次執行時可能不存在，因為它的匯入是僅類型的。 Generation 無需進行類型檢查即可載入 TypeScript 模組，且無需執行Tool即可列出架構。之後運行項目的類型檢查。

使用其產生的參數來呼叫已發現的Tool。以下假設伺服器發布`get_weather` with a string `location` and numeric `temperature`:

```typescript title="src/mcp/call-weather.ts"
import { mcp } from './client'

try {
  const tools = await mcp.listTools()
  const weather = tools.weather_get_weather
  if (weather?.execute) {
    const result = await weather.execute({ location: 'Paris' })
    if (result && 'temperature' in result && typeof result.temperature === 'number') {
      console.log(result.temperature)
    }
  }
} finally {
  await mcp.disconnect()
}
```

Tool可能不存在，執行可能會傳回協議信封、驗證錯誤或`undefined` alongside structured output. Narrow the result before using it. Missing output schemas produce `unknown`.

傳遞多個顯式客戶端檔案以產生多個輸出。直接將客戶端匯出為命名或預設匯出，使用不同的輸出路徑，並在伺服器配置匹配時為獨立客戶端提供不同的 ID。輸入和輸出路徑從命令的工作目錄解析。同一客戶端的重複匯出均處理一次。

發現失敗會使現有文件保持不變，模式問題產生也無法解決，例如引用循環、深度過大或未解析的本地引用。文件替換是每個文件的原子操作，而不是整個集合的操作。當伺服器架構變更時，使用等效權限重新產生。在生成之前，請自行提供憑證並載入任何環境檔案。導入客戶端會執行其模組和傳遞導入，因此選擇沒有應用程式啟動副作用的檔案。互動式身分驗證不是命令的一部分。

看[type generation reference](/reference/tools/mcp-client#generate-client-types) for export selection, instance caching, schema limitations, and failure handling.

### 靜態和運行時Tool {/* #static-and-runtime-tools */}

根據伺服器配置是否在請求之間發生變化來選擇如何載入Tool：

| |靜態Tool|執行時間Tool集 |
| :- | :- | :- |
|方法|`await mcpClient.listTools()` | `await mcpClient.listToolsets()` |
| Use case | Shared, fixed configuration | Per-user or per-request configuration |
| Credentials | Shared by all requests | Can vary between requests |
| Agent API | `tools` in the `Agent` constructor | `toolsets` in `generate()` or `stream()` |
| Tool names | Prefixed with the server name, such as `weather_get_weather` | Raw tool names. Same-named tools from different servers collide. See [`listToolsets()`](/reference/tools/mcp-client#listtoolsets). |

前面的Agent範例使用靜態Tool。對於運行時憑證，為請求建立客戶端並在呼叫Agent時傳遞其Tool集：

```typescript {5-16,21} title="src/handle-request.ts"
import { MCPClient } from '@mastra/mcp'
import { mastra } from './mastra'

export async function handleRequest(prompt: string, apiKey: string) {
  const userMcpClient = new MCPClient({
    servers: {
      weather: {
        url: new URL('https://weather.example.com/mcp'),
        requestInit: {
          headers: { Authorization: `Bearer ${apiKey}` },
        },
      },
    },
  })

  const agent = mastra.getAgent('assistant')
  const response = await agent.generate(prompt, {
    toolsets: await userMcpClient.listToolsets(),
  })

  await userMcpClient.disconnect()
  return response.text
}
```

訪問[`listTools()`](/reference/tools/mcp-client#listtools) and [`listToolsets()`](/reference/tools/mcp-client#listtoolsets) for their full APIs.

此範例在一個請求內完成。當Agent程式工作必須在請求結束後繼續或在進程重新啟動後繼續運行時，請使用[durable agents](/docs/harness/durable-agents) or [background tasks](/docs/harness/background-tasks) instead of building your own task tracking. Call-time `toolsets` can't move to another process, so with a durable agent, load per-request MCP tools in the agent's `tools` function from [request context](/docs/server/request-context).

### Tool審批 {/* #tool-approval */}

放`requireToolApproval` on a server to require approval for all its tools:

```typescript
const mcpClient = new MCPClient({
  servers: {
    github: {
      url: new URL('https://github.example.com/mcp'),
      requireToolApproval: true,
    },
  },
})
```

您也可以提供一個根據Tool名稱、參數或註解進行決定的函數：

```typescript
requireToolApproval: ({ toolName }) => toolName.startsWith('delete_')
```

將您無法控制的伺服器的Tool註釋視為不受信任的提示。訪問[tool approval](/reference/tools/mcp-client#tool-approval) for the callback context and security guidance.

### 安全 {/* #security */}

MCP 伺服器代表您的Agent程式運行程式碼並傳回內容，因此請像任何其他外部相依性一樣謹慎地配置它們：

* **Stdio子進程環境**：子進程僅繼承 MCP SDK 的策劃環境白名單（例如`PATH` and `HOME` on POSIX), not the full parent environment. Set `inheritDefaultEnv: false` on a server to pass only the variables listed in `env`.
* **出站主機限制**： 放`allowedHosts` when HTTP server URLs come from untrusted configuration, to restrict the hosts the client can contact. The default fetch path blocks redirect hops before sending them; a custom `fetch` is validated against its final response URL only after the request, so it must enforce its own redirect policy when outbound contact must be prevented.
* **Tool響應信任**：Tool結果是不受信任的模型輸入。使用[input and output processors](/docs/agents/processors) to sanitize content before it reaches the model, and `requireToolApproval` for sensitive tools.

參觀[MCPClient security reference](/reference/tools/mcp-client#security) for enforcement details of each option.

註冊中心提供託管或打包的 MCP 伺服器。上面的客戶端配置適用於註冊表端點和命令。

|登記處 |連線 |筆記|
| :- | :- | :- |

| [mcp.run](https://www.mcp.run/) | Signed hosted URL | Treat the profile URL as a secret |

## 公開 Mastra MCP 伺服器 {/* #expose-a-mastra-mcp-server */}

創建一個`MCPServer` to expose Mastra primitives to external MCP clients:

```typescript title="src/mastra/mcp/server.ts"
import { MCPServer } from '@mastra/mcp'
import { assistant } from '../agents/assistant'
import { weatherTool } from '../tools/weather'
import { weatherWorkflow } from '../workflows/weather'

export const mcpServer = new MCPServer({
  id: 'my-mcp-server',
  name: 'My MCP Server',
  version: '1.0.0',
  agents: { assistant },
  tools: { weatherTool },
  workflows: { weatherWorkflow },
})
```

在主伺服器上註冊伺服器`Mastra` instance:

```typescript title="src/mastra/index.ts"
import { Mastra } from '@mastra/core/mastra'
import { mcpServer } from './mcp/server'

export const mastra = new Mastra({
  mcpServers: { mcpServer },
})
```

:::提示驗證

使用 OAuth 中介軟體保護 HTTP MCP 伺服器。訪問[OAuth protection](/reference/tools/mcp-server#oauth-protection) for setup instructions.

:::

註冊伺服器位於`/api/mcp/:serverId/mcp` over Streamable HTTP. Because every request is self-contained, the same server runs unchanged on long-lived hosts and serverless platforms.

需要使用者提供某些資訊才能完成通話的Tool`context.suspend()` with a payload and declares a `resumeSchema`. The server turns that into an `input_required` round and runs the tool again with the answer in `context.resumeData`. Clients answer those rounds with the `inputRequests` handler on their server definition. Visit [Asking the caller for input](/reference/tools/mcp-server#asking-the-caller-for-input) and [Answering input requests](/reference/tools/mcp-client#answering-input-requests).

參觀[`MCPServer` reference](/reference/tools/mcp-server) for prompts, resources, transports, and other server options.

要在 Mastra 應用程式上公開每個Agent程式、Workflow和Tool而不定義伺服器，請使用[built-in MCP server](/docs/server/mcp) at `/api/mcp`.

### 發布stdio伺服器包 {/* #publish-a-stdio-server-package */}

當您希望用戶端透過以下命令在本地運行伺服器時，請打包使用標準輸入/輸出 (stdio) 傳輸的伺服器`npx`. Create a separate executable entry point that starts the server:

```typescript title="src/mastra/mcp/stdio.ts"
#!/usr/bin/env node
import { mcpServer } from './server'

mcpServer.startStdio().catch(error => {
  console.error('Failed to start MCP server:', error)
  process.exit(1)
})
```

`bin` field to that output. Include the built file in the published package and keep the shebang as its first line:

```json title="package.json"
{
  "bin": {
    "my-mcp-server": "dist/stdio.js"
  },
  "files": ["dist"]
}
```

發布包後，配置客戶端以按包名稱運行它：

```typescript title="src/mastra/mcp/client.ts"
import { MCPClient } from '@mastra/mcp'

const mcpClient = new MCPClient({
  servers: {
    myServer: {
      command: 'npx',
      args: ['-y', '@your-org/my-mcp-server@1.0.0'],
    },
  },
})
```

參觀[npm package publishing documentation](https://docs.npmjs.com/creating-and-publishing-scoped-public-packages) for package naming, authentication, and publication commands.

## 建立 MCP 應用程式 {/* #build-mcp-apps */}

這[MCP Apps extension](https://github.com/modelcontextprotocol/ext-apps) lets MCP tools serve interactive HTML interfaces through `ui://` resources. Mastra Studio renders these apps in sandboxed iframes on tool pages and in agent chat.

當Tool結果受益於互動（例如表單、計算器、顏色選擇器或資料視覺化）時，請使用 MCP 應用程式。

### 定義應用程式資源 {/* #define-an-app-resource */}

`content` summary for the model and place UI data in `structuredContent`. Link the tool to its app by setting `mcp._meta.ui.resourceUri` to the same `ui://` URI used in `appResources`:

```typescript title="src/mastra/mcp/calculator.ts"
import { MCPServer } from '@mastra/mcp'
import { createTool } from '@mastra/core/tools'
import { z } from 'zod'

const calculatorTool = createTool({
  id: 'calculatorWithUI',
  description: 'Calculate the sum of two numbers',
  inputSchema: z.object({ num1: z.number(), num2: z.number() }),
  mcp: { _meta: { ui: { resourceUri: 'ui://calculator/main' } } },
  execute: async ({ num1, num2 }) => ({
    content: [{ type: 'text', text: 'The result is displayed in the calculator app.' }],
    structuredContent: { result: num1 + num2 },
  }),
})

const calculatorMcpServer = new MCPServer({
  id: 'calculator-app-server',
  name: 'Calculator App Server',
  version: '1.0.0',
  tools: { calculatorTool },
  appResources: {
    'ui://calculator/main': { name: 'Calculator', htmlPath: './src/mastra/mcp/calculator.html' },
  },
})
```

模型看到`content`, while the app receives `structuredContent`. Visit [`appResources`](/reference/tools/mcp-server#mcp-apps-appresources) for inline HTML, file paths, metadata, and content security policy options.

### 將應用程式連接到 Studio {/* #connect-the-app-to-studio */}

使用`App` class from `@modelcontextprotocol/ext-apps` inside the HTML resource. Register event handlers before calling `connect()`:

```html title="src/mastra/mcp/calculator.html"
<!doctype html>
<html>
  <body>
    <p id="result">Waiting for input</p>
    <button id="recalculate">Recalculate</button>

    <script type="module">
      import { App } from 'https://cdn.jsdelivr.net/npm/@modelcontextprotocol/ext-apps/+esm'

      const app = new App({ name: 'Calculator', version: '1.0.0' })
      let toolInput

      app.ontoolinput = params => {
        toolInput = params.arguments
      }

      document.querySelector('#recalculate').addEventListener('click', async () => {
        const result = await app.callServerTool({
          name: 'calculatorWithUI',
          arguments: toolInput,
        })
        document.querySelector('#result').textContent = JSON.stringify(result)
      })

      await app.connect()
    </script>
  </body>
</html>
```

訪客端 API 服務於互動的不同部分：

|應用程式介面 |目的|
| :- | :- |
|`app.ontoolinput` | Receive the arguments from the host tool call |
| `app.callServerTool()` | Call an MCP tool from inside the iframe |
| `app.sendMessage()` | Add a user message to chat and start a new model turn |
| `app.connect()` | Connect to the host after registering event handlers |

參觀外部[`App` API reference](https://apps.extensions.modelcontextprotocol.io/api/classes/app.App.html) for all guest-side methods and lifecycle hooks.

### 註冊 MCP 應用程式 {/* #register-mcp-apps */}

將伺服器註冊到`Mastra` the same way as any other server in [Expose a Mastra MCP server](#expose-a-mastra-mcp-server), and pass its tool to the agent that should render the app.

`MCPClient.listTools()` and register its proxy so Studio can resolve the remote app resources:

```typescript title="src/mastra/remote-apps.ts"
import { Agent } from '@mastra/core/agent'
import { Mastra } from '@mastra/core/mastra'
import { mcpClient } from './mcp/client'

const tools = await mcpClient.listTools()
const mcpServers = mcpClient.toMCPServerProxies()

const agent = new Agent({
  id: 'remote-app-agent',
  name: 'Remote App Agent',
  instructions: 'Use the available remote tools.',
  model: '__GATEWAY_OPENAI_MODEL_LUNA__',
  tools,
})

export const mastra = new Mastra({
  agents: { agent },
  mcpServers,
})
```

Tool加載透過`listTools()` include a `serverId` in `_meta.ui`, allowing Studio to resolve each app resource without scanning every server. Visit [`toMCPServerProxies()`](/reference/tools/mcp-client#tomcpserverproxies) for proxy configuration details.

### 沙箱安全 {/* #sandbox-security */}

馬斯特拉工作室使用[`@mcp-ui/client`](https://www.npmjs.com/package/@mcp-ui/client) to load app HTML through a sandbox proxy and communicate over JSON-RPC with `postMessage`.

應用程式 iframe 允許腳本、表單和彈出視窗。他們無法存取父頁面的 DOM、cookie 或儲存。主機控制與訪客應用程式的所有通訊。

## MCP 活動 {/* #mcp-events */}

MCP 事件讓用戶端在伺服器上發生某些情況（例如開啟票證或建置完成）時做出反應，而不是按計畫呼叫Tool進行檢查。伺服器聲明事件類型，客戶端使用參數訂閱，伺服器透過與其Tool相同的 stdio 或 Streamable HTTP 傳輸傳遞每個符合的事件。

:::警告
MCP活動實施[SEP-3415](https://github.com/modelcontextprotocol/modelcontextprotocol/pull/3415), a draft MCP extension. The wire format and the Mastra API are experimental and may change in any release.
:::

* **訂閱：**&#x4E00;個客戶端請求一種帶有參數的事件類型，例如`{ project: 'web' }`. The server delivers only matching occurrences.
* **發生：**&#x4E00;項已交付的活動`eventId`, `name`, `timestamp`, and `data`. Delivery is at least once, and the client drops duplicates by `eventId` within a `dedupWindow` of recent ids. Handlers should still tolerate a repeat.
* **游標:**&#x4E8B;件序列中的不透明位置。保存它以便從以後的訂閱中恢復。重播僅涵蓋來源保留的歷史記錄。一個`emit()` source buffers in one process, so a restart or another instance serving the subscription can miss occurrences, and durable replay needs a `poll` source backed by shared storage.

### 發布活動 {/* #publish-events */}

聲明每種類型`defineEvent()` in the `events` option of `MCPServer`, then publish occurrences with `server.events.emit()`:

```typescript title="src/mastra/mcp/tickets.ts"
import { createTool } from '@mastra/core/tools'
import { MCPServer, defineEvent } from '@mastra/mcp'
import { z } from 'zod'

const ticket = z.object({ id: z.string(), project: z.string(), title: z.string() })

const server: MCPServer = new MCPServer({
  id: 'tickets',
  name: 'Tickets',
  version: '1.0.0',
  tools: {
    openTicket: createTool({
      id: 'openTicket',
      description: 'Opens a support ticket',
      inputSchema: ticket,
      execute: async input => server.events.emit('ticket.created', input),
    }),
  },
  events: {
    'ticket.created': defineEvent({
      description: 'A support ticket was opened',
      inputSchema: z.object({ project: z.string() }),
      payloadSchema: ticket,
      match: (args, data) => data.project === args.project,
    }),
  },
})
```

`http://localhost:4111/mcp` with [`startHTTP()`](/reference/tools/mcp-server#starthttp).

`match`決定哪些訂閱接收事件。它過濾客戶端選擇的參數，因此它不控制誰可以訂閱；添加`authorize` to restrict callers, since it runs on every poll and every subscription open and rejects the request when it returns `false`. An event type takes its occurrences from either `server.events.emit()`, which serves push and poll from an in-process buffer, or a `poll` function that reads an external system and supports poll only.

### 訂閱活動 {/* #subscribe-to-events */}

列出伺服器提供的類型`mcp.events.list()`, then subscribe with `mcp.events.subscribe()`. The returned subscription is an async iterable of occurrences:

```typescript title="src/mastra/mcp/client.ts"
import { MCPClient } from '@mastra/mcp'

const mcp = new MCPClient({ servers: { tickets: { url: new URL('http://localhost:4111/mcp') } } })

const eventTypes = await mcp.events.list('tickets')
const subscription = await mcp.events.subscribe('tickets', 'ticket.created', { project: 'web' })

for await (const event of subscription) {
  console.log(event.eventId, event.data)
  if (subscription.cursor) await saveCursor('tickets:web', subscription.cursor)
}
```

`subscribe()`一旦伺服器接受訂閱就解決。新的訂閱從現在開始，所以透過`options.cursor` to resume from a saved position. The client picks the first mode the event offers, in the order `webhook` when the client has `webhook` settings, then `push`, then `poll`, and reopens dropped streams on its own.

### 從事件開始運行 {/* #start-runs-from-events */}

在每次發生時啟動一次Agent運行或Workflow運行的循環中進行訂閱。該事件來自伺服器，因此透過`event.data` as data rather than as instructions, and save `subscription.cursor` after handling each one. Because the loop handles one occurrence at a time and a slow run delays the next, when order doesn't matter you can start runs without awaiting them and save the cursor only after every earlier run has finished, since a crash otherwise loses the occurrences whose runs were still going.

在推送或 webhook 傳遞下，客戶端緩衝循環未讀取的事件，且循環下降超過`maxBufferedEvents` behind loses the oldest ones and reports `MCP_EVENTS_BUFFER_OVERFLOW`. To deliver occurrences to agent threads as notifications instead of writing your own loop, use [`MCPEventsSignalProvider`](/reference/tools/mcp-client#events-in-agents-and-workflows-experimental).

當伺服器位於遠端且您的應用程式已提供 HTTP 服務時，請改用 Webhook 傳遞：啟用`webhook` in `eventsOptions` on the server and `webhook` on the client, and each occurrence arrives as a POST to your endpoint. For delivery modes, error codes, buffers, retries, and the `poll` source example, visit the [`MCPServer` events reference](/reference/tools/mcp-server#events-experimental) and the [`MCPClient` events reference](/reference/tools/mcp-client#events-property-experimental). The [MCP events example](https://github.com/mastra-ai/mastra/tree/main/examples/mcp-events) runs the agent flow end to end against a local stdio server.
