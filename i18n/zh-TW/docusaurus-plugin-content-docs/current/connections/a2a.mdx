# A2A (Agent-to-Agent)

Mastra 支援 [Agent-to-Agent (A2A) 協定](https://a2a-protocol.org/latest/) 0.3.0 版，適用於跨平台的多 Agent 系統。可透過 A2A 將 Mastra Agent 提供為遠端 Agent，或將遠端 A2A Agent 用作 Mastra 子 Agent；也能使用 JavaScript 用戶端 SDK 呼叫 A2A 端點。

A2A 是開放協定，可跨越網路、框架、供應商和程式語言的界線，將工作委派給 Agent。遠端 Agent 不必公開自己的工具、提示詞、記憶、Workflow 和基礎設施，只需提供可供其他系統探索及呼叫的協定端點。

## 何時使用 A2A {/* #when-to-use-a2a */}

- 上層 Agent 需要將工作委派給專門的遠端 Agent。
- 遠端 Agent 由其他服務、團隊、供應商或執行環境管理。
- 後端、瀏覽器應用程式或其他相容 A2A 的系統，需要以程式方式存取 Mastra Agent。
- 長時間執行的遠端工作需要任務 ID、狀態更新、產出物、取消、重新訂閱或推播通知。

## A2A 的運作方式 {/* #how-a2a-works */}

A2A 透過 Agent 卡片進行探索。卡片是由約定的公開 URL 提供的 JSON 文件，描述遠端 Agent，並包含接收 A2A JSON-RPC 要求的執行 URL。

Mastra Server 的 `apiPrefix` 使用預設值 `/api` 時，註冊為 `weather-agent` 的 Agent 會提供：

- Agent 卡片：`/api/.well-known/weather-agent/agent-card.json`
- 執行端點：`/api/a2a/weather-agent`

Agent 卡片包含名稱、描述、端點 URL、提供者、功能、安全性中繼資料和技能等欄位：

```json title="agent-card.json"
{
  "protocolVersion": "0.3.0",
  "name": "Weather Agent",
  "description": "Provides weather information.",
  "url": "https://agent.example.com/api/a2a/weather-agent",
  "version": "1.0",
  "provider": {
    "organization": "Acme",
    "url": "https://acme.example.com"
  },
  "capabilities": {
    "streaming": true,
    "pushNotifications": true,
    "stateTransitionHistory": false
  },
  "defaultInputModes": ["text/plain"],
  "defaultOutputModes": ["text/plain"],
  "skills": [
    {
      "id": "weather",
      "name": "weather",
      "description": "Gets weather conditions for a location.",
      "tags": ["tool"]
    }
  ]
}
```

A2A 以訊息和任務表示工作。訊息可包含文字、檔案或結構化資料片段。

任務是具有 ID 和生命週期狀態的有狀態工作單位。用戶端可以追蹤長時間執行的工作並傳送後續回合，也能取消工作，或在連線中斷後重新訂閱。

## 協議版本 {/* #protocol-versions */}

Mastra 在相同的 Agent 卡片及執行 URL 上支援 A2A 協定 v0.3 和 v1.0。`A2A-Version` 要求標頭用來選擇傳輸協定版本：

- 缺少、空值或 `0.3`：使用現有的 v0.3 API。
* `1.0`：使用 v1.0 API。
- 其他值：回傳 `VersionNotSupported` 協定錯誤。

`A2AAgent` 與 `MastraClient.getA2A()` 預設使用 v0.3。若要使用 v1.0 委派子 Agent，請在 `A2AAgent` 設定 `protocolVersion: '1.0'`；若要直接發送 v1.0 要求，請使用 `MastraClient.getA2AV1()`。兩種 v1.0 用戶端都會自動送出 `A2A-Version: 1.0`。直接呼叫的 v1.0 用戶端也新增 `tasks/list` 操作。

從 `@mastra/core/a2a/v1` 匯入 v1.0 協定型別及編解碼器。既有的 `@mastra/core/a2a/client` 匯出仍使用 v0.3。

## 開始使用 {/* #get-started */}

A2A 在 Mastra 中有兩條常見路徑：

- 透過 `A2AAgent`，將遠端 A2A Agent 作為 Mastra 子 Agent 使用。
- 透過 `MastraClient.getA2A()`，向 Mastra A2A 端點傳送要求。

當另一個 Mastra Agent 需要將工作委派給遠端 Agent 時，使用 `A2AAgent`。當應用程式程式碼需要直接呼叫啟用 A2A 的 Mastra 端點時，使用用戶端 SDK。

## 將 A2A Agent 作為子 Agent 使用 {/* #consume-a2a-agents-as-subagents */}

使用 `A2AAgent` 包裝遠端 A2A Agent，再依照[監督型 Agent](/docs/subagents) 模式將它加入上層 Agent。若遠端伺服器託管多個 Agent，或使用自訂的公開探索路徑，請明確傳入 Agent 卡片 URL。遠端 Agent 要求 A2A v1.0 時，設定 `protocolVersion: '1.0'`；省略則使用 v0.3。

```typescript title="src/mastra/agents/support-agent.ts"
import { Agent } from '@mastra/core/agent'
import { A2AAgent } from '@mastra/core/a2a'

const remoteWeatherAgent = new A2AAgent({
  url: 'https://weather.example.com/api/.well-known/weather-agent/agent-card.json',
  protocolVersion: '1.0',
  headers: {
    Authorization: `Bearer ${process.env.WEATHER_AGENT_TOKEN}`,
  },
})

export const supportAgent = new Agent({
  id: 'support-agent',
  name: 'Support Agent',
  instructions: 'Answer user questions and delegate weather questions when needed.',
  model: '__GATEWAY_OPENAI_MODEL__',
  agents: {
    remoteWeatherAgent,
  },
})
```

如果 `url` 指向網域，`A2AAgent` 會從 `/.well-known/agent-card.json` 取得 Agent 卡片。遵循此探索路徑的單 Agent 伺服器可使用網域 URL；多 Agent 伺服器則應傳入完整卡片 URL，例如 `https://agent.example.com/api/.well-known/weather-agent/agent-card.json`。

執行期間，`A2AAgent` 會：

- 取得並快取遠端 Agent 卡片。
- 從卡片讀取執行 URL 與功能。
- 對 v0.3 呼叫 `message/send` 或 `message/stream`；對 v1.0 呼叫 `SendMessage` 或 `SendStreamingMessage`。
- 將遠端訊息、任務、產出物與狀態更新轉為 Mastra 子 Agent 的結果。
- 當遠端任務需要後續輸入或重新訂閱時，支援 `resumeGenerate()` 和 `resumeStream()`。

若遠端卡片未宣告支援串流，`A2AAgent.stream()` 會改走非串流的 generate 路徑，並回傳緩衝後的串流結果。

## 使用客戶端 SDK 發送請求 {/* #send-requests-with-the-client-sdk */}

當應用程式程式碼要呼叫啟用 A2A 的 Mastra Agent，請使用 `MastraClient.getA2A()`。將 `baseUrl` 設為伺服器來源；若伺服器未使用預設的 `/api` 前綴，還要設定 `apiPrefix`。

```typescript title="src/a2a-client.ts"
import { MastraClient } from '@mastra/client-js'

const client = new MastraClient({
  baseUrl: 'https://agent.example.com',
  headers: {
    Authorization: `Bearer ${process.env.AGENT_API_TOKEN}`,
  },
})

const a2a = client.getA2A('weather-agent')
const card = await a2a.getAgentCard()

console.log(card.name, card.capabilities)
```

使用 `sendMessageStream()` 傳送訊息，並透過伺服器傳送事件 (SSE) 接收任務狀態及產出物更新：

```typescript title="src/a2a-client.ts" oxfmt:false
const stream = a2a.sendMessageStream({
  message: {
    kind: 'message',
    role: 'user',
    messageId: crypto.randomUUID(),
    parts: [{ kind: 'text', text: "What's the weather in Prague?" }],
  },
})

for await (const event of stream) {
  if (event.kind === 'artifact-update') {
    console.log(event.artifact.parts)
  }
}
```

若任務尚在執行時串流中斷，可使用 `resubscribeTask()` 繼續接收進行中任務的即時更新：

```typescript title="src/a2a-client.ts" oxfmt:false
const updates = a2a.resubscribeTask({
  id: 'task-123',
})

for await (const event of updates) {
  console.log(event)
}
```

### 使用 v1.0 用戶端 {/* #use-the-v10-client */}

使用 `getA2AV1()` 選擇 A2A v1.0 傳輸協定。協定套件提供編解碼器，可從 JSON 格式的輸入建立 v1 要求值：

```typescript title="src/a2a-v1-client.ts"
import { ListTasksRequest } from '@mastra/core/a2a/v1'
import { MastraClient } from '@mastra/client-js'

const client = new MastraClient({
  baseUrl: 'https://agent.example.com',
})

const a2a = client.getA2AV1('weather-agent')
const response = await a2a.listTasks(
  ListTasksRequest.fromJSON({
    contextId: 'customer-support',
    pageSize: 20,
  }),
)

for (const task of response.tasks) {
  console.log(task.id, task.status)
}
```

v1.0 用戶端支援 `getAgentCard()`、`sendMessage()`、`sendMessageStream()`、`getTask()`、`listTasks()`、`cancelTask()` 和 `resubscribeTask()`。

## 設定子 Agent 呼叫 {/* #configure-subagent-calls */}

`A2AAgent` 接受供需驗證或受限制環境使用的要求選項：

```typescript title="src/mastra/agents/support-agent.ts"
import { A2AAgent } from '@mastra/core/a2a'

const remoteWeatherAgent = new A2AAgent({
  url: 'https://weather.example.com/api/.well-known/weather-agent/agent-card.json',
  headers: {
    Authorization: `Bearer ${process.env.WEATHER_AGENT_TOKEN}`,
  },
  retries: 2,
  backoffMs: 250,
  maxBackoffMs: 1000,
  timeoutMs: 30_000,
})
```

若執行環境需要自訂 fetch 行為或取消要求，也可傳入 `credentials`、`fetch` 和 `abortSignal`。

## 人工參與流程 {/* #human-in-the-loop */}

A2A 以 `input-required` 任務狀態表示人工參與 (HITL) 的工作。任務暫停等待輸入時，用戶端以相同 `taskId` 傳送後續訊息，補上所需輸入，伺服器便可繼續執行。

Mastra 在伺服器端與用戶端，都將 Agent 的暫停機制對應至此狀態：

- **作為伺服器**：公開的 Agent 暫停時，任務會轉為 `input-required`。這包括因[工具核准](/docs/agents/human-in-the-loop)或工具呼叫 `suspend()` 而暫停。任務狀態訊息包含文字提示，以及帶有結構化 `suspendPayload` 和 `resumeSchema` 的資料片段。以相同 `taskId` 傳送後續 `message/send` 或 `message/stream` 要求，即可用提供的輸入繼續執行。
- **作為用戶端**：遠端任務進入 `input-required` 或 `auth-required` 時，`A2AAgent` 會回傳暫停結果，其中有 `finishReason: 'suspended'` 和 `suspendPayload`。呼叫 `resumeGenerate()` 或 `resumeStream()`，即可用原本的 `taskId` 將輸入或憑證傳回遠端任務。

```typescript title="src/a2a-hitl.ts"
import { A2AAgent } from '@mastra/core/a2a'

const agent = new A2AAgent({
  url: 'https://agent.example.com/api/.well-known/booking-agent/agent-card.json',
})

const result = await agent.generate('Book a flight to Paris', { runId: 'run-1' })

if (result.finishReason === 'suspended') {
  // Inspect result.suspendPayload, collect input from a human,
  // then resume the remote task.
  const resumed = await agent.resumeGenerate({ approved: true }, { runId: 'run-1' })
  console.log(resumed.text)
}
```

對於 `input-required` 任務，後續訊息可以用結構化資料片段攜帶恢復資料，也可以在文字片段中使用 JSON 或純文字。

如果恢復後仍需要額外輸入，任務會再次進入 `input-required`，重複上述流程。要跨要求恢復暫停的執行，Mastra 伺服器必須設定儲存空間，才能還原暫停狀態。

:::note
A2A 任務紀錄存於記憶體，因此只有暫停該任務的同一個伺服器程序能夠恢復。伺服器重新啟動，或水平擴充部署未使用黏著式路由，都會遺失任務紀錄；後續訊息將因找不到任務而失敗。
:::

## 推播通知 {/* #push-notifications */}

Mastra 支援對宣告 `capabilities.pushNotifications` 的遠端 Agent 使用 A2A 推播通知。當用戶端無法維持串流連線，或長時間執行的任務須在原始要求結束後更新回呼 URL 時，可使用推播通知。

用戶端擁有任務 ID 後，可為該任務註冊回呼 URL：

```typescript title="src/a2a-client.ts"
await a2a.setTaskPushNotificationConfig({
  taskId: 'task-123',
  pushNotificationConfig: {
    url: 'https://app.example.com/a2a/tasks',
    token: process.env.A2A_WEBHOOK_TOKEN,
  },
})
```

任務進入 `completed`、`failed`、`canceled`、`rejected`、`input-required` 或 `auth-required` 狀態時，Mastra Server 會將目前的任務快照送往已註冊的回呼。推播通知採盡力傳送。請保護回呼 URL、驗證通知權杖，並避免將內部網路位址設為推播目的地。

推播通知配置儲存在記憶體中，伺服器重新啟動後必須重新註冊。

## 簽署與驗證 Agent 卡片 {/* #sign-and-verify-agent-cards */}

Mastra 支援簽署 A2A Agent 卡片，讓用戶端確認探索到的卡片來自可信的發布者，且傳輸途中未遭更動。請在公開遠端 Agent 的 Mastra 伺服器上設定簽署：

```typescript title="src/mastra/index.ts"
import { Mastra } from '@mastra/core/mastra'

export const mastra = new Mastra({
  server: {
    a2a: {
      agentCardSigning: {
        privateKey: process.env.A2A_AGENT_CARD_PRIVATE_KEY!,
        protectedHeader: {
          alg: 'ES256',
          kid: 'agent-card-key',
        },
      },
    },
  },
})
```

設定簽署後，Mastra 會在 Agent 卡片中加入 `signatures` 陣列。用戶端須自行啟用驗證；未簽署的卡片仍會原樣回傳。

透過 `MastraClient.getA2A()` 驗證已簽署的卡片：

```typescript title="src/a2a-client.ts"
const card = await a2a.getAgentCard({
  verifySignature: {
    algorithms: ['ES256'],
    keyProvider: async ({ kid, jku }) => {
      return fetchTrustedPublicJwk({ kid, jku })
    },
  },
})

if (!card.signatures?.length) {
  throw new Error('Expected a signed A2A agent card.')
}
```

若用戶端在呼叫遠端 Agent 前必須確認可信金鑰，請在用戶端驗證簽章。

## 驗證子 Agent 卡片 {/* #verify-subagent-cards */}

當上層 Agent 須在委派工作前驗證遠端 Agent 時，使用 `verifyAgentCard`。驗證鉤子會收到取得的 Agent 卡片，以及取得位置與時間的相關資訊。

```typescript title="src/mastra/agents/support-agent.ts"
import { A2AAgent } from '@mastra/core/a2a'

const remoteWeatherAgent = new A2AAgent({
  url: 'https://weather.example.com/api/.well-known/weather-agent/agent-card.json',
  verifyAgentCard: {
    verify: async (card, context) => {
      if (card.provider?.organization !== 'Weather Inc') {
        throw new Error(`Unexpected provider for ${context.cardUrl}`)
      }
    },
  },
})
```

在上層 Agent 委派工作前，可透過此鉤子檢查預期的提供者、端點、憑證綁定身分、已簽署卡片或其他信任要求。
