# Knowledge

**加入版本：** `@mastra/core@1.82.0`

Knowledge 讓 Agent 在共用空間整理不隸屬於單一對話的資訊，例如政策、產品文件、慣例、操作手冊和其他 Agent 的經驗。Agent 透過 Tool 搜尋、讀取及寫入內容。釘選的頁面會透過 [Signal](/docs/signals/overview) 帶入 Agent 的脈絡，並在執行期間保持最新。

:::alpha

Knowledge 目前為 Alpha 版，API 可能隨版本變更。每次呼叫 Tool 都會檢查存取權，但目前不保證不同範圍之間的隔離。絕不能讓其他客戶或使用者取得的內容，請勿存入 Knowledge。目前也沒有內建匯入工具或保留機制。

:::

## 什麼是 Knowledge {/* #what-knowledge-is */}

Knowledge 是由頁面與筆記連成的圖，分成多個範圍。

- **頁面**記錄一個主題，包含名稱、簡短說明及 Markdown 內文。頁面可像資料夾一樣分層，例如 `org:acme#policies/refund` 指的是 `org:acme` 範圍內，`policies` 底下的 `refund` 頁面。
- **筆記**是加在頁面上的簡短事實，並會標示作者。人員和 Agent 都能新增筆記，無須重寫頁面。
- **連結**用來串接頁面。頁面內文和筆記可用 `[[org:acme#policies/refund]]` 連到其他頁面；閱讀頁面時，也會看到提及該頁面的筆記。這些連結讓 Knowledge 形成一張圖，而非一份文件清單。
- **範圍**是圖中獨立的一部分，例如 `org:acme` 或 `team:acme:support`。你先宣告需要哪些範圍類型，再由伺服器指定每次 Agent 呼叫，也就是每次**執行**，持有哪些範圍。
- **角色**決定單次執行在範圍內可執行哪些操作：檢視者可讀取，貢獻者可新增頁面與筆記，編輯者可修改頁面，擁有者還能刪除頁面與跨範圍移動頁面。每次呼叫 Tool 時，會依範圍宣告中的規則計算角色，不會逐一儲存使用者的角色。

## 何時使用 Knowledge {/* #when-to-use-knowledge */}

[Memory](/docs/memory/overview) 保留對話內容，讓 Agent 能在對話串中接續工作。Knowledge 保存需要長期使用的資訊，讓不同對話串、Agent 和人員共用。

若想讓 Agent 完成以下工作，可以使用 Knowledge：

- **遵循最新規則。** 釘選政策頁面後，有權讀取的 Agent 每一輪都會看到它。編輯頁面後，執行中的 Agent 會在下一輪取得新版本。
- **讓同一個 Agent 服務多個客戶或團隊。** 每個客戶或團隊的頁面都放在各自的範圍，伺服器為該次執行傳入的範圍決定它能讀取哪些頁面。
- **延續其他 Agent 累積的經驗。** Agent 將決策、慣例與操作手冊的要點寫入頁面或有作者標記的筆記，讓其他 Agent 和人員可以查找並補充。
- **在 Agent 之間交接工作。** 研究 Agent 寫下發現，規劃 Agent 在下方補上計畫，程式開發 Agent 從同一個範圍讀取兩項內容。
- **根據你的內容回答。** 將文件或政策載入某個範圍，再提供唯讀 Tool 給 Agent。

## 快速入門 {/* #quickstart */}

建立 Knowledge 執行個體，宣告它使用的範圍類型，再將它接到 Agent。`tools: true` 讓 Agent 取得搜尋、讀取及寫入頁面的工具。搭配 `KNOWLEDGE_ROUTES` 將執行個體註冊到 `Mastra`，就能在 Studio 瀏覽內容：

```typescript title="src/mastra/index.ts"
import { Mastra } from '@mastra/core'
import { Agent } from '@mastra/core/agent'
import { Knowledge, knowledgeMemoryScopes } from '@mastra/core/knowledge'
import { LibSQLStore } from '@mastra/libsql'
import { Memory } from '@mastra/memory'
import { KNOWLEDGE_ROUTES } from '@mastra/server/server-adapter'

const storage = new LibSQLStore({ id: 'storage', url: 'file:./mastra.db' })

export const knowledge = new Knowledge({
  id: 'company',
  storage,
  scopes: { ...knowledgeMemoryScopes() },
  tools: true,
})

export const agent = new Agent({
  id: 'assistant',
  name: 'Assistant',
  instructions: 'You help your team and keep its knowledge up to date.',
  model: '__GATEWAY_OPENAI_MODEL__',
  memory: new Memory({ storage }),
  knowledge,
})

export const mastra = new Mastra({
  agents: { agent },
  knowledge: { company: knowledge },
  server: { apiRoutes: [...KNOWLEDGE_ROUTES] },
})
```

`tools` 預設關閉。即使 Agent 接上 Knowledge，也必須開啟此選項才會取得工具。不一定需要 Memory；沒有 Memory 時，只要每次呼叫都傳入 `scopes` 即可，但[釘選脈絡](/docs/knowledge/pinned-context)仍需要 Memory。

`knowledgeMemoryScopes()` 宣告三種範圍：每個組織、每位使用者（`resource:`）及每個對話串（`thread:`）各有一個。每次執行都會指定持有的範圍。這個指令碼分別為同一組織的 Dana 與 Bea 執行 Agent，兩人使用各自的對話串：

```typescript title="src/try-knowledge.ts"
import { mastra } from './mastra'

const agent = mastra.getAgent('agent')

await agent.generate('Our refund window is 30 days. Save that for the team.', {
  scopes: ['org:acme', 'resource:dana', 'thread:dana-1'],
})

const answer = await agent.generate('How long is our refund window?', {
  scopes: ['org:acme', 'resource:bea', 'thread:bea-1'],
})

console.log(answer.text)
```

`resource:` 和 `thread:` 範圍也會告訴 Memory 對話屬於哪位使用者及哪個對話串。正式應用程式由伺服器程式碼根據通過身分驗證的使用者決定範圍，切勿使用模型或請求主體提供的資料。若要逐一設定請求，請參閱[設定執行的範圍](/docs/knowledge/scopes-and-access#set-a-runs-scopes)。

為 Dana 執行時，Agent 呼叫 `knowledge_page`，在 `org:acme` 範圍儲存頁面，並收到像 `{ "page": { "name": "Refund window", "ref": "org:acme#refunds", "scope": "org:acme", "version": 1 } }` 這樣的結果。為 Bea 執行時，Agent 呼叫 `knowledge_search` 找到 `org:acme#refunds`，再用 `knowledge_read` 讀取內容，回答退款期限為 30 天。搜尋只會傳回該次執行可讀取的頁面，因此持有其他 `org:` 範圍的執行找不到 Acme 的頁面。

若要查看頁面，請執行 `mastra dev`、開啟 Studio，然後選取 **Knowledge**。`org:acme` 範圍會顯示 Agent 寫入的頁面。
