## 搜尋如何找到頁面 {/* #how-search-finds-pages */}

`knowledge_search`將查詢中的單字與頁面名稱、描述和正文以及註釋文字進行配對。包含更多查詢單字的頁面排名較高。名稱中的一個單字在描述中的作用大於一個，並且描述中的一個單字在正文中的作用大於一個。頁面在註釋之前。

為了幫助搜尋找到頁面，請將人們搜尋的單字放在其名稱和描述中。完整排名順序請參見[`knowledge_search`](/reference/knowledge/knowledge-tools#knowledge_search).

搜尋僅傳回運行可以讀取的內容。

和`MongoDBStore`, pass `scope` to keep searches fast when runs can read many scopes. A search without `scope` first collects every scope the run can read, so it slows down as that number grows.

## 添加按含義搜索 {/* #add-search-by-meaning */}

透過一個`vector` store and an `embedder` to match pages and notes by meaning as well as by keyword. A search for "reimbursement" then finds a page about getting money back, with no shared word:

```typescript title="src/mastra/knowledge.ts"
import { Knowledge, knowledgeMemoryScopes } from '@mastra/core/knowledge'
import { ModelRouterEmbeddingModel } from '@mastra/core/llm'
import { LibSQLStore, LibSQLVector } from '@mastra/libsql'

export const knowledge = new Knowledge({
  id: 'company',
  storage: new LibSQLStore({ id: 'knowledge', url: 'file:./knowledge.db' }),
  vector: new LibSQLVector({ id: 'knowledge-vector', url: 'file:./knowledge.db' }),
  embedder: new ModelRouterEmbeddingModel('__GATEWAY_OPENAI_EMBEDDING_MODEL__'),
  scopes: { ...knowledgeMemoryScopes() },
  tools: true,
})
```

兩者都通過或都不通過。[`embedderOptions`](/reference/knowledge/knowledge-class#constructor-options) works the same way it does in Memory.

`knowledge_search`然後按排名合併關鍵字和含義結果，因此緊密的含義匹配可以出現在名稱匹配之前。每個語義命中都會透過運行的存取權限再次讀取，然後才能在結果中佔據一席之地，因此運行無法讀取的命中將被刪除，並且不會佔用插槽。與 alpha 中的所有訪問檢查一樣，這並不能保證[isolation boundary](/docs/knowledge/scopes-and-access). Search checks at most 1,000 semantic candidates, though, so when most close matches are unreadable, readable ones further down can be missed.

頁面和註釋在編寫時嵌入。範圍頁面未嵌入，但其中的註釋是嵌入的。長頁面被嵌入到各個部分中，搜尋仍然會返回每個頁面一次。看[Limits](/reference/knowledge/limits) for the sizes.

知識不會嵌入已經存在的內容。新增之前寫的頁面和註釋`vector` and `embedder` stay keyword-only until they change.

避免在已經嵌入內容的商店上切換嵌入器。知識還無法重新嵌入它：

* **不同維度：**&#x641C;尋使用新索引，因此現有內容僅包含關鍵字，直到發生變更。
* **相同尺寸：**&#x641C;尋繼續使用舊向量並將它們與新模型的查詢進行比較，這會給出較差的匹配，直到每個頁面發生變化。

### 當嵌入失敗時 {/* #when-embedding-fails */}

如果在寫入頁面或註釋時嵌入或向量寫入失敗，Knowledge 會在大約半秒、2 秒和 7.5 秒後再次嘗試。這涵蓋了一個擴展到零並且需要幾秒鐘才能喚醒的資料庫。Provider標記為不可重試的錯誤（例如錯誤的 API 金鑰）不會再嘗試。

如果每次嘗試都失敗，寫入仍然會成功並且 Mastra 會記錄警告。新頁面或註釋僅保留關鍵字。更新後的向量會保留其先前的向量，因此意味著搜尋與其舊內容相符。兩者都會持續到再次進行更改為止。一個`upsertPage()` call that comes back `unchanged` writes nothing, so it doesn't embed the page either.

如果嵌入器或向量儲存在搜尋過程中失敗，搜尋將返回關鍵字結果並記錄警告。
