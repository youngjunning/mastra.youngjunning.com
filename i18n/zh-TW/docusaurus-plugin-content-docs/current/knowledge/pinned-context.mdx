# 釘選上下文

釘選上下文會把選定的 Knowledge 頁面保留在 Agent 每一輪的上下文中，讓 Agent 不必搜尋。適合用於無論有沒有人提出都適用的常設指示、硬性規則及長期偏好。釘選頁面每輪都會用掉 token，其他內容可放在 Agent 需要時才搜尋和讀取的頁面。

您可以透過兩種方式固定頁面：

| | 在設定中釘選 | 由 Agent 釘選 |
| - | - | - |
| 設定方式 | 由你在範圍宣告中設定 | 由 Agent 使用釘選工具設定 |
| 提供給 | 持有該類型範圍的每次執行 | 持有釘選對象所涵蓋範圍的每次執行 |
| 額度用完時 | 一律提供頁面，必要時縮短 | 列出頁面名稱，讓 Agent 可以開啟 |
| 移除方式 | 修改宣告 | 由 Agent 取消釘選 |

兩種方式都要求執行時具備頁面的讀取權限。釘選本身不會授予頁面存取權限。

:::alpha

Knowledge 目前處於 alpha 階段，API 可能隨版本變更。

:::

## 啟用釘選上下文 {/* #turn-on-pinned-context */}

Agent 必須啟用 Memory 才能使用釘選上下文。在 `Knowledge` 實例上設定 `pinnedContext`：

```typescript title="src/mastra/knowledge.ts"
import { Knowledge, knowledgeMemoryScopes } from '@mastra/core/knowledge'
import { LibSQLStore } from '@mastra/libsql'

export const knowledge = new Knowledge({
  id: 'acme',
  storage: new LibSQLStore({ id: 'knowledge', url: 'file:./mastra.db' }),
  tools: true,
  pinnedContext: { maxTokens: 1000 },
  scopes: {
    ...knowledgeMemoryScopes(),
    // scope declarations, see below
  },
})
```

`pinnedContext: true` 允許每輪最多釘選 20 個頁面，額度為 500 個 token。使用上下文視窗較大的模型時，可以提高 `maxTokens`。Knowledge 每輪都可以用完整的額度。

固定的頁面透過[狀態訊號](/docs/signals/state-signals)傳給 Agent。第一輪會收到額度內的所有釘選頁面，後續各輪只收到變動。若第一輪快照已不在上下文中，例如被 Observational Memory 壓縮，下一輪會再次收到完整快照。執行中的 Agent 會在下一輪收到釘選頁面的編輯內容，提示詞快取也能繼續使用。沒有 Memory 的 Agent 不會收到釘選頁面，並會記錄一次警告。

## 在設定中釘選頁面 {/* #pin-pages-in-config */}

範圍宣告中的 `pinnedContext` 列出持有該範圍的每次執行都會收到的頁面。在此範例中，每次以客服角色執行時都會收到所屬組織的退款政策：

```typescript title="src/mastra/knowledge.ts" oxfmt:false
scopes: {
  ...knowledgeMemoryScopes(),
  'role:$orgId:support': {
    description: 'Customer support agents',
    pinnedContext: ['policy:$orgId#refund-policy'],
  },
  'policy:$orgId': {
    description: 'Company policies',
    access: [{ principal: 'org:$orgId', role: 'viewer' }],
    pages: [
      { key: 'refund-policy', name: 'Refund Policy', description: 'Refund limits and approvals' },
    ],
  },
},
```

每一項都是頁面路徑，預留位置的值來自該次執行持有的範圍。持有 `role:acme:support` 時會收到 `policy:acme#refund-policy`，持有 `role:globex:support` 時則會收到 `policy:globex#refund-policy`。該次執行也需要讀取權限，此處透過 `org:` 範圍取得：

| 執行持有的範圍 | 是否收到這份釘選的退款政策 |
| - | - |
| `org:acme`, `role:acme:support` | 會 |
| `org:acme`, `role:acme:sales` | 不會，但可以用工具讀取頁面 |
| `org:globex`, `role:globex:support` | 不會，收到的是 `policy:globex#refund-policy` |

Knowledge 在每次執行時都會查詢路徑。請依範例將路徑指向目標範圍的 `pages` 中宣告的範本頁面。工具無法移動範本頁面，因此釘選會持續有效。若頁面還不存在或沒有內文，系統不會提供內容，也不會回報錯誤。這裡的客服執行只有檢視權限，請從伺服器呼叫 [`upsertPage()`](/docs/knowledge/load-your-content) 寫入政策內文。

即使超出額度，設定中釘選的頁面也一定會提供。Agent 無法取消釘選。若要移除，請修改宣告。

## 讓 Agent 固定頁面 {/* #let-agents-pin-pages */}

Agent 可以在執行期間用 [`knowledge_pin`](/reference/knowledge/knowledge-tools#knowledge_pin) 工具釘選或取消釘選頁面。每筆釘選都有**對象**，也就是哪些範圍的執行會收到頁面。例如，Agent 可以為 `role:acme:support` 釘選退款政策。頁面移動時，Agent 儲存的釘選會跟著頁面移動。

要固定或取消固定頁面，運行需要以下兩項：

- 在頁面所屬範圍具有 `editor` 權限。
- 對於每個釘選對象的範圍，該次執行必須持有該範圍，或透過規則取得其 `editor` 權限。

在此範例中，政策管理員可以為自己組織的客服執行釘選頁面：

```typescript title="src/mastra/knowledge.ts" oxfmt:false
scopes: {
  ...knowledgeMemoryScopes(),
  'role:$orgId:policy-admin': { description: 'Edits company policy' },
  'role:$orgId:support': {
    description: 'Customer support agents',
    access: [{ principal: 'role:$orgId:policy-admin', role: 'editor' }],
  },
  'policy:$orgId': {
    description: 'Company policies',
    access: [
      { principal: 'org:$orgId', role: 'viewer' },
      { principal: 'role:$orgId:policy-admin', role: 'owner' },
    ],
  },
},
```

Acme 的政策管理員可以為 `role:acme:support` 釘選頁面，但不能為 `role:globex:support` 釘選。客服執行仍須有頁面讀取權限才會收到。

角色範圍上的 `editor` 也允許該次執行在此建立頁面。如果沒有 `self` 規則，任何人都無法讀取這些頁面。請把頁面放在 `policy:` 等內容範圍內，角色範圍只用來指定釘選對象。

## 釘選頁面清單 {/* #pinned-listings */}

釘選清單會將某個範圍或頁面下的頁面目錄放進上下文，格式與 [`knowledge_list`](/reference/knowledge/knowledge-tools#knowledge_list) 傳回的內容相同，包含各頁面的參照、名稱及子頁面數量。如果 Agent 需要知道有哪些頁面、頁面在哪裡，例如文件網站的章節，就釘選清單，讓 Agent 直接用 `knowledge_read` 讀取所需頁面。若每輪都需要頁面內容，就釘選頁面本身。

在範圍的 `pinnedContext` 中加入 `{ list, depth }` 即可釘選清單。`list` 指定範圍或頁面路徑，`depth` 指定往下顯示幾層，範圍是 1 到 3，預設為 1：

```typescript title="src/mastra/knowledge.ts"
import { Knowledge, knowledgeMemoryScopes } from '@mastra/core/knowledge'
import { LibSQLStore } from '@mastra/libsql'

export const knowledge = new Knowledge({
  id: 'docs',
  storage: new LibSQLStore({ id: 'knowledge', url: 'file:./mastra.db' }),
  tools: true,
  pinnedContext: true,
  scopes: {
    ...knowledgeMemoryScopes(),
    'site:$siteId': {
      description: 'A website',
      access: [{ principal: 'self', role: 'viewer' }],
      pinnedContext: [{ list: 'site:$siteId', depth: 1 }],
    },
  },
})
```

每次執行只要持有 `site:mastra`，就會收到這份清單：

```text
Pages under site:mastra (site:mastra, depth 1):
- site:mastra#docs — Docs (2 children)
- site:mastra#blog — Blog
- site:mastra#pricing — Pricing
```

釘選清單與釘選頁面遵循相同的規則：

- 和 `knowledge_list` 一樣，清單只顯示該次執行可讀取的頁面。若無法讀取清單指定的範圍或頁面，就不會收到內容。
- 當新增、重新命名或刪除列出的頁面時，它會在下一輪更新。
- 清單占用 `maxPins` 的一個名額，並與釘選頁面共用 `maxTokens` 額度。

清單超出額度時，會逐層列出放得下的頁面：第一層優先，再往第二層列出，最多到 `depth` 層。如果有頁面未列出，清單末尾會提示 Agent 用 `knowledge_list` 繼續查看。預設額度為 500 個 token，較大的範圍可能只顯示第一層。可提高 `maxTokens` 來顯示較深層的頁面。清單上限請參閱[限制](/reference/knowledge/limits)。

Agent 可在執行期間呼叫 `knowledge_pin` 並傳入 `kind: "list"` 來釘選清單，所需角色與釘選頁面相同。上述的 `site:` 執行只有檢視權限，因此這個呼叫必須由在 `site:mastra` 上具有 `editor` 規則的執行發出：

```json
{ "op": "pin", "kind": "list", "depth": 2, "page": "site:mastra#docs", "audience": ["site:mastra"] }
```

同一頁面可同時釘選頁面本身與頁面清單，兩者各自釘選與取消。引數請參閱 [`knowledge_pin`](/reference/knowledge/knowledge-tools#knowledge_pin)。

## 每次執行會收到哪些內容 {/* #what-a-run-receives */}

在每一輪中，Knowledge 都會以以下順序建立運行的固定上下文：

1. 該次執行持有的每個範圍在設定中釘選的頁面與清單。若超出額度，每項都縮短至均分到的額度。
1. Agent 為該次執行持有的任一範圍釘選的頁面與清單。優先順序較高的在前，同等時較新的在前。設定中已有的項目不會重複。
1. 放不進額度的釘選項目只會列出名稱，Agent 可用讀取工具開啟。

縮短的頁面末尾會提示 Agent 繼續讀取其餘內容。

範圍的 `pinnedContextPriority` 設定其優先順序，預設為 `0`。`knowledgeMemoryScopes()` 將 `thread:`、`resource:` 和 `org:` 的優先順序分別設為 2、1 和 0，因此單一使用者的釘選會排在整個組織的釘選之前。
