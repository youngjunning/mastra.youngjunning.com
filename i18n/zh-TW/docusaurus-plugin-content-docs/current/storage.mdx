# 貯存

儲存是 Mastra 運行時的持久層。它在流程重新啟動後保持記憶體、Workflow狀態、Observability資料、評估結果、計劃和長期運行的Agent狀態可用。

儲存能力：

* [記憶](/docs/memory/overview)：訊息歷史記錄、執行緒、資源和工作記憶體。
* [Workflow](/docs/workflows/overview)：用於暫停和恢復Workflow運行的持久快照。
* [可觀察性](/docs/observability/overview)：追蹤、跨度、指標、日誌和回饋。
* [埃瓦爾斯](/docs/evals/overview)：分數、資料集、實驗和評估結果。
* [長期Agent](/docs/harness/durable-agents)：後台任務、計劃、目標和執行緒狀態。

## 何時配置儲存 {/* #when-to-configure-storage */}

當狀態必須在重新啟動後保留或跨進程共用時，配置持久性儲存適配器。持久性儲存也可以在 Studio 中跨會話保持狀態可見。預設記憶體儲存對於測試和簡短的本地實驗很有用，但當進程退出時它會丟失資料。

當您的應用程式需要以下任何行為時，請使用儲存空間：

* Agent會記住過去的訊息或用戶事實。
* Workflow暫停並在重新啟動後恢復。
* 追蹤、指標、日誌、分數或回饋可供分析。
* 計劃和後台任務在部署中繼續進行。
*

## 儲存的工作原理 {/* #how-storage-works */}

Mastra 儲存被組織成**domains**. A domain owns one type of runtime data, and a storage adapter implements one or more domains.

|網域 |它儲存什麼 |
| - | - |
|`memory` | Threads, messages, resources, working memory, and other agent memory state. |
| `workflows` | Workflow snapshots used to suspend and resume runs. |
| `observability` | Traces, spans, metrics, logs, and feedback. |
| `scores` | Eval score records. |
| `datasets` | Dataset records and dataset items used by evals and experiments. |
| `experiments` | Experiment runs and per-item experiment results. |
| `backgroundTasks` | Background task records and execution state. |
| `schedules` | Schedule definitions and trigger history. |
| `threadState` | Durable task, goal, and thread state. |

適配器支援因網域而異。有關完整的網域清單和內建架構，請參閱[storage overview reference](/reference/storage/overview).

## 按資料形狀選擇後端 {/* #choose-a-backend-by-data-shape */}

不同的網域寫入和查詢不同類型的資料。根據網域的存取模式選擇後端：

* `memory`：在每個記住的Agent呼叫期間讀取和寫入行。使用事務資料庫，例如 libSQL、PostgreSQL 或 MongoDB。
* `observability`：寫入大量遙測資料並經常查詢聚合。使用專用的Observability儲存或線上分析處理 (OLAP) 後端，例如 ClickHouse 或 DuckDB。
* `workflows`：儲存復原運行時必須可用的持久快照。使用可靠的持久性資料庫。
* `scores`, `datasets`, and `experiments`: Store lower-frequency evaluation data that's often read later for analysis.
* `schedules`：儲存時間表定義和火災歷史記錄。使用實作計劃域的適配器。

當域有不同的操作需求時，使用[composite storage](#composite-storage) to route each domain to the right backend.

## 本地開始 {/* #get-started-locally */}

對於本機開發，請使用 libSQL 和檔案支援的資料庫。它不需要單獨的資料庫伺服器，並且在重新啟動之間保留狀態。

```typescript title="src/mastra/index.ts"
import { Mastra } from '@mastra/core'
import { LibSQLStore } from '@mastra/libsql'

export const mastra = new Mastra({
  storage: new LibSQLStore({
    id: 'mastra-storage',
    url: 'file:./mastra.db',
  }),
})
```

:::tip\[與 Studio 共用資料庫]

跑步時`mastra dev` alongside your application, use an absolute path so both processes access the same database:

```typescript
url: 'file:/absolute/path/to/your/project/mastra.db'
```

`file:./mastra.db` resolve based on each process's working directory, which may differ.

:::

Mastra 在首次使用時初始化所需的儲存結構。

## 配置用於生產 {/* #configure-for-production */}

對於生產，請使用持久託管資料庫。對於大多數團隊來說，PostgreSQL 是一個很好的預設選擇，因為它適用於交易運行時狀態，並且作為託管服務廣泛可用。

生產指導：

* 使用具有備份、監控和連接池功能的託管資料庫。
* 保留本機檔案資料庫，例如`file:./mastra.db` out of multi-process production deployments.
* 路由大容量域，尤其是`observability`, to a dedicated backend with [composite storage](#composite-storage).
* 配置[retention](/reference/storage/retention) policies on the storage adapter or composite store, then call `storage.prune()` from a scheduler or maintenance job.
* 根據您的應用程式使用的網域選擇Provider。例如，調度需要一個適配器來實現`schedules` domain.

### Agent級存儲 {/* #agent-level-storage */}

Agent級儲存配置在`Memory` instance. It overrides instance-level storage for that agent's memory data only.

```typescript title="src/mastra/agents/support-agent.ts"
import { Agent } from '@mastra/core/agent'
import { Memory } from '@mastra/memory'
import { PostgresStore } from '@mastra/pg'

export const supportAgent = new Agent({
  id: 'support-agent',
  name: 'Support agent',
  instructions: 'Answer customer support questions.',
  model: '__GATEWAY_OPENAI_MODEL__',
  memory: new Memory({
    storage: new PostgresStore({
      id: 'support-agent-storage',
      connectionString: process.env.SUPPORT_AGENT_DATABASE_URL,
    }),
  }),
})
```

當Agent程式需要隔離的記憶體邊界或不同的記憶體後端時，請使用Agent級儲存。

## 複合儲存 {/* #composite-storage */}

[`MastraCompositeStore`](/reference/storage/composite)將域路由到不同的後端。當一個資料庫不適合每個網域時使用它。

以下範例使用 libSQL 作為預設儲存並將Workflow狀態路由到 PostgreSQL：

```typescript title="src/mastra/index.ts"
import { Mastra } from '@mastra/core'
import { MastraCompositeStore } from '@mastra/core/storage'
import { LibSQLStore } from '@mastra/libsql'
import { WorkflowsPG } from '@mastra/pg'

export const mastra = new Mastra({
  storage: new MastraCompositeStore({
    id: 'composite-storage',
    default: new LibSQLStore({
      id: 'default-storage',
      url: 'file:./mastra.db',
    }),
    domains: {
      workflows: new WorkflowsPG({
        connectionString: process.env.DATABASE_URL,
      }),
    },
  }),
})
```

您也可以路由`observability` to a dedicated analytics backend. See the [observability quickstart](/docs/observability/overview#quickstart) for an observability-specific example.
