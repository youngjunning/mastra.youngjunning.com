# 儲存

儲存是 Mastra 執行環境的持久儲存層。程序重新啟動後，仍可使用記憶、Workflow 狀態、可觀測性資料、評估結果、排程及長時間執行的 Agent 狀態。

以下功能會使用儲存層：

- [Memory](/docs/memory/overview)：訊息記錄、執行緒、資源和工作記憶。
- [Workflow](/docs/workflows/overview)：用於暫停與繼續執行的持久快照。
- [可觀測性](/docs/observability/overview)：Trace、Span、指標、記錄和回饋。
- [Evals](/docs/evals/overview)：分數、資料集、實驗與評估結果。
- [長時間執行的 Agent](/docs/harness/durable-agents)：背景工作、排程、目標和執行緒狀態。

## 何時需要設定儲存 {/* #when-to-configure-storage */}

若要在重新啟動後保留狀態，或要讓多個程序共用狀態，請設定持久儲存介面卡。這也能讓 Studio 在不同工作階段看到相同狀態。預設的記憶體儲存適合測試及短時間的本機實驗，但程序結束後資料就會消失。

若應用程式需要下列任一行為，就應設定儲存：

- Agent 記住先前的訊息或使用者相關資訊。
- Workflow 可暫停，並在重新啟動後繼續執行。
- 保留 Trace、指標、記錄、分數或回饋，以供分析。
- 排程與背景工作在重新部署後仍可繼續執行。
- 多個執行程序可讀寫同一份狀態。

## 儲存如何運作 {/* #how-storage-works */}

Mastra 以**領域**組織儲存。每個領域負責一種執行階段資料，一個儲存介面卡可實作一或多個領域。

| 領域 | 儲存內容 |
| - | - |
| `memory` | 執行緒、訊息、資源、工作記憶及其他 Agent 記憶狀態。 |
| `workflows` | 用於暫停及繼續執行的 Workflow 快照。 |
| `observability` | Trace、Span、指標、記錄和回饋。 |
| `scores` | 評估分數紀錄。 |
| `datasets` | 評估與實驗使用的資料集紀錄和項目。 |
| `experiments` | 實驗執行紀錄及各項目的實驗結果。 |
| `backgroundTasks` | 背景工作紀錄與執行狀態。 |
| `schedules` | 排程定義與觸發記錄。 |
| `threadState` | 持久儲存的工作、目標及執行緒狀態。 |

介面卡支援的領域各不相同。完整的領域清單與內建結構描述請參閱[儲存參考概觀](/reference/storage/overview)。

## 依資料存取模式選擇後端 {/* #choose-a-backend-by-data-shape */}

各領域寫入與查詢的資料類型不同，請依領域的存取模式選擇後端：

- `memory`：每次呼叫啟用記憶的 Agent 都會讀寫資料列。請使用支援交易的資料庫，例如 libSQL、PostgreSQL 或 MongoDB。
- `observability`：寫入大量遙測資料，而且經常執行彙總查詢。請使用專用的可觀測性儲存，或 ClickHouse、DuckDB 等線上分析處理（OLAP）後端。
- `workflows`：持久儲存快照，讓執行作業繼續時一定能讀到。請使用可靠的持久儲存資料庫。
- `scores`、`datasets` 和 `experiments`：儲存寫入頻率較低的評估資料，通常在後續分析時讀取。
- `schedules`：儲存排程定義與觸發記錄。請使用有實作排程領域的介面卡。

各領域的運作需求不同時，可用[複合儲存](#composite-storage)將各領域導向合適的後端。

## 在本機開始使用 {/* #get-started-locally */}

本機開發可使用以檔案為基礎的 libSQL 資料庫，不必另外執行資料庫伺服器，也能在重新啟動後保留狀態。

```typescript title="src/mastra/index.ts"
import { Mastra } from '@mastra/core'
import { LibSQLStore } from '@mastra/libsql'

export const mastra = new Mastra({
  storage: new LibSQLStore({
    id: 'mastra-storage',
    url: 'file:./mastra.db',
  }),
})
```

:::tip[與 Studio 共用資料庫]

如果同時執行 `mastra dev` 和應用程式，請使用絕對路徑，讓兩個程序存取同一個資料庫：

```typescript
url: 'file:/absolute/path/to/your/project/mastra.db'
```

像 `file:./mastra.db` 這樣的相對路徑會依各程序的工作目錄解析，而這些目錄可能不同。

:::

Mastra 會在第一次使用時初始化所需的儲存結構。

## 設定正式環境 {/* #configure-for-production */}

正式環境請使用具備持久儲存能力的託管資料庫。PostgreSQL 適合多數團隊作為預設選擇，因為它適合處理需要交易的執行階段狀態，而且有許多託管服務可選。

正式環境的建議做法：

- 使用提供備份、監控與連線集區的託管資料庫。
- 在多程序的正式環境部署中，避免使用 `file:./mastra.db` 等本機檔案資料庫。
- 以[複合儲存](#composite-storage)將高資料量的領域（特別是 `observability`）導向專用後端。
- 在儲存介面卡或複合儲存中設定[保留](/reference/storage/retention)原則，再從排程器或維護工作呼叫 `storage.prune()`。
- 依應用程式使用的領域選擇 Provider。例如，排程需要實作 `schedules` 領域的介面卡。

## 設定範圍 {/* #configuration-scope */}

你可以在 Mastra 執行個體或 Agent 層級設定儲存。

### 執行個體層級的儲存 {/* #instance-level-storage */}

註冊於同一 Mastra 執行個體的 Agent、Workflow、可觀測性、Evals、排程和其他執行階段功能，共用執行個體層級的儲存。

<Tabs>
  <TabItem value="postgresql" label="PostgreSQL">
    ```typescript title="src/mastra/index.ts"
    import { Mastra } from '@mastra/core'
    import { PostgresStore } from '@mastra/pg'

    export const mastra = new Mastra({
      storage: new PostgresStore({
        id: 'mastra-storage',
        connectionString: process.env.DATABASE_URL,
      }),
    })
    ```
  </TabItem>

  <TabItem value="mongodb" label="MongoDB">
    ```typescript title="src/mastra/index.ts"
    import { Mastra } from '@mastra/core'
    import { MongoDBStore } from '@mastra/mongodb'

    export const mastra = new Mastra({
      storage: new MongoDBStore({
        id: 'mastra-storage',
        uri: process.env.MONGODB_URI,
        dbName: process.env.MONGODB_DB_NAME,
      }),
    })
    ```
  </TabItem>
</Tabs>

多數執行階段領域可共用同一個資料庫時，請使用執行個體層級的儲存。

### Agent 層級的儲存 {/* #agent-level-storage */}

Agent 層級的儲存是在 `Memory` 執行個體上設定，而且只會針對該 Agent 的記憶資料覆寫執行個體層級的儲存設定。

```typescript title="src/mastra/agents/support-agent.ts"
import { Agent } from '@mastra/core/agent'
import { Memory } from '@mastra/memory'
import { PostgresStore } from '@mastra/pg'

export const supportAgent = new Agent({
  id: 'support-agent',
  name: 'Support agent',
  instructions: 'Answer customer support questions.',
  model: '__GATEWAY_OPENAI_MODEL__',
  memory: new Memory({
    storage: new PostgresStore({
      id: 'support-agent-storage',
      connectionString: process.env.SUPPORT_AGENT_DATABASE_URL,
    }),
  }),
})
```

若 Agent 需要隔離記憶，或需要不同的記憶後端，請使用 Agent 層級的儲存。

## 複合儲存 {/* #composite-storage */}

[`MastraCompositeStore`](/reference/storage/composite) 可將不同領域導向不同後端。如果同一個資料庫無法兼顧各個領域，請使用複合儲存。

以下範例以 libSQL 作為預設儲存後端，並將 Workflow 狀態導向 PostgreSQL：

```typescript title="src/mastra/index.ts"
import { Mastra } from '@mastra/core'
import { MastraCompositeStore } from '@mastra/core/storage'
import { LibSQLStore } from '@mastra/libsql'
import { WorkflowsPG } from '@mastra/pg'

export const mastra = new Mastra({
  storage: new MastraCompositeStore({
    id: 'composite-storage',
    default: new LibSQLStore({
      id: 'default-storage',
      url: 'file:./mastra.db',
    }),
    domains: {
      workflows: new WorkflowsPG({
        connectionString: process.env.DATABASE_URL,
      }),
    },
  }),
})
```

也可以將 `observability` 導向專用的分析後端。相關範例請參閱[可觀測性快速入門](/docs/observability/overview#quickstart)。
