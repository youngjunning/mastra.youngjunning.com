# 動態Workflow

:::測試版

在 API 穩定之前，可能會在沒有重大版本更新的情況下發生重大變更。

:::

動態Workflow是以資料而不是程式碼表示的Workflow定義。定義是一個 JSON 文檔，用於描述Workflow的架構和步驟圖。 Mastra 驗證定義並將其註冊為可運行的Workflow，然後將其保留在儲存中，以便它在流程重新啟動後仍然存在。

由於定義不包含 JavaScript 閉包，因此任何產生 JSON 的內容都可以建立Workflow。來源包括 HTTP 用戶端或 LLM。視覺化編輯器或您自己的Tool也可以產生定義。註冊後，動態Workflow將透過與程式碼定義Workflow相同的執行 API 來運行。

## 何時使用動態Workflow {/* #when-to-use-dynamic-workflows */}

當使用者、Agent程式、視覺化編輯器或外部系統需要建立Workflow而不更改應用程式程式碼或再次部署時，請使用動態Workflow。

繼續定義Workflow[`createWorkflow()`](/docs/workflows/overview) when the workflow belongs in your application source or needs custom step functions. Dynamic workflows can invoke agents, tools, and workflows that are already registered on the `Mastra` instance.

## 快速入門 {/* #quickstart */}

以下範例註冊一個Tool並從動態Workflow中呼叫它。然後它運行Workflow。`LibSQLStore` persists the definition in `mastra.db`, so Mastra can restore it after a restart.

```typescript title="src/dynamic-workflow.ts"
import { Mastra } from '@mastra/core/mastra'
import { createTool } from '@mastra/core/tools'
import { LibSQLStore } from '@mastra/libsql'
import { z } from 'zod'

const greetingTool = createTool({
  id: 'create-greeting',
  description: 'Create a greeting for a name',
  inputSchema: z.object({
    name: z.string(),
  }),
  outputSchema: z.object({
    message: z.string(),
  }),
  execute: async ({ name }) => ({
    message: `Hello, ${name}!`,
  }),
})

const mastra = new Mastra({
  storage: new LibSQLStore({
    id: 'mastra-storage',
    url: 'file:./mastra.db',
  }),
  tools: { 'create-greeting': greetingTool },
})

await mastra.addDynamicWorkflow({
  id: 'greeting-workflow',
  description: 'Create a greeting for the supplied name',
  inputSchema: {
    type: 'object',
    properties: {
      name: { type: 'string' },
    },
    required: ['name'],
  },
  outputSchema: {
    type: 'object',
    properties: {
      message: { type: 'string' },
    },
    required: ['message'],
  },
  graph: [
    {
      type: 'tool',
      id: 'greet',
      toolId: 'create-greeting',
    },
  ],
})

const workflow = mastra.getWorkflow('greeting-workflow')
const run = await workflow.createRun()
const result = await run.start({
  inputData: { name: 'Ada' },
})

if (result.status === 'success') {
  console.log(result.result.message)
}
```

Workflow列印`Hello, Ada!`. Calling [`addDynamicWorkflow()`](/reference/core/addDynamicWorkflow) validates the definition before it changes storage or the live workflow registry.

這個定義使用 JSON 架構，因為它必須在 JSON 往返過程中存活下來。這`graph` describes which registered components to invoke and how data moves between them. See the [dynamic workflow definition reference](/reference/workflows/dynamic-workflow-definition) for every field and graph entry.

## 建置和更新定義 {/* #build-and-update-definitions */}

定義可以來自任何產生 JSON 的來源。例如，API 路由可以接受視覺化編輯器建立的定義並直接註冊：

```typescript
const definition = await request.json()
await mastra.addDynamicWorkflow(definition)
```

### 先註冊依賴 {/* #register-dependencies-first */}

在同一組件上註冊引用的組件`Mastra` instance before adding the dynamic workflow. Agent and nested workflow entries use their intrinsic IDs. A tool entry uses its key from the `Mastra` `tools` object. The quickstart registers the tool under `create-greeting` before referencing that key with `toolId`.

使用一個`mapping` entry when one step's output doesn't match the next step's input. Mapping entries can read data from the workflow input and previous step results, along with workflow state and request context. The [definition reference](/reference/workflows/dynamic-workflow-definition#mapping-steps) lists the supported mapping descriptors.

### 替換Workflow {/* #replace-a-workflow */}

新增具有相同內容的新定義`id` to replace the persisted definition and live registration:

```typescript
await mastra.addDynamicWorkflow(updatedDefinition)
```

新的運行使用更新的圖表。已经开始的运行将继续其原始图表。

### {/* #add-nested-workflows-together */}

當根Workflow引用尚未註冊的幫助程序Workflow時，請新增完整的Workflow集[`addDynamicWorkflows()`](/reference/core/addDynamicWorkflows):

```typescript
await mastra.addDynamicWorkflows([rootDefinition, helperDefinition])
```

Mastra 將捆綁包作為一個單元進行驗證，並根據依賴項確定註冊順序。如果驗證失敗，則不會註冊任何定義。

### 透過 HTTP 管理定義 {/* #manage-definitions-over-http */}

應用程式不需要直接訪問`Mastra` instance to manage dynamic workflows. Use one of these interfaces:

* [客戶端 SDK Workflow API](/reference/client-js/workflows)： 稱呼`upsertDynamicWorkflow()` from a JavaScript or TypeScript client.
* [伺服器路由](/reference/server/routes)：將定義發送至`POST /api/stored/workflows`.

在經過身份驗證的伺服器上，動態Workflow管理需要`stored-workflows:read` and `stored-workflows:write` permissions. Running the registered workflow requires `workflows:execute`.

### 保留定義 {/* #persist-definitions */}

儲存的定義使用`workflowDefinitions` storage domain. On startup, Mastra loads active definitions from storage and registers them in dependency order.

如果沒有支援該網域的儲存適配器，`addDynamicWorkflow()` still registers the workflow in memory, but the definition is lost when the process restarts. See the [storage reference](/reference/storage/overview) for adapter support.
