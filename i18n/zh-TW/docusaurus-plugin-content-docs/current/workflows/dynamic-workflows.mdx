# 動態 Workflow

:::beta

API 穩定前，即使主要版本號沒有變更，也可能出現不相容的變更。

:::

動態 Workflow 以資料定義 Workflow。定義是一份描述結構描述與步驟圖的 JSON 文件。Mastra 驗證後會註冊為可執行的 Workflow，並加以儲存，讓程序重新啟動後仍可使用。

定義不含 JavaScript 閉包，因此任何能產生 JSON 的來源都能建立 Workflow，例如 HTTP 用戶端、LLM、視覺化編輯器或自行開發的工具。註冊後，動態 Workflow 與程式碼定義的 Workflow 共用同一套執行 API。

## 何時使用動態 Workflow {/* #when-to-use-dynamic-workflows */}

若使用者、Agent、視覺化編輯器或外部系統需要建立 Workflow，又不能修改應用程式程式碼或重新部署，可使用動態 Workflow。

若 Workflow 是應用程式原始碼的一部分，或需要自訂步驟函式，請繼續使用 [`createWorkflow()`](/docs/workflows/overview) 定義。動態 Workflow 可以呼叫已在 `Mastra` 執行個體註冊的 Agent、Tool 和 Workflow。

## 快速入門 {/* #quickstart */}

以下範例先註冊 Tool，再由動態 Workflow 呼叫它並執行該 Workflow。`LibSQLStore` 會將定義儲存在 `mastra.db`，讓 Mastra 重新啟動後還原。

```typescript title="src/dynamic-workflow.ts"
import { Mastra } from '@mastra/core/mastra'
import { createTool } from '@mastra/core/tools'
import { LibSQLStore } from '@mastra/libsql'
import { z } from 'zod'

const greetingTool = createTool({
  id: 'create-greeting',
  description: 'Create a greeting for a name',
  inputSchema: z.object({
    name: z.string(),
  }),
  outputSchema: z.object({
    message: z.string(),
  }),
  execute: async ({ name }) => ({
    message: `Hello, ${name}!`,
  }),
})

const mastra = new Mastra({
  storage: new LibSQLStore({
    id: 'mastra-storage',
    url: 'file:./mastra.db',
  }),
  tools: { 'create-greeting': greetingTool },
})

await mastra.addDynamicWorkflow({
  id: 'greeting-workflow',
  description: 'Create a greeting for the supplied name',
  inputSchema: {
    type: 'object',
    properties: {
      name: { type: 'string' },
    },
    required: ['name'],
  },
  outputSchema: {
    type: 'object',
    properties: {
      message: { type: 'string' },
    },
    required: ['message'],
  },
  graph: [
    {
      type: 'tool',
      id: 'greet',
      toolId: 'create-greeting',
    },
  ],
})

const workflow = mastra.getWorkflow('greeting-workflow')
const run = await workflow.createRun()
const result = await run.start({
  inputData: { name: 'Ada' },
})

if (result.status === 'success') {
  console.log(result.result.message)
}
```

Workflow 會印出 `Hello, Ada!`。呼叫 [`addDynamicWorkflow()`](/reference/core/addDynamicWorkflow) 時，會先驗證定義，再變更儲存內容或目前的 Workflow 註冊表。

定義必須能轉成 JSON 再讀回，因此使用 JSON Schema。`graph` 說明要呼叫哪些已註冊的元件，以及資料如何在元件之間傳遞。所有欄位與圖項目請見[動態 Workflow 定義參考](/reference/workflows/dynamic-workflow-definition)。

## 建置和更新定義 {/* #build-and-update-definitions */}

任何能產生 JSON 的來源都能提供定義。例如，API 路由可以接收視覺化編輯器產生的定義並直接註冊：

```typescript
const definition = await request.json()
await mastra.addDynamicWorkflow(definition)
```

### 先註冊依賴 {/* #register-dependencies-first */}

新增動態 Workflow 前，請先在同一個 `Mastra` 執行個體註冊它參照的元件。Agent 和巢狀 Workflow 使用自身的 ID；Tool 使用它在 `Mastra` 的 `tools` 物件中的鍵。快速入門範例先用 `create-greeting` 註冊 Tool，再以 `toolId` 參照該鍵。

如果某個步驟的輸出不符合下一步的輸入，請使用 `mapping` 項目。對應項目可讀取 Workflow 輸入、先前步驟的結果、Workflow 狀態及請求脈絡。支援的對應描述項請見[定義參考](/reference/workflows/dynamic-workflow-definition#mapping-steps)。

### 取代 Workflow {/* #replace-a-workflow */}

新增相同 `id` 的定義，即可取代已儲存的定義及目前註冊的 Workflow：

```typescript
await mastra.addDynamicWorkflow(updatedDefinition)
```

新啟動的執行會使用更新後的步驟圖，已開始的執行則沿用原圖。

### 一併新增巢狀 Workflow {/* #add-nested-workflows-together */}

根 Workflow 若參照尚未註冊的輔助 Workflow，請使用 [`addDynamicWorkflows()`](/reference/core/addDynamicWorkflows) 一併新增所有定義：

```typescript
await mastra.addDynamicWorkflows([rootDefinition, helperDefinition])
```

Mastra 會將整組定義一起驗證，再依相依關係決定註冊順序。如果驗證失敗，所有定義都不會註冊。

### 透過 HTTP 管理定義 {/* #manage-definitions-over-http */}

應用程式無須直接存取 `Mastra` 執行個體，也能管理動態 Workflow。請使用下列任一介面：

- [Client SDK 的 Workflow API](/reference/client-js/workflows)：在 JavaScript 或 TypeScript 用戶端呼叫 `upsertDynamicWorkflow()`。
- [伺服器路由](/reference/server/routes)：將定義送到 `POST /api/stored/workflows`。

伺服器若啟用身分驗證，管理動態 Workflow 需要 `stored-workflows:read` 和 `stored-workflows:write` 權限，執行已註冊的 Workflow 則需要 `workflows:execute` 權限。

### 儲存定義 {/* #persist-definitions */}

定義儲存在 `workflowDefinitions` 儲存網域。啟動時，Mastra 會載入作用中的定義，再依相依順序註冊。

即使沒有支援此儲存網域的轉接器，`addDynamicWorkflow()` 還是會在記憶體中註冊 Workflow，但程序重新啟動後就會遺失定義。支援的轉接器請見[儲存參考](/reference/storage/overview)。
