# 快照

在 Mastra 中，快照會以可序列化的形式記錄 Workflow 在特定時間點的完整執行狀態。其中包含從暫停處繼續執行所需的所有資訊，包括：

- 各個步驟目前的狀態
- 已完成步驟的輸出
- Workflow 已走過的執行路徑
- 所有暫停的步驟及其中繼資料
- 各步驟剩餘的重試次數
- 繼續執行所需的其他上下文資料

每當 Workflow 暫停時，Mastra 都會自動建立及管理快照，並將快照持久儲存到設定的儲存系統。

## 快照在暫停與繼續執行時的作用 {/* #the-role-of-snapshots-in-suspend-and-resume */}

Mastra 透過快照實現暫停與繼續執行。當 Workflow 步驟呼叫 `await suspend()` 時：

1. Workflow 會在呼叫處暫停。
1. 系統將 Workflow 當下的狀態記錄成快照。
1. 系統將快照寫入持久儲存空間。
1. 步驟會標記為暫停，狀態是 `'suspended'`。
1. 之後對暫停的步驟呼叫 `resume()` 時，系統會讀取快照。
1. Workflow 從原本暫停的位置繼續執行。

這個機制可用來建立有人員參與的 Workflow、處理速率限制、等待外部資源，或實作可能需要長時間暫停的複雜分支 Workflow。

## 快照的內容 {/* #snapshot-anatomy */}

每份快照都包含 `runId`、輸入、步驟狀態（如 `success` 或 `suspended`）、暫停和繼續執行的酬載（若有），以及最終輸出。因此，繼續執行時可取得完整的上下文。

## 儲存與讀取快照 {/* #how-snapshots-are-saved-and-retrieved */}

快照會寫入設定的儲存系統。預設使用 libSQL，也能改用 Upstash、PostgreSQL 或 OracleDB。每份快照都存放在 `workflow_snapshots` 資料表，並以 Workflow 的 `runId` 識別。

### 儲存快照 {/* #saving-snapshots */}

Workflow 暫停時，Mastra 會依照下列流程自動持久儲存快照：

1. 步驟執行時呼叫 `suspend()` 函式，觸發快照流程。
1. `WorkflowInstance.suspend()` 方法會記錄暫停的狀態機。
1. 系統呼叫 `persistWorkflowSnapshot()` 儲存目前的狀態。
1. 系統將快照序列化後，寫入設定的資料庫中的 `workflow_snapshots` 資料表。
1. 儲存的紀錄包含 Workflow 名稱、執行 ID 及序列化後的快照。

### 讀取快照 {/* #retrieving-snapshots */}

Workflow 繼續執行時，Mastra 會依照下列流程讀取已儲存的快照：

1. 呼叫 `resume()` 方法，並傳入指定的步驟 ID。
1. 使用 `loadWorkflowSnapshot()` 從儲存空間載入快照。
1. 解析快照，準備繼續執行。
1. 依快照狀態重建 Workflow 的執行。
1. 讓暫停的步驟恢復並繼續執行。

```typescript
const storage = mastra.getStorage()
const workflowStore = await storage?.getStore('workflows')

const snapshot = await workflowStore?.loadWorkflowSnapshot({
  runId: '<run-id>',
  workflowName: '<workflow-id>',
})

console.log(snapshot)
```

## 快照的儲存選項 {/* #storage-options-for-snapshots */}

快照會透過 `Mastra` 類別上設定的 `storage` 執行個體持久儲存。註冊到同一 Mastra 執行個體的所有 Workflow 共用這個儲存層。Mastra 支援多種儲存選項，以配合不同環境。

```typescript title="src/mastra/index.ts"
import { Mastra } from '@mastra/core'
import { LibSQLStore } from '@mastra/libsql'
import { approvalWorkflow } from './workflows'

export const mastra = new Mastra({
  storage: new LibSQLStore({
    id: 'mastra-storage',
    url: ':memory:',
  }),
  workflows: { approvalWorkflow },
})
```

## 最佳實務 {/* #best-practices */}

1. **確認資料可序列化**：要寫入快照的所有資料都必須可序列化，也就是能轉成 JSON。
1. **縮小快照**：避免直接把大型資料物件放進 Workflow 上下文。只保留參照，例如 ID，需要時再取得資料。
1. **審慎處理繼續執行時的上下文**：請仔細決定恢復 Workflow 時要提供哪些上下文，這些內容會與現有快照資料合併。
1. **妥善設定監控**：監控暫停中的 Workflow，尤其是長時間執行的 Workflow，並確認它們能正常繼續執行。
1. **考量儲存擴充性**：若應用程式有許多暫停的 Workflow，請確認儲存方案的規模能滿足需求。

## 自訂快照中繼資料 {/* #custom-snapshot-metadata */}

定義 `suspendSchema` 後，即可在暫停 Workflow 時附加自訂中繼資料。這些資料會存入快照，供 Workflow 繼續執行時使用。

```typescript {30-34} title="src/mastra/workflows/test-workflow.ts"
import { createWorkflow, createStep } from '@mastra/core/workflows'
import { z } from 'zod'

const approvalStep = createStep({
  id: 'approval-step',
  description: 'Accepts a value, waits for confirmation',
  inputSchema: z.object({
    value: z.number(),
    user: z.string(),
    requiredApprovers: z.array(z.string()),
  }),
  suspendSchema: z.object({
    message: z.string(),
    requestedBy: z.string(),
    approvers: z.array(z.string()),
  }),
  resumeSchema: z.object({
    confirm: z.boolean(),
    approver: z.string(),
  }),
  outputSchema: z.object({
    value: z.number(),
    approved: z.boolean(),
  }),
  execute: async ({ inputData, resumeData, suspend }) => {
    const { value, user, requiredApprovers } = inputData
    const { confirm } = resumeData ?? {}

    if (!confirm) {
      return await suspend({
        message: 'Workflow suspended',
        requestedBy: user,
        approvers: [...requiredApprovers],
      })
    }

    return {
      value,
      approved: confirm,
    }
  },
})
```

### 提供繼續執行所需的資料 {/* #providing-resume-data */}

繼續執行暫停的步驟時，可用 `resumeData` 傳入結構化輸入。資料必須符合步驟的 `resumeSchema`。

```typescript {14-20}
const workflow = mastra.getWorkflow('approvalWorkflow')

const run = await workflow.createRun()

const result = await run.start({
  inputData: {
    value: 100,
    user: 'Michael',
    requiredApprovers: ['manager', 'finance'],
  },
})

if (result.status === 'suspended') {
  const resumedResult = await run.resume({
    step: 'approval-step',
    resumeData: {
      confirm: true,
      approver: 'manager',
    },
  })
}
```
