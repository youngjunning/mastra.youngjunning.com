# Workflows

Workflow 讓你以清楚、有結構的步驟安排複雜任務，不必仰賴單一 Agent 推理整個流程。你可以決定任務的拆分方式，以及資料流動的順序和時機。Workflow 預設使用內建執行引擎；如需代管基礎設施，也可以透過 Inngest 等 [Workflow runner](/docs/deployment/workflow-runners) 提供。

<Inject>
  **供 AI Agent 使用：**執行 `npx mastra api workflow run start test-workflow '{"inputData":{"message":"Hello, world!"}}'`，即可直接啟動此 Workflow，無須撰寫暫存腳本。此指令需要運作中的 Mastra 伺服器；可用 `npx mastra dev` 啟動本機伺服器，或以 `--url` 指定可連線伺服器的基底 URL。組出其他輸入前，先執行 `npx mastra api workflow run start --schema`。安裝 Mastra Skill：`npx skills add mastra-ai/skills --skill mastra`，以取得完整的 API CLI 探索、目標指定、Schema、驗證身分與錯誤處理指引。
</Inject>

## 何時使用 Workflow {/* #when-to-use-workflows */}

任務若能事先明確定義，且包含須依特定順序執行的多個步驟，就適合使用 Workflow。你可以精確控制資料在步驟間如何傳遞、轉換，以及各階段要呼叫哪些元件。

## 核心原則 {/* #core-principles */}

Mastra Workflow 遵循以下原則：

- 使用 [`createStep`](/reference/workflows/step) 定義**步驟**，指定輸入與輸出 Schema 及業務邏輯。
- 使用 [`createWorkflow`](/reference/workflows/workflow) 組合**步驟**，定義執行流程。
- 執行 **Workflow** 以完成整個序列；內建支援暫停、繼續執行及串流結果。

## 建立 Workflow 步驟 {/* #creating-a-workflow-step */}

步驟是 Workflow 的基本組成單位。使用 `createStep()` 建立步驟，並以 `inputSchema` 和 `outputSchema` 定義接收及回傳的資料。兩種 Schema 都可使用 [Standard JSON Schema](https://standardschema.dev/json-schema) 定義，例如透過 [Zod](https://zod.dev/)、[Valibot](https://valibot.dev/) 或 [ArkType](https://arktype.io/)。

`execute` 函式定義步驟要執行的工作，可用來呼叫程式碼中的函式、外部 API、Agent 或 Tool。

    ```typescript {7,10,16} title="src/mastra/workflows/test-workflow.ts"
    import { z } from 'zod'

    const step1 = createStep({
      id: 'step-1',
      inputSchema: z.object({
        message: z.string(),
      }),
      outputSchema: z.object({
        formatted: z.string(),
      }),
      execute: async ({ inputData }) => {
        const { message } = inputData

        return {
          formatted: message.toUpperCase(),
        }
      },
    })
    ```
  </TabItem>

## 建立 Workflow {/* #creating-a-workflow */}

使用 `createWorkflow()` 建立 Workflow，並以 `inputSchema` 和 `outputSchema` 定義接收及回傳的資料。兩種 Schema 都可使用 [Standard JSON Schema](https://standardschema.dev/json-schema) 定義，例如透過 [Zod](https://zod.dev/)、[Valibot](https://valibot.dev/) 或 [ArkType](https://arktype.io/)。以 `.then()` 加入步驟，最後呼叫 `.commit()` 完成 Workflow。

### 理解控制流程 {/* #understanding-control-flow */}

Workflow 有多種組合方式；所選方式會決定各步驟的 Schema 應如何設計。詳情請參閱[控制流程](/docs/workflows/control-flow)。

## Studio {/* #studio */}

開啟 [Studio](/docs/studio/overview)，在 **Workflows** 分頁選取 Workflow。

- **圖形檢視**：中央面板呈現 Workflow 的步驟與執行流程。
- **輸入表單**：右側邊欄根據 Workflow 的 `inputSchema` 產生表單。填寫後即可啟動執行。
- **即時狀態**：執行期間，圖形會即時更新各步驟狀態；側邊欄則顯示 Workflow 的輸入、輸出、狀態和日誌。
- [**時間回溯**](/docs/workflows/time-travel)：執行完畢後，可重播個別步驟以檢查或重試。

## Workflow 狀態 {/* #workflow-state */}

Workflow 狀態可讓多個步驟共用值，而不必在每一步的 inputSchema 和 outputSchema 之間傳遞。你可以用狀態追蹤進度、累積結果，或在整個 Workflow 內共用設定。

```typescript title="src/mastra/workflows/test-workflow.ts"
import { createStep } from '@mastra/core/workflows'
import { z } from 'zod'

const step1 = createStep({
  id: 'step-1',
  inputSchema: z.object({ message: z.string() }),
  outputSchema: z.object({ formatted: z.string() }),
  stateSchema: z.object({ counter: z.number() }),
  execute: async ({ inputData, state, setState }) => {
    // Read from state
    console.log(state.counter)

    // Update state for subsequent steps
    setState({ ...state, counter: state.counter + 1 })

    return { formatted: inputData.message.toUpperCase() }
  },
})
```

關於狀態 Schema、初始狀態、暫停與繼續執行之間的持久化，以及巢狀 Workflow，請參閱 [Workflow 狀態](/docs/workflows/workflow-state)。

## 將 Workflow 當作步驟 {/* #workflows-as-steps */}

把 Workflow 當作步驟，即可在更大的流程中重複使用其邏輯。輸入與輸出遵循[核心原則](/docs/workflows/control-flow)所述的相同 Schema 規則。

```typescript {29} title="src/mastra/workflows/test-workflow.ts" oxfmt:false
import { createWorkflow, createStep } from '@mastra/core/workflows';
import { z } from 'zod';

const step1 = createStep({...});
const step2 = createStep({...});

const childWorkflow = createWorkflow({
  id: "child-workflow",
  inputSchema: z.object({
    message: z.string()
  }),
  outputSchema: z.object({
    emphasized: z.string()
  })
})
  .then(step1)
  .then(step2)
  .commit();

export const testWorkflow = createWorkflow({
  id: "test-workflow",
  inputSchema: z.object({
    message: z.string()
  }),
  outputSchema: z.object({
    emphasized: z.string()
  })
})
  .then(childWorkflow)
  .commit();
```

### 複製 Workflow {/* #cloning-a-workflow */}

想沿用 Workflow 邏輯，但以新 ID 分開追蹤時，請使用 `cloneWorkflow()`。每個複本會獨立執行，並在日誌與可觀測性工具中顯示為不同的 Workflow。

```typescript oxfmt:false {6} title="src/mastra/workflows/test-workflow.ts"
import { cloneWorkflow, createWorkflow, createStep } from "@mastra/core/workflows";

const step1 = createStep({...});

const parentWorkflow = createWorkflow({...})
const clonedWorkflow = cloneWorkflow(parentWorkflow, { id: "cloned-workflow" });

export const testWorkflow = createWorkflow({...})
  .then(step1)
  .then(clonedWorkflow)
  .commit();
```

## 註冊 Workflow {/* #registering-a-workflow */}

在 Mastra 執行個體註冊 Workflow，即可讓整個應用程式使用。註冊後，Agent 或 Tool 能呼叫它，它也能存取日誌與可觀測性等共用資源：

```typescript {5} title="src/mastra/index.ts"
import { Mastra } from '@mastra/core/mastra'
import { testWorkflow } from './workflows/test-workflow'

export const mastra = new Mastra({
  workflows: { testWorkflow },
})
```

## 取得 Workflow 參照 {/* #referencing-a-workflow */}

你可以從 Agent、Tool、Mastra Client 或命令列執行 Workflow。依據使用情境，在 `mastra` 或 `mastraClient` 執行個體上呼叫 `.getWorkflow()` 取得參照：

```typescript
const testWorkflow = mastra.getWorkflow('testWorkflow')
```

:::note

相較於直接匯入，建議使用 `mastra.getWorkflow()`，理由有兩個：

1. 可取得 Mastra 執行個體的設定，包括記錄器、遙測、儲存空間、已註冊的 Agent 與向量儲存空間。
1. 可完整推論 Workflow 輸入與輸出 Schema 的 TypeScript 型別。

呼叫 `getWorkflow()` 時，請使用 Workflow 的**註冊鍵**（新增至 Mastra 時使用的鍵）。`getWorkflowById()` 可依 Workflow 的 `id` 屬性擷取，但無法提供同等程度的型別推論。
:::

## 執行 Workflow {/* #running-workflows */}

Workflow 有兩種執行模式：start 會等所有步驟完成才回傳，stream 則在執行期間發出事件。只需要最終結果時選擇 start；需要監看進度或在步驟完成時觸發動作時選擇 stream。

<Tabs>
  <TabItem value="start" label=".start()">
    先使用 `createRun()` 建立 Workflow 執行個體，再呼叫 `.start()`，傳入符合 Workflow `inputSchema` 的 `inputData`。Workflow 會執行所有步驟並回傳最終結果。

    ```typescript
    const run = await testWorkflow.createRun()

    const result = await run.start({
      inputData: {
        message: 'Hello world',
      },
    })

    if (result.status === 'success') {
      console.log(result.result)
    }
    ```
  </TabItem>

  <TabItem value="stream" label=".stream()">
    先使用 `.createRun()` 建立 Workflow 執行個體，再呼叫 `.stream()`，傳入符合 Workflow `inputSchema` 的 `inputData`。逐一讀取 `fullStream` 以追蹤進度，最後等待 `result` 取得最終結果。

    ```typescript
    const run = await testWorkflow.createRun()

    const stream = run.stream({
      inputData: {
        message: 'Hello world',
      },
    })

    for await (const chunk of stream.fullStream) {
      console.log(chunk)
    }

    // Get the final result (same type as run.start())
    const result = await stream.result

    if (result.status === 'success') {
      console.log(result.result)
    }
    ```
  </TabItem>
</Tabs>

### Workflow 結果型別 {/* #workflow-result-type */}

`run.start()` 與 `stream.result` 都會依 `status` 回傳可辨識聯集型別；狀態可能為 `success`、`failed`、`suspended`、`tripwire` 或 `paused`。無論狀態為何，都能安全存取 `result.status`、`result.input`、`result.steps`，以及可能存在的 `result.state`。

此外，各狀態會提供不同屬性：

| 狀態 | 專屬屬性 | 說明 |
| - | - | - |
| `success` | `result` | Workflow 的輸出資料 |
| `failed` | `error` | 造成失敗的錯誤 |
| `tripwire` | `tripwire` | 包含 `reason`、`retry?`、`metadata?`、`processorId?` |
| `suspended` | `suspendPayload`、`suspended` | 暫停資料與已暫停步驟路徑的陣列 |
| `paused` | _（無）_ | 僅有共通屬性 |

要讀取特定狀態的屬性，請先檢查 `status`：

```typescript
const result = await run.start({ inputData: { message: 'Hello world' } })

if (result.status === 'success') {
  console.log(result.result) // Only available when status is "success"
} else if (result.status === 'failed') {
  console.log(result.error.message)
} else if (result.status === 'suspended') {
  console.log(result.suspendPayload)
}
```

## 串流 {/* #streaming */}

通用 `writer` API 的用法請參閱[串流](/docs/guides/streaming#writer-api)。

### 檢查 Workflow 串流酬載 {/* #inspecting-workflow-stream-payloads */}

寫入串流的事件會包含在送出的資料區塊中。檢查區塊即可讀取事件類型、中間值或步驟專屬資料等自訂欄位。

```typescript
const testWorkflow = mastra.getWorkflow('testWorkflow')

const run = await testWorkflow.createRun()

const stream = await run.stream({
  inputData: {
    value: 'initial data',
  },
})

for await (const chunk of stream) {
  console.log(chunk)
}

if (result!.status === 'suspended') {
  // if the workflow is suspended, we can resume it with the resumeStream method
  const resumedStream = await run.resumeStream({
    resumeData: { value: 'resume data' },
  })

  for await (const chunk of resumedStream) {
    console.log(chunk)
  }
}
```

### 繼續中斷的 Workflow 串流 {/* #resuming-an-interrupted-workflow-stream */}

若 Workflow 串流因任何原因關閉或中斷，可使用 `resumeStream` 方法繼續。此方法會回傳新的 `ReadableStream`，供你持續觀察 Workflow 事件。

```typescript
const newStream = await run.resumeStream()

for await (const chunk of newStream) {
  console.log(chunk)
}
```

### 在 Workflow 中使用 Agent {/* #workflow-using-an-agent */}

將 Agent 的 `textStream` 傳入 Workflow 步驟的 `writer`，即可串流傳送部分輸出；Mastra 也會自動把 Agent 的用量彙整到該次 Workflow 執行。

```typescript
import { createStep } from '@mastra/core/workflows'
import { z } from 'zod'

export const testStep = createStep({
  execute: async ({ inputData, mastra, writer }) => {
    const { city } = inputData

    const testAgent = mastra?.getAgent('testAgent')
    const stream = await testAgent?.stream(`What is the weather in ${city}?`)

    await stream!.textStream.pipeTo(writer!)

    return {
      value: await stream!.text,
    }
  },
})
```

## 重新啟動執行中的 Workflow {/* #restarting-active-workflow-runs */}

若 Workflow 執行與伺服器中斷連線，可從最後一個進行中的步驟重新啟動。這對可能在伺服器失聯時繼續執行的長時間工作特別有用。重新啟動後，Workflow 會從該步驟接續執行。

### 使用 `restartAllActiveWorkflowRuns()` 重新啟動 Workflow 的所有進行中執行項目 {/* #restarting-all-active-workflow-runs-of-a-workflow-with-restartallactiveworkflowruns */}

`restartAllActiveWorkflowRuns()` 可重新啟動某個 Workflow 的所有進行中執行項目，無須逐一走訪並手動重新啟動。

```typescript
workflow.restartAllActiveWorkflowRuns()
```

執行項目會並行重新啟動，並行數上限由 `recovery.workflowConcurrency` 設定（預設為 `5`）。若執行項目共用不能並行處理的副作用，請在 Mastra 設定中改為 `1`。

若要排除 `Mastra.restartAllActiveWorkflowRuns()` 在啟動時觸發的自動重新啟動，請在 Workflow 的 `options` 中設定 `autoRestartActiveRuns: false`。這適合具有副作用、不宜全面重新執行的 Workflow。持久化 Agent Workflow 會自動設定此選項，因為其復原由選擇啟用的 `recovery.durableAgents: 'auto'` 路徑負責。

執行期間，Mastra 會持有該執行項目的儲存租約，並在背景續約。租約尚未到期時，`restart()` 會拒絕接手、擲出 `WORKFLOW_RESTART_RUN_OWNED` 錯誤，掃描程序也會略過它。租約僅供協調使用，無法阻止寫入。若程序停止續約卻仍在執行步驟，例如事件迴圈阻塞超過租約 TTL，復原機制可能再次執行該步驟。`workflow.restartAllActiveWorkflowRuns()` 會略過這種執行項目且不重新檢查；若要復原，請等租約到期後再次呼叫。不支援執行項目所有權的儲存配接器維持先前行為，會重新啟動所有進行中的執行項目。

伺服器啟動時呼叫的 `mastra.restartAllActiveWorkflowRuns()`，只會在預設引擎的執行項目已停止時重新啟動：沒有執行個體持有租約，而且執行項目與租約在 `recovery.workflowGraceMs`（預設 2 秒）期間都沒有變動。仍在執行或剛停止的項目會留給[復原迴圈](#recovery-loop)。

對於採用可重新投遞未確認事件的訊息代理（Redis Streams、Valkey Streams、Google Cloud Pub/Sub）的 pubsub，事件驅動執行項目由代理復原：Worker 若在步驟中途停止，代理會把步驟事件重新投遞給另一個 Worker，啟動中的執行個體不會重啟該項目。排程執行是例外，因為事件留在觸發它的程序內，故由復原機制重啟。對其他 pubsub（包括預設的程序內 pubsub），復原機制會立即重啟所有進行中的事件驅動執行項目。程序內 pubsub 只會在單一程序內傳遞事件，因此事件驅動 Workflow 不支援讓多個執行個體共用同一儲存空間並使用它。

重新啟動的執行項目會再次執行中斷的步驟；即使程序停止前步驟已完成，只要結果未儲存仍會重跑。在事件驅動引擎中，若結果已儲存，步驟事件即使延遲抵達（例如代理重新投遞，或儲存結果期間呼叫了 `restart()`），也不會再執行，而會從已儲存的結果繼續。這需要支援執行項目所有權的儲存配接器。設定 `autoRestartActiveRuns: false` 的 Workflow，包括持久化 Agent Workflow，仍會重跑步驟。因此，具有副作用的步驟應具備冪等性，避免重複執行造成額外影響。

步驟的 `execute` 函式會收到 `runId` 與 `workflowId`。將兩者和傳給 `createStep()` 的步驟 `id` 組合；若步驟有多個副作用，再加入各副作用的名稱，即可建立冪等鍵。

有些步驟還需要由輸入提供冪等鍵的一部分：

- 巢狀 Workflow 在復原或重新投遞時可能取得新的 `runId`。請把父 Workflow 的 `runId` 傳入巢狀 Workflow，並用它取代巢狀執行項目的 `runId`。
- `foreach` 會為每個項目各執行同一步驟一次。請把能識別該項目的 ID 加入冪等鍵。
- 迴圈每次迭代都會執行同一步驟。請從步驟回傳迭代編號，並在下一次迭代從輸入讀取。重複或繼續同一次迭代時，輸入相同，因此編號也不變。

關於 Agent 呼叫的 Tool，請參閱[讓 Tool 能安全地重複執行](/docs/harness/durable-agents#make-tools-safe-to-repeat)。

### 復原迴圈 {/* #recovery-loop */}

`mastra.startWorkers()` 也會在執行編排 Worker 的執行個體上啟動復原迴圈。每隔 `recovery.workflowScanIntervalMs`（預設 60 秒，可能上下浮動五分之一），迴圈會依 `restartAllActiveWorkflowRuns()` 的相同規則重新啟動已停止的預設引擎執行項目。執行個體崩潰後，首次掃描須等租約到期（`MASTRA_AGENT_THREAD_LEASE_TTL_MS`，預設 15 秒）且經過 `recovery.workflowGraceMs`。若掃描發現項目仍在寬限期內，下一次掃描會在寬限期結束後執行，但至少要等 1 秒。

共用儲存配接器的執行個體，會透過儲存空間中的租約資料列選出一個迴圈領導者。只有領導者的迴圈會列出執行項目；其他迴圈只嘗試接任。領導者會持續擔任此角色，直到透過 `stopWorkers()` 或 `shutdown()` 交還，或崩潰後租約到期。無論由誰領導，每個執行個體在啟動時仍會透過 `restartAllActiveWorkflowRuns()` 重啟自己的已停止預設引擎項目。兩次啟動之間，迴圈只復原領導者註冊的 Workflow；若各執行個體在同一儲存空間註冊不同 Workflow，其他項目須等下一次啟動。迴圈重啟的項目會在領導者上執行。

```typescript title="src/mastra/index.ts"
export const mastra = new Mastra({
  recovery: { workflowScanIntervalMs: 30_000 },
})
```

復原迴圈不會重啟事件驅動項目。可重新投遞未確認事件的代理會復原這些項目；其他 pubsub 則由 `restartAllActiveWorkflowRuns()` 在啟動時重啟。迴圈也會略過設定 `autoRestartActiveRuns: false` 的 Workflow；未註冊其他預設引擎 Workflow 的執行個體不會取得領導者租約資料列。若 `recovery.workflows` 為 `'off'`、以 `workers: false` 啟動、`MASTRA_WORKERS` 篩選未包含 `orchestration`，或儲存配接器不支援執行項目所有權，迴圈都不會運作。只呼叫 `restartAllActiveWorkflowRuns()` 而未呼叫 `startWorkers()` 的程序也不會運作此迴圈。

### 使用 `restart()` 重新啟動進行中的執行項目 {/* #restarting-an-active-workflow-run-with-restart */}

使用 `restart()` 從最後一個進行中的步驟重新啟動執行項目，並從該處繼續執行。

```typescript
const run = await workflow.createRun()

const result = await run.start({ inputData: { value: 'initial data' } })

const restartedResult = await run.restart()
```

### 找出進行中的執行項目 {/* #identifying-active-workflow-runs */}

進行中執行項目的 `status` 為 `running` 或 `waiting`。可檢查 Workflow 的 `status` 確認是否進行中，再以 `active` 識別這類項目。

```typescript
const activeRuns = await workflow.listActiveWorkflowRuns()
if (activeRuns.runs.length > 0) {
  console.log(activeRuns.runs)
}
```

:::note

Mastra 伺服器啟動時，會重新啟動不再由任何執行個體執行的進行中項目；其復原迴圈會持續處理預設引擎項目。

:::

## 使用 `RequestContext` {/* #using-requestcontext */}

使用 [RequestContext](/docs/server/request-context) 取得請求專屬的值，以便依請求內容調整行為。

```typescript title="src/mastra/workflows/test-workflow.ts"
import { createStep } from '@mastra/core/workflows'

export type UserTier = {
  'user-tier': 'enterprise' | 'pro'
}

const step1 = createStep({
  execute: async ({ requestContext }) => {
    const userTier = requestContext.get('user-tier') as UserTier['user-tier']

    const maxResults = userTier === 'enterprise' ? 1000 : 50

    return { maxResults }
  },
})
```

詳情請參閱[請求內容](/docs/server/request-context)。

:::tip

型別安全的請求內容 Schema 驗證方式，請參閱 [Schema 驗證](/docs/server/request-context#schema-validation)。

:::
