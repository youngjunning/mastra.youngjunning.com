# 時間回溯

時間回溯可以用已儲存的快照資料或自訂上下文，從任意指定步驟重新執行 Workflow。

你可以用它為失敗的 Workflow 除錯、用不同輸入測試個別步驟，或在不必重跑整個 Workflow 的情況下從錯誤中復原。尚未執行過的 Workflow 也可從任意指定步驟開始。

## 時間回溯的運作方式 {/* #how-time-travel-works */}

對一次 Workflow 執行呼叫 `timeTravel()` 時：

1. Workflow 會載入儲存空間中的現有快照（如有）。
1. 依快照或提供的上下文重建目標步驟之前的結果。
1. 使用提供或重建的輸入資料，從指定步驟開始執行。
1. Workflow 從該步驟繼續執行到完成。

如果記錄執行後 Workflow 定義已有變更（例如步驟重新命名），或該次執行未走到目標之前的某個步驟，時間回溯會在執行任何步驟前失敗並說明原因，已儲存的快照不會變更。

時間回溯依賴持久化的 Workflow 快照，因此必須設定儲存空間。

## 基本用法 {/* #basic-usage */}

使用 `run.timeTravel()` 從指定步驟重新執行 Workflow：

```typescript
import { mastra } from './mastra'

const workflow = mastra.getWorkflow('myWorkflow')
const run = await workflow.createRun()

const result = await run.timeTravel({
  step: 'step2',
  inputData: { previousStepResult: 'custom value' },
})
```

## 指定目標步驟 {/* #specifying-the-target-step */}

您可以使用步驟參考或步驟 ID 指定目標步驟：

### 使用步驟參考 {/* #using-step-reference */}

```typescript
const result = await run.timeTravel({
  step: step2,
  inputData: { value: 10 },
})
```

### 使用步驟 ID {/* #using-step-id */}

```typescript
const result = await run.timeTravel({
  step: 'step2',
  inputData: { value: 10 },
})
```

### 巢狀 Workflow 的步驟 {/* #nested-workflow-steps */}

要指定巢狀 Workflow 裡的步驟，可使用點號表示法、步驟 ID 陣列或步驟參照陣列：

```typescript
// Using dot notation
const result = await run.timeTravel({
  step: 'nestedWorkflow.step3',
  inputData: { value: 10 },
})

// Using array of step IDs
const result = await run.timeTravel({
  step: ['nestedWorkflow', 'step3'],
  inputData: { value: 10 },
})

// Using array of step references
const result = await run.timeTravel({
  step: [nestedWorkflow, step3],
  inputData: { value: 10 },
})
```

## 提供執行上下文 {/* #providing-execution-context */}

執行時間回溯時，可提供上下文來指定前面步驟的狀態：

```typescript {3-13}
const result = await run.timeTravel({
  step: 'step2',
  context: {
    step1: {
      status: 'success',
      payload: { value: 0 },
      output: { step1Result: 2 },
      startedAt: Date.now(),
      endedAt: Date.now(),
    },
  },
})
```

上下文物件以步驟 ID 為索引保存結果。每筆結果包括：

- `status`：步驟的執行狀態。常見值為 `success`、`failed` 或 `suspended`，也接受所有 Workflow 執行狀態：`running`、`success`、`failed`、`tripwire`、`suspended`、`waiting`、`pending`、`canceled`、`bailed`、`paused` 或 `skipped`。
- `payload`：傳遞到步驟的輸入數據
- `output`：步驟的輸出資料（對於成功的步驟）
- `startedAt`：步驟開始時的時間戳
- `endedAt`：步驟結束時的時間戳記（對於已完成的步驟）
- `suspendPayload`：傳給 `suspend()` 的資料，用於已暫停的步驟。
- `resumePayload`：傳給 `resume()` 的資料，用於已恢復執行的步驟。

## 重新執行失敗的 Workflow {/* #re-running-failed-workflows */}

時間回溯特別適合用來為失敗的 Workflow 執行除錯，或在失敗後復原：

```typescript
const workflow = mastra.getWorkflow('myWorkflow')
const run = await workflow.createRun()

// Initial run fails at step2
const failedResult = await run.start({
  inputData: { value: 1 },
})

if (failedResult.status === 'failed') {
  // Re-run from step2 with corrected input
  const recoveredResult = await run.timeTravel({
    step: 'step2',
    inputData: { step1Result: 5 }, // Provide corrected input
  })
}
```

## 回溯已暫停的 Workflow {/* #time-travel-with-suspended-workflows */}

你可以透過時間回溯，讓已暫停的 Workflow 從更早的步驟恢復執行：

```typescript
const run = await workflow.createRun()

// Start workflow - suspends at promptAgent step
const initialResult = await run.start({
  inputData: { input: 'test' },
})

if (initialResult.status === 'suspended') {
  // Time travel back to an earlier step with resume data
  const result = await run.timeTravel({
    step: 'getUserInput',
    resumeData: {
      userInput: 'corrected input',
    },
  })
}
```

## 串流接收回溯結果 {/* #streaming-time-travel-results */}

使用 `timeTravelStream()` 接收回溯執行中的串流事件：

```typescript
const run = await workflow.createRun()

const stream = run.timeTravelStream({
  step: 'step2',
  inputData: { value: 10 },
})

for await (const event of stream.fullStream) {
  console.log(event.type, event.payload)
}

const result = await stream.result

if (result.status === 'success') {
  console.log(result.result)
}
```

## 為時間回溯提供初始狀態 {/* #time-travel-with-initial-state */}

時間回溯時可提供初始狀態，用來設定整個 Workflow 的狀態：

```typescript
const result = await run.timeTravel({
  step: 'step2',
  inputData: { value: 10 },
  initialState: {
    counter: 5,
    metadata: { source: 'time-travel' },
  },
})
```

## 錯誤處理 {/* #error-handling */}

在特定情況下，時間回溯會擲出錯誤。開始執行之前，會以原子操作取得該次執行的控制權，確保一次只有一個呼叫可以繼續。並行呼叫會擲出 `WORKFLOW_TIME_TRAVEL_ALREADY_CLAIMED`，若該次執行已在進行，則擲出 `WORKFLOW_TIME_TRAVEL_RUN_RUNNING`。請參閱[並行回溯呼叫](/reference/workflows/run-methods/timeTravel#concurrent-time-travel-calls)。

### Workflow 正在執行 {/* #running-workflow */}

正在執行的 Workflow 無法進行時間回溯：

```typescript
try {
  await run.timeTravel({ step: 'step2' })
} catch (error) {
  // "This workflow run is still running, cannot time travel"
}
```

### 步驟 ID 無效 {/* #invalid-step-id */}

如果目前 Workflow 定義中不存在目標步驟，則時間旅行會拋出例外：

```typescript
try {
  await run.timeTravel({ step: 'nonExistentStep' })
} catch (error) {
  // "Cannot time travel to step 'nonExistentStep': the step does not exist in the current execution graph. ..."
}
```

錯誤也會列出執行快照中最多 10 個已記錄的步驟 ID（如有其餘 ID，會標示數量），並確認已儲存的快照沒有變更。若未記錄任何步驟結果，則會顯示 `Time travel target step not found in execution graph: 'nonExistentStep'. Verify the step id/path.`。

### 輸入資料無效 {/* #invalid-input-data */}

啟用 `validateInputs` 後，時間回溯會依步驟的 schema 驗證輸入資料：

```typescript
try {
  await run.timeTravel({
    step: 'step2',
    inputData: { invalidField: 'value' },
  })
} catch (error) {
  // "Invalid inputData: \n- step1Result: Required"
}
```

## 巢狀 Workflow 的上下文 {/* #nested-workflows-context */}

回溯至巢狀 Workflow 內部時，可以同時提供上層 Workflow 和巢狀 Workflow 步驟的上下文：

```typescript
const result = await run.timeTravel({
  step: 'nestedWorkflow.step3',
  context: {
    step1: {
      status: 'success',
      payload: { value: 0 },
      output: { step1Result: 2 },
      startedAt: Date.now(),
      endedAt: Date.now(),
    },
    nestedWorkflow: {
      status: 'running',
      payload: { step1Result: 2 },
      startedAt: Date.now(),
    },
  },
  nestedStepsContext: {
    nestedWorkflow: {
      step2: {
        status: 'success',
        payload: { step1Result: 2 },
        output: { step2Result: 3 },
        startedAt: Date.now(),
        endedAt: Date.now(),
      },
    },
  },
})
```

## 使用案例 {/* #use-cases */}

### 為失敗的步驟除錯 {/* #debugging-failed-steps */}

使用相同或修改後的輸入重新運行失敗的步驟以診斷問題：

```typescript
const result = await run.timeTravel({
  step: failedStepId,
  context: originalContext, // Use context from the failed run
})
```

### 在新的 Workflow 執行中測試步驟邏輯 {/* #testing-step-logic-on-new-workflow-run */}

以指定輸入在新一次 Workflow 執行中測試個別步驟的邏輯，不必從頭執行。

```typescript
const result = await run.timeTravel({
  step: 'processData',
  inputData: { testData: 'specific test case' },
})
```

### 從暫時性故障中恢復 {/* #recovering-from-transient-failures */}

重新運行因臨時問題（網路錯誤、速率限制）而失敗的步驟：

```typescript
// After fixing the external service issue
const result = await run.timeTravel({
  step: 'callExternalApi',
  inputData: savedInputData,
})
```
