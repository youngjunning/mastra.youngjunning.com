# 時間旅行

時間旅行可讓您使用儲存的快照資料或您提供的自訂上下文從任何特定步驟開始重新執行Workflow。

這對於調試失敗的Workflow或使用不同的輸入測試各個步驟，或從錯誤中恢復而不重新運行整個Workflow非常有用。您也可以使用時間旅行從任何特定步驟開始執行尚未執行的Workflow。

## 時間旅行如何運作 {/* #how-time-travel-works */}

當你打電話時`timeTravel()` on a workflow run:

1. Workflow從儲存載入現有快照（如果可用）
2. 目標步驟之前的步驟結果是根據快照或提供的上下文重建的
3. 使用提供的或重構的輸入資料從指定步驟開始執行
4. Workflow從那時起繼續完成

如果自記錄運行以來Workflow定義已變更（例如，重新命名了步驟），或者記錄的運行從未到達目標之前的步驟，則時間旅行會在執行任何操作之前失敗並出現描述性錯誤，並且儲存的快照保持不變。

時間旅行需要配置存儲，因為它依賴持久的Workflow快照。

## 基本用法 {/* #basic-usage */}

使用`run.timeTravel()` to re-execute a workflow from a specific step:

```typescript
import { mastra } from './mastra'

const workflow = mastra.getWorkflow('myWorkflow')
const run = await workflow.createRun()

const result = await run.timeTravel({
  step: 'step2',
  inputData: { previousStepResult: 'custom value' },
})
```

## 指定目標步驟 {/* #specifying-the-target-step */}

您可以使用步驟參考或步驟 ID 指定目標步驟：

### 使用步驟參考 {/* #using-step-reference */}

```typescript
const result = await run.timeTravel({
  step: step2,
  inputData: { value: 10 },
})
```

### 使用步驟 ID {/* #using-step-id */}

```typescript
const result = await run.timeTravel({
  step: 'step2',
  inputData: { value: 10 },
})
```

### 嵌套Workflow步驟 {/* #nested-workflow-steps */}

對於嵌套Workflow內的步驟，請使用點表示法、步驟 IDS 陣列或步驟來引用陣列：

```typescript
// Using dot notation
const result = await run.timeTravel({
  step: 'nestedWorkflow.step3',
  inputData: { value: 10 },
})

// Using array of step IDs
const result = await run.timeTravel({
  step: ['nestedWorkflow', 'step3'],
  inputData: { value: 10 },
})

// Using array of step references
const result = await run.timeTravel({
  step: [nestedWorkflow, step3],
  inputData: { value: 10 },
})
```

## 提供執行上下文 {/* #providing-execution-context */}

您可以提供上下文來指定時間旅行時先前步驟的狀態：

```typescript {3-13}
const result = await run.timeTravel({
  step: 'step2',
  context: {
    step1: {
      status: 'success',
      payload: { value: 0 },
      output: { step1Result: 2 },
      startedAt: Date.now(),
      endedAt: Date.now(),
    },
  },
})
```

上下文物件包含由步驟 ID 鍵入的步驟結果。每個步驟結果包括：

* `status`：步驟的執行狀態。常見`success`, `failed`, or `suspended`, but any workflow run status is accepted: `running`, `success`, `failed`, `tripwire`, `suspended`, `waiting`, `pending`, `canceled`, `bailed`, `paused`， 或者`skipped`
* `payload`：傳遞到步驟的輸入數據
* `output`：步驟的輸出資料（對於成功的步驟）
* `startedAt`：步驟開始時的時間戳
* `endedAt`：步驟結束時的時間戳記（對於已完成的步驟）
* `suspendPayload`：數據傳遞到`suspend()` (for suspended steps)
* `resumePayload`：數據傳遞到`resume()` (for resumed steps)

## 重新運行失敗的Workflow {/* #re-running-failed-workflows */}

時間旅行對於調試和從失敗的Workflow執行中恢復特別有用：

```typescript
const workflow = mastra.getWorkflow('myWorkflow')
const run = await workflow.createRun()

// Initial run fails at step2
const failedResult = await run.start({
  inputData: { value: 1 },
})

if (failedResult.status === 'failed') {
  // Re-run from step2 with corrected input
  const recoveredResult = await run.timeTravel({
    step: 'step2',
    inputData: { step1Result: 5 }, // Provide corrected input
  })
}
```

## 暫停Workflow的時間旅行 {/* #time-travel-with-suspended-workflows */}

您可以透過時間旅行來恢復先前步驟中暫停的Workflow：

```typescript
const run = await workflow.createRun()

// Start workflow - suspends at promptAgent step
const initialResult = await run.start({
  inputData: { input: 'test' },
})

if (initialResult.status === 'suspended') {
  // Time travel back to an earlier step with resume data
  const result = await run.timeTravel({
    step: 'getUserInput',
    resumeData: {
      userInput: 'corrected input',
    },
  })
}
```

## 串流時間旅行結果 {/* #streaming-time-travel-results */}

使用`timeTravelStream()` to receive streaming events during time travel execution:

```typescript
const run = await workflow.createRun()

const stream = run.timeTravelStream({
  step: 'step2',
  inputData: { value: 10 },
})

for await (const event of stream.fullStream) {
  console.log(event.type, event.payload)
}

const result = await stream.result

if (result.status === 'success') {
  console.log(result.result)
}
```

## 初始狀態的時間旅行 {/* #time-travel-with-initial-state */}

您可以在時間旅行時提供初始狀態來設定Workflow等級狀態：

```typescript
const result = await run.timeTravel({
  step: 'step2',
  inputData: { value: 10 },
  initialState: {
    counter: 5,
    metadata: { source: 'time-travel' },
  },
})
```

## 錯誤處理 {/* #error-handling */}

時間旅行在特定情況下會引發錯誤。在運行任何內容之前，時間旅行會自動聲明運行，因此一次僅進行一個呼叫。並發呼叫拋出異常`WORKFLOW_TIME_TRAVEL_ALREADY_CLAIMED`, or `WORKFLOW_TIME_TRAVEL_RUN_RUNNING` if the run is already executing. See [Concurrent time travel calls](/reference/workflows/run-methods/timeTravel#concurrent-time-travel-calls).

### 運行Workflow {/* #running-workflow */}

您無法時間旅行到目前正在運行的Workflow：

```typescript
try {
  await run.timeTravel({ step: 'step2' })
} catch (error) {
  // "This workflow run is still running, cannot time travel"
}
```

### 步驟 ID 無效 {/* #invalid-step-id */}

如果目前Workflow定義中不存在目標步驟，則時間旅行會拋出例外：

```typescript
try {
  await run.timeTravel({ step: 'nonExistentStep' })
} catch (error) {
  // "Cannot time travel to step 'nonExistentStep': the step does not exist in the current execution graph. ..."
}
```

該錯誤還列出了運行快照中記錄的最多 10 個步驟 ID（以及所有剩餘 ID 的計數），並確認儲存的快照未被修改。如果運行沒有記錄步驟結果，則會顯示錯誤`Time travel target step not found in execution graph: 'nonExistentStep'. Verify the step id/path.` instead.

### 輸入資料無效 {/* #invalid-input-data */}

什麼時候`validateInputs` is enabled, time travel validates the input data against the step's schema:

```typescript
try {
  await run.timeTravel({
    step: 'step2',
    inputData: { invalidField: 'value' },
  })
} catch (error) {
  // "Invalid inputData: \n- step1Result: Required"
}
```

## 嵌套Workflow上下文 {/* #nested-workflows-context */}

當時間進入嵌套Workflow時，您可以為父Workflow步驟和嵌套Workflow步驟提供上下文：

```typescript
const result = await run.timeTravel({
  step: 'nestedWorkflow.step3',
  context: {
    step1: {
      status: 'success',
      payload: { value: 0 },
      output: { step1Result: 2 },
      startedAt: Date.now(),
      endedAt: Date.now(),
    },
    nestedWorkflow: {
      status: 'running',
      payload: { step1Result: 2 },
      startedAt: Date.now(),
    },
  },
  nestedStepsContext: {
    nestedWorkflow: {
      step2: {
        status: 'success',
        payload: { step1Result: 2 },
        output: { step2Result: 3 },
        startedAt: Date.now(),
        endedAt: Date.now(),
      },
    },
  },
})
```

## 使用案例 {/* #use-cases */}

### 調試失敗的步驟 {/* #debugging-failed-steps */}

使用相同或修改後的輸入重新運行失敗的步驟以診斷問題：

```typescript
const result = await run.timeTravel({
  step: failedStepId,
  context: originalContext, // Use context from the failed run
})
```

### 在新Workflow運行中測試步驟邏輯 {/* #testing-step-logic-on-new-workflow-run */}

在新的Workflow運行中使用特定輸入測試各個步驟，這對於測試步驟邏輯而無需從頭開始Workflow執行非常有用。

```typescript
const result = await run.timeTravel({
  step: 'processData',
  inputData: { testData: 'specific test case' },
})
```

### 從暫時性故障中恢復 {/* #recovering-from-transient-failures */}

重新運行因臨時問題（網路錯誤、速率限制）而失敗的步驟：

```typescript
// After fixing the external service issue
const result = await run.timeTravel({
  step: 'callExternalApi',
  inputData: savedInputData,
})
```
