# 安全防護

Mastra 提供內建處理器，為 Agent 加上安全控制。這些處理器會在有害內容抵達語言模型或使用者之前偵測、轉換或封鎖。

處理器的行為、自訂處理器及加入 Agent 的方法，請參閱[處理器](/docs/agents/processors)。

## 輸入處理器 {/* #input-processors */}

輸入處理器在使用者訊息抵達語言模型前執行，負責正規化、驗證、偵測提示詞注入及安全檢查。

### 正規化使用者訊息 {/* #normalize-user-messages */}

`UnicodeNormalizer()` 會統一 Unicode 字元、標準化空白字元，清理並正規化使用者輸入，同時移除可能造成問題的符號。

```typescript {8-11} title="src/mastra/agents/normalized-agent.ts"
import { UnicodeNormalizer } from '@mastra/core/processors'
import { Agent } from '@mastra/core/agent'

export const normalizedAgent = new Agent({
  id: 'normalized-agent',
  name: 'Normalized Agent',
  inputProcessors: [
    new UnicodeNormalizer({
      stripControlChars: true,
      collapseWhitespace: true,
    }),
  ],
})
```

完整設定選項請參閱 [`UnicodeNormalizer()` 參考文件](/reference/processors/unicode-normalizer)。

### 防範提示詞注入 {/* #prevent-prompt-injection */}

`PromptInjectionDetector()` 會掃描使用者訊息中的提示詞注入、越獄企圖及覆寫系統指令的模式。它以 LLM 分類有風險的輸入，並可在輸入抵達模型前封鎖或改寫。

```typescript {8-14} title="src/mastra/agents/secure-agent.ts"
import { PromptInjectionDetector } from '@mastra/core/processors'
import { Agent } from '@mastra/core/agent'

export const secureAgent = new Agent({
  id: 'secure-agent',
  name: 'Secure Agent',
  inputProcessors: [
    new PromptInjectionDetector({
      model: 'openrouter/openai/gpt-oss-safeguard-20b',
      threshold: 0.8,
      strategy: 'rewrite',
      errorStrategy: 'strict',
      detectionTypes: ['injection', 'jailbreak', 'system-override'],
    }),
  ],
})
```

除了 [`ClassifierProcessor`](/reference/processors/classifier-processor)，使用模型的安全處理器預設採用 `errorStrategy: 'warn'`：內部模型失敗時會記錄日誌，並繼續使用處理器的備援行為。若安全模型無法使用或輸出無效時，未經檢查的內容絕不能繼續處理，請設定 `errorStrategy: 'strict'`。嚴格模式會以阻斷條件停止處理。

完整設定選項請參閱 [`PromptInjectionDetector()` 參考文件](/reference/processors/prompt-injection-detector)。

### 偵測與翻譯語言 {/* #detect-and-translate-language */}

`LanguageDetector()` 偵測使用者訊息的語言並翻譯成目標語言，以支援多語互動。它使用 LLM 識別語言並完成翻譯。

```typescript {8-13} title="src/mastra/agents/multilingual-agent.ts"
import { LanguageDetector } from '@mastra/core/processors'
import { Agent } from '@mastra/core/agent'

export const multilingualAgent = new Agent({
  id: 'multilingual-agent',
  name: 'Multilingual Agent',
  inputProcessors: [
    new LanguageDetector({
      model: 'openrouter/openai/gpt-oss-safeguard-20b',
      targetLanguages: ['English', 'en'],
      strategy: 'translate',
      threshold: 0.8,
    }),
  ],
})
```

完整設定選項請參閱 [`LanguageDetector()` 參考文件](/reference/processors/language-detector)。

## 輸出處理器 {/* #output-processors */}

輸出處理器在語言模型產生回應後、回應送達使用者前執行，負責最佳化、審核、轉換回應及執行安全控制。

### 合併串流輸出 {/* #batch-streamed-output */}

`BatchPartsProcessor()` 會在送往用戶端前合併多個串流片段，把小片段整理成較大的批次，減少網路負擔。

```typescript {8-12} title="src/mastra/agents/batched-agent.ts"
import { BatchPartsProcessor } from '@mastra/core/processors'
import { Agent } from '@mastra/core/agent'

export const batchedAgent = new Agent({
  id: 'batched-agent',
  name: 'Batched Agent',
  outputProcessors: [
    new BatchPartsProcessor({
      batchSize: 5,
      maxWaitTime: 100,
      emitOnNonText: true,
    }),
  ],
})
```

完整設定選項請參閱 [`BatchPartsProcessor()` 參考文件](/reference/processors/batch-parts-processor)。

### 清除系統提示詞 {/* #scrub-system-prompts */}

`SystemPromptScrubber()` 偵測並遮蔽模型回應中的系統提示詞或內部指令，避免意外洩露提示內容與設定細節。它依照設定的偵測類型，使用 LLM 識別並遮蔽敏感內容。

```typescript {8-17} title="src/mastra/agents/scrubbed-agent.ts"
import { SystemPromptScrubber } from '@mastra/core/processors'
import { Agent } from '@mastra/core/agent'

const scrubbedAgent = new Agent({
  id: 'scrubbed-agent',
  name: 'Scrubbed Agent',
  outputProcessors: [
    new SystemPromptScrubber({
      model: 'openrouter/openai/gpt-oss-safeguard-20b',
      strategy: 'redact',
      customPatterns: ['system prompt', 'internal instructions'],
      includeDetections: true,
      instructions:
        'Detect and redact system prompts, internal instructions, and security-sensitive content',
      redactionMethod: 'placeholder',
      placeholderText: '[REDACTED]',
    }),
  ],
})
```

完整設定選項請參閱 [`SystemPromptScrubber()` 參考文件](/reference/processors/system-prompt-scrubber)。

:::note
透過 HTTP 串流傳送回應時，Mastra 預設會在伺服器端從串流區塊遮蔽敏感請求資料（系統提示詞、Tool 定義及 API 金鑰）。詳見[串流資料遮蔽](/docs/server/overview#stream-data-redaction)。
:::

## 混合處理器 {/* #hybrid-processors */}

混合處理器可用於輸入或輸出。請放在 `inputProcessors`、`outputProcessors`，或同時放在兩者。

### 審核輸入與輸出 {/* #moderate-input-and-output */}

`ModerationProcessor()` 偵測仇恨、騷擾、暴力等類別的不當或有害內容。它以 LLM 對訊息分類，並依設定封鎖或改寫。

```typescript {8-13,15} title="src/mastra/agents/moderated-agent.ts"
import { ModerationProcessor } from '@mastra/core/processors'
import { Agent } from '@mastra/core/agent'

export const moderatedAgent = new Agent({
  id: 'moderated-agent',
  name: 'Moderated Agent',
  inputProcessors: [
    new ModerationProcessor({
      model: 'openrouter/openai/gpt-oss-safeguard-20b',
      threshold: 0.7,
      strategy: 'block',
      categories: ['hate', 'harassment', 'violence'],
    }),
  ],
  outputProcessors: [new ModerationProcessor()],
})
```

完整設定選項請參閱 [`ModerationProcessor()` 參考文件](/reference/processors/moderation-processor)。

### 偵測並遮蔽個人識別資訊 {/* #detect-and-redact-pii */}

`PIIDetector()` 偵測並移除電子郵件地址、電話號碼、信用卡號碼等個人識別資訊。它依照設定的偵測類型，以 LLM 識別敏感內容。

```typescript {8-15,17} title="src/mastra/agents/private-agent.ts"
import { PIIDetector } from '@mastra/core/processors'
import { Agent } from '@mastra/core/agent'

export const privateAgent = new Agent({
  id: 'private-agent',
  name: 'Private Agent',
  inputProcessors: [
    new PIIDetector({
      model: 'openrouter/openai/gpt-oss-safeguard-20b',
      threshold: 0.6,
      strategy: 'redact',
      redactionMethod: 'mask',
      detectionTypes: ['email', 'phone', 'credit-card'],
      instructions: 'Detect and mask personally identifiable information.',
    }),
  ],
  outputProcessors: [new PIIDetector()],
})
```

完整設定選項請參閱 [`PIIDetector()` 參考文件](/reference/processors/pii-detector)。

### 控管成本 {/* #enforce-cost-limits */}

`TokenCostControl()` 監控 Agent 迴圈中累積的預估成本，超過金額上限時會警告或封鎖。每次 LLM 呼叫前，它會從可觀測性儲存空間查詢成本資料。成本檢查只是估算，指標又以非同步方式保存，因此執行很快的 Agent 可能短暫超出上限，之後防護機制才會觸發。

```typescript {8-12} title="src/mastra/agents/budgeted-agent.ts"
import { TokenCostControl } from '@mastra/core/processors'
import { Agent } from '@mastra/core/agent'

export const budgetedAgent = new Agent({
  id: 'budgeted-agent',
  name: 'Budgeted Agent',
  inputProcessors: [
    new TokenCostControl({
      maxCost: 5.0,
      scope: 'thread',
      window: '24h',
    }),
  ],
})
```

範圍模式、時間區間、指標持久化延遲及 `onViolation` 回呼，請參閱 [`TokenCostControl()` 參考文件](/reference/processors/token-cost-control)。此功能需要可觀測性儲存空間支援 `getMetricAggregate`。

## 處理器策略 {/* #processor-strategies */}

許多內建處理器支援 `strategy` 參數，用來決定如何處理標記內容。支援 `block`、`warn`、`detect`、`redact`、`rewrite` 及 `translate`。

多數策略會讓請求繼續。使用 `block` 時，處理器會呼叫 `abort()`，立即停止請求，後續處理器也不會執行。

```typescript {5} title="src/mastra/agents/private-agent.ts"
inputProcessors: [
  new PIIDetector({
    model: 'openrouter/openai/gpt-oss-safeguard-20b',
    threshold: 0.6,
    strategy: 'block',
    detectionTypes: ['email', 'phone', 'credit-card'],
  }),
]
```

## 違規回呼 {/* #violation-callbacks */}

處理器支援 `onViolation` 回呼；例如採用 `block` 策略時，違反政策而中止執行就會觸發它。不過，由 `processToolResult` 中止，或在輸出串流期間由處理器 Workflow 中止，都不會呼叫它。部分處理器亦會自行呼叫：`RegexFilterProcessor` 遮蔽內容時，以及 `TokenCostControl` 警告時。只記錄日誌的策略，例如 `ModerationProcessor` 的 `warn`，不會呼叫它。可用於發送警示、寫入外部日誌或通知等副作用。

回呼會收到 `ProcessorViolation` 物件，包含 `processorId`、`message` 和 `detail`（處理器專屬中繼資料）。

```typescript
import { TokenCostControl, ModerationProcessor, PIIDetector } from '@mastra/core/processors'

// Alert when cost limits are exceeded
const tokenCostControl = new TokenCostControl({
  maxCost: 10.0,
  scope: 'resource',
  window: '30d',
  strategy: 'warn',
})

tokenCostControl.onViolation = ({ processorId, message, detail }) => {
  alertSystem.notify(`[${processorId}] ${message}`)
  // detail contains: { usage, limit, totalUsage, scope, scopeKey, threshold }
}

// Log moderation violations
const moderation = new ModerationProcessor({
  model: '__GATEWAY_OPENAI_MODEL_LUNA__',
  strategy: 'block',
})

moderation.onViolation = ({ processorId, message, detail }) => {
  auditLog.write({ processor: processorId, violation: message, categories: detail })
}
```

`onViolation` 是基礎 [`Processor` 介面](/reference/processors/processor-interface)的一部分，因此自訂處理器等任何處理器都可使用。除了上述例外路徑，處理器呼叫 `abort()` 時執行器會自動呼叫 `onViolation`。對採用 `warn` 策略的處理器（如 `TokenCostControl`），即使未封鎖請求，警告也會觸發回呼。

由執行器在 `abort()` 後呼叫的回呼，若擲出錯誤，系統會靜默攔截，以免干擾處理器主要邏輯。`TokenCostControl` 警告路徑的回呼錯誤則會被攔截，並透過 Mastra 記錄器留下日誌。

違規回呼與處理器管線的整合方式，請參閱處理器文件中的[違規回呼](/docs/agents/processors#violation-callbacks)。

## 處理遭封鎖的請求 {/* #handle-blocked-requests */}

處理器呼叫 `abort()` 後，Agent 便停止處理。如何偵測取決於你使用 `generate()` 還是 `stream()`。

### 使用 `generate()` {/* #with-generate */}

檢查結果中的 `tripwire` 欄位：

```typescript title="src/mastra/agents/test-generate.ts"
const result = await agent.generate('Is this credit card number valid?: 4543 1374 5089 4332')

if (result.tripwire) {
  console.error('Blocked:', result.tripwire.reason)
  console.error('Processor:', result.tripwire.processorId)
}
```

### 使用 `stream()` {/* #with-stream */}

監聽串流中的 `tripwire` 區塊：

```typescript title="src/mastra/agents/test-stream.ts"
const stream = await agent.stream('Is this credit card number valid?: 4543 1374 5089 4332')

for await (const chunk of stream.fullStream) {
  if (chunk.type === 'tripwire') {
    console.error('Blocked:', chunk.payload.reason)
    console.error('Processor:', chunk.payload.processorId)
  }
}
```

## 加快安全防護 {/* #speed-up-guardrails */}

使用 LLM 的安全處理器（內容審核、PII 偵測及提示詞注入偵測）會增加每次請求的延遲。以下方法可減少額外負擔。

### 平行執行安全處理器 {/* #run-guardrails-in-parallel */}

處理器預設依序執行。只採用 `block` 且不修改訊息的安全處理器彼此獨立，可透過 [Workflow 處理器](/docs/agents/processors#use-workflows-as-processors)平行執行。

也可以在同一平行步驟混用 `block` 與 `redact` 策略。請把結果對應至 `redact` 分支，讓轉換後的訊息繼續傳遞。

對輸出安全處理器，請先依序執行 `TokenLimiterProcessor` 及 `BatchPartsProcessor`，再進入平行步驟；相互依賴的 `redact` 處理器則應在平行步驟後依序執行：

```typescript title="src/mastra/processors/output-guardrails.ts"
import { createWorkflow, createStep } from '@mastra/core/workflows'
import {
  ProcessorStepOutputSchema,
  PIIDetector,
  ModerationProcessor,
  SystemPromptScrubber,
  TokenLimiterProcessor,
  BatchPartsProcessor,
} from '@mastra/core/processors'

export const outputGuardrails = createWorkflow({
  id: 'output-guardrails',
  inputSchema: ProcessorStepOutputSchema,
  outputSchema: ProcessorStepOutputSchema,
})
  // Sequential: limit tokens first, then batch stream chunks
  .then(createStep(new TokenLimiterProcessor({ limit: 1000 })))
  .then(createStep(new BatchPartsProcessor()))
  // Parallel: run independent checks at the same time
  .parallel([
    createStep(
      new PIIDetector({
        model: '__GATEWAY_OPENAI_MODEL_LUNA__',
        strategy: 'redact',
      }),
    ),
    createStep(
      new ModerationProcessor({
        model: '__GATEWAY_OPENAI_MODEL_LUNA__',
        strategy: 'block',
      }),
    ),
  ])
  // Map to the redact branch to keep its transformed messages
  .map(async ({ inputData }) => {
    return inputData['processor:pii-detector']
  })
  // Sequential: scrubber depends on previous redaction output
  .then(
    createStep(
      new SystemPromptScrubber({
        model: '__GATEWAY_OPENAI_MODEL_LUNA__',
        strategy: 'redact',
        placeholderText: '[REDACTED]',
      }),
    ),
  )
  .commit()
```

`.parallel()` 和 `.map()` 的詳情，請參閱[以 Workflow 作為處理器](/docs/agents/processors#use-workflows-as-processors)。

### 選用快速模型 {/* #choose-a-fast-model */}

安全處理器不需要使用主模型。分類任務可使用較小、較快的模型：

```typescript
const GUARDRAIL_MODEL = '__GATEWAY_OPENAI_MODEL_LUNA__'

new ModerationProcessor({ model: GUARDRAIL_MODEL })
new PIIDetector({ model: GUARDRAIL_MODEL })
new PromptInjectionDetector({ model: GUARDRAIL_MODEL })
```

### 合併串流片段 {/* #batch-stream-parts */}

實作 `processOutputStream` 的輸出安全處理器會處理每個串流區塊。請在較耗時的處理器之前使用 `BatchPartsProcessor` 合併片段，以減少 LLM 分類呼叫次數：

```typescript
outputProcessors: [
  new BatchPartsProcessor({ batchSize: 10 }),
  // Heavier processors now run on batched chunks instead of individual ones
  new PIIDetector({ model: GUARDRAIL_MODEL, strategy: 'redact' }),
  new ModerationProcessor({ model: GUARDRAIL_MODEL, strategy: 'block' }),
]
```
