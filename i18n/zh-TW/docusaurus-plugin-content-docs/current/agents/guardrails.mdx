# 護欄

Mastra 提供內建處理器，為您的Agent程式添加安全控制。這些處理器在有害內容到達語言模型或使用者之前對其進行檢測、轉換或封鎖。

[Processors](/docs/agents/processors).

## 輸入處理器 {/* #input-processors */}

輸入處理器在使用者訊息到達語言模型之前運行。它們處理規範化、驗證、提示注入檢測和安全檢查。

### 規範化用戶訊息 {/* #normalize-user-messages */}

這`UnicodeNormalizer()` cleans and normalizes user input by unifying Unicode characters and standardizing whitespace. It also removes problematic symbols.

```typescript {8-11} title="src/mastra/agents/normalized-agent.ts"
import { UnicodeNormalizer } from '@mastra/core/processors'
import { Agent } from '@mastra/core/agent'

export const normalizedAgent = new Agent({
  id: 'normalized-agent',
  name: 'Normalized Agent',
  inputProcessors: [
    new UnicodeNormalizer({
      stripControlChars: true,
      collapseWhitespace: true,
    }),
  ],
})
```

訪問[`UnicodeNormalizer()`](/reference/processors/unicode-normalizer) reference for a full list of configuration options.

### 防止提示注入 {/* #prevent-prompt-injection */}

這`PromptInjectionDetector()` scans user messages for prompt injection, jailbreak attempts, and system override patterns. It uses an LLM to classify risky input and can block or rewrite it before it reaches the model.

```typescript {8-14} title="src/mastra/agents/secure-agent.ts"
import { PromptInjectionDetector } from '@mastra/core/processors'
import { Agent } from '@mastra/core/agent'

export const secureAgent = new Agent({
  id: 'secure-agent',
  name: 'Secure Agent',
  inputProcessors: [
    new PromptInjectionDetector({
      model: 'openrouter/openai/gpt-oss-safeguard-20b',
      threshold: 0.8,
      strategy: 'rewrite',
      errorStrategy: 'strict',
      detectionTypes: ['injection', 'jailbreak', 'system-override'],
    }),
  ],
})
```

模型支援的護欄處理器，除了[`ClassifierProcessor`](/reference/processors/classifier-processor) default to `errorStrategy: 'warn'`, which logs internal model failures and continues with the processor's fallback. Use `errorStrategy: 'strict'` when unchecked content must not proceed if the guardrail model is unavailable or returns invalid output. Strict mode stops processing with a tripwire.

訪問[`PromptInjectionDetector()`](/reference/processors/prompt-injection-detector) reference for a full list of configuration options.

### 偵測並翻譯語言 {/* #detect-and-translate-language */}

這`LanguageDetector()` detects and translates user messages into a target language, enabling multilingual support. It uses an LLM to identify the language and perform the translation.

```typescript {8-13} title="src/mastra/agents/multilingual-agent.ts"
import { LanguageDetector } from '@mastra/core/processors'
import { Agent } from '@mastra/core/agent'

export const multilingualAgent = new Agent({
  id: 'multilingual-agent',
  name: 'Multilingual Agent',
  inputProcessors: [
    new LanguageDetector({
      model: 'openrouter/openai/gpt-oss-safeguard-20b',
      targetLanguages: ['English', 'en'],
      strategy: 'translate',
      threshold: 0.8,
    }),
  ],
})
```

訪問[`LanguageDetector()`](/reference/processors/language-detector) reference for a full list of configuration options.

## 輸出處理器 {/* #output-processors */}

輸出處理器在語言模型產生回應之後、到達使用者之前執行。他們處理響應優化、調節、轉換和安全控制。

### 批次流式輸出 {/* #batch-streamed-output */}

這`BatchPartsProcessor()` combines multiple stream parts before emitting them to the client. This reduces network overhead by consolidating small chunks into larger batches.

```typescript {8-12} title="src/mastra/agents/batched-agent.ts"
import { BatchPartsProcessor } from '@mastra/core/processors'
import { Agent } from '@mastra/core/agent'

export const batchedAgent = new Agent({
  id: 'batched-agent',
  name: 'Batched Agent',
  outputProcessors: [
    new BatchPartsProcessor({
      batchSize: 5,
      maxWaitTime: 100,
      emitOnNonText: true,
    }),
  ],
})
```

訪問[`BatchPartsProcessor()`](/reference/processors/batch-parts-processor) reference for a full list of configuration options.

### 擦洗系統提示 {/* #scrub-system-prompts */}

這`SystemPromptScrubber()` detects and redacts system prompts or internal instructions from model responses. It prevents unintended disclosure of prompt content or configuration details. It uses an LLM to identify and redact sensitive content based on configured detection types.

```typescript {8-17} title="src/mastra/agents/scrubbed-agent.ts"
import { SystemPromptScrubber } from '@mastra/core/processors'
import { Agent } from '@mastra/core/agent'

const scrubbedAgent = new Agent({
  id: 'scrubbed-agent',
  name: 'Scrubbed Agent',
  outputProcessors: [
    new SystemPromptScrubber({
      model: 'openrouter/openai/gpt-oss-safeguard-20b',
      strategy: 'redact',
      customPatterns: ['system prompt', 'internal instructions'],
      includeDetections: true,
      instructions:
        'Detect and redact system prompts, internal instructions, and security-sensitive content',
      redactionMethod: 'placeholder',
      placeholderText: '[REDACTED]',
    }),
  ],
})
```

訪問[`SystemPromptScrubber()`](/reference/processors/system-prompt-scrubber) reference for a full list of configuration options.

:::注意
當透過 HTTP 傳輸回應時，Mastra 預設會在伺服器層級從流區塊編輯敏感請求資料（系統提示、Tool定義、API 金鑰）。看[Stream data redaction](/docs/server/overview#stream-data-redaction) for details.
:::

## 混合處理器 {/* #hybrid-processors */}

混合處理器可以在輸入或輸出上運作。將它們放入`inputProcessors`, `outputProcessors`, or both.

### 適度的輸入和輸出 {/* #moderate-input-and-output */}

這`ModerationProcessor()` detects inappropriate or harmful content across categories like hate, harassment, and violence. It uses an LLM to classify the message and can block or rewrite it based on your configuration.

```typescript {8-13,15} title="src/mastra/agents/moderated-agent.ts"
import { ModerationProcessor } from '@mastra/core/processors'
import { Agent } from '@mastra/core/agent'

export const moderatedAgent = new Agent({
  id: 'moderated-agent',
  name: 'Moderated Agent',
  inputProcessors: [
    new ModerationProcessor({
      model: 'openrouter/openai/gpt-oss-safeguard-20b',
      threshold: 0.7,
      strategy: 'block',
      categories: ['hate', 'harassment', 'violence'],
    }),
  ],
  outputProcessors: [new ModerationProcessor()],
})
```

訪問[`ModerationProcessor()`](/reference/processors/moderation-processor) reference for a full list of configuration options.

### 檢測並編輯 PII {/* #detect-and-redact-pii */}

這`PIIDetector()` detects and removes personally identifiable information such as emails, phone numbers, and credit cards. It uses an LLM to identify sensitive content based on configured detection types.

```typescript {8-15,17} title="src/mastra/agents/private-agent.ts"
import { PIIDetector } from '@mastra/core/processors'
import { Agent } from '@mastra/core/agent'

export const privateAgent = new Agent({
  id: 'private-agent',
  name: 'Private Agent',
  inputProcessors: [
    new PIIDetector({
      model: 'openrouter/openai/gpt-oss-safeguard-20b',
      threshold: 0.6,
      strategy: 'redact',
      redactionMethod: 'mask',
      detectionTypes: ['email', 'phone', 'credit-card'],
      instructions: 'Detect and mask personally identifiable information.',
    }),
  ],
  outputProcessors: [new PIIDetector()],
})
```

訪問[`PIIDetector()`](/reference/processors/pii-detector) reference for a full list of configuration options.

### 實施成本限制 {/* #enforce-cost-limits */}

這`TokenCostControl()` monitors cumulative estimated cost across the agentic loop, blocking or warning when a monetary limit is exceeded. It queries cost data from observability storage before each LLM call. Cost checks are approximate, metrics are persisted asynchronously, so fast-running agents may briefly exceed the configured limit before the guard triggers.

```typescript {8-12} title="src/mastra/agents/budgeted-agent.ts"
import { TokenCostControl } from '@mastra/core/processors'
import { Agent } from '@mastra/core/agent'

export const budgetedAgent = new Agent({
  id: 'budgeted-agent',
  name: 'Budgeted Agent',
  inputProcessors: [
    new TokenCostControl({
      maxCost: 5.0,
      scope: 'thread',
      window: '24h',
    }),
  ],
})
```

訪問[`TokenCostControl()`](/reference/processors/token-cost-control) reference for scoping modes, time windows, metric persistence delays, and the `onViolation` callback. Requires observability storage with `getMetricAggregate` support.

## 處理器策略 {/* #processor-strategies */}

許多內建處理器支持`strategy` parameter that controls how they handle flagged content. Supported values include: `block`, `warn`, `detect`, `redact`, `rewrite`, and `translate`.

大多數策略允許請求繼續。什麼時候`block` is used, the processor calls `abort()`, which stops the request immediately and prevents subsequent processors from running.

```typescript {5} title="src/mastra/agents/private-agent.ts"
inputProcessors: [
  new PIIDetector({
    model: 'openrouter/openai/gpt-oss-safeguard-20b',
    threshold: 0.6,
    strategy: 'block',
    detectionTypes: ['email', 'phone', 'credit-card'],
  }),
]
```

## 違規回調 {/* #violation-callbacks */}

處理器支援`onViolation` callback that fires when a policy violation aborts the run, for example with the `block` strategy. Aborts from `processToolResult`, and from processor workflows while streaming output, don't call it. Some processors also call it directly: `RegexFilterProcessor` when it redacts content, and `TokenCostControl` when it warns. Strategies that only log, such as `ModerationProcessor`'s `warn`, don't call it. Use it for side effects like alerting, logging to external systems, or sending notifications.

回呼收到一個`ProcessorViolation` object with `processorId`, `message`, and `detail` (processor-specific metadata).

```typescript
import { TokenCostControl, ModerationProcessor, PIIDetector } from '@mastra/core/processors'

// Alert when cost limits are exceeded
const tokenCostControl = new TokenCostControl({
  maxCost: 10.0,
  scope: 'resource',
  window: '30d',
  strategy: 'warn',
})

tokenCostControl.onViolation = ({ processorId, message, detail }) => {
  alertSystem.notify(`[${processorId}] ${message}`)
  // detail contains: { usage, limit, totalUsage, scope, scopeKey, threshold }
}

// Log moderation violations
const moderation = new ModerationProcessor({
  model: '__GATEWAY_OPENAI_MODEL_LUNA__',
  strategy: 'block',
})

moderation.onViolation = ({ processorId, message, detail }) => {
  auditLog.write({ processor: processorId, violation: message, categories: detail })
}
```

這`onViolation` property is part of the base [`Processor` interface](/reference/processors/processor-interface), so any processor, including custom ones, can use it. The runner automatically invokes `onViolation` when a processor calls `abort()`, except on the paths noted above. For processors using a `warn` strategy (like `TokenCostControl`), the callback also fires on warnings without blocking the request.

之後運行程式呼叫的回調拋出的錯誤`abort()` are silently caught to prevent interfering with the processor's main logic. On the `TokenCostControl` warning path, callback errors are caught and logged through the Mastra logger.

有關違規回調如何與處理器管道集成的更多信息，請參閱[Violation callbacks](/docs/agents/processors#violation-callbacks) in the Processors documentation.

## 處理被阻止的請求 {/* #handle-blocked-requests */}

當處理器調用`abort()`, the agent stops processing. How you detect this depends on whether you use `generate()` or `stream()`.

### 和`generate()` {/* #with-generate */}

檢查`tripwire` field on the result:

```typescript title="src/mastra/agents/test-generate.ts"
const result = await agent.generate('Is this credit card number valid?: 4543 1374 5089 4332')

if (result.tripwire) {
  console.error('Blocked:', result.tripwire.reason)
  console.error('Processor:', result.tripwire.processorId)
}
```

### 和`stream()` {/* #with-stream */}

聽聽`tripwire` chunks in the stream:

```typescript title="src/mastra/agents/test-stream.ts"
const stream = await agent.stream('Is this credit card number valid?: 4543 1374 5089 4332')

for await (const chunk of stream.fullStream) {
  if (chunk.type === 'tripwire') {
    console.error('Blocked:', chunk.payload.reason)
    console.error('Processor:', chunk.payload.processorId)
  }
}
```

## 加快護欄速度 {/* #speed-up-guardrails */}

使用 LLM（審核、PII 偵測、提示注入）的 Guardrail 處理器會增加每個請求的延遲。這些技術減少了這種開銷。

### 平行運行護欄 {/* #run-guardrails-in-parallel */}

預設情況下，處理器會按順序運作。護欄僅`block` (and never mutate messages) are independent and can run using a [workflow processor](/docs/agents/processors#use-workflows-as-processors).

你也可以混合`block` and `redact` strategies in a single parallel step. Map to the `redact` branch so its transformed messages carry forward.

對於輸出護欄，運行`TokenLimiterProcessor` and `BatchPartsProcessor` sequentially *before* the parallel step, and any `redact` processors that depend on each other sequentially *after* it:

```typescript title="src/mastra/processors/output-guardrails.ts"
import { createWorkflow, createStep } from '@mastra/core/workflows'
import {
  ProcessorStepOutputSchema,
  PIIDetector,
  ModerationProcessor,
  SystemPromptScrubber,
  TokenLimiterProcessor,
  BatchPartsProcessor,
} from '@mastra/core/processors'

export const outputGuardrails = createWorkflow({
  id: 'output-guardrails',
  inputSchema: ProcessorStepOutputSchema,
  outputSchema: ProcessorStepOutputSchema,
})
  // Sequential: limit tokens first, then batch stream chunks
  .then(createStep(new TokenLimiterProcessor({ limit: 1000 })))
  .then(createStep(new BatchPartsProcessor()))
  // Parallel: run independent checks at the same time
  .parallel([
    createStep(
      new PIIDetector({
        model: '__GATEWAY_OPENAI_MODEL_LUNA__',
        strategy: 'redact',
      }),
    ),
    createStep(
      new ModerationProcessor({
        model: '__GATEWAY_OPENAI_MODEL_LUNA__',
        strategy: 'block',
      }),
    ),
  ])
  // Map to the redact branch to keep its transformed messages
  .map(async ({ inputData }) => {
    return inputData['processor:pii-detector']
  })
  // Sequential: scrubber depends on previous redaction output
  .then(
    createStep(
      new SystemPromptScrubber({
        model: '__GATEWAY_OPENAI_MODEL_LUNA__',
        strategy: 'redact',
        placeholderText: '[REDACTED]',
      }),
    ),
  )
  .commit()
```

看[workflows as processors](/docs/agents/processors#use-workflows-as-processors) for more details on `.parallel()` and `.map()`.

### 選擇快速型號 {/* #choose-a-fast-model */}

Guardrail 處理器不需要您的主要型號。使用小型、快速的模型來執行分類任務：

```typescript
const GUARDRAIL_MODEL = '__GATEWAY_OPENAI_MODEL_LUNA__'

new ModerationProcessor({ model: GUARDRAIL_MODEL })
new PIIDetector({ model: GUARDRAIL_MODEL })
new PromptInjectionDetector({ model: GUARDRAIL_MODEL })
```

### 批流部分 {/* #batch-stream-parts */}

`processOutputStream` run on every streamed chunk. Use `BatchPartsProcessor` *before* heavier processors to combine chunks and reduce the number of LLM classification calls:

```typescript
outputProcessors: [
  new BatchPartsProcessor({ batchSize: 10 }),
  // Heavier processors now run on batched chunks instead of individual ones
  new PIIDetector({ model: GUARDRAIL_MODEL, strategy: 'redact' }),
  new ModerationProcessor({ model: GUARDRAIL_MODEL, strategy: 'block' }),
]
```
