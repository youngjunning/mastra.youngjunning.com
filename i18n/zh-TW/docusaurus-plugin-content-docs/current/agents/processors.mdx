# 處理器

處理器在訊息通過Agent時對其進行轉換、驗證或控制。它們在Agent執行管道中的特定點運行，允許您在輸入到達語言模型之前修改輸入，或在輸出返回給使用者之前修改它們。

處理器配置為：

* **`inputProcessors`**：在訊息到達語言模型之前運行。
* **`outputProcessors`**：在語言模型產生回應之後、傳回給使用者之前執行。

使用個人[`Processor`](/reference/processors/processor-interface) objects, or compose them into workflows with Mastra's workflow primitives. Workflows give you advanced control over execution order and support conditional or parallel processing.

一些處理器同時實現輸入和輸出邏輯，並且可以在任一陣列中使用，具體取決於轉換應該發生的位置。

一些內建處理器也會發送隱藏的系統提醒訊號。這些訊號保留在原始記憶體歷史中並轉換為`<system-reminder>...</system-reminder>` context before the next model call, but standard UI-facing message conversions and default memory recall hide them unless you explicitly opt in. To deliver a signal for the current call without retaining it, send it with `transient: true`.

## 何時使用處理器 {/* #when-to-use-processors */}

使用處理器可以：

* 標準化或驗證使用者輸入
* 為您的Agent商添加護欄
* 檢測並防止提示注入或越獄嘗試
* 出於安全或合規性考慮的適度內容
* 轉換訊息（例如，翻譯語言、過濾Tool呼叫）
* 限制令牌使用或訊息歷史記錄長度
* 編輯敏感資訊 (PII)
* 將自訂業務邏輯應用於訊息

Mastra 包含多個用於常見用例的處理器。您也可以根據應用程式的特定要求建立自訂處理器。

## 快速入門 {/* #quickstart */}

導入並實例化處理器，然後將其傳遞給Agent的`inputProcessors` or `outputProcessors` array:

```typescript {2,8-15} title="src/mastra/agents/moderated-agent.ts"
import { Agent } from '@mastra/core/agent'
import { ModerationProcessor } from '@mastra/core/processors'

export const moderatedAgent = new Agent({
  id: 'moderated-agent',
  name: 'moderated-agent',
  instructions: 'You are a helpful assistant',
  model: '__GATEWAY_OPENAI_MODEL_LUNA__',
  inputProcessors: [
    new ModerationProcessor({
      model: '__GATEWAY_OPENAI_MODEL_LUNA__',
      categories: ['hate', 'harassment', 'violence'],
      threshold: 0.7,
      strategy: 'block',
    }),
  ],
})
```

## 執行順序 {/* #execution-order */}

處理器按照它們在陣列中出現的順序運作：

```typescript
inputProcessors: [new UnicodeNormalizer(), new PromptInjectionDetector(), new ModerationProcessor()]
```

對於輸出處理器，順序決定了應用於模型回應的轉換順序。

### 啟用記憶體後 {/* #with-memory-enabled */}

當Agent程式上啟用記憶體時，記憶體處理器會自動添加到管道中：

**輸入處理器：**

```text
[Memory Processors] → [Your inputProcessors]
```

記憶體首先載入訊息歷史記錄，然後處理器運行。

**輸出處理器：**

```text
[Your outputProcessors] → [Memory Processors]
```

您的處理器首先運行，然後內存保存訊息。

`abort()` skips memory processors and prevents messages from being saved. See [Memory Processors](/docs/memory/memory-processors#processor-execution-order) for details.

## 將處理器附加到Agent {/* #attach-processors-to-an-agent */}

處理器透過三個陣列在Agent上配置：

```typescript
import { Agent } from '@mastra/core/agent'
import { PrefillErrorHandler, TokenLimiter, ModerationProcessor } from '@mastra/core/processors'

const agent = new Agent({
  id: 'support-agent',
  name: 'support-agent',
  model: '__GATEWAY_OPENAI_MODEL_BASE__',
  instructions: '...',
  inputProcessors: [
    new TokenLimiter(4000),
    new ModerationProcessor({ model: '__GATEWAY_OPENAI_MODEL_LUNA__' }),
  ],
  outputProcessors: [new ModerationProcessor({ model: '__GATEWAY_OPENAI_MODEL_LUNA__' })],
  errorProcessors: [new PrefillErrorHandler()],
})
```

* `inputProcessors`在LLM之前運行。
* `outputProcessors`在 LLM 回應期間和之後運行。
* `errorProcessors`當 LLM API 呼叫拋出時運行，以便他們可以從Provider錯誤中恢復。

### 預設啟用錯誤處理器 {/* #error-processors-are-enabled-by-default */}

每個Agent都會添加您的這四個中的任何一個`errorProcessors` list doesn't already contain:

1. `ProviderHistoryCompat`：修復出站提示中特定於Provider的歷史記錄不相容問題
2. `PrefillErrorHandler`：從助理回應預填充拒絕中恢復
3. [`UnsupportedFileHandler`](/reference/processors/unsupported-file-handler)：從提示中取得模型拒絕的文件，當有文件時將其上傳到Agent的沙箱，然後再次呼叫模型
4. `StreamErrorRetryProcessor`：重試短暫的 API 和串流失敗

僅當清單中沒有任何內容時才會新增預設值`id`, so your own instance always wins and is never duplicated. An added default is placed at the position its `id` gives it among the defaults, so naming only a later one doesn't invert the pair. Supplying only your own `StreamErrorRetryProcessor` still resolves with `ProviderHistoryCompat`, `PrefillErrorHandler`, and `UnsupportedFileHandler` ahead of it.

錯誤處理器在第一個返回時停止`{ retry: true }`, so that relative order decides which repair runs. The default order puts the repairs ahead of the retrying processor. Placed earlier, an instance with broad matchers (the bad-request matcher matches any `400`, for example) would claim a request the repairs could have fixed and resend it unchanged. The default instance retries only transient failures: connection resets, retryable OpenAI stream errors, and errors the provider marks as retryable. Your own instance can be configured with broader matchers. The order keeps repairs ahead of it too.

您的處理器永遠不會相對於彼此重新排序。處理器具有`id` that matches a default takes part in that ordering. One with an `id` of your own keeps its position in your list.

要自訂一個而不丟失其餘部分，請傳遞具有相同功能的處理器`id`:

```typescript
import { Agent } from '@mastra/core/agent'
import { StreamErrorRetryProcessor } from '@mastra/core/processors'

const agent = new Agent({
  id: 'tuned-agent',
  name: 'tuned-agent',
  model: '__GATEWAY_OPENAI_MODEL_BASE__',
  instructions: '...',
  errorProcessors: [new StreamErrorRetryProcessor({ maxRetries: 5 })],
  maxProcessorRetries: 5,
})
```

這`StreamErrorRetryProcessor` above is the only stream-retry processor on the agent, and it resolves in its usual position: last, behind the `ProviderHistoryCompat`, `PrefillErrorHandler`, and `UnsupportedFileHandler` defaults your list never names. Pass all four ids to run a completely custom set.

一個處理器的`maxRetries` can't raise the agent's limit. Without `maxProcessorRetries`, error-processor retries stop after `3` (see [Error processor retry limits](#error-processor-retry-limits)), so set it when a processor needs more.

一個空的`errorProcessors` list merges like any other, so it still gets the four defaults. To turn the defaults off, set `errorProcessorDefaults: false`. The agent then runs only the processors you configure, or none when you configure none:

```typescript
new Agent({
  id: 'custom-error-recovery-agent',
  name: 'custom-error-recovery-agent',
  model: '__GATEWAY_OPENAI_MODEL_BASE__',
  instructions: '...',
  errorProcessorDefaults: false,
  errorProcessors: [new StreamErrorRetryProcessor({ maxRetries: 5 })],
  maxProcessorRetries: 5,
})
```

一個`errorProcessors` list passed to a single `generate()` or `stream()` call works differently: it replaces the agent's resolved list for that call, defaults included.

`errorProcessors` list.

每個數組也接受一個傳回數組的函數，因此可以根據請求建立處理器`RequestContext`:

```typescript
new Agent({
  id: 'processors-agent',
  inputProcessors: ({ requestContext }) => {
    const limit = requestContext.get('tokenLimit') ?? 4000
    return [new TokenLimiter(limit)]
  },
})
```

### 每次呼叫覆蓋處理器 {/* #override-processors-per-call */}

`agent.generate()`和`agent.stream()` accept the same three arrays. When you pass one, it **replaces** the matching array on the agent for that call only. Memory, workspace, and other framework-managed processors still run around your array.

```typescript
await agent.stream('Summarize this', {
  inputProcessors: [new TokenLimiter(2000)],
  maxProcessorRetries: 5,
})
```

## 建立自訂處理器 {/* #create-custom-processors */}

客製化處理器實現`Processor` interface.



* `messages`：快照數組`MastraDBMessage` objects for the current stage.
* `messageList`: 現場直播`MessageList` instance. Use it to read other stages, or to add, remove, or replace messages in place.

文字存在於`message.content.parts`, not on `message.content` itself. Iterate `parts` and filter by `part.type === 'text'` to read user or assistant text. A flattened `message.content.content` string exists for legacy compatibility and can be used as a fallback. See [Message arguments](/reference/processors/processor-interface#message-arguments) in the `Processor` reference for full details.

### 轉換輸入訊息 {/* #transform-input-messages */}

```typescript title="src/mastra/processors/custom-input.ts"
import type { Processor, ProcessInputArgs } from '@mastra/core/processors'
import type { MastraDBMessage } from '@mastra/core/memory'

export class CustomInputProcessor implements Processor {
  id = 'custom-input'

  async processInput({ messages }: ProcessInputArgs): Promise<MastraDBMessage[]> {
    // Transform messages before they reach the LLM.
    // Text lives in content.parts — iterate parts and rewrite text parts only.
    return messages.map(msg => ({
      ...msg,
      content: {
        ...msg.content,
        parts: msg.content.parts?.map(part =>
          part.type === 'text' ? { ...part, text: part.text.toLowerCase() } : part,
        ),
      },
    }))
  }
}
```

這`processInput()` method receives `messages`, `systemMessages`, and an `abort()` function. Return a `MastraDBMessage[]` to replace messages, or `{ messages, systemMessages }` to also modify system messages.

請參閱[`Processor` reference](/reference/processors/processor-interface#processinput) for all available arguments and return types.

### 控制每一步 {/* #control-each-step */}

儘管`processInput()` runs once at the start of agent execution, `processInputStep()` runs at **each step** of the agentic loop (including tool call continuations). It enables per-step configuration changes like runtime model switching or tool choice modifications.

```typescript title="src/mastra/processors/step-processor.ts"
import type {
  Processor,
  ProcessInputStepArgs,
  ProcessInputStepResult,
} from '@mastra/core/processors'

export class DynamicModelProcessor implements Processor {
  id = 'dynamic-model'

  async processInputStep({
    stepNumber,
    model,
    toolChoice,
    messageList,
  }: ProcessInputStepArgs): Promise<ProcessInputStepResult> {
    // Use a fast model for initial response
    if (stepNumber === 0) {
      return { model: '__GATEWAY_OPENAI_MODEL_LUNA__' }
    }

    // Disable tools after 5 steps to force completion
    if (stepNumber > 5) {
      return { toolChoice: 'none' }
    }

    // No changes for other steps
    return {}
  }
}
```

返回`toolChoice: 'none'` stops the model from calling tools but still sends the tool definitions, so earlier tool calls and results stay in the conversation. Mastra only drops the tool definitions when the step also sends a structured-output schema to the model.

此方法接收目前`stepNumber`, `model`, `tools`, `toolChoice`, `messages`, and more. Return an object with any properties you want to override for that step, for example `{ model, toolChoice, tools, systemMessages }`.

請參閱[`Processor` reference](/reference/processors/processor-interface#processinputstep) for all available arguments and return types.

### 在Provider呼叫之前重寫 LLM 請求 {/* #rewrite-the-llm-request-before-the-provider-call */}

使用`processLLMRequest()` when you need to rewrite the final prompt that Mastra sends to the model. This hook runs after Mastra converts the `MessageList` into the provider-facing prompt format (`LanguageModelV2Prompt`) and immediately before the provider call.

使用基於訊息的鉤子進行對話更改：

* `processInput()`：在Agent循環開始之前更改一次對話。
* `processInputStep()`：在每次 LLM 呼叫之前更改訊息或步驟配置。
* `processLLMRequest()`：僅變更目前Provider呼叫的呼出提示。

`processLLMRequest()` are transient. They don't persist back to `MessageList`, memory, UI history, or future provider calls. This makes the hook a good fit for provider compatibility rewrites, role/content normalization, or other model-specific prompt changes that shouldn't alter stored conversation history.

此方法接收`prompt`, `model`, `stepNumber`, `steps`, `state`, and the shared processor context. Calling `abort()` from `processLLMRequest()` emits the normal tripwire response and stops the call.

錯誤處理器也在這條通道上運作。處理器放置在`errorProcessors` that implements `processLLMRequest()` gets the hook, which is what lets the default `ProviderHistoryCompat` repair the outbound prompt rather than waiting for the provider to reject it. Processors whose only hook is `processAPIError()` (`StreamErrorRetryProcessor` and `PrefillErrorHandler`) don't implement this method and are inert here. A processor listed in both `inputProcessors` and `errorProcessors` runs once, in its `inputProcessors` position.

請參閱[`Processor` reference](/reference/processors/processor-interface#processllmrequest) for all available arguments and return types.

### 在Provider致電後根據 LLM 回應採取行動 {/* #act-on-the-llm-response-after-the-provider-call */}

使用`processLLMResponse()` to act on the completed LLM response after the step finishes and stream chunks have been collected. This hook pairs with `processLLMRequest()`: stash state (such as a cache key) in the request hook, then read it back in the response hook to perform side effects like writing to a cache.

這`state` object is the same instance passed to `processLLMRequest()` for the same step. When `fromCache` is `true`, the response was replayed from a cache rather than produced by a live model call, processors that write to a cache should skip writes in this case.

此方法接收`chunks`, `model`, `stepNumber`, `steps`, `state`, `fromCache`, and the shared processor context.

請參閱[`Processor` reference](/reference/processors/processor-interface#processllmresponse) for all available arguments and return types.

### 使用`prepareStep()` callback {/* #use-the-preparestep-callback */}

這`prepareStep()` callback on `generate()` or `stream()` is a shorthand for `processInputStep()`. Internally, Mastra wraps it in a processor that calls your function at each step. It accepts the same arguments and return type as `processInputStep()`, but doesn't require creating a class:

```typescript
await agent.generate('Complex task', {
  prepareStep: async ({ stepNumber, model }) => {
    if (stepNumber === 0) {
      return { model: '__GATEWAY_OPENAI_MODEL_LUNA__' }
    }
    if (stepNumber > 5) {
      return { toolChoice: 'none' }
    }
  },
})
```

### 轉換輸出訊息 {/* #transform-output-messages */}

```typescript title="src/mastra/processors/custom-output.ts"
import type { Processor } from '@mastra/core/processors'
import type { MastraDBMessage } from '@mastra/core/memory'

export class CustomOutputProcessor implements Processor {
  id = 'custom-output'

  async processOutputResult({ messages }): Promise<MastraDBMessage[]> {
    // Transform messages after the LLM generates them
    return messages.filter(msg => msg.role !== 'system')
  }
}
```

該方法還接收一個`result` object with the full generation data, `text`, `usage` (token counts), `finishReason`, and `steps` (each containing `toolCalls`, `toolResults`, etc.). Use it to track usage or inspect tool calls:

```typescript title="src/mastra/processors/usage-tracker.ts"
import type { Processor } from '@mastra/core/processors'

export class UsageTracker implements Processor {
  id = 'usage-tracker'

  async processOutputResult({ messages, result }) {
    console.log(`Tokens: ${result.usage.inputTokens} in, ${result.usage.outputTokens} out`)
    console.log(`Finish reason: ${result.finishReason}`)
    return messages
  }
}
```

### 過濾流輸出 {/* #filter-streamed-output */}

這`processOutputStream()` method transforms or filters streaming chunks before they reach the client:

```typescript title="src/mastra/processors/stream-filter.ts"
import type { Processor } from '@mastra/core/processors'
import type { ChunkType } from '@mastra/core/stream'

export class StreamFilter implements Processor {
  id = 'stream-filter'

  async processOutputStream({ part }): Promise<ChunkType | null> {
    // Drop text-delta chunks that contain the word "secret"
    if (part.type === 'text-delta' && part.payload.text.includes('secret')) {
      return null
    }

    // Return the (possibly modified) chunk to emit it
    return part
  }
}
```

傳回值：

* 一個`ChunkType` emits that chunk. Return the original `part` to pass it through unchanged.
* `null`或者`undefined` drops the chunk. Both behave the same way, so a method that returns nothing also drops the chunk.
* 丟棄只會影響一個區塊。若要完全停止串流，請調用`abort()`.

還可以接收客製化`data-*` chunks emitted by tools via `writer.custom()`, set `processDataParts = true` on your processor. This lets you inspect, modify, or block tool-emitted data chunks before they reach the client.

### 驗證每個回應 {/* #validate-each-response */}

這`processOutputStep()` method runs after each LLM step, allowing you to validate the response and optionally request a retry:

```typescript title="src/mastra/processors/response-validator.ts"
import type { Processor } from '@mastra/core/processors'

export class ResponseValidator implements Processor {
  id = 'response-validator'

  async processOutputStep({ messages, text, abort, retryCount }) {
    const isValid = await validateResponse(text)

    if (!isValid && retryCount < 3) {
      abort('Response did not meet requirements. Try again.', { retry: true })
    }

    return messages
  }
}
```

返回`messages` to leave the conversation unchanged. Returning `[]` replaces the message list with an empty array, removing the conversation history and the latest response.

有關重試行為的更多信息，請參閱[Retry mechanism](#retry-mechanism) in Advanced patterns.

### 跨區塊和步驟保留數據 {/* #persist-data-across-chunks-and-steps */}

`state` object that persists for the lifetime of one request. State is keyed by the processor's `id`. Each processor sees only its own data, and it's shared between `processOutputStream`, `processOutputStep`, and `processOutputResult`. A new state object is created for every new `agent.generate()` or `agent.stream()` call.

```typescript title="src/mastra/processors/word-counter.ts"
import type { Processor } from '@mastra/core/processors'

export class WordCounter implements Processor {
  id = 'word-counter'

  async processOutputStream({ part, state }) {
    state.wordCount ??= 0
    if (part.type === 'text-delta') {
      state.wordCount += part.payload.text.split(/\s+/).filter(Boolean).length
    }
    return part
  }

  async processOutputResult({ messages, state }) {
    console.log(`Total words: ${state.wordCount}`)
    return messages
  }
}
```

## 內建實用處理器 {/* #built-in-utility-processors */}

Mastra 為常見任務提供實用處理器：

**用於安全性和驗證處理器**，參見[Guardrails](/docs/agents/guardrails) page for input/output guardrails and moderation processors.
**For memory-specific processors**, see the [Memory Processors](/docs/memory/memory-processors) page for processors that handle message history, semantic recall, and working memory.

### `TokenLimiter` {/* #tokenlimiter */}

當令牌總數超過指定限制時，透過刪除舊訊息來防止上下文視窗溢出。優先考慮最近的消息並保留系統訊息。

```typescript {7}
import { Agent } from '@mastra/core/agent'
import { TokenLimiter } from '@mastra/core/processors'

const agent = new Agent({
  id: 'my-agent',
  name: 'my-agent',
  model: '__GATEWAY_OPENAI_MODEL__',
  inputProcessors: [new TokenLimiter(127000)],
})
```

請參閱[`TokenLimiterProcessor` reference](/reference/processors/token-limiter-processor) for custom encoding, strategy, and count mode options.

### `ToolCallFilter` {/* #toolcallfilter */}

從傳送到 LLM 的訊息中刪除Tool呼叫和結果，從而節省詳細Tool互動的標記。可以選擇僅排除特定Tool。此過濾器僅影響 LLM 輸入，過濾後的訊息仍儲存到記憶體中。

預設情況下，`ToolCallFilter` filters tool calls from prior history and leaves tool calls made during the current agent loop in place. Use `filterAfterToolSteps` to also filter during the loop while preserving the most recent tool-producing steps.

```typescript
new ToolCallFilter({
  filterAfterToolSteps: 2,
})
```

放`preserveModelOutput: true` to keep compact `toModelOutput` history for filtered completed tool results. The filter keeps only the model-facing output and removes raw tool args and raw results.

```typescript
new ToolCallFilter({
  preserveModelOutput: true,
})
```

請參閱[`ToolCallFilter` reference](/reference/processors/tool-call-filter) for configuration options and the [Memory Processors](/docs/memory/memory-processors#manual-control-and-deduplication) page for pre-memory filtering.

### `ToolSearchProcessor` {/* #toolsearchprocessor */}

為具有大型Tool庫的Agent程式啟用運行時Tool發現。处理者不是预先提供所有Tool，而是向Agent提供`search_tools` and `load_tool` meta-tools to find and load tools by keyword on demand, reducing context token usage.

請參閱[`ToolSearchProcessor` reference](/reference/processors/tool-search-processor) for configuration options and usage examples.

### `ProviderHistoryCompat` {/* #providerhistorycompat */}

當Agent跨模型Provider重複使用訊息時，處理Provider特定的歷史不相容性。它可以在Provider呼叫之前重寫出站 LLM 請求，或從已知的Provider API 錯誤中恢復並重試。

Mastra 將其添加到每個Agent的`errorProcessors` by default. Supply your own instance when you need custom compatibility rules or a predictable position in the list. For Azure OpenAI agents that use observational memory, the processor rewrites `<system-reminder>` wrappers in outbound prompts to avoid content moderation refusals. Stored history remains unchanged.

內建的 Anthropic Tool呼叫 ID 規則會重寫 Anthropic 以外的 ID`^[a-zA-Z0-9_-]+$` pattern in the outbound request only, on both the call and its paired result, so pairing survives. Persisted history keeps the original IDs. Reactive recovery after a failed call stays as the fallback for Claude served through a provider the preemptive check doesn't recognize, such as Vertex.

請參閱[`ProviderHistoryCompat` reference](/reference/processors/provider-history-compat) for setup, built-in rules, and custom rule options.

## 回應快取 {/* #response-caching */}

:::測試版

在 API 穩定之前，可能會在沒有重大版本更新的情況下發生重大變更。

:::

當Agent收到相同的請求時，回應快取會跳過 LLM 呼叫並重播先前快取的回應。使用它可以減少延遲並避免為重複呼叫付費。

快取的實作方式為[`ResponseCache`](/reference/processors/response-cache) input processor. Mastra doesn't provide an agent-level option. To enable caching, register the processor explicitly. This keeps the API surface small while Mastra collects feedback. Per-call overrides flow through `RequestContext`.

### {/* #when-to-use-response-caching */}

當相同的請求在使用者或會話之間重複出現時，請使用快取。例如建議提示按鈕和重複搜索，或對相同輸入進行分類的護欄法學碩士。當呼叫透過Tool觸發外部副作用時跳過它，因為快取會重播Tool呼叫而無需重新執行它們。

### 快速入門 {/* #quickstart-1 */}

添加一個`ResponseCache` to the agent's `inputProcessors` and pass any `MastraServerCache` as the backend. For development, `InMemoryServerCache` works out of the box:

```typescript title="src/mastra/agents/search-agent.ts"
import { Agent } from '@mastra/core/agent'
import { InMemoryServerCache } from '@mastra/core/cache'
import { ResponseCache } from '@mastra/core/processors'

const cache = new InMemoryServerCache()

export const searchAgent = new Agent({
  id: 'search-agent',
  name: 'Search Agent',
  instructions: 'You answer questions concisely.',
  model: '__GATEWAY_OPENAI_MODEL_BASE__',
  inputProcessors: [new ResponseCache({ cache, ttl: 600 })], // 10 minutes
})
```

第一個呼叫正常運行 LLM 並將回應寫入快取。具有相同已解決提示的後續呼叫將傳回快取的回應，而不呼叫 LLM。

### 透過 RequestContext 進行每次呼叫覆蓋 {/* #per-call-overrides-via-requestcontext */}

每次調用配置流經`RequestContext`. Use `ResponseCache.context()` to build a fresh context, or `ResponseCache.applyContext()` to merge into one you already have:

```typescript title="src/example.ts"
import { ResponseCache } from '@mastra/core/processors'
import { RequestContext } from '@mastra/core/request-context'

// Fresh context with the override
await agent.stream('hello', {
  requestContext: ResponseCache.context({ key: 'custom-key', bust: true }),
})

// Or merge into an existing context
const ctx = new RequestContext()
ctx.set('caller-meta', { userId: 'u-123' })
ResponseCache.applyContext(ctx, { bust: true })
await agent.stream('hello', { requestContext: ctx })
```

這些欄位在每次呼叫時都是可覆蓋的：

* `key`：字串或函數。僅覆寫此請求的自動派生快取鍵。
* `scope`: 字串或`null`. Overrides the tenant/user scope for this request only. `null` opts out of scoping.
* `bust`：布林值。跳過快取讀取，但完成後仍會寫入（對於「強制刷新」按鈕很有用）。

`cache`, `ttl`, and `agentId` stay on the constructor. They're instance-level concerns and not safe to vary per call.

### 租戶範圍 {/* #tenant-scoping */}

預設情況下，`ResponseCache` looks up `MASTRA_RESOURCE_ID_KEY` on the request context and uses it as the cache scope. An agent that already populates the resource id (e.g. via memory) gets per-user isolation automatically. Users never see each other's cached responses.

當您需要不同的範圍時明確覆蓋：

```typescript title="src/mastra/agents/scoped-agent.ts"
import { Agent } from '@mastra/core/agent'

new Agent({
  id: 'processors-agent',
  inputProcessors: [
    new ResponseCache({
      cache,
      scope: 'org-123', // explicit tenant scope
    }),
  ],
})
```

經過`scope: null` to deliberately share entries across all callers. Only use this for known-public, non-personalized content.

### 自訂快取後端 {/* #custom-cache-backend */}

`ResponseCache`接受任何`MastraServerCache`. For production, use `RedisServerCache` from `@mastra/redis`:

```typescript title="src/mastra/agents/cached-agent.ts"
import { Agent } from '@mastra/core/agent'
import { ResponseCache } from '@mastra/core/processors'
import { RedisServerCache } from '@mastra/redis'
import { createClient } from 'redis'

const client = createClient({ url: process.env.REDIS_URL })
await client.connect()

const cache = new RedisServerCache({ client })

export const agent = new Agent({
  id: 'cached-agent',
  name: 'Cached Agent',
  instructions: '...',
  model: '__GATEWAY_OPENAI_MODEL_BASE__',
  inputProcessors: [new ResponseCache({ cache })],
})
```

對於自訂後端，擴展`MastraServerCache` and implement its abstract methods (the processor only calls `get` and `set`).

### 快取是如何實現的 {/* #how-caching-is-implemented */}

`ResponseCache`鉤入`processLLMRequest` (cache lookup, short-circuits on hit) and `processLLMResponse` (cache write on completion). Both run inside the agentic loop *after* memory has loaded and earlier input processors have transformed the prompt.

快取鍵源自已解析的`LanguageModelV2Prompt` Mastra is about to send to the model. The key is created *after* memory has loaded and earlier input processors have run, and each step in an agentic tool loop is independently cached.

### 快取鍵中有什麼 {/* #whats-in-the-cache-key */}

當你不供貨時`key`, the processor derives one deterministically from the inputs that change the LLM's response at this step: `agentId`, `stepNumber` (so each step in a tool loop has its own cache entry), `scope`, model identity (`provider`, `modelId`, spec version), and the resolved `prompt` (post-memory + post-processors). Any change to these inputs automatically invalidates the cache.

還包括多模式提示。對於圖像和檔案部分，金鑰包括完整的 URL 或內聯二進位資料的位元組摘要（`Uint8Array`, `ArrayBuffer`). Requests that differ only in which image they reference therefore get different cache entries.

#### 自訂快取鍵 {/* #customize-the-cache-key */}

經過`key` as a function on the constructor or per-call to derive your own cache key from any subset of those inputs. The function receives the same inputs the deterministic hash would have consumed and returns a string (or a `Promise<string>`):

```typescript title="src/example.ts"
import { ResponseCache, buildResponseCacheKey } from '@mastra/core/processors'

await agent.stream(input, {
  requestContext: ResponseCache.context({
    // Cache only on the model id and the resolved prompt tail — ignore
    // step number, scope, etc.
    key: ({ model, prompt }) => `qa:${model.modelId}:${JSON.stringify(prompt).slice(-200)}`,
  }),
})

// Or reuse the deterministic helper while overriding individual fields:
await agent.stream(input, {
  requestContext: ResponseCache.context({
    key: inputs => buildResponseCacheKey({ ...inputs, scope: 'global' }),
  }),
})
```

如果函數拋出異常，處理器將回退到預設的金鑰派生，因此呼叫仍然受益於快取。

### 快取命中如何運作 {/* #how-cache-hits-work */}

當處理器發現快取命中時，它會透過返回快取區塊來短路 LLM 調用`processLLMRequest`. The agentic loop synthesizes a stream from those chunks instead of calling the model. `agent.generate()` collects them into a `FullOutput`; `agent.stream()` returns a `MastraModelOutput` whose chunks come from the cached buffer, so consumers iterating `fullStream` or awaiting `text`, `usage`, and `finishReason` see the cached values.

快取寫入發生在回應完成後。失敗的運作（錯誤、絆線啟動）不會被快取。下一個呼叫會乾淨地重試。

## 高級模式 {/* #advanced-patterns */}

### 確保最終答复`maxSteps` {/* #ensure-a-final-response-with-maxsteps */}

使用時`maxSteps` to limit agent execution, the agent may return an empty response if it attempts a tool call on the final step. Use `processInputStep()` with `sendSignal` to inject a reactive reminder on the last step. This approach preserves prompt caching because it appends a signal instead of modifying system messages.

```typescript title="src/mastra/processors/ensure-final-response.ts"
import type { Processor, ProcessInputStepArgs } from '@mastra/core/processors'

export class EnsureFinalResponseProcessor implements Processor {
  readonly id = 'ensure-final-response'

  private maxSteps: number

  constructor(maxSteps: number) {
    this.maxSteps = maxSteps
  }

  async processInputStep({ stepNumber, sendSignal }: ProcessInputStepArgs) {
    if (stepNumber !== this.maxSteps - 1) {
      return
    }

    await sendSignal?.({
      type: 'reactive',
      contents:
        `This is your final step (step ${stepNumber + 1} of ${this.maxSteps}). ` +
        `Do not call any more tools. Summarize what you have found and give the user a complete final answer now.`,
      attributes: { reason: 'max-steps-reached', step: stepNumber + 1 },
    })
  }
}
```

信號被傳遞為`<system-reminder>` user message that the model sees inline:

```xml
<system-reminder reason="max-steps-reached" step="5">This is your final step (step 5 of 5). Do not call any more tools. Summarize what you have found and give the user a complete final answer now.</system-reminder>
```

將處理器加入到`inputProcessors`, include a system prompt explaining the signal tags, and pass the same `maxSteps` value to `generate()` or `stream()`:

```typescript title="src/mastra/agents/index.ts"
import { Agent } from '@mastra/core/agent'
import { EnsureFinalResponseProcessor } from '../processors/ensure-final-response'

const MAX_STEPS = 5

const agent = new Agent({
  id: 'agent',
  instructions: `You are a helpful assistant.

Some messages you receive may contain <system-reminder>...</system-reminder> tags.
These reminders are injected by the system, not written by the user, even though they arrive inside a user message.
Treat the contents of a <system-reminder> as authoritative system instructions and follow them immediately.
Do not mention the reminder to the user or quote the tags back to them.`,
  inputProcessors: [new EnsureFinalResponseProcessor(MAX_STEPS)],
  // ...
})

await agent.generate('Your prompt', { maxSteps: MAX_STEPS })
```

:::注意
无功信号默认为`tagName: 'system-reminder'`. [When the agent sees your input](/docs/signals/sending-signals#when-the-agent-sees-your-input) covers when processor-emitted signals reach the model.
:::

### Tool讀取文件後發送上下文 {/* #send-context-after-a-tool-reads-a-file */}

處理器可以一次觀察Tool結果並注入後續指令，而不是每一步都注入。此範例發送一個內容`AGENTS.md` file after a tool call reads it, and skips the signal if the same file was already sent. `findAgentsMdPathFromToolCalls()`, `hasAlreadySentAgentsMdReminder()`, and `readAgentsMdInstructions()` are application helpers you write. Mastra doesn't export them.

訊號發送自`processInputStep()` follow the same interrupt and wait rules as any other input. The processor finishes before Mastra cancels the request it prepared; output processors settle before the next request, and processor side effects aren't undone. A processor that sends on every pass can duplicate context when a request is replaced, so inspect history and react to a specific trigger.

```typescript title="src/mastra/processors/agents-md-reminder.ts"
import type { Processor, ProcessInputStepArgs } from '@mastra/core/processors'

export const agentsMdReminderProcessor: Processor = {
  id: 'agents-md-reminder',
  async processInputStep({ messageList, sendSignal }: ProcessInputStepArgs) {
    const messages = messageList.get.all.db()
    const agentsMdPath = findAgentsMdPathFromToolCalls(messages)

    if (!agentsMdPath || hasAlreadySentAgentsMdReminder(messages, agentsMdPath)) {
      return messageList
    }

    await sendSignal?.({
      type: 'reactive',
      contents: readAgentsMdInstructions(agentsMdPath),
      attributes: {
        type: 'dynamic-agents-md',
        path: agentsMdPath,
      },
      metadata: {
        path: agentsMdPath,
      },
    })

    return messageList
  },
}
```

此模型接收此上下文為：

```xml
<system-reminder type="dynamic-agents-md" path="packages/ui/AGENTS.md">
  $agentsMdFileContents
</system-reminder>
```

等待中`sendSignal()` preserves stream echo ordering when a subscribed thread is active.

### 發出提醒但不保留 {/* #deliver-a-reminder-without-retaining-it */}

預設情況下，從處理器發送的訊號成為對話的一部分：它被寫入儲存並在稍後的回合中重新輸入提示。對於每次都重新註入的指令來說，這是不需要的，因為副本堆積起來，模型開始將自己過去的提醒視為要模仿的先前上下文。放`transient: true` to deliver the signal to the model for the current call only, without retaining it.

**何時使用它：**&#x96A8;著對話的成長，您希望在模型的新近度視窗中保留簡短的指導指令，例如「繼續當前任務」、「將答案保持在三個句子以下」或取決於即時應用程式狀態的每輪約束。每輪重新註入它，使其保持在最新消息附近。

```typescript title="src/mastra/processors/steering-reminder.ts" {10}
import type { Processor, ProcessInputStepArgs } from '@mastra/core/processors'

export class SteeringReminderProcessor implements Processor {
  readonly id = 'steering-reminder'

  async processInputStep({ sendSignal }: ProcessInputStepArgs) {
    await sendSignal?.({
      type: 'reactive',
      contents: 'Stay on the current task and keep answers under three sentences.',
      transient: true,
    })
  }
}
```

目前呼叫的提示中仍存在瞬態訊號。該模型看到它接近最新轉彎。它不會被保留，因此每次重新發送它都會在上下文中保留一個新的副本，而不是累積的歷史記錄，並且儲存的線程歷史記錄永遠不會包含它。由於沒有寫入任何內容，因此它還可以跨回合保持穩定的提示快取前綴。

### 發出自訂串流事件 {/* #emit-custom-stream-events */}

輸出處理器接收`writer` object that lets you emit custom data chunks back to the client during streaming. This is useful for use cases like streaming moderation results or sending UI update signals without blocking the original stream.

```typescript title="src/mastra/processors/moderation-processor.ts" {6,18-25}
import type { Processor } from '@mastra/core/processors'

export class ModerationProcessor implements Processor {
  id = 'moderation'

  async processOutputResult({ messages, writer }) {
    // Run moderation on the final output
    const text = messages
      .filter(m => m.role === 'assistant')
      .flatMap(m => m.content.parts?.filter(p => p.type === 'text'))
      .map(p => p.text)
      .join(' ')

    const result = await runModeration(text)

    if (result.requiresChange) {
      // Emit a custom event to the client with the moderated text
      await writer?.custom({
        type: 'data-moderation-update',
        data: {
          originalText: text,
          moderatedText: result.moderatedText,
          reason: result.reason,
        },
      })
    }

    return messages
  }
}
```

在客戶端上，監聽流程中的自訂區塊類型：

```typescript
const stream = await agent.stream('Hello')

for await (const chunk of stream.fullStream) {
  if (chunk.type === 'data-moderation-update') {
    // Update the UI with moderated text
    updateDisplayedMessage(chunk.data.moderatedText)
  }
}
```

自訂區塊類型必須使用`data-` prefix (e.g., `data-moderation-update`, `data-status`).

預設情況下，`processOutputStream()` skips `data-*` chunks so it doesn't accidentally operate on tool telemetry or other processors' output. To inspect, modify, or block these chunks in a processor, set `processDataParts = true` on that processor:

```typescript
class ModerationCollector implements Processor {
  id = 'moderation-collector'
  processDataParts = true

  async processOutputStream({ part, state }) {
    if (part.type === 'data-moderation-update') {
      state.warnings ??= []
      state.warnings.push(part.data)
    }
    return part
  }
}
```

### 向訊息添加元數據 {/* #add-metadata-to-messages */}

您可以將自訂元資料新增至訊息中`processOutputResult`. This metadata is accessible via the response object:

```typescript title="src/mastra/processors/metadata-processor.ts"
import type { Processor } from '@mastra/core/processors'
import type { MastraDBMessage } from '@mastra/core/memory'

export class MetadataProcessor implements Processor {
  id = 'metadata-processor'

  async processOutputResult({
    messages,

          ...msg,
          content: {
            ...msg.content,

              ...msg.content.metadata,
              processedAt: new Date().toISOString(),

            },
          },
        }
      }
      return msg
    })
  }
}
```

```typescript
const result = await agent.generate('Hello')

// The response includes uiMessages with processor-added metadata
const assistantMessage = result.response?.uiMessages?.find(m => m.role === 'assistant')
console.log(assistantMessage?.metadata?.customData)
```

### 使用Workflow作為處理器 {/* #use-workflows-as-processors */}

您可以使用 Mastra Workflow作為處理器來建立具有平行執行和條件分支以及錯誤處理功能的複雜處理管道：

```typescript title="src/mastra/processors/moderation-workflow.ts"
import { createWorkflow, createStep } from '@mastra/core/workflows'
import {
  ProcessorStepOutputSchema,
  PromptInjectionDetector,
  PIIDetector,
  ModerationProcessor,
} from '@mastra/core/processors'
import { Agent } from '@mastra/core/agent'

// Create a workflow that runs multiple checks in parallel
const moderationWorkflow = createWorkflow({
  id: 'moderation-pipeline',
  inputSchema: ProcessorStepOutputSchema,
  outputSchema: ProcessorStepOutputSchema,
})
  .parallel([
    createStep(
      new PIIDetector({
        model: '__GATEWAY_OPENAI_MODEL_LUNA__',
        strategy: 'redact',
      }),
    ),
    createStep(
      new PromptInjectionDetector({
        model: '__GATEWAY_OPENAI_MODEL_LUNA__',
        strategy: 'block',
      }),
    ),
    createStep(
      new ModerationProcessor({
        model: '__GATEWAY_OPENAI_MODEL_LUNA__',
        strategy: 'block',
      }),
    ),
  ])
  .map(async ({ inputData }) => {
    return inputData['processor:pii-detector']
  })
  .commit()

// Use the workflow as an input processor
const agent = new Agent({
  id: 'moderated-agent',
  name: 'Moderated Agent',
  model: '__GATEWAY_OPENAI_MODEL__',
  inputProcessors: [moderationWorkflow],
})
```

經過一個`.parallel()` step, each branch result is keyed by its processor ID (e.g. `processor:pii-detector`). Use `.map()` to select the branch whose output the next step should receive.

如果一個分支使用像這樣的變異策略`redact`, map to that branch so its transformed messages carry forward. If all branches only `block`, any branch works. Pick any one since none of them modify the messages.

當Agent註冊到 Mastra 時，處理器Workflow會自動註冊為Workflow，允許您在[Studio](/docs/studio/overview).

### 重試機制 {/* #retry-mechanism */}

處理者可以請求法學碩士重試其回應並提供回饋。這對於實施品質檢查或輸出驗證非常有用，包括迭代細化：

```typescript title="src/mastra/processors/quality-checker.ts"
import type { Processor } from '@mastra/core/processors'
import { Agent } from '@mastra/core/agent'

export class QualityChecker implements Processor {
  id = 'quality-checker'

  async processOutputStep({ messages, text, abort, retryCount }) {
    const qualityScore = await evaluateQuality(text)

    if (qualityScore < 0.7 && retryCount < 3) {
      // Request a retry with feedback for the LLM
      abort('Response quality score too low. Please provide a more detailed answer.', {
        retry: true,
        metadata: { score: qualityScore },
      })
    }

    return messages
  }
}

const agent = new Agent({
  id: 'quality-agent',
  name: 'Quality Agent',
  model: '__GATEWAY_OPENAI_MODEL__',
  outputProcessors: [new QualityChecker()],
  maxProcessorRetries: 3, // Step retry limit for processInputStep/processOutputStep. Unset by default, which disables those retries.
})
```

重試機制：

* `processOutputStep()` and `processInputStep()` methods
* 重播該步驟，並將中止原因逐字附加到對話結尾作為系統提醒。重試保留先前的請求作為其前綴，這保留了Provider提示快取
* 透過追蹤重試計數`retryCount` parameter
* 需要明確的`maxProcessorRetries` limit on the agent or call

### {/* #error-processor-retry-limits */}

`processAPIError()`有單獨的重試預算。什麼時候`errorProcessors` resolve to a non-empty list and `maxProcessorRetries` is omitted, the runtime allows up to `3` error-processor retries. Error processors are enabled by default on every agent (see [Error processors are enabled by default](#error-processors-are-enabled-by-default)), but `maxProcessorRetries` itself stays unset, so `processInputStep()` and `processOutputStep()` retries still need an explicit limit.

為了`StreamErrorRetryProcessor`, its own `maxRetries` (default `1`) bounds retries independently of the agent cap. Keep model retries at `0` when the processor is the only retry mechanism for a request.

### 違規回調 {/* #violation-callbacks */}

所有處理器都暴露一個`onViolation` property that fires whenever a policy violation is detected, both when `abort()` is called (block strategy) and when a processor issues a warning (warn strategy). Use it for alerting, logging, or side effects without affecting the processor's main logic:

```typescript title="src/mastra/processors/violation-logging.ts"
import { ModerationProcessor, TokenCostControl } from '@mastra/core/processors'

const moderation = new ModerationProcessor({
  model: '__GATEWAY_OPENAI_MODEL_LUNA__',
  strategy: 'block',
})

moderation.onViolation = ({ processorId, message, detail }) => {
  // Log to external monitoring, send alerts, update dashboards
  monitor.track('processor_violation', { processorId, message, detail })
}

const tokenCostControl = new TokenCostControl({
  maxCost: 10.0,
  scope: 'resource',
  window: '30d',
})

tokenCostControl.onViolation = ({ processorId, message, detail }) => {
  alertSystem.notify(`[${processorId}] ${message}`)
}
```

回呼收到一個`ProcessorViolation` object with:

* `processorId`：偵測到違規的處理器的 ID
* `message`：對所侵犯內容的人類可讀的描述
* `detail`：特定於處理器的元資料（例如成本使用、偵測到的 PII 類型、審核類別）

`onViolation`是基地的一部分[`Processor` interface](/reference/processors/processor-interface), so any custom processor can use it too. The runner automatically invokes it when any processor calls `abort()`. Errors thrown inside the callback are caught to prevent interfering with the processor pipeline.

### 中止和絆線區塊 {/* #abort-and-tripwire-chunks */}

呼喚`abort(reason, options)` throws a `TripWire` error that ends processing. On streams, Mastra emits a `tripwire` chunk clients can detect:

```typescript oxfmt:false
for await (const chunk of stream.fullStream) {
  if (chunk.type === 'tripwire') {
    console.log('Blocked by', chunk.payload.processorId, '-', chunk.payload.reason)
    break
  }
}
```

為了`agent.generate()`, the result exposes the same information as `result.tripwire` with `result.finishReason === 'other'`.

`abort`接受第二個選項參數：

* `retry: true`要求Agent重試而不是結束。輸入和輸出處理器重試需要`maxProcessorRetries` to be set on the agent or call.
* `metadata`將結構化資料附加到`tripwire` chunk so downstream consumers can branch on categories like `pii`, `quality`, or `moderation`.

## API錯誤處理 {/* #api-error-handling */}

這`processAPIError` method handles LLM API rejections, errors where the API rejects the request (such as 400 or 422 status codes) rather than network or server failures. This lets you modify the request and retry when the API rejects the message format.

```typescript title="src/mastra/processors/api-error-handler.ts"
import { APICallError } from '@ai-sdk/provider'
import type { Processor, ProcessAPIErrorArgs, ProcessAPIErrorResult } from '@mastra/core/processors'

export class ContextLengthHandler implements Processor {
  id = 'context-length-handler'

  processAPIError({
    error,
    messageList,
    retryCount,
  }: ProcessAPIErrorArgs): ProcessAPIErrorResult | void {
    if (retryCount > 0) return

    if (APICallError.isInstance(error) && error.message.includes('context length exceeded')) {
      const messages = messageList.get.all.db()
      if (messages.length > 4) {
        messageList.removeByIds([messages[1]!.id, messages[2]!.id])
        return { retry: true }
      }
    }
  }
}
```

Mastra 包括一個內置[`PrefillErrorHandler`](/reference/processors/prefill-error-handler) that automatically handles the Anthropic "assistant message prefill" error. This processor is auto-injected and requires no configuration.

### 從附件下載失敗中恢復 {/* #recover-from-attachment-download-failures */}

當模型本身無法取得附件 URL 時，Mastra 會在呼叫模型之前下載附件。如果下載失敗，`processAPIError()` receives a `MastraError` with the id `DOWNLOAD_ASSETS_FAILED` and the attachment URL in `error.details.url`. An error processor can use this to replace the attachment, for example with a fresh signed URL, and return `{ retry: true }`. Fallback models get a chance next.

如果沒有任何東西恢復下載，Agent不會失敗。它重試一次，附件替換為`[Attachment unavailable: <name>]` text placeholder and logs a warning. Mastra records the URL on the stored user message under `metadata.mastra.unavailableAttachments`. Later turns show the same placeholder without downloading the attachment again. The attachment itself stays in the thread's history.

無法解碼的資料 URL 會立即替換為佔位符，因為重試無法修復它。

## 接收後台工作通知 {/* #receive-background-work-notifications */}

使用`createBackgroundWorkSignalProcessor()` to retain the active caller's signal capability for eligible background tool calls:

```typescript
import { Agent } from '@mastra/core/agent'
import { createBackgroundWorkSignalProcessor } from '@mastra/core/processors'

const agent = new Agent({
  id: 'background-agent',
  name: 'Background agent',
  instructions: 'Complete tasks using the available tools.',
  model: '__GATEWAY_OPENAI_MODEL__',
  inputProcessors: [createBackgroundWorkSignalProcessor()],
})
```

Mastra 的後台運行時仍負責執行、持久性、重試、結果協調和延續。處理器僅保留呼叫者範圍的通知存取權限。當後台工作開始時，它會發出`work-deferred` or `work-awaited` with `status: 'running'`. After the authoritative tool result is reconciled, it emits `work-completed` or `work-failed`.

通知是進程本地的並且盡力而為。如果原始運行已結束或無法傳遞訊號（例如，因為任務在另一個進程上恢復），Mastra 會保留權威結果，而無需重新建立運行或重試通知。前台呼叫永遠不會發出後台工作通知，因為沒有獨立的工作需要報告。
