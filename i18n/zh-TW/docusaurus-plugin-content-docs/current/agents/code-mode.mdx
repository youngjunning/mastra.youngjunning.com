# 程式碼模式

**加入版本：** `@mastra/core@1.38.0`

程式碼模式讓 Agent 在隔離的 Sandbox 中使用多個 Tool 進行運算，最後傳回一份更準確的回應。

模型會把逐輪呼叫 Tool 的工作交給一個函式，並依照使用者的問題撰寫函式。這個函式透過 `external_*` 函式協調現有的 Tool，並精簡或彙整結果，形成一份結構化答案。

[`createCodeMode()`](/reference/tools/create-code-mode) 會傳回此 Tool，預設 `id` 是 `execute_typescript`。你可以設定 `id`，讓同一個 Agent 同時使用數個程式碼模式 Tool，各自限定可呼叫的 Tool（請參閱[限制各程式碼 Tool 的呼叫範圍](#scoping-tools-across-multiple-code-tools)）。

## 何時使用程式碼模式 {/* #when-to-use-code-mode */}

如果 Agent 要用多個 Tool 回答使用者的問題或完成複雜運算，可以使用程式碼模式：

- 減少往返次數：一次 Tool 呼叫即可完成需要多個 Tool 的查詢，省去每次選擇 Tool 時重跑 Agent 迴圈的開銷。
- 節省上下文空間：函式可先精簡或彙整大量的 Tool 回應，再傳回給 Agent。
- 算術結果準確：總和、平均值等算式交由 JavaScript 計算，無須透過 token 預測取得結果。
- 預先規劃：篩選、彙整與分支都能在同一個函式內完成，省去多輪處理。

## 運作原理 {/* #how-it-works */}

未使用程式碼模式時，涉及多個 Tool 的查詢可能要經過數輪 Agent 迴圈。模型先選擇一個 Tool、讀取結果，再視需要重複這個過程。

每一輪都會將完整的 Tool 回應加入 Agent 的上下文視窗，可能降低推論品質並增加 token 用量。

啟用程式碼模式後，Tool 仍在主機上執行，完整保留驗證、請求上下文及追蹤功能。Sandbox 只執行模型撰寫的協調程式碼，每次 `external_*` 呼叫都會轉交給主機上的實際 Tool。函式可先精簡或彙整結果，再將一份回應傳回 Agent。

函式會在 [Workspace 的 Sandbox](/docs/sandbox/overview) 中執行。由於程式碼是模型撰寫的，你必須明確選擇執行邊界：傳入 `sandbox`，或使用已提供 Sandbox 的 Workspace。若要在主機上執行，請明確傳入 `new LocalSandbox()`。函式會以具備主機權限的 `node` 程序執行，因此只應在可信任的開發環境或本機開發時使用。

如果傳輸機制本身就提供執行邊界，則是例外。[`IsolatedVmCodeModeTransport`](/reference/tools/isolated-vm-transport) 會在程序內的 V8 隔離環境執行程式，無須使用 Sandbox（請參閱[程序內隔離](#in-process-isolation)）。

## 快速上手 {/* #quickstart */}

`createCodeMode()` 會傳回 Tool 及產生的指令。未指定 `id` 時，Tool 會使用 `execute_typescript` 作為名稱。請將 Tool 和指令一併加入 Agent：

```typescript
import { Agent } from '@mastra/core/agent'
import { createCodeMode, createTool } from '@mastra/core/tools'
import { LocalSandbox } from '@mastra/core/workspace'
import { z } from 'zod'

const getTopProducts = createTool({
  id: 'getTopProducts',
  description: 'Get top selling products',
  inputSchema: z.object({ limit: z.number() }),
  outputSchema: z.object({
    products: z.array(z.object({ id: z.string(), name: z.string(), totalSales: z.number() })),
  }),
  execute: async ({ limit }) => fetchTopProducts(limit),
})

const getProductRatings = createTool({
  id: 'getProductRatings',
  description: 'Get ratings for a product',
  inputSchema: z.object({ productId: z.string() }),
  outputSchema: z.object({ ratings: z.array(z.object({ score: z.number() })) }),
  execute: async ({ productId }) => fetchRatings(productId),
})

const { tool, instructions } = createCodeMode({
  tools: { getTopProducts, getProductRatings },
  sandbox: new LocalSandbox(), // required; runs on the host — see "How it works"
})

const agent = new Agent({
  id: 'shop-assistant',
  name: 'shop-assistant',
  instructions: ['You are a helpful shopping assistant.', instructions],
  model: '__GATEWAY_OPENAI_MODEL__',
  tools: { execute_typescript: tool },
})
```

使用者問「排名前 5 的產品有哪些？各自的平均評分是多少？」時，模型會發出一次 `execute_typescript` 呼叫，交由函式處理多個 Tool 呼叫：

```typescript
const top = await external_getTopProducts({ limit: 5 })
const ratings = await Promise.all(
  top.products.map(p => external_getProductRatings({ productId: p.id })),
)
return top.products.map((product, i) => {
  const scores = ratings[i].ratings.map(r => r.score)
  const avg = scores.reduce((sum, s) => sum + s, 0) / scores.length
  return {
    name: product.name,
    sales: product.totalSales,
    averageRating: Math.round(avg * 100) / 100,
  }
})
```

五項評分查詢會平行執行，平均值由 JavaScript 計算，Agent 最後會收到一份結構化結果。

若要讓 `createCodeMode()` 發揮效果，可以掌握以下做法：

- 讓每個 Tool 專注於一項任務，再由模型在程式碼中組合使用。
- 當呼叫可以透過 `Promise.all` 平行執行時，程式碼模式最能發揮效果。

設定選項、回傳值、結果結構，以及如何檢視指令，請參閱 [`createCodeMode()` 參考文件](/reference/tools/create-code-mode)。

## 限制各程式碼 Tool 的呼叫範圍 {/* #scoping-tools-across-multiple-code-tools */}

`createCodeMode()` 的每次呼叫都會建立獨立的允許清單。呼叫多次就能為 Agent 建立數個程式碼 Tool，各自限定一組 Tool。每個執行個體只能使用該次 `createCodeMode()` 所接收的 Tool 對應的 `external_*` 函式，各組彼此隔離。

為每個 Tool 指定不同的 `id` 以免衝突，然後將各 Tool 的指令加入 Agent：

```typescript
const sales = createCodeMode({
  id: 'sales_code',
  tools: { listRecentOrders, getCustomer },
  sandbox,
})

const inventory = createCodeMode({
  id: 'inventory_code',
  tools: { listProducts, getSupplier },
  sandbox,
})

const agent = new Agent({
  id: 'ops-assistant',
  name: 'ops-assistant',
  instructions: ['You are an ops assistant.', sales.instructions, inventory.instructions],
  model: '__GATEWAY_OPENAI_MODEL__',
  tools: { sales_code: sales.tool, inventory_code: inventory.tool },
})
```

為 `sales_code` 產生的程式碼無法呼叫庫存 Tool，反之亦然。這樣可以落實最小權限原則，並縮小各 Tool 的提示範圍。

## 已連線的 Tool {/* #connected-tools */}

若要協調 Mastra Platform 上已連線的 Provider 所提供的 Tool，請使用 [`tools().codeMode()`](/reference/connect/tools#code-mode)（由 `@mastra/connect` 提供）。它會在每次請求時依照目前的連線建立程式碼 Tool 和指令，需要核准的 Tool 則由 Agent 直接呼叫。

## 遠端 Sandbox {/* #remote-sandboxes */}

預設的傳輸機制會將程式寫入主機的檔案系統，再以 `node` 執行。`LocalSandbox` 與主機共用檔案系統，因此可使用這項機制。遠端 Sandbox（例如 [E2B](/integrations/sandboxes/e2b)）會在獨立的微型虛擬機內執行，裡面沒有主機上的路徑。

遠端 Sandbox 需要能將程式寫入 Sandbox 檔案系統的傳輸機制。若使用 E2B，請將隨附的 `E2BCodeModeTransport` 當作第二個引數傳入 `createCodeMode`：

```typescript
import { createCodeMode } from '@mastra/core/tools'
import { E2BSandbox, E2BCodeModeTransport } from '@mastra/e2b'

const { tool, instructions } = createCodeMode(
  { tools, sandbox: new E2BSandbox() },
  new E2BCodeModeTransport(),
)
```

## 程序內隔離 {/* #in-process-isolation */}

若要建立安全邊界，又無須啟動其他程序或使用遠端 Sandbox，可以使用 [`IsolatedVmCodeModeTransport`](/reference/tools/isolated-vm-transport)（由 `@mastra/isolated-vm` 提供）。程式會在程序內的 V8 隔離環境執行，無須 Sandbox。這個環境無法存取檔案系統、網路或程序，只能使用連到主機上 Tool 的 `external_*` 函式。

```typescript
import { createCodeMode } from '@mastra/core/tools'
import { IsolatedVmCodeModeTransport } from '@mastra/isolated-vm'

const { tool, instructions } = createCodeMode(
  { tools }, // no sandbox needed
  new IsolatedVmCodeModeTransport({ memoryLimitMb: 128 }),
)
```

`isolated-vm` 是原生擴充模組。在 Node.js 20 以上版本中，必須加上 `--no-node-snapshot` 旗標才能啟動主機程序。設定方式請參閱 [IsolatedVmCodeModeTransport 參考文件](/reference/tools/isolated-vm-transport)。

若主機無法安裝原生擴充模組或設定 Node.js 啟動旗標（無伺服器平台經常有此限制），可改用 [`QuickJsCodeModeTransport`](/reference/tools/quickjs-transport)（由 `@mastra/quickjs` 提供）。它透過編譯成 WebAssembly 的 QuickJS 執行環境提供相同的程序內隔離，執行速度則較慢：

```typescript
import { createCodeMode } from '@mastra/core/tools'
import { QuickJsCodeModeTransport } from '@mastra/quickjs'

const { tool, instructions } = createCodeMode(
  { tools }, // no sandbox needed
  new QuickJsCodeModeTransport({ memoryLimitMb: 128 }),
)
```

各種傳輸機制的比較，請見[選擇傳輸機制](/reference/tools/quickjs-transport#choosing-a-transport)。
