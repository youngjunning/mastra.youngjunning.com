# Tool

Agent程式使用Tool來呼叫 API 或查詢資料庫。他們還可以從您的程式碼庫運行自訂函數。Tool透過提供對資料的結構化存取和執行明確定義的操作，為Agent提供了超越語言生成的功能。您还可以从远程加载Tool[MCP servers](/docs/connections/mcp)擴大Agent的能力。對於 Linear、Slack 和 GitHub 等服務，[連接](/docs/mastra-platform/connect#add-tools-to-an-agent)Mastra 平台提供具有託管憑證的現成Tool，您可以將其與您自己的憑證結合。

<Inject>
  **對於人工智慧Agent：** `execute` has exactly one signature: `execute(inputData, context)`. The first parameter is validated against `inputSchema`。運行時總是提供第二個參數`requestContext`, `tracingContext`, `abortSignal`，以及其他執行元資料。不使用時可以省略。其他形狀已經過時了。跑步`npx mastra api tool execute weather-tool '{"location":"San Francisco"}'`直接測試這個Tool，而不是寫臨時腳本。該命令需要一個正在運行的 Mastra 伺服器；啟動本地伺服器`npx mastra dev`，或傳遞可存取伺服器的基本 URL`--url`。跑步`npx mastra api tool execute --schema``npx skills add mastra-ai/skills --skill mastra`取得完整的 API CLI 發現、定位、架構、驗證和錯誤處理指南。
</Inject>

## 何時使用Tool {/* #when-to-use-tools */}

當Agent需要來自遠端資源的附加上下文或訊息，或需要執行執行特定操作的程式碼時，請使用Tool。這包括模型無法自行可靠處理的任務，例如獲取即時數據或返回一致的、定義明確的輸出。

## 快速入門 {/* #quickstart */}

進口[`createTool`](/reference/tools/create-tool) from `@mastra/core/tools` and define a tool with an `id`, `description`, `inputSchema`, `outputSchema`, and `execute` function.

此範例建立一個從 API 取得天氣資料的Tool。`execute` has exactly one signature: `execute(inputData, context)`. The first parameter contains input validated against `inputSchema`. The runtime always provides the second parameter as the execution context, though you may omit it from your function signature when unused. You can destructure the input fields directly in the function signature.

```typescript title="src/mastra/tools/weather-tool.ts"
import { createTool } from '@mastra/core/tools'
import { z } from 'zod'

export const weatherTool = createTool({
  id: 'weather-tool',
  description: 'Fetches weather for a location',
  inputSchema: z.object({
    location: z.string(),
  }),
  outputSchema: z.object({
    location: z.string(),
    temperatureCelsius: z.number(),
    conditions: z.string(),
  }),
  execute: async ({ location }, { abortSignal }) => {
    const response = await fetch(`https://wttr.in/${location}?format=j1`, {
      signal: abortSignal,
    })
    const data = await response.json()

    return {
      location,
      temperatureCelsius: Number(data.current_condition[0].temp_C),
      conditions: data.current_condition[0].weatherDesc[0].value,
    }
  },
})
```

創建Tool時，請保持描述簡潔並專注於該Tool的用途，並強調其主要用例。描述性架構名稱還可以幫助指導Agent如何使用該Tool。參觀[`createTool`](/reference/tools/create-tool) reference for more information on available properties, configurations, and examples.

若要使Agent程式可以使用Tool，請將其新增至`tools` property on the `Agent` class. Mentioning available tools and their general purpose in the agent's system prompt helps the agent decide when to call a tool and when not to.

```typescript {11} title="src/mastra/agents/weather-agent.ts"
import { Agent } from '@mastra/core/agent'
import { weatherTool } from '../tools/weather-tool'

export const weatherAgent = new Agent({
  id: 'weather-agent',
  name: 'Weather Agent',
  instructions: `
    You are a helpful weather assistant.
    Use the weatherTool to fetch current weather data.`,
  model: '__GATEWAY_OPENAI_MODEL__',
  tools: { weatherTool },
})
```

### 處理輸出驗證失敗 {/* #handle-output-validation-failures */}

當結果不匹配時`outputSchema`, Mastra logs a warning and returns a validation error object instead of the result. The model then treats the call as failed and may retry it. For tools whose side effects have already happened by the time the result is produced, set `outputValidation: 'warn'`. Mastra still logs the mismatch, but it returns the real result unchanged, which keeps the model from retrying an order that was already placed.

```typescript title="src/mastra/tools/place-order-tool.ts"
import { createTool } from '@mastra/core/tools'
import { z } from 'zod'

export const placeOrderTool = createTool({
  id: 'place-order',
  description: 'Places an order and returns its id and total',
  inputSchema: z.object({ sku: z.string(), quantity: z.number().int().positive() }),
  outputSchema: z.object({ orderId: z.string(), total: z.number() }),
  outputValidation: 'warn',
  execute: async ({ sku, quantity }) => {
    return await orders.create({ sku, quantity })
  },
})
```

## 多種Tool {/* #multiple-tools */}

透過將特定部分委託給各個Tool，Agent可以使用多個Tool來處理更複雜的任務。Agent根據使用者的訊息和Agent的指示以及Tool描述和模式來決定使用哪些Tool。

```typescript {13} title="src/mastra/agents/weather-agent.ts"

import { hazardsTool } from '../tools/hazards-tool'

export const weatherAgent = new Agent({
  id: 'weather-agent',
  name: 'Weather Agent',
  instructions: `
    You are a helpful weather assistant.
    Use the weatherTool to fetch current weather data.
    Use the hazardsTool to provide information about potential weather hazards.`,
  model: '__GATEWAY_OPENAI_MODEL__',
  tools: { weatherTool, hazardsTool },
})
```

```typescript title="src/mastra/agents/supervisor.ts"
  id: 'supervisor',
  name: 'Supervisor',
  instructions: 'Coordinate the writer to produce content.',
  model: '__GATEWAY_OPENAI_MODEL__',
  // highlight-next-line
  agents: { writer },
})
```

## 模型的形狀輸出 {/* #shape-output-for-the-model */}

使用`toModelOutput` when your tool returns rich structured data for your application, but you want the model to receive a smaller or multimodal representation. This keeps model context focused while preserving the full tool result in your app.

```typescript title="src/mastra/tools/weather-tool.ts"
import { createTool } from '@mastra/core/tools'

export const weatherTool = createTool({
  execute: async ({ location }) => {
    const response = await fetch(`https://wttr.in/${location}?format=j1`)
    const data = await response.json()

    return {
      location,
      temperatureCelsius: Number(data.current_condition[0].temp_C),
      conditions: data.current_condition[0].weatherDesc[0].value,
      weatherIconUrl: data.current_condition[0].weatherIconUrl[0].value,
      source: data,
    }
  },
  toModelOutput: output => {
    return {
      type: 'content',
      value: [
        {
          type: 'text',
          text: `${output.location}: ${output.temperatureCelsius}°C and ${output.conditions}`,
        },
        { type: 'image-url', url: output.weatherIconUrl },
      ],
    }
  },
})
```

`toModelOutput`也適用於客戶端Tool。對於通過的Tool`clientTools`, the mapping runs on the client after the tool executes, and the transformed output is sent back to the server alongside the raw result. For tools defined on the server without an `execute` function (the browser runs the tool and sends the result back on the next request), the server definition's `toModelOutput` is applied to the incoming result. The model receives the transformed content instead of the raw tool result.

## 在客戶端運行的Tool {/* #tools-that-run-on-the-client */}

沒有Tool的Tool`execute` function is a client tool: the server can't run it. The agent stops at the step where the model called it. The run ends with `finishReason: 'tool-calls'`, and the model doesn't produce more text until the tool has a result. Pick the pattern that matches what the model needs back:

* **客戶端運行該Tool，模型需要其結果**: 省略`execute`. The client runs the tool, adds the result to the conversation, and sends a new request so the agent continues. With AI SDK `useChat()`, see [client tools with `useChat()`](/integrations/agentic-ui/ai-sdk-ui#client-tools-with-usechat).
* **客戶端只渲染調用**（例如產品卡）：為Tool提供`execute` that returns a short acknowledgement. The agent continues in the same run, and the client renders the tool part from its input. Return a small value instead of echoing the input so the model context and stored messages stay small.
* **該Tool需要用戶提供結構化的答案**（例如確認購物車寫入）：致電`suspend()` in `execute`, and resume with the user's answer. See [runtime suspension with `suspend()`](/docs/agents/human-in-the-loop#runtime-suspension-with-suspend).

```typescript title="src/mastra/tools/show-product-tool.ts"
import { createTool } from '@mastra/core/tools'
import { z } from 'zod'

export const showProductTool = createTool({
  id: 'show-product',
  description: 'Shows a product card to the user',
  inputSchema: z.object({
    productId: z.string(),
  }),
  // highlight-next-line
  execute: async () => ({ rendered: true }),
})
```

子Agent無法運行客戶端Tool。當子Agent呼叫Tool時沒有`execute`, its run stops and the supervisor receives the unresolved calls in `subAgentPendingToolCalls` on the delegation result. Give client tools to the supervisor, or use `suspend()` in the subagent's tool. Suspension propagates through the supervisor, see [use `suspend()` in supervisor agents](/docs/agents/human-in-the-loop#use-suspend-in-supervisor-agents).

## 轉換 UI 和腳本的Tool負載 {/* #transform-tool-payloads-for-ui-and-transcripts */}

使用`transform` when a tool returns raw data your application needs, but browser-facing streams or user-visible transcript messages should receive a smaller or safer shape. `transform` is separate from `toModelOutput`: `toModelOutput` shapes the payload sent back to the model, while `transform` shapes tool input, output, errors, approval payloads, and suspension payloads for `display` and `transcript` targets.

Tool級轉換僅更改其定義的階段。在下面的例子中，僅`output` is transformed, so the stored tool input stays unchanged. If a transform is configured and it fails, Mastra doesn't fall back to the raw payload for display or transcript targets. Input deltas are suppressed when no safe `inputDelta` transform is available.

以下範例從兩個目標編輯秘密：

```typescript title="src/mastra/tools/customer-tool.ts"
import { createTool } from '@mastra/core/tools'
import { z } from 'zod'

export const customerTool = createTool({
  id: 'lookup-customer',
  description: 'Looks up a customer by id',
  inputSchema: z.object({
    customerId: z.string(),
  }),
  outputSchema: z.object({
    ssn: z.string(),
  }),
  execute: async ({ customerId }) => {
    // const response = await fetch(`https://your-crm.example.com/customers/${customerId}`)
    // const { ssn } = await response.json()
    return {
      ssn: '123-45-6789',
    }
  },
  // highlight-start
  transform: {
    display: {
      output: () => ({ ssn: '***-**-****' }),
    },
    transcript: {
      output: () => ({ ssn: '***-**-****' }),
    },
  },
  // highlight-end
})
```

您的應用程式程式碼仍然會收到原始數據`ssn` from the tool. Browser-facing streams get the `display` output, and user-visible transcript messages get the `transcript` output.

當 DurableAgent 可以在進程重新啟動後完成Tool呼叫時，請在Tool的`transform.transcript` configuration. A per-invocation transform passed to the DurableAgent lives in the in-process run registry and can't be recovered in a fresh process. The durable worker re-resolves the tool-level transform from the registered tool.

對於更多階段，包括`input`, `inputDelta`, `error`, `approval`, `suspend`, and `resume`, see the [`createTool()` reference](/reference/tools/create-tool#example-with-transform). For shared rules across several tools, configure the agent-level `transform` policy in the [`Agent` constructor](/reference/agents/agent#constructor-parameters).

## 圍繞Tool呼叫運行邏輯 {/* #run-logic-around-tool-calls */}

使用`hooks` to run custom logic before and after every tool call an agent makes. Hooks apply to all tool sources: assigned tools, memory tools, toolsets, client tools, agent and workflow tools, and [workspace tools](/reference/workspace/workspace-class#tool-hooks). Common uses include logging, auditing, input validation, and blocking specific calls.

```typescript title="src/mastra/agents/support-agent.ts"
import { Agent } from '@mastra/core/agent'
import { db } from '../db' // your application database client

export const supportAgent = new Agent({
  id: 'support-agent',
  name: 'support-agent',
  instructions: 'Help users with their questions.',
  model: '__GATEWAY_OPENAI_MODEL__',
  // highlight-start
  hooks: {
    beforeToolCall: ({ toolName, input }) => {
      console.log(`Running ${toolName}`, input)
    },
    afterToolCall: async ({ toolName, input, output, error }) => {
      await db.auditLog.insert({
        toolName,
        input,
        output,
        error: error ? String(error) : undefined,
      })
    },
  },
  // highlight-end
})
```

`afterToolCall`必須返回`void` (or `Promise<void>`). Await your storage call, but don't return its result. If the storage call throws, the tool call fails with that error, so catch it inside the hook if audit logging should be best-effort. `afterToolCall` doesn't run for calls skipped by `beforeToolCall` or for declined [pre-execution approvals](/docs/agents/human-in-the-loop#pre-execution-approval), so record those decisions where you handle them.

`beforeToolCall`在Tool執行之前運行並接收Tool名稱、輸入和執行上下文。返回`{ proceed: false, output }` to skip the tool call entirely, the agent receives `output` as the tool result:

```typescript
const guardedAgent = new Agent({
  id: 'guarded-agent',
  name: 'guarded-agent',
  instructions: 'Run shell commands for the user.',
  model: '__GATEWAY_OPENAI_MODEL__',
  hooks: {
    beforeToolCall: ({ toolName, input }) => {
      const command = (input as { command?: string }).command ?? ''
      if (toolName === 'execute_command' && command.includes('rm -rf')) {
        return { proceed: false, output: 'Command blocked by policy.' }
      }
    },
  },
})
```

`afterToolCall`Tool完成後運行，無論成功或失敗。成功後會收到`output`; if the tool threw, it receives `error` instead and the error is re-thrown after the hook runs.

### 每次執行掛鉤 {/* #per-execution-hooks */}

經過`hooks` to `.generate()` or `.stream()` to set hooks for a single execution. Per-execution hooks override matching agent-level hooks:

```typescript
await supportAgent.generate('Look up the order status', {
  hooks: {
    beforeToolCall: ({ toolName }) => {
      console.log(`This run only: ${toolName}`)
    },
  },
})
```

Agent級和每次執行掛鉤按鍵合併：僅傳遞`beforeToolCall` at execution time keeps the agent-level `afterToolCall`.

## 串流媒體 {/* #streaming */}

Tool支援生命週期掛鉤，使您可以在串流期間監視Tool執行的不同階段。這些鉤子對於日誌記錄或分析特別有用。

對於通用的`writer` API usage, see [Streaming](/docs/guides/streaming#writer-api).

### 可用的掛鉤 {/* #available-hooks */}

* **輸入開始時**：當Tool調用輸入流開始時調用
* **onInputDelta**：在輸入的每個區塊流入時調用
* **輸入可用時**：在解析和驗證完整輸入時調用
* **輸出**：Tool成功執行並輸出後調用

[createTool() reference](/reference/tools/create-tool#tool-lifecycle-hooks).

### 範例：使用`onInputAvailable` and `onOutput` {/* #example-using-oninputavailable-and-onoutput */}

```typescript
import { createTool } from '@mastra/core/tools'
import { z } from 'zod'

export const weatherTool = createTool({
  id: 'weather-tool',
  description: 'Get weather information',
  inputSchema: z.object({
    location: z.string(),
  }),
  outputSchema: z.object({
    location: z.string(),
    temperatureCelsius: z.number(),
    conditions: z.string(),
  }),
  // Called when the complete input is available
  onInputAvailable: ({ input, toolCallId }) => {
    console.log(`Weather requested for: ${input.location}`)
  },
  execute: async ({ location }) => {
    const weather = await fetchWeather(location)
    return weather
  },
  // Called after successful execution
  onOutput: ({ output, toolName }) => {
    console.log(`${toolName} result: ${output.temperatureCelsius}°C, ${output.conditions}`)
  },
})
```

### UI 中的串流Tool輸入 {/* #streaming-tool-input-in-uis */}

當模型產生Tool呼叫時，參數逐漸到達`tool-call-delta` stream chunks before the final `tool-call` chunk. UIs can listen for the corresponding `tool_input_start`, `tool_input_delta`, and `tool_input_end` events to render tool arguments as they stream in, for example, showing a file path or command immediately rather than waiting for the complete tool call.

`argsTextDelta` fragments lets you extract usable argument values before the JSON is complete. It enables features like live diff previews for edit tools, streaming file content for write tools, and instant display of search patterns or file paths.

經過`toolChoice` or `activeTools` to `.generate()` or `.stream()` to control which tools the agent uses at runtime.

```typescript
await agent.generate('Check the forecast', {

```

## 控制`toolName` in stream responses {/* #control-toolname-in-stream-responses */}

這`toolName` in stream responses is determined by the **object key** you use, not the `id` property of the tool, agent, or workflow.

```typescript oxfmt:false
export const weatherTool = createTool({
  id: 'weather-tool',
})

// Using the variable name as the key
tools: { weatherTool }
// Stream returns: toolName: "weatherTool"

// Using the tool's id as the key
tools: { [weatherTool.id]: weatherTool }
// Stream returns: toolName: "weather-tool"

// Using a custom key
tools: { "my-custom-name": weatherTool }
// Stream returns: toolName: "my-custom-name"
```

这使您可以指定如何在流中识别Tool。如果你想要`toolName` to match the tool's `id`, use the tool's `id` as the object key.

### 作為Tool的子Agent和Workflow {/* #subagents-and-workflows-as-tools */}

子Agent程式和Workflow遵循相同的模式。它們被轉換為帶有前綴的Tool，後面跟著您的物件鍵：

|物業 |前綴|範例鍵|`toolName` |
| - | - | - | - |
| `agents` | `agent-` | `weather` | `agent-weather` |
| `workflows` | `workflow-` | `research` | `workflow-research` |

```typescript
const orchestrator = new Agent({
  id: 'orchestrator',
  agents: {
    weather: weatherAgent, // toolName: "agent-weather"
  },
  workflows: {
    research: researchWorkflow, // toolName: "workflow-research"
  },
})
```

請注意，對於子Agent，您將在串流響應中看到兩個不同的標識符：

* `toolName: "agent-weather"`在Tool呼叫事件中：產生的Tool包裝器名稱
* `id: "weather-agent"`在`data-tool-agent` chunks: the subagent's actual `id` property

## 內建Tool {/* #built-in-tools */}

Mastra 包括與Agent無關的內建Tool`@mastra/core/tools` that add interactive and organizational capabilities to any agent.

每個Tool都有兩個名稱：您匯入的匯出以及模型在Tool呼叫、追蹤和Tool中看到的Tool ID`toolName` fields.

|出口|ToolID |目的|
| - | - | - |
|`askUserTool` | `ask_user` | Ask the user a question and wait for their answer |
| `submitPlanTool` | `submit_plan` | Submit a plan file for user approval |
| `taskWriteTool` | `task_write` | Create or replace a structured task list |
| `taskUpdateTool` | `task_update` | Update one tracked task by ID |
| `taskCompleteTool` | `task_complete` | Mark one tracked task completed |
| `taskCheckTool` | `task_check` | Check task list completion status |
| `webSearchTool` | `<provider.defined>` | Run the active provider's native web search |
| `webFetchTool` | `web_fetch` | Fetch a web page by URL and return its text content |

### 使用Provider網路搜尋 {/* #use-provider-web-search */}

進口`webSearchTool` from `@mastra/core/tools` when you want the model provider to run its native web search tool. Mastra resolves it at run time from the active model, then passes the provider-managed tool to the model.

```typescript {2,10} title="src/mastra/agents/research-agent.ts"
import { Agent } from '@mastra/core/agent'
import { webSearchTool } from '@mastra/core/tools'

export const researchAgent = new Agent({
  id: 'research-agent',
  name: 'Research Agent',
  instructions: 'Use web search when you need current information.',
  model: 'openai/gpt-5.6-sol',
  tools: {
    search: webSearchTool,
  },
})
```

`webSearchTool`支援 OpenAI、Anthropic、Google Gemini 和 xAI 模型。如果 Mastra 無法從活動模型推斷出這些Provider之一，則Agent運行失敗並顯示`MastraError`.

解析後的ToolID來自Provider：`openai.web_search`, `anthropic.web_search_20250305`, `google.google_search`, or `xai.web_search`.

透過 Mastra 閘道提供服務的模型，例如`mastra/openai/gpt-5.6-sol`, use the gateway's own web search (`openrouter.web_search`) instead. Results from gateway web search arrive in the model's text response, without separate tool-call or source chunks. Other provider-native tools aren't available through the gateway, so passing one makes the agent run fail with a `MastraError`.

這`search` key is only the agent-local tool name. Use any key. The `webSearchTool` value tells Mastra to use provider web search.

### 取得網頁 {/* #fetch-a-web-page */}

進口`webFetchTool` from `@mastra/core/tools` when the agent needs to read a specific URL. The tool requests the page over HTTP or HTTPS and returns its text content plus response metadata.

```typescript {2,10} title="src/mastra/agents/reader-agent.ts"
import { Agent } from '@mastra/core/agent'
import { webFetchTool } from '@mastra/core/tools'

export const readerAgent = new Agent({
  id: 'reader-agent',
  name: 'Reader Agent',
  instructions: 'Fetch the page the user links to before answering.',
  model: 'openai/gpt-5.6-sol',
  tools: {
    fetch: webFetchTool,
  },
})
```

該Tool需要一個`url` input and returns `content`, `truncated`, `status`, `statusText`, `contentType`, `url`, and `ok`. It applies these limits:

* 僅有的`http:` and `https:` URLs are allowed.
* 要求`localhost` and to private or reserved IP addresses are blocked, including addresses returned by DNS resolution.
* 響應被截斷為 100,000 個字符，其中`truncated: true` in the result.
* 請求最多遵循 5 次重定向，並在 15 秒後逾時。

失敗不會拋出。Tool返回`isError: true` with the reason in `content`, so the agent can retry or explain the problem.

### 向用戶提問 {/* #ask-the-user-a-question */}

進口[`askUserTool`](/reference/tools/ask-user-tool) and add it to the agent's toolset.

該Tool暫停運行並發出`tool-call-suspended` event with the question. It resumes when you call `resumeStream()` with the user's answer.

```typescript title="src/mastra/agents/index.ts"
import { Agent } from '@mastra/core/agent'
import { askUserTool } from '@mastra/core/tools'

const agent = new Agent({
  id: 'assistant',
  name: 'Assistant',
  instructions: 'Ask the user for clarification when the request is ambiguous.',
  model,
  tools: { askUserTool },
})
```

串流Agent並觀看`tool-call-suspended` chunks. The `suspendPayload` contains the question and optional structured choices:

```typescript title="src/run.ts"
const stream = await agent.stream('Summarize my project')

for await (const chunk of stream.fullStream) {
  if (chunk.type === 'tool-call-suspended') {
    const { question, options } = chunk.payload.suspendPayload
    console.log(question)
    const answer = await getUserAnswer() // your UI logic
    const resumed = await agent.resumeStream(answer, { runId: stream.runId })
    for await (const c of resumed.textStream) process.stdout.write(c)
  }
}
```

`askUserTool``options` array), and multi-select (`selectionMode: 'multi_select'`) prompts. Pair it with `autoResumeSuspendedTools` so the agent resumes automatically from the user's next chat message. See [Automatic tool resumption](/docs/agents/human-in-the-loop#automatic-tool-resumption) for details.

### 提交計劃供審查 {/* #submit-a-plan-for-review */}

進口[`submitPlanTool`](/reference/tools/submit-plan-tool) to let the agent write a plan to a file and submit it for user review. The tool suspends the run until the user approves or rejects:

```typescript title="src/run.ts"
for await (const chunk of stream.fullStream) {
  if (chunk.type === 'tool-call-suspended' && chunk.payload.toolName === 'submit_plan') {
    const { path } = chunk.payload.suspendPayload
    // Read and display the plan file, then resume:
    const resumed = await agent.resumeStream({ action: 'approved' }, { runId: stream.runId })
    for await (const c of resumed.textStream) process.stdout.write(c)
  }
}
```

### 任務追蹤 {/* #task-tracking */}

任务Tool管理Agent运行的结构化、持久的任务列表。他們需要[Memory](/docs/memory/overview) so the list is persisted in a thread-scoped store.

透過新增任務追蹤[`TaskSignalProvider`](/reference/signals/task-signal-provider), which bundles all four tools and the `TaskStateProcessor` in a single registration:

```typescript title="src/mastra/agents/index.ts"
import { Agent } from '@mastra/core/agent'
import { Memory } from '@mastra/memory'
import { TaskSignalProvider } from '@mastra/core/signals'

const agent = new Agent({
  id: 'coder',
  name: 'Coder',
  instructions: 'Track your progress with the task tools.',
  model,
  memory: new Memory(),
  signals: [new TaskSignalProvider()],
})
```

只能執行一項任務`in_progress` at a time. The list is stored in the thread-scoped `threadState` storage domain and projected onto the agent's [state-signal](/docs/signals/state-signals) lane, so it survives observational-memory truncation. See the [Task tools reference](/reference/tools/task-tools) for full schemas.

這[AgentController](/docs/harness/agent-controller) automatically includes all built-in tools in every mode, you don't need to add them manually. See [Tool approvals](/docs/harness/agent-controller#approve-tools-and-resume-suspensions) for AgentController-specific behavior.
