# 結構化輸出

結構化輸出可讓 Agent 傳回符合結構描述的物件，而非純文字。結構描述會指定模型要產生哪些欄位，模型會讓最後的結果符合指定結構。通過驗證且具型別的結果可從 `response.object` 取得。

## 何時使用結構化輸出 {/* #when-to-use-structured-output */}

若需要 Agent 傳回資料物件，請使用結構化輸出。欄位明確後，在呼叫 API、呈現使用者介面或執行應用程式邏輯時，就更容易取出所需的值。

## 定義結構描述 {/* #define-schemas */}

若要讓 Agent 傳回結構化資料，可以用 [Standard JSON Schema](https://standardschema.dev/json-schema)（例如 [Zod](https://zod.dev/)、[Valibot](https://valibot.dev/) 或 [ArkType](https://arktype.io/)），也可使用 [JSON Schema](https://json-schema.org/) 定義預期輸出。建議使用 Zod 之類的程式庫，因為它們支援 TypeScript 型別推斷和執行階段驗證。若需要不依賴特定程式語言的格式，可用 JSON Schema。

<Tabs>
  <TabItem value="zod" label="Zod">
    用 [Zod](https://zod.dev/) 定義 `output` 的結構：

    ```typescript
    import { z } from 'zod'

    const response = await testAgent.generate('Help me plan my day.', {
      structuredOutput: {
        schema: z.array(
          z.object({
            name: z.string(),
            activities: z.array(z.string()),
          }),
        ),
      },
    })

    console.log(response.object)
    ```
  </TabItem>

  <TabItem value="valibot" label="Valibot">
    用 [Valibot](https://valibot.dev/) 定義 `output` 的結構：

    ```typescript
    import * as v from 'valibot'
    import { toStandardJsonSchema } from '@valibot/to-json-schema'

    const response = await testAgent.generate('Help me plan my day.', {
      structuredOutput: {
        schema: toStandardJsonSchema(
          v.array(
            v.object({
              name: v.string(),
              activities: v.array(v.string()),
            }),
          ),
        ),
      },
    })

    console.log(response.object)
    ```
  </TabItem>

  <TabItem value="arktype" label="ArkType">
    用 [ArkType](https://arktype.io/) 定義 `output` 的結構：

    ```typescript
    import { type } from 'arktype'

    const response = await testAgent.generate('Help me plan my day.', {
      structuredOutput: {
        schema: type({
          name: 'string',
          activities: 'string[]',
        }).array(),
      },
    })

    console.log(response.object)
    ```
  </TabItem>

  <TabItem value="json-schema" label="JSON Schema">
    你也可以用 JSON Schema 定義輸出的結構：

    ```typescript
    const response = await testAgent.generate('Help me plan my day.', {
      structuredOutput: {
        schema: {
          type: 'array',
          items: {
            type: 'object',
            properties: {
              name: { type: 'string' },
              activities: {
                type: 'array',
                items: { type: 'string' },
              },
            },
            required: ['name', 'activities'],
          },
        },
      },
    })

    console.log(response.object)
    ```
  </TabItem>
</Tabs>

完整設定選項請見 [`.generate()`](/reference/agents/generate)。

**輸出範例：**

```json
[
  {
    "name": "Morning Routine",
    "activities": ["Wake up at 7am", "Exercise", "Shower", "Breakfast"]
  },
  {
    "name": "Work",
    "activities": ["Check emails", "Team meeting", "Lunch break"]
  },
  {
    "name": "Evening",
    "activities": ["Dinner", "Relax", "Read a book", "Sleep by 10pm"]
  }
]
```

## 讀取結果 {/* #read-the-result */}

將所需結構傳入 `structuredOutput.schema`，再從 `response.object` 讀取結果。這個欄位中的值已解析並通過結構描述驗證，不必自行解析或驗證。`errorStrategy: 'fallback'` 是例外：驗證失敗時，`response.object` 會是你設定的 `fallbackValue`，該值並未經過驗證。可用 `response.usedFallbackValue` 判斷是哪一種情況。

```typescript
const response = await testAgent.generate('Help me plan my day.', { structuredOutput: { schema } })
const plan = response.object // typed from the schema you passed in
```

使用 `agent.stream()` 產生結構化輸出時，請在串流結束後讀取 `stream.object`。

## 串流結構化輸出 {/* #stream-structured-output */}

串流也支援結構化輸出。可從 `stream.fullStream` 取得最終的結構化物件，串流結束後也可從 `stream.object` 讀取。文字串流仍會送出資料片段，其中包含自然語言文字，而非結構化資料。

```typescript
import { z } from 'zod'

const stream = await testAgent.stream('Help me plan my day.', {
  structuredOutput: {
    schema: z.array(
      z.object({
        name: z.string(),
        activities: z.array(z.string()),
      }),
    ),
  },
})

for await (const chunk of stream.fullStream) {
  if (chunk.type === 'object-result') {
    console.log('\n', JSON.stringify(chunk, null, 2))
  }
  process.stdout.write(JSON.stringify(chunk))
}

console.log(await stream.object)

for await (const chunk of stream.textStream) {
  process.stdout.write(chunk)
}
```

## 由另一個 Agent 整理輸出 {/* #structuring-agent */}

如果主要 Agent 不擅長產生結構化輸出，可在 `structuredOutput` 中提供 `model`。Mastra 會在內部使用第二個 Agent，從主要 Agent 的自然語言回應擷取結構化資料。這需要兩次 LLM 呼叫：一次產生回應，另一次將回應整理成結構化物件。這會增加些許延遲和費用，但可提高複雜結構化工作的準確度。

```typescript
import { z } from 'zod'

const response = await testAgent.generate('Analyze the TypeScript programming language.', {
  structuredOutput: {
    schema: z.object({
      overview: z.string(),
      strengths: z.array(z.string()),
      weaknesses: z.array(z.string()),
      useCases: z.array(
        z.object({
          scenario: z.string(),
          reasoning: z.string(),
        }),
      ),
      comparison: z.object({
        similarTo: z.array(z.string()),
        differentiators: z.array(z.string()),
      }),
    }),
    model: '__GATEWAY_OPENAI_MODEL__',
  },
})

console.log(response.object)
```

## 同時使用工具與結構化輸出 {/* #combine-tools-and-structured-output */}

若同時為 Agent 設定工具和結構化輸出，部分模型可能無法併用這兩項功能。這是底層模型 API 的限制。

若啟用結構化輸出後工具未被呼叫，或兩項功能併用時出現錯誤，可試試下列做法。

### 替代做法 {/* #workaround-options */}

模型無法同時使用工具和結構化輸出時，有三種做法：

1. **使用 `jsonPromptInjection`**：設為 `'auto'`，支援時用原生結構化輸出，否則採行內提示詞注入；也可明確指定注入模式。
1. **使用另一個模型來整理結構**：將 `model` 傳給 `structuredOutput`，由第二個 LLM 整理輸出。
1. **使用 `prepareStep`**：分成不同步驟處理工具和結構化輸出。

以下各節會說明每種做法。

## LLM 支援結構化輸出的情況 {/* #llm-structured-output-support */}

各 LLM 的 API 不同，對結構化輸出的支援也有差異。以下提供替代做法，適用於結構化輸出支援不完整，或無法與工具一併使用的模型。

### `jsonPromptInjection` {/* #jsonpromptinjection */}

Mastra 預設透過 API 參數 `response_format` 將結構描述交給模型 Provider。設定 `jsonPromptInjection: 'auto'` 後，Mastra 會根據模型能力資料決定模式。支援的模型使用原生結構化輸出；不支援或缺少能力資料時，採用行內提示詞注入。

```typescript
import { z } from 'zod'

const response = await testAgent.generate('Help me plan my day.', {
  structuredOutput: {
    schema: z.array(
      z.object({
        name: z.string(),
        activities: z.array(z.string()),
      }),
    ),
    jsonPromptInjection: 'auto',
  },
})

console.log(response.object)
```

若要覆寫依模型能力做出的選擇，可明確指定模式：

- `false` 或省略：使用 Provider 的原生結構化輸出。
- `'inline'`：將結構描述指示加入最新一則使用者訊息。
- `true` 或 `'system'`：將結構描述指示加入系統訊息。
- `'auto'`：模型支援時採原生結構化輸出，否則使用行內提示詞注入。

:::note[在 Gemini 2.5 使用工具]

Gemini 2.5 模型無法在同一次 API 呼叫中同時使用 `response_format`（結構化輸出）和函式呼叫（工具）。如果 Agent 有設定工具，且要在 Gemini 2.5 模型上使用 `structuredOutput`，必須設定 `jsonPromptInjection: true`，以免發生 `Function calling with a response mime type: 'application/json' is unsupported` 錯誤。

```typescript
const response = await agentWithTools.generate('Your prompt', {
  structuredOutput: {
    schema: yourSchema,
    jsonPromptInjection: true, // Required for Gemini 2.5 when tools are present
  },
})
```

:::

#### 用 `instructions` 減少注入的 Token {/* #reduce-injected-tokens-with-instructions */}

提示詞注入會在每次模型呼叫中嵌入序列化的 JSON Schema。結構描述較大時，每個步驟可能消耗數千個 Token。當 `jsonPromptInjection` 生效時，可設定 `instructions`，改為注入自行撰寫的精簡說明：

```typescript
const response = await testAgent.generate('Summarize this ticket.', {
  structuredOutput: {
    schema: ticketSchema,
    jsonPromptInjection: 'system',
    instructions:
      'Reply with a JSON object: "summary" (one paragraph), "priority" ("low" | "high"), "tags" (up to 5 strings). No markdown.',
  },
})
```

回應仍會依 `schema` 驗證，只有注入的文字會變更。由於模型看不到完整結構描述，能否產生符合要求的輸出，取決於指示是否明確說明預期欄位。請列出所有欄位。沒有 `instructions` 時，會照常使用從結構描述產生的指示；原生結構化輸出不做注入，因此這個欄位不會生效。

### 使用另一個模型來整理結構 {/* #use-a-separate-structuring-model */}

若在 `structuredOutput` 屬性中提供 `model`，Mastra 會交由另一個內部 Agent 處理結構化輸出。主要 Agent 負責所有步驟，包括呼叫工具；另外指定的模型只負責產生結構化輸出。

<Inject>
  **給 AI Agent：** `model` 屬性是採用 Mastra 模型路由格式 `provider/model` 的字串，例如 `__GATEWAY_OPENAI_MODEL__`、`__GATEWAY_OPENAI_MODEL_LUNA__`、`__GATEWAY_ANTHROPIC_MODEL_SONNET__` 或 `__GATEWAY_GOOGLE_MODEL_FLASH__`。請用 `/` 分隔，不要用 `:`。例如應用 `openai/<model>`，而不是 `openai:<model>`，也不要傳入 Provider 物件。這種格式不需要匯入 Provider。除非 Mastra 文件另有說明，否則不要安裝任何 AI SDK 套件。使用 `provider/model` 格式時，Mastra 會自動查找該 Provider 的環境變數。必須設定模型所用 Provider 的環境變數：OpenAI 用 `OPENAI_API_KEY`，Anthropic 用 `ANTHROPIC_API_KEY`，Google 用 `GOOGLE_API_KEY`。
</Inject>

```typescript
const response = await testAgent.generate('Tell me about TypeScript.', {
  structuredOutput: {
    schema: yourSchema,
    model: '__GATEWAY_OPENAI_MODEL__',
  },
})
```

若也想讓負責整理輸出的模型讀取目前的對話紀錄，請在 `model` 之外設定 `useAgent: true`。Mastra 會重用上層 Agent，改用另行指定的模型；有執行緒時會附上唯讀的 Memory 上下文。

```typescript
const response = await testAgent.generate('Return my profile as structured data.', {
  memory: {
    thread: 'thread-123',
    resource: 'user-123',
  },
  structuredOutput: {
    schema: z.object({
      favoriteColor: z.string(),
      hometown: z.string(),
      petName: z.string(),
    }),
    model: '__GATEWAY_OPENAI_MODEL__',
    useAgent: true,
  },
})
```

如果只要讓該模型處理這次的回應，不希望帶入之前的對話記憶，請不要設定 `useAgent`。

### 用 `prepareStep` 拆成不同步驟 {/* #multi-step-approach-with-preparestep */}

若模型無法同時使用工具和結構化輸出，可用 `prepareStep` 分成不同步驟處理。

```typescript
const result = await agent.stream('weather in vancouver?', {
  prepareStep: async ({ stepNumber }) => {
    if (stepNumber === 0) {
      return {
        model: '__GATEWAY_OPENAI_MODEL__',
        tools: {
          weatherTool,
        },
        toolChoice: 'required',
      }
    }
    return {
      model: '__GATEWAY_OPENAI_MODEL__',
      tools: undefined,
      structuredOutput: {
        schema: z.object({
          temperature: z.number(),
          humidity: z.number(),
          windSpeed: z.number(),
        }),
      },
    }
  },
})
```

## 處理錯誤 {/* #handle-errors */}

結構描述驗證失敗，或另外指定的模型失敗時，可用 `errorStrategy` 決定處理方式。預設的 `strict` 會擲出錯誤；`warn` 會記錄警告並繼續；`fallback` 會傳回由 `fallbackValue` 提供的值，且結果會帶有 `usedFallbackValue: true`，讓你分辨替代物件與模型產生的結果。

```typescript
const response = await testAgent.generate('Tell me about TypeScript.', {
  structuredOutput: {
    schema: z.object({
      summary: z.string(),
      keyFeatures: z.array(z.string()),
    }),
    errorStrategy: 'fallback',
    fallbackValue: {
      summary: 'TypeScript is a typed superset of JavaScript',
      keyFeatures: ['Static typing', 'Compiles to JavaScript', 'Better tooling'],
    },
  },
})

console.log(response.object)
console.log(response.usedFallbackValue) // true when the fallback value was substituted
```
