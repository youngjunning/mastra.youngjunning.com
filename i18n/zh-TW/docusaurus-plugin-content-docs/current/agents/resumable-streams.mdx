# 可恢復的串流

`observe()`，任何讀者都可以阻止它。

可恢復的流並不能使運作本身持久。重新連線不是崩潰復原：如果執行Agent程式的進程停止，則執行停止，觀察者會看到錯誤或僅看到其他內容。對於在進程重新啟動後仍然存在的運行，請使用[durable agents](/docs/harness/durable-agents), which publish through the same stream layer.

## 預設值 {/* #defaults */}

|Agent|流 |
| - | - |
|註冊於`Mastra` instance | On |
| Standalone (`new Agent()` without `Mastra`)|關閉 |
|普通Agent與`durable: true`|開啟，包括獨立Agent |
|普通Agent與`durable: false`|關閉，包括註冊Agent|
|顯式的`createDurableAgent()`包裝|始終發布；經過`cache: false`到工廠禁用重播緩存，而不是傳輸歷史記錄|

註冊Agent，無論是否持久，都會在`mastra.pubsub` and caches events in `mastra.serverCache`, or an in-memory cache when the server has none. Every `Mastra` instance that shares that PubSub and cache can observe the run. An agent-level `pubsub` takes precedence, except on the evented engine, whose steps always publish on `mastra.pubsub`.

## {/* #configure-streams */}

放`durable` on the agent to turn streams on or off, or to pass your own PubSub and cache:

```typescript title="src/mastra/agents/support-agent.ts"
import { Agent } from '@mastra/core/agent'

export const supportAgent = new Agent({
  id: 'support-agent',
  name: 'Support agent',
  instructions: 'You help customers with their orders.',
  model: '__GATEWAY_OPENAI_MODEL_BASE__',
  durable: {
    // Keep finished runs replayable for 2 minutes instead of 30 seconds
    cleanupTimeoutMs: 120_000,
  },
})
```

|選項 |預設 |說明 |
| - | - | - |
|`pubsub` | `mastra.pubsub` | Bus the run is published on. Use a shared bus to follow runs across processes. |
| `cache` | `mastra.serverCache`, else an in-memory cache | Replay cache. Pass `false` to disable this cache. Transports such as Redis Streams can still replay retained history. |
| `shouldCache` | Every topic | Return `false` for a topic to skip caching it. |
| `cleanupTimeoutMs` | `30000` | How long after it finishes a run is cleared. `0`僅關閉此計時器。快取本身的過期和驅逐仍然適用。 |

`durable: true`使用這些預設值開啟流，包括獨立Agent。

在平原上`Agent`, `durable` configures resumable streams only. For checkpoint-backed execution, wrap the agent explicitly with `createDurableAgent({ agent })`. To recover in-flight runs after a crash, also configure persistent workflow storage and `recovery: { durableAgents: 'auto' }`. For manual recovery instead, pass a `shouldPersistSnapshot` policy that includes `running` snapshots and call `recoverActiveRuns()` yourself. See [crash recovery](/docs/harness/durable-agents#crash-recovery) for setup and persistence policies.

`cache`, `pubsub`, `shouldCache`, and `cleanupTimeoutMs` options.

## 關閉流 {/* #turn-streams-off */}

流是有成本的。每個區塊都會發佈到 PubSub，並且在啟用快取的情況下，每個事件都會被存儲，直到運行被清理。記憶體中的快取就是進程記憶體。對於遠端 PubSub 或 Redis 等緩存，它是每個區塊的網路寫入。對於從不重新連接或觀察運行的大容量Agent，請關閉流：

```typescript title="src/mastra/agents/batch-agent.ts"
import { Agent } from '@mastra/core/agent'

export const batchAgent = new Agent({
  id: 'batch-agent',
  name: 'Batch agent',
  instructions: 'You classify support tickets.',
  model: '__GATEWAY_OPENAI_MODEL_BASE__',
  durable: false,
})
```

若要保持即時觀察但跳過重播緩存，請傳遞`durable: { cache: false }`.

### 運行時間可以保持多長時間 {/* #how-long-runs-stay-available */}

運行完成後，執行程序會安排清理其事件和所有權記錄`cleanupTimeoutMs`. The timer allows the process to exit before cleanup. Shared cache data then remains until expiry or eviction. Redis Streams retains its native topic data until `clearTopic()` succeeds or its idle TTL expires. The transport's default idle TTL is seven days. Configure `streamIdleTtlMs` to change it, or set it to `0` to disable transport expiry. A run parked on a tool approval or suspension isn't cleared by that timer, because resuming it continues on the same topic.

快取限制了其他一切：

* 運行日誌和所有權記錄向快取請求 24 小時 TTL。記憶體快取至少使用此 TTL 來儲存索引運行日誌，除非停用快取過期。快取條目限制可以更快地驅逐資料。
* 記憶體快取預設保存 1,000 個條目。每次運行都使用多個條目（其事件日誌、計數器及其所有權記錄），因此大流量會更快地驅逐較舊的運行。
* 當運行的所有權記錄被逐出或過期時，伺服器的觀察和中止路由傳回 404。無法重播已驅逐的運行事件。

當運行必須在伺服器之間保持可觀察性或需要長時間批准等待時，請使用根據您的流量調整大小的共用緩存，例如 Redis。

## {/* #follow-a-run */}

共用 PubSub 總線的Agent程式之間的運行 ID 必須是唯一的。

稱呼`observe()` with the run's ID to follow it from any agent instance that shares the bus. Without an offset, `observe()` replays the cached events and then delivers live ones. Replay needs the same replay cache too. An instance with its own cache receives only live events, unless the PubSub keeps history. When a run waits on a tool approval, the observation receives the approval request and stays open until the approved run finishes, errors or is aborted. Call `detach()` to stop following a parked run:

```typescript title="src/server/reconnect.ts"
import { supportAgent } from '../mastra/agents/support-agent'

export async function followRun(runId: string, request: Request) {
  const { output, detach } = await supportAgent.observe(runId)

  request.signal.addEventListener('abort', detach, { once: true })
  if (request.signal.aborted) detach()

  for await (const chunk of output.fullStream) {
    // Chunks from the run, including any missed while disconnected
  }
}
```

每個區塊來自`observe()` carries its run-log position as `chunk.index`. To resume an observation after a dropped connection, pass `index + 1` of the last chunk that has an index as `offset`. Chunks from a plain agent's `stream()`, and chunks delivered without a replay cache, carry no `index`, so a client that lost one of those connections should observe without an `offset`. The [`observe()` reference](/reference/agents/durable-agent#observerunid-options) covers which chunks carry no index, structured output, and replay limits.

透過 HTTP，觀察無法恢復的運行會失敗，而不是返回空流。未知的運行，或其所有權記錄過期或被驅逐的運行，回答 404，並且客戶端以`MastraClientError` carrying that status rather than resolving to an empty, closed stream.

`agent.hasResumableStreams()`報告該Agent是否發布其運行，以及是否與它們一起發布`observe()` and the server's observe and abort routes can reach them. It's `true` for a durable agent and for any agent with streams on.

### 直到空閒流 {/* #until-idle-streams */}

`streamUntilIdle()`和`resumeStreamUntilIdle()` combine the initial run and background-task continuations in their `fullStream`. Without an offset, `observe(returnedRunId)` replays only the initial segment and closes at its finish event. It doesn't reconnect to the combined until-idle stream or replay later background-task answers. Supplying an explicit run ID doesn't change this limit. The same limit applies to durable agents.

## 停止跑步 {/* #stop-a-run */}

當流打開時，關閉的讀取器不會停止運作。當客戶端與伺服器的流路由斷開連接時，伺服器會分離該讀取器並且運行繼續進行：它不斷生成令牌、調用Tool並運行`onFinish`, so the client can reconnect. Stop it explicitly, or set `durable: false` on a plain agent whose runs should end with the request. A durable agent's run always continues after a disconnect. A detached run still ends when it finishes, when it's stopped, or when its step budget is spent. With neither `maxSteps` nor `stopWhen` set, each loop stops after five steps, excluding processor retries. The budget applies per loop invocation, with a fresh loop after an approval or background continuation.

使用以下之一明確停止運作：

* `observe(runId)`返回一個`abort()` function that asks a running run to stop wherever it executes. The request is best effort. It doesn't wait for confirmation, and a failed publish is only logged. Use the abort route below when you need confirmation. A run parked on an approval no longer listens for it, so stop a parked run with the abort route below, or with `POST /agents/:agentId/threads/abort` for a run in a memory thread.
* `agent.abortRunStream(runId)`停止此進程中的運行，並要求在同一總線上的其他進程停止它。它返回`true` for a running run stopped in this process. A run parked on an approval outside a memory thread is cancelled here too, but the call returns `false`. A later approval in this process fails. The cancellation fence is process-local and leaves the shared snapshot intact. Another process can still approve that snapshot, so use the abort route below to stop a parked run in an app with more than one server. For a run elsewhere the request is best effort.
* 伺服器的`POST /agents/:agentId/runs/:runId/abort` route stops a run on any server that shares the PubSub and cache, after checking the caller owns it. It returns `{ aborted: true }` once the process executing the run confirms it stopped. For a run of a durable agent (`DurableAgent` or `createDurableAgent`, including evented agents) parked on an approval, the route also records the cancellation in storage and returns `{ aborted: true }` after that write is saved. A later approval or resume of that run is then refused with `409 Conflict` (`AGENT_RESUME_ABORTED_RUN`) on every server that shares the storage. If a resume claims the run first, no cancellation is recorded, and the route stops the resumed run like any running run. On storage adapters without concurrent updates, such as Redis, Valkey and LanceDB, an abort and an approval that arrive at the same moment aren't serialized, so an approval that overlaps the abort can still run its tool even though the abort returns `{ aborted: true }`. Wait for that response before relying on the recorded cancellation, which Inngest agents don't write. The route returns `{ aborted: false }` for a finished run, and when nothing stopped the run and no process answers in time. Runs in a memory thread can also be stopped with `POST /agents/:agentId/threads/abort`, but that route doesn't record the cancellation in storage, so use the run abort route to stop a parked durable run in an app with more than one server.

和`durable: false` on a non-durable agent, closing the HTTP request aborts the run, as before.

## 跨伺服器 {/* #across-servers */}

當多個伺服器共享 PubSub 和快取（例如 Redis）時，可以透過其中任何一個伺服器來觀察和停止在一台伺服器上啟動的運行：

* 每次運行都會在第一個事件之前將所有權記錄（Agent、運行、資源和執行緒）寫入快取。伺服器的觀察和中止路由會根據該記錄檢查呼叫者，因此每個伺服器上都會保留租用戶和執行緒檢查。
* 未知、過期或被逐出的記錄回傳 404。如果無法讀取緩存，路由將返回 503，而不是跳過檢查。
* 和`durable: { cache: false }` the record is kept in `mastra.serverCache`, so ownership still works across servers. Replay then depends on the PubSub: one that keeps history, like Redis Streams, replays it, and an in-process bus delivers only live events.
* 使用預設的記憶體快取和 PubSub，不會共享任何內容，因此只有運行Agent程式的伺服器才能觀察或停止其運行。
