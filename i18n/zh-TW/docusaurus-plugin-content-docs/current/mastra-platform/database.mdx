# 託管資料庫

可透過 CLI 或[平台](/docs/mastra-platform/overview)的專案設定佈建全託管資料庫，並將它連結至專案。Mastra 會在你選擇的供應商建立資料庫並安全保管憑證。資料庫就緒後，連線資訊會注入執行階段的環境變數，不必複製或設定連線字串。

```bash
mastra env db create --kind turso
```

## 何時使用託管資料庫 {/* #when-to-use-hosted-databases */}

如果專案需要由平台管理的持久儲存空間，可使用託管資料庫，例如：

- **Agent 記憶**：持久保存對話記錄與工作記憶，並支援跨工作階段的語意檢索。
- **應用程式資料**：儲存及擷取專案在執行時所需的關聯式或結構化資料。
- **向量搜尋**：儲存供檢索增強生成與語意搜尋使用的嵌入向量。

## 資料庫供應商 {/* #providers */}

目前可透過 Turso、Neon 和 Postgres 三家供應商使用託管資料庫，MongoDB 即將推出。連結資料庫時選擇其中一家，再在程式碼中把注入的變數交給對應的 Mastra 儲存配接器。

各供應商都會注入一組固定名稱的變數。例如，Neon 與 Postgres 都只注入 `DATABASE_URL`，Turso 則使用不同的 `TURSO_*` 變數。每個環境中的變數名稱不得重複，因此每個名稱最多只能對應一個資料庫。Neon 和 Postgres 都注入 `DATABASE_URL`，不能在同一環境並用。Turso 則可與其中任一種並用。

對多數以 Agent 為主的專案來說，**Turso** 最容易上手。它提供相容於 SQLite 的輕量引擎，適合 Agent 記憶、對話記錄及租戶隔離。若需要可從筆電、其他服務或遷移工具連線的公開無伺服器 Postgres，請選 **Neon**。若工作負載必須留在部署環境的私人網路，請選 **Postgres**：它與伺服器一同執行，且只有該伺服器可以連線。**MongoDB**（_即將推出_）會提供文件儲存與內建向量搜尋，適合不易對應至 SQL 的工作負載。

| 供應商 | 引擎 | 網路 | 適用情境 |
| - | - | - | - |
| **Turso** | LibSQL，相容於 SQLite | 公開 | Agent 記憶、租戶隔離 |
| **Neon** | 支援分支的無伺服器 Postgres | 公開 | 需從部署環境外部存取的關聯式工作負載 |
| **Postgres** | 託管 PostgreSQL | VPC（私人） | 必須留在部署環境私人網路中的關聯式工作負載 |
| **MongoDB** | 文件與向量搜尋 | _待定_ | 文件儲存、向量搜尋（_即將推出_） |

## 資料庫範圍 {/* #database-scope */}

連結資料庫時，可選擇下列兩種範圍之一：

- **環境範圍**：預設選項。資料庫只連結到一個環境，讓不同環境的資料彼此隔離，例如分別為正式與預備環境使用不同資料庫。專案只有一個環境時，`mastra env db create` 會自動選取；有多個環境時，CLI 會提示你選擇。
- **專案範圍**：專案的所有[環境](/docs/mastra-platform/environments)共用一個資料庫。使用 `--shared` 啟用，每次部署都會注入該資料庫的變數。

連結資料庫時會決定範圍，可用 `mastra env db list` 查看。

同一供應商的兩種範圍不可重疊。專案範圍的資料庫已向每個環境注入變數，因此再連結同一供應商的環境範圍資料庫，會因變數名稱衝突而遭拒。若要從共用資料庫改成各環境有自己的資料庫，請先刪除專案範圍的資料庫，再逐一連結各環境的資料庫。刪除資料庫會一併刪除供應商端的資料庫及所有資料，切換前請先匯出要保留的內容。不同環境各自的資料庫不會衝突，每次部署只會收到該環境的變數。

## 透過 CLI 連結資料庫 {/* #attach-with-the-cli */}

不必事先執行這個指令。如果專案需要託管資料庫，但目前還沒有，`mastra deploy` 會在部署前檢查時詢問是否要連結資料庫。選擇同意後，就能留在 CLI 繼續部署。如果組織可以使用 Neon 和 Postgres，而缺少的變數是 `DATABASE_URL`，提示會讓你選擇要佈建哪一種。

也可事先建立並連結資料庫。CLI 會輪詢狀態直到資料庫就緒，大約需要幾秒：

```bash
# Scoped to a single environment (the CLI picks the only one, or prompts if there are several)
mastra env db create --kind turso

# Scoped to a specific environment
mastra env db create staging --kind turso

# Shared by all environments
mastra env db create --kind turso --shared
```

支援 `turso`、`neon`（公開的無伺服器 Postgres）與 `postgres`（以 VPC 隔離的 Postgres）。常用選項如下：

- `--shared`：連結所有環境共用的專案範圍資料庫。不得與環境引數並用。
- `--name <name>`：資料庫名稱。預設由專案 slug 產生。
- `--region <region>`：專案範圍資料庫的供應商區域 ID，例如 `fra`。環境範圍的資料庫會自動配置在環境所在區域附近，明確提供的 `--region` 會被忽略。
- `--no-wait`：立即回傳，不等待輪詢結果。稍後可用 `mastra env db show` 查看進度。
- `--json`：輸出機器可讀的結果。專案有多個環境時，`--json` 須搭配環境引數或 `--shared`，不會顯示互動提示。

查看及管理已連結的資料庫：

```bash
mastra env db list
mastra env db show <database>
mastra env db delete <database>
```

`mastra env db list` 會顯示各資料庫的類型、狀態、範圍及注入的變數名稱。`mastra env db show` 會印出連線說明，並遮蔽機密值。若要查看這些值，請傳入 `--show-secrets`。`mastra env db delete` 會永久刪除供應商端的資料庫及所有資料。建立或刪除資料庫須具備組織的管理員角色。

## 從專案設定連結資料庫 {/* #attach-from-project-settings */}

<Steps>
  <StepItem>
    在[平台](/docs/mastra-platform/overview)開啟專案，前往 **Project Settings**。
  </StepItem>

  <StepItem>
    開啟 **Database** 區段，然後選取 **Add database**。
  </StepItem>

  <StepItem>
    選擇**供應商**（Turso、Neon 或 Postgres）。連結前還可以更換。
  </StepItem>

  <StepItem>
    設定資料庫：

    - **Name**：專案中用於識別此資料庫的標籤。
    - **Region**：資料庫的託管區域。請選擇最接近使用者的區域。Turso 預設為 `sjc`（聖荷西），全球有 20 多個據點可用。Neon 預設為 `aws-us-west-2`，可選擇位於美國、歐盟及亞太地區的 AWS 與 Azure 區域。Postgres 在部署所在的同一個私人網路執行，區域與環境的 Railway 區域一致（美國、歐盟或亞太地區）。
  </StepItem>

  <StepItem>
    選取 **Attach database**。資料庫會在背景佈建，一開始為 `provisioning`，供應商完成設定後會變為 `ready`。連線資訊會自動注入專案，作為伺服器執行階段的環境變數。
  </StepItem>
</Steps>

從專案設定連結的資料庫採用專案範圍。若要連結環境範圍的資料庫，請使用 [CLI](#attach-with-the-cli)。

## 從程式碼連線到資料庫 {/* #connect-from-your-code */}

在 **Project Settings → Database** 查看資料庫狀態。背景設定期間，已連結的資料庫會顯示 `provisioning`。狀態變成 `ready` 時，平台已將連線資訊注入為受管理的環境變數。

開啟狀態為 `ready` 的資料庫，即可查看這些變數與程式碼片段。請參考下方範例，用變數設定 Mastra 儲存配接器。

### 圖爾索 (LibSQL) {/* #turso-libsql */}

Turso 提供兩個環境變數：`TURSO_DATABASE_URL` 與 `TURSO_AUTH_TOKEN`。下方範例會用這些變數為 [LibSQLStore](/integrations/databases/libsql) 建立連線。

```ts title="src/mastra/storage.ts" caption="Connect a Turso (LibSQL) database"
import { LibSQLStore } from '@mastra/libsql'

export const storage = new LibSQLStore({
  id: 'mastra-storage',
  url: process.env.TURSO_DATABASE_URL!,
  authToken: process.env.TURSO_AUTH_TOKEN!,
})
```

安裝配接器：

```bash npm2yarn
npm install @mastra/libsql@latest
```

### Neon 與 Postgres {/* #neon-and-postgres */}

Neon（公開的無伺服器資料庫）與 Postgres（以 VPC 隔離）都只提供一個 `DATABASE_URL` 連線字串，因此兩者可使用相同的 [PostgresStore](/integrations/databases/postgresql) 程式碼。同一環境只能選用其中一種。

```ts title="src/mastra/storage.ts" caption="Connect a Neon or Postgres database"
import { PostgresStore } from '@mastra/pg'

export const storage = new PostgresStore({
  connectionString: process.env.DATABASE_URL!,
})
```

安裝配接器：

```bash npm2yarn
npm install @mastra/pg@latest
```

只有已部署的伺服器能存取以 VPC 隔離的 Postgres，本機開發時無法直接連線。開發時可將 `DATABASE_URL` 指向本機的 Postgres 或 Neon 分支，部署時再由平台注入受管理的值。

將 `storage` 執行個體傳入 `Mastra` 設定，讓 Agent、Memory 和 Workflow 都能使用：

```ts title="src/mastra/index.ts"
import { Mastra } from '@mastra/core'
import { storage } from './storage'

export const mastra = new Mastra({
  storage,
})
```

## 環境變數 {/* #environment-variables */}

每個供應商都會注入一組固定的受管理環境變數。資料庫狀態為 `ready` 後，專案便能在執行階段取用這些變數，不必自行定義。

| 提供商 | 变量 |
| - | - |
|圖爾索 |`TURSO_DATABASE_URL`, `TURSO_AUTH_TOKEN` |
| Neon | `DATABASE_URL` |
| Postgres | `DATABASE_URL` |

:::警告
請將連線憑證視為機密。驗證權杖（`TURSO_AUTH_TOKEN`）與 Postgres 連線字串（`DATABASE_URL`）都能授予完整的資料存取權限。平台預設會遮蔽這些值，只在你要求時顯示。
:::

## 管理資料庫 {/* #manage-a-database */}

- **查看連線資訊**：在專案設定中開啟狀態為 `ready` 的資料庫，即可查看其環境變數，以及可直接複製貼上的程式碼片段。
- **刪除**：從專案移除資料庫會刪除供應商端的資料庫，並清除注入的環境變數。此操作無法復原，請先確認不再需要這些資料。
