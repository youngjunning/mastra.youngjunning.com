# 託管資料庫

[platform](/docs/mastra-platform/overview)項目設定並將其附加到您的項目。 Mastra 與您的Provider一起建立它並安全地儲存憑證，並在資料庫準備就緒時將連接詳細資訊作為運行時環境變數注入，因此無需複製或配置連接字串。

```bash
mastra env db create --kind turso
```

## 何時使用託管資料庫 {/* #when-to-use-hosted-databases */}

當您的專案需要由平台管理的持久性儲存時，請使用託管資料庫，包括：

* **Agent記憶**：保留對話歷史和工作記憶，以及跨會話的語意回憶。
* **應用資料**：儲存和檢索專案執行時所需的關係或結構化資料。
* **向量搜尋**：儲存用於檢索增強生成和語義搜尋的嵌入。

## Provider {/* #providers */}

目前，託管資料庫可透過三個Provider取得：Turso、Neon 和 Postgres，MongoDB 即將推出。附加資料庫時選擇一個，然後將其註入的變數連接到程式碼中符合的 Mastra 儲存適配器。

每個Provider都會注入一組固定的變數名稱，例如，一個`DATABASE_URL` for both Neon and Postgres and separate `TURSO_*` variables for Turso. Those names must be unique within each environment, so a single environment can use at most one database per variable name. Because Neon and Postgres both inject `DATABASE_URL`, they're mutually exclusive within the same environment. Turso can be attached alongside either one.

對於大多數以Agent為中心的項目，**Turso** is the simplest starting point. It provides a lightweight, SQLite-compatible engine well suited to agent memory, conversation history, and per-tenant isolation. Choose **Neon** when you want a public, serverless Postgres you can reach from your laptop, other services, or a migration tool. Choose **Postgres** when your workload needs to stay on your deployment's private network: it runs alongside your server and is only reachable from it. **MongoDB** (*coming soon*) will add document storage and built-in vector search for workloads that don't map cleanly to SQL.

|供应商|发动机|网络|最适合 |
| - | - | - | - |
|**Turso** | LibSQL, SQLite-compatible | Public | Agent memory, per-tenant isolation |
| **Neon** | Serverless Postgres with branching | Public | Relational workloads reachable from outside your deployment |
| **Postgres** | Managed PostgreSQL | VPC (private) | Relational workloads that must stay on your deployment's private network |
| **MongoDB** | Document and vector search | *TBD* | Document storage, vector search (*coming soon*) |

## 資料庫範圍 {/* #database-scope */}

資料庫附加在兩個範圍之一：

* **環境範圍**:預設.連接到單一環境，以便資料在環境之間保持隔離（例如單獨的生產資料庫和登台資料庫）。當你的專案只有一個環境時，`mastra env db create` picks it automatically; with several, the CLI prompts you to select one.
* **專案範圍**：一個資料庫由所有項目共享[environments](/docs/mastra-platform/environments). Opt in with `--shared`. Its variables are injected into every deploy.

範圍是在附加資料庫時設定的，並顯示在`mastra env db list`.

同一Provider的範圍不能重疊。由於專案範圍的資料庫已將其變數注入到每個環境中，因此附加相同Provider的環境範圍的資料庫會因變數名稱衝突而被拒絕。若要從共用資料庫移至每個環境的資料庫，請先刪除項目範圍的資料庫，然後為每個環境附加一個資料庫。刪除資料庫會破壞它以及Provider及其所有數據，在切換範圍之前導出您需要保留的任何內容。不同環境中的環境範圍資料庫永遠不會衝突，每個部署僅接收其自己環境的變數。

## 使用 CLI 附加 {/* #attach-with-the-cli */}

您不必預先執行此命令。如果您的專案需要託管資料庫但還沒有，`mastra deploy` offers to attach one for you when the deploy preflight check runs. Say yes and the deploy continues without leaving the CLI. When both Neon and Postgres are available for your organization and the missing variable is `DATABASE_URL`, the prompt lets you choose which one to provision.

或者，提前建立並附加資料庫。 CLI 會進行輪詢，直到準備就緒，這需要幾秒鐘的時間：

```bash
# Scoped to a single environment (the CLI picks the only one, or prompts if there are several)
mastra env db create --kind turso

# Scoped to a specific environment
mastra env db create staging --kind turso

# Shared by all environments
mastra env db create --kind turso --shared
```

支援的種類有`turso`, `neon` (public serverless Postgres), and `postgres` (VPC-isolated Postgres). Useful flags:

* `--shared`：附加每個環境共享的項目範圍資料庫。不能與環境參數結合使用。
* `--name <name>`: 資料庫名稱。默认为从项目 slug 派生的名称。
* `--region <region>`：項目範圍資料庫的Provider區域 ID（例如`fra`). Environment-scoped databases are placed near the environment's region automatically, and an explicit `--region` is ignored.
* `--no-wait`：立即返回而不是輪詢。稍後檢查進度`mastra env db show`.
* `--json`：機器可讀的輸出。當專案有多個環境時，`--json` requires an environment argument or `--shared` (no interactive prompt).



```bash
mastra env db list
mastra env db show <database>
mastra env db delete <database>
```

`mastra env db list`顯示每個資料庫的種類、狀態、範圍和注入的變數名稱。`mastra env db show` prints connection instructions with secret values masked. Pass `--show-secrets` to reveal them. `mastra env db delete` permanently deletes the database and all of its data with the provider. Creating and deleting databases requires the admin role in your organization.

## 從項目設定附加 {/* #attach-from-project-settings */}

<Steps>
  <StepItem>
    在中開啟您的項目[platform](/docs/mastra-platform/overview) and go to **Project Settings**.
  </StepItem>

  <StepItem>
    打開**Database** section, then select **Add database**.
  </StepItem>

  <StepItem>
    選擇一個**provider** (Turso, Neon, or Postgres). You can switch providers before attaching.
  </StepItem>

  <StepItem>
    配置資料庫：

    * **姓名**：項目中資料庫的標籤。
    * **地區**：資料庫所在的位置。選擇最接近您的使用者的區域。圖爾索預設值`sjc` (San Jose) and is available in 20+ locations worldwide. Neon defaults to `aws-us-west-2` and is available across AWS and Azure regions in the US, EU, and APAC. Postgres runs on the same private network as your deployment. Its region follows the environment's Railway region (US, EU, or APAC).
  </StepItem>

  <StepItem>
    選擇**Attach database**. Provisioning runs in the background. The database starts in a `provisioning` state and moves to `ready` once the provider finishes setup. Connection details are injected into your project as server runtime environment variables automatically.
  </StepItem>
</Steps>

從項目設定附加的資料庫是項目範圍的。使用[CLI](#attach-with-the-cli) to attach an environment-scoped database.

## 從您的程式碼連接 {/* #connect-from-your-code */}

檢查資料庫狀態**Project Settings → Database**. An attached database shows `provisioning` while setup runs in the background. Once it's `ready`, the platform has injected its connection details as managed environment variables.

打開一個`ready` database to view those variables and a code snippet. Use the variables to configure a Mastra storage adapter, as shown below.

### 圖爾索 (LibSQL) {/* #turso-libsql */}

Turso公開了兩個環境變數：`TURSO_DATABASE_URL` and `TURSO_AUTH_TOKEN`. The following example connects a [LibSQLStore](/integrations/databases/libsql) using those variables.

```ts title="src/mastra/storage.ts" caption="Connect a Turso (LibSQL) database"
import { LibSQLStore } from '@mastra/libsql'

export const storage = new LibSQLStore({
  id: 'mastra-storage',
  url: process.env.TURSO_DATABASE_URL!,
  authToken: process.env.TURSO_AUTH_TOKEN!,
})
```

安裝適配器：

```bash npm2yarn
npm install @mastra/libsql@latest
```

### Neon 和 Postgres {/* #neon-and-postgres */}

Neon（公共無伺服器）和 Postgres（VPC 隔離）都公開一個`DATABASE_URL` connection string, so the same [PostgresStore](/integrations/databases/postgresql) code works for either. An environment can have one or the other, not both.

```ts title="src/mastra/storage.ts" caption="Connect a Neon or Postgres database"
import { PostgresStore } from '@mastra/pg'

export const storage = new PostgresStore({
  connectionString: process.env.DATABASE_URL!,
})
```

安裝適配器：

```bash npm2yarn
npm install @mastra/pg@latest
```

VPC 隔離的 Postgres 只能從部署的伺服器訪問，因此本地開發無法直接連接到它。觀點`DATABASE_URL` at a local Postgres (or a Neon branch) during development, then let the platform inject the managed value at deploy time.

透過`storage` instance to your `Mastra` configuration so agents, memory, and workflows can use it:

```ts title="src/mastra/index.ts"
import { Mastra } from '@mastra/core'
import { storage } from './storage'

export const mastra = new Mastra({
  storage,
})
```

## 環境變數 {/* #environment-variables */}

每個Provider都會注入一組固定的託管環境變數。當資料庫處於運行時，這些可用於您的項目`ready`. You don't define them yourself.

|Provider|變數|
| - | - |
|圖爾索 |`TURSO_DATABASE_URL`, `TURSO_AUTH_TOKEN` |
| Neon | `DATABASE_URL` |
| Postgres | `DATABASE_URL` |

:::警告
將連線憑證視為機密。身份驗證令牌 (`TURSO_AUTH_TOKEN`) and the Postgres connection string (`DATABASE_URL`) grant full access to your data. The platform masks them by default and only reveals them on request.
:::

## 管理資料庫 {/* #manage-a-database */}

* **查看連接詳細信息**: 打開一個`ready` database in your project settings to see its environment variables and a copy-pasteable code snippet.
* **刪除**：從項目中刪除資料庫會隨Provider一起刪除該資料庫並清除其註入的環境變數。這是不可逆轉的，因此請確保您不再需要該數據。
