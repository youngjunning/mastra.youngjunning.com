# 工作空間

Workspace 是 Mastra 平台在部署時配置並提供給 Agent 的一組執行階段資源。每個環境有自己的 Workspace，讓 `production` 與 `staging` 保持隔離。

每個 Workspace 提供下列兩種資源：

- 由 [`PlatformFilesystem`](/reference/workspace/platform-filesystem) 封裝的**儲存貯體**，供檔案系統使用。貯體會持久保存該環境的資料，Agent 可在不同次執行中讀寫。
- 一組由 [`PlatformSandbox`](/reference/workspace/platform-sandbox) 封裝的**隨需沙箱**，供執行指令使用。各 `PlatformSandbox` 執行個體會在 `start()` 時佈建自己的遠端沙箱，並在 `destroy()` 時銷毀。Agent 通常在同一工作階段中依任務啟動多個沙箱，用完後釋放。

Workspace 的範圍限於單一[環境](/docs/mastra-platform/environments)，所以 `production` 與 `staging` 不會共用儲存貯體或沙箱集區。平台負責佈建資源、驗證身分與清理閒置資源。

## 何時佈建 Workspace {/* #when-workspaces-are-provisioned */}

新專案預設啟用 Workspace。建立環境時，平台會自動佈建儲存貯體，並在背景預熱沙箱的基底映像，加快首次呼叫 `PlatformSandbox` 的啟動速度。

現有專案若尚未啟用這項功能，可在 Workspaces 分頁選取 **Enable workspaces**，為各環境佈建儲存貯體。

若環境佈建失敗，例如沙箱供應商負載過高，Workspaces 分頁會顯示失敗狀態及重試選項。環境仍會建立，只有 Workspace 在重試前無法使用。

## 在程式碼中使用 Workspace {/* #use-the-workspace-from-your-code */}

安裝 Provider 套件：

```bash npm2yarn
npm install @mastra/platform-workspace
```

將 Provider 組合成 Workspace，再向 Mastra 註冊：

```typescript title="src/mastra/workspace.ts"
import { Workspace } from '@mastra/core/workspace'
import { PlatformFilesystem, PlatformSandbox } from '@mastra/platform-workspace'

export const workspace = new Workspace({
  filesystem: new PlatformFilesystem(),
  sandbox: new PlatformSandbox(),
})
```

```typescript title="src/mastra/index.ts"
import { Mastra } from '@mastra/core'
import { workspace } from './workspace'

export const mastra = new Mastra({
  workspace,
})
```

`PlatformFilesystem` 和 `PlatformSandbox` 會從環境變數讀取設定，在平台上不必傳入選項。部署時平台會注入變數。請參閱[環境變數](#environment-variables)。

## 單一儲存貯體與多個沙箱 {/* #one-bucket-many-sandboxes */}

設計 Agent 時，請留意 `PlatformFilesystem` 與 `PlatformSandbox` 的生命週期不同。

**`PlatformFilesystem` 可持續存取環境的儲存貯體。** 使用它的請求與 Agent 都讀寫同一個物件儲存空間。除非明確刪除，Agent 寫入的資料在下次請求時仍看得到。

**`PlatformSandbox` 是佈建暫時沙箱的用戶端。** 每個 `PlatformSandbox` 執行個體各自管理一個遠端沙箱：

- `start()` 會佈建新沙箱；若有傳入 `sandboxId`，則重新連線至原有沙箱。
- `executeCommand()` 在沙箱中執行指令。
- `stop()` 會釋放目前程序的租約，遠端沙箱不受影響。虛擬機器會依環境的閒置政策繼續運作，之後呼叫 `start()` 時可傳入儲存的 `sandboxId` 重新連線。若只沿用相同的 `id`，就會建立新沙箱；該 `id` 若有復原檢查點，便用它初始化新沙箱。
- `destroy()` 會釋放虛擬機器。在 Railway 上，也會刪除呼叫端提供的復原 `id` 所對應的檢查點。在 E2B 上，只會終止虛擬機器，你擷取的快照仍由你管理。

採用同一份靜態設定的請求與 Agent 會共用一個 `PlatformSandbox`，不會針對個別請求或記憶執行緒建立沙箱。`PlatformFilesystem` 是獨立的 Provider；同時設定兩者也不會把環境的儲存貯體掛載到沙箱內。

Agent 若需要另一個隔離環境，例如為個別任務分配沙箱、按使用者區分租戶，或避免背景工作碰到共用的 shell 狀態，請另外建立 `PlatformSandbox`：

```typescript title="src/mastra/tools/run-in-fresh-sandbox.ts"
import { PlatformSandbox } from '@mastra/platform-workspace'

export async function runInFreshSandbox(command: string) {
  const sandbox = new PlatformSandbox()
  await sandbox.start()
  try {
    return await sandbox.executeCommand(command)
  } finally {
    await sandbox.destroy()
  }
}
```

也可用已設定的沙箱當範本，複製出一批沙箱。複本會繼承憑證、環境、網路隔離及預設值，不必逐一設定：

```typescript
const template = new PlatformSandbox({ networkIsolation: 'PRIVATE' })

const perProjectSandbox = template.clone({ id: `project-${projectId}` })
await perProjectSandbox.start()
```

完整生命週期、檢查點復原、重新連線和複製選項，請參閱 [`PlatformSandbox` 參考文件](/reference/workspace/platform-sandbox)。

## 環境變數 {/* #environment-variables */}

部署到設有 Workspace 的平台環境時，會自動取得下列變數：

| 變數 | 說明 |
| - | - |
| `MASTRA_PLATFORM_ACCESS_TOKEN` | 平台簽發的 JSON Web Token (JWT)，供 Workspace Provider 驗證身分，適用範圍限於部署所屬的組織及專案。 |
| `MASTRA_PROJECT_ID` | 部署所屬的專案。 |
| `MASTRA_ENVIRONMENT_ID` | 部署所屬的環境，決定平台使用的沙箱集區。 |
| `MASTRA_PLATFORM_BUCKET_NAME` | 環境所連結的儲存貯體名稱，決定 `PlatformFilesystem` 讀寫哪個貯體。 |

上述名稱是保留名稱。即使專案明確設定同名變數，仍以平台管理的值為準。

## 本機開發 {/* #local-development */}

把這四個變數寫入本機的 `.env` 檔案，就能沿用相同的 Provider。專案、環境與儲存貯體的值可在專案的 **Workspaces** 分頁取得。至於 `MASTRA_PLATFORM_ACCESS_TOKEN`，請在組織設定的 **API Tokens** 建立 `sk_` API 權杖。部署到平台時會改用注入的 JWT。

```bash title=".env"
MASTRA_PLATFORM_ACCESS_TOKEN=sk_your-api-token
MASTRA_PROJECT_ID=your-project-id
MASTRA_ENVIRONMENT_ID=your-environment-id
MASTRA_PLATFORM_BUCKET_NAME=your-bucket-name
```

`PlatformFilesystem` 和 `PlatformSandbox` 在本機與平台上的行為相同，會連到該環境的同一個儲存貯體與沙箱集區。如果要隔離正式環境的資料，請在本機執行時使用 `staging` 或 `preview` 的變數。

若要在完全不連線至平台的情況下開發，可在本機建置時改用 [`LocalFilesystem`](/reference/workspace/local-filesystem) 和 [`LocalSandbox`](/reference/workspace/local-sandbox)。

## 查看 Workspace {/* #inspect-the-workspace */}

平台專案的 Workspaces 分頁依環境顯示：

- 儲存貯體的狀態和內容，並提供上傳、下載及刪除操作。
- 最近的沙箱工作階段，以及各自的指令、結束代碼與執行時間。
- 資源佈建失敗的狀態，可選取 **Retry** 重試。
