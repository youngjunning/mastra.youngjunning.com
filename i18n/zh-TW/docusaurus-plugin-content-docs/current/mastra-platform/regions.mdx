# 區域

區域決定平台環境的執行位置、[託管資料庫](/docs/mastra-platform/database)的部署位置，以及可觀測性資料的儲存位置。建立環境時就會確定區域，之後無法變更。

Mastra Platform 目前提供 `us` 與 `eu` 兩個資料落地範圍，對應到 Railway 的特定運算區域。資料庫與可觀測性服務會自動依環境區域配置。

## 選擇區域 {/* #choose-a-region */}

建立環境或首次部署至該環境時，請傳入 `--region`。

```bash
mastra deploy --env production --region eu
mastra env create staging --region us
```

`mastra deploy --region` 和 `mastra env create --region` 都接受 `us` / `eu` 簡寫，或下表所列的正式 Railway 區域代碼。建議使用簡寫。

未指定區域時，預設使用 `us`，對應到奧勒岡州波特蘭的 `pdx`。

## 可用區域 {/* #available-regions */}

資料落地選擇器列出兩個地理範圍內的四個 Railway 區域。簡寫 `us` 與 `eu` 各自對應到該範圍的預設區域。

| 地理範圍 | Railway 代碼 | 位置 |
| - | - | - |
| `us` | `pdx`（預設） | 奧勒岡州波特蘭 |
| `us` | `iad` | 維吉尼亞州阿什本 |
| `us` | `sfo` | 加州舊金山 |
| `eu` | `ams`（預設） | 荷蘭阿姆斯特丹 |

若需將環境固定在特定資料中心，請直接傳入 Railway 區域代碼。傳入 `us` 會選擇 `pdx`，傳入 `eu` 會選擇 `ams`。

:::note
部署流程還有其他 Railway 區域，例如新加坡（`sin`）。由於託管資料庫與可觀測性服務尚未在美國和歐盟以外提供就近部署，這些區域暫時不會出現在選擇器中。若傳入無法辨識的區域，平台會改用美國的預設區域。
:::

## 託管資料庫的部署位置 {/* #hosted-database-placement */}

連結[環境範圍的資料庫](/docs/mastra-platform/database)時，平台會選擇供應商最靠近該環境的區域。這項決定由伺服器作出，因此即使對 `mastra env db create <env>` 指定 `--region`，仍會以環境區域為準。

| 環境區域 | Turso 區域 | Postgres（Neon）區域 |
| - | - | - |
| `pdx` | `sjc`（聖荷西） | `aws-us-west-2`（奧勒岡州） |
| `iad` | `iad`（阿什本） | `aws-us-east-1`（北維吉尼亞） |
| `sfo` | `sjc`（聖荷西） | `aws-us-west-2`（奧勒岡州） |
| `ams` | `ams`（阿姆斯特丹） | `aws-eu-central-1`（法蘭克福） |

專案範圍的資料庫可由多個環境共用，不受單一環境限制，因此可以明確指定 `--region`。請使用供應商的區域 ID，避免使用 `us` / `eu` 簡寫。

```bash
mastra env db create --kind turso --region fra
mastra env db create --kind neon --region aws-us-east-1
```

Turso 提供超過 20 個區域，Postgres（Neon）則涵蓋 AWS 和 Azure 在美國、歐盟及亞太的多個區域。完整清單請參閱 [Turso 區域清單](https://docs.turso.tech/features/data-edge#locations)與 [Neon 區域清單](https://neon.com/docs/introduction/regions)。若傳入供應商未提供的代碼，連結資料庫時會失敗，並傳回供應商的錯誤。

## 可觀測性資料的區域路由 {/* #observability-co-location */}

目前有兩個可觀測性資料收集區域，分別位於**美國**（愛荷華州，`us-central1`）與**歐盟**（阿姆斯特丹）。各環境的 Trace、日誌及指標會送往與資料落地範圍相符的收集區域。

| 環境區域 | 可觀測性資料收集區域 |
| - | - |
| `pdx`、`iad`、`sfo`、簡寫 `us` | 美國（愛荷華州） |
| `ams`、簡寫 `eu` | 歐盟（阿姆斯特丹） |

Railway 和資料庫供應商提供的區域比可觀測性資料收集區域多，因此某些組合無法部署在同一地點。`us` 範圍內的環境一律將遙測資料送往美國收集端，`eu` 範圍內的環境則送往歐盟收集端。即使 Railway 區域所在的城市沒有專用收集端點，也會依照這項規則傳送。資料仍保留在各自的地理範圍內，`eu` 環境的遙測資料不會傳至美國。
