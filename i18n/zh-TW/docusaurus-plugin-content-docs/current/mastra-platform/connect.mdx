# Connect

:::beta 公开测试

公開測試期間，可在 Mastra 平台免費使用 Mastra Connect。

:::

Connect 可在 [Mastra 平台](/docs/mastra-platform/overview)專案中管理 GitHub、Slack、Linear 等服務的連線。`@mastra/connect` 套件提供三種方式，讓應用程式使用這些連線：

- **工具** 讓 Agent 呼叫服務商的 API。Connect 提供現成工具，並將工具請求送往平台代理。代理會加上憑證並更新 OAuth 權杖。
- **頻道** 讓使用者透過 Slack、Telegram、Discord 或 Microsoft Teams 與 Agent 對話。Connect 會提供憑證給 Mastra 的[頻道](/docs/channels) Provider。
- **原始憑證** 適用於現有工具無法滿足需求時，讓程式碼直接呼叫服務商的 SDK。

本頁說明各服務商共用的設定。個別連線步驟及功能請參閱各服務商的[整合頁面](#providers)。

## 何时使用 Connect {/* #when-to-use-connect */}

若要將服務商帳號交由平台管理，可使用 Connect，應用程式就不用儲存憑證或更新 OAuth 權杖。新增或替換連線時無須修改 Agent 程式碼。工具解析器會在快取重新整理時取得連線異動，無須重新部署。

Connect 需要平台專案，但應用程式可以在本機或自己的基礎架構執行。Connect 工具與頻道可和[自訂工具](/docs/agents/tools)、[自行管理的頻道](/docs/channels)一起使用。

## 連線的運作方式 {/* #how-connections-work */}

**服務商**是可連線的服務，以 `linear` 或 `google-mail` 等 ID 識別。每條**連線**會授權該服務的一個帳號。連線屬於組織，可將同一條連線連結到多個專案，無須重新授權。

同一專案可以有同一服務商的多條連線，例如連到不同 Slack 工作區的帳號。請為各條連線取不同的顯示名稱，讓 Agent 能選對帳號。

各服務商提供的功能及授權方式不同。有些使用 OAuth，有些需要 API 金鑰，頻道也可能需要在廠商的主控台設定機器人或應用程式。各服務商的整合頁面列有相關要求。

## 开始使用 {/* #get-started */}

您需要一個 Mastra 平台專案，以及已透過 `mastra auth login` 登入的 [`mastra` CLI](/reference/cli/mastra)。

### 安装软件包 {/* #install-the-package */}

```bash npm2yarn
npm install @mastra/connect
```

### 配置环境 {/* #configure-the-environment */}

應用程式使用存取權杖向平台驗證身分。請為應用程式建立權杖：

```bash
mastra auth tokens create my-app
```

請將權杖儲存為 `MASTRA_PLATFORM_ACCESS_TOKEN`，這是 `@mastra/connect` 讀取的變數名稱。CLI 建議使用 `MASTRA_API_TOKEN`，但 `@mastra/connect` 會忽略該名稱。請在應用程式的環境變數中加入權杖和專案 ID：

```bash title=".env"
MASTRA_PLATFORM_ACCESS_TOKEN=your-token
MASTRA_PROJECT_ID=your-project-id
```

地區及其他選用變數請參閱[環境變數](/reference/connect/tools#environment-variables)。

### 連接帳號 {/* #connect-an-account */}

在服務商的[整合頁面](#providers)找到服務商 ID，再以該 ID 執行 `mastra connect add`。以下以授權 Linear 帳號為例：

```bash
mastra connect add linear
```

請在 `.env` 檔案所在的目錄執行指令。CLI 會引導您完成授權。執行 [`mastra connect list`](/reference/cli/mastra#mastra-connect-list) 可查看專案可用的服務商及連線狀態。連線的命名、移除及替換方式請參閱 [`mastra connect` 參考](/reference/cli/mastra#mastra-connect)。

## 為 Agent 新增工具 {/* #add-tools-to-an-agent */}

将 [`tools()`](/reference/connect/tools) 传给 Agent 的 `tools` 选项：

```typescript title="src/mastra/agents/ops.ts"
import { Agent } from '@mastra/core/agent'
import { tools } from '@mastra/connect'

export const opsAgent = new Agent({
  id: 'ops',
  name: 'ops',
  instructions: 'You help the team track work in Linear and GitHub.',
  model: '__GATEWAY_OPENAI_MODEL_LUNA__',
  tools: tools(),
})
```

未傳入選項時，Agent 會取得所有已連線且提供工具集的服務商的工具。每個工具鍵都有服務商前綴，例如 `linear_list_issues`。前綴可能與服務商 ID 不同，例如 `google-calendar` 的工具以 `google_calendar_` 開頭。[服務商工具集參考](/reference/connect/providers)列出所有工具鍵。部分服務商透過託管的 Model Context Protocol（MCP）伺服器提供工具。這些服務商也使用 `tools()` API，但工具會在執行階段探索。

若也要保留自己的工具，請在 `tools` 函式中展開解析器傳回的結果。鍵相同時，以自己的工具為準：

```typescript title="src/mastra/agents/ops.ts"
import { Agent } from '@mastra/core/agent'
import { tools } from '@mastra/connect'
import { weatherTool } from '../tools/weather'

const connectTools = tools()

export const opsAgent = new Agent({
  id: 'ops',
  name: 'ops',
  instructions: 'You help the team track work in Linear and GitHub.',
  model: '__GATEWAY_OPENAI_MODEL_LUNA__',
  tools: async ctx => ({ ...(await connectTools(ctx)), weatherTool }),
})
```

## 選擇工具並要求核准 {/* #choose-tools-and-require-approval */}

只提供 Agent 需要的工具。用 `providers` 選擇服務商、以 `allowTools` 允許特定工具鍵，並以 `requireApproval` 暫停選定的工具，等候核准後再執行：

```typescript
tools({
  providers: {
    linear: {
      allowTools: ['linear_list_issues', 'linear_create_issue'],
      requireApproval: ['linear_create_issue'],
    },
  },
})
```

工具預設不需核准即可執行。傳入 `requireApproval: true` 可要求核准該服務商的每個工具。工具集與 MCP 服務商都支援核准。如何處理核准要求，請參閱[人工介入指南](/docs/agents/human-in-the-loop)。

若服務商有多條連線，工具集會新增 `<provider>__list_connections` 工具。同一服務商的其他工具可透過 `connection_name` 輸入選擇帳號。若要固定使用某條連線，請為該服務商設定 `connectionId`。

[`tools()` 參考](/reference/connect/tools#parameters)說明排除篩選條件、萬用字元模式、依請求調整的選項與快取。

## 新增頻道 {/* #add-channels */}

將 [`channels()`](/reference/connect/channels) 傳給 `Mastra` 建構函式：

```typescript title="src/mastra/index.ts"
import { Mastra } from '@mastra/core'
import { channels } from '@mastra/connect'
import { assistant } from './agents/assistant'

export const mastra = new Mastra({
  agents: { assistant },
  channels: await channels(),
})
```

這會註冊頻道 Provider 及其 Webhook 路由。要啟用頻道，還需要完成兩個步驟：

1. **連線至服務商。** 平台連線會儲存機器人或應用程式的憑證。詳細步驟請參閱各服務商的整合頁面：[Slack](/integrations/channels/slack#agent-chat)、[Discord](/integrations/channels/discord#agent-chat)、[Telegram](/integrations/channels/telegram#connect) 和 [Microsoft Teams](/integrations/channels/teams#agent-chat)。
1. **在 Agent 上安裝頻道。** 在 Studio 將頻道連結到 Agent，使用者就能向該 Agent 傳送訊息。

服務商必須能透過公開 URL 存取伺服器，才能投遞 Webhook 或執行 OAuth 回呼。Mastra 平台會提供這個 URL。若在其他環境託管，請將 `MASTRA_SERVER_URL` 設為伺服器的公開 URL。本機開發時請使用公開的 HTTPS 通道。

[`channels()` 參考](/reference/connect/channels)說明服務商選擇、啟動錯誤與連線更新，也示範如何[混用 Connect 頻道與自行管理的頻道](/reference/connect/channels#combine-with-self-managed-channels)，以及[依頻道調整工具](/reference/connect/channels#vary-tools-by-channel)。

## 使用原始凭据 {/* #use-a-raw-credential */}

將連線 ID 傳給 [`credential()`](/reference/connect/credential)，即可在自己的程式碼取得連線憑證。需要呼叫服務商的 SDK 或工具未支援的 API 時，可使用此方式。

## 安全模型 {/* #security-model */}

呼叫工具時，平台在伺服器端將憑證加入請求，應用程式不會收到憑證。平台會記錄每次代理呼叫，供稽核及統計工具使用情況，但不會記錄工具引數或結果。

代理請求只能連到服務商的 API 主機。有些連線允許額外主機，例如 Supabase 專案的 URL。哪些工具可交給 Agent、哪些呼叫需要核准，均由您的程式碼決定。

`credential()` 會將原始憑證的秘密值傳回應用程式。使用該憑證發出的請求會繞過代理，因此不受代理的主機限制，也不會留下代理呼叫記錄。請勿記錄憑證或將它放入 Agent 的輸出。

## 疑難排解 {/* #troubleshooting */}

呼叫服務商失敗通常是連線憑證或設定所致。`proxy_error` 的 `status` 和 `detail` 屬性包含服務商的回應。

- **狀態 `401`：** 憑證可能已過期、撤銷或輪替。若需要替換憑證，請[重新授權連線](/reference/cli/mastra#replace-a-connection-that-needs-reauthorization)。
- **狀態 `403`：** 檢查服務商的回應，找出是否缺少授權範圍、受到資源限制或有帳號要求。使用 `allowTools` 篩選工具不會改變憑證的權限。
- **沒有某個服務商的工具：** 執行 `mastra connect list` 檢查專案及連線狀態，再檢查所選服務商和工具篩選條件。確認安裝的 `@mastra/connect` 版本包含該工具集。若應用程式的記錄出現 `[@mastra/connect] Skipping` 警告，代表有連線無法解析。

完整的錯誤代碼請參閱[錯誤參考](/reference/connect/tools#errors)。
