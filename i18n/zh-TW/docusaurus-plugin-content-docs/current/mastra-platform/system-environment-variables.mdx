# 系統環境變數

Mastra 平台會在每次部署中註入一組環境變數。它們保存程式碼運行所在的項目和環境的標識、程式碼運行的區域以及任何[hosted database](/docs/mastra-platform/database)附於其上。

您可以像讀取任何其他變數一樣讀取它們：

```ts
const environmentName = process.env.MASTRA_ENVIRONMENT_NAME
```

系統變數被保留。使用這些名稱之一儲存的變數將保留在專案或環境記錄中，但永遠不會到達運行時，因為平台的值是最後應用的。

## 專案和環境變數 {/* #project-and-environment-variables */}

每次部署時注入。

|變數|價值|
| - | - |
|`MASTRA_PROJECT_ID` | ID of the project being deployed |
| `MASTRA_ENVIRONMENT_ID` | ID of the environment. Stable across renames |
| `MASTRA_ENVIRONMENT_NAME` | Name of the environment, such as `production` |
| `MASTRA_ENVIRONMENT_SLUG`|環境的路由slug |
|`MASTRA_PLATFORM_REGION`|環境運作的區域，`US`或者`EU` |
| `MASTRA_PLATFORM_ACCESS_TOKEN`|部署用於呼叫平台 API 的令牌，包括可觀察性 |
|`MASTRA_PLATFORM_BUCKET_NAME`|支持環境的水桶[Workspace](/docs/mastra-platform/workspaces)。啟用Workspace時設定 |
|`MASTRA_WORKERS`|設定為`false`當專案聲明工作人員時在主服務上運行，因此它們僅在自己的服務中運行 |

## 託管資料庫變數 {/* #managed-database-variables */}

附加託管資料庫會將其連接變數新增至資料庫所覆蓋的環境。每個Provider的名稱都是固定的。

|Provider|變數|
| - | - |
|圖爾索 |`TURSO_DATABASE_URL`, `TURSO_AUTH_TOKEN` |
| Neon | `DATABASE_URL` |
| Postgres | `DATABASE_URL` |
| Redis | `REDIS_URL` |

尚未為每個組織啟用託管 Redis。當您的組織關閉時，Redis 不會顯示為資料庫選項，並且附加它會失敗。

值在部署時解析，並且永遠不會儲存在您的專案中。環境範圍的資料庫取代該環境的相同Provider的項目範圍的資料庫的值。

## 優先權 {/* #precedence */}

部署按此順序解析變量，最後一個獲勝：

1. 您儲存在正在部署的環境中的變數。其他環境的變數永遠不會被讀取。項目仍在進行中[legacy pipeline](/docs/mastra-platform/deploy#migrating-from-server-and-studio-deploys) use the variables stored on the project instead.
2. 該環境的託管資料庫變數。
3. 平台變數。

系統值最後應用，因此它們在名稱衝突中獲勝。您的儲存值保留在記錄中並繼續顯示在儀表板中，但正在運行的服務永遠看不到它。 「環境變數」頁面會以警告圖示標記這些行，以便您可以知道哪些值被隱藏。

附加到單一環境的資料庫會隱藏同一Provider的項目範圍資料庫，但僅限於該環境內部。若要將一個環境指向不同的資料庫，請附加一個[environment-scoped database](/docs/mastra-platform/database#attach-with-the-cli) rather than overwriting the connection variable by hand.

若要查看環境運行的內容，請將其變數拉入本機檔案：

```bash
mastra env vars pull staging --output .env.staging
```

託管值不會寫入檔案。它們僅顯示為名稱註釋。
