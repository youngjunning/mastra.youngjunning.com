# 系統環境變數

Mastra 平台每次部署時都會注入一組環境變數，包含程式碼執行所在的專案與環境識別資訊、執行區域，以及所連結的[託管資料庫](/docs/mastra-platform/database)憑證。

你可以像一般環境變數一樣讀取：

```ts
const environmentName = process.env.MASTRA_ENVIRONMENT_NAME
```

系統變數名稱為保留名稱。你儲存的同名變數會留在專案或環境記錄中，但執行階段只會使用最後套用的平台值。

## 專案與環境變數 {/* #project-and-environment-variables */}

下列變數會在每次部署時注入。

| 變數 | 值 |
| - | - |
| `MASTRA_PROJECT_ID` | 部署中的專案 ID |
| `MASTRA_ENVIRONMENT_ID` | 環境 ID，重新命名後仍維持不變 |
| `MASTRA_ENVIRONMENT_NAME` | 環境名稱，例如 `production` |
| `MASTRA_ENVIRONMENT_SLUG` | 環境的路由 slug |
| `MASTRA_PLATFORM_REGION` | 環境的執行區域，可為 `US` 或 `EU` |
| `MASTRA_PLATFORM_ACCESS_TOKEN` | 部署執行個體呼叫平台 API（包括可觀測性 API）時使用的權杖 |
| `MASTRA_PLATFORM_BUCKET_NAME` | 環境的 [Workspace](/docs/mastra-platform/workspaces) 所用的儲存貯體，啟用 Workspace 時設定 |
| `MASTRA_WORKERS` | 專案宣告 Worker 時，主服務會設為 `false`，讓 Worker 只在各自的服務中執行 |

## 託管資料庫變數 {/* #managed-database-variables */}

連結託管資料庫時，平台會將資料庫連線變數加入其涵蓋的環境。變數名稱依提供者而定，同一提供者的名稱固定。

| 提供者 | 變數 |
| - | - |
| Turso | `TURSO_DATABASE_URL`, `TURSO_AUTH_TOKEN` |
| Neon | `DATABASE_URL` |
| Postgres | `DATABASE_URL` |
| Redis | `REDIS_URL` |

目前並非每個組織都已啟用託管 Redis。若你的組織尚未啟用，資料庫選項中就不會顯示 Redis，嘗試連結也會失敗。

變數值在部署時解析，不會儲存在專案中。若環境層級和專案層級的資料庫來自同一提供者，該環境會使用環境層級資料庫的值。

## 優先順序 {/* #precedence */}

部署時會依下列順序解析變數，同名時以最後套用的值為準：

1. 儲存在要部署的環境中的變數。平台不會讀取其他環境的變數。仍採用[舊版部署管線](/docs/mastra-platform/deploy#migrating-from-server-and-studio-deploys)的專案會改用儲存在專案中的變數。
1. 該環境的託管資料庫變數。
1. 平台變數。

系統值最後套用，因此會覆蓋同名的變數。你原先儲存的值仍會留在記錄中，也會繼續顯示在儀表板上，但執行中的服務不會取得這些值。環境變數頁面會以警告圖示標記被覆蓋的項目。

若資料庫只連結至單一環境，只會在該環境中覆蓋同一提供者的專案層級資料庫。若要讓某個環境使用不同的資料庫，請連結[環境層級的資料庫](/docs/mastra-platform/database#attach-with-the-cli)，不要手動覆寫連線變數。

若要查看環境執行時使用的變數，請將它們下載到本機檔案：

```bash
mastra env vars pull staging --output .env.staging
```

檔案只會以註解列出託管變數的名稱，不會寫入實際的值。
