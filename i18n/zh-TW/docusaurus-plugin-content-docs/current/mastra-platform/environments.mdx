# 環境

每個平台項目都包含一個或多個環境。

環境是一個獨立的部署目標，具有自己的 URL、環境變數和部署歷史記錄。也可以有自己的[hosted database](/docs/mastra-platform/database).

使用環境來運行`production`, `staging`，以及單一專案中相同程式碼庫的預覽版本。

第一次執行 [`mastra deploy`](/docs/mastra-platform/deploy) 時，會建立 `production` 環境。你可透過 CLI 新增環境，或直接部署至尚未使用的環境名稱。

## 建立環境 {/* #create-an-environment */}

明確建立環境：

```bash
mastra env create staging
```

或讓部署建立它，這會提示您確認：

```bash
mastra deploy --env staging
```

`mastra env create` 預設會建立 `staging` 環境。請用 `--type` 指定 `staging` 或 `preview`，再用 `--region` 選擇環境的執行區域：

```bash
mastra env create eu-preview --type preview --region eu
```

每個專案只有一個 `production` 環境，由第一次部署建立。建立後無法更改區域。已連結的資料庫會自動配置在環境附近，可觀測性資料則送到對應資料落地分區的擷取區域。支援的區域、資料庫配置位置與可觀測性資料的同區配置，請見[區域](/docs/mastra-platform/regions)。每個專案可建立的環境數量取決於你的方案。

## 列出環境 {/* #list-environments */}

```bash
mastra env list
```

輸出會列出各環境的名稱、區域、目前生效的部署狀態，以及連結的資料庫所注入的受管理環境變數。在 CI 中可傳入 `--json`，取得機器可讀的輸出。

所有 `mastra env` 指令都會依序從 `--project` 旗標、`MASTRA_PROJECT_ID` 環境變數，以及首次部署寫入的 `.mastra-project.json` 檔案判定專案。在專案目錄中執行即可，不必另行指定專案。

## 環境變數 {/* #environment-variables */}

環境從兩個範圍解析其變數：

- **受管理變數**：由已連結的[託管資料庫](/docs/mastra-platform/database)（例如 `TURSO_DATABASE_URL`）或平台注入。這些變數由平台定義，無法編輯。完整清單請見[系統環境變數](/docs/mastra-platform/system-environment-variables)。
* **環境範圍的變數**：透過儀表板儲存在每個環境中。當您將一個變數應用於多個環境時，每個環境都會保留自己的副本。將這些值用於環境之間不同的值，例如用於登台和生產服務的 API 金鑰。

環境層級變數就是[部署](/docs/mastra-platform/deploy#environment-variables)頁面所述的已儲存變數。部署某個環境時，只會使用該環境的變數。仍採用[舊版部署管線](/docs/mastra-platform/deploy#migrating-from-server-and-studio-deploys)的專案會把變數存於專案層級，該專案每次部署都會使用它們。

部署開始時應用變數。要將更改的變數套用到正在執行的服務而不需要完全重新部署：

```bash
mastra env restart staging
```

若要查看環境部署實際運行的設置，以及按名稱列出的託管變量，請將它們拉入本機環境檔案中。每個環境都是獨立的。該文件永遠不會混合在另一個環境的值中：

```bash
mastra env vars pull staging --output .env.staging
```

託管變數值在部署時注入，並且永遠不會寫入檔案。它們僅顯示為名稱註釋。

:::note
環境變數無法覆寫託管資料庫變數。若要改用其他資料庫，請連結[環境層級的資料庫](/docs/mastra-platform/database#attach-with-the-cli)。
:::

## 部署歷史記錄 {/* #deploy-history */}

列出跨所有環境的部署，或過濾到一個：

```bash
mastra env deploys
mastra env deploys staging
```

每一列會顯示部署狀態、環境、時間戳記，以及目前生效的部署。部署依序經過 **queued → uploading → starting → deploying → running**；新版開始處理流量時，平台才會顯示 **running**。GitHub 觸發的部署會先從原始碼建置，因此會在 **queued** 和 **uploading** 之間經過 **building**。

## 隔離環境數據 {/* #isolate-an-environments-data */}

託管資料庫預設只供單一環境使用，因此正式與預備環境會各自讀寫自己的資料庫：

```bash
mastra env db create production --kind turso --name my-project-production-db
mastra env db create staging --kind turso --name my-project-staging-db
```

若要讓所有環境共用同一個資料庫，請用 `--shared` 連結：`mastra env db create --kind turso --shared`。

每個環境對同一家 Provider 只能使用一個資料庫。同一家 Provider 若已有共用資料庫（`--shared`），就會與環境層級的資料庫發生變數名稱衝突。執行 `mastra env db delete` 前，請匯出要保留的資料，因為這個指令會刪除該 Provider 的共用資料庫及內容。完整作用域規則請見[託管資料庫](/docs/mastra-platform/database)。

## 刪除環境 {/* #delete-an-environment */}

```bash
mastra env delete staging
```

CLI 在刪除之前要求確認。刪除環境會刪除其部署和儲存的變數。
