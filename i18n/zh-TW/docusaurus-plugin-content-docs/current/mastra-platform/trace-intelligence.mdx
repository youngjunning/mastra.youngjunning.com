# Mastra 平台上的追蹤情報

追蹤智能可以發現座席互動中重複出現的模式。它分析 Mastra Observability 捕獲的跟踪，並產生四個內建維度的追蹤訊號以及為專案啟用的任何自訂訊號。然後，它將相似的追蹤訊號聚集到主題中。

使用 Trace Intelligence 來調查以下問題：

* 用戶想要實現什麼目標？
* 哪些目標往往會成功、哪些目標尚未實現或阻礙？
* 成功和不成功的互動中會出現哪些Agent行為？
* 使用者情緒與目標和結果有何關係？

:::警告私人測試版
Trace Intelligence 可透過邀請獲得選定的 Mastra 平台專案。
:::

## 取得存取權限 {/* #get-access */}

1. 提交[Trace Intelligence private beta form](https://mastra.ai/trace-intelligence) to request access.
2. 確認[Mastra platform Observability](/docs/mastra-platform/observability) is enabled and that completed agent traces appear under **Traces**.
3. 至少需要`@mastra/core@1.53.0` and `mastra@1.20.2`. Upgrade your project then deploy or redeploy Studio for the enrolled project. Local Studio and server-only deployments aren't supported during the private beta.
4. 打開部署的Studio並選擇**Intelligence** in the sidebar.
5. 將代表性流量傳送給您的Agent商並留出時間進行分析。

Mastra 註冊專案後，您無需更改Agent定義或呼叫。

### 當數據可用時 {/* #when-data-is-available */}

追蹤智能需要來自一個Agent的足夠的經過處理的追蹤來識別重複出現的模式。初始主題通常至少在**100 completed traces** from that agent have been processed.

下的追蹤計數**Traces** can reach 100 before Trace Intelligence is ready because the analysis pipeline runs asynchronously. Processing can take several minutes after the threshold is reached. Traces that can't be analyzed don't contribute. As a result, 100 is a minimum rather than an exact UI trigger.

隨著更多追蹤到達，追蹤智慧會自動更新。 Studio 需要至少兩種追蹤訊號類型的主題，然後才能顯示關係流。

使用代表性流量。一組重複的測試提示可能會產生不具代表性的結果，例如一個廣泛的主題或大部分是噪音。

## 了解分析 {/* #understand-the-analysis */}

每個可分析的已完成追蹤都會產生四個內建追蹤訊號，以及為專案啟用的任何自訂訊號：

|追蹤訊號|意義|
| - | - |
|**Goal** | What the user is trying to achieve or have completed. |
| **Outcome** | The final completed, partial, blocked, failed, unresolved, or unclear state. |
| **Behavior** | Observable agent actions and patterns, including tool use, omissions, retries, failures, and recovery. |
| **Sentiment** | The user's emotional state or attitude. |

主題是由相似的追蹤訊號產生的簇。對於每個追蹤訊號類型，聚類都是獨立發生的。一條痕跡可以屬於每個維度中的一個單獨主題：目標、結果、行為和情緒。

### 主題和關係 {/* #themes-and-relationships */}

此流程圖連接相鄰追蹤訊號列中的主題：

* 一個**node** represents a theme. Its count is the number of distinct traces assigned to that theme in the selected snapshot.
* 一個**ribbon** connects traces assigned to themes in both adjacent columns. Its width represents the shared trace count.
* 將滑鼠懸停在節點或功能區上或將其聚焦以隔離其關係。



### 其他和噪音 {/* #other-and-noise */}

每個節點都會顯示其追蹤計數：在所選快照中分配給該主題的不同追蹤的數量。主題的詳細資訊也說明了其份額，例如「此快照中 70 條追蹤中的 28 條 (40%)」。

Studio 顯示每個追蹤訊號類型最常見的主題。它可以將較小的主題組合成**Other** to preserve totals without overcrowding the chart.

**噪音**包含與所選快照中的重複主題不一致的摘要。它不一定表示錯誤或低品質的互動。噪音可能包括罕見的請求和新出現的模式。它也可能包含不明確的互動或不相關的案例。較大的噪音份額可能表示流量變化很大或穩定主題的資料不足。

### 快照 {/* #snapshots */}

快照是一組軌跡上的移動分析視窗。快照可以重疊，因此不要將它們的追蹤計數加在一起。將主題的追蹤計數及其快照份額放在一起比較，因為視窗之間的流量可能會改變。

主題可以在快照中保留、消失、分割、合併或傳回。將主題名稱和描述視為產生的摘要，而不是固定的分類法。

## {/* #use-the-trace-intelligence-page */}

1. 打開**Intelligence** to see the entity index. Search or sort the index, then select an entity to open its analysis.
2. 在流程中選擇主題以開啟其詳細資訊並過濾每一列以尋找包含該主題的追蹤。
3. 詳細資訊面板顯示主題的描述、快照份額、分頁範例摘要以及追蹤計數隨時間變化的趨勢。
4. 選擇**Clear filter** to restore the complete flow.

實體在其訊號仍在收集或處理時出現。此索引顯示每個實體的分析追蹤計數、就緒和啟用的訊號計數、生命週期狀態和上次更新。

### 配置自訂訊號 {/* #configure-a-custom-signal */}

組織管理員可以在不離開 Intelligence 的情況下配置自訂訊號：

1. 返回實體索引並選擇**Signal settings**.
2. 選擇**Create signal**, provide a stable signal name, display label, description, and signal instructions, then save it. Definitions and their versions are shared across the organization.
3. 啟用下訊號**Current project**. Project enablement affects only the current project and applies to newly processed traces.
4. 從索引中開啟一個實體，並在其從收集到處理並準備就緒時追蹤其訊號狀態。

您可以編輯自訂訊號的標籤、描述或說明。指令變更會建立新版本並僅適用於新追蹤。您也可以存檔不再可用的定義或稍後恢復存檔的定義。

您也可以：

* 選擇**Noise** in the flow to inspect its share and generated example summaries.
* 拖曳圖表上方的列標題以重新排序追蹤訊號列並查看不同的關係視角。
* 使用時間軸選擇快照，或選擇**Play** to watch themes change over time.
* 切換到**Compare** to see which themes grew, shrank, entered the range, or left the range between two points in time, or **Lifelines** to follow each theme's share across the whole selected range.

對於具有超過 2,000 條追蹤的快照，無法按主題過濾流。選擇主題仍會在那裡打開其詳細信息，而不過濾流程。

## 故障排除 {/* #troubleshooting */}

### 情報不在側邊欄中 {/* #intelligence-isnt-in-the-sidebar */}

確認 Mastra 註冊了正確的項目，您使用與測試版相容的 Mastra 版本，並且您重新部署了 Studio，因為私有測試版不支援本機 Studio。

### 缺少Agent {/* #an-agent-is-missing */}

確認其完整的追蹤列在下面**Traces** and that the project is enrolled. Trace Intelligence lists an entity after signal generation begins, before its first themes are ready. If it recently reached 100 traces, allow time for asynchronous processing.

### 關係流不可用 {/* #the-relationship-flow-is-unavailable */}

這個流程需要至少兩種追蹤訊號類型的主題。繼續發送代表性流量並允許處理完成。

### 大多數摘要都是噪音 {/* #most-summaries-are-noise */}

收集更具代表性的流量並比較稍後的快照。多樣化或罕見的相互作用更難分組，而重複的測試提示可能會產生不具代表性的分佈。

## 內測限制 {/* #private-beta-limitations */}

* Trace Intelligence 僅適用於已部署 Studio 中已註冊的專案。
* 初始分析需要每個Agent至少 100 個已處理的追蹤。有些Agent商可能需要更多。
* 結果取決於捕獲痕蹟的多樣性和品質。
* 追蹤訊號摘要、主題標籤、聚類、閾值和 UI 行為在測試期間可能會發生變化。

報告回饋時，請包含組織 ID、專案 ID、Agent ID、選定的快照以及說明問題的主題或噪音範例。
