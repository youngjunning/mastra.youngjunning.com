# Mastra 平台的 Trace Intelligence

Trace Intelligence 分析 Mastra Observability 擷取的 Trace，產生四個內建維度及專案啟用的自訂訊號，再把相似的 Trace 訊號分群成主題，找出 Agent 互動中的重複模式。

你可以用 Trace Intelligence 探索下列問題：

- 使用者想完成什麼？
- 哪些目標通常能達成，哪些容易懸而未決或遇到阻礙？
- 成功與未成功的互動中，各出現了哪些 Agent 行為？
- 使用者情緒和目標、結果有什麼關聯？

:::warning 封閉測試
Trace Intelligence 僅開放給部分受邀的 Mastra 平台專案。
:::

## 取得存取權限 {/* #get-access */}

1. 送出 [Trace Intelligence 封閉測試表單](https://mastra.ai/trace-intelligence)，申請使用權限。
1. 確認已啟用 [Mastra 平台的 Observability](/docs/mastra-platform/observability)，並可在 **Traces** 看到已完成的 Agent Trace。
1. 版本至少須為 `@mastra/core@1.53.0` 和 `mastra@1.20.2`。升級後，為已加入測試的專案部署或重新部署 Studio。封閉測試期間不支援本機 Studio 或僅部署 Server。
1. 開啟已部署的 Studio，在側邊欄選取 **Intelligence**。
1. 將具代表性的流量送到 Agent，並預留分析時間。

Mastra 將專案納入測試後，不必調整 Agent 的定義或呼叫方式。

### 當數據可用時 {/* #when-data-is-available */}

Trace Intelligence 必須處理足夠多筆來自同一個 Agent 的 Trace，才能找出重複模式。第一批主題通常會在該 Agent 至少有 **100 筆已完成的 Trace** 經過處理後出現。

分析流程採非同步執行，**Traces** 可能已顯示 100 筆，分析卻還沒就緒。達到門檻後可能還要幾分鐘。無法分析的 Trace 不列入計算，因此 100 筆是最低門檻，介面不一定會在達標當下更新。

Trace Intelligence 會隨新 Trace 自動更新。至少兩類 Trace 訊號產生主題後，Studio 才能顯示關聯圖。

請使用具代表性的流量。反覆送出少數測試提示詞，可能使結果失去代表性，例如只得到一個過於廣泛的主題，或大多落在 Noise。

## 了解分析 {/* #understand-the-analysis */}

每筆已完成且可分析的 Trace 都會產生下列四種內建 Trace 訊號，以及專案已啟用的自訂訊號：

| Trace 訊號 | 意義 |
| - | - |
| **Goal** | 使用者想達成的目標或想完成的事項。 |
| **Outcome** | 最終狀態：完成、部分完成、受阻、失敗、未解決或不明確。 |
| **Behavior** | 可觀察的 Agent 動作和模式，包括工具使用、遺漏、重試、失敗與復原。 |
| **Sentiment** | 使用者的情緒狀態或態度。 |

相似的 Trace 訊號會分群成主題。各類訊號獨立分群，同一筆 Trace 可在 Goal、Outcome、Behavior 和 Sentiment 各自歸入不同主題。

### 主題和關係 {/* #themes-and-relationships */}

關聯圖會連接相鄰 Trace 訊號欄中的主題：

- **節點**代表主題，數字是所選快照中歸入該主題的不重複 Trace 筆數。
- **連帶**連接相鄰欄位中有共同 Trace 的主題，寬度表示共有的 Trace 筆數。
- 將游標移到節點或連帶上，或將焦點移至該處，即可單獨檢視其關聯。

圖中呈現的是關聯，無法用來判斷因果或執行順序。例如，Goal 和 Outcome 之間的連帶代表兩個主題出現在同一批 Trace 裡，無法據此判定目標造成了結果。

### Other 與 Noise {/* #other-and-noise */}

每個節點都會顯示所選快照中歸入該主題的不重複 Trace 筆數。主題詳細資料也會標示占比，例如「此快照的 70 筆 Trace 中有 28 筆屬於此主題（40%）」。

Studio 會顯示每類 Trace 訊號中最常見的主題，也可能把較小的主題合併到 **Other**，讓圖表保有完整的總數且不過於擁擠。

**Noise** 收錄在所選快照中無法穩定歸入任何重複主題的摘要。這不一定代表發生錯誤或互動品質不佳，也可能包含少見的請求、新出現的模式、意義不明的互動或不相關的案例。Noise 占比偏高，可能是流量差異很大，或資料尚不足以形成穩定主題。

### 快照 {/* #snapshots */}

快照涵蓋滑動分析視窗內的一組 Trace。快照可能重疊，因此請勿將筆數相加。各視窗的流量可能不同，比較時請同時參考主題的 Trace 筆數及其在快照中的占比。

主題在不同快照之間可能持續、消失、拆分、合併或再次出現。請把主題名稱和描述視為產生的摘要，避免當成固定的分類。

## 使用 Trace Intelligence 頁面 {/* #use-the-trace-intelligence-page */}

1. 開啟 **Intelligence** 檢視實體清單。搜尋或排序後，選取實體查看分析。
1. 選取圖中的主題即可開啟詳細資料，並將每一欄篩選至包含該主題的 Trace。
1. 詳細資料面板會顯示主題描述、快照占比、分頁呈現的範例摘要，以及 Trace 筆數隨時間的變化。
1. 選取 **Clear filter** 恢復完整的關聯圖。

即使訊號仍在收集或處理，實體也會出現在清單中。清單會列出各實體已分析的 Trace 筆數、已就緒與已啟用的訊號數量、生命週期狀態和上次更新時間。

### 配置自訂訊號 {/* #configure-a-custom-signal */}

組織管理員可以直接在 Intelligence 內設定自訂訊號：

1. 回到實體清單，選取 **Signal settings**。
1. 選取 **Create signal**，填入固定的訊號名稱、顯示標籤、描述和指令，再儲存。訊號定義及其版本由整個組織共用。
1. 在 **Current project** 下啟用訊號。這項設定只影響目前的專案，並套用於之後處理的 Trace。
1. 從清單開啟一個實體，追蹤訊號從收集到處理、最後就緒的狀態。

你可以編輯自訂訊號的標籤、描述或指令。變更指令會建立新版本，且只套用於新的 Trace。你也可以封存不再開放使用的定義，日後再還原。

您也可以：

- 在關聯圖中選取 **Noise**，查看其占比與產生的範例摘要。
- 拖曳圖表上方的欄標題，調整 Trace 訊號的欄位順序，從不同角度查看關聯。
- 在時間軸選取快照，或選取 **Play** 觀看主題如何隨時間變化。
- 切換至 **Compare**，查看兩個時間點之間哪些主題擴大、縮小、進入或離開範圍。也可切換至 **Lifelines**，追蹤各主題在整段所選時間內的占比。

快照超過 2,000 筆 Trace 時，無法依主題篩選關聯圖。選取主題仍可查看詳細資料。

## 故障排除 {/* #troubleshooting */}

### 側邊欄中沒有 Intelligence {/* #intelligence-isnt-in-the-sidebar */}

請確認 Mastra 已將正確的專案納入測試、目前使用的 Mastra 版本與測試版相容，且已重新部署 Studio。封閉測試不支援本機 Studio。

### 找不到某個 Agent {/* #an-agent-is-missing */}

確認該 Agent 已完成的 Trace 出現在 **Traces** 中，且專案已加入測試。開始產生訊號後，Trace Intelligence 就會列出該實體，不必等到首批主題就緒。若剛達到 100 筆，請等待非同步處理。

### 無法查看關聯圖 {/* #the-relationship-flow-is-unavailable */}

至少有兩類 Trace 訊號產生主題後，才能顯示關聯圖。請繼續送入具代表性的流量，並等待處理完成。

### 大多數摘要落在 Noise {/* #most-summaries-are-noise */}

請收集更多具代表性的流量，再比較後續的快照。多樣或罕見的互動較難歸類，反覆使用測試提示詞則可能讓分布失去代表性。

## 封閉測試的限制 {/* #private-beta-limitations */}

- 只有已加入測試的專案，才可在已部署的 Studio 使用 Trace Intelligence。
- 初次分析時，每個 Agent 至少需要 100 筆經過處理的 Trace。某些 Agent 可能需要更多。
- 結果取決於所擷取 Trace 的多樣性和品質。
- 測試期間，Trace 訊號摘要、主題標籤、分群、門檻和介面行為都可能變動。

提供意見回饋時，請附上組織 ID、專案 ID、Agent ID、所選快照，以及能說明問題的主題或 Noise 範例。
