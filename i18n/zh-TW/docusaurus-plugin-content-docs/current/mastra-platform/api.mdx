## Feedback API {/* #feedback-api */}

Feedback API 用來列出並分析匯出至 Mastra Platform Observability 的回饋。此 API 未區分版本，因此不保證向後相容。速率限制、資料保留期限，以及從資料擷取到可查詢的延遲，均未列為公開合約。

這些端點的查詢參數、要求本文與回應型別，與 Mastra 執行階段的回饋路由相同。完整規格請參閱[回饋參考文件](/reference/observability/feedback)，包括[清單查詢參數](/reference/observability/feedback#list-query-parameters)與 [`FeedbackFilter`](/reference/observability/feedback#feedbackfilter)。

請使用環境所屬資料存放區域的根 URL：

| 區域 | 根 URL |
| - | - |
| 美國 | `https://observability.mastra.ai/api/observability` |
| 歐盟 | `https://observability.eu.mastra.ai/api/observability` |

遙測資料會留在其存放區域。查詢另一個區域，不會取得該環境的紀錄。環境與區域的對應關係請參閱[可觀測性同區部署](/docs/mastra-platform/regions#observability-co-location)。

### 身分驗證與專案範圍 {/* #authentication-and-project-scope */}

每個要求都需要 Platform 存取權杖。可在 [Mastra Platform](https://projects.mastra.ai) 建立，或使用設定 Platform 時寫入 `.env` 的權杖。

加入 `X-Mastra-Project-Id` 可將結果限定在單一專案。若省略，查詢會涵蓋權杖所屬組織可存取的所有專案回饋。

```bash
curl -sS "https://observability.mastra.ai/api/observability/feedback?page=0&perPage=20&feedbackType=rating" \
  -H "Authorization: Bearer $MASTRA_PLATFORM_ACCESS_TOKEN" \
  -H "X-Mastra-Project-Id: $MASTRA_PROJECT_ID" | jq
```

請使用組織範圍的 Platform 存取權杖；不接受 `mk_*` 等 Gateway 推論金鑰。即使提供專案 ID，查詢仍限定在權杖所屬組織。

### 端點 {/* #endpoints */}

| 方法 | 端點 | 說明 |
| - | - | - |
| GET | `/feedback` | 列出回饋紀錄 |
| POST | `/feedback/aggregate` | 回傳單一彙總值 |
| POST | `/feedback/breakdown` | 依維度分組回饋 |
| POST | `/feedback/timeseries` | 依時間間隔分組回饋 |
| POST | `/feedback/percentiles` | 回傳百分位數序列 |

清單端點會把每個 [`FeedbackFilter`](/reference/observability/feedback#feedbackfilter) 欄位視為同名查詢參數，例如 `traceId`、`spanId`、`feedbackType`、`feedbackSource`、`environment`、`entityName`、`experimentId` 或 `tags`。要傳入多個值，請重複該參數，例如 `feedbackType=rating&feedbackType=thumbs`。

```bash
curl -sS "https://observability.mastra.ai/api/observability/feedback?traceId=trace-123&environment=production" \
  -H "Authorization: Bearer $MASTRA_PLATFORM_ACCESS_TOKEN" \
  -H "X-Mastra-Project-Id: $MASTRA_PROJECT_ID" | jq
```

| 參數 | 說明 |
| - | - |
| `page`, `perPage` | 從零起算的頁碼與每頁筆數（1 至 100）；預設為 `0` 與 `10`。 |
| `field`, `direction` | 依 `timestamp` 以 `ASC` 或 `DESC` 排序；預設為 `DESC`。 |
| `mode=delta` | 從分頁切換為增量輪詢。 |
| `after` | 上一次增量回應的游標；僅適用於增量模式。 |
| `limit` | 每次增量輪詢最多取得的更新數（1 至 100）；僅適用於增量模式。 |

回應包含 `feedback` 陣列，以及分頁或增量中繼資料。完整參數規格（包括以 JSON 編碼的 `timestamp` 等物件篩選條件）請參閱回饋參考文件的[清單查詢參數](/reference/observability/feedback#list-query-parameters)。

分析端點接受與[回饋參考文件](/reference/observability/feedback)相同的 JSON 要求格式，並回傳相同型別的結果。分析僅處理數值型回饋。

```bash
curl -sS "https://observability.mastra.ai/api/observability/feedback/aggregate" \
  -X POST \
  -H "Authorization: Bearer $MASTRA_PLATFORM_ACCESS_TOKEN" \
  -H "X-Mastra-Project-Id: $MASTRA_PROJECT_ID" \
  -H "Content-Type: application/json" \
  --data '{"feedbackType":"rating","feedbackSource":"user","aggregation":"avg"}' | jq
```

憑證無效時，API 回傳 `401`；組織授權失敗時回傳 `403`；查詢參數或 JSON 要求本文格式錯誤時回傳 `400`。

託管的可觀測性服務不提供建立回饋的路由。請依照[匯出回饋至 Mastra Platform](/docs/observability/feedback#export-feedback-to-mastra-platform)的說明，從應用程式匯出回饋。

### 身分驗證與專案範圍 {/* #authentication-and-project-scope-1 */}

加入 `X-Mastra-Project-Id` 可將結果限定在單一專案。若省略，查詢會涵蓋權杖所屬組織可存取的所有專案指標。

```bash
curl -sS "https://observability.mastra.ai/api/observability/discovery/metric-names?prefix=mastra_model_" \
  -H "Authorization: Bearer $MASTRA_PLATFORM_ACCESS_TOKEN" \
  -H "X-Mastra-Project-Id: $MASTRA_PROJECT_ID" | jq
```

請使用組織範圍的 Platform 存取權杖；不接受 `mk_*` 等 Gateway 推論金鑰。即使提供專案 ID，查詢仍限定在權杖所屬組織。

### 端點 {/* #endpoints-1 */}

| 方法 | 端點 | 說明 |
| - | - | - |
| GET | `/metrics` | 列出原始指標紀錄 |
| POST | `/metrics/aggregate` | 回傳單一彙總值 |
| POST | `/metrics/breakdown` | 依維度分組指標 |
| POST | `/metrics/timeseries` | 依時間間隔分組指標 |
| POST | `/metrics/percentiles` | 回傳單一指標的百分位數序列 |
| GET | `/discovery/metric-names` | 列出指標名稱 |
| GET | `/discovery/metric-label-keys` | 列出某指標的標籤鍵 |
| GET | `/discovery/metric-label-values` | 列出某指標標籤鍵的值 |

清單及探索端點以查詢參數接收引數。各端點接受的參數請參閱指標查詢參考文件中的 [`listMetrics(args)`](/reference/observability/metrics/queries#listmetricsargs) 與[指標探索](/reference/observability/metrics/queries#metric-discovery)。

分析端點接受與[指標查詢參考文件](/reference/observability/metrics/queries#analytics-methods)相同的 JSON 要求本文，並回傳相同型別的結果，包括 `name`、`aggregation`、`filters`、`groupBy`、`interval`、`percentiles`、`comparePeriod`、`limit`、`orderDirection` 及 `distinctColumn`。

```bash
curl -sS "https://observability.mastra.ai/api/observability/metrics/aggregate" \
  -X POST \
  -H "Authorization: Bearer $MASTRA_PLATFORM_ACCESS_TOKEN" \
  -H "X-Mastra-Project-Id: $MASTRA_PROJECT_ID" \
  -H "Content-Type: application/json" \
  --data '{"name":["mastra_model_total_input_tokens","mastra_model_total_output_tokens"],"aggregation":"sum","filters":{"timestamp":{"start":"2026-09-13T00:00:00Z","end":"2026-10-13T00:00:00Z"}},"comparePeriod":"previous_period"}' | jq
```

`filters.timestamp` 是選用項目。省略 `start` 與 `end` 時，查詢會涵蓋所有保留中的資料。`comparePeriod` 則要求同時提供 `start` 與 `end`；否則，上一期間的欄位為 `null`。

憑證無效時，API 回傳 `401`；組織授權失敗時回傳 `403`；查詢參數或 JSON 要求本文格式錯誤時回傳 `400`。

#### `MastraClient` {/* #mastraclient */}

`@mastra/client-js` 的 `MastraClient` 提供分析及探索方法。將 `baseUrl` 設為該區域的主機網址，不包含 `/api/observability` 路徑：

```typescript
import { MastraClient } from '@mastra/client-js'

const mastraClient = new MastraClient({
  baseUrl: 'https://observability.mastra.ai',
  headers: {
    Authorization: `Bearer ${process.env.MASTRA_PLATFORM_ACCESS_TOKEN}`,
    'X-Mastra-Project-Id': process.env.MASTRA_PROJECT_ID!,
  },
})

const result = await mastraClient.getMetricAggregate({
  name: ['mastra_model_total_input_tokens', 'mastra_model_total_output_tokens'],
  aggregation: 'sum',
})
```

#### CLI {/* #cli */}

[`mastra api metric`](/reference/cli/mastra#mastra-api-metric-aggregate) 指令預設連至美國端點。如要查詢歐盟區域，請傳入 `--url`：

```bash
mastra api --url https://observability.eu.mastra.ai metric aggregate '<json>'
```
