# Mastra 平台上的工作室

Mastra 平台上的 Studio 是一個託管的視覺化Workspace，用於測試Agent程式和運行Workflow以及檢查追蹤。當您想要與團隊共用 Studio 而不自行託管 Studio UI 時，請使用它。

您可以從 CLI 部署 Studio，如下所示，或連結 GitHub 儲存庫以進行推送部署。請參閱[GitHub integration](/docs/mastra-platform/github) for the repository-linked flow.

## 快速入門 {/* #quickstart */}

<Steps>
  <StepItem>
    遵循[get started guide](/docs) to create your first Mastra project.
  </StepItem>

  <StepItem>
    安裝`mastra` CLI globally:

    ```bash npm2yarn
    npm install -g mastra
    ```
  </StepItem>

  <StepItem>
    使用單一命令部署 Studio：

    ```bash
    mastra deploy
    ```

    成功部署後，CLI 會輸出已部署的 Studio 實例的 URL。
  </StepItem>
</Steps>

第一次部署時，CLI 會提示您建立新專案或選擇現有專案。然後它創建一個`.mastra-project.json` file in your project directory. This file links your local project to a platform project. It contains the `projectId`, `projectName`, and `organizationId`. Commit this file to your repository so CI/CD knows which project to deploy to.

## 部署如何運作 {/* #how-deploy-works */}

這`mastra deploy` command builds your project and compiles `src/mastra/` into `.mastra/output`. It packages that output as an artifact ZIP, then uploads and deploys it to a cloud sandbox.

部署轉換透過**queued → uploading → starting → deploying → running** or **failed** if something goes wrong. If a sandbox is already running for your project, the platform updates it in place with no downtime. Otherwise, it creates a fresh sandbox. Your instance URL is assigned per environment and remains stable across deploys to that environment.

請參閱[`mastra deploy` CLI reference](/reference/cli/mastra#mastra-deploy) for the full list of flags and CI/CD usage.

## 驗證 {/* #authentication */}

預設情況下，Mastra 平台上部署的每個 Studio 都受到平台身份驗證的保護。您的平台組織的成員使用其平台帳戶登錄，其他人無法存取已部署的 Studio。您無需配置任何內容即可獲得此行為。

平台身份驗證僅適用於 Studio UI。您的服务器的 API 路由由您自己控制[`server.auth`](/docs/studio/auth) configuration, or remain open if you haven't set one.

### 角色和權限 {/* #roles-and-permissions */}

平台身份驗證將您的組織角色對應到 Studio 權限：

|平台角色|工作室權限|
| - | - |
|`admin` | Full access (`*`) |
| `member` | Read and execute |
| `viewer` | Read-only |

若要自訂此映射，請設定`roleMapping` on `studio.rbac` in your Mastra configuration. When present, your mapping replaces the platform defaults. See [Role-based access control](/docs/studio/auth#role-based-access-control) for the permission format.

### 帶上你自己的授權 {/* #bring-your-own-auth */}

若要為已部署的 Studio 使用您自己的身份驗證Provider而不是平台身份驗證，請在專案上設定環境變數：

```bash
MASTRA_PLATFORM_STUDIO_AUTH=disabled
```

將其新增至您部署時使用的 env 檔案中，或透過儀表板儲存在專案中，然後重新部署。停用平台驗證後，部署不會影響您的身份驗證和 RBAC 配置。您自己的Provider驅動 Studio 登入流程，就像自架部署一樣。`studio.auth` protects the Studio UI, while `server.auth` protects your API routes. Studio requests fall back to `server.auth` when `studio.auth` isn't set.

:::警告
停用平台驗證會關閉平台帳號登入。如果您在沒有設定自己的驗證Provider的情況下停用它，則部署的 Studio 和所有 API 路由都可以公開存取。
:::

如果您啟用平台身份驗證並配置您自己的`studio.auth`, both providers validate tokens, but the login screen only offers the platform sign-in flow. To sign in through your own provider, disable platform auth.

## 環境文件 {/* #environment-files */}

本機環境檔案是可選的。當一個`.env` or `.env.*` file is present in the project directory, the deploy bundles its environment variables.

當存在多個 env 檔案時，CLI 會提示您選擇一個。若要以非互動方式選擇，請傳遞`--env-file`:

```bash
mastra deploy --env-file .env.production --yes
```

跨運行相同的程式碼庫`production` and `staging`, use [`mastra deploy --env`](/docs/mastra-platform/deploy#deploy-to-another-environment). See [Environments](/docs/mastra-platform/environments) for the full model.

## 以非互動方式建立一個新項目 {/* #create-a-new-project-non-interactively */}

在第一次運行時，`mastra deploy` can create a project. When `--project <name>` doesn't match an existing project, the CLI treats the value as a new project name and creates it after confirmation. Add `--yes` to make this flow fully scriptable:

```bash
mastra deploy --project "my-new-project" --yes
```

從 CI 或 AI 編碼Agent中使用它，而不是`mastra studio projects create`, which is interactive only.
