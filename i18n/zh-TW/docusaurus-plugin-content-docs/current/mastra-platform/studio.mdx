# Mastra 平台上的 Studio

Mastra 平台提供代管的視覺化 Studio 工作區，可用來測試 Agent、執行 Workflow，以及檢視追蹤紀錄。團隊可共用這個工作區，不必自行代管 Studio 介面。

你可以依照下方步驟用 CLI 部署 Studio，也可以連結 GitHub 儲存庫，讓推送觸發部署。連結儲存庫的流程請見 [GitHub 整合](/docs/mastra-platform/github)。

## 快速入門 {/* #quickstart */}

<Steps>
  <StepItem>
    依照[入門指南](/docs)建立第一個 Mastra 專案。
  </StepItem>

  <StepItem>
    在全域安裝 `mastra` CLI：

    ```bash npm2yarn
    npm install -g mastra
    ```
  </StepItem>

  <StepItem>
    用一行指令部署 Studio：

    ```bash
    mastra deploy
    ```

    部署成功時，CLI 會輸出已部署的 Studio 執行個體網址。
  </StepItem>
</Steps>

第一次部署時，CLI 會提示你建立新專案或選擇現有專案，接著在專案目錄建立 `.mastra-project.json`。這個檔案會連結本機與平台上的專案，內容包含 `projectId`、`projectName` 和 `organizationId`。請將它提交至儲存庫，讓 CI/CD 知道要部署到哪個專案。

## 部署流程 {/* #how-deploy-works */}

`mastra deploy` 會建置專案，將 `src/mastra/` 編譯到 `.mastra/output`，再將產出封裝成 ZIP 檔，上傳並部署至雲端沙箱。

部署會依序經過 **queued → uploading → starting → deploying → running**，出錯時會轉為 **failed**。若專案已有執行中的沙箱，平台會直接更新現有沙箱，服務不會中斷；否則會建立新的沙箱。執行個體的網址依環境分配，同一環境重新部署後仍使用相同的網址。

完整的旗標清單與 CI/CD 用法，請見 [`mastra deploy` CLI 參考文件](/reference/cli/mastra#mastra-deploy)。

## 驗證身分 {/* #authentication */}

在 Mastra 平台上部署的 Studio 預設受到平台身分驗證保護，不必另外設定。只有平台組織的成員能用自己的平台帳號登入，存取部署後的 Studio。

平台身分驗證只適用於 Studio 介面。伺服器的 API 路由由你自己的 [`server.auth`](/docs/studio/auth) 設定管理；未設定時，路由會保持開放。

### 角色與權限 {/* #roles-and-permissions */}

平台身分驗證會將組織角色對應到下列 Studio 權限：

| 平台角色 | Studio 權限 |
| - | - |
| `admin` | 完整存取權限（`*`） |
| `member` | 讀取與執行 |
| `viewer` | 唯讀 |

若要自訂對應方式，請設定 `roleMapping`（在 Mastra 設定的 `studio.rbac` 中）。設定後，自訂對應會取代平台預設值。權限格式請見[角色型存取控制](/docs/studio/auth#role-based-access-control)。

### 使用自己的身分驗證服務 {/* #bring-your-own-auth */}

若要讓部署後的 Studio 改用自己的身分驗證供應商，請在專案中設定下列環境變數：

```bash
MASTRA_PLATFORM_STUDIO_AUTH=disabled
```

將變數加到部署使用的環境變數檔，或透過管理介面儲存到專案，再重新部署。停用平台身分驗證後，部署程序會保留你的身分驗證及 RBAC 設定。Studio 會和自行代管時一樣，由你自己的供應商處理登入。`studio.auth` 保護 Studio 介面，`server.auth` 保護 API 路由。若未設定 `studio.auth`，Studio 請求會改用 `server.auth`。

:::warning
停用平台身分驗證後，就無法透過平台帳號登入。若停用時沒有設定自己的身分驗證供應商，任何人都可以存取部署後的 Studio 和所有 API 路由。
:::

若保留平台身分驗證，同時設定自己的 `studio.auth`，兩個供應商都會驗證權杖，但登入畫面只提供平台登入流程。若要透過自己的供應商登入，請停用平台身分驗證。

## 環境變數檔 {/* #environment-files */}

不一定要有本機環境變數檔。若專案目錄含有 `.env` 或 `.env.*` 檔，部署時會將檔案內的環境變數一併封裝。

若有多個環境變數檔，CLI 會請你選擇。若要略過互動提示，請用 `--env-file` 指定檔案：

```bash
mastra deploy --env-file .env.production --yes
```

若要在 `production` 和 `staging` 環境執行同一份程式碼，請使用 [`mastra deploy --env`](/docs/mastra-platform/deploy#deploy-to-another-environment)。完整的環境運作方式請見[環境](/docs/mastra-platform/environments)。

## 以非互動方式建立專案 {/* #create-a-new-project-non-interactively */}

第一次執行時，`mastra deploy` 可以建立專案。如果 `--project <name>` 沒有對應到現有專案，CLI 會將指定的值當成新專案名稱，並在確認後建立專案。加上 `--yes` 即可讓整個流程由指令碼自動執行：

```bash
mastra deploy --project "my-new-project" --yes
```

在 CI 或 AI 程式開發 Agent 中，請使用上述方式，因為 `mastra studio projects create` 只支援互動操作。
