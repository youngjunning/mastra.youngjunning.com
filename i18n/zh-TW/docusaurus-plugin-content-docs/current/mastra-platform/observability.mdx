# Mastra 平台的可觀測性

Mastra 平台可觀測性會收集 Mastra 應用程式的 Trace、日誌、指標、評分與回饋。使用它即可取得託管的可觀測性，無須部署 Studio 或 Server，也不必設定本機可觀測性儲存。

## 快速入門 {/* #quickstart */}

選擇符合專案情況的設定方式。

### 新專案 {/* #new-project */}

建立託管的 Mastra 專案，並在提示時啟用 Mastra 平台可觀測性：

```bash npm2yarn
npm create mastra@latest
```

create 指令會向 Mastra 平台驗證身分並建立可觀測性專案，接著建立存取權杖，將 `MASTRA_PLATFORM_ACCESS_TOKEN` 與 `MASTRA_PROJECT_ID` 寫入 `.env`。

### 現有項目 {/* #existing-project */}

若要將 Mastra 加入現有應用程式，請執行 `mastra init`，並在提示時啟用 Mastra 可觀測性：

```bash npm2yarn
npx mastra init
```

init 指令可選擇現有平台專案或建立新專案，接著建立存取權杖，將憑證寫入 `.env`。

## 手動配置 {/* #configure-manually */}

若略過平台設定或自動佈建失敗，請手動設定。

1. 在 [Mastra 平台](https://projects.mastra.ai)建立或開啟專案。
1. 為專案所屬組織建立存取權杖。
1. 從專案頁面複製專案 ID。
1. 將這兩個值加入 `.env`：

```bash title=".env"
MASTRA_PLATFORM_ACCESS_TOKEN=<your-platform-access-token>
MASTRA_PROJECT_ID=<your-project-id>
```

在可觀測性設定中註冊 [`MastraPlatformExporter`](/reference/observability/tracing/exporters/mastra-platform-exporter)：

```typescript title="src/mastra/index.ts"
import { Mastra } from '@mastra/core/mastra'
import { MastraPlatformExporter, Observability } from '@mastra/observability'

export const mastra = new Mastra({
  observability: new Observability({
    configs: {
      default: {
        serviceName: 'my-service',
        exporters: [new MastraPlatformExporter()],
      },
    },
  }),
})
```

Exporter 會從環境讀取存取權杖與專案 ID。請固定 `serviceName`，以便篩選可觀測性資料時區分應用程式與部署。

`MastraPlatformExporter` 會傳送已結束的 Span、日誌、指標、評分與回饋。它會緩衝事件，累積至 1,000 個事件或等待五秒後傳送一批。模型 Chunk Span 不會匯出。

:::note

`MastraPlatformExporter` 已取代 `CloudExporter`。`CloudExporter` 仍可用於向後相容，但已棄用。新程式碼請使用 `MastraPlatformExporter`。

:::

### 將資料儲存在本地 {/* #store-data-locally */}

若還希望將可觀測性資料持久化至已設定的 Mastra 儲存，並在本機 Studio 中檢視，請加入 `MastraStorageExporter`：

```typescript title="src/mastra/index.ts"
import { Mastra } from '@mastra/core/mastra'
import { MastraPlatformExporter, MastraStorageExporter, Observability } from '@mastra/observability'

export const mastra = new Mastra({
  observability: new Observability({
    configs: {
      default: {
        serviceName: 'my-service',
        exporters: [new MastraPlatformExporter(), new MastraStorageExporter()],
      },
    },
  }),
})
```

儲存需求與設定請參閱 [Mastra 儲存 Exporter](/docs/observability/integrations/exporters/mastra-storage)。

## 查看可觀測性資料 {/* #view-observability-data */}

在 [Mastra 平台](https://projects.mastra.ai)開啟專案，即可檢視匯出的 Trace、日誌、指標與評分，無須部署 Studio 或 Server。匯出的回饋可透過下述託管回饋 API 查詢。

維持一致的 `serviceName`，即可依特定應用程式或部署篩選資料。

## 查詢可觀測性資料 {/* #query-observability-data */}

使用 Mastra CLI 在終端機瀏覽託管 Trace：

```bash npm2yarn
npx mastra api trace list
```

CLI 從專案環境讀取 `MASTRA_PLATFORM_ACCESS_TOKEN` 與 `MASTRA_PROJECT_ID`，預設連至美國可觀測性端點。其他驗證方式與區域端點請參閱 [CLI 目標解析](/reference/cli/mastra#target-resolution)。

使用 `mastra api trace query` 依 Trace 欄位或相關 Span 尋找已完成的 Trace。例如，找出根 Span 耗時超過五秒的 Trace：

```bash
npx mastra api trace query '{
  "timeRange": {
    "from": "2026-08-01T00:00:00.000Z",
    "to": "2026-08-08T00:00:00.000Z"
  },
  "where": {
    "op": "gt",
    "left": { "path": "durationMs" },
    "right": { "literal": 5000 }
  },
  "page": { "limit": 25 }
}'
```

請選擇涵蓋已匯出 Trace、且在方案資料保留期內的時間範圍，並確保 `from` 早於 `to`。結果位於 `data.traces`。

Mastra 平台沿用 Mastra Server 的查詢與彙總請求結構。HTTP 端點、篩選器、回應格式、分頁與探索方式請參閱 [Trace 與 Span 查詢參考文件](/reference/observability/tracing/advanced-queries)：

| 工作 | CLI 指令 | 參考文件 |
| - | - | - |
| 尋找符合的 Trace | `mastra api trace query` | [查詢 Trace](/reference/observability/tracing/advanced-queries#query-traces) |
| 尋找個別 Span，包括巢狀執行 | `mastra api span query` | [查詢 Span](/reference/observability/tracing/advanced-queries#query-spans) |
| 彙總符合的 Trace | `mastra api trace aggregate` | [彙總 Trace](/reference/observability/tracing/advanced-queries#aggregate-traces) |
| 彙總個別 Span | `mastra api span aggregate` | [彙總 Span](/reference/observability/tracing/advanced-queries#aggregate-spans) |

每個指令都接收一個 JSON 參數，回應內容位於 `data` 之下。

### 平台範圍和差異 {/* #platform-scope-and-differences */}

使用 HTTP 標頭 `X-Mastra-Project-Id` 選擇單一專案。CLI 會從 `MASTRA_PROJECT_ID`、明確指定的標頭或專案設定中設定它。若未指定專案範圍，具組織層級存取權的憑證可跨專案查詢；綁定專案的憑證仍只能存取其專案。專案範圍須與查詢條件分開指定：不要在 `where` 中放入 `projectId`。

平台新增以下欄位與分組方式：

| 操作 | 平台新增功能 |
| - | - |
| `queryTraces()` 與 `querySpans()` | 每筆結果都包含 `projectId`。 |
| `aggregateTraces()` | 支援 `groupBy: ['projectId']` 與 `countDistinct.projectId`。 |
| `aggregateSpans()` | 支援 `groupBy: ['projectId']`，但不支援 `countDistinct.projectId`。 |

資料保留期限取決於方案：Starter 為 15 天、Teams 為 6 個月，Enterprise 則可自訂。最新方案限制請參閱[定價頁](https://mastra.ai/pricing)。

### 其他可觀測數據 {/* #other-observability-data */}

匯出的回饋可透過 HTTP 查詢。關於目前狀態、區域端點、驗證、專案範圍，以及 `traceId` 與 `environment` 等查詢參數，請參閱[回饋 API](/docs/mastra-platform/api#feedback-api)。

匯出的指標可透過 HTTP、`MastraClient` 或 `mastra api metric` 查詢。區域端點、驗證、專案範圍與支援的端點請參閱[指標 API](/docs/mastra-platform/api#metrics-api)。

## 匯入現有 Trace {/* #import-existing-traces */}

使用 `mastra traces import`，可將支援的 Provider 既有 Trace 歷史移至現有 Mastra 平台專案。此指令會在來源端讀取並驗證完整 Trace，轉換成 Mastra Span，再透過共用流程完成準備、上傳、續傳與驗證。

匯入指令目前支援 Langfuse。新增其他 Provider 配接器後，也可沿用相同的指令流程。

| Provider | 指令參數 | 來源需求 |
| - | - | - |
| Langfuse | `langfuse` | Langfuse Cloud 或自行託管的 Langfuse v4 以上版本 |

### 先決條件 {/* #prerequisites */}

開始匯入前，你需要：

- 一個 Mastra 平台專案。
- 透過 `mastra auth login` 完成 Mastra 平台驗證；無互動環境則提供 `MASTRA_API_TOKEN` 與 `MASTRA_ORG_ID`。
- 互動式登入時供上傳與回讀使用的 `MASTRA_PLATFORM_ACCESS_TOKEN`。試執行不需要此權杖。
- 受支援來源 Provider 的憑證。
- 足夠的本機磁碟空間，用來暫存準備好的 Trace。

### 配置目的地 {/* #configure-the-destination */}

互動式匯入時，請登入並選擇目的地專案所屬組織：

```bash
npx mastra auth login
npx mastra auth orgs switch
```

互動式登入允許探索專案。上傳或驗證 Trace 前，請設定目的地專案使用的平台存取權杖：

```bash title=".env"
MASTRA_PLATFORM_ACCESS_TOKEN=<mastra-platform-access-token>
```

若 `mastra init` 已為專案設定可觀測性，可使用它寫入 `.env` 的權杖；否則，請在 [Mastra 平台](https://projects.mastra.ai)建立存取權杖。

`--dry-run` 不需要此權杖，因為試執行不會連線至收集器或查詢 API。

`--target-project` 指定接收 Trace 的 Mastra 平台目的地專案。可傳入專案名稱、slug 或 ID，也可設定 `MASTRA_PROJECT_ID`：

```bash
npx mastra traces import langfuse --target-project my-mastra-project --dry-run
```

`--target-project` 優先於 `MASTRA_PROJECT_ID`。若兩者都未提供，CLI 會使用 `.mastra-project.json` 中連結的專案。

來源專案不是命令列選項，而是由 `.env` 中的 Provider 憑證決定。上傳任何內容前，準備摘要會列出來源專案。

對無互動環境，請設定 API 權杖與組織 ID。指令使用 `MASTRA_API_TOKEN` 探索專案、上傳與回讀。還須設定專案 ID 或傳入 `--target-project`：

```bash title=".env"
MASTRA_API_TOKEN=<mastra-api-token>
MASTRA_ORG_ID=<organization-id>
MASTRA_PROJECT_ID=<project-id>
```

### 配置Langfuse {/* #configure-langfuse */}

Langfuse API 金鑰只屬於一個 Langfuse 專案，因此也決定了來源專案。請在 Langfuse [建立專案 API 金鑰](https://langfuse.com/docs/api-and-data-platform/features/public-api)，再將它們加入執行指令所在目錄的 `.env` 或 `.env.local`：

```bash title=".env"
LANGFUSE_PUBLIC_KEY=<langfuse-public-key>
LANGFUSE_SECRET_KEY=<langfuse-secret-key>
```

Langfuse Cloud 預設使用 `https://cloud.langfuse.com` 的歐盟區域。若使用美國、日本、HIPAA Cloud 或自行託管的執行個體，請將 `LANGFUSE_BASE_URL` 設為對應的[區域主機](https://langfuse.com/security/data-regions)或自行託管執行個體的來源網址：

```bash title=".env"
LANGFUSE_BASE_URL=https://us.cloud.langfuse.com
```

### 預覽導入 {/* #preview-the-import */}

上傳前先試執行：

```bash
npx mastra traces import langfuse --target-project my-mastra-project --dry-run
```

試執行會讀取來源資料，在本機準備有效的 Mastra Trace，並回報：

- 來源 Langfuse 專案的名稱與 ID，以及目的地 Mastra 平台專案。
- 固定的匯入時間範圍。
- 已準備與已略過的 Trace 及 Span 數量。
- 已準備的本機資料大小。
- `report.json` 中的 Provider 警告與略過原因。

試執行不會上傳 Trace。指令會輸出一條 `--resume` 指令，之後可直接上傳已準備的資料，無須重新讀取來源。

### 選擇導入視窗 {/* #choose-the-import-window */}

預設選取截至匯入開始時的前 30 天。使用 `--since` 與 `--until` 可選擇較短的時間範圍：

```bash
npx mastra traces import langfuse \
  --target-project my-mastra-project \
  --since "$SINCE" \
  --until "$UNTIL" \
  --dry-run
```

將 `SINCE` 與 `UNTIL` 設為 ISO 8601 日期或時間戳記，並遵守下列規則：

- `--until` 必須位於過去 30 天內，且不能是未來時間。
- `--since` 必須早於 `--until`，且位於過去 30 天內。
- 選取的時間範圍不能超過 30 天。
- 若只設定 `--until`，預設起始時間為目前時間往前 30 天。

這個 30 天匯入範圍與方案的資料保留期限彼此獨立。

舊參數 `--from` 與 `--to` 仍可使用，但它們是 `--since` 與 `--until` 已棄用的隱藏別名，不會出現在指令說明中。新指令請使用 `--since` 與 `--until`。

是否納入 Trace 匯入，取決於根 Observation 的開始時間。Langfuse 配接器會在所選時間範圍中找出根節點，再讀取每條所選 Trace 目前可用的所有 Observation。若可用的父子樹或時間戳記無效，就會略過整條 Trace。

### 上傳並驗證 {/* #upload-and-verify */}

執行指令時不傳入 `--dry-run`，即可上傳已準備的 Trace：

```bash
npx mastra traces import langfuse --target-project my-mastra-project
```

CLI 會顯示準備摘要，並在上傳前要求確認。自動化環境可傳入 `--yes` 略過提示：

```bash
npx mastra traces import langfuse --target-project my-mastra-project --yes
```

匯入工具會將每條 Trace 完整放入同一個上傳請求，並僅在 Mastra 平台確認整批資料後記錄進度檢查點。來源或目的地的暫時性故障會進行有限次重試。

所有已準備的 Trace 獲確認後，匯入工具會回讀最多 10 條 Trace 的固定樣本，核對 Span ID、父子連結、名稱、Span 類型、事件旗標、時間戳記及是否有錯誤。它不會回讀或比較輸入、輸出、屬性、中繼資料或標籤。

若尚無法回讀，或樣本 Trace 有差異，匯入會暫停並保留已準備的資料。恢復匯入可重新驗證，無須再次上傳已確認的 Trace。

### 恢復導入 {/* #resume-an-import */}

試執行、取消、中斷、上傳失敗或暫停驗證後，若匯入尚未完成，請使用 CLI 輸出的原始指令恢復：

```bash
npx mastra traces import langfuse \
  --resume 00000000-0000-0000-0000-000000000000 \
  --target-project my-mastra-project
```

恢復匯入時必須使用原本的 Provider 與目的地專案。已儲存的時間範圍不能變更，因此 `--resume` 不得與 `--since`、`--until` 或 `--dry-run` 同時使用。

恢復方式取決於指令中斷的位置：

- 準備階段中斷：重新讀取並準備來源資料。
- 上傳階段中斷：從第一條尚未確認的 Trace 開始。
- 驗證暫停：重新回讀驗證，不重複上傳已確認的 Trace。
- 匯入已完成：回報已完成狀態，並重試剩餘的本機清理。

### 本地文件和清理 {/* #local-files-and-cleanup */}

匯入狀態儲存於：

```text
~/.mastra/imports/traces/<target-project-id>/<import-id>/
```

| 檔案 | 用途 | 生命週期 |
| - | - | - |
| `manifest.json` | 儲存來源身分、時間範圍、數量與已確認進度。 | 完成後保留。 |
| `traces.jsonl` | 每行儲存一條完整且已正規化的 Trace。 | 試執行與未完成匯入時保留，驗證成功後移除。 |
| `report.json` | 儲存數量、警告、略過樣本與驗證結果。 | 寫入後保留。 |

這些檔案可能包含 Trace 內容。Mastra 建立匯入目錄與檔案時，會將權限限制為本機使用者。請保護執行匯入的裝置與帳號。

### 導入的資料和限制 {/* #imported-data-and-limits */}

Langfuse 匯入有以下行為：

- Observation 會成為 Mastra Span，並保留父子關係與時間戳記。
- Langfuse `AGENT`、`TOOL` 與 `EVALUATOR` Observation，以及包含 `gen_ai.operation.name: invoke_agent` 等 OpenTelemetry GenAI 屬性的一般 Span，會保留其 Primitive 類型與名稱。Mastra 平台會像處理原生 Trace 一樣，在 Primitive type 與 Primitive name 欄顯示它們，並納入相應篩選器。
- 支援的欄位（例如名稱、輸入、輸出、錯誤、模型詳細資料、用量、成本、標籤與來源脈絡）會在存在時對應。
- 你在 Langfuse 設定的環境（例如 `staging`）會保留。Langfuse 內建的 `default` 環境不會複製；這些 Trace 在 Mastra 中沒有環境，Mastra Studio 會在每個環境顯示它們。
- 目的地 Trace 與 Span ID 具有決定性。原始 Langfuse ID 保留在 Span 中繼資料中，供關聯使用。
- 未知的 Langfuse Observation 類型會變成一般 Span，並發出警告，不會無聲捨棄。
- 只匯入 Trace Observation。評分、回饋、資料集、附件與日誌都不會匯入。

共用匯入工具也受下列限制：

- 每次匯入所準備的本機 Trace 資料上限為 5 GiB。若達到上限，請縮短時間範圍。
- 單條完整 Trace 必須符合匯入工具 4 MiB 上傳酬載上限。超出上限會被略過，並記錄 `trace_too_large` 原因。
- 不會將一條 Trace 拆分到多個上傳請求中。

試執行或完成匯入後，請查看 `report.json`，核對實際準備、略過、確認與驗證的內容。

完整選項與環境變數請參閱 [`mastra traces import` CLI 參考文件](/reference/cli/mastra#mastra-traces-import)。
