# 設定

部署至 Mastra Platform 時，CLI 會產生 `.mastra-project.json` 設定檔，並解析平台提供的環境變數。你也可以選擇讀取本機的 `.env` 檔案。

本頁說明專案設定檔與環境變數的載入方式。

## 專案設定 {/* #project-config */}

首次執行 [`mastra deploy`](/docs/mastra-platform/deploy) 時會自動建立 `.mastra-project.json`，將本機專案連結至平台專案。[GitHub 整合](/docs/mastra-platform/github)也會將同一份檔案寫入已連結的儲存庫。

請將此檔案提交至版本控制系統，讓後續部署（包括 CI 部署）都能找到正確的專案。

設定檔範例如下。

```json title=".mastra-project.json"
{
  "projectId": "06daaac4-89b1-40f0-9e3f-0993e039a627",
  "projectName": "my-project",
  "organizationId": "org_01KNA5YSP52SX4M6YVSXC2MAHP"
}
```

| 欄位 | 說明 |
| - | - |
| projectId | 建立專案時指派的 UUID。 |
| projectName | 方便辨識的專案名稱，會顯示在儀表板及 CLI 輸出中。 |
| organizationId | 專案所屬的組織。部署、API 金鑰及資源全都以此組織為範圍。 |

## 環境變數 {/* #environment-variables */}

你可以省略本機環境變數檔。[`mastra deploy`](/docs/mastra-platform/deploy) 會從以下三個來源取得變數。

- **受管理的變數**由[託管資料庫](/docs/mastra-platform/database)等平台資源注入。這些變數由平台定義，無法編輯。
- **已儲存的變數**透過儀表板存入專案或環境。每次部署都會原樣使用，不需要本機檔案。
- **本機環境變數檔**。部署時只會疊加一份本機檔案，可以是 `--env-file` 指定的檔案、搭配 `--env` 部署時對應的 `.env.<environment>`，或專案內唯一的 `.env*` 檔案。如有多個候選檔案，CLI 會請你選擇。不同檔案的變數不會合併。

傳入 `--env-file` 可指定部署要使用的環境變數檔，無須依賴預設選擇。

```bash
mastra deploy --env-file .env.production --yes
```

部署前請檢查本機環境變數檔並移除敏感資訊，避免上傳僅供開發使用或個人使用的機密資料。

### Observability {/* #observability */}

下列環境變數用於設定 Mastra Platform 的 Observability 產品。

| 變數 | 說明 |
| - | - |
| `MASTRA_PLATFORM_ACCESS_TOKEN` | 組織範圍的存取權杖。CLI 在佈建可觀測性服務時寫入此權杖，並用它向平台驗證身分。 |
| `MASTRA_PROJECT_ID` | 平台專案的 UUID。`MastraPlatformExporter` 會用它將可觀測性資料連結至平台專案。部署 Studio 與 Server 時，會從 `.mastra-project.json` 讀取專案 ID。 |
| `MASTRA_PLATFORM_OBSERVABILITY_ENDPOINT` | 選填，可覆寫 `MastraPlatformExporter` 和 Studio 的可觀測性端點。若專案不在預設的美國區域，請指定該區域的收集端點，例如 `https://observability.eu.mastra.ai`。預設值為 `https://observability.mastra.ai`。 |
| `MASTRA_ORG_ID` | 覆寫 CLI 指令目前使用的組織。若指令支援 `--org`，也可用這個參數指定組織。 |

`MastraPlatformExporter` 會讀取 `MASTRA_PLATFORM_ACCESS_TOKEN`，在匯出資料至平台時驗證身分。

## 多個環境 {/* #multiple-environments */}

同一專案可在多個[環境](/docs/mastra-platform/environments)（例如 `production` 和 `staging`）執行同一份程式碼。每個環境各有 URL、已儲存的變數及部署紀錄，並共用同一份 `.mastra-project.json`。

```bash
mastra deploy --env production --yes
mastra deploy --env staging --env-file .env.staging --yes
```

:::note
舊版平台規定每個環境各用一個專案。現在只需保留一個專案，再分別部署至各個環境。
:::
