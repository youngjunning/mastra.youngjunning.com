# Mastra 平台的 GitHub 整合

GitHub 整合將 Mastra 平台專案連結到 GitHub 儲存庫。當您將變更推送到儲存庫時，Studio 和 Server 將自動部署。

:::note
此整合僅適用於 GitHub.com 上託管的儲存庫。目前不支援自架 GitHub Enterprise 實例。
:::

連結儲存庫後，平台：

- 每次推送至已設定的分支時，建置及部署 Studio 和 Server。
- 為從範本建立的專案佈建託管資料庫並設定 Gateway API 金鑰。
- 顯示每次部署的提交、分支和 Pull Request 資訊。
- 透過 GitHub 檢查回報建置狀態，並在專案儀表板顯示即時狀態標記和內嵌記錄。

## 何時使用 GitHub 整合 {/* #when-to-use-the-github-integration */}

當您需要以下任一功能時，請選擇 GitHub 整合：

- 推送至 `main` 或其他任何分支時觸發部署，也能為 Studio 和 Server 設定不同分支。
- 由平台使用 Mastra 範本建立專案骨架，並提供新儲存庫、託管資料庫和 Gateway API 金鑰。
- 在平台儀表板上查看 Pull Request 和提交資訊，以便判斷問題。

臨時部署或使用 GitHub 以外的 CI 服務時，仍可使用 CLI（`mastra studio deploy` 和 `mastra server deploy`）。純 CLI 流程請參閱 [Studio](/docs/mastra-platform/studio) 和 [Server](/docs/mastra-platform/server)。

## 安裝 Mastra GitHub 應用程式 {/* #install-the-mastra-github-app */}

此整合由 Mastra GitHub 應用程式提供支援。

應用程式會讀取儲存庫內容、監聽已設定分支的 `push` 事件，並透過 GitHub 檢查回報部署狀態。

<Steps>
  <StepItem>
    在 [Mastra 平台儀表板](https://projects.mastra.ai) 開啟組織設定，找到 **GitHub App** 區段。
  </StepItem>

  <StepItem>
    選取 **Install GitHub App**，再選擇要安裝到哪個 GitHub 帳號或組織。

    若你不是 GitHub 組織的擁有者，GitHub 會建立待管理員核准的**安裝請求**。儀表板會同時追蹤待核准的請求與已完成的安裝。
  </StepItem>

  <StepItem>
    選擇應用程式可以存取的儲存庫。您可以限制特定儲存庫或授予帳戶上所有儲存庫的存取權限。

    您可以隨時從 GitHub 的應用程式設定撤銷或變更儲存庫存取權限。
  </StepItem>
</Steps>

:::note
如果 GitHub 日後更新應用程式所需的權限，儀表板會顯示**權限已過期**的警告和核准連結。管理員重新核准前，儲存庫操作會傳回 `403`。
:::

### 待處理的安裝請求 {/* #pending-installation-requests */}

當非管理員在組織上請求應用程式時，該請求將保持待處理狀態，直到組織管理員在 GitHub.com 上批准為止。儀表板：

- 在活動安裝旁邊列出待處理的請求。
- 允許同一使用者同時要求存取多個 GitHub 帳戶。
- 當您開啟頁面時，根據 GitHub 協調待處理狀態，刪除管理員已拒絕的請求或請求者已撤回的請求。

若要取消待處理的請求，請在儀表板選取該請求旁的 **Cancel**。

## 從範本建立項目 {/* #create-a-project-from-a-template */}

模板是最快的入門方式。該平台從 Mastra 模板創建一個新的儲存庫，並將其連結到一個新專案。然後，它提供模板聲明的任何託管資料庫並運行第一次部署。

<Steps>
  <StepItem>
    在儀表板選取 **Create project**，再選取 **Start from a template**。
  </StepItem>

  <StepItem>
    選擇一個範本並選擇擁有新儲存庫的 GitHub 帳戶。為儲存庫命名並選擇它是否應該是私有的。
  </StepItem>

  <StepItem>
    配置範本的託管資料庫要求。範本可以聲明所需的資料庫（例如 Turso 或 Neon），您可以根據要求選擇Provider和區域。
  </StepItem>

  <StepItem>
    新增範本所需的環境變數，例如 AI Provider 的 API 金鑰。平台會自動設定 `MASTRA_GATEWAY_API_KEY` 和 `MASTRA_PLATFORM_ACCESS_TOKEN`，讓範本中呼叫 Gateway 的程式碼在首次部署時就能執行。
  </StepItem>

  <StepItem>
    選取 **Create project**。平台會建立包含 `.mastra-project.json` 設定檔的儲存庫、佈建託管資料庫，接著觸發 Studio 和 Server 的首次部署。
  </StepItem>
</Steps>

首次部署會等託管資料庫佈建完成才開始，因此範本第一次建置時就能取得資料庫連線環境變數。

## 連結現有儲存庫 {/* #link-an-existing-repository */}

當您在 GitHub 儲存庫中已有 Mastra 專案時，請使用此流程。

<Steps>
  <StepItem>
    在儀表板選取 **Create project**，再選取 **Connect an existing repository**。也可開啟現有專案，在專案設定選取 **Link repository**。
  </StepItem>

  <StepItem>
    選擇一個安裝，然後選擇儲存庫。儲存庫搜尋適用於應用程式在該安裝上有權存取的每個儲存庫。
  </StepItem>

  <StepItem>
    選擇 Studio 和 Server 的部署分支。兩個目標預設都採用儲存庫的預設分支，也可以各用不同分支。

    你可以在專案中停用 Studio 或 Server。兩者皆已設定時，手動部署面板 **Deploy from GitHub** 預設會勾選兩個目標。
  </StepItem>

  <StepItem>
    選取 **Link repository**。平台會檢查儲存庫是否已包含指向其他專案的 `.mastra-project.json` 檔案。若有，儀表板會顯示警告及 **Overwrite** 選項，可在連結時取代該檔案。
  </StepItem>
</Steps>

連結後，下一次推送到配置的分支會觸發部署。

### `.mastra-project.json`衝突 {/* #mastra-projectjson-conflicts */}

平台會在每個已連結的儲存庫寫入 `.mastra-project.json` 檔案，以識別專案。如果儲存庫已有這個檔案，儀表板會在送出連結前檢查檔案內容：

- **遺失的**：平台在連結上建立文件。
- **匹配**：該文件已指向您正在連結的項目，因此無需進行任何更改。
- **衝突**：該文件指向不同的項目。您可以取消或明確覆蓋該文件。

檔案結構請參閱[設定](/docs/mastra-platform/configuration)。

## 推送時觸發部署 {/* #push-to-deploy */}

連結儲存庫後，每次推送到配置的分支都會觸發部署：

- 推送至 **Studio 分支**時會觸發 Studio 部署。
- 推送至 **Server 分支**時會觸發 Server 部署。
- 如果兩個目標共用一個分支，則一次推送會觸發兩個目標並行部署。

每個部署都帶有提交 SHA、分支和（如果可用）引入提交的拉取請求編號。建置在平台內運行，並在提交上運行檢查時將狀態報告回 GitHub。

每個部署目標一次只執行一個建置。若建置期間收到新的推送，平台會取消同一目標中仍在等候的舊建置，執行最新的建置。Studio 和 Server 的建置各自追蹤，因此兩者都已設定時可平行執行。

### 手動 GitHub 部署 {/* #manual-github-deploys */}

你也可以直接在儀表板觸發部署，不必推送。開啟專案並選取 **Deploy from GitHub**，選擇部署目標（Studio、Server 或兩者）和分支後送出。平台會部署該分支的最新提交，並將這次觸發記錄為 **GitHub Workflow** 部署。

## 追蹤部署 {/* #track-deploys */}

從範本建立專案或連結儲存庫後，**Setup** 頁面會為每個部署目標顯示一列。每一列都會：

- 顯示即時狀態徽章，輪詢部署至完成。
- 透過部署 ID 連結到部署詳細資訊頁面。
- 提供 **Show logs** 開關，在頁面內串流顯示建置和執行記錄。部署進行時，每三秒輪詢一次 Server 記錄。

## 權限和撤銷 {/* #permissions-and-revocation */}

若要停止從儲存庫部署，請執行下列其中一項操作：

- 在 **Project settings → Repository** 解除專案與儲存庫的連結。專案會保留歷史紀錄，日後仍可連結其他儲存庫。
- 在 GitHub.com 撤銷 Mastra GitHub App 對儲存庫的存取權限。現有部署會繼續執行，之後的推送不再觸發部署。
- **卸載 GitHub 應用程式**來自 GitHub 帳戶。這將刪除對該帳戶上每個儲存庫的存取權限。

若 GitHub 撤銷或輪替應用程式的安裝權杖，讀取儲存庫時會傳回 `github_app_permissions_outdated` 錯誤，儀表板會提示管理員重新核准權限。
