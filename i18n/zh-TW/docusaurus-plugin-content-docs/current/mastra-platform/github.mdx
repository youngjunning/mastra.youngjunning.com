# Mastra 平台上的 GitHub 集成

GitHub 整合將 Mastra 平台專案連結到 GitHub 儲存庫。當您將變更推送到儲存庫時，Studio 和 Server 將自動部署。

:::注意
此整合僅適用於 GitHub.com 上託管的儲存庫。目前不支援自架 GitHub Enterprise 實例。
:::

連結儲存庫後，平台：

* 每次推送到配置的分支時都會建置和部署 Studio 和 Server。
* 為從範本建立的專案提供託管資料庫和網關 API 金鑰。
* 顯示每次部署的提交、分支和拉取請求上下文。
* 在檢查運行時將建置狀態回報回 GitHub，並透過即時狀態徽章和內聯日誌報告到專案儀表板。

## 何時使用 GitHub 集成 {/* #when-to-use-the-github-integration */}

當您需要以下任一功能時，請選擇 GitHub 整合：

* 推送部署自`main` or any other branch, including separate branches for Studio and Server.
* 託管的入門流程，從 Mastra 範本建立項目，包括新的儲存庫、託管資料庫和網關 API 金鑰。
* 在平台儀表板內拉取請求並提交上下文以進行分類。

CLI 流程（`mastra studio deploy` and `mastra server deploy`) is still available for ad-hoc deploys and CI providers other than GitHub. See [Studio](/docs/mastra-platform/studio) and [Server](/docs/mastra-platform/server) for the CLI-only path.

## 安裝 Mastra GitHub 應用程式 {/* #install-the-mastra-github-app */}

此整合由 Mastra GitHub 應用程式提供支援。

該應用程式讀取存儲庫內容並監聽`push` events on the configured branches. It writes deploy status back as check runs.

<Steps>
  <StepItem>
    在[Mastra platform dashboard](https://projects.mastra.ai), open your organization settings. The page includes a **GitHub App** section.
  </StepItem>

  <StepItem>
    選擇**Install GitHub App** and choose the GitHub account or organization to install on.

    如果您不擁有 GitHub 組織，GitHub 會建立一個待處理的組織**installation request** that an admin must approve. The dashboard tracks pending requests alongside completed installations.
  </StepItem>

  <StepItem>
    選擇應用程式可以存取的儲存庫。您可以限制特定儲存庫或授予帳戶上所有儲存庫的存取權限。

    您可以隨時從 GitHub 的應用程式設定撤銷或變更儲存庫存取權限。
  </StepItem>
</Steps>

:::注意
如果 GitHub 稍後更新應用程式所需的權限，儀表板會顯示**outdated permissions** warning with an approval link. Repository operations return a `403` until an admin re-approves.
:::

### 待處理的安裝請求 {/* #pending-installation-requests */}

當非管理員在組織上請求應用程式時，該請求將保持待處理狀態，直到組織管理員在 GitHub.com 上批准為止。儀表板：

* 在活動安裝旁邊列出待處理的請求。
* 允許同一使用者同時要求存取多個 GitHub 帳戶。
* 當您開啟頁面時，根據 GitHub 協調待處理狀態，刪除管理員已拒絕的請求或請求者已撤回的請求。

若要取消待處理的請求，請選擇**Cancel** next to it in the dashboard.

## 從範本建立項目 {/* #create-a-project-from-a-template */}

模板是最快的入門方式。該平台從 Mastra 模板創建一個新的儲存庫，並將其連結到一個新專案。然後，它提供模板聲明的任何託管資料庫並運行第一次部署。

<Steps>
  <StepItem>
    在儀表板中，選擇**Create project** and choose **Start from a template**.
  </StepItem>

  <StepItem>
    選擇一個範本並選擇擁有新儲存庫的 GitHub 帳戶。為儲存庫命名並選擇它是否應該是私有的。
  </StepItem>

  <StepItem>
    配置範本的託管資料庫要求。範本可以聲明所需的資料庫（例如 Turso 或 Neon），您可以根據要求選擇Provider和區域。
  </StepItem>

  <StepItem>
    新增任何特定於範本的環境變數（例如，AI Provider API 金鑰）。平台種子`MASTRA_GATEWAY_API_KEY` and `MASTRA_PLATFORM_ACCESS_TOKEN` automatically so that template code that talks to the Gateway works on the first deploy.
  </StepItem>

  <StepItem>
    選擇**Create project**. The platform creates the repository with a `.mastra-project.json` config file, provisions its managed databases, then triggers the initial Studio and Server deploys.
  </StepItem>
</Steps>

初始部署在開始之前等待託管資料庫完成配置，因此範本的第一次建置會看到資料庫連接環境變數。

## 連結現有儲存庫 {/* #link-an-existing-repository */}

當您在 GitHub 儲存庫中已有 Mastra 專案時，請使用此流程。

<Steps>
  <StepItem>
    在儀表板中，選擇**Create project** and choose **Connect an existing repository**, or open an existing project and select **Link repository** from the project settings.
  </StepItem>

  <StepItem>
    選擇一個安裝，然後選擇儲存庫。儲存庫搜尋適用於應用程式在該安裝上有權存取的每個儲存庫。
  </StepItem>

  <StepItem>


    您可以為專案停用 Studio 或 Server。手冊**Deploy from GitHub** drawer selects both targets by default when both are configured.
  </StepItem>

  <StepItem>
    選擇**Link repository**. The platform validates that the repository doesn't already have a `.mastra-project.json` file pointing at a different project. If it does, the dashboard warns you and offers an **Overwrite** option that replaces the file on link.
  </StepItem>
</Steps>

連結後，下一次推送到配置的分支會觸發部署。

### `.mastra-project.json`衝突 {/* #mastra-projectjson-conflicts */}

平台寫了一個`.mastra-project.json` file into every linked repository to identify the project. When you link a repository that already has one of these files, the dashboard checks its contents before submitting:

* **遺失的**：平台在連結上建立文件。
* **匹配**：該文件已指向您正在連結的項目，因此無需進行任何更改。
* **衝突**：該文件指向不同的項目。您可以取消或明確覆蓋該文件。

看[Configuration](/docs/mastra-platform/configuration) for the file's schema.

## 一鍵部署 {/* #push-to-deploy */}

連結儲存庫後，每次推送到配置的分支都會觸發部署：

* **Studio branch** triggers a Studio deploy.
* **Server branch** triggers a Server deploy.
* 如果兩個目標共用一個分支，則一次推送會觸發兩個目標並行部署。

每個部署都帶有提交 SHA、分支和（如果可用）引入提交的拉取請求編號。建置在平台內運行，並在提交上運行檢查時將狀態報告回 GitHub。



### 手動 GitHub 部署 {/* #manual-github-deploys */}

您还可以从仪表板触发部署，而无需推送。打開項目並選擇**Deploy from GitHub**. Choose the target (Studio, Server, or both) together with a branch, then submit. The platform runs the deploy against the head commit of that branch and records the trigger as a **GitHub Workflow** deploy.

## 追蹤部署 {/* #track-deploys */}

從模板建立項目或連結到儲存庫後，**Setup** page shows one row per deploy target. Each row:

* 顯示即時狀態徽章，輪詢部署至完成。
* 透過部署 ID 連結到部署詳細資訊頁面。
* 暴露了一個**Show logs** toggle that streams build and runtime logs inline. Server logs poll every three seconds while the deploy is active.

## 權限和撤銷 {/* #permissions-and-revocation */}

若要停止從儲存庫部署，請執行下列其中一項操作：

* **取消連結儲存庫**從該項目中**Project settings → Repository**. The project keeps its history and you can re-link a different repository later.
* **刪除儲存庫存取權限**
* **卸載 GitHub 應用程式**來自 GitHub 帳戶。這將刪除對該帳戶上每個儲存庫的存取權限。

如果 GitHub 撤銷或輪換應用程式的安裝令牌，則儲存庫讀取將返回`github_app_permissions_outdated` error and the dashboard prompts an admin to re-approve permissions.
