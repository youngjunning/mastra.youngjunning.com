# LSP 代码检查

語言伺服器協定（LSP）讓 Agent 能取得專案程式碼的語意資訊。語言伺服器理解程式語言和專案結構，因此能找出符號的型別、宣告、實作與診斷資訊。

## LSP 提供哪些功能 {/* #what-lsp-adds */}

檔案與搜尋工具可回答不同的程式碼庫問題：

| 工具 | 適用情境 |
| - | - |
| `read_file` | 讀取已知檔案的原始內容及前後文 |
| `grep` | 在多個檔案中尋找符合文字或規則運算式的內容 |
| [搜尋](/docs/sandbox/search) | 依關鍵字或語意相似度擷取已建立索引的檔案 |
| LSP 檢查 | 取得型別相關資訊，並在專案中追蹤符號 |

LSP 檢查可搭配這些工具。Agent 可以先用 `grep` 找到符號，再透過 LSP 找到宣告，最後用 `read_file` 讀完整實作後再修改。

## 配置 LSP {/* #set-up-lsp */}

LSP 會啟動長時間執行的語言伺服器程序，並與它交換 JSON-RPC 訊息。啟用前請確認設定符合以下條件：

- 使用靜態 [Sandbox](/docs/sandbox/overview)，其程序管理員提供的程序控制代碼須有可讀的輸出串流與可寫的輸入串流。這裡不支援 Sandbox 解析函式。
- Mastra 應用程式已安裝 `vscode-jsonrpc` 與 `vscode-languageserver-protocol` 套件。
- 在 Sandbox 程序執行的環境安裝語言伺服器執行檔及其執行環境。
- 使用絕對路徑指定專案根目錄，Mastra 應用程式與 Sandbox 程序必須能透過相同路徑存取根目錄和專案檔案。

Mastra 內建 TypeScript 和 JavaScript、Python、Go 及 Rust 的伺服器定義，但仍須安裝相應的語言伺服器執行檔。其他檔案類型可[註冊其他伺服器](#custom-language-servers)。

安裝共用的協定套件：

```bash npm2yarn
npm install vscode-jsonrpc vscode-languageserver-protocol
```

接著為專案安裝語言伺服器。例如，安裝 TypeScript 及其語言伺服器：

```bash npm2yarn
npm install typescript typescript-language-server
```

建立靜態 `LocalSandbox`，讓檔案系統、Sandbox 和 LSP 根目錄都指向同一目錄：

```typescript title="src/mastra/workspaces.ts"
import { resolve } from 'node:path'
import { LocalFilesystem, LocalSandbox, Workspace } from '@mastra/core/workspace'

const projectPath = resolve('./workspace')

export const workspace = new Workspace({
  filesystem: new LocalFilesystem({
    basePath: projectPath,
  }),
  sandbox: new LocalSandbox({
    workingDirectory: projectPath,
  }),
  lsp: {
    root: projectPath,
  },
})
```

檔案系統提供 Agent 操作專案檔案的工具。第一次有 LSP 查詢需要語言伺服器時，Sandbox 會在相同目錄啟動它。若缺少任何必要的協定套件、程序管理員或伺服器執行檔，Mastra 會停用 LSP，或回報沒有可用的語言伺服器。

## 透過 Agent 工具檢查程式碼 {/* #inspect-code-with-the-agent-tool */}

啟用 LSP 後，Agent 可使用 `mastra_workspace_lsp_inspect`。輸入會指定檔案並將游標放在一個符號上：

```json
{
  "path": "/absolute/path/to/workspace/src/orders.ts",
  "line": 10,
  "match": "const order = await <<<findOrder(orderId)"
}
```

`line` 從 1 起算。將該行內容複製到 `match`，在要檢查的符號正前方插入一個 `<<<` 標記，只能插入一次。原始檔不含這個標記。

工具會傳回語言伺服器能提供的欄位：

| 字段 | 输出 |
| - | - |
| `hover` | 型別資訊或文件，以及其標記格式 |
| `diagnostics` | 被检查行的诊断严重程度、消息和来源 |
| `definition` | 宣告位置，可讀取檔案時附上單行預覽 |
| `implementation` | 实现位置 |
| `error` | 无法检查时返回配置、服务器或查询错误 |

無法取得的結果欄位會省略。依定義和實作的位置，可用 `read_file` 繼續閱讀完整脈絡。

## 调整 LSP 配置 {/* #configure-lsp */}

設定 `lsp: true` 可使用預設值。若要指定根目錄、伺服器探索方式、逾時或保留的用戶端，請改用物件：

```typescript oxfmt:false
lsp: {
  root: projectPath,
  diagnosticTimeout: 4_000,
  initTimeout: 8_000,
  maxOpenClients: 4,
  disableServers: ['eslint'],
  binaryOverrides: {
    typescript: '/opt/mastra-tools/typescript-language-server --stdio',
  },
  searchPaths: ['/opt/mastra-tools'],
},
```

`binaryOverrides` 可將內建伺服器 ID 對應至完整的啟動指令。`searchPaths` 可加入套件根目錄，其中的 `node_modules` 可能含有所需模組或執行檔。最後還可設定 `packageRunner`，例如 `pnpm dlx`。此備援方式預設停用，因為它可能安裝軟體，或在某些專案結構中停滯。

`diagnosticTimeout` 控制直接呼叫 `getDiagnostics()` 與 `getDiagnosticsMulti()` API 時等待診斷的時間。Agent 檢查工具目前最多等待五秒。

Mastra 通常從各檔案的位置往上尋找該伺服器的專案標記，藉此判定專案根目錄。若找不到標記，會改用 `lsp.root`。完整選項及預設值請參閱 [LSP 設定參考](/reference/workspace/workspace-class)。

### 限制保留的用戶端數量 {/* #limit-retained-clients */}

`maxOpenClients` 限制單一設定保留的語言伺服器用戶端數量，必須為正整數。達到上限後，Mastra 會在沒有使用中查詢租約的用戶端中，關閉最久未使用的一個。

如果保留的用戶端都有使用中的租約，下次取得租約時最多等待五秒。若仍無可用租約，`prepareQuery()` 和 `getDiagnostics()` 會傳回 `null`，`getDiagnosticsMulti()` 則略過無法取得用戶端的伺服器。省略 `maxOpenClients` 時，保留數量沒有上限。Mastra Code 的預設上限為 `4`。

### 重新命名工具 {/* #tool-name-remapping */}

透過 `tools` 設定 Agent 檢查工具。例如，加入以下項目就能使用較短的工具名稱：

```typescript
import { WORKSPACE_TOOLS } from '@mastra/core/workspace'

const tools = {
  [WORKSPACE_TOOLS.LSP.LSP_INSPECT]: {
    name: 'lsp_inspect',
  },
}
```

將 `tools` 與 `lsp` 設在同一層。`name` 會變更對外提供的工具名稱，設定鍵仍為 `WORKSPACE_TOOLS.LSP.LSP_INSPECT`。若要移除工具，在同一個項目設定 `enabled: false`。

產生的 Agent 工具共用的核准設定、動態政策、輸出限制及掛鉤，請參閱[工具設定參考](/reference/workspace/workspace-class#tool-configuration)。

## 自定义语言服务器 {/* #custom-language-servers */}

若語言沒有內建支援，或需要取代內建定義，請在 `lsp.servers` 下新增伺服器：

```typescript oxfmt:false
lsp: {
  root: projectPath,
  servers: {
    phpactor: {
      id: 'phpactor',
      name: 'Phpactor Language Server',
      languageIds: ['php'],
      extensions: ['.php'],
      markers: ['composer.json'],
      command: 'phpactor language-server',
      initializationOptions: {
        indexer: { enabled: true },
      },
    },
  },
},
```

每個定義支援下列欄位：

| 字段 | 必填 | 说明 |
| - | - | - |
| `id` | 是 | 唯一的伺服器 ID。使用內建 ID 可取代對應的定義。 |
| `name` | 是 | 用於記錄與錯誤訊息的易讀名稱。 |
| `languageIds` | 是 | 伺服器處理的 LSP 語言識別碼。 |
| `extensions` | 是 | 伺服器處理的副檔名，包含開頭的點。 |
| `markers` | 是 | 用來尋找專案根目錄的檔案或目錄。 |
| `command` | 是 | 启动服务器的完整命令。 |
| `initializationOptions` | 否 | LSP 初始化交握時傳送的設定。 |

自訂定義會與內建定義合併。若 `id` 相同，由自訂定義取代內建定義。如果伺服器列出多個語言 ID，Mastra 會將設定的每個副檔名對應至第一個語言 ID。

## 直接查询 LSP {/* #query-lsp-directly */}

應用程式碼可直接查詢已設定的 LSP 管理器。`getDiagnostics()` 和 `getDiagnosticsMulti()` 會自行管理用戶端租約，以及文件開啟與關閉通知。

`prepareQuery()` 可取得用戶端，直接查詢游標停留資訊、定義、實作等。請傳入絕對檔案路徑，它會開啟檔案並傳回租約。請先關閉檔案再釋放租約，並將這兩個呼叫都放在 `finally` 區塊：

```typescript
async function inspectHover(filePath: string, line: number, character: number) {
  const query = await workspace.lsp?.prepareQuery(filePath)
  if (!query) return null

  try {
    return await query.client.queryHover(query.uri, {
      line,
      character,
    })
  } finally {
    query.client.notifyClose(filePath)
    query.release()
  }
}
```

直接使用用戶端時，位置索引從 0 起算。若已設定 `maxOpenClients`，未釋放的租約可能使閒置用戶端無法被清除。拆除時，Mastra 最多等待五秒讓使用中的租約釋放，接著會強制關閉語言伺服器。受管理的 LSP 用戶端會在 Sandbox 銷毀前關閉。

## 限制 {/* #limitations */}

- LSP 只支援有對應內建或自訂伺服器的檔案類型。
- 單靠檔案系統無法執行語言伺服器。LSP 需要具備雙向程序管理功能的靜態 Sandbox。
- `LocalFilesystem` 的目錄限制和 `allowedPaths` 不會限制 LSP 檢查。請將 `lsp.root` 限制在受信任的專案中。如果使用者可以提交不可信任的主機路徑，請勿開放 LSP 工具。
- 檢查外部套件時，可能找到 `.d.ts` 等宣告檔，而非執行階段的原始碼。
- 語言伺服器可能略過不支援的游標停留資訊、診斷、定義或實作結果。

### 遠端 Sandbox {/* #remote-sandboxes */}

遠端 LSP 仍依賴主機。語言伺服器指令會透過遠端 Sandbox 的程序管理員執行，但搜尋執行檔、讀取檔案和部分原始碼預覽仍由 Mastra 主機處理。

符合下列所有條件時，才使用遠端 LSP：

- 遠端程序管理員提供可讀的輸出串流與可寫的輸入串流。
- 專案在 Mastra 主機與遠端 Sandbox 中使用相同的絕對路徑。
- 解析出的伺服器指令已安裝在遠端映像檔內。內建伺服器使用 `binaryOverrides` 設定，自訂伺服器則使用 `lsp.servers.command`。
- 主機能讀取檢查與定義預覽所需的檔案。

本機檔案系統與遠端 Sandbox 不會自動同步。只安裝在主機的執行檔無法在遠端 Sandbox 執行，只存在遠端的檔案也無法提供完整的主機端結果。若專案只存在遠端，在 LSP 能跨後端一致存取檔案以前，請用 `grep`、索引[搜尋](/docs/sandbox/search)及 Sandbox 指令。
