# 檔案系統中的 Skill

每個檔案系統 Skill 都是一個目錄，內含可重複使用的指令與輔助檔案。Mastra 會從 `skills` 選項指定的路徑找出 Skill，供使用這項設定的所有 Agent 使用。Skill 遵循 [Agent Skills 規格](https://agentskills.io)。

若要直接在某個 Agent 的程式碼定義 Skill，請使用 [Agent Skill](/docs/skills)。同一個 Agent 可以搭配使用兩種 Skill；兩者同名時，以直接定義的 Agent Skill 為準。

## 快速入門 {/* #quickstart */}

建立目錄，並在其中新增 `SKILL.md` 檔案：

```markdown title="workspace/skills/code-review/SKILL.md"
---
name: code-review
description: Reviews code for bugs and readability issues
---

# Code review

Check the code for bugs, missing error handling, and unclear naming.
```

設定此目錄：

```typescript title="src/mastra/workspaces.ts"
import { LocalFilesystem, Workspace } from '@mastra/core/workspace'

export const workspace = new Workspace({
  filesystem: new LocalFilesystem({
    basePath: './workspace',
  }),
  skills: ['skills'],
})
```

`skills` 的路徑以檔案系統根目錄為基準，因此 Mastra 會找到 `./workspace/skills/code-review/SKILL.md`。採用這項設定的 Agent 可在處理請求時視需要找出並載入 `code-review`。

## Skill 的目錄結構 {/* #skill-structure */}

每個 Skill 都有自己的目錄，其中必須有 `SKILL.md`，也可以放入輔助檔案：

```plaintext title="workspace/skills/code-review"
code-review/
  SKILL.md
  references/
    style-guide.md
  scripts/
    lint.ts
  assets/
    review-template.md
```

- `SKILL.md`：中繼資料與指令，Mastra 會在 Agent 選用 Skill 時載入
- `references/`：供 Agent 視需要讀取或搜尋的文件
- `scripts/`：Skill 使用的指令碼
- `assets/`：範本、圖片及其他輔助檔案

將主要流程寫在 `SKILL.md`，並把詳細資料移到 `references/`，讓 Agent 在需要時才讀取。

## `SKILL.md` 格式 {/* #skillmd-format */}

YAML frontmatter 必須包含 `name` 和 `description`。`name` 必須與 Skill 目錄同名，最多 64 個字元，且只能使用小寫字母、數字或連字號。連字號不得置於開頭或結尾，也不得連續出現。載入 Skill 時，Markdown 內文會以指令的形式傳回給 Agent。

Mastra 也會讀取選填欄位 `license`、`compatibility`、`user-invocable` 與 `metadata`。完整套件格式及欄位說明請見 [Agent Skills 規格](https://agentskills.io/specification)。

## Agent 如何使用 Skill {/* #how-agents-use-skills */}

設定 Skill 後，Mastra 會將每個 Skill 的名稱、描述、路徑與來源類型加入系統訊息。Agent 不必將每份指令檔都載入上下文，就能發現可用的 Skill。

Mastra 也提供三個工具給 Agent：

| 工具 | 用途 |
| - | - |
| `skill` | 載入 Skill 的 `SKILL.md` 指令，並列出參考資料、指令碼及資源檔案。 |
| `skill_read` | 讀取所選 Skill 目錄下任一檔案的全部或部分內容。 |
| `skill_search` | 搜尋 Skill 的名稱、描述、指令與參考檔案。 |

載入是無狀態的。指令會以工具結果保留在對話中；若上下文壓縮後不再包含這些指令，Agent 可以再次呼叫 `skill`。

### 關閉 Skill 清單 {/* #turn-off-the-skills-list */}

Skill 數量一多，每次請求都在系統訊息列出完整清單會耗用 token。加入 `SkillsProcessor` 並設定 `injectCatalog: false`，即可用簡短指令取代清單，讓 Agent 用 `skill_search` 搜尋，再用 `skill` 載入：

```typescript title="src/mastra/agents/support-agent.ts"
import { Agent } from '@mastra/core/agent'
import { SkillsProcessor } from '@mastra/core/processors'
import { workspace } from '../workspaces'

export const supportAgent = new Agent({
  id: 'support-agent',
  name: 'Support Agent',
  instructions: 'You help customers with support requests.',
  model: '__GATEWAY_OPENAI_MODEL__',
  workspace,
  inputProcessors: [new SkillsProcessor({ injectCatalog: false })],
})
```

檔案系統 Skill 和 [Agent Skill](/docs/skills) 都仍可使用 `skill`、`skill_read` 與 `skill_search`。`skill_search` 不需額外設定，會依查詢詞比對 Skill 的名稱、描述和內容。Skill 較多時，可在 Workspace 設定 [BM25 或向量搜尋](#search-skill-content)以改善排序。Agent Skill 一律會建立索引。

只有幾十個 Skill 時，可保留預設清單，讓 Agent 一次看到所有選項，Provider 也能快取這段固定的前綴。若 Skill 達到約一百個，或需要控制系統訊息長度，可關閉清單。搜尋指令的長度不受 Skill 數量影響。

[`SkillSearchProcessor`](/reference/processors/skill-search-processor) 也會隱藏清單，但會用自己的 `search_skills` 和 `load_skill` 取代標準工具，而且僅涵蓋 Workspace Skill。請擇一設定；若兩者都設定，Agent 會取得兩套工具。所有選項請見 [`SkillsProcessor`](/reference/processors/skills-processor) 參考文件。

## 設定 Skill 路徑 {/* #configure-skill-paths */}

`skills` 陣列接受下列路徑格式：

| 路徑 | 探索方式 |
| - | - |
| `skills` | 檢查每個直接子目錄是否有 `SKILL.md` 檔案。 |
| `skills/code-review` | 直接載入單一 Skill 目錄。 |
| `skills/code-review/SKILL.md` | 直接載入單一 Skill 檔案。 |
| `./**/skills` | 找出符合條件的目錄，再逐一探索其中的 Skill。 |
| `./**/SKILL.md` | 找出並載入符合條件的 Skill 檔案。 |

可加入多筆路徑，從專案、團隊或套件等不同的根目錄找出 Skill。

glob 從基準目錄往下最多走訪四層。

若有設定檔案系統，Mastra 會在該檔案系統中解析路徑；否則會以應用程式行程的目前工作目錄為基準，從本機磁碟讀取。明確指定 [`skillSource`](#custom-skill-sources) 會取代這兩種預設行為。

## 同名 Skill {/* #same-named-skills */}

Mastra 會在系統訊息中逐一列出檔案系統 Skill，並附上路徑及來源類型。若有多個同名 Skill，依名稱查找時會採用下列優先順序：

1. 本機專案路徑
1. `.mastra/skills` 底下的受管理路徑
1. `node_modules` 底下的外部路徑

若有多個最高優先順位的候選項目屬於同一來源類型，Mastra 無法判定該選哪一個，會擲出錯誤。請重新命名其中一個 Skill，或將它移到不同類型的來源。

Agent 可將系統訊息上顯示的確切路徑傳給 `skill` 或 `skill_read`，略過名稱解析。路徑結尾可保留或省略 `/SKILL.md`。若多筆設定路徑解析後指向同一個正規目錄，Mastra 會將它們視為別名，只列出一次該 Skill。

Mastra 會先解析直接定義的 [Agent Skill](/docs/skills)，再解析檔案系統 Skill。兩者同名時，以直接定義的 Skill 為準。

## 搜尋 Skill 內容 {/* #search-skill-content */}

若同時設定 Skill 與 [BM25 或向量搜尋](/docs/sandbox/search)，Mastra 會自動為每個 Skill 的名稱、描述、`SKILL.md` 指令和參考檔案建立索引。指令碼與資源檔案不會建立索引。

沒有設定 BM25 或向量搜尋時，`skill_search` 會改用不區分大小寫的文字比對，搜尋名稱、描述、指令及參考資料。結果依命中的查詢詞數量排序，命中名稱或描述的詞權重較高。如此不必另行設定，就能搜尋 Skill；集合較大時，索引搜尋則提供排序與語意檢索。

來自參考檔案的結果會附上檔案路徑，例如 `references/style-guide.md`，Agent 可將路徑傳給 `skill_read`。

Agent 查詢不存在的 Skill 名稱時，若可用的 Skill 不超過 20 個，`skill` 和 `skill_read` 會列出所有項目。若超過 20 個，最多建議五個相近的項目，並引導 Agent 使用 `skill_search`，避免名稱打錯就將完整清單放入對話。

## 動態 Skill 路徑 {/* #dynamic-skill-paths */}

若可用路徑取決於請求上下文，可傳入同步或非同步函式。下例會為具有 `developer` 角色的使用者加入開發用的 Skill：

```typescript title="src/mastra/workspaces.ts"
import { LocalFilesystem, Workspace } from '@mastra/core/workspace'

const workspace = new Workspace({
  filesystem: new LocalFilesystem({ basePath: './workspace' }),
  skills: ({ requestContext }) => {
    const paths = ['skills']

    if (requestContext?.get('user-role') === 'developer') {
      paths.push('developer-skills')
    }

    return paths
  },
})
```

Mastra 每次執行時都會求得函式結果，並將該請求適用的 Skill 集合提供給 Agent。回傳的路徑和靜態陣列一樣，可以是目錄、檔案或 glob。

## 自訂 Skill 來源 {/* #custom-skill-sources */}

若要從已設定的檔案系統或本機磁碟之外的後端取得 Skill，請設定 `skillSource`。自訂來源會依照各個設定路徑探索 Skill 並讀取檔案。

例如，`CompositeVersionedSkillSource` 會從依內容定址的 Blob 儲存區掛載已發布的 Skill 版本，放在 Mastra 可以探索的目錄底下：

```typescript title="src/mastra/workspaces.ts"
import { CompositeVersionedSkillSource, Workspace } from '@mastra/core/workspace'

const skillSource = new CompositeVersionedSkillSource(
  [
    {
      dirName: 'code-review',
      tree: versionTree,
      versionCreatedAt,
    },
  ],
  blobStore,
)

const workspace = new Workspace({
  skills: ['.'],
  skillSource,
})
```

明確指定 `skillSource` 後，如果找不到路徑，Mastra 不會改回使用已設定的檔案系統或本機磁碟。來源介面與相關選項請見[設定參考](/reference/workspace/workspace-class#constructor-parameters)。
