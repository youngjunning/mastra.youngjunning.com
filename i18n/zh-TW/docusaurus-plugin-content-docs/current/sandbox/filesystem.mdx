# 檔案系統

檔案系統提供 Agent 讀取、寫入、列出和[搜尋](/docs/sandbox/search)檔案的工具。你可以用它做為知識庫，或在暫時性的 Sandbox 執行之間保留檔案。

檔案存取有兩種設定方式：

- [直接存取檔案系統](#direct-filesystem-access)：透過 `filesystem` 指定一個檔案系統提供者，或自行建立的 [`CompositeFilesystem`](#manual-composition)。
- [掛載](#mounts)：使用 `mounts`，將帶有路徑前綴的提供者組成 `CompositeFilesystem`。靜態 Sandbox 和檔案系統提供者都支援掛載時，Mastra 會自動將提供者掛載到設定的路徑。遠端 Sandbox 一般使用使用者空間檔案系統（FUSE）掛載。

`filesystem` 與 `mounts` 只能擇一設定。同時設定會擲出錯誤代碼為 `INVALID_CONFIG` 的 `WorkspaceError`。

兩種設定都會提供 Agent 檔案工具。Sandbox 必須成功掛載提供者，指令才能存取其檔案。

設定檔案系統後，Agent 會取得以下工具：

| 工具 | 功能 |
| - | - |
| `mastra_workspace_read_file` | 讀取檔案的部分或全部內容。 |
| `mastra_workspace_write_file` | 建立或覆寫檔案。 |
| `mastra_workspace_edit_file` | 取代現有檔案內符合條件的文字。 |
| `mastra_workspace_list_files` | 列出檔案和目錄。 |
| `mastra_workspace_delete` | 刪除檔案或目錄。 |
| `mastra_workspace_file_stat` | 傳回檔案或目錄的中繼資料。 |
| `mastra_workspace_mkdir` | 建立目錄及尚未存在的所有上層目錄。 |
| `mastra_workspace_grep` | 使用正規表示式搜尋檔案內容。 |
| `mastra_workspace_ast_edit` | 依程式碼結構套用編輯。安裝 `@ast-grep/napi` 後即可使用。 |
| `mastra_workspace_apply_patch` | 以單次呼叫建立、更新、移動和刪除多個檔案。預設停用。 |

`apply_patch` 工具須個別在 `tools` 中啟用。設定頂層 `tools.enabled` 不會啟用這項工具。工具會先檢查修補內容中的所有變更，再寫入檔案：

```typescript title="src/mastra/workspaces/index.ts"
import { Workspace, LocalFilesystem, WORKSPACE_TOOLS } from '@mastra/core/workspace'

export const workspace = new Workspace({
  filesystem: new LocalFilesystem({ basePath: './workspace' }),
  tools: {
    [WORKSPACE_TOOLS.FILESYSTEM.APPLY_PATCH]: { enabled: true },
  },
})
```

## 支援的檔案系統 {/* #supported-filesystems */}

### `LocalFilesystem` {/* #localfilesystem */}

[`LocalFilesystem`](/reference/workspace/local-filesystem) 會連到 Mastra 應用程式所在機器上的目錄，適合本機開發或存取應用程式主機上已有的檔案。

### 其他檔案系統 {/* #other-filesystems */}

如果檔案位於應用程式主機以外，或已存放在外部服務中，請選用其他提供者：

## 直接存取檔案系統 {/* #direct-filesystem-access */}

若要讓 Agent 透過檔案工具存取提供者，請使用 `filesystem`。它也接受解析函式或手動建立的 `CompositeFilesystem`。

以下範例讓 Agent 取得能操作本機知識庫的檔案工具：

```typescript
import { LocalFilesystem, Workspace } from '@mastra/core/workspace'

const workspace = new Workspace({
  filesystem: new LocalFilesystem({
    basePath: './knowledge-base',
  }),
})
```

Agent 會取得 `mastra_workspace_read_file`、`mastra_workspace_write_file`、`mastra_workspace_list_files` 和 `mastra_workspace_grep` 等工具。路徑會在 `./knowledge-base` 下解析，無須設定 Sandbox 或指令工具。

若要為檔案建立索引以便進行關鍵字或語意檢索，請見[搜尋](/docs/sandbox/search)。系統產生的所有工具及其政策請見[檔案系統工具參考](/reference/workspace/workspace-class#filesystem-tools)。

## 掛載 {/* #mounts */}

若 Sandbox 內的程式需要按路徑存取持久保存的檔案，請使用 `mounts`。Sandbox 和檔案系統提供者都支援時，Mastra 會自動掛載。Agent 仍可使用檔案工具，也可透過指令工具對相同檔案執行 `ls`、`cat` 或 `python` 等指令。

例如，將 S3 儲存貯體掛載到 Daytona Sandbox 內的 `/workspace`：

```typescript
import { Mastra } from '@mastra/core'
import { Workspace } from '@mastra/core/workspace'
import { DaytonaSandbox } from '@mastra/daytona'
import { S3Filesystem } from '@mastra/s3'

const workspace = new Workspace({
  mounts: {
    '/workspace': new S3Filesystem({
      bucket: process.env.S3_BUCKET!,
      region: 'us-east-1',
    }),
  },
  sandbox: new DaytonaSandbox(),
})

export const mastra = new Mastra({ workspace })
```

### 使用掛載 {/* #using-mounts */}

提供者現有的檔案會出現在 `/workspace` 下。Agent 可以呼叫 `read_file('/workspace/report.md')` 或執行 `cat /workspace/report.md`。透過任一介面寫入的檔案都會由提供者保存，Sandbox 停止後仍可存取。

沒有掛載時，Agent 仍可在工具呼叫之間傳遞檔案內容，搭配檔案工具和 Sandbox 指令使用。這適用於部分文字檔。若程式需要目錄樹，或需要處理大型檔案或二進位檔案，掛載會更合適。

:::warning

檔案工具與指令工具各有獨立的政策。例如，即使 `write_file` 須經核准，Agent 仍可透過 `execute_command` 寫入同一掛載路徑。若檔案只能透過檔案工具存取，請停用 Sandbox 的指令工具。

:::

### 路徑 {/* #paths */}

檔案工具可以使用掛載路徑，在 Sandbox 成功掛載後，指令也能使用。底層提供者可能會將檔案存放在其他位置。

以掛載在 `/workspace` 的遠端提供者為例：

- 檔案工具使用類似 `/workspace/report.md` 的路徑。
- 遠端 Sandbox 指令通常使用相同路徑。
- 提供者會將路徑對應到已設定的儲存貯體、前綴或遠端目錄。

`LocalSandbox` 則是在 `workingDirectory` 內建立符號連結。掛載路徑 `/workspace` 在主機上會變成 `<workingDirectory>/workspace`，指令通常會用 `workspace` 存取它。

## 組合式檔案系統 {/* #composite-filesystem */}

`mounts` 選項會建立 `CompositeFilesystem`。這個 TypeScript 路徑路由器會將多個提供者呈現為同一棵虛擬目錄樹。

### 多個檔案系統 {/* #multiple-filesystems */}

在各自的掛載路徑下設定每個提供者：

```typescript
import { Workspace } from '@mastra/core/workspace'
import { E2BSandbox } from '@mastra/e2b'
import { GCSFilesystem } from '@mastra/gcs'
import { S3Filesystem } from '@mastra/s3'

const workspace = new Workspace({
  mounts: {
    '/data': new S3Filesystem({
      bucket: 'agent-data',
      region: 'us-east-1',
    }),
    '/reports': new GCSFilesystem({
      bucket: 'agent-reports',
    }),
  },
  sandbox: new E2BSandbox({ id: 'analysis-sandbox' }),
})
```

套用此設定後：

- `list_files('/')` 會傳回虛擬目錄 `data` 和 `reports`。
- `read_file('/data/input.csv')` 會導向 S3 提供者。
- `write_file('/reports/summary.md')` 會導向 Google Cloud Storage 提供者。
- 各掛載在 Sandbox 中成功後，Sandbox 指令也會使用相同路徑。

組合式檔案系統會移除掛載前綴，再將剩餘路徑交給對應的提供者。掛載路徑不可巢狀設定，因此同一組合式檔案系統不能同時包含 `/data` 和 `/data/archive`。

### 不使用 Sandbox {/* #without-a-sandbox */}

即使沒有設定 Sandbox，也可以使用 `mounts`。Mastra 仍會建立 `CompositeFilesystem`，所有檔案工具都可使用包含掛載前綴的路徑。由於沒有設定 Sandbox，Agent 不會取得指令或程序工具。

### 手動組合 {/* #manual-composition */}

你也可以自行建立 `CompositeFilesystem`，再透過 `filesystem` 傳入。這樣可以路由路徑，且不會自動設定 Sandbox 掛載：

```typescript
import { CompositeFilesystem, LocalFilesystem, Workspace } from '@mastra/core/workspace'
import { S3Filesystem } from '@mastra/s3'

const filesystem = new CompositeFilesystem({
  mounts: {
    '/local': new LocalFilesystem({ basePath: './data' }),
    '/archive': new S3Filesystem({
      bucket: 'agent-archive',
      region: 'us-east-1',
    }),
  },
})

const workspace = new Workspace({ filesystem })
```

如果應用程式的其他部分需要以組合式檔案系統做為提供者，請使用手動組合。一般的 Sandbox 掛載使用 `mounts` 選項即可用較少設定達到相同的路由效果。

## 掛載支援 {/* #mount-availability */}

檔案工具和組合路由即使沒有 Sandbox 掛載也能運作。如果遠端 Sandbox 與檔案系統提供者都支援掛載，`mounts` 會自動使用 FUSE，讓指令能存取檔案。`LocalSandbox` 則使用符號連結。

內建的 Sandbox 掛載目前支援下列組合：

| Sandbox 後端 | 檔案系統提供者 |
| - | - |
| `LocalSandbox` | `LocalFilesystem` |
| E2B | Amazon S3, Google Cloud Storage, Azure Blob Storage |
| Daytona | Amazon S3, Google Cloud Storage, Azure Blob Storage |
| Blaxel | Amazon S3, Google Cloud Storage |

遠端掛載可能需要 Sandbox 內有 `s3fs`、`gcsfuse` 或 `blobfuse2`。有些後端會在啟動時安裝缺少的軟體，可能需要網路連線，並延長啟動時間。其他組合則需要 [`onMount`](/reference/workspace/workspace-class#constructor-parameters) 掛鉤或提供者專屬設定。

若 Sandbox 無法掛載或掛載失敗，Workspace 仍可使用。檔案工具會繼續透過提供者的 SDK 存取檔案，但指令無法存取該路徑。Mastra 會告知 Agent，這些提供者僅能透過檔案工具存取。

## 依使用者或執行緒區分檔案系統 {/* #filesystems-per-user-or-thread */}

若要依請求、使用者、角色或租用戶選擇儲存空間，可以將解析函式傳入 `filesystem` 選項：

```typescript
const workspace = new Workspace({
  filesystem: ({ requestContext }) => {
    const userId = requestContext.get('user-id') as string

    return new S3Filesystem({
      bucket: process.env.S3_BUCKET!,
      region: process.env.S3_REGION!,
      prefix: `users/${userId}`,
    })
  },
})
```

每位使用者都有各自的檔案系統檢視，檔案工具會根據請求上下文自動解析要使用的提供者。

`mounts` 不接受解析函式，也不能和 Sandbox 解析函式搭配使用。若每位使用者或每個執行緒都需要獨立的 Sandbox 和儲存空間，請在 Sandbox 解析函式內建立並掛載提供者。請見[依使用者或執行緒區分 Sandbox](/docs/sandbox/overview#sandboxes-per-user-or-thread)。

## 政策與存取範圍 {/* #policies-and-containment */}

使用 `WORKSPACE_TOOLS.FILESYSTEM` 下的個別常數（例如 `WORKSPACE_TOOLS.FILESYSTEM.WRITE_FILE`）設定各檔案工具。核准可全域設定，也可依工具設定。先讀後寫及輸出限制則在各檔案系統工具的設定項目中指定。請見[檔案系統工具設定參考](/reference/workspace/workspace-class#filesystem-tools)。

`LocalFilesystem` 預設將存取限制在 `basePath` 內。如果 Agent 需要存取根目錄以外的特定目錄，請使用 `allowedPaths`：

```typescript
const workspace = new Workspace({
  filesystem: new LocalFilesystem({
    basePath: './knowledge-base',
    allowedPaths: ['../shared-policies'],
  }),
})
```

存取範圍限制適用於檔案系統操作，包括檔案工具及搜尋索引的建立，但不限制 Shell 指令。

若 Agent 可以使用檔案但不能修改，請設定 `readOnly: true`。若使用靜態提供者，Mastra 會移除與寫入相關的檔案工具。

如果使用檔案系統解析函式，必須等到處理請求時才知道提供者，因此寫入工具仍會註冊。提供者會在執行時拒絕寫入。

組合式檔案系統中的 `LocalFilesystem` 項目請保留預設值 `contained: true`。只有確定要開放對主機檔案系統的完整存取時，才設定 `contained: false`。
