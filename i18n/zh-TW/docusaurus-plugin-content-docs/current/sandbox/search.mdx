# 搜尋與索引

搜尋讓 Agent 無須逐一讀取檔案，就能快速找到相關內容。它可搭配[直接存取檔案系統](/docs/sandbox/filesystem#direct-filesystem-access)與[`mounts`](/docs/sandbox/filesystem#mounts)使用，但會將可搜尋內容存放在獨立索引中。

查詢讀取的是索引，而非即時檔案系統。因此，你也可以為資料庫、API 或其他應用程式來源的內容建立索引。

## 快速入門 {/* #quickstart */}

啟用 BM25 關鍵字搜尋、將文件加入索引，再執行搜尋：

```typescript title="src/mastra/workspaces.ts"
import { LocalFilesystem, Workspace } from '@mastra/core/workspace'

const workspace = new Workspace({
  filesystem: new LocalFilesystem({ basePath: './workspace' }),
  bm25: true,
})

await workspace.index('/docs/guide.md', 'Reset passwords from the account settings page.')

const results = await workspace.search('password reset')

for (const result of results) {
  console.log(`${result.id}: ${result.score}`)
  console.log(result.content)
}
```

`workspace.index()` 的第一個參數是搜尋結果回傳的文件 ID。本例中它看起來像檔案路徑，但 `index()` 不會讀取或建立該檔案。

設定搜尋後，Agent 也會取得搜尋與索引 Tool。請參閱 [Agent Tool](#agent-tools) 了解如何控制它們。

## 選擇搜尋模式 {/* #choose-a-search-mode */}

Mastra 支援三種搜尋模式：

| 模式 | 適用情境 | 查詢範例 |
| - | - | - |
| `bm25` | 精確術語、技術查詢與程式碼 | "useState hook", "404 error", "config.yaml" |
| `vector` | 概念與自然語言問題 | "how to handle user authentication" |
| `hybrid` | 同時包含精確術語與概念的查詢 | 多數 Agent 搜尋情境 |

若呼叫 `workspace.search()` 時未指定模式，且同時設定了 BM25 與向量搜尋，Mastra 會使用混合搜尋；否則使用已設定的模式。

### BM25 關鍵字搜尋 {/* #bm25-keyword-search */}

BM25 依詞頻與文件長度為文件評分，不需要外部服務或嵌入模型。傳入 `bm25: true` 即可使用快速入門中的預設設定。

傳入 `k1` 與 `b`，可調整詞頻飽和度及文件長度正規化：
向量搜尋利用嵌入尋找語意相近的內容。請設定向量儲存，以及每次嵌入一個字串的函式：
```typescript title="src/mastra/workspaces.ts"
import { Workspace, LocalFilesystem } from '@mastra/core/workspace'

const workspace = new Workspace({
  filesystem: new LocalFilesystem({ basePath: './workspace' }),
  bm25: {
    k1: 1.5,
    b: 0.75,
  },
})
```

### 向量搜尋 {/* #vector-search */}



```typescript title="src/mastra/workspaces.ts"
import { openai } from '@ai-sdk/openai'
import { Workspace, LocalFilesystem } from '@mastra/core/workspace'
import { PineconeVector } from '@mastra/pinecone'
import { embed } from 'ai'

const workspace = new Workspace({
  filesystem: new LocalFilesystem({ basePath: './workspace' }),
  vectorStore: new PineconeVector({
    id: 'workspace-search',
    apiKey: process.env.PINECONE_API_KEY!,
  }),
  embedder: async (text: string) => {
    const { embedding } = await embed({
      model: openai.embedding('__AI_SDK_OPENAI_EMBEDDING_MODEL__'),
      value: text,
    })
    return embedding
  },
})
```

#### 批次嵌入 {/* #batch-embedding */}

單一文字嵌入函式會為每份文件各呼叫一次 Provider。大型索引可使用 Provider 的批次 API，一次嵌入多份文件。

批次嵌入函式必須：

- 接收字串陣列。
- 依原順序為每個字串回傳一個嵌入。
- 具有 `batch: true` 屬性，讓 Mastra 在執行階段識別。
- 可選擇設定 `maxBatchSize`，表示 Provider 接受的最大陣列長度。

Mastra 會依 `maxBatchSize` 拆分較大的索引工作，並可同時處理各批次。請將它設為 Provider 文件記載的上限：

| Provider | 輸入數量上限 |
| - | - |
| OpenAI | 2048 |
| Cohere | 96 |
| Voyage | 128 |

若省略 `maxBatchSize`，Mastra 會使用內部預設批次大小。

將單文本嵌入器替換為批次嵌入器：

```typescript title="src/mastra/workspaces.ts"
import { openai } from '@ai-sdk/openai'
import { LocalFilesystem, Workspace } from '@mastra/core/workspace'
import { PineconeVector } from '@mastra/pinecone'
import { embedMany } from 'ai'

const model = openai.embedding('__AI_SDK_OPENAI_EMBEDDING_MODEL__')

const workspace = new Workspace({
  filesystem: new LocalFilesystem({ basePath: './workspace' }),
  vectorStore: new PineconeVector({
    id: 'workspace-search',
    apiKey: process.env.PINECONE_API_KEY!,
  }),
  embedder: Object.assign(
    async (texts: string[]) => {
      const { embeddings } = await embedMany({ model, values: texts })
      return embeddings
    },
    { batch: true as const, maxBatchSize: 2048 },
  ),
})
```

`Object.assign()` 將 `batch` 與 `maxBatchSize` 加為函式屬性。Mastra 會將它們讀作中繼資料，不會傳給 Provider。仍支援簽章為 `(text: string) => Promise<number[]>` 的單一文字嵌入函式。

### 伺服器端嵌入 {/* #server-side-embeddings */}

有些向量儲存會自行產生嵌入。使用這類儲存時可省略 `embedder`：Mastra 會傳送檔案文字，資料庫在寫入時嵌入文字，並在查詢時嵌入搜尋字串。

MongoDB 透過[自動嵌入](/integrations/vectors/mongodb#automated-embedding)實現此功能。請在向量儲存中指定 Voyage AI 模型：

```typescript title="src/mastra/workspaces.ts"
import { LocalFilesystem, Workspace } from '@mastra/core/workspace'
import { MongoDBVector } from '@mastra/mongodb'

const workspace = new Workspace({
  filesystem: new LocalFilesystem({ basePath: './workspace' }),
  vectorStore: new MongoDBVector({
    id: 'workspace-search',
    uri: process.env.MONGODB_URI!,
    dbName: process.env.MONGODB_DB_NAME!,
    // highlight-next-line
    autoEmbed: { model: 'voyage-4' },
  }),
})
```

MongoDB 會在背景嵌入新文件，因此剛加入索引的內容可能暫時不會出現在搜尋結果中。自動嵌入的需求請參閱 [MongoDB 參考文件](/integrations/vectors/mongodb#automated-embedding)。

其他所有儲存都要求應用程式提供向量，因此仍須設定 `embedder`。

### 混合搜尋 {/* #hybrid-search */}

同時設定 BM25 與向量搜尋，以結合關鍵字及語意結果：

```typescript title="src/mastra/workspaces.ts"
import { Workspace, LocalFilesystem } from '@mastra/core/workspace'

const workspace = new Workspace({
  filesystem: new LocalFilesystem({ basePath: './workspace' }),
  bm25: true,
  vectorStore: pineconeVector,
  embedder: embedderFn,
})
```

### 自訂索引名稱 {/* #custom-index-name */}

向量索引名稱預設由正規化後的 Workspace ID 加上 `_search` 組成；若向量儲存自行產生嵌入，則加上 `_search_selfembed`。需要固定或共用名稱時，請設定 `searchIndexName`：

```typescript title="src/mastra/workspaces.ts"
import { Workspace, LocalFilesystem } from '@mastra/core/workspace'

const workspace = new Workspace({
  filesystem: new LocalFilesystem({ basePath: './workspace' }),
  vectorStore: pineconeVector,
  embedder: embedderFn,
  // highlight-next-line
  searchIndexName: 'my_workspace_vectors',
})
```

名稱必須以字母或 `_` 開頭，只能包含字母、數字或 `_`，且最多 63 個字元。

## 索引內容 {/* #index-content */}

使用 `workspace.index()` 將提供的文字加入搜尋索引。Mastra 會為 BM25 搜尋斷詞；若已設定向量搜尋，也會產生嵌入。

文件 ID 不必對應檔案系統中的現有檔案。若需要篩選結果或提供更多脈絡，可加入中繼資料：

```typescript
await workspace.index('/docs/guide.md', 'Content of the guide...')

await workspace.index('/docs/api.md', apiDocContent, {
  metadata: {
    category: 'api',
    version: '2.0',
  },
})
```

手動建立索引適用於資料庫記錄與 API 回應，也適用於需要自行預先處理、分塊或標註內容的情境。

### 為應用程式內容建立索引 {/* #index-application-content */}

即使應用程式自行讀取內容，Workspace 仍須設定 `filesystem`、`sandbox` 或 `skills` Provider，才能將內容傳給 `workspace.index()`。否則，`Workspace` 建構函式會擲出 `Workspace requires at least a filesystem, sandbox, or skills`。

設定檔案系統不代表 Agent 應該使用它。預設情況下，使用此 Workspace 的 Agent 也會取得 `mastra_workspace_read_file` 與 `mastra_workspace_write_file` 等檔案 Tool。若只想開放搜尋，請先停用所有 Workspace Tool，再重新啟用搜尋 Tool：

```typescript title="src/mastra/workspaces.ts"
import { LocalFilesystem, Workspace, WORKSPACE_TOOLS } from '@mastra/core/workspace'

const workspace = new Workspace({
  filesystem: new LocalFilesystem({ basePath: './workspace' }),
  bm25: true,
  tools: {
    enabled: false,
    [WORKSPACE_TOOLS.SEARCH.SEARCH]: { enabled: true },
  },
})

for (const document of documents) {
  await workspace.index(document.id, document.content)
}
```

應用程式仍直接呼叫 `workspace.index()`。Tool 設定只控制 Agent 能呼叫哪些 Tool。

### 保持檔案和索引同步 {/* #keep-files-and-the-index-in-sync */}

檔案系統與索引的變更彼此獨立。寫入、編輯或刪除檔案不會更新索引內容，而 `workspace.index()` 也不會讀取或修改檔案。

要寫入檔案並讓它可被搜尋，需執行以下兩步：

```typescript
const path = 'notes/launch.md'
const content = '# Launch notes\n\nShip the new dashboard on Friday.'
const filesystem = workspace.filesystem

if (!filesystem) {
  throw new Error('This operation requires a static filesystem')
}

await filesystem.writeFile(path, content)
await workspace.index(path, content)
```

編輯檔案後，請再次索引其完整的更新內容。刪除檔案不會移除已索引文件，Mastra 目前也沒有公開刪除單一索引文件的方法。若 Agent 必須搜尋檔案系統的目前狀態，而你不維護獨立索引，請使用 `grep` 檔案 Tool。

## 搜尋內容 {/* #search-content */}

使用 `workspace.search()` 回傳依相關性排序的文件：

```typescript
const results = await workspace.search('authentication flow', {
  topK: 10,
  mode: 'hybrid',
  vectorWeight: 0.5,
})
```

| 選項 | 說明 |
| - | - |
| `topK` | 結果數量上限。直接呼叫 API 時預設為 10，Agent 搜尋 Tool 預設為 5。 |
| `mode` | 搜尋模式：`'bm25'`、`'vector'` 或 `'hybrid'`。預設使用 Workspace 設定中最合適的可用模式。 |
| `minScore` | 移除低於此分數的結果。分數尺度取決於模式、向量 Provider 與索引內容。 |
| `vectorWeight` | 混合模式中向量分數的權重。`0` 表示向量分數權重為零，`1` 表示 BM25 分數權重為零，`0.5` 表示兩者權重相同。 |
| `filter` | 向量檢索使用的向量儲存中繼資料篩選器。在混合模式中，它不會篩選僅由 BM25 回傳的結果。語法取決於所設定的向量儲存。 |
每筆結果包含符合的內容與分數：


```typescript
interface SearchResult {
  id: string
  content: string
  score: number
  lineRange?: {
    start: number
    end: number
  }
  metadata?: Record<string, unknown>
  scoreDetails?: {
    vector?: number
    bm25?: number
  }
}
```

分數等級不可互換：

- 單獨使用 BM25 搜尋時回傳原始 BM25 分數，不限於 0 到 1。
- 向量分數的意義取決於所設定的向量儲存。
- 混合搜尋會在加權計算時對 BM25 分數做最小最大正規化，但保留向量 Provider 的原始分數。合併分數也不限於 0 到 1。
- `scoreDetails` 保留原始組成分數，包括未正規化的 BM25 分數。
- 請依目前模式、向量 Provider 與索引內容調整 `minScore`，不要在不同索引間沿用同一門檻。

## Agent Tool {/* #agent-tools */}

設定搜尋後，Agent 會取得 `mastra_workspace_search` 與 `mastra_workspace_index`。你可以透過 `WORKSPACE_TOOLS.SEARCH` 分別設定。

若 Agent 只應搜尋現有內容而不能修改索引，請停用索引 Tool：

```typescript title="src/mastra/workspaces.ts"
import { LocalFilesystem, Workspace, WORKSPACE_TOOLS } from '@mastra/core/workspace'

const workspace = new Workspace({
  filesystem: new LocalFilesystem({ basePath: './workspace' }),
  bm25: true,
  tools: {
    [WORKSPACE_TOOLS.SEARCH.INDEX]: {
      enabled: false,
    },
  },
})
```

索引 Tool 接收與 `workspace.index()` 相同的 `path`、`content` 及可選中繼資料。它可能觸發嵌入呼叫與向量儲存寫入；若 Agent 修改索引前需要人工審核，請設定須經核准：

```typescript title="src/mastra/workspaces.ts"
import { Workspace, LocalFilesystem } from '@mastra/core/workspace'

const workspace = new Workspace({
  filesystem: new LocalFilesystem({ basePath: './workspace' }),
  bm25: true,
  tools: {
    [WORKSPACE_TOOLS.SEARCH.INDEX]: {
      requireApproval: true,
    },
  },
})
```

`requireReadBeforeWrite` 適用於檔案系統寫入 Tool，不適用於索引變更。即使索引不會寫入靜態檔案系統，只要該檔案系統是唯讀的，Mastra 仍會排除索引 Tool。

完整 Tool 清單請參閱[搜尋 Tool 參考文件](/reference/workspace/workspace-class#search-tools)，共用設定請參閱 [Tool 設定參考文件](/reference/workspace/workspace-class#tool-configuration)。

## 自動索引 {/* #auto-indexing */}

使用 `autoIndexPaths` 在應用程式啟動時為靜態檔案系統內容建立索引。

:::warning

`autoIndexPaths` 會在 `workspace.init()` 中執行。將 Workspace 傳給 `new Mastra({ workspace })` 只會註冊，不會初始化 Workspace 或建立索引。除非由 `AgentController` 等其他執行階段負責初始化，否則請呼叫並等待 `workspace.init()`。

```typescript
await workspace.init()
```

若由應用程式負責初始化，請在啟動時、開始處理請求前呼叫一次。

:::

在一般 Mastra 應用程式中，先建立 `Mastra`，讓 Workspace 能使用其日誌記錄器，再於模組啟動時初始化 Workspace：

```typescript title="src/mastra/index.ts"
import { Mastra } from '@mastra/core'
import { LocalFilesystem, Workspace } from '@mastra/core/workspace'

const workspace = new Workspace({
  filesystem: new LocalFilesystem({ basePath: './workspace' }),
  bm25: true,
  autoIndexPaths: ['docs', 'support/faq'],
})

export const mastra = new Mastra({ workspace })

await workspace.init()
```

頂層 `await` 會讓模組啟動等待初始化完成。`init()` 結束時，Mastra 已嘗試讀取並索引所有符合的檔案。

每個 `autoIndexPaths` 項目可以是檔案、目錄或 glob 模式。遞迴走訪目錄與 glob 時最多深入十層：

```typescript title="src/mastra/index.ts"
import { Mastra } from '@mastra/core'
import { Workspace, LocalFilesystem } from '@mastra/core/workspace'

const workspace = new Workspace({
  filesystem: new LocalFilesystem({ basePath: './workspace' }),
  bm25: true,
  autoIndexPaths: ['docs/**/*.md', 'support/**/*.txt'],
})

export const mastra = new Mastra({ workspace })

await workspace.init()
```

自動索引支援靜態 `filesystem` 或 `mounts`。路徑須包含掛載前綴，例如 `/docs/**/*.md`。它不支援檔案系統解析器，因為 Workspace 初始化時尚未選定 Provider。請手動為解析器提供的內容建立索引。

初始化只掃描一次，不會監看後續變更。建立索引前會將大型檔案分塊；在向量模式下還會產生嵌入。

盡量縮小設定路徑的範圍，避開相依套件與輸出目錄，也不要包含二進位檔案目錄。大型向量索引應使用批次嵌入函式。

再次呼叫 `workspace.init()` 會重新掃描路徑，先清空程序內的 BM25 索引再重建。不要在 Agent 呼叫、Tool、Workflow 步驟或請求處理函式中呼叫它。

持久化向量索引的行為不同。自動索引會取代讀取到的檔案，但後續掃描時仍可能保留先前已刪除檔案對應的文件。若向量須在程序重新啟動後保留，請使用固定的 Workspace `id` 或 `searchIndexName`，並依向量儲存的持久化行為規劃清理。
