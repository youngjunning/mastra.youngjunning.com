# 執照

Mastra 使用雙許可證模型，其中 Apache License 2.0 用於大部分程式碼庫，Mastra Enterprise License 用於企業特定功能。

* 駐留在名為的任何目錄下的所有內容`ee/` within Mastra's repository, including but not limited to:

  * `@mastra/core/auth/ee`
  * `@mastra/core/agent-builder/ee`
  * `@mastra/editor/ee`

  已根據中定義的許可證獲得許可[`ee/LICENSE`](https://github.com/mastra-ai/mastra/blob/main/ee/LICENSE).

* Mastra 軟體中包含的所有第三方元件均根據適用元件所有者提供的原始許可證獲得許可。

* 上述目錄或限制以外的內容可在「Apache License 2.0」下使用。

## 什麼需要 EE 許可證 {/* #what-requires-an-ee-license */}

您是否需要 Mastra 企業版 (EE) 授權取決於您配置的功能，而不是您安裝的軟體包。該表顯示了哪些功能在生產中需要許可證。每個功能都無需開發和測試許可即可使用。

|特色 |生產中需要 EE 許可證 |
| - | - |
| API 路由上的身份驗證（`server.auth`) with any provider, including Simple Auth, JWT, Auth0, Better Auth, Clerk, Firebase, Google, Neon, Okta, Supabase, and WorkOS | No |
| Studio with Simple Auth, JWT, or Mastra platform auth | No |
| Studio sign-in screen (an SSO button or an email and password form) with a third-party provider | Yes |
| Role-based access control (RBAC) with `server.rbac` or `studio.rbac`, using any provider | Yes |
| Fine-grained authorization (FGA) with `server.fga` or `studio.fga`|是的 |
|Agent生成器|是的 |

### 無生產許可證 {/* #without-a-license-in-production */}

在中設定您的許可證密鑰`MASTRA_LICENSE_KEY` environment variable. Mastra also reads the older `MASTRA_EE_LICENSE` variable. Without a valid key in production:

* **RBAC、FGA 或Agent程式產生器**：伺服器無法啟動，並且錯誤指出需要許可證的功能。
* **Studio 登入畫面與第三方Provider**：Studio 隱藏登入畫面。 API 路由上的身份驗證繼續有效。
