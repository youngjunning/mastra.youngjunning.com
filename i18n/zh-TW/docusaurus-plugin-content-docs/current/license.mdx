# 授權條款

Mastra 採用雙重授權。大部分程式碼適用 Apache License 2.0，企業專用功能則適用 Mastra Enterprise License。

- Mastra 儲存庫中，任何名為 `ee/` 的目錄下的所有內容，包括但不限於：

  - `@mastra/core/auth/ee`
  - `@mastra/core/agent-builder/ee`
  - `@mastra/editor/ee`

  均依 [`ee/LICENSE`](https://github.com/mastra-ai/mastra/blob/main/ee/LICENSE) 所載條款授權。

- Mastra 軟體納入的所有第三方元件，均適用各元件擁有者提供的原始授權條款。

- 不在上述目錄內且不受上述限制的內容，適用 Apache License 2.0。

## 哪些功能需要企業版授權 {/* #what-requires-an-ee-license */}

是否需要 Mastra 企業版（EE）授權，取決於你設定的功能，與安裝的套件無關。下表列出正式環境中需要授權的功能。開發和測試期間，所有功能均可免授權使用。

| 功能 | 正式環境是否需要 EE 授權 |
| - | - |
| 為 API 路由設定身分驗證（`server.auth`），可使用任何提供者，包括 Simple Auth、JWT、Auth0、Better Auth、Clerk、Firebase、Google、Neon、Okta、Supabase 與 WorkOS | 否 |
| Studio 搭配 Simple Auth、JWT 或 Mastra 平台身分驗證 | 否 |
| 搭配第三方提供者的 Studio 登入畫面（單一登入按鈕或電子郵件與密碼表單） | 是 |
| 使用任一提供者，透過 `server.rbac` 或 `studio.rbac` 設定角色型存取控制（RBAC） | 是 |
| 透過 `server.fga` 或 `studio.fga` 設定細粒度授權（FGA） | 是 |
| Agent Builder | 是 |

### 正式環境缺少有效授權時 {/* #without-a-license-in-production */}

請將授權金鑰設在 `MASTRA_LICENSE_KEY` 環境變數中。Mastra 也會讀取舊版的 `MASTRA_EE_LICENSE`。如果正式環境沒有有效的金鑰：

- **RBAC、FGA 或 Agent Builder**：伺服器不會啟動，錯誤訊息會指出哪項功能需要授權。
- **搭配第三方提供者的 Studio 登入畫面**：Studio 會隱藏登入畫面。API 路由的身分驗證仍會運作。

## Mastra Enterprise License {/* #mastra-enterprise-license */}

任何名為 `ee/` 的目錄（例如 `@mastra/core/auth/ee`）均依 Mastra Enterprise License 提供原始碼。正式環境使用這些功能需要有效的企業版授權，開發和測試則可自由使用。詳情請[聯絡業務團隊](https://mastra.ai/contact)。
