# 串流

Mastra 的 Agent 和 Workflow 支援即時傳回增量回應，使用者可以在產生內容的同時看到輸出，無須等到執行完畢。這適合聊天、長文、多步驟 Workflow，以及其他需要立即回饋的情境。

## 開始使用 {/* #getting-started */}

[`Agent.stream()`](/reference/streaming/agents/stream) 是 Agent 的標準串流 API。它會傳回 `MastraModelOutput`，其中的 `textStream` 可逐步讀取文字，而 `text`、`steps` 和 `usage` 等 Promise 會在串流結束時完成。

## Agent 串流 {/* #streaming-with-agents */}

簡單的提示可傳入單一字串。要提供多段上下文，可使用字串陣列。若要精確控制訊息角色和對話流程，請傳入包含 `role` 和 `content` 的訊息物件陣列。

### 使用 `Agent.stream()` {/* #using-agentstream */}

`textStream` 會在產生回應的過程中將回應拆成文字區塊並逐一傳送。用 `for await` 迴圈走訪 `textStream`，即可檢視各個區塊。

```typescript
const testAgent = mastra.getAgent('testAgent')

const stream = await testAgent.stream([{ role: 'user', content: 'Help me organize my day' }])

for await (const chunk of stream.textStream) {
  process.stdout.write(chunk)
}
```

詳情請參閱 [Agent.stream()](/reference/streaming/agents/stream)。

:::tip

Agent 若會派送[背景工作](/docs/harness/background-tasks)，可在呼叫 `stream()` 時使用 [`untilIdle` 選項](/reference/streaming/agents/stream#parameters)，例如 `untilIdle: true`。串流會保持開啟，直到這些工作完成，且 Agent 有機會回應工作結果。這個選項需要 Agent 啟用 Memory。

:::

### `Agent.stream()` 的輸出 {/* #output-from-agentstream */}

Agent 產生的回應會以串流輸出。

```text
Of course!
To help you organize your day effectively, I need a bit more information.
Here are some questions to consider:
...
```

### Agent 串流屬性 {/* #agent-stream-properties */}

Agent 串流提供下列回應屬性：

- **`stream.textStream`**：逐一送出文字區塊的可讀串流。
- **`stream.text`**：完成時傳回完整文字回應的 Promise。
- **`stream.steps`**：完成時傳回已完成模型步驟的 Promise。
- **`stream.finishReason`**：完成時傳回 Agent 結束串流原因的 Promise。
- **`stream.usage`**：完成時傳回 token 用量資訊的 Promise。
- **`stream.objectStream`** 與 **`stream.object`**：傳入 `structuredOutput` 時，分別提供部分與最終的結構化輸出。

完整屬性清單請參閱 [`MastraModelOutput` 參考](/reference/streaming/agents/MastraModelOutput)。

### 整合 AI SDK {/* #ai-sdk-integration */}

使用 `toAISdkStream()` 和 `toAISdkMessages()` 將 Mastra 串流和已儲存的訊息轉為 AI SDK 相容格式。為了向下相容，轉換函式預設使用 AI SDK v5。請傳入與已安裝的 AI SDK 相符的版本，例如 AI SDK v7 使用 `version: 'v7'`。

```typescript
import { toAISdkStream } from '@mastra/ai-sdk'

const testAgent = mastra.getAgent('testAgent')
const stream = await testAgent.stream([{ role: 'user', content: 'Help me organize my day' }])

const aiSDKStream = toAISdkStream(stream, {
  from: 'agent',
  version: 'v7',
})
```

使用 `toAISdkMessages()` 轉換已儲存的訊息，供 `useChat()` 的 `initialMessages` 使用：

```typescript
import { toAISdkMessages } from '@mastra/ai-sdk/ui'

const initialMessages = toAISdkMessages([{ role: 'user', content: 'Hello' }], { version: 'v7' })
```

路由處理函式請參閱 [AI SDK UI](/integrations/agentic-ui/ai-sdk-ui)，其中介紹 `handleChatStream()`、`handleWorkflowStream()` 和 `handleNetworkStream()`。呼叫這些函式時，也請傳入與已安裝的 AI SDK 相符的版本。完整選項請參閱 [`toAISdkStream()`](/reference/ai-sdk/to-ai-sdk-stream) 和 [`toAISdkMessages()`](/reference/ai-sdk/to-ai-sdk-messages) 的參考文件。

## Workflow 串流 {/* #streaming-with-workflows */}

Workflow 串流傳回一連串描述執行生命週期的結構化事件，而非逐步產生的文字區塊。透過 `.createRun()` 建立一次執行後，就能利用這些事件即時追蹤並回應 Workflow 的進度。

### 使用 `Run.stream()` {/* #using-runstream */}

`stream()` 方法會傳回 `WorkflowRunOutput`。其中的 `fullStream` 屬性是傳送 Workflow 事件的 `ReadableStream`。

```typescript
const run = await testWorkflow.createRun()

const stream = run.stream({
  inputData: {
    value: 'initial data',
  },
})

for await (const chunk of stream.fullStream) {
  console.log(chunk)
}
```

詳情請參閱 [Run.stream()](/reference/streaming/workflows/stream)。

### `Run.stream()` 的輸出 {/* #output-from-runstream */}

事件的頂層包含 `runId` 和 `from`，無須查看承載內容，就能識別對應的 Workflow 執行。

```typescript oxfmt:false
{
  type: 'workflow-start',
  runId: '1eeaf01a-d2bf-4e3f-8d1b-027795ccd3df',
  from: 'WORKFLOW',
  payload: {
    workflowId: 'testWorkflow'
  }
}
```

### Workflow 串流屬性 {/* #workflow-stream-properties */}

Workflow 串流提供下列回應屬性：

- **`stream.status`**：Workflow 的執行狀態。
- **`stream.result`**：Workflow 的執行結果。
- **`stream.usage`**：Workflow 這次執行的 token 總用量。

透過 Agent 或 Workflow 串流，可即時檢視大型語言模型的輸出或 Workflow 的執行狀態。你可以直接把回饋傳給使用者，或在應用程式中即時顯示 Workflow 的狀態變化。

Agent 或 Workflow 發出的事件對應產生和執行的不同階段，例如開始執行、產生文字或呼叫 Tool。

## 事件類型 {/* #event-types */}

Agent 串流和 Workflow 串流會在執行期間發出不同類型的事件。

### Agent 事件 {/* #agent-events */}

常見的 Agent 事件包括：

- **`start`**：Agent 開始執行。
- **`text-start`**、**`text-delta`** 和 **`text-end`**：開始與結束事件標示文字生成的範圍，增量事件帶有新產生的文字。
- **`reasoning-start`**、**`reasoning-delta`** 和 **`reasoning-end`**：開始與結束事件標示推理內容生成的範圍，增量事件帶有新產生的推理內容。
- **`tool-call`** 和 **`tool-result`**：呼叫 Tool 並傳回結果。
- **`step-start`** 和 **`step-finish`**：模型步驟開始與結束。
- **`finish`**：Agent 完成執行。

此處僅列出常見事件。所有 Agent 區塊類型及其承載內容，請參閱 [`ChunkType` 參考](/reference/streaming/ChunkType)。

### Workflow 事件 {/* #workflow-events */}

Workflow 事件包括：

- **`workflow-start`**：Workflow 開始執行。
- **`workflow-step-start`**：Workflow 的某個步驟開始。
- **`workflow-step-output`**：步驟送出自訂輸出。
- **`workflow-step-progress`**：步驟回報進度。
- **`workflow-step-result`**：步驟完成並傳回結果。
- **`workflow-finish`**：Workflow 完成執行。
- **`workflow-paused`**、**`workflow-step-suspended`** 和 **`workflow-canceled`**：Workflow 執行中斷。

Workflow 事件的詳細說明請參閱 [`Run.stream()` 參考](/reference/streaming/workflows/stream)。

## 檢視 Agent 串流 {/* #inspecting-agent-streams */}

用 `for await` 迴圈走訪 `stream.fullStream`，即可檢視送出的所有事件區塊。

```typescript
const testAgent = mastra.getAgent('testAgent')

const stream = await testAgent.stream([{ role: 'user', content: 'Help me organize my day' }])

for await (const chunk of stream.fullStream) {
  console.log(chunk)
}
```

詳情請參閱 [Agent.stream()](/reference/streaming/agents/stream)。

## Writer API {/* #writer-api */}

Tool 與 Workflow 步驟共用 `writer` API。各功能的使用範例請參閱 Tool 與 Workflow 文件。

## 在 Agent 串流中使用 Tool {/* #agent-using-tool */}

Agent 串流可搭配 Tool 呼叫，將 Tool 輸出直接寫入 Agent 的串流回應，讓使用者在互動時看到 Tool 活動。

```typescript {2,9}
import { Agent } from '@mastra/core/agent'
import { testTool } from '../tools/test-tool'

export const testAgent = new Agent({
  id: 'test-agent',
  name: 'Test Agent',
  instructions: 'You are a weather agent.',
  model: '__GATEWAY_OPENAI_MODEL__',
  tools: { testTool },
})
```

### 使用 `context.writer` {/* #using-contextwriter */}

Tool 的 `execute()` 函式中可使用 `context.writer` 物件，向目前的串流發出自訂事件、資料或值。Tool 會用這些事件在執行期間提供中間結果或狀態更新。

:::warning

必須用 `await` 等待 `writer.write()` 呼叫完成，否則串流會鎖定並出現 `WritableStream is locked` 錯誤。

:::

```typescript {4,7,14}
import { createTool } from '@mastra/core/tools'

export const testTool = createTool({
  execute: async (inputData, context) => {
    const { value } = inputData

    await context?.writer?.write({
      type: 'custom-event',
      status: 'pending',
    })

    const response = await fetch()

    await context?.writer?.write({
      type: 'custom-event',
      status: 'success',
    })

    return {
      value: '',
    }
  },
})
```

也可以用 `writer.custom()` 送出頂層串流區塊，方便整合 UI 框架。

```typescript {4,7,14}
import { createTool } from '@mastra/core/tools'

export const testTool = createTool({
  execute: async (inputData, context) => {
    const { value } = inputData

    await context?.writer?.custom({
      type: 'data-tool-progress',
      status: 'pending',
    })

    const response = await fetch()

    await context?.writer?.custom({
      type: 'data-tool-progress',
      status: 'success',
    })

    return {
      value: '',
    }
  },
})
```

### 暫態資料區塊 {/* #transient-data-chunks */}

預設情況下，`writer.custom()` 發出的 `data-*` 區塊會作為歷史訊息的一部分持久儲存。若某些區塊只在即時串流時需要，例如進度更新或詳細日誌，可設定 `transient: true` 略過持久儲存。暫態區塊仍會即時傳給用戶端，但不會存入資料庫。

```typescript {4}
await context?.writer?.custom({
  type: 'data-build-log',
  data: { line: 'Compiling module 3 of 12...' },
  transient: true,
})
```

資料量大或頻繁產生，且只在即時工作階段有用時，可使用暫態區塊。重新整理頁面後，就無法再取得這些區塊。系統只會從儲存空間載入 Tool 傳回的值及非暫態區塊。

## 使用 `writer` 引數 {/* #using-the-writer-argument */}

`writer` 引數會傳入 Workflow 步驟的 `execute` 函式，可向目前的串流發出自訂事件、資料或值。Workflow 步驟會用這些事件在執行期間提供中間結果或狀態更新。

:::warning

必須用 `await` 等待 `writer.write(...)` 呼叫完成，否則串流會鎖定並出現 `WritableStream is locked` 錯誤。

:::

```typescript {8,11,18}
import { createStep } from '@mastra/core/workflows'
import { z } from 'zod'

export const testStep = createStep({
  id: 'test-step',
  inputSchema: z.object({ url: z.url() }),
  outputSchema: z.object({ status: z.number() }),
  execute: async ({ inputData, writer }) => {
    const { url } = inputData

    await writer.write({
      type: 'custom-event',
      status: 'pending',
    })

    const response = await fetch(url)

    await writer.write({
      type: 'custom-event',
      status: 'success',
    })

    return {
      status: response.status,
    }
  },
})
```
