# 上下文工程

{/* vale ai-tells.VerbTricolon = NO */}

模型只能利用上下文視窗中的資訊，例如目前對話、記住的細節、應用程式資料、Tool 結果或知識庫的相關段落。

上下文工程是決定模型該在何時看到哪些資訊。目標是讓資訊保持相關且即時，而非越多越好。資訊太少，模型缺乏必要依據；太多，重要細節就更難找到，成本增加，甚至在達到上下文上限前便降低回答品質。

Mastra 提供多種機制，可將資訊帶入上下文、長期保留、依需求檢索，並在工作擴大時壓縮或隔離。本指南說明各機制的使用時機與搭配方式。

{/* vale ai-tells.VerbTricolon = YES */}

| 需求 | 從何著手 | 模型看到的內容 |
| - | - | - |
| 穩定的身分、規則或限制 | [指令](#instructions) | 每次模型呼叫的系統上下文 |
| 資料庫或 API 資料 | [Tool](#tools) | Tool 定義及選取的結果 |
| 目前客戶或應用程式資料 | [內嵌上下文](#inline-context) | 插入使用者訊息的資料 |
| 大型且穩定的知識庫 | [RAG](#rag) | 索引中語意相關的內容區塊 |
| 使用者或組織管理的文件 | [檔案系統](#filesystems) | 透過讀取或搜尋 Tool 選取的檔案 |
| 近期對話或持久事實 | [記憶](#memory) | 訊息歷史、觀察紀錄或檢索到的記憶 |
| 長時間進行的對話 | [觀察記憶](#observational-memory) | 精簡的觀察紀錄及近期尚未觀察的訊息 |
| 執行期間的新事件或狀態變化 | [Signals](#signals) | 使用者、反應式、通知或狀態訊息 |
| 只有部分工作需要的指令 | [動態 Skill](#dynamic-skills) | Skill 中繼資料及依需求載入的指令 |

## 指示 {/* #instructions */}

Agent 的 [`instructions`](/reference/agents/agent#constructor-parameters) 定義穩定的身分、行為與限制。它們屬於系統訊息，出現在模型請求的對話訊息之前。

```typescript title="src/mastra/agents/support-agent.ts"
import { Agent } from '@mastra/core/agent'

export const supportAgent = new Agent({
  id: 'support-agent',
  name: 'Support Agent',
  instructions: `You help customers understand their account.
    Use plain language and don't invent account details.`,
  model: '__GATEWAY_OPENAI_MODEL__',
})
```

指令應聚焦適用於多數呼叫的行為。加入目前帳戶資料、檢索文件或工作專屬細節，會讓基礎提示詞變長且更難重複使用。

指令也可以在執行時從 [`RequestContext`](/docs/server/request-context) 解析：

```typescript title="src/mastra/agents/support-agent.ts"
instructions: ({ requestContext }) => {
  const name = requestContext.get('name')

  return `You help ${name} understand their account.`
}
```

如果指令依賴每次請求都可能變動的資料，例如目前使用者、租戶、locale、角色或功能旗標，請使用 `RequestContext`。Agent 建立時求值的內容，包括插入的 `new Date()`，在處理程序的生命週期內都不會變。因此應在回呼中計算隨時間變化的值，並明確傳入時區：

```typescript title="src/mastra/agents/support-agent.ts"
instructions: () =>
  `You help customers understand their account.
  Today is ${new Date().toLocaleDateString('en-US', { timeZone: 'America/New_York' })}.`
```

在回呼中解析日期，長時間執行的伺服器就能在午夜後取得新日期；明確設定 `timeZone` 可避免主機時區影響日期。若日期必須在 Tool 接續時更新，或需與 Studio 的指令覆寫設定共存，請改用 [`processInputStep`](/reference/processors/processor-interface#processinputstep) 處理器。

:::tip

若解析後的指令頻繁變動，模型 Provider 可能無法重複使用提示詞快取的相同前綴。請將穩定部分放在前面，頻繁變動的背景資訊則透過訊息或訊號傳遞。

觀看[這段提示詞快取短片](https://youtu.be/eBB0dBqfvuQ)，了解可快取的提示詞前綴如何降低延遲與成本。

:::

## 內聯上下文 {/* #inline-context */}

多數應用程式會將相關值插入目前訊息，以傳遞執行時上下文。如果程式碼已載入客戶或應用程式資料，這種方式很合適：

```typescript
const customer = await db.customer.findById(customerId)

await supportAgent.generate(`
  Customer: ${customer.name}
  Plan: ${customer.plan}
  Question: ${question}
`)
```

選擇並標記模型所需的字段，而不是序列化整個資料庫記錄。這樣可以使提示更小，並使每個值的含義更加清晰。

啟用記憶後，Mastra 會儲存目前使用者訊息。請勿插入不應留在對話歷史中的敏感或暫時性資料。

若背景資訊只需影響一次回應，不應儲存到對話歷史，可傳入 [`context`](/reference/agents/generate) 訊息：

```typescript
await supportAgent.generate('Recommend the next action.', {
  context: [{ role: 'user', content: 'The customer has an unresolved billing dispute.' }],
})
```

模型會在本次執行看到這些背景資訊，但 Mastra 不會將它們存入記憶。若儲存背景資訊會干擾對話，或讓暫時性應用程式狀態在後續回合暴露，請使用 `context`。

## Tool {/* #tools */}

[Tool](/docs/agents/tools) 是從資料庫、API 或服務取得即時資料的建議方式。模型決定何時取資料並提供 Tool 參數，應用程式則控制查詢與傳回欄位。

```typescript title="src/mastra/tools/customer-tool.ts"
import { createTool } from '@mastra/core/tools'
import { z } from 'zod'

export const getCustomer = createTool({
  id: 'get-customer',
  description: 'Gets the current profile and plan for a customer',
  inputSchema: z.object({ customerId: z.string() }),
  execute: async ({ customerId }) => {
    const customer = await db.customer.findById(customerId)
    return { name: customer.name, plan: customer.plan, status: customer.status }
  },
})
```

應用程式程式碼需要完整結果、模型只需精簡表示時，請使用 [`toModelOutput`](/docs/agents/tools#shape-output-for-the-model)。

## RAG {/* #rag */}

[檢索增強生成 (RAG)](/reference/rag/overview)從索引語料庫中檢索語意相關的區塊。它仍然適合大型、穩定的知識庫，使用者可以在其中提出開放式問題，而這些問題不能清楚地映射到結構化資料庫查詢。

```typescript
import { ModelRouterEmbeddingModel } from '@mastra/core/llm'
import { createVectorQueryTool } from '@mastra/rag'

const knowledgeBase = createVectorQueryTool({
  vectorStoreName: 'knowledgeBase',
  indexName: 'support-docs',
  model: new ModelRouterEmbeddingModel('openai/text-embedding-3-small'),
})
```

將 `vectorStoreName` 參照的向量儲存註冊到 Agent 所在的 Mastra 執行個體。Mastra 支援[多種向量資料庫](/reference/rag/vector-databases)。如本例所示，RAG 常透過 Tool 提供。關鍵在於判斷 Agent 需要語意檢索，還是能直接查詢資料來源。

如今許多應用程式會先使用直接查詢特定資料來源的 Tool。模型更擅長選用這類 Tool，而直接查詢通常更簡單、成本更低，因為不必進行分塊、嵌入與向量索引。只有確實需要對非結構化內容做語意搜尋時才選用 RAG，並以中繼資料篩選、重新排序和保守的 `topK` 限制傳回的上下文。

## 檔案系統 {/* #filesystems */}

[檔案系統](/docs/sandbox/filesystem)讓 Agent 持續存取文件和其他檔案。檔案可位於本機目錄，或 Amazon S3、AgentFS、Google Drive 等 Provider。Agent 會取得列出、讀取與搜尋檔案的內建 Tool。

```typescript title="src/mastra/workspace.ts"
import { LocalFilesystem, Workspace } from '@mastra/core/workspace'

export const workspace = new Workspace({
  filesystem: new LocalFilesystem({ basePath: './knowledge-base' }),
  bm25: true,
  autoIndexPaths: ['**/*.md'],
})

// Agents receive tools including mastra_workspace_read_file, mastra_workspace_list_files,
// mastra_workspace_grep, mastra_workspace_search, and mastra_workspace_index.
await workspace.init()
```

[Workspace 搜尋](/docs/sandbox/search)支援 BM25 關鍵字搜尋、向量語意搜尋及混合搜尋。個人助理需要處理使用者檔案，或團隊透過 Google Drive 等服務更新組織知識庫時，可使用檔案系統。搜尋以 Workspace 索引為準，因此檔案變更後必須先更新索引，Agent 才能檢索最新內容。

:::tip

檔案系統搜尋也可使用向量，因此與 RAG 的功能有所重疊。若資料來源是一組 Agent 可能需要列出、讀取或更新的檔案，請選用檔案系統；若主要需求是檢索，且內容無須當作檔案處理，則選用獨立的 RAG 流程。

:::

## 記憶 {/* #memory */}

[記憶](/docs/memory/overview)讓 Agent 的多輪對話保持連貫。它將近期訊息與記住的細節帶入上下文，應用程式無須每回合重新傳送完整對話紀錄。

記憶需要儲存 Provider。每次呼叫還須指定擁有該記憶的 `resource`，以及識別對話的 `thread`。沿用這兩個值，才能接續同一對話：

```typescript title="src/mastra/agents/assistant.ts"
import { Agent } from '@mastra/core/agent'
import { Memory } from '@mastra/memory'

export const assistant = new Agent({
  id: 'assistant',
  name: 'Assistant',
  model: '__GATEWAY_OPENAI_MODEL__',
  memory: new Memory({
    options: {
      lastMessages: 20,
    },
  }),
})

await assistant.generate('Help me plan the next project milestone.', {
  memory: {
    resource: 'user-123',
    thread: 'project-456',
  },
})
```

本例假設儲存已設定於註冊的 Mastra 執行個體，或直接設定於 `Memory`。`lastMessages` 控制 Mastra 從執行緒載入的近期訊息數量，預設為 10。

訊息歷史適合較短的對話，近期回合通常足以提供所需上下文。`lastMessages` 視窗每次請求都會前移；超過上限後，每回合都會從提示詞開頭移除最舊訊息，讓 Provider 的提示詞快取失效。長對話建議使用[觀察記憶](/docs/memory/observational-memory)：它保留近期對話，將舊歷史整理成精簡的觀察紀錄，同時讓提示詞前綴維持穩定以利快取。

## 觀察記憶 {/* #observational-memory */}

對話歷史記錄隨著每個用戶訊息、回應和Tool呼叫而增長。即使在達到模型的硬上下文限制之前，長文本也會增加成本並使模型更難找到相關細節。壓縮用較小的表示法取代舊的、冗長的歷史記錄。

[觀察記憶](/docs/memory/observational-memory)持續處理不斷增加的歷史。Observer 將較舊訊息與 Tool 互動整理成精簡的觀察紀錄，定期反思再重新組織並壓縮這些紀錄。

啟用觀察記憶後，無須設定 `lastMessages`。觀察記憶會自行管理歷史：在上下文保留近期尚未觀察的訊息，並以觀察紀錄取代較早的訊息。

```typescript title="src/mastra/agents/assistant.ts"
import { Agent } from '@mastra/core/agent'
import { Memory } from '@mastra/memory'

export const assistant = new Agent({
  id: 'assistant',
  name: 'Assistant',
  model: '__GATEWAY_OPENAI_MODEL__',
  memory: new Memory({
    options: {
      observationalMemory: true,
    },
  }),
})
```

訊息經觀察後，模型會收到觀察紀錄、近期尚未觀察的訊息和續接提醒。非同步緩衝的觀察紀錄不會產生續接提示（`currentTask` 或 `suggestedResponse`），因為緩衝內容啟用時，延遲產生的提示可能已過時。原始訊息仍儲存在後端，但不再占用目前模型上下文。

觀察紀錄以穩定的區塊加入，幫助 Provider 重複使用既有提示詞前綴。觀察記憶也可在提示詞快取可能過期後，或 Agent 切換 Provider 前，啟用已緩衝的觀察紀錄。

## 訊號 {/* #signals */}

[訊號](/docs/signals/overview)將訊息或系統產生的上下文新增至記憶體支援的執行緒。傳遞取決於執行緒的狀態：訊號可以喚醒空閒Agent或進入活動循環。它還可以等待下一個回合或持續存在而不喚醒Agent。

狀態訊號需要記憶與既有執行緒；通知收件匣訊號需要支援通知的儲存介接器。

| API | 用途 | 上下文行為 |
| - | - | - |
| `sendMessage()` | 目前執行中的 Agent 應立即看到的使用者輸入 | 進入執行中的迴圈，或喚醒閒置執行緒 |
| `queueMessage()` | 應等待下一回合的使用者輸入 | 目前執行結束後開始處理 |
| `sendSignal()` | 背景結果、政策提醒或外部事件 | 依傳遞選項加入反應式或通知上下文 |
| `sendStateSignal()` | 瀏覽器、編輯器、工作等持續變動的狀態 | 透過快照與差異維護執行緒範圍的狀態通道 |

對系統而非使用者產生的上下文，請使用 `sendSignal()`：

```typescript
const result = agent.sendSignal(
  {
    type: 'notification',
    contents: 'CI failed on pull request 123: three tests failed.',
    attributes: { source: 'github', pullRequest: 123 },
  },
  {
    resourceId: 'user-123',
    threadId: 'project-456',
  },
)

await result.accepted
```

處理器可在 `processInputStep()` 期間傳送反應式訊號，提供依賴目前步驟或近期 Tool 結果的指引。若訊號只應送達目前模型呼叫，請設定 `transient: true`。需要時重新傳送，避免將重複提醒存入對話歷史。

狀態訊號表示隨時間變動的上下文。Mastra 會為每條狀態通道追蹤快照與差異；當舊快照離開作用中的上下文視窗後，可重新插入最新快照。處理器負責狀態時，可使用 `computeStateSignal()`。即使訊息歷史或觀察記憶移除較舊訊息，此通道仍能讓工作記憶、瀏覽器上下文與工作清單一同維持可用。

訊號會在目前回合附近附加不斷變化的上下文，而不是重寫Agent的基本指令。因此，瞬態和狀態訊號可以保留更穩定的提示前綴，同時保持當前指導和狀態對模型可見。

## 動態技能 {/* #dynamic-skills */}

[Agent Skill](/docs/skills) 讓 Agent 只在需要時載入工作專屬指令，無須將所有流程都放進基礎指令。適用於部分請求才需要的專門指引，也能縮小預設上下文。

## 情境控制 {/* #context-control */}

情境控制限制了模型隨著任務的成長所看到的內容。壓縮和處理器減少了一個Agent內的上下文，而子Agent邊界控制了Agent之間的移動。

### 壓實 {/* #compaction */}

若用過 Claude Code，你可能看過長時間工作階段中的上下文壓縮。Mastra 團隊有句玩笑話：「朋友不會讓朋友做上下文壓縮。」

上下文壓縮會等到對話達到 token 門檻，才摘要紀錄並取代較舊訊息。這是較粗略的備援方式：壓縮回合會增加延遲，而一份摘要必須概括先前所有內容。反覆摘要可能模糊時間順序，或遺失後來才顯得重要的細節。

長對話優先使用[觀察記憶](#observational-memory)。它能在背景非同步處理歷史，同時保留時間脈絡。反思會重新檢視累積的記憶，自然刪減不再重要的細節。Mastra 沒有開箱即用的上下文壓縮，但可透過自訂[處理器](/docs/agents/processors)實作。

### 處理器 {/* #processors */}

[處理器](/docs/agents/processors)控制進入模型上下文的內容，並且可以在模型呼叫之前重寫內容。當資訊應保留在儲存的歷史記錄或應用程式輸出中但不需要在每個步驟中傳回模型時，請使用它們。

例如，`ToolCallFilter` 會從下一次模型請求移除舊 Tool 的參數與結果，但不會從儲存中刪除這些訊息。模型收到較短的提示詞，應用程式仍可顯示或檢查完整互動。

使用 `processInput()` 或 `processInputStep()` 修改目前訊息清單；這些變更之後可能儲存到記憶。如果改寫只應作用於目前 Provider 呼叫，而不應影響記憶，請使用 `processLLMRequest()`。

Mastra 包含一些針對上下文膨脹的常見來源的控制項：

* [`toModelOutput`](/docs/agents/tools#shape-output-for-the-model)：將冗長的 Tool 結果換成更精簡的模型輸入。
* [`ToolCallFilter`](/reference/processors/tool-call-filter)：從模型輸入中刪除舊的Tool呼叫和結果，同時將它們保留在記憶體和 UI 中。
* [`ToolSearchProcessor`](/reference/processors/tool-search-processor)：以搜尋與載入 Tool 取代龐大的 Tool 目錄。
* [`TokenLimiter`](/reference/processors/token-limiter-processor)：修剪非系統訊息，直到提示符合令牌預算。

對冗長的 Tool 結果，先使用 [`toModelOutput`](/docs/agents/tools#shape-output-for-the-model)；對舊 Tool 互動，先使用 `ToolCallFilter`。將 `TokenLimiter` 當作最後的預算防護，而非只依賴模型的最大上下文視窗。

### 子Agent {/* #subagents */}

上下文膨脹的常見原因，是傳給[子 Agent](/docs/subagents) 或從它接收過多資訊。子 Agent 有獨立的模型上下文來執行委派工作，但仍須仔細控制這個邊界。

預設 Mastra 會將父 Agent 的對話轉給子 Agent。使用 `messageFilter` 只傳入該專責 Agent 需要的訊息：

```typescript
await supervisor.generate('Investigate the failed deployment.', {
  delegation: {
    messageFilter: ({ messages }) => messages.slice(-10),
  },
})
```

反過來，Mastra 預設將子 Agent 的文字傳回父模型，同時保留巢狀 Tool 呼叫與中繼資料供應用程式程式碼使用。除非父模型必須分析這些細節，否則請維持停用 `includeSubAgentToolResultsInModelContext`。使用 `onDelegationStart` 調整子 Agent 提示詞，並用 `onDelegationComplete` 精簡或替換傳回父模型的文字。

委派掛鉤、記憶隔離、迭代監控與結果控制詳見[子 Agent](/docs/subagents)。
