# 訊息記錄

訊息歷史是最基本、最重要的記憶形式。它使法學碩士可以在上下文視窗中查看最近的訊息，使您的Agent商能夠參考早期的交換並做出一致的回應。

您也可以檢索訊息歷史記錄以在 UI 中顯示過去的對話。

:::注意
每個訊息都屬於一個執行緒（對話）和一個資源（與其關聯的使用者或實體）。看[Threads and resources](#threads-and-resources) for more detail.
:::

## 執行緒和資源 {/* #threads-and-resources */}

Mastra 使用兩個識別符組織對話：

* **線**：包含一系列訊息的對話會話。
* **資源**：擁有執行緒的實體，例如使用者、組織、專案或應用程式中的其他網域實體。

Studio 會自動為您產生執行緒和資源 ID。打電話時`stream()` or `generate()` yourself, provide these identifiers explicitly.

## 入門 {/* #getting-started */}

安裝 Mastra 內存模組以及[storage adapter](/docs/storage#supported-providers) for your database. The examples below use `@mastra/libsql`, which stores data locally in a `mastra.db` file.

```bash npm2yarn
npm install @mastra/memory@latest @mastra/libsql@latest
```

訊息歷史記錄需要儲存適配器來保存對話。如果您尚未在 Mastra 實例上配置存儲，請執行以下操作：

```typescript title="src/mastra/index.ts"
import { Mastra } from '@mastra/core'
import { LibSQLStore } from '@mastra/libsql'

export const mastra = new Mastra({
  storage: new LibSQLStore({
    id: 'mastra-storage',
    url: 'file:./mastra.db',
  }),
})
```

實例化一個[`Memory`](/reference/memory/memory-class) instance in your agent:

```typescript title="src/mastra/agents/test-agent.ts"
import { Memory } from '@mastra/memory'
import { Agent } from '@mastra/core/agent'

export const agent = new Agent({
  id: 'test-agent',
  memory: new Memory({
    options: {
      lastMessages: 10,
    },
  }),
})
```

當您呼叫Agent程式時，訊息會自動儲存到資料庫中。您可以指定一個`threadId`, `resourceId`, and optional `metadata`:

<Tabs>
  <TabItem value="generate" label=".generate()">

    ```typescript
      memory: {
        thread: {
          id: 'thread-123',

    })
    ```

  </TabItem>

    ```typescript
        thread: {

      },
    })
    ```
  </TabItem>

當您呼叫時會自動建立線程和訊息`agent.generate()` or `agent.stream()`, but you can also create them manually with [`createThread()`](/reference/memory/createThread) and [`saveMessages()`](/reference/memory/memory-class).

:::

您可以透過兩種方式使用此歷史記錄：

* **自動納入**：Mastra 會自動在上下文視窗中包含最近的訊息。預設的 10 則訊息使客服人員能夠專注於對話。調整它與`lastMessages` when needed.
* [**手動查詢**](#querying)：要獲得更多控制，請直接使用查詢線程和訊息`recall()`. Use the results to choose which memories enter the context window or to render conversation history in your UI.



`lastMessages`計算每條儲存的訊息，包括Tool呼叫、Tool結果和[signals](/docs/signals/sending-signals) of any kind, so a single turn can add several messages to the count. The window also slides forward on every request: once a thread grows past the limit, the oldest message leaves context on each turn, which changes the start of the prompt and invalidates the provider prompt cache. For long-running conversations, use [Observational Memory](/docs/memory/observational-memory), which keeps the prompt prefix stable.

:::

### 從客戶端發送訊息 {/* #sending-messages-from-a-client */}

當您在客戶端應用程式中使用記憶體時，發送**only the new message** instead of the full conversation history. Mastra loads previous messages from storage.

AI SDK範例請參見[Using Mastra Memory](/integrations/agentic-ui/ai-sdk-ui#using-mastra-memory).

<details>
  <summary>傳遞完整的輸入歷史記錄</summary>

  Mastra 在載入儲存的訊息之前過濾用戶端回顯的歷史記錄。當訊息 ID 匹配時，它會使用儲存的副本作為基礎，保留儲存的時間戳記和Provider元數據，同時保留新的Tool結果。

  如果您自己組裝請求輸入並需要完全按照發送的方式進行處理，請設定`retainFullInput: true` on `memory.options` for that call, or in the memory constructor options to apply it agent-wide. This disables input filtering, but stored history still loads. Every input message that isn't already stored is saved to the thread, including few-shot examples.
</details>

### 透過令牌限制歷史記錄 {/* #limit-history-by-tokens */}

訊息計數不能很好地反映上下文大小：Tool結果可能是幾個令牌或數千個。使用`messageHistory` to keep recent history within a token budget instead:

```typescript title="src/mastra/agents/test-agent.ts"
import { Agent } from '@mastra/core/agent'
import { Memory } from '@mastra/memory'

export const agent = new Agent({
  id: 'test-agent',
  memory: new Memory({
    options: {
      messageHistory: { maxTokens: 8_000, atMaxRemoveTokens: 2_000 },
    },
  }),
})
```

Mastra 計算完整的提示`maxTokens`, including remembered history, system instructions, context, and the current turn. When the prompt exceeds the budget, Mastra removes the oldest remembered messages until the prompt is at most `maxTokens - atMaxRemoveTokens`. `atMaxRemoveTokens` defaults to 25% of `maxTokens`. Removing history in chunks keeps the prompt prefix stable across several turns, which helps provider prompt caches stay warm.

系統訊息、上下文、當前回合的輸入和Agent的回應永遠不會被修剪。連結的Tool呼叫和結果會一起刪除。如果僅受保護的內容超過`maxTokens`, Mastra removes all remembered history but keeps the protected content.

修剪後的郵件保留在儲存中。在Agent運行期間，Mastra 會保留每個執行緒的邊界，以便將它們排除在以後的輪次之外。環境`messageHistory` without `lastMessages` disables the default 10-message cap. Set both to combine a count cap with a token budget. Set `maxTokens` to `0` to disable message history.

：：：提示

當記憶體啟用時，[Studio](/docs/studio/overview) uses message history to display past conversations in the chat sidebar.

:::

## 主題標題生成 {/* #thread-title-generation */}

當以下情況發生時，Mastra 可以從對話記錄中自動產生描述性主題標題：`generateTitle` is enabled. Use this option when you build a chat interface that renders conversation titles in a thread list or sidebar.

```typescript title="src/mastra/agents/support-agent.ts"
import { Agent } from '@mastra/core/agent'
import { Memory } from '@mastra/memory'

export const supportAgent = new Agent({
  id: 'support-agent',
  name: 'Support agent',
  instructions: 'Answer customer support questions.',
  model: '__GATEWAY_OPENAI_MODEL__',
  memory: new Memory({
    options: {
      generateTitle: true,
    },
  }),
})
```

標題生成在Agent回應後非同步運行，不會影響回應時間。

### 串流傳輸生成的標題 {/* #streaming-the-generated-title */}

預設情況下，標題會產生在後台運行，並且運行的流不會等待它，因此 HTTP 用戶端只能在下一個執行緒取得時看到標題。放`emitEvent: true` to deliver the title on the run's stream instead: the stream waits for the title and emits a transient `data-thread-title` chunk before `finish`.

```typescript title="src/mastra/agents/support-agent.ts"
import { Agent } from '@mastra/core/agent'
import { Memory } from '@mastra/memory'

export const supportAgent = new Agent({
  id: 'support-agent',
  name: 'Support agent',
  instructions: 'Answer customer support questions.',
  model: '__GATEWAY_OPENAI_MODEL__',
  memory: new Memory({
    options: {
      generateTitle: {
        emitEvent: true,
      },
    },
  }),
})
```

串流用戶接收帶有持久標題的區塊，因此聊天 UI 可以重命名其線程列表條目而無需輪詢：

```typescript oxfmt:false
for await (const chunk of stream.fullStream) {
  if (chunk.type === 'data-thread-title') {
    renameThreadInSidebar(chunk.data.threadId, chunk.data.title)
  }
}
```

該區塊是暫時的：它被傳遞給流消費者，但從未作為對話訊息的一部分持久存在。因為流等待標題，`emitEvent` delays the stream's `finish` on the turn that generates the title: the first turn of a thread, or a later turn when `minMessages` sets a higher threshold. Leave it off to keep title generation fully non-blocking.



`emitEvent`適用於`stream()` runs. `generate()` returns JSON and can't carry the chunk, so it keeps non-blocking title generation. [Durable and evented agents](/docs/harness/durable-agents) don't emit this chunk yet. In all of these cases the title is still generated and persisted.

:::

為了優化成本或行為，請提供更小的[`model`](/models) and custom `instructions`:

```typescript title="src/mastra/agents/support-agent.ts"
import { Agent } from '@mastra/core/agent'
import { Memory } from '@mastra/memory'

export const supportAgent = new Agent({
  id: 'support-agent',
  name: 'Support agent',
  instructions: 'Answer customer support questions.',
  model: '__GATEWAY_OPENAI_MODEL__',
  memory: new Memory({
    options: {
      generateTitle: {
        model: '__GATEWAY_OPENAI_MODEL_LUNA__',
        instructions: 'Generate a one-word title.',
      },
    },
  }),
})
```

## 存取記憶體 {/* #accessing-memory */}

若要存取記憶體函數以查詢、複製或刪除線程和訊息，請調用`getMemory()` on an agent:

```typescript
const agent = mastra.getAgentById('test-agent')
const memory = await agent.getMemory()
```

使用`Memory` instance to query stored threads and messages or clone a conversation.

## 查詢 {/* #querying */}

使用這些方法來取得線程和訊息，以便在 UI 中顯示對話歷史記錄或自訂記憶體檢索邏輯。

:::警告
記憶體系統不強制執行存取控制。在執行任何查詢之前，請在應用程式邏輯中驗證目前使用者是否有權訪問`resourceId` being queried.
:::

### 執行緒數 {/* #threads */}

使用[`listThreads()`](/reference/memory/listThreads) to retrieve threads for a resource:

```typescript
const result = await memory.listThreads({
  filter: { resourceId: 'user-123' },
  perPage: false,
})
```

透過線程分頁：

```typescript
const result = await memory.listThreads({
  filter: { resourceId: 'user-123' },
  page: 0,
  perPage: 10,
})

console.log(result.threads) // thread objects
console.log(result.hasMore) // more pages available?
```

您也可以按元資料過濾並控制排序順序：

```typescript
const result = await memory.listThreads({
  filter: {
    resourceId: 'user-123',
    metadata: { status: 'active' },
  },
  orderBy: { field: 'createdAt', direction: 'DESC' },
})
```

若要按 ID 取得單一線程，請使用[`getThreadById()`](/reference/memory/getThreadById):

```typescript
const thread = await memory.getThreadById({ threadId: 'thread-123' })
```

### 留言 {/* #messages */}

一旦有了線程，就可以使用[`recall()`](/reference/memory/recall) to retrieve its messages. It supports pagination and [semantic search](/docs/memory/semantic-recall), with optional date filtering.

取得線程的歷史記錄而不分頁。 Recall預設隱藏提醒訊號；經過`hideSignals: false` to include them, `true` to hide all recognized signals, or an array to omit selected types. See [signal visibility and compatibility](/reference/memory/recall#signal-visibility) for matching rules and precedence.

```typescript
const { messages } = await memory.recall({
  threadId: 'thread-123',
  perPage: false,
})
```

透過訊息分頁：

```typescript
const { messages } = await memory.recall({
  threadId: 'thread-123',
  page: 0,
  perPage: 50,
})
```

按日期範圍過濾：

```typescript
const { messages } = await memory.recall({
  threadId: 'thread-123',
  filter: {
    dateRange: {
      start: new Date('2025-01-01'),
      end: new Date('2025-06-01'),
    },
  },
})
```

按淺層訊息元資料過濾：

```typescript
const { messages } = await memory.recall({
  threadId: 'thread-123',
  filter: {
    metadata: {
      category: 'billing',
      escalated: true,
      priority: 2,
      archivedAt: null,
    },
  },
})
```

元資料過濾器僅匹配淺標量值：`string`, finite `number`, `boolean`, and `null`.

所有指定的元資料鍵都使用 AND 語意。一個`null` filter matches only an explicit `null` value. A missing metadata key doesn't match.

元資料鍵必須以字母或底線開頭，並且僅包含字母數字字元。它們必須為 128 個字元或更少，並且不能使用保留的原型鍵，例如`__proto__`, `constructor`, or `prototype`.

效能取決於儲存後端。有些後端可以將篩選器的一部分推送到資料庫中，而其他後端則在應用執行緒、資源和日期約束之後但在分頁之前掃描候選訊息。

透過ID獲取單一訊息：

```typescript
const { messages } = await memory.recall({
  threadId: 'thread-123',
  include: [{ id: 'msg-123' }],
})
```

透過 ID 和周圍上下文獲取多個訊息：

```typescript
const { messages } = await memory.recall({
  threadId: 'thread-123',
  include: [
    { id: 'msg-123' },
    {
      id: 'msg-456',
      withPreviousMessages: 3,
      withNextMessages: 1,
    },
  ],
})
```

按含義搜尋（參見[Semantic recall](/docs/memory/semantic-recall) for setup):

```typescript
const { messages } = await memory.recall({
  threadId: 'thread-123',
  vectorSearchString: 'project deadline discussion',
  threadConfig: {
    semanticRecall: true,
  },
})
```

### 使用者介面格式 {/* #ui-format */}

訊息查詢返回`MastraDBMessage[]` format. To display messages in a frontend, you may need to convert them to a format your UI library expects. For example, [`toAISdkV5Messages`](/reference/ai-sdk/to-ai-sdk-v5-messages) converts messages to AI SDK UI format.

## 執行緒克隆 {/* #thread-cloning */}

線程克隆創建現有線程及其訊息的副本。這對於在潛在破壞性操作之前分支對話或建立檢查點，或測試對話的變體非常有用。

```typescript
const { thread, clonedMessages } = await memory.cloneThread({
  sourceThreadId: 'thread-123',
  title: 'Branched conversation',
})
```

您可以按計數或日期範圍過濾複製訊息並指定自訂執行緒 ID。實用方法也可用於檢查克隆關係。

如果您不需要返回複製的訊息，例如在分叉長線程時，請使用`copyThread()`. It never returns message payloads, and on LibSQL and PostgreSQL the rows are copied inside the database. When semantic recall is enabled, the copied messages are still read back in batches to generate embeddings.

看[`cloneThread()`](/reference/memory/cloneThread), [`copyThread()`](/reference/memory/copyThread), and [clone utilities](/reference/memory/clone-utilities) for the full API.

## 刪除訊息 {/* #deleting-messages */}

若要從線程中刪除訊息，請使用[`deleteMessages()`](/reference/memory/deleteMessages). You can delete by message ID or clear all messages from a thread.
