# 工作記憶

儘管[message history](/docs/memory/message-history)和[語意回憶](./semantic-recall)幫助Agent記住對話，工作記憶使他們能夠在互動過程中維護有關使用者的持久資訊。

工作記憶是Agent的活動暫存器：它保留有關使用者或任務的關鍵資訊。它可以在對話過程中保留一個人的姓名、偏好或其他重要細節。

這對於維護始終相關且始終可供Agent使用的持續狀態非常有用。

如果你使用[Observational Memory](/docs/memory/observational-memory), `observationalMemory.observation.manageWorkingMemory` lets OM update working memory for the agent.

:::提示\[📹觀看]

手錶[Mastra working memory](https://www.youtube.com/watch?v=UMy_JHLf1n8\&pp=ygUVbWFzdHJhIHdvcmtpbmcgbWVtb3J5) to see how agents keep persistent user context available across interactions.

:::

工作記憶可以在兩個不同的範圍內持續存在：

* **資源範圍**（預設）：內存在同一使用者的所有對話線程中持續存在
* **線程範圍**：每個會話執行緒的記憶體是隔離的

**要求：**&#x5728;範圍之間切換意味著Agent不會看到來自其他範圍的記憶體 - 線程範圍記憶體與資源範圍記憶體完全分開。

## 快速入門 {/* #quickstart */}

以下是設定具有工作記憶體的Agent程式的最小範例：

```typescript {11-15}
import { Agent } from '@mastra/core/agent'
import { Memory } from '@mastra/memory'

// Create agent with working memory enabled
const agent = new Agent({
  id: 'personal-assistant',
  name: 'PersonalAssistant',
  instructions: 'You are a helpful personal assistant.',
  model: '__GATEWAY_OPENAI_MODEL__',
  memory: new Memory({
    options: {
      workingMemory: {
        enabled: true,
      },
    },
  }),
})
```

## 它是如何運作的 {/* #how-it-works */}

工作記憶是一個 Markdown 文字區塊，Agent可以隨著時間的推移更新它以連續儲存相關資訊。

## 記憶體持久性範圍 {/* #memory-persistence-scopes */}

工作記憶可以在兩個不同的範圍內運行，讓您選擇記憶在對話中持續存在的方式：

### 資源範圍記憶體（預設） {/* #resource-scoped-memory-default */}

預設情況下，工作內存在同一使用者 (resourceId) 的所有對話執行緒中保持不變，從而啟用持久的使用者記憶體：

```typescript
const memory = new Memory({
  storage,
  options: {
    workingMemory: {
      enabled: true,
      scope: 'resource', // Memory persists across all user threads
      template: `# User Profile
- **Name**:
- **Location**:
- **Interests**:
- **Preferences**:
- **Long-term Goals**:
`,
    },
  },
})
```

**使用案例：**

* 記住用戶偏好的個人助理
* 維護客戶背景的客戶服務機器人
* 追蹤學生進度的教育應用程式

### 與Agent一起使用 {/* #usage-with-agents */}

使用資源範圍記憶體時，請確保傳遞`resource` parameter in the memory options:

```typescript
// Resource-scoped memory requires resource
const response = await agent.generate('Hello!', {
  memory: {
    thread: 'conversation-123',
    resource: 'user-alice-456', // Same user across different threads
  },
})
```

### 線程範圍內存 {/* #thread-scoped-memory */}

線程範圍記憶體將工作記憶體與各個對話線程隔離。每個執行緒維護自己的隔離記憶體：

```typescript
const memory = new Memory({
  storage,
  options: {
    workingMemory: {
      enabled: true,
      scope: 'thread', // Memory is isolated per thread
      template: `# User Profile
- **Name**:
- **Interests**:
- **Current Goal**:
`,
    },
  },
})
```

**使用案例：**

* 關於不同主題的不同對話
* 臨時或特定於會話的訊息
* 每個線程都需要工作內存但線程是短暫的並且彼此不相關的Workflow

## 存儲適配器支持 {/* #storage-adapter-support */}

資源範圍的工作記憶體需要特定的儲存適配器來支援`mastra_resources` table:

### 支援的儲存適配器 {/* #supported-storage-adapters */}

* **函式庫SQL** (`@mastra/libsql`)
* **PostgreSQL** (`@mastra/pg`)
* **甲骨文資料庫** (`@mastra/oracledb`)
* **烏普斯塔什** (`@mastra/upstash`)
* **MongoDB** (`@mastra/mongodb`)

## 自訂模板 {/* #custom-templates */}

範本指導Agent追蹤和更新工作記憶中的哪些資訊。當您未提供模板時，Mastra 將使用預設模板。為Agent程式的用例定義自訂模板，以便它記住最相關的資訊。有關多個使用者共享的線程，請參閱[Multi-user threads](./multi-user-threads).

以下是自訂模板的範例。在此範例中，一旦使用者發送包含任何資訊的訊息，Agent就會儲存使用者名稱、位置、時區等：

```typescript {5-28}
const memory = new Memory({
  options: {
    workingMemory: {
      enabled: true,
      template: `
# User Profile

## Personal info

- Name:
- Location:
- Timezone:

## Preferences

- Communication Style: [e.g., Formal, Casual]
- Project Goal:
- Key Deadlines:
  - [Deadline 1]: [Date]
  - [Deadline 2]: [Date]

## Session state

- Last Task Discussed:
- Open Questions:
  - [Question 1]
  - [Question 2]
`,
    },
  },
})
```

## 設計有效的模板 {/* #designing-effective-templates */}

結構良好的範本可以讓Agent輕鬆解析和更新資訊。治療
模板作為您希望助手保持最新的簡短形式。

* **簡短、集中的標籤。**&#x907F;免段落或很長的標題。保持標籤簡短（例如`## Personal Info` or `- Name:`) so updates are readable and less likely to be truncated.
* **使用一致的外殼。**&#x5927;小寫不一致 (`Timezone:` vs `timezone:`) can cause messy
  updates. Stick to Title Case or lower case for headings and bullet labels.
* **盡量減少佔位符文字。**&#x4F7F;用提示，例如`[e.g., Formal]` or `[Date]` to help the LLM
  fill in the correct spots.
* **縮寫很長的值。**&#x5982;果您只需要一個簡短的表格，請包括類似的指導`- Name: [First name or nickname]` or `- Address (short):` rather than the full legal text.
* **提及更新規則`instructions`.**&#x60A8;可以指示如何以及何時填充或清除部分內容
  模板直接在Agent的`instructions` field.

### 替代模板樣式 {/* #alternative-template-styles */}

如果您只需要幾個項目，請使用較短的單一區塊：

```typescript
const basicMemory = new Memory({
  options: {
    workingMemory: {
      enabled: true,
      template: `User Facts:\n- Name:\n- Favorite Color:\n- Current Topic:`,
    },
  },
})
```

如果您喜歡更具敘事性的風格，您還可以以短段落格式儲存關鍵事實：

```typescript
const paragraphMemory = new Memory({
  options: {
    workingMemory: {
      enabled: true,
      template: `Important Details:\n\nKeep a short paragraph capturing the user's important facts (name, main goal, current task).`,
    },
  },
})
```

## 結構化工作記憶 {/* #structured-working-memory */}

工作記憶也可以使用結構化模式而不是 Markdown 模板來定義。一個[Standard JSON Schema](https://standardschema.dev/json-schema) ([Zod](https://zod.dev/), [Valibot](https://valibot.dev/), [ArkType](https://arktype.io/), etc.). When using a schema, the agent will see and update working memory as a JSON object matching your schema.

您可以指定`template` or `schema`, but not both. If you omit both, Mastra uses the default working memory template.

### 範例：基於模式的工作內存 {/* #example-schema-based-working-memory */}

```typescript
import { z } from 'zod'
import { Memory } from '@mastra/memory'

const userProfileSchema = z.object({
  name: z.string().optional(),
  location: z.string().optional(),
  timezone: z.string().optional(),
  preferences: z
    .object({
      communicationStyle: z.string().optional(),
      projectGoal: z.string().optional(),
      deadlines: z.array(z.string()).optional(),
    })
    .optional(),
})

const memory = new Memory({
  options: {
    workingMemory: {
      enabled: true,
      schema: userProfileSchema,
      // template: ... (do not set)
    },
  },
})
```

提供架構後，Agent程式會接收 JSON 物件形式的工作記憶體。例如：

```json
{
  "name": "Sam",
  "location": "Berlin",
  "timezone": "CET",
  "preferences": {
    "communicationStyle": "Formal",
    "projectGoal": "Launch MVP",
    "deadlines": ["2025-07-01"]
  }
}
```

### 基於模式的記憶體的合併語義 {/* #merge-semantics-for-schema-based-memory */}

基於模式的工作記憶使用**merge semantics**, meaning the agent only needs to include fields it wants to add or update. Existing fields are preserved automatically.

* **物件欄位深度合併：**&#x50C5;更新提供的欄位；其他保持不變
* **設定一個字段為`null` to delete it:**&#x9019;會明確地從記憶體中刪除該字段
* **數組被完全替換：**&#x7576;提供數組欄位時，它將替換現有數組（數組不會逐元素合併）

### 並發更新 {/* #concurrent-updates */}

和`scope: 'resource'` and a storage adapter that supports atomic merges (currently `@mastra/pg`), each merge runs inside a row-locked database transaction. Concurrent updates to different fields from separate processes are all kept. Other adapters merge in the application, which only serializes writers inside a single process.

`memory.mergeWorkingMemory()`:

```typescript
await memory.mergeWorkingMemory({
  threadId: 'thread-1',
  resourceId: 'user-123',
  workingMemory: { preferences: { tone: 'formal' } },
})
```

如果工作記憶體不是基於模式和資源範圍的，或者儲存適配器不支援原子合併，則會拋出該錯誤。查看`await memory.supportsAtomicWorkingMemoryMerge()` first if you need to fall back.

## 在範本和模式之間進行選擇 {/* #choosing-between-template-and-schema */}

* 使用一個**template** (Markdown) if you want the agent to maintain memory as a free-form text block, such as a user profile or scratchpad. Templates use **replace semantics**: the agent must provide the complete memory content on each update.
* 使用一個**schema** for structured, type-safe JSON data that supports validation and programmatic access. The `workingMemory.schema` field accepts any `PublicSchema`-compatible schema, such as Zod v3 or v4. JSON Schema and already-standard schemas are also supported. **Merge semantics** preserve existing fields when the agent provides only the fields to update.
* 一次只能啟動一種模式：同時設定兩種模式`template` and `schema` isn't supported.

## 範例：多步驟保留 {/* #example-multi-step-retention */}

下面是如何進行的簡化視圖`User Profile` template updates across a short user
conversation:

```nohighlight
# User Profile

## Personal info

- Name:
- Location:
- Timezone:

--- After user says "My name is **Sam** and I'm from **Berlin**" ---

# User Profile
- Name: Sam
- Location: Berlin
- Timezone:

--- After user adds "By the way I'm normally in **CET**" ---

# User Profile
- Name: Sam
- Location: Berlin
- Timezone: CET
```

Agent現在可以參考`Sam` or `Berlin` in later responses without requesting the information
again because it has been stored in working memory.

如果您的Agent程式沒有按照您的預期正確更新工作內存，您可以添加系統
說明*how* and *when* to use this template in your agent's `instructions` setting.

## 設定初始工作記憶 {/* #setting-initial-working-memory */}

雖然Agent通常透過以下方式更新工作記憶`updateWorkingMemory` tool, you can also set initial working memory programmatically when creating or updating threads. This is useful for injecting user data (like their name, preferences, or other info) that you want available to the agent without passing it in every request.

### 透過線程元資料設定工作內存 {/* #setting-working-memory-via-thread-metadata */}

創建線程時，可以透過元資料提供初始工作內存`workingMemory` key:

```typescript title="src/app/medical-consultation.ts"
// Create a thread with initial working memory
const thread = await memory.createThread({
  threadId: 'thread-123',
  resourceId: 'user-456',
  title: 'Medical Consultation',
  metadata: {
    workingMemory: `# Patient Profile
- Name: John Doe
- Blood Type: O+
- Allergies: Penicillin
- Current Medications: None
- Medical History: Hypertension (controlled)
`,
  },
})

// The agent will now have access to this information in all messages
await agent.generate("What's my blood type?", {
  memory: {
    thread: thread.id,
    resource: 'user-456',
  },
})
// Response: "Your blood type is O+."
```

### 以程式設計方式更新工作內存 {/* #updating-working-memory-programmatically */}

您也可以更新現有執行緒的工作記憶體：

```typescript title="src/app/medical-consultation.ts"
// Update thread metadata to add/modify working memory
await memory.updateThread({
  id: 'thread-123',
  title: thread.title,
  metadata: {
    ...thread.metadata,
    workingMemory: `# Patient Profile
- Name: John Doe
- Blood Type: O+
- Allergies: Penicillin, Ibuprofen  // Updated
- Current Medications: Lisinopril 10mg daily  // Added
- Medical History: Hypertension (controlled)
`,
  },
})
```

### 直接記憶體更新 {/* #direct-memory-update */}

或者，使用`updateWorkingMemory` method directly:

```typescript title="src/app/medical-consultation.ts"
await memory.updateWorkingMemory({
  threadId: 'thread-123',
  resourceId: 'user-456', // Required for resource-scoped memory
  workingMemory: 'Updated memory content...',
})
```

## 只讀工作記憶體 {/* #read-only-working-memory */}

在某些情況下，您可能希望Agent程式能夠存取工作記憶體數據，但無法對其進行修改。這對於：

* **路由Agent**需要上下文但不應更新用戶配置文件
* **分Agent**在應該引用但不擁有記憶體的多Agent系統中

若要啟用唯讀模式，請設定`readOnly: true` in the memory options:

```typescript
const response = await agent.generate('What do you know about me?', {
  memory: {
    thread: 'conversation-123',
    resource: 'user-alice-456',
    options: {
      readOnly: true, // Working memory is provided but cannot be updated
    },
  },
})
```

## 選擇狀態訊號（實驗） {/* #opt-in-to-state-signals-experimental */}

預設情況下，工作記憶體會作為系統訊息的一部分到達模型。您可以選擇將其作為[state signal](/docs/signals/state-signals) instead by setting `useStateSignals: true`:

```typescript
const memory = new Memory({
  storage: new LibSQLStore({ id: 'mastra-storage', url: 'file:./mastra.db' }),
  options: {
    workingMemory: {
      enabled: true,
      template: '# User\n- name:\n- location:',
      useStateSignals: true, // experimental: deliver as state signal
    },
  },
})
```

有何變化：

* **存儲是相同的。**&#x76F8;同的資源/線程`workingMemory` field is read and written.
* **該Tool具有相同的形狀，但以新名稱顯示。**&#x5BEB;入仍然透過相同的底層Tool進行；在此路徑上它被註冊為`setWorkingMemory` (instead of `updateWorkingMemory`). The rename keeps legacy strip filters from removing tool-call parts so they persist as a normal audit trail and the next model step picks the new value up automatically.
* **僅限送貨。**&#x800C;不是折疊到系統提示符中，`Memory` auto-attaches a `WorkingMemoryStateProcessor` that emits the current working memory as a `state` signal with `stateId: 'working-memory'`.

您繼承了標準狀態訊號的好處：線程範圍的追蹤元數據，`cacheKey` dedup so identical snapshots are only emitted once, and `contextWindow.hasSnapshot` re-injection when an older snapshot rolls out of the window.

預設(`useStateSignals: false`) keeps the existing system-message behavior unchanged. `useStateSignals` isn't supported with template working memory `version: 'vnext'`.
