# 多人共用對話串

多位使用者可以共用同一個 Mastra 對話串。使用 [`sendMessage()`](/docs/signals/sending-signals) 傳送每位使用者的訊息，並在訊息的 `attributes` 標示發言者。Mastra 會用帶有這些屬性的 `<user>` 標籤呈現訊息，讓 Agent 在目前輪次或日後載入歷程時，都能辨識各位參與者。

## 何時使用多人共用對話串 {/* #when-to-use-multi-user-threads */}

多人透過同一個 Agent 處理相同主題時，可以共用對話串，例如：

- 有編輯者、審查者和核准者參與的協作文件
- 由同一位助理服務多位參與者的群組聊天
- 不同角色有不同權限的審查流程

## 所有參與者共用同一個 `resourceId` {/* #share-one-resourceid-across-all-participants */}

每個對話串只屬於一個 `resourceId`，共用時所有人必須傳入相同的值。單人應用程式預設使用使用者 ID；共用時則以對話本身決定 `resourceId`，例如共用文件用 `doc_${docId}`，群組聊天用 `room_${roomId}`。大家使用相同的 `resourceId` 和 `threadId`，就會讀寫同一份歷程。

## 在每則訊息附上發言者身分 {/* #send-each-message-with-the-speakers-identity */}

傳入包含 `contents` 和 `attributes` 的物件作為訊息。每個屬性都會成為模型讀取的 `<user>` 標籤上的 XML 屬性：

```typescript title="src/mastra/send.ts"
agent.sendMessage(
  {
    contents: 'Please make the cover page teal.',
    attributes: { name: 'Alice', role: 'editor' },
  },
  { resourceId: 'doc_42', threadId: 'doc_42' },
)
```

此模型接收：

```xml
<user name="Alice" role="editor">Please make the cover page teal.</user>
```

Mastra 會自動跳脫屬性值。屬性名稱必須是有效的 XML 名稱，例如 `name`、`role` 或 `user_id`。若名稱無效，將訊息呈現給模型時會產生 `Invalid signal XML attribute name` 錯誤。屬性會隨訊息儲存，後續輪次載入歷程時，模型仍知道是誰說了什麼。

## 讓 Agent 知道如何讀取標籤 {/* #tell-the-agent-how-to-read-the-tag */}

在 Agent 的指示中說明 `<user>` 標籤及其屬性。Agent 需要設定 `memory`，訊息才會儲存在對話串：

```typescript title="src/mastra/agents/collab.ts"
import { Agent } from '@mastra/core/agent'
import { LibSQLStore } from '@mastra/libsql'
import { Memory } from '@mastra/memory'

const memory = new Memory({
  storage: new LibSQLStore({ id: 'collab-storage', url: 'file:./collab.db' }),
  options: {
    lastMessages: 20,
  },
})

export const collabAgent = new Agent({
  id: 'collab',
  name: 'CollabAgent',
  model: '__GATEWAY_OPENAI_MODEL_LUNA__',
  memory,
  instructions: `
You are a collaborative document assistant. Several people talk to you in the same thread.

Each user message arrives in a <user> tag whose attributes say who sent it:

  <user name="Alice" role="editor">...message text...</user>

Address people by name. Editors propose changes and reviewers approve them.
When you refer to something said earlier, name the person who said it.
  `.trim(),
})
```

將每位參與者的訊息送到同一個對話串。對話串閒置時，`sendMessage()` 會啟動一次執行，`accepted` 會以該次執行的輸出完成：

```typescript title="src/mastra/send.ts"
import { collabAgent } from './agents/collab'

const doc = { resourceId: 'doc_42', threadId: 'doc_42' }

async function send(speaker: { name: string; role: string }, text: string) {
  const { accepted } = collabAgent.sendMessage({ contents: text, attributes: speaker }, doc)
  const result = await accepted
  if (result.action === 'wake') {
    return (await result.output.getFullOutput()).text
  }
}

await send({ name: 'Alice', role: 'editor' }, 'Please make the cover page teal.')
await send({ name: 'Bob', role: 'reviewer' }, 'I want QA sign-off before we publish.')
await send({ name: 'Alice', role: 'editor' }, 'Who asked for QA sign-off?')
// The agent answers that Bob asked for it.
```

如果 Agent 還在回覆其他人，Mastra 會把新訊息送入目前的輪次，`accepted` 的結果是 `action: 'deliver'`。正式應用程式應從[對話串串流](/docs/signals/thread-streams)呈現回覆，以取代逐次使用 `sendMessage()` 的結果，讓每位參與者都看到同一段對話。

## 搭配不同的 Memory 層 {/* #combining-with-memory-layers */}

依對話需要保留發言者資訊的時間長短，選擇適合的 Memory 層：

- **簡短對話**，或需要逐字記錄發言者與內容時：只使用[訊息歷程](#message-history-alone)。
- **長時間持續的對話串**超出脈絡視窗時：使用 [Observational Memory](#with-observational-memory)。

### 只使用訊息歷程 {/* #message-history-alone */}

`lastMessages` 會將先前的訊息連同 `<user>` 屬性帶回脈絡，讓發言者資訊跨輪次保留。上方 Agent 範例就是這樣設定的。

### 搭配 Observational Memory {/* #with-observational-memory */}

[Observational Memory](/docs/memory/observational-memory)（OM）會以觀察紀錄取代較早的訊息，讓較長的共用對話串仍能放進脈絡視窗。請在同一個 `Memory` 執行個體啟用：

```typescript title="src/mastra/agents/collab-om.ts"
import { LibSQLStore } from '@mastra/libsql'
import { Memory } from '@mastra/memory'

const memory = new Memory({
  storage: new LibSQLStore({ id: 'collab-storage', url: 'file:./collab.db' }),
  options: {
    observationalMemory: true,
  },
})
```

OM 會取代 `lastMessages` 載入歷程的做法，啟用 OM 時請省略 `lastMessages`。

Observer 會保留發言者的屬性，讓觀察紀錄指出每句話是誰說的。帶有 `attributes: { name: 'Alice', role: 'editor' }` 的訊息會標示為 `User (name="Alice" role="editor")`；未提供屬性時只會標為 `User`。

## 安全 {/* #security */}

請在伺服器上根據已通過身分驗證的使用者設定屬性，切勿從請求主體取得。若用戶端可自行指定 `name`，使用者就能冒充他人。請透過[請求脈絡](/docs/server/request-context)從身分驗證層讀取已驗證的使用者，在呼叫 `sendMessage()` 前建立 `attributes`。
