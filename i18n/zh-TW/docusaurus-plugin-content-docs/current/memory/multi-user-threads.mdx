# 多用戶執行緒

單一 Mastra 執行緒可以由多個使用者共用。发送每个用户的消息[`sendMessage()`](/docs/signals/sending-signals)並將揚聲器放入訊息中`attributes`。 Mastra 將訊息呈現為`<user>`標籤攜帶這些屬性，因此Agent可以在現在以及稍後從歷史記錄中載入訊息時區分參與者。

## 何時使用多用戶執行緒 {/* #when-to-use-multi-user-threads */}

當多人透過一個Agent處理同一主題時，請使用多用戶線程：

* 與編輯、審閱者和批准者協作的文檔
* 一名助理為多名參與者提供服務的群聊
* 審查不同角色具有不同權限的情況

## 分享一個`resourceId` across all participants {/* #share-one-resourceid-across-all-participants */}

`resourceId`, so everyone on a shared thread needs to pass the same value. Instead of a user ID (the default for single-user apps), key `resourceId` on the conversation itself, for example `doc_${docId}` for a shared document or `room_${roomId}` for a group chat. With everyone pointing at the same `resourceId` and `threadId`, they read and write the same history.

## 發送帶有說話者身份的每個訊息 {/* #send-each-message-with-the-speakers-identity */}

將訊息作為對象傳遞`contents` and `attributes`. Each attribute becomes an XML attribute on the `<user>` tag the model reads:

```typescript title="src/mastra/send.ts"
agent.sendMessage(
  {
    contents: 'Please make the cover page teal.',
    attributes: { name: 'Alice', role: 'editor' },
  },
  { resourceId: 'doc_42', threadId: 'doc_42' },
)
```

此模型接收：

```xml
<user name="Alice" role="editor">Please make the cover page teal.</user>
```

Mastra 為您轉義屬性值。屬性名稱必須是有效的 XML 名稱，例如`name`, `role` or `user_id`. Any other name fails with `Invalid signal XML attribute name` when the message is rendered for the model. The attributes are stored with the message, so when history loads on a later turn, the model still sees who said what.

## 告訴Agent如何讀取標籤 {/* #tell-the-agent-how-to-read-the-tag */}

描述`<user>` tag and its attributes in the agent's instructions. The agent needs `memory` so its messages are stored on the thread:

```typescript title="src/mastra/agents/collab.ts"
import { Agent } from '@mastra/core/agent'
import { LibSQLStore } from '@mastra/libsql'
import { Memory } from '@mastra/memory'

const memory = new Memory({
  storage: new LibSQLStore({ id: 'collab-storage', url: 'file:./collab.db' }),
  options: {
    lastMessages: 20,
  },
})

export const collabAgent = new Agent({
  id: 'collab',
  name: 'CollabAgent',
  model: '__GATEWAY_OPENAI_MODEL_LUNA__',
  memory,
  instructions: `
You are a collaborative document assistant. Several people talk to you in the same thread.

Each user message arrives in a <user> tag whose attributes say who sent it:

  <user name="Alice" role="editor">...message text...</user>

Address people by name. Editors propose changes and reviewers approve them.
When you refer to something said earlier, name the person who said it.
  `.trim(),
})
```

將每個參與者的消息傳送到同一個執行緒。當線程空閒時，`sendMessage()` starts a run and `accepted` resolves with its output:

```typescript title="src/mastra/send.ts"
import { collabAgent } from './agents/collab'

const doc = { resourceId: 'doc_42', threadId: 'doc_42' }

async function send(speaker: { name: string; role: string }, text: string) {
  const { accepted } = collabAgent.sendMessage({ contents: text, attributes: speaker }, doc)
  const result = await accepted
  if (result.action === 'wake') {
    return (await result.output.getFullOutput()).text
  }
}

await send({ name: 'Alice', role: 'editor' }, 'Please make the cover page teal.')
await send({ name: 'Bob', role: 'reviewer' }, 'I want QA sign-off before we publish.')
await send({ name: 'Alice', role: 'editor' }, 'Who asked for QA sign-off?')
// The agent answers that Bob asked for it.
```

當客服人員仍在回覆其他人時收到訊息時，Mastra 將其傳遞到正在運行的回合中，而不是開始新的回合，並且`accepted` resolves with `action: 'deliver'`. In a live app, render replies from the [thread stream](/docs/signals/thread-streams) rather than from each `sendMessage()` call. That way every participant sees the same conversation.

## 與記憶層結合 {/* #combining-with-memory-layers */}

根據對話需要記住每個參與者的時間來選擇記憶層：

* **簡短的對話**，或者當您需要逐字記錄誰說了什麼時：使用[message history alone](#message-history-alone).
* **長時間運行的執行緒**超出上下文視窗：使用[Observational Memory](#with-observational-memory).

### 僅訊息歷史記錄 {/* #message-history-alone */}

`lastMessages`將較早的消息帶回上下文中`<user>` attributes, so attribution survives across turns. The agent example above uses this setup.

### 具有觀察記憶 {/* #with-observational-memory */}

[觀察記憶](/docs/memory/observational-memory)(OM) 透過用觀察取代舊訊息，在上下文視窗內保留一個長共享執行緒。在相同的情況下啟用它`Memory`:

```typescript title="src/mastra/agents/collab-om.ts"
import { LibSQLStore } from '@mastra/libsql'
import { Memory } from '@mastra/memory'

const memory = new Memory({
  storage: new LibSQLStore({ id: 'collab-storage', url: 'file:./collab.db' }),
  options: {
    observationalMemory: true,
  },
})
```

OM 取代`lastMessages` history loading, so leave `lastMessages` out when OM is on.

觀察者保留說話者的屬性，因此觀察結果顯示誰說了什麼。發送的訊息`attributes: { name: 'Alice', role: 'editor' }` is labeled `User (name="Alice" role="editor")`. Messages sent without attributes are labeled plain `User`.

## 安全 {/* #security */}

從經過身份驗證的使用者（而不是請求正文）設定伺服器上的屬性。如果客戶可以選擇自己的`name`, one user can impersonate another. Use [request context](/docs/server/request-context) to read the verified user from your auth layer and build the `attributes` before calling `sendMessage()`.
