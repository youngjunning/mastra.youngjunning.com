# 子 Agent

**推出版本：** `@mastra/core@1.8.0`

子 Agent 是專門處理特定工作的 Agent，其他 Agent 可以將任務委派給它們。先把子 Agent 加到父 Agent 的 `agents` 屬性，再呼叫 [`Agent.stream()`](/reference/streaming/agents/stream) 或 [`Agent.generate()`](/reference/agents/generate)。父 Agent 會根據自身指示和各子 Agent 的 `description`，判斷何時以及如何委派任務。

## 何時使用子 Agent {/* #when-to-use-subagents */}

如果任務需要不同專長的 Agent 合作，就適合使用子 Agent。父 Agent 決定委派時機、將情境傳給各子 Agent，再整合它們的結果。

常見用途：

- 研究與寫作流程：由一個 Agent 蒐集資料，另一個 Agent 撰寫內容
- 各階段需要不同專業能力的多步驟任務
- 需要細緻控制委派行為的任務

:::note

負責協調子 Agent 的父 Agent 通常稱為監督 Agent。監督模式是 Mastra 建立多 Agent 系統的其中一種做法。其他做法請參閱[概念總覽](/docs/guides/multi-agent-systems)。

:::

## 快速開始 {/* #quickstart */}

先為子 Agent 撰寫清楚的描述，再將它們加入父 Agent：

```typescript title="src/mastra/agents/parent-agent.ts"
import { Agent } from '@mastra/core/agent'
import { Memory } from '@mastra/memory'
import { LibSQLStore } from '@mastra/libsql'

const researchAgent = new Agent({
  id: 'research-agent',
  // highlight-next-line
  description: 'Gathers factual information and returns bullet-point summaries.',
  model: '__GATEWAY_OPENAI_MODEL_LUNA__',
})

const writingAgent = new Agent({
  id: 'writing-agent',
  // highlight-next-line
  description: 'Transforms research into well-structured articles.',
  model: '__GATEWAY_OPENAI_MODEL_LUNA__',
})

// highlight-start
const parentAgent = new Agent({
  id: 'parent-agent',
  instructions: `You coordinate research and writing using specialized agents.
    Delegate to research-agent for facts, then writing-agent for content.`,
  model: '__GATEWAY_OPENAI_MODEL__',
  agents: { researchAgent, writingAgent },
  memory: new Memory({
    storage: new LibSQLStore({ id: 'storage', url: 'file:mastra.db' }),
  }),
})
// highlight-end

const stream = await parentAgent.stream('Research AI in education and write an article', {
  maxSteps: 10,
})

for await (const chunk of stream.textStream) {
  process.stdout.write(chunk)
}
```

## 委派掛鉤 {/* #delegation-hooks */}

委派掛鉤可在委派發生時攔截、修改或拒絕委派。你可以在 Agent 的 `delegation` 設定在 `defaultOptions`，也可以針對個別呼叫設定。

### `onDelegationStart` {/* #ondelegationstart */}

父 Agent 委派任務給子 Agent 前會呼叫此掛鉤。回傳物件即可控制該次委派：

- `proceed: true`：允許委派（預設行為）
- `proceed: false`：拒絕委派，並提供 `rejectionReason`
- `modifiedPrompt`：改寫傳給子 Agent 的提示
- `modifiedMaxSteps`：設定子 Agent 的迭代額度。此設定會覆蓋模型提供的 `maxSteps` 上限，因此可以調高或調低額度
- `threadMetadata`：建立子 Agent 執行緒時附加中繼資料（例如 `tenantId`），以便用 `memory.listThreads({ filter: { metadata } })` 篩選執行緒

:::note
監督模型在委派時傳入 `maxSteps`，Mastra 會將其限制為不高於子 Agent 的 `defaultOptions.maxSteps`。模型因此能降低子 Agent 的額度，卻無法提高。`modifiedMaxSteps` 會在套用上限後取代受限的值，因此能把額度提高到子 Agent 的預設值以上。可用它避免監督模型讓子 Agent 過早結束。
:::

```typescript title="src/mastra/agents/parent-agent.ts"
const stream = await parentAgent.stream('Research AI trends', {
  maxSteps: 10,
  delegation: {
    onDelegationStart: async context => {
      console.log(`Delegating to: ${context.primitiveId}`)

      // Modify the prompt for a specific agent
      if (context.primitiveId === 'research-agent') {
        return {
          proceed: true,
          modifiedPrompt: `${context.prompt}\n\nFocus on 2024-2025 data.`,
          modifiedMaxSteps: 5,
        }
      }

      // Reject delegation after too many iterations
      if (context.iteration > 8) {
        return {
          proceed: false,
          rejectionReason: 'Max iterations reached. Synthesize current findings.',
        }
      }

      return { proceed: true }
    },
  },
})
```

`context` 物件包含：

| 屬性 | 說明 |
| - | - |
| `primitiveId` | 接受委派的子 Agent ID |
| `prompt` | 父 Agent 傳送的提示 |
| `iteration` | 目前迭代次數 |
| `requestContext` | 子 Agent 執行時會收到的請求情境 |

### 委派邊界的請求情境 {/* #request-context-at-the-delegation-boundary */}

每次委派都會收到請求情境，其中的項目從父 Agent 執行時的情境淺層複製，但不包含只適用於該次執行的身分鍵。子 Agent 執行期間新增或刪除項目，不會影響父 Agent 的情境。若要傳值給這次委派，請在 `context.requestContext` 設定項目，並把這段操作放在 `onDelegationStart` 掛鉤中：

```typescript title="src/mastra/agents/parent-agent.ts"
const stream = await parentAgent.stream('Research AI trends', {
  maxSteps: 10,
  delegation: {
    onDelegationStart: async context => {
      context.requestContext.set('audience', 'technical')
    },
  },
})
```

子 Agent 可以在 Tool 與動態設定中讀取這些項目，例如 `instructions: ({ requestContext }) => ...`。詳情請參閱[請求情境](/docs/server/request-context)。若要搭配可持久化的 Agent 使用，值必須可序列化為 JSON。

### `onDelegationComplete` {/* #ondelegationcomplete */}

委派結束後會呼叫此掛鉤。可用來檢查結果、提供回饋，或停止執行：

- `context.bail()`：立即停止父 Agent 的迴圈
- 回傳 `{ feedback: '...' }`：將回饋存入父 Agent 的記憶，供下一輪使用
- 回傳 `{ resultText: '...' }`：在目前執行中，取代父模型看到的該次委派 Tool 結果文字

當子 Agent 的原始結果可能誤導父 Agent 時，請設定 `resultText`。例如，子 Agent 停在 Tool 呼叫步驟並回傳空白文字時，父模型可能誤以為委派成功，只是沒有內容。你也可以將失敗委派的錯誤文字換成更有幫助的訊息，但委派不會因此恢復；父 Agent 仍會收到失敗的 Tool 結果。`feedback` 要到下一輪才生效，`resultText` 則會立即影響父 Agent 的推理。

若要在失敗時停止父 Agent，並儲存回饋供日後使用，請呼叫 `bail()` 並回傳 `feedback`：

```typescript title="src/mastra/agents/parent-agent.ts"
const stream = await parentAgent.stream('Research AI trends', {
  maxSteps: 10,
  delegation: {
    onDelegationComplete: async context => {
      console.log(`Completed: ${context.primitiveId}`)

      // Bail on errors
      if (context.error) {
        context.bail()
        return {
          feedback: `Delegation to ${context.primitiveId} failed: ${context.error}. Try a different approach.`,
        }
      }
    },
  },
})
```

`context` 物件包含：

| 屬性 | 說明 |
| - | - |
| `primitiveId` | 已執行的子 Agent ID |
| `result` | 子 Agent 的回應；可用時包含 `text`、`usage`、`finishReason`、`subAgentToolResults`、`subAgentPendingToolCalls`、`subAgentThreadId` 和 `subAgentResourceId` |
| `success` | 委派是否成功 |
| `error` | 委派失敗時的原始錯誤 |
| `messages` | 收集到的子 Agent 對話紀錄，包含可用的部分訊息 |
| `bail()` | 停止父 Agent 迴圈的函式 |

#### 委派失敗 {/* #failed-delegations */}

子 Agent 執行失敗時，父模型會收到附帶一般錯誤訊息的失敗 Tool 結果。這不會自動停止父 Agent；它可以說明失敗原因，也可以改用其他方式。若要停止迴圈，請呼叫 `context.bail()`。

掛鉤會收到 `success: false`、原始 `error`，以及已收集到的部分結果與訊息。回傳 `resultText` 會取代父模型看到的錯誤文字，但不會改變委派的失敗狀態，也不會捨棄原始原因。空字串也是有效的替代值。

若要讓父 Agent 依照整理過的失敗訊息繼續，而非停止迴圈，請回傳 `resultText`，不要呼叫 `bail()`：

```typescript title="src/mastra/agents/parent-agent.ts"
const stream = await parentAgent.stream('Research AI trends', {
  maxSteps: 10,
  delegation: {
    onDelegationComplete: ({ success }) => {
      if (!success) {
        return {
          resultText: 'The delegated task failed. Try another approach.',
        }
      }
    },
  },
})
```

建議如範例所示，提供整理過的訊息。回傳 `{ resultText: error.message }` 會把底層錯誤訊息直接傳給父模型的 Provider，模型也可能轉述給終端使用者。Provider 錯誤可能含有敏感資訊。一般性的 `resultText` 也不能取代日誌、Trace 或串流錯誤內容的遮蔽政策。

委派若以[背景任務](/docs/harness/background-tasks)執行，設定的重試可能讓每次嘗試都觸發一次 `onDelegationComplete`。如果掛鉤有副作用，請處理重複呼叫。

### 掛鉤錯誤 {/* #hook-errors */}

委派掛鉤擲出錯誤時，預設仍會繼續委派：`onDelegationStart` 沿用原始提示，`messageFilter` 改用未篩選的情境，`onDelegationComplete` 保留子 Agent 的原始結果。若要讓委派失敗，請設定 `hookErrorStrategy: 'throw'`。

```typescript title="src/mastra/agents/parent-agent.ts"
const stream = await parentAgent.stream('Research AI trends', {
  maxSteps: 10,
  delegation: {
    hookErrorStrategy: 'throw',
    onDelegationComplete: async ({ result }) => {
      // If this throws, the parent sees a failed delegation instead of a
      // successful one whose result was silently dropped.
      await reportToAnalytics(result)
    },
  },
})
```

不論選用哪種方式，每次掛鉤失敗都會記錄在該次執行的請求情境中，鍵為 `__mastra_delegationHookErrors`，值為 `{ hook, primitiveId, toolCallId, runId, name, message }` 項目組成的清單，方便以程式偵測：

```typescript title="src/mastra/agents/parent-agent.ts"
import { RequestContext } from '@mastra/core/request-context'

const requestContext = new RequestContext()

await parentAgent.generate('Research AI trends', { maxSteps: 10, requestContext })

const hookErrors = requestContext.get('__mastra_delegationHookErrors') ?? []
```

當 `hookErrorStrategy` 設為 `'throw'` 時，`onDelegationStart` 擲出錯誤會完全阻止子 Agent 執行；`messageFilter` 或 `onDelegationComplete` 擲出錯誤，則會以失敗的 Tool 呼叫呈現給父 Agent。如果 `onDelegationComplete` 在處理失敗委派時擲出錯誤，對外呈現的仍是原始委派錯誤。掛鉤不會因自身失敗而再次觸發。

## 訊息篩選 {/* #message-filtering */}

子 Agent 預設會收到父 Agent 的完整對話情境。使用 `messageFilter` 控制要分享哪些訊息，例如移除敏感資料或限制情境大小。

```typescript title="src/mastra/agents/parent-agent.ts"
const stream = await parentAgent.stream('Research AI trends', {
  maxSteps: 10,
  delegation: {
    messageFilter: ({ messages, primitiveId, prompt }) => {
      // Remove messages containing sensitive data
      return messages
        .filter(msg => {
          const content =
            typeof msg.content === 'string' ? msg.content : JSON.stringify(msg.content)
          return !content.includes('confidential')
        })
        .slice(-10) // Only pass the last 10 messages
    },
  },
})
```

回呼會收到 `messages`（完整對話紀錄）、`primitiveId`（子 Agent ID）和 `prompt`（委派提示）。請回傳篩選後的訊息陣列。

## 子 Agent 的結果情境 {/* #subagent-result-context */}

子 Agent 完成後，父 Agent 的模型會在後續迭代收到子 Agent 的文字回應。巢狀 Tool 呼叫與子 Agent 中繼資料（例如執行緒 ID 和資源 ID）不會加入父 Agent 的模型情境。

應用程式程式碼與 UI 整合仍可從 Tool 結果的內容中檢視 `subAgentToolResults` 和其餘原始委派結果。

這樣既能保留除錯與顯示所需的資料，也不必在父 Agent 下一次呼叫模型時傳入巢狀 Tool 的引數或輸出。

子 Agent 無法執行客戶端 Tool（沒有 `execute` 函式的 Tool）。若子 Agent 呼叫這類 Tool，該次執行會停在當前步驟，`finishReason: 'tool-calls'`。委派結果會在 `subAgentPendingToolCalls` 列出尚未執行的呼叫，父 Agent 的模型也會得知哪些 Tool 未執行，而 Mastra 會記錄警告。請把客戶端 Tool 提供給父 Agent；如果子 Agent 需要使用者輸入，可在其 Tool 中使用 [`suspend()`](/docs/agents/human-in-the-loop#use-suspend-in-supervisor-agents)。

設定 `includeSubAgentToolResultsInModelContext`，即可將完整子 Agent 結果（包含巢狀 Tool 結果和子 Agent 中繼資料）加入父 Agent 的模型情境。

```typescript title="src/mastra/agents/parent-agent.ts"
await parentAgent.generate('Research AI trends', {
  delegation: {
    includeSubAgentToolResultsInModelContext: true,
  },
})
```

### 重複使用先前的子 Agent 結果 {/* #reusing-an-earlier-subagent-result */}

子 Agent 的結果預設以 Tool 結果形式送達父 Agent，但這些結果會從轉送給後續子 Agent 的情境中移除。父 Agent 必須在下一次委派提示中重述先前的結果，會消耗 token，也可能遺漏細節。

設定 `enableResultReferences`，即可讓後續委派原封不動地使用先前的結果：

```typescript title="src/mastra/agents/parent-agent.ts"
await parentAgent.generate('Find and fix the token refresh bug', {
  delegation: {
    enableResultReferences: true,
  },
})
```

啟用後：

- 每個成功且非空的子 Agent 結果都會取得引用 ID，例如 `explorer-1`。父 Agent 的模型會在子 Agent 文字後看到 `[ref: explorer-1]` 這一行。
- 委派 Tool 會增加 `contextFromRefs` 輸入。父 Agent 可以傳入先前的 ID，形式可以是字串（`["explorer-1"]`），也可以是附有選填標籤和註記的物件（`[{ ref: "explorer-1", as: "investigation", note: "bug location" }]`）。
- 引用文字會插入委派提示之前，每個結果各自放在標記區塊中，內容與先前子 Agent 產生的文字完全相同。`onDelegationStart` 與 `messageFilter` 收到展開後的提示。
- 若 `onDelegationComplete` 回傳 `resultText`，後續委派收到的便是取代後的文字。

引用只會保留在單次父 Agent 執行的記憶體中，不會持久儲存。遭拒絕、失敗、結果為空，以及背景任務形式的委派都不會取得引用 ID。未知 ID 會略過並記錄警告，委派則繼續進行。

引用文字來自另一個 Agent。每個區塊都會使用新產生、難以預測的標籤，並提醒接收的子 Agent 將內容視為資料。若子 Agent 會處理不可信任的輸入，仍應在 `onDelegationStart` 或透過 Processor 自行檢查。

## 迭代監控 {/* #iteration-monitoring */}

父 Agent 的迴圈每完成一次迭代，就會呼叫 `onIterationComplete`。你可以用它監控執行情況、引導下一次迭代，或提早停止。

```typescript title="src/mastra/agents/parent-agent.ts"
const stream = await parentAgent.stream('Research AI trends', {
  maxSteps: 10,
  onIterationComplete: async context => {
    console.log(`Iteration ${context.iteration}/${context.maxIterations}`)
    console.log(`Finish reason: ${context.finishReason}`)

    // Inject feedback to guide the agent
    if (!context.text.includes('recommendations')) {
      return {
        continue: true,
        feedback: 'Please include specific recommendations in your analysis.',
      }
    }

    // Stop early when the response is sufficient
    if (context.text.length > 1000 && context.finishReason === 'stop') {
      return { continue: false }
    }

    return { continue: true }
  },
})
```

回傳 `{ continue: true }` 會繼續迭代，回傳 `{ continue: false }` 則會停止。也可以透過選填的 `feedback` 在對話中加入指引。若 `feedback` 與 `continue: false` 同時設定，模型可能會再取得最後一輪機會，產生納入回饋的文字回應。只有目前迭代仍在進行中（例如 Tool 呼叫剛結束），才會額外提供這一輪。

## 記憶隔離 {/* #memory-isolation */}

Mastra 在委派期間隔離子 Agent 的記憶。子 Agent 會收到完整對話情境，以利判斷，但只有該次委派的提示和回應會存入自己的記憶。

運作方式：

1. **轉送完整情境**：父 Agent 委派任務時，子 Agent 會收到父 Agent 對話中的所有訊息
1. **限定記憶寫入範圍**：只有委派提示和子 Agent 的回應會存入子 Agent 的記憶
1. **每次呼叫都使用新執行緒**：每次委派都有專屬的執行緒 ID，彼此清楚區隔

因此，子 Agent 既有完成任務所需的情境，也不會讓父 Agent 的整段對話佔據自己的記憶。詳情請參閱[多 Agent 系統中的記憶](/docs/memory/overview#memory-in-multi-agent-systems)。

## Tool 核准請求的傳遞 {/* #tool-approval-propagation */}

Tool 的核准請求會沿委派鏈傳遞。子 Agent 使用設有 `requireApproval: true` 的 Tool 或呼叫 `suspend()` 時，核准請求會出現在父 Agent 的串流中。

```typescript
const sensitiveDataTool = createTool({
  id: 'get-user-data',
  requireApproval: true,
  execute: async input => {
    return await database.getUserData(input.userId)
  },
})

const dataAgent = new Agent({
  id: 'data-agent',
  tools: { sensitiveDataTool },
})

const parentAgent = new Agent({
  id: 'parent-agent',
  agents: { dataAgent },
  memory: new Memory(),
})

const stream = await parentAgent.stream('Get data for user 123')

for await (const chunk of stream.fullStream) {
  if (chunk.type === 'tool-call-approval') {
    console.log('Tool requires approval:', chunk.payload.toolName)
  }
}
```

## 取消執行 {/* #cancellation */}

將 `abortSignal` 傳給父 Agent 的 [`stream()`](/reference/streaming/agents/stream) 或 [`generate()`](/reference/agents/generate) 呼叫時，Mastra 會把同一個訊號轉送給接受委派的子 Agent。呼叫 `AbortController.abort()` 後，執行中的子 Agent 會在下一個步驟取消，不會繼續執行到完成。

```typescript
const controller = new AbortController()

const stream = await parentAgent.stream('Research AI trends', {
  abortSignal: controller.signal,
})

// Cancel the parent agent and any in-flight subagents
controller.abort()
```

## 任務完成評分 {/* #task-completion-scoring */}

Agent 不一定第一次就能產生完整且正確的輸出。任務完成評分器會在每次迭代後驗證任務是否完成；若驗證失敗，父 Agent 會繼續迭代。未通過的評分回饋會加入對話情境，讓子 Agent 知道還缺少什麼。

```typescript
import { createScorer } from '@mastra/core/evals'

const taskCompleteScorer = createScorer({
  id: 'task-complete',
  name: 'Task Completeness',
}).generateScore(async context => {
  const text = (context.run.output || '').toString()
  const hasAnalysis = text.includes('analysis')
  const hasRecommendations = text.includes('recommendation')
  return hasAnalysis && hasRecommendations ? 1 : 0
})

const stream = await parentAgent.stream('Research AI in education', {
  maxSteps: 10,
  isTaskComplete: {
    scorers: [taskCompleteScorer],
    strategy: 'all',
    onComplete: async result => {
      console.log('Task complete:', result.complete)
    },
  },
})
```

### 評分規準評分器 {/* #rubric-scorer */}

內建的評分規準評分器讓你以檢查清單定義「正確」，並讓 Agent 自我評估、反覆嘗試，直到符合所有規準或達到 `maxSteps`。

它使用 **LLM-as-judge** 評分方式。每次迭代後，另一個評分模型會依規準檢視 Agent 的輸出。所有必要項目均通過時，迴圈就會結束；未通過的項目則會把回饋加入對話，供 Agent 再次嘗試。

這種方式最適合成功條件明確、可驗證的任務。用法如下：

```typescript title="src/mastra/agents/rubric-scorer.ts"
import { Agent } from '@mastra/core/agent'
import { createRubricScorer } from '@mastra/evals/scorers/prebuilt'

const parentAgent = new Agent({
  id: 'parent-agent',
  instructions: 'You coordinate research and writing using specialized agents.',
  model: '__GATEWAY_OPENAI_MODEL__',
  agents: { researchAgent, writingAgent },
})

const rubricScorer = createRubricScorer({
  model: '__GATEWAY_OPENAI_MODEL_LUNA__',
  criteria: [
    { description: 'The response includes an analysis section' },
    { description: 'The response includes concrete recommendations' },
  ],
})

const stream = await parentAgent.stream('Research AI in education', {
  maxSteps: 10,
  isTaskComplete: {
    scorers: [rubricScorer],
    strategy: 'all',
  },
})
```

完整的 API 說明請參閱[評分規準評分器參考文件](/reference/evals/rubric)。

## 撰寫有效的指示 {/* #writing-effective-instructions */}

清楚的指示是有效委派的關鍵。

父 Agent 的 `instructions` 應列出可用資源及各自的使用時機，並定義協作方式和成功條件。

每個子 Agent 都應有明確的 `description`，說明用途、回傳格式，以及父 Agent 何時應使用它。

父 Agent 會根據這些描述決定委派方式。

```typescript
const parentAgent = new Agent({
  id: 'parent-agent',
  instructions: `You coordinate research and writing tasks.

Available resources:
- researchAgent: Gathers factual data and sources (returns bullet points)
- writingAgent: Transforms research into narrative content (returns full paragraphs)

Delegation strategy:
1. For research requests: Delegate to researchAgent first
2. For writing requests: Delegate to writingAgent
3. For complex requests: Delegate to researchAgent first, then writingAgent

Success criteria:
- All user questions are fully answered
- Response is well-formatted and complete`,
  agents: { researchAgent, writingAgent },
})
```

## 在背景執行子 Agent {/* #running-subagents-in-the-background */}

子 Agent 的呼叫會以 Tool 呼叫形式派送，因此可以作為[背景任務](/docs/harness/background-tasks)執行。如果一個或多個委派耗時較長，而你不希望阻塞父 Agent 的回應，就適合這樣做。

在 Mastra 實例上啟用 [backgroundTasks 管理器](/reference/configuration#backgroundtasks)，然後為父 Agent 的子 Agent 開啟背景執行：

```typescript title="src/mastra/agents/parent-agent.ts"
import { Agent } from '@mastra/core/agent'

const parentAgent = new Agent({
  id: 'parent-agent',
  instructions: 'Coordinate research and writing using the available agents.',
  model: '__GATEWAY_OPENAI_MODEL__',
  agents: { researchAgent, writingAgent },
  // highlight-start
  backgroundTasks: {
    tools: {
      researchAgent: { enabled: true, timeoutMs: 900_000 },
      writingAgent: { enabled: true, timeoutMs: 900_000 },
    },
  },
  // highlight-end
})

const stream = await parentAgent.streamUntilIdle('Research AI in education and write an article', {
  memory: { thread: 't1', resource: 'u1' },
})
```

請使用 [`streamUntilIdle()`](/reference/streaming/agents/streamUntilIdle)，而不是 `stream()`，讓串流維持開啟，直到子 Agent 完成且父 Agent 有機會回應其結果。

即使子 Agent 未列於父 Agent 的 `backgroundTasks.tools`，只要它本身有符合背景執行條件的 Tool，父 Agent 仍會將它派送為背景任務，並繼承其設定。詳情請參閱[繼承子 Agent 的設定](/docs/harness/background-tasks#inheriting-from-the-subagent)。

## 子 Agent 版本管理 {/* #subagent-versioning */}

使用 [Editor](/docs/studio/editor) 時，可以控制父 Agent 在執行期間採用各子 Agent 的哪個已儲存版本。版本覆寫可設於 Mastra 實例，也可針對個別呼叫設定：

```typescript
const result = await parentAgent.generate('Research and write about AI safety', {
  versions: {
    agents: {
      'research-agent': { status: 'published' },
      'writing-agent': { versionId: 'draft-456' },
    },
  },
})
```

版本覆寫會沿委派鏈自動傳遞。解析順序及伺服器 API 的詳情請參閱[子 Agent 版本管理](/reference/editor/versioning#sub-agent-versioning)。
