# 授權

[Studio](/docs/studio/overview)

您可以從基本的共享秘密 JWT 身份驗證開始，並在需要更高級的身份功能時切換到已知的Provider。

## 身份驗證保護什麼 {/* #what-auth-secures */}

設定身份驗證可以鎖定兩件事：

* **工作室使用者介面**
* **API路線**：內建路線（`/api/agents/*`, `/api/workflows/*`, etc.) and custom routes require authentication, whether requests come from Studio or direct API calls. A few built-in routes stay public, such as `GET /api/auth/capabilities`, which Studio uses to detect the login state.

預設情況下，您設定的Provider`server.auth` protects both. To give Studio its own provider, also set `studio.auth`. Requests from Studio, including its calls to API routes, then use `studio.auth` exclusively. All other requests keep using `server.auth`.

身份驗證是可選的。如果未設定身份驗證，則所有路由和 Studio 均可公開存取。可以使用以下方式在各個自訂路線上啟用公共訪問`requiresAuth: false`.

看[Custom API Routes](/docs/server/custom-api-routes#authentication) for controlling authentication on custom endpoints. Visit the [Studio Auth docs](/docs/studio/auth) for more on securing your Studio deployment.

:::警告
預設身份驗證配置可保護`/api/*` and treats `/api`, `/api/auth/*` as public. When you set a custom `server.apiPrefix`, those defaults no longer match and built-in routes fall outside the protected pattern. Update `server.auth.protected` and `server.auth.public` to reference your new prefix.
:::



Studio 驗證目前受以下Provider支援：Simple Auth、JWT、WorkOS、Better Auth 和 Google。

:::
