# 身分驗證

Mastra 讓你選擇身分驗證方式，使用符合現有技術堆疊的身分系統，保護 API 與 [Studio](/docs/studio/overview) 的存取。

你可以先用共用密鑰進行基本的 JWT 身分驗證，需要更進階的身分管理功能時，再改用現有的身分提供者。

## 身分驗證的保護範圍 {/* #what-auth-secures */}

設定身分驗證後，下列兩處會受到保護：

- **Studio 介面**：Studio 會顯示登入畫面，提供單一登入（SSO）、電子郵件與密碼登入，或同時提供兩種方式。如果也設定了 RBAC 提供者，Studio 會套用角色型存取控制，決定每位團隊成員可以檢視的內容和執行的操作。
- **API 路由**：無論請求來自 Studio 或直接呼叫 API，內建路由（如 `/api/agents/*`、`/api/workflows/*`）與自訂路由都需要驗證身分。少數內建路由仍可公開存取，例如 Studio 用來偵測登入狀態的 `GET /api/auth/capabilities`。

預設由 `server.auth` 設定的提供者保護這兩處。若要為 Studio 指定專用的提供者，請另外設定 `studio.auth`。之後，Studio 發出的請求（包括對 API 路由的呼叫）一律只使用 `studio.auth`，其他請求繼續使用 `server.auth`。

身分驗證可視需求設定。未設定時，所有路由與 Studio 都可公開存取。若要個別開放自訂路由，可在該路由設定 `requiresAuth: false`。

如需控制自訂端點的身分驗證，請參閱[自訂 API 路由](/docs/server/custom-api-routes#authentication)。如需保護部署後的 Studio，請參閱 [Studio 身分驗證文件](/docs/studio/auth)。

:::warning
預設驗證設定會保護 `/api/*`，並開放 `/api` 和 `/api/auth/*`。設定自訂的 `server.apiPrefix` 後，預設規則就無法比對新前綴，內建路由也會落在保護範圍之外。請更新 `server.auth.protected` 與 `server.auth.public`，改用新前綴。
:::

:::note

Studio 目前支援以下身分驗證提供者：Simple Auth、JWT、WorkOS、Better Auth 與 Google。

:::
