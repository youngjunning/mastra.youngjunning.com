# 事件發射器發布訂閱

`EventEmitterPubSub`是預設值[`PubSub`](/reference/pubsub/base)執行。它使用 Node.js 傳遞進程內事件[`EventEmitter`](https://nodejs.org/api/events.html#class-eventemitter)，因此它無需任何外部服務即可工作。

將其用於單進程應用程式。有關一台主機上跨進程的交付，請參閱[`UnixSocketPubSub`](/reference/pubsub/unix-socket-pubsub). For distributed delivery, see [`RedisStreamsPubSub`](/reference/pubsub/redis-streams) or [`GoogleCloudPubSub`](/reference/pubsub/google-cloud-pubsub).

由於它是進程內的，因此事件不會持久存在，也不會與其他進程共用。把它包起來[`CachingPubSub`](/reference/pubsub/caching-pubsub) when you need replay for resumable streams.

## 使用範例 {/* #usage-example */}

`EventEmitterPubSub`當您未配置時自動使用`pubsub` option, so most applications never construct it directly. Create one explicitly only when you want to configure or share it.

```typescript title="src/mastra/index.ts"
import { Mastra } from '@mastra/core'
import { EventEmitterPubSub } from '@mastra/core/events'

export const mastra = new Mastra({
  pubsub: new EventEmitterPubSub(),
})
```

若要與應用程式的其他部分共用發射器，請傳遞現有的`EventEmitter`:

```typescript
import EventEmitter from 'node:events'
import { EventEmitterPubSub } from '@mastra/core/events'

const emitter = new EventEmitter()
const pubsub = new EventEmitterPubSub(emitter)
```

若要顯示批次傳送錯誤，請傳遞一個記錄器：

```typescript
import { EventEmitterPubSub } from '@mastra/core/events'

const pubsub = new EventEmitterPubSub(undefined, { logger })
```

## 方法 {/* #methods */}

`EventEmitterPubSub`實施[`PubSub`](/reference/pubsub/base) contract. The methods below have behavior specific to this implementation.

### `subscribe(topic, cb, options?)` {/* #subscribetopic-cb-options */}

註冊主題的回調。沒有`options.group`, every subscriber receives every event. With a group, events are distributed round-robin across members of that group.

經過`options.batch` to opt in to batched delivery. See [Batching](#batching) below.

```typescript
await pubsub.subscribe('workflow.events', (event, ack, nack) => {
  console.log(event)
})
```

### `flush()` {/* #flush */}

等待任何待處理的重新投遞`nack` to fire before resolving.

```typescript
await pubsub.flush()
```

### `close()` {/* #close */}

刪除所有偵聽器並取消掛起的重新傳遞。在正常關閉期間呼叫此方法。

```typescript
await pubsub.close()
```

## 再次投遞 {/* #redelivery */}

當分組使用者呼叫時`nack`, the event is redelivered to the group after a short delay, and its `deliveryAttempt` count increases. Calling `ack` clears the tracking for that event. Fan-out subscribers receive no-op `ack` and `nack` functions, since each event reaches every subscriber once.

## 食材 {/* #batching */}

`EventEmitterPubSub`榮譽`options.batch` natively. When a subscriber opts in, events are held in a per-subscriber in-memory buffer and delivered as consecutive callback invocations once a flush condition is met. Both fan-out and group subscribers can batch. See [`SubscribeBatchOptions`](/reference/pubsub/base#subscribebatchoptions) for the full policy.

```typescript
await pubsub.subscribe(
  'workflow.events',
  event => {
    console.log(event)
  },
  {
    batch: {
      maxSize: 10, // flush once 10 events have queued
      maxWaitMs: 500, // ...or after 500ms, whichever comes first
    },
  },
)
```

緩衝區位於記憶體中且針對每個進程，因此批次狀態不會持續存在，並且不會在重新啟動後繼續存在。觸發的刷新`maxWaitMs` is best-effort: if a step such as a throwing `coalesce` fails, the error is surfaced through the configured `logger` rather than thrown. `flush()` drains every batched subscriber buffer before resolving.
