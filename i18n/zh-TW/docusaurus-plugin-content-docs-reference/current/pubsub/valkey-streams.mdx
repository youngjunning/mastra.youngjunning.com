# ValkeyStreamsPubSub

`ValkeyStreamsPubSub`是一個[`PubSub`](/reference/pubsub/base)和[`LeaseProvider`](/reference/pubsub/lease-provider)由 Valkey Streams 支持的實施[瓦爾基滑行](https://github.com/valkey-io/valkey-glide)。它提供持久的跨進程交付、消費者群組、重新交付、主題清理和分散式租賃。

將其用於 Valkey 部署。使用[`RedisStreamsPubSub`](/reference/pubsub/redis-streams) for Redis deployments that use the official `redis` client. Both integrations implement the same Mastra behavior, with independent tests running against Valkey and Redis.

## 安裝 {/* #installation */}

```bash npm2yarn
npm install @mastra/valkey-streams
```

## 使用範例 {/* #usage-example */}

```typescript title="src/mastra/index.ts"
import { Mastra } from '@mastra/core'
import { ValkeyStreamsPubSub } from '@mastra/valkey-streams'

export const mastra = new Mastra({
  pubsub: new ValkeyStreamsPubSub({
    url: 'valkey://localhost:6379',
  }),
})
```

## 配送行為 {/* #delivery-behavior */}

`ValkeyStreamsPubSub`支援拉式交付，但不支援數位重播偏移量。分組訂閱者透過共享消費者群組競爭事件。沒有群組的訂閱者透過私人消費者群組接收扇出交付。

使用`startFrom: "latest"` to skip retained entries when a group is first created. The default, `"earliest"`, reads retained entries first.

當訂戶呼叫時`nack`, the event is republished with an incremented `deliveryAttempt` and the original is acknowledged. Once an event reaches `maxDeliveryAttempts`, it's dropped instead of redelivered. Separately, each subscription periodically reclaims events that an earlier consumer in the group read but never acknowledged, controlled by `reclaimIntervalMs` and `reclaimIdleMs`.

訂閱永遠不會回收自己的處理程序仍在處理的事件，因此不會為相同事件呼叫兩次慢速處理程序。如果處理程序掛起，則該群組中的另一個使用者會在該事件閒置一段時間後回收該事件`reclaimIdleMs`. In a single-consumer group there's no sibling to do that, so set `inFlightTimeoutMs` to have the subscription nack the event itself after that long.

## 伺服器配置 {/* #server-configuration */}

放`maxmemory-policy` to `noeviction`. Consumer groups, unacknowledged entries, and lease keys are live state, and any evicting policy deletes them when the server reaches `maxmemory`, dropping events and leases. When `maxmemory` is set and the policy isn't `noeviction`, `ValkeyStreamsPubSub` logs a warning once after it first connects. To reclaim streams created without a TTL, follow the [Redis Streams runbook](/reference/pubsub/redis-streams#reclaim-streams-created-without-a-ttl) with `valkey-cli`.

## 清理和關閉 {/* #cleanup-and-shutdown */}

`clearTopic(topic)`刪除主題流及其消費者群組。`flush()` waits for in-flight publishes, and `close()` stops subscriptions and closes GLIDE connections.

```typescript
await pubsub.clearTopic('workflow.events.run-123')
await pubsub.flush()
await pubsub.close()
```
