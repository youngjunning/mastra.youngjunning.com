# ValkeyStreamsPubSub

`ValkeyStreamsPubSub` 是 [`PubSub`](/reference/pubsub/base) 與 [`LeaseProvider`](/reference/pubsub/lease-provider) 的實作，透過 [Valkey GLIDE](https://github.com/valkey-io/valkey-glide) 以 Valkey Streams 為基礎。它支援跨程序持久傳遞、消費者群組、重新傳遞、主題清理及分散式租約。

適用於 Valkey 部署。對於 Redis 部署，請使用 [`RedisStreamsPubSub`](/reference/pubsub/redis-streams)，適用於使用官方 `redis` 用戶端 的情況。兩種整合提供相同的 Mastra 行為，並分別針對 Valkey 與 Redis 執行獨立測試。

## 安裝 {/* #installation */}

```bash npm2yarn
npm install @mastra/valkey-streams
```

## 使用範例 {/* #usage-example */}

```typescript title="src/mastra/index.ts"
import { Mastra } from '@mastra/core'
import { ValkeyStreamsPubSub } from '@mastra/valkey-streams'

export const mastra = new Mastra({
  pubsub: new ValkeyStreamsPubSub({
    url: 'valkey://localhost:6379',
  }),
})
```

## 傳遞行為 {/* #delivery-behavior */}

`ValkeyStreamsPubSub` 支援拉取式傳遞，但不支援數值型重播位移量。同群組的訂閱者透過共用的消費者群組競爭接收事件。未指定群組的訂閱者透過各自的私有消費者群組接收扇出傳遞。

首次建立消費者群組時，使用 `startFrom: "latest"` 可略過已保留的條目。預設值 `"earliest"` 會先讀取這些條目。

訂閱者呼叫 `nack` 時，事件會以遞增的 `deliveryAttempt` 重新發布，原事件則會被確認。事件達到 `maxDeliveryAttempts` 後會被捨棄，不再重新傳遞。此外，每個訂閱都會定期回收同群組中先前消費者已讀取但未確認的事件；回收由 `reclaimIntervalMs` 與 `reclaimIdleMs` 控制。

訂閱不會回收自身處理常式仍在處理的事件，因此慢速處理常式不會因同一事件被呼叫兩次。若處理常式停滯，同群組的其他消費者可在事件閒置達到 `reclaimIdleMs` 後回收它。單一消費者群組沒有其他消費者可執行回收，可設定 `inFlightTimeoutMs`，讓訂閱在逾時後自行對事件執行 nack。

## 伺服器配置 {/* #server-configuration */}

將 `maxmemory-policy` 設為 `noeviction`。消費者群組、未確認的條目及租約鍵都是運作中的狀態；伺服器達到 `maxmemory` 時，任何允許逐出的策略都會刪除它們，導致事件與租約遺失。若已設定 `maxmemory` 且策略不是 `noeviction`，`ValkeyStreamsPubSub` 會在首次連線後記錄一次警告。若要清理未設定 TTL 的串流，請使用 `valkey-cli` 並參照 [Redis Streams 操作手冊](/reference/pubsub/redis-streams#reclaim-streams-created-without-a-ttl)。

## 清理和關閉 {/* #cleanup-and-shutdown */}

`clearTopic(topic)` 會刪除主題串流及其消費者群組。`flush()` 會等待進行中的發布完成；`close()` 會停止訂閱並關閉 GLIDE 連線。

```typescript
await pubsub.clearTopic('workflow.events.run-123')
await pubsub.flush()
await pubsub.close()
```
