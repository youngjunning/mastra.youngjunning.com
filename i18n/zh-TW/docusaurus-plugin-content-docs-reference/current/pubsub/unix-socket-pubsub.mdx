# UnixSocketPubSub

`UnixSocketPubSub` 是一種 [`PubSub`](/reference/pubsub/base) 實作，透過 Unix 網域通訊端在同一主機的多個程序間傳遞事件。它會選出一個程序擔任代理，其他程序則以用戶端身分連線。代理結束後，其餘用戶端會自動選出新代理。

多個本機程序需要共用串流時可使用它，例如在 Mastra Code 終端介面中協調跨程序的執行緒串流。單一程序內傳遞事件可使用 [`EventEmitterPubSub`](/reference/pubsub/event-emitter)；跨主機的分散式事件傳遞可使用 [`RedisStreamsPubSub`](/reference/pubsub/redis-streams) 或 [`GoogleCloudPubSub`](/reference/pubsub/google-cloud-pubsub)。

`UnixSocketPubSub` 採用推送式傳輸：事件不需要讀取迴圈就會送達，因此 Mastra 不會為它啟動拉取工作程序。

## 使用範例 {/* #usage-example */}

傳入所有參與程序共用的通訊端路徑。

```typescript title="src/mastra/index.ts"
import { Mastra } from '@mastra/core'
import { UnixSocketPubSub } from '@mastra/core/events'

export const mastra = new Mastra({
  pubsub: new UnixSocketPubSub('/tmp/mastra/events.sock'),
})
```

## 方法 {/* #methods */}

`UnixSocketPubSub` 實作了 [`PubSub`](/reference/pubsub/base) 介面。以下方法為此實作特有。

### `close()` {/* #close */}

關閉通訊端連線；若此實例是代理，也會釋放代理角色。應在正常關閉時呼叫。`close()` 最多等待一秒，讓先前已開始的租約釋放操作完成。若操作此後仍因其他程序持有鎖而受阻，就會以 `UnixSocketPubSub is closed` 錯誤遭到拒絕；在 `close()` 之後啟動的租約操作則會擲出錯誤。

```typescript
await pubsub.close()
```

## 代理選舉 {/* #broker-election */}

第一個將自身通訊端連結到共用路徑的程序會成為代理。它會在所有已連線用戶端之間轉送事件，其他程序則以用戶端身分連線。每個候選程序先以私有名稱繫結通訊端，再將其硬連結到共用路徑。如果該路徑已有通訊端，硬連結就會失敗，避免候選程序意外取代仍在運作的代理。

代理正常結束時會移除共用路徑。接著用戶端會重新連線，第一個成功將自身通訊端連結到該路徑的用戶端會成為新代理，其餘用戶端則會重新向它訂閱。

連線遭拒不會立即觸發接管。用戶端會先以退避策略重試；只有通訊端持續拒絕連線時，用戶端才會取得獨佔檔案鎖並取代該通訊端。代理只有在共用路徑仍指向自身通訊端時才會移除它。如果代理發現該路徑已被刪除或取代，就會卸任並以用戶端身分重新加入。因此，即使程序一度連到不同通訊端，最終仍會收斂至同一個代理，而不會持續分裂。
