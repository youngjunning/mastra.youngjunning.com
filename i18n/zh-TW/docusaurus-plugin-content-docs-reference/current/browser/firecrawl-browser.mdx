# FirecrawlBrowser 類別

`FirecrawlBrowser` 類別以 [Firecrawl Browser Sandbox](https://docs.firecrawl.dev/features/browser) 為基礎，提供瀏覽器自動化功能。它透過 Firecrawl API 建立遠端瀏覽器工作階段，並使用 Chrome DevTools Protocol (CDP) 連線。

`FirecrawlBrowser` 繼承 [`AgentBrowser`](/reference/browser/agent-browser)，提供相同的確定性 Tool 集。需要託管瀏覽器工作階段，而不想在本機安裝 Chromium 時，可使用此類別。本機自動化請參閱 [`AgentBrowser`](/reference/browser/agent-browser)；若要以自然語言進行 AI 驅動的互動，請參閱 [`StagehandBrowser`](/reference/browser/stagehand-browser)。

## 使用範例 {/* #usage-example */}

```typescript title="src/mastra/agents/index.ts"
import { Agent } from '@mastra/core/agent'
import { FirecrawlBrowser } from '@mastra/browser-firecrawl'

const browser = new FirecrawlBrowser({
  apiKey: process.env.FIRECRAWL_API_KEY,
  firecrawl: {
    ttl: 600,
  },
})

export const browserAgent = new Agent({
  id: 'browser-agent',
  name: 'Browser Agent',
  instructions: `You can browse the web. Use browser_snapshot to see the page structure,
then interact with elements using their refs (e.g., @e5).`,
  model: '__GATEWAY_OPENAI_MODEL__',
  browser,
})
```

## 工作階段生命週期 {/* #session-lifecycle */}

工作階段的建立方式取決於 `scope` 選項，該選項繼承自 `AgentBrowser`：

- `'thread'` （預設）：每個對話執行緒都有自己的 Firecrawl 沙箱工作階段，首次使用時建立，執行緒的瀏覽器工作階段銷毀時刪除。
- `'shared'`: 瀏覽器啟動時建立一個 Firecrawl 沙箱工作階段，供所有執行緒共用；瀏覽器關閉時刪除。

無論使用哪種設定，瀏覽器關閉時 `FirecrawlBrowser` 都會刪除遠端 Firecrawl 工作階段，即使建立工作階段或連線的過程曾中途失敗也是如此。

## Tool {/* #tools */}

`FirecrawlBrowser` 提供與 `AgentBrowser` 相同的 Tool 集，包括 `browser_goto`、`browser_snapshot`、`browser_click`、`browser_type` 與 `browser_screenshot`。完整清單及 Tool 參數請參閱 [`AgentBrowser` Tool 參考文件](/reference/browser/agent-browser)。
