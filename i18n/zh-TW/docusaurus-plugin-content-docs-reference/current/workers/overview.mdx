# 勞工

:::測試版

在 API 穩定之前，可能會在沒有重大版本更新的情況下發生重大變更。

:::

有關使用模式和部署拓撲，請參閱[Workers](/docs/deployment/workers).

## 環境變數 {/* #environment-variables */}

### `MASTRA_WORKERS` {/* #mastra_workers */}

控制哪些工作進程在目前進程中啟動。

|價值|行為 |
| - | - |
|*(not set)* | Default workers are auto-created based on configuration |
| `"false"` | Disables worker event processing. The process serves HTTP requests and can still publish events to PubSub (e.g., workflow starts) without consuming them. |
| `"orchestration"` | Only the orchestration worker starts |
| `"scheduler"`|僅調度程序工作者啟動 |
|`"backgroundTasks"`|僅後台任務worker啟動|
|`"orchestration,scheduler"`|多個工人（逗號分隔）|

使用它可以在同一建置工件的不同容器中運行不同的工作程序類型。

環境`MASTRA_WORKERS` to any value, including `"false"`, also makes `createWorkflow` build workflows that declare `schedule` on the evented engine. Set it on every process in a split deployment. See [Scheduled workflows](/docs/workflows/scheduled-workflows#execution-engine).

### `MASTRA_STEP_EXECUTION_URL` {/* #mastra_step_execution_url */}

API 伺服器的基本 URL，供編排工作人員用來遠端執行Workflow步驟。當編排工作執行緒在與 API 不同的進程中執行時需要。

```bash
MASTRA_STEP_EXECUTION_URL=http://api:4111/api
```

在生產中使用 HTTPS URL。看[Security recommendations](/docs/auth/workers#security-recommendations).

編排工作人員將步驟執行請求傳送至：

```text
${MASTRA_STEP_EXECUTION_URL}/workflows/:workflowId/runs/:runId/steps/execute
```

### `MASTRA_WORKER_AUTH_TOKEN` {/* #mastra_worker_auth_token */}

呼叫 API 的步驟執行端點時，編排工作執行緒發送的承載令牌。 API 的已設定身分驗證Provider必須識別此令牌。看[Worker authentication](/docs/auth/workers).

```bash
MASTRA_WORKER_AUTH_TOKEN=sk-worker-secret-token
```

## 工人類型 {/* #worker-types */}

### 編排工作者 {/* #orchestrationworker */}

處理來自 PubSub 的Workflow事件`workflows` topic. Requires a pull-capable PubSub like `@mastra/redis-streams` or `@mastra/google-cloud-pubsub` configured with a pull subscription.

* **姓名**: `orchestration`
* **發布訂閱主題**: `workflows`
* **消費群**: `mastra-orchestration`

### 調度工作者 {/* #schedulerworker */}

輪詢儲存以獲取到期的 cron 計劃並發布`workflow.start` event to the `workflows` topic for each fire. The orchestration worker runs default-engine workflows in-process and evented workflows step by step.

* **姓名**: `scheduler`
* **僅單一實例**：僅運行一個實例以避免重複火災

### 後台任務工作者 {/* #backgroundtaskworker */}

執行Agent分派的後台Tool呼叫。

* **姓名**: `backgroundTasks`
* **發布訂閱主題**: `background-tasks`
* **消費群**: `background-task-workers`
* **支援多個副本**：實例共享消費組

## 支援的儲存後端 {/* #supported-storage-backends */}

運行所有工作執行緒類型的部署需要一個實現以下功能的儲存後端`workflows`, `backgroundTasks`, and `schedules` domains. The `schedules` domain is specifically required by the SchedulerWorker. If you don't use scheduled workflows, backends without it can still support orchestration and background tasks. The following backends support all three:

|後端 |套餐 |
| - | - |
| PostgreSQL |[`@mastra/pg`](/integrations/databases/postgresql) |
| LibSQL | [`@mastra/libsql`](/integrations/databases/libsql) |
| MySQL | `@mastra/mysql` |
| MongoDB | [`@mastra/mongodb`](/integrations/databases/mongodb) |
| Spanner | [`@mastra/spanner`](/integrations/databases/spanner) |
| Convex | [`@mastra/convex`](/integrations/databases/convex) |

其他儲存後端（Upstash、DynamoDB、Cloudflare D1、ClickHouse、Redis）支援Workflow和一些工作人員功能，但缺少`schedules` domain. They can still be used for orchestration and background task workers if you don't deploy the scheduler.
