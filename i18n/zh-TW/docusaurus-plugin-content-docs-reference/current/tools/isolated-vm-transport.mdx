# 隔離Vm程式碼模式傳輸

這`IsolatedVmCodeModeTransport`班級跑步[編碼方式](/docs/agents/code-mode)進程內 V8 隔離中的程序，由[隔離虛擬機](https://github.com/laverdet/isolated-vm)。隔離是執行邊界，因此不需要Workspace沙箱：程式沒有檔案系統、網路、進程或模組存取權限。它唯一的能力是`external_*`函數，它回調主機上的真實Tool。

與預設值相比`StdioCodeModeTransport`, this transport spawns no processes and writes no temp files, which makes it a good fit for serverless and multi-tenant hosts where OS-level sandboxing isn't available.

## 安裝 {/* #installation */}

```bash npm2yarn
npm install @mastra/isolated-vm
```

`isolated-vm`是一個原生插件。它為常見平台提供預先建置的二進位文件，因此安裝通常不需要額外的設定。僅在沒有匹配預先建置的平台上才需要 C++ Tool鏈，在該平台上它會回退到從原始程式碼進行編譯。

在 Node.js 20 及更高版本上，建立隔離會崩潰，除非主機進程以`--no-node-snapshot`. The constructor reports the missing flag as an error. Pass it when starting the server or through `NODE_OPTIONS`:

```bash
NODE_OPTIONS=--no-node-snapshot npm run dev
```

## 用法 {/* #usage */}

將傳輸作為第二個參數傳遞給`createCodeMode()`. No `sandbox` is needed:

```typescript
import { createCodeMode } from '@mastra/core/tools'
import { IsolatedVmCodeModeTransport } from '@mastra/isolated-vm'

const { tool, instructions } = createCodeMode(
  { tools: { getTopProducts, getProductRatings } },
  new IsolatedVmCodeModeTransport({ memoryLimitMb: 128 }),
)
```

## 它是如何運作的 {/* #how-it-works */}

每次運行都會創建一個具有自己的堆的新分離株。使用 esbuild 在主機上剝離 TypeScript，然後在隔離內評估程式。每一個`external_*` call crosses the isolate boundary as JSON strings in both directions, so no host object references leak into model-authored code. The allow-list, tool validation, request context, and tracing all run on the host, the same as with other transports.

這`timeout` configured on `createCodeMode()` applies to both asynchronous hangs and synchronous infinite loops, and the isolate is disposed after every run.
