# Tool（）

傳回連接到 Mastra 平台專案的每個Provider的Tool的解析器。交給Agent`tools`選項，Mastra 在每個選項上調用它`generate()`和`stream()`。解析器快取Tool`ttlMs`並在快取過期後調用時啟動後台刷新。

```typescript title="src/mastra/agents/ops.ts"
import { Agent } from '@mastra/core/agent'
import { tools } from '@mastra/connect'

export const opsAgent = new Agent({
  id: 'ops',
  name: 'ops',
  instructions: 'You help the team track work in Linear and GitHub.',
  model: '__GATEWAY_OPENAI_MODEL_LUNA__',
  tools: tools(),
})
```

返回：`ToolsResolver`, a resolver producing a flat tool record keyed by tool key (for example `linear_create_issue`). See [The resolver](#the-resolver).

看[Connect](/docs/mastra-platform/connect#add-tools-to-an-agent) to get started.

### 每個請求選項 {/* #per-request-options */}

傳遞回調而不是選項物件來改變每個請求的選項，例如基於角色的篩選器或批准策略。回調在每個解析（同步或非同步）上運行並接收相同的上下文 Mastra 傳遞解析器（`requestContext` is populated when the resolver is an agent's `tools` option):

```typescript
const connected = tools(ctx => ({
  providers: {
    linear:
      ctx?.requestContext?.get('role') === 'viewer'
        ? { allowTools: ['linear_list_*'] }
        : { requireApproval: ['linear_delete_*'] },
  },
}))
```

解析器會記住每個不同選項值的快照，因此產生相同選項的請求與通常的選項共用快取快照`ttlMs` and stale-while-revalidate semantics. Structurally equal options returned from different calls count as the same value, except that non-serializable values such as a custom `client.fetch` compare by identity. The resolver keeps caches for at most 32 distinct options values and evicts the least recently used one past that, so derive options from a small, closed set of inputs such as roles, not from unbounded per-request data.

使用回調形式，選項驗證在生成選項值的第一個解析度運行，而不是在`tools()` time, and a validation error fails that resolution. `refresh()` fetches for the options the callback returns without a context (the same variant a direct `await connected()` call uses), and `disconnect()` closes every memoized variant.

## 解析器 {/* #the-resolver */}

返回的`ToolsResolver` caches its tools. Within `ttlMs` of the last fetch, it returns the cache. The first call after expiry still returns the cache right away and starts a background fetch from the platform (stale-while-revalidate). Later calls use the updated snapshot once the fetch succeeds, or keep using the cached snapshot if the refresh fails. Refreshes depend on calls to the resolver rather than idle polling. Use `await connected.refresh()` to wait for a fresh tool record.

`toolsets` option at generate time:

```typescript
import { tools } from '@mastra/connect'

const connected = tools()

const response = await agent.generate('Summarize my open issues.', {
  toolsets: { connect: await connected() },
})
```

解析器也公開了手動控制的方法：

* `refresh()`立即從平台獲取，然後更新快取並返回Tool記錄。如果平台獲取失敗則拒絕。
* `disconnect()`清除快取的快照並關閉此解析器後面狀態的 MCP 傳輸。使用相同選項建立的解析器共用該狀態，因此這也會斷開它們的連接。稍後的解決方案會重建狀態，並且已傳回的 MCP Tool會在下次呼叫時重新連線。
* `with(extra)`傳回一個新的解析器，它將額外的Tool合併到每個解析中，在按鍵衝突上給予額外的優先權。它接受靜態Tool記錄或函數（同步或非同步）和呼叫鏈。對於相同的合併，使用解析器結果的擴展`tools` callback, see [Add tools to an agent](/docs/mastra-platform/connect#add-tools-to-an-agent).
* `codeMode(options)`透過暴露Tool[Code Mode](#code-mode).

若要過濾Tool鍵以外的內容或選項無法表達的數據，請對Agent程式的已解析記錄進行後處理`tools` function. Create the resolver once, outside the function, so its cache is shared:

```typescript title="src/mastra/agents/ops.ts"
import { Agent } from '@mastra/core/agent'
import { tools } from '@mastra/connect'

const connectTools = tools({ providers: ['linear'] })
const viewerTools = new Set(['linear_list_issues'])

export const opsAgent = new Agent({
  id: 'ops',
  name: 'ops',
  instructions: 'You help the team track work in Linear.',
  model: '__GATEWAY_OPENAI_MODEL_LUNA__',
  tools: async ctx => {
    const all = await connectTools(ctx)

    if (ctx.requestContext?.get('role') === 'admin') {
      return all
    }
    return Object.fromEntries(Object.entries(all).filter(([key]) => viewerTools.has(key)))
  },
})
```

只有`admin` role gets every tool. Any other or missing role gets the viewer subset. Set `role` in trusted server-side code based on the authenticated user. [Vary tools by channel](/reference/connect/channels#vary-tools-by-channel) applies the same pattern to channel messages.

錯誤處理取決於原因：

* 配置錯誤（缺少項目 ID 或令牌、格式錯誤的Provider ID、兩者）`allowTools` and `disallowTools` at one level, invalid `ttlMs`) throw when you call `tools()`. With [the callback form](#per-request-options), they fail the first resolution that produces the invalid options instead.
* `invalid_options`. An unknown tool key or zero-match glob in a per-provider filter does the same. If the catalog can't be reached, an unknown ID downgrades to a warning and is skipped.
* 如果在快取快照時後台刷新失敗，解析程式將繼續為快取的Tool集提供服務並發出警告。只有當沒有快取任何內容時它才會拒絕。
* 當某個Provider出現問題（例如需要重新授權的連線）時，會記錄警告並跳過該Provider。其他Provider的Tool仍在載入。

## 代碼模式 {/* #code-mode */}

`codeMode()`[Code Mode](/docs/agents/code-mode): the agent writes one TypeScript program that calls the tools as `external_*` functions, instead of calling each tool in its own step. Use it when tasks fan out across many calls or providers, such as listing items in one provider and looking each one up in another.

```typescript title="src/mastra/agents/ops.ts"
import { Agent } from '@mastra/core/agent'
import { LocalSandbox } from '@mastra/core/workspace'
import { tools } from '@mastra/connect'

const code = tools({ providers: ['linear', 'slack'] }).codeMode({ sandbox: new LocalSandbox() })

export const opsAgent = new Agent({
  id: 'ops',
  name: 'ops',
  instructions: async ctx => ['You help the team track work.', await code.instructions(ctx)],
  model: '__GATEWAY_OPENAI_MODEL_LUNA__',
  tools: code.tools,
})
```

：：：警告

`LocalSandbox`作為主機運行模型編寫的程式`node` process with host privileges. Connected tools return third-party data, such as issue text, that can influence the code the model writes. Use `LocalSandbox` only for trusted or local development. See [how Code Mode works](/docs/agents/code-mode#how-it-works) for isolated alternatives.

:::

`codeMode()`返回兩個函數，`tools` and `instructions`. Pass both to the agent. Like the resolver, they resolve the current connections on every request. The functions the program can call change as providers are connected or disconnected. Within one request both use the same resolution, and the instructions never declare a function the program can't call.

該方法接受每個[`createCodeMode()` option](/reference/tools/create-code-mode) except `tools` (`sandbox`, `timeout`, `id`), plus `transport` for a [remote sandbox](/docs/agents/code-mode#remote-sandboxes) or [in-process isolation](/docs/agents/code-mode#in-process-isolation), and `toolSearch` for [tool search](#tool-search). Every resolver provides it, including the callback form and resolvers returned by `with()`. Extra tools from `with()` join the program's functions.

有些Tool仍然是直接AgentTool而不是程式功能，因為它們會暫停Agent運行，並且來自程式內部的呼叫不能：

* 需要通過批准的Tool`requireApproval`. The agent still waits for the user to approve each call.
* 這`request_connection` tool, so the connect prompt can still pause the run until the user connects.

為了[MCP providers](#mcp-providers), a `requireApproval` list keeps **all** of that provider's tools direct, including the ones the list doesn't name. Mastra discovers MCP tools at request time and checks the list on each call, so Code Mode has no way to know in advance which calls need approval and keeps every tool from that provider out of the program. Generated HTTP tools work differently, because only the tools that match the list stay direct.

```typescript
// Every neon-mcp tool stays direct, not just neon-mcp_run_sql
const ops = tools({
  providers: { 'neon-mcp': { requireApproval: ['neon-mcp_run_sql'] } },
}).codeMode({ sandbox })
```

若要讓程式呼叫該Provider的其他Tool，請使用下列命令刪除門控Tool`disallowTools` instead of gating them. To keep them gated, accept that the agent calls the provider's tools one at a time.

當沒有什麼可以編排的時候，例如當項目還沒有連接時，`tools` returns only the direct tools and `instructions` returns an empty string.

### Tool搜尋 {/* #tool-search */}

聲明指令中的每個函數都使用每個請求的上下文：單獨的 Linear 大約有 4,000 個令牌，而 Linear、GitHub 和 Stripe 總共有超過 20,000 個令牌。透過Tool搜索，指令只列出函數名稱，Agent會獲得`search_functions` tool that returns the TypeScript declarations for the functions it needs. The agent searches by what it wants to do or by exact names from the list, then writes the program. The program can still call every function. Only the declarations move behind the search.

當聲明每個函數需要超過約 10,000 個令牌時，Tool搜尋會自行開啟。放`toolSearch` to choose:

```typescript title="src/mastra/agents/ops.ts"
// Always list names only and search for declarations
const searching = tools().codeMode({ sandbox: new LocalSandbox(), toolSearch: true })

// Always declare every function up front
const declared = tools().codeMode({ sandbox: new LocalSandbox(), toolSearch: false })
```

## 選擇Provider {/* #choosing-providers */}

這`providers` array form is an allowlist: only listed providers are returned. Without the option, every connected provider with a supported toolset is included. A listed provider with no connection in the project yet is skipped and included automatically once a connection is attached. In the record form, `false` excludes a provider and never errors, even for IDs that match nothing.

使用陣列將發現限制為指定的Provider。記錄配置命名Provider而不排除其他Provider：

```typescript
const onlyLinear = tools({ providers: ['linear'] })
const allWithLinearApproval = tools({
  providers: { linear: { requireApproval: true } },
})
```

Tool鍵用於`allowTools` and `disallowTools` are listed per provider in the [provider toolsets reference](/reference/connect/providers).

## 連接解析度 {/* #connection-resolution */}

對於項目連結中存在的每個Provider：

1. 明確的`connectionId` option wins.
2. 否則，將自動使用單一活動連線。
3. 否則，Provider將被取消固定並在每次呼叫時進行路由：Tool集將獲得`<provider>__list_connections` tool, every other tool takes a required `connection_name` input, and the agent picks a connection per call using the display names `list_connections` returns. A `connection_name` that matches no active connection fails that call with `unknown_connection`.

合成的`list_connections` helper doesn't require approval and remains available even when top-level `allowTools` or `disallowTools` filters would exclude it.

連接於`needs_reauth` status are skipped with a warning until someone [replaces them](/reference/cli/mastra#replace-a-connection-that-needs-reauthorization).

## MCP Provider {/* #mcp-providers */}

除了產生的Tool集之外，解析器還會發現在平台目錄中宣傳 MCP 功能的任何連接的Provider。發現的Tool使用相同的平面合約，命名空間為`<provider-id>_<tool-name>`. If a provider has both a generated toolset and an MCP capability, the MCP catalog is preferred.

應用程式僅發送其平台令牌。在將每個協定請求Agent到Provider的 MCP 伺服器之前，平台會刪除呼叫者身份驗證並注入Provider憑證。 MCP 會話在刷新期間重複使用，並在連線變更、Provider分離或`disconnect()` is called.

發現的 MCP Tool遵循與產生的Tool相同的審批策略：不需要批准，除非`requireApproval` asks for it, for example `'neon-mcp': { requireApproval: ['neon-mcp_run_sql'] }`. Passing the removed `autoApproveTools` key throws an `invalid_options` error at call time.

## 環境變數 {/* #environment-variables */}

`tools()`, `channels()`, and `credential()` read these environment variables. Options passed in code take precedence.

|變數|目的|
| - | - |
|`MASTRA_PLATFORM_ACCESS_TOKEN` | Platform access token used to authenticate every request |
| `MASTRA_PLATFORM_SECRET_KEY` | Fallback token when `MASTRA_PLATFORM_ACCESS_TOKEN` is unset |
| `MASTRA_PROJECT_ID` | Project whose connections to use |
| `MASTRA_ORG_ID` | Organization ID, sent as the `x-organization-id` header when set |
| `MASTRA_PLATFORM_REGION` | `us` or `eu`. Selects `https://integrations.us.mastra.ai` or `https://integrations.eu.mastra.ai` instead of the default `https://integrations.mastra.ai` |
| `MASTRA_INTEGRATIONS_API_URL` | Connect API base URL. Overrides the region |

## 錯誤 {/* #errors */}

投擲`MastraConnectError` with a `code` property:

|程式碼|當 |
| - | - |
|`missing_project_id` | No project ID configured |
| `missing_access_token` | No platform token configured |
| `invalid_options` | Unknown or malformed provider ID, conflicting filters, duplicate or unmatched tool keys or globs, or invalid `ttlMs` |
| `unauthorized` | The platform rejected the token (401/403) |
| `proxy_error` | A proxied provider request failed, with `status` and `detail` carrying the provider response |
| `unknown_connection` | A tool call supplied a `connection_name` that matches no active connection |
| `platform_error` | Any other platform request failure |
