# Workflow 類別

`Workflow` 類別可用來建立狀態機，透過條件分支與資料驗證安排複雜的操作流程。

## 使用範例 {/* #usage-example */}

```typescript title="src/mastra/workflows/test-workflow.ts"
import { createWorkflow } from '@mastra/core/workflows'
import { z } from 'zod'

export const workflow = createWorkflow({
  id: 'test-workflow',
  inputSchema: z.object({
    value: z.string(),
  }),
  outputSchema: z.object({
    value: z.string(),
  }),
})
```

## 定義 Schema {/* #define-schemas */}

您可以使用任何支援 [Standard JSON Schema](https://standardschema.dev/json-schema) 的函式庫定義 Workflow 的 `inputSchema` 和 `outputSchema`，例如 [Zod](https://zod.dev/)、[Valibot](https://valibot.dev/) 與 [ArkType](https://arktype.io/)。

## 使用初始狀態執行 {/* #running-with-initial-state */}

啟動 Workflow 執行時，可以透過 `initialState` 設定 Workflow 狀態的初始值：

```typescript
const run = await workflow.createRun()

const result = await run.start({
  inputData: { value: 'hello' },
  initialState: {
    counter: 0,
    items: [],
  },
})
```

`initialState` 物件應符合 Workflow 的 `stateSchema` 所定義的結構。詳情請參閱 [Workflow 狀態](/docs/workflows/workflow-state)。

### 處理 tripwire 狀態 {/* #handling-tripwire-status */}

當 Workflow 中的 Agent 步驟觸發 tripwire 時，Workflow 會傳回 `status: 'tripwire'`，並附上 tripwire 詳情：

```typescript
const run = await workflow.createRun()
const result = await run.start({ inputData: { message: 'Hello' } })

if (result.status === 'tripwire') {
  console.log('Workflow terminated by tripwire:', result.tripwire?.reason)
  console.log('Processor ID:', result.tripwire?.processorId)
  console.log('Retry requested:', result.tripwire?.retry)
}
```

這與表示非預期錯誤的 `status: 'failed'` 不同。tripwire 狀態表示處理器刻意停止執行，例如進行內容審核時。
