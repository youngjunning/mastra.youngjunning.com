# Run.startAsync()

`.startAsync()` 啟動 Workflow 執行，無須等待完成。它會立即回傳 `runId`，讓 Workflow 在背景繼續執行。適用於耗時較長的 Workflow 或排程工作，也能避免呼叫端一直等待執行結束。

## 使用範例 {/* #usage-example */}

```typescript
const run = await workflow.createRun()

// Fire-and-forget - returns immediately
const { runId } = await run.startAsync({
  inputData: {
    value: 'initial data',
  },
})

// Optionally poll for completion later
const state = await workflow.getWorkflowRunById(runId)
```

## 何時使用 `startAsync()` {/* #when-to-use-startasync */}

在以下情況使用 `startAsync()`，而非 `start()`：

- **耗時較長的 Workflow**：執行可能需要幾分鐘或幾小時。
- **排程或 cron 觸發**：觸發 Workflow 時不阻塞排程器。
- **避免輪詢失敗**：對於 Inngest Workflow，`start()` 會輪詢執行結果；輪詢可能失敗並導致重試。`startAsync()` 可避免此問題。
- **背景處理**：將工作排入佇列，以非同步方式處理結果。

## 檢查 Workflow 狀態 {/* #checking-workflow-status */}

呼叫 `startAsync()` 後，可使用 `workflow.getWorkflowRunById()` 檢查執行狀態。它會回傳包含 `status`、`steps`、`result` 與 `error` 的執行狀態；若找不到該次執行，則回傳 `null`。

若未設定[儲存空間](/docs/storage)，或執行尚未持久化，該方法會回傳記憶體中的狀態：`isFromInMemory: true`、空的 `steps`，且沒有 `result` 或 `error`。若要在執行結束後讀取結果，請設定儲存空間。

```typescript
const state = await workflow.getWorkflowRunById(runId)

if (!state) {
  console.log('Workflow run not found')
} else if (state.status === 'success') {
  console.log('Workflow completed:', state.result)
} else if (state.status === 'failed') {
  console.log('Workflow failed:', state.error)
} else {
  console.log('Workflow status:', state.status)
}
```
