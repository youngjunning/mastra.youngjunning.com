# Run.startAsync()

這`.startAsync()`方法啟動Workflow運行而不等待完成。它立即返回`runId`，允許Workflow在背景執行。這對於長時間運行的Workflow或規劃任務非常有用。它還避免了Workflow完成時的阻塞。

## 使用範例 {/* #usage-example */}

```typescript
const run = await workflow.createRun()

// Fire-and-forget - returns immediately
const { runId } = await run.startAsync({
  inputData: {
    value: 'initial data',
  },
})

// Optionally poll for completion later
const state = await workflow.getWorkflowRunById(runId)
```

## 何時使用`startAsync()` {/* #when-to-use-startasync */}

使用`startAsync()` instead of `start()` when:

* **長時間運行的Workflow**：Workflow可能需要幾分鐘或幾小時才能完成
* **計劃/cron 觸發器**：您想要觸發Workflow而不阻塞排程程序
* **避免輪詢失敗**：透過 Ingest Workflow，`start()` polls for completion which can fail and cause retries. `startAsync()` avoids this issue
* **後台處理**：您想要對工作進行排隊並非同步處理結果

## 檢查Workflow狀態 {/* #checking-workflow-status */}

打電話後`startAsync()`, check the workflow status with `workflow.getWorkflowRunById()`. It returns the run state, including `status`, `steps`, `result`, and `error`, or `null` if the run isn't found.

未配置[storage](/docs/storage), or before the run is persisted, the method returns an in-memory state with `isFromInMemory: true`, empty `steps`, and no `result` or `error`. Configure storage to read a run's result after it finishes.

```typescript
const state = await workflow.getWorkflowRunById(runId)

if (!state) {
  console.log('Workflow run not found')
} else if (state.status === 'success') {
  console.log('Workflow completed:', state.result)
} else if (state.status === 'failed') {
  console.log('Workflow failed:', state.error)
} else {
  console.log('Workflow status:', state.status)
}
```
