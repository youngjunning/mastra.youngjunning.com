# Run.cancel()

`.cancel()` 會取消一次 Workflow 執行，停止執行並清理資源。

此方法會中止正在執行的步驟，並將 Workflow 狀態更新為 'canceled'。正在執行及暫停或等待中的 Workflow 都可取消。

使用預設引擎和事件驅動引擎時，巢狀 Workflow 執行會隨父執行一同取消，包括已暫停的執行。對已取消的執行再次呼叫 `cancel()`，仍會取消其中尚處於暫停狀態的巢狀執行。

## 使用範例 {/* #usage-example */}

```typescript
const run = await workflow.createRun()

await run.cancel()
```

## 取消流程 {/* #how-cancellation-works */}

呼叫後，Workflow 會：

1. **觸發中止訊號** — 使用標準 Web API AbortSignal 通知正在執行的步驟。
1. **阻止後續步驟** — 後續步驟不會執行。

## 中止訊號行為 {/* #abort-signal-behavior */}

檢查 `abortSignal` 參數的步驟可以回應取消要求：

- 步驟可以監聽 'abort' 事件：`abortSignal.addEventListener('abort', callback)`
- 步驟可以檢查是否已中止：`if (abortSignal.aborted) { ... }`
- 可用於取消計時器、網路請求或長時間執行的操作

若要在步驟執行途中取消，步驟必須主動檢查中止訊號；否則，目前步驟會執行完畢，但後續步驟不會執行。

## 擴充使用範例 {/* #extended-usage-examples */}

### 發生錯誤時取消 Workflow {/* #cancelling-a-workflow-on-error */}

```typescript
const run = await workflow.createRun()

try {
  const result = await run.start({ inputData: { value: 'initial data' } })
} catch (error) {
  await run.cancel()
}
```

### 建立回應取消的步驟 {/* #creating-a-step-that-responds-to-cancellation */}

```typescript
const step = createStep({
  id: 'long-running-step',
  execute: async ({ inputData, abortSignal, abort }) => {
    const timeout = new Promise(resolve => {
      const timer = setTimeout(() => resolve('done'), 10000)

      // Clean up if canceled
      abortSignal.addEventListener('abort', () => {
        clearTimeout(timer)
        resolve('canceled')
      })
    })

    const result = await timeout

    // Check if aborted after async operation
    if (abortSignal.aborted) {
      return abort() // Stop execution
    }

    return { result }
  },
})
```
