# 運行.取消()

這`.cancel()`方法取消Workflow運行，停止執行並清理資源。

此方法會中止任何正在執行的步驟並將Workflow狀態更新為「已取消」。它適用於主動運行的Workflow和暫停/等待的Workflow。

在預設引擎和事件引擎上，巢狀Workflow運行將與其父級一起取消，包括暫停的Workflow運行。呼喚`cancel()` on a run that's already canceled cancels any of its nested runs that are still suspended.

## 使用範例 {/* #usage-example */}

```typescript
const run = await workflow.createRun()

await run.cancel()
```

## 取消如何運作 {/* #how-cancellation-works */}

呼叫時，Workflow將：

1. **觸發中止訊號**- 使用標準Web API AbortSignal來通知執行步驟
2. **防止後續步驟**- 不會執行進一步的步驟

## 中止訊號行為 {/* #abort-signal-behavior */}

檢查的步驟`abortSignal` parameter can respond to cancellation:

* 可以監聽'abort'事件的步驟：`abortSignal.addEventListener('abort', callback)`
* 步驟可以檢查是否已經中止：`if (abortSignal.aborted) { ... }`
* 對於取消逾時、網路請求或長時間運行的操作很有用

步驟在執行過程中必須主動檢查要取消的中止訊號；否則，當前步驟將運行至完成，且後續步驟不會執行。

## 擴充使用範例 {/* #extended-usage-examples */}

### 出錯時取消Workflow {/* #cancelling-a-workflow-on-error */}

```typescript
const run = await workflow.createRun()

try {
  const result = await run.start({ inputData: { value: 'initial data' } })
} catch (error) {
  await run.cancel()
}
```

### 建立回應取消的步驟 {/* #creating-a-step-that-responds-to-cancellation */}

```typescript
const step = createStep({
  id: 'long-running-step',
  execute: async ({ inputData, abortSignal, abort }) => {
    const timeout = new Promise(resolve => {
      const timer = setTimeout(() => resolve('done'), 10000)

      // Clean up if canceled
      abortSignal.addEventListener('abort', () => {
        clearTimeout(timer)
        resolve('canceled')
      })
    })

    const result = await timeout

    // Check if aborted after async operation
    if (abortSignal.aborted) {
      return abort() // Stop execution
    }

    return { result }
  },
})
```
