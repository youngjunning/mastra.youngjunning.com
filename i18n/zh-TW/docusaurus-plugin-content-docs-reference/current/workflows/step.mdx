# Step 類別

Step 類別定義 Workflow 中的個別工作單元，封裝執行邏輯、資料驗證，以及輸入和輸出處理。
也可以傳入 Tool、Agent 或已設定的分類器，自動由其建立步驟。

## 使用範例 {/* #usage-example */}

```typescript title="src/mastra/workflows/test-workflow.ts"
import { createWorkflow, createStep } from '@mastra/core/workflows'
import { z } from 'zod'

const step1 = createStep({
  id: 'step-1',
  description: 'passes value from input to output',
  inputSchema: z.object({
    value: z.number(),
  }),
  outputSchema: z.object({
    value: z.number(),
  }),
  execute: async ({ inputData }) => {
    const { value } = inputData
    return {
      value,
    }
  },
})
```

## 從 Agent 建立步驟 {/* #creating-steps-from-agents */}

您可以直接從 Agent 建立步驟。此步驟會以 Agent 的名稱作為 ID。

### 基本 Agent 步驟 {/* #basic-agent-step */}

```typescript title="src/mastra/workflows/test-workflow.ts"
import { testAgent } from '../agents/test-agent'
import { createStep } from '@mastra/core/workflows'

const agentStep = createStep(testAgent)
// inputSchema: { prompt: string }
// outputSchema: { text: string }
```

### 具有結構化輸出的 Agent 步驟 {/* #agent-step-with-structured-output */}

傳入 `structuredOutput`，讓 Agent 傳回具型別的結構化資料：

```typescript title="src/mastra/workflows/test-workflow.ts"
import { createStep } from '@mastra/core/workflows'
import { z } from 'zod'

const articleSchema = z.object({
  title: z.string(),
  summary: z.string(),
  tags: z.array(z.string()),
})

const agentStep = createStep(testAgent, {
  structuredOutput: { schema: articleSchema },
})
// inputSchema: { prompt: string }
// outputSchema: { title: string, summary: string, tags: string[] }
```

## 從分類器建立步驟 {/* #creating-steps-from-classifiers */}

將建構時已設定問題的 [`Classifier`](/reference/classifier/classifier) 傳入 `createStep()`。預設情況下，分類器會評估完整的 `inputData`。使用 `state` 可從步驟脈絡中選取 JSON 值。

```typescript title="src/mastra/workflows/ticket-triage.ts"
import { Classifier } from '@mastra/core/classifier'
import { typeSafeAi } from '@ai-sdk/typesafe-ai'
import { createStep } from '@mastra/core/workflows'

const router = new Classifier({
  id: 'ticket-router',
  model: typeSafeAi.decisionModel('__AI_SDK_TYPESAFE_DECISION_MODEL__'),
  questions: {
    route: {
      type: 'choice',
      criteria: {
        billing: 'Billing, invoices, and payments',
        support: 'Account access and product help',
        other: 'Anything else',
      },
    },
    urgent: { type: 'boolean' },
  },
})

const classifyTicket = createStep(router, {
  maxRetries: 2,
  retries: 1,
})
```

此步驟的型別化輸出可安全表示為 JSON：

* `answers.route.choice` 是選取選項的字面值。
* `answers.urgent.probability` 是布林答案為 `true` 的機率，而非經過閾值判定的布林值。
* 選擇題和評分題的答案可能包含分布資訊。
* 決策模型拒絕回答的問題表示為 `{ type: 'refusal' }`，不含 `choice`、`score` 或 `probability`。
* `usage` 包含正規化後的 token 使用量。

`maxRetries` 控制分類器模型呼叫的重試次數。`retries` 控制 Workflow 步驟的重試次數。Workflow 輸出不包含分類器警告、回應中繼資料或原始 Provider 資料。

建構時未設定問題的分類器無法作為 Workflow 步驟。此步驟會評估完整輸入；若 Workflow 需要選取輸入資料或調整其結構，請在前面加入 `.map()`。

## 評分步驟輸出 {/* #scoring-step-output */}

在步驟設定 `scorers`，即可於該步驟執行時自動評估其輸出，而不只是評估 Workflow 的最終答案。這適用於多步驟 Workflow 和 RAG Workflow：例如，可查看檢索步驟在後續步驟推理前是否傳回相關片段，找出品質下降的步驟。

每個評分器都會收到該步驟自身的 `input` 和 `output`。步驟成功後，評分以非同步方式執行，結果會儲存在該步驟的 Trace 中。使用 `sampling` 控制評分器的執行頻率。

以下範例將評分器設定於檢索步驟，讓每次執行都接受評分：

```typescript title="src/mastra/workflows/rag-workflow.ts"
import { createStep } from '@mastra/core/workflows'
import { z } from 'zod'
import { retrievalRelevanceScorer } from '../scorers/retrieval-relevance'

const retrievalStep = createStep({
  id: 'retrieval',
  inputSchema: z.object({ query: z.string() }),
  outputSchema: z.object({ query: z.string(), chunks: z.array(z.string()) }),
  scorers: {
    retrievalRelevance: {
      scorer: retrievalRelevanceScorer(),
      sampling: { type: 'ratio', rate: 1 },
    },
  },
  execute: async ({ inputData }) => {
    const chunks = await retrieve(inputData.query)
    return { query: inputData.query, chunks }
  },
})
```

為每個要評估的步驟設定評分器，即可在多步驟 Workflow 中取得各步驟的分數。評分範圍限定於單一步驟，因此不需要專門的跨步驟指標，也能看出品質在哪個步驟改變。

透過 [`Workflow.agent()`](/reference/workflows/workflow-methods/agent) 和 [`Workflow.tool()`](/reference/workflows/workflow-methods/tool) 加入的 Agent 與 Tool 步驟，也可在步驟選項中使用相同的 `scorers` 選項。

:::note
請參閱[評分器總覽](/docs/evals/overview)，瞭解即時評估如何執行及結果的儲存位置；參閱[自訂評分器](/docs/evals/custom-scorers)，瞭解如何自行建立評分器。
:::
