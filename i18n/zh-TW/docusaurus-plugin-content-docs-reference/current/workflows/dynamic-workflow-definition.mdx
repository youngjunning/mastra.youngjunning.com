# 動態Workflow定義

:::測試版

在 API 穩定之前，可能會在沒有重大版本更新的情況下發生重大變更。

:::

動態Workflow定義是與 JSON 相容的`DynamicWorkflowGraph` accepted by [`Mastra.addDynamicWorkflow()`](/reference/core/addDynamicWorkflow), the stored-workflow server routes, and the Client SDK workflows API.

看[Dynamic workflows](/docs/workflows/dynamic-workflows) for a complete setup and usage example.

## 定義欄位 {/* #definition-fields */}

|領域 |類型 |必填|說明 |
| - | - | - | - |
|`id` | `string` | Yes | Unique workflow ID. This is also the ID used to retrieve and run the workflow. |
| `description` | `string`|沒有 |人類可讀的描述 |
|`inputSchema` | `JsonSchema`|是的 |Workflow輸入的 JSON 架構 |
|`outputSchema` | `JsonSchema`|是的 |Workflow輸出的 JSON 架構 |
|`stateSchema` | `JsonSchema`|沒有 |共享Workflow狀態的 JSON 模式 |
|`requestContextSchema` | `JsonSchema`|沒有 |從請求上下文讀取值的 JSON 架構 |
|`metadata` | `Record<string, unknown>`|沒有 |透過儲存保存任意 JSON 元資料 |
|`graph` | `SerializedStepFlowEntry[]`|是的 |組成Workflow的步驟條目 |

模式使用 JSON Schema 而不是 Zod，因此定義可以透過 JSON 往返。 Mastra 在註冊Workflow時將每個模式轉換為 Zod。

```json
{
  "id": "greeting-workflow",
  "description": "Returns a greeting for the supplied name",
  "inputSchema": {
    "type": "object",
    "properties": { "name": { "type": "string" } },
    "required": ["name"]
  },
  "outputSchema": {
    "type": "object",
    "properties": { "message": { "type": "string" } },
    "required": ["message"]
  },
  "graph": [
    {
      "type": "mapping",
      "id": "create-greeting",
      "mapConfig": "{\"message\":{\"template\":\"Hello, ${initData.name}!\"}}"
    }
  ]
}
```

## 圖表條目 {/* #graph-entries */}

條目在`graph` run in order. Each entry receives the previous entry's output, and the first entry receives the workflow input.

|條目類型 |說明 |
| - | - |
|`agent` | Invoke a registered agent |
| `classifier` | Evaluate data with a registered classifier |
| `tool` | Invoke a registered tool |
| `mapping` | Reshape data between steps |
| `workflow` | Invoke a registered workflow as a nested step |
| `parallel` | Run several steps concurrently and merge their outputs |
| `conditional` | Run every branch whose predicate is true, concurrently |
| `foreach` | Run one step per item of an array input |
| `loop` | Repeat a step while or until a predicate holds |
| `sleep` | Pause for a fixed duration |
| `sleepUntil` | Pause until a fixed date |

使用程式碼定義的Workflow[`.agent()`](/reference/workflows/workflow-methods/agent), [`.classifier()`](/reference/workflows/workflow-methods/classifier), and [`.tool()`](/reference/workflows/workflow-methods/tool) produce the same declarative entries when serialized.

### 身份和顯示字段 {/* #identity-and-display-fields */}

控制流程條目接受可選欄位來標識和描述條目而不影響執行：

|領域 |類型 |描述 |
| - | - | - |
|`id` | `string` | Stable identity for addressing the entry across edits and serialization. Optional on `parallel`, `conditional`, `foreach`, and `loop`; required on `mapping`, `sleep`, and `sleepUntil`. |
| `description` | `string` | Human-readable intent of the control-flow operation |
| `metadata` | `Record<string, unknown>` | Arbitrary JSON metadata preserved through storage, for example a display title for visual editors |

```json
{
  "type": "parallel",
  "id": "independent-enrichment",
  "description": "Run independent document enrichment tasks concurrently",
  "metadata": { "title": "Independent enrichment" },
  "steps": [
    { "type": "tool", "id": "extract-entities", "toolId": "entity-tool" },
    { "type": "tool", "id": "classify", "toolId": "classify-tool" }
  ]
}
```

所有三個場都可以在儲存和再水化中倖存下來，並且它們出現在`serializedStepGraph` for API and Studio consumers. Agent and tool steps carry the equivalent information on their own `description` and `options.metadata` fields.

### Agent步驟 {/* #agent-steps */}

一個`agent` entry invokes a registered agent by ID. Agent steps accept `{ prompt: string }` as input and return `{ text: string }` by default.

```json
{
  "type": "agent",
  "id": "summarize",
  "agentId": "support-agent"
}
```

這`id` identifies this call site within the workflow. Later steps address the result as `stepResults.summarize`, regardless of the agent's own ID.

添加一個`outputSchema` to request structured output from the agent:

```json
{
  "type": "agent",
  "id": "extract-subtopics",
  "agentId": "support-agent",
  "outputSchema": {
    "type": "array",
    "items": {
      "type": "object",
      "properties": { "title": { "type": "string" } },
      "required": ["title"]
    }
  }
}
```

使用一個`mapping` entry before an agent to build its `{ prompt }` input from workflow data.

Agent條目接受`options` object:

```json
{
  "type": "agent",
  "id": "summarize",
  "agentId": "support-agent",
  "options": { "retries": 2, "metadata": { "team": "support" } }
}
```

步驟描述來自註冊Agent。一個`description` set on the agent entry is ignored when the workflow is rehydrated.

僅有的`retries` and `metadata` persist. Function-valued options such as `onFinish` and function-valued `toolChoice` are rejected when a code-defined workflow is stored. Other agent call options don't persist.

### 分類器步驟 {/* #classifier-steps */}

一個`classifier` entry evaluates workflow data with a classifier registered on the `Mastra` instance. The classifier must have constructor-configured questions.

```json
{
  "type": "classifier",
  "id": "classify-ticket",
  "classifierId": "ticket-router",
  "options": {
    "maxRetries": 2,
    "retries": 1,
    "metadata": { "team": "support" }
  }
}
```

分類器評估完整的條目輸入。添加前面的`mapping` entry when the classifier needs a selected or reshaped input.

分類器輸出有兩條穩定路徑：

* `answers.<question>`包含鍵入的答案。其路線`choice`, `score`, or `probability` field according to the question type. Choice and score answers may include distributions. A refused question is `{ "type": "refusal" }` with no `choice`, `score`, or `probability`, so it matches no condition on those fields. Compare `answers.<question>.type` with `"refusal"` to route refusals explicitly.
* `usage`包含規範化的令牌使用情況。

使用現有的`conditional` entry to route on classifier output. For example, a following condition can compare `{ "path": "stepResults.classify-ticket.answers.route.choice" }` with `{ "literal": "billing" }`.

這`options` object can contain classifier model-call `maxRetries`, JSON-safe `providerOptions`, workflow step `retries`, and `metadata`. Classifier errors fail the workflow step.

### Tool步驟 {/* #tool-steps */}

一個`tool` entry invokes a tool by its registration key from the `Mastra` `tools` object. Mastra resolves the tool's input and output schemas from the registry when it registers the workflow.

```json
{
  "type": "tool",
  "id": "lookup",
  "toolId": "lookup-customer"
}
```

Tool條目接受相同的可選`description` and `options` fields as agent entries. Only `retries` and `metadata` persist.

### 繪圖步驟 {/* #mapping-steps */}

一個`mapping` entry reshapes data. Its `mapConfig` is a JSON string that encodes an object. Each key becomes a key in the step output, and each descriptor defines one source.

當你打電話時[`Mastra.addDynamicWorkflow()`](/reference/core/addDynamicWorkflow) directly, `mapConfig` also accepts the object itself. Mastra encodes it to a JSON string before registering and storing the definition, so the persisted row is the same either way. A stored definition always carries the JSON string form.

|描述符|描述 |
| - | - |
|`{ "value": ... }` | A constant JSON value |
| `{ "template": "..." }` | A string built from `${...}` placeholders |
| `{ "initData": true, "path": "a.b" }` | A value from the workflow input |
| `{ "step": "step-id", "path": "a.b" }` | A value from a preceding step's output |
| `{ "requestContextPath": "a.b" }` | A value from the request context |

這`step` source also accepts an array of step IDs:

```json
{ "step": ["escalate", "auto-reply"], "path": "text" }
```

第一個列出的具有非空結果的步驟提供該值。這可以選擇在 a 之後運行的分支`conditional` entry.

模板解析佔位符`initData`, `inputData`, `state`, `requestContext`, and `stepResults.<step-id>`:

```json
{
  "type": "mapping",
  "id": "build-prompt",
  "mapConfig": "{\"prompt\":{\"template\":\"Summarize this request: ${initData.request}\"}}"
}
```

由模板解析的物件和陣列被字串化為 JSON。一個`null` value inside a present result renders as an empty string. A template that references a step without a successful output fails the run.

映射條目必須是頂級圖形條目。它們不能放置在裡面`parallel`, `conditional`, `foreach`, or `loop` containers.

### 嵌套Workflow步驟 {/* #nested-workflow-steps */}

一個`workflow` entry invokes another registered workflow. The target can be code-defined or stored.

```json
{
  "type": "workflow",
  "id": "lookup-first",
  "workflowId": "lookup-customer-workflow"
}
```

這`id` identifies the call site. The same nested workflow can appear several times under different call-site IDs, and later steps address each result as `stepResults.<id>`. A `workflow` entry also accepts an optional `description`.

### 平行條目 {/* #parallel-entries */}

一個`parallel` entry runs several single steps concurrently and merges their outputs into an object keyed by step ID.

```json
{
  "type": "parallel",
  "steps": [
    { "type": "tool", "id": "first", "toolId": "lookup-customer" },
    { "type": "tool", "id": "second", "toolId": "lookup-customer" }
  ]
}
```

每個孩子必須是一個`agent`, `classifier`, `tool`, or `workflow` entry. All children receive the parallel entry's input directly.

### 有條件條目 {/* #conditional-entries */}

一個`conditional` entry pairs each step with a declarative predicate and runs every branch whose predicate is true.

```json
{
  "type": "conditional",
  "steps": [
    { "type": "agent", "id": "escalate", "agentId": "support-agent" },
    { "type": "agent", "id": "auto-reply", "agentId": "support-agent" }
  ],
  "predicates": [
    { "op": "eq", "left": { "path": "inputData.priority" }, "right": { "literal": "urgent" } },
    { "op": "ne", "left": { "path": "inputData.priority" }, "right": { "literal": "urgent" } }
  ]
}
```

每個孩子必須是一個`agent`, `classifier`, `tool`, or `workflow` entry, and each child needs a predicate. All children receive the conditional entry's input directly.

### 謂詞 {/* #predicates */}

條件條目和迴圈使用 JSON 謂詞 DSL。操作數是`{ "path": "..." }` references or `{ "literal": ... }` values. Paths resolve against `initData`, `inputData`, `stepResults`, and `state`.

|操作員|形狀|
| - | - |
|`eq`, `ne`, `lt`, `lte`, `gt`, `gte` | `{ "op": "eq", "left": ..., "right": ... }` |
| `in`, `notIn` | `{ "op": "in", "value": ..., "set": [...] }` |
| `exists`, `notExists` | `{ "op": "exists", "path": "..." }` |
| `truthy`, `falsy` | `{ "op": "truthy", "value": ... }` |
| `and`, `or` | `{ "op": "and", "args": [...] }` |
| `not` | `{ "op": "not", "arg": ... }` |

丟失的路徑不會拋出。基於路徑的運算子返回`false` when the path can't be resolved. Use `exists` or `notExists` to distinguish a missing value from a falsy value.

### Foreach 條目 {/* #foreach-entries */}

一個`foreach` entry runs its body once for each item in an array input. The preceding entry must produce a raw array. Results preserve input order, and concurrency defaults to `1`.

```json
{
  "type": "foreach",
  "step": { "type": "workflow", "id": "write-blurb", "workflowId": "blurb-workflow" },
  "opts": { "concurrency": 3 }
}
```

身體可以是一個`agent`, `tool`, or `workflow` entry, but not a `mapping` entry.

### 循環條目 {/* #loop-entries */}

一個`loop` repeats one step while (`dowhile`) or until (`dountil`) a predicate holds.

```json
{
  "type": "loop",
  "loopType": "dountil",
  "step": { "type": "tool", "id": "poll", "toolId": "check-status" },
  "predicate": {
    "op": "eq",
    "left": { "path": "inputData.status" },
    "right": { "literal": "done" }
  }
}
```

循環體必須是單步，並且儲存循環需要聲明性謂詞。

### 睡眠條目 {/* #sleep-entries */}

一個`sleep` entry pauses for a fixed number of milliseconds. A `sleepUntil` entry pauses until a fixed date represented by an ISO date string. Stored definitions require literal values.

```json
{ "type": "sleep", "id": "wait", "duration": 5000 }
```

```json
{ "type": "sleepUntil", "id": "wait-for-launch", "date": "2027-01-01T00:00:00.000Z" }
```

當必須在執行時間計算持續時間或日期時，請使用程式碼定義的Workflow。

## 驗證 {/* #validation */}

Mastra 在保留或註冊定義之前驗證定義：

* 結構：條目形狀和必填字段，包括放置規則，例如僅頂級映射。
* 參考文獻：各`agentId` and `workflowId` must resolve against the live registries or the same bundle. A `toolId` must match a tool registration key.
* 模式流：每個條目的輸入必須與前面的輸出相容，包括推斷的映射輸出。

驗證錯誤包括虛線路徑，例如`graph.2.steps.0`, that identifies the invalid entry.
