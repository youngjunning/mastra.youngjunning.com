# Express 轉接器

`@mastra/express` 套件提供伺服器轉接器，讓 Mastra 能搭配 [Express](https://expressjs.com) 執行。關於建構函式選項、初始化流程等通用概念，請參閱[伺服器轉接器](/docs/server/server-adapters)。

## 安裝 {/* #installation */}

安裝 Express 轉接器和 Express 框架：

```bash npm2yarn
npm install @mastra/express@latest express
```

## 使用範例 {/* #usage-example */}

```typescript title="server.ts"
import express from 'express'
import { MastraServer } from '@mastra/express'
import { mastra } from './mastra'

const app = express()
app.use(express.json()) // Required for body parsing

const server = new MastraServer({ app, mastra })
await server.init()

app.listen(4111, () => {
  console.log('Server running on port 4111')
})
```

Express 需要 `express.json()` 中介軟體來解析 JSON 請求主體。請在建立 `MastraServer` 前加入此中介軟體。`init()` 不會啟動 Mastra 的背景工作程序。若要執行[排程 Workflow](/docs/workflows/scheduled-workflows)、Agent 排程或事件監聽器，請在伺服器開始監聽後呼叫 `await mastra.startWorkers()`。請參閱[啟動背景工作程序](/docs/server/server-adapters#start-background-workers)。

## 與 Hono 的差異 {/* #differences-from-hono */}

| 項目 | Express | Hono |
| - | - | - |
| 請求主體解析 | 需要 `express.json()` | 由框架處理 |
| 上下文儲存 | `res.locals` | `c.get()` / `c.set()` |
| 中介軟體簽章 | `(req, res, next)` | `(c, next)` |
| 串流處理 | `res.write()` / `res.end()` | `stream()` 輔助函式 |
| AbortSignal | 根據 `res.on('close')` 建立，只有回應尚未完成時才會中止 | `c.req.raw.signal` |

## 新增自訂路由 {/* #adding-custom-routes */}

直接在 Express 應用程式中新增路由：

```typescript title="server.ts"
const app = express()
app.use(express.json())

const server = new MastraServer({ app, mastra })

// Before init - runs before Mastra middleware
app.get('/early-health', (req, res) => res.json({ status: 'ok' }))

await server.init()

// After init - has access to Mastra context
app.get('/custom', (req, res) => {
  const mastraInstance = res.locals.mastra
  res.json({ agents: Object.keys(mastraInstance.listAgents()) })
})

app.listen(4111)
```

:::tip

在 `init()` 前新增的路由無法存取 Mastra 上下文。若要存取 Mastra 實例與請求上下文，請在 `init()` 後新增路由。

:::

若需要由 Mastra 管理的身分驗證，以及 `requiresAuth` 等路由中繼資料，請優先使用 [`registerApiRoute()`](/reference/server/register-api-route)。對於直接掛載在 `app` 上的原生 Express 路由，請使用 `createAuthMiddleware()`：

```typescript title="server.ts"
import express from 'express'
import { createAuthMiddleware, MastraServer } from '@mastra/express'
import { mastra } from './mastra'

const app = express()
app.use(express.json())

const server = new MastraServer({ app, mastra })
await server.init()

app.get('/custom/protected', createAuthMiddleware({ mastra }), (req, res) => {
  const user = res.locals.requestContext?.get('mastra__user')
  if (!user) {
    return res.status(401).json({ error: 'Unauthorized' })
  }
  res.json({ user })
})

app.get('/custom/public', createAuthMiddleware({ mastra, requiresAuth: false }), (req, res) => {
  res.json({ ok: true })
})
```

當 Mastra 伺服器未設定 `auth`，或路由符合公開路徑模式時，`createAuthMiddleware()` 會略過身分驗證並呼叫下一個處理函式。公開路徑模式包含內建預設值（`/api` 和 `/api/auth/*`），以及你設定的任何 `auth.public` 模式。此時不會設定 `mastra__user`，因此受保護的處理函式應如上例所示，拒絕缺少該值的請求。

## 存取上下文 {/* #accessing-context */}

在 Express 中介軟體和路由中，透過 `res.locals` 存取 Mastra 上下文：

```typescript
app.get('/custom', (req, res) => {
  const mastra = res.locals.mastra
  const requestContext = res.locals.requestContext
  const abortSignal = res.locals.abortSignal

  const agent = mastra.getAgent('myAgent')
  res.json({ agent: agent.name })
})
```

`res.locals` 提供下列屬性：

| 鍵 | 說明 |
| - | - |
| `mastra` | Mastra 實例 |
| `requestContext` | 請求上下文對應表 |
| `abortSignal` | 請求取消訊號 |
| `registeredTools` | 已向轉接器註冊的 Tool |
| `taskStore` | A2A 作業的任務儲存區 |
| `customRouteAuthConfig` | 各路由的身分驗證覆寫設定 |

設定身分驗證後，可透過 `res.locals.requestContext.get('mastra__user')` 讀取通過驗證的使用者。用戶端無法透過 `requestContext` 查詢參數或請求主體設定保留鍵 `mastra__user`。在原生 Express 路由上，只有執行 [`createAuthMiddleware()`](#adding-custom-routes) 後才會填入此值，因此務必先套用該中介軟體，再信任使用者資訊。請勿依賴舊有的 `user` 鍵進行授權；在沒有身分驗證中介軟體的路由上，用戶端可以自行提供該值。

## 新增中介軟體 {/* #adding-middleware */}

若要讓 Express 中介軟體處理每個請求，請在 `init()` 前加入。此時尚無法存取 Mastra 上下文：

```typescript title="server.ts"
const app = express()
app.use(express.json())

// Runs on every request, before Mastra context exists
app.use((req, res, next) => {
  console.log(`${req.method} ${req.url}`)
  next()
})

const server = new MastraServer({ app, mastra })
await server.init()
```

在 `init()` 後加入的中介軟體不會在 Mastra 路由上執行。Express 會依註冊順序分派處理函式，因此在這些路由之後註冊的中介軟體，只會套用到稍後新增的路由。

此轉接器無法執行 [`server.middleware`](/docs/server/middleware) 處理函式，因為它們使用 Hono 的函式簽章。設定該選項時，轉接器會記錄警告。若需要在 Mastra 的上下文初始化步驟與路由之間執行 Express 中介軟體，請使用下方的手動初始化流程。

## 手動初始化 {/* #manual-initialization */}

若要自訂中介軟體的順序，請分別呼叫各個方法，不要呼叫 `init()`。詳情請參閱[手動初始化](/docs/server/server-adapters#manual-initialization)。
