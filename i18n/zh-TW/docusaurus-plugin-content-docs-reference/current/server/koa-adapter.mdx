# Koa 轉接器

`@mastra/koa` 套件提供在 [Koa](https://koajs.com) 中執行 Mastra 的伺服器轉接器。如需瞭解建構子選項、初始化流程等轉接器通用概念，請參閱[伺服器轉接器](/docs/server/server-adapters)。

## 安裝 {/* #installation */}

安裝 Koa 轉接器和 Koa 框架：

```bash npm2yarn
npm install @mastra/koa@latest koa koa-bodyparser
```

## 使用範例 {/* #usage-example */}

```typescript title="server.ts"
import Koa from 'koa'
import bodyParser from 'koa-bodyparser'
import { MastraServer } from '@mastra/koa'
import { mastra } from './mastra'

const app = new Koa()
app.use(bodyParser())

const server = new MastraServer({ app, mastra })

await server.init()

app.listen(3000, () => {
  console.log('Server running on http://localhost:3000')
})
```

`init()` 不會啟動 Mastra 的背景工作程序。若要執行[排程 Workflow](/docs/workflows/scheduled-workflows)、Agent 排程或事件監聽器，請在伺服器開始監聽後呼叫 `await mastra.startWorkers()`。詳情請參閱[啟動背景工作程序](/docs/server/server-adapters#start-background-workers)。

## 錯誤處理 {/* #error-handling */}

Koa 轉接器遵循 Koa 的標準錯誤處理方式：路由處理常式拋出的錯誤會沿 Koa 中介軟體鏈向上傳遞。您可以使用一般的 Koa 錯誤處理中介軟體：

```typescript title="server.ts"
const app = new Koa()
app.use(bodyParser())

// Your error middleware catches errors from Mastra route handlers
app.use(async (ctx, next) => {
  try {
    await next()
  } catch (err) {
    ctx.status = err.status || 500
    ctx.body = { error: err.message }
    // Log, report to Sentry, etc.
  }
})

const server = new MastraServer({ app, mastra })
await server.init()
```

轉接器也支援 [`server.onError`](/reference/configuration#serveronerror) 掛鉤。設定後，系統會在錯誤傳遞至中介軟體前呼叫此掛鉤，並直接使用其回傳的回應：

```typescript title="src/mastra/index.ts"
import { Mastra } from '@mastra/core'

const mastra = new Mastra({
  server: {
    onError: (err, c) => {
      console.error('Unhandled error:', err)
      return c.json({ error: err.message }, 500)
    },
  },
})
```

呼叫 `init()` 時，還會註冊全域錯誤處理中介軟體作為最後一道防線。依照 Koa 的標準慣例，到達此中介軟體的錯誤會透過 `ctx.app.emit('error', err, ctx)` 發出。對於路由處理常式已記錄的用戶端錯誤（4xx）及 `501` 錯誤，只有在您自行註冊 `error` 監聽器時，才會將其作為 `error` 事件發出；否則只會通知 `errorMonitor` 監聽器。

## 保護原始路由 {/* #protecting-raw-routes */}

需要 Mastra 管理的身分驗證及 `requiresAuth` 等路由中繼資料時，優先使用 [`registerApiRoute()`](/reference/server/register-api-route)。對於直接掛載到應用程式的原生 Koa 路由，請使用 `createAuthMiddleware()`：

```typescript title="server.ts"
import Koa from 'koa'
import { createAuthMiddleware, MastraServer } from '@mastra/koa'
import { mastra } from './mastra'

const app = new Koa()
const server = new MastraServer({ app, mastra })

await server.init()

app.use(createAuthMiddleware({ mastra }))
app.use(async ctx => {
  if (ctx.path !== '/custom/protected') return

  const user = ctx.state.requestContext.get('user')
  ctx.body = { user }
})
```

如需自訂中介軟體順序，請分別呼叫各個方法，而不要使用 `init()`。詳情請參閱[手動初始化](/docs/server/server-adapters#manual-initialization)。
