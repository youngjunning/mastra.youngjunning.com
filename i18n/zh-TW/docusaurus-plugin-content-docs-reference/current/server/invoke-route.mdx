# invokeRoute()

`invokeRoute()` 函式在程序內以呼叫者的身分執行伺服器路由，並傳回透過 HTTP 呼叫該路由時會收到的結果。請求上下文必須已通過 Mastra 伺服器的身分驗證。函式會執行與各轉接器上該路由的 HTTP 端點相同的檢查，包括身分驗證 Provider 的 `authorize`、`authorizeUser` 和 `rules`、結構描述驗證、RBAC 權限檢查，以及細粒度授權（FGA）。

使用它可透過其他通道（例如 MCP Tool）提供路由功能，無須經由 HTTP 伺服器代理呼叫，也能避免兩條呼叫路徑的行為逐漸產生差異。

## 使用範例 {/* #usage-example */}

```typescript title="src/mastra/tools/metric-aggregate.ts"
import { Mastra } from '@mastra/core/mastra'
import { RequestContext } from '@mastra/core/request-context'
import { createTool } from '@mastra/core/tools'
import { GET_METRIC_AGGREGATE } from '@mastra/server/handlers/observability'
import { invokeRoute } from '@mastra/server/server-adapter'
import { z } from 'zod'

export const agentRunCount = createTool({
  id: 'agentRunCount',
  description: 'Counts agent runs',
  inputSchema: z.object({}),
  execute: async (_input, { mastra, requestContext = new RequestContext() }) => {
    if (!(mastra instanceof Mastra)) throw new Error('agentRunCount must run inside Mastra')

    const { status, body } = await invokeRoute(GET_METRIC_AGGREGATE, {
      mastra,
      requestContext,
      body: { name: ['mastra_agent_duration_ms'], aggregation: 'count' },
    })
    if (status !== 200) throw new Error(`Metric aggregate failed with status ${status}`)
    return body
  },
})
```

## 行為 {/* #behavior */}

* **不會再次驗證身分。** 若已設定伺服器或 Studio 的身分驗證，請求上下文就必須包含 Mastra 伺服器驗證機制識別出的使用者。否則，`invokeRoute()` 會直接回傳 `401`，不執行處理常式。透過 Mastra 伺服器轉接器送達 MCP Tool 的請求會帶有這個上下文。
* **授權掛鉤會收到 HTTP 路徑。** `authorize()` 和 `rules` 會收到路由的 HTTP 方法，以及加上伺服器 `apiPrefix`（預設為 `/api`）且已代入路徑參數的路徑。`authorize()` 不會收到轉接器專用的請求上下文。
* **僅支援 JSON 路由。** 若路由採用其他 `responseType`，例如串流路由或 MCP 傳輸路由，`invokeRoute()` 會擲出錯誤。
* **處理常式不會收到 HTTP 專用參數。** 處理常式會收到剖析後的參數，以及 `mastra`、`requestContext` 和 `abortSignal`。若路由會讀取 `request`、`registeredTools`、`taskStore` 或 `routePrefix`，便不適合用這個函式呼叫。

## 與 `dispatchRoute()` 的差異 {/* #differences-from-dispatchroute */}

[`dispatchRoute()`](/reference/server/dispatch-route) 會對所有路由（含串流路由）執行相同的檢查，兩者的行為差異如下：

* 若已設定身分驗證，`invokeRoute()` 一律要求有通過驗證的使用者。`dispatchRoute()` 允許沒有使用者身分的呼叫者存取驗證設定中列為公開的路徑。
* `invokeRoute()` 以伺服器的 `apiPrefix` 組成傳給 `authorize()` 和 `rules` 的路徑。`dispatchRoute()` 則採用提供該路由的伺服器轉接器前綴。
* `invokeRoute()` 和 HTTP 轉接器一樣，允許請求主體的欄位覆寫同名的路徑參數。`dispatchRoute()` 以路徑參數為準。
* `invokeRoute()` 回傳 `{ status, body }`。`dispatchRoute()` 回傳處理常式的原始結果，檢查失敗時則回傳狀態碼和錯誤回應主體。
