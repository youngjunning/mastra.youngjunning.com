# 伺服器路由

當您呼叫時，伺服器適配器會註冊這些路由`server.init()`。所有路由都帶有前綴`prefix`選項（如果已配置）。

### 取得Agent查詢參數 {/* #get-agent-query-parameters */}

`GET /api/agents/:agentId`接受可選查詢參數來控制將哪個儲存的組態版本套用至程式碼定義Agent程式的覆寫：

|參數|類型 |預設 |描述 |
| - | - | - | - |
|`status` | `'draft' \| 'published'` | `'published'` | Which stored version to resolve. `draft` returns the latest version, and `published` returns the active version. |
| `versionId` | `string` | None | A specific version ID to resolve. Takes precedence over `status`. |

```bash
# Get agent with active published overrides (default)
GET /api/agents/my-agent

# Get agent with latest draft overrides
GET /api/agents/my-agent?status=draft

# Get agent with a specific version's overrides
GET /api/agents/my-agent?versionId=abc123
```

### Agent訊息路由 {/* #agent-message-routes */}

使用`POST /api/agents/:agentId/send-message` to send a user message to the active agent loop or wake an idle thread. Use `POST /api/agents/:agentId/queue-message` when the active run should finish before Mastra starts a follow-up run.

若要以相同的順序對鍵入的訊號進行排隊，請使用`POST /api/agents/:agentId/queue-signal` with a `signal` field in place of `message`. The `signal` field takes the same shape as `POST /api/agents/:agentId/signals`.

兩條路由都接受相同的請求正文：

```typescript oxfmt:false
{
  message: string | Array<TextPart | FilePart> | {
    contents: string | Array<TextPart | FilePart>;
    attributes?: Record<string, JSONValue>;
    metadata?: Record<string, unknown>;
    providerOptions?: ProviderMetadata;
  };
  runId?: string;
  resourceId?: string;
  threadId?: string;
  ifActive?: {
    behavior?: 'deliver' | 'persist' | 'discard';
    attributes?: Record<string, string | number | boolean>;
  };
  ifIdle?: {
    behavior?: 'wake' | 'persist' | 'discard';
    streamOptions?: Omit<AgentExecutionOptions, 'messages'>;
    attributes?: Record<string, string | number | boolean>;
  };
}
```

什麼時候`runId` is omitted, `resourceId` and `threadId` are required. `ifIdle` only applies to thread-targeted requests, not run-targeted requests.

#### 發送訊息 {/* #send-a-message */}

```bash
curl -X POST http://localhost:4111/api/agents/supportAgent/send-message \
  -H 'Content-Type: application/json' \
  -d '{
    "message": {
      "contents": "Show the shorter version.",
      "attributes": { "sentFrom": "web" }
    },
    "resourceId": "user_123",
    "threadId": "thread_456"
  }'
```

#### 將訊息放入隊列 {/* #queue-a-message */}

```bash
curl -X POST http://localhost:4111/api/agents/supportAgent/queue-message \
  -H 'Content-Type: application/json' \
  -d '{
    "message": "Also check whether the tests need updates.",
    "resourceId": "user_123",
    "threadId": "thread_456"
  }'
```

兩條路線均回：

```typescript oxfmt:false
{
  accepted: true;
  runId: string;
  signal?: CreatedAgentSignal;
}
```

### 線程取消路線 {/* #thread-cancellation-routes */}

`POST /api/agents/:agentId/threads/abort`接受`{ resourceId?: string, threadId: string, clearPendingSignals?: boolean }` and returns `{ aborted: boolean }`. Pending input survives unless `clearPendingSignals` is `true`. The clear happens locally before aborting and is forwarded to the active owner when necessary. For a remote owner, `aborted: true` means the request was sent, not acknowledged.

`POST /api/agents/:agentId/threads/signals/cancel`取消選定的待處理輸入而不中止。其 JSON 正文包含：

<PropertiesTable
  content={[
{ name: 'resourceId', type: 'string', isOptional: true, description: 'Resource ID for the memory thread.' },
{ name: 'threadId', type: 'string', description: 'Thread containing the pending signals.' },
{ name: 'signalIds', type: 'string[]', description: 'Between 1 and 1,000 nonempty signal IDs to cancel.' },
]}
/>

響應是`{ cancelledSignalIds: string[] }`, containing only IDs cancelled on the server process handling the request. Duplicates appear once. Unknown IDs and signals already handed to execution or another owner aren't included. Invalid bodies return HTTP 400.

兩條路線都需要`agents:execute` permission and apply thread ownership checks using the authenticated request context. When fine-grained authorization is configured, they also require `memory:write` permission on the thread, including threads not yet saved. Cancellation covers Agents sharing the memory thread, not only the Agent named in the URL. It doesn't undo persisted messages, state updates, notification records, or acceptance acknowledgements, and it excludes continuations from `continueWithMessages()`.

伺服器透過共享 PubSub 後端發布所有請求的 ID，即使沒有本地待處理的 ID，因此訂閱該線程的其他進程可以刪除匹配的待處理輸入。傳播是盡力且非同步的，並且 HTTP 回應不會確認遠端取消。中止清除會影響接收程序和活動擁有者，而不是每個程序的佇列。請參閱[client cancellation methods](/reference/client-js/agents#cancelqueuedmessages) for SDK usage.

升級`@mastra/core` alongside `@mastra/server` to use thread-wide cancellation and clear-on-abort. In multi-process deployments, upgrade every worker that can own the thread. If the Agent's core version doesn't support these semantics, the server returns HTTP 501 without cancelling input. Ordinary abort requests without `clearPendingSignals: true` remain supported on older cores that provide thread aborts.

### 訂閱Tool審核途徑 {/* #subscription-tool-approval-routes */}

使用`POST /api/agents/:agentId/send-tool-approval` when the client already has an active thread subscription. The route resumes the run and returns a JSON acknowledgement. Resumed stream chunks are delivered through `POST /api/agents/:agentId/threads/subscribe`.

```typescript oxfmt:false

  requestContext?: Record<string, unknown>;
}
```

路線返回：

```typescript oxfmt:false

  accepted: true;
  runId: string;
  toolCallId?: string;
}
```

### 運行結果 {/* #run-result */}

`POST /api/workflows/:workflowId/start-async`等待著`run.start()` and returns its execution result, rather than returning immediately after starting the run. The `status` distinguishes success, failure, tripwire, suspension, and pause. The `steps` record is keyed by step ID, and each step has its own status and an `output` when one is available. The workflow's output is the top-level `result` on success.

執行結果包含以下欄位。特定於狀態的欄位僅針對對應的結果出現：

```typescript oxfmt:false
{
  status: 'success' | 'failed' | 'tripwire' | 'suspended' | 'paused';
  input: unknown;                      // The inputData the run started with
  state?: unknown;                     // Workflow state
  result?: unknown;                    // Workflow output on success
  error?: unknown;                     // Error on failure
  tripwire?: unknown;                  // Tripwire details
  suspendPayload?: unknown;           // Payload returned on suspension
  suspended?: string[][];              // Suspended step paths
  steps: {
    [stepId: string]: {
      status: string;
      output?: unknown;
      error?: unknown;
      startedAt: number;               // Unix time in milliseconds
      endedAt?: number;
    };
  };
}
```

`GET /api/workflows/:workflowId/runs/:runId`返回運行元資料和執行狀態，使用可用的持久快照並回退到記憶體中運行。與上面的執行結果不同，它將運行的輸入公開為`payload` and state as `initialState`. `workflowName` is the workflow's `id`, which can differ from the registry key used in the path:

```typescript oxfmt:false
{
  runId: string;
  workflowName: string;
  resourceId?: string | null;
  createdAt: string;                   // ISO date string
  updatedAt: string;                   // ISO date string
  status: string;                      // Includes active states such as 'running' and 'waiting'
  initialState?: Record<string, unknown>;
  result?: unknown;
  error?: unknown;
  payload?: unknown;                   // The inputData the run started with
  steps?: {
    [stepId: string]: {
      payload?: unknown;               // This step's input
      status: string;
      output?: unknown;
      error?: unknown;                 // Present when the step failed
      startedAt: number;
      endedAt?: number;
    } | {
      payload?: unknown;
      status: string;
      output?: unknown;
      error?: unknown;
      startedAt: number;
      endedAt?: number;
    }[];                              // forEach iteration results
  };
  activeStepsPath?: Record<string, number[]>;
  serializedStepGraph?: unknown[];
  suspendedPaths?: Record<string, number[]>;
  resumeLabels?: Record<string, unknown>;
  waitingPaths?: Record<string, number[]>;
}
```

對於持久運行，請使用`fields` query parameter to trim the response. It accepts a comma-separated subset of `result`, `error`, `payload`, `steps`, `activeStepsPath`, and `serializedStepGraph`. Any other name is rejected with a 400. The metadata fields and `status` remain, along with `initialState` when nonempty:

```bash
curl 'http://localhost:4111/api/workflows/my-workflow/runs/1faf6f91-b9ac-4db0-9fb3-326687ba1972?fields=result'
```

一個`steps` entry can be a single step result or an array of iteration results for a `forEach` step. Check whether the entry is an array before reading its `status` or `output`.

經過`withNestedWorkflows=false` to skip expanding nested workflow executions inside `steps`. This doesn't remove the workflow's own step entries.

記憶體中的回退由以下方式標識`isFromInMemory: true`. It returns run metadata, `status`, and empty `steps`, but omits `result`, `payload`, and `error`. Its `createdAt` and `updatedAt` timestamps use the current time, not the run's actual timestamps. It doesn't apply field filtering or nested-workflow expansion.

## 知識 {/* #knowledge */}

預設不註冊這些路由。添加它們`KNOWLEDGE_ROUTES` from `@mastra/server/server-adapter` in `server.apiRoutes`, and register the instance on `Mastra` under `knowledge`. They need `@mastra/core` 1.81.0 or later, and the two link routes need 1.82.0 or later. With an RBAC provider, every route requires the `knowledge:read` permission. Without one, that check is skipped. See [Studio Knowledge](/docs/studio/knowledge) for setup.

|方法|路徑|描述 |
| - | - | - |
|`GET` | `/api/knowledge` | List the registered Knowledge instances, filtered by FGA when configured |
| `GET` | `/api/knowledge/:knowledgeKey/tree` | List the root scopes, or the children of `parentId` |
| `GET` | `/api/knowledge/:knowledgeKey/pages/:pageId` | Get a page with its ancestors, notes, pin and referenced pages |
| `GET` | `/api/knowledge/:knowledgeKey/link-counts` | Count the links into and out of each page in `pageId` |
| `GET` | `/api/knowledge/:knowledgeKey/pages/:pageId/links` | List the links into and out of one page |
| `GET` | `/api/knowledge/:knowledgeKey/graph` | Get a bounded graph of pages with parent and mention edges and scope grants |
| `GET` | `/api/knowledge/:knowledgeKey/search` | Search page names, descriptions, bodies and notes |
| `GET` | `/api/knowledge/:knowledgeKey/activity` | List recent changes, optionally for one scope or page |
| `GET` | `/api/knowledge/:knowledgeKey/events` | Stream the caller's readable writes as Server-Sent Events. See [Knowledge events](#knowledge-events) |

`:knowledgeKey`是實例註冊的密鑰`knowledge: { ... }`.

### 知識查詢參數 {/* #knowledge-query-parameters */}

### 知識獲取和錯誤 {/* #knowledge-access-and-errors */}

沒有`server.auth` or `studio.auth`, the routes read as the instance owner and return everything. With auth, they read only what the scopes in the request context key `MASTRA_KNOWLEDGE_PRINCIPALS_KEY` can read. Set it to an array of scopes, or `'all'`.

|狀態 |當 |
| - | - |
|`403` | Auth is configured and `MASTRA_KNOWLEDGE_PRINCIPALS_KEY` isn't set. `GET /api/knowledge` doesn't read the key, so it doesn't return `403` |
| `404` | The instance doesn't exist or the FGA provider denies `knowledge:read` on it, or the page doesn't exist or the caller can't read it. For an unreadable page, the link routes report zero counts and no links instead |
| `500` | `MASTRA_KNOWLEDGE_PRINCIPALS_KEY` isn't an array or `'all'`, or holds a scope that matches no declared scope type |
| `501` | `@mastra/core` is older than the route needs, or the store has no link index (link routes) |

`knowledge`, by its registered key, with `knowledge:read`. `GET /api/knowledge` lists only the instances the caller can read. With `requireForProtectedRoutes`, `GET /api/knowledge` is refused, because like other list routes it has no FGA metadata. Without an RBAC provider, the `knowledge:read` check is skipped.

NestJS 適配器尚不支援這些路由。

### 知識活動 {/* #knowledge-events */}

`GET /api/knowledge/:knowledgeKey/events`每次提交的寫入都會發送一個呼叫者可以讀取的事件：

```typescript oxfmt:false
{
  kind: 'scope' | 'page' | 'note' | 'pin';
  op: string;       // such as 'create', 'update', 'delete' or 'merge'
  pageId?: string;  // left out when the caller can't read the page, including a deleted one
  scopeId?: string; // left out when the caller can't read the scope
  at: string;       // ISO timestamp
}
```

不會發送與呼叫者無法讀取的任何內容相關的寫入。事件攜帶 ID，而不是內容，因此請取得其他路由發生的變更。什麼時候`pageId` is missing, refresh the scope in `scopeId`.

伺服器每 25 秒發送一條 keepalive 註釋，並在五分鐘後關閉串流。關閉後重新連線。新的流再次讀取呼叫者的範圍，因此撤銷的存取會停止更新。斷開連線時進行的寫入不會重播，因此請在重新連線後重新整理顯示的內容。

### 刪除實驗 {/* #delete-an-experiment */}

兩條刪除路徑都會刪除實驗及其結果記錄。當儲存支援可觀察性和跡線刪除時，Mastra 會在刪除實驗之前刪除實驗產生的跡線及其跨度和跡線連結訊號。

當您知道所屬資料集時，請使用資料集範圍的路由：

```bash
curl -X DELETE http://localhost:4111/api/datasets/dataset-id/experiments/experiment-id
```

此路線接受可選`organizationId` and `projectId` query parameters. It returns `404` if the dataset is outside the supplied tenancy, the experiment doesn't exist, or the experiment doesn't belong to the dataset.

當您沒有資料集引用時，包括當資料集刪除透過清除實驗而孤立實驗時，請使用頂級路由`datasetId`:

```bash
curl -X DELETE http://localhost:4111/api/experiments/experiment-id
```

頂級路由接受可選`organizationId` and `projectId` query parameters. When either is present, deletion is limited to that tenancy. A tenancy mismatch returns `{ "success": true }` without deleting the experiment. Without tenancy parameters, a missing experiment returns `404`.

刪除成功返回`{ "success": true }`. The top-level route returns the same response for a tenancy mismatch, but doesn't delete anything. Both routes return `501` unless the installed `@mastra/core` advertises support through the `experiment-deletion` feature flag, including when an older version predates this support. When storage lacks observability or trace deletion support, Mastra logs a warning, leaves the traces in place, and still deletes the experiment with its result records. If trace deletion fails for any other reason, the route returns `500` and preserves the experiment and result records. Traces are deleted in batches of 1,000, so some traces may already have been removed. Repeat the request to finish the deletion.

### 清除資料集項目 {/* #purge-a-dataset-item */}

`DELETE /api/datasets/:datasetId/items/:itemId/purge`從每個歷史版本、刪除邏輯刪除和連結的實驗結果中永久清除該項目的儲存內容。它不會建立新的資料集版本並且無法撤銷。看[`dataset.purgeItem()`](/reference/datasets/purgeItem) for the complete purge behavior.

```bash
curl -X DELETE http://localhost:4111/api/datasets/dataset-id/items/item-id/purge
```

此路線接受可選`organizationId` and `projectId` query parameters. It returns `404` if the dataset is outside the supplied tenancy or the item has no history in the dataset. It returns `501` unless the installed `@mastra/core` advertises support through the `dataset-item-purge` feature flag. MongoDB storage without transaction support returns `500` before changing any data. A successful purge returns `{ "success": true }`.

### 調用者驅動的實驗路線 {/* #caller-driven-experiment-routes */}

當您自己的編排器（例如臨時Workflow）擁有實驗循環並且 Mastra 充當記錄系統時，請使用這些路由。專案運行、結果提交和最終確定可以安全地重試。只有當請求包含呼叫者提供的內容時，才能安全地重試創建`id`; without one, each retry creates a new experiment. Item runs and result submissions upsert on `(experimentId, itemId, attempt)`. Finalize returns the stored record if the experiment is already completed.

#### 建立實驗請求正文 {/* #create-experiment-request-body */}

發佈到`/api/datasets/:datasetId/experiments` with `start: false` to create the experiment without running it. Include `targetType` and `targetId` when Mastra should execute items via the run-item route. Omit both for pure ingestion via the results route.

```typescript oxfmt:false
{
  start?: boolean;              // false creates the experiment without running it. Defaults to true.
  id?: string;                  // Caller-supplied experiment id (e.g. a workflow run id) for idempotent creates
  targetType?: 'agent' | 'workflow' | 'scorer'; // Provide with targetId, or omit both
  targetId?: string;
  scorerIds?: string[];         // Run-level scorer ids, resolved server-side. Requires a target when start is false.
  name?: string;
  description?: string;
  metadata?: Record<string, unknown>;
  version?: number;             // Pin to a specific dataset version (defaults to latest)
  provenance?: {
    source?: string;
    sourceId?: string;
    sourceVersion?: string;
    metadata?: Record<string, unknown>;
  };
  grouping?: {                  // Stable grouping dimensions for comparisons and repeated trials
    experimentSetId?: string;
    comparisonId?: string;
    variantId?: string;
    trialIndex?: number;
  };
}
```

退貨`{ experimentId, status, totalItems, datasetVersion }` when `start` is `false`.

#### 運行實驗項請求正文 {/* #run-experiment-item-request-body */}

`POST /api/datasets/:datasetId/experiments/:experimentId/items/:itemId/run`針對一項執行實驗目標並執行已解析的記分器，然後更新插入結果。需要使用目標創建實驗。

```typescript oxfmt:false
{
  attempt?: number;             // Zero-based repetition index. Defaults to 0.
  requestContext?: Record<string, unknown>; // Merged with the item's own request context (item wins)
}
```

退貨`{ result, scores }` with the persisted result row and the scores produced for the item.

#### 提交實驗結果請求正文 {/* #submit-experiment-result-request-body */}

```typescript oxfmt:false
{
  itemId: string;               // Dataset item this result belongs to
  attempt?: number;             // Zero-based repetition index. Defaults to 0.
  input?: unknown;              // Defaults to the dataset item input
  output?: unknown;             // Output produced by the external runner
  groundTruth?: unknown;        // Defaults to the dataset item groundTruth
  error?: {                     // Failure info when the item run failed
    message: string;
    stack?: string;
    code?: string;
  } | null;
  startedAt?: string;           // ISO date
  completedAt?: string;         // ISO date
  traceId?: string;
  scores?: Array<{              // Externally computed scores, persisted keyed by runId = experimentId
    scorerId: string;
    scorerName?: string;
    score: number;
    reason?: string;
    metadata?: Record<string, unknown>;
  }>;
}
```

傳回保留的實驗結果行。

#### 完成實驗 {/* #finalize-experiment */}

`POST /api/datasets/:datasetId/experiments/:experimentId/finalize`不需要身體。伺服器根據持久性結果行計算每個項目的計數並標記實驗`completed`: `succeededCount` (at least one attempt without an error), `failedCount` (every attempt errored), and `skippedCount` (never submitted). Returns the updated experiment record.

#### 呼叫者驅動的實驗錯誤回應 {/* #caller-driven-experiment-error-responses */}

|狀態 |狀況 |
| - | - |
|`400` | Result submitted to an experiment that has a target (`EXPERIMENT_HAS_TARGET`), item run requested on a target-less experiment (`EXPERIMENT_HAS_NO_TARGET`), `targetType` and `targetId` weren't provided together (`EXPERIMENT_INVALID_TARGET`), or the dataset has no items at the pinned version (`EXPERIMENT_NO_ITEMS`) |
| `404` | Dataset, experiment, dataset item, or target not found (`EXPERIMENT_TARGET_NOT_FOUND`) |
| `409` | Caller-supplied experiment `id` already exists for a different dataset or target (`EXPERIMENT_ID_CONFLICT`), or a call arrived after finalization (`EXPERIMENT_ALREADY_FINALIZED`) |

### 列出評分者的反應 {/* #list-scorers-response */}

回應是一個記錄，結合了通過註冊的記分員`scorers` option of the [`Mastra` class](/reference/core/mastra-class) with the scorers attached to agents and workflows. Agent and registered entries are keyed by scorer ID. Workflow entries currently use the scorer's name. Use the returned record key for `/api/scores/scorers/:scorerId`, and `scorer.config.id` when querying saved scores by scorer ID:

```typescript oxfmt:false
{
  [scorerId: string]: {
    scorer: {
      config: {
        id: string;
        name?: string;
        description: string;
        type?: unknown;
        judge?: unknown;
      };
    };
    sampling?: object;
    agentIds: string[];
    agentNames: string[];
    workflowIds: string[];
    isRegistered: boolean;             // True when the scorer is in the Mastra `scorers` option
    source: 'code' | 'stored' | 'fs';
  };
}
```

僅有的`scorer.config` is part of the supported contract. The `scorer` object also carries implementation fields such as `steps`, which can change between releases.

`GET /api/scores/scorers/:scorerId`傳回相同形狀的單一條目。返回未知 ID`null` with status 200 rather than a 404.

### 成績單查詢參數 {/* #score-list-query-parameters */}

```typescript oxfmt:false
{
  page?: number;        // Page number (0-indexed)
  perPage?: number;     // Items per page (default: 10)
  entityId?: string;    // `/api/scores/scorer/:scorerId` only
  entityType?: string;  // `/api/scores/scorer/:scorerId` only
}
```

為了`/api/scores/entity/:entityType/:entityId`, use `AGENT` or `WORKFLOW` as `entityType` and the agent or workflow registry key as `entityId`. The server resolves the key to the entity's own `id` before querying storage. Other `entityType` values are passed to storage as-is.

### 分數列表回應 {/* #score-list-response */}

```typescript oxfmt:false
{
  pagination: {
    total: number;
    page: number;
    perPage: number;
    hasMore: boolean;
  };
  scores: ScoreRowData[];
}
```

每筆記錄的形狀由[score persistence](/docs/evals/overview#score-persistence). The fields you will read most often are `id`, `scorerId`, `runId`, `entityId`, `score`, `output`, `scorer`, `entity`, `source` (`LIVE` or `TEST`), the optional `entityType`, `input`, `reason`, `traceId`, `spanId`, `resourceId` and `threadId`, and the `createdAt` and `updatedAt` timestamps. Records also carry the scorer's intermediate step results and prompts. Without a `scores` store configured the list routes return an empty page instead of an error.

### 保存分數請求正文 {/* #save-score-request-body */}

```typescript oxfmt:false
{
  score: Omit<ScoreRowData, 'id' | 'createdAt' | 'updatedAt'> & { id?: string };
}
```

如何提供`id` is treated depends on the storage adapter. Some adapters upsert by it, others always generate a new ID, so retried submissions can create duplicate rows there. The response is `{ score: ScoreRowData }` with the stored record. Saving requires storage. Without it the route responds with a 500.
