# SlackProvider

`SlackProvider` 提供將 Agent 連接 Slack 的託管方式。註冊到 `Mastra.channels` 後，它會透過 Manifest API 建立 Slack 應用程式並執行 OAuth 安裝流程，也會輪替設定權杖，並將 Slack 事件路由給 Agent。若希望由 Mastra 負責建立及安裝應用程式，請使用此方式。若要自行建立 Slack 應用程式、設定權限範圍與 webhook，請改使用較底層的 [`createSlackAdapter`](/integrations/channels/slack)，並設定在 Agent 的 `channels.adapters` 中。

## 使用範例 {/* #usage-example */}

在 `Mastra` 建構函式中註冊 Provider。重新整理權杖只能使用一次，並會在啟動時輪替。產生的存取權杖會持久化至 `Mastra.storage`。

```typescript title="src/mastra/index.ts"
import { Mastra } from '@mastra/core/mastra'
import { SlackProvider } from '@mastra/slack'

export const mastra = new Mastra({
  storage,
  channels: {
    slack: new SlackProvider({
      refreshToken: process.env.SLACK_APP_CONFIG_REFRESH_TOKEN,
      baseUrl: process.env.MASTRA_BASE_URL,
    }),
  },
})
```

如果建立物件時尚未取得憑證（例如透過 Editor UI 輸入，或從密鑰保管庫載入），可先建立不含憑證的 Provider，之後再呼叫 [`configure()`](#configurecredentials)：

```typescript title="src/mastra/index.ts"
const slack = new SlackProvider()

await slack.configure({
  refreshToken: process.env.SLACK_APP_CONFIG_REFRESH_TOKEN,
})
```

## 方法 {/* #methods */}

### Agent 連線 {/* #agent-connections */}

#### `connect(agentId, options?)` {/* #connectagentid-options */}

透過 Manifest API 為 Agent 建立 Slack 應用程式，並回傳含授權 URL 的 OAuth 結果，供使用者重新導向。必須設定 `baseUrl`。若該 Agent 已有待完成的安裝，則回傳既有授權 URL，不會重複建立應用程式。

```typescript
const result = await slack.connect('support-agent', {
  name: 'Support Bot',
})

// Redirect the user to result.authorizationUrl to install the app
```

返回：`Promise<ChannelConnectResult>`

```typescript
interface ChannelConnectResult {
  type: 'oauth'
  installationId: string
  authorizationUrl: string
}
```

#### `disconnect(agentId)` {/* #disconnectagentid */}

刪除 Agent 的 Slack 應用程式，並從儲存空間移除安裝紀錄，以中斷連線。

```typescript
await slack.disconnect('support-agent')
```

返回：`Promise<void>`

#### `getInstallation(agentId)` {/* #getinstallationagentid */}

回傳 Agent 的 Slack 安裝紀錄；若不存在則回傳 `null`。

```typescript
const installation = await slack.getInstallation('support-agent')
```

返回：`Promise<SlackInstallation | null>`

#### `listInstallations()` {/* #listinstallations */}

列出所有 Slack 安裝紀錄，包括有效及待完成的安裝；僅包含公開資訊。

```typescript
const installations = await slack.listInstallations()
```

返回：`Promise<ChannelInstallationInfo[]>`

### 配置 {/* #configuration */}

#### `configure(credentials)` {/* #configurecredentials */}

在執行期間提供或清除 Slack App Configuration 憑證。建立物件時尚未取得憑證，可使用此方法。傳入 `null` 會清除憑證並刪除已儲存的權杖。

```typescript
// Provide credentials (persists to storage immediately)
await slack.configure({ refreshToken: 'xoxe-1-...' })

// Clear credentials and stored tokens
await slack.configure(null)
```

返回：`Promise<void>`

#### `setBaseUrl(baseUrl)` {/* #setbaseurlbaseurl */}

設定 webhook 與 OAuth 回呼使用的公開基底 URL。建立物件時尚不知道 URL，且無法從伺服器設定自動偵測時使用。

```typescript
slack.setBaseUrl('https://abc123.trycloudflare.com')
```

#### `initialize()` {/* #initialize */}

為儲存空間中的每筆有效安裝紀錄重新建立 `SlackAdapter`，並將 `AgentChannels` 注入對應的 Agent，使其啟動後能接收 Slack 事件。此方法不會自動建立新應用程式；要建立請呼叫 `connect()`。Mastra 會自動呼叫，通常不需手動執行。

```typescript
await slack.initialize()
```

返回：`Promise<void>`

## 取得 Provider {/* #accessing-the-provider */}

透過具型別的 `channels` getter，以註冊時使用的 ID 為鍵取得 Provider：

```typescript
const result = await mastra.channels.slack.connect('support-agent')
```

若執行期間才知道鍵名，可透過字串 ID 查找並傳入具體型別：

```typescript
const slack = mastra.getChannelProvider<SlackProvider>('slack')
const result = await slack.connect('support-agent')
```

## 儲存要求 {/* #storage-requirement */}

`SlackProvider` 必須在 `Mastra` 上設定持久化儲存，才能加密並保存安裝紀錄及輪替中的設定權杖。若無持久化儲存，也未傳入自訂 `storage`，建構函式會擲出例外。
