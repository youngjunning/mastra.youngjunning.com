# TelegramProvider

`TelegramProvider` 透過 Bot API 將 Mastra Agent 連接至 Telegram 機器人。將它註冊於 `Mastra.channels` 後，即可管理機器人安裝、選擇 Webhook 或輪詢傳遞、驗證 Webhook 密鑰、註冊指令，並將 Telegram 對話路由至 Agent。

若希望由 Mastra 管理機器人的生命週期，請使用 `TelegramProvider`。若要自行設定底層 Telegram Adapter 與 Webhook，請使用 [`createTelegramAdapter`](/integrations/channels/telegram)，並將它放在 Agent 的 `channels.adapters` 中。

## 使用範例 {/* #usage-example */}

先透過 [BotFather](https://t.me/botfather) 建立機器人、設定 `TELEGRAM_BOT_TOKEN`，再以公開的基底網址註冊 Provider，以便透過 Webhook 傳遞：

```typescript title="src/mastra/index.ts"
import { Agent } from '@mastra/core/agent'
import { Mastra } from '@mastra/core/mastra'
import { TelegramProvider } from '@mastra/telegram'

const supportAgent = new Agent({
  id: 'support',
  name: 'Support agent',
  instructions: 'Help users with product questions.',
  model: 'openai/gpt-5-mini',
})

const telegram = new TelegramProvider({
  baseUrl: 'https://your-app.example.com',
})

export const mastra = new Mastra({
  agents: { supportAgent },
  channels: { telegram },
})

await telegram.connect('support', {
  botToken: process.env.TELEGRAM_BOT_TOKEN,
})
```

省略 `botToken` 時，`connect()` 會建立待完成的安裝並傳回 BotFather 深層連結，而不會立即啟用機器人。

## 方法 {/* #methods */}

### 安裝生命週期 {/* #installation-lifecycle */}

#### `connect(agentId, options)` {/* #connectagentid-options */}

將 Agent 連接至 Telegram 機器人。Provider 會呼叫 `getMe` 驗證 BotFather 權杖，準備選定的傳遞模式與指令，儲存安裝資訊，然後啟用 Adapter。

```typescript
const result = await telegram.connect('support', {
  botToken: process.env.TELEGRAM_BOT_TOKEN,
  name: 'Support bot',
  commands: [
    { command: 'help', description: 'Show support options' },
    { command: 'status', description: 'Check service status' },
  ],
})
```

`TelegramConnectOptions` 欄位：

    name: 'name',

返回：`Promise<ChannelConnectResult>`

#### `disconnect(agentId)` {/* #disconnectagentid */}

停止目前的傳輸並刪除已儲存的安裝資訊。在 Webhook 模式下，還會移除 Telegram Webhook。

```typescript
await telegram.disconnect('support')
```

返回：`Promise<void>`

#### `listInstallations()` {/* #listinstallations */}

列出已啟用與待完成的 Telegram 安裝，但不公開機器人或 Webhook 密鑰權杖。

```typescript
const installations = await telegram.listInstallations()
```

返回：`Promise<ChannelInstallationInfo[]>`

#### `getInstallation(agentId)` {/* #getinstallationagentid */}

傳回 Agent 的完整安裝資訊，包含敏感的機器人與 Webhook 權杖；若沒有安裝，則傳回 `null`。

```typescript
const installation = await telegram.getInstallation('support')
```

返回：`Promise<TelegramInstallation | null>`

### 配置和狀態 {/* #configuration-and-status */}

#### `configure(credentials)` {/* #configurecredentials */}

在執行階段更新 Bot API 的來源位址或 Webhook 基底網址。傳入 `null` 不會有作用，因為 Telegram 憑證屬於各個機器人安裝。

```typescript
await telegram.configure({
  baseUrl: 'https://new-app.example.com',
  apiBaseUrl: 'https://api.telegram.org',
})
```

返回：`Promise<void>`

#### `initialize()` {/* #initialize */}

Mastra 啟動時會呼叫此方法：先從儲存空間還原已啟用的安裝並重建 Telegram Adapter，再重新連接已註冊的 Agent。

```typescript
await telegram.initialize()
```

返回：`Promise<void>`

#### `isConfigured()` {/* #isconfigured */}

傳回是否至少有一個已啟用的 Telegram 安裝。

```typescript
const configured = telegram.isConfigured()
```

#### `getInfo()` {/* #getinfo */}

傳回供 Editor UI 探索頻道的中繼資料，包含連線狀態，以及 `botToken` 與 `name` 的連線選項 Schema。

```typescript
const info = telegram.getInfo()
```

返回：`ChannelPlatformInfo`

#### `getAdapter(installationId)` {/* #getadapterinstallationid */}

傳回已啟用安裝對應的即時 `TelegramAdapter`。

```typescript
const adapter = telegram.getAdapter(installationId)
```

返回：`TelegramAdapter | undefined`

#### `getRoutes()` {/* #getroutes */}

傳回 Provider 無需驗證的 `POST /telegram/events/:webhookId` 路由。Mastra 會自動註冊該路由。

```typescript
const routes = telegram.getRoutes()
```

返回：`ApiRoute[]`

## 傳遞模式 {/* #delivery-modes */}

- **`webhook`**：為每個機器人在 `/telegram/events/:webhookId` 下註冊 Webhook，並驗證 `X-Telegram-Bot-Api-Secret-Token` 標頭。
- **`polling`**：啟動 Telegram 的 `getUpdates` 迴圈前，先移除現有 Webhook。
- **`auto`**：有公開基底網址時使用 Webhook，否則使用輪詢。

正式環境應使用持久化頻道儲存空間，並設定 `encryptionKey` 或 `MASTRA_ENCRYPTION_KEY`，因為記憶體備援儲存無法在重新啟動後保留安裝資訊。
