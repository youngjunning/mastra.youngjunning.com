舊版 Workflow 功能已移除。
# Workflow



## 變更 {/* #changed */}

### `getWorkflows` 更名為 `listWorkflows` {/* #getworkflows-to-listworkflows */}

`mastra.getWorkflows()` 已更名為 `mastra.listWorkflows()`。這符合 API 中以 `list` 作為回傳多個項目的方法前綴的命名慣例。

遷移時，請將所有 `mastra.getWorkflows()` 呼叫改為 `mastra.listWorkflows()`。

```diff
- const workflows = mastra.getWorkflows();
+ const workflows = mastra.listWorkflows();
```

:::tip[程式碼遷移]

您可以使用 Mastra 的 codemod CLI 自動更新匯入敘述：

```bash
npx @mastra/codemod@latest v1/mastra-plural-apis .
```

:::

### 步驟內容中的 `RuntimeContext` 更名為 `RequestContext` {/* #runtimecontext-to-requestcontext-in-step-context */}

Workflow 步驟執行內容中的參數名稱已從 `runtimeContext` 改為 `requestContext`，與全域更名一致，語意也更明確。

遷移時，請將步驟執行函式中對 `runtimeContext` 的參照改為 `requestContext`。

```diff
  createStep({
-   execute: async ({ runtimeContext } ) => {
-     const userTier = context.runtimeContext.get('userTier');
+   execute: async ({ requestContext } ) => {
+     const userTier = requestContext.get('userTier');
      return { result: userTier };
    },
  });
```

:::tip[程式碼遷移]

您可以使用 Mastra 的 codemod CLI 自動更新匯入敘述：

```bash
npx @mastra/codemod@latest v1/runtime-context .
```

:::

### `createRunAsync` 更名為 `createRun` {/* #createrunasync-to-createrun */}

`createRunAsync()` 已更名為 `createRun()`。建立執行個體一律是非同步操作，因此移除多餘的「Async」後綴可讓 API 更精簡。

遷移時，請將方法呼叫中的 `createRunAsync` 改為 `createRun`。

```diff
- await workflow.createRunAsync({ input: { ... } });
+ await workflow.createRun({ input: { ... } });
```

### `runCount` 更名為 `retryCount`（舊名稱已棄用） {/* #runcount-to-retrycount-deprecated */}

Workflow 步驟執行時的 `runCount` 參數已棄用，改用 `retryCount`。新名稱清楚表明該值代表重試次數。舊的 `runCount` 仍可使用，但會顯示棄用警告。

遷移時，請將步驟執行函式中的 `runCount` 改為 `retryCount`。

```diff
  createStep({
    execute: async (inputData, context) => {
-     console.log(`Step run ${context.runCount} times`);
+     console.log(`Step retry count: ${context.retryCount}`);
    },
  });
```

### `getInitData` 回傳 `unknown` {/* #getinitdata-returns-unknown */}

執行函式中的 `getInitData` 現在回傳 `unknown`，而非 `any`。您需要自行指定型別。
遷移時，請將 `getInitData()` 改為 `getInitData<any>()`。

```diff
  createStep({
    execute: async ({ getInitData }) => {
-     const initData = getInitData();
-     if (initData.key === 'value') {}
+     const initData = getInitData<any>();
+     if (initData.key === 'value') {}
    },
  });
```

### 預設會驗證輸入 {/* #inputs-are-validated-by-default */}

過去預設不會驗證輸入。[`validateInputs`](/reference/workflows/workflow#constructor-parameters) 旗標決定是否驗證 Workflow 輸入，其預設值現已改為 `true`。若要維持舊行為，或有些 Workflow 的 schema 不需要驗證，請設定 `validateInputs: false`。

```diff
createWorkflow({
+  options: {
+    validateInputs: false
+  }
})
```

### 驗證步驟的 `suspendPayload` {/* #step-suspendpayload-validation */}

對於定義了 `suspendSchema` 的步驟，現在會驗證其 `suspendPayload`。是否執行這項驗證，同樣由 `validateInputs` 旗標決定。

```diff
  createStep({
    id: "suspend-resume-step",
    // ... other step properties
    suspendSchema: z.object({
      reason: z.string(),
      otherReason: z.string()
    }),
    execute: async ({ suspend, resumeData}) => {
      if (!resumeData) {
-       return suspend({ reason: "Suspension reason" }); // Missing otherReason
+       return suspend({ reason: "Suspension reason", otherReason: "Other reason" });
      }
    },
  });
```

### 分支結果欄位現在是選填的 {/* #branch-result-fields-are-now-optional */}

`.branch()` 現在回傳的 schema 中，所有分支輸出欄位都是選填的。這反映了執行時的行為：只有條件為真時，對應分支才會執行，因此任何分支的輸出都可能是 `undefined`。

遷移時，請更新所有使用分支輸出的程式碼，使其能處理選填值。

```diff
  const workflow = createWorkflow({...})
    .branch([
      [condition1, stepA],  // outputSchema: { result: z.string() }
      [condition2, stepB],  // outputSchema: { data: z.number() }
    ])
-   // Previously: stepA.result typed as string, stepB.data typed as number
+   // Now: stepA.result typed as string | undefined, stepB.data typed as number | undefined
    .then(nextStep);
```

如果程式碼依賴非選填型別，請在存取分支輸出時加入執行階段檢查，或提供預設值。

### `Run.start()` 與 `Run.timeTravel()` 中的 `writableStream` 改為 `outputWriter` {/* #writablestream-to-outputwriter-in-runstart--runtimetravel */}

`Run.start()` 與 `Run.timeTravel()` 中的 `writableStream` 參數已改為 `outputWriter`。現在要傳入非同步回呼函式，讓它直接接收每個 Workflow 事件資料區塊，而不是傳入 `WritableStream`。

這讓 API 更精簡：無須建立 `WritableStream` 包裝器，直接在回呼函式中處理資料區塊即可。

**範例：**將 Workflow 事件以串流方式傳送至 HTTP 回應（SSE）：

```diff
  const run = await workflow.createRun();

- const stream = new WritableStream({
-   write(chunk) {
-     response.write(`data: ${JSON.stringify(chunk)}\n\n`);
-   }
- });
- await run.start({ inputData, writableStream: stream });

+ await run.start({
+   inputData,
+   outputWriter: async (chunk) => {
+     response.write(`data: ${JSON.stringify(chunk)}\n\n`);
+   },
+ });
```

:::note

傳入步驟 `execute` 函式的 `writer` 參數不受此變更影響。它仍是擴充 `WritableStream<unknown>` 的 `ToolStream`，並提供 `.write()` 與 `.custom()` 方法：

```ts
createStep({
  id: 'my-step',
  execute: async ({ writer }) => {
    // This API is unchanged
    await writer.write({ data: 'some output' })
    await writer.custom({ type: 'custom-event', payload: {} })
  },
})
```

:::

### `setState()` 現為非同步函式，傳入的資料也會經過驗證 {/* #setstate-is-now-async-and-the-data-passed-is-validated */}

`setState()` 現在是非同步函式。啟用 `validateInputs` 時，會依照步驟的 `stateSchema` 驗證傳入資料。只要傳入想更新的欄位，無須展開先前的狀態（`...state`）。

遷移時，請以非同步方式呼叫 `setState()`。

```diff
- setState({ ...state, sharedCounter: state.sharedCounter + 1 });
+ await setState({ sharedCounter: state.sharedCounter + 1 });
+ // await setState({ ...state, sharedCounter: state.sharedCounter + 1 });
+ // this also works, as the previous state spread remains supported
```

## 已刪除 {/* #removed */}

### `streamVNext`、`resumeStreamVNext` 與 `observeStreamVNext` 方法 {/* #streamvnext-resumestreamvnext-and-observestreamvnext-methods */}

實驗性的 `streamVNext()`、`resumeStreamVNext()` 與 `observeStreamVNext()` 方法已移除。它們現在成為標準實作，事件結構與回傳型別也已更新。

遷移時，請使用標準的 `stream()`、`resumeStream()` 與 `observeStream()` 方法。請將事件型別檢查改為使用帶有 Workflow 前綴的名稱，並直接存取串流屬性。

詳情請參閱 [`Run.stream()`](/reference/streaming/workflows/stream)、[`Run.resumeStream()`](/reference/streaming/workflows/resumeStream) 與 [`Run.observeStream()`](/reference/streaming/workflows/observeStream)。


### 步驟條件函式的參數不再提供 `suspend()` 與 `setState()` {/* #suspend-and-setstate-arent-available-in-step-condition-functions-parameters */}

步驟條件函式的參數不再提供 `suspend()` 與 `setState()`。

遷移時，請改在步驟的執行函式中使用 `suspend()`。

```diff
.dowhile(step, async ({ suspend, state, setState }) => {
- setState({...state, updatedState: "updated state"})
- await suspend({ reason: "Suspension reason" });
+ // Use the suspend/setState in the step execute function instead
});
```

`dountil` 與 `branch` 的條件函式參數也一樣。

### 舊版 Workflow 匯出路徑 {/* #legacy-workflows-export */}

`@mastra/core` 中的 `./workflows/legacy` 匯出路徑已移除。舊版 Workflow 不再受支援。

遷移時，請使用新的 Workflow API。舊版 Workflow 沒有直接遷移的方式。

```diff
- import { LegacyWorkflow } from '@mastra/core/workflows/legacy';
+ // Legacy workflows are no longer supported
+ // Migrate to the new workflow API
```

### `WorkflowRunOutput` 的 `pipeThrough` 與 `pipeTo` 方法 {/* #pipethrough-and-pipeto-methods-from-workflowrunoutput */}

`WorkflowRunOutput` 的 `pipeThrough()` 與 `pipeTo()` 方法已棄用。這些方法仍可使用，但會在主控台顯示警告。

遷移時，請使用 `fullStream` 屬性，不要直接在執行結果上呼叫這些方法。

```diff
  const run = await workflow.createRun({ input: { ... } });
- await run.pipeTo(writableStream);
- const transformed = run.pipeThrough(transformStream);
+ await run.fullStream.pipeTo(writableStream);
+ const transformed = run.fullStream.pipeThrough(transformStream);
```

### watch 事件 API {/* #watch-events-api */}

舊版 watch 事件已移除，相關功能整合至 v2 事件 API。`watch()` 方法及相關 watch 端點不再可用。

遷移時，請使用 Workflow 事件 API 或串流，取代 watch 事件。

```diff
- const workflow = mastraClient.getWorkflow('my-workflow');
- const run = await workflow.createRun();
- await run.watch((event) => {
-   console.log('Step completed:', event);
- });

+ const workflow = mastraClient.getWorkflow('my-workflow');
+ const run = await workflow.createRun();
+ const stream = await run.stream({ inputData: { ... } });
+ for await (const chunk of stream) {
+   console.log('Step completed:', chunk);
+ }
```

### `waitForEvent` API {/* #waitforevent-api */}

Workflow 中的 `waitForEvent` API 已移除。請改用 suspend/resume API。

遷移時，請使用 suspend/resume API，等待 Workflow 執行至指定節點。

```diff
- workflow.waitForEvent('step-complete', step1).commit();
+ workflow.then(step1).commit();
+ // Use suspend/resume API instead, in step1 execute function
createStep({
- execute: async (inputData, context) => {
-  // ... execution logic
- }
+ execute: async (inputData, context) => {
+   if (!context.resumeData) {
+     return context.suspend({})
+   }
+ }
});
+
+ // after workflow is suspended, you can resume it
+ const result = await run.start({ inputData: { ... } });
+ if (result.status === 'suspended') {
+   const resumedResult = await run.resume({
+     resumeData: {
+       event: 'step-complete',
+     },
+     step: 'step1',
+   });
+ }
```

### `sendEvent` API {/* #sendevent-api */}

Workflow 中的 `sendEvent` API 已移除。請改用 suspend/resume API。
