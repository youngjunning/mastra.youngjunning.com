# 儲存

儲存 API 已統一規範，所有方法採用一致的分頁方式與命名規則。

## 資料庫遷移 {/* #database-migration */}

請透過慣用的遷移流程執行這些 SQL 遷移，例如使用 Prisma Migrate、Drizzle Kit，或交由 DBA 審核。

### 評分資料表欄位重新命名 {/* #scorers-table-column-rename */}

`mastra_scorers` 資料表中的 `runtimeContext` 欄位已重新命名為 `requestContext`。

:::note[誰需要執行此遷移]
只有在使用 `@mastra/pg` 或 `@mastra/libsql` 進行評估或評分，且 `runtimeContext` 欄位已有資料時，才需要執行。
:::

:::important[未執行此遷移的影響]
現有評分紀錄中的請求情境資料將無法存取。
:::

部署 v1 後，初始化程序會新增 `requestContext` 欄位。此時請複製資料，再刪除舊欄位：

```sql
UPDATE mastra_scorers SET "requestContext" = "runtimeContext" WHERE "runtimeContext" IS NOT NULL;
ALTER TABLE mastra_scorers DROP COLUMN "runtimeContext";
```

### 重複 span 遷移 {/* #duplicate-spans-migration */}

如果從舊版 Mastra 升級，`mastra_spans` 資料表中可能有重複的 `(traceId, spanId)` 紀錄。v1 會為這兩個欄位新增唯一約束，以確保資料完整性；若存在重複紀錄，就無法新增該約束。

:::note[誰需要執行此遷移]
只有在已有 Mastra v1 之前的 span 資料，並遇到重複鍵衝突或約束建立失敗的錯誤時，才需要執行。
:::

:::important[未執行此遷移的影響]
儲存初始化可能在新增唯一約束時失敗，或出現「duplicate key value violates unique constraint」等錯誤。
:::

#### 方案 1：使用 CLI（建議） {/* #option-1-use-the-cli-recommended */}

執行以下遷移指令，自動刪除重複 span 並新增約束：

```bash
npx mastra migrate
```

CLI 會先封裝專案並連線至已設定的儲存系統，再執行遷移。刪除重複紀錄時，它會根據 `endTime` 與屬性保留資訊最完整的一筆。

#### 方案 2：手動執行 SQL（PostgreSQL） {/* #option-2-manual-sql-postgresql */}

如果想手動執行遷移：

```sql
-- Remove duplicates, keeping the most complete record
DELETE FROM mastra_spans a USING mastra_spans b
WHERE a.ctid < b.ctid
  AND a."traceId" = b."traceId"
  AND a."spanId" = b."spanId";

-- Add the unique constraint
ALTER TABLE mastra_spans ADD CONSTRAINT mastra_spans_trace_span_unique UNIQUE ("traceId", "spanId");
```

#### 方案 3：手動遷移（其他資料庫） {/* #option-3-manual-migration-other-databases */}

對於 ClickHouse、LibSQL、MongoDB 或 MSSQL，請使用程式化 API：

```typescript
const storage = mastra.getStorage()
const observabilityStore = await storage.getStore('observability')

// Check if migration is needed
const status = await observabilityStore?.checkSpansMigrationStatus()
console.log(status)

// Run the migration
const result = await observabilityStore?.migrateSpans()
console.log(result)
```

### JSON 欄位（TEXT → JSONB） {/* #json-columns-text--jsonb */}

**僅適用於 PostgreSQL。**`mastra_threads` 資料表中的 `metadata` 欄位，以及 `mastra_workflow_snapshot` 資料表中的 `snapshot` 欄位，已從 TEXT 改為 JSONB。

:::note[建議]
遷移至 JSONB 後，可以使用 PostgreSQL 原生 JSON 運算子與 GIN 索引，提升 JSON 欄位的查詢效能。
:::

```sql
ALTER TABLE mastra_threads
ALTER COLUMN metadata TYPE jsonb
USING metadata::jsonb;

ALTER TABLE mastra_workflow_snapshot
ALTER COLUMN snapshot TYPE jsonb
USING snapshot::jsonb;
```

## 新增 {/* #added */}

### 使用 `MastraCompositeStore` 組合儲存系統 {/* #storage-composition-in-mastracompositestore */}

`MastraCompositeStore` 現在可以組合來自不同轉接器的儲存領域。當不同用途需要不同資料庫時，可使用此功能，例如以 PostgreSQL 儲存記憶與 Workflow 資料，並以專用資料庫儲存可觀測性資料。

```typescript
import { MastraCompositeStore } from '@mastra/core/storage'
import { MemoryPG, WorkflowsPG, ScoresPG } from '@mastra/pg'
import { MemoryLibSQL } from '@mastra/libsql'
import { Mastra } from '@mastra/core'

// Compose domains from different stores
const mastra = new Mastra({
  storage: new MastraCompositeStore({
    id: 'composite',
    domains: {
      memory: new MemoryLibSQL({ url: 'file:./local.db' }),
      workflows: new WorkflowsPG({ connectionString: process.env.DATABASE_URL }),
      scores: new ScoresPG({ connectionString: process.env.DATABASE_URL }),
    },
  }),
})
```

詳情請參閱[儲存組合參考文件](/reference/storage/composite)。

## 變更 {/* #changed */}

### `MastraStorage` 重新命名為 `MastraCompositeStore` {/* #mastrastorage-renamed-to-mastracompositestore */}

`MastraStorage` 類別已重新命名為 `MastraCompositeStore`，更準確地表明它是將不同儲存領域導向不同底層儲存系統的組合實作。這也能避免與廣義的「Mastra Storage」概念（即 Mastra 執行個體上的 `storage` 屬性）混淆。

舊名稱 `MastraStorage` 仍以已棄用的別名保留，以相容既有程式碼，但將於未來版本移除。

遷移時，請更新匯入與執行個體建立程式碼：

```diff
- import { MastraStorage } from "@mastra/core/storage";
+ import { MastraCompositeStore } from "@mastra/core/storage";
  import { MemoryLibSQL } from "@mastra/libsql";
  import { WorkflowsPG } from "@mastra/pg";

  export const mastra = new Mastra({
-   storage: new MastraStorage({
+   storage: new MastraCompositeStore({
      id: "composite",
      domains: {
        memory: new MemoryLibSQL({ url: "file:./memory.db" }),
        workflows: new WorkflowsPG({ connectionString: process.env.DATABASE_URL }),
      },
    }),
  });
```

:::note
如果直接使用單一儲存實作（例如 `PostgresStore` 或 `LibSQLStore`），請保留現有設定。此變更只影響明確使用 `MastraStorage` 組合儲存系統的程式碼。
:::

### 儲存執行個體必須提供 `id` 屬性 {/* #required-id-property-for-storage-instances */}

儲存執行個體現在必須提供 `id` 屬性。Mastra 使用這個唯一識別碼追蹤及管理儲存執行個體。應為應用程式中的每個儲存執行個體指定具描述性且唯一的 `id` 字串。

遷移時，請在儲存建構函式中新增 `id` 欄位。

```diff
  const storage = new PostgresStore({
+   id: 'main-postgres-store',
    connectionString: process.env.POSTGRES_CONNECTION_STRING,
    schemaName: 'public',
  });

  const upstashStore = new UpstashStore({
+   id: 'upstash-cache-store',
    url: process.env.UPSTASH_REDIS_REST_URL,
    token: process.env.UPSTASH_REDIS_REST_TOKEN,
  });
```

### 分頁參數從 `offset/limit` 改為 `page/perPage` {/* #pagination-from-offsetlimit-to-pageperpage */}

所有分頁 API 現在都使用 `page` 與 `perPage`，取代 `offset` 與 `limit`，與依頁碼分頁的網頁方式一致。

遷移時，請將所有分頁參數從 `offset/limit` 改為 `page/perPage`。請注意，`page` 從 0 開始計數。

```diff
  memoryStore.listMessages({
    threadId: 'thread-123',
-   offset: 0,
-   limit: 20,
+   page: 0,
+   perPage: 20,
  });
```

### `getMessagesPaginated` 改為 `listMessages` {/* #getmessagespaginated-to-listmessages */}

`getMessagesPaginated()` 已由 `listMessages()` 取代。新方法支援使用 `perPage: false` 擷取所有紀錄，不進行分頁。此變更遵循 `list*` 命名慣例，也讓擷取所有紀錄更有彈性。

遷移時，請更改方法名稱並更新分頁參數。現在可以使用 `perPage: false` 擷取所有紀錄。

```diff
+ const memoryStore = await storage.getStore('memory');
+
  // Paginated
- const result = await storage.getMessagesPaginated({
+ const result = await memoryStore?.listMessages({
    threadId: 'thread-123',
-   offset: 0,
-   limit: 20,
+   page: 0,
+   perPage: 20,
  });

  // Fetch all records (no pagination limit)
+ const allMessages = await memoryStore?.listMessages({
+   threadId: 'thread-123',
+   page: 0,
+   perPage: false,
+ });
```

### 透過 `getStore()` 存取特定儲存領域 {/* #domain-specific-storage-access-via-getstore */}

現在必須透過對應儲存領域的 store 執行儲存操作，而非直接在儲存執行個體上呼叫。

儲存領域包括：

- **`memory`** - 對話執行緒、訊息與資源
- **`workflows`** - Workflow 快照
- **`scores`** - 評估分數
- **`observability`** - trace 與 span
- **`agents`** - 已儲存的 Agent 資料

遷移時，請將儲存領域名稱傳入 `getStore()`，再呼叫傳回的 store 上的方法。

```diff
  const storage = mastra.getStorage();

  // Memory operations (threads, messages, resources)
- const thread = await storage.getThread({ threadId: '123' });
- await storage.saveThread({ thread });
+ const memoryStore = await storage.getStore('memory');
+ const thread = await memoryStore?.getThreadById({ threadId: '123' });
+ await memoryStore?.saveThread({ thread });

  // Workflow operations (snapshots)
- const snapshot = await storage.loadWorkflowSnapshot({ runId, workflowName });
- await storage.persistWorkflowSnapshot({ runId, workflowName, snapshot });
+ const workflowStore = await storage.getStore('workflows');
+ const snapshot = await workflowStore?.loadWorkflowSnapshot({ runId, workflowName });
+ await workflowStore?.persistWorkflowSnapshot({ runId, workflowName, snapshot });

  // Observability operations (traces, spans)
- const traces = await storage.listTraces({ page: 0, perPage: 20 });
+ const observabilityStore = await storage.getStore('observability');
+ const traces = await observabilityStore?.listTraces({ page: 0, perPage: 20 });

  // Score operations (evaluations)
- const scores = await storage.listScoresByScorerId({ scorerId: 'helpfulness' });
+ const scoresStore = await storage.getStore('scores');
+ const scores = await scoresStore?.listScoresByScorerId({ scorerId: 'helpfulness' });
```

### `getThreadsByResourceId` 改為 `listThreads` {/* #getthreadsbyresourceid-to-listthreads */}

`getThreadsByResourceId()` 已由 `listThreads()` 取代。新方法支援分頁，也能依 `resourceId`、`metadata` 或兩者組合篩選。

:::important

舊方法 `getThreadsByResourceId()` 會傳回所有符合條件的對話執行緒，不進行分頁。新方法 `listThreads()` 需要分頁參數。若要像以前一樣擷取所有對話執行緒，請使用 `perPage: false`。

:::

遷移時，請透過 memory store 呼叫新的 `listThreads()` 方法，並傳入分頁參數及選用的篩選物件。

```diff
- const threads = await storage.getThreadsByResourceId({
-   resourceId: 'res-123',
- });
+ const memoryStore = await storage.getStore('memory');
+
+ // Paginated (recommended for large datasets)
+ const result = await memoryStore?.listThreads({
+   filter: { resourceId: 'res-123' },
+   page: 0,
+   perPage: 20,
+ });
+ const threads = result?.threads;
+
+ // Or fetch all threads like before (use perPage: false)
+ const allResult = await memoryStore?.listThreads({
+   filter: { resourceId: 'res-123' },
+   perPage: false,
+ });
+ const allThreads = allResult?.threads;
```

新方法也支援：

- 列出所有對話執行緒（省略篩選條件）
- 僅依中繼資料篩選
- 組合使用 `resourceId` 與中繼資料篩選

```typescript
// List all threads
await memoryStore?.listThreads({ page: 0, perPage: 20 })

// Filter by metadata only
await memoryStore?.listThreads({
  filter: { metadata: { status: 'active' } },
  page: 0,
  perPage: 20,
})

// Combined filter
await memoryStore?.listThreads({
  filter: {
    resourceId: 'user-123',
    metadata: { category: 'support' },
  },
  page: 0,
  perPage: 20,
})
```

### 儲存方法 `getMessages` 與 `saveMessages` 的簽章變更 {/* #storage-getmessages-and-savemessages-signatures */}

`getMessages()` 與 `saveMessages()` 的方法簽章及傳回型別已變更。格式多載已移除，這兩個方法現在一律使用 `MastraDBMessage`。移除不同格式的處理方式後，API 更加簡潔。

遷移時，請使用 memory store、移除格式參數，並調整程式碼以處理一致的傳回型別。

```diff
+ const memoryStore = await storage.getStore('memory');
+
  // Always returns { messages: MastraDBMessage[] }
- const v1Messages = await storage.getMessages({ threadId, format: 'v1' });
- const v2Messages = await storage.getMessages({ threadId, format: 'v2' });
+ const result = await memoryStore?.getMessages({ threadId });
+ const messages = result?.messages; // MastraDBMessage[]

  // SaveMessages always uses MastraDBMessage
- await storage.saveMessages({ messages: v1Messages, format: 'v1' });
- await storage.saveMessages({ messages: v2Messages, format: 'v2' });
+ const saveResult = await memoryStore?.saveMessages({ messages: mastraDBMessages });
+ const saved = saveResult?.messages; // MastraDBMessage[]
```

### 向量儲存 API 從位置參數改為具名參數物件 {/* #vector-store-api-from-positional-arguments-to-arguments-by-name */}

所有向量儲存方法現在都使用參數物件，取代位置參數。如此一來，呼叫處便能清楚顯示每個值的用途，方法簽章也能在不依賴參數順序的情況下演進。

遷移時，請將所有向量儲存方法呼叫改為傳入參數物件。

```diff
- await vectorDB.createIndex(indexName, 3, 'cosine');
+ await vectorDB.createIndex({
+   indexName: indexName,
+   dimension: 3,
+   metric: 'cosine',
+ });

- await vectorDB.upsert(indexName, [[1, 2, 3]], [{ test: 'data' }]);
+ await vectorDB.upsert({
+   indexName: indexName,
+   vectors: [[1, 2, 3]],
+   metadata: [{ test: 'data' }],
+ });

- await vectorDB.query(indexName, [1, 2, 3], 5);
+ await vectorDB.query({
+   indexName: indexName,
+   queryVector: [1, 2, 3],
+   topK: 5,
+ });
```

```diff
- await vectorDB.updateIndexById(indexName, id, update);
```

## 移除 {/* #removed */}

### 不分頁的儲存函式 {/* #non-paginated-storage-functions */}

不分頁的儲存函式已移除，改用支援分頁的版本。所有清單操作現在都採用分頁方式，但仍可透過 `perPage: false` 擷取所有紀錄。分頁讓整個 API 的清單操作保持一致，也能避免意外載入大量資料。

遷移時，請透過對應儲存領域的 store 呼叫分頁方法。如需擷取所有紀錄，請使用 `perPage: false`。

```diff
- // Non-paginated direct access
- const messages = await storage.getMessages({ threadId });

+ // Use paginated methods via domain stores
+ const memoryStore = await storage.getStore('memory');
+ const result = await memoryStore?.listMessages({ threadId, page: 0, perPage: 20 });
+ // Or fetch all
+ const allMessages = await memoryStore?.listMessages({
+   threadId,
+   page: 0,
+   perPage: false,
+ });
```

### `getTraces` 與 `getTracesPaginated` {/* #gettraces-and-gettracespaginated */}

儲存系統中的 `getTraces()` 與 `getTracesPaginated()` 方法已移除。請透過可觀測性套件存取 trace，而非透過核心儲存系統存取。

遷移時，請改用可觀測性儲存方法。

```diff
- const traces = await storage.getTraces({ traceId: 'trace-123' });
- const paginated = await storage.getTracesPaginated({ page: 0, perPage: 20 });

+ // Use observability API for traces
+ import { initObservability } from '@mastra/observability';
+ const observability = initObservability({ config: { ... } });
+ // Access traces through observability API
```

### Evals 測試工具 {/* #evals-test-utilities */}

Evals 儲存領域的測試工具已從 `@internal/test-utils` 移除。這反映了舊版 evals 功能的移除。

遷移時，請直接使用儲存 API 進行測試，不再使用專門的 Evals 測試工具。

```diff
- import { createEvalsTests } from '@internal/test-utils/domains/evals';
- createEvalsTests({ storage });
```

### 從 MSSQL 儲存系統移除 TABLE\_EVALS {/* #table_evals-from-mssql-storage */}

MSSQL 儲存實作中的 `TABLE_EVALS` 資料表已移除。這反映了舊版 evals 功能的移除。

如果使用 MSSQL 儲存系統執行 evals，請遷移至其他儲存轉接器，或移除 evals 功能。
