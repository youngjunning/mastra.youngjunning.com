# 貯存

儲存 API 已經標準化，所有方法都具有一致的分頁和命名模式。

## 資料庫遷移 {/* #database-migration */}

透過正常遷移流程（例如 Prisma Migrate、Drizzle Kit 或 DBA 審核流程）來執行這些 SQL 遷移。

### 記分錶列重命名 {/* #scorers-table-column-rename */}

這`runtimeContext` column in `mastra_scorers` was renamed to `requestContext`.

:::注意\[誰需要此遷移]
僅當您使用`@mastra/pg` or `@mastra/libsql` with evals/scoring and have existing data in the `runtimeContext` column.
:::

:::重要\[沒有它會破壞什麼]
現有分數記錄的請求上下文資料將無法存取。
:::

部署 v1 後（新增了新的`requestContext` column on init), copy the data and drop the old column:

```sql
UPDATE mastra_scorers SET "requestContext" = "runtimeContext" WHERE "runtimeContext" IS NOT NULL;
ALTER TABLE mastra_scorers DROP COLUMN "runtimeContext";
```

### 重複跨度遷移 {/* #duplicate-spans-migration */}

`(traceId, spanId)` entries in your `mastra_spans` table. V1 adds a unique constraint on these columns to ensure data integrity, but this constraint can't be added if duplicates exist.

:::注意\[誰需要此遷移]
仅当您拥有 v1 之前的 Mastra 版本的现有跨度数据并且遇到有关重复键违规或约束创建失败的错误时。
:::

:::重要\[沒有它會破壞什麼]
嘗試新增唯一約束時，儲存初始化可能會失敗，或者您可能會看到「重複鍵值違反唯一約束」之類的錯誤。
:::

#### 選項 1：使用 CLI（建議） {/* #option-1-use-the-cli-recommended */}

執行遷移命令，該命令會自動對跨度進行重複資料刪除並新增約束：

```bash
npx mastra migrate
```

CLI 会捆绑您的项目并在运行迁移之前连接到您配置的存储。它保留了最完整的記錄（基於`endTime` and attributes) when removing duplicates.

#### 選項 2：手動 SQL (PostgreSQL) {/* #option-2-manual-sql-postgresql */}

如果您喜歡手動運行遷移：

```sql
-- Remove duplicates, keeping the most complete record
DELETE FROM mastra_spans a USING mastra_spans b
WHERE a.ctid < b.ctid
  AND a."traceId" = b."traceId"
  AND a."spanId" = b."spanId";

-- Add the unique constraint
ALTER TABLE mastra_spans ADD CONSTRAINT mastra_spans_trace_span_unique UNIQUE ("traceId", "spanId");
```

#### 選項 3：手動遷移（其他資料庫） {/* #option-3-manual-migration-other-databases */}

對於 ClickHouse、LibSQL、MongoDB 或 MSSQL，請使用程式設計 API：

```typescript
const storage = mastra.getStorage()
const observabilityStore = await storage.getStore('observability')

// Check if migration is needed
const status = await observabilityStore?.checkSpansMigrationStatus()
console.log(status)

// Run the migration
const result = await observabilityStore?.migrateSpans()
console.log(result)
```

### JSON 欄位（TEXT → JSONB） {/* #json-columns-text--jsonb */}

**僅限 PostgreSQL。**&#x9019;`metadata` column in `mastra_threads` and `snapshot` column in `mastra_workflow_snapshot` changed from TEXT to JSONB.

:::注意\[建議]
移轉到 JSONB 可啟用本機 PostgreSQL JSON 運算子和 GIN 索引，以提高 JSON 欄位的查詢效能。
:::

```sql
ALTER TABLE mastra_threads
ALTER COLUMN metadata TYPE jsonb
USING metadata::jsonb;

ALTER TABLE mastra_workflow_snapshot
ALTER COLUMN snapshot TYPE jsonb
USING snapshot::jsonb;
```

## 額外 {/* #added */}

### 儲存組成`MastraCompositeStore` {/* #storage-composition-in-mastracompositestore */}

`MastraCompositeStore`現在可以從不同的適配器組成儲存域。當不同的目的需要不同的資料庫時使用它，例如用於記憶體的 PostgreSQL 和具有專門資料庫的Workflow用於可觀察性。

```typescript
import { MastraCompositeStore } from '@mastra/core/storage'
import { MemoryPG, WorkflowsPG, ScoresPG } from '@mastra/pg'
import { MemoryLibSQL } from '@mastra/libsql'
import { Mastra } from '@mastra/core'

// Compose domains from different stores
const mastra = new Mastra({
  storage: new MastraCompositeStore({
    id: 'composite',
    domains: {
      memory: new MemoryLibSQL({ url: 'file:./local.db' }),
      workflows: new WorkflowsPG({ connectionString: process.env.DATABASE_URL }),
      scores: new ScoresPG({ connectionString: process.env.DATABASE_URL }),
    },
  }),
})
```

請參閱[Storage Composition reference](/reference/storage/composite) for more details.

## 改變了 {/* #changed */}

### `MastraStorage`重新命名為`MastraCompositeStore` {/* #mastrastorage-renamed-to-mastracompositestore */}

這`MastraStorage` class has been renamed to `MastraCompositeStore` to better reflect its role as a composite storage implementation that routes different domains to different underlying stores. This avoids confusion with the general "Mastra Storage" concept (the `storage` property on the Mastra instance).

舊的`MastraStorage` name remains available as a deprecated alias for backward compatibility, but will be removed in a future version.

若要遷移，請更新您的匯入和實例化：

```diff
- import { MastraStorage } from "@mastra/core/storage";
+ import { MastraCompositeStore } from "@mastra/core/storage";
  import { MemoryLibSQL } from "@mastra/libsql";
  import { WorkflowsPG } from "@mastra/pg";

  export const mastra = new Mastra({
-   storage: new MastraStorage({
+   storage: new MastraCompositeStore({
      id: "composite",
      domains: {
        memory: new MemoryLibSQL({ url: "file:./memory.db" }),
        workflows: new WorkflowsPG({ connectionString: process.env.DATABASE_URL }),
      },
    }),
  });
```

:::注意
如果您使用單一商店實現（例如`PostgresStore` or `LibSQLStore`) directly, keep the existing configuration. This only affects code that explicitly uses `MastraStorage` for composite storage.
:::

### 必需的`id` property for storage instances {/* #required-id-property-for-storage-instances */}

`id` property. This unique identifier is used for tracking and managing storage instances within Mastra. The `id` should be a descriptive, unique string for each storage instance in your application.

若要遷移，請新增`id` field to your storage constructor.

```diff
  const storage = new PostgresStore({
+   id: 'main-postgres-store',
    connectionString: process.env.POSTGRES_CONNECTION_STRING,
    schemaName: 'public',
  });

  const upstashStore = new UpstashStore({
+   id: 'upstash-cache-store',
    url: process.env.UPSTASH_REDIS_REST_URL,
    token: process.env.UPSTASH_REDIS_REST_TOKEN,
  });
```

### 分頁來自`offset/limit` to `page/perPage` {/* #pagination-from-offsetlimit-to-pageperpage */}

所有分頁 API 現在都使用`page` and `perPage` instead of `offset` and `limit`, matching page-based web pagination.

若要遷移，請更新所有分頁參數`offset/limit` to `page/perPage`. Note that `page` is 0-indexed.

```diff
  memoryStore.listMessages({
    threadId: 'thread-123',
-   offset: 0,
-   limit: 20,
+   page: 0,
+   perPage: 20,
  });
```

### `getMessagesPaginated`到`listMessages` {/* #getmessagespaginated-to-listmessages */}

這`getMessagesPaginated()` method has been replaced with `listMessages()`. The new method supports `perPage: false` to fetch all records without pagination. This change aligns with the `list*` naming convention and adds flexibility for fetching all records.

若要遷移，請重新命名該方法並更新分頁參數。您現在可以使用`perPage: false` to fetch all records.

```diff
+ const memoryStore = await storage.getStore('memory');
+
  // Paginated
- const result = await storage.getMessagesPaginated({
+ const result = await memoryStore?.listMessages({
    threadId: 'thread-123',
-   offset: 0,
-   limit: 20,
+   page: 0,
+   perPage: 20,
  });

  // Fetch all records (no pagination limit)
+ const allMessages = await memoryStore?.listMessages({
+   threadId: 'thread-123',
+   page: 0,
+   perPage: false,
+ });
```

### 域特定的儲存存取透過`getStore()` {/* #domain-specific-storage-access-via-getstore */}

現在可以透過特定於網域的儲存來存取儲存操作，而不是直接在儲存實例上存取。

域包括：

* **`memory`**- 線程、訊息和資源
* **`workflows`**- Workflow快照
* **`scores`**- 評估分數
* **`observability`**- 痕跡和跨度
* **`agents`**- 儲存的Agent數據

如需遷移，請致電`getStore()` with the domain name, then call methods on the returned store.

```diff
  const storage = mastra.getStorage();

  // Memory operations (threads, messages, resources)
- const thread = await storage.getThread({ threadId: '123' });
- await storage.saveThread({ thread });
+ const memoryStore = await storage.getStore('memory');
+ const thread = await memoryStore?.getThreadById({ threadId: '123' });
+ await memoryStore?.saveThread({ thread });

  // Workflow operations (snapshots)
- const snapshot = await storage.loadWorkflowSnapshot({ runId, workflowName });
- await storage.persistWorkflowSnapshot({ runId, workflowName, snapshot });
+ const workflowStore = await storage.getStore('workflows');
+ const snapshot = await workflowStore?.loadWorkflowSnapshot({ runId, workflowName });
+ await workflowStore?.persistWorkflowSnapshot({ runId, workflowName, snapshot });

  // Observability operations (traces, spans)
- const traces = await storage.listTraces({ page: 0, perPage: 20 });
+ const observabilityStore = await storage.getStore('observability');
+ const traces = await observabilityStore?.listTraces({ page: 0, perPage: 20 });

  // Score operations (evaluations)
- const scores = await storage.listScoresByScorerId({ scorerId: 'helpfulness' });
+ const scoresStore = await storage.getStore('scores');
+ const scores = await scoresStore?.listScoresByScorerId({ scorerId: 'helpfulness' });
```

### `getThreadsByResourceId`到`listThreads` {/* #getthreadsbyresourceid-to-listthreads */}

這`getThreadsByResourceId()` method has been replaced with `listThreads()`. The new method adds pagination support and filtering by `resourceId`, `metadata`, or both.

：：：重要的

舊的`getThreadsByResourceId()` returned all matching threads without pagination. The new `listThreads()` requires pagination parameters. To preserve the old behavior of fetching all threads, use `perPage: false`.

:::

`listThreads()` method with pagination and an optional filter object.

```diff
- const threads = await storage.getThreadsByResourceId({
-   resourceId: 'res-123',
- });
+ const memoryStore = await storage.getStore('memory');
+
+ // Paginated (recommended for large datasets)
+ const result = await memoryStore?.listThreads({
+   filter: { resourceId: 'res-123' },
+   page: 0,
+   perPage: 20,
+ });
+ const threads = result?.threads;
+
+ // Or fetch all threads like before (use perPage: false)
+ const allResult = await memoryStore?.listThreads({
+   filter: { resourceId: 'res-123' },
+   perPage: false,
+ });
+ const allThreads = allResult?.threads;
```

新方法也支援：

* 列出所有線程（省略過濾器）
* 僅按元資料過濾
* 組合的resourceId +元資料過濾器

```typescript
// List all threads
await memoryStore?.listThreads({ page: 0, perPage: 20 })

// Filter by metadata only
await memoryStore?.listThreads({
  filter: { metadata: { status: 'active' } },
  page: 0,
  perPage: 20,
})

// Combined filter
await memoryStore?.listThreads({
  filter: {
    resourceId: 'user-123',
    metadata: { category: 'support' },
  },
  page: 0,
  perPage: 20,
})
```

您可以使用 Mastra 的 codemod CLI 自動更新您的程式碼：

```bash

```

### 貯存`getMessages` and `saveMessages` signatures {/* #storage-getmessages-and-savemessages-signatures */}

這`getMessages()` and `saveMessages()` methods have changed signatures and return types. Format overloads have been removed, and the methods now always work with `MastraDBMessage`. This change simplifies the API by removing format variations.

若要遷移，請使用記憶體儲存、刪除格式參數並更新程式碼以使用一致的傳回類型。

```diff
+ const memoryStore = await storage.getStore('memory');
+
  // Always returns { messages: MastraDBMessage[] }
- const v1Messages = await storage.getMessages({ threadId, format: 'v1' });
- const v2Messages = await storage.getMessages({ threadId, format: 'v2' });
+ const result = await memoryStore?.getMessages({ threadId });
+ const messages = result?.messages; // MastraDBMessage[]

  // SaveMessages always uses MastraDBMessage
- await storage.saveMessages({ messages: v1Messages, format: 'v1' });
- await storage.saveMessages({ messages: v2Messages, format: 'v2' });
+ const saveResult = await memoryStore?.saveMessages({ messages: mastraDBMessages });
+ const saved = saveResult?.messages; // MastraDBMessage[]
```

### 從位置參數到按名稱參數的向量儲存 API {/* #vector-store-api-from-positional-arguments-to-arguments-by-name */}

所有向量存儲方法現在都使用參數物件而不是位置參數。這使得每個值的用途在呼叫站點可見，並讓方法簽名在不依賴參數順序的情況下發展。

若要遷移，請更新所有向量儲存方法呼叫以使用參數物件。

```diff
- await vectorDB.createIndex(indexName, 3, 'cosine');
+ await vectorDB.createIndex({
+   indexName: indexName,
+   dimension: 3,
+   metric: 'cosine',
+ });

- await vectorDB.upsert(indexName, [[1, 2, 3]], [{ test: 'data' }]);
+ await vectorDB.upsert({
+   indexName: indexName,
+   vectors: [[1, 2, 3]],
+   metadata: [{ test: 'data' }],
+ });

- await vectorDB.query(indexName, [1, 2, 3], 5);
+ await vectorDB.query({
+   indexName: indexName,
+   queryVector: [1, 2, 3],
+   topK: 5,
+ });
```

### 向量儲存方法重新命名 {/* #vector-store-method-renames */}

## 已刪除 {/* #removed */}

### 非分頁儲存函數 {/* #non-paginated-storage-functions */}

非分頁儲存功能已被刪除，以支援分頁版本。所有清單操作現在都使用分頁，儘管您可以使用以下命令來取得所有記錄`perPage: false`. Pagination aligns list operations across the API and prevents accidental loading of large datasets.

若要遷移，請透過網域儲存使用分頁方法。若要取得所有記錄，請使用`perPage: false`.

```diff
- // Non-paginated direct access
- const messages = await storage.getMessages({ threadId });

+ // Use paginated methods via domain stores
+ const memoryStore = await storage.getStore('memory');
+ const result = await memoryStore?.listMessages({ threadId, page: 0, perPage: 20 });
+ // Or fetch all
+ const allMessages = await memoryStore?.listMessages({
+   threadId,
+   page: 0,
+   perPage: false,
+ });
```

### `getTraces`和`getTracesPaginated` {/* #gettraces-and-gettracespaginated */}

這`getTraces()` and `getTracesPaginated()` methods have been removed from storage. Use the observability package to access traces instead of core storage.

要遷移，請改用可觀察性儲存方法。

```diff
- const traces = await storage.getTraces({ traceId: 'trace-123' });
- const paginated = await storage.getTracesPaginated({ page: 0, perPage: 20 });

+ // Use observability API for traces
+ import { initObservability } from '@mastra/observability';
+ const observability = initObservability({ config: { ... } });

```

### 來自 MSSQL 儲存的 TABLE\_EVALS {/* #table_evals-from-mssql-storage */}
