# 升級到 Mastra v1

:::note[先更新至最新的 0.x 版本]
升級至 v1 前，請確認 Mastra 已更新至最新的 0.x 版本。請先依照[升級至最新 0.x 版本指南](https://mastra.ai/guides/v0/migrations/upgrade-to-latest-0x)操作，再回到此處完成 v1 遷移。
:::

Mastra v1 於 2026 年 1 月發布。我們建議新專案使用 Mastra v1，現有專案則升級至 v1，以持續取得更新與支援。

本指南說明從 Mastra 0.x 升級至 v1.0 時的破壞性變更，並依套件及功能領域整理遷移步驟，協助您有系統地更新程式碼庫。

:::tip[需要協助嗎？]
遷移時有疑問？歡迎加入我們的 [Discord 社群](https://discord.gg/mastra-ai)提問。
:::

:::warning[從 Mastra Cloud 遷移？]
舊版 Mastra Cloud 產品已由 [Mastra 平台](/docs/mastra-platform/overview)取代。新平台將託管功能分為兩項獨立產品：**Studio**（視覺化環境與可觀測性）及 **Server**（正式環境 API）。舊版 Mastra Cloud 的存取權杖無法用於 Mastra 平台，請使用 `mastra auth tokens create` 建立新權杖。

如果只升級至 v1 套件，卻未將 `telemetry:` 設定遷移為 `observability:` 並建立 Studio 專案，可觀測性資料將停止傳送。請完整依照 [Mastra Cloud 遷移指南](/reference/migrations/mastra-cloud)操作。
:::

## 遷移策略 {/* #migration-strategy */}

### 將所有 Mastra 套件更新至 `latest` 標籤 {/* #update-all-mastra-packages-to-latest-tag */}

使用套件管理工具更新專案相依套件。請**同時更新所有** Mastra 套件（包括所有 `@mastra/*` 套件及 `mastra`），以確保版本相容。

以下是更新最常用軟體包的方法：

```bash npm2yarn
npm install @mastra/core@latest @mastra/loggers@latest @mastra/memory@latest mastra@latest
```

安裝其他 Mastra 套件時也使用 `@latest` 標籤，即可取得其最新的可用 v1 版本。請務必更新所有 Mastra 套件，尤其是在 monorepo 中，以免版本不一致。

### 更新 Node.js 版本 {/* #update-nodejs-version */}

Mastra v1 要求 Node.js 版本為 **22.13.0** 或以上。請一併更新開發環境與正式環境。

### 完成遷移清單 {/* #go-through-migration-checklist */}

請依照下方的[遷移清單](#migration-checklist)更新程式碼庫。每個項目都連結至對應變更的詳細指南。

:::note[Codemod]

我們提供了自動化 [codemod](https://github.com/mastra-ai/mastra/tree/main/packages/codemod)。您可以選擇一次執行所有 v1 codemod：

```bash
npx @mastra/codemod@latest v1
```

:::

:::note[需要遷移資料庫]

如果使用 PostgreSQL 或 LibSQL 儲存，您需要執行資料庫遷移。詳情請參閱[儲存遷移指南](/reference/migrations/upgrade-to-v1/storage#database-migration)。

:::

## 各領域的破壞性變更 {/* #breaking-changes-by-area */}

- **[Mastra 類別](/reference/migrations/upgrade-to-v1/mastra)** — 調整匯入路徑與屬性存取方式。
- **[Agent 類別](/reference/migrations/upgrade-to-v1/agent)** — 將語音方法移至命名空間，並更新串流 API。
- **[Tool](/reference/migrations/upgrade-to-v1/tools)** — `createTool` 的執行函式簽章改為分別接收輸入與上下文。
- **[Workflow](/reference/migrations/upgrade-to-v1/workflows)** — 變更函式名稱並移除舊功能。
- **[記憶體](/reference/migrations/upgrade-to-v1/memory)** — 設定現在需要明確指定參數，預設值也已變更。
- **[儲存](/reference/migrations/upgrade-to-v1/storage)** — 統一分頁方式，並將方法重新命名為 `list*` 模式。
- **[向量](/reference/migrations/upgrade-to-v1/vectors)** — 將向量儲存方法重新命名為 `list*` 模式。
- **[RAG](/reference/migrations/upgrade-to-v1/rag)** — 調整參數名稱，使其意義更清楚。
- **[MCP](/reference/migrations/upgrade-to-v1/mcp)** — 調整 Tool 上下文結構，並移除已棄用的用戶端類別。
- **[追蹤](/reference/migrations/upgrade-to-v1/tracing)** — 以專用的可觀測性套件與匯出器取代 OTEL 遙測。
- **[評估與評分器](/reference/migrations/upgrade-to-v1/evals)** — 整合評分器 API，並採用新的命名慣例。
- **[CLI](/reference/migrations/upgrade-to-v1/cli)** — 移除部分指令與旗標，簡化介面。
- **[部署](/reference/migrations/upgrade-to-v1/deployment)** — 更新 CloudflareDeployer 設定，改用標準的 wrangler.json 屬性名稱。
- **[用戶端 SDK](/reference/migrations/upgrade-to-v1/client)** — 重新命名型別與工具函式，維持命名一致。
- **[語音套件](/reference/migrations/upgrade-to-v1/voice)** — 將套件名稱中的 `speech` 改為 `voice`。

## 遷移清單 {/* #migration-checklist */}

請依序完成清單，先處理影響多數應用程式的變更。

:::note[Codemod]

我們提供了自動化 [codemod](https://github.com/mastra-ai/mastra/tree/main/packages/codemod)。本遷移指南會說明如何針對各項變更使用它們。

您也可以選擇一次執行所有 v1 codemod：

```bash
npx @mastra/codemod@latest v1
```

:::

### 高影響變更 {/* #high-impact-changes */}

- 將 `createTool` 的 Tool 函式簽章更新為 `(inputData, context)` 格式 — [Tool](/reference/migrations/upgrade-to-v1/tools)
- 將 `@mastra/core` 的匯入改為子路徑匯入 — [Mastra 類別](/reference/migrations/upgrade-to-v1/mastra)
- 將分頁參數從 `offset/limit` 更新為 `page/perPage` — [儲存](/reference/migrations/upgrade-to-v1/storage)
- 安裝 `@mastra/observability`，並使用 `new Observability()` 包裝設定 — [追蹤](/reference/migrations/upgrade-to-v1/tracing)
- 如果從 0.x OTEL 升級，請將 `telemetry:` 設定遷移為 `observability:` — [追蹤](/reference/migrations/upgrade-to-v1/tracing)

### 中等影響變更 {/* #medium-impact-changes */}

- 將整個程式碼庫中的 `RuntimeContext` 重新命名為 `RequestContext` — [Agent 類別](/reference/migrations/upgrade-to-v1/agent)、[Tool](/reference/migrations/upgrade-to-v1/tools)、[Workflow](/reference/migrations/upgrade-to-v1/workflows)
- 將儲存方法從 `get*` 模式改為 `list*` 模式 — [儲存](/reference/migrations/upgrade-to-v1/storage)
- 以 getter 方法取代直接存取屬性 — [Mastra 類別](/reference/migrations/upgrade-to-v1/mastra)、[Agent 類別](/reference/migrations/upgrade-to-v1/agent)
- 如果仰賴預設的 `thread` 作用域，請更新記憶體作用域設定 — [記憶體](/reference/migrations/upgrade-to-v1/memory)
- 更新向量儲存呼叫方式，改用具名參數 — [儲存](/reference/migrations/upgrade-to-v1/storage)
- 從 Agent 方法移除 `format` 參數 — [Agent 類別](/reference/migrations/upgrade-to-v1/agent)
- 改由 `agent.voice` 命名空間呼叫語音方法 — [Agent 類別](/reference/migrations/upgrade-to-v1/agent)
- 如果使用自訂處理器，將設定屬性 `processors` 重新命名為 `spanOutputProcessors` — [追蹤](/reference/migrations/upgrade-to-v1/tracing)

### 低影響變更 {/* #low-impact-changes */}

- 在文字分塊選項中，將 `keepSeparator` 重新命名為 `separatorPosition` — [RAG](/reference/migrations/upgrade-to-v1/rag)
- 將 `createRunAsync` 重新命名為 `createRun` — [Workflow](/reference/migrations/upgrade-to-v1/workflows)
- 將語音套件名稱從 `@mastra/speech-*` 更新為 `@mastra/voice-*` — [語音套件](/reference/migrations/upgrade-to-v1/voice)
- 更新評分器方法：`runExperiment` → `runEvals`，`getScorerByName` → `getScorerById` — [評估與評分器](/reference/migrations/upgrade-to-v1/evals)
- 移除已棄用的 CLI 旗標 — [CLI](/reference/migrations/upgrade-to-v1/cli)
- 將用戶端 SDK 型別從 `Get*` 更新為 `List*` — [用戶端 SDK](/reference/migrations/upgrade-to-v1/client)
- 以 `retryCount` 取代 `runCount` — [Workflow](/reference/migrations/upgrade-to-v1/workflows)
- 如果使用自訂匯出器，將其 `exportEvent` 方法更新為 `exportTracingEvent` — [追蹤](/reference/migrations/upgrade-to-v1/tracing)
