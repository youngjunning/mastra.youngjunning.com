# 記憶

記憶設定中的部分參數現在必須明確指定；預設值也已更新，以提升效能與可預測性。

## 變更 {/* #changed */}

### 語意召回與最近訊息的預設值 {/* #default-settings-for-semantic-recall-and-last-messages */}

預設值已依使用情況調整得更合理。`lastMessages` 的預設值從 40 降至 10；`semanticRecall` 與對話執行緒標題產生功能現在預設停用。這些變更可提升效能，並減少非預期的 LLM API 呼叫。

若原本依賴舊的預設值，遷移時請明確設定這些選項。

```diff
  const memory = new Memory({
    storage,
    vector,
    embedder,
+   options: {
+     lastMessages: 40, // Was default before
+     semanticRecall: {
+       topK: 2,
+       messageRange: 2,
+       scope: 'thread',
+     }, // Was enabled by default before
+     generateTitle: true, // Was enabled by default before
+   },
  });
```

### 預設記憶範圍從 `thread` 改為 `resource` {/* #default-memory-scope-from-thread-to-resource */}

工作記憶與語意召回的預設範圍均從 `'thread'` 改為 `'resource'`。這符合應用程式需要跨對話記住使用者資訊的常見情境。啟用語意召回後，預設會搜尋該使用者的所有對話，而非只搜尋目前的對話執行緒。

若要保留依對話執行緒隔離記憶的舊行為，遷移時請明確設定 `scope: 'thread'`。

```diff
  const memory = new Memory({
    storage,
    vector,
    embedder,
    options: {
      workingMemory: {
        enabled: true,
+       scope: 'thread', // Explicitly set to thread-scoped
        template: `# User Profile...`,
      },
      semanticRecall: {
        topK: 3,
+       scope: 'thread', // Explicitly set to thread-scoped
      },
    },
  });
```

### 對話執行緒標題產生選項的位置 {/* #thread-title-generation-location */}

`generateTitle` 已從 `threads.generateTitle` 移至記憶選項的頂層。將此選項放在對應的設定層級後，API 也更簡潔。

遷移時，請將 `generateTitle` 從 `threads` 設定移至 `options` 的頂層。

```diff
  const memory = new Memory({
    storage,
    vector,
    embedder,
    options: {
-     threads: {
-       generateTitle: true,
-     },
+     generateTitle: true,
    },
  });
```

### 調整語意召回的預設值 {/* #semantic-recall-default-settings-optimization */}

語意召回的預設值已根據 RAG 研究進行調整。`topK` 從 2 增至 4，`messageRange` 從 `{ before: 2, after: 2 }` 改為 `{ before: 1, after: 1 }`。這些變更只會使訊息數量略增，同時提高準確度。

若原本依賴先前的預設值，遷移時請明確設定這些值。

```diff
  const memory = new Memory({
    storage,
    vector,
    embedder,
    options: {
      semanticRecall: {
+       topK: 2, // Was default before
+       messageRange: { before: 2, after: 2 }, // Was default before
      },
    },
  });
```

### `memory.readOnly` 移至 `memory.options.readOnly` {/* #memoryreadonly-moved-to-memoryoptionsreadonly */}

`readOnly` 屬性已從 `memory` 選項的頂層移至 `options` 內，與 `lastMessages` 和 `semanticRecall` 等記憶設定選項保持一致。

遷移時，請將頂層的 `readOnly` 移入 `options`。

```diff
  agent.stream('Hello', {
    memory: {
      thread: threadId,
      resource: resourceId,
-     readOnly: true,
+     options: {
+       readOnly: true,
+     },
    },
  });
```

你可以使用 Mastra 的 codemod CLI 自動更新程式碼：

```bash
npx @mastra/codemod@latest v1/memory-readonly-to-options .
```

:::

### `Memory.query()` 更名為 `Memory.recall()` {/* #memoryquery-renamed-to-memoryrecall */}

`Memory.query()` 方法已更名為 `Memory.recall()`。新方法統一回傳較簡潔的 `{ messages: MastraDBMessage[] }`，不再回傳多種格式。新名稱也更貼切地描述從記憶中擷取訊息的操作，讓 API 更簡潔。

遷移時，請將 `query()` 改為 `recall()`，並更新依賴舊回傳格式的程式碼。

```diff
- const result = await memory.query({ threadId: 'thread-123' });
+ const result = await memory.recall({ threadId: 'thread-123' });
- // result: { messages: CoreMessage[], uiMessages: UIMessageWithMetadata[], messagesV2: MastraMessageV2[] }
+ // result: { messages: MastraDBMessage[] }
+ const messages = result.messages;
```

:::tip[Codemod]

你可以使用 Mastra 的 codemod CLI 自動更新程式碼：

```bash
npx @mastra/codemod@latest v1/memory-query-to-recall .
```

:::

### `Memory.recall()` 的參數變更 {/* #memoryrecall-parameter-changes */}

`Memory.recall()` 方法現在使用支援分頁的 `StorageListMessagesInput` 格式，`vectorMessageSearch` 參數也已更名為 `vectorSearchString`。這些變更讓記憶 API 與儲存層的分頁 API 保持一致，命名也更統一。

遷移時，請更新方法名稱、查詢參數及向量搜尋參數。

```diff
- memory.query({
+ memory.recall({
    threadId: 'thread-123',
-   vectorMessageSearch: 'What did we discuss?',
-   selectBy: { ... },
+   vectorSearchString: 'What did we discuss?',
+   page: 0,
+   perPage: 20,
+   orderBy: 'createdAt',
+   filter: { ... },
+   threadConfig: { semanticRecall: true },
  });
```

:::tip[Codemod]

你可以使用 Mastra 的 codemod CLI 自動更新程式碼：

```bash
npx @mastra/codemod@latest v1/memory-vector-search-param .
```

:::

### `MastraMessageV2` 型別更名為 `MastraDBMessage` {/* #mastramessagev2-type-renamed-to-mastradbmessage */}

`MastraMessageV2` 型別已更名為 `MastraDBMessage`，以更清楚地表明它是資料庫中的訊息格式。

遷移時，請將所有 `MastraMessageV2` 替換為 `MastraDBMessage`。

```diff
- import { MastraMessageV2 } from '@mastra/core';
- function yourCustomFunction(input: MastraMessageV2) {}
+ import type { MastraDBMessage } from '@mastra/core/agent';
+ function yourCustomFunction(input: MastraDBMessage) {}
```

:::tip[Codemod]

你可以使用 Mastra 的 codemod CLI 自動更新程式碼：

```bash
npx @mastra/codemod@latest v1/memory-message-v2-type .
```

:::

## 已刪除 {/* #removed */}

### 工作記憶的 `text-stream` 模式 {/* #working-memory-text-stream-mode */}

工作記憶的 `use: "text-stream"` 選項已移除，目前僅支援 `tool-call` 模式。移除可靠性較低的串流模式後，工作記憶 API 也更簡潔。

遷移時，請移除 `use: "text-stream"` 選項。工作記憶將預設使用 `tool-call` 模式。

```diff
  const memory = new Memory({
    storage,
    vector,
    embedder,
    options: {
      workingMemory: {
        enabled: true,
-       use: 'text-stream',
        template: '...',
      },
    },
  });
```

### `Memory.rememberMessages()` 方法 {/* #memoryremembermessages-method */}

`Memory.rememberMessages()` 方法已移除。它與 `query()`（現為 `recall()`）功能相同，統一使用一個方法可簡化 API。

遷移時，請將 `rememberMessages()` 呼叫改為 `recall()`。

```diff
- const { messages } = await memory.rememberMessages({
+ const { messages } = await memory.recall({
    threadId,
    resourceId,
  });
```

### 記憶方法的 `format` 參數 {/* #format-parameter-from-memory-methods */}

所有記憶讀取方法的 `format` 參數均已移除，現在一律預設回傳 `MastraDBMessage`。AI SDK 格式轉換已移至 `@mastra/ai-sdk/ui` 中的專用工具函式。將 UI 專用轉換程式碼移到獨立套件後，tree-shaking 的效果也獲得改善。

遷移時，請移除 `format` 參數，並使用轉換函式取得 AI SDK 格式。

```diff
- const messages = await memory.getMessages({ threadId, format: 'v2' });
- const uiMessages = await memory.getMessages({ threadId, format: 'ui' });

+ const result = await memory.recall({ threadId });
+ const messages = result.messages; // Always MastraDBMessage[]
+
+ // Use conversion functions for AI SDK formats
+ import { toAISdkV5Messages } from '@mastra/ai-sdk/ui';
+ const uiMessages = toAISdkV5Messages(messages);
```

### `MastraMessageV3` 型別 {/* #mastramessagev3-type */}

`MastraMessageV3` 型別及相關轉換方法已移除。訊息現在直接在 `MastraMessageV2`（現為 `MastraDBMessage`）與 AI SDK v5 格式之間轉換。移除中介格式後，整體架構更簡潔。

遷移時，請使用 `MastraDBMessage` 儲存訊息，或直接使用 AI SDK v5 訊息格式。

```diff
- import type { MastraMessageV3 } from '@mastra/core/agent';
- const v3Messages = messageList.get.all.v3();

+ // For storage
+ const v2Messages = messageList.get.all.v2();
+
+ // For AI SDK v5
+ const uiMessages = messageList.get.all.aiV5.ui();
+ const modelMessages = messageList.get.all.aiV5.model();
```

### 從 Memory 建構函式中移除 `processors` 設定 {/* #processors-config-from-memory-constructor */}

Memory 建構函式不再支援 `processors` 設定選項；繼續使用會擲回錯誤。請在 Agent 層級設定處理器，使其行為限定在 Agent 執行期間。

遷移時，請透過 `inputProcessors` 和／或 `outputProcessors` 將處理器設定從 Memory 移至 Agent。

```diff
+ import { TokenLimiter } from '@mastra/core/processors';
+
  const memory = new Memory({
    storage,
    vector,
    embedder,
-   processors: [/* ... */],
  });

  const agent = new Agent({
    id: 'agent',
    memory,
+   inputProcessors: [
+     new TokenLimiter({ limit: 4000 }), // Limits historical messages to fit context window
+   ],
  });
```

此外，`@mastra/memory/processors` 匯入路徑已移除。請改從 `@mastra/core/processors` 匯入處理器。詳情請參閱[處理器遷移指南](/reference/migrations/upgrade-to-v1/processors#memory-processor-exports-moved-to-core)。

若要進一步了解如何在 Agent 中使用處理器，請參閱[處理器文件](/docs/agents/processors)。包含記憶功能的完整範例請見 [TokenLimiter 參考文件](/reference/processors/token-limiter-processor#extended-usage-example)。
