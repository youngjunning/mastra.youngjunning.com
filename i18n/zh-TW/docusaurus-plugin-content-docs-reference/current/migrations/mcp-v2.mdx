# 將 @mastra/mcp 從 v1 遷移到 v2

`@mastra/mcp` 2.0 伺服器僅支援 MCP **2026-07-28** 協定版本，不再協商舊版協定。每個請求都獨立處理：`initialize` 握手、工作階段標頭、獨立的 HTTP+SSE 傳輸，以及由伺服器主動發起的請求均已移除。Tool、資源或提示詞需要呼叫端提供輸入時，會呼叫 `suspend()`。伺服器以原生的 `input_required` 結果結束請求；呼叫端回覆後，處理函式會重新執行，並透過 `resumeData` 取得回覆。

用戶端支援 2026-07-28；預設會探測每部伺服器，並使用該伺服器提供的協定版本，因此同一個 `MCPClient` 可連線至已升級及第三方伺服器。在協商為舊版協定的連線上，舊版不支援的功能會明確回報錯誤，不會由用戶端模擬實作。

如果仍需向 2026 年之前的用戶端**提供服務**，請繼續使用 `@mastra/mcp` 1.x。它仍相容於目前的 `@mastra/core`；同一個 Mastra 執行個體也可以同時註冊 1.x 和 2.x 伺服器。

Streamable HTTP 仍會以伺服器傳送事件串流回傳回應。移除的是獨立的 `GET /sse` + `POST /messages` 傳輸方式，而非 SSE 訊息格式。

## 變更 {/* #changed */}

### `@mastra/core` 的 peer 相依版本範圍 {/* #mastracore-peer-range */}

`@mastra/mcp` 2.0 需要 `@mastra/core` 1.76 或更新的 1.x 版本；這些版本包含共用的伺服器契約（`mcpVersion`、`MCPToolExecutionResultV2`、`context.mcp.protocolVersion`）。請一併更新這兩個套件。

```diff
- "@mastra/core": "^1.60.0",
- "@mastra/mcp": "^1.17.0"
+ "@mastra/core": "^1.76.0",
+ "@mastra/mcp": "^2.0.0"
```

### 需要呼叫端輸入的 Tool 會暫停並恢復 {/* #tools-that-ask-the-caller-for-input-suspend-and-resume */}

在 1.x 中，Tool 透過 `context.mcp.elicitation.sendRequest()` 要求輸入，並在請求保持開啟時等待回覆。在 2.0 中，Tool 呼叫 `context.suspend(payload)` 後即返回；伺服器以 `input_required` 結束請求。呼叫端回覆後，Tool 重新執行，並取得 `context.resumeData`（經 `resumeSchema` 驗證的回覆）和 `context.suspendPayload`（經 `suspendSchema` 驗證的暫停資料）。這與 Agent 和 Workflow 既有的 `suspend`/`resume` 機制相同，因此一份 `createTool` 定義即可供三者使用。

遷移時，請將每次 `sendRequest` 呼叫改為暫停操作。把下一輪所需的狀態放入暫停資料，並在 Tool 恢復時依該狀態選擇執行分支。伺服器不會重播先前的輪次：每一輪只能取得上一輪的暫停資料和當前回覆。

```diff
  export const bookDelivery = createTool({
    id: 'bookDelivery',
    inputSchema: z.object({ orderId: z.string() }),
    outputSchema: z.object({ confirmed: z.boolean() }),
+   suspendSchema: z.object({ phase: z.literal('address'), message: z.string() }),
+   resumeSchema: z.object({ address: z.string() }),
    execute: async ({ orderId }, context) => {
-     const answer = await context.mcp!.elicitation.sendRequest({
-       message: 'Delivery address?',
-       requestedSchema: addressSchema,
-     });
-     if (answer.action !== 'accept') return { confirmed: false };
-     await book(orderId, answer.content.address);
-     return { confirmed: true };
+     if (!context.resumeData) {
+       await context.suspend?.({ phase: 'address', message: 'Delivery address?' });
+       return;
+     }
+     await book(orderId, context.resumeData.address);
+     return { confirmed: true };
    },
  });
```

`resumeSchema` 會成為呼叫端填寫的表單，因此必須描述由基本型別欄位組成的扁平物件。呼叫端拒絕或取消表單時，這次呼叫會以錯誤結束，Tool 不會再次執行。

後續請求透過不透明的 `requestState` 字串關聯；用戶端必須逐位元組原樣傳回該字串。伺服器會對其簽章，並在處理函式執行前拒絕遭竄改、已過期或不屬於目前呼叫的狀態（Tool、引數或呼叫端不同）。呼叫端身分優先取授權層提供的權杖主體，其次取 `mapAuthInfoToUser` 傳回使用者的 `id`，最後取 bearer token 本身；因此，同一個 OAuth 用戶端背後的兩位使用者無法恢復彼此的呼叫輪次。未啟用授權的伺服器會將所有呼叫端視為同一個匿名主體，因此在 `ttlSeconds` 到期前，`requestState` 相當於 bearer 憑證：任何取得它的人都能回覆該輪請求。對於暫停流程涉及寫入、購買或變更帳戶等權限的 Tool，應啟用授權。暫停資料經過簽章，但未加密，因此應保持精簡且不含機密資訊（可存放 ID 和階段，不要存放機密資料）。請從環境中設定 `requestState: { key }`，讓所有可能處理後續請求的執行個體共用該金鑰。否則，伺服器會為每個行程產生獨立金鑰，後續請求只能由原行程處理。

```diff
  const server = new MCPServer({
    name: 'booking',
    version: '2.0.0',
    tools: { bookDelivery },
+   requestState: { key: process.env.MCP_REQUEST_STATE_KEY!, ttlSeconds: 600 },
  });
```

### `context.mcp` 維持不變，但移除了伺服器主動發起的請求 {/* #contextmcp-is-the-same-object-with-server-initiated-requests-removed */}

在 2.0 伺服器上，Tool 仍會收到 `context.mcp`：其中的 `extra`（包括用於取消的 `signal`、`requestId`、`authInfo` 和 `_meta`）、`log` 及 `progress` 與以往一樣可用，`context.mcp.protocolVersion` 為 `'2026-07-28'`。依賴伺服器主動發起請求的成員已棄用；在 2.0 伺服器上呼叫時會擲出錯誤，並指出替代方式：`elicitation.sendRequest` 改用 `suspend`，`extra.sendRequest` 和 `extra.sendNotification` 改用 `log` 與 `progress`。

### `executeTool` 會回報暫停狀態 {/* #executetool-reports-a-suspension */}

Tool 執行完畢時，`server.executeTool()` 和 Mastra REST 路由 `POST /api/mcp/:serverId/tools/:toolId/execute` 會傳回 `{ status: 'completed', output }`；Tool 要求輸入時則傳回 `{ status: 'suspended', suspendPayload, resumeSchema }`。若要繼續執行，請再次提交相同的 `data`，並附上 `resumeData` 和原樣傳回的 `suspendPayload`。無效的 `resumeData` 會使呼叫遭到拒絕。

```diff
- const output = await server.executeTool('bookDelivery', { orderId });
+ const result = await server.executeTool('bookDelivery', { orderId });
+ if (result.status === 'suspended') {
+   const answer = await askUser(result.suspendPayload, result.resumeSchema);
+   await server.executeTool('bookDelivery', { orderId }, { resumeData: answer, suspendPayload: result.suspendPayload });
+ }
```

### 資源與提示詞回呼也可以暫停 {/* #resource-and-prompt-callbacks-can-suspend-too */}

`getResourceContent` 和 `getPromptMessages` 除原有參數外，還會收到 `{ extra, requestContext, suspend, resumeData, suspendPayload }`。`extra` 是 Tool 在 `context.mcp.extra` 中看到的同一個協定脈絡；`requestContext` 是可信任的應用程式脈絡，已包含 `authInfo` 和由 `mapAuthInfoToUser` 對應出的使用者。若要在 `resources` 或 `prompts` 中使用 `suspend`，請宣告 `resumeSchema`。

```diff
  resources: {
    listResources: async ({ requestContext }) => listFor(requestContext.get('authInfo')?.clientId),
-   getResourceContent: async ({ uri, extra }) => read(uri, extra?.signal),
+   resumeSchema: z.object({ reader: z.string() }),
+   getResourceContent: async ({ uri, extra, suspend, resumeData }) => {
+     if (!resumeData) return suspend({ message: 'Who is reading?' });
+     return read(uri, resumeData.reader, extra.signal);
+   },
  },
```

### 依請求設定日誌層級，取代工作階段日誌層級 {/* #per-request-logging-replaces-session-log-levels */}

伺服器不再接受 `logging/setLevel`，也不再依連線保存日誌層級。用戶端可以在每個請求中傳送 `io.modelcontextprotocol/logLevel` 中繼資料鍵來啟用日誌；伺服器只會針對該請求傳送 `notifications/message`，並依指定的嚴重程度過濾。同一次 Tool 呼叫的後續輪次屬於新請求，必須重新啟用日誌。Tool 仍透過 `context.mcp.log(level, message, data)` 記錄日誌。Mastra logger 和可觀測性功能不受影響。

在用戶端，`enableServerLogs` 預設為 `true`，會為每個請求附上中繼資料鍵；日誌層級由 `serverLogLevel` 指定，預設為 `'info'`。設定 `enableServerLogs: false` 即可不接收伺服器日誌。已傳送的訊息仍會進入你的 `logger` 處理函式。

```diff
  servers: {
    weather: {
      url: new URL('http://localhost:4111/api/mcp/weather/mcp'),
      enableServerLogs: true,
+     serverLogLevel: 'warning',
      logger: msg => console.log(msg.serverName, msg.level, msg.message),
    },
  },
```

### 資源訂閱沿用原有 API，並共用一條監聽串流 {/* #resource-subscriptions-keep-their-api-and-ride-one-listen-stream */}

`resources.subscribe` 和 `resources.unsubscribe` 的函式簽章維持不變。用戶端會為每部伺服器使用一條 `subscriptions/listen` 串流，承載所有訂閱及清單變更處理函式；訂閱集合變更時會替換串流，重新連線後則會再次開啟。請先註冊處理函式再訂閱，以免遺漏事件。如果伺服器拒絕某項訂閱，該訂閱呼叫會失敗，既有訂閱則維持不變。

```ts
await mcp.resources.onUpdated('weather', ({ uri }) => refresh(uri))
await mcp.resources.subscribe('weather', 'weather://forecast')
// later
await mcp.resources.unsubscribe('weather', 'weather://forecast')
```

### 依伺服器設定用戶端輸入處理函式 {/* #client-input-handlers-are-configured-per-server */}

過去用戶端透過 `mcp.elicitation.onRequest(serverName, handler)` 回應伺服器發起的輸入請求。現在輸入請求包含在 `input_required` 結果中，因此處理函式改為在伺服器定義中設定，且一次只接收一個請求。設定處理函式會宣告支援 `elicitation.form` 能力。若未設定處理函式，`input_required` 結果會以錯誤呈現，用戶端不會代為回覆。

```diff
  const mcp = new MCPClient({
    servers: {
      booking: {
        url: new URL('http://localhost:4111/api/mcp/booking/mcp'),
+       inputRequests: async ({ key, params }) => askUser(key, params),
      },
    },
  });
- await mcp.elicitation.onRequest('booking', async params => askUser(params));
```

### 用戶端的 `protocolVersion` 用於固定協定版本，而非選擇版本 {/* #client-protocolversion-pins-instead-of-selecting-a-revision */}

1.x 用戶端接受 `protocolVersion: '2025-11-25' | '2026-07-28' | 'auto'`。2.0 用戶端一律支援 2026-07-28；省略此選項時，它會先透過 `server/discover` 探測伺服器，對尚未升級的伺服器則退回使用 `initialize` 握手。將其固定為 `'2026-07-28'` 可略過探測，並在遇到舊版伺服器時失敗；固定為 `'legacy'` 則會略過探測，直接使用握手。協商得到的協定版本會依連線快取，供重新連線時使用，也可透過 `mcp.getServerProtocolVersions()` 查詢。

在協商為舊版協定的連線上，共通的方法仍可使用（`tools/list`、`tools/call`、`resources/read`、`prompts/get`）。資源訂閱、清單變更處理函式和內嵌輸入請求則會擲出錯誤，並指出協商得到的協定版本。

```diff
  servers: {
    thirdParty: {
      url: new URL('https://example.com/mcp'),
-     protocolVersion: 'auto',
+     protocolVersion: 'legacy', // optional: skip the probe for a server known not to have upgraded
    },
  },
```

### OAuth 用戶端須預先註冊或使用用戶端 ID 中繼資料文件 {/* #oauth-clients-are-pre-registered-or-use-a-client-id-metadata-document */}

`MCPOAuthClientProvider` 不再動態註冊用戶端。請提供 `clientInformation`，指定已向授權伺服器註冊的用戶端；或提供 `clientMetadataUrl`（SEP-991），讓伺服器從 HTTPS URL 取得用戶端中繼資料。兩者都未提供時，建立 Provider 會擲出錯誤；系統也絕不會向 `registration_endpoint` 傳送請求。

```diff
  const authProvider = new MCPOAuthClientProvider({
    redirectUrl: 'http://localhost:3000/oauth/callback',
    clientMetadata: { client_name: 'My Agent', redirect_uris: ['http://localhost:3000/oauth/callback'] },
+   clientInformation: { client_id: process.env.MCP_OAUTH_CLIENT_ID! },
  });
```

持久化憑證的結構也已變更：權杖依授權伺服器的 `issuer` 儲存（即 SDK 的 `tokens(ctx)`/`saveTokens(tokens, ctx)` 脈絡）；Provider 也會持久化 OAuth 探索狀態，確保授權碼只與發起重新導向的伺服器交換。自訂 `OAuthStorage` 後端仍沿用相同的鍵值儲存契約，但不同 Provider 不得共用同一個儲存命名空間。`createOAuthCallbackServer` 現在也會傳回 RFC 9207 定義的 `iss` 參數。請在交換授權碼時傳入該參數，讓 SDK 能拒絕簽發者不符的請求。

### `startHTTP` 選項 {/* #starthttp-options */}

`startHTTP` 保留 `url`、`httpPath`、`req` 和 `res`。`options` 物件現在只包含請求安全性相關選項（`enableDnsRebindingProtection`、`allowedHosts`、`allowedOrigins`）。由於每個請求都是無狀態的，工作階段與 serverless 相關選項已移除。

```diff
  await server.startHTTP({
    url: new URL(req.url!, 'http://localhost'),
    httpPath: '/mcp',
    req,
    res,
-   options: { sessionIdGenerator: () => randomUUID(), serverless: false },
+   options: { enableDnsRebindingProtection: true, allowedHosts: ['localhost:4111'] },
  });
```

### 文件伺服器的 `Prompt` 中繼資料 {/* #docs-server-prompt-metadata */}

`MastraPrompt` 及其已棄用的 `version` 欄位均已移除；提示詞 Provider 會傳回 SDK 的 `Prompt` 型別，該型別由 `@mastra/mcp` 重新匯出。

```diff
- import type { MastraPrompt } from '@mastra/mcp';
+ import type { Prompt } from '@mastra/mcp';
```

## 已移除 {/* #removed */}

### 伺服器的 `protocolVersion` 選項 {/* #server-protocolversion-option */}

伺服器先前接受 `protocolVersion` 選項（`'2025-11-25'`、`'2026-07-28'` 或 `'auto'`）。現在伺服器只支援 `2026-07-28`，此版本由 `MCP_PROTOCOL_VERSION` 常數公開。請移除此選項；未提供 `2026-07-28` 的用戶端會收到明確的協商錯誤，伺服器不會降版。若仍需服務透過 HTTP 以 `initialize` 開始通訊的用戶端，請在伺服器上設定 `legacy: 'stateless'`。這些用戶端的每個請求都會在沒有工作階段的情況下獲得回應。

```diff
  const server = new MCPServer({
    name: 'weather',
    version: '1.0.0',
-   protocolVersion: '2026-07-28',
    tools,
  });
```

### `startSSE`、`startHonoSSE`、`connectSSE` 及 `/sse` + `/messages` 路由 {/* #startsse-starthonosse-connectsse-and-the-sse--messages-routes */}

伺服器不再提供獨立的 HTTP+SSE 傳輸；Streamable HTTP 不可用時，用戶端也不會退回使用這種傳輸方式。`startSSE` 和 `startHonoSSE` 仍保留在供 1.x 伺服器使用的共用 `MCPServerBase` 中，但在 2.0 伺服器上呼叫會遭拒。`connectSSE` 已移除。對於 2.0 伺服器，Mastra 伺服器轉接器會對 `/sse` 和 `/messages` 回傳 `404`，Studio 也不再顯示其 SSE 端點。請將所有用戶端指向 `/mcp` 端點。

```diff
- url: new URL('http://localhost:4111/api/mcp/weather/sse'),
+ url: new URL('http://localhost:4111/api/mcp/weather/mcp'),
```

### `handleServerlessRequest`, `sessionId`, `sessionIds`, `reconnectionOptions`, `eventSourceInit` {/* #handleserverlessrequest-sessionid-sessionids-reconnectionoptions-eventsourceinit */}

請求是無狀態的，因此不必恢復工作階段，也不必識別工作階段。`startHTTP` 同時適用於 serverless 和長期運作的伺服器。請從伺服器及用戶端定義中移除工作階段相關選項。

```diff
  servers: {
    weather: {
      url: new URL('http://localhost:4111/api/mcp/weather/mcp'),
-     sessionId: savedSessionId,
-     reconnectionOptions: { maxRetries: 3 },
    },
  },
```

### 伺服器和用戶端上的 `elicitation` 操作 {/* #elicitation-actions-on-server-and-client */}

`server.elicitation.sendRequest()` 和 `mcp.elicitation.onRequest()` 已移除。請在 Tool 中暫停執行，並在用戶端設定 `inputRequests`。

### `roots` 和 `sampling` {/* #roots-and-sampling */}

用戶端不再宣告 `roots` 能力。`setRoots()` 和 `sendRootsListChanged()` 已移除。伺服器既不會要求取樣，也不會宣告取樣能力。如果伺服器在 `input_required` 中嵌入 `roots/list` 或 `sampling/createMessage` 請求，用戶端不會回覆，因為它沒有對應的處理函式；呼叫會失敗，而不會捏造回應。

### `logging/setLevel` 和 `sendLoggingMessage` {/* #loggingsetlevel-and-sendloggingmessage */}

伺服器仍保留規範要求的靜態 `logging` 能力，但會以「找不到方法」錯誤拒絕 `logging/setLevel`。`server.sendLoggingMessage()` 和 `server.getServer()` 已移除。請透過 `context.mcp.log` 依請求記錄日誌，或繼續使用 Mastra logger。

### `resources/subscribe` 和 `resources/unsubscribe` {/* #resourcessubscribe-and-resourcesunsubscribe */}

舊版 `resources/subscribe` 已從伺服器和用戶端移除。`resources.subscribe` 現在使用 `subscriptions/listen`。

### 動態用戶端註冊 {/* #dynamic-client-registration */}

`registerClient`、`OAuthClientRegistrationError` 以及由 `saveClientInformation` 驅動的註冊備援機制均已移除。替代方式請參閱上方的 OAuth 章節。

### 區分 1.x 和 2.0 伺服器 {/* #telling-1x-and-20-servers-apart */}

兩者都繼承同一個 `MCPServerBase`，而 2.0 伺服器會將 `mcpVersion` 設為 `2`。在兩者行為不同之處，可據此分支處理，例如判斷 `executeTool` 的結果是否可能表示暫停。

```diff
  const server = mastra.getMCPServer('booking');
+ if (server?.mcpVersion === 2) { ... }
```
