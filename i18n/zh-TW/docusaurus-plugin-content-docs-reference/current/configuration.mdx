# 配置

以下參考涵蓋了 Mastra 中所有支援的選項。您可以透過實例化來初始化和配置 Mastra[`Mastra` class](/reference/core/mastra-class).

```ts title="src/mastra/index.ts"
import { Mastra } from '@mastra/core'

export const mastra = new Mastra({
  // Your options...
})
```

## 頂級選項 {/* #top-level-options */}

### Agent {/* #agents */}

**類型：** `Record<string, Agent>`

按名稱鍵入的Agent實例的記錄。Agent是自主系統，可以使用人工智慧模型、Tool和記憶體做出決策並採取行動。

參觀[Agents documentation](/docs/agents/overview) to learn more.

```typescript title="src/mastra/index.ts"
import { Mastra } from '@mastra/core'
import { Agent } from '@mastra/core/agent'

export const mastra = new Mastra({
  agents: {
    weatherAgent: new Agent({
      id: 'weather-agent',
      name: 'Weather Agent',
      instructions: 'You help with weather information',
      model: '__GATEWAY_OPENAI_MODEL__',
    }),
  },
})
```

### 後台任務 {/* #backgroundtasks */}

**類型：** `BackgroundTaskManagerConfig`

啟用並配置後台任務管理器。啟用後，Agent可以分派長時間運行的Tool呼叫（包括子Agent呼叫）以非同步運行，同時Agent循環繼續。任務是持久化的，所以配置的`storage` backend is required.

參觀[Background tasks documentation](/docs/harness/background-tasks) to learn more.

```typescript title="src/mastra/index.ts"
import { Mastra } from '@mastra/core'
import { LibSQLStore } from '@mastra/libsql'

export const mastra = new Mastra({
  storage: new LibSQLStore({
    id: 'mastra-storage',
    url: 'file:./mastra.db',
  }),
  backgroundTasks: {
    enabled: true,
    globalConcurrency: 10,
    perAgentConcurrency: 5,
    backpressure: 'queue',
    defaultTimeoutMs: 300_000,
  },
})
```

### 事件 {/* #events */}

**類型：** `Record<string, EventHandler | EventHandler[]>`

內部發布/訂閱系統的事件處理程序。將事件主題對應到事件發佈到這些主題時所呼叫的處理程序函數。

```typescript title="src/mastra/index.ts"
export const mastra = new Mastra({
  events: {
    'my-topic': async event => {
      console.log('Event received:', event)
    },
  },
})
```

**類型：** `Record<string, MastraModelGateway>`

用於存取 LLM Provider的自訂模型路由器網關。網關處理特定於Provider的身份驗證、URL 構造和模型解析。使用它來新增對自訂或自架 LLM Provider的支援。

```typescript title="src/mastra/index.ts"
export const mastra = new Mastra({
  gateways: {
    private: new MyPrivateGateway(),
  },
})
```

### id生成器 {/* #idgenerator */}

**類型：** `(context?: IdGeneratorContext) => string`\
**Default:** `crypto.randomUUID()`

用於建立唯一識別碼的自訂 ID 生成器功能。 Mastra 傳遞可選上下文，以便您可以根據正在建立的內容產生 ID。

`IdGeneratorContext`包括：

* `idType`: `'thread' | 'message' | 'run' | 'step' | 'generic'`
* `source?`: `'agent' | 'workflow' | 'memory'`
* `entityId?`：請求Agent/Workflow/記憶體實體的 ID
* `threadId?`：相關時的線程 ID（例如，建立訊息 ID 時）
* `resourceId?`：相關的資源 ID（例如，使用者範圍的執行緒）
* `role?`：建立訊息ID時的訊息角色
* `stepType?`：建立步驟ID時的Workflow步驟類型

：：：警告

Mastra 在內部使用它來為Workflow運行、Agent對話和其他資源建立 ID。大多數用戶不需要配置此選項。

:::

```typescript title="src/mastra/index.ts"
import { v4 as uuid } from '@lukeed/uuid'
import { Mastra } from '@mastra/core'

export const mastra = new Mastra({
  idGenerator: context => {
    if (context?.idType === 'message' && context?.threadId) {
      return `msg-${context.threadId}-${uuid()}`
    }

    if (context?.idType === 'run' && context?.source && context?.entityId) {
      return `${context.source}-run-${context.entityId}-${uuid()}`
    }

    return uuid()
  },
})
```

**類型：** `IMastraLogger | false`\

```typescript title="src/mastra/index.ts"
  logger: new PinoLogger({ name: 'MyApp', level: 'debug' }),
})
```

### mcp伺服器 {/* #mcpservers */}

**類型：** `Record<string, MCPServerBase>`

MCP（模型上下文協定）伺服器，向 MCP 相容客戶端公開 Mastra Tool、Agent、Workflow和資源。使用它來編寫您自己的 MCP 伺服器，任何支援該協定的系統都可以使用該伺服器。

參觀[MCP Overview](/docs/connections/mcp) to learn more.

```typescript title="src/mastra/index.ts"
import { Mastra } from '@mastra/core'
import { MCPServer } from '@mastra/mcp'

const mcpServer = new MCPServer({
  id: 'my-mcp-server',
  name: 'My MCP Server',
  version: '1.0.0',
})

export const mastra = new Mastra({
  mcpServers: {
    myServer: mcpServer,
  },
})
```

### 記憶 {/* #memory */}

**類型：** `Record<string, MastraMemory>`

可由Agent引用的記憶體實例註冊表，包括使用的儲存Agent`{ type: 'id', memoryId: '<key>' }`. Memory gives agents coherence across interactions by retaining relevant information from past conversations. Mastra supports message history for recent messages and working memory for persistent user-specific details. Semantic recall retrieves older messages based on relevance.

參觀[Memory documentation](/docs/memory/overview) to learn more.

：：：筆記

大多數用戶直接在Agent上配置記憶體。此頂級配置用於定義可在多個Agent程式之間共用的可重複使用記憶體實例。

:::

```typescript title="src/mastra/index.ts"
import { Mastra } from '@mastra/core'
import { Memory } from '@mastra/memory'
import { LibSQLStore } from '@mastra/libsql'

export const mastra = new Mastra({
  storage: new LibSQLStore({
    id: 'mastra-storage',
    url: ':memory:',
  }),
  memory: {
    chatMemory: new Memory({
      options: {
        lastMessages: 20,
      },
    }),
  },
})
```

### Observability {/* #observability */}

**類型：** `ObservabilityEntrypoint`

Mastra 為人工智慧應用程式提供可觀察性功能。使用了解 AI 特定模式的Tool監控 LLM 操作、追蹤Agent決策並調試複雜的Workflow。追蹤擷取模型互動、Agent執行路徑、Tool呼叫和Workflow步驟。

參觀[Observability documentation](/docs/observability/overview) to learn more.

```typescript title="src/mastra/index.ts"
import { Mastra } from '@mastra/core'
import { LibSQLStore } from '@mastra/libsql'
import { Observability, MastraStorageExporter } from '@mastra/observability'

export const mastra = new Mastra({
  storage: new LibSQLStore({
    id: 'mastra-storage',
    url: 'file:./mastra.db',
  }),
  observability: new Observability({
    configs: {
      default: {
        serviceName: 'my-app',
        exporters: [new MastraStorageExporter()],
      },
    },
  }),
})
```

參觀[Processors documentation](/docs/agents/processors) to learn more.

：：：筆記

:::

```typescript title="src/mastra/index.ts"
import { Mastra } from '@mastra/core'
import { ModerationProcessor } from '@mastra/core/processors'

export const mastra = new Mastra({
  processors: {
    moderation: new ModerationProcessor({
```

### 分類器 {/* #classifiers */}

**類型：** `Record<string, Classifier>`

分類器向決策模型詢問有關應用程式狀態的固定選項問題並返回鍵入的答案。在這裡註冊可重複使用的分類器以檢索它們`getClassifier()` or `getClassifierById()`. When a registered classifier is evaluated without an active trace, it starts a root `CLASSIFIER_EVALUATION` span through the `Mastra` instance's configured observability provider.

參觀[Classifier reference](/reference/classifier/classifier) to learn more.

```typescript title="src/mastra/index.ts"
import { Mastra } from '@mastra/core'
import { Classifier } from '@mastra/core/classifier'
import { typeSafeAi } from '@ai-sdk/typesafe-ai'

const safety = new Classifier({
  id: 'safety',
  model: typeSafeAi.decisionModel('__AI_SDK_TYPESAFE_DECISION_MODEL__'),
  questions: {
    unsafe: {
      type: 'boolean',
      criteria: { true: 'Unsafe', false: 'Safe' },
    },
  },
})

export const mastra = new Mastra({
  classifiers: { safety },
})
```

### Tool {/* #tools */}

**類型：** `Record<string, Tool>`

Tool是可重複使用的功能，Agent可以使用它們與外部系統進行互動。每個Tool定義輸入、輸出和執行邏輯。

參觀[Tools documentation](/docs/agents/tools) to learn more.

:::注意
大多數用戶直接在Agent上配置Tool。此頂級配置用於定義可在多個Agent程式之間共用的可重複使用Tool。
:::

```typescript title="src/mastra/index.ts"
import { Mastra } from '@mastra/core'
import { createTool } from '@mastra/core/tools'
import { z } from 'zod'

const weatherTool = createTool({
  id: 'get-weather',
  description: 'Fetches weather for a city',
  inputSchema: z.object({
    city: z.string(),
  }),
  execute: async () => {
    return { temperature: 20, conditions: 'Sunny' }
  },
})

export const mastra = new Mastra({
  tools: {
    weather: weatherTool,
  },
})
```

### Workspace {/* #workspace */}

### Bundler.pnpmWorkspaceSettings {/* #bundlerpnpmworkspacesettings */}

**類型：** `Record<string, JSONValue>`\
**Default:** `{}`

### server.handleShutdownSignals {/* #serverhandleshutdownsignals */}

**類型：** `boolean`\
**Default:** `true`

是否由伺服器生成`mastra dev` and `mastra build` installs its own `SIGINT`/`SIGTERM` handlers. By default, receiving a signal begins graceful shutdown. The generated server stops accepting new connections and drains in-flight requests before it runs `mastra.shutdown()` and exits the process (see [`server.drainTimeout`](#serverdraintimeout)).

放`handleShutdownSignals: false` to manage signals yourself, for example with a handler registered in your Mastra config module that calls `mastra.shutdown()`:

```typescript title="src/mastra/index.ts"
import { Mastra } from '@mastra/core'

export const mastra = new Mastra({
  server: {
    handleShutdownSignals: false,
  },
})

let shuttingDown = false
const shutdown = async () => {
  if (shuttingDown) return
  shuttingDown = true
  // custom shutdown coordination
  await mastra.shutdown()
  process.exit(0)
}

process.once('SIGINT', shutdown)
process.once('SIGTERM', shutdown)
```

請注意以下注意事項：

* 如果沒有您自己的處理程序，Node.js 將應用預設訊號行為：進程立即終止，不會耗盡。
* 您的處理程序無法存取生成的條目檔案中的 HTTP 伺服器句柄，因此它無法耗盡正在進行的 HTTP 請求。如果您只需要更長的排水窗口，請選擇[`server.drainTimeout`](#serverdraintimeout). For full control over the server lifecycle, use a [server adapter](/docs/server/server-adapters).
* 期間`mastra dev`, the built-in handlers release storage resources between hot reloads (for example, DuckDB file locks). Disabling them without an equivalent handler can cause lock conflicts after a reload.

* `'body'`: 請求體

```typescript title="src/mastra/index.ts"
      status: 422,
      body: {
        ok: false,
        errors: error.issues.map(i => ({
          path: i.path.join('.'),
          message: i.message,
        })),
        source: context,
      },
    }),
  },
```

### 伺服器.drainTimeout {/* #serverdraintimeout */}

**類型：** `number`\
**Default:** `5000` (5 seconds)

`SIGINT` or `SIGTERM`. The value must be finite and between `0` and `2147483647`. During this window the server stops accepting new connections and waits for in-flight requests (including active streams) to finish; if the deadline passes first, remaining HTTP connections are closed. Upgraded connections such as WebSockets end when the process exits. Either way, `mastra.shutdown({ drainTimeout })` then runs before the process exits. It gives in-flight workflow runs (including durable agent runs) the same window to reach a finished or suspended state before workers and pub/sub subscriptions are torn down. Background task cancellation and worker teardown share that window. The generated server then allows up to 5 seconds for workspace and storage cleanup. Setting `0` skips both drains.

當滾動部署需要讓長時間運行的Agent程式輪流或Workflow步驟完成時，請增加此值。 HTTP 消耗和Workflow消耗相繼運作。規劃最壞的情況，即該值的兩倍加上 5 秒的清理時間，並將總數保持在平台的寬限期以下（例如`terminationGracePeriodSeconds` on Kubernetes):

```typescript title="src/mastra/index.ts"
import { Mastra } from '@mastra/core'

export const mastra = new Mastra({
  server: {
    drainTimeout: 600000, // 10 minutes
  },
})
```

在排水期間再次發送任一關閉信號都會繞過它並立即終止該過程。

### 伺服器.studioBase {/* #serverstudiobase */}

**類型：** `string`\
**Default:** `/`

託管的基本路徑[Studio](/docs/studio/overview). Use this to host the Studio on a sub-path of your existing application instead of the root.

當與受益於共享網域的現有應用程式或身分驗證Tool（例如 Cloudflare 零信任）整合時，這非常有用。它還支援管理一個網域下的多個服務。

```typescript title="src/mastra/index.ts"
import { Mastra } from '@mastra/core'

export const mastra = new Mastra({
  server: {
    studioBase: '/my-mastra-studio',
  },
})
```

**範例 URL：**

* 預設:`http://localhost:4111/` (studio at root)
* 和`studioBase`: `http://localhost:4111/my-mastra-studio/` (studio at sub-path)

### 伺服器逾時 {/* #servertimeout */}

**類型：** `number`\
**Default:** `180000` (3 minutes)

請求超時（以毫秒為單位）。超過此持續時間的請求將被終止。

在無伺服器平台上，此限制與平臺本身的函數逾時無關。例如，[Vercel deployer](/reference/deployer/vercel#request-timeouts) sets Vercel's limit with `maxDuration` (seconds) while `server.timeout` still applies, so long requests need both raised.

```typescript title="src/mastra/index.ts"
import { Mastra } from '@mastra/core'

export const mastra = new Mastra({
  server: {
    timeout: 30000, // 30 seconds
  },
})
```
