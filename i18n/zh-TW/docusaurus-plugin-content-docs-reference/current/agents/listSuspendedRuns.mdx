# Agent.listSuspendedRuns()

**添加於：** `@mastra/core@1.43.0`

`.listSuspendedRuns()` 從 Workflow 快照儲存空間尋找已暫停的 Agent 執行，包括等待 Tool 呼叫[核准](/docs/agents/human-in-the-loop)的執行，以及由呼叫 `suspend()` 的 Tool 暫停的執行。透過儲存空間尋找執行的功能，在伺服器重新啟動後及多個伺服器執行個體之間仍可使用。

將傳回的 `runId` 傳入 [`resumeStream()`](/docs/agents/human-in-the-loop#runtime-suspension-with-suspend)、`approveToolCall()` 或 `declineToolCall()`，即可繼續執行。

篩選條件與 Workflow 執行清單 API（`listWorkflowRuns`）一致，並新增 Agent 層級的 `threadId` 篩選條件。

## 使用範例 {/* #usage-example */}

找出某段對話中待處理的執行並繼續執行。依照 `requiresApproval` 選擇方法：等待核准時使用 `approveToolCall()` / `declineToolCall()`；使用 `resumeStream()` 並傳入恢復資料，可繼續由 `suspend()` 暫停的執行：

```typescript
const { runs } = await agent.listSuspendedRuns({
  threadId: 'thread-123',
  resourceId: 'user-456',
})

const run = runs[0]
const toolCall = run?.toolCalls[0]

if (run && toolCall) {
  const stream = toolCall.requiresApproval
    ? await agent.approveToolCall({ runId: run.runId, toolCallId: toolCall.toolCallId })
    : await agent.resumeStream({ name: 'San Francisco' }, { runId: run.runId })
}
```

## 發現範圍 {/* #discovery-scope */}

結果僅屬於呼叫 `listSuspendedRuns()` 的 Agent，因為快照會保存所屬 Agent 的 ID。同一 Mastra 執行個體中由其他 Agent 啟動的執行不會傳回。在[監督 Agent 設定](/docs/agents/human-in-the-loop#tool-approval-supervisor-agents)中，監督 Agent 可找到自己需要恢復的外層執行；子 Agent 的內層執行只能從該子 Agent 查詢。使用 `threadId` 和 `resourceId` 可將結果限定為單一對話。

執行快照只在等待輸入期間保存，執行結束後即會刪除，因此只能從儲存空間找到已暫停的執行。只有為 Mastra 執行個體設定持久化的[儲存提供者](/docs/storage)，已暫停的執行才能在重新啟動後保留。預設的記憶體儲存空間會在重新啟動後遺失快照。

儲存配接器支援時，`threadId` 與 `resourceId` 篩選條件會下推至儲存查詢。`@mastra/pg` 和 `@mastra/libsql` 會在資料庫內篩選符合條件的執行，無須載入所有已暫停的快照；記憶體儲存空間則篩選其記錄。其他儲存配接器先擷取資料，再於處理程序中篩選。兩種方式的結果相同。
