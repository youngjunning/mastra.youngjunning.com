# Agent.listSuspendedRuns()

**添加於：** `@mastra/core@1.43.0`

這`.listSuspendedRuns()` method uses workflow snapshot storage to find suspended agent runs, including runs awaiting [approval](/docs/agents/human-in-the-loop)用於Tool調用並由調用的Tool暫停運行`suspend()`。伺服器重新啟動後，支援儲存的發現可以在多個伺服器實例中繼續工作。

透過返回的`runId` to [`resumeStream()`](/docs/agents/human-in-the-loop#runtime-suspension-with-suspend), `approveToolCall()`, or `declineToolCall()`繼續運行。

過濾器合約鏡像了Workflow運行清單 API（`listWorkflowRuns`), plus the agent-level `threadId` filter.

## 使用範例 {/* #usage-example */}

發現對話的待運行並繼續它。查看`requiresApproval` to pick the right continuation: `approveToolCall()` / `declineToolCall()` for approval suspensions, `resumeStream()` with resume data for `suspend()`-based suspensions:

```typescript
const { runs } = await agent.listSuspendedRuns({
  threadId: 'thread-123',
  resourceId: 'user-456',
})

const run = runs[0]
const toolCall = run?.toolCalls[0]

if (run && toolCall) {
  const stream = toolCall.requiresApproval
    ? await agent.approveToolCall({ runId: run.runId, toolCallId: toolCall.toolCallId })
    : await agent.resumeStream({ name: 'San Francisco' }, { runId: run.runId })
}
```

## 發現範圍 {/* #discovery-scope */}

結果僅限於您致電的Agent`listSuspendedRuns()` on because snapshots persist the owning agent's id. Runs started by other agents on the same Mastra instance aren't returned. In [supervisor setups](/docs/agents/human-in-the-loop#tool-approval-supervisor-agents), the supervisor sees its outer run to resume, while a subagent's inner run is visible only from the subagent itself. Filter by `threadId` and `resourceId` to limit results to one conversation.

運行快照僅在運行等待輸入時保留，並在運行完成後刪除，因此掛起的運行是唯一可從存儲中發現的運行。當 Mastra 實例具有持久性時，掛起的運行只能在重新啟動後繼續存在。[storage provider](/docs/storage) configured. With the default in-memory store, snapshots are lost on restart.

這`threadId` and `resourceId` filters are pushed down to the storage query where the adapter supports it. `@mastra/pg` and `@mastra/libsql` narrow matching runs inside the database instead of loading every suspended snapshot, and the in-memory store filters its in-memory records. Other storage adapters apply these filters in-process after fetching. Results are identical either way.
