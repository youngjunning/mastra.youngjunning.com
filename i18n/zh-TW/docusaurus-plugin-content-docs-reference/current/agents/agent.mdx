# Agent 類別

`Agent` 類別是使用 Mastra 建立 AI Agent 的基礎，提供產生回應、串流互動與語音功能。

## 使用範例 {/* #usage-examples */}

### 基本字串指令 {/* #basic-string-instructions */}

以字串或字串陣列傳入指令，是設定 Agent 最簡單的方式。適合只需提供提示詞、無須額外設定的情境。

```typescript title="src/mastra/agents/string-agent.ts"
import { Agent } from '@mastra/core/agent'

// String instructions
export const agent = new Agent({
  id: 'test-agent',
  name: 'Test Agent',
  // highlight-next-line
  instructions: 'You are a helpful assistant that provides concise answers.',
  model: '__GATEWAY_OPENAI_MODEL__',
})

// System message object
export const agent2 = new Agent({
  id: 'test-agent-2',
  name: 'Test Agent 2',
  // highlight-start
  instructions: {
    role: 'system',
    content: 'You are an expert programmer',
  },
  // highlight-end
  model: '__GATEWAY_OPENAI_MODEL__',
})

// Array of system messages
export const agent3 = new Agent({
  id: 'test-agent-3',
  name: 'Test Agent 3',
  // highlight-start
  instructions: [
    { role: 'system', content: 'You are a helpful assistant' },
    { role: 'system', content: 'You have expertise in TypeScript' },
  ],
  // highlight-end
  model: '__GATEWAY_OPENAI_MODEL__',
})
```

### Provider 專屬設定 {/* #provider-specific-configurations */}

各模型 Provider 也提供提示詞快取、推理設定等選項。可以在指令層級設定 `providerOptions`，為不同的 system 指令或提示詞指定不同的快取策略。

```typescript title="src/mastra/agents/core-message-agent.ts"
import { Agent } from '@mastra/core/agent'

export const agent = new Agent({
  id: 'core-message-agent',
  name: 'Core Message Agent',
  instructions: {
    role: 'system',
    content: 'You are a helpful assistant specialized in technical documentation.',
    // highlight-start
    providerOptions: {
      openai: {
        reasoningEffort: 'low',
      },
    },
    // highlight-end
  },
  model: '__GATEWAY_OPENAI_MODEL__',
})
```

### 混合指令格式 {/* #mixed-instruction-formats */}

```typescript title="src/mastra/agents/multi-message-agent.ts"
import { Agent } from '@mastra/core/agent'

// This could be customizable based on the user
const preferredTone = {
  role: 'system',
  content: 'Always maintain a professional and empathetic tone.',
}

export const agent = new Agent({
  id: 'multi-message-agent',
  name: 'Multi Message Agent',
  instructions: [
    { role: 'system', content: 'You are a customer service representative.' },
    preferredTone,
    {
      role: 'system',
      content: 'Escalate complex issues to human agents when needed.',
      providerOptions: {
        anthropic: { cacheControl: { type: 'ephemeral' } },
      },
    },
  ],
  model: '__GATEWAY_ANTHROPIC_MODEL_SONNET__',
})
```

## 模型字串 {/* #model-strings */}

最簡單的設定方式是將 `model` 設為 `provider/model` 格式的字串，以斜線分隔 Provider 與模型名稱。Mastra 會從環境變數讀取對應 Provider 的憑證，因此無須額外安裝或匯入 Provider 套件。

常用的 Provider 字串與憑證：

* **OpenAI**：`__GATEWAY_OPENAI_MODEL__` 使用 `OPENAI_API_KEY`。
* **Anthropic**：`__GATEWAY_ANTHROPIC_MODEL_SONNET__` 使用 `ANTHROPIC_API_KEY`。
* **Google**：`__GATEWAY_GOOGLE_MODEL_FLASH__` 使用 `GOOGLE_API_KEY` 或 `GOOGLE_GENERATIVE_AI_API_KEY`。

支援的模型 ID 請參閱[模型清單](/models)；完整的 Provider 清單請參閱[環境變數](/models/environment-variables)。

## Thread 訊號 {/* #thread-signals */}

使用 Agent 訊號將即時輸入與情境傳送至 memory thread。訊息 API 處理使用者撰寫的輸入；`sendSignal()` 是用於系統產生情境的較底層 API。

目標 thread 正在執行時，`sendMessage()` 會將訊息交給目前的 Agent 迴圈。thread 閒置時，Mastra 預設會以該訊息作為第一筆輸入啟動串流。

```typescript title="src/mastra/signals.ts"
const subscription = await agent.subscribeToThread({
  resourceId: 'user-123',
  threadId: 'thread-abc',
})

void (async () => {
  for await (const chunk of subscription.stream) {
    console.log(chunk)
  }
})()

agent.sendMessage('Use the latest customer note too.', {
  resourceId: 'user-123',
  threadId: 'thread-abc',
  ifIdle: {
    streamOptions: {
      maxSteps: 3,
    },
  },
})
```

可用 `attributes` 識別共用 thread 中的不同使用者。這些屬性會呈現為 XML，讓模型分辨每則訊息的發送者：

```typescript
agent.sendMessage(
  {
    contents: 'Can we simplify the API surface?',
    attributes: { name: 'Devin', from: 'slack' },
  },
  { resourceId: 'user-123', threadId: 'thread-abc' },
)
```

模型收到的內容如下：

```xml
<user name="Devin" from="slack">Can we simplify the API surface?</user>
```

若訊息需要依 thread 是否正在執行而帶有不同情境，請使用 `ifActive.attributes` 與 `ifIdle.attributes`：

```typescript title="src/mastra/signals.ts"
agent.sendMessage(
  {
    contents: 'Also cover the edge cases.',
    attributes: { source: 'chat' },
  },
  {
    resourceId: 'user-123',
    threadId: 'thread-abc',
    ifActive: { attributes: { delivery: 'while-active' } },
    ifIdle: { attributes: { delivery: 'new-message' } },
  },
)
```

thread 正在執行時，模型看到：

```xml
<user source="chat" delivery="while-active">Also cover the edge cases.</user>
```

thread 閒置時，模型看到：

```xml
<user source="chat" delivery="new-message">Also cover the edge cases.</user>
```

UI 可以看到訊息內容，也可以從訊號訊息讀取 `attributes` 與 `metadata` 以自訂顯示方式，例如顯示使用者名稱、頭像或平台徽章。

```typescript title="src/mastra/signals.ts"
    streamOptions: {
      maxSteps: 3,
    },
  },
})
```

回傳 `{ accepted: Promise<SendAgentSignalAccepted>, signal: CreatedAgentSignal, persisted?: Promise<void> }`。`accepted` 在 Mastra 決定如何處理訊息時解析：本程序執行 Agent（自行啟動或贏得啟動 lease）時為 `{ action: 'wake', runId, output }`；訊息轉送至現有執行工作（包括本程序輸掉跨程序喚醒競爭）時為 `{ action: 'deliver', runId }`；沒有執行工作啟動時為 `{ action: 'persist' }` 或 `{ action: 'discard' }`。`runId` 是處理該訊息的執行工作之權威 ID，僅在 `wake` 與 `deliver` 時存在。對於 `persist`/`discard`，可用 `result.signal.id` 關聯已儲存的訊息。`accepted` 表示路由決策已完成：`wake` 執行工作中的產生錯誤會透過 `output.consumeStream()` 顯示；只有訊息完全無法路由或啟動時（例如 Agent 設定錯誤）才會拒絕。`persisted` 僅在 `persist` 行為下存在，並於 Mastra 將訊息寫入 memory 後解析。`wake` 時，`output` 是可在程序內讀取的 Agent 串流。

### `queueMessage(message, options)` {/* #queuemessagemessage-options */}

將使用者訊息排入佇列，供 thread 的下一輪處理。若 thread 正在執行，Mastra 會等目前的執行工作結束，再以佇列訊息啟動新工作；若 thread 閒置，則立即啟動。

```typescript
agent.queueMessage('Also check whether the tests need updates.', {
  resourceId: 'user-123',
  threadId: 'thread-abc',
})
```

`queueMessage()` 接受與 `sendMessage()` 相同結構的 `message` 與 `options`，並回傳 `{ accepted: Promise<SendAgentSignalAccepted>, signal: CreatedAgentSignal, persisted?: Promise<void> }`；`accepted` 的語意也與 `sendMessage()` 相同。可傳入選用的 `queueOwnerId`，將本機佇列訊息分組，以便觀察與取消。owner ID 是本機中繼資料：不會隨訊息序列化，也不是授權機制。

使用 [`subscribeThreadEvents({ resourceId, threadId }, listener)`](/reference/signals/thread-events) 觀察共用 thread 中本機待處理的訊息。目前 listener 只接收 `queue-count-changed` 事件。訂閱選項、計數語意、取消訂閱行為，以及依 owner 範圍觀察的方式，請參閱 [Thread 事件參考](/reference/signals/thread-events)。

### `queueSignal(signal, options)` {/* #queuesignalsignal-options */}

將具型別的訊號排入佇列，供 thread 的下一輪處理。其行為與 `queueMessage()` 相同，但可接受任意訊號輸入，並為排入佇列的執行工作保留 `type`、`tagName` 與 `attributes`。

```typescript
agent.queueSignal(
  {
    type: 'reactive',
    tagName: 'skill',
    attributes: { name: 'triage' },
    contents: 'Triage the new issue.',
  },
  { resourceId: 'user-123', threadId: 'thread-abc' },
)
```

`queueSignal()` 接受與 `queueMessage()` 相同的 `options`（包括 `queueOwnerId`），並回傳相同結構的結果。佇列訊號與 `queueMessage()` 共用佇列，因此計入佇列計數事件，也可由 `cancelQueuedMessages()` 取消。

### `cancelQueuedMessages(options)` {/* #cancelqueuedmessagesoptions */}

取消待處理的輸入，但不中止執行中的工作。必須且只能提供一個選取條件：

* `signalIds` 取消共用同一 runtime 與 memory thread 的多個 Agent 中指定的輸入。包含等待執行準備的訊號、目前執行工作中待處理的訊號，以及等待後續執行的佇列訊息。
* `queueOwnerId` 只取消呼叫端 Agent 中屬於該 owner 群組的 `queueMessage()` 與 `queueSignal()` 項目，不影響其他 Agent 的輸入或其他佇列中的訊號。

```typescript
const { cancelledSignalIds } = agent.cancelQueuedMessages({
  resourceId: 'user-123',
  threadId: 'thread-abc',
  signalIds: ['signal-123', 'signal-456'],
})
```

回傳 `{ cancelledSignalIds: string[] }`，每個實際由此次呼叫取消的 ID 只出現一次。空陣列表示選定的訊號中沒有仍在本機待處理的項目。等待取得或轉移 lease 的訊號仍可取消；一旦開始執行或轉送，本機副本就無法再取消。

對於 `signalIds`，即使本機沒有待處理項目，Mastra 仍會透過 PubSub 發布所有要求取消的 ID。訂閱該 thread 的其他程序會取消符合條件的待處理輸入，包括等待 lease 的訊號。傳播採盡力而為且非同步進行，沒有遠端確認，因此本機結果為空不表示其他程序中要求取消的訊號仍在佇列中。依 owner 群組取消只影響呼叫端 Agent 的本機佇列。來自 `continueWithMessages()` 的後續執行、已儲存的訊息、state 更新及通知記錄均不受影響。已完成的 accepted 確認也不會改變。

在 serverless 處理常式中，等待 `accepted` 解析，並將 `wake` 結果中的 output 交給平台對應的 `waitUntil` 機制，讓取得執行權的程序在 HTTP 回應傳回後繼續讀取串流。

```typescript
const result = agent.sendSignal(signal, { resourceId, threadId })
ctx.waitUntil(
  result.accepted.then(async accepted => {
    if (accepted.action === 'wake') {
      await accepted.output.consumeStream()
    }
  }),
)
```

```typescript title="src/mastra/agents/support-agent.ts"
import { Agent } from '@mastra/core/agent'

export const supportAgent = new Agent({
  id: 'support-agent',
  name: 'Support Agent',
  instructions: 'Help the user triage updates.',
  model: '__GATEWAY_OPENAI_MODEL__',
  notifications: {
    deliveryPolicy: {
      priorities: {
        urgent: 'deliver',
      },
      decide: ({ record }) => {
        if (record.priority === 'low') {
          return {
            action: 'summarize',
            summaryAt: new Date(Date.now() + 30 * 60 * 1000),
          }
        }
      },
    },
  },
})
```

## `generate()` 的 memory 選項 {/* #generate-memory-options */}

呼叫 `agent.generate()` 時傳入 `memory`，可指定這次執行要讀取與寫入的對話 thread。常見結構是 `memory: { resource: string, thread: string }`：`resource` 識別擁有者，`thread` 識別對話。概念說明請參閱 [Thread 與 resource](/docs/memory/message-history#threads-and-resources)。

```typescript title="src/mastra/run.ts"
const response = await agent.generate('What did we decide about retries?', {
  memory: {
    resource: 'user-123',
    thread: 'support-thread-456',
  },
})
```

如需在呼叫期間建立或更新 thread 中繼資料，請使用 thread 物件：

```typescript title="src/mastra/run.ts"
const response = await agent.generate('Continue the support conversation.', {
  memory: {
    resource: 'user-123',
    thread: {
      id: 'support-thread-456',
      title: 'Billing support',
      metadata: { category: 'billing' },
    },
  },
})
```

## Tool hook {/* #tool-hooks */}

使用 `hooks`，可在 Agent 的每次 Tool 呼叫前後執行邏輯，包括指派給 Agent 的 Tool、memory Tool、Toolset、用戶端 Tool 與 workspace Tool。

```typescript title="src/mastra/agents/hooked-agent.ts"
import { Agent } from '@mastra/core/agent'

export const agent = new Agent({
  id: 'support-agent',
  name: 'support-agent',
  instructions: 'Help users with their questions.',
  model: '__GATEWAY_OPENAI_MODEL__',
  // highlight-start
  hooks: {
    beforeToolCall: ({ toolName, input }) => {
      console.log(`Running ${toolName}`, input)
    },
    afterToolCall: ({ toolName, output, error }) => {
      console.log(`Finished ${toolName}`, { output, error })
    },
  },
  // highlight-end
})
```

`beforeToolCall` 可以回傳 `{ proceed: false, output }` 以略過 Tool 呼叫。Agent 不會執行 Tool，而是將 `output` 作為 Tool 結果：

```typescript
const result = await agent.generate('Clean up old records', {
  hooks: {
    beforeToolCall: ({ toolName }) => {
      if (toolName === 'deleteRecord') {
        return { proceed: false, output: { blocked: true } }
      }
    },
  },
})
```

hook 情境的 `metadata` 包含 `agentId` 與 `agentName`。傳給 `generate()` 或 `stream()` 的執行專用 hook 會覆寫 Agent 層級的同名 hook。若 [workspace](/reference/workspace/workspace-class) 也定義了 `tools.hooks`，workspace hook 會在 Agent hook 包裝器內執行。

## Editor 覆寫設定 {/* #editor-overrides */}

註冊 [`MastraEditor`](/reference/editor/mastra-editor) 後，`editor` 欄位控制 Agent 的哪些部分由程式碼定義、哪些由 Studio 管理。由程式碼管理的欄位在 Studio 中為唯讀，儲存覆寫設定時會被移除。由 Studio 管理的欄位必須從程式碼省略。Agent 會從已儲存的覆寫設定讀取這些欄位；缺少欄位時會拒絕執行。

  content={[
{

欄位由 Studio 管理時，TypeScript 不允許在程式碼中設定該欄位：`editor: { instructions: true }` 與程式碼中的 `instructions`、`editor: { tools: true }` 與程式碼中的 `tools` 都會造成型別錯誤。若指令由 Studio 管理，在發布包含指令的已儲存版本前，Agent 會拒絕執行。

Agent 的 `id` 與 `name` 一律由程式碼定義。除非設定 `model: true`，模型也由程式碼管理。模型管理支援項目具有不可變 ID 的靜態備援陣列。以函式為值的模型設定無法透過 Editor 覆寫。用法請參閱 [Editor](/docs/studio/editor)。
