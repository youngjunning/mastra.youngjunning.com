# MastraScorer

`MastraScorer` 是 Mastra 中所有評分器的基類。它提供標準的 `.run()` 方法來評估輸入與輸出，並支援按 preprocess → analyze → generateScore → generateReason 順序執行的多步驟評分流程。

大多數使用者應通過 [`createScorer`](./create-scorer) 建立評分器實例。不建議直接實例化 `MastraScorer`。

## 獲取 `MastraScorer` 實例 {/* #how-to-get-a-mastrascorer-instance */}

呼叫 `createScorer` 工廠函數即可獲得一個 `MastraScorer` 實例：

```typescript
import { createScorer } from '@mastra/core/evals'

const scorer = createScorer({
  name: 'My Custom Scorer',
  description: 'Evaluates responses based on custom criteria',
}).generateScore(({ run, results }) => {
  // scoring logic
  return 0.85
})

// scorer is now a MastraScorer instance
```

## `.run()` 方法 {/* #run-method */}

`.run()` 是執行評分器、評估輸入與輸出的主要方法。它依次執行已定義的步驟（preprocess → analyze → generateScore → generateReason），回傳包含分數、評分理由和中間結果的詳細物件。

```typescript
const result = await scorer.run({
  input: 'What is machine learning?',
  output: 'Machine learning is a subset of artificial intelligence...',
  runId: 'optional-run-id',
  requestContext: {/* optional context */},
})
```

### Judge 結果 {/* #judge-results */}

可選的 `judge` 記錄包含基於提示詞的評分步驟呼叫評判模型的詳情。已知鍵包括 `preprocess`、`analyze`、`generateScore` 和 `generateReason`；每個鍵都包含按順序排列的 `executions` 陣列。

```typescript
interface ScorerJudgeExecutionBase {
  prompt: string
  judgeModelId: string
  judgeProvider?: string
  attemptCount: number
  modelCallCount: number
  durationMs: number
}

interface ScorerJudgeExecutionSuccess extends ScorerJudgeExecutionBase {
  status: 'success'
  output: JSONValue
  usage: ScorerJudgeUsage
  cost?: {
    amount: number
    unit: string
    source: string
  }
}

interface ScorerJudgeExecutionFailure extends ScorerJudgeExecutionBase {
  status: 'failed'
  output?: JSONValue
  rawOutput?: string
  usage?: ScorerJudgeUsage
  finishReason?: string
  error: {
    name: string
    message: string
    code?: string
  }
}

type ScorerJudgeExecution = ScorerJudgeExecutionSuccess | ScorerJudgeExecutionFailure

interface ScorerJudgeUsage {
  inputTokens?: number
  outputTokens?: number
  totalTokens?: number
  reasoningTokens?: number
  cachedInputTokens?: number
  cacheCreationInputTokens?: number
}

type ScorerJudgeResults = Partial<
  Record<
    'preprocess' | 'analyze' | 'generateScore' | 'generateReason',
    { executions: ScorerJudgeExecution[] }
  >
>
```

通過步驟鍵存取對應的評判模型執行詳情：

```typescript
const execution = result.judge?.generateScore?.executions[0]

console.log(execution?.status)
console.log(execution?.judgeModelId)
console.log(execution?.usage?.totalTokens)
console.log(execution?.durationMs)
```

`status` 表示提示詞步驟的執行結果，並非被評估回答的品質。結構化輸出的回退嘗試最終成功時，會產生一條 `success` 記錄，且 `attemptCount` 大於 1；所有嘗試都失敗時，則產生一條 `failed` 記錄。

成功的執行必須有經過驗證的 `output` 和規範化的 `usage`。失敗的執行必須有 `error` 摘要，且只包含執行時實際收到的證據。只有在輸出驗證成功、隨後回呼或編排又失敗時，失敗記錄才會包含 `output`。Mastra 不會解析 `rawOutput` 來產生 `output`。

`attemptCount` 統計評判模型呼叫次數，包括結構化輸出的回退嘗試。`modelCallCount` 統計這些嘗試中已完成的模型步驟數。`durationMs` 覆蓋整個提示詞步驟的執行時間。

函數步驟不會產生 `judge` 條目。該記錄中的用量屬於評分器的評判模型，而非被評估的 Agent 或 Workflow。匯總成功執行時應按 `status` 篩選；匯總所有已完成的 Provider 用量時應包含兩種狀態。可選的 `cost` 欄位僅出現在直接報告權威成本、來源和單位的成功執行中。

使用 Mastra 指標查詢多次評分執行的匯總用量、延遲和預估成本。`judge` 記錄只描述單次評分執行，不查詢指標或 Trace。

### 執行失敗 {/* #failed-runs */}

評分器某個階段失敗時，`.run()` 回傳的 Promise 仍會被拒絕。捕捉 `ScorerRunError` 可檢查已完成的階段及其結果：

```typescript
import { ScorerRunError } from '@mastra/core/evals'

try {
  const result = await scorer.run({ input, output })
  console.log(result.score)
} catch (error) {
  if (error instanceof ScorerRunError) {
    console.log(error.failedStep)
    console.log(error.completedSteps)
    console.log(error.result?.score)

    const failedExecution = error.result?.judge?.[error.failedStep]?.executions.find(
      execution => execution.status === 'failed',
    )
    console.log(failedExecution?.error)
  }

  throw error
}
```

`ScorerRunError` 提供以下屬性：

`result` 快照包含已完成階段的輸出和評判模型執行證據。例如，`generateScore` 回傳 `0` 後，若 `generateReason` 失敗，則 `error.result.score` 為 `0`，`generateScore` 的執行狀態為 `status: 'success'`，`generateReason` 的執行狀態為 `status: 'failed'`。整次執行仍視為失敗。

提示詞步驟失敗時，`error.result` 可能只包含執行標識、輸入和一條失敗的 `judge` 記錄。函數步驟若在產生評分器欄位前失敗，則不會產生結果。

`JSON.stringify(error)` 使用標準的 `MastraError` 序列化格式，會省略 `result`，其中包括成功和失敗的評判證據。需要評分產物或失敗時的原始輸出時，請顯式讀取 `result`。

內存中的實驗結果可以保留失敗評分器已產生的分數或理由，以及 `error`、`failedStep` 和 `completedSteps`。該評分器仍視為失敗，恢復的分數不會寫入舊版的成功評分存儲。

## 步驟執行順序 {/* #step-execution-flow */}

呼叫 `.run()` 時，MastraScorer 會按以下順序執行已定義的步驟：

1. **preprocess**（可選）：提取或轉換資料
1. **analyze**（可選）：處理輸入、輸出和預處理後的資料
1. **generateScore**（必需）：計算數值分數
1. **generateReason**（可選）：解釋該分數

每個步驟都會收到前面步驟的結果，因此可以組合複雜的評估流程。

## 用法示例 {/* #usage-example */}

```typescript
const scorer = createScorer({
  name: 'Quality Scorer',
  description: 'Evaluates response quality',
})
  .preprocess(({ run }) => {
    // Extract key information
    return { wordCount: run.output.split(' ').length }
  })
  .analyze(({ run, results }) => {
    // Analyze the response
    const hasSubstance = results.preprocessStepResult.wordCount > 10
    return { hasSubstance }
  })
  .generateScore(({ results }) => {
    // Calculate score
    return results.analyzeStepResult.hasSubstance ? 1.0 : 0.0
  })
  .generateReason(({ score, results }) => {
    // Explain the score
    const wordCount = results.preprocessStepResult.wordCount
    return `Score: ${score}. Response has ${wordCount} words.`
  })

// Use the scorer
const result = await scorer.run({
  input: 'What is machine learning?',
  output: 'Machine learning is a subset of artificial intelligence...',
})

console.log(result.score) // 1.0
console.log(result.reason) // "Score: 1.0. Response has 12 words."
```
