# 快速對齊記分器

這`createPromptAlignmentScorerLLM()`函數建立一個評分器，用於評估Agent回應與使用者提示在意圖理解和需求滿足方面的一致性，以及回應的完整性和格式的適當性。

## 評分詳情 {/* #scoring-details */}

### 記分器配置 {/* #scorer-configuration */}

您可以透過調整比例參數和評估模式來自訂提示對齊評分器以滿足您的評分需求。

```typescript
const scorer = createPromptAlignmentScorerLLM({
  model: '__GATEWAY_OPENAI_MODEL__',
  options: {
    scale: 10, // Score from 0-10 instead of 0-1
    evaluationMode: 'both', // 'user', 'system', or 'both' (default)
  },
})
```

### 多輪對話 {/* #multi-turn-conversations */}

預設情況下，記分員只能看到目前回合。在對話中，回覆如下`"A"` is meaningless on its own, so the judge can't tell what the user asked for and scores the response as misaligned.

放`includeConversationHistory` to give the judge the prior turns from the agent's memory. The judge uses them to interpret the current prompt, but still scores only the current response.

```typescript
const scorer = createPromptAlignmentScorerLLM({
  model: '__GATEWAY_OPENAI_MODEL__',
  options: {
    evaluationMode: 'user',
    includeConversationHistory: { maxMessages: 6 }, // or `true` for the last 10 messages
  },
})
```

這僅影響Agent運行，其中記分器接收記住的訊息。從簡單的提示字串中獲得的分數沒有變化。

### 多維度分析 {/* #multi-dimensional-analysis */}

提示對齊透過根據評估模式進行調整的加權評分來評估四個關鍵維度的反應：

#### 使用者模式（“使用者”） {/* #user-mode-user */}

僅評估與使用者提示的一致性：

1. **意圖一致**（40%權重）：回應是否解決了使用者的核心請求
2. **要求履行**（30%權重）：如果滿足所有使用者要求
3. **完整性**（20%權重）：回應是否詳細滿足使用者需求
4. **回應適當性**（10% 權重）：格式和語氣是否符合使用者期望

#### 系統模式（“系統”） {/* #system-mode-system */}

僅評估是否符合系統準則：

1. **意圖一致**（35%權重）：回應是否遵循系統行為準則
2. **要求履行**（35% 權重）：如果遵守所有系統約束
3. **完整性**（15%權重）：回應是否遵守所有系統規則
4. **回應適當性**（15% 權重）：如果格式和音調符合系統規範

#### 兩種模式（“兩者”-預設） {/* #both-mode-both---default */}

在一次分析中一起評估使用者和系統的一致性：

* 法官根據使用者提示和系統指南評估每個維度
* 使用使用者模式權重組合所得的維度分數
* 評分器不計算單獨的系統分數，因此結果不是使用者模式和系統模式分數的混合

### 評分公式 {/* #scoring-formula */}

**使用者模式：**

```text
Weighted Score = (intent_score × 0.4) + (requirements_score × 0.3) +
                 (completeness_score × 0.2) + (appropriateness_score × 0.1)
Final Score = Weighted Score × scale
```

**系統模式：**

```text
Weighted Score = (intent_score × 0.35) + (requirements_score × 0.35) +
                 (completeness_score × 0.15) + (appropriateness_score × 0.15)
Final Score = Weighted Score × scale
```

**兩種模式（預設）：**

```text
Weighted Score = (intent_score × 0.4) + (requirements_score × 0.3) +
                 (completeness_score × 0.2) + (appropriateness_score × 0.1)
Final Score = Weighted Score × scale
```

在這兩種模式下，每個向度的得分均來自於使用者提示和系統指引的綜合分析。

**權重分配原理**:

* **使用者模式**：優先考慮使用者滿意度的意圖 (40%) 和要求 (30%)
* **系統模式**：平等地平衡行為合規性（35%）和限制（35%）
* **兩種模式**：在組合分析中使用使用者模式權重，因此使用者需求保持主要，同時仍評估系統指南

### 分數解讀 {/* #score-interpretation */}

* **0.9-1.0**= 所有尺寸均具有出色的對齊度
* **0.8-0.9**= 非常好對齊，有微小間隙
* **0.7-0.8**= 良好的一致性，但缺少一些要求或完整性
* **0.6-0.7**= 適度對齊，有明顯間隙
* **0.4-0.6**= 與實質問題的一致性不佳
* **0.0-0.4**= 對齊非常差，反應不能有效地解決提示問題

### 何時使用每種模式 {/* #when-to-use-each-mode */}

**使用者模式（`'user'`)**- 在以下情況下使用：

* 評估客戶服務回應以提高用戶滿意度
* 從使用者角度測試內容產生質量
* 衡量回應解決使用者問題的程度
* 純粹專注於請求滿足，不受系統限制

**系統模式（`'system'`)**- 在以下情況下使用：

* 審核人工智慧安全性和行為準則合規性
* 確保Agent商遵循品牌聲音和語氣要求
* 驗證對內容政策和約束的遵守情況
* 測試系統層級行為一致性

**兩種模式（`'both'`)**- 使用時（默認，建議）：

* 在遵循系統指令的同時評估回應是否滿足使用者請求
* 使用者和系統需求都很重要的生產監控

### 多智能體系統評估 {/* #multi-agent-system-evaluation */}

比較不同Agent商或型號：

```typescript oxfmt:false
const agents = [agent1, agent2, agent3];
const testPrompts = [...]; // Array of test prompts

for (const agent of agents) {
  let totalScore = 0;
  for (const prompt of testPrompts) {
    const response = await agent.run(prompt);
    const evaluation = await scorer.run({ input: prompt, output: response });
    totalScore += evaluation.score;
  }
  console.log(`${agent.name} average alignment: ${totalScore / testPrompts.length}`);
}
```

### 優秀的對齊範例 {/* #excellent-alignment-example */}

在此範例中，回應完全解決了使用者的提示並滿足了所有要求。

```typescript title="src/example-excellent-prompt-alignment.ts"
import { createPromptAlignmentScorerLLM } from '@mastra/evals/scorers/prebuilt'

const scorer = createPromptAlignmentScorerLLM({
  model: '__GATEWAY_OPENAI_MODEL__',
})

const inputMessages = [
  {
    role: 'user',
    content:
      'Write a Python function to calculate factorial with error handling for negative numbers',
  },
]

const outputMessage = {
  text: `def factorial(n):
    """Calculate factorial of a number."""
    if n < 0:
        raise ValueError("Factorial not defined for negative numbers")
    if n == 0 or n == 1:
        return 1
    return n * factorial(n - 1)`,
}

const result = await scorer.run({
  input: inputMessages,
  output: outputMessage,
})

console.log(result)
```

在此範例中，回應獲得高分，因為它為請求的 Python 階乘函數提供了負數錯誤處理。


## 與其他得分手的比較 {/* #comparison-with-other-scorers */}

|方面|迅速對齊|答案相關性 |誠信|
| - | - | - | - |
|**Focus** | Multi-dimensional prompt adherence | Query-response relevance | Context groundedness |
| **Evaluation** | Intent, requirements, completeness, format | Semantic similarity to query | Factual consistency with context |
| **Use Case** | General prompt following | Information retrieval | RAG/context-based systems |
| **Dimensions** | 4 weighted dimensions | Single relevance dimension | Single faithfulness dimension |
