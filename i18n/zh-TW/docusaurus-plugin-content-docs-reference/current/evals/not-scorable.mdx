# notScorable()

表示目前這次執行沒有可供此評分器評估的內容。請從評分器的函式步驟（通常是 `preprocess`）直接傳回此值。後續步驟會略過，因此不會呼叫評判模型；平均分數、門檻檢查與閾值只計入此評分器實際評估的執行。

若一次執行是否符合評估條件取決於本身的輸入或輸出，例如是否呼叫特定工具，請使用 `notScorable()`。若條件可由請求情境或實體中繼資料表達，請改用[適用條件篩選器](/docs/evals/overview#how-live-evaluations-work)。操作流程請參閱[自訂評分器：略過無法評分的執行](/docs/evals/custom-scorers#skipping-runs-that-cant-be-scored)。

## 使用範例 {/* #usage-example */}

以下評分器使用 LLM 評判退款處理情況。對於從未呼叫 `refundCustomer` 的執行，會在詢問評判模型前宣告該次執行無法評分：

```typescript title="src/mastra/scorers/refund-judge.ts"
import { createScorer, notScorable } from '@mastra/core/evals'
import { extractToolCalls } from '@mastra/evals/scorers/utils'

export const refundJudge = createScorer({
  id: 'refund-judge',
  description: 'Judges how well refund requests were handled',
  type: 'agent',
  judge: {
    model: '__GATEWAY_OPENAI_MODEL_LUNA__',
    instructions: 'You are a strict QA reviewer for customer-support refund handling.',
  },
})
  .preprocess(({ run }) => {
    const { tools } = extractToolCalls(run.output)
    return tools.includes('refundCustomer')
      ? { tools }
      : notScorable('refundCustomer was not called')
  })
  .generateScore({
    description: 'Score the refund handling from 0 to 1',
    createPrompt: ({ run }) =>
      `Rate this refund handling from 0 to 1:\n${JSON.stringify(run.output)}`,
  })
```

**傳回：** `NotScorable`。這是評分器流程可辨識的不透明值。請直接從步驟傳回，不要包在其他物件中。

## 行為 {/* #behavior */}

- 任何函式步驟都可傳回此值：`preprocess`、`analyze`、`generateScore` 或 `generateReason`。提示物件步驟的輸出由模型產生，因此無法傳回此值。
- 已完成的步驟會保留其結果。
- `scorer.run()` 傳回包含 `notScorable: { step, reason? }` 且沒有 `score` 鍵的結果。請參閱 [`MastraScorer`](/reference/evals/mastra-scorer)。
- 即時評分不會儲存分數紀錄。[`runEvals()`](/reference/evals/run-evals) 不會將該次執行計入平均分數、門檻檢查、閾值或最終判定，但會將其計入 `summary.notScorable`。實驗會設定 `score: null`、`error: null` 與 `notScorable`。
