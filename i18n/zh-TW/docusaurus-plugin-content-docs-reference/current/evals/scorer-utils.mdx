# 記分器實用程式

Mastra 提供實用函數來幫助從記分器運行輸入和輸出中提取和處理資料。這些實用程式在以下方面特別有用`preprocess`自訂記分器的步驟。

## 進口 {/* #import */}

```typescript
import {
  getAssistantMessageFromRunOutput,
  getReasoningFromRunOutput,
  getUserMessageFromRunInput,
  getSystemMessagesFromRunInput,
  getCombinedSystemPrompt,
  extractToolCalls,
  extractInputMessages,
  extractAgentResponseMessages,
  compareTrajectories,
  createTrajectoryTestRun,
} from '@mastra/evals/scorers/utils'
```

軌跡提取函數可從`@mastra/core/evals`:

```typescript
import {
  extractTrajectory,
  extractWorkflowTrajectory,
  extractTrajectoryFromTrace,
} from '@mastra/core/evals'
```

## 訊息提取 {/* #message-extraction */}

### `getAssistantMessageFromRunOutput` {/* #getassistantmessagefromrunoutput */}

從運行輸出中包含文字的最後一則助理訊息中提取文字內容。不帶文字的尾隨輔助訊息（例如，僅Tool呼叫訊息）將被跳過。

```typescript
const scorer = createScorer({
  id: 'my-scorer',
  description: 'My scorer',
  type: 'agent',
})
  .preprocess(({ run }) => {
    const response = getAssistantMessageFromRunOutput(run.output)
    return { response }
  })
  .generateScore(({ results }) => {
    return results.preprocessStepResult?.response ? 1 : 0
  })
```

**返回：** `string | undefined` - The assistant message text, or undefined if no assistant message is found.

### `getUserMessageFromRunInput` {/* #getusermessagefromruninput */}

從運行輸入中的第一條用戶訊息中提取文字內容。

```typescript oxfmt:false
.preprocess(({ run }) => {
  const userMessage = getUserMessageFromRunInput(run.input);

```

### `extractInputMessages` {/* #extractinputmessages */}

從所有輸入訊息中提取文字內容作為數組。

```typescript oxfmt:false
.preprocess(({ run }) => {
  const allUserMessages = extractInputMessages(run.input);
  return { conversationHistory: allUserMessages.join("\n") };
})
```

**返回：** `string[]` - Array of text strings from each input message.

### `extractAgentResponseMessages` {/* #extractagentresponsemessages */}

從所有助理回應訊息中提取文字內容作為數組。

```typescript oxfmt:false
.preprocess(({ run }) => {
  const allResponses = extractAgentResponseMessages(run.output);
  return { allResponses };
})
```

**返回：** `string[]` - Array of text strings from each assistant message.

## 推理擷取 {/* #reasoning-extraction */}

### `getReasoningFromRunOutput` {/* #getreasoningfromrunoutput */}

從運行輸出中提取推理文字。這在評估推理模型的反應時特別有用，例如`deepseek-reasoner` that produce chain-of-thought reasoning.

推理可以儲存在兩個地方：

1. `content.reasoning`- 訊息內容的字串字段
2. `content.parts`- 作為零件`type: 'reasoning'` containing `details`

```typescript
import {
  getReasoningFromRunOutput,
  getAssistantMessageFromRunOutput,
} from '@mastra/evals/scorers/utils'

const reasoningQualityScorer = createScorer({
  id: 'reasoning-quality',
  name: 'Reasoning Quality',
  description: 'Evaluates the quality of model reasoning',
  type: 'agent',
})
  .preprocess(({ run }) => {
    const reasoning = getReasoningFromRunOutput(run.output)
    const response = getAssistantMessageFromRunOutput(run.output)
    return { reasoning, response }
  })
  .analyze(({ results }) => {
    const { reasoning } = results.preprocessStepResult || {}
    return {
      hasReasoning: !!reasoning,
      reasoningLength: reasoning?.length || 0,
      hasStepByStep: reasoning?.includes('step') || false,
    }
  })
  .generateScore(({ results }) => {
    const { hasReasoning, reasoningLength } = results.analyzeStepResult || {}
    if (!hasReasoning) return 0
    // Score based on reasoning length (normalized to 0-1)
    return Math.min(reasoningLength / 500, 1)
  })
  .generateReason(({ results, score }) => {
    const { hasReasoning, reasoningLength } = results.analyzeStepResult || {}
    if (!hasReasoning) {
      return 'No reasoning was provided by the model.'
    }
    return `Model provided ${reasoningLength} characters of reasoning. Score: ${score}`
  })
```

## 系統訊息提取 {/* #system-message-extraction */}

### `getSystemMessagesFromRunInput` {/* #getsystemmessagesfromruninput */}

從運行輸入中提取所有系統訊息，包括標準系統訊息和標記系統訊息（特殊提示，如記憶體指令）。

```typescript oxfmt:false
.preprocess(({ run }) => {
  const systemMessages = getSystemMessagesFromRunInput(run.input);
  return {
    systemPromptCount: systemMessages.length,
    systemPrompts: systemMessages
  };
})
```

**返回：** `string[]` - Array of system message strings.

### `getCombinedSystemPrompt` {/* #getcombinedsystemprompt */}

將所有系統訊息組合成一個提示字串，並用雙換行符連接。

```typescript oxfmt:false
.preprocess(({ run }) => {
  const fullSystemPrompt = getCombinedSystemPrompt(run.input);
  return { fullSystemPrompt };
})
```

**返回：** `string` - Combined system prompt string.

## Tool調用提取 {/* #tool-call-extraction */}

### `extractToolCalls` {/* #extracttoolcalls */}

從運行輸出中提取有關Tool調用的信息，不包括部分調用（`partial-call` state), including tool names, call IDs, and their positions in the message array.

```typescript
const toolUsageScorer = createScorer({
  id: 'tool-usage',
  description: 'Evaluates tool usage patterns',
  type: 'agent',
})
  .preprocess(({ run }) => {
    const { tools, toolCallInfos } = extractToolCalls(run.output)
    return {
      toolsUsed: tools,
      toolCount: tools.length,
      toolDetails: toolCallInfos,
    }
  })
  .generateScore(({ results }) => {
    const { toolCount } = results.preprocessStepResult || {}
    // Score based on appropriate tool usage
    return toolCount > 0 ? 1 : 0
  })
```

**返回：**

```typescript oxfmt:false
{
  tools: string[];           // Array of tool names
  toolCallInfos: ToolCallInfo[];  // Detailed tool call information
}
```

在哪裡`ToolCallInfo` is:

```typescript
type ToolCallInfo = {
  toolName: string // Name of the tool
  toolCallId: string // Unique call identifier
  messageIndex: number // Index in the output array
  invocationIndex: number // Index within message's tool invocations
}
```

## 測試實用程式 {/* #test-utilities */}

這些實用程式有助於建立用於記分器開發的測試資料。

### `createTestMessage` {/* #createtestmessage */}

創建一個`MastraDBMessage` object for testing purposes.

```typescript
import { createTestMessage } from '@mastra/evals/scorers/utils'

const userMessage = createTestMessage({
  content: 'What is the weather?',
  role: 'user',
})

const assistantMessage = createTestMessage({
  content: 'The weather is sunny.',
  role: 'assistant',
  toolInvocations: [
    {
      toolCallId: 'call-1',
      toolName: 'weatherTool',
      args: { location: 'London' },
      result: { temp: 20 },
      state: 'result',
    },
  ],
})
```

### `createAgentTestRun` {/* #createagenttestrun */}

為測試記分機建立完整的測試運行物件。

```typescript
import { createAgentTestRun, createTestMessage } from '@mastra/evals/scorers/utils'

const testRun = createAgentTestRun({
  inputMessages: [createTestMessage({ content: 'Hello', role: 'user' })],
  output: [createTestMessage({ content: 'Hi there!', role: 'assistant' })],
})

// Run your scorer with the test data
const result = await myScorer.run({
  input: testRun.input,
  output: testRun.output,
})
```

## 軌跡實用程式 {/* #trajectory-utilities */}

### `extractTrajectory` {/* #extracttrajectory */}

提取一個`Trajectory` from agent output messages (`MastraDBMessage[]`). Converts tool invocations into `ToolCallStep` objects. The `runEvals` pipeline calls this automatically for trajectory scorers: you only need it for direct testing.

可從`@mastra/core/evals`.

```typescript
import { extractTrajectory } from '@mastra/core/evals'

const trajectory = extractTrajectory(agentOutputMessages)
// trajectory.steps — ToolCallStep[] extracted from toolInvocations
// trajectory.rawOutput — the original MastraDBMessage[] array
```

**返回：** `Trajectory`: Contains `steps: TrajectoryStep[]` and `rawOutput`.

### `extractWorkflowTrajectory` {/* #extractworkflowtrajectory */}

提取一個`Trajectory` from workflow step results. Converts `StepResult` records into `WorkflowStepStep` objects, respecting the execution path ordering.

可從`@mastra/core/evals`.

```typescript
import { extractWorkflowTrajectory } from '@mastra/core/evals'

const trajectory = extractWorkflowTrajectory(
  workflowResult.steps, // Record<string, StepResult>
  workflowResult.stepExecutionPath, // string[] (optional)
)
// trajectory.steps — WorkflowStepStep[] in execution order
```

**返回：** `Trajectory`: Contains `steps: TrajectoryStep[]`, `totalDurationMs`, and `rawWorkflowResult`.

### `extractTrajectoryFromTrace` {/* #extracttrajectoryfromtrace */}

建構層次結構`Trajectory` from observability trace spans (`SpanRecord[]`). Reconstructs the parent-child span tree and maps each span to the appropriate `TrajectoryStep` discriminated union type with nested `children`.

當有儲存空間時，這是首選的提取方法。這`runEvals` pipeline calls this automatically when the target's `Mastra` instance has a configured storage backend. It produces richer trajectories than `extractTrajectory` or `extractWorkflowTrajectory` because it captures the full execution tree, including nested agent runs, tool calls, and model generations.

可從`@mastra/core/evals`.

```typescript
import { extractTrajectoryFromTrace } from '@mastra/core/evals'

// After fetching a trace from the observability store
const traceData = await observabilityStore.getTrace({ traceId })
const trajectory = extractTrajectoryFromTrace(traceData.spans, rootSpanId)
// trajectory.steps — hierarchical TrajectoryStep[] with children
```

**參數：**

* `spans` (`SpanRecord[]`): Array of span records from a trace query.
* `rootSpanId` (`string`, optional): Span ID to use as the starting point. When omitted, uses spans with no parent.

**返回：** `Trajectory`: Contains `steps: TrajectoryStep[]` with recursive `children` and `totalDurationMs`.

#### 跨度類型映射 {/* #span-type-mapping */}

|跨度類型|軌跡步進類型 |提取的關鍵字段 |
| - | - | - |
|`TOOL_CALL` | `tool_call` | `toolArgs`, `toolResult`, `success` |
| `MCP_TOOL_CALL` | `mcp_tool_call` | `toolArgs`, `toolResult`, `mcpServer`, `success` |
| `MODEL_GENERATION` | `model_generation` | `modelId`, `promptTokens`, `completionTokens`, `finishReason` |
| `AGENT_RUN` | `agent_run` | `agentId` (from entity ID) |
| `WORKFLOW_RUN` | `workflow_run` | `workflowId` (from entity ID) |
| `WORKFLOW_STEP` | `workflow_step` | `output` |
| `WORKFLOW_CONDITIONAL` | `workflow_conditional` | Base fields only (`name`, `durationMs`, `metadata`) |
| `WORKFLOW_PARALLEL` | `workflow_parallel`|僅基底字段（`name`, `durationMs`, `metadata`) |
| `WORKFLOW_LOOP` | `workflow_loop`|僅基底字段（`name`, `durationMs`, `metadata`) |
| `WORKFLOW_SLEEP` | `workflow_sleep`|僅基底字段（`name`, `durationMs`, `metadata`) |
| `WORKFLOW_WAIT_EVENT` | `workflow_wait_event`|僅基底字段（`name`, `durationMs`, `metadata`) |
| `PROCESSOR_RUN` | `processor_run`|僅基底字段（`name`, `durationMs`, `metadata`) |

跨度與類型`GENERIC`, `MODEL_STEP`, `MODEL_CHUNK`, and `WORKFLOW_CONDITIONAL_EVAL` are skipped as noise.

### `compareTrajectories` {/* #comparetrajectories */}

將實際軌跡與預期軌跡進行比較並傳回詳細的比較結果。內部使用由`createTrajectoryAccuracyScorerCode`.

這`expected` parameter accepts either a `Trajectory` (actual trajectory) or `{ steps: ExpectedStep[] }`. When using `ExpectedStep[]`, you can match by name only or by name + stepType. You can also include data for comparison. See [Expected steps](/reference/evals/trajectory-accuracy#expected-steps) for details.

```typescript
import { compareTrajectories } from '@mastra/evals/scorers/utils'

// Using ExpectedStep[] (recommended for expectations)
// Data fields (e.g. toolArgs) are auto-compared when present on expected steps
const result = compareTrajectories(
  actualTrajectory,
  { steps: [{ name: 'search' }, { name: 'summarize', stepType: 'tool_call' }] },
  { allowRepeatedSteps: true },
)
// result.score — 0.0 to 1.0
// result.missingSteps — step names not found
// result.extraSteps — unexpected step names
// result.outOfOrderSteps — steps found but in wrong order
```

**返回：** `TrajectoryComparisonResult`

### `createTrajectoryTestRun` {/* #createtrajectorytestrun */}

為軌跡記分器建立測試運行物件。包裹一個`Trajectory` into the expected `ScorerRun` format.

```typescript
import { createTrajectoryTestRun } from '@mastra/evals/scorers/utils'

const run = createTrajectoryTestRun({
  trajectory: {
    steps: [
      { stepType: 'tool_call', name: 'search', toolArgs: { q: 'test' } },
      { stepType: 'tool_call', name: 'summarize' },
    ],
  },
})

const result = await trajectoryScorer.run(run)
```

### `checkTrajectoryEfficiency` {/* #checktrajectoryefficiency */}

根據步驟、令牌和持續時間預算評估軌跡效率。也檢測冗餘調用（具有相同參數的相同Tool）。

```typescript
import { checkTrajectoryEfficiency } from '@mastra/evals/scorers/utils'

const result = checkTrajectoryEfficiency(trajectory, {
  maxSteps: 5,
  maxTotalTokens: 2000,
  maxTotalDurationMs: 5000,
  noRedundantCalls: true,
})
// result.score — 1.0 if within all budgets, lower with penalties
// result.redundantCalls — duplicate tool+args combos
// result.overStepBudget — true if maxSteps exceeded
// result.overTokenBudget — true if maxTotalTokens exceeded
// result.overDurationBudget — true if maxTotalDurationMs exceeded
```

**返回：** `TrajectoryEfficiencyResult`

### `checkTrajectoryBlacklist` {/* #checktrajectoryblacklist */}

檢查軌跡是否包含禁止的Tool或Tool呼叫序列。

```typescript
import { checkTrajectoryBlacklist } from '@mastra/evals/scorers/utils'

const result = checkTrajectoryBlacklist(trajectory, {
  blacklistedTools: ['deleteAll', 'admin-override'],
  blacklistedSequences: [['escalate', 'admin-override']],
})
// result.score — 1.0 if no violations, 0.0 if any found
// result.violatedTools — blacklisted tools that were called
// result.violatedSequences — blacklisted sequences that were detected
```

**返回：** `TrajectoryBlacklistResult`

### `analyzeToolFailures` {/* #analyzetoolfailures */}

偵測Tool故障模式，包括重試、回退和參數更正。

```typescript
import { analyzeToolFailures } from '@mastra/evals/scorers/utils'

const result = analyzeToolFailures(trajectory, {
  maxRetriesPerTool: 2,
})
// result.score — 1.0 if no failure patterns, lower if patterns detected
// result.patterns — detected patterns (retry, fallback, arg_correction)
```

**返回：** `ToolFailureAnalysisResult`

## 完整範例 {/* #complete-example */}

這是一個完整的範例，展示瞭如何一起使用多個實用程式：

```typescript
import { createScorer } from '@mastra/core/evals'
import {
  getAssistantMessageFromRunOutput,
  getReasoningFromRunOutput,
  getUserMessageFromRunInput,
  getCombinedSystemPrompt,
  extractToolCalls,
} from '@mastra/evals/scorers/utils'

const comprehensiveScorer = createScorer({
  id: 'comprehensive-analysis',
  name: 'Comprehensive Analysis',
  description: 'Analyzes all aspects of an agent response',
  type: 'agent',
})
  .preprocess(({ run }) => {
    // Extract all relevant data
    const userMessage = getUserMessageFromRunInput(run.input)
    const response = getAssistantMessageFromRunOutput(run.output)
    const reasoning = getReasoningFromRunOutput(run.output)
    const systemPrompt = getCombinedSystemPrompt(run.input)
    const { tools, toolCallInfos } = extractToolCalls(run.output)

    return {
      userMessage,
      response,
      reasoning,
      systemPrompt,
      toolsUsed: tools,
      toolCount: tools.length,
    }
  })
  .generateScore(({ results }) => {
    const { response, reasoning, toolCount } = results.preprocessStepResult || {}

    let score = 0
    if (response && response.length > 0) score += 0.4
    if (reasoning) score += 0.3
    if (toolCount > 0) score += 0.3

    return score
  })
  .generateReason(({ results, score }) => {
    const { response, reasoning, toolCount } = results.preprocessStepResult || {}

    const parts = []
    if (response) parts.push('provided a response')
    if (reasoning) parts.push('included reasoning')
    if (toolCount > 0) parts.push(`used ${toolCount} tool(s)`)

    return `Score: ${score}. The agent ${parts.join(', ')}.`
  })
```
