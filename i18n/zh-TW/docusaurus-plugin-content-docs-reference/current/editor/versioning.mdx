# 版本控制

編輯器版本儲存Agent程式和提示區塊。資料庫支援的資源使用草稿和發布操作。程式碼支援的Agent程式會覆寫使用確定性檔案和 Git 歷史記錄。

看[Editor versioning](/docs/studio/editor#versioning) for release and experimentation patterns.

## 資料庫生命週期 {/* #database-lifecycle */}

資源記錄儲存一個`activeVersionId`, while individual snapshots don't store a lifecycle status.

|術語 |意義|
| - | - |
|最新 |最近建立的配置快照 |
|發表 |選擇的快照`activeVersionId` |
| Draft | The latest snapshot when it differs from `activeVersionId`, or when no active version exists |
| Historical | Any other retained snapshot |

儲存變更的快照欄位會建立一個新的最新版本。僅保存相同的快照欄位或更改元資料不會建立版本。

如果存在活動版本，則建立草稿不會變更處理已發佈要求的版本。發布更新`activeVersionId`. Restoring a historical version copies its configuration into a new inactive draft.

直接命名空間方法和 REST API 都同意這一點。`editor.prompt.update()` and `editor.agent.update()` both create an inactive draft. Neither assigns the new version to `activeVersionId`. To publish a version from the SDK, pass it explicitly: `editor.agent.update({ id, status: 'published', activeVersionId: version.id })`. The stored-agent REST `PATCH`路線也會建立一個非活動草稿，除非`autoPublish`已啟用，並且`POST /stored/agents/:id/versions/:versionId/activate`發布它。

當通用儲存資源沒有活動版本時，已發布的解決方案可以回退到最新快照。對於程式碼定義的Agent覆蓋，請求`status: 'published'` without an active override returns the original code agent.

## 程式碼來源 {/* #code-source */}

和`source: 'code'`, active agent overrides are serialized as deterministic JSON under `<codePath>/agents/<encodedAgentId>.json`. The default `codePath` is `./mastra/editor`.

發布初始Agent以建立文件。稍後的伺服器更新預設會建立草稿，並在該版本啟動時寫入該檔案。 Git 版本在 Studio 中是唯讀的，並使用提交訊息作為其變更訊息。預設歷史記錄掃描最多讀取 50 個最近提交，並跳過解析的 JSON 快照未更改的連續提交。

看[`MastraEditor`](/reference/editor/mastra-editor#source) for source options.

## 選擇Agent版本 {/* #select-an-agent-version */}

呼喚[`mastra.getAgentById()`](/reference/core/getAgentById) without a selector returns the registered code-defined agent. Pass `status` or `versionId` to apply a stored override. See [Select a version](/docs/studio/editor#select-a-version) for a TypeScript example.

`/api`:

```bash title="Version selection through the API"
# Published version
curl http://localhost:4111/api/agents/support-agent

# Latest draft
curl http://localhost:4111/api/agents/support-agent?status=draft

# Exact version
curl http://localhost:4111/api/agents/support-agent?versionId=abc-123
```

請參閱[Client SDK agents reference](/reference/client-js/agents#version-management) for Client SDK and React SDK selectors.

## 子Agent程式版本控制 {/* #sub-agent-versioning */}

版本覆蓋透過傳播[supervisor-agent delegation](/docs/subagents) in request context. Define selectors at three levels:

1. `Mastra`實例`versions`: Defaults for every invocation
2. 伺服器請求體`versions`: Per-request values added to request context
3. 直接的`generate()` or `stream()` `versions`: Per-invocation values

條目按Agent ID 合併。對於相同的ID，優先權是**direct invocation > request body or existing request context > Mastra instance default**.

在 Mastra 實例上設定預設值：

```typescript title="src/mastra/index.ts"
import { Mastra } from '@mastra/core'
import { MastraEditor } from '@mastra/editor'

export const mastra = new Mastra({
  agents: { supervisor, researchAgent, writerAgent },
  editor: new MastraEditor(),
  versions: {
    agents: {
      'research-agent': { status: 'published' },
      'writer-agent': { versionId: 'abc-123' },
    },
  },
})
```

覆寫一個子Agent以進行直接呼叫：

```typescript title="src/routes/experiment.ts"
const result = await supervisor.generate('Research and write about AI safety', {
  versions: {
    agents: {
      'research-agent': { status: 'draft' },
    },
  },
})
```

或在伺服器請求正文中傳遞選擇器：

```bash title="Per-request sub-agent versions"
curl -X POST http://localhost:4111/api/agents/supervisor/generate \
  -H "Content-Type: application/json" \
  -d '{
    "messages": [{ "role": "user", "content": "Research AI safety" }],
    "versions": {
      "agents": {
        "research-agent": { "status": "draft" }
      }
    }
  }'
```

如果未配置編輯器或無法解析版本，Mastra 會記錄警告並使用程式碼定義的子Agent程式。

## 儲存Agent程式 REST API {/* #stored-agent-rest-api */}

預設 Mastra 伺服器前綴是`/api`. A custom server prefix changes the paths below.

|方法|路徑|描述 |
| - | - | - |
|`GET` | `/api/stored/agents` | List stored agents |
| `POST` | `/api/stored/agents` | Create a stored agent |
| `GET` | `/api/stored/agents/:storedAgentId` | Get a stored agent |
| `PATCH` | `/api/stored/agents/:storedAgentId` | Update a stored agent |
| `DELETE` | `/api/stored/agents/:storedAgentId` | Delete a stored agent |
| `GET` | `/api/stored/agents/:storedAgentId/dependents` | List readable dependents and count hidden cross-workspace references |
| `POST` | `/api/stored/agents/:storedAgentId/export` | Export the allowed override fields as deterministic JSON |

依賴者回應列出了呼叫者可讀的Agent`id` and `name`. Its `hiddenCount` field counts cross-workspace references that the caller can't read, but only when the target agent is public.

版本管理路由嵌套在`/api/stored/agents/:storedAgentId/versions`. See [version management](/reference/client-js/agents#version-management) for operations and Client SDK methods.

客戶端 SDK 公開`listStoredAgents()`, `createStoredAgent()`, and `getStoredAgent()`. The resource returned by `getStoredAgent(id)` includes methods for updates, deletion, dependents, export, and version management.
