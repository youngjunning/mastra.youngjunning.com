# ToolProvider

`ToolProvider` 介面定義了編輯器如何發現並解析外部平台的整合工具。Mastra 提供兩個內置實現：`ComposioToolProvider` 和 `ArcadeToolProvider`。

有關 Provider 設定及 Studio 工作流程，參見[編輯器工具](/docs/studio/editor#tools)；有關已儲存的工具選擇及解析行為，參見[工具設定](/reference/editor/tools)。

## ToolProvider 介面 {/* #toolprovider-interface */}

## ComposioToolProvider {/* #composiotoolprovider */}

連線 [Composio](https://composio.dev)，使用其數百種整合工具。

### 使用示例 {/* #usage-example */}

```typescript title="src/mastra/index.ts"
import { MastraEditor } from '@mastra/editor'
import { ComposioToolProvider } from '@mastra/editor/composio'

const editor = new MastraEditor({
  toolProviders: {
    composio: new ComposioToolProvider({
      apiKey: process.env.COMPOSIO_API_KEY!,
    }),
  },
})
```

### 工具 slug {/* #tool-slugs */}

Composio 工具使用大寫 slug 格式：`GITHUB_CREATE_ISSUE`、`SLACK_SEND_MESSAGE`。

### 身分驗證 {/* #authentication */}

連線預設採用按作者劃分的範圍。設置 `defaultScope: 'caller-supplied'` 後，授權會按請求上下文中 `MASTRA_RESOURCE_ID_KEY` 解析出的呼叫方身分分組。請確保每個已驗證請求都提供穩定且唯一的資源 ID。使用 `MastraAuthWorkos` 時，可設定 `mapUserToResourceId`，將該值設為已驗證使用者的資源 ID。

Provider 如何為工具呼叫解析 Composio 使用者，取決於連線類型：

- **綁定作者的連線**（`kind: 'author'`）使用 Agent 作者的使用者身分，對固定的已連線帳戶執行操作。
- **綁定執行者的連線**（`kind: 'invoker'`）使用已驗證執行者的身分，對精確固定的帳戶執行操作。該帳戶也可以是其他使用者透過 Composio 存取控制清單（ACL）共享給執行者的帳戶。使用者 ID 優先取自已設定的 `userIdResolver`，否則取自已驗證使用者，絕不使用 Memory 的 `resourceId`。若無已驗證使用者且解析器也未傳回結果，執行者身分解析會失敗。
- **呼叫方提供的範圍**（`scope: 'caller-supplied'`）優先使用已設定的 `userIdResolver`。否則，為兼容舊行為，改用到請求上下文中的 `resourceId`。若固定了具體的已連線帳戶，執行會路由到該帳戶；否則 Composio 會在使用者分組中自動選擇。

### 使用共享帳戶執行 {/* #execute-with-a-shared-account */}

Bob 需要使用 Alice 透過 Composio 共享的帳戶執行 Salesforce 工具。請區分以下幾種身分：

| 身分 | 值 |
| - | - |
| Memory 資源 | `project_123` |
| Composio 使用者 ID | `bob` |
| 已連線帳戶 | `ca_alice_salesforce` |

按常規方式註冊 Provider。Mastra 伺服器端身分驗證會將已驗證使用者寫入請求上下文，因此大多數應用無須設定 `userIdResolver`：

```typescript title="src/mastra/index.ts"
import { Mastra } from '@mastra/core/mastra'
import { MastraEditor } from '@mastra/editor'
import { ComposioToolProvider } from '@mastra/editor/composio'

const editor = new MastraEditor({
  toolProviders: {
    composio: new ComposioToolProvider({
      apiKey: process.env.COMPOSIO_API_KEY!,
    }),
  },
})

export const mastra = new Mastra({ editor })
```

為 Agent 設定固定到 `ca_alice_salesforce` 的執行者連線。Bob 呼叫 Agent 時，Mastra 將 `bob` 作為 Composio 使用者，並將固定的帳戶 ID 作為要使用的具體已連線帳戶。Memory 資源仍是 `project_123`。隨後 Composio 檢查該帳戶的 ACL 是否允許 Bob 執行操作。

### 建立共享帳戶 {/* #create-shared-accounts */}

設置 `sharedConnections`，使透過 `scope: 'shared'` 授權的連線建立為 Composio [SHARED 帳戶](https://docs.composio.dev/docs/shared-connections)：

```typescript title="src/mastra/index.ts"
new ComposioToolProvider({
  apiKey: process.env.COMPOSIO_API_KEY!,
  sharedConnections: {
    acl: { allowAllUsers: true, notAllowedUserIds: ['contractor_1'] },
  },
})
```

若未設置 `sharedConnections`，共享範圍的連線會成為 `shared` 使用者名下的 Composio PRIVATE 帳戶。對於需要自定義連線字段的工具套件，Composio 不支援 SHARED 帳戶，因此授權會失敗，而不會退回建立 PRIVATE 帳戶。

`listConnections()` 傳回所請求使用者的 PRIVATE 和 SHARED 帳戶，還會傳回其他使用者擁有且 ACL 授權給任一所請求使用者的 SHARED 帳戶。可以像固定其他已連線帳戶一樣固定這些帳戶。

### 將應用使用者映射到 Composio 使用者 {/* #map-application-users-to-composio-users */}

如果 Composio 使用者 ID 與 Mastra 身分驗證傳回的 ID 不同，或應用必須在執行前授權已儲存的固定帳戶，請使用 `userIdResolver`。

解析器傳回 Composio 使用者 ID，或傳回 `undefined` 以採用 Provider 的預設解析方式。傳回空字符串會拋出錯誤，不會悄然改用。解析器不能替換已連線帳戶。

此示例按組織為 Composio 使用者 ID 添加命名空間，並讓應用的授權層批准精確固定的帳戶：

```typescript title="src/mastra/index.ts"
import { MASTRA_USER_KEY } from '@mastra/server/auth'
import { ComposioToolProvider } from '@mastra/editor/composio'
import { canUseConnectedAccount } from './integration-authorization'

type AuthenticatedUser = {
  id: string
  organizationId: string
}

function isAuthenticatedUser(value: unknown): value is AuthenticatedUser {
  return (
    typeof value === 'object' &&
    value !== null &&
    'id' in value &&
    typeof value.id === 'string' &&
    'organizationId' in value &&
    typeof value.organizationId === 'string'
  )
}

const composio = new ComposioToolProvider({
  apiKey: process.env.COMPOSIO_API_KEY!,
  userIdResolver: async ({ requestContext, toolkit, connectedAccountId }) => {
    const user = requestContext?.getRaw(MASTRA_USER_KEY)
    if (!isAuthenticatedUser(user)) return undefined

    if (connectedAccountId) {
      const allowed = await canUseConnectedAccount({
        actorId: user.id,
        organizationId: user.organizationId,
        provider: 'composio',
        toolkit,
        connectedAccountId,
      })
      if (!allowed) {
        throw new Error('User cannot access this connected account')
      }
    }

    return `${user.organizationId}:${user.id}`
  },
})
```

建立 Composio 連線和共享帳戶 ACL 條目時，使用同一個帶命名空間的 ID。例如在此設定中，Bob 的 Composio 使用者 ID 為 `acme:bob`。

從 `userIdResolver` 拋出錯誤可拒絕請求。在解析已儲存 Agent 的過程中，Mastra 會記錄該失敗並省略此連線關聯的工具，因此不會向 Composio 發起工具呼叫；其他連線仍可繼續解析。若直接呼叫 `resolveToolsVNext()`，則錯誤會傳回給呼叫方。

### 連線管理工具 {/* #connection-management-tools */}

Composio 提供在 Agent 聊天中啓動和監控授權的工具。設置 `allowedToolkits` 時，請包含 `composio`，使這些工具可用：

```typescript title="src/mastra/index.ts"
const editor = new MastraEditor({
  toolProviders: {
    composio: new ComposioToolProvider({
      apiKey: process.env.COMPOSIO_API_KEY!,
      allowedToolkits: ['composio', 'gmail'],
      defaultScope: 'caller-supplied',
    }),
  },
})
```

只添加 Agent 所需的連線管理工具：

| 工具 | 行為 |
| - | - |
| `COMPOSIO_MANAGE_CONNECTIONS` | 透過呼叫方擁有的會話，在聊天中建立授權鏈接。 |
| `COMPOSIO_WAIT_FOR_CONNECTIONS` | 等待呼叫方完成授權，然後 Agent 才繼續執行。 |

`COMPOSIO_WAIT_FOR_CONNECTIONS` 是可選的。若不使用它，請完成授權並傳回聊天，再讓 Agent 繼續。已連線帳戶仍與呼叫方資源 ID 關聯，供後續請求使用。

### 工具 slug {/* #tool-slugs-1 */}

Arcade 工具使用 `Toolkit.ToolName` 格式，例如 `Github.GetRepository`、`Slack.SendMessage`。

### 身分驗證 {/* #authentication-1 */}

舊版 Arcade 解析器優先使用請求上下文中的 `resourceId`，其次使用傳入的 `userId`，最後改用到共享的 `default` 身分。僅在有意共享整合時使用 `default`。多租戶隔離部署應提供可信、穩定的 `resourceId` 或顯式 `userId`，因為兩者都省略時，呼叫方之間不會隔離。
