# ToolProvider

這`ToolProvider`介面定義了編輯器如何發現和解析來自外部平台的整合Tool。 Mastra 包括兩個內建實作：`ComposioToolProvider`和`ArcadeToolProvider`.

看[Editor tools](/docs/studio/editor#tools) for provider setup and the Studio workflow. See [tool configuration](/reference/editor/tools) for stored selections and resolution behavior.

## 組合ToolProvider {/* #composiotoolprovider */}

連接到[Composio](https://composio.dev) for access to hundreds of integration tools.

### 使用範例 {/* #usage-example */}

```typescript title="src/mastra/index.ts"
import { MastraEditor } from '@mastra/editor'
import { ComposioToolProvider } from '@mastra/editor/composio'

const editor = new MastraEditor({
  toolProviders: {
    composio: new ComposioToolProvider({
      apiKey: process.env.COMPOSIO_API_KEY!,
    }),
  },
})
```

### Tool區塊 {/* #tool-slugs */}

Composio Tool使用大寫 slug 格式：`GITHUB_CREATE_ISSUE`, `SLACK_SEND_MESSAGE`.

### 驗證 {/* #authentication */}

預設情況下，連線使用每個作者範圍。放`defaultScope: 'caller-supplied'` to bucket authorization by the caller identity resolved from `MASTRA_RESOURCE_ID_KEY` in request context. Ensure each authenticated request provides a stable, unique resource ID. When using `MastraAuthWorkos`, configure `mapUserToResourceId` to set this value from the authenticated user.

Provider如何解析 Composio 使用者的Tool呼叫取決於連線：

* **作者綁定的連接** (`kind: 'author'`) execute as the agent author's user against the pinned connected account.
* **呼叫者綁定的連接** (`kind: 'invoker'`) execute as the authenticated invoker against the exact pinned account, which may be an account another user shared with the invoker through Composio's access control list (ACL). The user ID comes from `userIdResolver` when configured, then the authenticated user, and never from the Memory `resourceId`. Invoker resolution fails when no authenticated user or resolver result exists.
* **調用者提供的範圍** (`scope: 'caller-supplied'`) uses `userIdResolver` when configured. Otherwise, it falls back to the legacy `resourceId` from request context for backward compatibility. When a specific connected account is pinned, execution routes to that exact account. Otherwise, Composio auto-resolves within the user's bucket.

### 使用共享帳戶執行 {/* #execute-with-a-shared-account */}

Bob 需要使用 Alice 透過 Composio 共享的帳戶來執行 Salesforce Tool。保持每個身分獨立：

|身份 |價值|
| - | - |
|記憶體資源|`project_123` |
| Composio user ID | `bob` |
| Connected account | `ca_alice_salesforce` |

正常註冊Provider。 Mastra 伺服器身份驗證將經過身份驗證的使用者寫入請求上下文，因此大多數應用程式不需要`userIdResolver`:

```typescript title="src/mastra/index.ts"
import { Mastra } from '@mastra/core/mastra'
import { MastraEditor } from '@mastra/editor'
import { ComposioToolProvider } from '@mastra/editor/composio'

const editor = new MastraEditor({
  toolProviders: {
    composio: new ComposioToolProvider({
      apiKey: process.env.COMPOSIO_API_KEY!,
    }),
  },
})

export const mastra = new Mastra({ editor })
```

使用固定的呼叫程序連接配置Agent`ca_alice_salesforce`. When Bob invokes the agent, Mastra sends `bob` as the Composio user and the pinned account ID as the exact connected account. The Memory resource stays `project_123`. Composio then checks whether the account's ACL permits Bob to execute it.

### 建立共享帳戶 {/* #create-shared-accounts */}

放`sharedConnections` to create Composio [SHARED accounts](https://docs.composio.dev/docs/shared-connections) for connections authorized with `scope: 'shared'`:

```typescript title="src/mastra/index.ts"
new ComposioToolProvider({
  apiKey: process.env.COMPOSIO_API_KEY!,
  sharedConnections: {
    acl: { allowAllUsers: true, notAllowedUserIds: ['contractor_1'] },
  },
})
```

沒有`sharedConnections`, shared-scope connections are Composio PRIVATE accounts under the `shared` user. Composio doesn't support SHARED accounts for toolkits that require custom connection fields, so authorization fails for those toolkits instead of creating a PRIVATE account.

`listConnections()`傳回所請求使用者的 PRIVATE 和 SHARED 帳戶，以及其 ACL 向所請求使用者之一授予存取權限的其他使用者所擁有的 SHARED 帳戶。您可以像任何其他連接的帳戶一樣固定這些帳戶。

### 將應用程式用戶映射到 Composio 用戶 {/* #map-application-users-to-composio-users */}

使用`userIdResolver` when your Composio user IDs differ from the IDs returned by Mastra authentication, or when your application must authorize the stored account pin before execution.

解析器返回 Composio 用戶 ID，或者`undefined` to use the provider's default resolution. Returning an empty string throws instead of silently falling back. The resolver can't replace the connected account.

此範例按組織對 Composio 使用者命名，並要求應用程式的授權層批准確切的帳戶 PIN：

```typescript title="src/mastra/index.ts"
import { MASTRA_USER_KEY } from '@mastra/server/auth'
import { ComposioToolProvider } from '@mastra/editor/composio'
import { canUseConnectedAccount } from './integration-authorization'

type AuthenticatedUser = {
  id: string
  organizationId: string
}

function isAuthenticatedUser(value: unknown): value is AuthenticatedUser {
  return (
    typeof value === 'object' &&
    value !== null &&
    'id' in value &&
    typeof value.id === 'string' &&
    'organizationId' in value &&
    typeof value.organizationId === 'string'
  )
}

const composio = new ComposioToolProvider({
  apiKey: process.env.COMPOSIO_API_KEY!,
  userIdResolver: async ({ requestContext, toolkit, connectedAccountId }) => {
    const user = requestContext?.getRaw(MASTRA_USER_KEY)
    if (!isAuthenticatedUser(user)) return undefined

    if (connectedAccountId) {
      const allowed = await canUseConnectedAccount({
        actorId: user.id,
        organizationId: user.organizationId,
        provider: 'composio',
        toolkit,
        connectedAccountId,
      })
      if (!allowed) {
        throw new Error('User cannot access this connected account')
      }
    }

    return `${user.organizationId}:${user.id}`
  },
})
```

建立 Composio 連線和共用帳戶 ACL 條目時使用相同的命名空間 ID。例如，在此設定中 Bob 的 Composio 使用者 ID 是`acme:bob`.

`userIdResolver` to deny the request. During stored-agent resolution, Mastra logs the failure and omits tools associated with that connection, so no tool call reaches Composio. Other connections continue to resolve. When calling `resolveToolsVNext()` directly, the error is returned to the caller instead.

### 連線管理Tool {/* #connection-management-tools */}

Composio 提供了用於啟動和監控Agent程式聊天授權的Tool。什麼時候`allowedToolkits` is set, include `composio` to make these tools available:

```typescript title="src/mastra/index.ts"
const editor = new MastraEditor({
  toolProviders: {
    composio: new ComposioToolProvider({
      apiKey: process.env.COMPOSIO_API_KEY!,
      allowedToolkits: ['composio', 'gmail'],
      defaultScope: 'caller-supplied',
    }),
  },
})
```

僅新增Agent程式所需的連線管理Tool：

|Tool|行為 |
| - | - |
|`COMPOSIO_MANAGE_CONNECTIONS` | Creates an authorization link in chat through a session owned by the caller. |
| `COMPOSIO_WAIT_FOR_CONNECTIONS` | Waits for the caller to finish authorization before the agent continues. |

`COMPOSIO_WAIT_FOR_CONNECTIONS`是可選的。如果沒有它，請完成授權並返回聊天。然後要求Agent繼續。連線的帳戶仍與呼叫者資源 ID 相關聯，以供以後請求。

街機Tool的使用`Toolkit.ToolName` format: `Github.GetRepository`, `Slack.SendMessage`.

### 驗證 {/* #authentication-1 */}

舊版 Arcade 解析器使用`resourceId` from request context when available, falling back to the supplied `userId` and then to a shared `default` identity. Reserve `default` for intentionally shared integrations, and provide a trusted, stable `resourceId` or explicit `userId` in tenant-isolated deployments because omitting both doesn't isolate callers.
