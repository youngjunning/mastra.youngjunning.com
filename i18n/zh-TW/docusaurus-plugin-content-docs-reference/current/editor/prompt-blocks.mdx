# 提示區塊

提示區塊是由編輯器管理的可重複使用的指令範本。Agent程式的指令可以將內嵌文字與嵌入的提示區塊以及獨立版本提示區塊的引用結合。

看[Prompt blocks](/docs/studio/editor#prompt-blocks) for the Studio workflow and common uses.

## 區塊類型 {/* #block-types */}

|類型 |描述 |
| - | - |
|`text` | Free-form text stored only in the agent version |
| `prompt_block` | A prompt block embedded in the agent version |
| `prompt_block_ref`|獨立儲存和版本控制的提示區塊的引用 |

引用的區塊在運行時解析。最終說明中省略了缺失或未發布的參考文獻。解析的非空塊用兩個換行符連接。

以下範例將儲存的區塊和內聯文字附加到Agent：

```typescript title="src/scripts/attach-prompt.ts"
import { mastra } from '../mastra'

const editor = mastra.getEditor()!

await editor.agent.update({
  id: 'support-agent',
  instructions: [
    { type: 'prompt_block_ref', id: 'brand-voice' },
    { type: 'text', content: 'Answer only questions about Acme products.' },
  ],
})
```

## 模板值 {/* #template-values */}

模板在運行時解析請求上下文中的值。

|語法 |請求上下文 |輸出|
| - | - | - |
|<code>{'{{userName}}'}</code> | `{ userName: 'Maya' }` | `Maya` |
| <code>{'{{user.name}}'}</code> | `{ user: { name: 'Maya' } }` | `Maya` |
| <code>{"{{task \u007c\u007c 'request'}}"}</code> | `{}` | `request` |
| <code>{'{{missingValue}}'}</code> | `{}` | `{{missingValue}}` |

變數名稱必須以字母或底線開頭。後備必須是單引號或雙引號字串。沒有後備的未解決佔位符保持不變。物件和陣列被序列化為 JSON。其他值將轉換為字串。

透過傳遞值[request context](/docs/server/request-context). Editor doesn't read a separate agent `variables` field.

## 顯示條件 {/* #display-conditions */}

提示區塊可以包括控制其是否包含在最終指令中的顯示條件。每個條件由三個部分組成：

* **鑰匙**：要檢查的請求上下文字段，例如`user.role` or `account.plan`.
* **操作員**：進行比較，例如`equals`, `contains`, or `exists`.
* **價值**：要比較的值。這`exists` and `not_exists` operators don't need one.

例如，條件`user.role` `equals` `admin` includes the block only when request context contains `{ user: { role: 'admin' } }`.

|操作員|範例|當 | 時，該區塊被包含在內。
| - | - | - |
|`equals` / `not_equals` | `user.role` equals `admin` | The field strictly equals, or doesn't equal, the value |
| `contains` / `not_contains` | `user.tags` contains `beta` | A string contains the value or an array contains the item |
| `greater_than` / `less_than` | `order.total` greater than `100` | The numeric field is above or below the value |
| `greater_than_or_equal` / `less_than_or_equal` | `account.seats` greater than or equal to `10` | The numeric field is at or beyond the value |
| `in` / `not_in` | `user.region`在`['US', 'CA']`|該欄位是否在提供的陣列中 |
|`exists` / `not_exists` | `account.plan`存在 |該欄位具有或不具有非空值 |

組將條件與`AND` or `OR`. For example, this group includes a block for admins on a paid plan:

```typescript
const rules = {
  operator: 'AND',
  conditions: [
    {
      field: 'user.role',
      operator: 'equals',
      value: 'admin',
    },
    {
      field: 'account.plan',
      operator: 'in',
      value: ['pro', 'enterprise'],
    },
  ],
}
```

支援點路徑。空組的計算結果為`true`, and an unknown operator evaluates to `false`. The storage type supports up to three nested group levels.

始終包含無條件的區塊。

一個`prompt_block_ref` can also have its own `rules`. They apply only to that reference in that agent, so you can reuse one stored block under different conditions. If the stored block has rules too, both must pass.

### 具有後備功能的運行時槽 {/* #runtime-slot-with-a-fallback */}

合併內聯`prompt_block` and a conditional `prompt_block_ref` to insert a value from request context and fall back to a shared stored block when the value is missing:

```typescript title="src/scripts/attach-prompt.ts"
await editor.agent.update({
  id: 'support-agent',
  instructions: [
    { type: 'text', content: 'Follow the platform safety policy.' },
    {
      type: 'prompt_block',
      content: '{{userPrompt}}',
      rules: {
        operator: 'AND',
        conditions: [
          { field: 'userPrompt', operator: 'exists' },
          { field: 'userPrompt', operator: 'not_equals', value: '' },
        ],
      },
    },
    {
      type: 'prompt_block_ref',
      id: 'default-user-prompt',
      rules: {
        operator: 'OR',
        conditions: [
          { field: 'userPrompt', operator: 'not_exists' },
          { field: 'userPrompt', operator: 'equals', value: '' },
        ],
      },
    },
  ],
})
```

當請求上下文包含非空時`userPrompt`, the agent receives that value. Otherwise, it receives the published `default-user-prompt` block. The stored block doesn't need to know about `userPrompt`.

：：：筆記

這`exists` operator treats an empty string as present. The extra `''` conditions make an empty `userPrompt` use the fallback too.

:::

## 程式化API {/* #programmatic-api */}

透過存取提示區塊`mastra.getEditor().prompt`. See the [`prompt` namespace](/reference/editor/mastra-editor#namespaces) for complete method signatures.

建立提示區塊：

```typescript title="src/scripts/seed-prompts.ts"
import { mastra } from '../mastra'

const editor = mastra.getEditor()!

await editor.prompt.create({
  id: 'brand-voice',
  name: 'Brand voice',
  description: 'Acme tone and style guidelines',
  content: 'Write in a friendly, concise tone. Address the user as {{userName || "there"}}.',
})
```

更新現有區塊：

```typescript title="src/scripts/update-prompt.ts"
await editor.prompt.update({
  id: 'brand-voice',
  content: 'Write in a friendly, concise tone. Greet the user by name when available.',
})
```

`update()`當內容變更時建立新草稿。使用`list()` to paginate through stored blocks, `getById()` to fetch one block, and `preview(blocks, context)` to resolve templates and conditions with draft references.

## 休息API {/* #rest-api */}

預設 Mastra 伺服器前綴是`/api`. A custom server prefix changes the paths below.

|方法|路徑|描述 |
| - | - | - |
|`GET` | `/api/stored/prompt-blocks` | List stored prompt blocks |
| `POST` | `/api/stored/prompt-blocks` | Create a stored prompt block |
| `GET` | `/api/stored/prompt-blocks/:storedPromptBlockId` | Get a stored prompt block |
| `PATCH` | `/api/stored/prompt-blocks/:storedPromptBlockId` | Update a stored prompt block |
| `DELETE` | `/api/stored/prompt-blocks/:storedPromptBlockId` | Delete a stored prompt block |

## 版本解析 {/* #version-resolution */}

運行時引用解析活動的發布區塊。編輯器預覽解析最新草稿。看[Editor versioning](/docs/studio/editor#versioning) for the shared draft, publish, and restore lifecycle.
