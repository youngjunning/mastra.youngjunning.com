# Prompt blocks

Prompt blocks 是由 Editor 管理、可重複使用的指令範本。Agent 指令可同時包含內嵌文字、嵌入式 prompt blocks，以及對獨立版本化 prompt blocks 的參照。

關於 Studio 的操作流程與常見用途，請參閱 [Prompt blocks](/docs/studio/editor#prompt-blocks)。

## 區塊類型 {/* #block-types */}

| 類型 | 說明 |
| - | - |
| `text` | 僅儲存在 Agent 版本中的自由格式文字 |
| `prompt_block` | 嵌入 Agent 版本中的 prompt block |
| `prompt_block_ref` | 對個別儲存且獨立版本化的 prompt block 的參照 |

參照的區塊會在執行階段解析。缺少或尚未發布的參照不會出現在最終指令中。解析後非空的區塊會以兩個換行字元連接。

以下範例將已儲存的區塊與內嵌文字附加至 Agent：

```typescript title="src/scripts/attach-prompt.ts"
import { mastra } from '../mastra'

const editor = mastra.getEditor()!

await editor.agent.update({
  id: 'support-agent',
  instructions: [
    { type: 'prompt_block_ref', id: 'brand-voice' },
    { type: 'text', content: 'Answer only questions about Acme products.' },
  ],
})
```

## 範本值 {/* #template-values */}

範本會在執行階段從請求上下文解析值。

| 語法 | 請求上下文 | 輸出 |
| - | - | - |
| <code>{'{{userName}}'}</code> | `{ userName: 'Maya' }` | `Maya` |
| <code>{'{{user.name}}'}</code> | `{ user: { name: 'Maya' } }` | `Maya` |
| <code>{"{{task \u007c\u007c 'request'}}"}</code> | `{}` | `request` |
| <code>{'{{missingValue}}'}</code> | `{}` | `{{missingValue}}` |

變數名稱必須以字母或底線開頭。備援值必須是單引號或雙引號字串。沒有備援值且無法解析的佔位符會維持原樣。物件與陣列會序列化為 JSON；其他值會轉換為字串。

請透過[請求上下文](/docs/server/request-context)傳入值。Editor 不會讀取獨立的 Agent `variables` 欄位。

## 顯示條件 {/* #display-conditions */}

Prompt block 可以包含顯示條件，用來控制它是否納入最終指令。每個條件包含三個部分：

- **鍵**：要檢查的請求上下文欄位，例如 `user.role` 或 `account.plan`。
- **運算子**：要執行的比較，例如 `equals`、`contains` 或 `exists`。
- **值**：用於比較的值。`exists` 與 `not_exists` 運算子不需要此值。

例如，條件 `user.role` `equals` `admin` 只有在請求上下文包含 `{ user: { role: 'admin' } }` 時，才會將此區塊納入指令。

| 運算子 | 範例 | 納入區塊的條件 |
| - | - | - |
| `equals` / `not_equals` | `user.role` 等於 `admin` | 欄位嚴格等於或不等於指定值 |
| `contains` / `not_contains` | `user.tags` 包含 `beta` | 字串包含指定值，或陣列包含指定項目 |
| `greater_than` / `less_than` | `order.total` 大於 `100` | 數值欄位大於或小於指定值 |
| `greater_than_or_equal` / `less_than_or_equal` | `account.seats` 大於或等於 `10` | 數值欄位大於或等於、小於或等於指定值 |
| `in` / `not_in` | `user.region` 屬於 `['US', 'CA']` | 欄位值屬於或不屬於給定陣列 |
| `exists` / `not_exists` | `account.plan` 存在 | 欄位具有或不具有非 null 值 |

條件群組可用 `AND` 或 `OR` 組合條件。例如，以下群組只會為使用付費方案的管理員納入區塊：

```typescript
const rules = {
  operator: 'AND',
  conditions: [
    {
      field: 'user.role',
      operator: 'equals',
      value: 'admin',
    },
    {
      field: 'account.plan',
      operator: 'in',
      value: ['pro', 'enterprise'],
    },
  ],
}
```

支援點分路徑。空條件群組的求值結果為 `true`，未知運算子的結果為 `false`。儲存型別最多支援三層巢狀條件群組。

沒有條件的區塊一律會納入指令。

`prompt_block_ref` 也可以有自己的 `rules`。這些規則只作用於該 Agent 中的這筆參照，因此同一個已儲存區塊可在不同條件下重複使用。如果已儲存區塊也有規則，則兩者都必須通過。

### 具有備援值的執行階段插槽 {/* #runtime-slot-with-a-fallback */}

將內嵌的 `prompt_block` 與具有條件的 `prompt_block_ref` 組合，即可從請求上下文插入值；若該值缺少，則改用共用的已儲存區塊：

```typescript title="src/scripts/attach-prompt.ts"
await editor.agent.update({
  id: 'support-agent',
  instructions: [
    { type: 'text', content: 'Follow the platform safety policy.' },
    {
      type: 'prompt_block',
      content: '{{userPrompt}}',
      rules: {
        operator: 'AND',
        conditions: [
          { field: 'userPrompt', operator: 'exists' },
          { field: 'userPrompt', operator: 'not_equals', value: '' },
        ],
      },
    },
    {
      type: 'prompt_block_ref',
      id: 'default-user-prompt',
      rules: {
        operator: 'OR',
        conditions: [
          { field: 'userPrompt', operator: 'not_exists' },
          { field: 'userPrompt', operator: 'equals', value: '' },
        ],
      },
    },
  ],
})
```

當請求上下文包含非空的 `userPrompt` 時，Agent 會收到該值；否則會收到已發布的 `default-user-prompt` 區塊。已儲存區塊不需要知道 `userPrompt`。

：：：筆記

`exists` 運算子會將空字串視為存在。額外的 `''` 條件讓空的 `userPrompt` 也使用備援區塊。

## 程式介面 {/* #programmatic-api */}

透過 `mastra.getEditor().prompt` 存取 prompt blocks。完整方法簽章請參閱 [`prompt` 命名空間](/reference/editor/mastra-editor#namespaces)。

建立 prompt block：

```typescript title="src/scripts/seed-prompts.ts"
import { mastra } from '../mastra'

const editor = mastra.getEditor()!

await editor.prompt.create({
  id: 'brand-voice',
  name: 'Brand voice',
  description: 'Acme tone and style guidelines',
  content: 'Write in a friendly, concise tone. Address the user as {{userName || "there"}}.',
})
```

更新現有區塊：

```typescript title="src/scripts/update-prompt.ts"
await editor.prompt.update({
  id: 'brand-voice',
  content: 'Write in a friendly, concise tone. Greet the user by name when available.',
})
```

內容變更時，`update()` 會建立新草稿。使用 `list()` 分頁讀取已儲存的區塊、`getById()` 取得單一區塊，並使用 `preview(blocks, context)` 以草稿參照解析範本與條件。

## REST API {/* #rest-api */}

Mastra 伺服器的預設前綴為 `/api`。自訂伺服器前綴會改變下列路徑。

| 方法 | 路徑 | 說明 |
| - | - | - |
| `GET` | `/api/stored/prompt-blocks` | 列出已儲存的 prompt blocks |
| `POST` | `/api/stored/prompt-blocks` | 建立已儲存的 prompt block |
| `GET` | `/api/stored/prompt-blocks/:storedPromptBlockId` | 取得已儲存的 prompt block |
| `PATCH` | `/api/stored/prompt-blocks/:storedPromptBlockId` | 更新已儲存的 prompt block |
| `DELETE` | `/api/stored/prompt-blocks/:storedPromptBlockId` | 刪除已儲存的 prompt block |

## 版本解析 {/* #version-resolution */}

執行階段的參照會解析為目前生效的已發布區塊；Editor 預覽則會解析為最新草稿。關於草稿、發布與還原的共同生命週期，請參閱 [Editor 版本管理](/docs/studio/editor#versioning)。
