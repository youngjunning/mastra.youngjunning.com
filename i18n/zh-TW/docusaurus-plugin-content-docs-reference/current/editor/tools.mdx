# Tool 設定

Editor 會將選取的 Tool 儲存為 Agent 版本的一部分。儲存的設定可加入已註冊的 Tool、來自整合 Provider 的 Tool，以及來自模型上下文協定（MCP）用戶端的 Tool。

Studio 中的操作流程與常見用途請參閱 [Editor Tool](/docs/studio/editor#tools)。

## Tool 來源 {/* #tool-sources */}

| 來源 | 說明 |
| - | - |
| 已註冊的 Tool | 在 Mastra 執行階段 Tool 登錄中註冊的 Tool |
| MCP 用戶端 | 由已儲存的本機或遠端 MCP 伺服器設定提供的 Tool |
| 整合 Tool | 透過舊版整合 Provider 設定解析的 Tool |
| [Tool Provider](/reference/editor/tool-provider) | 透過註冊到 `MastraEditor` 的 Provider 解析的 Tool，例如 Composio 或 Arcade |

以程式碼定義的 Agent 會保留現有的 Tool。[`editor` 覆寫設定](/reference/agents/agent#editor-overrides)控制 Editor 能否新增或移除 Tool，或僅能修改描述。

## 描述覆寫 {/* #description-overrides */}

每個選取的 Tool 都可儲存專屬於該 Agent 的描述。此描述會改變模型看到的內容，但不會修改原始 Tool 定義。

在僅能修改描述的模式下，Editor 只會覆寫以程式碼定義的 Agent 已有 Tool 的描述。對於 MCP Tool，Agent 層級描述的優先順序高於 MCP 用戶端中儲存的描述。

如果兩個來源解析出相同的 Tool ID，後解析的 Tool 會完整取代先前的 Tool，包括其描述。請參閱[解析順序](#resolution-order)。

## 條件式 Tool 集合 {/* #conditional-tool-sets */}

Editor 可為 `tools`、`mcpClients`、`integrationTools` 和 `toolProviders` 欄位儲存條件式設定變體。執行時，系統會根據請求內容的值，對符合條件的變體進行淺層合併。

條件規則使用與[提示區塊顯示條件](/reference/editor/prompt-blocks#display-conditions)相同的運算子和巢狀規則。

條件可套用至 Tool 欄位的設定變體或 MCP 用戶端參照。目前的 Editor 解析器不會評估已儲存 Tool 項目中各 Tool 的 `rules` 值。

## 已儲存的 MCP 用戶端 {/* #stored-mcp-clients */}

`editor.mcp` 命名空間管理可重複使用的 MCP 用戶端設定。CRUD 方法簽章請參閱 [`mcp` 命名空間](/reference/editor/mastra-editor#namespaces)。

`@mastra/mcp` 是 `@mastra/editor` 的可選對等依賴套件。設定已儲存的 MCP 用戶端前，請先安裝它，以便 Editor 在執行時載入這些用戶端的 Tool：

```bash npm2yarn
npm install @mastra/mcp
```

### 傳輸方式 {/* #transports */}

| 傳輸方式 | 已儲存的設定 |
| - | - |
| `stdio` | `command`，以及可選的 `args`、`env` 和 `timeout` |
| HTTP | `url`，以及可選的 `timeout` |

已儲存的 HTTP 定義不接受任意標頭。如果請求內容中有保留值 `mastra__authToken`，Editor 會將它作為 `Authorization: Bearer` 標頭轉送。

### 篩選 {/* #filtering */}

可在兩個層級設定 MCP Tool 的允許清單：

1. **伺服器層級**：已儲存伺服器的 `tools` 對應表會限制所有使用該用戶端的 Agent 可用的 Tool。在此層級省略 `tools`，會開放伺服器的所有 Tool。
2. **Agent 層級**：Agent 的 MCP 用戶端參照會進一步限制該 Agent 可用的 Tool。在此層級省略 `tools`，則不會選取任何 Tool。

Agent 層級的 Tool 名稱可包含命名空間，也可以只用名稱。若要在 Agent 層級選取所有剩餘 Tool，請明確傳入空的 `tools` 對應表：

```typescript
const mcpClients = {
  'docs-client': { tools: {} }, // all tools
  'search-client': { tools: { docs_search: {} } }, // only docs_search
  'billing-client': {}, // no tools
}
```

### 命名空間 {/* #namespacing */}

MCP Tool 使用 `serverName_toolName` 形式的 ID 避免衝突。例如，`search` Tool 來自 `docs` 伺服器時，其 ID 為 `docs_search`。

## 解析順序 {/* #resolution-order */}

Editor 依下列順序合併 Tool 紀錄。如果 ID 相同，後面的紀錄會取代前面的紀錄。

1. 以程式碼定義的 Tool
2. 已註冊且已儲存的 Tool
3. MCP Tool
4. 舊版整合 Tool
5. V1 Tool Provider 提供的 Tool

獨立儲存的 Agent 也遵循此順序，但沒有以程式碼定義的 Tool。靜態程式碼 Agent 的覆寫只處理到舊版整合 Tool，不包含 V1 Tool Provider。

盡可能讓不同來源的 Tool 使用唯一 ID。發生 ID 衝突時，後面的 Tool 會完整取代先前的 Tool，不會合併欄位。
