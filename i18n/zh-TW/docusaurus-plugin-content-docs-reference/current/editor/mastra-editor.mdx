# MastraEditor 類

這`MastraEditor`類別設定編輯器系統。將其傳遞給`Mastra`建構函數來開啟編輯器功能，例如提示區塊、Agent程式碼覆蓋、版本控制和ToolProvider。

看[Editor](/docs/studio/editor) for an introduction to what the editor does.

## 使用範例 {/* #usage-example */}

```typescript title="src/mastra/index.ts"
import { Mastra } from '@mastra/core'
import { MastraEditor } from '@mastra/editor'

export const mastra = new Mastra({
  agents: {/* your agents */},
  editor: new MastraEditor(),
})
```

### 註冊 Builder Agent {/* #registering-the-builder-agent */}

Builder UI 針對由`createBuilderAgent()` factory from `@mastra/editor/ee`. Import the factory, invoke it, and register the returned agent under `agents` on your Mastra instance:

```typescript filename="src/mastra/index.ts"
import { Mastra } from '@mastra/core'
import { MastraEditor } from '@mastra/editor'
import { createBuilderAgent } from '@mastra/editor/ee'

export const mastra = new Mastra({
  agents: { builderAgent: createBuilderAgent() },
  editor: new MastraEditor({
    builder: { enabled: true },
  }),
})
```

鍵名（`builderAgent`) is conventional. Any key works. The `@mastra/editor/ee` subpath is gated by the Mastra Enterprise Edition license at runtime.

請參閱[Agent Builder overview](https://agent-builder.mastra.ai/#prerequisites) for the full setup checklist.

### 儲存的Agent內存 {/* #stored-agent-memory */}

這`memory` field of a stored agent accepts one of these shapes:

* `{ type: 'id', memoryId: string }`：使用在Mastra實例上註冊的記憶體實例。小編抬頭一看`memoryId` as a registry key first, then as the memory instance's `id`. The agent uses that exact instance, including its storage, processors, and working memory settings.
* `{ type: 'inline', config: SerializedMemoryConfig }`：從可序列化配置建立新的記憶體實例。
* `SerializedMemoryConfig`：未標記的內聯配置。現有的儲存Agent程式使用此形狀並繼續工作。

引用一個已註冊的記憶體實例，因此許多儲存的Agent程式共用一個配置：

```typescript title="src/scripts/seed-agent.ts"
import { mastra } from '../mastra'

const editor = mastra.getEditor()!

await editor.agent.create({
  id: 'support-agent',
  name: 'Support agent',
  instructions: 'You are a friendly support agent for Acme.',
  model: { provider: 'openai', name: '__AI_SDK_OPENAI_MODEL_BASE__' },
  memory: { type: 'id', memoryId: 'supportMemory' },
})
```

當編輯器載入Agent程式時，引用將被解析。如果沒有匹配的註冊內存`memoryId`, the agent loads without memory and the editor logs a warning that names the missing key. The stored reference isn't changed. In conditional memory, a variant whose reference isn't registered is skipped. If you register memory with `mastra.addMemory()` after an agent has loaded, call `editor.agent.clearCache(id)` so the next load picks it up. Renaming or removing a key in the Mastra `memory` config detaches memory from every stored agent that references it, so keep keys stable across deployments.

`editor.agent.clone()`當來源Agent使用已註冊的記憶體實例時儲存引用，否則儲存內聯配置。

## 方法 {/* #methods */}

### Provider訪問 {/* #provider-access */}

#### `getToolProvider(id)` {/* #gettoolproviderid */}

透過 ID 傳回已註冊的ToolProvider。

```typescript
const composio = mastra.getEditor()?.getToolProvider('composio')
```

#### `getToolProviders()` {/* #gettoolproviders */}

傳回所有已註冊的ToolProvider作為`Record<string, ToolProvider>`.

#### `getProcessorProvider(id)` {/* #getprocessorproviderid */}

按 ID 返回已註冊的處理器Provider。

#### `getProcessorProviders()` {/* #getprocessorproviders */}

傳回所有已註冊的處理器Provider。

#### `getFilesystemProviders()` {/* #getfilesystemproviders */}

傳回所有已註冊的檔案系統Provider。

#### `getSandboxProviders()` {/* #getsandboxproviders */}

傳回所有已註冊的沙箱Provider。

#### `getBlobStoreProviders()` {/* #getblobstoreproviders */}

傳回所有已註冊的 blob 儲存Provider。

### 來源 {/* #source */}

#### `getSource()` {/* #getsource */}

返回配置的來源（`'code'` or `'db'`), or `undefined` when the editor was constructed without an explicit `source`.

```typescript
const source = mastra.getEditor()?.getSource()
```

返回：`'code' | 'db' | undefined`

什麼時候`source` is omitted, Editor uses the configured database storage even though `getSource()` returns `undefined`. See [Editor storage options](/docs/studio/editor#choose-where-changes-are-stored) for the storage workflows and [code-source versioning](/reference/editor/versioning#code-source) for activation and Git history behavior.
