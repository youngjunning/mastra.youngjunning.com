# MastraEditor 類

`MastraEditor` 類別負責設定編輯器系統。將實例傳入 `Mastra` 建構函式，即可啟用提示詞區塊、Agent 程式碼覆寫、版本管理與 Tool Provider 等編輯器功能。

編輯器功能介紹請參閱 [Editor](/docs/studio/editor)。

## 使用範例 {/* #usage-example */}

```typescript title="src/mastra/index.ts"
import { Mastra } from '@mastra/core'
import { MastraEditor } from '@mastra/editor'

export const mastra = new Mastra({
  agents: {/* your agents */},
  editor: new MastraEditor(),
})
```

## Agent Builder {/* #agent-builder */}

`builder` 欄位可啟用 [Agent Builder](https://agent-builder.mastra.ai/)，這是建立及編輯已儲存 Agent 的瀏覽器介面。相關文件包括：

* [Agent Builder 概述](https://agent-builder.mastra.ai/)：概念與入門指南。
* [AgentBuilderOptions](https://agent-builder.mastra.ai/reference/agent-builder-options)：完整的選項結構。
* [BuilderAgentDefaults](https://agent-builder.mastra.ai/reference/builder-agent-defaults)：管理員為新 Agent 固定的預設值。
* [builder.configuration.agent.models](https://agent-builder.mastra.ai/reference/builder-models)：允許使用的模型及預設模型。

### 註冊 Builder Agent {/* #registering-the-builder-agent */}

Builder 介面使用 `createBuilderAgent()` 工廠函式（來自 `@mastra/editor/ee`）建立的 Agent。匯入並呼叫該函式，再將傳回的 Agent 註冊在 Mastra 執行個體的 `agents` 欄位中：

```typescript filename="src/mastra/index.ts"
import { Mastra } from '@mastra/core'
import { MastraEditor } from '@mastra/editor'
import { createBuilderAgent } from '@mastra/editor/ee'

export const mastra = new Mastra({
  agents: { builderAgent: createBuilderAgent() },
  editor: new MastraEditor({
    builder: { enabled: true },
  }),
})
```

鍵名 `builderAgent` 只是慣例，也可以使用其他鍵名。`@mastra/editor/ee` 子路徑在執行階段受 Mastra 企業版授權限制。

完整設定清單請參閱 [Agent Builder 概述](https://agent-builder.mastra.ai/#prerequisites)。

### 已儲存 Agent 的 Memory {/* #stored-agent-memory */}

已儲存 Agent 的 `memory` 欄位支援以下形式：

* `{ type: 'id', memoryId: string }`：使用已在 Mastra 執行個體中註冊的 Memory 執行個體。編輯器先以 `memoryId` 作為登錄鍵查找，再以 Memory 執行個體的 `id` 查找。Agent 使用找到的同一個執行個體，包括其儲存空間、處理器及工作記憶設定。
* `{ type: 'inline', config: SerializedMemoryConfig }`：依據可序列化設定建立新的 Memory 執行個體。
* `SerializedMemoryConfig`：不帶類型標記的行內設定。現有的已儲存 Agent 仍可使用此形式。

參照已註冊的 Memory 執行個體，可讓多個已儲存 Agent 共用同一份設定：

```typescript title="src/scripts/seed-agent.ts"
import { mastra } from '../mastra'

const editor = mastra.getEditor()!

await editor.agent.create({
  id: 'support-agent',
  name: 'Support agent',
  instructions: 'You are a friendly support agent for Acme.',
  model: { provider: 'openai', name: '__AI_SDK_OPENAI_MODEL_BASE__' },
  memory: { type: 'id', memoryId: 'supportMemory' },
})
```

編輯器載入 Agent 時會解析此參照。若找不到與 `memoryId` 相符的已註冊 Memory，Agent 會在沒有 Memory 的情況下載入；編輯器會記錄一則含缺失鍵名的警告，且不會更改已儲存的參照。對於條件式 Memory，參照尚未註冊的變體會被略過。若 Agent 載入後才透過 `mastra.addMemory()` 註冊 Memory，請呼叫 `editor.agent.clearCache(id)`，讓下次載入使用新註冊的執行個體。重新命名或移除 Mastra `memory` 設定中的鍵，會使所有參照該鍵的已儲存 Agent 失去關聯，因此跨部署應維持鍵名不變。

來源 Agent 使用已註冊的 Memory 執行個體時，`editor.agent.clone()` 會儲存參照；否則會儲存行內設定。

## 方法 {/* #methods */}

### 存取 Provider {/* #provider-access */}

#### `getToolProvider(id)` {/* #gettoolproviderid */}

依 ID 傳回已註冊的 Tool Provider。

```typescript
const composio = mastra.getEditor()?.getToolProvider('composio')
```

#### `getToolProviders()` {/* #gettoolproviders */}

以 `Record<string, ToolProvider>` 形式傳回所有已註冊的 Tool Provider。

#### `getProcessorProvider(id)` {/* #getprocessorproviderid */}

依 ID 傳回已註冊的 Processor Provider。

#### `getProcessorProviders()` {/* #getprocessorproviders */}

傳回所有已註冊的 Processor Provider。

### 來源 {/* #source */}

#### `getSource()` {/* #getsource */}

傳回已設定的來源（`'code'` 或 `'db'`）；未明確指定時傳回 `undefined`（即建構時未傳入 `source`）。

```typescript
const source = mastra.getEditor()?.getSource()
```

返回：`'code' | 'db' | undefined`

省略 `source` 時，即使 `getSource()` 傳回 `undefined`，編輯器仍會使用已設定的資料庫儲存空間。儲存流程請參閱 [編輯器儲存選項](/docs/studio/editor#choose-where-changes-are-stored)；啟用及 Git 歷史紀錄的行為請參閱 [程式碼來源版本管理](/reference/editor/versioning#code-source)。
