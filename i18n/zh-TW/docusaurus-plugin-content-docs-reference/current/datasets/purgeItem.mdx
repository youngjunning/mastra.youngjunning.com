# 數據集.purgeItem()

**添加於：** `@mastra/core@1.65.0`

從每個歷史版本、刪除邏輯刪除和連結的實驗結果中永久清除資料集項目的內容。使用[`deleteItem()`](/reference/datasets/deleteItem) instead when you only need to remove an item from the current dataset version.

## 使用範例 {/* #usage-example */}

```typescript
import { Mastra } from '@mastra/core'

const mastra = new Mastra({/* storage config */})

const dataset = await mastra.datasets.get({ id: 'dataset-id' })

await dataset.purgeItem({ itemId: 'item-id' })
```

## 行為 {/* #behavior */}

清除會以編輯值取代現有歷史記錄行和刪除邏輯刪除中項目的內容字段，並在其元資料中新增清除標記。相同的欄位以及標籤和註釋將從連結到該資料集項目的實驗結果中刪除。清除後提交的實驗結果寫入會與編輯內容一起儲存。

清除與並發資料集項編寫器序列化或衝突，但不保證哪個操作會先完成。如果一個突變`updateItem()` call loses the race, it re-reads the purge marker and rejects with `DATASET_ITEM_PURGED`. `deleteItem()` remains idempotent, and any deletion tombstone created during the race stays redacted.

正常項目突變使用緩慢變化的維度類型 2 (SCD-2) 版本控制。永久清除有意覆蓋擦除的歷史不變性，同時保留專案身分和資料集版本時間軸。它不會建立新的資料集版本。版本固定讀取仍然可以傳回專案的行骨架，但其清除的內容不再可用。實驗計數器和審核狀態也被保留。

MongoDB 儲存需要具有事務支援的副本集或分片部署。如果交易不可用，則操作會在變更專案或其實驗結果之前失敗。

`externalId`保持不變，因為 Mastra 使用它作為身份密鑰。不要將敏感資料儲存在`externalId`.

清除是冪等的並且無法撤銷。
