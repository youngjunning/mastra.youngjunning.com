# dataset.purgeItem()

**新增於：** `@mastra/core@1.65.0`

從每個歷史版本、刪除墓碑及關聯的實驗結果中永久清除資料項目內容。若只需從目前資料集版本移除資料項目，請改用 [`deleteItem()`](/reference/datasets/deleteItem)。

## 使用範例 {/* #usage-example */}

```typescript
import { Mastra } from '@mastra/core'

const mastra = new Mastra({/* storage config */})

const dataset = await mastra.datasets.get({ id: 'dataset-id' })

await dataset.purgeItem({ itemId: 'item-id' })
```

## 行為 {/* #behavior */}

永久清除會將現有歷程記錄與刪除墓碑中的資料項目內容欄位替換為遮蔽值，並在其中繼資料加入清除標記。與該資料項目關聯的實驗結果中，相同欄位以及標籤和註解也會被清除。清除後提交的實驗結果寫入會以遮蔽內容儲存。

永久清除會與並行的資料項目寫入序列化執行或發生衝突，但不保證哪個操作先完成。若修改型 `updateItem()` 呼叫在競態中失敗，它會重新讀取清除標記，並以 `DATASET_ITEM_PURGED` 拒絕要求。`deleteItem()` 仍保持冪等，競態期間建立的任何刪除墓碑也會保持遮蔽狀態。

一般資料項目變更使用緩慢變動維度第 2 型（SCD-2）版本控制。永久清除會為滿足抹除需求而刻意覆寫歷史不可變性，同時保留資料項目身分與資料集版本時間軸。它不會建立新的資料集版本。鎖定版本的讀取仍可回傳資料項目的記錄骨架，但已清除的內容不再可用。實驗計數與檢閱狀態也會保留。

MongoDB 儲存需要支援交易的複本集或分片部署。若交易不可用，操作會在變更資料項目或其實驗結果前失敗。

`externalId` 保持不變，因為 Mastra 將它用作身分鍵。請勿在 `externalId` 中儲存敏感資料。

永久清除是冪等操作，且無法復原。
