# chatRoute()

建立以 AI SDK 格式串流傳送 Agent 對話的聊天路由處理函式。此函式註冊 HTTP `POST` 端點，接收訊息、執行 Agent，再以相容 AI SDK 的格式將回應串流傳送給用戶端。請在[自訂 API 路由](/docs/server/custom-api-routes)中使用。

如果需要不依賴特定框架的處理函式，請使用 [`handleChatStream()`](/reference/ai-sdk/handle-chat-stream)。

`chatRoute()` 維持現有的 AI SDK v5 預設行為。如果應用程式使用 AI SDK v6 的型別定義，請傳入 `version: 'v6'`。

:::note 連線中斷時的行為

預設情況下，`chatRoute()` 會將傳入請求的 `AbortSignal` 傳給 `agent.stream()`。如果用戶端中斷連線，Mastra 會中止進行中的產生作業。

設定 `resumable: true` 可讓產生作業在斷線後繼續，並允許 AI SDK UI 重新連接進行中的串流。可恢復的聊天不支援以 abort 取消：伺服器無法區分 `useChat().stop()`、頁面重新整理與網路中斷。

:::

## 使用範例 {/* #usage-example */}

此範例示範如何在 `/chat` 端點設定聊天路由，並使用 ID 為 `weatherAgent` 的 Agent。

```typescript title="src/mastra/index.ts"
import { Mastra } from '@mastra/core'
import { chatRoute } from '@mastra/ai-sdk'

export const mastra = new Mastra({
  server: {
    apiRoutes: [
      chatRoute({
        path: '/chat',
        agent: 'weatherAgent',
      }),
    ],
  },
})
```

也可以根據 `agentId` 在執行階段動態選擇 Agent。URL `/chat/weatherAgent` 會解析至 ID 為 `weatherAgent` 的 Agent。

```typescript title="src/mastra/index.ts"
import { Mastra } from '@mastra/core'
import { chatRoute } from '@mastra/ai-sdk'

export const mastra = new Mastra({
  server: {
    apiRoutes: [
      chatRoute({
        path: '/chat/:agentId',
      }),
    ],
  },
})
```

## 可恢復的串流 {/* #resumable-streams */}

在 `resumable: true` 設定下使用 `chatRoute()`，並在 `resume: true` 設定下使用 AI SDK UI 的 `useChat()`，即可在重新整理頁面或網路中斷後重新連接。此路由工廠會傳回包含以下兩項的陣列：

- `POST <path>`：啟動 Agent 執行。請求中的 AI SDK 聊天 ID 會成為 Mastra 記憶執行緒 ID。
- `GET <path>/:chatId/stream`：重播快取事件並追蹤進行中的執行。執行已結束、不可用、已過期或不在呼叫端範圍內時，路由會傳回 `204`。

將傳回的陣列作為 `server.apiRoutes` 的一個項目傳入。Mastra 設定伺服器時會攤平巢狀路由陣列。

```typescript title="src/mastra/index.ts"
import { Mastra } from '@mastra/core'
import { chatRoute } from '@mastra/ai-sdk'

export const mastra = new Mastra({
  server: {
    apiRoutes: [
      chatRoute({
        path: '/chat/:agentId',
        resumable: true,
      }),
    ],
  },
})
```

作用中執行的探索僅限目前處理程序。重新連接請求必須到達啟動產生作業的同一個伺服器處理程序。可恢復模式不會轉送請求的 `AbortSignal`，因此 `useChat().stop()` 只會關閉用戶端連線，不會取消 Agent 執行。

如果聊天使用資源 ID，請透過驗證中介軟體在請求內容中設定 `MASTRA_RESOURCE_ID_KEY`。不要只在 POST 請求本文的 `memory.resource` 中傳入資源 ID：重新連接的 GET 請求沒有本文，因此 `chatRoute()` 會以 `400` 拒絕這種設定。

## 附加配置 {/* #additional-configuration */}

可以使用 [`prepareSendMessagesRequest`](https://ai-sdk.dev/docs/reference/ai-sdk-ui/use-chat#transport.default-chat-transport.prepare-send-messages-request) 自訂傳送至聊天路由的請求，例如將額外設定傳給 Agent：

```typescript
const { error, status, sendMessage, messages, stop } = useChat({
  transport: new DefaultChatTransport({
    api: 'http://localhost:4111/chat',
    prepareSendMessagesRequest({ messages }) {
      return {
        body: {
          // With memory configured, send only the new message. Mastra loads the
          // rest of the conversation from storage.
          messages: [messages[messages.length - 1]],
          // Pass memory config
          memory: {
            thread: 'user-1',
            resource: 'user-1',
          },
        },
      }
    },
  }),
})
```

不使用記憶時，請傳送完整的 `messages` 陣列，聊天路由會將其作為請求內容。

使用記憶時，已儲存的執行緒是資料來源，因此 `regenerate` 和在 `useChat` 中編輯較早的訊息都不會變更它。若要修改已儲存的紀錄，請使用 `memory.saveMessages` 或記憶儲存區的 `updateMessages`，然後傳送新訊息。
