# withSseHeartbeat()

包裝伺服器傳送事件（SSE）的 `Response`，在底層串流閒置時定期送出 `: heartbeat` 註解。代理伺服器與負載平衡器常會關閉一段時間沒有位元組傳輸的連線，導致長時間推理或緩慢的 Tool 呼叫期間回應中斷。

使用 [`handleChatStream()`](/reference/ai-sdk/handle-chat-stream)、[`handleWorkflowStream()`](/reference/ai-sdk/handle-workflow-stream) 或 [`handleNetworkStream()`](/reference/ai-sdk/handle-network-stream) 自行建立回應時，可使用此函式。[`chatRoute()`](/reference/ai-sdk/chat-route) 會透過 `heartbeatMs` 選項在內部套用相同的包裝邏輯。

## 使用範例 {/* #usage-example */}

Next.js App Router 範例：

```typescript title="app/api/chat/route.ts"
import { handleChatStream, withSseHeartbeat } from '@mastra/ai-sdk'
import { createUIMessageStreamResponse } from 'ai'
import { mastra } from '@/src/mastra'

export async function POST(req: Request) {
  const params = await req.json()
  const stream = await handleChatStream({
    mastra,
    agentId: 'weatherAgent',
    version: 'v7',
    params,
  })
  return withSseHeartbeat(createUIMessageStreamResponse({ stream }), 15000)
}
```

請在回應編碼後再包裝。`handleChatStream()` 回傳 UI 訊息區塊串流；心跳是原始 SSE 註解，只有這些區塊序列化為傳輸格式後才能插入。

## 回傳值 {/* #returns */}

回傳一個 `Response`，以串流傳送原始回應主體，並在閒置期間插入心跳註解。若省略 `heartbeatMs`、其值小於等於 `0`，或回應沒有主體，則會原樣回傳輸入的回應。

## 行為 {/* #behavior */}

- 心跳只會插入完整 SSE 影格之間，不會拆分尚未傳送完畢的影格。
- 來源資料、串流結束與串流錯誤，始終優先於到期的心跳。
- 取消包裝後的回應會同時取消來源串流，並清除待觸發的心跳計時器。
- 啟用心跳時，若傳入的值無法由計時器排程，則會擲出 `RangeError`（非有限數值或大於 `2147483647` 的值）。開始串流傳送前，可使用 `assertValidHeartbeatMs()` 對使用者提供的設定執行相同檢查。
