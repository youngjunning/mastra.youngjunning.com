# withSseHeartbeat()

包裝伺服器發送的事件`Response`所以它發出週期性的`: heartbeat`當底層流空閒時發表評論。Agent和負載平衡器通常會關閉一段時間內不發送任何位元組的連接，這會在長時間推理突發或緩慢的Tool呼叫期間丟棄回應。

當您自己建立回應時使用此選項[`handleChatStream()`](/reference/ai-sdk/handle-chat-stream), [`handleWorkflowStream()`](/reference/ai-sdk/handle-workflow-stream), or [`handleNetworkStream()`](/reference/ai-sdk/handle-network-stream). [`chatRoute()`](/reference/ai-sdk/chat-route)透過其內部應用相同的包裝器`heartbeatMs`選項。

## 使用範例 {/* #usage-example */}

Next.js 應用程式路由器範例：

```typescript title="app/api/chat/route.ts"
import { handleChatStream, withSseHeartbeat } from '@mastra/ai-sdk'
import { createUIMessageStreamResponse } from 'ai'
import { mastra } from '@/src/mastra'

export async function POST(req: Request) {
  const params = await req.json()
  const stream = await handleChatStream({
    mastra,
    agentId: 'weatherAgent',
    version: 'v7',
    params,
  })
  return withSseHeartbeat(createUIMessageStreamResponse({ stream }), 15000)
}
```

編碼後包裝回應。`handleChatStream()` returns a stream of UI message chunks, and heartbeats are raw SSE comments that only exist once those chunks are serialized to the wire format.

## 退貨 {/* #returns */}

一個`Response` that streams the source body with heartbeat comments inserted during idle periods. The input response is returned unchanged when `heartbeatMs` is omitted, is `0` or less, or the response has no body.

## 行為 {/* #behavior */}

* 心跳僅插入完整的 SSE 幀之間，因此部分交付的幀永遠不會被分割。
* 來源資料、流完成和流錯誤始終優先於到期的心跳。
* 取消包裝的回應將取消來源流並清除待處理的心跳計時器。
* 一個`RangeError` is thrown when heartbeats are enabled with a value that can't be scheduled with a timer, meaning a non-finite number or a value greater than `2147483647`. Use `assertValidHeartbeatMs()` to apply the same check to user-supplied configuration before you start streaming.
