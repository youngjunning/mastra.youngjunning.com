# Mastra.addDynamicWorkflows()

:::beta

在 API 穩定之前，即使不提高主要版本號，也可能引入破壞性變更。

:::

`.addDynamicWorkflows()` 方法會新增一組可能互相參照的動態 Workflow 定義。典型情境是一個根 Workflow 及其巢狀的輔助 Workflow，而且這些定義先前都尚未存在。

系統會預先驗證整個定義套件，再依相依順序註冊各成員，確保輔助 Workflow 一律在巢狀使用它的 Workflow 之前就緒。

[`addDynamicWorkflow()`](/reference/core/addDynamicWorkflow) 適用於只新增一個成員的情況。

## 使用範例 {/* #usage-example */}

```typescript
await mastra.addDynamicWorkflows([
  helperDefinition, // nested by the root — order in the array doesn't matter
  rootDefinition, // graph contains { type: 'workflow', workflowId: helperDefinition.id }
])
```

## 傳回值 {/* #returns */}

傳回一個 Promise；所有成員完成驗證、註冊與持久化後，該 Promise 即告完成。

## 行為 {/* #behavior */}

* 參照會從執行個體 registry 與定義套件自身 ID 的聯集中解析，因此根 Workflow 可以巢狀使用同一次呼叫新增的輔助 Workflow。註冊順序由相依圖決定，與陣列順序無關。
* 被拒絕的定義套件不會註冊任何內容。系統會在修改任何內容前偵測重複 ID、無效成員與相依循環；若註冊或持久化途中失敗，記憶體中的 registry 會還原至先前狀態。
* 儲存空間寫入會在最後執行。若定義套件寫入途中發生儲存層級錯誤，可能留下部分已寫入的資料列，但 registry 仍會回復；這些孤立資料列在下次啟動前不會生效。
