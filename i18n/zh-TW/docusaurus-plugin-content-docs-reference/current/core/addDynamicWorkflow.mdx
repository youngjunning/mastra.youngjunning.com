# Mastra.addDynamicWorkflow()

:::beta

API 穩定前，可能出現未提升主版本號的破壞性變更。

:::

`.addDynamicWorkflow()` 會驗證動態 Workflow 定義，將其註冊為實例中可執行的 Workflow，並透過 `workflowDefinitions` 儲存領域持久化。註冊後，可像其他 Workflow 一樣透過 [`getWorkflow()`](/reference/core/getWorkflow) 執行。

完整設定範例請參閱[動態 Workflow](/docs/workflows/dynamic-workflows)；接受的欄位與圖節點請參閱[動態 Workflow 定義參考](/reference/workflows/dynamic-workflow-definition)。

## 使用範例 {/* #usage-example */}

```typescript
await mastra.addDynamicWorkflow({
  id: 'greeting-workflow',
  description: 'Returns a greeting for the supplied name',
  inputSchema: {
    type: 'object',
    properties: { name: { type: 'string' } },
    required: ['name'],
  },
  outputSchema: {
    type: 'object',
    properties: { message: { type: 'string' } },
    required: ['message'],
  },
  graph: [
    {
      type: 'mapping',
      id: 'create-greeting',
      mapConfig: JSON.stringify({
        message: { template: 'Hello, ${initData.name}!' },
      }),
    },
  ],
})

const run = await mastra.getWorkflow('greeting-workflow').createRun()
const result = await run.start({ inputData: { name: 'Ada' } })
```

## 回傳值 {/* #returns */}

回傳 Promise：定義完成驗證及註冊後便會兌現；若儲存提供 `workflowDefinitions` store，亦會先完成持久化。

## 行為 {/* #behavior */}

- 在修改任何內容前，會完整驗證定義的結構、參照及 schema 流程。圖中參照的 Agent、Tool 與 Workflow 必須已註冊至目前實例。
- 以既有 ID 加入定義，會同時取代已儲存的定義與目前註冊的 Workflow。執行中的任務仍沿用啟動時的圖。
- 若儲存配接器不支援 `workflowDefinitions` 領域，Workflow 仍會經過驗證並註冊於記憶體，但重新啟動後定義會遺失。
- 若要同時加入根 Workflow 及其巢狀的輔助 Workflow，請使用 [`addDynamicWorkflows()`](/reference/core/addDynamicWorkflows)。
