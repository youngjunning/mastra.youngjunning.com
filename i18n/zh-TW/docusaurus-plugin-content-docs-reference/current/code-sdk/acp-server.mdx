# ACP server

Mastra Code 透過 Agent Client Protocol (ACP) 提供程式設計 Agent 對話服務。ACP 用戶端將伺服器作為子程序啟動，並透過標準輸入與標準輸出交換以換行字元分隔的 JSON-RPC 訊息。標準錯誤輸出用於診斷資訊。

此伺服器將編輯器或其他 ACP 用戶端連接至 Mastra Code。若要將 Mastra Agent 連接至外部 ACP 伺服器，請使用 [ACP 連線](/docs/connections/acp)。

## 啟動伺服器 {/* #start-the-server */}

安裝 `mastracode` CLI 後，請將用戶端設定為執行：

```bash
mastracode --acp
```

如果用戶端支援命令與引數欄位，可使用：

```json
{
  "command": "mastracode",
  "args": ["--acp"]
}
```

初始化後，用戶端會呼叫 `session/new`，傳入絕對路徑 `cwd` 與 `mcpServers` 陣列。回應包含工作階段 ID 與可選的設定項目。後續提示與設定請求都必須帶入此 ID。

## 身分驗證 {/* #authentication */}

若尚未設定模型 Provider，`session/new` 會傳回 `auth_required` 錯誤；用戶端接著可提供 `initialize` 回應所列的驗證方法：

| 方法 ID | 類型 | 行為 |
| - | - | - |
| `openai-codex` | Agent | 開啟瀏覽器，使用 ChatGPT Plus 或 Pro 訂閱登入。 |
| `kimi-for-coding` | Agent | 開啟瀏覽器，核准 Kimi For Coding 裝置登入。 |
| `xai` | Agent | 開啟瀏覽器，核准 xAI 裝置登入。 |
| `anthropic` | Terminal | 執行 `mastracode login --provider anthropic`，使用 Claude Pro 或 Max 訂閱登入。 |
| `github-copilot` | Terminal | 執行 `mastracode login --provider github-copilot`，使用 GitHub Copilot 登入。 |
| `mastracode-login` | Terminal | 執行 `mastracode login`，選擇任一 Provider 或儲存 API 金鑰。 |

只有宣告支援終端驗證的用戶端才會收到終端類驗證方法。

對於 Agent 類驗證方法，`authenticate` 會在伺服器程序內完成登入，並在儲存憑證後傳回。如果 Provider 需要輸入內容（例如要貼上的驗證碼），請求會失敗，並提示在終端機執行 `mastracode login`。

伺服器程序環境中的 API 金鑰也視為已設定的 Provider。ACP 工作階段不會將專案 `.env` 檔案載入共用程序環境。新工作階段無須重新啟動伺服器即可讀取已儲存的憑證。如果預設模型的 Provider 尚未設定，新工作階段會改用已設定 Provider 的預設模型，例如在 Anthropic 登入後使用 `anthropic/claude-fable-5`。

await acpMain()

傳回 `Promise<void>`。此進入點會接管程序的標準串流與訊號處理常式。關閉標準輸入會釋放工作階段。收到 `SIGINT` 或 `SIGTERM` 後，程序最多等待十秒完成清理再結束。清理逾時或伺服器發生致命故障時，結束狀態碼為 `1`。

CLI 的 `--dangerous-auto-approve` 旗標可啟用相同的核准覆寫選項。`coAuthor` 的預設值請參閱[提交署名](/reference/code-sdk/mount-agent-controller#commit-attribution)。

## 工作階段與 MCP 伺服器 {/* #sessions-and-mcp-servers */}

每個工作階段都有獨立的執行環境與工作目錄。伺服器透過 stdio 或 HTTP 連接用戶端提供的 Model Context Protocol (MCP) 伺服器。不支援舊版 SSE 伺服器；使用它們會傳回無效參數錯誤。Stdio 程序會收到工作階段的工作目錄與提供的環境變數。HTTP 連線會收到提供的標頭。伺服器名稱重複，或用戶端與伺服器初始化失敗時，會傳回錯誤。

同一工作階段內的提示與設定變更會依序執行。不同工作階段可以並行執行。`session/cancel` 會停止指定工作階段目前進行中的回合，並取消佇列中的提示。

## 模型與推理控制 {/* #model-and-reasoning-controls */}

`session/new` 回應透過 `configOptions` 提供模型、模式與推理強度的選項。請將傳回的選項值用於 `session/set_config_option`：

```typescript
await connection.setSessionConfigOption({
  sessionId,
  configId: 'thought_level',
  value: 'high',
})
```

模型選項會保留完整的 Provider 路由 ID，且不列出尚未設定憑證的 Provider。即使探索結果未傳回工作階段已儲存的模型，該模型仍可使用。模式與模型變更會等待目前回合結束。

推理強度選項遵循所選模型的政策。Provider 可能會調整要求的等級。每個工作階段啟動時只讀取一次預設設定；模式變更與明確選擇的推理強度會持續生效。若要讀取設定檔的後續修改，請啟動新工作階段。

仍支援舊版 `session/set_mode` 與 `session/set_model` 請求。

## Skill 指令 {/* #skill-commands */}

收到 `session/new` 回應後，伺服器會透過 `available_commands_update` 告知用戶端可用的 Workspace Skill。用戶端可在第一個提示前提供 `/skill/<name>` 指令補全。伺服器會在後續每次提示前更新清單，若有變化就發送更新。

將指令作為文字提示送出，後面可以附加說明：

```typescript
await connection.prompt({
  sessionId,
  prompt: [{ type: 'text', text: '/skill/review Check the current changes' }],
})
```

伺服器會將 Skill 的指令與資源清單加入目前回合。它會使用 Mastra Code 的專案與全域 Skill 目錄。名稱重複時，會依 Workspace 目錄順序選擇第一個可供使用者呼叫的檔案。標記為 `user-invocable: false` 的 Skill 不會顯示，明確呼叫也會遭拒絕。Skill 不存在時會傳回無效參數錯誤，且不會開始推理。

`/goal` 等終端機指令不會作為 ACP 指令提供。

## 權限與錯誤 {/* #permissions-and-errors */}

預設情況下，Tool 核准與 Sandbox 存取請求會交由用戶端的權限介面處理。遭拒絕的 Tool 不會執行。取消暫停中的權限請求時，系統會先記錄拒絕再中止，因此後續回合不會重播該請求。不支援自由文字 Tool 問題。`ask_user` Tool 已停用。

Assistant 片段只包含 Assistant 輸出；使用者提示與內部系統訊號不會作為 Assistant 回覆送出。Provider 故障會傳回 JSON-RPC 錯誤。達到 Token 上限時傳回 `max_tokens`，內容過濾拒絕時傳回 `refusal`，取消時傳回 `cancelled`。

## 支援的協定範圍 {/* #supported-protocol-profile */}

伺服器支援 ACP v1 初始化、新工作階段、文字提示、文字資源、Assistant 與 Tool 更新、權限、取消、設定與指令探索。不會宣告支援載入工作階段。圖片、音訊及二進位資源提示會傳回無效參數錯誤。

儲存庫的 ACP 相容性檢查會依固定版本的上游 schema 驗證訊息，並以本機模型與 MCP fixture 測試建置後的 SDK。這些檢查涵蓋已實作的協定範圍，但不代表上游認證、不保證支援所有選用的 ACP 功能，也無法取代在用戶端測試真實 Provider 驗證。
