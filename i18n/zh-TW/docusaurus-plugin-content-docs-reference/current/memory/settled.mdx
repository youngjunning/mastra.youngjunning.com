# Memory.settled()

`.settled()` 方法會在該 `Memory` 執行個體啟動的背景工作完成後履行。有些記憶體工作會在 Agent 執行結果傳回後繼續進行：

- 觀察式記憶體週期（緩衝的觀察與反思，以及它們啟動的巢狀 Agent 執行）
- 由 `deleteThread()` 與 `deleteMessages()` 啟動的向量清理

關閉由你管理的儲存連線前，請先等待此方法完成；否則背景陳述式可能仍會存取已關閉的連線。指定範圍的呼叫傳回時，其他執行緒可能仍在使用儲存空間，因此關閉共用儲存空間前，應呼叫不帶範圍的 `settled()`。

此方法宣告於記憶體基底類別，因此也適用於 `MastraMemory` 執行個體（由 `agent.getMemory()` 傳回）。`scope` 參數僅在 `Memory`（來自 `@mastra/memory`）上提供。

## 使用範例 {/* #usage-example */}

```typescript
await agent.generate('Hello', {
  memory: { thread: 'thread-123', resource: 'user-456' },
})

await memory.settled()
await store.close()
```

## 等待一場對話 {/* #wait-for-one-conversation */}

在繁忙的伺服器上，其他執行緒會持續啟動新工作，因此等待全部工作可能耗時很久。可以傳入範圍來縮小等待對象。如果觀察式記憶體採用執行緒範圍，下方呼叫只等待 `thread-123`；如果採用資源範圍，則等待 `user-456` 底下的所有執行緒。

```typescript
await memory.settled({ threadId: 'thread-123', resourceId: 'user-456' })
```

## 擴充使用範例 {/* #extended-usage-example */}

測試套件與短期執行的程序最常需要此方法，因為它們通常在執行結束後立即關閉儲存空間。

```typescript title="src/test-memory.ts"
import { Memory } from '@mastra/memory'
import { PostgresStore } from '@mastra/pg'

const store = new PostgresStore({ connectionString })
const memory = new Memory({ storage: store })

// ... run your agent ...

// Wait for observational memory and vector cleanup to finish before closing.
await memory.settled()
await store.close()
```

<Callout type="note">
  `settled()` 會等待呼叫當下已開始的工作，以及這些工作後續排入佇列的
  工作。它不會阻止之後啟動的新工作，因此應在相關 Agent 執行結果傳回後呼叫。
</Callout>
