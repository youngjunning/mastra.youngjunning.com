# Memory.copyThread()

`.copyThread()` 方法會將現有執行緒及其訊息複製到新執行緒。它與 [`cloneThread()`](/reference/memory/cloneThread) 一樣，會複製工作記憶、觀察記憶及語義召回嵌入，但不會傳回複製後的訊息。使用 `@mastra/libsql` 或 `@mastra/pg` 時，資料列會在資料庫內複製，因此複製過程不會將訊息內容載入 Node.js 程序。仍會讀取內容的情況請參閱[記憶體使用情況](#memory-usage)。

如果只需要新執行緒 ID，例如為子 Agent 建立對話分支，請使用 `copyThread()`。如果還需要在回應中取得複製後的訊息，請使用 `cloneThread()`。

## 使用範例 {/* #usage-example */}

```typescript
import { Memory } from '@mastra/memory'
import { LibSQLStore } from '@mastra/libsql'

const memory = new Memory({
  storage: new LibSQLStore({ id: 'memory-store', url: 'file:./memory.db' }),
})

const { thread, messageIdMap } = await memory.copyThread({
  sourceThreadId: 'original-thread-123',
})
```

## 記憶體使用情況 {/* #memory-usage */}

`copyThread()` 專為大型執行緒設計：

* `@mastra/libsql` 和 `@mastra/pg` 使用 `INSERT … SELECT` 陳述式複製訊息，因此複製過程不會將訊息內容讀入程序。
* 其他儲存配接器透過其現有的 `cloneThread()` 實作複製訊息，可能會讀取並重新寫入每則訊息。`copyThread()` 在傳回前仍會捨棄訊息內容。
* 啟用語義召回後，系統會讀回複製的訊息以產生嵌入。系統按目標訊息 ID 每批處理 100 則訊息，因此記憶體中一次只保留一批。

`cloneThread()` 會呼叫 `copyThread()`，然後讀回新執行緒中的訊息，填入 `clonedMessages`。
