# 觀察記憶

**添加於：** `@mastra/memory@1.1.0`

觀察記憶 (OM) 是 Mastra 的長上下文Agent記憶記憶系統。一個**Observer** watches conversations and creates observations, which a **Reflector**透過組合相關項目並壓縮整體模式來進行重組。他們共同維護一個觀察日誌，隨著原始訊息歷史記錄的增長而取代它。

## 用法 {/* #usage */}

```typescript title="src/mastra/agents/agent.ts"
import { Memory } from '@mastra/memory'
import { Agent } from '@mastra/core/agent'

export const agent = new Agent({
  id: 'my-agent',
  name: 'my-agent',
  instructions: 'You are a helpful assistant.',
  model: '__GATEWAY_OPENAI_MODEL_LUNA__',
  memory: new Memory({
    options: {
      observationalMemory: true,
    },
  }),
})
```

## 配置 {/* #configuration */}

這`observationalMemory` option accepts `true`, a configuration object, or `false`. Setting `true`使 OM 具有自動模型選擇功能。傳遞配置物件時，設定`model`在頂層或之上`observation.model`和/或`reflection.model`。當省略所有模型欄位時，每個角色預設為`'auto'`.

觀察者輸入是多模式感知的。 OM 保留文字佔位符，例如`[Image #1: screenshot.png]` in the transcript it builds for the Observer, and also sends the underlying image parts when possible. This applies to both single-thread observation and batched multi-thread observation. Non-image files appear as placeholders only.

OM 透過快速本地標記估計執行閾值處理。文字用途`tokenx`, and image-like inputs use provider-aware heuristics plus deterministic fallbacks when metadata is incomplete.

### 萃取行為 {/* #extraction-behavior */}

* 提取的值儲存在線程 OM 元資料中`om.extracted`.
* 內建提取器值也鏡像到相容性元資料字段`currentTask`, `suggestedResponse`, and `threadTitle`.
* `thread-title`僅在以下情況下更新線程標題`observation.threadTitle` is enabled.
* `observation.extract`觀察期間運行。`reflection.extract` runs during reflection.
* 模式支援的提取器添加後續結構化輸出請求。
* 無模式提取器是直接在觀察者或反射器輸出中發出的內聯字串提取器。
* 動態提取器函數接收運行時上下文，包括`source`, `threadId`, `resourceId`, `mainAgent`, `memory`, and `requestContext` when available.
* `WorkingMemoryExtractor`使用正常的提取器管道透過活動更新工作內存`Memory` instance. It uses structured extraction when working memory has a JSON schema and skips OM metadata persistence, so the working memory payload isn't duplicated under OM extracted metadata.
* 什麼時候`workingMemory.schema` is set, `WorkingMemoryExtractor` validates each update against that schema before saving it. If an update doesn't match, it's skipped and reported as an extraction failure while the previous working memory stays in place. Because the schema isn't sent to the model as a structured output constraint, one invalid working memory update can't fail other extractors. A `null` in an optional field is treated as not provided.
* `observationalMemory.observation.manageWorkingMemory`添加`WorkingMemoryExtractor` and defaults `workingMemory.agentManaged` to `false`. It defaults `workingMemory.useStateSignals` to `true` when working memory is enabled.
* 提取失敗會在 OM 標記資料中報告，並且不會丟棄其他成功提取的值。

### 非同步緩衝 {/* #async-buffering */}

預設情況下，非同步緩衝處於啟用狀態，設定如下：

* `observation.bufferTokens: 0.2`每 20% 緩衝一次`messageTokens`.
* `observation.bufferActivation: 0.8`激活後保持閾值的20%。
* `reflection.bufferActivation: 0.5`在反射閾值的一半處開始背景反射。

緩衝觀察者呼叫不會產生繼續提示，並且啟動會清除儲存的提示。看[When buffering falls behind](#when-buffering-falls-behind) for what happens between the threshold and `blockAfter`.

放`observation.bufferTokens: false` to turn off buffering for both observation and reflection. Each then runs synchronously at its threshold.

```typescript oxfmt:false
observationalMemory: {
  observation: {
    bufferTokens: false,
  },
}
```

非同步緩衝在已棄用的版本中已關閉`scope: 'resource'`.

## 早期激活 {/* #early-activation */}

預設情況下，當訊息歷史記錄達到時，緩衝觀察將激活`observation.messageTokens`. OM can activate them sooner, which helps when a prompt cache is about to expire or when the agent switches model providers. In both cases the next request can't reuse the cached prompt anyway, so sending a smaller, compressed context costs nothing extra.

* `activateAfterIdle`：線程空閒這麼長時間後啟動。接受毫秒 (`300_000`), a duration string (`'5m'`, `'1hr'`), `'auto'` for a provider-aware prompt cache TTL, or a per-provider object (see [per-provider idle TTLs](#per-provider-idle-ttls)).
* `activateOnProviderChange`：下一步使用不同的時激活`provider/model` than the one that produced the latest assistant step. Default `false`.

```typescript title="src/mastra/memory.ts"
import { Memory } from '@mastra/memory'

const memory = new Memory({
  options: {
    observationalMemory: {
      activateAfterIdle: 'auto',
      activateOnProviderChange: true,
    },
  },
})
```

頂級設定僅適用於觀察。反射透過嵌套選擇自行加入`reflection` settings:

```typescript title="src/mastra/memory.ts"
import { Memory } from '@mastra/memory'

const memory = new Memory({
  options: {
    observationalMemory: {
      activateAfterIdle: '5m',
      observation: {
        activateAfterIdle: false,
      },
      reflection: {
        activateAfterIdle: '10m',
        activateOnProviderChange: true,
      },
    },
  },
})
```

這裡的觀察忽略了頂級空閒設置，而反射則選擇空閒和Provider更改激活。

### 自動空閒 TTL {/* #automatic-idle-ttls */}

和`activateAfterIdle: 'auto'`, Mastra picks the idle TTL from the active model provider:

|Provider|自動TTL |
| - | - |
| Anthropic、OpenRouter、未知Provider、xAI | 5 分鐘 |
|深度搜尋| 1小時|
|Google雙子座 | 24小時|
|格羅克 | 2小時|
| OpenAI 與`providerOptions.openai.promptCacheRetention: "24h"` | 1 hour |
| OpenAI with `providerOptions.openai.promptCacheRetention: "in_memory"` | 5 minutes |
| OpenAI `gpt-4*`, `gpt-5`, `gpt-5-*`, and `gpt-5.1` through `gpt-5.4` (including `-` suffixed variants) | 5 minutes |
| Other OpenAI models | 1 hour |

對於固定 TTL，請使用`'5m'` or `300_000`.

### 每個Provider的空閒 TTL {/* #per-provider-idle-ttls */}

`'auto'`無法看到您在單一訊息上設定的快取 TTL，例如 Anthropic 的`cacheControl: { type: 'ephemeral', ttl: '1h' }`. It keeps using the provider's 5-minute default, so buffered observations activate while the 1-hour cache is still warm. Pass an object to set the TTL per provider:

```typescript title="src/mastra/memory.ts"
import { Memory } from '@mastra/memory'

const memory = new Memory({
  options: {
    observationalMemory: {
      activateAfterIdle: { default: 'auto', anthropic: '1h' },
    },
  },
})
```

設定`anthropic` entry to the same TTL as your `cacheControl.ttl`. Mastra doesn't read the per-message cache setting, so keep the two in sync by hand.

物件如何解析：

* 鍵是Provider名稱。 Mastra 將它們與第一個先前的模型Provider的部分進行比較，不區分大小寫`.`, so `anthropic` matches both `anthropic` and `anthropic.messages`. Claude served through another provider uses that provider's key, for example `amazon-bedrock`. Keys must not contain `.` or `/`.
* 每個值接受與單一 TTL 相同的形式：毫秒、持續時間字串、`'auto'`, or `false` to turn off idle activation for that provider.
* `default`適用於每個沒有自己密鑰的Provider。沒有`default`, those providers don't idle-activate.
* `observation.activateAfterIdle`和`reflection.activateAfterIdle` accept the same object. An `observation.activateAfterIdle` object replaces the top-level value and isn't merged with it.

## 空閒時的緩衝區 {/* #buffer-on-idle */}

放`observation.bufferOnIdle: true` to run background observation buffering when an agent turn ends and the agent becomes idle. Short turns then get observed without waiting for the next turn or the `messageTokens` threshold.

```typescript title="src/mastra/memory.ts"
import { Memory } from '@mastra/memory'

const memory = new Memory({
  options: {
    observationalMemory: {
      observation: {
        bufferOnIdle: true,
      },
    },
  },
})
```

`bufferOnIdle`預設關閉。它是獨立於`bufferTokens`: `bufferTokens` controls buffering during steps, `bufferOnIdle` controls buffering at the end of an idle turn.

## 當緩衝落後時 {/* #when-buffering-falls-behind */}

當訊息到達的速度超過觀察者緩衝它們的速度時，歷史記錄就可以過去`messageTokens` before a buffered chunk is ready. Between `messageTokens` and `observation.blockAfter` (default `1.2`, so 36,000 tokens with the default threshold), Mastra keeps buffering in the background and activates the chunk on a later step, so the agent doesn't wait.

如果待處理的代幣仍然達到`blockAfter` after buffered activation, for example when a large tool result leaves an uncovered tail, a synchronous observation runs. At `blockAfter`, activation first waits a bounded time for a buffered observation that's still being produced. If that takes longer, Mastra observes the remaining messages synchronously and drops the late observation if its messages are already observed. Activations triggered by the idle TTL or a provider change don't wait.

多於`blockAfter`, activation may overshoot the retention target instead of using fewer chunks. Buffered activation usually keeps a minimum remaining context (the smaller of about 1,000 tokens or the configured retention floor), but a single chunk that covers the whole pending window still activates and can leave less.

非同步緩衝觀察者呼叫不會產生連續提示，因為延遲提示在啟動時可能已經過時。當緩衝區塊啟動時，任何儲存的建議回應和目前任務都會被清除。

反射緩衝以同樣的方式。當觀察達到時，它會在後台啟動`reflection.bufferActivation` (default `0.5`) of `reflection.observationTokens`, and runs synchronously above `reflection.blockAfter` (default `1.2`) when no buffered reflection is ready.

## 重試與失敗策略 {/* #retries-and-failure-policy */}

觀察者和反射器模型呼叫會在出現暫時性Provider錯誤時重試。每個階段有兩個設定：

* `maxRetries`：第一次模型呼叫後重試。預設`8`. This is the only retry setting for the stage: the underlying model call runs with no provider-level retries.
* `failurePolicy`：重試次數用完後會發生什麼事。`'abort'` (default) fails the turn, and `'continue'` lets it go on.

```typescript title="src/mastra/memory.ts"
import { Memory } from '@mastra/memory'

const memory = new Memory({
  options: {
    observationalMemory: {
      observation: {
        maxRetries: 8,
        failurePolicy: 'continue',
      },
      reflection: {
        maxRetries: 8,
        failurePolicy: 'continue',
      },
    },
  },
})
```

Provider中斷通常會導致兩個階段都中斷，因此如果您希望這一輪能夠倖存下來，請在兩個階段都設定策略。

和`'continue'`, Mastra reports the failure through OM diagnostics, keeps the failed input pending for a later cycle, and lets the turn continue. It doesn't advance observation boundaries or discard unobserved messages. A Reflector failure leaves already-persisted observations committed and retries reflection at the next threshold crossing.

此策略僅涵蓋同步運行中的觀察者和反射器模型以及Provider故障：`blockAfter`, when async buffering is off, and in resource-scoped observation. Persistence, indexing, transform, locking, invariant and explicit abort failures stay fatal.

無論政策如何，後台緩衝失敗永遠不會停止轉變。他們被報道為`om_buffering_failed`, and the failed input stays pending. If it keeps growing, it reaches `blockAfter`, where synchronous observation applies `failurePolicy`.

：：：警告

`'continue'`沒有長時間停電的後備裝置。未觀察到的訊息保持待處理狀態，並在主Agent的上下文中不斷增長，直到達到模型的上下文限制。

## 代幣估算 {/* #token-estimates */}

OM 根據本地代幣估計來決定何時觀察，而不是根據Provider的使用報告。文本估計為`tokenx`; images use provider-aware heuristics, which also apply to image-like `file` parts. Provider counts can run higher than the estimate, which is why [context-overflow recovery](/docs/memory/observational-memory#context-overflow-recovery) exists.

### 令牌計數緩存 {/* #token-count-cache */}

OM 快取訊息元資料中的估計，因此閾值檢查不會重新計數相同的內容：

* 每個零件的估計值儲存在`part.providerMetadata.mastra` and reused while the cache version and tokenizer source match.
* 僅包含字串內容（無部分）的訊息使用訊息層級快取。
* 每次傳遞都會重新計算訊息和對話開銷。僅快取有效負載估計值。
* `data-*`和`reasoning` parts are skipped and not cached.

### 提供您自己對文件的估計 {/* #supplying-your-own-estimate-for-a-file */}

您可以將令牌估算附加到`image` or `file` part with `providerMetadata.mastra.tokenEstimate`. The token counter uses it as is:

```typescript
const filePart = {
  type: 'file',
  data: 'storage://bucket/large-report.pdf',
  mimeType: 'application/pdf',
  filename: 'large-report.pdf',
  providerMetadata: {
    mastra: {
      tokenEstimate: {
        v: 0,
        source: 'client',
        key: 'client',
        tokens: 100_000,
      },
    },
  },
}
```

* `v`：快取架構版本。將其設定為`0`. OM doesn't read it for caller entries.
* `source`： 必須是`'client'`. This marks the entry as authoritative so it isn't recomputed or overwritten.
* `key`：設定為`'client'`. Framework entries put a content hash here. `'client'` keeps your estimate stable across writes.
* `tokens`：要使用的計數。必須是有限的非負數。

該估價僅在`image` and `file` parts. `text` and `tool-invocation` parts are always counted.

## 限制觀察者重讀的內容 {/* #limiting-what-the-observer-re-reads */}

預設情況下，觀察者接收完整的觀察日誌作為每批新訊息的上下文，加上先前的訊息`current-task` and `suggested-response` values. When the log grows large, set `observation.previousObserverTokens` to cap it:

```typescript title="src/mastra/memory.ts"
import { Memory } from '@mastra/memory'

const memory = new Memory({
  options: {
    observationalMemory: {
      observation: {
        previousObserverTokens: 10_000,
      },
    },
  },
})
```

* `false`（預設）：發送完整日誌。
* 一些數字，例如`2000`: keep about that many tokens of the most recent observations.
* `0`：未發送任何先前的觀察結果。

當緩衝反射待處理時，它已經覆蓋的行將被截斷先前的反射取代。

## 讓觀察者管理工作記憶 {/* #let-the-observer-manage-working-memory */}

放`observation.manageWorkingMemory: true` to have the Observer keep [working memory](/docs/memory/working-memory) up to date, instead of relying on the main agent to call the working memory tool.

```typescript title="src/mastra/memory.ts"
import { Memory } from '@mastra/memory'

const memory = new Memory({
  options: {
    workingMemory: {
      enabled: true,
    },
    observationalMemory: {
      observation: {
        manageWorkingMemory: true,
      },
    },
  },
})
```

這增加了一個`WorkingMemoryExtractor` and changes two working memory defaults:

* `workingMemory.agentManaged`預設為`false`, so the main agent no longer gets the working memory tool and instructions. Set it to `true` to keep them.
* `workingMemory.useStateSignals`預設為`true`, which moves working memory out of the system prompt into state signals so updates don't invalidate the prompt cache.

## 掛鉤 {/* #hooks */}

`observationalMemory.hooks`採用兩種鉤子：

* **生命週期掛鉤** (`onObservationStart`, `onObservationEnd`, `onReflectionStart`, `onReflectionEnd`) are for telemetry. They receive `threadId`, `resourceId` and `trigger`; the end hooks also receive the model call's `usage`, `providerMetadata` and any `error`. They never change what OM stores.
* **變換掛鉤** (`beforeObservation`, `afterObservation`, `beforeReflection`, `afterReflection`) change the data flowing through a cycle. Return nothing to pass the input through, or return a replacement.

```typescript
const memory = new Memory({
  options: {
    observationalMemory: {
      hooks: {
        // Drop or redact messages before the Observer sees them.
        beforeObservation: ({ messages }) => ({
          messages: messages.filter(m => !isSensitive(m)),
        }),
        // Rewrite observations before they are persisted.
        afterObservation: ({ observations }) => ({
          observations: redact(observations),
        }),
        // Rewrite the text the Reflector condenses.
        beforeReflection: ({ observations }) => ({
          observations: stripInternalNotes(observations),
        }),
        afterReflection: async ({ observations, resourceId }) => {
          await syncToExternalStore(resourceId, observations)
        },
      },
    },
  },
})
```

在每條路徑上始終等待轉換掛鉤：手動`observe()` and `reflect()`, synchronous observation during a turn, and async buffering. If `beforeObservation` returns an empty `messages` array, the Observer call is skipped and those messages are still marked as observed. If a transform hook throws, the cycle fails before committing the transformed text. Extractor callbacks and other side effects that already ran aren't rolled back.

`afterObservation`和`afterReflection` replace only the observation or reflection text. They don't touch the structured extractor values stored in thread metadata, and reflection extraction runs before `afterReflection`. Don't treat an after hook as a redaction boundary for everything in the cycle.

鉤子接收`threadId` and `resourceId`, so they can also update working memory with `memory.updateWorkingMemory()`. Those updates aren't atomic with the OM commit.

若要將技能指令排除在觀察者之外，請使用[`skillResultRedactor`](#skillresultredactor).

## 遷移現有線程 {/* #migrating-existing-threads */}

無需遷移。當執行緒首次超過時，OM 讀取現有訊息並觀察它們`observation.messageTokens`, processing the backlog then. Under the deprecated resource scope, all unobserved messages across a resource's threads are processed together, which can take a long time for users with many threads.

### 讀取提取器結果 {/* #read-extractor-results */}

### `data-om-status` {/* #data-om-status */}

在模型生成之前，每個Agent循環步驟發出一次。提供目前記憶體狀態的快照，包括上下文視窗的令牌使用情況以及任何非同步緩衝內容的狀態。

```typescript
interface DataOmStatusPart {
  type: 'data-om-status'
  data: {
    windows: {
      active: {
        /** Unobserved message tokens and the threshold that triggers observation */
        messages: { tokens: number; threshold: number }
        /** Observation tokens and the threshold that triggers reflection */
        observations: { tokens: number; threshold: number }
      }
      buffered: {
        observations: {
          /** Number of buffered chunks staged for activation */
          chunks: number
          /** Total message tokens across all buffered chunks */
          messageTokens: number
          /** Projected message tokens that would be removed if activation happened now (based on bufferActivation ratio and chunk boundaries) */
          projectedMessageRemoval: number
          /** Observation tokens that will be added on activation */
          observationTokens: number
          /** idle: no buffering in progress. running: background observer is working. complete: chunks are ready for activation. */
          status: 'idle' | 'running' | 'complete'
        }
        reflection: {
          /** Observation tokens that were fed into the reflector (pre-compression size) */
          inputObservationTokens: number
          /** Observation tokens the reflection will produce on activation (post-compression size) */
          observationTokens: number
          /** idle: no reflection buffered. running: background reflector is working. complete: reflection is ready for activation. */
          status: 'idle' | 'running' | 'complete'
        }
      }
    }
    recordId: string
    threadId: string
    stepNumber: number
    /** Increments each time the Reflector creates a new generation */
    generationCount: number
  }
}
```

`buffered.reflection.inputObservationTokens`是發送到 Reflector 的觀測值的大小。`buffered.reflection.observationTokens` is the compressed result: the size of what will replace those observations when the reflection activates. A client can use these two values to show a compression ratio.

客戶可以從原始值中得出百分比和激活後估計：

```typescript
// Message window usage %
const msgPercent = status.windows.active.messages.tokens / status.windows.active.messages.threshold

// Observation window usage %
const obsPercent =
  status.windows.active.observations.tokens / status.windows.active.observations.threshold

// Projected message tokens after buffered observations activate
// Uses projectedMessageRemoval which accounts for bufferActivation ratio and chunk boundaries
const postActivation =
  status.windows.active.messages.tokens -
  status.windows.buffered.observations.projectedMessageRemoval

// Reflection compression ratio (when buffered reflection exists)
const { inputObservationTokens, observationTokens } = status.windows.buffered.reflection
if (inputObservationTokens > 0) {
  const compressionRatio = observationTokens / inputObservationTokens
}
```

## 獨立使用 {/* #standalone-usage */}

大多數應用程式應該使用`Memory` class. Use the `ObservationalMemory` engine directly for benchmarking, experiments, or when OM must run in a specific order with other processors such as [guardrails](/docs/agents/guardrails).

將引擎包裹在`ObservationalMemoryProcessor`, which needs a `Memory` instance to load and persist messages. `stores.memory` is typed as optional on storage adapters, so assert or check it:

```typescript title="src/mastra/agents/agent.ts"
import { Agent } from '@mastra/core/agent'
import { LibSQLStore } from '@mastra/libsql'
import { Memory } from '@mastra/memory'
import { ObservationalMemory, ObservationalMemoryProcessor } from '@mastra/memory/processors'

const storage = new LibSQLStore({
  id: 'my-storage',
  url: 'file:./memory.db',
})

const memory = new Memory({ storage })

const om = new ObservationalMemory({
  storage: storage.stores.memory!,
  memory,
  model: '__GATEWAY_GOOGLE_MODEL_FLASH__',
  observation: {
    messageTokens: 20_000,
  },
  reflection: {
    observationTokens: 60_000,
  },
})

const omProcessor = new ObservationalMemoryProcessor(om, memory)

export const agent = new Agent({
  id: 'my-agent',
  name: 'My Agent',
  instructions: 'You are a helpful assistant.',
  model: '__GATEWAY_OPENAI_MODEL_LUNA__',
  inputProcessors: [omProcessor],
  outputProcessors: [omProcessor],
})
```

該引擎採用與`observationalMemory` config, plus `storage`, `onDebugEvent` and `obscureThreadIds`. See [standalone config](#standalone-config).

`om.observe()`僅在待處理令牌達到閾值時進行觀察。經過`force: true` to observe pending messages now. The bypass applies to that call only.

```typescript
const result = await om.observe({ threadId, resourceId, force: true })
// result.observed is true when pending messages were observed
```

Agent不需要它來從上下文視窗錯誤中恢復。[Context-overflow recovery](/docs/memory/observational-memory#context-overflow-recovery) handles that.

## 召回Tool {/* #recall-tool */}

什麼時候`retrieval` is truthy, Mastra registers a `recall` tool that pages through raw messages behind observation group ranges. With the default resource scope, the tool can list threads (`mode: "threads"`) and browse another thread through `threadId`. It also supports cross-thread search. Set `retrieval: { vector: true }` for semantic search (`mode: "search"`), or use `scope: 'thread'` to restrict the tool to the current thread. The tool is automatically added to the agent.

啟用檢索後，OM 也會注入指令，告訴Agent程式如何使用召回：何時驗證詳細資訊、如何搜尋和尋呼以及何時讀取原始訊息。它們從第一輪開始就包含在內，包括唯讀運行，並且僅描述配置的模式。反射組被標記`_kind: reflection_` so the agent treats them as lossy summaries. Use `retrieval: { instructions: '...' }` to append your own guidance after the built-in instructions.

### 觀察頁 {/* #observation-pages */}

配置向量搜尋後，`mode: "observations"` reads the original observation groups around a search hit, including groups that reflection condensed away and buffered groups that haven't been activated yet. Copy the hit's `groupId` exactly as shown and, in resource scope, its `threadId`:

```json
{
  "mode": "observations",
  "threadId": "source-thread-id",
  "groupId": "group-id-from-search",
  "direction": "after",
  "limit": 5
}
```

使用`direction: "before"` to page backward, or omit `direction` to include the anchor group itself. Pages return `{ results, count, hasMore }` with continuation calls, and say when newer messages haven't been observed yet.

### 搜尋結果 {/* #search-results */}

搜尋結果按日期列出，並共享 2,000 個標記的文字限額，因此長組會被縮短，從最匹配查詢的行開始。已經在Agent上下文中的結果作為短參考返回，排名較低的命中填充釋放的空間。`limit` counts excerpts, not references, so `count` can exceed `limit`.

### 儲存要求 {/* #storage-requirements */}

搜尋結果中的群組 ID 包括保存它們的記錄 (`groupId@recordId`), so paging reads a single record. Groups indexed before this change still work, but page by scanning the thread's observation history. Paging needs a storage adapter that supports observation history filters, so upgrade it together with `@mastra/memory`. Convex users need to redeploy their Mastra server functions.

### 按輸入令牌建模 {/* #modelbyinputtokens */}

`ModelByInputTokens`根據輸入令牌計數選擇模型。它選擇覆蓋實際輸入大小的最小閾值的模型。

#### 建構函數 {/* #constructor */}

```typescript
new ModelByInputTokens(config)
```

在哪裡`config` is an object with `upTo` keys that map token thresholds (numbers) to model targets. Each tier needs a concrete model ID, not `"auto"`.

#### 例子 {/* #example */}

```typescript
import { ModelByInputTokens } from '@mastra/memory'

const selector = new ModelByInputTokens({
  upTo: {
    10_000: 'google/gemini-2.5-flash', // Fast for small inputs
    40_000: '__GATEWAY_OPENAI_MODEL_LUNA__', // Stronger for medium inputs
    1_000_000: '__GATEWAY_OPENAI_MODEL__', // Most capable for large inputs
  },
})
```

#### 行為 {/* #behavior */}

* 閾值在內部排序，因此配置物件中的順序並不重要。
* `inputTokens ≤ smallest threshold`→ 使用該閾值的模型
* `inputTokens > largest threshold` → `resolve()` throws an error. If this happens during an OM Observer or Reflector run, OM aborts via TripWire, so callers receive an empty `text` result or streamed `tripwire` instead of a normal assistant response.
* OM 計算 Observer 或 Reflector 呼叫的輸入令牌計數，並直接解析匹配的模型層

### 技能結果編輯器 {/* #skillresultredactor */}

`skillResultRedactor`建立一個`beforeObservation` transform hook that redacts the results of the built-in Agent Skills tools (`skill`, `skill_search`, and `skill_read`) before the Observer model sees them. Each result is replaced with a placeholder while the tool call is kept, so the Observer still records which skill was used and what it was called with, without the skill text.

```typescript
import { Memory } from '@mastra/memory'
import { skillResultRedactor } from '@mastra/memory/hooks'

const memory = new Memory({
  options: {
    observationalMemory: {
      model: '__GATEWAY_GOOGLE_MODEL_FLASH__',
      hooks: {
        beforeObservation: skillResultRedactor(),
      },
    },
  },
})
```

經過`toolNames` to redact a different set of tools. To combine it with your own transform, chain the outputs and await each hook:

```typescript oxfmt:false
const dropSkillResults = skillResultRedactor()

hooks: {
  beforeObservation: async input => {
    const messages = (await dropSkillResults(input))?.messages ?? input.messages
    return { messages: messages.filter(m => m.role !== 'signal') }
  },
}
```

    'Tool names whose results are redacted. Defaults to the built-in skill tools: `skill`, `skill_search`, and `skill_read`. Use this to redact a different set of tool results.',

#### 退貨 {/* #returns */}

`(input: { messages: MastraDBMessage[] } & ObserveHookContext) => { messages: MastraDBMessage[] } | undefined`

該鉤子傳回訊息，其中匹配的Tool結果被佔位符替換，或者`undefined` when no message matched (which passes the payload through unchanged). Tool calls, arguments, and every other message are left as they are.
