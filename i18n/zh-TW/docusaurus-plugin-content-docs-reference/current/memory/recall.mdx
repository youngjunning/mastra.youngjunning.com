# Memory.recall()

`Memory.recall()` 方法會從指定執行緒擷取訊息，支援分頁、篩選選項和語意搜尋。

## 使用範例 {/* #usage-example */}

```typescript
const { messages } = await memory.recall({
  threadId: 'thread-123',
  perPage: 20,
})
```

## 信號可見性 {/* #signal-visibility */}

`hideSignals` 只會篩選這次呼叫回傳的訊息，不影響底層儲存內容或後續模型要求。一般訊息仍會回傳。此選項不是安全界線，也不會變更 `ifActive`、`ifIdle` 或 `transient` 等信號傳遞與持久化政策。

### 預設值與優先順序 {/* #defaults-and-precedence */}

| `hideSignals` | `includeSystemReminders` | 回傳的信號 |
| - | - | - |
| 未提供 | 未提供或 `false` | 沿用隱藏提醒的既有行為 |
| 未提供 | `true` | 所有信號 |
| `false` 或 `[]` | 任意值 | 所有信號 |
| `true` | 任意值 | 不回傳任何已辨識信號，包括舊版提醒 |
| 非空清單 | 任意值 | 除了符合指定類型之外的所有信號 |

與 [Agent 串流](/reference/streaming/agents/stream)不同，為維持相容性，recall 預設仍會隱藏提醒。已棄用的 `includeSystemReminders` 只在省略 `hideSignals` 時生效。

```typescript
const all = await memory.recall({
  threadId: 'thread-123',
  hideSignals: false,
})

const withoutSignals = await memory.recall({
  threadId: 'thread-123',
  hideSignals: true,
})

const withoutReminders = await memory.recall({
  threadId: 'thread-123',
  hideSignals: ['reactive', 'system-reminder'],
})
```

### 儲存類型與舊版訊息 {/* #stored-types-and-legacy-messages */}

Recall 比對的是**儲存的確切類型**，不會將別名正規化。例如，`['reactive']` 不會排除編碼為 `system-reminder` 的紀錄，`['user']` 也不會排除編碼為 `user-message` 的紀錄。較新的串流和訂閱則會正規化這些別名。若要在這些 API 中排除兩種提醒表示方式，請使用 `['reactive', 'system-reminder']`。

`data-signal` 或 `data-user-message` 區段中的已辨識類型，優先於信號中繼資料和舊版提醒標記。signal-role 訊息也可以在 `content.metadata.signal.type` 中編碼類型。未知類型或格式錯誤的信號區段不會符合排除條件，即使設定 `hideSignals: true` 也一樣。

如果沒有已辨識的編碼類型，依既有舊版提醒規則分類的訊息會視為 `system-reminder`，而非 `reactive`。這些規則包括：使用者訊息帶有 `systemReminder` 或 `dynamicAgentsMdReminder` 中繼資料，或第一個文字區段以 `<system-reminder` 開頭。這類紀錄在使用 `['reactive']` 時仍可見，使用 `['system-reminder']` 時則會排除。

### 分頁與 API 範圍 {/* #pagination-and-api-scope */}

篩選會在儲存查詢和分頁之後執行。因此，某頁可能少於 `perPage` 則訊息，甚至為空，但 `total`、`hasMore` 和頁面位移量不變。總數仍描述底層查詢結果，而非篩選後的訊息。

此選項適用於程序內的 `memory.recall()` 呼叫。本版本的 HTTP 和 client-js 契約尚未公開 `hideSignals`。

## 中繼資料篩選 {/* #metadata-filtering */}

使用 `filter.metadata` 比對儲存在訊息上的淺層純量中繼資料：

```typescript
const { messages } = await memory.recall({
  threadId: 'thread-123',
  filter: {
    metadata: {
      category: 'billing',
      escalated: true,
      priority: 2,
      archivedAt: null,
    },
  },
})
```

所有中繼資料條件以 AND 語意組合。訊息必須以相同型別精確符合每個鍵和值。`null` 只符合明確設為 `null` 的中繼資料，不符合缺少的鍵。

中繼資料篩選只支援淺層純量值：`string`、有限的 `number`、`boolean` 和 `null`。不支援巢狀物件、陣列、`NaN` 或無限值。中繼資料鍵必須以字母或底線開頭，且只能包含英數字元或底線，長度上限為 128 個字元。`__proto__`、`constructor` 和 `prototype` 等保留的原型鍵不可使用。效能取決於儲存後端；任意中繼資料篩選可能需要掃描候選訊息，因此請盡可能用 `threadId`、`resourceId` 或 `dateRange` 縮小查詢範圍。

## 延伸範例 {/* #extended-usage-example */}

```typescript title="src/test-memory.ts"
import { mastra } from './mastra'

const agent = mastra.getAgent('agent')
const memory = await agent.getMemory()

// Retrieve messages with pagination
const { messages } = await memory!.recall({
  threadId: 'thread-123',
  perPage: 50,
  vectorSearchString: 'What messages are there?',
  include: [
    {
      id: 'msg-123',
    },
    {
      id: 'msg-456',
      withPreviousMessages: 3,
      withNextMessages: 1,
    },
  ],
  threadConfig: {
    semanticRecall: true,
  },
})

console.log(messages) // MastraDBMessage[]

// Fetch all messages without pagination
const allMessages = await memory!.recall({
  threadId: 'thread-123',
  perPage: false, // Fetch all
})

// Convert to AI SDK format if needed
import { toAISdkV5Messages } from '@mastra/ai-sdk/ui'
const uiMessages = toAISdkV5Messages(messages)
```
