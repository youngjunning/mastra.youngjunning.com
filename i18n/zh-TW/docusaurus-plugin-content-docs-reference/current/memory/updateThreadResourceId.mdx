# Memory.updateThreadResourceId()

`.updateThreadResourceId()` 透過重新指派既有對話串的 `resourceId`，將其所有權轉移給另一個資源。它會更新對話串及其所有相關訊息，使其歸屬新資源，同時保留對話串原有的 `createdAt` 時間戳記。這適用於將私人對話串移入共用 Workspace 等情境。

## 使用範例 {/* #usage-example */}

```typescript
import { Memory } from '@mastra/memory'
import { LibSQLStore } from '@mastra/libsql'

const memory = new Memory({
  storage: new LibSQLStore({ id: 'memory-store', url: 'file:./memory.db' }),
})

const thread = await memory.updateThreadResourceId({
  threadId: 'thread-123',
  resourceId: 'new-resource-456',
})
```

## 行為 {/* #behavior */}

- 對話串的 `resourceId` 會重新指派給新資源，其所有訊息也會更新為參照新資源。
- 保留對話串原有的 `createdAt` 時間戳記，並更新 `updatedAt` 時間戳記。
- 若對話串已屬於目標資源，此方法不會更新資料，而是回傳既有對話串。
- 若對話串不存在，此方法會擲出錯誤。

## 安全性 {/* #security */}

轉移對話串所有權會改變其所屬資源，並繞過一般的逐資源所有權檢查。HTTP 端點（`POST /memory/threads/:threadId/transfer`）僅供不受資源範圍限制的特權呼叫者使用。已解析出資源範圍的請求會遭拒；若已設定 `server.auth` 但未提供 FGA Provider，此端點也會拒絕不指定資源範圍的請求，不會將其視為預設具備特權。請從受信任的服務環境執行轉移，勿直接對終端使用者開放。

和所有 Memory 操作（例如刪除對話串、列出訊息、寫入工作記憶）一樣，若伺服器完全未設定驗證，此端點也不會進行身分驗證。向不受信任的呼叫者開放 Memory API 前，請設定 `server.auth`；若要依資源執行存取控制，還須設定 FGA Provider。
