# Workspace 類別

**新增於：** `@mastra/core@1.1.0`

`Workspace` 類別結合檔案系統與 Sandbox，為 Agent 提供檔案儲存和指令執行功能，也支援對已建立索引的內容進行 BM25 搜尋和向量搜尋。

## 使用範例 {/* #usage-example */}

```typescript
import { Workspace, LocalFilesystem, LocalSandbox } from '@mastra/core/workspace'

const workspace = new Workspace({
  id: 'my-workspace',
  name: 'My Workspace',
  filesystem: new LocalFilesystem({
    basePath: './workspace',
  }),
  sandbox: new LocalSandbox({
    workingDirectory: './workspace',
  }),
  bm25: true,
  autoIndexPaths: ['docs'],
})
```


## Tool 設定 {/* #tool-configuration */}

`tools` 選項接受 `WorkspaceToolsConfig` 物件，用來控制要啟用哪些 Workspace Tool 及其安全設定。

```typescript {2,7-16}
import { Workspace } from '@mastra/core/workspace'
import { WORKSPACE_TOOLS } from '@mastra/core/workspace'

const workspace = new Workspace({
  id: 'my-workspace',
  name: 'My Workspace',
  tools: {
    // Global defaults (apply to all tools)
    enabled: true,
    requireApproval: false,

    // Per-tool overrides using WORKSPACE_TOOLS constants
    [WORKSPACE_TOOLS.FILESYSTEM.WRITE_FILE]: {
      requireApproval: true,
    },
  },
})
```

設定物件包含兩類設定：

* **全域設定**：`enabled` 和 `requireApproval` 適用於所有 Workspace Tool，除非個別 Tool 的設定覆寫它們。`hooks` 和 `writeLockTimeoutMs` 只能在全域設定，不能針對個別 Tool 設定。
* **個別 Tool 覆寫**：以 `WORKSPACE_TOOLS` 常數作為鍵，設定個別 Tool。

個別 Tool 的設定支援以下選項：

`ToolConfigContext` 包含 `{ requestContext, workspace }`。執行階段的政策使用 `ToolConfigWithArgsContext`，其中還包含 Tool 的 `args`。

```typescript {5-13}
import { Workspace, WORKSPACE_TOOLS } from '@mastra/core/workspace'

const workspace = new Workspace({
  id: 'my-workspace',
  tools: {
    enabled: ({ requestContext }) => requestContext.get('workspace-tools') === true,
    [WORKSPACE_TOOLS.FILESYSTEM.WRITE_FILE]: {
      requireApproval: ({ args }) => (args.path as string).startsWith('/protected'),
      requireReadBeforeWrite: true,
    },
    [WORKSPACE_TOOLS.SANDBOX.EXECUTE_COMMAND]: {
      maxOutputTokens: 5000,
    },
  },
})
```

各項功能的設定請參閱[檔案系統 Tool](/docs/sandbox/filesystem#using-mounts)、[Sandbox Tool](/docs/sandbox/overview#using-the-sandbox)、[LSP 檢查](/docs/sandbox/lsp#tool-name-remapping)和[搜尋 Tool](/docs/sandbox/search#agent-tools)。

### Tool 名稱重新對應 {/* #tool-name-remapping */}

在個別 Tool 設定中指定 `name` 屬性，即可重新命名 Workspace Tool。設定鍵仍使用原本的常數，只有向 Agent 公開的名稱會改變。

```typescript {8,9}
import { Workspace } from '@mastra/core/workspace'
import { WORKSPACE_TOOLS } from '@mastra/core/workspace'

const workspace = new Workspace({
  id: 'my-workspace',
  name: 'My Workspace',
  tools: {
    [WORKSPACE_TOOLS.FILESYSTEM.READ_FILE]: { name: 'view' },
    [WORKSPACE_TOOLS.FILESYSTEM.GREP]: { name: 'search_content' },
  },
})
```

所有 Workspace Tool 的名稱都必須唯一。若自訂名稱與其他 Tool 的預設或自訂名稱衝突，就會擲出錯誤。

### 先讀後寫追蹤 {/* #read-before-write-tracking */}

啟用 `requireReadBeforeWrite` 後，寫入 Tool 會拒絕修改 Agent 尚未讀取的檔案。如果 Agent 在 Mastra 執行個體中使用記憶執行緒運作，讀取紀錄會依執行緒儲存在 `threadState` 儲存網域中，與工作清單和目標共用同一儲存空間。只要設定的儲存配接器會持久保存執行緒狀態，這些紀錄便能跨暫停與繼續（例如 Tool 等待核准）、同一執行緒的後續回合，以及無伺服器環境中的程序重新啟動而保留。除了將 Agent 註冊到具備儲存空間的 Mastra 執行個體，無須額外設定。

如果檔案在讀取後發生變更，Agent 必須重新讀取，寫入才會獲准。成功寫入後，讀取紀錄會清除，因此下次修改前仍須重新讀取。沒有記憶執行緒或 Mastra 儲存空間時，讀取紀錄僅在當次執行期間有效。

讀取紀錄依檔案系統區分，檔案系統由其 Provider 和基礎路徑識別。沒有基礎路徑時只依 Provider 區分，因此相同 Provider 的執行個體共用讀取紀錄。如果同一執行緒在不同請求中解析到不同的檔案系統（例如 Workspace 或檔案系統隨請求情境動態變化），寫入前必須在新檔案系統上重新讀取檔案。設定相同的檔案系統（例如兩個 `basePath` 相同的 `LocalFilesystem` 執行個體）共用讀取紀錄。

### Tool hook {/* #tool-hooks */}

設定 `tools.hooks`，可在每次呼叫已啟用的 Workspace Tool 前後執行邏輯。Hook 在名稱重新對應後執行，其情境同時包含公開的 `toolName` 和原本的 `workspaceToolName`。

```typescript {6-14}
import { Workspace } from '@mastra/core/workspace'

const workspace = new Workspace({
  id: 'my-workspace',
  tools: {
    hooks: {
      beforeToolCall: ({ toolName, workspaceToolName, input }) => {
        console.log(`Running ${toolName} (${workspaceToolName})`, input)
      },
      afterToolCall: ({ toolName, output, error }) => {
        console.log(`Finished ${toolName}`, { output, error })
      },
    },
  },
})
```

## 方法 {/* #methods */}

### 生命週期 {/* #lifecycle */}

#### `init()` {/* #init */}

初始化 Workspace 並準備資源。

```typescript
await workspace.init()
```

多數情況下無須明確呼叫 `init()`：

* **Sandbox**：首次呼叫 `executeCommand()` 時會自動啟動。可呼叫 `init()`，避免首次執行指令的延遲。
* **檔案系統**：建立基礎目錄並執行 Provider 特定的初始化。某些 Provider 會在首次操作時自動建立目錄。
* **搜尋**：只有使用 `autoIndexPaths` 自動建立索引時才需要呼叫。

初始化執行：

* 啟動檔案系統 Provider（必要時建立基礎目錄）
* 啟動 Sandbox Provider（建立工作目錄，並在設定後建立隔離環境）
* 為搜尋建立 `autoIndexPaths` 指定檔案的索引

#### `stop()` {/* #stop */}

停止 Workspace 的運作中資源，但不銷毀它們。

```typescript
await workspace.stop()
```

`stop()` 會先關閉語言伺服器和瀏覽器，再停止 Sandbox Provider。遠端 Provider 會暫停 Sandbox，以便之後恢復；`LocalSandbox` 則會終止背景處理程序並卸載檔案系統。停止並不等於銷毀：檔案系統、搜尋索引和 Skill 仍可使用，下次執行 Sandbox 操作時會再次啟動 Sandbox。

`mastra.shutdown()` 會對已註冊的 Workspace 呼叫 `stop()`。程序重新啟動時，遠端 Sandbox 會暫停，而不會被刪除。若要完全銷毀 Workspace，必須明確呼叫 `destroy()` 或 `mastra.removeWorkspace(id, { destroy: true })`。

#### `destroy()` {/* #destroy */}

銷毀 Workspace 並清理資源。

```typescript
await workspace.destroy()
```

`destroy()` 會依序關閉 Workspace 擁有的語言伺服器、瀏覽器、Sandbox Provider 和檔案系統 Provider，並清除快取的 Sandbox 參照。

應用程式不再需要 Workspace 及其 Sandbox 時，應呼叫 `destroy()`。若要從 Mastra 登錄資料中移除 Workspace，請使用 [`mastra.removeWorkspace()`](/reference/core/removeWorkspace)。

`LocalFilesystem.destroy()` 不會刪除磁碟上的檔案。由解析函式傳回的檔案系統和 Sandbox Provider 歸應用程式所有，須由應用程式自行清理。

### 搜尋操作 {/* #search-operations */}

#### `index(path, content, options?)` {/* #indexpath-content-options */}

為搜尋建立內容索引。

```typescript
await workspace.index('/docs/guide.md', 'Guide content...')
```

#### `search(query, options?)` {/* #searchquery-options */}

搜尋已建立索引的內容。

```typescript
const results = await workspace.search('password reset', {
  topK: 10,
  mode: 'hybrid',
})
```

### 實用方法 {/* #utility */}

#### `getInfo()` {/* #getinfo */}

取得 Workspace 資訊。

```typescript
const info = await workspace.getInfo()
// { id, name, status, createdAt, lastAccessedAt, filesystem?, sandbox? }
```

傳入 `resolveDynamicProviders: false` 可略過檔案系統解析函式。如果目前請求尚未解析該檔案系統，會回報 `{ provider: 'dynamic', status: 'pending' }`。`getInfo()` 絕不會呼叫 Sandbox 解析函式，因為解析 Sandbox 可能會建立實際基礎設施。目前請求尚未解析的 Sandbox 也會回報 `{ provider: 'dynamic', status: 'pending' }`。

```typescript
const info = await workspace.getInfo({ resolveDynamicProviders: false })
```

### Skill Tool {/* #skill-tools */}

設定 Skill 時新增：

| Tool | 說明 |
| - | - |
| `skill` | 依名稱或路徑啟用 Skill，傳回完整指示、參考資料、指令碼和資源。 |
