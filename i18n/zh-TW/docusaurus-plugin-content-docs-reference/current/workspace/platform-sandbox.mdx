# 平台沙箱

用於在 Mastra 平台環境中配置沙箱的用戶端。每個`PlatformSandbox`實例擁有一個遠端沙箱：`start()`規定它，`executeCommand()`與它對抗，並且`destroy()`把它撕下來。建立額外的實例來擁有額外的遠端沙箱。使用`clone()`從配置的模板派生它們（請參閱[複製](#cloning-for-a-fleet-of-sandboxes)).

沙箱從預先建置的Provider範本啟動，其中已安裝 Python 3、Node 22、TypeScript、tsx 和常見建置Tool。您也可以建立一個[reusable template](#reusable-templates) with the portable `Template()` builder. Pass a stable `id` to opt into [checkpoint recovery](#checkpoint-recovery) so a new sandbox boots from the previous one's filesystem.

相關Provider：[`RailwaySandbox`](/integrations/sandboxes/railway) for self-hosted Railway sandboxes, [`LocalSandbox`](/reference/workspace/local-sandbox) for local sandboxes.

：：：筆記

接口詳情請參見[WorkspaceSandbox interface](/reference/workspace/sandbox).

:::

## 用法 {/* #usage */}

添加一個`PlatformSandbox` to a workspace and assign it to an agent:

```typescript
import { Agent } from '@mastra/core/agent'
import { Workspace } from '@mastra/core/workspace'
import { PlatformSandbox } from '@mastra/platform-workspace'

const workspace = new Workspace({
  sandbox: new PlatformSandbox({
    // accessToken, projectId, environmentId all fall back to env vars
    idleTimeoutMinutes: 30,
  }),
})

const agent = new Agent({
  id: 'code-agent',
  name: 'Code Agent',
  instructions: 'You are a coding assistant working in this workspace.',
  model: '__GATEWAY_ANTHROPIC_MODEL_SONNET__',
  workspace,
})

const response = await agent.generate(
  'Print "Hello, world!" and show the current working directory.',
)

console.log(response.text)
```

### 專用網路 {/* #private-networking */}

放`networkIsolation` to `PRIVATE` to join the environment's private network and reach other services running in the same Mastra Platform environment:

```typescript
const workspace = new Workspace({
  sandbox: new PlatformSandbox({
    networkIsolation: 'PRIVATE',
  }),
})
```

預設`ISOLATED` mode allows outbound internet access only, with no private network connectivity.

### 公共連接埠 {/* #public-ports */}

預設情況下，連接埠是私有的：開啟一個連接埠需要登入預覽連結。放`publicPorts` to let anyone with a port's URL reach it, for example a webhook receiver:

```typescript
const workspace = new Workspace({
  sandbox: new PlatformSandbox({
    publicPorts: true,
  }),
})
```

無論哪種方式，連接埠 URL 都是相同的。僅是否要求登入變更。此設定在建立沙箱時是固定的，因此在重新附加時傳遞該設定不會對該沙箱進行任何變更。克隆使用`publicPorts` option you passed, not the reattached sandbox's setting.

### 重新連接到正在運行的沙箱 {/* #reattaching-to-a-running-sandbox */}

透過現有的`sandboxId` to reattach to a live sandbox instead of creating a new one:

```typescript
const sandbox = new PlatformSandbox({
  sandboxId: 'sbx_abc123',
})
await sandbox.start()

const result = await sandbox.executeCommand('cat', ['/workspace/state.json'])
```

什麼時候`sandboxId` is set, `environmentId` isn't required because the sandbox already exists.

從以下位置讀取正在運行的沙箱的平台 ID`sandboxId` property after `start()` and persist it for the next reattach. The property is `undefined` until the sandbox has started in the current process. The option passed to the constructor is a hint for `start()`. Before `start()` runs, `getInfo()` answers from local state and doesn't ask the platform about the hint. Under the default `reattach: 'best-effort'`, if the platform no longer knows the id, `start()` falls through to a fresh provision keyed by the sandbox's logical `id`. That fallback needs `environmentId` (or `MASTRA_ENVIRONMENT_ID`), so pass it whenever a hint might be stale; without it, `start()` throws `environmentId is required`.

`start()`報告`{ outcome: 'connected' }` on reattach and `{ outcome: 'created' }` on a fresh provision (including a checkpoint-recovered boot, which is a new VM even when its filesystem was restored). See [`start()`](/reference/workspace/sandbox#start) for the shared contract.

當一個新的沙箱默默地失去你的應用程式所依賴的狀態時，設置`reattach: 'required'`:

```typescript
const sandbox = new PlatformSandbox({
  sandboxId: 'sbx_abc123',
  reattach: 'required',
})
```

和`reattach: 'required'`, a reattach target the platform reports as missing (404), gone (410), or destroyed rejects `start()` with a `SandboxError` whose `code` is `SANDBOX_REATTACH_FAILED`, and no sandbox is provisioned. The error's `details` include `provider`, `sandboxId`, `logicalId` (the sandbox's logical `id`), and `reason`. Other errors propagate unchanged. To start fresh, clear your persisted `sandboxId` and construct the sandbox without it. Clones inherit the `reattach` setting.

### 可重複使用的模板 {/* #reusable-templates */}

將可重複使用的模板建構器傳遞給`PlatformSandbox`. A fresh sandbox start sends the serialized definition to Platform, which content-addresses it and starts or reuses the provider build. Sandbox creation never blocks on a build. When the exact template isn't built yet, Platform boots the sandbox on the best available fallback and rebuilds the requested template in the background. The fallback is a same-lineage stale template with matching resources when one exists, otherwise the provider base template:

```typescript
import { PlatformSandbox, Template } from '@mastra/platform-workspace'

const commitSha = process.env.REPOSITORY_COMMIT_SHA!
const template = Template()
  .cpuCount(4)
  .memoryMB(8_192)
  .setWorkdir('/workspace/repo')
  .setEnvs({ BUILD_CONFIG_MARKER: 'template-v1' })
  .aptInstall(['git', 'jq'])
  .runCmd('git clone https://github.com/mastra-ai/mastra.git /workspace/repo')
  .runCmd(`git checkout ${commitSha}`)
  .runCmd('pnpm install --frozen-lockfile')

const sandbox = new PlatformSandbox({
  environmentId: 'env_abc',
  sandboxProvider: 'e2b',
  template,
})
await sandbox.start()
```

`Template()`支援`cpuCount`, `memoryMB`, `docker`, `runCmd`, `setWorkdir`, `setEnvs`, `aptInstall`, `pipInstall`, and `npmInstall`. Platform serializes the builder internally and computes the content hash. Call `await template.build(options)` to start or reuse that provider build without provisioning a sandbox. It returns `ready`, `pending`, or `failed`, with the template ID and an optional retry hint or error.

對E2B來說，`cpuCount()` and `memoryMB()` set the template build resources inherited by sandboxes created from the exact template or a resource-matched stale template. Both methods accept a positive safe integer. They default to 2 CPUs and 1,024 MB. Resource setters use last-value-wins semantics, and their effective values are part of the content identity. Omitting both setters is equivalent to explicitly selecting the defaults. If a pending build falls back to the provider base, that sandbox may use the provider's default resources. Check `templatePending` to detect this case.

`docker()`在 E2B 範本中安裝 Docker Engine 和 Compose。該守護程式在第一次使用 Docker 時啟動，因此從不使用它的沙箱無需付費。 Docker 僅在啟用時才是內容身分的一部分，因此沒有它的範本會保留其 ID。 Docker 至少使用 2,048 MB 記憶體。

Railway 將指令、工作目錄、環境和套件操作轉換為 Railway 範本指令。鐵路目前忽視`cpuCount()` and `memoryMB()` because its sandbox template API doesn't expose matching resource settings.

對於公共 GitHub 儲存庫，`createRepoTemplate()` can resolve and build the commit-pinned definition lazily when `start()` needs a fresh sandbox:

```typescript
import { createRepoTemplate, PlatformSandbox } from '@mastra/platform-workspace'

const sandbox = new PlatformSandbox({
  environmentId: 'env_abc',
  template: createRepoTemplate({
    getRepositoryAccess: async () => ({ cloneUrl: 'https://github.com/mastra-ai/mastra.git' }),
    setupCommand: 'pnpm install --frozen-lockfile',
    memoryMB: 2048,
  }),
})
await sandbox.start()
```

`createRepoTemplate()`接受相同的`cpuCount`, `memoryMB`, and `docker` settings as the `Template()` builder methods, as plain options. They carry the identity and stale-fallback semantics described above. Omit them for the provider defaults.

`setupCommand`也接受一個數組。每個條目都作為其自己的快取建置步驟運行。`workingDirectory` sets the cwd for the build and the sandbox, and the repository is cloned to `<workingDirectory>/<repo>`. `buildEnv` passes environment variables to the build steps only. They never enter the serialized definition. `buildEnvRevision` is an opaque id written ahead of the clone and setup steps. A new revision rebuilds them. Change it whenever `buildEnv` changes and never derive it from the values.

`getRepositoryAccess`鏡像 Factory 沙箱上下文攜帶的解析器，因此主機可以直接傳遞其上下文；當它不存在時，`createRepoTemplate()` returns `undefined` and the sandbox boots the provider default. The resolver skips reattachment to an existing `sandboxId`; on a fresh start, it resolves the repository's default-branch head before Platform starts or reuses the corresponding template build. If the repository head can't be resolved or the provider build fails, sandbox creation continues with the provider's default template so runtime setup can perform a cold checkout. For private repositories, the short-lived authorization token is sent as an ephemeral build environment value that stays out of the serialized definition and the persisted template record. It has no effect on content identity.

#### 一個範本中的多個儲存庫 {/* #several-repositories-in-one-template */}

經過`repos` instead of `getRepositoryAccess` to clone several repositories into one sandbox, each with its own access resolver and `setupCommand` (a string or an array, each entry its own build step):

```typescript
const template = createRepoTemplate({
  repos: [
    {
      getRepositoryAccess: async () => ({ cloneUrl: 'https://github.com/mastra-ai/mastra' }),
      setupCommand: 'pnpm install --frozen-lockfile',
    },
    {
      getRepositoryAccess: async () => ({
        cloneUrl: 'https://github.com/mastra-ai/template-docs-expert',
      }),
      setupCommand: 'npm install',
    },
  ],
  workspaceSetupCommand: 'npm install --global @mastra/mcp-docs-server',
  continueOnSetupFailure: true,
  workingDirectory: '/home/user/repos',
})
```

每個存儲庫都被克隆到`<workingDirectory>/<repo>`. Public repositories are built before private ones, keeping the caller's order within each group. Private credentials are ephemeral build envs visible to every build step, so any repository's setup command can read every other repository's token: only list repositories whose setup commands you trust together.

`workspaceSetupCommand`設定每個儲存庫後在工作目錄中執行。`continueOnSetupFailure` (default `false`) lets a failing setup command record its repository in `.mastra-sandbox/setup-failed` and continue instead of failing the build.

標記告訴會話圖像已經運行了什麼：`.mastra-sandbox/repos/<repo>` per repository and `.mastra-sandbox/workspace-setup` after the workspace commands, all under the working directory. With `continueOnSetupFailure`, check `.mastra-sandbox/setup-failed` first.

工作目錄和有序儲存庫清單形成系列金鑰，因此變更會啟動一個冷啟動的新系列，直到其第一個建置準備就緒，而設定指令或憑證的編輯則保留在熱系列中。如果任何條目的存取權限無法解決，範本將降級為僅資源，直到下一次解決為止。無法解析頭部的存儲庫將被取消固定克隆，而其他存儲庫則保留其固定。

`createRepoTemplate()`還附加了一個獨立於提交的`family` key to the definition (`repo:<cloneUrl>:<workingDirectory>/<repo>` for one repository, `repos:<hash>` over the working directory and the ordered clone URLs for a list). `family` groups successive builds of the "same thing", so every commit of the same repository belongs to the same family. Platform uses it to find a prior ready build in the same family and boot the new commit on that warm filesystem while the exact commit template builds in the background. For E2B, stale lookup is also partitioned by the effective CPU and memory settings so a fallback can't silently change the requested machine size. Callers using the raw `Template()` builder can attach their own family key with `.withFamily(key)` (any non-empty string up to 200 characters). Omit it to opt out of family fallback. The family key never influences the content-addressed template identity: two definitions that differ only in `family` share the same cache slot.

平台將建置狀態儲存在所選環境和Provider內的定義的伺服器派生內容雜湊下。

#### 觀察待處理的模板構建 {/* #observing-a-pending-template-build */}

當沙箱在後備模板（同一系列的資源匹配的先前成員或Provider基礎）上啟動時，平台回應包括`templatePending` field that `PlatformSandbox` surfaces for observability:

```typescript
await sandbox.start()
if (sandbox.templatePending) {
  // The sandbox is running on a fallback template.
  // A later start() of a sandbox with the same template definition
  // will pick up the exact template once the background build finishes.
  console.log('exact template still baking:', sandbox.templatePending.templateId)
}
```

`templatePending`當沙箱在確切的模板上啟動時未定義。`PlatformSandbox` never re-executes template operations inside a running sandbox. Reconcile any commit-specific filesystem state in your own runtime setup (for example, an `onStart` hook that runs `git fetch && git checkout <sha>`) exactly as you would with a fresh template. Reprovision on a later `start()` to pick up the ready exact template.

：：：警告

預設情況下，每個模板操作都會被序列化並發送到平台，平台根據所選Provider的功能對其進行解釋。使用`setEnvs(values, { ephemeral: true })` for short-lived build credentials: these values are sent separately and excluded from both content identity and persistence. They're unavailable at runtime and take precedence over serialized environment values with the same key. Supply them again on every build or fresh provision that may need to build. On Railway, the provider cache includes the transient build variables. Rotating a value can therefore trigger another provider build even though the Platform template ID stays stable.

### 檢查點恢復 {/* #checkpoint-recovery */}

建構函數`id` (explicit or auto-generated) is sent to the platform on `POST /sandbox` as an advisory recovery key:

* 如果平台認可`id` from a previous session, the new sandbox boots from the most recent checkpoint of that earlier sandbox's filesystem instead of the base recipe.
* 如果`id` isn't recognised, the platform starts a fresh sandbox from the base recipe. Auto-generated ids never match, so omitting `id` disables checkpoint recovery.

通過一個馬厩`id` to preserve a sandbox's filesystem across sessions or across a `destroy()`/`start()` cycle:

```typescript
const sandbox = new PlatformSandbox({
  id: `project-${projectId}`,
})
await sandbox.start() // Boots from the most recent checkpoint for this id, or fresh if unknown
```

檢查點恢復比`sandboxId` reattachment. Reattaching (via `sandboxId`) rejoins the exact live sandbox and its running processes. Checkpoint recovery constructs a brand new sandbox and restores its filesystem from the latest checkpoint the platform captured for the previous sandbox with that `id`. Running processes and any filesystem writes made after the last checkpoint aren't restored.

稱呼`snapshot()` after a filesystem update to capture the configured recovery checkpoint immediately. It resolves without capturing when the sandbox has no caller-provided `id` or isn't running.

```typescript
await sandbox.snapshot()
```

每個`id` maps to one independent filesystem. Reusing the same `id` across unrelated sandboxes causes the platform to boot them from each other's checkpoint.

放`seedCheckpointName` to provide a boot-only fallback when the checkpoint for `id` doesn't exist yet. The platform restores the checkpoint for `id` first when both exist. Later snapshots continue writing to the checkpoint for `id`. The seed remains unchanged.

```typescript
const sandbox = new PlatformSandbox({
  id: `project-session-${sessionId}`,
  seedCheckpointName: 'project-base',
})
```

### 克隆一組沙箱 {/* #cloning-for-a-fleet-of-sandboxes */}

`clone()`返回一個獨立的兄弟姐妹`PlatformSandbox` that inherits credentials and defaults (access token, project, environment, provider, template, network isolation, timeout, instructions, env, idle timeout, public ports) with per-instance overrides. The returned sandbox is unstarted and provisions on its own `start()`, so `clone()` performs no I/O:

```typescript
const template = new PlatformSandbox({
  networkIsolation: 'PRIVATE',
  idleTimeoutMinutes: 30,
})

const perProject = template.clone({ id: `project-${projectId}` })
await perProject.start()
```

結合`clone()` with a stable `id` per clone to opt each clone into [checkpoint recovery](#checkpoint-recovery) independently.

### 執行命令 {/* #executing-commands */}

`executeCommand`在遠端沙箱上運行命令並返回其輸出。經過`args` to have arguments safely shell-quoted:

```typescript
const result = await sandbox.executeCommand('python', ['analyze.py'], {
  timeout: 30_000,
  cwd: '/workspace',
  env: { INPUT: 'repo' },
})

console.log(result.stdout)
console.log(result.exitCode)
```

：：：警告

這`command` argument is a shell string and is concatenated verbatim into the remote shell. This lets you use pipes, redirects, and chaining (`ls -la | grep foo`) but means untrusted input must be passed through `args` (safely quoted) or shell-quoted by the caller. Untrusted `command` values allow arbitrary shell execution on the sandbox.

### 後台程式 {/* #background-processes */}

`sandbox.processes`在後台運行命令。當它們運行時輸出流，您可以列出、附加和停止它們：

```typescript
const handle = await sandbox.processes.spawn('pnpm dev', {
  onStdout: data => console.log(data),
})

// Everything running in the sandbox, plus exited processes not read yet
const running = await sandbox.processes.list()

await handle.kill()
```

流程沒有時間限制，除非您通過`timeout` to `spawn()` or the constructor. Call `get(pid)` to attach to a process this manager didn't start, for example after your app restarts. Output written before attaching isn't available.

長時間運行的進程的輸出流會定期重新連接，並且進程會透過它繼續運行。重新連接期間寫入的輸出會遺失，並且在其流重新連接時退出的進程會報告退出代碼`1` from `wait()` instead of its real exit code.

### 連接埠 URL {/* #port-urls */}

`sandbox.networking.getPortUrl(port)`傳回您的應用程式在沙箱中偵聽的連接埠的 URL，例如開發伺服器：

```typescript
await sandbox.processes.spawn('pnpm dev --host 0.0.0.0 --port 3000')

const url = await sandbox.networking?.getPortUrl(3000)
// https://3000-<sandbox id>.sandbox.us.mastra.cloud/
```

預設情況下，連接埠是私有的：沙箱組織成員登入 Mastra 後，會在瀏覽器中開啟 URL。和[`publicPorts: true`](#public-ports), anyone with the URL can open it without signing in. You can share it, since it never expires, and opening it wakes a paused sandbox.

`networking`是`undefined` on a sandbox whose ports can't be opened. `getPortUrl()` returns `null` without starting the sandbox when the sandbox isn't running or has been destroyed, for a port that isn't a whole number from 1 to 65535, and for the sandbox's reserved control port. Other platform errors, such as an invalid access token, are thrown.

您控制的瀏覽器（例如​​Agent程式的瀏覽器）無法登入。`getPortAuthCookie(port)` returns a cookie that lets it open the port's URL for an hour without signing in. Don't share the cookie: anyone holding it can open the port.

```typescript
const cookie = await sandbox.getPortAuthCookie(3000)
if (cookie) await browserContext.addCookies([cookie])
```

## 錯誤 {/* #errors */}

平台 API 故障增加`PlatformApiError`. Structured `{ error: { message, type } }` responses are parsed into `.code` (machine-readable kind) and `.proxyMessage` (human string); the raw response body stays available on `.body`:

```typescript
import { PlatformApiError } from '@mastra/platform-workspace'

try {
  await sandbox.executeCommand('cat', ['/missing.txt'])
} catch (err) {
  if (err instanceof PlatformApiError) {
    if (err.code === 'not_found') {
      // handle missing resource
    } else if (err.code === 'authentication_error') {
      // refresh token
    }
    console.error(err.status, err.code, err.proxyMessage)
  }
}
```

`code`和`proxyMessage` are `undefined` when the response body isn't JSON, for example an HTML 502 from a load balancer.

`executeCommand`在 direct-exec 資料平面（鐵路 TCP Agent的 WebSocket）上運行，並且還可以在不可恢復的故障時拋出兩個類型的沙箱錯誤：

```typescript
import { SandboxDestroyedError, SandboxExecTransportError } from '@mastra/platform-workspace'

try {
  await sandbox.executeCommand('pytest')
} catch (err) {
  if (err instanceof SandboxDestroyedError) {
    // /exec-lease returned 410; the sandbox has been destroyed.
    // The cached sandbox id and lease have already been cleared,
    // so reusing the instance will reprovision on the next call.
  } else if (err instanceof SandboxExecTransportError) {
    // Both the initial WebSocket attempt and the built-in retry
    // closed without an exit frame against a live sandbox.
    console.error(err.closeCode, err.closeReason, err.wsEndpoint)
  }
}
```

`SandboxExecTransportError`攜帶診斷欄位（`opened`, `closeCode`, `closeReason`, `wsEndpoint`, plus `sandboxId`, `command`, and `attempts`) so operators can distinguish a broken Railway data plane from a failed command.
