# PlatformSandbox

用於在 Mastra Platform 環境中建立 Sandbox 的用戶端。每個 `PlatformSandbox` 實例管理一個遠端 Sandbox：`start()` 建立它，`executeCommand()` 在其中執行命令，`destroy()` 將其銷毀。若要管理更多遠端 Sandbox，可建立更多實例，或使用 `clone()` 從已設定的範本衍生實例（請參閱[複製多個 Sandbox](#cloning-for-a-fleet-of-sandboxes)）。

Sandbox 從預先建置的 Provider 範本啟動，其中已安裝 Python 3、Node 22、TypeScript、tsx 與常用建置工具。你也可以使用可攜式的 `Template()` 建構器建立[可重複使用的範本](#reusable-templates)。傳入固定的 `id` 可啟用[檢查點復原](#checkpoint-recovery)，讓新 Sandbox 從先前 Sandbox 的檔案系統啟動。

相關 Provider：用於自行託管 Railway Sandbox 的 [`RailwaySandbox`](/integrations/sandboxes/railway)，以及用於本機 Sandbox 的 [`LocalSandbox`](/reference/workspace/local-sandbox)。

:::note

介面詳情請參閱 [WorkspaceSandbox 介面](/reference/workspace/sandbox)。

:::

部署至 Mastra Platform 時，系統會自動注入 `MASTRA_PLATFORM_ACCESS_TOKEN`、`MASTRA_PROJECT_ID` 和 `MASTRA_ENVIRONMENT_ID`，因此可以不傳入建構函式選項。本機開發時，`MASTRA_PLATFORM_ACCESS_TOKEN` 可以使用組織設定頁面 **API Tokens** 中以 `sk_` 開頭的 API 權杖。

Sandbox Provider 優先使用建構函式的 `sandboxProvider` 選項，其次使用 `SANDBOX_PROVIDER` 環境變數，預設使用 `e2b`。

## 用法 {/* #usage */}

將 `PlatformSandbox` 加入 Workspace，並指派給 Agent：

```typescript
import { Agent } from '@mastra/core/agent'
import { Workspace } from '@mastra/core/workspace'
import { PlatformSandbox } from '@mastra/platform-workspace'

const workspace = new Workspace({
  sandbox: new PlatformSandbox({
    // accessToken, projectId, environmentId all fall back to env vars
    idleTimeoutMinutes: 30,
  }),
})

const agent = new Agent({
  id: 'code-agent',
  name: 'Code Agent',
  instructions: 'You are a coding assistant working in this workspace.',
  model: '__GATEWAY_ANTHROPIC_MODEL_SONNET__',
  workspace,
})

const response = await agent.generate(
  'Print "Hello, world!" and show the current working directory.',
)

console.log(response.text)
```

### 專用網路 {/* #private-networking */}

將 `networkIsolation` 設為 `PRIVATE`，即可加入環境的私人網路，存取同一 Mastra Platform 環境中執行的其他服務：

```typescript
const workspace = new Workspace({
  sandbox: new PlatformSandbox({
    networkIsolation: 'PRIVATE',
  }),
})
```

預設的 `ISOLATED` 模式只允許連線至外部網際網路，不提供私人網路連線。

### 公開連接埠 {/* #public-ports */}

連接埠預設為私有，必須透過已登入的預覽連結存取。設定 `publicPorts` 後，任何取得連接埠 URL 的人都能存取，例如連線至接收 webhook 的服務：

```typescript
const workspace = new Workspace({
  sandbox: new PlatformSandbox({
    publicPorts: true,
  }),
})
```

兩種情況下的連接埠 URL 相同，差別只在於是否需要登入。此設定在建立 Sandbox 時確定，重新連接時傳入新值不會改變既有 Sandbox。複製的實例使用傳入的 `publicPorts` 選項，不會沿用重新連接的 Sandbox 設定。

### 重新連接至執行中的 Sandbox {/* #reattaching-to-a-running-sandbox */}

傳入既有的 `sandboxId`，即可重新連接至執行中的 Sandbox，而不建立新 Sandbox：

```typescript
const sandbox = new PlatformSandbox({
  sandboxId: 'sbx_abc123',
})
await sandbox.start()

const result = await sandbox.executeCommand('cat', ['/workspace/state.json'])
```

設定 `sandboxId` 後，Sandbox 已經存在，因此不需要提供 `environmentId`。

呼叫 `start()` 後，從 `sandboxId` 屬性讀取執行中 Sandbox 的平台 ID，並儲存以供下次重新連接。在目前程序啟動 Sandbox 之前，該屬性為 `undefined`。傳入建構函式的選項只是供 `start()` 使用的提示；在 `start()` 執行前，`getInfo()` 只回傳本機狀態，不會向平台查詢該提示。預設使用 `reattach: 'best-effort'` 時，如果平台已找不到該 ID，`start()` 會依 Sandbox 的邏輯 `id` 建立新 Sandbox。此回退操作需要 `environmentId`（或 `MASTRA_ENVIRONMENT_ID`）；若提示可能失效，請一併提供，否則 `start()` 會擲出 `environmentId is required`。

重新連接時，`start()` 回傳 `{ outcome: 'connected' }`；建立新 Sandbox 時回傳 `{ outcome: 'created' }`。從檢查點復原也屬於新建：即使檔案系統已還原，虛擬機仍是新的。共用約定請參閱 [`start()`](/reference/workspace/sandbox#start)。

如果建立新 Sandbox 會讓應用程式依賴的狀態在未察覺的情況下遺失，請設定 `reattach: 'required'`：

```typescript
const sandbox = new PlatformSandbox({
  sandboxId: 'sbx_abc123',
  reattach: 'required',
})
```

設定 `reattach: 'required'` 後，如果平台回報目標不存在（404）、已消失（410）或已銷毀，`start()` 會擲出 `code` 為 `SANDBOX_REATTACH_FAILED` 的 `SandboxError`，且不會建立 Sandbox。錯誤的 `details` 包含 `provider`、`sandboxId`、`logicalId`（Sandbox 的邏輯 `id`）和 `reason`。其他錯誤會原樣傳遞。若要重新建立，請清除已儲存的 `sandboxId`，並在建構 Sandbox 時不再傳入。複製的實例會繼承 `reattach` 設定。

### 可重複使用的範本 {/* #reusable-templates */}

將可重複使用的範本建構器傳給 `PlatformSandbox`。建立新 Sandbox 時，系統會將序列化後的定義傳送至 Platform。Platform 依內容識別該定義，並啟動或重用 Provider 的建置結果。建立 Sandbox 不會等待建置完成。如果完全相符的範本尚未建置完成，Platform 會先以可用的最佳替代範本啟動 Sandbox，並在背景建置指定範本。如果有同系列且資源設定相符的舊範本，就以該範本替代；否則使用 Provider 的基礎範本：

```typescript
import { PlatformSandbox, Template } from '@mastra/platform-workspace'

const commitSha = process.env.REPOSITORY_COMMIT_SHA!
const template = Template()
  .cpuCount(4)
  .memoryMB(8_192)
  .setWorkdir('/workspace/repo')
  .setEnvs({ BUILD_CONFIG_MARKER: 'template-v1' })
  .aptInstall(['git', 'jq'])
  .runCmd('git clone https://github.com/mastra-ai/mastra.git /workspace/repo')
  .runCmd(`git checkout ${commitSha}`)
  .runCmd('pnpm install --frozen-lockfile')

const sandbox = new PlatformSandbox({
  environmentId: 'env_abc',
  sandboxProvider: 'e2b',
  template,
})
await sandbox.start()
```

`Template()` 支援 `cpuCount`、`memoryMB`、`docker`、`runCmd`、`setWorkdir`、`setEnvs`、`aptInstall`、`pipInstall` 和 `npmInstall`。Platform 會在內部序列化建構器並計算內容雜湊。呼叫 `await template.build(options)` 可啟動或重用該 Provider 的建置，而不建立 Sandbox。此方法會回傳 `ready`、`pending` 或 `failed`，以及範本 ID；也可能包含重試提示或錯誤。

對 E2B 而言，`cpuCount()` 和 `memoryMB()` 設定範本的建置資源。從完全相符的範本或資源設定相符的同系列舊範本建立的 Sandbox 會沿用這些設定。兩個方法都接受正整數，且必須落在 JavaScript 的安全整數範圍內；預設為 2 顆 CPU 和 1,024 MB 記憶體。重複設定資源時以最後一次的值為準，生效的設定也會納入內容識別。兩者都省略，等同於明確指定預設值。如果待完成的建置改用 Provider 的基礎範本，該 Sandbox 可能使用 Provider 的預設資源；可檢查 `templatePending` 判斷是否發生這種情況。

`docker()` 會在 E2B 範本中安裝 Docker Engine 和 Compose。Docker 守護程序會在首次使用時才啟動，因此從未使用 Docker 的 Sandbox 不會產生相關費用。只有啟用 Docker 時，這項設定才會納入內容識別；未啟用 Docker 的範本會保有原本的 ID。使用 Docker 時，請配置至少 2,048 MB 記憶體。

Railway 會將命令、工作目錄、環境變數和套件操作轉換為 Railway 範本指令。Railway 的 Sandbox 範本 API 目前未提供對應的資源設定，因此會忽略 `cpuCount()` 和 `memoryMB()`。

對於公開的 GitHub 儲存庫，當 `start()` 需要建立新 Sandbox 時，`createRepoTemplate()` 才會解析並建置鎖定至特定提交的範本定義：

```typescript
import { createRepoTemplate, PlatformSandbox } from '@mastra/platform-workspace'

const sandbox = new PlatformSandbox({
  environmentId: 'env_abc',
  template: createRepoTemplate({
    getRepositoryAccess: async () => ({ cloneUrl: 'https://github.com/mastra-ai/mastra.git' }),
    setupCommand: 'pnpm install --frozen-lockfile',
    memoryMB: 2048,
  }),
})
await sandbox.start()
```

`createRepoTemplate()` 可透過一般選項接受 `cpuCount`、`memoryMB` 和 `docker`，與 `Template()` 建構器的同名方法相同。這些選項也遵循上述內容識別及使用同系列舊範本替代的規則。省略選項即可使用 Provider 的預設值。

`setupCommand` 也接受陣列，每個項目都會作為獨立、可快取的建置步驟執行。`workingDirectory` 設定建置及 Sandbox 的工作目錄，儲存庫會複製到 `<workingDirectory>/<repo>`。`buildEnv` 的環境變數只會傳給建置步驟，不會寫入序列化後的定義。`buildEnvRevision` 是在複製儲存庫及執行設定步驟前寫入的不透明 ID；變更版本會使這些步驟重新建置。每次變更 `buildEnv` 時都應更新此 ID，且不要根據環境變數的值推導它。

`getRepositoryAccess` 與 Factory Sandbox 上下文中的儲存庫存取解析器採用相同形式，因此宿主程式可以直接傳入該上下文。若未提供解析器，`createRepoTemplate()` 會回傳 `undefined`，Sandbox 則使用 Provider 的預設範本啟動。重新連接既有 `sandboxId` 時不會呼叫解析器；建立新 Sandbox 時，解析器會先取得儲存庫預設分支的最新提交，Platform 再啟動或重用對應的範本建置。如果無法解析該提交，或 Provider 建置失敗，仍會以 Provider 的預設範本建立 Sandbox，讓執行階段的設定程序從頭取得儲存庫。對於私有儲存庫，短效授權權杖會以暫時性建置環境變數傳送，不會寫入序列化後的定義或持久儲存的範本紀錄，也不影響內容識別。

#### 一個範本中的多個儲存庫 {/* #several-repositories-in-one-template */}

若要將多個儲存庫複製到同一個 Sandbox，請傳入 `repos`，而非 `getRepositoryAccess`。每個儲存庫都可有自己的存取解析器及 `setupCommand`；後者可以是字串或陣列，陣列中的每個項目都是獨立的建置步驟：

```typescript
const template = createRepoTemplate({
  repos: [
    {
      getRepositoryAccess: async () => ({ cloneUrl: 'https://github.com/mastra-ai/mastra' }),
      setupCommand: 'pnpm install --frozen-lockfile',
    },
    {
      getRepositoryAccess: async () => ({
        cloneUrl: 'https://github.com/mastra-ai/template-docs-expert',
      }),
      setupCommand: 'npm install',
    },
  ],
  workspaceSetupCommand: 'npm install --global @mastra/mcp-docs-server',
  continueOnSetupFailure: true,
  workingDirectory: '/home/user/repos',
})
```

每個儲存庫都會複製到 `<workingDirectory>/<repo>`。公開儲存庫會先於私有儲存庫建置，各組內仍依呼叫端提供的順序執行。私有儲存庫的憑證是所有建置步驟都能讀取的暫時性環境變數，因此任一儲存庫的設定命令都可能讀取其他儲存庫的權杖。請只將設定命令可相互信任的儲存庫列在一起。

所有儲存庫設定完成後，`workspaceSetupCommand` 會在工作目錄中執行。`continueOnSetupFailure` 預設為 `false`；啟用後，設定命令失敗時會將該儲存庫記錄在 `.mastra-sandbox/setup-failed`，並繼續執行，而不讓整個建置失敗。

這些標記可讓工作階段知道映像檔已完成哪些步驟：每個儲存庫對應 `.mastra-sandbox/repos/<repo>`，Workspace 設定命令完成後則會有 `.mastra-sandbox/workspace-setup`；它們都位於工作目錄下。若啟用 `continueOnSetupFailure`，請先檢查 `.mastra-sandbox/setup-failed`。

工作目錄和依序排列的儲存庫清單共同組成系列識別鍵。變更其中任一項都會建立新系列；在首次建置完成前，新系列須從頭啟動。變更設定命令或憑證則仍屬於原系列，可沿用已準備好的範本。如果任何儲存庫的存取資訊無法解析，範本會暫時退回只含資源設定的形式，直到下次解析。若無法取得某個儲存庫預設分支的最新提交，複製該儲存庫時就不會鎖定提交；其他儲存庫仍會維持各自鎖定的提交。

`createRepoTemplate()` 也會在定義中加入不隨提交變更的 `family` 識別鍵：單一儲存庫使用 `repo:<cloneUrl>:<workingDirectory>/<repo>`；儲存庫清單則使用根據工作目錄及依序排列的複製 URL 算出的 `repos:<hash>`。`family` 將同一組內容的連續建置歸為同一系列，因此同一儲存庫的各次提交都屬於同一系列。Platform 可據此找到同系列中先前已完成的建置，在其現成的檔案系統上啟動新提交，同時於背景建置完全符合該提交的範本。對 E2B 而言，查找舊範本時還會比對生效的 CPU 與記憶體設定，避免替代範本在未察覺的情況下改變指定的機器規格。直接使用 `Template()` 建構器時，可以透過 `.withFamily(key)` 指定系列識別鍵；`key` 必須是長度不超過 200 個字元的非空字串。省略即可停用同系列舊範本替代機制。系列識別鍵不影響依內容決定的範本身分：只有 `family` 不同的兩個定義會共用相同的快取位置。

Platform 會在所選環境及 Provider 中，以伺服器根據定義算出的內容雜湊儲存建置狀態。

#### 查看尚未完成的範本建置 {/* #observing-a-pending-template-build */}

當 Sandbox 使用替代範本啟動時，Platform 的回應會包含 `templatePending` 欄位，`PlatformSandbox` 也會提供此欄位供檢查。替代範本可能是同系列中資源設定相符的舊範本，或 Provider 的基礎範本：

```typescript
await sandbox.start()
if (sandbox.templatePending) {
  // The sandbox is running on a fallback template.
  // A later start() of a sandbox with the same template definition
  // will pick up the exact template once the background build finishes.
  console.log('exact template still baking:', sandbox.templatePending.templateId)
}
```

如果 Sandbox 使用完全相符的範本啟動，`templatePending` 會是 `undefined`。`PlatformSandbox` 不會在執行中的 Sandbox 裡重新執行範本操作。請在自己的執行階段設定程序中調整與提交相關的檔案系統狀態，做法與使用全新範本時相同；例如透過執行 `git fetch && git checkout <sha>` 的 `onStart` hook。待完全相符的範本建置完成後，可在之後呼叫 `start()` 時重新建立 Sandbox，以使用該範本。

:::warning

預設情況下，每項範本操作都會序列化並傳送至 Platform，由 Platform 依所選 Provider 的能力處理。短效建置憑證請使用 `setEnvs(values, { ephemeral: true })`：這些值會另外傳送，不納入內容識別，也不會持久儲存。它們無法在執行階段使用；若與序列化後的環境變數同名，則以這些暫時性值為準。每次建置或可能觸發建置的全新建立作業，都必須重新提供這些值。在 Railway 上，Provider 的快取會納入暫時性建置變數。因此，即使 Platform 範本 ID 不變，輪替變數值仍可能觸發另一次 Provider 建置。

:::

### 從檢查點還原 {/* #checkpoint-recovery */}

建構函式中的 `id` 可以明確指定，也可以自動產生。呼叫 `POST /sandbox` 時，系統會將它傳給 Platform，作為還原時的參考識別鍵：

* 如果 Platform 辨識出前一次工作階段使用的 `id`，新 Sandbox 會從先前 Sandbox 檔案系統的最新檢查點啟動，而非使用基礎建立設定。
* 如果 Platform 不辨識該 `id`，就會依基礎建立設定啟動全新 Sandbox。自動產生的 ID 不會與先前的 ID 相符，因此省略 `id` 就等於停用檢查點還原。

若要在不同工作階段之間，或在一次 `destroy()`／`start()` 週期之後保留 Sandbox 的檔案系統，請傳入固定的 `id`：

```typescript
const sandbox = new PlatformSandbox({
  id: `project-${projectId}`,
})
await sandbox.start() // Boots from the most recent checkpoint for this id, or fresh if unknown
```

檢查點還原的範圍比透過 `sandboxId` 重新連接更有限。重新連接會回到同一個仍在執行的 Sandbox，包含其中執行中的程序。檢查點還原則會建立全新 Sandbox，並以 Platform 為先前相同 `id` 的 Sandbox 擷取的最新檢查點還原檔案系統。執行中的程序，以及最近一次檢查點之後寫入的檔案，都不會還原。

更新檔案系統後，呼叫 `snapshot()` 可立即擷取已設定的還原檢查點。如果呼叫端未提供 `id`，或 Sandbox 尚未執行，此方法會直接完成，不會擷取檢查點。

```typescript
await sandbox.snapshot()
```

每個 `id` 都對應獨立的檔案系統。若不相關的 Sandbox 重用同一個 `id`，Platform 可能會讓它們從彼此的檢查點啟動。

設定 `seedCheckpointName`，可在 `id` 對應的檢查點尚不存在時，提供僅供啟動使用的備用檢查點。如果兩者都存在，Platform 會優先還原 `id` 對應的檢查點。之後擷取的快照仍會寫入 `id` 對應的檢查點，種子檢查點不會改變。

```typescript
const sandbox = new PlatformSandbox({
  id: `project-session-${sessionId}`,
  seedCheckpointName: 'project-base',
})
```

### 複製多個 Sandbox {/* #cloning-for-a-fleet-of-sandboxes */}

`clone()` 會傳回獨立的 `PlatformSandbox` 實例。它會繼承憑證及預設設定，包括存取權杖、專案、環境、Provider、範本、網路隔離、逾時時間、指示、環境變數、閒置逾時時間及公開連接埠；也可以針對個別實例覆寫設定。傳回的 Sandbox 尚未啟動，會在自身的 `start()` 呼叫時才建立，因此 `clone()` 不會執行 I/O：

```typescript
const template = new PlatformSandbox({
  networkIsolation: 'PRIVATE',
  idleTimeoutMinutes: 30,
})

const perProject = template.clone({ id: `project-${projectId}` })
await perProject.start()
```

搭配 `clone()` 為每個複製實例指定固定的 `id`，即可讓它們各自使用[檢查點還原](#checkpoint-recovery)。

### 執行命令 {/* #executing-commands */}

`executeCommand` 會在遠端 Sandbox 執行命令並回傳輸出。將參數透過 `args` 傳入，可安全地為它們加上 shell 引號：

```typescript
const result = await sandbox.executeCommand('python', ['analyze.py'], {
  timeout: 30_000,
  cwd: '/workspace',
  env: { INPUT: 'repo' },
})

console.log(result.stdout)
console.log(result.exitCode)
```

:::warning

`command` 參數是 shell 字串，會原樣串接到遠端 shell 命令中。這讓你可以使用管線、重新導向及串接命令（`ls -la | grep foo`），但不可信任的輸入必須透過會安全加上引號的 `args` 傳入，或由呼叫端自行加上 shell 引號。若將不可信任的值傳給 `command`，對方就能在 Sandbox 中執行任意 shell 命令。

:::

### 背景程序 {/* #background-processes */}

`sandbox.processes` 會在背景執行命令。程序執行期間會持續傳回輸出；你可以列出程序、連接至程序，或停止程序：

```typescript
const handle = await sandbox.processes.spawn('pnpm dev', {
  onStdout: data => console.log(data),
})

// Everything running in the sandbox, plus exited processes not read yet
const running = await sandbox.processes.list()

await handle.kill()
```

除非透過 `spawn()` 或建構函式傳入 `timeout`，否則程序沒有執行時間限制。呼叫 `get(pid)` 可以連接至這個管理器未啟動的程序，例如應用程式重新啟動後仍在執行的程序。連接前產生的輸出無法取得。

長時間執行的程序，其輸出串流會定期重新連接；程序在重新連接期間仍會持續執行。這段期間產生的輸出會遺失。如果程序恰好在輸出串流重新連接時結束，`wait()` 會回報結束代碼 `1`，而非實際的結束代碼。

### 連接埠 URL {/* #port-urls */}

`sandbox.networking.getPortUrl(port)` 會傳回應用程式在 Sandbox 中監聽的連接埠 URL，例如開發伺服器的 URL：

```typescript
await sandbox.processes.spawn('pnpm dev --host 0.0.0.0 --port 3000')

const url = await sandbox.networking?.getPortUrl(3000)
// https://3000-<sandbox id>.sandbox.us.mastra.cloud/
```

連接埠預設為私有：Sandbox 所屬組織的成員登入 Mastra 後，才能在瀏覽器中開啟該 URL。設定 [`publicPorts: true`](#public-ports) 後，任何取得 URL 的人都能無須登入直接開啟。此 URL 不會過期，因此可以分享；開啟 URL 也會喚醒已暫停的 Sandbox。

如果 Sandbox 的連接埠無法對外開放，`networking` 會是 `undefined`。當 Sandbox 未執行或已銷毀、連接埠不是 1 到 65535 的整數，或指定的是 Sandbox 保留的控制連接埠時，`getPortUrl()` 會直接傳回 `null`，不會啟動 Sandbox。其他 Platform 錯誤（例如存取權杖無效）則會擲出。

您控制的瀏覽器（例如 Agent 使用的瀏覽器）無法自行登入。`getPortAuthCookie(port)` 會傳回一個 Cookie，讓該瀏覽器在一小時內無須登入即可開啟連接埠 URL。請勿分享此 Cookie；任何持有者都能存取該連接埠。

```typescript
const cookie = await sandbox.getPortAuthCookie(3000)
if (cookie) await browserContext.addCookies([cookie])
```

## 錯誤 {/* #errors */}

Platform API 請求失敗時會擲出 `PlatformApiError`。結構化的 `{ error: { message, type } }` 回應會解析為 `.code`（供程式判讀的錯誤類型）和 `.proxyMessage`（供人閱讀的訊息）；原始回應內容仍可透過 `.body` 取得：

```typescript
import { PlatformApiError } from '@mastra/platform-workspace'

try {
  await sandbox.executeCommand('cat', ['/missing.txt'])
} catch (err) {
  if (err instanceof PlatformApiError) {
    if (err.code === 'not_found') {
      // handle missing resource
    } else if (err.code === 'authentication_error') {
      // refresh token
    }
    console.error(err.status, err.code, err.proxyMessage)
  }
}
```

如果回應內容不是 JSON，例如負載平衡器傳回 HTML 格式的 502 錯誤頁面，`code` 和 `proxyMessage` 都會是 `undefined`。

`executeCommand` 透過 direct-exec 資料平面執行命令（透過 WebSocket 連接 Railway tcp-proxy）。若發生無法復原的故障，還可能擲出以下兩種 Sandbox 錯誤：

```typescript
import { SandboxDestroyedError, SandboxExecTransportError } from '@mastra/platform-workspace'

try {
  await sandbox.executeCommand('pytest')
} catch (err) {
  if (err instanceof SandboxDestroyedError) {
    // /exec-lease returned 410; the sandbox has been destroyed.
    // The cached sandbox id and lease have already been cleared,
    // so reusing the instance will reprovision on the next call.
  } else if (err instanceof SandboxExecTransportError) {
    // Both the initial WebSocket attempt and the built-in retry
    // closed without an exit frame against a live sandbox.
    console.error(err.closeCode, err.closeReason, err.wsEndpoint)
  }
}
```

`SandboxExecTransportError` 提供 `opened`、`closeCode`、`closeReason`、`wsEndpoint`、`sandboxId`、`command` 和 `attempts` 等診斷欄位，協助維運人員區分 Railway 資料平面故障與命令執行失敗。
