# MastraAuthWorkos 類別

`MastraAuthWorkos` 類別透過 WorkOS 為 Mastra 提供身分驗證。它使用 WorkOS 存取權杖驗證傳入的請求，並透過 `auth` 選項整合至 Mastra 伺服器。

## 使用範例 {/* #usage-example */}

```typescript title="src/mastra/index.ts"
import { Mastra } from '@mastra/core'
import { MastraAuthWorkos } from '@mastra/auth-workos'

export const mastra = new Mastra({
  server: {
    auth: new MastraAuthWorkos({
      apiKey: process.env.WORKOS_API_KEY,
      clientId: process.env.WORKOS_CLIENT_ID,
    }),
  },
})
```

:::note

若已設定所需環境變數（`WORKOS_API_KEY` 和 `WORKOS_CLIENT_ID`），即可省略建構函式參數，直接使用 `new MastraAuthWorkos()`。

:::

## 預設授權行為 {/* #default-authorization-behavior */}

預設情況下，只要解析出的 WorkOS 使用者物件同時包含 `id` 和 `workosId`，`MastraAuthWorkos` 就會允許該已驗證使用者存取。

1. **權杖驗證**：透過 WorkOS 確認存取權杖有效且未過期
1. **取得使用者**：從已驗證的權杖中擷取使用者資料
1. **授權判斷**：若解析出的使用者包含必要識別碼，就允許存取

預設情況下，`MastraAuthWorkos` 負責身分驗證，不依角色限制存取。

## 載入 FGA 組織成員資格 {/* #fga-membership-loading */}

使用 `MastraFGAWorkos` 時，將 `fetchMemberships` 設為 `true`。這會在身分驗證期間載入使用者的 WorkOS 組織成員資格，讓 FGA 檢查能解析正確的組織成員資格 ID。

當 `fetchMemberships` 為 `false` 時，Mastra 不會在每次已驗證的請求中額外呼叫 WorkOS 的 `listOrganizationMemberships()`。

## 服務權杖與 JWT 宣告 {/* #service-tokens-and-jwt-claims */}

如果 WorkOS JWT 範本包含自訂宣告，可以將其直接對應至已驗證的 `WorkOSUser`。

```typescript title="src/mastra/auth.ts"
import { MastraAuthWorkos } from '@mastra/auth-workos'

const auth = new MastraAuthWorkos({
  apiKey: process.env.WORKOS_API_KEY,
  clientId: process.env.WORKOS_CLIENT_ID,
  redirectUri: process.env.WORKOS_REDIRECT_URI,
  trustJwtClaims: true,
  jwtClaims: {
    organizationId: 'org_id',
    organizationMembershipId: 'urn:mastra:organization_membership_id',
  },
})
```

啟用 `trustJwtClaims` 後，即使不適合透過 `getUser()` 查詢服務主體，Mastra 仍可使用已驗證的 Bearer 權杖完成身分驗證。對於機器對機器流程，建議以此方式將預先解析的 `organizationMembershipId` 傳入 FGA 檢查。

## 客製化授權 {/* #custom-authorization */}

若需要更嚴格的授權規則，可以繼承 `MastraAuthWorkos` 並覆寫 `authorizeUser()`：

```typescript title="src/mastra/auth.ts"
import { MastraAuthWorkos } from '@mastra/auth-workos'
import type { HonoRequest } from 'hono'

class AdminOnlyWorkosAuth extends MastraAuthWorkos {
  async authorizeUser(user: any, _request: HonoRequest): Promise<boolean> {
    return user?.metadata?.role === 'admin'
  }
}
```

## WorkOS 使用者類型 {/* #workos-user-type */}

`authorizeUser()` 與其他 WorkOS身分驗證hook 中的 `WorkOSUser` 類型，包含 Mastra 標準化的 使用者欄位及 WorkOS 專屬元資料。WorkOS 亦允許管理員設定自訂 JWT 範本，因此實際結構取決於設定。以下是 WorkOS 使用者物件的範例：

```javascript oxfmt:false
{
  'urn:myapp:full_name': 'John Doe',
  'urn:myapp:email': 'john.doe@example.com',
  'urn:myapp:organization_tier': 'bronze',
  'urn:myapp:user_language': 'en',
  'urn:myapp:organization_domain': 'example.com',
  iss: 'https://api.workos.com/user_management/client_01ABC123DEF456GHI789JKL012',
  sub: 'user_01XYZ789ABC123DEF456GHI012',
  sid: 'session_01PQR456STU789VWX012YZA345',
  jti: '01MNO678PQR901STU234VWX567',
  org_id: 'org_01DEF234GHI567JKL890MNO123',
  role: 'member',
  roles: [ 'member' ],
  permissions: [],
  exp: 1758290589,
  iat: 1758290289
}
```

以 `urn:myapp:` 開頭的屬性，是在 WorkOS JWT 範本中設定的自訂宣告。標準 JWT 宣告包括 `sub`（使用者 ID）、`iss`（簽發者）和 `exp`（到期時間）；WorkOS 專屬宣告包括 `org_id`、`role` 和 `roles`。
