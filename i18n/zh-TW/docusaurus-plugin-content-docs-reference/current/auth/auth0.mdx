# MastraAuthAuth0 類

這`MastraAuthAuth0`類別使用 Auth0 為 Mastra 提供身份驗證。它使用 Auth0 頒發的 JWT 令牌驗證傳入請求，並使用`auth`選項。

## 使用範例 {/* #usage-example */}

```typescript title="src/mastra/index.ts"
import { Mastra } from '@mastra/core'
import { MastraAuthAuth0 } from '@mastra/auth-auth0'

export const mastra = new Mastra({
  server: {
    auth: new MastraAuthAuth0({
      domain: process.env.AUTH0_DOMAIN,
      audience: process.env.AUTH0_AUDIENCE,
    }),
  },
})
```

：：：筆記

如果需要環境變數（`AUTH0_DOMAIN` and `AUTH0_AUDIENCE`) are set. In that case, use `new MastraAuthAuth0()` without any arguments.

## 預設授權行為 {/* #default-authorization-behavior */}

預設情況下，`MastraAuthAuth0` validates Auth0 JWT tokens and allows access to all authenticated users:

1. **令牌驗證**：使用 Auth0 的公鑰 (JWKS) 驗證 JWT 令牌
2. **簽名驗證**：確保令牌由您的 Auth0 租戶簽名
3. **過期檢查**：驗證令牌尚未過期
4. **觀眾驗證**：確認令牌是為您的特定 API（受眾）頒發的
5. **發行人驗證**：確保令牌是由您的 Auth0 網域頒發的

如果所有驗證都通過，則認為使用者已獲得授權。要实现自定义授权逻辑（例如基于角色的访问控制），请提供自定义`authorizeUser` function.

## Auth0 使用者類型 {/* #auth0-user-type */}

這`Auth0User` type used in the `authorizeUser` function corresponds to the decoded JWT token payload, which typically includes:

* `sub`：使用者的唯一識別碼（主題）
* `email`：使用者的電子郵件地址（如果包含在令牌中）
* `email_verified`: 信箱是否驗證
* `name`：使用者的顯示名稱（如果有）
* `picture`：使用者個人資料圖片的 URL（如果有）
* `iss`：令牌頒發者（您的 Auth0 網域）
* `aud`：令牌受眾（您的 API 識別碼）
* `iat`：以時間戳發行的令牌
* `exp`: 令牌過期時間戳
* `scope`：授予令牌的範圍
* 在 Auth0 租戶中配置的自訂聲明和應用程式元數據

可用的確切屬性取決於您的 Auth0 配置、請求的範圍以及您配置的任何自訂聲明。

經過身份驗證的用戶的`id` is the token's `id` claim, or its `sub` claim when the token has no `id`. RBAC looks up roles by this `id`, and it owns the records the user creates unless `mapUserToResourceId` is set. See [user IDs from JWT providers](/docs/guides/authentication-identity#user-ids-from-jwt-providers).
