# 複合儲存

`MastraCompositeStore` 可組合不同 Provider 的儲存領域。需要依用途使用不同資料庫時，例如以 LibSQL 儲存記憶、以 PostgreSQL 儲存 Workflow，就可以使用它。

## 安裝 {/* #installation */}

`MastraCompositeStore` 包含在 `@mastra/core` 中：

```bash npm2yarn
npm install @mastra/core@latest
```

還需要安裝要組合使用的儲存 Provider：

```bash npm2yarn
npm install @mastra/pg@latest @mastra/libsql@latest @mastra/mongodb@latest
```

## 儲存領域 {/* #storage-domains */}

Mastra 依領域組織儲存，每個領域負責特定類型的資料。不同領域可使用不同的儲存介接器；各儲存套件會匯出其實作的領域類別。

| 領域 | 說明 |
| - | - |
| `memory` | 持久保存 Agent 對話，包括執行緒（對話工作階段）、訊息、資源（使用者身分）與工作記憶（跨對話保留的脈絡）。 |
| `workflows` | Workflow 執行狀態。Workflow 因等待人工輸入、外部事件或排定的恢復時間而暫停時，狀態會儲存在此，讓伺服器重新啟動後可繼續執行。 |
| `scores` | Mastra Evals 系統的評估結果。分數與指標會持久保存，供日後分析和比較。 |
| `observability` | 遙測資料，包括 Trace 與 Span。Agent 互動、Tool 呼叫及 LLM 請求產生的 Span 會彙整為 Trace，供除錯與效能分析。 |
| `agents` | 已儲存 Agent 的設定。可在執行階段定義與更新 Agent，無須部署程式碼。 |
| `datasets` | 實驗執行使用的評估資料集，儲存資料集定義、Schema 與版本化項目。 |
| `experiments` | 實驗執行及逐項實驗結果，並連結至資料集與目標。 |

:::note

`MastraCompositeStore` 接受上述所有領域鍵，但各儲存套件支援的領域不同。可以依領域混用介接器，前提是相應套件已實作並匯出該領域類別。例如，`memory: new MemoryLibSQL(...)` 與 `workflows: new WorkflowsPG(...)` 可以搭配，因為兩個套件都匯出了對應的領域類別。

:::

## 用法 {/* #usage */}

### 基本組合 {/* #basic-composition */}

直接從各儲存套件匯入領域類別並組合：

```typescript title="src/mastra/index.ts"
import { MastraCompositeStore } from '@mastra/core/storage'
import { WorkflowsPG, ScoresPG } from '@mastra/pg'
import { MemoryLibSQL } from '@mastra/libsql'
import { Mastra } from '@mastra/core'

export const mastra = new Mastra({
  storage: new MastraCompositeStore({
    id: 'composite',
    domains: {
      memory: new MemoryLibSQL({ url: 'file:./local.db' }),
      workflows: new WorkflowsPG({ connectionString: process.env.DATABASE_URL }),
      scores: new ScoresPG({ connectionString: process.env.DATABASE_URL }),
    },
  }),
})
```

### 使用預設儲存 {/* #with-a-default-storage */}

使用 `default` 指定備援儲存，再覆寫特定領域：

```typescript title="src/mastra/index.ts"
import { MastraCompositeStore } from '@mastra/core/storage'
import { PostgresStore } from '@mastra/pg'
import { MemoryLibSQL } from '@mastra/libsql'
import { Mastra } from '@mastra/core'

const pgStore = new PostgresStore({
  id: 'pg',
  connectionString: process.env.DATABASE_URL,
})

export const mastra = new Mastra({
  storage: new MastraCompositeStore({
    id: 'composite',
    default: pgStore,
    domains: {
      memory: new MemoryLibSQL({ url: 'file:./local.db' }),
    },
  }),
})
```

### 混用後端 {/* #mixed-backends */}

使用各儲存套件的領域類別，將不同領域導向不同後端。以下範例把記憶與 Workflow 狀態存入 MongoDB，並把可觀測性資料存入 ClickHouse：

```typescript title="src/mastra/index.ts"
import { Mastra } from '@mastra/core'
import { MastraCompositeStore } from '@mastra/core/storage'
import { ObservabilityStorageClickhouse } from '@mastra/clickhouse'
import { MemoryStorageMongoDB, WorkflowsStorageMongoDB } from '@mastra/mongodb'

export const mastra = new Mastra({
  storage: new MastraCompositeStore({
    id: 'composite',
    domains: {
      memory: new MemoryStorageMongoDB({
        uri: process.env.MONGODB_URI,
        dbName: 'mastra_memory',
      }),
      workflows: new WorkflowsStorageMongoDB({
        uri: process.env.MONGODB_URI,
        dbName: 'mastra_workflows',
      }),
      observability: new ObservabilityStorageClickhouse({
        url: process.env.CLICKHOUSE_URL,
        username: process.env.CLICKHOUSE_USERNAME,
        password: process.env.CLICKHOUSE_PASSWORD,
      }),
    },
  }),
})
```

### 停用領域 {/* #disabling-a-domain */}

將領域設為 `false` 即可停用。停用的領域不會退回使用 `default`，因此不會持久保存該領域的資料：

```typescript title="src/mastra/index.ts"
import { MastraCompositeStore } from '@mastra/core/storage'
import { PostgresStore } from '@mastra/pg'
import { Mastra } from '@mastra/core'

const pgStore = new PostgresStore({
  id: 'pg',
  connectionString: process.env.DATABASE_URL,
})

export const mastra = new Mastra({
  storage: new MastraCompositeStore({
    id: 'composite',
    default: pgStore,
    domains: {
      // don't persist traces and spans
      observability: false,
    },
  }),
})
```

## 初始化 {/* #initialization */}

`MastraCompositeStore` 會分別初始化每個已設定的領域。傳入 Mastra 類別時，系統會自動呼叫 `init()`：

```typescript title="src/mastra/index.ts"
import { MastraCompositeStore } from '@mastra/core/storage'
import { MemoryPG, WorkflowsPG, ScoresPG } from '@mastra/pg'
import { Mastra } from '@mastra/core'

const storage = new MastraCompositeStore({
  id: 'composite',
  domains: {
    memory: new MemoryPG({ connectionString: process.env.DATABASE_URL }),
    workflows: new WorkflowsPG({ connectionString: process.env.DATABASE_URL }),
    scores: new ScoresPG({ connectionString: process.env.DATABASE_URL }),
  },
})

export const mastra = new Mastra({
  storage, // init() called automatically
})
```

直接使用儲存時，需明確呼叫 `init()`：

```typescript
import { MastraCompositeStore } from '@mastra/core/storage'
import { MemoryPG } from '@mastra/pg'

const storage = new MastraCompositeStore({
  id: 'composite',
  domains: {
    memory: new MemoryPG({ connectionString: process.env.DATABASE_URL }),
  },
})

await storage.init()

// Access domain-specific stores via getStore()
const memoryStore = await storage.getStore('memory')
const thread = await memoryStore?.getThreadById({ threadId: '...' })
```

## 關閉連線 {/* #closing-connections */}

`close()` 會釋放複合儲存所用各儲存實例的連線，包括 `default`、`editor`，以及使用自身用戶端的領域。即使多個領域共用同一實例，每個儲存實例也只會關閉一次。將複合儲存傳入 Mastra 類別時，`shutdown()` 會呼叫 `close()`：

```typescript title="src/mastra/index.ts"
import { MastraCompositeStore } from '@mastra/core/storage'
import { PostgresStore } from '@mastra/pg'
import { Mastra } from '@mastra/core'

const pgStore = new PostgresStore({
  id: 'pg-storage',
  connectionString: process.env.DATABASE_URL,
})

export const mastra = new Mastra({
  storage: new MastraCompositeStore({ id: 'composite', default: pgStore }),
})

process.on('SIGTERM', async () => {
  // Releases the Postgres pool, so the process can exit
  await mastra.shutdown()
})
```

若建立某個儲存實例僅為提供一個領域，便無法透過複合儲存存取它。請保留該實例的參照，並自行關閉：

```typescript title="src/mastra/index.ts"
import { MastraCompositeStore } from '@mastra/core/storage'
import { ClickhouseStore } from '@mastra/clickhouse'
import { PostgresStore } from '@mastra/pg'
import { Mastra } from '@mastra/core'

const pgStore = new PostgresStore({
  id: 'pg-storage',
  connectionString: process.env.DATABASE_URL,
})

const clickhouseStore = new ClickhouseStore({
  id: 'clickhouse-storage',
  url: process.env.CLICKHOUSE_URL,
  username: process.env.CLICKHOUSE_USERNAME,
  password: process.env.CLICKHOUSE_PASSWORD,
})

export const mastra = new Mastra({
  storage: new MastraCompositeStore({
    id: 'composite',
    default: pgStore,
    domains: { observability: clickhouseStore.stores?.observability },
  }),
})

process.on('SIGTERM', async () => {
  await mastra.shutdown()
  await clickhouseStore.close()
})
```

## 使用情境 {/* #use-cases */}

### 依工作負載使用不同資料庫 {/* #separate-databases-for-different-workloads */}

開發時使用本機資料庫，同時將正式環境資料保存在代管服務中：

```typescript
import { MastraCompositeStore } from '@mastra/core/storage'
import { MemoryPG, WorkflowsPG, ScoresPG } from '@mastra/pg'
import { MemoryLibSQL } from '@mastra/libsql'

const storage = new MastraCompositeStore({
  id: 'composite',
  domains: {
    // Use local SQLite for development, PostgreSQL for production
    memory:
      process.env.NODE_ENV === 'development'
        ? new MemoryLibSQL({ url: 'file:./dev.db' })
        : new MemoryPG({ connectionString: process.env.DATABASE_URL }),
    workflows: new WorkflowsPG({ connectionString: process.env.DATABASE_URL }),
    scores: new ScoresPG({ connectionString: process.env.DATABASE_URL }),
  },
})
```

### 為可觀測性使用專用儲存 {/* #specialized-storage-for-observability */}

正式環境的可觀測性資料可能很快就超出通用資料庫的負荷。單次 Agent 互動可產生數百個 Span；高流量應用程式每天可產生數千個 Trace。

**[ClickHouse](/integrations/databases/clickhouse)** 針對大量資料與高寫入量的分析工作負載最佳化，因此建議用於正式環境的可觀測性資料。使用複合儲存將可觀測性資料導向 ClickHouse，同時將其他資料保留在主要資料庫：

```typescript
import { MastraCompositeStore } from '@mastra/core/storage'
import { MemoryPG, WorkflowsPG, ScoresPG } from '@mastra/pg'
import { ObservabilityStorageClickhouseVNext } from '@mastra/clickhouse'

const storage = new MastraCompositeStore({
  id: 'composite',
  domains: {
    memory: new MemoryPG({ connectionString: process.env.DATABASE_URL }),
    workflows: new WorkflowsPG({ connectionString: process.env.DATABASE_URL }),
    scores: new ScoresPG({ connectionString: process.env.DATABASE_URL }),
    observability: new ObservabilityStorageClickhouseVNext({
      url: process.env.CLICKHOUSE_URL,
      username: process.env.CLICKHOUSE_USERNAME,
      password: process.env.CLICKHOUSE_PASSWORD,
    }),
  },
})
```

:::note

`ObservabilityStorageClickhouseVNext` 是目前的可觀測性領域實作。舊版 `ObservabilityStorageClickhouse` 類別也仍有匯出，並繼續支援尚未遷移的專案。詳情請參閱 [ClickHouse 儲存參考](/integrations/databases/clickhouse)。

:::

### 為多複本叢集設定 ClickHouse 複寫 {/* #replicated-clickhouse-for-multi-replica-clusters */}

對於自行管理且有多個複本的 ClickHouse 叢集，設定 `replication` 後，Mastra 會使用 `ReplicatedMergeTree` 引擎，並在 DDL 中套用 `ON CLUSTER`：

```typescript
import { MastraCompositeStore } from '@mastra/core/storage'
import { MemoryPG, WorkflowsPG, ScoresPG } from '@mastra/pg'
import { ObservabilityStorageClickhouseVNext } from '@mastra/clickhouse'

const storage = new MastraCompositeStore({
  id: 'composite',
  domains: {
    memory: new MemoryPG({ connectionString: process.env.DATABASE_URL }),
    workflows: new WorkflowsPG({ connectionString: process.env.DATABASE_URL }),
    scores: new ScoresPG({ connectionString: process.env.DATABASE_URL }),
    observability: new ObservabilityStorageClickhouseVNext({
      url: process.env.CLICKHOUSE_URL,
      username: process.env.CLICKHOUSE_USERNAME,
      password: process.env.CLICKHOUSE_PASSWORD,
      replication: {
        cluster: 'production_cluster',
        // Optional (defaults shown):
        // zookeeperPath: '/clickhouse/tables/{shard}/{database}/{table}',
        // replicaName: '{replica}',
      },
    }),
  },
})
```

請勿在 ClickHouse Cloud 設定 `replication`。Cloud 會在伺服器端將 `MergeTree` 改寫為 `SharedMergeTree`。完整設定格式與維運說明請參閱 [ClickHouse 儲存參考](/integrations/databases/clickhouse)。

:::note

使用不支援可觀測性的儲存 Provider（例如 Convex、DynamoDB 或 Cloudflare）時，也需要採用此方式。完整的支援清單請參閱 [MastraStorageExporter 文件](/docs/observability/integrations/exporters/mastra-storage#storage-provider-support)。

:::
