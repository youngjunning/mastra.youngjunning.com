# 元資料過濾器

Mastra 基於 MongoDB/Sift 查詢語法，在所有向量儲存中提供統一的元資料過濾語法。每個向量儲存將這些過濾器轉換為其本機查詢格式。例如，PgVector 使用 PostgreSQL JSONB 謂詞，而 OracleDB 將元資料儲存為 Oracle JSON 並將過濾器編譯為`JSON_VALUE`, `JSON_EXISTS`, `REGEXP_LIKE`， 和`LIKE`具有綁定值的謂詞。

## 基本範例 {/* #basic-example */}

```typescript
import { PgVector } from '@mastra/pg'

const store = new PgVector({
  id: 'pg-vector',
  connectionString,
})

const results = await store.query({
  indexName: 'my_index',
  queryVector: queryVector,
  topK: 10,
  filter: {
    category: 'electronics', // Simple equality
    price: { $gt: 100 }, // Numeric comparison
    tags: { $in: ['sale', 'new'] }, // Array membership
  },
})
```

## 共同規則和限制 {/* #common-rules-and-restrictions */}

1. 欄位名稱不能：
   * 包含點 (.)，除非引用嵌套字段
   * 以 $ 開頭或包含空字符
   * 為空字串

2. 值必須是：
   * 有效的 JSON 類型（字串、數字、布林值、物件、陣列）
   * 並非未定義
   * 為運算子正確鍵入（例如，用於數字比較的數字）

3. 邏輯運算符：
   * 必須包含有效條件
   * 不能為空
   * 必須正確嵌套
   * 只能在頂層使用或嵌套在其他邏輯運算符中
   * 不能在字段層級使用或嵌套在字段內
   * 不能在運算子內部使用
   * 有效的：`{ "$and": [{ "field": { "$gt": 100 } }] }`
   * 有效的：`{ "$or": [{ "$and": [{ "field": { "$gt": 100 } }] }] }`
   * 無效的：`{ "field": { "$and": [{ "$gt": 100 }] } }`
   * 無效的：`{ "field": { "$gt": { "$and": [{...}] } } }`

4. $非運算子：
   * 必須是一個對象
   * 不能為空
   * 可用於字段級別或頂級
   * 有效的：`{ "$not": { "field": "value" } }`
   * 有效的：`{ "field": { "$not": { "$eq": "value" } } }`

5. 運算符嵌套：
   * 邏輯運算子必須包含欄位條件，而不是直接運算符
   * 有效的：`{ "$and": [{ "field": { "$gt": 100 } }] }`
   * 無效的：`{ "$and": [{ "$gt": 100 }] }`

## 商店特定註釋 {/* #store-specific-notes */}

### 阿斯特拉 {/* #astra */}

* 使用點表示法支援嵌套字段查詢
* 數組字段必須在元資料中明確定義為數組
* 元資料值區分大小寫

### 色度資料庫 {/* #chromadb */}

* 其中過濾器僅傳回元資料中存在過濾欄位的結果
* 空元資料欄位不包含在篩選結果中
* 否定匹配必須存在元資料欄位（例如，$ne 不會匹配缺少該欄位的文件）

### Cloudflare 向量化 {/* #cloudflare-vectorize */}

* 在使用過濾之前需要明確元資料索引
* 使用`createMetadataIndex()` to index fields you want to filter on
* 每個 Vectorize 索引最多 10 個元資料索引
* 字串值的索引最多為前 64 個位元組（在 UTF-8 邊界上截斷）
* 數值使用 float64 精度
* 過濾器 JSON 必須小於 2048 位元組
* 欄位名稱不能包含點 (.) 或以 $ 開頭
* 字段名稱限制為 512 個字符
* 建立新的元資料索引以包含在過濾結果中後，必須重新插入向量
* 對於非常大的資料集（~10M+向量），範圍查詢可能會降低準確性

### 函式庫SQL {/* #libsql */}

* 支援使用點表示法的巢狀物件查詢
* 驗證數組欄位以確保它們包含有效的 JSON 數組
*
* 條件中的空數組得到妥善處理
* 元資料儲存在 JSONB 列中，以便有效率地查詢

### 甲骨文資料庫 {/* #oracledb */}

* 元資料以 Oracle JSON 形式與每個元資料一起儲存`VECTOR` row
* 標量比較使用`JSON_VALUE`, while array, existence, and element-match checks use `JSON_EXISTS`
* `$regex`使用Oracle`REGEXP_LIKE`; string `$contains` uses case-insensitive `LIKE`
* 巢狀欄位支援點表示法，並轉換為引號的 Oracle JSON 路徑
* 使用者提供的元資料值作為參數綁定，而不是插入到 SQL 中

### 向量 {/* #pgvector */}

* 完全支援 PostgreSQL 原生 JSON 查詢功能
* 使用本機數組函數有效處理數組操作
* 對數字、字串和布林值進行正確的類型處理
*
* 元資料儲存在 JSONB 列中以實現高效索引

### 松果 {/* #pinecone */}

* 元資料欄位名稱限制為 512 個字符
* 數值必須在 ±1e38 範圍內
*
* 嵌套物件用點表示法展平
* 元資料更新取代整個元資料對象

### 奎德蘭特 {/* #qdrant */}

* 支援使用嵌套條件的進階過濾
* 有效負載（元資料）欄位必須明確索引以進行過濾
* 使用`createPayloadIndex()` to index fields you want to filter on:

```typescript
// Index a field before filtering on it
await store.createPayloadIndex({
  indexName: 'my_index',
  fieldName: 'source',
  fieldSchema: 'keyword', // 'keyword' | 'integer' | 'float' | 'geo' | 'text' | 'bool' | 'datetime' | 'uuid'
})

// Now filtering works
const results = await store.query({
  indexName: 'my_index',
  queryVector: queryVector,
  filter: { source: 'document-a' },
})
```

* 有效率地處理地理空間查詢
* 對 null 值和空值的特殊處理
* 特定於向量的過濾功能
* 日期時間值必須採用 RFC 3339 格式
* `$regex`被轉換為 Qdrant 的全文匹配，它匹配整個標記而不是任意正則表達式或子字串（例如`{ name: { $regex: "item" } }` doesn't match `"item1"`). On unindexed payload fields, Qdrant versions before v1.19.1 fall back to substring matching

### 烏普斯塔什 {/* #upstash */}

* 元資料欄位鍵的 512 個字元限制
* 查詢大小有限（避免使用大型 IN 子句）
* 過濾器中不支援 null/未定義值
* 在內部轉換為類似 SQL 的語法
* 區分大小寫的字串比較
* 元資料更新是原子的

### MongoDB {/* #mongodb */}

* 需要 MongoDB Atlas 或啟用 MongoDB 向量搜尋的部署。商店查詢`$vectorSearch` aggregation stage.
*
* 支援上表中的比較、陣列、邏輯和元素運算符，以及`$regex` and `$size`. `$size` takes an integer, as in `{ tags: { $size: 3 } }`.
* 使用`filter` to match fields in the metadata object and `documentFilter` to match the original document text. You can combine them in a single query.
* 聲明您過濾的元資料字段`filterFields` when you create the index. Mastra passes filters that use only declared fields and the operators MongoDB Vector Search accepts (`$and`, `$or`, `$eq`, `$ne`, `$gt`, `$gte`, `$lt`, `$lte`, `$in`, `$nin`) directly to `$vectorSearch`:

```typescript
await store.createIndex({
  indexName: 'my_index',
  dimension: 1536,
  filterFields: ['category', 'price'],
})
```

* 引用未聲明欄位或使用其他運算子的篩選器採用後備路徑：Mastra 預先過濾集合並將符合的文件 ID 傳遞給`$vectorSearch`. This works only while the ID set fits within MongoDB's 16 MB BSON document limit. On large collections the query fails once that limit is exceeded, so declare your filter fields for selective queries over large data sets.

### 沙發底座 {/* #couchbase */}

* 目前不支援元數據過濾器。檢索結果後必須在客戶端進行過濾，或直接使用 Couchbase SDK 的搜尋功能進行更複雜的查詢。

### 亞馬遜 S3 矢量圖 {/* #amazon-s3-vectors */}

* 相等值必須是原語（字串/數字/布林值）。`null`/`undefined`, arrays, objects, and Date aren't allowed for equality. Range operators accept numbers or Date (Dates are normalized to epoch ms).
* `$in`/`$nin` require **non-empty arrays of primitives**. Date elements are allowed and normalized to epoch ms. **Array equality** isn't supported.
* 隱式 AND 被規範化 (`{a:1,b:2}` → `{$and:[{a:1},{b:2}]`). Logical operators must contain field conditions and use non-empty arrays. They may appear only at the root or within other logical operators (not inside field values).
* 列出的鍵`nonFilterableMetadataKeys` at index creation are stored but not filterable. This setting is immutable.
* $exists 需要一個布林值。
* 未定義/空/空過濾器被視為無過濾器。
* 每個元資料鍵名稱不得超過 63 個字元。
* 每個向量的總元資料：最多 40 KB（可過濾 + 不可過濾）
* 每個向量的元資料金鑰總數：最多 10 個
* 每個向量的可過濾元資料：最多 2 KB
* 每個向量索引的不可過濾元資料鍵：最多 10 個
