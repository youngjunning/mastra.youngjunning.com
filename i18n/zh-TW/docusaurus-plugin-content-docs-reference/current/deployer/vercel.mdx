# Vercel部署器

這`VercelDeployer`捆綁您的 Mastra 伺服器並產生符合 Vercel 的輸出[建構輸出 API](https://vercel.com/docs/build-output-api/v3)。 Vercel 將此輸出直接部署為無伺服器函數。

## 安裝 {/* #installation */}

使用`VercelDeployer`, install the `@mastra/deployer-vercel` package:

```bash npm2yarn
npm install @mastra/deployer-vercel@latest
```

## 使用範例 {/* #usage-example */}

進口`VercelDeployer` and set it as the deployer in your Mastra configuration:

```typescript title="src/mastra/index.ts"
import { Mastra } from '@mastra/core'
// highlight-next-line
import { VercelDeployer } from '@mastra/deployer-vercel'

export const mastra = new Mastra({
  // highlight-next-line
  deployer: new VercelDeployer(),
})
```

## 建構函數選項 {/* #constructor-options */}

部署者接受以下選項：

* `studio?: boolean`： 部署[Studio](/docs/studio/overview) alongside your API as static assets served from Vercel's Edge CDN. Defaults to `false`.
* `maxDuration?: number`：函數執行超時（以秒為單位）。這僅設定了 Vercel 的限制； Mastra自己的請求逾時是單獨配置的，參見[Request timeouts](#request-timeouts).
* `memory?: number`：函數記憶體（以MB為單位）
* `regions?: string[]`：部署該功能的區域（例如`['sfo1','iad1']`)

這`maxDuration`, `memory`, and `regions` options are merged into `.vercel/output/functions/index.func/.vc-config.json` while preserving default fields (`handler`, `launcherType`, `runtime`, `shouldAddHelpers`).

### 具有覆蓋的範例 {/* #example-with-overrides */}

```typescript title="src/mastra/index.ts"
import { Mastra } from '@mastra/core'
import { VercelDeployer } from '@mastra/deployer-vercel'

export const mastra = new Mastra({
  deployer: new VercelDeployer({
    studio: true,
    maxDuration: 600,
    memory: 1536,
    regions: ['sfo1', 'iad1'],
  }),
})
```

## 請求超時 {/* #request-timeouts */}

Vercel 的函數執行時間和 Mastra 的請求逾時是分開強制執行的：

* **Vercel函數執行時間**：由部署者設定`maxDuration` option, in seconds.
* **Mastra 請求逾時**: 設定為`server.timeout` in your `Mastra` config, in milliseconds. When unset it defaults to `180000` (180 seconds), and requests that exceed it are answered with `504 Gateway Timeout`.

`maxDuration`沒有改變`server.timeout`. A request that takes longer than 180 seconds fails even if `maxDuration` is higher, so raise both when you run long requests such as workflow runs or streaming agents:

```typescript title="src/mastra/index.ts"
import { Mastra } from '@mastra/core'
import { VercelDeployer } from '@mastra/deployer-vercel'

export const mastra = new Mastra({
  deployer: new VercelDeployer({
    maxDuration: 600, // seconds
  }),
  server: {
    timeout: 600_000, // milliseconds, keep at or below maxDuration
  },
})
```

## 建構輸出 {/* #build-output */}

運行後`mastra build`, the deployer generates a `.vercel/output` directory conforming to Vercel's [Build Output API (v3)](https://vercel.com/docs/build-output-api/v3). This directory contains routing configuration and serverless function bundles that Vercel deploys directly, bypassing framework detection.

輸出包含：

* **配置.json**：將請求定向到適當處理程序的路由配置
* **功能/**：您的 Mastra 伺服器捆綁為無伺服器功能
* **靜止的/**：Studio SPA 資產（僅當`studio: true`)

無工作室：

```bash
.vercel/
└── output/
    ├── config.json
    └── functions/
        └── index.func/
            ├── .vc-config.json
            ├── index.mjs
            └── node_modules/
```

和`studio: true`:

```bash
.vercel/
└── output/
    ├── config.json
    ├── static/
    │   ├── index.html
    │   └── assets/
    │       ├── *.js
    │       └── *.css
    └── functions/
        └── index.func/
            ├── .vc-config.json
            ├── index.mjs
            └── node_modules/
```

啟用 studio 後，將配置路由，以便`/` and the Studio routes listed in the Studio build's route manifest are served from `index.html` for client-side routing, and static assets (JS, CSS) are served from Vercel's Edge CDN with no function invocations. All other paths, including `/api/*` and custom routes registered with `registerApiRoute()`, are handled by the serverless function. Custom routes that fall under a Studio route (for example, `/agents/custom`) are served from `index.html` instead, so register custom routes outside Studio's route roots.

該資料夾是在建置期間產生的，不應提交給版本控制。
