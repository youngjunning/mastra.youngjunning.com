# Classifier

`Classifier` 使用決策模型，針對共用狀態回答一個或多個答案範圍固定的問題。若應用程式需要具型別的選項、數值分數或布林機率，卻不想解析生成文字，可使用它。

Classifier 只傳回評估結果。應用程式自行決定如何使用，例如選擇路由，或將機率與安全門檻比較。

`Classifier` 需要決策模型（`DecisionModelV4`，或已淘汰的 `EvaluationModelV4`；也可包裝在 `MastraDecisionModel` 中）。它不接受 `'provider/model'` 字串、單獨的模型 ID 或語言模型。

## 基本用法 {/* #basic-usage */}

此範例使用 [TypeSafe AI Provider](https://ai-sdk.dev/providers/ai-sdk-providers/typesafe-ai)。請確認已設定 `TYPESAFE_AI_API_KEY` 環境變數。若使用其他 Provider，請參閱[決策模型](#decision-models)。

安裝 Provider 套件：

```bash npm2yarn
npm install @ai-sdk/typesafe-ai
```

當每次評估都使用相同的問題集時，在建構函數中定義問題。保留問題物件字面量，以便 TypeScript 可以推斷答案鍵和選擇值。

```typescript
import { Classifier } from '@mastra/core/classifier'
import { typeSafeAi } from '@ai-sdk/typesafe-ai'

const classifier = new Classifier({
  id: 'request-classifier',
  model: typeSafeAi.decisionModel('__AI_SDK_TYPESAFE_DECISION_MODEL__'),
  questions: {
    route: {
      type: 'choice',
      instructions: 'Choose the team that should handle this request.',
      criteria: {
        billing: 'Questions about invoices, charges, or refunds',
        support: 'Questions about using or troubleshooting the product',
      },
    },
    urgent: {
      type: 'boolean',
      instructions: 'Does this request require an immediate response?',
    },
  },
})

const result = await classifier.decide({
  state: {
    subject: 'Duplicate charge',
    message: 'I was charged twice for the same subscription.',
  },
})

result.answers.route.choice // 'billing' | 'support' | undefined
result.answers.urgent.probability // P(true), from 0 to 1, or undefined
```

只有決策模型拒絕回答某個問題時，該欄位才會是 `undefined`。請參閱[遭拒絕的問題](#refused-questions)。

決策模型會在相同的 `state` 下接收所有問題。若某個問題省略 `instructions`，就會改用該問題的名稱。

## 決策模型 {/* #decision-models */}

本頁範例依照 AI SDK 文件中的 [TypeSafe AI Provider 設定](https://ai-sdk.dev/providers/ai-sdk-providers/typesafe-ai#setup)。其他 AI SDK Provider（包括 OpenAI、Anthropic 與 Google）也提供 `decisionModel()` 工廠；先前的 `evaluationModel()` 仍以已淘汰別名保留。Mastra 會呼叫 `doDecide()`；對較舊的 Provider，則改呼叫 `doEvaluate()`。完整清單、支援的模型 ID 及各 Provider 回答問題的方式，請參閱 [Provider 模型](https://ai-sdk.dev/docs/ai-sdk-core/decisions#provider-models)。

每個 Provider 都會匯出可直接使用的執行個體，本頁範例使用的就是這些執行個體。其他 Provider 請參閱 [AI SDK Provider](https://ai-sdk.dev/providers/ai-sdk-providers)。

透過調用工廠來明確傳遞密鑰：

```typescript
import { createTypeSafeAi } from '@ai-sdk/typesafe-ai'

const model = createTypeSafeAi({ apiKey: process.env.TYPESAFE_AI_API_KEY }).decisionModel(
  '__AI_SDK_TYPESAFE_DECISION_MODEL__',
)
```

## 問題類型 {/* #question-types */}

問題名稱會成為 `result.answers` 中的鍵。每個問題都可有一個包含相容於 JSON 值的選填 `instructions` 欄位。評判標準的值也可以是相容於 JSON 的資料，不限於字串。

### 選擇題 {/* #choice-questions */}

選擇題會從非空的 `criteria` 物件中選出一個鍵。

```typescript
const questions = {
  sentiment: {
    type: 'choice',
    instructions: 'Classify the customer sentiment.',
    criteria: {
      positive: 'The customer is satisfied or complimentary.',
      neutral: 'The customer has no clear positive or negative sentiment.',
      negative: 'The customer is dissatisfied or frustrated.',
    },
  },
} as const
```

答案包含選出的 `choice`。若 Provider 傳回 `probabilities`，該物件必須包含每個選項的鍵，且在 Provider 宣告的捨入精度範圍內，總和應為 `1`。

```typescript
const answer = {
  type: 'choice',
  choice: 'negative',
  probabilities: {
    positive: 0.05,
    neutral: 0.15,
    negative: 0.8,
  },
}
```

### 分數問題 {/* #score-questions */}

評分題使用至少有兩個等級的有序陣列。陣列索引定義分數範圍。若有三個標準，有效分數可從 `0` 到 `2`，包含小數。

```typescript
const questions = {
  quality: {
    type: 'score',
    instructions: 'Score the response quality.',
    criteria: ['Incorrect or unhelpful', 'Partially correct', 'Correct and complete'],
  },
} as const
```

Provider可以傳回每個等級的分數和可選機率：

```typescript
const answer = {
  type: 'score',
  score: 1.7,
  probabilities: {
    '0': 0.05,
    '1': 0.2,
    '2': 0.75,
  },
}
```

### 布爾問題 {/* #boolean-questions */}

布林題會傳回答案為 `true` 的估計機率。該值一律介於 `0` 與 `1` 之間，不代表「較可能的結果」的信賴程度。

```typescript
const questions = {
  unsafe: {
    type: 'boolean',
    instructions: 'Does the message contain unsafe content?',
    criteria: {
      true: 'The message contains unsafe content.',
      false: 'The message is safe.',
    },
  },
} as const
```

布林題的 `criteria` 欄位為選填。提供此欄位時，其中 `true` 與 `false` 的描述也可省略。

```typescript
const answer = {
  type: 'boolean',
  probability: 0.92,
}
```

### 拒答問題 {/* #refused-questions */}

決策模型可以拒絕回答任何問題，例如安全原則不允許回答時。遭拒絕的問題會傳回 `RefusalAnswer`，而不是選項、分數或布林答案。同一次呼叫中的其他問題仍會傳回各自的答案。

```typescript
const answer = {
  type: 'refusal',
}
```

遭拒絕的答案沒有 `choice`、`score` 或 `probability`。因此，`answers.route.choice === 'billing'` 這類相等性檢查會得到 `false`。讀取數值欄位前，請先檢查 `type`，並決定應用程式如何處理拒絕回答：

```typescript
const urgent = result.answers.urgent

if (urgent.type === 'refusal') {
  // Route to a human, block the input, or apply a default.
} else if (urgent.probability > 0.8) {
  // Escalate.
}
```

## 設計問題 {/* #designing-questions */}

以下原則有助於確保問題能根據狀態回答：

- 每個問題只要求一個判斷。如果任兩個欄位的變更都可能改變同一答案，就無法據此穩定地決定路由。
- 讓評判標準彼此互斥。`strong: 'A good fit'` 與 `partial: 'Maybe a fit'` 會讓機率分散在兩者之間。
- 為分數提供足夠的等級，以表示中間值。
- 若清單未涵蓋所有情況，加入其他選項。沒有 `other` 等級時，Classifier 必須將每筆輸入歸入列出的某個團隊。
- 將欄位放在 `state` 中，而不是 `instructions` 中。如此只變更一個欄位時，也只會改變一個答案。

若要檢查問題設計，可變更狀態中的一個欄位，確認只有一個答案改變。

### 每次呼叫時提供問題 {/* #per-call-questions */}

若每次評估的問題集不同，請在建構函式省略 `questions`。答案型別會依該次呼叫提供的問題推斷。

```typescript
import { Classifier } from '@mastra/core/classifier'
import { typeSafeAi } from '@ai-sdk/typesafe-ai'

const classifier = new Classifier({
  id: 'dynamic-classifier',
  model: typeSafeAi.decisionModel('__AI_SDK_TYPESAFE_DECISION_MODEL__'),
})

const result = await classifier.decide({
  state: { response: 'Your refund has been processed.' },
  questions: {
    tone: {
      type: 'choice',
      criteria: {
        empathetic: 'Acknowledges the customer and responds with care',
        neutral: 'States the outcome without emotional language',
      },
    },
  },
})

result.answers.tone.choice // 'empathetic' | 'neutral' | undefined
```

## 驗證和錯誤 {/* #validation-and-errors */}

`Classifier` 會在呼叫 Provider 前驗證輸入，並在傳回 Provider 輸出前驗證輸出。

輸入驗證包括：

- `id` 必須是非空字串。
- `state`、instructions 與 criteria 必須相容於 JSON。
- 問題物件與選擇題標準不可為空。
- 評分標準必須包含至少兩個已定義的等級。
- 決策模型必須支援每種問題類型。
- `maxRetries` 必須是非負整數。

Provider 回應必須為每個問題恰好包含一個答案。每個答案必須符合問題類型，或明確表示拒答。Classifier 還會拒絕無效選項、超出範圍的分數或機率、不完整的機率分布、非有限數值的 Token 用量、格式錯誤的警告，以及無效的回應時間戳記。

只有可重試的 AI SDK `APICallError` 錯誤才會重試，預設重試兩次。可透過 `maxRetries` 修改次數。其他錯誤會立即讓呼叫失敗。若所有重試都失敗，`decide()` 會重新擲出最後一次 Provider 錯誤。傳入的中止訊號觸發時，呼叫會以該訊號的中止原因遭到拒絕，即使取消發生在重試退避期間也是如此。

## 可觀測性 {/* #observability */}

若有運作中的 Mastra Span，`decide()` 會建立一個 `CLASSIFIER_EVALUATION` 子 Span。Span 輸入包含評估的 `state` 與問題，輸出包含答案及機率。Span 屬性會記錄 Classifier 與模型識別碼、Provider、問題數量與類型、嘗試次數、耗時及 Token 用量。Token 用量也會產生 [Token 與成本指標](/reference/observability/metrics/automatic-metrics#token-usage-metrics)。

若不想在匯出的 Trace 中包含狀態與答案，請設定 `hideInput` 與 `hideOutput`；這兩個選項位於呼叫 Classifier 的 Agent 或 Workflow 執行之 `tracingOptions` 中。請參閱[隱藏敏感輸入與輸出](/docs/observability/tracing/overview#hiding-sensitive-inputoutput)。

在 [Studio](/docs/studio/overview) 中依 Classifier 實體類型篩選 Trace，可單獨查看 Classifier 呼叫。Workflow 中的 Classifier 步驟會在流程圖中顯示為 Classifier 節點。

## 自訂 Provider 回應 {/* #customize-provider-responses */}

`Classifier` 會自動以 `MastraDecisionModel` 包裝原始 AI SDK 決策模型。若 Provider 輸出需要在驗證前正規化，可傳入自己的包裝器。

```typescript
import { Classifier, MastraDecisionModel, type DecisionModelResult } from '@mastra/core/classifier'
import { typeSafeAi } from '@ai-sdk/typesafe-ai'

class NormalizedDecisionModel extends MastraDecisionModel {
  protected override transformResult(result: DecisionModelResult): DecisionModelResult {
    return {
      ...result,
      answers: normalizeAnswers(result.answers),
    }
  }
}

const classifier = new Classifier({
  id: 'normalized-classifier',
  model: new NormalizedDecisionModel(
    typeSafeAi.decisionModel('__AI_SDK_TYPESAFE_DECISION_MODEL__'),
  ),
})
```

`transformResult()` 會在 Provider 呼叫之後、`Classifier` 驗證回應之前執行。

`MastraEvaluationModel` 與 `EvaluationModelResult` 分別是 `MastraDecisionModel` 與 `DecisionModelResult` 已淘汰的別名，將於未來版本移除。

## 註冊分類器 {/* #registering-classifiers */}

在 `Mastra` 執行個體上註冊 Classifier，可供整個應用程式共用，並透過鍵或 ID 取得。若評估已註冊的 Classifier 時沒有運作中的 Trace，它會啟動根 `CLASSIFIER_EVALUATION` Span，並使用 `Mastra` 執行個體設定的可觀測性 Provider。

```typescript title="src/mastra/index.ts"
import { Mastra } from '@mastra/core'
import { Classifier } from '@mastra/core/classifier'
import { typeSafeAi } from '@ai-sdk/typesafe-ai'

export const safety = new Classifier({
  id: 'safety',
  model: typeSafeAi.decisionModel('__AI_SDK_TYPESAFE_DECISION_MODEL__'),
  questions: {
    unsafe: { type: 'boolean' },
  },
})

export const mastra = new Mastra({
  classifiers: { safety },
})

mastra.getClassifier('safety')
mastra.getClassifierById('safety')
mastra.listClassifiers()
```

## 在 Workflow 中使用 Classifier {/* #using-classifiers-in-workflows */}

建構函式中已設定問題的 Classifier，可以透過 [`createStep(classifier)`](/reference/workflows/step) 或 [`.classifier()`](/reference/workflows/workflow-methods/classifier) 加入 Workflow。Workflow 輸出包含完整的具型別 `answers` 與正規化的 `usage`。

```typescript
import { safety } from '../index'

const workflow = createWorkflow({
  id: 'ticket-triage',
  inputSchema: z.object({ message: z.string() }),
  outputSchema: z.any(),
})
  .map({ message: { initData: true, path: 'message' } })
  .classifier<typeof safety.questions>('safety')
  .commit()
```

字串參照會在執行階段透過 `Mastra` 執行個體解析。ID 不包含問題型別，因此請透過型別參數提供，以維持答案的型別資訊。在 Studio 中，Workflow 流程圖會將此步驟顯示為 Classifier 節點。

Workflow Adapter 不會在步驟輸出中包含警告、原始 Provider 回應、標頭或 Provider 中繼資料。若需要這些 Provider 層級的細節，請直接呼叫 `decide()`，或查看 Classifier 的可觀測性資料。
