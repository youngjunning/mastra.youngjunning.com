# ModelSelectionProcessor

`ModelSelectionProcessor` 會對傳入請求分類一次，再覆寫本次執行使用的模型。它適用於成本路由：將能力較強的模型設為 Agent 的預設模型；只有決策模型確信低成本模型能處理請求時，處理器才改用低成本模型。

:::warning
路由可能增加成本，而非節省成本。不同模型之間不共用 Provider 的提示快取。每次切換模型都要再次按原價處理對話，低成本模型也可能需要更多步驟才能完成任務。啟用前，請用自己的請求資料衡量成本與品質。請參閱[成本權衡](#cost-tradeoffs)。
:::

請為每個模型說明適合處理的請求類型。處理器會為你建立 [Classifier](/reference/classifier/classifier)。處理器本身的 `model` 選項接受決策模型（`DecisionModelV4 | EvaluationModelV4 | MastraDecisionModel`），型別與 `Classifier` 接受的相同。此選項不支援 `'provider/model'` 字串。Provider 的設定方式請參閱[決策模型](/reference/classifier/classifier#decision-models)：

```typescript title="src/mastra/agents/support-agent.ts"
import { Agent } from '@mastra/core/agent'
import { ModelSelectionProcessor } from '@mastra/core/processors'
import { typeSafeAi } from '@ai-sdk/typesafe-ai'

export const agent = new Agent({
  name: 'support-agent',
  instructions: 'Answer the user concisely.',
  model: '__GATEWAY_OPENAI_MODEL__',
  inputProcessors: [
    new ModelSelectionProcessor({
      model: typeSafeAi.decisionModel('__AI_SDK_TYPESAFE_DECISION_MODEL__'),
      choices: [
        {
          model: '__GATEWAY_OPENAI_MODEL_LUNA__',
          criteria:
            'Answerable in one or two sentences from general knowledge, with no reasoning steps',
        },
        {
          model: '__GATEWAY_OPENAI_MODEL__',
          criteria:
            'Requires multi-step reasoning, planning, weighing trade-offs, or careful judgment',
        },
      ],
    }),
  ],
})
```

每個選項指定一個模型，以及適合交由該模型處理的請求。分類器會依這些描述判斷每個請求，並交給選中的模型處理。

預設情況下，這項決策適用於執行中的每一步。設定 `scope: 'first-step'` 可只路由第一次模型呼叫，後續步驟則使用 Agent 設定的模型。若任務比第一則訊息看起來更難，後續步驟便能擺脫首次決策；但如[路由範圍](#routing-scope)所述，這樣節省的成本也少得多。

## 決策回調 {/* #decision-callback */}

`onDecision` 每個請求觸發一次，即使處理器沒有選擇模型也是如此。可用它記錄實際處理請求的模型，以及選擇的信心分數：

```typescript
import { ModelSelectionProcessor } from '@mastra/core/processors'
import { typeSafeAi } from '@ai-sdk/typesafe-ai'
import { PinoLogger } from '@mastra/loggers'

const logger = new PinoLogger({ name: 'model-selection' })

new ModelSelectionProcessor({
  model: typeSafeAi.decisionModel('__AI_SDK_TYPESAFE_DECISION_MODEL__'),
  choices: [
    { model: '__GATEWAY_OPENAI_MODEL_LUNA__', criteria: 'Simple lookups' },
    { model: '__GATEWAY_OPENAI_MODEL__', criteria: 'Multi-step reasoning' },
  ],
  onDecision: decision => {
    logger.info('model routing', decision)
  },
})
```

決策結果包含實際使用的模型、選中的條件、該選擇的信心分數，以及沒有使用任何模型的原因。使用 `select` 時，結果不包含 `choice` 或 `probability`。沒有文字或發生錯誤時，結果分別包含 `abstained: 'no-text'` 或 `abstained: 'error'`；當 `select` 回傳 `undefined` 時，結果既沒有 `model`，也沒有 `abstained`：

## 現有分類器 {/* #existing-classifiers */}

傳入 `classifier` 而非 `choices`，即可使用自行設定的 [Classifier](/reference/classifier/classifier) 路由。同一個分類器也支援 scorer 或其他處理器時，這種方式特別實用。透過 `select` 將分類結果對應到模型：

```typescript
import { Classifier } from '@mastra/core/classifier'
import { typeSafeAi } from '@ai-sdk/typesafe-ai'

const triage = new Classifier({
  id: 'triage',
  model: typeSafeAi.decisionModel('__AI_SDK_TYPESAFE_DECISION_MODEL__'),
  questions: {
    complexity: {
      type: 'choice',
      criteria: {
        trivial: 'Answerable in one or two sentences with no reasoning steps',
        complex: 'Requires multi-step reasoning or careful judgment',
      },
    },
  },
})

new ModelSelectionProcessor({
  classifier: triage,
  select: ({ complexity }) =>
    complexity.choice === 'trivial' ? '__GATEWAY_OPENAI_MODEL_LUNA__' : undefined,
})
```

回傳 `undefined` 表示不選擇模型，此時使用 Agent 設定的模型。

## 路由範圍 {/* #routing-scope */}

執行中的每一步都會把目前的對話和所有 Tool 結果傳送給模型。因此第一次呼叫通常最便宜，而非最貴；只路由這次呼叫能省下的成本很少。

在四步執行中，第一次呼叫約占輸入 token 的 14%，因此只路由這一步，能取得的節省不到十分之一。這項估算將所有輸入 token 按原價計算。使用提示快取後，後續步驟的大部分輸入會以折扣價讀取快取，所以路由後續步驟的節省也比 token 占比顯示的少。

因此預設使用 `scope: 'run'`。若你更希望較長的執行在後續步驟回到能力較強的模型，而非一直沿用首次決策，可使用 `scope: 'first-step'`；但在多步執行中，這幾乎無法節省成本。

單步執行不受影響，因為只呼叫模型一次時，兩種範圍的行為相同。

## 多維度 {/* #multiple-dimensions */}

各選項的條件互斥，因此不適合根據多個獨立面向路由。此時可提出多個問題，再於 `select` 中組合答案。它接收具備完整型別資訊的答案，路由策略由你的程式碼決定：

```typescript
import { Classifier } from '@mastra/core/classifier'
import { typeSafeAi } from '@ai-sdk/typesafe-ai'
import { ModelSelectionProcessor } from '@mastra/core/processors'

const triage = new Classifier({
  id: 'triage',
  model: typeSafeAi.decisionModel('__AI_SDK_TYPESAFE_DECISION_MODEL__'),
  questions: {
    complexity: {
      type: 'choice',
      criteria: {
        trivial: 'Answerable in one or two sentences with no reasoning steps',
        complex: 'Requires multi-step reasoning or careful judgment',
      },
    },
    sensitive: {
      type: 'boolean',
      criteria: {
        true: 'Involves money, credentials, legal, medical, or safety consequences',
        false: 'Routine request with no sensitive consequences',
      },
    },
  },
})

new ModelSelectionProcessor({
  classifier: triage,
  select: ({ complexity, sensitive }) => {
    // Never downgrade a sensitive request, however simple it looks.
    if (sensitive.probability >= 0.3) return undefined
    return complexity.choice === 'trivial' ? '__GATEWAY_OPENAI_MODEL_LUNA__' : undefined
  },
})
```

## 機率和`minProbability` {/* #probabilities-and-minprobability */}

選項答案包含各條件的機率分布，路由決策的信心分數是實際選中條件的機率。並非所有決策模型都會回傳這項分布。

因此 `minProbability` 沒有預設值。各種設定的行為如下：

* **省略**：直接依選中的選項路由。分類器的答案就是最終決策。
* **設定**：只有機率達到或超過門檻，才使用選中的模型。若模型完全沒有回傳機率分布，處理器會**放棄路由**，因為無法評估的門檻不能視為已達成。

若決策模型不回傳選項的機率分布，設定 `minProbability` 後，處理器會對每個請求放棄路由。可記錄 `onDecision` 檢查：若 `abstained` 為 `below-threshold`，且沒有 `probability`，表示缺少機率分布，而非信心分數太低。

## 失敗行為 {/* #failure-behavior */}

路由採用失敗時放行的策略。若分類器出錯，或分類器 ID 未註冊，處理器會記錄警告並使用 Agent 設定的模型。請求沒有可供分類的使用者文字時，處理器會放棄路由，不記錄日誌，並向 `onDecision` 回報 `abstained: 'no-text'`。使用 `choices` 時，若決策模型拒絕回答路由問題，處理器會放棄路由並回報 `abstained: 'refused'`。使用 `select` 時，回呼會收到拒答結果，由你決定回傳模型或 `undefined`。對於成本最佳化，這樣比較安全：最壞的情況也只是使用原本設定的模型並支付相應費用。

這與[工具核准](/docs/agents/human-in-the-loop)適用的失敗時阻擋策略相反：工具核准遇到不確定情況應向上呈報，而非直接放行。

失敗時放行只適用於路由決策，不適用於選中的模型。若選中的模型失敗，而 Agent 設定了[備援模型](/models#model-fallbacks)，處理器會停止覆寫模型，由下一個已設定模型處理請求。若只設定一個模型，就沒有備援選項，選中模型的錯誤會使執行失敗。

## 成本權衡 {/* #cost-tradeoffs */}

每個請求都會額外呼叫一次分類器，換取部分請求使用低成本模型。是否省錢取決於實際請求資料：

* **提示快取**：Provider 會按模型快取提示前綴，快取輸入的計費價格低於一般價格。模型之間不共用快取。當一次呼叫切換至與上次不同的模型時，該模型必須按原價處理尚未快取的對話；部分 Provider 還會收取快取寫入費用。每個請求都單獨分類，因此同一討論串的連續回合可能交替使用不同模型。對系統提示、檢索內容或歷史記錄較長的 Agent 而言，一次切換的額外費用可能超過低成本模型節省的費用。
* **低成本模型的額外工作**：低成本模型可能犯更多錯誤、執行更多步驟，或呼叫更多 Tool 才能完成相同任務。若後續呼叫切回能力較強的模型，例如同一討論串的下一個請求，或使用 `scope: 'first-step'` 時的第二步，低成本模型先前執行的每一步，包括 Tool 呼叫與結果，都會以未快取輸入向能力較強的模型計費。

只有在實際請求中，不同模型的表現確實有差異，路由才有價值。若低成本模型的回答與能力較強的模型一樣準確，直接將低成本模型設為預設值即可。

啟用路由前，請分別使用及不使用處理器執行一組實際請求樣本，比較每項已完成任務的總成本，而非每個 token 的價格。納入快取讀寫、分類器呼叫、額外步驟與後續請求，並檢查被降級請求的回答品質。[Token 使用量指標](/reference/observability/metrics/automatic-metrics#token-usage-metrics)會回報每次模型呼叫的快取讀寫 token 數。

## 行為說明 {/* #behavior-notes */}

* 分類器在 `processInput` 中**每個請求只執行一次**，並非每步執行一次。決策保存在該請求的狀態中，供每一步讀取。
* 只對**最新一則使用者訊息**分類。系統提示、檢索內容與先前回合不會傳給分類器，因此上下文增加不會提高路由呼叫的輸入量。像 `"now apply that to the rest"` 這樣簡短的後續訊息，只會依這句話路由。若你的後續請求經常重新提出複雜推理問題，而非沿用先前結果，請保留能力較強的模型作為預設值。
* 只向下切換模型。將能力較強的模型設為 Agent 預設值，由處理器改用低成本模型。錯誤決策會降低該請求的品質。預設的 `scope: 'run'` 會讓錯誤降級影響執行中的每一步；即使任務比首則訊息看起來更難，仍會使用低成本模型。
* 處理器會在每個請求的關鍵路徑上增加一次分類器往返呼叫，包括最後放棄路由的請求。
* 使用 `choices` 時，每個條件以對應模型命名，因此 `onDecision` 會將選中的模型回報為 `choice`。
