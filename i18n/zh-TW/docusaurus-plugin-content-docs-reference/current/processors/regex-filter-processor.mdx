# RegexFilterProcessor

`RegexFilterProcessor` 透過正規表示式比對來篩選、遮蔽或封鎖 Agent 訊息中的內容，不會呼叫 LLM。

它支援常見模式（PII、密鑰、URL）的內建預設，也支援自訂正規表示式規則。可用於輸入、輸出或兩個階段。

## 使用範例 {/* #usage-example */}

封鎖輸入訊息中的 PII：

```typescript
import { RegexFilterProcessor } from '@mastra/core/processors'

const filter = new RegexFilterProcessor({
  presets: ['pii'],
  strategy: 'block',
  phase: 'input',
})
```

遮蔽輸出中的密鑰：

```typescript
import { RegexFilterProcessor } from '@mastra/core/processors'

const filter = new RegexFilterProcessor({
  presets: ['secrets'],
  strategy: 'redact',
  phase: 'output',
})
```

自訂規則：

```typescript
import { RegexFilterProcessor } from '@mastra/core/processors'

const filter = new RegexFilterProcessor({
  rules: [{ name: 'internal-id', pattern: /INTERNAL-\d{6}/g, replacement: '[INTERNAL_ID]' }],
  strategy: 'redact',
})
```

對於相符內容較長的自訂規則，可以加大串流處理時保留的尾端視窗（例如固定長度的密鑰，或
只有在結束分隔符號抵達後才能比對的值）：

```typescript
import { RegexFilterProcessor } from '@mastra/core/processors'

const filter = new RegexFilterProcessor({
  rules: [
    {
      name: 'armored-key',
      pattern: /-----BEGIN KEY-----[A-Z]+-----END KEY-----/g,
      replacement: '[KEY]',
    },
  ],
  strategy: 'redact',
  streamCarryoverSize: 256,
})
```

將處理器掛載至 Agent：

```typescript
import { Agent } from '@mastra/core/agent'
import { RegexFilterProcessor } from '@mastra/core/processors'

const agent = new Agent({
  id: 'my-agent',
  name: 'my-agent',
  model: '__GATEWAY_OPENAI_MODEL_LUNA__',
  inputProcessors: [
    new RegexFilterProcessor({
      presets: ['pii', 'secrets'],
      strategy: 'block',
    }),
  ],
})
```

## 錯誤行為 {/* #error-behavior */}

使用預設的 `block` 策略時，只要有任何模式相符，`RegexFilterProcessor` 就會擲出 `retry: false` 的 `TripWire` 錯誤。TripWire 中繼資料包含：

* `processorId`: `'regex-filter'`
* `matches`：相符物件陣列，欄位包括 `rule`、`match`（已遮蔽為 `'[REDACTED_MATCH]'`）及 `index`
* `strategy`: `'block'`

## 內建預設 {/* #built-in-presets */}

| 預設 | 比對模式 | 預設替換文字 |
| - | - | - |
| `pii` | 電子郵件地址、電話號碼、美國社會安全號碼、信用卡號 | `[EMAIL]`、`[PHONE]`、`[SSN]`、`[CREDIT_CARD]` |
| `secrets` | API 金鑰、Bearer Token、AWS 存取金鑰 | `[API_KEY]`、`[BEARER_TOKEN]`、`[AWS_KEY]` |
| `urls` | HTTP/HTTPS URL | `[URL]` |

## 遮蔽行為 {/* #redaction-behavior */}

每條規則獨立比對，因此兩條規則可能比對同一段文字。例如，沒有分隔符號的卡號可能同時符合 `phone` 和 `credit-card`。重疊的相符範圍會合併為一個區域，並使用最長匹配對應的替換文字取代一次。

```typescript
const filter = new RegexFilterProcessor({
  presets: ['pii'],
  strategy: 'redact',
})

// "Charge 4111111111111111 today" becomes "Charge [CREDIT_CARD] today"
```

對於單獨的相符內容，替換字串可以用 `$1` 或 `$&` 參照擷取群組。多個相符範圍合併為一個區域時，替換字串會原樣插入。規則透過後顧或前瞻比對周圍文字時也是如此；無論哪種情況，整個區域都會被遮蔽。

## 遮蔽報告 {/* #redaction-reporting */}

由於 `redact` 策略會直接改寫文字，下游程式碼無法判斷改變了什麼。可透過 `onViolation` 記錄每則已遮蔽訊息、訊息片段及串流區塊的變更；位移量相對於對應文字計算。非同步回呼會被等待，回呼錯誤則會被攔截，因此稽核接收端無法使用時不會讓請求失敗。

```typescript
import { RegexFilterProcessor, type RegexRedactionDetail } from '@mastra/core/processors'

const filter = new RegexFilterProcessor({
  presets: ['pii'],
  strategy: 'redact',
})

filter.onViolation = async ({ detail }) => {
  const redaction = detail as RegexRedactionDetail

  for (const entry of redaction.redactions) {
    await auditLog.write({
      phase: redaction.phase,
      messageId: redaction.messageId,
      rule: entry.rule,
      offset: entry.index,
      length: entry.length,
    })
  }
}
```

回呼會被等待；在 `processOutputStream` 中，每個包含相符內容的區塊都會觸發回呼。請讓回呼快速完成，或將工作交給佇列，避免緩慢的稽核接收端阻塞串流回應。未設定回呼時，`redact` 路徑仍為同步執行。

`block` 策略也透過同一回呼報告。處理器執行器捕捉 `TripWire` 時才會呼叫，因此這時的 `detail` 包含[錯誤行為](#error-behavior)中說明的 TripWire 中繼資料，而非下列結構。

預設不包含已遮蔽的原文。若稽核記錄複製了原本要保護的資料，就會擴大資料暴露範圍。只有目的地與原始資料受到同等保護時，才應設定 `includeRedactedValues`。基於相同理由，`block` 策略也不會在 `TripWire` 中繼資料中包含相符原文。
