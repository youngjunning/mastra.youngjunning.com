# CyberRefusalHandler

當 Provider 的網路安全防護機制拒絕某個步驟時，`CyberRefusalHandler` 會重試該步驟一次。Agent 長時間執行時，這類防護機制也可能拒絕一般的程式編寫工作。許多此類拒絕屬於誤判，要求模型繼續通常能讓任務繼續進行。如果重試後仍遭拒絕，拒絕結果會保留，並以一般錯誤或停止的形式呈現。

此處理器支援兩個 Provider，兩者回報拒絕的方式不同：

- **OpenAI**：模型呼叫因 `cyber_policy` 錯誤（"This content was flagged for possible cybersecurity risk"）而失敗。無論拒絕以 HTTP 錯誤或串流失敗的形式傳回，處理器都會比對錯誤代碼或訊息。此類拒絕由 `processAPIError` 處理；該方法僅對 `errorProcessors` 中的處理器執行。
- **Anthropic**：步驟結束時，Provider 中繼資料中的結束原因為 `content-filter`，且 `stopDetails.category: 'cyber'`。此類拒絕由 `processOutputStep` 處理；該方法對 `outputProcessors` 中的處理器執行。重試前會回復被拒絕的步驟，包括已產生的部分文字。

## 運作原理 {/* #how-it-works */}

對於 OpenAI 的拒絕：

1. 模型呼叫因 `cyber_policy` 錯誤而失敗
1. `CyberRefusalHandler` 檢查這是否為該步驟的首次重試
1. 傳送 `system-reminder` 訊號，內容為 `continue`
1. 傳回 `{ retry: true }`，然後再次呼叫同一個模型

對於 Anthropic 的拒絕：

1. 步驟因 `cyber` 分類器拒絕而結束
1. `CyberRefusalHandler` 檢查這是否為該步驟的首次重試
1. 呼叫 `abort('continue', { retry: true })`
1. 回復被拒絕的步驟，將 `continue` 作為系統提醒附加後再次呼叫模型

每個步驟最多重試一次。步驟成功後，重試次數會重設，因此同一次執行中，後續步驟若遭拒絕仍可重試一次。

## 使用範例 {/* #usage-example */}

將 `CyberRefusalHandler` 同時加入 `errorProcessors` 和 `outputProcessors`，以處理兩個 Provider 的拒絕：

```typescript title="src/mastra/agents/coding-agent.ts"
import { Agent } from '@mastra/core/agent'
import { CyberRefusalHandler, StreamErrorRetryProcessor } from '@mastra/core/processors'

export const agent = new Agent({
  id: 'coding-agent',
  name: 'Coding Agent',
  instructions: 'You are a coding agent.',
  model: '__GATEWAY_OPENAI_MODEL__',
  errorProcessors: [new CyberRefusalHandler(), new StreamErrorRetryProcessor()],
  outputProcessors: [new CyberRefusalHandler()],
  maxProcessorRetries: 3,
})
```

在 `errorProcessors` 中，將其放在 [`StreamErrorRetryProcessor`](/reference/processors/stream-error-retry-processor) 之前。錯誤處理器遇到第一個傳回 `{ retry: true }` 的處理器便會停止；若先執行一般重試處理器，被拒絕的請求就會原樣重送。

輸出步驟的重試會計入 `maxProcessorRetries`，而且與錯誤處理路徑不同，這裏沒有隱含的預設值。無論 Agent 是否設有 `errorProcessors`，都要明確設定此值，否則 Anthropic 的重試會被視為中止。

[`createCodingAgent()`](/reference/coding-agent/create-coding-agent) 預設會在兩個處理器列表中加入此處理器。
