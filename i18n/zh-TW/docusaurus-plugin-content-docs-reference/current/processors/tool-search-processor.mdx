# Tool搜尋處理器

這`ToolSearchProcessor`是一個**輸入處理器**允許運行時定義的Tool發現和載入。它不是預先向Agent提供所有Tool，而是為Agent提供兩個元Tool（`search_tools`和`load_tool`）讓它按需查找並載入Tool。這減少了使用大型Tool庫時上下文令牌的使用。

## 使用範例 {/* #usage-example */}

```typescript
import { ToolSearchProcessor } from '@mastra/core/processors'

const toolSearch = new ToolSearchProcessor({
  tools: {
    createIssue: githubTools.createIssue,
    sendEmail: emailTools.send,
    getWeather: weatherTools.forecast,
    // ... many more tools
  },
  search: {
    topK: 5,
    minScore: 0.1,
  },
})
```

## 方法 {/* #methods */}

### 國家檢查（遺留`'in-memory'` store) {/* #state-inspection-legacy-in-memory-store */}

這些方法在預設情況下運行`'in-memory'` store only. They're no-ops for the `'context'` store, whose state lives in the conversation messages rather than an in-process map.

#### `clearState(threadId)` {/* #clearstatethreadid */}

清除單一執行緒的載入Tool狀態。

```typescript
processor.clearState('thread-123')
```

#### `clearAllState()` {/* #clearallstate */}

清除每個執行緒的載入Tool狀態。

```typescript
processor.clearAllState()
```

#### `getStateStats()` {/* #getstatestats */}

返回追蹤的線程數和最舊的訪問時間，用於調試記憶體中的增長。

```typescript
const { threadCount, oldestAccessTime } = processor.getStateStats()
```

返回：`{ threadCount: number; oldestAccessTime: number | null }`

#### `cleanupNow()` {/* #cleanupnow */}

立即執行 TTL 清理，而不是等待計劃的掃描。

```typescript
const cleaned = processor.cleanupNow()
```

返回：`number`: the count of threads cleaned up.

## 請求感知過濾 {/* #request-aware-filtering */}

使用`filter` to apply request-specific policy to runtime-defined tools. The hook receives the resolved tool ID as `toolName`, the tool, request context, and phase. `toolName` is the ID returned by `search_tools`, which may differ from the key used in the `tools` object.

```typescript
import { ToolSearchProcessor } from '@mastra/core/processors'

const toolSearch = new ToolSearchProcessor({
  tools: allTools,
  filter: ({ toolName, requestContext, phase }) => {
    const plan = requestContext?.get('plan')

    if (phase === 'search') {
      return true
    }

    return plan === 'pro' || !toolName.startsWith('premium_')
  },
})
```

這`phase` value describes where the filter is being applied:

* `search`：過濾回傳的結果`search_tools`.
* `load`：塊`load_tool` from loading disallowed tools.
* `active`：如果不再允許，則隱藏目前請求中已載入的Tool。

如果鉤子拋出或拒絕，`ToolSearchProcessor` treats the tool as disallowed for that request. The hook may run for every matching search candidate, so keep async policy checks cheap or cached. The `search_tools` meta-tool is always available. `load_tool` is available unless `search.autoLoad` is enabled. Tools passed directly through the agent or `processInputStep` remain available unless you filter them outside `ToolSearchProcessor`, or enable `includeResolvedTools`.

## 搜尋請求解決Tool {/* #searching-request-resolved-tools */}

這`tools` option is fixed at construction, so you can't list tools that only exist per request (MCP tools that need the caller's credentials, or anything returned by a dynamic `tools` function). By default those tools bypass search and occupy prompt space on every turn.

放`includeResolvedTools: true` to index them for the request and withhold them from the prompt until the agent loads them:

```typescript title="src/mastra/agents/mcp-agent.ts"
import { Agent } from '@mastra/core/agent'
import { ToolSearchProcessor } from '@mastra/core/processors'

const toolSearch = new ToolSearchProcessor({
  tools: staticTools,
  includeResolvedTools: true,
})

const agent = new Agent({
  id: 'mcp-agent',
  name: 'mcp-agent',
  instructions: 'Search for a tool when you need a capability you do not have.',
  model: '__GATEWAY_OPENAI_MODEL__',
  // Resolved per request, then searchable alongside staticTools
  tools: async ({ requestContext }) => mcpClient.getTools(requestContext.get('userToken')),
  inputProcessors: [toolSearch],
})
```

每個請求都單獨索引，因此一個呼叫者載入的Tool永遠不會解析為另一個呼叫者俱有相同Tool名稱的實例。

此選項適用於為請求解析的每個Tool，包括記憶體、Workspace、技能和瀏覽器Tool。只有`search_tools` and `load_tool` meta-tools stay in the prompt, so any tool the agent relies on implicitly must be found through search before it can be called, unless `injectCatalog` is enabled and `search.autoLoad` is `false`, in which case the agent can load it directly with `load_tool`. With `search.autoLoad: true`, `load_tool` isn't exposed and `search_tools` activates matching tools.

## 擴充使用範例 {/* #extended-usage-example */}

```typescript title="src/mastra/agents/dynamic-tools-agent.ts"
import { Agent } from '@mastra/core/agent'
import { ToolSearchProcessor } from '@mastra/core/processors'

// Tools from various integrations
import { githubTools } from './tools/github'
import { slackTools } from './tools/slack'
import { dbTools } from './tools/database'

const toolSearch = new ToolSearchProcessor({
  tools: {
    ...githubTools, // createIssue, listPRs, mergePR, ...
    ...slackTools, // sendMessage, createChannel, ...
    ...dbTools, // query, insert, update, ...
  },
  search: {
    topK: 5,
    minScore: 0.1,
  },
})

const agent = new Agent({
  id: 'dynamic-tools-agent',
  name: 'dynamic-tools-agent',
  instructions:
    'You are a helpful assistant with access to many tools. Use search_tools to find relevant tools, then load_tool to make them available.',
  model: '__GATEWAY_OPENAI_MODEL__',
  inputProcessors: [toolSearch],
})
```

AgentWorkflow為：

1. Agent收到用戶訊息
2. Agent來電`search_tools` with keywords (e.g., "github issue")
3. Agent檢討結果和通話`load_tool` with the tool name
4. 載入的Tool在下一回合可用
5. Agent正常使用載入的Tool

## 單步發現`autoLoad` {/* #single-step-discovery-with-autoload */}

放`search.autoLoad` to `true` to skip the separate load step. The tools returned by `search_tools` are activated immediately, and the `load_tool` meta-tool isn't exposed. This removes one model turn per discovery, which lowers token usage and latency, and works the same across providers.

```typescript
const toolSearch = new ToolSearchProcessor({
  tools: allTools,
  search: {
    topK: 3,
    autoLoad: true,
  },
})
```

和`autoLoad` the workflow becomes:

1. Agent收到用戶訊息
2. Agent來電`search_tools` with keywords
3. 匹配Tool會自動啟動並在下一回合可用
4. Agent正常使用該Tool

每場比賽都已激活，所以請保持`topK` small (for example, `3`) to avoid adding tools the agent didn't need. Activated tools are appended after existing tools, which keeps the cached prompt prefix stable for providers that support prompt caching.

## 裝載Tool存儲 {/* #loaded-tool-storage */}

這`storage` option controls where the set of loaded tools is tracked. The default is `'in-memory'`. The `'context'` store is opt-in.

### `'in-memory'`(預設) {/* #in-memory-default */}

載入的Tool在每個線程的記憶體映射中進行跟踪，並透過基於 TTL 的清理來控制`ttl` option (default one hour). This is the original behavior:

* 無需內存配置。
* 進程重新啟動時狀態會遺失。
* 沒有線程ID的請求共享一個`'default'` entry.

使用`clearState`, `clearAllState`, `getStateStats`, and `cleanupNow` to inspect or reset this store.

### `'context'` {/* #context */}

載入狀態源自對話訊息：Tool已加載，而Tool已載入`search_tools` or `load_tool` result naming it remains in the messages. This mode:

* 無需記憶體配置即可運作。如果沒有內存，載入的Tool將僅保留用於當前進程，並且僅用於具有真實線程 ID 的請求。匿名請求要求呼叫者重新發送相關訊息，以在呼叫之間保留已載入的Tool。
* 只要訊息再次可用，就可以在重新啟動後繼續運行：從具有訊息歷史記錄的記憶體中，或因為呼叫者重新發送對話。如果沒有內存，重新啟動只能恢復呼叫者發送的訊息中的內容。
* 一旦結果不再出現在訊息中，就會自動卸載Tool。

```typescript
import { ToolSearchProcessor } from '@mastra/core/processors'

const toolSearch = new ToolSearchProcessor({
  tools: allTools,
  storage: 'context',
})
```

載入Tool在兩種模式下都是快取友好的：載入是僅附加的，因此對於支援提示快取的Provider來說，快取的提示前綴保持穩定。

卸載Tool會變更發送到模型的定義，移動快取的前綴，以便下一回合支付快取寫入費用，而不是接收快取命中。在`'in-memory'` mode, this happens when `ttl` evicts a thread's state; in `'context'` mode, it happens when older-message trimming removes the tool's discovery result. The model must then search for the unloaded tool before reuse. This expected tradeoff exchanges one cache write for a smaller prefix on later turns.

## 與其他處理器結合 {/* #combining-with-other-processors */}

```typescript
import { Agent } from '@mastra/core/agent'
import { ToolSearchProcessor, TokenLimiter } from '@mastra/core/processors'

const agent = new Agent({
  id: 'my-agent',
  name: 'my-agent',
  model: '__GATEWAY_OPENAI_MODEL__',
  inputProcessors: [
    new ToolSearchProcessor({
      tools: allTools,
      search: { topK: 5 },
    }),
    // Place TokenLimiter last to ensure context fits
    new TokenLimiter(127000),
  ],
})
```
