# PrefillErrorHandler

`PrefillErrorHandler` 是處理助理回覆預填錯誤的**錯誤處理器**。當對話以助理訊息結尾，而模型將請求解讀為預填助理回覆並拒絕處理時，就會發生這種錯誤。

偵測到此錯誤後，處理器會傳送隱藏的 `system-reminder` 訊號，內容為 `continue`，並指示重試。此提醒會作為訊號中繼資料保存，以供重建重試過程和保留原始歷程；面向 UI 的標準訊息轉換則會將它隱藏。

Mastra 預設將此處理器加入每個 Agent 的 `errorProcessors`，位於 `ProviderHistoryCompat` 之後、`StreamErrorRetryProcessor` 之前。它只在第一次重試時作用，因此無須設定。如需調整其行為，可提供自己的執行個體。清單中原有的處理器會保留；只有清單中沒有相同 `id` 時，才會加入預設執行個體。

## 運作方式 {/* #how-it-works */}

1. LLM API 呼叫失敗，並傳回已知的助理回覆預填拒絕訊息
2. `PrefillErrorHandler` 檢查目前是否為第一次重試
3. 它傳送隱藏的 `system-reminder` 訊號，內容為 `continue`
4. 它傳回 `{ retry: true }`，指示以修改後的訊息重試 LLM 呼叫

處理器直接根據 API 的拒絕回應採取動作，不再重新檢查對話目前是否以助理訊息結尾。因此，即使上游已轉換最後一則訊息的結構，只要模型提供者仍因預填語意拒絕請求，處理器也能進行復原。

## 使用範例 {/* #usage-example */}

如需調整預填錯誤的復原行為或明確指定其適用範圍，請提供自己的執行個體。此時不會再加入預設的 `PrefillErrorHandler`：

```typescript title="src/mastra/agents/my-agent.ts"
import { Agent } from '@mastra/core/agent'
import { PrefillErrorHandler } from '@mastra/core/processors'

export const agent = new Agent({
  id: 'my-agent',
  name: 'my-agent',
  instructions: 'You are a helpful assistant.',
  model: '__GATEWAY_ANTHROPIC_MODEL_OPUS__',
  errorProcessors: [new PrefillErrorHandler()],
})
```

如需自訂復原行為，可以提供實作 `processAPIError` 方法的錯誤處理器：

```typescript title="src/mastra/agents/custom-error-handling.ts"
import { Agent } from '@mastra/core/agent'
import type { Processor } from '@mastra/core/processors'

const customErrorHandler: Processor = {
  id: 'custom-prefill-error-handler',
  processAPIError({ error, messageList, retryCount }) {
    // Your custom logic here
  },
}

export const agent = new Agent({
  id: 'my-agent',
  name: 'my-agent',
  instructions: 'You are a helpful assistant.',
  model: '__GATEWAY_ANTHROPIC_MODEL_OPUS__',
  errorProcessors: [customErrorHandler],
})
```
