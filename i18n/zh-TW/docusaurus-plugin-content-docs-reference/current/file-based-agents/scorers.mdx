# Scorer

檔案式 Agent 會從其 `scorers/` 目錄發現 Scorer。本頁說明檔案式約定；內建 Scorer、自訂 Scorer 與取樣請參閱 [Scorer 指南](/docs/evals/overview)。

`scorers/` 下的每個檔案預設匯出一個 Scorer，檔名即為其鍵。預設匯出可以是 [`MastraScorer`](/reference/evals/create-scorer)，也可以是 `{ scorer, sampling }` 項目。

## 快速入門 {/* #quickstart */}

在 Agent 的 `scorers/` 目錄下放置檔案即可加入 Scorer。以下範例使用[自訂 Scorer](/docs/evals/custom-scorers)：

```typescript title="src/mastra/agents/weather/scorers/relevance.ts"
import { createScorer } from '@mastra/core/evals'

export default createScorer({
  id: 'relevance',
  description: 'Scores how relevant the response is',
}).generateScore(() => 1)
```

此 Scorer 會以 `relevance` 為键註冊到 `weather` Agent，效果與將其加入到 `config.scorers` 相同。

## 取樣 {/* #sampling */}

要控制 Scorer 的執行頻率，請預設匯出 `{ scorer, sampling }` 條目，而不是單獨的 Scorer：

```typescript title="src/mastra/agents/weather/scorers/relevance.ts"
import { createScorer } from '@mastra/core/evals'

const relevance = createScorer({
  id: 'relevance',
  description: 'Scores how relevant the response is',
}).generateScore(() => 1)

export default {
  scorer: relevance,
  sampling: { type: 'ratio', rate: 0.5 },
}
```

## 設定的優先權 {/* #precedence-with-config */}

發現的 Scorer 會與 [`config.ts`](/reference/file-based-agents/config) 中定義的 Scorer 合併。鍵衝突時，以 `config.scorers` 為準並發出警告。若 `config.scorers` 是函式，便無法靜態合併；已發現的 Scorer 會被忽略並發出警告。

鍵衝突時，優先順序如下：

1. 函式形式的 `config.scorers`
1. 紀錄形式的 `config.scorers`
1. `scorers/` 下發現的檔案

沒有鍵衝突的已發現 Scorer 會保留。

完整 Scorer 介面請參閱 [`createScorer()`](/reference/evals/create-scorer)。
