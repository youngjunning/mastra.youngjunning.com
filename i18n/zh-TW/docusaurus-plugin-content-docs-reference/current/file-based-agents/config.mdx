# config.ts

Agent 的 `config.ts` 設定模型與執行階段選項。屬於 [`Agent`](/reference/agents/agent) 本身的選項放在這裡；指令、工具與技能等由同層檔案提供。

## `config.ts` 應包含哪些設定 {/* #what-belongs-in-configts */}

`config.ts` 是檔案式 Agent 設定模型與執行階段選項的必要入口。模型、描述、預設執行選項、重試行為、評分器與顯示識別資訊等不需要獨立檔案的 Agent 層級設定，都放在這裡。

若要讓檔案式路由將相關設定合併到 Agent，請將它們放在同層檔案。例如，使用 `instructions.md` 儲存持續生效的提示詞，並以 `tools/` 存放可供模型呼叫的動作。

## 快速開始 {/* #quickstart */}

以下 `config.ts` 搭配 `instructions.md` 檔案，即可建立可運作的檔案式 Agent：

```typescript title="src/mastra/agents/weather/config.ts"
import { agentConfig } from '@mastra/core/agent'

export default agentConfig({
  model: '__GATEWAY_OPENAI_MODEL__',
})
```

```markdown title="src/mastra/agents/weather/instructions.md"
You are a helpful weather assistant. Answer questions about current conditions and forecasts.
```

Mastra 預設使用目錄名稱 `weather` 作為 Agent 的 `id` 與 `name`。同層的 `instructions.md` 提供必要的指令。

## 設定模型 {/* #set-the-model */}

`model` 是 `agentConfig()` 中唯一的必填欄位。若 Agent 目錄未提供模型，建置會失敗。其他能力由同層檔案提供，或使用預設值。

```typescript title="src/mastra/agents/weather/config.ts"
import { agentConfig } from '@mastra/core/agent'

export default agentConfig({
  model: '__GATEWAY_OPENAI_MODEL__',
})
```

## 從目錄取得識別資訊 {/* #identity-from-the-directory */}

檔案式 Agent 預設使用目錄名稱作為 `id` 與 `name`。對於 `src/mastra/agents/weather/`，除非覆寫這兩個欄位，否則 Mastra 會將 Agent 註冊為 `weather`。

當穩定的路由鍵與顯示名稱需要不同時，可覆寫 `id` 或 `name`。

```typescript title="src/mastra/agents/weather/config.ts"
import { agentConfig } from '@mastra/core/agent'

export default agentConfig({
  id: 'weather-assistant',
  name: 'Weather Assistant',
  model: '__GATEWAY_OPENAI_MODEL__',
})
```

## 設定執行階段選項 {/* #set-runtime-options */}

`agentConfig()` 接受 [`Agent` 建構函式選項](/reference/agents/agent#constructor-parameters)；其中 `id`、`name` 與同層檔案對應的欄位，也可透過檔案式慣例提供。完整選項請參閱 Agent 參考文件。

請注意：

- 檔案式子 Agent 必須有非空的 `description`，因為父層模型會用它決定委派路由。
- `defaultOptions`、`maxRetries`、`scorers` 等 Agent 選項若不需要獨立檔案，可以放在 `config.ts` 中。

## 相關設定放在哪裡 {/* #where-adjacent-settings-live */}

讓 `config.ts` 專注於執行階段選項。適合獨立管理的設定放在同層檔案中。

| 設定 | 檔案或資料夾 | 放在這裡的原因 |
| - | - | - |
| 指令 | [`instructions.md` 或 `instructions.ts`](/reference/file-based-agents/instructions) | 持續生效的提示詞可直接以 Markdown 閱讀，也可由 TypeScript 動態產生 |
| 工具 | [`tools/`](/reference/file-based-agents/tools) | 每個可呼叫動作都有獨立且具型別的模組 |
| 技能 | [`skills/`](/reference/file-based-agents/skills) | 按需載入的流程與始終生效的指令分開 |
| 記憶 | [`memory.ts`](/reference/file-based-agents/memory) | 設定持久化記憶，避免擠占執行階段選項 |
| Workspace | [`workspace.ts`](/reference/file-based-agents/workspace) | 將檔案與沙箱行為和模型設定分開配置 |
| Processor | [`processors/`](/reference/file-based-agents/processors) | 分開處理輸入與輸出流程 |
| 子 Agent | [`subagents/`](/reference/file-based-agents/subagents) | 每個專責的子 Agent 都有獨立目錄 |

## 優先順序 {/* #precedence */}

`config.ts` 與 Agent 其他檔案的合併規則如下：

| 類別 | 來源 A | 來源 B | 優先使用 |
| - | - | - | - |
| 指令 | 動態 `config.instructions` | [`instructions.ts` 或 `instructions.md`](/reference/file-based-agents/instructions) | 動態 `config.instructions` |
| 指令 | 靜態 `config.instructions` | [`instructions.ts` 或 `instructions.md`](/reference/file-based-agents/instructions) | 指令檔案 |
| 指令 | [`instructions.ts`](/reference/file-based-agents/instructions) | [`instructions.md`](/reference/file-based-agents/instructions) | `instructions.ts` |
| 工具 | `config.tools` | [`tools/`](/reference/file-based-agents/tools) | 兩者合併；鍵衝突時以 `config.tools` 為準 |
| 工具 | 函式形式的 `config.tools` | [`tools/`](/reference/file-based-agents/tools) | 函式形式的 `config.tools`；略過自動探索的工具 |
| 技能 | `config.skills` | [`skills/`](/reference/file-based-agents/skills) | 兩者合併；名稱衝突時以 `config.skills` 為準 |
| 技能 | 函式形式的 `config.skills` | [`skills/`](/reference/file-based-agents/skills) | 函式形式的 `config.skills`；略過自動探索的技能 |
| 記憶 | `config.memory` | [`memory.ts`](/reference/file-based-agents/memory) | `config.memory` |
| Workspace | `config.workspace` | [`workspace.ts`](/reference/file-based-agents/workspace) | `config.workspace` |

若 `instructions.md`、`instructions.ts` 和 `config.instructions` 全都缺少，建置會失敗。若 `config.memory` 與 `memory.ts` 都缺少，Agent 就沒有記憶。

## 探索流程 {/* #discovery-lifecycle */}

執行 `mastra dev` 或 `mastra build` 時，Mastra 打包工具會探索檔案式元件。過程中，它讀取 `src/mastra/` 下支援的檔案、匯入 TypeScript 與 JavaScript 模組，也會讀取 Markdown 指令與技能。接著複製 Workspace 初始檔案，並將組裝後的元件註冊到 Mastra 應用程式。

探索完成後，檔案式 Agent 會如一般 [`Agent`](/reference/agents/agent) 運作。從 Agent API、Studio、Workflow 或應用程式程式碼呼叫時，都使用與程式碼定義的 Agent 相同的執行階段。

探索機制以原始碼為依據，且採取保守策略。

它會略過符號連結、測試檔案，以及不屬於 Agent 的目錄。Workflow 與專案層級的單一檔案只有在具備預設匯出時，才會依檔案路由。

透過 Mastra CLI 啟動應用程式，以執行探索流程：

```bash npm2yarn
npx mastra dev
```

若直接匯入 `mastra` 執行個體，就不會探索 `agents/<name>/` 目錄與其他檔案慣例。將 Mastra 當成函式庫使用時，請改在程式碼中註冊這些元件。
