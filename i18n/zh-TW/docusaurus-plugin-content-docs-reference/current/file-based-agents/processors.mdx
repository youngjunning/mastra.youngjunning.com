# 處理器

檔案式 Agent 會從其 `processors/` 目錄探索[處理器](/docs/agents/processors)。本頁說明檔案式慣例；內建處理器、自訂處理器、串流行為與進階模式請參閱處理器指南。

`processors/input/` 下的檔案會在訊息送達模型前執行；`processors/output/` 下的檔案會在模型回應後執行。每個檔案預設匯出一個 [`Processor`](/reference/processors/processor-interface)，檔名會成為其探索鍵。

## 快速入門 {/* #quickstart */}

將處理器檔案放在 `processors/input/` 下，即可新增輸入處理器：

```typescript title="src/mastra/agents/weather/processors/input/pii.ts"
import { PIIDetector } from '@mastra/core/processors'

export default new PIIDetector({
  strategy: 'block',
})
```

此處理器會在使用者訊息送達模型前執行。

## 新增輸出處理器 {/* #add-an-output-processor */}

輸出處理器適合在回傳模型回應前進行篩選或轉換。此範例會從最終回應中遮蔽個人識別資訊（PII）。

```typescript title="src/mastra/agents/weather/processors/output/redact.ts"
import { PIIDetector } from '@mastra/core/processors'

export default new PIIDetector({
  strategy: 'redact',
})
```

## 執行順序 {/* #ordering */}

探索到的處理器會加在 [`config.ts`](/reference/file-based-agents/config) 中定義的處理器之後，因此設定中的處理器會先執行。

```text title="Ordering"
config.inputProcessors → processors/input/* → model
model → config.outputProcessors → processors/output/* → response
```

若 `config.inputProcessors` 或 `config.outputProcessors` 是函式，系統會忽略探索到的對應類型處理器並發出警告，因為函式形式的處理器無法靜態合併。

若 `config.ts` 匯出的是 `new Agent()` 而非設定物件，Mastra 會直接使用該 Agent。系統會忽略在 `processors/input/` 與 `processors/output/` 下探索到的檔案並發出警告，因此應改為將 `inputProcessors` 與 `outputProcessors` 設定到 `Agent` 上。

## 與設定的優先順序 {/* #precedence-with-config */}

需要在執行階段建立或由多個 Agent 共用的處理器，請在 `config.ts` 中設定。應與 Agent 一同檢閱的靜態單一 Agent 處理器，則使用檔案式處理器。

優先順序如下：

1. 函式形式的 `config.inputProcessors` 或 `config.outputProcessors`
1. 陣列形式的 `config.inputProcessors` 或 `config.outputProcessors`
1. 在 `processors/input/` 或 `processors/output/` 下探索到的檔案

完整介面請參閱 [`Processor` 參考](/reference/processors/processor-interface)。
