# 工作空間

一個[workspace](/docs/sandbox/overview)集合檔案系統存取和命令執行等功能。配置的後端決定哪些Tool可用。基於檔案的Agent程式在透過以下方式發現時會自動獲得預設Workspace`mastra dev`或者`mastra build`。此預設值包括檔案系統存取和命令執行，因此Agent可以讀取和寫入檔案以及運行 shell 命令，而無需額外配置。

使用此頁面進行基於文件的約定。有關Workspace提供程序、Tool、搜索、生命週期和沙箱的詳細信息，請參閱[Sandbox](/docs/sandbox/overview).

## 預設Workspace {/* #default-workspace */}

沒有`workspace.ts`, a file-based agent gets a default [`Workspace`](/reference/workspace/workspace-class) when the build provides a per-agent workspace path. The default workspace uses:

* [`LocalFilesystem`](/reference/workspace/local-filesystem)植根於Agent程式的捆綁Workspace目錄。
* [`LocalSandbox`](/reference/workspace/local-sandbox)具有相同的工作目錄。

這會自動提供Agent檔案Tool和 shell Tool。預設Workspace是每個Agent的。子Agent程式在其父Agent程式的Workspace路徑下取得巢狀Workspace目錄。

## 禁用預設Workspace {/* #disable-the-default-workspace */}

放`workspace` to `undefined` in `config.ts` to create the agent without a workspace:

```typescript title="src/mastra/agents/weather/config.ts"
import { agentConfig } from '@mastra/core/agent'

export default agentConfig({
  model: '__GATEWAY_OPENAI_MODEL__',
  workspace: undefined,
})
```

當您停用Workspace時，Agent程式不會接收自動檔案和 shell Tool。

## 快速入門 {/* #quickstart */}

對於預設Workspace，不要新增檔案。從這樣的Agent商目錄開始：

```text title="Default workspace"
src/mastra/agents/weather/
├── config.ts
└── instructions.md
```

添加`workspace.ts` only when you need to customize the workspace:

```typescript title="src/mastra/agents/weather/workspace.ts"
import { Workspace, LocalFilesystem, LocalSandbox } from '@mastra/core/workspace'

export default new Workspace({
  name: 'weather-workspace',
  filesystem: new LocalFilesystem({ basePath: './data/weather' }),
  sandbox: new LocalSandbox({ workingDirectory: './data/weather' }),
})
```

參觀[`Workspace` reference](/reference/workspace/workspace-class) for the full config.

## 何時自訂Workspace {/* #when-to-customize-the-workspace */}

當預設本地目錄不夠時自訂Workspace。常見原因包括：

* 將檔案Tool指向不同的檔案系統根目錄。
* 在不同的沙箱Provider中執行 shell 指令。
* 使用 BM25 或向量搜尋新增Workspace搜尋。
* 跨多個Agent程式共享一個Workspace。

有關提供程序模式和運行時行為，請參閱[sandbox guide](/docs/sandbox/overview) and [workspace search](/docs/sandbox/search).

## 運行時邊界 {/* #runtime-boundary */}

Workspace檔案系統控製檔案Tool訪問，沙箱決定 shell 指令的運作位置。除非明確地呼叫Workspace或沙箱 API，否則應用程式運行時程式碼仍會在您的應用程式或伺服器進程中運行，包括[`tools/`](/reference/file-based-agents/tools).

## 種子文件 {/* #seed-files */}

添加一個`workspace/` directory to include starting files with the agent. Mastra mirrors files under `workspace/` into the agent's default runtime workspace at build time. The agent starts with those files on disk.

```text title="Seed files"
src/mastra/agents/weather/
├── config.ts
└── workspace/
    ├── README.md
    └── data/
        └── cities.json
```

這些檔案被複製到捆綁的Workspace路徑中，Workspace檔案Tool和沙箱命令可以在其中讀取它們。鏡像過程中會跳過符號連結的種子檔案。

## 配置的優先權 {/* #precedence-with-config */}

`config.workspace`戰勝`workspace.ts`, including when you set it to `undefined`. Otherwise, Mastra uses the default file-based workspace. See [`config.ts` precedence](/reference/file-based-agents/config#precedence) for the full merge table.
