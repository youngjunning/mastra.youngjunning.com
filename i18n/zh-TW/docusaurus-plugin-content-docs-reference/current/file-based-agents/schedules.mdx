# 時間表

基於文件的Agent發現**schedules**從它的`schedules/`目錄。每個檔案都聲明一個重複任務：一個 cron 表達式以及Agent程式在觸發時應該執行的操作。 Mastra 在啟動時將它們註冊到計劃存儲中。計劃Agent不需要運行時註冊代碼。

使用此頁面進行基於文件的約定。若要在運行時建立計劃，請參閱[Schedules](/reference/schedules/overview).

`defineSchedule`重新出口自`@mastra/core/agent` so file-based agents need one import path. `@mastra/core/schedules` exports it too.

## 快速入門 {/* #quickstart */}

在agent下方新增一個文件`schedules/` directory:

```typescript title="src/mastra/agents/support/schedules/heartbeat.ts"
import { defineSchedule } from '@mastra/core/agent'

export default defineSchedule({
  cron: '*/5 * * * *',
  prompt: 'Check system health and report any failures.',
})
```

每五分鐘，Mastra 運行一次`support` agent with that prompt.

## 時間表身份 {/* #schedule-identity */}

時間表的 id 是其相對路徑`schedules/` with the extension stripped, so nested directories are a way to group related schedules:

```text title="Schedule layout"
src/mastra/agents/
└── support/
    ├── config.ts
    ├── instructions.md
    └── schedules/
        ├── heartbeat.ts      # id: heartbeat
        ├── cleanup.md        # id: cleanup
        └── billing/
            └── sweep.ts      # id: billing/sweep
```

該 ID 在各個版本中都是穩定的，這讓 Mastra 可以區分編輯後的時間表和新的時間表。重新命名或移動檔案被視為刪除一個計劃並建立另一個計劃。

`heartbeat.ts`和`heartbeat.md` resolve to the same id, so declaring both is a build error.

## 執行模式 {/* #execution-modes */}

時間表恰好設定一種執行模式。設定兩者或都不設定都會導致建置失敗。

### 提示方式 {/* #prompt-mode */}

`prompt`使用固定訊息運行所屬Agent程式。當調度以執行緒為目標時，火災會發送喚醒訊號並返回而不等待運行，因為執行緒流運行時驅動運行完成，而無執行緒調度則等待`agent.generate` and doesn't finish until the run does.

```typescript title="src/mastra/agents/support/schedules/digest.ts"
import { defineSchedule } from '@mastra/core/agent'

export default defineSchedule({
  cron: '0 9 * * 1',
  timezone: 'America/New_York',
  prompt: 'Summarize last week and post the digest.',
})
```

### 處理程序模式 {/* #handler-mode */}

`handler`當計劃觸發時計算火災參數。當提示取決於目前狀態、應跳過某些觸發或執行需要通道傳遞上下文時，請使用它。

```typescript title="src/mastra/agents/support/schedules/billing/sweep.ts"
import { defineSchedule } from '@mastra/core/agent'

export default defineSchedule({
  cron: '0 3 * * *',
  handler: async ({ mastra, agentId }) => {
    const overdue = await findOverdueInvoices()

    // Returning null skips this fire; nothing runs and the trigger is
    // recorded with outcome 'skipped'.
    if (overdue.length === 0) return null

    return {
      prompt: `Chase these overdue invoices: ${overdue.join(', ')}`,
      threadId: 'billing-ops',
      resourceId: agentId,
    }
  },
})
```

處理程序的傳回值合併到計畫的儲存欄位。返回`undefined` applies no overrides. The fire falls back to those stored fields. Since a handler-mode schedule can't declare a `prompt`, that fire then fails for a missing prompt. Return a `prompt` to run, or `null` to skip.

處理程序是函數，因此它們無法保留在儲存的計劃行上。當計劃觸發時，Mastra 會在進程中解決這些問題。不提供提示（且聲明不提示）的處理程序模式計畫會因原因而失敗，而不是向Agent程式發送空訊息。

進程內查找意味著執行調度程序的進程必須註冊擁有Agent程式。正常部署會啟動單一條目並免費取得該條目。獨立工作人員需要與伺服器相同的條目。從修剪過的條目啟動一個，它沒有可呼叫的處理程序。它的火不是熄滅而是熄滅。

### 降價時間表 {/* #markdown-schedules */}

一個`.md` schedule uses frontmatter for the cron and the document body as the prompt. This is prompt mode with more room to write:

```markdown title="src/mastra/agents/support/schedules/cleanup.md"
---
cron: '0 3 * * *'
timezone: 'UTC'
name: 'nightly cleanup'
---

Review tickets untouched for 30 days.

Close the ones that are clearly resolved and summarize the rest.
```

始終引用 cron。領先的`*` is a YAML alias, so `cron: */5 * * * *` is a parse error while `cron: "*/5 * * * *"` is fine.

Frontmatter 接受以下所有選項，除了`handler`, which needs a function and so needs a `.ts` or `.js` schedule module. `prompt` isn't settable either, because the body is the prompt. Unknown frontmatter fields fail the build rather than being silently ignored, so a typo like `ifIdel` is caught at build time.

## 測試開發中的時間表 {/* #testing-a-schedule-in-development */}

安排在其 cron 節奏上觸發，這在迭代時是不切實際的。而是根據 id 按需觸發一個：

```bash
# List schedules to find the id
curl http://localhost:4111/api/schedules

# Fire one now, out-of-band from its cron
curl -X POST http://localhost:4111/api/schedules/<scheduleId>/run
```

這記錄了一個觸發器`triggerKind: "manual"` and doesn't advance `nextFireAt`, so the regular cadence is unaffected. Studio lists the same schedules and their trigger history.

儲存的 ID 是命名空間和 URL 編碼的。`billing/sweep` on the `support` agent becomes `fsa_support__billing%2Fsweep`, so copy the id from the list response rather than assembling it by hand.

## 註冊和生命週期 {/* #registration-and-lifecycle */}

Mastra 在啟動時將聲明的時間表同步到時間表儲存中，並在Agent註冊後再次同步。聲明一個調度就足以啟動調度程序，無需`scheduler: { enabled: true }` needed.

同步將每個聲明的計劃與其儲存的行進行比較，並僅寫入更改的內容：

* 新的計劃文件建立一行。
* 編輯`cron` or `timezone` patches the row and recomputes the next fire time, so an edited schedule never fires on its old cadence.
* 刪除或重新命名計劃檔案會刪除其行。
* 透過 API 暫停計畫在重新部署後仍然有效。同步故意離開`status` alone.

同步僅刪除屬於目前進程中已註冊的Agent程式的行，因此保存Agent子集的程序永遠不會刪除其他Agent程式的計劃。當Agent從專案中完全刪除時，當調度程序發現沒有Agent可以運行時，其剩餘行將在下次觸發時被清理。

運行時創建的時間表通過`mastra.schedules.create(...)` live in a separate namespace and are never touched by this sync.

## 限制 {/* #limits */}

**僅限根Agent。**&#x5411;頂級Agent聲明時間表。一個`schedules/` directory under `subagents/` causes a build error because subagents are wired into their parent instead of being registered on the Mastra instance, leaving the scheduler unable to resolve them as targets. Give the parent the schedule and let it delegate.

**需要存儲。**&#x7531;於計劃是持久化的行，並且記憶體儲存中的行在重新啟動後無法繼續存在，因此實例需要[storage](/reference/file-based-agents/storage) configured.

**主持。**&#x8ABF;度程序作為 Mastra 進程內的後台工作程序運行，因此它需要一個主機來保持該進程處於活動狀態。長時間運行的節點伺服器和容器可以工作。凍結或回收請求之間的進程的環境（包括大多數無伺服器功能平台）將錯過火災。使用平台自己的 cron 來呼叫那裡的運行端點。

**代碼定義的Agent。**&#x4E00;個Agent目錄，其`config.ts` exports `new Agent({...})` is used verbatim, so its `schedules/` directory is ignored with a warning. Use `mastra.schedules.create(...)` for those.

## 例子 {/* #example */}

支援Agent有兩個時間表：固定的每週摘要，以及僅在有事情要做時運行的夜間清理。

```text title="Scheduled support agent"
src/mastra/agents/
└── support/
    ├── config.ts
    ├── instructions.md
    └── schedules/
        ├── weekly-digest.md
        └── billing/
            └── sweep.ts
```

```typescript title="src/mastra/agents/support/config.ts"
import { agentConfig } from '@mastra/core/agent'

export default agentConfig({
  model: '__GATEWAY_OPENAI_MODEL__',
})
```

```markdown title="src/mastra/agents/support/schedules/weekly-digest.md"
---
cron: '0 9 * * 1'
timezone: 'America/New_York'
---

Summarize the past week's tickets and post the digest to the team channel.
```

```typescript title="src/mastra/agents/support/schedules/billing/sweep.ts"
import { defineSchedule } from '@mastra/core/agent'

export default defineSchedule({
  cron: '0 3 * * *',
  timezone: 'America/New_York',
  handler: async () => {
    const overdue = await findOverdueInvoices()
    if (overdue.length === 0) return null
    return { prompt: `Draft reminders for ${overdue.length} overdue invoices.` }
  },
})
```
