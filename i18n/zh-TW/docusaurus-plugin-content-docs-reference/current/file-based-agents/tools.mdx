# Tool

檔案型 Agent 會探索 `.ts` 與 `.js` 檔案，前提是它們直接位於 Agent 的 `tools/` 目錄中。每個找到的檔案都會在建置時匯入，且必須預設匯出一個 Tool。凡是 Agent 的 `tools` 選項接受的 Tool 都可使用，例如 [`createTool()`](/reference/tools/create-tool) 的回傳值或 Vercel AI SDK 的 `tool()`。去掉副檔名的檔名就是模型呼叫該 Tool 時使用的鍵。

本頁說明檔案型 Tool 的慣例。Tool 的 Schema、執行選項、輸出格式處理與核准選項，請參閱 [`createTool()` 參考文件](/reference/tools/create-tool)。

## 快速入門 {/* #quickstart */}

在 `tools/` 下每個檔案放置一個 Tool。以下檔案會以 `get_weather` 這個鍵提供給 Agent。

```typescript title="src/mastra/agents/weather/tools/get_weather.ts"
import { createTool } from '@mastra/core/tools'
import { z } from 'zod'

export default createTool({
  id: 'get_weather',
  description: 'Get the current weather for a location.',
  inputSchema: z.object({
    location: z.string(),
  }),
  outputSchema: z.object({
    location: z.string(),
    temperatureCelsius: z.number(),
    conditions: z.string(),
  }),
  execute: async ({ location }) => {
    return { location, temperatureCelsius: 21, conditions: 'sunny' }
  },
})
```

## 整理 Tool 檔案 {/* #organizing-tools */}

每個 Tool 使用一個檔案，並依希望模型執行的動作命名：

* 使用 `get_weather.ts`、`search_docs.ts` 或 `create_ticket.ts` 這類名稱。
* 避免 `helper.ts`、`api.ts` 或 `utils.ts` 等含義模糊的名稱。
* 測試檔可與 Tool 放在一起，命名為 `*.test.ts` 或 `*.spec.ts`；探索機制會忽略這些檔案。
* 共用輔助程式碼應放在 `tools/` 之外，或放在 `tools/` 下不符合探索規則的檔案中。

巢狀目錄中的檔案不會被探索為 Tool。要整理相關 Tool，請使用清楚的檔名前綴，而非子資料夾，例如 `calendar_create_event.ts` 和 `calendar_list_events.ts`。

## Tool 選項 {/* #tool-options */}

檔案型慣例只決定 Tool 的位置與註冊方式；選項由 Tool 本身定義。對於以 `createTool()` 建立的 Tool：

* 使用 `description` 告訴模型何時呼叫該 Tool。
* 使用 `inputSchema` 和 `outputSchema` 定義結構化輸入與輸出。
* 使用 `toModelOutput`，可讓模型看到不同於 `execute` 原始回傳值的輸出格式。
* 若 Tool 執行前需要人工確認，使用 `requireApproval`。

完整選項請參閱 [`createTool()` 參考文件](/reference/tools/create-tool)；核准流程請參閱 [Tool 核准](/docs/harness/agent-controller#approve-tools-and-resume-suspensions)。Vercel AI SDK Tool 則使用 [AI SDK 的 `tool()` API](https://ai-sdk.dev/docs/reference/ai-sdk-core/tool)。

## 運行時邊界 {/* #runtime-boundary */}

Agent 呼叫 Tool 時，Tool 程式碼會在應用程式或伺服器的執行環境中運作。若 Tool 需要隔離檔案系統或 shell 操作，請明確呼叫 [Workspace](/reference/file-based-agents/workspace) 或 Sandbox API。

## 配置的優先權 {/* #precedence-with-config */}

自動探索的 Tool 會與 `tools` 設定合併，該設定位於 [`config.ts`](/reference/file-based-agents/config)。若鍵名衝突，以 `config.tools` 為準，並記錄警告。

若 `config.tools` 是函式，系統會忽略自動探索的 Tool 並記錄警告，因為函式形式的 Tool 設定無法靜態合併。
