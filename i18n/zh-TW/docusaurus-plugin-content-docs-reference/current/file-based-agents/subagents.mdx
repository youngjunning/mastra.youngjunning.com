# 子 Agent

以檔案為基礎的 Agent 可以宣告 **subagents（子 Agent）**，將任務委派給具備專長的子 Agent。父 Agent 使用的模型會將每個子 Agent 視為以其目錄命名的委派 Tool，並呼叫該 Tool 交付任務。子 Agent 的結果會回傳至父 Agent 的對話。

本頁說明以檔案為基礎的設定慣例。關於更廣泛的委派模式、Hook、Memory 隔離、Tool 核准傳遞與評分，請參閱 [Supervisor Agent](/docs/subagents)。

## 快速入門 {/* #quickstart */}

在 `subagents/` 底下為每個子 Agent 建立一個目錄：

```text title="Subagent layout"
src/mastra/agents/
└── supervisor/
    ├── config.ts
    ├── instructions.md
    └── subagents/
        └── researcher/
            ├── config.ts
            ├── instructions.md
            └── tools/
                └── search.ts
```

Mastra 會將 `researcher` 組裝為獨立的 Agent，並將它加入主管 Agent 的 `agents` 對應表。父 Agent 使用的模型可透過產生的 `researcher` 委派 Tool 將任務交給它。

子 Agent 的 `config.ts` 必須設定非空的 `description`。父 Agent 使用的模型會參考此描述，決定是否委派任務。

```typescript title="src/mastra/agents/supervisor/subagents/researcher/config.ts"
import { agentConfig } from '@mastra/core/agent'

export default agentConfig({
  model: '__GATEWAY_OPENAI_MODEL__',
  description: 'Researches a topic and returns cited findings.',
})
```

## 模型如何委託 {/* #how-the-model-delegates */}

子 Agent 的 `description` 是供父 Agent 使用的模型判斷委派對象的路由說明。撰寫方式與 [Tool 描述](/reference/file-based-agents/tools#tool-options)相同：說明子 Agent 的用途，以及何時應將任務交給它。

如果找到的子 Agent 未提供非空描述，建置會失敗。例外情況是父 Agent 的 `config.ts` 匯出了 `new Agent()`：此時系統會發出警告並忽略其 `subagents/` 目錄，因此不會檢查描述。請改為設定 `agents`，並將其配置在該 `Agent` 上。

## 隔離 {/* #isolation */}

子 Agent 彼此隔離，也不會繼承父 Agent 的 Tool、Skill、Workspace、Memory、處理器或其他子 Agent。每個子 Agent 都是擁有自己目錄的獨立 Agent。

如果多個 Agent 需要共用同一項相依項目，請在程式碼中定義，再透過各 Agent 的設定分別指定。

## 嵌套 {/* #nesting */}

子 Agent 也可以宣告自己的 `subagents/` 目錄，最多可在頂層 Agent 下巢狀三層。更深層的 `subagents/` 目錄會被忽略，並顯示警告。

```text title="Nested subagents"
src/mastra/agents/
└── supervisor/            # depth 0
    └── subagents/
        └── researcher/    # depth 1
            └── subagents/
                └── summarizer/ # depth 2
```

## 命名規則 {/* #naming-rules */}

- 子 Agent ID 與父 Agent 的某個 Tool 鍵衝突時，建置會失敗。
- 同一父 Agent 底下出現重複的子 Agent ID 時，建置會失敗。
- 如果子 Agent ID 也存在於父 Agent 的 `config.agents` 中，則以 `config.agents` 中的項目為準，並記錄警告。
- 如果 `config.agents` 是函式，就無法靜態合併；找到的子 Agent 會被忽略，並記錄警告。

## 範例 {/* #example */}

這個主管 Agent 負責協調研究與寫作流程。`researcher` 子 Agent 擁有搜尋 Tool，`writer` 子 Agent 則擁有用於草擬檔案的 Workspace。

```text title="Research supervisor"
src/mastra/agents/
└── research-supervisor/
    ├── config.ts
    ├── instructions.md
    └── subagents/
        ├── researcher/
        │   ├── config.ts
        │   ├── instructions.md
        │   └── tools/
        │       └── search_web.ts
        └── writer/
            ├── config.ts
            ├── instructions.md
            └── workspace/
                └── draft-template.md
```

```typescript title="src/mastra/agents/research-supervisor/config.ts"
import { agentConfig } from '@mastra/core/agent'

export default agentConfig({
  model: '__GATEWAY_OPENAI_MODEL__',
})
```

```markdown title="src/mastra/agents/research-supervisor/instructions.md"
You coordinate research and writing.

Delegate fact gathering to `researcher`. Delegate final drafting to `writer`.
```

```typescript title="src/mastra/agents/research-supervisor/subagents/researcher/config.ts"
import { agentConfig } from '@mastra/core/agent'

export default agentConfig({
  model: '__GATEWAY_OPENAI_MODEL_LUNA__',
  description: 'Use to gather facts, sources, and concise research notes for a topic.',
})
```

```typescript title="src/mastra/agents/research-supervisor/subagents/writer/config.ts"
import { agentConfig } from '@mastra/core/agent'

export default agentConfig({
  model: '__GATEWAY_OPENAI_MODEL__',
  description: 'Use to turn research notes into a structured draft.',
})
```
