# Notifications

通知收件匣紀錄是 `agent.sendNotificationSignal()` 持久儲存的狀態，與傳遞到執行緒的通知訊號並非同一個物件。紀錄追蹤路由、優先順序、傳遞狀態、去重與重試歷程；訊號的中繼資料包含紀錄的摘要與快照。

使用 [`Agent.sendNotificationSignal()`](/reference/agents/agent#sendnotificationsignalnotification-options) 建立紀錄；傳遞流程請參閱[通知指南](/docs/signals/notifications)。

## 合併待處理紀錄 {/* #coalescing-pending-records */}

`sendNotificationSignal()` 可將新通知合併至現有待處理紀錄，而不是另建一筆。只有執行緒、來源、種類、Agent 與資源均相同的紀錄才會參與合併。

每個鍵都有不同的用途：

- `dedupeKey` 標識同一事件。重試或重複的 Webhook 應更新現有紀錄時，請重用此鍵。
- `coalesceKey` 將相關事件歸為一組。多個事件應合併成一筆紀錄時使用，例如同一條管線的多次失敗。

兩個鍵用途不同，但遵循相同的比對規則。

當通知合併時：

- 新的 `summary` 與 `payload` 會取代舊值。
- 新通知提供 `priority` 時會更新優先順序。
- `attributes` 與 `metadata` 會合併，以新值為準。
- `coalescedCount` 會增加。

## 優先順序與狀態 {/* #priorities-and-statuses */}

`NotificationPriority` 控制預設的傳遞時機。

```typescript
type NotificationPriority = 'low' | 'medium' | 'high' | 'urgent'
```

`NotificationStatus` 表示紀錄的生命週期。

```typescript
type NotificationStatus =
  | 'pending'
  | 'delivered'
  | 'seen'
  | 'dismissed'
  | 'archived'
  | 'discarded'
  | 'failed'
```

`pending` 紀錄可進入派送流程。`delivered` 表示已送出完整的通知訊號。`seen`、`dismissed` 與 `archived` 是收件匣狀態。`discarded` 表示傳遞原則拒絕該通知。`failed` 表示傳遞已達五次嘗試上限。

## 傳遞決策 {/* #delivery-decisions */}

傳遞原則會傳回一個 `NotificationDeliveryDecision`。

```typescript
type NotificationDeliveryAction =
  | 'deliver'
  | 'queue'
  | 'defer'
  | 'summarize'
  | 'persist'
  | 'discard'

type NotificationDeliveryDecision = {
  action: NotificationDeliveryAction
  deliverAt?: Date
  summaryAt?: Date
  reason?: string
  streamOptions?: AgentExecutionOptions<unknown>
  hold?: boolean
}
```

`deliver` 立即送出完整的通知訊號。`queue` 與 `defer` 讓紀錄維持待處理，留待稍後派送。`summarize` 送出摘要或安排稍後送出。`persist` 只儲存紀錄，不送出訊號。`discard` 將紀錄標記為已捨棄，不進行傳遞。

傳遞時若喚醒閒置執行緒，就會附加 `streamOptions`。這些選項在傳遞時解析，因此即使通知經過延後或摘要處理，仍可帶有所喚醒執行緒需要的執行選項，例如模型選擇。

`hold` 只在傳遞時生效。它讓通知維持待處理，且不計為一次嘗試，以便由另一處理程序的派送器傳遞。若某處理程序共用通知儲存空間，卻無法執行目標執行緒，可使用它。首次送出通知時會忽略 `hold`。

## 傳遞原則 {/* #delivery-policies */}

透過 Agent 建構函式的 `notifications.deliveryPolicy` 選項設定原則。

```typescript
type NotificationDeliveryPolicyConfig = {
  default?: NotificationDeliveryAction | NotificationDeliveryDecision
  priorities?: Partial<
    Record<NotificationPriority, NotificationDeliveryAction | NotificationDeliveryDecision>
  >
  sources?: Record<string, NotificationDeliveryAction | NotificationDeliveryDecision>
  decide?: (
    input: NotificationDeliveryPolicyInput,
  ) =>
    | NotificationDeliveryAction
    | NotificationDeliveryDecision
    | undefined
    | Promise<NotificationDeliveryAction | NotificationDeliveryDecision | undefined>
}

type NotificationDeliveryPolicyInput = {
  record: NotificationRecord
  threadState: 'active' | 'idle'
  now: Date
}
```

Mastra 按以下順序評估該政策：

1. `decide`
1. `sources`：與 `record.source` 比對
1. `priorities`：與 `record.priority` 比對
4. `default`
1. 內建優先順序原則

內建策略是：

| 優先順序 | 閒置執行緒 | 執行中的執行緒 |
| - | - | - |
| `urgent` | 立即傳遞 | 立即傳遞 |
| `high` | 立即傳遞 | 立即送出摘要，待執行緒閒置後再傳遞 |
| `medium` | 立即傳遞 | 批次彙整成摘要 |
| `low` | 批次彙整成摘要 | 批次彙整成摘要 |

自訂 `decide` 函式會在收到通知時執行；若當時的決策是延後傳遞或安排摘要，傳遞時還會再次執行。紀錄中持久儲存的排程決定傳遞的時間與方式。傳遞時的決策只採用 `streamOptions` 與 `hold`。請確保決策函式沒有副作用。

## 已傳遞訊號的中繼資料 {/* #delivered-signal-metadata */}

紀錄傳遞後，串流接收端會收到帶有 `NotificationSignalMetadata` 的通知訊號。

```typescript
type NotificationSignalMetadata = {
  signal: 'notification'
  recordId: string
  source: string
  kind: string
  priority: NotificationPriority
  status: NotificationStatus
  coalescedCount?: number
  deliveredAt?: string
  seenAt?: string
}
```

Mastra 送出摘要時，接收端會收到帶有 `NotificationSummarySignalMetadata` 的摘要訊號。

```typescript
type NotificationSummarySignalMetadata = {
  signal: 'summary'
  pending: number
  groups: Array<{ source: string; count: number }>
  byPriority: Partial<Record<NotificationPriority, number>>
  notificationIds: string[]
  priority?: NotificationPriority
}
```

這些中繼資料結構描述的是訊號。已儲存的紀錄不是訊號，訊號也不包含紀錄的 `payload` 或重試歷程。

## 儲存 {/* #storage */}

通知紀錄需要支援 `notifications` 的儲存網域，例如 libSQL、PostgreSQL 或 MongoDB。否則，`sendNotificationSignal()` 無法儲存紀錄。

`sendSignal({ type: 'notification' })` 會略過收件匣儲存空間，直接傳遞通知形式的脈絡。若要讓 Agent 讀取與管理已儲存的紀錄，請使用 [`createNotificationInboxTool()`](/reference/signals/create-notification-inbox-tool)。
