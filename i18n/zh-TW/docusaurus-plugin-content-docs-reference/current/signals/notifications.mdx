# 通知

通知收件匣記錄是由以下方式儲存的持久狀態`agent.sendNotificationSignal()`。它與傳遞給線程的通知信號不是同一物件。此記錄追蹤路由、優先順序、傳送狀態、重複資料刪除和重試歷史記錄。該訊號在其元資料中攜帶該記錄的摘要和快照。

使用[`Agent.sendNotificationSignal()`](/reference/agents/agent#sendnotificationsignalnotification-options) to create records and the [Notifications guide](/docs/signals/notifications)為輸送流量。

## 合併待處理記錄 {/* #coalescing-pending-records */}

`sendNotificationSignal()`可以將新通知合併到現有待處理記錄中，而不是建立另一條通知。合併僅考慮同一執行緒、來源、種類、Agent和資源上的記錄。

每個鍵都有不同的用途：

* `dedupeKey`標識同一事件。當重試或重複的 Webhook 應更新現有記錄時重複使用它。
* `coalesceKey`組相關事件。當多個事件應成為一筆記錄時使用它，例如同一管道中的多個故障。

儘管用途不同，兩個密鑰都使用相同的匹配規則。

當通知合併時：

* 最新的`summary` and `payload` replace the previous values.
* `priority`當新通知提供時更新。
* `attributes`和`metadata` merge, with the new values taking precedence.
* `coalescedCount`增量。

## 優先事項和狀態 {/* #priorities-and-statuses */}

`NotificationPriority`控制預設交付時間。

```typescript
type NotificationPriority = 'low' | 'medium' | 'high' | 'urgent'
```

`NotificationStatus`是記錄的生命週期。

```typescript
type NotificationStatus =
  | 'pending'
  | 'delivered'
  | 'seen'
  | 'dismissed'
  | 'archived'
  | 'discarded'
  | 'failed'
```

`pending`記錄符合發送條件。`delivered` means a full notification signal was emitted. `seen`, `dismissed`, and `archived` are inbox states. `discarded` means the delivery policy rejected the notification. `failed` means delivery reached the five-attempt cap.

## 交付決策 {/* #delivery-decisions */}

交付政策返回`NotificationDeliveryDecision`.

```typescript
type NotificationDeliveryAction =
  | 'deliver'
  | 'queue'
  | 'defer'
  | 'summarize'
  | 'persist'
  | 'discard'

type NotificationDeliveryDecision = {
  action: NotificationDeliveryAction
  deliverAt?: Date
  summaryAt?: Date
  reason?: string
  streamOptions?: AgentExecutionOptions<unknown>
  hold?: boolean
}
```

`deliver`立即發出完整的通知訊號。`queue` and `defer` leave the record pending for later dispatch. `summarize` emits or schedules a summary. `persist` stores the record without emitting a signal. `discard` marks the record discarded without delivering it.

`streamOptions`當傳遞喚醒空閒執行緒時附加。它們在交付時得到解決，因此延遲或匯總通知仍然可以攜帶喚醒執行緒所需的執行選項，例如模型選擇。

`hold`僅適用於交貨時。它使通知處於掛起狀態，而不計算嘗試次數，以便另一個進程的調度程序可以傳遞它。當進程共享通知儲存但無法運行目標執行緒時使用它。`hold` is ignored when the notification is first sent.

## 配送政策 {/* #delivery-policies */}

透過Agent建構函數配置策略`notifications.deliveryPolicy` option.

```typescript
type NotificationDeliveryPolicyConfig = {
  default?: NotificationDeliveryAction | NotificationDeliveryDecision
  priorities?: Partial<
    Record<NotificationPriority, NotificationDeliveryAction | NotificationDeliveryDecision>
  >
  sources?: Record<string, NotificationDeliveryAction | NotificationDeliveryDecision>
  decide?: (
    input: NotificationDeliveryPolicyInput,
  ) =>
    | NotificationDeliveryAction
    | NotificationDeliveryDecision
    | undefined
    | Promise<NotificationDeliveryAction | NotificationDeliveryDecision | undefined>
}

type NotificationDeliveryPolicyInput = {
  record: NotificationRecord
  threadState: 'active' | 'idle'
  now: Date
}
```

Mastra 按以下順序評估該政策：

1. `decide`
2. `sources`, 匹配`record.source`
3. `priorities`, 匹配`record.priority`
4. `default`
5. 內建優先權策略

內建策略是：

|優先|空閒執行緒|活動執行緒 |
| - | - | - |
|`urgent` | Deliver immediately | Deliver immediately |
| `high` | Deliver immediately | Emit a summary immediately, then deliver later when the thread is idle |
| `medium` | Deliver immediately | Batch into a summary |
| `low` | Batch into a summary | Batch into a summary |

客製化`decide` function runs at receipt time and again at delivery time for records whose receipt-time decision deferred them or scheduled a summary. The record's persisted schedule fixes when and how it delivers. Only `streamOptions` and `hold` from the delivery-time decision are honored. Keep the decider side-effect free.

## 傳遞的信號元數據 {/* #delivered-signal-metadata */}

當記錄交付時，流消費者會收到一個通知訊號`NotificationSignalMetadata`.

```typescript
type NotificationSignalMetadata = {
  signal: 'notification'
  recordId: string
  source: string
  kind: string
  priority: NotificationPriority
  status: NotificationStatus
  coalescedCount?: number
  deliveredAt?: string
  seenAt?: string
}
```

當 Mastra 發出摘要時，消費者會收到一個摘要訊號`NotificationSummarySignalMetadata`.

```typescript
type NotificationSummarySignalMetadata = {
  signal: 'summary'
  pending: number
  groups: Array<{ source: string; count: number }>
  byPriority: Partial<Record<NotificationPriority, number>>
  notificationIds: string[]
  priority?: NotificationPriority
}
```

這些元資料形狀描述了訊號。儲存的記錄不是訊號，且訊號不包括記錄的`payload` or retry history.

## 儲存 {/* #storage */}

通知記錄需要支援的儲存域`notifications`, such as libSQL, PostgreSQL, or MongoDB. Without it, `sendNotificationSignal()` can't store records.

`sendSignal({ type: 'notification' })`繞過收件匣儲存並直接傳遞通知形狀的上下文。使用[`createNotificationInboxTool()`](/reference/signals/create-notification-inbox-tool) to read and manage stored records from an agent.
