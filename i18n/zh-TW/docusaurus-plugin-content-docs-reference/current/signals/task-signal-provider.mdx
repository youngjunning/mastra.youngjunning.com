# TaskSignalProvider

**新增於：** `@mastra/core@1.42.0`

只需註冊一次 Agent，即可整合內建任務 Tool（`task_write`、`task_update`、`task_complete`、`task_check`）與 `TaskStateProcessor`。藉此可為 Agent 加入結構化、可持久保存的任務清單，無須個別設定 Tool 和處理器。

它擴充了 [`SignalProvider`](/reference/signals/signal-provider)。任務清單以 `task` 狀態類型儲存於對話串範圍的 `threadState` 儲存領域，作為權威資料來源；處理器再將其投射到 Agent 的 `tasks` 狀態訊號通道。因此，即使觀察式記憶遭截斷，任務清單仍會保留，也不會使提示快取失效。

## 使用範例 {/* #usage-example */}

在已設定 `Memory` 與 Mastra `storage` 的 Agent 上註冊此 Provider：

```typescript title="src/mastra/index.ts"
import { Agent } from '@mastra/core/agent'
import { TaskSignalProvider } from '@mastra/core/signals'

const agent = new Agent({
  id: 'coder',
  name: 'coder',
  instructions: '...',
  model,
  memory,
  signals: [new TaskSignalProvider()],
})
```

Agent 會自動將四個任務 Tool 加入工具組，並將處理器註冊到輸入處理器鏈，無須額外設定。

任務追蹤需要由 Memory 支援的對話串（`threadId` + `resourceId`）。若未設定 Memory，任務 Tool 不會執行操作，並會回傳說明任務追蹤需要 Agent Memory 的結果。`threadState` 儲存領域預設使用記憶體實作，因此不設定儲存後端也能追蹤任務。

## 方法 {/* #methods */}

### 與 Agent 整合 {/* #agent-integration */}

將 Provider 傳入 `signals` 後，Agent 會自動呼叫這些方法，通常不需要手動呼叫。

#### `getTools()` {/* #gettools */}

回傳以 Tool ID（`task_write`、`task_update`、`task_complete`、`task_check`）為鍵的四個任務 Tool。Agent 會將它們加入工具組。

```typescript
const tools = new TaskSignalProvider().getTools()
// { task_write, task_update, task_complete, task_check }
```

回傳： `Record<string, Tool>`

#### `getInputProcessors()` {/* #getinputprocessors */}

回傳 Provider 的 `TaskStateProcessor` 實例。Agent 會將它註冊到輸入處理器鏈，並沿鏈傳遞 Mastra 實例，讓處理器能解析 `threadState` 儲存區。

```typescript
const [processor] = new TaskSignalProvider().getInputProcessors()
// processor instanceof TaskStateProcessor
```

回傳： `InputProcessorOrWorkflow[]`
