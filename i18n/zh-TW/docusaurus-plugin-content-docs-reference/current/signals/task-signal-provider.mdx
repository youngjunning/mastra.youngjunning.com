# 任務訊號Provider

**添加於：** `@mastra/core@1.42.0`

捆綁內建任務Tool（`task_write`, `task_update`, `task_complete`, `task_check`）和`TaskStateProcessor`單一Agent註冊背後。使用它可以向Agent添加結構化、持久的任務列表，而無需單獨連接Tool和處理器。

延伸[`SignalProvider`](/reference/signals/signal-provider). The task list is stored under the `task` state type in the thread-scoped `threadState` storage domain, which is the source of truth, and projected onto the `tasks` agent state-signal lane by the processor, so it survives observational-memory truncation without invalidating the prompt cache.

## 使用範例 {/* #usage-example */}

在Agent上註冊Provider`Memory` and a Mastra `storage`:

```typescript title="src/mastra/index.ts"
import { Agent } from '@mastra/core/agent'
import { TaskSignalProvider } from '@mastra/core/signals'

const agent = new Agent({
  id: 'coder',
  name: 'coder',
  instructions: '...',
  model,
  memory,
  signals: [new TaskSignalProvider()],
})
```

Agent程式會自動將四個任務Tool合併到其Tool集中，並將處理器註冊到其輸入處理器鏈上。無需其他接線。

任務追蹤需要記憶體支援的線程（`threadId` + `resourceId`). Without memory the task tools no-op and return a result explaining that task tracking requires agent memory. The `threadState` storage domain is wired in-memory by default, so task tracking works without configuring a storage backend.

## 方法 {/* #methods */}

### Agent整合 {/* #agent-integration */}

當Provider傳遞給Agent程式時，Agent會自動呼叫這些方法`signals`, so you normally don't call them directly.

#### `getTools()` {/* #gettools */}

傳回由Tool ID 鍵入的四個任務Tool（`task_write`, `task_update`, `task_complete`, `task_check`). The Agent merges these into its toolset.

```typescript
const tools = new TaskSignalProvider().getTools()
// { task_write, task_update, task_complete, task_check }
```

返回：`Record<string, Tool>`

#### `getInputProcessors()` {/* #getinputprocessors */}

返回Provider的`TaskStateProcessor` instance. The Agent registers it on the input-processor chain, which propagates the Mastra instance so the processor can resolve the `threadState` store.

```typescript
const [processor] = new TaskSignalProvider().getInputProcessors()
// processor instanceof TaskStateProcessor
```

返回：`InputProcessorOrWorkflow[]`
