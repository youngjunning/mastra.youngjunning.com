# 自動指標參考

Mastra 會自動從追蹤的執行中提取效能和使用指標。此頁面是 Mastra 發出的每個指標名稱、標籤和上下文欄位的完整參考。

有關設定說明，請參閱[Metrics overview](/docs/observability/metrics/overview).

## 當 Mastra 發出自動指標時 {/* #when-mastra-emits-automatic-metrics */}

當跨度結束時，會從跨度中提取指標。可觀察性層檢查每個已完成的跨度，計算持續時間，並從模型生成和分類器評估跨度中讀取令牌使用資料。無需手動儀器。

### 影響指標是否可用的因素有哪些 {/* #what-affects-whether-a-metric-is-available */}

指標在以下情況下到達儲存：

1. `MastraStorageExporter`被配置為導出器。
2. 儲存後端支援指標（ClickHouse、DuckDB 或啟用可觀察網域的 Postgres v-next）。

如果指標不可用，請參閱[troubleshooting](#troubleshooting).

## 持續時間指標 {/* #duration-metrics */}

持續時間指標記錄執行時間（以毫秒為單位），根據跨度的開始和結束時間戳記計算。每個持續時間指標包括`status` label set to `ok` or `error`, derived from the span's status.

|指標名稱 |跨度類型|描述 |
| - | - | - |
|`mastra_agent_duration_ms` | `AGENT_RUN` | Execution time of an agent run |
| `mastra_tool_duration_ms` | `TOOL_CALL`, `MCP_TOOL_CALL`, `PROVIDER_TOOL_CALL` | Execution time of a tool call, including MCP and provider-executed tool calls |
| `mastra_workflow_duration_ms` | `WORKFLOW_RUN`|Workflow運作的執行時間 |
|`mastra_model_duration_ms` | `MODEL_GENERATION`|模型產生的執行時間 |
|`mastra_processor_duration_ms` | `PROCESSOR_RUN`|處理器運作的執行時間 |

## 代幣使用指標 {/* #token-usage-metrics */}

令牌指標是從發出的`MODEL_GENERATION` and `CLASSIFIER_EVALUATION` spans that include `usage` data. Token metrics require usage data from the provider.

### 輸入令牌指標 {/* #input-token-metrics */}

|指標名稱 |說明 |
| - | - |
|`mastra_model_total_input_tokens` | Total input tokens |
| `mastra_model_input_text_tokens` | Text tokens in the input prompt |
| `mastra_model_input_cache_read_tokens` | Tokens read from prompt cache (e.g. Anthropic) |
| `mastra_model_input_cache_write_tokens` | Tokens written to prompt cache |
| `mastra_model_input_cache_write_5m_tokens` | Tokens written to prompt cache with a 5-minute TTL (e.g. Anthropic) |
| `mastra_model_input_cache_write_1h_tokens` | Tokens written to prompt cache with a 1-hour TTL (e.g. Anthropic) |
| `mastra_model_input_audio_tokens` | Audio tokens in the input (multimodal models) |
| `mastra_model_input_image_tokens` | Image tokens in the input (vision models) |

### 輸出代幣指標 {/* #output-token-metrics */}

|指標名稱 |說明 |
| - | - |
|`mastra_model_total_output_tokens` | Total output tokens |
| `mastra_model_output_text_tokens` | Text tokens in the model's output |
| `mastra_model_output_reasoning_tokens` | Reasoning / chain-of-thought tokens (e.g. OpenAI o-series) |
| `mastra_model_output_audio_tokens` | Audio tokens in the model's output |
| `mastra_model_output_image_tokens` | Output image tokens |

### Provider報告的詳細代幣類別 {/* #provider-reported-detailed-token-categories */}

詳細的細分指標（除了`total_input` and `total_output`) are only emitted when the provider reports them. If a category has zero tokens, the metric is skipped for that span. Different providers report different levels of detail. For example, not all providers report cache or audio tokens.

## 成本相關背景 {/* #cost-related-context */}

### 當附加成本上下文時 {/* #when-cost-context-is-attached */}

當Provider報告每個已完成的模型步驟的有效成本或當定價註冊表具有Provider和模型的匹配條目時，成本上下文會附加到令牌度量。 Mastra 將每一步Provider的成本匯總到一個查詢總計。如果任何已完成的步驟缺少有效的報告成本，Mastra 將使用定價註冊表而不是報告部分總計。如果兩個來源都不可用，則仍會發出不帶成本欄位的令牌指標。

來電者提供的`costContext` takes precedence over provider-reported costs and pricing registry estimates. Provider-reported totals use `costMetadata.source: 'provider_reported'`, `costMetadata.scope: 'query_total'`, and `costMetadata.reportedStepCount` to identify the source, scope, and number of completed steps included in the total.

### 價格從何來 {/* #where-prices-come-from */}

定價登記處使用的模型價格來自[models.dev](https://models.dev). `@mastra/observability` includes a snapshot of these prices, and each new release of the package includes recent prices. Stored cost estimates aren't recalculated when prices change. A [custom gateway](/models/gateways/custom-gateways#model-pricing) can return its own `pricing` for models that models.dev doesn't list. These prices only fill in models that models.dev doesn't price.

當你跑步時`mastra dev`, Mastra also refreshes prices from models.dev in the background once a day, and when a model has no price. Cost estimates don't wait for a refresh, so the first call to a newly released model can still have no cost. In other environments, such as production, you can turn on the refresh with `MASTRA_AUTO_REFRESH_PRICING=true`.

刷新的價格緩存在`~/.cache/mastra/pricing-data.json` and reused by later processes. If a refresh fails, Mastra keeps the prices it already has.

若要僅使用捆綁快照，請設定`MASTRA_AUTO_REFRESH_PRICING=false`. Setting `MASTRA_OFFLINE=true` also turns off the refresh.

### 可能包括哪些成本字段 {/* #what-cost-fields-may-be-included */}

|領域 |描述 |
| - | - |
|`provider` | Provider name (e.g. `openai`, `anthropic`) |
| `model` | Model identifier (e.g. `gpt-4o`, `claude-sonnet-4-20250514`) |
| `estimatedCost` | Estimated cost from token count and pricing tier, or a total reported by the provider |
| `costUnit` | Currency unit (e.g. `USD`) |
| `costMetadata` | Additional pricing context, including tier information, error details, and provider-reported cost source and scope |

## 與跡線的相關性 {/* #correlation-with-traces */}

### 指標如何與跨度和追蹤上下文相關 {/* #how-metrics-relate-to-spans-and-trace-context */}

每個指標都帶有一個`CorrelationContext` snapshot from the span that produced it. This context is stored alongside the metric value and links a metric to the exact span and trace.

相關欄位使用以下類別：

**跡線相關性**

* `traceId`：追蹤標識符
* `spanId`: 跨度標識符
* `tags`：來自跨度的標籤

**實體層次結構**

* `entityType`, `entityId`, `entityName`: The entity that produced the metric (e.g. agent, workflow)
* `parentEntityType`, `parentEntityId`, `parentEntityName`: The parent entity
* `rootEntityType`, `rootEntityId`, `rootEntityName`: The root entity in the call chain

**身分**

* `userId`, `organizationId`, `resourceId`: Identity context from the request
* `runId`, `sessionId`, `threadId`, `requestId`: Correlation IDs

**部署**

* `environment`：部署環境（例如`production`, `staging`)
* `source`: 來源標識符
* `serviceName`：可觀察性配置中的服務名稱
* `experimentId`：實驗標識符（如果適用）

### 為什麼關聯有助於調試 {/* #why-correlation-helps-with-debugging */}

當您在指標儀表板上發現延遲或令牌使用量激增時，關聯上下文可讓您直接鑽取產生指標的追蹤。從那裡您可以檢查各個跨度。根本原因可能是Tool呼叫緩慢或提示較大。這也可能是意外錯誤。

## 故障排除 {/* #troubleshooting */}

### 沒有可用的指標 {/* #no-metrics-are-available */}

* **可觀察性已配置**: 驗證您的`Mastra` instance has an `observability` config with at least one exporter.
* **`MastraStorageExporter`或者`MastraPlatformExporter` is present**：其他匯出器（Datadog、Langfuse 等）不在 Mastra 中顯示指標。`MastraStorageExporter` is required for the local Studio dashboard, and `MastraPlatformExporter` is required to view metrics in Mastra platform.
* **儲存支援指標**：指標需要具有分析功能的儲存（ClickHouse、DuckDB 或啟用了可觀察域的 Postgres v-next）。指標不支援其他面向行的資料庫（LibSQL、MSSQL）和文件儲存（MongoDB）。
* **抽樣不是0%**：如果採樣機率為`0` or strategy is `never`, all spans become no-ops and no metrics are extracted.

### 缺少持續時間指標 {/* #duration-metrics-are-missing */}

* **Span 有時間戳**：持續時間的計算方式為`startTime` and `endTime`. If either is missing, the metric is skipped.
* **Span 類型映射到度量**： 僅有的`AGENT_RUN`, `TOOL_CALL`, `MCP_TOOL_CALL`, `PROVIDER_TOOL_CALL`, `WORKFLOW_RUN`, `MODEL_GENERATION`, and `PROCESSOR_RUN` spans produce duration metrics.

### 缺少令牌指標 {/* #token-metrics-are-missing */}

* **Span是模型生成或分類器評估**：令牌指標僅從以下位置發出`MODEL_GENERATION` and `CLASSIFIER_EVALUATION` spans.
* **Provider報告使用情況**：模型Provider必須包含`usage` data in its response. Usage data is required to emit token metrics.
