# 自動指標參考

Mastra 會自動從受追蹤的執行過程擷取效能與使用量指標。本頁完整列出 Mastra 產生的指標名稱、標籤及情境欄位。

設定方式請參閱[指標總覽](/docs/observability/metrics/overview)。

## Mastra 何時產生自動指標 {/* #when-mastra-emits-automatic-metrics */}

Span 結束時，Mastra 會從中擷取指標。可觀測性層會檢查每個已完成的 Span、計算持續時間，並從模型生成及分類器評估 Span 讀取 token 使用量資料。無須手動埋點。

### 哪些因素會影響指標是否可用 {/* #what-affects-whether-a-metric-is-available */}

符合以下條件時，指標便會寫入儲存空間：

1. 已將 `MastraStorageExporter` 設定為匯出器。
2. 儲存後端支援指標（ClickHouse、DuckDB，或已啟用可觀測性領域的 Postgres v-next）。

若無法取得指標，請參閱[疑難排解](#troubleshooting)。

## 持續時間指標 {/* #duration-metrics */}

持續時間指標依 Span 的開始與結束時間戳記計算執行時間，單位為毫秒。每項指標都包含 `status` 標籤，值會依 Span 狀態設為 `ok` 或 `error`。

|指標名稱 |Span 類型|說明 |
| - | - | - |
|`mastra_agent_duration_ms` | `AGENT_RUN` | Agent 執行時間 |
| `mastra_tool_duration_ms` | `TOOL_CALL`, `MCP_TOOL_CALL`, `PROVIDER_TOOL_CALL` | Tool 呼叫的執行時間，包括 MCP Tool 呼叫與由 Provider 執行的 Tool 呼叫 |
| `mastra_workflow_duration_ms` | `WORKFLOW_RUN`|Workflow 執行時間 |
|`mastra_model_duration_ms` | `MODEL_GENERATION`|模型生成的執行時間 |
|`mastra_processor_duration_ms` | `PROCESSOR_RUN`|處理器執行時間 |

## Token 使用量指標 {/* #token-usage-metrics */}

Mastra 只會從含有 `usage` 資料的 `MODEL_GENERATION` 與 `CLASSIFIER_EVALUATION` Span 產生 token 指標。這些指標必須有 Provider 提供的使用量資料。

### 輸入 token 指標 {/* #input-token-metrics */}

|指標名稱 |說明 |
| - | - |
|`mastra_model_total_input_tokens` | 輸入 token 總數 |
| `mastra_model_input_text_tokens` | 輸入提示詞中的文字 token 數 |
| `mastra_model_input_cache_read_tokens` | 從提示詞快取讀取的 token 數（例如 Anthropic） |
| `mastra_model_input_cache_write_tokens` | 寫入提示詞快取的 token 數 |
| `mastra_model_input_cache_write_5m_tokens` | 寫入提示詞快取、存活時間為 5 分鐘的 token 數（例如 Anthropic） |
| `mastra_model_input_cache_write_1h_tokens` | 寫入提示詞快取、存活時間為 1 小時的 token 數（例如 Anthropic） |
| `mastra_model_input_audio_tokens` | 輸入中的音訊 token 數（多模態模型） |
| `mastra_model_input_image_tokens` | 輸入中的影像 token 數（視覺模型） |

### 輸出 token 指標 {/* #output-token-metrics */}

|指標名稱 |說明 |
| - | - |
|`mastra_model_total_output_tokens` | 輸出 token 總數 |
| `mastra_model_output_text_tokens` | 模型輸出中的文字 token 數 |
| `mastra_model_output_reasoning_tokens` | 推理或思維鏈 token 數（例如 OpenAI o 系列） |
| `mastra_model_output_audio_tokens` | 模型輸出中的音訊 token 數 |
| `mastra_model_output_image_tokens` | 輸出的影像 token 數 |

### Provider 回報的詳細 token 類別 {/* #provider-reported-detailed-token-categories */}

除了 `total_input` 與 `total_output`，只有 Provider 回報了相應資料，Mastra 才會產生細項指標。若某類別的 token 數為零，該 Span 就不會產生對應指標。各 Provider 回報的詳細程度不同，例如並非所有 Provider 都會回報快取或音訊 token 數。

## 成本相關情境資訊 {/* #cost-related-context */}

### 何時附加成本資訊 {/* #when-cost-context-is-attached */}

若 Provider 為每個已完成的模型步驟回報有效成本，或價格登錄表中有相符的 Provider 與模型價格，Mastra 就會在 token 指標中附加成本資訊。Mastra 會加總 Provider 回報的各步驟成本，得出整筆查詢的總成本。若任何已完成步驟缺少有效的成本資料，Mastra 會改用價格登錄表，而不會回報不完整的總成本。若兩種來源都不可用，Mastra 仍會產生 token 指標，但不包含成本欄位。

呼叫端提供的 `costContext` 優先於 Provider 回報的成本及價格登錄表的估算值。對於 Provider 回報的總成本，`costMetadata.source: 'provider_reported'`、`costMetadata.scope: 'query_total'` 與 `costMetadata.reportedStepCount` 分別標示來源、統計範圍，以及計入總成本的已完成步驟數。

### 價格資料來源 {/* #where-prices-come-from */}

價格登錄表採用 [models.dev](https://models.dev) 的模型價格。`@mastra/observability` 內含這些價格的快照，每次發行新版本時都會納入近期價格。價格變動後，已儲存的成本估算值不會重新計算。[自訂閘道](/models/gateways/custom-gateways#model-pricing)可為 models.dev 未列出的模型回傳自己的 `pricing`；這些價格只會補足 models.dev 未提供價格的模型。

執行 `mastra dev` 時，Mastra 也會每天在背景從 models.dev 更新一次價格，遇到沒有價格的模型時亦會更新。成本估算不會等待更新，因此首次呼叫新發行的模型時，仍可能沒有成本資料。在正式環境等其他環境中，可設定 `MASTRA_AUTO_REFRESH_PRICING=true` 以啟用更新。

更新後的價格會快取於 `~/.cache/mastra/pricing-data.json`，供後續處理程序重複使用。若更新失敗，Mastra 會保留現有價格。

若只要使用套件內附的快照，請設定 `MASTRA_AUTO_REFRESH_PRICING=false`。設定 `MASTRA_OFFLINE=true` 也會停用更新。

### 可能包含的成本欄位 {/* #what-cost-fields-may-be-included */}

|欄位 |說明 |
| - | - |
|`provider` | Provider 名稱（例如 `openai`、`anthropic`） |
| `model` | 模型識別碼（例如 `gpt-4o`、`claude-sonnet-4-20250514`） |
| `estimatedCost` | 依 token 數及價格級距估算的成本，或 Provider 回報的總成本 |
| `costUnit` | 貨幣單位（例如 `USD`） |
| `costMetadata` | 額外價格資訊，包括級距資訊、錯誤詳情，以及 Provider 回報的成本來源與統計範圍 |

## 與 Trace 的關聯 {/* #correlation-with-traces */}

### 指標如何關聯 Span 與 Trace 情境資訊 {/* #how-metrics-relate-to-spans-and-trace-context */}

每項指標都帶有產生該指標的 Span 所提供的 `CorrelationContext` 快照。此資訊會與指標值一同儲存，讓指標能精確對應到所屬 Span 與 Trace。

關聯欄位分為以下類別：

**Trace 關聯**

* `traceId`：Trace 識別碼
* `spanId`: Span 識別碼
* `tags`：Span 的標籤

**實體層次結構**

* `entityType`, `entityId`, `entityName`: 產生指標的實體（例如 Agent、Workflow）
* `parentEntityType`, `parentEntityId`, `parentEntityName`: 父實體
* `rootEntityType`, `rootEntityId`, `rootEntityName`: 呼叫鏈中的根實體

**身分**

* `userId`, `organizationId`, `resourceId`: 請求中的身分資訊
* `runId`, `sessionId`, `threadId`, `requestId`: 關聯 ID

**部署**

* `environment`：部署環境（例如 `production`、`staging`）
* `source`: 來源識別碼
* `serviceName`：可觀測性設定中的服務名稱
* `experimentId`：實驗識別碼（若適用）

### 關聯資訊如何協助除錯 {/* #why-correlation-helps-with-debugging */}

在指標儀表板看到延遲或 token 使用量突然攀升時，可透過關聯資訊直接檢視產生該指標的 Trace，再查看其中的個別 Span。根本原因可能是 Tool 呼叫緩慢、提示詞過長，也可能是意外錯誤。

## 故障排除 {/* #troubleshooting */}

### 沒有可用的指標 {/* #no-metrics-are-available */}

* **已設定可觀測性**: 確認 `Mastra` 執行個體已設定 `observability`，且至少有一個匯出器。
* **包含 `MastraStorageExporter` 或 `MastraPlatformExporter`**：Datadog、Langfuse 等其他匯出器不會在 Mastra 中顯示指標。本機 Studio 儀表板需要 `MastraStorageExporter`；若要在 Mastra 平台查看指標，則需要 `MastraPlatformExporter`。
* **儲存空間支援指標**：指標需要具備分析功能的儲存後端（ClickHouse、DuckDB，或已啟用可觀測性領域的 Postgres v-next）。其他以資料列為導向的資料庫（LibSQL、MSSQL）及文件型儲存（MongoDB）不支援指標。
* **取樣率不為 0%**：若取樣機率為 `0` 或策略為 `never`，所有 Span 都會成為空操作，因此不會擷取任何指標。

### 缺少持續時間指標 {/* #duration-metrics-are-missing */}

* **Span 有時間戳記**：持續時間依 `startTime` 與 `endTime` 計算。若缺少其中一個時間戳記，就會略過該指標。
* **Span 類型對應持續時間指標**：只有 `AGENT_RUN`、`TOOL_CALL`、`MCP_TOOL_CALL`、`PROVIDER_TOOL_CALL`、`WORKFLOW_RUN`、`MODEL_GENERATION` 與 `PROCESSOR_RUN` Span 會產生持續時間指標。

### 缺少 token 指標 {/* #token-metrics-are-missing */}

* **Span 是模型生成或分類器評估**：只有 `MODEL_GENERATION` 與 `CLASSIFIER_EVALUATION` Span 會產生 token 指標。
* **Provider 回報使用量**：模型 Provider 必須在回應中包含 `usage` 資料，系統才能產生 token 指標。
