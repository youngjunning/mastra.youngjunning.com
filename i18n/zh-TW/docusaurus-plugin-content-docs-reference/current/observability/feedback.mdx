# 回饋

**加入版本：** `@mastra/core@1.18.0`

回饋 API 儲存及查詢評分、按讚或倒讚、留言與修正等人工回饋可觀測性訊號。用法請參閱[回饋指南](/docs/observability/feedback)。

## 使用範例 {/* #usage-example */}

以下範例透過可觀測性入口，為已持久儲存的 trace 記錄評分。入口的 `addFeedback()` 是選用方法，呼叫前請確認目前的可觀測性實作是否支援。

```typescript
if (!mastra.observability.addFeedback) {
  throw new Error('Feedback is not supported by the active observability implementation')
}

await mastra.observability.addFeedback({
  traceId: 'trace-123',
  spanId: 'span-456',
  feedback: {
    feedbackSource: 'user',
    feedbackType: 'rating',
    value: 1,
    comment: 'Helpful answer.',
  },
})
```

## 創建回饋 {/* #create-feedback */}

### `addFeedback(args)` {/* #addfeedbackargs */}

向已設定的 Exporter 傳送針對 trace 或 span 的回饋。

```typescript
await mastra.observability.addFeedback?.({
  traceId: 'trace-123',
  spanId: 'span-456',
  feedback: {
    feedbackSource: 'user',
    feedbackType: 'rating',
    value: 1,
    comment: 'Helpful answer.',
  },
})
```

未提供 `correlationContext` 時，各 Exporter 會在自己的目的地處理對應的 trace 或 span。`MastraStorageExporter` 從本機儲存空間解析目標；本機查詢失敗不會阻止其他 Exporter。`MastraPlatformExporter` 不需要本機儲存空間。使用 `flush()` 或 `shutdown()` 等待待傳送資料處理完畢。

本機查詢必須取得目標 span 向上直到根 span 的完整父鏈，回饋才能繼承正確的根標籤。若重試後仍缺少任何祖先 span，儲存 Exporter 會記錄警告並略過本機寫入；其他 Exporter 仍會收到回饋。

### `createFeedback(args)` {/* #createfeedbackargs */}

透過可觀測性儲存領域建立一筆回饋紀錄。儲存層呼叫會直接寫入儲存空間，因此必須包含 `timestamp`。

```typescript
await observability.createFeedback({
  feedback: {
    feedbackId: 'feedback-1',
    timestamp: new Date(),
    traceId: 'trace-123',
    spanId: 'span-456',
    feedbackSource: 'user',
    feedbackType: 'rating',
    value: 1,
    comment: 'Helpful answer.',
  },
})
```

HTTP 與用戶端 SDK 的建立路由接受 `CreateFeedbackBody`，其中 `feedback.traceId` 必須為非空白字串，`spanId` 為選用。用戶端會在重試前補上缺少的 `feedbackId` 與 ISO 格式的 `timestamp`；直接呼叫 OSS HTTP 時可以省略，使用伺服器預設值。選用的頂層 `contextMode` 可選擇使用提供的上下文，或解析已儲存的 span；OSS 預設為 `"provided"`，Platform 預設為 `"resolve"`。請參閱[訊號寫入選項](/reference/client-js/observability#signal-write-options)：

```typescript
await mastraClient.createFeedback({
  feedback: {
    traceId: 'trace-123',
    spanId: 'span-456',
    feedbackSource: 'user',
    feedbackType: 'rating',
    value: 1,
  },
})
```

對 OSS HTTP 請求，已驗證使用者的 ID 會優先作為 `feedbackUserId`。沒有已驗證使用者時，請明確提供 `feedbackUserId`，或保留為 null 以提交匿名回饋。`userId` 表示 span 使用者，不作為 HTTP 回饋作者。直接呼叫儲存空間時，若省略 `feedbackUserId`，仍可使用已棄用的 `userId` 作者別名；明確設為 null 的作者會維持 null。

### `batchCreateFeedback(args)` {/* #batchcreatefeedbackargs */}

透過可觀測性儲存領域建立多筆回饋紀錄。HTTP 路由與 `@mastra/client-js` 均不提供此方法。

```typescript
await observability.batchCreateFeedback({
  feedbacks: [
    {
      feedbackId: 'feedback-1',
      timestamp: new Date(),
      traceId: 'trace-123',
      feedbackSource: 'user',
      feedbackType: 'rating',
      value: 1,
    },
    {
      feedbackId: 'feedback-2',
      timestamp: new Date(),
      traceId: 'trace-123',
      feedbackSource: 'qa',
      feedbackType: 'comment',
      value: 'Needs a citation before shipping.',
    },
  ],
})
```

## 刪除回饋 {/* #delete-feedback */}

### `deleteFeedback(args)` {/* #deletefeedbackargs */}

依 ID 刪除最多 1,000 筆回饋紀錄。此操作具有冪等性：不存在的 ID 會被忽略，空的 `feedbackIds` 陣列不會執行任何操作。提供 `organizationId` 或 `resourceId` 時，只會刪除符合該範圍的紀錄。

```typescript
await mastraClient.deleteFeedback({
  feedbackIds: ['feedback-1', 'feedback-2'],
})
```

  content={[
{
  name: 'feedbackIds',
  type: 'string[]',
  description: '要刪除的回饋紀錄 ID，最多接受 1,000 個。',
},
{
  name: 'organizationId',
  type: 'string',
  description: '僅刪除屬於此組織 ID 的紀錄。',
  isOptional: true,
},
{
  name: 'resourceId',
  type: 'string',
  description: '僅刪除屬於此資源 ID 的紀錄。',
  isOptional: true,
},
]}
/>

OSS HTTP 路由傳回 `{ success: boolean }`。`mastraClient.deleteFeedback()` 傳回 `Promise<{ success: boolean } | { accepted: true }>`，以支援將批次刪除排入佇列的 Platform 後端。accepted 回應表示清理已排入佇列，執行前紀錄仍可能可讀。請參閱[用戶端刪除回應處理](/reference/client-js/observability#deleting-traces)。儲存領域方法傳回 `Promise<void>`。超過 1,000 個 ID 的請求會傳回 `400`；執行低於 `1.66.0` 版 `@mastra/core` 的伺服器會傳回 `501`。ClickHouse vNext、PostgreSQL vNext、DuckDB 與記憶體內儲存空間支援刪除。其他配接器（包括 LibSQL 與 MongoDB）會擲出 `OBSERVABILITY_STORAGE_DELETE_FEEDBACK_NOT_IMPLEMENTED`。

在 ClickHouse 中，刪除操作會對主要回饋事件資料表執行輕量刪除，讓紀錄不再出現在包括 OLAP 查詢在內的讀取結果中，但不保證立即從實體儲存空間移除。因此，開源部署必須設定[可觀測性保留期限](/reference/storage/retention)，以便最終實體清除這些紀錄。每筆刪除請求成功後才標記為已套用；若失敗，請求仍為未套用狀態，不會阻止對仍可見的回饋呼叫 `updateFeedbackReviewStatus()`，可再次呼叫 `deleteFeedback()` 重試。`updateFeedbackReviewStatus()` 也會重試刪除：若重試成功，便擲出找不到紀錄的錯誤；若再次失敗，則儲存新狀態並擲出刪除錯誤。開源部署沒有背景協調程式。只有五種信號都有有限保留期限時，ClickHouse 才會為刪除請求設定 TTL。請參閱 [ClickHouse 原生 TTL](/reference/storage/retention#clickhouse-native-ttl)。刪除 API 不會更動獨立的增量游標資料表；其中只存放識別碼，不含回饋內容，並會在兩天內到期。

### `deleteScores(args)` {/* #deletescoresargs */}

依 ID 刪除最多 1,000 筆評分紀錄。行為與 `deleteFeedback()` 相同，但以 `scoreIds` 取代 `feedbackIds`；Oracle Database 也支援此操作。不支援的配接器會擲出 `OBSERVABILITY_STORAGE_DELETE_SCORES_NOT_IMPLEMENTED`。

```typescript
await mastraClient.deleteScores({
  scoreIds: ['score-1', 'score-2'],
})
```

  feedbackType: 'rating',
  groupBy: ['entityName'],
  aggregation: 'avg',

依時間間隔分桶傳回回饋值。

```typescript

  feedbackType: 'rating',
  interval: '1h',
  aggregation: 'avg',
  groupBy: ['feedbackSource'],
})
```

```typescript
const response = await mastraClient.getFeedbackPercentiles({
  feedbackType: 'rating',
  percentiles: [0.5, 0.95],
  interval: '1d',
})
```

## 替換回饋 {/* #replace-feedback */}

`PUT /api/observability/feedback/:feedbackId` 接受完整的 `{ feedback: { ... } }` 替換資料。保留原有的 `feedbackId`、`traceId` 與 `timestamp`，並包含所有要保留的欄位；省略的選用欄位會被清除。URL 與請求本文中的 ID 必須一致。請參閱[用戶端範例](/reference/client-js/observability#replacing-feedback)。

OSS 會先寫入已設定的儲存空間，再傳回成功，並分別通知支援此操作的 Exporter。`contextMode` 的意義與建立時相同。在 `"resolve"` 模式下，本機 trace 或 span 必須存在。若回饋紀錄不存在，會使用完整替換資料建立紀錄。變更現有紀錄的 trace 或時間戳記會傳回 `409`。

記憶體內、PostgreSQL vNext、DuckDB 與 ClickHouse vNext 儲存空間支援替換。請檢查伺服器上的 `capabilities.feedbackReplacement`；不支援的版本會傳回 `501`。依序重試原始 HTTP 建立請求不會撤銷替換。直接呼叫儲存空間的 `createFeedback()` 仍具備 upsert 行為；傳入 `onConflict: 'ignore'` 可保留現有紀錄。

ClickHouse 可沿用現有 schema，無須遷移。不同程序的並行寫入可能發生競爭，因此無法保證重疊的建立與替換操作的先後順序。使用此配接器時，請依序修改同一筆回饋紀錄。

若要向已設定的 Exporter 傳送替換事件，而不依賴本機儲存空間，請使用可觀測性入口：

```typescript
await mastra.observability.replaceFeedback?.({
  traceId: 'trace-123',
  feedback: {
    feedbackId: 'feedback-1',
    timestamp: new Date('2026-11-11T12:00:00.123Z'),
    feedbackType: 'thumbs',
    value: -1,
  },
})
```

各 Exporter 獨立處理自己的目的地。`MastraStorageExporter` 會在需要時解析本機 span 上下文，`MastraPlatformExporter` 則向 Platform 傳送 PUT 請求。不支援替換的 Exporter 會略過該事件。`flush()` 與 `shutdown()` 會等待待傳送資料處理完畢。

## 更新審核狀態 {/* #updating-review-status */}

若要在已設定的 Exporter 目的地變更審核狀態，請傳入回饋 ID，以及 `"reviewed"` 或 `"needs-review"`：

```typescript
await mastra.observability.updateFeedbackReviewStatus?.({
  feedbackId: 'feedback-123',
  reviewStatus: 'reviewed',
})
await mastra.observability.flush()
```

審核狀態更新會傳送至每個支援此操作的 Exporter，即使回饋未儲存在本機亦然。呼叫 `flush()` 或 `shutdown()`，等待待傳送資料處理完畢。

## HTTP 路由 {/* #http-routes */}

這些路由屬於 Mastra 執行環境，使用其設定的可觀測性儲存空間。它們與[未標示版本的 Mastra Platform Feedback API](/docs/mastra-platform/api#feedback-api) 不同；後者不提供建立回饋的路由。

| 方法 | 路徑 | 用途 | 權限 |
| - | - | - | - |
| `GET` | `/api/observability/feedback` | 列出回饋紀錄 | `observability:read` |
| `POST` | `/api/observability/feedback` | 建立回饋紀錄 | `observability:write` |
| `PUT` | `/api/observability/feedback/:feedbackId` | 完整替換回饋紀錄 | `observability:write` |
| `DELETE` | `/api/observability/feedback` | 依 ID 刪除回饋紀錄 | `observability:delete` |
| `DELETE` | `/api/observability/scores` | 依 ID 刪除評分紀錄 | `observability:delete` |
| `PATCH` | `/api/observability/feedback/:feedbackId/review-status` | 更新審核狀態 | `observability:write` |
| `POST` | `/api/observability/feedback/aggregate` | 傳回單一彙總值 | `observability:read` |
| `POST` | `/api/observability/feedback/breakdown` | 依維度將回饋分組 | `observability:read` |
| `POST` | `/api/observability/feedback/timeseries` | 依時間間隔將回饋分桶 | `observability:read` |
| `POST` | `/api/observability/feedback/percentiles` | 傳回百分位數序列 | `observability:read` |

### 列出查詢參數 {/* #list-query-parameters */}

`GET /api/observability/feedback` 以 URL 查詢參數接收引數。[Mastra Platform Feedback API](/docs/mastra-platform/api#feedback-api) 的 `GET /feedback` 端點也接受相同引數。

```bash
curl -sS "http://localhost:4111/api/observability/feedback?traceId=trace-123&environment=production&feedbackType=rating&page=0&perPage=20"
```

[`FeedbackFilter`](#feedbackfilter) 的每個欄位都可作為同名頂層查詢參數傳入，例如 `traceId`、`spanId`、`feedbackType`、`feedbackSource`、`feedbackUserId`、`reviewStatus`、`entityName`、`environment`、`experimentId` 或 `tags`。對接受陣列的篩選條件，可重複傳入參數，例如 `feedbackType=rating&feedbackType=thumbs`。物件型篩選條件（如 `timestamp`）須以 JSON 形式傳入，例如對 `timestamp={"start":"2026-01-01T00:00:00Z"}` 進行 URL 編碼。
