# 預設導出器

**已棄用於`@mastra/observability@1.12.0`**&#x8D0A;成[`MastraStorageExporter`](/reference/observability/tracing/exporters/mastra-storage-exporter).

:::警告\[已棄用]

`DefaultExporter`保留是為了向後相容，並將在未來的主要版本中刪除。使用[`MastraStorageExporter`](/reference/observability/tracing/exporters/mastra-storage-exporter) for new projects. Both classes share the same constructor, configuration, and runtime behavior. `DefaultExporter` keeps its original `mastra-default-observability-exporter`出口商`name`因此針對它所建立的監控規則繼續發揮作用。

:::

透過自動批次和重試邏輯將可觀察性事件持久保存到 Mastra Storage。

## `DefaultExporterConfig` {/* #defaultexporterconfig */}

```typescript
interface DefaultExporterConfig extends BaseExporterConfig {
  /** Maximum number of spans per batch. Default: 1000 */
  maxBatchSize?: number

  /** Maximum total buffer size before emergency flush. Default: 10000 */
  maxBufferSize?: number

  /** Maximum time to wait before flushing batch in milliseconds. Default: 5000 */
  maxBatchWaitMs?: number

  /** Maximum number of retry attempts. Default: 4 */
  maxRetries?: number

  /** Base retry delay in milliseconds (uses exponential backoff). Default: 500 */
  retryDelayMs?: number

  /** Tracing storage strategy or 'auto' for automatic selection. Default: 'auto' */
  strategy?: TracingStorageStrategy | 'auto'
}
```

延伸`BaseExporterConfig`, which includes:

* `logger?: IMastraLogger`- 記錄器實例
* `logLevel?: LogLevel | 'debug' | 'info' | 'warn' | 'error'`- 日誌等級（預設：INFO）

## `TracingStorageStrategy` {/* #tracingstoragestrategy */}

```typescript
type TracingStorageStrategy = 'realtime' | 'batch-with-updates' | 'insert-only'
```

### 策略行為 {/* #strategy-behaviors */}

* **即時的**：立即將每個事件持久保存到儲存中
* **大量更新**：批次建立和單獨更新，依序套用
* **僅插入**：僅處理SPAN\_ENDED事件，忽略更新

## 自動策略選擇 {/* #automatic-strategy-selection */}

什麼時候`strategy: 'auto'` (default), the exporter queries the storage adapter for its capabilities:

```typescript
interface TracingStrategy {
  /** Strategies supported by this adapter */
  supported: TracingStorageStrategy[]

  /** Preferred strategy for optimal performance */
  preferred: TracingStorageStrategy
}
```

出口商將：

1. 使用儲存適配器的首選策略（如果可用）
2. 如果首選策略不可用，則回退到第一個支援的策略
3. 如果不支援使用者指定的策略，則記錄警告

## 批次行為 {/* #batching-behavior */}

### 沖洗觸發器 {/* #flush-triggers */}

當滿足以下任何條件時，緩衝區將刷新：

* 緩衝區大小達到`maxBatchSize`
* 自第一個緩衝事件以來的時間超過`maxBatchWaitMs`
* 緩衝區大小達到`maxBufferSize` (emergency flush)
* `shutdown()`被稱為

### 重試邏輯 {/* #retry-logic */}

使用指數退避重試失敗的刷新：

* 重試延遲：`retryDelayMs * 2^attempt`
* 最大嘗試次數：`maxRetries`
* 所有重試失敗後批次將被丟棄

當儲存不支援訊號或重試次數耗盡時，`DefaultExporter` emits an `ObservabilityDropEvent` through `onDroppedEvent` handlers registered on exporters and bridges. The drop event includes the signal, reason, count, exporter name, storage name when known, and sanitized error details.

### 無序處理 {/* #out-of-order-handling */}

為了`batch-with-updates` strategy:

* 已建立的軌道
* 拒絕更新/結束尚未建立的跨度
* 記錄無序事件的警告
* 維護有序更新的序號

## 用法 {/* #usage */}

```typescript
import { DefaultExporter } from '@mastra/observability'

// Default configuration
const exporter = new DefaultExporter()

// Custom batching configuration
const customExporter = new DefaultExporter({
  maxBatchSize: 500,
  maxBatchWaitMs: 2000,
  strategy: 'batch-with-updates',
  logLevel: 'debug',
})
```
