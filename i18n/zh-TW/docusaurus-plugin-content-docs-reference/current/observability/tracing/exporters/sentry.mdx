# SentryExporter

使用 OpenTelemetry 語意慣例，將追蹤資料傳送到 Sentry，供 AI 追蹤與監控使用。

## 建構函式 {/* #constructor */}

```typescript oxfmt:false
new SentryExporter(config: SentryExporterConfig)
```

## `SentryExporterConfig` {/* #sentryexporterconfig */}

```typescript
interface SentryExporterConfig extends BaseExporterConfig {
  dsn?: string
  environment?: string
  tracesSampleRate?: number
  release?: string
  options?: Partial<Sentry.NodeOptions>
}
```

擴充自 `BaseExporterConfig`，其中還包括：

- `logger?: IMastraLogger` - Logger 實例
- `logLevel?: LogLevel | 'debug' | 'info' | 'warn' | 'error'` - 日誌等級（預設：INFO）

## 方法 {/* #methods */}

### `exportTracingEvent` {/* #exporttracingevent */}

```typescript oxfmt:false
async exportTracingEvent(event: TracingEvent): Promise<void>
```

將追蹤事件匯出到 Sentry。處理 SPAN_STARTED、SPAN_UPDATED 和 SPAN_ENDED 事件。

### 排空 {/* #flush */}

```typescript oxfmt:false
async flush(): Promise<void>
```

強制將所有待處理的 Span 傳送到 Sentry，不關閉匯出器。最多等待 2 秒以傳送資料。適用於需要在執行階段結束前確保 Span 已匯出的無伺服器環境。

### 關閉 {/* #shutdown */}

```typescript oxfmt:false
async shutdown(): Promise<void>
```

關閉 Sentry 連線前結束所有作用中的 Span 並清除內部狀態。最多等待 2 秒以傳送待處理的資料。

## 用法 {/* #usage */}

### 零設定（使用環境變數） {/* #zero-config-using-environment-variables */}

```typescript
import { SentryExporter } from '@mastra/sentry'

// Reads from SENTRY_DSN, SENTRY_ENVIRONMENT, SENTRY_RELEASE
const exporter = new SentryExporter()
```

### 明確設定 {/* #explicit-configuration */}

```typescript
import { SentryExporter } from '@mastra/sentry'

const exporter = new SentryExporter({
  dsn: process.env.SENTRY_DSN,
  environment: 'production',
  tracesSampleRate: 1.0,
  release: '1.0.0',
})
```

### 設定取樣 {/* #with-sampling */}

```typescript
const exporter = new SentryExporter({
  dsn: process.env.SENTRY_DSN,
  environment: 'production',
  tracesSampleRate: 0.1, // Send 10% of transactions to Sentry (recommended for high-load backends)
})
```

### 使用自訂 Sentry 選項 {/* #with-custom-sentry-options */}

```typescript
const exporter = new SentryExporter({
  dsn: process.env.SENTRY_DSN,
  environment: 'production',
  options: {
    integrations: [
      // Custom Sentry integrations
    ],
    beforeSend: event => {
      // Custom event processing
      return event
    },
  },
})
```

## Span 對應 {/* #span-mapping */}

Mastra Span 類型與 Sentry 操作的對應如下：

| Mastra SpanType | Sentry 操作 |
| - | - |
|`AGENT_RUN` | `gen_ai.invoke_agent` |
| `MODEL_GENERATION` | `gen_ai.chat` |
| `MODEL_STEP` | _(略過)_ |
| `MODEL_CHUNK` | _(略過)_ |
| `TOOL_CALL` | `gen_ai.execute_tool` |
| `MCP_TOOL_CALL` | `gen_ai.execute_tool` |
| `PROVIDER_TOOL_CALL` | `gen_ai.execute_tool` |
| `WORKFLOW_RUN` | `workflow.run` |
| `WORKFLOW_STEP` | `workflow.step` |
| `WORKFLOW_CONDITIONAL` | `workflow.conditional` |
| `WORKFLOW_CONDITIONAL_EVAL` | `workflow.conditional` |
| `WORKFLOW_PARALLEL` | `workflow.parallel` |
| `WORKFLOW_LOOP` | `workflow.loop` |
| `WORKFLOW_SLEEP` | `workflow.sleep` |
| `WORKFLOW_WAIT_EVENT` | `workflow.wait` |
| `PROCESSOR_RUN` | `ai.processor` |
| `GENERIC` | `ai.span` |

略過 MODEL_STEP 和 MODEL_CHUNK Span 以簡化追蹤層級，其資料會彙整到 MODEL_GENERATION Span。

## 環境變數 {/* #environment-variables */}

匯出器從以下環境變數讀取設定：

| 變數 | 說明 |
| - | - |
| `SENTRY_DSN` | 資料來源名稱（Data Source Name），指定 SDK 傳送事件的目標位置 |
| `SENTRY_ENVIRONMENT` | 部署環境名稱 |
| `SENTRY_RELEASE` | 已部署程式碼的版本 |

## `OpenTelemetry` 屬性 {/* #opentelemetry-attributes */}

匯出器設定以下標準 OpenTelemetry 屬性：

**共用屬性（所有 Span）：**

- `sentry.origin`：`auto.ai.mastra`（用於識別來自 Mastra 的 Span）
- `ai.span.type`：Mastra Span 類型
- `gen_ai.conversation.id`：聊天對話識別碼，取自 `metadata.threadId`，用於在 Sentry 的 Conversations 檢視中彙整 Span

**MODEL_GENERATION Span：**

* `gen_ai.operation.name`: `chat`
- `gen_ai.system`：模型提供者
- `gen_ai.request.model`：模型識別碼
- `gen_ai.request.messages`：輸入訊息／提示詞（JSON）
- `gen_ai.response.model`：回應模型
- `gen_ai.response.text`：輸出文字
- `gen_ai.response.tool_calls`：生成期間進行的 Tool 呼叫（JSON 陣列）
- `gen_ai.usage.input_tokens`：輸入 token 數
- `gen_ai.usage.output_tokens`：輸出 token 數
- `gen_ai.usage.total_tokens`：token 總數
- `gen_ai.request.stream`：是否使用串流傳輸
- `gen_ai.request.temperature`：溫度參數
- `gen_ai.completion_start_time`：第一個 token 的產生時間

**TOOL_CALL Span：**

* `gen_ai.operation.name`: `execute_tool`
- `gen_ai.tool.name`：Tool 識別碼
* `gen_ai.tool.type`: `function`
- `gen_ai.tool.call.id`：Tool 呼叫 ID
- `gen_ai.tool.input`：Tool 輸入
- `gen_ai.tool.output`：Tool 輸出
- `tool.success`：是否成功

**AGENT_RUN Span：**

* `gen_ai.operation.name`: `invoke_agent`
- `gen_ai.agent.name`：Agent 識別碼
- `gen_ai.pipeline.name`：Agent 名稱
- `gen_ai.agent.instructions`：Agent 指令
- `gen_ai.response.model`：子層生成使用的模型
- `gen_ai.response.text`：子層生成的輸出
- `gen_ai.usage.*`：子層生成的 token 用量
