# OtelExporter

將追蹤與日誌傳送至任何相容 OpenTelemetry 的可觀測性平台。追蹤採用標準化的 GenAI 語意慣例。日誌保留原始嚴重程度與訊息內容，並透過 OTEL 日誌紀錄原生的追蹤脈絡，以及 `mastra.traceId` / `mastra.spanId` 屬性與追蹤關聯。

## 建構函式 {/* #constructor */}

```typescript oxfmt:false
new OtelExporter(config: OtelExporterConfig)
```

## 中繼資料對應 {/* #metadata-mapping */}

使用 `metadataMapping`，可依後端要求將 `userId` 等中繼資料放在指定的 Span 屬性名稱下：

```typescript
import { OtelExporter } from '@mastra/otel-exporter'

const exporter = new OtelExporter({
  provider: {
    custom: { endpoints: { traces: 'https://collector.example.com/v1/traces' } },
  },
  metadataMapping: { userId: 'user.id', tenantId: 'tenant.id' },
})
```

中繼資料為 `{ userId: 'user-123', tenantId: 'acme' }` 的 Span 會匯出 `user.id` 與 `tenant.id`，同時保留既有的 `mastra.metadata.userId` 與 `mastra.metadata.tenantId` 屬性。對應會套用至包含指定中繼資料鍵的每個 Span，包括子 Span。

對應後的值皆為字串。物件與陣列會經過 JSON 編碼；缺少的鍵、`null`、`undefined` 和空字串會被略過。`0` 與 `false` 分別轉為 `"0"` 和 `"false"`。鍵採字面比對，因此含句點的鍵不會選取巢狀屬性。空白的目標名稱會被忽略。

明確設定的對應會覆寫同名的既有屬性。如果多個中繼資料鍵對應到同一名稱，以最後一個非空值為準。對應不影響日誌紀錄或資源屬性。

### 自訂訊號端點 {/* #custom-signal-endpoints */}

`endpoint` 與 `endpoints` 只能擇一提供。TypeScript 會拒絕同時包含兩者的設定；執行階段驗證也會拒絕該設定，顯示錯誤訊息並停用 exporter。

使用 `endpoints` 為各種訊號提供確切 URL。URL 會原樣傳給所選 exporter，不會新增、移除或替換路徑區段。追蹤與日誌端點可以使用不同主機及互不相關的路徑：

```typescript
import { OtelExporter } from '@mastra/otel-exporter'

const exporter = new OtelExporter({
  provider: {
    custom: {
      protocol: 'http/protobuf',
      endpoints: {
        traces: 'https://traces.example.com/api/ingest/?tenant=acme',
        logs: 'https://logs.example.com/events',
      },
    },
  },
})
```

至少提供一個訊號端點。只匯出追蹤時省略 `logs`；只匯出日誌時省略 `traces`。即使已設定端點，`signals` 開關仍可停用對應訊號。通訊協定與標頭適用於兩個端點，所選通訊協定必須支援該訊號。自訂 `exporter` 執行個體仍會覆寫追蹤的傳輸方式。

也可以明確傳入環境變數的值：

```typescript
const exporter = new OtelExporter({
  provider: {
    custom: {
      endpoints: {
        traces: process.env.OTEL_EXPORTER_OTLP_TRACES_ENDPOINT,
        logs: process.env.OTEL_EXPORTER_OTLP_LOGS_ENDPOINT,
      },
    },
  },
})
```

型別要求至少包含一個訊號鍵；使用環境變數設定時，值可以是 `undefined`。執行時至少要有一個非空 URL。缺少值會停用對應訊號。Mastra 不會自動載入端點環境變數。

為相容既有設定，單數形式的 `endpoint` 維持原有行為：OTLP 訊號路徑由 collector URL 推導，Zipkin 則直接使用設定的 URL。若要自訂路徑，請改用 `endpoints`。

## 方法 {/* #methods */}

### `exportTracingEvent` {/* #exporttracingevent */}

```typescript oxfmt:false
async exportTracingEvent(event: TracingEvent): Promise<void>
```

將追蹤事件匯出至已設定的 OTEL 後端。

### flush {/* #flush */}

```typescript oxfmt:false
async flush(): Promise<void>
```

強制將緩衝中的 Span 寫入 OTEL 後端，而不關閉 exporter。適用於無伺服器環境，可確保 Span 在執行階段結束前完成匯出。

### shutdown {/* #shutdown */}

```typescript oxfmt:false
async shutdown(): Promise<void>
```

送出待處理的追蹤並關閉 exporter。

## 通訊協定需求 {/* #protocol-requirements */}

不同 provider 需要不同的 OTEL exporter 套件。追蹤與日誌匯出彼此獨立：只需要追蹤時，安裝追蹤套件即可；若也要匯出日誌，則須同時安裝所選通訊協定的追蹤與日誌套件。Zipkin 不支援 OTLP 日誌。

| 通訊協定 | 追蹤套件 | 日誌套件 |
| - | - | - |
| gRPC | `@opentelemetry/exporter-trace-otlp-grpc` (+ `@grpc/grpc-js`) | `@opentelemetry/exporter-logs-otlp-grpc` (+ `@grpc/grpc-js`) |
| HTTP/Protobuf | `@opentelemetry/exporter-trace-otlp-proto` | `@opentelemetry/exporter-logs-otlp-proto` |
| HTTP/JSON | `@opentelemetry/exporter-trace-otlp-http` | `@opentelemetry/exporter-logs-otlp-http` |
| Zipkin | `@opentelemetry/exporter-zipkin` | 不支援 |

## 標籤支援 {/* #tags-support */}

OtelExporter 支援為追蹤加上標籤，以便分類與篩選。標籤只套用至根 Span，並儲存在 `mastra.tags` 屬性中。

### 用法 {/* #usage */}

```typescript
const result = await agent.generate('Hello', {
  tracingOptions: {
    tags: ['production', 'experiment-v2', 'user-request'],
  },
})
```

### 標籤的儲存方式 {/* #how-tags-are-stored */}

為了盡可能相容各種後端，標籤會以 JSON 字串化陣列的形式儲存在 Span 的 `mastra.tags` 屬性中：

```json
{
  "mastra.tags": "[\"production\",\"experiment-v2\",\"user-request\"]"
}
```

:::note
雖然 OpenTelemetry 規範支援原生陣列屬性，但許多後端（Jaeger、Zipkin、Tempo）對陣列的支援有限。使用 JSON 字串可確保不同可觀測性平台的行為一致。
:::
