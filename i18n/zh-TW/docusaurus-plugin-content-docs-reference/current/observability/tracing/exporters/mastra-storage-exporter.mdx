# MastraStorageExporter

透過自動批次處理與重試機制，將追蹤資料持久化至 Mastra 設定的儲存空間。

:::note

`MastraStorageExporter` 先前稱為 `DefaultExporter`。`@mastra/observability` 仍匯出原本的 `DefaultExporter` 類別，因此現有匯入仍可使用；但該類別已棄用，並會在未來的主要版本移除。新程式碼應使用 `MastraStorageExporter`。

:::

:::warning 平台儲存限制

設定 `MASTRA_DEPLOYMENT_ID` 後，此匯出器預設停用。若要允許匯出至遠端儲存，請在**可觀測性設定**中設定 `retainStorageExporterOnPlatform: true`，而非在匯出器建構函式中設定。即使選擇啟用，只要轉接器回報使用本機持久化，`InMemoryStore`（包括未設定儲存時的備援方案）、本機 libSQL、內嵌複本及 DuckDB 仍會遭到封鎖。即使日誌設定隱藏了初始化警告，也不會將可觀測性事件寫入該本機資料庫。

支援的提供者清單、轉接器升級需求與設定範例，請參閱[平台上的儲存匯出](/docs/observability/integrations/exporters/mastra-storage#export-to-storage-and-platform)。

:::

## `MastraStorageExporterConfig` {/* #mastrastorageexporterconfig */}

```typescript
interface MastraStorageExporterConfig extends BaseExporterConfig {
  /** Opt-in byte flush thresholds. Omit to keep count-based batching. */
  byteBatching?: {
    maxBatchBytes?: number // Default: 8 MiB
    maxConcurrentWrites?: number // Default: 1
  }

  /** Maximum number of spans per batch. Default: 1000 */
  maxBatchSize?: number

  /** Maximum total buffer size before emergency flush. Default: 10000 */
  maxBufferSize?: number

  /** Maximum time to wait before flushing batch in milliseconds. Default: 5000 */
  maxBatchWaitMs?: number

  /** Maximum number of retry attempts. Default: 4 */
  maxRetries?: number

  /** Base retry delay in milliseconds (uses exponential backoff). Default: 500 */
  retryDelayMs?: number

  /** Tracing storage strategy or 'auto' for automatic selection. Default: 'auto' */
  strategy?: TracingStorageStrategy | 'auto'
}
```

繼承 `BaseExporterConfig`，其中包含：

* `logger?: IMastraLogger` — 日誌記錄器實例
* `logLevel?: LogLevel | 'debug' | 'info' | 'warn' | 'error'` — 日誌等級（預設：INFO）

## 依位元組批次處理 {/* #byte-batching */}

使用 `byteBatching: {}` 啟用依位元組批次處理，也可以提供自訂門檻。當解析後的策略為 `realtime` 時，匯出器會忽略依位元組批次處理，維持立即寫入並等待完成：

```typescript
new MastraStorageExporter({
  byteBatching: {
    maxBatchBytes: 8 * 1024 * 1024,
    maxConcurrentWrites: 1,
  },
})
```

* `maxBatchBytes`：緩衝事件預設達到 8 MiB 時觸發寫入。較大的紀錄會完整傳送，不會因大小而截斷或捨棄。
* `maxConcurrentWrites`：控制同時進行的儲存寫入次數，預設為 1。以更新為基礎的追蹤策略一律逐次寫入，以維持 span 順序。

依紀錄數與計時器觸發的寫入仍然有效。儲存寫入速度落後時，排隊的紀錄會保留，因此佇列占用的記憶體可能增加。未啟用 `byteBatching` 時，匯出器維持原有依紀錄數批次處理的行為。

使用 `exporter.getByteBatchingStats()` 查看目前的佇列。

## `TracingStorageStrategy` {/* #tracingstoragestrategy */}

```typescript
type TracingStorageStrategy = 'realtime' | 'batch-with-updates' | 'insert-only'
```

### 策略行為 {/* #strategy-behaviors */}

* **`realtime`**：立即將每個事件寫入儲存空間。
* **`batch-with-updates`**：分別批次處理建立與更新，並依序套用。
* **`insert-only`**：只處理 `SPAN_ENDED` 事件，忽略更新。

## 自動策略選擇 {/* #automatic-strategy-selection */}

當 `strategy: 'auto'`（預設值）時，匯出器會查詢儲存轉接器支援的功能：

```typescript
interface TracingStrategy {
  /** Strategies supported by this adapter */
  supported: TracingStorageStrategy[]

  /** Preferred strategy for optimal performance */
  preferred: TracingStorageStrategy
}
```

匯出器會：

1. 使用儲存適配器的首選策略（如果可用）
2. 若偏好策略不可用，則改用第一個受支援的策略。
3. 若使用者指定的策略不受支援，則記錄警告。

## 批次行為 {/* #batching-behavior */}

### 寫入觸發條件 {/* #flush-triggers */}

當滿足以下任何條件時，緩衝區將刷新：

* 緩衝區大小達到 `maxBatchSize`。
* 距離第一個緩衝事件的時間超過 `maxBatchWaitMs`。
* 緩衝區大小達到 `maxBufferSize`（緊急寫入）。
* 呼叫 `shutdown()`。

### 重試邏輯 {/* #retry-logic */}

使用指數退避重試失敗的刷新：

* 重試延遲：`retryDelayMs * 2^attempt`
* 最大嘗試次數：`maxRetries`
* 所有重試失敗後批次將被丟棄

### 亂序事件處理 {/* #out-of-order-handling */}

對於 `batch-with-updates` 策略：

* 追蹤哪些 span 已建立。
* 拒絕更新或結束尚未建立的 span。
* 對亂序事件記錄警告。
* 維護序號，確保更新依序進行。

## 用法 {/* #usage */}

```typescript
import { MastraStorageExporter } from '@mastra/observability'

// Default configuration
const exporter = new MastraStorageExporter()

// Custom batching configuration
const customExporter = new MastraStorageExporter({
  maxBatchSize: 500,
  maxBatchWaitMs: 2000,
  strategy: 'batch-with-updates',
  logLevel: 'debug',
})
```

## 遷移自`DefaultExporter` {/* #migrating-from-defaultexporter */}

兩個類別的建構函式簽章與行為相同。遷移時請替換匯入與建構函式：

```typescript
// Before
import { DefaultExporter } from '@mastra/observability'
const exporter = new DefaultExporter()

// After
import { MastraStorageExporter } from '@mastra/observability'
const exporter = new MastraStorageExporter()
```

原有的 `DefaultExporter` 保持不變，因此在完成遷移前，比對舊匯出器名稱 `mastra-default-observability-exporter` 的儀表板與警示規則仍可運作。
