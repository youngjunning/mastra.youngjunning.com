# MastraStorageExporter

透過自動批次和重試邏輯將追蹤保留到 Mastra 的配置儲存。

：：：筆記

`MastraStorageExporter`以前被稱為`DefaultExporter`. The original `DefaultExporter`類別仍然導出自`@mastra/observability`因此現有的導入仍然有效，但它已被棄用，並將在未來的主要版本中刪除。新代碼應該使用`MastraStorageExporter`.

:::

:::警告 平台儲存限制

什麼時候`MASTRA_DEPLOYMENT_ID` is set, this exporter is disabled by default. Set `retainStorageExporterOnPlatform: true` on the **observability config**, not the exporter constructor, to allow remote storage export. `InMemoryStore` (including the fallback when no storage is configured), local libSQL, embedded replicas, and DuckDB remain blocked when the adapter reports local persistence, even with the opt-in. No observability events are written to that local database, even if the initialization warning is hidden by your logging setup.

看[storage export on Platform](/docs/observability/integrations/exporters/mastra-storage#export-to-storage-and-platform) for the supported-provider table, adapter upgrade requirements, and a configuration example.

:::

## 跨度預覽 {/* #span-previews */}

`MastraStorageExporter`自動產生簡短易讀的`inputPreview`, `outputPreview`, and `errorPreview` summaries based on the span type. Each preview contains up to 100 characters plus an ellipsis when truncated. Full payloads remain available separately.

## `MastraStorageExporterConfig` {/* #mastrastorageexporterconfig */}

```typescript
interface MastraStorageExporterConfig extends BaseExporterConfig {
  /** Opt-in byte flush thresholds. Omit to keep count-based batching. */
  byteBatching?: {
    maxBatchBytes?: number // Default: 8 MiB
    maxConcurrentWrites?: number // Default: 1
  }

  /** Maximum number of spans per batch. Default: 1000 */
  maxBatchSize?: number

  /** Maximum total buffer size before emergency flush. Default: 10000 */
  maxBufferSize?: number

  /** Maximum time to wait before flushing batch in milliseconds. Default: 5000 */
  maxBatchWaitMs?: number

  /** Maximum number of retry attempts. Default: 4 */
  maxRetries?: number

  /** Base retry delay in milliseconds (uses exponential backoff). Default: 500 */
  retryDelayMs?: number

  /** Tracing storage strategy or 'auto' for automatic selection. Default: 'auto' */
  strategy?: TracingStorageStrategy | 'auto'
}
```

延伸`BaseExporterConfig`, which includes:

* `logger?: IMastraLogger`- 記錄器實例
* `logLevel?: LogLevel | 'debug' | 'info' | 'warn' | 'error'`- 日誌等級（預設：INFO）

## 位元組批次 {/* #byte-batching */}

啟用位元組批次`byteBatching: {}` or supply custom thresholds. The exporter ignores byte batching when the resolved strategy is `realtime`, which keeps its immediate, awaited writes:

```typescript
new MastraStorageExporter({
  byteBatching: {
    maxBatchBytes: 8 * 1024 * 1024,
    maxConcurrentWrites: 1,
  },
})
```

* `maxBatchBytes`預設情況下，當緩衝事件達到 8 MiB 時觸發寫入。較大的記錄會完整發送，不會被截斷或基於大小的丟棄。
* `maxConcurrentWrites`控制並發儲存寫入。預設值為 1。基於更新的追蹤策略始終一次使用一次寫入來保留跨度順序。

記錄計數和基於計時器的刷新觸發器仍然適用。當儲存落後時，排隊的記錄會被保留，因此佇列記憶體會成長。沒有`byteBatching`, the exporter keeps its existing count-based batching behavior.

檢查目前隊列`exporter.getByteBatchingStats()`.

## `TracingStorageStrategy` {/* #tracingstoragestrategy */}

```typescript
type TracingStorageStrategy = 'realtime' | 'batch-with-updates' | 'insert-only'
```

### 策略行為 {/* #strategy-behaviors */}

* **即時的**：立即將每個事件持久保存到儲存中
* **大量更新**：批次建立和單獨更新，依序套用
* **僅插入**：僅處理SPAN\_ENDED事件，忽略更新

## 自動策略選擇 {/* #automatic-strategy-selection */}

什麼時候`strategy: 'auto'` (default), the exporter queries the storage adapter for its capabilities:

```typescript
interface TracingStrategy {
  /** Strategies supported by this adapter */
  supported: TracingStorageStrategy[]

  /** Preferred strategy for optimal performance */
  preferred: TracingStorageStrategy
}
```

出口商將：

1. 使用儲存適配器的首選策略（如果可用）
2. 如果首選策略不可用，則回退到第一個支援的策略
3. 如果不支援使用者指定的策略，則記錄警告

## 批次行為 {/* #batching-behavior */}

### 沖洗觸發器 {/* #flush-triggers */}

當滿足以下任何條件時，緩衝區將刷新：

* 緩衝區大小達到`maxBatchSize`
* 自第一個緩衝事件以來的時間超過`maxBatchWaitMs`
* 緩衝區大小達到`maxBufferSize` (emergency flush)
* `shutdown()`被稱為

### 重試邏輯 {/* #retry-logic */}

使用指數退避重試失敗的刷新：

* 重試延遲：`retryDelayMs * 2^attempt`
* 最大嘗試次數：`maxRetries`
* 所有重試失敗後批次將被丟棄

### 無序處理 {/* #out-of-order-handling */}

為了`batch-with-updates` strategy:

* 已建立的軌道
* 拒絕更新/結束尚未建立的跨度
* 記錄無序事件的警告
* 維護有序更新的序號

## 用法 {/* #usage */}

```typescript
import { MastraStorageExporter } from '@mastra/observability'

// Default configuration
const exporter = new MastraStorageExporter()

// Custom batching configuration
const customExporter = new MastraStorageExporter({
  maxBatchSize: 500,
  maxBatchWaitMs: 2000,
  strategy: 'batch-with-updates',
  logLevel: 'debug',
})
```

## 遷移自`DefaultExporter` {/* #migrating-from-defaultexporter */}

這兩個類別共享相同的建構函式簽名和行為。若要遷移，請替換導入和建構函數：

```typescript
// Before
import { DefaultExporter } from '@mastra/observability'
const exporter = new DefaultExporter()

// After
import { MastraStorageExporter } from '@mastra/observability'
const exporter = new MastraStorageExporter()
```

原來的`DefaultExporter` is preserved unchanged so dashboards or alert rules that match the previous `mastra-default-observability-exporter` exporter name keep working until you migrate.
