# SensitiveDataFilter

`SensitiveDataFilter` 是 Span 輸出處理器，會遮蔽欄位名稱與設定清單相符的值。[`Observability`](/reference/observability/tracing/configuration#observabilityregistryconfig) 預設會將其套用至一般的可觀測性設定。

## 使用範例 {/* #usage-example */}

使用頂層的 `sensitiveDataFilter` 選項設定自動套用的篩選器。篩選器會在使用者提供的 Span 輸出處理器之後執行，因此也能遮蔽這些處理器新增或暴露的值。

```typescript title="src/mastra/index.ts"
import { Mastra } from '@mastra/core/mastra'
import { Observability, MastraStorageExporter } from '@mastra/observability'

export const mastra = new Mastra({
  observability: new Observability({
    configs: {
      default: {
        serviceName: 'my-service',
        exporters: [new MastraStorageExporter()],
      },
    },
    sensitiveDataFilter: {
      sensitiveFields: ['password', 'authorization', 'customerSecret'],
      redactionToken: '[HIDDEN]',
      redactionStyle: 'full',
    },
  }),
})
```

傳入 `sensitiveFields` 會取代預設欄位清單。仍要遮蔽的預設欄位，都必須重新列入。

若要停用所有一般設定的自動篩選，請將 `sensitiveDataFilter` 設為 `false`：

```typescript
new Observability({
  configs: {
    debug: {
      serviceName: 'debug-service',
      exporters: [new MastraStorageExporter()],
    },
  },
  sensitiveDataFilter: false,
})
```

若一般設定的 `spanOutputProcessors` 已包含 `SensitiveDataFilter`，`Observability` 會使用該執行個體，不會再加入另一個。預先建立的 `ObservabilityInstance` 不會被修改；若這些執行個體需要篩選，請在建構時加入處理器。

## 遮蔽方式 {/* #redaction-styles */}

### 完全遮蔽 {/* #full-redaction */}

完全遮蔽會將每個相符的基本型別值替換為 `redactionToken`。

```jsonc oxfmt:false
// Before
{ "apiKey": "sk-abc123xyz789", "userId": "user_123" }

// After
{ "apiKey": "[REDACTED]", "userId": "user_123" }
```

### 部分遮蔽 {/* #partial-redaction */}

部分遮蔽會保留值的前三個及後三個字元。長度不超過六個字元的值則改用 `redactionToken`。非字串的基本型別值會先轉成字串再遮蔽。

```typescript
const filter = new SensitiveDataFilter({
  redactionStyle: 'partial',
})
```

```jsonc oxfmt:false
// Before
{ "apiKey": "sk-abc123xyz789" }

// After
{ "apiKey": "sk-…789" }
```

### 索引式遮蔽 {/* #indexed-redaction */}

索引式遮蔽會以穩定的代碼取代每個不重複的值。代碼根據最先與該值相符的欄位名稱產生，例如 `[APIKEY_1]`。只要 Trace 的對應關係仍保留，同一個值在該 Trace 的各個 Span 中都會對應到相同代碼，因此可在不暴露原始值的情況下關聯已遮蔽資料。即使該值之後出現在其他敏感欄位，也會沿用最初的代碼。

```typescript
const filter = new SensitiveDataFilter({
  redactionStyle: 'indexed',
})
```

```jsonc oxfmt:false
// Before (two spans in the same trace)
[{ "apiKey": "sk-alice-key" }, { "apiKey": "sk-bob-key" }]

// After
[{ "apiKey": "[APIKEY_1]" }, { "apiKey": "[APIKEY_2]" }]
```

對應關係以每個 Trace 為單位。每個 Trace 都會重新編號，因此無法透過代碼連結不同 Trace 的資料。

狀態有兩項容量限制。篩選器保留最近使用的 1000 個 Trace 的對應關係；超出時會移除最久未使用的 Trace。之後到達的該 Trace 的 Span 會建立新的對應關係，因此後續值可能取得新代碼。每個 Trace 最多追蹤 1000 個不重複的值。達到上限後，已追蹤的值仍使用原有代碼，新值則以 `redactionToken` 遮蔽。

非字串值會先轉成字串，再分配代碼。

## 欄位比對 {/* #field-matching */}

比對前，欄位名稱會轉成小寫並移除非英數字元：

* `api-key`、`api_key`、`Api Key` 和 `apiKey` 都會正規化為 `apikey`。
* 正規化後進行精確比對。`token` 會與 `Token` 相符，但不會與 `promptTokens`、`tokenCount` 或 `authToken` 相符。

若相符欄位包含物件或陣列，篩選器會走訪其值並遮蔽其中的敏感欄位，而不會取代整個結構。

## 處理行為 {/* #processing-behavior */}

`process()` 會分別篩選以下頂層 Span 欄位：

* `attributes`
* `metadata`
* `input`
* `output`
* `errorInfo`
* `requestContext`

對於每個欄位，處理器會：

* 走訪巢狀物件與陣列。
* 解析包含物件或陣列的 JSON 字串、篩選其中的值，再將結果序列化。
* 保留無效的 JSON 字串，不予變更。
* 保留 `Date` 執行個體。
* 將重複的物件參照替換為 `[Circular Reference]`。

若某個頂層 Span 欄位中的任何位置篩選失敗，整個欄位會被替換為以下標記：

```typescript
{
  error: {
    processor: 'sensitive-data-filter'
  }
}
```

## 方法 {/* #methods */}

### 處理 {/* #processing */}

#### `process(span)` {/* #processspan */}

就地遮蔽指定 Span 中支援的欄位，並回傳同一個 Span。

```typescript
import type { AnySpan } from '@mastra/core/observability'
import { SensitiveDataFilter } from '@mastra/observability'

const filter = new SensitiveDataFilter()

export function redactSpan(span: AnySpan): AnySpan {
  return filter.process(span)
}
```

#### `shutdown()` {/* #shutdown */}

