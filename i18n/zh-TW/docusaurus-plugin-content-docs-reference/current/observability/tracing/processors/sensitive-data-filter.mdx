# 敏感資料過濾器

`SensitiveDataFilter`是一個跨度輸出處理器，用於編輯欄位名稱與配置清單相符的值。[`Observability`](/reference/observability/tracing/configuration#observabilityregistryconfig)預設將其應用於普通的可觀察性配置。

## 使用範例 {/* #usage-example */}

使用頂級配置自動套用的過濾器`sensitiveDataFilter` option. The filter runs after user-provided span output processors so it can redact values they add or expose.

```typescript title="src/mastra/index.ts"
import { Mastra } from '@mastra/core/mastra'
import { Observability, MastraStorageExporter } from '@mastra/observability'

export const mastra = new Mastra({
  observability: new Observability({
    configs: {
      default: {
        serviceName: 'my-service',
        exporters: [new MastraStorageExporter()],
      },
    },
    sensitiveDataFilter: {
      sensitiveFields: ['password', 'authorization', 'customerSecret'],
      redactionToken: '[HIDDEN]',
      redactionStyle: 'full',
    },
  }),
})
```

透過`sensitiveFields` replaces the default field list. Include every default field you still want to redact.

若要停用所有普通配置的自動過濾，請設定`sensitiveDataFilter` to `false`:

```typescript
new Observability({
  configs: {
    debug: {
      serviceName: 'debug-service',
      exporters: [new MastraStorageExporter()],
    },
  },
  sensitiveDataFilter: false,
})
```

如果普通配置已經包含`SensitiveDataFilter` in `spanOutputProcessors`, `Observability` uses that instance and doesn't add another. Pre-instantiated `ObservabilityInstance` values aren't modified. Add the processor when constructing those instances if they need filtering.

## 密文樣式 {/* #redaction-styles */}

### 完全密文 {/* #full-redaction */}

完整編輯將每個匹配的原始值替換為`redactionToken`.

```jsonc oxfmt:false
// Before
{ "apiKey": "sk-abc123xyz789", "userId": "user_123" }

// After
{ "apiKey": "[REDACTED]", "userId": "user_123" }
```

### 部分編輯 {/* #partial-redaction */}

部分密文保留前三個字元。使用六個或更少字元的值`redactionToken` instead. Non-string primitive values are converted to strings before redaction.

```typescript
const filter = new SensitiveDataFilter({
  redactionStyle: 'partial',
})
```

```jsonc oxfmt:false
// Before
{ "apiKey": "sk-abc123xyz789" }

// After
{ "apiKey": "sk-…789" }
```

### 索引編輯 {/* #indexed-redaction */}

例如，索引編輯將每個唯一值替換為從與其匹配的第一個欄位名稱派生的穩定標記`[APIKEY_1]`. The same value maps to the same token across the spans of a trace while the trace's mapping is retained, so redacted values stay correlatable without exposing the raw value. Later occurrences under other sensitive fields reuse the first token.

```typescript
const filter = new SensitiveDataFilter({
  redactionStyle: 'indexed',
})
```

```jsonc oxfmt:false
// Before (two spans in the same trace)
[{ "apiKey": "sk-alice-key" }, { "apiKey": "sk-bob-key" }]

// After
[{ "apiKey": "[APIKEY_1]" }, { "apiKey": "[APIKEY_2]" }]
```

映射的範圍是按追蹤確定的。每個追蹤都會重新編號，因此來自不同追蹤的標記無法連結。

狀態以兩種方式受到限制。過濾器保留 1000 個最近使用的追蹤的映射。除此之外，最近最少使用的追蹤將被逐出，並且到達已逐出追蹤的跨度會開始新的映射，因此後面的值可能會收到新的令牌。每個追蹤還追蹤最多 1000 個唯一值。一旦達到該上限，已追蹤的值將保留其代幣，並且新值將被編輯`redactionToken`.

在分配標記之前，非字串值將轉換為字串。

## 現場匹配 {/* #field-matching */}

在比較之前，欄位名稱為小寫並去除非字母數字字元：

* `api-key`, `api_key`, `Api Key`, and `apiKey` normalize to `apikey`.
* 歸一化後匹配準確。`token` matches `Token`, but doesn't match `promptTokens`, `tokenCount`, or `authToken`.

當匹配字段包含物件或數組時，過濾器會遍歷該值並編輯其中的敏感字段，而不是替換完整的結構。

## 加工行為 {/* #processing-behavior */}

`process()`獨立過濾這些頂級跨度字段：

* `attributes`
* `metadata`
* `input`
* `output`
* `errorInfo`
* `requestContext`

在每個欄位中，處理器：

* 遍歷巢狀物件和陣列。
* 解析和過濾包含物件或陣列的 JSON 字串。然後它會序列化過濾後的值。
* 保留無效的 JSON 字串不變。
* 果醬`Date` instances.
* 將重複的物件參考替換為`[Circular Reference]`.

如果過濾在一個頂級跨度欄位中的任何位置失敗，則該完整欄位將替換為以下標記：

```typescript
{
  error: {
    processor: 'sensitive-data-filter'
  }
}
```

## 方法 {/* #methods */}

### 加工 {/* #processing */}

#### `process(span)` {/* #processspan */}

就地編輯所提供的跨度上支援的欄位並傳回相同的跨度。

```typescript
import type { AnySpan } from '@mastra/core/observability'
import { SensitiveDataFilter } from '@mastra/observability'

const filter = new SensitiveDataFilter()

export function redactSpan(span: AnySpan): AnySpan {
  return filter.process(span)
}
```
