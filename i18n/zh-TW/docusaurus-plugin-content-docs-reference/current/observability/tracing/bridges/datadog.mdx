# DatadogBridge

:::warning

Datadog Bridge 目前仍處於**實驗階段**。API 與設定選項可能在後續版本中變更。

:::

將 Mastra 追蹤與 Datadog 雙向整合。即時建立原生 `dd-trace` APM span，讓 Tool 與處理器內透過自動插樁產生的操作正確巢狀置於其父 Mastra span 之下。span 結束時，透過 `dd-trace` 的管線傳送 LLM Observability 資料。

## 建構函數 {/* #constructor */}

```typescript oxfmt:false
new DatadogBridge(config?: DatadogBridgeConfig)
```

## `DatadogBridgeConfig` {/* #datadogbridgeconfig */}

## 方法 {/* #methods */}

### `createSpan` {/* #createspan */}

```typescript oxfmt:false
createSpan(options: CreateSpanOptions<SpanType>): SpanIds | undefined
```

建立 span 時由 Mastra 可觀測性執行個體呼叫。立即透過 `tracer.startSpan()` 建立 dd-trace APM span，並傳回與 Mastra 相容的識別碼。Mastra 在 span 的整個生命週期中使用這些 ID。dd-trace span 物件儲存在內部，用於啟用作用域。

**傳回：** `SpanIds | undefined` - `{ spanId, traceId, parentSpanId }`；若 Bridge 已停用，則傳回 `undefined`。

### `executeInContext` {/* #executeincontext */}

```typescript oxfmt:false
executeInContext<T>(spanId: string, fn: () => Promise<T>): Promise<T>
```

在 Mastra span 的 dd-trace 上下文中執行非同步函式。函式內由 dd-trace 自動插樁的操作（HTTP、資料庫等）會以該 span 為父 span。

### `flush` {/* #flush */}

```typescript oxfmt:false
async flush(): Promise<void>
```

強制將緩衝中的 LLM Observability 資料送至 Datadog，而不關閉 Bridge。適用於需要在執行環境終止前確保資料已匯出的無伺服器環境。

清空採盡力而為的方式：dd-trace 透過背景寫入器傳送 LLM Observability 資料，無法等待請求完成。因此，要求 dd-trace 清空後，`flush()` 會等待 `flushGraceMs`（預設 2000 毫秒），再清空 APM Exporter。每次送出新資料的清空都會產生完整的等待時間，因此無伺服器處理程式若每次請求都等待 `flush()`，每次請求也都會等待。若短暫執行的程序所產生的 span 未出現在 Datadog，可延長等待時間；若有其他機制讓程序持續執行，可設為 `0` 略過等待。

### `shutdown` {/* #shutdown */}

```typescript oxfmt:false
async shutdown(): Promise<void>
```

強制結束未正確關閉的 APM span，並清空待傳送的 LLM Observability 資料。接著停用整合並清除所有內部狀態。

## 使用範例 {/* #usage-examples */}

### 基本用法 {/* #basic-usage */}

```typescript
import tracer from 'dd-trace'

tracer.init({
  service: process.env.DD_SERVICE || 'my-mastra-app',
  env: process.env.DD_ENV || 'production',
})

import { Mastra } from '@mastra/core'
import { Observability } from '@mastra/observability'
import { DatadogBridge } from '@mastra/datadog'

const mastra = new Mastra({
  observability: new Observability({
    configs: {
      default: {
        serviceName: 'my-mastra-app',
        bridge: new DatadogBridge({
          mlApp: process.env.DD_LLMOBS_ML_APP!,
        }),
      },
    },
  }),
  agents: { myAgent },
})
```

### 無 Agent 模式（僅 LLM Observability，無本機 Agent） {/* #agentless-mode-llm-observability-only-no-local-agent */}

若沒有本機 Datadog Agent，且只需要 LLM Observability 資料，請啟用無 Agent 模式：

```typescript
new DatadogBridge({
  mlApp: process.env.DD_LLMOBS_ML_APP!,
  apiKey: process.env.DD_API_KEY!,
  agentless: true,
})
```

注意：無 Agent 模式無法傳送 APM 資料。若只需要 LLM Observability 資料，而不需要 `dd-trace` APM，[Datadog Exporter](/reference/observability/tracing/exporters/datadog) 較簡單。

### 與其他 Exporter 搭配使用 {/* #with-additional-exporters */}

Bridge 可與非 Datadog Exporter 搭配，將 trace 傳送至其他目的地：

```typescript
import { Mastra } from '@mastra/core'
import { Observability, MastraStorageExporter } from '@mastra/observability'
import { DatadogBridge } from '@mastra/datadog'

const mastra = new Mastra({
  observability: new Observability({
    configs: {
      default: {
        serviceName: 'my-mastra-app',
        bridge: new DatadogBridge({
          mlApp: process.env.DD_LLMOBS_ML_APP!,
        }),
        exporters: [
          new MastraStorageExporter(), // Studio access
        ],
      },
    },
  }),
})
```

:::note
請勿在同一設定中同時使用 `DatadogBridge` 與 `DatadogExporter`。兩者都會將資料傳送至 LLM Observability，導致同一筆資料寫入兩次。
:::

## 設定要求 {/* #setup-requirements */}

DatadogBridge 必須在其他 import 之前初始化 `dd-trace`，讓自動插樁在載入 HTTP、資料庫與框架程式庫時完成修補。

完整設定步驟（包括 dd-trace 初始化、打包工具的 external 設定及 Agent 設定）請參閱 [DatadogBridge 指南](/integrations/observability/datadog#bridge)。

## 跨距映射 {/* #span-mapping */}

Mastra span 類型會對應至 Datadog LLM Observability span 類別：

| Mastra SpanType | Datadog 類別 |
| - | - |
|`AGENT_RUN` | `agent` |
| `MODEL_GENERATION` | `workflow` |
| `MODEL_STEP` | `llm` |
| `TOOL_CALL` | `tool` |
| `MCP_TOOL_CALL` | `tool` |
| `WORKFLOW_RUN` | `workflow` |
| 其他所有類型 | `task` |

## 標籤支援 {/* #tags-support */}

`tracingOptions.tags` 的值會成為結構化的 LLM Observability 註解標籤：`key:value` 項目拆成鍵值配對，不含冒號的標籤則設為 `true`。

```typescript
const result = await agent.generate('Hello', {
  tracingOptions: {
    tags: ['production', 'instance_name:career-scout-api'],
  },
})
```

這會產生：

```json
{
  "production": true,
  "instance_name": "career-scout-api"
}
```

## 環境變數 {/* #environment-variables */}

橋接器從這些環境變數中讀取配置：

|變數|描述 |
| - | - |
| `DD_API_KEY` | Datadog API 金鑰（僅無 Agent 模式需要） |
| `DD_LLMOBS_ML_APP` | ML 應用程式名稱 |
| `DD_SITE` | Datadog 站台 |
| `DD_ENV` | 環境名稱 |
| `DD_LLMOBS_AGENTLESS_ENABLED` | 設為 `'true'` 或 `'1'` 可啟用無 Agent 模式 |
