# Agents API

Agents API 提供了與 Mastra AI Agent程式互動的方法，包括產生回應和串流互動。它還提供了管理AgentTool的方法。

## 獲取所有Agent {/* #getting-all-agents */}

檢索所有可用Agent的清單：

```typescript
const agents = await mastraClient.listAgents()
```

將Agent ID 記錄傳回其序列化Agent程式配置。

## 與特定Agent商合作 {/* #working-with-a-specific-agent */}

透過 ID 取得特定Agent的實例：

```typescript title="src/mastra/agents/my-agent.ts"
import { Agent } from '@mastra/core/agent'

export const myAgent = new Agent({
  id: 'my-agent',
})
```

```typescript
const agent = mastraClient.getAgent('my-agent')
```

## Agent 方法 {/* #agent-methods */}

### `details()` {/* #details */}

檢索有關Agent的詳細資訊：

```typescript
const details = await agent.details()
```

### `generate()` {/* #generate */}

從Agent程式產生回應：

```typescript
const response = await agent.generate(
  [
    {
      role: 'user',
      content: 'Hello, how are you?',
    },
  ],
  {
    memory: {
      thread: 'thread-abc', // Optional: Thread ID for conversation context
      resource: 'user-123', // Optional: Resource ID
    },
    structuredOutput: {}, // Optional: Structured Output configuration
  },
)
```

您也可以使用帶有記憶體選項的簡化字串格式：

```typescript
const response = await agent.generate('Hello, how are you?', {
  memory: {
    thread: 'thread-1',
    resource: 'resource-1',
  },
})
```

### `stream()` {/* #stream */}

串流來自Agent程式的回應以進行即時互動：

```typescript
const response = await agent.stream('Tell me a story')

// Process data stream with the processDataStream util
response.processDataStream({
  onChunk: async chunk => {
    console.log(chunk)
  },
})
```

您也可以使用帶有記憶體選項的簡化字串格式：

```typescript
const response = await agent.stream('Tell me a story', {
  memory: {
    thread: 'thread-1',
    resource: 'resource-1',
  },
  clientTools: { colorChangeTool },
})

response.processDataStream({
  onChunk: async chunk => {
    if (chunk.type === 'text-delta') {
      console.log(chunk.payload.text)
    }
  },
})
```

您也可以直接從回應正文中讀取：

```typescript
const reader = response.body.getReader()
while (true) {
  const { done, value } = await reader.read()
  if (done) break
  console.log(new TextDecoder().decode(value))
}
```

#### 取消串流 {/* #cancelling-a-stream */}

取消回應正文將中止底層 HTTP 請求並停止任何待處理的客戶端Tool執行和後續請求：

```typescript
const response = await agent.stream('Tell me a story')
const reader = response.body.getReader()

const { value } = await reader.read()
await reader.cancel('user navigated away')
```

也可以傳入 `abortSignal`，從串流外部取消請求。`streamUntilIdle()`、`resumeStream()`、`resumeStreamUntilIdle()`、`approveToolCall()`、`declineToolCall()`、`generate()` 和 `generateLegacy()` 也支援此選項：

```typescript
const controller = new AbortController()

const response = await agent.stream('Tell me a story', {
  abortSignal: controller.signal,
})

// Later
controller.abort()
```

#### AI SDK相容格式 {/* #ai-sdk-compatible-format */}

若要在客戶端串流處理 `agent.stream(...)` 回應中符合 AI SDK 格式的內容片段，請將 `response.processDataStream` 包裝成 `ReadableStream<ChunkType>`，再使用 `toAISdkStream`：

```typescript title="client-ai-sdk-transform.ts"
import { createUIMessageStream } from 'ai'
import { toAISdkStream } from '@mastra/ai-sdk'
import type { ChunkType, MastraModelOutput } from '@mastra/core/stream'

const response = await agent.stream('Tell me a story')

const chunkStream: ReadableStream<ChunkType> = new ReadableStream<ChunkType>({
  start(controller) {
    response
      .processDataStream({
        onChunk: async chunk => controller.enqueue(chunk as ChunkType),
      })
      .finally(() => controller.close())
  },
})

const uiMessageStream = createUIMessageStream({
  execute: async ({ writer }) => {
    for await (const part of toAISdkStream(chunkStream as unknown as MastraModelOutput, {
      from: 'agent',
    })) {
      writer.write(part)
    }
  },
})

for await (const part of uiMessageStream) {
  console.log(part)
}
```

### `sendMessage()` {/* #sendmessage */}

將使用者輸入傳送至正在執行的 Agent 或閒置的記憶執行緒。搭配 `subscribeToThread()` 使用，客戶端即可呈現因訊息而喚醒或收到訊息的串流。

```typescript
const agent = mastraClient.getAgent('support-agent')

const result = await agent.sendMessage({
  message: {
    contents: 'Also consider the customer note I just added.',
    attributes: { sentFrom: 'web' },
  },
  resourceId: 'user-123',
  threadId: 'thread-abc',
})

console.log(result.runId)
```

`message` 接受字串、文字或檔案片段陣列，或包含 `contents`、`attributes`、`metadata` 和 `providerOptions` 的物件。

### `queueMessage()` {/* #queuemessage */}

將使用者編寫的輸入排隊以供下一個執行緒輪流使用。如果執行緒處於活動狀態，Mastra 將在目前運行完成後啟動新的運行。如果執行緒空閒，Mastra 會立即開始運作。

```typescript
await agent.queueMessage({
  message: 'Also check whether the tests need updates.',
  resourceId: 'user-123',
  threadId: 'thread-abc',
})
```

### `queueSignal()` {/* #queuesignal */}

將帶有類型的訊號加入佇列，供執行緒下一輪處理。排序方式與 `queueMessage()` 相同，並保留訊號的 `type`、`tagName` 和 `attributes`。

```typescript
await agent.queueSignal({
  signal: {
    type: 'reactive',
    tagName: 'skill',
    attributes: { name: 'triage' },
    contents: 'Triage the new issue.',
  },
  resourceId: 'user-123',
  threadId: 'thread-abc',
})
```

### `sendSignal()` {/* #sendsignal */}

向正在執行的 Agent 或記憶執行緒傳送較低階的訊號。此方法適用於不需要儲存至收件匣的系統產生內容，例如回應式提醒或通知類內容。若需要持久保存通知紀錄，請使用伺服器端的 [`Agent.sendNotificationSignal()`](/reference/agents/agent#sendnotificationsignalnotification-options) API。使用者輸入則優先使用 `sendMessage()` 或 `queueMessage()`。

```typescript
const agent = mastraClient.getAgent('support-agent')

const result = await agent.sendSignal({
  signal: {
    type: 'reactive',
    tagName: 'system-reminder',
    contents: 'Also consider the latest customer note.',
  },
  resourceId: 'user-123',
  threadId: 'thread-abc',
})

console.log(result.runId)
```

使用 `ifActive.behavior` 和 `ifIdle.behavior` 控制 Mastra 如何傳送、儲存或捨棄訊號，以及訊號是否喚醒執行緒：

```typescript
await agent.sendSignal({
  signal: { type: 'reactive', tagName: 'system-reminder', contents: 'Store this for later.' },
  resourceId: 'user-123',
  threadId: 'thread-abc',
  ifIdle: {
    behavior: 'persist',
  },
})
```

若喚醒閒置執行緒的串流需要模型設定、Tool 或執行階段內容等選項，請傳入 `ifIdle.streamOptions`：

```typescript
await agent.sendSignal({
  signal: { type: 'reactive', tagName: 'system-reminder', contents: 'Start from this signal.' },
  resourceId: 'user-123',
  threadId: 'thread-abc',
  ifIdle: {
    behavior: 'wake',
    streamOptions: {
      maxSteps: 3,
    },
  },
})
```

傳回 `{ accepted: true, runId: string }`。

### `subscribeToThread()` {/* #subscribetothread */}

訂閱記憶執行緒的原始串流區塊。執行緒可能由 `sendMessage()`、`queueMessage()`、`sendSignal()` 或伺服器端通知派送啟動或繼續執行；可透過此訂閱呈現其輸出。

```typescript
const agent = mastraClient.getAgent('support-agent')

const subscription = await agent.subscribeToThread({
  resourceId: 'user-123',
  threadId: 'thread-abc',
})

await subscription.processDataStream({
  onChunk: chunk => {
    console.log(chunk)
  },
  reconnect: true,
})
```

傳入 `withInitialHistory: true`（或 `{ perPage }`），即可在第一個 `thread-history` 區塊中收到已儲存的訊息，無須另行擷取歷史紀錄。之後不會重播已完成的執行，因此重新連線時不會再次串流已完成的回應。

在 React SDK 中，`useChat()` 會透過 `initialHistoryPagination` 提供第一頁的 `hasMore` 標記，讓你無須再次請求歷史紀錄，就能決定是否提供載入更早訊息的選項：

```typescript
import { useChat } from '@mastra/react'

const { messages, initialHistoryPagination } = useChat({
  agentId: 'support-agent',
  resourceId: 'user-123',
  threadId: 'thread-abc',
  enableThreadSignals: true,
  withInitialHistory: { perPage: 20 },
})

// { hasMore: true }: older messages exist
// { hasMore: false }: the page reaches the start of the thread
// undefined: history is disabled, still loading, or the subscription ended
```

`initialHistoryPagination` 僅描述目前 Agent、資源、執行緒及 `withInitialHistory` 值所對應的初始訂閱頁面。即時輸出或 `setMessages()` 都不會改變它。自行載入更早的頁面後，請使用那些回應中的 `hasMore` 值。

`subscribeToThread()` 會傳回底層的 `Response` 和 `processDataStream()` 輔助方法。此方法會持續讀取訂閱串流，直到連線關閉或請求遭到中止。傳入 `reconnect: true`，即可在傳輸連線關閉或重新連線請求失敗時重新訂閱，例如代理伺服器因閒置逾時而關閉連線後。若重新連線請求回傳 4xx 狀態碼（例如 `401` 或 `403`）或 `501`，`processDataStream()` 會停止重試，並以原始 `MastraClientError` 拒絕請求；`408` 和 `429` 仍會重試。

訂閱物件也提供 `abort(options?)` 和 `unsubscribe()`。`await subscription.abort({ clearPendingSignals: true })` 會請求中止執行並清除待處理訊號，但不會關閉訂閱。省略此旗標則會保留待處理輸入。`unsubscribe()` 會關閉訂閱，但不會中止執行。

### `abortRun(runId)` {/* #abortrunrunid */}

透過 ID 請求取消持久執行，包括沒有記憶執行緒的執行。取消回應本文或觸發客戶端層級的 `abortSignal`，只會讓觀察端與持久執行中斷連線。傳入串流方法的單次呼叫 `abortSignal` 則會請求取消執行。若未使用該訊號，請呼叫 `abortRun()` 停止執行。

```typescript
const runId = crypto.randomUUID()
const response = await agent.stream('Research this topic', { runId })

// When the user chooses Stop:
const { aborted } = await agent.abortRun(runId)
```

<PropertiesTable content={[{ name: 'runId', type: 'string', description: '要取消的持久執行 ID。' }]} />

傳回 `{ aborted: boolean }`。遠端中止請求是非同步的，因此 `true` 不代表執行程序已停止。未知或已完成的執行會傳回 `false`。此方法要求使用具持久執行能力的 Agent，並具備 Agent 執行權限；執行歸屬檢查同樣適用。啟用細緻授權後，具有記憶執行緒的執行還需要 `memory:write` 權限。非持久執行 Agent 會傳回 HTTP 501。

### `abortThread()` {/* #abortthread */}

請求取消執行緒中正在進行的執行。設定 `clearPendingSignals: true`，可在中止前清除待處理訊號。

```typescript

  resourceId: 'user-123',
  threadId: 'thread-abc',
  clearPendingSignals: true,
})
```

### `cancelQueuedMessages()` {/* #cancelqueuedmessages */}

取消選定的待處理訊號而不停止活動運作。該操作涵蓋處理此請求的伺服器進程上共享相同記憶體執行緒的Agent之間的待處理輸入。與核心方法不同，SDK 只接受訊號 ID，而不接受`queueOwnerId`.

```typescript
const { cancelledSignalIds } = await agent.cancelQueuedMessages({
  resourceId: 'user-123',
  threadId: 'thread-abc',
  signalIds: ['signal-123', 'signal-456'],
})
```

傳回 `{ cancelledSignalIds: string[] }`，列出接收請求的伺服器處理程序中各個已取消一次的 ID。回應不包含遠端確認。已交由執行程序或其他實例處理的訊號不在其中。若 ID 清單缺失、為空或超過數量上限，會傳回 HTTP 400。兩種取消方式都受執行緒歸屬限制。

伺服器透過其共享的 PubSub 後端發布所有請求的 ID，即使接收進程中沒有任何待處理的 ID。然後，其他訂閱的實例可以刪除匹配的掛起輸入，但這種盡力而為的非同步傳播不會確認遠端取消。取消不會撤銷已儲存的訊息、狀態更新、通知記錄或接受確認。它不會取消繼續`continueWithMessages()`.

伺服器必須使用支援整個執行緒取消及中止時清除訊號的核心版本。升級 `@mastra/server` 時，也請一併升級 `@mastra/core`。不受支援的請求會傳回 HTTP 501，不會使用舊版的取消行為。啟用細緻授權時，兩種取消方式除了 Agent 執行權限外，還需要該執行緒的 `memory:write` 權限。

### `streamUntilIdle()` {/* #streamuntilidle */}

以串流傳回回應，並保持串流開啟，直到執行期間派送的所有[背景任務](/docs/harness/background-tasks)完成。每項任務完成後，伺服器都會重新進入 Agent 迴圈，讓 LLM 在同一次呼叫中回應任務結果。此方法需要在 [Mastra 執行個體上啟用背景任務](/reference/configuration#backgroundtasks)，並提供記憶執行緒；否則會使用一般的 `stream()` 呼叫。

```typescript
const response = await agent.streamUntilIdle('Research solana for me', {
  memory: {
    thread: 'thread-1',
    resource: 'resource-1',
  },
  maxIdleMs: 5 * 60_000, //optional
})

response.processDataStream({
  onChunk: async chunk => {
    if (chunk.type === 'background-task-completed') {
      console.log('task complete:', chunk.payload.taskId)
    }
  },
})
```

### `resumeStreamUntilIdle()` {/* #resumestreamuntilidle */}

使用自訂資料恢復暫停的 Agent 串流，並保持串流開啟，直到執行期間派送的所有[背景任務](/docs/harness/background-tasks)完成。可用於在暫停點後繼續執行，例如 Agent 內的 Workflow 暫停。此方法需要在 [Mastra 執行個體上啟用背景任務](/reference/configuration#backgroundtasks)，並提供記憶執行緒；否則會使用一般的 `resumeStream()` 呼叫：

```typescript
const response = await agent.resumeStreamUntilIdle(
  { approved: true, selectedOption: 'plan-b' },
  {
    memory: {
      thread: 'thread-1',
      resource: 'resource-1',
    },
    runId: 'run-123',
    toolCallId: 'tool-call-456', // optional
    maxIdleMs: 5 * 60_000, //optional
  },
)

await response.processDataStream({
  onChunk: chunk => {
    console.log(chunk)
  },
})
```

此串流會輸出與 `stream()` 相同的區塊型別，另加用於任務生命週期事件的 `background-task-*` 區塊。完整的伺服器端 API 請參閱 [`Agent.streamUntilIdle()`](/reference/streaming/agents/streamUntilIdle)；資料格式請參閱[背景任務區塊](/reference/streaming/ChunkType#background-task-chunks)。

### `network()` {/* #network */}

來自Agent網路的串流響應以進行多Agent互動：

```typescript
const response = await agent.network('Research this topic and write a summary')

response.processDataStream({
  onChunk: async chunk => {
    console.log(chunk)
  },
})
```

### `listSuspendedRuns()` {/* #listsuspendedruns */}

從儲存空間列出 Agent 暫停中的執行，包括等待 Tool 呼叫核准或因 Tool 暫停而等待的執行。這項查詢以儲存空間為基礎，因此伺服器重新啟動後，或從其他伺服器執行個體查詢時仍可使用。將傳回的 `runId` 傳入 `approveToolCall()`、`declineToolCall()` 或 `resumeStream()`。

```typescript
const { runs, total } = await agent.listSuspendedRuns({
  threadId: 'thread-456',
  resourceId: 'user-123',
})

if (runs[0]) {
  console.log(runs[0].toolCalls) // [{ toolCallId, toolName, args, requiresApproval }]
  await agent.approveToolCall({
    runId: runs[0].runId,
    toolCallId: runs[0].toolCalls[0].toolCallId,
  })
}
```

可使用選用的篩選條件（`threadId`、`resourceId`、`fromDate`、`toDate`）及分頁參數（`perPage`、`page`）。傳回 `{ runs, total }`，其中 `total` 是分頁前符合條件的執行數量。傳回的執行資料格式請參閱 [`Agent.listSuspendedRuns()`](/reference/agents/listSuspendedRuns)。

### `approveToolCall()` {/* #approvetoolcall */}

批准待處理的Tool呼叫並返回連續流。當您渲染批准回應中復原的區塊時，請使用此選項。

```typescript
const response = await agent.approveToolCall({
  runId: 'run-123',
  toolCallId: 'tool-call-456',
})

response.processDataStream({
  onChunk: async chunk => {
    console.log(chunk)
  },
})
```

### `sendToolApproval()` {/* #sendtoolapproval */}

核准或拒絕已訂閱執行緒中待處理的 Tool 呼叫。若希望恢復後的區塊透過現有執行緒訂閱送達，而非另開後續串流，請搭配 `subscribeToThread()` 使用。

```typescript
const result = await agent.sendToolApproval({
  resourceId: 'user-123',
  threadId: 'thread-456',
  toolCallId: 'tool-call-456',
  approved: true,
})

console.log(result.accepted)
```

傳回 `{ accepted: true, runId: string, toolCallId?: string }`。

### `declineToolCall()` {/* #declinetoolcall */}

拒絕待處理的 Tool 呼叫並傳回後續串流。若要呈現拒絕回應中恢復的區塊，請使用此方法。可傳入選用的 `reason`，告知模型拒絕原因。預設值為 `Tool call was not approved by the user`。

```typescript
const response = await agent.declineToolCall({
  runId: 'run-123',
  toolCallId: 'tool-call-456',
  reason: 'This file is outside the allowed directory', // optional
})

response.processDataStream({
  onChunk: async chunk => {
    console.log(chunk)
  },
})
```

### `resumeStream()` {/* #resumestream */}

使用自訂資料恢復暫停的Agent程式流。使用它可以在暫停點後繼續執行，例如Agent內的Workflow暫停：

```typescript
const response = await agent.resumeStream(
  { approved: true, selectedOption: 'plan-b' },
  {
    runId: 'run-123',
    toolCallId: 'tool-call-456', // optional
  },
)

await response.processDataStream({
  onChunk: chunk => {
    console.log(chunk)
  },
})
```

### `approveToolCallGenerate()` {/* #approvetoolcallgenerate */}

使用 `generate()`（非串流）時，核准待處理的 Tool 呼叫。此方法會傳回完整回應：

```typescript
const output = await agent.generate('Find user John', {
  requireToolApproval: true,

if (output.finishReason === 'suspended') {
```

使用 `generate()`（非串流）時，拒絕待處理的 Tool 呼叫。此方法會傳回完整回應：

## 客戶端Tool {/* #client-tools */}

客戶端Tool可讓您在Agent請求時在客戶端執行自訂功能。

```typescript
import { createTool } from '@mastra/client-js'
import { z } from 'zod'

const colorChangeTool = createTool({
  id: 'changeColor',
  description: 'Changes the background color',
  inputSchema: z.object({
    color: z.string(),
  }),
  execute: async inputData => {
    document.body.style.backgroundColor = inputData.color
    return { success: true }
  },
})

// Use with generate
const response = await agent.generate('Change the background to blue', {
  clientTools: { colorChangeTool },
})

// Use with stream
const response = await agent.stream('Tell me a story', {
  memory: {
    thread: 'thread-1',
    resource: 'resource-1',
  },
  clientTools: { colorChangeTool },
})

response.processDataStream({
  onChunk: async chunk => {
    if (chunk.type === 'text-delta') {
      console.log(chunk.payload.text)
    } else if (chunk.type === 'tool-call') {
      console.log(
        `calling tool ${chunk.payload.toolName} with args ${JSON.stringify(
          chunk.payload.args,
          null,
          2,
        )}`,
      )
    }
  },
})
```

### 塑造模型的客戶端Tool輸出 {/* #shape-client-tool-output-for-the-model */}

客戶端 Tool 支援透過 `toModelOutput` 控制模型收到的內容，包括圖片等多模態內容。由於客戶端 Tool 在本機執行，對輸出的轉換也會在 `execute` 完成後於客戶端進行。客戶端會將轉換後的輸出和原始結果一併傳回伺服器，讓原始結果仍可供儲存及應用程式邏輯使用。

```typescript
const screenshotTool = createTool({
  id: 'takeScreenshot',
  description: 'Takes a screenshot of the current page',
  inputSchema: z.object({}),
  execute: async () => {
    const base64 = await captureScreenshot()
    return { ok: true, data: base64 }
  },
  toModelOutput: output => ({
    type: 'content',
    value: [{ type: 'media', data: output.data, mediaType: 'image/jpeg' }],
  }),
})
```

### 追蹤客戶端Tool {/* #tracing-client-tools */}

若伺服器已安裝並設定 `@mastra/observability`，客戶端 Tool 會記錄一個 `CLIENT_TOOL_CALL` span，作為目前 `AGENT_RUN` span 的子項。模型發出客戶端 Tool 呼叫時，伺服器會建立此 span，並將 W3C 追蹤載體注入送出的 Tool 呼叫區塊。Tool 參數可用後，此 span 便會結束。若伺服器端未設定可觀測性，客戶端 Tool 的追蹤不會執行任何操作。

客戶端 SDK 也會測量每個客戶端 Tool 的 `execute` 函式實際耗時，並傳回伺服器，以 `toolType: "client"` 的 `mastra_tool_duration_ms` 指標輸出。

若要在 Tool 的 `execute` 函式中取得更完整的遙測資料，請使用執行內容中的 `observe` 輔助方法，加入子 span 和結構化日誌：

```typescript
import { createTool } from '@mastra/client-js'
import { z } from 'zod'

const fetchUserTool = createTool({
  id: 'fetchUser',
  description: 'Fetches the current user profile',
  inputSchema: z.object({ userId: z.string() }),
  execute: async ({ userId }, { observe }) => {
    observe.log('info', 'fetching user', { userId })
    const user = await observe.span('http GET /users', async () => {
      const res = await fetch(`/api/users/${userId}`)
      return res.json()
    })
    return user
  },
})
```

`observe` 一律可用：若目前沒有有效的追蹤內容（例如在受追蹤的 Agent 之外執行），`span` 會直接執行函式，而 `log` 不會執行任何操作。無須進行空值檢查。

SDK 會將收集器緩衝的所有內容序列化為 OTLP/JSON，並在下一次請求的本文中傳回。伺服器端的 `@mastra/observability` 套件會驗證各個 span 是否屬於正確的追蹤（避免跨追蹤注入），再將各個 span 和日誌轉送至伺服器端遙測使用的同一個可觀測性匯流排。設定可觀測性後，現有的匯出器便會自動接收這些資料。

## 儲存Agent {/* #stored-agents */}

已儲存的 Agent 是保存在資料庫中的 Agent 設定，可在執行階段建立、更新及刪除。它們以鍵參照 Tool、Workflow、其他 Agent 和評分器；建立 Agent 實例時，這些項目會從 Mastra 登錄表中解析。記憶功能則以 `SerializedMemoryConfig` 物件直接設定，可指定 `lastMessages` 和 `semanticRecall` 等選項。

### `listStoredAgents()` {/* #liststoredagents */}

檢索所有儲存Agent程式的分頁清單：

```typescript
const result = await mastraClient.listStoredAgents()
console.log(result.agents) // Array of stored agents
console.log(result.total) // Total count
```

具有分頁和排序功能：

```typescript
const result = await mastraClient.listStoredAgents({
  page: 0,
  perPage: 20,
  orderBy: {
    field: 'createdAt',
    direction: 'DESC',
  },
})
```

### `createStoredAgent()` {/* #createstoredagent */}

建立一個新的儲存Agent：

```typescript
const agent = await mastraClient.createStoredAgent({
  id: 'my-agent',
  name: 'My Assistant',
  instructions: 'You are a helpful assistant.',
  model: {
    provider: 'openai',
    name: 'gpt-5.4',
  },
})
```

預設情況下，`createStoredAgent()` 會立即發布初始版本。將 `autoPublish` 設為 `false`，即可建立尚未發布的草稿，供你在呼叫 [`activateVersion()`](#activateversion) 前檢閱：

```typescript
const draft = await mastraClient.createStoredAgent({
  id: 'draft-agent',
  name: 'Draft Assistant',
  instructions: 'You are a helpful assistant.',
  model: {
    provider: 'openai',
    name: '__AI_SDK_OPENAI_MODEL_BASE__',
  },
  autoPublish: false,
})
```

以 `code` 作為來源的編輯器一律會發布初始版本，因為儲存操作會將 Agent 設定寫入檔案系統。

具有所有選項：

```typescript
const agent = await mastraClient.createStoredAgent({
  id: 'full-agent',
  name: 'Full Agent',
  description: 'A fully configured agent',
  instructions: 'You are a helpful assistant.',
  model: {
    provider: 'openai',
    name: 'gpt-5.4',
  },
  tools: { calculator: {}, weather: {} },
  workflows: { 'data-processing': {} },
  agents: { 'subagent-1': {} },
  memory: {
    options: {
      lastMessages: 20,
      semanticRecall: false,
    },
  },
  scorers: {
    'quality-scorer': {
      sampling: { type: 'ratio', rate: 0.1 },
    },
  },
  defaultOptions: {
    maxSteps: 10,
  },
  metadata: {
    version: '1.0',
    team: 'engineering',
  },
  durable: true,
})
```

#### 儲存Agent程式的可恢復流 {/* #resumable-streams-for-stored-agents */}

設定 `durable`，即可為還原後的一般 Agent 設定[可恢復串流](/docs/agents/resumable-streams)。傳入 `true` 可啟用串流，傳入 `false` 可停用；也可傳入物件，調整串流清理方式：

```typescript
const agent = await mastraClient.createStoredAgent({
  id: 'durable-agent',
  name: 'Durable Agent',
  instructions: 'You are a helpful assistant.',
  model: {
    provider: 'openai',
    name: 'gpt-5.4',
  },
  durable: { cleanupTimeoutMs: 0 },
})
```

此處僅接受可序列化的選項；快取和 pubsub 會沿用伺服器的 `Mastra` 執行個體設定。現有的已儲存 Agent 若設為 `durable: true`，此欄位也僅用於可恢復串流。若要保留持久執行及檢查點復原功能，請註冊以 `createDurableAgent({ agent })` 包裝的程式碼 Agent。
