# 資料集API

資料集 API 公開了 Mastra 的資料集和實驗路線`MastraClient`。它包括呼叫者驅動的實驗方法和實驗刪除方法。呼叫者驅動的方法讓您擁有的編排器（例如臨時Workflow）驅動實驗循環，而 Mastra 充當記錄系統。建立實驗，然後讓 Mastra 在伺服器端執行每個項目`runExperimentItem`或攝取您自己計算的結果`submitExperimentResult`，並在運行完成後呼叫 Finalize。

專案運行、結果提交和最終確定可以安全地重試。只有當請求包含呼叫者提供的內容時，才能安全地重試創建`id`; without one, each retry creates a new experiment.

* `createDatasetExperiment`在呼叫者提供的上是冪等的`id`
* `runExperimentItem`和`submitExperimentResult` upsert on `(experimentId, itemId, attempt)`
* `finalizeExperiment`如果實驗已完成，則傳回儲存的記錄

## 使用範例 {/* #usage-example */}

```typescript
import { MastraClient } from '@mastra/client-js'

const client = new MastraClient({
  baseUrl: 'http://localhost:4111',
})

// 1. Create the experiment. Pass your orchestrator's run ID so a
//    retried workflow converges on the same experiment.
const { experimentId, totalItems, datasetVersion } = await client.createDatasetExperiment({
  datasetId: 'clinical-triage-evals',
  id: 'temporal-wf-run-42',
  targetType: 'agent',
  targetId: 'triage-agent',
  scorerIds: ['clinical-judge'],
})

// 2. Run one item per activity. Mastra executes the agent, runs the
//    scorers, and upserts the result. Retried activities converge on
//    a single row per (experimentId, itemId, attempt).
const { result, scores } = await client.runExperimentItem({
  datasetId: 'clinical-triage-evals',
  experimentId,
  itemId: 'item-1',
})

// 3. Finalize. The server computes succeeded/failed/skipped counts
//    from the persisted rows.
const experiment = await client.finalizeExperiment({
  datasetId: 'clinical-triage-evals',
  experimentId,
})
```

對於純粹攝取，創建實驗時無需`targetType`/`targetId` and replace step 2 with `submitExperimentResult`.

## 完成實驗（） {/* #finalizeexperiment */}

標記調用者驅動的實驗已完成。伺服器透過計算持久結果行中的每個項目計數來為呼叫者處理簿記：`succeededCount` (at least one attempt without an error), `failedCount` (every attempt errored), and `skippedCount` (never submitted). Idempotent: finalizing an already-completed experiment returns the stored record.

## 刪除資料集實驗() {/* #deletedatasetexperiment */}

透過其資料集刪除實驗。伺服器刪除實驗的Observability跟踪，包括其跨度和追蹤連結訊號，然後刪除實驗及其結果記錄。不受支援的儲存會留下痕跡，並且伺服器會記錄警告。如果因任何其他原因刪除痕跡失敗，則承諾將被拒絕，並且 Mastra 會保留實驗及其結果記錄，儘管某些痕跡可能已被刪除。

```typescript
await client.deleteDatasetExperiment('dataset-id', 'experiment-id', {
  organizationId: 'organization-id',
  projectId: 'project-id',
})
```

## 清除資料集項目() {/* #purgedatasetitem */}

從現有資料集歷史記錄和連結的實驗結果中擦除項目的內容，包括結果標籤和註釋，同時保留版本歷史記錄、實驗計數器和審核狀態。稍後提交的項目結果將與經過編輯的內容一起存儲，並且稍後的數據集項目更新將被拒絕。

```typescript
await client.purgeDatasetItem('dataset-id', 'item-id', {
  organizationId: 'organization-id',
  projectId: 'project-id',
})
```

可選的第三個參數將清除範圍限定為租戶組織和專案。伺服器回`404` when the dataset doesn't belong to that scope or the item has no history in the dataset.

退貨`Promise<{ success: boolean }>`. The operation is idempotent and can't be undone. Purge serializes or conflicts with concurrent dataset item writers without guaranteeing which operation completes first. If a mutating item update loses the race, storage re-reads the purge marker and rejects it with `DATASET_ITEM_PURGED`. Deletes remain idempotent, and any deletion tombstone created during the race stays redacted. MongoDB storage requires a replica set or sharded deployment with transaction support. See [`dataset.purgeItem()`](/reference/datasets/purgeItem) for the complete purge behavior.
