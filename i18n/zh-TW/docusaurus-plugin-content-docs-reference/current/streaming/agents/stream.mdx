# Agent.stream()

`.stream()` 方法可即時串流傳回 Agent 回應，提供更多功能與彈性的格式。它接受訊息及選用的串流選項，既支援 Mastra 原生格式，也相容於 AI SDK v5 及更新版本。

## 使用範例 {/* #usage-example */}

```ts
const stream = await agent.stream('message for agent')
```

:::note

**模型相容性**：此方法適用於 V2 模型。V1 模型應使用 [`.streamLegacy()`](./streamLegacy)。框架會自動偵測模型版本；若版本不符，就會擲出錯誤。

:::

## `stopWhen`錯誤 {/* #stopwhen-errors */}

如果 `stopWhen` 謂詞拋出錯誤，`fullStream` 會以該錯誤拒絕，而不會為此次失敗發出 `step-finish`、`finish` 或 `error` 資料區塊。請在消費流時捕獲該拒絕：

```ts
async function consumeStream() {
  try {
    for await (const chunk of stream.fullStream) {
      console.log(chunk)
    }
  } catch (error) {
    console.error('stopWhen failed', error)
  }
}
```

持久傳輸會根據序列化後的錯誤名稱和訊息重建跨進程錯誤。流的消費方無法取得原始堆棧、cause 或子類身份。

## 訊號可見性 {/* #signal-visibility */}

默認情況下，信號（包括回應式提醒）會出現在 `fullStream` 中。設定 `hideSignals` 可從流中省略指定的信號資料區塊：

```ts
const stream = await agent.stream('Review the latest changes', {
  hideSignals: ['reactive', 'system-reminder'],
})

for await (const chunk of stream.fullStream) {
  console.log(chunk)
}
```

設定 `hideSignals: true` 可隱藏所有已識別的信號類型；設定 `hideSignals: false` 可顯示全部信號；傳入陣列則只隱藏指定類型。

陣列可包含 `user`、`state`、`reactive`、`notification`，以及舊別名 `user-message` 和 `system-reminder`。省略該選項、傳入 `false` 或 `[]` 均不會排除任何信號。流式處理會先將 `system-reminder` 正規化為 `reactive`，將 `user-message` 正規化為 `user`，再匹配 `data-signal`、`data-user-message` 或 `data-user-message-pending` 資料區塊中編碼的信號類型。未知或格式錯誤的信號資料區塊，以及文本、錯誤和完成事件，都會照常透過。

排除規則在 `experimentalTransform` 之後應用，因此轉換函式仍會收到未篩選的輸入。消費 `fullStream` 的適配器會繼承該篩選規則，但聚合的 `content`、`getFullOutput()`、響應訊息、回呼、模型脈絡和已保存訊息均不受影響。

每個[對話串訂閱](/reference/agents/agent#subscribetothreadoptions)都有獨立的排除規則，不受啟動該流時的設定影響。

相同規則也適用於 `resumeStream()`、`untilIdle` 後續回合，以及已棄用的 `streamUntilIdle()` 和 `resumeStreamUntilIdle()`，包括持久化 Agent。共用執行選項亦支援 `hideSignals`，可用於 `generate()` 和 `resumeGenerate()`，但不會篩選其傳回結果。HTTP 或 client-js 請求選項及舊版 `streamLegacy()` API 均不支援此選項。

與流式處理不同，為兼容舊行為，[Memory 召回](/reference/memory/recall)默認隱藏提醒。召回的排除規則會直接匹配儲存的類型，不會正規化別名。使用 `['reactive', 'system-reminder']` 可在不同介面中同時排除兩種提醒表示。

排除規則只控制傳回的資料，不影響授權或投遞，因此不構成安全邊界。`ifActive`、`ifIdle`、`persist`/`discard` 和 `transient` 等信號選項仍保持各自的投遞與持久化語義。

## 中止運行 {/* #aborting-a-run */}

傳入 [`abortSignal`](#parameters)，即可從 Agent 外部中止執行：

```ts
const controller = new AbortController()
const stream = await agent.stream('Summarize this repo', { abortSignal: controller.signal })

setTimeout(() => controller.abort(), 5_000)
```

中止執行時的行為：

* **流會發出 `abort` 資料區塊。** Signal 觸發後，執行會在下次檢查時停止，`fullStream` 會發出 `abort` 資料區塊。執行狀態以 `aborted` 結束原因為“已取消”；`onAbort` 會收到中止前已完成的步驟，以及目前步驟截至目前已流出的 assistant 文本。
* **中止採用協作方式。** 它在執行內部的下次檢查時生效，不會強行停止已在執行的工具代碼或 `onOutput` 鈎子；它們啟動的副作用仍可能完成。
* **使用者已看到的文本會保存。** 如果 Memory 可寫，中止前流出的 assistant 文本會作為普通 assistant 訊息持久化到對話串中，不包含錯誤部分。被取消的執行仍會經過輸出處理器，因此處理器拋出的錯誤仍可能影響保存；未進入處理器的輸出不會持久化。

如果已無法取得執行句柄，可使用 `runId` 呼叫 [`durableAgent.abortRunStream(runId)`](/reference/agents/durable-agent#abortrunstreamrunid)，以相同方式結束執行。

### Mastra 格式（預設） {/* #mastra-format-default */}

```ts title="index.ts"
const stream = await agent.stream('Tell me a story', {

}

// or access full stream

  console.log(chunk)
}

// Get full text after streaming
const fullText = await stream.text
```

### 限制執行時間 {/* #limiting-execution-time */}

透過 `modelSettings.timeout` 限制執行時長。`totalMs` 限制整個執行，包括每次循環迭代、工具呼叫和重試；`stepMs` 限制單次模型呼叫，涵蓋建立流連線和消費流的時間；`firstChunkMs` 僅適用於流式呼叫，限制模型發出首個含內容資料區塊的等待時間。

```ts title="index.ts"
const stream = await agent.stream('Tell me a story', {
  modelSettings: {
    timeout: {
      totalMs: 30000, // fail the run if it takes longer than 30s
      stepMs: 10000, // fail an individual model call after 10s
      firstChunkMs: 3000, // fail a model call that produces no content within 3s
    },
  },
})
```

超出時間預算會拋出 `MastraTimeoutError`，其 `timeoutType` 為 `'total'`、`'step'` 或 `'firstChunk'`。設定回退 [`models`](/reference/agents/agent) 時，各預算的行為不同：

* `totalMs` 超時會立即結束執行，不會嘗試下一個模型，因為它是整個執行的硬性截止時間。
* `stepMs` 超時不會在同一個模型上重試，但會嘗試下一個模型，可用於在 Provider 響應緩慢時故障轉移。
* `firstChunkMs` 超時與 `stepMs` 類似：不會在同一模型上重試，但會嘗試下一個模型。流開始和元資料資料區塊不算滿足該預算；只有首個文本、推理、工具呼叫、文件或來源資料區塊才算。開始輸出內容後，僅 `stepMs` 和 `totalMs` 繼續生效。每次 Provider 重試都會重新計算 `firstChunkMs` 預算。

呼叫時設定的嵌套 `timeout` 與各模型的 `modelSettings` 會按鍵合併，因此模型級 `stepMs` 覆蓋值不會清除呼叫級的 `firstChunkMs`。

### AI SDK v5+ 格式 {/* #ai-sdk-v5-format */}

若要將流用於 AI SDK v5 及以上版本，可使用 `toAISdkStream` 工具函數進行轉換。

```ts title="index.ts"
import { stepCountIs, createUIMessageStreamResponse } from 'ai'
import { toAISdkStream } from '@mastra/ai-sdk'

const stream = await agent.stream('Tell me a story', {
  stopWhen: stepCountIs(3), // Stop after 3 steps
  modelSettings: {
    temperature: 0.7,
  },

// In an API route for frontend integration
return createUIMessageStreamResponse({
  stream: toAISdkStream(stream, { from: 'agent' }),
})
```

### 使用回調 {/* #using-callbacks */}

所有回呼函數現在都可作為頂層屬性傳入，便於使用。

```ts title="index.ts"
const stream = await agent.stream('Tell me a story', {
  onFinish: result => {
    console.log('Streaming finished:', result)
  },
  onStepFinish: step => {
    console.log('Step completed:', step)
  },
  onChunk: chunk => {
    console.log('Received chunk:', chunk)
  },
  onError: ({ error }) => {
    console.error('Streaming error:', error)
  },
  onAbort: ({ steps, text }) => {
    console.log('Stream aborted after', steps.length, 'steps')
    console.log('Partial text:', text)
  },
})

// Process the stream
for await (const chunk of stream.textStream) {
  console.log(chunk)
}
```

```ts title="index.ts"
    new BatchPartsProcessor({ maxBatchSize: 3, maxWaitTime: 100 }),
  ],
})
```

## 回應 WebSocket 傳輸 {/* #responses-websocket-transport */}

透過 Provider 選項啟用 Responses WebSocket 流式傳輸。它只適用於流式呼叫，支援直接使用 OpenAI 模型和 Azure OpenAI Responses 部署。如果 WebSocket 流不可用，Mastra 會回退到 HTTP 流式傳輸。默認情況下，流結束後 Mastra 會關閉 WebSocket。

```ts title="index.ts"
const stream = await agent.stream('Hello', {
  providerOptions: {
    openai: {
      transport: 'websocket', // 'websocket' | 'fetch' | 'auto'
      websocket: {
        url: 'wss://api.openai.com/v1/responses',
        closeOnFinish: true, // default
      },
    },
  },
})
```

對於 Azure OpenAI，先將網關設定為 `useResponsesAPI: true`，再使用 `providerOptions.azure.transport`。

```ts title="index.ts"
const stream = await agent.stream('Hello', {
  providerOptions: {
    azure: {
      transport: 'websocket',
      store: false,
      websocket: { closeOnFinish: true },
    },
  },
})
```

若要在流結束後保持連線開啟，請設定 `closeOnFinish: false`，並在使用完畢後手動關閉。

```ts title="index.ts"
const stream = await agent.stream('Hello', {
  providerOptions: {
    openai: {
      transport: 'websocket',
      websocket: { closeOnFinish: false },
    },
  },
})

// Later, when you're done with the connection:
stream.transport?.close()
```

Responses WebSocket 連線一次只能處理一個響應。對於同一個 WebSocket 傳輸，Mastra 會拒絕同時包含 `previous_response_id` 的後續請求。請等目前流完成，再傳送響應鏈中的下一輪請求。
