# 模型 Provider

Mastra 提供統一介面，讓你透過單一 API 使用多個 Provider 的 LLM，並存取來自 223 個 Provider 的 8285 個模型。

## 功能 {/* #features */}

- **一個 API 適用所有模型**：不必安裝及管理額外的 Provider 相依套件，即可存取任何模型。

- **使用最新 AI**：無論模型來自哪個 Provider，發布後即可使用。Mastra 不綁定特定 Provider 的介面可避免供應商鎖定。

- [**混用模型**](#mix-and-match-models)：針對不同工作選用不同模型。例如，先以 GPT-5-mini 處理大型上下文，再切換至 Claude Opus 4.6 執行推理工作。

- [**模型備援**](#model-fallbacks)：如果某個 Provider 服務中斷，Mastra 可在應用程式層自動切換到其他 Provider；相較於 API 閘道，這種方式可盡量降低延遲。

## 基本用法 {/* #basic-usage */}

無論使用 OpenAI、Anthropic、Google，或 OpenRouter 等閘道，只要將模型指定為 `"provider/model-name"`，其餘部分由 Mastra 處理。

Mastra 會讀取對應的環境變數（例如 `ANTHROPIC_API_KEY`），並將請求路由至對應的 Provider。如果缺少 API 金鑰，執行階段錯誤會明確指出需要設定哪個變數。

## 混用模型 {/* #mix-and-match-models */}

有些模型速度較快但能力較弱，另一些則提供較大的上下文視窗或更強的推理能力。你可以依工作需求，使用同一 Provider 的不同模型，或跨 Provider 混用模型。

## 動態選擇模型 {/* #dynamic-model-selection */}

模型本質上是字串，因此你可以依據[請求上下文](/docs/server/request-context)、變數或其他邏輯動態選擇模型。

```typescript title="src/mastra/agents/dynamic-assistant-agent.ts"
import { Agent } from "@mastra/core/agent";

const agent = new Agent({
  id: "dynamic-assistant",
  name: "Dynamic Assistant",
  model: ({ requestContext }) => {
    const provider = requestContext.get("provider-id");
    const model = requestContext.get("model-id");
    return `${provider}/${model}`;
  },
});
```

這可實現以下實用模式：

- A/B 測試——比較模型在正式環境中的表現。
- 由使用者選擇模型——讓使用者在應用程式中選擇偏好的模型。
- 多租戶應用程式——每位客戶都可以使用自己的 API 金鑰和模型偏好。

## Provider 專屬選項 {/* #provider-specific-options */}

不同模型 Provider 會提供各自的設定選項。使用 OpenAI 時，可以調整 `reasoningEffort`；使用 Anthropic 時，可以調整 `cacheControl`。Mastra 支援在 Agent 層級或單一訊息中設定這些特定的 `providerOptions`。

```typescript title="src/mastra/agents/planner-agent.ts"
import { Agent } from "@mastra/core/agent";

// Agent level (apply to all future messages)
const planner = new Agent({
  id: "planner",
  name: "Planner",
  instructions: {
    role: "system",
    content: "You are a helpful assistant.",
    providerOptions: {
      openai: { reasoningEffort: "low" }
    }
  },
  model: "__GATEWAY_OPENAI_MODEL__",
});

const lowEffort =
  await planner.generate("Plan a simple 3 item dinner menu");

// Message level (apply only to this message)
const highEffort = await planner.generate([
  {
    role: "user",
    content: "Plan a simple 3 item dinner menu for a celiac",
    providerOptions: {
      openai: { reasoningEffort: "high" }
    }
  }
]);
```

## 模型備援 {/* #model-fallbacks */}

只依賴單一模型會讓應用程式產生單點故障。模型備援可在模型和 Provider 之間自動容錯移轉。如果主要模型無法使用，系統會依序使用已設定的備援模型重試請求，直到成功。

```typescript title="src/mastra/agents/resilient-assistant-agent.ts"
import { Agent } from '@mastra/core/agent';

const agent = new Agent({
  id: 'resilient-assistant',
  name: 'Resilient Assistant',
  instructions: 'You are a helpful assistant.',
  model: [
    {
      model: "__GATEWAY_OPENAI_MODEL__",
      maxRetries: 3,
    },
    {
      model: "__GATEWAY_ANTHROPIC_MODEL_SONNET__",
      maxRetries: 2,
    },
    {
      model: "__GATEWAY_GOOGLE_MODEL_FLASH__",
      maxRetries: 2,
    },
  ],
});
```

Mastra 會先嘗試主要模型。如果遇到 500 錯誤、速率限制或逾時，系統會自動切換至第一個備援模型；如果仍然失敗，則繼續切換至下一個。切換前，每個模型都會依各自的重試次數重試。

使用者不會感受到服務中斷：回應格式維持不變，只是改由其他模型傳回。系統沿備援鏈切換時會保留錯誤內容，在維持串流相容性的同時確保錯誤能清楚傳遞。

### 個別模型設定 {/* #per-model-settings */}

每個備援項目都可以設定自己的 `modelSettings`、`providerOptions` 和 `headers`。如果備援鏈中的模型需要不同的 temperature 或 Provider 專屬參數才能產生可比較的輸出，這會很有幫助。

```typescript title="src/mastra/agents/tuned-resilient-agent.ts"
import { Agent } from '@mastra/core/agent';

const agent = new Agent({
  id: 'tuned-resilient',
  name: 'Tuned Resilient Agent',
  instructions: 'You are a helpful assistant.',
  model: [
    {
      model: '__GATEWAY_GOOGLE_MODEL_FLASH__',
      maxRetries: 2,
      modelSettings: { temperature: 0.3 },
      providerOptions: { google: { thinkingConfig: { thinkingBudget: 0 } } },
    },
    {
      model: '__GATEWAY_OPENAI_MODEL_LUNA__',
      maxRetries: 2,
      modelSettings: { temperature: 0.7 },
      providerOptions: { openai: { reasoningEffort: 'low' } },
    },
  ],
});
```

**優先順序：**

- `modelSettings` 和 `providerOptions`：個別備援項目會覆寫呼叫時選項，而呼叫時選項會覆寫 Agent 的 `defaultOptions`。`modelSettings` 依鍵進行淺層合併；`providerOptions` 則遞迴深層合併，因此巢狀 Provider 設定（例如 `google.thinkingConfig`）可在各層保留同層鍵。
- `headers`：呼叫時的 `modelSettings.headers` 會覆寫個別備援項目的 `headers`，後者又會覆寫從模型路由器模型擷取的標頭。執行階段標頭（追蹤、驗證和租戶資訊）會刻意優先於模型層級標頭。

每個欄位也接受以 `requestContext` 為參數的函式，與動態模型的解析方式一致。

## 在 Mastra 中使用本機模型 {/* #use-local-models-with-mastra */}

Mastra 也支援在自有硬體上執行 `gpt-oss`、`Qwen3`、`DeepSeek` 等多種本機模型。執行本機模型的應用程式必須提供與 OpenAI 相容的 API 伺服器，供 Mastra 連線。我們建議使用 [LMStudio](https://lmstudio.ai/)（請參閱[執行 LMStudio 伺服器](https://lmstudio.ai/docs/developer/core/server)）。

對於自訂的 OpenAI 相容端點，`id` 是 Mastra 透過模型路由器傳送的路由格式。

如果遠端服務的行為類似直接 Provider，並且預期收到 `llama3.2` 這類不含命名空間的模型名稱，請使用 `provider/model`。

如果遠端服務的行為類似模型閘道，且上游模型命名空間包含 Provider，請使用 `gateway/provider/model`，例如 `mastra/google/gemini-2.5-flash` 或 `openrouter/google/gemini-2.5-flash`。

為 Mastra 的 `model` 設定 `url` 時，**務必**使用 OpenAI 相容端點的基礎 URL，而不是個別聊天端點。

```typescript title="src/mastra/agents/my-agent.ts"
import { Agent } from "@mastra/core/agent";

const agent = new Agent({
  id: "my-agent",
  name: "My Agent",
  instructions: "You are a helpful assistant",
  model: {
    id: "custom/my-qwen3-model",
    url: "http://your-custom-openai-compatible-endpoint.com/v1"
  }
})
```

如果遠端服務的行為類似模型閘道，請在 `id` 中加入閘道前綴：
```typescript title="src/mastra/agents/my-agent.ts"
import { Agent } from "@mastra/core/agent";

const agent = new Agent({
  id: "my-agent",
  name: "My Agent",
  instructions: "You are a helpful assistant",
  model: {
    id: "mastra/google/gemini-2.5-flash",
    url: "http://your-custom-openai-compatible-endpoint.com/v1"
  }
})
```

### 選擇 OpenAI Responses API {/* #select-the-openai-responses-api */}

自訂 `url` 端點預設使用 OpenAI Chat Completions API。如果端點公開 OpenAI Responses API（`/v1/responses`），例如需要在閘道上將函式工具與推理模型搭配使用，請設定 `api: "responses"`。

```typescript title="src/mastra/agents/my-agent.ts"
import { Agent } from "@mastra/core/agent";

const agent = new Agent({
  id: "my-agent",
  name: "My Agent",
  instructions: "You are a helpful assistant",
  model: {
    id: "custom/my-model",
    url: "http://your-custom-openai-compatible-endpoint.com/v1",
    api: "responses"
  }
})
```

省略 `api` 時，預設值為 `"chat"`，因此現有設定不受影響。

### 自訂端點的 Provider 選項 {/* #provider-options-for-custom-endpoints */}

傳遞到自訂端點的 `providerOptions` 鍵取決於該端點使用的 API。

在預設 Chat Completions 路徑上，請使用模型 `id` 的第一段作為鍵。對於 `id: "lmstudio/qwen/qwen3-30b-a3b-2507"`，鍵是 `lmstudio`；對於 `id: "openrouter/google/gemini-2.5-flash"`，鍵是 `openrouter`。也可以使用 camelCase 形式，例如 `id: "my-server/my-model"` 對應 `myServer`。如果該段包含句點，請使用第一個句點之前的部分。

如果 `id` 以已啟用閘道的前綴開頭，則屬於例外情況：此時使用前綴後的第一段作為鍵。Netlify 閘道一律啟用，因此 `id: "netlify/openai/gpt-4o"` 的鍵是 `openai`。設定 `MASTRA_GATEWAY_API_KEY` 或設定含 API 金鑰的 `MastraGateway` 後，`id: "mastra/google/gemini-2.5-flash"` 使用 `google`。

`reasoningEffort` 等型別化選項會對應至相應的請求欄位（`reasoning_effort`）。`parallel_tool_calls` 等其他鍵會依原樣複製到請求本文中，並覆寫 AI SDK 先前設定的同名欄位，包括 `model`、來自 `modelSettings` 的 `temperature`，以及結構化輸出的 `response_format`。`reasoning_effort`、`verbosity`、`messages`、`tools` 和 `tool_choice` 會在這些鍵之後設定；串流傳輸時，`stream` 和 `stream_options` 也會隨後設定，因此無法用這種方式覆寫。前兩個欄位應改用 `reasoningEffort` 和 `textVerbosity`。

```typescript title="src/mastra/agents/my-agent.ts"
import { Agent } from "@mastra/core/agent";

const agent = new Agent({
  id: "my-agent",
  name: "My Agent",
  instructions: "You are a helpful assistant",
  model: {
    id: "lmstudio/qwen/qwen3-30b-a3b-2507",
    url: "http://localhost:1234/v1"
  }
})
```

呼叫 Agent 時，請將選項放在 `lmstudio` 鍵下：

```typescript
const response = await agent.generate("Hello", {
  providerOptions: {
    lmstudio: {
      reasoningEffort: "low",
      parallel_tool_calls: false
    }
  }
})
```

除非其他鍵與從 `id` 得出的鍵一致，否則其行為如下：

- `openaiCompatible`：僅套用型別化選項 `user`、`reasoningEffort`、`textVerbosity` 和 `strictJsonSchema`；其下的其他鍵會被捨棄。`openai-compatible` 寫法已棄用，雖然仍可使用，但會在結果中加入警告。
- `openai`：在 Chat Completions 路徑上會被忽略，除非 `openai` 本身就是從 `id` 得出的鍵，例如 `openai/my-model` 或 `openai.foo/my-model`；此時其行為與上述說明一致。使用 `api: "responses"` 時，無論 `id` 前綴為何，都只有 `openai` 生效。該路徑只接受 OpenAI Provider 的型別化選項（例如 `parallelToolCalls`），`parallel_tool_calls` 等其他鍵會被捨棄。

不適用鍵下的選項會直接被捨棄，且不會發出警告。如果某個選項未影響請求，請先檢查所使用的鍵。
