# 模型Provider

Mastra 提供了一個統一的介面，用於與多個Provider的法學碩士合作，讓您可以透過單一 API 存取來自 223 個Provider的 8285 個模型。

## 特徵 {/* #features */}

* **適用於任何型號的一個 API**：存取任何模型，無需安裝和管理額外的Provider依賴項。

* **訪問最新的人工智慧**：新模型發布後立即使用，無論它們來自哪個Provider。透過 Mastra 與Provider無關的介面避免Provider鎖定。

* [**混搭模型**](#mix-and-match-models)：針對不同的任務使用不同的模型。例如，執行 GPT-5-mini 進行大上下文處理，然後切換到 Claude Opus 4.6 進行推理任務。

* [**模型後備**](#model-fallbacks)：如果某個Provider遇到中斷，Mastra 可以在應用程式層級自動切換到另一個Provider，與 API 閘道相比，最大限度地減少延遲。

## 基本用法 {/* #basic-usage */}

無論您使用的是 OpenAI、Anthropic、Google 還是 OpenRouter 等網關，請將模型指定為`"provider/model-name"` and Mastra handles the rest.

Mastra 讀取相關的環境變數（例如`ANTHROPIC_API_KEY`) and routes requests to the provider. If an API key is missing, you'll get a clear runtime error showing exactly which variable to set.

## 混搭模型 {/* #mix-and-match-models */}

有些模型速度更快，但能力較差，而有些模型則提供更大的上下文視窗或更強的推理能力。使用來自同一Provider的不同模型，或跨Provider混合搭配以適應每項任務。

// Use a cost-effective model for document processing

## 動態模型選擇 {/* #dynamic-model-selection */}

由於模型只是字串，因此您可以根據[request context](/docs/server/request-context), variables, or any other logic.

```typescript title="src/mastra/agents/dynamic-assistant-agent.ts"
import { Agent } from "@mastra/core/agent";

const agent = new Agent({
  id: "dynamic-assistant",
  name: "Dynamic Assistant",
  model: ({ requestContext }) => {
    const provider = requestContext.get("provider-id");
    const model = requestContext.get("model-id");
    return `${provider}/${model}`;
  },
});
```

這使得強大的模式成為可能：

* A/B 測試 - 比較生產中的模型性能。
* 使用者可選擇的模型 - 讓使用者在您的應用程式中選擇他們喜歡的模型。
* 多租戶應用程式 - 每個客戶都可以攜帶自己的 API 金鑰和模型首選項。

## 特定於Provider的選項 {/* #provider-specific-options */}

不同的模型Provider公開自己的配置選項。使用 OpenAI，您可以調整`reasoningEffort`. With Anthropic, you might tune `cacheControl`. Mastra lets you set these specific `providerOptions` either at the agent level or per message.

```typescript title="src/mastra/agents/planner-agent.ts"
import { Agent } from "@mastra/core/agent";

// Agent level (apply to all future messages)
const planner = new Agent({
  id: "planner",
  name: "Planner",
  instructions: {
    role: "system",
    content: "You are a helpful assistant.",
    providerOptions: {
      openai: { reasoningEffort: "low" }
    }
  },
  model: "__GATEWAY_OPENAI_MODEL__",
});

const lowEffort =
  await planner.generate("Plan a simple 3 item dinner menu");

// Message level (apply only to this message)
const highEffort = await planner.generate([
  {
    role: "user",
    content: "Plan a simple 3 item dinner menu for a celiac",
    providerOptions: {
      openai: { reasoningEffort: "high" }
    }
  }
]);
```

## 模型後備 {/* #model-fallbacks */}

依賴單一模型會為您的應用程式帶來單點故障。模型回退提供模型和Provider之間的自動故障轉移。如果主要模型不可用，則會針對下一個配置的回退重試請求，直到成功為止。

```typescript title="src/mastra/agents/resilient-assistant-agent.ts"
import { Agent } from '@mastra/core/agent';

const agent = new Agent({
  id: 'resilient-assistant',
  name: 'Resilient Assistant',
  instructions: 'You are a helpful assistant.',
  model: [
    {
      model: "__GATEWAY_OPENAI_MODEL__",
      maxRetries: 3,
    },
    {
      model: "__GATEWAY_ANTHROPIC_MODEL_SONNET__",
      maxRetries: 2,
    },
    {
      model: "__GATEWAY_GOOGLE_MODEL_FLASH__",
      maxRetries: 2,
    },
  ],
});
```

Mastra 首先嘗試您的主要模型。如果遇到 500 錯誤、速率限製或逾時，它會自動切換到您的第一個後備。如果這也失敗了，它就會轉移到下一個。每個模型在繼續之前都有自己的重試次數。

您的用戶永遠不會遇到中斷 - 回應以相同的格式返回，只是來自不同的模型。當系統通過回退鏈時，錯誤上下文將被保留，確保乾淨的錯誤傳播，同時保持流相容性。

### 每個模型的設置 {/* #per-model-settings */}

每個後備條目可以攜帶自己的`modelSettings`, `providerOptions`, and `headers` — useful when models in the chain need different temperatures or provider-specific knobs to produce comparable output.

```typescript title="src/mastra/agents/tuned-resilient-agent.ts"
import { Agent } from '@mastra/core/agent';

const agent = new Agent({
  id: 'tuned-resilient',
  name: 'Tuned Resilient Agent',
  instructions: 'You are a helpful assistant.',
  model: [
    {
      model: '__GATEWAY_GOOGLE_MODEL_FLASH__',
      maxRetries: 2,
      modelSettings: { temperature: 0.3 },
      providerOptions: { google: { thinkingConfig: { thinkingBudget: 0 } } },
    },
    {
      model: '__GATEWAY_OPENAI_MODEL_LUNA__',
      maxRetries: 2,
      modelSettings: { temperature: 0.7 },
      providerOptions: { openai: { reasoningEffort: 'low' } },
    },
  ],
});
```

**優先：**

* `modelSettings`和`providerOptions`: per-fallback entry overrides call-time options, which override agent `defaultOptions`. `modelSettings` shallow-merges by key. `providerOptions` deep-merges recursively, so nested provider config (e.g. `google.thinkingConfig`) preserves sibling keys across layers.
* `headers`: 通話時間`modelSettings.headers` overrides per-fallback `headers`, which overrides headers extracted from model-router models. Runtime headers (tracing, auth, tenancy) intentionally take precedence over model-level headers.

每個字段也接受一個函數`requestContext`, matching how dynamic models are resolved.

## 將本地模型與 Mastra 結合使用 {/* #use-local-models-with-mastra */}

Mastra 也支援本地模型，例如`gpt-oss`, `Qwen3`, `DeepSeek` and many more that you run on your own hardware. The application running your local model needs to provide an OpenAI-compatible API server for Mastra to connect to. We recommend using [LMStudio](https://lmstudio.ai/) (see [Running the LMStudio server](https://lmstudio.ai/docs/developer/core/server)).

`id` is the routing form that Mastra sends through the model router.

使用`provider/model` when the remote behaves like a direct provider and expects a bare model name such as `llama3.2`.

使用`gateway/provider/model` when the remote behaves like a model gateway and the upstream model namespace includes the provider, such as `mastra/google/gemini-2.5-flash` or `openrouter/google/gemini-2.5-flash`.

對於`url` it's **important** that you use the base URL of the OpenAI-compatible endpoint with Mastra's `model` setting and not the individual chat endpoints.

```typescript title="src/mastra/agents/my-agent.ts"
import { Agent } from "@mastra/core/agent";

const agent = new Agent({
  id: "my-agent",
  name: "My Agent",
  instructions: "You are a helpful assistant",
  model: {
    id: "custom/my-qwen3-model",
    url: "http://your-custom-openai-compatible-endpoint.com/v1"
  }
})
```

如果遙控器的行為類似於模型網關，請將網關前綴包含在`id`:

```typescript title="src/mastra/agents/my-agent.ts"
import { Agent } from "@mastra/core/agent";

const agent = new Agent({
  id: "my-agent",
  name: "My Agent",
  instructions: "You are a helpful assistant",
  model: {
    id: "mastra/google/gemini-2.5-flash",
    url: "http://your-custom-openai-compatible-endpoint.com/v1"
  }
})
```

### 選擇 OpenAI 響應 API {/* #select-the-openai-responses-api */}

風俗`url` endpoints use the OpenAI Chat Completions API by default. If your endpoint exposes the OpenAI Responses API (`/v1/responses`) — for example to combine function tools with reasoning models on gateways that require it — set `api: "responses"`.

```typescript title="src/mastra/agents/my-agent.ts"
import { Agent } from "@mastra/core/agent";

const agent = new Agent({
  id: "my-agent",
  name: "My Agent",
  instructions: "You are a helpful assistant",
  model: {
    id: "custom/my-model",
    url: "http://your-custom-openai-compatible-endpoint.com/v1",
    api: "responses"
  }
})
```

什麼時候`api` is omitted it defaults to `"chat"`, so existing configurations are unchanged.

### 自訂端點的Provider選項 {/* #provider-options-for-custom-endpoints */}

這`providerOptions` key that reaches a custom endpoint depends on the API it uses.

在預設的聊天完成路徑上，使用模型的第一段`id` as the key. For `id: "lmstudio/qwen/qwen3-30b-a3b-2507"`, the key is `lmstudio`, and for `id: "openrouter/google/gemini-2.5-flash"`, it's `openrouter`. A camelCase form also works, for example `myServer` for `id: "my-server/my-model"`. If the segment contains a period, use the part before the first period.

例外的是`id` that starts with the prefix of an enabled gateway, where the key is the segment after the prefix. Netlify's gateway is always enabled, so for `id: "netlify/openai/gpt-4o"`, the key is `openai`. When `MASTRA_GATEWAY_API_KEY` is set or a `MastraGateway` with an API key is configured, `id: "mastra/google/gemini-2.5-flash"` uses `google`.

輸入選項，例如`reasoningEffort` are mapped to their request field (`reasoning_effort`). Other keys, such as `parallel_tool_calls`, are copied into the request body as written. They replace any field of the same name that the AI SDK sets before them, including `model`, `temperature` from `modelSettings`, and the structured-output `response_format`. `reasoning_effort`, `verbosity`, `messages`, `tools`, and `tool_choice` are set after them, as are `stream` and `stream_options` when streaming, so those can't be replaced this way. Use `reasoningEffort` and `textVerbosity` instead of the first two.

```typescript title="src/mastra/agents/my-agent.ts"
import { Agent } from "@mastra/core/agent";

const agent = new Agent({
  id: "my-agent",
  name: "My Agent",
  instructions: "You are a helpful assistant",
  model: {
    id: "lmstudio/qwen/qwen3-30b-a3b-2507",
    url: "http://localhost:1234/v1"
  }
})
```

傳遞下面的選項`lmstudio` when you call the agent:

```typescript
const response = await agent.generate("Hello", {
  providerOptions: {
    lmstudio: {
      reasoningEffort: "low",
      parallel_tool_calls: false
    }
  }
})
```

其他鍵的行為有所不同，除非它們與`id`:

* `openaiCompatible`：僅套用鍵入的選項`user`, `reasoningEffort`, `textVerbosity`, and `strictJsonSchema`. Other keys under it are dropped. The `openai-compatible` spelling is deprecated. It still works but adds a warning to the result.
* `openai`：在聊天完成路徑上被忽略，除非`openai` is itself the key from the `id`, as in `openai/my-model` or `openai.foo/my-model`. Then it works as described above. With `api: "responses"`, only `openai` applies, whatever the `id` prefix. On that path it takes only the OpenAI provider's typed options, such as `parallelToolCalls`, and other keys, such as `parallel_tool_calls`, are dropped.

不適用的按鍵下的選項將被刪除，且不會發出警告。如果某個選項對請求沒有影響，請先檢查金鑰。
