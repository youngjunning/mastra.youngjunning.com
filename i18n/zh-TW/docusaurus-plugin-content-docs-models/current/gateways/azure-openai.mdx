Azure OpenAI 透過具有安全性、合規性和 SLA 保證的專用部署提供對 OpenAI 模型的企業級存取。

與其他具有固定模型名稱的Provider不同，Azure 使用**deployment names** that you configure in the Azure Portal.

## 用法 {/* #usage */}

預設情況下，未註冊 Azure OpenAI 網關。在您的 Mastra 實例上註冊它，並註冊在同一實例上使用它的Agent程式。否則`azure-openai/...` model IDs fail with `Could not find config for provider azure-openai`.

在Agent程式的模型 ID 中引用您的 Azure 部署名稱：

```typescript title="src/mastra/agents/my-agent.ts"
import { Agent } from "@mastra/core/agent";

export const myAgent = new Agent({
  id: "my-agent",
  name: "My Agent",
  instructions: "You are a helpful assistant",
  model: "azure-openai/my-gpt-5-4-deployment", // Use your Azure deployment name (autocompleted in dev mode)
});
```

註冊網關和Agent：

```typescript title="src/mastra/index.ts"
import { Mastra } from "@mastra/core";
import { AzureOpenAIGateway } from "@mastra/core/llm";
import { myAgent } from "./agents/my-agent";

export const mastra = new Mastra({
  gateways: {
    "azure-openai": new AzureOpenAIGateway({
      resourceName: "my-openai-resource",
      apiKey: process.env.AZURE_API_KEY!,
      deployments: ["my-gpt-5-4-deployment"],
    }),
  },
  agents: { myAgent },
});
```

從 Mastra 實例取得Agent並呼叫它：

```typescript
const agent = mastra.getAgent("myAgent");

// Generate a response
const response = await agent.generate("Hello!");

// Stream a response
const stream = await agent.stream("Tell me a story");
for await (const chunk of stream) {
  console.log(chunk);
}
```

看[Configuration](#configuration) for other authentication and deployment discovery options.

查看[Azure OpenAI model availability](https://learn.microsoft.com/en-us/azure/ai-services/openai/concepts/models) for region-specific options.

## Azure 部署的工作原理 {/* #how-azure-deployments-work */}

Azure 模型 ID 遵循下列模式：`azure-openai/your-deployment-name`

部署名稱是**specific to your Azure account** and chosen when you create a deployment in Azure Portal. Common examples:

* `azure-openai/my-gpt-5-4-deployment`
* `azure-openai/production-gpt-5-4`
* `azure-openai/staging-gpt-5-4-mini`

## 設定 {/* #setup */}

建立部署於[Azure OpenAI Studio](https://oai.azure.com/). The resource name and API key are in Azure Portal under "Keys and Endpoint".

### Microsoft Entra ID 驗證 {/* #microsoft-entra-id-authentication */}

當為 Azure OpenAI 資源停用 API 金鑰時，請使用 Microsoft Entra ID 驗證。傳遞任何與 Azure SDK 相容的憑證，例如`DefaultAzureCredential` from `@azure/identity`.

安裝`@azure/identity` in your Mastra project if you use `DefaultAzureCredential`.

```typescript
import { DefaultAzureCredential } from "@azure/identity";
import { Mastra } from "@mastra/core";
import { AzureOpenAIGateway } from "@mastra/core/llm";

export const mastra = new Mastra({
  gateways: {
    "azure-openai": new AzureOpenAIGateway({
      resourceName: "my-openai-resource",
      authentication: {
        type: "entraId",
        credential: new DefaultAzureCredential(),
      },
      deployments: ["gpt-5-4-prod", "gpt-5-4-mini-dev"],
    }),
  },
});
```

身分需要呼叫 Azure OpenAI 的權限，例如`Cognitive Services OpenAI User` role.

對於特定的託管身份，透過`ManagedIdentityCredential` instead.

```typescript
import { ManagedIdentityCredential } from "@azure/identity";

const credential = new ManagedIdentityCredential("client-id");
```

### Azure 回應 API {/* #azure-responses-api */}

Azure OpenAI 透過以下方式支援回應 API`v1` API path used by the AI SDK Azure provider. Set `useResponsesAPI: true` when your Azure resource and deployment support that route. The gateway then uses `apiVersion: "v1"` and `useDeploymentBasedUrls: false` by default.

```typescript
import { Mastra } from "@mastra/core";
import { AzureOpenAIGateway } from "@mastra/core/llm";

export const mastra = new Mastra({
  gateways: {
    "azure-openai": new AzureOpenAIGateway({
      resourceName: "my-openai-resource",
      apiKey: process.env.AZURE_API_KEY!,
      useResponsesAPI: true,
      deployments: ["my-gpt-5-4-deployment"],
    }),
  },
});
```

保持`useResponsesAPI` omitted or set it to `false` for the existing Azure chat completions route. That path keeps `apiVersion: "2024-04-01-preview"` and deployment-based URLs by default for compatibility.

您仍然可以配置`apiVersion` and `useDeploymentBasedUrls` directly. For example, set `useDeploymentBasedUrls: false` to use the Azure `v1` URL shape with the chat model constructor; the gateway defaults `apiVersion` to `"v1"` for that route. Passing `apiVersion: "v1"` by itself keeps the existing deployment-based URL default for compatibility.

不要合併`useResponsesAPI: true` with `useDeploymentBasedUrls: true`; the gateway rejects that configuration because Responses API support uses the Azure `v1` route.

使用`apiVersion: "v1"` for the GA `v1` route. Microsoft currently exposes preview `v1` features through feature-specific headers, such as `"aoai-evals": "preview"`, or through preview/alpha API paths. The gateway still accepts `apiVersion: "preview"` with `useDeploymentBasedUrls: false` for Azure provider configurations that require the preview query value. Date-based API versions are only for the legacy deployment-based route, so the gateway rejects them when `useResponsesAPI` is `true` or `useDeploymentBasedUrls` is `false`.

相同的 API 金鑰和 Microsoft Entra ID 驗證模式可與`v1` route.

### Azure 回應 WebSocket 傳輸 {/* #azure-responses-websocket-transport */}

Azure OpenAI 也支援回應 API 上的 WebSocket 模式。將其用於具有許多模型Tool往返的Agent或Tool循環。為單次請求和簡短對話保留標準 HTTP 傳輸。

WebSocket 傳輸需要`useResponsesAPI: true`, because Azure exposes it on the `v1` Responses path. Then opt in per stream request with `providerOptions.azure.transport: "websocket"`.

```typescript
import { Agent } from "@mastra/core/agent";

const agent = new Agent({
  id: "azure-ws-agent",
  name: "Azure WebSocket Agent",
  instructions: "Use tools when they are useful.",
  model: "azure-openai/my-gpt-5-4-deployment",
});

const stream = await agent.stream("Find and improve the slow function.", {
  providerOptions: {
    azure: {
      transport: "websocket",
      store: false,
      websocket: {
        closeOnFinish: false,
      },
    },
  },
});

for await (const chunk of stream.textStream) {
  process.stdout.write(chunk);
}

stream.transport?.close();
```

放`closeOnFinish: false` when you want to keep the socket open across follow-up turns. Azure keeps one response chain in connection-local memory, so continuing from the most recent `previous_response_id` can reduce continuation latency. The connection runs one response at a time and does not multiplex parallel runs.

不要發送重疊的後續請求`previous_response_id` on the same WebSocket transport. Mastra rejects overlapping continuation requests because Azure only keeps one in-flight response per connection. Wait for the active stream to finish before continuing the response chain.

### 嚴格的結構化輸出 {/* #strict-structured-output */}

網關發送[structured output](/docs/agents/structured-output) schemas and tool schemas without strict mode by default. Without strict mode the model can leave out keys, and Mastra then fails validation when a required key is missing.

放`providerOptions.azure.strictJsonSchema: true` to have Azure enforce your schema:

```typescript
import { z } from "zod";

const response = await agent.generate("Summarize the ticket.", {
  structuredOutput: {
    schema: z.object({
      summary: z.string(),
      priority: z.enum(["low", "medium", "high"]).optional(),
    }),
  },
  providerOptions: {
    azure: { strictJsonSchema: true },
  },
});
```

啟用嚴格模式後，Mastra 在發送架構之前準備好架構，以便 Azure 接受它們。每個鍵均按必需列出，可選鍵接受`null` and come back as `undefined`, and validation keywords such as `uniqueItems`, `pattern`, and `minimum` move into the field description. Mastra still validates the result against your original schema.

此設定涵蓋輸出架構和請求中的每個Tool，因為網關的 AI SDK 5 Azure Provider對兩者使用一個標誌。 Azure 嚴格模式無法使用自由格式鍵表達對象，例如`z.record()`, so keep strict mode off for agents whose output or tool schemas use them.

這`azure` key applies when `useResponsesAPI` is `true`. On the chat completions route, set `providerOptions.openai.strictJsonSchema` instead.

## 配置參考 {/* #configuration-reference */}

|選項 |類型 |必填|說明 |
|--------|------|----------|-------------|
|`resourceName` | `string` | Yes | Azure OpenAI resource name |
| `apiKey` | `string` | Yes\* | API key from "Keys and Endpoint" |
| `authentication` | `object` | No | Microsoft Entra ID authentication |
| `authentication.type` | `"entraId"` | Yes\* | Authentication mode |
| `authentication.credential` | `TokenCredential` | Yes\* | Azure SDK-compatible credential for `entraId` authentication mode |
| `authentication.scope` | `string` | No | Token scope (default: `https://cognitiveservices.azure.com/.default`) |
| `apiVersion` | `string` | No | API version (default: `2024-04-01-preview`, or `v1` when `useResponsesAPI` is `true` or `useDeploymentBasedUrls` is `false`) |
| `useResponsesAPI` | `boolean` | No | Resolve deployments through the Azure OpenAI Responses API (default: `false`) |
| `useDeploymentBasedUrls` | `boolean`|沒有 |使用基於 Azure 部署的 URL（預設：`true`， 或者`false`什麼時候`useResponsesAPI`是`true`) |
| `deployments` | `string[]`|沒有 |靜態模式的部署名稱 |
|`management` | `object`|沒有 |管理 API 憑證 |
|`management.tenantId` | `string`|是\* | Azure AD 租用戶 ID |
|`management.clientId` | `string`|是\* |服務主體客戶端 ID |
|`management.clientSecret` | `string`|是\* |服務主體秘密 |
|`management.subscriptionId` | `string`|是\* | Azure 订阅 ID |
|`management.resourceGroup` | `string`|是\* |資源組名稱|

\* 提供其中之一`apiKey` or `authentication.type: "entraId"`. Management fields are required if `management` is provided.
