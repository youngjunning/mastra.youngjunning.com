# <img src="https://models.dev/logos/azure.svg" alt="Azure OpenAI 標誌" className="inline w-8 h-8 mr-2 align-middle dark:invert dark:brightness-0 dark:contrast-200" />Azure OpenAI

Azure OpenAI 透過專用部署提供企業級的 OpenAI 模型存取，並提供安全、合規及 SLA 保證。

其他 Provider 使用固定的模型名稱，Azure 則使用你在 Azure Portal 設定的**部署名稱**。

## 用法 {/* #usage */}

Azure OpenAI 閘道預設不會註冊。請將閘道及使用它的 Agent 註冊在同一個 Mastra 執行個體，否則解析 `azure-openai/...` 模型 ID 時會出現 `Could not find config for provider azure-openai` 錯誤。

在 Agent 的模型 ID 中指定 Azure 部署名稱：

```typescript title="src/mastra/agents/my-agent.ts"
import { Agent } from "@mastra/core/agent";

export const myAgent = new Agent({
  id: "my-agent",
  name: "My Agent",
  instructions: "You are a helpful assistant",
  model: "azure-openai/my-gpt-5-4-deployment", // Use your Azure deployment name (autocompleted in dev mode)
});
```

註冊閘道與 Agent：

```typescript title="src/mastra/index.ts"
import { Mastra } from "@mastra/core";
import { AzureOpenAIGateway } from "@mastra/core/llm";
import { myAgent } from "./agents/my-agent";

export const mastra = new Mastra({
  gateways: {
    "azure-openai": new AzureOpenAIGateway({
      resourceName: "my-openai-resource",
      apiKey: process.env.AZURE_API_KEY!,
      deployments: ["my-gpt-5-4-deployment"],
    }),
  },
  agents: { myAgent },
});
```

從 Mastra 執行個體取得 Agent，再呼叫它：

```typescript
const agent = mastra.getAgent("myAgent");

// Generate a response
const response = await agent.generate("Hello!");

// Stream a response
const stream = await agent.stream("Tell me a story");
for await (const chunk of stream) {
  console.log(chunk);
}
```

其他驗證及部署探索方式請參閱[設定](#configuration)。

各區域可用的選項請參閱 [Azure OpenAI 模型可用性](https://learn.microsoft.com/en-us/azure/ai-services/openai/concepts/models)。

## Azure 部署的工作原理 {/* #how-azure-deployments-work */}

Azure 模型 ID 遵循下列模式：`azure-openai/your-deployment-name`

部署名稱**與你的 Azure 帳號相關聯**，請在 Azure Portal 建立部署時指定。常見範例如下：

* `azure-openai/my-gpt-5-4-deployment`
* `azure-openai/production-gpt-5-4`
* `azure-openai/staging-gpt-5-4-mini`

## 設定 {/* #setup */}

在 [Azure OpenAI Studio](https://oai.azure.com/) 建立部署。資源名稱和 API 金鑰可在 Azure Portal 的「Keys and Endpoint」中查看。

## 設定 {/* #configuration */}

建立閘道執行個體並傳入 Mastra。以下是常用的設定方式。

### 靜態部署 {/* #static-deployments */}

提供來自 Azure 入口網站的部署名稱。

```typescript
import { Mastra } from "@mastra/core";
import { AzureOpenAIGateway } from "@mastra/core/llm";

export const mastra = new Mastra({
  gateways: {
    "azure-openai": new AzureOpenAIGateway({
      resourceName: "my-openai-resource",
      apiKey: process.env.AZURE_API_KEY!,
      deployments: ["gpt-5-4-prod", "gpt-5-4-mini-dev"],
    }),
  },
});
```

### 動態探索 {/* #dynamic-discovery */}

提供管理 API 認證資訊後，閘道會查詢 Azure 管理 API 並列出部署。

```typescript
import { Mastra } from "@mastra/core";
import { AzureOpenAIGateway } from "@mastra/core/llm";

export const mastra = new Mastra({
  gateways: {
    "azure-openai": new AzureOpenAIGateway({
      resourceName: "my-openai-resource",
      apiKey: process.env.AZURE_API_KEY!,
      management: {
        tenantId: process.env.AZURE_TENANT_ID!,
        clientId: process.env.AZURE_CLIENT_ID!,
        clientSecret: process.env.AZURE_CLIENT_SECRET!,
        subscriptionId: process.env.AZURE_SUBSCRIPTION_ID!,
        resourceGroup: "my-resource-group",
      },
    }),
  },
});
```

服務主體需要「Cognitive Services User」角色。詳情請參閱 [Azure 文件](https://learn.microsoft.com/en-us/entra/identity-platform/howto-create-service-principal-portal)。

### Microsoft Entra ID 驗證 {/* #microsoft-entra-id-authentication */}

若 Azure OpenAI 資源已停用 API 金鑰，請使用 Microsoft Entra ID 驗證，並傳入與 Azure SDK 相容的認證，例如 `@azure/identity` 提供的 `DefaultAzureCredential`。

若使用 `DefaultAzureCredential`，請在 Mastra 專案安裝 `@azure/identity`。

```typescript
import { DefaultAzureCredential } from "@azure/identity";
import { Mastra } from "@mastra/core";
import { AzureOpenAIGateway } from "@mastra/core/llm";

export const mastra = new Mastra({
  gateways: {
    "azure-openai": new AzureOpenAIGateway({
      resourceName: "my-openai-resource",
      authentication: {
        type: "entraId",
        credential: new DefaultAzureCredential(),
      },
      deployments: ["gpt-5-4-prod", "gpt-5-4-mini-dev"],
    }),
  },
});
```

該身分須具備呼叫 Azure OpenAI 的權限，例如 `Cognitive Services OpenAI User` 角色。

若要指定受控識別，請改傳入 `ManagedIdentityCredential`。

```typescript
import { ManagedIdentityCredential } from "@azure/identity";

const credential = new ManagedIdentityCredential("client-id");
```

### Azure Responses API {/* #azure-responses-api */}

Azure OpenAI 透過 AI SDK Azure Provider 使用的 `v1` API 路徑支援 Responses API。若 Azure 資源與部署支援該路由，請設定 `useResponsesAPI: true`。此時閘道預設使用 `apiVersion: "v1"` 及 `useDeploymentBasedUrls: false`。

```typescript
import { Mastra } from "@mastra/core";
import { AzureOpenAIGateway } from "@mastra/core/llm";

export const mastra = new Mastra({
  gateways: {
    "azure-openai": new AzureOpenAIGateway({
      resourceName: "my-openai-resource",
      apiKey: process.env.AZURE_API_KEY!,
      useResponsesAPI: true,
      deployments: ["my-gpt-5-4-deployment"],
    }),
  },
});
```

若使用既有的 Azure chat completions 路由，請省略 `useResponsesAPI`，或將它設為 `false`。為了維持相容性，該路由預設沿用 `apiVersion: "2024-04-01-preview"` 及依部署產生的 URL。

你仍可直接設定 `apiVersion` 和 `useDeploymentBasedUrls`。例如，在聊天模型的建構函式設定 `useDeploymentBasedUrls: false`，即可使用 Azure `v1` URL 格式。閘道會將該路由的 `apiVersion` 預設為 `"v1"`。若只傳入 `apiVersion: "v1"`，為了維持相容性，仍會預設使用依部署產生的 URL。

請勿同時設定 `useResponsesAPI: true` 和 `useDeploymentBasedUrls: true`。Responses API 採用 Azure `v1` 路由，因此閘道會拒絕此組合。

正式發布的 `v1` 路由請使用 `apiVersion: "v1"`。Microsoft 目前透過功能專用標頭（例如 `"aoai-evals": "preview"`）或 preview/alpha API 路徑提供 `v1` 預覽功能。若 Azure Provider 設定需要 preview 查詢值，閘道仍接受 `apiVersion: "preview"` 搭配 `useDeploymentBasedUrls: false`。日期格式的 API 版本僅適用於舊版部署路由，因此當 `useResponsesAPI` 為 `true` 或 `useDeploymentBasedUrls` 為 `false` 時，閘道會拒絕這些版本。

`v1` 路由也支援相同的 API 金鑰和 Microsoft Entra ID 驗證方式。

### Azure Responses 的 WebSocket 傳輸 {/* #azure-responses-websocket-transport */}

Azure OpenAI 的 Responses API 也支援 WebSocket。若 Agent 或 Tool 迴圈需要讓模型和 Tool 多次往返，可使用此模式。單次請求和簡短對話請沿用標準 HTTP 傳輸。

WebSocket 傳輸需要設定 `useResponsesAPI: true`，因為 Azure 透過 `v1` Responses 路徑提供這項功能。接著，在各個串流請求中使用 `providerOptions.azure.transport: "websocket"` 啟用。

```typescript
import { Agent } from "@mastra/core/agent";

const agent = new Agent({
  id: "azure-ws-agent",
  name: "Azure WebSocket Agent",
  instructions: "Use tools when they are useful.",
  model: "azure-openai/my-gpt-5-4-deployment",
});

const stream = await agent.stream("Find and improve the slow function.", {
  providerOptions: {
    azure: {
      transport: "websocket",
      store: false,
      websocket: {
        closeOnFinish: false,
      },
    },
  },
});

for await (const chunk of stream.textStream) {
  process.stdout.write(chunk);
}

stream.transport?.close();
```

若要在後續對話輪次維持連線，請設定 `closeOnFinish: false`。Azure 會在連線的本機記憶體保留一條回應鏈，從最近的 `previous_response_id` 接續可降低延遲。每條連線一次只能處理一個回應，無法透過多工平行處理。

請勿在同一條 WebSocket 連線上使用 `previous_response_id` 同時傳送多個接續請求。Azure 每條連線一次只處理一個回應，因此 Mastra 會拒絕重疊的請求。請等目前的串流結束，再接續回應鏈。

### 嚴格結構化輸出 {/* #strict-structured-output */}

閘道預設以非嚴格模式傳送[結構化輸出](/docs/agents/structured-output)和 Tool 的 schema。模型可能省略欄位，若缺少必填欄位，Mastra 驗證就會失敗。

設定 `providerOptions.azure.strictJsonSchema: true`，由 Azure 強制依照 schema 產生輸出：

```typescript
import { z } from "zod";

const response = await agent.generate("Summarize the ticket.", {
  structuredOutput: {
    schema: z.object({
      summary: z.string(),
      priority: z.enum(["low", "medium", "high"]).optional(),
    }),
  },
  providerOptions: {
    azure: { strictJsonSchema: true },
  },
});
```

啟用嚴格模式後，Mastra 會先調整 schema 以符合 Azure 的要求。所有欄位都會列為必填，原本可選的欄位可回傳 `null`，再由 Mastra 轉回 `undefined`。`uniqueItems`、`pattern` 和 `minimum` 等驗證關鍵字會移到欄位說明中。Mastra 仍會依照原始 schema 驗證結果。

閘道使用的 AI SDK 5 Azure Provider 以同一個開關控制輸出 schema 和請求中的各個 Tool。Azure 嚴格模式無法表示 `z.record()` 這類允許任意鍵的物件。若 Agent 的輸出或 Tool schema 需要這類物件，請保持嚴格模式關閉。

`useResponsesAPI` 為 `true` 時適用 `azure` 鍵。若使用 chat completions 路由，請改設 `providerOptions.openai.strictJsonSchema`。

## 設定參考 {/* #configuration-reference */}

|選項 |類型 |必填|說明 |
|--------|------|----------|-------------|
| `resourceName` | `string` | 是 | Azure OpenAI 資源名稱 |
| `apiKey` | `string` | 是\* | 「Keys and Endpoint」中的 API 金鑰 |
| `authentication` | `object` | 否 | Microsoft Entra ID 驗證 |
| `authentication.type` | `"entraId"` | 是\* | 驗證模式 |
| `authentication.credential` | `TokenCredential` | 是\* | 適用於 `entraId` 驗證模式的 Azure SDK 相容認證 |
| `authentication.scope` | `string` | 否 | Token 範圍（預設值為 `https://cognitiveservices.azure.com/.default`） |
| `apiVersion` | `string` | 否 | API 版本（預設為 `2024-04-01-preview`。若 `useResponsesAPI` 為 `true` 或 `useDeploymentBasedUrls` 為 `false`，則預設為 `v1`） |
| `useResponsesAPI` | `boolean` | 否 | 透過 Azure OpenAI Responses API 解析部署（預設為 `false`） |
| `useDeploymentBasedUrls` | `boolean` | 否 | 使用依 Azure 部署產生的 URL（預設為 `true`，`useResponsesAPI` 為 `true` 時預設為 `false`） |
| `deployments` | `string[]` | 否 | 靜態模式使用的部署名稱 |
| `management` | `object` | 否 | 管理 API 認證資訊 |
| `management.tenantId` | `string` | 是\* | Azure AD 租用戶 ID |
| `management.clientId` | `string` | 是\* | 服務主體的用戶端 ID |
| `management.clientSecret` | `string` | 是\* | 服務主體的用戶端密碼 |
| `management.subscriptionId` | `string` | 是\* | Azure 訂用帳戶 ID |
| `management.resourceGroup` | `string` | 是\* | 資源群組名稱 |

\* 請在 `apiKey` 與 `authentication.type: "entraId"` 中擇一。若有提供 `management`，其子欄位皆為必填。
