# 自訂模型閘道

透過自訂模型閘道，你可以使用 `MastraModelGatewayInterface` 介面或 `MastraModelGateway` 基底類別，實作私有或專用的 LLM Provider 整合。

## 概觀 {/* #overview */}

閘道負責處理存取語言模型時的 Provider 專屬邏輯：

- Provider 設定和模型探索
- 驗證和 API 金鑰管理
- 為 API 端點建構 URL
- 建立語言模型執行個體

## 何時使用自訂閘道 {/* #when-to-use-custom-gateways */}

使用自訂閘道，可將 Mastra 連接至自行執行的開放權重模型，例如 gpt-oss、Llama、Gemma、Mistral、Qwen 或 DeepSeek。以下情況適合自行託管：

- 產業規範不允許將 prompt 或客戶資料傳送至第三方 API（例如 HIPAA、GDPR、金融或國防領域）
- 模型呼叫量夠大，按 token 計費的 API 成本已高於執行自有 GPU
- 已使用內部資料微調開放權重模型，並希望 Agent 使用該模型
- 需要模型只在主動升級時變更，以避免 Provider 更新破壞 prompt
- Agent 必須離線執行，或執行於隔離網路、邊緣硬體，或與應用程式相同的資料中心

閘道會列出端點後方的模型，讓這些模型取得具型別的模型 ID，並顯示在 Studio 模型選擇器中。閘道也可以在每次呼叫時解析認證；你也可以[限制 Studio 模型選擇器](#showing-only-custom-gateways-in-studio)，只顯示自己的模型。

如果只要呼叫一個與 OpenAI API 相容的端點，就不需要閘道：直接在模型設定中設定 `url` 即可。對於使用 `url` 的模型，Mastra 不會從環境變數讀取 API 金鑰，因此端點需要驗證時也應設定 `apiKey`。請參閱[在 Mastra 中使用本機模型](/models#use-local-models-with-mastra)。

## 建立自訂閘道 {/* #creating-a-custom-gateway */}

一般物件形式的閘道可實作 `MastraModelGatewayInterface`；類別形式的閘道可擴充 `MastraModelGateway` 基底類別。

### 選擇一般物件或類別 {/* #choose-a-plain-object-or-a-class */}

兩種形式在執行階段的行為相同。基底類別提供預設的 `getId()`、`shouldEnable()`、`handlesModel()` 和 `serializeForSpan()` 方法；如果一般物件省略這些方法，Mastra 也會套用相同的預設實作。

閘道設定固定且沒有狀態時，可以使用一般物件。以下情況應擴充 `MastraModelGateway`：

- 需要透過建構函式接收基礎 URL 或 API 金鑰等選項
- 需要保留私有狀態，例如快取的 token
- 需要執行多個執行個體，例如每個區域或版本各一個

以下範例使用一般物件實作該介面：

```typescript
import { type MastraModelGatewayInterface, type ProviderConfig } from '@mastra/core/llm';
import { createOpenAICompatible } from '@ai-sdk/openai-compatible-v5';

const myPrivateGateway: MastraModelGatewayInterface = {
  id: 'private',
  name: 'My Private Gateway',
  async fetchProviders(): Promise<Record<string, ProviderConfig>> {
    return {
      'my-provider': {
        name: 'My Provider',
        models: ['__GATEWAY_OPENAI_MODEL__'],
        apiKeyEnvVar: 'MY_API_KEY',
        gateway: 'private',
        url: 'https://api.myprovider.com/v1',
      },
    };
  },
  buildUrl() {
    return 'https://api.myprovider.com/v1';
  },
  async getApiKey() {
    return process.env.MY_API_KEY ?? '';
  },
  async resolveLanguageModel({ modelId, providerId, apiKey, headers }) {
    return createOpenAICompatible({
      name: providerId,
      apiKey,
      headers,
      baseURL: 'https://api.myprovider.com/v1',
    }).chatModel(modelId);
  },
};
```

以下範例擴充 `MastraModelGateway`，並透過建構函式接收 ID、基礎 URL 和 API 金鑰：

```typescript
import { MastraModelGateway, type GatewayLanguageModel, type ProviderConfig } from '@mastra/core/llm';
import { createOpenAICompatible } from '@ai-sdk/openai-compatible-v5';

interface MyPrivateGatewayOptions {
  id?: string;
  baseURL?: string;
  apiKey?: string;
}

class MyPrivateGateway extends MastraModelGateway {
  readonly id: string;
  readonly name = 'My Private Gateway';

  private readonly baseURL: string;
  private readonly apiKey?: string;

  constructor(options: MyPrivateGatewayOptions = {}) {
    super();
    this.id = options.id ?? 'private';
    this.baseURL = options.baseURL ?? 'https://api.myprovider.com/v1';
    this.apiKey = options.apiKey;
  }

  async fetchProviders(): Promise<Record<string, ProviderConfig>> {
    return {
      'my-provider': {
        name: 'My Provider',
        models: ['__GATEWAY_OPENAI_MODEL__', '__GATEWAY_ANTHROPIC_MODEL_SONNET__'],
        apiKeyEnvVar: 'MY_API_KEY',
        gateway: this.id,
        url: this.baseURL,
      },
    };
  }

  buildUrl(): string {
    return this.baseURL;
  }

  async getApiKey(): Promise<string> {
    const apiKey = this.apiKey ?? process.env.MY_API_KEY;
    if (!apiKey) {
      throw new Error('Missing MY_API_KEY environment variable');
    }
    return apiKey;
  }

  resolveLanguageModel({
    modelId,
    providerId,
    apiKey,
    headers,
  }: {
    modelId: string;
    providerId: string;
    apiKey: string;
    headers?: Record<string, string>;
  }): GatewayLanguageModel {
    return createOpenAICompatible({
      name: providerId,
      apiKey,
      headers,
      baseURL: this.baseURL,
      supportsStructuredOutputs: true,
    }).chatModel(modelId);
  }
}
```

如需為每個端點執行一個執行個體，請為各執行個體指派不同的 `id`。對於相同的 ID，Mastra 只保留最先註冊的閘道；該 ID 也是模型 ID 的前綴：

```typescript
import { Mastra } from '@mastra/core';

const mastra = new Mastra({
  gateways: {
    privateEu: new MyPrivateGateway({ id: 'private-eu', baseURL: 'https://eu.api.myprovider.com/v1' }),
    privateUs: new MyPrivateGateway({ id: 'private-us', baseURL: 'https://us.api.myprovider.com/v1' }),
  },
});

// Models: 'private-eu/my-provider/__GATEWAY_OPENAI_MODEL__' and 'private-us/my-provider/__GATEWAY_OPENAI_MODEL__'
```

### 由閘道管理的驗證 {/* #gateway-owned-authentication */}

如果認證查找由閘道負責，請加入 `resolveAuth`。Mastra 會先使用此 hook，之後才退回使用 `getApiKey()`。

```typescript
const myPrivateGateway: MastraModelGatewayInterface = {
  // ...gateway fields and methods
  async resolveAuth() {
    const apiKey = process.env.MY_API_KEY;
    return apiKey ? { apiKey, source: 'gateway' } : undefined;
  },
};
```

## 註冊自訂閘道 {/* #registering-custom-gateways */}

### 初始化時 {/* #during-initialization */}

建立 Mastra 執行個體時，以記錄形式傳入閘道：

```typescript
import { Mastra } from '@mastra/core';

const mastra = new Mastra({
  gateways: {
    myGateway: new MyPrivateGateway(),
    anotherGateway: new AnotherGateway(),
  },
});
```

### 初始化後 {/* #after-initialization */}

使用 `addGateway` 動態加入閘道：

```typescript
const mastra = new Mastra();

// Add with explicit key
mastra.addGateway(new MyPrivateGateway(), 'myGateway');

// Add using gateway's ID
mastra.addGateway(new MyPrivateGateway());
// Stored with key 'my-private-gateway' (the gateway's id)
```

## 使用自訂閘道 {/* #using-custom-gateways */}

以閘道 ID 作為前綴，參照自訂閘道中的模型：

```typescript
import { Agent } from '@mastra/core/agent';

const agent = new Agent({
  id: 'my-agent',
  name: 'My Agent',
  instructions: 'You are a helpful assistant',
  model: 'private/my-provider/__GATEWAY_OPENAI_MODEL__', // Uses MyPrivateGateway
});

mastra.addAgent(agent, 'myAgent');
```

建立 Agent 或使用模型時，Mastra 的模型路由器會根據模型 ID 自動選擇合適的閘道。閘道 ID 用作前綴；如果沒有符合的自訂閘道，則退回使用內建閘道。

### TypeScript 自動完成 {/* #typescript-autocomplete */}

#### 在開發環境中自動產生型別 {/* #automatic-type-generation-in-development */}

在開發模式（`MASTRA_DEV=true`）下執行時，Mastra 會自動為自訂閘道產生 TypeScript 型別。

1. **設定環境變數**：
   ```bash
   export MASTRA_DEV=true
   ```

1. **註冊閘道**：
   ```typescript
   const mastra = new Mastra({
     gateways: {
       myGateway: new MyPrivateGateway(),
     },
   });
   ```

1. **自動產生型別**：
   - 加入閘道時，Mastra 會與 GatewayRegistry 同步
   - 登錄會從自訂閘道擷取 Provider
   - TypeScript 型別會在 `~/.cache/mastra/` 中重新產生
   - IDE 會在數秒內讀取新型別

1. **自動完成功能現已可用**：
   ```typescript
   const agent = new Agent({
     model: 'my-gateway-id/my-provider/model-1', // Full autocomplete!
   });
   ```

#### 運作方式 {/* #how-it-works */}

GatewayRegistry 每小時執行一次同步，以：
- 對所有已註冊閘道呼叫 `fetchProviders()`
- 產生 TypeScript 型別定義
- 將型別定義寫入全域快取和專案的 `dist/` 目錄
- TypeScript 伺服器會自動讀取這些變更

:::tip
首次加入閘道時，產生型別可能需要數秒。後續更新會每小時在背景執行。
:::

#### 手動產生型別的替代方法 {/* #manual-type-generation-alternatives */}

如果未在開發模式下執行，或需要立即更新型別：

**選項 1：使用型別斷言（最簡單）**
```typescript
const agent = new Agent({
  id: 'my-agent',
  name: 'my-agent',
  instructions: 'You are a helpful assistant',
  model: 'private/my-provider/model-1' as any, // Bypass type checking
});
```

**選項 2：建立自訂聯集型別（型別安全）**
```typescript
import type { ModelRouterModelId } from '@mastra/core/llm';

// Define your custom model IDs
type CustomModelId =
  | 'private/my-provider/model-1'
  | 'private/my-provider/model-2'
  | 'private/my-provider/model-3';

// Combine with built-in models
type AllModelIds = ModelRouterModelId | CustomModelId;

const agent = new Agent({
  id: 'my-agent',
  name: 'my-agent',
  instructions: 'You are a helpful assistant',
  model: 'private/my-provider/model-1' satisfies AllModelIds,
});
```

**選項 3：全域擴充 ModelRouterModelId（進階）**
```typescript
// In a types.d.ts file in your project
// The import is required: it makes this file a module, so the block below
// merges into the existing types instead of replacing the module.
import '@mastra/core/llm';

declare module '@mastra/core/llm' {
  interface ProviderModelsMap {
    'my-provider': readonly ['model-1', 'model-2', 'model-3'];
  }
}
```

這會擴充內建型別，將自訂模型納入其中，進而提供完整的自動完成支援。

## 閘道管理 {/* #gateway-management */}

### getGateway(key) {/* #getgatewaykey */}

依註冊鍵取得閘道：

```typescript
const gateway = mastra.getGateway('myGateway');
console.log(gateway.name); // 'My Private Gateway'
```

### getGatewayById(id) {/* #getgatewaybyidid */}

依唯一 ID 取得閘道：

```typescript
const gateway = mastra.getGatewayById('my-private-gateway');
console.log(gateway.name); // 'My Private Gateway'
```

以下情況適合使用此方法：
- 閘道的明確 ID 與註冊鍵不同
- 需要跨不同執行個體依 ID 尋找閘道
- 需要支援閘道版本管理（例如 `'gateway-v1'`、`'gateway-v2'`）

如果沒有已註冊閘道使用指定 ID，`getGatewayById()` 會擲回 `MastraError`，而不是傳回 `undefined`。

### listGateways() {/* #listgateways */}

取得所有已註冊閘道：

```typescript
const gateways = mastra.listGateways();
console.log(Object.keys(gateways)); // ['myGateway', 'anotherGateway']
```

## 閘道屬性 {/* #gateway-properties */}

### 必填屬性 {/* #required */}

| 屬性 | 型別 | 說明 |
|----------|------|-------------|
| `id` | `string` | 閘道的唯一識別碼，用作模型字串的閘道前綴 |
| `name` | `string` | 便於閱讀的閘道名稱 |

### 方法 {/* #methods */}

| 方法 | 說明 |
|--------|-------------|
| `fetchProviders()` | 取得 Provider 設定 |
| `buildUrl(modelId, envVars?)` | 為模型建構 API URL |
| `getApiKey(modelId)` | 取得用於驗證的 API 金鑰 |
| `resolveLanguageModel(args)` | 建立語言模型執行個體 |
| `getId()` | 取得閘道 ID（傳回 `id` 或 `name`） |

## Provider 設定 {/* #provider-configuration */}

`fetchProviders()` 方法會傳回由 `ProviderConfig` 物件組成的記錄：

```typescript
interface ProviderConfig {
  name: string;                    // Display name
  models: string[];                // Available model IDs
  apiKeyEnvVar: string | string[]; // Environment variable(s) for API key
  gateway: string;                 // Gateway identifier
  url?: string;                    // Optional API base URL
  apiKeyHeader?: string;           // Optional custom auth header
  docUrl?: string;                 // Optional documentation URL
  pricing?: Record<string, ModelPricing>; // Optional prices per model ID
}
```

### 模型計價 {/* #model-pricing */}

models.dev 不會列出私有部署，因此相關呼叫在[指標](/docs/observability/metrics/overview)中沒有成本。可以為每個模型加入 `pricing` 項目，為其提供計價。價格以每 100 萬 token 的美元金額計算，並使用與 [models.dev](https://models.dev) 中模型 `cost` 相同的鍵：`input`、`output`、`cache_read`、`cache_write`、`reasoning`、`input_audio` 和 `output_audio`。`@mastra/observability` 會在首次呼叫無法計價的模型時讀取這些價格，因此也能識別之後透過 `addGateway()` 加入的閘道。在 `mastra dev` 下，或設定 `MASTRA_AUTO_REFRESH_PRICING=true` 後，Mastra 啟動時也會讀取價格，讓首次呼叫也能計價。models.dev 的價格優先順序較高。只有 models.dev 沒有相應 Provider 和模型 ID 的價格時，才會採用閘道價格；之後，該價格會用於這些 ID 的所有呼叫，包括直接呼叫。如果經銷商費率必須與直接呼叫分開，請為其指派獨立的 Provider ID。如果閘道的 `fetchProviders()` 失敗，系統會記錄日誌，並大約每小時重試一次。設定 `MASTRA_OFFLINE=true` 可略過載入。由於格式與 models.dev 相同，還可以加入 `tiers` 以支援長上下文計價。

```typescript
async fetchProviders(): Promise<Record<string, ProviderConfig>> {
  return {
    'my-provider': {
      name: 'My Provider',
      models: ['model-1'],
      apiKeyEnvVar: 'MY_API_KEY',
      gateway: 'private',
      url: 'https://api.myprovider.com/v1',
      pricing: {
        'model-1': { input: 0.5, output: 1.5, cache_read: 0.05 },
      },
    },
  };
}
```

## 閘道 ID 與鍵的差異 {/* #gateway-ids-vs-keys */}

請注意兩者的差異：

- **鍵**：將閘道加入 Mastra 時使用的註冊鍵（記錄鍵）
- **ID**：閘道的唯一識別碼（使用 `id` 屬性；如果未設定，則使用 `name`）

```typescript
class VersionedGateway extends MastraModelGateway {
  readonly id = 'my-gateway-v2';     // Unique ID for versioning and prefixing
  readonly name = 'My Gateway';       // Display name
}

const mastra = new Mastra({
  gateways: {
    currentGateway: new VersionedGateway(), // Key: 'currentGateway'
  },
});

// Retrieve by key
const byKey = mastra.getGateway('currentGateway');

// Retrieve by ID
const byId = mastra.getGatewayById('my-gateway-v2');

// Both return the same gateway
console.log(byKey === byId); // true
```

## 模型 ID 格式 {/* #model-id-format */}

透過自訂閘道存取的模型採用以下格式：

```
[gatewayId]/[provider]/[model]
```

範例：
- `private/my-provider/model-1`

## 進階範例 {/* #advanced-example */}

支援快取、以 token 為基礎的閘道：

```typescript
class TokenGateway extends MastraModelGateway {
  readonly id = 'token-gateway-v1';
  readonly name = 'Token Gateway';

  private tokenCache: Map<string, { token: string; expiresAt: number }> = new Map();

  async fetchProviders(): Promise<Record<string, ProviderConfig>> {
    const response = await fetch('https://api.gateway.com/providers');
    const data = await response.json();

    return {
      provider: {
        name: data.name,
        models: data.models,
        apiKeyEnvVar: 'GATEWAY_TOKEN',
        gateway: this.id,
      },
    };
  }

  async buildUrl(modelId: string, envVars?: Record<string, string>): Promise<string> {
    const token = await this.getApiKey(modelId);
    const siteId = envVars?.SITE_ID || process.env.SITE_ID;

    const response = await fetch(`https://api.gateway.com/sites/${siteId}/token`, {
      headers: { Authorization: `Bearer ${token}` },
    });

    const { url } = await response.json();
    return url;
  }

  async getApiKey(modelId: string): Promise<string> {
    const cached = this.tokenCache.get(modelId);

    if (cached && cached.expiresAt > Date.now()) {
      return cached.token;
    }

    const token = process.env.GATEWAY_TOKEN;
    if (!token) {
      throw new Error('Missing GATEWAY_TOKEN');
    }

    // Cache token for 1 hour
    this.tokenCache.set(modelId, {
      token,
      expiresAt: Date.now() + 3600000,
    });

    return token;
  }

  async resolveLanguageModel({ modelId, providerId, apiKey }: {
    modelId: string;
    providerId: string;
    apiKey: string;
  }): Promise<LanguageModelV2> {
    const baseURL = await this.buildUrl(`${providerId}/${modelId}`);

    return createOpenAICompatible({
      name: providerId,
      apiKey,
      baseURL,
      supportsStructuredOutputs: true,
    }).chatModel(modelId);
  }
}
```

## 錯誤處理 {/* #error-handling */}

為常見失敗情境提供說明清楚的錯誤訊息：

```typescript
class RobustGateway extends MastraModelGateway {
  // ... properties

  async getApiKey(modelId: string): Promise<string> {
    const apiKey = process.env.MY_API_KEY;

    if (!apiKey) {
      throw new Error(
        `Missing MY_API_KEY environment variable for model: ${modelId}. ` +
        `Please set MY_API_KEY in your environment.`
      );
    }

    return apiKey;
  }

  async buildUrl(modelId: string, envVars?: Record<string, string>): Promise<string> {
    const baseUrl = envVars?.BASE_URL || process.env.BASE_URL;

    if (!baseUrl) {
      throw new Error(
        `No base URL configured for model: ${modelId}. ` +
        `Set BASE_URL environment variable or pass it in envVars.`
      );
    }

    return baseUrl;
  }
}
```

## 測試自訂閘道 {/* #testing-custom-gateways */}

測試結構範例：

```typescript
import { describe, it, expect, beforeEach } from 'vitest';
import { Mastra } from '@mastra/core';

describe('MyPrivateGateway', () => {
  beforeEach(() => {
    process.env.MY_API_KEY = 'test-key';
  });

  it('should fetch providers', async () => {
    const gateway = new MyPrivateGateway();
    const providers = await gateway.fetchProviders();

    expect(providers['my-provider']).toBeDefined();
    expect(providers['my-provider'].models).toContain('model-1');
  });

  it('should integrate with Mastra', () => {
    const mastra = new Mastra({
      gateways: {
        private: new MyPrivateGateway(),
      },
    });

    const gateway = mastra.getGateway('private');
    expect(gateway.name).toBe('My Private Gateway');
  });

  it('should resolve models by ID', () => {
    const mastra = new Mastra({
      gateways: {
        key: new MyPrivateGateway(),
      },
    });

    const gateway = mastra.getGatewayById('my-private-gateway');
    expect(gateway).toBeDefined();
  });
});
```

## 最佳實務 {/* #best-practices */}

1. **使用具描述性的 ID 管理版本**：需要管理閘道版本時，請設定明確的 `id` 值
   ```typescript
   readonly id = 'my-gateway-v1';
   ```

1. **正確處理錯誤**：擲回說明清楚且包含可執行建議的錯誤

1. **快取高成本操作**：適時快取 token、URL 或 Provider 設定

1. **驗證環境變數**：在 `getApiKey` 和 `buildUrl` 中檢查必要的環境變數

1. **為閘道撰寫文件**：加入 JSDoc 註解，說明閘道的用途和設定

1. **遵循命名慣例**：為 Provider 和模型使用清楚一致的名稱

1. **處理非同步作業**：對網路請求和 I/O 作業使用 `async/await`

1. **完整測試**：為所有閘道方法撰寫單元測試

## 在 Studio 中只顯示自訂閘道 {/* #showing-only-custom-gateways-in-studio */}

預設情況下，**Studio** 會同時列出所有外部模型 Provider（例如 OpenAI、Anthropic 和 Gemini）以及已註冊的自訂閘道。如要隱藏外部 Provider，請設定 `AUTO_BLOCK_EXTERNAL_PROVIDERS` 環境變數：

```bash
AUTO_BLOCK_EXTERNAL_PROVIDERS=true
```

將該變數設定為 `true` 或 `1` 後，Mastra 只會傳回自行註冊的閘道所提供的 Provider。靜態 Provider 登錄和內建閘道（`models.dev`、`netlify` 和 `mastra`）會從模型選擇器中隱藏。如果所有模型流量都透過單一私有閘道路由，且不希望顯示其他 Provider，這項設定會很有幫助。該篩選器會套用至伺服器的 `GET /agents/providers` 端點，而 Studio 的模型選擇器正是使用該端點，因此 API 用戶端也不會看到外部 Provider。它只會變更列出的 Provider，並不會阻止 Agent 在程式碼中呼叫其他 Provider。

如果設定了該變數但未註冊任何自訂閘道，模型選擇器將會是空的。請至少註冊一個自訂閘道，以顯示其模型。

## 內建閘道 {/* #built-in-gateways */}

Mastra 提供以下內建閘道作為參考實作：

- **NetlifyGateway**：整合支援 token 交換的 Netlify AI Gateway
- **ModelsDevGateway**：models.dev 提供的 OpenAI 相容 Provider 登錄

閘道使用範例請參閱 [Netlify](/models/gateways/netlify)、[OpenRouter](/models/gateways/openrouter) 和 [Vercel](/models/gateways/vercel)。
