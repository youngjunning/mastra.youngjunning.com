# Langfuse

[Langfuse](https://langfuse.com/) 是專為 LLM 應用程式打造的開源可觀測性平台。透過 Langfuse 匯出器傳送 Trace 後，即可在 Langfuse 詳細檢視模型效能、token 用量與對話流程。

## 安裝 {/* #installation */}

```bash npm2yarn
npm install @mastra/langfuse@latest
```

## 設定 {/* #configuration */}

### 先決條件 {/* #prerequisites */}

1. **Langfuse 帳號**：前往 [cloud.langfuse.com](https://cloud.langfuse.com) 註冊，或自行架設 Langfuse。
2. **API 金鑰**：在 Langfuse 的 Settings → API Keys 中建立一組公開金鑰與秘密金鑰。
3. **環境變數**：將憑證設為環境變數。

```bash title=".env"
LANGFUSE_PUBLIC_KEY=pk-lf-xxxxxxxxxxxx
LANGFUSE_SECRET_KEY=sk-lf-xxxxxxxxxxxx
LANGFUSE_BASE_URL=https://cloud.langfuse.com  # Or your self-hosted URL
```

### 使用環境變數初始化 {/* #zero-config-setup */}

設定好環境變數後，建立匯出器時即可省略設定參數：

```typescript title="src/mastra/index.ts"
import { Mastra } from '@mastra/core'
import { Observability } from '@mastra/observability'
import { LangfuseExporter } from '@mastra/langfuse'

export const mastra = new Mastra({
  observability: new Observability({
    configs: {
      langfuse: {
        serviceName: 'my-service',
        exporters: [new LangfuseExporter()],
      },
    },
  }),
})
```

### 直接傳入設定 {/* #explicit-configuration */}

也可以直接傳入憑證，直接傳入的值會優先於環境變數：

```typescript title="src/mastra/index.ts"
import { Mastra } from '@mastra/core'
import { Observability } from '@mastra/observability'
import { LangfuseExporter } from '@mastra/langfuse'

export const mastra = new Mastra({
  observability: new Observability({
    configs: {
      langfuse: {
        serviceName: 'my-service',
        exporters: [
          new LangfuseExporter({
            publicKey: process.env.LANGFUSE_PUBLIC_KEY!,
            secretKey: process.env.LANGFUSE_SECRET_KEY!,
            baseUrl: process.env.LANGFUSE_BASE_URL,
            environment: process.env.NODE_ENV,
            release: process.env.GIT_COMMIT,
          }),
        ],
      },
    },
  }),
})
```

## 設定選項 {/* #configuration-options */}

### 即時與批次模式 {/* #realtime-vs-batch-mode */}

Langfuse 匯出器提供兩種 Trace 傳送模式：

#### 即時模式（開發） {/* #realtime-mode-development */}

Trace 會立即顯示在 Langfuse 儀表板中，方便除錯：

```typescript
new LangfuseExporter({
  publicKey: process.env.LANGFUSE_PUBLIC_KEY!,
  secretKey: process.env.LANGFUSE_SECRET_KEY!,
  realtime: true, // Flush after each event
})
```

#### 批次模式（正式環境） {/* #batch-mode-production */}

自動將 Trace 分批傳送，以提升效能：

```typescript
new LangfuseExporter({
  publicKey: process.env.LANGFUSE_PUBLIC_KEY!,
  secretKey: process.env.LANGFUSE_SECRET_KEY!,
  realtime: false, // Default - batch traces
})
```

#### 大量 Trace 的批次調校 {/* #batch-tuning-for-high-volume-traces */}

自行架設 Langfuse，或執行每秒會產生大量 span 的串流作業時，可以調整 OTEL 的批次大小與送出間隔，減輕 Langfuse 資料接收端點處理請求的負擔：

```typescript
new LangfuseExporter({
  publicKey: process.env.LANGFUSE_PUBLIC_KEY!,
  secretKey: process.env.LANGFUSE_SECRET_KEY!,
  flushAt: 500, // Maximum spans per OTEL export batch
  flushInterval: 20, // Maximum seconds between flushes
})
```

若要完全略過產生量大的 span 類型，例如串流回應的 `MODEL_CHUNK` span，請在可觀測性設定中使用 [`excludeSpanTypes` 選項](/reference/observability/tracing/span-filtering)：

```typescript
import { SpanType } from '@mastra/core/observability'

new Observability({
  configs: {
    langfuse: {
      serviceName: 'my-service',
      exporters: [new LangfuseExporter()],
      excludeSpanTypes: [SpanType.MODEL_CHUNK],
    },
  },
})
```

### 完整設定 {/* #complete-configuration */}

```typescript
new LangfuseExporter({
  // Required credentials
  publicKey: process.env.LANGFUSE_PUBLIC_KEY!,
  secretKey: process.env.LANGFUSE_SECRET_KEY!,

  // Optional settings
  baseUrl: process.env.LANGFUSE_BASE_URL, // Default: https://cloud.langfuse.com
  realtime: process.env.NODE_ENV === 'development', // Dynamic mode selection
  flushAt: 500, // Maximum spans per OTEL export batch
  flushInterval: 20, // Maximum seconds between flushes
  logLevel: 'info', // Diagnostic logging: debug | info | warn | error

  // Langfuse-specific settings
  environment: process.env.NODE_ENV, // Shows in Langfuse UI for filtering
  release: process.env.GIT_COMMIT, // Git commit hash for version tracking
})
```

## 設定個別 Agent 的評估範圍 {/* #scoping-evaluators-per-agent */}

你可以替 Langfuse 評估器（例如 LLM-as-a-Judge）加上篩選條件，只針對符合條件的 Trace 執行評估。Mastra 的 Langfuse 匯出器會自動將每筆 Trace 歸到啟動它的 Agent 或 Workflow，讓 Trace 層級的篩選條件能對應到正確的執行記錄。

當 Trace 的根 span 為 `AGENT_RUN` 時，匯出器會填入下列欄位：

* `langfuse.trace.name`：Agent 名稱，未設定名稱時使用 Agent ID。
* `langfuse.trace.metadata.agentId`：Agent ID。
* `langfuse.trace.metadata.agentName`：Agent 名稱。

`WORKFLOW_RUN` 根 span 也適用相同規則，匯出器會設定 `langfuse.trace.metadata.workflowId` 與 `langfuse.trace.metadata.workflowName`。

若要指定評估器只評估某個 Agent，請在 Langfuse 中設定下列任一條件：

* **Trace name（Trace 名稱）**：等於 Agent 名稱，例如 `weather-agent`。
* **Metadata（中繼資料）**：`agentId` 等於 Agent ID。

Langfuse 評估器的 Trace 名稱下拉選單會列出曾出現的各個不同名稱。Agent 產生至少一筆 Trace 後，就會在選單中有對應的項目。

透過 `mastra.metadata.traceName` 自訂 `traceName` 時，自訂值會優先於預設的 Agent 名稱。

以 `tracingOptions.nestUnderParent` 啟動的執行會隸屬於既有 Trace，因此匯出器不會以該次執行的資料填寫 Trace 的名稱、輸入、輸出、中繼資料、使用者或工作階段。請參閱[將執行巢狀置於先前的 Mastra 執行之下](/docs/observability/tracing/overview#nesting-a-run-under-an-earlier-mastra-run)。

## 依 span 屬性篩選觀測記錄 {/* #filtering-observations-by-span-attributes */}

Langfuse 的觀測層級評估器依觀測記錄的最外層中繼資料進行篩選。OpenTelemetry 匯出器以 `mastra.<span_type>.<key>` 寫入的每個純量 span 屬性（字串、數字或布林值），都會由 Langfuse 匯出器提升至 `langfuse.observation.metadata.<key>`，鍵名則會轉為 camelCase。匯出器也會在每筆觀測記錄上設定 `agentId`、`agentName`、`spanType` 與 `operationName`。

這項對應會為 `MODEL_STEP` span 產生 `stepIndex` 與 `isContinued`。若要讓每次 Agent 執行只針對產出最終答案的步驟評估一次，請在觀測層級評估器中同時篩選 `spanType` 等於 `model_step` 與 `isContinued` 等於 `"false"`。

這些值會以字串傳送，請用 `"false"` 或 `"1"` 等字串值比較。span 的輸入與輸出仍依各自的規則對應，物件或陣列類型的屬性值只會留在巢狀的 `attributes` 中繼資料中。

## 自訂 Trace 中繼資料 {/* #custom-trace-metadata */}

Langfuse 只能依最外層中繼資料篩選和分組 Trace。巢狀中繼資料的鍵不適用於篩選或分組。

若要加入自訂的最外層中繼資料，請在 span 中繼資料的 `langfuse` 底下設定鍵。匯出器會將各鍵轉送至 `langfuse.trace.metadata.<key>`，以便在 Langfuse 中用來篩選：

```typescript
const tracingOptions = {
  metadata: {
    langfuse: {
      customerId: 'cust_123',
      tier: 'enterprise',
    },
  },
}
```

這個範例會產生 `langfuse.trace.metadata.customerId` 與 `langfuse.trace.metadata.tier`。

根 span 的中繼資料也會轉送。Mastra 會在每個 Agent 和 Workflow 的根 span 上設定 `runId` 與 `resourceId`，你也可以透過 `tracingOptions.metadata` 加入自訂鍵。匯出器會將這些根 span 的鍵逐一轉送至 `langfuse.trace.metadata.<key>`。對應至 Langfuse 專用欄位的鍵（`userId`、`sessionId`、`threadId`、`traceName` 與 `version`）不會重複寫入 Trace 中繼資料。子 span 的其他中繼資料會留在各自的觀測記錄中。工作階段 ID 等專用欄位各有對應規則。

注意事項：

* 保留鍵 `prompt` 用於[連結提示詞](#prompt-linking)，不會以 Trace 中繼資料的形式轉送。
* 保留的識別鍵 `agentId`、`agentName`、`workflowId` 與 `workflowName` 取值自根 span，優先於同名的自訂值。
* `langfuse` 底下的鍵優先於根 span 中繼資料中的同名鍵。
* Langfuse 將 Trace 中繼資料屬性對應為字串，因此匯出器會以字串傳送這些值。數字、布林值與物件會序列化為 JSON。Langfuse Cloud 在接收資料時會將它們還原成原始型別。

## 對話工作階段 {/* #conversation-sessions */}

匯出器根據 span 中繼資料中的 `sessionId` 對應到 Langfuse 工作階段。若未提供 `sessionId` 或其值為 `null`，便改用 `threadId`。明確將 `sessionId` 設為空字串會停用這項備援，匯出器不會傳送工作階段 ID。

使用 [Observational Memory](/docs/memory/observational-memory) 時，Langfuse 匯出器會將 observer 和 reflector 的 span 保留在呼叫端的工作階段中，即使子 span 比父 span 早到也一樣。明確指定的 `sessionId` 優先，空字串也算。未指定時，匯出器會先取用 Observational Memory 傳遞的原始呼叫端執行緒識別碼，再回頭使用 span 本身的 `threadId`。Observational Memory 優先取用呼叫端 span 的非空 `threadId` 作為呼叫端識別碼，否則使用原始請求的執行緒 ID。巢狀觀測會保留外層呼叫端的識別碼。

以執行緒 ID 作為工作階段對應的備援，是 Langfuse 專有的行為。Observational Memory 不會為其他匯出器從執行緒 ID 產生通用的 `sessionId` 中繼資料。

observer 與 reflector 的內部執行緒彼此獨立。多執行緒觀測以發起呼叫的一方的工作階段為準，批次中的第一個執行緒不決定工作階段。這項行為不受 `bufferOnIdle` 設定影響，也不會變更緩衝方式或 span 的親子關係。

## 成本追蹤 {/* #cost-tracking */}

模型生成的成本中繼資料符合以下所有條件時，匯出器才會把 Provider 回報的成本轉送至 Langfuse 的 `cost_details` 欄位：

* 該 span 屬於模型生成。
* `costContext.costMetadata.source` 為 `'provider_reported'`。
* `costContext.costUnit` 為 `'USD'`。
* `costContext.estimatedCost` 是有限的非負數。

匯出器會略過預估成本，讓 Langfuse 套用自己的定價模型。如果 Langfuse 的生成記錄沒有成本，請確認 Provider 是否回報成本。若 Provider 未回報，請在 Langfuse 設定模型價格。

詳細規則請參閱 [`LangfuseExporter` 參考文件](/reference/observability/tracing/exporters/langfuse#cost-tracking)。

## 連結提示詞 {/* #prompt-linking */}

你可以將 LLM 生成記錄連結至存放在 [Langfuse Prompt Management](https://langfuse.com/docs/prompt-management) 的提示詞，藉此追蹤提示詞版本並查看相關指標。

### 使用輔助函式（建議） {/* #using-the-helper-recommended */}

搭配使用 `withLangfusePrompt` 與 `buildTracingOptions`，即可簡化設定：

```typescript title="src/agents/support-agent.ts"
import { Agent } from '@mastra/core/agent'
import { buildTracingOptions } from '@mastra/observability'
import { LangfuseExporter, withLangfusePrompt } from '@mastra/langfuse'

const exporter = new LangfuseExporter()

// Fetch the prompt from Langfuse Prompt Management via the client
const prompt = await exporter.client.prompt.get('customer-support', { type: 'text' })

export const supportAgent = new Agent({
  id: 'support-agent',
  name: 'support-agent',
  instructions: prompt.compile(), // Use the prompt text from Langfuse
  model: '__GATEWAY_OPENAI_MODEL__',
  defaultGenerateOptions: {
    tracingOptions: buildTracingOptions(
      withLangfusePrompt({ name: prompt.name, version: prompt.version }),
    ),
  },
})
```

輔助函式 `withLangfusePrompt` 接受 `name` 與 `version` 欄位，用來連結提示詞。Langfuse v5 要求兩個欄位都提供。

### 手動提供欄位 {/* #manual-fields */}

如果沒有使用 Langfuse SDK，也可以自行傳入欄位值：

```typescript
const tracingOptions = buildTracingOptions(withLangfusePrompt({ name: 'my-prompt', version: 1 }))
```

### 提示詞物件欄位 {/* #prompt-object-fields */}

提示詞物件必須同時包含 `name` 與 `version`：

| 欄位 | 型別 | 說明 |
| - | - | - |
| `name` | string | 提示詞在 Langfuse 中的名稱 |
| `version` | number | 提示詞的版本號碼 |

在 `MODEL_GENERATION` span 上設定這些欄位後，Langfuse 匯出器會自動把生成記錄連結至對應的提示詞。

## 將既有 Trace 匯入 Mastra Platform {/* #import-existing-traces-into-mastra-platform */}

Mastra CLI 可從 Langfuse Cloud 或自行架設的 Langfuse v4 以上版本執行個體匯入過往的 Trace 觀測記錄。匯入作業與本頁的匯出器設定各自獨立。憑證、試跑、接續匯入、驗證及目前限制，請參閱[匯入既有 Trace](/docs/mastra-platform/observability#import-existing-traces)。
