# 朗福斯

[朗福斯](https://langfuse.com/)是一個專為LLM應用程式設計的開源可觀測平台。 Langfuse 匯出器將您的追蹤傳送到 Langfuse，提供有關模型效能和代幣使用情況以及對話流的詳細見解。

## 安裝 {/* #installation */}

```bash npm2yarn
npm install @mastra/langfuse@latest
```

## 配置 {/* #configuration */}

### 先決條件 {/* #prerequisites */}

1. **浪熔帳戶**: 報名於[cloud.langfuse.com](https://cloud.langfuse.com) or deploy self-hosted
2. **API 金鑰**：在 Langfuse 設定 → API 金鑰中建立公鑰/私鑰對
3. **環境變數**：設定您的憑證

```bash title=".env"
LANGFUSE_PUBLIC_KEY=pk-lf-xxxxxxxxxxxx
LANGFUSE_SECRET_KEY=sk-lf-xxxxxxxxxxxx
LANGFUSE_BASE_URL=https://cloud.langfuse.com  # Or your self-hosted URL
```

### 零配置設定 {/* #zero-config-setup */}

設定環境變數後，無需配置即可使用匯出器：

```typescript title="src/mastra/index.ts"
import { Mastra } from '@mastra/core'
import { Observability } from '@mastra/observability'
import { LangfuseExporter } from '@mastra/langfuse'

export const mastra = new Mastra({
  observability: new Observability({
    configs: {
      langfuse: {
        serviceName: 'my-service',
        exporters: [new LangfuseExporter()],
      },
    },
  }),
})
```

### 明確配置 {/* #explicit-configuration */}

您也可以直接傳遞憑證（優先於環境變數）：

```typescript title="src/mastra/index.ts"
import { Mastra } from '@mastra/core'
import { Observability } from '@mastra/observability'
import { LangfuseExporter } from '@mastra/langfuse'

export const mastra = new Mastra({
  observability: new Observability({
    configs: {
      langfuse: {
        serviceName: 'my-service',
        exporters: [
          new LangfuseExporter({
            publicKey: process.env.LANGFUSE_PUBLIC_KEY!,
            secretKey: process.env.LANGFUSE_SECRET_KEY!,
            baseUrl: process.env.LANGFUSE_BASE_URL,
            environment: process.env.NODE_ENV,
            release: process.env.GIT_COMMIT,
          }),
        ],
      },
    },
  }),
})
```

## 配置選項 {/* #configuration-options */}

### 即時與批次模式 {/* #realtime-vs-batch-mode */}

Langfuse 導出器支援兩種發送追蹤的模式：

#### 即時模式（開發） {/* #realtime-mode-development */}

追蹤立即出現在 Langfuse 儀表板中，非常適合調試：

```typescript
new LangfuseExporter({
  publicKey: process.env.LANGFUSE_PUBLIC_KEY!,
  secretKey: process.env.LANGFUSE_SECRET_KEY!,
  realtime: true, // Flush after each event
})
```

#### 批次模式（生產） {/* #batch-mode-production */}

透過自動批次獲得更好的性能：

```typescript
new LangfuseExporter({
  publicKey: process.env.LANGFUSE_PUBLIC_KEY!,
  secretKey: process.env.LANGFUSE_SECRET_KEY!,
  realtime: false, // Default - batch traces
})
```

#### 大容量跡線的批量調整 {/* #batch-tuning-for-high-volume-traces */}

對於自架 Langfuse 部署或每秒產生多個跨距的串流運行，您可以調整 OTEL 批次大小和刷新間隔，以減少 Langfuse 攝取端點上的請求壓力：

```typescript
new LangfuseExporter({
  publicKey: process.env.LANGFUSE_PUBLIC_KEY!,
  secretKey: process.env.LANGFUSE_SECRET_KEY!,
  flushAt: 500, // Maximum spans per OTEL export batch
  flushInterval: 20, // Maximum seconds between flushes
})
```

完全抑制高容量跨度類型（例如`MODEL_CHUNK` spans from streamed responses), use the observability-level [`excludeSpanTypes` option](/reference/observability/tracing/span-filtering) rather than configuring the exporter:

```typescript
import { SpanType } from '@mastra/core/observability'

new Observability({
  configs: {
    langfuse: {
      serviceName: 'my-service',
      exporters: [new LangfuseExporter()],
      excludeSpanTypes: [SpanType.MODEL_CHUNK],
    },
  },
})
```

### 完整配置 {/* #complete-configuration */}

```typescript
new LangfuseExporter({
  // Required credentials
  publicKey: process.env.LANGFUSE_PUBLIC_KEY!,
  secretKey: process.env.LANGFUSE_SECRET_KEY!,

  // Optional settings
  baseUrl: process.env.LANGFUSE_BASE_URL, // Default: https://cloud.langfuse.com
  realtime: process.env.NODE_ENV === 'development', // Dynamic mode selection
  flushAt: 500, // Maximum spans per OTEL export batch
  flushInterval: 20, // Maximum seconds between flushes
  logLevel: 'info', // Diagnostic logging: debug | info | warn | error

  // Langfuse-specific settings
  environment: process.env.NODE_ENV, // Shows in Langfuse UI for filtering
  release: process.env.GIT_COMMIT, // Git commit hash for version tracking
})
```

## 每個Agent的範圍評估員 {/* #scoping-evaluators-per-agent */}

Langfuse 評估器（例如 LLM-as-a-Judge）可以經過篩選，僅針對特定追蹤運行。 Mastra Langfuse 導出器會自動將每個追蹤的範圍限定為啟動它的Agent或Workflow，因此追蹤等級篩選器解析為正確的運作。

對於根跨距為`AGENT_RUN`, the exporter sets:

* `langfuse.trace.name`：Agent名稱（或 id，未設定名稱時）
* `langfuse.trace.metadata.agentId`: Agent ID
* `langfuse.trace.metadata.agentName`: Agent名稱

這同樣適用於`WORKFLOW_RUN` root spans, which set `langfuse.trace.metadata.workflowId` and `langfuse.trace.metadata.workflowName`.

若要將評估器的範圍限定為特定Agent，請在 Langfuse 中設定任一篩選器：

* **追蹤名稱**: 等於Agent名稱（例如，`weather-agent`).
* **元數據**: `agentId` equals the agent id.

Langfuse 評估器篩選器中的追蹤名稱下拉清單列出了看到的每個不同值，因此每個Agent程式在產生至少一個追蹤後都會顯示為自己的條目。

如果您設定了自訂`traceName` via `mastra.metadata.traceName`, your value takes precedence over the default agent name.

跑步開始於`tracingOptions.nestUnderParent` doesn't own the trace, so the exporter doesn't write the trace name, input, output, metadata, user, or session from it. See [Nesting a run under an earlier Mastra run](/docs/observability/tracing/overview#nesting-a-run-under-an-earlier-mastra-run).

## 按跨度屬性過濾觀測值 {/* #filtering-observations-by-span-attributes */}

Langfuse 中的觀察級評估器過濾頂級觀察元資料。導出器提升 OpenTelemetry 導出器寫入的每個標量跨度屬性（字串、數字或布林值）`mastra.<span_type>.<key>` to `langfuse.observation.metadata.<key>`, with the key converted to camelCase. The exporter also sets `agentId`, `agentName`, `spanType`, and `operationName` on each observation.

對於一個`MODEL_STEP` span this produces `stepIndex` and `isContinued`. To judge each agent run once, against the step that produced the final answer, filter an observation-level evaluator on `spanType` equals `model_step` and `isContinued` equals `"false"`.

值會作為字串發送，因此請與字串值進行比較，例如`"false"` or `"1"`. Span input and output keep their own mapping, and attributes that hold objects or arrays stay in the nested `attributes` metadata only.

## 自訂追蹤元數據 {/* #custom-trace-metadata */}

Langfuse 僅按頂層元資料過濾追蹤和分組。嵌套元資料鍵不能用於篩選或分組。

要添加您自己的頂級元數據，請在下面設定鍵`langfuse` in your span metadata. The exporter forwards each key to `langfuse.trace.metadata.<key>`, where it becomes filterable in Langfuse:

```typescript
const tracingOptions = {
  metadata: {
    langfuse: {
      customerId: 'cust_123',
      tier: 'enterprise',
    },
  },
}
```

這個例子產生`langfuse.trace.metadata.customerId` and `langfuse.trace.metadata.tier`.

根跨度上的元資料也會被轉送。馬斯特拉套裝`runId` and `resourceId` on every agent and workflow root span, and you can add your own keys through `tracingOptions.metadata`. The exporter forwards each of these root span keys to `langfuse.trace.metadata.<key>`. Keys that map to a dedicated Langfuse field (`userId`, `sessionId`, `threadId`, `traceName`, and `version`) are not duplicated as trace metadata. Other metadata on child spans stays on the observation. Dedicated fields such as session IDs follow their own mapping rules.

筆記：

* 保留的`prompt` key is used for [prompt linking](#prompt-linking) and isn't forwarded as trace metadata.
* 保留的身份密鑰`agentId`, `agentName`, `workflowId`, and `workflowName` are set from the root span and take precedence over custom values with the same name.
* 下的按鍵`langfuse` take precedence over root span metadata with the same name.
* 值會作為字串傳送，因為 Langfuse 將追蹤元資料屬性對應為字串。數字、布林值和物件使用 JSON 進行序列化。 Langfuse Cloud 在攝取時將它們還原為原始類型。

## 對話會 {/* #conversation-sessions */}

導出器使用以下命令將跨度元資料對應到 Langfuse 會話`sessionId`, or `threadId` when `sessionId` is absent or `null`. An explicit empty `sessionId` suppresses this fallback and sends no session ID.

為了[Observational Memory](/docs/memory/observational-memory), the Langfuse exporter keeps observer and reflector spans in the caller's session, even when child spans arrive before their parents. An explicit `sessionId`, including an empty string, takes precedence. Otherwise, the exporter uses the original caller thread carried by Observational Memory before falling back to the span's own `threadId`. Observational Memory captures that caller identity from the caller span's non-empty `threadId`, or the original request's thread ID. Nested observation preserves the outer caller identity.

這種執行緒到會話的回退是 Langfuse 特有的。觀察記憶不能綜合通用的記憶`sessionId` metadata from a thread ID for other exporters.

内部观察者和反射器执行线程保持独立。多线程观察使用调用者的会话，而不是批处理中的第一个线程。無論什麼情況，此會話行為都適用`bufferOnIdle` setting and doesn't change buffering or span parentage.

## 成本追蹤 {/* #cost-tracking */}

出口商將Provider報告的成本轉送給 Langfuse`cost_details` field, but only when the generation's cost metadata meets every condition:

* 跨度是模型生成跨度。
* `costContext.costMetadata.source`是`'provider_reported'`.
* `costContext.costUnit`是`'USD'`.
* `costContext.estimatedCost`

預估成本故意不導出，因此 Langfuse 可以應用自己的定價模型。如果您的世代在 Langfuse 中顯示缺失成本，請檢查您的Provider是否報告成本；否則在 Langfuse 中配置型號價格。

請參閱[`LangfuseExporter` reference](/reference/observability/tracing/exporters/langfuse#cost-tracking) for the exact rules.

## 提示連結 {/* #prompt-linking */}

您可以將 LLM 產生連結到儲存在中的提示[Langfuse Prompt Management](https://langfuse.com/docs/prompt-management). It enables version tracking and metrics for your prompts.

### 使用助手（推薦） {/* #using-the-helper-recommended */}

使用`withLangfusePrompt` with `buildTracingOptions` for the cleanest API:

```typescript title="src/agents/support-agent.ts"
import { Agent } from '@mastra/core/agent'
import { buildTracingOptions } from '@mastra/observability'
import { LangfuseExporter, withLangfusePrompt } from '@mastra/langfuse'

const exporter = new LangfuseExporter()

// Fetch the prompt from Langfuse Prompt Management via the client
const prompt = await exporter.client.prompt.get('customer-support', { type: 'text' })

export const supportAgent = new Agent({
  id: 'support-agent',
  name: 'support-agent',
  instructions: prompt.compile(), // Use the prompt text from Langfuse
  model: '__GATEWAY_OPENAI_MODEL__',
  defaultGenerateOptions: {
    tracingOptions: buildTracingOptions(
      withLangfusePrompt({ name: prompt.name, version: prompt.version }),
    ),
  },
})
```

這`withLangfusePrompt` helper accepts `name` and `version` fields for prompt linking. Langfuse v5 requires both fields.

### 手動字段 {/* #manual-fields */}

如果您不使用 Langfuse SDK，您也可以傳遞手動欄位：

```typescript
const tracingOptions = buildTracingOptions(withLangfusePrompt({ name: 'my-prompt', version: 1 }))
```

### 提示對象字段 {/* #prompt-object-fields */}

提示物件需要兩者`name` and `version`:

|領域 |類型 |描述 |
| - | - | - |
|`name` | string | The prompt name in Langfuse |
| `version` | number | The prompt version number |

當設定為`MODEL_GENERATION` span, the Langfuse exporter automatically links the generation to the corresponding prompt.
