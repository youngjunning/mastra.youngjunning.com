# Datadog

[Datadog](https://datadoghq.com/) 是功能完整的監控平台，提供專門的 LLM Observability 功能。Mastra 可透過匯出器傳送已完成的追蹤資料，也能透過橋接器即時整合 `dd-trace` 上下文。

## 匯出器 {/* #exporter */}

Datadog 匯出器會將追蹤資料傳送至 Datadog LLM Observability，協助你掌握模型效能、Token 用量及對話流程。

### 安裝 {/* #installation */}

```bash npm2yarn
npm install @mastra/datadog@latest
```

### 配置 {/* #configuration */}

#### 先決條件 {/* #prerequisites */}

1. **Datadog 帳戶**：在 [datadoghq.com](https://datadoghq.com/) 註冊，並啟用 LLM Observability
2. **API 金鑰**：從 Datadog 的 Organization Settings → API Keys 取得 API 金鑰
3. **環境變數**：設定憑證

```bash title=".env"
DD_API_KEY=your-datadog-api-key
DD_LLMOBS_ML_APP=my-llm-app
DD_SITE=datadoghq.com  # Optional: defaults to datadoghq.com
DD_ENV=production      # Optional: environment name
```

#### 零設定配置 {/* #zero-config-setup */}

設定環境變數後，無須傳入設定即可使用匯出器：

```typescript title="src/mastra/index.ts"
import { Mastra } from '@mastra/core'
import { Observability } from '@mastra/observability'
import { DatadogExporter } from '@mastra/datadog'

export const mastra = new Mastra({
  observability: new Observability({
    configs: {
      datadog: {
        serviceName: 'my-service',
        exporters: [new DatadogExporter()],
      },
    },
  }),
})
```

#### 明確指定設定 {/* #explicit-configuration */}

你也可以直接傳入憑證；直接傳入的值優先於環境變數：

```typescript title="src/mastra/index.ts"
import { Mastra } from '@mastra/core'
import { Observability } from '@mastra/observability'
import { DatadogExporter } from '@mastra/datadog'

export const mastra = new Mastra({
  observability: new Observability({
    configs: {
      datadog: {
        serviceName: 'my-service',
        exporters: [
          new DatadogExporter({
            mlApp: process.env.DD_LLMOBS_ML_APP!,
            apiKey: process.env.DD_API_KEY!,
          }),
        ],
      },
    },
  }),
})
```

### 設定選項 {/* #configuration-options */}

#### 完整設定 {/* #complete-configuration */}

```typescript
new DatadogExporter({
  // Required settings
  mlApp: process.env.DD_LLMOBS_ML_APP!, // Groups traces under this ML app name
  apiKey: process.env.DD_API_KEY!, // Required for agentless mode (default)

  // Optional settings
  site: 'datadoghq.com', // Datadog site (datadoghq.eu, us3.datadoghq.com, etc.)
  service: 'my-service', // Service name (defaults to mlApp)
  env: 'production', // Environment name
  agentless: true, // true = direct HTTPS, false = local Datadog Agent

  // Advanced settings
  integrationsEnabled: false, // Enable dd-trace auto-instrumentation

  // Diagnostic logging
  logLevel: 'info', // debug | info | warn | error
})
```

#### 使用本機 Datadog Agent {/* #with-local-datadog-agent */}

如果本機正在執行 Datadog Agent，可以透過它轉送追蹤資料，而無須直接透過 HTTPS 傳送：

```typescript
new DatadogExporter({
  mlApp: process.env.DD_LLMOBS_ML_APP!,
  agentless: false, // Use local Datadog Agent
  env: 'production',
})
```

注意：使用 Agent 模式時，API 金鑰會從本機 Datadog Agent 的設定讀取。

### Span 類型對應 {/* #span-type-mapping */}

Mastra 的 Span 類型會自動對應至 Datadog LLM Observability 的 Span 種類：

| Mastra SpanType | Datadog 種類 |
| - | - |
|`AGENT_RUN` | `agent` |
| `MODEL_GENERATION` | `workflow` |
| `MODEL_STEP` | `llm` |
| `TOOL_CALL` | `tool` |
| `MCP_TOOL_CALL` | `tool` |
| `WORKFLOW_RUN` | `workflow` |
| 其他 Workflow 類型 | `task` |
| `GENERIC` | `task` |

除非另有指定，其他或未來新增的 Mastra Span 類型預設對應至 `task`。

### 應用程式效能監控 {/* #application-performance-monitoring */}

以上內容介紹 Mastra 與 [LLM Observability](https://docs.datadoghq.com/llm_observability/) 的整合。若要追蹤 Mastra HTTP 伺服器路由的請求延遲、錯誤及服務拓撲，請直接使用 `dd-trace` 接入 Datadog Application Performance Monitoring（APM）。

#### APM 先決條件 {/* #apm-prerequisites */}

1. **Datadog Agent**：在同一台主機上，或可透過網路存取的位置安裝 [Datadog Agent](https://docs.datadoghq.com/agent/)。它會在 `localhost:8126` 接收來自 `dd-trace` 的追蹤資料，並轉送至 Datadog。請依照 [Agent 安裝指南](https://docs.datadoghq.com/agent/) 完成設定。
2. **dd-trace 套件**：在專案中安裝追蹤函式庫：

   ```bash npm2yarn
   npm install dd-trace
   ```

:::note
APM 追蹤資料一律透過 Datadog Agent 傳送。LLM Observability 也支援無 Agent 模式，可直接透過 HTTPS 傳送至 Datadog。
:::

#### 僅 APM {/* #apm-only */}

在進入點檔案頂端、匯入其他任何模組之前，匯入並初始化 `dd-trace`：

```typescript title="src/mastra/index.ts"
import tracer from 'dd-trace'

tracer.init({
  service: process.env.DD_SERVICE || 'my-mastra-app',
  env: process.env.DD_ENV || 'production',
  version: process.env.DD_VERSION,
})

import { Mastra } from '@mastra/core'

export const mastra = new Mastra({
  bundler: {
    externals: [
      'dd-trace',
      '@datadog/native-metrics',
      '@datadog/native-appsec',
      '@datadog/native-iast-taint-tracking',
      '@datadog/pprof',
    ],
  },
})
```

設定追蹤器元資料環境變數：

```bash title=".env"
DD_SERVICE=my-mastra-app
DD_ENV=production
DD_VERSION=1.0.0
```

`dd-trace` 會自動為常見 HTTP 框架加入追蹤功能，包括 Mastra 支援的[伺服器轉接器](/docs/server/server-adapters)。傳入請求、對外 HTTP 呼叫及資料庫查詢都會以 APM 追蹤資料的形式顯示在 Datadog 中。

#### APM 與 LLM Observability {/* #apm-and-llm-observability */}

建立 Mastra 執行個體之前，先匯入並初始化 `dd-trace`。`DatadogExporter` 會偵測現有的 tracer，略過重複初始化，並在 APM 設定的基礎上加入 LLM Observability：

```typescript title="src/mastra/index.ts"
import tracer from 'dd-trace'

tracer.init({
  service: process.env.DD_SERVICE || 'my-mastra-app',
  env: process.env.DD_ENV || 'production',
  version: process.env.DD_VERSION,
})

import { Mastra } from '@mastra/core'
import { Observability } from '@mastra/observability'
import { DatadogExporter } from '@mastra/datadog'

export const mastra = new Mastra({
  observability: new Observability({
    configs: {
      datadog: {
        serviceName: 'my-mastra-app',
        exporters: [
          new DatadogExporter({
            mlApp: process.env.DD_LLMOBS_ML_APP!,
            apiKey: process.env.DD_API_KEY!,
          }),
        ],
      },
    },
  }),
  bundler: {
    externals: [
      'dd-trace',
      '@datadog/native-metrics',
      '@datadog/native-appsec',
      '@datadog/native-iast-taint-tracking',
      '@datadog/pprof',
    ],
  },
})
```

```bash title=".env"
DD_SERVICE=my-mastra-app
DD_ENV=production
DD_VERSION=1.0.0
DD_API_KEY=your-datadog-api-key
DD_LLMOBS_ML_APP=my-llm-app
```

伺服器路由會顯示為 APM 追蹤資料，LLM 呼叫則顯示為 LLM Observability Span；兩者在 Datadog 中歸屬同一服務。

:::note
務必在其他所有模組之前匯入並初始化 `dd-trace`，讓它能在載入時為 HTTP、資料庫及框架函式庫加入自動追蹤功能。
:::

### 故障排除 {/* #troubleshooting */}

#### 原生模組 ABI 不相容 {/* #native-module-abi-mismatch */}

如果您看到類似以下錯誤：

```text
Error: No native build was found for runtime=node abi=137 platform=linuxglibc arch=x64
```

這表示目前的 Node.js 版本與 `dd-trace` 的原生模組有相容性問題。這些原生模組屬於**選用項目**，用於提供效能監控功能。

**解決方案：**

1. **使用 Node.js 22.x**：原生模組與 Node.js 22.x 的兼容性最好。

2. **忽略原生模組警告**：`@datadog/native-metrics`、`@datadog/native-appsec` 等原生模組皆為選用項目。即使載入失敗，核心追蹤功能仍可運作。

#### 打包工具的外部相依套件設定 {/* #bundler-externals-configuration */}

使用 esbuild、webpack 或 Mastra CLI 打包工具時，可能需要將 `dd-trace` 及其相依套件標記為外部相依套件：

```typescript title="src/mastra/index.ts"
import { Mastra } from '@mastra/core'

export const mastra = new Mastra({
  bundler: {
    externals: [
      'dd-trace',
      '@datadog/native-metrics',
      '@datadog/native-appsec',
      '@datadog/native-iast-taint-tracking',
      '@datadog/pprof',
    ],
  },
})
```

## 橋接器 {/* #bridge */}

:::warning

Datadog Bridge 目前仍處於**實驗階段**。其 API 與設定選項可能在未來版本變更。

:::

Datadog Bridge 讓 Mastra 追蹤系統與 Datadog 雙向整合。匯出器會在執行結束後傳送追蹤資料；Bridge 則會即時建立原生 `dd-trace` Span，讓 Tool 與處理器中的自動追蹤 APM 操作（例如 HTTP 呼叫和資料庫查詢）正確歸入其父 Mastra Span。

### 何時使用 Bridge {/* #when-to-use-the-bridge */}

以下情況適合使用 `DatadogBridge`：

* 應用程式使用 `dd-trace` 自動追蹤 HTTP 伺服器、資料庫用戶端等
* 希望 Tool、MCP Tool 或輸出處理器發出的 APM 服務呼叫歸入對應的父 Mastra Span，而非請求處理程式
* 需要 APM 追蹤資料與 LLM Observability 資料共用一致的追蹤拓撲
* 建置需要跨服務傳播 Datadog 追蹤上下文的分散式系統

### 它是如何運作的 {/* #how-it-works */}

`DatadogBridge` 參與 `dd-trace` 流程的兩個環節：

**APM 上下文傳播（即時）：**

* 建立每個 Mastra Span 時，透過 `tracer.startSpan()` 建立對應的 `dd-trace` APM Span
* 執行期間透過 `tracer.scope().activate()`，在 `dd-trace` 的作用域中啟用該 APM Span
* 作用域中自動追蹤的操作會以正確的 Mastra Span 為父節點
* 沒有明確的 Mastra 父 Span 時，繼承目前啟用的 `dd-trace` 上下文，例如傳入請求 Span

**LLM Observability 資料傳送（Span 結束時）：**

* 透過 `dd-trace` 的 LLM Observability 流程傳送註記，包括模型資訊、Token 用量、輸入輸出及錯誤
* 透過巢狀的 `llmobs.trace()` 呼叫維持 Datadog LLM Observability 中的父子關係
* 沿用與 [Datadog Exporter](#span-type-mapping) 相同的資料結構及 Span 類型對應

### 追蹤和日誌關聯 {/* #trace-and-log-correlation */}

若沒有 Bridge，Datadog Exporter 只會在追蹤完成後建立 LLM Observability Span。執行期間，作用域中沒有對應的 `dd-trace` Span，因此 Tool 發出的 HTTP 或資料庫呼叫會歸入當時啟用的 `dd-trace` Span，通常是傳入請求的處理程式。結果，MCP Tool 或輸出處理器發出的服務呼叫會顯示為請求 Span 的子節點，而非實際發出呼叫的 Agent 或處理器 Span 的子節點。

Bridge 會預先建立真正的 `dd-trace` Span，讓自動追蹤執行時使用正確的作用域。

### 安裝 {/* #installation-1 */}

```bash npm2yarn
npm install @mastra/datadog dd-trace
```

Bridge 需要安裝 `dd-trace`，並透過本機 Datadog Agent（或相容的 OTLP 接收器）接收 APM 資料。Agent 的設定方式請參閱 [APM 先決條件](#apm-prerequisites)。

### 設定 {/* #configuration-1 */}

使用 `DatadogBridge` 需要完成兩個步驟：

1. 初始化 `dd-trace`，使其自動追蹤功能能為 HTTP、資料庫及框架函式庫加入支援
2. 在 Mastra 的可觀測性設定中加入 `DatadogBridge`

#### 步驟 1：初始化 dd-trace {/* #step-1-initialize-dd-trace */}

必須在匯入其他模組之前初始化 `dd-trace`，讓它能在載入時為函式庫加入自動追蹤功能。Bridge 會偵測並重複使用已初始化的 tracer。

```typescript title="src/mastra/index.ts"
import tracer from 'dd-trace'

tracer.init({
  service: process.env.DD_SERVICE || 'my-mastra-app',
  env: process.env.DD_ENV || 'production',
  version: process.env.DD_VERSION,
})

import { Mastra } from '@mastra/core'
import { Observability } from '@mastra/observability'
import { DatadogBridge } from '@mastra/datadog'

// ...
```

:::note
在應用程式進入點檔案的最頂端、匯入其他任何模組之前，匯入並初始化 `dd-trace`。
:::

#### 步驟 2：設定 Mastra {/* #step-2-mastra-configuration */}

在 Mastra 的可觀測性設定中加入 `DatadogBridge`：

```typescript title="src/mastra/index.ts"
import { Mastra } from '@mastra/core'
import { Observability } from '@mastra/observability'

export const mastra = new Mastra({
  observability: new Observability({
    configs: {
      default: {
        serviceName: 'my-mastra-app',
        bridge: new DatadogBridge({
          mlApp: process.env.DD_LLMOBS_ML_APP!,
        }),
      },
    },
  }),
  bundler: {
    externals: [
      'dd-trace',
      '@datadog/native-metrics',
      '@datadog/native-appsec',
      '@datadog/native-iast-taint-tracking',
      '@datadog/pprof',
    ],
  },
})
```

```bash title=".env"
DD_SERVICE=my-mastra-app
DD_ENV=production
DD_VERSION=1.0.0
DD_LLMOBS_ML_APP=my-llm-app
```

初始化 `dd-trace` 後，APM 資料會傳送至 `localhost:8126` 上的本機 Datadog Agent。Bridge 會在同一個 tracer 上啟用 LLM Observability，因此兩類資料都會在 Datadog 中歸屬同一服務。

使用 Bridge 時無須設定 Mastra 匯出器；APM 與 LLM Observability 資料都透過 `dd-trace` 傳送。若還要將追蹤資料傳送至其他目的地，仍可加入 Mastra 匯出器。

### Agent 模式與無 Agent 模式 {/* #agent-vs-agentless-mode */}

Bridge 預設使用 **Agent 模式**（`agentless: false`），並假設本機 Datadog Agent 在 `localhost:8126` 執行，接收 APM 與 LLM Observability 資料。使用 `dd-trace` 自動追蹤時通常採用此設定，因為 APM 資料一律透過 Agent 傳送。

若沒有本機 Datadog Agent，而且只需要 LLM Observability 資料（不使用 APM 自動追蹤），可以啟用無 Agent 模式，直接將資料傳送至 Datadog。此時必須提供 API 金鑰。

```typescript
new DatadogBridge({
  mlApp: process.env.DD_LLMOBS_ML_APP!,
  apiKey: process.env.DD_API_KEY!,
  agentless: true,
})
```

:::note
對大多數 Bridge 使用者而言，Agent 模式較合適。無 Agent 模式無法傳送 APM 資料，因此啟用後，LLM Observability 流量會與 APM 流量分開。若只需要 LLM Observability 且不使用 Agent，請改用 [Datadog Exporter](#exporter)。
:::

### 追蹤層次結構 {/* #trace-hierarchy */}

使用 `DatadogBridge` 後，追蹤資料在 `dd-trace` 與 Mastra 之間會維持正確的層級關係。Tool 與處理器發出的服務呼叫會歸入對應的 Mastra Span：

```text
HTTP POST /api/chat (from web framework instrumentation)
└── agent.orchestrator (from Mastra via DatadogBridge)
    ├── chat gpt-5.4 (LLM call)
    ├── tool.execute search (tool execution)
    │   └── HTTP GET api.example.com (auto-instrumented from inside the tool)
    └── processor.guardrail (output processor)
        └── HTTP POST guardrail-service/check (auto-instrumented from inside the processor)
```

在 Datadog 中，APM 追蹤資料會呈現完整拓撲；LLM Observability 則顯示 Agent 與 LLM 專屬 Span，以及其輸入、輸出和 Token 指標。

### Span 類型對應 {/* #span-type-mapping-1 */}

Bridge 為 LLM Observability 使用與 Datadog Exporter 相同的 Span 種類對應。請參閱匯出器章節的 [Span 類型對應](#span-type-mapping)。

### 使用標籤 {/* #using-tags */}

標籤有助於在 Datadog 中分類及篩選追蹤資料。執行 Agent 或 Workflow 時可加入標籤：

```typescript
const result = await agent.generate('Hello', {
  tracingOptions: {
    tags: ['production', 'experiment-v2', 'user-request'],
  },
})
```

採用 `key:value` 格式的標籤（例如 `instance_name:career-scout-api`）會拆成結構化標籤項目。沒有冒號的標籤，其值會設為 `true`。

### 將上下文鍵提升為扁平標籤 {/* #promoting-context-keys-to-flat-tags */}

使用 `requestContextKeys`，可將請求上下文或 Span 屬性中的指定鍵提升為扁平、可建立索引的 LLM Observability 標籤，以便在 Datadog 介面中篩選：

```typescript
new DatadogBridge({
  mlApp: process.env.DD_LLMOBS_ML_APP!,
  requestContextKeys: ['tenantId', 'agentId'],
})
```

提升後的鍵會從 `annotations.metadata` 移除，並以扁平標籤的形式加入每個 LLM Observability Span。

### 故障排除 {/* #troubleshooting-1 */}

若 APM Span 未如預期連接至 Mastra Span：

* 確認 `dd-trace` 在匯入其他任何模組**之前**初始化（它需要在載入時為函式庫加入追蹤功能）
* 確認本機 Datadog Agent 正在執行，且可以存取 `localhost:8126`
* 確認在可觀測性設定中將 `DatadogBridge` 設為 `bridge`，而非放入 `exporters`
* 確認沒有同時將 `DatadogExporter` 加入 `exporters`；兩者並用會重複傳送 LLM Observability 資料

關於 `dd-trace` 原生模組相容性與打包工具外部相依套件設定的問題，請參閱 [Datadog 匯出器疑難排解](#troubleshooting)。
