# Sentry

[Sentry](https://sentry.io/) 是提供 AI 專用追蹤功能的應用程式監控平台。Sentry 匯出器依照 OpenTelemetry 語意慣例傳送 Trace，讓你在 Sentry 查看模型效能、token 用量和 Tool 執行情形。

## 安裝 {/* #installation */}

```bash npm2yarn
npm install @mastra/sentry@latest
```

## 設定 {/* #configuration */}

### 事前準備 {/* #prerequisites */}

1. 到 [sentry.io](https://sentry.io/) 註冊 **Sentry 帳號**。
2. 在 Project Settings → Client Keys 取得專案的 **DSN**（[資料來源名稱](https://docs.sentry.io/concepts/key-terms/dsn-explainer/)）。
3. 依照下列範例設定**環境變數**。

```bash title=".env"
SENTRY_DSN=https://...@...sentry.io/...

# Optional
SENTRY_ENVIRONMENT=production
SENTRY_RELEASE=1.0.0
```

### 使用環境變數 {/* #zero-config-setup */}

設定好環境變數後，建立匯出器時不用傳入任何設定。

```typescript title="src/mastra/index.ts"
import { Mastra } from '@mastra/core'
import { Observability } from '@mastra/observability'
import { SentryExporter } from '@mastra/sentry'

export const mastra = new Mastra({
  observability: new Observability({
    configs: {
      sentry: {
        serviceName: 'my-service',
        exporters: [new SentryExporter()],
      },
    },
  }),
})
```

### 直接指定設定 {/* #explicit-configuration */}

也可以將憑證直接傳給匯出器。直接傳入的憑證優先於環境變數中的值。

```typescript title="src/mastra/index.ts"
import { Mastra } from '@mastra/core'
import { Observability } from '@mastra/observability'
import { SentryExporter } from '@mastra/sentry'

export const mastra = new Mastra({
  observability: new Observability({
    configs: {
      sentry: {
        serviceName: 'my-service',
        exporters: [
          new SentryExporter({
            dsn: process.env.SENTRY_DSN!,
            environment: 'production',
            tracesSampleRate: 1.0, // Send 100% of transactions to Sentry
          }),
        ],
      },
    },
  }),
})
```

## 設定選項 {/* #configuration-options */}

### 完整設定 {/* #complete-configuration */}

```typescript
new SentryExporter({
  // Required settings
  dsn: process.env.SENTRY_DSN!, // Data Source Name - tells the SDK where to send events

  // Optional settings
  environment: 'production', // Deployment environment (enables filtering issues and alerts by environment)
  tracesSampleRate: 1.0, // Percentage of transactions sent to Sentry (0.0 = 0%, 1.0 = 100%)
  release: '1.0.0', // Version of your code deployed (helps identify regressions and track deployments)

  // Advanced Sentry options
  options: {
    // Any additional Sentry.NodeOptions
    integrations: [],
    beforeSend: event => event,
    // ... other Sentry SDK options
  },

  // Diagnostic logging
  logLevel: 'info', // debug | info | warn | error
})
```

### 取樣設定 {/* #sampling-configuration */}

取樣率決定要將多少比例的交易傳送給 Sentry。應用程式負載較高時，可以調低取樣率。

```typescript
new SentryExporter({
  dsn: process.env.SENTRY_DSN!,
  tracesSampleRate: 0.1, // Send 10% of transactions to Sentry (recommended for high-load backends)
})
```

:::tip
開發時建議設為 `1.0`（100%）。正式環境中負載較高的應用程式建議設為 `0.1` 至 `0.2`（10% 至 20%）。若要完全停用追蹤，請省略 `tracesSampleRate`。設為 `0` 仍無法完全停用追蹤。
:::

## Span 類型對應 {/* #span-type-mapping */}

Mastra 的 Span 類型會自動對應到下列 Sentry 作業。

| Mastra SpanType | Sentry 作業 | 說明 |
| - | - | - |
| `AGENT_RUN` | `gen_ai.invoke_agent` | 包含 MODEL\_GENERATION 子 Span 的 token 用量 |
| `MODEL_GENERATION` | `gen_ai.chat` | 包含用量統計與串流資料 |
| `MODEL_STEP` | *（略過）* | 略過此類型以簡化 Trace 階層 |
| `MODEL_CHUNK` | *（略過）* | 資料彙整至 MODEL\_GENERATION |
| `TOOL_CALL` | `gen_ai.execute_tool` | 記錄 Tool 的執行過程、輸入與輸出 |
| `MCP_TOOL_CALL` | `gen_ai.execute_tool` | 記錄 MCP Tool 的執行情形 |
| `WORKFLOW_RUN` | `workflow.run` | |
| `WORKFLOW_STEP` | `workflow.step` | |
| `WORKFLOW_CONDITIONAL` | `workflow.conditional` | |
| `WORKFLOW_CONDITIONAL_EVAL` | `workflow.conditional` | |
| `WORKFLOW_PARALLEL` | `workflow.parallel` | |
| `WORKFLOW_LOOP` | `workflow.loop` | |
| `WORKFLOW_SLEEP` | `workflow.sleep` | |
| `WORKFLOW_WAIT_EVENT` | `workflow.wait` | |
| `PROCESSOR_RUN` | `ai.processor` | |
| `GENERIC` | `ai.span` | |

## OpenTelemetry 語意慣例 {/* #opentelemetry-semantic-conventions */}

匯出器採用標準的 GenAI 語意慣例，並使用 Sentry 專用屬性。

**MODEL\_GENERATION Span**

- `gen_ai.system`：模型 Provider，例如 `openai` 或 `anthropic`
- `gen_ai.request.model`：請求的模型識別碼，例如 `gpt-5.4`
- `gen_ai.response.model`：產生回應的模型
- `gen_ai.response.text`：回應中的文字
- `gen_ai.response.tool_calls`：產生回應時發出的 Tool 呼叫（JSON 陣列）
- `gen_ai.usage.input_tokens`：輸入 token 數
- `gen_ai.usage.output_tokens`：輸出 token 數
- `gen_ai.request.temperature`：溫度參數
- `gen_ai.request.stream`：是否要求以串流方式回傳
- `gen_ai.request.messages`：輸入訊息或提示詞（JSON）
- `gen_ai.completion_start_time`：收到第一個 token 的時間

**TOOL\_CALL Span**

- `gen_ai.tool.name`：Tool 識別碼
- `gen_ai.tool.type`：`function`
- `gen_ai.tool.call.id`：Tool 呼叫 ID
- `gen_ai.tool.input`：Tool 輸入（JSON）
- `gen_ai.tool.output`：Tool 輸出（JSON）
- `tool.success`：Tool 呼叫是否成功

**AGENT\_RUN Span**

- `gen_ai.agent.name`：Agent 識別碼
- `gen_ai.pipeline.name`：Agent 名稱（供 Sentry AI 檢視使用）
- `gen_ai.agent.instructions`：Agent 指令
- `gen_ai.response.model`：模型生成子 Span 記錄的模型
- `gen_ai.response.text`：模型生成子 Span 記錄的輸出文字
- `gen_ai.usage.*`：模型生成子 Span 記錄的 token 用量

## 功能 {/* #features */}

- **Trace 階層**。保留父 Span 與子 Span 的關係。
- **Token 用量追蹤**。自動記錄每次模型生成的 token 用量。
- **Tool 呼叫追蹤**。擷取 Tool 的執行資訊，包括輸入和輸出。
- **串流支援**。彙整串流回應。
- **錯誤追蹤**。自動記錄錯誤狀態並擷取例外。
- **Workflow 支援**。追蹤 Workflow 執行的各個步驟。
- **簡化階層**。略過 MODEL\_STEP 與 MODEL\_CHUNK Span，讓 Trace 更容易閱讀。
