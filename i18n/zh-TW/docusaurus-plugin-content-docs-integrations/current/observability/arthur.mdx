# Arthur

[Arthur](https://arthur.ai/) 透過開放原始碼的 [Arthur Engine](https://github.com/arthur-ai/arthur-engine)，為 AI 應用程式提供 Observability 與評估平台。Arthur 匯出器使用 OpenTelemetry，並遵循 [OpenInference](https://github.com/Arize-ai/openinference/tree/main/spec) 的語意慣例來傳送 Trace。

## 安裝 {/* #installation */}

```bash npm2yarn
npm install @mastra/arthur@latest
```

## 設定 {/* #configuration */}

### 先決條件 {/* #prerequisites */}

1. **Arthur Engine 執行個體**：依照 [Docker Compose 部署指南](https://docs.arthur.ai/docs/arthur-genai-engine-docker-compose-deployment-guide)啟動 Arthur Engine
1. **API 金鑰**：在 `http://localhost:3030` 的 Arthur Engine 介面中[產生 API 金鑰](https://docs.arthur.ai/docs/api-keys-management)
1. **任務 ID**（選用）：[建立任務](https://docs.arthur.ai/docs/create-a-task)，以便將 Trace 路由至指定任務

### 任務路由 {/* #task-routing */}

Arthur Engine 可透過兩種方式將 Trace 與任務建立關聯：

- **依服務名稱**：在 Observability 設定中指定 `serviceName`。Arthur Engine 會自動將 Trace 路由至同名任務，必要時會建立該任務。
- **依任務 ID**：將現有的 `taskId` 傳給匯出器，即可將 Trace 直接送至指定任務。

若同時提供兩者，會優先使用 `taskId`。

### 環境變數 {/* #environment-variables */}

```bash title=".env"
# Required
ARTHUR_API_KEY=your-api-key
ARTHUR_BASE_URL=http://localhost:3030

# Optional - route traces to a pre-existing task by ID
ARTHUR_TASK_ID=your-task-id
```

### 無須額外設定 {/* #zero-config-setup */}

設定環境變數後，即可直接使用匯出器，無須額外設定：

```typescript title="src/mastra/index.ts"
import { Mastra } from '@mastra/core'
import { Observability } from '@mastra/observability'
import { ArthurExporter } from '@mastra/arthur'

export const mastra = new Mastra({
  observability: new Observability({
    configs: {
      arthur: {
        serviceName: 'my-service',
        exporters: [new ArthurExporter()],
      },
    },
  }),
})
```

### 直接指定設定 {/* #explicit-configuration */}

你也可以直接傳入憑證（優先於環境變數）：

```typescript title="src/mastra/index.ts"
import { Mastra } from '@mastra/core'
import { Observability } from '@mastra/observability'
import { ArthurExporter } from '@mastra/arthur'

export const mastra = new Mastra({
  observability: new Observability({
    configs: {
      arthur: {
        serviceName: 'my-service',
        exporters: [
          new ArthurExporter({
            apiKey: process.env.ARTHUR_API_KEY!,
            endpoint: process.env.ARTHUR_BASE_URL!,
            taskId: process.env.ARTHUR_TASK_ID,
          }),
        ],
      },
    },
  }),
})
```

## 設定選項 {/* #configuration-options */}

### 完整設定 {/* #complete-configuration */}

```typescript
new ArthurExporter({
  // Arthur Configuration
  apiKey: 'your-api-key', // Required
  endpoint: 'http://localhost:3030', // Required
  taskId: 'your-task-id', // Optional

  // Optional OTLP settings
  headers: {
    'x-custom-header': 'value', // Additional headers for OTLP requests
  },

  // Debug and performance tuning
  logLevel: 'debug', // Logging: debug | info | warn | error
  batchSize: 512, // Batch size before exporting spans
  timeout: 30000, // Timeout in ms before exporting spans

  // Custom resource attributes
  resourceAttributes: {
    'deployment.environment': process.env.NODE_ENV,
    'service.version': process.env.APP_VERSION,
  },
})
```

### 自訂中繼資料 {/* #custom-metadata */}

非保留的 span 屬性會序列化至 OpenInference 的 `metadata` 資料內容中，並顯示在 Arthur 中。你可以透過 `tracingOptions.metadata` 新增這些屬性：

```ts
await agent.generate(input, {
  tracingOptions: {
    metadata: {
      companyId: 'acme-co',
      tier: 'enterprise',
    },
  },
})
```

系統會自動排除保留欄位，例如 `input`、`output`、`sessionId`、對話串與使用者 ID，以及 OpenInference ID。

## OpenInference 語意慣例 {/* #openinference-semantic-conventions */}

此匯出器實作了適用於生成式 AI 應用程式的 [OpenInference 語意慣例](https://github.com/Arize-ai/openinference/tree/main/spec)，讓不同的 Observability 平台能使用標準化的 Trace 結構。
