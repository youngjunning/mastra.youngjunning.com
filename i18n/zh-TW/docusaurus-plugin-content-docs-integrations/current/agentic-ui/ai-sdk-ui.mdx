# AI SDK UI

[AI SDK UI](https://sdk.vercel.ai) 提供建構 AI 介面所需的 React 工具與元件。本指南說明如何透過 `@mastra/ai-sdk` 將 Mastra 的輸出轉換為 AI SDK 相容格式，讓前端能使用 AI SDK UI 的 Hook 與元件。

:::note
正在從 AI SDK v4 遷移至 v5？請參閱[遷移指南](/reference/migrations/ai-sdk-v4-to-v5)。
:::

:::tip

想看更多範例？請瀏覽 Mastra 的 [**UI Dojo**](https://ui-dojo.mastra.ai/)，或閱讀 [Next.js 快速入門指南](/integrations/frameworks/next-js)。

:::

## 入門 {/* #getting-started */}

安裝 `@mastra/ai-sdk` 套件，即可搭配使用 Mastra 與 AI SDK UI。`@mastra/ai-sdk` 套件提供自訂 API 路由與工具，將 Mastra Agent 的輸出以 AI SDK 相容格式串流傳送；內容包括聊天、Workflow 與 Agent 網路的路由處理函式，以及用於 UI 整合的工具函式和匯出型別。

`@mastra/ai-sdk` 可搭配 AI SDK UI 的三個主要 Hook 使用：[`useChat()`](https://ai-sdk.dev/docs/ai-sdk-ui/chatbot)、[`useCompletion()`](https://ai-sdk.dev/docs/ai-sdk-ui/completion) 與 [`useObject()`](https://ai-sdk.dev/docs/ai-sdk-ui/object-generation)。

先安裝必要套件：

```bash npm2yarn
npm install @mastra/ai-sdk@latest @ai-sdk/react ai
```

安裝完成後，就可以依照以下整合指南與實作範例繼續操作。

## 整合指南 {/* #integration-guides */}

一般會先建立 API 路由，以 AI SDK 相容格式串流傳送 Mastra 內容，再透過 `useChat()` 等 AI SDK UI Hook 呼叫路由。請選擇其中一種方式：

- [Mastra 伺服器](#mastras-server)
- [不依賴特定框架](#framework-agnostic)

設定好 API 路由後，就能在 [`useChat()`](#usechat) Hook 中使用。

### Mastra 伺服器 {/* #mastras-server */}

將 Mastra 作為獨立伺服器執行，再把前端（例如 Vite + React 應用程式）連接到其 API 端點。此方式會用到 Mastra 的[自訂 API 路由](/docs/server/custom-api-routes)功能。

:::note

Mastra 的 [**UI Dojo**](https://ui-dojo.mastra.ai/) 示範了這種架構。

:::

可以使用 [`chatRoute()`](/reference/ai-sdk/chat-route)、[`workflowRoute()`](/reference/ai-sdk/workflow-route) 與 [`networkRoute()`](/reference/ai-sdk/network-route) 建立 API 路由，以 AI SDK 相容格式串流傳送 Mastra 內容。路由建立後，就能在 [`useChat()`](#usechat) 中呼叫。

### 不依賴特定框架 {/* #framework-agnostic */}

如果使用 Next.js 或 Express 等框架，而不執行 Mastra 伺服器，可以在自己的 API 路由處理函式中呼叫 [`handleChatStream()`](/reference/ai-sdk/handle-chat-stream)、[`handleWorkflowStream()`](/reference/ai-sdk/handle-workflow-stream) 與 [`handleNetworkStream()`](/reference/ai-sdk/handle-network-stream)。

這些函式會傳回 `ReadableStream`，可透過 [`createUIMessageStreamResponse()`](https://ai-sdk.dev/docs/reference/ai-sdk-ui/create-ui-message-stream-response) 封裝成回應。

:::tip AI SDK 版本相容性

為了維持向後相容，不依賴特定框架的處理函式預設使用 AI SDK v5。請傳入與已安裝 AI SDK 相符的版本；例如使用 AI SDK v7 時傳入 `version: 'v7'`。呼叫 `handleChatStream()` 與 `handleNetworkStream()` 時，將 `messages` 指定為已安裝 `ai` 版本中的 `UIMessage[]`，可獲得較準確的 TypeScript 型別推論。

:::

以下範例說明如何在 Next.js App Router 中使用這些函式。

### `useChat()` {/* #usechat */}

無論透過 [Mastra 伺服器](#mastras-server)或[自行選擇的框架](#framework-agnostic)建立 API 路由，都可以在 `useChat()` Hook 中呼叫對應端點。

假設 `/chat` 路由使用天氣 Agent，就可以像下面這樣向它提問。請務必將 `api` URL 設為正確的端點。

```ts {9} oxfmt:false
import { useChat } from '@ai-sdk/react'
import { useState } from 'react'
import { DefaultChatTransport } from 'ai'

export default function Chat() {
  const [inputValue, setInputValue] = useState('')
  const { messages, sendMessage } = useChat({
    transport: new DefaultChatTransport({
      api: 'http://localhost:4111/chat',
    }),
  })

  const handleFormSubmit = (e: React.FormEvent) => {
    e.preventDefault()
    sendMessage({ text: inputValue })
  }

  return (
    <div>
      <pre>{JSON.stringify(messages, null, 2)}</pre>
      <form onSubmit={handleFormSubmit}>
        <input
          value={inputValue}
          onChange={e => setInputValue(e.target.value)}
          placeholder="Name of the city"
        />
      </form>
    </div>
  )
}
```

可以使用 [`prepareSendMessagesRequest`](https://ai-sdk.dev/docs/reference/ai-sdk-ui/use-chat#transport.default-chat-transport.prepare-send-messages-request) 自訂傳送至聊天路由的請求，例如傳入額外的 Agent 設定。

### 連線中斷後恢復聊天串流 {/* #resume-a-chat-stream-after-a-disconnect */}

在 Mastra 路由上啟用可恢復的串流：

```typescript title="src/mastra/index.ts"
import { Mastra } from '@mastra/core'
import { chatRoute } from '@mastra/ai-sdk'

export const mastra = new Mastra({
  server: {
    apiRoutes: [
      chatRoute({
        path: '/chat',
        agent: 'weatherAgent',
        resumable: true,
      }),
    ],
  },
})
```

將固定的聊天 ID 傳給 `useChat()`，並設定 `resume: true`。若元件重新掛載時生成任務仍在執行，AI SDK UI 會透過 `GET /chat/:chatId/stream` 重新連線。

```tsx title="src/components/chat.tsx" oxfmt:false
import { useChat } from '@ai-sdk/react'
import { DefaultChatTransport } from 'ai'

export function Chat({ chatId }: { chatId: string }) {
  const { messages, sendMessage, status } = useChat({
    id: chatId,
    resume: true,
    transport: new DefaultChatTransport({
      api: 'http://localhost:4111/chat',
    }),
  })

  // ...render messages and call sendMessage()
}
```

將 `chatId` 保存在 URL、瀏覽器儲存空間或應用程式狀態中，讓重新整理後能沿用相同的值。只有仍在執行的任務可以恢復；已完成或無法取得的任務會傳回 `204`，因此已完成的聊天記錄須另外從記憶載入。

可恢復模式讓生成任務在 POST 連線關閉後繼續執行，因此 `useChat().stop()` 不會取消 Agent 任務。執行中任務僅能在同一個程序內查找，重新連線請求必須送達原本仍在執行的 Mastra 伺服器程序。

如果聊天使用資源 ID，驗證中介軟體必須在請求脈絡中設定 `MASTRA_RESOURCE_ID_KEY`。不能只在 POST 請求本文的 `memory.resource` 中傳送資源 ID，因為重新連線的 GET 請求沒有本文。

### 在 `useChat()` 中使用前端 Tool {/* #client-tools-with-usechat */}

沒有 `execute` 函式的 Tool 會在前端執行。模型呼叫它時，Agent 任務會在該步驟結束，串流以狀態為 `input-available` 的 `tool-{toolKey}` 部分結束。若要讓 Agent 繼續，請在瀏覽器中執行 Tool、透過 `addToolOutput()` 加入結果，再將對話傳回伺服器。設定 `sendAutomaticallyWhen` 後，上一則 assistant 訊息中的每個 Tool 呼叫都有結果時，便會自動送出下一個請求：

```tsx title="src/components/chat.tsx" oxfmt:false
import { useChat } from '@ai-sdk/react'
import { DefaultChatTransport, lastAssistantMessageIsCompleteWithToolCalls } from 'ai'

export default function Chat() {
  const { messages, sendMessage, addToolOutput } = useChat({
    transport: new DefaultChatTransport({
      api: 'http://localhost:4111/chat',
    }),
    sendAutomaticallyWhen: lastAssistantMessageIsCompleteWithToolCalls,
    async onToolCall({ toolCall }) {
      if (toolCall.toolName === 'addToCart') {
        const input = toolCall.input as { productId: string }
        const cart = await addToCartInBrowser(input.productId)

        // Don't await addToolOutput inside onToolCall to avoid deadlocks
        addToolOutput({ tool: 'addToCart', toolCallId: toolCall.toolCallId, output: cart })
      }
    },
  })

  // ...render messages and call sendMessage()
}
```

如果前端只需呈現 Tool 呼叫，而模型不需要結果，可以替 Tool 提供一個回傳簡短確認訊息的 `execute` 函式。Agent 隨後會在同一個請求中繼續生成。請參閱[在前端執行的 Tool](/docs/agents/tools#tools-that-run-on-the-client)。

子 Agent 無法執行前端 Tool：瀏覽器不會收到子 Agent 的 Tool 呼叫。請在聊天路由直接連接的 Agent 上定義前端 Tool。

### 從 `useChat()` 恢復暫停的 Tool {/* #resuming-a-suspended-tool-from-usechat */}

Tool 呼叫 `suspend()` 時，串流會包含 `data-tool-call-suspended` 部分，其中有 `runId`、`toolCallId` 與 `suspendPayload`。若要恢復，請在請求本文中傳送符合該 Tool 的 `resumeSchema` 的 `resumeData`，以及 `runId`。此時 `handleChatStream()` 與 `chatRoute()` 會呼叫 `agent.resumeStream()`，而不是啟動新任務：

```tsx title="src/components/chat.tsx" oxfmt:false
const { messages, sendMessage } = useChat({
  transport: new DefaultChatTransport({
    api: 'http://localhost:4111/chat',
    prepareSendMessagesRequest: ({ messages, body }) => {
      const resume = body?.resume as { runId: string; resumeData: unknown } | undefined
      if (resume) {
        return { body: { messages, runId: resume.runId, resumeData: resume.resumeData } }
      }
      return { body: { messages } }
    },
  }),
})

// When the user confirms the suspended tool call:
sendMessage(
  { text: 'Confirmed' },
  { body: { resume: { runId: suspended.runId, resumeData: { confirmed: true } } } },
)
```

`suspended` 是 `messages` 中最後一個 `data-tool-call-suspended` 部分的 `data`。

若 Tool 在[子 Agent](/docs/agents/human-in-the-loop#identify-which-subagent-tool-paused) 內執行，`data-tool-call-suspended` 與 `data-tool-call-approval` 部分中的 `toolCallId` 代表上層 Agent 對子 Agent 的呼叫。這些部分也包含 `delegatedToolCallId` 與 `delegatedToolName`，用來指出子 Agent 中實際暫停的 Tool 呼叫。可以用它們標示呈現給使用者的提示；恢復時仍使用 `runId` 與 `toolCallId`。

## 使用 Mastra 記憶 {/* #using-mastra-memory */}

若 Agent 已設定[記憶](/docs/memory/overview)，Mastra 會在伺服器端從儲存空間載入對話記錄。前端只需傳送新訊息，無須傳送完整記錄。

傳送完整對話記錄既多餘，也可能造成訊息順序錯誤，因為前端時間戳記可能與資料庫中的時間戳記衝突。Mastra 會先過濾前端回傳的歷史訊息，再載入已儲存的訊息；若訊息 ID 相同，便以儲存的版本為基礎，保留其時間戳記、Provider 中繼資料與推理內容，只加上新的 Tool 結果。

```typescript
import { useChat } from '@ai-sdk/react'
import { DefaultChatTransport } from 'ai'

const { messages, sendMessage } = useChat({
  transport: new DefaultChatTransport({
    api: 'http://localhost:4111/chat/weatherAgent',
    prepareSendMessagesRequest({ messages }) {
      return {
        body: {
          messages: [messages[messages.length - 1]],
          memory: {
            thread: 'user-thread-123',
            resource: 'user-123',
          },
        },
      }
    },
  }),
})
```

請依應用程式本身的狀態設定 `memory.thread` 與 `memory.resource`，例如 URL 參數、驗證脈絡或資料庫中的值。

關於 Mastra 記憶如何載入與儲存訊息，請參閱[訊息記錄](/docs/memory/message-history)。

[`chatRoute()`](/reference/ai-sdk/chat-route) 與 [`handleChatStream()`](/reference/ai-sdk/handle-chat-stream) 已支援記憶。請設定前端只傳送新訊息，並附上對話與資源識別碼。

### `useCompletion()` {/* #usecompletion */}

`useCompletion()` Hook 處理前端與 Mastra Agent 之間的單輪文字補全，讓你透過 HTTP 傳送提示詞並接收串流回應。

前端程式碼可以這樣寫：



```typescript title="app/page.tsx" oxfmt:false
import { useCompletion } from '@ai-sdk/react'

export default function Page() {
  const { completion, input, handleInputChange, handleSubmit } = useCompletion({
    api: '/api/completion',
  })

  return (
    <form onSubmit={handleSubmit}>
      <input name="prompt" value={input} onChange={handleInputChange} id="input" />
      <button type="submit">Submit</button>
      <div>{completion}</div>
    </form>
  )
}
```

## 自訂 UI {/* #custom-ui */}

自訂 UI（也稱為生成式 UI）可依 Mastra 串流傳來的資料呈現自訂 React 元件。除了直接顯示文字或 JSON，也能以視覺化元件呈現 Tool 輸出、Workflow 進度、Agent 網路執行過程與自訂事件。

下列情境適合使用自訂 UI：

- 將 Tool 輸出呈現為視覺化元件，例如以天氣卡片取代 JSON
- 透過狀態指示器顯示 Workflow 步驟進度
- 逐步呈現 Agent 網路的執行過程
- 在耗時作業期間顯示進度指示器或狀態更新

### 資料片段類型 {/* #data-part-types */}

Mastra 會將資料以訊息中的「片段」串流傳送至前端。每個片段的 `type` 決定呈現方式。`@mastra/ai-sdk` 套件會將 Mastra 串流轉換成與 AI SDK 相容的 [UI Message DataParts](https://ai-sdk.dev/docs/reference/ai-sdk-core/ui-message#datauipart)。

| 資料片段類型 | 來源 | 說明 |
| - | - | - |
| `tool-{toolKey}` | AI SDK 內建 | Tool 呼叫，狀態包括 `input-available`、`output-available` 與 `output-error` |
| `data-workflow` | `workflowRoute()` | Workflow 執行狀態快照，包含步驟狀態與最終輸出 |
| `data-workflow-step` | `workflowRoute()` | Workflow 步驟增量，包含變動步驟的完整資料 |
| `data-network` | `networkRoute()` | Agent 網路執行過程，包含依序排列的步驟與輸出 |
| `data-tool-agent` | Tool 內的巢狀 Agent | 目前巢狀步驟仍在執行時的精簡 Agent 快照 |
| `data-tool-agent-step` | Tool 內的巢狀 Agent | 巢狀步驟完成時發出的完整步驟資料 |
| `data-tool-workflow` | Tool 內的巢狀 Workflow | 從 Tool 的 `execute()` 串流傳出的 Workflow 輸出 |
| `data-tool-network` | Tool 內的巢狀 Agent 網路 | 從 Tool 的 `execute()` 串流傳出的網路輸出 |
| `data-{custom}` | `writer.custom()` | 用於進度指示器、狀態更新等的自訂事件 |

### 呈現 Tool 輸出 {/* #rendering-tool-outputs */}

Agent 呼叫 Tool 時，AI SDK 會自動建立 `tool-{toolKey}` 片段。其中包含 Tool 的狀態與輸出，可用來呈現自訂元件。

Tool 片段會依序經過下列狀態：

- `input-streaming`：正在串流傳送 Tool 輸入（啟用 Tool 呼叫串流時）
- `input-available`：Tool 已收到完整輸入，等待執行
- `output-available`：Tool 執行完成並產生輸出
- `output-error`：Tool 執行失敗

以下範例將天氣 Tool 的輸出呈現為自訂 `WeatherCard` 元件。

<Tabs>
  <TabItem value="backend" label="Backend">
    為 Tool 定義 `outputSchema`，讓前端知道待呈現資料的結構。

    ```typescript title="src/mastra/tools/weather-tool.ts" {10-17}
    import { createTool } from '@mastra/core/tools'
    import { z } from 'zod'

    export const weatherTool = createTool({
      id: 'get-weather',
      description: 'Get current weather for a location',
      inputSchema: z.object({
        location: z.string().describe('The location to get the weather for'),
      }),
      outputSchema: z.object({
        temperature: z.number(),
        feelsLike: z.number(),
        humidity: z.number(),
        windSpeed: z.number(),
        conditions: z.string(),
        location: z.string(),
      }),
      execute: async inputData => {
        const response = await fetch(
          `https://api.weatherapi.com/v1/current.json?key=${process.env.WEATHER_API_KEY}&q=${inputData.location}`,
        )
        const data = await response.json()
        return {
          temperature: data.current.temp_c,
          feelsLike: data.current.feelslike_c,
          humidity: data.current.humidity,
          windSpeed: data.current.wind_kph,
          conditions: data.current.condition.text,
          location: data.location.name,
        }
      },
    })
    ```
  </TabItem>

  <TabItem value="frontend" label="Frontend">
    檢查訊息中的 `tool-{toolKey}` 片段，依 Tool 的狀態與輸出呈現自訂元件。

    ```typescript title="src/components/chat.tsx" {24-35} oxfmt:false
    import { useChat } from '@ai-sdk/react'
    import { DefaultChatTransport } from 'ai'
    import { WeatherCard } from './weather-card'
    import { Loader } from './loader'

    export function Chat() {
      const { messages, sendMessage } = useChat({
        transport: new DefaultChatTransport({
          api: 'http://localhost:4111/chat/weatherAgent',
        }),
      })

      return (
        <div>
          {messages.map(message => (
            <div key={message.id}>
              {message.parts.map((part, index) => {
                // Handle user text messages
                if (part.type === 'text' && message.role === 'user') {
                  return <p key={index}>{part.text}</p>
                }

                // Handle weather tool output
                if (part.type === 'tool-weatherTool') {
                  switch (part.state) {
                    case 'input-available':
                      return <Loader key={index} />
                    case 'output-available':
                      return <WeatherCard key={index} {...part.output} />
                    case 'output-error':
                      return <div key={index}>Error: {part.errorText}</div>
                    default:
                      return null
                  }
                }

                return null
              })}
            </div>
          ))}
        </div>
      )
    }
    ```
  </TabItem>

### 呈現 Workflow 資料 {/* #rendering-workflow-data */}

### 自訂事件 {/* #custom-events */}

在 Tool 的 `execute()` 函式中使用 `writer.custom()` 發出自訂資料片段，可在 Tool 執行期間更新進度指示器、狀態或其他自訂 UI。

自訂事件的類型必須以 `data-` 開頭，才能辨識為資料片段。

:::warning

呼叫 `writer.custom()` 時必須使用 `await`，否則可能出現 `WritableStream is locked` 錯誤。

:::

<Tabs>
  <TabItem value="backend" label="Backend">
    在 Tool 的 `execute()` 函式中使用 `writer.custom()`，於不同執行階段發出以 `data-` 開頭的自訂事件。

    ```typescript title="src/mastra/tools/task-tool.ts" {18-24,30-36}
    import { createTool } from '@mastra/core/tools'
    import { z } from 'zod'

    export const taskTool = createTool({
      id: 'process-task',
      description: 'Process a task with progress updates',
      inputSchema: z.object({
        task: z.string().describe('The task to process'),
      }),
      outputSchema: z.object({
        result: z.string(),
        status: z.string(),
      }),
      execute: async (inputData, context) => {
        const { task } = inputData

        // Emit "in progress" custom event
        await context?.writer?.custom({
          type: 'data-tool-progress',
          data: {
            status: 'in-progress',
            message: 'Gathering information...',
          },
        })

        // Simulate work
        await new Promise(resolve => setTimeout(resolve, 3000))

        // Emit "done" custom event
        await context?.writer?.custom({
          type: 'data-tool-progress',
          data: {
            status: 'done',
            message: `Successfully processed "${task}"`,
          },
        })

        return {
          result: `Task "${task}" has been completed successfully!`,
          status: 'completed',
        }
      },
    })
    ```
  </TabItem>

  <TabItem value="frontend" label="Frontend">
    依自訂事件類型篩選訊息片段，並呈現會隨新事件更新的進度指示器。

    ```typescript title="src/components/task-chat.tsx" {31-41,45} oxfmt:false
    import { useChat } from '@ai-sdk/react'
    import { DefaultChatTransport } from 'ai'
    import { useMemo } from 'react'

    type ProgressData = {
      status: 'in-progress' | 'done'
      message: string
    }

    function ProgressIndicator({ progress }: { progress: ProgressData }) {
      return (
        <div className="progress-indicator">
          {progress.status === 'in-progress' ? (
            <span className="spinner" />
          ) : (
            <span className="check-icon" />
          )}
          <span className={`status-${progress.status}`}>{progress.message}</span>
        </div>
      )
    }

    export function TaskChat() {
      const { messages, sendMessage } = useChat({
        transport: new DefaultChatTransport({
          api: 'http://localhost:4111/chat/taskAgent',
        }),
      })

      // Extract the latest progress event from messages
      const latestProgress = useMemo(() => {
        const allProgressParts: ProgressData[] = []
        messages.forEach(message => {
          message.parts.forEach(part => {
            if (part.type === 'data-tool-progress') {
              allProgressParts.push(part.data as ProgressData)
            }
          })
        })
        return allProgressParts[allProgressParts.length - 1]
      }, [messages])

      return (
        <div>
          {latestProgress && <ProgressIndicator progress={latestProgress} />}
          {messages.map(message => (
            <div key={message.id}>
              {message.parts.map((part, index) => {
                if (part.type === 'text') {
                  return <p key={index}>{part.text}</p>
                }
                return null
              })}
            </div>
          ))}
        </div>
      )
    }
    ```

### 經使用者核准後恢復暫停的 Workflow {/* #workflow-suspendresume-with-user-approval */}

Workflow 可暫停執行，等候使用者輸入後再繼續，適用於核准流程、確認及其他需要人工參與的情境。

此 Workflow 使用：

- `suspendSchema` / `resumeSchema`：定義暫停時傳送的資料與恢復時接收的資料結構
- `suspend()`：暫停 Workflow，並將暫停時的資料傳送至 UI
- `resumeData`：包含 Workflow 恢復時使用者提供的回覆
- `bail()`：提前結束 Workflow，例如使用者拒絕時

<Tabs>
  <TabItem value="backend" label="Backend">
    建立一個等待核准時會暫停的 Workflow 步驟。步驟會檢查 `resumeData`，判斷是否正從暫停狀態恢復；首次執行時則呼叫 `suspend()`。

    ```typescript title="src/mastra/workflows/approval-workflow.ts"
    import { createStep, createWorkflow } from '@mastra/core/workflows'
    import { z } from 'zod'

    const requestApproval = createStep({
      id: 'request-approval',
      inputSchema: z.object({ requestId: z.string(), summary: z.string() }),
      outputSchema: z.object({
        approved: z.boolean(),
        requestId: z.string(),
        approvedBy: z.string().optional(),
      }),
      resumeSchema: z.object({
        approved: z.boolean(),
        approverName: z.string().optional(),
      }),
      suspendSchema: z.object({
        message: z.string(),
        requestId: z.string(),
      }),
      execute: async ({ inputData, resumeData, suspend, bail }) => {
        // User rejected - bail out
        if (resumeData?.approved === false) {
          return bail({ message: 'Request rejected' })
        }
        // User approved - continue
        if (resumeData?.approved) {
          return {
            approved: true,
            requestId: inputData.requestId,
            approvedBy: resumeData.approverName || 'User',
          }
        }
        // First execution - suspend and wait
        return await suspend({
          message: `Please approve: ${inputData.summary}`,
          requestId: inputData.requestId,
        })
      },
    })

    export const approvalWorkflow = createWorkflow({
      id: 'approval-workflow',
      inputSchema: z.object({ requestId: z.string(), summary: z.string() }),
      outputSchema: z.object({
        approved: z.boolean(),
        requestId: z.string(),
        approvedBy: z.string().optional(),
      }),
    }).then(requestApproval)

    approvalWorkflow.commit()
    ```

    偵測 Workflow 何時暫停，並傳送包含 `runId`、`step` 與 `resumeData` 的恢復資料。

    ```typescript title="src/components/approval-workflow.tsx" oxfmt:false
    import { useChat } from '@ai-sdk/react'
    import { DefaultChatTransport } from 'ai'
    import { useMemo, useState } from 'react'
    import type { WorkflowDataPart } from '@mastra/ai-sdk'

    type WorkflowData = WorkflowDataPart['data']

    export function ApprovalWorkflow() {
      const [requestId, setRequestId] = useState('')
      const [summary, setSummary] = useState('')

      const { messages, sendMessage, setMessages, status } = useChat({
        transport: new DefaultChatTransport({
          api: 'http://localhost:4111/workflow/approvalWorkflow',
          prepareSendMessagesRequest: ({ messages }) => {
            const lastMessage = messages[messages.length - 1]
            const text = lastMessage.parts.find(p => p.type === 'text')?.text
            const metadata = lastMessage.metadata as Record<string, string>

            // Resuming: send runId, step, and resumeData
            if (text === 'Approve' || text === 'Reject') {
              return {
                body: {
                  runId: metadata.runId,
                  step: 'request-approval',
                  resumeData: { approved: text === 'Approve' },
                },
              }
            }
            // Starting: send inputData
            return {
              body: { inputData: { requestId: metadata.requestId, summary: metadata.summary } },
            }
          },
        }),
      })

      // Find suspended workflow
      const suspended = useMemo(() => {
        for (const m of messages) {
          for (const p of m.parts) {
            if (p.type === 'data-workflow' && (p.data as WorkflowData).status === 'suspended') {
              return { data: p.data as WorkflowData, runId: p.id }
            }
          }
        }
        return null
      }, [messages])

      const handleApprove = () => {
        setMessages([])
        sendMessage({ text: 'Approve', metadata: { runId: suspended?.runId } })
      }

      const handleReject = () => {
        setMessages([])
        sendMessage({ text: 'Reject', metadata: { runId: suspended?.runId } })
      }

      return (
        <div>
          {!suspended ? (
            <form
              onSubmit={e => {
                e.preventDefault()
                setMessages([])
                sendMessage({ text: 'Start', metadata: { requestId, summary } })
              }}
            >
              <input
                value={requestId}
                onChange={e => setRequestId(e.target.value)}
                placeholder="Request ID"
              />
              <input value={summary} onChange={e => setSummary(e.target.value)} placeholder="Summary" />
              <button type="submit" disabled={status !== 'ready'}>
                Submit
              </button>
            </form>
          ) : (
            <div>
              <p>
                {
                  (suspended.data.steps['request-approval']?.suspendPayload as { message: string })
                    ?.message
                }
              </p>
              <button onClick={handleApprove}>Approve</button>
              <button onClick={handleReject}>Reject</button>
            </div>
          )}
        </div>
      )
    }
    ```

- 可以透過 `step.suspendPayload` 取得暫停時的資料

### Tool 中的巢狀 Agent 串流 {/* #nested-agent-streams-in-tools */}

Tool 可在內部呼叫 Agent，並將其輸出串流傳回 UI。巢狀步驟仍在執行時會產生精簡的 `data-tool-agent` 快照；巢狀步驟完成時會產生 `data-tool-agent-step` 片段；整個巢狀任務結束時，還會產生一份完整的 `data-tool-agent` 快照。

這兩種片段都含有巢狀上層 Agent 鏈的委派中繼資料：

- `ancestry`：由外而內排列的委派路徑。每個項目都包含 `toolCallId`，也可能包含 `toolName` 和標準化的 `agentId`。
- `depth`：已知的 Agent 委派層數。直接子 Agent 的深度為 `1`。
- `parentAgentId`：巢狀 Agent 的直接上層 Agent ID。直接子 Agent 不含此欄位，因為根上層 Agent 的 ID 不屬於 Tool 封裝資料。

片段的 `id` 會維持為巢狀 Agent 的任務 ID，因此後續快照會在任務執行期間更新同一份 UI 狀態。

此模式使用：

- `context.mastra.getAgent()`：在 Tool 中取得 Agent 實例
- `agent.stream()`：串流傳送 Agent 的回應
- `stream.fullStream.pipeTo(context.writer)`：將 Agent 串流導入 Tool 的 writer

要點：

- 將 `fullStream` 導入 `context.writer` 會產生 `data-tool-agent` 片段
- 若需要剛完成的巢狀步驟的完整資料，請讀取 `data-tool-agent-step`
- `AgentDataPart` 與 `AgentStepDataPart` 都包含 `ancestry`、`depth` 及選用的 `parentAgentId` 欄位
- `AgentDataPart` 的片段本身包含 `id`，其 `data.text` 是巢狀 Agent 目前的文字快照
- 巢狀 Agent 中發生錯誤的 Tool 會記錄於 `data.toolErrors`；每個項目為 `{ toolCallId, toolName, args?, errorText, providerExecuted? }`。`errorText` 是可安全序列化為 JSON 的字串，因此錯誤傳至前端後不會變成 `{}`
- `toolErrors` 與 `toolCalls`、`toolResults` 一樣，會在每個巢狀步驟邊界重設。已完成步驟的錯誤可從 `data-tool-agent-step` 的 `data.step.toolErrors`，或最終快照的 `data.steps[]` 中讀取
- 串流結束後，Tool 仍會傳回自己的輸出

### 從 Workflow 步驟串流傳送 Agent 文字 {/* #streaming-agent-text-from-workflow-steps */}

Workflow 步驟可將 Agent 串流導入該步驟的 `writer`，即時傳送 Agent 的文字輸出。使用者因此能在 Workflow 執行時看到 Agent 的「思考」過程，無須等步驟結束。

此模式使用：

- Workflow 步驟中的 `writer`：將 Agent 的 `fullStream` 導入步驟的 writer
- text 與 `data-workflow` 片段：前端同時接收串流文字與步驟進度

    ```typescript title="src/mastra/workflows/weather-workflow.ts"
    import { createStep, createWorkflow } from '@mastra/core/workflows'
    import { z } from 'zod'
    import { weatherAgent } from '../agents/weather-agent'

    const analyzeWeather = createStep({
      id: 'analyze-weather',
      inputSchema: z.object({ location: z.string() }),
      outputSchema: z.object({ analysis: z.string(), location: z.string() }),
      execute: async ({ inputData, writer }) => {
        const response = await weatherAgent.stream(
          `Analyze the weather in ${inputData.location} and provide insights.`,
        )

        // Pipe agent stream to step writer for real-time text streaming
        await response.fullStream.pipeTo(writer)

        return {
          analysis: await response.text,
          location: inputData.location,
        }
      },
    })

    const calculateScore = createStep({
      id: 'calculate-score',
      inputSchema: z.object({ analysis: z.string(), location: z.string() }),
      outputSchema: z.object({ score: z.number(), summary: z.string() }),
      execute: async ({ inputData }) => {
        const score = inputData.analysis.includes('sunny') ? 85 : 50
        return { score, summary: `Comfort score for ${inputData.location}: ${score}/100` }
      },
    })

    export const weatherWorkflow = createWorkflow({
      id: 'weather-workflow',
      inputSchema: z.object({ location: z.string() }),
      outputSchema: z.object({ score: z.number(), summary: z.string() }),
    })
      .then(analyzeWeather)
      .then(calculateScore)

    weatherWorkflow.commit()
    ```
