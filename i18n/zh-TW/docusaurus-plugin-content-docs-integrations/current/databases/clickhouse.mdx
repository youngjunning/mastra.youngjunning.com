# ClickHouse

[ClickHouse](https://clickhouse.com/) 是專為分析工作負載設計的列式資料庫。`@mastra/clickhouse` 套件為多個 Mastra 儲存領域提供適配器，也是正式環境可觀測性的建議後端。

ClickHouse 最常在[組合式儲存](/reference/storage/composite)中專門處理可觀測性資料，其餘儲存領域則交由另一個資料庫處理。

## 何時使用 ClickHouse {/* #when-to-use-clickhouse */}

適合在正式環境中儲存追蹤、日誌、指標、評分與回饋。

本機開發時，請組合使用 [LibSQL](/integrations/databases/libsql)（處理記憶與 Workflow）及 `@mastra/duckdb`（處理可觀測性）。單獨使用其中一個都無法滿足開發環境的所有儲存需求：LibSQL 未實作可觀測性領域，DuckDB 則未實作其他領域。範例請參閱[可觀測性概覽](/docs/observability/overview)。

## 安裝 {/* #installation */}

```bash npm2yarn
npm install @mastra/clickhouse@latest
```

你還需要運作中的 ClickHouse 伺服器。託管及自行架設的方案請參閱[託管選項](#hosting-options)。

## 用法 {/* #usage */}

### 使用 vNext 儲存可觀測性資料（建議） {/* #observability-with-vnext-recommended */}

`ObservabilityStorageClickhouseVNext` 是目前的可觀測性領域實作。它採用以 `ReplacingMergeTree` 為基礎的僅插入資料表結構，針對追蹤、日誌、指標、評分與回饋的資料量進行了最佳化。

將它與另一個儲存適配器組合使用，避免可觀測性資料寫入與應用程式資料爭用資源：

```typescript title="src/mastra/index.ts"
import { Mastra } from '@mastra/core'
import { MastraCompositeStore } from '@mastra/core/storage'
import { PostgresStore } from '@mastra/pg'
import { ObservabilityStorageClickhouseVNext } from '@mastra/clickhouse'
import { Observability, MastraStorageExporter } from '@mastra/observability'

const observabilityStore = new ObservabilityStorageClickhouseVNext({
  url: process.env.CLICKHOUSE_URL!,
  username: process.env.CLICKHOUSE_USERNAME!,
  password: process.env.CLICKHOUSE_PASSWORD!,
})

export const mastra = new Mastra({
  storage: new MastraCompositeStore({
    id: 'composite-storage',
    default: new PostgresStore({
      id: 'pg',
      connectionString: process.env.DATABASE_URL!,
    }),
    domains: {
      observability: observabilityStore,
    },
  }),
  observability: new Observability({
    configs: {
      default: {
        serviceName: 'mastra',
        exporters: [new MastraStorageExporter()],
      },
    },
  }),
})
```

以 ClickHouse 作為可觀測性後端時，`MastraStorageExporter` 會自動選用寫入吞吐量最高的 `insert-only` 策略。詳見[追蹤策略](/docs/observability/integrations/exporters/mastra-storage#tracing-strategies)。

刪除追蹤時，也會刪除以同一追蹤 ID 關聯的 span、追蹤根與分支、指標、日誌、評分及回饋。沒有追蹤 ID 的訊號會保留。Mastra 會記錄刪除條件，並等待 ClickHouse 套用輕量級刪除遮罩。呼叫完成後，一般讀取不再傳回此次刪除所符合的資料列。

輕量級刪除只透過 ClickHouse 的 `_row_exists` 遮罩隱藏資料列。資料何時從磁碟實際移除，取決於合併作業及部署時設定的保留 TTL。只有傳入 `retention` 選項，`ObservabilityStorageClickhouseVNext` 才會設定保留期限；Mastra 不會設定預設的保留 TTL。

當五種可觀測性訊號都有有限的保留期限時，Mastra 也會替刪除請求設定 TTL，使其保留時間長於所保護的訊號資料列。只要任何一種訊號沒有保留期限限制，刪除請求也不設期限。計算方式請參閱[儲存保留期限](/reference/storage/retention#clickhouse-native-ttl)。

更新回饋的審核狀態時，系統會讀取目前資料列，再插入替代資料列，因此需要 `SELECT` 與 `INSERT` 權限，而非 `ALTER UPDATE`；插入物化檢視會將每次更新提供給增量輪詢。重新執行刪除的更新還需要[初始化](#initialization)一節所列的刪除權限。如果更新發生時，同一筆回饋正在刪除，更新會再次執行刪除並回傳「找不到」，因此不會重建已刪除的回饋。刪除失敗不會阻止審核狀態更新，但下一次更新會重試：成功則回傳「找不到」；再次失敗則儲存新狀態，同時回傳刪除錯誤。如果網路錯誤或副本延遲使審核資料列在刪除成功後仍存在，下一次更新該回饋時會再次刪除，並回傳「找不到」。

### 使用舊版領域儲存可觀測性資料 {/* #observability-with-the-legacy-domain */}

`ObservabilityStorageClickhouse` 是原有的可觀測性適配器，仍支援尚未遷移至 vNext 資料表結構的專案。它與 vNext 類別採用相同的設定結構。

```typescript
import { ObservabilityStorageClickhouse } from '@mastra/clickhouse'

const observabilityStore = new ObservabilityStorageClickhouse({
  url: process.env.CLICKHOUSE_URL!,
  username: process.env.CLICKHOUSE_USERNAME!,
  password: process.env.CLICKHOUSE_PASSWORD!,
})
```

新專案應使用 `ObservabilityStorageClickhouseVNext`。

### 從舊版遷移到 vNext {/* #migrating-from-legacy-to-vnext */}

若要將舊版 `mastra_ai_spans` 資料表中的歷史 span 遷移至 vNext 資料表結構，請執行：

```bash npm2yarn
npx mastra migrate
```

遷移作業會按天分批將 span 資料從 `mastra_ai_spans` 複製至 `mastra_span_events`，並處理欄位對應及舊資料去重。原資料表會保留作為備份。遷移後，即可透過 vNext 適配器在 Studio 中查看追蹤。

:::note
遷移不會刪除舊資料表。確認遷移結果後再手動刪除。
:::

### 將 ClickHouse 用於所有儲存領域 {/* #clickhouse-for-every-domain */}

`ClickhouseStoreVNext` 以 ClickHouse 承載 `memory`、`workflows` 及 `observability` 領域，並自動使用 vNext 可觀測性適配器。如果希望整個應用程式都使用 ClickHouse，又不想自行設定組合式儲存，可使用此類別。

```typescript title="src/mastra/index.ts"
import { Mastra } from '@mastra/core'
import { ClickhouseStoreVNext } from '@mastra/clickhouse'

export const mastra = new Mastra({
  storage: new ClickhouseStoreVNext({
    id: 'clickhouse-storage',
    url: process.env.CLICKHOUSE_URL!,
    username: process.env.CLICKHOUSE_USERNAME!,
    password: process.env.CLICKHOUSE_PASSWORD!,
  }),
})
```

`ClickhouseStoreVNext` 接受與 `ClickhouseStore` 相同的設定，並在所有儲存領域共用同一個 ClickHouse 用戶端。

#### 手動組合儲存 {/* #manual-composition */}

`ClickhouseStore` 是透過舊版可觀測性適配器承載所有領域的既有類別。新專案應優先使用 `ClickhouseStoreVNext`。若要自訂組合式儲存，例如將某個領域改用其他後端，請手動組合：

```typescript title="src/mastra/index.ts"
import { Mastra } from '@mastra/core'
import { MastraCompositeStore } from '@mastra/core/storage'
import { ClickhouseStore, ObservabilityStorageClickhouseVNext } from '@mastra/clickhouse'

const credentials = {
  url: process.env.CLICKHOUSE_URL!,
  username: process.env.CLICKHOUSE_USERNAME!,
  password: process.env.CLICKHOUSE_PASSWORD!,
}

export const mastra = new Mastra({
  storage: new MastraCompositeStore({
    id: 'composite-storage',
    default: new ClickhouseStore({ id: 'clickhouse-storage', ...credentials }),
    domains: {
      observability: new ObservabilityStorageClickhouseVNext(credentials),
    },
  }),
})
```

### 使用自訂 ClickHouse 用戶端 {/* #bring-your-own-clickhouse-client */}

若需要自訂請求逾時、壓縮或攔截器等連線設定，可以傳入預先設定的用戶端：

```typescript
import { createClient } from '@clickhouse/client'
import { ClickhouseStore } from '@mastra/clickhouse'

const client = createClient({
  url: process.env.CLICKHOUSE_URL!,
  username: process.env.CLICKHOUSE_USERNAME!,
  password: process.env.CLICKHOUSE_PASSWORD!,
  request_timeout: 60_000,
  compression: { request: true, response: true },
})

const storage = new ClickhouseStore({ id: 'clickhouse-storage', client })
```

`ObservabilityStorageClickhouse` 與 `ObservabilityStorageClickhouseVNext` 也接受相同形式的 `client` 參數。

`ClickhouseStore` 也接受 `ClickHouseClientConfigOptions` 的所有選項，例如 `database`、`request_timeout`、`compression`、`keep_alive` 與 `max_open_connections`。

`ClickhouseStore` 與 `ObservabilityStorageClickhouseVNext` 會將 `clickhouse_settings` 套用至各自執行的每筆查詢。在 ClickHouse Cloud 等將資料存放於物件儲存的服務上，限制預先讀取可降低每筆可觀測性查詢的記憶體用量，但未命中本機快取的查詢可能變慢：

```typescript title="src/mastra/index.ts"
const observabilityStore = new ObservabilityStorageClickhouseVNext({
  url: process.env.CLICKHOUSE_URL!,
  username: process.env.CLICKHOUSE_USERNAME!,
  password: process.env.CLICKHOUSE_PASSWORD!,
  clickhouse_settings: {
    filesystem_prefetches_limit: 8,
  },
})
```

### 多副本叢集 {/* #replicated-clusters */}

當 Mastra 透過負載平衡器寫入多副本 ClickHouse 叢集時，使用 `replication`。

```typescript
const storage = new ClickhouseStoreVNext({
  id: 'clickhouse-storage',
  url: process.env.CLICKHOUSE_URL!,
  username: process.env.CLICKHOUSE_USERNAME!,
  password: process.env.CLICKHOUSE_PASSWORD!,
  replication: {
    cluster: 'company_cluster',
  },
})
```

設定 `replication` 後，Mastra 會將資料表引擎從 `MergeTree` 與 `ReplacingMergeTree` 分別改為 `ReplicatedMergeTree` 與 `ReplicatedReplacingMergeTree`。預設的引擎參數為：

* `zookeeperPath`: `'/clickhouse/tables/{shard}/{database}/{table}'`
* `replicaName`: `'{replica}'`

這些預設值符合常見的自行管理叢集慣例。如果叢集現有資料表採用不同的路徑配置，例如不含 `{database}` 區段的 `/clickhouse/tables/{shard}/{table}`，請明確設定相符的 `zookeeperPath`。Mastra 不會從 Keeper 讀取叢集慣例；路徑不符會使 Mastra 的中繼資料寫入與叢集其餘部分不同的分支。

```typescript
new ClickhouseStoreVNext({
  url: process.env.CLICKHOUSE_URL!,
  username: process.env.CLICKHOUSE_USERNAME!,
  password: process.env.CLICKHOUSE_PASSWORD!,
  replication: {
    cluster: 'company_cluster',
    zookeeperPath: '/clickhouse/tables/{shard}/{table}',
  },
})
```

設定 `cluster` 後，Mastra 會在其管理的建立資料表、建立物化檢視、欄位遷移、修改 TTL 及刪除資料表等 DDL 中加入 `ON CLUSTER`。

設定 `cluster` 後，`optimizeTable()` 與 `materializeTtl()` 等手動維護作業會在每個副本上執行。大型叢集執行這些作業的成本可能很高，建議安排在離峰時段；例行合併應交由背景合併佇列處理，無須在每次重新啟動時觸發。

如果現有 Mastra 資料表使用本機 `MergeTree` 或 `ReplacingMergeTree` 引擎，啟用 `replication` 後初始化會失敗。Mastra 不會自動轉換本機資料表，因為跨副本複製並替換資料表並不安全。啟用複寫前，需將受影響的資料表重建為 `Replicated*` 資料表。安全遷移的步驟是：重新命名本機資料表，執行 `CREATE TABLE ... ENGINE = ReplicatedMergeTree(...) ON CLUSTER ...`，再執行 `INSERT INTO ... SELECT * FROM <renamed_local>`，最後刪除 `<renamed_local>`。

不要在 ClickHouse Cloud 上設定 `replication`。Cloud 會在伺服器端將 `MergeTree` 改寫為 `SharedMergeTree`；明確使用 `ReplicatedMergeTree` 會產生錯誤的 DDL。`replication` 僅適用於自行管理的多副本叢集。

### 可觀測性領域選項 {/* #observability-domain-options */}

`ObservabilityStorageClickhouse` 與 `ObservabilityStorageClickhouseVNext` 接受與 `ClickhouseStore` 相同的連線選項：`url`、`username`、`password` 或預先設定的 `client`。`ObservabilityStorageClickhouseVNext` 另接受 `retention`（以天為單位的逐訊號 TTL，詳見 [ClickHouse 原生 TTL](/reference/storage/retention#clickhouse-native-ttl)）及 `traceQuery`（[追蹤查詢](/reference/observability/tracing/advanced-queries)的執行限制）。

## 託管選項 {/* #hosting-options */}

只要能透過 HTTP 連線，就可以使用 ClickHouse。常見方案包括：

* **[ClickHouse Cloud](https://clickhouse.com/cloud)**：提供免費試用方案的託管服務。其連線資訊可直接用於 `url`、`username` 與 `password`。
* **自行架設**：執行官方 [`clickhouse/clickhouse-server`](https://hub.docker.com/r/clickhouse/clickhouse-server) 容器，或使用[官方安裝套件](https://clickhouse.com/docs/en/install)。適用於 VPS、專用伺服器或 Kubernetes。

本機開發時：

```bash
docker run -d --name mastra-clickhouse \
  -p 8123:8123 -p 9000:9000 \
  -e CLICKHOUSE_USER=default \
  -e CLICKHOUSE_PASSWORD=password \
  clickhouse/clickhouse-server
```

```typescript
new ObservabilityStorageClickhouseVNext({
  url: 'http://localhost:8123',
  username: 'default',
  password: 'password',
})
```

## 使用 Railway 和類似平台進行部署 {/* #deploying-with-railway-and-similar-platforms */}

[Railway](https://railway.com)、[Fly.io](https://fly.io)、[Render](https://render.com) 及 Heroku 等平台會在暫存檔案系統上執行應用程式容器。DuckDB 等嵌入式可觀測性後端需要可寫入且持久的本機檔案，因此在這些平台上可能重新啟動後遺失資料，甚至無法部署。

此時可使用 ClickHouse。ClickHouse 透過 HTTP 存取，因此相同的連線設定可用於不同的應用程式託管平台：

```typescript title="src/mastra/index.ts"
import { Mastra } from '@mastra/core'
import { MastraCompositeStore } from '@mastra/core/storage'
import { PostgresStore } from '@mastra/pg'
import { ObservabilityStorageClickhouseVNext } from '@mastra/clickhouse'
import { Observability, MastraStorageExporter } from '@mastra/observability'

export const mastra = new Mastra({
  storage: new MastraCompositeStore({
    id: 'composite-storage',
    default: new PostgresStore({
      id: 'pg',
      connectionString: process.env.DATABASE_URL!,
    }),
    domains: {
      observability: new ObservabilityStorageClickhouseVNext({
        url: process.env.CLICKHOUSE_URL!,
        username: process.env.CLICKHOUSE_USERNAME!,
        password: process.env.CLICKHOUSE_PASSWORD!,
      }),
    },
  }),
  observability: new Observability({
    configs: {
      default: {
        serviceName: 'mastra',
        exporters: [new MastraStorageExporter()],
      },
    },
  }),
})
```

使用以下任一選項配置資料庫：

* **託管服務**：使用 ClickHouse Cloud，並在應用程式託管平台設定 `CLICKHOUSE_URL`、`CLICKHOUSE_USERNAME` 與 `CLICKHOUSE_PASSWORD` 環境變數。
* **在 Railway 上自行架設**：使用官方 Docker 映像檔，為 Railway 專案新增 ClickHouse 服務，再透過 Railway 私有網路從應用程式服務連線。

其他使用暫存檔案系統的託管平台也適用。若應用程式資料也需存放在應用程式主機之外，請為 `default` 儲存搭配託管 PostgreSQL 或 LibSQL/Turso 執行個體。

:::warning
不要將像 DuckDB 這樣的嵌入式後端指向臨時容器檔案系統內的路徑。當容器重新啟動時，寫入其中的資料會遺失，並且在某些平台上該路徑是唯讀的。
:::

## 初始化 {/* #initialization */}

傳入 `Mastra` 類別後，`ClickhouseStore` 會自動呼叫 `init()`，建立資料表結構並執行尚未完成的遷移。透過 `MastraCompositeStore` 使用 `ObservabilityStorageClickhouseVNext` 時也是如此。

若在 `Mastra` 之外管理儲存，請明確呼叫 `init()`：

```typescript
import { ObservabilityStorageClickhouseVNext } from '@mastra/clickhouse'

const observability = new ObservabilityStorageClickhouseVNext({
  url: process.env.CLICKHOUSE_URL!,
  username: process.env.CLICKHOUSE_USERNAME!,
  password: process.env.CLICKHOUSE_PASSWORD!,
})

await observability.init()
```

在 CI/CD 流程中，可為 `ClickhouseStore` 設定 `disableInit: true`，並於使用較高權限憑證的部署步驟執行 `init()`。應用程式執行時的憑證需要：

* 對 Mastra 資料表的 `SELECT` 與 `INSERT` 權限。
* 對需要刪除資料的可觀測性資料表的 `ALTER DELETE` 權限。在 ClickHouse 26.6 及更早版本中，輕量級刪除還需要這些資料表的 `ALTER UPDATE` 權限；ClickHouse 26.7 已取消此要求。

## 可觀察性 {/* #observability */}

ClickHouse 是正式環境可觀測性的建議後端：

* **僅插入策略**：`MastraStorageExporter` 批次寫入已完成的 span，無須逐筆更新，因此能提供最高的寫入吞吐量。
* **列式壓縮**：相較於列向式資料庫中的相同資料，span 屬性及日誌負載通常有更好的壓縮效果。

完整的策略對照及正式環境指南請參閱 [`MastraStorageExporter` 參考文件](/docs/observability/integrations/exporters/mastra-storage#storage-provider-support)。
