# Google Cloud Spanner

Mastra 的 Google Cloud Spanner 儲存介接器提供可水平擴充容量、具備強一致性的儲存後端，採用 Cloud Spanner 的 GoogleSQL 方言。

## 安裝 {/* #installation */}

```bash npm2yarn
npm install @mastra/spanner@latest
```

## 使用方式 {/* #usage */}

```typescript
import { SpannerStore } from '@mastra/spanner'

const storage = new SpannerStore({
  id: 'spanner-storage',
  projectId: process.env.SPANNER_PROJECT_ID!,
  instanceId: process.env.SPANNER_INSTANCE_ID!,
  databaseId: process.env.SPANNER_DATABASE_ID!,
})
```

執行個體與資料庫都必須事先建立。介接器會在首次使用時建立所需的資料表，因此 Spanner 用戶端使用的憑證必須具備變更資料庫結構的權限。也可以在部署步驟中使用權限較高的憑證呼叫一次 `storage.init()`。

## 建構函式範例 {/* #constructor-examples */}

你可以用以下幾種方式建立 `SpannerStore` 執行個體：

```typescript
import { Spanner } from '@google-cloud/spanner'
import { SpannerStore } from '@mastra/spanner'

// Using projectId / instanceId / databaseId
const store1 = new SpannerStore({
  id: 'spanner-storage-1',
  projectId: 'my-gcp-project',
  instanceId: 'my-instance',
  databaseId: 'mastra',
})

// Reusing an existing Spanner Database handle
const spanner = new Spanner({ projectId: 'my-gcp-project' })
const database = spanner.instance('my-instance').database('mastra')

const store2 = new SpannerStore({
  id: 'spanner-storage-2',
  database,
})

// Using the local Spanner emulator (set the SPANNER_EMULATOR_HOST env var)
process.env.SPANNER_EMULATOR_HOST = 'localhost:9010'
const store3 = new SpannerStore({
  id: 'spanner-storage-emulator',
  projectId: 'test-project',
  instanceId: 'test-instance',
  databaseId: 'test-db',
  spannerOptions: { servicePath: 'localhost', port: 9010, sslCreds: undefined },
})
```

## 附加說明 {/* #additional-notes */}

### 資料庫結構管理 {/* #schema-management */}

儲存介接器使用 GoogleSQL 方言建立下列資料表：

* `mastra_workflow_snapshot`：Workflow 狀態與執行資料
* `mastra_threads`：對話串
* `mastra_messages`：個別訊息
* `mastra_resources`：資源工作記憶
* `mastra_scorers`：評估分數
* `mastra_background_tasks`：背景 Tool 執行狀態
* `mastra_agents`：Agent 的精簡記錄（ID、狀態及目前生效的版本）
* `mastra_agent_versions`：依版本保存的 Agent 設定快照
* `mastra_mcp_clients` / `mastra_mcp_client_versions`：MCP 用戶端設定及版本歷程
* `mastra_mcp_servers` / `mastra_mcp_server_versions`：MCP 伺服器設定及版本歷程
* `mastra_skills` / `mastra_skill_versions`：Skill 記錄及各版本的快照（指令、參考資料、指令碼、資源與內容樹）
* `mastra_skill_blobs`：以 SHA-256 雜湊值為索引鍵的內容定址 Blob 儲存空間，用於儲存各版本的 Skill 內容
* `mastra_prompt_blocks` / `mastra_prompt_block_versions`：提示區塊記錄及各版本的內容快照（範本內容、規則與請求情境的結構定義）
* `mastra_scorer_definitions` / `mastra_scorer_definition_versions`：評分器定義記錄及各版本的設定快照（評審指令、模型、分數範圍、預先設定與預設取樣）
* `mastra_schedules` / `mastra_schedule_triggers`：由 cron 驅動的 Workflow 排程和觸發歷程，供 Mastra 內建的 `WorkflowScheduler` 使用
* `mastra_workspaces` / `mastra_workspace_versions`：Workspace 記錄及各版本的設定快照（檔案系統、Sandbox、掛載、搜尋、Skill 與 Tool）
* `mastra_datasets` / `mastra_dataset_items` / `mastra_dataset_versions`：評估資料集、採用 SCD-2 保留版本的項目，以及版本快照
* `mastra_experiments` / `mastra_experiment_results`：實驗執行記錄及各個項目的結果
* `mastra_favorites`：各使用者收藏的 Agent 和 Skill，反正規化的 `favoriteCount` 維護在上層記錄中
* `mastra_channel_installations` / `mastra_channel_config`：跨平台頻道安裝記錄及各平台的設定
* `mastra_ai_spans`：用於可觀測性的 AI 追蹤 Span，分別記錄每筆 Trace 和 Span，提供 Studio 追蹤介面所需的資料

資料表使用 `STRING(MAX)` 儲存文字和 JSON 承載資料，也使用 `INT64`、`FLOAT64`、`BOOL` 與 `TIMESTAMP` 型別。

下列資料表含有 Spanner 專用的 `STORED` 產生欄位。介接器根據 JSON 承載資料填入欄位值，讓常用的篩選條件可以利用一般次要索引，避免透過 `JSON_VALUE` 掃描：

* `mastra_workflow_snapshot.snapshotStatus`：從 `snapshot` 擷取 `$.status`，供 `listWorkflowRuns({ status })` 使用。
* `mastra_schedules.target_workflow_id`：從 `target` 擷取 `$.workflowId`，供 `listSchedules({ workflowId })` 使用。

介接器會在 `init()` 期間透過 `ALTER TABLE ... ADD COLUMN IF NOT EXISTS` 新增這兩個欄位。使用 `initMode: 'validate'` 時，資料庫結構由外部管理，因此會略過新增步驟。如果對應欄位不存在，介接器會在執行時改用 `JSON_VALUE` 篩選。

介接器不會建立或使用獨立的 schema 命名空間。若要隔離資料，請使用專用資料庫。

### 初始化 {/* #initialization */}

將儲存執行個體傳給 `Mastra` 類別後，Mastra 會在任何儲存操作開始前自動呼叫 `init()`：

```typescript
import { Mastra } from '@mastra/core'
import { SpannerStore } from '@mastra/spanner'

const storage = new SpannerStore({
  id: 'spanner-storage',
  projectId: process.env.SPANNER_PROJECT_ID!,
  instanceId: process.env.SPANNER_INSTANCE_ID!,
  databaseId: process.env.SPANNER_DATABASE_ID!,
})

const mastra = new Mastra({
  storage, // init() is called automatically
})
```

如果直接使用儲存執行個體，請在第一次操作前呼叫一次 `init()`。Spanner 不允許同時變更資料庫結構，因此 `SpannerStore.init()` 會依序初始化各個儲存領域。

```typescript
const storage = new SpannerStore({
  id: 'spanner-storage',
  projectId: process.env.SPANNER_PROJECT_ID!,
  instanceId: process.env.SPANNER_INSTANCE_ID!,
  databaseId: process.env.SPANNER_DATABASE_ID!,
})

await storage.init()
const memory = await storage.getStore('memory')
const thread = await memory?.getThreadById({ threadId: '...' })
```

:::warning
如果 `disableInit` 為 true，且未呼叫 `init()`，所需的資料表便不存在，儲存操作會失敗。
:::

### GoogleSQL 特有行為 {/* #googlesql-specifics */}

此介接器有幾項行為與其他關聯式資料庫介接器不同：

* 新增或更新資料時使用 `INSERT OR UPDATE`。Spanner 的這類操作不支援 `RETURNING` 子句，因此呼叫端若需要寫入後的狀態，必須重新讀取資料。
* Spanner 不支援 `TRUNCATE`。`dangerouslyClearAll()` 會執行 `DELETE WHERE TRUE`。
* 識別字以反引號括住。
* DDL 透過 `database.updateSchema(...)` 套用。這是非同步的長時間執行作業。
* Spanner 不支援 `NULLS FIRST/LAST`。介接器使用 `IS NULL` 做為排序鍵，以模擬 NULL 值的排序行為。
* Spanner 未原生支援 JSON 包含比對。介接器會將 `listTraces` 的 `metadata` 和 `scope` 篩選條件轉為逐鍵執行的 `JSON_VALUE(...) = @v` 等值檢查，並將 `tags` 篩選條件轉為對 `JSON_QUERY_ARRAY(...)` 結果執行的 `EXISTS` 檢查。Postgres 的 `@>` 包含運算子可透過一次索引掃描比對巢狀結構。Spanner 的轉換方式仍能處理大多數單次查詢，但無法表示深層巢狀的結構比對。

### 直接存取資料庫 {/* #direct-database-access */}

`SpannerStore` 提供底層的 Spanner 用戶端物件：

```typescript
store.database // @google-cloud/spanner Database
store.instance // @google-cloud/spanner Instance (when created internally)
store.spanner // @google-cloud/spanner Spanner client (when created internally)
```

這些物件適用於自訂交易或檢視資料庫結構等進階用途。直接使用資料庫物件時，會略過介接器的驗證和 JSON 轉換邏輯。

### 使用模擬器在本機開發 {/* #local-development-with-the-emulator */}

使用 Docker 在本機執行 Cloud Spanner 模擬器：

```bash
docker run -p 9010:9010 -p 9020:9020 gcr.io/cloud-spanner-emulator/emulator
```

設定 `SPANNER_EMULATOR_HOST=localhost:9010`，並在執行應用程式前建立執行個體與資料庫：

```bash
gcloud spanner instances create test-instance --config=emulator-config --nodes=1
gcloud spanner databases create test-db --instance=test-instance
```

連線時，在 Node.js 程序中設定相同的環境變數。`@google-cloud/spanner` 用戶端會自動偵測模擬器。
