# DynamoDB

DynamoDB 儲存配接器採用 [ElectroDB](https://electrodb.dev/) 的單一資料表設計，為 Mastra 提供大容量、高效能的 NoSQL 資料庫儲存方案。

:::warning[不支援可觀測性]

DynamoDB 儲存配接器**不支援可觀測性資料**。`MastraStorageExporter` 匯出的 Trace 無法持久化儲存至 DynamoDB。如果只使用 DynamoDB 作為儲存 Provider，[Studio](/docs/studio/overview) 的可觀測性功能便無法運作。若要啟用這些功能，請透過[複合儲存](/reference/storage/composite#specialized-storage-for-observability)將可觀測性資料送至支援該功能的 Provider，例如 ClickHouse。

:::

:::warning[資料項目大小上限]
DynamoDB 的**單一資料項目大小上限為 400 KB**。儲存含有 Base64 編碼附件（例如圖片）的訊息時，可能會超過這個上限。若要瞭解如何將附件上傳到外部儲存空間等因應方式，請參閱[處理大型附件](/docs/memory/memory-processors#handling-large-attachments)。
:::

## 功能 {/* #features */}

* 以高效率的單一資料表設計滿足 Mastra 的各類儲存需求
* 透過 ElectroDB 安全地依型別存取 DynamoDB 資料
* 支援設定 AWS 憑證、區域和端點
* 支援 AWS DynamoDB Local，便於在本機開發
* 儲存對話串、訊息、評估和 Workflow 資料
* 針對無伺服器環境最佳化
* 可為不同實體類型分別設定 TTL（存留時間），讓資料自動到期

## 安裝 {/* #installation */}

```bash npm2yarn
npm install @mastra/dynamodb@latest
```

## 事前準備 {/* #prerequisites */}

使用這個套件前，**必須**先建立符合指定結構的 DynamoDB 資料表，並設定主索引鍵和全域次要索引（GSI）。資料表和 GSI 須在配接器外預先建置。

請依 [TABLE\_SETUP.md](https://github.com/mastra-ai/mastra/blob/main/stores/dynamodb/TABLE_SETUP.md) 的步驟，使用 AWS CloudFormation 或 AWS CDK 完成資料表設定，再繼續操作。

## 使用方式 {/* #usage */}

### 基本使用方式 {/* #basic-usage */}

```typescript
import { Memory } from '@mastra/memory'
import { DynamoDBStore } from '@mastra/dynamodb'

// Initialize the DynamoDB storage
const storage = new DynamoDBStore({
  id: 'dynamodb', // Unique identifier for this storage instance
  config: {
    tableName: 'mastra-single-table', // Name of your DynamoDB table
    region: 'us-east-1', // Optional: AWS region, defaults to 'us-east-1'
    // endpoint: "http://localhost:8000", // Optional: For local DynamoDB
    // credentials: { accessKeyId: "YOUR_ACCESS_KEY", secretAccessKey: "YOUR_SECRET_KEY" } // Optional
  },
})

// Example: Initialize Memory with DynamoDB storage
const memory = new Memory({
  storage,
  options: {
    lastMessages: 10,
  },
})
```

### 透過 DynamoDB Local 在本機開發 {/* #local-development-with-dynamodb-local */}

在本機開發時，可以使用 [DynamoDB Local](https://docs.aws.amazon.com/amazondynamodb/latest/developerguide/DynamoDBLocal.html)。

1. **啟動 DynamoDB Local，例如使用 Docker。**

   ```bash
   docker run -p 8000:8000 amazon/dynamodb-local
   ```

2. **將 `DynamoDBStore` 設定為連線至本機端點。**

   ```typescript
   import { DynamoDBStore } from '@mastra/dynamodb'

   const storage = new DynamoDBStore({
     id: 'dynamodb-local',
     config: {
       tableName: 'mastra-single-table', // Ensure this table is created in your local DynamoDB
       region: 'localhost', // Can be any string for local, 'localhost' is common
       endpoint: 'http://localhost:8000',
       // For DynamoDB Local, credentials are not typically required unless configured.
       // If you've configured local credentials:
       // credentials: { accessKeyId: "fakeMyKeyId", secretAccessKey: "fakeSecretAccessKey" }
     },
   })
   ```

   本機的 DynamoDB 執行個體仍需要資料表和 GSI。可以在 AWS CLI 指定本機端點後建立。

## 設定 TTL（存留時間） {/* #ttl-time-to-live-configuration */}

DynamoDB 的 TTL 功能可在指定時間過後自動刪除資料項目，適用於下列情境。

* **節省成本**：自動清除舊資料，降低儲存成本
* **管理資料生命週期**：落實資料保留政策，符合相關規範
* **維持效能**：避免資料表持續膨脹
* **符合隱私規範**：在指定期限過後自動清除個人資料

### 啟用 TTL {/* #enabling-ttl */}

使用 TTL 前，必須完成下列兩個步驟。

1. **在 DynamoDBStore 中設定 TTL**，如以下範例所示。
2. **使用 AWS 主控台或 CLI，為 DynamoDB 資料表啟用 TTL**，並指定屬性名稱（預設為 `ttl`）。

```typescript
import { DynamoDBStore } from '@mastra/dynamodb'

const storage = new DynamoDBStore({
  name: 'dynamodb',
  config: {
    tableName: 'mastra-single-table',
    region: 'us-east-1',
    ttl: {
      // Messages expire after 30 days
      message: {
        enabled: true,
        defaultTtlSeconds: 30 * 24 * 60 * 60, // 30 days
      },
      // Threads expire after 90 days
      thread: {
        enabled: true,
        defaultTtlSeconds: 90 * 24 * 60 * 60, // 90 days
      },
      // Traces expire after 7 days with custom attribute name
      trace: {
        enabled: true,
        attributeName: 'expiresAt', // Custom TTL attribute
        defaultTtlSeconds: 7 * 24 * 60 * 60, // 7 days
      },
      // Workflow snapshots don't expire
      workflow_snapshot: {
        enabled: false,
      },
    },
  },
})
```

### 支援的實體類型 {/* #supported-entity-types */}

### 為 DynamoDB 資料表啟用 TTL {/* #enabling-ttl-on-your-dynamodb-table */}

在程式碼設定 TTL 後，還必須在 DynamoDB 資料表上啟用這項功能。

**使用 AWS CLI**

```bash
aws dynamodb update-time-to-live \
  --table-name mastra-single-table \
  --time-to-live-specification "Enabled=true, AttributeName=ttl"
```

**使用 AWS 主控台**

1. 開啟 DynamoDB 主控台。
2. 選取要設定的資料表。
3. 切換到「其他設定」（Additional settings）索引標籤。
4. 在「存留時間 (TTL)」（Time to Live (TTL)）區段中，選取「管理 TTL」（Manage TTL）。
5. 啟用 TTL 並指定屬性名稱（預設為 `ttl`）。

:::note

資料項目到期後，DynamoDB 會在 48 小時內刪除該項目。實際刪除前仍可查詢。

:::

## AWS IAM 權限 {/* #aws-iam-permissions */}

執行程式碼所使用的 IAM 角色或使用者，須具備操作指定 DynamoDB 資料表及其索引的權限。請在下列政策範例中，將 `${YOUR_TABLE_NAME}` 換成實際資料表名稱，並將 `${YOUR_AWS_REGION}` 和 `${YOUR_AWS_ACCOUNT_ID}` 換成對應的 AWS 區域和帳戶 ID。

```json
{
  "Version": "2012-10-17",
  "Statement": [
    {
      "Effect": "Allow",
      "Action": [
        "dynamodb:DescribeTable",
        "dynamodb:GetItem",
        "dynamodb:PutItem",
        "dynamodb:UpdateItem",
        "dynamodb:DeleteItem",
        "dynamodb:Query",
        "dynamodb:Scan",
        "dynamodb:BatchGetItem",
        "dynamodb:BatchWriteItem"
      ],
      "Resource": [
        "arn:aws:dynamodb:${YOUR_AWS_REGION}:${YOUR_AWS_ACCOUNT_ID}:table/${YOUR_TABLE_NAME}",
        "arn:aws:dynamodb:${YOUR_AWS_REGION}:${YOUR_AWS_ACCOUNT_ID}:table/${YOUR_TABLE_NAME}/index/*"
      ]
    }
  ]
}
```

## 使用注意事項 {/* #key-considerations */}

使用 DynamoDB 儲存配接器時，請留意以下事項。

* **預先建置資料表**：使用配接器之前，必須依照 [TABLE\_SETUP.md](https://github.com/mastra-ai/mastra/blob/main/stores/dynamodb/TABLE_SETUP.md) 自行建立並設定 DynamoDB 資料表和全域次要索引（GSI）。
* **單一資料表設計**：對話串、訊息等 Mastra 資料集中在同一張 DynamoDB 資料表。這是針對 DynamoDB 最佳化的設計方式，有別於關聯式資料庫的做法。
* **掌握 GSI 結構**：瞭解 `TABLE_SETUP.md` 中的 GSI 結構，有助於掌握如何擷取資料，以及可以採用哪些查詢模式。
* **ElectroDB**：配接器透過 ElectroDB 管理與 DynamoDB 的互動，為底層操作提供抽象層和型別安全。

## 儲存架構 {/* #architectural-approach */}

此儲存配接器透過 [ElectroDB](https://electrodb.dev/) 採用 **單一資料表設計**，這是 DynamoDB 常見且建議採用的做法。關聯式資料庫配接器（例如 `@mastra/pg` 或 `@mastra/libsql`）通常採用多張資料表，分別存放對話串、訊息等不同實體。

這個架構有以下特點。

* **善用 DynamoDB 原生功能**：單一資料表設計針對 DynamoDB 的鍵值存取與查詢功能最佳化，通常比仿照關聯式模型有更好的效能與容量表現。
* **由外部管理資料表**：部分配接器可能提供輔助函式，讓你透過程式碼建表。此配接器則要求 **在使用前從外部建置 DynamoDB 資料表及其全域次要索引（GSI）**，並且只操作既有資料表結構。使用 AWS CloudFormation 或 CDK 等工具的詳細步驟，請參閱 [TABLE\_SETUP.md](https://github.com/mastra-ai/mastra/blob/main/stores/dynamodb/TABLE_SETUP.md)。
* **一致的介面**：即使底層儲存模型有別，此配接器仍實作與其他配接器相同的 `MastraStorage` 介面，因此可以在 Mastra 的 `Memory` 元件中互換。

### Mastra 資料在單一資料表中的組織方式 {/* #mastra-data-in-the-single-table */}

ElectroDB 在同一張 DynamoDB 資料表中區分並管理各類 Mastra 實體，例如對話串、訊息、Trace、評估和 Workflow。每種實體都有專屬的模型、索引鍵結構和屬性，讓配接器能在同一張資料表中有效率地儲存及擷取不同類型的資料。

舉例來說，`Thread` 資料項目可以使用 `THREAD#<threadId>` 作為主索引鍵。同一個對話串中的 `Message` 資料項目則可以使用 `THREAD#<threadId>` 作為分割區索引鍵，並使用 `MESSAGE#<messageId>` 作為排序索引鍵。`TABLE_SETUP.md` 說明的全域次要索引（GSI）支援各類實體的常見存取模式，例如擷取某個對話串中的所有訊息，或查詢與某個 Workflow 相關的 Trace。

### 單一資料表設計的優點 {/* #advantages-of-single-table-design */}

透過 ElectroDB 在 DynamoDB 實作單一資料表設計，有以下優點。

1. **可能降低成本**：資料表較少時，更容易佈建及管理讀取與寫入容量單位（RCU/WCU），尤其是在使用隨需容量時。
2. **改善效能**：可將相關資料存放在一起，或透過 GSI 有效率地存取，加快常見查詢。
3. **簡化管理**：需要監控和備份的資料表較少，管理負擔也會降低。
4. **降低存取模式的複雜度**：ElectroDB 協助管理同一張資料表中的多種資料項目和存取模式。
5. **支援交易**：視需要，可在同一筆 DynamoDB 交易中操作同一張資料表裡不同類型的實體。
