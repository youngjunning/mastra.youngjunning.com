# PostgreSQL

PostgreSQL 儲存實作提供以 PostgreSQL 資料庫為基礎、可用於正式環境的儲存方案。

## 安裝 {/* #installation */}

```bash npm2yarn
npm install @mastra/pg@latest
```

## 用法 {/* #usage */}

```typescript
import { PostgresStore } from '@mastra/pg'

const storage = new PostgresStore({
  id: 'pg-storage',
  connectionString: process.env.DATABASE_URL,
})
```

## 構造函數範例 {/* #constructor-examples */}

可以透過以下方式建立 `PostgresStore` 實例：

```ts
import { PostgresStore } from '@mastra/pg'
import { Pool } from 'pg'

// Using a connection string
const store1 = new PostgresStore({
  id: 'pg-storage-1',
  connectionString: 'postgresql://user:password@localhost:5432/mydb',
})

// Using a connection string with pool options
const store2 = new PostgresStore({
  id: 'pg-storage-2',
  connectionString: 'postgresql://user:password@localhost:5432/mydb',
  schemaName: 'custom_schema',
  max: 30, // Max pool connections
  idleTimeoutMillis: 60000, // Idle timeout
  ssl: { rejectUnauthorized: false },
})

// Using individual connection parameters
const store3 = new PostgresStore({
  id: 'pg-storage-3',
  host: 'localhost',
  port: 5432,
  database: 'mydb',
  user: 'user',
  password: 'password',
})

// Using a pre-configured pg.Pool (recommended for pool reuse)
const existingPool = new Pool({
  connectionString: 'postgresql://user:password@localhost:5432/mydb',
  max: 20,
  // ... your custom pool configuration
})

const store4 = new PostgresStore({
  id: 'pg-storage-4',
  pool: existingPool,
  schemaName: 'custom_schema', // optional
})
```

## 附加說明 {/* #additional-notes */}

### Schema 管理 {/* #schema-management */}

儲存實作會自動建立及更新 schema，並建立以下資料表：

* `mastra_workflow_snapshot`：儲存 Workflow 狀態與執行資料
* `mastra_evals`：儲存評估結果與中繼資料
* `mastra_threads`：儲存對話串
* `mastra_messages`：儲存個別訊息
* `mastra_traces`：儲存遙測與追蹤資料
* `mastra_scorers`：儲存評分與評估資料
* `mastra_resources`：儲存資源的工作記憶資料
* `mastra_notifications`：儲存通知收件匣紀錄與傳送中繼資料

`PostgresStore` 透過 `getStore('notifications')` 提供通知儲存空間。

### 可觀察性 {/* #observability */}

PostgreSQL 支援可觀測性，也能處理少量 trace。吞吐能力取決於硬體、schema 設計、索引及資料保留政策等部署因素，應在實際環境中驗證。若正式環境的 trace 量很大，可以考慮：

* 使用 `insert-only` [追蹤策略](/docs/observability/integrations/exporters/mastra-storage#tracing-strategies)，減少資料庫寫入操作
* 將資料表分割，以便有效保留資料
* 如需進一步擴充，透過[組合儲存使用 ClickHouse](/reference/storage/composite#specialized-storage-for-observability) 處理可觀測性資料

`PostgresStoreVNext` 則採用 `event-sourced` [追蹤策略](/docs/observability/integrations/exporters/mastra-storage#tracing-strategies)。span 開始與結束時各寫入一筆資料，不會就地更新資料列；讀取 trace 時才合併這些資料列。寫入始終只會追加，執行程序尚未結束時，Studio 中就能看到 trace。

#### 篩選值建議 {/* #filter-suggestions */}

Studio 的 Traces、Logs 和 Metrics 頁面會根據可觀測性資料提供篩選值建議，包括 tag、服務名稱、環境、實體名稱、指標名稱與 label。這些值會快取在資料庫中；快取過期後，系統會在背景重新計算。

為降低大型資料集的更新成本，發現程序只掃描最近 30 天的事件。只出現在更早事件中的值不會列為建議，但仍可用來篩選。使用 `discovery` 調整掃描範圍或更新頻率：

```typescript
import { PostgresStoreVNext } from '@mastra/pg'

const storage = new PostgresStoreVNext({
  id: 'pg-storage',
  connectionString: process.env.DATABASE_URL,
  observability: {
    connectionString: process.env.OBSERVABILITY_DATABASE_URL,
    discovery: {
      lookbackSeconds: 7 * 24 * 60 * 60, // scan the last 7 days; 0 scans all history
      ttlSeconds: 15 * 60, // refresh at most every 15 minutes
    },
  },
})
```

如果更新太慢，可降低 `lookbackSeconds`；如果更新頻率高於篩選值的變動頻率，可提高 `ttlSeconds`。同一快取項目每次只由一個程序更新，因此增加伺服器實例不會讓更新工作量倍增。

#### 每日分割區 {/* #day-partitions */}

`PostgresStoreVNext` 將可觀測性事件存入按日分割的資料表。若已安裝 TimescaleDB 或 pg\_partman，該擴充套件會建立分割區。未安裝擴充套件時，`init()` 會為昨天、今天及之後 `futureDays` 天（預設 14 天）建立分割區。若寫入日期落在此範圍內卻沒有對應分割區，系統會先建立分割區再重試，因此預建範圍用盡後仍可繼續寫入。日期超出此範圍的資料列仍會遭到拒絕。

建立分割區屬於 DDL 操作。若應用程式執行角色無法建立資料表，或不擁有可觀測性資料表，寫入就會失敗；錯誤會指出資料表及缺少分割區的日期。exporter 重試後會捨棄該批資料。在這種設定下，應使用能建立資料表且擁有可觀測性資料表的角色，至少每隔 `futureDays` 天排程呼叫一次 `ensurePartitions()`。它只延長原生每日分割區的涵蓋範圍，對 TimescaleDB 或 pg\_partman 不起作用。也可以安裝 TimescaleDB，或為 pg\_partman 啟用背景 worker、排程呼叫 `run_maintenance()`，讓資料庫自行維護分割區。

增大 `futureDays` 可讓排程工作兩次執行之間有更長間隔：

```typescript
import { PostgresStoreVNext } from '@mastra/pg'

const storage = new PostgresStoreVNext({
  id: 'pg-storage',
  connectionString: process.env.DATABASE_URL,
  observability: {
    connectionString: process.env.OBSERVABILITY_DATABASE_URL,
    partitioning: {
      futureDays: 60, // pre-create 60 days of partitions on init()
    },
  },
})
```

接著在排程工作中呼叫 `ensurePartitions()`：

```typescript
// OBSERVABILITY_DATABASE_URL connects as a role that owns the observability tables
await storage.ensurePartitions()
await storage.close()
```

### 初始化 {/* #initialization */}

將儲存空間傳入 Mastra 類別後，系統會在執行任何儲存操作前自動呼叫 `init()`：

```typescript
import { Mastra } from '@mastra/core'
import { PostgresStore } from '@mastra/pg'

const storage = new PostgresStore({
  id: 'pg-storage',
  connectionString: process.env.DATABASE_URL,
})

const mastra = new Mastra({
  storage, // init() is called automatically
})
```

若不透過 Mastra 而直接使用儲存空間，必須明確呼叫 `init()` 來建立資料表：

```typescript
import { PostgresStore } from '@mastra/pg'

const storage = new PostgresStore({
  id: 'pg-storage',
  connectionString: process.env.DATABASE_URL,
})

// Required when using storage directly
await storage.init()

// Access domain-specific stores via getStore()
const memoryStore = await storage.getStore('memory')
const thread = await memoryStore?.getThreadById({ threadId: '...' })
```

:::warning
如果沒有呼叫 `init()`，資料表就不會建立；儲存操作可能無聲失敗或擲出錯誤。
:::

### 託管 PostgreSQL 和連線池 {/* #managed-postgresql-and-connection-poolers */}

`PostgresStore` 可使用託管 PostgreSQL Provider 提供的連線字串建立連線，不需要安裝該 Provider 專用的套件。

`init()` 會在同一條連線上執行所有 schema 變更，因此可透過 PgBouncer 等交易模式連線池運作。可以使用 Provider 提供的池化連線字串，讓 Mastra 在啟動時建立 schema。

#### 獨立初始化 schema {/* #separate-schema-initialization */}

若執行階段的資料庫角色無法建立資料表或索引，請在部署期間使用具備相關權限的角色執行一次 `init()`：

```typescript title="scripts/init-storage.ts"
import { PostgresStore } from '@mastra/pg'

const storage = new PostgresStore({
  id: 'pg-storage-init',
  connectionString: process.env.DATABASE_ADMIN_URL,
})

try {
  await storage.init()
  // Only needed if the application uses Knowledge
  await storage.initKnowledge()
} finally {
  await storage.close()
}
```

執行階段的角色需要具備讀寫此腳本所建立資料表的權限。請參閱 [PostgreSQL 權限文件](https://www.postgresql.org/docs/current/ddl-priv.html)。

接著在執行階段的儲存實例設定 `disableInit: true`，略過 schema 建立：

```typescript title="src/mastra/index.ts"
import { Mastra } from '@mastra/core'
import { PostgresStore } from '@mastra/pg'

export const mastra = new Mastra({
  storage: new PostgresStore({
    id: 'pg-storage',
    connectionString: process.env.DATABASE_URL,
    disableInit: true,
  }),
})
```

設定 `disableInit: true` 後，即使明確呼叫 `init()` 也不會執行任何操作，因此部署腳本中的儲存實例不要設定此選項。

### 使用現有連線池 {/* #using-an-existing-pool */}

如果應用程式已有 `pg.Pool`（例如與 ORM 共用，或用於資料列層級安全性），可以直接傳給 `PostgresStore`：

```typescript
import { Pool } from 'pg'
import { PostgresStore } from '@mastra/pg'

// Your existing pool (shared across your application)
const pool = new Pool({
  connectionString: process.env.DATABASE_URL,
  max: 20,
})

const storage = new PostgresStore({
  id: 'shared-storage',
  pool: pool,
})
```

**連線池的生命週期：**

* **由你提供連線池**時：Mastra 會使用該連線池，但呼叫 `store.close()` 時**不會**關閉它；連線池的生命週期由你管理。
* **由 Mastra 建立連線池**時：Mastra 擁有該連線池，呼叫 `store.close()` 時會將其關閉。

### 直接存取資料庫與連線池 {/* #direct-database-and-pool-access */}

`PostgresStore` 提供底層資料庫用戶端與連線池，供進階情境使用：

```typescript
store.db // DbClient - query interface with helpers (any, one, tx, etc.)
store.pool // pg.Pool - the underlying connection pool
```

**使用 `store.db` 查詢：**

```typescript
// Execute queries with helper methods
const users = await store.db.any('SELECT * FROM users WHERE active = $1', [true])
const user = await store.db.one('SELECT * FROM users WHERE id = $1', [userId])
const maybeUser = await store.db.oneOrNone('SELECT * FROM users WHERE email = $1', [email])

// Use transactions
const result = await store.db.tx(async t => {
  await t.none('INSERT INTO logs (message) VALUES ($1)', ['Started'])
  const data = await t.any('SELECT * FROM items')
  return data
})
```

**直接使用 `store.pool`：**

```typescript
// Get a client for manual connection management
const client = await store.pool.connect()
try {
  await client.query('SET LOCAL app.user_id = $1', [userId])
  const result = await client.query('SELECT * FROM protected_table')
  return result.rows
} finally {
  client.release()
}
```

使用這些欄位時：

* 你必須自行妥善管理連線與交易。
* 只有連線池由 Mastra 建立時，關閉儲存空間（`store.close()`）才會銷毀連線池。
* 直接存取會略過 PostgresStore 方法提供的其他邏輯或驗證。

這種方式適合需要底層存取能力的進階情境。

### 與 Next.js 一起使用 {/* #using-with-nextjs */}

在 Next.js 應用程式中使用 `PostgresStore` 時，開發期間的[熱模組替換（HMR）](https://nextjs.org/docs/architecture/fast-refresh)可能建立多個儲存實例，並出現以下警告：

```text
WARNING: Creating a duplicate database object for the same connection.
```

為避免這種情況，請將 `PostgresStore` 實例存放在全域物件中，使其在 HMR 重新載入後仍可重複使用：

```typescript title="src/mastra/storage.ts"
import { PostgresStore } from '@mastra/pg'
import { Memory } from '@mastra/memory'

// Extend the global type to include our instances
declare global {
  var pgStore: PostgresStore | undefined
  var memory: Memory | undefined
}

// Get or create the PostgresStore instance
function getPgStore(): PostgresStore {
  if (!global.pgStore) {
    if (!process.env.DATABASE_URL) {
      throw new Error('DATABASE_URL is not defined in environment variables')
    }
    global.pgStore = new PostgresStore({
      id: 'pg-storage',
      connectionString: process.env.DATABASE_URL,
      ssl: process.env.DATABASE_SSL === 'true' ? { rejectUnauthorized: false } : false,
    })
  }
  return global.pgStore
}

// Get or create the Memory instance
function getMemory(): Memory {
  if (!global.memory) {
    global.memory = new Memory({
      storage: getPgStore(),
    })
  }
  return global.memory
}

export const storage = getPgStore()
export const memory = getMemory()
```

然後在 Mastra 配置中使用導出的實例：

```typescript title="src/mastra/index.ts"
import { Mastra } from '@mastra/core/mastra'
import { storage } from './storage'

export const mastra = new Mastra({
  storage,
  // ...other config
})
```

無論開發期間模組重新載入多少次，這種寫法都只會建立一個 `PostgresStore` 實例。同樣的方式也適用於 `LibSQLStore` 等其他儲存 Provider。

:::tip
只有在本機開發使用 HMR 時才需要這種單例模式。正式環境建置中，模組只會載入一次。
:::

## 使用範例 {/* #usage-example */}

### 為 Agent 加入記憶 {/* #adding-memory-to-an-agent */}

若要為 Agent 加入以 PostgreSQL 儲存的記憶，請使用 `Memory` 類別，並將透過 `PostgresStore` 建立的實例指定給 `storage` 鍵。`connectionString` 可以指向遠端資料庫，也可以是本機資料庫連線。

```typescript title="src/mastra/agents/example-pg-agent.ts"
import { Memory } from '@mastra/memory'
import { Agent } from '@mastra/core/agent'
import { PostgresStore } from '@mastra/pg'

export const pgAgent = new Agent({
  id: 'pg-agent',
  name: 'PG Agent',
  instructions:
    'You are an AI agent with the ability to automatically recall memories from previous interactions.',
  model: '__GATEWAY_OPENAI_MODEL__',
  memory: new Memory({
    storage: new PostgresStore({
      id: 'pg-agent-storage',
      connectionString: process.env.DATABASE_URL!,
    }),
    options: {
      generateTitle: true, // Explicitly enable automatic title generation
    },
  }),
})
```

### 使用 Agent {/* #using-the-agent */}

使用 `memoryOptions` 限定這次請求的記憶檢索範圍。設定 `lastMessages: 5`，讓依時間先後檢索的訊息最多包含五則；使用 `semanticRecall` 取得最相關的 `topK: 3` 則訊息，並透過 `messageRange: 2` 納入每筆符合結果相鄰的訊息作為脈絡。

```typescript title="src/test-pg-agent.ts"
import 'dotenv/config'

import { mastra } from './mastra'

const threadId = '123'
const resourceId = 'user-456'

const agent = mastra.getAgent('pg-agent')

const message = await agent.stream('My name is Mastra', {
  memory: {
    thread: threadId,
    resource: resourceId,
  },
})

await message.textStream.pipeTo(new WritableStream())

const stream = await agent.stream("What's my name?", {
  memory: {
    thread: threadId,
    resource: resourceId,
  },
  memoryOptions: {
    lastMessages: 5,
    semanticRecall: {
      topK: 3,
      messageRange: 2,
    },
  },
})

for await (const chunk of stream.textStream) {
  process.stdout.write(chunk)
}
```

## 索引管理 {/* #index-management */}

PostgreSQL 儲存提供索引管理來最佳化查詢效能。

### 預設索引 {/* #default-indexes */}

PostgreSQL 儲存在初始化期間為常見查詢模式建立複合索引：

* `mastra_threads_resourceid_createdat_idx`: (resourceId, createdAt DESC)
* `mastra_messages_thread_id_createdat_idx`: (thread_id, createdAt DESC)
* `mastra_ai_spans_traceid_startedat_idx`: (traceId, startedAt DESC)
* `mastra_ai_spans_parentspanid_startedat_idx`: (parentSpanId, startedAt DESC)
* `mastra_ai_spans_name_startedat_idx`: (name, startedAt DESC)
* `mastra_ai_spans_scope_startedat_idx`: (scope, startedAt DESC)
* `mastra_scores_trace_id_span_id_created_at_idx`: (traceId, spanId, createdAt DESC)
* `mastra_workflow_snapshot_name_createdat_idx`: (workflow_name, createdAt DESC)
* `mastra_workflow_snapshot_name_status_createdat_idx`: (workflow_name, snapshot->>'status', createdAt DESC)，僅在 `snapshot` 欄位為 `jsonb` 時建立

這些索引可提升需要排序的篩選查詢效能，包括訊息查詢中的 `dateRange` 篩選，以及 Studio 的 Workflow 執行清單。

### 配置索引 {/* #configuring-indexes */}

您可以透過建構函式選項控制索引建立：

```typescript
import { PostgresStore } from '@mastra/pg'

// Skip default indexes (manage indexes separately)
const store = new PostgresStore({
  id: 'pg-storage',
  connectionString: process.env.DATABASE_URL,
  skipDefaultIndexes: true,
})

// Add custom indexes during initialization
const storeWithCustomIndexes = new PostgresStore({
  id: 'pg-storage',
  connectionString: process.env.DATABASE_URL,
  indexes: [
    {
      name: 'idx_threads_metadata_type',
      table: 'mastra_threads',
      columns: ["metadata->>'type'"],
    },
    {
      name: 'idx_messages_status',
      table: 'mastra_messages',
      columns: ["metadata->>'status'"],
    },
  ],
})
```

對於進階索引類型，您可以指定其他選項：

* `unique: true`：建立唯一性限制
* `where: 'condition'`：建立部分索引
* `method: 'brin'`：用於時間序列資料
* `storage: { fillfactor: 90 }`：用於經常更新的資料表
* `concurrent: true`：以不阻塞寫入的方式建立索引（預設）

### 指定 schema 的索引 {/* #schema-specific-indexes */}

使用自訂 schema 時，索引名稱會以 schema 名稱為前綴：

```typescript
const storage = new PostgresStore({
  id: 'pg-storage',
  connectionString: process.env.DATABASE_URL,
  schemaName: 'custom_schema',
  indexes: [
    {
      name: 'idx_threads_status',
      table: 'mastra_threads',
      columns: ['status'],
    },
  ],
})

// Creates index as: custom_schema_idx_threads_status
```

### 透過 SQL 管理索引 {/* #managing-indexes-via-sql */}

如需列出、刪除或分析索引，可透過 `db` 存取器直接執行 SQL 查詢：

```typescript
// List indexes for a table
const indexes = await storage.db.any(`
  SELECT indexname, indexdef
  FROM pg_indexes
  WHERE tablename = 'mastra_messages'
`)

// Drop an index
await storage.db.none('DROP INDEX IF EXISTS idx_my_custom_index')

// Analyze index usage
const stats = await storage.db.one(`
  SELECT idx_scan, idx_tup_read
  FROM pg_stat_user_indexes
  WHERE indexrelname = 'mastra_messages_thread_id_createdat_idx'
`)
```

### 索引類型和用例 {/* #index-types-and-use-cases */}

PostgreSQL 提供多種索引類型，分別針對不同情境最佳化：

| 索引類型 | 適用情境 | 儲存空間 | 速度 |
| - | - | - | - |
| **btree**（預設） | 範圍查詢、排序、一般用途 | 中等 | 快 |
| **hash** | 僅用於相等比較 | 小 | `=` 比較非常快 |
| **gin** | JSONB、陣列、全文搜尋 | 大 | 包含關係查詢快 |
| **gist** | 幾何資料、全文搜尋 | 中等 | 最近鄰查詢快 |
| **spgist** | 非平衡資料、文字模式 | 小 | 特定模式查詢快 |
| **brin** | 具有自然排序的大型資料表 | 很小 | 範圍查詢快 |
