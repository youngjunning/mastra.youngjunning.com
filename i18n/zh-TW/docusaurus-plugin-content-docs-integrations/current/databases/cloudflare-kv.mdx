# Cloudflare

Mastra 提供兩種 Cloudflare 儲存實作：

* **Cloudflare KV**（`CloudflareKVStorage`）：全球分散式鍵值儲存，提供最終一致性
* **Cloudflare Durable Objects**（`CloudflareDOStorage`）：由 Durable Objects 提供的 SQLite 儲存空間，具備強一致性

:::warning[不支援可觀測性]

Cloudflare 儲存**不支援儲存可觀測性資料**。若只使用 Cloudflare 儲存，`MastraStorageExporter` 匯出的追蹤資料就無法持久保存，[Studio](/docs/studio/overview) 的可觀測性功能也無法運作。若要啟用可觀測性，請使用[複合儲存](/reference/storage/composite#specialized-storage-for-observability)，將可觀測性資料導向 ClickHouse 等支援這項功能的儲存服務。

:::

## 安裝 {/* #installation */}

```bash npm2yarn
npm install @mastra/cloudflare@latest
```

## Cloudflare KV 儲存 {/* #cloudflare-kv-storage */}

這項實作透過 Cloudflare Workers KV 提供全球分散式的無伺服器鍵值儲存。

### 用法 {/* #usage */}

```typescript
import { CloudflareKVStorage } from '@mastra/cloudflare/kv'

// --- Example 1: Using Workers Binding ---
const storageWorkers = new CloudflareKVStorage({
  id: 'cloudflare-workers-storage',
  bindings: {
    threads: THREADS_KV, // KVNamespace binding for threads table
    messages: MESSAGES_KV, // KVNamespace binding for messages table
    // Add other tables as needed
  },
  keyPrefix: 'dev_', // Optional: isolate keys per environment
})

// --- Example 2: Using REST API ---
const storageRest = new CloudflareKVStorage({
  id: 'cloudflare-rest-storage',
  accountId: process.env.CLOUDFLARE_ACCOUNT_ID!, // Cloudflare Account ID
  apiToken: process.env.CLOUDFLARE_API_TOKEN!, // Cloudflare API Token
  namespacePrefix: 'dev_', // Optional: isolate namespaces per environment
})
```

### 附加說明 {/* #additional-notes */}

### 結構描述管理 {/* #schema-management */}

這項儲存實作會自動建立及更新結構描述，並建立下列資料表：

* `threads`：儲存對話串
* `messages`：儲存個別訊息
* `metadata`：儲存對話串和訊息的額外中繼資料

### 一致性與資料傳播 {/* #consistency--propagation */}

Cloudflare KV 提供最終一致性。寫入資料後，部分區域可能無法立即讀取該筆資料。

:::warning[在不同 Worker 之間繼續執行]

寫入 KV 的資料可能要等約 60 秒才會傳到其他位置。如果某個 Worker 暫停一次 Workflow 或[持久化 Agent](/docs/harness/durable-agents) 的執行，而另一個 Worker 隨即接手，例如使用者很快核准了 Tool 呼叫，接手的 Worker 可能會讀到較早的快照。這時可能會因 `AGENT_RESUME_NO_SNAPSHOT_FOUND` 或 `WORKFLOW_RUN_NOT_SUSPENDED` 而無法繼續執行，也可能從較早的步驟繼續。

如果同一次執行可能由不同的 Worker 或處理程序負責暫停與繼續，請改用 [Cloudflare Durable Objects 儲存](#cloudflare-durable-objects-storage)。

:::

### 鍵的結構與命名空間 {/* #key-structure--namespacing */}

Cloudflare KV 的鍵由可設定的前置詞和各資料表專用的格式組成，例如 `threads:threadId`。
部署在 Workers 時，可用 `keyPrefix` 隔離同一個命名空間中的資料。透過 REST API 存取時，可用 `namespacePrefix` 讓不同環境或應用程式各自使用獨立的命名空間。

## Cloudflare Durable Objects 儲存 {/* #cloudflare-durable-objects-storage */}

這項實作透過 Cloudflare Durable Objects 提供具備強一致性的 SQLite 儲存空間，適合需要交易一致性及 SQL 查詢的應用程式。

### 用法 {/* #usage-1 */}

```typescript
import { DurableObject } from 'cloudflare:workers'
import { CloudflareDOStorage } from '@mastra/cloudflare/do'

class AgentDurableObject extends DurableObject<Env> {
  private storage: CloudflareDOStorage

  constructor(ctx: DurableObjectState, env: Env) {
    super(ctx, env)
    this.storage = new CloudflareDOStorage({
      sql: ctx.storage.sql,
      tablePrefix: 'mastra_', // Optional: prefix for table names
    })
  }

  async run() {
    const memory = await this.storage.getStore('memory')
    await memory?.saveThread({
      thread: { id: 'thread-1', resourceId: 'user-1', title: 'Chat', metadata: {} },
    })
  }
}
```

### 強一致性 {/* #strong-consistency */}

Durable Objects 保證強一致性。同一個 Durable Object 內的讀取和寫入作業都會依序執行，適合需要快速回應並長時間執行的 Agent。

### SQL 功能 {/* #sql-capabilities */}

Durable Objects 採用 SQLite，可有效率地進行查詢、篩選和分頁。鍵值儲存無法提供這些功能。

## 結構描述管理 {/* #schema-management-1 */}

兩種儲存實作都會自動建立及更新結構描述，並建立下列資料表：

* `threads`：儲存對話串
* `messages`：儲存個別訊息
* `workflow_snapshot`：儲存 Workflow 的執行狀態

## 已棄用的別名 {/* #deprecated-aliases */}

為維持向下相容性，仍可使用下列別名：

```typescript
// These are deprecated - use CloudflareKVStorage and CloudflareDOStorage instead
import { CloudflareStore } from '@mastra/cloudflare/kv' // alias for CloudflareKVStorage
import { DOStore } from '@mastra/cloudflare/do' // alias for CloudflareDOStorage
```
