# Convex

Mastra 透過 [Convex](https://convex.dev) 提供無伺服器儲存。Convex 是支援即時同步及自動快取的全端 TypeScript 開發平台。

:::warning[不支援可觀測性]

Convex 儲存**不支援可觀測性領域的資料**。`MastraStorageExporter` 的追蹤記錄無法持久儲存至 Convex。若只使用 Convex 作為儲存 Provider，[Studio](/docs/studio/overview) 的可觀測性功能便無法運作。若要啟用可觀測性，請透過[複合儲存](/reference/storage/composite#specialized-storage-for-observability)將相關資料導向支援此功能的 Provider，例如 ClickHouse。

:::

:::warning[記錄大小上限]
在 Convex 中，**每筆記錄上限為 1 MiB**。儲存含有 Base64 編碼附件（例如圖片）的訊息時，可能會超過此上限。請參閱[處理大型附件](/docs/memory/memory-processors#handling-large-attachments)取得替代做法，例如將附件上傳至 S3、Cloudflare R2 或 [Convex 檔案儲存空間](https://docs.convex.dev/file-storage)等外部儲存空間。
:::

## 安裝 {/* #installation */}

```bash npm2yarn
npm install @mastra/convex@latest
```

## 設定 Convex {/* #convex-setup */}

使用 `ConvexStore` 前，請先在 Convex 專案中定義資料庫結構，並建立儲存處理函式。
下方的結構範例包含 `ConvexStore` 和 `ConvexServerCache` 的完整設定。若只使用 `ConvexStore`，可略過 `mastraCacheTable` 和 `mastraCacheListItemsTable`；若要使用 `ConvexServerCache`，請加入這兩個資料表，並建立快取處理函式。

### 1. 定義 Convex 資料庫結構 {/* #1-set-up-convex-schema */}

在 `convex/schema.ts` 中加入以下程式碼：

```typescript
import { defineSchema } from 'convex/server'
import {
  mastraThreadsTable,
  mastraMessagesTable,
  mastraResourcesTable,
  mastraWorkflowSnapshotsTable,
  mastraScoresTable,
  mastraObservationalMemoryTable,
  mastraVectorIndexesTable,
  mastraVectorsTable,
  mastraCacheTable,
  mastraCacheListItemsTable,
  mastraDocumentsTable,
} from '@mastra/convex/schema'

export default defineSchema({
  mastra_threads: mastraThreadsTable,
  mastra_messages: mastraMessagesTable,
  mastra_resources: mastraResourcesTable,
  mastra_workflow_snapshots: mastraWorkflowSnapshotsTable,
  mastra_scorers: mastraScoresTable,
  mastra_observational_memory: mastraObservationalMemoryTable,
  mastra_vector_indexes: mastraVectorIndexesTable,
  mastra_vectors: mastraVectorsTable,
  mastra_cache: mastraCacheTable,
  mastra_cache_list_items: mastraCacheListItemsTable,
  mastra_documents: mastraDocumentsTable,
})
```

### 2. 建立儲存處理函式 {/* #2-create-the-storage-handler */}

在 `convex/mastra/storage.ts` 中加入以下程式碼：

```typescript
import { mastraStorage } from '@mastra/convex/server'

export const handle = mastraStorage
```

若有使用 `ConvexServerCache`，請建立 `convex/mastra/cache.ts` 並加入以下程式碼：

```typescript
import { mastraCache } from '@mastra/convex/server'

export const handle = mastraCache
```

### 3. 部署至 Convex {/* #3-deploy-to-convex */}

```bash
npx convex dev
# or for production
npx convex deploy
```

## 用法 {/* #usage */}

```typescript
import { ConvexServerCache, ConvexStore } from '@mastra/convex'

const storage = new ConvexStore({
  id: 'convex-storage',
  deploymentUrl: process.env.CONVEX_URL!,
  adminAuthToken: process.env.CONVEX_ADMIN_KEY!,
})

const cache = new ConvexServerCache({
  deploymentUrl: process.env.CONVEX_URL!,
  adminAuthToken: process.env.CONVEX_ADMIN_KEY!,
})
```

## 建構函式範例 {/* #constructor-examples */}

```ts
import { ConvexServerCache, ConvexStore } from '@mastra/convex'

// Basic configuration
const store = new ConvexStore({
  id: 'convex-storage',
  deploymentUrl: 'https://your-project.convex.cloud',
  adminAuthToken: 'your-admin-token',
})

// With custom storage function path
const storeCustom = new ConvexStore({
  id: 'convex-storage',
  deploymentUrl: 'https://your-project.convex.cloud',
  adminAuthToken: 'your-admin-token',
  storageFunction: 'custom/path:handler',
})

// Server cache for durable stream replay and response caching
const cache = new ConvexServerCache({
  deploymentUrl: 'https://your-project.convex.cloud',
  adminAuthToken: 'your-admin-token',
  cacheFunction: 'mastra/cache:handle',
})
```

## 伺服器快取 {/* #server-cache */}

`ConvexServerCache` 以 Convex 實作 Mastra 的伺服器快取介面約定。需要持久保存快取狀態時，可以用它支援持久化 Agent 的串流續傳、Workflow 串流重播，或快取回應。

`ConvexServerCache` 將每個清單項目分開儲存為一份 Convex 文件，避免串流重播清單在同一份文件中持續增長，有助於維持在 Convex 的記錄大小上限內。

每個純量快取值與每個清單項目都各自儲存為一筆 Convex 資料列，且不得超過單筆資料列的大小上限。清單非常大時，即使只重播指定範圍，仍受 Convex 的查詢限制。

快取清理和 `clear()` 都分批執行，每批都有處理上限。單次用戶端呼叫最多能反覆執行 1,000 次 Convex 寫入操作，每次最多處理 25 個清單項目。`clear()` 正在清理某個鍵時，讀取該鍵可能會傳回空結果，直到清理完成為止。

若快取命名空間非常大，請分次清除，或使用涵蓋範圍較小的前綴，以免清理作業執行太久。

批次清理期間，快取的中繼資料可能暫時處於內部 `deleted` 狀態。下一輪清理會移除這些資料列。在 `clear()` 執行完畢前，請避免寫入使用同一前綴的新值。

`clear()` 只會刪除已儲存的 `keyPrefix` 與設定的 `keyPrefix` 完全相同的資料列，不會以字串前綴比對的方式清除巢狀前綴下的資料。每次呼叫 `listPush()` 時，都會依快取設定的 `ttlMs` 更新清單的存留時間。

請將 `keyPrefix` 設為非空值，除非你確定要讓 `clear()` 移除部署中的所有快取鍵。讀取或寫入時，系統會逐步回收已到期的清單資料列。`clear()` 會移除該前綴對應的所有資料列。

`ConvexServerCache` 最適合持久保存頻率適中的事件，以供重播。若 token 串流的事件頻率很高，建議批次處理事件，或改用延遲較低的快取後端。

`ConvexServerCache` 無法取代分散式發布／訂閱傳輸機制。若應用程式需要在不同處理程序之間即時傳遞事件，請另外設定適用於正式環境的發布／訂閱後端。

## 附加說明 {/* #additional-notes */}

### 資料庫結構管理 {/* #schema-management */}

儲存實作會為各個 Mastra 領域使用有型別定義的 Convex 資料表：

| 領域 | Convex 資料表 | 用途 |
| - | - | - |
| 對話串 | `mastra_threads` | 對話串 |
| 訊息 | `mastra_messages` | 聊天訊息 |
| 資源 | `mastra_resources` | 使用者的工作記憶 |
| 觀察記憶 | `mastra_observational_memory` | 觀察記憶的生成結果 |
| Workflow | `mastra_workflow_snapshots` | Workflow 狀態 |
| 評分器 | `mastra_scorers` | 評估資料 |
| 快取 | `mastra_cache` | 快取值、計數器與清單中繼資料 |
| 快取項目 | `mastra_cache_list_items` | 快取清單的項目 |
| 備援儲存 | `mastra_documents` | 未知資料表的資料 |

### 觀察記憶 {/* #observational-memory */}

`ConvexStore` 支援[觀察記憶](/docs/memory/observational-memory)。若要啟用這項功能，請將 `mastraObservationalMemoryTable` 加入 Convex 資料庫結構，再執行 `npx convex deploy` 重新部署。若現有部署是在這個資料表加入前建立的，也須更新其資料庫結構。

### 架構 {/* #architecture */}

所有具型別定義的資料表都包含：

* `id` 欄位，用來儲存 Mastra 的記錄 ID（與 Convex 自動產生的 `_id` 不同）
* `by_record_id` 索引，可依 Mastra ID 快速查找記錄

這項設計符合 Mastra 的儲存約定，也能運用 Convex 的自動索引與即時功能。

### 環境變數 {/* #environment-variables */}

請為部署設定下列環境變數：

* `CONVEX_URL`：Convex 部署網址
* `CONVEX_ADMIN_KEY`：管理員驗證權杖（可從 Convex 控制台取得）
