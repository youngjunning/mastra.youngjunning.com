# DuckDB

[DuckDB](https://duckdb.org/) 是在應用程式程序內執行的嵌入式分析資料庫。`@mastra/duckdb` 套件為本機開發提供以 OLAP 為基礎的可觀測性儲存，可存放追蹤資料、日誌、指標、評分與回饋，不必執行外部服務。

如需向量搜尋，請參閱 [DuckDB 向量儲存參考文件](/integrations/vectors/duckdb)。這項功能使用同一個套件提供的獨立 API。

## 何時使用 DuckDB {/* #when-to-use-duckdb */}

DuckDB 適合在本機開發可觀測性功能。它採用嵌入式架構，將資料存放在檔案中，不必另行啟動資料庫伺服器即可使用。它支援與 ClickHouse 相同的可觀測性訊號，方便在部署至正式環境的後端前測試儀表板與探索追蹤資料。

DuckDB 目前僅實作 `observability` 儲存領域。設定[複合儲存](/reference/storage/composite)時，可搭配 [LibSQL](/integrations/databases/libsql) 等儲存配接器，提供 `memory` 與 `workflows` 所需的儲存功能。

:::warning
DuckDB 適用於開發環境，不建議用於正式環境。它在應用程式程序內執行，將資料持久儲存於單一本機檔案，無法在採用暫時性檔案系統的平台上運作，例如 Railway、Fly.io、Render、Heroku 或無伺服器容器。正式環境的可觀測性儲存請使用 [ClickHouse](/integrations/databases/clickhouse)。
:::

## 安裝 {/* #installation */}

```bash npm2yarn
npm install @mastra/duckdb@latest
```

## 使用方式 {/* #usage */}

### 在複合儲存中提供可觀測性儲存 {/* #as-the-observability-domain-in-a-composite-store */}

這是本機開發的標準設定。DuckDB 負責可觀測性儲存，LibSQL 負責其他儲存領域。

```typescript title="src/mastra/index.ts"
import { Mastra } from '@mastra/core'
import { MastraCompositeStore } from '@mastra/core/storage'
import { LibSQLStore } from '@mastra/libsql'
import { DuckDBStore } from '@mastra/duckdb'
import { Observability, MastraStorageExporter } from '@mastra/observability'

export const mastra = new Mastra({
  storage: new MastraCompositeStore({
    id: 'composite-storage',
    default: new LibSQLStore({
      id: 'mastra-storage',
      url: 'file:./mastra.db',
    }),
    domains: {
      observability: new DuckDBStore().observability,
    },
  }),
  observability: new Observability({
    configs: {
      default: {
        serviceName: 'mastra',
        exporters: [new MastraStorageExporter()],
      },
    },
  }),
})
```

透過 `.observability` 存取屬性即可直接取得可觀測性儲存。也可呼叫 `getStore()` 取得相同的儲存實例。這個通用方法適用於任何支援複合儲存的配接器：

```typescript
const observability = await new DuckDBStore().getStore('observability')
```

### 獨立使用 {/* #standalone */}

如果只需要在 `Mastra` 的複合儲存之外使用可觀測性儲存，可直接建立 `DuckDBStore` 實例並存取其可觀測性儲存領域：

```typescript
import { DuckDBStore } from '@mastra/duckdb'

const duckdb = new DuckDBStore({ path: './traces.duckdb' })
const observability = duckdb.observability

await observability.init()
```

### 記憶體資料庫 {/* #in-memory-database */}

將路徑設為 `:memory:` 可使用暫時性的 DuckDB 記憶體實例。程序結束時，資料會消失，適合用於單元測試與短時間執行的指令碼。

```typescript
const duckdb = new DuckDBStore({ path: ':memory:' })
```

### 底層型別 {/* #lower-level-types */}

`@mastra/duckdb` 也匯出 `DuckDBConnection` 及對應的 `DuckDBStorageConfig` 型別，讓多個 Mastra 儲存實例可透過 `DuckDBConnection` 共用同一個底層資料庫。大多數應用程式不必直接使用這兩者。

## 支援的儲存領域 {/* #supported-domains */}

DuckDB 目前僅實作一個儲存領域：

| 儲存領域 | 是否支援 |
| - | - |
| `observability` | 是 |
| `memory` | 否 |
| `workflows` | 否 |
| `scores` | 否 |
| `agents` | 否 |

若要支援所有儲存領域，請將 `DuckDBStore` 與支援其餘領域的配接器搭配使用。本機開發最常搭配 [LibSQL](/integrations/databases/libsql)。

## 初始化 {/* #initialization */}

透過 `MastraCompositeStore` 將可觀測性儲存傳入 `Mastra` 後，該儲存領域會在首次使用時自動初始化。若要在 `Mastra` 之外明確執行初始化，請呼叫可觀測性儲存的 `init()` 方法：

```typescript
import { DuckDBStore } from '@mastra/duckdb'

const duckdb = new DuckDBStore({ path: './traces.duckdb' })
await duckdb.observability.init()
```

## 可觀測性策略 {/* #observability-strategy */}

DuckDB 支援 `MastraStorageExporter` 採用的 `event-sourced` 策略。這項策略會先將 span 暫存在記憶體中，再批次寫入已完成的事件，適合開發環境的流量。若正式環境的流量較大，請參閱 [`MastraStorageExporter` 支援的儲存供應商](/docs/observability/integrations/exporters/mastra-storage#storage-provider-support)。
