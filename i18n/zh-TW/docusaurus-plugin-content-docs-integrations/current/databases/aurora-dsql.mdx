# Aurora DSQL

Aurora DSQL 儲存實作透過 Amazon Aurora DSQL 提供儲存功能，並使用 IAM 進行身分驗證。

Aurora DSQL 不支援 PostgreSQL 擴充功能（`CREATE EXTENSION`），包括 `pgvector`。若要儲存向量，請使用獨立的向量儲存服務，例如 `@mastra/s3vectors`。

## 安裝 {/* #installation */}

```bash copy
npm install @mastra/dsql@beta
```

## 先決條件 {/* #prerequisites */}

- Amazon Aurora DSQL 叢集
- 可透過 IAM 身分驗證存取該 DSQL 叢集的 AWS 憑證

## 用法 {/* #usage */}

```typescript copy showLineNumbers
import { DSQLStore } from '@mastra/dsql'

const storage = new DSQLStore({
  id: 'my-dsql-store',
  host: 'abc123.dsql.us-east-1.on.aws',
  // region is auto-detected from host, or specify explicitly:
  // region: 'us-east-1',
  // user: 'admin', // default
  // database: 'postgres', // default
})

// Initialize the store (creates tables if needed)
await storage.init()
```

## 建構函式範例 {/* #constructor-examples */}

你可以透過以下方式建立 DSQLStore 執行個體：

```typescript copy showLineNumbers
import { DSQLStore } from '@mastra/dsql'

// Basic configuration (region auto-detected from host)
const store1 = new DSQLStore({
  id: 'my-dsql-store',
  host: 'abc123.dsql.us-east-1.on.aws',
})

// With explicit region and schema
const store2 = new DSQLStore({
  id: 'my-dsql-store',
  host: 'abc123.dsql.us-east-1.on.aws',
  region: 'us-east-1',
  schemaName: 'my_app',
})

// With custom credentials provider
import { fromNodeProviderChain } from '@aws-sdk/credential-providers'

const store3 = new DSQLStore({
  id: 'my-dsql-store',
  host: 'abc123.dsql.us-east-1.on.aws',
  customCredentialsProvider: fromNodeProviderChain(),
})

// With connection pool settings
const store4 = new DSQLStore({
  id: 'my-dsql-store',
  host: 'abc123.dsql.us-east-1.on.aws',
  max: 20,
  min: 2,
  idleTimeoutMillis: 300000,
  maxLifetimeSeconds: 3000,
  connectionTimeoutMillis: 10000,
})

// Using a pre-configured pg.Pool
import { Pool } from 'pg'
import { AuroraDSQLClient } from '@aws/aurora-dsql-node-postgres-connector'

const pool = new Pool({
  host: 'abc123.dsql.us-east-1.on.aws',
  Client: AuroraDSQLClient,
  region: 'us-east-1',
})

const store5 = new DSQLStore({
  id: 'my-dsql-store',
  pool,
})
```

## 補充說明 {/* #additional-notes */}

### 結構描述管理 {/* #schema-management */}

此儲存實作會自動建立及更新結構描述，並建立以下資料表：

- `mastra_workflow_snapshot`：儲存 Workflow 狀態與執行資料
- `mastra_threads`：儲存對話執行緒
- `mastra_messages`：儲存個別訊息
- `mastra_ai_spans`：儲存用於可觀測性的 span 資料
- `mastra_scorers`：儲存評分與評估資料
- `mastra_resources`：儲存資源的工作記憶資料
- `mastra_agents`：儲存 Agent 資料

### 初始化 {/* #initialization */}

將儲存執行個體傳入 Mastra 類別時，系統會在任何儲存操作之前自動呼叫 `init()`：

```typescript copy showLineNumbers
import { Mastra } from '@mastra/core'
import { DSQLStore } from '@mastra/dsql'

const storage = new DSQLStore({
  id: 'my-dsql-store',
  host: 'abc123.dsql.us-east-1.on.aws',
})

const mastra = new Mastra({
  storage, // init() is called automatically
})
```

若不透過 Mastra，而是直接使用儲存執行個體，就必須明確呼叫 `init()` 來建立資料表：

```typescript copy showLineNumbers
import { DSQLStore } from '@mastra/dsql'

const storage = new DSQLStore({
  id: 'my-dsql-store',
  host: 'abc123.dsql.us-east-1.on.aws',
})

// Required when using storage directly
await storage.init()

// Access domain-specific stores via getStore()
const memoryStore = await storage.getStore('memory')
const thread = await memoryStore?.getThreadById({ threadId: '...' })
```

:::warning
若未呼叫 `init()`，資料表便不會建立，儲存操作可能無聲失敗或擲出錯誤。
:::

### 直接存取資料庫與連線池 {/* #direct-database-and-pool-access */}

`DSQLStore` 將底層資料庫用戶端與 pg.Pool 執行個體公開為公用欄位：

```typescript copy showLineNumbers
storage.db // Database client for executing queries
storage.pool // Underlying pg.Pool instance
```

這些欄位可用於直接查詢及自訂交易管理。使用時請注意：

- 你需要自行妥善處理連線與交易。
- 如果連線池是由儲存執行個體建立，關閉該執行個體（`storage.close()`）時會銷毀連線池。
- 直接存取會略過 `DSQLStore` 方法提供的其他邏輯或驗證。

這種方式適用於需要底層存取能力的進階情境。

### Aurora DSQL 的特性 {/* #aurora-dsql-specifics */}

#### 僅支援 IAM 身分驗證 {/* #iam-only-authentication */}

連線透過 IAM 進行身分驗證，不需要資料庫密碼。`@mastra/dsql` 使用 `@aws/aurora-dsql-node-postgres-connector` 產生短效驗證權杖。你可以透過 `customCredentialsProvider` 提供自訂憑證提供者。

#### 單一資料庫與結構描述隔離 {/* #single-database-schema-based-isolation */}

每個叢集只提供一個名為 `postgres` 的資料庫。邏輯隔離透過結構描述實現；`schemaName` 選項決定 Mastra 資料表建立在哪個結構描述中。

#### 不支援 PostgreSQL 擴充功能 {/* #no-postgresql-extensions */}

Aurora DSQL 不支援 `CREATE EXTENSION`，因此也不支援 `pgvector`、`PostGIS` 等擴充功能。若要儲存向量，可搭配 `DSQLStore` 使用 `@mastra/s3vectors` 等獨立儲存服務。

#### 以文字儲存 JSON {/* #json-stored-as-text */}

JSON/JSONB 可作為查詢型別，但不能作為欄位型別。`@mastra/dsql` 將中繼資料、內容等結構化欄位存入 `TEXT` 欄位，並在查詢時轉型為 JSON。

#### 結構描述與 DDL 限制 {/* #schema-and-ddl-constraints */}

以下 PostgreSQL 功能無法使用：

- 外鍵約束
- `TRUNCATE`
- 同步執行的 `CREATE INDEX`

索引透過 `CREATE INDEX ASYNC` 非同步建立。儲存執行個體的 `init()` 與索引輔助 API 均遵守這些限制。

#### 交易與樂觀並行控制 {/* #transactions-and-optimistic-concurrency */}

Aurora DSQL 使用樂觀並行控制（OCC）；發生資源競爭時，可能傳回可重試的 OCC 錯誤。交易的時間與大小都有限制。大量批次操作應在應用程式層拆分為較小批次。

#### 連線存續時間 {/* #connection-lifetime */}

單一連線的存續時間限制約為 60 分鐘。預設的 `maxLifetimeSeconds: 3300` 可確保連線在達到此限制前重新建立。

## 使用範例 {/* #usage-example */}

### 為 Agent 加入記憶 {/* #adding-memory-to-an-agent */}

若要讓 Agent 使用 Aurora DSQL 儲存記憶，請使用 `Memory` 類別，並透過 `DSQLStore` 設定新的 `storage` 屬性。`host` 應指向你的 Aurora DSQL 叢集端點。

```typescript title="src/mastra/agents/example-dsql-agent.ts" copy showLineNumbers
import { Memory } from '@mastra/memory'
import { Agent } from '@mastra/core/agent'
import { DSQLStore } from '@mastra/dsql'

export const dsqlAgent = new Agent({
  id: 'dsql-agent',
  name: 'DSQL Agent',
  instructions:
    'You are an AI agent with the ability to automatically recall memories from previous interactions.',
  model: '__GATEWAY_OPENAI_MODEL__',
  memory: new Memory({
    storage: new DSQLStore({
      id: 'dsql-agent-storage',
      host: process.env.DSQL_HOST!,
    }),
    options: {
      generateTitle: true, // Explicitly enable automatic title generation
    },
  }),
})
```

### 使用 Agent {/* #using-the-agent */}

使用 `memoryOptions` 限定此次請求的記憶回想範圍。設定 `lastMessages: 5`，限制依時間先後回想的近期訊息數量；使用 `semanticRecall` 擷取最相關的 `topK: 3` 則訊息，並透過 `messageRange: 2` 納入每則符合條件訊息的相鄰訊息作為上下文。

```typescript title="src/test-dsql-agent.ts" copy showLineNumbers
import 'dotenv/config'

import { mastra } from './mastra'

const threadId = '123'
const resourceId = 'user-456'

const agent = mastra.getAgent('dsql-agent')

const message = await agent.stream('My name is Mastra', {
  memory: {
    thread: threadId,
    resource: resourceId,
  },
})

await message.textStream.pipeTo(new WritableStream())

const stream = await agent.stream("What's my name?", {
  memory: {
    thread: threadId,
    resource: resourceId,
  },
  memoryOptions: {
    lastMessages: 5,
    semanticRecall: {
      topK: 3,
      messageRange: 2,
    },
  },
})

for await (const chunk of stream.textStream) {
  process.stdout.write(chunk)
}
```

## 索引管理 {/* #index-management */}

Aurora DSQL 儲存提供索引管理功能，以改善查詢效能。

### 自動建立的效能索引 {/* #automatic-performance-indexes */}

Aurora DSQL 儲存會在初始化時，針對常見查詢模式自動建立以下複合索引：

- `mastra_threads_resourceid_createdat_idx`：（resourceId、createdAt）
- `mastra_messages_thread_id_createdat_idx`：（thread_id、createdAt）
- `mastra_ai_spans_traceid_startedat_idx`：（traceId、startedAt）
- `mastra_ai_spans_parentspanid_startedat_idx`：（parentSpanId、startedAt）
- `mastra_ai_spans_name_idx`：（name）
- `mastra_ai_spans_spantype_startedat_idx`：（spanType、startedAt）
- `mastra_scores_trace_id_span_id_created_at_idx`：（traceId、spanId、createdAt）

Aurora DSQL 使用 `CREATE INDEX ASYNC` 非同步建立這些索引。因此，呼叫 `init()` 後，新索引可能不會立即可用。即使索引尚未建立完成，儲存執行個體仍可運作，但查詢速度可能較慢。

### 建立自訂索引 {/* #creating-custom-indexes */}

你可以建立其他索引，最佳化特定的查詢模式：

```typescript copy showLineNumbers
await storage.createIndex({
  name: 'idx_threads_resource',
  table: 'mastra_threads',
  columns: ['resourceId'],
})

await storage.createIndex({
  name: 'idx_messages_composite',
  table: 'mastra_messages',
  columns: ['thread_id', 'createdAt'],
})
```

Aurora DSQL 不允許在 `CREATE INDEX ASYNC` 中使用 `ASC`/`DESC`。若指定這些修飾詞，系統會自動移除。

### 管理索引 {/* #managing-indexes */}

列出並監控現有索引：

```typescript copy showLineNumbers

const allIndexes = await storage.listIndexes()
console.log(allIndexes)
// [
//   {
//     name: 'mastra_threads_pkey',
//     table: 'mastra_threads',
//     columns: ['id'],
//     unique: true,
//     size: '16 KB',
//     definition: 'CREATE UNIQUE INDEX...'
//   },
//   ...
// ]

// List indexes for a specific table
const threadIndexes = await storage.listIndexes('mastra_threads')

// Get detailed statistics for an index
const stats = await storage.describeIndex('idx_threads_resource')
console.log(stats)
// {
//   name: 'idx_threads_resource',
//   table: 'mastra_threads',
//   columns: ['resourceId'],
//   unique: false,
//   size: '128 KB',
//   definition: 'CREATE INDEX idx_threads_resource...',
//   method: 'btree',
//   scans: 1542,
//   tuples_read: 45230,
//   tuples_fetched: 12050
// }

// Drop an index
await storage.dropIndex('idx_threads_status')
```

### 特定結構描述中的索引 {/* #schema-specific-indexes */}

使用自訂結構描述時，建立的索引名稱會加上結構描述前綴：

```typescript copy showLineNumbers
const storage = new DSQLStore({
  id: 'my-dsql-store',
  host: 'abc123.dsql.us-east-1.on.aws',
  schemaName: 'custom_schema',
})

// Creates index as: custom_schema_idx_threads_status
await storage.createIndex({
  name: 'idx_threads_status',
  table: 'mastra_threads',
  columns: ['status'],
})
```
