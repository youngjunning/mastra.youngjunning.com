# Cloudflare D1

Mastra 的 Cloudflare D1 儲存實作以 D1 作為無伺服器 SQL 資料庫，支援關聯式資料操作和交易一致性。

:::warning[不支援可觀測性]

Cloudflare D1 儲存**不支援可觀測性領域**。`MastraStorageExporter` 匯出的追蹤資料無法儲存至 D1。若 D1 是唯一的儲存 Provider，就無法使用 [Studio](/docs/studio/overview) 的可觀測性功能。若要啟用可觀測性，請使用[複合儲存](/reference/storage/composite#specialized-storage-for-observability)，將可觀測性資料送往支援這項功能的 Provider，例如 ClickHouse。

:::

:::warning[單筆資料大小限制]
Cloudflare D1 規定**每筆資料列最多為 1 MiB**。儲存含有 Base64 編碼附件（如圖片）的訊息時，可能會超過這項限制。請參閱[處理大型附件](/docs/memory/memory-processors#handling-large-attachments)，了解將附件上傳至外部儲存空間等替代做法。
:::

## 安裝 {/* #installation */}

```bash npm2yarn
npm install @mastra/cloudflare-d1@latest
```

## 使用方式 {/* #usage */}

### 搭配 Mastra 的 CloudflareDeployer 使用 {/* #using-with-mastra-cloudflaredeployer */}

在 Cloudflare 上為 Mastra 設定 D1Store 時，標準做法是使用 `CloudflareDeployer`。從 `cloudflare:workers` 匯入 `env`，並在 `new Mastra({...})` 內直接初始化 `D1Store`。

```typescript title="src/mastra/index.ts"
import { env } from 'cloudflare:workers'
import { D1Store } from '@mastra/cloudflare-d1'
import { Mastra } from '@mastra/core'
import { CloudflareDeployer } from '@mastra/deployer-cloudflare'

export const mastra = new Mastra({
  storage: new D1Store({ binding: env.DB }),
  deployer: new CloudflareDeployer({
    name: 'my-worker',
    d1_databases: [
      {
        binding: 'DB',
        database_name: 'your-database-name',
        database_id: 'your-database-id',
      },
    ],
  }),
})
```

:::note
使用 `import { env } from 'cloudflare:workers'` 時，必須在 `new Mastra({...})` 內直接初始化 `D1Store`，不能把它抽成模組層級變數。也可以等到 `env` 可用後，再於 `fetch` 處理函式內初始化 `D1Store`。詳情請參閱 [CloudflareDeployer 參考文件](/reference/deployer/cloudflare#cloudflare-bindings)。
:::

### 在未提供 HTTP 路由的 Cloudflare Worker 中使用 {/* #using-in-a-cloudflare-worker-without-http-routes */}

若只想在 Worker 中直接呼叫 Mastra，例如執行 Agent 或觸發 Workflow，而不提供 HTTP 路由，就不需要 `CloudflareDeployer`。從 Worker 的 `env` 參數取得 D1 繫結，再透過程式碼呼叫 Mastra。

```typescript
import { D1Store } from '@mastra/cloudflare-d1'
import { Mastra } from '@mastra/core'

type Env = {
  DB: D1Database
}

export default {
  async fetch(request: Request, env: Env, ctx: ExecutionContext) {
    const mastra = new Mastra({
      storage: new D1Store({ binding: env.DB }),
    })

    const agent = mastra.getAgent('my-agent')
    const result = await agent.generate('Hello')

    return Response.json({ text: result.text })
  },
}
```

### 透過 REST API 存取 {/* #using-with-rest-api */}

若在 Workers 以外的環境執行，例如 Node.js 或無伺服器函式，請透過 REST API 存取 D1：

```typescript
import { D1Store } from '@mastra/cloudflare-d1'

const storage = new D1Store({
  accountId: process.env.CLOUDFLARE_ACCOUNT_ID!, // Cloudflare Account ID
  databaseId: process.env.CLOUDFLARE_D1_DATABASE_ID!, // D1 Database ID
  apiToken: process.env.CLOUDFLARE_API_TOKEN!, // Cloudflare API Token
  tablePrefix: 'dev_', // Optional: isolate tables per environment
})
```

### Wrangler 設定 {/* #wrangler-configuration */}

將 D1 資料庫繫結加入 `wrangler.toml`：

```toml
[[d1_databases]]
binding = "DB"
database_name = "your-database-name"
database_id = "your-database-id"
```

也可以加到 `wrangler.jsonc`：

```jsonc
{
  "d1_databases": [
    {
      "binding": "DB",
      "database_name": "your-database-name",
      "database_id": "your-database-id",
    },
  ],
}
```

## 補充說明 {/* #additional-notes */}

### 資料庫綱要管理 {/* #schema-management */}

儲存實作會自動建立及更新資料庫綱要，並建立以下資料表：

* `threads`：儲存對話串
* `messages`：儲存個別訊息
* `metadata`：儲存對話串與訊息的額外中繼資料

### 初始化 {/* #initialization */}

將儲存執行個體傳給 Mastra 類別後，Mastra 會在執行任何儲存操作之前自動呼叫 `init()`：

```typescript
import { Mastra } from '@mastra/core'
import { D1Store } from '@mastra/cloudflare-d1'

type Env = {
  DB: D1Database
}

// In a Cloudflare Worker
export default {
  async fetch(request: Request, env: Env, ctx: ExecutionContext) {
    const storage = new D1Store({
      binding: env.DB,
    })

    const mastra = new Mastra({
      storage, // init() is called automatically
    })

    // Your handler logic here
    return new Response('Success')
  },
}
```

若未透過 Mastra，而是直接使用儲存執行個體，就必須明確呼叫 `init()` 來建立資料表：

```typescript
import { D1Store } from '@mastra/cloudflare-d1'

type Env = {
  DB: D1Database
}

// In a Cloudflare Worker
export default {
  async fetch(request: Request, env: Env, ctx: ExecutionContext) {
    const storage = new D1Store({
      id: 'd1-storage',
      binding: env.DB,
    })

    // Required when using storage directly
    await storage.init()

    // Access domain-specific stores via getStore()
    const memoryStore = await storage.getStore('memory')
    const thread = await memoryStore?.getThreadById({ threadId: '...' })

    return new Response('Success')
  },
}
```

:::warning
若未呼叫 `init()`，就不會建立資料表，儲存操作會無聲失敗或拋出錯誤。
:::

### 交易與一致性 {/* #transactions--consistency */}

Cloudflare D1 為單一資料列的操作提供交易保證。多項操作也可以合併成一個不可分割的工作單元：要麼全部成功，要麼全部不生效。

### 建立和遷移資料表 {/* #table-creation--migrations */}

儲存初始化時會自動建立資料表，也可使用 `tablePrefix` 選項隔離不同環境的資料表。新增資料行、變更資料型別或調整索引等較複雜的綱要變更，必須手動遷移並事先仔細規劃，以免遺失資料。
