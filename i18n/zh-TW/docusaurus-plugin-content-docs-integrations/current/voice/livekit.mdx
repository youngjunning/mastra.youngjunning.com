# LiveKit

## 快速入門 {/* #quickstart */}

即時語音讓使用者能透過瀏覽器或電話，與 Mastra Agent 即時對話。Mastra 使用開放原始碼的 WebRTC 平台 [LiveKit](https://livekit.io) 處理即時音訊和視訊。

[`@mastra/livekit`](#api-reference) 套件將 Mastra Agent 連接至 [LiveKit Agents 框架](https://docs.livekit.io/agents/)：LiveKit 負責音訊處理流程，包括語音活動偵測、串流語音轉文字、語意回合偵測、使用者打斷 Agent，以及文字轉語音。Mastra Agent 則使用自己的模型、Tool 和記憶功能產生每次回應。

需要低延遲、可隨時打斷的語音對話時，請使用即時語音。如需不依賴 LiveKit、由 Provider 提供的語音對語音功能，請參閱[語音對語音](/reference/voice/speech-to-speech)。

以下步驟會從空白專案開始，建立可對話的語音 Agent。語音工作階段需要設定兩個部分：Mastra 伺服器上的 API 路由，用來核發存取權杖；以及獨立的 worker 程序，用來執行音訊處理流程，並在每個回合呼叫 Agent。

<Steps>
  <StepItem>
    安裝整合套件，以及用於語音活動偵測和回合偵測的 LiveKit 外掛程式：

    ```bash npm2yarn
    npm install @mastra/livekit @livekit/agents @livekit/agents-plugin-silero @livekit/agents-plugin-livekit
    ```
  </StepItem>

  <StepItem>
    在 `.env` 檔案中設定 LiveKit 憑證。您可以在 [LiveKit Cloud](https://cloud.livekit.io) 建立免費專案，或使用 [`livekit-server --dev`](https://docs.livekit.io/home/self-hosting/local/) 執行本機伺服器：

    ```bash title=".env"
    LIVEKIT_URL=wss://your-project.livekit.cloud
    LIVEKIT_API_KEY=your-api-key
    LIVEKIT_API_SECRET=your-api-secret
    ```
  </StepItem>

  <StepItem>
    將語音 Agent 加入 Mastra 執行個體，並提供連線路由。`liveKitConnectionRoute()` 輔助函式會新增 `POST /voice/livekit/connection-details` 端點，核發 LiveKit 權杖並將 Agent 派送至房間：

    ```typescript title="src/mastra/index.ts"
    import { Mastra } from '@mastra/core/mastra'
    import { Agent } from '@mastra/core/agent'
    import { liveKitConnectionRoute } from '@mastra/livekit'

    const supportAgent = new Agent({
      id: 'support',
      name: 'Support',
      instructions: 'You are a friendly phone support agent. Keep replies short and conversational.',
      model: '__GATEWAY_OPENAI_MODEL_LUNA__',
    })

    export const mastra = new Mastra({
      agents: { support: supportAgent },
      server: {
        apiRoutes: [liveKitConnectionRoute({ agentName: 'mastra-voice' })],
      },
    })
    ```
  </StepItem>

  <StepItem>
    建立 worker。它會以獨立程序執行、接聽 LiveKit 工作階段，並在每個回合呼叫 Agent。Worker API 位於 `@mastra/livekit/worker` 進入點，因此 Mastra 伺服器不會載入 LiveKit Agents 執行環境。此範例以 LiveKit Inference 模型字串指定語音轉文字和文字轉語音功能，不需要額外安裝 Provider 外掛程式：

    ```typescript title="src/mastra/voice-worker.ts"
    import { fileURLToPath } from 'node:url'
    import { createLiveKitWorker, runLiveKitWorker } from '@mastra/livekit/worker'
    import { mastra } from './index'

    export default createLiveKitWorker({
      mastra,
      agent: 'support',
      stt: 'deepgram/nova-3',
      tts: 'cartesia/sonic-3',
      turnDetection: 'multilingual',
      greeting: 'Hi! How can I help you today?',
    })

    if (process.argv[1] === fileURLToPath(import.meta.url)) {
      runLiveKitWorker({ entry: import.meta.url, agentName: 'mastra-voice' })
    }
    ```

    `agent` 選項指定由哪個 Mastra Agent 回應工作階段。您可以如範例所示傳入固定的鍵值；也可以省略此選項，改用派送中繼資料中的 `agentId`，讓同一個 worker 服務 Mastra 執行個體中的所有 Agent。
  </StepItem>

  <StepItem>
    下載回合偵測和語音活動偵測模型；只需下載一次。接著在一個終端機執行 worker，並在另一個終端機執行 Mastra 伺服器：

    ```bash
    npx livekit-agents download-files
    npx tsx src/mastra/voice-worker.ts dev
    ```

    ```bash npm2yarn
    npm run dev
    ```

    Worker 會向 LiveKit 伺服器註冊並等待工作階段；`mastra dev` 則提供連線路由。
  </StepItem>

  <StepItem>
    與 Agent 對話。開啟託管版的 [LiveKit Agents Playground](https://agents-playground.livekit.io) 並連接您的專案，即可開始通話，無須自行建立前端。

    若要連接自己的應用程式，請呼叫連線路由取得權杖。`POST /voice/livekit/connection-details` 的請求主體可選擇性包含 `agentId`、`threadId` 和 `resourceId` 欄位，回應如下：

    ```json
    {
      "serverUrl": "wss://your-project.livekit.cloud",
      "roomName": "mastra-voice-a1b2c3d4",
      "participantName": "user-1",
      "participantToken": "eyJhbGci..."
    }
    ```

    此回應符合 LiveKit 前端起始專案使用的資料格式，因此以 [agent-starter-react](https://github.com/livekit-examples/agent-starter-react) 或 [LiveKit React 元件](https://docs.livekit.io/reference/components/react/) 建立的應用程式無須修改即可使用。
  </StepItem>
</Steps>

### 回合偵測與打斷 {/* #turn-detection-and-interruptions */}

LiveKit 會判斷使用者何時說完，以及 Agent 何時遭到打斷。預設設定通常已足夠；您可以透過 `turnHandling` 調整：

```typescript title="src/mastra/voice-worker.ts"
export default createLiveKitWorker({
  mastra,
  agent: 'support',
  stt: 'deepgram/nova-3',
  tts: 'cartesia/sonic-3',
  turnDetection: 'multilingual',
  turnHandling: {
    endpointing: { mode: 'dynamic', minDelay: 300, maxDelay: 3000 },
    interruption: { minDuration: 500, resumeFalseInterruption: true },
  },
})
```

* `turnDetection: 'multilingual'`：在本機 CPU 上執行 LiveKit 的語意回合結束模型。模型會讀取即時逐字稿，避免在使用者話還沒說完時打斷對方。若要依靜音時間判定回合結束，請改用 `'vad'` 或 `'stt'`。
* `endpointing`：限定使用者停止說話後，Agent 最多等待多久。
* `interruption`：控制使用者打斷 Agent 時的處理方式。當使用者在 Agent 說話時插話，LiveKit 會停止播放並取消進行中的 Mastra 串流，因此也會停止產生權杖。
* `preemptiveGeneration`：在使用者即將說完時，就開始產生 Mastra Agent 的回應，以縮短等待第一個權杖的時間。Worker 預設停用此功能：每次預先產生回應時，都會根據暫時的逐字稿執行 Mastra Agent；即使 LiveKit 稍後捨棄該次執行，部分使用者訊息和未曾說出的部分回應也已寫入對話執行緒。如果延遲比對話執行緒的準確歷史紀錄更重要，可透過 `preemptiveGeneration: { enabled: true }` 重新啟用；若要兼顧兩者，則以唯讀模式執行回合。詳見[預先產生回應與記憶功能](#preemptive-generation-with-memory)。

所有選項請參閱 [LiveKit 回合偵測文件](https://docs.livekit.io/agents/logic/turns/)。

若要停用語音活動偵測，請在 `createLiveKitWorker()` 中設定 `vad: false`。Worker 會將 `null` 傳給 LiveKit；若省略 `vad`，LiveKit 則會啟用內建的偵測器。停用時，請選擇不依賴 VAD 的回合偵測模式，例如 `'manual'`。`sessionOptions` 中的值會覆寫 worker 產生的選項，包括 `vad`。

### 依通話設定語音和轉錄 {/* #per-call-voices-and-transcription */}

頂層的 `stt` 和 `tts` 選項適用於所有通話。若要依通話選擇設定，例如讓每個租戶使用不同的聲音或語言，請改用 `configuration.stt` 和 `configuration.tts` 解析函式。每個解析函式會在每通電話中執行一次，接收派送中繼資料、請求內容、房間名稱和工作內容，並回傳對應頂層選項可接受的值：外掛程式執行個體或推論模型字串。回傳 `undefined` 則會沿用頂層選項。

以下範例根據派送中繼資料中的 `tenant` 欄位，為每個租戶選擇專屬的文字轉語音聲音：

```typescript title="src/mastra/voice-worker.ts"
import * as cartesia from '@livekit/agents-plugin-cartesia'

// One voice id per tenant, resolved from the dispatch metadata on each call.
const tenantVoices: Record<string, string> = {
  meridian: 'your-cartesia-voice-id-1',
  coastal: 'your-cartesia-voice-id-2',
}
// The resolver runs during call setup, so cache plugin instances across calls.
const ttsByVoice = new Map<string, cartesia.TTS>()

export default createLiveKitWorker({
  mastra,
  agent: 'support',
  stt: 'deepgram/nova-3',
  tts: 'cartesia/sonic-3',
  configuration: {
    tts: ({ requestContext }) => {
      const voice = tenantVoices[requestContext?.tenant as string]
      if (!voice) return undefined // fall back to the top-level `tts`
      let tts = ttsByVoice.get(voice)
      if (!tts) {
        tts = new cartesia.TTS({ voice })
        ttsByVoice.set(voice, tts)
      }
      return tts
    },
  },
})
```

`configuration.stt` 也能以相同方式依通話設定轉錄，例如為不同租戶選擇不同的轉錄模型或語言。開場問候語同樣可依通話設定：`configuration.greeting.text` 接受使用相同通話內容的解析函式，讓同一個 worker 以各租戶專屬的措辭開場。

### 依通話設定回合偵測 {/* #per-call-turn-detection */}

LiveKit 的 `TurnDetector` 類別在建立時會讀取工作的推論執行器，因此只能在 LiveKit 工作內建立，不能在定義 worker 選項的模組層級建立。若要使用這類偵測器，請設定 `configuration.turnDetection` 解析函式。它會在每通電話中執行一次，接收與 `configuration.stt` 相同的通話內容，並回傳頂層 `turnDetection` 選項可接受的值。回傳 `undefined` 則會沿用頂層選項。

```typescript title="src/mastra/voice-worker.ts"
import { turnDetector } from '@livekit/agents-plugin-livekit'

export default createLiveKitWorker({
  mastra,
  agent: 'support',
  stt: 'deepgram/nova-3',
  tts: 'cartesia/sonic-3',
  turnDetection: 'multilingual',
  configuration: {
    // Constructed inside the job, where the inference executor is available.
    turnDetection: () => new turnDetector.MultilingualModel(0.2),
  },
})
```

語意模型的推論執行器必須在 Agent 伺服器啟動前註冊，因此設定此解析函式後，worker 會預先匯入 `@livekit/agents-plugin-livekit`。將頂層 `turnDetection` 設為 `'multilingual'` 或 `'english'`，即可只預先註冊該模型；否則兩種模型都會保持可用。

### 記憶功能與對話執行緒 {/* #memory-and-threads */}

若選定的 Mastra Agent 已設定記憶功能，每通電話都會對應一個記憶功能的對話執行緒：

* `thread` 預設使用派送中繼資料中的 `threadId`；若未提供，則使用房間名稱。
* `resource` 預設使用派送中繼資料中的 `resourceId`；若未提供，則使用對話執行緒。請在此傳入終端使用者的 ID，讓通話歸屬於正確的使用者。Mastra Studio 會傳入 Agent ID，與側邊欄列出對話執行緒的方式一致。
* 若對話執行緒尚不存在，worker 會建立標題為「語音通話」、中繼資料為 `{ source: 'livekit' }` 的執行緒，並將說出的開場問候語儲存為第一則助理訊息，讓執行緒保留完整通話逐字稿。可設定 `persistGreeting: false` 停用此行為。

每個回合只會傳送新的使用者輸入；對話歷史、語意回憶和工作記憶由 Mastra Memory 提供。若要透過語音接續既有的文字對話，請在連線請求主體中傳入 `threadId`，將工作階段綁定至該對話執行緒。在 Studio 中，從已開啟的聊天開始通話，也會綁定至該執行緒；每次對話後，逐字稿都會加入聊天內容。

當使用者打斷 Agent 時，進行中的內容產生作業會中止，該回合此時不會儲存任何內容。LiveKit 會在逐字稿中保留使用者實際聽到的部分；下一個回合，worker 會重新傳送這段已播放的內容，將它補入對話執行緒，使執行緒與通話內容一致。如果使用者打斷後立刻掛斷，最後這段內容就不會被記錄。詳情及補齊紀錄的方法，請參閱[遭打斷的回合](#interrupted-turns)。

#### 預先產生回應與記憶功能 {/* #preemptive-generation-with-memory */}

LiveKit 預先產生回應時，會根據暫時的逐字稿呼叫 Mastra Agent；若逐字稿後來改變，便捨棄該次執行。外掛程式無法區分預測性的執行與正式回合，因此設定 `memory` 後，每次執行都會寫入記憶功能，包括遭捨棄的執行。若要啟用預先產生回應，同時維持對話執行緒的正確性，請在記憶功能對應設定中傳入 `options: { readOnly: true }`。Agent 仍可讀取執行緒中的歷史紀錄、語意回憶和工作記憶，但不會寫入，因此預測性的執行不會留下紀錄。此時您需要自行儲存已確認的回合：監聽 LiveKit 的 `ConversationItemAdded` 事件，該事件只會對工作階段已確認的項目觸發。訊息保留 LiveKit 的 ID，因此重試儲存也不會產生重複紀錄。

```typescript title="src/mastra/voice-worker.ts"
import { voice } from '@livekit/agents'
import { createLiveKitWorker } from '@mastra/livekit/worker'
import { mastra } from './index'

export default createLiveKitWorker({
  mastra,
  agent: 'support',
  memory: ({ metadata, roomName }) => ({
    thread: metadata.threadId ?? roomName,
    resource: metadata.resourceId ?? roomName,
    options: { readOnly: true },
  }),
  turnHandling: { preemptiveGeneration: { enabled: true } },
  onSessionStart: async ({ session, ctx, agent }) => {
    const mapping = agent.memory
    const memory = await mastra.getAgent('support').getMemory()
    if (!mapping || !memory) return

    let shuttingDown = false
    const maxRetries = 5
    const retryTimers = new Set<ReturnType<typeof setTimeout>>()
    ctx.addShutdownCallback(async () => {
      shuttingDown = true
      for (const timer of retryTimers) clearTimeout(timer)
      retryTimers.clear()
    })

    session.on(voice.AgentSessionEventTypes.ConversationItemAdded, ({ item }) => {
      if (item.type !== 'message' || (item.role !== 'user' && item.role !== 'assistant')) return

      const persist = async (attempt = 0): Promise<void> => {
        try {
          await memory.saveMessages({
            messages: [
              {
                id: item.id,
                threadId: mapping.thread,
                resourceId: mapping.resource ?? mapping.thread,
                role: item.role,
                content: {
                  format: 2,
                  parts: [{ type: 'text', text: item.textContent ?? '' }],
                },
                type: 'text',
                createdAt: new Date(),
              },
            ],
          })
        } catch (error) {
          if (shuttingDown) return
          if (attempt >= maxRetries) {
            console.error(`Failed to persist committed voice item ${item.id}; giving up`, error)
            return
          }
          console.error(`Failed to persist committed voice item ${item.id}; retrying`, error)
          const delay = Math.min(1_000 * 2 ** attempt, 30_000)
          const timer = setTimeout(() => {
            retryTimers.delete(timer)
            void persist(attempt + 1)
          }, delay)
          retryTimers.add(timer)
        }
      }

      void persist()
    })
  },
})
```

相同的 `options` 欄位也適用於 `MastraVoiceAgent` 和 `MastraLLM`；使用遠端傳輸時，此欄位會以請求主體中的 `memory.options` 轉送。

### Tool 執行期間播放語音 {/* #speak-while-tools-run */}

執行耗時的 Tool 時，語音對話不宜長時間沒有聲音。使用 `toolFeedback`，即可在 Mastra Agent 開始呼叫 Tool 時先說一段簡短的話：

```typescript title="src/mastra/voice-worker.ts"
export default createLiveKitWorker({
  mastra,
  agent: 'support',
  stt: 'deepgram/nova-3',
  tts: 'cartesia/sonic-3',
  toolFeedback: ({ toolName }) =>
    toolName === 'searchOrders' ? 'Let me look that up.' : undefined,
})
```

這段話會作為回應的一部分播放，並記錄在逐字稿中。

### 使用 Workflow 產生回應 {/* #generate-replies-with-a-workflow */}

Worker 預設使用 Mastra Agent 產生每次回應。若每個回合都需要執行多步驟邏輯，例如分類意圖、選擇處理路徑、依序呼叫 Tool，再組成回應，請改用 Mastra [Workflow](/docs/workflows/overview) 產生回應，並以 `workflow` 取代 `agent`。

LiveKit 仍負責音訊處理流程，並在每個回合呼叫 Mastra 一次，因此 Workflow 每個回合都會執行至結束。Workflow 無法暫停或恢復，對話狀態也不會在回合之間保留。請透過 `workflowInput` 傳入逐字稿，讓 Workflow 不需自行保存狀態：

```typescript title="src/mastra/voice-worker.ts"
import { createLiveKitWorker, chatContextToMessages } from '@mastra/livekit/worker'
import { mastra } from './index'

export default createLiveKitWorker({
  mastra,
  workflow: 'phoneConversation',
  workflowInput: ({ chatCtx }) => ({ history: chatContextToMessages(chatCtx) }),
  replyStep: 'generateResponse',
  stt: 'deepgram/nova-3',
  tts: 'cartesia/sonic-3',
  turnDetection: 'multilingual',
})
```

Workflow 串流輸出的是結構化的步驟事件，而非文字。若要一邊產生文字、一邊播放語音，請在產生回應的步驟中，將 Agent 的文字串流傳送至該步驟的 `writer`：

```typescript title="src/mastra/workflows/phone-conversation.ts"
import { createStep } from '@mastra/core/workflows'

const generateResponse = createStep({
  id: 'generateResponse',
  // input and output schemas omitted
  execute: async ({ inputData, mastra, writer, abortSignal }) => {
    const stream = await mastra.getAgent('voice').stream(inputData.history, { abortSignal })
    await stream.textStream.pipeTo(writer)
    return { assistantMessage: await stream.text }
  },
})
```

* `replyStep`：只播放指定步驟的輸出。若省略此選項，所有寫入各自 `writer` 的步驟都會被播放。
* `resultText`：當沒有步驟串流輸出文字時，從最終執行結果取得回應的備援方式。透過 `writer` 串流輸出可縮短等待第一個權杖的時間，因此建議優先使用。
* `abortSignal`：將步驟的 `abortSignal` 傳入 `agent.stream()`，讓使用者插話時能迅速停止內容產生。使用者打斷時，worker 會取消該次執行。
* `generate`：若需要完全控制回應的產生方式，請改為傳入 `generate` 函式。它可以是任何將單一回合轉為文字串流的回應產生器。

使用 Workflow 時，worker 不會像 Agent 的 `stream()` 那樣自動儲存回合。請在 Workflow 中儲存對話歷史，或以 LiveKit 逐字稿作為準確紀錄，並在每個回合傳入。

### 使用 Mastra 作為 LLM 元件 {/* #use-mastra-as-the-llm-component */}

`createLiveKitWorker()` 會替您管理 LiveKit 工作階段。若要自行管理工作階段，請改用 [`MastraLLM`](#mastrallm)：這是標準的 LiveKit LLM 外掛程式，可將 Mastra Agent 放入您自行建立的 `voice.AgentSession` 的 `llm` 欄位。Mastra 應用程式、Agent 執行流程、Tool、記憶功能和可觀測性功能都在 Mastra 伺服器上執行，worker 則透過 HTTP 存取。Worker 程序不需要載入 Mastra 應用程式、資料庫或模型 Provider 的金鑰。

```typescript title="src/mastra/voice-worker-plugin.ts"
import { fileURLToPath } from 'node:url'
import { defineAgent, voice } from '@livekit/agents'
import * as silero from '@livekit/agents-plugin-silero'
import { MastraLLM } from '@mastra/livekit/plugin'
import { runLiveKitWorker } from '@mastra/livekit/worker'

export default defineAgent({
  entry: async ctx => {
    await ctx.connect()

    const session = new voice.AgentSession({
      llm: new MastraLLM({
        remote: { baseUrl: process.env.MASTRA_URL!, agentId: 'support' },
        memory: { thread: ctx.room.name!, resource: 'user-7' },
      }),
      stt: 'deepgram/nova-3',
      tts: 'cartesia/sonic-3',
      vad: await silero.VAD.load(),
      // Required with `memory` unless memory.options.readOnly is set: LiveKit enables
      // preemptive generation by default.
      turnHandling: { preemptiveGeneration: { enabled: false } },
    })

    await session.start({
      // These instructions never reach the Mastra agent; its own instructions apply.
      agent: new voice.Agent({ instructions: 'Replies come from the Mastra agent.' }),
      room: ctx.room,
    })

    session.say('Hi! How can I help you today?')
  },
})

if (process.argv[1] === fileURLToPath(import.meta.url)) {
  runLiveKitWorker({ entry: import.meta.url, agentName: 'mastra-voice' })
}
```

兩種方式共用相同的回覆處理流程；請依照由誰管理工作階段來選擇：

| | `createLiveKitWorker()` | `MastraLLM` |
| - | - | - |
| 工作階段由誰管理 | Worker 輔助函式建立並管理 `AgentSession` | 由你的程式碼建立工作階段，可自行設定所有 LiveKit 選項與 hook |
| Mastra 應用程式執行位置 | Worker 行程中 | Mastra 伺服器上，透過 HTTP 存取（或透過 `agent` 在同一行程中執行） |
| Worker 行程需要的資源 | Mastra 應用程式、儲存系統，以及模型 Provider 金鑰 | LiveKit SDK，以及連線至伺服器的網路存取權 |
| 內建便利功能 | 開場問候、同意機制、Agent 主動掛斷、對話執行緒初始化、可觀測性彙整 | 使用[工作階段輔助函式](#runendcall)自行實作所需功能 |
| 適用情境 | 快速建立可運作的語音 Agent；Studio 語音模式 | 既有 LiveKit 應用程式，或需要完整控制工作階段 |

Tool 保留在 Mastra Agent 上，並於伺服器執行。傳給工作階段的 LiveKit 端 Tool 會被忽略。Worker 可透過 `toolFeedback`（語音過場訊息）、`onToolCall`（每次 Tool 呼叫開始時觸發）和 `onTurnComplete`（每次回覆後觸發，提供文字、Tool 呼叫及 token 用量）取得 Tool 活動資訊。若要讓 Agent 主動掛斷，將 `onToolCall` 與 [`runEndCall()`](#runendcall) 搭配使用即可。

:::warning
請勿將 `memory` 選項與 LiveKit 的 `preemptiveGeneration` 一起使用；自行建立工作階段時，LiveKit 預設會啟用預先生成。LiveKit 捨棄推測性的回合之前，部分使用者訊息與尚未唸出的部分回覆就可能已寫入對話執行緒。請設定 `turnHandling: { preemptiveGeneration: { enabled: false } }`；或不使用 `memory`，改為每回合傳入完整逐字稿；或設定 `memory.options.readOnly`，自行儲存已確認的回合。詳見[記憶體與預先生成](#preemptive-generation-with-memory)。
:::

`MastraLLM` 也接受同一行程中的 Mastra `agent` 實例，讓你自行管理工作階段而無須另外部署；也可傳入自訂的 `generate` 函式。遠端傳輸功能可獨立透過 [`createRemoteAgentReplyGenerator()`](#createremoteagentreplygenerator) 使用，也能接入 `createLiveKitWorker` 的 `generate` 選項，讓內建完整功能的 Worker 連線至遠端伺服器。

在自己的程式碼中使用 `dispatchVoiceSession()`，將語音 Agent 加入房間，例如加入既有房間，或進行撥出的 [SIP 通話](https://docs.livekit.io/sip/)：

```typescript
import { dispatchVoiceSession } from '@mastra/livekit'

await dispatchVoiceSession({
  roomName: 'support-call-42',
  agentName: 'mastra-voice',
  metadata: { agentId: 'support', threadId: 'thread-42', resourceId: 'user-7' },

```

### 通話錄音 {/* #record-calls */}

將 `recording` 傳給 `dispatchVoiceSession()` 或 `liveKitConnectionRoute()`，即可建立啟用 [LiveKit 自動 egress](https://docs.livekit.io/transport/media/ingress-egress/egress/autoegress/) 的房間。Mastra 會先建立已設定錄音的房間，再派遣語音 Agent。省略 `recording` 時，既有行為與回傳值不變。

錄音需要 LiveKit Cloud 或自行架設的 [egress 服務](https://docs.livekit.io/transport/self-hosting/egress/)，以及輸出目的地。以下範例將來電者與 Agent 的音訊混合錄製為單一 OGG 檔案，存入 S3 儲存貯體。請在伺服器上設定 `RECORDINGS_S3_BUCKET`、`RECORDINGS_S3_REGION`、`RECORDINGS_S3_ACCESS_KEY` 和 `RECORDINGS_S3_SECRET`，以及 LiveKit 憑證。

安裝伺服器 SDK，以使用其中的輸出格式列舉：

```bash npm2yarn
npm install livekit-server-sdk
```

在僅供伺服器使用的模組中定義錄音設定：

```typescript title="src/mastra/recording.ts"
import type { LiveKitRecordingOptions } from '@mastra/livekit'
import { EncodedFileType } from 'livekit-server-sdk'

export const recording: LiveKitRecordingOptions = {
  room: {
    audioOnly: true,
    fileOutputs: [
      {
        fileType: EncodedFileType.OGG,
        filepath: 'calls/{room_name}.ogg',
        output: {
          case: 's3',
          value: {
            bucket: process.env.RECORDINGS_S3_BUCKET!,
            region: process.env.RECORDINGS_S3_REGION!,
            accessKey: process.env.RECORDINGS_S3_ACCESS_KEY!,
            secret: process.env.RECORDINGS_S3_SECRET!,
          },
        },
      },
    ],
  },
}
```

`LiveKitRecordingOptions` 接受用來建立 LiveKit `RoomEgress` 的設定，可傳入一般物件或 SDK 實例。設定 `room.audioOnly: true` 可錄製混合音訊；若要分開錄製，則使用 `tracks` 或 `participant`。Mastra 會將這些設定傳給 LiveKit，不會替你選擇格式或儲存服務。其他輸出目的地請參閱 [LiveKit 輸出選項](https://docs.livekit.io/transport/media/ingress-egress/egress/outputs/)。

撥出電話時，請在加入電話參與者前設定錄音：

```typescript title="src/start-call.ts"
import { randomUUID } from 'node:crypto'
import { dispatchVoiceSession } from '@mastra/livekit'
import { recording } from './mastra/recording'

const roomName = `support-call-${randomUUID()}`

await dispatchVoiceSession({
  roomName,
  metadata: { agentId: 'support', resourceId: 'caller-7' },
  recording,
})

// Add the phone participant to roomName through your existing LiveKit SIP code.
```

每個要錄音的工作階段都應使用新的房間名稱，並在撥號前等待派遣完成。若房間已存在，`dispatchVoiceSession()` 會擲出 `LiveKitRecordingRoomConflictError`；可從 `@mastra/livekit` 匯入此錯誤來處理衝突。檢查房間是否存在與建立房間是兩個獨立請求，因此應用程式必須防止其他行程同時建立同名房間。此選項不會在既有房間開始錄音，也不會補錄先前的音訊。

瀏覽器工作階段則將相同設定傳給連線路由：

```typescript title="src/mastra/index.ts"
import { Mastra } from '@mastra/core/mastra'
import { liveKitConnectionRoute } from '@mastra/livekit'
import { recording } from './recording'

export const mastra = new Mastra({
  server: {
    apiRoutes: [liveKitConnectionRoute({ recording })],
  },
})
```

啟用錄音後，連線路由會在收到連線資訊請求時建立房間並派遣 Agent，此時瀏覽器尚未加入。回應仍為 `{ serverUrl, roomName, participantName, participantToken }`。錄音設定與儲存憑證只留在伺服器，不會放入加入房間的 token 或 Agent 中繼資料。

路由也接受同步或非同步的 `recording` 回呼。回呼會收到 `{ body, context, roomName }`，其中包含已確定的房間名稱，讓伺服器能依工作階段選擇設定。傳回 `undefined` 即可略過該次請求的錄音。路由不會直接從請求本文讀取錄音設定。

若錄音房間已存在，路由會在派遣 Agent 或核發 token 前回傳 HTTP 409。其他建立房間或派遣錯誤也會使操作失敗；路由不會在失敗時核發 token。若房間建立後派遣失敗，房間仍會留在 LiveKit。設定成功不代表錄音一定能完成或上傳成功。向使用者提供錄音前，請透過 LiveKit 的 [egress 事件](https://docs.livekit.io/intro/basics/rooms-participants-tracks/webhooks-events/#webhook-events)確認完成狀態並取得檔案資訊。若要驗證設定，請撥打一通測試電話、結束房間，再播放儲存貯體 `calls/` 下完成的檔案，確認雙方音訊都已錄入。

#### 錄音生命週期與同意機制 {/* #recording-lifecycle-and-consent */}

啟用 `recording` 後，錄音會在建立房間時開始，早於瀏覽器連線或電話參與者加入。即使連線請求最後未完成，Agent 仍可能啟動並耗用錄音與儲存資源。對使用者開放連線路由前，請先設定身分驗證與應用程式層級的限制。

`createConsentTool()` 和 `configuration.consentPolicy` 無法控制 LiveKit egress，也不會延後、暫停或停止自動錄音。若應用程式必須在通話中取得同意後才能錄音，請先取得同意，再使用 LiveKit 的明確 egress API，在既有房間中開始錄音。單靠語音問候無法阻止此功能啟動。

錄音遵循 LiveKit 房間的生命週期。僅讓 Agent 中斷連線，不一定會結束房間或完成檔案。將錄音標記為可用之前，請等待 egress 成功完成並取得檔案結果。設定失敗與無人使用的房間，都需要由應用程式負責清理。

音訊檔案存放在設定的輸出儲存空間，與 Mastra 記憶體、逐字稿及追蹤資料分開。刪除 Mastra 對話執行緒不會刪除錄音。應用程式須管理終端使用者的儲存存取權、保留期限及下載連結。即使依工作階段選擇錄音設定，儲存憑證也應保留在伺服器設定中。

### 在 Studio 中檢視錄音 {/* #review-recordings-in-studio */}

註冊 `liveKitRecordingRoute()`，即可在 Studio 的語音通話追蹤面板中加入 **Review Audio** 按鈕。按下後會開啟該通話的音訊播放器。錄音與追蹤資料的儲存設定都必須完成：路由會讀取已儲存的 `voice call` span，並將其中的 `roomName` 傳給伺服器端的解析函式。瀏覽器只會提供追蹤 ID。

解析函式應傳回 `{ url, expiresAt? }`；若檔案尚不可用，則傳回 `undefined`。存取私人儲存空間時，請使用短效簽章 URL。路由不會將播放 URL 存入追蹤資料，Studio 每次開啟檢視時都會要求新的 URL。若檔案不存在或播放失敗，可按 **Refresh recording**，在上傳完成或連結過期後重試。

若使用上述 S3 設定，錄音與播放都應使用相同的 `calls/{room_name}.ogg` 物件鍵值。即使房間已結束，不同通話的房間名稱仍須保持唯一。請在應用程式中安裝 AWS SDK：

```bash npm2yarn
npm install @aws-sdk/client-s3 @aws-sdk/s3-request-presigner
```

```typescript title="src/mastra/recording-playback.ts"
import {
  GetObjectCommand,
  HeadObjectCommand,
  S3Client,
  S3ServiceException,
} from '@aws-sdk/client-s3'
import { getSignedUrl } from '@aws-sdk/s3-request-presigner'
import { liveKitRecordingRoute } from '@mastra/livekit'
import { authorizeRecording } from './recording-access'

const s3 = new S3Client({
  region: process.env.RECORDINGS_S3_REGION!,
  credentials: {
    accessKeyId: process.env.RECORDINGS_S3_ACCESS_KEY!,
    secretAccessKey: process.env.RECORDINGS_S3_SECRET!,
  },
})

export const recordingReviewRoute = liveKitRecordingRoute({
  authorize: authorizeRecording,
  resolveRecording: async ({ roomName }) => {
    const object = {
      Bucket: process.env.RECORDINGS_S3_BUCKET!,
      Key: `calls/${roomName}.ogg`,
    }
    try {
      await s3.send(new HeadObjectCommand(object))
    } catch (error) {
      if (error instanceof S3ServiceException && error.$metadata.httpStatusCode === 404)
        return undefined
      throw error
    }
    const expiresIn = 15 * 60
    return {
      url: await getSignedUrl(
        s3,
        new GetObjectCommand({ ...object, ResponseContentType: 'audio/ogg' }),
        { expiresIn },
      ),
      expiresAt: new Date(Date.now() + expiresIn * 1000).toISOString(),
    }
  },
})
```

將 `recordingReviewRoute` 與 `liveKitConnectionRoute({ recording })` 一起加入 `server.apiRoutes`。保留預設路徑 `GET /voice/livekit/recordings/:traceId`，以供 Studio 探索。只要 Worker 已儲存通話追蹤資料，且解析函式找得到檔案，透過連線路由或伺服器主動派遣建立的錄音都能檢視。

檢視路由預設要求身分驗證，也必須明確提供 `authorize({ traceId, context })` 回呼。請在應用程式中實作 `authorizeRecording` 輔助函式，根據可信的擁有權或租戶紀錄，檢查已驗證使用者是否有權存取指定追蹤資料。只有允許存取時才傳回 `true`。通過身分驗證本身不代表擁有該錄音。

若未提供授權回呼，路由會拒絕註冊；即使 `requiresAuth` 為 `false` 也一樣。遭拒的請求會在讀取追蹤資料或產生播放 URL 前回傳 `403`。授權政策發生錯誤時，也會停止解析。只有授權成功後，解析函式才會收到已儲存的 `span` 與請求的 `context`。

:::warning

僅在本機示範時使用 `requiresAuth: false`。此設定不會略過必要的錄音授權回呼。若示範用的授權政策允許存取所有錄音，請明確將其限制在本機開發環境，並在部署前更換。

:::

只有錄音上傳權限，並不代表能播放錄音。簽發 URL 所用的憑證需要對錄音物件具備 `s3:GetObject` 權限，包括執行 `HEAD` 檢查。若要讓不存在的物件回傳 `404` 而非 `403`，S3 還需要 `s3:ListBucket` 權限。應用程式可以使用獨立的讀取憑證來播放錄音。瀏覽器會收到可授權存取該檔案的暫時 URL，請將其視為敏感資訊。詳見 [S3 物件權限](https://docs.aws.amazon.com/AmazonS3/latest/API/API_HeadObject.html)與[預先簽署的 URL](https://docs.aws.amazon.com/AmazonS3/latest/userguide/using-presigned-url.html)。

`liveKitRecordingRoute()` 不依賴特定儲存服務。你可以從其他 Provider，或由 LiveKit 完成事件更新的錄音索引，解析播放 URL。此路由不要求 LiveKit 保留歷史 egress 作業。若檔名包含時間戳記或儲存貯體可能變更，請在應用程式中保存房間與物件的對應關係，並查詢該關係，而非自行組合物件鍵值。

### 可觀察性 {/* #observability */}

若 Mastra 實例已設定[可觀測性](/docs/observability/overview)，Worker 會追蹤每通電話。每個工作階段會建立一個 `voice call` span，並將下列資料納入其中：

* 每回合的 Mastra Agent 執行紀錄，包括模型生成、Tool 呼叫及記憶體操作，與文字聊天的記錄方式相同。
* 各項 LiveKit 處理流程指標的子 span：語音轉文字、文字轉語音、話語結束（回合偵測）、語音活動偵測，以及模型產生第一個 token 的時間。這些 span 包含文字追蹤資料無法呈現的延遲與音訊測量值。
* 工作階段結束時寫入 span 的各模型用量彙總，包含整通電話的 token、字元及音訊總量。

Worker 是獨立行程，因此儲存後端必須能同時接受伺服器與 Worker 的寫入。以 SQLite 為基礎的 [LibSQL](/integrations/databases/libsql) 可以使用，僅支援單一寫入者的儲存系統則不行。追蹤資料、記憶體與對話執行緒可以共用同一個儲存系統：

```typescript title="src/mastra/index.ts"
import { Mastra } from '@mastra/core/mastra'
import { LibSQLStore } from '@mastra/libsql'
import { Observability, MastraStorageExporter } from '@mastra/observability'

export const mastra = new Mastra({
  storage: new LibSQLStore({ id: 'voice-agent-storage', url: 'file:./voice-agent.db' }),
  observability: new Observability({
    configs: {
      default: {
        serviceName: 'voice-agent',
        exporters: [new MastraStorageExporter()],
      },
    },
  }),
})
```

追蹤預設啟用。若要關閉，請將 `observability: false` 傳給 `createLiveKitWorker`。

### 從應用程式請求播放錄音 {/* #request-recording-playback-from-your-application */}

從 `@mastra/livekit/client` 匯入瀏覽器用戶端輔助函式。若要使用此入口，請安裝 1.x 系列中 1.51.2 版或更新的 `@mastra/client-js`：

```bash npm2yarn
npm install @mastra/livekit @mastra/client-js
```

```typescript
import { MastraClient } from '@mastra/client-js'
import { getLiveKitRecording } from '@mastra/livekit/client'
import type { LiveKitRecordingResponse } from '@mastra/livekit/client'

const client = new MastraClient({
  baseUrl: 'https://mastra.example.com',
  credentials: 'include',
})

const recording: LiveKitRecordingResponse = await getLiveKitRecording(client, traceId)
if (recording.status === 'ready') {
  audioElement.src = recording.url
}
```

請先在伺服器註冊 [`liveKitRecordingRoute()`](#review-recordings-in-studio)。輔助函式會請求其預設路徑 `/voice/livekit/recordings/:traceId`，不受用戶端 API 前綴影響。它會沿用用戶端的驗證標頭、Cookie、自訂 fetch 函式及中止訊號。若要取消單次請求，可將 `{ signal }` 作為第三個引數傳入。失敗的請求會使用 `MastraClientError`，且不會自動重試。

`@mastra/client-js@1.51.2` 宣告支援 Zod 3 與 4，但其相依套件 `@ai-sdk/ui-utils@1.2.11` 將 Zod 3 宣告為 peer dependency。版本範圍不一致，可能導致使用 Zod 4 時，嚴格檢查相依套件的 npm 安裝失敗。搭配此 SDK 使用 Zod `^3.25.76`，即可同時符合兩者的 peer dependency 範圍。未安裝選用用戶端 SDK 的伺服器與 Worker 端也支援 Zod 4。

`/client` 入口不會匯入 LiveKit 伺服器與 Worker 端程式碼。此整合套件的其他入口不需要 `@mastra/client-js`。安裝 `@mastra/livekit` 時仍會安裝套件層級的相依套件；瀏覽器入口只控制哪些程式碼進入瀏覽器 bundle。儲存憑證與錄音授權仍留在伺服器。

### 回合指標與播放完成狀態 {/* #turn-metrics-and-playback-completion */}

`createLiveKitWorker()` 接受兩個觀察回呼，用於評估語音通話：

```typescript title="src/mastra/voice-worker.ts"
import { createLiveKitWorker } from '@mastra/livekit/worker'

export default createLiveKitWorker({
  mastra,
  agent: 'support',
  onTurnMetrics: metrics => {
    console.info('voice metric', metrics)
  },
  onSpeechComplete: speech => {
    console.info('speech outcome', speech.speechId, speech.outcome)
  },
})
```

觀察回呼會非同步執行，音訊處理流程不會等待它們。錯誤會記錄至日誌。請讓回呼執行的工作保持精簡。兩者都不會寫入或調整記憶體資料。

`onTurnMetrics` 會收到帶有版本資訊的紀錄，其 phase 為 `phase: 'generation'` 或 `phase: 'speech'`。生成階段的紀錄包含 `turnId`、唯一的 `attemptId`、最終 `outcome`、`durationMs`、選用的 `firstTextMs`，以及 Tool 執行時間。同一則使用者訊息的多次嘗試共用相同回合 ID。Tool 執行時間從橋接層收到 Tool 呼叫起算，到收到結果為止；遠端執行時間包含傳輸耗時，並非純粹的伺服器執行時間。若 Tool 未傳回結果，就沒有執行時間。

語音紀錄還包含 LiveKit 的 `speechId`。橋接層會將回合與嘗試 ID 放在助理訊息的中繼資料中，以便播放後關聯紀錄。若語音沒有對應的助理訊息，例如取消後未產生輸出的語音，就會以語音 ID 作為回合 ID，且不包含嘗試 ID。請勿依事件抵達順序推測關聯。

| 測量值 | 意義 |
| - | - |
| 生成階段的 `firstTextMs` | 從開始生成到第一段文字送往語音合成的時間，可能包含過場訊息。 |
| 語音階段的 `firstAudioMs` | LiveKit 回報從來電者說話結束到第一段輸出音訊的時間，可能包含過場訊息。 |
| 語音階段的 `completionMs` | 從來電者說話結束到輸出音訊播放完畢的時間。語音若遭中斷、取消或失敗，則不提供此值。 |
| `speechStartedAt` / `speechEndedAt` | 若可取得，則為播放開始與結束的 Unix 紀元時間戳記，單位為毫秒。 |

缺少的測量值為 `undefined`，而不是零。本機生成時間使用單調時鐘計算。LiveKit 的語音時間值會轉換為毫秒。設定可觀測性後，這些紀錄會以事件形式出現在既有的 `voice call` 追蹤資料中。若 LiveKit 提供語音 ID，處理流程的指標事件會保留該 ID。

`onSpeechComplete` 會在語音 handle 完成時執行一次；若工作階段關閉時該語音仍在處理中，也會執行一次。它提供語音指標，以及選用的 `playedText` 和 `transcriptSource`。結果可能是 `completed`、`interrupted`、`cancelled` 或 `failed`。語音生命週期顯示完成，不代表一定產生了音訊；請檢查是否有相關音訊測量值。

測量來源是 `server-playout`。依輸出端的同步支援程度，LiveKit 已確認的逐字稿可能只有部分內容，或只是估算結果。這無法證明遠端瀏覽器或電話聽眾聽見了每個字。`transcriptSource: 'unavailable'` 表示沒有可用的已確認助理逐字稿。

生成階段仍應使用 `onTurnComplete` 的既有契約。它可能在語音播放結束前觸發，並回報 `interrupted: false`，即使來電者稍後中斷音訊也一樣。播放結果請使用 `onSpeechComplete`。既有的 Agent 記憶體可能已儲存生成的文字；新增此 hook 不會改變該儲存行為。

若工作階段由你自行管理，請在 `session.start()` 之前，從 `@mastra/livekit/worker` 或 `@mastra/livekit/plugin` 呼叫 `observeVoiceSession(session, { onTurnMetrics, onSpeechComplete })`。其回傳值可用來解除觀察，並將仍在處理的語音結束為已取消。Worker 會自動附加觀察回呼。

### 語音片段邊界 {/* #speech-segment-boundaries */}

內建 Agent、遠端與 Workflow 回覆產生器會保留文字片段及 Tool 步驟的邊界。Tool 回饋文字進入佇列後會立即送出，因此 Tool 仍在執行時，確認訊息就可能送達文字轉語音服務。送出請求會標示片段邊界，但無法保證每個語音 Provider 都會立即產生音訊。

自訂產生器仍可傳回字串串流。若要明確送出邊界，請傳回 `ReadableStream<VoiceReplyChunk>`，並將 `VOICE_TEXT_FLUSH` 加入佇列；兩者都由 `@mastra/livekit/worker` 和 `@mastra/livekit/plugin` 匯出。直接讀取回覆產生器的程式碼，必須區分字串與邊界物件。切勿將邊界物件串接到逐字稿中。

Worker 會將邊界轉換為 LiveKit 的 `FlushSentinel`。使用 `MastraLLM` 外掛時，請在自行管理的 LiveKit Agent 中加入節點轉接器：

```typescript
import { voice } from '@livekit/agents'
import { MastraLLM, mastraLLMNode } from '@mastra/livekit/plugin'

class SupportAgent extends voice.Agent {
  override llmNode(...args: Parameters<voice.Agent['llmNode']>) {
    return mastraLLMNode(this, ...args)
  }
}

const session = new voice.AgentSession({
  llm: new MastraLLM({ agent: supportAgent }),
  // Configure STT and TTS for your application.
})
await session.start({ agent: new SupportAgent({ instructions: 'Support assistant' }), room })
```

沒有轉接器時，外掛仍會輸出文字，但 LiveKit 的預設節點不會將外掛的邊界中繼資料轉換為送出標記。在 Workflow 回覆步驟中使用 `pipeAgentReplyToWriter()`，可保留計算時間所需的邊界與 Tool 結果。

### 部署 {/* #deployment */}

Worker 是獨立於 Mastra 伺服器的行程。使用正式環境命令，將其部署為持續執行的 Node 服務：

```bash
node dist/voice-worker.js start
```

LiveKit 關於資源規模、正常關閉及託管的指引仍然適用。請參閱[部署 Agent](https://docs.livekit.io/agents/ops/deployment/)。Worker 會主動向外連線至 LiveKit，因此不需要開放入站連接埠。

### 運作方式 {/* #how-it-works */}

LiveKit 語音工作階段包含三個部分：

1. Mastra 伺服器產生 LiveKit 存取 token，並將 Agent 派遣至房間。派遣資訊包含 Mastra Agent ID、記憶體對話執行緒及資源等中繼資料。
2. LiveKit Agent Worker（獨立且持續執行的行程）接收工作並執行音訊處理流程。音訊透過 WebRTC 在瀏覽器與 Worker 之間傳輸，不會經過 Mastra HTTP 伺服器。
3. 使用者每完成一回合，Worker 就會以新輸入呼叫 Mastra Agent 的 `stream()`，並唸出串流回傳的文字。使用者打斷時，LiveKit 會取消串流，Mastra 也會停止生成。

對話歷史儲存在 Mastra Memory 中，因此語音工作階段與文字聊天可以共用同一個對話執行緒。

## 升級至 0.5.0 {/* #upgrade-to-050 */}

0.5.0 預發行版需要 LiveKit Agents 1.7.1 或更新的 1.x 版本。語音輔助函式會使用 `FlushSentinel` 和 `SpeechHandle.exception()`，但 Agents 1.4.0 不提供這些功能。部署前，請測試提供的預發行版本或套件封存檔。更新相依套件的版本範圍不會更新現有鎖定檔；安裝後請檢查實際安裝的版本。

如果你曾在較早的快照中使用 `client.getLiveKitRecording(traceId)`，請改用從 `@mastra/livekit/client` 匯入的 `getLiveKitRecording(client, traceId)`。`LiveKitRecordingResponse` 也應從同一入口匯入，取代從 client-js 匯入的 `GetLiveKitRecordingResponse`。

### 授權存取錄音 {/* #authorize-recording-access */}

升級已註冊 `liveKitRecordingRoute()` 的應用程式前，請加入 `authorize({ traceId, context })` 回呼，檢查已驗證身分的使用者是否有權存取請求的 trace。即使設定 `requiresAuth: false`，這個回呼仍是必要的；若省略，註冊路由時會擲出錯誤。只有在允許存取時才回傳 `true`，而且這項檢查必須先於 trace 查詢或播放網址解析。設定範例請參閱[在 Studio 中檢視錄音](#review-recordings-in-studio)。

### 安裝相容的套件 {/* #install-compatible-packages */}

Agents 與其外掛必須使用完全相同的發行版本。經測試的版本組合如下：

| 套件 | 版本 |
| - | - |
| `@livekit/agents` | `1.7.1` |
| `@livekit/agents-plugin-livekit` | `1.7.1` |
| `@livekit/agents-plugin-silero` | `1.7.1` |
| `@livekit/rtc-node` | `0.13.34` |
| `livekit-server-sdk` | `2.16.0` |

如果使用本機的預發行版封存檔，請與對應版本的 LiveKit 套件一起安裝：

```bash npm2yarn
npm install ./mastra-livekit-0.5.0-next.0.tgz @livekit/agents@1.7.1 @livekit/agents-plugin-livekit@1.7.1 @livekit/agents-plugin-silero@1.7.1 @livekit/rtc-node@0.13.34 livekit-server-sdk@2.16.0
```

請將封存檔路徑替換為實際提供的預發行版路徑。其他 `@livekit/agents-plugin-*` 套件也應安裝相同的發行版本。Agents 1.7.1 和 Silero 1.7.1 需要 RTC `^0.13.34`；RTC 1.x 不符合這項要求。請勿略過 peer dependency 錯誤強行安裝。

請使用 Node.js 22.13 或更新版本。`@mastra/livekit` 與 Agents 都需要 Zod `^3.25.76 || ^4.1.8`。安裝 0.5.0 前，請先升級較舊的 Zod 版本。接著確認已安裝的相依套件樹，並初始化 worker 使用的模型：

```bash npm2yarn
npm ls @mastra/livekit @livekit/agents @livekit/agents-plugin-livekit @livekit/agents-plugin-silero @livekit/rtc-node
npx tsx src/mastra/voice-worker.ts download-files
```

整合套件與自訂的 `voice.AgentSession` 應共用同一份已安裝的 Agents。若安裝了多份，可能無法通過 LiveKit 的執行階段類別檢查。

### 檢查 VAD 與回合結束偵測 {/* #check-vad-and-turn-detection */}

現在設定 `vad: false` 會在建立工作階段時停用 VAD。先前 worker 雖會略過外掛預熱，卻將 `undefined` 傳給 LiveKit，因此可能啟用 LiveKit 內建的 VAD。如果應用程式依賴先前的行為，請明確設定偵測器。

```typescript title="src/mastra/voice-worker.ts"
import { createLiveKitWorker } from '@mastra/livekit/worker'
import { mastra } from './index'

export default createLiveKitWorker({
  mastra,
  agent: 'support',
  vad: false,
  turnDetection: 'manual',
})
```

預設設定仍會在預熱期間載入 Silero 外掛。`'english'` 與 `'multilingual'` 回合結束偵測選項仍會選用原有的文字模型。你可以透過現有的實例與解析函式選項使用 LiveKit 較新的 `inference.VAD` 和 `inference.TurnDetector` API；是否改用這些 API 需要另行決定，因為這可能改變語音結束點判定、模型下載與雲端用量。

### 檢查自訂 LiveKit Tool {/* #review-custom-livekit-tools */}

Mastra Tool 仍透過 Mastra Agent 執行。如果你也實作了 LiveKit Tool 或自訂 LiveKit 外掛，請留意 Agents 1.4 之後的變更：

* `ToolContext` 是類別。請使用其存取器與 `flatten()`，不要將它當作一般物件列舉或修改。
* 現在支援具名 Tool 清單與重複名稱檢查。匿名 Tool 的物件簡寫仍可使用，無須轉換每個 Tool 對應表。
* Provider Tool 使用 `ProviderTool` 的子類別，取代舊有的 `ProviderDefinedTool` API。

自訂外掛的遷移詳情，請參閱 [LiveKit Tool API](https://github.com/livekit/agents-js/blob/main/agents/src/llm/tool_context.ts)。

### 檢查關閉流程 {/* #review-shutdown */}

`onCallEnd` hook 仍使用 LiveKit 的工作關閉回呼。請確保清理作業在設定的關閉時限內完成，並確認來電者中斷連線或 worker 收到關閉訊號時，清理作業都能完成。

### 驗證錄音與通話 {/* #verify-recordings-and-calls */}

整合套件的房間層級 `recording` 設定與 S3 權限維持不變。LiveKit Agents 的 `AgentSession.start({ record })` 控制另一套工作階段錄音與遙測機制。停用其中一套，不會停用另一套。

正式採用預發行版前，請測試瀏覽器通話，以及透過已設定 SIP trunk 進行的電話通話。確認雙方語音、中斷、Tool、開場問候與同意處理、掛斷、完整 trace，以及 `onCallEnd` 都正常運作。啟用錄音時，請等待 S3 物件產生，再使用 **Review Audio** 播放。也請測試停用錄音，以及使用已存在的房間名稱時遭到拒絕的情況。這些檢查應在已安裝模型檔案與原生程式庫的部署映像上執行。

## API 參考 {/* #api-reference */}

`@mastra/livekit` 套件將 Mastra Agent 連接至 LiveKit Agents 框架。LiveKit 負責音訊處理流程，包括語音活動偵測、語音轉文字、回合結束偵測、文字轉語音與插話；此套件則將回覆產生流程銜接至 Mastra Agent 的 `stream()` 呼叫。

設定方式與基本概念請參閱[即時語音](#quickstart)。

此套件有三個入口點：

* `@mastra/livekit`：伺服器端 API，包括 [`liveKitConnectionRoute()`](#livekitconnectionroute)、[`dispatchVoiceSession()`](#dispatchvoicesession)、[`pipeAgentReplyToWriter()`](#pipeagentreplytowriter)、[`serializeSessionMetadata()`](#livekitsessionmetadata) 與 [`createEndCallTool()`](#createendcalltool)。請從 Mastra 伺服器程式碼匯入這些 API。此入口不會載入 LiveKit Agents 執行階段。
* `@mastra/livekit/worker`：worker 執行階段，包括 [`createLiveKitWorker()`](#createlivekitworker)、[`runLiveKitWorker()`](#runlivekitworker)、[`chatContextToMessages()`](#chatcontexttomessages)、每個工作階段使用的 Agent 類別 [`MastraVoiceAgent`](#mastravoiceagent)，以及工作階段輔助函式 [`speakGreeting()`](#speakgreeting)、[`waitForAgentDoneSpeaking()`](#waitforagentdonespeaking) 與 [`runEndCall()`](#runendcall)。只應從 worker 入口檔案匯入。
* `@mastra/livekit/plugin`：LLM 元件外掛，包括 [`MastraLLM`](#mastrallm) 與 [`createRemoteAgentReplyGenerator()`](#createremoteagentreplygenerator)。自行建立 `voice.AgentSession` 的 worker 應從此入口匯入。`@mastra/livekit/worker` 也會匯出 `createRemoteAgentReplyGenerator()`，因為它可用於 `createLiveKitWorker()` 的 `generate` 選項。`MastraLLM` 則只能從外掛入口匯入。

### `createLiveKitWorker()` {/* #createlivekitworker */}

建立由 Mastra Agent 回應語音工作階段的 LiveKit Agent 定義。請將它作為 worker 入口檔案的預設匯出。

```typescript title="src/mastra/voice-worker.ts"
import { fileURLToPath } from 'node:url'
import { createLiveKitWorker, runLiveKitWorker } from '@mastra/livekit/worker'
import { mastra } from './index'

export default createLiveKitWorker({
  mastra,
  agent: 'support',
  stt: 'deepgram/nova-3',
  tts: 'cartesia/sonic-3',
  turnDetection: 'multilingual',
})

if (process.argv[1] === fileURLToPath(import.meta.url)) {
  runLiveKitWorker({ entry: import.meta.url, agentName: 'mastra-voice' })
}
```

### `pipeAgentReplyToWriter()` {/* #pipeagentreplytowriter */}

在 Workflow 回覆路徑上，將 Mastra Agent 的回覆串流傳入 Workflow 步驟的 `writer`。此函式會轉送 Agent 的文字增量，讓文字轉語音在完整回覆產生前就開始播放；也會轉送 Tool 呼叫區塊，使 `toolFeedback` 得以觸發，且 `onTurnComplete` 能取得 Tool 清單。若只傳入 `stream.textStream`，Tool 呼叫會在未提示的情況下遺失。請將步驟的 `abortSignal` 傳給 `agent.stream()`，讓使用者插話時能及時停止產生回覆。

```typescript title="src/mastra/workflows/phone-conversation.ts"
import { pipeAgentReplyToWriter } from '@mastra/livekit'
import { createStep } from '@mastra/core/workflows'

const generateResponse = createStep({
  id: 'generateResponse',
  // input and output schemas omitted
  execute: async ({ inputData, mastra, writer, abortSignal }) => {
    const stream = await mastra.getAgent('support').stream(inputData.turn, { abortSignal })
    const reply = await pipeAgentReplyToWriter(stream, writer)
    return { reply }
  },
})
```

回傳：`Promise<string>`，內容為累積的回覆文字。

### `MastraVoiceAgent` {/* #mastravoiceagent */}

這是 LiveKit `voice.Agent` 的子類別，由 [`createLiveKitWorker()`](#createlivekitworker) 為每個工作階段建立。Mastra Agent（或自訂 `generate` 來源）的回覆會經由 Agent 的 `llmNode` 傳送；音訊循環、回合偵測與使用者插話仍由 LiveKit 處理。如果你自行管理 `voice.AgentSession`，也可以自行建立此類別。例如，不需語音轉文字、文字轉語音或實際運行的 worker，就能使用 `@livekit/agents` 的 `voice.testing` 測試由 Mastra 支援的 Agent。`createMastraVoiceAgent(options)` 是功能相同的工廠函式。

```typescript title="src/mastra/voice-agent.test.ts"
import { initializeLogger, voice } from '@livekit/agents'
import { MastraVoiceAgent } from '@mastra/livekit/worker'
import { supportAgent } from './agents/support'

// Required outside a LiveKit worker: AgentSession needs the LiveKit logger initialized.
initializeLogger({ level: 'silent', pretty: false })

const session = new voice.AgentSession()
await session.start({ agent: new MastraVoiceAgent({ agent: supportAgent, memory: false }) })

// run() returns a RunResult, not a promise; wait() resolves when the turn completes.
const result = session.run({ userInput: 'What are your opening hours?' })
await result.wait()
result.expect.nextEvent().isMessage({ role: 'assistant' })
result.expect.noMoreEvents()
```

Agent 自帶佔位用的 `llm.LLM`，讓 LiveKit 執行回覆管線。內容產生一律經過 `llmNode`，因此工作階段 `llm` 欄位中的 `FakeLLM` 會被忽略；呼叫佔位物件的 `chat()` 則會擲出錯誤。若要在測試中替換模型，請為 Mastra Agent 提供模擬模型，或傳入自訂 `generate` 函式。

### `MastraLLM` {/* #mastrallm */}

這是由 Mastra Agent 支援的標準 LiveKit LLM 外掛程式（`llm.LLM`）。如果你自行建立 `voice.AgentSession`，並想在 `llm` 欄位使用 Mastra，即可使用此元件。若要由系統管理，則可使用 [`createLiveKitWorker()`](#createlivekitworker)。選用方式請參閱[將 Mastra 用作 LLM 元件](#use-mastra-as-the-llm-component)。

使用 `remote` 時，外掛程式會透過 HTTP 上的 Server-Sent Events (SSE)，從你的 Mastra 伺服器串流傳送每回合的回覆。Agent 循環、Tool 與記憶功能都在伺服器端執行；中斷 Agent 也會終止伺服器端的內容產生。

```typescript title="src/mastra/voice-worker-plugin.ts"
import { voice } from '@livekit/agents'
import { MastraLLM } from '@mastra/livekit/plugin'

const session = new voice.AgentSession({
  llm: new MastraLLM({
    remote: { baseUrl: process.env.MASTRA_URL!, agentId: 'support' },
    memory: { thread: callId, resource: userId },
  }),
  stt: 'deepgram/nova-3',
  tts: 'cartesia/sonic-3',
  // Required with `memory` unless memory.options.readOnly is set: LiveKit enables
  // preemptive generation by default.
  turnHandling: { preemptiveGeneration: { enabled: false } },
})
```

外掛程式回報的 `provider` 為 `mastra`，`model` 為 Agent ID，因此 LiveKit 指標與備援適配器可像辨識其他 LLM 一樣辨識它。

#### 在 Mastra Agent 上執行的 Tool {/* #tools-run-on-the-mastra-agent */}

Tool 在伺服器端的 Mastra Agent 上定義並執行。外掛程式不會轉送 LiveKit 的 Tool 定義：如果工作階段傳入非空的 `toolCtx`，就會記錄一次警告，列出被忽略的 Tool。每個 Tool 都必須能在伺服器端完成；需要核准或用戶端執行的 Tool 會使該回合失敗並顯示具體錯誤，而不會讓通話一直等待。

worker 可透過 `toolFeedback`、`onToolCall` 和 `onTurnComplete` 得知 Tool 活動。

#### 指示 {/* #instructions */}

LiveKit 會將你的 `voice.Agent` 的 `instructions` 注入每個請求的聊天上下文。外掛程式會捨棄這些指示，因為應以伺服器端 Mastra Agent 自身的指示為準。若要修改提示詞，請修改 Mastra Agent。

#### 中斷的回合 {/* #interrupted-turns */}

當使用者打斷回覆時：

1. 外掛程式取消串流。伺服器中止產生內容，且不會持久化該回合的任何內容。
2. LiveKit 在聊天上下文中記錄使用者實際聽到的部分，並將其標記為已中斷。
3. 下一回合，外掛程式會在新的使用者訊息之前重新傳送該段使用者已聽到的內容，讓記憶執行緒補齊資料，與通話內容一致。訊息帶有 LiveKit 的訊息 ID，伺服器會依 ID 去重，因此重試與重新傳送仍具冪等性。

如果使用者在打斷回覆後立即掛斷，最後那段內容就不會被記錄。若對話逐字稿必須包含它，請立即根據工作階段事件補寫；由於使用相同的訊息 ID，下一回合重新傳送時會更新或插入該訊息，而不會產生重複項目：

```typescript title="src/mastra/voice-worker-plugin.ts"
import { voice } from '@livekit/agents'
import { MastraClient } from '@mastra/client-js'

const client = new MastraClient({ baseUrl: process.env.MASTRA_URL! })

session.on(voice.AgentSessionEventTypes.ConversationItemAdded, ({ item }) => {
  if (item.type !== 'message' || item.role !== 'assistant' || !item.interrupted) return
  void client.saveMessageToMemory({
    agentId: 'support',
    messages: [
      {
        id: item.id,
        threadId: callId,
        resourceId: userId,
        role: 'assistant',
        content: item.textContent ?? '',
        type: 'text',
        createdAt: new Date(),
      },
    ],
  })
})
```

#### 用量指標 {/* #usage-metrics */}

當伺服器回報某回合的 token 用量時，外掛程式會將資料提供給 LiveKit。因此，工作階段的 `metrics_collected` 事件會像其他 LLM 外掛程式一樣，包含首個 token 的等待時間、持續時間與 token 數量。同一份用量資料（`promptTokens`、`completionTokens`、`promptCachedTokens`、`totalTokens`）也會以 `result.usage` 傳入 `onTurnComplete`。

#### 錯誤與逾時 {/* #errors-and-timeouts */}

傳輸層會擲出 LiveKit 的 `APIError` 類型（`APIStatusError`、`APIConnectionError`、`APITimeoutError`），因此工作階段的重試政策（`connOptions.maxRetry`）與 `FallbackAdapter` 容錯移轉機制都能照常運作。回合一旦輸出第一個 token，就不會重試：語音回覆若已被使用者聽到一部分，應立即失敗，而非重新播放。

連線及首個 token 的逾時監控會使用工作階段的 `connOptions.timeoutMs`（預設為 10 秒），因此即使伺服器接受連線卻始終未開始串流，也不會讓通話無限期保持靜音。

如果 Mastra 伺服器在通話期間中斷，每次嘗試回覆都會在重試後因特定類型的錯誤而失敗；連續多次回覆失敗後，LiveKit 會關閉工作階段。若能在允許的失敗次數用盡前恢復伺服器，通話就能在下一回合恢復。

#### 訊息內容 {/* #message-content */}

擷取訊息時只保留文字：圖片內容會被捨棄，音訊內容也只有逐字稿會納入。語音管線不受影響，但你自行注入聊天上下文的項目必須包含文字。

### `createRemoteAgentReplyGenerator()` {/* #createremoteagentreplygenerator */}

建立在**遠端** Mastra 伺服器上透過 HTTP/SSE 執行 Agent 循環的回覆產生器。`MastraLLM` 的 `remote` 模式會在內部使用它。你也可以將它直接傳入 `createLiveKitWorker` 的 `generate` 選項，讓功能完整的 worker 使用遠端伺服器：

```typescript title="src/mastra/voice-worker.ts"
import { createLiveKitWorker, createRemoteAgentReplyGenerator } from '@mastra/livekit/worker'
import { mastra } from './index'

export default createLiveKitWorker({
  mastra, // local instance for logger and worker config; replies come from the remote server
  generate: createRemoteAgentReplyGenerator({
    baseUrl: process.env.MASTRA_URL!,
    agentId: 'support',
  }),
  memory: ({ metadata, roomName }) => ({ thread: metadata.threadId ?? roomName }),
  stt: 'deepgram/nova-3',
  tts: 'cartesia/sonic-3',
})
```

使用 `generate` 路徑時，worker 層級的 `toolFeedback` 與 `onTurnComplete` 選項不會生效，worker 的通話結束偵測也不會觸發；請改將這些掛鉤傳給產生器。

取消回合（使用者插話）會終止 HTTP 請求，進而中止伺服器端的內容產生。錯誤會以 LiveKit 的 `APIError` 類型擲出。`retries` 選項只適用於初次連線嘗試；回合一旦輸出第一個區塊，就不會重試。

### `waitForAgentDoneSpeaking()` {/* #waitforagentdonespeaking */}

當 Agent 不再產生或播放回覆，也就是狀態已離開 `thinking` 和 `speaking` 時，promise 便會完成。如果 Agent 已處於閒置狀態，則會立即完成；為避免無限等待，最遲會在 `maxWaitMs` 內完成，預設為 30 秒。關閉工作階段前先呼叫此函式，讓結束語播放完畢，避免遭到截斷。

```typescript
import { waitForAgentDoneSpeaking } from '@mastra/livekit/worker'

await waitForAgentDoneSpeaking(session)
```

### `runEndCall()` {/* #runendcall */}

Agent 要求掛斷後，這個函式會結束通話。它會等待 Agent 說完結束語，並在不中斷的情況下播放可選的最後訊息 `message`。接著刪除房間並掛斷來電者，包含 SIP 來電者。作業會透過已註冊的回呼關閉。

在自行管理的工作階段中，搭配 [`MastraLLM`](#mastrallm) 的 `onToolCall` 與伺服器端 Agent 的[結束通話 Tool](#createendcalltool)，即可實作由 Agent 主動掛斷的流程：

```typescript title="src/mastra/voice-worker-plugin.ts"
import { MastraLLM } from '@mastra/livekit/plugin'
import { DEFAULT_END_CALL_TOOL, runEndCall } from '@mastra/livekit/worker'

let ending = false

const llm = new MastraLLM({
  remote: { baseUrl: process.env.MASTRA_URL!, agentId: 'support' },
  onToolCall: ({ toolName }) => {
    if (toolName !== DEFAULT_END_CALL_TOOL || ending) return
    ending = true
    void runEndCall(session, ctx, {}, console)
  },
})
```

匯出的常數 `DEFAULT_END_CALL_TOOL`（`'endCall'`）、`DEFAULT_END_CALL_REASON` 和 `DEFAULT_END_CALL_MAX_WAIT_MS`（30000）分別保存預設值。
