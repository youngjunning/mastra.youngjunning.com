# 直播套件

## 快速入門 {/* #quickstart */}

即時語音將 Mastra Agent轉變為用戶可以在瀏覽器中或透過電話進行的即時通話。 Mastra 建立在[LiveKit](https://livekit.io), an open source WebRTC platform for realtime audio and video.

這[`@mastra/livekit`](#api-reference) package connects Mastra agents to the [LiveKit Agents framework](https://docs.livekit.io/agents/)：LiveKit 擁有音訊循環，如語音活動偵測、串流語音到文字、語義轉向偵測、插入和文字轉語音。您的 Mastra Agent程式使用自己的模型、Tool和記憶體產生每個回應。

當您需要低延遲、可中斷的語音對話時，請使用即時語音。對於不使用 LiveKit 的基於Provider的語音到語音，請參閱[Speech to Speech](/reference/voice/speech-to-speech).

這些步驟將您從空專案轉變為可以與之交談的語音Agent。語音會話有兩個移動部分，您可以在此處設定：Mastra 伺服器上的 API 路由，用於分發存取令牌，以及一個單獨的工作進程，用於運行音訊管道並每輪調用您的Agent。

<Steps>
  <StepItem>
    安裝整合包以及 LiveKit 插件以進行語音活動檢測和轉彎檢測：

    ```bash npm2yarn
    npm install @mastra/livekit @livekit/agents @livekit/agents-plugin-silero @livekit/agents-plugin-livekit
    ```
  </StepItem>

  <StepItem>
    將您的 LiveKit 憑證設定在`.env` file. Create a free project on [LiveKit Cloud](https://cloud.livekit.io), or run a local server with [`livekit-server --dev`](https://docs.livekit.io/home/self-hosting/local/):

    ```bash title=".env"
    LIVEKIT_URL=wss://your-project.livekit.cloud
    LIVEKIT_API_KEY=your-api-key
    LIVEKIT_API_SECRET=your-api-secret
    ```
  </StepItem>

  <StepItem>
    將語音Agent程式新增至您的 Mastra 實例並公開連線路由。這`liveKitConnectionRoute()` helper adds a `POST /voice/livekit/connection-details` endpoint that mints a LiveKit token and dispatches your agent into a room:

    ```typescript title="src/mastra/index.ts"
    import { Mastra } from '@mastra/core/mastra'
    import { Agent } from '@mastra/core/agent'
    import { liveKitConnectionRoute } from '@mastra/livekit'

    const supportAgent = new Agent({
      id: 'support',
      name: 'Support',
      instructions: 'You are a friendly phone support agent. Keep replies short and conversational.',
      model: '__GATEWAY_OPENAI_MODEL_LUNA__',
    })

    export const mastra = new Mastra({
      agents: { support: supportAgent },
      server: {
        apiRoutes: [liveKitConnectionRoute({ agentName: 'mastra-voice' })],
      },
    })
    ```
  </StepItem>

  <StepItem>
    創建工人。它作為一個單獨的進程運行，應答 LiveKit 會話，並每輪呼叫您的Agent。 Worker API 存在於`@mastra/livekit/worker` entry point, so the Mastra server never loads the LiveKit agents runtime. This example uses LiveKit Inference model strings for speech-to-text and text-to-speech, so no provider plugins are required:

    ```typescript title="src/mastra/voice-worker.ts"
    import { fileURLToPath } from 'node:url'
    import { createLiveKitWorker, runLiveKitWorker } from '@mastra/livekit/worker'
    import { mastra } from './index'

    export default createLiveKitWorker({
      mastra,
      agent: 'support',
      stt: 'deepgram/nova-3',
      tts: 'cartesia/sonic-3',
      turnDetection: 'multilingual',
      greeting: 'Hi! How can I help you today?',
    })

    if (process.argv[1] === fileURLToPath(import.meta.url)) {
      runLiveKitWorker({ entry: import.meta.url, agentName: 'mastra-voice' })
    }
    ```

    這`agent` option selects which Mastra agent answers each session. Pass a fixed key as shown, or omit it to use the `agentId` from the dispatch metadata, so one worker can serve every agent on your Mastra instance.
  </StepItem>

  <StepItem>
    下載一次轉彎偵測和語音活動偵測模型。然後在一個終端機中運行工作程序，在另一個終端機中運行 Mastra 伺服器：

    ```bash
    npx livekit-agents download-files
    npx tsx src/mastra/voice-worker.ts dev
    ```

    ```bash npm2yarn
    npm run dev
    ```

    工作人員向您的 LiveKit 伺服器註冊並等待會話，同時`mastra dev` serves the connection route.
  </StepItem>

  <StepItem>
    與您的Agent交談。打開託管的[LiveKit Agents Playground](https://agents-playground.livekit.io) and connect it to your project to start a call without building a frontend.

    若要連接您自己的應用程序，請呼叫令牌的連接路由。`POST /voice/livekit/connection-details` accepts optional `agentId`, `threadId`, and `resourceId` fields in the request body and returns:

    ```json
    {
      "serverUrl": "wss://your-project.livekit.cloud",
      "roomName": "mastra-voice-a1b2c3d4",
      "participantName": "user-1",
      "participantToken": "eyJhbGci..."
    }
    ```

    此回應與 LiveKit 前端啟動器使用的合約相匹配，因此應用程式建構自[agent-starter-react](https://github.com/livekit-examples/agent-starter-react) or the [LiveKit React components](https://docs.livekit.io/reference/components/react/) work without changes.
  </StepItem>

### 轉彎檢測與中斷 {/* #turn-detection-and-interruptions */}

LiveKit 決定使用者何時結束演講以及Agent商何時被打斷。預設值運作良好；調整它們`turnHandling`:

```typescript title="src/mastra/voice-worker.ts"
export default createLiveKitWorker({
  mastra,
  agent: 'support',
  stt: 'deepgram/nova-3',
  tts: 'cartesia/sonic-3',
  turnDetection: 'multilingual',
  turnHandling: {
    endpointing: { mode: 'dynamic', minDelay: 300, maxDelay: 3000 },
    interruption: { minDuration: 500, resumeFalseInterruption: true },
  },
})
```

* `turnDetection: 'multilingual'`：在 CPU 上本地運行 LiveKit 的語意回合結束模型。它會讀取即時文字記錄，以避免打斷使用者的思考。使用`'vad'` or `'stt'` for silence-based endpointing instead.
* `endpointing`：限制使用者停止講話後Agent等待的時間。
* `interruption`：控制插入。當使用者透過Agent程式講話時，LiveKit 會停止播放並取消正在進行的 Mastra 串流，因此令牌產生也會停止。
* `preemptiveGeneration`：在用戶仍在完成時開始 Mastra Agent的回复，隱藏首次標記的時間。預設情況下，worker 會停用它：每次搶佔式嘗試都會在臨時記錄上執行 Mastra Agent，而 LiveKit 隨後丟棄的運行已經保留了部分用戶訊息和對線程的部分、從未說出的回應。重新啟用它`preemptiveGeneration: { enabled: true }` if latency matters more than exact thread history, or keep both by running turns read-only; see [preemptive generation with memory](#preemptive-generation-with-memory).

請參閱[LiveKit turn detection docs](https://docs.livekit.io/agents/logic/turns/) for all options.

若要停用語音活動偵測，請設定`vad: false` on `createLiveKitWorker()`. The worker passes `null` to LiveKit, which otherwise enables its bundled detector when `vad` is omitted. Choose a turn detection mode that doesn't require VAD, such as `'manual'`, when disabling it. Values in `sessionOptions` override the worker's generated options, including `vad`.

### 每次通話的語音和轉錄 {/* #per-call-voices-and-transcription */}

頂層`stt` and `tts` options apply to every call. To pick them per call, one voice or language per tenant, set the `configuration.stt` and `configuration.tts` resolvers instead. Each resolver runs once per call with the dispatch metadata, request context, room name, and job context, and returns a value accepted by the matching top-level option. The value is either a plugin instance or an inference model string. Return `undefined` to fall back to the top-level option.

以下範例為每個租用戶提供了自己的文字轉語音語音，並關閉了`tenant` entry in the dispatch metadata:

```typescript title="src/mastra/voice-worker.ts"
import * as cartesia from '@livekit/agents-plugin-cartesia'

// One voice id per tenant, resolved from the dispatch metadata on each call.
const tenantVoices: Record<string, string> = {
  meridian: 'your-cartesia-voice-id-1',
  coastal: 'your-cartesia-voice-id-2',
}
// The resolver runs during call setup, so cache plugin instances across calls.
const ttsByVoice = new Map<string, cartesia.TTS>()

export default createLiveKitWorker({
  mastra,
  agent: 'support',
  stt: 'deepgram/nova-3',
  tts: 'cartesia/sonic-3',
  configuration: {
    tts: ({ requestContext }) => {
      const voice = tenantVoices[requestContext?.tenant as string]
      if (!voice) return undefined // fall back to the top-level `tts`
      let tts = ttsByVoice.get(voice)
      if (!tts) {
        tts = new cartesia.TTS({ voice })
        ttsByVoice.set(voice, tts)
      }
      return tts
    },
  },
})
```

`configuration.stt`每次呼叫轉錄的工作方式相同，例如每個租戶使用不同的轉錄模型或語言。問候語有一個匹配的每次呼叫形式：`configuration.greeting.text` accepts a resolver with the same call context, so one worker can open with each tenant's own phrasing.

### 每次呼叫轉彎偵測 {/* #per-call-turn-detection */}

LiveKit 的`TurnDetector` classes read the job's inference executor when constructed, so they can only be created inside a LiveKit job, not at module scope where the worker options live. To use one, set the `configuration.turnDetection` resolver. It runs once per call with the same call context as `configuration.stt` and returns anything the top-level `turnDetection` option accepts. Return `undefined` to fall back to the top-level option.

```typescript title="src/mastra/voice-worker.ts"
import { turnDetector } from '@livekit/agents-plugin-livekit'

export default createLiveKitWorker({
  mastra,
  agent: 'support',
  stt: 'deepgram/nova-3',
  tts: 'cartesia/sonic-3',
  turnDetection: 'multilingual',
  configuration: {
    // Constructed inside the job, where the inference executor is available.
    turnDetection: () => new turnDetector.MultilingualModel(0.2),
  },
})
```

語意模型的推理運行器必須在Agent伺服器啟動之前註冊，因此當設定此解析器時，工作器將匯入`@livekit/agents-plugin-livekit` up front. Keep the top-level `turnDetection` set to `'multilingual'` or `'english'` to pre-register only that model; otherwise both stay available.

### 記憶體和線程 {/* #memory-and-threads */}

當解析後的 Mastra Agent程式配置了記憶體時，每次呼叫都會成為一個記憶體線程：

* `thread`預設為`threadId` from dispatch metadata, then to the room name.
* `resource`預設為`resourceId` from dispatch metadata, then to the thread. Send your end user's id here so calls group under the right user. Mastra Studio sends the agent id, matching how its sidebar lists threads.
* 當線程尚不存在時，工作人員會使用元資料建立標題為「語音通話」的線程`{ source: 'livekit' }`, and the spoken greeting is saved as the first assistant message so the thread reads as a full call transcript (disable with `persistGreeting: false`).

每輪僅發送新的用戶輸入； Mastra Memory 提供歷史、語義回憶和工作記憶。透過傳遞將會話固定到現有線程`threadId` in the connection request body, which is useful for continuing a text conversation by voice. In Studio, starting a call from an open chat binds the call to that thread, and the transcript fills into the chat after each exchange.

當使用者中斷Agent程式時，正在進行的產生將中止，並且此時該輪中的任何內容都不會保留。 LiveKit 將使用者實際聽到的部分保留在其記錄中，並且在下一個回合中，工作人員重新發送僅聽到的片段，以便執行緒回填以匹配呼叫。如果使用者在打斷後立即掛斷，則最後的片段不會被記錄。看[interrupted turns](#interrupted-turns) for the details and a reconciliation recipe.

#### 帶內存的搶佔式生成 {/* #preemptive-generation-with-memory */}

LiveKit 的搶佔式產生在臨時轉錄本上呼叫 Mastra Agent，並丟棄轉錄本已更改的運行。該插件無法區分推測運行和真實回合，因此`memory` set every run persists, including discarded ones. To keep preemptive generation on without corrupting the thread, pass `options: { readOnly: true }` in the memory mapping. The agent still reads history, semantic recall, and working memory from the thread but writes nothing, so speculative runs leave no trace. Persistence of committed turns then belongs to you: save them from LiveKit's `ConversationItemAdded` event, which fires only for items the session committed. Messages keep LiveKit's ids, so saves stay idempotent across retries.

```typescript title="src/mastra/voice-worker.ts"
import { voice } from '@livekit/agents'
import { createLiveKitWorker } from '@mastra/livekit/worker'
import { mastra } from './index'

export default createLiveKitWorker({
  mastra,
  agent: 'support',
  memory: ({ metadata, roomName }) => ({
    thread: metadata.threadId ?? roomName,
    resource: metadata.resourceId ?? roomName,
    options: { readOnly: true },
  }),
  turnHandling: { preemptiveGeneration: { enabled: true } },
  onSessionStart: async ({ session, ctx, agent }) => {
    const mapping = agent.memory
    const memory = await mastra.getAgent('support').getMemory()
    if (!mapping || !memory) return

    let shuttingDown = false
    const maxRetries = 5
    const retryTimers = new Set<ReturnType<typeof setTimeout>>()
    ctx.addShutdownCallback(async () => {
      shuttingDown = true
      for (const timer of retryTimers) clearTimeout(timer)
      retryTimers.clear()
    })

    session.on(voice.AgentSessionEventTypes.ConversationItemAdded, ({ item }) => {
      if (item.type !== 'message' || (item.role !== 'user' && item.role !== 'assistant')) return

      const persist = async (attempt = 0): Promise<void> => {
        try {
          await memory.saveMessages({
            messages: [
              {
                id: item.id,
                threadId: mapping.thread,
                resourceId: mapping.resource ?? mapping.thread,
                role: item.role,
                content: {
                  format: 2,
                  parts: [{ type: 'text', text: item.textContent ?? '' }],
                },
                type: 'text',
                createdAt: new Date(),
              },
            ],
          })
        } catch (error) {
          if (shuttingDown) return
          if (attempt >= maxRetries) {
            console.error(`Failed to persist committed voice item ${item.id}; giving up`, error)
            return
          }
          console.error(`Failed to persist committed voice item ${item.id}; retrying`, error)
          const delay = Math.min(1_000 * 2 ** attempt, 30_000)
          const timer = setTimeout(() => {
            retryTimers.delete(timer)
            void persist(attempt + 1)
          }, delay)
          retryTimers.add(timer)
        }
      }

      void persist()
    })
  },
})
```

相同`options` field works on `MastraVoiceAgent` and `MastraLLM`; on the remote transport it's forwarded in the request body as `memory.options`.

### Tool運行時說話 {/* #speak-while-tools-run */}

當Tool運作緩慢時，語音對話無法保持沉默。使用`toolFeedback` to speak a short phrase when the Mastra agent starts a tool call:

```typescript title="src/mastra/voice-worker.ts"
export default createLiveKitWorker({
  mastra,
  agent: 'support',
  stt: 'deepgram/nova-3',
  tts: 'cartesia/sonic-3',
  toolFeedback: ({ toolName }) =>
    toolName === 'searchOrders' ? 'Let me look that up.' : undefined,
})
```

該短語作為答复的一部分被說出並記錄在筆錄中。

### 使用Workflow產生回复 {/* #generate-replies-with-a-workflow */}

預設情況下，工作人員使用 Mastra Agent程式產生每個回應。要每回合運行多步驟邏輯（例如對意圖、路由、按順序調用Tool進行分類，然後撰寫回复），請使用 Mastra 生成回复[workflow](/docs/workflows/overview) instead. Set `workflow` in place of `agent`.

LiveKit 仍然擁有音訊循環並每回合調用一次 Mastra，因此Workflow每回合都會運行完成。Workflow無法暫停或恢復，且輪流之間不會傳輸任何對話狀態。透過傳遞成績單`workflowInput` so the workflow stays stateless:

```typescript title="src/mastra/voice-worker.ts"
import { createLiveKitWorker, chatContextToMessages } from '@mastra/livekit/worker'
import { mastra } from './index'

export default createLiveKitWorker({
  mastra,
  workflow: 'phoneConversation',
  workflowInput: ({ chatCtx }) => ({ history: chatContextToMessages(chatCtx) }),
  replyStep: 'generateResponse',
  stt: 'deepgram/nova-3',
  tts: 'cartesia/sonic-3',
  turnDetection: 'multilingual',
})
```

Workflow串流結構化步驟事件，而不是文字。為了在生成令牌時說出令牌，回應步驟將其Agent的文字透過管道傳輸到步驟中`writer`:

```typescript title="src/mastra/workflows/phone-conversation.ts"
import { createStep } from '@mastra/core/workflows'

const generateResponse = createStep({
  id: 'generateResponse',
  // input and output schemas omitted
  execute: async ({ inputData, mastra, writer, abortSignal }) => {
    const stream = await mastra.getAgent('voice').stream(inputData.history, { abortSignal })
    await stream.textStream.pipeTo(writer)
    return { assistantMessage: await stream.text }
  },
})
```

* `replyStep`：將語音輸出限制為一級。省略它來講述寫入其的每一步`writer`.
* `resultText`：當沒有步驟流程文字時，從最終運行結果派生回應的後備方案。流過`writer` gives lower time-to-first-token, so prefer it.
* `abortSignal`：前進步驟`abortSignal` into `agent.stream()` so barge-in stops generation promptly. When the user interrupts, the worker cancels the run.
* `generate`：要完全控制，請傳遞`generate` function instead. It can be any reply generator that turns a turn into a text stream.

透過Workflow，工作人員不會像Agent商的方式自動轉變`stream()` does. Persist conversation history inside the workflow, or keep the LiveKit transcript as the source of truth and pass it in each turn.

### 使用 Mastra 作為 LLM 組成部分 {/* #use-mastra-as-the-llm-component */}

`createLiveKitWorker()`為您擁有 LiveKit 會話。要自己擁有會話，請使用[`MastraLLM`](#mastrallm) instead: a standard LiveKit LLM plugin that puts a Mastra agent in the `llm` slot of your own `voice.AgentSession`. The Mastra app, agent loop, tools, memory, observability, runs on your Mastra server, and the worker reaches it over HTTP. The worker process needs no Mastra app, database, or model provider keys.

```typescript title="src/mastra/voice-worker-plugin.ts"
import { fileURLToPath } from 'node:url'
import { defineAgent, voice } from '@livekit/agents'
import * as silero from '@livekit/agents-plugin-silero'
import { MastraLLM } from '@mastra/livekit/plugin'
import { runLiveKitWorker } from '@mastra/livekit/worker'

export default defineAgent({
  entry: async ctx => {
    await ctx.connect()

    const session = new voice.AgentSession({
      llm: new MastraLLM({
        remote: { baseUrl: process.env.MASTRA_URL!, agentId: 'support' },
        memory: { thread: ctx.room.name!, resource: 'user-7' },
      }),
      stt: 'deepgram/nova-3',
      tts: 'cartesia/sonic-3',
      vad: await silero.VAD.load(),
      // Required with `memory` unless memory.options.readOnly is set: LiveKit enables
      // preemptive generation by default.
      turnHandling: { preemptiveGeneration: { enabled: false } },
    })

    await session.start({
      // These instructions never reach the Mastra agent; its own instructions apply.
      agent: new voice.Agent({ instructions: 'Replies come from the Mastra agent.' }),
      room: ctx.room,
    })

    session.say('Hi! How can I help you today?')
  },
})

if (process.argv[1] === fileURLToPath(import.meta.url)) {
  runLiveKitWorker({ entry: import.meta.url, agentName: 'mastra-voice' })
}
```

兩條路徑共享下面相同的回覆管道；選擇誰應該擁有會話：

| | `createLiveKitWorker()` | `MastraLLM` |
| - | - | - |
| Session ownership | The worker helper builds and manages the `AgentSession` | Your code builds the session; every LiveKit option and hook is yours |
| Where the Mastra app runs | In the worker process | On your Mastra server, reached over HTTP (or in-process via `agent`) |
| Worker process needs | Your Mastra app, storage, and model provider keys | Only the LiveKit SDK and network access to your server |
| Built-in conveniences | Greeting, consent gating, agent-initiated hang-up, thread bootstrap, observability roll-up | Rebuild what you need with the [session helpers](#runendcall) |
| Best for | Fastest path to a working voice agent; Studio voice mode | Existing LiveKit apps and full control over the session |

Tool保留在 Mastra Agent上並在伺服器上執行。傳遞到會話的 LiveKit 端Tool將被忽略。Tool活動透過以下方式到達工人`toolFeedback` (spoken filler), `onToolCall` (fires as each tool call starts), and `onTurnComplete` (fires after each reply with the text, tool calls, and token usage). Agent-initiated hang-up takes a few lines: pair `onToolCall` with [`runEndCall()`](#runendcall).

:::警告
不要組合`memory` option with LiveKit's `preemptiveGeneration`, which LiveKit enables by default in sessions you build yourself. A speculative turn persists a partial user message and a partial, never-spoken reply to the thread before LiveKit discards it. Set `turnHandling: { preemptiveGeneration: { enabled: false } }`, run without `memory` and pass the full transcript each turn, or set `memory.options.readOnly` and persist committed turns yourself; see [preemptive generation with memory](#preemptive-generation-with-memory).
:::

`MastraLLM`也接受正在處理的 Mastra`agent` instance, session ownership without a second deployment, or a custom `generate` function. The remote transport is available standalone as [`createRemoteAgentReplyGenerator()`](#createremoteagentreplygenerator), which also plugs into `createLiveKitWorker`'s `generate` option to run the batteries-included worker against a remote server.


### 通話錄音 {/* #record-calls */}

經過`recording` to `dispatchVoiceSession()` or `liveKitConnectionRoute()` to create a room with [LiveKit auto egress](https://docs.livekit.io/transport/media/ingress-egress/egress/autoegress/). Mastra creates the room with recording configured, then dispatches the voice agent. Omitting `recording` preserves the existing behavior and return values.

錄製需要 LiveKit Cloud 或自架[egress service](https://docs.livekit.io/transport/self-hosting/egress/), plus an output destination. The example below records the caller and agent into a single mixed OGG audio file in an S3 bucket. Set `RECORDINGS_S3_BUCKET`, `RECORDINGS_S3_REGION`, `RECORDINGS_S3_ACCESS_KEY`, and `RECORDINGS_S3_SECRET` on your server, alongside the LiveKit credentials.

安裝伺服器 SDK 以使用其輸出格式枚舉：

```bash npm2yarn
npm install livekit-server-sdk
```

在僅伺服器模組中定義錄製設定：

```typescript title="src/mastra/recording.ts"
import type { LiveKitRecordingOptions } from '@mastra/livekit'
import { EncodedFileType } from 'livekit-server-sdk'

export const recording: LiveKitRecordingOptions = {
  room: {
    audioOnly: true,
    fileOutputs: [
      {
        fileType: EncodedFileType.OGG,
        filepath: 'calls/{room_name}.ogg',
        output: {
          case: 's3',
          value: {
            bucket: process.env.RECORDINGS_S3_BUCKET!,
            region: process.env.RECORDINGS_S3_REGION!,
            accessKey: process.env.RECORDINGS_S3_ACCESS_KEY!,
            secret: process.env.RECORDINGS_S3_SECRET!,
          },
        },
      },
    ],
  },
}
```

`LiveKitRecordingOptions`接受用於建置 LiveKit 的設置`RoomEgress`, as either a plain object or an SDK instance. Set `room.audioOnly: true` for mixed audio, or use `tracks` or `participant` for separate recordings. Mastra passes these settings to LiveKit without choosing a format or storage provider for you. See [LiveKit output options](https://docs.livekit.io/transport/media/ingress-egress/egress/outputs/) for other destinations.

對於出站電話，請在新增電話參與者之前配置錄音：

```typescript title="src/start-call.ts"
import { randomUUID } from 'node:crypto'
import { dispatchVoiceSession } from '@mastra/livekit'
import { recording } from './mastra/recording'

const roomName = `support-call-${randomUUID()}`

await dispatchVoiceSession({
  roomName,
  metadata: { agentId: 'support', resourceId: 'caller-7' },
  recording,
})

// Add the phone participant to roomName through your existing LiveKit SIP code.
```

為每個錄製的會話使用新的房間名稱，並在撥號前等待調度。`dispatchVoiceSession()` throws `LiveKitRecordingRoomConflictError` if the room already exists. Import this error from `@mastra/livekit` to handle the conflict. The existence check and room creation are separate requests, so your application must prevent another process from creating the same room concurrently. This option doesn't start recording in an existing room or capture earlier audio.

對於瀏覽器會話，將相同的設定傳遞到連線路由：

```typescript title="src/mastra/index.ts"
import { Mastra } from '@mastra/core/mastra'
import { liveKitConnectionRoute } from '@mastra/livekit'
import { recording } from './recording'

export const mastra = new Mastra({
  server: {
    apiRoutes: [liveKitConnectionRoute({ recording })],
  },
})
```

啟用記錄後，路由會在瀏覽器加入之前建立房間並在請求連線詳細資料時調度Agent程式。回應依然`{ serverUrl, roomName, participantName, participantToken }`. Recording settings and storage credentials stay on the server and aren't included in the join token or agent metadata.

該路由也接受同步或非同步`recording` callback. It receives `{ body, context, roomName }`, including the resolved room name, so your server can choose settings for each session. Return `undefined` to skip recording for that request. Recording configuration isn't read directly from the request body.

現有錄音室在Agent程式排程或令牌頒發之前傳回 HTTP 409。其他房間創建和調度錯誤拒絕操作；該路由不會在失敗時發出令牌。如果建立房間後調度失敗，房間仍保留在 LiveKit 中。成功的設定並不能保證錄製完成或成功上傳。使用LiveKit的[egress events](https://docs.livekit.io/intro/basics/rooms-participants-tracks/webhooks-events/#webhook-events) to check completion and retrieve file details before making a recording available to users. To verify the setup, make a test call, end the room, and listen to the completed file under `calls/` in your bucket for audio from both participants.

#### 記錄生命週期和同意 {/* #recording-lifecycle-and-consent */}

啟用`recording` starts recording during room creation, before a browser connects or a phone participant joins. An abandoned connection request can still start the agent and consume recording and storage resources. Configure authentication and application limits on the connection route before exposing it to users.

`createConsentTool()`和`configuration.consentPolicy` don't control LiveKit egress. They don't delay, pause, or stop an automatic recording. If your application needs consent during the call before capturing audio, obtain it first and use LiveKit's explicit egress APIs to start recording in the existing room. A spoken greeting alone doesn't gate this feature.

錄音遵循 LiveKit 房間生命週期。僅斷開Agent的連線並不一定會結束房間或完成文件。在將記錄標記為就緒之前，等待成功的出口完成狀態和文件結果。將失敗的設置和廢棄的房間視為應用程式清理責任。

音訊檔案位於配置的輸出儲存中，與 Mastra 記憶體、轉錄本和軌跡分開。刪除 Mastra 執行緒不會刪除錄音。您的應用程式管理最終用戶的儲存存取、保留和下載連結。將儲存憑證保留在伺服器配置中，包括在選擇每個會話的錄製設定時。

### 在 Studio 中查看錄音 {/* #review-recordings-in-studio */}

登記`liveKitRecordingRoute()` to add **Review Audio** to a voice call's trace panel in Studio. The button opens an audio player for that call. Recording and trace storage must both be configured: the route reads the stored `voice call` span and passes its `roomName` to your server-side resolver. The browser supplies only the trace ID.

解析器返回`{ url, expiresAt? }`, or `undefined` when no file is available. Use a short-lived signed URL for private storage. The route doesn't persist playback URLs in traces, and Studio requests a fresh URL each time the review opens. Missing files and playback errors offer **Refresh recording** so you can retry after the upload finishes or a link expires.

對於上面的 S3 配置，使用相同的`calls/{room_name}.ogg` object key for recording and playback. Room names must remain unique across calls, including after a room has ended. Install the AWS SDK in your application:

```bash npm2yarn
npm install @aws-sdk/client-s3 @aws-sdk/s3-request-presigner
```

```typescript title="src/mastra/recording-playback.ts"
import {
  GetObjectCommand,
  HeadObjectCommand,
  S3Client,
  S3ServiceException,
} from '@aws-sdk/client-s3'
import { getSignedUrl } from '@aws-sdk/s3-request-presigner'
import { liveKitRecordingRoute } from '@mastra/livekit'
import { authorizeRecording } from './recording-access'

const s3 = new S3Client({
  region: process.env.RECORDINGS_S3_REGION!,
  credentials: {
    accessKeyId: process.env.RECORDINGS_S3_ACCESS_KEY!,
    secretAccessKey: process.env.RECORDINGS_S3_SECRET!,
  },
})

export const recordingReviewRoute = liveKitRecordingRoute({
  authorize: authorizeRecording,
  resolveRecording: async ({ roomName }) => {
    const object = {
      Bucket: process.env.RECORDINGS_S3_BUCKET!,
      Key: `calls/${roomName}.ogg`,
    }
    try {
      await s3.send(new HeadObjectCommand(object))
    } catch (error) {
      if (error instanceof S3ServiceException && error.$metadata.httpStatusCode === 404)
        return undefined
      throw error
    }
    const expiresIn = 15 * 60
    return {
      url: await getSignedUrl(
        s3,
        new GetObjectCommand({ ...object, ResponseContentType: 'audio/ogg' }),
        { expiresIn },
      ),
      expiresAt: new Date(Date.now() + expiresIn * 1000).toISOString(),
    }
  },
})
```

添加`recordingReviewRoute` to `server.apiRoutes` alongside `liveKitConnectionRoute({ recording })`. Keep the default path, `GET /voice/livekit/recordings/:traceId`, for Studio discovery. Both the connection route and server-initiated dispatch recordings can be reviewed, as long as the worker persisted the call trace and your resolver can locate its file.

審核路由預設需要身份驗證和顯式`authorize({ traceId, context })` callback. Implement the `authorizeRecording` helper in your application to check the authenticated user's access to the requested trace against your trusted ownership or tenant records. Return `true` only when access is allowed. Authentication alone doesn't establish recording ownership.

此路由拒絕註冊時缺少授權回調，包括何時`requiresAuth` is `false`. A denied request returns `403` before trace storage is read or a playback URL is generated. Policy errors also stop resolution. The resolver receives the stored `span` and request `context` only after authorization succeeds.

：：：警告

使用`requiresAuth: false` only for a local demo. It doesn't bypass the required recording authorization callback. If a demo policy allows all recordings, keep that policy explicitly limited to local development and replace it before deployment.

:::

僅錄製上傳權限並不授予播放存取權限。簽名憑證需要`s3:GetObject` for the recording objects, including the `HEAD` check. S3 also requires `s3:ListBucket` to return a missing-object `404` instead of `403`. Your application can use separate read credentials for playback. The browser receives a temporary URL that authorizes access to that file, so treat it as sensitive. See [S3 object permissions](https://docs.aws.amazon.com/AmazonS3/latest/API/API_HeadObject.html) and [presigned URLs](https://docs.aws.amazon.com/AmazonS3/latest/userguide/using-presigned-url.html).

`liveKitRecordingRoute()`是獨立於儲存的。您可以解析來自其他Provider的 URL 或由 LiveKit 完成事件填入的記錄索引。它不依賴 LiveKit 保留歷史出口作業。如果您使用帶有時間戳記的檔案名稱或變更儲存桶，請保留應用程式中從房間到物件的映射並解析該映射，而不是建置密鑰。

### 可觀察性 {/* #observability */}

當 Mastra 實例有[observability](/docs/observability/overview) configured, the worker traces each call. It opens one `voice call` span per session and nests everything under it:

* 每個回合的 Mastra Agent都會運行，包括模型生成、Tool呼叫和記憶體操作，就像文字聊天記錄它們一樣。
* 每個 LiveKit 管道指標的子跨度：語音到文字、文字轉語音、話語結束（轉彎偵測）、語音活動偵測和模型的首次標記時間。它們攜帶文字追蹤無法顯示的延遲和音訊測量值。
* 會話結束時寫入跨度的每個模型的使用匯總（整個呼叫的令牌、字元和音訊總計）。

工作執行緒是一個單獨的進程，因此將儲存體指向接受來自伺服器和工作執行緒的並發寫入的後端。 SQLite 支援[LibSQL](/integrations/databases/libsql) works. Single-writer stores don't. Traces, memory, and threads can share one store:

```typescript title="src/mastra/index.ts"
import { Mastra } from '@mastra/core/mastra'
import { LibSQLStore } from '@mastra/libsql'
import { Observability, MastraStorageExporter } from '@mastra/observability'

export const mastra = new Mastra({
  storage: new LibSQLStore({ id: 'voice-agent-storage', url: 'file:./voice-agent.db' }),
  observability: new Observability({
    configs: {
      default: {
        serviceName: 'voice-agent',
        exporters: [new MastraStorageExporter()],
      },
    },
  }),
})
```

預設情況下，追蹤處於開啟狀態。經過`observability: false` to `createLiveKitWorker` to turn it off.

從下列位置匯入瀏覽器用戶端幫助程序`@mastra/livekit/client`. Install `@mastra/client-js` 1.51.2 or newer within 1.x to use this entry point:

### 轉動指標和播放完成情況 {/* #turn-metrics-and-playback-completion */}

`createLiveKitWorker()`接受兩位觀察員來評估語音通話：

```typescript title="src/mastra/voice-worker.ts"
import { createLiveKitWorker } from '@mastra/livekit/worker'

export default createLiveKitWorker({
  mastra,
  agent: 'support',
  onTurnMetrics: metrics => {
    console.info('voice metric', metrics)
  },
  onSpeechComplete: speech => {
    console.info('speech outcome', speech.speechId, speech.outcome)
  },
})
```

觀察者異步運行，音頻管道不等待。記錄錯誤。讓他們的工作保持小規模。觀察者都不會寫入或協調記憶。

`onTurnMetrics`接收版本化記錄`phase: 'generation'` or `phase: 'speech'`. Generation records contain a `turnId`, a unique `attemptId`, a terminal `outcome`, `durationMs`, optional `firstTextMs`, and tool timings. Attempts for the same user message share its turn ID. Tool durations run from the bridge receiving a tool call to receiving its result; remote durations include transport and aren't pure server execution times. A tool without a result has no duration.

語音記錄還包含 LiveKit 的`speechId`. The bridge carries turn and attempt IDs in assistant message metadata so they can be joined after playback. Speech without a correlated assistant message, such as cancelled speech that produced no output, uses its speech ID as the turn ID and omits the attempt ID. Don't infer a correlation by matching event arrival order.

|測量|意義|
| - | - |
|一代`firstTextMs` | Time from starting generation to the first text forwarded toward speech synthesis. Can include filler. |
| Speech `firstAudioMs` | Time from caller speech ending to the first output audio, as reported by LiveKit. Can include filler. |
| Speech `completionMs` | Time from caller speech ending to completed output playback. Omitted for interrupted, cancelled, or failed speech. |
| `speechStartedAt` / `speechEndedAt` | Playback timestamps in Unix epoch milliseconds when available. |

缺少的測量值是`undefined`, not zero. Local generation durations use a monotonic clock. LiveKit's speech timing values are converted to milliseconds. When observability is configured, these records appear as events in the existing `voice call` trace. Pipeline metric events retain LiveKit's speech ID when supplied.

`onSpeechComplete`當語音句柄完成時，或會話因該語音待處理而關閉時執行一次。它提供語音指標以及可選的`playedText` and `transcriptSource`. Outcomes are `completed`, `interrupted`, `cancelled`, or `failed`. A completed speech lifecycle alone doesn't prove that audio was produced; check whether the relevant audio measurements are present.

測量源是`server-playout`. LiveKit's committed transcript can be partial or estimated, depending on the output's synchronization support. It doesn't prove that the remote browser or phone listener heard every word. `transcriptSource: 'unavailable'` means no committed assistant transcript was available.

繼續使用`onTurnComplete` for its existing generation contract. It can fire before speech playback finishes, with `interrupted: false`, even when the caller interrupts the audio later. Use `onSpeechComplete` for playback outcomes. Existing agent memory may already contain generated text; adding this hook doesn't change that persistence behavior.

對於您擁有的會話，請致電`observeVoiceSession(session, { onTurnMetrics, onSpeechComplete })` from `@mastra/livekit/worker` or `@mastra/livekit/plugin` before `session.start()`. Its return value detaches the observer and finalizes pending speech as cancelled. The worker attaches its observer automatically.

### 語音段邊界 {/* #speech-segment-boundaries */}

內建Agent、遠端和Workflow回復產生器保留文字段和Tool步驟邊界。Tool回饋在其文字排隊後被刷新，因此確認可以在Tool仍在運行時到達文字到語音。刷新請求段邊界；它不能保證來自每個語音Provider的即時音訊。

自訂生成器可以繼續傳回字串流。若要發出顯式邊界，請返回`ReadableStream<VoiceReplyChunk>` and enqueue `VOICE_TEXT_FLUSH`, both exported from `@mastra/livekit/worker` and `@mastra/livekit/plugin`. Consumers that read a reply generator directly must distinguish strings from boundary objects. Never concatenate a boundary object into a transcript.

工作人員將邊界轉換為 LiveKit 的邊界`FlushSentinel`. With the `MastraLLM` plugin, add the node adapter to the LiveKit agent you own:

```typescript
import { voice } from '@livekit/agents'
import { MastraLLM, mastraLLMNode } from '@mastra/livekit/plugin'

class SupportAgent extends voice.Agent {
  override llmNode(...args: Parameters<voice.Agent['llmNode']>) {
    return mastraLLMNode(this, ...args)
  }
}

const session = new voice.AgentSession({
  llm: new MastraLLM({ agent: supportAgent }),
  // Configure STT and TTS for your application.
})
await session.start({ agent: new SupportAgent({ instructions: 'Support assistant' }), room })
```

如果沒有適配器，插件仍然會發出文本，但 LiveKit 的預設節點不會將插件的邊界元資料轉換為刷新標記。使用`pipeAgentReplyToWriter()` in a workflow reply step to preserve the boundaries and tool results used for timing.

### 它是如何運作的 {/* #how-it-works */}

LiveKit 語音會話涉及三個部分：

1. 您的 Mastra 伺服器會產生一個 LiveKit 存取權杖並將您的Agent分派到一個房間。調度攜帶元數據，例如 Mastra Agent ID、內存線程和資源。
2. LiveKit Agent程式工作執行緒（一個單獨的長時間運行的程序）接收作業並執行音訊管道。音訊透過 WebRTC 在瀏覽器和工作器之間流動，並且永遠不會通過您的 Mastra HTTP 伺服器。
3. 每次用戶完成一輪時，工作人員都會致電 Mastra Agent的電話`stream()` with the new input and speaks the streamed text. When the user interrupts, LiveKit cancels the stream and Mastra stops generating.

對話歷史記錄儲存在 Mastra Memory 中，因此語音會話和文字聊天可以共用一個執行緒。

### 檢查VAD和轉彎檢測 {/* #check-vad-and-turn-detection */}

`vad: false`現在在會話創建時禁用 VAD。之前，worker 跳过了插件预热但通过了`undefined` to LiveKit, which could enable its bundled VAD. If an application relied on that behavior, configure a detector explicitly.

```typescript title="src/mastra/voice-worker.ts"
import { createLiveKitWorker } from '@mastra/livekit/worker'
import { mastra } from './index'

export default createLiveKitWorker({
  mastra,
  agent: 'support',
  vad: false,
  turnDetection: 'manual',
})
```

預設情況下，預熱期間仍會載入 Silero 插件。這`'english'` and `'multilingual'` turn detection options still select their existing text models. LiveKit's newer `inference.VAD` and `inference.TurnDetector` APIs are available through the existing instance and resolver options; switching to them is a separate choice that can change endpointing, model downloads, and cloud usage.

### 查看自訂 LiveKit Tool {/* #review-custom-livekit-tools */}

Mastra Tool繼續透過 Mastra Agent程式運作。如果您也實作了 LiveKit Tool或自訂 LiveKit 插件，請考慮自 Agents 1.4 以來的變更：

* `ToolContext`是一個類別。使用它的存取器和`flatten()` instead of enumerating or mutating it as a plain object.
* 支援命名Tool清單和重複名稱檢查。仍然支援匿名Tool的物件簡寫；不需要轉換每個Tool圖。
* ProviderTool使用的子類`ProviderTool` instead of the older `ProviderDefinedTool` API.

請參閱[LiveKit tool API](https://github.com/livekit/agents-js/blob/main/agents/src/llm/tool_context.ts) for custom plugin migration details.

### 審查關閉 {/* #review-shutdown */}

這`onCallEnd` hook still uses LiveKit's job shutdown callbacks. Keep cleanup within the configured shutdown window, and verify that it completes when a caller disconnects or a worker receives a shutdown signal.

### 驗證錄音和通話 {/* #verify-recordings-and-calls */}

集成的房間級別`recording` configuration and S3 permissions stay the same. LiveKit Agents' `AgentSession.start({ record })` controls separate session recording and telemetry. Disabling one doesn't disable the other.

在推廣預發布之前，請先透過設定的 SIP 中繼測試瀏覽器通話和電話通話。驗證發言者、中斷、Tool、問候和同意行為、掛斷、已完成的追蹤以及`onCallEnd`. When recording is enabled, wait for the S3 object and play it with **Review Audio**. Also test recording disabled and rejection of an existing room name. Run these checks on the deployment image with its model files and native libraries installed.

## API參考 {/* #api-reference */}

這`@mastra/livekit` package connects Mastra agents to the LiveKit Agents framework. LiveKit runs the audio pipeline (voice activity detection, speech-to-text, turn detection, text-to-speech, barge-in) and the package bridges reply generation to a Mastra agent's `stream()` call.

看[Realtime voice](#quickstart) for setup and concepts.

該包有三個入口點：

* `@mastra/livekit`：伺服器端API，[`liveKitConnectionRoute()`](#livekitconnectionroute), [`dispatchVoiceSession()`](#dispatchvoicesession), [`pipeAgentReplyToWriter()`](#pipeagentreplytowriter), [`serializeSessionMetadata()`](#livekitsessionmetadata), and [`createEndCallTool()`](#createendcalltool). Import these from Mastra server code. This entry never loads the LiveKit agents runtime.
* `@mastra/livekit/worker`：工人運作時，[`createLiveKitWorker()`](#createlivekitworker), [`runLiveKitWorker()`](#runlivekitworker), [`chatContextToMessages()`](#chatcontexttomessages), the per-session agent class [`MastraVoiceAgent`](#mastravoiceagent), and the session helpers [`speakGreeting()`](#speakgreeting), [`waitForAgentDoneSpeaking()`](#waitforagentdonespeaking), and [`runEndCall()`](#runendcall). Import it only from the worker entry file.
* `@mastra/livekit/plugin`：LLM元件插件，[`MastraLLM`](#mastrallm) and [`createRemoteAgentReplyGenerator()`](#createremoteagentreplygenerator). Import it in workers that build their own `voice.AgentSession`. `createRemoteAgentReplyGenerator()` is also exported from `@mastra/livekit/worker` because it plugs into `createLiveKitWorker()`'s `generate` option. `MastraLLM` is plugin-only.

### `MastraVoiceAgent` {/* #mastravoiceagent */}

現場Tool包`voice.Agent` subclass that [`createLiveKitWorker()`](#createlivekitworker) builds for every session. Replies come from a Mastra agent (or a custom `generate` source) through the agent's `llmNode`; LiveKit keeps the audio loop, turn detection, and barge-in. Construct it yourself when you own the `voice.AgentSession`, for example to test a Mastra-backed agent with `@livekit/agents`' `voice.testing` harness without speech-to-text, text-to-speech, or a live worker. `createMastraVoiceAgent(options)` is an equivalent factory.

```typescript title="src/mastra/voice-agent.test.ts"
import { initializeLogger, voice } from '@livekit/agents'
import { MastraVoiceAgent } from '@mastra/livekit/worker'
import { supportAgent } from './agents/support'

// Required outside a LiveKit worker: AgentSession needs the LiveKit logger initialized.
initializeLogger({ level: 'silent', pretty: false })

const session = new voice.AgentSession()
await session.start({ agent: new MastraVoiceAgent({ agent: supportAgent, memory: false }) })

// run() returns a RunResult, not a promise; wait() resolves when the turn completes.
const result = session.run({ userInput: 'What are your opening hours?' })
await result.wait()
result.expect.nextEvent().isMessage({ role: 'assistant' })
result.expect.noMoreEvents()
```

Agent帶有自己的佔位符`llm.LLM` so LiveKit runs the reply pipeline; generation always goes through `llmNode`, so a `FakeLLM` in the session's `llm` slot is ignored and calling the placeholder's `chat()` throws. To stub the model in tests, give the Mastra agent a mock model or pass a custom `generate` function.

### `MastraLLM` {/* #mastrallm */}

一個標準的 LiveKit LLM 外掛程式（`llm.LLM`) backed by a Mastra agent. Use it when you build the `voice.AgentSession` yourself and want Mastra in the `llm` slot. [`createLiveKitWorker()`](#createlivekitworker) is the managed alternative. See [Use Mastra as the LLM component](#use-mastra-as-the-llm-component) for how to choose.

和`remote`, the plugin streams each turn from your Mastra server over HTTP using Server-Sent Events (SSE). The agent loop, tools, and memory run server-side, and interrupting the agent aborts the server-side generation.

```typescript title="src/mastra/voice-worker-plugin.ts"
import { voice } from '@livekit/agents'
import { MastraLLM } from '@mastra/livekit/plugin'

const session = new voice.AgentSession({
  llm: new MastraLLM({
    remote: { baseUrl: process.env.MASTRA_URL!, agentId: 'support' },
    memory: { thread: callId, resource: userId },
  }),
  stt: 'deepgram/nova-3',
  tts: 'cartesia/sonic-3',
  // Required with `memory` unless memory.options.readOnly is set: LiveKit enables
  // preemptive generation by default.
  turnHandling: { preemptiveGeneration: { enabled: false } },
})
```

插件報告`provider` as `mastra` and `model` as the agent id, so LiveKit metrics and fallback adapters identify it like any other LLM.

#### 在 Mastra Agent上運行的Tool {/* #tools-run-on-the-mastra-agent */}

Tool在 Mastra Agent的伺服器端定義和執行。該外掛程式從不轉送 LiveKit Tool定義：如果會話傳遞非空`toolCtx`, it logs a one-time warning naming the ignored tools. Every tool must complete server-side: a tool that requires approval or client-side execution fails the turn with a descriptive error instead of hanging the call.

Tool活動透過以下方式到達工人`toolFeedback`, `onToolCall`, and `onTurnComplete`.

#### 指示 {/* #instructions */}

LiveKit 注入你的`voice.Agent`'s `instructions` into the chat context of every request. The plugin drops them because the server-side Mastra agent's own instructions are authoritative. To change the prompt, change the Mastra agent.

#### 轉彎中斷 {/* #interrupted-turns */}

當用戶打斷回覆時：

1. 該插件取消串流。伺服器中止產生並且從該回合開始不保留任何內容。
2. LiveKit 記錄使用者在聊天情境中實際聽到的部分，並標記為中斷。
3. 在下一輪，插件會重新發送僅聽的片段，在新用戶訊息之前排序，因此記憶體線程會回填以匹配呼叫。訊息攜帶 LiveKit 的訊息 id，伺服器透過 id 進行重複資料刪除，因此重試和重新發送保持冪等性。

如果使用者在打斷後立即掛斷，則最後的片段不會被記錄。當抄本必須捕獲它時，立即從會話事件中進行協調；共享訊息 id 意味著下一輪重新發送 upsert，而不是重複：

```typescript title="src/mastra/voice-worker-plugin.ts"
import { voice } from '@livekit/agents'
import { MastraClient } from '@mastra/client-js'

const client = new MastraClient({ baseUrl: process.env.MASTRA_URL! })

session.on(voice.AgentSessionEventTypes.ConversationItemAdded, ({ item }) => {
  if (item.type !== 'message' || item.role !== 'assistant' || !item.interrupted) return
  void client.saveMessageToMemory({
    agentId: 'support',
    messages: [
      {
        id: item.id,
        threadId: callId,
        resourceId: userId,
        role: 'assistant',
        content: item.textContent ?? '',
        type: 'text',
        createdAt: new Date(),
      },
    ],
  })
})
```

#### 使用指標 {/* #usage-metrics */}

當伺服器報告一輪的令牌使用情況時，插件會將其提供給 LiveKit，因此會話的`metrics_collected` events carry time-to-first-token, duration, and token counts like any LLM plugin. The same usage object (`promptTokens`, `completionTokens`, `promptCachedTokens`, `totalTokens`) arrives on `onTurnComplete` as `result.usage`.

#### 錯誤和超時 {/* #errors-and-timeouts */}

傳輸拋出 LiveKit 的`APIError` types (`APIStatusError`, `APIConnectionError`, `APITimeoutError`), so the session's retry policy (`connOptions.maxRetry`) and `FallbackAdapter` failover work unchanged. A turn is never retried after its first token: a voice reply is better failed fast than replayed half-heard.

`connOptions.timeoutMs` (10 seconds by default), so a server that accepts the connection but never streams can't cause indefinite dead air.

如果 Mastra 伺服器在呼叫中發生故障，每次回覆嘗試都會失敗，並在重試後出現鍵入錯誤，並且 LiveKit 在多次連續失敗回復後關閉會話。在預算用完之前恢復伺服器並且呼叫在下一輪恢復。

#### 留言內容 {/* #message-content */}

訊息提取僅包含文字：圖像內容被刪除，音訊內容僅透過其文字記錄包含在內。語音管道不受影響，但您自己注入聊天上下文的項目必須攜帶文字。

### `createRemoteAgentReplyGenerator()` {/* #createremoteagentreplygenerator */}

建立一個回復產生器，在 a 上運行Agent循環**remote** Mastra server over HTTP/SSE. `MastraLLM`'s `remote` mode uses it internally. Use it directly through `createLiveKitWorker`'s `generate` option to run the batteries-included worker against a remote server:

```typescript title="src/mastra/voice-worker.ts"
import { createLiveKitWorker, createRemoteAgentReplyGenerator } from '@mastra/livekit/worker'
import { mastra } from './index'

export default createLiveKitWorker({
  mastra, // local instance for logger and worker config; replies come from the remote server
  generate: createRemoteAgentReplyGenerator({
    baseUrl: process.env.MASTRA_URL!,
    agentId: 'support',
  }),
  memory: ({ metadata, roomName }) => ({ thread: metadata.threadId ?? roomName }),
  stt: 'deepgram/nova-3',
  tts: 'cartesia/sonic-3',
})
```

上`generate` path the worker-level `toolFeedback` and `onTurnComplete` options don't apply, and the worker's end-call detection doesn't fire; pass the hooks to the generator instead.

取消轉向（打斷）會破壞 HTTP 請求，從而中止伺服器上的產生。錯誤作為 LiveKit 拋出`APIError` types. The `retries` option applies only to initial connection attempts. A turn is never retried after its first chunk.

返回：`VoiceReplyGenerator`.

### `waitForAgentDoneSpeaking()` {/* #waitforagentdonespeaking */}

一旦Agent不再產生或播放回复，則解決：其狀態已離開`thinking` and `speaking`. Resolves immediately when the agent is already idle, and always resolves within `maxWaitMs` (30 seconds by default) as a safety cap. Use it before tearing a session down so closing words play out instead of being cut off.

```typescript
import { waitForAgentDoneSpeaking } from '@mastra/livekit/worker'

await waitForAgentDoneSpeaking(session)
```

### `runEndCall()` {/* #runendcall */}

在客服人員要求掛斷電話後結束通話。它等待Agent的結束語並說出可選的最後一句話`message` without interruption. It then deletes the room and hangs up the caller, including SIP callers. The job shuts down with its registered callbacks.

與它配對[`MastraLLM`](#mastrallm)'s `onToolCall` and an [end-call tool](#createendcalltool) on the server-side agent to rebuild agent-initiated hang-up on a session you own:

```typescript title="src/mastra/voice-worker-plugin.ts"
import { MastraLLM } from '@mastra/livekit/plugin'
import { DEFAULT_END_CALL_TOOL, runEndCall } from '@mastra/livekit/worker'

let ending = false

const llm = new MastraLLM({
  remote: { baseUrl: process.env.MASTRA_URL!, agentId: 'support' },
  onToolCall: ({ toolName }) => {
    if (toolName !== DEFAULT_END_CALL_TOOL || ending) return
    ending = true
    void runEndCall(session, ctx, {}, console)
  },
})
```

導出的常數`DEFAULT_END_CALL_TOOL` (`'endCall'`), `DEFAULT_END_CALL_REASON`, and `DEFAULT_END_CALL_MAX_WAIT_MS` (30000) hold the defaults.

### `createEndCallTool()` {/* #createendcalltool */}

建置Agent程式在想要結束呼叫時呼叫的 Mastra Tool。該Tool發出意圖並可以運行可選的簿記。工作人員執行實際的掛斷操作。該Tool位於伺服器安全的根條目上。將其新增至伺服器程式碼中定義的Agent程式。

```typescript title="src/mastra/agents/support-agent.ts"
import { Agent } from '@mastra/core/agent'
import { createEndCallTool } from '@mastra/livekit'

const supportAgent = new Agent({
  id: 'support',
  name: 'Support',
  instructions:
    'Help the caller. When everything is wrapped up, say goodbye and call endCall as your final action.',
  model: '__GATEWAY_OPENAI_MODEL_LUNA__',
  tools: { endCall: createEndCallTool() },
})
```

和`createLiveKitWorker()`, set `configuration: { endCall: {} }` and the worker watches for the tool and hangs up. On a session you own, rebuild the hang-up with [`runEndCall()`](#runendcall).
