# GitHub

在 Mastra 中，可以透過兩種方式使用 GitHub：

- **Agent Tool** 讓 Agent 透過 [Mastra Connect](/docs/mastra-platform/connect) 操作儲存庫、議題、Pull Request、發行版本及工作流程執行記錄。
- **[Pull Request 訊號](#pull-request-signals)**讓 Agent 追蹤 Pull Request（PR），並在 PR 有變更時做出回應。

## 連線設定 {/* #connect */}

開始前，請依照 [Connect 設定步驟](/docs/mastra-platform/connect#get-started) 安裝 `@mastra/connect`，並設定 Mastra 平台上的專案。Connect 會將 GitHub 憑證保存在 Mastra 平台上，應用程式本身不會儲存這些憑證。

## Pull Request 訊號 {/* #pull-request-signals */}

`@mastra/github-signals` Provider 會輪詢已訂閱的 PR，並在有相關活動時，向 Agent 的對話執行緒傳送[通知訊號](/docs/signals/notifications)。Provider 在你自己的基礎架構上執行，透過 GitHub CLI 存取 GitHub，無須使用 Connect 連線。

### 安裝 {/* #installation */}

安裝 GitHub Signals，以及本範例用於記憶功能的套件：

```bash npm2yarn
npm install @mastra/github-signals @mastra/libsql @mastra/memory
```

### 必要條件 {/* #prerequisites */}

使用 GitHub Signals 須符合下列條件：

- 使用支援記憶及通知功能的 Mastra 儲存介面卡。Provider 會將訂閱儲存在對話執行緒的中繼資料中，因此要先建立該執行緒。
- `PATH` 上可執行 `gitcrawl`，且已設定好要監控的儲存庫存取權。Provider 會執行 `gitcrawl sync` 並讀取其 SQLite 資料庫。
- `PATH` 上可執行 `sqlite3`。
- 已安裝 [GitHub CLI](https://cli.github.com/) 並完成驗證。Provider 會根據 `gh api` 實際傳回的結果檢查儲存庫權限及 GitHub App 的擁有者，再決定是否通知 Agent。

預設情況下，具有 `admin`、`maintain` 或 `write` 權限的使用者所留下的留言可以觸發通知。CodeRabbit 和 Devin 機器人的留言也明確獲准觸發通知。

檢查機器人授權時，Provider 會先比對 `ignoredBots`。登入名稱必須完全相符，比對時不區分大小寫。未列入忽略清單的機器人只要符合其中一項條件，就可以觸發通知：機器人列在 `authorizedBots` 中；GitHub App 由使用者擁有，且該使用者在儲存庫中的權限列在 `authorizedPermissions` 中；或 GitHub App 與儲存庫由同一個組織擁有。預設允許的權限為 `admin`、`maintain` 和 `write`。

查詢 GitHub App 擁有者時，若查詢失敗、資訊無法存取、回應格式有誤或查詢不受支援，Provider 就會拒絕機器人的留言。查詢成功的結果會快取 24 小時，失敗的結果不會快取。

### Agent 與訂閱 {/* #agent-and-subscription */}

建立一個 `GithubSignals` 執行個體，並註冊到 Agent。接著將 Agent 和儲存介面卡註冊到 Mastra 執行個體：

```typescript title="src/mastra/index.ts"
import { Agent } from '@mastra/core/agent'
import { Mastra } from '@mastra/core/mastra'
import { Memory } from '@mastra/memory'
import { GithubSignals } from '@mastra/github-signals'
import { LibSQLStore } from '@mastra/libsql'

export const githubSignals = new GithubSignals()

export const devAgent = new Agent({
  id: 'dev-agent',
  name: 'Development Agent',
  instructions: 'Triage pull request activity and help resolve issues.',
  model: '__GATEWAY_OPENAI_MODEL__',
  memory: new Memory(),
  signals: [githubSignals],
})

export const mastra = new Mastra({
  agents: { devAgent },
  storage: new LibSQLStore({
    id: 'mastra-storage',
    url: 'file:./mastra.db',
  }),
})
```

Agent 建立記憶功能的對話執行緒後，就能讓該執行緒訂閱 PR。如果只需要追蹤程式碼修訂、有權限的作者所留的最新 PR 留言，以及可偵測到的審查討論狀態變更，請選擇 `review` 模式：

```typescript
await githubSignals.subscribeThreadToPR({
  threadId: 'thread-123',
  resourceId: 'user-123',
  pr: {
    owner: 'acme',
    repo: 'web-app',
    number: 42,
  },
  mode: 'review',
})
```

Provider 會立即同步 PR、儲存訂閱，並開始每五分鐘輪詢一次。若要調整間隔，可在 `GithubSignals` 的建構函式中設定 `pollIntervalMs`。程序重新啟動後，請對每一筆已持久保存的執行緒訂閱呼叫 `startPollingForThread()`，以恢復輪詢。

每個對話執行緒同時只能有一筆 GitHub Signals 訂閱。讓同一執行緒訂閱另一個 PR 時，會取代原有的訂閱。

### 訂閱模式 {/* #subscription-modes */}

GitHub Signals 支援兩種訂閱模式：

- `review`：追蹤 PR 來源分支最新提交的變更、有權限的作者所留的最新 PR 留言，以及可偵測到的審查討論狀態變更，包括所有審查討論都已解決的情況。
- `working`：追蹤 Provider 可偵測且能觸發通知的所有 PR 活動。包含留言的通知仍須通過既有的授權檢查。未指定 `mode`，或已儲存的訂閱沒有有效模式時，會採用此預設模式。

下表列出兩種模式如何處理各類 PR 活動：

| Pull Request 活動 | `working` | `review` |
| - | - | - |
| 首次取得 PR 狀態 | 傳送初始狀態通知 | 儲存所有游標，不傳送通知。若 PR 已關閉或合併，則傳送通知並移除訂閱 |
| 新增提交或強制推送 | 最新留言的作者有權限時傳送通知 | 即使沒有留言作者也會傳送通知 |
| 最新 PR 留言有更新，且作者有權限 | 傳送通知 | 傳送通知 |
| 偵測到審查討論狀態變更 | 仍有未解決的討論時傳送通知 | 傳送通知，包括所有審查討論都已解決時 |
| 持續整合檢查開始、失敗或恢復 | 傳送通知 | 儲存新狀態，不傳送通知 |
| 發生或解決合併衝突 | 傳送通知 | 儲存新狀態，不傳送通知 |
| 其他可觸發通知的 PR 整體狀態變更 | 通過適用的授權檢查後傳送通知 | 儲存新狀態，不傳送通知 |
| PR 未合併即關閉 | 傳送通知並保留訂閱 | 傳送通知並移除訂閱 |
| PR 重新開啟 | 傳送通知 | 不傳送通知，因為 PR 關閉時已移除訂閱 |
| PR 合併 | 傳送通知並移除訂閱 | 傳送通知並移除訂閱 |

審查模式會使用 `gitcrawl` 提供的最新 PR 留言。快照不會區分 PR 的一般討論與針對特定程式碼行的審查留言。留言通知會附上留言內容，因此作者必須有權限。審查狀態通知只包含 Provider 產生的狀態摘要，不查核作者權限。

審查狀態游標會記錄未解決的審查討論串數量，以及其中最新一筆討論串的時間戳記。數量降到零時會回報這項變更，但無法回報已解決討論串中的新回覆。

若在訂閱當下已知 PR 已關閉或合併，Provider 不會保存訂閱，也不會傳送活動通知。其他情況下，審查模式會儲存第一份可用且顯示 PR 仍開啟的快照，不傳送通知。即使訂閱當下取得快照失敗，直到後續輪詢才首次取得快照，也適用同一規則。若第一份可用的輪詢快照或之後的快照顯示 PR 已關閉或合併，Provider 會傳送結束通知並移除訂閱。PR 之後若重新開啟，必須再次訂閱才能繼續追蹤。

### 訂閱 Tool {/* #subscription-tools */}

Provider 會為 Agent 新增 `github_subscribe_pr` 和 `github_unsubscribe_pr` 兩個 Tool。訂閱時可傳入 `mode`：

```json
{
  "owner": "acme",
  "repo": "web-app",
  "number": 42,
  "mode": "review"
}
```

省略 `mode` 時會使用 `working` 模式。若只是要查看一次 PR，無須訂閱。

### MastraCode 指令 {/* #mastracode-commands */}

在 MastraCode 中，可以用 PR 編號、`owner/repo#number` 或完整的 GitHub PR 網址指定 PR。`--mode` 選項與其值之間須以空格分隔：

```text
/github subscribe 42 --mode review
/github acme/web-app#42 --mode working
/github unsubscribe 42
/github debug
```

MastraCode 不接受 `--mode=review` 這種寫法，也不接受省略模式值、重複指定模式值或無法辨識的模式。取消訂閱時不能帶入模式選項。`/github debug` 會顯示已儲存的模式，舊版訂閱若缺少模式值或模式值無效，則顯示為 `working`。
