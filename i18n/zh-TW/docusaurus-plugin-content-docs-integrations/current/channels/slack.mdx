# 鬆弛

以兩種方式將 Slack 與 Mastra 結合使用：

* **AgentTool**讓Agent程式在 Slack 中執行操作，例如讀取對話或傳送訊息。
* **Agent聊天**讓人們可以在 Slack 頻道線程或直接訊息中向您的Agent程式發送訊息。 Mastra 為每個訊息運行Agent，並將回應串流傳回 Slack。 Slack 轉接器為您處理 Slack AI 指示器和互動式卡片。

[馬斯特拉連接](/docs/mastra-platform/connect)在 Mastra 平台上設定並保留 Slack 憑證。對於Agent聊天，您還可以建立和管理自己的 Slack 應用程式。

## 連接 {/* #connect */}

在開始之前，請完成[Connect setup](/docs/mastra-platform/connect#get-started) to install `@mastra/connect` and configure your platform project.

Slack Tool和 Slack 聊天使用具有不同憑證的單獨連接，因此一個連接無法同時服務這兩個連接：

* `slack`授權AgentTool的Workspace。
* `slack-channels`儲存用於Agent聊天的應用程式配置令牌。

若要同時使用兩者，請新增兩個連接。

### Agent聊天 {/* #agent-chat */}

Slack 聊天使用應用程式設定令牌，讓 Mastra 為每個客服人員建立一個 Slack 應用程式。 Mastra 創建並管理這些應用程式。它不使用您自己創建的 Slack 應用程序，例如來自[self-managed setup](#self-managed-setup).

您的伺服器需要 Slack 可以存取的公共 URL 以進行 Webhook 傳遞和 OAuth 回呼。 Mastra 平台提供此 URL。當您在其他地方託管時，請設定`MASTRA_SERVER_URL` to your public server URL. For local development, use a public HTTPS tunnel.

1. 打開[Slack apps](https://api.slack.com/apps), then open **Your App Configuration Tokens**.

2. 為將運行Agent程式的Workspace產生應用程式配置令牌。

3. 跑步`mastra connect add slack-channels` and complete the authorization flow. The platform stores and rotates the configuration credential.

4. 經過[`channels()`](/reference/connect/channels) to the `Mastra` constructor. It registers the Slack channel provider and its routes:

   ```typescript title="src/mastra/index.ts"
   import { Mastra } from '@mastra/core'
   import { channels } from '@mastra/connect'
   import { assistant } from './agents/assistant'

   export const mastra = new Mastra({
     agents: { assistant },
     channels: await channels({ providers: ['slack'] }),
   })
   ```

   這`slack` key in `channels()` refers to the `slack-channels` connection.

5. 啟動您的 Mastra 申請。

6. 在 Studio 中，將 Slack 通道連接到Agent程式。 Mastra 建立一個 Slack 應用程式並傳回一個授權 URL。打開它，選擇Workspace，然後批准機器人範圍。

這[default Slack manifest](/reference/channels/slack-provider#default-manifest) lists the requested scopes and event subscriptions.

## 自我管理設定 {/* #self-managed-setup */}

自己建立一個 Slack 應用程式並將其憑證儲存在您的 Mastra 環境中。當您想要直接控制 Slack 應用程式時，請使用此路徑進行Agent聊天。

### 安裝 {/* #installation */}

從 Chat SDK 安裝 Slack 轉接器：

```bash npm2yarn
npm install @chat-adapter/slack
```

添加`createSlackAdapter()` to the agent's `channels.adapters` object:

```typescript title="src/mastra/agents/your-agent.ts"
import { Agent } from '@mastra/core/agent'
import { createSlackAdapter } from '@chat-adapter/slack'

export const yourAgent = new Agent({
  id: 'your-agent',
  name: 'Your Agent',
  instructions: 'Help people plan tasks, answer questions, and coordinate work in Slack.',
  model: '__GATEWAY_ANTHROPIC_MODEL_OPUS__',
  channels: {
    adapters: {
      slack: createSlackAdapter(),
    },
  },
})
```

### 創建 Slack 應用程式 {/* #create-a-slack-app */}

要連接您的Agent，請在您希望運行它的Workspace中建立一個 Slack 應用程式。 Slack 應用程式控制Agent程式在 Slack 中的顯示、其功能以及其接收的事件。

本指南使用[manifest](https://docs.slack.dev/app-manifests/configuring-apps-with-app-manifests/#creating_manifests): a configuration file that creates the Slack app settings for you. This is the fastest path when you are adding your agent to your own workspace. It doesn't cover the platform OAuth flow where other workspaces install your agent.

從清單建立 Slack 應用程式：

1. 打開[api.slack.com/apps](https://api.slack.com/apps).
2. 選擇**Create an app**.
3. 選擇**From a manifest**.
4. 選擇Agent應運行的Workspace。
5. 貼上此清單，然後選擇**Create**. Slack accepts JSON or YAML, so use whichever tab matches the format shown in the app creation modal:

此清單配置：

* `display_information.name`和`features.bot_user.display_name`: Set your agent's name in Slack. You can update it at any time. Remember to reinstall the app after changing names or permissions.
* `app_home.messages_tab_enabled`和`app_home.messages_tab_read_only_enabled`: Enable direct messages from the Slack app's **Messages** tab.
* `always_online`：顯示 Slack 機器人使用者始終可用。
* `oauth_config.scopes.bot`：授予在機器人所在的頻道中發布和閱讀訊息的權限。它還涵蓋提及和直接訊息以及用戶查找。
* `event_subscriptions`
* `interactivity`：啟用互動式卡片並告訴 Slack 將卡片操作傳送到哪裡。

創建應用程式後，打開**Install App**, select **Install to Workspace**, and approve the requested scopes.

### 設定 Slack 憑證 {/* #set-slack-credentials */}

在 Mastra 中設定 Slack 憑證，以便它可以驗證 Slack 請求並將訊息傳回 Slack。

在 Slack 應用程式設定中，複製以下值：

* **基本訊息** > **App Credentials** > **Signing Secret**
* **OAuth 和權限** > **Bot User OAuth Token**

將它們設定在您的 Mastra 環境中：

```bash title=".env"
SLACK_SIGNING_SECRET=your-signing-secret
SLACK_BOT_TOKEN=xoxb-your-bot-token
```

Mastra 自動讀取這些環境變數。

### 配置 webhook 路由 {/* #configure-the-webhook-route */}

Slack 透過 webhooks 將通道活動傳送到 Mastra。 Webhook 是發生某事（例如新訊息、提及或使用者選擇互動式卡片）時 Slack 呼叫的 HTTP 端點。

Mastra 會自動為您的Agent註冊 Slack webhook 路由：

```text
/api/agents/<YOUR-AGENT-ID>/channels/slack/webhook
```

從公用 Mastra 伺服器 URL 和產生的路由建立 webhook URL：

```text
https://<YOUR-PUBLIC-URL>/api/agents/<YOUR-AGENT-ID>/channels/slack/webhook
```

Slack 無法將事件傳送至`localhost`. For local development, keep the Mastra dev server running and expose `http://localhost:4111` with a tunnel before you save the request URL in Slack.

使用隧道，例如`cloudflared` or `ngrok` for local development:

```bash npm2yarn
npx cloudflared tunnel --url http://localhost:4111
```

使用產生的隧道主機作為`<YOUR-PUBLIC-URL>`, for example:

```text
https://abc123.trycloudflare.com/api/agents/your-agent/channels/slack/webhook
```

更新 Slack 中的請求 URL：

1. 在 Slack 應用程式設定中，打開**Event Subscriptions**.
2. 代替**Request URL** with the final webhook URL.
3. 選擇**Save Changes**.
4. 打開**Interactivity & Shortcuts**.
5. 代替**Request URL** with the same webhook URL.
6. 選擇**Save Changes**.
7. 如果 Slack 要求您重新安裝應用程式，請打開**OAuth & Permissions** and select **Reinstall to Workspace**.

### 在 Slack 中嘗試一下 {/* #try-it-in-slack */}

打開與 Slack 機器人用戶的直接訊息並發送訊息。直接訊息之所以有效，是因為清單包含`message.im` event and `im:*` scopes.

若要在頻道中使用Agent，請先邀請 Slack 機器人使用者：

```text
/invite @your-bot-name
```

在頻道中提及機器人：

```text
@your-bot-name What can you help me with?
```

Agent在線程中做出回應。回應內容取決於Agent上配置的模型、指令、記憶體和Tool。

## 驗證 {/* #authentication */}

Slack 適配器沒有內建使用者允許清單。安裝應用程式後，Workspace中的任何人都可以透過向Agent程式發送直接訊息或在其成員的頻道中提及它來與Agent程式交談。 Slack 使用簽署金鑰驗證每個要求，Mastra 為 Webhook 收到的每個有效訊息運行Agent程式。

控制存取的主要機制是通道成員資格。機器人僅接收來自直接訊息和它被邀請加入的頻道的事件，因此機器人所屬的頻道集定義了誰可以存取它。讓機器人遠離不應回應的頻道，並將其從頻道中刪除以切斷訪問。

為了更好地控制，請對寄件者的身分進行控制。每個請求都攜帶發送者在通道中的 Slack 使用者 ID[request context](#request-context), so you can allow or deny specific users in an input processor or tool before the agent acts.

### 伺服器認證 {/* #server-authentication */}

Slack webhook 路由不受 Mastra 的約束[server authentication](/docs/auth/overview). Slack can't send a bearer token, so Mastra registers the channel webhook as a public route and verifies each request with the Slack signing secret instead. This holds even when you enable a provider like [`MastraAuthSimple`](/docs/auth/simple-auth): the rest of your API stays protected, but the webhook route relies on the signing secret rather than your server auth. With the self-managed setup, keep `SLACK_SIGNING_SECRET` set so the adapter can reject requests that Slack didn't sign.

### 外部管道 {/* #external-channels */}

共享頻道（[Slack Connect](https://slack.com/connect)) let people from other workspaces join a conversation. If a workspace member adds the bot to a shared channel, everyone in that channel can talk to the agent, including external members outside your organization. Anyone who can reach the agent can also reach the tools and data it has access to.

將機器人新增至共用或外部通道視為授予這些參與者對Agent的存取權限。在此之前，請確認Agent程式的Tool和資料可以安全地向外部成員公開，並在需要限制Agent程式的回應對象時控制寄件者的使用者 ID。

## 請求上下文 {/* #request-context */}

對於每條訊息，Mastra 都會在[request context](/docs/server/request-context) under the `channel` key. It carries the sender's Slack display name and user ID, the bot's own identity, and details about where the message came from. Read it from an input processor or a tool to identify the user or branch on the conversation type:

```typescript title="src/mastra/tools/whoami.ts"
import { createTool } from '@mastra/core/tools'
import type { ChannelContext } from '@mastra/core/channels'
import { z } from 'zod'

export const whoami = createTool({
  id: 'whoami',
  description: 'Return the Slack identity of the current user',
  inputSchema: z.object({}),
  execute: async (_input, context) => {
    const channel = context?.requestContext?.get('channel') as ChannelContext | undefined

    return {
      platform: channel?.platform,
      userId: channel?.userId,
      userName: channel?.userName,
      isDM: channel?.isDM,
    }
  },
})
```

通道上下文包括：

* `botMention`, `botUserId`, and `botUserName`: The bot's own identity on Slack.
* `channelId`和`threadId`: The Slack channel and thread the message arrived on.
* `isDM`：訊息是否為私訊。
* `platform`：平台標識符，`slack` for this adapter.
* `userId`和`userName`: The sender's Slack user ID and display name.

Mastra 也將此上下文轉換為簡短的系統訊息。Agent商了解平台和自己的身份，以及對話是直接訊息還是公共管道。看[thread context](/docs/channels#thread-context) in the channels overview for how to change that behavior.

## 生產部署 {/* #production-deployment */}

使用自我管理設置，在部署 Mastra 伺服器時將 Slack 應用程式設定中的兩個請求 URL 更新為生產 Webhook URL。用於本機開發的隧道 URL 是臨時的，並且會在隧道重新啟動時發生變化。

無伺服器平台上的通道可能需要`waitUntil` and shared pub/sub configuration so background responses and thread leases work across short-lived instances. See [serverless deployment](/docs/channels#serverless-deployment) in the channels overview.

### 閒置伺服器 {/* #idle-servers */}

當平台伺服器沒有接收流量時，它們會縮小到空閒狀態，這對 Slack 來說很好。下一個事件（例如提及或直接訊息）將透過傳遞其 Webhook 請求來喚醒伺服器，然後伺服器繼續處理請求。伺服器空閒後的第一次回應在啟動時可能需要更長的時間，這是預期的。 Slack 期望`200` acknowledgement within 3 seconds and retries the event up to three times when delivery fails or times out, so a very slow cold start may take a retry before the agent responds. Subsequent messages respond at normal speed while the server stays warm.
