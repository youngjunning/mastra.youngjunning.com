# Slack

Mastra 有兩種整合 Slack 的方式。

* **Agent 的 Tool** 讓 Agent 在 Slack 中執行操作，例如讀取對話或傳送訊息。
* **與 Agent 對話**讓使用者在 Slack 頻道的討論串中或透過私訊傳訊息給 Agent。Mastra 每收到一則訊息就會執行 Agent，並以串流方式將回覆傳回 Slack。Slack 轉接器會處理 Slack AI 狀態指示和互動式卡片。

[Mastra Connect](/docs/mastra-platform/connect) 可設定這兩種整合，並將 Slack 憑證保存在 Mastra 平台上。若要讓使用者與 Agent 對話，也可以自行建立並管理 Slack 應用程式。

## 使用 Connect {/* #connect */}

開始前，請依照 [Connect 設定指南](/docs/mastra-platform/connect#get-started)安裝 `@mastra/connect`，並設定平台專案。

Slack Tool 和 Slack 對話各有專用的連線與憑證。

* `slack` 授權 Agent 的 Tool 存取 Slack Workspace。
* `slack-channels` 儲存 Agent 對話所需的應用程式設定權杖。

若要同時使用這兩項功能，請各自新增連線。

### 與 Agent 對話 {/* #agent-chat */}

Slack 對話功能使用應用程式設定權杖，讓 Mastra 為每個 Agent 建立並管理一個 Slack 應用程式。這個流程不會使用你已建立的 Slack 應用程式，例如依照[自行設定](#self-managed-setup)步驟建立的應用程式。

伺服器必須有 Slack 能連線的公開網址，才能接收 webhook 請求與 OAuth 回呼。Mastra 平台會提供這個網址。如果部署在其他環境，請將 `MASTRA_SERVER_URL` 設為伺服器的公開網址。在本機開發時，請使用公開的 HTTPS 通道。

1. 開啟 [Slack 應用程式管理頁面](https://api.slack.com/apps)，接著開啟 **Your App Configuration Tokens**。

2. 為 Agent 將執行所在的 Slack Workspace 產生應用程式設定權杖。

3. 執行 `mastra connect add slack-channels` 並完成授權流程。平台會儲存並輪替設定憑證。

4. 將 [`channels()`](/reference/connect/channels) 的傳回值傳入 `Mastra` 建構函式，以註冊 Slack 頻道 Provider 及其路由。

   ```typescript title="src/mastra/index.ts"
   import { Mastra } from '@mastra/core'
   import { channels } from '@mastra/connect'
   import { assistant } from './agents/assistant'

   export const mastra = new Mastra({
     agents: { assistant },
     channels: await channels({ providers: ['slack'] }),
   })
   ```

   在 `channels()` 中，`slack` 對應至 `slack-channels` 連線。

5. 啟動 Mastra 應用程式。

6. 在 Studio 中，將 Slack 頻道連接至 Agent。Mastra 會建立 Slack 應用程式並傳回授權網址。開啟該網址，選取 Slack Workspace，並核准機器人要求的權限。

[預設的 Slack 應用程式資訊清單](/reference/channels/slack-provider#default-manifest)列出所要求的權限範圍與訂閱的事件。

## 自行設定 Slack 應用程式 {/* #self-managed-setup */}

如果想直接管理供 Agent 對話使用的 Slack 應用程式，請自行建立應用程式，並將憑證儲存在 Mastra 環境中。

### 安裝 {/* #installation */}

安裝 Chat SDK 提供的 Slack 轉接器。

```bash npm2yarn
npm install @chat-adapter/slack
```

在 Agent 的 `channels.adapters` 物件中加入 `createSlackAdapter()`。

```typescript title="src/mastra/agents/your-agent.ts"
import { Agent } from '@mastra/core/agent'
import { createSlackAdapter } from '@chat-adapter/slack'

export const yourAgent = new Agent({
  id: 'your-agent',
  name: 'Your Agent',
  instructions: 'Help people plan tasks, answer questions, and coordinate work in Slack.',
  model: '__GATEWAY_ANTHROPIC_MODEL_OPUS__',
  channels: {
    adapters: {
      slack: createSlackAdapter(),
    },
  },
})
```

### 建立 Slack 應用程式 {/* #create-a-slack-app */}

若要連接 Agent，請在預計執行 Agent 的 Slack Workspace 中建立 Slack 應用程式。這個應用程式決定 Agent 在 Slack 中的顯示方式、可用功能及會收到哪些事件。

本指南透過[應用程式資訊清單](https://docs.slack.dev/app-manifests/configuring-apps-with-app-manifests/#creating_manifests)自動產生 Slack 應用程式的設定。將 Agent 加到自己的 Slack Workspace 時，這是最快的做法。其他 Slack Workspace 安裝 Agent 時所需的平台 OAuth 流程不在本指南範圍內。

按照下列步驟，從資訊清單建立 Slack 應用程式。

1. 開啟 [api.slack.com/apps](https://api.slack.com/apps)。
2. 選取 **Create an app**。
3. 選取 **From a manifest**。
4. 選取要執行 Agent 的 Slack Workspace。
5. 貼上下方的資訊清單，再選取 **Create**。Slack 接受 JSON 或 YAML，請依建立應用程式的對話框所顯示的格式選取對應分頁。

資訊清單會套用下列設定。

* `display_information.name` 與 `features.bot_user.display_name` 設定 Agent 在 Slack 中的名稱。名稱可以隨時修改，變更名稱或權限後請重新安裝應用程式。
* `app_home.messages_tab_enabled` 與 `app_home.messages_tab_read_only_enabled` 讓使用者能從 Slack 應用程式的 **Messages** 分頁傳送私訊。
* `always_online` 讓 Slack 機器人帳號一律顯示為上線。
* `oauth_config.scopes.bot` 允許機器人在已加入的頻道中張貼及讀取訊息，也涵蓋提及、私訊及查詢使用者所需的權限。
* `event_subscriptions` 指定 Slack 要傳送哪些訊息事件到 webhook。
* `interactivity` 啟用互動式卡片，並指定 Slack 要將卡片上的操作傳送到哪個網址。

建立應用程式後，開啟 **Install App**，選取 **Install to Workspace**，並核准所要求的權限。

### 設定 Slack 憑證 {/* #set-slack-credentials */}

在 Mastra 中設定 Slack 憑證，讓 Mastra 能驗證 Slack 傳來的請求，並將訊息傳回 Slack。

從 Slack 應用程式設定的下列位置複製憑證。

* **Basic Information** > **App Credentials** > **Signing Secret**
* **OAuth & Permissions** > **Bot User OAuth Token**

將複製的值設為 Mastra 環境中的變數。

```bash title=".env"
SLACK_SIGNING_SECRET=your-signing-secret
SLACK_BOT_TOKEN=xoxb-your-bot-token
```

Mastra 會自動讀取這些環境變數。

### 設定 webhook 路由 {/* #configure-the-webhook-route */}

Slack 透過 webhook 將頻道活動通知 Mastra。有新訊息、提及或使用者點選互動式卡片時，Slack 會呼叫 webhook 的 HTTP 端點。

Mastra 會自動為 Agent 註冊下列 Slack webhook 路由。

```text
/api/agents/<YOUR-AGENT-ID>/channels/slack/webhook
```

將 Mastra 伺服器的公開網址與產生的路由接在一起，即可組成 webhook 網址。

```text
https://<YOUR-PUBLIC-URL>/api/agents/<YOUR-AGENT-ID>/channels/slack/webhook
```

Slack 無法將事件傳送到 `localhost`。在本機開發時，請讓 Mastra 開發伺服器持續執行，並透過通道將 `http://localhost:4111` 開放給外部連線，再到 Slack 儲存請求網址。

本機開發時，可使用 `cloudflared` 或 `ngrok` 建立通道。

```bash npm2yarn
npx cloudflared tunnel --url http://localhost:4111
```

將 `<YOUR-PUBLIC-URL>` 換成通道產生的主機名稱，如下例所示。

```text
https://abc123.trycloudflare.com/api/agents/your-agent/channels/slack/webhook
```

按照下列步驟更新 Slack 的請求網址。

1. 在 Slack 應用程式設定中，開啟 **Event Subscriptions**。
2. 將 **Request URL** 改為完整的 webhook 網址。
3. 選取 **Save Changes**。
4. 開啟 **Interactivity & Shortcuts**。
5. 將 **Request URL** 改為同一個 webhook 網址。
6. 選取 **Save Changes**。
7. 如果 Slack 要求重新安裝應用程式，請開啟 **OAuth & Permissions**，再選取 **Reinstall to Workspace**。

### 在 Slack 中測試對話 {/* #try-it-in-slack */}

在 Slack 中開啟與機器人的私訊對話，傳送一則訊息。資訊清單包含 `message.im` 事件訂閱和 `im:*` 權限範圍，因此可使用私訊。

若要在頻道中使用 Agent，請先邀請 Slack 機器人加入該頻道。

```text
/invite @your-bot-name
```

接著在頻道中提及機器人。

```text
@your-bot-name What can you help me with?
```

Agent 會在同一個討論串中回覆。回覆內容取決於 Agent 所使用的模型、指令、記憶與 Tool。

## 驗證與存取控制 {/* #authentication */}

Slack 轉接器沒有內建的使用者允許清單。安裝應用程式後，Slack Workspace 中的任何人都可以私訊 Agent，或在機器人已加入的頻道提及它。每個 Slack 請求都會透過簽署密鑰驗證，Mastra 會針對 webhook 收到的每則有效訊息執行 Agent。

存取權主要由頻道成員資格決定。機器人只會收到私訊和受邀加入的頻道所傳來的事件，因此它加入哪些頻道，便決定了誰能透過頻道聯絡它。只將機器人加入允許它回覆的頻道。若要取消某個頻道的存取權，請將機器人移出該頻道。

若需要更細緻的存取控制，可依傳訊者身分判斷。每個請求的頻道[請求內容](#request-context)都包含傳訊者的 Slack 使用者 ID。你可以在輸入處理器或 Tool 中檢查該 ID，在 Agent 採取行動前決定是否允許該使用者存取。

### 伺服器驗證 {/* #server-authentication */}

Slack webhook 路由不受 Mastra 的[伺服器驗證](/docs/auth/overview)限制。由於 Slack 無法傳送 Bearer 權杖，Mastra 會將頻道 webhook 註冊為公開路由，並以 Slack 簽署密鑰驗證每個請求。即使啟用了 [`MastraAuthSimple`](/docs/auth/simple-auth) 等驗證 Provider，其他 API 仍受伺服器驗證保護，webhook 路由則繼續使用簽署密鑰。自行設定 Slack 應用程式時，請保留 `SLACK_SIGNING_SECRET` 的設定，讓轉接器能拒絕未經 Slack 簽署的請求。

### 外部頻道 {/* #external-channels */}

[Slack Connect](https://slack.com/connect) 共用頻道讓其他 Slack Workspace 的成員也能加入對話。只要有 Slack Workspace 成員將機器人加到共用頻道，該頻道的每個人都能和 Agent 對話，包括組織外的成員。能聯絡 Agent 的人也能接觸 Agent 可存取的 Tool 和資料。

將機器人加入共用或外部頻道，就等於授予頻道參與者存取 Agent 的權限。加入前，請確認 Agent 的 Tool 和資料可以安全地開放給外部成員。若需要限制 Agent 回覆哪些成員，請依傳訊者的使用者 ID 控制存取。

## 請求內容 {/* #request-context */}

Mastra 每收到一則訊息，就會將頻道內容物件放在[請求內容](/docs/server/request-context)的 `channel` 鍵下。物件包含傳訊者的 Slack 顯示名稱和使用者 ID、機器人本身的身分，以及訊息來源的詳細資訊。你可以在輸入處理器或 Tool 中讀取這個物件，辨識使用者或依對話類型執行不同的邏輯。

```typescript title="src/mastra/tools/whoami.ts"
import { createTool } from '@mastra/core/tools'
import type { ChannelContext } from '@mastra/core/channels'
import { z } from 'zod'

export const whoami = createTool({
  id: 'whoami',
  description: 'Return the Slack identity of the current user',
  inputSchema: z.object({}),
  execute: async (_input, context) => {
    const channel = context?.requestContext?.get('channel') as ChannelContext | undefined

    return {
      platform: channel?.platform,
      userId: channel?.userId,
      userName: channel?.userName,
      isDM: channel?.isDM,
    }
  },
})
```

頻道內容物件包含下列欄位。

* `botMention`、`botUserId` 與 `botUserName` 代表機器人在 Slack 上的身分。
* `channelId` 與 `threadId` 代表訊息所在的 Slack 頻道和討論串。
* `isDM` 表示訊息是否為私訊。
* `platform` 是平台識別碼。此轉接器的值為 `slack`。
* `userId` 與 `userName` 分別是傳訊者的 Slack 使用者 ID 和顯示名稱。

Mastra 也會將這些資訊轉成一則簡短的系統訊息，讓 Agent 知道目前的平台、自己的身分，以及對話是在私訊或公開頻道中進行。若要變更此行為，請參閱頻道總覽的[討論串脈絡](/docs/channels#thread-context)。

## 正式環境部署 {/* #production-deployment */}

如果是自行管理的 Slack 應用程式，部署 Mastra 伺服器時，請將 Slack 應用程式設定中的兩個請求網址都改為正式環境的 webhook 網址。本機開發用的通道網址是暫時的，通道重新啟動後便會變更。

在無伺服器平台使用頻道整合時，可能需要設定 `waitUntil` 和共用的發布／訂閱機制，讓背景回覆和討論串租約能在生命週期短暫的執行個體之間運作。請參閱頻道總覽中的[無伺服器部署](/docs/channels#serverless-deployment)。

### 閒置伺服器 {/* #idle-servers */}

沒有流量時，平台伺服器會縮減至閒置狀態，Slack 整合仍可正常運作。下一次出現提及或私訊等事件時，Slack 送出的 webhook 請求會喚醒伺服器，讓它繼續處理請求。閒置後的首次回覆可能因為伺服器啟動而稍慢。Slack 預期在 3 秒內收到 `200` 確認回應，投遞失敗或逾時時最多會重試三次。如果冷啟動很慢，Agent 可能要等 Slack 重試後才會回覆。只要伺服器持續執行，後續訊息就會以正常速度獲得回覆。
