# Ring

Ring 訊號讓 Mastra Agent 接收 Ring 門鈴與攝影機回報的事件，例如有人按門鈴或裝置偵測到移動。每個事件都會以[通知訊號](/docs/signals/notifications)的形式送到 Agent 的對話串。Agent 可以取得快照或影片片段，查看誰在門口。

事件和媒體均來自 [Ring Partner API](https://developer.amazon.com/docs/ring/api-documentation.html)。這個 API 不提供照明、警報器、門鎖或雙向通話功能。

## 安裝 {/* #installation */}

安裝所需的套件：

```bash npm2yarn
npm install @mastra/ring-signals @mastra/libsql @mastra/memory
```

## 使用前的準備 {/* #prerequisites */}

使用 Ring 訊號前，請準備以下項目：

* 一台使用 Ring 付費方案的 Ring 裝置。方案須包含 **Person, Package & Vehicle Alerts**（人員、包裹與車輛警示），移動偵測事件才會回報偵測到的類型。
* 在 [Ring Developer Console](https://developer.amazon.com/ring/console/apps) 建立的 **Private App**（私人應用程式），並選取 **Cameras and Doorbells** 權限範圍。請保留 **Client ID**、**Client Secret** 和 **HMAC Signature Key**。
* 支援頻道與通知的 Mastra 儲存配接器。已連結的 Ring 帳號會存入頻道儲存區，通知訊號則使用通知儲存區。
* Mastra 伺服器可從公開網路存取的 HTTPS 網址。Ring 會呼叫伺服器來連結帳號及傳送事件。本機開發時可使用通道，例如 `npx cloudflared tunnel --url http://localhost:4111`。

將開發者應用程式的憑證加入環境變數：

```bash title=".env"
RING_CLIENT_ID=your-client-id
RING_CLIENT_SECRET=your-client-secret
RING_HMAC_KEY=your-hmac-signature-key
MASTRA_ENCRYPTION_KEY=a-long-random-string
RING_BASE_URL=http://localhost:4111
```

`MASTRA_ENCRYPTION_KEY` 用來加密儲存的 Ring 權杖。如果未設定，系統會以未加密的方式儲存權杖，並記錄警告。`RING_BASE_URL` 是選填的 Mastra 伺服器網址，用來產生快照與影片片段連結。詳情請參閱[媒體連結](#media-links)。

## 設定 Agent {/* #agent-configuration */}

將 `new RingSignals()` 加入 Agent 的 `signals` 陣列：

```typescript title="src/mastra/agents/home-agent.ts"
import { Agent } from '@mastra/core/agent'
import { Memory } from '@mastra/memory'
import { RingSignals } from '@mastra/ring-signals'

export const homeAgent = new Agent({
  id: 'home-agent',
  name: 'Home Agent',
  instructions: 'Watch the front door and say briefly whether each event needs attention.',
  model: '__GATEWAY_OPENAI_MODEL__',
  memory: new Memory(),
  signals: [new RingSignals()],
})
```

預設會從環境變數讀取 `RING_CLIENT_ID`、`RING_CLIENT_SECRET`、`RING_HMAC_KEY` 和 `RING_BASE_URL`。若要覆寫這些值，請在設定中傳入 `clientId`、`clientSecret`、`hmacKey` 和 `baseUrl`。所有選項及其預設值請參閱 [RingSignals 參考文件](/reference/signals/ring-signals)。

在 Mastra 執行個體中註冊 Agent 和儲存配接器：

```typescript title="src/mastra/index.ts"
import { Mastra } from '@mastra/core'
import { LibSQLStore } from '@mastra/libsql'
import { homeAgent } from './agents/home-agent'

export const mastra = new Mastra({
  agents: { homeAgent },
  storage: new LibSQLStore({
    id: 'mastra-storage',
    url: 'file:./mastra.db',
  }),
})
```

## 連結帳號 {/* #account-linking */}

若要將 Ring 帳號連結到 Agent，請依序在以下兩個網站完成設定：

1. 在 Amazon 開發者網站的 [Ring Developer Console](https://developer.amazon.com/ring/console/apps) 設定開發者應用程式。
2. 在 [ring.com](https://ring.com) 將開發者應用程式連結到擁有該裝置的 Ring 帳號。

### Ring 開發者控制台 {/* #ring-developer-console */}

Mastra 伺服器會自動在 `/ring` 底下新增 Ring 所需的路由：

| Ring 設定欄位 | 路由 | 用途 |
| - | - | - |
| Account Link URL | `GET <server URL>/ring/link` | 完成帳號連結並顯示結果 |
| Token Exchange URL | `POST <server URL>/ring/token` | 以授權碼交換權杖 |
| Webhook URL | `POST <server URL>/ring/webhook` | 傳送門鈴、移動偵測和其他事件 |
| App Homepage URL | `GET <server URL>/ring/home` | 從應用程式的 Ring Appstore 頁面連到應用程式首頁 |

Ring 呼叫這些路由時不需通過 Mastra 的身分驗證。Webhook 會以 Ring 的簽章驗證，帳號連結則會以 Ring 提供的一次性值（nonce）驗證。

權杖交換路由本身不做驗證，而是將收到的每個授權碼交給 Ring，由 Ring 拒絕非其簽發的授權碼。為避免有人大量呼叫這個路由，請在伺服器的中介軟體中為 `/ring/token` 設定請求頻率限制。

每個 `RingSignals` 執行個體都會新增自己的路由。如果多個 Agent 都使用 `RingSignals`，請為每個執行個體設定各自的 `routePrefix` 和 Ring 開發者應用程式。若兩個執行個體使用相同的前綴，Mastra 只會註冊第一個執行個體的路由，第二個 Agent 將收不到 Ring 事件。

1. 開啟開發者應用程式的 **Account linking** 設定，填入表格中的四個網址。
2. 在 **Connect** 區段選取 **Connect Ring account**，並以擁有該裝置的 Ring 帳號登入。私人開發者應用程式僅供在此處連結的帳號使用。

### ring.com {/* #ringcom */}

1. 在網站上登入 Ring 帳號。
2. 前往 `https://ring.com/appstore/<your-app>`，開啟開發者應用程式在 Ring Appstore 的頁面。
3. 連結應用程式。完成後，頁面會顯示 `Ring account linked`。

已連結的應用程式會列在 Ring 帳號的 [Integrations（整合）](https://account.ring.com/account/integrations)頁面。你可以在這裡暫停或移除應用程式。

### 連結後 {/* #after-linking */}

帳號權杖會存入頻道儲存區，並在到期前更新。從 Ring 帳號的 **Integrations** 頁面移除開發者應用程式時，Ring 會傳送 `app_integration_removed` 事件，觸發該帳號權杖的刪除作業。

一個 Agent 可以連結多個 Ring 帳號。Ring 允許每個私人開發者應用程式最多連結 10 個帳號。每台裝置都會對應到擁有該裝置的帳號。

### 測試整合 {/* #test-the-integration */}

按下門鈴按鈕。裝置的對話串會收到 `button_press` 通知，Agent 也會回覆。你可以在 Studio 開啟該 Agent 查看對話串。對話串 ID 就是裝置 ID。

## 事件與優先順序 {/* #events-and-priorities */}

Ring 事件會以通知訊號送達。預設會啟用 `button_press`（優先順序為 `high`）和 `motion_detected`（優先順序為 `medium`）。所有事件類型及其預設設定請參閱 [RingSignals 參考文件](/reference/signals/ring-signals#events)。

使用 `events` 選項可變更預設設定或啟用事件。若要停用某個事件，請將該事件設為 `false`：

```typescript
new RingSignals({
  events: {
    motion_detected: {
      priority: 'medium',
      summary: 'Motion was detected at the front door.',
      attributes: event => ({ ...event.data.attributes, location: 'front door' }),
    },
    device_offline: { priority: 'low', summary: 'Device went offline.', coalesce: true },
  },
})
```

Agent 可以看到每則通知的 `deviceId`、`timestamp` 和 `motionType` 屬性。你可以透過 `attributes` 加入自訂屬性，例如裝置所在的位置。

`coalesce` 會將重複發生的同一事件合併成一則待處理通知，讓[傳遞策略](/docs/signals/notifications)依收到的事件次數決定如何處理。預設會將低優先順序的通知彙整成摘要。

## 對話串路由 {/* #thread-routing */}

預設每台 Ring 裝置都有自己的對話串。`threadId` 是裝置 ID，`resourceId` 是 Agent ID。

你可以手動設定 `target.resourceId` 和 `target.threadId` 來自訂這兩個值：

```typescript
new RingSignals({
  target: { resourceId: 'home', threadId: 'ring-alerts' },
})
```

若要依事件選擇對話串，請將 `target` 設為函式。這個函式會接收 Ring 為該事件傳送的 Webhook 資料，並回傳該事件的傳送目標。Webhook 資料包含下列欄位：

* `event.data.type`：事件類型，請參閱[事件與優先順序](#events-and-priorities)。
* `event.data.attributes.source`：裝置事件會填入送出事件的裝置 ID，應用程式整合事件會填入帳號 ID，訂閱事件則會填入 `subscriptions`。
* `event.data.attributes.timestamp`：裝置事件的發生時間，以 Unix 紀元起算的毫秒數表示。訂閱事件沒有這個欄位。
* `event.data.attributes.sub_type`：移動偵測事件的觸發類型可為 `human`、`vehicle`、`package_delivery` 或 `other_motion`。若關閉 Smart Alerts，值為 `motion`。訂閱事件的值則是 `paid` 或 `trial`。
* `event.meta.account_id`：裝置所屬的 Ring 帳號 ID。

這個範例將各類活動分流到不同的對話串。例如，偵測到有人移動時會送到 `ring-human`，偵測到車輛移動時會送到 `ring-vehicle`。按門鈴的事件沒有 `sub_type`，因此會送到 `ring-doorbell`：

```typescript
new RingSignals({
  target: event => {
    const activity = event.data.attributes.sub_type ?? 'doorbell'
    return { resourceId: 'home', threadId: `ring-${activity}` }
  },
})
```

若要略過事件，請回傳 `undefined`。函式可以是 `async`。完整的 Webhook 資料型別 `RingWebhookEvent` 請參閱 [RingSignals 參考文件](/reference/signals/ring-signals#ringwebhookevent)。

## 快照與影片片段 Tool {/* #snapshot-and-clip-tools */}

Agent 可以使用以下兩個 Tool：

* `ring_snapshot`：取得事件的靜態影像並傳給模型，讓 Agent 能描述畫面內容。如果 Ring 沒有事件剛發生後的影像， Tool會改用事件發生前最近一張影像。
* `ring_clip`：取得從事件發生時開始的影片片段。Ring 需要時間處理錄影，因此 Tool會重試，直到影片片段可供取得。預設不會將影片傳給模型。詳情請參閱[將媒體傳給模型](#let-the-model-see-media)。

### 將媒體傳給模型 {/* #let-the-model-see-media */}

`visibleToModel` 控制 Tool是否將媒體本身傳給模型。大多數模型支援影像輸入，只有少數支援影片輸入，因此 `ring_snapshot` 的預設值是 `true`，`ring_clip` 的預設值則是 `false`。如果 Agent 使用支援影片輸入的模型，例如 `__GATEWAY_GOOGLE_MODEL_FLASH__`，就可以為影片片段開啟此選項：

```typescript
new RingSignals({
  tools: {
    clip: { visibleToModel: true },
  },
})
```

當 `visibleToModel` 設為 `false` 時，模型只會收到 Tool傳回的文字結果和連結，因此無法描述媒體的畫面內容。

:::note

為影片片段開啟 `visibleToModel` 前，請先確認模型支援影片輸入。Gemini 模型支援影片輸入，Anthropic 和 OpenAI 模型則不支援。Anthropic 會捨棄影片並發出警告，其他模型 API 可能會拒絕整個請求。

影片的每一秒都會占用模型的上下文視窗。預設長度為 15 秒的影片片段會使用數千個 token。如果把 `durationMs` 設為上限 15 分鐘，影片片段可能會用掉數十萬個 token。讓模型處理影片片段時，請將 `durationMs` 設短一些。影片不會儲存在 Agent 的記憶中，因此只會在取得影片的那個步驟占用上下文空間。

:::

### 媒體連結 {/* #media-links */}

Ring 不提供可供分享的媒體連結。下載快照或影片片段需要 Ring 帳號的權杖，因此瀏覽器或聊天應用程式無法直接向 Ring 下載。設定 `baseUrl` 後， Tool會回傳指向你自己伺服器的簽章連結，路徑位於 `<baseUrl>/ring/media/` 底下。開啟連結時，伺服器會向 Ring 取得媒體，再傳給開啟連結的一方。伺服器不會永久儲存媒體，只會在記憶體中快取最近存取的媒體幾分鐘。

將 `RING_BASE_URL` 設為 Mastra 伺服器的網址。開發時可使用 `http://localhost:4111` 或通道網址，正式環境則使用部署後的網址。

若未設定 `RING_BASE_URL` 或 `baseUrl`， Tool就不會回傳連結。Agent 仍可看到每張快照，聊天頻道也仍可收到附件，但應用程式沒有可顯示的連結。

### 在聊天頻道中傳送媒體附件 {/* #attach-media-in-chat-channels */}

如果 Agent 也使用 iMessage 或 Slack 等[頻道](/docs/channels)，使用者無法在聊天中看到 Tool的執行結果。 Tool會改以檔案附件的形式，將快照和影片片段送到頻道的對話串，讓使用者能在對話中開啟。Studio、網頁和 API 的對話串會直接從 Tool結果讀取媒體，因此不會收到附件。

所有頻道預設都支援傳送附件，不需額外設定。若要調整這項行為，請設定各 Tool的以下選項：

* `attachment`：設為 `false` 可停用附件。也可以提供平台名稱清單，例如 `['imessage', 'slack']`， Tool就只會在清單中的平台傳送附件。
* `maxAttachmentBytes`：附件的檔案大小上限，以位元組為單位。超過上限的檔案不會附上。

這個範例只在 iMessage 和 Slack 傳送快照附件，並將 Discord 的影片片段附件上限設為 10 MB：

```typescript
new RingSignals({
  tools: {
    snapshot: { attachment: ['imessage', 'slack'] },
    clip: { maxAttachmentBytes: { discord: 10_000_000 } },
  },
})
```

平台名稱是你在 Agent 的 `channels.adapters` 設定中為配接器指定的鍵名。此範例中的平台名稱為 `imessage` 和 `slack`：

```typescript oxfmt:false
channels: {
  adapters: {
    imessage: { adapter: createiMessageAdapter() },
    slack: { adapter: createSlackAdapter() },
  },
},
```

如果平台不在清單中，或檔案大小超過上限， Tool就不會將媒體附加到頻道的對話串，而會請 Agent 在回覆中分享連結。這項行為需要設定 `baseUrl` 才能產生連結。附件檔案不會儲存在 Agent 的記憶中。

### 將 Ring 警示傳送到聊天對話 {/* #send-ring-alerts-to-a-chat */}

若要在聊天中收到 Ring 警示，頻道和 Ring 必須使用同一個對話串。透過 `resolveResourceId` 和 `resolveThreadId` 為頻道對話串指定固定的資源 ID 和對話串 ID，再將 `target` 設為相同的值。傳送第一則訊息前，請在 `.env` 中將 `HOME_OWNER_USER_ID` 設為你在該頻道平台的使用者 ID（`message.author.userId`）。只有你傳給 Agent 的私訊會使用 Ring 的對話串。群組對話和其他傳訊者會保留各自的對話串，因此收不到 Ring 警示。這些使用者仍可請 Agent 取得 Ring 媒體，詳見下方警告。

```typescript title="src/mastra/agents/home-agent.ts"
import { Agent } from '@mastra/core/agent'
import { Memory } from '@mastra/memory'
import { RingSignals } from '@mastra/ring-signals'
import { createiMessageAdapter } from '@photon-ai/chat-adapter-imessage'

const resourceId = 'home'
const threadId = 'ring-alerts'
// Your user ID on the channel platform
const ownerUserId = process.env.HOME_OWNER_USER_ID
if (!ownerUserId) {
  throw new Error('Set HOME_OWNER_USER_ID to your user ID on the channel platform')
}

export const homeAgent = new Agent({
  id: 'home-agent',
  name: 'Home Agent',
  instructions: 'Watch the front door and say briefly whether each event needs attention.',
  model: '__GATEWAY_OPENAI_MODEL__',
  memory: new Memory(),
  channels: {
    resolveResourceId: ({ thread, message, defaultResourceId }) =>
      thread.isDM && message.author.userId === ownerUserId ? resourceId : defaultResourceId,
    resolveThreadId: ctx => (ctx.resourceId === resourceId ? threadId : ctx.defaultThreadId),
    adapters: {
      imessage: { adapter: createiMessageAdapter() },
    },
  },
  signals: [
    new RingSignals({
      target: { resourceId, threadId },
    }),
  ],
})
```

頻道收到第一則訊息時會建立 `ring-alerts` 對話串，之後 Ring 事件就會送到同一個對話串。如果 Ring 事件先送達，就會由 Ring 建立對話串。頻道無法接手既有的對話串，因此會另開一個。

:::warning

請在第一個 Ring 事件送達前，從頻道開啟新對話並傳訊息給 Agent。用來決定 ID 的函式只會在建立對話串時執行，因此加入這些函式之前就已開始的對話會繼續使用原本的對話串。

任何能透過頻道傳訊息給 Agent 的人，都可以請 Agent 使用 Ring Tool。請限制哪些人可以在該平台上聯繫 Agent。

:::

## 限制 {/* #limitations */}

* Ring 預期在五秒內收到 Webhook 回應。如果平台會讓閒置的伺服器進入休眠，休眠後的第一個事件可能會延遲送達。
* Ring Partner API 無法存取使用端對端加密的裝置。
* Ring 會在每張快照和每段影片上加上浮水印。
* 只有在帳號連結後發生的事件，才能取得快照和影片片段。
* Studio 會顯示 Tool結果中的快照，但無法播放影片片段。若要觀看影片，請開啟 Tool結果中的影片網址。
