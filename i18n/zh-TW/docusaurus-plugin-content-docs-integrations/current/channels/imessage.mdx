# iMessage

透過 iMessage 頻道，Mastra Agent 可以接收 iMessage 的私訊和群組訊息。[Photon](https://app.photon.codes) 和 [Linq](https://linqapp.com) 各自維護用來串接 Mastra 與 iMessage 的轉接器。Mastra 負責將轉接器接到 Agent 並提供 Webhook 路由。啟用門號、設定憑證及註冊 Webhook 的方式請參閱各轉接器的文件。

## 選擇轉接器 {/* #choose-an-adapter */}

兩種轉接器與 Mastra 的串接方式相同，請先選擇要使用的 Provider。

* **Photon** 提供代管及自架的 iMessage 服務，支援 Webhook，也可透過[閘道監聽器](#gateway-listener)維持連線並串流傳送訊息。
* **Linq** 提供代管的 iMessage、RCS 和 SMS API，透過 Webhook 接收事件，並支援 Tapback 回應及媒體內容的雙向對應。

## 安裝轉接器 {/* #install-the-adapter */}

<Tabs groupId="imessage-provider">
  <TabItem value="photon" label="Photon">
    安裝 Photon iMessage 轉接器。

    ```bash npm2yarn
    npm install @photon-ai/chat-adapter-imessage
    ```
  </TabItem>

  <TabItem value="linq" label="Linq">
    安裝 Linq Chat SDK 轉接器。

    ```bash npm2yarn
    npm install @linqapp/chat-sdk-adapter
    ```
  </TabItem>
</Tabs>

## 設定 Agent {/* #agent-configuration */}

在 Agent 的 `channels.adapters` 物件中呼叫轉接器的工廠函式。

<Tabs groupId="imessage-provider">
  <TabItem value="photon" label="Photon">
    ```typescript title="src/mastra/agents/imessage-agent.ts"
    import { Agent } from '@mastra/core/agent'
    import { createiMessageAdapter } from '@photon-ai/chat-adapter-imessage'

    export const imessageAgent = new Agent({
      id: 'imessage-agent',
      name: 'iMessage Agent',
      instructions: 'Answer questions and help with tasks over iMessage.',
      model: '__GATEWAY_OPENAI_MODEL__',
      channels: {
        adapters: {
          imessage: {
            adapter: createiMessageAdapter(),
            toolDisplay: 'text',
          },
        },
        threadContext: { maxMessages: 0 },
      },
    })
    ```

    當 Agent 首次在群組聊天中被提及時，Mastra 通常會向平台查詢聊天記錄。Photon 轉接器無法執行這項查詢，因此請設定 `threadContext: { maxMessages: 0 }` 略過這一步。
  </TabItem>

  <TabItem value="linq" label="Linq">
    ```typescript title="src/mastra/agents/imessage-agent.ts"
    import { Agent } from '@mastra/core/agent'
    import { createLinqAdapter } from '@linqapp/chat-sdk-adapter'

    export const imessageAgent = new Agent({
      id: 'imessage-agent',
      name: 'iMessage Agent',
      instructions: 'Answer questions and help with tasks over iMessage.',
      model: '__GATEWAY_OPENAI_MODEL__',
      channels: {
        adapters: {
          imessage: {
            adapter: createLinqAdapter({
              apiKey: process.env.LINQ_API_KEY!,
              signingSecret: process.env.LINQ_WEBHOOK_SECRET!,
            }),
            toolDisplay: 'text',
          },
        },
      },
    })
    ```

    將憑證直接傳入 `createLinqAdapter()`。`apiKey` 是你的 Linq API 金鑰，`signingSecret` 則來自 [Webhook 訂閱](#webhook-url)。Linq 轉接器可以擷取對話記錄，因此可沿用 `threadContext` 的預設行為。
  </TabItem>
</Tabs>

在 Mastra 執行個體中註冊 Agent。

```typescript title="src/mastra/index.ts"
import { Mastra } from '@mastra/core'
import { imessageAgent } from './agents/imessage-agent'

export const mastra = new Mastra({
  agents: { imessageAgent },
})
```

以 `imessage` 作為轉接器的索引鍵。Mastra 會根據這個索引鍵決定 Webhook 路徑及 `requestContext` 中的 `platform` 值。

iMessage 沒有可核准或拒絕 Tool 呼叫的互動卡片，因此兩種轉接器都要設定 `toolDisplay: 'text'`，在訊息中以文字說明 Tool 呼叫。Photon 無法顯示卡片。Linq 會將卡片轉成純文字，按鈕只會顯示標籤，無法觸發操作。

:::warning

純文字訊息無法送出核准或拒絕的決定。設有 `requireApproval: true` 的 Tool 會維持暫停，直到有人透過介面或 API 明確送出核准或拒絕，例如在 Studio 中操作。只有在其他介面能處理這項決定時，才適合在 iMessage Agent 上使用需要核准的 Tool。請參閱 [Tool 核准](/docs/channels#tool-approval)。

:::

## 設定轉接器 {/* #adapter-setup */}

<Tabs groupId="imessage-provider">
  <TabItem value="photon" label="Photon">
    請依照 [Photon iMessage 轉接器文件](https://github.com/photon-hq/vercel-chat-adapter-imessage)完成 iMessage 專用設定，包括啟用門號、設定代管或自架模式，以及註冊 Webhook。轉接器會依你設定的環境變數選擇模式。

    如果使用代管服務，請在 [app.photon.codes](https://app.photon.codes) 建立專案，並用專案憑證設定下列環境變數。

    ```bash title=".env"
    IMESSAGE_PROJECT_ID=your-project-id
    IMESSAGE_PROJECT_SECRET=your-project-secret
    IMESSAGE_WEBHOOK_SECRET=your-webhook-signing-secret
    ```

    如果使用自架伺服器，請將轉接器指向伺服器的 gRPC 位址，格式為 `host:port`。轉接器會移除 URL 的配置名稱（scheme）。位址如果只有主機名稱，就會補上 `:443`。

    ```bash title=".env"
    IMESSAGE_SERVER_URL=imessage.example.com:443
    IMESSAGE_API_KEY=your-server-token
    IMESSAGE_PHONE=+15551234567
    ```

    `IMESSAGE_PHONE` 是選填項目，在自架伺服器有多個門號時用於訊息路由。你也可以直接把這些值傳入 `createiMessageAdapter()`，其中可傳入 `credentials` 函式，在首次使用時從密鑰儲存庫取得專案 ID 與密鑰。
  </TabItem>

  <TabItem value="linq" label="Linq">
    請依照 [Linq API 文件](https://docs.linqapp.com/)完成 Linq 專用設定，包括啟用門號與取得 API 金鑰。建立 Linq 帳號後，複製 API 金鑰，並設定 Agent 組態會讀取的憑證。

    ```bash title=".env"
    LINQ_API_KEY=your-linq-api-key
    LINQ_WEBHOOK_SECRET=your-webhook-signing-secret
    ```

    `LINQ_WEBHOOK_SECRET` 是下一節建立 Webhook 訂閱時傳回的簽章密鑰。你也可以使用轉接器的 `baseURL` 選項，指定其他 Linq API 基礎 URL，例如 Sandbox 環境的網址。
  </TabItem>
</Tabs>

## Webhook URL {/* #webhook-url */}

Mastra 會根據 Agent ID 和轉接器的索引鍵產生 iMessage Webhook 路由。

```text
/api/agents/imessage-agent/channels/imessage/webhook
```

以 Mastra 伺服器對外公開的 URL 為基礎，接上這段路徑。

```text
https://your-app.example.com/api/agents/imessage-agent/channels/imessage/webhook
```

<Tabs groupId="imessage-provider">
  <TabItem value="photon" label="Photon">
    在 [Photon 控制台](https://app.photon.codes)註冊這個 URL，並將傳回的簽章密鑰設為 `IMESSAGE_WEBHOOK_SECRET`。密鑰只會在註冊時顯示一次。轉接器會驗證每次投遞的簽章，並拒絕簽章不符的請求。只有代管模式支援 Webhook。
  </TabItem>

  <TabItem value="linq" label="Linq">
    建立 [Webhook 訂閱](https://docs.linqapp.com/guides/webhooks/subscriptions/)，將這個 URL 設為目標，並至少訂閱下列事件。

    * `message.received`
    * `reaction.added`
    * `reaction.removed`

    將訂閱傳回的 `signing_secret` 設為 `LINQ_WEBHOOK_SECRET`。密鑰只會在建立訂閱時顯示一次，之後無法再次取得。轉接器會驗證每次投遞的 HMAC 簽章，檢查是否有重送攻擊，並拒絕簽章不符的請求。
  </TabItem>
</Tabs>

:::note

兩個 Provider 都只會向公開的 HTTPS 端點投遞訊息，不支援 `http://` 或 `localhost` 之類的私人位址。在本機開發時，請依照[頻道總覽](/docs/channels#webhook-routes)的說明使用通道（tunnel）。

:::

## 重複投遞 {/* #duplicate-deliveries */}

Photon 和 Linq 採用至少投遞一次的機制，投遞失敗時會依退避策略重試，因此同一則訊息可能重複送達。Chat SDK 透過頻道狀態轉接器略過重複的訊息，而 Mastra 預設會把去重用的索引鍵保存在記憶體中。這種做法適用於單一持續運作的伺服器。

伺服器重新啟動後，Agent 仍可能收到重複的訊息。在無伺服器環境中，重試請求若被導向另一個執行個體，也會發生同樣的情況。透過 `channels.state` 傳入共用的狀態轉接器，讓各執行個體都能讀取去重用的索引鍵。請搭配 iMessage 轉接器安裝一個狀態轉接器。

```bash npm2yarn
npm install @chat-adapter/state-redis
```

`createRedisState()` 會讀取 `REDIS_URL` 環境變數。

```typescript title="src/mastra/agents/imessage-agent.ts" oxfmt:false
import { createRedisState } from '@chat-adapter/state-redis'

channels: {
  adapters: {
    imessage: {
      adapter: createiMessageAdapter(),
      toolDisplay: 'text',
    },
  },
  state: createRedisState(),
},
```

使用具有副作用的 Tool 時，去重尤其重要，因為使用者會看到同一則訊息被處理兩次所造成的結果。

## 已讀回條 {/* #read-receipts */}

iPhone 的「訊息」App 會針對 Agent 送出的每則訊息傳送已讀回條。Photon 轉接器會將回條當成收到的訊息交給 Mastra，其中沒有文字，也沒有附件。Mastra 會略過這類訊息，避免 Agent 不斷回覆自己。這些訊息的 ID 帶有 `:read:` 字尾，並會在 `debug` 層級的記錄中標示為已略過。

所有轉接器都適用同一項規則。收到的訊息如果沒有文字也沒有附件，就不會觸發 Agent 執行。自訂的 `onDirectMessage`、`onMention` 或 `onSubscribedMessage` 處理函式仍會收到這類訊息，可以在呼叫 `defaultHandler` 前處理。

## 閘道監聽器 {/* #gateway-listener */}

Photon 轉接器在代管與自架模式下都能維持連線，即時串流傳送訊息，無須接收 Webhook。Linq 轉接器透過 Webhook 接收事件，沒有閘道模式。

Mastra 會在初始化時啟動閘道監聽器，連線中斷時會重新連線，因此持續運作的伺服器無須設定 cron 工作或新增路由。若使用 Webhook，請在轉接器設定中加入 `gateway: false`，關閉監聽器。

```typescript title="src/mastra/agents/imessage-agent.ts" oxfmt:false
imessage: {
  adapter: createiMessageAdapter(),
  toolDisplay: 'text',
  gateway: false,
},
```

無伺服器平台建議優先使用 Webhook。閘道監聽器需要持續執行的處理程序。請參閱[無伺服器部署](/docs/channels#serverless-deployment)。
