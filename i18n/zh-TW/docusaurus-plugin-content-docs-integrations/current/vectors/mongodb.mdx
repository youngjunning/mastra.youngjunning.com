# MongoDB 向量儲存

`MongoDBVector` 類別透過 [MongoDB Vector Search](https://www.mongodb.com/docs/atlas/atlas-vector-search/) 提供向量搜尋，讓您在 MongoDB 集合中有效率地搜尋相似內容並篩選中繼資料。

## 安裝 {/* #installation */}

```bash npm2yarn
npm install @mastra/mongodb@latest
```

## 使用範例 {/* #usage-example */}

```typescript
import { MongoDBVector } from '@mastra/mongodb'

const store = new MongoDBVector({
  id: 'mongodb-vector',
  uri: process.env.MONGODB_URI,
  dbName: process.env.MONGODB_DB_NAME,
})
```

### 自訂嵌入欄位路徑 {/* #custom-embedding-field-path */}

若要將嵌入向量存放在巢狀欄位中，例如與既有 MongoDB 集合整合，請使用 `embeddingFieldPath` 選項：

```typescript
import { MongoDBVector } from '@mastra/mongodb'

const store = new MongoDBVector({
  id: 'mongodb-vector',
  uri: process.env.MONGODB_URI,
  dbName: process.env.MONGODB_DB_NAME,
  embeddingFieldPath: 'text.contentEmbedding', // Store embeddings at text.contentEmbedding
})
```

### `createSearchIndex()` {/* #createsearchindex */}

在向量索引對應的集合上建立 MongoDB Search（BM25／全文）索引，並記錄為 `textQuery()` 和 `hybridQuery()` 使用的文字搜尋索引。

**受管集合與自有集合：**

* 對於**受管索引**（建立時未指定 `collectionName`），`createIndex()` 已建立名為 `${collectionName}_search_index` 的*動態*全文索引，涵蓋所有字串欄位。因此，只有需要**限定欄位**的對應方式或**自訂索引名稱**時，才須呼叫 `createSearchIndex()`。
* 對於**自有索引**（建立時指定了 `collectionName`），`createIndex()` 不會自動建立全文索引。若要在呼叫端擁有的業務集合上使用 `textQuery()`/`hybridQuery()`，必須明確呼叫 `createSearchIndex()` 建立可能產生費用的文字索引。在此之前，`textQuery()`/`hybridQuery()` 會明確報錯，不會查詢不存在的索引。

命名：

* 提供 `fields` 但**未**明確指定 `searchIndexName` 時，欄位對應索引會使用**獨立**的預設名稱 `${collectionName}_${indexName}_search_fields_index`（每個邏輯索引各不相同），避免與受管集合自動建立的動態索引衝突而被默默忽略。此名稱會持久記錄為文字搜尋索引，因此 `textQuery()`/`hybridQuery()` 會自動使用限定欄位的對應方式。
* 指定 `searchIndexName` 時，會使用並持久保存該確切名稱。`textQuery()`/`hybridQuery()` 會自動取得已保存的名稱；也可以透過各自的 `searchIndexName` / `textSearchIndexName` 參數，覆寫單次呼叫使用的名稱。

對 `autoEmbed` 索引而言，`dimension` 取自索引定義；若索引未指定維度，便回報 MongoDB 的預設值 `1024`。若`autoEmbed` 索引未指定相似性函式，結果會省略 `metric`。由於產生的向量不儲存在文件中，`count` 統計的是包含嵌入文字欄位的文件數量。

### `deleteIndex()` {/* #deleteindex */}

刪除向量索引。行為取決於索引的創建方式：

* **受管索引**（建立時未指定 `collectionName`）：刪除整個集合及其中所有資料。
* **自有索引**（建立時指定了 `collectionName`）：刪除 MongoDB vectorSearch 索引。若 `createSearchIndex()` 也建立了配套的全文搜尋索引，該索引亦會刪除。同一集合上仍被其他邏輯索引參照的 vectorSearch 或全文索引會予以保留。呼叫端的業務集合及其文件不受影響。本向量儲存絕不會刪除不是由它建立的集合。

建立索引時會持久記錄它是否屬於自有集合，因此即使由另一個處理程序操作，也能正確套用刪除規則，例如初始化作業建立索引後，由長期執行的服務刪除。請一律傳入**邏輯索引名稱**（呼叫 `createIndex` 時使用的 `indexName`），而非實際集合名稱。

},
]}

## 自動嵌入 {/* #automated-embedding */}

MongoDB 可以代為產生嵌入向量。建立索引時設定 `autoEmbed` 與 Voyage AI 模型，透過 `documents` 寫入純文字，再以 `queryText` 搜尋。應用程式不必執行嵌入 Provider，也不必傳送向量。

```typescript
import { MongoDBVector } from '@mastra/mongodb'

const store = new MongoDBVector({
  id: 'mongodb-vector',
  uri: process.env.MONGODB_URI,
  dbName: process.env.MONGODB_DB_NAME,
})

// No `dimension`: the embedding model determines it.
await store.createIndex({
  indexName: 'movies',
  autoEmbed: { model: 'voyage-4' },
  filterFields: ['year'],
})

// Automated Embedding indexes build slower than client-embedded ones.
await store.waitForIndexReady({ indexName: 'movies', timeoutMs: 300000 })

// No `vectors`: MongoDB embeds the text as documents are written.
await store.upsert({
  indexName: 'movies',
  documents: [
    'A lonely astronaut adrift near a strange ocean planet.',
    'A heist crew robs a bank vault in Paris.',
  ],
  metadata: [{ year: 1972 }, { year: 2001 }],
})

// No `queryVector`: MongoDB embeds the query string with the same model.
const results = await store.query({
  indexName: 'movies',
  queryText: 'space opera about isolation',
  topK: 5,
  filter: { year: { $gt: 1970 } },
})
```

`autoEmbed` 索引定義接受的其他欄位會原樣傳給 MongoDB，因此即使套件未更新，也能使用此版本發布後新增的選項。省略的選項沿用 MongoDB 的預設值。

**重要提示：**

* 自動嵌入是 **MongoDB 預覽功能**。它需要支援自動嵌入的 Atlas 叢集；本機開發可使用 `mongodb/mongodb-atlas-local:preview` 映像檔。自行管理的部署還須為 `mongot` 設定 Voyage AI API 金鑰。
* Voyage AI API 金鑰必須透過 Atlas UI 進行設定。由 Voyage AI 直接頒發的密鑰會被預設嵌入端點拒絕。
* **MongoDB 將產生的向量儲存在集合之外**，因此文件只包含文字。`autoEmbed` 索引不支援 `includeVector: true`，使用時會發生錯誤。
* 嵌入是異步生成的。即使索引報告就緒，查詢也可以在寫入後短時間內合法地不傳回結果。
* 索引只能宣告向量欄位或 `autoEmbed` 欄位，不可同時宣告。省略 `autoEmbed` 就能繼續自行提供向量；用戶端產生嵌入向量的流程不變。
* 向 `autoEmbed` 索引傳入 `vectors` 會發生錯誤，因為向量會寫入索引不會讀取的欄位。
* 當 `document` 是用來產生嵌入向量的欄位時，它不再是已宣告的篩選欄位，因此 `documentFilter` 會自動使用 `$match` 預篩選。透過 `filterFields` 宣告的中繼資料篩選條件仍會下推至 `$vectorSearch`。
* `updateVector()` 不允許更新 `autoEmbed` 索引的向量。請改以新文字更新或插入文件，MongoDB 會重新產生嵌入向量。
* `queryVector` 仍可用於 `autoEmbed` 索引，但向量須由相容的模型產生，且符合索引的 `quantization`；不相符時 MongoDB 會拒絕查詢。
* 文件與查詢的嵌入向量產生費用均依 token 計算。

## 為現有集合建立索引 {/* #indexing-an-existing-collection */}

您可以直接在既有業務集合上建立向量索引，不必使用受管集合。這能為 MongoDB 資料庫中已有的文件加入向量搜尋功能。

```typescript
import { MongoDBVector } from '@mastra/mongodb'

const store = new MongoDBVector({
  id: 'mongodb-vector',
  uri: process.env.MONGODB_URI,
  dbName: process.env.MONGODB_DB_NAME,
})

// Create a vector index on an existing 'transactions' collection
await store.createIndex({
  indexName: 'precedents',
  dimension: 1024,
  collectionName: 'transactions', // Use existing collection
  searchIndexName: 'txn_vec_idx', // Custom search index name
})

// Wait for the index to be ready
await store.waitForIndexReady({ indexName: 'precedents' })

// Query using document mode to get full source documents
const hits = await store.query({
  indexName: 'precedents',
  queryVector: embeddings,
  topK: 5,
  metadataMode: 'document', // Returns full document as metadata
})

// hits[0].metadata now contains all fields from the source document
console.log(hits[0].metadata.amount, hits[0].metadata.customField)

// Full-text / hybrid search on a BYO collection is opt-in: provision the text index first.
await store.createSearchIndex({ indexName: 'precedents', fields: ['note'] })
```

**重要提示：**

* 集合必須已存在，且文件包含 `embedding` 欄位，或包含所設定的自訂 `embeddingFieldPath` 欄位。
* 指定 `collectionName` 後，本向量儲存絕不會建立或刪除該集合。
* **自有索引預設為唯讀。** `upsert()`、`updateVector()`、`deleteVector()` 與 `deleteVectors()` 會明確報錯，不會修改呼叫端的業務文件。若要允許本向量儲存向集合寫入嵌入向量或刪除文件，須明確呼叫 `createIndex({ ..., allowWrites: true })`。這項政策會持久保存，重新啟動後仍有效。舊版寫入且沒有此旗標的項目會以唯讀處理，安全地拒絕寫入。
* 查詢時使用 `metadataMode: 'document'`，可將完整來源文件當作 `metadata` 傳回。
* 在 `'document'` 模式下，預設會從 `metadata` 省略嵌入欄位；傳入 `includeVector: true` 可保留該欄位，並另以頂層 `vector` 提供。
* **`'document'` 模式的篩選作用於根文件欄位**，而非巢狀的 `metadata.` 子文件。`filter: { lane: 'fraud' }` 會比對業務文件頂層的 `lane` 欄位；在預設的 `'field'` 模式下，受管集合的未加前綴欄位名稱會改寫為 `metadata.<field>`。下推篩選與 `$match` 備援路徑都遵循此規則。
* **支援原生 `ObjectId` 型別的 `_id`。** 業務集合通常以 `ObjectId` 作為鍵；查詢結果會依 `QueryResult.id` 契約將 `_id` 轉為字串，`deleteVector()`/`updateVector()`/`deleteVectors()` 接受該字串並比對底層 `ObjectId` 文件。使用字串 `_id` 的受管集合不受影響。
* 自有集合上的全文與混合搜尋須**明確啟用**：系統不會自動建立全文索引，因此須在呼叫 `textQuery()`/`hybridQuery()` 前呼叫 `createSearchIndex()`。全文索引會非同步建置；若要立即執行文字或混合查詢，請先呼叫 `waitForSearchIndexReady()`，或傳入 `waitUntilReady: true`。
* 對自有索引呼叫 `deleteIndex()` 會刪除向量索引及已建立的文字索引，但會**保留**集合及其中的文件。

## 最佳實踐 {/* #best-practices */}

* 為篩選條件使用的中繼資料欄位建立索引，以取得較佳的查詢效能。
* 在元資料中使用一致的欄位命名以避免意外的查詢結果。
* 定期監控索引和集合統計資料以確保高效搜尋。
* 為既有集合建立索引時，請確保所有文件都有必要的 `embedding` 欄位。

### 在 `MongoDB` 中使用向量嵌入 {/* #vector-embeddings-with-mongodb */}

嵌入向量是數值向量，Memory 的 `semanticRecall` 藉此依語意而非關鍵字擷取相關訊息。

:::note

建議在正式環境使用 MongoDB Vector Search。自行託管時，可透過 [Atlas CLI 建立本機 Atlas 部署](https://www.mongodb.com/docs/atlas/cli/current/atlas-cli-deploy-local/)來使用 Vector Search。

```bash npm2yarn
npm install @mastra/fastembed@latest
```

```typescript title="src/mastra/agents/example-mongodb-agent.ts"
import { Memory } from '@mastra/memory'
import { Agent } from '@mastra/core/agent'
import { MongoDBStore, MongoDBVector } from '@mastra/mongodb'

export const mongodbAgent = new Agent({
  id: 'mongodb-agent',
  name: 'mongodb-agent',
  instructions:
    'You are an AI agent with the ability to automatically recall memories from previous interactions.',
  model: '__GATEWAY_OPENAI_MODEL__',

    storage: new MongoDBStore({
      id: 'mongodb-storage',

      lastMessages: 10,

        topK: 3,
        messageRange: 2,
      },

})
```
