# Google Cloud Storage

這項整合會將檔案儲存至 Google Cloud Storage。介面的詳細說明請參閱 [WorkspaceFilesystem 介面](/reference/workspace/filesystem)。

## 安裝 {/* #installation */}

```bash npm2yarn
npm install @mastra/gcs
```

## 使用方式 {/* #usage */}

在 Workspace 中加入 `GCSFilesystem`，接著將該 Workspace 指派給 Agent。

```typescript
import { Agent } from '@mastra/core/agent'
import { Workspace } from '@mastra/core/workspace'
import { GCSFilesystem } from '@mastra/gcs'

const workspace = new Workspace({
  filesystem: new GCSFilesystem({
    bucket: 'my-gcs-bucket',
    projectId: 'my-project-id',
    credentials: JSON.parse(process.env.GCS_SERVICE_ACCOUNT_KEY),
  }),
})

const agent = new Agent({
  id: 'file-agent',
  name: 'file-agent',
  model: '__GATEWAY_ANTHROPIC_MODEL_OPUS__',
  workspace,
})
```

### 使用應用程式預設憑證 {/* #using-application-default-credentials */}

如果應用程式在 Google Cloud 上執行，或已設定 `gcloud` CLI，就可以省略憑證。

```typescript
import { GCSFilesystem } from '@mastra/gcs'

const filesystem = new GCSFilesystem({
  bucket: 'my-gcs-bucket',
  // Uses Application Default Credentials automatically
})
```

[應用程式預設憑證（ADC）](https://cloud.google.com/docs/authentication/application-default-credentials)會依下列順序自動尋找憑證。

1. `GOOGLE_APPLICATION_CREDENTIALS` 環境變數指定的服務帳戶金鑰檔案
2. 在 GCP（Compute Engine、Cloud Run、GKE 等）上執行時所用的預設服務帳戶憑證
3. 透過 `gcloud auth application-default login` 取得的使用者憑證（供本機開發使用）

### 使用金鑰檔案路徑 {/* #using-a-key-file-path */}

也可以傳入服務帳戶的金鑰檔案路徑。

```typescript
import { GCSFilesystem } from '@mastra/gcs'

const filesystem = new GCSFilesystem({
  bucket: 'my-gcs-bucket',
  projectId: 'my-project-id',
  credentials: '/path/to/service-account-key.json',
})
```

## 方法 {/* #methods */}

GCSFilesystem 實作 [WorkspaceFilesystem 介面](/reference/workspace/filesystem)，提供所有標準檔案系統方法。

* `readFile(path, options?)` - 讀取檔案內容
* `writeFile(path, content, options?)` - 將內容寫入檔案
* `appendFile(path, content)` - 在檔案末尾附加內容
* `deleteFile(path, options?)` - 刪除檔案
* `copyFile(src, dest, options?)` - 複製檔案
* `moveFile(src, dest, options?)` - 移動或重新命名檔案
* `mkdir(path, options?)` - 建立目錄
* `rmdir(path, options?)` - 移除目錄
* `readdir(path, options?)` - 列出目錄內容
* `exists(path)` - 檢查路徑是否存在
* `stat(path)` - 取得檔案或目錄的中繼資料

### `init()` {/* #init */}

初始化檔案系統，並確認憑證是否有效、儲存桶是否可存取。

```typescript
await filesystem.init()
```

### `getInfo()` {/* #getinfo */}

傳回這個檔案系統執行個體的中繼資料。

```typescript
const info = filesystem.getInfo()
// { id: '...', name: 'GCSFilesystem', provider: 'gcs', status: 'ready' }
```

### `getMountConfig()` {/* #getmountconfig */}

傳回掛載設定，供支援掛載這類檔案系統的 Sandbox 使用。

```typescript
const config = filesystem.getMountConfig()
// { type: 'gcs', bucket: 'my-bucket', ... }
```

## 掛載至 E2B Sandbox {/* #mounting-in-e2b-sandboxes */}

在 E2B Sandbox 中掛載 GCSFilesystem 後，就能像存取本機目錄一樣存取儲存桶。

```typescript
import { Workspace } from '@mastra/core/workspace'
import { GCSFilesystem } from '@mastra/gcs'
import { E2BSandbox } from '@mastra/e2b'

const workspace = new Workspace({
  mounts: {
    '/data': new GCSFilesystem({
      bucket: 'my-gcs-bucket',
      projectId: 'my-project-id',
      credentials: JSON.parse(process.env.GCS_SERVICE_ACCOUNT_KEY),
    }),
  },
  sandbox: new E2BSandbox({ id: 'dev-sandbox' }),
})
```

掛載的詳細說明請參閱 [E2BSandbox 參考文件](/integrations/sandboxes/e2b)。
