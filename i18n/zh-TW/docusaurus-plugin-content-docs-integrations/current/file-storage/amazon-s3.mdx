# Amazon S3

你可以用 Amazon S3 或相容於 S3 的服務儲存檔案，例如 Cloudflare R2、Neon Object Storage、MinIO、DigitalOcean Spaces 和 Tigris。介面細節請見 [WorkspaceFilesystem 介面](/reference/workspace/filesystem)。

## 安裝 {/* #installation */}

```bash npm2yarn
npm install @mastra/s3
```

## 使用方式 {/* #usage */}

在 Workspace 中加入 `S3Filesystem`，再將這個 Workspace 指派給 Agent。

```typescript
import { Agent } from '@mastra/core/agent'
import { Workspace } from '@mastra/core/workspace'
import { S3Filesystem } from '@mastra/s3'

const workspace = new Workspace({
  filesystem: new S3Filesystem({
    bucket: 'my-bucket',
    region: 'us-east-1',
    accessKeyId: process.env.AWS_ACCESS_KEY_ID,
    secretAccessKey: process.env.AWS_SECRET_ACCESS_KEY,
  }),
})

const agent = new Agent({
  id: 'file-agent',
  name: 'file-agent',
  model: '__GATEWAY_ANTHROPIC_MODEL_OPUS__',
  workspace,
})
```

### AWS 憑證 Provider 鏈 {/* #aws-credential-provider-chain */}

如果未提供憑證，`S3Filesystem` 會採用 AWS SDK 預設的憑證 Provider 鏈，自動從環境變數、`~/.aws` 設定檔、ECS 容器憑證、EC2 執行個體設定檔及其他標準來源取得憑證。

```typescript
import { S3Filesystem } from '@mastra/s3'

// SDK discovers credentials from the environment automatically
const filesystem = new S3Filesystem({
  bucket: 'my-bucket',
  region: 'us-east-1',
})
```

若要自動更新憑證，可以傳入憑證 Provider 函式。部署在 ECS 或 Lambda 上，或使用 SSO、AssumeRole 且需要更新會到期的臨時憑證時，都適合採用這種方式。

若要直接呼叫 `fromNodeProviderChain()`，請安裝 AWS SDK 的憑證 Provider 套件。

```bash npm2yarn
npm install @aws-sdk/credential-providers
```

```typescript
import { S3Filesystem } from '@mastra/s3'
import { fromNodeProviderChain } from '@aws-sdk/credential-providers'

const filesystem = new S3Filesystem({
  bucket: 'my-bucket',
  region: 'us-east-1',
  credentials: fromNodeProviderChain(),
})
```

憑證 Provider 函式僅適用於 `S3Filesystem` 的 API 呼叫。將檔案系統掛載至 E2B 或 Daytona Sandbox 時，掛載設定僅接受靜態的 `accessKeyId`、`secretAccessKey` 和 `sessionToken` 值，因此必須在掛載機制之外處理憑證更新。掛載的存續時間與隔離要求請見 [Daytona 的臨時憑證](/integrations/sandboxes/daytona#temporary-s3-credentials)。

### 依前綴限定權限 {/* #prefix-scoped-permissions */}

設定 `prefix` 時，初始化會呼叫 `ListObjectsV2`，帶入正規化後以 `/` 結尾的前綴，以及 `MaxKeys: 1`。憑證必須允許列出該前綴下的物件。未設定前綴時，初始化會改用 `HeadBucket`。這些檢查僅確認存取權，不確認目錄是否存在。

前綴只限定檔案系統使用的物件鍵範圍。若要隔離存取，請透過儲存 Provider 的政策，將所用憑證的存取權限限定在該前綴。請將權限範圍較廣的上層憑證留在後端。有前綴的檔案系統初始化時，除了讀寫權限，也需要列出物件的權限。

### Cloudflare R2 {/* #cloudflare-r2 */}

```typescript
import { S3Filesystem } from '@mastra/s3'

const filesystem = new S3Filesystem({
  bucket: 'my-r2-bucket',
  region: 'auto',
  endpoint: `https://${process.env.R2_ACCOUNT_ID}.r2.cloudflarestorage.com`,
  accessKeyId: process.env.R2_ACCESS_KEY_ID,
  secretAccessKey: process.env.R2_SECRET_ACCESS_KEY,
})
```

### Neon Object Storage {/* #neon-object-storage */}

```typescript
import { S3Filesystem } from '@mastra/s3'

const filesystem = new S3Filesystem({
  bucket: 'agent-files',
  region: process.env.AWS_REGION!,
  endpoint: process.env.AWS_ENDPOINT_URL_S3,
  accessKeyId: process.env.AWS_ACCESS_KEY_ID,
  secretAccessKey: process.env.AWS_SECRET_ACCESS_KEY,
})
```

`neon deploy` 和 `neon env pull` 會寫入目前 Neon 分支的這些變數。請保留預設的路徑式定址。每個分支都有專屬端點及各自的檔案副本。儲存貯體的設定及分支用法請見 [Neon Object Storage](/integrations/file-storage/neon)。

### MinIO {/* #minio */}

```typescript
import { S3Filesystem } from '@mastra/s3'

const filesystem = new S3Filesystem({
  bucket: 'my-bucket',
  region: 'us-east-1',
  endpoint: 'http://localhost:9000',
  accessKeyId: 'minioadmin',
  secretAccessKey: 'minioadmin',
})
```

### Tigris {/* #tigris */}

```typescript
import { S3Filesystem } from '@mastra/s3'

const filesystem = new S3Filesystem({
  bucket: 'my-bucket',
  region: 'auto',
  endpoint: 'https://t3.storage.dev',
  accessKeyId: process.env.TIGRIS_ACCESS_KEY_ID,
  secretAccessKey: process.env.TIGRIS_SECRET_ACCESS_KEY,
  forcePathStyle: false,
})
```

Tigris 採用虛擬主機式定址，必須將 `forcePathStyle` 設為 `false`。使用自訂端點時，這項設定的預設值為 `true`。請在 [Tigris 控制台](https://console.tigris.dev/)建立憑證。存取金鑰以 `tid_` 開頭，私密存取金鑰以 `tsec_` 開頭。

## 方法 {/* #methods */}

S3Filesystem 實作 [WorkspaceFilesystem 介面](/reference/workspace/filesystem)，提供下列所有標準檔案系統方法。

* `readFile(path, options?)` - 讀取檔案內容
* `writeFile(path, content, options?)` - 將內容寫入檔案
* `appendFile(path, content)` - 將內容加到檔案末尾
* `deleteFile(path, options?)` - 刪除檔案
* `copyFile(src, dest, options?)` - 複製檔案
* `moveFile(src, dest, options?)` - 移動檔案或重新命名
* `mkdir(path, options?)` - 建立目錄
* `rmdir(path, options?)` - 移除目錄
* `readdir(path, options?)` - 列出目錄內容
* `exists(path)` - 檢查路徑是否存在
* `stat(path)` - 取得檔案或目錄的中繼資料

### `init()` {/* #init */}

初始化檔案系統，並驗證憑證及儲存貯體的存取權限。

```typescript
await filesystem.init()
```

### `getInfo()` {/* #getinfo */}

傳回這個檔案系統執行個體的中繼資料。

```typescript
const info = filesystem.getInfo()
// { id: '...', name: 'S3Filesystem', provider: 's3', status: 'ready' }
```

### `getMountConfig()` {/* #getmountconfig */}

傳回掛載設定，供支援掛載這類檔案系統的 Sandbox 使用。

```typescript
const config = filesystem.getMountConfig()
// { type: 's3', bucket: 'my-bucket', region: 'us-east-1', ... }
```

## 掛載至 E2B Sandbox {/* #mounting-in-e2b-sandboxes */}

你可以將 S3Filesystem 掛載至 E2B Sandbox，再以存取本機目錄的方式存取儲存貯體。

```typescript
import { Workspace } from '@mastra/core/workspace'
import { S3Filesystem } from '@mastra/s3'
import { E2BSandbox } from '@mastra/e2b'

const workspace = new Workspace({
  mounts: {
    '/data': new S3Filesystem({
      bucket: 'my-bucket',
      region: 'us-east-1',
      accessKeyId: process.env.AWS_ACCESS_KEY_ID,
      secretAccessKey: process.env.AWS_SECRET_ACCESS_KEY,
    }),
  },
  sandbox: new E2BSandbox({ id: 'dev-sandbox' }),
})
```

掛載細節請參閱 [E2BSandbox 參考文件](/integrations/sandboxes/e2b)。
