# Google Drive

在 Mastra 中，有兩種使用 Google Drive 的方式：

* **Agent 的 Tool**：透過 [Mastra Connect](/docs/mastra-platform/connect)，Agent 可以在整個 Google Drive 帳戶中尋找、上傳及整理檔案。
* **[Workspace 檔案系統](#workspace-filesystem)**：使用 `@mastra/google-drive` 套件，將 Agent 的 Workspace 檔案儲存在同一個 Google Drive 資料夾。

## Connect {/* #connect */}

開始前，請依照 [Connect 設定步驟](/docs/mastra-platform/connect#get-started) 安裝 `@mastra/connect`，並設定你的平台專案。

## Workspace 檔案系統 {/* #workspace-filesystem */}

`GoogleDriveFilesystem` 會將檔案集中儲存在一個 Google Drive 資料夾。每個目錄都對應到設定的根目錄底下的一個 Drive 資料夾，路徑遵循 POSIX 語意，例如 `/notes/todo.txt`。如需介面詳細資訊，請參閱 [WorkspaceFilesystem 介面](/reference/workspace/filesystem)。

### 安裝 {/* #installation */}

```bash npm2yarn
npm install @mastra/google-drive
```

### 使用方式 {/* #usage */}

將 `GoogleDriveFilesystem` 加入 Workspace，再將該 Workspace 指派給 Agent：

```typescript
import { Agent } from '@mastra/core/agent'
import { Workspace } from '@mastra/core/workspace'
import { GoogleDriveFilesystem } from '@mastra/google-drive'

const workspace = new Workspace({
  filesystem: new GoogleDriveFilesystem({
    folderId: process.env.GOOGLE_DRIVE_FOLDER_ID!,
    accessToken: process.env.GOOGLE_DRIVE_ACCESS_TOKEN!,
  }),
})

const agent = new Agent({
  id: 'drive-agent',
  name: 'Drive Agent',
  model: '__GATEWAY_OPENAI_MODEL_LUNA__',
  workspace,
})
```

#### 身分驗證 {/* #authentication */}

使用下列任一方式進行身分驗證：

* **`accessToken`**：事先取得的 OAuth 存取權杖。請使用 `https://www.googleapis.com/auth/drive` 授權範圍，讓權杖能存取共用給已驗證身分的資料夾。
* **`getAccessToken`**：傳回權杖的回呼函式，適合由外部機制更新權杖時使用。
* **`serviceAccount`**：Google 服務帳戶。請將目標資料夾共用給服務帳戶的電子郵件地址。

##### 服務帳戶 {/* #service-account */}

後端 Agent 建議使用服務帳戶驗證。這種方式不必經過使用者同意流程，也不必自行處理權杖更新。你只需要服務帳戶 JSON 金鑰檔中的**兩個值**：`client_email` 和 `private_key`。

###### 設定服務帳戶 {/* #set-up-the-service-account */}

1. 開啟 [Google Cloud 控制台](https://console.cloud.google.com/)，選取或建立專案。
2. 前往 **API 和服務 > 程式庫**，搜尋 **Google Drive API**，再選取**啟用**。
3. 前往 **API 和服務 > 憑證**，選取**建立憑證 > 服務帳戶**，並填妥表單。角色可留空，因為 Drive 權限是透過共用資料夾授予的，與 IAM 角色無關。
4. 開啟剛建立的服務帳戶，切換到**金鑰**分頁，選取**新增金鑰 > 建立新金鑰 > JSON**。瀏覽器會下載 JSON 金鑰檔。
5. 複製 JSON 檔中的 `client_email` 值。共用 Drive 資料夾時，請使用這個地址。

###### 與服務帳戶共用雲端硬碟資料夾 {/* #share-the-drive-folder-with-the-service-account */}

服務帳戶有獨立的 Google 身分。你必須明確將 Drive 內容共用給它，它才能存取。

1. 在 [Google Drive](https://drive.google.com/) 開啟目標資料夾。
2. 選取**共用**。
3. 貼上服務帳戶的 `client_email` 電子郵件地址。
4. 將角色設為**編輯者**（可讀寫）或**檢視者**（唯讀），再選取**傳送**。
5. 從網址複製資料夾 ID，也就是 `https://drive.google.com/drive/folders/<folderId>` 中 `/folders/` 後面的部分。

:::warning

服務帳戶無法在一般的「我的雲端硬碟」資料夾中建立檔案。服務帳戶沒有個人 Drive 儲存空間配額，因此它建立的檔案必須由具備配額的實體持有。如果只共用個人 Drive 資料夾，仍可讀取檔案，但寫入時會發生配額錯誤。

如果需要寫入，請將資料夾放在**共用雲端硬碟**（舊稱團隊雲端硬碟）中，並將服務帳戶加入該共用雲端硬碟的成員名單。服務帳戶建立檔案所需的儲存空間配額由共用雲端硬碟提供。

如果只讀取個人 Drive 資料夾的內容，則不受此限制。

:::

###### 設定檔案系統 {/* #configure-the-filesystem */}

從 JSON 檔案複製 `client_email` 和 `private_key`，並設定為環境變數：

```bash filename=".env"
GOOGLE_DRIVE_FOLDER_ID=1AbCdEfGhIjKlMnOpQrStUvWxYz
GOOGLE_DRIVE_CLIENT_EMAIL=my-bot@my-project.iam.gserviceaccount.com
# Wrap the value in quotes — the key contains newlines that must be preserved.
GOOGLE_DRIVE_PRIVATE_KEY="-----BEGIN PRIVATE KEY-----\nMIIEvQIBADANBgkq...\n-----END PRIVATE KEY-----\n"
```

```typescript
import { GoogleDriveFilesystem } from '@mastra/google-drive'

const filesystem = new GoogleDriveFilesystem({
  folderId: process.env.GOOGLE_DRIVE_FOLDER_ID!,
  serviceAccount: {
    clientEmail: process.env.GOOGLE_DRIVE_CLIENT_EMAIL!,
    privateKey: process.env.GOOGLE_DRIVE_PRIVATE_KEY!,
  },
})
```

**不必**複製整個 JSON 檔案，也不必傳入 `project_id`、`client_id`、`private_key_id` 或 `token_uri` 等未使用的欄位。只有 `clientEmail` 和 `privateKey` 是必填欄位；`privateKeyId`、`scopes` 和 `subject` 皆可省略。`scopes` 預設為 `['https://www.googleapis.com/auth/drive']`。服務帳戶需要這個授權範圍，才能存取共用給它的資料夾。範圍較窄的 `drive.file` 只允許存取應用程式自行建立的檔案，因此存取共用給服務帳戶的資料夾時會收到 `404 Not Found`。

`GoogleDriveFilesystem` 會在簽署前自動正規化 `privateKey` 字串。它會去除字串兩端的引號，包括 JSON 包裝值中經過跳脫的引號，並將字面上的 `\n` 轉為實際的換行字元。它也會統一 `\r\n` 換行格式，並移除結尾的逗號。無論 `.env` 載入器如何處理這個值，金鑰都能正常使用。

###### 故障排除 {/* #troubleshoot */}

* **`404 File not found: <folderId>`**：服務帳戶沒有資料夾的存取權。請確認共用對象的地址與 `client_email` 完全相符，且資料夾 ID 與網址中的 ID 一致。
* **寫入時出現 `storageQuotaExceeded`**：資料夾位於個人的「我的雲端硬碟」。請將資料夾移到共用雲端硬碟，並將服務帳戶新增為成員。
* **`error:1E08010C:DECODER routines::unsupported`**：`privateKey` 的格式有誤。請確認該值包含完整的 PEM 區塊，並保留換行（使用字面上的 `\n` 也可以）。

#### 唯讀模式 {/* #read-only-mode */}

傳入 `readOnly: true` 可封鎖寫入作業（`writeFile`、`appendFile`、`deleteFile`、`copyFile`、`moveFile`、`mkdir`、`rmdir`）。

```typescript
const filesystem = new GoogleDriveFilesystem({
  folderId,
  accessToken,
  readOnly: true,
})
```

### 方法 {/* #methods */}

GoogleDriveFilesystem 實作 [WorkspaceFilesystem 介面](/reference/workspace/filesystem)，提供所有標準的檔案系統方法：

* `readFile(path, options?)`：下載檔案內容
* `writeFile(path, content, options?)`：上傳或覆寫檔案
* `appendFile(path, content)`：讀取檔案，在末尾加入內容後重新上傳
* `deleteFile(path, options?)`：刪除檔案
* `copyFile(src, dest, options?)`：透過 Drive 的 `files.copy` API 複製檔案
* `moveFile(src, dest, options?)`：變更檔案的上層資料夾，以移動檔案
* `mkdir(path, options?)`：建立資料夾
* `rmdir(path, options?)`：移除資料夾
* `readdir(path, options?)`：列出資料夾內容（支援 `recursive` 遞迴列舉和 `extension` 副檔名篩選）
* `stat(path)`：傳回檔案或資料夾在 Drive 中的中繼資料
* `exists(path)`：確認檔案或資料夾是否存在

### 注意事項 {/* #notes */}

* Google Drive 允許同一個資料夾內有多個同名檔案。`GoogleDriveFilesystem` 解析路徑時會採用第一個相符項目。如果是依路徑查找，請確保同一個資料夾內的名稱不重複。
* 未設定 `recursive`（預設情況）或將它設為 `true` 時，`writeFile` 會自動建立上層資料夾。若設為 `recursive: false`，上層資料夾必須已經存在。
* 寫入時會檢查 `WriteOptions` 中的 `expectedMtime`。如果儲存的 `modifiedTime` 與預期值不同，系統會拒絕寫入並擲出 `StaleFileError`，以支援開放式並行存取。
* 此 Provider 只透過內建的 `fetch` 呼叫 Drive REST 端點（`https://www.googleapis.com/drive/v3` 和 `https://www.googleapis.com/upload/drive/v3`），不需要額外的相依套件。
