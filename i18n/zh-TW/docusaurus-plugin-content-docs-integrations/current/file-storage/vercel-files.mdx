# Vercel Files

你可以將檔案存到 [FilesSDK](https://files-sdk.dev) 支援的任何儲存後端。FilesSDK 為 S3、Cloudflare R2、Google Cloud Storage、Azure Blob、Vercel Blob、MinIO、本機檔案系統等提供統一的抽象層。介面細節請參閱 [WorkspaceFilesystem 介面](/reference/workspace/filesystem)。

想用同一個轉接器和同一份程式碼連接多種儲存後端時，可使用 `FilesSDKFilesystem`。切換底層驅動程式即可沿用原本的 Workspace 設定。如果只會使用一種後端，且希望直接使用該後端專屬的設定選項，建議選用對應的 Provider，例如 [`S3Filesystem`](/integrations/file-storage/amazon-s3) 或 [`GCSFilesystem`](/integrations/file-storage/google-cloud-storage)。

## 安裝 {/* #installation */}

```bash npm2yarn
npm install @mastra/files-sdk files-sdk
```

`files-sdk` 是同儕相依套件，請搭配選用的轉接器設定。

## 用法 {/* #usage */}

選好轉接器後，用它建立 FilesSDK 的 `Files` 執行個體，再將該執行個體傳給 `FilesSDKFilesystem`。

```typescript
import { Agent } from '@mastra/core/agent'
import { Workspace } from '@mastra/core/workspace'
import { FilesSDKFilesystem } from '@mastra/files-sdk'
import { Files } from 'files-sdk'
import { s3 } from 'files-sdk/s3'

const files = new Files({
  adapter: s3({
    bucket: 'my-bucket',
    region: 'us-east-1',
  }),
})

const workspace = new Workspace({
  filesystem: new FilesSDKFilesystem({ files }),
})

const agent = new Agent({
  id: 'file-agent',
  name: 'file-agent',
  model: '__GATEWAY_ANTHROPIC_MODEL_OPUS__',
  workspace,
})
```

### 切換轉接器 {/* #swapping-adapters */}

`FilesSDKFilesystem` 可搭配任何 FilesSDK 轉接器。更換用來建立驅動程式的工廠函式，即可切換後端。

```typescript
import { Files } from 'files-sdk'
import { r2 } from 'files-sdk/r2'
import { gcs } from 'files-sdk/gcs'
import { azure } from 'files-sdk/azure'
import { neon } from 'files-sdk/neon'
import { fs } from 'files-sdk/fs'

// Cloudflare R2
const r2Files = new Files({ adapter: r2({ accountId, bucket, accessKeyId, secretAccessKey }) })

// Google Cloud Storage
const gcsFiles = new Files({ adapter: gcs({ bucket, projectId }) })

// Azure Blob
const azureFiles = new Files({ adapter: azure({ container, connectionString }) })

// Neon Object Storage (reads AWS_* variables from `neon env pull`)
const neonFiles = new Files({ adapter: neon({ bucket }) })

// Local filesystem (useful for tests and development)
const localFiles = new Files({ adapter: fs({ root: './workspace' }) })
```

完整的轉接器清單與設定選項請參閱 [FilesSDK 文件](https://files-sdk.dev)。

### 唯讀掛載 {/* #read-only-mounts */}

```typescript
const filesystem = new FilesSDKFilesystem({
  files,
  readOnly: true,
})
```

所有寫入操作（`writeFile`、`appendFile`、`deleteFile`、`copyFile`、`moveFile`、`mkdir`、`rmdir`）都會擲出 `WorkspaceReadOnlyError`，讀取則可照常進行。

## 方法 {/* #methods */}

`FilesSDKFilesystem` 實作 [WorkspaceFilesystem 介面](/reference/workspace/filesystem)，提供所有標準檔案系統方法。

* `readFile(path, options?)` - 讀取檔案內容
* `writeFile(path, content, options?)` - 將內容寫入檔案
* `appendFile(path, content)` - 在檔案末端附加內容
* `deleteFile(path, options?)` - 刪除檔案
* `copyFile(src, dest, options?)` - 複製檔案
* `moveFile(src, dest, options?)` - 移動或重新命名檔案
* `mkdir(path, options?)` - 建立目錄（在物件儲存中不會執行任何動作）
* `rmdir(path, options?)` - 刪除目錄
* `readdir(path, options?)` - 列出目錄內容
* `exists(path)` - 檢查路徑是否存在
* `stat(path)` - 取得檔案或目錄的中繼資料

### `init()` {/* #init */}

初始化檔案系統，並確認已設定的轉接器能否使用提供的憑證列出物件鍵。

```typescript
await filesystem.init()
```

### `getInfo()` {/* #getinfo */}

傳回此檔案系統執行個體的中繼資料。

```typescript
const info = filesystem.getInfo()
// { id: '...', name: 'FilesSDKFilesystem', provider: 'files-sdk', status: 'ready' }
```

### `files` {/* #files */}

底層的 FilesSDK `Files` 執行個體可透過公開屬性存取。需要直接呼叫轉接器專屬的 API 時，可使用這個屬性。

```typescript
const url = await filesystem.files.url('reports/q3.pdf')
```

## 物件儲存的運作方式 {/* #object-store-semantics */}

即使底層轉接器採用階層式結構（例如 `fs`），`FilesSDKFilesystem` 也會將設定的後端視為物件儲存，讓各轉接器的行為一致。

* **`mkdir`** 不會執行任何動作。只要有物件鍵以該目錄路徑為前綴，就視為該目錄存在。
* **`exists`** 只有在路徑與某個檔案的鍵完全相符，或至少有一個下層物件鍵以該路徑為前綴時，才會傳回 `true`。階層式轉接器中留下的空目錄不列入計算。
* **`deleteFile`** 找不到物件鍵時會擲出 `FileNotFoundError`，但傳入 `{ force: true }` 時例外。
* **`deleteFile`** 處理目錄時會交由 `rmdir({ recursive: true })` 執行，與 [`S3Filesystem`](/integrations/file-storage/amazon-s3) 和 [`GCSFilesystem`](/integrations/file-storage/google-cloud-storage) 的行為相同。
* **`moveFile`** 先呼叫 `copyFile`，再呼叫 `deleteFile`。整個過程並非 **不可分割的原子操作**。如果複製成功，但刪除來源檔案失敗，來源和目的地的檔案都會保留。
* **`appendFile`** 會先讀取、再修改，最後寫回。若同時對同一個物件鍵附加內容，各次寫入可能互相覆蓋。這是物件儲存本身的特性，其他採用物件儲存的工具也會遇到。
* **`readdir({ recursive: true })`** 會一併列出中間層的目錄項目，例如同時列出 `a/b` 和 `a/b/c.txt`。
