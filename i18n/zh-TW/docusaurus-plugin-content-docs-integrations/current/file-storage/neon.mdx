# Neon Object Storage

[Neon Object Storage](https://neon.com/docs/storage/overview)是 Neon 專案內建的 S3 相容儲存服務。每個儲存貯體隸屬於一個分支。建立子分支時，子分支會以寫入時複製的方式取得父分支檔案的副本。Mastra 透過 [`S3Filesystem`](/integrations/file-storage/amazon-s3) 連線至此服務，讓 Agent 使用的 Workspace 檔案與 [Neon Postgres](/integrations/databases/neon) 資料庫中的資料列一同建立分支。介面細節請參閱 [Workspace 檔案系統介面](/reference/workspace/filesystem)。

## 開始之前 {/* #before-you-begin */}

你需要：

- 一個位於支援物件儲存區域的 [Neon](https://neon.com) 專案。支援的區域有 `aws-us-east-1`、`aws-us-east-2`、`aws-eu-central-1` 或 `aws-ap-southeast-1`
- [Neon CLI](https://neon.com/docs/cli/install)

## 安裝 {/* #installation */}

```bash npm2yarn
npm install @mastra/s3 @neon/config
```

## 建立儲存貯體 {/* #create-a-bucket */}

在專案根目錄的 `neon.ts` 中宣告儲存貯體：

```typescript title="neon.ts"
import { defineConfig } from '@neon/config/v1'

export default defineConfig({
  buckets: {
    'agent-files': {},
  },
})
```

儲存貯體預設為私人。若要開放匿名讀取，請設定 `access: 'public_read'`。

將目錄連結至 Neon 專案，接著在連結的分支上建立儲存貯體：

```bash
neon link
neon deploy
```

`neon deploy` 會建立儲存貯體，並將分支的儲存憑證寫入 `.env`。若 `.env` 不存在，則寫入 `.env.local`。`mastra dev` 可載入這兩種檔案。

若要在不使用 `neon.ts` 的情況下建立儲存貯體，請先執行 `neon bucket create agent-files`，再用下列指令手動擷取憑證：

```bash
neon env pull --service object-storage
```

## 環境變數 {/* #environment-variables */}

Neon 會為物件儲存設定下列四個環境變數：

| 變數 | 值 |
| - | - |
| `AWS_ACCESS_KEY_ID` | 分支憑證的存取金鑰 ID |
| `AWS_SECRET_ACCESS_KEY` | 同一組憑證的秘密存取金鑰 |
| `AWS_ENDPOINT_URL_S3` | 分支的 S3 端點 |
| `AWS_REGION` | 專案所在的區域，例如 `us-east-2` |

憑證可用於核發該憑證的分支及其子分支。在 [Neon Function](/integrations/deploy/neon) 中，Neon 會注入這些環境變數，因此不需要 `.env` 檔案。

## 使用方式 {/* #usage */}

將這些環境變數傳給 `S3Filesystem`，再將 Workspace 指派給 Agent：

```typescript title="src/mastra/agents/file-agent.ts"
import { Agent } from '@mastra/core/agent'
import { Workspace } from '@mastra/core/workspace'
import { S3Filesystem } from '@mastra/s3'

const workspace = new Workspace({
  filesystem: new S3Filesystem({
    bucket: 'agent-files',
    region: process.env.AWS_REGION!,
    endpoint: process.env.AWS_ENDPOINT_URL_S3,
    accessKeyId: process.env.AWS_ACCESS_KEY_ID,
    secretAccessKey: process.env.AWS_SECRET_ACCESS_KEY,
  }),
})

export const fileAgent = new Agent({
  id: 'file-agent',
  name: 'file-agent',
  instructions: 'You manage files in the workspace.',
  model: '__GATEWAY_ANTHROPIC_MODEL_OPUS__',
  workspace,
})
```

請務必設定 `endpoint`。Neon 只接受路徑樣式請求，而 `S3Filesystem` 必須在設定 `endpoint` 後才會採用這種樣式。若省略此選項，AWS SDK 仍會讀取 `AWS_ENDPOINT_URL_S3`，但會送出虛擬主機樣式請求（`agent-files.<endpoint-host>`），導致 TLS 驗證失敗。

`S3Filesystem` 會辨識 Neon 端點，並將 `icon` 設為 `'neon'`、`displayName` 設為 `Neon Object Storage`，讓 Studio 在檔案樹中顯示 Neon 掛載項目。

使用 `prefix`，即可在同一個儲存貯體內為每個 Agent、使用者或對話串各自指定資料夾：

```typescript
const filesystem = new S3Filesystem({
  bucket: 'agent-files',
  prefix: `users/${userId}`,
  region: process.env.AWS_REGION,
  endpoint: process.env.AWS_ENDPOINT_URL_S3,
  accessKeyId: process.env.AWS_ACCESS_KEY_ID,
  secretAccessKey: process.env.AWS_SECRET_ACCESS_KEY,
})
```

前綴會限制檔案系統可定址的物件鍵範圍，不提供授權隔離。

## 分支 {/* #branches */}

每個分支都有自己的儲存端點。新分支一建立，就會取得當時父分支中的所有儲存貯體與檔案。子分支上的寫入和刪除不會影響父分支，之後寫入父分支的內容也不會出現在子分支。

透過分支，預覽部署、測試執行或實驗性 Agent 都能取得正式環境檔案的完整副本，無須實際複製資料：

```bash
neon checkout preview/new-tools --create
```

`neon checkout --create` 會建立分支，在 `.neon` 中固定該分支，並將子分支的環境變數連同儲存端點擷取至 `.env`。父分支的憑證也適用於子分支，但端點必須使用子分支的端點。若要捨棄子分支的檔案，刪除該分支即可。

## Skill Blob 儲存 {/* #skill-blob-storage */}

`S3BlobStore` 用來儲存 [`MastraEditor`](/reference/editor/mastra-editor) 產生、可依內容定址的 Skill Blob。它接受相同的連線選項：

```typescript
import { S3BlobStore } from '@mastra/s3'

const blobStore = new S3BlobStore({
  bucket: 'agent-files',
  region: process.env.AWS_REGION!,
  endpoint: process.env.AWS_ENDPOINT_URL_S3,
  accessKeyId: process.env.AWS_ACCESS_KEY_ID,
  secretAccessKey: process.env.AWS_SECRET_ACCESS_KEY,
})
```

## FilesSDK 配接器 {/* #filessdk-adapter */}

如果使用 [`FilesSDKFilesystem`](/integrations/file-storage/vercel-files)，`neon` 配接器會讀取相同的 `AWS_*` 環境變數。請一併安裝配接器會載入的 AWS SDK 套件：

```bash npm2yarn
npm install @mastra/files-sdk files-sdk @aws-sdk/client-s3 @aws-sdk/s3-presigned-post @aws-sdk/s3-request-presigner
```

```typescript
import { Workspace } from '@mastra/core/workspace'
import { FilesSDKFilesystem } from '@mastra/files-sdk'
import { Files } from 'files-sdk'
import { neon } from 'files-sdk/neon'

const workspace = new Workspace({
  filesystem: new FilesSDKFilesystem({
    files: new Files({ adapter: neon({ bucket: 'agent-files' }) }),
    icon: 'neon',
    displayName: 'Neon Object Storage',
  }),
})
```
