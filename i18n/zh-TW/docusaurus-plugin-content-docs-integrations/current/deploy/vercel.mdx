# Vercel 部署工具

使用 `@mastra/deployer-vercel` 將 Mastra 伺服器部署為 Vercel 上的無伺服器函式。部署工具會打包程式碼，並產生符合 Vercel [Build Output API](https://vercel.com/docs/build-output-api/v3) 規格的 `.vercel/output` 目錄，無須額外設定即可部署。

:::note
本指南說明如何部署 [Mastra 伺服器](/docs/server/overview)。如果你使用[伺服器轉接器](/docs/server/server-adapters)或 [Web 框架](/docs/deployment/web-framework)，請依照該框架的一般流程部署。
:::

## 開始之前 {/* #before-you-begin */}

你需要一個 [Mastra 應用程式](/docs)和一個 [Vercel](https://vercel.com/) 帳號。

:::warning
Vercel Functions 使用暫存檔案系統，因此你設定的所有儲存空間（包括 Observability 的儲存空間）都必須託管在外部。如果你在 [LibSQLStore](/integrations/databases/libsql) 中使用檔案 URL，請改用託管在遠端的資料庫。
:::

## 安裝 {/* #installation */}

將 `@mastra/deployer-vercel` 套件加入專案：

```bash npm2yarn
npm install @mastra/deployer-vercel@latest
```

匯入 [`VercelDeployer`](/reference/deployer/vercel)，並在 Mastra 設定中將它指定為部署工具：

```typescript title="src/mastra/index.ts"
import { Mastra } from '@mastra/core'
// highlight-next-line
import { VercelDeployer } from '@mastra/deployer-vercel'

export const mastra = new Mastra({
  // highlight-next-line
  deployer: new VercelDeployer(),
})
```

## 部署 {/* #deploy */}

<Steps>
  <StepItem>
    將專案推送到遠端 Git Provider（例如 GitHub），再將儲存庫連接至 Vercel。

    Vercel 預設會執行 `npm run build`，進而觸發 `mastra build`。如果尚未設定建置指令碼，請在 `package.json` 中加入 `"build": "mastra build"`。

    :::note

    請記得設定執行應用程式所需的環境變數，例如 [Model Provider](/models/providers) 的 API 金鑰。

    :::
  </StepItem>

  <StepItem>
    準備就緒後，點選 **Deploy**，並等待首次部署完成。
  </StepItem>

  <StepItem>
    前往 `https://<your-project>.vercel.app/api/agents` 驗證部署；該網址應傳回 Agent 的 JSON 清單。

    Mastra 伺服器會在每個端點的路徑前加上 `/api`，因此送出請求時，請在網址中加上這個前綴。
  </StepItem>

  <StepItem>
    現在可以透過 HTTP 呼叫 Mastra 端點。

    :::warning
    在公開端點之前，請先設定[身分驗證](/docs/auth/overview)。
    :::
  </StepItem>
</Steps>

## Studio {/* #studio */}

啟用 `studio` 選項，即可將 [Studio](/docs/studio/overview) 與 API 一起部署。Studio 會部署為由 Vercel Edge CDN 提供的靜態資源，因此不會消耗函式呼叫次數。

```typescript title="src/mastra/index.ts"
import { Mastra } from '@mastra/core'
import { VercelDeployer } from '@mastra/deployer-vercel'

export const mastra = new Mastra({
  deployer: new VercelDeployer({
    // highlight-next-line
    studio: true,
  }),
})
```

部署後，可透過根 URL（`https://<your-project>.vercel.app/`）使用 Studio，API 仍位於 `/api/*`。Studio 會自動連線至同源 API，因此不需要額外的環境變數。

Studio 的頁面由 CDN 提供，其餘路徑都會轉送到你的伺服器，因此透過 [`registerApiRoute()`](/docs/server/custom-api-routes) 新增的路由仍可透過各自的路徑存取。請避免讓自訂路由使用 Studio 已有的路徑（例如 `/agents` 或 `/workflows`），因為 Studio 會優先處理這些路徑。

:::warning
Studio 連線至 Mastra 伺服器後，即可完整存取你的 Agent、Workflow 和 Tool。請務必在正式環境中採取適當的保護措施，例如要求身分驗證或限制透過 VPN 存取，以防止未經授權的存取。
:::

## 選用的覆寫設定 {/* #optional-overrides */}

Vercel 部署工具支援將設定選項寫入 Vercel Output API 的函式設定。`maxDuration`、`memory` 和 `regions` 等可用選項，請參閱 [`VercelDeployer` 參考文件](/reference/deployer/vercel#constructor-options)。

請求逾時有兩項獨立的限制。`maxDuration`（單位為秒）限制 Vercel 允許函式執行的最長時間；Mastra 的 `server.timeout`（單位為毫秒，預設為 `180000`）則限制 Mastra 在回傳 `504 Gateway Timeout` 前最多會等待多久。只提高 `maxDuration` 不會延長 Mastra 的 180 秒上限，因此執行 Workflow 等需要較長時間的請求時，必須同時調整兩項設定：

```typescript title="src/mastra/index.ts"
export const mastra = new Mastra({
  deployer: new VercelDeployer({ maxDuration: 600 }),
  server: { timeout: 600_000 },
})
```

詳情請參閱[請求逾時](/reference/deployer/vercel#request-timeouts)。

## Observability {/* #observability */}

無伺服器函式可能在回傳回應後立即終止。尚未完成的非同步作業（例如傳送遙測資料）可能因此中斷。等待 `flush()` 完成，可確保所有 Trace 都在函式結束前送出。

```typescript title="api/chat.ts"
import type { VercelRequest, VercelResponse } from '@vercel/node'
import { mastra } from '../src/mastra'

export default async function handler(req: VercelRequest, res: VercelResponse) {
  const { message } = req.body
  const agent = mastra.getAgent('myAgent')
  const result = await agent.generate([{ role: 'user', content: message }])

  await mastra.observability.flush()

  return res.json(result)
}
```

:::warning
Vercel 部署工具不會呼叫 `flush`。如有需要，請自行包裝處理函式，加入在回傳回應前執行的呼叫邏輯。你也可以部署到持續執行的伺服器，例如[虛擬機器](/integrations/deploy/digital-ocean)，就不會遇到這個問題。
:::
