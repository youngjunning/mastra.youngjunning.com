# Amazon Bedrock AgentCore

透過 [AgentCore CLI](https://github.com/aws/agentcore-cli) 將 Mastra 應用程式部署至 [Amazon Bedrock AgentCore Runtime](https://docs.aws.amazon.com/bedrock-agentcore/)。CLI 會產生可帶入自有程式碼（BYO）的 TypeScript 專案骨架，使用 AWS CodeBuild 建置容器，並佈建執行環境。部署時無須啟動本機的 Docker 常駐程序。

本指南沿用 [AgentCore 官方 TypeScript 教學](https://docs.aws.amazon.com/bedrock-agentcore/latest/devguide/runtime-get-started-cli-typescript.html)的步驟，並調整範例，讓呼叫處理常式能呼叫 Mastra Agent。

:::note

若要透過 Lambda 部署完整的 Mastra 伺服器，請參閱 [AWS Lambda 指南](/integrations/deploy/aws-lambda)。若要部署至長時間運作的虛擬機器，請參閱 [Amazon EC2 指南](/integrations/deploy/amazon-ec2)。

:::

## 開始之前 {/* #before-you-begin */}

請先備妥：

* 具備 Amazon Bedrock AgentCore、AWS CodeBuild、Amazon ECR 和 AWS IAM 所需權限的 [AWS 帳戶](https://aws.amazon.com/)
* 已安裝並完成身分驗證的 [AWS CLI](https://aws.amazon.com/cli/)（使用 `aws configure` 或 `aws sso login`）
* 已安裝 Node.js `v22.13.0` 或更新版本
* [Docker](https://www.docker.com/)、[Podman](https://podman.io/) 或 [Finch](https://runfinch.com/)，供 `agentcore dev` 在本機測試使用（`agentcore deploy` 無須安裝）

只有[部分 AWS 區域](https://docs.aws.amazon.com/bedrock-agentcore/latest/devguide/agentcore-regions.html)提供 Amazon Bedrock AgentCore Runtime。請選擇可使用 AgentCore 的區域，並確認預計呼叫的基礎模型已在該區域啟用。

## 建立 AgentCore 專案 {/* #create-a-new-agentcore-project */}

執行下列指令以建立 AgentCore 專案：

```bash npm2yarn
npx @aws/agentcore create --name MastraOnAgentCore --no-agent
```

切換至剛建立的 `MastraOnAgentCore` 目錄：

```bash
cd MastraOnAgentCore
```

初始化一個使用自有程式碼（BYO）的 TypeScript Agent，位置為 `app/MastraAgent`：

```bash npm2yarn
npx @aws/agentcore add agent --name MastraAgent --type byo --build Container --language TypeScript --framework Strands --model-provider Bedrock --code-location app/MastraAgent
```

CLI 會更新 `agentcore/agentcore.json`，並建立空白的 `app/MastraAgent` 目錄。

## 設定 Agent 專案 {/* #set-up-the-agent-project */}

切換至 `app/MastraAgent` 目錄，初始化 Node.js 專案：

```bash
cd app/MastraAgent
npm init --init-type=module -y
```

安裝必要的相依套件。`bedrock-agentcore` 套件提供 `BedrockAgentCoreApp` HTTP 伺服器，實作 [AgentCore Runtime 服務契約](https://docs.aws.amazon.com/bedrock-agentcore/latest/devguide/runtime-service-contract.html)。有了 `@ai-sdk/amazon-bedrock` 和 `@aws-sdk/credential-providers`，Mastra Agent 就能透過 AgentCore Runtime 的執行角色呼叫 Bedrock。

```bash npm2yarn
npm install bedrock-agentcore @opentelemetry/auto-instrumentations-node @ai-sdk/amazon-bedrock @aws-sdk/credential-providers --legacy-peer-deps
```

再安裝 TypeScript 與相關的開發用相依套件：

```bash npm2yarn
npm install --save-dev typescript @types/node tsx
```

執行 [`mastra init`](/reference/cli/mastra#mastra-init) 建立 Mastra 專案。出現提示時可任選一個 Provider，下一步會覆寫這項設定。

```bash npm2yarn
npx mastra@latest init
```

將產生的 `src/mastra/agents/weather-agent.ts` 換成下列內容，改用 Amazon Bedrock。下一步會移除儲存層，因此這裡一併移除原本的 `memory: new Memory()`。

```ts title="app/MastraAgent/src/mastra/agents/weather-agent.ts"
import { Agent } from '@mastra/core/agent'
import { createAmazonBedrock } from '@ai-sdk/amazon-bedrock'
import { fromNodeProviderChain } from '@aws-sdk/credential-providers'
import { weatherTool } from '../tools/weather-tool.js'

const bedrock = createAmazonBedrock({
  credentialProvider: fromNodeProviderChain(),
})

export const weatherAgent = new Agent({
  id: 'weather-agent',
  name: 'Weather Agent',
  instructions:
    'You are a helpful weather assistant. Use the weatherTool to fetch current weather data.',
  model: bedrock('us.anthropic.claude-sonnet-4-6'),
  tools: { weatherTool },
})
```

:::note

`fromNodeProviderChain()` 讓 Agent 依照 SDK 的標準憑證解析鏈取得 AWS 憑證，可用來源包括環境變數、共用設定檔、SSO，以及容器或 EC2 角色。

:::

替換產生的 `src/mastra/index.ts`，移除預設的檔案式儲存與可觀測性設定。AgentCore Runtime 容器以非 root 使用者身分執行，應用程式目錄為唯讀。在這種環境中，預設的 `LibSQLStore` 無法開啟 `./mastra.db`，導致執行環境無法啟動。

```ts title="app/MastraAgent/src/mastra/index.ts"
import { Mastra } from '@mastra/core/mastra'
import { PinoLogger } from '@mastra/loggers'
import { weatherWorkflow } from './workflows/weather-workflow.js'
import { weatherAgent } from './agents/weather-agent.js'

export const mastra = new Mastra({
  workflows: { weatherWorkflow },
  agents: { weatherAgent },
  logger: new PinoLogger({
    name: 'Mastra',
    level: 'info',
  }),
})
```

建立 `tsconfig.json`，填入下列內容：

```json title="app/MastraAgent/tsconfig.json"
{
  "compilerOptions": {
    "outDir": "./dist",
    "rootDir": ".",
    "strict": true,
    "esModuleInterop": true,
    "skipLibCheck": true,
    "types": ["node"],
    "declaration": true,
    "target": "ES2022",
    "module": "NodeNext",
    "moduleResolution": "NodeNext",
    "forceConsistentCasingInFileNames": true
  },
  "include": ["*.ts", "src/**/*"],
  "exclude": ["node_modules", "dist"]
}
```

:::note

加入 `tsconfig.json` 後，編輯器會在產生的 `src/mastra` 專案中顯示錯誤，因為這份設定要求匯入路徑包含副檔名。依照下例加上 `.js` 即可修正：

```ts title="app/MastraAgent/src/mastra/index.ts"
// Before
import { weatherWorkflow } from './workflows/weather-workflow'
// After
import { weatherWorkflow } from './workflows/weather-workflow.js'
```

:::

更新 `package.json`，指定進入點與建置指令碼。使用 `npm pkg set` 可保留 `mastra init` 加入的相依套件。

```bash
npm pkg set main=dist/agent.js scripts.build=tsc scripts.start="node dist/agent.js" scripts.dev="npx tsx --watch agent.ts"
```

## 初始化 Agent {/* #initialize-the-agent */}

建立 `agent.ts`。每次收到 `POST /invocations` 請求，系統就會執行其中的處理常式。請在處理常式內取得 Mastra Agent 並呼叫它：

```ts title="app/MastraAgent/agent.ts"
import { BedrockAgentCoreApp } from 'bedrock-agentcore/runtime'
import { mastra } from './src/mastra/index.js'

const app = new BedrockAgentCoreApp({
  invocationHandler: {
    process: async (payload, context) => {
      const { prompt } = payload as { prompt: string }

      const agent = mastra.getAgentById('weather-agent')
      const response = await agent.generate(prompt, {
        runId: context.sessionId,
      })

      return response.text
    },
  },
})

app.run()
```

執行 `npm run build`，確認專案可成功編譯。

## 建立 Dockerfile {/* #create-a-dockerfile */}

在 `app/MastraAgent` 目錄中建立 `Dockerfile`。容器部署採用 Docker 多階段建置，建置階段會將 TypeScript 編譯成 JavaScript，正式環境階段只執行編譯後的程式。基於安全考量，映像檔會以非 root 使用者身分執行，並公開 8080（HTTP）、8000（MCP）與 9000（A2A）連接埠。啟動時會自動載入 OpenTelemetry 檢測功能。

```dockerfile title="app/MastraAgent/Dockerfile"
FROM node:22-slim AS builder

WORKDIR /app
COPY package*.json ./
RUN npm ci
COPY . .
RUN npm run build

FROM node:22-slim
WORKDIR /app
ENV AWS_REGION=us-east-1
COPY --from=builder /app/dist ./dist
COPY --from=builder /app/node_modules ./node_modules
COPY --from=builder /app/package*.json ./

RUN useradd -m bedrock_agentcore
USER bedrock_agentcore

EXPOSE 8080 8000 9000
CMD ["node", "--require", "@opentelemetry/auto-instrumentations-node/register", "dist/agent.js"]
```

:::note

請依 Bedrock 模型 ID 的前綴（`us.`、`jp.`、`eu.` 或 `global.`）選擇相符的 `AWS_REGION`。

:::

另外建立 `.dockerignore`，將不必要的檔案排除在 Docker 建置內容之外：

```bash
node_modules
dist
.git
*.log
```

## 測試 Agent {/* #test-your-agent */}

回到專案根目錄：

```bash
cd ../..
```

在本機啟動 Agent 以進行測試：

```bash npm2yarn
npx @aws/agentcore dev --runtime MastraAgent
```

另開一個終端機，送出測試請求：

```bash npm2yarn
npx @aws/agentcore dev "What is the weather in Tokyo?"
```

## 部署 Agent {/* #deploy-your-agent */}

在 `agentcore/aws-targets.json` 中指定 AWS 帳戶與區域：

```json title="agentcore/aws-targets.json"
[
  {
    "name": "default",
    "account": "123456789012",
    "region": "us-east-1"
  }
]
```

將 Agent 部署至 AgentCore Runtime。CLI 會使用 AWS CodeBuild 建置映像檔、將映像檔推送至 Amazon ECR，接著建立執行環境及 `DEFAULT` 端點。

```bash npm2yarn
npx @aws/agentcore deploy
```

:::note

部署前，請在 `agentcore/agentcore.json` 中該 Agent 的 `environmentVariables` 欄位下設定 Provider API 金鑰與其他機密資訊。

:::

## 驗證部署結果 {/* #verify-your-deployment */}

執行 `agentcore status` 查看執行環境的 ARN、端點和近期呼叫記錄，再從 CLI 呼叫部署完成的 Agent：

```bash
npx @aws/agentcore invoke "What is the weather in Tokyo?"
```

若要在 token 產生時即時接收串流輸出，請使用 `--stream`：

```bash
npx @aws/agentcore invoke --stream "Plan a 3-day trip to Tokyo"
```
