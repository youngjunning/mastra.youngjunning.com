# Azure App Services

將 Mastra 應用程式部署至 Azure App Services。

:::note
本指南說明如何部署 [Mastra 伺服器](/docs/server/overview)。如果你使用[伺服器轉接器](/docs/server/server-adapters)或 [Web 框架](/docs/deployment/web-framework)，請依照該框架的一般流程部署。
:::

## 開始之前 {/* #before-you-begin */}

你需要準備：

- 一個 [Mastra 應用程式](/docs)
- 一個具有有效訂閱的 [Azure 帳戶](https://azure.microsoft.com/)
- 一個包含 Mastra 應用程式的 [GitHub 儲存庫](https://github.com/)

:::warning
Azure App Services 的部分定價層級使用暫存檔案系統，因此重新部署時會遺失所有本機資料庫檔案。如果你的 [LibSQLStore](/integrations/databases/libsql) 使用本機檔案，請改為連線至相容於 LibSQL 的遠端資料庫（例如 [Turso](https://turso.tech/)）。
:::

## 建立新的 App Service {/* #create-a-new-app-service */}

以下步驟會說明如何建立新的 Azure App Service 來託管 Mastra 應用程式。這會為應用程式設定執行所需的基礎架構和環境。

<Steps>
  <StepItem>
    登入 [Azure Portal](https://portal.azure.com)，前往 **[App Services](https://docs.microsoft.com/en-us/azure/app-service/)**，或在頂端搜尋列搜尋該項目。選取 **Create** 以建立新的 App Service，再從下拉式選單中選取 **Web App**。
  </StepItem>

  <StepItem>
    設定 App Service 的下列項目：

    - **Subscription**：選取你的 Azure 訂閱
    - **Resource Group**：建立新的資源群組，或選取現有的資源群組
    - **Instance name**：為應用程式輸入唯一名稱（這個名稱會成為 URL 的一部分）
    - **Publish**：選取 **Code**
    - **Runtime stack**：選取 **Node 22 LTS**
    - **Operating System**：選取 **Linux**
    - **Region**：選擇鄰近使用者的區域
    - **Linux Plan**：視所選區域而定，你可能可以選擇方案。若有此選項，請選擇符合需求的方案。
    - 選取 **Review + Create**，等待驗證完成後，再選取 **Create**。
  </StepItem>

  <StepItem>
    新的部署已觸發。等待部署完成後，在後續步驟區段選取 **Go to resource**。
  </StepItem>

  <StepItem>
    設定 GitHub 部署前，請先設定環境變數。在左側側邊欄前往 **Settings** > **Environment variables**，然後新增所需的環境變數，例如：

    - Model Provider 的 API 金鑰（例如 `OPENAI_API_KEY`）
    - 資料庫連線字串
    - Mastra 應用程式所需的其他設定值

    選取 **Apply** 以儲存變更。
  </StepItem>
</Steps>

## 透過 GitHub 部署 {/* #github-deployment */}

依照下列步驟，將 Azure App Service 連結至 GitHub 儲存庫，以啟用持續部署。每次將變更推送到儲存庫時，Azure 都會自動建置並部署應用程式。

<Steps>
  <StepItem>
    在左側側邊欄前往 **Deployment Center**，選取 **GitHub** 做為部署來源。如果尚未在 Azure 中完成 GitHub 驗證，請登入 GitHub。

    在此範例中，請繼續使用 [GitHub Actions](https://docs.github.com/en/actions) 做為 Provider，並選取組織、儲存庫和分支。

    Azure 會產生 GitHub Workflow 檔案，你可以先預覽再繼續。選取 **Save**（按鈕位於頁面頂端）。
  </StepItem>

  <StepItem>
    Azure 建立 Workflow 後，會觸發一次 GitHub Actions 執行，並將 Workflow 檔案合併至你的分支。請**取消這次初始執行**，因為在完成必要修改前，這次執行會失敗。

    :::warning
    Azure 產生的預設 Workflow 在部署 Mastra 應用程式時會失敗，因此需要修改。
    :::

    將最新變更拉取到本機儲存庫，並修改產生的 Workflow 檔案（`.github/workflows/main_<your-app-name>.yml`）：
  </StepItem>

  <StepItem>
    找到名為「npm install, build, and test」的步驟，然後進行以下修改：

    - 將步驟名稱改為「npm install and build」
    - 如果 Mastra 應用程式尚未設定可正常執行的測試，請從 run 區段移除 `npm test` 指令，因為預設的測試指令稿會執行失敗並中斷部署。如果測試可以正常執行，就可以保留測試指令。
  </StepItem>

  <StepItem>
    找到「Zip artifact for deployment」步驟，將其中的 zip 指令替換成以下指令：

    ```yaml
    run: (cd .mastra/output && zip ../../release.zip -r .)
    ```

    這樣一來，部署套件只會包含 `.mastra/output` 中的建置產物。
  </StepItem>

  <StepItem>
    提交並推送 Workflow 的變更。Azure 儀表板中的 **Deployment Center** 會自動觸發建置。請持續查看部署進度，直到部署成功完成。
  </StepItem>
</Steps>

## 驗證部署結果 {/* #verify-your-deployment */}

建置成功後，請稍候片刻，讓應用程式啟動。您可以使用 Azure 入口網站 **Overview** 索引標籤中提供的預設 URL，存取已部署的應用程式。應用程式網址為 `https://<your-app-name>.azurewebsites.net`。

從 Azure 入口網站複製 URL，然後在瀏覽器中前往 `https://<your-app-name>.azurewebsites.net/api/agents`。頁面應顯示 Agent 的 JSON 清單。

現在你可以透過 HTTP 呼叫 Mastra 端點。

:::warning
公開端點前，請先設定[身分驗證](/docs/auth/overview)。
:::
