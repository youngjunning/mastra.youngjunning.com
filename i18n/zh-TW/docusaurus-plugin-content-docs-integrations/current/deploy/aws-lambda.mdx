# AWS Lambda

透過 Docker 容器與 [AWS Lambda Web Adapter](https://github.com/awslabs/aws-lambda-web-adapter)，即可將 Mastra 應用程式部署到 AWS Lambda。Mastra 伺服器會以容器化 Lambda 函式的形式執行，並自動調整規模。

:::注意
本指南說明如何部署 [Mastra 伺服器](/docs/server/overview)。如果你使用[伺服器轉接器](/docs/server/server-adapters)或 [Web 框架](/docs/deployment/web-framework)，請依該框架的慣用流程部署。
:::

## 開始之前 {/* #before-you-begin */}

開始前請準備：

* 一個 [Mastra 應用程式](/docs)
* 一個具備 Lambda、ECR 和 IAM 操作權限的 [AWS 帳戶](https://aws.amazon.com/)
* 安裝 **[AWS CLI](https://aws.amazon.com/cli/)**，並執行 `aws configure` 設定身分驗證
* 安裝並啟動 **[Docker](https://www.docker.com/)**

:::警告
AWS Lambda 使用暫時性的檔案系統，本機資料庫檔案會在兩次呼叫之間遺失。如果 [LibSQLStore](/integrations/databases/libsql) 使用本機檔案，請改為連線至相容於 LibSQL 的遠端資料庫，例如 [Turso](https://turso.tech/)。
:::

## 建立 Dockerfile {/* #create-a-dockerfile */}

在專案的根目錄建立 `Dockerfile`：

```dockerfile title="Dockerfile"
FROM node:22-alpine

WORKDIR /app

# Install dependencies
COPY package*.json ./
RUN npm ci

# Copy source and build Mastra
COPY src ./src
RUN npx mastra build

# Alpine compatibility for some native deps
RUN apk add --no-cache gcompat

# Add the Lambda Web Adapter
COPY --from=public.ecr.aws/awsguru/aws-lambda-adapter:0.9.1 /lambda-adapter /opt/extensions/lambda-adapter

# Run as non-root
RUN addgroup -g 1001 -S nodejs && \
  adduser -S mastra -u 1001 && \
  chown -R mastra:nodejs /app

USER mastra

# Adapter / app configuration
ENV PORT=8080
ENV NODE_ENV=production
ENV AWS_LWA_READINESS_CHECK_PATH="/api"

# Start the Mastra server
CMD ["node", ".mastra/output/index.mjs"]
```

:::注意
這個 Dockerfile 使用 npm。如果你使用 pnpm、yarn 或其他套件管理工具，請配合調整指令。例如，`npm ci` 無法使用 pnpm 的鎖定檔。
:::

## 建置並推送 Docker 映像 {/* #build-and-push-the-docker-image */}

<Steps>
  <StepItem>
    設定部署所需的環境變數。請為 ECR 和 Lambda 等 AWS 服務選用同一個區域，以免在其他區域找不到所需的資源：

    ```bash
    export PROJECT_NAME="your-mastra-app"
    export AWS_REGION="us-east-1"
    export AWS_ACCOUNT_ID=$(aws sts get-caller-identity --query Account --output text)
    ```
  </StepItem>

  <StepItem>
    建置 Docker 映像。請停用 BuildKit，以確保映像與 Lambda 的容器執行環境相容：

    ```bash
    export DOCKER_BUILDKIT=0
    docker build --platform linux/arm64 -t "$PROJECT_NAME" .
    ```

    :::注意
    BuildKit 預設產生的映像格式可能與 Lambda 不相容。設定 `DOCKER_BUILDKIT=0` 即可使用傳統建置工具，產生 Lambda 能穩定接受的映像格式。
    :::
  </StepItem>

  <StepItem>
    建立 Amazon ECR 儲存庫，用來存放 Docker 映像：

    ```bash
    aws ecr create-repository --repository-name "$PROJECT_NAME" --region "$AWS_REGION"
    ```
  </StepItem>

  <StepItem>
    登入 Amazon ECR：

    ```bash
    aws ecr get-login-password --region "$AWS_REGION" | \
      docker login --username AWS --password-stdin \
      "$AWS_ACCOUNT_ID.dkr.ecr.$AWS_REGION.amazonaws.com"
    ```
  </StepItem>

  <StepItem>
    為映像加上標籤，再推送到 ECR：

    ```bash
    docker tag "$PROJECT_NAME":latest \
      "$AWS_ACCOUNT_ID.dkr.ecr.$AWS_REGION.amazonaws.com/$PROJECT_NAME":latest

    docker push \
      "$AWS_ACCOUNT_ID.dkr.ecr.$AWS_REGION.amazonaws.com/$PROJECT_NAME":latest
    ```
  </StepItem>
</Steps>

## 建立 Lambda 函式 {/* #create-the-lambda-function */}

<Steps>
  <StepItem>
    開啟 [AWS Lambda 主控台](https://console.aws.amazon.com/lambda/)，點選 **Create function**。確認目前選取的區域與建立 ECR 儲存庫時所用的區域相同。
  </StepItem>

  <StepItem>
    選取 **Container image**，接著設定函式：

    * **函式名稱**：輸入名稱，例如 `mastra-app`。
    * **容器映像 URI**：點選 **Browse images**，選取你的 ECR 儲存庫，再選取 `latest` 標籤。
    * **架構**：選取 **arm64**。

    點選 **Create function** 建立 Lambda 函式。
  </StepItem>

  <StepItem>
    設定記憶體與逾時時間。前往 **Configuration** > **General configuration**，點選 **Edit**：

    * **記憶體**：512 MB，可依應用程式的需求調整。
    * **逾時時間**：至少 1 分鐘。對大多數 Mastra 應用程式而言，預設的 3 秒太短。

    點選 **Save**。
  </StepItem>

  <StepItem>
    前往 **Configuration** > **Environment variables**，點選 **Edit**，再新增 Mastra 應用程式所需的環境變數：

    * `OPENAI_API_KEY`：若使用 OpenAI，請填入 OpenAI API 金鑰。
    * `ANTHROPIC_API_KEY`：若使用 Anthropic，請填入 Anthropic API 金鑰。
    * 視需要新增其他 Provider 專用的 API 金鑰等設定。例如，LibSQL 搭配 Turso 使用時，請新增 `TURSO_DATABASE_URL` 和 `TURSO_AUTH_TOKEN`。

    點選 **Save**。
  </StepItem>

  <StepItem>
    啟用函式 URL，讓外部可以存取。前往 **Configuration** > **Function URL**，點選 **Create function URL**：

    * **驗證類型**：選取 **NONE**，允許公開存取。
    * 在 **Additional settings** 中勾選 **Configure cross-origin resource sharing (CORS)**，再設定以下欄位：
      * **允許的來源**：`*`
      * **允許的標頭**：`content-type`。若搭配 CloudFront 或 API Gateway 等服務，還須允許 `x-amzn-request-context`。
      * **允許的 HTTP 方法**：`*`

    點選 **Save**。
  </StepItem>
</Steps>

## 驗證部署結果 {/* #verify-your-deployment */}

<Steps>
  <StepItem>
    從 Lambda 主控台複製 **Function URL**，在瀏覽器開啟 `<your-function-url>/api/agents`。畫面上應會顯示 JSON 格式的 Agent 清單。
  </StepItem>

  <StepItem>
    現在可以透過 HTTP 呼叫 Mastra 端點。

    :::警告
    部署到正式環境時，請在公開端點之前設定[身分驗證](/docs/auth/overview)。將 CORS 允許的來源限定為信任的網域，使用 AWS IAM 角色安全地存取其他 AWS 服務，並將敏感的環境變數存放在 AWS Secrets Manager 或 Parameter Store。
    :::
  </StepItem>
</Steps>

## 後續步驟 {/* #next-steps */}

依照本指南的步驟，即可快速將 Mastra 部署到 AWS Lambda。正式環境的工作負載可考慮為 Lambda 函式啟用 [CloudWatch 監控](https://docs.aws.amazon.com/lambda/latest/dg/monitoring-cloudwatchlogs.html)，設定 [AWS X-Ray](https://docs.aws.amazon.com/lambda/latest/dg/services-xray.html) 進行分散式追蹤，並設定[佈建並行](https://docs.aws.amazon.com/lambda/latest/dg/provisioned-concurrency.html)以維持效能穩定。
