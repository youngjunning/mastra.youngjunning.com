# NestJS

本指南會帶你使用 Mastra 和 NestJS 建立能呼叫 Tool 的 AI Agent。[NestJS 伺服器轉接器](/reference/server/nestjs-adapter)會透過 NestJS 模組註冊 Mastra 的 Agent 和 Workflow 路由，讓既有的 NestJS 應用程式直接處理這些路由。

## 開始之前 {/* #before-you-begin */}

* 準備受支援的[模型 Provider](/models) 所提供的 API 金鑰。如果還沒決定要用哪一家，可以使用 [OpenAI](/models/providers/openai)。
* 安裝 Node.js `v22.13.0` 或更新版本。
* 使用 NestJS 的 Express 平台（`@nestjs/platform-express`）。

## 建立 NestJS 應用程式（選用） {/* #create-a-new-nestjs-app-optional */}

如果已有 NestJS 應用程式，可以跳到下一步。

執行下列指令以建立 NestJS 應用程式：

```bash npm2yarn
npx @nestjs/cli new mastra-nest
```

這會建立名為 `mastra-nest` 的專案。你也可以自行指定專案名稱。

## 初始化 Mastra {/* #initialize-mastra */}

切換到 NestJS 專案目錄：

```bash
cd mastra-nest
```

執行 [`mastra init`](/reference/cli/mastra#mastra-init)，依照提示選擇 Provider（例如 OpenAI），再輸入 API 金鑰：

```bash npm2yarn
npx mastra@latest init
```

這個指令會建立 `src/mastra` 資料夾，內含天氣查詢 Agent 範例與下列檔案：

* `index.ts`：Mastra 設定，包含記憶設定。
* `tools/weather-tool.ts`：用來取得指定地點天氣資訊的 Tool。
* `agents/weather-agent.ts`：天氣查詢 Agent，其提示詞會指示它使用這個 Tool。

稍後註冊 NestJS 轉接器時，會傳入由 `src/mastra/index.ts` 匯出的 Mastra 執行個體。

## 依模組系統調整產生的檔案 {/* #update-the-generated-files-for-your-module-system */}

`mastra init` 產生的檔案需要依模組系統做一項調整，才能在 NestJS 專案中編譯。請查看 `package.json` 的 `type` 欄位。NestJS CLI v12 會建立 ECMAScript 模組（ESM）專案，並設為 `"type": "module"`。較早版本的 CLI 則會建立 CommonJS 專案。

<Tabs>
  <TabItem value="esm" label="ESM">
    ESM 專案採用 `"moduleResolution": "nodenext"`，因此相對匯入路徑必須包含副檔名。請在產生的檔案中，為每個相對匯入路徑加上 `.js`，例如：

    ```typescript title="src/mastra/index.ts"
    import { weatherWorkflow } from './workflows/weather-workflow.js'
    import { weatherAgent } from './agents/weather-agent.js'
    ```

    ```typescript title="src/mastra/agents/weather-agent.ts"
    import { weatherTool } from '../tools/weather-tool.js'
    ```
  </TabItem>

  <TabItem value="commonjs" label="CommonJS">
    CommonJS 不支援頂層 `await`。開啟 `src/mastra/index.ts`，移除 `DuckDBStore` 的匯入，以及 `MastraCompositeStore` 的 `domains` 選項：

    ```typescript title="src/mastra/index.ts" oxfmt:false
    import { DuckDBStore } from '@mastra/duckdb'

    // ...

    domains: {
      observability: await new DuckDBStore().getStore('observability'),
    },
    ```

    移除後，可觀測性資料會寫入預設的 LibSQL 儲存空間。
  </TabItem>
</Tabs>

## 加入伺服器轉接器 {/* #add-server-adapter */}

安裝 NestJS 伺服器轉接器套件：

```bash npm2yarn
npm install @mastra/nestjs@latest
```

開啟 `src/app.module.ts` 並註冊 `MastraModule`：

```typescript title="src/app.module.ts"
import { Module } from '@nestjs/common'
import { MastraModule } from '@mastra/nestjs'
import { mastra } from './mastra/index.js'

@Module({
  imports: [
    MastraModule.register({
      mastra,
    }),
  ],
})
export class AppModule {}
```

:::note

`MastraModule` 會註冊一個可比對所有路由的控制器（`@All('*')`）。如果先匯入這個模組，再匯入應用程式的其他模組，該控制器可能攔截與 Mastra 無關的路由並傳回 404。為避免衝突，請最後匯入 `MastraModule`，或將它掛載在專用前綴下，例如 `/api/v1/mastra`。

:::

## 測試 Agent {/* #test-your-agent */}

Mastra 預設會將端點設在 `/api` 子路徑下，並使用對應的 Agent 或 Workflow ID。`mastra init` 預設建立的 `weather-agent` 可透過 `/api/agents/weather-agent` 存取。

啟動 NestJS 伺服器：

```bash npm2yarn
npm run start
```

另開一個終端機視窗，用 `curl` 向天氣查詢 Agent 提問：

```bash
curl -X POST http://localhost:3000/api/agents/weather-agent/generate -H "Content-Type: application/json" -d "{\"messages\":[{\"role\":\"user\",\"content\":\"What is the weather like in Seoul?\"}]}"
```

## 在自訂服務中使用 Mastra {/* #use-mastra-in-your-own-services */}

這個模組匯出 `MastraService` 封裝類別和 `MASTRA` 注入權杖，兩者都能讓 NestJS 服務存取 Mastra。

### MastraService {/* #mastraservice */}

`MastraService` 是可注入的封裝類別，提供常用操作的方法：

```typescript title="src/agent.service.ts"
import { Injectable } from '@nestjs/common'
import { MastraService } from '@mastra/nestjs'

@Injectable()
export class AgentService {
  constructor(private readonly mastraService: MastraService) {}

  async chat(agentId: string, message: string) {
    const agent = this.mastraService.getAgent(agentId)
    return agent.generate({
      messages: [{ role: 'user', content: message }],
    })
  }

  async runWorkflow(workflowId: string, input: Record<string, unknown>) {
    const workflow = this.mastraService.getWorkflow(workflowId)
    return workflow.start({ inputData: input })
  }
}
```

`MastraService` 提供下列成員：

* `getMastra()`：傳回底層的 `Mastra` 執行個體。
* `getAgent(id)`：呼叫 `mastra.getAgent(id)` 的簡便方式。
* `getWorkflow(id)`：呼叫 `mastra.getWorkflow(id)` 的簡便方式。
* `getOptions()`：傳回模組設定。
* `isShuttingDown`：開始執行正常關閉程序後，值為 `true`。

### MASTRA 注入權杖 {/* #mastra-token */}

如果需要直接使用 `Mastra` 執行個體，例如存取儲存空間、記憶或其他核心 API，可以用 `MASTRA` 權杖注入該執行個體：

```typescript title="src/memory.service.ts"
import { Injectable, Inject } from '@nestjs/common'
import { MASTRA } from '@mastra/nestjs'
import type { Mastra } from '@mastra/core/mastra'

@Injectable()
export class MemoryService {
  constructor(@Inject(MASTRA) private readonly mastra: Mastra) {}

  async getThreadMessages(threadId: string) {
    const memory = this.mastra.getMemory()
    return memory?.getMessages({ threadId })
  }
}
```

兩種方式取得的都是 `MastraModule` 註冊的同一個 `Mastra` 單例。
