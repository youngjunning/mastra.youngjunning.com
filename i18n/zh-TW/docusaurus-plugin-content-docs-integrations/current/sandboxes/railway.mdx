# Railway

在暫時性、隔離的 [Railway](https://docs.railway.com/sandboxes) Sandbox 中執行指令。每個 Sandbox 都是透過 Railway TypeScript SDK 隨需建立的獨立 Debian Linux 虛擬機器。它支援串流指令輸出、指令逾時、可設定的閒置逾時、`ISOLATED`/`PRIVATE` 網路隔離、透過 Railway 範本建構器建立自訂基礎映像、使用檢查點復原、分叉執行中的 Sandbox，以及依 ID 重新連線至現有 Sandbox。介面詳情請參閱 [WorkspaceSandbox 介面](/reference/workspace/sandbox)。

## 安裝 {/* #installation */}

```bash npm2yarn
npm install @mastra/railway
```

## 用法 {/* #usage */}

將 `RailwaySandbox` 加入 Workspace，再把該 Workspace 指派給 Agent：

```typescript
import { Agent } from '@mastra/core/agent'
import { Workspace } from '@mastra/core/workspace'
import { RailwaySandbox } from '@mastra/railway'

const workspace = new Workspace({
  sandbox: new RailwaySandbox({
    // token + environmentId read from RAILWAY_API_TOKEN / RAILWAY_ENVIRONMENT_ID
    idleTimeoutMinutes: 30,
  }),
})

const agent = new Agent({
  id: 'code-agent',
  name: 'Code Agent',
  instructions: 'You are a coding assistant working in this workspace.',
  model: '__GATEWAY_ANTHROPIC_MODEL_SONNET__',
  workspace,
})

const response = await agent.generate(
  'Print "Hello, world!" and show the current working directory.',
)

console.log(response.text)
```

### 專用網路 {/* #private-networking */}

加入環境的私人網路，以存取其他 Railway 服務（例如 `postgres.railway.internal`）：

```typescript
const workspace = new Workspace({
  sandbox: new RailwaySandbox({
    networkIsolation: 'PRIVATE',
    env: { NODE_ENV: 'production' },
  }),
})
```

預設的 `ISOLATED` 模式只允許連線至外部網際網路，無法連接私人網路。

### 自訂基礎映像（範本） {/* #custom-base-image-templates */}

預先安裝套件並執行設定步驟，讓每個 Sandbox 啟動後即可使用。將建構回呼傳給 Railway 範本建構器；首次呼叫 `start()` 時會建構一次範本：

```typescript
const workspace = new Workspace({
  sandbox: new RailwaySandbox({
    template: t => t.withPackages('git', 'curl').run('npm i -g pnpm').workdir('/app'),
  }),
})
```

你也可以傳入預先建構的 `SandboxTemplate`，供多個 Sandbox 重複使用，而不必重新建構。設定 `sandboxId` 後會忽略範本，因為重新連線會使用現有 Sandbox 的檔案系統。

### 分叉執行中的 Sandbox {/* #forking-a-running-sandbox */}

將執行中 Sandbox 的檔案系統複製到新的獨立 Sandbox。新 Sandbox 會重新啟動，不會複製執行中的程序。傳回的 `RailwaySandbox` 已啟動：

```typescript
const child = await sandbox.fork({ idleTimeoutMinutes: 15 })

const result = await child.executeCommand('cat', ['/app/state.json'])
console.log(result.stdout)
```

分叉出的 Sandbox 會繼承來源 Sandbox 的憑證和預設設定，除非透過 `fork()` 選項覆寫。

### 檢查點恢復 {/* #checkpoint-recovery */}

設定 `checkpointName`，可在 Railway 更換 Sandbox 後保留其檔案系統。呼叫 `start()` 時，`RailwaySandbox` 會先嘗試從檢查點建立 Sandbox。如果檢查點不存在，就從設定的範本或預設映像建立 Sandbox，然後儲存檢查點。

```typescript
const sandbox = new RailwaySandbox({
  checkpointName: 'project-session-42',
  idleTimeoutMinutes: 30,
})
```

`RailwaySandbox` 會在閒置逾時前不久更新檢查點。復原時會使用最近一次成功儲存的檢查點，不會還原執行中的程序，也不會還原上次檢查點之後的檔案系統寫入。

設定 `seedCheckpointName`，可在 `checkpointName` 尚不存在時提供僅供啟動使用的備用檢查點。若兩個檢查點都存在，Railway 會優先還原 `checkpointName`。之後的快照只會寫入 `checkpointName`，因此每個 Sandbox 都有獨立的復原歷程。

```typescript
const sandbox = new RailwaySandbox({
  checkpointName: 'project-session-42',
  seedCheckpointName: 'project-base',
})
```

更新檔案系統後，呼叫 `snapshot()` 可立即儲存至設定的檢查點。若未設定 `checkpointName` 或 Sandbox 未執行，此方法會直接完成，不會儲存快照。

```typescript
await sandbox.snapshot()
```

每個獨立的檔案系統都應使用穩定的檢查點名稱。不要讓無關的工作階段或專案共用檢查點名稱。

### 複製 Sandbox 的檢查點 {/* #cloned-sandbox-checkpoints */}

當已設定的 `RailwaySandbox` 作為一組 Sandbox 的範本時，可使用 `clone({ checkpointName })`：

```typescript
const template = new RailwaySandbox({ idleTimeoutMinutes: 30 })

const sessionSandbox = template.clone({
  id: 'session-42',
  checkpointName: 'project-session-42',
})

await sessionSandbox.start()
```

複製出的 Sandbox 使用傳給 `clone()` 的檢查點。若未覆寫此設定，則繼承範本 Sandbox 的 `checkpointName`。

### 串流輸出 {/* #streaming-output */}

透過 `onStdout` 和 `onStderr` 回呼即時接收指令輸出：

```typescript
await sandbox.executeCommand('bash', ['-c', 'for i in 1 2 3; do echo "line $i"; sleep 1; done'], {
  onStdout: chunk => process.stdout.write(chunk),
  onStderr: chunk => process.stderr.write(chunk),
})
```

兩個回呼都是選用的，也可以分別使用。

### 重新連線至現有 Sandbox {/* #reattaching-to-an-existing-sandbox */}

Railway Sandbox 可以在建立它的程序結束後繼續執行。使用 Railway ID 重新連線，不必建立新的 Sandbox：

```typescript
const sandbox = new RailwaySandbox({ sandboxId: 'existing-railway-sandbox-id' })
await sandbox._start()

const result = await sandbox.executeCommand('cat', ['/tmp/state.txt'])
```

預設情況下（`reattach: 'best-effort'`），如果該 ID 對應的 Sandbox 已不存在或未執行，`start()` 會建立替代 Sandbox，並回報 `{ outcome: 'created' }`。如果替換 Sandbox 會讓應用程式所需的狀態在沒有提示的情況下遺失，請設定 `reattach: 'required'`：

```typescript
const sandbox = new RailwaySandbox({
  sandboxId: 'existing-railway-sandbox-id',
  reattach: 'required',
})
```

設定 `reattach: 'required'` 後，如果 Sandbox 不存在或已停止，`start()` 會擲出 `code` 為 `SANDBOX_REATTACH_FAILED` 的 `SandboxError`，而且不會建立新 Sandbox。錯誤的 `details` 包含 `provider`、`sandboxId` 和 `logicalId`（Sandbox 的邏輯 `id`）。網路或驗證失敗等其他錯誤會原樣傳遞。若要重新開始，請清除持久儲存的 `sandboxId`，並在建立 Sandbox 時不要傳入它。複製出的實例會繼承 `reattach` 設定。

## 背景程序 {/* #background-processes */}

`RailwaySandbox` 內建程序管理器，用於啟動和管理背景程序。每個程序都以 Railway `exec` 工作階段執行。

```typescript
const sandbox = new RailwaySandbox()
await sandbox.start()

// Spawn a background process
const handle = await sandbox.processes.spawn('node server.js', {
  env: { PORT: '3000' },
  onStdout: data => console.log(data),
})

// Interact with the process
console.log(handle.stdout)
await handle.kill()
```

Railway 的 `exec` API 不支援 stdin 串流，因此不支援 `sendStdin()`。

完整 API 請參閱 [`SandboxProcessManager` 參考文件](/reference/workspace/process-manager)。

## 編輯器 Provider {/* #editor-provider */}

在 `MastraEditor` 中註冊 Provider，將已儲存的 Sandbox 設定還原為執行階段實例：

```typescript
import { railwaySandboxProvider } from '@mastra/railway'

const editor = new MastraEditor({
  sandboxes: { [railwaySandboxProvider.id]: railwaySandboxProvider },
})
```

有關註冊自訂 Sandbox Provider 的詳情，請參閱 [Sandbox Provider 參考文件](/reference/editor/sandbox-provider)。
