# 鐵路

[Railway](https://docs.railway.com/sandboxes)沙箱。每個沙箱都是獨立的 Debian Linux VM，透過 Railway TypeScript SDK 按需配置。支援具有流輸出、命令逾時、可配置空閒逾時的命令執行，`ISOLATED`/`PRIVATE`網路隔離、透過 Railway 模板建構器自訂基礎映像、檢查點支援的復原、分叉正在運行的沙箱以及透過 ID 重新附加到現有沙箱。接口詳情請參見[WorkspaceSandbox介面](/reference/workspace/sandbox).

## 安裝 {/* #installation */}

```bash npm2yarn
npm install @mastra/railway
```

## 用法 {/* #usage */}

添加一個`RailwaySandbox` to a workspace and assign it to an agent:

```typescript
import { Agent } from '@mastra/core/agent'
import { Workspace } from '@mastra/core/workspace'
import { RailwaySandbox } from '@mastra/railway'

const workspace = new Workspace({
  sandbox: new RailwaySandbox({
    // token + environmentId read from RAILWAY_API_TOKEN / RAILWAY_ENVIRONMENT_ID
    idleTimeoutMinutes: 30,
  }),
})

const agent = new Agent({
  id: 'code-agent',
  name: 'Code Agent',
  instructions: 'You are a coding assistant working in this workspace.',
  model: '__GATEWAY_ANTHROPIC_MODEL_SONNET__',
  workspace,
})

const response = await agent.generate(
  'Print "Hello, world!" and show the current working directory.',
)

console.log(response.text)
```

### 專用網路 {/* #private-networking */}

加入環境的專用網路以存取其他鐵路服務（例如`postgres.railway.internal`):

```typescript
const workspace = new Workspace({
  sandbox: new RailwaySandbox({
    networkIsolation: 'PRIVATE',
    env: { NODE_ENV: 'production' },
  }),
})
```

預設`ISOLATED` mode allows outbound internet access only, with no private network connectivity.

### 自訂基礎鏡像（模板） {/* #custom-base-image-templates */}

預先安裝軟體包並運行設定步驟，以便每個沙箱開始準備就緒。透過鐵路模板建構器傳遞建構器回調：模板在第一個模板上建構一次`start()`:

```typescript
const workspace = new Workspace({
  sandbox: new RailwaySandbox({
    template: t => t.withPackages('git', 'curl').run('npm i -g pnpm').workdir('/app'),
  }),
})
```

您也可以傳遞預先建構的`SandboxTemplate` to reuse it across sandboxes without rebuilding. Templates are ignored when `sandboxId` is set, since reattaching uses the existing sandbox's filesystem.

### 分叉正在運作的沙箱 {/* #forking-a-running-sandbox */}

將正在運行的沙箱的檔案系統克隆到一個新的獨立沙箱中：全新啟動，而不是即時進程。返回的`RailwaySandbox` is already started:

```typescript
const child = await sandbox.fork({ idleTimeoutMinutes: 15 })

const result = await child.executeCommand('cat', ['/app/state.json'])
console.log(result.stdout)
```

分叉的沙箱繼承父級的憑證和預設值，除非透過`fork()` options.

### 檢查點恢復 {/* #checkpoint-recovery */}

放`checkpointName` to preserve a sandbox filesystem across Railway sandbox replacement. On `start()`, `RailwaySandbox` first tries to create the sandbox from the checkpoint. If the checkpoint is missing, it creates a sandbox from the configured template or default image, then captures the checkpoint.

```typescript
const sandbox = new RailwaySandbox({
  checkpointName: 'project-session-42',
  idleTimeoutMinutes: 30,
})
```

`RailwaySandbox`在空閒超時之前不久刷新檢查點。恢復恢復最新的成功檢查點。它不會恢復上一個檢查點之後正在執行的進程或檔案系統寫入。

放`seedCheckpointName` to provide a boot-only fallback when `checkpointName` doesn't exist yet. Railway restores `checkpointName` first when both checkpoints exist. Later snapshots write only to `checkpointName`, so each sandbox keeps an independent recovery history.

```typescript
const sandbox = new RailwaySandbox({
  checkpointName: 'project-session-42',
  seedCheckpointName: 'project-base',
})
```

稱呼`snapshot()` after a filesystem update to capture the configured checkpoint immediately. It resolves without capturing when `checkpointName` isn't configured or the sandbox isn't running.

```typescript
await sandbox.snapshot()
```

為每個獨立的檔案系統使用一個穩定的檢查點名稱。不要在不相關的會話或項目之間共用檢查點名稱。

### 克隆Sandbox檢查點 {/* #cloned-sandbox-checkpoints */}

使用`clone({ checkpointName })` when a configured `RailwaySandbox` acts as the template for a sandbox fleet:

```typescript
const template = new RailwaySandbox({ idleTimeoutMinutes: 30 })

const sessionSandbox = template.clone({
  id: 'session-42',
  checkpointName: 'project-session-42',
})

await sessionSandbox.start()
```

克隆的沙箱使用傳遞給的檢查點`clone()`. If no override is passed, it inherits the template sandbox's `checkpointName`.

### 串流輸出 {/* #streaming-output */}

透過即時串流命令輸出`onStdout` and `onStderr` callbacks:

```typescript
await sandbox.executeCommand('bash', ['-c', 'for i in 1 2 3; do echo "line $i"; sleep 1; done'], {
  onStdout: chunk => process.stdout.write(chunk),
  onStderr: chunk => process.stderr.write(chunk),
})
```

兩個回調都是可選的並且可以獨立使用。

### 重新附加到現有沙箱 {/* #reattaching-to-an-existing-sandbox */}

鐵路沙箱的壽命比創建它的過程還要長。透過其鐵路 ID 重新連接，而不是配置新的：

```typescript
const sandbox = new RailwaySandbox({ sandboxId: 'existing-railway-sandbox-id' })
await sandbox._start()

const result = await sandbox.executeCommand('cat', ['/tmp/state.txt'])
```

預設情況下 （`reattach: 'best-effort'`), if the sandbox with that ID no longer exists or isn't running, `start()` provisions a replacement sandbox and reports `{ outcome: 'created' }`. When a replacement would silently lose state your app depends on, set `reattach: 'required'`:

```typescript
const sandbox = new RailwaySandbox({
  sandboxId: 'existing-railway-sandbox-id',
  reattach: 'required',
})
```

和`reattach: 'required'`, a missing or stopped sandbox rejects `start()` with a `SandboxError` whose `code` is `SANDBOX_REATTACH_FAILED`, and no new sandbox is created. The error's `details` include `provider`, `sandboxId`, and `logicalId` (the sandbox's logical `id`). Other errors, such as network or authentication failures, propagate unchanged. To start fresh, clear your persisted `sandboxId` and construct the sandbox without it. Clones inherit the `reattach` setting.

## 後台程式 {/* #background-processes */}

`RailwaySandbox`包括一個內建的進程管理器，用於產生和管理後台進程。每個產生的進程都作為鐵路運行`exec` session.

```typescript
const sandbox = new RailwaySandbox()
await sandbox.start()

// Spawn a background process
const handle = await sandbox.processes.spawn('node server.js', {
  env: { PORT: '3000' },
  onStdout: data => console.log(data),
})

// Interact with the process
console.log(handle.stdout)
await handle.kill()
```

鐵路的`exec` API doesn't stream stdin, so `sendStdin()` isn't supported.

看[`SandboxProcessManager` reference](/reference/workspace/process-manager) for the full API.

## 編輯器Provider {/* #editor-provider */}

向Provider註冊`MastraEditor` to hydrate stored sandbox configs into runtime instances:

```typescript
import { railwaySandboxProvider } from '@mastra/railway'

const editor = new MastraEditor({
  sandboxes: { [railwaySandboxProvider.id]: railwaySandboxProvider },
})
```

請參閱[Sandbox provider reference](/reference/editor/sandbox-provider) for details on registering custom sandbox providers.
