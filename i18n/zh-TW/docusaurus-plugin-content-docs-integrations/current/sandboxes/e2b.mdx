# E2B

在隔離的 [E2B](https://e2b.dev) 雲端 Sandbox 中執行命令。E2B 提供安全的暫時性環境，並支援掛載雲端儲存空間。介面詳情請參閱 [WorkspaceSandbox 介面](/reference/workspace/sandbox)。

## 安裝 {/* #installation */}

```bash npm2yarn
npm install @mastra/e2b
```

## 用法 {/* #usage */}

將 `E2BSandbox` 加入 Workspace，並指派給 Agent：

```typescript
import { Agent } from '@mastra/core/agent'
import { Workspace } from '@mastra/core/workspace'
import { E2BSandbox } from '@mastra/e2b'

const workspace = new Workspace({
  sandbox: new E2BSandbox({
    id: 'dev-sandbox',
    timeout: 60_000, // 60 second timeout (default: 5 minutes)
  }),
})

const agent = new Agent({
  id: 'dev-agent',
  name: 'dev-agent',
  model: '__GATEWAY_ANTHROPIC_MODEL_OPUS__',
  workspace,
})
```

## 要求重新連線 {/* #requiring-reattachment */}

傳入已持久儲存的 `sandboxId`，但對應的 Sandbox 已不存在時，預設的 `reattach: 'best-effort'` 會接著依邏輯 ID 查找，可能重新連線至另一個具有相同 `id` 的 Sandbox，也可能建立新 Sandbox。若換用其他 Sandbox 會讓應用程式依賴的狀態在未察覺的情況下遺失，請設定 `reattach: 'required'`：

```typescript title="src/mastra/workspaces.ts"
const sandbox = new E2BSandbox({
  id: 'session-123',
  sandboxId: persistedSandboxId,
  reattach: 'required',
})
```

使用 `reattach: 'required'` 時，若 Sandbox 已不存在，`start()` 會以 `SandboxError` 拒絕，錯誤的 `code` 為 `SANDBOX_REATTACH_FAILED`，且不會進行查找或建立。錯誤的 `details` 包含 `provider`、`sandboxId` 和 `logicalId`（Sandbox 的邏輯 `id`）。其他錯誤與使用 `'best-effort'` 時相同，會原樣向上拋出。若要重新開始，請清除已持久儲存的 `sandboxId`，並在建構 Sandbox 時省略該選項。複製出的執行個體會繼承 `reattach` 設定。

## 背景程序 {/* #background-processes */}

`E2BSandbox` 內建程序管理器，可啟動及管理背景程序。程序在 E2B 雲端 Sandbox 中執行，使用 E2B SDK 的 `commands.run()`，並設定 `background: true`。

```typescript
const sandbox = new E2BSandbox({ id: 'dev-sandbox' })
await sandbox.start()

// Spawn a background process
const handle = await sandbox.processes.spawn('node server.js', {
  env: { PORT: '3000' },
  onStdout: data => console.log(data),
})

// Interact with the process
console.log(handle.stdout)
await handle.sendStdin('input\n')
await handle.kill()
```

`list()` 會傳回 Sandbox 中正在執行的程序，包括並非由此管理器啟動的程序；它也會傳回輸出尚未被讀取的已結束程序。

E2B 程序管理器支援重新連線至外部啟動的程序，以及重新連線前啟動的程序。傳入 PID 呼叫 `get(pid)`，即可連線至現有程序。連線前產生的輸出無法取得：

```typescript
const handle = await sandbox.processes.get(existingPid)
if (handle) {
  console.log(handle.stdout)
}
```

完整 API 請參閱 [`SandboxProcessManager` 參考文件](/reference/workspace/process-manager)。

## 掛載雲端儲存空間 {/* #mounting-cloud-storage */}

E2B Sandbox 可以掛載 S3、GCS 和 Azure Blob 檔案系統，讓 Sandbox 內的程式如同存取本機目錄般存取雲端儲存空間。適用情境包括：

- 處理存放在雲端儲存貯體中的大型資料集
- 將輸出檔案直接寫入雲端儲存空間
- 在 Sandbox 工作階段之間共用資料

### 使用 mounts 設定 {/* #using-the-mounts-config */}

掛載檔案系統最簡單的方式是使用 Workspace 的 `mounts` 設定：

```typescript
import { Workspace } from '@mastra/core/workspace'
import { S3Filesystem } from '@mastra/s3'
import { GCSFilesystem } from '@mastra/gcs'
import { E2BSandbox } from '@mastra/e2b'

const workspace = new Workspace({
  mounts: {
    '/s3-data': new S3Filesystem({
      bucket: 'my-s3-bucket',
      region: 'us-east-1',
      accessKeyId: process.env.AWS_ACCESS_KEY_ID,
      secretAccessKey: process.env.AWS_SECRET_ACCESS_KEY,
    }),
    '/gcs-data': new GCSFilesystem({
      bucket: 'my-gcs-bucket',
      projectId: 'my-project',
      credentials: JSON.parse(process.env.GCS_SERVICE_ACCOUNT_KEY),
    }),
  },
  sandbox: new E2BSandbox({ id: 'dev-sandbox' }),
})
```

Sandbox 啟動時，檔案系統會自動掛載至指定路徑。接著，Sandbox 中執行的程式碼可以像存取本機目錄一樣，存取 `/s3-data` 和 `/gcs-data` 中的檔案。

### 掛載運作方式 {/* #how-mounting-works */}

E2B Sandbox 使用 FUSE（使用者空間檔案系統）掛載雲端儲存空間：

- **S3/R2**：透過 [s3fs-fuse](https://github.com/s3fs-fuse/s3fs-fuse) 掛載
- **GCS**：透過 [gcsfuse](https://github.com/GoogleCloudPlatform/gcsfuse) 掛載
- **Azure Blob**：透過 [blobfuse2](https://github.com/Azure/azure-storage-fuse) 掛載

使用掛載功能時，E2B Sandbox 會自動安裝所需的 FUSE 工具。為取得較佳效能，請預先建置已安裝這些工具的自訂範本。

## 自訂範本 {/* #custom-templates */}

未指定範本時，E2BSandbox 預設會自動建置範本：安裝 `s3fs` 以支援掛載 S3，以目前的 Node.js LTS 版本取代基礎映像中的舊版執行環境，並啟用 corepack，讓 `pnpm` 和 `yarn` 使用儲存庫 `packageManager` 欄位指定的版本。此範本會快取，並在不同 Sandbox 執行個體之間重複使用。

Node.js 版本會精確固定，也是範本識別資訊的一部分。向 `createDefaultMountableTemplate()` 傳入 `nodeVersion` 可選擇其他版本；變更版本會建置新範本。

掛載 GCS 時，若尚未安裝 `gcsfuse`，系統會自動安裝。如需加入其他工具或縮短冷啟動時間，請使用自訂範本。

### 使用現有範本 {/* #using-an-existing-template */}

如果已有預先建置的範本，請傳入其 ID：

```typescript
const workspace = new Workspace({
  sandbox: new E2BSandbox({
    id: 'dev-sandbox',
    template: 'my-custom-template',
  }),
})
```

### 自訂預設範本 {/* #customizing-the-default-template */}

傳入函式即可自訂預設的可掛載範本。函式會接收 `TemplateBuilder`，並應傳回修改後的範本：

```typescript
const workspace = new Workspace({
  sandbox: new E2BSandbox({
    template: base =>
      base
        .aptInstall(['ffmpeg', 'imagemagick', 'poppler-utils'])
        .pipInstall(['pandas', 'numpy'])
        .npmInstall(['sharp']),
  }),
})
```

範本建構器支援鏈式呼叫，例如：

- `aptInstall(packages)`：安裝系統套件
- `pipInstall(packages)`：安裝 Python 套件
- `npmInstall(packages)`：安裝 Node.js 套件
- `runCmd(command)`：執行 shell 命令
- `setEnvs(vars)`：設定環境變數
- `copy(src, dest)`：將檔案複製到範本中

完整方法清單請參閱 [E2B 範本文件](https://e2b.dev/docs/template/defining-template)。

### 預先建置範本 {/* #pre-building-templates */}

預設範本會在首次使用時建置並快取。如需縮短冷啟動時間或加入 GCS 支援，可以預先建置範本：

```typescript
import { createDefaultMountableTemplate } from '@mastra/e2b'
import { Template } from 'e2b'

// Get the default mountable template (includes s3fs)
const { template, id } = createDefaultMountableTemplate()

// Build and save to E2B
const result = await Template.build(template, id)
console.log('Template ID:', result.templateId)

// Use this ID in your E2BSandbox config for instant startup
const sandbox = new E2BSandbox({
  template: result.templateId,
})
```

如需加快使用 GCS 時的冷啟動，請在自訂範本中預先安裝 `gcsfuse`：

```typescript
const workspace = new Workspace({
  sandbox: new E2BSandbox({
    id: 'dev-sandbox',
    template: base => base.aptInstall(['gcsfuse']),
  }),
})
```

此步驟可省略：掛載時若沒有 `gcsfuse`，系統會自動安裝。

### 儲存庫範本 {/* #repository-templates */}

`createRepoTemplate` 產生範本規格，在建置時複製儲存庫並執行其設定命令。如此一來，每個 Sandbox 啟動時都已有備妥的檢出內容和已安裝的相依套件，無須在每個工作階段重新複製儲存庫：

```typescript
import { E2BSandbox, createRepoTemplate } from '@mastra/e2b'

const sandbox = new E2BSandbox({
  id: sessionId,
  template: createRepoTemplate({
    getRepositoryAccess: async () => ({
      cloneUrl: 'https://github.com/octocat/hello-world.git',
    }),
    setupCommand: 'pnpm install',
  }),
})
```

`getRepositoryAccess` 提供複製 URL；若是私人儲存庫，也會提供憑證。它是複製 URL 的唯一來源，因此實際複製的儲存庫與範本識別資訊所依據的儲存庫不會不一致。若它傳回 `undefined`，`createRepoTemplate` 也會傳回 `undefined`。沒有儲存庫的工作階段因此可直接要求 Provider 使用預設範本，無須在呼叫處加上條件判斷。

每組儲存庫與設定命令恰好對應一個範本：範本名稱包含儲存庫 slug 和輸入內容的短雜湊值，提交 SHA 則作為該名稱上的標籤（`mastra-repo-<owner>-<repo>-<hash>:sha-<sha>`）。解析規格時，範本會固定至儲存庫目前預設分支的最新提交：查找範本前會執行 `git ls-remote`（不複製儲存庫，約 100 毫秒），並以該 SHA 命名標籤。預設分支更新後，下一個新的 Sandbox 會以新標籤就地重建同一範本；舊 SHA 標籤保留為可清理的建置紀錄，而不會堆積成過時範本。若無法解析最新提交，參照會退回穩定的 `current` 標籤，建置時複製預設分支當下的內容。

解析會依需要進行，只有範本首次建置會阻礙啟動。每次成功建置也會更新穩定的 `current` 標籤。因此，最新提交變更後，下一個 Sandbox 可立即從上一次建置啟動，而新的 SHA 參照會在 E2B 端背景建置；執行階段的設定會透過 `git fetch` 將稍舊的檢出內容快轉至最新版本，因此程式碼是否為最新不取決於範本。設定命令變更後，其雜湊值會產生新的範本名稱。

`setupCommand` 也接受陣列，每個項目都是獨立且可快取的建置步驟。`workingDirectory` 設定建置及 Sandbox 的目前工作目錄，儲存庫會複製到 `<workingDirectory>/<repo>`。

#### 在同一範本中包含多個儲存庫 {/* #several-repositories-in-one-template */}

使用 `repos` 取代 `getRepositoryAccess`，可將多個儲存庫複製到同一範本。每個儲存庫都有自己的憑證解析函式和設定命令；設定命令可以是字串或陣列，陣列中的每個項目都是獨立的建置步驟：

```typescript
const sandbox = new E2BSandbox({
  id: sessionId,
  template: createRepoTemplate({
    repos: [
      {
        getRepositoryAccess: async () => ({
          cloneUrl: 'https://github.com/mastra-ai/mastra.git',
        }),
        setupCommand: 'pnpm install --frozen-lockfile',
      },
      {
        getRepositoryAccess: async () => ({
          cloneUrl: 'https://github.com/mastra-ai/template-docs-expert.git',
        }),
        setupCommand: 'npm install',
      },
    ],
    workspaceSetupCommand: 'npm install --global @mastra/mcp-docs-server',
    continueOnSetupFailure: true,
    workingDirectory: '/home/user/repos',
  }),
})
```

每個儲存庫都會複製到 `<workingDirectory>/<repo>`。公開儲存庫會先於私人儲存庫建置，各組內維持呼叫端指定的順序。私人儲存庫憑證會作為建置環境變數，所有建置步驟都看得到，因此任一儲存庫的設定命令都能讀取其他儲存庫的權杖。請只將設定命令彼此可信的儲存庫放在同一清單。

所有儲存庫設定完成後，`workspaceSetupCommand` 會在工作目錄中執行。`continueOnSetupFailure` 預設為 `false`；啟用後，設定命令失敗時會將對應的儲存庫記錄於 `.mastra-sandbox/setup-failed` 並繼續執行，而非讓建置失敗。

標記檔案讓工作階段知道映像中已執行的步驟：每個儲存庫對應 `.mastra-sandbox/repos/<repo>`，Workspace 命令執行後對應 `.mastra-sandbox/workspace-setup`；這些檔案都位於工作目錄下。啟用 `continueOnSetupFailure` 時，請先檢查 `.mastra-sandbox/setup-failed`。

新增或移除儲存庫、修改設定命令都會建立新範本；輪替憑證則會沿用現有範本。如果任何儲存庫的存取設定無法解析，Sandbox 會退回預設範本。如果某個儲存庫的最新提交無法解析，複製時就不會固定提交，而其他儲存庫仍維持各自固定的提交。

除非規格要求更高的資源，否則範本會按 E2B 的預設機器規格（2 個 vCPU、1024 MB）建置。傳入 `cpuCount` 和 `memoryMB`，可設定由該範本建立的 Sandbox 所使用的機器規格：

```typescript
const sandbox = new E2BSandbox({
  id: sessionId,
  template: createRepoTemplate({
    getRepositoryAccess: async () => ({
      cloneUrl: 'https://github.com/octocat/hello-world.git',
    }),
    setupCommand: 'pnpm install',
    cpuCount: 4,
    memoryMB: 2048,
  }),
})
```

資源規格也是範本識別資訊的一部分：它們與儲存庫及設定命令一起參與範本名稱的雜湊計算，因此調整規格會建置新範本，不會悄悄沿用舊規格的範本。若儲存庫範本建置失敗、Sandbox 退回預設的可掛載範本，後備範本也會依要求的規格建置，確保設定步驟不會落在規格較低的機器上。E2B 可接受的規格值仍受帳戶方案等級限制。

若要在合併後主動預熱範本，無須等到第一個工作階段，可在排程工作或合併至主分支的事件處理常式中，以相同選項呼叫 `refreshRepoTemplate`。它執行與 Sandbox 啟動時相同的解析流程：解析目前的最新提交，若已有建置就沿用，否則建置範本並更新 `current`；傳回 `{ ref, action, sha }`：

```typescript
import { refreshRepoTemplate } from '@mastra/e2b'

const result = await refreshRepoTemplate({
  getRepositoryAccess: async () => ({
    cloneUrl: 'https://github.com/octocat/hello-world.git',
  }),
  setupCommand: 'pnpm install',
})
// { ref: 'mastra-repo-octocat-hello-world-…:sha-…', action: 'built' | 'reused', sha: '…' }
```

此範本建置於預設的可掛載基礎映像之上，也就是 E2B 的 `base` 映像；其中已有 git、常用工具，以及用於掛載的 `s3fs`/FUSE。儲存庫會複製到建置使用者家目錄下的 `$HOME/<repo>`，儲存庫名稱由複製 URL 得出。建置步驟及執行階段命令，都以 Sandbox 的非 root 使用者 `user` 身分在其家目錄執行，因此無須預先準備目錄，執行階段檔案的擁有權也會維持正確；在執行階段檢查 `$HOME`，就能在範本留下的位置找到檢出內容。

失敗處理機制可避免損壞的範本卡住工作階段：

- 建置失敗時會退回預設的可掛載範本；工作階段仍可在執行階段將儲存庫重新複製到 `$HOME`。
- 對於失敗建置的參照，E2B 仍會讓 `Template.exists` 判定其存在，因此損壞的參照原本可能一直被沿用。若透過具名參照建立 Sandbox 失敗，系統會捨棄快取的解析結果，並沿後備流程重試建立。

若缺少範本工具鏈的 Sandbox 比啟動失敗更難接受，請在解析後的規格中設定 `fallbackTemplate: false`。此時建置失敗，或參照無法建立 Sandbox，都會讓 `start()` 以原始錯誤拒絕，而不會退回後備範本：

```typescript title="src/mastra/workspaces.ts"
const repoTemplate = createRepoTemplate({
  getRepositoryAccess: async () => ({ cloneUrl: 'https://github.com/acme/app.git' }),
  setupCommand: 'pnpm install',
})!

const sandbox = new E2BSandbox({
  template: {
    resolveSpec: async () => ({ ...(await repoTemplate.resolveSpec()), fallbackTemplate: false }),
  },
})
```

對於私人儲存庫，若 `getRepositoryAccess` 除了複製 URL，也傳回 `authorization`，便可建置預熱範本。該憑證應在每次解析範本時新核發，且有效期較短，例如 GitHub App 安裝權杖。憑證透過 shell 中的 `http.extraheader` 驗證最新提交查詢與建置時的複製作業。它會進入範本定義的環境（建置步驟可見，但不會持久儲存至執行階段 Sandbox 環境），且不會接觸映像檔案系統，因此擷取的映像層不會包含它。憑證設為 `GH_TOKEN`，與工作階段執行設定前注入的變數相同，因此呼叫 `gh` 或經驗證的 HTTPS 請求，在建置及工作階段中的行為一致。

請只傳入短期憑證：憑證值會保留在範本定義中，直到下次重建，因此其有效期限決定了暴露時間。請注意，複製的儲存庫內容會成為團隊可見的範本映像的一部分。存取函式未傳回憑證時，複製作業不會使用權杖：公開儲存庫仍可正常建置；私人儲存庫的建置則會退回後備流程，由工作階段在執行階段使用注入的驗證資訊完成複製。

若設定命令需要自己的憑證，例如套件登錄庫權杖或私人索引 URL，請透過 `buildEnv` 傳入；它接受紀錄物件或非同步解析函式。這些值是範本識別資訊的一部分，變更任一值都會產生新範本。若不希望值出現在範本名稱中，還需傳入 `buildEnvRevision`。這些值仍會像複製憑證一樣傳給建置步驟，但範本名稱只使用修訂識別碼。每次變更值時，都應更新修訂識別碼。

`repoTemplateRef` 可計算規格對應的帶標籤參照，而不執行建置；使用 E2B CLI 清理舊 SHA 標籤時很實用。

### 每個工作階段使用獨立 Sandbox {/* #per-session-sandboxes */}

對於每個工作階段建立一個 Sandbox 的主機程式，例如使用 Mastra Factory 的 `sandbox` 設定，請使用 `E2BFactorySandbox`：Sandbox 以工作階段 ID 識別（依 ID 呼叫 getOrCreate，因此在 E2B 閒置逾時後會暫停，並可依 ID 恢復）；儲存庫範本由 `createRepoTemplate` 根據該工作階段的儲存庫產生；專案的 `cpuCount` 和 `memoryMb` 設定會傳入範本。請參閱 [FactorySandbox 參考文件](/reference/workspace/factory-sandbox)。

```typescript
import { MastraFactory } from '@mastra/factory'
import { E2BFactorySandbox } from '@mastra/e2b'

new MastraFactory({
  sandbox: new E2BFactorySandbox({ apiKey: process.env.E2B_API_KEY }),
})
```

也支援直接使用回呼：`sandbox: ctx => new E2BSandbox({ id: ctx.sessionId, template: createRepoTemplate(ctx) })`。Factory 會將其視為沒有可調整設定的自訂 Provider。無論採用哪種方式，Factory 都會為傳回的 Sandbox 附加自身的工作階段設定。

## 與 Code Mode 搭配使用 {/* #using-with-code-mode */}

[Code Mode](/docs/agents/code-mode) 讓 Agent 撰寫單一 TypeScript 程式來協調其 Tool。由於 E2B 在遠端微型虛擬機器中執行該程式，因此需要將程式寫入 Sandbox 檔案系統，而不是主機檔案系統的傳輸方式。`@mastra/e2b` 為此提供 `E2BCodeModeTransport`。請將它作為 `createCodeMode` 的第二個引數傳入：

```typescript
import { createCodeMode } from '@mastra/core/tools'
import { E2BSandbox, E2BCodeModeTransport } from '@mastra/e2b'

const { tool, instructions } = createCodeMode(
  {
    tools: { getWeather, getForecast },
    sandbox: new E2BSandbox({ timeout: 60_000 }),
  },
  new E2BCodeModeTransport(),
)
```

`E2BCodeModeTransport` 會在 Sandbox 尚未執行時自動啟動它，在主機上使用 esbuild 移除 TypeScript 語法（因此不受 Sandbox 中 Node 版本影響），在虛擬機器內執行 `node`，並於完成後清除程式檔案。`@mastra/core` 提供的預設 `StdioCodeModeTransport` 僅適用於與主機共用檔案系統的 Sandbox，例如 `LocalSandbox`。
