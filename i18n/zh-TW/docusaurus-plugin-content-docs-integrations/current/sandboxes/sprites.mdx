# Fly.io Sprites

透過官方 `@fly/sprites` SDK，在具備持久性的 [Fly.io Sprites](https://sprites.dev) 中執行指令。Sprite 是 Linux 虛擬機器，每次執行結束後都會保留檔案系統，並在閒置時自動休眠。`SpritesSandbox` 依名稱取得或建立 Sprite，讓新的程序可以重新連線並存取原有檔案。執行指令時支援串流輸出、逾時與取消，也支援向背景程序傳送標準輸入及建立檢查點。介面細節請參閱 [WorkspaceSandbox 介面](/reference/workspace/sandbox)。

## 安裝 {/* #installation */}

```bash npm2yarn
npm install @mastra/sprites
```

:::note
`@mastra/sprites` 使用的 `@fly/sprites` SDK 需要 Node.js 24 或更新版本。
:::

從以下三種方式擇一設定 Sprites API 權杖。

## 使用方式 {/* #usage */}

將 `SpritesSandbox` 加入 Workspace，再將該 Workspace 指派給 Agent。

```typescript
import { Agent } from '@mastra/core/agent'
import { Workspace } from '@mastra/core/workspace'
import { SpritesSandbox } from '@mastra/sprites'

const workspace = new Workspace({
  sandbox: new SpritesSandbox({
    id: 'mastra-project',
    // token read from SPRITES_TOKEN
  }),
})

const agent = new Agent({
  id: 'code-agent',
  name: 'Code Agent',
  instructions: 'You are a coding assistant working in this workspace.',
  model: '__GATEWAY_ANTHROPIC_MODEL_SONNET__',
  workspace,
})

const response = await agent.generate(
  'Print "Hello, world!" and show the current working directory.',
)

console.log(response.text)
```

### 重複使用 Sprite {/* #reusing-a-sprite */}

`id` 代表 Sprite 的名稱。呼叫 `start()` 時，`SpritesSandbox` 會搜尋同名的 Sprite。找到時會重新連線，找不到時則會建立一個。先前工作階段寫入的檔案會保留下來。

```typescript
const first = new SpritesSandbox({ id: 'mastra-project' })
await first.executeCommand('sh', ['-c', 'echo hello > notes.txt'])
await first.stop()

// Later, possibly in another process
const second = new SpritesSandbox({ id: 'mastra-project' })
const result = await second.executeCommand('cat', ['notes.txt'])
console.log(result.stdout) // hello
```

只要帳戶中已有同名的 Sprite，就會沿用該 Sprite，因此請為專案選用專屬的名稱。省略 `id` 時，系統會隨機產生名稱。

`spriteConfig`（記憶體、CPU、區域與儲存空間）只在建立 Sprite 時套用。

### 停止與銷毀 {/* #stopping-and-destroying */}

`stop()` 和 `destroy()` 的作用如下。

* `stop()` 會終止這個執行個體啟動的背景程序並關閉 SDK 連線，Sprite 與檔案系統都會保留。Sprite 閒置時會自動休眠，無須手動暫停。
* `destroy()` 會永久刪除 Sprite 及其檔案系統，無須先呼叫 `start()`。若 Sprite 已不存在，便視為已刪除。

```typescript
const sandbox = new SpritesSandbox({ id: 'mastra-project' })

// Remove the Sprite when the project is finished
await sandbox.destroy()
```

### 檢查點 {/* #checkpoints */}

`snapshot()` 會為 Sprite 的目前狀態建立檢查點，並等到建立完成才返回。

```typescript
await sandbox.snapshot()
```

檢查點儲存在 Sprite 內，無法用來啟動其他 Sandbox 或為其提供初始狀態。因此，`supportsCheckpoints` 為 `false`，而 `SpritesSandbox` 未實作 `clone()`。若要列出或還原檢查點，請透過 `sandbox.sprite` 使用 `@fly/sprites` SDK。

### 串流輸出 {/* #streaming-output */}

傳入 `onStdout` 和 `onStderr`，即可即時接收輸出。

```typescript
await sandbox.executeCommand('npm', ['install'], {
  onStdout: data => process.stdout.write(data),
  onStderr: data => process.stderr.write(data),
  timeout: 120_000,
})
```

指令逾時或其 `abortSignal` 觸發時，指令會遭到終止，結果會帶有 `killed: true`。

## 背景程序 {/* #background-processes */}

`SpritesSandbox` 內建程序管理器，可啟動和管理背景程序。每個程序都在各自的 Sprites exec 工作階段執行，並支援從 stdin 接收輸入。

```typescript
const sandbox = new SpritesSandbox({ id: 'mastra-project' })
await sandbox.start()

const handle = await sandbox.processes.spawn('node server.js', {
  env: { PORT: '3000' },
  onStdout: data => console.log(data),
})

await handle.sendStdin('reload\n')
await handle.kill()
```

某個 `SpritesSandbox` 執行個體啟動的程序，其他執行個體無法看見。呼叫該執行個體的 `stop()` 會終止這些程序。

完整 API 請參閱 [`SandboxProcessManager` 參考文件](/reference/workspace/process-manager)。

## 編輯器的 Provider {/* #editor-provider */}

將 Provider 註冊至 `MastraEditor`，即可在執行時從已儲存的 Sandbox 設定建立執行個體。

```typescript
import { MastraEditor } from '@mastra/editor'
import { spritesSandboxProvider } from '@mastra/sprites'

const editor = new MastraEditor({
  sandboxes: { [spritesSandboxProvider.id]: spritesSandboxProvider },
})
```

如需註冊自訂 Sandbox Provider，請參閱 [Sandbox Provider 參考文件](/reference/editor/sandbox-provider)。
