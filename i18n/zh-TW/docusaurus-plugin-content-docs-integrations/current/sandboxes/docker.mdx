# Docker

在本機的 Docker 容器內執行指令。容器會持續運作，指令透過 `docker exec` 執行。適用於本機開發、CI/CD、實體隔離網路部署，以及不需要雲端 Sandbox、需控制成本的情境。介面詳情請參閱 [WorkspaceSandbox 介面](/reference/workspace/sandbox)。

## 安裝 {/* #installation */}

```bash npm2yarn
npm install @mastra/docker
```

主機上必須執行 [Docker Engine](https://docs.docker.com/engine/install/)。

## 用法 {/* #usage */}

將 `DockerSandbox` 加入 Workspace，再將該 Workspace 指派給 Agent：

```typescript
import { Agent } from '@mastra/core/agent'
import { Workspace } from '@mastra/core/workspace'
import { DockerSandbox } from '@mastra/docker'

const workspace = new Workspace({
  sandbox: new DockerSandbox({
    image: 'node:22-slim',
  }),
})

const agent = new Agent({
  id: 'dev-agent',
  name: 'dev-agent',
  model: '__GATEWAY_ANTHROPIC_MODEL_OPUS__',
  workspace,
})
```

### 儲存庫範本 {/* #repository-templates */}

`createDockerRepoTemplate` 建立的映像檔已包含簽出的儲存庫及初始化指令的執行結果，因此工作階段開始時相依套件已安裝完成，無須重新複製儲存庫：

```typescript
import { DockerSandbox, createDockerRepoTemplate } from '@mastra/docker'

const sandbox = new DockerSandbox({
  id: sessionId,
  template: createDockerRepoTemplate({
    getRepositoryAccess: async () => ({
      cloneUrl: 'https://github.com/octocat/hello-world.git',
    }),
    setupCommand: 'npm ci',
  }),
})
```

`getRepositoryAccess` 提供複製 URL；對私人儲存庫，還會提供短效憑證。憑證僅以建置密鑰形式傳入複製步驟，不會進入映像檔、映像檔層或映像檔識別資訊。若 `getRepositoryAccess` 為 `undefined`，`createDockerRepoTemplate` 也會傳回 `undefined`，選用 Provider 的預設映像檔，呼叫端無須另加條件判斷。

儲存庫會複製到 `<workingDirectory>/<repo>`（預設為 `/workspace`），此路徑隨後成為 Sandbox 的工作目錄。傳入 `ref` 可指定預設分支以外的分支、標籤或提交。建置前，解析器會執行 `git ls-remote`，將 ref 固定至特定提交；該提交也是映像檔識別資訊的一部分。因此，分支移至新提交後，下次建立新的 Sandbox 時會產生新映像檔；分支未變動時則重用快取映像檔。若無法解析分支指向的提交，解析器會拒絕繼續，不會快取未固定提交的複製結果。

`setupCommand` 也接受陣列，每個項目都是獨立的可快取建置步驟。指令不能包含未跳脫的換行字元，否則會開始一條新的 Dockerfile 指令。可在行尾加上 `\`，或將指令拆成不同項目。

#### 在單一映像檔中放入多個儲存庫 {/* #several-repositories-in-one-image */}

使用 `repos` 取代 `getRepositoryAccess`，即可將多個儲存庫複製到同一個映像檔。每個儲存庫都能分別設定存取解析器、`ref` 和初始化指令；初始化指令可為字串或陣列，陣列中的每個項目各自構成一個建置步驟：

```typescript
const sandbox = new DockerSandbox({
  id: sessionId,
  template: createDockerRepoTemplate({
    repos: [
      {
        getRepositoryAccess: async () => ({
          cloneUrl: 'https://github.com/mastra-ai/template-docs-expert.git',
        }),
        setupCommand: 'npm install',
      },
      {
        getRepositoryAccess: async () => ({
          cloneUrl: 'https://github.com/mastra-ai/good-issue.git',
        }),
        ref: 'main',
      },
    ],
    workspaceSetupCommand: 'npm install --global @mastra/mcp-docs-server',
    continueOnSetupFailure: true,
    workingDirectory: '/workspace',
  }),
})
```

每個儲存庫都會複製到 `<workingDirectory>/<repo>`，工作目錄則成為 Sandbox 的目前目錄。建置時先處理公開儲存庫，再處理私人儲存庫；各組內維持呼叫端指定的順序。私人儲存庫的憑證僅以建置密鑰形式傳入該儲存庫的複製步驟，初始化指令無法讀取。

所有儲存庫完成初始化後，`workspaceSetupCommand` 會在工作目錄中執行。啟用 `continueOnSetupFailure`（預設為 `false`）後，若某個初始化指令失敗，對應的儲存庫會記錄在 `.mastra-sandbox/setup-failed`，建置仍會繼續，而不會整體失敗。

工作目錄中的標記可讓工作階段判斷映像檔已執行哪些步驟：每個儲存庫對應 `.mastra-sandbox/repos/<repo>`，Workspace 初始化指令執行後則有 `.mastra-sandbox/workspace-setup`。若已啟用 `continueOnSetupFailure`，請先檢查 `.mastra-sandbox/setup-failed`。

若任何儲存庫的存取資訊或分支指向的提交無法解析，整個解析過程都會失敗，Sandbox 將改用預設範本。

## Docker Cloud Sandboxes {/* #docker-cloud-sandboxes */}

`DockerSandboxesSandbox` 在 Docker Cloud Sandboxes 的 microVM 中執行指令，而非使用本機容器。若要存取 Docker Cloud Sandboxes，請提供已完成驗證的 `@docker/sandboxes` 用戶端。

```typescript
import { Sandboxes, pat } from '@docker/sandboxes'
import { Workspace } from '@mastra/core/workspace'
import { DockerSandboxesSandbox } from '@mastra/docker'

const client = new Sandboxes({
  auth: pat({
    username: process.env.DOCKER_USERNAME!,
    personalAccessToken: process.env.DOCKER_PAT!,
  }),
})
const workspace = new Workspace({
  sandbox: new DockerSandboxesSandbox({
    id: sessionId,
    image: 'ubuntu:24.04',
    environment: { NODE_ENV: 'production' },
    client,
  }),
})
```

`id` 會作為遠端 Sandbox 的顯示名稱，供重新連線時查找。新實例使用相同的 `id` 時，會重新連線至現有的 microVM；若該 microVM 已停止，還會將它重新啟動。每個實例都有獨立的建立冪等鍵。傳入 `sandboxId` 可直接重新連線至已知的遠端 Sandbox。

指令透過 `sh -lc` 執行，因此指令字串可使用管線、重新導向和 `&&`。另外傳入的 `args` 會加上 shell 引號。`executeCommand` 支援 `timeout`、`abortSignal`、串流式 `onStdout`/`onStderr` 回呼，以及 `maxRetainedBytes`（每個串流預設保留 1 MiB）。呼叫 `destroy()` 會刪除遠端 Sandbox。

## 背景程序 {/* #background-processes */}

`DockerSandbox` 內建程序管理器，可啟動及管理背景程序。程序透過 `docker exec` 在容器內執行。

```typescript
const sandbox = new DockerSandbox({ id: 'dev-sandbox' })
await sandbox._start()

// Spawn a background process
const handle = await sandbox.processes.spawn('node server.js', {
  env: { PORT: '3000' },
  onStdout: data => console.log(data),
})

// Interact with the process and signal EOF
console.log(handle.stdout)
await handle.sendStdin('input\n')
await handle.closeStdin()
await handle.wait()
```

完整 API 請參閱 [`SandboxProcessManager` 參考文件](/reference/workspace/process-manager)。

## 環境變數 {/* #environment-variables */}

使用 `env` 設定容器層級的環境變數。啟動程序時，也能為個別指令傳入環境變數：

```typescript
const sandbox = new DockerSandbox({
  image: 'node:22-slim',
  env: {
    NODE_ENV: 'production',
    DATABASE_URL: 'postgres://localhost:5432/mydb',
  },
})
```

## 寫入文件 {/* #write-files */}

使用 `writeFiles` 可在一次呼叫中上傳多個檔案。相對路徑以工作目錄為基準解析。可為個別檔案設定選用的 `mode` 以控制 POSIX 權限；其值必須是 `0o001` 至 `0o777` 之間的整數。省略 `mode` 時，新檔案會以 `0644` 權限建立。

```typescript
await sandbox.writeFiles([
  { path: 'src/index.js', content: "console.log('hello')\n" },
  { path: 'run.sh', content: '#!/bin/sh\n', mode: 0o755 },
])
```

Docker 是唯一會套用明確 `mode` 的內建 Sandbox。無法遵循個別檔案權限設定的 Provider（Vercel、E2B、Daytona、Cloudflare）會拒絕包含 `mode` 的 `writeFiles` 呼叫，不會默默忽略它。

## 繫結掛載 {/* #bind-mounts */}

使用 `volumes` 選項將主機目錄掛載至容器：

```typescript
const sandbox = new DockerSandbox({
  image: 'node:22-slim',
  volumes: {
    '/my/project': '/workspace/project',
    '/shared/data': '/data',
  },
})
```

繫結掛載會在建立容器時套用。主機路徑必須在 Sandbox 啟動前存在。

## 安全強化 {/* #hardening */}

使用 Docker 專屬的資源限制和安全強化選項約束 Sandbox 容器。以下範例限制記憶體與程序數量，並透過相符的 `cpuPeriod` 和 `cpuQuota` 將 CPU 限制為單核心；同時移除 Linux capabilities、將根檔案系統設為唯讀，並把 `/tmp` 掛載為可寫入的暫存空間：

```typescript
const sandbox = new DockerSandbox({
  image: 'node:22-slim',
  memory: 512 * 1024 * 1024,
  memorySwap: 512 * 1024 * 1024,
  cpuPeriod: 100_000,
  cpuQuota: 100_000,
  pidsLimit: 256,
  readonlyRootfs: true,
  capDrop: ['ALL'],
  capAdd: ['NET_BIND_SERVICE'],
  securityOpt: ['no-new-privileges:true'],
  ulimits: [{ name: 'nofile', soft: 1024, hard: 2048 }],
  tmpfs: {
    '/tmp': 'rw,noexec,nosuid,size=64m',
  },
})
```

這些選項直接對應至 Docker 的 `HostConfig` 欄位；未傳入時不會設定。

啟用安全強化前，請考量以下影響：

* `readonlyRootfs`：在容器內安裝套件，或使用會寫入掛載路徑以外位置的 Tool，可能會失敗。可為 `/tmp` 等暫存寫入路徑加入 `tmpfs`；必要時，也可為 `~/.npm` 等套件管理器快取掛載 tmpfs 或儲存卷。
* `capDrop`：移除所有 capabilities 會停用需要 Linux capabilities 的指令，包括 `ping` 和掛載操作。依賴 FUSE 的工具也會停用。只重新加入工作負載確實需要的 capabilities。
* `memory`：Docker 將 `0` 視為無限制。只有不需要記憶體上限時，才省略 `memory` 或傳入 `0`。
* `memorySwap`：Docker 的記憶體與交換空間行為取決於主機及 Docker 常駐程式的設定。設定 `memory` 但未設定 `memorySwap` 時，Docker 預設允許交換空間用量達到記憶體上限的兩倍。若要停用容器的交換空間，請將 `memorySwap` 設為與 `memory` 相同；Docker 也接受 `-1`，表示交換空間無限制。
* `pidsLimit`：值設得過低可能影響 `docker exec` 工作負載，因為長時間運作的容器每執行一條指令，都會啟動額外程序。
* `privileged`：特權容器會略過 capabilities 和安全性選項的控制。除非工作負載確實需要，否則不要將 `privileged: true` 與 capabilities 或安全性選項併用。
* 重新連線：Sandbox ID 相符時，`DockerSandbox` 會重用現有容器。若檢查到的 `HostConfig` 強化值不同，會發出警告。若要套用變更後的強化選項，必須銷毀並重新建立 Sandbox。Docker 可能會正規化檢查結果中的值；若原容器使用 Docker 預設的交換空間行為，重新連線時變更 `memorySwap` 也可能觸發警告。
* Docker Desktop：在 macOS 和 Windows 上，資源限制作用於 Docker Desktop 虛擬機器內部，因此虛擬機器分配到的資源可能進一步限制容器可用資源。

## 重連 {/* #reconnection */}

`DockerSandbox` 可透過比對標籤重新連線至現有容器。呼叫 `start()` 時，它會尋找 `mastra.sandbox.id` 標籤與 Sandbox ID 相符的容器。找到後：

* 直接重用正在執行的容器。
* 重新啟動已停止的容器。

```typescript
// First run — creates a new container
const sandbox = new DockerSandbox({ id: 'persistent-sandbox' })
await sandbox._start()

// Later — reconnects to the existing container
const sandbox2 = new DockerSandbox({ id: 'persistent-sandbox' })
await sandbox2._start()
```

## Docker 連線選項 {/* #docker-connection-options */}

透過 `dockerOptions` 連線至遠端 Docker 主機，或使用自訂通訊端路徑：

```typescript
// Remote Docker host
const sandbox = new DockerSandbox({
  dockerOptions: {
    host: '192.168.1.100',
    port: 2376,
    ca: fs.readFileSync('ca.pem'),
    cert: fs.readFileSync('cert.pem'),
    key: fs.readFileSync('key.pem'),
  },
})

// Custom socket path
const sandbox = new DockerSandbox({
  dockerOptions: {
    socketPath: '/var/run/docker.sock',
  },
})
```
