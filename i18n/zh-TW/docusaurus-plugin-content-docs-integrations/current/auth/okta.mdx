# Okta

`@mastra/auth-okta` 套件透過 Okta 為 Mastra 提供身分驗證和角色型存取控制（RBAC）。此套件支援使用加密工作階段 Cookie 的 OAuth 2.0 / OIDC 登入流程，並可將 Okta 群組對應至 Mastra 權限。

## 先決條件 {/* #prerequisites */}

本指南使用 Okta 進行身分驗證。開始前請完成以下步驟。

1. 前往 [okta.com](https://www.okta.com/) 建立 Okta 帳號。
2. 在 Okta 管理主控台設定 OAuth 應用程式，選擇 Web 應用程式與授權碼授權類型（Authorization Code）。
3. 將重新導向 URI 加入應用程式的登入重新導向 URI 清單。
4. 建立供 RBAC 使用的 API 權杖。

請確認已設定下列環境變數。

```env title=".env"
OKTA_DOMAIN=dev-123456.okta.com
OKTA_CLIENT_ID=your-client-id
OKTA_CLIENT_SECRET=your-client-secret
OKTA_REDIRECT_URI=http://localhost:4111/api/auth/callback
OKTA_COOKIE_PASSWORD=a-random-string-at-least-32-characters-long
OKTA_API_TOKEN=your-api-token
```

:::note

`OKTA_COOKIE_PASSWORD` 用來加密工作階段 Cookie。省略時，伺服器會使用自動產生的值，重新啟動後便不會保留該值。正式環境請明確設定這個變數。

只有使用 `MastraRBACOkta` 將 Okta 群組對應至權限時，才需要設定 `OKTA_API_TOKEN`。

:::

## 安裝 {/* #installation */}

```bash npm2yarn
npm install @mastra/auth-okta
```

## 使用範例 {/* #usage-examples */}

### 透過環境變數設定身分驗證 {/* #basic-usage-with-environment-variables */}

設定上述環境變數後，呼叫建構函式時可省略所有參數。

```typescript title="src/mastra/index.ts"
import { Mastra } from '@mastra/core'
import { MastraAuthOkta } from '@mastra/auth-okta'

export const mastra = new Mastra({
  server: {
    auth: new MastraAuthOkta(),
  },
})
```

### 搭配 RBAC 使用身分驗證 {/* #auth-with-rbac */}

:::note

在正式環境使用 RBAC 須具備 Mastra Enterprise Edition（EE）授權，開發環境則可直接使用。請參閱[哪些功能需要 EE 授權](/docs/license#what-requires-an-ee-license)。如需詳細資訊，請[聯絡業務團隊](https://mastra.ai/contact)。

:::

加入 `MastraRBACOkta`，即可將 Okta 群組對應至 Mastra 權限。

```typescript title="src/mastra/index.ts"
import { Mastra } from '@mastra/core'
import { MastraAuthOkta, MastraRBACOkta } from '@mastra/auth-okta'

export const mastra = new Mastra({
  server: {
    auth: new MastraAuthOkta(),
    rbac: new MastraRBACOkta({
      roleMapping: {
        Admin: ['*'],
        Engineering: ['agents:*', 'workflows:*', 'tools:*'],
        Viewer: ['agents:read', 'workflows:read'],
        _default: [], // users with unmapped groups get no permissions
      },
    }),
  },
})
```

### 搭配其他身分驗證 Provider {/* #cross-provider-usage */}

可以由 Auth0、Clerk 等其他身分驗證 Provider 負責登入，再由 Okta 提供 RBAC。傳入 `getUserId` 函式，即可依據登入 Provider 的使用者物件找出對應的 Okta 使用者 ID。

```typescript title="src/mastra/index.ts"
import { Mastra } from '@mastra/core'
import { MastraAuthAuth0 } from '@mastra/auth-auth0'
import { MastraRBACOkta } from '@mastra/auth-okta'

export const mastra = new Mastra({
  server: {
    auth: new MastraAuthAuth0(),
    rbac: new MastraRBACOkta({
      getUserId: user => user.metadata?.oktaUserId || user.email,
      roleMapping: {
        Engineering: ['agents:*', 'workflows:*'],
        Admin: ['*'],
        _default: [],
      },
    }),
  },
})
```

:::note

若要連結不同 Provider 上的同一位使用者，請將 Okta 使用者 ID 儲存在登入 Provider 的使用者中繼資料中。Mastra 會依據這個 ID 向 Okta 取得該使用者所屬的群組。

:::

所有可用的設定選項請參閱 [MastraAuthOkta](/reference/auth/okta)。

## 角色對應 {/* #role-mapping */}

`roleMapping` 選項會將每個 Okta 群組名稱對應至一組 Mastra 權限字串，以陣列表示。權限字串採用 `resource:action` 格式，支援萬用字元。

```typescript
const rbac = new MastraRBACOkta({
  roleMapping: {
    // full access to everything
    Admin: ['*'],

    // full access to agents and workflows
    Engineering: ['agents:*', 'workflows:*'],

    // read-only access
    Viewer: ['agents:read', 'workflows:read'],

    // users whose groups don't match any key above
    _default: [],
  },
})
```

如果使用者所屬的 Okta 群組都沒有對應到其他鍵，就會套用 `_default` 鍵所指定的權限。

## 用戶端設定 {/* #client-side-setup */}

啟用身分驗證後，送往 Mastra 路由的請求都必須通過驗證。`MastraAuthOkta` 採用單一登入（SSO），使用者會在 Okta 代管的登入頁面驗證身分。登入後，系統會自動設定加密的工作階段 Cookie。

### 使用 Cookie 維持工作階段（建議） {/* #cookie-session-recommended */}

若前端需要傳送跨來源請求，例如由 `:3000` 上的前端呼叫 `:4111` 上的 Mastra，請在 Mastra 伺服器的 CORS 設定中允許傳送憑證。

```typescript title="src/mastra/index.ts"
import { Mastra } from '@mastra/core'

export const mastra = new Mastra({
  server: {
    auth: new MastraAuthOkta(),
    cors: {
      origin: 'http://localhost:3000',
      credentials: true,
    },
  },
})
```

將用戶端設定為隨請求傳送憑證。

```typescript title="lib/mastra-client.ts"
import { MastraClient } from '@mastra/client-js'

export const mastraClient = new MastraClient({
  baseUrl: 'http://localhost:4111',
  credentials: 'include',
})
```

### Bearer 權杖 {/* #bearer-token */}

也可以將 Okta 權杖當作 Bearer 權杖傳送。Mastra 會使用 Okta 的 JWKS 端點驗證權杖，其 `aud` 宣告必須符合設定的對象（audience）。對象預設為用戶端 ID，可透過 `audience` 選項或 `OKTA_AUDIENCE` 覆寫。

Okta 會把用戶端 ID 寫入 **ID 權杖**的 `aud` 宣告，因此 ID 權杖可沿用預設值。**存取權杖**則帶有簽發該權杖的授權伺服器所指定的對象，請依伺服器類型設定相符的值。

* **組織授權伺服器**（預設類型，簽發者為 `https://{domain}`）。將對象設為 `https://{domain}`。
* **自訂授權伺服器**（簽發者為 `https://{domain}/oauth2/{name}`）。使用 Okta 管理主控台中該伺服器的對象值，例如 `api://default`。

```env title=".env"
OKTA_AUDIENCE=https://dev-123456.okta.com
```

若要接受多個對象值，請傳入陣列。例如，可以同時接受瀏覽器傳來的 ID 權杖和服務呼叫端傳來的存取權杖，兩者皆由同一個 Provider 簽發。

```typescript title="src/mastra/index.ts"
new MastraAuthOkta({
  audience: ['your-client-id', 'https://dev-123456.okta.com'],
})
```

:::note

`audience` 只適用於 Bearer 權杖。SSO 登入流程中交換的 ID 權杖一律以用戶端 ID 驗證。

:::

```typescript title="lib/mastra-client.ts"
import { MastraClient } from '@mastra/client-js'

export const createMastraClient = (token: string) => {
  return new MastraClient({
    baseUrl: 'http://localhost:4111',
    headers: {
      Authorization: `Bearer ${token}`,
    },
  })
}
```

其他設定選項請參閱 [Mastra Client SDK](/docs/server/mastra-client)。

## 故障排除 {/* #troubleshooting */}

* **所有請求都回傳 401**。確認 Okta 網域、用戶端 ID 和用戶端密鑰無誤，並檢查 Okta 應用程式的重新導向 URI 是否與 `OKTA_REDIRECT_URI` 一致。
* **請求回傳 401，伺服器記錄出現 `unexpected "aud" claim value`**。Bearer 權杖的對象與設定值不符。常見原因是傳送了存取權杖，但對象仍沿用預設的用戶端 ID。請將 `OKTA_AUDIENCE` 設為簽發該權杖的授權伺服器所指定的對象。請參閱 [Bearer 權杖](#bearer-token)。
* **跨來源請求未附帶 Cookie**。在 `MastraClient` 設定 `credentials: "include"`，並在 `server.cors` 指定前端來源及 `credentials: true`。
* **伺服器重新啟動後工作階段遺失**。將 `OKTA_COOKIE_PASSWORD` 設為至少 32 個字元的固定值。若未設定，伺服器每次重新啟動時都會使用新產生的金鑰。
* **RBAC 回傳的權限清單為空**。確認已設定 `OKTA_API_TOKEN`，且權杖有權列出使用者所屬的群組。檢查 `roleMapping` 中的群組名稱是否與 Okta 中的名稱完全相符。
