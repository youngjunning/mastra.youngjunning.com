# Neon

透過 `@mastra/auth-neon` 套件，Mastra 可以整合 [Neon Auth](https://neon.com/docs/auth/overview)。Neon Auth 是以 Better Auth 為基礎的代管身分驗證服務，會將使用者和工作階段儲存在你的 Neon 資料庫。這個套件會驗證以 Bearer 權杖傳送的 Neon Auth JWT 及 Neon Auth 工作階段 Cookie，並讓 Studio 使用者以電子郵件地址和密碼登入或註冊。

## 先決條件 {/* #prerequisites */}

在 [Neon 主控台](https://console.neon.tech)為 Neon 專案的一個分支啟用 Neon Auth。**Auth** 頁面會顯示該分支的 Neon Auth 網址。請將這個網址加入 `.env` 檔案：

```env title=".env"
NEON_AUTH_BASE_URL=https://ep-example-123456.neonauth.us-east-2.aws.neon.tech/neondb/auth
```

請使用 Neon 顯示的完整網址，保留 `/neondb/auth` 路徑。Mastra 會根據這個網址判斷 JWKS 端點（`<NEON_AUTH_BASE_URL>/.well-known/jwks.json`）及預期的 JWT 簽發者。

Neon Auth 只接受來自信任來源的登入請求。開啟 **Allow localhost** 後，即可接受來自 `localhost` 的請求。部署前，請在 Neon Auth 設定中將 Mastra 伺服器和 Studio 使用的網域加入信任網域清單，否則 Neon Auth 會拒絕 Studio 的登入請求，並傳回 `Invalid origin` 錯誤。

## 安裝 {/* #installation */}

安裝 `@mastra/auth-neon` 套件：

```bash npm2yarn
npm install @mastra/auth-neon@latest
```

## 使用範例 {/* #usage-example */}

將 `MastraAuthNeon` 註冊為伺服器的身分驗證 Provider：

```typescript {2,6} title="src/mastra/index.ts"
import { Mastra } from '@mastra/core'
import { MastraAuthNeon } from '@mastra/auth-neon'

export const mastra = new Mastra({
  server: {
    auth: new MastraAuthNeon(),
  },
})
```

`MastraAuthNeon` 預設會讀取 `NEON_AUTH_BASE_URL`。你也可以直接傳入 `baseUrl`。

完成設定後，呼叫 `/api` 下的任何路由都需要 Neon Auth 憑證。這個 Provider 接受下列任一種憑證：

* **Neon Auth JWT**，放在 `Authorization: Bearer <token>` 標頭。Mastra 使用 Neon Auth 的 JWKS 驗證簽章，並檢查簽發者、接收對象及到期時間。
* **Neon Auth 工作階段 Cookie**（`__Secure-neon-auth.session_token`）。Mastra 每次收到請求時，都會透過 Neon Auth 驗證這個 Cookie。

所有可用的設定選項請見 [MastraAuthNeon](/reference/auth/neon)。

## 登入 Studio {/* #studio-sign-in */}

設定 `MastraAuthNeon` 後，Studio 會顯示供使用者輸入電子郵件地址和密碼的表單。Mastra 會將登入憑證轉送給 Neon Auth，並將 Neon Auth 工作階段 Cookie 存在瀏覽器中。在 Studio 建立的帳號會出現在 Neon Auth 的使用者清單，在應用程式其他地方建立的帳號也可以登入 Studio。

工作階段 Cookie 設有 `Secure` 屬性，因此只有透過 HTTPS 或從 `localhost` 存取 Studio 時，瀏覽器才會儲存它。若透過其他主機上的純 HTTP 存取 Studio，就無法維持登入狀態。

若只允許既有使用者登入，請停用註冊功能。這會隱藏註冊表單，並拒絕送往 Mastra API 的註冊請求：

```typescript title="src/mastra/index.ts"
new MastraAuthNeon({
  signUpEnabled: false,
})
```

登出 Studio 時，Mastra 會清除 Studio 的工作階段 Cookie，並嘗試撤銷 Neon Auth 中的工作階段。如果送往 Neon Auth 的請求失敗，該工作階段可能仍然有效。

## 客戶端設定 {/* #client-side-setup */}

使用 Neon Auth SDK 的前端可以為已登入的使用者取得效期較短的 JWT，並傳送給 Mastra。

### 取得 JWT {/* #retrieving-a-jwt */}

若前端使用 Vite，請在前端的 `.env` 檔案中，將 `VITE_NEON_AUTH_URL` 設為與 Mastra 伺服器的 `NEON_AUTH_BASE_URL` 相同的 Neon Auth 網址。

使用者登入後，呼叫 [Neon Auth SDK](https://neon.com/docs/reference/javascript-sdk) 的 `authClient.getSession()`。傳回的工作階段包含要傳給 Mastra 的 JWT：

```typescript title="lib/auth.ts"
import { createAuthClient } from '@neon/neon-js/auth'

export const authClient = createAuthClient(import.meta.env.VITE_NEON_AUTH_URL)

export async function getMastraToken() {
  const { data, error } = await authClient.getSession()
  if (error) throw error
  if (!data?.session) throw new Error('Not signed in to Neon Auth')
  return data.session.token
}
```

Neon Auth JWT 會在 15 分鐘後到期。請在每批 Mastra 呼叫前重新取得權杖，無須儲存權杖供後續批次重複使用。

:::note

跨來源 Cookie 的要求和其他取得權杖的方式，請見 [Neon Auth JWT 指南](https://neon.com/docs/auth/guides/plugins/jwt)。

:::

### 設定 `MastraClient` {/* #configuring-mastraclient */}

在 `Authorization` 標頭中傳送 JWT：

```typescript {6} title="lib/mastra/mastra-client.ts"
import { MastraClient } from '@mastra/client-js'

export const createMastraClient = (token: string) =>
  new MastraClient({
    baseUrl: 'https://<mastra-api-url>',
    headers: { Authorization: `Bearer ${token}` },
  })
```

更多設定選項請見 [Mastra Client SDK](/docs/server/mastra-client)。

## 基於角色的存取控制 {/* #role-based-access-control */}

`MastraRBACNeon` 將 Neon Auth [組織外掛](https://neon.com/docs/auth/guides/plugins/organization)的角色（`owner`、`admin` 和 `member`）對應到 Mastra 權限。未列在 `roleMapping` 中的角色會取得 `_default` 權限：

```typescript {2,7-14} title="src/mastra/index.ts"
import { Mastra } from '@mastra/core'
import { MastraAuthNeon, MastraRBACNeon } from '@mastra/auth-neon'

export const mastra = new Mastra({
  server: {
    auth: new MastraAuthNeon(),
    rbac: new MastraRBACNeon({
      roleMapping: {
        owner: ['*'],
        admin: ['*'],
        member: ['agents:read', 'agents:execute', 'workflows:read'],
        _default: [],
      },
    }),
  },
})
```

收到帶有工作階段 Cookie 的請求時，Mastra 會向 Neon Auth 讀取使用者在目前工作階段所選組織中的角色。設定 `organizationId` 即可固定使用同一個組織。使用者若非該組織的成員，就沒有角色，因此也不會取得權限。若使用者沒有作用中的組織，Mastra 會採用其 Neon Auth 使用者角色，例如 `user` 或 `admin`。

Neon Auth JWT 不含組織角色。其中的 `role` 宣告一律是 `authenticated`，也就是 Neon Data API 使用的 Postgres 角色，Mastra 會忽略這項宣告。因此，帶有 Bearer JWT 的請求預設沒有角色，也不會取得權限。若要讓這類請求取得權限，請透過 `getUserRoles` 自行查出使用者角色：

```typescript title="src/mastra/index.ts"
new MastraRBACNeon({
  roleMapping: { admin: ['*'], member: ['agents:read'], _default: [] },
  getUserRoles: async user => lookUpRolesInYourDatabase(user.id),
})
```

:::note

RBAC 在正式環境中需要 Mastra Enterprise Edition (EE) 授權，在開發環境中則可直接使用。請見[哪些功能需要 EE 授權](/docs/license#what-requires-an-ee-license)。

:::

## 驗證設定 {/* #verify-the-setup */}

啟動 Mastra 伺服器，向受保護的路由送出未附憑證的請求：

```bash
curl -i http://localhost:4111/api/agents
```

伺服器會回傳 `401 Unauthorized`。在 `Authorization: Bearer <token>` 標頭放入 Neon Auth JWT 後重新送出請求，伺服器就會回傳 `200 OK` 和你的 Agent 清單。在 `http://localhost:4111` 的 Studio 登入表單中，可以使用任何 Neon Auth 使用者的電子郵件地址和密碼登入。
