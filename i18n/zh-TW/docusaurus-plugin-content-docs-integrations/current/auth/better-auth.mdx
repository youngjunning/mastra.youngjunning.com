# Better Auth

`@mastra/auth-better-auth` 套件以 Better Auth 為 Mastra 提供身分驗證。此套件透過 `server.auth` 選項與 Mastra 伺服器整合，並使用你的 Better Auth 執行個體驗證收到的請求。

## 先決條件 {/* #prerequisites */}

這個範例使用 Better Auth。請確認已完成 Better Auth 執行個體與環境變數的設定。

```env title=".env"
# Required by Better Auth
BETTER_AUTH_SECRET=...   # at least 32 chars
BETTER_AUTH_URL=http://localhost:3000

# Example DB URL used by the snippet below (adjust for your setup)
DATABASE_URL=postgres://...
```

:::note

為了安全性與穩定性，Better Auth 建議明確設定 `baseURL`，也可以透過 `BETTER_AUTH_URL` 設定。

:::

如果尚未掛載 Better Auth 的處理常式，請依照 [Better Auth 安裝指南](https://www.better-auth.com/docs/installation)，將它掛載在 `/api/auth/*` 路由或你設定的基底路徑上，讓應用程式能讓使用者登入並建立工作階段。

## 安裝 {/* #installation */}

安裝 `@mastra/auth-better-auth` 套件。

```bash npm2yarn
npm install @mastra/auth-better-auth
```

## 使用範例 {/* #usage-example */}

先建立 Better Auth 執行個體。

```ts title="lib/auth.ts"
import { betterAuth } from 'better-auth'

export const auth = betterAuth({
  database: {
    provider: 'postgresql',
    url: process.env.DATABASE_URL!,
  },
  emailAndPassword: {
    enabled: true,
  },
  baseURL: process.env.BETTER_AUTH_URL,
  secret: process.env.BETTER_AUTH_SECRET,
})
```

接著將該執行個體與 Mastra 整合。

```ts title="src/mastra/index.ts"
import { Mastra } from '@mastra/core'
import { MastraAuthBetterAuth } from '@mastra/auth-better-auth'
import { auth } from '@/lib/auth'

const mastraAuth = new MastraAuthBetterAuth({
  auth,
})

export const mastra = new Mastra({
  server: {
    auth: mastraAuth,
  },
})
```

所有可用的設定選項請參閱 [MastraAuthBetterAuth](/reference/auth/better-auth)。

## 自訂授權 {/* #custom-authorization */}

```ts
const mastraAuth = new MastraAuthBetterAuth({
  auth,
  async authorizeUser(user) {
    // Example: only allow verified emails
    return user?.user?.emailVerified === true
  },
})
```

## 路由設定 {/* #route-configuration */}

```ts
const mastraAuth = new MastraAuthBetterAuth({
  auth,
  public: ['/health', '/api/status'],
  protected: ['/api/*', '/admin/*'],
})
```

### 比對規則 {/* #matching-rules */}

* `public` 和 `protected` 都接受精確路徑、萬用字元模式（例如 `/api/*`）與路徑參數（例如 `/users/:id`）。
* 若要將規則套用至特定 HTTP 方法，請使用 `["/api/agents", ["GET", "POST"]]` 這類元組。
* 路由若同時符合 `public` 與 `protected`，以 `public` 為準，無須驗證身分。
* 若兩者皆不符合，路由預設受保護，除非明確標為 `requiresAuth: false`。

## 用戶端設定 {/* #client-side-setup */}

啟用身分驗證後，送往 Mastra 內建路由的請求都必須通過驗證。用戶端必須隨請求傳送目前 Better Auth 設定所使用的憑證。

### 使用 Cookie 的工作階段（建議） {/* #cookie-session-recommended */}

如果 Better Auth 使用 Cookie，請設定用戶端隨請求傳送憑證。若請求來自不同來源，例如在 `:3000` 執行的 Next.js 呼叫在 `:4111` 執行的 Mastra，請在 Mastra 伺服器的 CORS 設定中允許傳送憑證。

```ts title="src/mastra/index.ts"
import { Mastra } from '@mastra/core'

export const mastra = new Mastra({
  server: {
    auth: mastraAuth,
    cors: {
      origin: 'http://localhost:3000', // your frontend origin
      credentials: true,
    },
  },
})
```

接著設定用戶端，讓請求帶上憑證。

```ts
import { MastraClient } from '@mastra/client-js'

export const mastraClient = new MastraClient({
  baseUrl: 'http://localhost:4111',
  credentials: 'include',
})
```

如果直接呼叫 API，也請設定 `fetch` 隨請求附上憑證。

```ts
await fetch('http://localhost:4111/api/agents/weatherAgent/generate', {
  method: 'POST',
  headers: {
    'Content-Type': 'application/json',
  },
  credentials: 'include',
  body: JSON.stringify({ messages: 'Weather in London' }),
})
```

### Bearer 權杖 {/* #bearer-token */}

你可以將已簽署的工作階段權杖當作 Bearer 權杖使用。從 Better Auth 用戶端的工作階段取得權杖，並將它放入 `Authorization` 標頭。

```ts
import { MastraClient } from '@mastra/client-js'
import { authClient } from './auth-client' // your Better Auth client

const session = await authClient.getSession()

export const mastraClient = new MastraClient({
  baseUrl: 'http://localhost:4111',
  headers: {
    Authorization: `Bearer ${session.data?.session.token}`,
  },
})
```

更多設定選項請參閱 [Mastra Client SDK](/docs/server/mastra-client)。

## 故障排除 {/* #troubleshooting */}

* **每個請求都回傳 401**。確認 Better Auth 的處理常式已掛載，且應用程式能建立有效的工作階段。檢查用戶端是否帶上工作階段 Cookie 或 `Authorization: Bearer <signed-token>` 標頭。
* **跨來源請求未傳送 Cookie**。在 `MastraClient` 設定 `credentials: "include"`，並在 `server.cors` 指定前端來源及設定 `credentials: true`。
* **Bearer 權杖遭拒**。請傳送由 `authClient.getSession()` 取得的完整、已簽署的工作階段權杖，避免使用原始或未簽署的權杖。
* **基底 URL 有問題**。在 `betterAuth({ ... })` 中設定 `baseURL`，或設定 `BETTER_AUTH_URL`。
* **資料庫連線錯誤**。確認 `DATABASE_URL` 與資料庫提供者的設定正確。
