# Google

`@mastra/auth-google` 套件透過 Google Workspace 為 Mastra 提供身分驗證與角色型存取控制（RBAC）。這個套件支援 OAuth 2.0 / OIDC 登入流程，使用加密的工作階段 Cookie，驗證 Google ID 權杖，並將 Google Workspace 群組對應至 Mastra 權限。

如果 Studio 使用者透過 Google 登入，而且你要將存取權限限制在一或多個 Google Workspace 網域，請使用這個套件。

## 先決條件 {/* #prerequisites */}

本指南使用 Google Workspace 進行身分驗證。開始前，請完成下列準備：

1. 建立或選取 Google Cloud 專案
2. 為 Web 應用程式設定 OAuth 用戶端
3. 將 Mastra SSO 回呼 URL 加入已授權的重新導向 URI 清單
4. 如果要使用 RBAC，請設定 Google Workspace 群組

如果要透過 Google Groups 實作 RBAC，請另外設定具備全網域委派權限的 Google Workspace 服務帳戶，並授予該帳戶下列 Directory API 授權範圍，以唯讀方式存取群組：

```text
https://www.googleapis.com/auth/admin.directory.group.readonly
```

請設定下列環境變數。

```env title=".env"
GOOGLE_CLIENT_ID=your-client-id.apps.googleusercontent.com
GOOGLE_CLIENT_SECRET=your-client-secret
GOOGLE_REDIRECT_URI=http://localhost:4111/api/auth/sso/callback
GOOGLE_COOKIE_PASSWORD=a-random-string-at-least-32-characters-long
GOOGLE_ALLOWED_DOMAINS=example.com

GOOGLE_SERVICE_ACCOUNT_EMAIL=service-account@project.iam.gserviceaccount.com
GOOGLE_SERVICE_ACCOUNT_PRIVATE_KEY="-----BEGIN PRIVATE KEY-----\n...\n-----END PRIVATE KEY-----\n"
GOOGLE_WORKSPACE_ADMIN_EMAIL=admin@example.com
```

:::note[說明]

`GOOGLE_COOKIE_PASSWORD` 用於加密工作階段 Cookie。若未設定，系統會自動產生一個值，伺服器重新啟動後便不會保留該值。請在正式環境中明確設定此變數。

`MastraAuthGoogle` 會自動讀取 `GOOGLE_*` 身分驗證變數。上面列出的服務帳戶變數由傳給 `MastraRBACGoogle` 的設定程式碼讀取。

:::

## 安裝 {/* #installation */}

使用 `MastraAuthGoogle` 類別之前，請先安裝 `@mastra/auth-google` 套件。

```bash npm2yarn
npm install @mastra/auth-google
```

## 使用範例 {/* #usage-examples */}

### 使用環境變數進行基本設定 {/* #basic-usage-with-environment-variables */}

設定上述環境變數後，建構函式的所有參數都可以省略：

```typescript title="src/mastra/index.ts"
import { Mastra } from '@mastra/core'
import { MastraAuthGoogle } from '@mastra/auth-google'

export const mastra = new Mastra({
  server: {
    auth: new MastraAuthGoogle(),
  },
})
```

:::warning[警告]

使用 `allowedDomains` 或 `GOOGLE_ALLOWED_DOMAINS`，將存取限制在指定的 Workspace 網域。Mastra 檢查的是 Google 提供且已驗證的 `hd` 宣告，而非電子郵件地址的尾碼。

:::

### 自訂設定 {/* #custom-configuration */}

如果不想依賴環境變數，可以直接將設定選項傳給建構函式：

```typescript title="src/mastra/index.ts"
import { Mastra } from '@mastra/core'
import { MastraAuthGoogle } from '@mastra/auth-google'

export const mastra = new Mastra({
  server: {
    auth: new MastraAuthGoogle({
      clientId: process.env.GOOGLE_CLIENT_ID,
      clientSecret: process.env.GOOGLE_CLIENT_SECRET,
      redirectUri: process.env.GOOGLE_REDIRECT_URI,
      allowedDomains: ['example.com'],
    }),
  },
})
```

### 身分驗證與以 Google Groups 為依據的 RBAC {/* #auth-with-google-groups-rbac */}

:::note[說明]

在正式環境中使用 RBAC 需要 Mastra 企業版（EE）授權。在開發環境中則不需要授權。請參閱[哪些功能需要 EE 授權](/docs/license#what-requires-an-ee-license)，或[聯絡業務團隊](https://mastra.ai/contact)了解詳情。

:::

加入 `MastraRBACGoogle`，將 Google Workspace 群組對應至 Mastra 權限：

```typescript title="src/mastra/index.ts"
import { Mastra } from '@mastra/core'
import { MastraAuthGoogle, MastraRBACGoogle } from '@mastra/auth-google'

export const mastra = new Mastra({
  server: {
    auth: new MastraAuthGoogle(),
    rbac: new MastraRBACGoogle({
      serviceAccount: {
        clientEmail: process.env.GOOGLE_SERVICE_ACCOUNT_EMAIL!,
        privateKey: process.env.GOOGLE_SERVICE_ACCOUNT_PRIVATE_KEY!,
        subject: process.env.GOOGLE_WORKSPACE_ADMIN_EMAIL!,
      },
      roleMapping: {
        'admins@example.com': ['*'],
        'engineering@example.com': ['agents:*', 'workflows:*', 'tools:*'],
        'viewers@example.com': ['agents:read', 'workflows:read'],
        _default: [], // users with unmapped groups get no permissions
      },
    }),
  },
})
```

### 搭配其他身分驗證 Provider {/* #cross-provider-usage */}

可以讓 Auth0、Clerk 等其他身分驗證 Provider 處理登入，再以 Google Workspace 群組實作 RBAC。傳入 `getUserKey` 函式，從該 Provider 的使用者物件取得 Google Directory API 所需的使用者索引鍵：

```typescript title="src/mastra/index.ts"
import { Mastra } from '@mastra/core'
import { MastraAuthAuth0 } from '@mastra/auth-auth0'
import { MastraRBACGoogle } from '@mastra/auth-google'

export const mastra = new Mastra({
  server: {
    auth: new MastraAuthAuth0(),
    rbac: new MastraRBACGoogle({
      getUserKey: user => {
        if (!user || typeof user !== 'object') return undefined

        const { email } = user as { email?: unknown }
        return typeof email === 'string' ? email : undefined
      },
      serviceAccount: {
        clientEmail: process.env.GOOGLE_SERVICE_ACCOUNT_EMAIL!,
        privateKey: process.env.GOOGLE_SERVICE_ACCOUNT_PRIVATE_KEY!,
        subject: process.env.GOOGLE_WORKSPACE_ADMIN_EMAIL!,
      },
      roleMapping: {
        'engineering@example.com': ['agents:*', 'workflows:*'],
        'admins@example.com': ['*'],
        _default: [],
      },
    }),
  },
})
```

如需完整的設定選項，請參閱 [MastraAuthGoogle](/reference/auth/google)。

## 角色對應 {/* #role-mapping */}

`roleMapping` 選項會將 Google Workspace 群組的電子郵件地址對應至由 Mastra 權限字串組成的陣列。權限採用 `resource:action` 格式，並支援萬用字元：

```typescript
const rbac = new MastraRBACGoogle({
  roleMapping: {
    // full access to everything
    'admins@example.com': ['*'],

    // full access to agents and workflows
    'engineering@example.com': ['agents:*', 'workflows:*'],

    // read-only access
    'viewers@example.com': ['agents:read', 'workflows:read'],

    // users whose groups don't match any key above
    _default: [],
  },
})
```

預設以群組的電子郵件地址當作角色 ID。若要依群組名稱或其他屬性建立對應，請使用 `mapGroupToRoles`。如果使用者所屬的 Google Workspace 群組都未對應到其他索引鍵，就依 `_default` 索引鍵指派權限。

## 用戶端設定 {/* #client-side-setup */}

啟用身分驗證後，傳送至 Mastra 路由的請求必須通過驗證。使用 `GOOGLE_CLIENT_SECRET` 啟用 SSO 後，`MastraAuthGoogle` 會使用 Google 登入，並在登入後設定加密的工作階段 Cookie。

### 使用 Cookie 維持工作階段（建議） {/* #cookie-session-recommended */}

如果需要傳送跨來源請求，例如在 `:3000` 執行的前端呼叫在 `:4111` 執行的 Mastra，請在 Mastra 伺服器上允許 CORS 請求攜帶憑證：

```typescript title="src/mastra/index.ts"
import { Mastra } from '@mastra/core'

export const mastra = new Mastra({
  server: {
    auth: new MastraAuthGoogle(),
    cors: {
      origin: 'http://localhost:3000',
      credentials: true,
    },
  },
})
```

設定用戶端，讓請求攜帶憑證：

```typescript title="lib/mastra-client.ts"
import { MastraClient } from '@mastra/client-js'

export const mastraClient = new MastraClient({
  baseUrl: 'http://localhost:4111',
  credentials: 'include',
})
```

### Bearer 權杖 {/* #bearer-token */}

也可以將 Google ID 權杖當作 Bearer 權杖傳送。Mastra 會使用從 Google 的 JSON Web 金鑰集（JWKS）端點取得的金鑰驗證權杖：

```typescript title="lib/mastra-client.ts"
import { MastraClient } from '@mastra/client-js'

export const createMastraClient = (idToken: string) => {
  return new MastraClient({
    baseUrl: 'http://localhost:4111',
    headers: {
      Authorization: `Bearer ${idToken}`,
    },
  })
}
```

如需更多設定選項，請參閱 [Mastra Client SDK](/docs/server/mastra-client)。

## 故障排除 {/* #troubleshooting */}

* **登入後收到 401**：確認 `GOOGLE_CLIENT_ID`、`GOOGLE_CLIENT_SECRET` 和 `GOOGLE_REDIRECT_URI` 與 Google Cloud 的 OAuth 用戶端設定一致。
* **Workspace 使用者無法存取**：確認 Google ID 權杖的 `hd` 宣告符合 `GOOGLE_ALLOWED_DOMAINS` 列出的其中一個網域。
* **個人 Gmail 帳戶無法存取**：設定 `allowedDomains` 後，這是預期行為，因為個人 Gmail 帳戶沒有 Workspace 的 `hd` 宣告。
* **RBAC 傳回預設權限**：系統未能判定該使用者的任何角色。請檢查使用者的電子郵件地址或自訂的 `getUserKey`，以及使用者所屬的 Google 群組和 `roleMapping`。如果 Directory API 查詢失敗，Provider 會擲出錯誤，而不會傳回 `_default`。
* **跨來源請求沒有附帶 Cookie**：在 `MastraClient` 中設定 `credentials: "include"`，並在 `server.cors` 中指定前端的來源及設定 `credentials: true`。
* **伺服器重新啟動後工作階段遺失**：將 `GOOGLE_COOKIE_PASSWORD` 設為至少 32 個字元的固定值。若未設定，開發環境會在每次重新啟動時自動產生新的金鑰。
