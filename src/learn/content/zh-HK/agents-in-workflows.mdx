購票流程已可提供報價、暫停等候批核，並模擬扣款。今課會為流程加上兩個步驟，看看工具和 Agent 各有甚麼作用，以及甚麼時候適合用哪一個。

先加上 `validatePark`，在執行其餘步驟之前，用樂園查詢工具核對提交的名稱。扣款後加入 `postPurchaseSummary`，直接調用主題樂園 Agent，由它利用本身的工具整理一份簡短的遊園指引，串流傳回，作為最終輸出的一部分。

流程內每一步的要求都不同。核對名稱要嚴格按固定規則做，直接用工具便可；要整理有用的遊園指引，就要按語境作判斷，交給 Agent 較合適。流程負責編排先後，各步驟按工作需要選用做法。

> 「開首由工具按嚴格規則查詢，最後由 Agent 推理。整個執行次序一直由流程控制。」
>
> — Guil Hernandez
