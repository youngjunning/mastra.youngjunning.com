只保留消息历史有局限。对话一长，工具调用、排队时间查询、天气查询和从网页抓取的乐园数据很快就会堆积。本课会启用 Observational Memory（观察记忆），把不断增长的原始历史压缩成更精炼、Agent 能用得上的上下文。

你会将 Agent 切换到 `observationalMemory`，把作用域设为 `resource`，让同一用户在不同对话线程中共享记忆。在 Studio 中先开启一段对话，再换到新线程继续，就能看到先前的偏好仍然有效。

> **注意：** 本课采用的 Observational Memory 设置 `scope: 'resource'` 已弃用。要跨线程延续对话，请保留默认的线程作用域，并启用 [检索模式](/docs/memory/observational-memory#retrieval-mode)或[资源作用域的工作记忆](/docs/memory/working-memory#resource-scoped-memory-default)。

Observational Memory 会自动压缩历史记录，省去手动调节 `lastMessages` 的工作。这样，即使是长会话或跨多个线程的对话，也能保持连贯，无须每次调用都带上全部原始历史。

> “你不会记住每次对话里说过的每一个字。你会留意发生了什么，久而久之，这些观察会沉淀成更有用的信息。OM 就是按这个思路设计的。”
>
> — Guil Hernandez
