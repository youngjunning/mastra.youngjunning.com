購票 Workflow 已能產生報價、暫停等候核准，並模擬扣款。這堂課會加入兩個步驟，讓你了解工具與 Agent 在流程中各能做什麼、何時該選用哪一個。

先新增 `validatePark`，讓樂園查詢工具在其他步驟執行前確認送出的樂園名稱。扣款後，再透過 `postPurchaseSummary` 直接呼叫主題樂園 Agent，由它運用自己的工具撰寫簡短的遊園指南，並將指南串流傳回，納入最終輸出。

各步驟的需求不盡相同。驗證必須嚴格遵循固定規則，直接呼叫工具就很合適；遊園指南要能派上用場，則需要根據情境判斷，適合交給 Agent。Workflow 負責控制順序，各步驟再依需求選用工具或 Agent。

> 「開頭由工具負責按規則查詢，結尾由 Agent 推理。從頭到尾都由 Workflow 安排執行順序。」
>
> — Guil Hernandez
