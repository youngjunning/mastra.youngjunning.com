只用基本的訊息歷史記錄有其限制。對話一長，工具呼叫、排隊時間查詢、天氣查詢和從網頁擷取的樂園資料很快就會累積起來。這堂課會啟用 Observational Memory（觀察記憶），將不斷累積的原始記錄濃縮成 Agent 用得上的上下文。

你會將 Agent 改用 `observationalMemory`，並把範圍設成 `resource`，讓同一位使用者在不同對話串中共用記憶。你會在 Studio 開啟一段對話，再到新的對話串接續聊下去，確認之前的偏好仍然有效。

> **注意：** 本課使用的 Observational Memory 設定 `scope: 'resource'` 已淘汰。若要延續不同對話串之間的上下文，請保留預設的對話串範圍，並啟用[檢索模式](/docs/memory/observational-memory#retrieval-mode)或[資源範圍的工作記憶](/docs/memory/working-memory#resource-scoped-memory-default)。

Observational Memory 會自動壓縮資料，取代手動調整 `lastMessages` 的做法。即使對話很長，或分散在不同對話串，內容仍能前後連貫，每次呼叫也不必把所有原始記錄帶進來。

> 「你不會記得自己每次對話的每一句話。你會留意發生了哪些事，時間一久，這些觀察就會濃縮成更有用的資訊。OM 用的就是這個概念。」
>
> — Guil Hernandez
